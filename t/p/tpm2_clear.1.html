tpm2_clear(1) Manuel des commandes générales tpm2_clear(1)

NOM

tpm2_clear(1) - Efface les valeurs d'autorisation des hiérarchies de verrouillage, d'endossement et de propriétaire, ainsi que d'autres données du TPM.

SYNTAXE

tpm2_clear [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_clear(1) - Envoie une commande d'effacement au TPM pour effacer les 3 valeurs d'autorisation des hiérarchies. Prend en argument la valeur d'authentification pour la hiérarchie de plateforme ou de verrouillage. Les détails des modifications apportées au TPM se trouvent dans la partie 3, section « Commandes », de la spécification de la bibliothèque TPM, disponible à l'URL ci-dessous. - https://trustedcomputinggroup.org/resource/tpm-library-specification

Veuillez rechercher la version correspondant à la version de votre spécification de support TPM et à la commande TPM2_Clear. La version de spécification prise en charge par le TPM peut être trouvée en exécutant tpm2_getcap properties-fixed dans la propriété TPM_PT_REVISION.

NOTE : Tous les objets créés sous les hiérarchies respectives sont perdus.

OPTIONS

•
-c, --auth-hierarchy=OBJET:

Spécifie la hiérarchie sur laquelle les outils doivent opérer. Par défaut, elle opère sur la hiérarchie de verrouillage.

NOTE : L'opération sur la hiérarchie de plateforme nécessite une authentification de plateforme.

•
--cphash=FICHIER

Chemin d'accès au fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash.

•
ARGUMENT l'argument de ligne de commande spécifie l'AUTH à définir pour l'objet spécifié avec -c.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un descripteur ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un *préfixe* de l'un des éléments suivants :
•
owner : la hiérarchie du propriétaire
•
platform : la hiérarchie de la plateforme
•
endorsement : la hiérarchie d'endossement
•
lockout : l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un descripteur, par exemple 0x81010013, et utilisé directement.*OBJET*.

Formatage de l'autorisation

L'autorisation pour l'utilisation d'un objet en TPM2.0 peut se présenter sous 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations sont par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes ci-dessous en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme des chaînes de caractères lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations ; les mots de passe passés en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctions d'historique de shell courantes.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour envoyer un mot de passe via stdin :
echo foobar | tpm2_tool -p file:-
# pour utiliser un here-string bash via stdin :
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé *session*. Indiquez ensuite le chemin d'accès à un fichier de session créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le descripteur de session (par exemple, un mot de passe de politique), ajoutez un '+' suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEXADÉCIMALE 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

La spécification PCR est documentée dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie du contenu brut du PCR tel qu'il est renvoyé par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez le spécificateur :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

tpm2_clear

tpm2_clear - Clear the TPM's state

SYNOPSIS

tpm2_clear [OPTIONS] [PASSWORD]

DESCRIPTION

The tpm2_clear command is used to clear the TPM state. This will reset the TPM to its factory default settings. This operation can only be performed if the lockout authorization is enabled and the correct lockout password is provided. If the lockout authorization is disabled, this command will fail.

OPTIONS

These are the available options for the tpm2_clear command:

-c, --clear
This option specifies which hierarchy to clear. It can take the following values:
owner: Clear the owner hierarchy.
endorsement: Clear the endorsement hierarchy.
lockout: Clear the lockout hierarchy.
platform: Clear the platform hierarchy.
all: Clear all hierarchies.

Context Object Format

The default TPM2 context object format is defined in the tpm2_context(7) manpage. A context object may be passed to the tool using the standard input streams or a file. The format used is JSON.

Authorization Formatting

The TPM supports authorization values for various hierarchies. These values can be set to an empty value or a specific password. The formatting for these values is handled by the tool.

COMMON OPTIONS

These options are common to most tools in the tpm2-tools suite. Please refer to the tpm2_tool(8) manpage for details on the following options:

•
-?, -h, --help: Print the help message and exit.
•
-V, --version: Print version information and exit.
•
-v, --verbose: Increase verbosity.
•
-d, --debug: Enable debug output.
•
-Q, --quiet: Silence normal output.
•
-t, --tcti: Specify the TCTI.
•
-i, --input: Specify the input file.
•
-o, --output: Specify the output file.
•
-p, --password: Specify the authorization password.

Additional common options include -T, -R, -Z, and others as described in the tpm2_tool(8) manpage. The full list of common options and their descriptions can be found there. The environment variable MANPATH can be used to specify the path to the manual pages. See man(1) for more details.

•
-v, --version: Affiche les informations de version de cet outil, les TCTI pris en charge et quitte.
•
-V, --verbose: Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque cette option est utilisée, le numéro de fichier et de ligne est imprimé.
•
-Q, --quiet: Réduit au silence la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata: Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush: Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

TCTI Configuration

Le TCTI, ou « Transmission Interface », est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour la communication avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

La spécification d'une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

TCTI Defaults

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant les sémantiques de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTI susmentionnés est le défaut.

Custom TCTIs

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, il peut s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel que compris par les sémantiques de dlopen(3).

TCTI OPTIONS

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et chaîne de valeur sont séparées par un caractère `=`.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifier le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les différents modules TCTI connus.

EXAMPLES

Définir les autorisations owner, endorsement et lockout à une valeur vide

tpm2_clear lockoutpasswd

Effacer les valeurs d'autorisation sur la hiérarchie de la plateforme

tpm2_clear -c p

Returns

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de traitement des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
