tpm2_nvreadpublic(1) Manuel des commandes générales tpm2_nvreadpublic(1)

NOM

tpm2_nvreadpublic(1) - Affiche tous les index Non-Volatiles (NV) définis.

SYNOPSIS

tpm2_nvreadpublic [OPTIONS]

DESCRIPTION

tpm2_nvreadpublic(1) - Affiche tous les index Non-Volatiles (NV) définis sur la sortie standard au format YAML.

Affiche les métadonnées de tous les index NV définis. Les métadonnées comprennent :

•
La taille de la région définie.
•
L'algorithme de hachage utilisé pour calculer le nom de l'index.
•
La politique d'autorisation.
•
Les attributs NV tels que définis dans la section « Attributs NV ».

Exemple de sortie

0x1500015:
  hash algorithm:
    friendly: sha256
    value: 0xB
  attributes:
    friendly: ownerwrite|ownerread
    value: 0x2000200
  size: 32
  authorization policy:
0x1500017:
  hash algorithm:
    friendly: sha256
    value: 0xB
  attributes:
    friendly: ownerwrite|ownerread
    value: 0x2000200
  size: 32
  authorization policy:

OPTIONS

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash à moins que rphash ne soit également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est communément appelé rpHash.

•
-S, --session=SESSION_POLITIQUE:

Spécifie une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

•
-n, --name=FICHIER:

Le nom de l'index NV qui doit être fourni lors du calcul uniquement du cpHash sans réellement expédier la commande au TPM.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page man de l'outil. Par défaut, il tente d'appeler le paginator man pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le paginator man échoue, les options courtes seront affichées sur la sortie standard.

Pour utiliser avec succès la fonctionnalité des pages man, il faut que les pages man soient installées ou sur MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tcti supportés et quitte.
•
-V, --verbose : Augmente les informations que l'outil affiche sur la console pendant son exécution. Lorsque cette option est utilisée, le fichier et le numéro de ligne sont affichés.
•
-Q, --quiet : Silence la sortie normale de l'outil sur la sortie standard.
•
-Z, --enable-errata : Active l'application de corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne supporte AUCUNE option et DOIT être présenté sous la forme exacte « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom_tcti>:<configuration_option_tcti>

Spécifier une chaîne vide pour <nom_tcti> ou <configuration_option_tcti> utilise la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera quel TCTI parmi ceux mentionnés ci-dessus est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom_tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier périphérique caractère du TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de simples paires clé-valeur séparées par une virgule `,`. Chaque clé et valeur sont séparées par un signe égal `=`.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name` : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type` : Le type de l'instance dbus
e (une chaîne) limitée à `session' et `system'.

Spécifiez le nom tcti de tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes.

ATTRIBUTS NV

Les attributs NV sont utilisés pour contrôler diverses propriétés de l'espace défini NV. Lorsqu'ils sont spécifiés comme option, le masque de champ de bits brut ou les "noms conviviaux" peuvent être utilisés. Les valeurs se trouvent dans le Tableau 204, Partie 2 de la spécification TPM2.0, qui peut être consultée ici :

https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-2-Structures-01.38.pdf

Les noms conviviaux sont calculés en prenant le champ name du tableau 204 et en supprimant le préfixe TPMA_NV_ et en mettant le résultat en minuscules. Ainsi, TPMA_NV_PPWRITE devient ppwrite. Les noms conviviaux peuvent être joints en utilisant le symbole OU bit à bit « | ».

Notez que le champ TPM_NT a une largeur de 4 bits et peut donc être défini via le format nt=. Par exemple, pour définir les champs TPMA_NV_OWNERREAD, TPMA_NV_OWNERWRITE, TPMA_NV_POLICYWRITE et TPMA_NT = 0x2, l'argument serait :

ownerread|ownerwrite|policywrite|nt=0x2

De plus, le champ NT, qui désigne le type de l'index NV, peut également être spécifié via des noms conviviaux : * ordinary - Ordinary contient des données opaques au TPM qui ne peuvent être modifiées qu'à l'aide de TPM2_NV_Write. * extend - Extend est utilisé de manière similaire à un PCR et ne peut être modifié qu'avec TPM2_NV_Extend. Sa taille est déterminée par la longueur de l'algorithme de hachage utilisé. * counter - Counter contient une valeur de 8 octets qui doit être utilisée comme compteur et ne peut être modifiée qu'avec TPM2_NV_Increment. * bits - Bit Field contient une valeur de 8 octets à utiliser comme champ de bits et ne peut être modifié qu'avec TPM2_NV_SetBits. * pinfail - PIN Fail contient un pinCount de 8 octets qui s'incrémente en cas d'échec d'autorisation PIN et un pinLimit. * pinpass - PIN Pass contient un pinCount de 8 octets qui s'incrémente en cas de succès d'autorisation PIN et un pinLimit.

Par exemple, pour définir les champs TPMA_NV_OWNERREAD, TPMA_NV_OWNERWRITE, TPMA_NV_POLICYWRITE et TPMA_NT = bits, l'argument serait :

ownerread|ownerwrite|policywrite|nt=bits

EXEMPLES

Lister les indices NV définis sur stdout

tpm2_nvreadpublic

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
