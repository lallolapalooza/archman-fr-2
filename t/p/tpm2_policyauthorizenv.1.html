tpm2_policyauthorizenv(1) Manuel des commandes générales tpm2_policyauthorizenv(1)

NOM

tpm2_policyauthorizenv(1) - Permet des politiques mutables en référençant une politique depuis un index NV.

SYNTAXE

tpm2_policyauthorizenv [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_policyauthorizenv(1) - Cette commande permet aux politiques de changer en référençant la politique d'autorisation écrite dans un index NV. L'index NV contenant la politique d'autorisation doit rester lisible même pour une session d'essai. L'index peut être spécifié comme un descripteur brut ou une valeur de décalage dans la plage de descripteurs nv « TPM2_HR_NV_INDEX ».

OPTIONS

•
-C, --hierarchy=OBJET:

Spécifie la hiérarchie utilisée pour l'autorisation. Les options prises en charge sont :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<nombre> où un descripteur de hiérarchie ou un index nv peut être utilisé.

Lorsque -C n'est pas explicitement passé, le descripteur d'index sera utilisé pour s'autoriser contre l'index. La valeur d'authentification de l'index est définie via l'option -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie.

•
-L, --policy=FICHIER:

Fichier pour enregistrer le digest de politique.

•
-S, --session=FICHIER:

Le fichier de session de politique généré via l'option -S de tpm2_startauthsession(1).

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash.

Configuration du TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande a toujours priorité sur la variable d'environnement.

Les TCTIs connus actuellement sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que noms de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne prend pas en charge AUCUNE option et DOIT être présenté comme le texte exact de « none ».

Les arguments, que ce soit pour l'option de ligne de commande ou la variable d'environnement, sont sous la forme :

<nom_tcti>:<configuration_option_tcti>

Spécifier une chaîne vide pour <nom_tcti> ou <configuration_option_tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom_tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI `device`, le fichier de périphérique caractère TPM à utiliser par le TCTI `device` peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI `mssim`, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI `abrmd`, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et valeur sont séparées par un caractère `=`.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd et tabrmd sont synonymes. les différents modules TCTI connus.

EXEMPLES

Créez un mot de passe de politique et écrivez le digest de la politique dans un index NV. Construisez une politique d'autorisation NV référençant l'index NV dans une session de type trial. Le digest de politique résultant est ensuite utilisé dans la création d'objets.

Dans une session d'autorisation de politique, satisfaites d'abord la politique écrite dans l'index NV. Ensuite, exécutez policyauthorizenv qui satisfait l'autorisation pour l'objet.

Définir l'index NV de test pour stocker la politique d'authentification

nv_test_index=0x01500001
tpm2_nvdefine -C o -p nvpass $nv_test_index -a "authread|authwrite" -s 34

Définir la politique d'authentification

tpm2_startauthsession -S session.ctx
tpm2_policypassword -S session.ctx -L policy.pass
tpm2_flushcontext session.ctx

Écrire la politique d'authentification dans l'index NV

echo "000b" | xxd -p -r | cat - policy.pass | \
tpm2_nvwrite -C $nv_test_index -P nvpass $nv_test_index -i-

Définir policyauthorizenv

tpm2_startauthsession -S session.ctx
tpm2_policyauthorizenv -S session.ctx -C $nv_test_index -P nvpass \
-L policyauthorizenv.1500001 $nv_test_index
tpm2_flushcontext session.ctx

Créer et charger un objet de scellement avec politique d'authentification = policyauthorizenv

tpm2_createprimary -C o -c prim.ctx
echo "secretdata" | \
tpm2_create -C prim.ctx -u key.pub -r key.priv \
-a "fixedtpm|fixedparent|adminwithpolicy" -L policyauthorizenv.1500001 -i-
tpm2_load -C prim.ctx -u key.pub -r key.priv -c key.ctx

Satisfaire la politique d'authentification stockée dans l'index NV et donc policyauthorizenv

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policypassword -S session.ctx
tpm2_policyauthorizenv -S session.ctx -C $nv_test_index -P nvpass $nv_test_index
tpm2_unseal -c key.ctx -p session:session.ctx
tpm2_flushcontext session.ctx

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.

Limitations

Il attend qu'une session soit déjà établie via tpm2_startauthsession(1) et nécessite l'une des options suivantes :

•
accès direct au périphérique
•
support de session étendue avec tpm2-abrmd.

Sans cela, la plupart des gestionnaires de ressources ne sauvegarderont **pas** l'état de la session entre les invocations de commande.
