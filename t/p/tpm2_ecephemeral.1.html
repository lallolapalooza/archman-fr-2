tpm2_ecephemeral(1) Manuel des commandes générales tpm2_ecephemeral(1)

NOM

tpm2_ecephemeral(1) - Crée une clé éphémère pour une utilisation dans un protocole d'échange de clés en deux phases.

SYNOPSIS

tpm2_ecephemeral [OPTIONS]

DESCRIPTION

tpm2_ecephemeral(1) - Crée une clé éphémère pour une utilisation dans un protocole d'échange de clés en deux phases.

OPTIONS

•
ARGUMENT=ALGORITHME :

Spécifie la courbe ECC. Exemple : ecc521.

•
-u, --public=FICHIER

Spécifie le chemin du fichier pour sauvegarder le point public éphémère Q ≔ [r]G.

•
-t, --counter=FICHIER

Spécifie le chemin du fichier pour sauvegarder les 16 bits de poids faible du compteur de validation.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash.

Références

Spécificateurs d'algorithmes

Les options qui acceptent des algorithmes prennent en charge les « noms sympas ».

Il existe deux classes principales de chaînes de spécification d'algorithmes : simples et complexes. Seuls certains algorithmes seront acceptés par le TPM, en fonction de l'utilisation et des conditions.

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour la création par le TPM, ont de nombreux algorithmes à renseigner dans les données publiques. Des éléments tels que le type, le schéma et les détails asymétriques, la taille de la clé, etc. Voici le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de type

Cette partie du spécificateur d'algorithme complexe est requise. Les détails restants du schéma et du symétrique seront par défaut en fonction du type spécifié et du type de l'objet en cours de création.

•
aes - Par défaut AES : aes128
•
aes128<mode> - AES 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, il prend par défaut null.
•
aes192<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - Par défaut SM4 : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, il prend par défaut null.
•
ecc - Courbe elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - Par défaut RSA : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de schéma

Ensuite, il y a un champ optionnel, il peut être sauté.

Les schémas sont généralement des Schémas de signature ou des Schémas de chiffrement asymétrique. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est manquant, il prend par défaut sha256. Certains ne prennent aucun argument et d'autres en prennent plusieurs.

Schémas optionnels de hachage

Ces spécificateurs de schéma sont suivis d'un trait et d'un algorithme de hachage valide. Par exemple : oaep-sha256.

Schémas à options multiples

Ce spécificateur de schéma est suivi d'un nombre (taille max UINT16) puis suivi d'un trait (-) et d'un algorithme de hachage valide. * ecdaa Par exemple, ecdaa4-sha256. Si aucun nombre n'est spécifié, il prend par défaut 4.

Schémas sans options

Ce spécificateur de schéma ne prend AUCUN argument. * rsaes

Nom

tpm2_create - créer une clé TPM2

SYNOPSIS

tpm2_create [OPTIONS] [operand ...]

DESCRIPTION

Le tpm2_create L'utilitaire TPM2 créer un nouvel objet et enregistrer ses détails dans deux fichiers. Les fichiers contiendra la clé publique et la clé privée.

Cette commande est utilisée pour créer un objet clé à partir d'un objet parent.

Un objet clé est un objet public et privé.

OPTIONS

-C context file
Le fichier de contexte de l'objet parent. Cet objet parent sera utilisé pour l'utilisation de l'objet créé.
-G alg:scheme
Ce champ est facultatif, et par défaut basé sur le type d'objet en cours de création et ses attributs. Généralement, tout spécificateur Symétrique valide de la liste Spécificateurs de type devrait fonctionner. Si non spécifié, les détails symétriques d'un objet asymétrique par défaut à aes128cfb.

Exemples

Créer une clé rsa2048 avec un schéma de chiffrement asymétrique rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Créer une clé ecc256 avec un schéma de signature ecdaa avec un compte de 4 et un hachage sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algorithmes cryptographiques ALGORITHME.

OPTIONS COURANTES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page de manuel de l'outil. Par défaut, il tente d'appeler le pager de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option "man" est spécifié, cependant si "man" est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option "no-man" est spécifiée, ou si le pager de manuel échoue, les options courtes seront envoyées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages de manuel, il faut que les pages de manuel soient installées ou présentes dans MANPATH, Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tctis pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque cette option est utilisée, le nom du fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet : Réduit au silence la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des correctifs d'errata. Utile si un correctif d'errata doit être appliqué aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush : Active la suppression automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également supprimé. La suppression automatique peut également être activée si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration du TCTI

Le TCTI ou "Transmission Interface" est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option en ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option en ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lorsque l'on parle directement au fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne prend pas en charge AUCUNE option et DOIT être présenté comme le texte exact de "none".

Les arguments de l'option en ligne de commande ou de la variable d'environnement sont sous la forme :

<tcti-name>:<tcti-option-config>

Spécifier une chaîne vide pour le <tcti-name> ou <tcti-option-config> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Valeurs par défaut du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur "default-tcti" indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique TPM à utiliser par le TCTI device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère ','. Chaque clé et valeur sont séparées par un caractère '='.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifier le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les différents modules TCTI connus.

tpm2_ecephemeral -u ecc.q -t ecc.ctr ecc256

NOM

tpm2_ecephemeral — Crée une clé d'enveloppement éphémère pour l'encapsulation et le déchiffrement d'une clé symétrique

SYNOPIS

tpm2_ecephemeral [OPTIONS] [PARAMÈTRES]

DESCRIPTION

tpm2_ecephemeral est un outil pour créer des clés d'enveloppement éphémères pour encapsuler une clé symétrique à l'aide d'un algorithme à clé publique. L'outil utilise le TPM pour générer une nouvelle paire de clés à clé publique éphémère et une clé symétrique. Il retourne la clé publique éphémère, le SEED, et le ciphertext de la clé symétrique.

OPTIONS

-b, --parent-auth POL_AUTH
Autorisation pour le parent de l'objet de la clé de chiffrement. La valeur par défaut est vide (pas d'autorisation). Le format d'autorisation est la chaîne d'autorisation ou le chemin d'accès au fichier contenant l'autorisation.
-u, --public-key-path PATH
Chemin d'accès où enregistrer la clé publique éphémère.
-o, --output-path PATH
Chemin d'accès où enregistrer le ciphertext de la clé symétrique encapsulée.
-s, --seed-path PATH
Chemin d'accès où enregistrer la SEED utilisée pour générer la clé symétrique.
-a, --alg ALGORITHM
L'algorithme d'encapsulation à utiliser. Les algorithmes pris en charge sont : rsa, ecc. La valeur par défaut est rsa.
-k, --key-size SIZE
La taille de la clé symétrique en bits. Les valeurs prises en charge sont 128, 192, 256. La valeur par défaut est 256.
--kdf KDF_SCHEME
Le schéma KDF à utiliser pour dériver la clé symétrique. Les schémas pris en charge sont : kdfNone, kdfHmac, kdfXor, kdfTls. La valeur par défaut est kdfNone.
--kdf-alg KDF_ALG
L'algorithme de hachage à utiliser pour le KDF. Les algorithmes pris en charge sont : sha1, sha256, sha384, sha512. La valeur par défaut est sha256.
-h, --help
Affiche l'aide et quitte.
-v, --version
Affiche les informations de version et quitte.

RETOURS

Retourne 0 si l'opération réussit, une valeur non nulle en cas d'échec.

Les bogues connus sont documentés sur https://github.com/tpm2-software/tpm2-tools/issues.
