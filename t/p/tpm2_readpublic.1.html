tpm2_readpublic(1) Manuel des commandes générales tpm2_readpublic(1)

NOM

tpm2_readpublic(1) - Lire la zone publique d'un objet chargé.

SYNOPSIS

tpm2_readpublic [OPTIONS]

DESCRIPTION

tpm2_readpublic(1) - Lit la zone publique d'un objet chargé.

OPTIONS

•
-c, --object-context=OBJET:

Objet de contexte pour l'objet à lire.

•
-n, --name=FICHIER:

Un fichier optionnel pour sauvegarder la structure du nom de l'objet.

•
-f, --format:

Sélection du format pour le fichier de sortie de la clé publique. `tss' (par défaut) produira un blob binaire selon la spécification TPM 2.0. `pem' produira une clé publique encodée PEM compatible avec OpenSSL. `der' produira une clé publique encodée DER compatible avec OpenSSL. `tpmt' produira un blob binaire de la structure TPMT_PUBLIC référencée par les spécifications TPM 2.0.

Format de la clé publique.

•
-o, --output=FICHIER:

Le chemin du fichier de sortie, enregistrant la partie publique de l'objet.

•
-t, --serialized-handle=HANDLE:

Si l'objet à lire est un objet persistant spécifié par un handle brut, sauvegarder optionnellement le handle sérialisé pour une utilisation ultérieure. Cette routine ne vérifie PAS le nom de l'objet lu. Les appelants doivent s'assurer que le contenu du nom correspond au nom attendu de l'objet.

•
-q, --qualified-name=FICHIER:

Sauvegarde le nom qualifié de l'objet dans FICHIER. Le nom qualifié de l'objet est le hash de l'algorithme de nom du qualifié du parent et du nom de l'objet. Ainsi, le nom qualifié de l'objet sert de preuve des parents de l'objet.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante, dans l'ordre:

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument est une correspondance de préfixe avec l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie de plateforme
•
endorsement: la hiérarchie d'approbation
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013, et utilisé directement._OBJET_.

Configuration du TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande surcharge toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge le fait de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne prend pas en charge *AUCUNE* option et *DOIT* être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom_tcti>:<config_options_tcti>

La spécification d'une chaîne vide pour le <nom_tcti> ou les <config_options_tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

Sérialiser un handle d'objet persistant existant sur disque pour une utilisation ultérieure

Ce flux de travail est principalement destiné aux objets TPM persistants existants. Ce flux de travail ne vérifie pas que le nom de l'objet sérialisé correspond à celui attendu, et par conséquent, le handle sérialisé pourrait pointer vers un objet contrôlé par un attaquant si aucune vérification n'est effectuée. Si vous créez un objet à partir de zéro, enregistrez le handle sérialisé lors de la création de l'objet persistant.

Nous supposons qu'un objet a déjà été rendu persistant, par exemple via :

# Nous supposons qu'un objet a déjà été rendu persistant, par exemple
tpm2_createprimary -c primary.ctx
# les fichiers de contexte contiennent toutes les informations pour que le TPM vérifie l'objet
tpm2_evictcontrol -c primary.ctx
persistent-handle: 0x81000001
action: persisted

Utilisez ensuite le handle persistant pour obtenir un handle sérialisé :

# Le résultat du handle persistant pourrait se trouver sur un objet contrôlé par un attaquant,
# la meilleure pratique est d'utiliser l'option "-o:" pour tpm2_evictcontrol afin d'obtenir plutôt
# un handle sérialisé.
tpm2_readpublic -c 0x81000001 -o output.dat -f pem -t primary.handle
# utilisez ce handle vérifié dans une session chiffrée avec le tpm
tpm2_startauthsession --policy-session -S session.ctx -c primary.handle

Pour les nouveaux objets, il est préférable d'utiliser tous les handles sérialisés.

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de traitement des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
