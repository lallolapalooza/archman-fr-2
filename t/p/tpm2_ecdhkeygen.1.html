NOM

tpm2_ecdhkeygen(1) - Crée une clé éphémère et l'utilise pour générer la valeur secrète partagée en utilisant les paramètres d'une clé publique ECC.

SYNOPSIS

tpm2_ecdhkeygen [OPTIONS]

DESCRIPTION

tpm2_ecdhkeygen(1) - Crée une clé éphémère et l'utilise pour générer la valeur secrète partagée en utilisant les paramètres d'une clé publique ECC.

OPTIONS

•
-c, --context=FICHIER:

Objet de contexte pointant vers la clé publique ECC. Soit un fichier, soit un numéro de handle. Voir la section « Format de l'objet de contexte ».

•
-u, --public=FICHIER:

Point de sortie ECC Q.

•
-o, --output=FICHIER

Spécifie le chemin du fichier pour sauvegarder le secret ECDH calculé ou le point Z.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. C'est ce qu'on appelle couramment cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash.

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour la création par le TPM, ont de nombreux algorithmes à renseigner dans les données publiques. Par exemple, le type, le schéma et les détails asymétriques, la taille de la clé, etc. Voici le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de type

Cette partie du spécificateur d'algorithme complexe est requise. Le schéma et les détails symétriques restants seront utilisés par défaut en fonction du type spécifié et du type de l'objet créé.

•
aes - AES par défaut : aes128
•
aes128<mode> - AES 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, il est par défaut à null.
•
aes192<mode> - Idem que aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Idem que aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - SM4 par défaut : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, il est par défaut à null.
•
ecc - Courbe elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - RSA par défaut : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de schéma

Ensuite, il y a un champ optionnel, il peut être sauté.

Les schémas sont généralement des Schémas de signature ou des Schémas de chiffrement asymétrique. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est manquant, il est par défaut à sha256. Certains ne prennent aucun argument, et d'autres prennent plusieurs arguments.

Spécificateurs de schéma avec hachage optionnel

Ces spécificateurs de schéma sont suivis d'un trait d'union et d'un algorithme de hachage valide. Par exemple : oaep-sha256.

NAME

tpm2_create - Create a primary key or an object

SYNOPSIS

tpm2_create [OPTIONS] [-u key.pub] [-r key.priv]

DESCRIPTION

The tpm2_create command creates a primary or non-primary object under a specified parent key. The new object can be either a primary key or a policy or regular object.

The command supports creating keys that are asymmetric (RSA or ECC) or symmetric (AES or CAMELLIA).

Primary Key Creation

Primary keys are created using the tpm2_createprimary command. These keys are used to establish the root of trust for objects created within the TPM.

Object Creation with Parent Key

This command creates objects (e.g., keys, seeds) using an existing primary or non-primary key as the parent. The parent key is specified using the -C option.

OPTIONS

-C parent handle or file
Specifies the parent object handle or context file to create the new object under. This is required unless creating a primary key (use tpm2_createprimary for that).
-G key-params
Specifies the key parameters for the object to be created. This is a string that follows the format: <key-type>[:<symmetric-alg>][:<signing-alg>]. The default is rsa2048.
-u public file
The path to the file where the public key is written.
-r private file
The path to the file where the private key is written.
-p password
The password for the parent object.
-f attributes
Specifies the attributes of the object to be created. This is a comma separated list of attributes. For a list of attributes, see the Attributes section.
-l policy-file
The path to the policy file used for authorization.
-i input file
The path to the input file for the object.
-a auth-policy
The authorization policy for the object.

Algorithm Specifiers

The -G option takes a string that specifies the algorithm details for the key being created. The format is generally: <key-type>[:<symmetric-alg>][:<signing-alg>].

Key Types:

  • rsa: RSA key. Requires size specifier like rsa2048, rsa3072, or rsa4096.
  • ecc: Elliptic Curve key. Requires curve specifier like ecc256, ecc384, or ecc521.

Symmetric Algorithms (used with key types that support them, like RSA):

  • rsaes: RSAES encryption scheme.
  • rsassa: RSASSA signing scheme. Requires hash algorithm specifier like rsassa-sha1, rsassa-sha256, etc.

Signing Algorithms (used with ECC keys):

  • ecdaa: ECDAA signing scheme. Requires hash algorithm specifier like ecdaa-sha256.
  • ecdsa: ECDSA signing scheme. Requires hash algorithm specifier like ecdsa-sha256.

Hash Algorithms (used with signing schemes):

  • sha1, sha256, sha384, sha512.

Example Algorithm Specifiers:

  • rsa2048: Creates a 2048-bit RSA key.
  • rsa2048:sha256: Creates a 2048-bit RSA key for signing with SHA-256.
  • ecc256:ecdsa: Creates a 256-bit ECC key for ECDSA signing.
  • ecc384:ecdaa-sha384: Creates a 384-bit ECC key for ECDAA signing with SHA-384.

The default algorithm specifier is rsa2048.

Symmetric Details Specifiers

This field is optional, and defaults based on the type of object being created and it’s attributes. Generally, any valid Symmetric specifier from the Type Specifiers list should work. If not specified, an asymmetric objects symmetric details defaults to aes128cfb.

Examples

Create an rsa2048 key with an rsaes asymmetric encryption scheme

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Create an ecc256 key with an ecdaa signing scheme with a count of 4 and sha384 hash

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv cryptographic algorithms ALGORITHM.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.
