tpm2_changeeps(1) Manuel des commandes générales tpm2_changeeps(1)

NOM

tpm2_changeeps(1) - Remplace la graine primaire d'homologation active par une nouvelle graine générée à partir du RNG du TPM2.

SYNOPSIS

tpm2_changeeps [OPTIONS]

DESCRIPTION

tpm2_changeeps(1) - Remplace la graine primaire d'homologation active par une nouvelle graine générée à partir du RNG du TPM2. Les objets transitoires et persistants sous la hiérarchie d'homologation sont perdus. Cette commande nécessite une authentification de plateforme.

OPTIONS

•
-p, --auth=AUTH

Spécifie le AUTH pour la hiérarchie de plateforme.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. C'est ce qu'on appelle couramment le cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash, sauf si un rphash est également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. C'est ce qu'on appelle couramment le rpHash.

•
-S, --session=FICHIER:

La session créée avec tpm2_startauthsession. Cela peut être utilisé pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

Références

Formatage de l'authentification

L'authentification pour l'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les authentifications par défaut sont le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes ci-dessous en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne de caractères lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'authentification.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: » est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: » doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un « - » pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe transmis en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/mot_de_passe
# pour echo un mot de passe via stdin :
echo foobar | tpm2_tool -p file:-
# pour utiliser une chaîne ici bash via stdin :
tpm2_tool -p file:- <<< foobar

Sessions

Lorsque vous utilisez une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite le chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le descripteur de session (par exemple, un mot de passe de politique), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Authentifications PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie du contenu PCR brut tel que renvoyé par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant le AUTH.

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Typiquement utilisé pour la communication avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne supporte AUCUNE option et DOIT ÊTRE présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou le <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). NAME

tpm2_changeeps — Change the Endorsement Primary Seed (EPS)

SYNOPSIS

tpm2_changeeps [OPTIONS]

DESCRIPTION

The tpm2_changeeps command is used to change the Endorsement Primary Seed (EPS) of the TPM.

The EPS is a crucial seed used in the creation of primary keys within the TPM. Modifying it effectively changes the root of trust for endorsement keys.

This operation requires the platform authorization to be NULL. If the platform authorization is not NULL, the command will fail.

The command needs a valid TCTI context to communicate with the TPM.

TCTI Configuration

The Tool Control Transmission Interface (TCTI) specifies how the tpm2 tools communicate with the TPM. The default TCTI is determined by the TPM2TOOLS_TCTI environment variable or defaults to mssim if not specified. The available TCTIs are:

•
device: Use the TPM character device file. Default is /dev/tpm0.
•
mssim: Use the TPM simulator. Default is host=localhost,port=2321.
•
abrmd: Use the tcti interface of the tpm2-abrmd daemon.

The TCTI can be specified using the -T or --tcti option. For example:

$ tpm2_changeeps -T device:/dev/tpmrm0
$ export TPM2TOOLS_TCTI="mssim:host=127.0.0.1,port=3276"
$ tpm2_changeeps

The tpm2_changeeps command, like other tpm2-tools, will print version information on startup. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,` character. Each key and value string are separated by a `=` character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Changer la graine primaire de cautionnement où l'authentification de la plateforme est NULL.

tpm2_changeeps

Retourne

Les outils peuvent retourner l'un des codes suivants:

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.

Limitations

Il s'attend à ce qu'une session soit déjà établie via tpm2_startauthsession(1) et nécessite l'un des éléments suivants:

•
accès direct à l'appareil
•
prise en charge des sessions étendues avec tpm2-abrmd.

Sans cela, la plupart des gestionnaires de ressources ne sauvegarderont pas l'état de la session entre les invocations de commandes.
