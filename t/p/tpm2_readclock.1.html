NOM

tpm2_readclock(1) - Récupère les informations de temps du TPM.

SYNOPIS

tpm2_readclock [OPTIONS]

DESCRIPTION

tpm2_readclock(1) - Lit la structure TPMS_TIME_INFO actuelle du TPM. La structure contient les valeurs actuelles de Time, Clock, resetCount et restartCount. La structure est affichée en YAML sur la sortie standard. La sortie YAML est définie comme suit :

time: 13673142     # Valeur sur 64 bits du temps pendant lequel le TPM a été alimenté en ms.
clock_info:
  clock: 13673142  # Valeur sur 64 bits du temps pendant lequel le TPM a été alimenté depuis le dernier TPM2_Clear en ms.
  reset_count: 0   # Valeur sur 32 bits du nombre de réinitialisations du TPM depuis le dernier
                   # TPM2_Clear.
  restart_count: 0 # Valeur sur 32 bits du nombre de fois que TPM2_Shutdown ou
                   # _TPM_Hash_Start se sont produits depuis la dernière réinitialisation du TPM ou
                   # le dernier TPM2_Clear.
  safe: yes        # Valeur booléenne oui|non indiquant si aucune valeur de Clock supérieure à
                   # la valeur actuelle de Clock n'a été rapportée précédemment par
                   # le TPM.

Cet outil ne prend aucun argument ni aucune option spécifique à l'outil.

Configuration du TCTI

Le TCTI ou "Interface de Transmission" est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne supporte *AUCUNE* option et *DOIT* être présenté comme le texte exact de "none".

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respective.

Valeurs par défaut du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim DANS CET ORDRE et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur "default-tcti" indiquera lequel des TCTI susmentionnés est le défaut.

TCTI Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI `device`, le fichier de périphérique caractère TPM à utiliser par le TCTI `device` peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI `mssim`, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI `abrmd`, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et valeur sont séparées par un caractère `=`.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session` et `system`.

Spécifier le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les différents modules TCTI connus.
