tpm2_policycommandcode(1) Manuel des commandes générales tpm2_policycommandcode(1)

NOM

tpm2_policycommandcode(1) - Restreindre l'autorisation des objets TPM à des commandes TPM spécifiques.

SYNOPIS

tpm2_policycommandcode [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_policycommandcode(1) - Restreint l'autorisation des objets TPM à des commandes TPM spécifiques. Utile lorsque vous souhaitez autoriser uniquement des commandes spécifiques à interagir avec l'objet TPM.

Comme argument, il accepte le code de commande sous forme d'entier ou de chaîne de caractères conviviale. Le mappage entre chaîne conviviale et code de commande se trouve dans la section CORRESPONDANCES DES CODES DE COMMANDE.

OPTIONS

•
-S, --session=FICHIER:

Un fichier de session provenant de l'option -S de tpm2_startauthsession(1).

•
-L, --policy=FICHIER:

Fichier pour sauvegarder l'empreinte de la politique.

•
ARGUMENT L'argument de ligne de commande spécifie le code de commande TPM2.
•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash.

Références

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche la page man de l'outil. Par défaut, il tente d'invoquer le pager man pour l'outil, mais en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, mais si “man” est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le pager man échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages man, celles-ci doivent être installées ou disponibles dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version pour cet outil, les TCTI pris en charge et quitte.
•
-V, --verbose: Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque cette option est utilisée, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet: Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata: Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush: Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Le vidage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI connus actuellement sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils autorisent les options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT ÊTRE présenté comme le texte exact de “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-option-tcti>

La spécification d'une chaîne vide pour <nom-tcti> ou <configuration-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respective.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTI susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur sont séparées par un caractère `=.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limité à `session' et `system'.

Spécifier le nom TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Démarrez une session de politique et étendez-la avec une commande spécifique comme unseal. Les tentatives d'effectuer d'autres opérations échoueraient.

Créer une politique de déverrouillage unique

tpm2_startauthsession -S session.dat
tpm2_policycommandcode -S session.dat -L policy.dat TPM2_CC_Unseal
tpm2_flushcontext session.dat

Créer l'objet avec une politique d'authentification de déverrouillage unique

tpm2_createprimary -C o -c prim.ctx
tpm2_create -C prim.ctx -u sealkey.pub -r sealkey.priv -L policy.dat \
  -i- <<< "SEALED-SECRET"

Essayer l'opération de déverrouillage

tpm2_load -C prim.ctx -u sealkey.pub -r sealkey.priv -n sealkey.name \
  -c sealkey.ctx
tpm2_startauthsession --policy-session -S session.dat
tpm2_policycommandcode -S session.dat -L policy.dat TPM2_CC_Unseal
tpm2_unseal -p session:session.dat -c sealkey.ctx
SEALED-SECRET
tpm2_flushcontext session.dat

Essayer toute autre opération

echo "Encrypt Me" > plain.txt
tpm2_encryptdecrypt plain.txt -o enc.txt -c sealkey.ctx plain.txt
ERROR: Esys_EncryptDecrypt2(0x12F) - tpm:error(2.0): authValue or authPolicy is
not available for selected entity

Retours

Les outils peuvent renvoyer l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.

Limitations

Il attend qu'une session soit déjà établie via tpm2_startauthsession(1) et nécessite l'une des options suivantes :

•
accès direct au périphérique
•
support de session étendue avec tpm2-abrmd.

Sans cela, la plupart des gestionnaires de ressources ne sauvegarderont pas l'état de la session entre les invocations de commande.
