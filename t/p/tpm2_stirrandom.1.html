tpm2_stirrandom(1) Manuel des commandes générales tpm2_stirrandom(1)

NOM

tpm2_stirrandom(1) - Ajoute des « informations supplémentaires » dans l'état du générateur de nombres aléatoires du TPM.

SYNTAXE

tpm2_stirrandom [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_stirrandom(1) - Injecte des « informations supplémentaires » sous forme d'octets dans le pool de capacités protégées par entropie du TPM.

Les « informations supplémentaires » peuvent être extraites d'un fichier spécifié comme argument ou lues depuis STDIN si aucun argument n'est spécifié.

Jusqu'à 128 octets peuvent être injectés en une seule fois via l'entrée standard vers tpm2_stirrandom(1).

Si le fichier d'entrée est plus grand que 128 octets, tpm2_stirrandom(1) échouera.

L'ajout de données via tpm2_stirrandom(1) déclenchera un re-semis du générateur de nombres aléatoires protégé par capacité du TPM. Il est utilisé lors de l'exécution de toute action sensible sur un emplacement protégé tel que le chargement d'une clé persistante ou l'action sur une capacité protégée comme la mise à jour du firmware du TPM.

OPTIONS

Cette commande n'a pas d'option.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche le manuel de l'outil. Par défaut, il tente d'appeler le pagineur de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » explicite est demandé, l'outil fournira des erreurs de man sur la sortie d'erreur standard. Si l'option « no-man » est spécifiée, ou si le pagineur de manuel échoue, les options courtes seront affichées sur la sortie standard.

Pour utiliser correctement la fonctionnalité des pages de manuel, celles-ci doivent être installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version de cet outil, les tcti pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur la sortie standard.
•
-Z, --enable-errata : Active l'application des corrections d'erreurs. Utile si une correction d'erreur doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Le vidage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande a toujours priorité sur la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils autorisent les options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne prend pas en charge *AUCUNE* option et *DOIT* être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom_tcti>:<configuration_option_tcti>

La spécification d'une chaîne vide pour <nom_tcti> ou <configuration_option_tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera quel TCTI parmi ceux mentionnés ci-dessus est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom_tcti est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI de périphérique, le fichier du périphérique caractère TPM à utiliser par le TCTI de périphérique peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère « , ». Chaque clé et chaîne de valeur sont séparées par un caractère « = ».
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifiez le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.)

Exemples

Injecter 64 octets depuis stdin en utilisant un fichier

dd if=/dev/urandom bs=1 count=64 > myrandom.bin
tpm2_stirrandom < ./myrandom.bin

Injecter des octets depuis un fichier et lire jusqu'à 128 octets

dd if=/dev/urandom of=./myrandom.bin bs=1 count=42
tpm2_stirrandom ./myrandom.bin

NOTES

Veuillez noter que même si les « informations supplémentaires » ajoutées par tpm2_stirrandom(1) peuvent être de l'entropie collectée à partir d'autres sources DRBG, le TPM n'a aucun moyen de déterminer si la valeur possède ou non de l'entropie. Par conséquent, elle sera simplement considérée comme une « entrée supplémentaire ».

L'« entrée supplémentaire » est telle que définie dans https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-90.pdf NIST SP800-90A

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
