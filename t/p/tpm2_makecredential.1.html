tpm2_makecredential(1) Manuel des commandes générales tpm2_makecredential(1)

NOM

tpm2_makecredential(1) - Génère les données chiffrées choisies par l'utilisateur et la clé de chiffrement des données encapsulées pour le processus d'accréditation respectueux de la vie privée d'un objet TPM.

SYNTAXE

tpm2_makecredential [OPTIONS]

DESCRIPTION

tpm2_makecredential(1) - Le TPM prend en charge un protocole de préservation de la vie privée pour la distribution des identifiants pour les clés sur un TPM. Le processus garantit que l'objet TPM accrédité (AIK) est chargé sur le même TPM qu'un objet clé publique bien connu (EK) sans connaître les propriétés publiques spécifiques de l'objet TPM accrédité (AIK). La vie privée est garantie du fait que seul le nom de l'objet TPM accrédité (AIK) est partagé et non la clé publique de l'objet TPM accrédité elle-même.

La génération d'identifiants est la première étape de ce processus, où, après réception de la clé publique de l'objet clé publique (EK) du TPM et du nom de l'objet TPM accrédité (AIK), des données chiffrées choisies par l'utilisateur sont générées et la clé de chiffrement des données secrètes est générée et encapsulée à l'aide de processus cryptographiques spécifiques à l'activation des identifiants, ce qui garantit que l'objet TPM accrédité (AIK) est chargé sur le TPM avec l'objet clé publique bien connu (EK).

tpm2_makecredential peut être utilisé pour générer les données chiffrées choisies par l'utilisateur et la clé de chiffrement des données secrètes encapsulée sans TPM en utilisant l'option TCTI none.

OPTIONS

•
-e, --encryption-key=FICHIER:

OBSOLÈTE, utilisez -u ou –public à la place.

•
-u, --public=FICHIER:

Une clé publique TPM qui a été utilisée pour encapsuler la graine. REMARQUE : Cette option est identique à -e et est ajoutée pour la rendre similaire aux autres outils spécifiant la clé publique. L'ancienne option est conservée pour des raisons de compatibilité ascendante.

•
-G, --key-algorithm=ALGORITHME:

L'algorithme de clé associé à la clé publique TPM. Spécifiez RSA ou ECC. Lorsque cette option est utilisée, la clé publique d'entrée est attendue au format PEM et le modèle EK TCG par défaut est utilisé pour les propriétés de la clé.

•
-s, --secret=FICHIER ou STDIN:

Le secret qui sera protégé par la clé dérivée de la graine aléatoire. Il peut être spécifié comme un fichier ou passé via stdin.

•
-n, --name=FICHIER:

Le nom de la clé pour laquelle le certificat doit être créé.

•
-o, --credential-blob=FICHIER:

Le chemin du fichier de sortie, enregistrant les données chiffrées choisies par l'utilisateur et la clé de chiffrement des données secrètes encapsulée.

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne prend pas en charge AUCUNE option et DOIT être présenté sous la forme exacte de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> utilise la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera quel TCTI parmi ceux mentionnés ci-dessus est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

tpm2_makecredential(1) — tpm2-tools

DESCRIPTION

Le tpm2_makecredential est un outil qui sera utilisé pour créer un objet credentiel.

L'attribut `credential` d'un objet TPM2 peut être utilisé pour stocker des données sensibles qui nécessitent une authentification avant de pouvoir être accédées.

L'outil tpm2_makecredential créera un credentiel à partir des données d'entrée pour l'utilisation avec un objet TPM2 existant. Un des cas d'utilisation courant est de fournir un identifiant pour la création d'une clé d'attestation.

Il est nécessaire de fournir un objet de contexte pour un objet TPM2 existant. Ceci est généralement réalisé en spécifiant le handle de l'objet TPM2.

Ce programme implémente la commande TPM2 `TPM2_MakeCredential`.

Par défaut, cet outil utilisera le TCTI par défaut.

Pour plus d'informations sur les TCTI, voir la page de manuel tpm2_options(7).

SYNOPSIS

tpm2_makecredential [OPTIONS]

OPTIONS

-C OBJECT
Le handle de l'objet TPM2 que l'on souhaite utiliser pour la création du credentiel. Ceci peut être un handle d'un objet clé, ou le handle de l'EVIER (Endorsement Hierarchy).
-u AUTH_DATA
Les données d'authentification du credentiel. Ceci peut être un fichier contenant les données brutes, ou un objet créé via une autre commande comme tpm2_createek ou tpm2_createak.
-r DATA
Un fichier contenant la clé publique de l'objet TPM2. Si non fourni, il sera lu à partir de tpm2_getcap.
-n NAME
Le nom de l'objet TPM2 dont les données sont utilisées pour la création du credentiel. Si non fourni, le nom sera lu à partir de tpm2_getcap.
-o OUTFILE
Un fichier pour écrire les données du credentiel. Par défaut, il sera écrit sur la sortie standard.
-p PASSWORD
Le mot de passe à utiliser pour la création du credentiel. Si non fourni, il sera lu à partir de l'entrée standard.
-s
Indique que les données d'authentification sont signées par la clé privée. Ceci est utilisé pour les credentiels de type `attestation credentials`.
-G [rsa|ecc]
Permet de spécifier le schéma de cryptographie utilisé pour la création de la clé. Par défaut, il utilisera RSA.
-f [pem|bin]
Permet de spécifier le format de sortie de la clé publique. Par défaut, il utilisera le format binaire.
-Q
Mode silencieux.
-t TCTI
Spécifie le TCTI à utiliser pour communiquer avec le TPM. Pour plus d'informations, voir TCTI Configuration ci-dessous.
--help
Affiche l'aide et quitte.
--version
Affiche les informations de version et quitte.

COMMON OPTIONS

Ces options sont communes à la plupart des outils tpm2. Pour plus d'informations, voir tpm2_options(7).

TCTI Configuration

Le paramètre TCTI permet de configurer la manière dont l'outil communique avec le module TPM (TPM Device).

mssim: Pour le TCTI mssim, le format de la chaîne de configuration est une liste de paires clé-valeur séparées par un caractère `,`. Chaque paire est de la forme `key=value`.

Les clés supportées sont:

`host'
L'adresse IP de l'hôte où le simulateur TPM est en cours d'exécution. La valeur par défaut est 127.0.0.1.
`port'
Le port sur lequel le simulateur TPM est en cours d'exécution. La valeur par défaut est 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et valeur sont séparées par un caractère `=`.
abrmd supporte deux clés:
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd et tabrmd sont synonymes.

EXAMPLES

tpm2 createek -Q -c 0x81010009 -G rsa -u ek.pub
tpm2 createak -C 0x81010009 -c ak.ctx -G rsa -g sha256 -s rsassa -u ak.pub \
-n ak.name -p akpass> ak.out
file_size=`ls -l ak.name | awk {'print $5'}`
loaded_key_name=`cat ak.name | xxd -p -c $file_size`
tpm2 readpublic -c 0x81010009 -o ek.pem -f pem -Q
echo "12345678" | tpm2 makecredential -Q -u ek.pem -s - -n $loaded_key_name \
-o mkcred.out -G rsa

Returns

Les outils peuvent retourner l'un des codes suivants:

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
