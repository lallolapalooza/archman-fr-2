NOM

tpm2_gettestresult(1) - Obtenir le résultat des tests effectués par le TPM

SYNOPIS

tpm2_gettestresult [OPTIONS]

DESCRIPTION

tpm2_gettestresult(1) retournera le résultat des tests effectués par le TPM.

Le code d'erreur indiquera si le test s'est exécuté avec succès ou s'il a échoué.

Si des algorithmes en attente sont programmés pour être testés, tpm2_gettestresult retournera “TESTING”. Sinon, “FAILED” sera retourné ou “SUCCESS” en fonction du résultat du test.

Les informations dépendant du fabricant seront également imprimées au format hexadécimal brut.

OPTIONS

Cet outil n'accepte aucune option spécifique à l'outil.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche le manuel de l'outil. Par défaut, il tente d'appeler le pagemaker de manuel pour l'outil, mais en cas d'échec, il affiche un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, mais si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le pagemaker de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages de manuel, il faut que les pages de manuel soient installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tctis pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil affiche sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont affichés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également purgé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true.

Configuration TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande a toujours priorité sur la variable d'environnement.

Les TCTIs connus actuellement sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé pour communiquer directement avec le fichier de périphérique du TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils autorisent les options hors-tpm et prennent donc en charge l'absence d'utilisation d'un TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne prend pas en charge *AUCUNE* option et *DOIT ÊTRE* présenté comme le texte exact de “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <config-options-tcti> utilise la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, il peut s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier du périphérique caractère du TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et valeur de chaîne sont séparées par un caractère `= `.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name` : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type` : Le type de l'instance dbus (une chaîne de caractères) limitée à `session` et `system`.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes.

EXEMPLES

Obtenir le résultat des tests du TPM

tpm2_gettestresult

NOTES

Cette commande est l'une des rares commandes autorisées à être soumises au TPM en mode défaillance.

Retour

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Auth

tpm2_gettestresult(1) — tpm2-tools

NAME

tpm2_gettestresult - get the results of the TPM test interface

SYNOPSIS

tpm2_gettestresult [OPTIONS]

DESCRIPTION

The tpm2_gettestresult command is used to query the TPM's test interface and retrieve the results of the TPM test. This command is useful for debugging and verifying the TPM's functionality.

OPTIONS

•
-h, --help
Help information.
•
-v, --version
Return version information.
•
-c, --cancel
Cancel the ongoing test.
•
-f, --force
Force the test to start even if it is already running.

COMMON OPTIONS

These options are common to all tpm2-tools and allow the user to specify the TPM device, the command's policy, and other common settings.

•
-T, --tcti tcti-name
Tab separated list of TCTI options. Default is libtspi.
•
-I, --interface tcti-name
Same as --tcti.
•
-C, --context file
Load TPM context from file.
•
-P, --password password
Password for TPM operations.
•
-e, --enable-hashes
Enable hashes in output.
•
-p, --policy file
Policy file.

TCTI Configuration

The TCTI (TPM Command Transmission Interface) specifies how the tpm2-tools communicate with the TPM device. The --tcti option accepts a comma-separated list of TCTI specifications. The following TCTIs are commonly supported:

•
device
Use the device driver (/dev/tpm0 or similar).
•
mssim
Use the Microsoft Simulator.
•
swtpm
Use the software TPM simulator.

For more details on TCTI configuration, refer to the tpm2-tcti man page.

TCTI OPTIONS

•
device:
path=/dev/tpm0
port=some_port
•
mssim:
host=127.0.0.1
port=2321
•
swtpm:
host=127.0.0.1
port=2322

EXAMPLES

To retrieve the results of the TPM test:

$ tpm2_gettestresult

To cancel an ongoing TPM test:

$ tpm2_gettestresult -c

NOTES

The TPM test interface is a diagnostic tool and may not be available on all TPMs or may require specific configurations.

Returns

The command returns 0 on success, and a non-zero value on failure. The specific return codes indicate the following:

•
0 - Success.
•
1 - General error.
•
2 - TPM error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
