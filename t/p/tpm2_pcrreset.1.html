tpm2_pcrreset(1) Manuel des commandes générales tpm2_pcrreset(1)

NOM

tpm2_pcrreset(1) - Réinitialiser une ou plusieurs banques de PCR

SYNTAXE

tpm2_pcrreset [OPTIONS] INDEX_PCR ...

DESCRIPTION

tpm2_pcrreset(1) - Réinitialise la valeur PCR dans toutes les banques pour l'index spécifié. Plusieurs index de PCR peuvent être spécifiés.

La valeur de réinitialisation dépend du fabricant et est soit une séquence de 00 soit de FF sur la longueur de l'algorithme de hachage pour chaque banque prise en charge.

INDEX_PCR est une liste d'index de PCR séparés par des espaces à réinitialiser lors de l'exécution de la commande.

OPTIONS

Cet outil n'accepte aucune option spécifique.

•
--cphash=FICHIER

Chemin d'accès au fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche la page de manuel de l'outil. Par défaut, il tente d'appeler le pager man pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le pager man échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages man, il faut que les pages man soient installées ou présentes dans MANPATH. Consultez man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version pour cet outil, les tcti pris en charge et quitte.
•
-V, --verbose: Augmente les informations que l'outil imprime sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet: Silence la sortie normale de l'outil vers stdout.
•
-Z, --enable-errata: Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush: Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true.

Configuration du TCTI

Le TCTI ou « Transmission Interface » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel de TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne prend pas en charge AUCUNE option et DOIT être présenté sous la forme exacte « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom_tcti>:<config_option_tcti>

Spécifier une chaîne vide pour <nom_tcti> ou <config_option_tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché à l'aide de la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim dans **cet ordre** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera quel TCTI parmi ceux mentionnés ci-dessus est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom_tcti est utilisée pour la recherche. Ainsi, il peut s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'interprété par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et chaîne de valeur sont séparées par un caractère `=`.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes.

tpm2_pcrreset 23

Réinitialiser plusieurs PCRs

tpm2_pcrreset 16 23

NAME

tpm2_pcrreset

reset PCRs

SYNOPSIS

tpm2_pcrreset [-C context] [-P password] [-p pcr_index]...

DESCRIPTION

tpm2_pcrreset is used to reset the values of one or more Platform Configuration Registers (PCRs) to zero.

The command requires authorization with the Owner authorization value to reset PCRs.

Note that not all PCRs are resettable. PCR 0 to 15 are part of the Static Root of Trust Measurement (SRTM) and are not resettable. PCRs 16 to 22 are generally reserved for Dynamic Root of Trust Measurement (DRTM) or are otherwise allocated for specific functionalities and may not be resettable depending on the TPM manufacturer's implementation and the current TPM locality.

OPTIONS

The options are:

-C context
The context of the primary key for the loaded session. For this command, it is typically the owner authorization.
-P password
The password for the authorization value specified with -C. If the authorization value is not set, this option is ignored.
-p pcr_index
Specifies the PCR index to reset. This option can be specified multiple times to reset multiple PCRs. The indices are 0-based.

COMMON OPTIONS

See tpm2_tool.common(7) for options that are common to all tpm2-* tools.

TCTI Configuration

The TPM Communication Interface (TCTI) is used to communicate with the TPM. The default TCTI is the socket TCTI, which is configured via environment variables. For more information, see tpm2_tool.common(7).

TCTI OPTIONS

The following TCTI options are supported:

-T tcti-list
Specify the TCTI library to use for connecting to the TPM.

For example:

-T mssim for the mssim simulator.

-T device for the device TCTI.

-T mssim:host=localhost,port=6677 for a remote mssim simulator.

EXAMPLES

Reset PCR 17 and PCR 18:

$ tpm2_pcrreset -P owner_password -p 17 -p 18

NOTES

PCR 0 to 15 are part of the Static Root of Trust Measurement (SRTM) and cannot be reset. The TPM specification dictates that these PCRs are controlled by the firmware and are only reset upon TPM reset or system reboot.

PCRs 16 to 22 are often reserved for Dynamic Root of Trust Measurement (DRTM) or other specific functionalities. Whether these PCRs are resettable depends on the TPM manufacturer's implementation and the current TPM locality. Some TPMs might allow resetting these PCRs under specific conditions (e.g., when the TPM is in a specific locality or when specific authorization is provided), while others may not allow it at all.

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

NOM

tpm2_pcrreset

réinitialiser les PCR

SYNTAXE

tpm2_pcrreset [-C contexte] [-P mot_de_passe] [-p index_pcr]...

DESCRIPTION

tpm2_pcrreset est utilisé pour réinitialiser les valeurs d'un ou plusieurs registres de configuration de plateforme (PCR) à zéro.

La commande nécessite une autorisation avec la valeur d'autorisation Propriétaire pour réinitialiser les PCR.

Notez que tous les PCR ne sont pas réinitialisables. Les PCR 0 à 15 font partie de la racine statique de mesure de confiance (SRTM) et ne sont pas réinitialisables. Les PCR 16 à 22 sont généralement réservés à la mesure dynamique de confiance (DRTM) ou sont dédiés à des localités spécifiques et pourraient ne pas être réinitialisables en fonction de l'implémentation du fabricant du TPM et de la localité actuelle du TPM.

OPTIONS

Les options sont :

-C contexte
Le contexte de la clé primaire de la session chargée. Pour cette commande, il s'agit généralement de l'autorisation du propriétaire.
-P mot_de_passe
Le mot de passe de la valeur d'autorisation spécifiée avec -C. Si la valeur d'autorisation n'est pas définie, cette option est ignorée.
-p index_pcr
Spécifie l'indice du PCR à réinitialiser. Cette option peut être spécifiée plusieurs fois pour réinitialiser plusieurs PCR. Les indices sont basés sur zéro.

OPTIONS COMMUNES

Voir tpm2_tool.common(7) pour les options communes à tous les outils tpm2-*.

Configuration TCTI

L'interface de communication TPM (TCTI) est utilisée pour communiquer avec le TPM. Le TCTI par défaut est le TCTI de socket, qui est configuré via des variables d'environnement. Pour plus d'informations, voir tpm2_tool.common(7).

OPTIONS TCTI

Les options TCTI suivantes sont prises en charge :

-T liste_tcti
Spécifiez la bibliothèque TCTI à utiliser pour se connecter au TPM.

Par exemple :

-T mssim pour le simulateur mssim.

-T device pour le TCTI de périphérique.

-T mssim:host=localhost,port=6677 pour un simulateur mssim distant.

EXEMPLES

Réinitialiser les PCR 17 et 18 :

$ tpm2_pcrreset -P mot_de_passe_proprietaire -p 17 -p 18

NOTES

Les PCR 0 à 15 font partie de la racine statique de mesure de confiance (SRTM) et ne peuvent pas être réinitialisés. La spécification du TPM stipule que ces PCR sont contrôlés par le firmware et ne sont réinitialisés qu'à la réinitialisation du TPM ou au redémarrage du système.

Les PCR 16 à 22 sont souvent réservés à la mesure dynamique de confiance (DRTM) ou à d'autres fonctionnalités spécifiques. Que ces PCR soient réinitialisables dépend de l'implémentation du fabricant du TPM et de la localité actuelle du TPM. Certains TPM peuvent permettre de réinitialiser ces PCR dans des conditions spécifiques (par exemple, lorsque le TPM est dans une localité spécifique ou lorsqu'une autorisation spécifique est fournie), tandis que d'autres peuvent ne pas le permettre du tout.

Retour

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
