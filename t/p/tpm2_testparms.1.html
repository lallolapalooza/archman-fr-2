NOM

tpm2_testparms(1) - Vérifie que la suite d'algorithmes spécifiée est prise en charge par le TPM

SYNOPSIS

tpm2_testparms [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_testparms(1) - Vérifie que la suite spécifiée par ALG_SPEC est disponible pour l'utilisation selon ALGORITHM.

Les algorithmes doivent suivre les « normes de formatage », voir la section « Spécificateurs d'algorithmes ».

Voir également la section « Schémas de signature pris en charge » pour une liste des algorithmes de hachage pris en charge.

OPTIONS

Cet outil n'accepte aucune option spécifique à l'outil.

Références

OPTIONS COMMUNES

Cette collection d'options sont communes à de nombreux programmes et fournissent des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche le manuel de l'outil. Par défaut, il tente d'appeler le pagineur de manuel pour l'outil, cependant, en cas d'échec, il affiche un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le pagineur de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser correctement la fonctionnalité de manuel, il faut que les pages du manuel soient installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tctis pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil affiche sur la console pendant son exécution. En utilisant cette option, le fichier et le numéro de ligne sont affichés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également purgé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande a toujours priorité sur la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique du TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge échoueront lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend en charge *AUCUNE* option et *DOIT* être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <configuration-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, il peut s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère du TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et chaîne de valeur sont séparées par un caractère `=`.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name` : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type` : Le type de l'instance dbus (une chaîne) limitée à `session` et `system`.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les différents modules TCTI connus.

Les options qui acceptent des algorithmes prennent en charge les « noms conviviaux ».

Il existe deux classes principales de chaînes de spécification d'algorithmes, simples et complexes. Seuls certains algorithmes seront acceptés par le TPM, en fonction de l'utilisation et des conditions.

Nom

tpm2_create - Créer un objet clé TPM

Synopsis

std
tpm2_create [OPTIONS] -u PRIMARY_KEY_OUT -r PRIMARY_KEY_PRIV_OUT

Description

tpm2_create est un utilitaire qui permet de créer des clés TPM. La création d'une clé consomme un Primary Key Handle (le créateur de la clé) et produit une clé enfant. La clé enfant est composée d'un fichier de données publiques et d'un fichier de données privées.

La clé parente est spécifiée par l'option -C, PARENT_KEY_HANDLE. Il peut s'agir d'un handle que le TPM charge lors de l'initialisation (par exemple, owner, platform, storage) ou d'un contexte d'un objet clé qui a déjà été chargé en mémoire avec tpm2_load.

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour création par le TPM, ont de nombreux algorithmes à peupler dans les données publiques. Des éléments tels que le type, le schéma et les détails asymétriques, la taille de la clé, etc. Voici le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de type

Cette partie du spécificateur d'algorithme complexe est requise. Les détails restants du schéma et les détails symétriques seront par défaut en fonction du type spécifié et du type de l'objet en cours de création.

•
aes - AES par défaut : aes128
•
aes128<mode> - AES 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
aes192<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - SM4 par défaut : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
ecc - Courbe elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - RSA par défaut : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de schéma

Ensuite, il y a un champ facultatif, il peut être ignoré.

Les schémas sont généralement des Schémas de signature ou des Schémas de chiffrement asymétrique. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est manquant, la valeur par défaut est sha256. Certains ne prennent aucun argument, et d'autres prennent plusieurs arguments.

Spécificateurs de schéma optionnels de hachage

Ces spécificateurs de schéma sont suivis d'un trait d'union et d'un algorithme de hachage valide. Par exemple : oaep-sha256.

Spécificateurs de schéma multi-options

Ce spécificateur de schéma est suivi d'un compteur (taille maximale UINT16) puis d'un trait d'union (-) et d'un algorithme de hachage valide. * ecdaa Par exemple, ecdaa4-sha256. Si aucun compteur n'est spécifié, la valeur par défaut est 4.

Spécificateurs de schéma sans option

Ce spécificateur de schéma ne prend AUCUN argument. * rsaes

Spécificateurs de détails symétriques

Ce champ est facultatif et par défaut en fonction du type d'objet en cours de création et de ses attributs. En général, tout spécificateur Symétrique valide de la liste des Spécificateurs de type devrait fonctionner. S'il n'est pas spécifié, les détails symétriques d'un objet asymétrique sont par défaut aes128cfb.

Exemples

Créer une clé rsa2048 avec un schéma de chiffrement asymétrique rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Créer une clé ecc256 avec un schéma de signature ecdaa avec un compteur de 4 et un hachage sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algorithmes cryptographiques ALGORITHME.

Spécificateurs de format de signature

Sélection du format pour le fichier de sortie de signature. tss (la valeur par défaut) produira un blob binaire conformément aux spécifications de TPM 2.0 et à tout éventuel remplissage du compilateur. L'option plain produira les données de signature brutes telles que définies par l'algorithme cryptographique utilisé.

EXEMPLES

Vérifier si "rsa" est supporté

tpm2_testparms rsa

Vérifier que ECDSA utilisant P-256 avec AES-128 en mode CTR est disponible

tpm2_testparms ecc256:ecdsa:aes128ctr

Retourne

Les utilitaires peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.

    SYNOPIS

    tpm2_testparms [OPTIONS] [FICHIERS]

    DESCRIPTION

    La commande tpm2_testparms teste les paramètres de configuration TCTI pour les utilitaires TPM2. Les paramètres sont fournis sous la forme d'une liste de chaînes de caractères séparées par des virgules, où chaque chaîne est dans le format "clé=valeur". Les valeurs peuvent être des chaînes de caractères simples, des chaînes de caractères entre guillemets ou des chaînes de caractères entre accolades.

    Les utilitaires TPM2 utilisent le champ de configuration TCTI pour localiser et initialiser le pilote TCTI (transport layer communication interface) afin de communiquer avec le périphérique TPM.

    La commande tpm2_testparms peut être utilisée pour vérifier la validité de ces paramètres avant de les utiliser dans des scripts ou dans d'autres configurations.

    OPTIONS

    Aucune option spécifique à cette commande n'est documentée ici. Les options générales sont décrites dans la section OPTIONS COMMUNES.

    OPTIONS COMMUNES

    Les options suivantes sont disponibles pour la plupart des commandes tpm2 :

    -h, --help
    Affiche un message d'aide et quitte.
    -v, --version
    Affiche les informations de version et quitte.
    -c, --clear
    Efface toutes les données de configuration TCTI.
    -f, --force
    Force l'écrasement des configurations existantes.
    -p, --path=chemin
    Spécifie le chemin du fichier de configuration TCTI.

    Configuration TCTI

    La configuration TCTI est une chaîne de caractères contenant des paires clé=valeur qui définissent comment se connecter au TPM. Les clés et valeurs courantes incluent :

    • device : Le chemin vers le périphérique TCTI (par exemple, /dev/tpm0).
    • host : L'adresse IP ou le nom d'hôte du périphérique TPM distant.
    • port : Le port sur lequel le périphérique TPM distant est accessible.
    • use-raw-bytes : Booléen, spécifie si les données brutes doivent être utilisées.

    OPTIONS TCTI

    Les options TCTI spécifiques dépendent du pilote TCTI utilisé. Par exemple, pour le TCTI libtsp, vous pouvez avoir des options comme :

    • --tcti-list : Liste les TCTI disponibles.
    • --tcti-name=nom : Spécifie le nom du TCTI à utiliser.

    Pour plus de détails sur les options TCTI spécifiques, consultez la documentation du pilote TCTI correspondant.

    Spécificateurs d'algorithmes

    Vous pouvez spécifier des algorithmes de chiffrement et de signature pour diverses opérations TPM. Les spécificateurs courants incluent :

    • rsa : Algorithme RSA.
    • ecc : Algorithme ECC (Elliptic Curve Cryptography).
    • sha1, sha256, sha384, sha512 : Algorithmes de hachage.

    Spécificateurs de format de signature

    Les spécificateurs de format de signature définissent la manière dont les signatures sont formatées. Les options courantes incluent :

    • pkcs1 : Format PKCS#1.
    • der : Format DER (Distinguished Encoding Rules).

    EXEMPLES

    Testez une configuration TCTI simple pour un périphérique local :

    $ tpm2_testparms --tcti-conf "device=/dev/tpm0"

    Testez une configuration TCTI pour un périphérique distant via TCP :

    $ tpm2_testparms --tcti-conf "host=192.168.1.100,port=2321"

    Testez une configuration TCTI avec des spécificateurs d'algorithmes et de format de signature :

    $ tpm2_testparms --tcti-conf "device=/dev/tpm0" --alg rsa --sig-hash sha256 --sig-format pkcs1

    Retour

    0 si la configuration TCTI est valide, une valeur différente de zéro en cas d'erreur.
