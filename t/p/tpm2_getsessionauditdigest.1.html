tpm2_getsessionauditdigest(1) Manuel des commandes générales tpm2_getsessionauditdigest(1)

NOM

tpm2_getsessionauditdigest(1) - Récupérer les données d'attestation d'audit de commande du TPM.

SYNOPSIS

tpm2_getsessionauditdigest [OPTIONS]

DESCRIPTION

tpm2_getsessionauditdigest(1) - Récupérer les données d'attestation de résumé d'audit de session du TPM. Les données d'attestation incluent le résumé d'audit de session et une signature sur le résumé d'audit de session. La session elle-même est démarrée avec la commande tpm2_startauthsession.

OPTIONS

•
-P, --hierarchy-auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie d'endossement.

•
-c, --key-context=OBJECT:

Objet de contexte pour la clé de signature qui signe les données d'attestation.

•
-p, --auth=AUTH:

Spécifie la valeur d'autorisation pour la clé spécifiée par l'option -c.

•
-q, --qualification=CHAINE_HEX_OU_FICHIER:

Données fournies sous forme de chaîne hexadécimale ou de fichier binaire pour qualifier la citation, facultatif. Ceci est généralement utilisé pour ajouter un nonce contre les attaques par rejeu.

•
-s, --signature=FICHIER:

Fichier de sortie de signature, enregistre la signature dans le format spécifié via l'option -f.

•
-m, --message=FICHIER:

Fichier de sortie de message, enregistre le message de citation qui constitue les données signées par le TPM. Ce sont les données d'attestation de résumé d'audit de commande.

•
-f, --format=FORMAT:

Sélection du format pour le fichier de sortie de signature.

•
-g, --hash-algorithm:

Algorithme de hachage pour la signature. Par défaut, sha256.

•
--scheme=ALGORITHME:

Le schéma de signature utilisé pour signer le message. Facultatif. Les schémas de signature doivent suivre les « normes de formatage », voir la section « Spécificateurs d'algorithmes ». Voir également la section « Schémas de signature pris en charge » pour une liste des schémas de signature pris en charge. Si spécifié, le schéma de signature doit correspondre au type de clé. S'il n'est pas spécifié, un schéma de signature par défaut pour le type de clé sera utilisé.

•
-S, --session=FICHIER:

Le chemin de la session qui active et enregistre les résumés d'audit.

Références

Format de l'Objet de Contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante, dans l'ordre :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à une préfixe de l'un des éléments suivants :
•
owner : la hiérarchie propriétaire
•
platform : la hiérarchie de plateforme
•
endorsement : la hiérarchie d'endossement
•
lockout : l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.

Formatage de l'Autorisation

L'autorisation pour l'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes ci-dessous en utilisant des identifiants de préfixe.

Remarque : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe “str:” ou son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne Hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe “hex:” est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe avec des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe “file:”, doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un “-” pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche la fuite d'informations, les mots de passe passés en tant qu'options pouvant être lus à partir de la liste des processus ou des fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour envoyer un mot de passe via stdin :
echo monmotdepasse | tpm2_tool -p file:-
# pour utiliser une chaîne ici bash via stdin :
tpm2_tool -p file:- <<< monmotdepasse

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + suivi d'une chaîne telle que décrite dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEXADECIMALE 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe “pcr:” et le mini-langage PCR. Le mini-langage PCR est le suivant : <sp%C3%A9cificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument facultatif qui contient la sortie du contenu PCR brut tel que renvoyé par tpm2_pcrread(1).

Spécificateurs de banque PCR

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

spécifiant AUTH.

Spécificateurs de Format de Signature

Sélection du format pour le fichier de sortie de la signature. tss (la valeur par défaut) produira un bloc binaire conformément à la spécification TPM 2.0 et à tout remplissage potentiel du compilateur. L'option plain produira les données de signature brutes telles que définies par l'algorithme cryptographique utilisé. signature FORMAT.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche le manuel de l'outil. Par défaut, il tente d'appeler le pager man pour l'outil, cependant, en cas d'échec, il affichera un résumé court de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le pager man échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité de pages man, il faut que les pages man soient installées ou sur MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tctis supportés et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque vous utilisez cette option, le numéro de fichier et de ligne sont imprimés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également purgé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors-TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant les sémantiques de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est par défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par les sémantiques de dlopen(3).

OPTIONS DU TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI de périphérique, le fichier de périphérique caractère TPM à utiliser par le TCTI de périphérique peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque chaîne clé et valeur sont séparées par un caractère `=`.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les différents modules TCTI connus.

EXEMPLES

tpm2_createprimary -Q -C e -c prim.ctx
tpm2_create -Q -C prim.ctx -c signing_key.ctx -u signing_key.pub \
-r signing_key.priv
tpm2_startauthsession -S session.ctx --audit-session
tpm2_getrandom 8 -S session.ctx
tpm2_getsessionauditdigest -c signing_key.ctx -m att.data -s att.sig \
-S session.ctx

Retour

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
