tpm2_createpolicy(1) Manuel des commandes générales tpm2_createpolicy(1)

NOM

tpm2_createpolicy(1) - Crée des politiques d'autorisation simples basées sur les valeurs de plusieurs indices PCR sur plusieurs banques activées.

SYNTAXE

tpm2_createpolicy [OPTIONS]

DESCRIPTION

tpm2_createpolicy(1) - Crée des politiques d'autorisation simples basées sur les valeurs de plusieurs indices PCR sur plusieurs banques activées. Il peut ensuite être utilisé avec la création d'objets et/ou des outils utilisant l'objet.

OPTIONS

Ces options contrôlent la création de la session d'autorisation de politique :

•
-L, --policy=FICHIER:

Le fichier où enregistrer le digest de la politique.

•
--policy-pcr:

Identifie le type de politique PCR pour la création de la politique.

•
-g, --policy-algorithm=ALGORITHME:

L'algorithme de hachage utilisé dans le calcul du digest de la politique.

•
-l, --pcr-list=PCR:

La liste des banques PCR et les identifiants des PCR sélectionnés pour chaque banque.

•
-f, --pcr=FICHIER:

Chemin optionnel ou Nom du fichier contenant les valeurs PCR attendues pour l'indice spécifié. Par défaut, les PCR actuels sont lus conformément à la liste définie.

•
--policy-session:

Démarre une session de politique de type TPM_SE_POLICY. Par défaut, il utilise TPM_SE_TRIAL si cette option n'est pas spécifiée.

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour la création par le TPM, ont de nombreux algorithmes à remplir dans les données publiques. Des choses comme le type, le schéma et les détails asymétriques, la taille de la clé, etc. Ci-dessous se trouve le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de type

Cette partie du spécificateur d'algorithme complexe est requise. Les détails du schéma et symétriques restants seront pris par défaut en fonction du type spécifié et du type de l'objet en cours de création.

•
aes - AES par défaut : aes128
•
aes128<mode> - AES 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, il prend par défaut null.
•
aes192<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - SM4 par défaut : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, il prend par défaut null.
•
ecc - Courbe elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - RSA par défaut : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de schéma

Ensuite, un champ optionnel, qui peut être sauté.

Les schémas sont généralement des Schémas de Signature ou des Schémas de Chiffrement Asymétrique. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est manquant, il prend par défaut sha256. Certains ne prennent aucun argument, et d'autres en prennent plusieurs.

Spécificateurs de Détails Symétriques

Ce champ est facultatif et dépend par défaut du *type* d'objet en cours de création et de ses attributs. Généralement, tout spécificateur Symétrique valide de la liste des spécificateurs de Type devrait fonctionner. S'il n'est pas spécifié, les détails symétriques des objets asymétriques sont par défaut aes128cfb.

Configuration du TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <config-option-tcti> résulte en l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI `device`, le fichier périphérique caractère TPM à utiliser par le TCTI `device` peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI `mssim`, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI `abrmd`, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et valeur sont séparées par un caractère `=`.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name` : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type` : Le type de l'instance dbus (une chaîne de caractères) limitée à `session` et `system`.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Créer une politique d'autorisation liée à un index PCR spécifique

create a policy digest

SYNOPSIS

tpm2_createpolicy [-h|--help] [-v|--version] [-c|--context file] [-p|--policy file] [-f|--policy-file file] [-r|--raw-output] [-S|--session hex string] [-l|--login policy hex string] [-n|--name policy hex string] [-P|--password policy hex string] [-T|--tcti name:device] [-I|--tcti-conf file]

DESCRIPTION

tpm2_createpolicy will create a policy digest. It will then output the policy digest in a format that can be consumed by other tools.

tpm2_createpolicy is a tool in the tpm2_tools(1) package.

OPTIONS

Algorithm Specifiers

The following options are used to specify the algorithm digests that make up the policy:

-L policy file
Specifies the policy digest file to be used. This option is meant for tools like tpm2_createpolicy that can consume policy digests.
-f policy file
Specifies the policy digest file to be used. This option is meant for tools like tpm2_createpolicy that can consume policy digests.
-l policy hex string
Specifies the policy digest to be used. This option is meant for tools like tpm2_createpolicy that can consume policy digests.

TCTI Configuration

The following options are used to configure the TCTI (TPM Command Transmission Interface) layer:

-T, --tcti name:device
Specifies the TCTI module and device to use. The default is ‘tabrmd:’. Example: 
-T mssap:0x1234
will use the mssap TCTI with device 0x1234.
-I, --tcti-conf file
Specify a configuration file for the TCTI.
-S, --session hex string
Specify the policy session handle.
-n, --name policy hex string
Specify the policy name.
-P, --password policy hex string
Specify the policy password.

TCTI OPTIONS

The following options are used to specify the TCTI options:

-c, --context file
The file containing the context of the TPM session.
-p, --policy file
The file containing the policy digest.
-f, --policy-file file
The file containing the policy digest.
-r, --raw-output
Output the policy digest in raw format.

EXAMPLES

Create a policy digest and save it to a file:

$ tpm2_createpolicy -L policy.file -f pcr0.bin
0x4:0 -L policy.file -f pcr0.bin

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
