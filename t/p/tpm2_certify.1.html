tpm2_certify(1) Manuel des commandes générales tpm2_certify(1)

NOM

tpm2_certify(1) - Prouve qu'un objet est chargé dans le TPM.

SYNTAXE

tpm2_certify [OPTIONS]

DESCRIPTION

tpm2_certify(1) - Prouve qu'un objet avec un NOM spécifique est chargé dans le TPM. En certifiant que l'objet est chargé, le TPM garantit qu'une partie publique avec un NOM donné est auto-cohérente et associée à une partie sensible valide.

Si une partie tierce possède une partie publique portant le même NOM qu'un NOM certifié avec cette commande, alors les valeurs de cette partie publique sont correctes. Un objet dont seule la partie publique est chargée ne peut pas être certifié.

OPTIONS

Ces options contrôlent la certification :

•
-c, --certifiedkey-context=OBJET:

L'objet à certifier.

•
-C, --signingkey-context=OBJET:

La clé utilisée pour signer la structure d'attestation.

•
-P, --certifiedkey-auth=AUTH:

La valeur d'autorisation fournie pour l'objet spécifié avec -c.

•
-g, --hash-algorithm=ALGORITHME:

L'algorithme de hachage à utiliser lors de la génération de la signature.

•
--scheme=ALGORITHME:

Le schéma de signature utilisé pour signer le message. Facultatif. Les schémas de signature doivent suivre les « normes de formatage », voir la section « Spécificateurs d'algorithmes ». Voir également la section « Schémas de signature pris en charge » pour une liste des schémas de signature pris en charge. S'il est spécifié, le schéma de signature doit correspondre au type de clé. S'il n'est pas spécifié, un schéma de signature par défaut pour le type de clé sera utilisé.

•
-p, --signingkey-auth=AUTH:

La valeur d'autorisation pour la clé de signature spécifiée avec -C.

•
-o, --attestation=FICHIER:

Nom du fichier de sortie pour les données d'attestation.

•
-s, --signature=FICHIER:

Nom du fichier de sortie pour les données de signature.

•
-f, --format=FORMAT:

Sélection du format pour le fichier de sortie de signature.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il retournera simplement un cpHash, sauf si rphash est également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est communément appelé rpHash.

•
-S, --session=FICHIER:

La session créée à l'aide de tpm2_startauthsession. Cela peut être utilisé pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante, dans l'ordre :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme objet transitoire TPM restauré.
•
Si l'argument est une correspondance de préfixe sur l'un des éléments suivants :
•
owner : la hiérarchie du propriétaire
•
platform : la hiérarchie de la plateforme
•
endorsement : la hiérarchie de caution
•
lockout : l'objet persistant de contrôle du verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.

Formatage de l'autorisation

L'autorisation pour l'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : « Les autorisations utilisent le mot de passe VIDE par défaut lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: » est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi l'utilisation de mots de passe contenant des caractères non imprimables et/ou peu pratiques pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: » doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un « - » pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche les fuites d'informations ; les mots de passe passés en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctions d'historique courantes du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour afficher un mot de passe via stdin :
echo foobar | tpm2_tool -p file:-
# pour utiliser une chaîne ici bash via stdin :
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + suivi d'une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour la création par le TPM, ont de nombreux algorithmes à renseigner dans les données publiques. Par exemple le type, le schéma et les détails asymétriques, la taille de la clé, etc. Ci-dessous se trouve le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de type

Cette partie du spécificateur d'algorithme complexe est requise. Les schémas et détails symétriques restants seront par défaut en fonction du type spécifié et du type de l'objet en cours de création.

•
aes - AES par défaut : aes128
•
aes128<mode> - AES 128 bits avec mode facultatif (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
aes192<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - SM4 par défaut : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode facultatif (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
ecc - Courbe elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - RSA par défaut : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de schéma

Ensuite, il y a un champ facultatif, il peut être ignoré.

Les schémas sont généralement des **schémas de signature** ou des **schémas de chiffrement** **asymétriques**. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est manquant, il prend par défaut sha256. Certains ne prennent aucun argument, et d'autres prennent plusieurs arguments.

Spécificateurs de schéma facultatif de hachage

Ces spécificateurs de schéma sont suivis d'un tiret et d'un algorithme de hachage valide. Par exemple : oaep-sha256.

Spécificateurs de schéma à options multiples

Ce spécificateur de schéma est suivi d'un compte (taille maximale UINT16) puis suivi d'un tiret (-) et d'un algorithme de hachage valide. * ecdaa Par exemple, ecdaa4-sha256. Si aucun compte n'est spécifié, la valeur par défaut est 4.

Spécificateurs de schéma sans option

Ce spécificateur de schéma ne prend AUCUN argument. * rsaes

Spécificateurs de détails symétriques

Ce champ est facultatif et prend par défaut en fonction du type de l'objet en cours de création et de ses attributs. Généralement, tout spécificateur **symétrique** valide de la liste des **Spécificateurs de Type** devrait fonctionner. S'il n'est pas spécifié, les détails symétriques d'un objet asymétrique prennent par défaut aes128cfb.

Exemples

Créer une clé rsa2048 avec un schéma de chiffrement asymétrique rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Créer une clé ecc256 avec un schéma de signature ecdaa avec un compte de 4 et un hachage sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algorithmes cryptographiques ALGORITHME.

Spécificateurs de format de signature

Sélection du format pour le fichier de sortie de signature. tss (la valeur par défaut) générera un blob binaire conformément à la spécification TPM 2.0 et à tout rembourrage potentiel du compilateur. L'option plain générera les données de signature brutes telles que définies par l'algorithme cryptographique utilisé. Format de signature FORMAT.

NOM

tpm2_certify

certifie un objet de données avec une clé de signature

SYNTAXIS

tpm2_certify [-h] [-V] [-q] [-V] [-Q] [-Z] [-R] [-T tcti] [-c context] [-C auth_context] [-u attestation_key_public] [-r attestation_key_private] [-n attestation_key_name] [-g alg] [-f format] [-o output] [-s signature] [-p password] [-P parent_password] [-- arg... ]

DESCRIPTION

La commande tpm2_certify est utilisée pour certifier des données avec une clé de signature TPM.

Elle prend une clé de signature et une clé primaire comme entrée et produit un certificat et une signature.

OPTIONS

La commande tpm2_certify accepte les options suivantes :

-h, --help
Affiche l'aide et quitte.
-V, --version
Affiche les informations de version et quitte.
-q, --quiet
Supprime la sortie normale de l'outil vers stdout.
-Q, --really-quiet
Supprime toute la sortie, y compris les messages d'erreur.
-Z, --enable-errata
Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
-R, --autoflush
Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.
-T, --tcti tcti
Configure le TCTI (Transmission Control Interface) pour la communication avec le TPM. Le format est <tcti-name>:<tcti-options>. Les TCTI connus sont : device, mssim, tabrmd (ou abrmd).
-c, --context context
Spécifie le fichier de contexte de l'objet de politique ou de l'objet de clé primaire à utiliser pour la commande.
-C, --auth_context auth_context
Spécifie le contexte d'autorisation pour l'objet de clé primaire.
-u, --attestation-key-public attestation_key_public
Fichier contenant la clé publique de la clé d'attestation.
-r, --attestation-key-private attestation_key_private
Fichier contenant la clé privée de la clé d'attestation.
-n, --attestation-key-name attestation_key_name
Fichier contenant le nom de la clé d'attestation.
-g, --algorithm alg
Spécifie l'algorithme de signature à utiliser. Exemples : rsa, ecc. Par défaut, utilise l'algorithme de la clé d'attestation.
-f, --format format
Spécifie le format des données d'attestation. Les formats pris en charge sont : raw, pem, der. Par défaut : raw.
-o, --output output
Fichier de sortie pour les données d'attestation certifiées.
-s, --signature signature
Fichier de sortie pour la signature.
-p, --password password
Mot de passe pour déverrouiller la clé de signature.
-P, --parent-password parent_password
Mot de passe pour déverrouiller l'objet parent.

FORMAT DES OBJETS DE CONTRÔLE

Les objets de contrôle sont spécifiés par un chemin de fichier. Les formats supportés sont les fichiers binaires de contexte générés par TPM2 tools.

FORMATAGE DE L'AUTORISATION

L'autorisation peut être spécifiée sous forme de mot de passe, de clé de politique ou de fichier de contexte.

SPÉCIFICATEURS D'ALGORITHME

Les algorithmes peuvent être spécifiés par leur nom (par exemple, sha256, rsa, ecc) ou par leur identifiant numérique.

SPÉCIFICATEURS DE FORMAT DE SIGNATURE

Le format de signature peut être spécifié par son nom (par exemple, pkcs1, der) ou par son identifiant numérique.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour la communication avec les TPM via différents médiums.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Remarque : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne supporte AUCUNE option et DOIT ÊTRE présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <configuration-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant les sémantiques de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTI susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel que compris par les sémantiques de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque chaîne de clé et de valeur est séparée par un caractère `=`.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifier le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

REMARQUE: abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Créez une clé primaire et certifiez-la avec une clé de signature.

tpm2_createprimary -Q -C e -g sha256 -G rsa -c primary.ctx
tpm2_create -Q -g sha256 -G rsa -u certify.pub -r certify.priv -C primary.ctx
tpm2_load -Q -C primary.ctx -u certify.pub -r certify.priv -n certify.name \
-c certify.ctx
tpm2_certify -Q -c primary.ctx -C certify.ctx -g sha256 -o attest.out -s sig.out

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de traitement des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
