tpm2_nvundefine(1) Manuel des commandes générales tpm2_nvundefine(1)

NOM

tpm2_nvundefine(1) - Supprime un index Non Volatil (NV).

SYNOPSIS

tpm2_nvundefine [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_nvundefine(1) - Supprime un index Non Volatil (NV) qui avait été précédemment défini avec tpm2_nvdefine(1). L'index est spécifié comme argument. Il peut être spécifié comme un handle brut ou une valeur de décalage de la plage de handles NV “TPM2_HR_NV_INDEX”.

L'outil est également capable de supprimer les index NV avec l'attribut TPMA_NV_POLICY_DELETE, et l'outil utilise cet attribut pour la hiérarchie par défaut afin de sélectionner lorsque -C est absent. La valeur par défaut pour -C est la hiérarchie “propriétaire” lorsque TPMA_NV_POLICY_DELETE est effacé et “plateforme” lorsque TPMA_NV_POLICY_DELETE est défini.

OPTIONS

•
-C, --hierarchy=OBJECT:

Spécifie la hiérarchie utilisée pour autoriser. Les options prises en charge sont :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<num> où un handle de hiérarchie peut être spécifié.
•
-P, --auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie.

•
-S, --session=POLICY_SESSION:

Spécifie une session de politique à utiliser lorsque l'index NV a l'attribut TPMA_NV_POLICY_DELETE défini. Ceci peut également être utilisé pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres. Remarque :

1.
Si TPM2_CC_NV_UndefineSpaceSpecial est invoqué, alors une seule session auxiliaire supplémentaire peut être spécifiée. L'ordre dans lequel les sessions sont spécifiées est également important. La première spécification de -S est interprétée comme la session pour satisfaire le rôle ADMIN requis pour TPM2_CC_NV_UndefineSpaceSpecial.
2.
Si TPM2_CC_NV_Undefine est invoqué, alors seulement deux sessions auxiliaires supplémentaires peuvent être spécifiées.
•
--cphash=FILE

Chemin du fichier pour enregistrer le hash des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash, il renvoie simplement un cpHash à moins que rphash ne soit également requis.

•
--rphash=FILE

Chemin du fichier pour enregistrer le hash des paramètres de la réponse. Ceci est communément appelé rpHash.

•
--with-policydelete=NONE

Ceci doit être spécifié lors du calcul du cpHash avec --tcti=none. Ceci est une exigence car il n'y a aucun moyen de savoir si l'attribut TPMA_NV_POLICYDELETE a été défini à partir du nom de l'index NV seul.

•
-n, --name=FILE:

Le nom de l'index NV qui doit être fourni lors du calcul du cpHash sans réellement expédier la commande au TPM.

•
ARGUMENT l'argument de ligne de commande spécifie l'index NV ou le numéro de décalage.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet TPM transitoire restauré.
•
Si l'argument correspond à un *préfixe* sur l'un des éléments suivants :
•
owner : la hiérarchie du propriétaire
•
platform : la hiérarchie de la plateforme
•
endorsement : la hiérarchie de l'endossement
•
lockout : l'objet persistant de contrôle du verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par ex. 0x81010013 et utilisé directement._OBJECT_.

Formatage de l'autorisation

L'autorisation pour l'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : “Les autorisations par défaut sont le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées”.

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont supposés être sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe “str:” ou son absence (chaîne brute sans préfixe) n'est pas interprété, et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe “hex:” est converti de sa forme hexadécimale en un tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe “file:” doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un “-” pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche la fuite d'informations, les mots de passe passés en tant qu'options peuvent être lus depuis la liste des processus ou les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour écho un mot de passe via stdin:
echo foobar | tpm2_tool -p file:-
# pour utiliser une chaîne ici bash via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'autorisation à envoyer avec le handle de session (par ex. mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification *HEXADÉCIMALE* 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe “pcr:” et le mini-langage PCR. Le mini-langage PCR est le suivant : <pcr-spec>=<fichier-pcr-brut>

La spécification PCR est documentée dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument facultatif qui contient la sortie des contenus PCR bruts tels que retournés par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez le spécificateur :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page de manuel de l'outil. Par défaut, il tente d'invoquer le paginator de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le paginator de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser correctement la fonctionnalité des pages de manuel, il faut que les pages de manuel soient installées ou sur MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tctis pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. En utilisant cette option, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également effacé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge l'absence de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT ÊTRE présenté comme le texte exact « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> utilise la valeur par défaut pour cette partie respectivement.

Valeurs par défaut TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est par défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI de périphérique, le fichier de périphérique de caractère TPM à utiliser par le TCTI de périphérique peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et chaîne de valeur sont séparées par un caractère `=.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifier le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

Exemples

Définir un index NV ordinaire et le supprimer

tpm2_nvdefine 1
tpm2_nvundefine 1

Définir un index NV ordinaire avec l'attribut TPMA_NV_POLICY_DELETE et le supprimer

tpm2_startauthsession -S s.ctx
tpm2_policyauthvalue -S s.ctx
tpm2_policycommandcode -S s.ctx -L policy.dat TPM2_CC_NV_UndefineSpaceSpecial
tpm2_nvdefine -C p -s 32 \
  -a "ppread|ppwrite|authread|authwrite|platformcreate|policydelete|write_stclear|read_stclear" \
  -L policy.dat 1
tpm2_flushcontext s.ctx
tpm2_startauthsession --policy-session -S s.ctx
tpm2_policyauthvalue -S s.ctx
tpm2_policycommandcode -S s.ctx TPM2_CC_NV_UndefineSpaceSpecial
tpm2_nvundefine -S s.ctx 1

Retours

Les outils peuvent renvoyer l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
