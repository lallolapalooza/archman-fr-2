tpm2_policynv(1) Manuel des commandes générales tpm2_policynv(1)

NOM

tpm2_policynv(1) - Évalue l'autorisation de politique en comparant une valeur spécifiée au contenu de l'Index NV spécifié.

SYNTAXE

tpm2_policynv [OPTIONS] [ARGUMENT] [ARGUMENT]

DESCRIPTION

tpm2_policynv(1) - Cette commande évalue l'autorisation de politique en comparant le contenu écrit dans un index NV à celui spécifié dans les options de l'outil. L'outil prend deux arguments - (1) L'index NV spécifié sous forme de descripteur brut ou de valeur de décalage par rapport à la plage de descripteurs nv « TPM2_HR_NV_INDEX » et (2) Un opérateur de comparaison pour les comparaisons d'amplitude et/ou les opérations de test de bits. Dans la spécification, l'index NV contenant les données est appelé opérandeA et les données que l'utilisateur spécifie pour comparer est appelé opérandeB. L'opérateur de comparaison peut être spécifié comme suit : * « eq » si opérandeA = opérandeB * « neq » si opérandeA != opérandeB * « sgt » si opérandeA signé > opérandeB signé * « ugt » si opérandeA non signé > opérandeB non signé * « slt » si opérandeA signé < opérandeB signé * « ult » si opérandeA non signé < opérandeB non signé * « sge » si opérandeA signé >= opérandeB signé * « uge » si opérandeA non signé >= opérandeB non signé * « sle » si opérandeA signé <= opérandeB signé * « ule » si opérandeA non signé <= opérandeB non signé * « bs » si tous les bits définis dans opérandeA sont définis dans opérandeB * « bc » si tous les bits définis dans opérandeA sont effacés dans opérandeB

OPTIONS

•
-C, --hierarchy=OBJET:

Spécifie la hiérarchie utilisée pour autoriser. Les options supportées sont :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<num> où un descripteur de hiérarchie ou un index nv peut être utilisé.

Lorsque -C n'est pas explicitement passé, le descripteur d'index sera utilisé pour autoriser contre l'index. La valeur d'authentification de l'index est définie via l'option -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Spécifie la valeur d'authentification pour la hiérarchie.

•
-L, --policy=FICHIER:

Fichier pour enregistrer le résumé de la politique.

•
-S, --session=FICHIER:

Le fichier de session de politique généré via l'option -S de tpm2_startauthsession ou sauvegardé d'une précédente exécution de l'outil.

•
--offset=NOMBRE_NATUREL:

Le décalage dans l'index NV où commencer la comparaison. La taille des données commençant au décalage et se terminant à la taille de l'index NV ne doit pas dépasser la taille de l'opérande spécifié dans les options.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash.

•
-i, --input=FICHIER:

Spécifie le fichier d'entrée avec les données à comparer aux contenus de l'Index NV. Dans la spécification standard, ceci est appelé opérande ou plus spécifiquement opérandeB. Il peut être spécifié comme une entrée de fichier ou stdin si la valeur de l'option est « - ».

Références

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche le manuel de l'outil. Par défaut, il tente d'invoquer le pagineur de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le pagineur de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages de manuel, il faut que les pages de manuel soient installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version pour cet outil, les tctis supportés et quitte.
•
-V, --verbose: Augmente les informations que l'outil affiche sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont affichés.
•
-Q, --quiet: Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata: Active l'application de correctifs d'errata. Utile si un correctif d'errata doit être appliqué aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush: Active le vidage automatique pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Le vidage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne supporte *AUCUNE* option et *DOIT* être présenté comme le texte exact « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera quel TCTI parmi ceux mentionnés est le défaut.

OPTIONS TCTI

Cet ensemble d'options est utilisé pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI de périphérique, le fichier de périphérique caractère TPM à utiliser par le TCTI de périphérique peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom d'hôte ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et chaîne de valeur sont séparées par un caractère `=.
•
TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Teste si la valeur du contenu de l'index NV est égale à un nombre d'entrée. Pour ce faire, nous créons d'abord un index NV de 1 octet et écrivons une valeur. Par exemple, 0xAA. Ensuite, nous tentons de créer une politique qui devient valide si l'opération de comparaison d'égalité du contenu de l'index NV par rapport à celle spécifiée dans les options de l'outil.

Définir l'index NV de test et écrire la valeur 0xAA dedans

nv_test_index=0x01500001
tpm2_nvdefine -C o -p nvpass $nv_test_index -a "authread|authwrite" -s 1
echo "aa" | xxd -r -p | tpm2_nvwrite -P nvpass -i- $nv_test_index

Tenter de définir policynv avec une valeur de comparaison incorrecte spécifiée dans les options.

tpm2_startauthsession -S session.ctx --policy-session
### Cela devrait échouer
echo 0xBB | tpm2_policynv -S session.ctx -L policy.nv -i- 0x1500001 eq -P nvpass
tpm2_flushcontext session.ctx

Tenter de définir policynv avec la bonne valeur de comparaison spécifiée dans les options.

tpm2_startauthsession -S session.ctx --policy-session
### Cela devrait passer
echo 0xAA | tpm2_policynv -S session.ctx -L policy.nv -i- 0x1500001 eq -P nvpass
tpm2_flushcontext session.ctx

Retourne

Les outils peuvent renvoyer l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de traitement des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.

Limitations

Il s'attend à ce qu'une session soit déjà établie via tpm2_startauthsession(1) et nécessite l'une des options suivantes :

•
accès direct au périphérique
•
prise en charge des sessions étendues avec tpm2-abrmd.

Sans cela, la plupart des gestionnaires de ressources ne sauvegarderont pas l'état de la session entre les invocations de commandes.
