tpm2_rsadecrypt(1) Manuel des commandes générales tpm2_rsadecrypt(1)

NOM

tpm2_rsadecrypt(1) - Effectue une opération de déchiffrement RSA à l'aide du TPM.

SYNOPIS

tpm2_rsadecrypt [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_rsadecrypt(1) - Effectue un déchiffrement RSA sur le contenu du fichier en utilisant le schéma de remplissage indiqué, conformément à la RFC 3447 de l'IETF (PKCS#1). L'argument de la ligne de commande vaut par défaut stdin s'il n'est pas spécifié.

La clé référencée par le contexte de clé doit être :

1.
Une clé RSA
2.
Avoir l'attribut decrypt DEFINI dans ses attributs.

OPTIONS

•
-c, --key-context=OBJET:

Objet de contexte pointant vers la partie publique de la clé RSA à utiliser pour le déchiffrement. Soit un fichier, soit un numéro de handle. Voir la section « Format de l'objet de contexte ».

•
-p, --auth=AUTH:

Valeur d'autorisation facultative pour utiliser la clé spécifiée par -c.

•
-o, --output=FICHIER:

Chemin facultatif du fichier de sortie pour enregistrer les données déchiffrées. Par défaut, les données binaires déchiffrées sont imprimées sur STDOUT.

•
-s, --scheme=FORMAT:

Facultatif, définit le schéma de remplissage (par défaut : rsaes).

•
null - TPM_ALG_NULL utilise le schéma de la clé s'il est défini.
•
rsaes - TPM_ALG_RSAES, qui est RSAES_PKCSV1.5.
•
oaep - TPM_ALG_OAEP, qui est RSAES_OAEP.
•
-l, --label=FICHIER OU CHAINE:

Facultatif, définit les données de l'étiquette. Le TPM exige que le dernier octet de l'étiquette soit zéro, cela est géré en interne par l'outil. Aucun autre octet intégré ne peut exister, sinon le TPM tronquera votre étiquette.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash.

•
ARGUMENT l'argument de la ligne de commande spécifie le fichier contenant les données à déchiffrer.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante, dans l'ordre :

•
Si l'argument est un chemin de fichier, le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un préfixe de l'un des éléments suivants :
•
owner : la hiérarchie propriétaire
•
platform : la hiérarchie de plateforme
•
endorsement : la hiérarchie d'approbation
•
lockout : l'objet persistant de contrôle du lockout
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013, et utilisé directement._OBJECT_.

Formatage de l'autorisation

L'autorisation pour l'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : « Les autorisations utilisent le MOT DE PASSE VIDE par défaut lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont supposés être sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en un tableau d'octets, permettant ainsi des mots de passe avec des caractères non imprimables et/ou peu conviviaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser stdin. Le stockage des mots de passe dans des fichiers évite les fuites d'informations ; les mots de passe passés en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour echo un mot de passe via stdin:
echo foobar | tpm2_tool -p file:-
# pour utiliser un here-string bash via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de stratégie pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de stratégie), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument facultatif qui contient la sortie du contenu PCR brut tel que retourné par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

Nom

tpm2_rsadecrypt - déchiffre des données à l'aide d'une clé RSA privée, en utilisant le TPM.

Synopsis

tpm2_rsadecrypt [OPTIONS]—in in —out out

Description

La commande tpm2_rsadecrypt déchiffre le contenu du fichier in avec la clé RSA spécifiée dans le fichier key et enregistre le résultat dans le fichier out.

Les clés utilisées pour le chiffrement/déchiffrement RSA sont des objets persistants ou de contexte créés à l'aide de tpm2_createkey, tpm2_createprimary et tpm2_load.

Pour pouvoir utiliser l'option -c, vous devez avoir créé un objet de clé précédemment.

Options

—in in
Le chemin d'accès au fichier contenant les données chiffrées à déchiffrer. Le format des données doit correspondre au schéma de remplissage utilisé lors du chiffrement.
—out out
Le chemin d'accès au fichier où seront enregistrées les données déchiffrées.
-c key-context
Le chemin d'accès au fichier contenant le contexte de l'objet clé RSA à utiliser pour le déchiffrement. Ce fichier est généré par tpm2_createkey, tpm2_createprimary ou tpm2_load.
-p password
Le mot de passe utilisé pour l'authentification de l'objet clé. Si l'objet clé est protégé par un mot de passe et qu'il n'est pas spécifié ici, la commande demandera le mot de passe.
-f [pkcs1|oaep]
Le schéma de remplissage utilisé lors du chiffrement. Les options valides sont pkcs1 et oaep. La valeur par défaut est oaep.
-s [sha1|sha256|sha384|sha512|null]
Utilisé avec le schéma oaep pour spécifier l'algorithme de hachage. La valeur par défaut est sha256.
-t [null|no-da|da]
Utilisé avec le schéma oaep pour spécifier le type de gestion de la confidentialité des données. Les options valides sont null, no-da et da. La valeur par défaut est null.

Format des objets de contexte

Les objets de contexte sont générés par les commandes tpm2_createprimary, tpm2_create et tpm2_load. Ils contiennent les informations nécessaires pour référencer et utiliser des objets dans le TPM. Ces fichiers peuvent être chargés en utilisant l'option -c.

Format de l'autorisation

L'autorisation pour un objet peut être fournie via un mot de passe en ligne de commande avec l'option -p. Si l'objet est protégé par un mot de passe et que celui-ci n'est pas fourni, la commande demandera le mot de passe.

Options Communes

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche la page de manuel de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le programme de pagination de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages de manuel, celles-ci doivent être installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version de cet outil, les tctis pris en charge et quitte.
•
-V, --verbose: Augmente les informations que l'outil imprime sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet: Silence la sortie normale de l'outil vers stdout.
•
-Z, --enable-errata: Active l'application de corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.

Configuration TCTI

Le TCTI ou “Transmission Interface” est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé pour parler directement à un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT ÊTRE présenté exactement comme “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque chaîne de clé et de valeur sont séparées par un caractère `=’.
•
TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifier le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

Exemples

Créer une clé RSA et la charger

tpm2_createprimary -c primary.ctx
tpm2_create -C primary.ctx -Grsa2048 -u key.pub -r key.priv
tpm2_load -C primary.ctx -u key.pub -r key.priv -c key.ctx

Chiffrer en utilisant RSA

echo "mon message" > msg.dat
tpm2_rsaencrypt -c key.ctx -o msg.enc msg.dat

Déchiffrer en utilisant RSA

tpm2_rsadecrypt -c key.ctx -o msg.ptext msg.enc
cat msg.ptext
mon message

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
