tpm2_hash(1) Manuel des commandes générales tpm2_hash(1)

NOM

tpm2_hash(1) - Effectue une opération de hachage avec le TPM.

SYNTAXE

tpm2_hash [OPTIONS] [ARGUMENT ou ENTRÉE STANDARD]

DESCRIPTION

tpm2_hash(1) - Effectue une opération de hachage sur un fichier et renvoie les résultats. Si aucun argument n'est spécifié, les données sont lues depuis l'entrée standard. Si les résultats du hachage doivent être utilisés dans une opération de signature qui utilise une clé de signature restreinte, alors le ticket renvoyé par cette commande peut indiquer que le hachage est sûr à signer.

La sortie est par défaut sur la sortie standard et au format binaire, sauf spécification contraire via les options -o et –hex respectivement.

OPTIONS

•
-C, --hierarchy=OBJET:

Hiérarchie à utiliser pour le ticket. Par défaut, o, TPM_RH_OWNER, lorsqu'aucune valeur n'a été spécifiée. Options prises en charge :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
e pour TPM_RH_ENDORSEMENT
•
n pour TPM_RH_NULL
•
-g, --hash-algorithm=ALGORITHME:

L'algorithme de hachage pour l'opération de résumé.

•
--hex

Convertit le hmac de sortie en format hexadécimal sans le préfixe « 0x ».

•
-o, --output=FICHIER ou SORTIE STANDARD:

Fichier optionnel pour sauvegarder le résultat du hachage. Par défaut, sortie standard en format hexadécimal.

•
-t, --ticket=FICHIER_TICKET

Fichier optionnel enregistrant le résultat du ticket. Par défaut, sortie standard en format hexadécimal.

•
ARGUMENT ou ENTRÉE STANDARD L'argument de la ligne de commande spécifie le FICHIER à hacher.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un descripteur ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, le fichier est chargé comme un objet TPM transitoire restauré.
•
Si l'argument correspond à une correspondance de *préfixe* sur l'un des éléments suivants :
•
owner : la hiérarchie propriétaire
•
platform : la hiérarchie de plateforme
•
endorsement : la hiérarchie d'endossement
•
lockout : l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un descripteur, par exemple 0x81010013 et utilisé directement._OBJET_.

Formatage de l'autorisation

L'autorisation d'utiliser un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations sont par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes ci-dessous en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont supposés être sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str : » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex : » est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe avec des caractères non imprimables et/ou non conviviaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file : » doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un « - » pour utiliser l'entrée standard. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe passés en option peuvent être lus depuis la liste des processus ou les fonctions d'historique des shells courants.

Exemples

# pour utiliser l'entrée standard et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour echo un mot de passe via l'entrée standard:
echo foobar | tpm2_tool -p file:-
# pour utiliser une here-string bash via l'entrée standard:
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le descripteur de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations de PCR

Vous pouvez satisfaire une politique de PCR en utilisant le préfixe « pcr : » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie du contenu PCR brut tel que renvoyé par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR sur sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge le non-usage d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend en charge *AUCUNE* option et *DOIT ÊTRE* présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom_tcti>:<configuration_options_tcti>

Spécifier une chaîne vide pour le <nom_tcti> ou la <configuration_options_tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Valeurs par défaut TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom_tcti est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI= « device:/dev/tpm0 »

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI= « mssim:host=localhost,port=2321 »

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque chaîne de clé et de valeur est séparée par un caractère `= `.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Hacher un fichier avec l'algorithme de hachage sha1 et enregistrer le hachage et le ticket dans un fichier

tpm2_hash -C e -g sha1 -o hash.bin -t ticket.bin data.txt

Retours

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
