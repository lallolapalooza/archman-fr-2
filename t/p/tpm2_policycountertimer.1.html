tpm2_policycountertimer(1)

Paquet: tpm2-tools

Licences: BSD-3-Clause

tpm2_policycountertimer(1) General Commands Manual tpm2_policycountertimer(1)

NAME

tpm2_policycountertimer(1) - Permet l'autorisation de politique en évaluant l'opération de comparaison sur les paramètres TPM (heure, horloge, nombre de réinitialisations, nombre de redémarrages et indicateur de sécurité de l'horloge TPM).

SYNOPSIS

tpm2_policycountertimer [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_policycountertimer(1) - Permet l'autorisation de politique en évaluant l'opération de comparaison sur les paramètres TPM (heure, horloge, nombre de réinitialisations, nombre de redémarrages et indicateur de sécurité de l'horloge TPM). En cas de temps/horloge, il est saisi en millisecondes. Le paramètre et la valeur sont donnés comme argument de ligne de commande comme suit :

tpm2_policycountertimer -S session.ctx safe
tpm2_policycountertimer -S session.ctx clock=<N ms>
tpm2_policycountertimer -S session.ctx time=<N ms>
tpm2_policycountertimer -S session.ctx resets=<N>
tpm2_policycountertimer -S session.ctx restarts=<N>

Par défaut, la comparaison teste l'égalité et teste également par défaut le temps.

OPTIONS

•
-L, --policy=FILE:

Fichier pour enregistrer le résumé de la politique.

•
-S, --session=FILE:

Le fichier de session de politique généré via l'option -S de tpm2_startauthsession ou sauvegardé d'une exécution précédente de l'outil.

•
–eq

si la valeur de l'heure actuelle dans le TPM = valeur de l'heure d'entrée spécifiée.

•
–neq

si la valeur de l'heure actuelle dans le TPM != valeur de l'heure d'entrée spécifiée.

•
–sgt

si la valeur signée de l'heure actuelle dans le TPM > valeur signée de l'heure d'entrée spécifiée.

•
–ugt

si la valeur non signée de l'heure actuelle dans le TPM > valeur non signée de l'heure d'entrée spécifiée.

•
–slt

si la valeur signée de l'heure actuelle dans le TPM < valeur signée de l'heure d'entrée spécifiée.

•
–ult

si la valeur non signée de l'heure actuelle dans le TPM < valeur non signée de l'heure d'entrée spécifiée.

•
–sge

si la valeur signée de l'heure actuelle dans le TPM >= valeur signée de l'heure d'entrée spécifiée.

•
–uge

si la valeur non signée de l'heure actuelle dans le TPM >= valeur non signée de l'heure d'entrée spécifiée.

•
–sle

si la valeur signée de l'heure actuelle dans le TPM <= valeur non signée de l'heure d'entrée spécifiée.

•
–ule

si la valeur non signée de l'heure actuelle dans le TPM <= valeur non signée de l'heure d'entrée spécifiée.

•
–bs

si tous les bits définis dans la valeur de l'heure actuelle du TPM sont définis dans la valeur de l'heure d'entrée spécifiée.

•
–bc

si tous les bits définis dans la valeur de l'heure actuelle du TPM sont effacés dans la valeur de l'heure d'entrée spécifiée.

•
--cphash=FILE

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour la communication avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Remarque : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge l'absence d'utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne prend pas en charge *AUCUNE* option et *DOIT* être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <configuration-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Valeurs par défaut du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché à l'aide de la sémantique dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim *DANS CET ORDRE* et *UTILISERONT LE PREMIER TROUVÉ*. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTI susmentionnés est par défaut.

TCTI personnalisés

"Pp">Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI de type device, le fichier de périphérique caractère du TPM à utiliser par le TCTI de type device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom d'hôte ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur sont séparées par un caractère `=.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI abrmd (par défaut) et une chaîne de configuration bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Créez un objet de scellement avec une politique d'autorisation qui s'évalue uniquement pendant la première minute après le redémarrage du TPM.

Créer la politique et l'objet de scellement

tpm2_startauthsession -S session.ctx
tpm2_policycountertimer -S session.ctx -L policy.countertimer --ult 60000
tpm2_flushcontext session.ctx
tpm2_createprimary -C o -c prim.ctx -Q
echo "SUPERSECRET" | \
tpm2_create -Q -u key.pub -r key.priv -i- -C prim.ctx \
-L policy.countertimer -a "fixedtpm|fixedparent" -c key.ctx

Le déscellement devrait fonctionner dans la première minute après le redémarrage du TPM

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policycountertimer -S session.ctx --ult 60000
tpm2_unseal -c key.ctx -p session:session.ctx
tpm2_flushcontext session.ctx

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.

Limitations

Il s'attend à ce qu'une session soit déjà établie via tpm2_startauthsession(1) et nécessite l'un des éléments suivants :

•
accès direct au périphérique
•
prise en charge de sessions étendues avec tpm2-abrmd.

Sans cela, la plupart des gestionnaires de ressources ne conserveront pas l'état de la session entre les invocations de commandes.
