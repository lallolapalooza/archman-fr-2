tpm2_policysigned(1) Manuel des commandes générales tpm2_policysigned(1)

NOM

tpm2_policysigned(1) - Active l'autorisation de politique en vérifiant la signature des paramètres TPM2 optionnels. La signature est générée par une autorité de signature.

SYNTAXE

tpm2_policysigned [OPTIONS]

DESCRIPTION

tpm2_policysigned(1) - Active l'autorisation de politique en vérifiant la signature des paramètres TPM2 optionnels. La signature est générée par une autorité de signature. Les paramètres TPM2 optionnels sont cpHashA, nonceTPM, policyRef et expiration.

OPTIONS

•
-L, --policy=FICHIER:

Fichier pour sauvegarder le résumé de politique composé.

•
-S, --session=FICHIER:

Le fichier de session de politique généré via l'option -S de tpm2_startauthsession(1).

•
-c, --key-context=OBJET:

Objet de contexte pour la clé utilisée pour l'opération. Soit un fichier, soit un numéro de handle. Voir la section « Format de l'objet de contexte ».

•
-g, --hash-algorithm=ALGORITHME:

L'algorithme de hachage utilisé pour résumer le message.

•
-s, --signature=FICHIER:

Le fichier de signature d'entrée de la signature à valider.

•
-f, --format=FORMAT:

Définit le fichier de signature d'entrée à un format spécifié. Le défaut est le format de données TPMT_SIGNATURE de tpm2.0, cependant différents schémas peuvent être sélectionnés si les données proviennent d'une source externe comme OpenSSL. L'outil prend actuellement en charge rsassa et ecdsa.

•
-t, --expiration=NOMBRE_NATUREL:

Définit le temps d'expiration de la politique en secondes. En l'absence de nonceTPM, le temps d'expiration est la valeur de délai d'attente de la politique. Si l'expiration est une valeur négative, un ticket d'autorisation est en plus retourné. Si la valeur d'expiration est 0, la politique n'a pas de limite de temps pour l'autorisation.

•
--cphash-input=FICHIER:

Le résumé des paramètres de commande (cpHash), appliquant la commande TPM à autoriser ainsi que son handle et les valeurs des paramètres.

•
--ticket=FICHIER:

Le fichier de ticket pour enregistrer la structure du ticket d'autorisation.

•
--timeout=FICHIER:

Le chemin du fichier pour enregistrer la structure de délai d'attente retournée.

•
-q, --qualification=CHAÎNE_HEX_OU_FICHIER:

Optionnel, les données de qualification de la politique que le signataire peut choisir d'inclure dans la signature. Peut être une chaîne hexadécimale ou un chemin.

•
-x, --nonce-tpm:

Active la comparaison du nonceTPM de la session actuelle pour assurer la validité de l'autorisation de politique limitée à la session actuelle.

Références

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche la page de manuel de l'outil. Par défaut, il tente d'appeler le pagineur de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le pagineur de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages de manuel, celles-ci doivent être installées ou sur MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version pour cet outil, les tctis pris en charge et quitte.
•
-V, --verbose: Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque cette option est utilisée, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet: Supprime la sortie normale de l'outil vers stdout.
•
-Z, --enable-errata: Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush: Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé depuis un fichier de contexte, l'objet parent transitoire sera également vidé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI, ou « Interface de transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour la communication avec des TPMs via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne supporte *AUCUNE* option et *DOIT* être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou le <config-option-tcti> entraîne l'utilisation du défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim dans cet ordre et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs mentionnés ci-dessus est le défaut.

TCTIs Personnalisés

Tout TCTI implémentant l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

tpm2_policysigned(1)

NAME

tpm2_policysigned

calculate PCR values and to define policies for TPM command authorization

SYNOPSIS

tpm2_policysigned [ OPTIONS ] [ --policy-file POLICY_FILE ]

DESCRIPTION

The tpm2_policysigned command is used to define a policy that requires a signature to be provided by the client. This is useful when you want to ensure that a specific operation is authorized by a client who possesses a particular key. The command calculates the PCR values and defines the policy in a way that it can be used to authorize TPM commands.

The policy is created by signing a digest of the policy session's nonce, a policy reference value, and a CP hash. The signature itself is then provided as input to the tpm2_policysigned command, along with the public key corresponding to the private key that was used to create the signature.

The following policy values are taken into consideration when generating the policy digest:

•
The nonce obtained from the session using tpm2_startauthsession.
•
The CP hash which is the digest of the command parameters hash. This is computed by the TPM and is set to zero if the parameter hash is not used.
•
The policy reference value, which is a policy digest value that is set by the user.
•
The expiration value, which is a time value. It is set to zero if it is not used.

OPTIONS

A list of common options that all commands share. See also tpm2_options(7).

•
Common Options
•
TCTI Configuration

COMMON OPTIONS

The following options are available on all TPM 2.0 tools.

-h, --help
Print the help information for the command.
-v, --version
Print the version information for the command.
-d, --debug
Enable debug output.

TCTI Configuration

The TCTI (Tabernacle Communication Transport Interface) is used to specify how to communicate with the TPM.

-T, --tcti

Specify the TCTI configuration string. The format of this string depends on the TCTI module being used. See TCTI OPTIONS below for more details.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Authorize a TPM operation on an object whose authorization is bound to specific signing authority.

Create the signing authority

openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -outform PEM -pubout -out public.pem

Generate signature with nonceTPM, cpHashA, policyRef and expiration set to 0

echo "00 00 00 00" | xxd -r -p | \
openssl dgst -sha256 -sign private.pem -out signature.dat

Load the verification key and Create the policysigned policy

tpm2_loadexternal -C o -G rsa -u public.pem -c signing_key.ctx
tpm2_startauthsession -S session.ctx
tpm2_policysigned -S session.ctx -g sha256 -s signature.dat -f rsassa \
-c signing_key.ctx -L policy.signed
tpm2_flushcontext session.ctx

Create a sealing object to use the policysigned

echo "plaintext" > secret.data
tpm2_createprimary -C o -c prim.ctx
tpm2_create -u key.pub -r sealing_key.priv -c sealing_key.ctx -C prim.ctx \
-i secret.data -L policy.signed

Satisfy the policy and unseal secret

tpm2_startauthsession -S session.ctx --policy-session
tpm2_policysigned -S session.ctx -g sha256 -s signature.dat -f rsassa \
-c signing_key.ctx -L policy.signed
tpm2_unseal -p session:session.ctx -c sealing_key.ctx
tpm2_flushcontext session.ctx

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
