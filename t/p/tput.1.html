tput(1) Commandes utilisateur tput(1)

NOM

tput - initialiser un terminal, utiliser ses capacités, ou interroger la base de données terminfo

SYNTAXE

tput [-T type-terminal] {code-cap [paramètre ...]} ...

tput [-T type-terminal] [-x] clear

tput [-T type-terminal] init

tput [-T type-terminal] reset

tput [-T type-terminal] longname

tput -S

tput -V

DESCRIPTION

tput utilise la bibliothèque et la base de données terminfo pour rendre disponibles au shell des capacités et informations spécifiques au terminal, pour initialiser ou réinitialiser le terminal, ou pour rapporter une description du type de terminal actuel (ou spécifié). Les capacités du terminal sont accédées par un code-cap.

terminfo(5) discute en détail des capacités des terminaux et présente une liste complète des codes-cap.

Lors de la récupération des valeurs de capacité, le résultat dépend du type de capacité.

Booléen
tput établit son code de sortie à 0 si le terminal possède le code-cap, et 1 s'il ne le possède pas.
numérique
tput écrit la valeur décimale du code-cap dans le flux de sortie standard si elle est définie (-1 si elle ne l'est pas) suivie d'un saut de ligne.
chaîne
tput écrit la valeur du code-cap dans le flux de sortie standard si elle est définie, sans saut de ligne final.

Avant d'utiliser une valeur retournée sur la sortie standard, l'application doit tester le code de sortie de tput pour s'assurer qu'il est 0 ; voir la section « CODE DE SORTIE » ci-dessous.

Opérandes

Généralement, un opérande est un code-cap, un code de capacité de la base de données du terminal, ou un paramètre de celui-ci. Trois autres sont spécialement reconnus par tput : init, reset, et longname. Bien que ceux-ci ressemblent à des codes de capacité, ils reçoivent en fait un traitement spécial ; nous les appelons « pseudo-capacités ».

code-cap
indique une capacité de la base de données du terminal.
Si le code-cap est de type chaîne et prend des paramètres, tput interprète les arguments suivant le code-cap comme paramètres, jusqu'à la quantité (fixe) requise par la capacité.
La plupart des paramètres sont numériques. Seules quelques capacités de terminal nécessitent des paramètres de chaîne ; tput utilise une table pour décider lesquels passer comme chaînes. Normalement, tput utilise tparm(3X) pour effectuer la substitution. Si aucun paramètre n'est donné pour la capacité, tput écrit la chaîne sans effectuer la substitution.
init
initialise le terminal. Si la base de données du terminal est présente et qu'une entrée pour le type de terminal de l'utilisateur existe, les actions suivantes se produisent.
(1)
tput récupère les paramètres du mode du terminal. Il teste successivement les descripteurs de fichiers correspondant à
  • le flux d'erreur standard,
  • le flux de sortie standard,
  • le flux d'entrée standard, et
  • /dev/tty
pour obtenir les paramètres du terminal. Les ayant récupérés, tput se souvient quel descripteur utiliser pour les mises à jour ultérieures.
(2)
Si les dimensions du terminal ne peuvent pas être obtenues du système d'exploitation, mais que l'environnement ou l'entrée de la base de données du terminal les décrit, tput met à jour la notion de celles-ci par le système d'exploitation.
(3)
tput met à jour les modes du terminal.
  • Tous les délais spécifiés dans l'entrée (par exemple, lors de l'envoi d'un saut de ligne) sont définis dans le pilote de terminal.
  • L'expansion des tabulations est activée ou désactivée selon la spécification dans l'entrée, et
  • si les tabulations ne sont pas étendues, les tabulations standard (toutes les 8 espaces) sont définies.
(4)
Si des capacités d'initialisation, détaillées dans la sous-section « Tabulations et Initialisation » de terminfo(5), sont présentes, tput les écrit dans le flux de sortie standard.
(5)
tput vide le flux de sortie standard.
Si une entrée manque d'informations nécessaires à une activité ci-dessus, cette activité est silencieusement ignorée.
reset
réinitialise le terminal. Une réinitialisation diffère de l'initialisation de deux manières.
(1)
tput met les modes du terminal dans un état « sain »,
  • active les modes "cooked" et "echo",
  • désactive les modes cbreak et raw,
  • active la traduction des sauts de ligne, et
  • définit les caractères spéciaux non définis à leurs valeurs par défaut.
(2)
Si des capacités de réinitialisation sont définies pour le type de terminal, tput les écrit dans le flux de sortie. Sinon, tput utilise les capacités d'initialisation définies. Les capacités de réinitialisation sont détaillées dans la sous-section « Tabulations et Initialisation » de terminfo(5).
longname
Une entrée terminfo commence par un ou plusieurs noms par lesquels une application peut faire référence à l'entrée, avant la liste des capacités du terminal. Les noms sont séparés par des caractères “|”. X/Open Curses appelle le dernier nom le « nom long » et indique qu'il peut contenir des espaces.
tic avertit si le dernier nom ne contient pas d'espaces, pour tenir compte des anciennes entrées terminfo qui traitaient le nom long comme une fonctionnalité optionnelle. Le nom long est souvent appelé le champ de description.
Si la base de données du terminal est présente et qu'une entrée pour le type de terminal de l'utilisateur existe, tput rapporte sa description dans le flux de sortie standard, sans saut de ligne final. Voir terminfo(5).

Note : Rediriger la sortie de “tput init” ou “tput reset” vers un fichier ne capturera qu'une partie de leurs actions. Les modifications des modes du terminal ne sont pas affectées par la redirection du descripteur de fichier, car les modes du terminal sont modifiés via ioctl(2).

Alias

Si tput est invoqué via un lien portant l'un des noms clear, init ou reset, il fonctionne comme s'il était exécuté avec l'opérande (pseudo-)capacité correspondant. Par exemple, exécuter un lien nommé reset qui pointe vers tput a le même effet que « tput reset ».

Cette fonctionnalité a été introduite par ncurses 5.2 en 2000. Elle est rarement utilisée :

clear
est un programme distinct, à la fois plus petit et exécuté plus fréquemment.
init
a le même nom qu'un autre programme largement utilisé.
reset
est fourni par l'utilitaire tset(1) (également via un lien nommé reset).

Taille du terminal

Outre les pseudo-capacités (telles que init), tput traite les codes-cap lines et cols de manière spéciale : il peut appeler setupterm(3X) pour obtenir la taille du terminal.

  • Tout d'abord, tput tente d'obtenir ces capacités à partir de la base de données du terminal. Cela échoue généralement pour les émulateurs de terminal, qui n'ont pas de taille de fenêtre fixe et omettent donc les capacités.

  • Enfin, il examine les variables d'environnement LINES et COLUMNS, qui peuvent remplacer la taille du terminal.

    OPTIONS

    -S
    récupère plusieurs capacités par invocation de tput. Les capacités doivent être passées à tput depuis le flux d'entrée standard au lieu de la ligne de commande (voir la section « EXEMPLES » ci-dessous). Une seule cap-code est autorisée par ligne. L'option -S modifie la signification des statuts de sortie 0 et 1 (voir la section « STATUT DE SORTIE » ci-dessous).
    Certaines capacités utilisent des paramètres de chaîne plutôt que numériques. tput utilise une table interne et la présence de paramètres dans son entrée pour décider comment les interpréter, et s'il faut utiliser tparm(3X).
    -T type
    indique le type de terminal. Normalement, cette option est inutile, car une valeur par défaut est prise à partir de la variable d'environnement TERM. Si spécifiée, les variables d'environnement LINES et COLUMNS sont également ignorées.
    -V
    signale la version de ncurses associée à tput, et quitte avec un statut de succès.
    -x
    empêche « tput clear » de tenter d'effacer le tampon de défilement.

    STATUT DE SORTIE

    Normalement, il faut interpréter les statuts de sortie de tput comme suit.

    Statut Signification lorsque -S n'est pas spécifié
    0 Capacité booléenne ou chaîne présente
    1 Capacité booléenne ou numérique absente
    2 Erreur d'utilisation ou type de terminal non spécifié
    3 Type de terminal non reconnu
    4 Code de capacité non reconnu
    >4 Erreur système (4 + errno)

    Lorsque l'option -S est utilisée, certains statuts changent de signification.

    Statut Signification lorsque -S est spécifié
    0 tous les opérandes interprétés
    1 inutilisé
    4 certains opérandes non interprétés

    ENVIRONNEMENT

    tput lit une variable d'environnement.

    TERM
    dénote le type de terminal. Chaque type de terminal est distinct, bien que beaucoup soient similaires. L'option -T remplace sa valeur.

    FICHIERS

    /usr/share/tabset
    base de données d'initialisation des tabulations
    /usr/share/terminfo
    base de données compilée des descriptions de terminaux

    PORTABILITÉ

    Au fil du temps, le tput de ncurses a différé de celui de System V sur deux points importants, l'un étant maintenant principalement historique.

    •
    « tput cap-code » écrit sur la sortie standard, qui n'a pas besoin d'être un périphérique terminal. Cependant, les opérandes qui manipulent les modes du terminal peuvent ne pas utiliser la sortie standard.
    Les opérandes init et reset de System V tput utilisent la logique de 4.1cBSD tset, manipulant les modes du terminal. Il vérifie les mêmes descripteurs de fichiers (et /dev/tty) pour l'association à un périphérique terminal que ce que fait maintenant ncurses, et si aucun n'est trouvé, il suppose finalement un terminal de 1200 bauds. Lors de la mise à jour des modes du terminal, il ignore les erreurs.
    Jusqu'à ncurses 6.1 (voir la section « HISTORIQUE » ci-dessous), tput ne modifiait pas les modes du terminal. Il utilise maintenant un schéma similaire à System V, utilisant des fonctions partagées avec tset (et finalement basées sur 4.4BSD tset). S'il ne parvient pas à ouvrir un terminal (par exemple, lorsqu'il est exécuté par cron(1)), tput quitte avec un statut d'erreur.
    •
    System V tput suppose que le type d'un opérande cap-code est numérique si tous les caractères de sa valeur sont des nombres décimaux ; sinon, il traite cap-code comme une capacité de chaîne.
    La plupart des implémentations qui prennent en charge les opérandes cap-code utilisent la fonction tparm(3X) pour développer ses paramètres. Cette fonction attend un mélange de paramètres numériques et de chaînes, obligeant tput à savoir quel type utiliser.
    Le tput de ncurses utilise une table pour déterminer les types de paramètres pour les opérandes cap-code standard, et une fonction interne pour analyser les opérandes cap-code non standard.
    Bien que plus fiable que l'utilitaire de System V, un problème de portabilité est introduit par cette analyse. Un développeur d'OpenBSD a adapté la fonction de bibliothèque interne de ncurses pour porter le tput basé sur termcap de NetBSD vers terminfo, et l'a modifié pour interpréter plusieurs cap-codes (et paramètres) sur la ligne de commande. Les applications portables ne devraient pas s'appuyer sur cette fonctionnalité ; ncurses l'offre pour prendre en charge les applications écrites spécifiquement pour OpenBSD.

    Cette implémentation, contrairement à d'autres, accepte les codes cap-code de termcap et terminfo si le support de termcap est compilé. Dans ce cas, cependant, les codes prédéfinis de termcap et terminfo présentent deux ambiguïtés ; ncurses suppose le code terminfo.

    • Le cap-code dl signifie delete_line pour termcap mais parm_delete_line pour terminfo. termcap utilise le code DL pour parm_delete_line. terminfo utilise le code dl1 pour delete_line.
    • Le cap-code ed signifie exit_delete_mode pour termcap mais clr_eos pour terminfo. termcap utilise le code cd pour clr_eos. terminfo utilise le code rmdc pour exit_delete_mode.

    L'opérande longname, l'option -S et les fonctionnalités de substitution de paramètres utilisées dans l'exemple cup ci-dessous, n'étaient pas prises en charge dans curses d'AT&T/USL avant SVr4 (1989). Plus tard, 4.3BSD-Reno (1990) a ajouté la prise en charge de longname, et en 1994, NetBSD a ajouté la prise en charge des fonctionnalités de substitution de paramètres.

    IEEE Std 1003.1/The Open Group Base Specifications Issue 7 (POSIX.1-2008) documentent uniquement les opérandes clear, init et reset. Quelques observations intéressantes découlent de cette sélection.

    • ncurses prend en charge clear comme tout autre cap-code standard. Les autres (init et longname) ne correspondent pas à des capacités de terminal.
    • Le tput sur les systèmes basés sur SVr4 comme Solaris, IRIX64 et HP-UX, ainsi que d'autres comme AIX et Tru64, prennent également en charge les opérandes cap-code standard.
    • Quelques plateformes comme FreeBSD reconnaissent les codes termcap plutôt que les codes de capacité terminfo dans leurs commandes tput respectives. Depuis 2010, le tput de NetBSD utilise les codes terminfo. Avant cela, il (comme FreeBSD) reconnaissait les codes termcap.
    À partir de 2021, FreeBSD utilise le tput de ncurses, configuré à la fois pour terminfo (testé en premier) et termcap (en secours).

    Parce que (apparemment) tous les systèmes Unix certifiés prennent en charge l'ensemble complet des codes de capacité, la raison de ne documenter que quelques-uns peut ne pas être évidente.

    • X/Open Curses Issue 7 documente tput différemment, avec cap-code et les autres fonctionnalités utilisées dans cette implémentation.
    • C'est-à-dire qu'il existe deux normes pour tput : POSIX (un sous-ensemble) et X/Open Curses (l'implémentation complète). POSIX documente un sous-ensemble pour éviter la complication de l'inclusion de X/Open Curses et de la base de données des capacités de terminal.
    • Bien qu'il soit certainement possible d'écrire un programme tput sans utiliser curses, aucun système avec une implémentation de curses ne fournit d'utilitaire tput qui ne prenne pas également en charge les cap-codes standard.

    X/Open Curses Issue 7 (2009) est la première version à documenter les utilitaires. Cependant, cette partie de X/Open Curses ne suit pas la pratique existante (c'est-à-dire le comportement de curses de System V).

    • Elle attribue le statut de sortie 4 à « opérande invalide », qui peut avoir la même signification que « capacité inconnue ». Par exemple, le code source de Solaris xcurses utilise le terme « invalide » dans ce cas.
    • Elle attribue le statut de sortie 255 à une variable numérique qui n'est pas spécifiée dans la base de données terminfo. C'est probablement une erreur de documentation, confondant le « -1 » écrit sur la sortie standard pour indiquer une capacité numérique absente ou annulée avec un statut de sortie (non signé).

    Les différentes implémentations de System V (AIX, HP-UX, Solaris) utilisent les mêmes statuts de sortie que ncurses.

    NetBSD curses documente des statuts de sortie qui ne correspondent ni à ncurses ni à X/Open Curses.

    HISTORIQUE

    Bill Joy a écrit une commande tput lors du développement de 4BSD en octobre 1980. Cette version initiale ne faisait que nettoyer l'écran, et n'était pas incluse dans les distributions officielles.

    System V a développé une commande tput différente.

    • SVr2 (1984) fournissait un tput rudimentaire qui vérifiait
    tput(1) - Documentation Linux

    HISTOIRE

    La commande tput est apparue dans les anciennes versions de System V.

    • Les premières versions de tput, utilisées avec le système termcap, étaient une simple interface à la routine de bibliothèque tparm(3X). L'utilisateur spécifiait un code de capacité et des paramètres facultatifs. La commande imprimait la chaîne de sortie résultante. Il n'y avait pas de vérification que la capacité soit supportée, et les paramètres qui ne sont pas utilisés par la capacité sont simplement ignorés. Les chaînes retournées par tput n'ont pas été mises en cache. Les versions plus anciennes du programme utilisaient la routine tputs plutôt que tparm. Ces versions ne pouvaient pas utiliser de paramètres pour des capacités prédéfinies, et le programme ne donnait qu'une valeur 0 pour ces dernières. tput a été étendu pour supporter les paramètres, et a été refondu pour appeler directement tparm au lieu de tputs. Il était possible de spécifier des chaînes de paramètre dans la base de données termcap elle-même. Ce programme a été écrit par David A. Pike.

    • BSD tset (voir tset(1)) était un programme qui utilisait la base de données terminfo pour initialiser le terminal, définir les paramètres de ligne, et mettre en place une terminale de secours. Au fil du temps, le programme a incorporé la routine de bibliothèque tparm(3X), et a ajouté la capacité de traiter les paramètres spécifiés dans les bases de données terminfo ou termcap. Il a été étendu pour gérer les opérandes d'initialisation et de réinitialisation. Le programme de base utilisait les capacités termcap pour obtenir des informations, tandis que la version System V utilisait les capacités terminfo. Les opérandes init et reset ont été ajoutés pour obtenir la fonctionnalité de réinitialisation de BSD tset. Le programme original de BSD n'utilisait pas tparm(3X) pour les capacités paramétrées.
    • SVr3 (1987) a remplacé cela par un programme plus complet dont la prise en charge des opérandes init et reset (plus de la moitié du programme) incorporait la fonctionnalité reset de BSD tset écrit par Eric Allman.
    • SVr4 (1989) a ajouté l'initialisation des couleurs en utilisant les capacités orig_colors (oc) et orig_pair (op) dans sa logique init.

    Keith Bostic a refactorisé BSD tput pour sa distribution dans 4.3BSD-Tahoe (1988), puis l'a remplacé l'année suivante par une nouvelle implémentation basée sur SVr4 tput. La version de Bostic acceptait similairement certains paramètres nommés pour des (pseudo-)capacités terminfo : clear, init, longname, et reset. Cependant, parce qu'il ne disposait que de termcap, il acceptait des codes termcap pour d'autres capacités. De plus, le BSD tput de Bostic ne modifiait pas les modes du terminal comme l'avait fait le BSD tset antérieur.

    Au même moment, Bostic a ajouté un script shell nommé « clear » qui utilisait tput pour effacer l'écran. Ces deux éléments sont apparus dans 4.4BSD, devenant l'implémentation BSD « moderne » de tput.

    L'origine du tput de ncurses se situe en dehors de System V et de BSD, dans le paquet mytinfo de Ross Ridge, publié sur comp.sources.unix en décembre 1992. Le programme de Ridge faisait une utilisation plus sophistiquée des capacités du terminal que le programme BSD. Eric Raymond a utilisé ce programme tput (et d'autres parties de mytinfo) dans ncurses en juin 1995. En incorporant les parties traitant des capacités du terminal presque sans modification, Raymond a apporté des améliorations à la façon dont les paramètres de la ligne de commande étaient gérés.

    Avant ncurses 6.1 (2018), ses utilitaires tset et tput différaient.

    • tset était plus efficace, réinitialisant les modes du terminal et les caractères spéciaux.
    • En revanche, le répertoire de capacités de terminal de tset pour réinitialiser le terminal était plus limité ; il ne possédait que les équivalents de reset_1string (rs1), reset_2string (rs2), et reset_file (rf), et non les fonctionnalités de mise à jour des taquets de tabulation et des marges de tput.

    Le programme reset est traditionnellement un alias pour tset en raison de sa capacité à réinitialiser les modes du terminal et les caractères spéciaux.

    Depuis ncurses 6.1, les fonctionnalités « reset » des deux programmes sont (principalement) les mêmes. Deux différences mineures subsistent.

    • Le programme tset attend une seconde lors de la réinitialisation, au cas où le terminal serait un périphérique matériel.
    • Les deux programmes écrivent les chaînes d'initialisation du terminal sur des flux différents ; c'est-à-dire, la sortie d'erreur standard pour tset et la sortie standard pour tput.

    EXEMPLES

    tput init
    Initialise le terminal selon le type de terminal dans la variable d'environnement TERM. Si le système n'initialise pas de manière fiable le terminal lors de la connexion, cette commande peut être incluse dans $HOME/.profile après l'exportation de la variable d'environnement TERM.
    tput -T5620 reset
    Réinitialise un terminal AT&T 5620, en remplaçant le type de terminal dans la variable d'environnement TERM.
    tput cnorm
    Définit la visibilité du curseur sur normale.
    tput home
    Déplace le curseur à la ligne 0, colonne 0 : le coin supérieur gauche de l'écran, généralement connu sous le nom de position du curseur « home ».
    tput clear
    Efface l'écran : écrit la valeur de la capacité clear_screen sur le flux de sortie standard.
    tput cols
    Rapporte le nombre de colonnes utilisées par le type de terminal actuel.
    tput -Tadm3a cols
    Rapporte le nombre de colonnes utilisées par un terminal ADM-3A.
    strong=`tput smso` normal=`tput rmso`
    Définit des variables shell avec des valeurs de capacité : strong et normal, pour commencer et terminer, respectivement, le mode de mise en évidence pour le terminal. On pourrait les utiliser pour présenter une invite.
    printf "${strong}Nom d'utilisateur:${normal} "
    tput hc
    Indique par un statut de sortie si le terminal est un périphérique d'impression.
    tput cup 23 4
    Déplace le curseur à la ligne 23, colonne 4.
    tput cup
    Rapporte la valeur de la capacité cursor_address (cup) (utilisée pour le déplacement du curseur), sans aucune substitution de paramètre.
    tput longname
    Rapporte la description de la base de données terminfo du type de terminal spécifié dans la variable d'environnement TERM.
    tput -S
    Traite plusieurs capacités. L'option -S peut être utilisée de manière profitable avec un « here document » shell.
    $ tput -S <<!
> clear
> cup 10 10
> bold
> !
    Ce qui précède efface l'écran, déplace le curseur à la position (10, 10) et active le mode gras (extra lumineux).
    tput clear cup 10 10 bold
    Effectue les mêmes actions que l'exemple précédent « tput -S ».
