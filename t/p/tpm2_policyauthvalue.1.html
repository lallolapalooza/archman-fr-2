tpm2_policyauthvalue(1) Manuel des commandes générales tpm2_policyauthvalue(1)

NOM

tpm2_policyauthvalue(1) - Permet de lier une politique à la valeur d'autorisation de l'objet TPM autorisé.

SYNOPSIS

tpm2_policyauthvalue [OPTIONS]

DESCRIPTION

tpm2_policyauthvalue(1) - Active une politique qui exige que le mot de passe d'authentification de l'objet soit fourni. Ceci est équivalent à s'authentifier en utilisant le mot de passe de l'objet en texte clair ou HMAC. Il l'impose comme une politique. Il fournit un mécanisme pour permettre l'authentification par mot de passe lorsqu'un objet n'autorise que l'autorisation basée sur une politique, c'est-à-dire que l'attribut d'objet “userwithauth” est 0.

OPTIONS

•
-L, --policy=FICHIER:

Fichier où enregistrer le digest de politique composé.

•
-S, --session=FICHIER:

Le fichier de session de politique généré via l'option -S de tpm2_startauthsession(1).

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash.

Configuration du TCTI

Le TCTI ou “Transmission Interface” est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option en ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option en ligne de commande a toujours priorité sur la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne supporte *AUCUNE* option et *DOIT* être présenté comme le texte exact de “none”.

Les arguments de l'option en ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> résulte en l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI implémentant l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS DU TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur sont séparées par un caractère `=.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limité à `session' et `system'.

Spécifier le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

pour s'authentifier à l'aide de la valeur en clair de l'objet TPM. Bien que nous puissions nous authentifier avec une session de mot de passe éphémère, dans cet exemple, nous nous authentifierons avec la phrase secrète en clair dans une session de politique à la place, en utilisant l'outil tpm2_policyauthvalue(1).

Créer la politique de mot de passe

tpm2_startauthsession -S session.dat
tpm2_policyauthvalue -S session.dat -L policy.dat
tpm2_flushcontext session.dat

Créer l'objet avec une phrase secrète et la politique de mot de passe

tpm2_createprimary -C o -c prim.ctx
tpm2_create -g sha256 -G aes -u key.pub -r key.priv -C prim.ctx -L policy.dat \
  -p testpswd

S'authentifier avec une phrase secrète en clair

tpm2_load -C prim.ctx -u key.pub -r key.priv -n key.name -c key.ctx
echo "plaintext" > plain.txt
tpm2_encryptdecrypt -c key.ctx -o encrypt.out plain.txt -p testpswd

S'authentifier avec un mot de passe et la politique

tpm2_startauthsession --policy-session -S session.dat
tpm2_policyauthvalue -S session.dat
tpm2_encryptdecrypt -c key.ctx -o encrypt.out -p session:session.dat+testpswd \
plain.txt
tpm2_flushcontext session.dat

Retours

Les outils peuvent renvoyer l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.

Limitations

Il attend qu'une session soit déjà établie via tpm2_startauthsession(1) et nécessite l'un des éléments suivants :

•
accès direct au périphérique
•
support de session étendue avec tpm2-abrmd.

Sans cela, la plupart des gestionnaires de ressources ne sauvegarderont pas l'état de la session entre les invocations de commandes.
