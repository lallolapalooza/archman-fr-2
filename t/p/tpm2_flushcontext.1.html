tpm2_flushcontext(1) Manuel des commandes générales tpm2_flushcontext(1)

NOM

tpm2_flushcontext(1) - Supprime un handle spécifié, ou tous les contextes associés à un objet transitoire, une session chargée ou une session sauvegardée du TPM.

SYNTAXE

tpm2_flushcontext [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_flushcontext(1) - Supprime un handle spécifié, ou tous les contextes associés à un objet transitoire, une session chargée ou une session sauvegardée du TPM. L'objet à vider est spécifié comme premier argument de l'outil et est sous l'une des formes suivantes : - Le handle de l'objet à vider du TPM. Doit être un numéro de handle valide. - Vide une session via un fichier de session. Un fichier de session est généré à partir de l'option -S de tpm2_startauthsession(1).

OPTIONS

•
-t, --transient-object:

Supprime tous les objets transitoires.

•
-l, --loaded-session:

Supprime toutes les sessions chargées.

•
-s, --saved-session:

Supprime toutes les sessions sauvegardées.

•
ARGUMENT L'argument de la ligne de commande spécifie l'OBJET à retirer de la mémoire résidente du TPM.
•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. C'est ce qu'on appelle couramment le cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche la page man de l'outil. Par défaut, il tente d'appeler le pagineur man pour l'outil, mais en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, cependant si un “man” explicite est demandé, l'outil fournira les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le pagineur man échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages man, il faut que les pages man soient installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version pour cet outil, les tctis supportés et quitte.
•
-V, --verbose: Augmente les informations que l'outil imprime sur la console pendant son exécution. En utilisant cette option, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet: Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata: Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush: Active le vidage automatique pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Le vidage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true.

Configuration du TCTI

Le TCTI, ou “Interface de Transmission”, est le mécanisme de communication avec le TPM. Les TCTIs peuvent être changés pour communiquer avec des TPMs via différents médiums.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lorsque l'on communique directement avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne supporte *AUCUNE* option et *DOIT* être présenté comme le texte exact “none”.

Les arguments pour l'option de ligne de commande ou la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

La spécification d'une chaîne vide pour le <nom-tcti> ou le <config-options-tcti> résulte en l'utilisation de la valeur par défaut pour cette partie respectivement.

Valeurs par défaut du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim *DANS CET ORDRE* et *UTILISERONT LE PREMIER TROUVÉ*. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute du nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur sont séparées par un caractère `='.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifier le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes

EXEMPLES

Vider un objet transitoire

Généralement, lors de l'utilisation du TPM, les interactions se font via un gestionnaire de ressources, comme tpm2-abrmd(8). Lorsque le processus se termine, les identifiants d'objets transitoires sont vidés. Par conséquent, le vidage des objets transitoires via la ligne de commande n'est pas nécessaire. Cependant, lors de l'interaction directe avec le TPM, ce scénario est possible. L'exemple ci-dessous suppose un accès TPM direct non médiatisé par un gestionnaire de ressources. Spécifiquement, nous utiliserons le simulateur.

tpm2_createprimary -Tmssim -c primary.ctx
tpm2_getcap -T mssim handles-transient
- 0x80000000
tpm2_flushcontext -T mssim 0x80000000

Vider tous les objets transitoires

tpm2_flushcontext \--transient-object

Vider une session

tpm2_startauthsession -S session.dat
tpm2_flushcontext session.dat

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
