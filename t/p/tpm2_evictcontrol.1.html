tpm2_evictcontrol(1) Manuel des commandes générales tpm2_evictcontrol(1)

NOM

tpm2_evictcontrol(1) - Rendre un objet transitoire persistant ou expulser un objet persistant.

SYNOPIS

tpm2_evictcontrol [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_evictcontrol(1) - Permet de rendre un objet transitoire persistant ou d'expulser un objet persistant. L'argument HANDLE contrôle l'index auquel le handle sera assigné. Si l'objet spécifié via -c est transitoire et qu'un HANDLE permanent est spécifié, l'objet sera rendu persistant au HANDLE. Si HANDLE est un -, alors l'objet sera rendu persistant au premier emplacement de handle permanent disponible. Si l'objet spécifié via -c est un handle permanent, alors l'objet sera expulsé de son emplacement de handle permanent.

OPTIONS

•
-C, --hierarchy=OBJECT:

La hiérarchie d'autorisation utilisée pour autoriser les commandes. La valeur par défaut est la hiérarchie “propriétaire”. Options prises en charge :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<num> où un nombre brut peut être utilisé.
•
-c, --object-context=OBJECT:

Un spécificateur d'objet de contexte d'un objet transitoire ou persistant. Si OBJECT est un objet transitoire, il sera rendu persistant, soit au handle spécifié par l'argument, soit au premier handle persistant vacant disponible. Si l'objet OBJECT est pour un objet persistant, alors l'objet sera expulsé de la mémoire non volatile.

•
-P, --auth=AUTH:

La valeur d'autorisation pour la hiérarchie spécifiée avec -C.

•
-o, --output=FILE:

Optionnellement, sortie d'un objet sérialisé représentant le handle persistant. S'ils ne sont pas altérés, ces fichiers sont plus sûrs à utiliser que les handles persistants bruts. Un handle persistant brut doit être vérifié pour s'assurer que l'objet auquel il pointe est celui attendu.

•
--cphash=FILE

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash.

•
ARGUMENT l'argument de ligne de commande spécifie le handle persistant dans lequel enregistrer l'objet transitoire.

Sortie

L'outil produit un dictionnaire conforme YAML avec les champs : persistent-handle: action: evicted|persisted

Où persistent-handle est le handle sur lequel l'action a eu lieu. Où action peut être soit evicted (expulsé) soit persisted (rendu persistant). Si un objet est expulsé, alors l'objet n'est plus résident à l'adresse persistent-handle dans le TPM. Si un objet est rendu persistant, alors l'objet est résident à l'adresse persistent-handle dans le TPM.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante dans l'ordre :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument est une correspondance de préfixe sur l'un des éléments suivants :
•
owner: la hiérarchie du propriétaire
•
platform: la hiérarchie de la plateforme
•
endorsement: la hiérarchie d'endossement
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.

Format des autorisations

L'autorisation pour utiliser un objet en TPM2.0 peut se présenter sous 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : « Les autorisations par défaut sont le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes ci-dessous en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe “str:” ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe “hex:” est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe avec des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe “file:”, devrait être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un “-” pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe passés en tant qu'options pouvant être lus depuis la liste des processus ou les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour écho un mot de passe via stdin :
echo foobar | tpm2_tool -p file:-
# pour utiliser une chaîne ici bash via stdin :
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, un mot de passe de politique), ajoutez un + suivi d'une chaîne telle que décrite dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe “pcr:” et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécification-pcr>=<fichier-pcr-brut>

T

he PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant *AUTH*.

OPTIONS COMMUNES

Cet ensemble d'options est commun à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page man de l'outil. Par défaut, il tente d'appeler le paginator man pour l'outil, cependant, en cas d'échec, il affichera un résumé court de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le paginator man échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages man, celles-ci doivent être installées ou se trouver dans *MANPATH*. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tcti pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil affiche sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont affichés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. des informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé pour parler directement au fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lors de leur utilisation sans connexion TCTI. Ne prend en charge *AUCUNE* option et *DOIT ÊTRE* présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cet ensemble d'options est utilisé pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et valeur sont séparées par un caractère `=`.
•
TCTI abrmd prend en charge deux clés :
1.
`bus_name` : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type` : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifiez le nom TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les différents modules TCTI connus.

EXEMPLES

Pour rendre un handle transitoire persistant à l'adresse 0x81010002

tpm2_changeauth -c o ownerauth
tpm2_createprimary -c primary.ctx -P ownerauth
tpm2_evictcontrol -C o -c primary.ctx 0x81010002 -P ownerauth

Pour supprimer un handle persistant

tpm2_evictcontrol -C o -c 0x81010002 -P ownerauth

Pour rendre un handle transitoire persistant et générer un handle persistant sérialisé.

tpm2_evictcontrol -C o -c primary.ctx -o primary.handle -P ownerauth

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
