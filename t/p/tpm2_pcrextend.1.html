tpm2_pcrextend(1) Manuel des commandes générales tpm2_pcrextend(1)

NOM

tpm2_pcrextend(1) - Étend un PCR.

SYNTAXE

tpm2_pcrextend [OPTIONS] SPEC_COND_DIGEST_PCR

DESCRIPTION

tpm2_pcrextend(1) - Étend les PCR avec les valeurs indiquées par SPEC_COND_DIGEST_PCR.

Un SPEC_COND_DIGEST_PCR est défini comme suit :

•
Un identifiant numérique de PCR.
•
Un deux-points suivi de la spécification du hachage de l'algorithme.

La spécification du hachage de l'algorithme est la suivante : * Le nom convivial de l'algorithme ou son numéro brut. * Un signe égal. * La valeur hexadécimale du hachage.

Exemple de Spécification de Digest

4:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15

Note : Plusieurs spécifications de PCR et de hachage sont autorisées. Plusieurs hachages entraînent l'extension du PCR avec les deux hachages. Plusieurs mêmes valeurs de PCR entraînent l'extension du PCR à plusieurs reprises. L'extension se fait dans l'ordre, de gauche à droite, tel que spécifié. Au plus 5 extensions de hachage par entrée de PCR sont prises en charge. Ceci est fait pour simplifier l'analyseur.

OPTIONS

Cet outil n'accepte aucune option spécifique à l'outil.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page de manuel de l'outil. Par défaut, il tente d'appeler le gestionnaire de pages de manuel pour l'outil, mais en cas d'échec, il affiche un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, cependant, si « man » est explicitement demandé, l'outil fournira des erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le gestionnaire de pages de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser correctement la fonctionnalité des pages de manuel, celles-ci doivent être installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version de cet outil, les tcti supportés et quitte.
•
-V, --verbose : Augmente les informations que l'outil imprime sur la console pendant son exécution. Lorsque cette option est utilisée, le numéro de fichier et de ligne sont affichés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active la suppression automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également supprimé. La suppression automatique peut également être activée si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true.

Configuration TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT être présenté sous la forme exacte de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera quel TCTI parmi les susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur de chaîne sont séparées par un caractère `= '.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes.

Spécificateurs de banques PCR

EXEMPLES

Étendre la banque SHA1 du PCR 4 avec un hachage

tpm2_pcrextend 4:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15

Étendre le PCR 4

tpm2_pcrextend 4:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15 \
    sha256=7509e5bda0c752fc225797927011774589a94827a23413d130168553065350b0

Étendre le PCR 10 avec deux hachages différents

tpm2_pcrextend 10:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15:sha256=7509e5bda0c752fc225797927011774589a94827a23413d130168553065350b0

Étendre le PCR 10 deux fois avec le même hachage

tpm2_pcrextend 10:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15 \
    10:sha1=f1d2d2f924e986ac86fdf7b36c94bcdf32beec15

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non pris en charge. Applicable à tpm2_testparams.
