tpm2_quote(1) Manuel des commandes générales tpm2_quote(1)

NOM

tpm2_quote(1) - Fournit une citation et une signature du TPM.

SYNTAXE

tpm2_quote [OPTIONS]

DESCRIPTION

tpm2_quote(1) - Fournit une citation et une signature pour une liste donnée de PCR dans l'algorithme/les banques spécifiés.

OPTIONS

•
-c, --key-context=OBJET:

Objet de contexte pour la clé de signature de citation.

•
-p, --auth=AUTH:

Spécifie la valeur d'autorisation pour la clé AK spécifiée par l'option -C.

•
-l, --pcr-list=PCR:

La liste des banques PCR et des identifiants des PCR sélectionnés pour chaque banque. Voir aussi la section NOTES ci-dessous.

•
-m, --message=FICHIER:

Fichier de sortie du message, enregistre le message de citation qui constitue les données signées par le TPM.

•
-s, --signature=FICHIER:

Fichier de sortie de la signature, enregistre la signature dans le format spécifié via l'option -f.

•
-f, --format=FORMAT:

Sélection du format pour le fichier de sortie de la signature.

•
-o, --pcr=FICHIER.

Fichier de sortie des PCR, facultatif, enregistre la liste des valeurs PCR telles que définies par -l.

•
-F, --pcrs_format=FORMAT:

Sélection du format pour le bloc binaire dans le fichier de sortie des PCR. 'values' produira un bloc binaire des valeurs PCR. 'serialized' produira un bloc binaire des valeurs PCR sous la forme d'une structure de données sérialisée au format little-endian. Facultatif. Par défaut : 'serialized'.

•
-q, --qualification=CHAINE_HEX_OU_CHEMIN:

Données fournies sous forme de chaîne hexadécimale ou de fichier binaire pour qualifier la citation, facultatif. Ceci est généralement utilisé pour ajouter un nonce contre les attaques par rejeu.

•
-g, --hash-algorithm:

Algorithme de hachage pour la signature. Par défaut : sha256.

•
--scheme=ALGORITHME:

Le schéma de signature utilisé pour signer le message. Facultatif. Les schémas de signature doivent suivre les « normes de formatage », voir la section « Spécificateurs d'algorithmes ». Voir également la section « Schémas de signature pris en charge » pour une liste des schémas de signature pris en charge. S'il est spécifié, le schéma de signature doit correspondre au type de clé. S'il n'est pas spécifié, un schéma de signature par défaut pour le type de clé sera utilisé.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash.

Références

Format de l'Objet de Contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre*:

•
Si l'argument est un chemin de fichier, le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un *préfixe* parmi :
•
owner : la hiérarchie du propriétaire
•
platform : la hiérarchie de la plateforme
•
endorsement : la hiérarchie d'approbation
•
lockout : l'objet persistant de contrôle du verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013, et utilisé directement.

Formatage de l'Autorisation

L'autorisation d'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes ci-dessous à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont supposés être sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: » est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou non compatibles avec le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: » doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche les fuites d'informations ; les mots de passe transmis en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes d'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour écho d'un mot de passe via stdin :
echo motdepasse | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin :
tpm2_tool -p file:- <<< motdepasse

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécification-pcr>=<fichier-pcr-brut>

tpm2_quote(1)

tpm2_quote(1) - quote PCR values.

tpm2_quote [OPTIONS] [ARGUMENTS]

tpm2_quote is used to read PCR values from the TPM and return a quote for the PCRs. The quote is a signed digest of the PCR values and may be used to attest to the state of the platform.

Description

The tpm2_quote command is used to generate a signed quote for a set of PCRs. This command is useful for attesting to the integrity of the system by providing a cryptographically signed digest of the PCR values. The PCRs quoted are specified by PCR bank specifiers.

The PCR spec is documented in in the section “PCR bank specifiers”.

The raw-pcr-file is an optional argument that contains the output of the raw PCR contents as returned by tpm2_pcrread(1).

PCR bank specifiers

Examples

To satisfy a PCR policy of sha256 on banks 0, 1, 2 and 3 use a specifier of:

pcr:sha256:0,1,2,3

specifying AUTH.

Signature Format Specifiers

Format selection for the signature output file. tss (the default) will output a binary blob according to the TPM 2.0 specification and any potential compiler padding. The option plain will output the plain signature data as defined by the used cryptographic algorithm. signature FORMAT.

PCR Bank Specifiers

PCR Bank Selection lists follow the below specification:

<BANK>:<PCR>[,<PCR>] or <BANK>:all

multiple banks may be separated by `+'.

For example:

sha1:3,4+sha256:all

will select PCRs 3 and 4 from the SHA1 bank and PCRs 0 to 23 from the SHA256 bank.

Certain commands support specifying forward sealing values as well:

sha1:0,1=da39a3ee5e6b4b0d3255bfef95601890afd80709,2

This will select the current values for PCRs 0 and 2, but use the specified value for PCR 1. Digest lengths must match the bank size. An optional 0x prefix will be stripped off.

Note

PCR Selections allow for up to 5 hash to pcr selection mappings. This is a limitation in design in the single call to the tpm to get the pcr values.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

tpm2_createprimary -C e -c primary.ctx

tpm2_load -C primary.ctx -u key.pub -r key.priv -c key.ctx
tpm2_quote -Q -c key.ctx -l 0x0004:16,17,18+0x000b:16,17,18

NOTES

The maximum number of PCR that can be quoted at once is associated with the maximum length of a bank.

On most TPMs, it means that this tool can quote up to 24 PCRs at once.
