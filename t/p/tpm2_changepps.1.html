tpm2_changepps(1) Manuel des commandes générales tpm2_changepps(1)

NOM

tpm2_changepps(1) - Remplace la graine primaire de plateforme active par une nouvelle générée à partir du RNG du TPM2.

SYNOPIS

tpm2_changepps [OPTIONS]

DESCRIPTION

tpm2_changepps(1) - Remplace la graine primaire de plateforme active par une nouvelle générée à partir du RNG du TPM2. Les objets Transitoires et Persistants sous la hiérarchie de la plateforme sont perdus tout en conservant les objets NV.

OPTIONS

•
-p, --auth spécifie l'AUTH pour la hiérarchie de la plateforme.
•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash, sauf si rphash est également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est couramment appelé rpHash.

•
-S, --session=FICHIER:

La session créée à l'aide de tpm2_startauthsession. Ceci peut être utilisé pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

Références

Formatage de l'autorisation

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : "Les autorisations sont par défaut un MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées".

Mots de passe

Les mots de passe sont interprétés sous les formes ci-dessous en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe "str:" ou son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe "hex:" est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe avec des caractères non imprimables et/ou peu conviviaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe "file:" doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un "-" pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche la fuite d'informations, les mots de passe passés en tant qu'options peuvent être lus depuis la liste des processus ou les fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/mot_de_passe
# pour échoer un mot de passe via stdin:
echo foobar | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite le chemin d'un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe "pcr:" et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section "Spécificateurs de banques PCR".

Le fichier-pcr-brut est un argument facultatif qui contient la sortie des contenus PCR bruts tels que retournés par tpm2_pcrread(1).

Spécificateurs de banques PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant l'AUTH.

Configuration du TCTI

Le TCTI ou "Interface de Transmission" est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour la communication avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs connus actuellement sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé pour communiquer directement avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne supporte AUCUNE option et DOIT être présenté comme le texte exact de "none".

Les arguments pour l'option de ligne de commande ou la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). DESCRIPTION

This tool is part of the tpm2-tools suite. It provides an interface to the TPM2_ChangePPS command.

The Change Platform Primary Seed command (ChangePPS) is used to change the platform primary seed (PPS). This command requires that the caller be authorized with the Platform Auth value.

The platform primary seed is used to generate the platform primary key (PPK). The PPK is a primary seed for all primary keys created by the platform. The platform primary seed is used to derive the platform primary key.

The command is intended to be used to change the platform primary seed when the platform primary seed is unknown. This can be used to recover from a situation where the platform primary seed is lost.

If the platform Auth is not specified, the tools will attempt to use an empty string. This is required for the use case where the platform primary seed is unknown.

If the platform Auth is NULL, the command will fail.

This command is intended to be used to change the platform primary seed when the platform primary seed is unknown. This can be used to recover from a situation where the platform primary seed is lost.

The command expects a session to be already established via tpm2_startauthsession(1). The session must have been created with the TPM_SE_POLICY or TPM_SE_TRIAL session attribute.

The command can be used with any of the TCTI modules defined in tpm2-tools(7). The default TCTI is the device TCTI, which is typically /dev/tpm0.

The command can be configured using the TPM2TOOLS_TCTI environment variable, or by using the -T command line option.

TCTI Configuration

The TCTI configuration is used to specify the TCTI module to be used, and any options that are specific to that TCTI module. The TCTI configuration is specified as a string that follows the format: tcti-name:tcti-options.

The tcti-name is the name of the TCTI module to be used. The supported TCTI names are:

•
device: Use the device TCTI module.
•
mssim: Use the mssim TCTI module.
•
abrmd: Use the abrmd TCTI module.

The tcti-options is a string that specifies any options that are specific to the TCTI module. The format of the tcti-options string depends on the TCTI module being used.

If no TCTI configuration is specified, the default TCTI configuration is used. The default TCTI configuration is to use the device TCTI module with no options.

The following is a list of the default TCTI configurations for each TCTI module:

•
device: /dev/tpm0
•
mssim: 127.0.0.1:2321
•
abrmd: None

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.

Limitations

It expects a session to be already established via tpm2_startauthsession(1) and requires one of the following:

•
direct device access
•
extended session support with tpm2-abrmd.

Without it, most resource managers will not save session state between command invocations.
