tpm2_encryptdecrypt(1) Manuel des commandes générales tpm2_encryptdecrypt(1)

NOM

tpm2_encryptdecrypt(1) - Effectue le chiffrement ou le déchiffrement symétrique.

SYNTAXE

tpm2_encryptdecrypt [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_encryptdecrypt(1) - Effectue le chiffrement ou le déchiffrement symétrique avec une clé symétrique spécifiée sur le contenu de FICHIER. Si FICHIER n'est pas spécifié, utilise stdin par défaut.

OPTIONS

•
-c, --key-context=OBJET:

L'objet de clé de chiffrement.

•
-p, --auth=AUTH:

La valeur d'autorisation pour l'objet de clé de chiffrement.

•
-d, --decrypt:

Effectue une opération de déchiffrement. Par défaut, effectue un chiffrement lorsque cette option n'est pas spécifiée.

•
-e, --pad:

Active le remplissage pkcs7 pour les modes de chiffrement AES applicables cfb/cbc/ecb. Applicable uniquement au chiffrement et aux données d'entrée dont le dernier bloc est plus court que la longueur du bloc de chiffrement.

•
-o, --output=FICHIER ou STDOUT:

Le chemin du fichier de sortie pour les données chiffrées ou déchiffrées. S'il n'est pas spécifié, utilise stdout par défaut.

•
-G, --mode=ALGORITHME:

L'algorithme de clé associé à cet objet. Par défaut, utilise les propriétés de l'objet ou CFB s'il n'est pas défini.

•
-t, --iv=FICHIER:

Vecteur d'initialisation optionnel à utiliser. Par défaut, utilise des zéros. La syntaxe permet de spécifier une source de fichier d'entrée et une source de fichier de sortie. Le chemin du fichier d'entrée est le premier, suivi éventuellement d'un deux-points ":" et du chemin du fichier IV de sortie. Cet IV de sortie peut être sauvegardé pour des appels ultérieurs lors de l'enchaînement.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash.

•
ARGUMENT l'argument de ligne de commande spécifie le chemin du fichier d'entrée FICHIER des données à chiffrer ou déchiffrer.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante, dans l'ordre :

•
Si l'argument est un chemin de fichier, le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un préfixe de l'un des éléments suivants :
•
owner : la hiérarchie du propriétaire
•
platform : la hiérarchie de la plateforme
•
endorsement : la hiérarchie d'endossement
•
lockout : l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement._OBJET_.

Formatage de l'autorisation

L'autorisation pour l'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : "Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées".

Mots de passe

Les mots de passe sont interprétés sous les formes ci-dessous à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe "str:" ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe "hex:" est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou peu pratiques pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe "file:" doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil ou un "-" pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche la fuite d'informations, les mots de passe passés en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes d'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour écho d'un mot de passe via stdin:
echo foobar | tpm2_tool -p file:-
# pour utiliser une here-string bash via stdin:
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'autorisation à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'autorisation mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'autorisation HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe "pcr:" et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section "Spécificateurs de banque PCR".

Le fichier-pcr-brut est un argument optionnel qui contient la sortie du contenu PCR brut tel que renvoyé par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

Spécificateurs complexes

Les objets, lorsqu’ils sont spécifiés pour la création par le TPM, ont de nombreux algorithmes à renseigner dans les données publiques. Des éléments tels que le type, le schéma et les détails asymétriques, la taille de la clé, etc. Voici le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de type

Cette partie du spécificateur d’algorithme complexe est obligatoire. Le schéma restant et les détails symétriques seront par défaut en fonction du type spécifié et du type de l’objet en cours de création.

•
aes - AES par défaut : aes128
•
aes128<mode> - AES 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n’est pas spécifié, la valeur par défaut est null.
•
aes192<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - SM4 par défaut : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n’est pas spécifié, la valeur par défaut est null.
•
ecc - Courbe elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - RSA par défaut : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de schéma

Ensuite, c’est un champ optionnel, il peut être ignoré.

Les schémas sont généralement des Schémas de Signature ou des Schémas de Chiffrement Asymétrique. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l’algorithme de hachage est manquant, la valeur par défaut est sha256. Certains ne prennent aucun argument, et d’autres en prennent plusieurs.

Schémas de spécification de schéma optionnels de hachage

Ces spécificateurs de schéma sont suivis d’un trait d’union et d’un algorithme de hachage valide. Par exemple : oaep-sha256.

Ce spécificateur de schéma est suivi d’un compte (taille maximale UINT16) puis d’un trait d’union (-) et d’un algorithme de hachage valide. * ecdaa Par exemple, ecdaa4-sha256. Si aucun compte n’est spécifié, la valeur par défaut est 4.

Schémas de spécification sans option

Ce spécificateur de schéma ne prend AUCUN argument. * rsaes

Spécificateurs de détails symétriques

Ce champ est optionnel et prend par défaut en fonction du type d’objet en cours de création et de ses attributs. Généralement, tout spécificateur Symétrique valide de la liste des Spécificateurs de Type devrait fonctionner. S’il n’est pas spécifié, les détails symétriques des objets asymétriques sont par défaut aes128cfb.

Exemples

Créer une clé rsa2048 avec un schéma de chiffrement asymétrique rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Créer une clé ecc256 avec un schéma de signature ecdaa avec un compte de 4 et un hachage sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algorithmes cryptographiques ALGORITHME.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour la communication avec des TPMs sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L’option de ligne de commande -T ou --tcti
2.
La variable d’environnement : TPM2TOOLS_TCTI.

Note : L’option de ligne de commande remplace toujours la variable d’environnement.

Les TCTIs actuellement connus sont :

tpm2_encryptdecrypt(1) — tpm2-tools — man pages

TCTI Configuration

The TCTI ( TPM Command Transmission Interface ) is used to specify how the tools will communicate with the TPM. The TCTI can be set using the command line option -T, or the environment variable TPM2TOOLS_TCTI. The available TCTIs are:

tabrmd - The resource manager, called
        tabrmd.
        Note that tabrmd and abrmd as a tcti name are synonymous.
mssim - Typically used for communicating to the TPM software
        simulator.
device - Used when talking directly to a TPM device file.
none - Do not initalize a connection with the TPM. Some tools allow for
        off-tpm options and thus support not using a TCTI. Tools that do not
        support it will error when attempted to be used without a TCTI connection.
        Does not support ANY options and MUST BE presented as the
        exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Create an AES key

tpm2_createprimary -c primary.ctx
tpm2_create -C primary.ctx -Gaes128 -u key.pub -r key.priv
tpm2_load -C primary.ctx -u key.pub -r key.priv -c key.ctx

Encrypt and Decrypt some data

echo "my secret" > secret.dat
tpm2_encryptdecrypt -c key.ctx -o secret.enc secret.dat
tpm2_encryptdecrypt -d -c key.ctx -o secret.dec secret.enc
cat secret.dec
my secret
