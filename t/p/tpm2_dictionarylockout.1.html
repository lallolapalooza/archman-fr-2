tpm2_dictionarylockout(1) Manuel des commandes générales tpm2_dictionarylockout(1)

NOM

tpm2_dictionarylockout(1) - Configure ou efface les paramètres de verrouillage par attaque par dictionnaire.

SYNOPSIS

tpm2_dictionarylockout [OPTIONS]

DESCRIPTION

tpm2_dictionarylockout(1) - Configure les paramètres de verrouillage par attaque par dictionnaire ou efface l'état de verrouillage par attaque par dictionnaire.

OPTIONS

•
-s, --setup-parameters:

Indique que l'outil doit configurer les paramètres de verrouillage par attaque par dictionnaire.

•
-c, --clear-lockout:

Indique que l'outil doit effacer l'état de verrouillage par attaque par dictionnaire.

•
-l, --lockout-recovery-time=NOMBRE_NATUREL:

Spécifie le temps d'attente en secondes avant qu'une autre tentative d'authentification TPM_RH_LOCKOUT puisse être effectuée après une authentification échouée.

•
-t, --recovery-time=NOMBRE_NATUREL:

Spécifie le temps d'attente en secondes avant qu'une autre tentative d'authentification d'objet protégé par DA puisse être effectuée après un nombre maximal d'authentifications échouées.

•
-n, --max-tries=NOMBRE_NATUREL:

Spécifie le nombre maximum de tentatives d'authentification autorisées sur un objet protégé par DA ; après quoi DA est activé.

•
-p, --auth=AUTH:

La valeur d'autorisation pour le handle de verrouillage.

•
--cphash=FICHIER

Chemin d'accès au fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il retourne simplement un cpHash.

Références

Format d'autorisation

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : Les autorisations sont par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées.

Mots de passe

Les mots de passe sont interprétés dans les formes ci-dessous à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne de caractères lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: » est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi des mots de passe avec des caractères non imprimables et/ou peu conviviaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: » doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser stdin. Stocker les mots de passe dans des fichiers empêche la fuite d'informations, les mots de passe passés en options peuvent être lus depuis la liste des processus ou les fonctionnalités courantes de l'historique du shell.

Exemples

# utiliser stdin et être invité
file:-
# utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# écho d'un mot de passe via stdin :
echo mdp | tpm2_tool -p file:-
# utiliser une chaîne ici bash via stdin :
tpm2_tool -p file:- <<< mdp

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'autorisation à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'autorisation monmdp.

session:session.ctx+monmdp

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'autorisation HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banques PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie des contenus PCR bruts tels que retournés par tpm2_pcrread(1).

Spécificateurs de banques PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTORISATION.

Configuration TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour communiquer avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel de TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge l'absence de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend pas en charge *AUCUNE* option et *DOIT* être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Valeurs par défaut TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur "default-tcti" indiquera lequel des TCTI susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère ','. Chaque clé et valeur sont séparées par un caractère '='.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifiez le nom du TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

tpm2_dictionarylockout -c -p passwd
tpm2_dictionarylockout -s -n 5 -t 6 -l 7 -p passwd

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
