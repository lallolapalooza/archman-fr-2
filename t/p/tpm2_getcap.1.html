tpm2_getcap(1) Manuel des commandes générales tpm2_getcap(1)

NOM

tpm2_getcap(1) - Affiche les capacités du TPM sous une forme lisible.

SYNTAXE

tpm2_getcap [OPTIONS] [CAPACITÉ]

DESCRIPTION

tpm2_getcap(1) - Interroge le TPM pour ses capacités / propriétés et les affiche sur la console. Il prend une forme textuelle de la capacité à interroger comme argument de l'outil. Les groupes de capacités actuellement supportés sont :

•
algorithms : Affiche des données sur les algorithmes supportés.
•
commands : Affiche des données sur les commandes supportées.
•
pcrs : Affiche les PCRs actuellement alloués.
•
properties-fixed : Affiche les propriétés fixes du TPM.
•
properties-variable : Affiche les propriétés variables du TPM.
•
ecc-curves : Affiche des données sur les courbes elliptiques.
•
handles-transient : Affiche les identifiants des objets transitoires.
•
handles-persistent : Affiche les identifiants des objets persistants.
•
handles-permanent : Affiche les identifiants des objets permanents.
•
handles-pcr : Affiche les identifiants des PCRs.
•
handles-nv-index : Affiche les identifiants des indices NV.
•
handles-loaded-session : Affiche les identifiants des sessions HMAC et de politique chargées.
•
handles-saved-session : Affiche les identifiants des sessions sauvegardées.
•
vendor[:num] : Affiche les propriétés du vendeur sous forme de tampon hexadécimal. La chaîne « vendor » peut être suffixée par deux points suivis d'un nombre tel qu'interprété par strtoul(3) avec une base 0. Cette valeur est utilisée comme valeur de propriété dans la commande TPM2_GetCapability, et vaut par défaut 1. Un exemple pour l'appeler avec une valeur de propriété de 2 est : tpm2_getcap vendor:2

Si les requêtes vendeur bloquent, essayez l'option « -i » pour ignorer le champ moreData et ne lire qu'une seule fois.

NOTE : si les requêtes vendeur bloquent, essayez l'option « -i » pour ignorer le champ moreData et ne lire qu'une seule fois.

OPTIONS

•
-l, --list:

Liste les noms de capacités supportés connus. Ces noms peuvent être fournis comme argument de l'option -c. La sortie est au format liste conforme YAML sur stdout.

Par exemple :

  - algorithms
  - commands
  - properties-fixed
  ...
•
--ignore-moredata

Ignore le champ moreData lors du traitement de réponses TPM erronées.

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche la page de manuel de l'outil. Par défaut, il tente d'invoquer le pageur de manuel pour l'outil, mais en cas d'échec, il affiche un bref résumé de l'outil. C'est le même comportement si l'argument d'option « man » est spécifié, mais si « man » est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option « no-man » est spécifiée, ou si le pageur de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité de pages de manuel, celles-ci doivent être installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version : Affiche les informations de version pour cet outil, les tctis supportés et quitte.
•
-V, --verbose : Augmente les informations que l'outil affiche sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont affichés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
•
-Z, --enable-errata : Active l'application de corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également purgé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true.

Configuration TCTI

Le TCTI ou « Transmission Interface » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs via différents médias.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel du TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors-tpm et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

La spécification d'une chaîne vide pour le <nom-tcti> ou le <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché à l'aide des sémantiques de dlopen(3). Les outils rechercheront tabrmd, device et mssim dans cet ordre et utiliseront le premier trouvé. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'interprété par les sémantiques de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier du périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration i
s a série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et chaîne de valeur sont séparées par un caractère `=`.
•
TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limité à `session' et `system'.

Spécifiez le nom tcti de tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes.

EXEMPLES

Pour lister les propriétés fixes du TPM

tpm2_getcap properties-fixed

Pour lister les groupes de capacités supportés

tpm2_getcap -l

Retourne

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de traitement des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
