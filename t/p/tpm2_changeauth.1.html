tpm2_changeauth(1) Manuel des commandes générales tpm2_changeauth(1)

NOM

tpm2_changeauth - Change les valeurs d'autorisation des objets TPM.

SYNTAXE

tpm2_changeauth [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_changeauth - Configure les valeurs d'autorisation pour les divers hiérarchies, indices NV, objets transitoires et persistants.

Note : Pour les objets non permanents (objets transitoires et objets persistants), les copies des informations privées (fichiers ou descripteurs persistants) créées avant le changement d'autorisation ne sont pas invalidées.

OPTIONS

Les mots de passe doivent suivre les « normes de formatage des autorisations par mot de passe », voir la section « Formatage des autorisations ».

•
-c, --object-context=OBJET:

L'objet contexte de clé à utiliser pour l'opération.

•
-p, --object-auth=AUTH:

La valeur d'autorisation précédente pour l'objet TPM spécifié avec -c.

•
-C, --parent-context=OBJET:

L'objet parent. Ceci est requis si l'objet pour l'opération est un objet transitoire ou persistant.

•
-r, --private=FICHIER: Le fichier de sortie qui contient la nouvelle partie sensible de l'objet dont l'autorisation a été modifiée. # Détails de protection

Les objets qui peuvent sortir du TPM doivent être protégés (confidentialité et intégrité). Par exemple, les objets transitoires nécessitent que les données protégées par le TPM (clé ou matériel de scellage) soient stockées à l'extérieur du TPM. Ceci est visible dans des outils comme tpm2_create(1), où l'option -r génère ces données protégées. Ce blob contient les parties sensibles de l'objet. Les parties sensibles de l'objet sont protégées par l'objet parent, en utilisant les détails de chiffrement symétrique du parent pour chiffrer les données sensibles et y appliquer un HMAC.

Des détails approfondis peuvent être trouvés dans les sections 23 de :

•
https://trustedcomputinggroup.org/wp-content/uploads/TPM-Rev-2.0-Part-1-Architecture-01.38.pdf

Notamment la Figure 20, est pertinente, même si elle fait spécifiquement référence aux blobs de duplication, le processus est identique.

Si la sortie provient de tpm2_duplicate(1), la sortie sera légèrement différente, comme décrit entièrement dans la section 23.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash, à moins qu'un rphash ne soit également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est communément appelé rpHash.

•
-S, --session=FICHIER:

La session créée à l'aide de tpm2_startauthsession. Ceci peut être utilisé pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

•
ARGUMENT l'argument de ligne de commande spécifie la valeur AUTH à définir pour l'objet spécifié avec -c.

Références

Format de l'Objet Contexte

Le type d'un objet contexte, qu'il s'agisse d'un descripteur ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un *préfixe* sur l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie de plateforme
•
endorsement: la hiérarchie d'endossement
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un descripteur, par ex. 0x81010013 et utilisé directement.

Formatage des Autorisations

L'autorisation d'utilisation d'un objet dans TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

NOTE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes à l'aide d'identifiants de préfixe.

Note : Par défaut, les mots de passe sont considérés comme étant sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne de caractères, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe), n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi des mots de passe avec des caractères non imprimables et/ou non adaptés au terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », devrait être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser stdin. Stocker les mots de passe dans des fichiers évite les fuites d'informations, les mots de passe passés en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctions communes d'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier depuis un chemin
file:chemin/vers/fichier/motdepasse
# pour 'echo' un mot de passe via stdin :
echo foobar | tpm2_tool -p file:-
# pour utiliser une 'here-string' bash via stdin :
tpm2_tool -p file:- <<< foobar

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Optionnellement, si la session nécessite une valeur d'authentification à envoyer avec le descripteur de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification mypassword.

session:session.ctx+mypassword

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

-h, --help=[man|no-man] : Affiche le manuel de l'outil. Par défaut, il tente d'appeler le pager de manuel pour l'outil, mais en cas d'échec, il affiche un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, mais si “man” est explicitement demandé, l'outil affichera les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le pager de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser correctement la fonctionnalité de manuel, il faut que les manuels soient installés ou présents dans MANPATH. Voir man(1) pour plus de détails.

-v, --version : Affiche les informations de version pour cet outil, les tctis pris en charge et quitte.
-V, --verbose : Augmente les informations que l'outil affiche sur la console pendant son exécution. Lors de l'utilisation de cette option, le nom du fichier et le numéro de ligne sont affichés.
-Q, --quiet : Supprime la sortie normale de l'outil sur stdout.
-Z, --enable-errata : Active l'application de correctifs d'errata. Utile si un correctif d'errata doit être appliqué aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
-R, --autoflush : Active l'autoflush pour les objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. L'autoflush peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. informations que de nombreux utilisateurs peuvent attendre.

Configuration du TCTI

Le TCTI ou “Transmission Interface” est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec les TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge le non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils tenteront d'être utilisés sans connexion TCTI. Ne prend pas en charge TOUTES les options et DOIT être présenté comme le texte exact de “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <configuration-options-tcti> utilise la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'entendu par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

device : Pour le TCTI device, le fichier de périphérique TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et chaque valeur sont séparées par un caractère `=.
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifiez le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifiez le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les différents modules TCTI connus.

EXEMPLES

Définir les autorisations propriétaire, endorsement et lockout sur newpass

tpm2_changeauth -c owner newpass
tpm2_changeauth -c endorsement newpass
tpm2_changeauth -c lockout newpass

Changer les autorisations propriétaire, endorsement et lockout

tpm2_changeauth -c o -p newpass newerpass
tpm2_changeauth -c e -p newpass newerpass
tpm2_changeauth -c l -p newpass newerpass

Définir l'autorisation propriétaire sur un mot de passe vide

tpm2_changeauth -c o -p oldpass

Modifier l'autorisation pour un objet transitoire chargeable

tpm2_createprimary -Q -C o -c prim.ctx
tpm2_create -Q -g sha256 -G aes -u key.pub -r key.priv -C prim.ctx
tpm2_load -C prim.ctx -u key.pub -r key.priv -n key.name -c key.ctx
tpm2_changeauth -c key.ctx -C prim.ctx -r key.priv newkeyauth

Modifier l'autorisation pour un Index NV

Nécessite un support de session étendue.

tpm2_startauthsession -S session.ctx
tpm2_policycommandcode -S session.ctx -L policy.nvchange TPM2_CC_NV_ChangeAuth
tpm2_flushcontext session.ctx
NVIndex=0x1500015
tpm2_nvdefine   $NVIndex -C o -s 32 -a "authread|authwrite" -L policy.nvchange
tpm2_startauthsession \--policy-session -S session.ctx
tpm2_policycommandcode -S session.ctx -L policy.nvchange TPM2_CC_NV_ChangeAuth
tpm2_changeauth -p session:session.ctx -c $NVIndex newindexauth

Retourne

Les outils peuvent retourner l'un des codes suivants :

0 - Succès.
1 - Erreur générale non spécifique.
2 - Erreur de traitement des options.
3 - Erreur d'authentification.
4 - Erreur liée au TCTI.
5 - Schéma non supporté. Applicable à tpm2_testparams.

AIDE tpm2_changeauth(1) — tpm2-tools

NOM

tpm2_changeauth — Changer l’authentification du TPM.

SYNOPSIS

tpm2_changeauth [--tcti=<tcti-name>] [--tcti-device=<device>] [--tcti-socket=<host:port>] [--tcti-log=<logfile>] [--tcti-cmdsize=<size>] [--tcti-recvsize=<size>] [--tcti-max-tpm-response-size=<size>] [--tcti-max-response-size=<size>] [--tcti-connection-type=<type>] [--tcti-interface-type=<type>] [--tcti-cfg=<param1=value1:param2=value2>] -Q [--quiet] -V [--verbose] -H [--help] -C <tpm-context> -p <parent-ctx> -u <new-auth> -o <new-parent-ctx> -q <owner-auth>

DESCRIPTION

tpm2_changeauth est un utilitaire du tpm2-tools qui permet de changer l'authentification d'un objet TPM.

Il peut changer l'authentification de l'Owner (propriétaire) du TPM. Si l'option -u est spécifiée, il peut changer l'authentification du Parent (parent) d'un objet.

OPTIONS

Un résumé des options est inclus ci-dessous.

-Q, --quiet
Supprime les messages de sortie.
-V, --verbose
Affiche des informations détaillées sur le processus.
-H, --help
Affiche l'aide et quitte.
-C, --tpm-context <tpm-context>
Le handle du TPM.
-p, --parent-ctx <parent-ctx>
Le handle du parent de l'objet dont l'authentification doit être changée.
-u, --new-auth <new-auth>
La nouvelle authentification pour l'objet.
-o, --new-parent-ctx <new-parent-ctx>
Le handle du nouveau parent de l'objet.
-q, --owner-auth <owner-auth>
L'authentification du propriétaire du TPM.

Context Object Format

Le format d'objet de contexte est un octet suivi par un ou plusieurs identifiants.

Le premier octet indique le type de l'objet de contexte:

  • 0x01: Handle d'un objet persistant (Persistent Object Handle).
  • 0x02: Handle d'une clé de stockage (Primary Storage Key Handle).
  • 0x03: Handle d'une clé d'attestation (Attestation Key Handle).
  • 0x04: Handle d'une clé de scellage (Seal Key Handle).

Les identifiants sont généralement des nombres hexadécimaux.

Authorization Formatting

L'authentification est généralement fournie sous forme de chaîne de caractères. Si la chaîne contient des caractères spéciaux ou des espaces, elle doit être mise entre guillemets.

COMMON OPTIONS

Les options communes aux autres commandes tpm2-tools sont également disponibles.

TCTI Configuration

Le TCTI (Tab Character Transmission Interface) est utilisé pour communiquer avec le TPM. Il peut être configuré via des options de ligne de commande.

TCTI OPTIONS

--tcti=<tcti-name>
Spécifie le nom du TCTI à utiliser (par exemple, device, socket, mssim).
--tcti-device=<device>
Spécifie le périphérique du TCTI (par exemple, /dev/tpm0).
--tcti-socket=<host:port>
Spécifie l'hôte et le port du TCTI socket.
--tcti-log=<logfile>
Enregistre les communications TCTI dans un fichier journal.
--tcti-cmdsize=<size>
Spécifie la taille maximale des commandes TCTI.
--tcti-recvsize=<size>
Spécifie la taille maximale des données reçues par le TCTI.
--tcti-max-tpm-response-size=<size>
Spécifie la taille maximale de réponse du TPM.
--tcti-max-response-size=<size>
Spécifie la taille maximale de réponse du TCTI.
--tcti-connection-type=<type>
Spécifie le type de connexion pour certains TCTI.
--tcti-interface-type=<type>
Spécifie le type d'interface pour certains TCTI.
--tcti-cfg=<param1=value1:param2=value2>
Permet de configurer des paramètres spécifiques au TCTI.

EXAMPLES

Changer l'authentification de l'Owner du TPM:

$ tpm2_changeauth -q --owner-auth=old_owner_auth new_owner_auth

Changer l'authentification d'un objet parent:

$ tpm2_changeauth -p 0x81000001 -u new_parent_auth -o 0x81000002

Returns

Retourne 0 si l'opération réussit, une valeur non nulle en cas d'échec.
