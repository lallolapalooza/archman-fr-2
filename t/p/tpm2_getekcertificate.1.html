tpm2_getekcertificate(1) Manuel des commandes générales tpm2_getekcertificate(1)

NOM

tpm2_getekcertificate(1) - Récupère le certificat de la clé de cautionnement.

SYNTAXE

tpm2_getekcertificate [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_getekcertificate(1) - Récupère le certificat de la clé de cautionnement. Le certificat est présent soit dans les index NV spécifiés par le TCG, soit sur le serveur d'hébergement du certificat de clé de cautionnement du fabricant du TPM. Voici les conditions qui dictent la recherche du certificat.

1.
Index NV :

Emplacement de recherche par défaut lorsque ARGUMENT n'est pas spécifié.

2.
Serveur de certificat Intel-EK :

Emplacement de recherche lorsque le certificat EK n'a pas pu être trouvé dans l'index NV ET que le bit tpmEPSgenerated est EFFACÉ ET que le fabricant est INTC.

3.
Serveur de recertification Intel-EK :

Emplacement de recherche lorsque le certificat EK n'a pas pu être trouvé dans l'index NV ET que le bit tpmEPSgenerated est DÉFINI ET que le fabricant est INTC.

Remarque :

Dans cette opération, des informations sont fournies concernant les logiciels supplémentaires à exécuter dans le cadre du service de réapprovisionnement/recertification.

Une fois le processus de réapprovisionnement/recertification terminé, les certificats EK peuvent être lus à partir des index NV en exécutant une autre instance de tpm2_getekcertificate.

4.
Serveur générique ou autre serveur de certificat EK :

Emplacement de recherche lorsque ARGUMENT spécifie l'adresse d'hébergement web du certificat EK.

OPTIONS

•
-o, --ek-certificate=FICHIER ou STDOUT :

Le fichier dans lequel enregistrer le certificat de la clé de cautionnement. Lorsque des certificats EK sont trouvés dans les indices NV du TPM, cette option peut être spécifiée plusieurs fois pour enregistrer les certificats EK RSA et ECC dans l'ordre. L'outil avertira si des certificats EK supplémentaires sont trouvés dans les indices NV du TPM et si un seul fichier de sortie est spécifié. Si l'option n'est pas spécifiée, tous les certificats EK récupérés, que ce soit depuis l'hébergement web du fabricant ou depuis les indices NV du TPM, sont envoyés sur la sortie standard.

•
-X, --allow-unverified :

Spécifie de tenter de se connecter au serveur de provisionnement du fabricant du TPM sans vérifier le certificat du serveur. Cette option est sans pertinence lorsque les certificats EK sont trouvés dans les indices NV du TPM.

AVERTISSEMENT : Cette option ne doit être utilisée que sur des plateformes avec d'anciens certificats CA.

•
-u, --ek-public=FICHIER :

Spécifie le chemin du fichier pour la partie publique de la clé de cautionnement au format tss.

•
-x, --offline :

Cette option active le mode hors ligne de l'outil. Ainsi, les certificats peuvent être récupérés pour des clés publiques EK fournies qui n'appartiennent pas à la plateforme sur laquelle l'outil est exécuté. Utile dans le provisionnement d'usine de plusieurs plateformes qui ne sont pas connectées individuellement à Internet. Dans un tel scénario, un seul serveur de provisionnement connecté à Internet peut utiliser cet outil en mode hors ligne. Cela force l'outil à ne pas rechercher les certificats EK dans les indices NV.

•
--raw :

Cette option force l'outil à afficher le certificat EK tel qu'il est reçu de la source : NV/hébergement web.

•
-E, --encoding=ENCODAGE :

Spécifie explicitement le format d'encodage à utiliser. Normalement, la méthode par défaut est celle utilisée par Intel, sauf si un fTPM AMD est détecté, auquel cas l'encodage spécifique AMD est utilisé. Utilisez `a' pour AMD et `i' pour Intel.

•
ARGUMENT l'argument de ligne de commande spécifie l'adresse URL du portail de certificat EK. Cela force l'outil à ne pas rechercher les certificats EK dans les indices NV.

Références

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man] : Affiche le manuel de l'outil. Par défaut, il tente d'appeler le pagineur de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. Le comportement est le même si l'argument d'option « man » est spécifié, cependant si « man » est explicitement demandé, l'outil fournira les erreurs de man sur stderr. •
-v, --version : Affiche les informations de version pour cet outil, les tctis pris en charge et quitte.
•
-V, --verbose : Augmente les informations que l'outil affiche sur la console pendant son exécution. Lorsque cette option est utilisée, le fichier et le numéro de ligne sont affichés.
•
-Q, --quiet : Supprime la sortie normale de l'outil sur la sortie standard.
•
-Z, --enable-errata : Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.
•
-R, --autoflush : Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Configuration TCTI

Le TCTI, ou « Interface de transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Remarque : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lorsqu'ils seront tentés d'être utilisés sans connexion TCTI. Ne supporte *AUCUNE* option et *DOIT* être présenté comme le texte exact « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

La spécification d'une chaîne vide pour <nom-tcti> ou <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs **DANS CET ORDRE**.

tpm2_getekcertificate(1) — tpm2-tools

NAME

tpm2_getekcertificate - Retrieve the EK certificate from the TPM manufacturer backend or TPM NV.

SYNOPSIS

tpm2_getekcertificate [-h|--help] [-V|--version] [-v|--verbose] [-T|--tcti tcti-name] [-c|--ctx context-file] [-f|--format format] [-p|--pem] [-o|--output output-file] [-X|--external-cert] [-x|--x509-structure] [-u|--ek-public public-ek-file] [certificate-source ...]

DESCRIPTION

The tpm2_getekcertificate utility is used to retrieve the Endorsement Key (EK) certificate. The EK is a unique primary key generated by the TPM manufacturer. An EK certificate is a certificate signed by the manufacturer that attests to the EK's origin.

The tool supports multiple sources for the EK certificate:

TPM NV indices: The tool can read the EK certificate stored in specific NV indices of the TPM. This is the primary mechanism for certified platforms.
Manufacturer backend: The tool can fetch the EK certificate from a manufacturer-specific backend server over the network. This is useful when the certificate is not stored on the TPM or is outdated.

The tool attempts to retrieve the certificate in the following order:

  1. Checks the NV indices specified on the command line or the default NV indices.
  2. If not found or if explicitly requested via the -X option, it queries the manufacturer backend. This requires the public part of the EK to be provided via the -u option and a valid URL for the backend server.

OPTIONS

A list of options are available:

-h, --help
Prints the help messages.
-V, --version
Prints the version string of the tool.
-v, --verbose
Enables verbosity, including additional debugging information.
-T, --tcti tcti-name
Specifies the Tagged Command Transmission Interface (TCTI). The TCTI is responsible for the communication between the tpm2-tools and the TPM device. If not specified, the tool will use the default TCTI. The default TCTI can be queried using the -v option. See also TCTI Configuration.
-c, --ctx context-file
The TPM context file containing the loaded objects. For example, the context for the primary key or other objects used in the TPM operations.
-f, --format format
Specify the output certificate format. The supported formats are: "raw" (binary DER), "pem" (Base64 encoded DER with PEM headers).
-p, --pem
Output the certificate in PEM format. This is a shorthand for --format pem.
-o, --output output-file
Specifies the output file to save the retrieved certificate. If not specified, the certificate will be printed to standard output.
-X, --external-cert
Fetch the EK certificate from the manufacturer backend instead of the TPM NV indices. This option requires the public part of the EK to be provided via the -u option.
-x, --x509-structure
When fetching from the manufacturer backend, this option requests the full X509 certificate structure. Without this option, only the signed EK certificate is retrieved.
-u, --ek-public public-ek-file
Specifies the file containing the public part of the Endorsement Key (EK). This is required when fetching the certificate from the manufacturer backend using the -X option.
certificate-source
An optional list of URLs or file paths pointing to potential EK certificate sources. If not provided, the tool will use default locations or NV indices.

COMMON OPTIONS

These options are common to most of the tpm2-tools.

-c, --context file
Load TPM context data from file.
-e, --ephemeral
Use ephemeral context.
-f, --force
Allow operations that might overwrite existing data.
-n, --nocheck
Skip primary key checks.
-p, --password password
Password for authorization.
-P, --parent-password password
Password for the parent key authorization.
-S, --session file
The session file containing the session data.
-t, --timeout seconds
Timeout for TPM operations in seconds.
-T, --tcti name
Tagging command transmission interface (TCTI) string.
-v, --verbose
Enable verbose output.

TCTI Configuration

The tpm2-tools can be configured to use different Tagged Command Transmission Interfaces (TCTIs) to communicate with the TPM. The TCTI is specified using the -T option or the TPM2TOOLS_TCTI environment variable. The tool will try to load TCTIs in the following order:

  1. From the -T command line option.
  2. From the TPM2TOOLS_TCTI environment variable.
  3. The default TCTI configured at build time.
  4. The hardcoded default TCTI (`tabrmd`).

If multiple TCTIs are specified in the TPM2TOOLS_TCTI environment variable, separated by colons (':'), the tool will attempt to load the first one successfully. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

NOTES

When the verbose option is specified, additional curl debugging information is provided by setting the curl mode verbose, see https://curl.haxx.se/libcurl/c/CURLOPT_VERBOSE.html for more information.

EXAMPLES

Retrieve EK certificate from TPM manufacturer backend by supplying EK public.

tpm2_createek -G rsa -u ek.pub -c key.ctx
tpm2_getekcertificate -X -o ECcert.bin -u ek.pub \
https://tpm.manufacturer.com/ekcertserver/

Retrieve EK certificate from Intel backend if certificate not found on NV.

tpm2_createek -G rsa -u ek.pub -c key.ctx
tpm2_getekcertificate -X -o ECcert.bin -u ek.pub

Retrieve EK certificate from Intel backend for an offline platform.

tpm2_getekcertificate -X -x -o ECcert.bin -u ek.pub

Retrieve EK certificate from TPM NV indices only, fail otherwise.

tpm2_getekcertificate -o ECcert.bin

Retrieve multiple EK certificates from TPM NV indices only, fail otherwise.

tpm2_getekcertificate -o RSA_EK_cert.bin -o ECC_EK_cert.bin

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
