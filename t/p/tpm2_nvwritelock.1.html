NOM

tpm2_nvwritelock(1) - Verrouille l'index Non-Volatile (NV) contre les écritures futures.

SYNOPIS

tpm2_nvwritelock [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_nvwritelock(1) - Verrouille l'index Non-Volatile (NV) contre les écritures futures. Le verrouillage de l'index NV est levé lors du redémarrage du TPM et l'index NV redevient inscriptible. L'index peut être spécifié comme un handle brut ou une valeur de décalage de la plage de handles nv « TPM2_HR_NV_INDEX ».

OPTIONS

•
-C, --hierarchy=OBJET:

Spécifie la hiérarchie utilisée pour l'autorisation. Les options supportées sont :

•
o pour TPM_RH_OWNER
•
p pour TPM_RH_PLATFORM
•
<num> où un handle de hiérarchie ou un index nv peut être utilisé.

Lorsque -C n'est pas explicitement passé, le handle de l'index sera utilisé pour autoriser contre l'index. La valeur d'authentification de l'index est définie via l'option -p de tpm2_nvdefine(1).

•
-P, --auth=AUTH:

Spécifie la valeur d'autorisation pour la hiérarchie.

•
--global:

Verrouille tous les index NV avec l'attribut TPMA_NV_GLOBALLOCK. Cette option ne nécessite pas d'index NV ni d'argument de décalage.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. C'est ce qu'on appelle couramment le cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécute pas réellement la commande, il renvoie simplement un cpHash sauf si rphash est également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. C'est ce qu'on appelle couramment le rpHash.

•
-S, --session=FICHIER:

La session créée avec tpm2_startauthsession. Elle peut être utilisée pour spécifier une session auxiliaire pour l'audit et/ou le chiffrement/déchiffrement des paramètres.

•
-n, --name=FICHIER:

Le nom de l'index NV qui doit être fourni lorsque seul le cpHash est calculé sans envoyer réellement la commande au TPM.

•
ARGUMENT l'argument de la ligne de commande spécifie le numéro de l'index NV ou le décalage.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un début de chaîne pour l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie de la plateforme
•
endorsement: la hiérarchie d'endossement
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.

Format de l'autorisation

L'autorisation pour l'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : « Les autorisations utilisent par défaut le MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées ».

Mots de passe

Les mots de passe sont interprétés dans les formes suivantes en utilisant des identifiants de préfixe.

Note : Par défaut, les mots de passe sont supposés être sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne de caractères

Un mot de passe sous forme de chaîne, spécifié par le préfixe « str: » ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'autorisation.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe « hex: », est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou peu conviviaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe « file: », doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un « - » pour utiliser l'entrée standard. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations ; les mots de passe passés en option peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser l'entrée standard et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour envoyer un mot de passe via l'entrée standard:
echo motdepasse | tpm2_tool -p file:-
# pour utiliser une chaîne ici bash via l'entrée standard:
tpm2_tool -p file:- <<< motdepasse

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session nommé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session nommé session.ctx ET envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session nommé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Autorisations de PCR

Vous pouvez satisfaire une politique PCR en utilisant le préfixe « pcr: » et le mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section « Spécificateurs de banque PCR ».

Le fichier-pcr-brut est un argument optionnel qui contient la sortie des contenus PCR bruts tels que renvoyés par tpm2_pcrread(1).

NOM

tpm2_nvwritelock - écrire sur les emplacements NV Index

SYNOPSIS

tpm2_nvwritelock [OPTIONS] <nvindex>

DESCRIPTION

tpm2_nvwritelock écrit sur l'index NV spécifié. Pour cela, un mot de passe d'autorisation est requis.

L'utilisation de cette commande avec l'option --auth est déconseillée. Utilisez plutôt l'une des options de gestion des contextes ou des mots de passe suivants :

•
-c | --context <context file>
•
-P | --auth <password>
•
-L | --policy <policy file>
•
-U | --parent-auth <password>
•
-S | --parent-context <context file>

Pour plus d'informations, voir la section AUTHORIZATION.

L'objet du contexte nvindex est obtenu soit via l'argument de ligne de commande, soit via l'argument de contexte.

OPTIONS

Chacune des options suivantes peut être utilisée pour configurer la commande.

-C, --context <key file>
Le contexte de l'objet pour le fichier de clé. Ceci est un objet de contexte qui doit être charge dans le TPM. Ceci est géré par la fonction _tpm2_handle_context.
-H, --parent-context <context file>
Le contexte de l'objet parent. Ceci est un objet de contexte qui doit être charge dans le TPM.
-P, --auth <password>
La valeur du mot de passe pour l'autorisation de l'objet de contexte. Les mots de passe sont souvent des nombres hexadécimaux.
-L, --policy <policy file>
Le fichier de politique qui est utilisé pour autoriser la commande.
-U, --parent-auth <password>
La valeur du mot de passe pour l'autorisation de l'objet de contexte parent. Les mots de passe sont souvent des nombres hexadécimaux.
--global
Verrouille l'accès global du NV. Cela est possible seulement si l'attribut TPMA_NV_GLOBAL_LOCK est défini lors de la définition du NV Index.
-t, --ticket <ticket file>
Le fichier contenant le ticket de politique et l'attestation de la valeur du nonce (qui sont requis lors de l'utilisation d'une politique).

Context Object Format

Le format des fichiers de contexte est une séquence de lignes de l'une des formes suivantes:

type:handle
value

Le type est soit NV, soit OBJECT. La valeur est la valeur de l'attribut de l'objet, tel que le mot de passe.

Le format peut aussi être utilisé pour stocker des valeurs de politique :

type:handle
policy:value
nonce:value
ticket:value
digest:value

Le type policy est utilisé pour stocker une politique en mémoire. Le type digest est utilisé pour stocker le résumé de la politique qui est requise pour les commandes.

L'option tpm2_handle_context(1) est utilisée pour obtenir des informations sur la façon dont les fichiers de contexte sont gérés.

Authorization Formatting

L'authentification est requise pour la plupart des commandes. Elle peut être fournie via l'un des mécanismes suivants :

•
Le mot de passe de l'objet, fourni via l'option -P ou --auth.
•
Une politique, fournie via l'option -L ou --policy, et les informations de politique, fournies via l'option -t ou --ticket.
•
L'authentification de l'objet parent, fournie via l'option -U ou --parent-auth. Applicable quand l'objet est un descendant d'un autre objet.

Les mots de passe et les données de politique sont souvent représentés sous forme hexadécimale. Par exemple, le mot de passe d'administrateur par défaut est souvent 0x00000000.

Certaines commandes, comme tpm2_nvdefine(1), créent des objets NV. Ces objets ont des autorisations qui spécifient quel type d'accès est permis. Les autorisations sont des chaînes de caractères qui spécifient les types d'accès, séparées par des barres verticales (|). Les autorisations courantes sont :

•
ownerread: L'administrateur peut lire l'index NV.
•
ownerwrite: L'administrateur peut écrire sur l'index NV.
•
ownerclear: L'administrateur peut effacer l'index NV.
•
read: N'importe qui peut lire l'index NV.
•
write: N'importe qui peut écrire sur l'index NV.
•
writedefine: Permet de modifier les autorisations de l'index NV lors de sa définition.
•
writeall: Permet d'écrire sur l'index NV.
•
policyread: L'accès à l'index NV est autorisé via une politique.
•
policywrite: L'écriture sur l'index NV est autorisée via une politique.
•
policyall: Accès à l'index NV via une politique.
•
policycommandcode: L'accès à l'index NV est autorisé via une politique de code de commande.
•
portability: L'index NV est portable.
•
tightlybound: L'index NV est strictement lié.
•
userwrite: L'utilisateur peut écrire sur l'index NV.
•
userread: L'utilisateur peut lire l'index NV.
•
ownerchangeauth: L'administrateur peut changer le mot de passe de l'index NV.
•
no_da: L'index NV n'a pas de démon d'accès (DA).
•
permission: Le bit d'autorisation est utilisé pour définir le bit de permission.
•
ph: L'index NV est protégé par une politique de hachage.
•
pcc: L'index NV est protégé par une politique de code de commande.
•
pm: L'index NV est protégé par une politique de pcr.
•
pl: L'index NV est protégé par une politique de liste de commandes.
•
ps: L'index NV est protégé par une politique de chaîne.
•
pi: L'index NV est protégé par une politique d'entrée.
•
pc: L'index NV est protégé par une politique de pcr.
•
pcr: Ce champ est utilisé pour spécifier une politique de pcr qui est composé des registres de PCR suivants.
pcr:sha256:0,1,2,3

en spécifiant AUTH.

-Z, --enable-errata : Active l'application des correctifs d'errata. Utile si un correctif d'errata doit être appliqué aux commandes envoyées au TPM. La définition de la variable d'environnement TPM2TOOLS_ENABLE_ERRATA est équivalente.

Configuration TCTI

Le TCTI ou « Transmission Interface » est le mécanisme de communication avec le TPM. Les TCTI peuvent être modifiés pour la communication avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTI connus actuels sont :

tabrmd : Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
mssim : Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
device : Utilisé lors de la communication directe avec le fichier de périphérique TPM.
none : Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Les outils qui ne le supportent pas généreront une erreur lors de leur tentative d'utilisation sans connexion TCTI. Ne supporte AUCUNE option et DOIT ÊTRE présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTI tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTI susmentionnés est le défaut.

TCTIs personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute du nom-tcti est utilisée pour la recherche. Ainsi, il peut s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'interprété par la sémantique de dlopen(3).

OPTIONS TCTI

Cet ensemble d'options est utilisé pour configurer les divers modules TCTI connus disponibles :

device : Pour le TCTI device, le fichier de périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI= « device:/dev/tpm0 »

mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI= « mssim:host=localhost,port=2321 »

abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque chaîne clé et valeur est séparée par un caractère `= `.
TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limitée à `session' et `system'.

Spécifier le nom tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

EXEMPLES

Verrouiller un index

tpm2_nvdefine -C o -s 32 \
  -a "ownerread|policywrite|ownerwrite|writedefine" 1
echo "foobar" > nv.writelock
tpm2_nvwrite -C o -i nv.writelock 1
tpm2_nvwritelock -C o 1
# échoue avec "NV access locked"
tpm2_nvwrite -C o -i nv.writelock 1

Verrouillage global

tpm2_nvdefine -C o -s 32 \
  -a "ownerread|policywrite|ownerwrite|globallock" 1
tpm2_nvwritelock -C o --global
# cette commande échoue avec "NV access locked".
echo foo | tpm2_nvwrite -C o -i- 1

Retours

Les outils peuvent retourner l'un des codes suivants :

0 : Succès.
1 : Erreur générale non spécifique.
2 : Erreur de traitement des options.
3 : Erreur d'authentification.
4 : Erreur liée au TCTI.
5 : Schéma non supporté. Applicable à tpm2_testparams.

Synopsis

writelock [-h|--help] [-v|--version] [-a|--all] [-f|--force] [--no-sync] [-s|--unlock] [PATH...]

Description

The writelock command is a utility that allows you to manage write locks on files and directories. Write locks are a mechanism to prevent accidental modification or deletion of important files.

Options

  • -h, --help: Display a help message and exit.
  • -v, --version: Display version information and exit.
  • -a, --all: Apply the operation to all files and directories in the current directory.
  • -f, --force: Force the operation, even if the file is already locked or unlocked.
  • --no-sync: Do not synchronize changes to disk immediately.
  • -s, --unlock: Remove the write lock from the specified files or directories.
  • PATH...: One or more paths to files or directories.

Examples

Lock a file: 

writelock my_important_file.txt

Unlock a file: 

writelock -s my_important_file.txt

Lock all files in the current directory: 

writelock -a

Unlock all files in the current directory: 

writelock -as

Synopsis

writelock [-h|--help] [-v|--version] [-a|--all] [-f|--force] [--no-sync] [-s|--unlock] [CHEMIN...]

Description

La commande writelock est un utilitaire qui permet de gérer les verrous d'écriture sur les fichiers et les répertoires. Les verrous d'écriture sont un mécanisme pour empêcher la modification ou la suppression accidentelle de fichiers importants.

Options

  • -h, --help : Affiche un message d'aide et quitte.
  • -v, --version : Affiche les informations de version et quitte.
  • -a, --all : Applique l'opération à tous les fichiers et répertoires du répertoire courant.
  • -f, --force : Force l'opération, même si le fichier est déjà verrouillé ou déverrouillé.
  • --no-sync : Ne synchronise pas immédiatement les modifications sur le disque.
  • -s, --unlock : Supprime le verrou d'écriture des fichiers ou répertoires spécifiés.
  • CHEMIN... : Un ou plusieurs chemins vers des fichiers ou des répertoires.

Exemples

Verrouiller un fichier : 

writelock mon_fichier_important.txt

Déverrouiller un fichier : 

writelock -s mon_fichier_important.txt

Verrouiller tous les fichiers dans le répertoire courant : 

writelock -a

Déverrouiller tous les fichiers dans le répertoire courant : 

writelock -as
