NOM

tpm2_getrandom(1) - Récupère des octets aléatoires du TPM.

SYNOPIS

tpm2_getrandom [OPTIONS] [ARGUMENT]

DESCRIPTION

tpm2_getrandom(1) - Renvoie les TAILLE octets suivants provenant du générateur de nombres aléatoires. Le paramètre TAILLE est attendu comme seul argument de l'outil.

Notez que la spécification TPM recommande que les TPM fixent le nombre d'entrées disponibles à la taille maximale de la sortie d'un algorithme de hachage en octets.

La plupart des TPM le font, et donc l'outil vérifie que la taille d'entrée est limitée par la propriété TPM2_PT_MAX_DIGEST et émet une erreur si elle est trop grande.

La sortie est par défaut sur stdout et au format binaire, sauf indication contraire avec les options -o et –hex respectivement.

OPTIONS

•
-o, --output=FICHIER

Spécifie le nom du fichier de sortie pour les octets bruts. Par défaut, la sortie est sur stdout sous forme de chaîne hexadécimale.

•
--hex

Convertit les données de sortie au format hexadécimal sans le préfixe « 0x ».

•
-f, --force

Ignore la vérification que :

•
La taille demandée est dans la limite de taille de hachage du TPM.
•
Le nombre d'octets aléatoires récupérés correspond à la quantité demandée.
•
-S, --session=FICHIER:

La session créée avec tpm2_startauthsession. Plusieurs de celles-ci peuvent être spécifiées. Par exemple, vous pouvez avoir une session pour l'audit et une autre pour le chiffrement des paramètres.

•
--cphash=FICHIER:

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est couramment appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, en l'absence de l'option rphash, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash.

•
--rphash=FICHIER:

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est couramment appelé rpHash.

•
ARGUMENT l'argument de ligne de commande spécifie la taille de la sortie.

Configuration TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPM via différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Remarque : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Typiquement utilisé pour communiquer avec le simulateur logiciel de TPM.
•
device - Utilisé lors de la communication directe avec un fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors TPM et supportent donc de ne pas utiliser de TCTI. Ceux qui ne le supportent pas généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne supporte AUCUNE option et DOIT être présenté sous la forme exacte « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <config-option-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, il pourrait s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier du périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le numéro de port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le abr

tpm2_getrandom(1) — tpm2-tools

NAME

tpm2_getrandom

get random bytes from the TPM

SYNOPSIS

tpm2_getrandom [OPTIONS] [size]

DESCRIPTION

The tpm2_getrandom command is used to retrieve random bytes generated by the TPM. The number of bytes to retrieve is specified by the size argument.

OPTIONS

These are the options available for the tpm2_getrandom command:

size
The number of random bytes to retrieve. This is an optional argument. If not specified, the command will attempt to retrieve 32 bytes of random data.

COMMON OPTIONS

In addition to the options above, the following options are available on most tpm2-* tools:

-C, --context <ctx>
The TPM context to use. This can be a TPM Handle, a file path containing a TPM context, or a string representing a TPM context.
-T, --tcti <tcti-name>
The Tabernacle Connection and Transport Interface (TCTI) to use. This specifies how the tool communicates with the TPM. If not specified, the default TCTI is used.
-I, --device <device>
The path to the TPM device (e.g., /dev/tpm0).
-P, --password <password>
The password to use for operations that require authorization.
-u, --unix-path <path>
The path to the TPM character device for socket TCTI.
-S, --socket <host:port>
The host and port to connect to for socket TCTI.
-n, --name <name>
The name of the TPM device for the given TCTI.
-e, --entity <entity>
The entity to use for authorization.
-p, --parent-auth <parent-auth>
The authorization value for the parent key.
-c, --child-auth <child-auth>
The authorization value for the child key.
-f, --force
Force the operation, even if it might be unsafe.
-d, --debug
Enable debug output.
-v, --version
Print version information and exit.
-h, --help
Print help information and exit.

TCTI Configuration

The configuration string format is a series of simple key value pairs separated by a `,​' character. Each key and value string are separated by a `=​' character.

•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

TCTI OPTIONS

The following options are used to configure the TCTI:

-T, --tcti <tcti-name>
The TCTI to use. This can be one of the following:
device
Use the device TCTI to communicate with the TPM device directly.
socket
Use the socket TCTI to communicate with a remote TPM via a socket.
abrmd
Use the abrmd TCTI to communicate with the TPM Resource Manager daemon.
mssim
Use the mssim TCTI to communicate with the Microsoft Simulator.
nul
Use the nul TCTI, which does nothing.

The TCTI can also be specified with a configuration string. For example, to use the abrmd TCTI with the session bus, you would use --tcti=abrmd:bus_type=session.

EXAMPLES

Generate a random 20 bytes and output the binary data to a file

tpm2_getrandom -o random.out 20

Generate a random 8 bytes and output the hex formatted data to stdout

tpm2_getrandom 8

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
