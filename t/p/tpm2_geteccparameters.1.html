NOM

tpm2_geteccparameters(1) - Récupère les paramètres d'une courbe ECC identifiée par son curveID assigné par TCG.

SYNTAXE

tpm2_geteccparameters [OPTIONS]

DESCRIPTION

tpm2_geteccparameters(1) - Récupère les paramètres d'une courbe ECC identifiée par son curveID assigné par TCG.

OPTIONS

•
ARGUMENT=ALGORITHME:

Spécifiez la courbe ECC. Exemple: ecc521.

•
-o, --output=FICHIER

Spécifiez le chemin du fichier pour enregistrer les paramètres ECC.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hash des paramètres de la commande. Ceci est communément appelé cpHash. NOTE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash.

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour la création par le TPM, ont de nombreux algorithmes à renseigner dans les données publiques. Des choses comme le type, le schéma et les détails asymétriques, la taille de la clé, etc. Voici le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de type

Cette partie du spécificateur d'algorithme complexe est requise. Les schémas restants et les détails symétriques seront par défaut en fonction du type spécifié et du type de l'objet en cours de création.

•
aes - AES par défaut : aes128
•
aes128<mode> - AES 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
aes192<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 192 bits.
•
aes256<mode> - Identique à aes128<mode>, sauf pour une taille de clé de 256 bits.
•
sm4 - SM4 par défaut : sm4128
•
sm4128 ou sm4_128 <mode> - SM4 128 bits avec mode optionnel (ctr|ofb|cbc|cfb|ecb). Si le mode n'est pas spécifié, la valeur par défaut est null.
•
ecc - Courbe elliptique, par défaut ecc256.
•
ecc192 ou ecc_nist_p192 - Courbe NIST ECC 192 bits
•
ecc224 ou ecc_nist_p224 - Courbe NIST ECC 224 bits
•
ecc256 ou ecc_nist_p256 - Courbe NIST ECC 256 bits
•
ecc384 ou ecc_nist_p384 - Courbe NIST ECC 384 bits
•
ecc521 ou ecc_nist_p521 - Courbe NIST ECC 521 bits
•
ecc_sm2 ou ecc_sm2_p256 - Courbe SM2 256 bits
•
rsa - RSA par défaut : rsa2048
•
rsa1024 - RSA avec une taille de clé de 1024 bits.
•
rsa2048 - RSA avec une taille de clé de 2048 bits.
•
rsa3072 - RSA avec une taille de clé de 3072 bits.
•
rsa4096 - RSA avec une taille de clé de 4096 bits.

Spécificateurs de schéma

Ensuite, un champ optionnel, il peut être sauté.

Les schémas sont généralement des Schémas de signature ou des Schémas de chiffrement asymétrique. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est manquant, la valeur par défaut est sha256. Certains ne prennent aucun argument, et d'autres prennent plusieurs arguments.

NAME

tpm2_create — create a primary or other key object

SYNOPSIS

tpm2_create [-C context] [-G alg=key-alg[:key-bits]] [-g alg=hash-alg] [-u public.out] [-r private.out] [-p policy.hex] [-f] [-a authpolicy.hex] [-l parent-policy.hex] [-i input.bin] [-o output.bin] [-P password]

DESCRIPTION

tpm2_create is used to create a primary key object or other key objects. The key type, size, and associated algorithm specifiers are defined in the Algorithm Specifiers section.

The created key is stored in two files, one for the public key component and one for the private key component. The public key file is saved to the file specified by the -u option and the private key file is saved to the file specified by the -r option.

When creating a primary key, the parent context -C is typically the primary TPM context (e.g. TPM 1.2 PKHA or TPM 2.0 PEM0).

When creating an object that is not a primary key, the parent context -C should be an existing key or loaded context that the new key will be associated with.

The key algorithms can be specified via the -G option. The hash algorithm is specified via the -g option. If no algorithm is specified, the tool will default to using rsa2048. The default hash algorithm is sha256.

The created object has a created policy digest. This policy digest can be generated from a policy session or by specifying a policy digest in hex format using the -a option.

A created object can have a policy session attached to it. This policy session digest is calculated from a policy session or by specifying a policy digest in hex format using the -l option. This option is applicable for objects other than primary keys.

The -f option allows the creation of an object with the fixedTPM attribute set. This attribute makes the object immutable after creation.

The -i and -o options are used to specify input data and output data respectively. This is useful for symmetric encryption algorithms like aes, where the key is created and then the input data is encrypted.

The -P option allows you to specify the password for the primary key object. This can be a hex string or a password.

OPTIONS

-C context
The parent object context. This can be a TPM context handle, or a file containing a TPM context handle.
-G alg=key-alg[:key-bits]
The algorithm to use for the key. This can be specified as a key algorithm name, and optionally with the key size. The supported key algorithms are:
  • rsa[:key-bits]
  • rsa2048
  • rsa3072
  • rsa4096
  • ecc[:curve]
  • ecc256
  • ecc384
  • ecc521
The supported curves for ecc are:
  • nistp192
  • nistp224
  • nistp256
  • nistp384
  • nistp521
  • secp192k1
  • secp224k1
  • secp256k1
  • wz-sha256
  • wz-sha384
  • wz-sha512
The default key size for rsa is 2048 bits. The default curve for ecc is nistp256. For asymmetric encryption schemes, the key type specifier is key-alg[:key-bits[:scheme]]. The scheme is a string containing the asymmetric encryption algorithm and mode, e.g. rsaes, rsaes-oaep, rsaes-pss, ecdaa. For signing schemes, the key type specifier is key-alg[:key-bits[:scheme[:hash-alg]]]. The scheme is a string containing the signing algorithm and mode, e.g. ecdsa, ecdnepg, ecdaa. The hash algorithm is specified as described in the -g option. The default signing scheme is ecdsa and the default hash algorithm is sha256.
-g alg=hash-alg
The hash algorithm to use for the key. This option is applicable for signing algorithms or when generating keys for symmetric encryption. The supported hash algorithms are:
  • sha1
  • sha256
  • sha384
  • sha512
  • sha3_256
  • sha3_384
  • sha3_512
  • shake128
  • shake256
The default hash algorithm is sha256.
-u public.out
The file to save the public key data to. This is a required parameter.
-r private.out
The file to save the private key data to. This is a required parameter.
-p policy.hex
The policy digest of the created object. This option is used when creating an object with a policy digest, and the policy digest is provided in hex format.
-f
Sets the fixedTPM attribute for the created object. This makes the object immutable after creation.
-a authpolicy.hex
The authorization policy for the created object. This option is used when creating an object with an authorization policy, and the policy digest is provided in hex format.
-l parent-policy.hex
The policy session digest of the parent object. This option is applicable for objects other than primary keys.
-i input.bin
Input data to be encrypted using the created key. This option is useful for symmetric encryption algorithms.
-o output.bin
Output file for the encrypted data. This option is used in conjunction with the -i option.
-P password
The password for the primary key object. This can be a hex string or a password.

Algorithm Specifiers

This section details how to specify algorithms for the -G and -g options. The general format for the -G option is key-alg=key-type[:key-bits[:scheme[:hash-alg]]] and for the -g option is hash-alg.

For rsa keys:

rsa[:key-bits]
Specifies an RSA key. The default key size is 2048 bits. Supported key sizes are 2048, 3072, and 4096.
rsaes
Specifies RSA with PKCS#1 v1.5 encryption.
rsaes-oaep
Specifies RSA with OAEP encryption.
rsaes-pss
Specifies RSA with PSS signature.

For ecc keys:

ecc[:curve]
Specifies an ECC key. The default curve is nistp256. Supported curves are: nistp192, nistp224, nistp256, nistp384, nistp521, secp192k1, secp224k1, secp256k1, wz-sha256, wz-sha384, wz-sha512.
ecdsa[:hash-alg]
Specifies ECDSA signature scheme. The default hash algorithm is sha256.
ecdaa[count[:hash-alg]]
Specifies EC-DAA signature scheme. The count specifies the number of signatures that can be accumulated. The default hash algorithm is sha256.

For symmetric encryption keys:

aes[:key-bits]
Specifies an AES key. The default key size is 128 bits. Supported key sizes are 128, 192, and 256.
aes-cfb
Specifies AES with CFB mode. This mode is often used for encrypting data. If not specified, an asymmetric objects symmetric details defaults to aes128cfb.

Examples

Create an rsa2048 key with an rsaes asymmetric encryption scheme

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Create an ecc256 key with an ecdaa signing scheme with a count of 4 and sha384 hash

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv cryptographic algorithms ALGORITHM.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.
