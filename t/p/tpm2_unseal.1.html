tpm2_unseal(1) Manuel des commandes générales tpm2_unseal(1)

NOM

tpm2_unseal(1) - Renvoie un blob de données dans un objet TPM chargé. Le blob de données est renvoyé en clair.

SYNOPSIS

tpm2_unseal [OPTIONS]

DESCRIPTION

tpm2_unseal(1) - Renvoie un blob de données dans un objet TPM chargé. Le blob de données est renvoyé en clair. Les données sont scellées au moment de la création de l'objet à l'aide de l'outil tpm2_create. Un tel objet destiné au scellement de données doit être de type TPM_ALG_KEYEDHASH.

OPTIONS

•
-c, --object-context=OBJET:

Contexte de l'objet pour l'objet chargé.

•
-p, --auth=AUTH:

Valeur d'authentification optionnelle à utiliser pour la clé spécifiée par -c.

•
-o, --output=FICHIER:

Nom du fichier de sortie contenant les données déscellées. Par défaut, il s'agit de STDOUT si non spécifié.

•
--cphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de la commande. Ceci est communément appelé cpHash. REMARQUE : Lorsque cette option est sélectionnée, l'outil n'exécutera pas réellement la commande, il renverra simplement un cpHash, il renverra simplement un cpHash, à moins que rphash ne soit également requis.

•
--rphash=FICHIER

Chemin du fichier pour enregistrer le hachage des paramètres de réponse. Ceci est communément appelé rpHash.

•
-S, --session=FICHIER:

La session créée à l'aide de tpm2_startauthsession. Plusieurs de ces sessions peuvent être spécifiées. Par exemple, vous pouvez avoir une session pour l'audit et une autre pour le chiffrement/déchiffrement des paramètres.

Références

Format de l'Objet de Contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante par ordre:

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à un préfixe sur l'un des éléments suivants:
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie de plateforme
•
endorsement: la hiérarchie d'endossement
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple, 0x81010013 et utilisé directement.

Format de l'Authentification

L'authentification pour l'utilisation d'un objet en TPM2.0 peut prendre 3 formes différentes : 1. Mot de passe 2. HMAC 3. Sessions

REMARQUE : “Les authentifications par défaut sont un MOT DE PASSE VIDE lorsqu'elles ne sont pas spécifiées”.

Mots de passe

Les mots de passe sont interprétés sous les formes suivantes à l'aide d'identifiants de préfixe.

Remarque : Par défaut, les mots de passe sont supposés être sous forme de chaîne lorsqu'ils n'ont pas de préfixe.

Chaîne

Un mot de passe sous forme de chaîne, spécifié par le préfixe “str:” ou son absence (chaîne brute sans préfixe) n'est pas interprété et est directement utilisé pour l'authentification.

Exemples

foobar
str:foobar

Chaîne hexadécimale

Un mot de passe sous forme de chaîne hexadécimale, spécifié par le préfixe “hex:” est converti d'une forme hexadécimale en une forme de tableau d'octets, permettant ainsi les mots de passe contenant des caractères non imprimables et/ou peu conviviaux pour le terminal.

Exemple

hex:1122334455667788

Fichier

Un mot de passe basé sur un fichier, spécifié par le préfixe “file:” doit être le chemin d'un fichier contenant le mot de passe à lire par l'outil, ou un “-” pour utiliser stdin. Le stockage des mots de passe dans des fichiers empêche les fuites d'informations, les mots de passe transmis en tant qu'options peuvent être lus à partir de la liste des processus ou des fonctionnalités courantes de l'historique du shell.

Exemples

# pour utiliser stdin et être invité
file:-
# pour utiliser un fichier à partir d'un chemin
file:chemin/vers/fichier/motdepasse
# pour afficher un mot de passe via stdin :
echo motdepasse | tpm2_tool -p file:-
# pour utiliser une chaîne here-string bash via stdin :
tpm2_tool -p file:- <<< motdepasse

Sessions

Lors de l'utilisation d'une session de politique pour autoriser l'utilisation d'un objet, préfixez l'argument de l'option avec le mot-clé session. Indiquez ensuite un chemin vers un fichier de session qui a été créé avec tpm2_startauthsession(1). Facultativement, si la session nécessite une valeur d'authentification à envoyer avec le handle de session (par exemple, mot de passe de politique), ajoutez un + et une chaîne comme décrit dans la section Mots de passe.

Exemples

Pour utiliser un fichier de contexte de session appelé session.ctx.

session:session.ctx

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification monmotdepasse.

session:session.ctx+monmotdepasse

Pour utiliser un fichier de contexte de session appelé session.ctx ET envoyer la valeur d'authentification HEX 0x11223344.

session:session.ctx+hex:11223344

Authentifications de PCR

Vous pouvez satisfaire une politique PCR à l'aide du préfixe “pcr:” et du mini-langage PCR. Le mini-langage PCR est le suivant : <spécificateur-pcr>=<fichier-pcr-brut>

Le spécificateur PCR est documenté dans la section “Spécificateurs de banque PCR”.

Le fichier-pcr-brut est un argument optionnel qui contient la sortie du contenu PCR brut tel que renvoyé par tpm2_pcrread(1).

Spécificateurs de banque PCR

Exemples

Pour satisfaire une politique PCR de sha256 sur les banques 0, 1, 2 et 3, utilisez un spécificateur de :

pcr:sha256:0,1,2,3

en spécifiant AUTH.

tpm2_unseal(1)

NAME

tpm2_unseal

unseal data that was sealed using tpm2_seal

SYNOPSIS

tpm2_unseal [OPTIONS]  [-c AUTH_HANDLE]  [-p POLICY_digest]  [-o output_file]

DESCRIPTION

tpm2_unseal is used to unseal data that was sealed using tpm2_seal(1). The tool requires the sealed context object handle, and can optionally take a policy digest and an output file.

OPTIONS

•
-c AUTH_HANDLE, --auth-handle=AUTH_HANDLE

The handle of the sealed object used to unseal the data. This handle can be specified as a decimal or hexadecimal number, or as a context file name. The context file is generated by a previous call to tpm2_seal(1).

•
-p POLICY_digest, --policy-digest=POLICY_digest

The policy digest used to authorize the unsealing operation. This can be specified in several ways:

1.
A raw policy digest value (e.g. sha256:1234...).
2.
The name of a policy file previously created using tpm2_policysession(1).
3.
A file containing the digest of the policy. This file is created using tpm2_dumpchosenpolicy(1).
4.
The keyword pcr followed by a list of PCRs and digest values. This requires the TPM to be rebooted for the PCR values to be updated. The format is: pcr:sha1:0,1,2 or pcr:sha256:0,1,2.
•
-o output_file, --output-file=output_file

The file where the unsealed data will be written. If not specified, the unsealed data will be written to standard output.

Context Object Format

The context object format can be specified by the user in the following ways:

A file path to a context file, which is generated by a previous call to tpm2_seal(1).
A numeric handle, which is the TPM handle of the object. This can be specified in decimal or hexadecimal format (e.g. 0x80000000 or 2147483648).

Authorization Formatting

The authorization value can be specified in the following ways:

The authorisation value can be specified as a password string on the command line. This is not recommended for security reasons.
The authorisation value can be specified as a policy digest. This can be in the form of a file previously created by tpm2_policysession(1) or tpm2_dumpchosenpolicy(1).
The policy digest can be specified in the form of PCR values. The format is pcr:sha1:0,1,2 or pcr:sha256:0,1,2. This will require the TPM to be rebooted for the PCR values to be updated.

COMMON OPTIONS

To successfully use the manpages feature requires the manpages to be installed or on MANPATH, See man(1) for more details.

•
-v, --version: Display version information for this tool, supported tctis and exit.
•
-V, --verbose: Increase the information that the tool prints to the console during its execution. When using this option the file and line number are printed.
•
-Q, --quiet: Silence normal tool output to stdout.
•
-Z, --enable-errata: Enable the application of errata fixups. Useful if an errata fixup needs to be applied to commands sent to the TPM. Defining the environment TPM2TOOLS_ENABLE_ERRATA is equivalent.
•
-R, --autoflush: Enable autoflush for transient objects created by the command. If a parent object is loaded from a context file also the transient parent object will be flushed. Autoflush can also be activated if the environment variable TPM2TOOLS_AUTOFLUSH is is set to yes or true. information many users may expect.

TCTI Configuration

The TCTI or “Transmission Interface” is the communication mechanism with the TPM. TCTIs can be changed for communication with TPMs across different mediums.

To control the TCTI, the tools respect:

1.
The command line option -T or --tcti
2.
The environment variable: TPM2TOOLS_TCTI.

Note: The command line option always overrides the environment variable.

The current known TCTIs are:

•
tabrmd - The resource manager, called tabrmd. Note that tabrmd and abrmd as a tcti name are synonymous.
•
mssim - Typically used for communicating to the TPM software simulator.
•
device - Used when talking directly to a TPM device file.
•
none - Do not initalize a connection with the TPM. Some tools allow for off-tpm options and thus support not using a TCTI. Tools that do not support it will error when attempted to be used without a TCTI connection. Does not support ANY options and MUST BE presented as the exact text of “none”.

The arguments to either the command line option or the environment variable are in the form:

<tcti-name>:<tcti-option-config>

Specifying an empty string for either the <tcti-name> or <tcti-option-config> results in the default being used for that portion respectively.

TCTI Defaults

When a TCTI is not specified, the default TCTI is searched for using dlopen(3) semantics. The tools will search for tabrmd, device and mssim TCTIs IN THAT ORDER and USE THE FIRST ONE FOUND. You can query what TCTI will be chosen as the default by using the -v option to print the version information. The “default-tcti” key-value pair will indicate which of the aforementioned TCTIs is the default.

Custom TCTIs

Any TCTI that implements the dynamic TCTI interface can be loaded. The tools internally use dlopen(3), and the raw tcti-name value is used for the lookup. Thus, this could be a path to the shared library, or a library name as understood by dlopen(3) semantics.

TCTI OPTIONS

This collection of options are used to configure the various known TCTI modules available:

•
device: For the device TCTI, the TPM character device file for use by the device TCTI can be specified. The default is /dev/tpm0.

Example: -T device:/dev/tpm0 or export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: For the mssim TCTI, the domain name or IP address and port number used by the simulator can be specified. The default are 127.0.0.1 and 2321.

Example: -T mssim:host=localhost,port=2321 or export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: For the abrmd TCTI, the configuration string format is a series of simple key value pairs separated by a `,' character. Each key and value string are separated by a `=' character.
•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

tpm2_createprimary -c primary.ctx -Q
tpm2_pcrread -Q -o pcr.bin sha256:0,1,2,3
tpm2_createpolicy -Q --policy-pcr -l sha256:0,1,2,3 -f pcr.bin -L pcr.policy
echo 'secret' | tpm2_create -C primary.ctx -L pcr.policy -i-\
-u seal.pub -r seal.priv -c seal.ctx -Q
tpm2_unseal -c seal.ctx -p pcr:sha256:0,1,2,3

Returns

Tools can return any of the following codes:

•
0 - Success.
•
1 - General non-specific error.
•
2 - Options handling error.
•
3 - Authentication error.
•
4 - TCTI related error.
•
5 - Non supported scheme. Applicable to tpm2_testparams.
