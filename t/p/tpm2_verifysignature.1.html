tpm2_verifysignature(1) Manuel des commandes générales tpm2_verifysignature(1)

NOM

tpm2_verifysignature(1) - Valide une signature à l'aide du TPM.

SYNOPSIS

tpm2_verifysignature [OPTIONS]

DESCRIPTION

tpm2_verifysignature(1) - Utilise les clés chargées pour valider une signature sur un message avec le hachage du message transmis au TPM. Si la vérification de la signature réussit, le TPM produira un TPMT_TK_VERIFIED. Sinon, le TPM retournera TPM_RC_SIGNATURE. Si l'objet référence une clé asymétrique, seule la partie publique de la clé doit être chargée. Si l'objet référence une clé symétrique, les parties publique et privée doivent être chargées.

OPTIONS

•
-c, --key-context=OBJET:

Objet de contexte pour le contexte de clé utilisé pour l'opération. Soit un fichier, soit un numéro de handle. Voir la section « Format de l'objet de contexte ».

•
-g, --hash-algorithm=ALGORITHME:

L'algorithme de hachage utilisé pour hacher le message. Les algorithmes doivent suivre les « normes de formatage », voir la section « Spécificateurs d'algorithmes ». Voir également la section « Algorithmes de hachage pris en charge » pour une liste des algorithmes de hachage pris en charge.

•
-m, --message=FICHIER:

Le fichier message, contenant le contenu à hacher.

•
-d, --digest=FICHIER:

Le fichier de hachage d'entrée, contenant le hachage du message. Si cette option est sélectionnée, les options message (-m) et algorithm (-g) ne doivent pas être spécifiées.

•
-s, --signature=FICHIER:

Le fichier de signature d'entrée de la signature à valider.

•
-f, --scheme=SCHEME:

Le schéma de signature utilisé pour signer le message. Cette option ne doit être spécifiée que si la signature provient d'un format non standard tss, comme openssl. Voir « Spécificateurs de format de signature » pour plus de détails. Le format tss contient les métadonnées de signature nécessaires pour comprendre son schéma de signature.

Les schémas de signature doivent suivre les « normes de formatage », voir la section « Spécificateurs d'algorithmes ».

•
--format=SCHEME:

Obsolète. Identique à --scheme.

•
-t, --ticket=FICHIER:

Le fichier ticket pour enregistrer la structure de validation.

Références

Format de l'objet de contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme objet transitoire TPM restauré.
•
Si l'argument correspond à un préfixe de l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie de plateforme
•
endorsement: la hiérarchie d'approbation
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013 et utilisé directement.*OBJET*.

Spécificateurs complexes

Les objets, lorsqu'ils sont spécifiés pour la création par le TPM, ont de nombreux algorithmes à renseigner dans les données publiques. Des éléments tels que le type, le schéma et les détails asymétriques, la taille de la clé, etc. Voici le format général pour spécifier ces données : <type>:<schéma>:<détails-symétriques>

Spécificateurs de Schéma

Ensuite, il y a un champ optionnel, il peut être ignoré.

Les schémas sont généralement des Schémas de Signature ou des Schémas de Chiffrement Asymétrique. La plupart des schémas de signature prennent un algorithme de hachage directement après le schéma de signature. Si l'algorithme de hachage est manquant, la valeur par défaut est sha256. Certains ne prennent aucun argument, et d'autres prennent plusieurs arguments.

Schémas Optionnels avec Hachage

Ces spécificateurs de schéma sont suivis d'un trait et d'un algorithme de hachage valide. Par exemple : oaep-sha256.

Schémas avec Options Multiples

Ce spécificateur de schéma est suivi d'un compte (taille maximale UINT16) puis d'un trait (-) et d'un algorithme de hachage valide. * ecdaa Par exemple, ecdaa4-sha256. Si aucun compte n'est spécifié, la valeur par défaut est 4.

Schémas Sans Options

Ce spécificateur de schéma ne prend AUCUN argument. * rsaes

Spécificateurs de Détails Symétriques

Ce champ est optionnel et sa valeur par défaut dépend du type d'objet créé et de ses attributs. Généralement, tout spécificateur Symétrique valide de la liste des spécificateurs de Type devrait fonctionner. S'il n'est pas spécifié, les détails symétriques des objets asymétriques prennent par défaut la valeur aes128cfb.

Exemples

Créer une clé rsa2048 avec un schéma de chiffrement asymétrique rsaes

tpm2_create -C parent.ctx -G rsa2048:rsaes -u key.pub -r key.priv

Créer une clé ecc256 avec un schéma de signature ecdaa avec un compte de 4 et un hachage sha384

/tpm2_create -C parent.ctx -G ecc256:ecdaa4-sha384 -u key.pub -r key.priv algorithmes cryptographiques ALGORITHME.

Configuration du TCTI

Le TCTI ou « Interface de Transmission » est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour la communication avec des TPM sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé pour communiquer directement avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge le fait de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne prend pas en charge *AUCUNE* option et *DOIT ÊTRE* présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-options-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou le <config-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Valeurs par défaut du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim DANS CET ORDRE et UTILISERONT LE PREMIER TROUVÉ. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est la valeur par défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute tcti-name est utilisée pour la recherche. Ainsi, il peut s'agir d'un chemin vers la bibliothèque partagée, ou d'un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

OPTIONS DU TCTI

Cet ensemble d'options est utilisé pour configurer les divers modules TCTI connus disponibles :

•
device : Pour le TCTI device, le fichier caractère du périphérique TPM à utiliser par le TCTI device peut être spécifié. La valeur par défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim : Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le port utilisés par le simulateur peuvent être spécifiés. Les valeurs par défaut sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd : Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,`. Chaque clé et valeur sont séparées par un caractère `=.
•
Le TCTI abrmd prend en charge deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne de caractères).
2.
`bus_type' : Le type de l'instance dbus (une chaîne de caractères) limitée à `session' et `system'.

Spécifier le nom TCTI tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le TCTI par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. les divers modules TCTI connus.

Spécificateurs de Format de Signature

Format Specifiers

Sélection du format pour le fichier de sortie de la signature. tss (le défaut) produira un bloc binaire conforme à la spécification TPM 2.0 et à tout éventuel remplissage du compilateur. L'option plain produira les données de signature brutes telles que définies par l'algorithme cryptographique utilisé.

EXEMPLES

Signer et vérifier avec le TPM en utilisant la hiérarchie endorsement

tpm2_createprimary -C e -c primary.ctx
tpm2_create -G rsa -u rsa.pub -r rsa.priv -C primary.ctx
tpm2_load -C primary.ctx -u rsa.pub -r rsa.priv -c rsa.ctx
echo "mon message" > message.dat
tpm2_sign -c rsa.ctx -g sha256 -s sig.rssa message.dat
tpm2_verifysignature -c rsa.ctx -g sha256 -m message.dat -s sig.rssa

Signer avec openssl et vérifier avec le TPM

# Générer une clé ECC
openssl ecparam -name prime256v1 -genkey -noout -out private.ecc.pem
openssl ec -in private.ecc.pem -out public.ecc.pem -pubout
# Générer un hash à signer (OSSL a besoin du hash du message)
echo "données à signer" > data.in.raw
sha256sum data.in.raw | awk '{ print "000000 " $1 }' | \
xxd -r -c 32 > data.in.digest
# Charger la clé privée pour la signature
tpm2_loadexternal -Q -G ecc -r private.ecc.pem -c key.ctx
# Signer dans le TPM et vérifier avec OSSL
tpm2_sign -Q -c key.ctx -g sha256 -d data.in.digest -f plain -s data.out.signed
openssl dgst -verify public.ecc.pem -keyform pem -sha256 \
-signature data.out.signed data.in.raw
# Signer avec openssl et vérifier avec TPM
openssl dgst -sha256 -sign private.ecc.pem -out data.out.signed data.in.raw
tpm2_verifysignature -Q -c key.ctx -g sha256 -m data.in.raw -f ecdsa \
-s data.out.signed

Retour

Les outils peuvent retourner l'un des codes suivants :

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
