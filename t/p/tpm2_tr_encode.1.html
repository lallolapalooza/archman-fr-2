tpm2_tr_encode(1) Manuel des commandes générales tpm2_tr_encode(1)

NOM

tpm2_tr_encode(1) - Code un handle persistant et TPM2B_NAME sous forme d'un ESYS_TR sérialisé en sortie.

SYNOPIS

tpm2_tr_encode [OPTIONS]

DESCRIPTION

tpm2_tr_encode(1) - Code un handle TPM2 persistant ainsi qu'une TPM2B_PUBLIC remplie sous forme d'un ESYS_TR sérialisé. Ceci est utile pour déplacer une clé publique et un handle d'un environnement où un TPM n'est pas disponible vers un autre environnement avec un TPM et l'utiliser via l'API ESAPI ou tpm2-tools(1).

OPTIONS

•
-c, --object-context=OBJET:

Handle persistant.

•
-f, --format:

Sélection du format pour le fichier de sortie de la clé publique. `tss' (par défaut) produira un blob binaire conforme aux spécifications TPM 2.0. `pem' produira une clé publique encodée en PEM compatible avec OpenSSL. `der' produira une clé publique encodée en DER compatible avec OpenSSL. `tpmt' produira un blob binaire de la structure TPMT_PUBLIC référencée par les spécifications TPM 2.0.

Format de la clé publique.

•
-o, --output=FICHIER:

Chemin du fichier de sortie, enregistrant le ESYS_TR sérialisé.

Références

Format de l'Objet de Contexte

Le type d'un objet de contexte, qu'il s'agisse d'un handle ou d'un nom de fichier, est déterminé selon la logique suivante *dans l'ordre* :

•
Si l'argument est un chemin de fichier, alors le fichier est chargé comme un objet transitoire TPM restauré.
•
Si l'argument correspond à une correspondance de *préfixe* sur l'un des éléments suivants :
•
owner: la hiérarchie propriétaire
•
platform: la hiérarchie de plateforme
•
endorsement: la hiérarchie d'endossement
•
lockout: l'objet persistant de contrôle de verrouillage
•
Si l'argument peut être chargé comme un nombre, il sera traité comme un handle, par exemple 0x81010013, et utilisé directement. *OBJET*.

Configuration du TCTI

Le TCTI, ou « Interface de Transmission », est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs via différents médias.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom de tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel de TPM.
•
device - Utilisé pour communiquer directement avec le fichier de périphérique TPM.
•
none - N'initialise pas de connexion avec le TPM. Certains outils permettent des options hors TPM et prennent donc en charge la non-utilisation d'un TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne prend en charge *AUCUNE* option et *DOIT* être présenté comme le texte exact de « none ».

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<config-option-tcti>

Spécifier une chaîne vide pour le <nom-tcti> ou la <config-option-tcti> utilise la valeur par défaut pour cette partie respectivement.

Défauts du TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront les TCTIs tabrmd, device et mssim **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur « default-tcti » indiquera lequel des TCTIs susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela pourrait être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel qu'il est compris par la sémantique de dlopen(3).

Cette collection d'options est utilisée pour configurer les différents modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•

NAME

tpm2_tr_encode — encode a TPM handle into a TPM2B_PUBLIC, or TPM2B_NAME

SYNOPSIS

tpm2_tr_encode [OPTIONS] [handle] [output file]

DESCRIPTION

Encode a TPM handle into a TPM2B structure. The handle is encoded into a TPM2B_PUBLIC structure by default. If the TPM2B_NAME option is specified, the handle is encoded into a TPM2B_NAME structure. The output is written to a file.

The output of the command is a binary file containing the encoded handle.

OPTIONS

The following options are available:

-c OBJECT
The TPM object to use for the operation. This can be a hierarchy, a loaded object, or an object opened by UUID. The object is specified as a handle (e.g. 0x81000002) or as a file path containing a handle.
-u PATH
Specifies the path to the input file containing the public portion of the handle. This option is used when the handle is not directly available as an input. It's expected that this file contains a TPM2B_PUBLIC structure.
-o PATH
Specifies the path to the output file where the encoded handle will be written.
-n
Encode the handle as a TPM2B_NAME structure instead of the default TPM2B_PUBLIC structure.
--tcti=TCTI
Specifies the Tagged Command Transmission Interface (TCTI) to use for communicating with the TPM. The default TCTI is based on the value of the TPM2TCTI environment variable. This option can be used to override the default.
-h, --help
Prints the help message and exits.

Context Object Format

The context object format is a binary file containing a marshaled TPM context object. The context object is used to represent a handle to a TPM object, such as a primary key, a loaded key, or a session.

COMMON OPTIONS

These options are common to all tpm2-* tools.

-z, --cphash
Compute the CP hash of the command and print it to stdout.

TCTI Configuration

The TCTI is used to establish a connection to the TPM. The following TCTIs are supported:

-"foo"
This is an example TCTI module name. The actual TCTI modules will be available on the system.

When specifying a TCTI, you can also specify configuration options for that TCTI. The configuration options are specified as a comma-separated list of key=value pairs.

For example, to specify the tabrmd TCTI with a specific bus_name, you would use:

\--tcti=tabrmd:bus_name=com.example.FooBar

The TCTI configuration string is a list of properties where each property and value string are separated by a `=' character.

TCTI OPTIONS

•
TCTI abrmd supports two keys:
1.
`bus_name' : The name of the tabrmd service on the bus (a string).
2.
`bus_type' : The type of the dbus instance (a string) limited to `session' and `system'.

Specify the tabrmd tcti name and a config string of bus_name=com.example.FooBar:

\--tcti=tabrmd:bus_name=com.example.FooBar

Specify the default (abrmd) tcti and a config string of bus_type=session:

\--tcti:bus_type=session

NOTE: abrmd and tabrmd are synonymous. the various known TCTI modules.

EXAMPLES

Sérialiser une clé publique et un handle en tant que ESYS_TR

tpm2_createprimary -c primary.ctx
tpm2_evictcontrol -c primary.ctx -o primary.tr 0x81000002
tpm2_readpublic -c primary.tr -o primary.pub
tpm2_tr_encode -c 0x81000002 -u primary.pub -o primary2.tr

Retourne

Les outils peuvent retourner l'un des codes suivants:

•
0 - Succès.
•
1 - Erreur générale non spécifique.
•
2 - Erreur de gestion des options.
•
3 - Erreur d'authentification.
•
4 - Erreur liée au TCTI.
•
5 - Schéma non supporté. Applicable à tpm2_testparams.
