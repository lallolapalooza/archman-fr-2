tpm2_startup(1) Manuel des commandes générales tpm2_startup(1)

NOM

tpm2_startup(1) - Envoie une commande de démarrage au TPM.

SYNTAXE

tpm2_startup [OPTIONS]

DESCRIPTION

tpm2_startup(1) - Envoie une commande TPM2_Startup avec soit TPM_SU_CLEAR soit TPM_SU_STATE.

OPTIONS

•
-c, --clear:

Le type de démarrage envoyé sera TPM_SU_CLEAR au lieu de TPM2_SU_STATE.

Références

OPTIONS COMMUNES

Cette collection d'options est commune à de nombreux programmes et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help=[man|no-man]: Affiche la page de manuel de l'outil. Par défaut, il tente d'appeler le paginator de manuel pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le paginator de manuel échoue, les options courtes seront affichées sur stdout.

Pour utiliser avec succès la fonctionnalité des pages de manuel, il faut que les pages de manuel soient installées ou sur MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version pour cet outil, les tcti supportés et quitte.
•
-V, --verbose: Augmente les informations que l'outil imprime sur la console pendant son exécution. Lors de l'utilisation de cette option, le fichier et le numéro de ligne sont imprimés.
•
-Q, --quiet: Supprime la sortie normale de l'outil vers stdout.
•
-Z, --enable-errata: Active l'application des corrections d'errata. Utile si une correction d'errata doit être appliquée aux commandes envoyées au TPM. Définir l'environnement TPM2TOOLS_ENABLE_ERRATA est équivalent.
•
-R, --autoflush: Active le vidage automatique des objets transitoires créés par la commande. Si un objet parent est chargé à partir d'un fichier de contexte, l'objet parent transitoire sera également vidé. Le vidage automatique peut également être activé si la variable d'environnement TPM2TOOLS_AUTOFLUSH est définie sur yes ou true. Des informations que de nombreux utilisateurs peuvent attendre.

Configuration TCTI

Le TCTI, ou interface de transmission, est le mécanisme de communication avec le TPM. Les TCTIs peuvent être modifiés pour communiquer avec des TPMs sur différents supports.

Pour contrôler le TCTI, les outils respectent :

1.
L'option de ligne de commande -T ou --tcti
2.
La variable d'environnement : TPM2TOOLS_TCTI.

Note : L'option de ligne de commande remplace toujours la variable d'environnement.

Les TCTIs actuellement connus sont :

•
tabrmd - Le gestionnaire de ressources, appelé tabrmd. Notez que tabrmd et abrmd en tant que nom tcti sont synonymes.
•
mssim - Généralement utilisé pour communiquer avec le simulateur logiciel TPM.
•
device - Utilisé lors de la communication directe avec le fichier de périphérique TPM.
•
none - Ne pas initialiser de connexion avec le TPM. Certains outils permettent des options hors-tpm et prennent donc en charge de ne pas utiliser de TCTI. Les outils qui ne le prennent pas en charge généreront une erreur lorsqu'ils seront utilisés sans connexion TCTI. Ne prend en charge AUCUNE option et DOIT être présenté comme le texte exact de “none”.

Les arguments de l'option de ligne de commande ou de la variable d'environnement sont sous la forme :

<nom-tcti>:<configuration-options-tcti>

Spécifier une chaîne vide pour <nom-tcti> ou <configuration-options-tcti> entraîne l'utilisation de la valeur par défaut pour cette partie respectivement.

Défauts TCTI

Lorsqu'un TCTI n'est pas spécifié, le TCTI par défaut est recherché en utilisant la sémantique de dlopen(3). Les outils rechercheront tabrmd, device et mssim TCTIs **DANS CET ORDRE** et **UTILISERONT LE PREMIER TROUVÉ**. Vous pouvez interroger quel TCTI sera choisi par défaut en utilisant l'option -v pour afficher les informations de version. La paire clé-valeur “default-tcti” indiquera quel TCTI parmi les susmentionnés est le défaut.

TCTIs Personnalisés

Tout TCTI qui implémente l'interface TCTI dynamique peut être chargé. Les outils utilisent en interne dlopen(3), et la valeur brute nom-tcti est utilisée pour la recherche. Ainsi, cela peut être un chemin vers la bibliothèque partagée, ou un nom de bibliothèque tel que compris par la sémantique de dlopen(3).

OPTIONS TCTI

Cette collection d'options est utilisée pour configurer les divers modules TCTI connus disponibles :

•
device: Pour le TCTI device, le fichier du périphérique caractère TPM à utiliser par le TCTI device peut être spécifié. Le défaut est /dev/tpm0.

Exemple : -T device:/dev/tpm0 ou export TPM2TOOLS_TCTI=“device:/dev/tpm0”

•
mssim: Pour le TCTI mssim, le nom de domaine ou l'adresse IP et le port utilisés par le simulateur peuvent être spécifiés. Les défauts sont 127.0.0.1 et 2321.

Exemple : -T mssim:host=localhost,port=2321 ou export TPM2TOOLS_TCTI=“mssim:host=localhost,port=2321”

•
abrmd: Pour le TCTI abrmd, le format de la chaîne de configuration est une série de paires clé-valeur simples séparées par un caractère `,'. Chaque clé et valeur sont séparées par un caractère `='.
•
Le TCTI abrmd supporte deux clés :
1.
`bus_name' : Le nom du service tabrmd sur le bus (une chaîne).
2.
`bus_type' : Le type de l'instance dbus (une chaîne) limité à `session' et `system'.

Spécifier le nom du tcti tabrmd et une chaîne de configuration de bus_name=com.example.FooBar :

\--tcti=tabrmd:bus_name=com.example.FooBar

Spécifier le tcti par défaut (abrmd) et une chaîne de configuration de bus_type=session :

\--tcti:bus_type=session

NOTE : abrmd et tabrmd sont synonymes. Les divers modules TCTI connus.

EXEMPLES

Envoyer une commande TPM Startup avec les flags TPM2_SU_STATE

tpm2_startup

Envoyer une commande TPM Startup avec les flags TPM2_SU_CLEAR

tpm2_startup -c

NOTES

Généralement, un gestionnaire de ressources (comme tpm2-abrmd) ou un logiciel de bas niveau/de démarrage aura déjà envoyé cette commande.
