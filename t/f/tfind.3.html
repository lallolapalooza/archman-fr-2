tsearch(3) Manuel des fonctions de bibliothèque tsearch(3)

NOM

tsearch, tfind, tdelete, twalk, twalk_r, tdestroy - gérer un arbre binaire de recherche

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <search.h>
typedef enum { preorder, postorder, endorder, leaf } VISIT;
void *tfind(const void *key, void *const *rootp,
            typeof(int (const void *, const void *)) *compar);
void *tsearch(const void *key, void **rootp,
            typeof(int (const void *, const void *)) *compar);
void *tdelete(const void *restrict key, void **restrict rootp,
            typeof(int (const void *, const void *)) *compar);
void twalk(const void *root,
            typeof(void (const void *nodep, VISIT which, int depth))
                *action);
#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <search.h>
void twalk_r(const void *root,
            typeof(void (const void *nodep, VISIT which, void *closure))
                *action,
            void *closure);
void tdestroy(void *root,
            typeof(void (void *nodep)) *free_node);

DESCRIPTION

tsearch(), tfind(), twalk(), et tdelete() gèrent un arbre binaire de recherche. Ils sont généralisés de l'algorithme T de Knuth (6.2.2). Le premier champ de chaque nœud de l'arbre est un pointeur vers l'élément de données correspondant. (Le programme appelant doit stocker les données réelles.) compar pointe vers une routine de comparaison, qui prend des pointeurs vers deux éléments. Elle doit retourner un entier qui est négatif, zéro, ou positif, selon que le premier élément est inférieur, égal, ou supérieur au second.

tsearch() recherche un élément dans l'arbre. key pointe vers l'élément recherché. rootp pointe vers une variable qui pointe vers la racine de l'arbre. Si l'arbre est vide, la variable pointée par rootp doit être mise à NULL. Si l'élément est trouvé dans l'arbre, alors tsearch() retourne un pointeur vers le nœud de l'arbre correspondant. (Autrement dit, tsearch() retourne un pointeur vers un pointeur vers l'élément de données.) Si l'élément n'est pas trouvé, alors tsearch() l'ajoute et retourne un pointeur vers le nœud de l'arbre correspondant.

tfind() est similaire à tsearch(), sauf que si l'élément n'est pas trouvé, alors tfind() retourne NULL.

tdelete() supprime un élément de l'arbre. Ses arguments sont les mêmes que ceux de tsearch().

twalk() effectue un parcours en profondeur, de gauche à droite, d'un arbre binaire. root pointe vers le nœud de départ du parcours. Si ce nœud n'est pas la racine, seule une partie de l'arbre sera visitée. twalk() appelle la fonction utilisateur action chaque fois qu'un nœud est visité (c'est-à-dire trois fois pour un nœud interne, et une fois pour une feuille). action, à son tour, prend trois arguments. Le premier argument est un pointeur vers le nœud visité. La structure du nœud n'est pas spécifiée, mais il est possible de caster le pointeur vers un pointeur-vers-pointeur-vers-élément pour accéder à l'élément stocké dans le nœud. L'application ne doit pas modifier la structure pointée par cet argument. Le deuxième argument est un entier qui prend l'une des valeurs preorder, postorder, ou endorder selon qu'il s'agit de la première, deuxième ou troisième visite du nœud interne, ou la valeur leaf s'il s'agit de la visite unique d'une feuille. (Ces symboles sont définis dans <search.h>.) Le troisième argument est la profondeur du nœud ; le nœud racine a une profondeur de zéro.

(Plus communément, preorder, postorder, et endorder sont connus sous les noms de preorder, inorder, et postorder : avant de visiter les enfants, après le premier et avant le second, et après avoir visité les enfants. Ainsi, le choix du nom postorder est assez déroutant.)

twalk_r() est similaire à twalk(), mais au lieu de l'argument depth, le pointeur d'argument closure est passé à chaque invocation de la fonction de rappel d'action, inchangé. Ce pointeur peut être utilisé pour passer des informations vers et depuis la fonction de rappel de manière thread-safe, sans recourir à des variables globales.

tdestroy() supprime tout l'arbre pointé par root, libérant toutes les ressources allouées par la fonction tsearch(). Pour les données dans chaque nœud de l'arbre, la fonction free_node est appelée. Le pointeur vers les données est passé en argument à la fonction. Si aucun travail de ce type n'est nécessaire, free_node doit pointer vers une fonction qui ne fait rien.

VALEUR DE RETOUR

tsearch() retourne un pointeur vers un nœud correspondant dans l'arbre, ou vers le nœud nouvellement ajouté, ou NULL s'il n'y avait pas assez de mémoire pour ajouter l'élément. tfind() retourne un pointeur vers le nœud, ou NULL si aucune correspondance n'est trouvée. S'il existe plusieurs éléments qui correspondent à la clé, l'élément dont le nœud est retourné n'est pas spécifié.

tdelete() retourne un pointeur vers le parent du nœud supprimé, ou NULL si l'élément n'a pas été trouvé. Si le nœud supprimé était le nœud racine, tdelete() retourne un pointeur dangling qui ne doit pas être accédé.

tsearch(), tfind(), et tdelete() retournent également NULL si rootp était NULL à l'entrée.

NOTES

twalk() prend un pointeur vers la racine, tandis que les autres fonctions prennent un pointeur vers une variable qui pointe vers la racine.

tdelete() libère la mémoire nécessaire pour le nœud dans l'arbre. L'utilisateur est responsable de libérer la mémoire pour les données correspondantes.

L'exemple de programme dépend du fait que twalk() ne fait plus référence à un nœud après avoir appelé la fonction utilisateur avec l'argument "endorder" ou "leaf". Cela fonctionne avec l'implémentation de la bibliothèque GNU, mais n'est pas dans la documentation System V.
