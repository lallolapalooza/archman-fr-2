tfmtodit(1) Manuel des commandes générales tfmtodit(1)

Nom

tfmtodit - adapte les fichiers TeX Font Metrics pour une utilisation avec groff et grodvi

Synopsis

tfmtodit [-s] [-g fichier.gf] [-k car-ajustement] fichier.tfm fichier.map description-police
tfmtodit --help
tfmtodit -v
tfmtodit --version

Description

tfmtodit crée un fichier de description de police à utiliser avec le périphérique de sortie dvi de groff(1). fichier.tfm est le nom du fichier TeX font metric pour la police. fichier.map attribue des identifiants de caractères ordinaires ou spéciaux de groff aux indices de glyphes dans la police ; il doit consister en une séquence de lignes de la forme

i c1 ... cn
où i est la position du glyphe dans la police en décimal, et c1 à cn sont des identifiants de glyphes dans le format utilisé par les descriptions de polices groff. Si un glyphe n'a pas de noms groff mais existe dans fichier.tfm, il est inclus dans le fichier de description de police groff en tant que glyphe sans nom. La sortie est écrite au format groff_font(5) dans description-police, un fichier nommé d'après le nom de police groff prévu.

Si la police est « spéciale », ce qui signifie que groff doit la rechercher chaque fois qu'un glyphe n'est pas trouvé dans la police actuelle, utilisez l'option -s et nommez description-police dans la directive fonts du fichier DESC du périphérique de sortie.

Pour effectuer une bonne composition mathématique, groff nécessite des informations de métriques de police qui ne sont pas présentes dans fichier.tfm. C'est parce que TeX a des polices italiques mathématiques séparées, tandis que groff utilise des polices italiques normales pour les mathématiques. Les informations supplémentaires requises par groff sont fournies par les deux arguments de la macro math_fit dans les programmes Metafont pour les polices Computer Modern. Dans une police de texte (une police pour laquelle math_fit est fausse), Metafont ignore normalement ces deux arguments. Metafont peut être amené à inclure ces informations dans les fichiers GF (« generic font ») qu'il produit en chargeant la définition suivante après cmbase lors de la création de cm.base.

def ignore_math_fit(expr left_adjustment,right_adjustment) =
    special "adjustment";
    numspecial left_adjustment*16/designsize;
    numspecial right_adjustment*16/designsize;
    enddef;
Pour la famille de polices EC, chargez la définition suivante après exbase; envisagez de patcher localement exbase.mf. 
def ignore_math_fit(expr left_adjustment,right_adjustment) =
    ori_special "adjustment";
    ori_numspecial left_adjustment*16/designsize;
    ori_numspecial right_adjustment*16/designsize;
    enddef;
La seule différence par rapport à l'exemple précédent est le préfixe « ori_ » appliqué à « special » et « numspecial ». Le fichier GF créé en utilisant ce cm.base ou exbase.mf modifié doit être spécifié avec l'option -g, qui ne doit pas être donnée pour une police pour laquelle math_fit est vraie.

Options

--help affiche un message d'utilisation, tandis que -v et --version affichent les informations de version ; tous se terminent ensuite.

-g fichier.gf
Utilise le fichier.gf produit par Metafont contenant des commandes « special » et « numspecial » pour obtenir des informations supplémentaires de métriques de police.
-k car-ajustement
Le caractère d'ajustement de cette police est à la position car-ajustement. car-ajustement doit être un entier ; il peut être donné en décimal, avec un 0 initial en octal, ou avec un 0x initial en hexadécimal. Tous les crans dont le second composant est car-ajustement sont ignorés.
-s
Ajoute la directive special au fichier de description de police.
