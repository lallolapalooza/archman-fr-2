NOM

bounce - Rapports d'état de livraison Postfix

SYNTAXE

bounce [options génériques du démon Postfix]

DESCRIPTION


Le démon bounce(8) maintient des fichiers journaux par message avec des informations d'état de livraison. Chaque fichier journal est nommé d'après le fichier de file d'attente auquel il correspond et est conservé dans un sous-répertoire de file d'attente nommé d'après le nom du service dans le fichier master.cf (soit bounce, defer ou trace). Ce programme est destiné à être exécuté par le gestionnaire de processus master(8).

Le démon bounce(8) traite deux types de requêtes de service :

  • Ajouter un enregistrement d'état de livraison (non-)livraison de destinataire à un fichier journal par message.
  • Mettre en file d'attente un message de notification d'état de livraison, avec une copie d'un fichier journal par message et du message correspondant. Lorsque le message de notification d'état de livraison est mis en file d'attente avec succès, le fichier journal par message est supprimé.

Le logiciel fait un effort maximal de notification. Une notification de non-livraison est envoyée même si le fichier journal ou le message original ne peuvent pas être lus.

Optionnellement, un client bounce (defer, trace) peut demander que le fichier journal par message soit supprimé lorsque l'opération demandée échoue. Ceci est utilisé par les clients qui ne peuvent pas réessayer les transactions par eux-mêmes et qui dépendent de la logique de nouvelle tentative dans leur propre client.

Les problèmes et les transactions sont enregistrés dans syslogd(8) ou postlogd(8).

Les modifications apportées à main.cf sont prises en compte automatiquement, car les processus bounce(8) ne s'exécutent que pendant une durée limitée. Utilisez la commande "postfix reload" pour accélérer la prise en compte d'une modification.

trace(8) — Postfix trace lookup

NAME

trace — Postfix trace lookup

SYNOPSIS

trace

DESCRIPTION

The trace(8) command is a Postfix support utility that implements the trace lookup service. It is used by the Postfix SMTP client to retrieve delivery status information for a given message.

The trace lookup service is activated when the Postfix SMTP client receives a request for a trace lookup. The request specifies a message identifier (typically a trace_id as described in RFC 8689). The trace service then searches its cache for a corresponding delivery status record. If found, it returns the status information to the client. If not found, it indicates that the information is not available.

The trace service maintains a cache of delivery status records. These records are populated by the Postfix mail system when messages are delivered or deferred. The cache is stored in memory and is periodically flushed to disk to ensure data persistence.

STANDARDS

The trace lookup service is based on the trace lookup protocol described in RFC 8689.

DIAGNOSTICS

The trace service logs its activity to the Postfix system log. Diagnostic messages may indicate issues with cache management, disk I/O, or network communication.

CONFIGURATION PARAMETERS

The behavior of the trace service is controlled by the following Postfix configuration parameters:

trace_lookup_max_cache_size
The maximum size of the trace lookup cache.
trace_lookup_cache_timeout
The time-to-live for entries in the trace lookup cache.
trace_lookup_file
The file where the trace lookup cache is stored.
trace_lookup_port
The network port on which the trace lookup service listens.

These parameters can be set in the main.cf file. For more details, see postconf(5).

The trace service relies on the Postfix queue manager (qmgr(8)) to receive delivery status updates. The format of bounce messages is described in bounce(5).

The trace service interacts with the Postfix master process (master(8)) and is managed by the Postfix system logging daemon (postlogd(8)). System logging is handled by syslogd(8).

The trace lookup protocol is defined in RFC 8689.
