NOM

trace-cmd-profile - profiler les tâches en cours d'exécution

SYNTAXE

trace-cmd profile [OPTIONS] [commande]

DESCRIPTION

La commande trace-cmd(1) profile démarrera le traçage comme trace-cmd-record(1), avec l'option --profile, sauf qu'elle n'écrira pas dans un fichier, mais lira les événements au fur et à mesure de leur occurrence et mettra à jour le comptage des événements. Lorsque le traçage sera terminé, elle rapportera les résultats comme le ferait trace-cmd-report(1) avec son option --profile. En d'autres termes, la commande profile effectue le travail de trace-cmd record --profile, et trace-cmd report --profile sans avoir à enregistrer les données sur disque, entre les deux.

L'avantage d'utiliser la commande profile est que le profilage peut être effectué sur une longue période où l'enregistrement de tous les événements prendrait trop d'espace disque.

Cela activera plusieurs événements ainsi que le traçeur de graphe de fonctions avec une profondeur d'un (si le noyau le supporte). Ceci est pour montrer où les tâches entrent et sortent du noyau et combien de temps elles ont passé dans le noyau.

Pour désactiver le graphe de fonctions appelées, utilisez l'option -p pour activer un autre traçeur. Pour ne pas activer de traçeur, utilisez -p nop.

Tous les temps sont actuellement en nanosecondes.

OPTIONS

Ce sont les mêmes que trace-cmd-record(1) avec l'option --profile.

-p tracer

Définit un plugin de traçage à exécuter au lieu du traçage de graphe de fonctions réglé à une profondeur de 1. Pour ne pas exécuter de traçeur, utilisez -p nop.

-S

Active uniquement le traçeur ou les événements spécifiés sur la ligne de commande. Avec cette option, le traçeur function_graph n'est pas activé, ni aucun événement (comme sched_switch), sauf s'ils sont spécifiquement spécifiés sur la ligne de commande (c'est-à-dire -p function -e sched_switch -e sched_wakeup).

-G

Définit les événements d'interruption (soft et hard) comme globaux (associés au CPU plutôt qu'aux tâches).

-o fichier

Écrit la sortie du profil dans fichier. Ceci remplace --stderr

-H event-hooks

Ajoute des correspondances d'événements personnalisées pour connecter deux événements ensemble. Le format est : [<systeme_debut>:]<evenement_debut>,<correspondance_debut>[,<pid_debut>]/ [<systeme_fin>:]<evenement_fin>,<correspondance_fin>[,<flags>] 
Le systeme_debut:evenement_debut (systeme_debut est optionnel), est l'événement qui
démarre la mesure du temps.
correspondance_debut est le champ dans l'événement de début qui doit correspondre à
la correspondance_fin dans l'événement de fin.
pid_debut est optionnel, car les correspondances sont associées aux tâches qui
exécutent les événements. Si un autre champ doit être utilisé pour trouver cette
tâche, il est spécifié avec pid_debut.
systeme_fin:evenement_fin est l'événement qui termine la mesure du temps
(systeme_fin est optionnel).
correspondance_fin est le champ dans correspondance_fin qui correspondra au champ
correspondance_debut de l'événement de début.
flags sont optionnels et peuvent être les suivants (insensible à la casse) :
p : Les deux événements sont épinglés sur le même CPU (début et fin se
    produisent toujours sur le même CPU).
s : L'événement doit avoir une pile tracée avec lui (active le traçage
    de pile pour l'événement de début).
g : L'événement est global (pas associé à une tâche). pid_debut n'est
    pas applicable avec ce drapeau.

--stderr

Redirige la sortie vers stderr. La sortie de la commande exécutée n'est pas modifiée. Cela permet de regarder la commande s'exécuter et de sauvegarder la sortie du profil dans un autre fichier.

--verbose[=niveau]

Définit le niveau de journalisation. Les niveaux de journalisation supportés sont "none", "critical", "error", "warning", "info", "debug", "all" ou leurs identifiants "0", "1", "2", "3", "4", "5", "6". Définir le niveau de journalisation à une valeur spécifique active tous les journaux de ce niveau et de tous les niveaux précédents. Le niveau sera "info" par défaut s'il n'est pas spécifié. 
Exemple : active tous les journaux critiques, d'erreur et d'avertissement
trace-cmd profile --verbose=warning

Ce qui précède utilise -F pour suivre la tâche de veille (sleep). Il filtre uniquement les événements liés à la veille. Notez que pour suivre les forks, vous devez également inclure l'option -c.

D'autres tâches apparaîtront dans le profil si les événements font référence à plus d'une tâche (comme le font sched_switch et sched_wakeup. Les champs "prev_pid" et "next_pid" de sched_switch, et les champs "common_pid" et "pid" de sched_wakeup).

Les traces de pile sont attachées aux événements qui y sont liés.

En examinant la sortie ci-dessus :

Event: sched_switch:R (2) Total: 234559 Avg: 117279 Max: 129886 Min:104673

Le traçage de graphe de fonctions peut produire trop de surcharge car il se déclenche toujours (sans tracer) sur toutes les fonctions. Pour limiter les fonctions aux appels système uniquement (pas aux interruptions), ajoutez l'option suivante :

-l 'sys_*' -l 'SyS_*'

Pour désactiver complètement le traçage de graphe de fonctions, utilisez :

-p nop

Pour utiliser le traçage de fonction à la place (notez que cela n'enregistrera pas les timings, mais seulement le nombre de fois où une fonction est atteinte) :

-p function
