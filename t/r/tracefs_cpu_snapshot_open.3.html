Paquet: libtracefs

LIBTRACEFS(3) Manuel libtracefs LIBTRACEFS(3)

NOM

tracefs_cpu_open, tracefs_cpu_close, tracefs_cpu_alloc_fd, tracefs_cpu_free_fd, tracefs_cpu_snapshot_open - Ouverture de données trace_pipe_raw en lecture

SYNOPSIS

#include <tracefs.h>
struct tracefs_cpu *tracefs_cpu_open(struct tracefs_instance *instance,
                                     int cpu, bool nonblock);
void tracefs_cpu_close(struct tracefs_cpu *tcpu);
struct tracefs_cpu *tracefs_cpu_alloc_fd(int fd, int subbuf_size, bool nonblock);
void tracefs_cpu_free_fd(struct tracefs_cpu *tcpu);
struct tracefs_cpu *tracefs_cpu_snapshot_open(struct tracefs_instance *instance,
                                             int cpu, bool nonblock);

DESCRIPTION

Cet ensemble d'API peut être utilisé pour ouvrir les données brutes des fichiers trace_pipe_raw du système de fichiers tracefs afin de les lire avec les fonctions tracefs_cpu_read(3).

La fonction tracefs_cpu_open() crée un descripteur qui peut lire le fichier tracefs trace_pipe_raw pour un cpu donné dans une instance donnée. Si instance est NULL, le fichier trace_pipe_raw de niveau supérieur est utilisé.

La fonction tracefs_cpu_close() ferme tous les descripteurs de fichiers associés au trace_pipe_raw ouvert par tracefs_cpu_open().

La fonction tracefs_cpu_alloc_fd() créera un descripteur tracefs_cpu à partir d'un descripteur de fichier existant fd. Ceci est utile lorsqu'on se connecte à un socket ou à un pipe où l'autre extrémité fournit des données de traçage brutes dans le même format que le fichier trace_pipe_raw (comme dans le traçage invité vers hôte). L'appelant est responsable de déterminer la subbuf_size qui sera utilisée pour découper les sous-buffers lus à partir du descripteur de fichier. Le paramètre nonblock est traité de la même manière que le paramètre du même nom dans tracefs_cpu_open().

La fonction tracefs_cpu_free_fd() est utilisée pour libérer le descripteur renvoyé par tracefs_cpu_alloc_fd(). Elle effectue tout le nettoyage que tracefs_cpu_close() effectue, et pourrait également être utilisée pour libérer le descripteur créé par tracefs_cpu_alloc_fd(), mais elle fermera également le descripteur de fichier passé en argument. Notez que tracefs_cpu_free_fd() ne doit pas être utilisée sur le descripteur renvoyé par tracefs_cpu_open() car elle ne fermera pas le descripteur de fichier créé par celle-ci.

La fonction tracefs_cpu_snapshot_open() est similaire à tracefs_cpu_open(), à la différence qu'elle ouvre le buffer d'instantané (voir tracefs_snapshot_snap(3)). Le buffer d'instantané n'a pas d'écrivain ; il est uniquement créé par une action d'instantané qui échange le buffer circulaire actuel avec le buffer d'instantané. Le paramètre nonblock, lorsqu'il est faux, agit un peu différemment ici aussi. Les lectures ne sont pas affectées par le fichier "buffer_percent". Si le buffer d'instantané est vide, il bloquera jusqu'à ce qu'un nouvel instantané se produise.

VALEUR DE RETOUR

Les fonctions tracefs_cpu_open() et tracefs_cpu_snapshot_open() renvoient toutes deux un descripteur de type struct tracefs_cpu qui peut être utilisé par les autres fonctions, ou NULL en cas d'erreur.

La fonction tracefs_cpu_alloc_fd() renvoie un descripteur de type struct tracefs_cpu qui peut être utilisé par les fonctions liées à tracefs_cpu_read(3), où le descripteur lira le descripteur de fichier fd passé en argument.

EXEMPLE

Voir tracefs_cpu_read(3) pour un exemple.
