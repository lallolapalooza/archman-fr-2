TREE(1) Manuel des commandes générales TREE(1)

NOM

tree - liste le contenu des répertoires dans un format arborescent.

SYNTAXE

tree [-acdfghilnpqrstuvxACDFJQNSUX] [-L niveau [-R]] [-H [-]baseHREF] [-T titre] [-o nom_fichier] [-P motif] [-I motif] [--gitignore] [--gitfile[=]fichier] [--matchdirs] [--metafirst] [--ignore-case] [--nolinks] [--hintro[=]fichier] [--houtro[=]fichier] [--inodes] [--device] [--sort[=]nom] [--dirsfirst] [--filesfirst] [--filelimit[=]#] [--si] [--du] [--prune] [--charset[=]X] [--timefmt[=]format] [--fromfile] [--fromtabfile] [--fflinks] [--info] [--infofile[=]fichier] [--noreport] [--hyperlink] [--scheme[=]schéma] [--authority[=]nom_hôte] [--opt-toggle] [--version] [--help] [--] [répertoire ...]

DESCRIPTION

Tree est un programme de listage récursif de répertoires qui produit un listage de fichiers à indentation arborescente, colorisé à la manière de dircolors si la variable d'environnement LS_COLORS est définie et que la sortie est redirigée vers un terminal. Sans arguments, tree liste les fichiers du répertoire courant. Lorsque des arguments de répertoire sont donnés, tree liste tous les fichiers et/ou répertoires trouvés dans les répertoires donnés, chacun à son tour. Une fois le listage de tous les fichiers/répertoires terminés, tree renvoie le nombre total de fichiers et/ou de répertoires listés.

Par défaut, lorsqu'un lien symbolique est rencontré, le chemin vers lequel le lien symbolique pointe est affiché après le nom du lien sous la forme :


nom -> chemin_réel

Si l'option `-l' est donnée et que le lien symbolique pointe vers un répertoire existant, alors tree suivra le chemin du lien symbolique comme s'il s'agissait d'un répertoire réel.

OPTIONS

Tree comprend les options de ligne de commande suivantes :

OPTIONS DE LISTAGE

-a
Tous les fichiers sont affichés. Par défaut, tree n'affiche pas les fichiers cachés (ceux commençant par un point `.'). En aucun cas tree n'affiche les constructions du système de fichiers `.' (répertoire courant) et `..' (répertoire précédent).
-d
Lister uniquement les répertoires.
-l
Suit les liens symboliques s'ils pointent vers des répertoires, comme s'ils étaient des répertoires. Les liens symboliques qui entraînent une récursion sont évités lors de leur détection.
-f
Affiche le préfixe du chemin complet pour chaque fichier.
-x
Ne rester que sur le système de fichiers courant. Similaire à find -xdev.
-L niveau
Profondeur maximale d'affichage de l'arborescence du répertoire.
-R
Traverse récursivement l'arborescence tous les niveaux répertoires (voir l'option -L), et à chaque niveau, sort vers un fichier nommé 00Tree.html (similaire à -o).
-P motif
Lister uniquement les fichiers qui correspondent au motif de caractères génériques. Vous pouvez avoir plusieurs options -P. Note : vous devez utiliser l'option -a pour considérer également les fichiers commençant par un point `.' pour la correspondance. Les opérateurs de caractères génériques valides sont `*' (zéro ou plusieurs caractères quelconques), `**` (zéro ou plusieurs caractères quelconques ainsi que des / nuls, c'est-à-dire que /**/ peut correspondre à un seul /), `?' (un seul caractère quelconque), `[...]' (un seul caractère listé entre crochets (éventuellement - (tiret) pour une plage de caractères : ex: [A-Z]), et `[^...]' (un seul caractère non listé entre crochets) et `|' sépare les motifs alternatifs. Un '/' à la fin du motif correspond aux répertoires, mais pas aux fichiers.
-I motif
Ne pas lister les fichiers qui correspondent au motif de caractères génériques. Vous pouvez avoir plusieurs options -I. Voir -P ci-dessus pour des informations sur les motifs de caractères génériques.
--gitignore
Utilise les fichiers .gitignore de git pour filtrer les fichiers et répertoires. Utilise également $GIT_DIR/info/exclude s'il est présent.
--gitfile[=]fichier
Utilise fichier explicitement comme fichier .gitignore.
--ignore-case
Si un motif de correspondance est spécifié par l'option -P ou -I, cela provoquera la correspondance du motif sans tenir compte de la casse de chaque lettre.
--matchdirs
Si un motif de correspondance est spécifié par l'option -P, cela provoquera l'application du motif aux noms de répertoires (en plus des noms de fichiers). En cas de correspondance sur le nom du répertoire, la correspondance est désactivée pour le contenu du répertoire. Si l'option --prune est utilisée, les dossiers vides correspondant au motif ne seront pas élagués.
--metafirst
Affiche les informations de métadonnées au début de la ligne plutôt qu'après les lignes d'indentation.
--prune
Fait en sorte que tree élague les répertoires vides de la sortie, utile lorsqu'il est utilisé conjointement avec -P ou -I. Voir BOGUES ET NOTES ci-dessous pour plus d'informations sur cette option.
--info
Affiche les commentaires de fichiers trouvés dans les fichiers .info. Voir FICHIERS .INFO ci-dessous pour plus d'informations sur le format des fichiers .info.
--infofile[=]fichier
Utilise fichier explicitement comme fichier info.
--noreport
Omet l'impression du rapport de fichiers et de répertoires à la fin du listage de l'arbre.
--charset[=]jeu_de_caractères
Définit le jeu de caractères à utiliser lors de la génération de HTML et pour le dessin des lignes.
--filelimit[=]#
Ne pas descendre dans les répertoires qui contiennent plus de # entrées.
--timefmt[=]format
Affiche (implique -D) et formate la date selon la chaîne de format qui utilise la syntaxe de strftime(3).
-o nom_fichier
Redirige la sortie vers nom_fichier.

OPTIONS DE FICHIER

-q
Affiche les caractères non imprimables dans les noms de fichiers sous forme de points d'interrogation au lieu de la valeur par défaut.
-N
Affiche les caractères non imprimables tels quels au lieu de les échapper en octal.
-Q
Met les noms de fichiers entre guillemets doubles.
-p
Affiche le type de fichier et les permissions pour chaque fichier (comme avec ls -l).
-u
Affiche le nom d'utilisateur, ou l'UID # si aucun nom d'utilisateur n'est disponible, du fichier.
-g
Affiche le nom du groupe, ou le GID # si aucun nom de groupe n'est disponible, du fichier.
-s
Affiche la taille de chaque fichier en octets avec le nom.
-h
Affiche la taille de chaque fichier mais de manière plus lisible, par exemple en ajoutant une lettre de taille pour les kilo-octets (K), méga-octets (M), giga-octets (G), téra-octets (T), péta-octets (P) et exa-octets (E).
--si
Comme -h mais utilise les unités SI (puissances de 1000) au li

--du
Pour chaque répertoire, affiche sa taille comme l'accumulation des tailles de tous ses fichiers et sous-répertoires (et leurs fichiers, et ainsi de suite). La quantité totale d'espace utilisé est également indiquée dans le rapport final (comme la commande 'du -c'). Cette option nécessite que tree lise l'intégralité de l'arborescence du répertoire avant de l'émettre, voir BUGS AND NOTES ci-dessous. Implique -s.
-D
Affiche la date de la dernière modification ou, si -c est utilisé, la dernière date de changement d'état du fichier listé.
-F
Ajoute un '/' pour les répertoires, un '=' pour les fichiers socket, un '*' pour les fichiers exécutables, un '>' pour les portes (Solaris) et un '|' pour les FIFO, comme avec ls -F
--inodes
Affiche le numéro d'inode du fichier ou du répertoire
--device
Affiche le numéro de périphérique auquel le fichier ou le répertoire appartient

OPTIONS DE TRI

-v
Trie la sortie par version.
-t
Trie la sortie par la dernière heure de modification au lieu de l'ordre alphabétique.
-c
Trie la sortie par le dernier changement d'état au lieu de l'ordre alphabétique. Modifie l'option -D (si utilisée) pour afficher le dernier changement d'état au lieu de l'heure de modification.
-U
Ne pas trier. Liste les fichiers dans l'ordre du répertoire. Désactive --dirsfirst.
-r
Trie la sortie dans l'ordre inverse. C'est un méta-tri qui modifie les tris ci-dessus. Cette option est désactivée lorsque -U est utilisée.
--dirsfirst
Liste les répertoires avant les fichiers. C'est un méta-tri qui modifie les tris ci-dessus. Cette option est désactivée lorsque -U est utilisée.
--filesfirst
Liste les fichiers avant les répertoires. C'est un méta-tri qui modifie les tris ci-dessus. Cette option est désactivée lorsque -U est utilisée.
--sort[=]type
Trie la sortie par type au lieu du nom. Les valeurs possibles sont : ctime (-c), mtime (-t), size, version (-v) ou none (-U).

OPTIONS GRAPHIQUES

-i
Empêche tree d'afficher les lignes d'indentation, utile lorsqu'il est utilisé conjointement avec l'option -f. Supprime également autant d'espaces que possible lorsqu'il est utilisé avec les options -J ou -X.
-A
Active le hack graphique de lignes ANSI lors de l'affichage des lignes d'indentation.
-S
Active les graphiques de lignes CP437 (utile lors de l'utilisation des polices du mode console Linux). Cette option est maintenant équivalente à `--charset=IBM437' et pourrait être obsolète à terme.
-n
Désactive la coloration systématiquement, remplacé par l'option -C, cependant, remplace CLICOLOR_FORCE s'il est présent.
-C
Active la coloration systématiquement, en utilisant les couleurs par défaut intégrées si les variables d'environnement LS_COLORS ou TREE_COLORS ne sont pas définies. Utile pour coloriser la sortie vers un pipe.

OPTIONS XML/JSON/HTML/HYPERLIENS

-X
Active la sortie XML. Affiche l'arborescence du répertoire sous forme de fichier formaté XML.
-J
Active la sortie JSON. Affiche l'arborescence du répertoire sous forme de tableau formaté JSON.
-H [-]baseHREF
Active la sortie HTML, y compris les références HTTP. Utile pour les sites FTP. baseHREF donne l'emplacement FTP de base lors de l'utilisation de la sortie HTML. C'est-à-dire que le répertoire local peut être `/local/ftp/pub', mais il doit être référencé comme `ftp://hostname.organization.domain/pub' (baseHREF devrait être `ftp://hostname.organization.domain'). Si baseHREF commence par un tiret (-), alors le tiret est supprimé et indique que tree doit supprimer le premier nom de répertoire de l'URL href. Indice : n'utilisez pas de lignes ANSI avec cette option, et ne donnez pas plus d'un répertoire dans la liste des répertoires. Si vous souhaitez utiliser les couleurs via une feuille de style CSS, utilisez l'option -C en plus de cette option pour forcer la sortie couleur.
--hintro[=]fichier
Utilise fichier comme introduction HTML à la place de celle par défaut. Utilisez un fichier vide ou /dev/null pour éliminer l'introduction.
--houtro[=]fichier
Utilise fichier comme outro HTML à la place de celle par défaut. Utilisez un fichier vide ou /dev/null pour éliminer l'outro.
-T titre
Définit le titre et l'en-tête H1 en mode de sortie HTML.
--nolinks
Désactive les hyperliens dans la sortie HTML.
--hyperlink
Active les hyperliens de terminal OSC 8 pour les terminaux qui les supportent. Voir BUGS AND NOTES ci-dessous.
--scheme[=]schema
Définit le schéma utilisé dans les hyperliens OSC 8. Le schéma par défaut est 'file://'. Si le schéma omet le deux-points (:), alors :// sera ajouté au schéma.
--authority[=]hostname|authority
Définit l'autorité (nom d'hôte) à utiliser pour les hyperliens OSC 8. Par défaut, le nom d'hôte local de la machine tel que retourné par gethostname() est utilisé comme autorité. Un point (.) ou un ensemble de guillemets vides (""), sans '=', (c'est-à-dire la chaîne vide) peut être utilisé pour indiquer une autorité nulle.

OPTIONS D'ENTRÉE

--fromfile
Lit une liste de répertoires à partir d'un fichier plutôt qu'à partir du système de fichiers. Les chemins fournis sur la ligne de commande sont des fichiers à lire plutôt que des répertoires à rechercher. Le répertoire point (.) indique que tree doit lire les chemins depuis l'entrée standard. NOTE : ceci convient uniquement pour lire la sortie d'un programme tel que find, pas 'tree -fi' car les liens symboliques ne sont pas distingués des fichiers qui contiennent simplement ' -> ' comme partie du nom de fichier, sauf si l'option --fflinks est utilisée.
--fromtabfile
Comme --fromfile, tree lit une arborescence de répertoires à partir d'un fichier texte où les fichiers sont indentés par tabulation dans un format d'arbre pour indiquer le niveau d'imbrication du répertoire.
--fflinks
Traite les informations de liens symboliques trouvées dans un fichier, comme celles issues de la sortie de 'tree -fi --noreport'. Seule la première occurrence de la chaîne ' -> ' est utilisée pour indiquer la séparation entre le nom du fichier et le lien.

OPTIONS DIVERSES

--opt-toggle
Active la "bascule" d'option. Permet d'activer la capacité de basculer des options telles que -a, -h, etc. Utile à ajouter à un alias lorsque vous souhaitez désactiver des options activées dans l'alias.
--help
Affiche une liste d'utilisation détaillée.
--version
Affiche la version de tree.
--
Terminateur de traitement des options. Aucune autre option ne sera traitée après ceci.

FICHIERS .INFO

Les fichiers .info sont similaires aux fichiers .gitignore. Si un fichier .info est trouvé lors du balayage d'un répertoire, il est lu et ajouté à une pile d'informations .info. Chaque fichier est composé de commentaires (lignes commençant par des dièses (#)) ou de motifs génériques qui peuvent correspondre à un fichier par rapport au répertoire dans lequel le fichier .info est trouvé. Si un fichier correspond à un motif, le commentaire indenté par tabulation qui suit le motif est utilisé comme commentaire de fichier. Un commentaire est terminé par une ligne non indentée par tabulation. Plusieurs motifs, chacun sur une ligne, peuvent partager le même commentaire.

FICHIERS

/etc/DIR_COLORS Base de données système des couleurs.
~/.dircolors Base de données utilisateur des couleurs.
.gitignore Fichier d'exclusion Git
$GIT_DIR/info/exclude Liste d'exclusion globale des fichiers Git
.info Fichier de commentaires de fichier
/usr/share/finfo/global_info Fichier global de commentaires de fichier

ENVIRONNEMENT

LS_COLORS Informations de couleur créées par dircolors
TREE_COLORS Utilise ceci pour les informations de couleur au-dessus de LS_COLORS s'il est défini.
TREE_CHARSET Jeu de caractères que tree doit utiliser en mode HTML.
CLICOLOR Active la coloration même si TREE_COLORS ou LS_COLORS n'est pas défini.
CLICOLOR_FORCE Active systématiquement la coloration (équivalent à -C)
NO_COLOR Désactive la coloration (équivalent à -n) (voir https://no-color.org/)
LC_CTYPE Locale pour la sortie des noms de fichiers.
LC_TIME Locale pour la sortie de timefmt, voir strftime(3).
TZ Fuseau horaire pour la sortie de timefmt, voir strftime(3).
STDDATA_FD Active la fonctionnalité stddata, optionnellement définit le descripteur à utiliser.

BOGUES ET NOTES

L'option -P et -I par défaut ne supprime pas les répertoires "vides". Utilisez l'option --prune.

Les options -h et --si arrondissent à l'entier le plus proche, contrairement aux implémentations de ls qui arrondissent toujours à l'entier supérieur.

La suppression des fichiers et répertoires avec les options -I, -P et --filelimit entraînera des rapports de comptage de fichiers/répertoires incorrects.

Les options --prune et --du font que l'arbre accumule l'intégralité de l'arbre en mémoire avant de l'émettre. Pour les grands arbres de répertoires, cela peut entraîner un délai important dans la sortie et l'utilisation de grandes quantités de mémoire.

Le tampon d'expansion timefmt est limité à un nombre ridiculement grand de 255 caractères. La sortie de chaînes de temps plus longues que cela sera indéfinie, mais il est garanti qu'elle ne dépassera pas 255 caractères.

Les arbres XML/JSON ne sont pas colorés, ce qui est un peu dommage. L'utilitaire jq peut cependant coloriser le JSON, mais pas les noms de fichiers par type de fichier à la manière de LS_COLORS.

Les hyperliens OSC 8 peuvent être mal pris en charge par votre terminal. Pour ma version de Konsole, il est nécessaire de définir le schéma sur file: (sans //) et d'utiliser une autorité nulle. Il peut également être nécessaire de passer 3,5 heures à trouver l'option pour activer les hyperliens.

Probablement plus.

Depuis la version 2.0.0, sous Linux, tree tentera de produire automatiquement un arbre JSON compact sur le descripteur de fichier 3 (ce que j'appelle stddata), s'il est présent et que la variable d'environnement STDDATA_FD est définie ou définie sur une valeur de descripteur de fichier positive et non nulle à utiliser pour la sortie. On espère qu'un jour un meilleur shell Linux/Unix pourra profiter de cette fonctionnalité, bien que le BSON serait probablement un meilleur format pour cela.
