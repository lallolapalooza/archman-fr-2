truncate(2) Manuel des appels système truncate(2)

NOM

truncate, ftruncate - tronquer un fichier à une longueur spécifiée

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int truncate(const char *path, off_t length);
int ftruncate(int fd, off_t length);
Conditions de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

truncate():

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.12 : */ _POSIX_C_SOURCE >= 200809L
        || /* glibc <= 2.19 : */ _BSD_SOURCE

ftruncate():

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.3.5 : */ _POSIX_C_SOURCE >= 200112L
        || /* glibc <= 2.19 : */ _BSD_SOURCE

DESCRIPTION

Les fonctions truncate() et ftruncate() tronquent le fichier régulier nommé par path ou référencé par fd à une taille de précisément length octets.

Si le fichier était précédemment plus grand que cette taille, les données supplémentaires sont perdues. Si le fichier était précédemment plus court, il est étendu, et la partie étendue sera lue comme des octets nuls ('\0').

Le décalage du fichier n'est pas modifié.

Si la taille a été modifiée, alors les champs st_ctime et st_mtime (respectivement, temps du dernier changement de statut et temps de la dernière modification ; voir inode(7)) du fichier sont mis à jour, et les bits de mode set-user-ID et set-group-ID peuvent être effacés.

Avec ftruncate(), le fichier doit être ouvert en écriture ; avec truncate(), le fichier doit être accessible en écriture.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

Pour truncate():

EACCES
L'autorisation de recherche est refusée pour un composant du préfixe du chemin, ou le fichier nommé n'est pas accessible en écriture par l'utilisateur. (Voir aussi path_resolution(7).)
EFAULT
L'argument path pointe en dehors de l'espace d'adressage alloué au processus.
EFBIG
L'argument length est supérieur à la taille maximale du fichier. (XSI)
EINTR
Pendant le blocage en attente de complétion, l'appel a été interrompu par un gestionnaire de signaux ; voir fcntl(2) et signal(7).
EINVAL
L'argument length est négatif ou supérieur à la taille maximale du fichier.
EIO
Une erreur d'E/S s'est produite lors de la mise à jour de l'inode.
EISDIR
Le fichier nommé est un répertoire.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la traduction du nom de chemin.
ENAMETOOLONG
Un composant d'un nom de chemin a dépassé 255 caractères, ou un nom de chemin entier a dépassé 1023 caractères.
ENOENT
Le fichier nommé n'existe pas.
ENOTDIR
Un composant du préfixe du chemin n'est pas un répertoire.
EPERM
Le système de fichiers sous-jacent ne prend pas en charge l'extension d'un fichier au-delà de sa taille actuelle.
EPERM
L'opération a été empêchée par un scellage de fichier ; voir fcntl(2).
EROFS
Le fichier nommé réside sur un système de fichiers en lecture seule.
ETXTBSY
Le fichier est un fichier exécutable en cours d'exécution.

Pour ftruncate(), les mêmes erreurs s'appliquent, mais au lieu de ce qui peut être erroné pour path, nous avons maintenant ce qui peut être erroné pour le descripteur de fichier, fd:

EBADF
fd n'est pas un descripteur de fichier valide.
EBADF ou EINVAL
fd n'est pas ouvert en écriture.
EINVAL
fd ne référence pas un fichier régulier ou un objet de mémoire partagée POSIX.
EINVAL ou EBADF
Le descripteur de fichier fd n'est pas ouvert en écriture. POSIX autorise, et les applications portables doivent gérer, l'une ou l'autre de ces erreurs pour ce cas. (Linux produit EINVAL.)

VERSIONS

Les détails décrits ci-dessus concernent les systèmes conformes XSI. Pour les systèmes non conformes XSI, la norme POSIX autorise deux comportements pour ftruncate() lorsque length dépasse la longueur du fichier (notez que truncate() n'est pas du tout spécifié dans un tel environnement) : soit retourner une erreur, soit étendre le fichier. Comme la plupart des implémentations UNIX, Linux suit l'exigence XSI lorsqu'il traite des systèmes de fichiers natifs. Cependant, certains systèmes de fichiers non natifs ne permettent pas à truncate() et ftruncate() d'être utilisés pour étendre un fichier au-delà de sa longueur actuelle : un exemple notable sur Linux est VFAT.

Sur certaines architectures 32 bits, la signature de l'appel pour ces appels système diffère, pour les raisons décrites dans syscall(2).

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4, 4.2BSD.

Les appels système truncate() et ftruncate() originaux de Linux n'étaient pas conçus pour gérer les décalages de fichiers volumineux. Par conséquent, Linux 2.4 a ajouté les appels système truncate64() et ftruncate64() qui gèrent les fichiers volumineux. Cependant, ces détails peuvent être ignorés par les applications utilisant glibc, dont les fonctions d'encapsulation utilisent de manière transparente les appels système plus récents lorsqu'ils sont disponibles.

NOTES

ftruncate() peut également être utilisé pour définir la taille d'un objet de mémoire partagée POSIX ; voir shm_open(3).

BOGUES

Un bogue dans les fichiers d'en-tête de glibc 2.12 faisait que la valeur minimale de _POSIX_C_SOURCE requise pour exposer la déclaration de ftruncate() était 200809L au lieu de 200112L. Ceci a été corrigé dans les versions ultérieures de glibc.

VOIR AUSSI

truncate(1), open(2), stat(2), path_resolution(7)
