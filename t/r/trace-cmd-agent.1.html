NOM

trace-cmd-agent - S'exécute comme agent sur une machine (à contrôler par une autre machine)

SYNOPIS

trace-cmd agent [OPTIONS]

DESCRIPTION

L'agent trace-cmd(1) écoute via un vsocket (pour les machines virtuelles) ou un port TCP pour les connexions afin de contrôler le traçage de la machine. L'agent démarrera alors le traçage sur la machine locale et transmettra les données à la connexion de contrôle.

OPTIONS

-N client

Écoute sur TCP au lieu d'un vsocket. Doit passer le nom d'hôte ou l'adresse IP d'un client pour autoriser la connexion. Il ne se connectera qu'au client spécifié. Notez que tout processus sur ce client peut contrôler l'agent. 
*Ceci est un réglage très peu sûr. À n'utiliser que sur un réseau de confiance*
*À n'utiliser que si la machine cliente est totalement fiable*

-p port

Cette option spécifie le port sur lequel écouter.

-D

Cette option fait passer trace-cmd agent en mode démon et l'exécute en arrière-plan.

-P cid

Permet à un agent d'agir également comme serveur proxy, où il peut être exécuté sur un hôte et se connecter à un invité. cid est l'identifiant de contexte (voir vsock(7)) du client (par exemple, une machine virtuelle invitée) auquel il autorisera la connexion.

--verbose[=level]

Définit le niveau de journalisation. Les niveaux de journalisation supportés sont "none", "critical", "error", "warning", "info", "debug", "all" ou leurs identifiants "0", "1", "2", "3", "4", "5", "6". Le réglage du niveau de journalisation à une valeur spécifique active tous les journaux de ce niveau et des niveaux précédents. Le niveau sera par défaut "info" si aucun n'est spécifié. 
Exemple : activer tous les journaux critiques, d'erreur et d'avertissement
trace-cmd listen --verbose=warning
