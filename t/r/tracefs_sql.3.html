NOM

tracefs_sql - Créer un événement synthétique via une instruction SQL

SYNTAXE

#include <tracefs.h>
struct tracefs_synth *tracefs_sql(struct tep_handle *tep, const char *name,
                                        const char *sql_buffer, char **err);

DESCRIPTION

Les événements synthétiques sont des événements créés dynamiquement qui lient deux événements existants via une ou plusieurs correspondances de champs entre les deux événements. Ils peuvent être utilisés pour trouver la latence entre les événements, ou simplement pour transmettre les champs du premier événement au second événement afin de les afficher comme un seul événement.

L'interface du noyau Linux pour créer des événements synthétiques est complexe, et il faut une meilleure façon de créer des événements synthétiques qui soit facile à comprendre via la technologie existante.

Si l'on considère chaque événement comme une table, où les champs sont les colonnes de la table et chaque instance de l'événement comme une ligne, on peut comprendre comment SQL peut être utilisé pour lier deux événements et former un autre événement (une autre table). En utilisant la syntaxe SQL SELECT FROM JOIN ON [ WHERE ], un événement synthétique peut être facilement créé à partir de deux événements différents.

Pour des requêtes SQL simples permettant de créer un histogramme au lieu d'un événement synthétique, voir HISTOGRAMMES ci-dessous.

tracefs_sql() prend un gestionnaire tep (Voir tep_local_events(3)) qui est utilisé pour vérifier les événements dans l'expression sql_buffer. Le name est le nom de l'événement synthétique à créer. Si err pointe vers une adresse de chaîne, elle sera remplie d'un message détaillé sur tout type d'erreur d'analyse syntaxique, y compris les champs qui n'appartiennent pas à un événement, ou si les événements ou les champs ne sont pas correctement comparés.

L'exemple de programme ci-dessous est un analyseur entièrement fonctionnel qui créera un événement synthétique à partir d'une syntaxe SQL passée via la ligne de commande ou un fichier.

Le format SQL est le suivant :

SELECT <champs> FROM <événement-de-début> JOIN <événement-de-fin> ON <champs-correspondants> WHERE <filtre>

Notez que, bien que les exemples montrent les commandes SQL en majuscules, elles ne sont pas obligatoires. C'est-à-dire que vous pouvez utiliser "SELECT" ou "select" ou "sElEct".

Par exemple :

SELECT syscalls.sys_enter_read.fd, syscalls.sys_exit_read.ret FROM syscalls.sys_enter_read
   JOIN syscalls.sys_exit_read
   ON syscalls.sys_enter_read.common_pid = syscalls.sys_exit_write.common_pid

Créera un événement synthétique avec les champs :

u64 fd; s64 ret;

Parce que la fonction prend un gestionnaire tep, et que généralement tous les noms d'événements sont uniques, vous pouvez omettre le nom du système (groupe) de l'événement, et tracefs_sql() le découvrira pour vous.

C'est-à-dire que l'instruction ci-dessus fonctionnerait avec :

SELECT sys_enter_read.fd, sys_exit_read.ret FROM sys_enter_read JOIN sys_exit_read
   ON sys_enter_read.common_pid = sys_exit_write.common_pid

Le mot-clé AS peut être utilisé pour nommer les champs ainsi que pour donner un alias aux événements, de sorte que ce qui précède peut être encore simplifié comme suit :

SELECT start.fd, end.ret FROM sys_enter_read AS start JOIN sys_exit_read AS end ON start.common_pid = end.common_pid

Ce qui précède aliaste sys_enter_read en start et sys_exit_read en end et utilise ces alias pour faire référence à l'événement tout au long de l'instruction.

L'utilisation du mot-clé AS dans la partie sélection de l'instruction SQL définira comment ces champs seront nommés dans l'événement synthétique.

SELECT start.fd AS filed, end.ret AS return FROM sys_enter_read AS start JOIN sys_exit_read AS end
   ON start.common_pid = end.common_pid

Ce qui précède étiquette le fd de start comme filed et le ret de end comme return, où l'événement synthétique créé aura maintenant les champs :

u64 filed; s64 return;

Les champs peuvent également être calculés avec des résultats transmis à l'événement synthétique :

select start.truesize, end.len, (start.truesize - end.len) as diff from napi_gro_receive_entry as start
   JOIN netif_receive_skb as end ON start.skbaddr = end.skbaddr

Ce qui montrerait la truesize de l'événement napi_gro_receive_entry, la longueur réelle len du contenu, montrée par netif_receive_skb, et la différence entre les deux, exprimée par le champ diff.

Le code prend également en charge l'enregistrement des horodatages à l'un ou l'autre des événements, et l'exécution de calculs sur ceux-ci. Pour la latence de réveil, vous avez :

select start.pid, (end.TIMESTAMP_USECS - start.TIMESTAMP_USECS) as lat from sched_waking as start
   JOIN sched_switch as end ON start.pid = end.next_pid

Ce qui précède créera un événement synthétique qui enregistre le pid de la tâche qui est réveillée, et la différence de temps entre l'événement sched_waking et l'événement sched_switch. TIMESTAMP_USECS tronquera le temps à la microseconde, car l'horodatage généralement enregistré dans le tampon de traçage a une résolution en nanosecondes. Si vous ne voulez pas cette troncature, utilisez TIMESTAMP à la place de TIMESTAMP_USECS.

Parce que c'est très courant d'avoir :

   (end.TIMESTAMP_USECS - start.TIMESTAMP_USECS)

Ce qui précède peut être représenté par TIMESTAMP_DELTA_USECS ou si les nanosecondes sont acceptables, vous pouvez utiliser TIMESTAMP_DELTA. C'est-à-dire que la sélection précédente peut également être représentée par :

select start.pid, TIMESTAMP_DELTA_USECS as lat from sched_waking as start JOIN sched_switch as end ON start.pid = end.next_pid

Enfin, la clause WHERE peut être ajoutée, ce qui vous permettra d'ajouter des filtres sur l'un ou l'autre des événements.

select start.pid, (end.TIMESTAMP_USECS - start.TIMESTAMP_USECS) as lat from sched_waking as start
   JOIN sched_switch as end ON start.pid = end.next_pid
   WHERE start.prio < 100 && (!(end.prev_pid < 1 || end.prev_prio > 100) || end.prev_pid == 0)

NOTE

Bien que les deux événements puissent être utilisés ensemble dans la clause WHERE, ils ne doivent pas être mélangés en dehors des instructions "&&" les plus externes. Vous ne pouvez pas utiliser OR (||) pour combiner les événements, où un filtre d'un événement est OR'd à un filtre de l'autre événement. Cela n'a pas de sens, car l'événement synthétique nécessite que les deux événements se produisent pour être enregistrés. Si l'un est filtré, l'événement synthétique ne s'exécute pas.

select start.pid, (end.TIMESTAMP_USECS - start.TIMESTAMP_USECS) as lat from sched_waking as start
   JOIN sched_switch as end ON start.pid = end.next_pid
   WHERE start.prio < 100 && end.prev_prio < 100

Ce qui précède est valide.

Alors que ce qui suit ne l'est pas.

select start.pid, (end.TIMESTAMP_USECS - start.TIMESTAMP_USECS) as lat from sched_waking as start
   JOIN sched_switch as end ON start.pid = end.next_pid
   WHERE start.prio < 100 || end.prev_prio < 100

Si le noyau le prend en charge, vous pouvez passer une trace de pile entre les événements.

select start.prev_pid as pid, (end.TIMESTAMP_USECS - start.TIMESTAMP_USECS) as delta, start.STACKTRACE as stack
   FROM sched_switch as start JOIN sched_switch as end ON start.prev_pid = end.next_pid
   WHERE start.prev_state == 2

Ce qui précède enregistrera une trace de pile lorsqu'une tâche est dans l'état UNINTERRUPTIBLE (bloqué), et déclenchera l'événement synthétique lorsqu'elle sera à nouveau planifiée, enregistrant la différence de temps pendant laquelle elle était bloquée. Il enregistrera la trace de pile de l'endroit où elle se trouvait lorsqu'elle a été retirée de la planification, ainsi que la delta.

MOTS-CLÉS EN TANT QUE CHAMPS D'ÉVÉNEMENT

Dans certains cas, un événement peut avoir un mot-clé. Par exemple, regcache_drop_region a "from" comme champ et ce qui suit ne fonctionnera pas :

  select from from regcache_drop_region

Dans de tels cas, ajoutez une barre oblique inverse au champ conflit, et cela indiquera à l'analyseur que "from" est un champ et non un mot-clé :

  select \from from regcache_drop_region

HISTOGRAMMES

Des instructions SQL simples sans JOIN ON

DESCRIPTION

The tracefs_sql function is used to convert an SQL-like query language into a synthetic event definition that can be used by libtracefs to capture events. This function parses the given buffer, which should be a string containing the SQL-like command, and creates a synthetic event structure based on it. The name parameter specifies the name of the synthetic event, and tep is a handle to the trace event parser. The trace_dir parameter allows specifying a custom tracefs mount point.

The SQL-like language supports filtering, joining, and transforming event data. The tracefs_sql function is the primary way to define complex event capturing rules for libtracefs. The generated synthetic event can be a simple event or a histogram.

When generating a histogram, the tracefs_sql function returns a synthetic event descriptor that can be further processed to retrieve histogram-specific information. The tracefs_synth_get_start_hist(3) function can be used to obtain the struct tracefs_hist descriptor from the returned synthetic event descriptor when a histogram is created.

To utilize the histogram types (see xxx), the CAST command of SQL can be used.

That is:

  select CAST(common_pid AS comm), CAST(id AS syscall) FROM sys_enter

Which produces:

Note, string fields may not be cast.

The possible types to cast to are:

HEX - convert the value to use hex and not decimal

SYM - convert a pointer to symbolic (kallsyms values)

SYM-OFFSET - convert a pointer to symbolic and include the offset.

SYSCALL - convert the number to the mapped system call name

EXECNAME or COMM - can only be used with the common_pid field. Will show the task name of the process.

LOG or LOG2 - bucket the key values in a log 2 values (1, 2, 3-4, 5-8, 9-16, 17-32, ...)

The above fields are not case sensitive, and "LOG2" works as good as "log".

A special CAST to COUNTER or COUNTER will make the field a value and not a key. For example:

  SELECT common_pid, CAST(bytes_req AS _COUNTER_) FROM kmalloc

Which will create

RETURN VALUE

Returns 0 on success and -1 on failure. On failure, if err is defined, it will be allocated to hold a detailed description of what went wrong if it the error was caused by a parsing error, or that an event, field does not exist or is not compatible with what it was combined with.

CREATE A TOOL

The below example is a functional program that can be used to parse SQL commands into synthetic events.

   man tracefs_sql | sed -ne '/^EXAMPLE/,/FILES/ { /EXAMPLE/d ; /FILES/d ; p}' > sqlhist.c
   gcc -o sqlhist sqlhist.c `pkg-config --cflags --libs libtracefs`

Then you can run the above examples:

  sudo ./sqlhist 'select start.pid, (end.TIMESTAMP_USECS - start.TIMESTAMP_USECS) as lat from sched_waking as start
                  JOIN sched_switch as end ON start.pid = end.next_pid
                  WHERE start.prio < 100 || end.prev_prio < 100'

EXAMPLE

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <tracefs.h>
static void usage(char **argv)
{
        fprintf(stderr, "usage: %s [-ed][-n name][-s][-S fields][-m var][-c var][-T][-t dir][-f file | sql-command-line]\n"
                "  -n name - name of synthetic event 'Anonymous' if left off\n"
                "  -t dir - use dir instead of /sys/kernel/tracing\n"
                "  -e - execute the commands to create the synthetic event\n"
                "  -m - trigger the action when var is a new max.\n"
                "  -c - trigger the action when var changes.\n"
                "  -s - used with -m or -c to do a snapshot of the tracing buffer\n"
                "  -S - used with -m or -c to save fields of the end event (comma deliminated)\n"
                "  -T - used with -m or -c to do both a snapshot and a trace\n"
                "  -f file - read sql lines from file otherwise from the command line\n"
                "            if file is '-' then read from standard input.\n",
                argv[0]);
        exit(-1);
}
enum action {
        ACTION_DEFAULT          = 0,
        ACTION_SNAPSHOT         = (1 << 0),
        ACTION_TRACE            = (1 << 1),
        ACTION_SAVE             = (1 << 2),
        ACTION_MAX              = (1 << 3),
        ACTION_CHANGE           = (1 << 4),
};
#define ACTIONS ((ACTION_MAX - 1))
static int do_sql(const char *instance_name,
                  const char *buffer, const char *name, const char *var,
                  const char *trace_dir, bool execute, int action,
                  char **save_fields)
{
        struct tracefs_synth *synth;
        struct tep_handle *tep;
        struct trace_seq seq;
        enum tracefs_synth_handler handler;
        char *err;
        int ret;
        if ((action & ACTIONS) && !var) {
                fprintf(stderr, "Error: -s, -S and -T not supported without -m or -c");
                exit(-1);
        }
        if (!name)
                name = "Anonymous";
        trace_seq_init(&seq);
        tep = tracefs_local_events(trace_dir);
        if (!tep) {
                if (!trace_dir)
                        trace_dir = "tracefs directory";
                perror(trace_dir);
                exit(-1);
        }
        synth = tracefs_sql(tep, name, buffer, &err);
        if (!synth) {
                perror("Failed creating synthetic event!");
                if (err)
                        fprintf(stderr, "%s", err);
                free(err);
                exit(-1);
        }
        if (tracefs_synth_complete(synth)) {
                if (var) {
                        if (action & ACTION_MAX)
                                handler = TRACEFS_SYNTH_HANDLE_MAX;
                        else
                                handler = TRACEFS_SYNTH_HANDLE_CHANGE;
                        if (action & ACTION_SAVE) {
                                ret = tracefs_synth_save(synth, handler, var, save_fields);
                                if (ret < 0) {
                                        err = "adding save";
                                        goto failed_action;
                                }
                        }
                        if (action & ACTION_TRACE) {
                                /*
                                 * By doing the trace before snapshot, it will be included
                                 * in the snapshot.
                                 */
                                ret = tracefs_synth_trace(synth, handler, var);
                                if (ret < 0) {
                                        err = "adding trace";
                                        goto failed_action;
                                }
                        }
                        if (action & ACTION_SNAPSHOT) {
                                ret = tracefs_synth_snapshot(synth, handler, var);
                                if (ret < 0) {
                                        err = "adding snapshot";
 failed_action:
                                        perror(err);
                                        if (errno == ENODEV)
                                                fprintf(stderr, "ERROR: '%s' is not a variable\n",
                                                        var);
                                        exit(-1);
                                }
                        }
                }
                tracefs_synth_echo_cmd(&seq, synth);
                if (execute) {
                        ret = tracefs_synth_create(synth);
                        if (ret < 0) {
                                fprintf(stderr, "%s\n", tracefs_error_last(NULL));
                                exit(-1);
                        }
                }
        } else {
                struct tracefs_instance *instance = NULL;
                struct tracefs_hist *hist;
                hist = tracefs_synth_get_start_hist(synth);
                if (!hist) {
                        perror("get_start_hist");
                        exit(-1);
                }
                if (instance_name) {
                        if (execute)
                                instance = tracefs_instance_create(instance_name);
                        else
                                instance = tracefs_instance_alloc(trace_dir,
                                                                  instance_name);
                        if (!instance) {
                                perror("Failed to create instance");
                                exit(-1);
                        }
                }
                tracefs_hist_echo_cmd(&seq, instance, hist, 0);
                if (execute) {
                        ret = tracefs_hist_start(instance, hist);
                        if (ret < 0) {
                                fprintf(stderr, "%s\n", tracefs_error_last(instance));
                                exit(-1);
                        }
                }
        }
        tracefs_synth_free(synth);
        trace_seq_do_printf(&seq);
        trace_seq_destroy(&seq);
        return 0;
}
int main (int argc, char **argv)
{
        char *trace_dir = NULL;
        char *buffer = NULL;
        char buf[BUFSIZ];
        int buffer_size = 0;
        const char *file = NULL;
        const char *instance = NULL;
        bool execute = false;
        char **save_fields = NULL;
        const char *nam
e; const char *var; int action = 0; char *tok; FILE *fp; size_t r; int c; int i; for (;;) { c = getopt(argc, argv, "ht:f:en:m:c:sS:TB:"); if (c == -1) break; switch(c) { case 'h': usage(argv); case 't': trace_dir = optarg; break; case 'f': file = optarg; break; case 'e': execute = true; break; case 'm': action |= ACTION_MAX; var = optarg; break; case 'c': action |= ACTION_CHANGE; var = optarg; break; case 's': action |= ACTION_SNAPSHOT; break; case 'S': action |= ACTION_SAVE; tok = strtok(optarg, ","); while (tok) { save_fields = tracefs_list_add(save_fields, tok); tok = strtok(NULL, ","); } if (!save_fields) { perror(optarg); exit(-1); } break; case 'T': action |= ACTION_TRACE | ACTION_SNAPSHOT; break; case 'B': instance = optarg; break; case 'n': name = optarg; break; } } if ((action & (ACTION_MAX|ACTION_CHANGE)) == (ACTION_MAX|ACTION_CHANGE)) { fprintf(stderr, "Impossible d'utiliser -m et -c ensemble\n"); exit(-1); } if (file) { if (!strcmp(file, "-")) fp = stdin; else fp = fopen(file, "r"); if (!fp) { perror(file); exit(-1); } while ((r = fread(buf, 1, BUFSIZ, fp)) > 0) { buffer = realloc(buffer, buffer_size + r + 1); strncpy(buffer + buffer_size, buf, r); buffer_size += r; } fclose(fp); if (buffer_size) buffer[buffer_size] = '\0'; } else if (argc == optind) { usage(argv); } else { for (i = optind; i < argc; i++) { r = strlen(argv[i]); buffer = realloc(buffer, buffer_size + r + 2); if (i != optind) buffer[buffer_size++] = ' '; strcpy(buffer + buffer_size, argv[i]); buffer_size += r; } } do_sql(instance, buffer, name, var, trace_dir, execute, action, save_fields); free(buffer); return 0; }
