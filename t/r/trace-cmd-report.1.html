NOM

trace-cmd-report - affiche en ASCII un trace créé par trace-cmd record

SYNTAXE

trace-cmd report [OPTIONS] [fichier-entree [fichier-entree ...]]

DESCRIPTION

La commande report de trace-cmd(1) affichera un rapport lisible par l'homme d'une trace créée par trace-cmd record.

OPTIONS

-i fichier-entree

Par défaut, trace-cmd report lira le fichier trace.dat. Mais l'option -i ouvrira le fichier-entree spécifié à la place. Notez que le fichier d'entrée peut également être spécifié comme dernier élément de la ligne de commande.

-e

Affiche l'endianness du fichier. trace-cmd report est assez intelligent pour pouvoir lire des fichiers big-endian sur des machines little-endian, et vice versa.

-f

Affiche la liste de toutes les fonctions qui ont été mappées dans le fichier trace.dat. Notez que cette liste peut contenir des fonctions qui n'apparaissent peut-être pas dans la trace, car c'est la liste des mappings pour traduire les adresses de fonctions en noms de fonctions.

-P

Affiche la liste des données "trace_printk()". Les points de données brutes de la trace pointent vers des pointeurs statiques dans le noyau. Ceci doit être stocké dans le fichier trace.dat.

-E

Liste les événements possibles dans le fichier (mais cette liste n'est pas nécessairement la liste des événements dans le fichier).

--events

Liste les formats d'événements qui sont stockés dans le fichier trace.dat.

--event regex

Imprime les événements qui correspondent à la regex donnée. Si deux-points sont spécifiés, alors les caractères avant les deux-points seront utilisés pour faire correspondre le système et les caractères après les deux-points correspondront à l'événement. 
trace-cmd report --event sys:read
Ce qui précède ne correspondra qu'aux événements où le nom du système
contient "sys" et le nom de l'événement contient "read".
trace-cmd report --event read
Ce qui précède correspondra à tous les événements contenant "read" dans leur
nom. Il peut également lister tous les événements d'un système contenant
"read".

--check-events

Analyse les chaînes de format d'événements qui sont stockées dans le fichier trace.dat et renvoie si les formats peuvent être analysés correctement. Il chargera les plugins sauf si -N est spécifié.

-t

Imprime l'horodatage complet. Les horodatages dans le fichier de données sont généralement enregistrés à la nanoseconde. Mais l'affichage par défaut de l'horodatage n'est qu'à la microseconde. Pour voir l'horodatage complet, ajoutez l'option -t.

-F filtre

Ajoute un filtre pour limiter les événements affichés. Les filtres définis après un fichier d'entrée (spécifié avec -i) ne s'appliquent qu'à ce fichier d'entrée. Les filtres fournis avant tout fichier d'entrée sont considérés comme globaux et s'appliquent à tous les fichiers d'entrée. 
Le format du filtre est :
    <evenements> ':' <filtre>
    <evenements> = SYSTEM'/'EVENT  | SYSTEM | EVENT | <evenements> ',' <evenements>
    <filtre> = CHAMP_EVENEMENT <op> <valeur> | <filtre> '&&' <filtre> |
               <filtre> '||' <filtre> | '(' <filtre> ')' | '!' <filtre>
    <op> = '==' | '!=' | '>=' | '<=' | '>' | '<' | '&' | '|' | '^' |
           '+' | '-' | '*' | '/' | '%'
    <valeur> = NUM | CHAINE | CHAMP_EVENEMENT
SYSTEM est le nom du système sur lequel filtrer. Si l'EVENT est omis,
alors il s'applique à tous les événements sous le SYSTEM. Si une seule chaîne
est utilisée sans le '/' pour délimiter entre SYSTEM et EVENT, alors le filtre
sera appliqué à tous les systèmes et événements qui correspondent à la chaîne
donnée.
Les espaces blancs sont ignorés, de sorte que "sched:next_pid==123" est
équivalent à "sched : next_pid == 123".
CHAINE est définie avec des guillemets simples ou doubles (le guillemet
simple doit se terminer par un guillemet simple, et le double par un double).
Les espaces blancs à l'intérieur des guillemets ne sont pas ignorés.
La représentation d'un SYSTEM ou d'un EVENT peut également être une expression
régulière telle que définie par regcomp(3).
CHAMP_EVENEMENT est le nom du champ d'un événement sur lequel on filtre.
Si l'événement ne contient pas le CHAMP_EVENEMENT, cette partie de l'équation
sera considérée comme fausse.
    -F 'sched : bogus == 1 || common_pid == 2'
Le "bogus == 1" sera toujours évalué à FAUX car aucun événement n'a de champ
appelé "bogus", mais le "common_pid == 2" sera toujours évalué car tous
les événements ont le champ "common_pid". Tout événement "sched" qui a été
tracé par le processus avec le PID de 2 sera affiché.
Notez que le CHAMP_EVENEMENT est le nom du champ tel qu'affiché par le format
d'un événement (tel qu'affiché avec *--events*), et non ce qui est trouvé dans
la sortie. Si la sortie affiche "ID:foo" mais que le champ auquel "foo"
appartient s'appelait "name" dans le format de l'événement, alors "name" doit
être utilisé dans le filtre. Il en va de même pour les valeurs. Si la valeur
affichée est convertie en symbole de chaîne, le filtre vérifie la valeur
d'origine et non la valeur affichée. Par exemple, pour filtrer toutes les
tâches qui étaient dans l'état de fonctionnement lors d'un changement de contexte
:
    -F 'sched/sched_switch : prev_state==0'
Bien que la sortie affiche 'R', avoir 'prev_stat=="R"' ne fonctionnera pas.
Note : Vous pouvez également spécifier 'COMM' comme CHAMP_EVENEMENT. Cela
utilisera le nom de la tâche (ou comm) de l'enregistrement pour comparer. Par
exemple, pour exclure toutes les tâches "trace-cmd" :
    -F '.*:COMM != "trace-cmd"'

-I

Ne pas imprimer les événements où le drapeau de latence HARDIRQ est défini. Cela filtrera la plupart des événements provenant du contexte d'interruption. Notez que cela peut ne pas filtrer les fonctions tracées qui sont dans le contexte d'interruption mais qui ont été appelées avant que le drapeau "in interrupt" du noyau ne soit défini.

-S

Ne pas imprimer les événements où le drapeau de latence SOFTIRQ est défini. Cela filtrera la plupart des événements provenant du contexte d'interruption douce.

-v

Cela fait que les filtres suivants de -F filtrent les événements correspondants.
    -v -F 'sched/sched_switch : prev_state == 0'
N'affichera aucun événement sched_switch ayant un prev_state de 0. La
suppression de *-v* n'affichera que ces événements.

-T

Teste les filtres de -F. Après le traitement d'une chaîne de filtre, le filtre résultant sera affiché pour chaque événement. Ceci est utile pour utiliser un filtre pour plus d'un événement où un champ peut ne pas exister dans tous les événements. Il peut également être utilisé pour s'assurer qu'il n'y a pas de noms de champs d'événement mal orthographiés, car ils seront simplement ignorés. -T est ignoré si -F n'est pas spécifié.

-V

Affiche des messages détaillés (voir --verbose mais uniquement pour les nombres)

-L

Ne chargera pas les plugins à l'échelle du système. Il charge "local uniquement". C'est ce qu'il trouve dans le répertoire ~/.trace-cmd/plugins.

-N

Ne chargera aucun plugin.

-n evenement-re

Cela fera que tous les événements qui correspondent à l'option ignoreront tout gestionnaire enregistré (par les plugins) pour imprimer l'événement. L'événement normal sera imprimé à la place. Le evenement-re est une expression régulière telle que définie par regcomp(3).

--profile

Avec l'option --profile, "trace-cmd report" traitera tous les événements d'abord, puis affichera un format indiquant où les tâches ont passé leur temps dans le noyau, ainsi que là où elles sont le plus bloquées, et où les latences de réveil se situent. 
Voir trace-cmd-profile(1) pour plus de détails et d'exemples.

-G

Définit les événements d'interruption (douces et dures) comme globaux (associés au CPU plutôt qu'aux tâches). Ne fonctionne que pour --profile.

-H hooks-evenement

Ajoute des correspondances d'événements personnalisées

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

g pour connecter deux événements quelconques ensemble. 
Voir trace-cmd-profile(1) pour le format.

-R

Cela affichera les événements au format "brut". C'est-à-dire qu'il ignorera le format d'impression de l'événement et affichera simplement le contenu de chaque champ.

-r event-re

Cela amènera tous les événements qui correspondent à l'option à imprimer ses champs bruts. Le event-re est une expression régulière telle que définie par regcomp(3).

-l

Ceci ajoute un format de "sortie de latence". Des informations sur les interruptions désactivées, les soft irq désactivés, le drapeau "need_resched" défini, le compteur de préemption et le verrouillage du grand noyau sont enregistrées avec chaque événement. Mais l'affichage par défaut ne montre pas ces informations. Cette option définira l'affichage de ces informations avec 6 caractères. Lorsque l'un des champs est zéro ou N/A, un '.\' est affiché.
      <idle>-0       0d.h1. 106467.859747: function:             ktime_get <-- tick_check_idle
Le 0d.h1. désigne ces informations.
Il commence par un nombre. Cela représente le numéro du CPU sur lequel l'événement s'est produit.
Le deuxième caractère est l'un des suivants :
'd' - Interruptions désactivées
'.' - Interruptions activées
'X' - Possède des drapeaux non encore connus par trace-cmd
Le troisième caractère est le drapeau "need rescheduling".
'N' - Un ordonnancement est prévu
'.' - Aucun ordonnancement n'est prévu
Le quatrième caractère représente le contexte dans lequel l'événement s'est déclenché
'h' - Contexte d'interruption matérielle
's' - Contexte d'interruption logicielle
'H' - Contexte d'interruption matérielle qui a interrompu une interruption logicielle
'.' - Contexte normal
Le suivant est un nombre (doit être inférieur à 10), qui représente la profondeur de préemption (le nombre d'appels à preempt_disable() sans preempt_enable()).
'.' signifie que la préemption est activée.
Sur certains systèmes, la "désactivation de migration" peut exister, auquel cas un nombre sera affiché pour cela, ou '.' signifiant que la migration est activée.
Si lockdep est activé sur le système, alors le nombre représente la profondeur des verrous détenus lors du déclenchement de l'événement. '.' signifie qu'aucun verrou n'est détenu.

-w

Si les événements sched_switch et sched_wakeup sont tous deux activés, cette option rapportera la latence entre le moment où la tâche a été réveillée pour la première fois et le moment où elle a été planifiée.

-q

Silence les avertissements non critiques.

-O

Passe des options aux plugins trace-cmd chargés. 
-O plugin:var=value
Le 'plugin:' et '=value' sont facultatifs. La valeur peut être omise pour les options booléennes. Si le 'plugin:' est omis, toute variable qui correspond dans tous les plugins sera définie.
Exemple : -O fgraph:tailprint

--cpu <liste de cpu>

Liste de CPUs, séparés par "," ou ":", utilisés pour filtrer les événements. Une plage de CPUs peut être spécifiée en utilisant la notation "cpuX-cpuY", où tous les CPUs dans la plage entre cpuX et cpuY seront inclus dans la liste. L'ordre des CPUs dans la liste doit être du plus petit au plus grand. 
Exemple : "--cpu 0,3" - afficher les événements des CPUs 0 et 3
          "--cpu 2-4" - afficher les événements des CPUs 2, 3 et 4

--cpus

Liste les CPUs qui ont des données dans le fichier de trace, puis quitte.

--first-event

Affiche l'horodatage du premier événement de tous les CPUs qui ont des données.

--last-event

Affiche l'horodatage du dernier événement de tous les CPUs qui ont des données.

--stat

Si le fichier trace.dat a enregistré les statistiques finales (affichées à la fin de l'enregistrement), l'option --stat peut être utilisée pour les récupérer.

--uname

Si le fichier trace.dat a enregistré uname pendant l'exécution, cela récupérera ces informations.

--version

Si le fichier trace.dat a enregistré la version de l'exécutable utilisé pour le créer, il affichera cette version.

--ts-offset offset

Ajoute (ou soustrait si négatif) un décalage pour tous les horodatages du fichier de données précédent spécifié avec -i. Ceci est utile pour fusionner et trier plusieurs fichiers trace.dat où la différence d'horodatage est connue. Par exemple, si une trace est effectuée sur un invité virtuel, et une autre trace est effectuée sur l'hôte. Si l'horodatage de l'hôte est 1000 unités en avance sur celui de l'invité, ce qui suit peut être fait : 
trace-cmd report -i host.dat --ts-offset -1000 -i guest.dat
Cela soustraira 1000 unités d'horodatage à tous les événements de l'hôte lors de leur fusion avec les événements de guest.dat. Notez que les unités sont celles brutes enregistrées dans la trace. Si les unités sont des nanosecondes, l'ajout (ou la soustraction) du décalage sera en nanosecondes, même si les unités affichées sont en microsecondes.

--ts2secs HZ

Convertit la source d'horloge actuelle en une sortie en secondes (résolution en nanosecondes). Lors de l'utilisation d'horloges comme x86-tsc, si la fréquence est connue, en passant la fréquence de l'horloge, cela convertira le temps en secondes. 
Cette option affecte tout fichier trace.dat donné avec *-i* qui la précède.
Si cette option apparaît avant toute option *-i*, alors cette valeur devient la conversion par défaut pour tous les autres fichiers trace.dat. Si une autre option --ts2secs apparaît après un fichier trace.dat *-i*, alors cette option remplacera la valeur par défaut.
Exemple : Sur une machine de 3,4 GHz
trace-cmd record -p function -C x86-tsc
trace-cmd report --ts2ns 3400000000
Le rapport convertira les horodatages de cycles en un affichage lisible en secondes. La résolution d'affichage par défaut est la microseconde, sauf si *-t* est utilisé.
La valeur de --ts-offset doit toujours être dans les unités brutes d'horodatage, même avec cette option. Le décalage sera également converti.

--ts-diff

Affiche les différences de temps entre les événements. La différence apparaîtra entre parenthèses juste après l'horodatage.

--ts-check

S'assure qu'aucun horodatage ne remonte dans le temps, et si c'est le cas, affiche un message d'avertissement.

--nodate

Ignore la conversion des horodatages à la date définie par l'option trace-cmd record(3) --date.

--raw-ts

Affiche les horodatages bruts, sans aucune correction.

--align-ts

Affiche les horodatages alignés sur le premier événement.

--verbose[=level]

Définit le niveau de journalisation. Les niveaux de journalisation pris en charge sont "none", "crit", "err", "warn", "info", "debug", "all" ou leurs identifiants "0", "1", "2", "3", "4", "5", "6". La définition du niveau de journalisation à une valeur spécifique active tous les journaux de ce niveau et de tous les niveaux précédents. Le niveau sera "info" par défaut s'il n'est pas spécifié. 
Exemple : activer tous les journaux critiques, d'erreur et d'avertissement
trace-cmd report --verbose=warning

'.' - signifie interruptions et halves inférieures activées
'd' - signifie interruptions et halves inférieures désactivées

La deuxième position :

'N' - signifie que le drapeau "NEED_RESCHED" est défini et que le noyau doit essayer d'ordonnancer dès que possible.

Th

troisième position :

'.' - Dans un contexte normal/planifiable
's' - Dans un contexte d'interruption logicielle (soft interrupt)
'h' - Dans un contexte d'interruption matérielle (hard interrupt)
'H' - Dans un contexte d'interruption matérielle qui a interrompu une interruption logicielle

La quatrième position est la profondeur du compteur de préemption :

'pass:[.]' - la préemption est activée
'#' - la profondeur de la préemption désactivée (imbriquée)

La cinquième colonne est le compteur de désactivation de migration :

'.' - la migration est activée
'#' - la profondeur de la migration désactivée (imbriquée)

trace-cmd(1) - Page de manuel

NOM

trace-cmd-report - Afficher les résultats des traces enregistrées par trace-cmd

SYNOPSIS

trace-cmd report [options]

DESCRIPTION

trace-cmd(1) est un outil d'interface pour le traçage dynamique du noyau Linux via trace-events. Le traçage peut être effectué par des utilisateurs ou par le noyau lui-même. trace-cmd gère l'activation et la désactivation des événements de traçage, l'enregistrement des données et l'extraction des données dans différents formats.

La commande trace-cmd report analyse les données enregistrées par trace-cmd record et les affiche sous forme de rapport lisible par l'homme. Elle peut également afficher des statistiques sur les événements tracés.

Par défaut, trace-cmd report lit les données à partir du fichier de données par défaut (trace.dat) dans le répertoire courant. Utilisez l'option -i pour spécifier un fichier d'entrée différent.

Le rapport généré peut contenir divers détails sur les événements tracés, y compris les commutations de contexte, les réveils de tâches, et la latence entre le réveil et la commutation.

Le rapport peut inclure des informations sur les tâches en temps réel (RT) et leurs latences. Les priorités RT dans le noyau vont de 0 (la plus élevée) à 99. Les priorités inférieures à 100 correspondent aux tâches RT.

Exemple de sortie du rapport pour les événements de planification et les latences RT :

La version ci-dessus n'affichera que les réveils et les commutations de contexte des tâches Temps Réel. La *prio* utilisée dans le noyau commence à 0 pour la priorité la plus élevée. Ainsi, la *prio* 0 équivaut à la priorité temps réel 99 de l'espace utilisateur, et la priorité 98 équivaut à la priorité temps réel 1 de l'espace utilisateur. Les priorités inférieures à 100 représentent les tâches Temps Réel. Notez que les temps de réveil totaux sont identiques aux temps des tâches RT.

OPTIONS

Voir trace-cmd(1) pour la liste complète des options. Les options pertinentes pour trace-cmd report incluent :

-i, --input fichier
Spécifie le fichier contenant les données de trace enregistrées. Par défaut, il s'agit de trace.dat.
-o, --output fichier
Spécifie le fichier dans lequel écrire le rapport. Par défaut, la sortie est envoyée à stdout.
--profile
Affiche des informations de profil détaillées, y compris les traces de la pile d'appels pour chaque événement.
--comm nom_tache
Filtre les événements pour ne montrer que ceux relatifs à la tâche spécifiée.
--cpu numéro_cpu
Filtre les événements pour ne montrer que ceux qui se sont produits sur le CPU spécifié.
--pid pid
Filtre les événements pour ne montrer que ceux relatifs au processus ayant le PID spécifié.
-s, --stats
Affiche des statistiques sommaires sur les événements tracés.
-T, --time
Affiche les timestamps pour chaque événement.
-D, --raw-timestamp
Affiche les timestamps bruts (non normalisés) pour chaque événement.
-f, --format format
Spécifie le format de sortie. Les formats possibles incluent default, json, csv.

EXEMPLES

Pour afficher un rapport des données enregistrées dans trace.dat :

 $ trace-cmd report

Pour afficher un rapport à partir d'un fichier de données spécifique et le sauvegarder dans rapport.txt :

 $ trace-cmd report -i my_trace.dat -o rapport.txt

Pour afficher un rapport avec des statistiques et les traces de pile pour la tâche "bash" :

 $ trace-cmd report --profile --comm bash -s

Pour afficher un rapport des événements de commutation de contexte (sched_switch) sur le CPU 0 :

 $ trace-cmd report --event sched_switch --cpu 0
