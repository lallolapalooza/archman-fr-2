TRANSPORT(5) Manuel des formats de fichiers TRANSPORT(5)

NOM

transport - Format de la table des transports Postfix

SYNOPSIS

postmap /etc/postfix/transport
postmap -q "chaîne" /etc/postfix/transport
postmap -q - /etc/postfix/transport <fichier_entrée

DESCRIPTION


La table facultative transport(5) spécifie un mappage entre les adresses e-mail et les transports de livraison des messages ainsi que les destinations du prochain saut (next-hop). Les transports de livraison des messages tels que local ou smtp sont définis dans le fichier master.cf, et les destinations du prochain saut sont généralement des hôtes ou des noms de domaine. La table est interrogée par le démon trivial-rewrite(8).

Ce mappage remplace la sélection par défaut de transport:nexthop qui est intégrée à Postfix :

local_transport (par défaut: local:$myhostname)
C'est la valeur par défaut pour la livraison finale aux domaines listés avec mydestination, et pour les destinations [adresse_ip] qui correspondent à $inet_interfaces ou $proxy_interfaces. La destination nexthop par défaut est le nom d'hôte du MTA.
virtual_transport (par défaut: virtual:)
C'est la valeur par défaut pour la livraison finale aux domaines listés avec virtual_mailbox_domains. La destination nexthop par défaut est le domaine du destinataire.
relay_transport (par défaut: relay:)
C'est la valeur par défaut pour la livraison à distance aux domaines listés avec relay_domains. Par ordre de priorité décroissante, la destination nexthop est prise à partir de relay_transport, sender_dependent_relayhost_maps, relayhost, ou à partir du domaine du destinataire.
default_transport (par défaut: smtp:)
C'est la valeur par défaut pour la livraison à distance vers d'autres destinations. Par ordre de priorité décroissante, la destination nexthop est prise à partir de sender_dependent_default_transport_maps, default_transport, sender_dependent_relayhost_maps, relayhost, ou à partir du domaine du destinataire.

Normalement, la table transport(5) est spécifiée sous forme de fichier texte qui sert d'entrée à la commande postmap(1). Le résultat, un fichier indexé au format dbm ou db, est utilisé pour des recherches rapides par le système de messagerie. Exécutez la commande "postmap /etc/postfix/transport" pour reconstruire un fichier indexé après avoir modifié la table de transport correspondante.

Lorsque la table est fournie par d'autres moyens tels que NIS, LDAP ou SQL, les mêmes recherches sont effectuées que pour les fichiers indexés ordinaires.

Alternativement, la table peut être fournie sous forme de table d'expressions régulières où les motifs sont donnés comme expressions régulières, ou les recherches peuvent être dirigées vers un serveur basé sur TCP. Dans ces cas, les recherches sont effectuées d'une manière légèrement différente, comme décrit ci-dessous sous "TABLES D'EXPRESSIONS RÉGULIÈRES" ou "TABLES BASÉES SUR TCP".

CASSE D'ÉCRITURE

La chaîne de recherche est mise en minuscules avant la recherche dans la base de données. Depuis Postfix 2.3, la chaîne de recherche n'est pas mise en minuscules avec les types de bases de données comme regexp: ou pcre: dont les champs de recherche peuvent correspondre aux lettres majuscules et minuscules.

FORMAT DE LA TABLE

Le format d'entrée pour la commande postmap(1) est le suivant :

motif résultat
Lorsque motif correspond à l'adresse ou au domaine du destinataire, utilisez le résultat correspondant.
lignes vides et commentaires
Les lignes vides et les lignes contenant uniquement des espaces sont ignorées, tout comme les lignes dont le premier caractère non blanc est un `#'.
texte multi-lignes
Une ligne logique commence par un texte non blanc. Une ligne qui commence par un espace blanc continue une ligne logique.

Le motif spécifie une adresse e-mail, un nom de domaine, ou une hiérarchie de noms de domaine, tel que décrit dans la section "ORDRE DE RECHERCHE DANS LA TABLE".

Le résultat est de la forme transport:nexthop et spécifie comment ou où livrer le courrier. Ceci est décrit dans la section "FORMAT DU RÉSULTAT".

ORDRE DE RECHERCHE DANS LA TABLE

Avec les recherches dans des fichiers indexés tels que DB ou DBM, ou dans des tables réseau telles que NIS, LDAP ou SQL, les motifs sont essayés dans l'ordre indiqué ci-dessous :

utilisateur+extension@domaine transport:nexthop
Livrer le courrier pour utilisateur+extension@domaine via transport à nexthop.
utilisateur@domaine transport:nexthop
Livrer le courrier pour utilisateur@domaine via transport à nexthop.
domaine transport:nexthop
Livrer le courrier pour domaine via transport à nexthop.
.domaine transport:nexthop
Livrer le courrier pour tout sous-domaine de domaine via transport à nexthop. Ceci ne s'applique que lorsque la chaîne transport_maps n'est pas listée dans le paramètre de configuration parent_domain_matches_subdomains. Sinon, un nom de domaine correspond à lui-même et à ses sous-domaines.
* transport:nexthop
Le motif spécial * représente n'importe quelle adresse (c'est-à-dire qu'il fonctionne comme le motif générique, et est propre aux tables de transport Postfix).

Note 1 : l'adresse du destinataire nulle est recherchée comme $empty_address_recipient@$myhostname (par défaut : mailer-daemon@hostname).

Note 2 : la recherche utilisateur@domaine ou utilisateur+extension@domaine est disponible dans Postfix 2.0 et versions ultérieures.

FORMAT DU RÉSULTAT

Le résultat de la recherche est de la forme transport:nexthop. Le champ transport spécifie un transport de livraison de courrier tel que smtp ou local. Le champ nexthop spécifie où et comment livrer le courrier.

Le champ transport spécifie le nom d'un transport de livraison de courrier (le premier nom d'une entrée de service de livraison de courrier dans le fichier master.cf de Postfix).

Le champ nexthop spécifie généralement un domaine ou un nom d'hôte destinataire. Dans le cas du client SMTP/LMTP de Postfix, le champ nexthop peut contenir une liste de destinations nexthop séparées par une virgule ou un espace blanc (Postfix 3.5 et versions ultérieures).

La syntaxe d'une destination nexthop dépend du transport. Avec SMTP, spécifiez un service sur un port non par défaut sous la forme hôte:service, et désactivez les recherches DNS MX (échangeur de courrier) avec [hôte] ou [hôte]:port. La forme [] est requise lorsque vous spécifiez une adresse IP au lieu d'un nom d'hôte.

Un champ transport nul et un champ nexthop nul signifient "ne pas changer" : utiliser le transport de livraison et les informations nexthop qui seraient utilisées si la table de transport entière n'existait pas.

Un champ transport non nul avec un champ nexthop nul réinitialise les informations nexthop au domaine du destinataire.

Un champ transport nul avec un champ nexthop non nul ne modifie pas les informations de transport.

EXEMPLES

Pour livrer le courrier interne directement, tout en utilisant un relais de courrier pour tout autre courrier, spécifiez une entrée nulle pour les destinations internes (ne pas changer le transport de livraison ou les informations nexthop) et spécifiez un caractère générique pour toutes les autres destinations.

     my.domain    :
     .my.domain   :
     *            smtp:outbound-relay.my.domain

Pour envoyer du courrier pour example.com et ses sous-domaines via le transport uucp vers l'hôte UUCP nommé example :

     example.com      uucp:example
     .example.com     uucp:example

Lorsqu'aucun nom d'hôte nexthop n'est spécifié

transport(5) — Postfix documentation

NAME

transport — Postfix déroutement de courrier de bas niveau

SYNOPSIS

/etc/postfix/transport, transport:all

DESCRIPTION

Le fichier transport permet de spécifier le programme de livraison (transport) et la destination (next-hop) pour les messages destinés à des domaines ou à des adresses spécifiques. Le fichier transport est utilisé par le serveur trivial-rewrite(8).

La syntaxe générale est la suivante :

    destination_domaine     transport:destination
    destinataire          transport:destination

Si un transport n'est pas spécifié, Postfix utilise le transport qui correspond à la classe du domaine de l'adresse (voir DESCRIPTION ci-dessus). Le format transport peut aussi être une spécification de programme de livraison personnalisé.

Le domaine de destination destination_domaine correspond à la partie domaine d'une adresse de messagerie. Le domaine est ensuite recherché en commençant par le plus spécifique. Si le domaine de destination est une chaîne vide, il correspond à toutes les adresses.

Le champ transport spécifie le programme de livraison à utiliser. Les transports courants incluent smtp, local, virtual, pipe, et error. Si aucun transport n'est spécifié, le transport par défaut est utilisé.

Le champ destination spécifie la destination du message. Il peut s'agir d'un nom d'hôte, d'une adresse IP, d'un chemin de fichier ou d'un autre format selon le transport utilisé.

CASE FOLDING

Les noms de domaine dans les tables de recherche de transport sont convertis en minuscules avant la comparaison. Les adresses de destinataire ne sont pas converties en minuscules.

TABLE FORMAT

Les tables de recherche de transport peuvent être sous forme de fichiers texte simples, de bases de données Berkeley (hash), de bases de données DBM ou de tables gérées par le service réseau tcp_table.

Les fichiers texte simples contiennent une entrée par ligne. Les commentaires commencent par un caractère dièse (#). Les lignes vides sont ignorées. Les espaces blancs au début et à la fin d'une ligne sont ignorés.

Exemple de fichier texte :

    # Mapper example.com vers le transport lent
    example.com      slow:

    # Mapper un sous-domaine vers un serveur spécifique
    .example.com     :[gateway.example.com]

    # Mapper un domaine spécifique vers un hôte et un port SMTP
    bar.com          smtp:bar.example:2025

TABLE SEARCH ORDER

Les tables de recherche de transport sont recherchées dans l'ordre où elles sont spécifiées dans le fichier de configuration main.cf. Si plusieurs entrées correspondent à une adresse, la première entrée trouvée est utilisée.

RESULT FORMAT

Le résultat d'une recherche dans la table de transport est une paire composée du nom du transport et de la destination suivant le format :

    transport:destination

Par exemple, smtp:bar.example.com spécifie le transport smtp et la destination bar.example.com.

Si le champ transport est vide, le domaine de destination est utilisé comme transport.

Le caractère : après le nom du transport est facultatif. Le caractère : suivant le nom de l'hôte est utilisé pour séparer le nom de l'hôte du numéro de port.

Si le nom d'hôte est placé entre crochets (par exemple, [gateway.example.com]), les recherches MX sont désactivées. Cela empêche les boucles de routage de courrier lorsque votre machine est le serveur MX principal.

Pour les livraisons via SMTP ou LMTP, vous pouvez spécifier hôte:service au lieu d'un simple hôte.

    example.com      smtp:bar.example:2025

Cela achemine le courrier pour utilisateur@example.com vers l'hôte bar.example sur le port 2025. Au lieu d'un port numérique, un nom symbolique peut être utilisé.

Les livraisons via SMTP ou LMTP prennent en charge plusieurs destinations (Postfix >= 3.5) :

    example.com      smtp:bar.example, foo.example

Ceci essaie de livrer à bar.example avant d'essayer de livrer à foo.example.

EXAMPLES

Pour diriger le courrier destiné à utilisateur@example.com via le transport slow vers un échangeur de courrier pour example.com. Le transport slow peut être configuré pour ne gérer qu'un seul processus de livraison à la fois :

     example.com      slow:

Lorsque aucun transport n'est spécifié, Postfix utilise le transport qui correspond à la classe de domaine de l'adresse (voir DESCRIPTION ci-dessus). Le code suivant envoie tout le courrier destiné à example.com et à ses sous-domaines à l'hôte gateway.example.com :

     example.com      :[gateway.example.com]
     .example.com     :[gateway.example.com]

Dans l'exemple ci-dessus, les [] suppriment les recherches MX. Cela évite les boucles de routage de courrier lorsque votre machine est le serveur MX principal pour example.com.

Dans le cas de livraison via SMTP ou LMTP, on peut spécifier hôte:service au lieu d'un simple hôte :

     example.com      smtp:bar.example:2025

Cela achemine le courrier pour utilisateur@example.com vers l'hôte bar.example sur le port 2025. Au lieu d'un port numérique, un nom symbolique peut être utilisé. Spécifiez [] autour du nom d'hôte si les recherches MX doivent être désactivées.

Les livraisons via SMTP ou LMTP prennent en charge plusieurs destinations (Postfix >= 3.5) :

     example.com      smtp:bar.example, foo.example

Cela tente de livrer à bar.example avant de tenter de livrer à foo.example.

Le mailer d'erreur peut être utilisé pour rejeter le courrier :

     .example.com     error:mail for *.example.com is not deliverable

Cela provoque le rejet de tout courrier destiné à utilisateur@quelquechose.example.com.

TABLES D'EXPRESSIONS RÉGULIÈRES

Cette section décrit comment les recherches de table changent lorsque la table est fournie sous forme d'expressions régulières. Pour une description de la syntaxe des tables de recherche par expressions régulières, voir regexp_table(5) ou pcre_table(5).

Chaque modèle est une expression régulière qui est appliquée à l'adresse entière recherchée. Ainsi, some.domain.hierarchy n'est pas recherché via ses domaines parents, ni user+foo@domain recherché comme user@domain.

Les modèles sont appliqués dans l'ordre spécifié dans la table, jusqu'à ce qu'un modèle correspondant à la chaîne de recherche soit trouvé.

Le serveur trivial-rewrite(8) n'autorise pas la substitution d'expressions régulières de $1 etc. dans les tables de recherche d'expressions régulières, car cela pourrait ouvrir une faille de sécurité (Postfix version 2.3 et ultérieures).

TABLES BASÉES SUR TCP

Cette section décrit comment les recherches de table changent lorsque les recherches sont dirigées vers un serveur basé sur TCP. Pour une description du protocole de recherche client/serveur TCP, voir tcp_table(5). Cette fonctionnalité n'est pas disponible jusqu'à et incluant la version 2.4 de Postfix.

Chaque opération de recherche utilise l'adresse du destinataire entière une fois. Ainsi, some.domain.hierarchy n'est pas recherché via ses domaines parents, ni user+foo@domain recherché comme user@domain.

Les résultats sont les mêmes qu'avec les recherches dans des fichiers indexés.

PARAMÈTRES DE CONFIGURATION

Les paramètres suivants de main.cf sont particulièrement pertinents. Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

empty_address_recipient (MAILER-DAEMON)
Le destinataire du courrier adressé à l'adresse nulle.
parent_domain_matches_subdomains (voir la sortie de 'postconf -d')
Une liste de fonctionnalités Postfix où le modèle "example.com" correspond également aux sous-domaines d'example.com, au lieu de nécessiter un modèle explicite ".example.com".
transport_maps (vide)
Tables de recherche optionnelles avec des correspondances entre l'adresse du destinataire et (transport de livraison du message, destination prochaine).
