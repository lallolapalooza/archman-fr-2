PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

trace.h — traçage

SYNTAXE

#include <trace.h>

DESCRIPTION

L'en-tête <trace.h> définit la structure posix_trace_event_info, qui doit inclure au moins les membres suivants :

trace_event_id_t  posix_event_id
pid_t             posix_pid
void             *posix_prog_address
pthread_t         posix_thread_id
struct timespec   posix_timestamp
int               posix_truncation_status

L'en-tête <trace.h> définit la structure posix_trace_status_info, qui doit inclure au moins les membres suivants :

int     posix_stream_full_status
int     posix_stream_overrun_status
int     posix_stream_status
int     posix_log_full_status
int     posix_log_overrun_status
int     posix_stream_flush_error
int     posix_stream_flush_status

trace.h - Interface de traçage de noyau Linux

Cette page de manuel a été générée à partir de la documentation du noyau Linux.

NOM

trace.h - Interface de traçage de noyau Linux

SYNTAXE

#include <trace/api/trace.h>

DESCRIPTION

Les fichiers d'en-tête dans ce répertoire fournissent des interfaces pour générer des événements de traçage et pour s'y abonner. Le but est de fournir une interface de traçage unifiée pour le noyau Linux qui est simple à utiliser et à étendre.

Le traçage dans le noyau est basé sur des événements statiques. Chaque événement est défini avec un nom, une liste de champs et un type. Ces informations sont utilisées pour générer du code C qui sera utilisé par les programmes du noyau pour émettre des événements et par les programmes hors noyau pour s'abonner à ces événements.

Les définitions des événements se trouvent dans le répertoire include/trace/events/. Chaque fichier définit un ensemble d'événements liés. Par exemple, le fichier include/trace/events/sched.h contient les définitions des événements liés à la planification.

Pour émettre un événement, vous incluez le fichier d'en-tête approprié et utilisez la macro trace_event(). Par exemple :

TRACE_EVENT(my_event,
                    TP_PROTO(int arg1, char *arg2),
                    TP_ARGS(arg1, arg2),
                    TP_FIELDS(fld_int(arg1, "my_arg1") fld_str(arg2, "my_arg2"))
                );

Pour s'abonner à des événements, vous utilisez le système perf ou les bibliothèques de traçage comme libtraceevent.

UTILISATION DE L'APPLICATION

Les développeurs de pilotes et de sous-systèmes peuvent utiliser ces interfaces pour ajouter des événements de traçage à leur code. Cela peut être utile pour le débogage, la surveillance des performances et l'analyse du comportement du système.

JUSTIFICATION

Le traçage est essentiel pour comprendre et déboguer les systèmes complexes. Une interface de traçage unifiée simplifie le processus pour les développeurs et permet une analyse plus cohérente.

ORIENTATIONS FUTURES

Le système de traçage continue d'évoluer avec de nouvelles fonctionnalités et de meilleures performances. Les plans futurs incluent une intégration plus poussée avec d'autres outils de surveillance et de débogage.

VOIR AUSSI

ftrace(8), perf(1), trace-cmd(1), Documentation/trace/ dans les sources du noyau Linux.
