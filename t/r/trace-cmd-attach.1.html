TRACE-CMD-ATTACH(1) Manuel libtracefs TRACE-CMD-ATTACH(1)

NOM

trace-cmd-attach - attacher un fichier trace.dat invité à un fichier trace.dat hôte

SYNTAXE

trace-cmd attach [OPTIONS] fichier-trace-hote fichier-trace-invite [pid-invite ...]

DESCRIPTION

trace-cmd(1) attach est utilisé pour prendre un fichier trace.dat créé sur un invité et l'attacher à un fichier trace.dat créé sur l'hôte. Dans la plupart des cas, trace-cmd-agent(1) peut être utilisé pour automatiser cela, mais si pour une raison quelconque, l'agent n'est pas approprié, il peut être nécessaire de démarrer l'enregistrement de trace-cmd sur l'invité avec trace-cmd-record(1). Si l'enregistrement de l'hôte est activé en même temps, on peut utiliser trace-cmd attach(1) pour connecter les fichiers invité et hôte comme s'ils avaient été créés par l'agent trace-cmd.

fichier-trace-hote

Le fichier trace.dat créé par l'hôte. Doit avoir les événements kvm_exit et kvm_entry, et utiliser l'horloge "tsc2nsec".

fichier-trace-invite

Le fichier trace.dat créé par l'invité. Doit utiliser l'horloge "x86-tsc". Pour l'instant, ce n'est pris en charge que sur x86, cela pourrait prendre en charge d'autres architectures plus tard.

pid-invite

L'identifiant de processus du thread hôte qui représente les threads invités. Chaque identifiant de processus qui représente tous les vCPUs de l'invité doit être listé. Notez que vous pouvez ajouter plus que les threads qui représentent les vCPUs de l'invité, car l'outil recherchera dans le fichier fichier-trace-hote les événements kvm_exit et kvm_entry pour faire correspondre ces PIDs avec les vCPUs qu'ils représentent.

OPTIONS

-c cpus

Spécifie le nombre de processeurs de l'invité.

-s timeshift

Une liste séparée par des virgules du format décalage,échelle,fraction,horodatage Ces valeurs correspondent à celles fournies dans /sys/kernel/kvm/<pid>/vcpu/* 
*décalage*: Le décalage de l'invité. "tsc-offest" dans le répertoire. Notez
          que la valeur listée ici est l'inverse de celle indiquée dans le
          répertoire.
*échelle*: Le facteur d'échelle. "tsc-scaling-ratio"
*fraction*: Les bits de fraction. "tsc-scaling-ratio-frac-bits"
*horodatage*: L'horodatage à partir duquel utiliser les informations ci-dessus.
          Dans certains cas, les valeurs peuvent changer avec le temps. En
          ajoutant un horodatage, cela prendra effet après que l'horodatage
          soit atteint. Normalement, cela serait zéro.
Actuellement, un seul timeshift est donné par CPU. Une option *-s* doit être
fournie pour chaque CPU. S'il y a moins d'options que de CPUs, la dernière option
fournie sera utilisée pour les CPUs restants. Si une seule option est donnée, alors
les valeurs de cette option seront utilisées pour tous les CPUs.

EXEMPLES

Activer tous les événements pour le traçage :

  $ # trouver le processus pour un invité donné
  $ ps aux |grep qemu
 libvirt+   63170  5.6  1.6 13994848 4257540 ?    Sl   Mai02 2884:49 /usr/bin/qemu-system-x86_64...
  $ # Utiliser 63170 pour trouver tous les PIDs de l'invité donné
  $ ls /proc/63170/task
 1541591  63170  63198  63209  63211  63213  63214  63215  63216  63217  63218  63219  63234
  $ # Trouver le décalage tsc
  $ su
  # cat /sys/kernel/debug/kvm/63170-15/vcpu0/tsc-offset
 -27950965013436847
  # trace-cmd record -C tsc2nsec -e kvm -e sched -e irq -e timer
# sur l'invité:
  # trace-cmd record -C x86-tsc -e sched -e irq -e timer sleep 10
# de retour sur l'hôte, appuyer sur Ctrl^C pour arrêter le traçage après que l'invité ait terminé
  # # Rendre le fichier trace.dat appartenant à votre compte utilisateur.
  # chown user.user trace.dat
  # exit
  $ scp root@guest:trace.dat trace-guest.dat
  $ # maintenant attacher les deux fichiers (l'invité a 8 CPUs)
  $ trace-cmd attach -c 8 -s 27950965013436847 trace.dat trace-guest.dat 1541591  63170  63198  63209  63211  63213  63214  63215  63216  63217  63218  63219  63234
  $ trace-cmd report -i trace.dat -i trace-guest.dat
  $ # vous devriez maintenant voir la trace de l'invité entrelacée dans la trace de l'hôte.
