trace(n) Commandes intégrées Tcl trace(n)

NOM

trace - Surveiller les accès aux variables, les utilisations de commandes et les exécutions de commandes

SYNOPSIS

trace option ?arg arg ...?

DESCRIPTION

Cette commande provoque l'exécution de commandes Tcl lorsque certaines opérations sont invoquées. Les options légales (qui peuvent être abrégées) sont :

trace add type nom ops ?args?
Où type est command, execution, ou variable.
trace add command nom ops préfixeCommande
Organiser l'exécution de préfixeCommande (avec des arguments supplémentaires) chaque fois que la commande nom est modifiée d'une des manières indiquées par la liste ops. Nom sera résolu en utilisant les règles de résolution d'espace de noms habituelles utilisées par les commandes. Si la commande n'existe pas, une erreur sera levée.

Ops indique quelles opérations sont d'intérêt, et est une liste d'un ou plusieurs des éléments suivants :

rename
Invoquer préfixeCommande chaque fois que la commande tracée est renommée. Notez que le renommage vers une chaîne vide est considéré comme une suppression, et ne sera pas tracé avec "rename".
delete
Invoquer préfixeCommande lorsque la commande tracée est supprimée. Les commandes peuvent être supprimées explicitement en utilisant la commande rename pour renommer la commande en une chaîne vide. Les commandes sont également supprimées lorsque l'interpréteur est supprimé, mais les traces ne seront pas invoquées car il n'y a pas d'interpréteur dans lequel les exécuter.

Lorsque la trace se déclenche, en fonction des opérations tracées, un certain nombre d'arguments sont ajoutés à préfixeCommande de sorte que la commande réelle soit la suivante :

préfixeCommande ancienNom nouveauNom op

AncienNom et nouveauNom donnent le nom actuel (ancien) de la commande tracée et le nom auquel elle est renommée (une chaîne vide s'il s'agit d'une opération de "suppression"). Op indique quelle opération est effectuée sur la commande, et est l'un des rename ou delete tel que défini ci-dessus. L'opération de trace ne peut pas être utilisée pour empêcher la suppression d'une commande. Tcl supprimera toujours la commande une fois la trace terminée. Les renommages ou suppressions récursifs ne provoqueront pas d'autres traces du même type à être évaluées, donc une trace de suppression qui supprime elle-même la commande, ou une trace de renommage qui renomme elle-même la commande ne provoquera pas d'autres évaluations de traces. AncienNom et nouveauNom sont entièrement qualifiés avec tous les espaces de noms dans lesquels ils apparaissent.

trace add execution nom ops préfixeCommande
Organiser l'exécution de préfixeCommande (avec des arguments supplémentaires) chaque fois que la commande nom est exécutée, avec des traces se produisant aux points indiqués par la liste ops. Nom sera résolu en utilisant les règles de résolution d'espace de noms habituelles utilisées par les commandes. Si la commande n'existe pas, une erreur sera levée.

Ops indique quelles opérations sont d'intérêt, et est une liste d'un ou plusieurs des éléments suivants :

enter
Invoquer préfixeCommande chaque fois que la commande nom est exécutée, juste avant que l'exécution réelle n'ait lieu.
leave
Invoquer préfixeCommande chaque fois que la commande nom est exécutée, juste après que l'exécution réelle ait eu lieu.
enterstep
Invoquer préfixeCommande pour chaque commande Tcl qui est exécutée depuis le début de l'exécution de la procédure nom jusqu'à la fin de cette procédure. PréfixeCommande est invoqué juste avant l'exécution réelle de la commande Tcl signalée. Par exemple, si nous avons "proc foo {} { puts "hello" }", alors une trace enterstep serait invoquée juste avant l'exécution de "puts "hello"". Le réglage d'une trace enterstep sur une commande nom qui ne fait pas référence à une procédure ne provoquera pas d'erreur et sera simplement ignoré.
leavestep
Invoquer préfixeCommande pour chaque commande Tcl qui est exécutée depuis le début de l'exécution de la procédure nom jusqu'à la fin de cette procédure. PréfixeCommande est invoqué juste après l'exécution réelle de la commande Tcl signalée. Le réglage d'une trace leavestep sur une commande nom qui ne fait pas référence à une procédure ne provoquera pas d'erreur et sera simplement ignoré.

Lorsque la trace se déclenche, en fonction des opérations tracées, un certain nombre d'arguments sont ajoutés à préfixeCommande de sorte que la commande réelle soit la suivante :

Pour les opérations enter et enterstep :

préfixeCommande chaîneCommande op

ChaîneCommande donne la commande actuelle complète en cours d'exécution (la commande tracée pour une opération enter, une commande arbitraire pour une opération enterstep), y compris tous les arguments dans leur forme entièrement développée. Op indique quelle opération est effectuée sur l'exécution de la commande, et est l'un des enter ou enterstep tel que défini ci-dessus. L'opération de trace peut être utilisée pour arrêter l'exécution de la commande, en supprimant la commande en question. Bien sûr, lorsque la commande sera exécutée ultérieurement, une erreur "commande invalide" se produira.

Pour les opérations leave et leavestep :

préfixeCommande chaîneCommande code résultat op

ChaîneCommande donne la commande actuelle complète en cours d'exécution (la commande tracée pour une opération enter, une commande arbitraire pour une opération enterstep), y compris tous les arguments dans leur forme entièrement développée. Code donne le code de résultat de cette exécution, et résultat la chaîne de résultat. Op indique quelle opération est effectuée sur l'exécution de la commande, et est l'un des leave ou leavestep tel que défini ci-dessus. Notez que la création de nombreuses traces enterstep ou leavestep peut conduire à des résultats peu intuitifs, car les commandes invoquées par une trace peuvent elles-mêmes entraîner d'autres invocations de commandes pour d'autres traces.

PréfixeCommande s'exécute dans le même contexte que le code qui a invoqué l'opération tracée : ainsi, préfixeCommande, s'il est invoqué depuis une procédure, aura accès aux mêmes variables locales que le code dans la procédure. Ce contexte peut être différent du contexte dans lequel la trace a été créée. Si préfixeCommande invoque une procédure (ce qu'il fait normalement), alors la procédure devra utiliser les commandes upvar ou uplevel si elle souhaite accéder aux variables locales du code qui a invoqué l'opération de trace.

Pendant que préfixeCommande s'exécute lors d'une trace d'exécution, les traces sur nom sont temporairement désactivées. Cela permet à préfixeCommande d'exécuter nom dans son corps sans invoquer d'autres traces. Si une erreur se produit lors de l'exécution de préfixeCommande, alors la commande nom dans son ensemble retournera cette même erreur.

Lorsque plusieurs traces sont définies sur nom, alors pour les opérations enter et enterstep, les commandes tracées sont invoquées dans l'ordre inverse de la création des traces ; et pour les opérations leave et leavestep, les commandes tracées sont invoquées dans l'ordre original de création.

Le comportement des traces d'exécution est actuellement indéfini pour une commande nom importée dans un autre espace de noms.

trace add variable nom ops préfixeCommande
Organiser l'exécution de préfixeCommande chaque fois que la variable nom est accédée d'une des manières indiquées par la liste ops. Nom peut faire référence à une variable normale, à un élément d'un tableau, ou à un tableau entier (c'est-à-dire que nom peut être juste le nom d'un tableau, sans index entre parenthèses). Si nom fait référence à un tableau entier, alors préfixeCommande est invoqué chaque fois qu'un élément du tableau est manipulé. Si la variable d

Ops indique quelles opérations sont d'intérêt, et est une liste d'un ou plusieurs des éléments suivants :

array
Appelle commandPrefix chaque fois que la variable est accédée ou modifiée via la commande array, à condition que name ne soit pas une variable scalaire au moment où la commande array est invoquée. Si name est une variable scalaire, l'accès via la commande array ne déclenchera pas le trace.
read
Appelle commandPrefix chaque fois que la variable est lue.
write
Appelle commandPrefix chaque fois que la variable est écrite.
unset
Appelle commandPrefix chaque fois que la variable est désassignée. Les variables peuvent être désassignées explicitement avec la commande unset, ou implicitement lorsque des procédures retournent (toutes leurs variables locales sont désassignées). Les variables sont également désassignées lorsque les interpréteurs sont supprimés, mais les traces ne seront pas appelées car il n'y a pas d'interpréteur dans lequel les exécuter.

Lorsque le trace se déclenche, trois arguments sont ajoutés à commandPrefix de sorte que la commande réelle est la suivante :

commandPrefix name1 name2 op

Name1 et name2 donnent le(s) nom(s) de la variable accédée : si la variable est scalaire, name1 donne le nom de la variable et name2 est une chaîne vide ; si la variable est un élément de tableau, name1 donne le nom du tableau et name2 donne l'index dans le tableau ; si un tableau entier est supprimé et que le trace a été enregistré sur le tableau global, plutôt que sur un élément unique, alors name1 donne le nom du tableau et name2 est une chaîne vide. Name1 et name2 ne sont pas nécessairement les mêmes que le nom utilisé dans la commande trace variable : la commande upvar permet à une procédure de faire référence à une variable sous un nom différent. Op indique quelle opération est effectuée sur la variable, et est soit read, write, ou unset tel que défini ci-dessus.

CommandPrefix s'exécute dans le même contexte que le code qui a invoqué l'opération tracée : si la variable a été accédée dans le cadre d'une procédure Tcl, alors commandPrefix aura accès aux mêmes variables locales que le code de la procédure. Ce contexte peut être différent du contexte dans lequel le trace a été créé. Si commandPrefix invoque une procédure (ce qu'il fait normalement), alors la procédure devra utiliser upvar ou uplevel si elle souhaite accéder à la variable tracée. Notez également que name1 peut ne pas nécessairement être le même que le nom utilisé pour définir le trace sur la variable ; des différences peuvent survenir si l'accès est effectué via une variable définie avec la commande upvar.

Pour les traces de lecture et d'écriture, commandPrefix peut modifier la variable pour affecter le résultat de l'opération tracée. Si commandPrefix modifie la valeur d'une variable lors d'un trace de lecture ou d'écriture, alors la nouvelle valeur sera renvoyée comme résultat de l'opération tracée. La valeur de retour de commandPrefix est ignorée sauf que si elle renvoie une erreur quelconque, l'opération tracée renvoie également une erreur avec le même message d'erreur renvoyé par la commande de trace (ce mécanisme peut être utilisé pour implémenter des variables en lecture seule, par exemple). Pour les traces d'écriture, commandPrefix est appelée après que la valeur de la variable a été modifiée ; elle peut écrire une nouvelle valeur dans la variable pour remplacer la valeur d'origine spécifiée dans l'opération d'écriture. Pour implémenter des variables en lecture seule, commandPrefix devra restaurer l'ancienne valeur de la variable.

Pendant que commandPrefix s'exécute lors d'un trace de lecture ou d'écriture, les traces sur la variable sont temporairement désactivées. Cela signifie que les lectures et écritures invoquées par commandPrefix se feront directement, sans invoquer à nouveau commandPrefix (ou d'autres traces). Cependant, si commandPrefix désassigne la variable, alors les traces de désassignation seront appelées.

Lorsqu'un trace de désassignation est appelé, la variable a déjà été supprimée : elle apparaîtra comme indéfinie, sans traces. Si une désassignation se produit en raison d'un retour de procédure, alors le trace sera appelé dans le contexte de variable de la procédure à laquelle on retourne : la pile d'appels de la procédure qui retourne n'existera plus. Les traces ne sont pas désactivés pendant les traces de désassignation, donc si une commande de trace de désassignation crée un nouveau trace et accède à la variable, le trace sera appelé. Toutes les erreurs dans les traces de désassignation sont ignorées.

S'il existe plusieurs traces sur une variable, ils sont appelés dans l'ordre de création, le plus récent d'abord. Si un trace renvoie une erreur, alors aucun autre trace n'est appelé pour la variable. Si un élément de tableau a un trace défini, et qu'il existe également un trace défini sur le tableau dans son ensemble, le trace sur le tableau global est appelé avant celui de l'élément.

Une fois créé, le trace reste en vigueur soit jusqu'à ce que le trace soit supprimé avec la commande trace remove variable décrite ci-dessous, jusqu'à ce que la variable soit désassignée, soit jusqu'à ce que l'interpréteur soit supprimé. La désassignation d'un élément de tableau supprimera tous les traces sur cet élément, mais ne supprimera pas les traces sur le tableau global.

Cette commande renvoie une chaîne vide.

trace remove type name opList commandPrefix
Où type est soit command, execution ou variable.
trace remove command name opList commandPrefix
S'il existe un trace défini sur la commande name avec les opérations et la commande données par opList et commandPrefix, alors le trace est supprimé, de sorte que commandPrefix ne sera plus jamais appelé. Renvoie une chaîne vide. Si name n'existe pas, la commande lèvera une erreur.
trace remove execution name opList commandPrefix
S'il existe un trace défini sur la commande name avec les opérations et la commande données par opList et commandPrefix, alors le trace est supprimé, de sorte que commandPrefix ne sera plus jamais appelé. Renvoie une chaîne vide. Si name n'existe pas, la commande lèvera une erreur.
trace remove variable name opList commandPrefix
S'il existe un trace défini sur la variable name avec les opérations et la commande données par opList et commandPrefix, alors le trace est supprimé, de sorte que commandPrefix ne sera plus jamais appelé. Renvoie une chaîne vide.
trace info type name
Où type est soit command, execution ou variable.
trace info command name
Renvoie une liste contenant un élément pour chaque trace actuellement défini sur la commande name. Chaque élément de la liste est lui-même une liste contenant deux éléments, qui sont opList et commandPrefix associés au trace. Si name n'a pas de traces définis, alors le résultat de la commande sera une chaîne vide. Si name n'existe pas, la commande lèvera une erreur.
trace info execution name
Renvoie une liste contenant un élément pour chaque trace actuellement défini sur la commande name. Chaque élément de la liste est lui-même une liste contenant deux éléments, qui sont opList et commandPrefix associés au trace. Si name n'a pas de traces définis, alors le résultat de la commande sera une chaîne vide. Si name n'existe pas, la commande lèvera une erreur.
trace info variable name
Renvoie une liste contenant un élément pour chaque trace actuellement défini sur la variable name. Chaque élément de la liste est lui-même une liste contenant deux éléments, qui sont opList et commandPrefix associés au trace. Si name n'existe pas ou n'a pas de traces définis, alors le résultat de la commande sera une chaîne vide.

Pour des raisons de compatibilité descendante, trois autres sous-commandes sont disponibles :

trace variable name ops command
Ceci est équivalent à trace add variable name ops command.
trace vdelete name ops command
Ceci est équivalent à trace remove variable name ops command
trace vinfo name
Ceci est équivalent à trace info variable name

Ces sous-commandes sont dépréciées et seront probablement supprimées dans une future version de Tcl. Elles utilisent une syntaxe plus ancienne dans laquelle array, read, write, unset sont remplacés par a, r, w et u respectivement, et l'argument ops n'est pas une liste, mais simplement une concaténation de chaînes des opérations, telle que rwua.

EXEMPLES

Imprimer un message chaque fois que l'une des variables globales foo et bar est mise à jour, même si elles ont un nom local différent à ce moment-là (ce qui peut être fait avec la commande upvar) :

proc tracer {varname args} {
    upvar #0 $varname var
    puts "$varname a été mis à jour à \"$var\""
}
trace add variable foo write "tracer foo"
trace add variable bar write "tracer bar"

Assurer que la variable globale foobar contienne toujours le produit des variables globales foo et bar :

proc doMult args {
    global foo bar foobar
    set foobar [expr {$foo * $bar}]
}
trace add variable foo write doMult
trace add variable bar write doMult

Imprimer un trace de ce que font les commandes exécutées pendant le traitement d'une procédure Tcl :

proc x {} { y }
proc y {} { z }
proc z {} { puts hello }
proc report args {puts [info level 0]}
trace add execution

SYNOPIS

set varName value
trace option arg ...

DESCRIPTION

La commande trace enregistre des appels de commandes Tcl. Elle peut être utilisée pour enregistrer des modifications de variables, des appels de commandes, ou des ouvertures et fermetures de fichiers. Il existe plusieurs options.

trace option arg ...
Lance un nouveau trace.
trace var varName ops script
Enregistre les modifications apportées à la variable varName. ops est une chaîne de caractères contenant zéro ou plus des caractères 'r', 'w', et 'u' pour indiquer respectivement les lectures, les écritures et les non-définitons de la variable. Lorsque l'une de ces opérations se produit sur varName, le script est exécuté. Le script est généralement évalué dans le contexte du niveau d'appel appelant l'opération sur la variable.
trace read varName script
Équivalent à trace var varName r script.
trace write varName script
Équivalent à trace var varName w script.
trace unset varName script
Équivalent à trace var varName u script.
trace cmd cmdName script
Enregistre les invocations de la commande cmdName. Lorsque cmdName est appelée, le script est exécuté. Le script est généralement évalué dans le contexte du niveau d'appel appelant la commande.
trace file channelId ops script
Enregistre les opérations sur le canal channelId. ops est une chaîne de caractères contenant zéro ou plus des caractères 'r' et 'w' pour indiquer respectivement les lectures et les écritures sur le canal. Lorsque l'une de ces opérations se produit sur channelId, le script est exécuté. Le script est généralement évalué dans le contexte du niveau d'appel appelant l'opération sur le canal.
trace delete traceId
Supprime un trace existant identifié par traceId. traceId est retourné par la commande trace lors de la création du trace.
trace clear
Supprime tous les traces actifs.

EXEMPLES

x enterstep report
x
  → report y enterstep
    report z enterstep
    report {puts hello} enterstep
    hello
