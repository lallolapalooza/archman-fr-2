NOM

trace-cmd-restore - restaurer un enregistrement de trace échoué

SYNTAXE

trace-cmd restore [OPTIONS] [commande] fichier-cpu [fichier-cpu ...]

DESCRIPTION

La commande restore de trace-cmd(1) restaurera un fichier trace-cmd-record(1) corrompu. Si, pour une raison quelconque, un enregistrement trace-cmd échoue, il laissera les fichiers de données par-cpu sans créer le fichier final trace.dat. La commande trace-cmd restore ajoutera les fichiers pour créer un fichier trace.dat fonctionnel qui pourra être lu avec trace-cmd-report(1).

Lorsque trace-cmd record s'exécute, il lance un processus par CPU et écrit dans un fichier par CPU généralement nommé trace.dat.cpuX, où X représente le numéro du CPU qu'il trace. Si l'option -o a été utilisée dans trace-cmd record, alors les fichiers de données CPU auront ce nom au lieu du nom trace.dat. Si un crash inattendu se produit avant la fin du traçage, les fichiers par CPU existeront toujours mais il n'y aura pas de fichier trace.dat à lire. trace-cmd restore vous permettra de créer un fichier trace.dat avec les fichiers de données existants.

OPTIONS

-c

Crée un fichier trace.dat partiel à partir de la machine, à utiliser avec une restauration complète trace-cmd restore à un autre moment. Cette option est utile pour les appareils embarqués. Si un serveur contient les fichiers CPU d'un enregistrement trace-cmd corrompu (ou trace-cmd listen), trace-cmd restore peut être exécuté sur l'appareil embarqué avec l'option -c pour obtenir toutes les informations stockées de cet appareil embarqué. Ensuite, le fichier créé pourrait être copié sur le serveur pour y exécuter trace-cmd restore avec les fichiers CPU. 
Si -o n'est pas spécifié, alors le fichier créé sera nommé
'trace-partial.dat'. En effet, ce fichier n'est pas une version complète
que trace-cmd-report(1) pourrait utiliser.

-t tracing_dir

Utilisé avec -c, il remplace l'emplacement à partir duquel lire les événements. Par défaut, les informations de traçage sont lues depuis debugfs/tracing. -t utilisera cet emplacement à la place. Ceci peut être utile si le fichier trace.dat à créer provient d'une autre machine. Il suffit de faire un tar -cvf events.tar debugfs/tracing et de copier et décompresser ce fichier localement, puis d'utiliser ce répertoire à la place.

-k kallsyms

Utilisé avec -c, il remplace l'emplacement à partir duquel lire le fichier kallsyms. Par défaut, /proc/kallsyms est utilisé. -k remplacera le fichier pour lire le fichier kallsyms. Ceci peut être utile si le fichier trace.dat à créer provient d'une autre machine. Il suffit de copier le fichier /proc/kallsyms localement, et d'utiliser -k pour pointer vers ce fichier.

-o sortie'

Par défaut, trace-cmd restore créera un fichier trace.dat (ou trace-partial.dat si -c est spécifié). Vous pouvez spécifier un autre fichier d'écriture avec l'option -o.

-i entrée

Par défaut, trace-cmd restore lira les informations du système actuel pour créer les données initiales stockées dans le fichier trace.dat. Si le crash s'est produit sur une autre machine, cette machine devrait avoir exécuté trace-cmd restore avec l'option -c pour créer le fichier partiel trace.dat. Ce fichier peut ensuite être copié sur la machine actuelle où trace-cmd restore utilisera -i pour charger ce fichier au lieu de lire depuis le système actuel.

EXEMPLES

Si un crash s'est produit sur une autre machine, vous pourriez exécuter :

$ trace-cmd restore -c -o box-partial.dat

Ensuite, sur le serveur qui a les fichiers CPU :

$ trace-cmd restore -i box-partial.dat trace.dat.cpu0 trace.dat.cpu1

Ceci créerait un fichier trace.dat pour la boîte embarquée.
