Paquet: libtracefs

LIBTRACEFS(3) Manuel libtracefs LIBTRACEFS(3)

NOM

tracefs_cpu_open, tracefs_cpu_close, tracefs_cpu_alloc_fd, tracefs_cpu_free_fd, tracefs_cpu_snapshot_open - Ouverture des données trace_pipe_raw pour la lecture

SYNOPSIS

#include <tracefs.h>
struct tracefs_cpu *tracefs_cpu_open(struct tracefs_instance *instance,
                                     int cpu, bool nonblock);
void tracefs_cpu_close(struct tracefs_cpu *tcpu);
struct tracefs_cpu *tracefs_cpu_alloc_fd(int fd, int subbuf_size, bool nonblock);
void tracefs_cpu_free_fd(struct tracefs_cpu *tcpu);
struct tracefs_cpu *tracefs_cpu_snapshot_open(struct tracefs_instance *instance,
                                             int cpu, bool nonblock);

DESCRIPTION

Cet ensemble d'API peut être utilisé pour ouvrir les données brutes des fichiers trace_pipe_raw du système de fichiers tracefs afin de les lire avec les fonctions de tracefs_cpu_read(3).

tracefs_cpu_open() crée un descripteur qui peut lire le fichier tracefs trace_pipe_raw pour un cpu donné dans une instance donnée. Si instance est NULL, le fichier tracefs trace_pipe_raw de plus haut niveau est utilisé.

tracefs_cpu_close() ferme tous les descripteurs de fichiers associés à trace_pipe_raw ouvert par tracefs_cpu_open().

tracefs_cpu_alloc_fd() créera un descripteur tracefs_cpu à partir d'un descripteur de fichier existant fd. Ceci est utile pour l'utiliser lors de la connexion à un socket ou un pipe où l'autre extrémité fournit des données de traçage brutes dans le même format que le fichier trace_pipe_raw (comme dans le traçage invité vers hôte). L'appelant est responsable de la détermination de la subbuf_size qui sera utilisée pour découper les sous-buffers lus par le descripteur de fichier. Le paramètre nonblock est traité de la même manière que le paramètre du même nom dans tracefs_cpu_open().

tracefs_cpu_free_fd() est utilisé pour libérer le descripteur retourné par tracefs_cpu_alloc_fd(). Il effectue tout le nettoyage que tracefs_cpu_close() effectue, et qui pourrait également être utilisé pour libérer le descripteur créé par tracefs_cpu_alloc_fd(), mais fermera également le descripteur de fichier passé. Notez que tracefs_cpu_free_fd() ne doit pas être utilisé sur le descripteur retourné par tracefs_cpu_open(), car il ne fermera pas le descripteur de fichier créé par celui-ci.

tracefs_cpu_snapshot_open() est similaire à tracefs_cpu_open(), sauf qu'il ouvre le buffer de snapshot (voir tracefs_snapshot_snap(3)). Le buffer de snapshot n'a pas d'écrivain, il est uniquement créé par une action de snapshot qui échange le buffer circulaire actuel avec le buffer de snapshot. Le paramètre nonblock, lorsqu'il est faux, agit un peu différemment ici aussi. Les lectures ne sont pas affectées par le fichier "buffer_percent". Si le buffer de snapshot est vide, il se bloquera jusqu'à ce qu'un nouveau snapshot se produise.

VALEUR DE RETOUR

tracefs_cpu_open() et *tracefs_cpu_snapshot_open() retournent tous deux un descripteur struct tracefs_cpu qui peut être utilisé par les autres fonctions ou NULL en cas d'erreur.

tracefs_cpu_alloc_fd() retourne un descripteur struct tracefs_cpu qui peut être utilisé par les fonctions liées à tracefs_cpu_read(3), où le descripteur lira le descripteur de fichier fd passé.

EXEMPLE

Voir tracefs_cpu_read(3) pour un exemple.
