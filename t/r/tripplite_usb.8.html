NOM

tripplite_usb - Pilote pour les onduleurs Tripp Lite USB plus anciens (pas HID PDC)

SYNTAXE

tripplite_usb -h

tripplite_usb -a NOM_ONDULEUR [OPTIONS]

MATERIEL SUPPORTE

Ce pilote devrait fonctionner avec les onduleurs Tripp Lite plus anciens qui sont détectés comme des périphériques de classe USB HID, mais qui ne sont pas de véritables périphériques de classe HID Power-Device. Jusqu'à présent, les périphériques pris en charge par tripplite_usb ont l'ID produit 0001, et les unités plus récentes (telles que celles avec "LCD" dans le nom du modèle) avec l'ID produit 2001 nécessitent plutôt le pilote usbhid-ups(8).

Veuillez signaler les succès ou les échecs à la liste de diffusion nut-upsuser. Une information clé est le numéro de protocole, renvoyé dans ups.firmware.aux. Assurez-vous également d'activer le débogage (-DDD) pour des messages de journal plus informatifs.

Si votre onduleur Tripp Lite utilise un port série, vous voudrez peut-être considérer les pilotes tripplite(8) ou tripplitesu(8).

Ce pilote a été testé avec les modèles suivants :

•INTERNETOFFICE700
•OMNIVS1000
•OMNIVS1500XL (quelques avertissements)
•SMART700USB
•SMART1500RM2U
•SMART2200RMXL2U
•SMART3000RM2U

Si vous avez utilisé le logiciel PowerAlert de Tripp Lite pour vous connecter à votre onduleur, il y a de fortes chances que tripplite_usb fonctionne s'il utilise l'un des protocoles suivants :

•Protocole 0004
•Protocole 1001
•Protocole 2001
•Protocole 3003
•Protocole 3005

D'autre part, si la page Web de votre onduleur sur le site Web de Tripp-Lite indique "Le port USB conforme HID permet également une intégration directe avec les fonctionnalités de gestion d'alimentation et d'arrêt automatique intégrées de Windows et MAC OS X", vous devriez utiliser le pilote usbhid-ups(8) à la place.

ARGUMENTS EXTRA

Ce pilote prend en charge les paramètres optionnels suivants dans le fichier ups.conf(5) (ou avec -x sur la ligne de commande) :

port = chaîne

Option requise pour tous les pilotes NUT. Une certaine valeur doit être définie, typiquement auto pour les pilotes qui gèrent les connexions USB.

Note
Il peut s'agir d'un chemin d'accès au système de fichiers de périphériques comme /dev/usb/hiddev0, mais l'utilisation actuelle de l'API libusb empêche la connaissance et la correspondance par de tels identifiants. Ils peuvent également être intrinsèquement peu fiables (dépendants du rebranchement et de l'ordre d'énumération). À l'heure actuelle, la valeur réelle est ignorée, mais syntaxiquement une configuration de port doit toujours être présente.

Il est possible de contrôler plusieurs unités d'onduleur simultanément en exécutant plusieurs instances de ce pilote, à condition qu'elles puissent être distinguées de manière unique en définissant une combinaison des options vendor, product, vendorid, productid, serial, bus et/ou device détaillées ci-dessous. Pour les périphériques ou systèmes d'exploitation qui ne fournissent pas suffisamment d'informations, l'option allow_duplicates peut être utile (limitée et risquée !)

vendorid = regex, productid = regex, vendor = regex, product = regex, serial = regex

Sélectionne un onduleur spécifique, s'il y en a plus d'un connecté via USB. Chaque option spécifie une expression régulière étendue (voir regex(7) pour plus d'informations sur les expressions régulières), qui doit correspondre aux valeurs complètes des chaînes de fournisseur/produit/numéro de série respectives de l'onduleur (moins les espaces blancs environnants), ou au code hexadécimal complet à 4 chiffres pour les ID de fournisseur et de produit.

Essayez lsusb(8) ou exécutez ce pilote NUT avec l'argument de ligne de commande -DD pour trouver les chaînes à faire correspondre.

Exemples :

•-x vendor="Foo.Corporation.*"
•-x vendorid="051d*" (APC)
•-x product=".*(Smart|Back)-?UPS.*"

bus = regex

OPTIONNEL, NON RECOMMANDÉ.

Sélectionne un onduleur sur un bus USB spécifique ou un groupe de bus. L'argument est une expression régulière qui doit correspondre au nom du bus sur lequel l'onduleur est connecté (par exemple, bus="002" ou bus="00[2-3]") tel qu'il apparaît sous Linux dans /sys/bus/usb/devices ou lsusb(8) ; y compris les zéros initiaux.


Note
Les numéros de bus ne sont pas garantis par le système d'exploitation pour être stables entre les redémarrages, les rechargements de pilotes de noyau ou les rebranchements de périphériques (par exemple, changer la population visible des hubs USB).

device = regex

OPTIONNEL, NON RECOMMANDÉ.

Sélectionne un onduleur sur un périphérique USB spécifique ou un groupe de périphériques. L'argument est une expression régulière qui doit correspondre au nom du périphérique auquel l'onduleur est connecté (par exemple, device="001" ou device="00[1-2]") tel qu'il apparaît sous Linux dans /sys/bus/usb/devices ou lsusb(8) ; y compris les zéros initiaux.


Note
Les numéros de périphériques ne sont pas garantis par le système d'exploitation pour être stables entre les redémarrages ou les rebranchements de périphériques.

busport = regex

OPTIONNEL, NON RECOMMANDÉ.

Si pris en charge par le matériel, le système d'exploitation et libusb dans le déploiement particulier, cette option devrait permettre de spécifier les numéros de port physiques sur un hub USB, plutôt que les valeurs d'énumération logiques des périphériques, et par conséquent — cela devrait être moins volatile entre les redémarrages ou les rebranchements. La valeur peut être vue dans la sortie de topologie USB de lsusb -tv sur les systèmes disposant de cet outil, par exemple.


Note
Cette option n'est pas pratiquement prise en charge par certaines versions de NUT (elle devrait alors être ignorée avec un avertissement), et pas par tous les systèmes sur lesquels NUT peut fonctionner.

allow_duplicates

OPTIONNEL, NON RECOMMANDÉ.

Si vous avez plusieurs appareils d'onduleur qui ne peuvent pas être identifiés de manière unique par les options ci-dessus (par exemple, seul le VID:PID peut y être découvert), ce drapeau permet à chaque instance de pilote où il est défini de prendre la première correspondance disponible, ou de continuer à en essayer une autre.

Normalement, l'initialisation du pilote s'arrêterait à ce stade en signalant "Ressource occupée" ou une erreur similaire, en supposant que l'appareil, autrement correctement mis en correspondance, est unique — et qu'un autre processus le gère déjà.


Attention
Cette fonctionnalité est intrinsèquement non déterministe ! L'association du nom de l'instance du pilote avec le périphérique réel peut varier entre les exécutions !

Si vous voulez seulement savoir qu'au moins un de vos onduleurs sans nom est en ligne, cette option peut aider.

Si vous devez vraiment savoir lequel, cela ne le fera pas !

usb_set_altinterface = bAlternateSetting

Force un appel redondant à usb_set_altinterface(), surtout si nécessaire pour les périphériques assurant plusieurs rôles USB où l'onduleur n'est pas représenté par l'interface numéro 0 (par défaut).

usb_config_index, usb_hid_rep_index, usb_hid_desc_index, usb_hid_ep_in, usb_hid_ep_out

Force l'utilisation d'indices d'interface, de points de terminaison, de descripteurs, etc. spécifiques, plutôt que de prendre par défaut 0 (rarement d'autres valeurs dans certains pilotes pour certains périphériques connus pour utiliser des nombres non nuls). Spécifié sous forme de nombre hexadécimal.

En règle générale pour la découverte de usb_hid_desc_index, vous pouvez voir de plus grandes valeurs wDescriptorLength (environ 600+ octets) dans les rapports de lsusb ou d'outils similaires.

LIBUSB_DEBUG = ENTIER

Le dépannage à l'exécution des pilotes NUT compatibles USB peut impliquer non seulement l'augmentation de la verbosité commune du débogage NUT (par exemple, en utilisant le paramètre DEBUG_MIN dans ups.conf(5) ou des commandes de protocole pour modifier la valeur driver.debug), mais peut également bénéficier du débogage spécifique à LibUSB.

Sélectionne une UPS spécifique par son identifiant unique d'UPS. L'argument est une expression régulière qui doit correspondre à la chaîne de l'identifiant d'UPS. Cela permet une identification précise des appareils UPS lorsque plusieurs appareils de même marque et modèle sont connectés. Voir ci-dessous comment lire et écrire l'identifiant d'UPS (id d'unité) à l'aide de upsrw(8).


Notes pour le pilote tripplite_usb gérant les paramètres courants de correspondance USB :
•product est une expression régulière pour faire correspondre la chaîne du produit de l'UPS. Ce serait utile si vous avez deux modèles d'UPS Tripp Lite différents connectés au même système de surveillance, et que vous voulez être sûr de les arrêter dans le bon ordre.

Cette expression régulière est mise en correspondance avec la chaîne de produit USB complète telle qu'elle apparaît dans lsusb(8). L'attribut ups.model dans la sortie de upsc(8) ne liste que le nom après TRIPP LITE, donc pour faire correspondre un SMART2200RMXL2U, vous pourriez utiliser une expression régulière comme .*SMART2200.*.

•Le productid est une expression régulière qui correspond à l'ID produit de l'UPS sous forme de quatre chiffres hexadécimaux. Jusqu'à présent, les seuls appareils connus qui fonctionnent avec ce pilote ont un ID produit de 0001.
•L'option serial peut être utile ou non : il ne semble pas que ces UPS Tripp Lite particulières prises en charge par ce pilote utilisent le champ descripteur iSerial pour retourner un numéro de série. Cependant, si votre unité le prend en charge, vous pouvez le spécifier ici.

offdelay

Ce réglage contrôle le délai entre la réception de la commande "kill" (-k) et la coupure réelle de l'alimentation de l'ordinateur.

battery_min, battery_max

Ces valeurs flottantes correspondent aux tensions "vides" (10%) et "pleines" (100%) de la batterie. Elles sont utilisées pour une approximation de l'état de charge de la batterie. La valeur calculée de battery.charge sera limitée à la plage de 10 % à 100 %, de sorte que la tension de repos de la batterie chargée puisse être utilisée pour battery_max, et que la tension de charge flottante plus élevée ne pose pas de problème.

VARIABLES D'EXÉCUTION

ups.delay.shutdown

Cette variable est identique au réglage offdelay, mais elle peut être modifiée à l'exécution par upsrw(8).

ups.id

Certains modèles SMARTPRO disposent d'un identifiant d'unité (ups.id) qui peut être défini et récupéré. Si votre UPS prend en charge cette fonctionnalité, cette variable sera répertoriée dans la sortie de upsrw(8).

outlet.1.switch

Certaines unités Tripp Lite ont une prise commutable (généralement la prise n°1) qui peut être allumée et éteinte en écrivant 1 ou 0, respectivement, dans outlet.1.switch avec upsrw(8).

Si votre unité a plusieurs prises commutables, remplacez le numéro de prise par 1 dans le nom de la variable. Assurez-vous de tester ceci d'abord — il n'y a aucun autre moyen de s'assurer que le numéro utilisé par le pilote correspond à l'étiquette sur l'unité.

PROBLÈMES CONNUS ET BOGUES

Le pilote n'a pas été développé avec la documentation officielle de Tripp Lite, donc certains événements peuvent dérouter le pilote. Si vous observez un comportement étrange, veuillez relancer le pilote avec -DDD pour augmenter la verbosité.

Jusqu'à présent, les UPS Tripp Lite ne semblent pas avoir de numéro de série ou d'autre identifiant globalement unique accessible via USB. Ainsi, lors de la surveillance de plusieurs UPS Tripp Lite USB, vous devriez utiliser les options de configuration bus, device ou product pour spécifier uniquement quel UPS une instance de pilote donnée doit contrôler.

Par exemple, vous pouvez facilement surveiller un OMNIVS1000 et un SMART1500RM2U en même temps, car ils ont des chaînes d'ID produit USB différentes. Si vous avez deux unités SMART1500RM2U, vous devrez trouver sur quel bus USB et quel numéro de périphérique chaque unité se trouve (via lsusb(8)).

Certains modèles SMART\*2U ont un numéro d'identifiant d'unité configurable, et vous pouvez maintenant utiliser l'argument de configuration upsid pour spécifier de manière unique quel UPS une instance de pilote donnée doit contrôler. Cela permet une identification précise des appareils UPS lorsque plusieurs appareils sont connectés. Pour récupérer ou définir l'upsid, vous pouvez utiliser l'utilitaire upsrw(8).
