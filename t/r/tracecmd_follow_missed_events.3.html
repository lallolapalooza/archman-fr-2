NOM

tracecmd_iterate_events, tracecmd_iterate_events_multi, tracecmd_follow_event, tracecmd_follow_missed_events, tracecmd_filter_add, tracecmd_iterate_reset - Lire les événements d'un fichier de trace

SYNTAXE

#include <trace-cmd.h>
int tracecmd_iterate_events(struct tracecmd_input *handle,
                            cpu_set_t *cpus, int cpu_size,
                            int (*callback)(struct tracecmd_input *,
                                            struct tep_record *,
                                            int, void *),
                            void *callback_data);
int tracecmd_iterate_events_multi(struct tracecmd_input **handles,
                                  int nr_handles,
                                  int (*callback)(struct tracecmd_input *,
                                                           struct tep_record *,
                                                           int, void *),
                                  void *callback_data);
int tracecmd_iterate_events_reverse(struct tracecmd_input *handle,
                            cpu_set_t *cpus, int cpu_size,
                            int (*callback)(struct tracecmd_input *,
                                            struct tep_record *,
                                            int, void *),
                            void *callback_data, bool cont);
int tracecmd_follow_event(struct tracecmd_input *handle,
                          const char *system, const char *event_name,
                          int (*callback)(struct tracecmd_input *,
                                          struct tep_event *,
                                          struct tep_record *,
                                          int, void *),
                          void *callback_data);
int tracecmd_follow_missed_events(struct tracecmd_input *handle,
                                   int (*callback)(struct tracecmd_input *,
                                                   struct tep_event *,
                                                   struct tep_record *,
                                                   int, void *),
                                   void *callback_data);
struct tracecmd_filter *tracecmd_filter_add(struct tracecmd_input handle,
                                            const char *filter_str, bool neg);
int *tracecmd_iterate_reset(struct tracecmd_input *handle);

DESCRIPTION

Cet ensemble d'API peut être utilisé pour itérer sur les événements après avoir ouvert un fichier de trace à l'aide de l'une des fonctions d'ouverture comme tracecmd_open(3) ou tracecmd_open_fd(3).

La fonction tracecmd_iterate_events() itérera à travers tous les événements du fichier de trace défini par handle, où handle est renvoyé par l'une des fonctions tracecmd_open(3). Elle appellera la fonction callback() sur les événements des CPUs définis par cpus. La taille cpu_size doit être la taille de cpus (voir CPU_SET(3)). Si cpus est NULL, alors cpu_size est ignoré et callback() sera appelé pour tous les événements sur tous les CPUs dans le fichier de trace. callback_data est passé à callback() comme dernier paramètre. callback peut être NULL, ce qui est utile si tracecmd_follow_event() est utilisé, mais notez que si callback est NULL, alors callback_data est ignoré et non envoyé au callback de tracecmd_follow_event().

La fonction tracecmd_iterate_events_multi() est similaire à tracecmd_iterate_events(), sauf qu'elle permet d'itérer sur plus d'un fichier de trace. Si tracecmd agent(1) est utilisé pour obtenir un fichier de trace pour l'hôte et l'invité, assurez-vous que le fichier de trace de l'hôte est la première entrée dans handles et tracecmd_iterate_events_multi() synchronisera les métadonnées pour les fichiers invités qui suivent dans handles. handles est un tableau de descripteurs de fichiers de trace qui ont été ouverts par tracecmd_open(3) et ses similaires. Notez que, contrairement à tracecmd_iterate_events(), tracecmd_iterate_events_multi() ne filtre pas sur les CPUs, car cela rendrait l'API trop complexe pour savoir sur quel handle filtrer les CPUs. Si le filtrage par CPU est souhaité, alors le callback doit vérifier le champ record→cpu et renvoyer 0 s'il ne s'agit pas du CPU souhaité à traiter. nr_handles indique le nombre d'éléments dans handles. callback_data est passé au callback comme dernier paramètre. callback peut être NULL, ce qui est utile si tracecmd_follow_event() est utilisé, mais notez que si callback est NULL, alors callback_data est ignoré et non envoyé au callback de tracecmd_follow_event().

La fonction tracecmd_iterate_events_reverse() fonctionne à peu près de la même manière que tracecmd_iterate_events(), mais au lieu d'appeler la fonction callback() pour chaque événement dans l'ordre du timestamp, elle appellera la fonction callback() pour chaque événement dans l'ordre inverse du timestamp. Si cont est faux, elle commencera par appeler l'événement avec le timestamp le plus ancien dans le fichier trace.dat. Si cont est réglé sur vrai, elle continuera là où la position actuelle des données de traçage se trouve. Par exemple, si le callback() renvoie quelque chose d'autre que zéro, il quittera l'itération. Si tracecmd_iterate_events_reverse() est appelé à nouveau avec cont à vrai, il continuera là où il s'est arrêté. Si cont est faux, il recommencera à l'événement avec le timestamp le plus ancien. Le handle, cpus, cpu_size et callback_data agissent de la même manière que tracecmd_iterate_events().

Le callback() pour tracecmd_iterate_events(), tracecmd_iterate_events_reverse() et tracecmd_iterate_events_multi() a le prototype suivant :

int callback()(struct tracecmd_input *handle, struct tep_record *record, int cpu, void *data);

Le handle est le même handle passé à tracecmd_iterate_events() ou le handle courant de handles passé à tracecmd_iterate_events_multi() auquel le record appartient. Le record est l'enregistrement de l'événement courant. Le cpu est le CPU courant en cours de traitement. Notez que pour tracecmd_iterate_events_multi(), il peut ne pas s'agir du CPU réel du fichier, mais du nième CPU de tous les handles combinés. Utilisez record→cpu pour obtenir le CPU réel sur lequel l'événement se trouve.

La fonction tracecmd_follow_event() s'attachera à un descripteur de fichier de trace handle et appellera le callback lorsque l'événement décrit par system et name correspondra à un événement lors de l'itération de tracecmd_iterate_events() ou tracecmd_iterate_events_multi(). Notez que le cpu est le nième CPU pour tracecmd_iterate_events() et tracecmd_iterate_events_multi(). Si le CPU réel du record est nécessaire, utilisez record→cpu. Pour tracecmd_iterate_events_multi(), le callback n'est appelé que si le handle correspond au descripteur de fichier de trace courant dans handles. Le callback_data est passé comme dernier paramètre à la fonction callback(). Notez que cette fonction callback() sera appelée avant la fonction callback() de tracecmd_iterate_events() ou de tracecmd_iterate_events_multi().

Le prototype du callback() pour *tracecmd_follow_event()_ est :

int callback()(struct tracecmd_input *handle, struct tep_event *event, struct tep_record *_record, int cpu, void *data);

La fonction tracecmd_follow_missed_events() s'attachera à un descripteur de fichier de trace handle et appellera le callback lorsque des événements manqués sont détectés. L'event contiendra le type d'événement que représente le record. Le record contiendra les informations sur les événements manqués. Le cpu est le nième CPU pour tracecmd_iterate_events() et tracecmd_iterate_events_multi(). Si le CPU auquel appartiennent les événements manqués est nécessaire, utilisez record→cpu. Si record→missed_events est un nombre positif, il contient le nombre d'événements manqués depuis le dernier événement sur son CPU, sinon il sera négatif, ce qui signifiera que le nombre d'événements manqués est inconnu mais qu'il y a eu des événements manqués depuis le dernier événement sur le CPU. NOM

tracecmd_iterate_events, tracecmd_iterate_events_reverse, tracecmd_iterate_events_multi, tracecmd_filter_add, tracecmd_iterate_reset - parcourir les événements enregistrés

SYNTAXE

#include <trace-cmd.h>

int
tracecmd_iterate_events(struct tracecmd_input *handle,
                            cpu_set_t *cpuset, size_t cpusetsize,
                            tracecmd_callback_t callback, void *data);
int
tracecmd_iterate_events_reverse(struct tracecmd_input *handle,
                                    cpu_set_t *cpuset, size_t cpusetsize,
                                    tracecmd_callback_t callback, void *data);
int
tracecmd_iterate_events_multi(struct tracecmd_input **handles,
                                  int nr_handles,
                                  tracecmd_callback_t callback, void *data);
struct tracecmd_handle *
tracecmd_filter_add(struct tracecmd_input *handle,
                        const char *filter_str, bool neg);
int
tracecmd_iterate_reset(struct tracecmd_input *handle);

DESCRIPTION

Ces fonctions sont utilisées pour itérer sur les événements enregistrés dans un fichier trace. Les itérateurs peuvent être utilisés pour lire les événements séquentiellement ou en sens inverse.

Les fonctions tracecmd_iterate_events() et tracecmd_iterate_events_reverse() parcourent les événements du fichier spécifié par handle. Si cpuset et cpusetsize ne sont pas NULL, alors seuls les événements des CPUs spécifiés dans le cpuset seront parcourus. Sinon, tous les événements seront parcourus. La fonction callback est appelée pour chaque événement trouvé. Si callback est NULL, alors tracecmd_iterate_events() et tracecmd_iterate_events_reverse() se comportent comme s'ils avaient appelé tracecmd_follow_all_events(). Si callback retourne une valeur non nulle, l'itérateur s'arrête.

La fonction tracecmd_iterate_events_multi() parcourt les événements à partir d'un tableau de handles. Les arguments callback et data sont les mêmes que pour tracecmd_iterate_events().

La fonction callback est une fonction de rappel qui prend les arguments suivants :

typedef int (*tracecmd_callback_t)(struct tracecmd_input *handle,
                                   struct tep_record *record,
                                   int cpu, void *data);

Le membre cpu du record indique le CPU sur lequel l'événement s'est produit. L'argument data est un pointeur vers les données fournies à la fonction d'itération.

Si la fonction callback retourne une valeur non nulle, cela arrête l'itération. La fonction callback est appelée avant les autres callbacks et les filtres ajoutés par tracecmd_filter_add() sont ignorés. Si callback retourne une valeur non nulle, cela arrêtera l'itérateur avant qu'il n'appelle d'autres callbacks de l'itérateur pour l'enregistrement donné.

La fonction tracecmd_filter_add() ajoute un filtre à handle qui affecte à la fois tracecmd_iterate_events() et tracecmd_iterate_events_multi(). Le filter_str est une chaîne de caractères définissant un filtre dans un format défini par tep_filter_add_filter_str(3). Si neg est vrai, alors les événements qui correspondent au filtre seront ignorés, sinon les événements qui correspondent exécuteront la fonction callback() dans les itérateurs.

La fonction tracecmd_iterate_reset() réinitialise handle pour qu'il recommence depuis le début, de sorte que le prochain appel à tracecmd_iterate_events() recommence à partir du premier événement, au lieu de continuer là où il s'était arrêté.

VALEUR DE RETOUR

Toutes les fonctions tracecmd_iterate_events(), tracecmd_iterate_events_reverse() et tracecmd_iterate_events_multi() retournent zéro si elles ont parcouru avec succès tous les événements (en gérant les filtres et les follow-ups appropriés). Ou une valeur d'erreur, qui peut inclure le retour d'un résultat non nul de la fonction callback().

tracecmd_iterate_reset() retourne 0 en cas de succès et -1 en cas d'erreur. Notez que si -1 est retourné, une réinitialisation partielle peut également s'être produite.

EXEMPLE

#define _GNU_SOURCE
#include <sched.h>
#include <stdlib.h>
#include <getopt.h>
#include <trace-cmd.h>
struct private_data {
        int             cpu;
        const char      *file;
};
static int print_events(struct tracecmd_input *handle, struct tep_record *record, int cpu, void *data)
{
        static struct trace_seq seq;
        struct tep_handle *tep = tracecmd_get_tep(handle);
        struct private_data *pdata = tracecmd_get_private(handle);
        /* For multi handles we need this */
        if (pdata->cpu >= 0 && pdata->cpu != record->cpu)
                return 0;
        if (!seq.buffer)
                trace_seq_init(&seq);
        trace_seq_reset(&seq);
        trace_seq_printf(&seq, "%s: ", pdata->file);
        tep_print_event(tep, &seq, record, "%6.1000d [%03d] %s-%d %s: %s\n",
                        TEP_PRINT_TIME, TEP_PRINT_CPU, TEP_PRINT_COMM, TEP_PRINT_PID,
                        TEP_PRINT_NAME, TEP_PRINT_INFO);
        trace_seq_terminate(&seq);
        trace_seq_do_printf(&seq);
        return 0;
}
static int print_event(struct tracecmd_input *handle, struct tep_event *event,
                       struct tep_record *record, int cpu, void *data)
{
        return print_events(handle, record, cpu, data);
}
static int missed_events(struct tracecmd_input *handle, struct tep_event *event,
                         struct tep_record *record, int cpu, void *data)
{
        if (record->missed_events > 0)
                printf("CPU [%03d] has %d missed events\n",
                         record->cpu, record->missed_events);
        else
                printf("CPU [%03d] has missed events\n", record->cpu);
        return 0;
}
static void usage(const char *argv0)
{
        printf("usage: [-c cpu][-f filter][-e event] %s trace.dat [trace.dat ...]\n",
               argv0);
        exit(-1);
}
int main(int argc, char **argv)
{
        struct tracecmd_input **handles = NULL;
        const char *filter_str = NULL;
        const char *argv0 = argv[0];
        struct private_data *priv;
        cpu_set_t *cpuset = NULL;
        char *event = NULL;
        size_t cpusize = 0;
        int nr_handles = 0;
        int cpu = -1;
        int i;
        int c;
        while ((c = getopt(argc, argv, "c:f:e:")) >= 0) {
                switch (c) {
                case 'c':
                        /* filter all trace data to this one CPU. */
                        cpu = atoi(optarg);
                        break;
                case 'f':
                        filter_str = optarg;
                        break;
                case 'e':
                        event = optarg;
                        break;
                default:
                        usage(argv0);
                }
        }
        argc -= optind;
        argv += optind;
        if (argc == 0)
                usage(argv0);
        for (i = 0; i < argc; i++) {
                handles = realloc(handles, sizeof(*handles) * (nr_handles + 1));
                if (!handles)
                        exit(-1);
                handles[nr_handles] = tracecmd_open(argv[i], 0);
                if (!handles[nr_handles]) {
                        perror(argv[i]);
                        exit(-1);
                }
                if (filter_str) {
                        if (tracecmd_filter_add(handles[nr_handles], filter_str, false) == NULL) {
                                perror("adding filter");
                                exit(-1);
                        }
                }
                priv = calloc(1, sizeof(*priv));
                if (!priv)
                        exit(-1);
                priv->file = argv[i];
                priv->cpu = cpu;
                tracecmd_set_private(handles[nr_handles], priv);
                if (event) {
                        if (tracecmd_follow_event(handles[nr_handles], NULL, event, print_event, NULL) < 0) {
                                printf("Could not follow event %s for file %s\n", event, argv[i]);
                                exit(-1);
                        }
                }
                tracecmd_follow_missed_events(handles[nr_handles], missed_events, NULL);
                nr_handles++;
        }
        /* Shortcut */
        if (nr_handles == 1) {
                if (cpu >= 0) {
                        cpuset = CPU_ALLOC(cpu + 1);
                        if (!cpuset)
                                exit(-1);
                        cpusize = CPU_ALLOC_SIZE(cpu + 1);
                        CPU_SET_S(cpu, cpusize, cpuset);
                }
                if (event)
                        tracecmd_iterate_events(handles[0], cpuset, cpusize, NULL, NULL);
                else
                        tracecmd_iterate_events(handles[0], cpuset, cpusize, print_events, NULL);
        } else {
                if (event)
                        tracecmd_iterate_events_multi(handles, nr_handles, NULL, NULL);
                else
                        tracecmd_iterate_events_multi(handles, nr_handles, print_events, NULL);
        }
        for (i = 0; i < nr_handles; i++) {
                priv = tracecmd_get_private(handles[i]);
                free(priv);
                tracecmd_close(handles[i]);
        }
        free(handles);
}

tracecmd_follow_missed_events(3)

NOM

tracecmd_follow_missed_events - Suivre les événements manqués dans une trace

SYNOPSIS

#include <tracecmd.h>

int tracecmd_follow_missed_events(struct tracecmd_input *input,

const char *filename,

tracecmd_event_callback callback,

void *data);

DESCRIPTION

La fonction tracecmd_follow_missed_events parcourt un fichier de trace et appelle le rappel callback pour chaque événement manqué.

input
Un pointeur vers une structure tracecmd_input initialisée.
filename
Le nom du fichier de trace à lire.
callback
Une fonction de rappel à appeler pour chaque événement manqué. La fonction de rappel doit avoir la signature suivante : int (*callback)(struct tracecmd_event *event, void *data); Elle doit retourner 0 pour continuer le traitement et une valeur non nulle pour l'arrêter.
data
Les données personnalisées à passer à la fonction de rappel.

Les événements manqués sont des événements qui ont été perdus en raison d'une saturation du tampon de trace. Ces événements sont généralement représentés par une ligne spéciale dans le fichier de trace.

VALEUR DE RETOUR

Retourne 0 en cas de succès, ou une valeur d'erreur négative en cas d'échec.

tracecmd(1), tracecmd_open(3)
