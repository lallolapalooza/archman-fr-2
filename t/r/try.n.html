NOM

try - Intercepter et traiter les erreurs et les exceptions

SYNOPSIS

try corps ?gestionnaire...? ?finally script?

DESCRIPTION

Cette commande exécute le script corps et, en fonction du résultat de ce script (sortie normale, erreur ou tout autre résultat exceptionnel), exécute un script gestionnaire pour traiter le cas. Une fois tout cela effectué, si la clause finally est présente, le script qu'elle contient sera exécuté et le résultat du gestionnaire (ou du corps si aucun gestionnaire ne correspond) sera autorisé à continuer à se propager. Notez que la clause finally est traitée même si une erreur se produit et quel que soit le gestionnaire utilisé, le cas échéant.

Les clauses gestionnaire sont chacune exprimées en plusieurs mots et doivent avoir l'une des formes suivantes :

on code listeVariables script
Cette clause correspond si l'évaluation de corps s'est terminée avec le code d'exception code. Le code peut être exprimé sous forme d'entier ou de l'un des mots littéraux suivants : ok, error, return, break, ou continue. Ces littéraux correspondent respectivement aux entiers 0 à 4.
trap motif listeVariables script
Cette clause correspond si l'évaluation de corps a abouti à une erreur et que le préfixe de -errorcode du dictionnaire d'état de l'interpréteur est égal au motif. Le nombre de mots préfixés pris dans -errorcode est égal à la longueur de la liste de motif, et les espaces inter-mots sont normalisés dans -errorcode et motif avant la comparaison.

Le mot listeVariables dans chaque gestionnaire est toujours interprété comme une liste de noms de variables. Si le premier mot de la liste est présent et non vide, il nomme une variable dans laquelle le résultat de l'évaluation de corps (du try principal) sera placé ; cela contiendra la forme lisible par l'homme de toute erreur. Si le second mot de la liste est présent et non vide, il nomme une variable dans laquelle le dictionnaire d'options de l'interpréteur au moment de l'achèvement de l'exécution de corps sera placé.

Le mot script de chaque gestionnaire est également toujours interprété de la même manière : comme un script Tcl à évaluer si la clause correspond. Si script est un littéral “-” et que le gestionnaire n'est pas le dernier, le script du gestionnaire suivant est invoqué à la place (tout comme avec la commande switch).

Notez que les clauses gestionnaire sont comparées dans l'ordre et que la première qui correspond est toujours sélectionnée. Au plus une clause gestionnaire sera sélectionnée. Par conséquent, un on error masquera tout trap ultérieur dans le try. Notez également qu'on error équivaut à trap {}.

Si une exception (c'est-à-dire tout résultat différent de ok) survient pendant l'évaluation de la clause gestionnaire ou de la clause finally, le dictionnaire d'état de l'exception d'origine sera ajouté au dictionnaire d'état de la nouvelle exception sous la clé -during.

EXEMPLES

S'assurer qu'un fichier est fermé quoi qu'il arrive :

set f [open /some/file/name a]
try {
    puts $f "some message"
    # ...
} finally {
    close $f
}

Gérer différentes raisons pour lesquelles un fichier ne peut pas être ouvert en lecture :

try {
    set f [open /some/file/name r]
} trap {POSIX EISDIR} {} {
    puts "failed to open /some/file/name: it's a directory"
} trap {POSIX ENOENT} {} {
    puts "failed to open /some/file/name: it doesn't exist"
}
