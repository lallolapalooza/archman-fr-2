NOM

trustman - Gérer les clés utilisées comme ancres de confiance

SYNTAXE

trustman [options]

DESCRIPTION

trustman gère les clés utilisées par DNSSEC comme ancres de confiance conformément à la RFC5011. Il peut être utilisé comme démon pour la vérification continue des clés ou manuellement pour l'initialisation et la vérification des clés ponctuelles.

Par défaut, trustman s'exécute comme un démon pour s'assurer que les clés stockées localement dans les fichiers de configuration correspondent toujours aux mêmes clés récupérées de la zone où elles sont définies. De plus, ces vérifications peuvent être effectuées une fois manuellement (-S) et au premier plan (-f).

Pour chaque vérification de discordance de clé, si des discordances de clé sont détectées, trustman effectue les opérations suivantes :

- définit un minuteur de délai d'attente pour les nouvelles clés ;
- définit un minuteur de délai d'attente pour les clés manquantes ;
- supprime les clés révoquées du fichier de configuration.

Lors des exécutions ultérieures, les minuteurs sont vérifiés. Si les minuteurs ont expiré, les clés sont ajoutées ou supprimées du fichier de configuration, selon le cas.

named.conf et dnsval.conf sont les fichiers de configuration habituels. Ces fichiers doivent être spécifiés dans le fichier de configuration DNSSEC-Tools ou dans les options de la ligne de commande.

OPTIONS

trustman prend un certain nombre d'options, chacune décrite dans cette section. Chaque nom d'option peut être raccourci au nombre minimum de caractères uniques, mais certaines options ont également un alias (comme indiqué.) La forme à une lettre de chaque option est indiquée entre parenthèses, par exemple : -anchor_data_file (-a).

-fichier_donnees_ancre fichier (-a)
Un fichier de données persistant pour stocker les nouvelles clés en attente d'ajout.
-config fichier (-c)
Crée un fichier de configuration pour trustman à partir des options de ligne de commande données. Le fichier de configuration DNSSEC-Tools existant est copié dans le fichier de configuration spécifié, et de nouvelles entrées de configuration sont ajoutées correspondant aux options de ligne de commande. Les entrées spécifiques à trustman déjà présentes dans le fichier de configuration existant seront remplacées par de nouvelles entrées provenant de la ligne de commande. Cela permettra de spécifier moins d'options de ligne de commande à l'avenir.
-fichier_conf_dnsval /chemin/vers/dnsval.conf (-k)
Un fichier dnsval.conf à lire et potentiellement à mettre à jour.
-dtconfig fichier_config (-d)
Nom d'un fichier de configuration DNSSEC-Tools alternatif à traiter. S'il est spécifié, ce fichier de configuration est utilisé *à la place* du fichier de configuration DNSSEC-Tools normal, et non en plus. De plus, il sera traité avant les fichiers *keyrec*, les fichiers *rollrec* et les options de la ligne de commande.
-premier_plan (-f)
S'exécute au premier plan. trustman s'exécutera toujours en boucle. Pour une seule exécution, utilisez plutôt l'option -single_run.
-temps_attente secondes (-w)
La valeur du minuteur de délai d'attente. C'est le nombre de secondes à partir du moment où une nouvelle clé est trouvée. Généralement, la valeur par défaut et recommandée de 30 jours doit être utilisée.
-addr_courriel_contact adresse_courriel (-m)
Adresse de courriel de la personne contact à qui les rapports doivent être envoyés.
-monitor (-M)
Indique que trustman a été exécuté à partir d'un système de surveillance, et un résumé des événements sera imprimé. La spécification de cette option active automatiquement l'option -single_run et désactive l'option -verbose.

Ceci a été développé pour être utilisé avec le système de surveillance Nagios, mais il peut être adapté à d'autres moniteurs.

-fichier_conf_named /chemin/vers/named.conf (-n)
Un fichier named.conf à lire et potentiellement à mettre à jour.
-pas_courriel
Empêche l'envoi de courriels, même si un serveur SMTP a été spécifié dans le fichier de configuration. Ceci est utile pour n'envoyer des notifications que via stdout (-p) ou syslog (-L).
-pas_revocation
Cette option désactive les vérifications du bit de RÉVOCATION.
-pas_erreur (-N)
Envoie un rapport même en l'absence d'erreurs.
-afficher (-p)
Journalise les messages sur stdout.
-fichier_conf_resolv fichier_config (-r)
Un fichier resolv.conf à lire. /dev/null peut être spécifié pour forcer *libval* à répondre récursivement à la requête plutôt qu'à demander à d'autres serveurs de noms.)
-fichier_racine_hints /chemin/vers/root.hints (-o)
Un fichier root.hints à lire.
-execution_unique (-S)
Ne pas boucler, mais exécuter une seule fois.
-temps_sommeil secondes (-t)
Le nombre de secondes à attendre entre les vérifications. Par défaut, 3600 (une heure).
-serveur_smtp nom_serveur_smtp (-s)
Le serveur SMTP que trustman doit utiliser pour envoyer les rapports par courriel.
-syslog (-L)
Journalise les messages dans syslog.
-repertoire_temporaire repertoire (-T)
Spécifie où les fichiers temporaires doivent être créés. Ceci est utilisé lors de la création de nouvelles versions des fichiers dnsval.conf et named.conf avant qu'elles ne soient déplacées.

Les fichiers créés dans ce répertoire seront *renommés* à leur emplacement final. Vous devez vous assurer que ce répertoire, l'emplacement final de dnsval.conf, et l'emplacement final de named.conf se trouvent sur la même partition de disque. La plupart des systèmes d'exploitation ne renomment que les fichiers au sein d'une partition et donneront une erreur si on leur demande de renommer un fichier d'une partition à une autre.

-zone zone (-z)
La zone à vérifier. La spécification de cette option remplace le fichier de configuration par défaut.
-aide (-h)
Affiche un message d'aide.
-verbeux (-v)
Donne une sortie détaillée.
-Version (-V)
Affiche les informations de version pour trustman et le paquet DNSSEC-Tools.

CONFIGURATION

En plus des arguments de la ligne de commande, le fichier dnssec-tools.conf peut être configuré avec les valeurs suivantes pour supprimer la nécessité d'utiliser certaines options de la ligne de commande. Les options de la ligne de commande remplacent toujours les paramètres du fichier dnssec-tools.conf.

fichier_ancres_ta fichier
Ceci spécifie le fichier où les informations d'état de trustman seront conservées. Ceci est équivalent à l'indicateur -fichier_donnees_ancre.
contact_ta email_contact
Ceci est équivalent à l'indicateur -addr_courriel_contact pour spécifier à qui les avis par courriel seront envoyés.
fichier_conf_dnsval_ta fichier
Ceci spécifie le fichier dnsval.conf à lire et à écrire. Ceci est équivalent à l'indicateur -fichier_conf_dnsval.
fichier_conf_named_ta fichier
Ceci spécifie le fichier named.conf à lire et à écrire. Ceci est équivalent à l'indicateur -fichier_conf_named.
fichier_conf_resolv_ta fichier
Ceci spécifie le fichier resolv.conf

taroothintsfile fichier
Ceci spécifie le fichier root.hints à lire. Ceci est équivalent à l'indicateur -root_hints_file.
tasmtpserver nomserveur
Ceci est équivalent à l'indicateur -smtp_server pour spécifier le serveur SMTP auquel les notifications par e-mail seront envoyées.

Voir la note sur le renommage dans la description de l'option -tmp_dir.

CODES DE SORTIE

trustman peut se terminer pour les raisons suivantes :

0 - Exécution réussie. En mode démon, cela peut simplement signifier
    que le démon a été démarré avec succès. Le démon lui-même
    peut se terminer avec une autre erreur.
1 - Options invalides spécifiées.
2 - Aucun fichier new-key spécifié.
3 - Impossible d'ouvrir le fichier new-key.
4 - Impossible de déterminer un ensemble de zones à vérifier.
5 - Une erreur de gestion de fichier a été rencontrée.
