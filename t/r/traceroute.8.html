TRACEROUTE(8) Traceroute pour Linux TRACEROUTE(8)

NOM

traceroute - imprime la trace des paquets vers un hôte réseau

SYNTAXE

traceroute [-46dFITUnreAV] [-f premier_ttl] [-g passerelle,...]
[-i périphérique] [-m ttl_max] [-p port] [-s addr_src]
[-q nrequetes] [-N requetes_simultanées] [-t tos]
[-l etiqueta_flux] [-w temps_attente] [-z attente_envoi] [-UL] [-D]
[-P proto] [--sport=port] [-M methode] [-O options_mod]
[--mtu] [--back]
hote [longueur_paquet]
traceroute6 [options]

DESCRIPTION

traceroute suit la route empruntée par les paquets IP depuis un réseau IP jusqu'à un hôte donné. Il utilise le champ Time To Live (TTL) du protocole IP et tente d'obtenir une réponse ICMP TIME_EXCEEDED de chaque passerelle sur le chemin vers l'hôte.

traceroute6 est équivalent à traceroute -6

Le seul paramètre requis est le nom ou l'adresse IP de l'hôte de destination. La longueur_paquet optionnelle est la taille totale du paquet de sonde (60 octets par défaut pour IPv4 et 80 pour IPv6). La taille spécifiée peut être ignorée dans certaines situations ou augmentée jusqu'à une valeur minimale.

Ce programme tente de tracer la route qu'un paquet IP suivrait vers un hôte Internet en lançant des paquets de sonde avec un TTL faible (temps de vie), puis en écoutant une réponse ICMP "temps dépassé" provenant d'une passerelle. Nous commençons nos sondes avec un TTL de un et augmentons d'un jusqu'à ce que nous obtenions un "port inaccessible" ICMP (ou une réinitialisation TCP), ce qui signifie que nous avons atteint l'"hôte", ou atteint un maximum (qui est de 30 sauts par défaut). Trois sondes (par défaut) sont envoyées à chaque réglage de TTL et une ligne est imprimée montrant le TTL, l'adresse de la passerelle et le temps de trajet aller-retour de chaque sonde. L'adresse peut être suivie d'informations supplémentaires lorsque cela est demandé. Si les réponses des sondes proviennent de passerelles différentes, l'adresse de chaque système répondant sera imprimée. S'il n'y a pas de réponse dans un délai imparti, un "*" (astérisque) est imprimé pour cette sonde.

Après le temps de trajet, une annotation supplémentaire peut être imprimée : !H, !N, ou !P (hôte, réseau ou protocole inaccessible), !S (échec du routage source), !F (fragmentation requise), !X (communication interdite par administration), !V (violation de la précédence de l'hôte), !C (priorité tronquée en vigueur), ou !<num> (code d'inaccessibilité ICMP <num>). Si presque toutes les sondes entraînent une forme d'inaccessibilité, traceroute abandonnera et se terminera.

Nous ne voulons pas que l'hôte de destination traite les paquets de sonde UDP, nous définissons donc le port de destination sur une valeur peu probable (vous pouvez la modifier avec le drapeau -p). Il n'y a pas un tel problème pour le traçage ICMP ou TCP (pour TCP, nous utilisons une technique semi-ouverte, qui empêche nos sondes d'être vues par les applications sur l'hôte de destination).

Dans l'environnement réseau moderne, les méthodes traditionnelles de traceroute peuvent ne pas toujours être applicables, en raison de l'utilisation répandue des pare-feux. Ces pare-feux filtrent les ports UDP "peu probables", voire les échos ICMP. Pour résoudre ce problème, des méthodes de traçage supplémentaires sont implémentées (y compris TCP), voir la section LISTE DES MÉTHODES DISPONIBLES ci-dessous. Ces méthodes tentent d'utiliser un protocole et un port source/destination particuliers, afin de contourner les pare-feux (pour être vu par les pare-feux comme simplement le début d'un type de session réseau autorisé).

OPTIONS

--help
Imprime les informations d'aide et quitte.
-4, -6
Force explicitement le traçage IPv4 ou IPv6. Par défaut, le programme essaiera de résoudre le nom donné et choisira automatiquement le protocole approprié. Si la résolution d'un nom d'hôte renvoie des adresses IPv4 et IPv6, traceroute utilisera IPv4.
-I, --icmp
Utilise ECHO ICMP pour les sondes.
-T, --tcp
Utilise SYN TCP pour les sondes.
-d, --debug
Active le débogage au niveau des sockets (lorsque le noyau Linux le prend en charge).
-F, --dont-fragment
Ne pas fragmenter les paquets de sonde. (Pour IPv4, il définit également le bit DF, qui indique aux routeurs intermédiaires de ne pas fragmenter non plus à distance.

En faisant varier la taille du paquet de sonde avec le paramètre de ligne de commande longueur_paquet, vous pouvez obtenir manuellement des informations sur la MTU des sauts réseau individuels. L'option --mtu (voir ci-dessous) tente de le faire automatiquement.

Notez que les fonctionnalités de non-fragmentation (comme -F ou --mtu) ne fonctionnent correctement que depuis le noyau Linux 2.6.22. Avant cette version, IPv6 était toujours fragmenté, IPv4 pouvait utiliser uniquement la MTU finale découverte (depuis le cache de routage), qui peut être inférieure à la MTU réelle d'un périphérique.

-f premier_ttl, --first=premier_ttl
Spécifie le TTL de départ. Par défaut 1.
-g passerelle, --gateway=passerelle
Indique à traceroute d'ajouter une option de routage source IP au paquet de sortie qui indique au réseau de router le paquet via la passerelle spécifiée (la plupart des routeurs ont désactivé le routage source pour des raisons de sécurité). En général, plusieurs passerelles sont autorisées (séparées par des virgules). Pour IPv6, la forme num,addr,addr... est autorisée, où num est un type d'en-tête de routage (par défaut type 2). Notez que l'en-tête de routage de type 0 est maintenant obsolète (rfc5095).
-i interface, --interface=interface
Spécifie l'interface via laquelle traceroute doit envoyer les paquets. Par défaut, l'interface est sélectionnée selon la table de routage.
-m ttl_max, --max-hops=ttl_max
Spécifie le nombre maximum de sauts (valeur maximale de temps de vie) que traceroute sondera. Par défaut, il est de 30.
-N requetes_simultanées, --sim-queries=requetes_simultanées
Spécifie le nombre de paquets de sonde envoyés simultanément. L'envoi de plusieurs sondes simultanément peut considérablement accélérer traceroute. La valeur par défaut est 16.
Notez que certains routeurs et hôtes peuvent utiliser la limitation du débit ICMP. Dans une telle situation, spécifier un nombre trop élevé peut entraîner la perte de certaines réponses.
-n
N'essaie pas de mapper les adresses IP aux noms d'hôtes lors de leur affichage.
-p port, --port=port
Pour le traçage UDP, spécifie le port de destination de base que traceroute utilisera (le numéro de port de destination sera incrémenté par chaque sonde).
Pour le traçage ICMP, spécifie la valeur initiale de séquence ICMP (également incrémentée par chaque sonde).
Pour TCP et autres, spécifie uniquement le port de destination (constant) auquel se connecter.
-t tos, --tos=tos
Pour IPv4, définit le Type de Service (TOS) et la valeur de précédence. Les valeurs utiles sont 16 (délai faible) et 8 (débit élevé). Notez que pour utiliser certaines valeurs de précédence TOS, vous devez être superutilisateur.
Pour IPv6, définit la valeur de contrôle de trafic.
-l etiqueta_flux, --flowlabel=etiqueta_flux
Utilise l'étiquette de flux spécifiée pour les paquets IPv6.
-w max[,ici,proche], --wait=max[,ici,proche]
Détermine combien de temps attendre pour une réponse à une sonde.

Il y a trois valeurs (en général) flottantes séparées par une virgule (ou une barre oblique). Max spécifie le temps maximum (en secondes, par défaut 5.0) à attendre, dans tous les cas.

Déterminer la durée réelle et raisonnable d'attente.

La valeur optionnelle ici (par défaut 3.0) spécifie un facteur pour multiplier le temps d'aller-retour d'une réponse déjà reçue du **même** saut. La valeur résultante est utilisée comme délai d'attente pour la sonde, au lieu de (mais pas plus que) max. La valeur optionnelle proche (par défaut 10.0) spécifie un facteur similaire pour une réponse d'un **prochain** saut. (Le temps du premier résultat trouvé est utilisé dans les deux cas).

Premièrement, nous recherchons le **même** saut (de la sonde qui sera imprimée en premier à partir de maintenant). Si rien n'est trouvé, alors recherchez un **prochain** saut. Si rien n'est trouvé, utilisez max. Si ici et/ou proche ont des valeurs nulles, le calcul correspondant est ignoré.
Ici et proche sont toujours définis sur zéro si seul max est spécifié (pour la compatibilité avec les versions précédentes).

-q nrequêtes, --requêtes=nrequêtes
Définit le nombre de paquets de sonde par saut. La valeur par défaut est 3.
-r
Ignore les tables de routage normales et envoie directement à un hôte sur un réseau attaché. Si l'hôte n'est pas sur un réseau directement attaché, une erreur est renvoyée. Cette option peut être utilisée pour pinguer un hôte local via une interface qui n'a pas de route qui la traverse.
-s adresse_source, --source=adresse_source
Choisit une adresse source alternative. Notez que vous devez sélectionner l'adresse de l'une des interfaces. Par défaut, l'adresse de l'interface sortante est utilisée.
-z attente_envoi, --attente-envoi=attente_envoi
Intervalle de temps minimum entre les sondes (par défaut 0). Si la valeur est supérieure à 10, elle spécifie un nombre en millisecondes, sinon c'est un nombre de secondes (les valeurs flottantes sont également autorisées). Utile lorsque certains routeurs utilisent une limite de débit pour les messages ICMP.
-e, --extensions
Affiche les extensions ICMP (rfc4884). La forme générale est CLASSE/TYPE: suivie d'un vidage hexadécimal. Le MPLS (rfc4950) est affiché analysé, sous la forme : MPLS:L=label,E=exp_use,S=stack_bottom,T=TTL (plusieurs objets séparés par / ). Les informations d'interface (rfc5837) sont également analysées, sous la forme suivante : {INC|SUB|OUT|NXT}:index,IP_addr,"nom",mtu=MTU (les quatre champs peuvent être manquants).
-A, --recherches-chemin-as
Effectue des recherches de chemin AS dans les registres de routage et affiche les résultats directement après les adresses correspondantes.
-V, --version
Affiche la version et quitte.

Il existe des options supplémentaires destinées à un usage avancé (telles que des méthodes de traçage alternatives, etc.) :

--sport=port
Choisit le port source à utiliser. Implique -N 1 -w 5. Normalement, les ports source (si applicables) sont choisis par le système.
--fwmark=marque
Définit la marque du pare-feu pour les paquets sortants (depuis le noyau Linux 2.6.25).
-M méthode, --module=nom
Utilise la méthode spécifiée pour les opérations de traceroute. La méthode UDP traditionnelle par défaut a le nom default, icmp (-I) et tcp (-T) ont respectivement les noms icmp et tcp.
Des options spécifiques à la méthode peuvent être passées via -O . La plupart des méthodes ont leurs raccourcis simples, (-I signifie -M icmp, etc.).
-O option, --options=options
Spécifie une option spécifique à la méthode. Plusieurs options sont séparées par une virgule (ou utilisez plusieurs -O sur la ligne de commande). Chaque méthode peut avoir ses propres options spécifiques, ou aucune. Pour afficher des informations sur les options disponibles, utilisez -O help.
-U, --udp
Utilise UDP vers un port de destination particulier pour le traceroute (au lieu d'incrémenter le port pour chaque sonde). Le port par défaut est 53 (dns).
-UL
Utilise UDPLITE pour le traceroute (le port par défaut est 53).
-D, --dccp
Utilise des requêtes DCCP pour les sondes.
-P protocole, --protocole=protocole
Utilise un paquet brut du protocole spécifié pour le traceroute. Le protocole par défaut est 253 (rfc3692).
--mtu
Découvre la MTU le long du chemin tracé. Implique -F -N 1. La nouvelle mtu est affichée une fois sous la forme F=NUM lors de la première sonde d'un saut qui nécessite une telle mtu pour être atteinte. (En fait, le message ICMP correspondant "frag needed" est normalement envoyé par le saut précédent).

Notez que certains routeurs peuvent mettre en cache les informations vues une fois sur la fragmentation. Ainsi, vous pouvez recevoir la MTU finale d'un saut plus proche. Essayez de spécifier un tos inhabituel avec -t , cela peut aider pour une tentative (puis il peut également être mis en cache là-bas).
Voir l'option -F pour plus d'informations.

--back
Affiche le nombre de sauts arrière lorsqu'il semble différent de la direction avant. Ce nombre est estimé en supposant que les sauts distants envoient des paquets de réponse avec le TTL initial défini sur 64, 128 ou 255 (ce qui semble être une pratique courante). Il est affiché comme une valeur négative sous la forme '-NUM'.

LISTE DES MÉTHODES DISPONIBLES

En général, une méthode de traceroute particulière peut devoir être choisie par -M nom, mais la plupart des méthodes ont leurs simples commutateurs de ligne de commande (vous pouvez les voir après le nom de la méthode, s'ils sont présents).

défaut

La méthode traditionnelle et ancienne de traceroute. Utilisée par défaut.

Les paquets de sonde sont des datagrammes UDP avec des ports de destination dits "improbables". Le port "improbable" de la première sonde est 33434, puis pour chaque sonde suivante, il est incrémenté de un. Comme les ports sont censés être inutilisés, l'hôte de destination renvoie normalement "icmp unreach port" comme réponse finale. (Personne ne sait ce qui se passe lorsque certaines applications écoutent de tels ports, cependant).

Cette méthode est autorisée pour les utilisateurs non privilégiés.

icmp       -I

La méthode la plus courante à l'heure actuelle, qui utilise des paquets d'écho ICMP pour les sondes.
Si vous pouvez pinguer(8) l'hôte de destination, le traceroute ICMP est également applicable.

Cette méthode peut être autorisée pour les utilisateurs non privilégiés depuis le noyau 3.0 (IPv4, pour IPv6 depuis 3.11), qui prend en charge les nouveaux sockets dgram icmp (ou "ping"). Pour autoriser de tels sockets, l'administrateur système doit fournir la plage sysctl net/ipv4/ping_group_range pour correspondre à n'importe quel groupe de l'utilisateur.
Options :

raw
Utilise uniquement les sockets bruts (la manière traditionnelle).
Cette voie est essayée en premier par défaut (pour des raisons de compatibilité), puis de nouveaux sockets dgram icmp en secours.
dgram
Utilise uniquement les sockets dgram icmp.

tcp        -T

Méthode moderne bien connue, conçue pour contourner les pare-feu.
Utilise le port de destination constant (par défaut 80, http).

Si certains filtres sont présents dans le chemin réseau, alors il est très probable que tous les ports UDP "improbables" (comme pour la méthode défaut) ou même les échos ICMP (comme pour icmp) soient filtrés, et tout le traceroute s'arrêtera simplement à un tel pare-feu. Pour contourner un filtre réseau, nous devons utiliser uniquement des combinaisons de protocoles/ports autorisées. Si nous traçons pour un serveur de messagerie, par exemple, il est plus probable que -T -p 25 puisse l'atteindre, même lorsque -I ne le peut pas.

Cette méthode utilise la technique bien connue du "half-open", qui empêche les applications sur l'hôte de destination de voir nos sondes. Normalement, un syn TCP est envoyé. Pour les ports non écoutés, nous recevons un reset TCP, et tout est terminé. Pour les ports activement écoutés, nous recevons un syn+ack TCP, mais nous répondons par un reset TCP (au lieu du ack TCP attendu), de cette façon la session TCP distante est abandonnée sans même que l'application ne s'en aperçoive.

Il existe quelques options pour la méthode tcp :

syn,ack,fin,rst,psh,urg,ece,cwr
Définit les drapeaux TCP spécifiés pour le paquet de sonde, dans n'importe quelle combinaison.
flags=num
Définit le champ des drapeaux dans l'en-tête TCP exactement à num.
ecn
Envoie un paquet syn avec les drapeaux TCP ECE et CWR (pour Explicit Congestion Notification, rfc3168).
sack,timestamps,window_scaling
Utilise l'option d'en-tête TCP correspondante dans le paquet de sonde sortant.
sysctl
Utilise le paramètre sysctl actuel (/proc/sys/net/*) pour les options d'en-tête TCP ci-dessus et ecn. Toujours défini par défaut, si rien d'autre n'est spécifié.
fastopen
Utilise l'option TCP fastopen (lors de syn), uniquement pour la négociation initiale du cookie.
mss=[num]
Utilise la valeur de num (ou non modifiée) pour l'option d'en-tête TCP maxseg (lors de syn), et découvre son limitation le long du chemin tracé. Le nouveau mss modifié est affiché une fois sous la forme M=NUM lors de la première sonde pour laquelle il a été détecté. Notez que certains routeurs peuvent renvoyer

LIST OF AVAILABLE METHODS

tcp        -T

Use tcp SYN datagrams for probes. This is the default method. It is the most common method because it is less intrusive. Routers do not send ICMP error messages if they receive a SYN packet for a port for which they do not have a listener. So, we will not receive ICMP `Destination unreachable' messages.

Note that routers are not the only ones to consider. A probe datagram may be discarded by the final tcp connection handler, also. For that reason, this method may not be able to discover the final hop. (For more info, see the info option).

This method is allowed for unprivileged users, if they have root privileges, they may be able to use spoofed packets (see the option -s for more details).

Options:

TTL
Set the initial TTL for probes.
port=num
Set destination port to num (default 33434).
source=addr
Set source IP address to addr.
seq
Use sequence numbers for probes.
ack=num
Use num as ACK number.
window=num
Use num as window size.
mss=num
Use num as mss value.
-TTL
Set the initial TTL for probes.
sack
Enable sack.
timestamps
Enable timestamps.
window_scaling
Enable window scaling.
fastopen
Enable fastopen.
sysctl
Try to use RFC1323 options (timestamp, window scaling, echo, sack, etc.). These options are not supported by all systems, so they are set dynamically. See also info option. This is default.
syn
This is default.

If no options are specified, the default options are syn,sysctl.

info

Print tcp flags and supported options of final tcp replies when the target host is reached. Allows to determine whether an application listens the port and other useful things. Supported tcp options are all that can be set by -T -O, ie. mss, sack, timestamps, window_scaling and fastopen, with the similar output format (a value for mss and just presence for others).

Default options is syn,sysctl.

tcpconn

An initial implementation of tcp method, simple using connect(2) call, which does full tcp session opening. Not recommended for normal use, because a destination application is always affected (and can be confused).

udp        -U

Use udp datagram with constant destination port (default 53, dns).
Intended to bypass firewall as well.

Note, that unlike in tcp method, the correspond application on the destination host always receive our probes (with random data), and most can easily be confused by them. Most cases it will not respond to our packets though, so we will never see the final hop in the trace. (Fortunately, it seems that at least dns servers replies with something angry).

This method is allowed for unprivileged users.

udplite    -UL

Use udplite datagram for probes (with constant destination port, default 53).

This method is allowed for unprivileged users.
Options:

coverage=num
Set udplite send coverage to num.

dccp    -D

Use DCCP Request packets for probes (rfc4340).

This method uses the same "half-open technique" as used for TCP. The default destination port is 33434.

Options:

service=num
Set DCCP service code to num (default is 1885957735).

raw        -P proto

Send raw packet of protocol proto.
No protocol-specific headers are used, just IP header only.
Implies -N 1 -w 5 .
Options:

protocol=proto
Use IP protocol proto (default 253).

NOTES

To speed up work, normally several probes are sent simultaneously. On the other hand, it creates a "storm of packages", especially in the reply direction. Routers can throttle the rate of icmp responses, and some of replies can be lost. To avoid this, decrease the number of simultaneous probes, or even set it to 1 (like in initial traceroute implementation), i.e. -N 1

The final (target) host can drop some of the simultaneous probes, and might even answer only the latest ones. It can lead to extra "looks like expired" hops near the final hop. We use a smart algorithm to auto-detect such a situation, but if it cannot help in your case, just use -N 1 too.

For even greater stability you can slow down the program's work by -z option, for example use -z 0.5 for half-second pause between probes.

To avoid an extra waiting, we use adaptive algorithm for timeouts (see -w option for more info). It can lead to premature expiry (especially when response times differ at times) and printing "*" instead of a time. In such a case, switch this algorithm off, by specifying -w with the desired timeout only (for example, -w 5).

If some hops report nothing for every method, the last chance to obtain something is to use ping -R command (IPv4, and for nearest 8 hops only).
