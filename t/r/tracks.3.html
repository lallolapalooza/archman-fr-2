void LIBMTP_destroy_track_t (LIBMTP_track_t * track)

Ceci détruit une structure de métadonnées de piste et désalloue la mémoire utilisée par celle-ci, y compris les chaînes de caractères. N'utilisez jamais une structure de métadonnées de piste après avoir appelé cette fonction dessus.

Paramètres

track les métadonnées de piste à détruire.

int LIBMTP_Get_Track_To_File (LIBMTP_mtpdevice_t * device, uint32_t const id, char const *const path, LIBMTP_progressfunc_t const callback, void const *const data)

Ceci récupère une piste du périphérique vers un fichier identifié par un nom de fichier. Ceci est en fait juste un wrapper pour la fonction LIBMTP_Get_File_To_File().

Paramètres

device un pointeur vers le périphérique à partir duquel récupérer la piste.
id l'ID de la piste à récupérer.
path un nom de fichier à utiliser pour la piste récupérée.
callback une fonction d'indicateur de progression ou NULL pour ignorer.
data un pointeur défini par l'utilisateur qui est transmis à la fonction de progression afin de transmettre des données définies par l'utilisateur aux mises à jour de progression. S'il n'est pas utilisé, définissez-le sur NULL.

Retourne

0 si le transfert a réussi, toute autre valeur signifie un échec.

tracklist = LIBMTP_Get_Tracklisting_With_Callback_For_Storage(device, storage_id, callback, data);
while (tracklist != NULL) {

  // Faites quelque chose avec chaque élément de la liste ici...

  tracklist = tracklist->next;
  LIBMTP_destroy_track_t(tmp);

LIBMTP_track_t * LIBMTP_Get_Trackmetadata (LIBMTP_mtpdevice_t * device, uint32_t const trackid)

Cette fonction récupère les métadonnées d'une seule piste de l'appareil.

N'appelez pas cette fonction de manière répétée ! Les handles de piste sont recherchés linéairement O(n) et l'appel peut impliquer du trafic USB (lent), utilisez donc LIBMTP_Get_Tracklisting() et mettez les pistes en cache, de préférence dans une structure de données efficace telle qu'une liste de hachage.

Paramètres

device un pointeur vers l'appareil à partir duquel obtenir les métadonnées de la piste.
trackid l'ID objet de la piste pour laquelle vous souhaitez obtenir les métadonnées.

Retourne

une entrée de métadonnées de piste en cas de succès ou NULL en cas d'échec.

int LIBMTP_Send_Track_From_File (LIBMTP_mtpdevice_t * device, char const *const path, LIBMTP_track_t *const metadata, LIBMTP_progressfunc_t const callback, void const *const data)

Cette fonction envoie une piste d'un fichier local vers un appareil MTP. Un nom de fichier et un ensemble de métadonnées doivent être fournis en entrée.

Paramètres

device un pointeur vers l'appareil auquel envoyer la piste.
path le nom du fichier local qui sera envoyé.
metadata un ensemble de métadonnées de piste à écrire avec le fichier. Après cet appel, le champ metadata->item_id contiendra le nouvel ID de la piste. D'autres champs tels que metadata->filename, metadata->parent_id ou metadata->storage_id peuvent également changer pendant cette opération en raison des restrictions de l'appareil, ne vous fiez donc pas au contenu de cette structure pour qu'il soit préservé d'une quelconque manière.
  • metadata->parent_id doit être défini sur le parent (par exemple, dossier) dans lequel stocker cette piste. Comme certains appareils sont un peu pointilleux sur l'emplacement des fichiers, un dossier par défaut sera choisi si libmtp a détecté un dossier pour le type de fichier actuel et que ce paramètre est défini sur 0. Si celui-ci est 0 et qu'aucun dossier par défaut ne peut être trouvé, le fichier sera stocké dans le dossier racine.
  • metadata->storage_id doit être défini sur le stockage souhaité (par exemple, carte mémoire ou tout ce que votre appareil présente) pour stocker cette piste. Le définir sur 0 stockera la piste sur le stockage principal.

callback une fonction d'indicateur de progression ou NULL pour l'ignorer.
data un pointeur défini par l'utilisateur qui est transmis à la fonction de progression afin de transmettre des données définies par l'utilisateur aux mises à jour de progression. S'il n'est pas utilisé, définissez-le sur NULL.

Retourne

0 si le transfert a réussi, toute autre valeur signifie un échec.

    int LIBMTP_Send_Track_From_File (LIBMTP_mtpdevice_t * device, const char * filename, LIBMTP_track_t *const metadata, LIBMTP_progressfunc_t const callback, void const *const data)

    This function sends a track to an MTP device. A filename and a set of metadata must be given as input.

    Parameters

    device a pointer to the device to send the track to.
    filename the name of the track to send.
    metadata a track metadata set to be written along with the file. After this call the field metadata->item_id will contain the new track ID. Other fields such as the metadata->filename, metadata->parent_id or metadata->storage_id may also change during this operation due to device restrictions, so do not rely on the contents of this struct to be preserved in any way.
    • metadata->parent_id should be set to the parent (e.g. folder) to store this track in. Since some devices are a bit picky about where files are placed, a default folder will be chosen if libmtp has detected one for the current filetype and this parameter is set to 0. If this is 0 and no default folder can be found, the file will be stored in the root folder.
    • metadata->storage_id should be set to the desired storage (e.g. memory card or whatever your device presents) to store this track in. Setting this to 0 will store the track on the primary storage.

    callback a progress indicator function or NULL to ignore.
    data a user-defined pointer that is passed along to the progress function in order to pass along some user defined data to the progress updates. If not used, set this to NULL.

    Returns

    0 if the transfer was successful, any other value means failure.

    This function updates the MTP track object metadata on a single file identified by an object ID.

    Parameters

    device a pointer to the device to update the track metadata on.
    metadata a track metadata set to be written to the file. notice that the track_id field of the metadata structure must be correct so that the function can update the right file. If some properties of this metadata are set to NULL (strings) or 0 (numerical values) they will be discarded and the track will not be tagged with these blank values.

    Returns

    0 on success, any other value means failure. If some or all of the properties fail to update we will still return success. On some devices (notably iRiver T30) properties that exist cannot be updated.
