LIBTRACEFS(3) Manuel libtracefs LIBTRACEFS(3)

NOM

tracefs_cpu_open_mapped, tracefs_cpu_is_mapped, tracefs_mapped_is_supported, tracefs_cpu_map, tracefs_cpu_unmap - Mappage mémoire du tampon circulaire

SYNOPSIS

#include <tracefs.h>
bool tracefs_cpu_is_mapped(struct tracefs_cpu *tcpu);
bool tracefs_mapped_is_supported(void);
int tracefs_cpu_map(struct tracefs_cpu *tcpu);
void tracefs_cpu_unmap(struct tracefs_cpu *tcpu);
struct tracefs_cpu *tracefs_cpu_open_mapped(struct tracefs_instance *instance,
                                            int cpu, bool nonblock);

DESCRIPTION

Si trace_pipe_raw prend en charge le mappage mémoire, c'est généralement une méthode plus efficace pour lire les données du tampon circulaire du noyau que la lecture simple, car elle n'implique pas de copie de la mémoire lue.

Si le mappage mémoire est pris en charge par le noyau et que l'application demande à utiliser le mappage mémoire via tracefs_cpu_map() ou tracefs_cpu_open_mapped(), alors les fonctions tracefs_cpu_read(3) et tracefs_cpu_read_buf(3) utiliseront directement le mappage au lieu d'appeler l'appel système de lecture.

Notez que le mappage forcera tracefs_cpu_buffered_read(3) et tracefs_cpu_buffered_read_buf(3) à se comporter comme tracefs_cpu_read(3) et tracefs_cpu_read_buf(3) respectivement, car il n'est pas logique d'utiliser un pipe de "splice" lorsqu'il est mappé. Le noyau effectuera une copie pour les lectures avec splice sur le mappage, puis une autre copie dans la fonction lorsqu'il pourrait éviter la copie si le tampon circulaire est mappé en mémoire.

Si le tcpu est mappé en mémoire, cela forcera également tracefs_cpu_write(3) et tracefs_cpu_pipe(3) à copier depuis le mappage au lieu d'utiliser splice. Par conséquent, il faut être prudent lors de la décision de mapper ou non le tampon circulaire, et c'est pourquoi il n'est pas mappé par défaut.

La fonction tracefs_cpu_is_mapped() retournera vrai si tcpu a actuellement son tampon circulaire mappé en mémoire et faux sinon. Cela n'indique pas si le noyau prend en charge le mappage mémoire, mais cela peut généralement être déterminé en appelant tracefs_cpu_map().

La fonction tracefs_mapped_is_supported() retourne vrai si le tampon circulaire peut être mappé en mémoire.

La fonction tracefs_cpu_map() tentera de mapper le tampon circulaire associé à tcpu s'il n'est pas déjà mappé.

La fonction tracefs_cpu_unmap() démappe le tampon circulaire associé à tcpu s'il est mappé.

La fonction tracefs_cpu_open_mapped() est équivalente à l'appel de tracefs_cpu_open(3) suivi de tracefs_cpu_map() sur le tcpu retourné par tracefs_cpu_open(3). Notez que cela réussira toujours même si le mappage échoue, auquel cas il se comportera de la même manière que tracefs_cpu_open(3). Si l'on veut savoir si le mappage a réussi ou non, il faut appeler tracefs_cpu_is_mapped() sur le tcpu retourné.

VALEUR DES RETOURS

tracefs_cpu_is_mapped() retourne vrai si le tcpu donné a son tampon circulaire mappé en mémoire ou faux sinon.

tracefs_mapped_is_supported() retourne vrai si le tampon circulaire de traçage peut être mappé en mémoire ou faux s'il ne le peut pas ou si une erreur s'est produite.

tracefs_cpu_map() retourne 0 en cas de succès et -1 en cas d'erreur lors du mappage. Si 0 est retourné, alors tracefs_cpu_is_mapped() retournera vrai ensuite, ou faux si le mappage a échoué.

tracefs_cpu_open_mapped() retourne un tracefs_cpu alloué en cas de succès de création, que le mappage du tampon circulaire ait réussi ou non. Il retourne NULL pour les mêmes raisons que tracefs_cpu_open(3) retourne NULL. Si le succès du mappage doit être connu, alors appeler tracefs_cpu_is_mapped() ensuite est nécessaire.

EXEMPLE

#include <stdlib.h>
#include <ctype.h>
#include <tracefs.h>
static void read_subbuf(struct tep_handle *tep, struct kbuffer *kbuf)
{
        static struct trace_seq seq;
        struct tep_record record;
        int missed_events;
        if (seq.buffer)
                trace_seq_reset(&seq);
        else
                trace_seq_init(&seq);
        while ((record.data = kbuffer_read_event(kbuf, &record.ts))) {
                record.size = kbuffer_event_size(kbuf);
                missed_events = kbuffer_missed_events(kbuf);
                if (missed_events) {
                        printf("[MISSED EVENTS");
                        if (missed_events > 0)
                                printf(": %d]\n", missed_events);
                        else
                                printf("]\n");
                }
                kbuffer_next_event(kbuf, NULL);
                tep_print_event(tep, &seq, &record,
                                "%s-%d %6.1000d\t%s: %s\n",
                                TEP_PRINT_COMM,
                                TEP_PRINT_PID,
                                TEP_PRINT_TIME,
                                TEP_PRINT_NAME,
                                TEP_PRINT_INFO);
                trace_seq_do_printf(&seq);
                trace_seq_reset(&seq);
        }
}
int main (int argc, char **argv)
{
        struct tracefs_cpu *tcpu;
        struct tep_handle *tep;
        struct kbuffer *kbuf;
        bool mapped;
        int cpu;
        if (argc < 2 || !isdigit(argv[1][0])) {
                printf("usage: %s cpu\n\n", argv[0]);
                exit(-1);
        }
        cpu = atoi(argv[1]);
        tep = tracefs_local_events(NULL);
        if (!tep) {
                perror("Reading trace event formats");
                exit(-1);
        }
        tcpu = tracefs_cpu_open_mapped(NULL, cpu, 0);
        if (!tcpu) {
                perror("Open CPU 0 file");
                exit(-1);
        }
        /*
         * If this kernel supports mapping, use normal read,
         * otherwise use the piped buffer read, although if
         * the mapping succeeded, tracefs_cpu_buffered_read_buf()
         * acts the same as tracefs_cpu_read_buf(). But this is just
         * an example on how to use tracefs_cpu_is_mapped().
         */
        mapped = tracefs_cpu_is_mapped(tcpu);
        if (!mapped)
                printf("Was not able to map, falling back to buffered read\n");
        while ((kbuf = mapped ? tracefs_cpu_read_buf(tcpu, true) :
                        tracefs_cpu_buffered_read_buf(tcpu, true))) {
                read_subbuf(tep, kbuf);
        }
        kbuf = tracefs_cpu_flush_buf(tcpu);
        if (kbuf)
                read_subbuf(tep, kbuf);
        tracefs_cpu_close(tcpu);
        tep_free(tep);
        return 0;
}

DESCRIPTION

The tracefs library provides an interface to read trace data from the Linux kernel's trace buffer. The functions described here are used to read trace data from a specific CPU.

The tracefs_cpu_open_mapped and tracefs_cpu_open functions open a file descriptor for a given CPU. The tracefs_cpu_open_mapped function uses memory mapping to read the trace data, which can be more efficient for large trace buffers. The tracefs_cpu_open function reads the trace data using standard file I/O.

The tracefs_cpu_close function closes the file descriptor opened by tracefs_cpu_open_mapped or tracefs_cpu_open.

The tracefs_cpu_read function reads trace data from the opened CPU. It reads up to size bytes into the buffer buf. It returns the number of bytes read, or a negative value on error.

The tracefs_cpu_next function advances the file offset to the next trace record on the CPU. This is useful for reading trace data iteratively.

The tracefs_cpu_pid_open_mapped, tracefs_cpu_pid_open, tracefs_cpu_pid_read, and tracefs_cpu_pid_next functions are similar to their non-pid counterparts, but they are used to read trace data for a specific process ID (PID).

The tracefs_cpu_event_open_mapped, tracefs_cpu_event_open, tracefs_cpu_event_read, and tracefs_cpu_event_next functions are used to read trace data for a specific event.

The tracefs_cpu_event_pid_open_mapped, tracefs_cpu_event_pid_open, tracefs_cpu_event_pid_read, and tracefs_cpu_event_pid_next functions are used to read trace data for a specific event and PID.

The tracefs_cpu_event_set function enables a specific event for tracing on the CPU. The tracefs_cpu_event_unset function disables a specific event. The tracefs_cpu_event_clear function clears all trace data for the CPU.

RETURN VALUE

On success, tracefs_cpu_open_mapped, tracefs_cpu_open, tracefs_cpu_pid_open_mapped, tracefs_cpu_pid_open, tracefs_cpu_event_open_mapped, tracefs_cpu_event_open, tracefs_cpu_event_pid_open_mapped, and tracefs_cpu_event_pid_open return a pointer to a tracefs_cpu_t structure. On failure, they return NULL.

On success, tracefs_cpu_read, tracefs_cpu_pid_read, tracefs_cpu_event_read, and tracefs_cpu_event_pid_read return the number of bytes read. On failure, they return a negative value.

On success, tracefs_cpu_next, tracefs_cpu_pid_next, tracefs_cpu_event_next, tracefs_cpu_event_pid_next, tracefs_cpu_event_set, tracefs_cpu_event_unset, and tracefs_cpu_event_clear return 0. On failure, they return a negative value.

EXAMPLE

The following example demonstrates how to read trace data from CPU 0:

   tracefs_cpu_t *cpu_data;
   char buf[4096];
   int ret;

   cpu_data = tracefs_cpu_open(NULL, 0);
   if (!cpu_data) {
       perror("tracefs_cpu_open");
       return 1;
   }

   while ((ret = tracefs_cpu_read(cpu_data, buf, sizeof(buf) - 1)) > 0) {
       buf[ret] = '\0';
       printf("%s", buf);
       tracefs_cpu_next(cpu_data);
   }

   if (ret < 0) {
       perror("tracefs_cpu_read");
   }

   tracefs_cpu_close(cpu_data);

FILES

The tracefs library uses the tracefs filesystem, which is typically mounted at /sys/kernel/tracing.
