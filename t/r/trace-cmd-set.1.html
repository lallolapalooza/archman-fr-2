NOM

trace-cmd-set - définit un paramètre de configuration du traqueur interne Ftrace de Linux

SYNTAXE

trace-cmd set [OPTIONS] [commande]

DESCRIPTION

La commande trace-cmd(1) set définit un paramètre de configuration du traqueur du noyau Linux Ftrace. La commande spécifiée sera exécutée après la configuration de l'état ftrace. L'état ftrace configuré peut être restauré à ses valeurs par défaut en utilisant la commande trace-cmd-reset(1).

OPTIONS

-p tracer

Spécifie un traqueur. Les traqueurs font généralement plus que simplement tracer un événement. Les traqueurs courants sont : function, function_graph, preemptirqsoff, irqsoff, preemptoff et wakeup. Un traqueur doit être pris en charge par le noyau en cours d'exécution. Pour voir la liste des traqueurs disponibles, consultez trace-cmd-list(1).

-e événement

Spécifie un événement à tracer. Divers points de trace statiques ont été ajoutés au noyau Linux. Ils sont regroupés par sous-système où vous pouvez activer tous les événements d'un sous-système donné ou spécifier des événements spécifiques à activer. L'événement est au format "sous-système:nom-de-l'événement". Vous pouvez également spécifier uniquement le sous-système sans le :nom-de-l'événement ou le nom de l'événement sans le "sous-système:". L'utilisation de "-e sched_switch" activera l'événement "sched_switch", tandis que "-e sched" activera tous les événements sous le sous-système "sched". 
L'« événement » peut également contenir des expressions génériques (glob). C'est-à-dire que « *stat* » sélectionnera tous les événements (ou sous-systèmes) qui contiennent les caractères « stat » dans leurs noms.
Le mot-clé « all » peut être utilisé pour activer tous les événements.

-T

Active une trace de pile sur chaque événement. Par exemple : 
          <idle>-0     [003] 58549.289091: sched_switch:         kworker/0:1:0 [120] R ==> trace-cmd:2603 [120]
          <idle>-0     [003] 58549.289092: kernel_stack:         <trace de pile>
=> schedule (ffffffff814b260e)
=> cpu_idle (ffffffff8100a38c)
=> start_secondary (ffffffff814ab828)

--func-stack

Active une trace de pile sur toutes les fonctions. Notez que cela ne s'applique qu'au traqueur de plugin "function" et n'aura d'effet que si l'option -l est utilisée et réussit à limiter les fonctions. Si le traqueur de fonction n'est pas filtré et que la trace de pile est activée, vous pouvez bloquer la machine en direct.

-f filtre

Spécifie un filtre pour l'événement précédent. Cela doit apparaître après un -e. Cela filtrera les événements qui seront enregistrés en fonction du contenu de l'événement. Le filtrage est passé directement au noyau, donc ce qui est autorisé peut dépendre de la version du noyau que vous avez. Fondamentalement, cela vous permettra d'utiliser la notation C pour vérifier si un événement doit être traité ou non.
    ==, >=, <=, >, <, &, |, && et ||
Les éléments ci-dessus sont généralement sûrs à utiliser pour comparer des champs.

-R déclencheur

Spécifie un déclencheur pour l'événement précédent. Cela doit apparaître après un -e. Cela ajoutera un déclencheur donné à l'événement donné. Pour activer uniquement le déclencheur et non l'événement lui-même, placez l'événement après l'option -v. 
Consultez Documentation/trace/events.txt dans les sources du noyau Linux pour plus
d'informations sur les déclencheurs.

-v

Cela inversera les options spécifiées après lui sur la ligne de commande. Cela affecte :
     -e: Fait en sorte que tous les événements spécifiés ne soient pas tracés. Ceci est utile pour
           sélectionner un sous-système à tracer mais pour exclure divers événements.
           Par exemple : « -e sched -v -e « *stat* » » activera tous les événements
           du sous-système sched sauf ceux qui contiennent « stat » dans leurs noms.
     -B: Supprime l'instance ftrace spécifiée. Il ne doit y avoir aucune
           options de configuration relatives à cette instance dans la ligne de commande.
           Par exemple : « -v -B bar -B foo » supprimera l'instance bar et créera
           une nouvelle instance foo.
    Note : l'option -v a été empruntée à la manière dont grep(1) inverse les correspondances suivantes.

-P pid

Cela filtrera uniquement les identifiants de processus spécifiés. L'utilisation de -P vous permettra de ne tracer que les événements causés par le processus.

-c

Utilisé avec -P pour tracer également les enfants du processus (si le noyau le prend en charge).

--user

Exécute la commande spécifiée telle quelle.

-C horloge

Définit l'horloge de trace sur « horloge ». 
Utilisez trace-cmd(1) list -C pour voir quelles horloges sont disponibles.

-l nom-de-fonction

Cela limitera les traqueurs function et function_graph à ne tracer que la fonction donnée. Plus d'une -l peuvent être spécifiées sur la ligne de commande pour tracer plus d'une fonction. L'utilisation limitée d'expressions génériques est également autorisée. Ce sont match* pour filtrer uniquement les fonctions qui commencent par match. *match pour filtrer uniquement les fonctions qui se terminent par match. *match\* pour filtrer uniquement les fonctions qui contiennent match.

-g nom-de-fonction

Cette option est pour le plugin function_graph. Elle graphiquera la fonction donnée. C'est-à-dire qu'elle ne tracera que la fonction et toutes les fonctions qu'elle appelle. Vous pouvez avoir plus d'un -g sur la ligne de commande.

-n nom-de-fonction

Ceci a l'effet opposé de -l. La fonction donnée avec l'option -n ne sera pas tracée. Ceci a la priorité, c'est-à-dire que si vous incluez la même fonction pour -n et -l, elle ne sera pas tracée.

-d

Certains plugins de traçage activent le traqueur de fonctions par défaut. Comme les traqueurs de latence. Cette option empêche l'activation du traqueur de fonctions au démarrage.

-D

L'option -d essaiera d'utiliser l'option function-trace pour désactiver le traqueur de fonctions (si disponible), sinon elle utilise par défaut le fichier proc : /proc/sys/kernel/ftrace_enabled, mais ne le touchera pas si l'option function-trace est disponible. L'option -D désactivera à la fois le fichier proc ftrace_enabled ainsi que l'option function-trace si elle existe. 
Notez que cela désactive le traçage de fonctions pour tous les utilisateurs, y compris ceux en dehors des traqueurs ftrace (stack_tracer, perf, etc.).

-O option

Ftrace a diverses options qui peuvent être activées ou désactivées. Ceci vous permet de les définir. L'ajout du texte no à une option la désactive. Par exemple : « -O nograph-time » désactivera l'option Ftrace « graph-time ».

-b taille

Ceci définit la taille du tampon circulaire à taille kilo-octets. Comme le tampon circulaire Ftrace est par CPU, cette taille est la taille de chaque tampon circulaire par CPU dans le noyau. L'utilisation de « -b 10000 » sur une machine avec 4 CPU rendra Ftrace d'une taille totale de tampon de 40 Mo.

-B nom-tampon

Si le noyau prend en charge plusieurs tampons, cela ajoutera un tampon avec le nom donné. Si le nom du tampon existe déjà, ce tampon est simplement réinitialisé. 
Après la mention d'un nom de tampon, tous les événements ajoutés par la suite seront associés à ce tampon. Si aucun tampon n'est spécifié, ou si un événement est spécifié avant un nom de tampon, il sera associé au tampon principal (racine).
trace-cmd set -e sched -B block -e block -B time -e timer sleep 1
Ce qui précède activera tous les événements sched dans le tampon principal. Il créera ensuite une instance de tampon 'block' et activera tous les événements block dans ce tampon. Une instance de tampon 'time' sera créée et tous les événements timer seront activés pour cet événement.

-m taille

La taille maximale en kilo-octets qu'un tampon par CPU devrait avoir. Notez que, en raison de l'arrondi à la taille de page, le nombre peut ne pas être totalement correct. De plus, cela est effectué en basculant entre deux tampons dont la taille est moitié de la taille donnée, donc la sortie peut ne pas avoir la taille donnée même si beaucoup plus a été écrit. 
Utilisez ceci pour éviter de manquer d'espace disque lors de longues exécutions.

-M cpumask

NOM

trace-cmd-set

pour configurer les traceurs du noyau Linux

SYNOPSIS

trace-cmd [OPTIONS] set [OPTIONS]

DESCRIPTION

La commande trace-cmd set est utilisée pour configurer le système de traçage du noyau Linux. Elle permet de définir le traceur actif, d'activer ou de désactiver des événements spécifiques, de configurer des tampons de traçage et de gérer divers paramètres liés au traçage.

OPTIONS

-p | --tracer tracer

Spécifie le traceur à utiliser. Les traceurs disponibles incluent function, function_graph, hwlat, irq, kpi, sched_switch, sched_wakeup, sched_pi_wait, sched_migrate, sync, userstacktrace, vmstat, splice, tcp, sock, bpf.

-e | --event event1[,event2]...

Spécifie les événements à activer ou désactiver. Utiliser "all" pour tous les événements, "*" pour tous les événements de tous les traceurs, ou une liste d'événements spécifiques séparés par des virgules. Les noms d'événements peuvent être préfixés par le nom du traceur (par exemple, sched:*).

-f | --funcgraph-order order

Définit l'ordre d'affichage des fonctions pour le traceur function_graph. Les valeurs possibles sont none, sym, func, ret_chain, chain.

-t | --trace trace

Affiche les fonctions du noyau ou les fonctions des modules qui sont tracées. Il est possible de spécifier des motifs (wildcards).

-n | --func func

Spécifie une liste de fonctions à tracer. Peut utiliser des motifs (wildcards).

-l | --funcfilter funcfilter

Spécifie une liste de filtres de fonctions. Chaque filtre peut inclure des fonctions, des motifs, des noms de modules ou des numéros de ligne.

-u | --unmatched-func

Ne pas afficher les fonctions qui ne correspondent à aucun filtre.

-m | --func-mask cpumask

Définit le masque de CPU pour le traçage. Il affecte uniquement la dernière instance de tampon donnée. Si fourni avant toute instance de tampon, il affecte le tampon principal. La valeur fournie doit être un nombre hexadécimal. 
trace-cmd set -p function -M c -B events13 -e all -M 5
Si le -M est omis, le masque reste le même. Pour activer tous les
CPUs, passez la valeur '-1'.

-i

Par défaut, si un événement listé n'est pas trouvé par trace-cmd, il se terminera avec une erreur. Cette option ignorera simplement les événements listés dans la ligne de commande mais non trouvés sur le système.

-q | --quiet

Supprime la sortie normale, sauf les erreurs.

--max-graph-depth depth

Définit la profondeur maximale à laquelle le traceur function_graph tracera dans une fonction. Une valeur de un n'affichera que l'entrée de l'espace utilisateur dans le noyau, mais aucune fonction appelée dans le noyau. La valeur par défaut est zéro, ce qui signifie aucune limite.

--cmdlines-size size

Définit le nombre d'entrées que le fichier de traçage du noyau "saved_cmdlines" peut contenir. Ce fichier est un tampon circulaire qui stocke la correspondance entre les cmdlines et les PID. S'il est plein, cela conduit à des cmdlines non résolus ("<...>") dans le traçage. La valeur par défaut du noyau est 128.

--module module

Filtre le nom d'un module dans le traçage de fonctions. C'est équivalent à ajouter :mod:module après toutes les autres fonctions filtrées. Si aucun autre filtre de fonction n'est listé, alors toutes les fonctions des modules seront filtrées dans le filtre. 
'--module snd'  est équivalent à  '-l :mod:snd'
'--module snd -l "*jack*"' est équivalent à '-l "*jack*:mod:snd"'
'--module snd -n "*"' est équivalent à '-n :mod:snd'

--stderr

Redirige la sortie vers stderr au lieu de stdout, mais la sortie de la commande exécutée ne sera pas modifiée. Ceci est utile si vous voulez surveiller la sortie de la commande exécutée, mais pas voir la sortie de trace-cmd.

--fork

Si une commande est listée, trace-cmd attendra que cette commande se termine, à moins que l'option --fork ne soit spécifiée. Dans ce cas, il créera un fork de la commande et reviendra immédiatement.

--verbose[=level]

Définit le niveau de journalisation. Les niveaux de journalisation supportés sont "none", "critical", "error", "warning", "info", "debug", "all" ou leurs identifiants "0", "1", "2", "3", "4", "5", "6". La définition du niveau de journalisation à une valeur spécifique active toutes les journaux de ce niveau et de tous les niveaux précédents. Le niveau sera par défaut "info" si aucun n'est spécifié. 
Exemple : activer tous les journaux critiques, d'erreur et d'avertissement
trace-cmd set --verbose=warning

EXEMPLES

Activer tous les événements pour le traçage :

 # trace-cmd set -e all

Définir le traceur de fonctions :

 # trace-cmd set -p function
