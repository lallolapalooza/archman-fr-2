NOM

tracecmd_iterate_events, tracecmd_iterate_events_multi, tracecmd_follow_event, tracecmd_follow_missed_events, tracecmd_filter_add, tracecmd_iterate_reset - Lire les événements d'un fichier de trace

SYNTAXE

#include <trace-cmd.h>
int tracecmd_iterate_events(struct tracecmd_input *handle,
                            cpu_set_t *cpus, int cpu_size,
                            int (*callback)(struct tracecmd_input *,
                                            struct tep_record *,
                                            int, void *),
                            void *callback_data);
int tracecmd_iterate_events_multi(struct tracecmd_input **handles,
                                  int nr_handles,
                                  int (*callback)(struct tracecmd_input *,
                                                           struct tep_record *,
                                                           int, void *),
                                  void *callback_data);
int tracecmd_iterate_events_reverse(struct tracecmd_input *handle,
                            cpu_set_t *cpus, int cpu_size,
                            int (*callback)(struct tracecmd_input *,
                                            struct tep_record *,
                                            int, void *),
                            void *callback_data, bool cont);
int tracecmd_follow_event(struct tracecmd_input *handle,
                          const char *system, const char *event_name,
                          int (*callback)(struct tracecmd_input *,
                                          struct tep_event *,
                                          struct tep_record *,
                                          int, void *),
                          void *callback_data);
int tracecmd_follow_missed_events(struct tracecmd_input *handle,
                                   int (*callback)(struct tracecmd_input *,
                                                   struct tep_event *,
                                                   struct tep_record *,
                                                   int, void *),
                                   void *callback_data);
struct tracecmd_filter *tracecmd_filter_add(struct tracecmd_input handle,
                                            const char *filter_str, bool neg);
int *tracecmd_iterate_reset(struct tracecmd_input *handle);

DESCRIPTION

Cet ensemble d'API peut être utilisé pour itérer sur les événements après avoir ouvert un fichier de trace en utilisant l'une des fonctions d'ouverture comme tracecmd_open(3) ou tracecmd_open_fd(3).

La fonction tracecmd_iterate_events() itérera sur tous les événements dans le fichier de trace défini par handle, où handle est retourné par l'une des fonctions tracecmd_open(3). Elle appellera la fonction callback() sur les événements des CPU définis par cpus. cpu_size doit être la taille de cpus (voir CPU_SET(3)). Si cpus est NULL, alors cpu_size est ignoré et callback() sera appelé pour tous les événements sur tous les CPU du fichier de trace. callback_data est passé à callback() comme dernier paramètre. callback peut être NULL, ce qui est utile si tracecmd_follow_event() est utilisé, mais notez que si callback est NULL, alors callback_data est ignoré et non envoyé au callback de tracecmd_follow_event().

La fonction tracecmd_iterate_events_multi() est similaire à tracecmd_iterate_events() sauf qu'elle permet d'itérer sur plus d'un fichier de trace. Si tracecmd agent(1) est utilisé pour obtenir un fichier de trace pour l'hôte et l'invité, assurez-vous que le fichier de trace de l'hôte est la première entrée dans handles et tracecmd_iterate_events_multi() effectuera la synchronisation des métadonnées pour les fichiers invités qui suivent dans handles. handles est un tableau de descripteurs de fichiers de trace qui ont été ouverts par tracecmd_open(3) et ses amis. Notez que, contrairement à tracecmd_iterate_events(), tracecmd_iterate_events_multi() ne filtre pas sur les CPU, car cela rendrait l'API trop complexe pour savoir quel handle filtrer les CPU. Si un filtrage par CPU est désiré, alors le callback doit vérifier record→cpu et retourner 0 s'il ne s'agit pas du CPU désiré à traiter. nr_handles indique le nombre d'éléments dans handles. callback_data est passé au callback comme dernier paramètre. callback peut être NULL, ce qui est utile si tracecmd_follow_event() est utilisé, mais notez que si callback est NULL, alors callback_data est ignoré et non envoyé au callback de tracecmd_follow_event().

La fonction tracecmd_iterate_events_reverse() fonctionne pratiquement de la même manière que tracecmd_iterate_events(), mais au lieu d'appeler la fonction callback() pour chaque événement dans l'ordre des horodatages, elle appellera la fonction callback() pour chaque événement dans l'ordre inverse des horodatages. Si cont est false, elle commencera par appeler l'événement avec l'horodatage le plus ancien dans le fichier trace.dat. Si cont est défini à true, elle continuera là où la position actuelle des données de traçage est. Par exemple, si le callback() retourne quelque chose d'autre que zéro, il quittera l'itération. Si tracecmd_iterate_events_reverse() est appelée à nouveau avec cont à true, elle continuera là où elle s'est arrêtée. Si cont est false, elle recommencera à l'événement avec l'horodatage le plus ancien. handle, cpus, cpu_size et callback_data agissent de la même manière que tracecmd_iterate_events().

Le callback() pour tracecmd_iterate_events(), tracecmd_iterate_events_reverse() et tracecmd_iterate_events_multi() est du prototype suivant :

int callback()(struct tracecmd_input *handle, struct tep_record *record, int cpu, void *data);

handle est le même handle passé à tracecmd_iterate_events() ou le handle actuel de handles passé à tracecmd_iterate_events_multi() auquel appartient record. record est l'enregistrement de l'événement actuel. cpu est le CPU actuel en cours de traitement. Notez que pour tracecmd_iterate_events_multi(), il peut ne pas s'agir du CPU réel du fichier, mais du n-ième CPU de tous les handles mis ensemble. Utilisez record→cpu pour obtenir le CPU réel sur lequel se trouve l'événement.

La fonction tracecmd_follow_event() s'attachera à un descripteur de fichier de trace handle et appellera le callback lorsque l'événement décrit par system et name correspond à un événement dans l'itération de tracecmd_iterate_events() ou tracecmd_iterate_events_multi(). Notez que cpu est le n-ième CPU pour tracecmd_iterate_events() et tracecmd_iterate_events_multi(). Si le CPU réel de record est nécessaire, utilisez record→cpu. Pour tracecmd_iterate_events_multi(), le callback n'est appelé que si le handle correspond au descripteur de fichier de trace actuel dans handles. callback_data est passé comme dernier paramètre à la fonction callback(). Notez que cette fonction callback() sera appelée avant la fonction callback() de tracecmd_iterate_events() ou de tracecmd_iterate_events_multi().

Le prototype du callback() pour *tracecmd_follow_event()* est :

int callback()(struct tracecmd_input *handle, struct tep_event *event, struct tep_record *_record, int cpu, void *data);

La fonction tracecmd_follow_missed_events() s'attachera à un descripteur de fichier de trace handle et appellera le callback lorsque des événements manqués sont détectés. event contiendra le type d'événement que représente record. record contiendra les informations sur les événements manqués. cpu est le n-ième CPU pour tracecmd_iterate_events() et tracecmd_iterate_events_multi(). Si le CPU auquel les événements manqués appartiennent est nécessaire, utilisez record→cpu. Si record→missed_events est un nombre positif, il contient le nombre d'événements manqués depuis le dernier événement sur son CPU, sinon il sera négatif, ce qui signifie que le nombre d'événements manqués est inconnu mais que des événements manqués existent depuis le dernier événement sur le CPU.
