NOM

trace-cmd-record - enregistrer une trace du traçeur interne du noyau Linux Ftrace

SYNTAXE

trace-cmd record [OPTIONS] [commande]

DESCRIPTION

La commande record de trace-cmd configurera le traçeur Ftrace du noyau Linux pour enregistrer les plugins ou événements spécifiés qui se produisent pendant l'exécution de la commande. Si aucune commande n'est fournie, l'enregistrement se poursuivra jusqu'à ce que l'utilisateur appuie sur Ctrl-C.

La commande record de trace-cmd configurera le traçeur Ftrace pour commencer à tracer les divers événements ou plugins donnés sur la ligne de commande. Elle créera ensuite un certain nombre de processus de traçage (un par CPU) qui commenceront à enregistrer depuis le tampon circulaire du noyau directement dans des fichiers temporaires. Lorsque la commande sera terminée (ou que Ctrl-C sera pressé), tous les fichiers seront combinés en un fichier trace.dat qui pourra être lu ultérieurement (voir trace-cmd-report(1)).

OPTIONS

-p tracer

Spécifie un traçeur. Les traçeurs font généralement plus que simplement tracer un événement. Les traçeurs courants sont : function, function_graph, preemptirqsoff, irqsoff, preemptoff et wakeup. Un traçeur doit être pris en charge par le noyau en cours d'exécution. Pour voir la liste des traçeurs disponibles, consultez trace-cmd-list(1).

-e événement

Spécifie un événement à tracer. Divers points de trace statiques ont été ajoutés au noyau Linux. Ils sont groupés par sous-système où vous pouvez activer tous les événements d'un sous-système donné ou spécifier des événements spécifiques à activer. L' événement est du format « sous-système:nom-événement ». Vous pouvez également spécifier uniquement le sous-système sans le nom-événement ou le nom-événement sans le « sous-système: ». Utiliser « -e sched_switch » activera l'événement « sched_switch », tandis que « -e sched » activera tous les événements du sous-système « sched ». 
L'« événement » peut également contenir des expressions génériques (glob). C'est-à-dire que « *stat* » sélectionnera tous les événements (ou sous-systèmes) dont le nom contient les caractères « stat ».
Le mot-clé « all » peut être utilisé pour activer tous les événements.

-a

Chaque événement enregistré a son fichier de format de sortie sauvegardé dans le fichier de sortie pour pouvoir l'afficher plus tard. Mais si d'autres événements sont activés dans la trace sans que trace-cmd en soit informé, les formats de ces événements ne seront pas enregistrés et trace-cmd report ne pourra pas les afficher. Si c'est le cas, spécifiez l'option -a et le format de tous les événements du système sera sauvegardé.

-T

Active une trace de la pile (stacktrace) à chaque événement. Par exemple : 
          <idle>-0     [003] 58549.289091: sched_switch:         kworker/0:1:0 [120] R ==> trace-cmd:2603 [120]
          <idle>-0     [003] 58549.289092: kernel_stack:         <stack trace>
=> schedule (ffffffff814b260e)
=> cpu_idle (ffffffff8100a38c)
=> start_secondary (ffffffff814ab828)

--func-stack

Active une trace de la pile pour toutes les fonctions. Notez que cela s'applique uniquement au traçeur plugin « function », et n'aura d'effet que si l'option -l est utilisée et réussit à limiter les fonctions. Si le traçeur de fonctions n'est pas filtré et que la trace de la pile est activée, vous pourriez bloquer la machine.

-f filtre

Spécifie un filtre pour l'événement précédent. Ceci doit apparaître après un -e. Cela filtrera les événements enregistrés en fonction du contenu de l'événement. Le filtrage est passé directement au noyau, donc ce qui est autorisé peut dépendre de la version du noyau que vous avez. Fondamentalement, cela vous permettra d'utiliser la notation C pour vérifier si un événement doit être traité ou non.
    ==, >=, <=, >, <, &, |, && et ||
Les éléments ci-dessus sont généralement sûrs à utiliser pour comparer des champs.

--no-filter

Ne filtre pas les threads de trace-cmd. Par défaut, les threads sont filtrés pour ne pas être tracés par les événements. Cette option permettra également de tracer les threads de trace-cmd.

-R déclencheur

Spécifie un déclencheur pour l'événement précédent. Ceci doit apparaître après un -e. Cela ajoutera un déclencheur donné à l'événement donné. Pour activer uniquement le déclencheur et non l'événement lui-même, placez l'événement après l'option -v. 
Consultez Documentation/trace/events.txt dans les sources du noyau Linux pour plus d'informations sur les déclencheurs.

-v

Cela fera en sorte que tous les événements spécifiés après cette option sur la ligne de commande ne soient pas tracés. C'est utile pour sélectionner un sous-système à tracer mais pour exclure divers événements. Par exemple : « -e sched -v -e "*stat\*" » activera tous les événements du sous-système sched, à l'exception de ceux qui contiennent « stat » dans leur nom. 
Note : l'option -v a été prise de la manière dont grep(1) inverse les correspondances suivantes.

-F

Cela filtrera uniquement l'exécutable donné sur la ligne de commande. Si aucune commande n'est donnée, cela se filtrera lui-même (assez inutile). L'utilisation de -F vous permettra de tracer uniquement les événements causés par la commande donnée.

-P pid

Similaire à -F mais vous permet de spécifier un ID de processus à tracer.

-c

Utilisé avec -F (ou -P si le noyau le prend en charge) pour tracer également les enfants du processus.

--user

Exécute la commande spécifiée en tant qu'utilisateur donné.

-C horloge

Définit l'horloge de trace sur « horloge ». 
Utilisez trace-cmd(1) list -C pour voir quelles horloges sont disponibles.

-o fichier-sortie

Par défaut, trace-cmd report créera un fichier trace.dat. Vous pouvez spécifier un autre fichier vers lequel écrire avec l'option -o.

-l nom-fonction

Cela limitera les traçeurs function et function_graph à ne tracer que le nom de fonction donné. Plus d'un -l peut être spécifié sur la ligne de commande pour tracer plus d'une fonction. Cela prend en charge à la fois l'analyse regex(3) complète, ou l'analyse glob de base. Si le filtre ne contient que des caractères alphanumériques, _, *, ? et ., il sera analysé comme un glob de base. Pour le forcer à être une regex, préfixez le filtre par ^ ou ajoutez-lui $ et il sera alors analysé comme une regex.

-g nom-fonction

Cette option est pour le plugin function_graph. Elle graphiquera la fonction donnée. C'est-à-dire qu'elle ne tracera que la fonction et toutes les fonctions qu'elle appelle. Vous pouvez avoir plus d'un -g sur la ligne de commande.

-n nom-fonction

Ceci a l'effet inverse de -l. La fonction donnée avec l'option -n ne sera pas tracée. Cela a la priorité, c'est-à-dire que si vous incluez la même fonction pour -n et -l, elle ne sera pas tracée.

-d

Certains plugins de traçage activent le traçeur de fonctions par défaut. Comme les traçeurs de latence. Cette option empêche le traçeur de fonctions d'être activé au démarrage.

-D

L'option -d essaiera d'utiliser l'option function-trace pour désactiver le traçeur de fonctions (si disponible), sinon elle utilisera par défaut le fichier proc : /proc/sys/kernel/ftrace_enabled, mais ne le touchera pas si l'option function-trace est disponible. L'option -D désactivera à la fois le fichier proc ftrace_enabled ainsi que l'option function-trace si elle existe. 
Notez que cela désactive le traçage de fonctions pour tous les utilisateurs, y compris ceux extérieurs aux traçeurs ftrace (stack_tracer, perf, etc.).

-O option

Ftrace possède diverses options qui peuvent être activées ou désactivées. Cela vous permet de les définir. L'ajout du texte no à une option la désactive. Par exemple : « -O nograph-time » désactivera l'option Ftrace « graph-time ».

-s intervalle

Les processus créés par trace-cmd pour enregistrer depuis le tampon circulaire doivent se réveiller pour effectuer l'enregistrement. Définir l' intervalle à zéro fera se réveiller les processus chaque fois que de nouvelles données sont écrites dans le tampon. Mais étant donné que Ftrace enregistre l'activité du noyau, l'acte de ces processus qui se rendorment peut entraîner de nouveaux événements dans le tampon circulaire qui w
ill réveillera le processus. Cela ajoutera inutilement des données supplémentaires dans le tampon circulaire. 
La métrique 'interval' est en microsecondes. La valeur par défaut est définie à 1000 (1 ms).
C'est le temps pendant lequel chaque processus d'enregistrement dormira avant de se réveiller pour
enregistrer toute nouvelle donnée qui a été écrite dans le tampon circulaire.

-r priorité

La priorité d'exécution des threads de capture. Sur un système chargé, les threads de capture de traces peuvent être affamés et des événements peuvent être perdus. Cela augmente la priorité de ces threads à la priorité temps réel (FIFO). Mais utilisez cette option avec précaution, car elle peut également modifier le comportement du système tracé.

-b taille

Définit la taille du tampon circulaire à taille kilo-octets. Comme le tampon circulaire Ftrace est par CPU, cette taille est la taille de chaque tampon circulaire par CPU à l'intérieur du noyau. L'utilisation de "-b 10000" sur une machine avec 4 CPU donnera à Ftrace une taille de tampon totale de 40 Mo.

--subbuf-size

Le tampon circulaire de traçage du noyau Linux est divisé en sous-tampons. Ces sous-tampons ont généralement la taille de la "page-size" de l'architecture. (4096 pour x86). Un événement ne peut pas être plus grand que la partie données d'un sous-tampon, mais dans la plupart des cas, ce n'est pas un problème. Cependant, le temps que met l'écrivain à passer d'un sous-tampon à l'autre a un peu plus de surcharge que l'ajout d'événements dans le sous-tampon. En augmentant sa taille, cela permettra des événements plus grands (bien que ce soit rarement un problème) mais accélérera également le traçage lui-même. 
L'inconvénient des sous-tampons plus grands est qu'une "lecture" du tampon circulaire
sort le sous-tampon du tampon circulaire et le remplace par un nouveau sous-tampon.
Cela n'aura peut-être aucun impact réel, mais cela peut modifier légèrement le comportement. Ou pas !

-B nom-tampon

Si le noyau prend en charge plusieurs tampons, cela ajoutera un tampon avec le nom donné. Si le nom du tampon existe déjà, ce tampon est simplement réinitialisé et ne sera pas supprimé à la fin de l'exécution de record. Si le tampon est créé, il sera supprimé à la fin de l'exécution (sauf si l'option -k est définie ou si la commande start a été utilisée). 
Après qu'un nom de tampon est spécifié, tous les événements ajoutés par la suite seront
associés à ce tampon. Si aucun tampon n'est spécifié, ou si un événement est spécifié avant un nom de tampon,
il sera associé au tampon principal (racine).
trace-cmd record -e sched -B block -e block -B time -e timer sleep 1
Ce qui précède activera tous les événements sched dans le tampon principal. Il créera ensuite
une instance de tampon 'block' et activera tous les événements block dans ce tampon. Une instance de tampon
'time' est créée et tous les événements timer seront activés pour cet événement.

-m taille

La taille maximale en kilo-octets qu'un tampon par CPU devrait avoir. Notez que, en raison de l'arrondi à la taille de page, le nombre peut ne pas être totalement correct. De plus, cela est effectué en basculant entre deux tampons dont la taille est la moitié de la taille donnée, donc la sortie peut ne pas correspondre à la taille donnée même si beaucoup plus a été écrit. 
Utilisez ceci pour éviter de manquer d'espace disque lors de longues exécutions.

-M masque-cpu

Définit le masque CPU à tracer. Il n'affecte que la dernière instance de tampon donnée. S'il est fourni avant toute instance de tampon, il affecte le tampon principal. La valeur fournie doit être un nombre hexadécimal. 
trace-cmd record -p function -M c -B events13 -e all -M 5
Si -M est omis, le masque reste le même. Pour activer tous les CPU, passez la valeur '-1'.

-k

Par défaut, lorsque trace-cmd a terminé le traçage, il réinitialise les tampons et désactive tout le traçage qu'il a activé. Cette option empêche trace-cmd de désactiver le traceur et de réinitialiser le tampon. Cette option est utile pour le débogage de trace-cmd. 
Note : généralement, trace-cmd rétablit le fichier "tracing_on" à son état antérieur.
Cette option laissera ce fichier défini sur zéro.

-i

Par défaut, si un événement est listé que trace-cmd ne trouve pas, il se terminera avec une erreur. Cette option ignorera simplement les événements qui sont listés sur la ligne de commande mais qui ne sont pas trouvés sur le système.

-N hôte:port

Si une autre machine exécute "trace-cmd listen", cette option est utilisée pour envoyer les données à cette machine avec des paquets UDP. Au lieu d'écrire dans un fichier de sortie, les données sont envoyées à une machine distante. C'est idéal pour les machines embarquées avec peu de stockage, ou pour avoir une seule machine qui conservera toutes les données dans un référentiel unique. 
Note : cette option n'est pas prise en charge avec les plugins de traceur de latence :
 wake-up, wake-up_rt, irqsoff, preemptoff et preemptirqsoff

-V cid:port

Si l'enregistrement s'effectue sur une VM invitée et que l'hôte exécute trace-cmd listen avec l'option -V également, ou si l'on enregistre sur l'hôte et qu'un invité exécute trace-cmd listen avec l'option -V, alors connectez-vous à l'écouteur (identique à la connexion avec l'option -N via le réseau). Cela a les mêmes limitations que l'option -N ci-dessus concernant les plugins de traceur de latence.

-t

Cette option est utilisée avec -N, lorsqu'il y a un besoin d'envoyer les données en direct avec des paquets TCP au lieu d'UDP. Bien que TCP ne soit pas aussi rapide que l'envoi de paquets UDP, il peut être nécessaire si le réseau n'est pas très fiable, si la quantité de données n'est pas intensive, et si une garantie est nécessaire que toutes les informations tracées sont transférées avec succès.

-q | --quiet

À utiliser lors de l'enregistrement d'une application. Supprime la sortie normale (sauf les erreurs) pour ne laisser que la sortie de l'application à afficher.

--date

Avec l'option --date, "trace-cmd" écrira des horodatages dans le tampon de trace une fois l'enregistrement terminé. Il mappera ensuite l'horodatage pour obtenir gettimeofday, ce qui permettra une sortie en temps réel à partir des horodatages lors de la lecture du fichier trace.dat créé.

--max-graph-depth profondeur

Définit la profondeur maximale à laquelle le traceur de fonction_graph tracera dans une fonction. Une valeur de un n'affichera que le point d'entrée de l'espace utilisateur dans le noyau, mais pas les fonctions appelées dans le noyau. La valeur par défaut est zéro, ce qui signifie aucune limite.

--cmdlines-size taille

Définit le nombre d'entrées que le fichier de traçage du noyau "saved_cmdlines" peut contenir. Ce fichier est un tampon circulaire qui stocke la correspondance entre les cmdlines et les PID. S'il est plein, cela conduit à des cmdlines non résolues ("<...>") dans la trace. La valeur par défaut du noyau est 128.

--module module

Filtre le nom d'un module dans le traçage de fonctions. C'est équivalent à ajouter :mod:module après toutes les autres fonctions filtrées. Si aucun autre filtre de fonction n'est spécifié, alors toutes les fonctions des modules seront filtrées. 
'--module snd'  est équivalent à  '-l :mod:snd'
'--module snd -l "*jack*"' est équivalent à '-l "*jack*:mod:snd"'
'--module snd -n "*"' est équivalent à '-n :mod:snd'

--proc-map

Enregistre la carte d'adresses du processus tracé dans le fichier trace.dat. Les processus tracés peuvent être spécifiés à l'aide de l'option -P, ou comme une commande donnée.

--profile

Avec l'option --profile, "trace-cmd" activera le traçage qui peut être utilisé avec l'option --profile de trace-cmd-report(1). Si aucun traceur -p n'est défini et que la profondeur du graphe de fonctions est prise en charge par le noyau, alors le traceur function_graph sera activé avec une profondeur de un (n'affichant que le point d'entrée de l'espace utilisateur dans le noyau). Il activera également divers points de trace avec traçage de pile afin que le rapport puisse montrer où les tâches ont été bloquées le plus longtemps. 
Voir trace-cmd-profile(1) pour plus de détails et d'exemples.

-G

Définit les événements d'interruption (soft et hard) comme globaux (associés au CPU au lieu des tâches). Fonctionne uniquement avec --profile.

-H crochets-événements

Ajoute des événements personnalisés pour connecter deux événements ensemble. Lorsqu'il n'est pas utilisé avec --profile, il enregistrera le paramètre et celui-ci sera également utilisé par trace-cmd report --profile. C'est-à-dire : 
trace-cmd record -H hrtimer_expire_entry,hrtimer/hrtimer_expire_exit,hrtimer,sp
trace-cmd report --profile
Profilera les temps de hrtimer_expire_entry et hrtimer_expire_ext.
Voir trace-cmd-profile(1) pour le format.

-S

(pour --profile uniquement) Active uniquement le traceur ou les événements spécifiés sur la ligne de commande. Avec cette option, le traceur function_graph n'est pas activé, ni aucun événement (comme sched_switch), sauf s'ils sont spécifiquement spécifiés sur la ligne de commande (c'est-à-dire -p function -e sched_switch -e sched_wakeup).

--temp répertoire

Lorsque trace-cmd enregistre la trace, il enregistre les données par CPU dans un fichier séparé pour chaque CPU. À la fin de la trace, ces fichiers sont concaténés dans le fichier final trace.dat. Si le fichier final se trouve sur un système de fichiers réseau, il peut ne pas être approprié de copier ces fichiers temporaires dans le même emplacement. --temp peut être utilisé pour indiquer à trace-cmd où ces fichiers temporaires doivent être créés.

--ts-offset offset

Ajoute un décalage pour l'horodatage dans le fichier trace.dat. Cela ajoutera une option de décalage dans le fichier trace.dat afin qu'un rapport trace-cmd décale tous les horodatages des événements du décalage donné. Le décalage est en unités brutes. C'est-à-dire que si les horodatages des événements sont en nanosecondes, le décalage sera également en nanosecondes même si les unités affichées sont en microsecondes.

--tsync-interval

Définit l'intervalle de boucle, en ms, pour la synchronisation des horodatages avec les invités : Si un nombre négatif est spécifié, la synchronisation des horodatages est désactivée. Si 0 est spécifié, aucune boucle n'est effectuée - le décalage des horodatages est calculé seulement deux fois, au début et à la fin de la trace. La synchronisation des horodatages avec les invités ne fonctionne que s'il y a un support pour VSOCK.

--tsc2nsec

Convertit l'horloge actuelle en nanosecondes, en utilisant le multiplicateur et le décalage tsc de l'interface perf du noyau Linux. Cette option ne modifie pas l'horloge de trace, elle suppose simplement que le multiplicateur et le décalage tsc sont applicables à l'horloge sélectionnée. Vous pouvez utiliser l'horloge "-C tsc2nsec" si vous n'êtes pas sûr de ce qui cl

--stderr

Faire sortir la sortie vers stderr au lieu de stdout, mais la sortie de la commande exécutée ne sera pas modifiée. Ceci est utile si vous voulez surveiller la sortie de la commande en cours d'exécution, mais ne pas voir la sortie de trace-cmd.

--poll

L'attente de données disponibles sur les tampons circulaires de trace peut déclencher des IPI. Cela peut générer un bruit de trace inacceptable lors du traçage de systèmes à faible latence ou en temps réel. L'option poll force trace-cmd à utiliser O_NONBLOCK. Les traces sont extraites par attente active (busy waiting), ce qui monopolise les CPU, donc à n'utiliser que lorsque c'est vraiment nécessaire.

--name

Donner un nom spécifique à l'agent en cours de traitement. Utilisé après -A pour donner un nom à l'invité tracé. Utile lorsqu'on utilise l'ID vsocket au lieu d'un nom d'invité.

--verbose[=level]

Définir le niveau de journalisation. Les niveaux de journalisation pris en charge sont "none", "critical", "error", "warning", "info", "debug", "all" ou leurs identifiants "0", "1", "2", "3", "4", "5", "6". La définition du niveau de journalisation à une valeur spécifique active toutes les journaux de ce niveau et de tous les niveaux précédents. Le niveau sera défini par défaut sur "info" si aucun n'est spécifié. 
Exemple : activer tous les journaux critiques, d'erreur et d'avertissement
trace-cmd record --verbose=warning

--file-version

Version souhaitée du fichier de sortie. Les versions prises en charge sont 6 ou 7.

--compression

Compression du fichier de sortie de trace, une des chaînes suivantes peut être passée : 
'any' - sélectionne automatiquement le meilleur algorithme de compression disponible
'none' - ne pas compresser le fichier de trace
'name' - le nom de l'algorithme de compression souhaité. Les algorithmes disponibles peuvent être listés avec
trace-cmd list -c

--proxy vsocket

Utiliser un proxy vsocket pour atteindre l'agent. Agit de la même manière que -A (pour un agent) mais enverra la connexion proxy à l'agent. Il est supposé s'exécuter sur un invité privilégié dont l'hôte est informé (comme indiqué par le cid dans l'option -P pour l'agent).

--daemonize Exécute trace-cmd en arrière-plan comme un démon après le démarrage de l'enregistrement. Crée un fichier pid à /var/run/trace-cmd-record.pid avec le pid de trace-cmd pendant l'enregistrement.

NOM

trace-cmd-record — Enregistre l'activité du noyau Linux via ftrace

SYNTAXE

trace-cmd record [options] [command]

DESCRIPTION

trace-cmd est un outil pour gérer le traçage du noyau via le système ftrace. Le sous-commande record est utilisée pour enregistrer les événements tracés dans un fichier.

Le traçage peut être configuré pour enregistrer des événements spécifiques (par exemple, des événements de fonction, des événements du noyau, des événements personnalisés) ainsi que des événements liés au système de fichiers et aux requêtes de blocage. Les données tracées sont enregistrées dans un fichier au format trace.dat par défaut dans le répertoire courant.

Le traçage peut être lancé pour une période de temps déterminée ou jusqu'à ce qu'il soit manuellement arrêté.

OPTIONS

Les options suivantes sont disponibles :

  • -e <événement> : Spécifie un événement à tracer. Peut être utilisé plusieurs fois pour spécifier plusieurs événements. Les événements disponibles peuvent être listés avec trace-cmd list.
  • -f <fichier> : Spécifie le fichier de sortie. Par défaut, trace.dat.
  • -p <profil> : Charge un profil de traçage prédéfini.
  • -s <durée> : Enregistre pendant une durée spécifiée (par exemple, 10s pour 10 secondes).
  • -D : Enregistre les événements de l'espace utilisateur en plus des événements du noyau.
  • -C : Annule le traçage après l'enregistrement.
  • -V : Affiche les versions de trace-cmd et de ftrace.
  • -h : Affiche l'aide.

Pour une liste complète des options et des configurations, voir le manuel de trace-cmd.

EXEMPLES

Pour enregistrer les événements de fonction du noyau pendant 10 secondes :

# trace-cmd record -e function -s 10s

Pour enregistrer les événements spécifiés et leurs sous-événements pendant une minute dans un fichier nommé mytrace.dat :

# trace-cmd record -e sched_switch -e printk -f mytrace.dat -s 1m

Pour enregistrer tous les événements disponibles jusqu'à ce que le traçage soit arrêté manuellement :

# trace-cmd record

Pour arrêter le traçage, appuyez sur Ctrl+C.
