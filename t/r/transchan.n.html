NOM

transchan - API de gestionnaire de commande pour les transformations de canal

SYNOPSIS

prefCmd option ?arg arg ...?

DESCRIPTION

Le gestionnaire au niveau Tcl pour une transformation de canal doit être une commande avec des sous-commandes (appelée un *ensemble* bien que cela n'implique pas qu'il doive être créé avec namespace ensemble create ; ce mécanisme n'est lié à namespace ensemble d'aucune façon). Notez que prefCmd est ce qui a été spécifié dans l'appel à chan push, et peut consister en plusieurs arguments ; cela sera développé en plusieurs mots à la place du préfixe.

De toutes les sous-commandes possibles, le gestionnaire *doit* prendre en charge initialize et finalize. Les transformations pour les canaux écrivables doivent également prendre en charge write, et les transformations pour les canaux lisibles doivent également prendre en charge read.

Notez que dans les descriptions ci-dessous, prefCmd peut être constitué de plusieurs mots, et handle est la valeur retournée par l'appel chan push utilisé pour créer la transformation.

SOUS-COMMANDES GÉNÉRALES

Les sous-commandes suivantes sont pertinentes pour tous les types de canaux.

prefCmd clear handle
Cette sous-commande optionnelle est appelée pour signifier à la transformation que toutes les données stockées dans les tampons internes (entrantes ou sortantes) doivent être effacées. Elle est appelée lorsqu'une chan seek est effectuée sur le canal transformé.
prefCmd finalize handle
Cette sous-commande obligatoire est appelée en dernier pour le handle donné, puis plus jamais, et elle existe pour permettre le nettoyage de toutes les structures de données au niveau Tcl associées à la transformation. Attention ! Toutes les erreurs levées par cette sous-commande seront ignorées. Il n'est pas garanti qu'elle soit appelée si l'interpréteur est supprimé.
prefCmd initialize handle mode
Cette sous-commande obligatoire est appelée en premier, puis plus jamais (pour le handle donné). Sa responsabilité est d'initialiser toutes les parties de la transformation au niveau Tcl. Le mode est une liste contenant read et/ou write.
write
implique que le canal est écrivable.
read
implique que le canal est lisible.

La valeur de retour de la sous-commande doit être une liste contenant les noms de toutes les sous-commandes supportées par ce gestionnaire. Toute erreur levée par la sous-commande empêchera la création de la transformation. L'erreur levée apparaîtra comme une erreur levée par chan push.

SOUS-COMMANDES LIÉES À LA LECTURE

Ces sous-commandes sont utilisées pour gérer les transformations appliquées aux canaux lisibles ; bien que read soit strictement facultative, elle doit être prise en charge si l'une des autres l'est, sinon le canal sera rendu non lisible.

prefCmd drain handle
Cette sous-commande optionnelle est appelée chaque fois que les données dans le tampon d'entrée (c'est-à-dire de lecture) de la transformation doivent être forcées vers le haut, c'est-à-dire vers l'utilisateur ou le script. Le résultat retourné par la méthode est considéré comme les données binaires à envoyer vers le niveau supérieur à cette transformation (le lecteur ou une transformation de niveau supérieur).

En d'autres termes, lorsque cette méthode est appelée, la transformation ne peut plus différer l'opération de transformation réelle et doit transformer toutes les données en attente dans ses tampons de lecture internes et retourner le résultat de cette action.

prefCmd limit? handle
Cette sous-commande optionnelle est appelée pour permettre au moteur d'E/S Tcl de déterminer jusqu'où il doit lire en avance. Si elle est présente, elle doit retourner un nombre entier supérieur à zéro indiquant combien d'octets doivent être lus en avance, ou un nombre entier inférieur à zéro pour indiquer que le moteur d'E/S peut lire aussi loin qu'il le souhaite.
prefCmd read handle buffer
Cette sous-commande, qui doit être présente pour que la transformation fonctionne avec des canaux lisibles, est appelée chaque fois que le canal de base, ou une transformation sous cette transformation, envoie des données vers le haut. Le buffer contient les données binaires qui nous ont été fournies par le bas. Il incombe à cette sous-commande de transformer réellement les données. Le résultat retourné par la sous-commande est considéré comme les données binaires à envoyer plus loin vers la transformation au-dessus de cette transformation. Cela peut aussi être l'utilisateur ou le script qui a initialement lu à partir du canal.

Notez que le résultat peut être vide, ou même inférieur aux données reçues ; la transformation n'est pas obligée de transformer tout ce qui lui est donné immédiatement. Elle est autorisée à stocker les données entrantes dans des tampons internes et à différer la transformation réelle jusqu'à ce qu'elle ait plus de données.

SOUS-COMMANDES LIÉES À L’ÉCRITURE

Ces sous-commandes sont utilisées pour gérer les transformations appliquées aux canaux écrivables ; bien que write soit strictement facultative, elle doit être prise en charge si l'une des autres l'est, sinon le canal sera rendu non écrivable.

prefCmd flush handle
Cette sous-commande optionnelle est appelée chaque fois que les données dans le tampon d'écriture de la transformation doivent être forcées vers le bas, c'est-à-dire vers le canal de base. Le résultat retourné par la sous-commande est considéré comme les données binaires à écrire vers la transformation sous la transformation actuelle. Cela peut aussi être le canal de base.

En d'autres termes, lorsque cette sous-commande est appelée, la transformation ne peut plus différer l'opération de transformation réelle et doit transformer toutes les données en attente dans ses tampons d'écriture internes et retourner le résultat de cette action.

prefCmd write handle buffer
Cette sous-commande, qui doit être présente pour que la transformation fonctionne avec des canaux écrivables, est appelée chaque fois que l'utilisateur, ou une transformation au-dessus de cette transformation, écrit des données vers le bas. Le buffer contient les données binaires qui nous ont été écrites. Il incombe à cette sous-commande de transformer réellement les données.

Le résultat retourné par la sous-commande est considéré comme les données binaires à écrire vers la transformation sous cette transformation. Cela peut aussi être le canal de base. Notez que le résultat peut être vide, ou inférieur aux données reçues ; la transformation n'est pas obligée de transformer immédiatement tout ce qui lui a été écrit. Elle est autorisée à stocker ces données dans des tampons internes et à différer la transformation réelle jusqu'à ce qu'elle ait plus de données.
