tzset(3) Manuel des fonctions de bibliothèque tzset(3)

NOM

tzset, tzname, timezone, daylight - initialiser les informations de conversion horaire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <time.h>
void tzset(void);
extern char *tzname[2];
extern long timezone;
extern int daylight;
Exigences de macro de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

tzset():

    _POSIX_C_SOURCE

tzname :

    _POSIX_C_SOURCE

timezone, daylight :

    _XOPEN_SOURCE
        || /* glibc >= 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _SVID_SOURCE

DESCRIPTION

La fonction tzset() initialise la variable tzname à partir de la variable d'environnement TZ. Cette fonction est appelée automatiquement par les autres fonctions de conversion horaire qui dépendent du fuseau horaire. Dans un environnement de type System-V, elle définit également les variables timezone (secondes à l'ouest de l'UTC) et daylight (à 0 si ce fuseau horaire n'a pas de règles d'heure d'été, ou à une valeur non nulle s'il existe une heure, passée, présente ou future où l'heure d'été s'applique).

La fonction tzset() initialise ces variables à des valeurs non spécifiées si ce fuseau horaire est un fuseau horaire géographique comme "America/New_York" (voir ci-dessous).

Si la variable TZ n'apparaît pas dans l'environnement, le fuseau horaire du système est utilisé. Le fuseau horaire du système est configuré en copiant ou en créant un lien vers un fichier au format tzfile(5) dans /etc/localtime. Une base de données des fuseaux horaires de ces fichiers peut se trouver dans le répertoire des fuseaux horaires du système (voir la section FICHIERS ci-dessous).

Si la variable TZ apparaît dans l'environnement, mais que sa valeur est vide, ou que sa valeur ne peut pas être interprétée en utilisant l'un des formats spécifiés ci-dessous, alors le Temps Universel Coordonné (UTC) est utilisé.

Une valeur non vide de TZ peut être l'un des deux formats, chacun pouvant être précédé d'un deux-points qui est ignoré. Le premier format est une chaîne de caractères qui représente directement le fuseau horaire à utiliser :


std décalage[dst[décalage][,début[/heure],fin[/heure]]]

Il n'y a pas d'espaces dans la spécification. La chaîne std spécifie une abréviation pour le fuseau horaire et doit être composée de trois caractères alphabétiques ou plus. Lorsqu'elle est encadrée par des signes inférieur à (<) et supérieur à (>), la jeu de caractères est élargi pour inclure le signe plus (+), le signe moins (-) et des chiffres. La chaîne décalage suit immédiatement std et spécifie la valeur temporelle à ajouter à l'heure locale pour obtenir le Temps Universel Coordonné (UTC). Le décalage est positif si le fuseau horaire local est à l'ouest du Méridien de Greenwich et négatif s'il est à l'est. L'heure doit être comprise entre 0 et 24, et les minutes et secondes entre 00 et 59 :


[+|-]hh[:mm[:ss]]

La chaîne dst et le décalage spécifient le nom et le décalage pour le fuseau horaire d'heure d'été correspondant. Si le décalage est omis, il est par défaut d'une heure en avance sur l'heure standard.

Les champs début spécifient quand l'heure d'été entre en vigueur et le champ fin spécifie quand le changement est effectué pour revenir à l'heure standard. Ces champs peuvent avoir les formats suivants :

Jn
Ceci spécifie le jour julien avec n entre 1 et 365. Les jours bissextiles ne sont pas comptés. Dans ce format, le 29 février ne peut pas être représenté ; le 28 février est le jour 59, et le 1er mars est toujours le jour 60.
n
Ceci spécifie le jour julien basé sur zéro avec n entre 0 et 365. Le 29 février est compté lors des années bissextiles.
Mm.s.j
Ceci spécifie le jour j (0 <= j <= 6) de la semaine s (1 <= s <= 5) du mois m (1 <= m <= 12). La semaine 1 est la première semaine dans laquelle le jour j se produit et la semaine 5 est la dernière semaine dans laquelle le jour j se produit. Le jour 0 est un dimanche.

Les champs heure spécifient quand, à l'heure locale actuellement en vigueur, le changement vers l'autre heure se produit. Ils utilisent le même format que décalage, à l'exception du fait que l'heure peut être dans la plage [-167, 167] pour représenter les heures avant et après le jour nommé. Si omis, la valeur par défaut est 02:00:00.

Voici un exemple pour la Nouvelle-Zélande, où l'heure standard (NZST) est 12 heures en avance sur l'UTC, et l'heure d'été (NZDT), 13 heures en avance sur l'UTC, s'étend du dernier dimanche de septembre, à l'heure par défaut 02:00:00, au premier dimanche d'avril à 03:00:00.


TZ="NZST-12:00:00NZDT-13:00:00,M9.5.0,M4.1.0/3"

Le second format —ou format "géographique" — spécifie que les informations du fuseau horaire doivent être lues à partir d'un fichier :


spéc_fichier

Le spéc_fichier spécifie un fichier au format tzfile(5) à lire pour obtenir les informations du fuseau horaire. Si spéc_fichier ne commence pas par un '/', la spécification du fichier est relative au répertoire des fuseaux horaires du système. Si le fichier spécifié ne peut pas être lu ou interprété, le Temps Universel Coordonné (UTC) est utilisé ; cependant, les applications ne doivent pas dépendre de valeurs spéc_fichier aléatoires représentant l'UTC, car les formats de TZ peuvent être étendus à l'avenir.

Voici un exemple, encore une fois pour la Nouvelle-Zélande :


TZ="Pacific/Auckland"

ENVIRONNEMENT

TZ
Si cette variable est définie, sa valeur a priorité sur le fuseau horaire configuré par le système.
TZDIR
Si cette variable est définie, sa valeur a priorité sur le chemin du répertoire de la base de données des fuseaux horaires configuré par le système.

FICHIERS

/etc/localtime
Le fichier du fuseau horaire du système.
/usr/share/zoneinfo/
Le répertoire de la base de données des fuseaux horaires du système.
/usr/share/zoneinfo/posixrules
Lorsqu'une chaîne TZ inclut un fuseau horaire dst sans rien qui la suive, ce fichier est utilisé pour les règles de début/fin. Il est au format tzfile(5). Par défaut, le Makefile zoneinfo crée un lien symbolique vers le tzfile de America/New_York.

Ce sont les emplacements de fichiers standards actuels, mais ils sont configurables lors de la compilation de glibc.

HISTORIQUE

tzset()
tzname
POSIX.1-1988, SVr4, 4.3BSD.
timezone
daylight
POSIX.1-2001 (XSI), SVr4, 4.3BSD.

4.3BSD possédait une fonction char *timezone(zone, dst) qui renvoyait le nom du fuseau horaire correspondant à son premier argument (minutes à l'ouest de l'UTC). Si le second argument était 0, le nom standard était utilisé, sinon la version heure d'été.

NOTES

La fonction tzset() est appelée implicitement par les fonctions de conversion de temps telles que localtime(3), mktime(3), et strftime(3).

Le comportement de tzset() et des variables associées peut être affecté par les paramètres régionaux (LC_TIME).

Les règles d'heure d'été peuvent être complexes et varier selon les régions et les années. Il est recommandé d'utiliser les informations de fuseaux horaires fournies par la base de données zoneinfo (format tzfile(5)) plutôt que de spécifier manuellement les règles dans la variable TZ.

L'utilisation de la variable d'environnement TZ peut avoir des effets de bord inattendus si elle n'est pas gérée correctement. Il est généralement préférable de laisser le fuseau horaire du système être utilisé sauf nécessité absolue de le modifier.

Pour une utilisation thread-safe, il est conseillé d'utiliser les fonctions alternatives qui ne dépendent pas de variables globales, telles que localtime_r(3) et gmtime_r(3), qui permettent de spécifier des buffers pour stocker les résultats.

La manipulation directe des variables tzname, timezone, et daylight n'est pas recommandée, car leur contenu est géré par les appels système et les fonctions de la bibliothèque C.

EATS'>AVERTISSEMENTS

Étant donné que les valeurs de tzname, timezone et daylight sont souvent non spécifiées et que leur accès peut entraîner un comportement indéfini dans les applications multithread, le code doit plutôt obtenir le décalage et les abréviations du fuseau horaire à partir des membres tm_gmtoff et tm_zone de la structure de temps décomposée tm(3type).

BOGUES

Étant donné que cette fonction ne signale pas d'erreurs, il n'y a aucun moyen de savoir si la valeur de TZ représente un fuseau horaire valide.
