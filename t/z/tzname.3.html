tzset(3) Manuel des fonctions de bibliothèque tzset(3)

NOM

tzset, tzname, timezone, daylight — initialiser les informations de conversion de fuseau horaire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <time.h>
void tzset(void);
extern char *tzname[2];
extern long timezone;
extern int daylight;

tzset():

    _POSIX_C_SOURCE

tzname:

    _POSIX_C_SOURCE

timezone, daylight:

    _XOPEN_SOURCE
        || /* glibc >= 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _SVID_SOURCE

DESCRIPTION

La fonction tzset() initialise la variable tzname à partir de la variable d'environnement TZ. Cette fonction est appelée automatiquement par les autres fonctions de conversion de temps qui dépendent du fuseau horaire. Dans un environnement de type System-V, elle définit également les variables timezone (secondes à l'Ouest de l'UTC) et daylight (à 0 si ce fuseau horaire n'a pas de règles d'heure d'été, ou à une valeur non nulle s'il existe une période, passée, présente ou future, où l'heure d'été s'applique).

La fonction tzset() initialise ces variables à des valeurs non spécifiées si ce fuseau horaire est un fuseau horaire géographique comme "America/New_York" (voir ci-dessous).

Si la variable TZ n'apparaît pas dans l'environnement, le fuseau horaire du système est utilisé. Le fuseau horaire du système est configuré en copiant ou en liant un fichier au format tzfile(5) vers /etc/localtime. Une base de données des fuseaux horaires de ces fichiers peut se trouver dans le répertoire des fuseaux horaires du système (voir la section FICHIERS ci-dessous).

Si la variable TZ apparaît dans l'environnement, mais que sa valeur est vide, ou que sa valeur ne peut pas être interprétée en utilisant l'un des formats spécifiés ci-dessous, alors le Temps Universel Coordonné (UTC) est utilisé.

Une valeur non vide de TZ peut être dans l'un des deux formats, chacun pouvant être précédé d'un deux-points qui est ignoré. Le premier format est une chaîne de caractères qui représente directement le fuseau horaire à utiliser :


std décalage[été[décalage][,début[/heure],fin[/heure]]]

Il n'y a pas d'espaces dans la spécification. La chaîne std spécifie une abréviation pour le fuseau horaire et doit être composée d'au moins trois caractères alphabétiques. Lorsqu'elle est entourée des signes inférieur (<) et supérieur (>), l'ensemble de caractères est étendu pour inclure le signe plus (+), le signe moins (-) et les chiffres. La chaîne décalage suit immédiatement std et spécifie la valeur temporelle à ajouter à l'heure locale pour obtenir le Temps Universel Coordonné (UTC). Le décalage est positif si le fuseau horaire local est à l'ouest du Méridien de Greenwich et négatif s'il est à l'est. L'heure doit être comprise entre 0 et 24, et les minutes et secondes entre 00 et 59 :


[+|-]hh[:mm[:ss]]

La chaîne été et le décalage spécifient le nom et le décalage pour le fuseau horaire d'heure d'été correspondant. Si le décalage est omis, il est par défaut d'une heure d'avance sur l'heure standard.

Les champs début spécifient quand l'heure d'été entre en vigueur et le champ fin spécifie quand le changement est effectué pour revenir à l'heure standard. Ces champs peuvent avoir les formats suivants :

Jn
Ceci spécifie le jour julien avec n compris entre 1 et 365. Les jours bissextiles ne sont pas comptés. Dans ce format, le 29 février ne peut pas être représenté ; le 28 février est le jour 59, et le 1er mars est toujours le jour 60.
n
Ceci spécifie le jour julien basé sur zéro avec n compris entre 0 et 365. Le 29 février est compté les années bissextiles.
Mm.s.j
Ceci spécifie le jour j (0 <= j <= 6) de la semaine s (1 <= s <= 5) du mois m (1 <= m <= 12). La semaine 1 est la première semaine où le jour j survient et la semaine 5 est la dernière semaine où le jour j survient. Le jour 0 est un dimanche.

Les champs heure spécifient quand, dans l'heure locale actuellement en vigueur, le changement vers l'autre heure se produit. Ils utilisent le même format que décalage, à l'exception que l'heure peut être dans la plage [-167, 167] pour représenter les heures avant et après le jour nommé. Si omis, la valeur par défaut est 02:00:00.

Voici un exemple pour la Nouvelle-Zélande, où l'heure standard (NZST) est 12 heures en avance sur l'UTC, et l'heure d'été (NZDT), 13 heures en avance sur l'UTC, s'étend du dernier dimanche de septembre, à l'heure par défaut 02:00:00, au premier dimanche d'avril à 03:00:00.


TZ="NZST-12:00:00NZDT-13:00:00,M9.5.0,M4.1.0/3"

Le deuxième format, dit "géographique", spécifie que les informations du fuseau horaire doivent être lues à partir d'un fichier :


spéc_fichier

Le spéc_fichier spécifie un fichier au format tzfile(5) à lire pour obtenir les informations du fuseau horaire. Si spéc_fichier ne commence pas par un '/', la spécification du fichier est relative au répertoire des fuseaux horaires du système. Si le fichier spécifié ne peut être lu ou interprété, le Temps Universel Coordonné (UTC) est utilisé ; cependant, les applications ne doivent pas se fier à des spéc_fichier aléatoires représentant l'UTC, car les formats de TZ pourraient être étendus à l'avenir.

Voici un exemple, toujours pour la Nouvelle-Zélande :


TZ="Pacific/Auckland"

FICHIERS

/etc/localtime
Le fichier du fuseau horaire du système.
/usr/share/zoneinfo/
Le répertoire de la base de données des fuseaux horaires du système.
/usr/share/zoneinfo/posixrules
Lorsqu'une chaîne TZ inclut un fuseau horaire d'été sans rien suivre, ce fichier est utilisé pour les règles de début/fin. Il est au format tzfile(5). Par défaut, le Makefile zoneinfo le lie symboliquement au tzfile de America/New_York.

Ce sont les emplacements standard actuels des fichiers, mais ils sont configurables lors de la compilation de glibc.

tzname(3) - man page

NAME

tzname - timezone name

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

char *tzname[2];

extern int daylight;

extern long timezone;

extern int getitimer(int, struct itimerval *);

extern int setitimer(int, const struct itimerval *, struct itimerval *);

extern time_t mktime(struct tm *);

extern struct tm *localtime(const time_t *);

extern struct tm *gmtime(const time_t *);

extern struct tm *localtime_r(const time_t *, struct tm *);

extern struct tm *gmtime_r(const time_t *, struct tm *);

extern struct tm *localtime_r(const time_t *, struct tm *);

extern struct tm *gmtime_r(const time_t *, struct tm *);

extern char *tzset(void);

extern char *tzname(void);

extern char *tzname_r(const time_t *timer, char *buf, size_t bufsz);

DESCRIPTION

The three global variables tzname, daylight, and timezone are used by the time conversion functions localtime(3), gmtime(3), mktime(3), and strftime(3) to specify the local time zone.

tzname is an array of two pointers to characters. tzname[0] points to the name of the standard time zone (e.g., "EST" for Eastern Standard Time), and tzname[1] points to the name of the daylight saving time zone (e.g., "EDT" for Eastern Daylight Time).

daylight is a nonzero integer if a standard/daylight saving time zone abbreviation is available, and zero otherwise. timezone is the offset in seconds west of UTC of the local standard time.

When the system starts up, or when the TZ environment variable is changed, the tzset function is called automatically. It initializes the tzname, daylight, and timezone global variables based on the information specified by the TZ environment variable.

If the TZ environment variable is not set, the system's local time zone is used. The exact mechanism for determining the local time zone depends on the system implementation. On many systems, this is done by reading the file /etc/localtime.

tzset may also be called explicitly to update the time zone variables if the TZ environment variable has been changed.

The tzname function (without arguments) returns a pointer to the current timezone abbreviation. This function is deprecated. Use tzname[0] or tzname[1] directly.

The tzname_r function is the reentrant version of tzname. It stores the timezone abbreviation for the given time timer into the buffer pointed to by buf, of size bufsz. It returns a pointer to the abbreviation within the buffer, or NULL on error. The abbreviation returned is either the standard or daylight saving time abbreviation, depending on whether daylight saving time is in effect at the time specified by timer.

ENVIRONMENT

TZ

The TZ environment variable specifies the time zone to be used. Its format is described in tzfile(5).

FILES

/etc/localtime
System's local time zone file.
/usr/share/zoneinfo/
Directory containing time zone files.

ATTRIBUTES

For an explanation of the terms used in this section, see attributes(7).

Interface Attribute
tzname, daylight, timezone Global
tzset None
tzname() (deprecated) None
tzname_r Thread-safe

STANDARDS

The behavior of tzname, daylight, timezone, and tzset is described by POSIX.1-2008 &plusmn; Section 8.1.1. The tzname_r function is a GNU extension.

HISTORY

The tzname, daylight, and timezone variables have been part of Unix since Version 7.

CAVEATS

The global variables tzname, daylight, and timezone are not thread-safe. In multithreaded applications, code should instead obtain time zone offset and abbreviations from the tm_gmtoff and tm_zone members of the broken-down time structure tm(3type).

BUGS

Since this function does not report errors, there's no way to know if the value of TZ represents a valid time zone.
