tep_add_plugin_path(3)

Paquet: libtraceevent

Licences: GPL-2.0-only, LGPL-2.1-only

LIBTRACEEVENT(3) Manuel libtraceevent LIBTRACEEVENT(3)

NOM

tep_load_plugins, tep_unload_plugins, tep_load_plugins_hook, tep_add_plugin_path, tep_plugin_add_option - Charger / décharger des plugins traceevent.

SYNTAXE

#include <event-parse.h>
struct tep_plugin_list *tep_load_plugins(struct tep_handle *tep);
void tep_unload_plugins(struct tep_plugin_list *plugin_list, struct tep_handle *tep);
void tep_load_plugins_hook(struct tep_handle *tep, const char *suffix,
                           void (*load_plugin)(struct tep_handle *tep,
                                               const char *path,
                                               const char *name,
                                               void *data),
                           void *data);
int tep_add_plugin_path(struct tep_handle *tep, char *path,
                          enum tep_plugin_load_priority prio);
int tep_plugin_add_option(const char *name, const char *val);

DESCRIPTION

La fonction tep_load_plugins() charge tous les plugins, situés dans les répertoires de plugins. L'argument tep est le contexte de l'analyseur d'événements de trace. Les répertoires de plugins sont :

        - Répertoires spécifiés dans tep→plugins_dir avec la priorité TEP_PLUGIN_FIRST
        - Répertoire des plugins système, défini lors de la compilation de la bibliothèque. Il
          dépend du préfixe d'installation de la bibliothèque et est généralement
          (préfixe_installation)/lib/traceevent/plugins
        - Répertoire défini par la variable d'environnement TRACEEVENT_PLUGIN_DIR
        - Répertoire des plugins utilisateur, situé à ~/.local/lib/traceevent/plugins
        - Répertoires spécifiés dans tep→plugins_dir avec la priorité TEP_PLUGIN_LAST

Le chargement des plugins peut être contrôlé par tep_flags, en utilisant l'API tep_set_flag() :

        TEP_DISABLE_SYS_PLUGINS       - ne pas charger les plugins situés dans
                                        le répertoire des plugins système.
        TEP_DISABLE_PLUGINS           - ne pas charger de plugins.

L'API tep_set_flag() doit être appelée avant tep_load_plugins(), si le chargement de tous les plugins n'est pas souhaité.

La fonction tep_unload_plugins() décharge les plugins, précédemment chargés par tep_load_plugins(). L'argument tep est le contexte de l'analyseur d'événements de trace. Le plugin_list est la liste des plugins chargés, retournée par la fonction tep_load_plugins().

La fonction tep_load_plugins_hook() parcourt tous les répertoires contenant des plugins et appelle le hook load_plugin() spécifié par l'utilisateur pour chaque fichier de plugin. Seuls les fichiers avec le suffixe donné sont considérés comme des plugins. Le data est un contexte spécifié par l'utilisateur, passé à load_plugin(). Les répertoires et l'ordre de parcours sont les mêmes que dans l'API tep_load_plugins().

La fonction tep_add_plugin_path() ajoute des répertoires supplémentaires de plugins à la liste tep→plugins_dir. Elle doit être appelée avant tep_load_plugins() afin que les plugins des nouveaux répertoires soient chargés. L'argument tep est le contexte de l'analyseur d'événements de trace. Le path est le chemin complet vers le nouveau répertoire de plugins. L'argument prio spécifie l'ordre de priorité de chargement pour le nouveau répertoire de plugins. La priorité de chargement est importante en cas de versions différentes du même plugin situées dans plusieurs répertoires de plugins. Le dernier plugin chargé l'emporte. La priorité peut être :

        TEP_PLUGIN_FIRST      - Charger les plugins de ce répertoire en premier
        TEP_PLUGIN_LAST       - Charger les plugins de ce répertoire en dernier

Où les plugins dans TEP_PLUGIN_LAST" auront la priorité sur les plugins des autres répertoires.

La fonction tep_plugin_add_option() définit des options définies par un plugin. Le name est le nom de l'option à définir avec la valeur val. Les plugins peuvent ajouter des options pour modifier leur comportement et tep_plugin_add_option() est utilisée par l'application pour effectuer ces modifications.

VALEUR DE RETOUR

La fonction tep_load_plugins() retourne une liste des plugins chargés avec succès, ou NULL si aucun plugin n'est chargé. La fonction tep_add_plugin_path() retourne -1 en cas d'erreur, 0 sinon.

EXEMPLE

#include <event-parse.h>
...
struct tep_handle *tep = tep_alloc();
...
tep_add_plugin_path(tep, "~/dev_plugins", TEP_PLUGIN_LAST);
...
struct tep_plugin_list *plugins = tep_load_plugins(tep);
if (plugins == NULL) {
        /* aucun plugin n'est chargé */
}
...
tep_unload_plugins(plugins, tep);
...
void print_plugin(struct tep_handle *tep, const char *path,
                  const char *name, void *data)
{
        pritnf("Trouvé plugin libtraceevent %s/%s\n", path, name);
}
...
tep_load_plugins_hook(tep, ".so", print_plugin, NULL);
...
