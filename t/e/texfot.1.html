NOM

texfot - exécute TeX en filtrant la transcription en ligne pour les messages intéressants

SYNOPIS

texfot [option]... texcmd [texarg...]

DESCRIPTION

"texfot" invoque texcmd avec les arguments texarg donnés, en filtrant la sortie en ligne pour les messages « intéressants ». Sa valeur de sortie est celle de texcmd. Exemples :

# Exemple d'invocation basique :
texfot pdflatex fichier.tex

# Normalement, la sortie complète est copiée dans /tmp/fot.$UID avant
# le filtrage, mais cela peut être omis, ou le nom du fichier modifié :
texfot --tee=/dev/null lualatex fichier.tex

# Exemple d'invocation de moteur plus complexe :
texfot xelatex --recorder '\nonstopmode\input fichier'

Voici un exemple de ce à quoi ressemble la sortie (dans son intégralité) lors d'une exécution sans erreur :

/chemin/vers/texfot: invocation : pdflatex hello.ltx
Ceci est pdfTeX, Version 3.141592653-2.6-1.40.24 (TeX Live 2022) (format préchargé=pdflatex)
Sortie écrite sur hello.pdf (1 page, 94415 octets).

Outre ses propres options, décrites ci-dessous, "texfot" exécute simplement la commande donnée avec les arguments donnés (même approche de la syntaxe de ligne de commande que "env", "nice", "timeout", etc.). Ainsi, "texfot" fonctionne avec n'importe quel moteur et n'importe quelles options de ligne de commande.

"texfot" ne regarde pas le fichier journal (log) ni aucun autre fichier de sortie possible ; il ne regarde que la sortie standard et l'erreur standard de la commande. stdout est traité en premier, puis stderr. "texfot" écrit toutes les lignes acceptées sur sa sortie standard.

Les messages affichés sont destinés à être ceux qui nécessitent probablement une action de la part de l'auteur : messages d'erreur, boîtes trop pleines et trop vides, citations non définies, caractères manquants dans les polices, etc.

FLUX OPÉRATIONNEL

Voici l'ordre dans lequel les lignes de sortie sont vérifiées :

1.
Si la « prochaine ligne » doit être imprimée (voir ci-dessous), l'imprimer.
2.
Sinon, si la ligne correspond à une liste d'expressions régulières fournies par l'utilisateur à accepter (donnée avec "--accept", voir ci-dessous), dans cet ordre, l'imprimer.
3.
Sinon, si la ligne correspond à la liste intégrée d'expressions régulières à ignorer, ou à une liste d'expressions régulières fournies par l'utilisateur à ignorer (donnée avec "--ignore", voir ci-dessous), dans cet ordre, l'ignorer.
4.
Sinon, si la ligne correspond à la liste d'expressions régulières pour lesquelles la prochaine ligne (deux lignes au total) doit être affichée, afficher cette ligne et définir le drapeau « prochaine ligne » pour le prochain passage dans la boucle. Les exemples courants sont les messages d'erreur "!" et "nom_fichier:num_ligne:", qui sont généralement suivis d'une ligne avec des détails spécifiques sur l'erreur.
5.
Sinon, si la ligne correspond à la liste d'expressions régulières à afficher, l'afficher.
6.
Sinon, par défaut : si la ligne provient de stdout, l'ignorer ; si la ligne provient de stderr, l'imprimer (sur stdout), avec le préfixe "[stderr] ". Cette distinction est faite car les moteurs TeX écrivent relativement peu de messages sur stderr, et il est probable que tout message de ce type doive être pris en compte.

Une fois qu'une vérification particulière correspond, le programme passe au traitement de la ligne suivante.

"texfot" correspond exclusivement ligne par ligne ; cependant, TeX lui-même fusionne les lignes de sortie, généralement à la colonne 79. Cela signifie que les correspondances peuvent échouer parce que le texte correspondant a été divisé sur deux lignes. Pour contourner ce problème, vous pouvez effectivement désactiver le repliement de TeX en définissant le paramètre "max_print_line" sur un nombre élevé, soit dans l'environnement, soit sur la ligne de commande :

# Lorsque les erreurs sont manquées en raison du repliement des lignes par TeX :
texfot pdftex --cnf-line max_print_line=999 fichier.tex

# Équivalent :
env max_print_line=999 texfot pdftex fichier.tex

N'hésitez pas à parcourir le code source du script, qui est essentiellement une boucle simple correspondant aux différentes listes comme ci-dessus. Vous pouvez voir les expressions régulières exactes qui correspondent dans les différentes catégories dans le code source.

Soit dit en passant, bien que rien dans cette opération de base ne soit spécifique aux moteurs TeX, toutes les expressions régulières incluses dans le programme sont spécifiques à TeX. Donc, en pratique, le programme n'est utile qu'avec les moteurs TeX, bien qu'il serait assez facile de l'adapter (s'il y avait autre chose d'aussi verbeux que TeX pour que cela soit utile).

OPTIONS

Les options suivantes s'appliquent à "texfot" lui-même (pas au moteur TeX invoqué ; consultez la documentation du moteur ou la sortie de "--help" pour cela).

La première option non optionnelle termine l'analyse des options de "texfot", et le reste de la ligne de commande est invoqué comme commande TeX, sans analyse supplémentaire. Par exemple, "texfot --debug tex --debug" affichera des informations de débogage de "texfot" et de "tex". Les moteurs TeX, contrairement à de nombreux programmes standard, nécessitent que les options soient spécifiées avant le nom du fichier d'entrée ou le texte.

Les options peuvent commencer par - ou --, et peuvent être abrégées sans ambiguïté. Il est cependant préférable d'utiliser le nom complet de l'option dans les scripts, afin d'éviter d'éventuelles collisions avec de nouvelles options à l'avenir.

"--accept" regexp
Accepte les lignes de la sortie TeX correspondant à (Perl) regexp. Peut être répété. Cette liste est vérifiée en premier, donc toutes les correspondances seront affichées, quelles que soient les autres options. Ces expressions régulières ne sont pas automatiquement ancrées (ou modifiées autrement), elles sont simplement utilisées telles quelles.
"--debug"
"--no-debug"
Affiche (ou non) ce que fait le programme sur la sortie standard ; désactivé par défaut.
"--ignore" regexp
Ignore les lignes de la sortie TeX correspondant à (Perl) regexp. Peut être répété. S'ajoute à l'ensemble par défaut des expressions régulières à ignorer plutôt que de les remplacer. Comme les expressions régulières d'acceptation, elles ne sont pas automatiquement ancrées (ou modifiées autrement).
"--interactive"
"--no-interactive"
Par défaut, l'entrée standard du processus TeX est fermée afin que le mode interactif de TeX (attente d'entrée en cas d'erreur, invite "*", etc.) ne soit jamais activé. Donner "--interactive" permet l'interaction.
"--quiet"
"--no-quiet"
Par défaut, la commande TeX invoquée est signalée sur la sortie standard ; "--quiet" omet cette signalisation. Pour obtenir une exécution complètement silencieuse, redirigez la sortie standard : "texfot ... >/dev/null". (Les seuls messages sur la sortie d'erreur standard devraient être des erreurs de "texfot" lui-même, il ne devrait donc pas être nécessaire de rediriger cela, mais cela pourrait bien sûr être fait.)
"--stderr"
"--no-stderr"
Par défaut, "texfot" rapporte tout ce qui est écrit sur stderr par la commande TeX (sur stdout). "--no-stderr" omet cette signalisation. (Certains programmes, comme "dvisvgm", peuvent être assez verbeux sur stderr.)
"--tee" fichier
Par défaut, la sortie en cours de filtrage est "tee"-ée (dupliquée), avant filtrage, pour faciliter la vérification de la sortie complète en cas de problèmes.

Le fichier par défaut est "$TMPDIR/fot."uid ; si "TMPDIR" n'est pas défini, "TMP" est utilisé s'il est défini ; si aucun des deux n'est défini, le répertoire par défaut est "/tmp". Par exemple : "/tmp/fot.1001". Le suffixe uid est l'identifiant utilisateur effectif du processus, ajouté pour une évitement basique des collisions entre différents utilisateurs sur le même système.

RATIONALE

J'ai écrit ceci parce que, dans mon travail d'éditeur de TUGboat (https://tug.org/TUGboat, les soumissions d'articles sont toujours les bienvenues !), j'exécute et réexécute de nombreux documents, plusieurs fois chacun. Il était facile de perdre des avertissements que je devais voir dans la masse de sorties invariables et sans intérêt de TeX, comme les fichiers de style lus et les polices utilisées. Je voulais voir tous les messages et uniquement ceux qui nécessitaient une action de ma part.

J'ai trouvé d'autres programmes de nature similaire, le paquet LaTeX "silence", et de nombreux autres wrappers (La)TeX, mais il semblait qu'aucun d'entre eux ne faisait ce que je voulais. Soit ils lisaient le fichier journal (je voulais regarder uniquement la sortie en ligne), soit ils produisaient plus ou moins que ce que je voulais, soit ils nécessitaient d'appeler TeX différemment (je voulais garder mon processus de construction exactement le même, le plus important étant l'appel TeX, qui peut devenir compliqué). D'où l'écriture de ce petit script.

Voici quelques mots-clés si vous souhaitez explorer d'autres options : texloganalyser, pydflatex, logfilter, latexmk, rubber, arara, et la recherche de "log" sur https://ctan.org/search.

"texfot" est écrit en Perl et s'exécute sous Unix. Il peut fonctionner sous Windows si Perl et d'autres logiciels sont installés, mais je n'utilise pas Windows et ne prend pas en charge "texfot" là-bas.

Le nom vient des fichiers "trip.fot" et "trap.fot" qui font partie des tests de torture trip et trap de Knuth, qui enregistrent la sortie en ligne des programmes. Je ne suis pas sûr de ce que signifie « fot » dans trip et trap, mais je peux prétendre qu'il signifie « filter online transcript » dans le cas présent :).
