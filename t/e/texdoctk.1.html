TEXDOCTK(1) Manuel des commandes générales TEXDOCTK(1)

NOM

texdoctk - Interface graphique pour un accès plus facile à la documentation des paquets et programmes TeX

SYNOPIS

texdoctk -[aq]

DESCRIPTION

texdoctk est une interface graphique pour un accès plus facile à une grande partie de la documentation et des tutoriels pour TeX et ses différents dérivés (principalement LaTeX). Il est optimisé et inclus dans les distributions teTeX et fpTeX et également disponible avec TeXLive.

La documentation est regroupée en 17 catégories ; le 18ème bouton du panneau principal est inactif par défaut et destiné à être utilisé avec des ajouts locaux (voir la section CONFIGURATION ci-dessous).

Dans la fenêtre des paramètres, vous verrez une case à cocher dans les menus des convertisseurs html->ps et text->ps pour activer/désactiver la redirection de sortie. Ceci est dû au fait que certains convertisseurs n'écrivent pas leur sortie dans un fichier mais sur la sortie standard par défaut, une redirection est donc nécessaire, par exemple :

a2ps monfichier.txt >monfichier.ps

OPTIONS

-v
verbeux : active certains messages du visualiseur qui sont autrement envoyés vers stderr, ainsi que certaines fenêtres d'avertissement. Ceci peut également être configuré dans un fichier de configuration.
-a
autoview : démarre automatiquement le visualiseur si une liste ne contient qu'un seul élément (cela se produira fréquemment dans les résultats de recherche). Ceci peut également être configuré dans un fichier de configuration.

CONFIGURATION

La configuration est contrôlée par le fichier de configuration système par défaut ($TEXMFMAIN)/texdoctk/texdocrc.defaults, dont la plupart des entrées peuvent cependant être remplacées par les propres fichiers ~/.texdocrc optionnels de l'utilisateur et/ou les options de ligne de commande.

Le menu Paramètres et les fichiers de configuration

Le menu Paramètres est utilisé pour modifier les paramètres configurables par l'utilisateur de texdoctk pour la durée de l'appel du programme ou comme nouveaux paramètres par défaut. Ce dernier cas est le but du bouton Enregistrer, qui génère ou réécrit le fichier ~/.texdocrc de l'utilisateur. Les paramètres système par défaut ne peuvent pas être modifiés avec le menu Paramètres.

Chemins
Les chemins de type TEXMF sur le système sont rapportés, et l'utilisateur peut spécifier le nom du sous-répertoire de $HOMETEXMF où la documentation personnelle est stockée.
Comportement général du visualiseur

Supprimer les messages d'erreur bascule le mode verbeux (voir l'option -v) ; par défaut, il est désactivé.

Démarrer automatiquement le visualiseur pour les listes à un élément si une liste ne contient qu'un seul élément (voir l'option -a)

Utiliser le visualiseur de texte pour les formats de fichier inconnus c'est-à-dire traiter le fichier comme du texte brut. texdoctk devrait reconnaître les formats de fichier habituels et également assimiler des noms comme README à du texte brut, mais certaines documentations peuvent avoir des noms inventés librement. Par défaut, cette option est activée ; si elle est désactivée, tenter de visualiser de tels fichiers provoquera une erreur. Ce commutateur n'influence pas l'impression : les formats non reconnus ne peuvent pas être imprimés.

Changer les couleurs du visualiseur en utilisant soit des triplets RGB au format #rrggbb soit les noms standardisés.

Texte DVI/PostScript/PDF/HTML/Brut
Pour les fichiers texte, texdoctk fournit son propre visualiseur. Si ce visualiseur est désactivé, mais qu'aucun visualiseur alternatif n'est spécifié, texdoctk essaie de lire le contenu de la variable d'environnement $PAGER.

Si vous souhaitez imprimer la documentation, vous aurez besoin de convertisseurs pour transformer les fichiers non-PS en PostScript. Voici quelques suggestions :

dvi->ps : dvips (fait partie de teTeX) (http://www.radicaleye.com/dvips.html)

pdf->ps : pdf2ps (http://www.cs.wisc.edu/~ghost) ou Acrobat Reader (http://www.adobe.com)

html->ps : html2ps (http://user.it.uu.se/~jan/html2ps.html)

texte brut->ps : a2ps (http://www-inf.enst.fr/~demaille/a2ps/)

Les menus des convertisseurs html->ps et text->ps permettent d'activer/désactiver la redirection de sortie. Ceci est dû au fait que certains convertisseurs n'écrivent pas leur sortie dans un fichier mais sur la sortie standard par défaut, une redirection est donc nécessaire, par exemple : a2ps monfichier.txt >monfichier.ps

Le fichier de configuration système est ($TEXMFMAIN)/texdoctk/texdocrc.defaults et ne devrait être accessible en écriture que par l'administrateur de l'installation, à l'aide d'un éditeur de texte. Le fichier de configuration utilisateur optionnel est ~/.texdocrc et peut remplacer tous les paramètres système sauf ceux qui affectent l'installation dans son ensemble. La méthode préférée pour le modifier est via le menu Paramètres.

Les bases de données

texdoctk est livré avec un fichier de base de données par défaut ($TEXMFMAIN)/texdoctk/texdoctk.dat avec un format spécial. Il est divisé en 17 sections correspondant aux 17 boutons qui sont actifs par défaut. Chaque section commence par une ligne

@nom_section

où nom_section est le texte tel qu'il apparaît sur le bouton. Ce titre est suivi par les entrées descriptives pour chaque documentation, qui ont ce format :

étiquette_paquet;Description courte pour la liste (optionnel nom_paquet);chemin dans le répertoire doc;mots-clés optionnels

(sans casser la ligne !). Les commentaires (initiés par un #) et les lignes vides sont ignorés par le programme. Le deuxième champ est le texte affiché dans les listes de sélection de texdoctk, et vous voudrez probablement y mentionner le nom du paquet entre parenthèses ; le premier champ est une étiquette unique pour le paquet à usage interne du programme, qui sera généralement choisie identique au nom du paquet, mais peut être différente s'il y a plus d'un fichier de documentation avec un paquet.

L'administrateur installera probablement des paquets supplémentaires dans l'arbre texmf local. La documentation correspondante peut être rendue accessible par une base de données supplémentaire $TEXMFLOCAL/texdoctk/texdoctk-local.dat. De plus, les utilisateurs individuels peuvent éventuellement installer des paquets supplémentaires dans un sous-répertoire texmf de leur $HOME, pour lequel ils peuvent créer eux-mêmes une base de données individuelle comme $TEXMFHOME/texdoctk/texdoctk-pers.dat. Après la création de tels fichiers, texhash doit être exécuté.

Les deux types de bases de données doivent avoir la même structure que la base de données système, bien qu'elles n'aient pas besoin (et ne devraient pas) inclure toutes ses sections s'il n'y a pas d'entrées supplémentaires. Par exemple, si le paquet foo est ajouté à l'arbre local de telle sorte que son fichier de documentation soit ($TEXMFLOCAL)/doc/latex/foo/foo.dvi et qu'il est décidé qu'il correspond le mieux à la catégorie existante Graphiques, texdoctk-local.dat ressemblerait à ceci :

@Graphiques
foo;Créer des cloches et des sifflets (foo);latex/foo/foo.dvi;décoration

L'entrée pour foo sera alors ajoutée à la liste des entrées dans la catégorie Graphiques. Le 18ème bouton peut être activé de la même manière, mais en utilisant un nouveau nom de catégorie ; les entrées possibles au début de la base de données qui n'ont pas été assignées à une catégorie seront assignées à la catégorie par défaut Divers, rendant le 18ème bouton actif avec cette étiquette. Notez que vous ne pouvez pas avoir plus de 18 catégories ; s'il y en a plus, seule celle définie en dernier apparaîtra et sera utilisée.

Si la documentation est incluse dans le fichier .sty au lieu d'un fichier de documentation approprié, les mots-clés optionnels doivent commencer par -?- directement après le point-virgule, où ? est 0, 1, 2 ou 3 ; ce sont des indicateurs qui indiquent dans quelle partie du .sty se trouvent les instructions et doivent aider texdoctk à extraire la documentation du style et à la présenter sans le code, ce qui serait normalement d'une utilité limitée.

0
aucun endroit spécifique, dispersé entre le code
1
à la fin, derrière \endinput ; certains fichiers .sty ont une documentation bien organisée après la fin du code réel, où TeX ne la voit pas lors de la compilation
2
au début, terminé par %%%%%% ; dans d'autres cas, certaines informations d'utilisation se trouvent au début du .sty sous forme de commentaire terminé par un

CONFIGURATION

Un fichier de configuration peut être créé en utilisant l'option --config. Les fichiers de configuration suivants sont lus dans l'ordre suivant :

1
Un fichier spécifié avec l'option --config.
2
Le fichier ~/.texdocrc du répertoire personnel de l'utilisateur, s'il existe. Ce fichier peut aussi être créé avec le menu Settings.
3
Le fichier texdoctkrc.defaults du répertoire $TEXMFMAIN/texdoctk.

Les règles de recherche sont les suivantes :

1
Le répertoire de recherche est $TEXMFMAIN/texdoctk.
2
Les bases de données sont recherchées dans les répertoires listés dans la variable d'environnement TEXMFCNF.
3
Les bases de données sont recherchées dans le répertoire $TEXMFMAIN. Si plusieurs bases de données sont trouvées, elles sont traitées dans l'ordre donné par TEXMFCNF.
4
Les bases de données sont recherchées dans les répertoires locaux tels que spécifiés dans $TEXMFLOCAL et $TEXMFHOME.

La recherche de documents suit les règles suivantes :

1
Les fichiers de documentation sont recherchés dans les répertoires spécifiés dans la variable d'environnement TEXDOCDIRS. Si cette variable n'est pas définie, les répertoires suivants sont utilisés :
  • $TEXMFMAIN/texmf-dist/doc/man
  • $TEXMFMAIN/texmf-dist/doc/info
  • $TEXMFMAIN/texmf-dist/doc/html
  • $TEXMFMAIN/texmf-dist/doc/latex
  • $TEXMFMAIN/texmf-dist/doc/txt
  • $TEXMFLOCAL/doc/man
  • $TEXMFLOCAL/doc/info
  • $TEXMFLOCAL/doc/html
  • $TEXMFLOCAL/doc/latex
  • $TEXMFLOCAL/doc/txt
  • $TEXMFHOME/texdoc
2
Si le répertoire de recherche est vide, une recherche est effectuée dans tous les répertoires listés dans la variable d'environnement TEXMF. Pour chaque répertoire trouvé, les sous-répertoires doc/man, doc/info, doc/html, doc/latex et doc/txt sont recherchés.
3
Les lignes vides ne sont pas acceptées comme terminating ; une ligne remplie de % est nécessaire ; le dernier caractère de la ligne doit être un signe de pourcentage.
3
Comme 2, mais avec une ligne vide comme terminaison.

Voir la base de données système pour de nombreux exemples.

FICHIERS

$TEXMFMAIN/texdoctk/texdocrc.defaults fichier de configuration système

~/.texdocrc (facultatif) fichier de configuration personnel ; peut également être créé avec le menu Settings

$TEXMFMAIN/texdoctk/texdoctk.dat fichier de base de données par défaut pour les fichiers de documentation de la distribution

$TEXMFLOCAL/texdoctk/texdoctk-local.dat (facultatif) fichier de base de données local pour les fichiers de documentation

$TEXMFHOME/texdoctk/texdoctk-pers.dat (facultatif) fichier de base de données personnel des utilisateurs individuels pour les fichiers de documentation

BOGUES

Le placement des widgets dans les toplevels de sujet devient laid lorsque le toplevel est étiré ou rétréci.

La police des étiquettes de trame du menu Settings n'est pas forcée à la police par défaut ; cela deviendra visible par exemple sur les écrans haute résolution, où la police des étiquettes n'est pas mise à l'échelle.

La sortie d'erreur de Netscape et Mozilla sera écrite sur stderr même si le mode silencieux était activé.
