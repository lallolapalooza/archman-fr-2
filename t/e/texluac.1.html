LUATEX(1) Manuel des commandes générales LUATEX(1)

NOM

luatex, dviluatex, luahbtex, luajittex, texlua, texluac - Une version étendue de TeX utilisant Lua comme langage de script embarqué

SYNTAXE

luatex [--lua=FICHIER] [OPTION]... [NOMTEX[.tex]] [COMMANDES]
luatex [--lua=FICHIER] [OPTION]... \PREMIERE-LIGNE
luatex [--lua=FICHIER] [OPTION]... &FMT [ARGS]

DESCRIPTION

Exécute le compositeur luaTeX sur NOMTEX, créant généralement NOMTEX.pdf. Toutes les COMMANDES restantes sont traitées comme une entrée luaTeX, après la lecture de NOMTEX.

Alternativement, si le premier argument non-option commence par une barre oblique inverse, interprète tous les arguments non-options comme une ligne d'entrée luaTeX.

Alternativement, si le premier argument non-option commence par un &, le mot suivant est considéré comme le FMT à lire, annulant tout le reste. Les arguments restants sont traités comme ci-dessus.

Si aucun argument ou option n'est spécifié, demande une entrée.

Lorsqu'il est appelé en tant que texlua, il agit comme un interpréteur Lua. Lorsqu'il est appelé en tant que texluac, il agit comme un compilateur de bytecode Lua.

LuaTeX a commencé comme une version étendue de pdfTeX avec support Unicode et des polices OpenType, un langage de script Lua embarqué, les extensions e-TeX et Omega, ainsi qu'un moteur MetaPost intégré, qui peut créer des fichiers PDF ainsi que des fichiers DVI. Pour plus d'informations sur luatex, voir http://www.luatex.org ; et vous pouvez lire le manuel LuaTeX en utilisant l'utilitaire texdoc (texdoc luatex).

Toutes les entrées et sorties de texte de LuaTeX sont considérées comme du texte Unicode, bien que divers filtres permettent de supporter n'importe quel encodage.

En mode DVI, LuaTeX peut être utilisé comme un remplacement complet du moteur TeX.

En mode PDF, LuaTeX peut gérer nativement les formats graphiques PDF, JPG, JBIG2 et PNG. LuaTeX ne peut pas inclure des fichiers graphiques PostScript ou Encapsulated PostScript (EPS) ; convertissez-les d'abord en PDF en utilisant epstopdf (1).

La variante luajittex inclut le compilateur JIT (Just-In-Time) de Lua.

La variante luahbtex peut utiliser le moteur HarfBuzz pour la mise en forme des glyphes, au lieu du moteur de mise en forme intégré de LuaTeX.

OPTIONS

Lorsque l'exécutable LuaTeX démarre, il recherche l'option de ligne de commande --lua. S'il n'y a pas d'option --lua, la ligne de commande est interprétée de manière similaire aux programmes web2c traditionnels. Mais si l'option est présente, LuaTeX entrera dans un mode d'analyse de ligne de commande alternatif par rapport aux programmes web2c standard. La présence de --lua rend la plupart des autres options peu fiables, car le fichier d'initialisation lua peut désactiver kpathsea et/ou accrocher des fonctions à divers callbacks.

--lua=FICHIER
Le fichier d'initialisation lua.

Les deux options suivantes modifient le comportement de l'exécutable :

--luaonly
Démarre LuaTeX comme un interpréteur Lua. Dans ce mode, il définira arg[0] de Lua sur le nom du script trouvé, en plaçant les options précédentes dans des valeurs négatives et le reste de la ligne de commande dans les valeurs positives, tout comme l'interpréteur Lua. LuaTeX se terminera immédiatement après l'exécution du script Lua spécifié.
--luaconly
Démarre LuaTeX comme un compilateur de bytecode Lua. Dans ce mode, LuaTeX est exactement comme luac de la distribution Lua autonome, à l'exception qu'il n'a pas le commutateur -l, et qu'il accepte (mais ignore) le commutateur --luaconly.

Ensuite, les options web2c régulières :

--debug-format

Débogage du chargement du format.
--draftmode
Définit \pdfdraftmode afin que luaTeX n'écrive pas de PDF et ne lise aucune image incluse, accélérant ainsi l'exécution.
--enable-write18

Synonyme de --shell-escape.
--disable-write18

Synonyme de --no-shell-escape.
--shell-escape

Active la construction \write18{commande}, et les fonctions Lua os.execute(), os.exec(), os.spawn(), et io.popen(). La commande peut être n'importe quelle commande shell. Cette construction est normalement interdite pour des raisons de sécurité.
--no-shell-escape

Désactive la construction \write18{commande} et les autres fonctions Lua, même si elles sont activées dans le fichier texmf.cnf.
--shell-restricted
Active une version restreinte de \write18, os.execute(), os.exec(), os.spawn(), et io.popen(), seules les commandes listées dans le fichier texmf.cnf sont autorisées.
--file-line-error
Imprime les messages d'erreur sous la forme fichier:ligne:erreur, ce qui est similaire à la manière dont de nombreux compilateurs les formatent.
--no-file-line-error
Désactive l'impression des messages d'erreur dans le style fichier:ligne:erreur.
--fmt=FORMAT
Utilise FORMAT comme nom du format à utiliser, au lieu du nom par lequel luaTeX a été appelé ou d'une ligne %&.
--help
Affiche un message d'aide et quitte.
--ini
Démarre en mode INI, qui est utilisé pour créer des formats. Le mode INI peut être utilisé pour la composition, mais aucun format n'est préchargé, et des initialisations de base comme la définition des codes de catégorie peuvent être requises.
--interaction=MODE
Définit le mode d'interaction. Le MODE peut être soit batchmode, nonstopmode, scrollmode, et errorstopmode. La signification de ces modes est la même que celle des \commandes correspondantes.
--jobname=NOM
Utilise NOM pour le nom du travail, au lieu de le dériver du nom du fichier d'entrée.
--kpathsea-debug=MASQUE
Définit les drapeaux de débogage de la recherche de chemins selon le MASQUE. Voir le manuel de Kpathsea pour plus de détails.
--mktex=FMT
Active la génération de mktexFMT, où FMT doit être soit tex soit tfm.
--nosocket
Désactive la bibliothèque luasocket (réseau).
--output-comment=CHAINE
En mode DVI, utilise CHAINE pour le commentaire du fichier DVI au lieu de la date. Cette option est ignorée en mode PDF.
--output-directory=REPERTOIRE
Écrit les fichiers de sortie dans REPERTOIRE au lieu du répertoire courant. Recherche les fichiers d'entrée dans REPERTOIRE d'abord, puis le long du chemin de recherche normal.
--output-format=FORMAT
Définit le mode de format de sortie, où FORMAT doit être soit pdf soit dvi. Cela influence également l'ensemble des formats graphiques compris par luaTeX.
--progname=NOM
Prétend être le programme NOM (uniquement pour kpathsea).
--recorder
Active l'enregistreur de noms de fichiers. Cela laisse une trace des fichiers ouverts pour l'entrée et la sortie dans un fichier avec l'extension .fls.
--safer
Désactive certaines commandes Lua qui peuvent facilement être abusées par un document malveillant.
--synctex=VALEUR
Active ou désactive la fonctionnalité SyncTeX. La VALEUR peut être soit 1 (pour activer), 0 (pour désactiver), ou -1 (pour détecter automatiquement).
--tex-prints-the-texmf-cnf-and-exits
Affiche le nom du fichier texmf.cnf utilisé et quitte.
--tex-prints-the-version-of-this-program-and-exits
Affiche la version de ce programme et quitte.
--true
Force l'utilisation des routines de TeX basées sur des chaînes de caractères. Ce commutateur est ignoré par LuaTeX.
--uninitialized-file-errors
Imprimer des erreurs lorsque des fichiers non initialisés sont utilisés.
--utility=CHEMIN
Définit le chemin d'accès à l'utilitaire MetaPost.
--version
Imprime la version et quitte.
--verbose
Imprime des messages supplémentaires pendant l'exécution.
--write18

Synonyme de --shell-escape.
--no-write18

Synonyme de --no-shell-escape.

FILES

AUTEURS

Les principaux auteurs de LuaTeX sont Taco Hoekwater, Hartmut Henkel, Hans Hagen et Luigi Scarso, avec l'aide de Martin Schröder, Karel Skoupy et Han The Thanh.

TeX a été conçu par Donald E. Knuth, qui l'a implémenté en utilisant son système Web pour les programmes Pascal. Il a été porté sur Unix à Stanford par Howard Trickey et à Cornell par Pavel Curtis. La version maintenant proposée avec la distribution Unix TeX est celle générée par le système Web vers C (web2c), initialement écrit par Tomas Rokicki et Tim Morgan.
