TEX(1) Manuel des commandes générales TEX(1)

NOM

tex, initex - mise en forme et composition de texte

SYNTAXE

tex [options] [&format] [fichier|\commandes]

DESCRIPTION

Exécute le compositeur TeX sur le fichier, créant généralement fichier.dvi. Si l'argument de fichier n'a pas d'extension, ".tex" lui sera ajouté. Au lieu d'un nom de fichier, un ensemble de commandes TeX peut être donné, dont la première doit commencer par une barre oblique inverse. Avec un argument &format, TeX utilise un ensemble différent de commandes précompilées, contenues dans format.fmt ; il est généralement préférable d'utiliser l'option -fmt format à la place.

TeX met en forme le texte et les commandes mélangés contenus dans les fichiers nommés et produit un fichier indépendant du périphérique de composition (appelé DVI, abréviation de DeVice Independent). Les capacités et le langage de TeX sont décrits dans The TeXbook. TeX est normalement utilisé avec un grand nombre de macros précompilées, et il existe plusieurs systèmes de mise en forme spécifiques, tels que LaTeX, qui nécessitent le support de plusieurs fichiers de macros.

Cette version de TeX examine sa ligne de commande pour voir sous quel nom elle a été appelée. S'ils existent, alors initex et virtex sont des liens symboliques vers l'exécutable tex. Lorsqu'elle est appelée comme initex (ou lorsque l'option -ini est donnée), elle peut être utilisée pour précompiler des macros dans un fichier .fmt. Lorsqu'elle est appelée comme virtex, elle utilise le format plain. Lorsqu'elle est appelée sous tout autre nom, TeX utilise ce nom comme nom du format à utiliser. Par exemple, lorsqu'elle est appelée comme tex, le format tex est utilisé, qui est identique au format plain. Les commandes définies par le format plain sont documentées dans The TeXbook. D'autres formats souvent disponibles incluent latex et amstex.

Les arguments de ligne de commande sans option du programme TeX lui sont passés comme première ligne d'entrée. (Mais il est souvent plus facile de taper des arguments étendus comme première ligne d'entrée, car les shells UNIX ont tendance à ignorer ou à mal interpréter les symboles favoris de TeX, tels que les barres obliques inverses, à moins que vous ne les citiez.) Comme décrit dans The TeXbook, cette première ligne doit commencer par un nom de fichier, une \séquence-de-contrôle, ou un &nom-de-format.

L'utilisation normale consiste à taper

tex papier
pour commencer le traitement de papier.tex. Le nom papier sera le ``nom de travail'' (jobname), et est utilisé pour former les noms de fichiers de sortie. Si TeX ne reçoit pas de nom de fichier sur la première ligne, le nom de travail est texput. En recherchant un fichier, TeX recherche le nom avec et sans l'extension par défaut (.tex) ajoutée, à moins que le nom ne contienne déjà cette extension. Si papier est le nom de travail, un journal des messages d'erreur, avec beaucoup plus de détails que ce qui apparaît normalement à l'écran, apparaîtra dans papier.log, et le fichier de sortie sera dans papier.dvi.

Cette version de TeX peut regarder la première ligne du fichier papier.tex pour voir si elle commence par la séquence magique %&. Si la première ligne commence par %&format -translate-file nom-tcx alors TeX utilisera le format et la table de traduction nommés nom-tcx pour traiter le fichier source. Le nom du format ou la spécification -translate-file peuvent être omis, mais pas les deux. Cela remplace la sélection du format basée sur le nom sous lequel le programme est invoqué. L'option -parse-first-line ou la variable de configuration parse_first_line contrôle si ce comportement est activé.

La réponse e à l'invite d'erreur de TeX démarre l'éditeur par défaut du système à la ligne courante du fichier courant. La variable d'environnement TEXEDIT peut être utilisée pour changer l'éditeur utilisé. Elle peut contenir une chaîne avec "%s" indiquant où va le nom de fichier et "%d" indiquant où va le numéro de ligne décimal (s'il y en a un). Par exemple, une chaîne TEXEDIT pour emacs peut être définie avec la commande sh

TEXEDIT="emacs +%d %s"; export TEXEDIT

Un fichier pratique dans la bibliothèque est null.tex, ne contenant rien. Quand TeX ne trouve pas un fichier qu'il pense que vous voulez importer, il continue à vous demander un autre nom de fichier ; répondre `null' vous sort de la boucle si vous ne voulez rien importer. Vous pouvez aussi taper votre caractère EOF (généralement contrôle-D).

OPTIONS

Cette version de TeX comprend les options de ligne de commande suivantes.

-cnf-line chaîne
Interprète chaîne comme une ligne de configuration texmf.cnf. Voir le manuel de Kpathsea.
-enc
Active les extensions encTeX. Cette option n'est effective qu'en combinaison avec -ini. Pour la documentation des extensions encTeX, voir http://www.olsak.net/enctex.html.
-file-line-error
Affiche les messages d'erreur sous la forme fichier:ligne:erreur, ce qui est similaire à la façon dont de nombreux compilateurs les formatent.
-no-file-line-error
Désactive l'affichage des messages d'erreur au style fichier:ligne:erreur.
-file-line-error-style
C'est l'ancien nom de l'option -file-line-error.
-fmt format
Utilise format comme nom du format à utiliser, au lieu du nom sous lequel TeX a été appelé ou d'une ligne %&.
-halt-on-error
Se termine avec un code d'erreur lorsqu'une erreur est rencontrée pendant le traitement.
-help
Affiche un message d'aide et quitte.
-ini
Démarre en mode INI, qui est utilisé pour exporter des formats. Le mode INI peut être utilisé pour la composition, mais aucun format n'est préchargé, et des initialisations de base comme la définition des codes de catégorie peuvent être requises.
-interaction mode
Définit le mode d'interaction. Le mode peut être batchmode, nonstopmode, scrollmode, et errorstopmode. La signification de ces modes est la même que celle des \commands correspondants.
-ipc
Envoie la sortie DVI vers un socket ainsi que vers le fichier de sortie habituel. La disponibilité de cette option est à la discrétion de l'installateur.
-ipc-start
Comme -ipc, et démarre également le serveur à l'autre extrémité. La disponibilité de cette option est à la discrétion de l'installateur.
-jobname nom
Utilise nom pour le nom du travail, au lieu de le dériver du nom du fichier d'entrée.
-kpathsea-debug masque-de-bits
Définit les drapeaux de débogage de recherche de chemins selon le masque de bits. Voir le manuel Kpathsea pour les détails.
-mktex fmt
Active mktexfmt, où fmt doit être soit tex soit tfm.
-mltex
Active les extensions MLTeX. N'est effectif qu'en combinaison avec -ini.
-no-mktex fmt
Désactive mktexfmt, où fmt doit être soit tex soit tfm.
-output-comment chaîne
Utilise chaîne pour le commentaire du fichier DVI au lieu de la date.
-output-directory répertoire
Écrit les fichiers de sortie dans répertoire au lieu du répertoire courant. Recherche les fichiers d'entrée dans répertoire d'abord, puis le long du chemin de recherche normal. Voir aussi la description de la variable d'environnement TEXMFOUTPUT.
-parse-firs

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

t-line
Si la première ligne du fichier d'entrée principal commence par %&, elle est analysée pour rechercher un nom de vidage ou une option -translate-file.
-no-parse-first-line
Désactiver l'analyse de la première ligne du fichier d'entrée principal.
-progname name
Se faire passer pour le programme name. Ceci affecte à la fois le format utilisé et les chemins de recherche.
-recorder
Activer l'enregistreur de noms de fichiers. Ceci laisse une trace des fichiers ouverts en entrée et en sortie dans un fichier avec l'extension .fls.
-shell-escape
Activer la construction \write18{command}. La command peut être n'importe quelle commande shell. Cette construction est normalement interdite pour des raisons de sécurité.
-no-shell-escape
Désactiver la construction \write18{command}, même si elle est activée dans le fichier texmf.cnf.
-src-specials
Insérer des "source specials" dans le fichier DVI.
-src-specials where
Insérer des "source specials" à certains endroits du fichier DVI. where est une liste de valeurs séparées par des virgules : cr, display, hbox, math, par, parent, ou vbox.
-translate-file tcxname
Utiliser la table de traduction tcxname pour définir le mappage des caractères d'entrée et le remappage des caractères de sortie.
-default-translate-file tcxname
Comme -translate-file, sauf qu'une ligne %& peut outrepasser ce réglage.
-version
Afficher les informations de version et quitter.

ENVIRONNEMENT

Voir la documentation de la bibliothèque Kpathsearch (le nœud "Path specifications") pour des détails précis sur la manière dont les variables d'environnement sont utilisées. L'utilitaire kpsewhich peut être utilisé pour interroger les valeurs des variables.

Une mise en garde : Dans la plupart des formats TeX, vous ne pouvez pas utiliser ~ dans un nom de fichier que vous donnez directement à TeX, car ~ est un caractère actif, et est donc développé, pas pris comme partie du nom de fichier. D'autres programmes, comme Metafont, n'ont pas ce problème.

TEXMFOUTPUT
Normalement, TeX place ses fichiers de sortie dans le répertoire courant. Si un fichier de sortie ne peut pas y être ouvert, il essaie de l'ouvrir dans le répertoire spécifié dans la variable d'environnement TEXMFOUTPUT. Il n'y a pas de valeur par défaut pour cette variable. Par exemple, si vous faites tex paper et que le répertoire courant n'est pas inscriptible, si TEXMFOUTPUT a la valeur /tmp, TeX tente de créer /tmp/paper.log (et /tmp/paper.dvi, s'il y a une sortie produite.) TEXMFOUTPUT est également vérifié pour les fichiers d'entrée, car TeX génère souvent des fichiers qui doivent être lus par la suite ; pour l'entrée, aucun suffixe (tel que ".tex") n'est ajouté par défaut, le nom d'entrée est simplement vérifié tel quel.
TEXINPUTS
Chemin de recherche pour les fichiers \input et \openin. Ceci devrait probablement commencer par '.', afin que les fichiers utilisateurs soient trouvés avant les fichiers système. Un composant de chemin vide sera remplacé par les chemins définis dans le fichier texmf.cnf. Par exemple, définir TEXINPUTS à ".:/home/user/tex:" pour ajouter le répertoire courant et ``/home/user/tex'' au début du chemin de recherche standard.
TEXFORMATS
Chemin de recherche pour les fichiers de format.
TEXPOOL
Chemin de recherche pour les chaînes internes de tex.
TEXEDIT
Modèle de commande pour basculer vers l'éditeur. La valeur par défaut, généralement vi, est définie lors de la compilation de TeX.
TFMFONTS
Chemin de recherche pour les fichiers de métrique de polices (.tfm).

FICHIERS

L'emplacement des fichiers mentionnés ci-dessous varie d'un système à l'autre. Utilisez l'utilitaire kpsewhich pour trouver leurs emplacements.

texmf.cnf
Fichier de configuration. Il contient les définitions des chemins de recherche ainsi que d'autres paramètres de configuration comme parse_first_line.
tex.pool
Fichier texte contenant les chaînes internes de TeX.
texfonts.map
Définitions de mappage de noms de fichiers.
*.tfm
Fichiers métriques pour les polices de TeX.
*.fmt
Fichiers de format TeX prédigérés (.fmt).
$TEXMFMAIN/tex/plain/base/plain.tex
Le package de macros de base décrit dans le TeXbook.

NOTES

Cette page de manuel n'est pas destinée à être exhaustive. La documentation complète de cette version de TeX se trouve dans le manuel info Web2C: A TeX implementation.

BOGUES

Cette version de TeX implémente un certain nombre d'extensions optionnelles. En fait, beaucoup de ces extensions entrent en conflit, à des degrés divers, avec la définition de TeX. Lorsque de telles extensions sont activées, la bannière affichée au démarrage de TeX est modifiée pour afficher TeXk au lieu de TeX.

Cette version de TeX ne piège pas le dépassement arithmétique lors de l'addition ou de la soustraction de dimensions. Les cas où cela se produit sont rares, mais lorsqu'ils se produisent, le fichier DVI généré sera invalide.

TRIVIA

TeX, prononcé correctement, rime avec "beurk". L'orthographe correcte dans les polices de style machine à écrire est "TeX" et non "TEX" ou "tex".
