NCURSES_CONST char * const strcodes[];
NCURSES_CONST char * const strfnames[];
NCURSES_CONST char * const strnames[];

DESCRIPTION

Cette page résume les variables fournies par l'interface terminfo de bas niveau de la bibliothèque curses. Une description plus complète est donnée dans la page de manuel curs_terminfo(3X).

Selon la configuration, il peut s'agir de variables réelles, ou de macros (voir curs_threads(3X)) qui fournissent un accès en lecture seule à l'état de curses. Dans les deux cas, les applications devraient les traiter comme étant en lecture seule afin d'éviter de confondre la bibliothèque.

Mapping de jeu de caractères alternatif

Après avoir initialisé les interfaces curses ou terminfo, le tableau acs_map contient des informations utilisées pour traduire les cellules avec l'attribut vidéo A_ALTCHARSET en caractères de dessin de lignes.

L'encodage des informations dans ce tableau a changé périodiquement. Les développeurs d'applications doivent seulement savoir qu'il est utilisé pour les constantes “ACS_” dans <curses.h>.

Les données comparables pour la bibliothèque de caractères larges sont une variable privée.

Données du terminal courant

Après avoir initialisé les interfaces curses ou terminfo, cur_term contient des données décrivant le terminal courant. Cette variable est également définie par effet secondaire de set_term(3X) et delscreen(3X).

Il est possible de sauvegarder une valeur de cur_term pour une utilisation ultérieure comme paramètre pour set_term, pour basculer entre les écrans. Alternativement, on peut sauvegarder la valeur de retour de newterm ou setupterm(3X) pour la réutiliser dans set_term.

Tables de recherche terminfo

Les programmes tic(1) et infocmp(1) utilisent des tables de recherche pour les noms longs et courts des capacités terminfo, ainsi que les noms correspondants pour les capacités termcap. Celles-ci sont disponibles pour d'autres applications, bien que les tables de hachage utilisées par les fonctions terminfo et termcap ne le soient pas.

Les noms longs des capacités terminfo utilisent un “f” (eff) dans leurs noms : boolfnames, numfnames, et strfnames.

Ce sont les noms courts pour les capacités terminfo : boolnames, numnames, et strnames.

Ce sont les noms correspondants utilisés pour les descriptions termcap : boolcodes, numcodes, et strcodes.

Type de terminal

Une description de terminal commence par un ou plusieurs noms de terminal séparés par “|” (barres verticales). Lors de l'initialisation des interfaces curses ou terminfo, setupterm(3X) copie les noms de terminal dans le tableau ttytype.

Noms terminfo

En plus des variables, <term.h> définit également un symbole pour chaque nom long de capacité terminfo. Ceux-ci sont basés sur le symbole CUR, qui est défini comme suit :

#define CUR ((TERMTYPE *)(cur_term))->

Ces symboles fournissent une méthode d'accès plus rapide aux capacités terminfo que l'utilisation de tigetstr(3X), etc.

La définition réelle de CUR dépend de l'implémentation, mais chaque bibliothèque terminfo fournit ces noms longs définis pour pointer vers la description de terminal courante chargée en mémoire.

NOTES

L'interface terminfo de bas niveau est initialisée à l'aide de setupterm(3X). L'interface curses de haut niveau utilise l'interface terminfo de bas niveau, en interne.

PORTABILITÉ

X/Open Curses ne décrit aucune de ces variables, à l'exception de cur_term. (L'inclusion de cur_term semble être un oubli, car d'autres informations comparables de bas niveau sont omises par X/Open).

D'autres implémentations peuvent avoir des variables comparables. Certaines implémentations fournissent les variables dans leurs bibliothèques, mais les omettent des fichiers d'en-tête.

Toutes les implémentations qui fournissent des interfaces terminfo ajoutent des définitions comme décrit dans la section Noms terminfo. La plupart, mais pas toutes, basent la définition sur la variable cur_term.
