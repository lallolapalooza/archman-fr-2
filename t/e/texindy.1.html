NOM

texindy - créer un index trié et étiqueté à partir d'un index LaTeX brut

SYNTAXE

texindy [-V?h] [-qv] [-iglr] [-d magic] [-o outfile.ind] [-t log] \
        [-L lang] [-C codepage] [-M module] [idx0 idx1 ...]

Options longues style GNU pour les options courtes :

-V / --version
-? / -h / --help
-q / --quiet
-v / --verbose
-i / --stdin
-g / --german
-l / --letter-ordering
-r / --no-ranges
-d / --debug          (plusieurs fois)
-o / --out-file
-t / --log-file
-L / --language
-C / --codepage
-M / --module         (plusieurs fois)
-I / --input-markup   (supporté : latex, xelatex, omega)

DESCRIPTION

texindy est la commande spécifique à LaTeX de xindy, le système d'indexation flexible. Il prend un index brut en entrée et produit un index fusionné, trié et étiqueté. La fusion, le tri et l'étiquetage sont contrôlés par des modules xindy, avec un ensemble pratique déjà préchargé.

Les fichiers contenant l'index brut sont passés en arguments. Si aucun argument n'est passé, l'index brut sera lu depuis l'entrée standard.

Une bonne introduction à texindy se trouve dans le chapitre d'indexation du LaTeX Companion (2e éd.)

Si vous souhaitez produire un index pour des documents LaTeX avec un balisage d'index spécial, la commande xindy(1) vous intéressera probablement davantage.

texindy est une approche pour fusionner le support du framework make-rules, des modules xindy propres (par exemple, pour des commandes LaTeX spéciales dans l'index) et un niveau raisonnable de compatibilité MakeIndex.

OPTIONS

"--version" / -V
affiche les numéros de version de tous les composants pertinents et quitte.
"--help" / -h / -?
affiche le message d'utilisation avec l'explication des options.
"--quiet" / -q
Ne pas afficher les messages de progression. N'afficher que les messages d'erreur.
"--verbose" / -v
Afficher des messages de progression détaillés.
"--debug" magie / -d magie
Affiche des messages de débogage, cette option peut être spécifiée plusieurs fois. magie détermine ce qui est affiché : 
magie          remarque
------------------------------------------------------------
script         messages de progression internes des scripts pilotes
keep_tmpfiles  ne pas supprimer les fichiers temporaires
markup         trace de balisage de sortie, comme expliqué dans le manuel xindy
level=n        niveau de journalisation, n est 0 (défaut), 1, 2 ou 3
"--out-file" outfile.ind / -o outfile.ind
Écrit l'index dans le fichier outfile.ind. Si cette option n'est pas passée, le nom du fichier de sortie est le nom de base du premier argument et l'extension de fichier ind. Si l'index brut est lu depuis l'entrée standard, cette option est obligatoire.
"--log-file" log.ilg / -t log.ilg
Écrit les messages de journalisation dans le fichier log.ilg. Ces messages de journalisation sont indépendants des messages de progression que vous pouvez influencer avec "--debug" ou "--verbose".
"--language" lang / -L lang
L'index est trié selon les règles de la langue lang. Ces règles sont encodées dans un module xindy créé par make-rules.

Si aucun encodage d'entrée n'est spécifié via "--codepage" ou imposé par le balisage d'entrée, un module xindy pour cette langue est recherché avec un encodage latin, cp, iso, ascii ou utf8, dans cet ordre.

"--codepage" enc / -C enc
Il existe deux situations et cas d'utilisation différents pour cette option.
1.
Le balisage d'entrée est "latex" (par défaut).

Alors, l'entrée brute de texindy est supposée être encodée en Représentation Caractère Interne LaTeX (LICR). C'est-à-dire que les caractères non ASCII sont encodés sous forme de séquences de commandes. Cette option indique à xindy l'encodage qu'il doit utiliser pour les en-têtes de groupes de lettres. (De plus, elle spécifie l'encodage utilisé en interne pour le tri -- mais cela n'affecte pas le résultat.)

Seuls les encodages LICR pour les alphabets latins sont pris en charge ; plus précisément les caractères qui sont dans les encodages LICR latin1, latin2 et latin3 de LaTeX.

Même lorsque vous spécifiez "utf8" comme page de codes, seuls ces caractères seront connus. Mais si vous utilisez des alphabets non latins, vous utilisez probablement (ou devriez utiliser) XeLaTeX ou LuaLaTeX, et alors vous avez un balisage d'entrée différent.

2.
Le balisage d'entrée est "xelatex" ou "omega".

Alors cette option est ignorée ; la page de codes "utf8" est imposée.

L'entrée brute de texindy est supposée être encodée en UTF-8. LICR n'est pas utilisé.

"--module" module / -M module
Charge le module xindy module.xdy. Cette option peut être spécifiée plusieurs fois. Les modules sont recherchés dans le chemin de recherche xindy qui peut être modifié avec la variable d'environnement "XINDY_SEARCHPATH".
"--input-markup" entrée / -I entrée
Spécifie le balisage d'entrée de l'index brut. Les valeurs prises en charge pour entrée sont "latex", "xelatex" et "omega".

"latex" est le balisage d'entrée qui est émis par défaut par le noyau LaTeX, ou par le package macro "index" de David Jones, lorsqu'il est utilisé avec LaTeX standard ou pdfLaTeX. La notation ^^-des caractères mono-octet est prise en charge. L'utilisation du package inputenc de LaTeX est également supposée, c'est-à-dire que l'entrée brute est encodée en LICR.

"xelatex" est un balisage d'entrée similaire à "latex", mais sans utilisation de inputenc. L'entrée brute est encodée en UTF-8. LuaLaTeX a le même balisage d'entrée, il n'y a pas de valeur d'option spéciale pour cela.

"omega" est un balisage d'entrée similaire au balisage d'entrée "latex", mais avec la notation ^^ d'Omega comme encodage pour les caractères non ASCII. L'encodage LICR n'est alors pas utilisé, et "utf8" est imposé comme page de codes pour le tri et pour la sortie des en-têtes de groupes de lettres.

EXEMPLES

Crée un index pour un document qui est `file.idx` :

texindy file.idx

Crée un index pour un document en français :

texindy -L french file.idx

Crée un index avec des entrées brutes dans le fichier `file.idx`, et écrit le résultat dans `file.ind`. Les messages de journalisation sont écrits dans `file.ilg`.

texindy -o file.ind -t file.ilg file.idx

Crée un index en utilisant les informations de tri allemandes (standard Duden) :

texindy -g file.idx

Crée un index en utilisant les informations de tri allemandes (standard DIN) :

texindy -L german-din file.idx

Utilise les fichiers `idx0` et `idx1` comme entrée et écrit le résultat dans `out.ind`.

texindy -o out.ind idx0 idx1

Crée un index pour des entrées en UTF-8 à partir de l'entrée standard, et écrit le résultat dans `out.ind`.

cat file.idx | texindy -I xelatex -o out.ind -

Crée un index pour des entrées en UTF-8 à partir de l'entrée standard, et écrit le résultat dans `out.ind`.

cat file.idx | texindy -I latex -C utf8 -o out.ind

Crée un index pour une langue non latine comme le russe, avec des entrées en UTF-8.

texindy -L russian -C utf8 file.idx

MODULES STANDARD TEXINDY

Il existe un ensemble de modules standard texindy qui aident au traitement des fichiers d'index LaTeX. Certains d'entre eux sont chargés automatiquement. Certains sont chargés par défaut, ce qui peut être désactivé avec une option texindy. D'autres peuvent être spécifiés comme argument "--module" pour obtenir un effet spécifique.

Module xindy    Catégorie  Description

Tri

word-order      Par défaut   Un espace précède toute lettre de l'alphabet :
                          ``index style'' est listé avant ``indexing''.
                          Désactivé avec l'option -l.
letter-order    Add-on    Les espaces sont ignorés : ``index style''
                          est trié après ``indexing''.
keep-blanks     Add-on    Les espaces blancs de début et de fin (espaces
                          et tabulations) ne sont pas ignorés ; les espaces
                          blancs intermédiaires ne sont pas modifiés.
ignore-hyphen   Add-on    Les traits d'union sont ignorés :
                          ``ad-hoc'' est trié comme ``adhoc''.
ignore-punctuation Add-on Tous les types de caractères de ponctuation sont
                          ignorés : traits d'union, points, virgules, barres
                          obliques, parenthèses, etc.
numeric-sort    Auto      Les nombres sont triés numériquement, pas comme
                          des caractères : ``V64'' apparaît avant ``V128''.

Numéros de page

page-ranges     Par défaut   Les apparitions sur plus de deux pages consécutives
                          sont listées sous forme de plage : ``1--4''.
                          Désactivé avec l'option -r.
ff-ranges       Add-on    Utilise la notation implicite ``ff'' pour les plages
                          de trois pages, et des plages explicites
                          ensuite : 2f, 2ff, 2--6.
ff-ranges-only  Add-on    Utilise uniquement des plages implicites : 2f, 2ff.
book-order      Add-on    Trie les numéros de page avec un schéma de numérotation
                          de livre courant correctement -- chiffres romains d'abord,
                          puis chiffres arabes, puis autres : i, 1, A.

Marquage et mise en page

tex             Auto      Gère les conventions TeX de base.
latex-loc-fmts  Auto      Fournit des commandes de formatage LaTeX
                          pour l'encapsulation des numéros de page.
latex           Auto      Gère les conventions LaTeX, tant dans les entrées
                          d'index brutes que dans le marquage de sortie ;
                          implique tex.
makeindex       Auto      Émule la syntaxe d'entrée et le comportement de citation
                          par défaut de MakeIndex.
latin-lettergroups Auto   La mise en page contient une seule lettre latine
                          au-dessus de chaque groupe de mots commençant par la
                          même lettre.
german-sty      Add-on    Gère le marquage des umlauts des options german et
                          ngerman de babel.

COMPATIBILITÉ AVEC MAKEINDEX

xindy ne prétend pas être complètement compatible avec MakeIndex, cela l'empêcherait de bénéficier de certaines de ses améliorations. Cela dit, nous nous efforçons de fournir autant de compatibilité que possible. Les incompatibilités les plus importantes sont

  • Pour les entrées d'index brutes en syntaxe LaTeX, "\index{aaa|bbb}" est interprété différemment. Pour MakeIndex, "bbb" est un marquage qui est généré sous forme de balise LaTeX pour ce numéro de page. Pour xindy, il s'agit d'un attribut de localisation, un identifiant abstrait qui sera ultérieurement associé à un marquage qui devrait être généré pour cet attribut.

    Pour une utilisation simple, lorsque "bbb" est "textbf" ou similaire, nous fournissons des définitions d'attributs de localisation qui imitent le comportement de MakeIndex.

    Pour une utilisation plus complexe, lorsque "bbb" n'est pas un identifiant, aucune définition de compatibilité de ce type n'existe et n'a peut-être pas été créée avec le xindy actuel. En particulier, cela signifie que par défaut, le package LaTeX "hyperref" créera des fichiers d'index bruts qui ne peuvent pas être traités par xindy. Ce n'est pas un bug, c'est le résultat malheureux d'une incompatibilité intentionnelle. Il n'est actuellement pas possible d'obtenir à la fois les liens d'index de hyperref et d'utiliser xindy.

    Une situation similaire est rapportée pour la classe LaTeX "memoir".

    Les programmeurs qui connaissent Common Lisp et Lex et qui souhaitent travailler sur un remède sont priés de contacter l'auteur.

  • Si vous avez une plage d'index et un attribut de localisation, par ex. "\index{key\(attr}" démarre la plage, il faut (1) spécifier cet attribut également dans l'entrée de fermeture de plage (c.-à-d. comme "\index{key\)attr}") et (2) déclarer l'attribut d'index dans un fichier de style xindy.

    MakeIndex générera le marquage "\attr{page1--page2}" pour une telle construction. Il n'est pas possible d'y parvenir dans xindy, la sortie sera "\attrMarkup{page1}--\attrMarkup{page2}". (Ceci est en fait considéré comme un bug, mais pas une priorité élevée.)

    La différence entre les balises de numéro de page de MakeIndex et les attributs de localisation de xindy a déjà été expliquée dans le point précédent.

  • Les définitions de compatibilité MakeIndex ne prennent en charge que la syntaxe brute d'index et la définition de marquage par défaut. Il n'est pas possible de configurer l'analyse des index bruts ou d'utiliser un fichier de style MakeIndex pour décrire le marquage de sortie.

ENVIRONNEMENT

"TEXINDY_AUTO_MODULE"
C'est le nom du module xindy qui charge tous les modules chargés automatiquement. La valeur par défaut est "texindy".
