NOM

tecla, teclarc - L'interface utilisateur fournie par la bibliothèque Tecla.

DESCRIPTION

Cette page de manuel décrit les fonctionnalités d'édition de ligne de commande disponibles pour les utilisateurs de programmes qui lisent l'entrée du clavier via la bibliothèque Tecla. Les utilisateurs du shell tcsh trouveront les raccourcis clavier par défaut très familiers. Les utilisateurs du shell bash les trouveront également assez familiers, mais avec quelques différences mineures, notamment dans la manière dont les recherches avant et arrière dans la liste des commandes historiques sont effectuées. Il existe deux modes d'édition majeurs, l'un avec des raccourcis clavier de type emacs et l'autre avec des raccourcis clavier de type vi. Par défaut, le mode emacs est activé, mais le mode vi peut être sélectionné alternativement via le fichier de configuration de l'utilisateur. Ce fichier peut également être utilisé pour modifier les raccourcis de touches individuelles selon les préférences de l'utilisateur. Par défaut, la complétion par tabulation est fournie. Si l'application n'a pas reconfiguré cela pour compléter d'autres types de symboles, la complétion par tabulation complète les noms de fichiers.

NOTATION DES SEQUENCES DE TOUCHES

Dans le reste de cette page de manuel, ainsi que dans tous les fichiers de configuration Tecla, les séquences de touches sont exprimées comme suit.

^A  ou  C-a
    Ceci est un contrôle-A, entré en appuyant sur la touche contrôle en
    même temps que la touche A.
\E    ou   M-
    Dans les séquences de touches, ces deux notations peuvent être entrées
    soit en appuyant sur la touche échap, puis sur la touche suivante, soit en
    appuyant sur la touche Meta en même temps que la touche suivante. Ainsi
    la séquence de touches M-p peut être tapée de deux manières, en appuyant
    sur la touche échap, suivie de l'appui sur p, ou en appuyant sur
    la touche Meta en même temps que p.
up
    Ceci fait référence à la touche flèche haut.
down
    Ceci fait référence à la touche flèche bas.
left
    Ceci fait référence à la touche flèche gauche.
right
    Ceci fait référence à la touche flèche droite.
a
    Ceci est simplement une touche A normale.

LE FICHIER DE CONFIGURATION TECLA

Par défaut, Tecla recherche un fichier nommé .teclarc dans votre répertoire personnel (c'est-à-dire ~/.teclarc). S'il trouve ce fichier, il le lit, interprétant chaque ligne comme définissant un nouveau raccourci clavier ou une option de configuration d'édition. Étant donné que les raccourcis clavier emacs sont installés par défaut, si vous souhaitez utiliser le mode d'édition vi, qui n'est pas par défaut, l'élément le plus important à placer dans ce fichier est la ligne suivante :

  edit-mode vi

Ceci reconfigurera les raccourcis par défaut pour le mode vi. L'ensemble complet des arguments que cette commande accepte est :

  vi     -  Installe des raccourcis clavier similaires à ceux de l'éditeur
            vi.
  emacs  -  Installe des raccourcis clavier similaires à ceux de l'éditeur
            emacs. C'est le comportement par défaut.
  none   -  Utilise uniquement les fonctions d'édition de ligne natives
            fournies par le pilote de terminal.

Pour empêcher la sonnerie du terminal, par exemple lorsqu'une séquence de contrôle non reconnue est tapée, placez la ligne suivante dans le fichier de configuration :

  nobeep

Un exemple de ligne de raccourci clavier dans le fichier de configuration est le suivant.

  bind M-[2~ insert-mode

Sur de nombreux claviers, la séquence de touches ci-dessus est générée lorsque l'on appuie sur la touche insert. Ainsi, avec ce raccourci, on peut basculer entre les modes d'insertion et d'écrasement du mode emacs en appuyant sur une seule touche. On pourrait également le faire en tapant la séquence de caractères ci-dessus un par un. Comme expliqué ci-dessus, la partie M- de cette séquence peut être tapée soit en appuyant sur la touche échap avant la touche suivante, soit en appuyant sur la touche Meta en même temps que la touche suivante. Ainsi, si vous aviez défini le raccourci clavier ci-dessus, et que la touche insert de votre clavier ne générait pas la séquence de touches ci-dessus, vous pourriez toujours la taper de l'une des deux manières suivantes :

  1. Appuyez momentanément sur la touche échap, puis appuyez sur '[', puis sur '2', puis
     enfin sur '~'.
  2. Appuyez sur la touche Meta en même temps que sur la touche '[',
     puis appuyez sur '2', puis sur '~'.

Si vous définissez un raccourci pour une séquence de touches déjà liée à une fonction, le nouveau raccourci remplace l'ancien. Si, dans le nouveau raccourci, vous omettez le nom de la nouvelle fonction à lier à la séquence de touches, le raccourci d'origine devient indéfini.

À partir des versions de libtecla ultérieures à 1.3.3, il est désormais possible de lier des séquences de touches commençant par un caractère imprimable. Auparavant, les séquences de touches devaient commencer par un caractère de contrôle ou méta.

Notez que les mots-clés spéciaux "up", "down", "left" et "right" font référence aux touches fléchées, et ne sont donc pas traités comme des séquences de touches. Ainsi, par exemple, pour reconfigurer les touches fléchées haut et bas afin d'utiliser le mécanisme de recherche d'historique au lieu de la simple méthode de rappel d'historique, vous pourriez placer ce qui suit dans votre fichier de configuration :

  bind up history-search-backwards
  bind down history-search-backwards

Pour délier un raccourci existant, vous pouvez le faire avec la commande bind en omettant de nommer une action pour reconfigurer la séquence de touches. Par exemple, en ne spécifiant pas de fonction d'action, la commande suivante délie l'action par défaut de début de ligne de la séquence de touches ^A :

  bind ^A

Si vous créez un fichier de configuration ~/.teclarc, mais qu'il semble n'avoir aucun effet sur le programme, consultez la documentation du programme pour voir si l'auteur a choisi un nom différent pour ce fichier.

COMPLÉTION DES NOMS DE FICHIERS ET DES TILDE

Avec les raccourcis clavier par défaut, appuyer sur la touche TAB (également appelée ^I) amène Tecla à tenter de compléter le nom de fichier incomplet qui précède le curseur. Tecla recherche en arrière à partir du curseur, cherchant le début du nom de fichier, s'arrêtant lorsqu'il rencontre un espace ou le début de la ligne. Si plus d'un fichier a le préfixe spécifié, Tecla complète le nom de fichier jusqu'au point où les correspondances ambiguës commencent à différer, puis liste les correspondances possibles.

En plus des noms de fichiers littéralement écrits, Tecla peut compléter les fichiers commençant par ~/ et les expressions ~utilisateur/, ainsi que ceux contenant des expressions $variable_env. En particulier, si vous appuyez sur TAB dans une expression ~utilisateur incomplète, Tecla tentera de compléter le nom d'utilisateur, listant les correspondances ambiguës.

La liaison de complétion est implémentée à l'aide de la fonction cpl_word_completions(), qui est également disponible séparément pour les utilisateurs de cette bibliothèque. Voir la page de manuel cpl_complete_word(3) pour plus de détails.

EXPANSION DES NOMS DE FICHIERS

Avec les raccourcis clavier par défaut, appuyer sur ^X* amène Tecla à développer le nom de fichier qui précède le curseur, remplaçant les expressions ~/ et ~utilisateur/ par les répertoires personnels correspondants, et remplaçant les expressions $variable_env par la valeur de la variable d'environnement spécifiée, puis, s'il y a des jokers, remplaçant le nom de fichier ainsi développé par une liste séparée par des espaces des fichiers qui correspondent aux jokers.

La liaison d'expansion est implémentée à l'aide de la fonction ef_expand_file(). Voir la page de manuel ef_expand_file(3) pour plus de détails.

RAPPEL DES LIGNES TAPEES PRECÉDEMMENT

Chaque fois qu'une nouvelle ligne est entrée par l'utilisateur, elle est ajoutée à une liste de lignes d'entrée historiques maintenue dans l'objet ressource GetLine. Vous pouvez parcourir cette liste en haut et en bas à l'aide des touches fléchées haut et bas. Alternativement, vous pouvez faire de même avec les touches ^P et ^N, et en mode commande vi, vous pouvez alternativement utiliser les caractères k et j. Ainsi, appuyer une fois sur la flèche haut remplace la ligne d'entrée actuelle par la ligne précédemment entrée. Appuyer à nouveau sur la flèche haut la remplace par la ligne entrée avant celle-ci, etc. Après être retourné une ou plusieurs lignes dans la liste d'historique, on peut revenir à des lignes plus récentes en appuyant sur la flèche bas une ou plusieurs fois. Si vous le faites suffisamment de fois, vous reviendrez à la ligne d'origine que vous étiez en train de taper lorsque vous avez d'abord appuyé sur la flèche haut.

Notez qu'en mode vi, toutes les fonctions de rappel d'historique font passer la bibliothèque en mode commande.

En mode emacs, les touches M-p et M-n fonctionnent comme les touches ^P et ^N, sauf qu'elles sautent toutes les lignes historiques sauf celles qui partagent le préfixe qui précède le curseur. En mode commande vi, les caractères majuscules K et J font la même chose, sauf que la chaîne

que leur recherche inclut le caractère sous le curseur ainsi que ce qui le précède.

Ainsi, par exemple, supposez que vous étiez en mode emacs, et que vous veniez d'entrer la liste de commandes suivante dans l'ordre indiqué :

  ls ~/tecla/
  cd ~/tecla
  ls -l getline.c
  emacs ~/tecla/getline.c

Si vous tapiez ensuite :

  ls

puis que vous appuyiez sur M-p, alors au lieu de rappeler la ligne emacs précédemment tapée, qui ne commence pas par « ls », Tecla rappellerait la ligne « ls -l getline.c ». Appuyer à nouveau sur M-p rappellerait la ligne « ls ~/tecla/ ».

Notez que si la chaîne que vous recherchez contient des caractères spéciaux, *, ? ou '[', alors elle est interprétée comme un motif à correspondre. Ainsi, en poursuivant avec l'exemple ci-dessus, après avoir tapé la liste de commandes indiquée, si vous tapiez ensuite :

  *tecla*

et que vous appuyiez sur M-p, alors la ligne « emacs ~/tecla/getline.c » serait rappelée en premier, car elle contient le mot tecla quelque part dans la ligne. De même, appuyer à nouveau sur M-p rappellerait la ligne « ls ~/tecla/ », et appuyer une fois de plus rappellerait la ligne « ls ~/tecla/ ». La syntaxe des motifs est la même que celle décrite pour l'expansion des noms de fichiers, dans la page de manuel ef_expand_file(3.

FICHIERS HISTORIQUE

Les auteurs de programmes qui utilisent la bibliothèque Tecla ont la possibilité de sauvegarder les lignes de commande historiques dans un fichier avant de quitter, et de les relire ensuite à partir de ce fichier lors du prochain démarrage du programme. Il n'y a pas de nom standard pour ce fichier, car il est logique que chaque application utilise son propre fichier historique, afin que les commandes de différentes applications ne se mélangent pas.

JEUX DE CARACTERES INTERNATIONAUX

Depuis la version 1.4.0 de libtecla, Tecla est compatible 8 bits. Cela signifie que tous les caractères 8 bits qui sont imprimables dans la locale actuelle de l'utilisateur sont maintenant affichés tels quels et inclus dans la ligne d'entrée retournée. En supposant que le programme appelant contienne correctement un appel comme suit :

  setlocale(LC_CTYPE, "");

alors la locale actuelle est déterminée par la première des variables d'environnement LC_CTYPE, LC_ALL, et LANG, que l'on trouve contenir un nom de locale valide. Si aucune de ces variables n'est définie, ou si le programme néglige d'appeler setlocale, alors la locale par défaut C est utilisée, qui est US 7 bits ASCII. Sur la plupart des plateformes de type Unix, vous pouvez obtenir une liste des locales valides en tapant la commande :

  locale -a

à l'invite du shell.

Touches Meta et locales

Attention, dans la plupart des locales autres que la locale C par défaut, les caractères méta deviennent imprimables, et ils ne sont alors plus considérés comme correspondant aux liaisons de touches de type M-c. Cela permet de saisir des caractères internationaux avec la touche Compose sans déclencher de manière inattendue les liaisons de touches méta. Vous pouvez toujours invoquer les liaisons méta, car il existe deux façons de le faire. Par exemple, la liaison M-c peut également être invoquée en appuyant momentanément sur la touche Échap, puis en appuyant sur la touche c, et cela fonctionnera quelle que soit la locale. De plus, de nombreux émulateurs de terminaux modernes, tels que gnome-terminal de GNOME et konsole de KDE, génèrent déjà des paires d'échappement comme celles-ci lorsque vous utilisez la touche méta, plutôt qu'un vrai caractère méta, et d'autres émulateurs ont généralement un moyen de demander ce comportement, vous pouvez donc continuer à utiliser la touche méta sur la plupart des systèmes.

Par exemple, bien que les émulateurs de terminaux xterm génèrent par défaut de vrais caractères méta 8 bits lorsque vous utilisez la touche méta, ils peuvent être configurés pour produire la paire d'échappement équivalente en définissant leur ressource X EightBitInput sur False. Vous pouvez soit le faire en plaçant une ligne comme celle-ci dans votre fichier ~/.Xdefaults,

  XTerm*EightBitInput: False
ou en lançant un xterm avec un argument de ligne de commande -xrm '*EightBitInput: False'. Dans les versions récentes de xterm, vous pouvez activer ou désactiver cette fonctionnalité avec l'option "Meta Sends Escape" dans le menu qui s'affiche lorsque vous appuyez sur le bouton gauche de la souris et la touche Contrôle dans une fenêtre xterm. Dans CDE, les dtterms peuvent être contraints de manière similaire à générer des paires d'échappement à la place des caractères méta, en définissant la ressource Dtterm*KshMode sur True.

Entrer des caractères internationaux

Si vous n'avez pas de clavier qui génère tous les caractères internationaux dont vous avez besoin, il existe généralement une touche Compose qui vous permettra de saisir des caractères spéciaux, ou un moyen d'en créer une. Par exemple, sous X windows sur les systèmes de type Unix, si votre clavier n'a pas de touche Compose, vous pouvez désigner une touche redondante pour remplir cette fonction avec la commande xmodmap. Par exemple, sur de nombreux claviers PC, il y a une touche microsoft-windows, qui est par ailleurs inutile sous Linux. Sur mon ordinateur portable, le programme xev indique que l'appui sur cette touche génère le keycode 115, donc pour transformer cette touche en touche Compose, je fais ce qui suit :

  xmodmap -e 'keycode 115 = Multi_key'

Je peux alors entrer un i avec un tréma au-dessus en tapant cette touche, suivi de ", suivi de i.

NAME

tecla-readline - Readline-like line editing

DESCRIPTION

This manual page describes the key bindings and editing commands that are available when using the readline-like line editing interface provided by the libtecla library.

The libtecla library supports two primary editing modes: Emacs mode and Vi mode. These modes dictate how the user interacts with the command line for editing and history navigation.

KEY SEQUENCE NOTATION

The following notation is used to describe key sequences:

  • ^char: Control-char (e.g., ^C is Control-C).
  • M-char: Meta-char. On systems without a Meta key, this is often achieved by pressing the Escape key before the char key. (e.g., M-a is Meta-a, which can be typed as Escape then 'a').
  • \r: The Return or Enter key.
  • \n: The Newline character.
  • ^?: The Delete character (often backspace on older terminals).
  • ^H: The Backspace character.

The cursor keys are refered to by name, as follows. This is necessary because different types of terminals generate different key sequences when their cursor keys are pressed.

  • right -> cursor-right
  • left -> cursor-left
  • up -> up-history
  • down -> down-history

The cursor keys normally generate a keysequence that start with an escape character, so beware that using the arrow keys will put you into command mode (if you aren't already in command mode).

THE TECLA CONFIGURATION FILE

The file ~/.teclarc can be used to customize the behavior of libtecla. Key bindings can be modified, and new bindings can be added within this file. The syntax generally follows a pattern like:

set editing-mode vi
bind ^[kh up-history
bind M-j down-history

Refer to the libtecla documentation or source code for detailed configuration options.

FILENAME AND TILDE COMPLETION

Pressing the TAB key (which generates ^I) typically performs filename completion. If the current word on the command line is a partial filename or path, pressing TAB will attempt to complete it. If there are multiple possible completions, pressing TAB again may cycle through them or list the possibilities.

Tilde expansion (e.g., '~' expanding to the user's home directory) is also handled automatically when appropriate.

FILENAME EXPANSION

The libtecla library can perform shell-like filename expansion, similar to the `*` and `?` wildcards. The command associated with this is typically triggered by a key sequence like ^X* (Ctrl-X followed by *).

RECALLING PREVIOUSLY TYPED LINES

History navigation is a core feature. The Up and Down arrow keys (bound to up-history and down-history respectively) allow you to cycle through previously entered commands. Other key bindings, such as M-p, M-n, M-k, M-j, and history search functions (history-search-forward, history-search-backward) provide alternative ways to access command history.

HISTORY FILES

libtecla can optionally read from and write to history files (typically ~/.tecla_history). This allows command history to persist across different shell sessions. The command ^X^R (Ctrl-X followed by Ctrl-R) is often used to re-read the history file.

INTERNATIONAL CHARACTER SETS

libtecla supports international character sets, allowing for editing of lines containing multi-byte characters. Key bindings that operate on characters or words will generally respect character boundaries in these encodings.

ENTERING REPEAT COUNTS

Many of the key binding functions described previously, take an optional count, typed in before the target keysequence. This is interpreted as a repeat count by most bindings. A notable exception is the goto-column binding, which interprets the count as a column number.

By default you can specify this count argument by pressing the meta key while typing in the numeric count. This relies on the digit-argument action being bound to Meta-0, Meta-1 etc. Once any one of these bindings has been activated, you can optionally take your finger off the meta key to type in the rest of the number, since every numeric digit thereafter is treated as part of the number, unless it is preceded by the literal-next binding. As soon as a non-digit, or literal digit key is pressed the repeat count is terminated and either causes the just typed character to be added to the line that many times, or causes the next key-binding function to be given that argument.

For example, in emacs mode, typing:

  M-12a

causes the letter 'a' to be added to the line 12 times, whereas

  M-4M-c

Capitalizes the next 4 words.

In vi command mode the Meta modifier is automatically added to all characters typed in, so to enter a count in vi command-mode, just involves typing in the number, just as it does in the vi editor itself. So for example, in vi command mode, typing:

  4w2x

moves the cursor four words to the right, then deletes two characters.

You can also bind digit-argument to other key sequences. If these end in a numeric digit, that digit gets appended to the current repeat count. If it doesn't end in a numeric digit, a new repeat count is started with a value of zero, and can be completed by typing in the number, after letting go of the key which triggered the digit-argument action.

NAME

teclarc - Description du format de fichier de l'archive de clavier teclib.

SYNOPSIS

N/A

DESCRIPTION

Le fichier teclarc est une archive contenant des descriptions de dispositions de clavier au format teclib.

Ces archives sont généralement utilisées par les programmes qui doivent charger des dispositions de clavier spécifiques, comme les émulateurs de terminal ou les gestionnaires de fenêtres.

La structure exacte de l'archive teclarc dépend de la version spécifique de teclib utilisée. Cependant, elle contient généralement plusieurs fichiers de description de dispositions, chacun décrivant une disposition de clavier particulière.

Les fichiers individuels au sein de l'archive peuvent être compressés ou non. Les formats de compression courants incluent gzip, bzip2 ou xz.

FILES

  • /usr/share/teclib/ : Répertoire par défaut où les archives teclarc sont généralement stockées.
