NOM

termkey - bibliothèque de lecture des frappes au terminal

DESCRIPTION

termkey est une bibliothèque qui permet aux programmes de lire et d'interpréter les frappes au clavier et autres événements d'un terminal. Elle comprend les schémas d'encodage utilisés par les terminaux pour encoder les frappes au clavier, et UTF-8 , ce qui lui permet de renvoyer des événements représentant les événements clavier.

termkey fonctionne de manière pseudo-orientée objet. Elle fournit une fonction, termkey_new(3), qui renvoie un pointeur vers une structure nouvellement allouée. Toutes les autres fonctions prennent ce pointeur comme premier argument. Une utilisation typique de cette bibliothèque consisterait à appeler termkey_new() pour construire une nouvelle instance représentant le flux stdin, puis à utiliser la fonction termkey_waitkey(3) pour attendre et interpréter les événements de frappe au clavier. La fonction termkey_destroy(3) peut être utilisée pour désallouer les ressources utilisées par l'instance si le programme a fini de l'utiliser.

Lecture des événements

Chaque instance d'une structure termkey peut être utilisée de l'une des trois manières suivantes par le programme. Elle peut être utilisée de manière synchrone, bloquant pour attendre les frappes au clavier depuis un descripteur de fichier. Elle peut être utilisée de manière asynchrone, renvoyant les frappes au clavier si elles sont disponibles, tout en coopérant avec un programme non bloquant. Ou elle peut être utilisée de manière abstraite, interprétant les octets de frappe au clavier qui lui sont directement transmis par le programme conteneur.

Pour obtenir le prochain événement clavier de manière synchrone, un programme peut appeler termkey_waitkey(3). Cela renverra un événement de son tampon interne, ou bloquera jusqu'à ce qu'une touche soit disponible, la renvoyant lorsqu'elle sera prête. Cela se comporte de manière similaire à getc(3), fgetc(3), ou similaire, sauf qu'elle comprend et renvoie des événements de frappe clavier entiers, plutôt que des octets uniques.

Pour travailler avec un programme asynchrone, deux autres fonctions sont utilisées. termkey_advisereadable(3) informe une instance termkey que d'autres octets d'entrée peuvent être disponibles à partir de son descripteur de fichier, afin qu'elle appelle read(2) pour les obtenir. Le programme peut alors appeler termkey_getkey(3) pour extraire les événements de frappe clavier du tampon interne, d'une manière similaire à termkey_waitkey().

Enfin, les octets d'entrée peuvent être transmis directement à l'instance termkey, en appelant termkey_push_bytes(3). Cela peut être utile si les octets ont déjà été lus du terminal par l'application, ou même dans des situations qui n'impliquent pas directement un descripteur de fichier de terminal. En raison de ces situations, il est possible de construire une instance termkey non associée à un descripteur de fichier, en passant -1 comme descripteur de fichier.

Une instance termkey contient un tampon d'octets en attente qui ont été lus mais pas encore consommés par termkey_getkey(3). termkey_get_buffer_remaining(3) renvoie le nombre d'octets d'espace tampon actuellement libre dans l'instance. termkey_set_buffer_size(3) et termkey_get_buffer_size(3) peuvent être utilisés pour contrôler et renvoyer la taille totale de ce tampon.

Événements clavier

Les événements clavier sont stockés dans des structures. Chaque structure contient les détails d'un événement clavier. Cette structure est définie comme suit.


typedef struct {
    TermKeyType type;
    union {
        long       codepoint; /* TERMKEY_TYPE_UNICODE  */
        int        number;    /* TERMKEY_TYPE_FUNCTION */
        TermKeySym sym;       /* TERMKEY_TYPE_KEYSYM   */
    } code;
    int modifiers;
    char utf8[7];
} TermKeyKey;

Le champ type indique le type d'événement et détermine quel membre de l'union code est valide. Ce sera l'une des constantes suivantes :

TERMKEY_TYPE_UNICODE
un point de code Unicode. Cette valeur indique que code.codepoint est valide et contiendra le numéro du point de code de la frappe clavier. En mode Unicode (si le bit TERMKEY_FLAG_UTF8 est défini), ce sera son numéro de caractère Unicode. En mode octet brut, il contiendra un seul octet de 8 bits.
TERMKEY_TYPE_FUNCTION
une touche de fonction numérotée. Cette valeur indique que code.number est valide et contient le numéro de la touche de fonction numérotée.
TERMKEY_TYPE_KEYSYM
une touche symbolique. Cette valeur indique que code.sym est valide et contient la valeur symbolique de la touche.
TERMKEY_TYPE_MOUSE
un clic, un relâchement ou un mouvement de bouton de souris. La structure code doit être considérée comme opaque ; termkey_interpret_mouse(3) peut être utilisée pour l'interpréter.
TERMKEY_TYPE_POSITION
un rapport de position du curseur. La structure code doit être considérée comme opaque ; termkey_interpret_position(3) peut être utilisée pour l'interpréter.
TERMKEY_TYPE_MODEREPORT
un rapport de valeur de mode ANSI ou DEC. La structure code doit être considérée comme opaque ; termkey_interpret_modereport(3) peut être utilisée pour l'interpréter.
TERMKEY_TYPE_DCS
une séquence DCS incluant son terminateur. La structure code doit être considérée comme opaque ; termkey_interpret_string(3) peut être utilisée pour l'interpréter.
TERMKEY_TYPE_OSC
une séquence OSC incluant son terminateur. La structure code doit être considérée comme opaque ; termkey_interpret_string(3) peut être utilisée pour l'interpréter.
TERMKEY_TYPE_UNKNOWN_CSI
une séquence CSI non reconnue. La structure code doit être considérée comme opaque ; termkey_interpret_csi(3) peut être utilisée pour l'interpréter.

Le masque de bits modifiers est composé d'un OU binaire des constantes TERMKEY_KEYMOD_SHIFT, TERMKEY_KEYMOD_CTRL et TERMKEY_KEYMOD_ALT.

Le champ utf8 est uniquement défini pour les événements dont le type est TERMKEY_TYPE_UNICODE. Il ne doit pas être lu pour d'autres événements.

Les événements clavier représentant des touches spéciales (type est TERMKEY_TYPE_KEYSYM) ont une valeur symbolique qui identifie la touche spéciale, dans code.sym. termkey_get_keyname(3) peut être utilisée pour convertir cette valeur symbolique en une chaîne de caractères, et termkey_lookup_keyname(3) peut être utilisée pour convertir des noms de chaînes en valeurs symboliques.

Une paire de fonctions est également fournie pour convertir entre les événements clavier et les chaînes de caractères. termkey_strfkey(3) convertit un événement clavier en une chaîne, et termkey_strpkey(3) analyse une chaîne en la transformant en un événement clavier.

Les événements clavier peuvent être comparés pour égalité ou ordre en utilisant termkey_keycmp(3).

Indicateurs de contrôle

Les détails du comportement d'une instance termkey sont contrôlés par deux masques de bits d'indicateurs. termkey_set_flags(3) et termkey_get_flags(3) définissent ou renvoient les indicateurs utilisés pour contrôler le comportement général, et termkey_set_canonflags(3) et termkey_get_canonflags(3) définissent ou renvoient les indicateurs qui contrôlent le comportement de canonicalisation des valeurs de touches effectué par termkey_canonicalise(3).

Les indicateurs de contrôle suivants sont reconnus.

TERMKEY_FLAG_RAW
En mode brut, les octets sont retournés tels quels, sans aucune interprétation. Le seul événement qui sera généré est TERMKEY_TYPE_UNICODE avec un champ codepoint contenant l'octet lu. Ce mode est désactivé par défaut.
TERMKEY_FLAG_UTF8
En mode UTF-8, les séquences d'octets qui peuvent être interprétées comme des caractères Unicode sont converties en événements TERMKEY_TYPE_UNICODE. Les octets qui ne forment pas des caractères Unicode valides sont retournés individuellement comme événements TERMKEY_TYPE_UNICODE. Ce mode est activé par défaut.
TERMKEY_FLAG_SPACESYMBOL
Lorsque l'indicateur TERMKEY_FLAG_SPACESYMBOL est activé, la touche Espace sera interprétée comme une touche symbolique (type TERMKEY_TYPE_KEYSYM) ayant la valeur TERMKEY_SYM_SPACE. Par défaut, l'espace est interprétée comme un caractère Unicode.
TERMKEY_FLAG_CRLF
Lorsque l'indicateur TERMKEY_FLAG_CRLF est activé, les séquences de retours chariot (CR) seront interprétées comme des sauts de ligne (LF). Cela est utile lorsque le programme s'attend à des sauts de ligne (LF) pour représenter les fins de ligne, mais que le terminal peut envoyer des retours chariot (CR) seuls. Cet indicateur est désactivé par défaut.

Les indicateurs de canonicalisation suivants sont reconnus.

TERMKEY_CANON_DELKEY
Lorsque l'indicateur TERMKEY_CANON_DELKEY est activé, la touche Suppr (souvent envoyée comme code d'échappement différent selon le terminal) sera normalisée en un événement représentant la touche Suppr.
TERMKEY_CANON_DELCRLF
Lorsque l'indicateur TERMKEY_CANON_DELCRLF est activé, une touche Entrée envoyée comme retour chariot (CR) sera également traitée comme une fin de ligne (LF). Elle sera également interprétée comme une combinaison de CR et LF (retour chariot, saut de ligne).
TERMKEY_CANON_BLINK
Lorsque l'indicateur TERMKEY_CANON_BLINK est activé, les séquences de touches envoyées pour activer ou désactiver le clignotement du curseur seront converties en événements de touche symbolique, plutôt qu'en séquences d'échappement brutes.

L'utilisateur doit appeler cela à un moment ultérieur avant que l'instance ne soit utilisable.

Les drapeaux de canonicalisation suivants sont reconnus.

TERMKEY_CANON_SPACESYMBOL
Si ce drapeau est défini, alors un caractère d'espace Unicode est représenté en utilisant le symbole TERMKEY_SYM_SPACE. Si ce drapeau n'est pas défini, il est représenté par le point de code Unicode U+0020.
TERMKEY_CANON_DELBS
Si ce drapeau est défini, alors un caractère ASCII DEL est représenté par le symbole TERMKEY_SYM_BACKSPACE. Sinon, il est représenté par TERMKEY_SYM_DEL. Un caractère ASCII BS est toujours représenté par TERMKEY_SYM_BACKSPACE, quel que soit ce drapeau.

Événements multi-octets

Les touches spéciales, les événements de souris et le texte Unicode encodé en UTF-8 sont tous représentés par plusieurs octets. Si le début d'une séquence multi-octets est vu par termkey_waitkey(), il attendra un court instant pour voir si le reste de la séquence arrive. Si la séquence reste incomplète après ce délai, elle sera retournée dans son état incomplet. Les séquences d'échappement partielles sont retournées comme une touche Échap (TERMKEY_SYM_ESCAPE) suivie du texte contenu dans la séquence. Les séquences UTF-8 partielles sont retournées comme le caractère de remplacement Unicode, U+FFFD.

La durée pendant laquelle l'instance termkey attend est définie par termkey_set_waittime(3), et est retournée par termkey_get_waittime(3). Initialement, elle sera définie à 50 millisecondes.

Événements de souris

Le type d'événement TERMKEY_TYPE_MOUSE indique un événement de souris. Le champ code de la structure d'événement doit être considéré comme opaque, bien que modifiers sera valide. Pour obtenir les détails de l'événement de souris, appelez termkey_interpret_mouse(3) en passant la structure d'événement et des pointeurs vers des entiers pour y stocker le résultat.

termkey reconnaît trois protocoles de souris : le protocole X10 original (CSI M suivi de trois octets), l'encodage SGR (CSI < ... M, comme demandé par CSI ? 1006 h), et l'encodage rxvt (CSI ... M, comme demandé par CSI ? 1015 h). Quel encodage est utilisé est déduit automatiquement par termkey, et n'a pas besoin d'être spécifié explicitement.

Événements de position

Le type d'événement TERMKEY_TYPE_POSITION indique un rapport de position du curseur. Ceci est généralement envoyé par un terminal en réponse à la commande "Rapport de position du curseur" (CSI ? 6 n). Les octets de l'événement sont opaques, mais peuvent être obtenus en appelant termkey_interpret_position(3) en passant la structure d'événement et des pointeurs vers des entiers pour y stocker le résultat. Notez que seule une séquence DEC CPR (CSI ? R) est reconnue, et non le préfixe non-DEC CSI R car ce dernier pourrait être interprété comme la touche de fonction F3 à la place.

Rapports de mode

Le type d'événement TERMKEY_TYPE_MODEREPORT indique un rapport de mode ANSI ou DEC. Ceci est généralement envoyé par un terminal en réponse à la commande "Requête de mode" (CSI $p ou CSI ? $p). Les octets de l'événement sont opaques, mais peuvent être obtenus en appelant termkey_interpret_modereport(3) en passant la structure d'événement et des pointeurs vers des entiers pour y stocker le résultat.

Chaînes de contrôle

Les types d'événements TERMKEY_TYPE_DCS et TERMKEY_TYPE_OSC indiquent une chaîne de contrôle DCS ou OSC. Celles-ci sont généralement envoyées par le terminal en réponse à des chaînes similaires envoyées comme requêtes par l'application. Les octets de l'événement sont opaques, mais le corps de la chaîne elle-même peut être obtenu en appelant termkey_interpret_string(3) immédiatement après la réception de cet événement. L'instance termkey sous-jacente ne peut stocker qu'une chaîne en attente, donc l'application doit s'assurer d'appeler cette fonction rapidement après la réception de l'événement ; au minimum, avant d'appeler toute autre fonction qui insérera des octets dans l'instance ou en retirera des événements de touche.

CSI non reconnus

Le type d'événement TERMKEY_TYPE_UNKNOWN_CSI indique une séquence CSI que termkey ne reconnaît pas. Elle aura été extraite du flux, mais est disponible pour que l'application l'inspecte en appelant termkey_interpret_csi(3). Il est important que si l'application souhaite inspecter cette séquence, cela soit fait immédiatement, avant toute autre opération d'E/S sur l'instance termkey (spécifiquement, avant d'appeler à nouveau termkey_waitkey() ou termkey_getkey()), sinon l'espace tampon consommé par la séquence sera écrasé. D'autres types d'événements de touche ne souffrent pas de cette limitation car la structure TermKeyKey est suffisante pour contenir toutes les informations requises.
