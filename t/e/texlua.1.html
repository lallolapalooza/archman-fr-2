LUATEX(1) Manuel des commandes générales LUATEX(1)

NOM

luatex, dviluatex, luahbtex, luajittex, texlua, texluac - Une version étendue de TeX utilisant Lua comme langage de script embarqué

SYNTAXE

luatex [--lua=FICHIER] [OPTION]... [NOMTEX[.tex]] [COMMANDES]
luatex [--lua=FICHIER] [OPTION]... \PREMIERE-LIGNE
luatex [--lua=FICHIER] [OPTION]... &FMT [ARGS]

DESCRIPTION

Exécute le compositeur luaTeX sur NOMTEX, créant généralement NOMTEX.pdf. Toutes les COMMANDES restantes sont traitées comme une entrée luaTeX, après la lecture de NOMTEX.

Alternativement, si le premier argument non-option commence par une barre oblique inverse, interpréter tous les arguments non-options comme une ligne d'entrée luaTeX.

Alternativement, si le premier argument non-option commence par un &, le mot suivant est considéré comme le FMT à lire, remplaçant tout le reste. Tous les arguments restants sont traités comme ci-dessus.

Si aucun argument ou option n'est spécifié, demande une entrée.

Si appelé comme texlua, il agit comme un interpréteur Lua. Si appelé comme texluac, il agit comme un compilateur de bytecode Lua.

LuaTeX a commencé comme une version étendue de pdfTeX avec prise en charge d'Unicode et de polices OpenType, langage de script embarqué Lua, les extensions e-TeX et Omega, ainsi qu'un moteur MetaPost intégré, capable de créer des fichiers PDF ainsi que des fichiers DVI. Pour plus d'informations sur luatex, voir http://www.luatex.org ; et vous pouvez lire le manuel LuaTeX en utilisant l'utilitaire texdoc (texdoc luatex).

Toute entrée et sortie de texte LuaTeX est considérée comme du texte Unicode, bien que divers filtres permettent de prendre en charge n'importe quelle encodage.

En mode DVI, LuaTeX peut être utilisé comme un remplacement complet du moteur TeX.

En mode PDF, LuaTeX peut gérer nativement les formats graphiques PDF, JPG, JBIG2 et PNG. LuaTeX ne peut pas inclure de fichiers graphiques PostScript ou Encapsulated PostScript (EPS) ; convertissez-les d'abord en PDF en utilisant epstopdf(1).

La variante luajittex inclut le compilateur Just-In-Time (JIT) de Lua.

La variante luahbtex peut utiliser le moteur HarfBuzz pour la mise en forme des glyphes, au lieu du moteur de mise en forme intégré de LuaTeX.

OPTIONS

Lorsque l'exécutable LuaTeX démarre, il recherche l'option de ligne de commande --lua. S'il n'y a pas d'option --lua, la ligne de commande est interprétée de manière similaire aux programmes web2c traditionnels. Mais si l'option est présente, LuaTeX entrera dans un mode alternatif d'analyse de ligne de commande par rapport aux programmes web2c standards. La présence de --lua rend la plupart des autres options peu fiables, car le fichier d'initialisation lua peut désactiver kpathsea et/ou accrocher des fonctions à divers callbacks.

--lua=FICHIER
Le fichier d'initialisation lua.

Les deux options suivantes modifient le comportement de l'exécutable :

--luaonly
Démarre LuaTeX comme un interpréteur Lua. Dans ce mode, il définira arg[0] de Lua sur le nom du script trouvé, en poussant les options précédentes dans des valeurs négatives et le reste de la ligne de commande dans les valeurs positives, tout comme l'interpréteur Lua. LuaTeX se terminera immédiatement après l'exécution du script Lua spécifié.
--luaconly
Démarre LuaTeX comme un compilateur de bytecode Lua. Dans ce mode, LuaTeX est exactement comme luac de la distribution Lua autonome, sauf qu'il n'a pas le commutateur -l, et qu'il accepte (mais ignore) le commutateur --luaconly.

Ensuite, les options web2c régulières :

--debug-format

Débogage du chargement des formats.
--draftmode
Définit \pdfdraftmode afin que luaTeX n'écrive pas de PDF et ne lise pas les images incluses, accélérant ainsi l'exécution.
--enable-write18

Synonyme de --shell-escape.
--disable-write18

Synonyme de --no-shell-escape.
--shell-escape

Active la construction \write18{commande}, ainsi que les fonctions Lua os.execute(), os.exec(), os.spawn() et io.popen(). La commande peut être n'importe quelle commande de shell. Cette construction est normalement interdite pour des raisons de sécurité.
--no-shell-escape

Désactive la construction \write18{commande} et les autres fonctions Lua, même si elle est activée dans le fichier texmf.cnf.
--shell-restricted
Active une version restreinte de \write18, os.execute(), os.exec(), os.spawn() et io.popen() ; seules les commandes listées dans le fichier texmf.cnf sont autorisées.
--file-line-error
Affiche les messages d'erreur sous la forme fichier:ligne:erreur, similaire à la façon dont de nombreux compilateurs les formatent.
--no-file-line-error
Désactive l'affichage des messages d'erreur dans le style fichier:ligne:erreur.
--fmt=FORMAT
Utilise FORMAT comme nom du format à utiliser, au lieu du nom sous lequel luaTeX a été appelé ou d'une ligne %&.
--help
Affiche un message d'aide et quitte.
--ini
Démarre en mode INI, utilisé pour dumper les formats. Le mode INI peut être utilisé pour la composition, mais aucun format n'est préchargé, et des initialisations de base comme la définition des codes de catégorie peuvent être nécessaires.
--interaction=MODE
Définit le mode d'interaction. Le MODE peut être batchmode, nonstopmode, scrollmode, ou errorstopmode. La signification de ces modes est la même que celle des \commands correspondants.
--jobname=NOM
Utilise NOM pour le nom du job, au lieu de le dériver du nom du fichier d'entrée.
--kpathsea-debug=MASQUE
Définit les indicateurs de débogage de recherche de chemins selon le MASQUE. Voir le manuel de Kpathsea pour les détails.
--mktex=FMT
Active la génération de mktexFMT, où FMT doit être tex ou tfm.
--nosocket
Désactive la bibliothèque luasocket (réseau).
--output-comment=CHAÎNE
En mode DVI, utilise CHAÎNE pour le commentaire du fichier DVI au lieu de la date. Cette option est ignorée en mode PDF.
--output-directory=RÉPERTOIRE
Écrit les fichiers de sortie dans RÉPERTOIRE au lieu du répertoire courant. Recherche les fichiers d'entrée dans RÉPERTOIRE d'abord, puis le long du chemin de recherche normal.
--output-format=FORMAT
Définit le mode du format de sortie, où FORMAT doit être soit pdf, soit dvi. Ceci influence également l'ensemble des formats graphiques compris par luaTeX.
--progname=NOM
Prétend être le programme NOM (uniquement pour kpathsea).
--recorder
Active l'enregistreur de noms de fichiers. Ceci laisse une trace des fichiers ouverts en entrée et en sortie dans un fichier avec l'extension .fls.
--safer
Désactive certaines commandes Lua qui peuvent être facilement exploitées par un document malveillant.
--syncte
x=NUMÉRO
Activer/désactiver l'extension SyncTeX.
--version
Afficher les informations de version et quitter.
--credits
Afficher les crédits et les détails de la version.
Les options suivantes sont ignorées :
--8bit, --etex, --parse-first-line, --no-parse-first-line
Celles-ci sont toujours activées.
--default-translate-file=NOM_TCX, --translate-file=NOM_TCX
Celles-ci sont toujours désactivées.

AUTEURS

Les auteurs principaux de LuaTeX sont Taco Hoekwater, Hartmut Henkel, Hans Hagen et Luigi Scarso, avec l'aide de Martin Schröder, Karel Skoupy et Han The Thanh.

TeX a été conçu par Donald E. Knuth, qui l'a implémenté en utilisant son système Web pour les programmes Pascal. Il a été porté sur Unix à Stanford par Howard Trickey, et à Cornell par Pavel Curtis. La version maintenant proposée avec la distribution Unix TeX est celle générée par le système Web vers C (web2c), initialement écrit par Tomas Rokicki et Tim Morgan.

La page d'accueil de LuaTeX est http://luatex.org.
