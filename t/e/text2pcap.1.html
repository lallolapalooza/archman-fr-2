NOM

text2pcap - Générer un fichier de capture à partir d'une extraction hexadécimale ASCII de paquets

SYNTAXE

text2pcap [ -a ] [ -b 2|8|16|64 ] [ -D ] [ -e <ethertype> ] [ -E <encapsulation type> ] [ -F <file format> ] [ -i <proto> ] [ -l <typenum> ] [ -N <intf-name> ] [ -m <max-packet> ] [ -o hex|oct|dec|none ] [ -q ] [ -r <regex> ] [ -s <srcport>,<destport>,<tag> ] [ -S <srcport>,<destport>,<ppi> ] [ -t <timefmt> ] [ -T <srcport>,<destport> ] [ -u <srcport>,<destport> ] [ -4 <srcip>,<destip> ] [ -6 <srcip>,<destip> ] [ --little-endian ] <infile>|- <outfile>|-

text2pcap -h|--help

text2pcap -v|--version

DESCRIPTION

Text2pcap est un programme qui lit une extraction hexadécimale ASCII et écrit les données décrites dans un fichier de capture. text2pcap peut lire des extractions hexadécimales contenant plusieurs paquets et construire un fichier de capture de plusieurs paquets. Text2pcap est également capable de générer des en-têtes Ethernet, IP et UDP, TCP ou SCTP factices, afin de construire des dumps de paquets entièrement traitables à partir d'extractions hexadécimales de données uniquement au niveau de l'application.

Text2pcap peut écrire le fichier dans plusieurs formats de sortie. L'indicateur -F peut être utilisé pour spécifier le format dans lequel écrire le fichier de capture, text2pcap -F fournit une liste des formats de sortie disponibles. Par défaut, il écrit les paquets dans outfile au format de fichier pcapng. Text2pcap prend également en charge les formats de compression, qui peuvent être spécifiés avec les options --compress. Si cette option n'est pas donnée, la méthode de compression souhaitée, le cas échéant, est déduite de l'extension de outfile ; par exemple, si elle a l'extension '.gz', le fichier de sortie est compressé dans une archive gzip.

Text2pcap comprend de nombreux formats d'extraction hexadécimale différents. Le format natif que Wireshark affiche dans le volet Octets du paquet, copie dans le presse-papiers, imprime et enregistre, et que tshark produit avec l'option --hexdump est celui généré par od -Ax -tx1 -v ou hexdump -X -v. C'est-à-dire que chaque ligne doit commencer par un décalage décrivant la position dans le paquet, chaque octet est affiché individuellement, avec des espaces séparant les octets les uns des autres, et les lignes répétées ou entièrement constituées de NUL ('\0') ne sont pas omises. Les chiffres hexadécimaux peuvent être en majuscules ou en minuscules. Text2pcap peut gérer d'autres formats d'extraction hexadécimale, dont certains peuvent être détectés automatiquement et dont certains nécessitent l'activation d'options pour être correctement reconnus.

Les décalages sont suivis d'un ou plusieurs espaces ou tabulations les séparant des octets. Les décalages peuvent éventuellement être suivis d'un seul deux-points après les chiffres. Les décalages peuvent être compris entre 3 et 8 chiffres ; la base hexadécimale (radix) est supposée par défaut, mais ils peuvent être en octal ou décimal - voir -o. Si les décalages sont en hex, ils peuvent être précédés de 0x ou 0X. Chaque paquet doit commencer par le décalage zéro, et un décalage zéro indique le début d'un nouveau paquet. Les valeurs de décalage doivent être correctes ; une valeur inattendue entraîne l'abandon du paquet courant et l'attente du début du paquet suivant. Il existe également un mode à paquet unique sans décalages ; voir -o.

Il n'y a aucune limite sur la largeur ou le nombre d'octets par ligne, mais les lignes contenant uniquement des octets hexadécimaux sans décalage initial sont ignorées (en d'autres termes, les sauts de ligne ne doivent pas être insérés dans les lignes longues qui s'enroulent.) Les octets doivent être en hexadécimal ; contrairement aux décalages (et au mode regex alternatif mentionné plus loin), d'autres bases telles que l'octal, le décimal ou le binaire ne sont pas supportées. Les groupes d'octets de deux à quatre octets sont également pris en charge. Par défaut, les groupes d'octets sont supposés être en ordre d'octets réseau (big-endian) ; l'option --little-endian peut être utilisée pour prendre en charge l'ordre d'octets little-endian.

Les paquets peuvent être précédés d'un indicateur de direction ('I' ou 'O') et/ou d'une horodatage si indiqué par la ligne de commande (voir -D et -t). Si les deux sont présents, l'indicateur de direction précède l'horodatage. Le format des horodatages est spécifié comme paramètre obligatoire à -t. Si aucun horodatage n'est analysé, dans le cas du premier paquet, l'heure système actuelle est utilisée, tandis que les paquets suivants sont écrits avec des horodatages une microseconde plus tard que ceux du paquet précédent.

D'autres textes dans les données d'entrée sont ignorés. Tout texte avant le décalage est ignoré, y compris les caractères de transfert d'e-mail '>'. Tout texte sur une ligne après les octets est ignoré, par exemple un dump de caractères ASCII (mais voir -a pour s'assurer que les chiffres hexadécimaux dans le dump de caractères sont ignorés s'il n'y a pas de délimiteur entre le dump hexadécimal et la traduction des caractères ASCII). Toute ligne dont le premier caractère non blanc est un '#' sera ignorée comme commentaire. Certains utilitaires d'extraction hexadécimale utilisent une ligne contenant un unique '*' pour indiquer les lignes omises, soit en dupliquant la ligne précédente, soit entièrement composée d'octets NUL ('\0') ; ceci n'est pas supporté. Toutes les lignes de texte entre les lignes de chaînes d'octets sont considérées comme un préambule ; le début du préambule est analysé pour l'indicateur de direction et l'horodatage comme mentionné ci-dessus et sinon ignoré.

Toute ligne commençant par #TEXT2PCAP est une directive et des options peuvent être insérées après cette commande pour être traitées par text2pcap. Actuellement, aucune directive n'est implémentée ; à l'avenir, elles pourront être utilisées pour un contrôle plus fin du dump et de la manière dont il doit être traité, par exemple les horodatages, le type d'encapsulation, etc.

En général, à part ces restrictions, text2pcap est assez libéral dans la lecture des extractions hexadécimales et a été testé avec une variété de sorties corrompues (y compris après avoir été transférées par e-mail plusieurs fois, avec un enroulement de ligne limité, etc.)

Voici un exemple de dump que text2pcap peut reconnaître, avec un indicateur directionnel et un horodatage optionnels :

000000 00 0e b6 00 00 02 00 0e b6 00 00 01 08 00 45 00
000010 00 28 00 00 00 00 ff 01 37 d1 c0 00 02 01 c0 00
000020 02 02 08 00 a6 2f 00 01 00 01 48 65 6c 6c 6f 20
000030 57 6f 72 6c 64 21
000036

Text2pcap est également capable d'analyser un fichier d'entrée texte en utilisant une expression régulière personnalisée compatible Perl qui correspond à un seul paquet. text2pcap recherche dans le fichier donné (qui doit se terminer par '\n') les chaînes non vides et non chevauchantes correspondant à l'expression régulière. Les sous-groupes de capture nommés, qui doivent correspondre exactement une fois par paquet, sont utilisés pour identifier les champs à importer. Les champs suivants sont pris en charge en mode regex, un obligatoire et trois optionnels :

"data"  Données capturées réelles à importer
"time"  Horodatage du paquet
"dir"   Direction du paquet
"seqno" ID arbitraire du paquet

Le champ 'data' représente les données capturées, qui doivent être dans un encodage choisi : hexadécimal (par défaut), octal, binaire ou base64 et ne contenir aucun caractère dans le champ de données en dehors de l'ensemble d'encodage, à l'exception des espaces blancs. Le champ 'time' est analysé conformément au format spécifié dans le paramètre -t. Le premier caractère du champ 'dir' est comparé à un ensemble de caractères correspondant à l'entrée et à la sortie, qui par défaut sont "iI<" pour l'entrée et "oO>" pour la sortie, afin d'attribuer une direction. Le champ 'seqno' est supposé être un entier positif en base 10 utilisé pour un ID arbitraire. Les informations d'un champ optionnel ne seront écrites que si le champ est présent dans l'expression régulière et si le format du fichier de capture le prend en charge. (Par exemple, le format pcapng prend en charge les trois champs, mais le format pcap ne prend en charge que les horodatages.)

Voici un exemple de dump que le mode regex peut traiter avec l'expression régulière '^(?<dir>[<>])\s(?<time>\d+:\d\d:\d\d.\d+)\s(?<data>[0-9a-fA-F]+)$' avec le format d'horodatage '%H:%M:%S.%f', des indications directionnelles de '<' et '>', et un encodage hexadécimal :

> 0:00:00.280836 a1216c8b00000000000089086b0b82020407
< 0:00:00.295459 a2010800000000000000000800000000
> 0:00:00.296982 a1303c8b00000008007088286b0bc1ffcbf0f9ff
> 0:00:00.305644 a121718b0000000000008ba86a0b8008
< 0:00:00.319061 a2010900000000000000001000600000
> 0:00:00.330937 a130428b00000008007589186b0bb9ffd9f0fdfa3eb4295e

99f3aaffd2f005 > 0:00:00.356037 a121788b0000000000008a18

L'expression régulière est compilée avec le support multiligne, et il est recommandé d'utiliser les ancres '^' et '$' pour de meilleurs résultats.

Text2pcap permet également à l'utilisateur de lire des dépôts de données au niveau applicatif et d'insérer des en-têtes factices L2, L3 et L4 avant chaque paquet. Cela permet à Wireshark ou à tout autre décodeur de paquets complets de gérer ces dépôts. Si le type d'encapsulation est Ethernet, l'utilisateur peut choisir d'insérer des en-têtes Ethernet, des en-têtes Ethernet et IP, ou des en-têtes Ethernet, IP et UDP/TCP/SCTP avant chaque paquet. Les en-têtes factices peuvent également être utilisés avec les encapsulations Raw IP, Raw IPv4 ou Raw IPv6, sans l'en-tête Ethernet. Ces options d'encapsulation peuvent être utilisées en mode dépôt hexadécimal et en mode expression régulière.

Lorsque <infile> ou <outfile> sont '-', l'entrée standard ou la sortie standard, respectivement, sont utilisées.

OPTIONS

-a

Active l'identification des dépôts de texte ASCII. Cela permet d'identifier le début du dépôt de texte ASCII et de ne pas l'inclure dans le paquet, même s'il ressemble à du HEX. Ce paramètre n'a aucun effet en mode expression régulière.

NOTE : Ne l'activez pas si le fichier d'entrée ne contient pas le dépôt de texte ASCII, ou si le dépôt ASCII est séparé du dépôt hexadécimal par un délimiteur non blanc tel que |.

-b 2|8|16|64

Spécifie la base (radix) du codage des données du paquet en mode expression régulière. Les options supportées sont 2 (binaire), 8 (octal), 16 (hexadécimal) et 64 (encodage base64), hexadécimal étant la valeur par défaut. Ce paramètre n'a aucun effet en mode dépôt hexadécimal.

-D

Indique que le texte avant chaque paquet d'entrée peut commencer soit par un I ou un O indiquant que le paquet est entrant ou sortant. Si ce flag et le flag t sont utilisés, l'indicateur directionnel est attendu avant le code temporel. Ce paramètre n'a aucun effet en mode expression régulière, où la présence du groupe capturant <dir> détermine si les indicateurs de direction sont attendus.

L'indication de direction est stockée dans les en-têtes de paquet si le format de sortie le prend en charge (par ex. pcapng), et est également utilisée lors de la génération d'en-têtes factices pour échanger les adresses et ports source et destination de manière appropriée.

-e <ethertype>

Inclut un en-tête Ethernet factice avant chaque paquet. Spécifie l'EtherType pour l'en-tête Ethernet en hexadécimal. Utilisez cette option si votre dépôt contient un en-tête de couche 3 et une charge utile (par ex. en-tête IP), mais pas d'encapsulation de couche 2. Exemple : -e 0x806 pour spécifier un paquet ARP.

Pour les paquets IP, au lieu de générer un en-tête Ethernet factice, vous pouvez également utiliser -E rawip ou -l 101 pour indiquer une encapsulation IP brute. Notez que l'encapsulation IP brute ne fonctionne pas pour les paquets de couche 3 autres que IP (par ex. ARP), tandis que la génération d'un en-tête Ethernet factice avec -e fonctionne pour tout type de paquet L3.

-E <type d'encapsulation>

Définit le type d'encapsulation des paquets pour le fichier de capture de sortie. text2pcap -E fournit une liste des types disponibles ; notez que tous les formats de fichiers ne prennent pas en charge tous les types d'encapsulation. Le type par défaut est ether (Ethernet).

NOTE : Ceci définit le type d'encapsulation du fichier de sortie, mais ne traduit pas les en-têtes de paquet ni n'ajoute d'en-têtes supplémentaires. Il est utilisé pour spécifier l'encapsulation qui correspond aux données d'entrée.

-F <format de fichier>

Définit le format de fichier du fichier de capture de sortie. Text2pcap peut écrire le fichier dans plusieurs formats ; text2pcap -F fournit une liste des formats de sortie disponibles. Le défaut est le format pcapng.

-h|--help

Affiche le numéro de version et les options, puis quitte.

-i <proto>

Inclut des en-têtes IP factices avant chaque paquet. Spécifie le protocole IP pour le paquet en décimal. Utilisez cette option si votre dépôt est la charge utile d'un paquet IP (c'est-à-dire qu'il contient des informations complètes de couche 4) mais ne contient pas d'en-tête IP avec chaque paquet. Notez qu'un en-tête Ethernet approprié est automatiquement inclus avec chaque paquet si le type de couche liaison est Ethernet. Exemple : -i 46 pour spécifier un paquet RSVP (protocole IP 46). Voir https://www.iana.org/assignments/protocol-numbers/protocol-numbers.xhtml pour la liste complète des numéros de protocole Internet attribués.

-l <numéro de type>

Définit le type d'encapsulation des paquets pour le fichier de capture de sortie, en utilisant les numéros de type d'en-tête de couche liaison pcap. Par défaut, Ethernet (1). Voir https://www.tcpdump.org/linktypes.html pour la liste complète des encapsulations possibles. Exemple : -l 7 pour les paquets ARCNet encapsulés à la manière BSD.

-m <paquet maximum>

Définit la longueur maximale du paquet, par défaut 262144. Utile pour tester différentes frontières de paquet lorsqu'un flux de données au niveau applicatif est uniquement disponible. Exemple :

od -Ax -tx1 -v stream | text2pcap -m1460 -T1234,1234 - stream.pcap

convertira un flux de données brut en une séquence de paquets Ethernet TCP.

-N <nom d'interface>

Spécifie un nom pour l'interface incluse lors de l'écriture d'un fichier au format pcapng.

-o hex|oct|dec|none

Spécifie le radix pour les décalages (hexadécimal, octal, décimal ou aucun). Par défaut, hexadécimal. Ceci correspond à l'option -A pour od. Ce paramètre n'a aucun effet en mode expression régulière.

NOTE : Avec -o none, un seul paquet sera créé, ignorant tout indicateur de direction ou horodatage après le premier octet, ainsi que tous les décalages.

-P <dissecteur>

Inclut un en-tête EXPORTED_PDU avant chaque paquet. Spécifie, sous forme de chaîne, le dissecteur à appeler pour le paquet (balise DISSECTOR_NAME). Utilisez cette option si votre dépôt est la charge utile d'un seul protocole de couche supérieure (donc spécifier un type de couche liaison ne fonctionnerait pas) et que vous souhaitez créer un fichier de capture sans pile de protocoles factice complète. Définit automatiquement le type de couche liaison sur Exportation PDU Supérieure Wireshark. Sans cette option, si le type de couche liaison Exportation PDU Supérieure (252) est sélectionné, le dissecteur par défaut est "data".

-q

Ne pas afficher le résumé des options sélectionnées au début, ni le nombre de paquets traités à la fin.

-r <expression régulière>

Traite le fichier en mode expression régulière en utilisant expression régulière comme décrit ci-dessus.

NOTE : Le mode expression régulière utilise des E/S mappées en mémoire et ne fonctionne pas sur les flux qui ne supportent pas la recherche, comme les terminaux et les pipes.

-s <port source>,<port destination>,<tag>

Inclut des en-têtes SCTP factices avant chaque paquet. Spécifie, en décimal, les ports SCTP source et destination, ainsi que le tag de vérification, pour le paquet. Utilisez cette option si votre dépôt est la charge utile SCTP d'un paquet mais n'inclut aucun en-tête SCTP, IP ou Ethernet. Notez que des en-têtes Ethernet et IP appropriés sont également inclus automatiquement avec chaque paquet. Une somme de contrôle CRC32C sera placée dans l'en-tête SCTP.

-S <port source>,<port destination>,<ppi>

Inclut des en-têtes SCTP factices avant chaque paquet. Spécifie, en décimal, les ports SCTP source et destination, et un tag de vérification de 0, pour le paquet, et préfixe un en-tête de bloc de données SCTP factice avec un identifiant de protocole de charge utile si ppi. Utilisez cette option si votre dépôt est la charge utile SCTP d'un paquet mais n'inclut aucun en-tête SCTP, IP ou Ethernet. Notez que des en-têtes Ethernet et IP appropriés sont automatiquement inclus avec chaque paquet. Une somme de contrôle CRC32C sera placée dans l'en-tête SCTP.

-t <format de temps>

Traite le texte avant le paquet comme un code date/heure ; format de temps est une chaîne de format supportée par strftime(3), complétée avec le descripteur de champ '%f' pour les secondes fractionnaires jusqu'à la nanoseconde. Exemple : L'heure "10:15:14.5476" a le code de format "%H:%M:%S.%f". La chaîne de format spéciale ISO indique que la chaîne doit être analysée selon la spécification ISO-8601. Ce paramètre est utilisé en mode expression régulière si et seulement si le groupe capturant <time> est présent.

NOTE : Les champs date/heure de la date/heure actuelle sont utilisés par défaut pour les champs non spécifiés.

-T <port source>,<port destination>

Inclut des en-têtes TCP factices avant chaque paquet. Spécifie les ports TCP source et destination pour le paquet en décimal. Utilisez cette option si votre dépôt est la charge utile TCP d'un paquet mais n'inclut aucun en-tête TCP, IP ou Ethernet. Notez que des en-têtes Ethernet et IP appropriés sont également inclus automatiquement avec chaque paquet. Les numéros de séquence commenceront à 0.

-u <port source>,<port destination>

Inclut des en-têtes UDP factices avant chaque paquet. Spécifie les ports UDP source et destination pour le paquet en décimal. Utilisez cette option si votre dépôt est la charge utile UDP d'un paquet mais n'inclut aucun en-tête UDP, IP ou Ethernet. Notez que des en-têtes Ethernet et IP appropriés sont également inclus automatiquement avec chaque paquet. Exemple : -u1000,69 pour que les paquets ressemblent à des paquets TFTP/UDP.

-v|--version

Affiche les informations complètes de version, puis quitte.

-4 <ip source>,<ip destination>

Prépare un en-tête IP factice avec les adresses source et destination IPv4 spécifiées. Cette option doit être accompagnée de l'une des options suivantes : -i, -s, -S, -T, -u. Utilisez cette option pour appliquer des adresses IP "personnalisées". Exemple : -4 10.0.0.1,10.0.0.2 pour utiliser 10.0.0.1 et 10.0.0.2 pour tous les paquets IP.

-6 <ip source>,<ip destination>

Prépare un en-tête IP factice avec les adresses source et destination IPv6 spécifiées. Cette option doit être accompagnée de l'une des options suivantes : -i, -s, -S, -T, -u. Utilisez cette option pour appliquer des adresses IP "personnalisées". Exemple : -6 2001:db8::b3ff:fe1e:8329,2001:0db8:85a3::8a2e:0370:7334 pour utiliser 2001:db8::b3ff:fe1e:8329 et 2001:0db8:85a3::8a2e:0370:7334 pour tous les paquets IP.

--compress <type>

Compresse le fichier de sortie en utilisant le format de compression spécifié. --compress sans argument fournit une liste des types de compression disponibles.

NAME

text2pcap - Convert text-based network protocol dumps into pcap(5) files

SYNOPSIS

text2pcap [ -a ] [ -l ] [ -n ] [ -A snaplen ] [ -C choplen ] [ -D ] [ -E ] [ -i infile ] [ -o outfile ] [ -p snaplen ] [ -s snaplen ] [ -S ] [ -T ] [ -t ts_format ] [ -u ] [ -U ] [ -x ] [ -X ether type ] [ -y link_type ] [ --log-level level ] [ --log-fatal level ] [ --log-domains list ] [ --log-debug list ] [ --log-noisy list ] [ --log-fatal-domains list ] [ --log-file path ] [ infile...

DESCRIPTION

Text2pcap is a utility program that reads network protocol information supplied in various text file formats and writes the corresponding packet data, in pcap (see pcap(5)) format, to the specified output file.

The output file is a pcap file, which can be read by `tcpdump(8)` and `wireshark(1)`.

Text2pcap can read multiple input files. The input files can be specified on the command line, or read from standard input if no input files are specified.

The output file name is specified with the -o option. If not specified, the output file will be named output.pcap.

The packet size in the output pcap file is specified with the -p option. If not specified, the packet size will be automatically determined from the input data.

The link-layer type in the output pcap file is specified with the -y option. If not specified, the link-layer type will be assumed to be Ethernet.

The timestamp format in the input files can be specified with the -t option. If not specified, timestamps will be assumed to be missing.

The following input formats are supported:

-a
Enable the capture of ARP packets. By default, ARP packets are discarded.
-A
Set the default snaplen (maximum capture length) for packets. If not specified, the snaplen is set to 65535.
-C
Set the default choplen (capture length) for packets. If not specified, the choplen is set to 65535.
-D
Treat input lines as UTF-8 encoded.
-E
Treat input lines as UTF-16 encoded.
-i
Specify input file. This option can be used multiple times. If not used, standard input is assumed.
-l
Enable the capture of LACP packets. By default, LACP packets are discarded.
-n
Do not prepend packet numbers to output lines. By default, packet numbers are prepended.
-o
Specify output file. If not specified, defaults to output.pcap.
-p
Set the snaplen (maximum capture length) for packets. If not specified, the snaplen is set to 65535.
-s
Set the snaplen (maximum capture length) for packets. If not specified, the snaplen is set to 65535.
-S
Assume that the input file contains Ethernet packets.
-T
Assume that the input file contains TCP packets.
-t
Specify the timestamp format for the input file. The format string uses the same syntax as strftime(3).
-u
Assume that the input file contains UDP packets.
-U
Treat input lines as UTF-32 encoded.
-x
Hexadecimal dump of packets.
-X
Specify the Ethertype for the packets. If not specified, the Ethertype is assumed to be 0x0800 (IP).
-y
Specify the link-layer type for the output pcap file. If not specified, the link-layer type is assumed to be Ethernet.

DIAGNOSTIC OPTIONS

--log-level <level>

Set the active log level. Supported levels in lowest to highest order are "noisy", "debug", "info", "message", "warning", "critical", and "error". Messages at each level and higher will be printed, for example "warning" prints "warning", "critical", and "error" messages and "noisy" prints all messages. Levels are case insensitive.

--log-fatal <level>

Abort the program if any messages are logged at the specified level or higher. For example, "warning" aborts on any "warning", "critical", or "error" messages.

--log-domains <list>

Only print messages for the specified log domains, e.g. "GUI,Epan,sshdump". List of domains must be comma-separated. Can be negated with "!" as the first character (inverts the match).

--log-debug <list>

Force the specified domains to log at the "debug" level. List of domains must be comma-separated. Can be negated with "!" as the first character (inverts the match).

--log-noisy <list>

Force the specified domains to log at the "noisy" level. List of domains must be comma-separated. Can be negated with "!" as the first character (inverts the match).

--log-fatal-domains <list>

Abort the program if any messages are logged for the specified log domains. List of domains must be comma-separated.

--log-file <path>

Write log messages and stderr output to the specified file.
