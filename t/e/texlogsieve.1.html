TEXLOGSIEVE(1) Commandes Utilisateur TEXLOGSIEVE(1)

NOM

texlogsieve - filtre et résume les fichiers journaux LaTeX

SYNTAXE

texlogsieve [OPTION]... [FICHIER D'ENTRÉE]

DESCRIPTION

texlogsieve lit un fichier journal LaTeX (ou l'entrée standard si aucun fichier n'est spécifié), filtre les messages les moins pertinents et affiche un rapport de résumé.

texlogsieve doit être exécuté depuis le même répertoire que [pdf|lua|xe]latex, car il recherche les fichiers utilisés lors de la compilation (paquets chargés depuis le répertoire courant, fichiers inclus avec \input etc.). De plus, comme il ne peut pas détecter si LaTeX s'arrête pour une entrée utilisateur, vous devriez vraiment exécuter LaTeX en mode nonstopmode lorsque texlogsieve lit depuis un pipe.

Le programme s'efforce de gérer correctement le retour à la ligne de TeX. Il comprend la variable de configuration TeX max_print_line et lit sa valeur aux mêmes endroits que TeX. Définir max_print_line à une valeur supérieure à 9999 fait ignorer le retour à la ligne par texlogsieve.

Les valeurs par défaut sont raisonnables ; vous pouvez espérer faire simplement :

[pdf|lua|xe]latex -interaction nonstopmode monfichier.tex | texlogsieve

ou

texlogsieve monfichier.log

et être satisfait du résultat.

OPTIONS

--page-delay, --no-page-delay
Active/désactive le regroupement des messages par page avant l'affichage. Lorsque activé, les messages ne sont émis qu'après la fin de la page courante (shipout). L'avantage est que le numéro de page est inclus dans le message (activé par défaut).
--summary, --no-summary
Active/désactive le résumé final (activé par défaut).
--only-summary
Aucun message, affiche uniquement le résumé final (désactivé par défaut).
--shipouts, --no-shipouts
Active/désactive le rapport des shipouts (désactivé par défaut avec page-delay, activé sans page-delay).
--file-banner, --no-file-banner
Affiche/n'affiche pas les bannières “From file...” (activé par défaut, sauf avec le niveau DEBUG car ce serait redondant et confusant).
--repetitions, --no-repetitions
Autorise/empêche les messages répétés (désactivé par défaut, c'est-à-dire que les messages répétés sont supprimés).
--be-redundant, --no-be-redundant
Présente/supprime les messages ordinaires qui apparaîtront également dans le résumé. Ceci affecte les messages qui ont des résumés spéciaux (tels que les boîtes sous/pleines ou les citations non définies). Avec --no-be-redundant (la valeur par défaut), ces messages sont filtrés et n'apparaissent que dans le résumé final.
--box-detail, --no-box-detail
Inclut/exclut les informations détaillées sur les boîtes sous/pleines dans le résumé final. Avec --no-box-detail, le résumé présente uniquement une liste des pages et fichiers qui avaient des boîtes sous/pleines (activé par défaut).
--ref-detail, --no-ref-detail
Inclut/exclut les informations détaillées sur les références non définies dans le résumé final. Avec --no-ref-detail, le résumé présente uniquement une liste des références non définies, sans numéros de page ni noms de fichiers (activé par défaut).
--cite-detail, --no-cite-detail
Inclut/exclut les informations détaillées sur les citations non définies dans le résumé final. Avec --no-cite-detail, le résumé présente uniquement une liste des citations non définies, sans numéros de page ni noms de fichiers (activé par défaut).
--summary-detail, --no-summary-detail
Inverse --box-detail, --ref-detail et --cite-detail à la fois.
--heartbeat, --no-heartbeat
Active/désactive la jauge de progression en mode page-delay (activé par défaut).
--color, --no-color
Active/désactive la sortie colorée. Sous Windows, cela ne fonctionnera qu'avec une version de Windows 10 ou ultérieure (désactivé par défaut).
--tips, --no-tips
Active/désactive la suggestion de corrections pour certains avertissements connus (activé par défaut).
-l NIVEAU, --minlevel=NIVEAU
Filtre les messages dont le niveau de sévérité est inférieur à NIVEAU. Les niveaux valides sont DEBUG (pas de filtrage), INFO, WARNING, CRITICAL et UNKNOWN (par défaut WARNING).
-u, --unwrap-only
Ne filtre pas les messages et n'affiche pas le résumé, seulement déroule les longues lignes enroulées. La sortie devrait être très similaire (mais pas identique) au fichier d'entrée, mais avec les lignes enroulées reconstruites. Cela active -l debug, --no-summary, --no-page-delay, --repetitions, --be-redundant, --shipouts, et --no-file-banner, et supprime également les messages verbeux “ouverture/fermeture de fichier” et “shipout”, les simulant plutôt dans le format TeX, avec parenthèses et crochets. Ceci est utile si vous préférez les rapports générés par un autre outil, mais que vous souhaitez bénéficier de l'algorithme de déroulement de ligne de texlogsieve ; la sortie générée par cette option devrait être analysable par d'autres outils (mais vous devrez probablement forcer l'autre outil à ne pas essayer de dérouler les lignes).
--silence-package=NOMPAQUET
Filtre les messages qui peuvent être identifiés comme provenant du paquet donné. Utilisez cette option plusieurs fois pour supprimer les messages de plusieurs paquets différents.
--silence-string=EXTRAIT DU MESSAGE NON DÉSIRÉ
Filtre les messages qui contiennent la chaîne donnée (il suffit de fournir une partie du texte du message pour que le message entier soit supprimé). Utilisez cette option plusieurs fois pour supprimer plusieurs messages différents. La chaîne doit être une seule ligne, mais ce n'est pas un problème pour les messages de journal multilignes : les espaces dans la chaîne fournie correspondent à toute séquence de caractères d'espacement dans le message, y compris les nouvelles lignes. Si nécessaire, vous pouvez précéder la chaîne de “////”, auquel cas vous pouvez utiliser la mise en correspondance de motifs de style Lua (https://www.lua.org/pil/20.2.html). Notez que la chaîne est utilisée telle quelle : vous devrez peut-être l'entourer de guillemets ou échapper les caractères spéciaux tels que “\” au profit du shell, mais une telle mise en guillemets et échappement est inutile (et nuisible) dans le fichier de configuration.
--silence-file=NOMFICHIER OU GLOB FICHIER
Filtre les messages qui ont été générés lors du traitement du fichier donné. N'utilisez pas de chemins absolus ou relatifs, seulement des noms de fichiers. Les globes de fichiers simples, tels que “*.cls”, fonctionnent comme prévu. Si vous n'utilisez que des paquets que vous connaissez déjà, le silence de “*.sty” peut être une bonne idée (notez que cela ne supprime pas tous les messages de tous les paquets, seulement les messages générés lors du chargement des paquets). Utilisez cette option plusieurs fois pour supprimer les messages de plusieurs fichiers différents.
--semisilence-file=NOMFICHIER OU GLOB FICHIER
Exactement comme l'option précédente, mais non récursive. Cela signifie que les messages générés lors du traitement du fichier donné sont exclus, mais que les messages générés par un autre fichier qui a été ouvert par celui-ci ne le sont pas. Par exemple, si “chapters.tex” inclut (avec \input) les fichiers “chapter1.tex” et “chapter2.tex”, l'utilisation de “--silence-file=chapters.tex” empêchera l'affichage des messages générés par l'un des trois fichiers. Si, cependant, vous utilisez “--semisilence-file=chapters.tex”, les messages générés par chapters.tex seront supprimés, mais les messages générés par chapter1.tex ou chapter2.tex ne le seront pas.
--add-file=NOMFICHIER
Ajoute un fichier à la liste des fichiers qui sont examinés. Cela est utile si vous utilisez des fichiers de configuration ou des classes personnalisées qui ne sont pas dans le répertoire courant et que texlogsieve ne peut pas trouver. Si le nom du fichier contient des séparateurs de chemin (par exemple, « /usr/share/texmf/tex/latex/foo/bar.cls »), il sera considéré comme un chemin absolu ; sinon, il sera considéré comme relatif au répertoire courant.
--config=FICHIER DE CONFIGURATION
Spécifie un fichier de configuration contenant des options pour texlogsieve. Les options dans le fichier de configuration sont traitées avant celles données sur la ligne de commande. Le format du fichier de configuration est une liste d'options par ligne, comme sur la ligne de commande, mais sans les tirets doubles. Les lignes commençant par “#” sont ignorées. Les lignes vides sont également ignorées. Le chemin du fichier de configuration peut être absolu ou relatif au répertoire courant.
--help
Affiche un message d'aide et quitte.
--version
Affiche les informations de version et quitte.

EXEMPLES

Pour traiter un fichier journal existant et afficher les messages, utilisez :

$ texlogsieve myfile.log

Pour traiter la sortie d'une compilation LaTeX en temps réel :

$ latex -interaction nonstopmode myfile.tex | texlogsieve

Pour afficher uniquement le résumé des erreurs et avertissements :

$ texlogsieve --only-summary myfile.log

Pour filtrer les messages du paquet `foo` et les références non définies :

$ texlogsieve --silence-package=foo --no-ref-detail myfile.log

Pour afficher les messages colorisés, en désactivant le résumé des boîtes sous/pleines :

$ texlogsieve --color --no-box-detail myfile.log

OPTIONS

--add-[debug|info|warning|critical]-message=MESSAGE
Ajoute MESSAGE à la liste des messages connus du programme avec le niveau de gravité donné ; voir la Section MESSAGES NON RECONNUS ci-dessous pour plus d'informations à ce sujet. Comme --silence-string, ceux-ci doivent être sur une seule ligne ; contrairement à --silence-string, vous devez insérer \n explicitement pour indiquer les sauts de ligne (il s'agit littéralement d'un caractère antislash suivi de la lettre « n », pas d'un caractère de saut de ligne). Vous pouvez précéder la chaîne de « //// » pour utiliser la correspondance de motifs de style lua, mais l'incorporation de \n pour indiquer les sauts de ligne est inévitable. Utilisez ces options plusieurs fois pour ajouter de nombreux messages différents.
--set-to-level-[debug|info|warning|critical]=EXCERPT OF MESSAGE
Redéfinit le niveau de gravité des messages qui contiennent la chaîne fournie au niveau donné. Vérifiez l'explication de --silence-string, car cela fonctionne de manière similaire. Utilisez ces options plusieurs fois pour changer le niveau de gravité de nombreux messages différents.
-c CFGFILE, --config-file=CFGFILE
Lit les options du fichier de configuration donné en plus des fichiers de configuration par défaut (voir la section FICHIER DE CONFIGURATION).
-v, --verbose
Imprime la liste des fichiers de configuration lus et un bref résumé des options de configuration actives les plus importantes.
-h, --help
Affiche une description concise des options.
--version
Imprime la version du programme.

MESSAGES NON RECONNUS

texlogsieve gère automatiquement les messages tels que « Package blah Info:... » ou « LaTeX Warning:... ». Cependant, de nombreux messages ne suivent pas ce schéma. Pour fonctionner, texlogsieve doit connaître ces autres messages à l'avance.

Bien que texlogsieve reconnaisse un bon nombre de messages dès le départ, vous pouvez rencontrer un message généré par un package qu'il ne connaît pas (vous pouvez le vérifier en utilisant « -l unknown »). Si c'est le cas, vous pouvez utiliser les options --add-[debug|info|warning|critical]-message pour l'ajouter à la liste des messages connus du programme.

FICHIER DE CONFIGURATION

texlogsieve recherche automatiquement le fichier de configuration (facultatif) texlogsieverc dans $TEXINPUTS (c'est-à-dire qu'il recherche en utilisant Kpathsea). Dans la configuration par défaut, le répertoire courant est dans $TEXINPUTS, donc ajouter un fichier de configuration de ce nom au répertoire du projet suffit à le faire fonctionner. Les options du fichier de configuration sont exactement les mêmes que les options de ligne de commande longues décrites ci-dessus, mais sans les caractères « -- » qui les précèdent. Les lignes commençant par un signe « # » sont des commentaires. Un exemple de fichier de configuration :

no-page-delay
# no-page-delay active les expéditions, mais nous ne voulons pas de cela
no-shipouts
silence-string = Hyperreferences in rotated content will be misplaced
# pas besoin d'échapper le caractère « \" » (ou tout autre)
silence-string = Using \overbracket and \underbracket from `mathtools'
# faire taire une chaîne en utilisant la correspondance de motifs lua
silence-string = ////luaotfload | aux : font no %d+ %(.-%)
silence-files = *.sty

Si vous souhaitez également avoir un fichier de configuration générique pour tous vos projets (une bonne idée), placez-le dans $HOME/.texlogsieverc sur les systèmes de type Unix ; sous Windows, placez-le soit dans %LOCALAPPDATA%\texlogsieverc (C:\Users\<nomdutilisateur>\AppData\Local) soit dans %APPDATA%\texlogsieverc (C:\Documents and Settings\<nomutilisateur>\Application Data ou C:\Users\<nomutilisateur>\AppData\Roaming).

LIMITATIONS

texlogsieve n'essaie pas de faire quoi que ce soit d'intelligent concernant les messages d'erreur (mais il affiche un avertissement dans le résumé s'il en détecte un ; consultez la section CONSEILS de la documentation pdf à ce sujet) ; en cas d'erreur, vous voudrez probablement regarder directement le fichier journal de toute façon. Il ne peut pas non plus détecter si LaTeX s'arrête pour une entrée utilisateur, vous devriez donc vraiment exécuter LaTeX en nonstopmode lorsque texlogsieve lit à partir d'un tube.

Puisqu'il a besoin de savoir à quels messages s'attendre, texlogsieve est actuellement orienté vers LaTeX ; je n'ai aucune idée de son fonctionnement avec ConTeXt ou TeX simple. Néanmoins, ajouter la prise en charge pour eux ne devrait pas être trop difficile.
