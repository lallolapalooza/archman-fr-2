TEE(1P) Manuel du programmeur POSIX TEE(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

tee — dupliquer l'entrée standard

SYNTAXE

tee [-ai] [fichier...]

DESCRIPTION

L'utilitaire tee copie l'entrée standard vers la sortie standard, en créant une copie dans zéro ou plusieurs fichiers. L'utilitaire tee ne doit pas mettre en mémoire tampon la sortie.

Si l'option -a n'est pas spécifiée, les fichiers de sortie seront écraseés (voir Section 1.1.1.4, Lecture, Écriture et Création de Fichiers.

OPTIONS

L'utilitaire tee doit être conforme aux Définitions de base du volume POSIX.1‐2017, Section 12.2, Directives de Syntaxe d'Utilitaires.

Les options suivantes doivent être supportées :

-a
Ajoute la sortie aux fichiers.
-i
Ignore le signal SIGINT.

OPÉRANDES

Les opérandes suivants doivent être supportés :

fichier
Un chemin d'accès d'un fichier de sortie. Si un opérande fichier est '-', il fait référence à un fichier nommé -; les implémentations ne doivent pas le traiter comme signifiant la sortie standard. Le traitement d'au moins 13 opérandes fichier doit être supporté.

ENTRÉE STANDARD

L'entrée standard peut être de n'importe quel type.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes doivent affecter l'exécution de tee :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume des Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'Internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, écrase les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut, sauf si l'option -i a été spécifiée, SIGINT sera ignoré.

SORTIE STANDARD

La sortie standard sera une copie de l'entrée standard.

ERREUR STANDARD

L'erreur standard sera utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Si des opérandes fichier sont spécifiés, l'entrée standard sera copiée dans chaque fichier nommé.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes doivent être retournées :

 0
L'entrée standard a été copiée avec succès dans tous les fichiers de sortie.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Si une écriture dans l'un des opérandes fichier ouverts avec succès échoue, les écritures dans les autres opérandes fichier ouverts avec succès et dans la sortie standard se poursuivront, mais le statut de sortie sera non nul. Sinon, les actions par défaut spécifiées dans la Section 1.4, Défauts de Description des Utilitaires s'appliquent.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICANT

L'utilitaire tee est généralement utilisé dans un pipeline, pour faire une copie de la sortie d'un utilitaire.

L'opérande fichier est techniquement facultatif, mais tee n'est pas plus utile que cat lorsqu'aucun n'est spécifié.

EXEMPLES

Sauvegarder une forme intermédiaire non triée des données dans un pipeline :

... | tee unsorted | sort > sorted

JUSTIFICATION

L'exigence de non-mise en mémoire tampon signifie que tee n'est pas autorisé à utiliser les écritures entièrement mises en tampon ou en ligne de la norme ISO C. Cela ne signifie pas que tee doit faire des lectures d'1 octet suivies d'écritures d'1 octet.

Il convient de noter que les premières versions de BSD ignorent les options invalides et acceptent un seul '-' comme alternative à -i. Elles impriment également un message en cas d'impossibilité d'ouvrir un fichier :

"tee: cannot access %s\n", <chemin>

Les implémentations historiques ignorent les erreurs d'écriture. Ceci n'est explicitement pas autorisé par ce volume de POSIX.1‐2017.

Certaines implémentations historiques utilisent O_APPEND lors de la fourniture du mode d'ajout; d'autres utilisent la fonction lseek() pour se déplacer à la fin du fichier après l'ouverture du fichier sans O_APPEND. Ce volume de POSIX.1‐2017 exige une fonctionnalité équivalente à l'utilisation de O_APPEND ; voir Section 1.1.1.4, Lecture, Écriture et Création de Fichiers.
