Description Détaillée

Une interface d'entrée/sortie abstraite.

Attention

C'est du matériel avancé, du hardcore. Vous n'en avez pas besoin, sauf si vous savez vraiment ce que vous faites. La plupart des applications n'en auront pas besoin.

Historiquement, PhysicsFS fournissait un accès au système de fichiers physique et aux archives à l'intérieur de ce système de fichiers. Cependant, parfois, vous avez besoin de plus de puissance que cela. Peut-être avez-vous besoin de fournir une archive entièrement contenue dans la RAM, ou vous avez besoin de relier une autre API d'E/S de fichiers à PhysicsFS, ou vous avez besoin de traduire les bits (peut-être avez-vous un fichier .zip standard crypté et vous devez le décrypter à la volée pour l'archiveur zip incrédule).

Un PHYSFS_Io est l'interface que les Archiveurs utilisent pour obtenir des données d'archive. Historiquement, cela correspondait aux E/S de fichiers vers le système de fichiers physique, mais depuis PhysicsFS 2.1, les applications peuvent fournir leurs propres implémentations d'E/S au moment de l'exécution.

Cette interface n'est pas nécessairement un bon ajustement universel pour les E/S. Il y a quelques exigences à noter :

  • Elles ne font que des E/S bloquantes (du moins, pour l'instant).
  • Elles doivent pouvoir être dupliquées. Si vous avez un descripteur de fichier provenant de fopen(), vous devez être capable de créer un clone unique de celui-ci (afin que nous ayons deux descripteurs pour le même fichier qui puissent tous deux chercher/lire/etc sans se gêner).
  • Elles doivent connaître la taille de leur ensemble de données complet.
  • Elles doivent pouvoir chercher et rembobiner à la demande.

...en bref, vous n'allez probablement pas écrire une implémentation HTTP.

Sécurité des threads : les implémentations PHYSFS_Io ne sont pas garanties d'être sûres en elles-mêmes pour les threads. Sous le capot, là où PhysicsFS les utilise, la bibliothèque fournit ses propres verrous. Si vous prévoyez de les utiliser directement à partir de threads séparés, vous devriez soit utiliser des mutex pour les protéger, soit ne pas utiliser le même PHYSFS_Io à partir de deux threads en même temps.

void(* PHYSFS_Io::destroy) (struct PHYSFS_Io *io)

Nettoyer et désallouer l'instance d'E/S. Libérer les ressources associées, y compris (opaque) le cas échéant.

Cette fonction doit toujours réussir : à ce titre, elle retourne void. Le système peut appeler votre méthode flush() avant cela. Vous pouvez signaler un échec là si nécessaire. Cette méthode peut toujours être appelée si flush() échoue, auquel cas vous devrez abandonner les données non vidées et autres conditions d'échec, et nettoyer.

Une fois cette méthode appelée pour une instance donnée, le système supposera qu'il est dangereux de toucher à nouveau cette instance et écartera toute référence à celle-ci.

Paramètres

s L'instance d'E/S à détruire.

struct PHYSFS_Io *(* PHYSFS_Io::duplicate) (struct PHYSFS_Io *io)

Dupliquer cette instance d'E/S. Cela doit aboutir à une copie complète de ce PHYSFS_Io, qui puisse vivre complètement indépendamment. La copie doit être capable d'effectuer toutes ses opérations sans altérer l'original, y compris la destruction séparée de l'un ou l'autre objet (donc, par exemple : ils ne peuvent pas partager un descripteur de fichier ; chacun a besoin du sien).

Si vous ne pouvez pas dupliquer un descripteur, il est légal de retourner NULL, mais vous avez presque certainement besoin de cette fonctionnalité si vous voulez utiliser ce PHYSFS_Io pour sauvegarder une archive.

Paramètres

io L'instance d'E/S à dupliquer.

Retours

Une nouvelle valeur pour le champ (opaque) d'un flux, ou NULL en cas d'erreur.

int(* PHYSFS_Io::flush) (struct PHYSFS_Io *io)

Vider les ressources vers le support, ou où que ce soit. C'est l'occasion de signaler les échecs pour les écritures qui avaient prétendu avoir réussi plus tôt, mais qui avaient encore une chance d'échouer réellement. Cette méthode peut être NULL si le vidage n'est pas nécessaire.

Cette fonction peut être appelée avant destroy(), car elle peut signaler un échec et destroy() ne le peut pas. Elle peut également être appelée à d'autres moments.

Paramètres

io L'instance d'E/S à vider.

Retours

Zéro en cas d'erreur, non nul en cas de succès.

PHYSFS_sint64(* PHYSFS_Io::length) (struct PHYSFS_Io *io)

Déterminer la taille de l'ensemble de données de l'instance d'E/S. Retourner le nombre d'octets disponibles dans le fichier, ou -1 si vous ne parvenez pas à le déterminer. Un échec sera presque certainement fatal à une utilisation ultérieure de ce flux, vous ne pouvez donc pas laisser cela non implémenté.

Paramètres

io L'instance d'E/S à interroger.

Retours

Taille totale, en octets, de l'ensemble de données.

void* PHYSFS_Io::opaque

Données d'instance pour cette structure. Chaque instance a un pointeur associé qui peut être utilisé pour stocker tout ce qu'elle souhaite. Ce pointeur est par instance de flux, donc il changera probablement lors de l'appel à duplicate(). Il peut être désalloué pendant la méthode destroy().

PHYSFS_sint64(* PHYSFS_Io::read) (struct PHYSFS_Io *io, void *buf, PHYSFS_uint64 len)

Lire plus de données. Lire (len) octets depuis l'interface, à la position d'E/S actuelle, et les stocker dans (buffer). La position d'E/S actuelle devrait avancer du nombre d'octets lus avec succès.

Vous n'avez pas à implémenter cela ; définissez-le à NULL s'il n'est pas implémenté. Ceci ne sera utilisé que si le fichier est ouvert en lecture. S'il est défini à NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Paramètres

io L'instance d'E/S à lire.
buf Le tampon dans lequel stocker les données. Il doit être au moins de taille (len) octets et ne peut pas être NULL.
len Le nombre d'octets à lire depuis l'interface.

Retours

nombre d'octets lus du fichier, 0 en cas de fin de fichier, -1 en cas d'échec complet.

PHYSFS_sint64(* PHYSFS_Io::tell) (struct PHYSFS_Io *io)

Rapporter la position actuelle d'E/S. Retourne le nombre d'octets lus ou écrits depuis le début du fichier. Retourne -1 en cas d'erreur. Cette fonction ne doit jamais être NULL.

Paramètres

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Écrire plus de données. Écrit (len) octets du (buffer) dans l'interface, à la position d'E/S actuelle. La position d'E/S actuelle devrait avancer du nombre d'octets qui ont été effectivement écrits.

Vous n'avez pas à implémenter cela ; définissez-le à NULL s'il n'est pas implémenté. Ceci ne sera utilisé que si le fichier est ouvert en écriture. S'il est défini à NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Paramètres

io L'instance d'E/S à écrire.
buffer Le tampon contenant les données à écrire. Il ne peut pas être NULL.
len Le nombre d'octets à écrire dans l'interface.

Retours

nombre d'octets réellement écrits, -1 en cas d'échec complet.

PHYSFS_uint32 PHYSFS_Io::version

Informations sur la compatibilité binaire. Ceci doit être défini à zéro pour le moment. Les versions futures de cette structure incrémenteront ce champ, afin que nous sachions ce qu'une implémentation donnée prend en charge. Nous continuerons probablement à prendre en charge les anciennes versions à mesure que nous proposerons de nouvelles fonctionnalités, cependant.

PHYSFS_sint64(* PHYSFS_Io::write) (struct PHYSFS_Io *io, const void *buffer, PHYSFS_uint64 len)

Écrire plus de données. Écrire (len) octets depuis (buffer) vers l'interface à la position actuelle des E/S. La position actuelle des E/S doit avancer du nombre d'octets écrits avec succès.

Vous n'êtes pas obligé d'implémenter cela ; définissez-le sur NULL si non implémenté. Ceci ne sera utilisé que si le fichier est ouvert en écriture. Si défini sur NULL, une implémentation par défaut qui signale immédiatement un échec sera utilisée.

Vous êtes autorisé à mettre en tampon ; une écriture peut réussir ici et échouer plus tard lors de la purge. Notez que PHYSFS_setBuffer() peut fonctionner à un niveau supérieur à vos E/S, vous ne devriez donc généralement pas implémenter vos propres routines de mise en tampon.

Paramètres

io L'instance d'E/S vers laquelle écrire.
buffer Le tampon à partir duquel lire les données. Il doit avoir au moins (len) octets et ne peut pas être NULL.
len Le nombre d'octets à lire depuis (buffer).

Retourne

nombre d'octets écrits dans le fichier, -1 en cas d'échec complet.
