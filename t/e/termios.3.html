DESCRIPTION

Les fonctions termios décrivent une interface de terminal générale qui est fournie pour contrôler les ports de communication asynchrones.

La structure termios

Beaucoup des fonctions décrites ici ont un argument termios_p qui est un pointeur vers une structure termios. Cette structure contient au moins les membres suivants :


tcflag_t c_iflag;      /* modes d'entrée */
tcflag_t c_oflag;      /* modes de sortie */
tcflag_t c_cflag;      /* modes de contrôle */
tcflag_t c_lflag;      /* modes locaux */
cc_t     c_cc[NCCS];   /* caractères spéciaux */

Les valeurs qui peuvent être assignées à ces champs sont décrites ci-dessous. Dans le cas des quatre premiers champs de masque de bits, les définitions de certains des drapeaux associés qui peuvent être définis ne sont exposées que si une macro de test de fonctionnalité spécifique (voir feature_test_macros(7)) est définie, comme indiqué entre crochets ("[]").

Dans les descriptions ci-dessous, "non POSIX" signifie que la valeur n'est pas spécifiée dans POSIX.1-2001, et "XSI" signifie que la valeur est spécifiée dans POSIX.1-2001 dans le cadre de l'extension XSI.

Constantes de drapeau c_iflag :

IGNBRK
Ignorer la condition BREAK en entrée.
BRKINT
Si IGNBRK est défini, un BREAK est ignoré. S'il n'est pas défini mais que BRKINT est défini, alors un BREAK vide les files d'attente d'entrée et de sortie, et si le terminal est le terminal de contrôle d'un groupe de processus principal, il envoie un signal SIGINT à ce groupe de processus principal. Lorsque ni IGNBRK ni BRKINT ne sont définis, un BREAK se lit comme un octet nul ('\0'), sauf lorsque PARMRK est défini, auquel cas il se lit comme la séquence \377 \0 \0.
IGNPAR
Ignorer les erreurs de trame et les erreurs de parité.
PARMRK
Si ce bit est défini, les octets d'entrée avec des erreurs de parité ou de trame sont marqués lorsqu'ils sont transmis au programme. Ce bit n'est significatif que lorsque INPCK est défini et IGNPAR n'est pas défini. La manière dont les octets erronés sont marqués est avec deux octets précédents, \377 et \0. Ainsi, le programme lit en fait trois octets pour un octet erroné reçu du terminal. Si un octet valide a la valeur \377, et que ISTRIP (voir ci-dessous) n'est pas défini, le programme peut le confondre avec le préfixe qui marque une erreur de parité. Par conséquent, un octet valide \377 est transmis au programme sous forme de deux octets, \377 \377, dans ce cas.
Si ni IGNPAR ni PARMRK ne sont définis, lire un caractère avec une erreur de parité ou de trame comme \0.
INPCK
Activer la vérification de la parité d'entrée.
ISTRIP
Supprimer le huitième bit.
INLCR
Traduire NL en CR à l'entrée.
IGNCR
Ignorer le retour chariot à l'entrée.
ICRNL
Traduire le retour chariot en nouvelle ligne à l'entrée (sauf si IGNCR est défini).
IUCLC
(non POSIX) Mapper les caractères majuscules en minuscules à l'entrée.
IXON
Activer le contrôle de flux XON/XOFF en sortie.
IXANY
(XSI) La frappe de n'importe quel caractère redémarrera la sortie arrêtée. (Par défaut, seul le caractère START permet de redémarrer la sortie.)
IXOFF
Activer le contrôle de flux XON/XOFF en entrée.
IMAXBEL
(non POSIX) Sonner une cloche lorsque la file d'attente d'entrée est pleine. Linux n'implémente pas ce bit et se comporte comme s'il était toujours défini.
IUTF8 (depuis Linux 2.6.4)
(non POSIX) L'entrée est en UTF8 ; cela permet d'effacer correctement les caractères en mode "cooked".

Constantes de drapeau c_oflag :

OPOST
Activer le traitement de sortie défini par l'implémentation.
OLCUC
(non POSIX) Mapper les caractères minuscules en majuscules à la sortie.
ONLCR
(XSI) Mapper NL en CR-NL à la sortie.
OCRNL
Mapper CR en NL à la sortie.
ONOCR
Ne pas sortir de CR à la colonne 0.
ONLRET
Le caractère NL est supposé effectuer la fonction de retour chariot ; la colonne actuelle telle que vue par le noyau est mise à 0 après NL et CR.
OFILL
Envoyer des caractères de remplissage pour un délai, plutôt que d'utiliser un délai temporel.
OFDEL
Le caractère de remplissage est ASCII DEL (0177). S'il n'est pas défini, le caractère de remplissage est ASCII NUL ('\0'). (Non implémenté sous Linux.)
NLDLY
Masque de délai pour la nouvelle ligne. Les valeurs sont NL0 et NL1. [nécessite _BSD_SOURCE ou _SVID_SOURCE ou _XOPEN_SOURCE]
CRDLY
Masque de délai pour le retour chariot. Les valeurs sont CR0, CR1, CR2 ou CR3. [nécessite _BSD_SOURCE ou _SVID_SOURCE ou _XOPEN_SOURCE]
TABDLY
Masque de délai pour la tabulation horizontale. Les valeurs sont TAB0, TAB1, TAB2, TAB3 (ou XTABS, mais voir la section BUGS). Une valeur de TAB3, c'est-à-dire XTABS, développe les tabulations en espaces (avec des tabulations toutes les huit colonnes). [nécessite _BSD_SOURCE ou _SVID_SOURCE ou _XOPEN_SOURCE]
BSDLY
Masque de délai pour le retour arrière. Les valeurs sont BS0 ou BS1. (N'a jamais été implémenté.) [nécessite _BSD_SOURCE ou _SVID_SOURCE ou _XOPEN_SOURCE]
VTDLY
Masque de délai pour la tabulation verticale. Les valeurs sont VT0 ou VT1.
FFDLY
Masque de délai pour le saut de page. Les valeurs sont FF0 ou FF1.

c_cflag flag constants:

ISIG
Lorsque ce bit est défini, les signaux INTR, QUIT et SUSP sont générés.
ICANON
Activer le mode canonique (mode "cooked"). Sinon, le mode est en mode non canonique (mode "raw").
ECHOE
(not in POSIX) Si ICANON est défini, l'écho des caractères de suppression (erase) sera fourni par une séquence de caractères effaçant visuellement le caractère ou le mot.
ECHO, ECHOE, ECHOK, ECHONL, ECHOPRINT, NOFLSH
Les constantes de drapeau c_lflag sont :
ECHO
Activer l'écho des caractères d'entrée.
ECHONL
Si ECHO est défini, l'écho de la nouvelle ligne (NL) est activé. Ceci est fait séparément de l'écho des autres caractères. Ainsi, si ECHO est défini et ECHONL est défini, un caractère NL est affiché.
NOFLSH
Désactiver le vidage du tampon d'entrée/sortie lorsque les signaux INTR, QUIT ou SUSP sont générés.
TOSTOP
(not in POSIX) Envoyer un signal SIGSTOP au processus s'exécutant dans le terminal de contrôle, lorsque ce processus tente d'écrire sur le terminal.
ZCTLECHO
(not in POSIX) Écho des caractères de contrôle. Si ce bit est défini, les caractères qui ont une valeur inférieure à 0x20 (sauf le caractère NUL et le caractère DELETE) sont échosés précédés d'un caret (^), et le caractère qui suit est le caractère correspondant à la valeur (par exemple, un caractère ASCII 0x07 (BEL) sera échosé comme ^G).

La structure c_cc contient les valeurs des caractères spéciaux.

Les actions optionnelles

L'argument optional_actions de tcsetattr() spécifie quand les modifications doivent prendre effet. Les valeurs possibles sont TCSANOW, TCSADRAIN, ou TCSAFLUSH.

TCSANOW
Les changements prennent effet immédiatement.
TCSADRAIN
Les changements prennent effet après que toutes les sorties écrites sur fd aient été transmises. Utile pour changer les attributs sans perdre de données en sortie.
TCSAFLUSH
Les changements prennent effet après que toutes les sorties écrites sur fd aient été transmises, et après que toutes les entrées non lues sur fd aient été ignorées. Utile pour changer les attributs sans perdre de données en entrée ou en sortie.

Les fonctions cfgetospeed() et cfgetispeed() retournent les débits en bauds de sortie et d'entrée, respectivement. Ces débits sont des valeurs de type speed_t.

Les fonctions cfsetospeed() et cfsetispeed() définissent les débits en bauds de sortie et d'entrée, respectivement. Les valeurs possibles pour speed sont définies dans <asm/termbits.h> et sont des constantes comme B50, B75, B110, B134, B150, B200, B300, B600, B1200, B1800, B2400, B4800, B9600, B19200, B38400, B57600, B115200, B230400, B460800, B500000, B576000, B921600, B1000000, B1152000, B1500000, B2000000, B2500000, B3000000, B3500000, B4000000.

La fonction cfsetspeed() est un alias pour cfsetospeed(). Elle est fournie pour la compatibilité avec certaines anciennes interfaces.

La fonction cfmakeraw() met le terminal en mode "raw" (non canonique) sans écho, en désactivant toutes les interprétations de caractères spéciaux et de contrôle de flux.

La fonction tcsendbreak() envoie une condition de "break" sur le port série associé à fd. Si duration est 0, la fonction envoie une pause d'au moins 0,25 seconde. Si duration est différent de 0, la durée de la pause est égale à duration dixièmes de seconde. L'envoi d'une condition de break est défini par la norme POSIX comme l'envoi d'une séquence d'octets nuls pendant une durée spécifiée. La manière dont cela est implémenté peut varier.

La fonction tcdrain() attend que toutes les sorties écrites sur le descripteur de fichier fd aient été transmises. Elle est utile pour garantir que les données sont effectivement envoyées avant de continuer.

La fonction tcflush() vide les files d'attente spécifiées dans le descripteur de fichier fd. La valeur de queue_selector peut être TCIFLUSH (vide la file d'attente d'entrée), TCOFLUSH (vide la file d'attente de sortie), ou TCIOFLUSH (vide les deux files d'attente).

La fonction tcflow() contrôle le flux de données sur le descripteur de fichier fd. La valeur de action peut être TCOOFF (arrête la sortie), TCOON (recommence la sortie), TCIOFF (envoie une séquence XOFF pour arrêter l'entrée), ou TCION (envoie une séquence XON pour recommencer l'entrée).

VALEUR DE RETOUR

En cas de succès, toutes ces fonctions retournent 0. En cas d'erreur, elles retournent -1 et définissent errno pour indiquer l'erreur.

ERREURS

EBADF
Le descripteur de fichier fd n'est pas valide.
EINTR
Une interruption de signal s'est produite pendant l'opération.
EINVAL
Une valeur invalide a été fournie pour un argument (par exemple, optional_actions ou queue_selector).
ENOTTY
Le descripteur de fichier fd n'est pas associé à un terminal.
ENXIO
Le périphérique associé à fd ne peut pas être accédé.
EIO
Une erreur d'entrée/sortie s'est produite.

CONFORMITÉ

Les fonctions termios, tcgetattr, tcsetattr, tcsendbreak, tcdrain, tcflush et tcflow sont conformes à POSIX.1-2001. Les fonctions cfmakeraw, cfgetispeed, cfgetospeed, cfsetispeed, cfsetospeed et cfsetspeed sont conformes à POSIX.1-2001 avec les extensions BSD.

BOGUES

Sous Linux, le drapeau XTABS dans c_oflag est équivalent à TAB3. La définition de TAB3 sans l'extension XSI n'est pas prise en charge. La valeur TAB3 doit être utilisée.

VOIR AUSSI

DESCRIPTION

The termios structure contains the terminal c_cc array, which holds values for the terminal special characters. The following special characters can be set:

VINTR
(intr, 003, ETX, Ctrl-C) Interrupt character (INTR). An attempt is made to send a SIGINT signal to every process in the foreground process group associated with the terminal.
VQUIT
(quit, 034, FS, Ctrl-\) Quit character (QUIT). An attempt is made to send a SIGQUIT signal to every process in the foreground process group associated with the terminal.
VERASE
(erase, 0177, DEL) Erase character (ERASE). The equivalent of the erase character is deleted from the current line, before the erase character is deleted. (Not all terminals support erase character)
VKILL
(kill, 027, ETB, Ctrl-U) Kill character (KILL). The erase character is deleted from the current line, before the kill character is deleted. (Not all terminals support kill character)
VEOF
(eof, 004, EOT, Ctrl-D) End-of-file character (EOF). A read from the terminal will return value 0, indicating end-of-file.
VTIME
Timeout in deciseconds for noncanonical read (TIME).
VMIN
Minimum number of bytes for noncanonical read (MIN).
VSWTC
(not in POSIX) EOF character (SWTCH). A character for switching to virtual consoles (obsolete).
VSTART
(start, 021, DC1, Ctrl-Q) Start character (START). Restarts the output of an input stopped by the START/STOP characters.
VSTOP
(stop, 023, DC3, Ctrl-S) Stop character (STOP). Stops the output of an input.
VREPRINT
(not in POSIX; 022, SYN, Ctrl-R) Reprint character (REPRINT). If ICANON and IEXTEN are set, the current line is reprinted.
VDISCARD
(not in POSIX; 032, SUB, Ctrl-V) Discard character (DISCARD). All currently-read input is discarded.
VSUSP
(not in POSIX; 032, FS, Ctrl-Z) Suspend character (SUSP). A signal SIGTSTP is sent to the foreground process group.
VWERASE
(not in POSIX; 027, ETB, Ctrl-W) Word erase (WERASE). If ICANON and IEXTEN are set, the equivalent of the erase character is deleted from the current line, before the word erase character is deleted.
VLNEXT
(not in POSIX; 026, SYN, Ctrl-V) Literal next character (LNEXT). The next character typed is not processed by the line discipline driver, but is passed into the read queue exactly as it is typed.
VEOL
(not in POSIX) Alternate End-of-file character (EOL).
VDSUSP
(not in POSIX; 030, EOT, Ctrl-^ ) Delayed suspend character (DSUSP). A signal SIGTSTP is sent to the foreground process group.
VREPRINT
(not in POSIX; 022, SYN, Ctrl-R) Reprint character (REPRINT). Recognized when ICANON and IEXTEN are set, and then not passed as input.
VDISCARD
(not in POSIX; 032, SUB, Ctrl-V) Discard character (DISCARD). Recognized when ICANON and IEXTEN are set, and then not passed as input.
VWERASE
(not in POSIX; 027, ETB, Ctrl-W) Word erase (WERASE). Recognized when ICANON and IEXTEN are set, and then not passed as input.
VLNEXT
(not in POSIX; 026, SYN, Ctrl-V) Literal next character (LNEXT). Recognized when ICANON and IEXTEN are set, and then not passed as input.
VEOL2
(not in POSIX) Alternate End-of-line character (EOL2).

An individual terminal special character can be disabled by setting the value of the corresponding c_cc element to _POSIX_VDISABLE.

The above symbolic subscript values are all different, except that VTIME and VMIN may have the same value as VEOL, VEOL2, or VEOF. In noncanonical mode, the special character meaning is replaced by the timeout meaning. For an explanation of VMIN and VTIME, see the description of noncanonical mode below.

Retrieving and changing terminal settings

tcgetattr() gets the parameters associated with the object referred to by fd, and stores them in the termios structure referenced by termios_p. This function may be invoked from a background process; however, the terminal attributes may be subsequently changed by a foreground process.

tcsetattr() sets the parameters associated with the terminal (unless support is required from the underlying hardware that is not available) from the termios structure referenced by termios_p. optional_actions specifies when the changes take effect:

TCSANOW
the change occurs immediately.
TCSADRAIN
the change occurs after all output written to fd has been transmitted. This option should be used when changing parameters that affect output.
TCSAFLUSH
the change occurs after all output written to the object referred to by fd has been transmitted, and all input that has been received but not read will be discarded before the change is made.

Canonical and noncanonical mode

The setting of the ICANON canon flag in c_lflag determines whether the terminal is operating in canonical mode (ICANON set) or noncanonical mode (ICANON unset). By default, ICANON is set.

In canonical mode:

•
Input is made available line by line. An input line is available when one of the line delimiters is typed (NL, EOL, EOL2; or EOF at the start of line). Except in the case of EOF, the line delimiter is included in the buffer returned by read(2).
•
Line editing is enabled (ERASE, KILL; and if the IEXTEN flag is set: WERASE, REPRINT, LNEXT). A read(2) returns at most one line of input; if the read(2) requested fewer bytes than are available in the current line of input, then only as many bytes as requested are read, and the remaining characters will be available for a future read(2).
•
The maximum line length is 4096 chars (including the terminating newline character); lines longer than 4096 chars are truncated. After 4095 characters, input processing (e.g., ISIG and ECHO processing) continues, but any input data after 4095 characters up to (but not including) any terminating newline is discarded. This ensures that the terminal can always receive more input until at least one line can be read.

In noncanonical mode input is available immediately (without the user having to type a line-delimiter character), no input processing is performed, and line editing is disabled. The read buffer will only accept 4095 chars; this provides the necessary space for a newline char if the input mode is switched to canonical. The settings of MIN (c_cc[VMIN]) and TIME (c_cc[VTIME]) determine the circumstances in which a read(2) completes; there are four distinct cases:

MIN == 0, TIME == 0 (polling read)
If data is available, read(2) returns immediately, with the lesser of the number of bytes available, or the number of bytes requested. If no data is available, read(2) returns 0.
MIN > 0, TIME == 0 (blocking read)
read(2) blocks until MIN bytes are available, and returns up to the number of bytes requested.
MIN == 0, TIME > 0 (read with timeout)
TIME specifies the limit for a timer in tenths of a second. The timer is started when read(2) is called. read(2) returns either when at least one byte of data is available, or when the timer expires. If the timer expires without any input becoming available, read(2) returns 0. If data is already available at the time of the call to read(2), the call behaves as though the data was received immediately after the call.
MIN > 0, TIME > 0 (read with interbyte timeout)
TIME specifies the limit for a timer in tenths of a second. Once an initial byte of input becomes available, the timer is restarted after each further byte is received. read(2) returns when any of the following conditions is met:
•
MIN bytes have been received.
•
The interbyte timer expires.
•
The number of bytes requested by read(2) has been received. (POSIX does not specify this termination condition, and on some other implementations read(2) does not return in this case.)
Because the timer is started only after the initial byte becomes available, at least one byte will be read. If data is already available at the time of the call to read(2), the call behaves as though the data was received immediately after the call.

POSIX does not specify whether the setting of the O_NONBLOCK file status flag takes precedence over the MIN and TIME settings. If O_NONBLOCK is set, a read(2) in noncanonical mode may return immediately, regardless of the setting of MIN or TIME. Furthermore, if no data is available, POSIX permits a read(2) in noncanonical mode to return either 0, or -1 with errno set to EAGAIN.

Raw mode

cfmakeraw() sets the terminal to something like the "raw" mode of the old Version 7 terminal driver: input is available character by character, echoing is disabled, and all special processing of terminal input and output characters is disabled. The terminal attributes are set as follows:


termios_p->c_iflag &= ~(IGNBRK | BRKINT | PARMRK | ISTRIP
                | INLCR | IGNCR | ICRNL | IXON);
termios_p->c_oflag &= ~OPOST;
termios_p->c_lflag &= ~(ECHO | ECHONL | ICANON | ISIG | IEXTEN);
termios_p->c_cflag &= ~(CSIZE | PARENB);
termios_p->c_cflag |= CS8;

Line control

tcsendbreak() transmits a continuous stream of zero-valued bits for a specific duration, if the terminal is using asynchronous serial data transmission. If duration is zero, it transmits zero-valued bits for at least 0.25 seconds, and not more than 0.5 seconds. If duration is not zero, it sends zero-valued bits for some implementation-defined length of time.

If the terminal is not using asynchronous serial data transmission, tcsendbreak() returns without taking any action.

tcdrain() waits until all output written to the object referred to by fd has been transmitted.

tcflush() discards data written to the object referred to by fd but not transmitted, or data received but not read, depending on the value of queue_selector:

TCIFLUSH
flushes data received but not read.
TCOFLUSH
flushes data written but not transmitted.
TCIOFLUSH
flushes both data received but not read, and data written but not transmitted.

tcflow() suspends transmission or reception of data on the object referred to by fd, depending on the value of action:

TCOOFF
suspends output.
TCOON
restarts suspended output.
TCIOFF
transmits a STOP character, which stops the terminal device from transmitting data to the system.
TCION
transmits a START character, which starts the terminal device transmitting data to the system.

The default on open of a terminal file is that neither its input nor its output is suspended.

Line speed

The baud rate functions are provided for getting and setting the values of the input and output baud rates in the termios structure. The new values do not take effect until tcsetattr() is successfully called.

Setting the speed to B0 instructs the modem to "hang up". The actual bit rate corresponding to B38400 may be altered with setserial(8).

0

Par conséquent, lors de multiples modifications, il peut être nécessaire de suivre cet appel avec un autre appel à tcgetattr() pour vérifier que toutes les modifications ont été effectuées avec succès.

NOTES

UNIX V7 et plusieurs systèmes ultérieurs ont une liste de débits en bauds où après les valeurs B0 à B9600 on trouve les deux constantes EXTA, EXTB ("External A" et "External B"). De nombreux systèmes étendent la liste avec des débits beaucoup plus élevés.

L'effet d'une duration non nulle avec tcsendbreak() varie. SunOS spécifie une interruption de duration * N secondes, où N est au moins 0.25 et pas plus de 0.5. Linux, AIX, DU, Tru64 envoient une interruption de duration millisecondes. FreeBSD et NetBSD et HP-UX et MacOS ignorent la valeur de duration. Sous Solaris et UnixWare, tcsendbreak() avec une duration non nulle se comporte comme tcdrain().

BOGUES

Sur l'architecture Alpha avant Linux 4.16 (et glibc avant glibc 2.28), la valeur XTABS était différente de TAB3 et elle était ignorée par le code de discipline de ligne N_TTY du pilote de terminal en conséquence (car elle ne faisait pas partie du masque TABDLY).
