NOM

term - conventions pour la dénomination des types de terminaux

DESCRIPTION

La variable d'environnement TERM doit normalement contenir le nom du type du terminal, de la console ou du périphérique d'affichage que vous utilisez. Cette information est essentielle pour tous les programmes orientés écran, y compris votre éditeur et votre programme de courrier.

Une valeur par défaut pour TERM sera définie par ligne, soit par /etc/inittab (par exemple, les Unix de type System-V), soit par /etc/ttys (les Unix BSD). Cela suffira presque toujours pour les consoles de stations de travail et de micro-ordinateurs.

Si vous utilisez une ligne commutée, le type de périphérique qui y est connecté peut varier. Les anciens systèmes Unix pré-configuraient un type de terminal très basique comme “dumb” ou “dialup” sur les lignes commutées. Les systèmes plus récents peuvent pré-configurer “vt100”, reflétant la prévalence des terminaux compatibles DEC VT100 et des émulateurs d'ordinateurs personnels.

Les clients Telnet modernes transmettent votre variable d'environnement TERM du côté local vers le côté distant. Il peut y avoir des problèmes si l'entrée terminfo ou termcap distante pour votre type n'est pas compatible avec la vôtre, mais cette situation est rare et peut presque toujours être évitée en exportant explicitement “vt100” (en supposant que vous utilisez effectivement une console, un terminal ou un émulateur de terminal superset VT100).

Dans tous les cas, vous êtes libre de remplacer le réglage système de TERM selon vos goûts dans votre profil shell. L'utilitaire tset(1) peut être utile ; vous pouvez lui donner un ensemble de règles pour déduire ou demander un type de terminal en fonction du périphérique tty et du débit en bauds.

Définir votre propre valeur TERM peut également être utile si vous avez créé une entrée personnalisée incorporant des options (telles que la sonnerie visuelle ou la vidéo inversée) que vous souhaitez substituer au type par défaut du système pour votre ligne.

Les descriptions de types de terminaux sont stockées sous forme de fichiers de données de capacités sous /usr/share/terminfo. Pour parcourir une liste de tous les noms de terminaux reconnus par le système, exécutez :


toe | more

depuis votre shell. Ces fichiers de capacités sont dans un format binaire optimisé pour la vitesse de récupération (contrairement à l'ancien format textuel termcap qu'ils remplacent) ; pour examiner une entrée, vous devez utiliser la commande infocmp(1M). Appelez-la comme suit :


infocmp nom_entrée

où nom_entrée est le nom du type que vous souhaitez examiner (et le nom de son fichier de capacités dans le sous-répertoire de /usr/share/terminfo nommé d'après sa première lettre). Cette commande décharge un fichier de capacités au format texte décrit par terminfo(5).

La première ligne d'une description terminfo(5) donne les noms sous lesquels terminfo connaît un terminal, séparés par des caractères “|” (barre verticale) avec le dernier champ de nom terminé par une virgule. Le premier champ de nom est le nom primaire du type, et c'est celui à utiliser lors de la définition de TERM. Le dernier champ de nom (s'il est distinct du premier) est en fait une description du type de terminal (il peut contenir des espaces ; les autres doivent être des mots uniques). Les champs de nom entre le premier et le dernier (s'ils sont présents) sont des alias pour le terminal, généralement des noms historiques conservés pour des raisons de compatibilité.

Il existe certaines conventions sur la manière de choisir les noms primaires de terminaux qui aident à les maintenir informatifs et uniques. Voici un guide étape par étape pour nommer les terminaux qui explique également comment les analyser :

Premièrement, choisissez un nom racine. La racine consistera en une lettre minuscule suivie de jusqu'à sept lettres minuscules ou chiffres. Vous devez éviter d'utiliser des caractères de ponctuation dans les noms racines, car ils sont utilisés et interprétés comme des noms de fichiers et des métacaractères de shell (tels que !, $, *, ?, etc.) incorporés dans ceux-ci peuvent provoquer un comportement étrange et inutile. La barre oblique (/), ou tout autre caractère pouvant être interprété par le système de fichiers de quelqu'un (\\, $, [, ]), est particulièrement dangereuse (terminfo est indépendant de la plateforme, et choisir des noms avec des caractères spéciaux pourrait un jour rendre la vie difficile aux utilisateurs d'un futur port). Le caractère point (.) est relativement sûr tant qu'il n'y en a pas plus d'un par nom racine ; certains noms terminfo historiques l'utilisent.

Le nom racine d'un type de console de terminal ou de station de travail devrait presque toujours commencer par un préfixe de vendeur (tel que hp pour Hewlett-Packard, wy pour Wyse, ou att pour les terminaux AT&T), ou un nom commun de la ligne de terminal (vt pour la série VT de terminaux de DEC, ou sun pour les consoles de stations de travail Sun Microsystems, ou regent pour la série ADDS Regent. Vous pouvez lister l'arborescence terminfo pour voir quels préfixes sont déjà couramment utilisés. Le préfixe du nom racine doit être suivi le cas échéant d'un numéro de modèle ; ainsi vt100, hp2621, wy50.

Le nom racine d'un type de console PC-Unix doit être le nom du système d'exploitation, c'est-à-dire linux, bsdos, freebsd, netbsd. Il ne doit pas être console ou tout autre nom générique qui pourrait prêter à confusion dans un environnement multiplateforme ! Si un numéro de modèle suit, il doit indiquer soit le niveau de version du système d'exploitation, soit le niveau de version du pilote de console.

Le nom racine d'un émulateur de terminal (à condition qu'il ne corresponde pas à l'un des types standard ANSI ou vt100) doit être le nom du programme ou une abréviation facilement reconnaissable de celui-ci (c'est-à-dire versaterm, ctrm).

Après le nom racine, vous pouvez ajouter un nombre raisonnable de suffixes de fonctionnalités séparés par des traits d'union.

2p
Possède deux pages de mémoire. De même 4p, 8p, etc.
mc
Cookie magique. Certains terminaux (notamment les anciens Wyse) ne peuvent supporter qu'un seul attribut sans perte de cookie magique. Leur entrée de base est généralement associée à une autre qui a ce suffixe et utilise des cookies magiques pour supporter plusieurs attributs.
-am
Activez la marge automatique (retour à la ligne de la marge droite).
-m
Mode mono - supprime le support des couleurs.
-na
Pas de touches fléchées - termcap ignore les touches fléchées qui sont effectivement présentes sur le terminal, de sorte que l'utilisateur peut utiliser les touches fléchées localement.
-nam
Pas de marge automatique - supprime la capacité am.
-nl
Pas d'étiquettes - supprime les étiquettes logicielles.
-nsl
Pas de ligne de statut - supprime la ligne de statut.
-pp
Possède un port d'imprimante qui est utilisé.
-rv
Terminal en mode vidéo inversé (noir sur blanc).
-s
Active la ligne de statut.
-vb
Utilise la sonnerie visible (flash) au lieu de biper.
-w
Large ; le terminal est en mode 132 colonnes.

Conventionnellement, si votre type de terminal est une variante destinée à spécifier une hauteur de ligne, ce suffixe doit venir en premier. Ainsi, pour un terminal hypothétique FuBarCo modèle 2317 en mode 30 lignes avec vidéo inversée, la meilleure forme serait fubar-30-rv (plutôt que, par exemple, “fubar-rv-30”).

Les types de terminaux qui sont écrits non pas comme des entrées autonomes, mais plutôt comme des composants à brancher sur d'autres entrées via des capacités use, se distinguent par l'utilisation de signes plus intégrés plutôt que de traits d'union.

Les commandes qui utilisent un type de terminal pour contrôler l'affichage acceptent souvent une option -T qui accepte un argument de nom de terminal. Ces programmes doivent se rabattre sur la variable d'environnement TERM lorsqu'aucune option -T n'est spécifiée.

FICHIERS

/usr/share/terminfo
base de données compilée des descriptions de terminaux
/etc/inittab
initialisation des lignes tty (Unix de type AT&T)
/etc/ttys
initialisation des lignes tty (Unix de type BSD)

PORTABILITÉ

Pour une compatibilité maximale avec les anciens Unix System V, les noms et alias doivent être uniques dans les 14 premiers caractères.

VOIR AUSSI
