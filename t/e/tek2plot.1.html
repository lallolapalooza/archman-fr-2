NOM

tek2plot - traduire les fichiers Tektronix vers d'autres formats graphiques

SYNTAXE

tek2plot [ options ] [ fichiers ]

DESCRIPTION

tek2plot traduit les fichiers graphiques Tektronix vers d'autres formats, ou les affiche sur un écran X Window System. Le format de sortie est spécifié avec l'option -T. Les formats de sortie possibles sont les mêmes que ceux pris en charge par graph(1), plot(1), pic2plot(1) et plotfont(1). Si un fichier de sortie est produit, il est écrit sur la sortie standard.

Les options et les noms de fichiers peuvent être entremêlés sur la ligne de commande, mais les options sont traitées avant la lecture des noms de fichiers. Si -- est rencontré, il est interprété comme la fin des options. Si aucun nom de fichier n'est spécifié, ou si le nom de fichier - est rencontré, l'entrée standard est lue.

OPTIONS

Options générales

-T type

--output-format type
Sélectionne type comme format de sortie. Il peut s'agir de "X", "png", "pnm", "gif", "svg", "ai", "ps", "cgm", "fig", "pcl", "hpgl", "regis", "tek", ou "meta" (par défaut). Ceux-ci correspondent respectivement au système X Window, au format PNG (Portable Network Graphics), au format anymap portable (PBM/PGM/PPM), à un format pseudo-GIF qui n'utilise pas l'encodage LZW, au nouveau format SVG (Scalable Vector Graphics) basé sur XML, au format utilisé par Adobe Illustrator, Postscript ou Encapsulated Postscript (EPS) qui peut être édité avec idraw(1), au format CGM (par défaut, conforme au profil WebCGM), au format utilisé par l'éditeur de dessin xfig(1), au langage d'imprimante PCL 5 de Hewlett-Packard, au langage graphique HP-GL de Hewlett-Packard, au format graphique ReGIS qui peut être affiché par l'émulateur de terminal dxterm(1) ou par un terminal VT330 ou VT340, au format Tektronix lui-même, et au format méta-fichier indépendant du périphérique GNU. Sauf si type est "X", un fichier de sortie est produit et écrit sur la sortie standard.
Omettre l'option -T équivaut à spécifier -T meta. Le format méta-fichier GNU peut être traduit vers d'autres formats avec plot(1).
-p n

--page-number n
Produire uniquement la page numéro n, dans le fichier Tektronix ou la séquence de fichiers Tektronix en cours de traduction. n doit être un entier non négatif, car un fichier Tektronix peut se composer d'une ou plusieurs pages, numérotées à partir de zéro.
Le comportement par défaut si l'option -p n'est pas utilisée est de produire toutes les pages non vides successivement. Par exemple, tek2plot -T X affiche chaque page Tektronix dans sa propre fenêtre X. Si l'option -T png, -T pnm, -T gif, -T ai ou -T fig est utilisée, le comportement par défaut est de produire uniquement la première page Tektronix non vide, car les fichiers dans ces formats de sortie ne contiennent qu'une seule page de graphiques.
La plupart des fichiers Tektronix se composent soit d'une page (page n°0) soit de deux pages (une page n°0 vide et la page n°1). Les fichiers Tektronix produits par les utilitaires de tracé GNU (par exemple, par graph -T tek) sont normalement du second type.
-F nom

--font-name nom
Utiliser la police nom pour le rendu des polices Tektronix natives, si elle est disponible. La police par défaut est "Courier" sauf pour tek2plot -T png, tek2plot -T pnm, tek2plot -T gif, tek2plot -T hpgl, tek2plot -T regis et tek2plot -T tek, pour lesquelles c'est "HersheySerif". Une liste des polices disponibles peut être obtenue avec l'option --help-fonts (voir ci-dessous). Si une police autre que la famille Courier est utilisée, l'option --position-chars (voir ci-dessous) devrait probablement être spécifiée.
L'option -F n'est utile que si vous avez un fichier Tektronix qui dessine du texte en utilisant les polices Tektronix natives. Les fichiers Tektronix produits par les utilitaires de tracé GNU (par exemple, par graph -T tek) n'utilisent pas les polices Tektronix natives : ils utilisent des polices vectorielles Hershey à la place.
-W line_width

--line-width line_width
Définir la largeur des lignes, en fraction de la largeur de l'écran, à line_width. Une valeur négative signifie qu'une valeur par défaut doit être utilisée. Cette valeur dépend du format. L'interprétation d'une largeur de ligne nulle dépend également du format (dans certains formats de sortie, une ligne de largeur nulle est la ligne la plus fine qui puisse être dessinée ; dans d'autres, une ligne de largeur nulle est invisible).
--bg-color nom
Définir la couleur utilisée pour l'arrière-plan à nom. Ceci n'est pertinent que pour tek2plot -T X, tek2plot -T png, tek2plot -T pnm, tek2plot -T gif, tek2plot -T svg, tek2plot -T cgm et tek2plot -T regis. Un nom non reconnu définit la couleur sur la valeur par défaut, qui est "white". La variable d'environnement BG_COLOR peut également être utilisée pour spécifier la couleur de l'arrière-plan. Si l'option -T svg ou -T cgm est utilisée, un fichier de sortie sans arrière-plan peut être produit en définissant la couleur de l'arrière-plan sur "none".
Si l'option -T png ou -T gif est utilisée, un fichier PNG transparent ou un pseudo-GIF transparent, respectivement, peut être produit en définissant la variable d'environnement TRANSPARENT_COLOR sur le nom de la couleur d'arrière-plan.
--bitmap-size bitmap_size
Définir la taille de l'affichage graphique dans lequel le tracé sera dessiné, en pixels, à bitmap_size. La valeur par défaut est "570x570". Ceci n'est pertinent que pour plot -T X, plot -T png, plot -T pnm et plot -T gif. Si vous choisissez une taille de fenêtre rectangulaire (non carrée), les polices du tracé seront mises à l'échelle de manière anisotrope, c'est-à-dire par des facteurs différents dans les directions horizontale et verticale. Pour plot -T X, cela nécessite un affichage X11R6. Toute police qui ne peut pas être mise à l'échelle de cette manière sera remplacée par une police évolutive par défaut, telle que la police vectorielle "HersheySerif".
La variable d'environnement BITMAPSIZE peut également être utilisée pour spécifier la taille de la fenêtre. Pour des raisons de compatibilité ascendante, la ressource X Xplot.geometry peut être utilisée à la place.
--emulate-color option
Si option est yes, remplace chaque couleur de la sortie par une nuance de gris appropriée. Ceci est rarement utile, sauf lors de l'utilisation de ` tek2plot -T pcl pour préparer la sortie pour un périphérique PCL 5. (De nombreux périphériques PCL 5 monochromes, tels que les LaserJet monochromes, font un mauvais travail d'émulation des couleurs par eux-mêmes.) Vous pouvez également demander l'émulation des couleurs en définissant la variable d'environnement EMULATE_COLOR sur "yes".
--max-line-length max_line_length
Définir le nombre maximum de points qu'une ligne polygonale peut contenir, avant d'être vidée, à max_line_length. Si ce vidage se produit, la ligne polygonale sera divisée en deux ou plusieurs sous-lignes, bien que la division ne devrait pas être perceptible. La valeur par défaut de max_line_length est 500.
La raison pour laquelle les lignes polygonales longues sont divisées est que certains périphériques d'affichage (par exemple, les anciennes imprimantes Postscript et les traceurs HP-GL) ont des tailles de tampon limitées. La variable d'environnement MAX_LINE_LENGTH

OPTIONS

--bitmap-size sizexsize
Set the size of the bitmap graphics display to sizexsize pixels. This option is only relevant to tek2plot -T X, tek2plot -T png, and tek2plot -T gif. The default is "512x512". The environment variable BITMAPSIZE can also be used to specify the bitmap size.
--bg-color color
Set the background color to color. The default is "white". The environment variable BG_COLOR can also be used to specify the background color.
--emulate-color
Emulate color output on a monochrome display. This option is relevant only to tek2plot -T X. The environment variable EMULATE_COLOR can also be used to specify this.
--max-line-length length
Set the maximum length of a line in the output to length units. This option is only relevant to tek2plot -T fig. The default is "6.0". The environment variable MAX_LINE_LENGTH can also be used to specify the maximum line length.
--page-size pagesize
Set the size of the page on which the plot will be positioned. This is relevant only to tek2plot -T svg, tek2plot -T ai, tek2plot -T ps, tek2plot -T cgm, tek2plot -T fig, tek2plot -T pcl, and tek2plot -T hpgl. The default is "letter", which means an 8.5 inch by 11 inch page. Any ISO page size in the range "a0"..."a4" or ANSI page size in the range "a"..."e" may be specified ("letter" is an alias for "a" and "tabloid" is an alias for "b"). "legal" and "ledger" are recognized page sizes also. The environment variable PAGESIZE can equally well be used to specify the page size.
The graphics display in which the plot is drawn will be a square region that would occupy nearly the full width of the specified page. An alternative size for the graphics display can be specified. For example, the page size could be specified as "letter,xsize=4in,ysize=6in", or "a4,xsize=5.0cm,ysize=100mm". For all of the above except tek2plot -T hpgl, the graphics display will, by default, be centered on the page. For all of the above except tek2plot -T svg and tek2plot -T cgm, the graphics display may be repositioned manually, by specifying the location of its lower left corner, relative to the lower left corner of the page. For example, the page size could be specified as "letter,xorigin=2in,yorigin=3in", or "a4,xorigin=0.5cm,yorigin=0.5cm". It is also possible to specify an offset vector. For example, the page size could be specified as "letter,xoffset=1in", or "letter,xoffset=1in,yoffset=1.2in", or "a4,yoffset=-1cm". In SVG format and WebCGM format it is possible to specify the size of the graphics display, but not its position.
--pen-color name
Set the pen color to be name. An unrecognized name sets the pen color to the default, which is "black".
--position-chars
Position the characters in each text string individually. If the text font is not a member of the Courier family, and especially if it is not a fixed-width font, this option is recommended. It will improve the appearance of text strings, at the price of making it difficult to edit the output file with xfig(1), idraw(1), or Illustrator.
--rotation angle
Rotate the graphics display by angle degrees. Recognized values are "0", "90", "180", and "270". "no" and "yes" are equivalent to "0" and "90", respectively. The environment variable ROTATION can also be used to specify a rotation angle.
--use-tek-fonts
Use the bitmap fonts that were used on the original Tektronix 4010/4014 terminal. This option is relevant only to tek2plot -T X. The four relevant bitmap fonts are distributed with most versions of the GNU plotting utilities, under the names "tekfont0"..."tekfont3". They can easily be installed on any modern X Window System display. For this option to work properly, you must also select a window size of 1024x1024 pixels, either by using the --bitmap-size 1024x1024 option or by setting the value of the Xplot.geometry resource. This is because bitmap fonts, unlike the scalable fonts that tek2plot normally uses, cannot be rescaled.
This option is useful only if you have a file in Tektronix format that draws text using native Tektronix fonts. Tektronix files produced by the GNU plotting utilities (e.g., by graph -T tek) do not use native Tektronix fonts: they use Hershey vector fonts instead.

Options pour la sortie de métafichier

L'option suivante n'est pertinente que si l'option -T est omise ou si -T meta est utilisée. Dans ce cas, tek2plot génère un métafichier graphique GNU, qui doit être traduit vers d'autres formats avec plot(1).

-O

--portable-output
Génère la version portable (lisible par l'homme) du format de métafichier GNU, plutôt qu'une version binaire (par défaut). Le format de la version binaire dépend de la machine.

Options d'information

--help
Affiche une liste des options de ligne de commande et quitte.
--help-fonts
Affiche un tableau des polices disponibles et quitte. Le tableau dépendra du format de sortie spécifié avec l'option -T. tek2plot -T X, tek2plot -T svg, tek2plot -T ai, tek2plot -T ps, tek2plot -T cgm, et tek2plot -T fig prennent tous en charge les 35 polices Postscript standard. tek2plot -T svg, tek2plot -T pcl, et tek2plot -T hpgl prennent en charge les 45 polices PCL 5 standard, et ces deux dernières prennent en charge un certain nombre de polices vectorielles Hewlett-Packard. Les sept prennent en charge un ensemble de 22 polices vectorielles Hershey, tout comme tek2plot -T png, tek2plot -T pnm, tek2plot -T gif, tek2plot -T regis, et tek2plot -T tek. tek2plot sans option -T prend en principe en charge toutes ces polices, car sa sortie doit être traduite vers d'autres formats avec plot(1).
L'utilitaire plotfont(1) peut être utilisé pour obtenir une carte de caractères de toute police prise en charge.
--list-fonts
Similaire à --help-fonts, mais liste les polices dans une seule colonne pour faciliter le passage à d'autres programmes. Si aucun format de sortie n'est spécifié avec l'option -T, l'ensemble complet des polices prises en charge est listé.
--version
Affiche le numéro de version de tek2plot et du paquet d'utilitaires de traçage, puis quitte.

ENVIRONNEMENT

Les variables d'environnement BITMAPSIZE, PAGESIZE, BG_COLOR, EMULATE_COLOR, MAX_LINE_LENGTH et ROTATION servent de sauvegardes pour les options --bitmap-size, --page-size, --bg-color, --emulate-color, --max-line-length, et --rotation, respectivement. Les autres variables d'environnement sont spécifiques aux formats de sortie individuels.

tek2plot -T X, qui ouvre une fenêtre sur un écran X Window System et y dessine des graphiques, vérifie la variable d'environnement DISPLAY. Sa valeur détermine l'affichage qui sera utilisé.

tek2plot -T png et tek2plot -T gif, qui produisent une sortie au format PNG et pseudo-GIF respectivement, sont affectés par la variable d'environnement INTERLACE. Si sa valeur est "yes", la sortie sera entrelacée. De plus, si la variable d'environnement TRANSPARENT_COLOR est définie sur le nom d'une couleur, cette couleur sera traitée comme transparente dans la sortie.

tek2plot -T pnm, qui produit une sortie au format portable anymap (PBM/PGM/PPM), est affecté par la variable d'environnement PNM_PORTABLE. Si sa valeur est "yes", la sortie sera dans un format lisible par l'homme plutôt qu'en binaire (par défaut).

tek2plot -T cgm, qui produit une sortie au format CGM (Computer Graphics Metafile), est affecté par les variables d'environnement CGM_MAX_VERSION et CGM_ENCODING. Par défaut, il produit une version codée en binaire du format CGM version 3. Pour la compatibilité descendante, le numéro de version peut être réduit en définissant CGM_MAX_VERSION sur "2" ou "1". Indépendamment de la version, le fichier CGM de sortie utilisera le codage texte clair lisible par l'homme si CGM_ENCODING est défini sur "clear_text". Cependant, seuls les fichiers CGM codés en binaire sont conformes au profil WebCGM.

tek2plot -T pcl, qui produit une sortie PCL 5 pour les imprimantes et traceurs Hewlett-Packard, est affecté par la variable d'environnement PCL_ASSIGN_COLORS. Elle doit être définie sur "yes" lors de la production de sortie PCL 5 pour une imprimante couleur ou un autre périphérique couleur. Cela garantira une reproduction des couleurs précise en donnant au périphérique de sortie une liberté totale dans l'attribution des couleurs, en interne, à ses "stylos logiques". Si elle est "no", l'appareil utilisera un ensemble fixe de stylos colorés et émule d'autres couleurs par tramage. La valeur par défaut est "no" car les appareils PCL 5 monochromes, beaucoup plus courants que les appareils couleur, doivent utiliser le tramage pour émuler la couleur.

tek2plot -T hpgl, qui produit une sortie en langage Hewlett-Packard Graphics Language, est affecté par plusieurs variables d'environnement. La plus importante est HPGL_VERSION, qui peut être définie sur "1", "1.5", ou "2" (par défaut). "1" signifie que la sortie doit être générique HP-GL, "1.5" signifie que la sortie doit convenir au traceur graphique HP7550A et aux traceurs de dessin HP758x, HP7595A et HP7596A (HP-GL avec quelques extensions HP-GL/2), et "2" signifie que la sortie doit être le HP-GL/2 moderne. Si la version est "1" ou "1.5", les seules polices disponibles seront des polices vectorielles, et toutes les lignes seront tracées avec une largeur par défaut (l'option -W ne fonctionnera pas).

La position de l'affichage graphique tek2plot -T hpgl sur la page peut être tournée de 90 degrés dans le sens inverse des aiguilles d'une montre en définissant la variable d'environnement HPGL_ROTATE sur "yes". Ce n'est pas la même chose que la rotation obtenue avec l'option --rotation, car elle tourne à la fois l'affichage graphique et repositionne son coin inférieur gauche vers un autre coin de la page. Outre "no" et "yes", les valeurs reconnues pour HPGL_ROTATE sont "0", "90", "180", et "270". "no" et "yes" sont équivalents à "0" et "90", respectivement. "180" et "270" sont suppo

rté uniquement si HPGL_VERSION est "2" (par défaut).

Par défaut, tek2plot -T hpgl dessinera avec un ensemble fixe de stylos. Les stylos présents peuvent être spécifiés en définissant la variable d'environnement HPGL_PENS . Si HPGL_VERSION est "1", la valeur par défaut de HPGL_PENS est "1=black" ; si HPGL_VERSION est "1.5" ou "2", la valeur par défaut de HPGL_PENS est "1=black:2=red:3=green:4=yellow:5=blue:6=magenta:7=cyan". Le format devrait être auto-explicatif. En définissant HPGL_PENS , vous pouvez spécifier une couleur pour n'importe quel stylo dans la plage #1...#31. Toutes les couleurs reconnues par le système X Window peuvent être utilisées. Le stylo #1 doit toujours être présent, bien qu'il n'ait pas besoin d'être noir. Tout autre stylo dans la plage #1...#31 peut être omis.

Si HPGL_VERSION est "2", alors tek2plot -T hpgl sera également affecté par la variable d'environnement HPGL_ASSIGN_COLORS. Si sa valeur est "yes", alors tek2plot -T hpgl ne sera pas limité à la palette spécifiée dans HPGL_PENS: il attribuera des couleurs aux "stylos logiques" dans la plage #1...#31, au besoin. La valeur par défaut est "no" car, à part des imprimantes LaserJet couleur et des traceurs DesignJet, peu de périphériques HP-GL/2 permettent l'attribution de couleurs aux stylos logiques.

Le dessin de lignes blanches visibles n'est pris en charge que si HPGL_VERSION est "2" et que la variable d'environnement HPGL_OPAQUE_MODE est "yes" (par défaut). Si sa valeur est "no", les lignes blanches (s'il y en a), normalement dessinées avec le stylo #0, ne seront pas dessinées. Cette fonctionnalité est destinée à s'adapter aux anciens périphériques HP-GL/2. Les traceurs HP-GL/2, par exemple, ne prennent pas en charge l'utilisation du stylo #0 pour dessiner des lignes blanches visibles. Certains anciens périphériques HP-GL/2 peuvent, en fait, mal fonctionner s'ils sont invités à dessiner des objets opaques.
