TERMINOLOGY(1) Manuel de terminology TERMINOLOGY(1)

NOM

Terminology - Émulateur de terminal écrit avec les EFL (Enlightenment Foundation Libraries).

SYNTAXE

terminology [options]

DESCRIPTION

Ceci est un émulateur de terminal EFL avec quelques extras. Il possède de nombreuses fonctionnalités, y compris le support de terminaux divisés, le support d'onglets, des icônes de prévisualisation pour les fichiers, et ainsi de suite...

OPTIONS

-e, --exec <cmnd>
Spécifie la commande à exécuter. Par défaut, utilise $SHELL (ou le shell de passe ou /bin/sh). Lorsque utilisé avec -S/--split, chaque argument est utilisé comme commande pour une division, en omettant les arguments supplémentaires. Avec 3 divisions, une verticale, une commande à droite, une division horizontale à gauche avec seulement une commande en bas, les arguments suivants doivent être utilisés : --split v-h-- -e commande1 $SHELL commande2
-d=RÉPERTOIRE_COURANT, --current-directory=RÉPERTOIRE_COURANT
Changer de répertoire pour l'exécution de la commande du terminal. Type : STR.
-t=THÈME, --theme=THÈME
Utiliser le thème edje nommé ou le chemin vers le fichier de thème. Type : STR.
-b=ARRIÈRE-PLAN, --background=ARRIÈRE-PLAN
Utiliser le fichier nommé comme fond d'écran pour terminology. Type : STR.
-g=GÉOMÉTRIE, --geometry=GÉOMÉTRIE
Géométrie du terminal à utiliser (par ex. 80x24 ou 80x24+50+20 etc.). Type : STR.
-n=NOM, --name=NOM
Définir le nom de la fenêtre. Type : STR.
-r=RÔLE, --role=RÔLE
Définir le rôle de la fenêtre. Type : STR.
-S=vh-, --split=vh-
Terminology peut démarrer avec des divisions ouvertes comme décrit ci-dessous. Les arguments sont une chaîne avec les caractères suivants :
-S v divise le terminal verticalement
-S h divise horizontalement
- définit un espace réservé pour un shell ou une commande lorsqu'il est utilisé avec
--exec/-e
Exemples :
______
| | |
$ terminology -S v |__|__|


______
|_____|
$ terminology -S h |_____|


______
|__| |
$ terminology -S vh |__|__|


______
| |__|
$ terminology -S v-h |__|__|


______
$ terminology -S vh--h |__|__|
hv--v |__|__|
Type : STR.

-T=TITRE, --title=TITRE
Définir le titre de la fenêtre. Type : STR.
-i=NOM_ICÔNE, --icon-name=NOM_ICÔNE
Définir le nom de l'icône. Type : STR.
-f=POLICE, --font=POLICE
Définir la police (NOM/TAILLE pour les polices vectorielles, NOM pour les polices bitmap). Type : STR.
-l, --login
Exécuter le shell en tant que shell de connexion. Type : BOOL.
-m=MUTE_VIDÉO, --video-mute=MUTE_VIDÉO
Définir le mode muet pour la lecture vidéo. Type : BOOL.
-c=CLIGNOTEMENT_CURSEUR, --cursor-blink=CLIGNOTEMENT_CURSEUR
Définir le mode de clignotement du curseur. Type : BOOL.
-G=SONNETTE_VISUELLE, --visual-bell=SONNETTE_VISUELLE
Définir le mode de sonnette visuelle. Type : BOOL.
-F, --fullscreen
Passer en mode plein écran dès le départ.
-I, --iconic
Passer en état icône dès le départ.
-B, --borderless
Devenir une fenêtre gérée sans bordures.
-O, --override
Devenir une fenêtre avec override-redirect.
-M, --maximized
Devenir maximisé dès le départ.
-W, --nowm
Terminology est exécuté sans gestionnaire de fenêtres (wm).
-H, --hold
Ne pas quitter lorsque le processus de commande se termine.
-s, --single
Forcer une seule instance si l'exécution multi-instance est activée.
-2, --256color
Définir TERM sur xterm-256color au lieu de xterm.
--active-links=ACTIVER-LIENS
Si les liens doivent être mis en surbrillance. Type : BOOL.
--no-wizard
Ne pas afficher l'assistant au démarrage. Type : BOOL.
--scale=ÉCHELLE
Facteur d'échelle à utiliser sur l'interface utilisateur. Type : DOUBLE.
--colorscheme=SCHÉMA_COULEURS
Utiliser le schéma de couleurs nommé. Type : STR.
-V, --version
Afficher la version du programme.
-C, --copyright
Afficher le copyright.
-L, --license
Afficher la licence.
-h, --help
Afficher ce message.

SÉQUENCES D'ÉCHAPPEMENT ÉTENDUES POUR TERMINOLOGY :

[\033][}][COMMANDE][\000]
c'est-à-dire :
1. Caractère ESC (\033 ou 0x1b)
2. Caractère }
3. Séquence de caractères UTF8 autres que nul (\000 ou 0x00).
4. Caractère \000 (octet nul ou 0x00 pour indiquer la fin de la séquence). Exemple :
echo -n '\033}Bonjour le monde\000'

Commandes :

Toutes les valeurs entre crochets [] doivent être remplacées par un contenu (nombres, chaînes de caractères, chemins, URLs, etc.). Exemple :

aa[CHEMIN-DU-FICHIER] devrait devenir quelque chose comme :
aa/tmp/fichier.png ou aa[vrai/faux] devrait devenir quelque chose comme :
aavrai ou
aafaux

---

pn[CHEMIN-COMPLET-OU-URL]
affiche immédiatement le média/URL donné en popup.

pq[CHEMIN-COMPLET-OU-URL]
met en file d'attente un popup pour le fichier média/URL donné.

bt[CHEMIN-COMPLET-OU-URL]
définit temporairement le média d'arrière-plan du terminal (fichier/URL).

bp[CHEMIN-COMPLET-OU-URL]
définit de manière permanente le média d'arrière-plan du terminal (fichier/URL).

at[on/vrai/oui/off/faux/non]
définit temporairement l'état alpha du terminal sur activé ou désactivé.

ap[on/vrai/oui/off/faux/non]
définit de manière permanente l'état alpha du terminal sur activé ou désactivé.

qs
interroge la grille et la taille de la police. stdin recevra :
L;H;TW;TH
où L est la largeur de la grille du terminal en caractères
où H est la hauteur de la grille du terminal en caractères
où TW est la largeur d'une cellule de caractère en pixels
où TH est la hauteur d'une cellule de caractère en pixels

is[LW;H;CHEMIN-COMPLET-OU-URL]
insère un média ÉTIRÉ (où l'image s'étirera pour remplir la zone de
cellule) et définit la zone de cellule attendue comme étant L
caractères de large et H caractères de haut, avec l'image/média/URL.
où C est le caractère de remplacement à identifier dans le texte ultérieur
où L est la largeur en cellules de caractères (jusqu'à 511).
où H est la hauteur en cellules de caractères (jusqu'à 511).


notez que cette séquence d'échappement seule n'a aucun effet. Elle indique une intention future d'insérer du média dans le terminal. Le terminal attendra une grille de LxH "caractères de remplacement" par la suite, chaque séquence de ces caractères de remplacement étant précédée d'une commande d'échappement ib et se terminant par une commande d'échappement ie.


le CHEMIN-COMPLET-OU-URL pour toutes les commandes i (is,
ic, if, it) peut être de la forme :


/chemin/complet/vers/fichier.png


OU


/chemin/complet/vers/lien0/chemin/complet/vers/fichier.png


où un caractère de nouvelle ligne sépare une URI pour un lien et
un chemin complet vers un fichier à afficher dans la région. Le lien
est l'URI de destination lorsque l'utilisateur peut cliquer sur l'image
média donnée.


Exemple :


printf("\033}is#5;3;%s\033}ib#####\033}ie\0\033}ib#####\033}ie\0\033}ib#####\033}ie\0, "/tmp/icon.png");


notez que # est le caractère de remplacement, et plus tard les caractères # s'ils sont à l'intérieur des séquences de début/fin, seront remplacés par le média indiqué dans la séquence d'insertion de média.

ic[CW;H;CHEMIN-COMPLET-OU-URL]
insère un média CENTRÉ (centré dans la zone de cellule). Sinon, les
paramètres sont identiques à la commande is, mais
conserve le rapport d'aspect et est complété par un espace vide.

if[CW;H;CHEMIN-COMPLET-OU-URL]
insère un média REMPLI (remplit la zone de cellule). Sinon, les paramètres
sont identiques à la commande is, mais assure que toute la
zone est remplie comme un arrière-plan même si le média dépasse les
limites de la cellule et est centré.

EXTENDED ESCAPES FOR TERMINOLOGY:

Terminology utilise des séquences d'échappement étendues pour diverses fonctionnalités. Ces séquences commencent par une combinaison d'échappement de terminologie (généralement ESC + ] ou ESC + }), suivie d'une commande spécifique.

i[CW;H;FULL-PATH-OR-URL]

insère un média THUMB (zone de cellule miniature). Sinon, les paramètres
sont identiques à la commande is, mais utilise la génération de miniatures
pour créer une version rapide à charger mais de faible résolution
(en cache) du média.
i[CW;H;LINK\nFULL-PATH-OR-URL]

insère un média THUMB avec un lien (zone de cellule miniature). Sinon, les paramètres
sont identiques à la commande is, mais utilise la génération de miniatures pour
créer une version rapide à charger mais de faible résolution (en cache) du média.
LINK est un chemin (ou une url) à ouvrir _lorsque_ la miniature est cliquée par l'utilisateur.
ij[CW;H;FULL-PATH\nGROUP][\n][cmd1][\r\n][cmd2]...

insère un objet EDJE avec le chemin de fichier donné et le nom de groupe donné.
La liste de commandes (et le délimiteur d'espace \n avant la liste)
est facultative, mais est exécutée/analysée avant l'affichage de l'objet réel
pour faire des choses comme initialiser son état initial. Voir la commande `iC`
pour plus de détails sur la liste de commandes.

Soyez conscient qu'une fois que vous avez un objet avec un ID de canal attribué,
il peut renvoyer des signaux et des messages via des échappements sur stdin. Ces
échappements suivront le format d'échappement étendu de terminology
(ESC + } ...  00), et le contenu sera l'un des suivants :

;CHID\ndrag\nPART NAME\nVAL1\nVAL2
;CHID\ndrag,start\nPART NAME\nVAL1\nVAL2
;CHID\ndrag,stop\nPART NAME\nVAL1\nVAL2
;CHID\ndrag,step\nPART NAME\nVAL1\nVAL2
;CHID\drag,set\nPART NAME\nVAL1\nVAL2
signal;CHID\nSIGNAL STRING\nSOURCE STRING
message;CHID\nOPCODE ID\nstring\nSTRING1
message;CHID\nOPCODE ID\nint\nINT1
message;CHID\nOPCODE ID\nfloat\nFLOAT1
message;CHID\nOPCODE ID\nstring_set\nSTRING1\nSTRING2\nSTRING3...
message;CHID\nOPCODE ID\nint_set\nINT1\nINT2\nINT3...
message;CHID\nOPCODE ID\nfloat_set\nFLOAT1\nFLOAT2\nFLOAT3...
message;CHID\nOPCODE ID\nstring_int\nSTRING1\nINT1
message;CHID\nOPCODE ID\nstring_float\nSTRING1\nFLOAT1
message;CHID\nOPCODE ID\nstring_int_set\nSTRING1\nINT1\nINT2\nINT3...
message;CHID\nOPCODE ID\nstring_float_set\nSTRING1\nFLOAT1\nFLOAT2\nFLOAT3...
iC[CHID]\n[cmd1][\r\n][cmd2][\r\n][cmd3]...

envoie une COMMANDE (cmd1, cmd2, cmd3 etc.) à un ID de canal nommé existant
CHID. cela peut être une liste de 1 ou plusieurs chaînes de commande,
chaque chaîne étant délimitée par une séquence continue de 1 ou plusieurs \r
et/ou \n caractères. par exemple "\n", "\r", "\r\n",
"\n\r", "\n\r\n\n\n", etc.

Les commandes comprises sont :

text\nPART NAME\nTEXT STRING
définit le texte de "PART NAME" à la chaîne "TEXT STRING"

emit\nSIGNAL STRING\nSOURCE STRING
émet le signal "SIGNAL STRING" "SOURCE STRING"

drag\nPART NAME\n[value|size|step|page]\nVAL1\nVAL2
manipule le draggable du nom "PART NAME" et définit soit
les propriétés "value", "size", "step" ou "page"
à "VAL1" et "VAL2" pour x et y, où
VAL1 et VAL2 sont des valeurs flottantes

chid\nCHANNEL ID
définit l'ID de canal d'un objet edje donné (uniquement valide dans les commandes
de configuration pour l'objet edje inline) à "CHANNEL ID" afin qu'il puisse être
adressé plus tard.

message\nOPCODE ID\n[string|int|float|string_set|int_set|...
float_set|string|int|string_float|string_int_set|...
string_float_set]\n[message data]
envoie un message avec l'opcode (entier) ID "OPCODE ID" de l'un des
types donnés pris en charge ("string", "int", "float",
etc.) et ensuite avec les "message data" donnés à la fin.
Le format de message data dépend du type de message :
string: STRING1
int: INT1
float: FLOAT1
string_set: STRING1\nSTRING2\nSTRING3...
int_set: INT1\nINT2\nINT3...
float_set: FLOAT1\nFLOAT2\nFLOAT3...
string_int: STRING1\nINT1
string_float: STRING1\nFLOAT1
string_int_set: STRING1\nINT1\nINT2\nINT3...
string_float_set: STRING1\nFLOAT1\nFLOAT2\nFLOAT3...
ib

démarre l'exécution de la séquence de remplacement de média.
ie

termine l'exécution de la séquence de remplacement de média.
fr[PATH/FILE]

démarre l'envoi d'un fichier nommé PATH / FILE
fs[SIZE_BYTES]

définit la taille en octets d'un envoi de fichier démarré avec l'échappement fr ci-dessus
fd[CHECKSUM DATA]

bloc de données pour le transfert de fichier actuel avec checksum sous forme de
chaîne décimale qui est la somme de chaque octet lorsqu'il est traité comme un
char non signé par octet. le checksum est un entier signé de 32 bits.
le checksum est la somme des données après échappement. 4 bits à la fois par octet de données,
encodés avec les bits de poids fort dans un octet puis les bits de poids faible, avec les bits encodés
comme une valeur de 4 bits étant 0x40 + la valeur de 4 bits
par octet. (@ == 0x0, A == 0x1, B == 0x2, ... N == 0xe, O == 0xf).
donc pour reconstruire un octet, ce sera (((bytes[0] - 0x40) & 0xf) << 4) |
((bytes[1] - 0x40) & 0xf) par paire d'octets dans le bloc de données.
fx

quitte le mode d'envoi de fichier (normalement à la fin du fichier ou lorsqu'il est
terminé)
