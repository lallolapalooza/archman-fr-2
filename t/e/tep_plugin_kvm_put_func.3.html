tep_plugin_kvm_put_func(3)

Paquet: libtraceevent

Licences: GPL-2.0-only, LGPL-2.1-only

LIBTRACEEVENT(3) Manuel libtraceevent LIBTRACEEVENT(3)

NOM

tep_plugin_kvm_get_func, tep_plugin_kvm_put_func - Ajouter le nom de la fonction pour le pointeur d'instruction du plugin kvm

SYNTAXE

#include <event-parse.h>
const char *tep_plugin_kvm_get_func(struct tep_event *event,
                                    struct tep_record *record,
                                    unsigned long long *paddr);
void tep_plugin_kvm_put_func(const char *func);

DESCRIPTION

Les fonctions tep_plugin_kvm_get_func() et tep_plugin_kvm_put_func() ne doivent pas être appelées par une application, mais plutôt définies par une application.

Certains événements (comme kvm_exit et kvm_entry) contiennent le pointeur d'instruction indiquant où, dans l'invité, le contexte est passé de l'invité à l'hôte. Comme l'hôte ne connaît que le pointeur d'instruction et n'a pas d'informations sur la fonction de l'invité à laquelle appartient ce pointeur d'instruction, il ne peut qu'afficher l'adresse.

Cependant, l'application peut disposer d'informations supplémentaires sur l'invité, savoir où se trouvait l'invité au moment de la sortie et même connaître le nom de la fonction associée à cette adresse.

Le plugin KVM pour libtraceevent est appelé lors de ces événements, puis il appelle tep_plugin_kvm_get_func() pour voir si cette fonction peut résoudre l'adresse du pointeur d'instruction en un nom de fonction réel. Si le retour n'est pas NULL, il affichera la fonction dans la sortie de cet événement.

Ces fonctions sont actuellement définies comme des fonctions faibles au sein du plugin, afin de ne pas nécessiter leur définition ailleurs. Pour qu'une application remplace la fonction faible, elle devra définir la fonction dans un fichier qui est compilé avec -rdynamic. Cela indiquera à l'éditeur de liens dynamique d'examiner ce fichier objet et d'utiliser les noms de fonctions pour résoudre les fonctions faibles dans d'autres objets partagés (dans ce cas, l'objet partagé du plugin KVM).

Si l'application définit tep_plugin_kvm_get_func(), elle doit utiliser le prototype ci-dessus. L'argument event contiendra l'événement KVM qui possède le champ du pointeur d'instruction. L'argument record sera l'instance de cet événement. La fonction de l'application n'a pas besoin d'utiliser ces paramètres, mais ils peuvent être utiles pour trouver le nom de la fonction correspondant à l'adresse. L'argument paddr est un pointeur vers une valeur 64 bits (où seuls 32 bits peuvent être utilisés sur les machines 32 bits). Cette valeur est le pointeur d'instruction à rechercher. Si l'application connaît également l'adresse de début de la fonction, elle peut définir paddr à cette adresse, et le plugin KVM ajoutera également un "+offset" au nom de la fonction, où l'offset est la valeur originale dans paddr moins la valeur dans paddr au moment de l'appel. Enfin, l'application doit retourner le nom de la fonction sous forme de chaîne terminée par un caractère nul si elle en trouve une.

Si la chaîne retournée par tep_plugin_kvm_get_func() a été allouée, le plugin KVM appellera tep_plugin_kvm_put_func() lorsqu'il aura terminé, en passant la valeur retournée par tep_plugin_kvm_get_func() comme argument func. Cela permet à l'application de la libérer si nécessaire.

VALEUR DE RETOUR

La fonction tep_plugin_kvm_get_func() ne doit pas être appelée par l'application, mais plutôt définie par l'application. Elle doit retourner une chaîne terminée par un caractère nul représentant la fonction pour le pointeur d'instruction donné, passé par référence dans paddr. Elle peut ensuite mettre à jour facultativement paddr avec une valeur correspondant au début de la fonction. La chaîne retournée peut être libérée par la fonction tep_plugin_kvm_put_func() que l'application doit définir pour nettoyer la chaîne.

L'exemple ci-dessous doit être compilé avec le drapeau -rdynamic afin que l'éditeur de liens dynamique puisse résoudre les fonctions tep_plugin_kvm_get_func() et tep_plugin_kvm_put_func().

Lorsqu'il est exécuté sur un fichier trace.dat produit par trace-cmd(1) enregistrant les événements kvm_exit et kvm_entry sur un invité, et que le fichier /proc/kallsyms de l'invité est passé comme deuxième paramètre, la sortie produite ressemblera à ceci :

CPU 0/KVM-20407 83156.177626 [000] kvm_exit     reason APIC_ACCESS rip 0xffffffffb0056ee2 exit native_apic_mem_write+0x2 info 10b0 0
CPU 0/KVM-20407 83156.177632 [000] kvm_entry     vcpu 0 rip 0xffffffffb0056ee8 enter native_apic_mem_write+0x8

Mais sans ces callbacks, cela ressemblerait à ceci :

CPU 0/KVM-20407 83156.177626 [000] kvm_exit     reason APIC_ACCESS rip 0xffffffffb0056ee2 info 10b0 0
CPU 0/KVM-20407 83156.177632 [000] kvm_entry     vcpu 0 rip 0xffffffffb0056ee8

EXEMPLE

#include <stdio.h>
#include <stdlib.h>
#include <event-parse.h>
#include <trace-cmd.h>
#include <sys/stat.h>
static struct tep_handle *tep;
const char *tep_plugin_kvm_get_func(struct tep_event *event, struct tep_record *record,
                                    unsigned long long *paddr)
{
        const char *func;
        char *event_func;
        char *ename;
        func = tep_find_function(tep, *paddr);
        if (!func)
                return NULL;
        if (strcmp(event->name, "kvm_exit") == 0)
                ename = "exit";
        else
                ename = "enter";
        /*
         * Normalement, renvoyer directement func est suffisant et alors
         * tep_plugin_kvm_put_func() ne serait pas requis. Mais cet exemple
         * montre comment gérer l'allocation de la chaîne retournée.
         */
        event_func = malloc(strlen(ename) + strlen(func) + 2);
        if (!event_func)
                return NULL;
        sprintf(event_func, "%s %s", ename, func);
        *paddr = tep_find_function_address(tep, *paddr);
        return event_func;
}
void tep_plugin_kvm_put_func(const char *func)
{
        char *f = (char *)func;
        free(f);
}
static int show_event(struct tracecmd_input *handle, struct tep_event *event,
                      struct tep_record *record, int cpu, void *data)
{
        static struct trace_seq seq;
        tep = data;
        if (!seq.buffer)
                trace_seq_init(&seq);
        trace_seq_reset(&seq);
        tep_print_event(tracecmd_get_tep(handle), &seq, record,
                        "%s-%d\t%6.1000d [%03d] %s\t%s\n",
                        TEP_PRINT_COMM, TEP_PRINT_PID,
                        TEP_PRINT_TIME, TEP_PRINT_CPU,
                        TEP_PRINT_NAME, TEP_PRINT_INFO);
        trace_seq_terminate(&seq);
        trace_seq_do_printf(&seq);
        return 0;
}
int main(int argc, char **argv)
{
        struct tracecmd_input *handle;
        struct tep_handle *guest_tep;
        struct stat st;
        FILE *fp;
        char *buf;
        if (argc < 3) {
                printf("usage: trace.dat guest_kallsyms_file\n");
                exit(-1);
        }
        handle = tracecmd_open(argv[1], 0);
        if (!handle) {
                perror(argv[1]);
                exit(-1);
        }
        /* Seulement pour l'analyse de kallsyms */
        guest_tep = tep_alloc();
        if (!guest_tep)
                exit(-1);
        if (stat(argv[2], &st) < 0) {
                perror(argv[2]);
                exit(-1);
        }
        buf = malloc(st.st_size + 1);
        if (!buf)
                exit(-1);
        fp = fopen(argv[2], "r");
        if (!fp) {
                perror(argv[2]);
                exit(-1);
        }
        if (fread(buf, st.st_size, 1, fp) < 0) {
                perror(argv[2]);
                exit(-1);
        }
        buf[st.st_size] = '\0';
        if (tep_parse_kallsyms(guest_tep, buf) < 0) {
                printf("Échec de l'analyse de %s\n", argv[2]);
                exit(-1);
        }
        free(buf);
        tracecmd_follow_event(handle, "kvm", "kvm_exit", show_event, guest_tep);
        tracecmd_follow_event(handle, "kvm", "kvm_entry", show_event, guest_tep);
        tracecmd_iterate_events(handle, NULL, 0, NULL, NULL);
        tep_free(guest_tep);
        tracecmd_close(handle);
}

NAME

tep_plugin_kvm_put_func - Get the KVM related functions

SYNOPSIS

#include <eng/util.h>

struct tep_event_filter *tep_plugin_kvm_put_func(void);

DESCRIPTION

The function tep_plugin_kvm_put_func() is used to get the KVM related functions. These functions are used to filter KVM events.

RETURN VALUE

Returns a pointer to a struct tep_event_filter on success, or NULL on failure.

EXAMPLE

Here is an example of how to use the tep_plugin_kvm_put_func() function:

struct tep_event_filter *filter;
filter = tep_plugin_kvm_put_func();
if (!filter) {
  // handle error
}
