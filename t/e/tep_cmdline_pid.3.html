tep_cmdline_pid(3)

Paquet: libtraceevent

Licences: GPL-2.0-only, LGPL-2.1-only

LIBTRACEEVENT(3) Manuel libtraceevent LIBTRACEEVENT(3)

NOM

tep_register_comm, tep_override_comm, tep_is_pid_registered, tep_data_comm_from_pid, tep_data_pid_from_comm, tep_cmdline_pid - Gérer les correspondances pid vers nom de processus.

SYNTAXE

#include <event-parse.h>
int tep_register_comm(struct tep_handle *tep, const char *comm, int pid);
int tep_override_comm(struct tep_handle *tep, const char *comm, int pid);
bool tep_is_pid_registered(struct tep_handle *tep, int pid);
const char *tep_data_comm_from_pid(struct tep_handle *pevent, int pid);
struct cmdline *tep_data_pid_from_comm(struct tep_handle *pevent, const char *comm, struct cmdline *next);
int tep_cmdline_pid(struct tep_handle *pevent, struct cmdline *cmdline);

DESCRIPTION

Ces fonctions peuvent être utilisées pour gérer la correspondance entre pid et nom de processus. La bibliothèque construit un cache de ces correspondances, qui est utilisé pour afficher le nom du processus, au lieu de son pid. Ces informations peuvent être récupérées à partir du fichier tracefs/saved_cmdlines.

La fonction tep_register_comm() enregistre une correspondance pid / nom de processus. Si une commande avec le même pid est déjà enregistrée, une erreur est retournée. L'argument pid est l'ID du processus, l'argument comm est le nom du processus, tep est le contexte de l'événement. Le comm est dupliqué en interne.

La fonction tep_override_comm() enregistre une correspondance pid / nom de processus. Si un processus avec le même pid est déjà enregistré, la chaîne de nom de processus est mise à jour avec la nouvelle. L'argument pid est l'ID du processus, l'argument comm est le nom du processus, tep est le contexte de l'événement. Le comm est dupliqué en interne.

La fonction tep_is_pid_registered() vérifie si un pid a une correspondance de nom de processus enregistrée. L'argument pid est l'ID du processus, tep est le contexte de l'événement.

La fonction tep_data_comm_from_pid() retourne le nom du processus pour un pid donné. L'argument pid est l'ID du processus, tep est le contexte de l'événement. La chaîne retournée ne doit pas être libérée, mais sera libérée lorsque le gestionnaire tep sera fermé.

La fonction tep_data_pid_from_comm() retourne un pid pour un nom de processus donné. L'argument comm est le nom du processus, tep est le contexte de l'événement. L'argument next est la structure cmdline pour rechercher le pid suivant. Comme il peut y avoir plus d'un pid pour un processus donné, le résultat de cet appel peut être passé lors d'un appel récurrent dans le paramètre next, pour rechercher le pid suivant. Si next est NULL, elle retournera le premier pid associé au comm. La fonction effectue une recherche linéaire, elle peut donc être lente.

La fonction tep_cmdline_pid() retourne le pid associé à une cmdline donnée. L'argument tep est le contexte de l'événement.

VALEUR DE RETOUR

La fonction tep_register_comm() retourne 0 en cas de succès. En cas d'erreur, -1 est retourné et errno est défini pour indiquer la cause du problème : ENOMEM, s'il n'y a pas assez de mémoire pour dupliquer le comm, ou EEXIST si une correspondance pour ce pid est déjà enregistrée.

La fonction tep_override_comm() retourne 0 en cas de succès. En cas d'erreur, -1 est retourné et errno est défini pour indiquer la cause du problème : ENOMEM, s'il n'y a pas assez de mémoire pour dupliquer le comm.

La fonction tep_is_pid_registered() retourne vrai si le pid a un nom de processus qui lui est associé, faux sinon.

La fonction tep_data_comm_from_pid() retourne le nom du processus sous forme de chaîne, ou la chaîne "<...>" s'il n'y a pas de correspondance pour le pid donné.

La fonction tep_data_pid_from_comm() retourne un pointeur vers une structure cmdline, qui contient un pid pour un processus donné, ou NULL si aucun n'est trouvé. Ce résultat peut être passé lors d'un appel récurrent comme paramètre next de la fonction.

La fonction tep_cmdline_pid() retourne le pid pour la cmdline donnée. Si cmdline est NULL, alors -1 est retourné.

EXEMPLE

L'exemple suivant enregistre un pid pour la commande « ls », dans le contexte de l'événement tep et effectue diverses recherches de correspondances pid / nom de processus :

#include <event-parse.h>
...
int ret;
int ls_pid = 1021;
struct tep_handle *tep = tep_alloc();
...
        ret = tep_register_comm(tep, "ls", ls_pid);
        if (ret != 0 && errno == EEXIST)
                ret = tep_override_comm(tep, "ls", ls_pid);
        if (ret != 0) {
                /* Échec de l'enregistrement de la correspondance pid / commande */
        }
...
        if (tep_is_pid_registered(tep, ls_pid) == 0) {
                /* La correspondance de commande pour ls_pid n'est pas enregistrée */
        }
...
        const char *comm = tep_data_comm_from_pid(tep, ls_pid);
        if (comm) {
                /* Nom de processus trouvé pour ls_pid */
        }
...
        int pid;
        struct cmdline *cmd = tep_data_pid_from_comm(tep, "ls", NULL);
        while (cmd) {
                pid = tep_cmdline_pid(tep, cmd);
                /* Pid trouvé pour le processus « ls » */
                cmd = tep_data_pid_from_comm(tep, "ls", cmd);
        }

tep_cmdline_pid(3) - man pages

TEP_CMDLINE_PID is a probe that traces the command line of a process. It is triggered when a process is created or its command line is updated.

SYNOPSIS

tep_cmdline_pid(pid)

DESCRIPTION

The tep_cmdline_pid probe allows you to trace the command line of a process identified by its process ID (PID). This probe is useful for monitoring process creation and command-line arguments used.

RETURN VALUE

This probe does not return any specific value. It is used for tracing purposes.

EXAMPLE

To trace the command line of a process with PID 1234, you can use the following command: 

sudo tep_cmdline_pid 1234

FILES

No specific files are associated with this probe.
