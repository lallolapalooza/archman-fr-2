NOM

tecla, teclarc - L'interface utilisateur fournie par la bibliothèque Tecla.

DESCRIPTION

Cette page de manuel décrit les fonctionnalités d'édition en ligne de commande disponibles pour les utilisateurs de programmes qui lisent l'entrée du clavier via la bibliothèque Tecla. Les utilisateurs du shell tcsh trouveront les raccourcis clavier par défaut très familiers. Les utilisateurs du shell bash les trouveront également assez familiers, mais avec quelques différences mineures, notamment dans la manière dont les recherches avant et arrière dans la liste des commandes historiques sont effectuées. Il existe deux modes d'édition majeurs, l'un avec des raccourcis clavier de type emacs et l'autre avec des raccourcis clavier de type vi. Par défaut, le mode emacs est activé, mais le mode vi peut être sélectionné alternativement via le fichier de configuration de l'utilisateur. Ce fichier peut également être utilisé pour modifier les liaisons de touches individuelles selon les préférences de l'utilisateur. Par défaut, la complétion par tabulation est fournie. Si l'application n'a pas reconfiguré cela pour compléter d'autres types de symboles, la complétion par tabulation complète les noms de fichiers.

NOTATION DES SEQUENCES DE TOUCHES

Dans le reste de cette page de manuel, ainsi que dans tous les fichiers de configuration Tecla, les séquences de touches sont exprimées comme suit.

^A  ou  C-a
    Ceci est un contrôle-A, entré en appuyant sur la touche contrôle en même
    temps que la touche A.
\E    ou   M-
    Dans les séquences de touches, ces deux notations peuvent être entrées
    soit en appuyant sur la touche échappement, puis la touche suivante,
    soit en appuyant sur la touche Meta en même temps que la touche suivante.
    Ainsi, la séquence de touches M-p peut être tapée de deux manières,
    en appuyant sur la touche échappement, suivie de l'appui sur p,
    ou en appuyant sur la touche Meta en même temps que p.
up
    Ceci fait référence à la touche flèche haut.
down
    Ceci fait référence à la touche flèche bas.
left
    Ceci fait référence à la touche flèche gauche.
right
    Ceci fait référence à la touche flèche droite.
a
    Ceci est simplement une touche A normale.

LE FICHIER DE CONFIGURATION TECLA

Par défaut, Tecla recherche un fichier nommé .teclarc dans votre répertoire personnel (c'est-à-dire ~/.teclarc). S'il trouve ce fichier, il le lit, interprétant chaque ligne comme définissant une nouvelle liaison de touches ou une option de configuration d'édition. Puisque les raccourcis clavier emacs sont installés par défaut, si vous souhaitez utiliser le mode d'édition vi non-défaut, l'élément le plus important à mettre dans ce fichier est la ligne suivante :

  edit-mode vi

Cela reconfigurera les liaisons par défaut pour le mode vi. L'ensemble complet des arguments que cette commande accepte est :

  vi     -  Installe les liaisons de touches comme celles de l'éditeur
            vi.
  emacs  -  Installe les liaisons de touches comme celles de l'éditeur
            emacs. C'est le défaut.
  none   -  Utilise uniquement les facilités natives d'édition de ligne
            fournies par le pilote du terminal.

Pour empêcher la sonnerie du terminal de retentir, par exemple lorsqu'une séquence de contrôle non reconnue est tapée, placez la ligne suivante dans le fichier de configuration :

  nobeep

Un exemple de ligne de liaison de touches dans le fichier de configuration est le suivant.

  bind M-[2~ insert-mode

Sur de nombreux claviers, la séquence de touches ci-dessus est générée lorsque l'on appuie sur la touche insert, donc avec cette liaison de touches, on peut basculer entre les modes d'insertion et d'écrasement du mode emacs en appuyant sur une seule touche. On pourrait également le faire en tapant la séquence de caractères ci-dessus un par un. Comme expliqué ci-dessus, la partie M- de cette séquence peut être tapée soit en appuyant sur la touche échappement avant la touche suivante, soit en appuyant sur la touche Meta en même temps que la touche suivante. Donc, si vous aviez défini la liaison de touches ci-dessus, et que la touche d'insertion de votre clavier ne générait pas la séquence de touches ci-dessus, vous pourriez toujours la taper de l'une des 2 manières suivantes.

  1. Appuyez momentanément sur la touche échappement, puis appuyez sur
     '[', puis '2', puis enfin '~'.
  2. Appuyez sur la touche meta en même temps que vous appuyez sur la
     touche '[', puis appuyez sur '2', puis '~'.

Si vous définissez une liaison de touches pour une séquence de touches déjà liée à une fonction, la nouvelle liaison remplace l'ancienne. Si dans la nouvelle liaison vous omettez le nom de la nouvelle fonction à lier à la séquence de touches, la liaison d'origine devient indéfinie.

À partir des versions de libtecla ultérieures à 1.3.3, il est désormais possible de lier des séquences de touches commençant par un caractère imprimable. Auparavant, les séquences de touches devaient commencer par un caractère de contrôle ou méta.

Notez que les mots-clés spéciaux « up », « down », « left » et « right » font référence aux touches fléchées, et ne sont donc pas traités comme des séquences de touches. Ainsi, par exemple, pour reconfigurer les touches fléchées haut et bas afin d'utiliser le mécanisme de recherche d'historique au lieu de la simple méthode de rappel d'historique, vous pouvez placer ce qui suit dans votre fichier de configuration :

  bind up history-search-backwards
  bind down history-search-backwards

Pour délier une liaison existante, vous pouvez le faire avec la commande bind en omettant de spécifier une fonction d'action pour lier la séquence de touches. Par exemple, en n'omettant pas de spécifier une fonction d'action, la commande suivante délie l'action par défaut de début de ligne de la séquence de touches ^A :

  bind ^A

Si vous créez un fichier de configuration ~/.teclarc, mais qu'il semble n'avoir aucun effet sur le programme, consultez la documentation du programme pour voir si l'auteur a choisi un nom différent pour ce fichier.

COMPLETION DE NOM DE FICHIER ET TILDE

Avec les liaisons de touches par défaut, appuyer sur la touche TAB (alias. ^I) amène Tecla à tenter de compléter le nom de fichier incomplet qui précède le curseur. Tecla recherche en arrière à partir du curseur, cherchant le début du nom de fichier, s'arrêtant lorsqu'il rencontre un espace ou le début de la ligne. Si plus d'un fichier a le préfixe spécifié, Tecla complète le nom de fichier jusqu'au point où les correspondances ambiguës commencent à différer, puis liste les correspondances possibles.

En plus des noms de fichiers littéralement écrits, Tecla peut compléter les fichiers commençant par ~/ et les expressions ~utilisateur/ ainsi que ceux contenant des expressions $variable_env. En particulier, si vous appuyez sur TAB dans une expression ~utilisateur incomplète, Tecla tentera de compléter le nom d'utilisateur, listant toute correspondance ambiguë.

La liaison de complétion est implémentée en utilisant la fonction cpl_word_completions(), qui est également disponible séparément aux utilisateurs de cette bibliothèque. Voir la page de manuel cpl_complete_word(3) pour plus de détails.

EXPANSION DES NOMS DE FICHIER

Avec les liaisons de touches par défaut, appuyer sur ^X* amène Tecla à développer le nom de fichier qui précède le curseur, remplaçant les expressions ~/ et ~utilisateur/ par les répertoires personnels correspondants, et remplaçant les expressions $variable_env par la valeur de la variable d'environnement spécifiée, puis, s'il y a des jokers, remplaçant le nom de fichier développé jusqu'à présent par une liste de noms de fichiers séparés par des espaces qui correspondent aux jokers.

La liaison d'expansion est implémentée en utilisant la fonction ef_expand_file(). Voir la page de manuel ef_expand_file(3) pour plus de détails.

RAPPEL DES LIGNES TAPEES PRECÉDEMMENT

Chaque fois qu'une nouvelle ligne est entrée par l'utilisateur, elle est ajoutée à une liste de lignes d'entrée historiques maintenue dans l'objet de ressource GetLine. Vous pouvez parcourir cette liste de haut en bas en utilisant les touches fléchées haut et bas. Alternativement, vous pouvez faire de même avec les touches ^P et ^N, et en mode commande vi, vous pouvez alternativement utiliser les caractères k et j. Ainsi, appuyer une fois sur la flèche haut remplace la ligne d'entrée actuelle par la ligne précédemment entrée. Appuyer à nouveau sur la flèche haut la remplace par la ligne entrée avant elle, etc. Après être revenu d'une ou plusieurs lignes dans la liste d'historique, vous pouvez revenir à des lignes plus récentes en appuyant plusieurs fois sur la flèche bas. Si vous le faites suffisamment de fois, vous reviendrez à la ligne d'origine que vous étiez en train d'entrer lorsque vous avez d'abord appuyé sur la flèche haut.

Notez qu'en mode vi, toutes les fonctions de rappel d'historique font passer la bibliothèque en mode commande.

HISTORY SEARCH

They search for includes the character under the cursor as well as what precedes it.

Thus for example, suppose that you were in emacs mode, and you had just entered the following list of commands in the order shown:

  ls ~/tecla/
  cd ~/tecla
  ls -l getline.c
  emacs ~/tecla/getline.c

If you next typed:

  ls

and then hit M-p, then rather than returning the previously typed emacs line, which doesn't start with "ls", Tecla would recall the "ls -l getline.c" line. Pressing M-p again would recall the "ls ~/tecla/" line.

Note that if the string that you are searching for, contains any of the special characters, *, ?, or '[', then it is interpretted as a pattern to be matched. Thus, cotinuing with the above example, after typing in the list of commands shown, if you then typed:

  *tecla*

and hit M-p, then the "emacs ~/tecla/getline.c" line would be recalled first, since it contains the word tecla somewhere in the line, Similarly, hitting M-p again, would recall the "ls ~/tecla/" line, and hitting it once more would recall the "ls ~/tecla/" line. The pattern syntax is the same as that described for filename expansion, in the ef_expand_file(3 man page.

FICHIERS HISTORIQUES

Authors of programs that use the Tecla library have the option of saving historical command-lines in a file before exiting, and subsequently reading them back in from this file when the program is next started. There is no standard name for this file, since it makes sense for each application to use its own history file, so that commands from different applications don't get mixed up.

SETS DE CARACTÈRES INTERNATIONAUX

Since libtecla version 1.4.0, Tecla has been 8-bit clean. This means that all 8-bit characters that are printable in the user's current locale are now displayed verbatim and included in the returned input line. Assuming that the calling program correctly contains a call like the following,

  setlocale(LC_CTYPE, "");

then the current locale is determined by the first of the environment variables LC_CTYPE, LC_ALL, and LANG, that is found to contain a valid locale name. If none of these variables are defined, or the program neglects to call setlocale, then the default C locale is used, which is US 7-bit ASCII. On most unix-like platforms, you can get a list of valid locales by typing the command:

  locale -a

at the shell prompt.

Touches Meta et locales

Beware that in most locales other than the default C locale, meta characters become printable, and they are then no longer considered to match M-c style key bindings. This allows international characters to be entered with the compose key without unexpectedly triggering meta key bindings. You can still invoke meta bindings, since there are actually two ways to do this. For example the binding M-c can also be invoked by pressing the escape key momentarily, then pressing the c key, and this will work regardless of locale. Moreover, many modern terminal emulators, such as gnome's gnome-terminal's and KDE's konsole terminals, already generate escape pairs like this when you use the meta key, rather than a real meta character, and other emulators usually have a way to request this behavior, so you can continue to use the meta key on most systems.

For example, although xterm terminal emulators generate real 8-bit meta characters by default when you use the meta key, they can be configured to output the equivalent escape pair by setting their EightBitInput X resource to False. You can either do this by placing a line like the following in your ~/.Xdefaults file,

  XTerm*EightBitInput: False
or by starting an xterm with an -xrm '*EightBitInput: False' command-line argument. In recent versions of xterm you can toggle this feature on and off with the "Meta Sends Escape" option in the menu that is displayed when you press the left mouse button and the control key within an xterm window. In CDE, dtterms can be similarly coerced to generate escape pairs in place of meta characters, by setting the Dtterm*KshMode resource to True.

Saisie de caractères internationaux

If you don't have a keyboard that generates all of the international characters that you need, there is usually a compose key that will allow you to enter special characters, or a way to create one. For example, under X windows on unix-like systems, if your keyboard doesn't have a compose key, you can designate a redundant key to serve this purpose with the xmodmap command. For example, on many PC keyboards there is a microsoft-windows key, which is otherwise useless under Linux. On my laptop the xev program reports that pressing this key generates keycode 115, so to turn this key into a compose key, I do the following:

  xmodmap -e 'keycode 115 = Multi_key'

I can then enter an i with a umlaut over it by typing this key, followed by ", followed by i.

LIAISONS DE TOUCHES PAR DÉFAUT EN MODE VI

Les liaisons de touches par défaut suivantes sont conçues pour imiter le style d'édition vi autant que possible. Cela signifie que très peu de fonctions d'édition sont fournies en mode de saisie de caractères initial, les fonctions d'édition étant plutôt fournies par le mode commande vi. Le mode commande vi est entré chaque fois que le caractère d'échappement est pressé, ou chaque fois qu'une séquence de touches commençant par un caractère méta est entrée. Sous UNIX, le pilote de terminal définit un certain nombre de touches spéciales pour certaines fonctions. ENTRER LES COMPTES DE RÉPÉTITION

Beaucoup de fonctions de raccourcis clavier décrites précédemment, prennent un compte optionnel, tapé avant la séquence de touches cible. Ceci est interprété comme un compte de répétition par la plupart des raccourcis. Une exception notable est le raccourci goto-column, qui interprète le compte comme un numéro de colonne.

Par défaut, vous pouvez spécifier cet argument de compte en appuyant sur la touche méta tout en tapant le compte numérique. Ceci repose sur l'action digit-argument étant liée à Meta-0, Meta-1 etc. Une fois que l'un de ces raccourcis a été activé, vous pouvez éventuellement retirer votre doigt de la touche méta pour taper le reste du nombre, car chaque chiffre numérique suivant est traité comme faisant partie du nombre, à moins qu'il ne soit précédé par le raccourci literal-next. Dès qu'un caractère non numérique, ou un chiffre littéral, est pressé, le compte de répétition est terminé et soit provoque l'ajout du caractère juste tapé à la ligne autant de fois, soit provoque la transmission du prochain raccourci clavier avec cet argument.

Par exemple, en mode emacs, taper:

  M-12a

fait ajouter la lettre 'a' à la ligne 12 fois, alors que

  M-4M-c

met en majuscules les 4 mots suivants.

En mode commande vi, le modificateur Meta est automatiquement ajouté à tous les caractères tapés. Donc, pour entrer un compte en mode commande vi, il suffit de taper le nombre, tout comme cela se fait dans l'éditeur vi lui-même. Ainsi, par exemple, en mode commande vi, taper:

  4w2x

déplace le curseur de quatre mots vers la droite, puis supprime deux caractères.

Vous pouvez également lier digit-argument à d'autres séquences de touches. Si celles-ci se terminent par un chiffre numérique, ce chiffre est ajouté au compte de répétition actuel. Si elles ne se terminent pas par un chiffre numérique, un nouveau compte de répétition est démarré avec une valeur de zéro, et peut être complété en tapant le nombre, après avoir relâché la touche qui a déclenché l'action digit-argument.

    tecla, tecla.tcsh, tecla.zsh -- un outil de gestion de session à la tty

    SOMMAIRE

    
tecla
tecla --start
tecla --start [program] [args...]
tecla --stop
tecla --status
tecla --list
tecla --kill <session_id>
tecla --recover
tecla --help

    DESCRIPTION

    tecla est un outil de gestion de session à la tty. Il est conçu pour vous permettre de sauvegarder votre état de session et de le restaurer plus tard, en vous permettant de vous déconnecter et de vous reconnecter plus tard à la même session. C'est particulièrement utile pour les utilisateurs qui travaillent sur des serveurs distants ou qui ont besoin de gérer plusieurs sessions en parallèle.

    tecla peut être utilisé pour démarrer une nouvelle session, arrêter une session existante, vérifier le statut de la session, lister les sessions disponibles, tuer une session spécifique, et récupérer des sessions perdues.

    OPTIONS

    --start : Démarre une nouvelle session. Si un programme et ses arguments sont spécifiés, il sera exécuté dans la nouvelle session. Sinon, un shell interactif sera lancé.

    --stop : Arrête la session actuelle.

    --status : Affiche le statut de la session actuelle.

    --list : Liste toutes les sessions disponibles.

    --kill <session_id> : Tue la session spécifiée par son ID.

    --recover : Tente de récupérer des sessions perdues.

    --help : Affiche l'aide et quitte.

    EXEMPLES

    
# Démarrer une nouvelle session avec un shell interactif
tecla --start

# Démarrer une nouvelle session et exécuter 'vim mon_fichier.txt'
tecla --start vim mon_fichier.txt

# Arrêter la session actuelle
tecla --stop

# Lister toutes les sessions disponibles
tecla --list

# Tuer la session avec l'ID '12345'
tecla --kill 12345

    FICHIERS

    Les fichiers de session sont généralement stockés dans ~/.tecla/sessions.
