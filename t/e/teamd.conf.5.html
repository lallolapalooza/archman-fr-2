TEAMD.CONF(5) Configuration du démon teamd TEAMD.CONF(5)

NOM

teamd.conf — Fichier de configuration du démon libteam

DESCRIPTION

teamd utilise le format de configuration JSON.

OPTIONS

device (chaîne de caractères)
Nom souhaité du nouveau périphérique team.
debug_level (entier)
Niveau des messages de débogage. Plus il est élevé, plus il y aura de messages de débogage affichés. C'est équivalent à l'ajout des options de ligne de commande "-g".

Par défaut : 0 (désactivé)

hwaddr (chaîne de caractères)
Adresse matérielle souhaitée du nouveau périphérique team. Le format habituel d'adresse MAC est accepté.
runner.name (chaîne de caractères)
Nom du périphérique team. Les runners suivants sont disponibles :

broadcast — Runner simple qui dirige le périphérique team pour transmettre les paquets via tous les ports.

roundrobin — Runner simple qui dirige le périphérique team pour transmettre les paquets de manière cyclique.

random — Runner simple qui dirige le périphérique team pour transmettre les paquets sur un port sélectionné aléatoirement.

activebackup — Surveille les changements de lien et sélectionne le port actif à utiliser pour les transferts de données.

loadbalance — Pour effectuer un équilibrage de charge passif, le runner configure uniquement une fonction de hachage BPF qui déterminera le port pour la transmission des paquets. Pour effectuer un équilibrage de charge actif, le runner déplace les hachages entre les ports disponibles en essayant d'atteindre un équilibre parfait.

lacp — Implémente le protocole 802.3ad LACP. Peut utiliser les mêmes possibilités de sélection de port Tx que le runner loadbalance.

Par défaut : roundrobin

notify_peers.count (entier)
Nombre de rafales de NAs non sollicités et de paquets ARP gratuits envoyés après l'activation ou la désactivation d'un port.

Par défaut : 0 (désactivé)

Par défaut pour le runner activebackup : 1

notify_peers.interval (entier)
La valeur est un nombre positif en millisecondes. Spécifie un intervalle entre les rafales de paquets notify-peer.

Par défaut : 0

mcast_rejoin.count (entier)
Nombre de rafales de requêtes de réadhésion aux groupes multicast envoyées après l'activation ou la désactivation d'un port.

Par défaut : 0 (désactivé)

Par défaut pour le runner activebackup : 1

mcast_rejoin.interval (entier)
La valeur est un nombre positif en millisecondes. Spécifie un intervalle entre les rafales de requêtes de réadhésion aux groupes multicast.

Par défaut : 0

link_watch.name | ports.PORTIFNAME.link_watch.name (chaîne de caractères)
Nom du surveillant de lien à utiliser. Les surveillants de lien suivants sont disponibles :

ethtool — Utilise Libteam lib pour obtenir les changements d'état des ports ethtool.

arp_ping — Des requêtes ARP sont envoyées via un port. Si une réponse ARP est reçue, le lien est considéré comme actif.

nsna_ping — Similaire au précédent, sauf qu'il utilise le mécanisme Neighbor Solicitation / Neighbor Advertisement d'IPv6. C'est une alternative à arp_ping et devient utile dans les environnements purement IPv6.

ports (objet)
Liste des ports, périphériques réseau, à utiliser dans un périphérique team.

Voir les exemples pour plus d'informations.

ports.PORTIFNAME.queue_id (entier)
ID de la file d'attente à laquelle ce port doit être mappé.

Par défaut : Aucun

OPTIONS SPéCIFIQUES AU RUNNER ACTIVE-BACKUP

runner.hwaddr_policy (chaîne de caractères)
Définit la politique de configuration des adresses matérielles du périphérique team et des périphériques ports pendant la durée de vie du team. Les options suivantes sont disponibles :

same_all — Tous les ports auront toujours la même adresse matérielle que le périphérique team associé.

by_active — Le périphérique team adopte l'adresse matérielle du port actif actuel. Ceci est utile lorsque le périphérique port n'est pas capable de changer son adresse matérielle.

only_active — Seul le port actif adopte l'adresse matérielle du périphérique team. Les autres conservent leur propre adresse.

Par défaut : same_all

ports.PORTIFNAME.prio (entier)
Priorité du port. Un nombre plus élevé signifie une priorité plus élevée.

Par défaut : 0

ports.PORTIFNAME.sticky (booléen)
Indicateur qui spécifie si le port est "collant" (sticky). S'il est défini, cela signifie que le port n'est pas désélectionné si un autre port avec une priorité plus élevée ou de meilleurs paramètres devient disponible.

Par défaut : faux

OPTIONS SPéCIFIQUES AU RUNNER LOAD BALANCE

runner.tx_hash (tableau)
Liste des types de fragments (chaînes de caractères) qui devraient être utilisés pour le calcul du hachage Tx des paquets. Les suivants sont disponibles :

eth — Utilise les adresses MAC source et destination.

vlan — Utilise l'ID VLAN.

ipv4 — Utilise les adresses IPv4 source et destination.

ipv6 — Utilise les adresses IPv6 source et destination.

ip — Utilise les adresses IPv4 et IPv6 source et destination.

l3 — Utilise les adresses IPv4 et IPv6 source et destination.

tcp — Utilise les ports TCP source et destination.

udp — Utilise les ports UDP source et destination.

sctp — Utilise les ports SCTP source et destination.

l4 — Utilise les ports TCP, UDP et SCTP source et destination.

Par défaut : ["eth", "ipv4", "ipv6"]

runner.tx_balancer.name (chaîne de caractères)
Nom de l'équilibreur de charge Tx actif. L'équilibrage de charge Tx actif est désactivé par défaut. La seule valeur disponible est basic.

Par défaut : Aucun

runner.tx_balancer.balancing_interval (entier)
En dixièmes de seconde. Intervalle périodique entre les rééquilibrages.

Par défaut : 50

OPTIONS SPéCIFIQUES AU RUNNER LACP

runner.active (booléen)
Si true, les trames LACPDU sont envoyées le long des liens configurés périodiquement. Sinon, il agit comme "parler quand on vous parle".

Par défaut : vrai

runner.fast_rate (bool)
L'option spécifie la fréquence à laquelle il est demandé à notre partenaire de liaison de transmettre des paquets LACPDU. Si la valeur est true, les paquets seront envoyés une fois par seconde. Sinon, ils seront envoyés toutes les 30 secondes.

Par défaut : false

runner.tx_hash (tableau)
Identique à l'exécuteur d'équilibrage de charge.
runner.tx_balancer.name (chaîne)
Identique à l'exécuteur d'équilibrage de charge.
runner.tx_balancer.balancing_interval (entier)
Identique à l'exécuteur d'équilibrage de charge.
runner.sys_prio (entier)
Priorité du système, la valeur peut être comprise entre 0 et 65535.

Par défaut : 65535

runner.min_ports (entier)
Spécifie le nombre minimum de ports qui doivent être actifs avant de signaler la porteuse dans l'interface maître, la valeur peut être comprise entre 1 et 1024.

Par défaut : 1

runner.agg_select_policy (chaîne)
Ceci sélectionne la politique de sélection des agrégateurs. Les options suivantes sont disponibles :

lacp_prio — L'agrégateur avec la priorité la plus élevée selon la norme LACP sera sélectionné. La priorité de l'agrégateur est affectée par l'option par port lacp_prio.

lacp_prio_stable — Identique à la précédente, sauf que l'agrégateur sélectionné n'est pas remplacé s'il est toujours utilisable.

bandwidth — Sélectionne l'agrégateur avec la bande passante totale la plus élevée.

count — Sélectionne l'agrégateur avec le plus grand nombre de ports.

port_config — L'agrégateur avec la priorité la plus élevée selon les options par port prio et sticky sera sélectionné. Cela signifie que l'agrégateur contenant le port avec la priorité la plus élevée sera sélectionné, sauf si au moins un des ports de l'agrégateur actuellement sélectionné est collant (sticky).

Par défaut : lacp_prio

ports.PORTIFNAME.lacp_prio (entier)
Priorité du port selon la norme LACP. Un nombre plus bas signifie une priorité plus élevée.

Par défaut : 255

ports.PORTIFNAME.lacp_key (entier)
Clé du port selon la norme LACP. Il n'est possible d'agréger que des ports ayant la même clé.

Par défaut : 0

OPTIONS SPÉCIFIQUES À ETHTOOL LINK WATCH

link_watch.delay_up | ports.PORTIFNAME.link_watch.delay_up (entier)
La valeur est un nombre positif en millisecondes. Il s'agit du délai entre le moment où la liaison devient active et le moment où l'exécuteur en est notifié.

Par défaut : 0

link_watch.delay_down | ports.PORTIFNAME.link_watch.delay_down (entier)
La valeur est un nombre positif en millisecondes. Il s'agit du délai entre le moment où la liaison devient inactive et le moment où l'exécuteur en est notifié.

Par défaut : 0

OPTIONS SPÉCIFIQUES À ARP PING LINK WATCH

link_watch.interval | ports.PORTIFNAME.link_watch.interval (entier)
La valeur est un nombre positif en millisecondes. C'est l'intervalle entre l'envoi des requêtes ARP.

Par défaut : 1000

link_watch.init_wait | ports.PORTIFNAME.link_watch.init_wait (entier)
La valeur est un nombre positif en millisecondes. Il s'agit du délai entre l'initialisation de la surveillance de la liaison et le premier envoi de la requête ARP.

Par défaut : 0

link_watch.missed_max | ports.PORTIFNAME.link_watch.missed_max (entier)
Nombre maximum de réponses ARP manquées. Si ce nombre est dépassé, la liaison est signalée comme étant inactive.

Par défaut : 3

link_watch.source_host | ports.PORTIFNAME.link_watch.source_host (nom d'hôte)
Nom d'hôte à convertir en adresse IP qui sera utilisée comme adresse source dans la requête ARP.

Par défaut : 0.0.0.0

link_watch.target_host | ports.PORTIFNAME.link_watch.target_host (nom d'hôte)
Nom d'hôte à convertir en adresse IP qui sera utilisée comme adresse de destination dans la requête ARP.
link_watch.validate_active | ports.PORTIFNAME.link_watch.validate_active (bool)
Valide les paquets ARP reçus sur les ports actifs. Si cette option n'est pas définie, tous les paquets ARP entrants seront considérés comme une réponse valide.

Par défaut : false

link_watch.validate_inactive | ports.PORTIFNAME.link_watch.validate_inactive (bool)
Valide les paquets ARP reçus sur les ports inactifs. Si cette option n'est pas définie, tous les paquets ARP entrants seront considérés comme une réponse valide.

Par défaut : false

link_watch.vlanid | ports.PORTIFNAME.link_watch.vlanid (entier)
Par défaut, les requêtes ARP sont envoyées sans étiquettes VLAN. Cette option permet d'envoyer les requêtes ARP sortantes avec l'identifiant VLAN spécifié.

Par défaut : Aucun

link_watch.send_always | ports.PORTIFNAME.link_watch.send_always (bool)
Par défaut, les requêtes ARP sont envoyées uniquement sur les ports actifs. Cette option permet de les envoyer même sur les ports inactifs.

Par défaut : false

OPTIONS SPÉCIFIQUES À NS/NA PING LINK WATCH

link_watch.interval | ports.PORTIFNAME.link_watch.interval (entier)
La valeur est un nombre positif en millisecondes. C'est l'intervalle entre l'envoi des paquets NS.

Par défaut : 1000

link_watch.init_wait | ports.PORTIFNAME.link_watch.init_wait (entier)
La valeur est un nombre positif en millisecondes. Il s'agit du délai entre l'initialisation de la surveillance de la liaison et le premier envoi du paquet NS.
link_watch.missed_max | ports.PORTIFNAME.link_watch.missed_max (entier)
Nombre maximum de paquets NA reçus manqués. Si ce nombre est dépassé, la liaison est signalée comme étant inactive.

Par défaut : 3

link_watch.target_host | ports.PORTIFNAME.link_watch.target_host (nom d'hôte)
Nom d'hôte à convertir en adresse IPv6 qui sera utilisée comme adresse cible dans le paquet NS.
link_watch_policy (chaîne)
Nom de la politique d'évaluation des link-watchers. Les options disponibles sont les suivantes :

any — La liaison est considérée comme active si n'importe lequel des link-watchers la signale comme active.

all — La liaison est considérée comme active si tous les link-watchers la signalent comme active.

Par défaut : any

EXEMPLES

{
  "device": "team0",
  "runner": {"name": "roundrobin"},
  "ports": {"eth1": {}, "eth2": {}}
}

Configuration très basique.

{
  "device": "team0",
  "runner": {"name": "activebackup"},
  "link_watch": {"name": "ethtool"},
  "ports": {
    "eth1": {
      "prio": -10,
      "sticky": true
    },
    "eth2": {
      "prio": 100
    }
  }
}

Cette configuration utilise l'exécuteur active-backup avec le surveillant de liaison ethtool. Le port eth2 a une priorité plus élevée, mais le drapeau sticky garantit que si eth1 devient actif, il reste actif tant que la liaison est active.

{
  "device": "team0",
  "runner": {"name": "activebackup"},
  "link_watch": {
    "name": "ethtool",
    "delay_up": 2500,
    "delay_down": 1000
  },
  "ports": {
    "eth1": {
      "prio": -10,
      "sticky": true
    },
    "eth2": {
      "prio": 100
    }
  }
}

Similaire à la précédente. La seule différence est que les changements de liaison ne sont pas immédiatement transmis à l'exécuteur, mais des délais sont appliqués.

{
  "devic
e": "team0", "runner": {"name": "activebackup"}, "link_watch": { "name": "arp_ping", "interval": 100, "missed_max": 30, "target_host": "192.168.23.1" }, "ports": { "eth1": { "prio": -10, "sticky": true }, "eth2": { "prio": 100 } } }

Cette configuration utilise la surveillance de lien par ping ARP.

{
"device": "team0",
"runner": {"name": "activebackup"},
"link_watch": [
  {
    "name": "arp_ping",
    "interval": 100,
    "missed_max": 30,
    "target_host": "192.168.23.1"
  },
  {
    "name": "arp_ping",
    "interval": 50,
    "missed_max": 20,
    "target_host": "192.168.24.1"
  }
],
"ports": {
  "eth1": {
    "prio": -10,
    "sticky": true
  },
  "eth2": {
    "prio": 100
    }
  }
}

Similaire à la précédente, mais utilise deux surveillances de lien en même temps.

{
  "device": "team0",
  "runner": {"name": "activebackup"},
  "link_watch_policy": "all",
  "link_watch": [
    {
    "name": "arp_ping",
    "interval": 100,
    "missed_max": 30,
    "target_host": "192.168.23.1"
    },
    {
    "name": "ethtool"
    }
  ],
  "ports":  {
    "eth1": {
      "prio": -10,
      "sticky": true
    },
    "eth2": {
      "prio": 100
    }
  }
}

Deux surveillances de lien sont utilisées en même temps. Le lien n'est considéré comme actif que si toutes les surveillances configurées indiquent que le lien est actif.

{
  "device": "team0",
  "runner": {
    "name": "loadbalance",
    "tx_hash": ["eth", "ipv4", "ipv6"]
  },
  "ports": {"eth1": {}, "eth2": {}}
}

Configuration pour l'équilibrage de charge de transmission (Tx) passif basé sur un hachage.

{
  "device": "team0",
  "runner": {
    "name": "loadbalance",
    "tx_hash": ["eth", "ipv4", "ipv6"],
    "tx_balancer": {
      "name": "basic"
    }
  },
  "ports": {"eth1": {}, "eth2": {}}
}

Configuration pour l'équilibrage de charge de transmission (Tx) actif utilisant un équilibreur de charge de base.

{
  "device": "team0",
  "runner": {
    "name": "lacp",
    "active": true,
    "fast_rate": true,
    "tx_hash": ["eth", "ipv4", "ipv6"]
  },
  "link_watch": {"name": "ethtool"},
  "ports": {"eth1": {}, "eth2": {}}
}

Configuration pour la connexion à un homologue compatible LACP.
