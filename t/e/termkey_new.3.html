termkey_new(3)

Paquet: libtermkey

Licences: MIT

TERMKEY_NEW(3) Manuel des fonctions de bibliothèque TERMKEY_NEW(3)

NOM

termkey_new, termkey_destroy - créer ou détruire une nouvelle instance termkey

SYNTAXE

#include <termkey.h>

TERMKEY_CHECK_VERSION;
TermKey *termkey_new(int fd, int flags);
TermKey *termkey_new_abstract(const char *term, int flags);
void termkey_destroy(TermKey *tk);

Lier avec -ltermkey.

DESCRIPTION

termkey_new() crée une nouvelle instance termkey(7) connectée au descripteur de fichier ouvert par fd en utilisant les flags. La structure TermKey doit être considérée comme opaque ; ses contenus ne sont pas destinés à être utilisés en dehors de la bibliothèque.

termkey_new_abstract() crée une nouvelle instance termkey() sans descripteur de fichier associé. Comme cela est généralement fait pour gérer d'autres sources d'entrée d'octets de terminal, elle prend également une chaîne indiquant le type de terminal à utiliser.

termkey_destroy() détruit l'instance donnée et libère toutes les ressources qu'elle contrôle. Elle ne fermera pas le descripteur de fichier sous-jacent donné comme argument fd à termkey_new().

Le constructeur tente de détecter si la locale actuelle est sensible à l'UTF-8 ou non, et définit l'indicateur TERMKEY_FLAG_UTF8 ou TERMKEY_FLAG_RAW. L'un de ces deux bits sera toujours actif. Les indicateurs actuellement actifs peuvent être obtenus par termkey_get_flags(3).

Si un descripteur de fichier est fourni, le pilote terminfo peut envoyer une chaîne pour initialiser ou définir l'état du terminal avant que termkey_new() ne retourne. Cela ne sera pas fait si aucun descripteur de fichier n'est fourni, ou si le descripteur de fichier est un tube (S_ISFIFO()). Dans ce cas, il sera de la responsabilité de l'appelant de s'assurer que le terminal est dans le bon mode. Une fois initialisé, le terminal peut être arrêté par termkey_stop(3), et redémarré par termkey_start(3).

Ce comportement est modifié par l'indicateur TERMKEY_FLAG_NOSTART. Si celui-ci est passé dans l'argument flags, alors l'instance ne sera pas encore démarrée par le constructeur ; l'appelant doit invoquer termkey_start() à un moment futur avant que l'instance ne soit utilisable.

MACRO DE VÉRIFICATION DE VERSION

Avant d'appeler toute fonction de la bibliothèque termkey, une application doit utiliser la macro TERMKEY_CHECK_VERSION pour vérifier que la version chargée de la bibliothèque est compatible avec la version pour laquelle elle a été compilée. Cela devrait être fait tôt, idéalement juste après l'entrée dans sa fonction main().

VALEUR DE RETOUR

En cas de succès, termkey_new() retourne un pointeur vers la nouvelle instance. En cas d'échec, NULL est retourné avec errno défini pour indiquer l'échec. termkey_destroy() ne retourne aucune valeur.

ERREURS

ENOENT
Aucun pilote n'a pu reconnaître le type de terminal donné.
ENOMEM
Un appel à malloc(3) a échoué à allouer de la mémoire.

De plus, termkey_new() peut échouer si fstat(2) ou write(2) échoue sur le descripteur de fichier donné.
