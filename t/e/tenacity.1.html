tenacity(1) Manuel des commandes générales tenacity(1)

NOM

tenacity - Éditeur audio graphique multiplateforme basé sur Audacity

SYNTAXE

tenacity -help
tenacity -version

tenacity [-blocksize nnn] -test
tenacity [-blocksize nnn] [ FICHIER-AUDIO ] ...

DESCRIPTION

Tenacity est un éditeur audio graphique. Cette page de manuel ne décrit pas toutes les fonctionnalités de Tenacity ni la manière de l'utiliser ; pour cela, consultez la documentation html fournie avec le programme, qui devrait être accessible depuis le menu Aide. Cette page de manuel décrit les fonctionnalités spécifiques à Unix, y compris les fichiers spéciaux et les variables d'environnement.

Tenacity utilise actuellement libsndfile pour ouvrir de nombreux formats audio non compressés tels que WAV, AIFF et AU, et il peut également être lié à libmad, libvorbis, et libflac, pour prendre en charge l'ouverture des fichiers MP2/3, Ogg Vorbis et FLAC, respectivement. LAME, libvorbis, libflac et libtwolame fournissent des installations pour exporter des fichiers vers tous ces formats également.

Tenacity est principalement un éditeur interactif et graphique, pas un outil de traitement par lots. Bien qu'il existe un outil de traitement par lots basique, il est expérimental et incomplet. Si vous avez besoin de traiter des fichiers audio par lots ou d'effectuer des modifications simples depuis la ligne de commande, l'utilisation de sox ou ecasound pilotés par un script bash sera beaucoup plus puissante que Tenacity.

HISTORIQUE

En avril 2021, Muse Group (Muse) a annoncé avoir acquis Audacity et continuerait son développement. Plus tard, une nouvelle demande de tirage a été faite pour introduire la télémétrie dans Audacity. Cela a provoqué une controverse, mais la demande de tirage n'a finalement pas été fusionnée. Le plus proche de la télémétrie présent dans les versions modernes d'Audacity n'est que le rapport d'erreurs, où les informations personnelles NE sont PAS collectées.

En juillet 2021, une mise à jour de la politique de confidentialité d'Audacity a suscité la controverse. Il y était indiqué que le programme n'était pas adapté aux enfants de moins de 13 ans. Cela a soulevé une possible violation de la GPL par. De plus, un nouveau Contributor License Agreement a également suscité une nouvelle controverse. Tout cela a déclenché le besoin parmi la communauté d'Audacity de créer des forks. Par conséquent, ce programme, comme d'autres dérivés, a vu le jour afin de résoudre les méfaits commis par les nouveaux propriétaires d'Audacity.

Le 26 novembre 2022, le développement de Tenacity a été officiellement redémarré par Avery King, rejoignant d'autres contributeurs de Tenacity et le principal mainteneur d'Audacium pour continuer le travail sur le projet en vue de leur première version : Tenacity 1.3.

OPTIOS

--help
Affiche une brève liste des options de ligne de commande
--version
Affiche le numéro de version de Tenacity
--test
exécute des tests d'autodiagnostic (présent uniquement dans les versions de développement)
--blocksize nnn
Définit la taille de bloc de Tenacity pour l'écriture de fichiers sur disque à nnn octets

FICHIERS

$XDG_CONFIG_HOME/tenacity/tenacity.cfg

Fichier de configuration par utilisateur.

/var/tmp/tenacity-<utilisateur>/

Emplacement par défaut du répertoire temporaire de Tenacity, où <utilisateur> est votre nom d'utilisateur. Si cet emplacement ne convient pas (par exemple, manque d'espace dans /var/tmp), vous devriez modifier le répertoire temporaire dans les Préférences et redémarrer Tenacity. Tenacity est un éditeur basé sur disque, donc le répertoire temporaire est très important : il doit toujours être sur un disque rapide (local) avec beaucoup d'espace libre.

Sur de nombreux systèmes Linux modernes, tous les fichiers dans /tmp/ seront supprimés à chaque redémarrage du système, ce qui rend beaucoup plus difficile la récupération d'un enregistrement en cours lors d'un crash du système. C'est pourquoi le réglage par défaut est d'utiliser un répertoire dans /var/tmp/ qui ne sera normalement pas supprimé par le système. Ouvrez les Préférences pour vérifier.

CHEMIN DE RECHERCHE

Lors de la recherche de plug-ins, de fichiers d'aide, de fichiers de localisation ou d'autres fichiers de configuration, Tenacity recherche les emplacements suivants, dans cet ordre :

TENACITY_PATH

Tous les répertoires dans la variable d'environnement TENACITY_PATH seront recherchés avant tout autre endroit.

.

Le répertoire de travail actuel lorsque Tenacity est démarré.

<prefix>/share/tenacity

Le répertoire Tenacity à l'échelle du système, où <prefix> est généralement /usr ou /usr/local, selon l'endroit où le programme a été installé.

<prefix>/share/doc/tenacity

Le répertoire de documentation Tenacity à l'échelle du système, où <prefix> est généralement /usr ou /usr/local, selon l'endroit où le programme a été installé.

Pour les fichiers de localisation en particulier (c'est-à-dire les traductions de Tenacity dans d'autres langues), Tenacity recherche également <prefix>/share/locale

PLUG-INS

Tenacity prend en charge deux types de plug-ins sous Unix : les plug-ins LADSPA et Nyquist. Ceux-ci sont généralement placés dans un répertoire appelé plug-ins quelque part sur le chemin de recherche (voir ci-dessus).

Les plug-ins LADSPA peuvent être soit dans le répertoire des plug-ins, soit dans un répertoire ladspa sur le chemin de recherche si vous choisissez d'en créer un. Tenacity recherchera également les répertoires dans la variable d'environnement LADSPA_PATH pour des plug-ins LADSPA supplémentaires.

Les plug-ins Nyquist peuvent être soit dans le répertoire des plug-ins, soit dans un répertoire nyquist sur le chemin de recherche si vous choisissez d'en créer un.

NOM

tenacity - Une bibliothèque Python pour la gestion de la résilience

SYNOPSIS

tenacity est une bibliothèque Python qui vous aide à gérer la façon dont vos programmes réagissent aux échecs en injectant des stratégies de résilience dans vos fonctions.

DESCRIPTION

La bibliothèque tenacity permet aux développeurs d'ajouter facilement des mécanismes de nouvelle tentative (retry) et de circuit breaker à leurs applications Python. Elle fournit une manière déclarative d'ajouter ces comportements, souvent grâce à des décorateurs.

Elle est particulièrement utile dans les scénarios où une fonction peut échouer temporairement en raison de problèmes réseau, de ressources indisponibles ou d'autres conditions transitoires. tenacity permet de configurer :

  • Le nombre de nouvelles tentatives.
  • Le délai entre les nouvelles tentatives (avec exponentielle, délai fixe, etc.).
  • Les exceptions qui doivent déclencher une nouvelle tentative.
  • Des actions à exécuter avant ou après une nouvelle tentative (par exemple, journalisation).
  • La gestion des circuits ouverts (circuit breaker) pour éviter de surcharger un service défaillant.

OPTIONS

tenacity est principalement utilisée comme une bibliothèque en Python et n'a pas d'options en ligne de commande directes. Ses options sont configurées via l'API Python, généralement lors de la définition de stratégies de résilience.

EXEMPLES

Exemple d'utilisation d'un décorateur de nouvelle tentative :

from tenacity import retry, wait_fixed, stop_after_attempt

@retry(wait=wait_fixed(1), stop=stop_after_attempt(3))
def ma_fonction_qui_peut_echouer():
    print("Tentative de connexion...")
    # Simule une erreur aléatoire
    if random.random() < 0.7:
        raise ConnectionError("Erreur de connexion")
    print("Connexion réussie !")
    return "Succès"

ma_fonction_qui_peut_echouer()

FICHIERS

Aucun fichier spécifique à mentionner, sauf si tenacity est utilisé pour interagir avec des fichiers configurés par l'utilisateur.

CHEMIN DE RECHERCHE

tenacity est une bibliothèque Python, donc son "chemin de recherche" est déterminé par le système de modules Python (sys.path).

PLUGINS

Il n'y a pas de système de plugins formellement défini dans tenacity, mais sa conception modulaire permet d'étendre ses fonctionnalités ou d'intégrer des stratégies personnalisées.
