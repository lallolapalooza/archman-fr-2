NOM

termscu - SCU de terminaison DICOM

SYNTAXE

termscu [options] peer port

DESCRIPTION

L'application termscu implémente un utilisateur de classe de service (SCU) pour la classe SOP de fermeture privée de DCMTK. Elle tente de négocier cette classe SOP de fermeture privée avec un fournisseur de classe de service (SCP) qui (si cette fonctionnalité est implémentée) s'arrêtera immédiatement après avoir refusé l'association. L'application peut être utilisée pour arrêter certaines des applications serveur de DCMTK.

PARAMETRES

peer  nom d'hôte du pair DICOM
port  numéro de port TCP/IP du pair

OPTIONS

options générales

  -h    --help
          affiche ce message d'aide et quitte
        --version
          affiche les informations de version et quitte
        --arguments
          affiche les arguments étendus de la ligne de commande
  -q    --quiet
          mode silencieux, n'affiche aucun avertissement ni erreur
  -v    --verbose
          mode verbeux, affiche les détails du traitement
  -d    --debug
          mode de débogage, affiche les informations de débogage
  -ll   --log-level  [n]iveau : chaîne de caractères
          (fatal, error, warn, info, debug, trace)
          utilise le niveau n pour le logger
  -lc   --log-config  [f]ichier : chaîne de caractères
          utilise le fichier de configuration f pour le logger

options réseau

version du protocole IP :
  -i4   --ipv4
          utilise uniquement IPv4 (par défaut)
  -i6   --ipv6
          utilise uniquement IPv6
  -i0   --ip-auto
          utilise la recherche DNS pour déterminer le protocole IP
titres des entités applicatives :
  -aet  --aetitle  [t]itre_ea : chaîne de caractères
          définit mon titre EA appelant (par défaut: ECHOSCU)
  -aec  --call  [t]itre_ea : chaîne de caractères
          définit le titre EA appelé du pair (par défaut: ANY-SCP)
autres options réseau :
  -pdu  --max-pdu  [n]ombre d'octets : entier (4096..131072)
          définit le PDU de réception maximum à n octets (par défaut: 16384)

NOTES

Conformité DICOM

L'application termscu prend en charge les classes SOP suivantes en tant que SCU :

PrivateShutdownSOPClass  1.2.276.0.7230010.3.4.1915765545.18030.917282194.0

JOURNAUX

Le niveau de sortie des journaux des différents outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seuls les erreurs et les avertissements sont écrits dans le flux d'erreur standard. L'utilisation de l'option --verbose permet également de signaler des messages informatifs tels que les détails du traitement. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seuls les erreurs fatales sont signalées. Dans de tels événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, consultez la documentation du module "oflog".

Dans le cas où la sortie des journaux doit être écrite dans un fichier (éventuellement avec rotation des fichiers journaux), vers syslog (Unix) ou le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets indiquent les valeurs optionnelles (0-1), trois points indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' respectivement. Généralement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, l'apparition la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés à l'aide d'un signe '@' comme préfixe du nom de fichier (par exemple, @command.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (les espaces multiples sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer les combinaisons courantes d'options/paramètres et évite les lignes de commande trop longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

ENVIRONNEMENT

L'utilitaire termscu tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé, sauf si le dictionnaire est intégré à l'application (par défaut pour Windows).

Le comportement par défaut doit être privilégié et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH du shell Unix, c'est-à-dire qu'un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. Une erreur se produira si aucun dictionnaire de données ne peut être chargé.
