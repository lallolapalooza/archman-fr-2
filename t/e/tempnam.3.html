tempnam(3) Manuel des fonctions de bibliothèque tempnam(3)

NOM

tempnam - créer un nom pour un fichier temporaire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <stdio.h>
char *tempnam(const char *dir, const char *pfx);
Exigences des macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

tempnam() :

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    glibc 2.19 et versions antérieures :
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

N'utilisez jamais cette fonction. Utilisez plutôt mkstemp(3) ou tmpfile(3).

La fonction tempnam() renvoie un pointeur vers une chaîne qui est un nom de fichier valide, et tel qu'un fichier avec ce nom n'existait pas lorsque tempnam() l'a vérifié. Le suffixe du nom de fichier du chemin généré commencera par pfx si pfx est une chaîne non NULL d'au plus cinq octets. La partie préfixe du répertoire du chemin généré doit être « appropriée » (souvent cela implique au moins la possibilité d'écrire).

Les tentatives pour trouver un répertoire approprié suivent les étapes suivantes :

(1)
Si la variable d'environnement TMPDIR existe et contient le nom d'un répertoire approprié, celui-ci est utilisé.
(2)
Sinon, si l'argument dir n'est pas NULL et est approprié, il est utilisé.
(3)
Sinon, P_tmpdir (tel que défini dans <stdio.h>) est utilisé lorsqu'il est approprié.
(4)
Enfin, un répertoire défini par l'implémentation peut être utilisé.

La chaîne renvoyée par tempnam() est allouée en utilisant malloc(3) et doit donc être libérée par free(3).

VALEUR DE RETOUR

En cas de succès, la fonction tempnam() renvoie un pointeur vers un nom de fichier temporaire unique. Elle renvoie NULL si un nom unique ne peut pas être généré, avec errno défini pour indiquer l'erreur.

ERREURS

ENOMEM
Échec de l'allocation de stockage.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
tempnam () Sécurité des threads MT-Safe env

NORMES

POSIX.1-2008.

HISTORIQUE

SVr4, 4.3BSD, POSIX.1-2001. Obsolète dans POSIX.1-2008.

NOTES

Bien que tempnam() génère des noms difficiles à deviner, il est néanmoins possible qu'entre le moment où tempnam() renvoie un nom de fichier et le moment où le programme l'ouvre, un autre programme puisse créer ce nom de fichier en utilisant open(2), ou le créer comme un lien symbolique. Cela peut entraîner des failles de sécurité. Pour éviter de telles possibilités, utilisez le drapeau O_EXCL de open(2) pour ouvrir le nom de fichier. Ou mieux encore, utilisez mkstemp(3) ou tmpfile(3).

SUSv2 ne mentionne pas l'utilisation de TMPDIR ; glibc l'utilisera uniquement lorsque le programme n'est pas set-user-ID. Sur SVr4, le répertoire utilisé sous (4) est /tmp (et c'est ce que fait glibc).

Parce qu'elle alloue dynamiquement de la mémoire utilisée pour renvoyer le nom de fichier, tempnam() est réentrante, et donc thread safe, contrairement à tmpnam(3).

La fonction tempnam() génère une chaîne différente à chaque appel, jusqu'à TMP_MAX (défini dans <stdio.h>) fois. Si elle est appelée plus de TMP_MAX fois, le comportement est défini par l'implémentation.

tempnam() utilise au plus les cinq premiers octets de pfx.

L'implémentation glibc de tempnam() échoue avec l'erreur EEXIST en cas d'échec à trouver un nom unique.

BOGUES

La signification précise de « approprié » n'est pas définie ; il n'est pas spécifié comment l'accessibilité d'un répertoire est déterminée.

VOIR AUSSI

mkstemp(3), mktemp(3), tmpfile(3), tmpnam(3)
