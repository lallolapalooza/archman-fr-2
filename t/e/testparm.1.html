TESTPARM(1) Commandes utilisateur TESTPARM(1)

NOM

testparm - vérifie un fichier de configuration smb.conf pour l'exactitude interne

SYNTAXE

testparm [-s|--suppress-prompt] [-v|--verbose] [-?|--help] [--usage] [-d|--debuglevel=DEBUGLEVEL] [--debug-stdout] {nom_fichier_config } [nom_hote IP_hote]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

testparm est un programme de test très simple pour vérifier l'exactitude interne d'un fichier de configuration smbd(8). Si ce programme ne rapporte aucun problème, vous pouvez utiliser le fichier de configuration en toute confiance que smbd chargera correctement le fichier de configuration.

Notez que ce n'est PAS une garantie que les services spécifiés dans le fichier de configuration seront disponibles ou fonctionneront comme prévu.

Si le nom d'hôte et l'adresse IP optionnels sont spécifiés sur la ligne de commande, ce programme de test parcourra les entrées de service en rapportant si l'hôte spécifié a accès à chaque service.

Si testparm trouve une erreur dans le fichier smb.conf, il renvoie un code de sortie de 1 au programme appelant, sinon il renvoie un code de sortie de 0. Cela permet aux scripts shell de tester la sortie de testparm.

OPTIONS

-s|--suppress-prompt

Sans cette option, testparm demandera une pression sur la touche retour après avoir affiché les noms des services et avant de décharger les définitions de service.

-v|--verbose

Si cette option est spécifiée, testparm affichera également toutes les options qui n'ont pas été utilisées dans smb.conf(5) et sont donc définies à leurs valeurs par défaut.

--parameter-name nom_parametre

Affiche le paramètre nommé. Si aucun nom_section n'est défini, la vue est limitée par défaut à la section globale. Il est également possible d'afficher une option paramétrique. Pour ce faire, l'option doit être séparée par un deux-points du nom_parametre.

--section-name nom_section

Affiche la section nommée.

--show-all-parameters

Affiche les paramètres, le type, les valeurs possibles.

-l|--skip-logic-checks

Ignore les vérifications logiques globales.

-?|--help

Affiche un résumé des options de ligne de commande.

--usage

Affiche un bref message d'utilisation.

-d|--debuglevel=niveau

niveau est un entier de 0 à 10. La valeur par défaut si ce paramètre n'est pas spécifié est 1 pour les applications client.

Plus cette valeur est élevée, plus les informations détaillées seront enregistrées dans les fichiers journaux sur les activités du serveur. Au niveau 0, seuls les erreurs critiques et les avertissements sérieux seront enregistrés. Le niveau 1 est un niveau raisonnable pour une utilisation quotidienne - il génère une petite quantité d'informations sur les opérations effectuées.

Les niveaux supérieurs à 1 généreront une quantité considérable de données de journal, et ne devraient être utilisés que lors de l'investigation d'un problème. Les niveaux supérieurs à 3 sont conçus pour être utilisés uniquement par les développeurs et génèrent d'énormes quantités de données de journal, dont la plupart sont extrêmement cryptiques.

Notez que la spécification de ce paramètre ici remplacera le paramètre log level du fichier /etc/samba/smb.conf.

--debug-stdout

Redirigera la sortie de débogage vers STDOUT. Par défaut, tous les clients enregistrent sur STDERR.

--configfile=<fichier de configuration>

Le fichier spécifié contient les détails de configuration requis par le client. Les informations de ce fichier peuvent être générales pour le client et le serveur ou fournir uniquement des options spécifiques au client telles que client smb encrypt. Voir /etc/samba/smb.conf pour plus d'informations. Le nom du fichier de configuration par défaut est déterminé lors de la compilation.

--option=<nom>=<valeur>

Définit l'option smb.conf(5) "<nom>" à la valeur "<valeur>" à partir de la ligne de commande. Ceci remplace les valeurs par défaut compilées et les options lues dans le fichier de configuration. Si un nom ou une valeur inclut un espace, entourez tout --option=nom=valeur de guillemets.

-V|--version

Affiche le numéro de version du programme.

nom_fichier_config

C'est le nom du fichier de configuration à vérifier. Si ce paramètre n'est pas présent, le fichier smb.conf(5) par défaut sera vérifié.

nom_hote

Si ce paramètre et le suivant sont spécifiés, alors testparm examinera les paramètres hosts allow et hosts deny dans le fichier smb.conf(5) pour déterminer si le nom d'hôte avec cette adresse IP serait autorisé à accéder au serveur smbd. Si ce paramètre est fourni, le paramètre IP_hote doit également être fourni.

IP_hote

C'est l'adresse IP de l'hôte spécifié dans le paramètre précédent. Cette adresse doit être fournie si le paramètre nom_hote est fourni.

FICHIERS

smb.conf(5)

C'est généralement le nom du fichier de configuration utilisé par smbd(8).

DIAGNOSTICS

Le programme affichera un message indiquant si le fichier de configuration s'est chargé correctement ou non. Ce message peut être précédé d'erreurs et d'avertissements si le fichier ne s'est pas chargé. Si le fichier s'est chargé correctement, le programme décharge ensuite tous les détails de service connus vers la sortie standard.

Pour certains cas d'utilisation, le protocole SMB nécessite l'utilisation d'algorithmes cryptographiques connus pour être faibles et déjà cassés. Les chiffrements DES et ARCFOUR (RC4) ainsi que les algorithmes de hachage SHA1 et MD5 sont considérés comme faibles mais sont requis pour des raisons de compatibilité descendante. L'utilitaire testparm indique si les outils Samba régresseront vers ces algorithmes cryptographiques faibles s'il n'est pas possible d'utiliser la cryptographie forte par défaut. En mode FIPS, la cryptographie faible ne peut pas être activée.
