TESSERACT(1)   TESSERACT(1)

NOM

tesseract - moteur OCR en ligne de commande

SYNTAXE

tesseract FICHIER BASENAME_SORTIE [OPTIONS]... [FICHIER_CONFIG]...

DESCRIPTION

tesseract(1) est un moteur OCR de qualité commerciale développé à l'origine chez HP entre 1985 et 1995. En 1995, ce moteur figurait parmi les 3 meilleurs évalués par UNLV. Il a été rendu open-source par HP et UNLV en 2005, et a été développé chez Google jusqu'en 2018.

ARGUMENTS D'ENTRÉE/SORTIE

FICHIER

Le nom du fichier d'entrée. Il peut s'agir d'un fichier image ou d'un fichier texte.

La plupart des formats de fichiers image (tout ce qui est lisible par Leptonica) sont supportés.

Un fichier texte liste les noms de toutes les images d'entrée (un nom d'image par ligne). Les résultats seront combinés en un seul fichier pour chaque format de fichier de sortie (txt, pdf, hocr, xml).

Si FICHIER est stdin ou -, l'entrée standard est utilisée.

BASENAME_SORTIE

Le nom de base du fichier de sortie (auquel l'extension appropriée sera ajoutée). Par défaut, la sortie sera un fichier texte avec .txt ajouté au nom de base, sauf si un ou plusieurs paramètres sont définis qui spécifient explicitement la sortie souhaitée.

Si BASENAME_SORTIE est stdout ou -, la sortie standard est utilisée.

OPTIONS

-c CONFIGVAR=VALEUR

Définit la valeur du paramètre CONFIGVAR à VALEUR. Plusieurs arguments -c sont autorisés.

--dpi N

Spécifie la résolution N en DPI pour l'image (les images) d'entrée. Une valeur typique pour N est 300. Sans cette option, la résolution est lue à partir des métadonnées incluses dans l'image. Si une image n'inclut pas ces informations, Tesseract essaie de les deviner.

-l LANGUE, -l SCRIPT

La langue ou le script à utiliser. Si aucun n'est spécifié, 'eng' (anglais) est supposé. Plusieurs langues peuvent être spécifiées, séparées par des signes plus. Tesseract utilise des codes de langue ISO 639-2 à 3 caractères (voir LANGUES ET SCRIPTS).

--psm N

Configure Tesseract pour exécuter uniquement un sous-ensemble de l'analyse de la mise en page et supposer une certaine forme d'image. Les options pour N sont : 
0 = Détection d'orientation et de script (OSD) uniquement.
1 = Segmentation automatique de la page avec OSD.
2 = Segmentation automatique de la page, mais sans OSD, ni OCR. (non implémenté)
3 = Segmentation entièrement automatique de la page, mais sans OSD. (Défaut)
4 = Supposer une seule colonne de texte de tailles variables.
5 = Supposer un seul bloc uniforme de texte aligné verticalement.
6 = Supposer un seul bloc uniforme de texte.
7 = Traiter l'image comme une seule ligne de texte.
8 = Traiter l'image comme un seul mot.
9 = Traiter l'image comme un seul mot dans un cercle.
10 = Traiter l'image comme un seul caractère.
11 = Texte épars. Trouver autant de texte que possible sans ordre particulier.
12 = Texte épars avec OSD.
13 = Ligne brute. Traiter l'image comme une seule ligne de texte,
     en contournant les astuces spécifiques à Tesseract.

--oem N

Spécifie le mode du moteur OCR. Les options pour N sont : 
0 = Tesseract original uniquement.
1 = LSTM neuronal uniquement.
2 = Tesseract + LSTM.
3 = Défaut, basé sur ce qui est disponible.

--tessdata-dir CHEMIN

Spécifie l'emplacement du chemin tessdata.

--user-patterns FICHIER

Spécifie l'emplacement du fichier de motifs utilisateur.

--user-words FICHIER

Spécifie l'emplacement du fichier de mots utilisateur.

FICHIER_CONFIG

Le nom d'une configuration à utiliser. Le nom peut être un fichier dans tessdata/configs ou tessdata/tessconfigs, ou un chemin de fichier absolu ou relatif. Une configuration est un fichier texte brut qui contient une liste de paramètres et leurs valeurs, un par ligne, avec un espace séparant le paramètre de la valeur.

Les fichiers de configuration intéressants incluent :

•alto — Sortie au format ALTO (BASENAME_SORTIE.xml).
•hocr — Sortie au format hOCR (BASENAME_SORTIE.hocr).
•page — Sortie au format PAGE (BASENAME_SORTIE.page.xml). La sortie peut être personnalisée avec les indicateurs : page_xml_polygon — Créer des polygones au lieu de boîtes englobantes (défaut : vrai) page_xml_level — Créer le fichier PAGE au niveau 0=ligne ou 1=mot (défaut : 0)
•pdf — Sortie PDF (BASENAME_SORTIE.pdf).
•tsv — Sortie TSV (BASENAME_SORTIE.tsv).
•txt — Sortie texte brut (BASENAME_SORTIE.txt).
•get.images — Écrit les images d'entrée traitées dans un fichier (BASENAME_SORTIE.processedPAGENUMBER.tif).
•logfile — Redirige les messages de débogage vers un fichier (tesseract.log).
•lstm.train — Fichiers de sortie utilisés par l'entraînement LSTM (BASENAME_SORTIE.lstmf).
•makebox — Écrit un fichier box (BASENAME_SORTIE.box).
•quiet — Redirige les messages de débogage vers /dev/null.

Il est possible de sélectionner plusieurs fichiers de configuration, par exemple tesseract image.png demo alto hocr pdf txt créera quatre fichiers de sortie demo.alto, demo.hocr, demo.pdf et demo.txt avec les résultats OCR.

Attention : Les options -l LANGUE, -l SCRIPT et --psm N doivent apparaître avant tout FICHIER_CONFIG.

OPTIONS UNIQUES

-h, --help

Affiche le message d'aide.

--help-extra

Affiche l'aide supplémentaire pour les utilisateurs avancés.

--help-psm

Affiche les modes de segmentation de page.

--help-oem

Affiche les modes du moteur OCR.

-v, --version

Retourne la version actuelle de l'exécutable tesseract(1).

--list-langs

Liste les langues disponibles pour le moteur tesseract. Peut être utilisé avec --tessdata-dir CHEMIN.

--print-parameters

Imprime les paramètres de tesseract.

LANGUES ET SCRIPTS

Pour reconnaître du texte avec Tesseract, il est normalement nécessaire de spécifier la (les) langue(s) ou le (les) script(s) du texte (sauf s'il s'agit de texte anglais qui est supporté par défaut) en utilisant -l LANGUE ou -l SCRIPT.

La sélection d'une langue sélectionne automatiquement également le jeu de caractères et le dictionnaire spécifiques à cette langue (liste de mots).

La sélection d'un script sélectionne généralement tous les caractères de ce script qui peuvent provenir de différentes langues. Le dictionnaire inclus contient également un mélange de différentes langues. Dans la plupart des cas, un script prend également en charge l'anglais. Il est donc possible de reconnaître une langue pour laquelle aucun entraînement spécifique n'a été effectué en utilisant les données entraînées pour le script dans lequel elle est écrite.

Plusieurs langues ou scripts peuvent être spécifiés en utilisant +. Exemple : tesseract myimage.png myimage -l eng+deu+fra.

https://github.com/tesseract-ocr/tessdata_fast fournit des modèles linguistiques et script rapide qui font également partie des distributions Linux.

FICHIERS DE CONFIGURATION ET AUGMENTATION AVEC DES DONNÉES UTILISATEUR

Les fichiers de configuration Tesseract consistent en des lignes avec des paires paramètre-valeur (séparées par des espaces). Les paramètres sont documentés comme des indicateurs dans le code source, comme celui-ci dans tesseractclass.h :

STRING_VAR_H(tessedit_char_blacklist, "", "Liste noire des caractères à ne pas reconnaître");

Ces paramètres peuvent activer ou désactiver diverses fonctionnalités du moteur, et peuvent provoquer le chargement (ou non) de diverses données. Par exemple, supposons que vous souhaitiez faire de l'OCR en anglais, mais supprimer le dictionnaire normal et charger une liste de mots alternative et une liste de motifs alternative - ces deux fichiers sont les fichiers de données supplémentaires les plus couramment utilisés.

Si votre pack linguistique se trouve dans /chemin/vers/eng.traineddata et la configuration hocr dans /chemin/vers/configs/hocr, créez alors trois nouveaux fichiers :

/chemin/vers/eng.user-words :

the
quick
brown
fox
jumped

/chemin/vers/eng.user-patterns :

1-\d\d\d-GOOG-411
www.\n\\\*.com

/chemin/vers/configs/bazaar :

load_system_dawg     F
load_freq_dawg       F
user_words_suffix    user-words
user_patterns_suffix user-patterns

Maintenant, si vous passez le mot bazaar comme CONFIGFILE à Tesseract, Tesseract ne se souciera pas de charger le dictionnaire système ni le dictionnaire des mots fréquents et chargera et utilisera les fichiers eng.user-words et eng.user-patterns que vous avez fournis. Le premier est une simple liste de mots, un par ligne. Le format du second est documenté dans dict/trie.h sur read_pattern_list().

VARIABLES D'ENVIRONNEMENT

TESSDATA_PREFIX

Si TESSDATA_PREFIX est défini sur un chemin, alors ce chemin est utilisé pour trouver le répertoire tessdata avec les modèles de reconnaissance de langue et de script et les fichiers de configuration. L'utilisation de --tessdata-dir CHEMIN est l'alternative recommandée.

OMP_THREAD_LIMIT

Si l'exécutable tesseract a été compilé avec le support du multithreading, il utilisera normalement quatre cœurs CPU pour le processus OCR. Bien que cela puisse être plus rapide pour une seule image, cela donne de mauvaises performances si l'ordinateur hôte fournit moins de quatre cœurs CPU ou si l'OCR est effectuée pour de nombreuses images. Un seul cœur CPU est utilisé avec OMP_THREAD_LIMIT=1.

HISTORIQUE

Le moteur a été développé chez Hewlett Packard Laboratories Bristol et chez Hewlett Packard Co, Greeley Colorado entre 1985 et 1994, avec quelques modifications supplémentaires apportées en 1996 pour le portage sous Windows, et quelques adaptations C++ en 1998. Une grande partie du code a été écrite en C, puis une autre partie en C++. Le code C++ utilise intensivement un système de listes à l'aide de macros. Cela est antérieur à STL, était portable avant STL, et est plus efficace que les listes STL, mais présente le gros inconvénient que si vous obtenez une violation de segmentation, il est difficile de la déboguer.

La version 2.00 a apporté le support Unicode (UTF-8), six langues, et la capacité d'entraîner Tesseract.

Tesseract a été inclus dans le Quatrième Test Annuel de Précision OCR de l'UNLV. Voir https://github.com/tesseract-ocr/docs/blob/main/AT-1995.pdf. Depuis Tesseract 2.00, des scripts sont inclus pour permettre à quiconque de reproduire certains de ces tests. Voir https://tesseract-ocr.github.io/tessdoc/TestingTesseract.html pour plus de détails.

Tesseract 3.00 a ajouté un certain nombre de nouvelles langues, dont le chinois, le japonais et le coréen. Il a également introduit un nouveau système de gestion des données linguistiques en un seul fichier.

Tesseract 3.02 a ajouté la prise en charge du texte bidirectionnel, la capacité de reconnaître plusieurs langues dans une seule image et une meilleure analyse de la mise en page.

Tesseract 4 ajoute un nouveau moteur OCR basé sur les réseaux neuronaux (LSTM) qui est axé sur la reconnaissance de lignes, mais prend également en charge le moteur OCR hérité Tesseract 3 qui fonctionne en reconnaissant des motifs de caractères. La compatibilité avec Tesseract 3 est activée par --oem 0. Cela nécessite également des fichiers traineddata qui prennent en charge le moteur hérité, par exemple ceux du dépôt tessdata (https://github.com/tesseract-ocr/tessdata).

Pour plus de détails, voir les notes de version dans la documentation de Tesseract (https://tesseract-ocr.github.io/tessdoc/ReleaseNotes.html).
