NOM

tep_data_type, tep_data_pid, tep_data_preempt_count, tep_data_flags - Extraire les champs communs d'un enregistrement.

SYNOPSIS

#include <event-parse.h>
enum trace_flag_type {
        TRACE_FLAG_IRQS_OFF,
        TRACE_FLAG_IRQS_NOSUPPORT,
        TRACE_FLAG_NEED_RESCHED,
        TRACE_FLAG_HARDIRQ,
        TRACE_FLAG_SOFTIRQ,
};
int tep_data_type(struct tep_handle *tep, struct tep_record *rec);
int tep_data_pid(struct tep_handle *tep, struct tep_record *rec);
int tep_data_preempt_count(struct tep_handle *tep, struct tep_record *rec);
int tep_data_flags(struct tep_handle *tep, struct tep_record *rec);

DESCRIPTION

Cet ensemble de fonctions peut être utilisé pour extraire les champs communs d'un enregistrement.

La fonction tep_data_type() obtient l'identifiant de l'événement à partir de l'enregistrement rec. Elle lit le champ "common_type". L'argument tep est le contexte d'analyse des événements de trace.

La fonction tep_data_pid() obtient l'identifiant du processus à partir de l'enregistrement rec. Elle lit le champ "common_pid". L'argument tep est le contexte d'analyse des événements de trace.

La fonction tep_data_preempt_count() obtient le compteur de préemption à partir de l'enregistrement rec. Elle lit le champ "common_preempt_count". L'argument tep est le contexte d'analyse des événements de trace.

La fonction tep_data_flags() obtient les drapeaux de latence à partir de l'enregistrement rec. Elle lit le champ "common_flags". L'argument tep est le contexte d'analyse des événements de trace. Les drapeaux de latence pris en charge sont :

        TRACE_FLAG_IRQS_OFF,          Interrupts désactivés.
        TRACE_FLAG_IRQS_NOSUPPORT,    La lecture du drapeau IRQ n'est pas prise en charge par l'architecture.
        TRACE_FLAG_NEED_RESCHED,      La tâche doit être replanifiée.
        TRACE_FLAG_HARDIRQ,           IRQ matériel en cours d'exécution.
        TRACE_FLAG_SOFTIRQ,           IRQ logiciel en cours d'exécution.

VALEUR DE RETOUR

La fonction tep_data_type() retourne un entier, représentant l'identifiant de l'événement.

La fonction tep_data_pid() retourne un entier, représentant l'identifiant du processus.

La fonction tep_data_preempt_count() retourne un entier, représentant le compteur de préemption.

La fonction tep_data_flags() retourne un entier, représentant les drapeaux de latence. Consultez l'énumération trace_flag_type pour les drapeaux pris en charge.

Toutes ces fonctions retournent un entier négatif en cas d'erreur.

EXEMPLE

#include <event-parse.h>
...
struct tep_handle *tep = tep_alloc();
...
void process_record(struct tep_record *record)
{
        int data;
        data = tep_data_type(tep, record);
        if (data >= 0) {
                /* Got the ID of the event */
        }
        data = tep_data_pid(tep, record);
        if (data >= 0) {
                /* Got the process ID */
        }
        data = tep_data_preempt_count(tep, record);
        if (data >= 0) {
                /* Got the preemption count */
        }
        data = tep_data_flags(tep, record);
        if (data >= 0) {
                /* Got the latency flags */
        }
}
...
