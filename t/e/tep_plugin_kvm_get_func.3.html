NOM

tep_plugin_kvm_get_func, tep_plugin_kvm_put_func - Ajouter le nom de la fonction pour le pointeur d'instruction du plugin kvm

SYNTAXE

#include <event-parse.h>
const char *tep_plugin_kvm_get_func(struct tep_event *event,
                                    struct tep_record *record,
                                    unsigned long long *paddr);
void tep_plugin_kvm_put_func(const char *func);

DESCRIPTION

Les fonctions tep_plugin_kvm_get_func() et tep_plugin_kvm_put_func() ne doivent pas être appelées par une application, mais plutôt définies par une application.

Certains événements (comme kvm_exit et kvm_entry) contiennent le pointeur d'instruction de l'endroit dans l'invité où le contexte est passé de l'invité à l'hôte. Comme l'hôte ne connaît que le pointeur d'instruction et n'a pas d'informations sur la fonction de l'invité à laquelle appartient ce pointeur d'instruction, il ne peut imprimer que l'adresse.

Cependant, l'application peut avoir plus d'informations sur l'invité, et savoir où se trouvait l'invité lorsque la sortie s'est produite, et même connaître le nom de la fonction de cette adresse.

Le plugin KVM pour libtraceevent est appelé sur ces événements, puis appelle tep_plugin_kvm_get_func() pour voir si cette fonction peut résoudre l'adresse du pointeur d'instruction en un nom de fonction réel. Si le retour n'est pas NULL, il imprimera la fonction dans la sortie pour cet événement.

Ces fonctions sont actuellement définies comme des fonctions faibles au sein du plugin, afin de ne pas nécessiter qu'elles soient définies ailleurs. Pour qu'une application remplace la fonction faible, elle devra définir la fonction dans un fichier qui est compilé avec -rdynamic. Cela indiquera au lieur dynamique d'examiner ce fichier objet et d'utiliser les noms de fonctions pour résoudre les fonctions faibles dans d'autres objets partagés (dans ce cas, l'objet partagé du plugin KVM).

Si l'application définit tep_plugin_kvm_get_func(), elle doit utiliser le prototype ci-dessus. L'event contiendra l'événement KVM qui a le champ pointeur d'instruction. Le record sera l'instance de cet événement. La fonction de l'application n'a pas besoin d'utiliser ces paramètres, mais ils peuvent être utiles pour trouver le nom de la fonction pour l'adresse. Le paddr est un pointeur vers une valeur 64 bits (où seuls 32 bits peuvent être utilisés sur des machines 32 bits). Cette valeur est le pointeur d'instruction à rechercher. Si l'application connaît également l'adresse de début de la fonction, elle peut définir paddr à cette adresse, et le plugin KVM ajoutera également un "+offset" au nom de la fonction où l'offset est la valeur d'origine dans paddr moins la valeur dans paddr lorsqu'elle est appelée. Enfin, l'application doit retourner le nom de la fonction sous forme de chaîne terminée par un nul si elle en trouve une.

Si la chaîne retournée par tep_plugin_kvm_get_func() a été allouée, le plugin KVM appellera tep_plugin_kvm_put_func() lorsqu'il aura terminé, en passant la valeur retournée par tep_plugin_kvm_get_func() comme func. Cela permet à l'application de la libérer si nécessaire.

VALEUR DE RETOUR

La fonction tep_plugin_kvm_get_func() ne doit pas être appelée par l'application mais plutôt définie par l'application. Elle doit retourner une chaîne terminée par un nul représentant la fonction pour le pointeur d'instruction donné qui lui est passé par référence dans paddr. Elle peut alors éventuellement mettre à jour paddr avec une valeur qui contient le début de la fonction. La chaîne retournée peut être libérée par tep_plugin_kvm_put_func() que l'application doit définir pour nettoyer la chaîne.

L'exemple ci-dessous doit être compilé avec le drapeau -rdynamic afin que le lieur dynamique puisse résoudre les fonctions tep_plugin_kvm_get_func() et tep_plugin_kvm_put_func().

Lors de l'exécution sur un fichier trace.dat produit par trace-cmd(1) enregistrant les événements kvm_exit et kvm_entry sur un invité, puis que le fichier /proc/kallsyms de l'invité est passé comme deuxième paramètre, la sortie produite ressemblera à ceci :

CPU 0/KVM-20407 83156.177626 [000] kvm_exit     reason APIC_ACCESS rip 0xffffffffb0056ee2 exit native_apic_mem_write+0x2 info 10b0 0
CPU 0/KVM-20407 83156.177632 [000] kvm_entry     vcpu 0 rip 0xffffffffb0056ee8 enter native_apic_mem_write+0x8

Mais sans ces rappels de fonction, cela ressemblerait à ceci :

CPU 0/KVM-20407 83156.177626 [000] kvm_exit     reason APIC_ACCESS rip 0xffffffffb0056ee2 info 10b0 0
CPU 0/KVM-20407 83156.177632 [000] kvm_entry     vcpu 0 rip 0xffffffffb0056ee8

EXEMPLE

#include <stdio.h>
#include <stdlib.h>
#include <event-parse.h>
#include <trace-cmd.h>
#include <sys/stat.h>
static struct tep_handle *tep;
const char *tep_plugin_kvm_get_func(struct tep_event *event, struct tep_record *record,
                                    unsigned long long *paddr)
{
        const char *func;
        char *event_func;
        char *ename;
        func = tep_find_function(tep, *paddr);
        if (!func)
                return NULL;
        if (strcmp(event->name, "kvm_exit") == 0)
                ename = "exit";
        else
                ename = "enter";
        /*
         * Normalement, retourner directement func est suffisant et alors
         * tep_plugin_kvm_put_func() ne serait pas requis. Mais cet exemple
         * montre comment gérer l'allocation de la chaîne retournée.
         */
        event_func = malloc(strlen(ename) + strlen(func) + 2);
        if (!event_func)
                return NULL;
        sprintf(event_func, "%s %s", ename, func);
        *paddr = tep_find_function_address(tep, *paddr);
        return event_func;
}
void tep_plugin_kvm_put_func(const char *func)
{
        char *f = (char *)func;
        free(f);
}
static int show_event(struct tracecmd_input *handle, struct tep_event *event,
                      struct tep_record *record, int cpu, void *data)
{
        static struct trace_seq seq;
        tep = data;
        if (!seq.buffer)
                trace_seq_init(&seq);
        trace_seq_reset(&seq);
        tep_print_event(tracecmd_get_tep(handle), &seq, record,
                        "%s-%d\t%6.1000d [%03d] %s\t%s\n",
                        TEP_PRINT_COMM, TEP_PRINT_PID,
                        TEP_PRINT_TIME, TEP_PRINT_CPU,
                        TEP_PRINT_NAME, TEP_PRINT_INFO);
        trace_seq_terminate(&seq);
        trace_seq_do_printf(&seq);
        return 0;
}
int main(int argc, char **argv)
{
        struct tracecmd_input *handle;
        struct tep_handle *guest_tep;
        struct stat st;
        FILE *fp;
        char *buf;
        if (argc < 3) {
                printf("usage: trace.dat guest_kallsyms_file\n");
                exit(-1);
        }
        handle = tracecmd_open(argv[1], 0);
        if (!handle) {
                perror(argv[1]);
                exit(-1);
        }
        /* Seulement pour l'analyse kallsyms */
        guest_tep = tep_alloc();
        if (!guest_tep)
                exit(-1);
        if (stat(argv[2], &st) < 0) {
                perror(argv[2]);
                exit(-1);
        }
        buf = malloc(st.st_size + 1);
        if (!buf)
                exit(-1);
        fp = fopen(argv[2], "r");
        if (!fp) {
                perror(argv[2]);
                exit(-1);
        }
        if (fread(buf, st.st_size, 1, fp) < 0) {
                perror(argv[2]);
                exit(-1);
        }
        buf[st.st_size] = '\0';
        if (tep_parse_kallsyms(guest_tep, buf) < 0) {
                printf("Échec de l'analyse de %s\n", argv[2]);
                exit(-1);
        }
        free(buf);
        tracecmd_follow_event(handle, "kvm", "kvm_exit", show_event, guest_tep);
        tracecmd_follow_event(handle, "kvm", "kvm_entry", show_event, guest_tep);
        tracecmd_iterate_events(handle, NULL, 0, NULL, NULL);
        tep_free(guest_tep);
        tracecmd_close(handle);
}

NAME

tep_plugin_kvm_get_func - Get function of the KVM plugin

SYNOPSIS

#include <traceevent/tsp_kvm.h>

int tep_plugin_kvm_get_func(struct tep_handle *tep, const char *name);

DESCRIPTION

The function tep_plugin_kvm_get_func is part of the libtraceevent library. It is used to retrieve the function pointer associated with a KVM (Kernel-based Virtual Machine) event plugin.

This function takes a tep_handle pointer and the name of the KVM event as input. It returns an integer representing the function pointer. If the event is not found or an error occurs, it may return a specific error code or a value indicating failure.

The KVM plugin is used to parse and interpret KVM-specific trace events generated by the Linux kernel.

RETURN VALUE

Returns an integer representing the function pointer for the KVM event. Specific return values for success and failure depend on the implementation details of the KVM plugin and libtraceevent.

EXAMPLE

While a direct code example is not provided here, a typical usage scenario would involve initializing a tep_handle, loading the KVM plugin, and then calling tep_plugin_kvm_get_func to get a specific KVM event function.

```c

struct tep_handle *tep;
int func_ptr;

tep = tep_alloc();
if (!tep) {
    // Handle error
    return -1;
}

// Load KVM plugin (assuming it's registered or loaded by default)
// ...

// Get the function pointer for a KVM event, e.g., "kvm_entry"
func_ptr = tep_plugin_kvm_get_func(tep, "kvm_entry");

if (func_ptr < 0) {
    // Handle error: KVM event function not found or error occurred
    fprintf(stderr, "Failed to get KVM function pointer\n");
} else {
    // Use the function pointer (the exact usage depends on the plugin's API)
    printf("KVM function pointer: %d\n", func_ptr);
}

tep_free(tep);

```

NOM

tep_plugin_kvm_get_func - Obtenir la fonction du plugin KVM

SYNTAXE

#include <traceevent/tsp_kvm.h>

int tep_plugin_kvm_get_func(struct tep_handle *tep, const char *name);

DESCRIPTION

La fonction tep_plugin_kvm_get_func fait partie de la bibliothèque libtraceevent. Elle est utilisée pour récupérer le pointeur de fonction associé à un plugin d'événement KVM (Kernel-based Virtual Machine).

Cette fonction prend en entrée un pointeur tep_handle et le nom de l'événement KVM. Elle retourne un entier représentant le pointeur de fonction. Si l'événement n'est pas trouvé ou si une erreur se produit, elle peut retourner un code d'erreur spécifique ou une valeur indiquant l'échec.

Le plugin KVM est utilisé pour analyser et interpréter les événements de trace spécifiques à KVM générés par le noyau Linux.

VALEUR DE RETOUR

Retourne un entier représentant le pointeur de fonction pour l'événement KVM. Les valeurs de retour spécifiques pour le succès et l'échec dépendent des détails d'implémentation du plugin KVM et de libtraceevent.

EXEMPLE

Bien qu'un exemple de code direct ne soit pas fourni ici, un scénario d'utilisation typique impliquerait l'initialisation d'un tep_handle, le chargement du plugin KVM, puis l'appel à tep_plugin_kvm_get_func pour obtenir la fonction d'un événement KVM spécifique.

```c

struct tep_handle *tep;
int func_ptr;

tep = tep_alloc();
if (!tep) {
    // Gérer l'erreur
    return -1;
}

// Charger le plugin KVM (en supposant qu'il est enregistré ou chargé par défaut)
// ...

// Obtenir le pointeur de fonction pour un événement KVM, par exemple "kvm_entry"
func_ptr = tep_plugin_kvm_get_func(tep, "kvm_entry");

if (func_ptr < 0) {
    // Gérer l'erreur : pointeur de fonction KVM non trouvé ou erreur s'est produite
    fprintf(stderr, "Échec de l'obtention du pointeur de fonction KVM\n");
} else {
    // Utiliser le pointeur de fonction (l'utilisation exacte dépend de l'API du plugin)
    printf("Pointeur de fonction KVM : %d\n", func_ptr);
}

tep_free(tep);

```
