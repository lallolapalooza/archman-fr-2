tep_is_pid_registered(3)

Paquet: libtraceevent

Licences: GPL-2.0-only, LGPL-2.1-only

LIBTRACEEVENT(3) Manuel libtraceevent LIBTRACEEVENT(3)

NOM

tep_register_comm, tep_override_comm, tep_is_pid_registered, tep_data_comm_from_pid, tep_data_pid_from_comm, tep_cmdline_pid - Gérer les mappages pid vers nom de processus.

SYNTAXE

#include <event-parse.h>
int tep_register_comm(struct tep_handle *tep, const char *comm, int pid);
int tep_override_comm(struct tep_handle *tep, const char *comm, int pid);
bool tep_is_pid_registered(struct tep_handle *tep, int pid);
const char *tep_data_comm_from_pid(struct tep_handle *pevent, int pid);
struct cmdline *tep_data_pid_from_comm(struct tep_handle *pevent, const char *comm, struct cmdline *next);
int tep_cmdline_pid(struct tep_handle *pevent, struct cmdline *cmdline);

DESCRIPTION

Ces fonctions peuvent être utilisées pour gérer le mappage entre pid et nom de processus. La bibliothèque construit un cache de ces mappages, qui est utilisé pour afficher le nom du processus, au lieu de son pid. Ces informations peuvent être récupérées à partir du fichier tracefs/saved_cmdlines.

La fonction tep_register_comm() enregistre un mappage pid / nom de processus. Si une commande avec le même pid est déjà enregistrée, une erreur est retournée. L'argument pid est l'identifiant du processus, l'argument comm est le nom du processus, tep est le contexte de l'événement. Le comm est dupliqué en interne.

La fonction tep_override_comm() enregistre un mappage pid / nom de processus. Si un processus avec le même pid est déjà enregistré, la chaîne de caractères du nom du processus est mise à jour avec la nouvelle. L'argument pid est l'identifiant du processus, l'argument comm est le nom du processus, tep est le contexte de l'événement. Le comm est dupliqué en interne.

La fonction tep_is_pid_registered() vérifie si un pid a un mappage de nom de processus enregistré. L'argument pid est l'identifiant du processus, tep est le contexte de l'événement.

La fonction tep_data_comm_from_pid() renvoie le nom du processus pour un pid donné. L'argument pid est l'identifiant du processus, tep est le contexte de l'événement. La chaîne de caractères renvoyée ne doit pas être libérée, mais sera libérée lorsque le gestionnaire tep sera fermé.

La fonction tep_data_pid_from_comm() renvoie un pid pour un nom de processus donné. L'argument comm est le nom du processus, tep est le contexte de l'événement. L'argument next est la structure cmdline pour rechercher le pid suivant. Comme il peut y avoir plus d'un pid pour une commande donnée, le résultat de cet appel peut être passé lors d'un appel récurrent dans le paramètre next, pour rechercher le pid suivant. Si next est NULL, il renverra le premier pid associé à comm. La fonction effectue une recherche linéaire, elle peut donc être lente.

La fonction tep_cmdline_pid() renvoie le pid associé à une cmdline donnée. L'argument tep est le contexte de l'événement.

VALEUR DE RETOUR

La fonction tep_register_comm() renvoie 0 en cas de succès. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer la cause du problème : ENOMEM, s'il n'y a pas assez de mémoire pour dupliquer le comm ou EEXIST si un mappage pour ce pid est déjà enregistré.

La fonction tep_override_comm() renvoie 0 en cas de succès. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer la cause du problème : ENOMEM, s'il n'y a pas assez de mémoire pour dupliquer le comm.

La fonction tep_is_pid_registered() renvoie true si le pid a un nom de processus mappé, false sinon.

La fonction tep_data_comm_from_pid() renvoie le nom du processus sous forme de chaîne de caractères, ou la chaîne "<...>" s'il n'y a pas de mappage pour le pid donné.

La fonction tep_data_pid_from_comm() renvoie un pointeur vers une structure cmdline, qui contient un pid pour un processus donné, ou NULL si aucun n'est trouvé. Ce résultat peut être passé lors d'un appel récurrent en tant que paramètre next de la fonction.

La fonction tep_cmdline_pid() renvoie le pid pour la cmdline donnée. Si cmdline est NULL, alors -1 est renvoyé.

EXEMPLE

L'exemple suivant enregistre le pid pour la commande "ls", dans le contexte de l'événement tep et effectue diverses recherches de mappages pid / nom de processus :

#include <event-parse.h>
...
int ret;
int ls_pid = 1021;
struct tep_handle *tep = tep_alloc();
...
        ret = tep_register_comm(tep, "ls", ls_pid);
        if (ret != 0 && errno == EEXIST)
                ret = tep_override_comm(tep, "ls", ls_pid);
        if (ret != 0) {
                /* Échec de l'enregistrement du mappage pid / commande */
        }
...
        if (tep_is_pid_registered(tep, ls_pid) == 0) {
                /* Le mappage de commande pour ls_pid n'est pas enregistré */
        }
...
        const char *comm = tep_data_comm_from_pid(tep, ls_pid);
        if (comm) {
                /* Nom de processus trouvé pour ls_pid */
        }
...
        int pid;
        struct cmdline *cmd = tep_data_pid_from_comm(tep, "ls", NULL);
        while (cmd) {
                pid = tep_cmdline_pid(tep, cmd);
                /* Pid trouvé pour le processus "ls" */
                cmd = tep_data_pid_from_comm(tep, "ls", cmd);
        }
