threads::shared(3perl) Perl Programmers Reference Guide threads::shared(3perl)

NAME

threads::shared - Extension Perl pour le partage de structures de données entre threads

VERSION

Ce document décrit threads::shared version 1.70

SYNOPSIS

use threads;
use threads::shared;
my $var :shared;
my %hsh :shared;
my @ary :shared;
my ($scalar, @array, %hash);
share($scalar);
share(@array);
share(%hash);
$var = $scalar_value;
$var = $shared_ref_value;
$var = shared_clone($non_shared_ref_value);
$var = shared_clone({'foo' => [qw/foo bar baz/]});
$hsh{'foo'} = $scalar_value;
$hsh{'bar'} = $shared_ref_value;
$hsh{'baz'} = shared_clone($non_shared_ref_value);
$hsh{'quz'} = shared_clone([1..3]);
$ary[0] = $scalar_value;
$ary[1] = $shared_ref_value;
$ary[2] = shared_clone($non_shared_ref_value);
$ary[3] = shared_clone([ {}, [] ]);
{ lock(%hash); ...  }
cond_wait($scalar);
cond_timedwait($scalar, time() + 30);
cond_broadcast(@array);
cond_signal(%hash);
my $lockvar :shared;
# condition var != lock var
cond_wait($var, $lockvar);
cond_timedwait($var, time()+30, $lockvar);

DESCRIPTION

Par défaut, les variables sont privées à chaque thread, et chaque nouveau thread créé obtient une copie privée de chaque variable existante. Ce module vous permet de partager des variables entre différents threads (et pseudo-forks sous Win32). Il est utilisé conjointement avec le module threads.

Ce module prend en charge le partage des types de données suivants uniquement : scalaires et références de scalaires, tableaux et références de tableaux, et hachages et références de hachages.

EXPORT

Les fonctions suivantes sont exportées par ce module : "share", "shared_clone", "is_shared", "cond_wait", "cond_timedwait", "cond_signal" et "cond_broadcast"

Notez que si ce module est importé alors que threads n'a pas encore été chargé, toutes ces fonctions deviennent des no-op. Cela permet d'écrire des modules qui fonctionneront dans des environnements à la fois threadés et non threadés.

FUNCTIONS

share VARIABLE
"share" prend une variable et la marque comme partagée : 
my ($scalar, @array, %hash);
share($scalar);
share(@array);
share(%hash);

"share" retournera la rvalue partagée, mais toujours sous forme de référence.

Les variables peuvent également être marquées comme partagées au moment de la compilation en utilisant l'attribut ":shared" :

my ($var, %hash, @array) :shared;

Les variables partagées ne peuvent stocker que des scalaires, des références de variables partagées, ou des références de données partagées (discuté dans la section suivante) :

my ($var, %hash, @array) :shared;
my $bork;
# Stockage de scalaires
$var = 1;
$hash{'foo'} = 'bar';
$array[0] = 1.5;
# Stockage de références partagées
$var = \%hash;
$hash{'ary'} = \@array;
$array[1] = \$var;
# Les lignes suivantes sont des erreurs :
#   $var = \$bork;                    # référence d'une variable non partagée
#   $hash{'bork'} = [];               # référence de tableau non partagée
#   push(@array, { 'x' => 1 });       # référence de hachage non partagée
shared_clone REF
"shared_clone" prend une référence, et retourne une version partagée de son argument, effectuant une copie profonde de tous les éléments non partagés. Tous les éléments partagés dans l'argument sont utilisés tels quels (c'est-à-dire qu'ils ne sont pas clonés). 
my $cpy = shared_clone({'foo' => [qw/foo bar baz/]});

Le statut de l'objet (c'est-à-dire la classe dans laquelle un objet est béni) est également cloné.

my $obj = {'foo' => [qw/foo bar baz/]};
bless($obj, 'Foo');
my $cpy = shared_clone($obj);
print(ref($cpy), "\n");         # Affiche 'Foo'

Pour cloner des références de tableaux ou de hachages vides, les syntaxes suivantes peuvent également être utilisées :

$var = &share([]);   # Identique à $var = shared_clone([]);
$var = &share({});   # Identique à $var = shared_clone({});

Tous les types de données Perl ne peuvent pas être clonés (par exemple, les globs, les références de code). Par défaut, "shared_clone" provoquera une erreur s'il rencontre de tels éléments. Pour modifier ce comportement en un avertissement, définissez ce qui suit :

$threads::shared::clone_warn = 1;

Dans ce cas, "undef" sera substitué à l'élément à cloner. S'il est réglé sur zéro :

$threads::shared::clone_warn = 0;

alors la substitution par "undef" sera effectuée silencieusement.

is_shared VARIABLE
"is_shared" vérifie si la variable spécifiée est partagée ou non. Si elle est partagée, elle retourne l'ID interne de la variable (similaire à refaddr() (voir Scalar::Util). Sinon, elle retourne "undef". 
if (is_shared($var)) {
    print("\$var est partagé\n");
} else {
    print("\$var n'est pas partagé\n");
}

Lorsqu'utilisé sur un élément d'un tableau ou d'un hachage, "is_shared" vérifie si l'élément spécifié appartient à un tableau ou un hachage partagé. (Il ne vérifie pas le contenu de cet élément.)

my %hash :shared;
if (is_shared(%hash)) {
    print("\"\%hash est partagé\n");
}
$hash{'elem'} = 1;
if (is_shared($hash{'elem'})) {
    print("\$hash{'elem'} est dans un hachage partagé\n");
}
lock VARIABLE
"lock" place un verrou d'aide sur une variable jusqu'à ce que le verrou sorte de portée. Si la variable est verrouillée par un autre thread, l'appel "lock" bloquera jusqu'à ce qu'elle soit disponible. Des appels multiples à "lock" par le même thread depuis des portées dynamiquement imbriquées sont sûrs : la variable restera verrouillée jusqu'à ce que le verrou le plus externe sur la variable sorte de portée.

"lock" suit les références exactement sur un niveau :

my %hash :shared;
my $ref = \%hash;
lock($ref);           # Ceci est équivalent à lock(%hash)

Notez que vous ne pouvez pas déverrouiller explicitement une variable ; vous pouvez seulement attendre que le verrou sorte de portée. Ceci est plus facilement réalisé en verrouillant la variable à l'intérieur d'un bloc.

my $var :shared;
{
    lock($var);
    # $var est verrouillé d'ici à la fin du bloc
    ...
}
# $var est maintenant déverrouillé

Comme les verrous sont d'aide, ils n'empêchent pas l'accès ou la modification des données par un autre thread qui ne tente pas lui-même d'obtenir un verrou sur la variable.

Vous ne pouvez pas verrouiller les éléments individuels d'une variable conteneur :

my %hash :shared;
$hash{'foo'} = 'bar';
#lock($hash{'foo'});          # Erreur
lock(%hash);                  # Fonctionne

Si vous avez besoin d'un contrôle plus fin sur l'accès aux variables partagées, consultez Thread::Semaphore.

cond_wait VARIABLE
cond_wait CONDVAR, LOCKVAR
La fonction "cond_wait" prend une variable verrouillée comme paramètre, déverrouille la variable, et bloque jusqu'à ce qu'un autre thread effectue un "cond_signal" ou un "cond_broadcast" pour cette même variable verrouillée. La variable sur laquelle "cond_wait" a bloqué est reverrouillée après que le "cond_wait" soit satisfait. S'il y a plusieurs threads en "cond_wait" sur la même variable, tous sauf un se reverrouilleront en attendant de réacquérir le verrou sur la variable. (Donc, si vous utilisez seulement "cond_wait" pour la synchronisation, libérez le verrou dès que possible). Les deux actions de déverrouiller la variable et d'entrer dans l'état d'attente bloquée sont atomiques, les deux actions de sortir de l'état d'attente bloquée et de reverrouiller la variable ne le sont pas.

Dans sa seconde forme, "cond_wait" prend une variable partagée non verrouillée suivie

par une variable partagée et verrouillée. La seconde variable est déverrouillée et l'exécution du thread suspendue jusqu'à ce qu'un autre thread signale la première variable.

Il est important de noter que la variable peut être notifiée même si aucun thread n'a appelé "cond_signal" ou "cond_broadcast" sur la variable. Il est donc important de vérifier la valeur de la variable et de revenir à l'attente si l'exigence n'est pas remplie. Par exemple, pour faire une pause jusqu'à ce qu'un compteur partagé tombe à zéro :

{ lock($counter); cond_wait($counter) until $counter == 0; }
cond_timedwait VARIABLE, ABS_TIMEOUT
cond_timedwait CONDVAR, ABS_TIMEOUT, LOCKVAR
Dans sa forme à deux arguments, "cond_timedwait" prend une variable verrouillée et un délai d'attente absolu en secondes d'époque (voir time() dans perlfunc pour plus d'informations) comme paramètres, déverrouille la variable et bloque jusqu'à ce que le délai d'attente soit atteint ou qu'un autre thread signale la variable. Une valeur fausse est retournée si le délai d'attente est atteint, et une valeur vraie sinon. Dans les deux cas, la variable est reverrouillée au retour.

Comme "cond_wait", cette fonction peut prendre une variable partagée et verrouillée comme paramètre supplémentaire ; dans ce cas, le premier paramètre est une variable de condition déverrouillée protégée par une variable de verrouillage distincte.

Encore une fois, comme "cond_wait", le réveil et la réacquisition du verrou ne sont pas atomiques, et vous devez toujours vérifier la condition souhaitée après le retour de cette fonction. Comme le délai d'attente est une valeur absolue, il n'a cependant pas besoin d'être recalculé à chaque passage :

lock($var);
my $abs = time() + 15;
until ($ok = desired_condition($var)) {
    last if !cond_timedwait($var, $abs);
}
# on l'a eu si $ok, sinon on a dépassé le délai !
cond_signal VARIABLE
La fonction "cond_signal" prend une variable verrouillée comme paramètre et débloque un thread qui est en train de "cond_wait" sur cette variable. Si plus d'un thread est bloqué dans un "cond_wait" sur cette variable, un seul (et lequel est indéterminé) sera débloqué.

S'il n'y a pas de threads bloqués dans un "cond_wait" sur la variable, le signal est ignoré. En verrouillant toujours avant de signaler, vous pouvez (avec précaution) éviter de signaler avant qu'un autre thread n'ait entré cond_wait().

"cond_signal" générera normalement un avertissement si vous tentez de l'utiliser sur une variable déverrouillée. Dans les rares cas où cela pourrait être sensé, vous pouvez supprimer l'avertissement avec :

{ no warnings 'threads'; cond_signal($foo); }
cond_broadcast VARIABLE
La fonction "cond_broadcast" fonctionne similairement à "cond_signal". "cond_broadcast", cependant, débloquera tous les threads qui sont bloqués dans un "cond_wait" sur la variable verrouillée, plutôt qu'un seul.

OBJETS

threads::shared exporte une version de bless() qui fonctionne sur des objets partagés de telle sorte que les bénédictions se propagent entre les threads.

# Créer un objet 'Foo' partagé
my $foo :shared = shared_clone({});
bless($foo, 'Foo');
# Créer un objet 'Bar' partagé
my $bar :shared = shared_clone({});
bless($bar, 'Bar');
# Placer 'bar' à l'intérieur de 'foo'
$foo->{'bar'} = $bar;
# Re-bénir les objets via un thread
threads->create(sub {
    # Re-bénir l'objet externe
    bless($foo, 'Yin');
    # Impossible de re-bénir directement l'objet interne
    #bless($foo->{'bar'}, 'Yang');
    # Récupérer et re-bénir l'objet interne
    my $obj = $foo->{'bar'};
    bless($obj, 'Yang');
    $foo->{'bar'} = $obj;
})->join();
print(ref($foo),          "\n");    # Affiche 'Yin'
print(ref($foo->{'bar'}), "\n");    # Affiche 'Yang'
print(ref($bar),          "\n");    # Affiche aussi 'Yang'

NOTES

threads::shared est conçu pour se désactiver silencieusement si les threads ne sont pas disponibles. Cela vous permet d'écrire des modules et des paquets qui peuvent être utilisés dans des applications filetées et non filetées.

Si vous souhaitez accéder aux threads, vous devez "use threads" avant de "use threads::shared". threads émettra un avertissement si vous l'utilisez après threads::shared.

AVERTISSEMENTS

cond_broadcast() appelé sur une variable déverrouillée
cond_signal() appelé sur une variable déverrouillée
Voir "cond_signal VARIABLE", ci-dessus.

BOGUES ET LIMITATIONS

Lorsque "share" est utilisé sur des tableaux, des hachages, des références de tableaux ou des références de hachages, toute donnée qu'ils contiennent sera perdue.

my @arr = qw(foo bar baz);
share(@arr);
# @arr est maintenant vide (c'est-à-dire == ());
# Créer un objet 'foo'
my $foo = { 'data' => 99 };
bless($foo, 'foo');
# Partager l'objet
share($foo);        # Le contenu est maintenant effacé
print("ERREUR : \$foo est vide\n")
    if (! exists($foo->{'data'}));

Par conséquent, remplissez de telles variables après les avoir déclarées comme partagées. (Les scalaires et les références scalaires ne sont pas affectés par ce problème.)

Bénir un élément partagé après qu'il a été imbriqué dans un autre élément partagé ne propage pas la bénédiction à la référence partagée :

my $foo = &share({});
my $bar = &share({});
$bar->{foo} = $foo;
bless($foo, 'baz');   # $foo est maintenant de classe 'baz',
                      # mais $bar->{foo} n'est pas béni.

Par conséquent, vous devriez bénir les objets avant de les partager.

Il n'est souvent pas judicieux de partager un objet à moins que la classe elle-même n'ait été écrite pour prendre en charge le partage. Par exemple, le destructeur d'un objet partagé peut être appelé plusieurs fois, une fois pour la sortie de portée de chaque thread, ou peut ne pas être appelé du tout s'il est intégré dans un autre objet partagé. Un autre problème est que le contenu des objets basés sur des hachages sera perdu en raison de la limitation mentionnée ci-dessus. Voir examples/class.pl (dans la distribution CPAN de ce module) pour savoir comment créer une classe qui prend en charge le partage d'objets.

Les destructeurs peuvent ne pas être appelés sur les objets si ces objets existent toujours au moment de la destruction globale. Si les destructeurs doivent être appelés, assurez-vous qu'il n'y a pas de références circulaires et que rien ne référence les objets avant que le programme ne se termine.

Ne prend pas en charge "splice" sur les tableaux. Ne prend pas en charge la modification explicite des longueurs de tableaux via $#array -- utilisez plutôt "push" et "pop".

Prendre des références aux éléments des tableaux et hachages partagés ne vivifie pas automatiquement les éléments, pas plus qu'un découpage d'un tableau/hachage partagé sur des indices/clés inexistants ne vivifie les éléments.

share() vous permet de share($hashref->{key}) et share($arrayref->[idx]) sans afficher de message d'erreur. Mais le "$hashref->{key}" ou "$arrayref->[idx]" n'est pas partagé, provoquant l'erreur "lock can only be used on shared values" (le verrou ne peut être utilisé que sur des valeurs partagées) lorsque vous tentez de lock($hashref->{key}) ou lock($arrayref->[idx]) dans un autre thread.

L'utilisation de refaddr() n'est pas fiable pour tester si deux références partagées sont équivalentes (par exemple, lors du test de références circulaires). Utilisez plutôt is_shared() :

use threads;
use threads::shared;
use Scalar::Util qw(refaddr);
# Si ref est partagé, utiliser l'ID interne de threads::shared.
# Sinon, utiliser refaddr().
my $addr1 = is_shared($ref1) || refaddr($ref1);
my $addr2 = is_shared($ref2) || refaddr($ref2);
if ($addr1 == $addr2) {
    # Les refs sont équivalentes
}

each() ne fonctionne pas correctement sur les références partagées intégrées dans des structures partagées. Par exemple :

my %foo :shared;
$foo{'bar'} = shared_clone({'a'=>'x', 'b'=>'y', 'c'=>'z'});
while (my ($key, $val) = each(%{$foo{'bar'}})) {
    ...
}

L'une des méthodes suivantes fonctionnera à la place :

my $ref = $foo{'bar'};
while (my ($key, $val) = each(%{$ref})) {
    ...
}
foreach my $key (keys(%{$foo{'bar'}})) {
    my $val = $foo{'bar'}{$key};
    ...
}

Ce module prend en charge les variables à double valeur créées en utilisant dualvar() de Scalar::Util. Cependant, bien que $! se comporte comme une double valeur, il est implémenté comme un SV lié. Pour propager sa valeur, utilisez la construction suivante, si nécessaire :

my $errno :shared = dualvar($!,$!);
