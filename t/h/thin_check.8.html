NOM

thin_check - valide les métadonnées de provisionnement fin sur un périphérique ou un fichier

SYNTAXE

thin_check [options] {périphérique|fichier}

DESCRIPTION

thin_check vérifie les métadonnées de provisionnement fin créées par la cible de provisionnement fin de device-mapper sur un périphérique ou un fichier.

L'outil ne peut pas être exécuté sur des métadonnées actives sauf si l'option --metadata-snapshot est utilisée.

OPTIONS

-q, --quiet
Supprime les messages de sortie, renvoie uniquement le code de sortie.
-h, --help
Affiche l'aide et quitte.
-V, --version
Affiche les informations de version et quitte.
--super-block-only
Vérifie uniquement le super bloc.
--skip-mappings
Ignore la vérification des mappages de blocs qui constituent la majeure partie des métadonnées.
--ignore-non-fatal-errors
Ne retournera un code de sortie non nul que s'il trouve une erreur fatale.
    Un exemple d'erreur non fatale est un compte de références de bloc de données
    incorrect qui fait qu'un bloc est considéré comme alloué alors qu'il ne l'est
    pas en réalité. Ignorer les erreurs pendant longtemps n'est pas conseillé, vous
    devriez utiliser thin_repair pour les corriger.
--clear-needs-check-flag
Efface le drapeau 'needs_check' dans le super bloc.
    Le noyau peut définir un drapeau pour forcer la vérification du pool avant sa
    prochaine activation. Définissez ce commutateur pour effacer le drapeau si la
    vérification des métadonnées réussit. Si la vérification des métadonnées a
    échoué, le drapeau n'est pas effacé et une exécution de thin_repair est nécessaire
    pour corriger les problèmes. Après le succès de thin_repair, vous pouvez exécuter
    thin_check à nouveau.
--metadata-snapshot, -m
Vérifie l'instantané des métadonnées.
    Cela vérifie l'arbre des périphériques et les mappages dans un instantané des
    métadonnées. L'instantané ne contient pas d'espaces de données, ceux-ci ne seront donc
    pas vérifiés. Ceci peut être utilisé sur des métadonnées actives.
--auto-repair
Répare automatiquement les problèmes triviaux trouvés avec les métadonnées.
    Corrige actuellement uniquement les fuites de métadonnées.
--override-mapping-root <bloc>
Spécifie une racine de mappage à utiliser.
    N'utilisez pas ceci. Ceci remplace ce qui est spécifié dans le super bloc. N'utilisez ceci
    que si vous comprenez vraiment le format des métadonnées et que vous essayez de
    récupérer des métadonnées endommagées.

EXEMPLE

Analyse les métadonnées de provisionnement fin sur le volume logique /dev/vg/metadata :

    $ thin_check /dev/vg/metadata
Le périphérique ne doit pas être activement utilisé par la cible lors de l'exécution.

DIAGNOSTICS

thin_check renvoie un code de sortie de 0 en cas de succès ou de 1 en cas d'erreur.
