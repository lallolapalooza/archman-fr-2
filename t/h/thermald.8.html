NOM

thermald - démarrer le démon thermique Linux

SYNTAXE

thermald [ OPTIONS ]

DESCRIPTION

thermald est un démon Linux utilisé pour prévenir la surchauffe des plateformes. Ce démon surveille la température et applique une compensation en utilisant les méthodes de refroidissement disponibles.

Par défaut, il surveille la température du CPU à l'aide des capteurs de température numériques du CPU disponibles et maintient la température du CPU sous contrôle, avant que le matériel ne prenne des mesures correctives agressives.

Le démon thermique recherche les capteurs thermiques et les pilotes de refroidissement thermique dans le sysfs thermique de Linux (/sys/class/thermal) et construit une liste de capteurs et de pilotes de refroidissement. Chacun des capteurs thermiques peut être lié optionnellement à un pilote de refroidissement par les pilotes intégrés au noyau. Dans ce cas, le cœur thermique du noyau Linux peut directement prendre des mesures basées sur les points de déclenchement de température, pour chaque capteur et périphérique de refroidissement associé. Par exemple, une température de déclenchement X dans un capteur peut être associée à un pilote de refroidissement Y. Ainsi, lorsque la température du capteur = X, le pilote de refroidissement "Y" est activé.

Le démon thermique permet de modifier cette relation ou d'en ajouter une nouvelle via un fichier de configuration thermique (thermal-conf.xml). Ce fichier est automatiquement créé (thermal-conf.xml.auto) et utilisé, si la plateforme dispose d'une table de relation thermique ACPI. Sinon, il doit être configuré manuellement.

Pour la configuration manuelle, référez-vous à la page de manuel de thermal-conf.xml.

Sur certaines plateformes plus récentes, la création automatique du fichier de configuration est effectuée par un outil compagnon "dptfxtract". Cet outil peut être téléchargé depuis "https://github.com/intel/dptfxtract". Il est suggéré, dans le cadre du processus d'installation, d'exécuter dptfxtract.

Il peut y avoir plusieurs fichiers de configuration. L'utilisateur peut sélectionner un fichier de configuration via l'option -config-file pour remplacer la sélection par défaut. La sélection par défaut choisit l'un des fichiers dans l'ordre suivant :

- /etc/thermald/thermal-conf.xml.auto

- /var/run/thermald/thermal-conf.xml.auto

- /etc/thermald/thermal-conf.xml

(* En supposant que le préfixe de compilation configure est /.)

Il existe un autre outil compagnon "ThermalMonitor", qui présente une interface graphique. Cela permet de surveiller les capteurs et de modifier les déclencheurs thermiques pour donner plus de contrôle à l'utilisateur. Le code source de "ThermalMonitor" fait partie de la source github de thermald, dans le dossier tools.

OPTIONS

-h, --help
Affiche les options d'aide.
--version
Affiche la version de thermald et quitte.
--no-daemon
Ne pas devenir un démon : le mode par défaut est le mode démon.
--loglevel=info
Niveau de journalisation : niveau info et supérieur.
--loglevel=debug
Niveau de journalisation : niveau debug et supérieur : Journalisation maximale.
--poll-interval
Intervalle d'interrogation en secondes : Interroge les changements de température des zones. Pour désactiver l'interrogation, mettez à zéro. L'interrogation ne peut être désactivée que si les capteurs de température disponibles peuvent notifier les changements de température de manière asynchrone.
--dbus-enable
Active D-Bus.
--exclusive-control
Agit comme contrôleur thermique exclusif. Cela utilisera le gouverneur de l'espace utilisateur pour le sysfs thermique et prendra le contrôle.
--ignore-cpuid-check
Ignore la vérification cpuid pour les modèles de CPU pris en charge.
--config-file
Spécifie le chemin de thermal-conf.xml et ignore le thermal-conf.xml par défaut.
--ignore-default-control
Ignore le contrôle de température par défaut du CPU. Suivez strictement thermal-conf.xml ou thermal-conf.xml.auto.
--workaround-enabled
Active des solutions de contournement spéciales pour la limite de puissance MMIO RAPL et le décalage TCC toutes les 30 secondes. Cela permet de désactiver le MMIO RAPL lorsqu'il n'est pas utilisé et d'ajuster le décalage TCC sur certains ordinateurs portables Lenovo.
--disable-active-power
Désactive la gestion active de l'alimentation. Cela ne définira pas les limites de puissance actives à l'aide du MMIO RAPL. Cela peut entraîner des performances limitées, si le système démarre avec des limites de puissance plus basses.
--adaptive
Utilise les tables adaptatives DPTF lorsqu'elles sont présentes. Cela ignorera la configuration thermald via les fichiers xml.
--test-mode
Force l'utilisation du mode adaptatif et quitte si ce n'est pas pris en charge, au lieu de redémarrer en mode non adaptatif. Cette option est principalement destinée aux développeurs.
--systemd
Suppose que thermald est démarré par systemd. Cela empêchera l'exécution en tant que démon, quelle que soit l'option --no-daemon.
--ignore-critical-trip
Si la configuration a défini un point de température critique, trop bas, cette option évitera l'arrêt du système lors de l'atteinte de cette limite de température.
