thermal-conf.xml(5) Manuel des formats de fichiers thermal-conf.xml(5)

NOM

thermal-conf.xml - Fichier de configuration du démon thermique

SYNTAXE

$(TDCONFDIR)/etc/thermald/thermal-conf.xml

DESCRIPTION

thermal-conf.xml est un fichier de configuration pour le démon thermique. Il est utilisé pour configurer les capteurs thermiques, les zones et les dispositifs de refroidissement. L'emplacement de ce fichier dépend de l'option de configuration utilisée lors de la compilation.

La terminologie utilisée dans ce fichier est conforme à la norme "Advanced Configuration and Power Interface Specification". Le modèle thermique ACPI est basé sur des régions conceptuelles de plateforme appelées zones thermiques qui contiennent physiquement des dispositifs, des capteurs thermiques et des contrôles de refroidissement. Par exemple, une zone thermique peut être un processeur ou un couvercle d'ordinateur portable. Une zone peut contenir plusieurs capteurs pour surveiller la température. Un dispositif de refroidissement fournit une interface pour réduire la température d'un dispositif source, ce qui entraîne une augmentation de la température. Un exemple de dispositif de refroidissement est un ventilateur ou un pilote Linux qui peut limiter la fréquence du dispositif source.

Une configuration de zone thermique comprend un ou plusieurs points de seuil. Un point de seuil est une température à laquelle un dispositif de refroidissement doit être activé.

Un dispositif de refroidissement peut être actif ou passif. Un exemple de dispositif actif est un ventilateur, qui ne réduira pas les performances au prix d'une consommation d'énergie et d'un bruit plus importants. Un dispositif passif utilise la limitation des performances pour contrôler la température. En plus des dispositifs de refroidissement présents dans le sysfs thermique, les dispositifs de refroidissement suivants sont intégrés à thermald, qui peuvent être utilisés comme types de dispositifs de refroidissement valides :

  • rapl_controller
  • intel_pstate
  • cpufreq
  • LCD

Le sysfs thermique sous Linux (/sys/class/thermal) fournit un moyen de représenter la configuration ACPI par plateforme. Le régulateur thermique du noyau utilise ces données pour contrôler les thermiques de la plateforme. Mais il existe certaines limitations que thermald tente de résoudre. Par exemple :

  • Si les données ACPI ne sont pas optimisées ou sont boguées. Dans ce cas, thermal-conf.xml peut être utilisé pour corriger le comportement sans modification du BIOS.
  • Il peut y avoir des zones thermiques exposées par le sysfs thermique sans actions de refroidissement associées. Dans ce cas, thermal conf.xml peut être utilisé pour lier les dispositifs de refroidissement à ces zones.
  • La meilleure méthode de refroidissement peut ne pas être dans le sysfs thermique. Dans ce cas, thermal-conf.xml peut être utilisé pour associer une zone à un dispositif de refroidissement externe.
  • Spécifier les relations thermiques. Une zone peut être influencée par plusieurs dispositifs sources avec des degrés variables. Dans ce cas, thermal-conf.xml peut être utilisé pour définir l'influence relative pour appliquer la compensation.

FORMAT DU FICHIER

Le format du fichier de configuration est conforme aux spécifications XML. Un ensemble de balises est défini pour spécifier la plateforme, les capteurs, les zones, les dispositifs de refroidissement et les points de seuil.

<ThermalConfiguration>
  <Platform>
    <Name>Nom de la plateforme exemple</Name>
    <!-- L'UUID est facultatif, s'il est présent, il correspondra. Le nom du produit
         et l'UUID peuvent contenir un caractère générique "*", qui correspond
         à n'importe quelle plateforme. -->
    <UUID>UUID exemple</UUID>
    <!-- le format du fichier de configuration est conforme aux spécifications
         XML. Un ensemble de balises est défini pour spécifier la plateforme, les
         capteurs, les zones, les dispositifs de refroidissement et les points de
         seuil. -->
    <ProductName>Nom du produit exemple</ProductName>
    <Preference>QUIET|PERFORMANCE</Preference>
    <!-- Le mode QUIET n'utilisera que des dispositifs de refroidissement passifs.
         "PERFORMANCE" ne sélectionnera que des dispositifs actifs. -->
    <ThermalSensors>
      <ThermalSensor>
        <!-- Nouveau capteur avec un type et un chemin -->
        <Type>capteur_exemple_1</Type>
        <Path>/chemin_quelconque</Path>
        <AsyncCapable>0</AsyncCapable>
      </ThermalSensor>
      <ThermalSensor>
        <!-- Déjà présent dans le sysfs thermique, activez-le ou
             ajoutez/modifiez la configuration. Par exemple, nous indiquons ici
             que le capteur peut effectuer des événements asynchrones pour éviter le
             sondage. -->
        <Type>capteur_sysfs_thermique_exemple</Type>
        <!-- S'il est capable d'asynchronisme, alors nous n'avons pas besoin de sonder. -->
        <AsyncCapable>1</AsyncCapable>
      </ThermalSensor>
    </ThermalSensors>
    <ThermalZones>
      <ThermalZone>
        <Type>Type de zone exemple</Type>
        <TripPoints>
          <TripPoint>
            <SensorType>capteur_exemple_1</SensorType>
            <!-- Température à laquelle prendre une mesure. -->
            <Temperature> 75000 </Temperature>
            <!-- max/passive/active Si un type MAX est spécifié, alors
                 le démon utilisera le contrôle PID pour limiter agressivement
                 afin d'éviter d'atteindre cette température. -->
            <type>max</type>
            <!-- SEQUENTIAL | PARALLEL. Lorsqu'une température de point de seuil
                 est violée, un certain nombre de dispositifs de refroidissement peuvent
                 être activés. Si le type de contrôle est SEQUENTIAL, alors il
                 épuisera le premier dispositif de refroidissement avant d'essayer le
                 suivant. -->
            <ControlType>SEQUENTIAL</ControlType>
            <CoolingDevice>
              <index>1</index>
              <type>dispositif_refroidissement_exemple</type>
              <!-- L'influence sera utilisée pour ordonner les dispositifs de
                   refroidissement. Le premier dispositif de refroidissement utilisé sera
                   celui qui a la plus grande influence. -->
              <influence> 100 </influence>
              <!-- Délai d'utilisation de ce dispositif de refroidissement, cela prend
                   également du temps pour refroidir réellement une zone. -->
              <SamplingPeriod> 12 </SamplingPeriod>
              <!-- Définir un état spécifique de ce dispositif de refroidissement lorsque
                   ce seuil est violé. -->
              <TargetState> 6 </TargetState>
            </CoolingDevice>
          </TripPoint>
        </TripPoints>
      </ThermalZone>
    </ThermalZones>
    <CoolingDevices>
      <CoolingDevice>
        <!-- Le dispositif de refroidissement peut être spécifié par un type et
             facultativement un chemin sysfs. Si le type est déjà présent dans le
             sysfs thermique, un chemin n'est pas nécessaire. La compensation peut
             utiliser min/max et la taille du pas pour refroidir progressivement le
             système. La période de temporisation peut être utilisée pour forcer une
             période d'attente avant l'action. -->
        <Type>dispositif_refroidissement_exemple</Type>
        <MinState>0</MinState>
        <IncDecStep>10</IncDecStep>
        <ReadBack> 0 </ReadBack>
        <MaxState>50</MaxState>
        <DebouncePeriod>5000</DebouncePeriod>
        <!-- S'il n'y a pas de paramètres PID, la compensation augmente par étapes
             et exponentiellement (si une seule étape ne parvient pas à changer la
             tendance). Alternativement, des paramètres PID peuvent être spécifiés,
             alors la prochaine étape utilisera le calcul PID à l'aide des constantes
             PID fournies. -->
        <PidControl>
          <kp>0.001</kp>
          <kd>0.0001</kd>
          <ki>0.0001</ki>
        </PidControl>
        <!-- Écrire un préfixe attaché à la valeur d'état, comme ci-dessous,
             le préfixe est "level ". Il préservera les espaces tels qu'ils sont
             entrer lors de l'écriture dans sysfs. -->
        <WritePrefix>level </WritePrefix>
      </CoolingDevice>
    </CoolingDevices>
  </Platform>
</ThermalConfiguration>

<?xml version="1.0"?>
<ThermalConfiguration>
  <Platform>
    <Name>Remplacement du défaut passif du CPU</Name>
    <ProductName>*</ProductName>
    <Preference>QUIET</Preference>
    <ThermalZones>
      <ThermalZone>
        <Type>cpu</Type>
        <TripPoints>
          <TripPoint>
            <Temperature>86000</Temperature>
            <type>passive</type>
          </TripPoint>
        </TripPoints>
      </ThermalZone>
    </ThermalZones>
  </Platform>
</ThermalConfiguration>

NOM

thermald.conf — Fichier de configuration pour thermald

DESCRIPTION

Le programme thermald est une daémon qui gère la température du système et contrôle la température du système. La configuration est fournie sous la forme d'un fichier XML. Voici la description des différentes sections.

La section <ThermalConfiguration> est l'élément racine du fichier de configuration.

La section <Platform> décrit la configuration pour une plateforme matérielle spécifique. Elle peut contenir les sous-sections suivantes :

<Name>
Nom de la plateforme. Ce nom est utilisé pour l'identification.
<ProductName>
Modèle de produit de la plateforme. Le caractère générique * peut être utilisé pour correspondre à n'importe quel nom de produit.
<Preference>
Indique la préférence de performance pour la plateforme. Les valeurs possibles sont PERFORMANCE et QUIET.
<ThermalZones>
Cette section contient une liste de zones thermiques définies pour la plateforme.
<CoolingDevices>
Cette section contient une liste de périphériques de refroidissement définis pour la plateforme.

La section <ThermalZone> décrit une zone thermique spécifique. Elle peut contenir les sous-sections suivantes :

<Type>
Type de zone thermique. Par exemple, x86_pkg_temp pour la température du package du processeur x86, cpu_thermal pour la température du CPU, etc.
<TripPoints>
Cette section contient une liste de points de déclenchement définis pour la zone thermique.

La section <TripPoint> définit un seuil de température pour une action de refroidissement. Elle peut contenir les sous-sections suivantes :

<SensorType>
Le type de capteur utilisé pour cette zone thermique. Ceci est souvent le même que <Type> de la <ThermalZone>.
<Temperature>
La température (en degrés Celsius x 1000) à laquelle ce point de déclenchement est activé.
<type>
Le type d'action à effectuer. Les valeurs possibles sont passive (réduire la puissance) ou hotplug (retirer le processeur).
<ControlType>
Si ce point de déclenchement est utilisé pour le contrôle, spécifiez le type de contrôle. Les valeurs possibles sont SEQUENTIAL pour un contrôle séquentiel et PID pour un contrôle PID.
<CoolingDevice>
Définit le périphérique de refroidissement à utiliser lorsqu'un point de déclenchement est atteint. Peut contenir les sous-sections suivantes :
<index>
Un index facultatif pour identifier un périphérique de refroidissement spécifique, utilisé avec <Type>.
<type>
Le type de périphérique de refroidissement. Par exemple, CPU, GPU, Fan, _Fan, etc.
<influence>
L'influence (en pourcentage) de ce périphérique de refroidissement sur la température globale. Utilisé avec le contrôle PID.
<SamplingPeriod>
La période d'échantillonnage (en secondes) pour ce périphérique de refroidissement. Utilisé avec le contrôle PID.
<TargetState>
L'état cible pour le périphérique de refroidissement. Ceci est utilisé pour définir une vitesse de ventilateur spécifique ou un niveau de puissance.

La section <CoolingDevice> dans la section <CoolingDevices> décrit un périphérique de refroidissement spécifique. Elle peut contenir les sous-sections suivantes :

<Type>
Le type de périphérique de refroidissement.
<Path>
Le chemin du fichier sysfs pour contrôler ce périphérique de refroidissement.
<MinState>
L'état minimum du périphérique de refroidissement.
<MaxState>
L'état maximum du périphérique de refroidissement.
<IncDecStep>
L'incrément ou le décrément pour l'état du périphérique de refroidissement.
<ReadBack>
Indique si la valeur écrite peut être lue à partir du fichier sysfs pour vérifier l'état.
<DebouncePeriod>
La période de temporisation (en secondes) avant d'appliquer les changements.
<WritePrefix>
Un préfixe à écrire dans le fichier sysfs avant la valeur de l'état. Utile lorsque l'interface sysfs attend une chaîne spécifique.
<PidControl>
Paramètres de contrôle PID :
<kp>
Constante proportionnelle.
<ki>
Constante intégrale.
<kd>
Constante dérivée.

Exemple 1 : Contrôle de la vitesse du ventilateur basé sur la température du package CPU. Lorsque la température du package CPU atteint 50 °C, le ventilateur est activé.

<?xml version="1.0"?>
<ThermalConfiguration>
  <Platform>
    <Name>Example Fan Control</Name>
    <ProductName>*</ProductName>
    <Preference>QUIET</Preference>
    <ThermalZones>
      <ThermalZone>
        <Type>x86_pkg_temp</Type>
        <TripPoints>
          <TripPoint>
            <SensorType>x86_pkg_temp</SensorType>
            <Temperature>50000</Temperature>
            <type>passive</type>
            <CoolingDevice>
              <type>Fan</type>
            </CoolingDevice>
          </TripPoint>
        </TripPoints>
      </ThermalZone>
    </ThermalZones>
    <CoolingDevices>
      <CoolingDevice>
        <Type>Fan</Type>
        <Path>/sys/devices/platform/thinkpad_hwmon/pwm1</Path>
        <MinState>0</MinState>
        <MaxState>255</MaxState>
      </CoolingDevice>
    </CoolingDevices>
  </Platform>
</ThermalConfiguration>

          </TripPoint>

      </ThermalZone>

Exemple 3 : Dans cet exemple, le Lenovo Thinkpad X220 et la vitesse du ventilateur sont contrôlés. Ici, un périphérique de refroidissement "_Fan", peut être contrôlé via sysfs /sys/devices/platform/thinkpad_hwmon/pwm1. Lorsque la température x86_pkg_temp atteint 45 °C, le ventilateur est démarré avec des vitesses croissantes, si la température ne peut pas être contrôlée à 45 °C.

<?xml version="1.0"?>
<ThermalConfiguration>
  <Platform>
    <Name>Lenovo ThinkPad X220</Name>
    <ProductName>*</ProductName>
    <Preference>QUIET</Preference>
    <ThermalZones>
      <ThermalZone>
        <Type>x86_pkg_temp</Type>
        <TripPoints>
          <TripPoint>
            <SensorType>x86_pkg_temp</SensorType>
            <Temperature>45000</Temperature>
            <type>passive</type>
            <ControlType>SEQUENTIAL</ControlType>
            <CoolingDevice>
              <index>1</index>
              <type>_Fan</type>
              <influence> 100 </influence>
              <SamplingPeriod> 12 </SamplingPeriod>
            </CoolingDevice>
          </TripPoint>
        </TripPoints>
      </ThermalZone>
    </ThermalZones>
    <CoolingDevices>
      <CoolingDevice>
        <Type>_Fan</Type>
        <Path>/sys/devices/platform/thinkpad_hwmon/pwm1</Path>
        <MinState>0</MinState>
        <IncDecStep>30</IncDecStep>
        <ReadBack> 0 </ReadBack>
        <MaxState>255</MaxState>
        <DebouncePeriod>5</DebouncePeriod>
      </CoolingDevice>
    </CoolingDevices>
  </Platform>
</ThermalConfiguration>

Exemple 4 : L'exemple suivant montre comment utiliser le PID. Ici, une fois que la température dépasse 80 °C, une compensation est calculée à l'aide du PID en utilisant 80 °C comme point de consigne du PID. La compensation dépend de l'erreur par rapport au point de consigne. Ici, le périphérique de refroidissement du processeur intégré par défaut est utilisé avec un état minimum de 0 et un état maximum de 10.

<?xml version="1.0"?>
<ThermalConfiguration>
  <Platform>
    <Name>Utiliser les paramètres PID </Name>
    <ProductName>*</ProductName>
    <Preference>QUIET</Preference>
    <ThermalZones>
      <ThermalZone>
        <Type>x86_pkg_temp</Type>
        <TripPoints>
          <TripPoint>
            <SensorType>x86_pkg_temp</SensorType>
            <Temperature>80000</Temperature>
            <type>passive</type>
            <ControlType>SEQUENTIAL</ControlType>
            <CoolingDevice>
              <type>Processor</type>
            </CoolingDevice>
          </TripPoint>
        </TripPoints>
      </ThermalZone>
    </ThermalZones>
    <CoolingDevices>
      <CoolingDevice>
        <Type>Processor</Type>
        <PidControl>
          <kp>0.0002</kp>
          <kd>0</kd>
          <ki>0</ki>
        </PidControl>
      </CoolingDevice>
    </CoolingDevices>
  </Platform>
</ThermalConfiguration>

Exemple 5 : L'exemple suivant montre comment contrôler le ventilateur lorsque le sysfs attend un préfixe de chaîne spécifique. Par exemple, au lieu d'écrire simplement un nombre dans le sysfs de contrôle du ventilateur, l'interface nécessite "level " devant l'indice de vitesse.

  </Platform>
