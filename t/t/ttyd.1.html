NOM

ttyd - Partagez votre terminal sur le web

SYNOPSIS

ttyd [options] <commande> [<arguments...>]

DESCRIPTION

ttyd est un outil en ligne de commande pour partager le terminal sur le web qui fonctionne sur les systèmes *nix et Windows, avec les caractéristiques suivantes :

  • Construit sur Libwebsockets avec libuv pour la rapidité
  • Terminal complet basé sur Xterm.js avec prise en charge des langues CJK (chinois, japonais, coréen) et IME
  • Intégration graphique ZMODEM avec prise en charge de lrzsz
  • Prise en charge de la sortie d'image Sixel
  • Prise en charge SSL basée sur OpenSSL
  • Exécutez n'importe quelle commande personnalisée avec des options
  • Prise en charge de l'authentification de base et de nombreuses autres options personnalisées
  • Multiplateforme : macOS, Linux, FreeBSD/OpenBSD, OpenWrt/LEDE, Windows

OPTIONS

-p, --port
Port d'écoute (par défaut : 7681, utiliser 0 pour un port aléatoire)

-i, --interface
Interface réseau à lier (par ex. : eth0), ou chemin du socket de domaine UNIX (par ex. : /var/run/ttyd.sock)

-U, --socket-owner
Propriétaire utilisateur du fichier de socket de domaine UNIX, lorsqu'il est activé (par ex. : user:group)

-c, --credential USER[:PASSWORD]
Identifiants pour l'authentification de base (format : nomutilisateur:motdepasse)

-H, --auth-header
Nom de l'en-tête HTTP pour le proxy d'authentification, cela configurera ttyd pour laisser un proxy inverse HTTP gérer l'authentification

-u, --uid
ID utilisateur sous lequel exécuter

-g, --gid
ID de groupe sous lequel exécuter

-s, --signal
Signal à envoyer à la commande lors de sa sortie (par défaut : 1, SIGHUP)

-w, --cwd
Répertoire de travail à définir pour le programme enfant

-a, --url-arg
Autoriser le client à envoyer des arguments de ligne de commande dans l'URL (par ex. : http://localhost:7681?arg=foo&arg=bar)

-W, --writable
Autoriser les clients à écrire sur le TTY (lecture seule par défaut)

-t, --client-option
Envoyer une option au client (format : clé=valeur), répéter pour ajouter d'autres options, voir OPTIONS CLIENT pour les détails

-T, --terminal-type
Type de terminal à signaler, par défaut : xterm-256color

-O, --check-origin
Ne pas autoriser les connexions websocket d'une origine différente

-m, --max-clients
Nombre maximum de clients à supporter (par défaut : 0, pas de limite)

-o, --once
Accepter un seul client et quitter lors de la déconnexion

-q, --exit-no-conn
Quitter lorsque tous les clients sont déconnectés

-B, --browser
Ouvrir le terminal avec le navigateur système par défaut

-I, --index
Chemin personnalisé de index.html

-b, --base-path
Chemin de base attendu pour les requêtes provenant d'un proxy inverse (par ex. : /monté/ici, longueur max : 128)

-P, --ping-interval
Intervalle de ping websocket (secondes) (par défaut : 5)

-6, --ipv6
Activer la prise en charge IPv6

-S, --ssl
Activer SSL

-C, --ssl-cert
Chemin du fichier de certificat SSL

-K, --ssl-key
Chemin du fichier de clé SSL

-A, --ssl-ca
Chemin du fichier CA SSL pour la vérification du certificat client

-d, --debug
Définir le niveau de journalisation (par défaut : 7)

-v, --version
Afficher la version et quitter

-h, --help
Afficher ce texte et quitter

OPTIONS CLIENT

ttyd dispose d'un mécanisme pour transmettre des arguments de ligne de commande côté serveur à la page du navigateur, appelé options client :

-t, --client-option     Envoyer une option au client (format : clé=valeur), répéter pour ajouter d'autres options

Usage de base

  • -t rendererType=canvas : utiliser le rendu canvas pour xterm.js (par défaut : webgl)
  • -t disableLeaveAlert=true : désactiver l'alerte de sortie de page
  • -t disableResizeOverlay=true : désactiver la superposition de redimensionnement du terminal
  • -t disableReconnect=true : empêcher le terminal de se reconnecter en cas d'erreur/fermeture de connexion
  • -t enableZmodem=true : activer la prise en charge du transfert de fichiers ZMODEM ⟨https://en.wikipedia.org/wiki/ZMODEM⟩ / lrzsz ⟨https://ohse.de/uwe/software/lrzsz.html⟩
  • -t enableTrzsz=true : activer la prise en charge du transfert de fichiers trzsz ⟨https://trzsz.github.io⟩
  • -t enableSixel=true : activer la prise en charge de la sortie d'image Sixel ⟨https://en.wikipedia.org/wiki/Sixel⟩ (Utilisation ⟨https://saitoha.github.io/libsixel/⟩)
  • -t titleFixed=hello : définir un titre fixe pour la fenêtre du navigateur
  • -t fontSize=20 : modifier la taille de la police du terminal

Usage avancé

Vous pouvez utiliser l'option client pour modifier tous les paramètres de xterm définis dans ITerminalOptions ⟨https://xtermjs.org/docs/api/terminal/interfaces/iterminaloptions/⟩, exemples :

  • -t cursorStyle=bar : définir le style du curseur sur bar
  • -t lineHeight=1.5 : définir la hauteur de ligne sur 1.5
  • -t 'theme={"background": "green"}' : définir la couleur d'arrière-plan sur vert

pour essayer les options d'exemple ci-dessus, exécutez :

ttyd -t cursorStyle=bar -t lineHeight=1.5 -t 'theme={"background": "green"}' bash

EXEMPLES

ttyd démarre le serveur web sur le port 7681 par défaut, vous pouvez utiliser l'option -p pour le modifier, la commande sera lancée avec les arguments comme options. Par exemple, exécutez :

ttyd -p 8080 bash -x

Ensuite, ouvrez http://localhost:8080 avec un navigateur, vous obtiendrez un shell bash avec le mode débogage activé. Plus d'exemples :

  • Si vous souhaitez vous connecter avec vos comptes système dans le navigateur web, exécutez ttyd login.
  • Vous pouvez même exécuter une commande qui n'est pas un shell comme vim, essayez : ttyd vim, le navigateur web vous affichera un éditeur vim.
  • Partage d'un processus unique avec plusieurs clients : ttyd tmux new -A -s ttyd vim, exécutez tmux new -A -s ttyd pour vous connecter à la session tmux depuis le terminal.

SSL comment-faire

Générez des certificats auto-signés pour CA et serveur/client SSL :

# Certificat CA (le FQDN doit être différent du serveur/client)
openssl genrsa -out ca.key 2048
openssl req -new -x509 -days 365 -key ca.key -subj "/C=CN/ST=GD/L=SZ/O=Acme, Inc./CN=Acme Root CA" -out ca.crt
# Certificat serveur (pour plusieurs domaines, changez subjectAltName en : DNS:example.com,DNS:www.example.com)
openssl req -newkey rsa:2048 -nodes -keyout server.key -subj "/C=CN/ST=GD/L=SZ/O=Acme, Inc./CN=localhost" -out server.csr
openssl x509 -sha256 -req -extfile <(printf "subjectAltName=DNS:localhost") -days 365 -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt
# Certificat client (le format p12/pem peut être utile pour certains clients)
openssl req -newkey rsa:2048 -nodes -keyout client.key -subj "/C=CN/ST=GD/L=SZ/O=Acme, Inc./CN=client" -out client.csr
openssl x509 -req -days 365 -in client.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out client.crt
openssl pkcs12 -export -clcerts -in client.crt -inkey client.key -out client.p12
openssl pkcs12 -in client.p12 -out client.pem -clcerts

Ensuite, démarrez ttyd :

ttyd --ssl --ssl-cert server.crt --ssl-key server.key --ssl-ca ca.crt bash

Vous voudrez peut-être tester la vérification du certificat client avec curl(1) :

curl --insecure --cert client.p12[:password] -v https://localhost:7681

Si vous ne souhaitez pas activer la vérification du certificat client, supprimez l'option --ssl-ca.

Docker et ttyd

Les conteneurs Docker sont des environnements isolés plus sécurisés, ce qui est utile pour protéger le système hôte. Vous pouvez utiliser ttyd avec Docker comme suit :

  • Partage d'un seul conteneur Docker avec plusieurs clients : docker run -it --rm -p 7681:7681 tsl0922/ttyd.
  • Création d'un nouveau conteneur Docker pour chaque client : ttyd docker run -it --rm ubuntu.

Proxy inverse Nginx

Exemple de configuration pour proxy ttyd sous le chemin /ttyd :

location ~ ^/ttyd(.*)$ {
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_pass http://127.0.0.1:7681/$1;
}
