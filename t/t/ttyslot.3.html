ttyslot(3) Manuel des fonctions de bibliothèque ttyslot(3)

NOM

ttyslot - trouver l'emplacement du terminal de l'utilisateur actuel dans un fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>       /* Voir NOTES */
int ttyslot(void);
Exigences pour les macros de test de fonctionnalités dans glibc (voir feature_test_macros(7)) :

ttyslot() :

    Depuis glibc 2.24 :
        _DEFAULT_SOURCE
    De glibc 2.20 à glibc 2.23 :
        _DEFAULT_SOURCE || (_XOPEN_SOURCE && _XOPEN_SOURCE < 500)
    glibc 2.19 et antérieur :
        _BSD_SOURCE || (_XOPEN_SOURCE && _XOPEN_SOURCE < 500)

DESCRIPTION

La fonction obsolète ttyslot() renvoie l'indice de l'entrée de l'utilisateur actuel dans un certain fichier.

Maintenant, "Quel fichier ?" demanderez-vous. Eh bien, regardons d'abord un peu d'histoire.

Histoire ancienne

Il existait un fichier /etc/ttys dans UNIX V6, qui était lu par le programme init(1) pour savoir quoi faire de chaque ligne de terminal. Chaque ligne était composée de trois caractères. Le premier caractère était soit '0' soit '1', où '0' signifiait "ignorer". Le deuxième caractère désignait le terminal : '8' représentait "/dev/tty8". Le troisième caractère était un argument pour getty(8) indiquant la séquence des débits de ligne à essayer ('-' signifiait : commencer à essayer 110 bauds). Ainsi, une ligne typique était "18-". Un décrochage sur une ligne était résolu en changeant le '1' en '0', en signalant init, en rechangeant le '0' en '1', et en signalant init à nouveau.

Dans UNIX V7, le format a été modifié : ici, le deuxième caractère était l'argument de getty(8) indiquant la séquence des débits de ligne à essayer ('0' signifiait : parcourir 300-1200-150-110 bauds ; '4' était pour la console en ligne DECwriter) tandis que le reste de la ligne contenait le nom du tty. Ainsi, une ligne typique était "14console".

Les systèmes ultérieurs ont une syntaxe plus élaborée. Les systèmes de type System V ont plutôt /etc/inittab.

Histoire ancienne (2)

D'un autre côté, il y a le fichier /etc/utmp qui liste les personnes actuellement connectées. Il est maintenu par login(1). Il a une taille fixe, et l'indice approprié dans le fichier était déterminé par login(1) en utilisant l'appel ttyslot() pour trouver le numéro de la ligne dans /etc/ttys (en comptant à partir de 1).

La sémantique de ttyslot

Ainsi, la fonction ttyslot() renvoie l'indice du terminal contrôleur du processus appelant dans le fichier /etc/ttys, et c'est (généralement) le même que l'indice de l'entrée de l'utilisateur actuel dans le fichier /etc/utmp. BSD a toujours le fichier /etc/ttys, mais les systèmes de type System V ne l'ont pas, et ne peuvent donc pas s'y référer. Par conséquent, sur ces systèmes, la documentation indique que ttyslot() renvoie l'indice de l'utilisateur actuel dans la base de données de comptabilité des utilisateurs.

VALEUR DE RETOUR

En cas de succès, cette fonction renvoie le numéro d'emplacement. En cas d'erreur (par exemple, si aucun des descripteurs de fichiers 0, 1 ou 2 n'est associé à un terminal qui apparaît dans cette base de données), elle renvoie 0 sur UNIX V6 et V7 et les systèmes de type BSD, mais -1 sur les systèmes de type System V.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
ttyslot () Sécurité des threads MT-Unsafe

VERSIONS

Le fichier utmp se trouve à divers endroits selon les systèmes, tels que /etc/utmp, /var/adm/utmp, /var/run/utmp.

NORMES

Aucune.

HISTORIQUE

SUSv1 ; marqué comme OBSOLÈTE dans SUSv2 ; supprimé dans POSIX.1-2001. SUSv2 exige -1 en cas d'erreur.

L'implémentation glibc2 de cette fonction lit le fichier _PATH_TTYS, défini dans <ttyent.h> comme "/etc/ttys". Elle renvoie 0 en cas d'erreur. Comme les systèmes Linux n'ont généralement pas de "/etc/ttys", elle renverra toujours 0.

Sur les systèmes de type BSD et Linux, la déclaration de ttyslot() est fournie par <unistd.h>. Sur les systèmes de type System V, la déclaration est fournie par <stdlib.h>. Depuis glibc 2.24, <stdlib.h> fournit également la déclaration avec les définitions de macros de test de fonctionnalités suivantes :


(_XOPEN_SOURCE >= 500 ||
        (_XOPEN_SOURCE && _XOPEN_SOURCE_EXTENDED))
    && ! (_POSIX_C_SOURCE >= 200112L || _XOPEN_SOURCE >= 600)

Minix a également fttyslot(fd).

VOIR AUSSI

getttyent(3), ttyname(3), utmp(5)
