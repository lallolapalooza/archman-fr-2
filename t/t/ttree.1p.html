NOM

Template::Tools::ttree - Traite des arborescences complètes de templates

SYNTAXE

ttree [options] [fichiers]

DESCRIPTION

Le script ttree est utilisé pour traiter des arborescences complètes de répertoires contenant des fichiers templates. Le résultat du traitement de chaque fichier est ensuite écrit dans un fichier correspondant dans un répertoire de destination. Le script compare les dates de modification des fichiers source et destination (lorsqu'ils existent déjà) et ne traite que les fichiers qui ont été modifiés. En d'autres termes, c'est l'équivalent de 'make' pour le Template Toolkit.

Il supporte un certain nombre d'options qui peuvent être utilisées pour configurer le comportement, définir des emplacements et des options du Template Toolkit. Le script lit d'abord le fichier de configuration .ttreerc dans le répertoire HOME, ou un fichier alternatif spécifié dans la variable d'environnement TTREERC. Ensuite, il traite les arguments de la ligne de commande, y compris les fichiers de configuration supplémentaires spécifiés via l'option "-f" (fichier).

Le fichier de configuration .ttreerc

Lorsque vous exécutez ttree pour la première fois, il vous demandera si vous souhaitez qu'il crée un fichier .ttreerc pour vous. Celui-ci sera créé dans votre répertoire personnel.

$ ttree
Voulez-vous que je crée un fichier '.ttreerc' d'exemple pour vous ?
(fichier: /home/abw/.ttreerc)   [o/n] : o
/home/abw/.ttreerc créé. Veuillez l'éditer en conséquence et relancer ttree

Le but de ce fichier est de définir toutes les options de configuration globales que vous souhaitez appliquer à chaque fois que ttree est exécuté. Par exemple, vous pouvez utiliser les options "ignore" et "copy" / "link" pour spécifier des expressions régulières qui définissent quels fichiers doivent être ignorés et lesquels doivent être copiés ou liés plutôt que d'être traités comme des templates. Vous pouvez également définir des drapeaux comme "verbose" et "recurse" selon vos préférences.

Un .ttreerc minimal :

# ignorer ces fichiers
ignore = \b(CVS|RCS)\b
ignore = ^#
ignore = ~$
# copier ces fichiers
copy   = \.(gif|png|jpg|pdf)$
# parcourir récursivement les répertoires
recurse
# fournir des informations sur ce qui se passe
verbose

Dans la plupart des cas, vous voudrez créer un fichier de configuration ttree différent pour chaque projet sur lequel vous travaillez. L'option "cfg" vous permet de spécifier un répertoire où ttree peut trouver d'autres fichiers de configuration.

cfg = /home/abw/.ttree

L'option de ligne de commande "-f" peut être utilisée pour spécifier quel fichier de configuration doit être utilisé. Vous pouvez spécifier un nom de fichier en utilisant un chemin absolu ou relatif :

$ ttree -f /home/abw/web/exemple/etc/ttree.cfg
$ ttree -f ./etc/ttree.cfg
$ ttree -f ../etc/ttree.cfg

Si le fichier de configuration ne commence pas par "/" ou "." ou quelque chose qui ressemble à un chemin absolu MS-DOS (par exemple, "C:\\etc\\ttree.cfg"), alors ttree le recherchera dans le répertoire spécifié par l'option "cfg".

$ ttree -f test1          # /home/abw/.ttree/test1

L'option "cfg" ne peut être utilisée que dans le fichier .ttreerc. Toutes les autres options peuvent être utilisées dans le fichier .ttreerc ou dans tout autre fichier de configuration ttree. Elles peuvent toutes également être spécifiées comme options en ligne de commande.

N'oubliez pas que .ttreerc est toujours traité avant tout fichier de configuration spécifié avec l'option "-f". Certaines options comme "lib" peuvent être utilisées un nombre illimité de fois et leurs valeurs s'accumulent.

Par exemple, considérons les fichiers de configuration suivants :

/home/abw/.ttreerc :

cfg = /home/abw/.ttree
lib = /usr/local/tt2/templates

/home/abw/.ttree/myconfig :

lib = /home/abw/web/exemple/templates/lib

Lorsque ttree est invoqué comme suit :

$ ttree -f myconfig

l'option "lib" sera définie pour les répertoires suivants :

/usr/local/tt2/templates
/home/abw/web/exemple/templates/lib

Tous les templates situés dans /usr/local/tt2/templates seront utilisés de préférence à ceux situés dans /home/abw/web/exemple/templates/lib. C'est peut-être ce que vous voulez, mais peut-être pas. Pour cette raison, il est bon de garder .ttreerc aussi simple que possible et d'utiliser des fichiers de configuration différents pour chaque projet ttree.

Options de répertoire

L'option "src" est utilisée pour définir le répertoire contenant les templates sources à traiter. Elle peut être fournie en option de ligne de commande ou dans un fichier de configuration comme montré ici :

src = /home/abw/web/exemple/templates/src

Chaque template de ce répertoire correspond typiquement à une seule page web ou à un autre document.

L'option "dest" est utilisée pour spécifier le répertoire de destination pour la sortie générée.

dest = /home/abw/web/exemple/html

L'option "lib" est utilisée pour définir un ou plusieurs répertoires contenant des templates de bibliothèque supplémentaires. Ces templates ne sont pas des documents en soi et comprennent généralement des composants plus petits et modulaires comme des en-têtes, des pieds de page et des menus qui sont incorporés dans les templates de pages.

lib = /home/abw/web/exemple/templates/lib
lib = /usr/local/tt2/templates

L'option "lib" peut être utilisée de manière répétée pour ajouter d'autres répertoires au chemin de recherche.

Une liste de templates peut être passée à ttree comme arguments de ligne de commande.

$ ttree foo.html bar.html

Il recherche ces templates dans le répertoire "src" et les traite via le Template Toolkit, en utilisant tout composant de template supplémentaire des répertoires "lib". La sortie générée est ensuite écrite dans le fichier correspondant dans le répertoire "dest".

Si ttree est invoqué sans spécifier explicitement de templates à traiter, il traitera tous les fichiers du répertoire "src". Si l'option "-r" (récursif) est définie, il parcourra en plus les sous-répertoires et traitera tous les autres fichiers templates qu'il y trouvera.

$ ttree -r

Si un template a déjà été traité, ttree comparera les dates de modification des fichiers source et destination. Si le template source (ou un fichier dont il dépend) n'a pas été modifié plus récemment que le fichier de sortie généré, ttree ne le traitera pas. L'option -a (tout) peut être utilisée pour forcer ttree à traiter tous les fichiers, quelle que soit leur date de modification.

$ tree -a

Tous les templates explicitement nommés en argument de ligne de commande sont toujours traités et la vérification de la date de modification est contournée.

Options de fichier

Les options "ignore", "copy", "link" et "accept" sont utilisées pour spécifier des expressions régulières Perl pour filtrer les noms de fichiers. Les fichiers qui correspondent à l'une des options "ignore" ne seront pas traités. Les fichiers restants qui correspondent à l'une des expressions régulières "copy" ou "link" seront copiés ou liés dans le répertoire de destination. Les fichiers situés dans l'un des répertoires "copy_dir" sont également copiés. Les fichiers restants qui correspondent ensuite à l'un des critères "accept" sont ensuite traités via le Template Toolkit. Si aucun paramètre "accept" n'est spécifié, tous les fichiers seront acceptés pour le traitement s'ils n'ont pas déjà été copiés ou ignorés.

# ignorer ces fichiers
ignore = \b(CVS|RCS)\b
ignore = ^#
ignore = ~$
# copier ces fichiers
copy   = \.(gif|png|jpg|pdf)$
# accepter uniquement les templates .tt2
accept = \.tt2$

L'option "suffix

" l'option est utilisée pour définir des correspondances entre les extensions de fichiers pour les modèles source et les fichiers de sortie générés. L'exemple suivant spécifie que les modèles source avec un suffixe ".tt2" doivent être générés en fichiers ".html" :

suffixe tt2=html

Ou sur la ligne de commande :

--suffixe tt2=html

Vous pouvez fournir un nombre quelconque de correspondances de suffixes différentes en répétant cette option.

L'option "binmode" est utilisée pour définir l'encodage du fichier de sortie. Par exemple, utilisez "--binmode=:utf8" pour définir le format de sortie en unicode.

Dépendances des modèles

Les options "depend" et "depend_file" vous permettent de spécifier comment un fichier modèle donné dépend d'un autre fichier ou groupe de fichiers. L'option "depend" est utilisée pour exprimer une seule dépendance.

$ ttree --depend foo=bar,baz

Cet exemple de ligne de commande montre l'option "--depend" utilisée pour spécifier que le fichier foo dépend des modèles bar et baz. Cette option peut être utilisée plusieurs fois sur la ligne de commande :

$ ttree --depend foo=bar,baz --depend crash=bang,wallop

ou dans un fichier de configuration :

depend foo=bar,baz
depend crash=bang,wallop

Le fichier apparaissant à gauche de "=" est spécifié par rapport aux répertoires "src" ou "lib". Le(s) fichier(s) apparaissant à droite peuvent être spécifiés par rapport à n'importe lequel de ces répertoires ou comme des chemins de fichiers absolus.

Par exemple :

$ ttree --depend foo=bar,/tmp/baz

Pour définir une dépendance qui s'applique à tous les fichiers, utilisez "*" à gauche de "=".

$ ttree --depend *=header,footer

ou dans un fichier de configuration :

depend *=header,footer

Tous les modèles définis dans les options "pre_process", "post_process", "process" ou "wrapper" seront automatiquement ajoutés à la liste des dépendances globales qui s'appliquent à tous les modèles.

L'option "depend_file" peut être utilisée pour spécifier un fichier contenant des informations de dépendance.

$ ttree --depend_file=/home/abw/web/example/etc/ttree.dep

Voici un exemple de fichier de dépendances :

# Ceci est un commentaire. Il est ignoré.
index.html: header footer menubar
header: titlebar hotlinks
menubar: menuitem
# s'étendant sur plusieurs lignes avec le backslash
another.html: header footer menubar \
sidebar searchform

Les lignes commençant par le caractère "#" sont des commentaires et sont ignorées. Les lignes vides sont également ignorées. Toutes les autres lignes doivent fournir un nom de fichier suivi d'un deux-points, puis d'une liste de fichiers dépendants séparés par des espaces, des virgules ou les deux. Les espaces autour du deux-points sont également facultatifs. Les lignes se terminant par le caractère "\" sont continuées sur la ligne suivante.

Les fichiers contenant des espaces peuvent être mis entre guillemets. Ceci n'est nécessaire que pour les fichiers après le deux-points (':'). Le fichier avant le deux-points peut être mis entre guillemets s'il contient un deux-points.

Comme pour les options de ligne de commande, le caractère "*" peut être utilisé comme joker pour spécifier une dépendance pour tous les modèles.

* : config,header

Options de Template Toolkit

ttree donne également accès à la gamme habituelle d'options de Template Toolkit. Par exemple, les options ttree "--pre_chomp" et "--post_chomp" correspondent aux options "PRE_CHOMP" et "POST_CHOMP".

Exécutez "ttree -h" pour un résumé des options disponibles.
