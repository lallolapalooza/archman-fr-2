TTF2TFM(1) Manuel des commandes générales TTF2TFM(1)

NOM

ttf2tfm - construire des fichiers métriques TeX à partir d'une police TrueType

SYNTAXE

ttf2tfm
fichier.ttf[.ttf|.ttc] [-c facteur-hauteur-caps] [-e facteur-extension] [-E id-encodage] [-f index-police] [-l] [-L fichier-ligature[.sfd]] [-n] [-N] [-O] [-p fichier-enc-entree[.enc]] [-P id-plateforme] [-q] [-r nom-glyphe-ancien nom-glyphe-nouveau] [-R fichier-remplacement[.rpl]] [-s facteur-inclinaison] [-t fichier-enc-sortie[.enc]] [-T fichier-enc-entree-sortie[.enc]] [-u] [-v fichier-vpl[.vpl]] [-V fichier-vpl-sc[.vpl]] [-w] [-x] [-y facteur-decalage-vertical] fichier-tfm[.tfm]]

ttf2tfm --version | --help

DESCRIPTION

Ce programme extrait les informations métriques et de crénage d'une police TrueType et les convertit en fichiers métriques utilisables par TeX (très similaire à afm2tfm qui fait partie du paquet dvips ; veuillez consulter ses fichiers d'information pour plus de détails sur les divers paramètres (en particulier les fichiers d'encodage).

Comme une police TrueType contient souvent plus de 256 glyphes, certains moyens sont nécessaires pour mapper un sous-ensemble des glyphes TrueType à une police TeX. Pour ce faire, deux tables de mappage sont nécessaires : la première (appelée encodage `entrée' ou `brut') mappe la police TrueType à une police TeX brute (cette table de mappage est utilisée par ttf2tfm et ttf2pk), et la seconde (appelée encodage `sortie' ou `virtuel') mappe la police TeX brute à une autre police TeX (virtuelle), fournissant toutes les informations de crénage et de ligature nécessaires à TeX.

Ce mappage en deux étapes présente l'avantage qu'une seule police brute peut être accédée avec divers encodages LaTeX (par exemple, T1 et OT1) via le mécanisme de polices virtuelles, et un seul fichier PK est nécessaire.

Pour les polices CJKV (chinois/japonais/coréen/vietnamien ancien), un mécanisme différent est fourni (voir ci-dessous la section FICHIERS DE DÉFINITION DE SOUS-POLICE).

PARAMETRES

La plupart des noms de commutateurs de ligne de commande sont les mêmes que dans afm2tfm par commodité. Un ou plusieurs espaces entre une option et sa valeur sont obligatoires ; les options ne peuvent pas être concaténées. Pour des raisons historiques, le premier paramètre ne peut *pas* être un commutateur mais doit être le nom de la police.

-c facteur-hauteur-caps
La hauteur des petites capitales créées avec le commutateur -V. La valeur par défaut de ce nombre réel est 0,8 fois la hauteur des glyphes en majuscules.
Sera ignoré en mode sous-police.
-e facteur-extension
Le facteur d'extension pour étirer les caractères horizontalement. La valeur par défaut de ce nombre réel est 1,0 ; si elle est inférieure à 1,0, vous obtenez une police condensée.
-E id-encodage
L'ID d'encodage TrueType. La valeur par défaut de cet entier non négatif est 1.
Sera ignoré si -N est utilisé.
-f index-police
L'index de la police dans une Collection TrueType. Par défaut, c'est la première police (index 0). [Les collections TrueType se trouvent généralement dans certaines polices CJK ; par exemple, le premier index de police spécifie les glyphes et les métriques pour l'écriture horizontale, et le second index de police fait de même pour l'écriture verticale. Les collections TrueType ont généralement l'extension `.ttc'.]
Sera ignoré pour les polices TrueType ordinaires.
-l
Crée des ligatures dans les sous-polices entre le premier et le second octet de tous les codes de caractères d'origine. Exemple : Le code de caractère 0xABCD correspond à la position de caractère 123 dans la sous-police 45. Ensuite, une ligature dans la sous-police 45 entre les positions 0xAB et 0xCD pointant vers le caractère 123 sera produite. Les polices du paquet HLaTeX coréen utilisent cette fonctionnalité. Notez que cette option génère des ligatures correctes uniquement pour les polices TrueType où le cmap d'entrée est identique à l'encodage de sortie. Dans le cas de HLaTeX, les TTF doivent avoir l'ID de plateforme 3 et l'ID d'encodage 5.
Sera ignoré si ce n'est pas en mode sous-police.
-L fichier-ligature
Identique à -l, mais les codes de caractères pour les ligatures sont spécifiés dans le fichier-ligature. Par exemple, `-L KS-HLaTeX' génère des ligatures correctes pour le paquet HLaTeX coréen, quel que soit l'ID de plateforme et l'ID d'encodage de la police TrueType utilisée (le fichier KS-HLaTeX.sfd fait partie du paquet ttf2pk).
Les fichiers de ligature ont le même format et la même extension que les fichiers SFD. Cette option sera ignorée si ce n'est pas en mode sous-police.
-n
Utilise les noms PS (des glyphes) de la police TrueType. Seuls les glyphes ayant une entrée valide dans le cmap sélectionné sont utilisés.
Sera ignoré en mode sous-police.
-N
Utilise uniquement les noms PS de la police TrueType. Aucun cmap n'est utilisé, donc les commutateurs -E et -P n'ont aucun effet, provoquant un message d'avertissement.
Sera ignoré en mode sous-police.
-O
Utilise des valeurs octales pour tous les codes de caractères dans le fichier VPL au lieu de noms ; ceci est utile pour les polices de symboles ou CJK où les noms de caractères tels que `A' sont dénués de sens.
-p fichier-enc-entree
Le nom du fichier d'encodage d'entrée pour le mappage TTF→Tex brut. Ce paramètre doit être spécifié dans un fichier de mappage (par défaut : ttfonts.map) enregistré dans ttf2pk.cfg pour les appels successifs à ttf2pk.
Sera ignoré en mode sous-police.
-P id-plateforme
L'ID de plateforme TrueType. La valeur par défaut de cet entier non négatif est 3.
Sera ignoré si -N est utilisé.
-q
Rend ttf2tfm silencieux. Il supprime toute sortie d'information, sauf les messages d'avertissement et d'erreur. Pour les polices CJK, la sortie peut devenir assez volumineuse si vous ne spécifiez pas ce commutateur.
-r nom-glyphe-ancien nom-glyphe-nouveau
Remplace nom-glyphe-ancien par nom-glyphe-nouveau. Ce commutateur est utile si vous souhaitez donner un nom à un glyphe sans nom (c'est-à-dire un glyphe qui ne peut être représenté qu'avec `.gXXX' ou `.cXXX') ou si vous souhaitez renommer un nom de glyphe existant. Vous ne pouvez pas utiliser les constructions de noms de glyphes `.gXXX' ou `.cXXX' pour nom-glyphe-nouveau ; plusieurs occurrences de -r sont possibles.
Si en mode sous-police ou si aucun fichier d'encodage n'est spécifié, ce commutateur est ignoré.
-R fichier-remplacement
Utilisez ce commutateur si vous avez de nombreuses paires de remplacement ; elles peuvent être collectées dans un fichier qui devrait avoir l'extension `.rpl'. La syntaxe utilisée dans de tels fichiers de remplacement est simple : chaque ligne non vide doit contenir une paire `nom-glyphe-ancien nom-glyphe-nouveau' séparée par des espaces blancs (sans les guillemets). Un signe de pourcentage commence un commentaire de ligne ; vous pouvez continuer une ligne sur la ligne suivante avec une barre oblique inverse comme dernier caractère.
Si en mode sous-police ou si aucun fichier d'encodage n'est spécifié, ce commutateur est ignoré.
-s facteur-inclinaison
Le facteur d'obliquité pour incliner la police, généralement beaucoup plus petit que 1. La valeur par défaut de ce nombre réel est 0,0 ; si la valeur est supérieure à zéro, les caractères penchent vers la droite, sinon vers la gauche.
-t� A0;outencfile
Le nom du fichier de codage de sortie pour la (les) police(s) virtuelle(s). Seuls les caractères de la police TeX brute sont utilisés.
Sera ignoré en mode sous-police.
-T inoutencfile
Ceci est équivalent à `-p inoutencfile -t inoutencfile'.
Sera ignoré en mode sous-police.
-u
Utiliser uniquement les caractères spécifiés dans le codage de sortie, et aucun autre. Par défaut, ttf2tfm essaie d'inclure tous les caractères de la police virtuelle, même ceux qui ne sont pas présents dans le codage de la police virtuelle (il les place dans des positions autrement inutilisées, de manière assez arbitraire).
Sera ignoré en mode sous-police.
-v vplfile
Produire un fichier VPL en plus du fichier TFM. Si aucun fichier de codage de sortie n'est spécifié, ttf2tfm utilise un codage de police par défaut (cmtt10). Remarque : Veillez à utiliser des noms différents pour la police virtuelle et la police brute !
Sera ignoré en mode sous-police.
-V scvplfile
Identique à -v, mais la police virtuelle générée est une police pseudo petites capitales obtenue en redimensionnant les lettres majuscules par 0,8 (resp. la valeur spécifiée avec -c) pour composer les lettres minuscules. Cette police gère les lettres accentuées et conserve un crénage correct.
Sera ignoré en mode sous-police.
-w
Générer des vecteurs d'encodage PostScript contenant des indices de glyphes, principalement utilisés pour intégrer les polices TrueType dans pdfTeX. ttf2tfm prend les noms TFM et remplace le suffixe par .enc ; c'est-à-dire que pour les fichiers foo01.tfm, foo02.tfm, ... il crée foo01.enc, foo02.enc, ... au même endroit.
Sera ignoré si pas en mode sous-police.
-x
Faire pivoter tous les glyphes de 90 degrés dans le sens inverse des aiguilles d'une montre. Si aucun paramètre -y n'est donné, les glyphes pivotés sont décalés verticalement vers le bas de 0,25em.
Sera ignoré si pas en mode sous-police.
-y vertical-shift-factor
Décaler vers le bas les glyphes pivotés de la quantité donnée (l'unité est em).
Ignoré si pas en mode sous-police ou si les glyphes ne sont pas pivotés.
--version
Affiche la version actuelle de ttf2tfm et de la bibliothèque de recherche de fichiers utilisée (par exemple, kpathsea).
--help
Affiche les informations d'utilisation.

Si aucun nom de fichier TFM n'est donné, le nom du fichier TTF est utilisé, y compris le chemin complet et le remplacement de l'extension par `.tfm'.

CMAPS

Contrairement aux polices PostScript Type 1 (mais similaire au nouveau format de police PostScript CID), la plupart des polices TrueType ont plus d'une table de mappage native, également appelée `cmap', qui mappe les indices de glyphes TTF (internes) aux codes de caractères TTF (externes). Les exemples courants incluent une table de mappage vers les positions de caractères codées en Unicode, et le mappage Macintosh standard.

Pour spécifier une table de mappage TrueType, utilisez les options -P et -E. Avec -P, vous spécifiez l'ID de la plateforme ; les valeurs définies sont :

Le programme s'arrêtera si vous spécifiez une paire d'ID de plateforme/codage invalide. Il affichera alors les paires pid/eid possibles. Veuillez noter que la plupart des polices ont au plus deux ou trois cmaps, correspondant généralement aux paires pid/eid (1,0), (3,0) ou (3,1) pour les polices basées sur le latin. Les polices Microsoft valides devraient avoir une table de mappage (3,1), mais certaines polices existent (principalement des polices asiatiques) qui ont un cmap (3,1) non codé en Unicode. La raison de ce comportement étrange est le fait que certaines anciennes versions de MS Windows rejetteront les polices ayant un cmap non-(3,1) (car tous les ID de codage Microsoft non-Unicode sont pour les versions asiatiques de MS Windows).

Les options -P et -E de ttf2tfm doivent être spécifiées de la même manière pour ttf2pk ; les paramètres correspondants dans un fichier de mappage sont respectivement `Pid' et `Eid'.

La paire pid/eid par défaut est (3,1).

De même, une option -f doit être spécifiée comme paramètre `Fontindex' dans un fichier de mappage.

Si vous utilisez le commutateur -N, tous les cmaps sont ignorés, en utilisant uniquement les noms PostScript dans la police TrueType. L'option correspondante dans un fichier de mappage est `PS=Only'. Si vous utilisez le commutateur -n, les noms de glyphes par défaut intégrés à ttf2tfm sont remplacés par les noms de glyphes PS trouvés dans la police. Dans de nombreux cas, ce n'est pas ce que vous souhaitez, car les noms de glyphes dans la police sont souvent incorrects ou non standard. L'option correspondante dans un fichier de mappage est `PS=Yes'.

Les noms de glyphes de remplacement uniques spécifiés avec -r doivent être donnés directement sous la forme `ancien-nomdeglyphe nouveau-nomdeglyphe' dans un fichier de mappage ; -R est équivalent à l'option `Replacement'.

ENCODAGES D'ENTRÉE ET DE SORTIE

Vous devez spécifier les vecteurs d'encodage de la police TrueType vers la police TeX brute et de la police TeX brute vers la police TeX virtuelle exactement comme avec afm2tfm, mais vous avez plus de possibilités pour adresser les codes de caractères. [Par `vecteur d'encodage', on entend une table de mappage avec 256 entrées sous forme de vecteur PostScript ; voir le fichier T1-WGL4.enc de ce package pour un exemple.] Avec afm2tfm, vous devez accéder à chaque glyphe par son nom de glyphe Adobe, par exemple `/quotedsingle' ou `/Acircumflex'. Ceci a été étendu avec ttf2tfm ; maintenant, vous pouvez (et parfois devez) accéder directement aux points de code et/ou aux glyphes, en utilisant la syntaxe suivante pour spécifier la position du caractère en notation décimale, octale ou hexadécimale : `/.c<nombre-décimal>', `/.c0<nombre-octal>', ou `/.c0x<nombre-hexadécimal>'. Exemples : `/.c72', `/.c0646', `/.c0x48'. Pour accéder directement à un indice de glyphe, utilisez le caractère `g' au lieu de `c' dans la notation que nous venons d'introduire. Exemple : `/.g0x32'. [Note : La notation `.cXXX' n'a aucun sens si -N est utilisé.]

Pour les paires pid/eid (1,0) et (3,1), ttf2tfm et ttf2pk reconnaissent les noms de glyphes Adobe par défaut intégrés ; le premier suit les noms donnés dans l'annexe E du livre `Inside Macintosh', volume 6, le second utilise les noms donnés dans la spécification TrueType (WGL4, un sous-ensemble Unicode). Notez que les noms Adobe pour un glyphe donné ne sont souvent pas uniques et diffèrent parfois, par exemple, de nombreuses polices PS ont le glyphe `mu', alors que ce glyphe s'appelle `mu1' dans le jeu de caractères WGL4 pour le distinguer de la vraie lettre grecque mu. Soyez également conscient que les polices OpenType (c'est-à-dire TrueType 2.0) utilisent une table WGL4 mise à jour ; nous utilisons les données de la dernière spécification TrueType publiée (1.66). Vous pouvez trouver ces tables de mappage dans le fichier source ttfenc.c.

D'autre part, les commutateurs -n et -N font que

ttf2tfm lit et utilise les noms PostScript dans la police TrueType elle-même (stockés dans la table `post') au lieu des noms de glyphes Adobe par défaut.

Utilisez le commutateur -r pour remapper des noms de glyphes uniques et -R pour spécifier un fichier contenant des paires de noms de glyphes de remplacement.

Si vous ne sélectionnez pas d'encodage d'entrée, les 256 premiers glyphes de la police TrueType avec une entrée valide dans le cmap sélectionné seront mappés à la police TeX brute (sans l'option -q, ttf2tfm imprime cette table de mappage sur la sortie standard), suivis de tous les glyphes non encore abordés dans le cmap sélectionné. Cependant, certains points de code pour la paire pid/eid (1,0) sont omis car ils ne représentent pas de glyphes utiles pour TeX : 0x00 (null), 0x08 (backspace), 0x09 (horizontal tabulation), 0x0d (carriage return) et 0x1d (group separator). Le caractère `invalid character' avec l'index de glyphe 0 sera également omis.

Si vous sélectionnez le commutateur -N, les 256 premiers glyphes de la police TrueType avec un nom PostScript valide seront utilisés si aucun encodage d'entrée n'est spécifié. Encore une fois, certains glyphes sont omis : `.notdef', `.null' et `nonmarkingreturn'.

Si vous ne sélectionnez pas d'encodage de sortie, ttf2tfm utilise la même table de mappage que celle utilisée par afm2tfm (vous pouvez la trouver dans le fichier source texenc.c) ; elle correspond au texte machine à écrire de TeX. Les positions inutilisées (causées par des points de code vides dans la table de mappage ou des glyphes manquants dans la police TrueType) seront remplies (de manière plutôt arbitraire) avec des caractères présents dans l'encodage d'entrée mais non spécifiés dans l'encodage de sortie (sans l'option -q, ttf2tfm imprime l'encodage de sortie final sur la sortie standard). Utilisez l'option -u si vous ne souhaitez que les glyphes de la police virtuelle qui sont définis dans le fichier d'encodage de sortie, et rien de plus.

Une fonctionnalité manquante dans afm2tfm a été ajoutée et est nécessaire pour l'encodage T1 de LaTeX : ttf2tfm construira le glyphe `Germandbls' (en concaténant simplement deux glyphes `S') même pour les polices normales si possible. Il apparaît dans la liste des glyphes comme le dernier élément, marqué d'un astérisque. Comme il ne s'agit pas d'un glyphe réel, il ne sera disponible que dans la police virtuelle.

Pour les deux encodages d'entrée et de sortie, une position de code vide est représentée par le nom de glyphe `/.notdef'.

Dans les fichiers d'encodage, vous pouvez utiliser `\' comme caractère final d'une ligne pour indiquer que l'entrée est poursuivie sur la ligne suivante. La barre oblique inverse et le caractère de nouvelle ligne qui suit seront supprimés.

FICHIERS DE DEFINITION DE SOUS-POLICES

Les polices CJKV (Chinois/Japonais/Coréen/Ancien Vietnamien) contiennent généralement plusieurs milliers de glyphes ; pour les utiliser avec TeX, il est nécessaire de diviser ces grandes polices en sous-polices. Les fichiers de définition de sous-polices (ayant généralement l'extension `.sfd') sont un moyen simple d'y parvenir en douceur.

Le nom d'un fichier de sous-police se compose généralement d'un préfixe, d'un infixe de sous-police et d'un postfixe (qui est généralement vide), par exemple.


ntukai23 → préfixe : ntukai, infixe : 23, postfixe : (vide)

Voici la syntaxe d'une ligne dans un fichier SFD, décrivant une sous-police :

<espace> <infixe> <espace> <plages> <espace>
<infixe> :=
tout sauf des espaces. Il est préférable d'utiliser uniquement des caractères alphanumériques.
<espace> :=
espace, saut de page, retour chariot, tabulations horizontales et verticales -- pas de caractères de nouvelle ligne.
<plages> :=
<plages> <espace> <point de code> |
<plages> <espace> <plage> |
<plages> <espace> <décalage> <espace> <plage>
<point de code> :=
<nombre>
<plage> :=
<nombre> `_' <nombre>
<décalage> :=
<nombre> `:'
<nombre> :=
hexadécimal (préfixe `0x'), décimal ou octal (préfixe `0')

Une ligne peut être continuée sur la ligne suivante avec une barre oblique inverse terminant la ligne. Les plages ne doivent pas se chevaucher ; les décalages doivent être compris entre 0 et 255.

Exemple :


La ligne


03 10: 0x2349 0x2345_0x2347


attribue aux positions de code 10, 11, 12 et 13 de la sous-police ayant l'infixe `03' les codes de caractère 0x2349, 0x2345, 0x2346 et 0x2347 respectivement.

Les fichiers SFD de la distribution sont personnalisés pour le package CJK pour LaTeX.

Vous devez intégrer le nom du fichier SFD dans le nom de la police TFM (à l'endroit où l'infixe apparaîtra) entouré de deux signes `@', sur la ligne de commande ou dans un fichier de mappage ; ttf2tfm et ttf2pk passent alors en mode sous-police.

Il est possible d'utiliser plus d'un fichier SFD en les séparant par des virgules et sans espace ; pour une sous-police donnée, le premier fichier est analysé pour une entrée, puis le fichier suivant, et ainsi de suite. Les entrées ultérieures remplacent les entrées trouvées précédemment (éventuellement seulement partiellement). Par exemple, le premier fichier SFD configure la plage 0x10-0xA0, et le suivant modifie les entrées 0x12 et 0x25. Comme on peut facilement le constater, cet algorithme permet d'ajouter et de remplacer, mais pas de supprimer des entrées.

Le mode sous-police désactive les options -n, -N, -p, -r, -R, -t, -T, -u, -v, -V et -w pour ttf2tfm ; de même, aucun paramètre `Encoding' ou `Replacement' n'est autorisé dans un fichier de mappage. Les noms de glyphes de remplacement uniques sont également ignorés.

ttf2tfm créera tous les fichiers TFM de sous-police spécifiés dans les fichiers SFD (à condition que la sous-police contienne des glyphes) en une seule exécution.

Exemple :


L'appel


ttf2tfm ntukai.ttf ntukai@Big5,Big5-supp@


utilisera Big5.sfd et Big5-supp.sfd, produisant tous les fichiers de sous-police ntukai01.tfm, ntukai02.tfm, etc.

VALEUR DE RETOUR

ttf2tfm renvoie 0 en cas de succès et 1 en cas d'erreur ; les messages d'avertissement et d'erreur sont écrits sur la sortie d'erreur standard.

QUELQUES NOTES SUR LA RECHERCHE DE FICHIERS

ttf2pk et ttf2tfm utilisent soit la bibliothèque kpathsea, emtexdir, soit MiKTeX pour rechercher des fichiers (emtexdir ne fonctionnera que sur les systèmes d'exploitation ayant un environnement de type MS-DOS, c'est-à-dire MS-DOS, OS/2, Windows ; MikTeX est spécifique à MS Windows).

En dernier recours, les deux programmes peuvent être compilés sans bibliothèque de recherche ; les fichiers recherchés doivent alors se trouver dans le répertoire courant ou être spécifiés avec un chemin. Les extensions par défaut seront également ajoutées (à l'exception que seul `.ttf' est ajouté et non `.ttc').

kpathsea

La version actuelle de kpathsea est affichée à l'écran si vous appelez ttf2pk ou ttf2tfm avec le commutateur de ligne de commande --version.

Voici un tableau des types de fichiers et des variables kpathsea correspondantes. TTF2PKINPUTS et TTF2TFMINPUTS sont des variables d'environnement spécifiques au programme introduites dans kpathsea version 3.2 :

.ttf et .ttc TTFONTS
ttf2pk.cfg TTF2PKINPUTS
.map TTF2PKINPUTS
.enc TTF2PKINPUTS, TTF2TFMINPUTS
.rpl TTF2PKINPUTS, TTF2TFMINPUTS
.tfm TFMFONTS
.sfd TTF2PKINPUTS, TTF2TFMINPUTS

Veuillez consulter les fichiers d'information de kpathsea pour plus de détails sur ces variables.

Vous devriez définir la variable TEXMFCNF sur le répertoire où se trouve votre fichier de configuration texmf.cnf.

Voici la commande appropriée pour savoir à quelle valeur une variable kpathsea est définie (nous utilisons TTFONTS comme exemple). Ceci est particulièrement utile si une variable n'est pas définie dans texmf.cnf ou dans l'environnement, pointant ainsi vers la valeur par défaut qui est codée en dur dans la bibliothèque kpathsea.

kpsewhich -progname=ttf2tfm -expand-var='$TTFONTS'

Nous sélectionnons également le nom du programme car il est possible de spécifier des variables qui sont recherchées uniquement pour un programme donné -- dans notre exemple, ce serait TTFONTS.ttf2tfm.

Une méthode similaire, mais pas identique, consiste à dire


kpsewhich -progname=ttf2tfm -show-path='truetype fonts'

[Une liste complète des types de formats peut être obtenue en tapant `kpsewhich --help' à l'invite de commande.] C'est exactement ainsi que ttf2tfm (et ttf2pk) recherche les fichiers ; le désavantage est que toutes les variables sont développées, ce qui peut entraîner des chaînes très longues.

emtexdir

Voici la liste des suffixes et leurs variables d'environnement associées à définir dans autoexec.bat (resp. dans config.sys pour OS/2) :

.ttf et .ttc TTFONTS
ttf2pk.cfg TTFCFG
.map TTFCFG
.enc TTFCFG
.rpl TTFCFG
.tfm TEXTFM
.sfd TTFCFG

Si l'une des variables n'est pas définie, un message d'avertissement est émis. Le répertoire courant sera toujours recherché. Comme d'habitude, un point d'exclamation ajouté à un chemin de répertoire entraîne la recherche des sous-répertoires à un niveau de profondeur, deux points d'exclamation entraînent la recherche de tous les sous-répertoires. Exemple :


TTFONTS=c:\fonts\truetype!!;d:\myfonts\truetype!

Des constructions comme `c:\fonts!!\truetype' ne sont pas possibles.

MiKTeX

ttf2tfm et ttf2pk ont été entièrement intégrés à MiKTeX. Veuillez vous référer à la documentation de MiKTeX pour plus de détails sur la recherche de fichiers.

PROBLEMES

De nombreuses implémentations de vptovf n'autorisent que 100 octets pour l'en-tête TFM (la limite est de 1024 dans le format de fichier TFM lui-même) : 8 octets

pour les sommes de contrôle et la taille de conception, 40 octets pour le nom de famille, 20 octets pour l'encodage et 4 octets pour un octet de face. Il ne reste que 28 octets pour des informations supplémentaires utilisées par ttf2tfm pour une chaîne d'identification (qui est essentiellement une copie de la ligne de commande), et cette limite est toujours dépassée.

La solution optimale consiste à augmenter la valeur de max_header_bytes dans le fichier vptovf.web (et probablement pltotf.web aussi) à, disons, 400 et à recompiler vptovf (et pltotf). Sinon, vous obtiendrez des messages d'erreur (inoffensifs) comme


Cet index d'en-tête est trop grand pour la taille actuelle de ma table

qui peut être ignoré sans risque.
