NOM

ttk::intro - Introduction au moteur de thèmes Tk

APERÇU

L'ensemble de widgets thèmes Tk est basé sur une version révisée et améliorée de TIP #48 (https://tip.tcl-lang.org/48) spécifiant un moteur de style. Les concepts principaux sont décrits ci-dessous. L'idée principale est de séparer, dans la mesure du possible, le code implémentant le comportement d'un widget du code implémentant son apparence. Les liaisons de classe de widgets sont principalement responsables du maintien de l'état du widget et de l'invocation des rappels ; tous les aspects de l'apparence du widget sont contrôlés par le style du widget (c'est-à-dire le style des éléments du widget).

THÈMES

Un thème est une collection d'éléments et de styles qui déterminent l'apparence de l'ensemble de widgets. Les thèmes peuvent être utilisés pour :

  • isoler les différences entre plateformes (X11 vs Windows classique vs XP vs Aqua ...)
  • s'adapter aux limitations d'affichage (faible nombre de couleurs, niveaux de gris, monochrome, écrans minuscules)
  • l'accessibilité (contraste élevé, grande police)
  • le branding de suites d'applications
  • se fondre dans le reste du bureau (Gnome, KDE, Java)
  • et, bien sûr : le « eye candy ».

ÉLÉMENTS

Un élément affiche une partie individuelle d'un widget. Par exemple, un widget de barre de défilement vertical contient les éléments uparrow, downarrow, trough et slider.

Les noms d'éléments utilisent une notation décimale récursive. Par exemple, uparrow identifie un élément de flèche générique, et Scrollbar.uparrow et Combobox.uparrow identifient des éléments spécifiques au widget. Lors de la recherche d'un élément, le moteur de style recherche d'abord le nom spécifique, et si aucun élément de ce nom n'est trouvé, il recherche des éléments génériques en supprimant successivement les composants principaux du nom de l'élément.

Comme les widgets, les éléments ont des options qui spécifient quoi afficher et comment l'afficher. Par exemple, l'élément text (qui affiche une chaîne de caractères) a les options -text, -font, -foreground, -background, -underline et -width. La valeur d'une option d'élément est prise à partir (par ordre de priorité) :

  • une option du même nom et type dans le widget contenant l'élément ;
  • un réglage dynamique spécifié par style map et l'état actuel ;
  • le réglage par défaut spécifié par style configure ; ou
  • la valeur par défaut intégrée de l'élément pour l'option.

DISPOSITIONS

Une disposition spécifie quels éléments composent un widget et comment ils sont arrangés. Le moteur de disposition utilise une version simplifiée de l'algorithme pack : en commençant par une cavité initiale égale à la taille du widget, les éléments se voient allouer un espace dans la cavité le long du côté spécifié par l'option -side, et sont placés dans l'espace selon l'option -sticky. Par exemple, la disposition d'une barre de défilement horizontale est :

ttk::style layout Horizontal.TScrollbar {
    Scrollbar.trough -children {
	Scrollbar.leftarrow -side left -sticky w
	Scrollbar.rightarrow -side right -sticky e
	Scrollbar.thumb -sticky ew
    }
}

Par défaut, la disposition d'un widget est la même que son nom de classe. Certains widgets peuvent outrepasser cela (par exemple, le widget ttk::scrollbar choisit différentes dispositions en fonction de l'option -orient).

ÉTATS

Dans Tk standard, de nombreux widgets ont une option -state qui (dans la plupart des cas) est soit normal, soit disabled. Certains widgets prennent en charge des états supplémentaires, tels que le widget entry qui a un état readonly et les différentes saveurs de boutons qui ont un état active.

L'ensemble de widgets Tk thémés généralise cette idée : chaque widget a un bitmap d'indicateurs d'état indépendants. Les indicateurs d'état des widgets incluent active, disabled, pressed, focus, etc. (voir ttk::widget(n) pour la liste complète des indicateurs d'état).

Au lieu d'une option -state, chaque widget possède désormais une commande de widget state qui est utilisée pour définir ou interroger l'état. Une spécification d'état est une liste de noms d'état symboliques indiquant quels bits sont définis, chacun étant facultativement préfixé par un point d'exclamation indiquant que le bit est effacé à la place.

Par exemple, les liaisons de classe pour le widget ttk::button sont :

bind TButton <Enter>		{ %W state active }
bind TButton <Leave>		{ %W state !active }
bind TButton <ButtonPress-1>	{ %W state pressed }
bind TButton <Button1-Leave>	{ %W state !pressed }
bind TButton <Button1-Enter>	{ %W state pressed }
bind TButton <ButtonRelease-1>	\
    { %W instate {pressed} { %W state !pressed ; %W invoke } }

Cela spécifie que le widget devient active lorsque le pointeur entre dans le widget, et inactif lorsqu'il en sort. De même, il devient pressed lorsque le bouton de la souris est enfoncé, et !pressed lors de l'événement ButtonRelease. De plus, le bouton se désenfonce si le pointeur est déplacé en dehors du widget pendant que le bouton 1 est maintenu enfoncé, et se réenfonce s'il est ramené à l'intérieur. Enfin, lorsque le bouton de la souris est relâché, la commande -command du widget est appelée, mais seulement si le bouton est actuellement dans l'état pressed. (Les liaisons réelles sont un peu plus compliquées que ce qui précède, mais pas beaucoup plus).

STYLES

Chaque widget est associé à un style, qui spécifie les valeurs des options d'élément. Les noms de style utilisent une notation décimale récursive comme les dispositions et les éléments ; par défaut, les widgets utilisent le nom de classe pour rechercher un style dans le thème actuel. Par exemple :

ttk::style configure TButton \
	-background #d9d9d9 \
	-foreground black \
	-relief raised \
	;

De nombreux éléments s'affichent différemment en fonction de l'état du widget. Par exemple, les boutons ont un arrière-plan différent lorsqu'ils sont actifs, un premier plan différent lorsqu'ils sont désactivés, et un relief différent lorsqu'ils sont enfoncés. La commande style map spécifie les réglages dynamiques d'options pour un style particulier :

ttk::style map TButton \
	-background [list disabled #d9d9d9  active #ececec] \
	-foreground [list disabled #a3a3a3] \
	-relief [list {pressed !disabled} sunken] \
	;
