ttyname(3) Manuel des fonctions de bibliothèque ttyname(3)

NOM

ttyname, ttyname_r — retourner le nom d'un terminal

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
char *ttyname(int fd);
int ttyname_r(size_t size;
              int fd, char buf[size], size_t size);

DESCRIPTION

La fonction ttyname() retourne un pointeur vers le chemin d'accès se terminant par un caractère nul du périphérique terminal ouvert sur le descripteur de fichier fd, ou NULL en cas d'erreur (par exemple, si fd n'est pas connecté à un terminal). La valeur retournée peut pointer vers des données statiques, potentiellement écrasées par l'appel suivant. La fonction ttyname_r() stocke ce chemin d'accès dans le tampon buf de taille size.

VALEUR DE RETOUR

La fonction ttyname() retourne un pointeur vers un chemin d'accès en cas de succès. En cas d'erreur, NULL est retourné et errno est défini pour indiquer l'erreur. La fonction ttyname_r() retourne 0 en cas de succès et un numéro d'erreur en cas d'erreur.

ERREURS

EBADF
Descripteur de fichier invalide.
ENODEV
fd fait référence à un périphérique pseudoterminal esclave mais le chemin d'accès correspondant n'a pas pu être trouvé (voir NOTES).
ENOTTY
fd ne fait pas référence à un périphérique terminal.
ERANGE
(ttyname_r()) size était trop petit pour permettre le stockage du chemin d'accès.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
ttyname () Sécurité des threads MT-Unsafe race:ttyname
ttyname_r () Sécurité des threads MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001, 4.2BSD.

NOTES

Un processus qui conserve un descripteur de fichier faisant référence à un périphérique pts(4) ouvert lors du passage à un autre espace de noms de montage utilisant une instance différente de /dev/ptmx peut toujours trouver accidentellement qu'un chemin d'accès de périphérique du même nom pour ce descripteur de fichier existe. Cependant, ce chemin d'accès de périphérique fait référence à un périphérique différent et ne peut donc pas être utilisé pour accéder au périphérique auquel le descripteur de fichier fait référence. L'appel à ttyname() ou ttyname_r() sur le descripteur de fichier dans le nouvel espace de noms de montage provoquera le retour de NULL par ces fonctions et la définition de errno à ENODEV.
