tk_getOpenFile(n) Commandes intégrées Tk tk_getOpenFile(n)

NOM

tk_getOpenFile, tk_getSaveFile - afficher une boîte de dialogue pour que l'utilisateur sélectionne un fichier à ouvrir ou à enregistrer.

SYNOPSIS

tk_getOpenFile ?option valeur ...?
tk_getSaveFile ?option valeur ...?

DESCRIPTION

Les procédures tk_getOpenFile et tk_getSaveFile affichent une boîte de dialogue pour que l'utilisateur sélectionne un fichier à ouvrir ou à enregistrer. La commande tk_getOpenFile est généralement associée à la commande Ouvrir du menu Fichier. Son but est que l'utilisateur sélectionne un fichier existant uniquement. Si l'utilisateur entre un fichier inexistant, la boîte de dialogue affiche un message d'erreur et demande à l'utilisateur de fournir une sélection alternative. Si une application permet à l'utilisateur de créer de nouveaux fichiers, elle devrait le faire en fournissant une commande distincte Nouveau dans le menu.

La commande tk_getSaveFile est généralement associée à la commande Enregistrer sous du menu Fichier. Si l'utilisateur entre un fichier qui existe déjà, la boîte de dialogue demande à l'utilisateur une confirmation pour savoir si le fichier existant doit être écrasé ou non.

Les paires option-valeur suivantes sont possibles en tant qu'arguments de ligne de commande pour ces deux commandes :

-command chaîne
Spécifie le préfixe d'une commande Tcl à invoquer lorsque l'utilisateur ferme la boîte de dialogue après avoir sélectionné un élément. Ce rappel n'est pas appelé si l'utilisateur a annulé la boîte de dialogue. La commande réelle consiste en chaîne suivi d'un espace et de la valeur sélectionnée par l'utilisateur dans la boîte de dialogue. Ceci n'est disponible que sur macOS.
-confirmoverwrite booléen
Configure la réaction de la boîte de dialogue Enregistrer lorsque le fichier sélectionné existe déjà et que l'enregistrement l'écraserait. Une valeur vraie demande qu'une boîte de dialogue de confirmation soit présentée à l'utilisateur. Une valeur fausse demande que l'écrasement ait lieu sans confirmation. La valeur par défaut est vraie.
-defaultextension extension
Spécifie une chaîne qui sera ajoutée au nom de fichier si l'utilisateur entre un nom de fichier sans extension. La valeur par défaut est la chaîne vide, ce qui signifie qu'aucune extension ne sera ajoutée au nom de fichier dans tous les cas. Cette option est ignorée sur macOS, qui n'exige pas d'extensions pour les noms de fichiers, et l'implémentation UNIX devine des valeurs raisonnables pour celle-ci à partir de l'option -filetypes lorsqu'elle n'est pas fournie.
-filetypes listeModèlesFichiers
Si une liste de types de fichiers existe dans la boîte de dialogue de fichiers sur la plateforme particulière, cette option fournit les types de fichiers dans cette liste. Lorsque l'utilisateur choisit un type de fichier dans la liste, seuls les fichiers de ce type sont listés. Si cette option n'est pas spécifiée, ou si elle est définie sur la liste vide, ou si la liste des types de fichiers n'est pas prise en charge par la plateforme particulière, alors tous les fichiers sont listés indépendamment de leurs types. Voir la section SPÉCIFICATION DES MODÈLES DE FICHIERS ci-dessous pour une discussion sur le contenu de listeModèlesFichiers.
-initialdir répertoire
Spécifie que les fichiers dans répertoire doivent être affichés lorsque la boîte de dialogue apparaît. Si ce paramètre n'est pas spécifié, le répertoire initial est par défaut le répertoire de travail courant sur les systèmes non-Windows et sur les systèmes Windows avant Vista. Sur les systèmes Vista et ultérieurs, le répertoire initial est par défaut le dernier répertoire sélectionné par l'utilisateur pour l'application. Si le paramètre spécifie un chemin relatif, la valeur de retour convertira le chemin relatif en un chemin absolu.
-initialfile nomFichier
Spécifie un nom de fichier à afficher dans la boîte de dialogue lorsqu'elle apparaît.
-message chaîne
Spécifie un message à inclure dans la zone client de la boîte de dialogue. Ceci n'est disponible que sur macOS.
-multiple booléen
Permet à l'utilisateur de choisir plusieurs fichiers dans la boîte de dialogue Ouvrir.
-parent fenêtre
Fait de fenêtre le parent logique de la boîte de dialogue de fichier. La boîte de dialogue de fichier est affichée au-dessus de sa fenêtre parente. Sur macOS, cela transforme la boîte de dialogue de fichier en une feuille attachée à la fenêtre parente.
-title chaîneTitre
Spécifie une chaîne à afficher comme titre de la boîte de dialogue. Si cette option n'est pas spécifiée, un titre par défaut est affiché.
-typevariable nomVariable
La variable globale nomVariable est utilisée pour présélectionner le filtre à utiliser dans listeFiltres lorsque la boîte de dialogue est ouverte et est mise à jour à la fermeture de la boîte de dialogue, vers le dernier filtre sélectionné. La variable est lue une fois au début pour sélectionner le filtre approprié. Si la variable n'existe pas, ou si sa valeur ne correspond à aucun nom de filtre, ou est vide ({}), la boîte de dialogue reviendra au comportement par défaut de sélection du premier filtre de la liste. Si la boîte de dialogue est annulée, la variable n'est pas modifiée.

Si l'utilisateur sélectionne un fichier, tk_getOpenFile et tk_getSaveFile retournent le chemin complet de ce fichier. Si l'utilisateur annule l'opération, les deux commandes retournent la chaîne vide.

SPÉCIFICATION DES MODÈLES DE FICHIERS

La valeur listeModèlesFichiers fournie par l'option -filetypes est une liste de modèles de fichiers. Chaque modèle de fichier est une liste de la forme

nomType {extension ?extension ...?} ?{typeMac ?typeMac ...?}?
nomType est le nom du type de fichier décrit par ce modèle de fichier et est la chaîne de texte qui apparaît dans la liste des types de fichiers. extension est une extension de fichier pour ce modèle de fichier. typeMac est un type de fichier Macintosh de quatre caractères. La liste des typeMac est facultative et peut être omise pour les applications qui n'ont pas besoin de s'exécuter sur la plateforme Macintosh.

Plusieurs modèles de fichiers peuvent avoir le même nomType, auquel cas ils font référence au même type de fichier et partagent la même entrée dans la liste. Lorsque l'utilisateur sélectionne une entrée dans la liste, tous les fichiers qui correspondent à au moins un des modèles de fichiers correspondant à cette entrée sont listés. Habituellement, chaque modèle de fichier correspond à un type de fichier distinct. L'utilisation de plusieurs modèles de fichiers pour un seul type de fichier n'est nécessaire que sur la plateforme Macintosh.

Sur la plateforme Macintosh, un fichier correspond à un modèle de fichier si son nom correspond à au moins une des extensions ET s'il appartient à au moins l'un des typeMac du modèle de fichier. Par exemple, le modèle de fichier Fichiers source C dans le code d'exemple correspond aux fichiers qui ont une extension .c ET appartiennent au typeMac TEXT. Pour utiliser la règle OU à la place, vous pouvez utiliser deux modèles de fichiers, un avec les extensions uniquement et l'autre avec le typeMac uniquement. Le type de fichier Fichiers GIF dans le code d'exemple correspond aux fichiers qui ont soit une extension .gif soit appartiennent au typeMac GIFF.

Sur les plateformes Unix et Windows, un fichier correspond à un modèle de fichier si son nom correspond à au moins une des extensions du modèle de fichier. Les typeMac sont ignorés.

SPÉCIFICATION DES EXTENSIONS

Sur les plateformes Unix et Macintosh, les extensions sont mises en correspondance en utilisant la correspondance de modèles de style glob. Sur la plateforme Windows, les extensions sont mises en correspondance par le système d'exploitation sous-jacent. Les types d'extensions possibles sont :

(1)
l'extension spéciale “*” correspond à n'importe quel fichier ;
(2)
l'extension spéciale “” correspond à tous les fichiers qui n'ont pas d'extension (c'est-à-dire, le nom du fichier ne contient pas de caractère point) ;
(3)
toute chaîne de caractères qui ne contient aucun caractère joker (* et ?).

En raison des différentes règles de correspondance de modèles sur les diverses plateformes, pour assurer la portabilité, les caractères jokers ne sont pas autorisés dans les extensions, sauf comme dans l'extension spéciale “*”. Les extensions sans point

EXEMPLE

set types {
    {{Fichiers texte}       {.txt}        }
    {{Scripts TCL}      {.tcl}        }
    {{Fichiers source C}   {.c}      TEXT}
    {{Fichiers GIF}        {.gif}        }
    {{Fichiers GIF}        {}        GIFF}
    {{Tous les fichiers}        *             }
}
set filename [tk_getOpenFile -filetypes $types]
if {$filename ne ""} {
    # Ouvrir le fichier ...
}
