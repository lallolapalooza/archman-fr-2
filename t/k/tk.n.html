tk(n) Commandes intégrées Tk tk(n)

NOM

tk - Manipuler l'état interne de Tk

SYNTAXE

tk option ?arg ...?

DESCRIPTION

La commande tk fournit un accès à divers éléments de l'état interne de Tk. La plupart des informations manipulées par cette commande concernent l'application dans son ensemble, ou un écran ou une affichage, plutôt qu'une fenêtre particulière. La commande peut prendre n'importe laquelle des formes suivantes en fonction de l'argument option. Les formes légales sont :

tk appname ?nouveauNom?
Si nouveauNom n'est pas spécifié, cette commande renvoie le nom de l'application (le nom qui peut être utilisé dans les commandes send pour communiquer avec l'application). Si nouveauNom est spécifié, alors le nom de l'application est changé en nouveauNom. Si le nom donné est déjà utilisé, alors un suffixe de la forme “ #2” ou “ #3” est ajouté afin de rendre le nom unique. Le résultat de la commande est le nom effectivement choisi. nouveauNom ne devrait pas commencer par une lettre majuscule. Cela interférera avec le traitement des options, car les noms commençant par des majuscules sont supposés être des classes ; par conséquent, Tk pourrait ne pas être en mesure de trouver certaines options pour l'application. Si les envois ont été désactivés en supprimant la commande send, cette commande les réactivera et recréera la commande send.
tk busy sousCommande ...
Cette commande contrôle le marquage des hiérarchies de fenêtres comme “occupées”, les rendant non interactives pendant qu'une autre opération est en cours. Pour plus de détails, consultez la page de manuel busy.
tk caret fenêtre ?-x x? ?-y y? ?-height hauteur?
Définit et interroge la position du curseur (caret) pour l'affichage de la fenêtre Tk spécifiée fenêtre. Le curseur est l'emplacement du curseur par affichage utilisé pour indiquer le focus global (par exemple, pour se conformer aux directives d'accessibilité de Microsoft), ainsi que pour la localisation des fenêtres XIM (X Input Methods) ou IME Windows au-dessus de l'emplacement. Si aucune option n'est spécifiée, les dernières valeurs utilisées pour définir le curseur sont renvoyées au format paire clé-valeur. -x et -y représentent les coordonnées relatives à la fenêtre, et -height est la hauteur de l'emplacement actuel du curseur, ou la hauteur de la fenêtre spécifiée si aucune n'est donnée.
tk inactive ?-displayof fenêtre? ?reset?
Renvoie un entier positif, le nombre de millisecondes écoulées depuis la dernière interaction de l'utilisateur avec le système. Si l'option -displayof est fournie, la valeur de retour fait référence à l'affichage de fenêtre ; sinon, elle fait référence à l'affichage de la fenêtre principale de l'application.

tk inactive renverra -1, si l'interrogation du temps d'inactivité de l'utilisateur n'est pas prise en charge par le système, et dans les interpréteurs sécurisés.

Si la chaîne littérale reset est donnée comme argument supplémentaire, le minuteur est réinitialisé et une chaîne vide est renvoyée. La réinitialisation du temps d'inactivité est interdite dans les interpréteurs sécurisés et provoquera une erreur si elle est tentée.

tk fontchooser sousCommande ...
Contrôle la boîte de dialogue de sélection de polices de Tk. Pour plus de détails, consultez la page de manuel fontchooser.
tk scaling ?-displayof fenêtre? ?nombre?
Définit et interroge le facteur d'échelle actuel utilisé par Tk pour convertir entre les unités physiques (par exemple, points, pouces ou millimètres) et les pixels. L'argument nombre est un nombre à virgule flottante qui spécifie le nombre de pixels par point sur l'affichage de fenêtre. Si l'argument fenêtre est omis, il prend par défaut la fenêtre principale. Si l'argument nombre est omis, la valeur actuelle du facteur d'échelle est renvoyée.

Un “point” est une unité de mesure égale à 1/72 pouce. Un facteur d'échelle de 1.0 correspond à 1 pixel par point, ce qui est équivalent à un moniteur standard de 72 dpi. Un facteur d'échelle de 1.25 signifierait 1.25 pixels par point, ce qui correspond au réglage d'un moniteur de 90 dpi ; définir le facteur d'échelle à 1.25 sur un moniteur de 72 dpi entraînerait l'affichage de tout dans l'application 1.25 fois plus grand que la normale. La valeur initiale du facteur d'échelle est définie lors du démarrage de l'application, en fonction des propriétés du moniteur installé, mais elle peut être modifiée à tout moment. Les mesures effectuées après la modification du facteur d'échelle utiliseront le nouveau facteur d'échelle, mais il est indéfini si les widgets existants se redimensionneront dynamiquement pour s'adapter au nouveau facteur d'échelle.

tk useinputmethods ?-displayof fenêtre? ?booléen?
Définit et interroge l'état de savoir si Tk doit utiliser XIM (X Input Methods) pour filtrer les événements. L'état résultant est renvoyé. XIM est utilisé dans certaines locales (c'est-à-dire japonais, coréen), pour gérer les périphériques d'entrée spéciaux. Cette fonctionnalité n'est significative que sur X. Si le support XIM n'est pas disponible, cela renverra toujours 0. Si l'argument fenêtre est omis, il prend par défaut la fenêtre principale. Si l'argument booléen est omis, l'état actuel est renvoyé. Ceci est activé par défaut pour l'affichage principal.
tk windowingsystem
Renvoie le système de fenêtrage Tk actuel, l'un des suivants : x11 (basé sur X11), win32 (Microsoft Windows), ou aqua (macOS Aqua).
