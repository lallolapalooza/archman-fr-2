Chaque position peut éventuellement être suivie dans l'élément de liste suivant par l'un des mots-clés left, right, center ou numeric, qui spécifie comment justifier le texte par rapport à la tabulation. Left est par défaut ; il fait que le texte suivant le caractère de tabulation est positionné avec son bord gauche à la position de tabulation. Numeric signifie que le point décimal dans le texte est positionné à la position de tabulation ; s'il n'y a pas de point décimal, alors le chiffre le moins significatif du nombre est positionné juste à gauche de la position de tabulation ; s'il n'y a pas de nombre dans le texte, alors le texte est aligné à droite à la position de tabulation. Par exemple, « -tabs {2c left 4c 6c center} » crée trois tabulations avec des intervalles de deux centimètres ; les deux premières utilisent un alignement à gauche et la troisième utilise un alignement au centre.

Les distances des tabulations doivent être strictement positives et doivent toujours augmenter d'une tabulation à la suivante (sinon, une erreur est générée). La valeur de l'option -tabs peut être remplacée par des options -tabs dans les balises.

Si aucune option -tabs n'est spécifiée, ou si elle est spécifiée comme une liste vide, alors Tk utilise des tabulations par défaut espacées tous les huit caractères (taille moyenne). Pour obtenir un espacement standard différent, par exemple tous les 4 caractères, configurez simplement le widget avec « -tabs "[expr {4 * [font measure $font 0]}] left" -tabstyle wordprocessor ».

DESCRIPTION

La commande text crée une nouvelle fenêtre (donnée par l'argument pathName) et en fait un widget texte. Des options supplémentaires, décrites ci-dessus, peuvent être spécifiées sur la ligne de commande ou dans la base de données d'options pour configurer des aspects du texte tels que sa couleur d'arrière-plan par défaut et son relief. La commande text retourne le nom du chemin de la nouvelle fenêtre.

Un widget texte affiche une ou plusieurs lignes de texte et permet de modifier ce texte. Les widgets texte prennent en charge quatre types d'annotations sur le texte, appelées balises, marques, fenêtres intégrées ou images intégrées. Les balises permettent d'afficher différentes parties du texte avec différentes polices et couleurs. De plus, des commandes Tcl peuvent être associées aux balises afin que des scripts soient invoqués lors d'actions particulières telles que des frappes au clavier et des pressions sur les boutons de la souris dans des plages de texte spécifiques. Voir TAGS ci-dessous pour plus de détails.

La deuxième forme d'annotation consiste en des marqueurs flottants dans le texte appelés "marques". Les marques sont utilisées pour suivre diverses positions intéressantes dans le texte au fur et à mesure de son édition. Voir MARKS ci-dessous pour plus de détails.

La troisième forme d'annotation permet d'intégrer des fenêtres arbitraires dans un widget texte. Voir EMBEDDED WINDOWS ci-dessous pour plus de détails.

La quatrième forme d'annotation permet d'intégrer des images Tk dans un widget texte. Voir EMBEDDED IMAGES ci-dessous pour plus de détails.

Le widget texte dispose également d'un mécanisme intégré d'annulation/rétablissement. Voir THE UNDO MECHANISM ci-dessous pour plus de détails.

Le widget texte permet la création de widgets pairs. Ce sont d'autres widgets texte qui partagent les mêmes données sous-jacentes (texte, marques, balises, images, etc.). Voir PEER WIDGETS ci-dessous pour plus de détails.

INDICES

De nombreuses commandes de widget pour les textes prennent un ou plusieurs indices comme arguments. Un indice est une chaîne de caractères utilisée pour indiquer une position particulière dans un texte, telle qu'un endroit pour insérer des caractères ou un point de terminaison d'une plage de caractères à supprimer. Les indices ont la syntaxe

base modificateur modificateur modificateur ...
Où base donne un point de départ et les modificateurs ajustent l'indice à partir du point de départ (par exemple, avancer ou reculer d'un caractère). Chaque indice doit contenir une base, mais les modificateurs sont facultatifs. La plupart des modificateurs (tels que décrits ci-dessous) permettent un sous-modificateur facultatif. Les sous-modificateurs valides sont any et display. Si le sous-modificateur est abrégé, il doit être suivi d'un espace blanc, mais sinon il n'est pas nécessaire d'avoir d'espace entre le sous-modificateur et le modificateur suivant. Typiquement, le sous-modificateur display ajuste la signification du modificateur suivant pour le faire référencer des unités visuelles ou non élidées plutôt que des unités logiques, mais cela est expliqué pour chaque cas pertinent ci-dessous. Enfin, là où count est utilisé dans le cadre d'un modificateur, il peut être positif ou négatif, donc “base - -3 lignes” est tout à fait valide (et équivalent à “base +3lignes”).

La base d'un indice doit avoir l'une des formes suivantes :

ligne.caractère
Indique le caractère'ème caractère de la ligne ligne. Les lignes sont numérotées à partir de 1 pour la cohérence avec d'autres programmes UNIX utilisant ce schéma de numérotation. Au sein d'une ligne, les caractères sont numérotés à partir de 0. Si caractère est end, il fait référence au caractère de nouvelle ligne qui termine la ligne.
@x,y
Indique le caractère qui recouvre le pixel dont les coordonnées x et y dans la fenêtre du texte sont x et y.
end
Indique la fin du texte (le caractère juste après la dernière nouvelle ligne).
marque
Indique le caractère juste après la marque dont le nom est marque (voir MARKS pour les détails).
tag.first
Indique le premier caractère du texte qui a été marqué avec tag. Cette forme génère une erreur si aucun caractère n'est actuellement marqué avec tag.
tag.last
Indique le caractère juste après le dernier caractère du texte marqué avec tag. Cette forme génère une erreur si aucun caractère n'est actuellement marqué avec tag.
pathName
Indique la position de la fenêtre intégrée dont le nom est pathName. Cette forme génère une erreur s'il n'y a pas de fenêtre intégrée sous ce nom.
imageName
Indique la position de l'image intégrée dont le nom est imageName. Cette forme génère une erreur s'il n'y a pas d'image intégrée sous ce nom.

Si la base peut correspondre à plusieurs des formes ci-dessus, par exemple si un mark et un imageName ont la même valeur, alors la forme apparaissant plus tôt dans la liste ci-dessus a la priorité. Si des modificateurs suivent l'indice de base, chacun d'eux doit avoir l'une des formes listées ci-dessous. Les mots-clés tels que chars et wordend peuvent être abrégés tant que l'abréviation est sans ambiguïté.

+ count ?submodifier? chars
Ajuste l'indice en avant de count caractères, en passant aux lignes suivantes du texte si nécessaire. S'il y a moins de count caractères dans le texte après l'indice actuel, l'indice est défini sur le dernier indice du texte. Les espaces de part et d'autre de count sont facultatifs. Si le sous-modificateur display est donné, les caractères élidés sont ignorés sans être comptés. Si any est donné, tous les caractères sont comptés. Pour des raisons historiques, si aucun modificateur n'est donné, le décompte s'effectue en unités de positions d'indice (voir INDICES pour les détails). Ce comportement pourrait être modifié dans une future version majeure, donc si vous avez besoin d'un décompte d'indice, il est conseillé d'utiliser indices autant que possible.
- count ?submodifier? chars
Ajuste l'indice en arrière de count caractères, en passant aux lignes précédentes du texte si nécessaire. S'il y a moins de count caractères dans le texte avant l'indice actuel, l'indice est défini sur le premier indice du texte (1.0). Les espaces de part et d'autre de count sont facultatifs. Si le sous-modificateur display est donné, les caractères élidés sont ignorés sans être comptés. Si any est donné, tous les caractères sont comptés. Pour des raisons historiques, si aucun modificateur n'est donné, le décompte s'effectue en unités de positions d'indice (voir INDICES pour les détails). Ce comportement pourrait être modifié dans une future version majeure, donc si vous avez besoin d'un décompte d'indice, il est conseillé d'utiliser indices autant que possible.
+ count ?submodifier? indices
Ajuste l'indice en avant de count positions d'indice, en passant aux lignes suivantes du texte si nécessaire. S'il y a moins de count positions d'indice dans le texte après l'indice actuel, l'indice est défini sur la dernière position d'indice du texte. Les espaces de part et d'autre de count sont facultatifs. Notez qu'une position d'indice est soit un seul caractère, soit une seule image intégrée ou une seule fenêtre intégrée. Si le sous-modificateur display est donné, les indices élidés sont ignorés sans être comptés. Si any est donné, tous les indices sont comptés ; c'est aussi le comportement par défaut si aucun modificateur n'est donné.
- count ?submodifier? indices
Ajuste l'indice en arrière de count positions d'indice, en passant aux lignes précédentes du texte si nécessaire. S'il y a moins de count positions d'indice dans le texte avant l'indice actuel, l'indice est défini sur la première position d'indice (1.0) du texte. Les espaces de part et d'autre de count sont facultatifs. Si le sous-modificateur display est donné, les indices élidés sont ignorés sans être comptés. Si any est donné, tous les indices sont comptés ; c'est aussi le comportement par défaut si aucun modificateur n'est donné.
+ count ?submodifier? lines
Ajuste l'indice en avant de count lignes, en conservant la même position de caractère dans la ligne. S'il y a moins de count lignes après la ligne contenant l'indice actuel, l'indice est défini pour faire référence à la même position de caractère sur la dernière ligne du texte. Ensuite, si la ligne n'est pas assez longue pour contenir un caractère à la position de caractère indiquée, la position de caractère est ajustée pour faire référence au dernier caractère de la ligne (la nouvelle ligne). Les espaces de part et d'autre de count sont facultatifs. Si le sous-modificateur display est donné, chaque ligne d'affichage visuelle est comptée séparément. Sinon, si any (ou aucun modificateur) est donné, chaque ligne logique (peu importe combien de fois elle est renvoyée visuellement) compte une seule fois. Si les lignes concernées ne sont pas renvoyées, ces deux méthodes de comptage sont équivalentes.
- compter ?sousmodificateur? lignes
Ajuste l'index vers l'arrière de compter lignes logiques, en conservant la même position de caractère dans la ligne. S'il y a moins de compter lignes avant la ligne contenant l'index actuel, l'index est alors défini pour faire référence à la même position de caractère sur la première ligne du texte. Ensuite, si la ligne n'est pas assez longue pour contenir un caractère à la position de caractère indiquée, ajustez la position de caractère pour qu'elle fasse référence au dernier caractère de la ligne (le retour à la ligne). Les espaces avant et après compter sont facultatifs. Si le sous-modificateur affichage est donné, alors chaque ligne d'affichage visuelle est comptée séparément. Sinon, si aucun (ou aucun modificateur) n'est donné, alors chaque ligne logique (peu importe combien de fois elle est coupée visuellement) compte une seule fois. Si les lignes pertinentes ne sont pas coupées, alors ces deux méthodes de comptage sont équivalentes.
?sousmodificateur? debutligne
Ajuste l'index pour qu'il fasse référence au premier index de la ligne. Si le sous-modificateur affichage est donné, c'est le premier index de la ligne d'affichage, sinon de la ligne logique.
?sousmodificateur? finligne
Ajuste l'index pour qu'il fasse référence au dernier index de la ligne (le retour à la ligne). Si le sous-modificateur affichage est donné, c'est le dernier index de la ligne d'affichage, sinon de la ligne logique.
?sousmodificateur? debutmot
Ajuste l'index pour qu'il fasse référence au premier caractère du mot contenant l'index actuel. Un mot est constitué d'un nombre quelconque de caractères adjacents qui sont des lettres, des chiffres ou des tirets bas, ou d'un seul caractère qui n'est pas l'un de ceux-ci. Si le sous-modificateur affichage est donné, cela n'examine que les caractères non élidés, sinon tous les caractères (élidés ou non) sont examinés.
?sousmodificateur? finmot
Ajuste l'index pour qu'il fasse référence au caractère juste après le dernier caractère du mot contenant l'index actuel. Si l'index actuel fait référence au dernier caractère du texte, il n'est pas modifié. Si le sous-modificateur affichage est donné, cela n'examine que les caractères non élidés, sinon tous les caractères (élidés ou non) sont examinés.

Si plus d'un modificateur est présent, ils sont appliqués dans l'ordre de gauche à droite. Par exemple, l'index « fin - 1 car » fait référence à l'avant-dernier caractère du texte et « inser debutmot - 1 c » fait référence au caractère juste avant le premier caractère du mot contenant le curseur d'insertion. Les modificateurs sont appliqués un par un dans cet ordre de gauche à droite, et après chaque étape, l'index résultant est contraint d'être un index valide dans le widget de texte. Ainsi, par exemple, l'index « 1.0 -1c +1c » fait référence à l'index « 2.0 ».

Là où les modificateurs entraînent des changements d'index par lignes d'affichage, caractères d'affichage ou indices d'affichage, et où la base fait référence à un index à l'intérieur d'une balise élidée, cet index de base est considéré comme équivalent au premier index non élidé suivant.

BALISES

La première forme d'annotation dans les widgets de texte est une balise. Une balise est une chaîne textuelle associée à certains des caractères d'un texte. Les balises peuvent contenir des caractères arbitraires, mais il est probablement préférable d'éviter d'utiliser les caractères « " » (espace), +, ou - : ces caractères ont une signification spéciale dans les indices, donc les balises qui les contiennent ne peuvent pas être utilisées comme indices. Il peut y avoir un nombre quelconque de balises associées aux caractères d'un texte. Chaque balise peut faire référence à un seul caractère, à une plage de caractères, ou à plusieurs plages de caractères. Un caractère individuel peut avoir un nombre quelconque de balises qui lui sont associées.

Un ordre de priorité est défini entre les balises, et cet ordre est utilisé pour implémenter certaines des fonctions liées aux balises décrites ci-dessous. Lorsqu'une balise est définie (en l'associant à des caractères ou en définissant ses options d'affichage ou en lui liant des commandes), elle reçoit une priorité supérieure à celle de toute balise existante. L'ordre de priorité des balises peut être redéfini en utilisant les commandes de widget « nomChemin tag raise » et « nomChemin tag lower ».

Les balises servent trois objectifs dans les widgets de texte. Premièrement, elles contrôlent la manière dont les informations sont affichées à l'écran. Par défaut, les caractères sont affichés comme déterminé par les options -arrièreplan, -police et -premierplan du widget de texte. Cependant, des options d'affichage peuvent être associées à des balises individuelles en utilisant la commande de widget « nomChemin tag configure ». Si un caractère a été balisé, alors les options d'affichage associées à la balise remplacent le style d'affichage par défaut. Les options suivantes sont actuellement prises en charge pour les balises :

-arrièreplan couleur
Couleur spécifie la couleur d'arrière-plan à utiliser pour les caractères associés à la balise. Elle peut avoir l'une des formes acceptées par Tk_GetColor.
-motifarrPlan bitmap
Bitmap spécifie une bitmap utilisée comme motif de tramage pour l'arrière-plan. Elle peut avoir l'une des formes acceptées par Tk_GetBitmap. Si bitmap n'a pas été spécifié, ou s'il est spécifié comme une chaîne vide, alors un remplissage solide sera utilisé pour l'arrière-plan.
-bordure pixels
Pixels spécifie la largeur d'une bordure à dessiner autour de la balise en utilisant l'une des formes acceptées par Tk_GetPixels. Cette option doit être utilisée conjointement avec l'option -relief pour fournir la bordure souhaitée.
-elide booléen
Élider spécifie si les données doivent être élidées. Les données élidées (caractères, images, fenêtres intégrées, etc.) ne sont pas affichées et ne prennent pas d'espace à l'écran, mais se comportent par la suite comme des données normales.
-motifAvantPlan bitmap
Bitmap spécifie une bitmap utilisée comme motif de tramage lors du dessin du texte et d'autres informations de premier plan telles que les soulignements. Elle peut avoir l'une des formes acceptées par Tk_GetBitmap. Si bitmap n'a pas été spécifié, ou s'il est spécifié comme une chaîne vide, alors un remplissage solide sera utilisé.
-police nomPolice
NomPolice est le nom d'une police à utiliser pour le dessin des caractères. Il peut avoir l'une des formes acceptées par Tk_GetFont.
-premierplan couleur
Couleur spécifie la couleur à utiliser lors du dessin du texte et d'autres informations de premier plan telles que les soulignements. Elle peut avoir l'une des formes acceptées par Tk_GetColor.
-alignement alignement
Si le premier caractère non élidé d'une ligne d'affichage a une balise pour laquelle cette option a été spécifiée, alors alignement détermine comment aligner la ligne. Il doit être l'un des mots : gauche, droite ou centre. Si une ligne est coupée, alors l'alignement de chaque ligne à l'écran est déterminé par le premier caractère non élidé de cette ligne d'affichage.
-margeGauche1 pixels
Si le premier caractère non élidé d'une ligne de texte a une balise pour laquelle cette option a été spécifiée, alors pixels spécifie de combien la ligne doit être indentée par rapport au bord gauche de la fenêtre. Pixels peut avoir l'une des formes standard pour les distances d'écran. Si une ligne de texte est coupée, cette option ne s'applique qu'à la première ligne affichée ; l'option -margeGauche2 contrôle l'indentation des lignes suivantes.
-margeGauche2 pixels
Si le premier caractère non élidé d'une ligne d'affichage a une balise pour laquelle cette option a été spécifiée, et si la ligne d'affichage n'est pas la première de sa ligne de texte (c'est-à-dire que la ligne de texte a été coupée), alors pixels spécifie de combien la ligne doit être indentée par rapport au bord gauche de la fenêtre. Pixels peut avoir l'une des formes standard pour les distances d'écran. Cette option n'est utilisée que lorsque le retour à la ligne est activé, et elle ne s'applique qu'aux deuxième et suivantes lignes d'affichage pour une ligne de texte.
-couleurMargeGauche couleur
Couleur spécifie la couleur d'arrière-plan à utiliser dans les régions qui ne contiennent pas de caractères car elles sont indentées par -margeGauche1 ou -margeGauche2. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur utilisée est spécifiée par l'option de balise -arrièreplan (ou, si celle-ci est également non spécifiée, par l'option de widget -arrièreplan).
-decalage pixels
Pixels spécifie un décalage vertical de la ligne de base du texte par rapport à la ligne de base de la ligne globale, en pixels. Par exemple, un décalage positif peut être utilisé pour les exposants et un décalage négatif pour les indices. Pixels peut avoir l'une des formes standard pour les distances d'écran.
-barreHorizontale booléen
Spécifie si une ligne horizontale doit être dessinée au milieu des caractères. Booléen peut avoir l'une des formes acceptées par Tcl_GetBoolean.
-couleurBarreHorizontale couleur
Couleur spécifie la couleur à utiliser lors de l'affichage de la barre horizontale. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur spécifiée par l'option de balise -premierplan est utilisée.
-relief relief
Relief spécifie le style de relief à utiliser pour dessiner la bordure, dans l'une des formes acceptées par Tk_GetRelief. Cette option est utilisée conjointement avec l'option -bordure pour obtenir l'apparence de bordure souhaitée.
-margeDroite pixels
Si le premier caractère non élidé d'une ligne d'affichage a une balise pour laquelle cette option a été spécifiée, alors pixels spécifie la largeur de la marge à laisser entre la fin de la ligne et le bord droit de la fenêtre. Pixels peut avoir l'une des formes standard pour les distances d'écran. Cette option n'est utilisée que lorsque le retour à la ligne est activé. Si une ligne de texte est coupée, la marge droite de chaque ligne affichée
splay est déterminé par le premier caractère non élidé de cette ligne d'affichage.
-rmargincolor couleur
Couleur spécifie la couleur d'arrière-plan à utiliser dans les régions qui ne contiennent pas de caractères parce qu'elles sont indentées par -rmargin. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur utilisée est spécifiée par l'option de tag -background (ou, si celle-ci est également non spécifiée, par l'option de widget -background).
-selectbackground couleur
Couleur spécifie la couleur d'arrière-plan à utiliser lors de l'affichage des éléments sélectionnés. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur spécifiée par l'option de tag -background est utilisée.
-selectforeground couleur
Couleur spécifie la couleur de premier plan à utiliser lors de l'affichage des éléments sélectionnés. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur spécifiée par l'option de tag -foreground est utilisée.
-spacing1 pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser au-dessus de chaque ligne de texte, en utilisant l'une des formes standard pour les distances d'écran. Si une ligne est coupée, cette option ne s'applique qu'à la première ligne sur l'affichage.
-spacing2 pixels
Pour les lignes coupées, cette option spécifie la quantité d'espace supplémentaire à laisser entre les lignes d'affichage pour une seule ligne de texte. Pixels peut avoir l'une des formes standard pour les distances d'écran.
-spacing3 pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser en dessous de chaque ligne de texte, en utilisant l'une des formes standard pour les distances d'écran. Si une ligne est coupée, cette option ne s'applique qu'à la dernière ligne sur l'affichage.
-tabs listeOnglets
ListeOnglets spécifie un ensemble de tabulations dans la même forme que pour l'option -tabs du widget texte. Cette option ne s'applique à une ligne d'affichage que si elle s'applique au premier caractère non élidé de cette ligne d'affichage. Si cette option est spécifiée comme une chaîne vide, elle annule l'option, la laissant non spécifiée pour le tag (par défaut). Si l'option est spécifiée comme une chaîne non vide qui est une liste vide, comme -tags { }, alors elle demande des tabulations par défaut de 8 caractères comme décrit pour l'option de widget -tags.
-tabstyle style
Style spécifie soit le style de tabulation tabular soit le style wordprocessor à utiliser pour le widget texte. Cette option ne s'applique à une ligne d'affichage que si elle s'applique au premier caractère non élidé de cette ligne d'affichage. Si cette option est spécifiée comme une chaîne vide, elle annule l'option, la laissant non spécifiée pour le tag (par défaut).
-underline booléen
Booléen spécifie si oui ou non tracer un soulignement sous les caractères. Il peut avoir l'une des formes acceptées par Tcl_GetBoolean.
-underlinefg couleur
Couleur spécifie la couleur à utiliser lors de l'affichage du soulignement. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur spécifiée par l'option de tag -foreground est utilisée.
-wrap mode
Mode spécifie comment gérer les lignes qui sont plus larges que la fenêtre du texte. Cette option ne s'applique à une ligne d'affichage que si elle s'applique au premier caractère non élidé de cette ligne d'affichage. Elle a les mêmes valeurs légales que l'option -wrap pour le widget texte : none, char, ou word. Si cette option de tag est spécifiée, elle remplace l'option -wrap du widget texte.

Si un caractère a plusieurs tags associés, et si leurs options d'affichage entrent en conflit, alors les options du tag de priorité la plus élevée sont utilisées. Si une option d'affichage particulière n'a pas été spécifiée pour un tag particulier, ou si elle est spécifiée comme une chaîne vide, alors cette option ne sera jamais utilisée ; l'option du tag de priorité immédiatement inférieure sera utilisée à la place. Si aucun tag ne spécifie une option d'affichage particulière, alors le style par défaut du widget sera utilisé.

Le deuxième objectif des tags est les liaisons d'événements. Vous pouvez associer des liaisons à un tag de la même manière que vous pouvez associer des liaisons à une classe de widget : chaque fois que des événements X particuliers se produisent sur des caractères portant le tag donné, une commande Tcl donnée sera exécutée. Les liaisons de tags peuvent être utilisées pour donner des comportements à des plages de caractères ; entre autres choses, cela permet d'implémenter des fonctionnalités de type hypertexte. Pour plus de détails, voir la description de la commande de widget “nomChemin tag bind” ci-dessous. Les liaisons de tags sont partagées entre tous les widgets pairs (y compris toute liaison pour le tag spécial sel).

La troisième utilisation des tags est la gestion de la sélection. Voir LA SÉLECTION ci-dessous. À l'exception du tag spécial sel, tous les tags sont partagés entre les widgets texte pairs, et peuvent être manipulés sur une base égale depuis l'un de ces widgets. Le tag sel existe séparément et indépendamment dans chaque widget texte pair (mais toute liaison de tag vers sel est partagée).

MARQUES

La deuxième forme d'annotation dans les widgets texte est une marque. Les marques sont utilisées pour se souvenir de lieux particuliers dans un texte. Elles ressemblent aux tags en ce sens qu'elles ont des noms et qu'elles font référence à des endroits dans le fichier, mais une marque n'est pas associée à des caractères particuliers. Au lieu de cela, une marque est associée à l'espace entre deux caractères. Une seule position peut être associée à une marque à un moment donné. Si les caractères autour d'une marque sont supprimés, la marque restera ; elle aura simplement de nouveaux caractères voisins. En revanche, si les caractères contenant un tag sont supprimés, alors le tag n'aura plus d'association avec les caractères du fichier. Les marques peuvent être manipulées avec la commande de widget “nomChemin mark”, et leurs positions actuelles peuvent être déterminées en utilisant le nom de la marque comme index dans les commandes de widget.

Chaque marque a également une “gravité”, qui est soit left (gauche) soit right (droite). La gravité d'une marque spécifie ce qui arrive à la marque lorsque du texte est inséré à l'emplacement de la marque. Si une marque a une gravité gauche, alors la marque est traitée comme si elle était attachée au caractère situé à sa gauche, de sorte que la marque restera à gauche de tout texte inséré à la position de la marque. Si la marque a une gravité droite, le nouveau texte inséré à la position de la marque apparaîtra à gauche de la marque (de sorte que la marque reste la plus à droite). La gravité d'une marque est par défaut right.

L'espace de noms pour les marques est différent de celui pour les tags : le même nom peut être utilisé à la fois pour une marque et pour un tag, mais ils feront référence à des choses différentes.

Deux marques ont une importance particulière. Premièrement, la marque insert est associée au curseur d'insertion, comme décrit sous LE CURSEUR D'INSERTION ci-dessous. Deuxièmement, la marque current est associée au caractère le plus proche de la souris et est ajustée automatiquement pour suivre la position de la souris et toute modification du texte dans le widget (une exception : current n'est pas mis à jour en réponse aux mouvements de la souris si un bouton de souris est enfoncé ; la mise à jour sera différée jusqu'à ce que tous les boutons de souris aient été relâchés). Aucune de ces marques spéciales ne peut être supprimée. À l'exception de ces deux marques spéciales, toutes les marques sont partagées entre les widgets texte pairs, et peuvent être manipulées sur une base égale depuis n'importe quel widget pair.

FENÊTRES INTÉGRÉES

La troisième forme d'annotation dans les widgets texte est une fenêtre intégrée. Chaque annotation de fenêtre intégrée provoque l'affichage d'une fenêtre à un point particulier du texte. Il peut y avoir n'importe quel nombre de fenêtres intégrées dans un widget texte, et n'importe quel widget peut être utilisé comme fenêtre intégrée (sous réserve des règles habituelles de gestion de la géométrie, qui exigent que la fenêtre texte soit le parent de la fenêtre intégrée ou un descendant de son parent).

La position de la fenêtre intégrée à l'écran sera mise à jour lorsque le texte sera modifié ou défilé, et elle sera mappée et démappée lorsqu'elle entrera et sortira de la zone visible du widget texte. Chaque fenêtre intégrée occupe une unité d'espace d'index dans le widget texte, et elle peut être référencée soit par le nom de sa fenêtre intégrée, soit par sa position dans l'espace d'index du widget. Si la plage de texte contenant la fenêtre intégrée est supprimée, la fenêtre est détruite. De même, si le widget texte dans son ensemble est supprimé, la fenêtre est détruite.

Élir une fenêtre intégrée immédiatement après sa programmation pour création via la commande de widget nomChemin window create l'empêchera d'être effectivement créée. Délire une fenêtre intégrée élidée programmée pour création via nomChemin window create index -create déclenchera automatiquement le script de création associé. Après avoir détruit une fenêtre intégrée élidée, cette dernière ne sera pas recréée automatiquement.

Lorsqu'une fenêtre intégrée est ajoutée à un widget texte avec la commande de widget nomChemin window create, plusieurs options de configuration peuvent lui être associées. Ces options peuvent être modifiées ultérieurement avec la commande de widget nomChemin window configure. Les options suivantes sont actuellement prises en charge :

-align où
Si la fenêtre n'a pas la même hauteur que la ligne dans laquelle elle est affichée, cette option détermine où la fenêtre est affichée sur la ligne. Où doit avoir l'une des valeurs top (aligner le haut de la fenêtre avec le haut de la ligne), center (centrer la fenêtre dans la zone de la ligne), bottom (aligner le bas de la fenêtre avec le bas de la zone de la ligne), ou baseline (aligner le bas de la fenêtre avec la ligne de base de la ligne).
-create script
Spécifie un script Tcl qui peut être évalué pour créer la fenêtre pour le annotation. Si aucune option -window n'a été spécifiée pour l'annotation, ce script sera évalué au moment où l'annotation est sur le point d'être affichée à l'écran. Script doit créer une fenêtre pour l'annotation et retourner le nom de cette fenêtre comme résultat. Deux substitutions seront effectuées dans script avant l'évaluation. %W sera substitué par le nom du widget texte parent, et %% sera substitué par un seul %. Si la fenêtre de l'annotation doit jamais être supprimée, script sera à nouveau évalué la prochaine fois que l'annotation sera affichée.
-padx pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser de chaque côté de la fenêtre intégrée. Il peut avoir l'une des formes usuelles définies pour une distance d'écran.
-pady pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser en haut et en bas de la fenêtre intégrée. Il peut avoir l'une des formes usuelles définies pour une distance d'écran.
-stretch booléen
Si la hauteur demandée de la fenêtre intégrée est inférieure à la hauteur de la ligne dans laquelle elle est affichée, cette option peut être utilisée pour spécifier si la fenêtre doit être étirée verticalement pour remplir sa ligne. Si l'option -pady a également été spécifiée, le rembourrage demandé sera conservé même si la fenêtre est étirée.
-window nomChemin
Spécifie le nom d'une fenêtre à afficher dans l'annotation. Notez que si un nomChemin a été défini, la configuration ultérieure d'une fenêtre sur une chaîne vide ne supprimera pas le widget correspondant à l'ancien nomChemin. Elle supprimera plutôt l'association entre l'ancien nomChemin et le widget texte. Si plusieurs widgets pairs sont utilisés, il est généralement plus simple d'utiliser l'option -create si des fenêtres intégrées sont souhaitées dans chaque paire.

IMAGES INTÉGRÉES

La forme finale d'annotation dans les widgets texte est une image intégrée. Chaque annotation d'image intégrée provoque l'affichage d'une image à un point particulier du texte. Il peut y avoir un nombre quelconque d'images intégrées dans un widget texte, et une image particulière peut être intégrée à plusieurs endroits dans le même widget texte.

La position de l'image intégrée à l'écran sera mise à jour lorsque le texte sera modifié ou défilé. Chaque image intégrée occupe un espace d'index de taille unitaire dans le widget texte, et elle peut être référencée soit par sa position dans l'espace d'index du widget, soit par le nom qui lui est attribué lorsque l'image est insérée dans le widget texte avec nomChemin image créer. Si la plage de texte contenant l'image intégrée est supprimée, cette copie de l'image est retirée de l'écran.

Élir une image intégrée immédiatement après sa planification via nomChemin image créer index -create l'empêchera d'être effectivement créée. Désélire une image intégrée élidée planifiée pour la création via nomChemin image créer index -create déclenchera automatiquement le script de création associé. Après la destruction d'une image intégrée élidée, celle-ci ne sera pas recréée automatiquement.

Lorsqu'une image intégrée est ajoutée à un widget texte avec la commande de widget nomChemin image créer, un nom unique à cette instance de l'image est renvoyé. Ce nom peut ensuite être utilisé pour référencer cette instance d'image. Le nom est pris comme valeur de l'option -name (décrite ci-dessous). Si l'option -name n'est pas fournie, le nom de l'image -image est utilisé à la place. Si nomImage est déjà utilisé dans le widget texte, alors #nn est ajouté à la fin de nomImage, où nn est un entier arbitraire. Cela garantit que nomImage est unique. Une fois ce nom attribué à cette instance de l'image, il ne change pas, même si les valeurs -image ou -name peuvent être modifiées avec nomChemin image configurer.

Lorsqu'une image intégrée est ajoutée à un widget texte avec la commande de widget nomChemin image créer, plusieurs options de configuration peuvent lui être associées. Ces options peuvent être modifiées ultérieurement avec la commande de widget nomChemin image configurer. Les options suivantes sont actuellement prises en charge :

-align où
Si l'image n'a pas la même hauteur que la ligne dans laquelle elle est affichée, cette option détermine où l'image est affichée sur la ligne. Où doit avoir l'une des valeurs top (aligner le haut de l'image avec le haut de la ligne), center (centrer l'image dans la plage de la ligne), bottom (aligner le bas de l'image avec le bas de la zone de la ligne), ou baseline (aligner le bas de l'image avec la ligne de base de la ligne).
-image image
Spécifie le nom de l'image Tk à afficher dans l'annotation. Si image n'est pas une image Tk valide, une erreur est renvoyée.
-name nomImage
Spécifie le nom par lequel cette instance d'image peut être référencée dans le widget texte. Si nomImage n'est pas fourni, alors le nom de l'image Tk est utilisé à la place. Si le nomImage est déjà utilisé, #nn est ajouté à la fin du nom comme décrit ci-dessus.
-padx pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser de chaque côté de l'image intégrée. Il peut avoir l'une des formes usuelles définies pour une distance d'écran.
-pady pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser en haut et en bas de l'image intégrée. Il peut avoir l'une des formes usuelles définies pour une distance d'écran.

LA SÉLECTION

Le support de la sélection est implémenté via des tags. Si l'option -exportselection du widget texte est vraie, alors le tag sel sera associé à la sélection :

[1]
Chaque fois que des caractères sont tagués avec sel, le widget texte revendiquera la propriété de la sélection.
[2]
Les tentatives de récupération de la sélection seront traitées par le widget texte, retournant tous les caractères avec le tag sel.
[3]
Si la sélection est revendiquée par une autre application ou par une autre fenêtre de cette application, alors le tag sel sera retiré de tous les caractères du texte.
[4]
Chaque fois que la plage du tag sel change, un événement virtuel <<Selection>> est généré. Il peut également être généré lorsque la sélection est affectée mais pas réellement modifiée. De plus, plusieurs changements de sélection peuvent se produire avant que les événements ne puissent être traités, entraînant plusieurs événements avec la même sélection visible.

Le tag sel est automatiquement défini lors de la création d'un widget texte, et il ne peut pas être supprimé avec la commande de widget « nomChemin tag supprimer ». De plus, les options -selectbackground, -selectborderwidth et -selectforeground du widget texte sont liées aux options -background, -borderwidth et -foreground du tag sel : les changements dans l'une ou l'autre seront automatiquement reflétés dans l'autre. De plus, l'option -inactiveselectbackground du widget texte est utilisée à la place de -selectbackground lorsque le widget texte n'a pas le focus. Cela permet un contrôle programmatique de la visualisation du tag sel pour les fenêtres de premier plan et d'arrière-plan, ou pour que sel ne soit pas affiché du tout (lorsque -inactiveselectbackground est vide) pour les fenêtres d'arrière-plan. Chaque widget texte pair a son propre tag sel qui peut être configuré et défini séparément.

LE CURSEUR D'INSERTION

La marque nommée insert a une signification spéciale dans les widgets texte. Elle est automatiquement définie lors de la création d'un widget texte et ne peut pas être désactivée avec la commande de widget « nomChemin mark unset ». La marque insert représente la position du curseur d'insertion, et le curseur d'insertion sera automatiquement dessiné à cet endroit chaque fois que le widget texte aura le focus d'entrée.

LE FLAG MODIFIÉ

Le widget texte peut suivre les modifications du contenu du widget au moyen du flag modifié. L'insertion ou la suppression de texte définira ce flag. Le flag peut être interrogé, défini et effacé par programmation. Chaque fois que l'état du flag change, un événement virtuel <<Modifié>> est généré. Voir la commande de widget nomChemin edit modified pour plus de détails.

LE MÉCANISME D'ANNULATION

Le widget texte dispose d'un mécanisme d'annulation et de rétablissement illimité (lorsque l'option de widget -undo est vraie) qui enregistre chaque action d'insertion et de suppression sur une pile.

Des limites (appelées « séparateurs ») sont insérées entre les actions de modification. Le but de ces séparateurs est de regrouper les insertions, suppressions et remplacements en une seule action de modification composée. Lors de l'annulation d'une modification, tout ce qui se trouve entre deux séparateurs sera annulé. Les modifications annulées sont ensuite déplacées vers la pile de rétablissement, de sorte qu'une modification annulée peut être rétablis à nouveau. La pile de rétablissement est effacée chaque fois que de nouvelles actions de modification sont enregistrées sur la pile d'annulation. Les piles d'annulation et de rétablissement peuvent être effacées pour maintenir leur profondeur sous contrôle.

Les séparateurs sont insérés automatiquement lorsque l'option de widget -autoseparators est vraie. Vous pouvez également insérer des séparateurs par programmation. Si un séparateur est déjà présent en haut de la pile d'annulation, aucun autre ne sera inséré. Cela signifie que deux séparateurs sur la pile d'annulation sont toujours séparés par au moins une action d'insertion ou de suppression.

L'événement virtuel <<UndoStack>> est généré chaque fois que la pile d'annulation ou la pile de rétablissement devient vide ou non vide.

Le mécanisme d'annulation est également lié au flag modifié. Cela signifie que l'annulation ou le rétablissement des modifications peut ramener un widget texte modifié à l'état non modifié ou inversement. Le flag modifié sera automatiquement réglé à l'état approprié. Ce couplage automatique ne fonctionnera pas

ork lorsque le drapeau modified a été défini par l'utilisateur, jusqu'à ce que le drapeau soit désactivé à nouveau.

Voir ci-dessous pour la commande de widget edit de nomChemin qui contrôle le mécanisme d'annulation.

WIDGETS PAIRS

Le widget de texte possède un espace de stockage distinct pour toutes ses données concernant le contenu textuel de chaque ligne, les marques, les balises, les images et les fenêtres, ainsi que la pile d'annulation.

Bien que cet espace de stockage de données ne soit pas directement accessible (c'est-à-dire sans widget de texte comme intermédiaire), plusieurs widgets de texte peuvent être créés, chacun présentant des vues différentes sur les mêmes données sous-jacentes. De tels widgets de texte sont appelés widgets de texte pairs.

Lorsque du texte est ajouté, supprimé, modifié et colorisé dans un widget, et lorsque des images, des marques, des balises sont ajustées, toutes ces modifications seront reflétées dans tous les pairs.

Toutes les données et balises sont partagées, à l'exception de quelques détails mineurs. Premièrement, la balise sel peut être définie et configurée (dans son style d'affichage) différemment pour chaque pair. Deuxièmement, chaque pair a ses propres positions de marque insert et current (mais toutes les autres marques sont partagées). Troisièmement, les fenêtres intégrées, qui sont d'autres widgets arbitraires, ne peuvent pas être partagées entre les pairs. Cela signifie que l'option -window des fenêtres intégrées est définie indépendamment pour chaque pair (il est conseillé d'utiliser les capacités de script -create pour permettre à chaque pair de créer ses propres fenêtres intégrées selon les besoins). Quatrièmement, toutes les options de configuration de chaque pair (par exemple, -font, etc.) peuvent être définies indépendamment, à l'exception de -undo, -maxundo, -autoseparators (c'est-à-dire que tous les problèmes d'état d'annulation, de rétablissement et de modification sont partagés).

Enfin, un seul pair n'a pas besoin de contenir toutes les lignes de l'espace de stockage de données sous-jacent. Lors de la création d'un pair, une plage contiguë de lignes (par exemple, uniquement les lignes 52 à 125) peut être spécifiée. Cela permet à un pair de ne contenir qu'une petite partie du texte global. La plage de lignes s'étendra et se contractera à mesure que le texte sera inséré ou supprimé. Le pair n'affichera jamais que des lignes de texte complètes (on ne peut pas partager seulement une partie d'une ligne). Si le contenu du pair se contracte à rien (c'est-à-dire que toutes les lignes complètes du widget pair ont été supprimées d'un autre widget), alors il est impossible d'insérer de nouvelles lignes. Le pair deviendra simplement une coque vide sur laquelle l'arrière-plan peut être configuré, mais qui n'affichera jamais aucun contenu (sans reconfiguration manuelle des lignes de début et de fin). Notez qu'un pair qui ne contient pas toutes les données sous-jacentes a toujours des indices numérotés de “1.0” à “end”. Il se trouve simplement que ces indices reflètent un sous-ensemble des données totales, et les données en dehors de la plage contenue ne sont pas accessibles au pair. Cela signifie que la commande nomPair index end peut renvoyer des valeurs très différentes dans différents pairs. De même, des commandes comme nomPair tag ranges ne renverront pas de plages d'indices en dehors de ce qui est significatif pour le pair. Les options de configuration -startline et -endline peuvent être utilisées pour contrôler la quantité de données sous-jacentes contenues dans un widget de texte donné.

Notez que les pairs sont vraiment des pairs. La suppression du widget de texte “original” ne provoquera la suppression d'aucun autre pair, ni ne les affectera autrement.

Voir ci-dessous pour la commande de widget nomChemin peer qui contrôle la création de widgets pairs.

MISE À JOUR ASYNCHRONE DES HAUTEURS DE LIGNE

Afin de maintenir une expérience utilisateur réactive, le widget de texte calcule les métriques de ligne (hauteurs de ligne en pixels) de manière asynchrone. De ce fait, certaines commandes du widget de texte peuvent renvoyer des résultats incorrects si les calculs asynchrones ne sont pas terminés au moment de l'appel. Ceci s'applique à nomChemin count -ypixels et nomChemin yview.

Encore une fois, pour des raisons de performance, il ne serait pas approprié de laisser ces commandes attendre toujours la fin du calcul de mise à jour à chaque fois qu'elles sont appelées. Dans la plupart des cas d'utilisation de ces commandes, un résultat plus ou moins inexact n'a pas vraiment d'importance par rapport à la vitesse d'exécution.

Si un résultat précis est nécessaire (et si le widget de texte est géré par un gestionnaire de géométrie), on peut recourir à nomChemin sync et nomChemin pendingsync pour contrôler la synchronisation de la vue des widgets de texte.

L'événement virtuel <<WidgetViewSync>> est déclenché lorsque les hauteurs de ligne du widget de texte deviennent obsolètes (en raison d'une commande d'édition ou d'un changement de configuration), et à nouveau lorsque les données internes du widget de texte sont de nouveau synchronisées avec la vue du widget. Le champ detail (%d substitution) est soit vrai (lorsque le widget est synchronisé), soit faux (lorsqu'il ne l'est pas).

nomChemin sync, nomChemin pendingsync et <<WidgetViewSync>> s'appliquent à chaque widget de texte indépendamment de ses pairs.

Exemples d'utilisation :

## Exemple 1 :
# compléter immédiatement les métriques de ligne à tout prix (GUI non réactive)
$w sync
$w yview moveto $fraction
## Exemple 2 :
# attendre de manière synchrone des métriques de ligne à jour (GUI réactive)
# avant d'exécuter la commande programmée, mais ne pas bloquer le flux d'exécution
$w sync -command [list $w yview moveto $fraction]
## Exemple 3 :
# init
set yud($w) 0
proc updateaction w {
set ::yud($w) 1
# toute autre action de mise à jour ici...
}
# runtime, attendre de manière synchrone des métriques de ligne à jour (GUI réactive)
$w sync -command [list updateaction $w]
vwait yud($w)
$w yview moveto $fraction
## Exemple 4 :
# init
set todo($w) {}
proc updateaction w {
foreach cmd $::todo($w) {uplevel #0 $cmd}
set todo($w) {}
}
# runtime
lappend todo($w) [list $w yview moveto $fraction]
$w sync -command [list updateaction $w]
## Exemple 5 :
# init
set todo($w) {}
bind $w <<WidgetViewSync>> {
if {%d} {
foreach cmd $todo(%W) {eval $cmd}
set todo(%W) {}
}
}
# runtime
if {![$w pendingsync]} {
$w yview moveto $fraction
} else {
lappend todo($w) [list $w yview moveto $fraction]
}

COMMANDE WIDGET

La commande text crée une nouvelle commande Tcl dont le nom est le même que le nom du chemin de la fenêtre du texte. Cette commande peut être utilisée pour exécuter diverses opérations sur le widget. Elle a la forme générale suivante :

nomChemin option ?arg arg ...?
nomChemin est le nom de la commande, qui est le même que le nom du chemin du widget de texte. option et les args déterminent le comportement exact de la commande. Les commandes suivantes sont possibles pour les widgets de texte :
nomChemin bbox index
Renvoie une liste de quatre éléments décrivant la zone de l'écran du caractère donné par index. Les deux premiers éléments de la liste donnent les coordonnées x et y du coin supérieur gauche de la zone occupée par le caractère, et les deux derniers éléments donnent la largeur et la hauteur de la zone. Si le caractère n'est que partiellement visible à l'écran, alors la valeur de retour reflète uniquement la partie visible. Si le caractère n'est pas visible à l'écran, alors la valeur de retour est une liste vide.
nomChemin cget option
Renvoie la valeur actuelle de l'option de configuration donnée par option. option peut avoir l'une des valeurs acceptées par la commande text.
nomChemin compare index1 op index2
Compare les indices donnés par index1 et index2 selon l'opérateur relationnel donné par op, et renvoie 1 si la relation est satisfaite et 0 si elle ne l'est pas. op doit être l'un des opérateurs <, <=, ==, >=, >, ou !=. Si op est == alors 1 est renvoyé si les deux indices font référence au même caractère, si op est < alors 1 est renvoyé si index1 fait référence à un caractère plus précoce dans le texte que index2, et ainsi de suite.
nomChemin configure ?option? ?valeur option valeur ...?
Interroge ou modifie les options de configuration du widget. Si aucune option n'est spécifiée, renvoie une liste décrivant toutes les options disponibles pour nomChemin (voir Tk_ConfigureInfo pour des informations sur le format de cette liste). Si option est spécifiée sans valeur, alors la commande renvoie une liste décrivant l'option nommée (cette liste sera identique à la sous-liste correspondante de la valeur renvoyée si aucune option n'est spécifiée). Si une ou plusieurs paires option-valeur sont spécifiées, alors la commande modifie les options du widget données pour avoir les valeurs données ; dans ce cas, la commande renvoie une chaîne vide. option peut avoir l'une des valeurs acceptées par la commande text.
nomChemin count ?options? index1 index2
Compte le nombre d'éléments pertinents entre les deux indices. Si index1 est après index2, le résultat sera un nombre négatif (et cela vaut pour chacune des options possibles). Les éléments réels qui sont comptés dépendent des options données. Le résultat est une liste d'entiers, un pour le résultat de chaque option de comptage donnée. Les options de comptage valides sont -chars, -displaychars, -displayindices, -displaylines, -indices, -lines, -xpixels et -ypixels. La valeur par défaut, si aucune option n'est spécifiée, est -indices. Il existe une option supplémentaire possible -update qui est un modificateur. Si elle est donnée (et si le widget de texte est géré par un gestionnaire de géométrie), alors toutes les options ultérieures garantissent que toute information potentiellement obsolète est recalculée. Cela n'a actuellement d'effet que pour le comptage -ypixels (qui, si -update n'est pas donné, utilisera la valeur mise en cache actuelle du widget de texte pour chaque ligne). Cette option -update est obsolète par nomChemin sync, nomChemin pendingsync et <<WidgetViewSync>>. Les options de comptage sont interprétées comme suit :
-chars
compte tous les caractères, qu'ils soient éludés ou non. Ne compte pas les fenêtres ou les images intégrées.
-displaychars
compte tous les caractères non éludés.
-displayindices
compte tous les caractères, fenêtres et images non éludés.
-displaylines
compte toutes les lignes d'affichage (c'est-à-dire en comptant une pour chaque fois qu'une ligne est renvoyée) de la ligne du premier index jusqu'à, mais non comprise, la ligne d'affichage du deuxième index. Par conséquent, s'ils sont tous deux sur la même ligne d'affichage, zéro sera retourné. Par définition, les lignes d'affichage sont visibles et par conséquent, ceci ne compte que des portions de lignes réelles visibles.
-indices
compter tous les caractères et les fenêtres ou images intégrés (c'est-à-dire tout ce qui compte dans l'espace d'index du widget textuel), qu'ils soient éludés ou non.
-lignes
compter toutes les lignes logiques (indépendamment du renvoi) de la ligne du premier index jusqu'à, mais non comprise, la ligne du deuxième index. Par conséquent, s'ils sont tous deux sur la même ligne, zéro sera retourné. Les lignes logiques sont comptées qu'elles soient actuellement visibles (non éludées) ou non.
-xpixels
compter le nombre de pixels horizontaux du premier pixel du premier index jusqu'au (mais non compris) premier pixel du deuxième index. Pour compter la largeur totale désirée du widget textuel (en supposant que le renvoi n'est pas activé), trouvez d'abord la ligne la plus longue, puis utilisez « .text count -xpixels " [I] `${ligne}.0` [I] " [I] `${ligne}.0 lineend` ».
-ypixels
compter le nombre de pixels verticaux du premier pixel du premier index jusqu'au (mais non compris) premier pixel du deuxième index. Si les deux index sont sur la même ligne d'affichage, zéro sera retourné. Pour compter le nombre total de pixels verticaux dans le widget textuel, utilisez « .text count -ypixels 1.0 end » et pour vous assurer qu'il est à jour, utilisez « .text count -update -ypixels 1.0 end ».

La commande retourne un entier positif ou négatif correspondant au nombre d'éléments comptés entre les deux index. Un tel entier est retourné pour chaque option de comptage donnée, donc une liste est retournée si plus d'une option a été fournie. Par exemple « .text count -xpixels -ypixels 1.3 4.5 » est parfaitement valide et retournera une liste de deux éléments.

cheminNom debug ?booléen?
Si booléen est spécifié, alors il doit avoir une des valeurs vraies ou fausses acceptées par Tcl_GetBoolean. Si la valeur est vraie, alors des vérifications de cohérence interne seront activées dans le code B-tree associé aux widgets textuels. Si booléen a une valeur fausse, les vérifications de débogage seront désactivées. Dans les deux cas, la commande retourne une chaîne vide. Si booléen n'est pas spécifié, alors la commande retourne on ou off pour indiquer si le débogage est activé ou non. Il existe un seul commutateur de débogage partagé par tous les widgets textuels : activer ou désactiver le débogage dans n'importe quel widget l'active ou le désactive pour tous les widgets. Pour les widgets avec une grande quantité de texte, les vérifications de cohérence peuvent entraîner un ralentissement notable.

Lorsque le débogage est activé, les routines de dessin du widget textuel définissent les variables globales tk_textRedraw et tk_textRelayout aux listes d'index qui sont redessinés. Les valeurs de ces variables sont testées par la suite de tests de Tk.

cheminNom delete index1 ?index2 ...?
Supprime une plage de caractères du texte. Si index1 et index2 sont spécifiés, alors supprime tous les caractères à partir de celui donné par index1 et s'arrêtant juste avant index2 (c'est-à-dire que le caractère à index2 n'est pas supprimé). Si index2 ne spécifie pas une position ultérieure dans le texte par rapport à index1, alors aucun caractère n'est supprimé. Si index2 n'est pas spécifié, alors le caractère unique à index1 est supprimé. Les tentatives de suppression de caractères d'une manière qui laisserait le texte sans nouvelle ligne comme dernier caractère seront ajustées par le widget textuel pour l'éviter. En particulier, la suppression de lignes de texte complètes jusqu'à la fin du texte supprimera également le caractère de nouvelle ligne juste avant le bloc supprimé afin qu'il soit remplacé par la nouvelle nouvelle ligne finale du widget textuel. La commande retourne une chaîne vide. Si plusieurs index sont donnés, plusieurs plages de texte seront supprimées. Tous les index sont d'abord vérifiés pour leur validité avant toute suppression. Ils sont triés et le texte est retiré de la dernière plage à la première plage afin que le texte supprimé ne provoque pas d'effets secondaires indésirables de décalage d'index. Si plusieurs plages avec le même index de départ sont données, alors la plage la plus longue est utilisée. Si des plages qui se chevauchent sont données, alors elles seront fusionnées en intervalles qui ne provoquent pas la suppression de texte en dehors des plages données en raison du texte décalé pendant la suppression.
cheminNom dlineinfo index
Retourne une liste avec cinq éléments décrivant la zone occupée par la ligne d'affichage contenant index. Les deux premiers éléments de la liste donnent les coordonnées x et y du coin supérieur gauche de la zone occupée par la ligne, les troisième et quatrième éléments donnent la largeur et la hauteur de la zone, et le cinquième élément donne la position de la ligne de base pour la ligne, mesurée vers le bas à partir du haut de la zone. Toutes ces informations sont mesurées en pixels. Si le mode de renvoi actuel est none et que la ligne s'étend au-delà des limites de la fenêtre, la zone retournée reflète toute la zone de la ligne, y compris les portions qui sont hors de la fenêtre. Si la ligne est plus courte que la largeur totale de la fenêtre, alors la zone retournée reflète seulement la portion de la ligne occupée par les caractères et les fenêtres intégrées. Si la ligne d'affichage contenant index n'est pas visible à l'écran, alors la valeur de retour est une liste vide.
cheminNom dump ?commutateurs? index1 ?index2?
Retourne le contenu du widget textuel de index1 jusqu'à, mais non compris, index2, incluant le texte et des informations sur les marques, les étiquettes et les fenêtres intégrées. Si index2 n'est pas spécifié, alors il est par défaut un caractère après index1. Les informations sont retournées dans le format suivant :

clé1 valeur1 index1 clé2 valeur2 index2 ...

Les valeurs possibles de clé sont text, mark, tagon, tagoff, image, et window. La valeur correspondante est le texte, le nom de la marque, le nom de l'étiquette, le nom de l'image, ou le nom de la fenêtre. L'information index est l'index du début du texte, de la marque, de la transition d'étiquette, de l'image ou de la fenêtre. Un ou plusieurs des commutateurs suivants (ou leurs abréviations) peuvent être spécifiés pour contrôler le dump :

-all
Retourne des informations sur tous les éléments : texte, marques, étiquettes, images et fenêtres. C'est la valeur par défaut.
-command commande
Au lieu de retourner les informations comme résultat de l'opération de dump, invoque la commande sur chaque élément du widget textuel dans la plage. La commande a trois arguments ajoutés avant d'être évaluée : la clé, la valeur, et l'index.
-image
Inclut des informations sur les images dans les résultats du dump.
-mark
Inclut des informations sur les marques dans les résultats du dump.
-tag
Inclut des informations sur les transitions d'étiquettes dans les résultats du dump. Les informations d'étiquette sont retournées comme des éléments tagon et tagoff qui indiquent le début et la fin de chaque plage de chaque étiquette, respectivement.
-text
Inclut des informations sur le texte dans les résultats du dump. La valeur est le texte jusqu'à l'élément suivant ou la fin de la plage indiquée par index2. Un élément de texte ne s'étend pas sur les nouvelles lignes. Un bloc de texte multiligne qui ne contient aucune marque ou transition d'étiquette sera toujours déversé comme un ensemble de segments de texte se terminant chacun par une nouvelle ligne. La nouvelle ligne fait partie de la valeur.
-window
Inclut des informations sur les fenêtres intégrées dans les résultats du dump. La valeur d'une fenêtre est son chemin Tk, sauf si la fenêtre n'a pas encore été créée. (Elle doit avoir un script de création.) Dans ce cas, une chaîne vide est retournée, et vous devez interroger la fenêtre par sa position d'index pour obtenir plus d'informations.
cheminNom edit option ?arg arg ...?
Cette commande contrôle le mécanisme d'annulation et le drapeau modifié. Le comportement exact de la commande dépend de l'argument option qui suit l'argument edit. Les formes suivantes de la commande sont actuellement prises en charge :
cheminNom edit canredo
Retourne un booléen vrai si la ré-exécution est possible, c'est-à-dire lorsque la pile de ré-exécution n'est pas vide. Sinon, retourne faux.
cheminNom edit canundo
Retourne un booléen vrai si l'annulation est possible, c'est-à-dire lorsque la pile d'annulation n'est pas vide. Sinon, retourne faux.
cheminNom edit modified ?booléen?
Si booléen n'est pas spécifié, retourne le drapeau modifié du widget. Les commandes d'insertion, de suppression, d'édition d'annulation et de ré-exécution d'édition ou l'utilisateur peuvent définir ou effacer le drapeau modifié. Si booléen est spécifié, définit le drapeau modifié du widget à booléen.
cheminNom edit redo
Lorsque l'option -undo est vraie, réapplique les dernières modifications annulées à condition qu'aucune autre modification n'ait été effectuée depuis. Génère une erreur lorsque la pile de ré-exécution est vide. Ne fait rien lorsque l'option -undo est fausse.
cheminNom edit reset
Efface les piles d'annulation et de ré-exécution.
cheminNom edit separator
Insère un séparateur (limite) sur la pile d'annulation. Ne fait rien lorsque l'option -undo est fausse.
cheminNom edit undo
Annule la dernière action de modification lorsque l'option -undo est vraie. Une action de modification est définie comme toutes les commandes d'insertion et de suppression
qui sont enregistrés sur la pile d'annulation entre deux séparateurs. Génère une erreur lorsque la pile d'annulation est vide. Ne fait rien lorsque l'option -undo est fausse.
pathName get ?-displaychars? ?--? index1 ?index2 ...?
Retourne une plage de caractères du texte. La valeur de retour sera tous les caractères du texte, commençant par celui dont l'index est index1 et se terminant juste avant celui dont l'index est index2 (le caractère à index2 ne sera pas retourné). Si index2 est omis, alors le caractère unique à index1 est retourné. S'il n'y a pas de caractères dans la plage spécifiée (par exemple, si index1 est après la fin du fichier ou si index2 est inférieur ou égal à index1), une chaîne vide est retournée. Si la plage spécifiée contient des fenêtres intégrées, aucune information à leur sujet n'est incluse dans la chaîne retournée. Si plusieurs paires d'indices sont données, plusieurs plages de texte seront retournées dans une liste. Les plages invalides ne seront pas représentées par des chaînes vides dans la liste. Les plages sont retournées dans l'ordre où elles sont passées à pathName get. Si l'option -displaychars est donnée, alors, à l'intérieur de chaque plage, seuls les caractères qui ne sont pas éludés seront retournés. Cela peut avoir pour effet que certaines des plages retournées soient des chaînes vides.
pathName image option ?arg arg ...?
Cette commande est utilisée pour manipuler les images intégrées. Le comportement de la commande dépend de l'argument option qui suit l'argument image. Les formes suivantes de la commande sont actuellement prises en charge :
pathName image cget index option
Retourne la valeur d'une option de configuration pour une image intégrée. Index identifie l'image intégrée, et option spécifie une configuration particulière, qui doit être l'une de celles listées dans la section IMPRIMÉS INTÉGRÉS.
pathName image configure index ?option value ...?
Interroge ou modifie les options de configuration pour une image intégrée. Si aucune option n'est spécifiée, retourne une liste décrivant toutes les options disponibles pour l'image intégrée à l'index (voir Tk_ConfigureInfo pour plus d'informations sur le format de cette liste). Si option est spécifiée sans valeur, alors la commande retourne une liste décrivant l'option nommée (cette liste sera identique à la sous-liste correspondante de la valeur retournée si aucune option n'est spécifiée). Si une ou plusieurs paires option-valeur sont spécifiées, alors la commande modifie les options données pour leur attribuer les valeurs données ; dans ce cas, la commande retourne une chaîne vide. Voir IMPRIMÉS INTÉGRÉS pour des informations sur les options prises en charge.
pathName image create index ?option value ...?
Cette commande crée une nouvelle annotation d'image, qui apparaîtra dans le texte à la position donnée par index. Un nombre quelconque de paires option-valeur peuvent être spécifiées pour configurer l'annotation. Retourne un identifiant unique qui peut être utilisé comme index pour faire référence à cette image. Voir IMPRIMÉS INTÉGRÉS pour des informations sur les options prises en charge, et une description de l'identifiant retourné.
pathName image names
Retourne une liste dont les éléments sont les noms de toutes les instances d'image actuellement intégrées dans window.
pathName index index
Retourne la position correspondant à index sous la forme ligne.caractère où ligne est le numéro de ligne et caractère est le numéro de caractère. Index peut avoir l'une des formes décrites sous INDEX ci-dessus.
pathName insert index chars ?tagList chars tagList ...?
Insère tous les arguments chars juste avant le caractère à index. Si index fait référence à la fin du texte (le caractère après la dernière nouvelle ligne), alors le nouveau texte est inséré juste avant la dernière nouvelle ligne. S'il y a un seul argument chars et aucune tagList, alors le nouveau texte recevra les balises qui sont présentes à la fois sur le caractère avant et le caractère après le point d'insertion ; si une balise n'est présente que sur l'un de ces caractères, elle ne sera pas appliquée au nouveau texte. Si tagList est spécifié, alors il consiste en une liste de noms de balises ; les nouveaux caractères recevront toutes les balises de cette liste et aucune autre, indépendamment des balises présentes autour du point d'insertion. Si plusieurs paires chars-tagList sont présentes, elles produisent le même effet que si une commande pathName insert distincte avait été émise pour chaque paire, dans l'ordre. Le dernier argument tagList peut être omis.
pathName mark option ?arg arg ...?
Cette commande est utilisée pour manipuler les marques. Le comportement exact de la commande dépend de l'argument option qui suit l'argument mark. Les formes suivantes de la commande sont actuellement prises en charge :
pathName mark gravity markName ?direction?
Si direction n'est pas spécifié, retourne left ou right pour indiquer à quel de ses caractères adjacents markName est attaché. Si direction est spécifié, il doit être left ou right ; la gravité de markName est définie sur la valeur donnée.
pathName mark names
Retourne une liste dont les éléments sont les noms de toutes les marques qui sont actuellement définies.
pathName mark next index
Retourne le nom de la marque suivante à partir de index ou après. Si index est spécifié sous forme numérique, alors la recherche de la marque suivante commence à cet index. Si index est le nom d'une marque, alors la recherche de la marque suivante commence immédiatement après cette marque. Cela peut encore retourner une marque à la même position s'il y a plusieurs marques au même index. Ces sémantiques signifient que l'opération mark next peut être utilisée pour parcourir toutes les marques d'un widget texte dans le même ordre que les informations de marque retournées par l'opération pathName dump. Si une marque a été définie sur l'index spécial end, alors elle apparaît comme étant après end par rapport à l'opération pathName mark next. Une chaîne vide est retournée s'il n'y a pas de marques après index.

Si index est le nom d'une marque, alors la recherche de la marque suivante commence juste avant cette marque. Cela peut encore retourner une marque à la même position s'il y a plusieurs marques au même index. Ces sémantiques signifient que l'opération pathName mark previous peut être utilisée pour parcourir toutes les marques d'un widget texte dans l'ordre inverse des informations de marque retournées par l'opération pathName dump. pathName search ?switches? pattern index ?stopIndex?
Recherche le texte dans pathName à partir de index pour une plage de caractères correspondant à pattern. Si une correspondance est trouvée, l'index du premier caractère de la correspondance est renvoyé comme résultat ; sinon, une chaîne vide est renvoyée. Un ou plusieurs des commutateurs suivants (ou leurs abréviations) peuvent être spécifiés pour contrôler la recherche :
-forwards
La recherche se poursuivra vers l'avant dans le texte, trouvant la première plage correspondante commençant à ou après la position donnée par index. C'est le comportement par défaut.
-backwards
La recherche se poursuivra vers l'arrière dans le texte, trouvant la plage correspondante la plus proche de index dont le premier caractère est avant index (il n'est pas autorisé d'être à index). Notez que, pour diverses raisons, les recherches inversées peuvent être considérablement plus lentes que les recherches avant (en particulier lors de l'utilisation de -regexp), il est donc recommandé que le code critique en termes de performance utilise des recherches avant.
-exact
Utilise une correspondance exacte : les caractères dans la plage correspondante doivent être identiques à ceux de pattern. C'est le comportement par défaut.
-regexp
Traite pattern comme une expression régulière et la fait correspondre au texte en utilisant les règles des expressions régulières (voir la commande regexp et la page re_syntax pour les détails). La correspondance par défaut passe automatiquement les options -lineanchor et -linestop au moteur regexp (sauf si -nolinestop est utilisé), de sorte que ^$ correspondent au début et à la fin de la ligne, et ., [^ les séquences ne correspondront jamais au caractère de nouvelle ligne \n.
-nolinestop
Cela permet à . et [^ les séquences de correspondre au caractère de nouvelle ligne \n, ce qu'elles ne feront pas autrement (voir la commande regexp pour les détails). Cette option n'est pertinente que si -regexp est également donné, et une erreur sera générée sinon. Par exemple, pour faire correspondre l'intégralité du texte, utilisez “pathName search -nolinestop -regexp ".*" 1.0”.
-nocase
Ignore les différences de casse entre le motif et le texte.
-count varName
L'argument suivant -count donne le nom d'une variable ; si une correspondance est trouvée, le nombre d'positions d'index entre le début et la fin de la plage correspondante sera stocké dans la variable. S'il n'y a pas d'images ou de fenêtres intégrées dans la plage correspondante (et s'il n'y a pas de caractères élidés si -elide n'est pas donné), cela équivaut au nombre de caractères correspondants. Dans les deux cas, la plage matchIdx à matchIdx + $count caractères retournera le texte intégralement correspondant.
-all
Trouve toutes les correspondances dans la plage donnée et renvoie une liste des index du premier caractère de chaque correspondance. Si un commutateur -count varName est donné, alors varName est également défini sur une liste contenant un élément pour chaque correspondance réussie. Notez que, même pour les recherches exactes, les éléments de cette liste peuvent être différents, s'il y a des images intégrées, des fenêtres ou du texte caché. Les recherches avec -all se comportent de manière très similaire à la commande Tcl regexp -all, en ce sens que les correspondances qui se chevauchent ne sont normalement pas retournées. Par exemple, appliquer une recherche -all du motif “\w+” sur “hello there” ne trouvera que deux correspondances, une pour chaque mot, et faire correspondre “Z[a-z]+Z” à “ZooZooZoo” ne trouvera qu'une seule correspondance.
-overlap
Lors de l'exécution de recherches -all, le comportement normal est que les correspondances qui chevauchent une correspondance déjà trouvée ne seront pas retournées. Ce commutateur modifie ce comportement de sorte que toutes les correspondances qui ne sont pas totalement incluses dans une autre correspondance soient retournées. Par exemple, appliquer une recherche -overlap du motif “\w+” sur “hello there” ne trouvera que deux correspondances (c'est-à-dire qu'il n'y a aucune différence avec juste -all), mais faire correspondre “Z[a-z]+Z” à “ZooZooZoo” trouvera maintenant deux correspondances. Une erreur sera générée si ce commutateur est utilisé sans -all.
-strictlimits
Lors de toute recherche, le comportement normal est que les limites de début et de fin sont vérifiées par rapport au début du texte correspondant. Avec le drapeau -strictlimits, toute la plage correspondante doit se trouver à l'intérieur des limites de début et de fin spécifiées pour que la correspondance soit valide.
-elide
Recherche également le texte élidé (caché). Par défaut, seul le texte affiché est recherché.
--
Ce commutateur n'a aucun effet, sauf celui de terminer la liste des commutateurs : l'argument suivant sera traité comme pattern même s'il commence par -.

La plage correspondante peut se situer sur une seule ligne de texte, ou s'étendre sur plusieurs lignes (si des parties du motif peuvent correspondre à un nouveau caractère de ligne). Pour la correspondance d'expressions régulières, vous pouvez utiliser les diverses fonctionnalités de correspondance de nouvelles lignes telles que $ pour correspondre à la fin d'une ligne, ^ pour correspondre au début d'une ligne, et pour contrôler si . est autorisé à correspondre à un nouveau caractère de ligne. Si stopIndex est spécifié, la recherche s'arrête à cet index : pour les recherches avant, aucune correspondance à ou après stopIndex ne sera considérée ; pour les recherches arrière, aucune correspondance avant dans le texte que stopIndex ne sera considérée. Si stopIndex est omis, l'intégralité du texte sera recherchée : lorsque le début ou la fin du texte est atteint, la recherche continue à l'autre extrémité jusqu'à ce que l'emplacement de départ soit à nouveau atteint ; si stopIndex est spécifié, aucun retournement ne se produira. Cela signifie que, par exemple, si la recherche est -forwards mais que stopIndex est plus tôt dans le texte que startIndex, rien ne sera jamais trouvé. Si script et sequence sont tous deux omis, la commande renvoie une liste de toutes les séquences pour lesquelles des liaisons ont été définies pour tagName.

Les seuls événements pour lesquels des liaisons peuvent être spécifiées sont ceux liés à la souris et au clavier (tels que Enter, Leave, ButtonPress, Motion, et KeyPress) ou des événements virtuels. Les liaisons d'événements de souris et de clavier pour un widget texte utilisent respectivement les marques current et insert décrites sous MARQUES ci-dessus. Un événement Enter est déclenché pour une balise lorsque la balise devient pour la première fois présente sur le caractère courant, et un événement Leave est déclenché pour une balise lorsqu'elle cesse d'être présente sur le caractère courant. Les événements Enter et Leave peuvent se produire soit parce que la marque current s'est déplacée, soit parce que le caractère à cette position a changé. Notez que ces événements sont différents des événements Enter et Leave pour les fenêtres. Les événements de souris sont dirigés vers le caractère courant, tandis que les événements de clavier sont dirigés vers le caractère d'insertion. Si un événement virtuel est utilisé dans une liaison, cette liaison ne peut être déclenchée que si l'événement virtuel est défini par un événement sous-jacent lié à la souris ou au clavier.

Il est possible que le caractère courant ait plusieurs balises, et que chacune d'elles ait une liaison pour une séquence d'événements particulière. Lorsque cela se produit, une liaison est invoquée pour chaque balise, dans l'ordre de priorité la plus basse à la plus haute. S'il existe plusieurs liaisons correspondantes pour une seule balise, la liaison la plus spécifique est choisie (voir l'entrée du manuel de la commande bind pour plus de détails). Les commandes continue et break dans les scripts de liaison sont traitées de la même manière que pour les liaisons créées avec la commande bind.

Si des liaisons sont créées pour le widget dans son ensemble en utilisant la commande bind, ces liaisons complèteront les liaisons de balises. Les liaisons de balises seront invoquées en premier, suivies des liaisons pour la fenêtre dans son ensemble.

DESCRIPTION

The text widget displays text in multiple lines, with support for various fonts, colors, and other attributes. Text can be associated with arbitrary indices in the text, and these indices can be used to change the attributes of the text, or to bind commands to arbitrary regions of the text. The text widget can also be embedded with other Tk widgets, such as buttons and canvases.

The text widget is organized as a sequence of characters. Each character is associated with an index, which is a string that normally identifies a position between characters. The first character in the text widget is at index 1.0 (line 1, character 0). Indices have the following formats:

[i]
A floating-point number i. The integer part of i indicates the line number (starting from 1), and the fractional part indicates the character position within that line (starting from 0). For example, 1.0 refers to the first character of the first line, and 3.5 refers to the 5th character of the 3rd line. If an index is not present, it defaults to 1.0.
[i].end
Refers to the position after the last character in line i. For example, 1.end refers to the position after the last character of the first line.
end
Refers to the position after the last character in the text widget. This is equivalent to 1.end where 1 is the number of the last line in the widget.
insert
Refers to the current position of the insertion cursor.
current
Refers to the position of the insertion cursor if the mouse button is currently pressed down, or the position of the insertion cursor if the mouse button is not pressed down. This is useful for button-activated selections.
anchor
Refers to the anchor position of the selection. The anchor is the position at which the selection started.
[+/-]N
If N is an integer, this refers to the character position N characters before or after the current insertion cursor position. For example, insert-1 refers to the character before the insertion cursor.
[+/-]N chars
Similar to +/-N, but the count is in characters. A character is defined as a unit of text that is displayed as a single glyph. This includes non-ASCII characters.
[+/-]N words
Moves N words forwards or backwards from the insertion cursor. Words are delimited by the characters defined in the -wordBreak option.
[+/-]N lines
Moves N lines forwards or backwards from the insertion cursor. Lines are delimited by newline characters.
[+/-]N paragraphs
Moves N paragraphs forwards or backwards from the insertion cursor. Paragraphs are delimited by one or more blank lines.
[+/-]N sceans
Moves N sceans forwards or backwards from the insertion cursor. Sceans are delimited by the characters defined in the -sceneBreak option.
markName
Refers to the position of the mark named markName.
@x,y
Refers to the character position nearest the screen coordinates x,y. Coordinates are relative to the widget's top-left corner.

In addition to the above, indices can be combined with modifiers like - or + to specify positions relative to a given index. For example, 1.0+2c refers to the position 2 characters after the beginning of the first line.

KNOWN ISSUES

ISSUES CONCERNING CHARS AND INDICES

Before Tk 8.5, the widget used the string “chars” to refer to index positions (which included characters, embedded windows and embedded images). As of Tk 8.5 the text widget deals separately and correctly with “chars” and “indices”. For backwards compatibility, however, the index modifiers “+N chars” and “-N chars” continue to refer to indices. One must use any of the full forms “+N any chars” or “-N any chars” etc. to refer to actual character indices. This confusion may be fixed in a future release by making the widget correctly interpret “+N chars” as a synonym for “+N any chars”.

PERFORMANCE ISSUES

Text widgets should run efficiently under a variety of conditions. The text widget uses about 2-3 bytes of main memory for each byte of text, so texts containing a megabyte or more should be practical on most workstations. Text is represented internally with a modified B-tree structure that makes operations relatively efficient even with large texts. Tags are included in the B-tree structure in a way that allows tags to span large ranges or have many disjoint smaller ranges without loss of efficiency. Marks are also implemented in a way that allows large numbers of marks. In most cases it is fine to have large numbers of unique tags, or a tag that has many distinct ranges.

One performance problem can arise if you have hundreds or thousands of different tags that all have the following characteristics: the first and last ranges of each tag are near the beginning and end of the text, respectively, or a single tag range covers most of the text widget. The cost of adding and deleting tags like this is proportional to the number of other tags with the same properties. In contrast, there is no problem with having thousands of distinct tags if their overall ranges are localized and spread uniformly throughout the text.

Very long text lines can be expensive, especially if they have many marks and tags within them.

The display line with the insert cursor is redrawn each time the cursor blinks, which causes a steady stream of graphics traffic. Set the -insertofftime attribute to 0 avoid this.

KNOWN BUGS

The pathName search -regexp sub-command attempts to perform sophisticated regexp matching across multiple lines in an efficient fashion (since Tk 8.5), examining each line individually, and then in small groups of lines, whether searching forwards or backwards. Under certain conditions the search result might differ from that obtained by applying the same regexp to the entire text from the widget in one go. For example, when searching with a greedy regexp, the widget will continue to attempt to add extra lines to the match as long as one of two conditions are true: either Tcl's regexp library returns a code to indicate a longer match is possible (but there are known bugs in Tcl which mean this code is not always correctly returned); or if each extra line added results in at least a partial match with the pattern. This means in the case where the first extra line added results in no match and Tcl's regexp system returns the incorrect code and adding a second extra line would actually match, the text widget will return the wrong result. In practice this is a rare problem, but it can occur, for example:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\ncccc\nbbbb\naaaa\n"
.t search -regexp -- {(a+|b+\nc+\nb+)+\na+} 1.0
will not find a match when one exists of 19 characters starting from the first “b”.

Whenever one possible match is fully enclosed in another, the search command will attempt to ensure only the larger match is returned. When performing backwards regexp searches it is possible that Tcl will not always achieve this, in the case where a match is preceded by one or more short, non-overlapping matches, all of which are preceded by a large match which actually encompasses all of them. The search algorithm used by the widget does not look back arbitrarily far for a possible match which might cover large portions of the widget. For example:

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\nbbbb\nbbbb\nbbbb\n"
.t search -regexp -backward -- {b+\n|a+\n(b+\n)+} end
matches at “5.0” when a true greedy match would match at “1.0”. Similarly if we add -all to this case, it matches at all of “5.0”, “4.0”, “3.0” and “1.0”, when really it should only match at “1.0” since that match encloses all the others.

NOM

tk_textCut - Coupe ou supprime une portion de texte du tampon.

SYNOPIS

tk_textCut widget ?range?

DESCRIPTION

La commande tk_textCut coupe le texte dans la plage spécifiée du tampon de texte du widget widget, puis place le texte coupé dans le presse-papiers du système.

Si aucun range n'est spécifié, la sélection actuelle est utilisée. Si la sélection est vide, rien ne se passe.

INVOCATION

widget : Le nom du widget Tk Text dont le contenu doit être modifié.

range : Une chaîne spécifiant la plage de texte à couper. La syntaxe de range est décrite dans la page de manuel tk_text. La plage par défaut est la sélection actuelle.

OPTIONS

Aucune option spécifique à cette commande.

PARAMÈTRES

Aucun paramètre spécifique à cette commande.

DÉTAILS

La commande tk_textCut effectue deux actions principales :

  1. Elle supprime le texte spécifié par range du tampon du widget.
  2. Elle copie le texte supprimé dans le presse-papiers du système.

Si vous souhaitez simplement supprimer le texte sans le copier dans le presse-papiers, utilisez la commande tk_textDelete.

Cette commande est généralement appelée via une association de touches (par exemple, Ctrl+X) ou un élément de menu.

MARQUES

Les marques du texte ne sont pas affectées par cette opération, sauf si elles se trouvent dans la plage coupée, auquel cas elles sont supprimées.

FENÊTRES EMBARQUÉES

Si la plage coupée contient des fenêtres embarquées, celles-ci sont également supprimées du tampon. Les fenêtres elles-mêmes ne sont pas affectées.

IMAGES EMBARQUÉES

Si la plage coupée contient des images embarquées, celles-ci sont également supprimées du tampon. Les images elles-mêmes ne sont pas affectées.

LA SÉLECTION

Si aucun range n'est spécifié, la sélection actuelle est coupée. Après l'opération, il n'y a plus de sélection active.

LE CURSEUR D'INSERTION

Le curseur d'insertion est positionné au début de la plage coupée après l'opération.

LE DRAPEAU MODIFIÉ

L'option -modified du widget Text (si elle est activée) est mise à true après une opération de coupe réussie.

LE MÉCANISME D'ANNULATION

La commande tk_textCut est généralement enregistrée dans le mécanisme d'annulation du widget Text, permettant son annulation ultérieure avec la commande tk_textUndo.

WIDGETS JUMEAUX

Si le widget Text est un widget jumeau (par exemple, pour le partage d'une sélection), la coupe se fait sur le tampon du widget spécifié.

MISE À JOUR ASYNCHRONE DES HAUTEURS DE LIGNE

Les modifications de contenu dues à la coupe peuvent entraîner une mise à jour asynchrone des hauteurs de ligne pour maintenir une mise en page cohérente.

COMMANDE DE WIDGET

tk_textCut est une sous-commande de la commande principale du widget Text.

ASSOCIATIONS

Cette commande est souvent associée à des événements clavier et souris pour permettre aux utilisateurs d'interagir facilement avec le tampon de texte.

PROBLÈMES CONNUS

Aucun problème connu n'est spécifiquement documenté pour cette commande.
