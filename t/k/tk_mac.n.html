CALLBACKS DE GESTIONNAIRE D'ÉVÉNEMENTS

L'environnement applicatif Aqua/macOS définit un certain nombre d'événements supplémentaires auxquels les applications doivent répondre. Ces événements sont mappés par Tk à des appels de commandes dans le namespace ::tk::mac ; sauf indication contraire, si la commande est absente, aucune action ne sera entreprise.

::tk::mac::DoScriptFile
Le gestionnaire d'événements Apple par défaut pour AEDoScriptHandler. Cette commande exécute un fichier Tcl lorsqu'un AppleScript envoie une commande « do script » à Wish avec un chemin de fichier comme paramètre.
::tk::mac::DoScriptText
Le gestionnaire d'événements Apple par défaut pour AEDoScriptHandler. Cette commande exécute du code Tcl lorsqu'un AppleScript envoie une commande « do script » à Wish avec du code Tcl ou une procédure Tcl comme paramètre.
::tk::mac::ShowPreferences
Le gestionnaire d'événements Apple par défaut pour kAEShowPreferences, « pref ». L'élément de menu « Préférences » du menu de l'application n'est activé que lorsque cette procédure est définie. Généralement, cette commande est utilisée pour encapsuler une commande spécifique de préférences de l'application, qui fait apparaître une fenêtre de préférences. Quelque chose comme :
proc ::tk::mac::ShowPreferences {} {
    setPref
}
::tk::mac::OpenApplication
Si une procédure de ce nom est définie, cette procédure sera appelée lorsque votre application sera ouverte initialement. C'est le gestionnaire d'événements Apple par défaut pour kAEOpenApplication, « oapp ».
::tk::mac::ReopenApplication
Si une procédure de ce nom est définie, c'est le gestionnaire d'événements Apple par défaut pour kAEReopenApplication, « rapp », l'événement Apple envoyé lorsque votre application est ouverte alors qu'elle est déjà en cours d'exécution (par exemple, en cliquant sur son icône dans le Dock). Voici un exemple qui affiche une fenêtre minimisée lorsque l'icône du Dock est cliquée :
proc ::tk::mac::ReopenApplication {} {
    if {[wm state .] eq "withdrawn"} {
        wm state . normal
    } else {
        wm deiconify .
    }
    raise .
}
::tk::mac::OpenDocument fichier...
Si une procédure de ce nom est définie, c'est le gestionnaire d'événements Apple par défaut pour kAEOpenDocuments, « odoc », l'événement Apple envoyé lorsque votre application est invitée à ouvrir un ou plusieurs documents (par exemple, par glisser-déposer sur l'application ou en ouvrant un document d'un type associé à l'application). La procédure doit prendre en arguments les chemins des fichiers à ouvrir, comme ceci :
proc ::tk::mac::OpenDocument {args} {
    foreach f $args {my_open_document $f}
}
::tk::mac::PrintDocument fichier...
Si une procédure de ce nom est définie, c'est le gestionnaire d'événements Apple par défaut pour kAEPrintDocuments, « pdoc », l'événement Apple envoyé lorsque votre application est invitée à imprimer un document. Elle prend en argument un seul chemin de fichier absolu.
::tk::mac::Quit
Si une procédure de ce nom est définie, c'est le gestionnaire d'événements Apple par défaut pour kAEQuitApplication, « quit », l'événement Apple envoyé lorsque votre application est invitée à se quitter, par exemple via l'élément de menu « Quitter » dans le menu de l'application, l'élément de menu « Quitter » dans le menu du Dock, ou lors d'une déconnexion/redémarrage/arrêt, etc. Si ce n'est pas défini, exit est appelé à la place.
::tk::mac::OnHide
Si défini, ceci est appelé lorsque votre application reçoit un événement kEventAppHidden, par exemple via l'élément de menu « Cacher » du menu de l'application ou du Dock.
::tk::mac::OnShow
Si défini, ceci est appelé lorsque votre application reçoit un événement kEventAppShown, par exemple via l'élément de menu « Afficher tout » du menu de l'application, ou en cliquant sur l'icône du Dock d'une application cachée.
::tk::mac::ShowHelp
Personnalise le comportement du menu Aide d'Apple ; si cette procédure n'est pas définie, l'élément de menu Aide standard spécifique à la plateforme « Aide [VotreApp] » effectue l'action Cocoa par défaut consistant à afficher le Livre d'aide configuré dans le fichier Info.plist de l'application (ou à afficher une alerte si aucun Livre d'aide n'est défini).
::tk::mac::PerformService
Exécute une procédure Tcl appelée depuis le menu « Services » de macOS dans l'élément de menu de l'application. Le menu « Services » permet la communication inter-applications ; des données d'une application, comme du texte sélectionné, peuvent être envoyées à une autre application pour traitement, par exemple à Safari en tant qu'élément de recherche pour Google, ou à TextEdit pour être ajoutées à un fichier. Un exemple de la procédure est ci-dessous, et devrait être réécrit dans un script d'application pour la personnalisation :
proc ::tk::mac::PerformService {} {
    set data [clipboard get]
    $w insert end $data
}
Notez que le mécanisme pour récupérer les données provient du presse-papiers ; il n'existe aucun autre moyen pris en charge pour obtenir les données. Si le processus de Services n'est pas souhaité, les clés NSServices peuvent être supprimées du fichier Info.plist de l'application. Le code sous-jacent prenant en charge cette commande permet également aux widgets text, entry et ttk::entry d'accéder aux services d'autres applications via le menu Services. La clé NSPortName dans le fichier Info.plist de Wish est actuellement définie sur « Wish » ; si un développeur modifie le nom de l'exécutable Wish en quelque chose
d'autre, cette clé doit être modifiée avec le même nom.
::tk::mac::LaunchURL URL...
Si défini, lance une URL au sein de Tk. Ceci serait utilisé si une application Tk souhaite gérer une URL elle-même, comme afficher des données d'un flux RSS, plutôt que de lancer une application par défaut pour gérer l'URL, bien qu'elle puisse être définie comme telle. Wish inclut un schéma d'URL de substitution « foo:// » dans la clé CFBundleURLSchemes de son fichier Info.plist ; cela doit être personnalisé pour le schéma d'URL spécifique que le développeur souhaite prendre en charge.
::tk::mac::GetAppPath
Retourne le chemin du fichier de l'application en cours.

DIALOGUES ADDITIONNELS

Aqua/macOS définit des dialogues supplémentaires que les applications doivent prendre en charge.

::tk::mac::standardAboutPanel
Fait apparaître le panneau « À propos » standard de Cocoa avec les informations remplies à partir des fichiers du bundle d'application. Le panneau affiche l'icône de l'application et les valeurs associées aux clés info.plist nommées CFBundleName, CFBundleShortVersionString, NSAboutPanelOptionVersion et NSHumanReadableCopyright. Si un fichier nommé Credits.html ou Credits.rtf existe dans le répertoire Resources du bundle, son contenu sera affiché dans une zone de texte défilante en bas de la boîte de dialogue. Voir la documentation pour -[NSApplication orderFrontStandardAboutPanelWithOptions:] pour plus de détails. Un point d'accroche est également prévu pour une boîte de dialogue « À propos » personnalisée. Si une procédure Tcl nommée tkAboutDialog est définie dans l'interpréteur principal, cette procédure sera appelée au lieu d'ouvrir standardAboutPanel.

CONFIGURATION SYSTÈME

Il existe un certain nombre d'options de configuration globales supplémentaires qui contrôlent les détails du rendu par défaut de Tk.

::tk::mac::useCompatibilityMetrics booléen
Préserve la compatibilité avec les anciennes métriques Tk/Aqua ; régler à false pour un espacement plus natif.
::tk::mac::CGAntialiasLimit limite
Définit la limite d'anti-aliasing ; les lignes plus fines que limite pixels ne seront pas anti-aliasées. Entier, réglé à 0 par défaut, ce qui rend toutes les lignes anti-aliasées.
::tk::mac::antialiasedtext nombre
Définit le texte anti-aliasé. Contrôle l'anti-aliasing du texte
liasing, valeurs possibles pour nombre sont -1 (par défaut, utiliser la valeur par défaut du système pour le texte AA), 0 (pas de AA de texte), 1 (utiliser le AA de texte).
::tk::mac::useThemedToplevel booléen
Définit les fenêtres de niveau supérieur pour qu'elles s'affichent avec le fond grisâtre/rayé moderne de Mac. Équivalent à configurer la fenêtre de niveau supérieur avec “-background systemWindowHeaderBackground”, ou à utiliser un ttk::frame.

COMMANDES DE SUPPORT

::tk::mac::iconBitmap nom largeur hauteur -type valeur
Rend les icônes natives et les bitmaps dans les applications Tk (y compris tout fichier image lisible par NSImage). Un nom de bitmap natif est interprété comme suit (dans l'ordre) :
  • nom d'icône intégré prédéfini 32x32 (stop, caution, document, etc.)
  • nom, tel que défini par tk::mac::iconBitmap
  • Nom d'image NSImage
  • Chaîne d'URL NSImage
  • Type OSType 4 caractères de l'icône IconServices

Les arguments largeur et hauteur de tk::mac::iconBitmap définissent les dimensions de l'image à créer, et -type doit être l'un des éléments suivants :

-file
icône du fichier au chemin donné
-fileType
icône du type de fichier donné
-osType
icône du type de fichier OSType 4 caractères donné
-systemType
icône pour le type OSType 4 caractères IconServices donné
-namedImage
NSImage nommé pour le nom donné
-imageFile
image au chemin donné
