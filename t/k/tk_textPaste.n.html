Nom de ligne de commande : -tabs
Nom de base de données : tabs
Classe de base de données : Tabs
Spécifie un ensemble de taquets de tabulation pour la fenêtre. La valeur de l'option consiste en une liste de distances d'écran donnant les positions des taquets de tabulation, dont chacun est une distance relative au bord gauche du widget (excluant les bordures, le remplissage, etc.). Chaque position peut facultativement être suivie dans l'élément de liste suivant par l'un des mots-clés left, right, center, ou numeric, qui spécifie comment justifier le texte par rapport au taquet de tabulation. Left est le défaut ; il provoque le positionnement du texte suivant le caractère de tabulation avec son bord gauche à la position de tabulation. Right signifie que le bord droit du texte suivant le caractère de tabulation est positionné au taquet de tabulation, et center signifie que le texte est centré au taquet de tabulation. Numeric signifie que le point décimal dans le texte est positionné au taquet de tabulation ; s'il n'y a pas de point décimal, alors le chiffre le moins significatif du nombre est positionné juste à gauche du taquet de tabulation ; s'il n'y a pas de nombre dans le texte, alors le texte est aligné à droite au taquet de tabulation. Par exemple, “-tabs {2c left 4c 6c center}” crée trois taquets de tabulation à intervalles de deux centimètres ; les deux premiers utilisent l'alignement à gauche et le troisième utilise l'alignement au centre.

Si la liste des taquets de tabulation n'a pas assez d'éléments pour couvrir toutes les tabulations d'une ligne de texte, Tk extrapole de nouveaux taquets de tabulation en utilisant l'espacement et l'alignement du dernier taquet de tabulation de la liste. Les distances de tabulation doivent être strictement positives et doivent toujours augmenter d'un taquet de tabulation à l'autre (sinon, une erreur est générée). La valeur de l'option -tabs peut être remplacée par des options -tabs dans les balises.

Si aucune option -tabs n'est spécifiée, ou si elle est spécifiée comme une liste vide, alors Tk utilise des tabulations par défaut espacées tous les huit caractères (taille moyenne). Pour obtenir un espacement standard différent, par exemple tous les 4 caractères, il suffit de configurer le widget avec “-tabs "[expr {4 * [font measure $font 0]}] left" -tabstyle wordprocessor”.

DESCRIPTION

La commande text crée une nouvelle fenêtre (spécifiée par l'argument pathName) et en fait un widget de texte. Des options supplémentaires, décrites ci-dessus, peuvent être spécifiées sur la ligne de commande ou dans la base de données d'options pour configurer certains aspects du texte, tels que sa couleur d'arrière-plan par défaut et son relief. La commande text renvoie le nom du chemin de la nouvelle fenêtre.

Un widget de texte affiche une ou plusieurs lignes de texte et permet de modifier ce texte. Les widgets de texte prennent en charge quatre types d'annotations différentes sur le texte, appelées balises (tags), marques (marks), fenêtres intégrées (embedded windows) ou images intégrées (embedded images). Les balises permettent d'afficher différentes portions de texte avec différentes polices et couleurs. De plus, des commandes Tcl peuvent être associées à des balises afin que des scripts soient exécutés lors d'actions particulières telles que des frappes au clavier et des clics de souris dans des plages de texte spécifiques. Voir TAGS ci-dessous pour plus de détails.

La deuxième forme d'annotation consiste en des marqueurs flottants dans le texte appelés « marques ». Les marques sont utilisées pour garder une trace de diverses positions intéressantes dans le texte au fur et à mesure de son édition. Voir MARKS ci-dessous pour plus de détails.

La troisième forme d'annotation permet d'intégrer des fenêtres arbitraires dans un widget de texte. Voir EMBEDDED WINDOWS ci-dessous pour plus de détails.

La quatrième forme d'annotation permet d'intégrer des images Tk dans un widget de texte. Voir EMBEDDED IMAGES ci-dessous pour plus de détails.

Le widget de texte dispose également d'un mécanisme intégré d'annulation/rétablissement. Voir THE UNDO MECHANISM ci-dessous pour plus de détails.

Le widget de texte permet la création de widgets pairs. Ce sont d'autres widgets de texte qui partagent les mêmes données sous-jacentes (texte, marques, balises, images, etc.). Voir PEER WIDGETS ci-dessous pour plus de détails.

INDICES

Beaucoup des commandes de widget pour les textes prennent un ou plusieurs indices comme arguments. Un indice est une chaîne de caractères utilisée pour indiquer une position particulière dans un texte, par exemple un endroit où insérer des caractères ou une extrémité d'une plage de caractères à supprimer. Les indices ont la syntaxe

base modificateur modificateur modificateur ...
Où base donne un point de départ et les modificateurs ajustent l'indice à partir du point de départ (par exemple, avancer ou reculer d'un caractère). Chaque indice doit contenir une base, mais les modificateurs sont facultatifs. La plupart des modificateurs (tels que décrits ci-dessous) permettent un sous-modificateur facultatif. Les sous-modificateurs valides sont any et display. Si le sous-modificateur est abrégé, il doit être suivi d'un espace, mais sinon, il n'y a pas besoin d'espace entre le sous-modificateur et le modificateur suivant. Généralement, le sous-modificateur display ajuste la signification du modificateur suivant pour qu'il se réfère à des unités visuelles ou non élidées plutôt qu'à des unités logiques, mais cela est expliqué pour chaque cas pertinent ci-dessous. Enfin, lorsque count est utilisé dans le cadre d'un modificateur, il peut être positif ou négatif, donc « base - -3 lines » est tout à fait valide (et équivalent à « base +3lines »).

La base d'un indice doit avoir l'une des formes suivantes :

ligne.caractère
Indique le caractère'ème caractère de la ligne ligne. Les lignes sont numérotées à partir de 1 pour la cohérence avec d'autres programmes UNIX qui utilisent ce schéma de numérotation. Au sein d'une ligne, les caractères sont numérotés à partir de 0. Si caractère est end, alors il fait référence au caractère de nouvelle ligne qui termine la ligne.
@x,y
Indique le caractère qui couvre le pixel dont les coordonnées x et y dans la fenêtre du texte sont x et y.
end
Indique la fin du texte (le caractère juste après le dernier saut de ligne).
mark
Indique le caractère juste après la marque dont le nom est mark (voir MARKS pour les détails).
tag.first
Indique le premier caractère du texte qui a été marqué avec tag. Cette forme génère une erreur si aucun caractère n'est actuellement marqué avec tag.
tag.last
Indique le caractère juste après le dernier caractère du texte qui a été marqué avec tag. Cette forme génère une erreur si aucun caractère n'est actuellement marqué avec tag.
pathName
Indique la position de la fenêtre intégrée dont le nom est pathName. Cette forme génère une erreur s'il n'y a pas de fenêtre intégrée portant ce nom.
imageName
Indique la position de l'image intégrée dont le nom est imageName. Cette forme génère une erreur s'il n'y a pas d'image intégrée portant ce nom.

Si la base peut correspondre à plusieurs des formes ci-dessus, par exemple si un mark et un imageName ont la même valeur, alors la forme plus tôt dans la liste ci-dessus a la priorité. Si des modificateurs suivent l'indice de base, chacun d'eux doit avoir l'une des formes listées ci-dessous. Les mots-clés tels que chars et wordend peuvent être abrégés tant que l'abréviation est sans ambiguïté.

+ count ?submodifier? chars
Ajuste l'indice vers l'avant de count caractères, en passant aux lignes suivantes dans le texte si nécessaire. S'il y a moins de count caractères dans le texte après l'indice actuel, alors l'indice est défini sur le dernier indice du texte. Les espaces de chaque côté de count sont facultatifs. Si le sous-modificateur display est donné, les caractères élidés sont sautés sans être comptés. Si any est donné, alors tous les caractères sont comptés. Pour des raisons historiques, si aucun modificateur n'est donné, le décompte s'effectue en unités de positions d'indice (voir INDICES pour les détails). Ce comportement peut être modifié dans une future version majeure, donc si vous avez besoin d'un décompte d'indices, il est recommandé d'utiliser indices autant que possible.
- count ?submodifier? chars
Ajuste l'indice vers l'arrière de count caractères, en passant aux lignes précédentes dans le texte si nécessaire. S'il y a moins de count caractères dans le texte avant l'indice actuel, alors l'indice est défini sur le premier indice du texte (1.0). Les espaces de chaque côté de count sont facultatifs. Si le sous-modificateur display est donné, les caractères élidés sont sautés sans être comptés. Si any est donné, alors tous les caractères sont comptés. Pour des raisons historiques, si aucun modificateur n'est donné, le décompte s'effectue en unités de positions d'indice (voir INDICES pour les détails). Ce comportement peut être modifié dans une future version majeure, donc si vous avez besoin d'un décompte d'indices, il est recommandé d'utiliser indices autant que possible.
+ count ?submodifier? indices
Ajuste l'indice vers l'avant de count positions d'indice, en passant aux lignes suivantes dans le texte si nécessaire. S'il y a moins de count positions d'indice dans le texte après l'indice actuel, alors l'indice est défini sur la dernière position d'indice du texte. Les espaces de chaque côté de count sont facultatifs. Notez qu'une position d'indice est soit un caractère unique, soit une image intégrée unique, soit une fenêtre intégrée unique. Si le sous-modificateur display est donné, les indices élidés sont sautés sans être comptés. Si any est donné, alors tous les indices sont comptés ; c'est également le comportement par défaut si aucun modificateur n'est donné.
- count ?submodifier? indices
Ajuste l'indice vers l'arrière de count positions d'indice, en passant aux lignes précédentes dans le texte si nécessaire. S'il y a moins de count positions d'indice dans le texte avant l'indice actuel, alors l'indice est défini sur la première position d'indice (1.0) du texte. Les espaces de chaque côté de count sont facultatifs. Si le sous-modificateur display est donné, les indices élidés sont sautés sans être comptés. Si any est donné, alors tous les indices sont comptés ; c'est également le comportement par défaut si aucun modificateur n'est donné.
+ count ?submodifier? lines
Ajuste l'indice vers l'avant de count lignes, en conservant la même position de caractère dans la ligne. S'il y a moins de count lignes après la ligne contenant l'indice actuel, alors l'indice est défini pour faire référence à la même position de caractère sur la dernière ligne du texte. Ensuite, si la ligne n'est pas assez longue pour contenir un caractère à la position indiquée, la position du caractère est ajustée pour faire référence au dernier caractère de la ligne (le saut de ligne). Les espaces de chaque côté de count sont facultatifs. Si le sous-modificateur display est donné, alors chaque ligne d'affichage visuelle est comptée séparément. Sinon, si any (ou aucun modificateur) est donné, alors chaque ligne logique (peu importe combien de fois elle est renvoyée à la ligne visuellement) compte une seule fois. Si les lignes concernées ne sont pas renvoyées à la ligne, alors ces deux méthodes de comptage sont équivalentes.
- compte ?sous-modificateur? lignes
Déplace l'index vers l'arrière de compte lignes logiques, en conservant la même position de caractère dans la ligne. S'il y a moins de compte lignes avant la ligne contenant l'index actuel, l'index est défini pour faire référence à la même position de caractère sur la première ligne du texte. Ensuite, si la ligne n'est pas assez longue pour contenir un caractère à la position de caractère indiquée, la position de caractère est ajustée pour faire référence au dernier caractère de la ligne (le saut de ligne). Les espaces de part et d'autre de compte sont optionnels. Si le sous-modificateur affichage est donné, alors chaque ligne d'affichage visuelle est comptée séparément. Sinon, si quelconque (ou aucun modificateur) est donné, alors chaque ligne logique (peu importe combien de fois elle est retournée visuellement) ne compte qu'une seule fois. Si les lignes pertinentes ne sont pas retournées, alors ces deux méthodes de comptage sont équivalentes.
?sous-modificateur? debutligne
Ajuste l'index pour faire référence au premier index de la ligne. Si le sous-modificateur affichage est donné, c'est le premier index de la ligne d'affichage, sinon de la ligne logique.
?sous-modificateur? finligne
Ajuste l'index pour faire référence au dernier index de la ligne (le saut de ligne). Si le sous-modificateur affichage est donné, c'est le dernier index de la ligne d'affichage, sinon de la ligne logique.
?sous-modificateur? debutmot
Ajuste l'index pour faire référence au premier caractère du mot contenant l'index actuel. Un mot est constitué d'un nombre quelconque de caractères adjacents qui sont des lettres, des chiffres ou des underscores, ou d'un seul caractère qui n'est pas l'un de ceux-ci. Si le sous-modificateur affichage est donné, cela n'examine que les caractères non élidés, sinon tous les caractères (élidés ou non) sont examinés.
?sous-modificateur? finmot
Ajuste l'index pour faire référence au caractère juste après le dernier caractère du mot contenant l'index actuel. Si l'index actuel fait référence au dernier caractère du texte, il n'est pas modifié. Si le sous-modificateur affichage est donné, cela n'examine que les caractères non élidés, sinon tous les caractères (élidés ou non) sont examinés.

Si plusieurs modificateurs sont présents, ils sont appliqués dans l'ordre de gauche à droite. Par exemple, l'index « fin - 1 car » fait référence à l'avant-dernier caractère du texte et « insertion debutmot - 1 c » fait référence au caractère juste avant le premier du mot contenant le curseur d'insertion. Les modificateurs sont appliqués un par un dans cet ordre de gauche à droite, et après chaque étape, l'index résultant est contraint d'être un index valide dans le widget texte. Ainsi, par exemple, l'index « 1.0 -1c +1c » fait référence à l'index « 2.0 ».

Lorsque les modificateurs entraînent des changements d'index par lignes d'affichage, caractères d'affichage ou indices d'affichage, et que la base fait référence à un index à l'intérieur d'une balise élidée, cet index de base est considéré comme équivalent au premier index non élidé suivant.

BALISES

La première forme d'annotation dans les widgets texte est une balise. Une balise est une chaîne textuelle associée à certains caractères d'un texte. Les balises peuvent contenir des caractères arbitraires, mais il est probablement préférable d'éviter d'utiliser les caractères « » (espace), +, ou - : ces caractères ont une signification spéciale dans les indices, donc les balises qui les contiennent ne peuvent pas être utilisées comme indices. Il peut y avoir un nombre quelconque de balises associées à des caractères dans un texte. Chaque balise peut faire référence à un seul caractère, une plage de caractères, ou plusieurs plages de caractères. Un caractère individuel peut avoir un nombre quelconque de balises qui lui sont associées.

Un ordre de priorité est défini entre les balises, et cet ordre est utilisé dans l'implémentation de certaines des fonctions liées aux balises décrites ci-dessous. Lorsqu'une balise est définie (en l'associant à des caractères ou en définissant ses options d'affichage ou en lui liant des commandes), elle reçoit une priorité supérieure à toute balise existante. L'ordre de priorité des balises peut être redéfini en utilisant les commandes de widget « nomFichier tag raise » et « nomFichier tag lower ».

Les balises servent trois objectifs dans les widgets texte. Premièrement, elles contrôlent la façon dont les informations sont affichées à l'écran. Par défaut, les caractères sont affichés comme déterminé par les options -arrière-plan, -police, et -avant-plan du widget texte. Cependant, des options d'affichage peuvent être associées à des balises individuelles en utilisant la commande de widget « nomFichier tag configure ». Si un caractère a été balisé, alors les options d'affichage associées à la balise remplacent le style d'affichage par défaut. Les options suivantes sont actuellement prises en charge pour les balises :

-arrière-plan couleur
Couleur spécifie la couleur de fond à utiliser pour les caractères associés à la balise. Elle peut avoir l'une des formes acceptées par Tk_GetColor.
-motifbg bitmap
Bitmap spécifie une bitmap qui est utilisée comme motif de tramage pour l'arrière-plan. Elle peut avoir l'une des formes acceptées par Tk_GetBitmap. Si bitmap n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors un remplissage solide sera utilisé pour l'arrière-plan.
-bordure pixels
Pixels spécifie la largeur d'une bordure à dessiner autour de la balise en utilisant l'une des formes acceptées par Tk_GetPixels. Cette option devrait être utilisée conjointement avec l'option -relief pour fournir la bordure souhaitée.
-elide booléen
Élider spécifie si les données doivent être élidées. Les données élidées (caractères, images, fenêtres intégrées, etc.) ne sont pas affichées et ne prennent pas d'espace à l'écran, mais se comportent par la suite comme des données normales.
-motiffg bitmap
Bitmap spécifie une bitmap qui est utilisée comme motif de tramage lors du dessin de texte et d'autres informations de premier plan telles que les soulignements. Elle peut avoir l'une des formes acceptées par Tk_GetBitmap. Si bitmap n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors un remplissage solide sera utilisé.
-police nomPolice
NomPolice est le nom d'une police à utiliser pour dessiner des caractères. Elle peut avoir l'une des formes acceptées par Tk_GetFont.
-avant-plan couleur
Couleur spécifie la couleur à utiliser lors du dessin de texte et d'autres informations de premier plan telles que les soulignements. Elle peut avoir l'une des formes acceptées par Tk_GetColor.
-alignement alignement
Si le premier caractère non élidé d'une ligne d'affichage a une balise pour laquelle cette option a été spécifiée, alors alignement détermine comment aligner la ligne. Elle doit être l'une de gauche, droite, ou centre. Si une ligne est retournée, alors l'alignement de chaque ligne à l'écran est déterminé par le premier caractère non élidé de cette ligne d'affichage.
-margel1 pixels
Si le premier caractère non élidé d'une ligne de texte a une balise pour laquelle cette option a été spécifiée, alors pixels spécifie de combien la ligne doit être indentée par rapport au bord gauche de la fenêtre. Pixels peut avoir l'une des formes standard pour les distances d'écran. Si une ligne de texte est retournée, cette option ne s'applique qu'à la première ligne affichée ; l'option -margel2 contrôle l'indentation des lignes suivantes.
-margel2 pixels
Si le premier caractère non élidé d'une ligne d'affichage a une balise pour laquelle cette option a été spécifiée, et si la ligne d'affichage n'est pas la première de sa ligne de texte (c'est-à-dire que la ligne de texte a été retournée), alors pixels spécifie de combien la ligne doit être indentée par rapport au bord gauche de la fenêtre. Pixels peut avoir l'une des formes standard pour les distances d'écran. Cette option n'est utilisée que lorsque le retour à la ligne est activé, et elle ne s'applique qu'aux deuxièmes lignes d'affichage et suivantes pour une ligne de texte.
-couleurmargel couleur
Couleur spécifie la couleur de fond à utiliser dans les régions qui ne contiennent pas de caractères parce qu'elles sont indentées par -margel1 ou -margel2. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur utilisée est celle spécifiée par l'option de balise -arrière-plan (ou, si celle-ci est également non spécifiée, par l'option -arrière-plan du widget).
-decalage pixels
Pixels spécifie une quantité par laquelle la ligne de base du texte doit être décalée verticalement par rapport à la ligne de base de la ligne globale, en pixels. Par exemple, un décalage positif peut être utilisé pour les exposants et un décalage négatif pour les indices. Pixels peut avoir l'une des formes standard pour les distances d'écran.
-barremilieu booléen
Spécifie si une règle horizontale doit être dessinée au milieu des caractères. Booléen peut avoir l'une des formes acceptées par Tcl_GetBoolean.
-couleurbarremilieu couleur
Couleur spécifie la couleur à utiliser lors de l'affichage de la barre au milieu. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur spécifiée par l'option de balise -avant-plan est utilisée.
-relief relief
Relief spécifie le style de relief à utiliser pour dessiner la bordure, dans l'une des formes acceptées par Tk_GetRelief. Cette option est utilisée conjointement avec l'option -bordure pour activer l'apparence de bordure souhaitée.
-marger pixels
Si le premier caractère non élidé d'une ligne d'affichage a une balise pour laquelle cette option a été spécifiée, alors pixels spécifie la largeur de la marge à laisser entre la fin de la ligne et le bord droit de la fenêtre. Pixels peut avoir l'une des formes standard pour les distances d'écran. Cette option n'est utilisée que lorsque le retour à la ligne est activé. Si une ligne de texte est retournée, la marge droite de chaque ligne de la
display est déterminé par le premier caractère non élidé de cette ligne d'affichage.
-rmargincolor couleur
Couleur spécifie la couleur de fond à utiliser dans les régions qui ne contiennent pas de caractères parce qu'elles sont indentées par -rmargin. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur utilisée est celle spécifiée par l'option de tag -background (ou, si celle-ci est également non spécifiée, par l'option de widget -background).
-selectbackground couleur
Couleur spécifie la couleur de fond à utiliser lors de l'affichage des éléments sélectionnés. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur spécifiée par l'option de tag -background est utilisée.
-selectforeground couleur
Couleur spécifie la couleur de premier plan à utiliser lors de l'affichage des éléments sélectionnés. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur spécifiée par l'option de tag -foreground est utilisée.
-spacing1 pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser au-dessus de chaque ligne de texte, en utilisant l'une des formes standard pour les distances d'écran. Si une ligne est coupée, cette option ne s'applique qu'à la première ligne affichée.
-spacing2 pixels
Pour les lignes coupées, cette option spécifie la quantité d'espace supplémentaire à laisser entre les lignes d'affichage pour une seule ligne de texte. Pixels peut avoir l'une des formes standard pour les distances d'écran.
-spacing3 pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser en dessous de chaque ligne de texte, en utilisant l'une des formes standard pour les distances d'écran. Si une ligne est coupée, cette option ne s'applique qu'à la dernière ligne affichée.
-tabs listeTabulations
ListeTabulations spécifie un ensemble de tabulations dans la même forme que pour l'option -tabs du widget texte. Cette option ne s'applique à une ligne d'affichage que si elle s'applique au premier caractère non élidé de cette ligne d'affichage. Si cette option est spécifiée comme une chaîne vide, elle annule l'option, la laissant non spécifiée pour le tag (par défaut). Si l'option est spécifiée comme une chaîne non vide qui est une liste vide, telle que -tags { }, alors elle demande des tabulations par défaut de 8 caractères comme décrit pour l'option de widget -tags.
-tabstyle style
Style spécifie soit le style de tabulation tabular soit wordprocessor à utiliser pour le widget texte. Cette option ne s'applique à une ligne d'affichage que si elle s'applique au premier caractère non élidé de cette ligne d'affichage. Si cette option est spécifiée comme une chaîne vide, elle annule l'option, la laissant non spécifiée pour le tag (par défaut).
-underline booléen
Booléen spécifie si des caractères doivent être soulignés ou non. Elle peut avoir l'une des formes acceptées par Tcl_GetBoolean.
-underlinefg couleur
Couleur spécifie la couleur à utiliser lors de l'affichage du soulignement. Elle peut avoir l'une des formes acceptées par Tk_GetColor. Si couleur n'a pas été spécifiée, ou si elle est spécifiée comme une chaîne vide, alors la couleur spécifiée par l'option de tag -foreground est utilisée.
-wrap mode
Mode spécifie comment gérer les lignes plus larges que la fenêtre du texte. Cette option ne s'applique à une ligne d'affichage que si elle s'applique au premier caractère non élidé de cette ligne d'affichage. Elle a les mêmes valeurs valides que l'option -wrap du widget texte : none, char, ou word. Si cette option de tag est spécifiée, elle remplace l'option -wrap du widget texte.

Si un caractère a plusieurs tags associés, et si leurs options d'affichage entrent en conflit, alors les options du tag de priorité la plus élevée sont utilisées. Si une option d'affichage particulière n'a pas été spécifiée pour un tag particulier, ou si elle est spécifiée comme une chaîne vide, alors cette option ne sera jamais utilisée ; l'option du tag de priorité supérieure sera utilisée à la place. Si aucun tag ne spécifie une option d'affichage particulière, alors le style par défaut du widget sera utilisé.

Le deuxième objectif des tags est les liaisons d'événements. Vous pouvez associer des liaisons à un tag de la même manière que vous pouvez associer des liaisons à une classe de widget : chaque fois que des événements X particuliers se produisent sur des caractères portant le tag donné, une commande Tcl donnée sera exécutée. Les liaisons de tag peuvent être utilisées pour donner des comportements à des plages de caractères ; entre autres choses, cela permet d'implémenter des fonctionnalités de type hypertexte. Pour plus de détails, voir la description de la commande de widget “nomChemin tag bind” ci-dessous. Les liaisons de tag sont partagées entre tous les widgets pairs (y compris les liaisons pour le tag spécial sel).

Le troisième usage des tags est la gestion de la sélection. Voir LA SÉLECTION ci-dessous. À l'exception du tag spécial sel, tous les tags sont partagés entre les widgets texte pairs, et peuvent être manipulés sur une base égale depuis n'importe lequel de ces widgets. Le tag sel existe séparément et indépendamment dans chaque widget texte pair (mais toutes les liaisons de tag vers sel sont partagées).

MARQUEURS

La deuxième forme d'annotation dans les widgets texte est un marqueur. Les marqueurs sont utilisés pour mémoriser des endroits particuliers dans un texte. Ils sont un peu comme les tags, en ce sens qu'ils ont des noms et qu'ils font référence à des endroits dans le fichier, mais un marqueur n'est pas associé à des caractères particuliers. Au lieu de cela, un marqueur est associé à l'espace entre deux caractères. Une seule position peut être associée à un marqueur à la fois. Si les caractères entourant un marqueur sont supprimés, le marqueur restera ; il aura simplement de nouveaux caractères voisins. En revanche, si les caractères contenant un tag sont supprimés, le tag n'aura plus d'association avec les caractères du fichier. Les marqueurs peuvent être manipulés avec la commande de widget “nomChemin mark”, et leurs positions actuelles peuvent être déterminées en utilisant le nom du marqueur comme indice dans les commandes de widget.

Chaque marqueur a également une “gravité”, qui est soit left (gauche) soit right (droite). La gravité d'un marqueur spécifie ce qui arrive au marqueur lorsque du texte est inséré à l'emplacement du marqueur. Si un marqueur a une gravité gauche, alors le marqueur est traité comme s'il était attaché au caractère à sa gauche, de sorte que le marqueur restera à gauche de tout texte inséré à la position du marqueur. Si le marqueur a une gravité droite, le nouveau texte inséré à la position du marqueur apparaîtra à gauche du marqueur (de sorte que le marqueur reste le plus à droite). La gravité d'un marqueur est par défaut right.

L'espace de noms pour les marqueurs est différent de celui pour les tags : le même nom peut être utilisé pour un marqueur et un tag, mais ils feront référence à des choses différentes.

Deux marqueurs ont une signification particulière. Premièrement, le marqueur insert est associé au curseur d'insertion, comme décrit sous LE CURSEUR D'INSERTION ci-dessous. Deuxièmement, le marqueur current est associé au caractère le plus proche de la souris et est ajusté automatiquement pour suivre la position de la souris et les modifications du texte dans le widget (une exception : current n'est pas mis à jour en réponse aux mouvements de la souris si un bouton de souris est enfoncé ; la mise à jour sera différée jusqu'à ce que tous les boutons de souris aient été relâchés). Aucun de ces marqueurs spéciaux ne peut être supprimé. À l'exception de ces deux marqueurs spéciaux, tous les marqueurs sont partagés entre les widgets texte pairs, et peuvent être manipulés sur une base égale depuis n'importe quel pair.

FENÊTRES INTÉGRÉES

La troisième forme d'annotation dans les widgets texte est une fenêtre intégrée. Chaque annotation de fenêtre intégrée provoque l'affichage d'une fenêtre à un point particulier du texte. Il peut y avoir un nombre quelconque de fenêtres intégrées dans un widget texte, et n'importe quel widget peut être utilisé comme fenêtre intégrée (sous réserve des règles habituelles de gestion de la géométrie, qui exigent que la fenêtre texte soit le parent de la fenêtre intégrée ou un descendant de son parent).

La position de la fenêtre intégrée à l'écran sera mise à jour à mesure que le texte est modifié ou défilé, et elle sera mappée et démappée à mesure qu'elle entre et sort de la zone visible du widget texte. Chaque fenêtre intégrée occupe une unité d'espace d'index dans le widget texte, et elle peut être référencée soit par le nom de sa fenêtre intégrée, soit par sa position dans l'espace d'index du widget. Si la plage de texte contenant la fenêtre intégrée est supprimée, la fenêtre est détruite. De même, si le widget texte dans son ensemble est supprimé, la fenêtre est détruite.

Élider une fenêtre intégrée immédiatement après l'avoir planifiée pour création via nomChemin window create index-create l'empêchera d'être effectivement créée. Dé-élider une fenêtre intégrée élidée prévue pour création via nomChemin window create index -create déclenchera automatiquement le script de création associé. Après la destruction d'une fenêtre intégrée élidée, cette dernière ne sera pas recréée automatiquement.

Lorsqu'une fenêtre intégrée est ajoutée à un widget texte avec la commande de widget nomChemin window create, plusieurs options de configuration peuvent lui être associées. Ces options peuvent être modifiées ultérieurement avec la commande de widget nomChemin window configure. Les options suivantes sont actuellement prises en charge :

-align où
Si la fenêtre n'a pas la même hauteur que la ligne dans laquelle elle est affichée, cette option détermine où la fenêtre est affichée sur la ligne. Où doit avoir l'une des valeurs top (aligner le haut de la fenêtre avec le haut de la ligne), center (centrer la fenêtre dans la plage de la ligne), bottom (aligner le bas de la fenêtre avec le bas de la zone de la ligne), ou baseline (aligner le bas de la fenêtre avec la ligne de base de la ligne).
-create script
Spécifie un script Tcl qui peut être évalué pour créer la fenêtre pour la
annotation. Si aucune option -window n'a été spécifiée pour l'annotation, ce script sera évalué lorsque l'annotation est sur le point d'être affichée à l'écran. Script doit créer une fenêtre pour l'annotation et retourner le nom de cette fenêtre comme résultat. Deux substitutions seront effectuées dans script avant l'évaluation. %W sera substitué par le nom du widget texte parent, et %% sera substitué par un seul %. Si la fenêtre de l'annotation doit jamais être supprimée, script sera évalué à nouveau la prochaine fois que l'annotation sera affichée.
-padx pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser de chaque côté de la fenêtre intégrée. Il peut avoir l'une des formes habituellement définies pour une distance d'écran.
-pady pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser en haut et en bas de la fenêtre intégrée. Il peut avoir l'une des formes habituellement définies pour une distance d'écran.
-stretch booléen
Si la hauteur demandée de la fenêtre intégrée est inférieure à la hauteur de la ligne dans laquelle elle est affichée, cette option peut être utilisée pour spécifier si la fenêtre doit être étirée verticalement pour remplir sa ligne. Si l'option -pady a également été spécifiée, le rembourrage demandé sera conservé même si la fenêtre est étirée.
-window nomChemin
Spécifie le nom d'une fenêtre à afficher dans l'annotation. Notez que si un nomChemin a été défini, configurer plus tard une fenêtre sur une chaîne vide ne supprimera pas le widget correspondant à l'ancien nomChemin. Plutôt, cela supprimera l'association entre l'ancien nomChemin et le widget texte. Si plusieurs widgets pairs sont utilisés, il est généralement plus simple d'utiliser l'option -create si des fenêtres intégrées sont souhaitées dans chaque pair.

IMAGES INTEGREES

La forme finale d'annotation dans les widgets texte est une image intégrée. Chaque annotation d'image intégrée provoque l'affichage d'une image à un point particulier du texte. Il peut y avoir un nombre quelconque d'images intégrées dans un widget texte, et une image particulière peut être intégrée à plusieurs endroits dans le même widget texte.

La position de l'image intégrée à l'écran sera mise à jour au fur et à mesure que le texte est modifié ou défilé. Chaque image intégrée occupe un espace d'index d'une unité dans le widget texte, et elle peut être référencée soit par sa position dans l'espace d'index du widget, soit par le nom qui lui est assigné lorsque l'image est insérée dans le widget texte avec nomChemin image create. Si la plage de texte contenant l'image intégrée est supprimée, cette copie de l'image est retirée de l'écran.

Éliminer une image intégrée immédiatement après sa planification pour la création via nomChemin image create index -create l'empêchera d'être effectivement créée. Annuler l'élimination d'une image intégrée planifiée pour la création via nomChemin image create index -create déclenchera automatiquement le script de création associé. Après la destruction d'une image intégrée éliminée, celle-ci ne sera pas recréée automatiquement.

Lorsqu'une image intégrée est ajoutée à un widget texte avec la commande de widget nomChemin image create, un nom unique pour cette instance de l'image est retourné. Ce nom peut alors être utilisé pour référencer cette instance d'image. Le nom est considéré comme étant la valeur de l'option -name (décrite ci-dessous). Si l'option -name n'est pas fournie, le nom -image est utilisé à la place. Si nomImage est déjà utilisé dans le widget texte, alors #nn est ajouté à la fin de nomImage, où nn est un entier arbitraire. Ceci garantit que nomImage est unique. Une fois ce nom assigné à cette instance de l'image, il ne change pas, même si les valeurs -image ou -name peuvent être modifiées avec nomChemin image configure.

Lorsqu'une image intégrée est ajoutée à un widget texte avec la commande de widget nomChemin image create, plusieurs options de configuration peuvent lui être associées. Ces options peuvent être modifiées ultérieurement avec la commande de widget nomChemin image configure. Les options suivantes sont actuellement prises en charge :

-align où
Si l'image n'a pas la même hauteur que la ligne dans laquelle elle est affichée, cette option détermine où l'image est affichée dans la ligne. Où doit avoir l'une des valeurs top (aligner le haut de l'image avec le haut de la ligne), center (centrer l'image dans la plage de la ligne), bottom (aligner le bas de l'image avec le bas de la zone de la ligne), ou baseline (aligner le bas de l'image avec la ligne de base de la ligne).
-image image
Spécifie le nom de l'image Tk à afficher dans l'annotation. Si image n'est pas une image Tk valide, une erreur est retournée.
-name NomImage
Spécifie le nom par lequel cette instance d'image peut être référencée dans le widget texte. Si NomImage n'est pas fourni, le nom de l'image Tk est utilisé à la place. Si le nomImage est déjà utilisé, #nn est ajouté à la fin du nom comme décrit ci-dessus.
-padx pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser de chaque côté de l'image intégrée. Il peut avoir l'une des formes habituellement définies pour une distance d'écran.
-pady pixels
Pixels spécifie la quantité d'espace supplémentaire à laisser en haut et en bas de l'image intégrée. Il peut avoir l'une des formes habituellement définies pour une distance d'écran.

LA SELECTION

Le support de la sélection est implémenté via des balises. Si l'option -exportselection pour le widget texte est vraie, alors la balise sel sera associée à la sélection :

[1]
Chaque fois que des caractères sont marqués avec sel, le widget texte revendiquera la propriété de la sélection.
[2]
Les tentatives de récupération de la sélection seront traitées par le widget texte, retournant tous les caractères marqués avec la balise sel.
[3]
Si la sélection est revendiquée par une autre application ou par une autre fenêtre au sein de cette application, la balise sel sera retirée de tous les caractères du texte.
[4]
Chaque fois que la plage de la balise sel change, un événement virtuel <<Selection>> est généré. Il pourrait également être généré lorsque la sélection est affectée mais pas réellement modifiée. De plus, plusieurs changements de sélection pourraient se produire avant que les événements puissent être traités, entraînant plusieurs événements avec la même sélection visible.

La balise sel est automatiquement définie lorsqu'un widget texte est créé, et elle ne peut pas être supprimée avec la commande de widget “nomChemin tag delete”. De plus, les options -selectbackground, -selectborderwidth, et -selectforeground pour le widget texte sont liées aux options -background, -borderwidth, et -foreground pour la balise sel : les changements dans l'une seront automatiquement reflétés dans l'autre. De plus, l'option -inactiveselectbackground pour le widget texte est utilisée à la place de -selectbackground lorsque le widget texte n'a pas le focus. Cela permet un contrôle programmatique sur la visualisation de la balise sel pour les fenêtres de premier plan et d'arrière-plan, ou pour que sel ne soit pas affiché du tout (lorsque -inactiveselectbackground est vide) pour les fenêtres d'arrière-plan. Chaque widget texte pair a sa propre balise sel qui peut être configurée et définie séparément.

LE CURSEUR D'INSERTION

La marque nommée insert a une signification spéciale dans les widgets texte. Elle est définie automatiquement lorsqu'un widget texte est créé et ne peut pas être désactivée avec la commande de widget “nomChemin mark unset”. La marque insert représente la position du curseur d'insertion, et le curseur d'insertion sera automatiquement dessiné à cet endroit chaque fois que le widget texte aura le focus d'entrée.

LE FLAG MODIFIÉ

Le widget texte peut suivre les modifications apportées au contenu du widget au moyen du flag modifié. L'insertion ou la suppression de texte définira ce flag. Le flag peut être interrogé, défini et effacé programmablement. Chaque fois que le flag change d'état, un événement virtuel <<Modified>> est généré. Voir la commande de widget nomChemin edit modified pour plus de détails.

LE MÉCANISME D'ANNULATION

Le widget texte dispose d'un mécanisme d'annulation et de rétablissement illimité (lorsque l'option de widget -undo est vraie) qui enregistre chaque action d'insertion et de suppression sur une pile.

Des limites (appelées « séparateurs ») sont insérées entre les actions d'édition. Le but de ces séparateurs est de regrouper les insertions, les suppressions et les remplacements en une seule action d'édition composée. Lors de l'annulation d'une modification, tout ce qui se trouve entre deux séparateurs sera annulé. Les modifications annulées sont ensuite déplacées vers la pile de rétablissement, de sorte qu'une édition annulée puisse être rétablir. La pile de rétablissement est effacée chaque fois que de nouvelles actions d'édition sont enregistrées sur la pile d'annulation. Les piles d'annulation et de rétablissement peuvent être effacées pour maintenir leur profondeur sous contrôle.

Les séparateurs sont insérés automatiquement lorsque l'option de widget -autoseparators est vraie. Vous pouvez également insérer des séparateurs par programmation. Si un séparateur est déjà présent en haut de la pile d'annulation, aucun autre ne sera inséré. Cela signifie que deux séparateurs sur la pile d'annulation sont toujours séparés par au moins une action d'insertion ou de suppression.

L'événement virtuel <<UndoStack>> est généré chaque fois que la pile d'annulation ou la pile de rétablissement devient vide ou non vide.

Le mécanisme d'annulation est également lié au flag modifié. Cela signifie qu'annuler ou rétablir des modifications peut ramener un widget texte modifié à l'état non modifié ou vice versa. Le flag modifié sera automatiquement défini à l'état approprié. Ce couplage automatique ne

travail lorsque le drapeau modified a été défini par l'utilisateur, jusqu'à ce que le drapeau soit réinitialisé à nouveau.

Voir ci-dessous pour la commande de widget edit pathName qui contrôle le mécanisme d'annulation.

WIDGETS PAIRS

Le widget texte possède un espace de stockage distinct pour toutes ses données concernant le contenu textuel de chaque ligne, les marques, les étiquettes, les images et les fenêtres, ainsi que la pile d'annulation.

Bien que cet espace de stockage de données ne soit pas accessible directement (c'est-à-dire sans un widget texte comme intermédiaire), plusieurs widgets texte peuvent être créés, chacun présentant des vues différentes des mêmes données sous-jacentes. Ces widgets texte sont appelés widgets texte pairs.

À mesure que du texte est ajouté, supprimé, édité et colorisé dans l'un des widgets, et que les images, les marques et les étiquettes sont ajustées, toutes ces modifications seront reflétées dans tous les pairs.

Toutes les données et le balisage sont partagés, à l'exception de quelques détails mineurs. Premièrement, l'étiquette sel peut être définie et configurée (dans son style d'affichage) différemment pour chaque pair. Deuxièmement, chaque pair possède ses propres positions de marque insert et current (mais toutes les autres marques sont partagées). Troisièmement, les fenêtres intégrées, qui sont d'autres widgets arbitraires, ne peuvent pas être partagées entre les pairs. Cela signifie que l'option -window des fenêtres intégrées est définie indépendamment pour chaque pair (il est conseillé d'utiliser les capacités de script -create pour permettre à chaque pair de créer ses propres fenêtres intégrées selon ses besoins). Quatrièmement, toutes les options de configuration de chaque pair (par exemple, -font, etc.) peuvent être définies indépendamment, à l'exception de -undo, -maxundo, -autoseparators (c'est-à-dire que toutes les questions relatives à l'état d'annulation, de rétablissement et de modification sont partagées).

Enfin, un seul pair n'a pas besoin de contenir toutes les lignes de l'espace de stockage de données sous-jacent. Lors de la création d'un pair, une plage contiguë de lignes (par exemple, seulement les lignes 52 à 125) peut être spécifiée. Cela permet à un pair de ne contenir qu'une petite partie du texte global. La plage de lignes s'étendra et se contractera à mesure que du texte sera inséré ou supprimé. Le pair n'affichera jamais que des lignes de texte complètes (on ne peut pas partager seulement une partie d'une ligne). Si le contenu du pair se contracte à rien (c'est-à-dire que toutes les lignes complètes du widget pair ont été supprimées d'un autre widget), alors il est impossible d'insérer de nouvelles lignes. Le pair deviendra simplement une coquille vide sur laquelle l'arrière-plan peut être configuré, mais qui n'affichera jamais aucun contenu (sans reconfiguration manuelle des lignes de début et de fin). Notez qu'un pair qui ne contient pas toutes les données de l'espace de stockage sous-jacent a toujours des indices numérotés de “1.0” à “end”. Il est simplement que ces indices reflètent un sous-ensemble des données totales, et que les données en dehors de la plage contenue ne sont pas accessibles au pair. Cela signifie que la commande peerName index end peut renvoyer des valeurs très différentes dans différents pairs. De même, des commandes comme peerName tag ranges ne renverront pas de plages d'indices en dehors de ce qui est significatif pour le pair. Les options de configuration -startline et -endline peuvent être utilisées pour contrôler la quantité de données sous-jacentes contenues dans un widget texte donné.

Notez que les pairs sont réellement des pairs. La suppression du widget texte "original" n'entraînera pas la suppression d'autres pairs, ni leur affectation.

Voir ci-dessous pour la commande de widget peer pathName qui contrôle la création de widgets pairs.

MISE À JOUR ASYNCHRONE DES HAUTEURS DE LIGNE

Afin de maintenir une expérience utilisateur réactive, le widget texte calcule les métriques des lignes (hauteurs de ligne en pixels) de manière asynchrone. De ce fait, certaines commandes du widget texte peuvent renvoyer des résultats incorrects si les calculs asynchrones ne sont pas terminés au moment de l'appel. Cela s'applique à pathName count -ypixels et pathName yview.

Encore une fois, pour des raisons de performance, il ne serait pas approprié de laisser ces commandes attendre systématiquement la fin du calcul de mise à jour à chaque appel. Dans la plupart des cas d'utilisation de ces commandes, un résultat plus ou moins inexact n'a pas vraiment d'importance par rapport à la vitesse d'exécution.

Dans le cas où un résultat précis est nécessaire (et si le widget texte est géré par un gestionnaire de géométrie), on peut recourir à pathName sync et pathName pendingsync pour contrôler la synchronisation de la vue des widgets texte.

L'événement virtuel <<WidgetViewSync>> est déclenché lorsque les hauteurs de ligne du widget texte deviennent obsolètes (en raison d'une commande d'édition ou d'un changement de configuration), et à nouveau lorsque les données internes du widget texte sont de nouveau synchronisées avec la vue du widget. Le champ detail (%d substitution) est soit vrai (lorsque le widget est synchronisé) soit faux (lorsque ce n'est pas le cas).

pathName sync, pathName pendingsync et <<WidgetViewSync>> s'appliquent à chaque widget texte indépendamment de ses pairs.

Exemples d'utilisation :

## Exemple 1 :
# achever immédiatement les métriques de ligne à tout prix (interface graphique non réactive)
$w sync
$w yview moveto $fraction
## Exemple 2 :
# attendre de manière synchrone des métriques de ligne à jour (interface graphique réactive)
# avant d'exécuter la commande planifiée, mais ne pas bloquer le flux d'exécution
$w sync -command [list $w yview moveto $fraction]
## Exemple 3 :
# initialisation
set yud($w) 0
proc updateaction w {
set ::yud($w) 1
# toute autre action de mise à jour ici...
}
# exécution, attendre de manière synchrone des métriques de ligne à jour (interface graphique réactive)
$w sync -command [list updateaction $w]
vwait yud($w)
$w yview moveto $fraction
## Exemple 4 :
# initialisation
set todo($w) {}
proc updateaction w {
foreach cmd $::todo($w) {uplevel #0 $cmd}
set todo($w) {}
}
# exécution
lappend todo($w) [list $w yview moveto $fraction]
$w sync -command [list updateaction $w]
## Exemple 5 :
# initialisation
set todo($w) {}
bind $w <<WidgetViewSync>> {
if {%d} {
foreach cmd $todo(%W) {eval $cmd}
set todo(%W) {}
}
}
# exécution
if {![$w pendingsync]} {
$w yview moveto $fraction
} else {
lappend todo($w) [list $w yview moveto $fraction]
}

COMMANDE DU WIDGET

La commande text crée une nouvelle commande Tcl dont le nom est identique au chemin d'accès de la fenêtre de texte. Cette commande peut être utilisée pour invoquer diverses opérations sur le widget. Elle a la forme générale suivante :

pathName option ?arg arg ...?
PathName est le nom de la commande, qui est le même que le nom du chemin d'accès du widget texte. Option et les args déterminent le comportement exact de la commande. Les commandes suivantes sont possibles pour les widgets texte :
pathName bbox index
Renvoie une liste de quatre éléments décrivant la zone de l'écran du caractère donné par index. Les deux premiers éléments de la liste donnent les coordonnées x et y du coin supérieur gauche de la zone occupée par le caractère, et les deux derniers éléments donnent la largeur et la hauteur de la zone. Si le caractère n'est que partiellement visible à l'écran, la valeur renvoyée reflète uniquement la partie visible. Si le caractère n'est pas visible à l'écran, la valeur renvoyée est une liste vide.
pathName cget option
Renvoie la valeur actuelle de l'option de configuration donnée par option. Option peut avoir l'une des valeurs acceptées par la commande text.
pathName compare index1 op index2
Compare les indices donnés par index1 et index2 selon l'opérateur relationnel donné par op, et renvoie 1 si la relation est satisfaite et 0 si elle ne l'est pas. Op doit être l'un des opérateurs <, <=, ==, >=, >, ou !=. Si op est ==, 1 est renvoyé si les deux indices font référence au même caractère, si op est < alors 1 est renvoyé si index1 fait référence à un caractère antérieur dans le texte à index2, et ainsi de suite.
pathName configure ?option? ?value option value ...?
Interroge ou modifie les options de configuration du widget. Si aucune option n'est spécifiée, renvoie une liste décrivant toutes les options disponibles pour pathName (voir Tk_ConfigureInfo pour des informations sur le format de cette liste). Si option est spécifiée sans value, la commande renvoie une liste décrivant l'option nommée (cette liste sera identique à la sous-liste correspondante de la valeur renvoyée si aucune option n'est spécifiée). Si une ou plusieurs paires option-valeur sont spécifiées, la commande modifie les options du widget données pour leur attribuer les valeurs données ; dans ce cas, la commande renvoie une chaîne vide. Option peut avoir l'une des valeurs acceptées par la commande text.
pathName count ?options? index1 index2
Compte le nombre d'éléments pertinents entre les deux indices. Si index1 est postérieur à index2, le résultat sera un nombre négatif (et cela est valable pour chacune des options possibles). Les éléments effectivement comptés dépendent des options fournies. Le résultat est une liste d'entiers, un pour le résultat de chaque option de comptage donnée. Les options de comptage valides sont -chars, -displaychars, -displayindices, -displaylines, -indices, -lines, -xpixels et -ypixels. La valeur par défaut, si aucune option n'est spécifiée, est -indices. Il existe une option supplémentaire possible -update qui est un modificateur. Si elle est donnée (et si le widget texte est géré par un gestionnaire de géométrie), alors toutes les options suivantes garantissent que toute information potentiellement obsolète est recalculée. Cela n'a actuellement d'effet que pour le comptage -ypixels (qui, si -update n'est pas donné, utilisera la valeur mise en cache actuelle du widget texte pour chaque ligne). Cette option -update est obsolète par pathName sync, pathName pendingsync et <<WidgetViewSync>>. Les options de comptage sont interprétées comme suit :
-chars
compte tous les caractères, qu'ils soient élidés ou non. Ne compte pas les fenêtres ou les images intégrées.
-displaychars
compte tous les caractères non élidés.
-displayindices
compte tous les caractères, fenêtres et images non élidés.
-displaylines
compte
t toutes les lignes affichées (c'est-à-dire en comptant une pour chaque retour à la ligne) depuis la ligne du premier index jusqu'à, mais sans inclure, la ligne affichée du second index. Par conséquent, s'ils sont tous deux sur la même ligne d'affichage, zéro sera retourné. Par définition, les lignes affichées sont visibles et par conséquent, cela ne compte que des portions de lignes réellement visibles.
-indices
compte tous les caractères et fenêtres ou images incorporés (c'est-à-dire tout ce qui compte dans l'espace d'index du widget texte), qu'ils soient éludés ou non.
-lignes
compte toutes les lignes logiques (indépendamment du retour à la ligne) de la ligne du premier index jusqu'à, mais sans inclure, la ligne du second index. Par conséquent, s'ils sont tous deux sur la même ligne, zéro sera retourné. Les lignes logiques sont comptées qu'elles soient actuellement visibles (non éludées) ou non.
-xpixels
compte le nombre de pixels horizontaux du premier pixel du premier index au premier pixel du second index (sans l'inclure). Pour compter la largeur totale souhaitée du widget texte (en supposant que le retour à la ligne n'est pas activé), trouvez d'abord la ligne la plus longue, puis utilisez « .text count -xpixels "${line}.0" "${line}.0 lineend" ».
-ypixels
compte le nombre de pixels verticaux du premier pixel du premier index au premier pixel du second index (sans l'inclure). Si les deux index sont sur la même ligne d'affichage, zéro sera retourné. Pour compter le nombre total de pixels verticaux dans le widget texte, utilisez « .text count -ypixels 1.0 end », et pour vous assurer que c'est à jour, utilisez « .text count -update -ypixels 1.0 end ».

La commande retourne un entier positif ou négatif correspondant au nombre d'éléments comptés entre les deux index. Un tel entier est retourné pour chaque option de comptage donnée, donc une liste est retournée si plus d'une option a été fournie. Par exemple, « .text count -xpixels -ypixels 1.3 4.5 » est parfaitement valide et retournera une liste de deux éléments.

pathName debug ?booléen?
Si booléen est spécifié, alors il doit avoir l'une des valeurs vraies ou fausses acceptées par Tcl_GetBoolean. Si la valeur est une valeur vraie, alors les vérifications de cohérence interne seront activées dans le code B-tree associé aux widgets texte. Si booléen a une valeur fausse, alors les vérifications de débogage seront désactivées. Dans les deux cas, la commande retourne une chaîne vide. Si booléen n'est pas spécifié, alors la commande retourne on ou off pour indiquer si le débogage est activé ou non. Il existe un seul commutateur de débogage partagé par tous les widgets texte : activer ou désactiver le débogage dans un widget l'active ou le désactive pour tous les widgets. Pour les widgets contenant une grande quantité de texte, les vérifications de cohérence peuvent provoquer un ralentissement notable.

Lorsque le débogage est activé, les routines de dessin du widget texte définissent les variables globales tk_textRedraw et tk_textRelayout aux listes d'index qui sont redessinés. Les valeurs de ces variables sont testées par la suite de tests de Tk.

pathName delete index1 ?index2 ...?
Supprime une plage de caractères du texte. Si index1 et index2 sont tous deux spécifiés, alors supprime tous les caractères commençant par celui donné par index1 et s'arrêtant juste avant index2 (c'est-à-dire que le caractère à index2 n'est pas supprimé). Si index2 ne spécifie pas une position postérieure à index1, alors aucun caractère n'est supprimé. Si index2 n'est pas spécifié, alors le caractère unique à index1 est supprimé. Les tentatives de suppression de caractères d'une manière qui laisserait le texte sans retour à la ligne comme dernier caractère seront ajustées par le widget texte pour éviter cela. En particulier, la suppression de lignes complètes de texte jusqu'à la fin du texte supprimera également le caractère de retour à la ligne juste avant le bloc supprimé, de sorte qu'il sera remplacé par le nouveau retour à la ligne final du widget texte. La commande retourne une chaîne vide. Si plus d'index sont donnés, plusieurs plages de texte seront supprimées. Tous les index sont d'abord vérifiés pour leur validité avant que toute suppression ne soit effectuée. Ils sont triés et le texte est supprimé de la dernière plage à la première plage, de sorte que le texte supprimé ne provoque pas d'effets secondaires indésirables de décalage d'index. Si plusieurs plages avec le même index de début sont données, alors la plage la plus longue est utilisée. Si des plages qui se chevauchent sont données, alors elles seront fusionnées en segments qui ne provoquent pas la suppression de texte en dehors des plages données en raison du texte décalé lors de la suppression.
pathName dlineinfo index
Retourne une liste de cinq éléments décrivant la zone occupée par la ligne d'affichage contenant index. Les deux premiers éléments de la liste donnent les coordonnées x et y du coin supérieur gauche de la zone occupée par la ligne, les troisième et quatrième éléments donnent la largeur et la hauteur de la zone, et le cinquième élément donne la position de la ligne de base pour la ligne, mesurée vers le bas à partir du haut de la zone. Toutes ces informations sont mesurées en pixels. Si le mode de retour à la ligne actuel est none et que la ligne s'étend au-delà des limites de la fenêtre, la zone retournée reflète toute la zone de la ligne, y compris les portions qui sont hors de la fenêtre. Si la ligne est plus courte que la largeur totale de la fenêtre, alors la zone retournée reflète uniquement la portion de la ligne occupée par des caractères et des fenêtres incorporées. Si la ligne d'affichage contenant index n'est pas visible à l'écran, alors la valeur de retour est une liste vide.
pathName dump ?switches? index1 ?index2?
Retourne le contenu du widget texte de index1 jusqu'à, mais sans inclure, index2, y compris le texte et les informations sur les marques, les balises et les fenêtres incorporées. Si index2 n'est pas spécifié, alors il est par défaut un caractère après index1. Les informations sont retournées dans le format suivant :

clé1 valeur1 index1 clé2 valeur2 index2 ...

Les valeurs possibles de clé sont text, mark, tagon, tagoff, image, et window. La valeur correspondante est le texte, le nom de la marque, le nom de la balise, le nom de l'image ou le nom de la fenêtre. L'information d'index est l'index du début du texte, de la marque, de la transition de balise, de l'image ou de la fenêtre. Une ou plusieurs des options suivantes (ou leurs abréviations) peuvent être spécifiées pour contrôler le dump :

-tout
Retourne les informations sur tous les éléments : texte, marques, balises, images et fenêtres. C'est la valeur par défaut.
-command commande
Au lieu de retourner les informations comme résultat de l'opération de dump, invoque la commande sur chaque élément du widget texte dans la plage. La commande a trois arguments ajoutés avant d'être évaluée : la clé, la valeur et l'index.
-image
Inclut les informations sur les images dans les résultats du dump.
-marque
Inclut les informations sur les marques dans les résultats du dump.
-balise
Inclut les informations sur les transitions de balises dans les résultats du dump. Les informations de balise sont retournées comme éléments tagon et tagoff qui indiquent le début et la fin de chaque plage de chaque balise, respectivement.
-texte
Inclut les informations sur le texte dans les résultats du dump. La valeur est le texte jusqu'à l'élément suivant ou la fin de la plage indiquée par index2. Un élément de texte ne s'étend pas sur les retours à la ligne. Un bloc de texte multiligne qui ne contient aucune marque ou transition de balise sera toujours déchargé sous forme d'un ensemble de segments de texte qui se terminent chacun par un retour à la ligne. Le retour à la ligne fait partie de la valeur.
-fenetre
Inclut les informations sur les fenêtres incorporées dans les résultats du dump. La valeur d'une fenêtre est son chemin d'accès Tk, sauf si la fenêtre n'a pas encore été créée (elle doit avoir un script de création). Dans ce cas, une chaîne vide est retournée, et vous devez interroger la fenêtre par sa position d'index pour obtenir plus d'informations.
pathName edit option ?arg arg ...?
Cette commande contrôle le mécanisme d'annulation et le drapeau modifié. Le comportement exact de la commande dépend de l'argument option qui suit l'argument edit. Les formes suivantes de la commande sont actuellement prises en charge :
pathName edit canredo
Retourne un booléen vrai si le redo est possible, c'est-à-dire lorsque la pile de redo n'est pas vide. Sinon, retourne faux.
pathName edit canundo
Retourne un booléen vrai si l'undo est possible, c'est-à-dire lorsque la pile d'undo n'est pas vide. Sinon, retourne faux.
pathName edit modified ?booléen?
Si booléen n'est pas spécifié, retourne le drapeau modifié du widget. Les commandes insert, delete, edit undo et edit redo ou l'utilisateur peuvent définir ou effacer le drapeau modifié. Si booléen est spécifié, définit le drapeau modifié du widget à booléen.
pathName edit redo
Lorsque l'option -undo est vraie, réapplique les dernières modifications annulées à condition qu'aucune autre modification n'ait été faite depuis. Génère une erreur lorsque la pile de redo est vide. Ne fait rien lorsque l'option -undo est fausse.
pathName edit reset
Vide les piles d'undo et de redo.
pathName edit separator
Insère un séparateur (limite) sur la pile d'undo. Ne fait rien lorsque l'option -undo est fausse.
pathName edit undo
Annule la dernière action d'édition lorsque l'option -undo est vraie. Une action d'édition est définie comme toutes les commandes d'insertion et de suppression
enregistrés sur la pile d'annulation entre deux séparateurs. Génère une erreur lorsque la pile d'annulation est vide. Ne fait rien lorsque l'option -undo est fausse.
cheminNom get ?-displaychars? ?--? index1 ?index2 ...?
Retourne une plage de caractères du texte. La valeur de retour sera tous les caractères du texte commençant par celui dont l'index est index1 et se terminant juste avant celui dont l'index est index2 (le caractère à index2 ne sera pas retourné). Si index2 est omis, alors le caractère unique à index1 est retourné. S'il n'y a pas de caractères dans la plage spécifiée (par exemple, si index1 est après la fin du fichier ou si index2 est inférieur ou égal à index1), une chaîne vide est retournée. Si la plage spécifiée contient des fenêtres intégrées, aucune information à leur sujet n'est incluse dans la chaîne retournée. Si plusieurs paires d'index sont données, plusieurs plages de texte seront retournées dans une liste. Les plages invalides ne seront pas représentées par des chaînes vides dans la liste. Les plages sont retournées dans l'ordre passé à cheminNom get. Si l'option -displaychars est donnée, alors, dans chaque plage, seuls les caractères qui ne sont pas élidés seront retournés. Cela peut avoir pour effet que certaines des plages retournées soient des chaînes vides.
cheminNom image option ?arg arg ...?
Cette commande est utilisée pour manipuler les images intégrées. Le comportement de la commande dépend de l'argument option qui suit l'argument image. Les formes suivantes de la commande sont actuellement prises en charge :
cheminNom image cget index option
Retourne la valeur d'une option de configuration pour une image intégrée. Index identifie l'image intégrée, et option spécifie une configuration particulière, qui doit être l'une de celles listées dans la section IMAGES INTÉGRÉES.
cheminNom image configure index ?option valeur ...?
Interroge ou modifie les options de configuration d'une image intégrée. Si aucune option n'est spécifiée, retourne une liste décrivant toutes les options disponibles pour l'image intégrée à index (voir Tk_ConfigureInfo pour plus d'informations sur le format de cette liste). Si option est spécifiée sans valeur, alors la commande retourne une liste décrivant l'option nommée (cette liste sera identique à la sous-liste correspondante de la valeur retournée si aucune option n'est spécifiée). Si une ou plusieurs paires option-valeur sont spécifiées, alors la commande modifie l' (les) option (s) donnée (s) pour avoir la (les) valeur (s) donnée (s) ; dans ce cas, la commande retourne une chaîne vide. Voir IMAGES INTÉGRÉES pour plus d'informations sur les options qui sont prises en charge.
cheminNom image create index ?option valeur ...?
Cette commande crée une nouvelle annotation d'image, qui apparaîtra dans le texte à la position indiquée par index. N'importe quel nombre de paires option-valeur peut être spécifié pour configurer l'annotation. Retourne un identifiant unique qui peut être utilisé comme index pour faire référence à cette image. Voir IMAGES INTÉGRÉES pour plus d'informations sur les options qui sont prises en charge, et une description de l'identifiant retourné.
cheminNom image names
Retourne une liste dont les éléments sont les noms de toutes les instances d'images actuellement intégrées dans fenêtre.
cheminNom index index
Retourne la position correspondant à index sous la forme ligne.caractère où ligne est le numéro de ligne et caractère est le numéro du caractère. Index peut avoir l'une des formes décrites sous INDEX ci-dessus.
cheminNom insert index caractères ?listeTags caractères listeTags ...?
Insère tous les arguments caractères juste avant le caractère à index. Si index fait référence à la fin du texte (le caractère après la dernière nouvelle ligne), alors le nouveau texte est inséré juste avant la dernière nouvelle ligne à la place. S'il y a un seul argument caractères et aucune listeTags, alors le nouveau texte recevra tous les tags présents à la fois sur le caractère avant et sur le caractère après le point d'insertion ; si un tag est présent sur seulement un de ces caractères, alors il ne sera pas appliqué au nouveau texte. Si une listeTags est spécifiée, alors elle consiste en une liste de noms de tags ; les nouveaux caractères recevront tous les tags de cette liste et aucun autre, indépendamment des tags présents autour du point d'insertion. Si plusieurs paires d'arguments caractères-listeTags sont présentes, elles produisent le même effet que si une commande de widget séparée cheminNom insert avait été émise pour chaque paire, dans l'ordre. Le dernier argument listeTags peut être omis.
cheminNom mark option ?arg arg ...?
Cette commande est utilisée pour manipuler les marques. Le comportement exact de la commande dépend de l'argument option qui suit l'argument mark. Les formes suivantes de la commande sont actuellement prises en charge :
cheminNom mark gravity nomMarque ?direction?
Si direction n'est pas spécifiée, retourne left ou right pour indiquer à quel de ses caractères adjacents nomMarque est attaché. Si direction est spécifiée, elle doit être left ou right ; la gravité de nomMarque est définie à la valeur donnée.
cheminNom mark names
Retourne une liste dont les éléments sont les noms de toutes les marques qui sont actuellement définies.
cheminNom mark next index
Retourne le nom de la marque suivante à partir de index ou à index. Si index est spécifié sous forme numérique, alors la recherche de la marque suivante commence à cet index. Si index est le nom d'une marque, alors la recherche de la marque suivante commence immédiatement après cette marque. Cela peut toujours retourner une marque à la même position s'il y a plusieurs marques au même index. Ces sémantiques signifient que l'opération mark next peut être utilisée pour parcourir toutes les marques d'un widget texte dans le même ordre que les informations de marque retournées par l'opération cheminNom dump. Si une marque a été définie à l'index spécial end, alors elle apparaît comme étant après end par rapport à l'opération cheminNom mark next. Une chaîne vide est retournée s'il n'y a pas de marques après index.
cheminNom mark previous index

pathName search ?switches? pattern index ?stopIndex?
Recherche le texte dans pathName à partir de index pour une plage de caractères qui correspond à pattern. Si une correspondance est trouvée, l'index du premier caractère de la correspondance est renvoyé comme résultat ; sinon, une chaîne vide est renvoyée. Un ou plusieurs des commutateurs suivants (ou leurs abréviations) peuvent être spécifiés pour contrôler la recherche :
-forwards
La recherche se poursuivra en avant dans le texte, trouvant la première plage correspondante à partir de la position donnée par index ou après. C'est le comportement par défaut.
-backwards
La recherche se poursuivra en arrière dans le texte, trouvant la plage correspondante la plus proche de index dont le premier caractère est avant index (il n'est pas autorisé d'être à index). Notez que, pour diverses raisons, les recherches en arrière peuvent être considérablement plus lentes que les recherches en avant (en particulier lors de l'utilisation de -regexp), il est donc recommandé que le code critique en termes de performance utilise des recherches en avant.
-exact
Utilise une correspondance exacte : les caractères de la plage correspondante doivent être identiques à ceux de pattern. C'est le comportement par défaut.
-regexp
Traite pattern comme une expression régulière et la fait correspondre au texte en utilisant les règles des expressions régulières (voir la commande regexp et la page re_syntax pour plus de détails). La correspondance par défaut passe automatiquement les options -lineanchor et -linestop au moteur regexp (sauf si -nolinestop est utilisé), de sorte que ^$ corresponde au début et à la fin de la ligne, et que ., [^ les séquences ne correspondent jamais au caractère de nouvelle ligne \n.
-nolinestop
Ceci permet à . et [^ les séquences de correspondre au caractère de nouvelle ligne \n, ce qu'elles ne font pas autrement (voir la commande regexp pour plus de détails). Cette option n'est significative que si -regexp est également spécifié, sinon une erreur sera générée. Par exemple, pour faire correspondre tout le texte, utilisez « pathName search -nolinestop -regexp ".*" 1.0 ».
-nocase
Ignore les différences de casse entre le motif et le texte.
-count varName
L'argument suivant -count donne le nom d'une variable ; si une correspondance est trouvée, le nombre de positions d'index entre le début et la fin de la plage correspondante sera stocké dans la variable. S'il n'y a pas d'images intégrées ou de fenêtres dans la plage correspondante (et qu'il n'y a pas de caractères élidés si -elide n'est pas spécifié), cela équivaut au nombre de caractères correspondants. Dans les deux cas, la plage matchIdx à matchIdx + $count chars retournera tout le texte correspondant.
-all
Trouve toutes les correspondances dans la plage donnée et renvoie une liste des indices du premier caractère de chaque correspondance. Si un commutateur -count varName est donné, alors varName est également défini sur une liste contenant un élément pour chaque correspondance réussie. Notez que, même pour les recherches exactes, les éléments de cette liste peuvent être différents, s'il y a des images intégrées, des fenêtres ou du texte masqué. Les recherches avec -all se comportent de manière très similaire à la commande Tcl regexp -all, en ce sens que les correspondances qui se chevauchent ne sont normalement pas retournées. Par exemple, appliquer une recherche -all du motif « \w+ » sur « hello there » ne correspondra que deux fois, une fois pour chaque mot, et faire correspondre « Z[a-z]+Z » sur « ZooZooZoo » ne correspondra qu'une fois.
-overlap
Lors de l'exécution de recherches -all, le comportement normal est que les correspondances qui chevauchent une correspondance déjà trouvée ne seront pas retournées. Ce commutateur modifie ce comportement de sorte que toutes les correspondances qui ne sont pas totalement incluses dans une autre correspondance soient retournées. Par exemple, appliquer une recherche -overlap du motif « \w+ » sur « hello there » ne correspondra que deux fois (c'est-à-dire qu'il n'y aura pas de différence par rapport à un simple -all), mais faire correspondre « Z[a-z]+Z » sur « ZooZooZoo » correspondra maintenant deux fois. Une erreur sera générée si ce commutateur est utilisé sans -all.
-strictlimits
Lors de l'exécution de toute recherche, le comportement normal est que les limites de début et de fin sont vérifiées par rapport au début du texte correspondant. Avec le drapeau -strictlimits, toute la plage correspondante doit se trouver à l'intérieur des limites de début et de fin spécifiées pour que la correspondance soit valide.
-elide
Recherche également le texte élidé (masqué). Par défaut, seul le texte affiché est recherché.
--
Ce commutateur n'a aucun effet, sauf pour terminer la liste des commutateurs : l'argument suivant sera traité comme pattern même s'il commence par -.

La plage de correspondance peut être sur une seule ligne de texte, ou s'étendre sur plusieurs lignes (si des parties du motif peuvent correspondre à un nouvelle ligne). Pour la correspondance d'expressions régulières, vous pouvez utiliser les diverses fonctionnalités de correspondance de nouvelles lignes telles que $ pour correspondre à la fin d'une ligne, ^ pour correspondre au début d'une ligne, et pour contrôler si . est autorisé à correspondre à une nouvelle ligne. Si stopIndex est spécifié, la recherche s'arrête à cet index : pour les recherches avant, aucune correspondance à l'index stopIndex ou après ne sera prise en compte ; pour les recherches arrière, aucune correspondance antérieure à stopIndex ne sera prise en compte. Si stopIndex est omis, tout le texte sera recherché : lorsque le début ou la fin du texte est atteint, la recherche continue à l'autre extrémité jusqu'à ce que l'emplacement de départ soit à nouveau atteint ; si stopIndex est spécifié, aucun retour à la ligne ne se produira. Cela signifie que, par exemple, si la recherche est -forwards mais que stopIndex est avant startIndex dans le texte, rien ne sera jamais trouvé. PROBLÈMES CONNUS

PROBLÈMES CONCERNANT LES CARACTÈRES ET LES INDEX

Avant Tk 8.5, le widget utilisait la chaîne « chars » pour faire référence aux positions d'index (qui incluaient les caractères, les fenêtres incorporées et les images incorporées). Depuis Tk 8.5, le widget texte gère séparément et correctement les « chars » et les « indices ». Pour des raisons de compatibilité ascendante, cependant, les modificateurs d'index « +N chars » et « -N chars » continuent de faire référence aux indices. Il faut utiliser l'une des formes complètes « +N any chars » ou « -N any chars », etc. pour faire référence aux index de caractères réels. Cette confusion pourra être corrigée dans une future version en faisant interpréter correctement au widget « +N chars » comme un synonyme de « +N any chars ».

PROBLÈMES DE PERFORMANCE

Les widgets texte devraient fonctionner efficacement dans diverses conditions. Le widget texte utilise environ 2-3 octets de mémoire principale pour chaque octet de texte, donc des textes contenant un mégaoctet ou plus devraient être réalisables sur la plupart des postes de travail. Le texte est représenté en interne avec une structure B-tree modifiée qui rend les opérations relativement efficaces, même avec de grands textes. Les balises sont incluses dans la structure B-tree de manière à permettre aux balises de couvrir de grandes plages ou d'avoir de nombreuses petites plages disjointes sans perte d'efficacité. Les marques sont également implémentées de manière à permettre un grand nombre de marques. Dans la plupart des cas, il est acceptable d'avoir un grand nombre de balises uniques, ou une balise qui a de nombreuses plages distinctes.

Un problème de performance peut survenir si vous avez des centaines ou des milliers de balises différentes qui ont toutes les caractéristiques suivantes : les première et dernière plages de chaque balise sont respectivement près du début et de la fin du texte, ou une seule plage de balise couvre la majeure partie du widget texte. Le coût d'ajout et de suppression de balises de ce type est proportionnel au nombre d'autres balises ayant les mêmes propriétés. En revanche, il n'y a aucun problème à avoir des milliers de balises distinctes si leurs plages globales sont localisées et réparties uniformément dans tout le texte.

Les lignes de texte très longues peuvent être coûteuses, surtout si elles contiennent de nombreuses marques et balises.

La ligne d'affichage avec le curseur d'insertion est redessinée chaque fois que le curseur clignote, ce qui génère un flux constant de trafic graphique. Définissez l'attribut -insertofftime sur 0 pour éviter cela.

BOGUES CONNUS

La sous-commande pathName search -regexp tente d'effectuer une correspondance regexp sophistiquée sur plusieurs lignes de manière efficace (depuis Tk 8.5), en examinant chaque ligne individuellement, puis par petits groupes de lignes, que la recherche soit effectuée vers l'avant ou vers l'arrière. Dans certaines conditions, le résultat de la recherche peut différer de celui obtenu en appliquant la même regexp à l'ensemble du texte du widget en une seule fois. Par exemple, lors de la recherche avec une regexp gourmande, le widget continuera à tenter d'ajouter des lignes supplémentaires à la correspondance tant que l'une des deux conditions suivantes est vraie : soit la bibliothèque regexp de Tcl renvoie un code indiquant qu'une correspondance plus longue est possible (mais il existe des bogues connus dans Tcl qui font que ce code n'est pas toujours correctement renvoyé) ; soit si chaque ligne supplémentaire ajoutée entraîne au moins une correspondance partielle avec le modèle. Cela signifie que dans le cas où la première ligne supplémentaire ajoutée ne produit aucune correspondance et où le système regexp de Tcl renvoie le code incorrect, et où l'ajout d'une deuxième ligne supplémentaire correspondrait réellement, le widget texte renverra un résultat erroné. En pratique, il s'agit d'un problème rare, mais il peut survenir, par exemple :

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\ncccc\nbbbb\naaaa\n"
.t search -regexp -- {(a+|b+\nc+\nb+)+\na+} 1.0
ne trouvera pas de correspondance alors qu'il en existe une de 19 caractères commençant par le premier « b ».

Chaque fois qu'une correspondance possible est entièrement incluse dans une autre, la commande de recherche tentera de s'assurer que seule la correspondance la plus grande est retournée. Lors de la recherche arrière par regexp, il est possible que Tcl n'y parvienne pas toujours, dans le cas où une correspondance est précédée d'une ou plusieurs correspondances courtes et non chevauchantes, toutes précédées d'une grande correspondance qui les englobe réellement toutes. L'algorithme de recherche utilisé par le widget ne regarde pas arbitrairement loin pour une correspondance possible qui pourrait couvrir de larges portions du widget. Par exemple :

pack [text .t]
.t insert 1.0 "aaaa\nbbbb\nbbbb\nbbbb\nbbbb\n"
.t search -regexp -backward -- {b+\n|a+\n(b+\n)+} end
correspond à « 5.0 » alors qu'une véritable correspondance gourmande correspondrait à « 1.0 ». De même, si nous ajoutons -all à ce cas, il correspond à tous les « 5.0 », « 4.0 », « 3.0 » et « 1.0 », alors qu'en réalité il ne devrait correspondre qu'à « 1.0 » puisque cette correspondance englobe toutes les autres.
