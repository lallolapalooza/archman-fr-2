tk_getOpenFile(n) Commandes intégrées Tk tk_getOpenFile(n)

NOM

tk_getOpenFile, tk_getSaveFile - ouvrir une boîte de dialogue pour que l'utilisateur sélectionne un fichier à ouvrir ou à enregistrer.

SYNOPSIS

tk_getOpenFile ?option valeur ...?
tk_getSaveFile ?option valeur ...?

DESCRIPTION

Les procédures tk_getOpenFile et tk_getSaveFile ouvrent une boîte de dialogue pour que l'utilisateur sélectionne un fichier à ouvrir ou à enregistrer. La commande tk_getOpenFile est généralement associée à la commande Ouvrir du menu Fichier. Son but est de permettre à l'utilisateur de sélectionner un fichier existant uniquement. Si l'utilisateur saisit un fichier inexistant, la boîte de dialogue affiche un message d'erreur et demande à l'utilisateur de faire une sélection alternative. Si une application permet à l'utilisateur de créer de nouveaux fichiers, elle devrait le faire en fournissant une commande de menu Nouveau séparée.

La commande tk_getSaveFile est généralement associée à la commande Enregistrer sous du menu Fichier. Si l'utilisateur saisit un fichier qui existe déjà, la boîte de dialogue demande à l'utilisateur une confirmation pour savoir si le fichier existant doit être écrasé ou non.

Les paires option-valeur suivantes sont possibles en tant qu'arguments de ligne de commande pour ces deux commandes :

-command chaîne
Spécifie le préfixe d'une commande Tcl à invoquer lorsque l'utilisateur ferme la boîte de dialogue après avoir sélectionné un élément. Ce rappel n'est pas appelé si l'utilisateur a annulé la boîte de dialogue. La commande réelle consiste en chaîne suivie d'un espace et de la valeur sélectionnée par l'utilisateur dans la boîte de dialogue. Ceci n'est disponible que sur macOS.
-confirmoverwrite booléen
Configure la réaction de la boîte de dialogue Enregistrer lorsqu'un fichier sélectionné existe déjà et que l'enregistrement l'écraserait. Une valeur vraie demande la présentation d'une boîte de dialogue de confirmation à l'utilisateur. Une valeur fausse demande que l'écrasement se fasse sans confirmation. La valeur par défaut est vraie.
-defaultextension extension
Spécifie une chaîne qui sera ajoutée au nom de fichier si l'utilisateur saisit un nom de fichier sans extension. La valeur par défaut est la chaîne vide, ce qui signifie qu'aucune extension ne sera ajoutée au nom de fichier dans tous les cas. Cette option est ignorée sur macOS, qui n'exige pas d'extensions pour les noms de fichiers, et l'implémentation UNIX devine des valeurs raisonnables à partir de l'option -filetypes lorsque celle-ci n'est pas fournie.
-filetypes liste_motifs_fichiers
Si une liste de types de fichiers existe dans la boîte de dialogue de fichiers sur la plateforme particulière, cette option fournit les types de fichiers dans cette liste. Lorsque l'utilisateur choisit un type de fichier dans la liste, seuls les fichiers de ce type sont répertoriés. Si cette option n'est pas spécifiée, ou si elle est définie sur la liste vide, ou si la liste des types de fichiers n'est pas prise en charge par la plateforme particulière, alors tous les fichiers sont répertoriés indépendamment de leur type. Voir la section SPÉCIFICATION DES MOTIFS DE FICHIERS ci-dessous pour une discussion sur le contenu de liste_motifs_fichiers.
-initialdir répertoire
Spécifie que les fichiers dans répertoire doivent être affichés lorsque la boîte de dialogue s'ouvre. Si ce paramètre n'est pas spécifié, le répertoire initial est par défaut le répertoire de travail courant sur les systèmes non-Windows et sur les systèmes Windows avant Vista. Sur les systèmes Vista et ultérieurs, le répertoire initial est par défaut le dernier répertoire sélectionné par l'utilisateur pour l'application. Si le paramètre spécifie un chemin relatif, la valeur renvoyée convertira le chemin relatif en chemin absolu.
-initialfile nom_fichier
Spécifie un nom de fichier à afficher dans la boîte de dialogue lorsqu'elle s'ouvre.
-message chaîne
Spécifie un message à inclure dans la zone client de la boîte de dialogue. Ceci n'est disponible que sur macOS.
-multiple booléen
Permet à l'utilisateur de choisir plusieurs fichiers dans la boîte de dialogue Ouvrir.
-parent fenêtre
Fait de fenêtre le parent logique de la boîte de dialogue de fichiers. La boîte de dialogue de fichiers est affichée par-dessus sa fenêtre parente. Sur macOS, cela transforme la boîte de dialogue de fichiers en une feuille attachée à la fenêtre parente.
-title chaîne_titre
Spécifie une chaîne à afficher comme titre de la boîte de dialogue. Si cette option n'est pas spécifiée, un titre par défaut est affiché.
-typevariable nom_variable
La variable globale nom_variable est utilisée pour présélectionner le filtre à utiliser dans liste_filtres lorsque la boîte de dialogue s'ouvre, et est mise à jour lors de la fermeture de la boîte de dialogue, vers le dernier filtre sélectionné. La variable est lue une fois au début pour sélectionner le filtre approprié. Si la variable n'existe pas, ou si sa valeur ne correspond à aucun nom de type de filtre, ou est vide ({}), la boîte de dialogue reviendra au comportement par défaut de sélection du premier filtre de la liste. Si la boîte de dialogue est annulée, la variable n'est pas modifiée.

Si l'utilisateur sélectionne un fichier, tk_getOpenFile et tk_getSaveFile renvoient le chemin complet de ce fichier. Si l'utilisateur annule l'opération, les deux commandes renvoient la chaîne vide.

SPECIFICATION DES MOTIFS DE FICHIERS

La valeur liste_motifs_fichiers fournie par l'option -filetypes est une liste de motifs de fichiers. Chaque motif de fichier est une liste de la forme

nomType {extension ?extension ...?} ?{typeMac ?typeMac ...?}?
nomType est le nom du type de fichier décrit par ce motif de fichier et est la chaîne de caractères qui apparaît dans la liste Types de fichiers. extension est une extension de fichier pour ce motif de fichier. typeMac est un type de fichier Macintosh de quatre caractères. La liste des typeMac est facultative et peut être omise pour les applications qui n'ont pas besoin de s'exécuter sur la plateforme Macintosh.

Plusieurs motifs de fichiers peuvent avoir le même nomType, auquel cas ils se réfèrent au même type de fichier et partagent la même entrée dans la liste. Lorsque l'utilisateur sélectionne une entrée dans la liste, tous les fichiers qui correspondent à au moins un des motifs de fichiers correspondant à cette entrée sont listés. Généralement, chaque motif de fichier correspond à un type de fichier distinct. L'utilisation de plus d'un motif de fichier pour un type de fichier n'est nécessaire que sur la plateforme Macintosh.

Sur la plateforme Macintosh, un fichier correspond à un motif de fichier si son nom correspond à au moins une des extensions ET s'il appartient à au moins un des typeMac du motif de fichier. Par exemple, le motif de fichier Fichiers source C dans l'exemple de code correspond aux fichiers ayant une extension .c ET appartenant au typeMac TEXT. Pour utiliser la règle OU à la place, vous pouvez utiliser deux motifs de fichiers, l'un avec les extensions uniquement et l'autre avec le typeMac uniquement. Le type de fichier Fichiers GIF dans l'exemple de code correspond aux fichiers qui ont soit une extension .gif OU appartiennent au typeMac GIFF.

Sur les plateformes Unix et Windows, un fichier correspond à un motif de fichier si son nom correspond à au moins une des extensions du motif de fichier. Les typeMac sont ignorés.

SPECIFICATION DES EXTENSIONS

Sur les plateformes Unix et Macintosh, les extensions sont correspondées à l'aide de la correspondance de motifs de style glob. Sur la plateforme Windows, les extensions sont correspondées par le système d'exploitation sous-jacent. Les types d'extensions possibles sont :

(1)
l'extension spéciale “*” correspond à n'importe quel fichier ;
(2)
l'extension spéciale “” correspond à tous les fichiers qui n'ont pas d'extension (c'est-à-dire, le nom de fichier ne contient aucun caractère point) ;
(3)
toute chaîne de caractères qui ne contient pas de caractères génériques (* et ?).

tk_getOpenFile(n) — Arch manual pages

NAME

tk_getOpenFile — invoke file selection dialog

SYNOPSIS

tk_getOpenFile ?-option value? ... ?-command cmd?

DESCRIPTION

The tk_getOpenFile command invokes the standard Tk file selection dialog. This dialog allows the user to select a file from the file system. The dialog can be customized using various options.

The command returns the name of the selected file. If the user cancels the dialog, it returns an empty string.

The following options are supported:

-filetypes ?list?
Specifies a list of file type descriptions. Each description is a list containing a human-readable name and a pattern or a list of patterns. For example: 
{{Text Files} {.txt}}
{{TCL Scripts} {.tcl}}
{{C Source Files} {.c}}
{{All Files} *}
The patterns can use standard shell wildcards (*, ?, []). If the pattern is empty, it means all files will be listed.

If a file type description also contains a third element, this element is a suffix to be appended to the filename if the selected file doesn't already have a matching suffix.

If the -filetypes option is not specified, the dialog will default to showing all files.

-initialdir ?dir?
Specifies the initial directory to display in the dialog. If not specified, the current working directory is used.
-initialfile ?file?
Specifies the initial file to select in the dialog. This is useful for pre-selecting a file when editing an existing file.
-parent ?window?
Specifies the parent window for the dialog. If not specified, the dialog will be associated with the toplevel window containing the widget that invoked the command.
-title ?string?
Specifies the title for the dialog window. If not specified, the dialog will have a default title.
-command ?cmd?
Specifies a Tcl command to be executed when the user selects a file and clicks "Open". The selected filename will be appended as an argument to the command. If the user cancels the dialog, the command will not be executed.

SPECIFYING FILE PATTERNS

File type descriptions consist of a human-readable name followed by one or more file patterns. The patterns are shell-style wildcards. A pattern consists of literal characters and the following special sequences:

*
Matches any sequence of zero or more characters.
?
Matches any single character.
[chars]
Matches any one of the characters in chars.
\x
Matches the character x literally. This is useful for matching characters that have special meaning, such as `*’, `?’, `[’, and `\’ itself.

A pattern can be a single pattern or a list of patterns. If it is a list, the file type will match any file whose name matches any of the patterns in the list.

An empty pattern matches all files. This is useful for providing an "All Files" option.

SPECIFYING EXTENSIONS

If a file type description includes a third element, this element is treated as a default extension. If the user enters a filename without an extension, and the entered filename does not match any of the specified patterns for the currently selected file type, the default extension will be appended to the filename. If the selected file type has multiple patterns and none of them match, the default extension will be appended. If the selected file type has no patterns (i.e. it matches all files), the default extension will be appended if the filename does not already have an extension.

The use of backslashes or other special characters in the patterns or default extensions may not be portable across all platforms. Tcl stop character (e.g. “~”) are allowed but may not work on all platforms.

EXAMPLE

set types {
    {{Text Files}       {.txt}        }
    {{TCL Scripts}      {.tcl}        }
    {{C Source Files}   {.c}      TEXT}
    {{GIF Files}        {.gif}        }
    {{GIF Files}        {}        GIFF}
    {{All Files}        *             }
}
set filename [tk_getOpenFile -filetypes $types]
if {$filename ne ""} {
    # Open the file ...
}
