INTRODUCTION

La commande menu crée une nouvelle fenêtre de premier niveau (donnée par l'argument nomChemin) et en fait un widget menu. Ce widget menu peut soit être utilisé comme une fenêtre pop-up, soit être appliqué à un toplevel (avec son option -menu) pour en faire la barre de menus de ce toplevel. Des options supplémentaires, décrites ci-dessus, peuvent être spécifiées sur la ligne de commande ou dans la base de données d'options pour configurer des aspects du menu tels que ses couleurs et sa police. La commande menu renvoie son argument nomChemin. Au moment où cette commande est appelée, aucune fenêtre nommée nomChemin ne doit exister, mais le parent de nomChemin doit exister.

Un menu est un widget qui affiche une collection d'entrées sur une ligne, disposées en une ou plusieurs colonnes. Il existe plusieurs types d'entrées, chacune avec des propriétés différentes. Les entrées de types différents peuvent être combinées dans un seul menu. Les entrées de menu ne sont pas identiques aux widgets d'entrée. En fait, les entrées de menu ne sont même pas des widgets distincts ; l'ensemble du menu est un seul widget.

Les entrées de menu sont affichées avec jusqu'à trois champs séparés. Le champ principal est une étiquette sous forme de chaîne de texte, d'une bitmap ou d'une image, contrôlée par les options -label, -bitmap et -image pour l'entrée. Si l'option -accelerator est spécifiée pour une entrée, un deuxième champ textuel est affiché à droite de l'étiquette. L'accélérateur décrit typiquement une séquence de touches qui peut être utilisée dans l'application pour obtenir le même résultat que l'appel de l'entrée de menu. Ceci est une option d'affichage, cela ne définit pas réellement la liaison correspondante (ce qui peut être réalisé en utilisant la commande bind). Le troisième champ est un *indicateur*. L'indicateur n'est présent que pour les entrées de type case à cocher ou bouton radio. Il indique si l'entrée est sélectionnée ou non, et il est affiché à gauche de la chaîne de l'entrée.

En utilisation normale, une entrée devient active (s'affiche différemment) chaque fois que le pointeur de la souris se trouve sur l'entrée. Si un bouton de la souris est relâché sur l'entrée, l'entrée est *appelée*. L'effet de l'appel est différent pour chaque type d'entrée ; ces effets sont décrits ci-dessous dans les sections sur les entrées individuelles.

Les entrées peuvent être *désactivées*, ce qui fait que leurs étiquettes et accélérateurs s'affichent avec des couleurs plus sombres. Les liaisons de menu par défaut ne permettront pas à une entrée désactivée d'être activée ou appelée. Les entrées désactivées peuvent être réactivées, auquel cas il devient à nouveau possible de les activer et de les appeler.

Chaque fois que l'entrée active d'un menu est modifiée, un événement virtuel <<MenuSelect>> est envoyé au menu. L'élément actif peut alors être interrogé à partir du menu, et une action peut être entreprise, telle que la définition d'un texte d'aide contextuelle pour l'entrée.

TYPES D'ENTRÉES

ENTRÉES DE COMMANDE

Le type d'entrée de menu le plus courant est une entrée de commande, qui se comporte de manière similaire à un widget bouton. Lorsqu'une entrée de commande est appelée, une commande Tcl est exécutée. La commande Tcl est spécifiée avec l'option -command.

ENTRÉES DE SÉPARATEUR

Un séparateur est une entrée qui est affichée comme une ligne de division horizontale. Un séparateur ne peut pas être activé ou appelé, et il n'a d'autre comportement que son apparence visuelle.

ENTRÉES DE CASE À COCHER

Une entrée de menu de type case à cocher se comporte de manière similaire à un widget case à cocher. Lorsqu'elle est appelée, elle bascule entre les états sélectionné et désélectionné. Lorsque l'entrée est sélectionnée, une valeur particulière est stockée dans une variable globale particulière (déterminée par les options -onvalue et -variable de l'entrée) ; lorsque l'entrée est désélectionnée, une autre valeur (déterminée par l'option -offvalue) est stockée dans la variable globale. Une boîte indicateur est affichée à gauche de l'étiquette dans une entrée de case à cocher. Si l'entrée est sélectionnée, le centre de l'indicateur s'affiche dans la couleur spécifiée par l'option -selectcolor de l'entrée ; sinon, le centre de l'indicateur s'affiche dans la couleur d'arrière-plan du menu. Si une option -command est spécifiée pour une entrée de case à cocher, sa valeur est évaluée comme une commande Tcl chaque fois que l'entrée est appelée ; cela se produit après le basculement de l'état sélectionné de l'entrée.

ENTRÉES DE BOUTON RADIO

Une entrée de menu de type bouton radio se comporte de manière similaire à un widget bouton radio. Les entrées de bouton radio sont organisées en groupes dont une seule entrée peut être sélectionnée à la fois. OPTIONS

Menu widgets have a default configuration of colors and stipple patterns, but it is possible to override them. MENU ENTRY OPTIONS

The options listed below apply to individual entries within a menu. These options are specified when an entry is created using the add widget command. They can also be modified later using the entryconfigure widget command. The list below applies to entries of type command, checkbutton, radiobutton, and cascade.

-activebackground color
Specifies the background color for the entry when the mouse cursor is over it and the entry is active. Defaults to the value of system highlight color.
-activeforeground color
Specifies the foreground color for the entry when the mouse cursor is over it and the entry is active. Defaults to the value of system highlight text color.
-background color
Specifies the background color for the entry. Defaults to the value of the menu's background color.
-bitmap bitmap
Specifies a bitmap to be displayed in the entry. This is mutually exclusive with the -image option. If specified, it overrides any image. If the entry is a checkbutton or radiobutton, this bitmap is displayed in the indicator area.
-borderwidth num
Specifies the width of the border around the entry. Defaults to 0.
-checkedimage image
Specifies an image to display in the indicator area of a checkbutton or radiobutton entry when the entry is checked or selected, respectively. This is mutually exclusive with the -checkmonochrome and -radiomonochrome options. The image may be a bitmap or a photo image. If this option is set, it overrides the -checkbackground and -checkborderwidth options.
-checkbackground color
Specifies the background color for the indicator area of a checkbutton or radiobutton entry when it is checked or selected. Defaults to the value of the menu's background color.
-checkborderwidth num
Specifies the border width for the indicator area of a checkbutton or radiobutton entry. Defaults to 1.
-checkcolor color
Specifies the color to use for the indicator of a checkbutton or radiobutton when it is checked or selected. Defaults to the menu's foreground color.
-checkimage image
Specifies an image to display in the indicator area of a checkbutton or radiobutton entry when it is checked or selected, respectively. This is mutually exclusive with the -checkmonochrome and -radiomonochrome options. The image may be a bitmap or a photo image. If this option is set, it overrides the -checkbackground and -checkborderwidth options.
-command script
Specifies a Tcl script to be executed whenever the entry is invoked. This option is ignored for entries of type separator.
-default value
Specifies the default value for a checkbutton or radiobutton entry. If this is true, the entry is initially selected/checked. Defaults to false.
-discriminator value
Specifies the value associated with a radiobutton entry. This option is only relevant for radiobutton entries. When a radiobutton is selected, its associated variable is set to this value.
-font fontName
Specifies the font to be used for the entry's label. Defaults to the menu's font.
-foreground color
Specifies the foreground color for the entry. Defaults to the menu's foreground color.
-image image
Specifies an image to be displayed in the entry. This is mutually exclusive with the -bitmap option. The image may be a bitmap or a photo image. If specified, it overrides any bitmap. If the entry is a checkbutton or radiobutton, this image is displayed in the indicator area.
-indicatoron boolean
Specifies whether to display an indicator for checkbutton and radiobutton entries. Defaults to true.
-label string
Specifies the text string to be displayed for the entry. Defaults to the empty string.
-menu menuName
Specifies the name of a menu to be displayed when this entry is selected. This option is only valid for cascade entries. The menu specified by menuName must be a child of the menu containing this cascade entry.
-offimage image
Specifies an image to display in the indicator area of a checkbutton or radiobutton entry when it is unchecked or unselected, respectively. This is mutually exclusive with the -checkmonochrome and -radiomonochrome options. The image may be a bitmap or a photo image. If this option is set, it overrides the -checkbackground and -checkborderwidth options.
-radiobehavior boolean
Specifies whether radiobutton entries should behave as a group. If true, selecting one radiobutton automatically deselects any other selected radiobutton in the same group. Defaults to false.
-selectcolor color
Specifies the color to use for the indicator of a checkbutton or radiobutton when it is selected. Defaults to the menu's foreground color.
-separatorborderwidth num
Specifies the border width for separator entries. Defaults to 0.
-separatorpadx num
Specifies the padding on either side of the separator line within the separator entry. Defaults to 4 pixels.
-separatorpady num
Specifies the padding above and below the separator line within the separator entry. Defaults to 4 pixels.
-state state
Specifies whether the entry should be active or disabled. Legal values are normal and disabled. Defaults to normal.
-underline integer
Specifies the character in the label which should be underlined. For example, if the label is "File" and the underline option is 1, then 'i' will be underlined. This is used for keyboard traversal. Defaults to -1 (no character underlined).
-variable varName
Specifies the name of the Tcl variable associated with the entry. For checkbutton and radiobutton entries, this variable holds the entry's state (0 or 1 for checkbuttons, the value specified by -discriminator for radiobuttons). For command entries, this variable is set to 1 when the entry is invoked, and 0 when it is not. For cascade entries, this variable is set to 1 when the cascade menu is posted, and 0 when it is unposted.
-visa image
Specifies an image to display in the entry. This is mutually exclusive with the -bitmap option. The image may be a bitmap or a photo image.

CHECKBUTTON AND RADIOBUTTON ENTRIES

A checkbutton entry displays a small box to its left. If the box is checked, the entry is considered selected. A radiobutton entry displays a small diamond to its left. If the diamond is filled in, the entry is considered selected. Radiobutton entries are always grouped: selecting one radiobutton entry automatically deselects any other selected entry in the same group. Grouping is determined by the value of the -variable option: if two or more entries share the same variable name, they belong to the same group. An entry is initially selected if its associated variable matches its -discriminator value (for radiobuttons) or is non-zero (for checkbuttons). The -default option can also be used to specify the initial state (see -default option). Once an entry has become selected, any change to the entry's associated variable will cause the entry to deselect itself. If a -command option is specified for a checkbutton or radiobutton entry, then its value is evaluated as a Tcl command each time the entry is invoked; this happens after changing the state of the entry.

CASCADE ENTRIES

A cascade entry is one with an associated menu (determined by the -menu option). Cascade entries allow the construction of cascading menus. The postcascade widget command can be used to post and unpost the associated menu just next to of the cascade entry. The associated menu must be a child of the menu containing the cascade entry (this is needed in order for menu traversal to work correctly).

A cascade entry posts its associated menu by invoking a Tcl command of the form

menu post x y
where menu is the path name of the associated menu, and x and y are the root-window coordinates of the upper-right corner of the cascade entry. On Unix, the lower-level menu is unposted by executing a Tcl command with the form 
menu unpost
where menu is the name of the associated menu. On other platforms, the platform's native code takes care of unposting the menu.

If a -command option is specified for a cascade entry then it is evaluated as a Tcl command whenever the entry is invoked. This is not supported on Windows.

TEAR-OFF ENTRIES

A tear-off entry appears at the top of the menu if enabled with the -tearoff option. It is not like other menu entries in that it cannot be created with the add widget command and cannot be deleted with the delete widget command. When a tear-off entry is created it appears as a dashed line at the top of the menu. Under the default bindings, invoking the tear-off entry causes a torn-off copy to be made of the menu and all of its submenus.

MENUBARS

Any menu can be set as a menubar for a toplevel window (see toplevel command for syntax). On the Macintosh, whenever the toplevel is in front, this menu's cascade items will appear in the menubar across the top of the main monitor. On Windows and Unix, this menu's items will be displayed in a menubar across the top of the window. These menus will behave according to the interface guidelines of their platforms. For every menu set as a menubar, a clone menu is made. See the CLONES section for more information.

As noted, menubars may behave differently on different platforms. One example of this concerns the handling of checkbuttons and radiobuttons within the menu. While it is permitted to put these menu elements on menubars, they may not be drawn with indicators on some platforms, due to system restrictions.

SPECIAL MENUS IN MENUBARS

Certain menus in a menubar will be treated specially. On the Macintosh, access to the special Application, Window and Help menus is provided. On Windows, access to the Windows System menu in each window is provided. On X Windows, a special right-justified help menu may be provided if Motif menu compatibility is enabled. In all cases, these menus must be created with the command name of the menubar menu concatenated with the special name. So for a menubar named .menubar, on the Macintosh, the special menus would be .menubar.apple, .menubar.window and .menubar.help; on Windows, the special menu would be .menubar.system; on X Windows, the help menu would be .menubar.help.

When Tk sees a .menubar.apple menu as the first menu in a menubar on the Macintosh, that menu's contents make up the first items of the Application menu whenever the window containing the menubar is in front. After all of the Tk-defined items, the menu will have a separator, followed by all standard Application menu items. Such a .apple menu must be present in a menu when that menu is first configured as a toplevel's menubar, otherwise a default application menu (hidden from Tk) will be inserted into the menubar at that time and subsequent addition of a .apple menu will no longer result in it becoming the Application menu.

When Tk sees a .menubar.window menu on the Macintosh, the menu's contents are inserted into the standard Window menu of the user's menubar whenever the window's menubar is in front. The first items in the menu are provided by macOS, and the names of the current toplevels are automatically appended after all the Tk-defined items and a separator. The Window menu on the Mac also allows toggling the window into a fullscreen state, and managing a tabbed window interface (multiple windows grouped into a single window) if supported by that version of the operating system.

When Tk sees a .menubar.help menu on the Macintosh, the menu's contents are appended to the standard Help menu of the user's menubar whenever the window's menubar is in front. The first items in the menu are provided by macOS.

When Tk sees a System menu on Windows, its items are appended to the system menu that the menubar is attached to. This menu is tied to the application icon and can be invoked with the mouse or by typing Alt+Spacebar. Due to limitations in the Windows API, any font changes, colors, images, bitmaps, or tearoff images will not appear in the system menu.

When Tk sees a Help menu on X Windows and Motif menu compatibility is enabled the menu is moved to be last in the menubar and is right justified. Motif menu compatibility is enabled by setting the Tk option *Menu.useMotifHelp to true or by calling tk::classic::restore menu.

CLONES

When a menu is set as a menubar for a toplevel window, or when a menu is torn off, a clone of the menu is made. This clone is a menu widget in its own right, but it is a child of the original. Changes in the configuration of the original are reflected in the clone. Additionally, any cascades that are pointed to are also cloned so that menu traversal will work right. Clones are destroyed when either the tearoff or menubar goes away, or when the original menu is destroyed.

WIDGET COMMAND

The menu command creates a new Tcl command whose name is pathName. This command may be used to invoke various operations on the widget. It has the following general form:

pathName option ?arg arg ...?
Option and the args determine the exact behavior of the command.

Many of the widget commands for a menu take as one argument an indicator of which entry of the menu to operate on. These indicators are called indexes and may be specified in any of the following forms:

active
Indicates the entry that is currently active. If no entry is active then this form is equivalent to none. This form may not be abbreviated.
end
Indicates the bottommost entry in the menu. If there are no entries in the menu then this form is equivalent to none. This form may not be abbreviated.
last
Same as end.
none
Indicates “no entry at all”; this is used most commonly with the activate option to deactivate all the entries in the menu. In most cases the specification of none causes nothing to happen in the widget command. This form may not be abbreviated.
@x,y
Indicates the entry that covers the point in the menu's window specified by x and y (in pixel coordinates). If no entry covers that point, then this form is equivalent to none. If only a single number is specified, it is treated as the y-coordinate.
number
Specifies the entry numerically, where 0 corresponds to the top-most entry of the menu, 1 to the entry below it, and so on.
pattern
If the index does not satisfy one of the above forms then this form is used. Pattern is pattern-matched against the label of each entry in the menu, in order from the top down, until a matching entry is found. The rules of string match are used.

If the index could match more than one of the above forms, then the form earlier in the above list takes precedence.

The following widget commands are possible for menu widgets:

pathName activate index
Change the state of the entry indicated by index to active and redisplay it using its active colors. Any previously-active entry is deactivated. If index is specified as none, or if the specified entry is disabled, then the menu ends up with no active entry. Returns an empty string.
pathName add type ?option value option value ...?
Add a new entry to the bottom of the menu. The new entry's type is given by type and must be one of cascade, checkbutton, command, radiobutton, or separator, or a unique abbreviation of one of the above. If additional arguments are present, they specify the options listed in the MENU ENTRY OPTIONS section below. The add widget command returns an empty string.
pathName cget option
Returns the current value of the configuration option given by option. Option may have any of the values listed in the OPTIONS section. The command returns an empty string if the option is not recognized.
pathName delete firstIndex ?lastIndex?
Delete one or more entries from the menu. FirstIndex indicates the first entry to delete, and lastIndex indicates the last entry to delete. If lastIndex is omitted, then only the entry indicated by firstIndex is deleted. Returns an empty string.
pathName entrycget index option
Returns the current value of the configuration option given by option for the entry specified by index. Option may have any of the values listed in the MENU ENTRY OPTIONS section. The command returns an empty string if the option is not recognized.
pathName entryconfigure index ?option value option value ...?
Modify the configuration options for the entry specified by index. The available options are the same as those listed in the MENU ENTRY OPTIONS section. This command returns an empty string.
pathName insert beforeIndex type ?option value option value ...?
Insert a new entry into the menu just before the entry specified by beforeIndex. The new entry's type is given by type and must be one of cascade, checkbutton, command, radiobutton, or separator, or a unique abbreviation of one of the above. If additional arguments are present, they specify the options listed in the MENU ENTRY OPTIONS section below. The insert widget command returns an empty string.
pathName invoke index
Invokes the command associated with the entry specified by index. For command entries, this executes the -command script. For checkbutton and radiobutton entries, this toggles the state of the entry and executes the -command script if one is defined. For cascade entries, this posts the associated menu. Returns the value returned by the invoked command, or an empty string if no command is associated with the entry or if the entry is disabled.
pathName post x y
Displays the menu at the specified screen coordinates x and y. The coordinates are relative to the root window. Returns an empty string.
pathName scan option ?arg?
This command is used to scan through a menu that is too large to fit in the screen. It may be invoked with the following options:
scan mark x
The argument x is a screen coordinate indicating where the scan should begin. This should be called first.
scan dragto x
The argument x is a screen coordinate indicating where the mouse has been dragged to. The menu will scroll up or down to follow the mouse. This should be called after scan mark.
Returns an empty string.
pathName See also
checkbutton, radiobutton, cascade, menu, menubutton, toplevel.
pathName type
Returns the string menu.
pathName unpost
Removes the menu from the screen. Returns an empty string.

COMMANDS

cheminNom add type ?option valeur option valeur ...?
Ajoute une nouvelle entrée au menu. La valeur de type détermine le type d'entrée à ajouter. Les types valides sont cascader, checkbutton, command, radiobutton, separator et tearoff. Pour les types valides cascader, checkbutton, command et radiobutton, le comportement peut être modifié avec les options spécifiées. Les options -accelerator, -bitmap, -command, -font, -foreground, -help, -image, -label, -menu, -selectcolor, -selectimage, -underline et -variable sont décrites plus loin dans la section OPTIONS DES ENTRÉES DE MENU. Les options spécifiques à cascader, checkbutton et radiobutton sont également décrites dans cette section. Le type separator n'accepte aucune option et ajoute une ligne de séparation au menu. Le type tearoff ajoute une entrée de détachement au menu (voir la description de l'option -tearoff pour le widget menu). Si la valeur de l'option -tearoff du menu est 0, alors aucune entrée de détachement ne peut être ajoutée au menu. Sinon, le comportement dépend du nombre d'entrées de détachement déjà présentes dans le menu. Si le menu n'a pas encore d'entrée de détachement, alors une nouvelle est ajoutée à la position spécifiée par index. Si une entrée de détachement existe déjà, alors elle est remplacée. Le résultat de la commande est une chaîne représentant l'index de la nouvelle entrée dans la liste des entrées du menu.
cheminNom cloner nouveauCheminNom ?typeClone?
Crée un clone du menu actuel nommé nouveauCheminNom. Ce clone est un menu à part entière, mais toute modification apportée au clone est répercutée sur le menu d'origine et vice versa. typeClone peut être normal, menubar, ou tearoff. Ne devrait normalement pas être appelée en dehors de la bibliothèque Tk. Voir la section CLONES pour plus d'informations.
cheminNom configure ?option? ?valeur option valeur ...?
Interroge ou modifie les options de configuration du widget. Si aucune option n'est spécifiée, renvoie une liste décrivant toutes les options disponibles pour cheminNom (voir Tk_ConfigureInfo pour des informations sur le format de cette liste). Si une option est spécifiée sans valeur, alors la commande renvoie une liste décrivant l'option nommée (cette liste sera identique à la sous-liste correspondante de la valeur renvoyée si aucune option n'est spécifiée). Si une ou plusieurs paires option-valeur sont spécifiées, alors la commande modifie l'option (les options) du widget donné(es) pour lui attribuer la (les) valeur(s) donnée(s) ; dans ce cas, la commande renvoie une chaîne vide. Option peut avoir l'une des valeurs acceptées par la commande menu.
cheminNom delete index1 ?index2?
Supprime toutes les entrées de menu entre index1 et index2 inclus. Si index2 est omis, il prend la valeur de index1. Les tentatives de suppression d'une entrée de menu détachable sont ignorées (au lieu de cela, vous devriez changer l'option -tearoff pour supprimer l'entrée détachable).
cheminNom entrycget index option
Renvoie la valeur actuelle d'une option de configuration pour l'entrée donnée par index. Option peut avoir l'un des noms décrits dans la section OPTIONS DES ENTRÉES DE MENU ci-dessous.
cheminNom entryconfigure index ?options...?
Cette commande est similaire à la commande configure, sauf qu'elle s'applique aux options d'une entrée individuelle, tandis que configure s'applique aux options du menu dans son ensemble. Options peut avoir l'une des valeurs décrites dans la section OPTIONS DES ENTRÉES DE MENU ci-dessous. Si des options sont spécifiées, les options sont modifiées comme indiqué dans la commande et la commande renvoie une chaîne vide. Si aucune option n'est spécifiée, renvoie une liste décrivant les options actuelles pour l'entrée index (voir Tk_ConfigureInfo pour des informations sur le format de cette liste).
cheminNom index index
Renvoie l'index numérique correspondant à index, ou none si index a été spécifié comme none.
cheminNom insert index type ?option valeur option valeur ...?
Identique à la commande de widget add, sauf qu'elle insère la nouvelle entrée juste avant l'entrée donnée par index, au lieu de l'ajouter à la fin du menu. Le type, l>option, et valeur arguments ont la même interprétation que pour la commande de widget add. Il n'est pas possible d'insérer de nouvelles entrées de menu avant l'entrée détachable, si le menu en possède une.
cheminNom invoke index
Déclenche l'action de l'entrée de menu. Voir les sections sur les entrées individuelles ci-dessus pour les détails sur ce qui se passe. Si l'entrée de menu est désactivée, rien ne se passe. Si l'entrée a une commande associée, le résultat de cette commande est renvoyé comme résultat de la commande de widget invoke. Sinon, le résultat est une chaîne vide. Note : l'appel d'une entrée de menu ne désactive pas automatiquement le menu ; les liaisons par défaut s'en chargent normalement avant d'appeler la commande de widget invoke.
cheminNom post x y ?index?
Organise l'affichage du menu à l'écran aux coordonnées de la fenêtre racine données par x et y. Si un index est spécifié, le menu sera situé de telle sorte que l'entrée avec cet index soit affichée à ce point. Ces coordonnées sont ajustées si nécessaire pour garantir que l'intégralité du menu soit visible à l'écran. Cette commande renvoie normalement une chaîne vide. Si l'option -postcommand a été spécifiée, alors sa valeur est exécutée comme un script Tcl avant de poster le menu et le résultat de ce script est renvoyé comme résultat de la commande de widget post. Si une erreur survient lors de l'exécution de la commande, alors l'erreur est renvoyée sans poster le menu.
cheminNom postcascade index
Affiche le sous-menu associé à l'entrée en cascade donnée par index, et désactive tout sous-menu précédemment affiché. Si index ne correspond pas à une entrée en cascade, ou si cheminNom n'est pas affiché, la commande n'a aucun effet, sauf celui de désactiver tout sous-menu actuellement affiché.
cheminNom type index
Renvoie le type de l'entrée de menu donnée par index. C'est l'argument type passé à la commande de widget add ou insert lors de la création de l'entrée, comme command ou separator, ou tearoff pour une entrée détachable.
cheminNom unpost
Désactive la fenêtre afin qu'elle ne soit plus affichée. Si un menu en cascade de niveau inférieur est affiché, désactive ce menu. Renvoie une chaîne vide. Cette sous-commande ne fonctionne pas sous Windows et Macintosh, car ces plateformes ont leur propre manière de désactiver les menus.
cheminNom xposition index
Renvoie une chaîne décimale donnant la coordonnée x dans la fenêtre du menu du pixel le plus à gauche de l'entrée spécifiée par index.
cheminNom yposition index
Renvoie une chaîne décimale donnant la coordonnée y dans la fenêtre du menu du pixel le plus haut de l'entrée spécifiée par index.

OPTIONS DES ENTRÉES DE MENU

Les options suivantes sont autorisées sur les entrées de menu. La plupart des options ne sont pas prises en charge par tous les types d'entrées.

-activebackground valeur
Spécifie une couleur d'arrière-plan à utiliser pour afficher cette entrée lorsqu'elle est active. Cette option est ignorée sur Aqua/macOS. Si elle est spécifiée comme une chaîne vide (par défaut), alors l'option -activebackground du menu global est utilisée. Si la variable tk_strictMotif a été définie pour demander une conformité stricte à Motif, alors cette option est ignorée et l'option -background est utilisée à sa place. Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-activeforeground valeur
Spécifie une couleur de premier plan à utiliser pour afficher cette entrée lorsqu'elle est active. Cette option est ignorée sur Aqua/macOS. Si cette option est spécifiée comme une chaîne vide (par défaut), alors l'option -activeforeground du menu global est utilisée. Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-accelerator valeur
Spécifie une chaîne à afficher sur le côté droit de l'entrée de menu. Décrit normalement une séquence de touches accélératrices qui peut être utilisée pour déclencher la même fonction que l'entrée de menu. Ceci est une option d'affichage, elle ne définit pas réellement la liaison correspondante (ce qui peut être réalisé en utilisant la commande bind). Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-background valeur
Spécifie une couleur d'arrière-plan à utiliser pour afficher cette entrée lorsqu'elle est dans l'état normal (ni active ni désactivée). Cette option est ignorée sur Aqua/macOS. Si elle est spécifiée comme une chaîne vide (par défaut), alors l'option -background du menu global est utilisée. Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-bitmap valeur
Spécifie un bitmap à afficher dans le menu au lieu d'une étiquette textuelle, sous l'une des formes acceptées par Tk_GetBitmap. Cette option remplace l'option -label (contrôlée par l'option -compound) mais peut être réinitialisée à une chaîne vide pour permettre l'affichage d'une étiquette textuelle. Si une option -image a été spécifiée, elle remplace -bitmap. Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-columnbreak valeur
Lorsque cette option est à zéro, l'entrée apparaît sous l'entrée précédente. Lorsque cette option est à un, l'entrée apparaît en haut d'une nouvelle colonne dans le menu. Cette option est ignorée sur Aqua/macOS, où les menus sont toujours en une seule colonne.
-command valeur
Spécifie une commande Tcl à exécuter lorsque l'entrée de menu est invoquée. Non disponible pour les entrées de type séparateur ou détachable.
-compound valeur
Spécifie si l'entrée de menu doit afficher à la fois une image et du texte, et si oui, où l'image doit être placée par rapport au texte. Les valeurs valides pour cette option sont bottom, center, left, none, right et top. La valeur par défaut est none, ce qui signifie que le bouton affichera soit une image, soit du texte, en fonction des valeurs des options -image et -bitmap.
-font valeur
Spécifie la police à utiliser lors du dessin de l'étiquette ou de la chaîne d'accélérateur dans cette entrée. Si cette option est spécifiée comme une chaîne vide (par défaut), alors l'option -font du menu global est utilisée. Cette option n'est pas disponible pour les entrées de type séparateur ou détachable.
-foreground valeur
Spécifie une couleur de premier plan à utiliser pour afficher cette entr
try when it is in the normal state (neither active nor disabled). This option is ignored on Aqua/macOS. If it is specified as an empty string (the default), then the -foreground option for the overall menu is used. This option is not available for separator or tear-off entries.
-hidemargin value
Spécifie si les marges standard doivent être dessinées pour cette entrée de menu. Ceci est utile lors de la création de palettes avec des images, c'est-à-dire des palettes de couleurs, des palettes de motifs, etc. 1 indique que la marge pour l'entrée est masquée ; 0 signifie que la marge est utilisée.
-image value
Spécifie une image à afficher dans le menu au lieu d'une chaîne de caractères ou d'un bitmap. L'image doit avoir été créée par une invocation précédente de image create. Cette option remplace les options -label et -bitmap (tel que contrôlé par l'option -compound) mais peut être réinitialisée à une chaîne vide pour permettre l'affichage d'une étiquette textuelle ou bitmap. Cette option n'est pas disponible pour les entrées séparateur ou détachable.
-indicatoron value
Disponible uniquement pour les entrées de type case à cocher (checkbutton) et bouton radio (radiobutton). Value est une valeur booléenne qui détermine si l'indicateur doit être affiché ou non.
-label value
Spécifie une chaîne de caractères à afficher comme étiquette d'identification dans l'entrée du menu. Non disponible pour les entrées séparateur ou détachable.
-menu value
Disponible uniquement pour les entrées de cascade. Spécifie le nom du chemin du sous-menu associé à cette entrée. Le sous-menu doit être un enfant du menu.
-offvalue value
Disponible uniquement pour les entrées de type case à cocher. Spécifie la valeur à stocker dans la variable associée à l'entrée lorsque l'entrée est désélectionnée.
-onvalue value
Disponible uniquement pour les entrées de type case à cocher. Spécifie la valeur à stocker dans la variable associée à l'entrée lorsque l'entrée est sélectionnée.
-selectcolor value
Disponible uniquement pour les entrées de type case à cocher et bouton radio. Spécifie la couleur à afficher dans l'indicateur lorsque l'entrée est sélectionnée. Si la valeur est une chaîne vide (par défaut), alors l'option -selectcolor du menu détermine la couleur de l'indicateur.
-selectimage value
Disponible uniquement pour les entrées de type case à cocher et bouton radio. Spécifie une image à afficher dans l'entrée (à la place de l'option -image) lorsqu'elle est sélectionnée. Value est le nom d'une image, qui doit avoir été créée par une invocation précédente de image create. Cette option est ignorée à moins que l'option -image n'ait été spécifiée.
-state value
Spécifie l'un des trois états pour l'entrée : normal, active, ou disabled. En état normal, l'entrée est affichée en utilisant l'option -foreground pour le menu et l'option -background de l'entrée ou du menu. L'état actif est généralement utilisé lorsque le pointeur se trouve sur l'entrée. En état actif, l'entrée est affichée en utilisant l'option -activeforeground pour le menu ainsi que l'option -activebackground de l'entrée. L'état désactivé signifie que l'entrée doit être insensible : les liaisons par défaut refuseront d'activer ou d'invoquer l'entrée. Dans cet état, l'entrée est affichée selon l'option -disabledforeground pour le menu et l'option -background de l'entrée. Cette option n'est pas disponible pour les entrées séparateur.
-underline value
Spécifie l'index entier d'un caractère à souligner dans l'entrée. Cette option est également interrogée par les liaisons par défaut et utilisée pour implémenter la navigation au clavier. 0 correspond au premier caractère du texte affiché dans l'entrée, 1 au caractère suivant, et ainsi de suite. Si un bitmap ou une image est affiché dans l'entrée, cette option est ignorée. Cette option n'est pas disponible pour les entrées séparateur ou détachable.
-value value
Disponible uniquement pour les entrées de bouton radio. Spécifie la valeur à stocker dans la variable associée à l'entrée lorsque l'entrée est sélectionnée. Si une chaîne vide est spécifiée, alors l'option -label de l'entrée est utilisée comme valeur à stocker dans la variable.
-variable value
Disponible uniquement pour les entrées de type case à cocher et bouton radio. Spécifie le nom d'une variable globale à définir lorsque l'entrée est sélectionnée. Pour les entrées de type case à cocher, la variable est également définie lorsque l'entrée est désélectionnée. Pour les entrées de bouton radio, la modification de la variable entraîne la désélection de l'entrée actuellement sélectionnée.

Pour les entrées de type case à cocher, la valeur par défaut de cette option est prise à partir de l'option -label, et pour les entrées de bouton radio, une seule valeur fixe est utilisée. Il est recommandé de toujours définir l'option -variable lors de la création d'une case à cocher ou d'un bouton radio.

CONFIGURATIONS DU MENU

Les liaisons par défaut prennent en charge quatre façons différentes d'utiliser les menus :

Menus déroulants dans la barre de menu
C'est le cas le plus courant. Vous créez un widget menu qui deviendra la barre de menu. Vous ajoutez ensuite des entrées de cascade à ce menu, en spécifiant les menus déroulants que vous souhaitez utiliser dans votre barre de menu. Vous créez ensuite tous les menus déroulants. Une fois cela fait, spécifiez le menu à l'aide de l'option -menu de la commande widget du toplevel. Voir l'entrée du manuel toplevel pour plus de détails.
Menus déroulants dans les boutons de menu
C'est la manière compatible de faire des barres de menu. Vous créez un widget menubutton pour chaque menu de niveau supérieur, et généralement vous disposez une série de menubuttons en ligne dans une fenêtre de barre de menu. Vous créez également les menus de niveau supérieur et tous les sous-menus en cascade, et vous les reliez avec les options -menu dans les menubuttons et les entrées de menu de cascade. Le menu de niveau supérieur doit être un enfant du menubutton, et chaque sous-menu doit être un enfant du menu qui y fait référence. Une fois cela fait, les liaisons par défaut permettront aux utilisateurs de parcourir et d'invoquer l'arborescence des menus via son menubutton ; voir l'entrée du manuel menubutton pour plus de détails.
Menus contextuels
Les menus contextuels s'affichent généralement en réponse à un clic de bouton de souris ou à une combinaison de touches. Vous créez les menus contextuels et tous les sous-menus en cascade, puis vous appelez la procédure tk_popup au moment approprié pour afficher le menu de niveau supérieur.
Menus d'options
Un menu d'options consiste en un menubutton avec un menu associé qui vous permet de sélectionner l'une des plusieurs valeurs. La valeur actuelle est affichée dans le menubutton et est également stockée dans une variable globale. Utilisez la procédure tk_optionMenu pour créer des menubuttons d'options et leurs menus.
Menus détachables
Vous créez un menu détachable en invoquant l'entrée détachable en haut d'un menu existant. Les liaisons par défaut créeront un nouveau menu qui est une copie du menu original et le laisseront affiché en permanence comme une fenêtre de niveau supérieur. Le menu détachable se comporte exactement comme le menu original.

LIAISONS PAR DÉFAUT

Tk crée automatiquement des liaisons de classe pour les menus qui leur donnent le comportement par défaut suivant :

[1]
Lorsque la souris entre dans un menu, l'entrée sous le curseur de la souris s'active ; lorsque la souris se déplace sur le menu, l'entrée active change pour suivre la souris.
[2]
Lorsque la souris quitte un menu, toutes les entrées du menu se désactivent, sauf dans le cas spécial où la souris se déplace d'un menu vers un sous-menu en cascade.
[3]
Lorsqu'un bouton est relâché sur un menu, l'entrée active (le cas échéant) est invoquée. Le menu se ferme également à moins qu'il ne s'agisse d'un menu détachable.
[4]
Les touches Espace et Entrée invoquent l'entrée active et ferment le menu.
[5]
Si l'une des entrées d'un menu a des lettres soulignées avec l'option -underline, alors la pression de l'une des lettres soulignées (ou son équivalent majuscule ou minuscule) invoque cette entrée et ferme le menu.
[6]
La touche Échap annule une sélection de menu en cours sans invoquer d'entrée. Elle ferme également le menu à moins qu'il ne s'agisse d'un menu détachable.
[7]
Les touches Haut et Bas activent l'entrée immédiatement supérieure ou inférieure dans le menu. Lorsqu'une extrémité du menu est atteinte, l'entrée active revient à l'autre extrémité.
[8]
La touche Gauche se déplace vers le menu suivant à gauche. Si le menu actuel est un sous-menu en cascade, alors le sous-menu est fermé et l'entrée de menu actuelle devient l'entrée de cascade dans le parent. Si le menu actuel est un menu de niveau supérieur affiché à partir d'un menubutton, alors le menubutton actuel est fermé et le menubutton suivant à gauche est affiché. Sinon, la touche n'a aucun effet. L'ordre gauche-droite des menubuttons est déterminé par leur ordre d'empilement : Tk suppose que le menubutton le plus bas (qui par défaut est le premier créé) est à gauche.
[9]
La touche Droite se déplace vers le menu suivant à droite. Si l'entrée actuelle est une entrée en cascade, alors le sous-menu est affiché et l'entrée de menu actuelle devient la première entrée du sous-menu. Sinon, si le menu actuel a été affiché à partir d'un menubutton, alors le menubutton actuel est fermé et le menubutton suivant à droite est affiché.

Les entrées de menu désactivées sont insensibles : elles ne s'activent pas et ignorent les pressions et les relâchements de boutons de souris.

Plusieurs des liaisons utilisent la commande tk_menuSetFocus. Elle enregistre le focus actuel et définit le focus sur son argument pathName, qui est un widget menu.

Le comportement des menus peut être modifié en définissant de nouvelles liaisons pour des widgets individuels ou en redéfinissant les liaisons de classe.

tk_menuSetFocus(n) — Tk 8.6 Manual Page

NAME

tk_menuSetFocus - Set the focus to a menu widget

SYNOPSIS

tk_menuSetFocus menu

DESCRIPTION

The tk_menuSetFocus command sets the input focus to the specified Tk widget, which must be a menu widget.

This command is intended to be used in conjunction with keyboard navigation bindings for menus. For example, when a menu is popped up, you might want to set the focus to the menu so that the user can immediately start navigating it with the arrow keys.

This command has no effect if the specified widget does not currently have focus.

EXAMPLE

set menubar [menu .menubar]
. configure -menu $menubar
set filemenu [$menubar add cascade -label {File} -menu .filemenu]
set file_popup [menu .filemenu]
$filemenu configure -menu $file_popup
$file_popup add command -label {Open} -command {puts "Open clicked"}
$file_popup add command -label {Save} -command {puts "Save clicked"}
.bind <<ShowMenu>> {
    tk_menuSetFocus .filemenu
}

SEE ALSO

bind(n), ttk::menu(n)

KEYWORDS

menu, focus, keyboard

This command is a convenience wrapper around the Tk core function that sets the focus to a widget. It is not intended to be called directly by application code, but rather by Tk itself or by code that is implementing menu-related behavior.

The command also handles the case where the menu is already a submenu of another menu. In this situation, it will ensure that the focus is set correctly to the menu that was just popped up.

Consider using the standard Tk focus commands if you need more control over focus management.

The tk_menuOptionSet(n) command can be used to specify values for the options to individual entries.
