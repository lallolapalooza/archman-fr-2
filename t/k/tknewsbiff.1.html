TKNEWSBIFF(1) Manuel des commandes générales TKNEWSBIFF(1)

NOM

tknewsbiff - afficher une fenêtre lorsqu'il y a de nouvelles actualités

SYNTAXE

tknewsbiff [ serveur ou fichier-de-configuration ]

INTRODUCTION

tknewsbiff affiche une fenêtre lorsqu'il y a des actualités non lues dans vos groupes de discussion favoris et supprime la fenêtre une fois que vous avez lu les actualités. tknewsbiff peut éventuellement jouer un son, démarrer votre lecteur de news, etc.

SLECTION DES GROUPES DE DISCUSSION

Par défaut, le fichier de configuration ~/.tknewsbiff décrit le comportement de tknewsbiff. La syntaxe respecte les règles Tcl habituelles - cependant, même si vous ne connaissez pas Tcl, toutes les configurations, à l'exception des plus ésotériques, seront évidentes.

Chaque groupe de discussion (ou ensemble de groupes de discussion) à surveiller est décrit à l'aide de la commande "watch". Par exemple :

watch dc.dining
watch nist.*
watch comp.unix.wizard  -threshold 3
watch *.sources.*       -threshold 20

Pour chaque motif de groupe de discussion, tout groupe de discussion qui correspond et auquel vous êtes abonné (selon votre fichier newsrc) est éligible à être signalé. Par défaut, tknewsbiff signale le groupe de discussion s'il y a au moins un article non lu. L'indicateur "-threshold" modifie le seuil au nombre suivant. Par exemple, "-threshold 3" signifie qu'il doit y avoir au moins trois articles non lus avant que tknewsbiff ne signale le groupe de discussion.

Si aucune commande watch n'est donnée (ou si aucun fichier de configuration n'existe), tous les groupes auxquels vous êtes abonné sont surveillés.

Pour supprimer des groupes de discussion qui seraient autrement signalés, utilisez la commande "ignore". Par exemple, ce qui suit correspond à tous les groupes comp.* et nist.* sauf les groupes nist.posix ou .d (discussion) :

watch comp.*
watch nist.*
ignore nist.posix.*
ignore *.d

L'indicateur "-new" décrit une commande à exécuter lorsque le groupe de discussion est signalé pour la première fois comme ayant des nouvelles non lues. Par exemple, les lignes suivantes invoquent la commande UNIX "play" pour jouer un son.

watch dc.dining -new "exec play /usr/local/sounds/yumyum.au"
watch rec.auto* -new "exec play /usr/local/sounds/vroom.au"

Vous pouvez réduire la verbosité des actions en définissant des procédures. Par exemple, si vous avez de nombreux indicateurs -new qui jouent tous des fichiers sonores, vous pourriez définir une procédure sonore. Cela permettrait à la spécification -new d'être beaucoup plus courte.

proc play {sound} {
	exec play /usr/local/sounds/$sound.au
}
watch dc.dining -new "play yumyum"
watch rec.auto* -new "play vroom"

Soit dit en passant, vous pouvez ajouter un "&" à la fin d'une commande "exec" pour exécuter les commandes de manière asynchrone. Cependant, il n'est probablement pas judicieux de le faire lorsque vous jouez des fichiers sonores de toute façon.

"newsgroup" est une variable en lecture seule qui contient le nom du groupe de discussion signalé. Ceci est utile lorsque l'action est déclenchée par un motif. Par exemple, la ligne suivante pourrait faire passer le nom du groupe de discussion par un synthétiseur vocal :

watch * -new {
	exec play herald.au
	exec speak "Nouvelles actualités arrivées dans $newsgroup."
}

L'indicateur "-display" décrit une commande à exécuter chaque fois que le groupe de discussion est signalé comme ayant des nouvelles non lues. La commande spéciale "display" est la commande par défaut. Elle planifie l'écriture de $newsgroup dans l'affichage de tknewsbiff lors de sa réécriture. Par exemple, en fournissant explicitement un indicateur -display qui omet la commande display, vous pouvez désactiver l'affichage des groupes de discussion qui sont déjà signalés via -new.

watch dc.dining -new {exec play yumyum.au} -display {}

Si vous souhaitez exécuter une action de manière répétée et toujours afficher le groupe de discussion de la manière par défaut, invoquez explicitement la commande display via l'indicateur -display. Par exemple :

watch *security* -display {
	exec play red-alert.au
	display
}

Les actions associées aux indicateurs -new et -display sont exécutées une seule fois pour chaque groupe de discussion correspondant. La commande exécutée est celle associée au premier motif du fichier de configuration qui correspond et respecte le seuil donné.

Toute commande simplement listée dans le fichier de configuration est exécutée à chaque fois avant la boucle de mise à jour dans tknewsbiff. La procédure réservée (mais définie par l'utilisateur) "user" est exécutée immédiatement après que les groupes de discussion sont programmés pour être écrits dans l'affichage et avant qu'ils ne soient effectivement écrits.

Par exemple, supposons que des articles non lus apparaissent dans plusieurs groupes rec.auto et que vous jouiez le même son pour chacun d'eux. Pour éviter de jouer le son plusieurs fois de suite, faites en sorte que la commande -new définisse simplement un indicateur. Dans la procédure user, jouez le son si l'indicateur est défini (et réinitialisez ensuite l'indicateur).

La procédure user pourrait également être utilisée pour démarrer un lecteur de news. Cela éviterait la possibilité de démarrer plusieurs lecteurs de news simplement parce que plusieurs groupes de discussion contenaient des articles non lus. (Une vérification devrait, bien sûr, être effectuée pour s'assurer qu'un lecteur de news n'est pas déjà en cours d'exécution.)

PLUS DE VARIABLES

Les lignes d'exemple suivantes montrent des variables qui peuvent affecter le comportement de tknewsbiff

set delay          120
set server         news.nist.gov
set server_timeout 60
set newsrc         ~/.newsrc
set width          40
set height         20
set active_file    /usr/news/lib/active

tknewsbiff alterne entre la vérification des nouvelles non lues et le sommeil (un peu comme de nombreux étudiants). La variable "delay" décrit le nombre de secondes à attendre.

La variable "server" nomme un serveur de news NNTP. La valeur par défaut est "news". La variable "server" n'est utilisée que si la variable "active_file" n'est pas définie.

La variable "server_timeout" décrit combien de secondes attendre une réponse du serveur avant d'abandonner. -1 signifie attendre indéfiniment ou jusqu'à ce que le serveur lui-même expire. La valeur par défaut est 60 secondes.

La variable "newsrc" décrit le nom de votre fichier .newsrc. Par défaut, tknewsbiff cherche dans votre répertoire personnel un fichier newsrc. Un newsrc spécifique au serveur est utilisé s'il est trouvé. Par exemple, si vous avez défini le serveur sur "cubit.nist.gov", alors tknewsbiff recherche ~/.newsrc-cubit.nist.gov. (Ceci est la convention gnus d'Emacs - ce qui est très pratique lorsque vous lisez des news depuis plusieurs serveurs.) S'il n'y a pas de newsrc spécifique au serveur, tknewsbiff utilise ~/.newsrc.

La variable "width" décrit la largeur que tknewsbiff utilisera pour afficher les informations. Si certains noms de groupes de discussion sont suffisamment longs, ils seront tronqués afin que les décomptes d'articles puissent toujours être affichés. Vous pouvez redimensionner manuellement la fenêtre pour voir ce qui a été tronqué. Cependant, si votre fichier de configuration définit la variable width, la fenêtre sera restaurée à cette taille la prochaine fois que tknewsbiff vérifiera les nouvelles non lues et mettra à jour son affichage.

La variable "height" décrit la hauteur maximale que tknewsbiff utilisera pour afficher les informations. Si moins de groupes de discussion sont signalés, tknewsbiff réduira la fenêtre de manière appropriée. Vous pouvez redimensionner manuellement la fenêtre, mais si votre fichier de configuration définit la variable height, la fenêtre sera restaurée à cette taille la prochaine fois que tknewsbiff vérifiera les nouvelles non lues et mettra à jour son affichage.

La variable "active_file" décrit le nom du fichier d'activité des news. Si elle est définie, le fichier d'activité est lu directement de préférence à l'utilisation de NNTP (même si la variable "server" est définie). Ceci est particulièrement utile pour tester de nouveaux fichiers de configuration car vous pouvez modifier un faux fichier d'activité et ensuite cliquer sur le bouton 2 pour voir immédiatement comment tknewsbiff répond (voir BOUTONS ci-dessous).

Si la variable d'environnement DOTDIR est définie, alors sa valeur est utilisée comme répertoire dans lequel trouver tous les fichiers ponctuels au lieu du répertoire personnel. En particulier, cela affecte le fichier de configuration tknewsbiff et le fichier .newsrc (en supposant que la variable newsrc n'est pas explicitement définie).

SURVEILLER DIFFÉRENTS SERVEURS DE NEWS

Pour surveiller plusieurs serveurs, exécutez tknewsbiff plusieurs fois. (Puisque vous avez besoin de fichiers .newsrc différents et que les serveurs ont des groupes de discussion et des numéros d'articles différents de toute façon, il est inutile d'essayer de faire cela en un seul processus.)

Vous pouvez indiquer à tknewsbiff un serveur différent avec un argument approprié. L'argument est essayé à la fois comme nom de fichier de configuration et comme suffixe de la chaîne "~/.tknewsbiff-". tknewsbiff(1) - Page de manuel

NOM

tknewsbiff - Afficheur d'actualités NNTP pour Tk

SYNTAXE

tknewsbiff [configuration_file | serveur] [options]

INTRODUCTION

tknewsbiff est un programme qui surveille les nouvelles sur un serveur NNTP et vous informe lorsqu'il y a de nouvelles actualités. Il utilise la bibliothèque Tk pour son interface utilisateur. L'apparence de tknewsbiff peut être modifiée en utilisant la base de données de ressources X et en utilisant un fichier de configuration. Ce dernier est décrit plus en détail dans la section CONFIGURATION.

SÉLECTION DES GROUPES DE NOUVELLES

tknewsbiff sélectionne les groupes de nouvelles à surveiller en lisant le fichier ~/.newsrc. Les groupes qui n'y sont pas répertoriés sont considérés comme inconnus. Le programme utilise le fichier active pour déterminer quels groupes sont réellement sur le serveur. tknewsbiff ne traitera que les groupes qui apparaissent à la fois dans ~/.newsrc et dans le fichier active.

La liste des groupes de nouvelles auxquels vous êtes abonné est supposée être stockée dans votre fichier ~/.newsrc. Le programme suppose que ce fichier est mis à jour par votre lecteur de nouvelles habituel.

Si vous souhaitez que tknewsbiff surveille des groupes de nouvelles qui ne sont pas répertoriés dans votre fichier ~/.newsrc, vous pouvez explicitement les ajouter à la liste watch_list dans votre fichier de configuration. Par exemple, pour surveiller les groupes alt.sources.newsgroups et comp.sources.unix, vous pouvez ajouter les lignes suivantes à votre fichier de configuration :

watch alt.sources.newsgroups
watch comp.sources.unix

Si vous voulez spécifier les groupes qui doivent être ignorés, utilisez la commande ignore. Par exemple, pour ignorer tous les groupes commençant par comp.mail :

ignore comp.mail.*

Si vous souhaitez voir uniquement les nouvelles dans les groupes que vous spécifiez, vous pouvez utiliser le modèle de correspondance le plus restrictif possible.

Par défaut, tknewsbiff surveille tous les groupes auxquels vous êtes abonné et qui sont répertoriés dans le fichier active. Vous pouvez modifier ce comportement en spécifiant un fichier de configuration ou un serveur différent.

PLUS DE VARIABLES

Voici quelques variables supplémentaires que vous pouvez utiliser dans votre fichier de configuration.

update
Ceci spécifie l'intervalle, en secondes, entre les vérifications des nouvelles. La valeur par défaut est 60.
server
Ceci spécifie le serveur NNTP à contacter. La valeur par défaut est news.server. Si cette variable n'est pas définie, tknewsbiff tentera de deviner le serveur à partir de la variable d'environnement NNTPSERVER. Si cela échoue également, le programme ne fonctionnera pas.
display
Si cette variable est définie sur 0, la fenêtre d'affichage des nouvelles n'apparaîtra pas. Par défaut, elle est définie sur 1.
display_list
Une liste des groupes de nouvelles affichés dans la fenêtre. Ce n'est pas une variable qui peut être définie par l'utilisateur, mais plutôt une variable utilisée en interne par tknewsbiff. Elle est cependant accessible pour être utilisée dans des commandes lier.
active_file
Le nom du fichier actif. Par défaut, il est lu à partir du serveur NNTP. Si vous fournissez un nom de fichier, tknewsbiff le lira à partir de ce fichier.

SURVEILLER DIFFÉRENTS SERVEURS DE NOUVELLES

La commande tknewsbiff peut être appelée avec un argument qui spécifie un fichier de configuration ou un serveur. Ceci est utile si vous souhaitez surveiller plusieurs serveurs de nouvelles simultanément, chacun avec sa propre configuration.

Par exemple, si vous avez un fichier de configuration nommé ~/.tknewsbiff-kidney, les deux commandes suivantes utiliseront ce fichier de configuration.

tknewsbiff kidney
tknewsbiff ~/.tknewsbiff-kidney

Dans les deux cas, le serveur réel à contacter est défini par la valeur de la variable server dans le fichier de configuration.

Si aucun fichier de configuration n'est trouvé, l'argument est utilisé comme serveur à contacter. Cela permet à tknewsbiff d'être exécuté sans aucune préparation.

Si l'argument est le mot-clé spécial active (ou se termine par /active), il est utilisé comme nom d'un fichier actif. Ceci est ensuite utilisé pour initialiser la variable active_file afin que tknewsbiff lise directement à partir du fichier actif plutôt que d'utiliser NNTP.

Créer votre propre fichier actif est un moyen pratique de tester votre fichier de configuration. Par exemple, après avoir exécuté la commande suivante, vous pouvez éditer votre fichier actif de manière répétée et déclencher la commande update-now (en appuyant sur le bouton 2 ou en définissant la variable delay très bas) pour voir comment tknewsbiff répond.

Le fichier actif doit suivre le format d'un vrai fichier actif. Le format est un groupe de nouvelles par ligne. Après le nom du groupe de nouvelles se trouve le numéro de l'article le plus élevé, le numéro de l'article le plus bas. Enfin, il y a la lettre y ou m. m signifie que le groupe de nouvelles est modéré. y signifie que la publication est autorisée.

FENÊTRE

Lorsque des nouvelles non lues sont trouvées, une fenêtre apparaît. La fenêtre liste les noms des groupes de nouvelles et le nombre d'articles non lus dans chacun (sauf si supprimé par le drapeau -display). Lorsqu'il n'y a plus de nouvelles non lues, la fenêtre disparaît (bien que le processus continue de s'exécuter).

BOUTONS

Les liaisons de boutons ou de touches peuvent être assignées par des commandes bind. N'hésitez pas à les modifier. Les commandes bind par défaut sont :

bind .list <1> help
bind .list <2> update-now
bind .list <3> unmapwindow

Par défaut, le bouton 1 (gauche) est lié à help. La commande help fait apparaître une fenêtre d'aide de tknewsbiff.

Par défaut, le bouton 2 (milieu) est lié à update-now. La commande update-now fait en sorte que tknewsbiff vérifie immédiatement les nouvelles non lues. Si votre serveur de nouvelles est lent ou maintient un très grand nombre de groupes de nouvelles, ou si vous avez un grand nombre de modèles dans votre fichier de configuration, tknewsbiff peut prendre un temps considérable avant de mettre à jour la fenêtre.

Par défaut, le bouton 3 (droite) est lié à unmapwindow. La commande unmapwindow fait disparaître la fenêtre de l'affichage jusqu'à la prochaine fois qu'elle trouvera des nouvelles non lues. (La commande mapwindow fait restaurer la fenêtre par tknewsbiff.)

À titre d'exemple, voici une liaison pour faire apparaître un xterm et exécuter rn lorsque vous maintenez la touche Maj enfoncée et appuyez sur le bouton 1 dans la fenêtre de liste.

bind .list <Shift-1> {
	exec xterm -e rn &
}

Voici une liaison similaire. Cependant, elle indique à rn de regarder uniquement le groupe de nouvelles qui se trouve sous la souris lorsque vous l'avez pressée. (La variable display_list est décrite plus loin dans cette page de manuel.)

bind .list <Shift-1> {
	exec xterm -e rn [lindex $display_list [.list nearest %y]] &
}

AUTRES COMMANDES ET VARIABLES

Les commandes intégrées déjà mentionnées sont : watch, ignore, display, help, update-now, unmapwindow, et mapwindow.

Toute commande Tcl et Tk peut également être donnée. En particulier, la liste des groupes de nouvelles est stockée dans le widget de liste .list, et la barre de défilement est stockée dans le widget de barre de défilement .scroll. Ainsi, par exemple, si vous souhaitez modifier les couleurs de premier plan et d'arrière-plan de la liste des groupes de nouvelles, vous pouvez dire :

.list config -bg honeydew1 -fg orchid2

Celles-ci peuvent également être contrôlées par la base de données de ressources X. Cependant, le fichier de configuration permet des commandes arbitrairement complexes à évaluer plutôt que de simples affectations.

Certaines commandes Tcl/Tk peuvent perturber le bon fonctionnement de tknewsbiff. Celles-ci seront probablement évidentes pour quiconque connaît suffisamment pour donner ces commandes en premier lieu. À titre de simple exemple, le programme suppose que la police de la boîte de liste est à largeur fixe. Les groupes de nouvelles ne s'aligneront probablement pas si vous utilisez une police à largeur variable.

Les variables suivantes sont accessibles et peuvent être utilisées à des fins ésotériques. Toutes les autres variables sont privées. Les variables et commandes privées commencent par _ vous n'avez donc pas à vous soucier des collisions accidentelles.

Le tableau db est une base de données qui maintient des informations sur les nouvelles lues et non lues. db($newsgroup,hi) est l'article le plus élevé qui existe. db($newsgroup,seen) est l'article le plus élevé que vous avez lu.

Un certain nombre de listes maintiennent des informations intéressantes. active_list est une liste de groupes de nouvelles connus. seen_list est une liste de groupes de nouvelles qui ont été vus jusqu'à présent pendant le traitement des drapeaux -new et -display. previous_seen_list est seen_list du cycle précédent. ignore_list est la liste des modèles de groupes de nouvelles à ignorer. watch_list est la liste des modèles de groupes de nouvelles à surveiller. display_list est la liste des groupes de nouvelles qui seront affichés à la prochaine occasion.

MISE À JOUR DE VOS FICHIERS

tknewsbiff relit automatiquement votre fichier de configuration chaque fois qu'il se réveille pour vérifier les nouvelles non lues. Pour forcer tknewsbiff à relire le fichier immédiatement (par exemple, si vous testez une nouvelle configuration ou si vous venez de modifier votre fichier newsrc), appuyez sur le bouton 2 dans l'affichage (voir BOUTONS ci-dessus).

LIMITATIONS

tknewsbiff définit le nombre d'articles non lus comme l'article existant le plus élevé moins l'article le plus élevé que vous avez lu. Donc, si vous avez lu le dernier article du groupe de nouvelles mais aucun autre, tknewsbiff pense qu'il n'y a pas d'articles non lus. (Il est impossible de faire mieux en lisant le fichier actif et il serait très long de le faire plus précisément via NNTP car les serveurs ne fournissent aucun moyen efficace de signaler leurs propres trous dans les groupes de nouvelles.) Heureusement, cette définition est considérée comme une fonctionnalité par la plupart des gens. Elle vous permet de lire des articles puis de les marquer comme « non lus » mais sans que tknewsbiff continue de vous dire qu'ils sont non lus.

PRÉOCCUPATIONS INJUSTIFIÉES

Votre administrateur de nouvelles peut se demander si de nombreuses personnes utilisant tknewsbiff ont un impact sévère sur un serveur NNTP. En fait, l'impact est négligeable même lorsque le délai est très faible. Pour collecter toutes les informations dont il a besoin, tknewsbiff utilise une seule requête NNTP : il demande simplement le fichier actif. Le serveur NNTP n'effectue aucun calcul, formatage, etc., il envoie simplement le fichier. Tout le traitement intéressant se déroule localement dans le programme tknewsbiff lui-même.
