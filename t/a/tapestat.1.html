TAPESTAT(1) Manuel de l'utilisateur Linux TAPESTAT(1)

NOM

tapestat - Rapport sur les statistiques de bande.

SYNTAXE

tapestat [ -k | -m ] [ -t ] [ -U ] [ -V ] [ -y ] [ -z ] [ --human ] [ -o JSON ] [ intervalle [ compte ] ]

DESCRIPTION

La commande tapestat est utilisée pour surveiller l'activité des lecteurs de bande connectés à un système.

Le premier rapport généré par la commande tapestat fournit des statistiques concernant le temps écoulé depuis le démarrage du système, sauf si l'option -y est utilisée, auquel cas ce premier rapport est omis. Chaque rapport suivant couvre le temps écoulé depuis le rapport précédent.

Le paramètre intervalle spécifie la durée en secondes entre chaque rapport. Le paramètre compte peut être spécifié conjointement avec le paramètre intervalle. Si le paramètre compte est spécifié, la valeur de compte détermine le nombre de rapports générés à intervalle secondes d'intervalle. Si le paramètre intervalle est spécifié sans le paramètre compte, la commande tapestat génère des rapports en continu.

RAPPORT

Le rapport tapestat fournit des statistiques pour chaque lecteur de bande connecté au système. Les données suivantes sont affichées :

r/s
Le nombre de lectures émises exprimé en nombre par seconde moyen sur l'intervalle.
w/s
Le nombre d'écritures émises exprimé en nombre par seconde moyen sur l'intervalle.
kB_read/s | MB_read/s
La quantité de données lues exprimée en kibioctets (par défaut ou si l'option -k est utilisée) ou en mébioctets (si l'option -m est utilisée) par seconde moyen sur l'intervalle.
kB_wrtn/s | MB_wrtn/s
La quantité de données écrites exprimée en kibioctets (par défaut ou si l'option -k est utilisée) ou en mébioctets (si l'option -m est utilisée) par seconde moyen sur l'intervalle.
%Rd
Pourcentage d'attente en lecture - Le pourcentage du temps sur l'intervalle passé à attendre la fin des requêtes de lecture. Le temps est mesuré à partir du moment où la requête est expédiée à la couche intermédiaire SCSI jusqu'à ce qu'elle signale son achèvement.
%Wr
Pourcentage d'attente en écriture - Le pourcentage du temps sur l'intervalle passé à attendre la fin des requêtes d'écriture. Le temps est mesuré à partir du moment où la requête est expédiée à la couche intermédiaire SCSI jusqu'à ce qu'elle signale son achèvement.
%Oa
Pourcentage d'attente global - Le pourcentage du temps sur l'intervalle passé à attendre la fin de toute requête d'E/S (lecture, écriture et autres).
Rs/s
Le nombre d'E/S, exprimé en nombre par seconde moyen sur l'intervalle, pour lesquelles une valeur résiduelle non nulle a été rencontrée.
Ot/s
Le nombre d'E/S, exprimé en nombre par seconde moyen sur l'intervalle, qui ont été incluses comme "autres". Les autres E/S incluent les appels ioctl effectués au pilote de bande et les opérations implicites effectuées par le pilote de bande telles que la rembobinage à la fermeture (pour les périphériques de bande qui implémentent le rembobinage à la fermeture). Cela n'inclut aucune E/S effectuée en utilisant des méthodes en dehors du pilote de bande (par exemple, via les ioctls sg).

OPTIONS

--human
Afficher les tailles dans un format lisible par l'homme (par exemple, 1.0k, 1.2M, etc.) Les unités affichées avec cette option remplacent toutes les autres unités par défaut (par exemple, kibioctets, secteurs...) associées aux métriques.
-k
Afficher la quantité de données écrites ou lues en kibioctets par seconde au lieu de mébioctets. Cette option est mutuellement exclusive avec -m.
-m
Afficher la quantité de données écrites ou lues en mébioctets par seconde au lieu de kibioctets. Cette option est mutuellement exclusive avec -k.
-o JSON
Afficher les statistiques au format JSON (JavaScript Object Notation). L'ordre des champs de sortie JSON est indéfini, et de nouveaux champs pourront être ajoutés à l'avenir.
-t
Afficher les horodatages. Le format de l'horodatage peut dépendre de la valeur de la variable d'environnement S_TIME_FORMAT (voir ci-dessous) et de l'utilisation ou non de l'option -U.
-U
Afficher l'horodatage (UTC - Temps Universel Coordonné) en secondes depuis l'époque.
-V
Afficher la version et quitter.
-y
Omettre la statistique initiale montrant les valeurs depuis le démarrage.
-z
Demande à tapestat d'omettre la sortie pour toute bande pour laquelle il n'y a eu aucune activité pendant la période d'échantillonnage.

CONSIDÉRATIONS

Il est possible qu'une valeur en pourcentage (lecture, écriture ou autre) soit supérieure à 100 pour cent (la commande tapestat n'affichera jamais une valeur en pourcentage supérieure à 999). Si le rembobinage d'une bande prend 40 secondes alors que l'intervalle est de 5 secondes, la valeur %Oa sera de 0 dans les intervalles avant que le rembobinage ne soit terminé, puis d'environ 800 % lorsque le rembobinage sera terminé.

Des valeurs similaires seront observées pour %Rd et %Wr si un lecteur de bande arrête de lire ou d'écrire puis redémarre (c'est-à-dire s'il arrête le streaming). Dans un tel cas, vous pourriez voir r/s ou w/s tomber à zéro et la valeur %Rd/%Wr pourrait être supérieure à 100 lorsque la lecture ou l'écriture reprend (selon le temps nécessaire pour redémarrer l'écriture ou la lecture). Ce n'est un problème que si cela se produit fréquemment car cela peut user la bande et affecter les temps de sauvegarde.

Pour les lecteurs de bande rapides, vous pourriez observer de faibles temps d'attente en pourcentage. Cela n'indique pas de problème avec le lecteur de bande. Pour un lecteur de bande plus lent (par exemple, une ancienne génération de lecteur DDS), la vitesse de la bande (et du lecteur de bande) est beaucoup plus lente que les E/S du système de fichiers, les pourcentages de temps d'attente sont susceptibles d'être plus élevés. Pour les lecteurs de bande plus rapides (par exemple, LTO), les pourcentages de temps d'attente sont susceptibles d'être plus bas car le programme écrivant sur ou lisant depuis la bande effectuera beaucoup plus d'E/S système en raison du débit plus élevé.

Bien que les statistiques de bande soient implémentées dans le noyau à l'aide de variables atomiques, elles ne peuvent pas être lues de manière atomique en groupe. Toutes les valeurs de statistiques sont lues à partir de différents fichiers sous /sys, de ce fait, il peut y avoir des achèvements d'E/S lors de la lecture des différents fichiers pour le même lecteur de bande. Cela peut entraîner un ensemble de statistiques pour un appareil contenant certaines valeurs avant qu'une E/S ne soit terminée et d'autres après.

Cette commande utilise le troncage comme méthode d'arrondi lors du calcul des statistiques par seconde. Si, par exemple, vous utilisez dd pour copier une bande sur une autre et que vous exécutez tapestat avec un intervalle de 5 secondes et que sur l'intervalle il y a eu 3210 écritures et 3209 lectures, alors w/s affichera 642 et r/s 641 (641.8 tronqué à 641). Dans ce cas, s'il s'agissait d'une archive tar copiée (avec une taille de bloc de 10k), vous verriez également une différence entre kB_read/s et kB_wrtn/s de 2 (une E/S de 10k divisée par la période d'intervalle de 5 secondes). Si, au lieu de cela, il y avait 3210 écritures et 3211 lectures, alors w/s et r/s afficheraient tous deux 642, mais vous verriez toujours une différence entre les valeurs kB_read/s et kB_wrtn/s de 2 kB/s.

Cette commande utilise un intervalle en secondes. Cependant, en interne, l'intervalle est suivi par appareil et peut potentiellement avoir un effet sur les statistiques par seconde rapportées. Le temps de capture de chaque ensemble de statistiques est conservé avec ces statistiques. La différence entre le temps actuel et précédent est convertie en millisecondes pour être utilisée dans les calculs. Nous pouvons examiner comment cela peut impacter les statistiques rapportées en utilisant l'exemple d'une archive tar copiée entre deux lecteurs de bande à l'aide de dd. Si les deux appareils rapportaient 28900 kibioctets transférés et que le lecteur de bande en lecture avait un intervalle de 5001 millisecondes et le lecteur de bande en écriture 5000 millisecondes, cela se traduirait par 5778 kB_read/s et 5780 kB_wrtn/s.

tapestat(1) - tapestat

SYNOPSIS

tapestat [ -p ] [ -t ] [ -V ] [ interval [ count ] ]

DESCRIPTION

The tapestat command is used to monitor tape input/output statistics. It can be run on the local machine and collected data is displayed in the same format as the iostat(1) command. The statistics are gathered from the sysfs filesystem.

The statistics are collected for all tape devices detected by the kernel.

REPORT

The tape statistics report contains the following information:

tapedev
The name of the tape device.
rkb/s
The number of kilobytes read per second.
wkb/s
The number of kilobytes written per second.
rkB/s
The number of megabytes read per second.
wkB/s
The number of megabytes written per second.
rMB/s
The number of megabytes read per second.
wMB/s
The number of megabytes written per second.
rerror/s
The number of read errors per second.
werror/s
The number of write errors per second.
rblks/s
The number of blocks read per second.
wblks/s
The number of blocks written per second.
rbig/s
The number of big blocks read per second.
wbig/s
The number of big blocks written per second.
rgrd/s
The number of read requests that were granted per second.
wgrd/s
The number of write requests that were granted per second.
rfs/s
The number of read requests that were issued per second.
wfs/s
The number of write requests that were issued per second.
rwait/s
The average number of milliseconds an I/O request waited to be serviced.
wwait/s
The average number of milliseconds an I/O request waited to be serviced.
r/s
The number of read operations completed per second.
w/s
The number of write operations completed per second.
r_await
The average time (in milliseconds) for read requests issued by the system to be served by the device.
w_await
The average time (in milliseconds) for write requests issued by the system to be served by the device.
rareq-sz
The average size (in sectors) of read requests issued to the device.
wareq-sz
The average size (in sectors) of write requests issued to the device.
r_macavg
The average size (in sectors) of read requests completed by the device.
w_macavg
The average size (in sectors) of write requests completed by the device.
r_macsum
The number of read requests completed by the device.
w_macsum
The number of write requests completed by the device.
rbdsz
The average number of bytes per read, fragmented between requests.
wbdsz
The average number of bytes per write, fragmented between requests.
r_iosz
The average number of bytes per read.
w_iosz
The average number of bytes per write.
rsz
The average number of bytes read per operation.
wsz
The average number of bytes written per operation.
rq-sz
The average size (in kilobytes) of I/O requests sent to the device.
q-sz
The average queue length of the requests that were issued to the device.
util
Percentage of CPU time during which I/O requests were issued to the device. Note that this is the device utilization, not the CPU utilization.

OPTIONS

-p
Print statistics for tape devices only. By default, all devices are printed.
-t
Print the current time in the header.
-V
Print version information and exit.

The optional interval argument specifies the rate at which statistics are printed (in seconds). If the interval is specified, the count argument must also be specified. The count argument defines the number of decimal reporting intervals.

If no arguments are provided, the utility will run until killed. When tapestat is invoked with an interval and count, it produces a multiline report. Each line frame shows the average statistics since the previous frame. The first frame is the same as when no interval has been specified.

CONSIDERATIONS

When calculating statistics for a given interval, the command reads the current values from the kernel and subtracts the values from the previous interval. This means that the statistics are calculated over the time elapsed since the previous reading. If the system clock is changed, the statistics may be incorrect. In particular, if the system clock is set backwards, the statistics may be negative.

The statistics are reported as unsigned integers. Some fields are calculated based on the difference between two consecutive readings. In the case of read or write operations, the difference may be negative if the values wrapped around. The utility will calculate the correct difference by adding 2^N to the result, where N is the number of bits in the value. For example, if a value has 64 bits, and the current reading is 0 and the previous reading was 2^64 - 1, the difference will be 1.

The value for util is calculated by dividing the total I/O time (in milliseconds) by the time elapsed since the last reading (in milliseconds). The result is multiplied by 100 to express it as a percentage. The result is then rounded down to the nearest integer.

Due to the nature of kernel statistics reporting, a small number of I/O operations may be lost during I/O completion, rounding down, and small differences in the interval period on the statistics calculated should be minimal but may be non-zero.

ENVIRONMENT

The tapestat command takes into account the following environment variables:

S_COLORS
By default statistics are displayed in color when the output is connected to a terminal. Use this variable to change the settings. Possible values for this variable are never, always or auto (the latter is equivalent to the default settings).
Please note that the color (being red, yellow, or some other color) used to display a value is not indicative of any kind of issue simply because of the color. It only indicates different ranges of values.
S_COLORS_SGR
Specify the colors and other attributes used to display statistics on the terminal. Its value is a colon-separated list of capabilities that defaults to I=32;22:N=34;1:W=35;1:X=31;1:Z=34;22. Supported capabilities are:
I=
SGR (Select Graphic Rendition) substring for tape names.
N=
SGR substring for non-zero statistics values.
W= (or M=)
SGR substring for percentage values in the range from 75% to 90% (or in the range 10% to 25% depending on the metric's meaning).
X= (or H=)
SGR substring for percentage values greater than or equal to 90% (or lower than or equal to 10% depending on the metric's meaning).
Z=
SGR substring for zero values.
S_TIME_FORMAT
If this variable exists and its value is ISO then the current locale will be ignored when printing the date in the report header. The tapestat command will use the ISO 8601 format (YYYY-MM-DD) instead. The timestamp displayed with option -t will also be compliant with ISO 8601 format.

BUGS

/sys filesystem must be mounted for tapestat to work. It will not work on kernels that do not have sysfs support

This command requires kernel version 4.2 or later (or tape statistics support backported for an earlier kernel version).

Although tapestat displays units corresponding to kilobytes (kB), megabytes (MB)..., it actually uses kibibytes (kiB), mebibytes (MiB)... A kibibyte is equal to 1024 bytes, and a mebibyte is equal to 1024 kibibytes.

FILES

/sys/class/scsi_tape/st<num>/stats/*

Statistics files for tape devices.

/proc/uptime contains system uptime.
