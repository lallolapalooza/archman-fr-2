NOM

taskrc - Détails de configuration de la commande task(1)

SYNOPSIS

$HOME/.taskrc
task rc:<chemin-répertoire>/.taskrc ...
TASKRC=<chemin-répertoire>/.taskrc task ...
XDG_CONFIG_HOME=<chemin-répertoire>/task/taskrc task ...

DESCRIPTION

Taskwarrior obtient ses données de configuration à partir d'un fichier appelé .taskrc. Ce fichier est normalement situé dans le répertoire personnel de l'utilisateur :

    $HOME/.taskrc

L'emplacement par défaut peut être remplacé en utilisant l'attribut rc: lors de l'exécution de task :

    $ task rc:<chemin-répertoire>/.taskrc ...

ou en utilisant la variable d'environnement TASKRC :

    $ TASKRC=/tmp/.taskrc task ...

De plus, si aucun ~/.taskrc n'existe, taskwarrior vérifiera si la variable d'environnement XDG_CONFIG_HOME est définie :

    $ XDG_CONFIG_HOME=~/.config task ...

Les options individuelles peuvent être remplacées en utilisant l'attribut rc.<nom>: lors de l'exécution de task :

    $ task rc.<nom>:<valeur> ...

ou

    $ task rc.<nom>=<valeur> ...

Si Taskwarrior est exécuté sans fichier de configuration existant, il demandera s'il doit créer un fichier .taskrc par défaut dans le répertoire personnel de l'utilisateur.

Le fichier .taskrc suit une syntaxe très simple définissant des paires nom/valeur :

    <nom> = <valeur>

Il peut y avoir des espaces blancs autour de <nom>, de '=', et de <valeur>, et ils sont ignorés. Les espaces blancs à l'intérieur de la <valeur> sont conservés. Les espaces blancs ne sont pas autorisés dans les listes séparées par des virgules. L'entrée doit être sur une seule ligne, pas de continuation. Les valeurs prennent en charge UTF8 ainsi que le codage JSON, tel que \uNNNN.

Notez que Taskwarrior est flexible quant aux valeurs utilisées pour représenter les éléments booléens. Vous pouvez utiliser "1" pour activer, tout autre chose est interprété comme désactivé. Les valeurs "on", "yes", "y" et "true" sont également prises en charge.

    include <fichier>

Il peut y avoir des espaces blancs autour de 'include' et <fichier>. Le fichier peut être un chemin absolu ou relatif, et le caractère spécial '~' est développé pour signifier $HOME. Si un chemin relatif est spécifié, il sera évalué par rapport aux répertoires suivants (listés par ordre de priorité) : 1. le répertoire courant 2. le répertoire contenant le fichier taskrc 3. les répertoires définis par le gestionnaire de paquets (qui contiennent généralement des thèmes prédéfinis)

Notez que les variables d'environnement sont également développées dans les chemins (et toutes autres variables taskrc).

    # <comment>

Un commentaire se compose du caractère '#', et s'étend du '#' jusqu'à la fin de la ligne. Il n'y a aucun moyen de commenter un bloc de plusieurs lignes. Il peut y avoir des lignes vides.

Presque toutes les valeurs ont un réglage par défaut, et un fichier .taskrc vide est celui qui utilise tous les défauts. Le contenu du fichier .taskrc représente donc des substitutions des valeurs par défaut. Pour supprimer complètement une valeur par défaut, il doit y avoir une entrée comme celle-ci :

    <nom> =

Cette entrée remplace la valeur par défaut par une valeur vide.

MODIFICATION

Vous pouvez modifier votre fichier .taskrc à la main si vous le souhaitez, ou vous pouvez utiliser la commande 'config'. Pour définir définitivement une valeur dans votre fichier .taskrc, utilisez cette commande :

    $ task config nag "Vous avez des tâches plus urgentes."

Pour supprimer une entrée, utilisez cette commande :

    $ task config nag

Taskwarrior utilisera alors la valeur par défaut. Pour définir explicitement une valeur à vide, et donc éviter d'utiliser la valeur par défaut, utilisez cette commande :

    $ task config nag ""

Taskwarrior affichera également tous vos paramètres avec cette commande :

    $ task show

et en plus, il effectuera une vérification de toutes les valeurs du fichier, vous avertissant de tout ce qu'il trouve de suspect.

INCLUSION DE FICHIERS DE CONFIGURATION

Le .taskrc peut inclure d'autres fichiers contenant des paramètres de configuration en utilisant l'instruction include :

    include <chemin/vers/le/fichier/de/configuration/a/inclure>

En utilisant des fichiers d'inclusion, vous pouvez diviser votre fichier de configuration principal en plusieurs fichiers contenant uniquement les données de configuration pertinentes comme les couleurs, etc.

Il y a deux excellentes utilisations des inclusions dans votre .taskrc, montrées ici :

    include holidays.en-US.rc
    include dark-16.theme

Cela inclut deux fichiers standard distribués avec Taskwarrior, qui définissent un ensemble de jours fériés américains et configurent un thème 16 couleurs pour colorer les rapports et le calendrier.

VARIABLES ENVIRONNEMENT

Ces variables d'environnement remplacent les valeurs par défaut, mais pas les arguments de la ligne de commande.

TASKDATA=~/.task
Ceci remplace le chemin par défaut pour les données de Taskwarrior.
TASKRC=~/.taskrc
Ceci remplace le fichier RC par défaut.

Cette variable d'environnement sera vérifiée si ~/.taskrc n'existe pas.

XDG_CONFIG_HOME=~/.config
Si défini, taskwarrior recherchera un fichier $XDG_CONFIG_HOME/task/taskrc.

VARIABLES CONFIGURATION

Les noms de variables valides et leurs valeurs par défaut sont :

FICHIERS

data.location=$HOME/.task
C'est un chemin vers le répertoire contenant toutes les données de Taskwarrior. Par défaut, il est configuré sur ~/.task, par exemple : /home/paul/.task

Notez que vous pouvez utiliser le caractère méta de shell ~, qui sera correctement développé.

Notez que la variable d'environnement TASKDATA remplace ce réglage.

hooks.location=$HOME/.task/hooks
C'est un chemin vers le répertoire des scripts de hooks. Par défaut, c'est ~/.task/hooks.
gc=1
Peut être utilisé pour suspendre temporairement la reconstruction, afin que les identifiants des tâches ne changent pas. La reconstruction nécessite un accès en lecture/écriture à la base de données, donc la désactivation de `gc` peut améliorer les performances.

Notez que cela doit être utilisé sous la forme d'une substitution de ligne de commande (task rc.gc=0 ...), et non utilisé en permanence dans le fichier .taskrc, car cela affecte significativement les performances à long terme.

purge.on-sync=0
Si défini, les anciennes tâches seront automatiquement purgées après chaque synchronisation. Les tâches sont identifiées comme "anciennes" lorsqu'elles ont le statut "Deleted" et n'ont pas été modifiées depuis 180 jours.
hooks=1
Ce commutateur maître active le traitement des scripts de hooks. La valeur par défaut est '1', mais certaines extensions et environnements peuvent avoir besoin de désactiver les hooks.
exit.on.missing.db=0
Lorsqu'il est défini sur '1', le programme se termine si la base de données (~/.task ou rc.data.location ou substitution TASKDATA) est manquante. La valeur par défaut est '0'.

TERMINAL

detection=1
Détermine s'il faut utiliser ioctl pour établir la taille de la fenêtre que vous utilisez, pour le retour à la ligne du texte.
limit:25
Spécifie le nombre de tâches souhaité qu'un rapport doit afficher, si un entier positif est donné. La valeur 'page' peut également être utilisée, et limitera la sortie du rapport au nombre de lignes de texte qui tiennent sur l'écran. La valeur par défaut est '25'.

defaultwidth=80
La largeur de la sortie utilisée lorsque le support de détection automatique n'est pas disponible. Par défaut à 80. Si défini à 0, il est interprété comme une largeur infinie, donc sans retour à la ligne ; ceci est utile lorsque la sortie du rapport est redirigée vers un fichier pour un traitement ultérieur.
defaultheight=24
La hauteur de la sortie utilisée lorsque le support de détection automatique n'est pas disponible. Par défaut à 24. Si défini à 0, il est interprété comme une hauteur infinie. Ceci est utile lorsque les graphiques sont redirigés vers un fichier pour un traitement ultérieur.
avoidlastcolumn=0
Utilise la largeur du terminal moins un comme largeur totale. Cela évite de placer des codes de couleur dans la dernière colonne, ce qui peut causer des problèmes aux utilisateurs de Cygwin. La valeur par défaut est '0'.
hyphenate=1
Casse les lignes lorsque les ruptures de retour à la ligne se produisent au milieu d'un mot. La valeur par défaut est '1'.
editor=vi
Spécifie quel éditeur de texte vous souhaitez utiliser lorsque la commande task edit <ID> est utilisée. Taskwarrior recherchera d'abord cette variable de configuration. Si elle est trouvée, elle est utilisée. Sinon, il recherchera les variables d'environnement $VISUAL ou $EDITOR, avant d'utiliser par défaut "vi".
reserved.lines=1
Ceci est le nombre de lignes réservées en bas de l'écran pour l'invite de commande du shell. Ceci n'est référencé que lorsque 'limit:page' est utilisé.

DIVERS

verbose=1|0|nothing|list...
Lorsqu'il est défini sur "1" (par défaut), des commentaires explicatifs utiles sont ajoutés à toutes les sorties de Taskwarrior. Le définir à "0" signifie que vous verrez une sortie normale.

La valeur spéciale "nothing" peut être utilisée pour éliminer toute sortie optionnelle, ce qui permet d'afficher uniquement les données formatées, sans rien d'autre. Cette sortie est la plus facilement analysable et utilisable par les scripts shell.

Alternativement, vous pouvez spécifier une liste de jetons de verbosité séparés par des virgules qui contrôlent des occasions spécifiques où une sortie est générée. Cette liste peut contenir :

    blank      Insère des lignes vides supplémentaires dans la sortie, pour plus de clarté
    header     Messages qui apparaissent avant la sortie du rapport (cela inclut les remplacements de .taskrc/.task et le message "[task next]")
    footnote   Messages qui apparaissent après la sortie du rapport (principalement des messages d'état et des descriptions de changement)
    label      Étiquettes de colonne sur les rapports tabulaires
    new-id     Fournit un retour d'information sur les nouvelles tâches avec des ID (et des UUID pour les nouvelles tâches avec l'ID 0, telles que les nouvelles tâches terminées).
    new-uuid   Fournit un retour d'information sur les nouvelles tâches avec des UUID. Remplace new-id. Utile pour l'automatisation.
    news       Rappelle de lire les nouvelles mises en avant des sorties jusqu'à ce que l'utilisateur exécute "task news".
    affected   Rapporte 'N tâches affectées' et similaires
    edit       Utilise le modèle verbeux pour la commande 'edit'
    special    Retour d'information lors de l'application de tags spéciaux
    project    Retour d'information sur les changements de statut de projet
    sync       Retour d'information sur la synchronisation
    filter     Affiche le filtre utilisé dans la commande
    context    Affiche le contexte actuel. Affiché dans la note de bas de page.
    override   Notification lorsque les options de configuration sont remplacées
    recur      Notification lorsqu'une nouvelle instance de tâche récurrente est créée
    default    Notifications sur le choix de taskwarrior d'effectuer une action par défaut.

Les jetons "affected", "new-id", "new-uuid", "project", "override" et "recur" impliquent "footnote".

Le jeton "default" implique "header".

Notez que le réglage "1" est équivalent à tous les jetons spécifiés, et le réglage "nothing" est équivalent à aucun des jetons spécifiés.

Voici les équivalents raccourcis :

    verbose=on
    verbose=blank,header,footnote,label,new-id,news,affected,edit,special,project,sync,filter,override,recur
    verbose=0
    verbose=blank,label,new-id,edit
    verbose=nothing
    verbose=

Ces commentaires supplémentaires sont envoyés à l'erreur standard pour l'en-tête, la note de bas de page et le projet. Les autres sont envoyés à la sortie standard.

confirmation=1
Peut être "1" ou "0", et détermine si Taskwarrior demandera une confirmation avant de supprimer une tâche ou d'effectuer la commande undo. La valeur par défaut est "1". Envisagez de laisser ceci activé, par sécurité.
allow.empty.filter=1
Un filtre vide combiné à une commande d'écriture est potentiellement une façon de modifier toutes les tâches par erreur, et lorsque cela est détecté, une confirmation est requise. Définir ceci à '0' signifie que c'est une erreur d'utiliser une commande d'écriture sans filtre.
indent.annotation=2
Contrôle le nombre d'espaces pour indenter les annotations lorsqu'elles sont affichées sous le champ description. La valeur par défaut est "2".
indent.report=0
Contrôle l'indentation de toute la sortie du rapport. Par défaut, c'est "0".
row.padding=0
Contrôle le padding gauche et droit autour de chaque ligne de la sortie du rapport. Par défaut, c'est "0".
column.padding=0
Contrôle le padding entre les colonnes de la sortie du rapport. Par défaut, c'est "1".
bulk=3
Est un nombre, par défaut 3. Lorsque ce nombre ou plus de tâches sont modifiées en une seule commande, une confirmation sera requise, quel que soit la valeur de la variable confirmation. La valeur spéciale bulk=0 est traitée comme l'infini.

Ceci est utile pour empêcher les changements involontaires à grande échelle.

nag=Vous avez des tâches plus urgentes.
Peut être une chaîne de texte, ou vide. Elle est utilisée comme une invite lorsqu'une tâche est démarrée ou terminée, lorsqu'il y a d'autres tâches avec une urgence plus élevée. La valeur par défaut est : 'Vous avez des tâches plus urgentes'. C'est un rappel gentil que vous contredisez vos propres paramètres d'urgence.
list.all.projects=0
Peut être "1" ou "0", et détermine si la commande 'projects' liste tous les noms de projets que vous avez utilisés, ou seulement ceux utilisés dans les tâches actives. La valeur par défaut est "0".
summary.all.projects=0
Si défini sur "1", affiche tous les projets dans le rapport de résumé, même s'il n'y a pas de tâches en attente. La valeur par défaut est "0".
complete.all.tags=1
Peut être "1" ou "0", et détermine si les scripts de complétion par tabulation prennent en compte tous les noms de tags que vous avez utilisés, ou seulement ceux utilisés dans les tâches actives. La valeur par défaut est "0".
list.all.tags=1
Peut être "1" ou "0", et détermine si la commande 'tags' liste tous les noms de tags que vous avez utilisés, ou seulement ceux utilisés dans les tâches actives. La valeur par défaut est "0".
print.empty.columns=1
Peut être "1" ou "0", et détermine si les colonnes sans aucune donnée pour aucune tâche sont imprimées. Par défaut, c'est "0".
search.case.sensitive=1
Peut être "1" ou "0", et détermine si la recherche par mot-clé et les substitutions sur la description et les annotations sont effectuées de manière sensible à la casse. Par défaut, c'est "1" sur la plupart des plateformes. Par défaut, c'est "0" sur Cygwin en raison de problèmes avec l'ancienne bibliothèque regex concernant l'insensibilité à la casse.
regex=1
Contrôle si le support des expressions régulières est activé. La valeur par défaut est "1".
xterm.title=1
Définit le titre de la fenêtre xterm lors de l'exécution des rapports. Par défaut, c'est "0".
expressions=infix|postfix
Définit une préférence pour les expressions infixes (1 + 2) ou postfixes (1 2 +). Par défaut, c'est infixe.
json.array=1
Détermine si la commande d'exportation englobe la sortie JSON dans '[...]' et ajoute ',' après chaque objet de tâche exporté pour créer un tableau JSON correctement formé. Avec json.array=0, export écrit des objets JSON bruts sur STDOUT, un par ligne. Par défaut, c'est "1".
_forcecolor=1
Taskwarrior désactive automatiquement la couleur lorsque la sortie n'est pas envoyée directement à un TTY. Par exemple, cette commande :
$ task list > file

n'utilisera aucune couleur. Pour remplacer cela, utilisez :

$ task rc._forcecolor=yes list > file

Par défaut, c'est "0".

active.indicator=*
Le caractère ou la chaîne à afficher dans la colonne start.active. Par défaut, c'est *.
tag.indicator=+
Le caractère ou la chaîne à afficher dans la colonne tag.indicator. Par défaut, c'est +.
dependency.indicator=D
Le caractère ou la chaîne à afficher dans la colonne depends.indicator. Par défaut, c'est D.

CONFIGURATION OPTIONS

uda.name.indicator=U
Le caractère ou la chaîne à afficher dans la colonne de l'indicateur <uda>. La valeur par défaut est U.
recurrence=1
Contrôle si la récurrence est activée et si les tâches récurrentes continuent de générer de nouvelles instances de tâches. La valeur par défaut est "1".

Si vous synchronisez plusieurs clients, il est conseillé de définir 'recurrence=1' sur votre client principal et 'recurrence=0' sur TOUS les autres clients. Il s'agit d'une solution de contournement pour un bug de duplication.

recurrence.confirmation=prompt
Contrôle si les modifications apportées aux tâches récurrentes se propagent aux autres tâches enfants avec ou sans confirmation. Une valeur de 'yes' signifie propager les modifications sans confirmation. Une valeur de 'no' signifie ne pas propager les modifications et ne pas demander de confirmation. Une valeur de 'prompt' vous demande à chaque fois. La valeur par défaut est 'prompt'.
recurrence.indicator=R
Le caractère ou la chaîne à afficher dans la colonne de l'indicateur de récurrence. La valeur par défaut est R.
recurrence.limit=1
Le nombre de tâches récurrentes futures à afficher. La valeur par défaut est 1. Par exemple, si une tâche récurrente hebdomadaire est ajoutée avec une date d'échéance demain, et que recurrence.limit est défini sur 2, alors un rapport listera 2 tâches récurrentes en attente, une pour demain, et une pour une semaine à partir de demain.
abbreviation.minimum=2
Longueur minimale de toute commande/valeur abrégée. Cela signifie que "ve", "ver", "vers", "versi", "versio" équivaudront tous à "version", mais "v" ne le fera pas. La valeur par défaut est 2.
debug=0
Taskwarrior dispose d'un mode de débogage qui affiche des informations de diagnostic. Généralement, ce n'est pas quelque chose que quiconque voudrait, mais lors du signalement d'un bug, la sortie de débogage peut être utile. Elle peut également aider à expliquer comment la ligne de commande est analysée, mais les informations sont affichées d'une manière conviviale pour les développeurs, pas pour les utilisateurs.

L'activation du débogage définit automatiquement debug.hooks=1 et debug.parser=1 s'ils n'ont pas déjà de valeurs assignées. La valeur par défaut est "0".

debug.hooks=0
Contrôle le niveau de diagnostic du système de hooks. Le niveau 0 signifie aucun diagnostic. Le niveau 1 affiche les appels de hooks. Le niveau 2 affiche également le statut de sortie et les E/S.
debug.parser=0
Contrôle le niveau de diagnostic de l'analyseur. Le niveau 0 n'affiche aucun diagnostic. Le niveau 1 affiche l'arbre d'analyse final. Le niveau 2 affiche l'arbre d'analyse de toutes les phases de l'analyse. Le niveau 3 affiche les détails de l'évaluation des expressions.
obfuscate=0
Lorsqu'il est défini sur '1', remplace tout le texte du rapport par 'xxx'. Ceci est utile pour partager la sortie du rapport dans les rapports de bugs. La valeur par défaut est '0'.
alias.rm=delete
Taskwarrior prend en charge les alias de commandes. Cet alias fournit un nom alternatif (rm) pour la commande delete. Vous pouvez utiliser des alias pour fournir des noms alternatifs à n'importe laquelle des commandes. Plusieurs commandes que vous pouvez utiliser sont en fait des alias - le rapport 'history', par exemple, ou 'export'.
burndown.cumulative=1
Peut être "1" ou "0", et contrôle le comportement de la commande burndown. Lorsqu'il est défini sur 1, il additionne toutes les tâches complétées, sinon elles ne sont tracées que dans l'intervalle où la tâche a été complétée. La valeur par défaut est 1.

DATES

dateformat=Y-M-D
dateformat.report=
dateformat.holiday=YMD
dateformat.edit=Y-M-D H:N:S
dateformat.info=Y-M-D H:N:S
dateformat.annotation=
report.X.dateformat=Y-M-D
Il s'agit d'une chaîne de caractères qui définit comment Taskwarrior formate les valeurs de date. L'ordre de priorité pour la variable de configuration est report.X.dateformat puis dateformat.report puis dateformat pour le formatage des dates d'échéance dans les rapports. Si report.X.dateformat et dateformat.report ne sont pas définis, alors dateformat sera appliqué à la date. Les dates saisies ainsi que toutes les autres dates affichées dans les rapports sont formatées selon dateformat.

La valeur par défaut est la norme ISO-8601 : Y-M-D. La chaîne peut contenir les caractères :

    m  mois avec chiffre minimal,    par exemple 1 ou 12
    d  jour avec chiffre minimal,      par exemple 1 ou 30
    y  année à deux chiffres,         par exemple 09 ou 12
    D  jour à deux chiffres,          par exemple 01 ou 30
    M  mois à deux chiffres,          par exemple 01 ou 12
    Y  année à quatre chiffres,       par exemple 2009 ou 2015
    a  nom court du jour de la semaine,  par exemple Lun ou Mer
    A  nom long du jour de la semaine,   par exemple Lundi ou Mercredi
    b  nom court du mois,             par exemple Jan ou Août
    B  nom long du mois,              par exemple Janvier ou Août
    v  semaine avec chiffre minimal,    par exemple 3 ou 37
    V  semaine à deux chiffres,        par exemple 03 ou 37
    h  heure avec chiffre minimal,     par exemple 3 ou 21
    n  minutes avec chiffre minimal,    par exemple 5 ou 42
    s  secondes avec chiffre minimal,    par exemple 7 ou 47
    H  heure à deux chiffres,          par exemple 03 ou 21
    N  minutes à deux chiffres,        par exemple 05 ou 42
    S  secondes à deux chiffres,       par exemple 07 ou 47
    J  jour julien à trois chiffres,   par exemple 023 ou 365
    j  jour julien,             par exemple 23 ou 365
    w  jour de la semaine,        par exemple 0 pour Lundi, 5 pour Vendredi
Les caractères 'v', 'V', 'a' et 'A' ne peuvent être utilisés que pour le formatage des dates imprimées (pas pour leur analyse).
La chaîne peut également contenir d'autres caractères servant d'espaces réservés ou de formatage. Exemples pour d'autres valeurs de dateformat :
    d/m/Y  utiliserait pour l'entrée et la sortie 24/7/2009
    yMD    utiliserait pour l'entrée et la sortie 090724
    M-D-Y  utiliserait pour l'entrée et la sortie 07-24-2009
Exemples pour d'autres valeurs de dateformat.report :
    a D b Y (V)   émettrait "Ven 24 Juil 2009 (30)"
    A, B D, Y     émettrait "Vendredi, Juillet 24, 2009"
    wV a Y-M-D    émettrait "w30 Ven 2009-07-24"
    yMD.HN        émettrait "110124.2342"
    m/d/Y H:N     émettrait "1/24/2011 10:42"
    a D b Y H:N:S émettrait "Lun 24 Jan 2011 11:19:42"
Les champs non définis prennent leurs valeurs minimales valides (1 pour le mois et le jour et 0 pour l'heure, les minutes et les secondes) lorsqu'au moins un autre champ de date global est défini. Sinon, ils sont définis sur les valeurs correspondantes de "maintenant". Par exemple :
    8/1/2013  avec m/d/Y   implique le 1er août 2013 à minuit (inféré)
    8/1 20:40 avec m/d H:N implique le 1er août 2013 (inféré) à 20:40
date.iso=1
Active la prise en charge des dates ISO-8601. La valeur par défaut est "1".

CALENDRIER

weekstart=Sunday
Détermine le jour de début de la semaine. Les valeurs valides sont uniquement Dimanche ou Lundi. La valeur par défaut est "Sunday".
displayweeknumber=1
Détermine si les numéros de semaine sont affichés lors de l'utilisation de la commande "task calendar". Le numéro de semaine dépend du jour de début de la semaine. La valeur par défaut est "1".
due=7
Il s'agit du nombre de jours dans le futur qui définissent quand une tâche est considérée comme due, et est colorée en conséquence. La valeur par défaut est 7.
calendar.details=sparse
Si défini sur "full", l'exécution de "task calendar" affichera les détails des tâches dont les dates d'échéance tombent dans la période du calendrier. Les jours correspondants seront codés par couleur dans le calendrier. S'il est défini sur "sparse", seuls les jours correspondants seront codés par couleur et aucun détail ne sera affiché. L'affichage des dates d'échéance avec détails est désactivé en définissant la variable sur "none". La valeur par défaut est "sparse".
calendar.details.report=list
Le rapport à exécuter lors de l'affichage des détails des tâches avec dates d'échéance lors de l'exécution de la commande "task calendar". La valeur par défaut est "list".
calendar.offset=0
Si "1", le premier mois du rapport de calendrier est effectivement modifié par la valeur de décalage spécifiée dans calendar.offset.value. Il est par défaut à "0".
calendar.offset.value=-1

URGENCE

Le calcul de l'urgence utilise un polynôme avec plusieurs termes, chacun ayant un coefficient configurable. Ces coefficients sont :

urgency.blocking.coefficient=8.0
Coefficient d'urgence pour les tâches bloquantes
urgency.blocked.coefficient=-5.0
Coefficient d'urgence pour les tâches bloquées
urgency.due.coefficient=12.0
Coefficient d'urgence pour les dates d'échéance
urgency.waiting.coefficient=-3.0
Coefficient d'urgence pour le statut en attente
urgency.active.coefficient=4.0
Coefficient d'urgence pour les tâches actives
urgency.scheduled.coefficient=5.0
Coefficient d'urgence pour les tâches planifiées
urgency.project.coefficient=1.0
Coefficient d'urgence pour les projets
urgency.tags.coefficient=1.0
Coefficient d'urgence pour les étiquettes
urgency.annotations.coefficient=1.0
Coefficient d'urgence pour les annotations
urgency.age.coefficient=2.0
Coefficient d'urgence pour l'âge des tâches
urgency.age.max=365
Âge maximum en jours. Après ce nombre de jours écoulé, l'urgence d'une tâche n'augmentera plus en raison de son âge.
urgency.user.tag.<tag>.coefficient=...
Coefficient d'étiquette spécifique.
urgency.user.tag.next.coefficient=15.0
Coefficient d'urgence pour l'étiquette 'next'.
urgency.user.project.<project>.coefficient=...
Coefficient de projet spécifique.
urgency.user.keyword.<keyword>.coefficient=...
Coefficient de mot-clé de description spécifique.
urgency.uda.<name>.coefficient=...
Présence/absence de données UDA.
urgency.uda.<name>.<value>.coefficient=...
Valeur spécifique de données UDA.

Les coefficients reflètent l'importance relative des divers termes dans le calcul de l'urgence. Ce sont des valeurs par défaut, et elles peuvent être modifiées selon vos préférences, mais il est important de considérer attentivement toute modification.

urgency.inherit=0

Pas vraiment un coefficient. Lorsqu'il est activé, les tâches bloquantes héritent de la valeur d'urgence la plus élevée trouvée parmi les tâches qu'elles bloquent. Ceci est fait récursivement. Il est recommandé de définir urgency.blocking.coefficient et urgency.blocked.coefficient à 0.0 afin que ce paramètre soit le plus utile.

DÉFAUTS

default.project=foo
Fournit un nom de projet par défaut pour la commande task add, si vous n'en spécifiez pas. La valeur par défaut est vide.
default.due=...
Fournit une date d'échéance par défaut pour la commande task add, si vous n'en spécifiez pas. Vous pouvez utiliser une date, ou une valeur de durée qui est supposée être relative à 'maintenant'. La valeur par défaut est vide.
default.scheduled=...
Fournit une date de planification par défaut pour la commande task add, si vous n'en spécifiez pas. Vous pouvez utiliser une date, ou une valeur de durée qui est supposée être relative à 'maintenant'. La valeur par défaut est vide.
uda.<nom>.default=...
Fournit des valeurs par défaut pour les champs UDA lors de l'utilisation de la commande task add, si vous ne spécifiez pas de valeurs. La valeur par défaut est vide.
default.command=next
Fournit une commande par défaut qui est exécutée chaque fois que Taskwarrior est invoqué sans arguments. Par exemple, si réglé sur : 
    default.command=project:foo list
alors Taskwarrior exécutera la commande "project:foo list" si aucune commande n'est spécifiée. Cela signifie qu'en tapant simplement
    $ task

    ID Projet Pri Description
     1 foo     H   Concevoir foo
     2 foo         Construire foo

RAPPORTS

Les rapports peuvent être personnalisés en utilisant les variables de configuration suivantes. Les colonnes de sortie, leurs étiquettes et l'ordre de tri peuvent être définis à l'aide des variables correspondantes pour chaque rapport. Chaque nom de rapport est utilisé comme nom de "commande". Par exemple

task overdue
report.X.description
La description du rapport X lors de l'exécution de la commande "task help".
report.X.columns
Ceci est une liste séparée par des virgules de colonnes et de spécificateurs de formatage. Voir la commande 'task columns' pour une liste complète des options et des exemples.
report.X.context
Une valeur booléenne représentant si le rapport donné doit respecter (appliquer) le contexte actuellement actif. Voir la section CONTEXTE pour les détails sur le contexte. Par défaut à 1.
report.X.labels
Les étiquettes pour chaque colonne qui seront utilisées lors de la génération du rapport X. Les étiquettes sont une liste séparée par des virgules.
report.X.sort
L'ordre de tri des tâches dans le rapport généré X. L'ordre de tri est spécifié en utilisant les IDs de colonne postfixés par un "+" pour l'ordre de tri ascendant ou un "-" pour l'ordre de tri descendant. Les IDs de tri sont séparés par des virgules. Par exemple : 
    report.list.sort=due+,priority-,start.active-,project+

De plus, après le "+" ou le "-", il peut y avoir un slash "/" qui indique qu'il y a des sauts après que les valeurs de la colonne changent. Par exemple :

    report.minimal.sort=project+/,description+

Cet ordre de tri spécifie maintenant qu'il y a une rupture de liste entre chaque projet. Une rupture de liste est simplement une ligne vide, qui fournit un regroupement visuel.

Une valeur de tri spéciale de "none" indique qu'aucun tri n'est requis, et les tâches seront présentées dans l'ordre (le cas échéant) dans lequel elles sont sélectionnées.

Une valeur de tri spéciale de "random" indique que les tâches seront triées dans un ordre aléatoire. Chaque fois qu'un rapport avec 'sort:random' est exécuté, un nouvel ordre aléatoire sera généré.

report.X.filter
Ceci ajoute un filtre au rapport X afin que seules les tâches correspondant aux critères du filtre soient affichées dans le rapport généré.

Il existe un cas spécial pour 'report.timesheet.filter', qui peut être spécifié même si le rapport 'timesheet' n'est pas très personnalisable.

report.X.dateformat
Ceci ajoute un format de date au rapport X qui sera utilisé par la colonne "date d'échéance". S'il n'est pas défini, dateformat.report puis dateformat seront utilisés dans cet ordre. Voir la section DATES pour les détails sur les espaces réservés de séquence.
report.X.annotations
Ceci ajoute la possibilité de contrôler la sortie des annotations pour une tâche dans un rapport. Obsolète. Utilisez la colonne description avec un format (par exemple, description.count) à la place.
Taskwarrior livre un certain nombre de rapports prédéfinis, qui sont :
next
Liste les tâches les plus importantes.
long
Liste toutes les tâches en attente et toutes les données, correspondant aux critères spécifiés.
list
Liste toutes les tâches correspondant aux critères spécifiés.
ls
Listage court de toutes les tâches correspondant aux critères spécifiés.
minimal
Listage minimal de toutes les tâches correspondant aux critères spécifiés.
newest
Affiche les tâches les plus récentes.
oldest
Affiche les tâches les plus anciennes.
overdue
Liste les tâches en retard correspondant aux critères spécifiés.
active
Liste les tâches actives correspondant aux critères spécifiés.
completed
Liste les tâches terminées correspondant aux critères spécifiés.
recurring
Liste les tâches récurrentes correspondant aux critères spécifiés.
waiting
Liste toutes les tâches en attente correspondant aux critères spécifiés.
all
Liste toutes les tâches correspondant aux critères spécifiés.
blocked
Liste toutes les tâches qui ont des dépendances.

ATTRIBUTS DÉFINIS PAR L'UTILISATEUR

Les attributs définis par l'utilisateur (UDA) sont un mécanisme d'extension qui permet de définir de nouveaux attributs pour Taskwarrior afin de stocker et d'afficher des informations. Un exemple serait un attribut 'estimate' qui pourrait être utilisé pour stocker des estimations de temps associées à une tâche. Cet attribut 'estimate' n'est pas intégré à Taskwarrior, mais avec quelques simples réglages de configuration, vous pouvez indiquer à Taskwarrior de stocker cet élément et de le rendre accessible pour des rapports et filtres personnalisés.

Cela vous permet d'améliorer Taskwarrior pour qu'il s'adapte à votre flux de travail, ou de contourner les règles et d'utiliser Taskwarrior pour stocker et synchroniser des données qui ne sont pas nécessairement liées aux tâches.

Une restriction importante est que, comme il s'agit d'un système ouvert qui permet la définition de tout nouvel attribut, Taskwarrior ne peut pas comprendre la signification de cet attribut. Ainsi, bien que Taskwarrior stockera, modifiera, rapportera, triera et filtrera fidèlement vos UDA, il ne comprend rien à leur sujet. Par exemple, si vous définissez un UDA nommé 'estimate', Taskwarrior ne saura pas si cette valeur représente des semaines, des heures, des minutes, de l'argent ou un autre décompte de ressources.

uda.<nom>.type=string|numeric|uuid|date|duration
Définit un UDA nommé '<nom>', du type spécifié.
uda.<nom>.label=<en-tête de colonne>
Fournit une étiquette de rapport par défaut pour l'UDA nommé '<nom>'.
uda.<nom>.values=A,B,C
Pour les UDA de type 'string' uniquement, ceci fournit une liste séparée par des virgules des valeurs acceptables. Dans cet exemple, l'UDA '<nom>' ne peut contenir que les valeurs 'A', 'B' ou 'C', mais peut également ne pas avoir de valeur.

Notez que l'ordre des valeurs est important et indique l'ordre de tri, de la plus élevée ('A') à la plus basse ('C').

Notez qu'une valeur vide est autorisée.

uda.<nom>.default=...
Fournit une valeur par défaut pour l'UDA nommé '<nom>'.
Exemple d'UDA 'estimate'
Cet exemple montre un UDA 'estimate' qui stocke des valeurs spécifiques pour la taille d'une tâche. Notez la valeur vide après 'trivial'.
uda.estimate.type=string
uda.estimate.label=Estimation de taille
uda.estimate.values=énorme,grand,moyen,petit,trivial,
Notez que les valeurs sont triées


énorme > grand > moyen > petit > trivial > ''

CONTEXTE

La définition du contexte est un mécanisme qui permet à l'utilisateur de définir un filtre permanent, évitant ainsi la nécessité de spécifier un filtre de manière répétée. Plus de détails sur l'utilisation peuvent être trouvés dans la page de manuel task(1).

Le contexte actuel est stocké dans le fichier .taskrc, avec les définitions de tous les contextes fournis par l'utilisateur.

context=<nom>
Stocke la valeur du contexte actuellement actif.
context.<nom>.read=<filtre>

context.<nom>.write=<modifications>
Stocke la définition du contexte de lecture ou d'écriture avec le nom <nom>. Le contexte de lecture est le filtre par défaut appliqué lorsque le contexte est actif. Les modifications du contexte d'écriture sont les modifications par défaut appliquées aux tâches nouvellement ajoutées lorsque le contexte est actif.
context.<nom>.rc.<clé>=<valeur>
Le type rc permet de remplacer n'importe quel paramètre de configuration pour le contexte actuel, par exemple, si la commande par défaut pour le contexte 'home' doit être changée en 'home_report', l'instruction suivante pourrait être ajoutée :

context.home.rc.default.command=home_report

SYNCHRONISATION

Ces paramètres de configuration sont utilisés pour se connecter et synchroniser les tâches avec le serveur de tâches.
