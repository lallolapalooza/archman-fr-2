NOM

targets.conf - Fichier de configuration SCSI Target Linux

DESCRIPTION

tgt-admin utilise par défaut le fichier /etc/tgt/targets.conf pour initialiser la configuration de tgtd. Sa structure est similaire au HTML, avec une hiérarchie de balises imbriquées pour définir les cibles et les LUNs.

SYNTAXE DU FICHIER DE CONFIGURATION

Les directives globales configurent les options qui sont globales pour la configuration de tgtd, tout en définissant les cibles exportées via des sections de cible.

Les sections de cible contiennent des directives spécifiques à un périphérique cible. Elles définissent les LUNs exportées de chaque cible via les directives « backing-store » et « direct-store », ainsi que d'autres options propres à la cible.

Les directives LUN (« backing-store » et « direct-store ») peuvent contenir des options spécifiques à une seule unité logique exportée.

DIRECTIVES GLOBALES

À l'exception des directives de cible, chacune de celles-ci ne devrait apparaître qu'une seule fois.

<target <IQN>>

Définit le début d'une définition de cible. IQN est un Nom Qualifié ISCSI tel que « iqn.2001-04.com.example:storage1 ».

À l'intérieur de ce bloc doivent se trouver les directives de niveau cible, telles que décrites ci-dessous.

La définition de cible se termine par « </target> »

default-driver <lld>

Au lieu de spécifier un type de pilote pour chaque cible, default-driver définit un pilote de bas niveau par défaut pour toutes les cibles exportées. Il peut être remplacé au niveau de chaque cible. Les valeurs valides pour lld sont « iscsi » ou « iser ». Puisque iscsi est supposé si cette directive n'est pas présente, elle n'est généralement nécessaire que si iser est le défaut souhaité.

include <path>

Inclut la configuration d'un autre fichier de configuration. Les jokers sont autorisés, donc un exemple comme « include /etc/tgt/xen/*.conf » est permis.

ignore-errors yes

Les erreurs de tgtadm seront ignorées. Par défaut : no.

control-port <port>

Définit une clé de socket locale différente pour communiquer avec tgtd. Par défaut : 0. Ceci est généralement utile uniquement si plusieurs instances de tgtd sont utilisées.

iSNSServerIP <addr>

Définit l'adresse du serveur iSNS au format d'adresse IPv4 en notation pointée. Requis lors de l'utilisation d'iSNS, ignoré sinon.

iSNSAccessControl <value>

Définit le contrôle d'accès iSNS. Les valeurs valides sont « On » ou « Off ». Requis lors de l'utilisation d'iSNS, ignoré sinon.

iSNSServerPort <port>

Définit un port de serveur iSNS différent. Par défaut : 3205. Optionnel lors de l'utilisation d'iSNS, ignoré sinon.

iSNS On

Active iSNS. La seule valeur valide est « On ». Par défaut : off.

incomingdiscoveryuser <user> <userpassword>

Définit le paramètre d'authentification de découverte entrante iscsi. Si aucune valeur n'est donnée, aucune authentification n'est effectuée.

outgoingdiscoveryuser <user> <userpassword>

Définit le paramètre d'authentification de découverte sortante iscsi. Si aucune valeur n'est donnée, aucune authentification n'est effectuée.

DIRECTIVES DE NIVEAU CIBLE

Chaque cible peut exporter plusieurs périphériques bloc, ou unités logiques (LUNs). Aux fins de la numérotation des LUNs, les directives backing-store sont traitées avant les directives direct-store.

backing-store <path>

Définit une unité logique (LUN) exportée par la cible. Ceci peut spécifier soit un fichier régulier, soit un périphérique bloc.

direct-store <path>

Définit une unité logique mappée directement (LUN) avec les mêmes propriétés que le périphérique physique (telles que VENDOR_ID, SERIAL_NUM, etc.).

driver <lld>

Définit le pilote de bas niveau à utiliser pour cette cible, « iscsi » ou « iser » (sans guillemets). Ceci remplace la directive globale « default-driver ».

initiator-address <addr>

Autorise les connexions uniquement depuis l'adresse IP spécifiée. Par défaut ALL si aucune directive initiator-address n'est spécifiée.

initiator-name <addr>

Autorise les connexions uniquement depuis le nom d'initiateur spécifié.

incominguser <user> <userpassword>

Définit le paramètre d'authentification entrante iscsi. Si aucun « incominguser » n'est spécifié, il n'est pas utilisé. Cette directive peut être utilisée plusieurs fois par cible.

outgoinguser <user> <userpassword>

Définit le paramètre d'authentification sortante iscsi. Si aucun « outgoinguser » n'est spécifié, il n'est pas utilisé. Cette directive peut être utilisée plusieurs fois par cible.

controller_tid <val>

Définit le tid du contrôleur. Par défaut, le prochain entier disponible.

DIRECTIVES DE NIVEAU LUN

Toutes ces directives peuvent être listées au niveau de la cible (et s'appliquer à toutes les LUNs) ou à l'intérieur de la définition d'une LUN individuelle, si elle est définie en utilisant le format de définition multi-lignes de style conteneur, plutôt que le format de définition sur une seule ligne :

<backing-store /dev/sdb1>
  # Les directives LUN vont ici
</backing-store>
<direct-store /dev/sdb1>
  # Les directives LUN vont ici
</direct-store>

Il est recommandé d'utiliser soit des définitions de LUN sur une seule ligne, soit de style conteneur, à l'intérieur d'une cible. Le mélange des styles peut entraîner des erreurs d'analyse.

write-cache <val>

« on » ou « off », par défaut on.

scsi_id <val>

scsi_sn <val>

vendor_id <val>

product_id <val>

product_rev <val>

sense_format <val>

removable <val>

path <val>

mode_page <val>

readonly <val>

device-type <val>

bs-type <val>

allow-in-use <val>

block-size <val>

Spécifie la taille du bloc pour cette LUN.

lbppbe <val>

Spécifie l'exposant des blocs logiques par bloc physique. Par défaut, TGTD configurera le lbppbe pour correspondre automatiquement au système de fichiers sous-jacent. Utilisez ce paramètre pour remplacer ce réglage.

Ceci est une option interne qui ne devrait pas être définie directement.

la_lba <val>

Spécifie l'adresse de bloc logique alignée la plus basse. Ceci est une option interne qui ne devrait pas être définie directement.

optimal_xfer_gran <val>

Spécifie la granularité de transfert optimale, à refléter dans le VPD des limites de bloc. Ceci est une option interne qui ne devrait pas être définie directement.

optimal_xfer_len <val>

Spécifie la longueur de transfert optimale, à refléter dans le VPD des limites de bloc. Ceci est une option interne qui ne devrait pas être définie directement.

params <vals>

Passe des paramètres supplémentaires à tgtadm.

Notez que '${tid}' et '${lun}' peuvent être utilisés textuellement pour faire référence au tid et à la lun qui sont configurés. Voir targets.conf.vtl.L700 pour un exemple.

EXEMPLE DE FICHIER DE CONFIGURATION

Exemple de fichier de configuration :
<target iqn.2007-04.com.example:san.monitoring>
  backing-store /dev/san/monitoring
  # si aucun "incominguser" n'est spécifié, il n'est pas utilisé
  incominguser backup secretpass12
  # par défaut ALL si aucune "initiator-address" n'est spécifiée
  initiator-address 192.168.1.2
</target>
<target iqn.2007-02.com.example:san.xen1>
  backing-store /dev/san/xen1-disk1 # LUN1
  direct-store /dev/san/xen1-disk2  # LUN2
  initiator-address 192.168.1.2     # IP autorisée
  initiator-address 192.168.5.6     # IP autorisée
  incominguser user1 secretpass12
  incominguser user2 secretpass23
  outgoinguser userA secretpas
