TALK(1P) Manuel du programmeur POSIX TALK(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

talk — parler à un autre utilisateur

SYNOPIS

talk adresse [terminal]

DESCRIPTION

L'utilitaire talk est un programme de communication bidirectionnel, orienté écran.

Lors de sa première invocation, talk envoie un message similaire à :

Message de <chaîne non spécifiée>
talk: demande de connexion par votre_adresse
talk: répondez avec : talk votre_adresse

À ce stade, le destinataire du message peut répondre en tapant :

talk votre_adresse

Une fois la communication établie, les deux parties peuvent taper simultanément, leur sortie étant affichée dans des régions séparées de l'écran. Les caractères sont traités comme suit :

*
Taper le caractère <alert> (sonnerie) alertera le terminal du destinataire.
*
Taper <control>‐L provoquera le rafraîchissement des régions de l'écran de l'expéditeur.
*
Taper les caractères d'effacement (erase) et d'élimination (kill) affectera le terminal de l'expéditeur de la manière décrite par l'interface termios dans le volume Définitions de base de POSIX.1‐2017, Chapitre 11, Interface générale de terminal.
*
Taper les caractères d'interruption (interrupt) ou de fin de fichier (end-of-file) terminera l'utilitaire talk local. Une fois la session talk terminée d'un côté, l'autre partie de la session talk sera notifiée que la session talk est terminée et ne pourra rien faire d'autre que de se quitter.
*
Taper des caractères des classifications LC_CTYPE print (imprimable) ou space (espace) provoquera l'envoi de ces caractères au terminal du destinataire.
*
Quand et seulement quand le mode local stty iexten est activé, l'existence et le traitement de caractères de contrôle spéciaux supplémentaires et de fonctions multi-octets ou mono-octet sont définis par l'implémentation.
*
Taper d'autres caractères non imprimables provoquera l'envoi de séquences de caractères imprimables définies par l'implémentation au terminal du destinataire.

La permission d'être destinataire d'un message talk peut être refusée ou accordée en utilisant l'utilitaire mesg. Cependant, les privilèges d'un utilisateur peuvent restreindre davantage le domaine d'accessibilité des terminaux d'autres utilisateurs. L'utilitaire talk échouera lorsque l'utilisateur n'aura pas les privilèges appropriés pour effectuer l'action demandée.

Certains terminaux en mode bloc n'ont pas toutes les capacités nécessaires pour prendre en charge l'échange simultané de messages requis pour talk. Lorsque ce type d'échange ne peut pas être pris en charge sur de tels terminaux, l'implémentation peut prendre en charge un échange avec des niveaux d'interaction simultanée réduits ou signaler une erreur décrivant la déficience liée au terminal.

OPTIONS

Aucune.

OPÉRANDES

Les opérandes suivants seront pris en charge :

adresse
Le destinataire de la session talk. Une forme d'<adresse> est le <nom d'utilisateur>, tel que retourné par l'utilitaire who. D'autres formats d'adresse et leur traitement ne sont pas spécifiés.
terminal
Si le destinataire est connecté plus d'une fois, l'argument terminal peut être utilisé pour indiquer le nom du terminal approprié. Si terminal n'est pas spécifié, le message talk sera affiché sur un ou plusieurs terminaux accessibles utilisés par le destinataire. Le format de terminal sera le même que celui retourné par l'utilitaire who.

STDIN

Les caractères lus depuis l'entrée standard seront copiés vers le terminal du destinataire d'une manière non spécifiée. Si l'entrée standard n'est pas un terminal, talk affichera un message de diagnostic et se terminera avec un statut non nul.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de talk :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée). Si la locale du destinataire n'utilise pas un LC_CTYPE équivalent à celui de l'expéditeur, les résultats sont indéfinis.
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard et des messages informatifs écrits sur la sortie standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
TERM
Détermine le nom du type de terminal de l'invocateur. Si cette variable n'est pas définie ou est nulle, un type de terminal par défaut non spécifié sera utilisé.

ÉVÉNEMENTS ASYNCHRONES

Lorsque l'utilitaire talk reçoit un signal SIGINT, l'utilitaire se termine et se quitte avec un statut zéro. Il prend l'action standard pour tous les autres signaux.

STDOUT

Si la sortie standard est un terminal, les caractères copiés depuis l'entrée standard du destinataire peuvent être écrits sur la sortie standard. La sortie standard peut également être utilisée pour les messages de diagnostic. Si la sortie standard n'est pas un terminal, talk se terminera avec un statut non nul.

STDERR

Aucun.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite ou talk a été invoqué sur un terminal incapable de le supporter.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

talk(1p) — talk — POSIX utility

PROLOG

This manual page is a translation of the POSIX standard document and is provided for informational purposes only. In case of a discrepancy, the POSIX standard is the definitive source.

NAME

talk — talk to another user

SYNOPSIS

talk tname [file]

DESCRIPTION

The talk utility shall allow a user to have a two-way communication with another user logged in on the same or a different host. The tname argument specifies the recipient. It can be a terminal name (as used by write) or a user name (which implies the controlling terminal of that user). If the user is logged in on a different host, tname shall be in the form user@host or host:user.

If the recipient is logged in on the same host, tname can be the name of the recipient's terminal. In this case, the recipient's terminal is opened, and a message indicating that the calling user wishes to talk is sent.

If the recipient is logged in on a different host, the talk client running on the local host shall attempt to contact the talk daemon (talkd) on the remote host.

The file argument is the name of a TTY device file to which the current user's terminal is connected.

When the recipient accepts the call, the screen is split into two sections. The top section is for the recipient's messages, and the bottom section is for the calling user's messages. Keystrokes typed by each user are displayed in their respective sections.

The talk utility shall handle control character sequences.

EXAMPLES

None.

RATIONALE

The write utility was included in this volume of POSIX.1‐2017 since it can be implemented on all terminal types. The talk utility, which cannot be implemented on certain terminals, was considered to be a ``better'' communications interface. Both of these programs are in widespread use on historical implementations. Therefore, both utilities have been specified.

All references to networking abilities (talking to a user on another system) were removed as being outside the scope of this volume of POSIX.1‐2017.

Historical BSD and System V versions of talk terminate both of the conversations when either user breaks out of the session. This can lead to adverse consequences if a user unwittingly continues to enter text that is interpreted by the shell when the other terminates the session. Therefore, the version of talk specified by this volume of POSIX.1‐2017 requires both users to terminate their end of the session explicitly.

Only messages sent to the terminal of the invoking user can be internationalized in any way:

*
The original “Message from <unspecified string> …” message sent to the terminal of the recipient cannot be internationalized because the environment of the recipient is as yet inaccessible to the talk utility. The environment of the invoking party is irrelevant.
*
Subsequent communication between the two parties cannot be internationalized because the two parties may specify different languages in their environment (and non-portable characters cannot be mapped from one language to another).
*
Neither party can be required to communicate in a language other than C and/or the one specified by their environment because unavailable terminal hardware support (for example, fonts) may be required.

The text in the STDOUT section reflects the usage of the verb “display” in this section; some talk implementations actually use standard output to write to the terminal, but this volume of POSIX.1‐2017 does not require that to be the case.

The format of the terminal name is unspecified, but the descriptions of ps, talk, who, and write require that they all use or accept the same format.

The handling of non-printable characters is partially implementation-defined because the details of mapping them to printable sequences is not needed by the user. Historical implementations, for security reasons, disallow the transmission of non-printable characters that may send commands to the other terminal.

FUTURE DIRECTIONS

None.
