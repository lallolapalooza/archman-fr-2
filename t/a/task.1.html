NOM

task - Un gestionnaire de liste de tâches en ligne de commande.

SYNTAXE

task <filtre> <commande> [ <mods> | <args> ]
task --version

DESCRIPTION

Taskwarrior est un gestionnaire de liste de tâches en ligne de commande. Il maintient une liste de tâches que vous souhaitez accomplir, vous permettant de les ajouter/supprimer et de les manipuler. Taskwarrior dispose d'un riche ensemble de sous-commandes qui vous permettent de faire diverses choses avec lui.

Au cœur, Taskwarrior est un programme de traitement de listes. Vous ajoutez du texte et des paramètres associés supplémentaires et réaffichez les informations d'une manière agréable. Il devient un programme de liste de tâches lorsque vous ajoutez des dates d'échéance et la récurrence. Il devient un programme de liste de tâches organisée lorsque vous ajoutez des priorités, des étiquettes (descripteurs en un mot), des groupes de projets, etc.

FILTRE

Le <filtre> se compose de zéro ou plusieurs critères de recherche qui sélectionnent les tâches. Par exemple, pour lister toutes les tâches en attente appartenant au projet 'Home' :

  task project:Home list

Vous pouvez spécifier plusieurs termes de filtre, chacun restreignant davantage le résultat :

  task project:Home +weekend garden list

Cet exemple applique trois filtres : le projet 'Home', l'étiquette 'weekend', et la description ou les annotations doivent contenir la séquence de caractères 'garden'. Dans cet exemple, 'garden' est traduit interneent en :

  description.contains:garden

comme raccourci pratique. Le 'contains' ici est un modificateur d'attribut, utilisé pour exercer plus de contrôle sur le filtre que la simple absence ou présence. Voir la section 'MODIFICATEURS D'ATTRIBUT' ci-dessous pour une liste complète des modificateurs.

Notez qu'un filtre peut avoir zéro terme, ce qui signifie que toutes les tâches s'appliquent à la commande. Cela peut être dangereux, et ce cas spécial est confirmé et ne peut être annulé. Par exemple, cette commande :

  task modify +work
  Cette commande n'a pas de filtre et modifiera toutes les tâches. Êtes-vous sûr ? (oui/non)

ajoutera l'étiquette 'work' à toutes les tâches, mais seulement après confirmation.

Plus d'exemples de filtres :

  task                                      <commande> <mods>
  task 28                                   <commande> <mods>
  task +weekend                             <commande> <mods>
  task +bills due.by:eom                    <commande> <mods>
  task project:Home due.before:today        <commande> <mods>
  task ebeeab00-ccf8-464b-8b58-f7f2d606edfb <commande> <mods>

Par défaut, les éléments du filtre sont combinés avec un opérateur 'et' implicite, mais 'ou' et 'xor' peuvent également être utilisés, à condition que des parenthèses soient incluses :

  task '( /[Cc]at|[Dd]og/ or /[0-9]+/ )'      <commande> <mods>

Les parenthèses isolent le terme logique de tout filtre de commande par défaut ou filtre de rapport implicite qui serait combiné avec un 'et' implicite.

Un filtre peut cibler des tâches spécifiques en utilisant des numéros d'ID ou d'UUID. Pour spécifier plusieurs tâches, utilisez l'une des formes suivantes (liste séparée par des espaces de numéros d'ID, de numéros d'UUID ou de plages d'ID) :

  task 1 2 3                                    delete
  task 1-3                                      info
  task 1 2-5 19                                 modify pri:H
  task 4-7 ebeeab00-ccf8-464b-8b58-f7f2d606edfb info

Notez qu'il peut être nécessaire d'échapper correctement les caractères spéciaux ainsi que les guillemets afin d'éviter leurs significations spéciales dans le shell. Voir également la section 'SPÉCIFICATION DES DESCRIPTIONS' pour plus d'informations.

MODIFICATIONS

Les <mods> se composent de zéro ou plusieurs changements à appliquer aux tâches sélectionnées, tels que :

  task <filtre> <commande> project:Home
  task <filtre> <commande> +weekend +garden due:tomorrow
  task <filtre> <commande> Texte de description/annotation
  task <filtre> <commande> /de/vers/     <- remplacer la première occurrence
  task <filtre> <commande> /de/vers/g    <- remplacer toutes les occurrences

SOUS-COMMANDES

Taskwarrior prend en charge différents types de commandes. Il existe des commandes de lecture, des commandes d'écriture, des commandes diverses et des commandes d'aide aux scripts. Les commandes de lecture ne permettent pas la modification des tâches. Les commandes d'écriture peuvent modifier presque tous les aspects d'une tâche. Les commandes d'aide aux scripts sont fournies pour vous aider à écrire des scripts complémentaires, par exemple, la complétion automatique du shell (seule une sortie minimale est générée, comme avec verbose=nothing). Les commandes qui sont explicitement affectées par le contexte sont indiquées comme telles.

SOUS-COMMANDES DE LECTURE

Les rapports sont des sous-commandes de lecture. Il existe plusieurs rapports prédéfinis dans Taskwarrior. La sortie et le comportement de tri de ces rapports peuvent être configurés dans le fichier de configuration. Voir également la page man taskrc(5). Il existe également d'autres sous-commandes de lecture qui ne sont pas des rapports.

task --version
C'est le seul argument de ligne de commande conventionnel que Taskwarrior prend en charge, et il est destiné aux scripts complémentaires pour vérifier le numéro de version d'une installation de Taskwarrior sans invoquer les mécanismes qui créent des fichiers par défaut.

task <filtre> burndown.monthly

task calendar [due|<mois> <année>|<année>] [a]

Si un mois et une année sont spécifiés ('6 2015'), alors les mois affichés commenceront au mois et à l'année spécifiés. Si l'argument 'due' est fourni, il affichera le mois de début de la tâche échue la plus ancienne.
task colors [<échantillon> | légende]

task <filtre> ids
Applique le filtre puis extrait uniquement les identifiants de tâche et les présente sous forme d'une liste séparée par des espaces. Ceci est utile comme entrée pour une commande task, pour réaliser ceci : 
  task $(task project:Home ids) modify priority:H

Cet exemple obtient d'abord les identifiants pour le filtre project:Home, puis définit la priorité sur H pour chacune de ces tâches. Ceci peut aussi être réalisé directement :

  task project:Home modify priority:H

Cette commande est principalement utile pour les scripts externes.

task <filtre> uuids
Applique le filtre sur toutes les tâches (même les tâches supprimées et terminées) puis extrait uniquement les UUIDs de tâche et les présente sous forme d'une liste séparée par des espaces. Ceci est utile comme entrée pour une commande task, pour réaliser ceci : 
  task $(task project:Home status:completed uuids) modify status:pending

Cet exemple obtient d'abord les UUIDs pour les filtres project:Home et status:completed, puis remet chacune de ces tâches en attente à nouveau.

Cette commande est principalement utile pour les scripts externes.

SOUS-COMMANDES D'ÉCRITURE

task add <mods>
Ajoute une nouvelle tâche en attente à la liste des tâches. Elle est affectée par le contexte actuellement défini.
task <filtre> annotate <mods>
Ajoute une annotation à une tâche existante.
task <filtre> append <mods>
Ajoute du texte de description à la fin d'une tâche existante.
task <filtre> delete <mods>
Supprime la tâche spécifiée de la liste des tâches. Est affectée par le contexte.
task <filtre> denotate <mods>
Supprime une annotation pour la tâche spécifiée. Si la description fournie correspond exactement à une annotation, l'annotation correspondante est supprimée. Si la description fournie correspond partiellement à des annotations, la première annotation partiellement correspondante est supprimée. Est affectée par le contexte.
task <filtre> done <mods>
Marque la tâche spécifiée comme terminée. Est affectée par le contexte.
task <filtre> duplicate <mods>
Duplique la tâche spécifiée et permet des modifications. Est affectée par le contexte.
task <filtre> edit
Lance un éditeur de texte pour modifier directement tous les aspects d'une tâche. En général, ce n'est pas la méthode recommandée pour modifier les tâches, mais elle est fournie pour des circonstances exceptionnelles. À utiliser avec prudence. Est affectée par le contexte.
task import [<fichier> ...]
Importe des tâches au format JSON. Peut être utilisé pour ajouter de nouvelles tâches ou mettre à jour celles existantes. Les tâches sont identifiées par leur UUID.

Si aucun fichier ou "-" n'est spécifié, importe les tâches depuis STDIN.

Il est recommandé de définir rc.recurrence.confirmation à un niveau approprié si l'importation doit être utilisée dans des flux de travail automatisés. Voir taskrc(5).

Pour importer d'autres formats de fichiers, la version standard de task est fournie avec quelques exemples de scripts, tels que :

  import-todo.sh.pl
  import-yaml.pl
task import-v2
Importe les tâches du format Taskwarrior v2.x. Ceci est utilisé lors de la mise à niveau de la version 2.x à la version 3.x.
task log <mods>
Ajoute une nouvelle tâche déjà terminée à la liste des tâches. Elle est affectée par le contexte actuellement défini.
task <filtre> modify <mods>
Modifie la tâche existante avec les informations fournies.
task <filtre> prepend <mods>
Ajoute du texte de description au début d'une tâche existante. Est affecté par le contexte.
task <filtre> purge
Supprime définitivement les tâches spécifiées des fichiers de données. Seules les tâches déjà supprimées peuvent être purgées. Cette commande a un effet local uniquement et les modifications qu'elle introduit ne sont pas synchronisées. Est affectée par le contexte.

Avertissement : provoque une perte de données permanente et irréversible.

task <filtre> start <mods>
Marque les tâches spécifiées comme démarrées. Est affectée par le contexte.
task <filtre> stop <mods>
Supprime le temps de *démarrage* de la tâche spécifiée. Est affectée par le contexte.

SOUS-COMMANDES DIVERS

Les sous-commandes diverses n'acceptent aucun argument en ligne de commande, ou acceptent des arguments non standard.

task calc <expression>
Évalue une expression algébrique. Peut être utilisée pour tester comment Taskwarrior analyse et évalue l'expression donnée en ligne de commande.

Exemples :

    task calc 1 + 1
    2
    task calc now + 8d
    2015-03-26T18:06:57
    task calc eom
    2015-03-31T23:59:59
task config [<nom> [<;valeur> | '']]
Ajoute, modifie et supprime des paramètres directement dans la configuration de Taskwarrior. Cette commande modifie le paramètre 'nom' avec une nouvelle valeur 'valeur', ou ajoute une nouvelle entrée équivalente à 'nom=valeur' : 
    task config nom valeur

Cette commande définit une valeur vide. Cela a pour effet de supprimer toute valeur par défaut :

    task config nom ''

Enfin, cette commande supprime toute entrée 'nom=...' du fichier .taskrc :

    task config nom
task context <nom>
Définit le contexte actif actuel. Voir la section CONTEXTE.

Exemple :

    task context travail
task context delete <nom>
Supprime le contexte nommé <nom>. Si le contexte en cours de suppression est actuellement défini comme actif, il sera désactivé.

Exemple :

    task context delete travail
task context define <nom> <filtre>
Définit un nouveau contexte nommé <nom> avec la définition <filtre>. Cette commande n'affecte pas le contexte actuellement défini, elle ajoute simplement une nouvelle définition de contexte.

Exemples :

    task context define travail projet:Travail
    task context define maison projet:Maison ou +maison
    task context define superurgent à_faire:aujourd'hui et +urgent
task context list
Affiche une liste des contextes disponibles avec leurs définitions.
task context none
Efface le contexte actif actuel, s'il y en avait un défini.
task context show
Affiche le contexte actif actuel, ainsi que sa définition.
task diagnostics
Affiche des informations de diagnostic, du type de celles nécessaires lors du signalement d'un problème. Lorsque vous signalez un bug, il est probable que la plateforme, la version et l'environnement soient importants. L'exécution de cette commande génère un résumé d'informations similaires qui devrait accompagner un rapport de bug.

Elle inclut des informations sur le compilateur, les bibliothèques et le logiciel. Elle n'inclut aucune information personnelle, autre que l'emplacement de vos données de tâches.

Cette commande effectue également un scan de diagnostic de vos données à la recherche de problèmes courants, tels que des UUID dupliqués.

task execute <commande externe>
Exécute la commande spécifiée. Non utile en soi, mais lorsqu'elle est utilisée en conjonction avec des alias et des extensions, elle peut fournir une intégration transparente.
task logo
Affiche le logo de Taskwarrior.
task news
Guide l'utilisateur à travers les notes de version importantes chaque fois qu'une nouvelle version de Taskwarrior est installée. Elle fournit un retour personnalisé, des avertissements de dépréciation et des conseils d'utilisation, le cas échéant.
task reports
Liste tous les rapports pris en charge. Cela inclut les rapports intégrés et tous les rapports personnalisés que vous avez définis.
task show [all | <substring>]
Affiche tous les paramètres actuels. Si une sous-chaîne est spécifiée, seuls les paramètres contenant cette sous-chaîne seront affichés.
task <filtre> stats
Affiche les statistiques des tâches définies par le filtre. Est affecté par le contexte.
task <filtre> summary
Affiche un rapport de l'état agrégé des tâches par projet. Est affecté par le contexte.
task sync
La commande sync synchronise les données avec le Taskserver, s'il est configuré.

Note : Si vous utilisez plusieurs clients de synchronisation, assurez-vous que ce paramètre (qui est le défaut) est activé sur votre client principal :

  recurrence=on

et sur tous les autres clients (ce n'est pas le défaut) :

  recurrence=off

Ceci est une solution de contournement pour éviter un bug de récurrence qui duplique les tâches récurrentes.

task <filtre> tags
Affiche une liste de toutes les étiquettes utilisées. Toutes les étiquettes spéciales utilisées sont mises en évidence. Notez que les étiquettes virtuelles ne sont pas listées - elles n'existent pas réellement et ne sont qu'une notation pratique pour d'autres métadonnées de tâches. Il est erroné de tenter d'ajouter ou de supprimer une étiquette virtuelle. Est affecté par le contexte.
task timesheet [<semaines>]
Affiche un rapport hebdomadaire des tâches terminées et commencées.
task undo
Annule la dernière action. Respecte le paramètre de confirmation.
task version
Affiche le numéro de version de Taskwarrior.

task _get <DOM> [<DOM> ...]
Accède et affiche la ou les références DOM. Utilisé pour extraire des valeurs individuelles des tâches ou du système. Les références DOM prises en charge sont : 
  rc.<nom>
  tw.syncneeded
  tw.program
  tw.args
  tw.width
  tw.height
  tw.version
  context.program    (Obsolète en 2.6.0)
  context.args       (Obsolète en 2.6.0)
  context.width      (Obsolète en 2.6.0)
  context.height     (Obsolète en 2.6.0)

  system.os

Notez que la référence 'rc.<nom>' pourrait nécessiter d'être échappée à l'aide de '--' pour empêcher que la référence ne soit interprétée comme un remplacement.

De plus, certains composants des attributs de types particuliers peuvent être extraits par des références DOM.

  $ task _get 2.due.year
  2015

Pour une liste complète des références DOM spécifiques aux attributs prises en charge, consultez la documentation en ligne à l'adresse : https://taskwarrior.org/docs/dom.html

ATTRIBUTS ET MÉTADONNÉES

ID
Les tâches peuvent être spécifiées de manière unique par des identifiants, qui sont les index de l'"ensemble de travail" des tâches (principalement les tâches en attente et récurrentes). L'ID d'une tâche peut donc changer, mais uniquement lorsqu'un rapport affichant les IDs est exécuté. Lors de la modification de tâches, il est sûr de se fier au dernier ID affiché. Exécutez toujours un rapport pour vérifier que vous avez le bon ID pour une tâche. Les IDs peuvent être donnés à task sous forme de séquence, par exemple : 
task 1,4-10,19 delete
+tag|-tag
Les étiquettes sont des mots arbitraires associés à une tâche. Utilisez + pour ajouter une étiquette et - pour supprimer une étiquette d'une tâche. Une tâche peut avoir n'importe quelle quantité d'étiquettes.

Certaines étiquettes (appelées 'étiquettes spéciales') peuvent être utilisées pour affecter la façon dont les tâches sont traitées. Par exemple, si une tâche a l'étiquette spéciale 'nocolor', alors elle est exécuté

TAGS

Il existe trois types de balises : celles qui sont destinées à la gestion des tâches, celles qui représentent des métadonnées de tâches et celles qui sont destinées à la modification des attributs.

Les balises de gestion des tâches sont des chaînes de caractères qui n'ont pas de tiret ou de deux-points. Elles sont destinées à regrouper des tâches, mais ne peuvent pas être utilisées pour filtrer les tâches, sauf si la commande task est configurée pour ignorer toutes les règles de couleur. Les balises spéciales prises en charge sont :

    +nocolor     Désactive le traitement des règles de couleur pour cette tâche
    +nonag       L'achèvement de cette tâche supprime tous les messages de rappel
    +nocal       Cette tâche n'apparaîtra pas dans le calendrier
    +next        Fait remonter la tâche pour qu'elle apparaisse dans le rapport 'next'

Il existe également des balises virtuelles, qui représentent les métadonnées des tâches sous forme de balises. Ces balises n'existent pas, mais peuvent être utilisées pour filtrer les tâches. Les balises virtuelles prises en charge sont :

    ACTIVE       Correspond si la tâche est démarrée
    ANNOTATED    Correspond si la tâche a des annotations
    BLOCKED      Correspond si la tâche est bloquée
    BLOCKING     Correspond si la tâche bloque
    CHILD        Correspond si la tâche a un parent (déprécié en 2.6.0)
    COMPLETED    Correspond si la tâche a le statut complété
    DELETED      Correspond si la tâche a le statut supprimé
    DUE          Correspond si la tâche est due dans les 7 prochains jours (Voir rc.due)
    INSTANCE     Correspond si la tâche est une instance récurrente
    LATEST       Correspond si la tâche est la dernière tâche ajoutée
    MONTH        Correspond si la tâche est due ce mois-ci
    ORPHAN       Correspond si la tâche a des valeurs UDA orphelines
    OVERDUE      Correspond si la tâche est en retard
    PARENT       Correspond si la tâche est un parent (déprécié en 2.6.0)
    PENDING      Correspond si la tâche a le statut en attente
    PRIORITY     Correspond si la tâche a une priorité
    PROJECT      Correspond si la tâche a un projet
    QUARTER      Correspond si la tâche est due ce trimestre
    READY        Correspond si la tâche est actionnable
    SCHEDULED    Correspond si la tâche est planifiée
    TAGGED       Correspond si la tâche a des balises
    TEMPLATE     Correspond si la tâche est un modèle de récurrence
    TODAY        Correspond si la tâche est due aujourd'hui
    TOMORROW     Correspond si la tâche est due demain
    UDA          Correspond si la tâche a des valeurs UDA
    UNBLOCKED    Correspond si la tâche n'est pas bloquée
    UNTIL        Correspond si la tâche expire
    WAITING      Correspond si la tâche est en attente
    WEEK         Correspond si la tâche est due cette semaine
    YEAR         Correspond si la tâche est due cette année
    YESTERDAY    Correspond si la tâche était due hier

Vous pouvez utiliser +BLOCKED pour filtrer les tâches bloquées, ou -BLOCKED pour les tâches débloquées. De même, -BLOCKED est équivalent à +UNBLOCKED. Il est erroné de tenter d'ajouter ou de supprimer une balise virtuelle.

project:<nom-projet>
Spécifie le projet auquel une tâche est liée.
status:pending|deleted|completed|waiting|recurring
Spécifie l'état de la tâche.
priority:H|M|L ou priority:
Spécifie la priorité Haute, Moyenne, Basse et aucune priorité pour une tâche.
due:<date-limite>
Spécifie la date limite d'une tâche.
recur:<fréquence>
Spécifie la fréquence d'une récurrence d'une tâche.
scheduled:<date-prête>
Spécifie la date après laquelle une tâche peut être accomplie.
until:<date-d'expiration de tâche>
Spécifie la date d'expiration d'une tâche, après laquelle elle sera supprimée.
limit:<nombre-de-lignes>
Spécifie le nombre de tâches souhaité qu'un rapport doit afficher, si un entier positif est donné. La valeur 'page' peut également être utilisée et limitera la sortie du rapport à autant de lignes de texte qu'il en tiendra sur l'écran. La valeur par défaut est 25 lignes.
wait:<date-d'attente>
Lorsqu'une tâche reçoit une date d'attente, elle est masquée de la plupart des rapports intégrés, qui excluent +WAITING. Lorsque la date est passée, la tâche n'est plus considérée comme +WAITING et redevient visible. Notez que, pour des raisons de compatibilité, ces tâches sont affichées avec le statut "waiting", mais cela changera dans une future version.
depends:<id1,id2 ...>
Déclare que cette tâche dépend de id1 et id2. Cela signifie que les tâches id1 et id2 doivent être complétées avant cette tâche. Par conséquent, cette tâche apparaîtra dans le rapport 'blocked'. Il accepte une liste d'identifiants numériques, d'identifiants UUID et de plages d'identifiants séparés par des virgules. En préfixant un élément de cette liste par '-', les tâches spécifiées sont retirées de la liste de dépendances.
entry:<date-de-création>
Pour des fins de rapport, spécifie la date à laquelle une tâche a été créée.
modified:<date-de-modification>
Spécifie la date de modification la plus récente.

MODIFICATEURS D'ATTRIBUTS

Les modificateurs d'attributs améliorent les filtres. Les modificateurs pris en charge sont :

before (synonymes under, below)
after (synonymes over, above)
by
none
any
is (synonyme equals)
isnt (synonyme not)
has (synonyme contains)
hasnt
startswith (synonyme left)
endswith (synonyme right)
word
noword

Ils peuvent être appliqués à tous les attributs réguliers (voir ci-dessus) et aux attributs calculés suivants :

urgency (ou abrégé urg)

Par exemple :

    task due.before:eom priority.not:L list

Le modificateur before est utilisé pour comparer des valeurs, en conservant la sémantique, donc project.before:B liste tous les projets qui commencent par 'A'. La priorité 'L' est avant 'M', et due:2011-01-01 est avant due:2011-01-02. Les synonymes 'under' et 'below' sont inclus pour permettre des filtres plus naturels.

Le modificateur after est l'inverse du modificateur before.

Le modificateur by est identique à 'before', sauf qu'il inclut également le moment en question. Par exemple :

    task add test due:eoy

sera trouvé lors de l'utilisation du filtre inclusif 'by' :

    task due.by:eoy

mais pas lorsque le filtre non inclusif 'before' est utilisé :

    task due.before:eoy

cela s'applique également à d'autres dates nommées telles que 'eom', 'eod', etc. ; le modificateur compare en utilisant '<=' plutôt que '<' comme le fait 'before'.

Le modificateur none exige que l'attribut n'ait pas de valeur. Par exemple :

    task priority:      list
    task priority.none: list

sont équivalents et listent les tâches qui n'ont pas de priorité.

Le modificateur any exige que l'attribut ait une valeur, mais n'importe quelle valeur suffit.

Le modificateur is exige une correspondance exacte avec la valeur.

Le modificateur isnt est l'inverse du modificateur is.

Le modificateur has est utilisé pour rechercher une sous-chaîne, par exemple :

    task description.has:foo list
    task foo                 list

Ces commandes sont équivalentes et renverront toute tâche qui contient 'foo' dans sa description ou ses annotations.

Le modificateur hasnt est l'inverse du modificateur has.

Le modificateur startswith correspond au début d'un attribut, de sorte que :

    task project.startswith:H list
    task project:H            list

sont équivalents et correspondront à tout projet commençant par 'H'. La correspondance de tous les projets ne commençant pas par 'H' se fait avec :

    task project.not:H         list

Le modificateur endswith correspond à la fin d'un attribut.

Le modificateur word exige que l'attribut contienne le mot entier spécifié, de sorte que ceci :

    task description.word:foo list

correspondra à la description 'foo bar baz' mais ne correspondra pas à 'dog food'.

Le modificateur noword est l'inverse du modificateur word.

EXPRESSIONS ET OPÉRATEURS

Vous pouvez utiliser les opérateurs suivants dans les expressions de filtre :

  and  or  xor  !               Opérateurs logiques
  <  <=  =  ==  !=  !==  >=  >  Opérateurs relationnels
  (  )                          Priorité

Par exemple :

  task due.before:eom priority.not:L list
  task '( due < eom or priority != L )' list
  task '! ( project:Home or project:Garden )' list

L'opérateur = teste l'égalité approximative. Les dates correspondent si elles sont le même jour (l'heure et les minutes sont ignorées). Les chaînes correspondent si l'opérande gauche commence par l'opérande droit. L'opérateur == teste l'égalité exacte. Les opérateurs != et !== sont la négation de = et == respectivement. L'opérateur de négation est !.

Notez que les parenthèses sont nécessaires lors de l'utilisation d'un opérateur logique autre que l'opérateur 'and'. La raison est que certains rapports contiennent des filtres qui doivent être combinés avec la ligne de commande. Considérez cet exemple :

  task project:Home or project:Garden list

Bien que cela semble correct, ce n'est pas le cas. Le rapport 'list' contient un filtre de :

  task show report.list.filter
  Config Variable    Value
  -----------------  --------------
  report.list.filter status:pending

Ce qui signifie que l'exemple est en réalité :

  task status:pending project:Home or project:Garden list

L'opérateur 'and' implicite en fait :

  task status:pending and project:Home or project:Garden list

Ceci est une erreur de précédence - 'and' et 'or' doivent être regroupés à l'aide de parenthèses, comme ceci :

  task status:pending and ( project:Home or project:Garden ) list

L'exemple original doit donc être saisi comme suit :

  task '( project:Home or project:Garden )' list

Cela inclut des guillemets pour échapper les parenthèses, afin que le shell ne les interprète pas et ne les cache pas à Taskwarrior.

Il y a de la redondance entre les opérateurs, les modificateurs d'attributs et d'autres syntaxes simplifiées. Par exemple, les commandes suivantes sont toutes équivalentes :

  task foo                      list
  task /foo/                    list
  task description.contains:foo list
  task description.has:foo      list
  task 'description ~ foo'

CONTEXTE

Le contexte est une requête définie par l'utilisateur, qui est automatiquement appliquée à toutes les commandes qui filtrent la liste des tâches et aux commandes qui créent de nouvelles tâches (ajouter, enregistrer). Par exemple, toute commande de rapport sera affectée par le contexte actif actuel. Voici une liste des commandes affectées :

    add
    burndown
    count
    delete
    denotate
    done
    duplicate
    edit
    history
    log
    prepend
    projects
    purge
    start
    stats
    stop
    summary
    tags

Toutes les autres commandes NE sont PAS affectées par le contexte.

    $ task list
    ID Age Project  Description        Urg
    1  2j  Sport    Run 5 miles        1.42
    2  1j  Home     Clean the dishes   1.14
    $ task context home
    Context 'home' défini. Utilisez 'task context none' pour le supprimer.
    $ task list
    ID Age Project  Description        Urg
    2  1j  Home     Clean the dishes   1.14
    Context 'home' défini. Utilisez 'task context none' pour le supprimer.

La liste des tâches a été automatiquement filtrée pour le projet : Maison.

    $ task add Vaccuum the carpet
    Tâche 3 créée.
    Context 'home' défini. Utilisez 'task context none' pour le supprimer.
    $ task list
    ID Age Project  Description        Urg
    2  1j  Home     Clean the dishes   1.14
    3  5s  Home     Vaccuum the carpet 1.14
    Context 'home' défini. Utilisez 'task context none' pour le supprimer.

Notez que la nouvelle tâche ajoutée "Vaccuum the carpet" a automatiquement le "project:Home" défini.

Comme vu dans l'exemple ci-dessus, le contexte est appliqué en spécifiant son nom à la commande "context". Pour changer le contexte actuellement appliqué, passez simplement le nom du nouveau contexte à la commande 'context'.

Pour désactiver tout contexte, utilisez la sous-commande 'none'.

    $ task context none
    Contexte désactivé.
    $ task list
    ID Age Project  Description         Urg
    1  2j  Sport    Run 5 miles         1.42
    2  1j  Home     Clean the dishes    1.14
    3  7s  Home     Vaccuum the carpet  1.14

Les contextes peuvent être définis en utilisant la sous-commande 'define', en spécifiant à la fois le nom du nouveau contexte et son filtre attribué.

    $ task context define home project:Home
    Êtes-vous sûr de vouloir ajouter 'context.home.read' avec la valeur 'project:Home' ? (oui/non) oui
    Êtes-vous sûr de vouloir ajouter 'context.home.write' avec la valeur 'project:Home' ? (oui/non) oui
    Contexte 'home' défini avec succès.

Notez que vous avez été invité séparément à définir le contexte 'lecture' et 'écriture'. Cela vous permet de spécifier des contextes qui ne fonctionnent que pour les commandes de rapport ou uniquement pour les commandes qui créent des tâches.

Pour supprimer la définition, utilisez la sous-commande 'delete'.

    $ task context delete home
    Êtes-vous sûr de vouloir supprimer 'context.home.read' ? (oui/non) oui
    Êtes-vous sûr de vouloir supprimer 'context.home.write' ? (oui/non) oui
    Contexte 'home' supprimé.

Pour vérifier quel est le contexte actuellement actif, utilisez la sous-commande 'show'.

    $ task context show
    Le contexte 'home' avec
    * filtre de lecture : '+home'
    * filtre d'écriture : '+home'
    est actuellement appliqué.

Les contextes peuvent stocker des filtres arbitrairement complexes.

    $ task context define family project:Family or +paul or +nancy
    Êtes-vous sûr de vouloir ajouter 'context.family.read' avec la valeur 'project:Family or +paul or +nancy' ? (oui/non) oui
    Êtes-vous sûr de vouloir ajouter 'context.family.write' avec la valeur 'project:Family or +paul or +nancy' ? (oui/non) non
    Contexte 'family' défini avec succès.

Notez que vous avez décidé de ne pas définir le filtre complexe comme contexte d'écriture. La raison de cette décision est que le filtre complexe dans l'exemple ne se traduit pas directement par une modification. En fait, si un tel contexte est utilisé comme contexte d'écriture, voici ce qui se passe :

    $ task add Call Paul
    Tâche 4 créée.
    Context 'family' défini. Utilisez 'task context none' pour le supprimer.
    $ task 4 list
    ID Age  Project Tags       Description      Urg
     4 9min Family  nancy paul or or Call Paul    0

Il n'y a pas de correspondance claire entre le filtre complexe utilisé et les modifications (seul le projet doit-il être défini ? uniquement les tags ? les deux ?). De plus, notez la présence des opérateurs 'or' dans la description. Taskwarrior n'essaie pas de deviner l'intention de l'utilisateur, et au lieu de cela, l'utilisateur est invité à définir la variable "context.<nom>.write" pour expliciter son intention, par exemple :

    $ task config context.family.write project:Family
    Êtes-vous sûr de vouloir changer la valeur de 'context.family.write' de 'project:Family or +paul or +nancy' à 'project:Family' ? (oui/non) oui
    Le fichier de configuration /home/tbabej/.config/task/taskrc a été modifié.
    $ task context
    Nom   Type  Définition                        Actif
    family read  project:Family or +paul or +nancy oui
           write project:Family                    oui
    home   read  +home                             non
           write +home                             non

Notez la différence entre les contextes de lecture et d'écriture pour le contexte "family", tandis que pour le contexte "home", ils restent les mêmes.

De plus, chaque paramètre de configuration peut être remplacé pour le contexte actuel, en spécifiant context.<nom>.rc.<paramètre>. Par exemple, si la commande par défaut pour le contexte familial doit afficher le rapport familial :

    $ task config context.family.rc.default.command family_report

ABRÉVIATION DES COMMANDES

Toutes les commandes Taskwarrior peuvent être abrégées tant qu'un préfixe unique est utilisé, par exemple :

  $ task li

est une abréviation sans ambiguïté pour

  $ task list

mais

  $ task l

pourrait être list, ls ou long.

Notez que vous pouvez restreindre la taille minimale d'abréviation en utilisant le paramètre de configuration :

  abbreviation.minimum=3

SPÉCIFICATION DES DESCRIPTIONS

Certaines descriptions de tâches doivent être échappées en raison du shell et de la signification spéciale de certains caractères pour le shell. Cela peut être fait soit en ajoutant des guillemets à la description, soit en échappant le caractère spécial :

  $ task add "guillemets ' guillemets"
  $ task add echappes \' guillemets

L'argument -- (un double tiret) indique à Taskwarrior de traiter tous les autres arguments comme une description :

  $ task add -- project:Home needs scheduling

Dans d'autres situations, le shell voit les espaces et divise les arguments. Par exemple, cette commande :

  $ t
task(1) — Arch manual pages

MODIFICATIONS

La commande task 123 modifier /de ceci/à cela/ est décomposée en plusieurs arguments, ce qui est corrigé avec des guillemets :

  $ task 123 modify "/de ceci/à cela/"

Il est parfois nécessaire de forcer le shell à passer les guillemets intacts à Taskwarrior, vous pouvez donc utiliser :

  $ task add project:\'Projet Trois Mots\' description

Taskwarrior prend en charge Unicode en utilisant uniquement l'encodage UTF8.

FICHIER DE CONFIGURATION ET OPTIONS DE REDEFINITION

Taskwarrior stocke sa configuration dans un fichier dans le répertoire personnel de l'utilisateur : ~/.taskrc. Le fichier de configuration par défaut peut être redéfini avec :

task rc:<chemin-vers-fichier-alternatif> ...
Spécifie un fichier de configuration alternatif avec la priorité la plus élevée.
TASKRC=<chemin-vers-fichier-alternatif> task ..
La variable d'environnement spécifie un fichier de configuration alternatif à utiliser.
XDG_CONFIG_HOME=<chemin-vers-domaine-config-alternatif> task ..
La variable d'environnement spécifie un fichier de configuration alternatif à utiliser.
task rc.<nom>:<valeur> ...
task rc.<nom>=<valeur> ... Spécifie des redéfinitions individuelles du fichier de configuration.
TASKDATA=/tmp/.task task ...
La variable d'environnement redéfinit le paramètre par défaut et le réglage de configuration 'data.location' du répertoire de données de tâches.
