FBB::Table(3bobcat) Génère des tableaux texte FBB::Table(3bobcat)

NOM

FBB::Table - Génère des tableaux remplis ligne par ligne ou colonne par colonne à partir d'informations insérées dans un std::ostream

SYNOPIS

#include <bobcat/tablebuf>
Option de liaison : -lbobcat

DESCRIPTION

Les objets FBB::Tablebuf sont des objets std::streambuf qui peuvent être utilisés pour créer des tableaux. Les tableaux sont remplis colonne par colonne ou ligne par ligne. Beaucoup des caractéristiques du tableau peuvent être affinées par un objet FBB::TableSupport distinct, décrit dans une page de manuel séparée (TableSupport(3bobcat)). Lorsqu'aucun objet FBB::TableSupport n'est utilisé, un simple tableau ligne par ligne ou colonne par colonne est construit et peut être inséré dans un std::ostream. L'affichage d'un tableau (par exemple, sur le flux de sortie standard) implique les étapes suivantes :

o
Optionnellement, un objet TableSupport est créé ;
o
Un objet Tablebuf est créé (en lui passant éventuellement un objet TableSupport) ;
o
L'objet Tablebuf est utilisé pour initialiser un std::ostream
o
Les éléments du tableau sont remplis en insérant des informations dans cet std::ostream
o
Le Tablebuf lui-même contient le tableau formaté et peut être inséré dans un std::ostream tel que std::cout.

Les tableaux définis par TableBuf se composent d'un nombre de lignes (dépendant du nombre d'éléments) et d'un nombre fixe de colonnes, cette dernière valeur étant spécifiée à la construction. Les colonnes et les lignes sont normalement adressées en utilisant des indices (commençant à 0). Avant la colonne la plus à gauche, entre les colonnes et après la dernière colonne, des séparateurs sont définis. Par défaut, les séparateurs sont vides, mais chaque séparateur peut recevoir une largeur ou un contenu (fixe). Le séparateur avant la colonne col est adressé comme séparateur col, le séparateur le plus à droite est adressé comme séparateur nColummns.

De même, les lignes peuvent être séparées les unes des autres à l'aide de séparateurs. Ces lignes de séparation sont également vides par défaut. Le séparateur de ligne avant la ligne row est adressé comme séparateur de ligne row. Le séparateur de ligne suivant la dernière ligne est adressé comme séparateur de ligne nRows, où nRows est la valeur retournée par la fonction membre nRows.

Les séparateurs non par défaut (c'est-à-dire non vides) sont définis en utilisant des objets FBB::TableSupport (cf. tablesupport(3bobcat)).

La classe sœur de TableBuf, Table, peut être utilisée pour insérer des éléments dans un tableau de manière plus directe. Avec TableBuf, des séparateurs de champs sont utilisés pour passer à l'élément de tableau suivant, et (avec les tableaux remplis ligne par ligne) un séparateur de ligne peut être utilisé pour passer à la ligne suivante lorsqu'elle est partiellement définie. Au lieu de cela, avec les objets Table, chaque nouvelle insertion définit un autre élément de tableau, et aucun flux std::ostream enveloppant n'est requis.

ESPACE DE NOMMAGE

FBB
Tous les constructeurs, membres, opérateurs et manipulateurs mentionnés dans cette page de manuel sont définis dans l'espace de nommage FBB.

HERITE DE

std::streambuf - permettant aux objets TableBuf d'être enveloppés dans des objets std::ostream.

FBB::TableBase - Cette classe implémente des éléments communs à l'implémentation du tableau (la classe FBB::TableBuf est également dérivée de TableBase). La classe TableBase n'est pas destinée à être utilisée autrement, et aucune page de manuel distincte n'est fournie. Toutes les facilités fournies par Table héritées de TableBase sont décrites dans cette page de manuel.

ENUMERATIONS

Les énumérations suivantes sont définies dans la classe FBB::Tablebuf.

enum FillDirection
Cette énumération a deux valeurs :

o
ROWWISE :
Lorsque cette valeur est spécifiée à la construction, les éléments sont ajoutés ligne par ligne au tableau. C'est-à-dire que le deuxième élément inséré dans le Table sera trouvé dans la deuxième colonne de la première ligne.
o
COLUMNWISE :
Lorsque cette valeur est spécifiée à la construction, les éléments sont ajoutés colonne par colonne au tableau. C'est-à-dire que le deuxième élément sera trouvé dans la deuxième ligne de la première colonne.

enum WidthType
Cette énumération contient deux valeurs :

o
COLUMNWIDTH :
Cette valeur peut être spécifiée lorsque les colonnes doivent avoir des largeurs variables. Dans ce cas, chaque colonne sera aussi large que son élément le plus large. C'est le WidthType par défaut utilisé par les objets Table.
o
EQUALWIDTH :
Cette valeur peut être spécifiée lorsque toutes les colonnes du tableau doivent avoir une largeur égale (c'est-à-dire égale à la largeur de l'élément de tableau le plus large),

CONSTRUCTEURS

o
Tablebuf(size_t nColumns, Table::FillDirection direction, Table::WidthType widthType = Table::COLUMNWIDTH) :
Le nombre de colonnes du tableau, les directions de remplissage et le type de largeur des colonnes doivent être fournis. Le nombre de lignes est implicite par la combinaison de ce paramètre et du nombre d'éléments qui est effectivement inséré dans l'objet Table. Le paramètre direction spécifie la manière dont les nouveaux éléments sont ajoutés à l'objet Table : ligne par ligne ou colonne par colonne. Enfin, le paramètre widthType est utilisé pour spécifier la manière dont la largeur des colonnes du tableau est déterminée. Chaque colonne définit sa propre largeur ou toutes les colonnes ont des largeurs égales.
o
TableBuf(TableSupport &tableSupport, Table::FillDirection direction, Table::WidthType widthType = Table::COLUMNWIDTH) :
Ce constructeur fonctionne de manière identique au constructeur précédent, mais attend une référence supplémentaire à un objet TableSupport. Un objet TableSupport offre des fonctionnalités de formatage supplémentaires utilisées par les éléments définissant le tableau, tels que les lignes horizontales entre les lignes, les séparateurs supplémentaires, etc. L'objet TableSupport est passé comme référence non constante car l'objet Table doit pouvoir manipuler ses données. Voir tablesuppport(3bobcat) pour plus d'informations sur TableSupport.

Les constructeurs et opérateurs d'affectation par copie et par déplacement ne sont pas disponibles.

OPÉRATEURS SURCHARGÉS

o
std::ostream &operator<<(std::ostream &out, TableBuf &tablebuf) :
Cet opérateur insère un TableBuf dans un objet std::ostream. Notez que l'objet TableBuf inséré dans out est un objet non constant, car le tableau peut devoir être complété en ajoutant des éléments vides pour ceux qui manquent. Le flux out ne doit pas être égal à l'objet std::ostream utilisé pour encapsuler un objet TableBuf.
o
TableBuf &operator<<(TableBuf &obj, Align const &align) :
Cet opérateur est utilisé pour modifier l'alignement par défaut d'une colonne ou d'un élément. C'est un wrapper autour de la fonction membre setAlign() (voir ci-dessous pour sa description). Par défaut, tous les éléments sont alignés à droite. Voir align(3bobcat) pour plus d'informations sur la classe Align. Contrairement aux opérateurs d'insertion disponibles pour les objets de type Table, l'opérateur d'insertion pour les objets TableBuf est uniquement utilisé pour définir l'alignement des colonnes ou des cellules.

MEMBER FUNCTIONS

o
void clear():
Le contenu du tableau est effacé. Tous les éléments existants sont supprimés, et le tableau sera vide.
o
size_t nRows():
Le nombre de lignes actuellement disponibles dans le tableau est renvoyé. Sa valeur n'est définie qu'après l'appel de def().
o
TableBuf &setAlign(Align const &align):
Le type d'alignement d'une colonne ou d'un élément de l'objet TableBuf est défini à l'aide de setAlign. Les alignements standard std::left, std::right et std::internal peuvent être spécifiés, mais en outre, l'alignement FBB::center peut être utilisé si les éléments doivent être centrés dans leur colonne. Une construction telle que 
tab << Align(2, FBB::center)
demande le centrage de tous les éléments de la colonne du tableau dont l'indice est 2 (c'est-à-dire la 3ème colonne du tableau), tandis qu'une construction telle que 
tab << Align(2, 3, FBB::center)
demande le centrage de l'élément [2][3]. Il incombe au programmeur de s'assurer que de tels éléments existent. Par défaut, tous les éléments sont alignés à droite.
o
TableBuf &def():
Après insertion d'éléments dans un objet TableBuf, son nombre d'éléments peut ou non être un multiple entier du nombre de colonnes spécifié lors de la construction. Pour `compléter' un objet TableBuf en un objet rectangulaire, pour lequel toutes les largeurs de colonnes et tous les alignements ont été déterminés, def peut être appelé. Il est appelé automatiquement par operator<<(ostream, TableBuf). Dans d'autres situations, il peut être appelé explicitement pour forcer l'insertion d'une autre ligne dans un tableau en utilisant des insertions ROWWISE. Avec des insertions COLUMNWISE, son fonctionnement est complexe, car les nouveaux éléments ajoutés à un tableau rempli COLUMNWISE réorganiseront ses éléments sur les colonnes du tableau.
o
setFieldSeparator(char fs):
Le séparateur de champ par défaut est le caractère `backspace' (\b). Après insertion d'un séparateur de champ, le prochain élément de tableau sera défini. L'insertion de deux séparateurs de champ insère un élément de tableau vide et commence la définition de l'élément suivant. Ce caractère séparateur de champ peut être redéfini par cette fonction. L'appel de setFieldSeparator sans argument désactive l'utilisation d'un caractère séparateur de champ, et laisse uniquement l'utilisation du manipulateur fs pour passer au champ suivant.
o
setRowSeparator(char rs):
Le séparateur de ligne par défaut est le caractère de nouvelle ligne (\n). Après insertion d'un séparateur de ligne, le prochain élément à entrer dans le tableau sera l'élément le plus à gauche de la prochaine ligne. L'insertion de deux séparateurs de ligne ajoute une ligne vide au tableau. L'appel de setRowSeparator sans argument désactive l'utilisation d'un caractère séparateur de ligne, et laisse uniquement l'utilisation du manipulateur rs pour passer au champ suivant.

MANIPULATEURS

o
Table &def(Table &table):
Ce manipulateur peut être inséré dans l'ostream qui enveloppe un TableBuf pour appeler la fonction membre def() du tableau.
o
FBB::fs:
Ce manipulateur peut être inséré dans l'ostream qui enveloppe un TableBuf pour passer au champ suivant du tableau. C'est une alternative à l'utilisation du caractère séparateur de champ.
o
FBB::rs:
Ce manipulateur peut être inséré dans l'ostream qui enveloppe un TableBuf pour passer à la ligne suivante du tableau. C'est une alternative à l'utilisation du caractère séparateur de ligne.

EXEMPLE

#include <iostream>
#include <ostream>
#include <string>
#include <algorithm>
#include <iterator>
#include <bobcat/tablebuf>
#include <bobcat/tablelines>
using namespace std;
using namespace FBB;
int main()
{
    TableLines tablelines;
    tablelines << 0;            // définir les largeurs des séparateurs
    for (size_t sep = 0; sep != 8; ++sep)
        tablelines << 3;
    TableBuf tab(tablelines, 8, TableBuf::ROWWISE);
    ostream out(&tab);
    copy(istream_iterator<string>(cin), istream_iterator<string>(),
            ostream_iterator<string>(out, "\b"));
    cout << tab << ’\n’;            // compléter le tableau et insérer
}
