NOM

tang - Serveur de liaison cryptographique basé sur le réseau

APERÇU

Tang est un service de liaison de clés cryptographiques à la présence réseau. Il offre une alternative sécurisée, sans état et anonyme aux services de mise en fiducie de clés.

Le projet Tang est né comme un outil pour aider à l'automatisation du déchiffrement. Les mécanismes existants utilisent principalement des systèmes de mise en fiducie de clés où un client chiffre des données avec une clé symétrique et stocke cette clé sur un serveur distant pour récupération ultérieure. L'objectif souhaité de cette configuration est que le client puisse automatiquement déchiffrer les données lorsqu'il peut contacter le serveur de fiducie et récupérer la clé.

Cependant, les serveurs de fiducie ont de nombreuses exigences supplémentaires, notamment l'authentification (pour que les clients ne puissent pas obtenir de clés qu'ils ne sont pas censés avoir) et le chiffrement du transport (pour que les attaquants qui écoutent sur le réseau ne puissent pas intercepter les clés en transit).

Tang évite cette complexité. Au lieu de stocker une clé symétrique à distance, le client effectue un échange de clés asymétriques avec le serveur Tang. Étant donné que le serveur Tang ne stocke ni ne transporte de clés symétriques, ni l'authentification ni le chiffrement ne sont requis. Ainsi, Tang est complètement sans état et sans configuration. De plus, les clients peuvent être complètement anonymes.

Tang ne fournit pas de client. Mais il exporte une API REST simple et ne transfère que des objets conformes aux normes JSON Object Signing and Encryption (JOSE), vous permettant de créer vos propres clients à l'aide de composants prêts à l'emploi. Pour un framework de chiffrement automatisé prêt à l'emploi avec prise en charge de Tang, consultez le projet Clevis. Pour les détails techniques complets du protocole Tang, consultez la page d'accueil du projet Tang.

DÉMARRAGE

Mettre en place un serveur Tang est simple :

$ sudo systemctl enable tangd.socket --now

C'est tout. Le serveur fonctionne maintenant avec un nouvel ensemble de clés cryptographiques et démarrera automatiquement lors du prochain redémarrage.

CONFIGURATION

Tang se veut un service réseau minimal et n'a donc aucune configuration. Pour ajuster les paramètres réseau, vous pouvez remplacer le fichier d'unité tangd.socket en utilisant les mécanismes système standard de systemd. Voir systemd.unit(5) et systemd.socket(5) pour plus d'informations.

EN MODE AUTONOME OU VIA SYSTEMD

Le serveur Tang peut être exécuté via l'activation de socket systemd ou de manière autonome lorsque le paramètre -l est passé. Le port par défaut utilisé est 9090 et peut être modifié avec l'option -p.

tang -l -p 9090

POINT DE TERMINAISON

Le serveur Tang peut se voir attribuer un point de terminaison. Ce point de terminaison agira comme un préfixe pour l'URL à laquelle le client accédera. Ce point de terminaison peut être spécifié avec l'option -e.

tang -l -p 9090 -e this/is/an/endpoint

Lorsque le point de terminaison est spécifié, il sera ajouté au début de l'URL normale adv/rec. Si aucun point de terminaison n'est fourni, et en supposant que le port 9090 est utilisé, le serveur Tang écoutera sur les URL suivantes :

http://localhost:9090/adv (GET)
http://localhost:9090/rec (POST)

Si un point de terminaison est fourni, et en supposant que le point de terminaison est /this/is/an/endpoint/, et en supposant également que le port 9090 est utilisé, le serveur Tang écoutera sur les URL suivantes :

http://localhost:9090/this/is/an/endpoint/adv (GET)
http://localhost:9090/this/is/an/endpoint/rec (POST)

ROTATION DES CLÉS

Afin de préserver la sécurité du système sur le long terme, vous devez périodiquement faire pivoter vos clés. L'intervalle précis auquel vous devriez faire pivoter dépend de votre application, de la taille des clés et de la politique institutionnelle. Pour des recommandations courantes, voir : https://www.keylength.com.

Il existe un script pratique pour gérer cela. Voir tangd-rotate-keys(1) pour plus d'informations. Cela peut également être effectué manuellement comme décrit ci-dessous.

Pour faire pivoter les clés, nous devons d'abord générer de nouvelles clés dans le répertoire de la base de données des clés. C'est généralement /var/db/tang. Par exemple, vous pouvez créer de nouvelles clés de signature et d'échange avec les commandes suivantes :

# DB=/var/db/tang
# jose jwk gen -i '{"alg":"ES512"}' -o $DB/new_sig.jwk
# jose jwk gen -i '{"alg":"ECMR"}' -o $DB/new_exc.jwk

Ensuite, renommez les anciennes clés pour qu'elles aient un . en préfixe afin de les masquer de la publicité :

# mv $DB/old_sig.jwk $DB/.old_sig.jwk
# mv $DB/old_exc.jwk $DB/.old_exc.jwk

Tang prendra immédiatement en compte toutes les modifications. Aucun redémarrage n'est nécessaire.

À ce stade, les nouvelles liaisons client utiliseront les nouvelles clés et les anciens clients pourront continuer à utiliser les anciennes clés. Une fois que vous êtes sûr que tous les anciens clients ont été migrés pour utiliser les nouvelles clés, vous pouvez supprimer les anciennes clés. Soyez conscient que la suppression des anciennes clés pendant que les clients les utilisent peut entraîner une perte de données. Vous avez été averti.

HAUTE PERFORMANCE

Le protocole Tang est extrêmement rapide. Cependant, dans la configuration par défaut, nous utilisons l'activation de socket systemd pour démarrer un processus par connexion. Cela impose une surcharge de performance. Pour la plupart des déploiements, cela reste probablement suffisamment rapide, étant donné que Tang est extrêmement léger. Mais pour les déploiements plus importants, de meilleures performances peuvent être obtenues.

Notre recommandation pour obtenir un débit plus élevé est de faire transiter le trafic vers Tang via vos services Web existants à l'aide d'un pool de connexions. Comme il y a un processus par connexion, maintenir un certain nombre de connexions ouvertes dans cette configuration permettra un parallélisme efficace car il n'y a pas de verrous internes dans Tang.

Pour Apache, cela est possible en utilisant la directive ProxyPass du module mod_proxy.

HAUTE DISPONIBILITÉ

Tang offre deux méthodes pour construire un déploiement à haute disponibilité.

1. Redondance client (recommandé)
2. Partage de clés avec round-robin DNS

Bien qu'il puisse être tentant de partager des clés entre les serveurs Tang, cette méthode doit être évitée. Le partage de clés augmente le risque de compromission des clés et nécessite une infrastructure d'automatisation supplémentaire.

Au lieu de cela, les clients doivent être codés avec la capacité de se lier à plusieurs serveurs Tang. Dans cette configuration, chaque serveur Tang aura ses propres clés et les clients pourront déchiffrer en contactant un sous-ensemble de ces serveurs.

Clevis prend déjà en charge ce flux de travail via son plugin sss.

Cependant, si vous pensez toujours que le partage de clés est la bonne stratégie de déploiement, Tang ne vous en empêchera pas. Transférez simplement (en toute sécurité !) tout le contenu du répertoire de la base de données à tous vos serveurs. Assurez-vous de ne pas oublier les clés non annoncées ! Ensuite, configurez le round-robin DNS afin que les clients soient répartis sur vos serveurs.

COMMANDES

Le serveur Tang ne fournit aucune commande publique.
