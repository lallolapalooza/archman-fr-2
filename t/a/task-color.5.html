NOM

task-color - Un tutoriel sur les couleurs pour le gestionnaire de tâches en ligne de commande Taskwarrior.

MONOCHROME AUTOMATIQUE

Il convient de mentionner que Taskwarrior est conscient de savoir si sa sortie va vers un terminal, ou vers un fichier ou via un pipe. Lorsque la sortie de Taskwarrior va vers un terminal, la couleur est souhaitable, mais considérez la commande suivante :

    $ task list > file.txt

Voulons-nous vraiment avoir tous ces codes de contrôle de couleur dans le fichier ? Taskwarrior suppose que non, et désactive temporairement la couleur pendant la génération de la sortie. Cela explique la sortie de la commande suivante :

    $ task show | grep '^color '
    color                        off

elle renvoie toujours 'off', quelle que soit la configuration, car la sortie est envoyée à un pipe.

Si vous vouliez ces codes de couleur, vous pouvez outrepasser ce comportement en réglant la variable _forcecolor sur on, comme ceci :

    $ task config _forcecolor on
    $ task config | grep '^color '
    color                        on

ou en la remplaçant temporairement comme ceci :

    $ task rc._forcecolor=on config | grep '^color '
    color                        on

COULEURS DISPONIBLES

Taskwarrior dispose d'une commande 'color' qui affiche toutes les couleurs qu'il est capable d'afficher. Essayez ceci :

    $ task color

La sortie ne peut pas être reproduite ici dans une page de manuel, mais vous devriez voir un ensemble d'échantillons de couleurs. Le nombre que vous verrez dépend de la capacité de votre programme de terminal à les rendre.

Vous devriez au moins voir les couleurs de base et les effets - si c'est le cas, vous avez le support 16 couleurs. Si votre terminal supporte 256 couleurs, vous le saurez !

SUPPORT 16-COULEURS

Le support de base des couleurs est fourni par des noms de couleurs :

    black, red, blue, green, magenta, cyan, yellow, white

La couleur de premier plan (pour le texte) est simplement spécifiée comme l'une des couleurs ci-dessus, ou n'est pas spécifiée du tout pour utiliser la couleur de texte par défaut du terminal.

La couleur d'arrière-plan est spécifiée en utilisant le mot 'on', et l'une des couleurs ci-dessus. Quelques exemples :

    green                 # texte vert, couleur d'arrière-plan par défaut
    green on yellow       # texte vert, arrière-plan jaune
    on yellow             # couleur de texte par défaut, arrière-plan jaune

Ces couleurs peuvent être modifiées davantage, en rendant le premier plan gras, ou en rendant l'arrière-plan lumineux. Quelques exemples :

    bold green
    bold white on bright red
    on bright cyan

L'ordre des mots n'a pas d'importance, donc les éléments suivants sont équivalents :

    bold green
    green bold

Mais le 'on' est important - les couleurs avant 'on' sont au premier plan, et les couleurs après 'on' sont à l'arrière-plan.

Il existe un attribut supplémentaire 'underline' qui peut être utilisé :

    underline bold red on black

Et un attribut 'inverse' :

    inverse red

Taskwarrior dispose d'une commande qui vous aide à visualiser ces combinaisons de couleurs. Essayez ceci :

    $ task color underline bold red on black

Vous pouvez utiliser cette commande pour voir comment les différentes combinaisons de couleurs fonctionnent. Vous verrez également des exemples de couleurs affichés, comme ceux ci-dessus, en plus de l'exemple demandé.

Certaines combinaisons sont très jolies, d'autres horribles. Différents programmes de terminal implémentent des versions légèrement différentes du 'rouge', par exemple, vous pourriez donc voir des variations inattendues d'une machine à l'autre. La luminosité de votre écran est également un facteur.

SUPPORT 256-COULEURS

L'utilisation de 256 couleurs suit la même forme, mais les noms sont différents, et certaines couleurs peuvent être référencées de différentes manières. D'abord, il y a l'ordinal de couleur, qui se présente comme suit :

    color0
    color1
    color2
    ...
    color255

Cela vous donne accès aux 256 couleurs, mais ne vous aide pas beaucoup. Cette plage est une combinaison de 8 couleurs de base (color0 - color7), puis 8 variations plus vives (color8 - color15). Ensuite, un bloc de 216 couleurs (color16 - color231). Puis un bloc de 24 nuances de gris (color232 - color255).

Le grand bloc de 216 couleurs (6x6x6 = 216) représente un cube de couleurs, qui peut être adressé via des valeurs RVB allant de 0 à 5 pour chaque couleur composante. Une valeur de 0 signifie aucune de cette couleur composante, et une valeur de 5 signifie la couleur composante la plus intense. Par exemple, un rouge vif est spécifié comme suit :

    rgb500

Et un rouge plus sombre serait :

    rgb300

Notez que les trois chiffres représentent les trois valeurs composantes, donc dans cet exemple, le 5, 0 et 0 représentent rouge=5, vert=0, bleu=0. La combinaison d'un rouge intense sans vert et sans bleu donne du rouge. De même, le bleu et le vert sont :

    rgb005
    rgb050

Un autre exemple - le jaune vif - est un mélange de rouge vif et de vert vif, mais sans composante bleue, donc le jaune vif est adressé comme suit :

    rgb550

Un rose doux serait adressé comme suit :

    rgb515

Voyez si vous êtes d'accord, en exécutant :

    $ task color black on rgb515

Vous remarquerez peut-être que le grand bloc de couleurs est représenté par 6 carrés. Toutes les couleurs du premier carré ont une valeur de rouge de 0. Toutes les couleurs du 6ème carré ont une valeur de rouge de 5. Dans chaque carré, le bleu va de 0 à 5 de gauche à droite, et dans chaque carré le vert va de 0 à 5, de haut en bas. Ce système demande un peu d'habitude.

Le bloc de 24 nuances de gris peut également être accédé en tant que gray0 - gray23, dans une rampe continue du noir au blanc.

MÉLANGE DE 16- ET 256-COULEURS

Si vous spécifiez 16 couleurs et visualisez sur un terminal 256 couleurs, pas de problème. Si vous essayez l'inverse, spécifiant 256 couleurs et visualisant sur un terminal 16 couleurs, vous serez déçu, peut-être même choqué.

Il y a une cartographie limitée des couleurs - par exemple, si vous deviez spécifier cette combinaison :

    red on gray3

vous mélangez une spécification 16 couleurs et 256 couleurs. Taskwarrior mappera rouge à color1 et continuera. Notez que rouge et color1 ne sont pas exactement la même teinte.

Notez également qu'il n'y a pas d'attributs gras ou lumineux lors de l'utilisation de 256 couleurs, mais qu'il y a toujours le soulignement disponible.

LÉGENDE

Taskwarrior affichera des exemples de toutes les couleurs définies utilisées dans votre .taskrc, ou thème, si vous exécutez cette commande :

    $ task color legend

Cela vous donne un exemple de chacune des couleurs, afin que vous puissiez en voir l'effet, sans nécessairement créer un ensemble de tâches qui répondent à chacun des critères de règle.

RÈGLES

Taskwarrior supporte les règles de colorisation. Ce sont des valeurs de configuration qui spécifient une couleur et les conditions dans lesquelles cette couleur est utilisée. À titre d'exemple, ajoutons quelques tâches :

    $ task add project:Home priority:H pay the bills               (1)
    $ task add project:Home            clean the rug               (2)
    $ task add project:Garden          clean out the garage        (3)

Nous pouvons ajouter une règle de couleur qui utilise un arrière-plan bleu pour toutes les tâches du projet Home :

    $ task config color.project.Home 'on blue'

Nous utilisons des guillemets autour de 'on blue' car il y a deux mots, mais ils représentent une seule valeur dans le fichier .taskrc. Supposons maintenant que nous souhaitions utiliser une couleur de texte jaune gras pour tout le travail de nettoyage :

    $ task config color.keyword.clean 'bold yellow'

Que se passe-t-il maintenant pour la tâche 2, qui appartient au projet Home (arrière-plan bleu), et qui est aussi une tâche de nettoyage (premier plan jaune gras) ? Les couleurs sont combinées, et la tâche est affichée comme "bold yellow on blue".

Les règles de couleur peuvent être appliquées par projet et par mot-clé de description, comme montré, ainsi que par priorité (ou absence de priorité), par statut actif, par date d'échéance ou retard, par présence d'un tag ou d'un tag spécifique (peut-être la règle la plus utile) ou par le fait d'être une tâche récurrente.

Il est possible de créer un mélange de règles très coloré. Avec le support 256 couleurs, ces couleurs peuvent être subtiles et complémentaires, mais sans précaution, cela peut être un désordre visuel. Attention !

Dans de tels cas, envisagez d'utiliser l'option 'rule.color.merge=no' pour désactiver le mélange des couleurs.

La priorité des règles de couleur est déterminée par la variable de configuration 'rule.precedence.color', qui contient par défaut :

```

    project, keywords, priority, due, overdue, active, recur

```

Cette liste indique la priorité des règles. Les éléments situés plus loin dans la liste ont une priorité plus élevée.

task-color(5)

NOM

task-color - Les couleurs des tâches

DISPONIBLES

Les couleurs Taskwarrior sont définies dans le fichier taskrc(5), et chaque couleur est spécifiée par une chaîne de la forme color.nom. Les noms des couleurs peuvent être n'importe quel attribut d'une tâche, comme 'id', 'priority', 'project', 'tags', 'due', 'recurring', 'none', 'uda'.

Si le nom de la couleur est de la forme color.attribut.valeur, la couleur est utilisée si la tâche correspond à cet attribut et à cette valeur. Par exemple, color.priority.H spécifie la couleur des tâches dont la priorité est 'H'.

Si le nom de la couleur est de la forme color.attribut.valeur.attribut.valeur, les deux conditions doivent être remplies. Par exemple, color.project.foo.priority.H spécifie la couleur des tâches du projet 'foo' dont la priorité est 'H'.

Les règles de couleur sont évaluées dans l'ordre suivant :

    color.default
    color.active
    color.scheduled
    color.recurring
    color.deleted
    color.completed
    color.overdue
    color.due.today
    color.due
    color.blocked
    color.blocking
    color.project.
    color.tag.
    color.keyword.
    color.uda.

La règle color.default est la règle de base utilisée si aucune autre règle ne correspond.

La règle color.active s'applique aux tâches actives, ce qui signifie que ce ne sont ni des tâches terminées, ni des tâches supprimées.

Les règles color.scheduled et color.recurring s'appliquent aux tâches avec les attributs correspondants.

Les règles color.deleted et color.completed s'appliquent aux tâches avec les états correspondants.

Les règles color.overdue, color.due.today et color.due s'appliquent aux tâches dont la date d'échéance est passée, aujourd'hui ou dans le futur respectivement.

Les règles color.blocked et color.blocking s'appliquent aux tâches qui sont bloquées ou qui bloquent d'autres tâches.

Les règles de la forme color.project.nom, color.tag.nom et color.uda.nom s'appliquent aux tâches ayant le projet, le tag ou l'UDA spécifié.

Les règles de la forme color.project., color.tag. et color.uda., sans nom spécifique, s'appliquent à toutes les tâches ayant un projet, un tag ou un UDA, respectivement.

Il y a aussi color.project.none, color.tag.none et color.uda.priority.none pour représenter spécifiquement les données manquantes.

SUPPORT MONOCHROME

Si votre terminal ne prend pas en charge les couleurs, Taskwarrior utilise une couleur par défaut.

16-COLOR SUPPORT

Taskwarrior prend en charge les 16 couleurs ANSI standard (noir, rouge, vert, jaune, bleu, magenta, cyan, blanc et leurs versions claires). Ces couleurs sont spécifiées en utilisant les noms black, red, green, yellow, blue, magenta, cyan, white, bold-black, bold-red, bold-green, bold-yellow, bold-blue, bold-magenta, bold-cyan, bold-white.

256-COLOR SUPPORT

Taskwarrior prend également en charge les 256 couleurs ANSI. Vous pouvez spécifier ces couleurs en utilisant leur nom ou leur numéro de couleur dans la palette de 256 couleurs. Par exemple, color.default.256:red ou color.default.256:196 pour le rouge vif.

MELANGE 16- ET 256-COLORS

Il est possible de mélanger les 16 couleurs et les 256 couleurs. Par exemple, vous pouvez utiliser color.red.256:blue pour spécifier la couleur bleue pour les tâches rouges, tout en utilisant les 16 couleurs pour le reste.

LÉGENDE

Le tableau suivant montre les règles de couleur par défaut :

    deleted,completed,active,keyword.,tag.,project.,overdue,scheduled,due.today,due,blocked,blocking,recurring,tagged,uda.

Ce sont juste les règles de couleur sans le préfixe 'color.'. La règle 'color.deleted' a la priorité la plus élevée, et 'color.uda.' la plus basse.

La règle de mot-clé montrée ici comme 'keyword.' correspond à un modèle générique, signifiant 'color.keyword.*', ou en d'autres termes toutes les règles de mot-clé.

Il y a aussi 'color.project.none', 'color.tag.none' et 'color.uda.priority.none' pour représenter spécifiquement les données manquantes.

THÈMES

Taskwarrior prend en charge les thèmes. Ce que cela signifie réellement, c'est qu'avec la capacité d'inclure d'autres fichiers dans le fichier .taskrc, différents ensembles de règles de couleur peuvent être inclus.

Pour avoir une bonne idée de ce à quoi ressemble un thème de couleur, essayez d'ajouter cette entrée à votre fichier .taskrc :

    include dark-256.theme

Vous pouvez utiliser n'importe lequel des thèmes Taskwarrior standard :

    dark-16.theme
    dark-256.theme
    dark-blue-256.theme
    dark-gray-256.theme
    dark-green-256.theme
    dark-red-256.theme
    dark-violets-256.theme
    dark-yellow-green.theme
    light-16.theme
    light-256.theme
    solarized-dark-256.theme
    solarized-light-256.theme
    dark-default-16.theme
    dark-gray-blue-256.theme
    no-color.theme

Gardez à l'esprit que si vous utilisez un terminal avec un fond sombre, vous obtiendrez de meilleurs résultats en utilisant un thème sombre.

Vous pouvez également voir comment le thème colorera les différentes tâches avec la commande :

    $ task color legend

Mieux encore, créez le vôtre et partagez-le. Nous serons heureux d'héberger le fichier thème sur https://taskwarrior.org.
