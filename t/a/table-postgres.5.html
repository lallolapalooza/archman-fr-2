TABLE_POSTGRESQL(5) Manuel des formats de fichiers TABLE_POSTGRESQL(5)

NOM

table_postgresql — description du format des tables PostgreSQL pour le démon de messagerie smtpd(8)

DESCRIPTION

Cette page de manuel documente le format des tables PostgreSQL utilisées par le démon de messagerie smtpd(8).

Le format décrit ici s'applique aux tables définies dans smtpd.conf(5).

TABLE POSTGRESQL

Une table postgresql permet de stocker des noms d'utilisateur, des mots de passe, des alias et des domaines dans un format partageable entre différentes machines prenant en charge postgres(1).

La table est utilisée par smtpd(8) lors de l'authentification d'un utilisateur, lorsque des informations utilisateur telles que l'identifiant utilisateur et/ou le répertoire personnel sont requises pour une livraison, lorsqu'une recherche de domaine peut être nécessaire, et/ou lors de la recherche d'un alias.

Une table PostgreSQL se compose d'une ou plusieurs postgresql(1) bases de données avec une ou plusieurs tables.

Si la table est utilisée pour l'authentification, le mot de passe doit être chiffré à l'aide de la fonction crypt(3). Ces mots de passe peuvent être générés à l'aide de l'utilitaire encrypt(1) ou de la commande encrypt de smtpctl(8).

FICHIER DE CONFIGURATION TABLE POSTGRESQL

Les options de configuration suivantes sont disponibles :

conninfo host='hôte' user='utilisateur' password='mot de passe' dbname='nom de base'
Informations de connexion nécessaires pour se connecter à la base de données PostgreSQL. Par exemple : 
conninfo host='db.example.com' user='maildba' password='...' dbname='opensmtpdb'
query_alias instruction SQL
Ceci est utilisé pour fournir une requête afin de rechercher des alias. Le point d'interrogation est remplacé par les données appropriées. Pour les alias, il s'agit du côté gauche de l'adresse SMTP. Ceci attend qu'un VARCHAR soit retourné avec le nom d'utilisateur auquel l'alias se résout.
query_credentials instruction SQL
Ceci est utilisé pour fournir une requête pour rechercher les informations d'identification utilisateur. Le point d'interrogation est remplacé par les données appropriées. Pour les informations d'identification, il s'agit du côté gauche de l'adresse SMTP. La requête s'attend à ce que deux VARCHAR soient retournés, un avec un nom d'utilisateur et un avec un mot de passe au format crypt(3).
query_domain instruction SQL
Ceci est utilisé pour fournir une requête afin de rechercher un domaine. Le point d'interrogation est remplacé par les données appropriées. Pour le domaine, il s'agirait du côté droit de l'adresse SMTP. Ceci attend qu'un VARCHAR soit retourné avec un nom de domaine correspondant.
query_mailaddrmap instruction SQL
Ceci est utilisé pour fournir une requête afin de rechercher des expéditeurs. Le point d'interrogation est remplacé par les données appropriées. Ceci attend qu'un VARCHAR soit retourné avec l'adresse depuis laquelle l'expéditeur est autorisé à envoyer des e-mails.

Une instruction SQL générique ressemblerait à ceci :

query_ SELECT value FROM table WHERE key=$1;

FICHIERS

/etc/mail/postgres.conf
Fichier de configuration par défaut de table-postgresql(5).

EXEMPLES

EXEMPLE GÉNÉRIQUE

Exemple basé sur la FAQ d'OpenSMTPD : Construction d'un serveur de messagerie. La partie filtrage est exclue dans cet exemple.

La configuration ci-dessous est destinée à un serveur de messagerie de taille moyenne qui gère plusieurs domaines avec plusieurs utilisateurs virtuels et est basée sur plusieurs hypothèses. L'une d'elles est qu'un seul utilisateur système nommé vmail est utilisé pour tous les utilisateurs virtuels. Cet utilisateur doit être créé :

# useradd -g =uid -c "Virtual Mail" -d /var/vmail -s /sbin/nologin vmail
# mkdir /var/vmail
# chown vmail:vmail /var/vmail

Schéma PostgreSQL :

CREATE TABLE domains (
  id SERIAL,
  domain VARCHAR(255) NOT NULL DEFAULT ''
);
CREATE TABLE virtuals (
    id SERIAL,
    email VARCHAR(255) NOT NULL DEFAULT '',
    destination VARCHAR(255) NOT NULL DEFAULT ''
);
CREATE TABLE credentials (
    id SERIAL,
    email VARCHAR(255) NOT NULL DEFAULT '',
    password VARCHAR(255) NOT NULL DEFAULT ''
);

Cela peut être peuplé comme suit :

INSERT INTO domains VALUES (1, "example.com");
INSERT INTO domains VALUES (2, "example.net");
INSERT INTO domains VALUES (3, "example.org");

INSERT INTO virtuals VALUES (1, "abuse@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (2, "postmaster@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (3, "webmaster@example.com", "bob@example.com");
INSERT INTO virtuals VALUES (4, "bob@example.com", "vmail");
INSERT INTO virtuals VALUES (5, "abuse@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (6, "postmaster@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (7, "webmaster@example.net", "alice@example.net");
INSERT INTO virtuals VALUES (8, "alice@example.net", "vmail");

INSERT INTO credentials VALUES (1, "bob@example.com", "$2b$08$ANGFKBL.BnDLL0bUl7I6aumTCLRJSQluSQLuueWRG.xceworWrUIu");
INSERT INTO credentials VALUES (2, "alice@example.net", "$2b$08$AkHdB37kaj2NEoTcISHSYOCEBA5vyW1RcD8H1HG.XX0P/G1KIYwii");

/etc/mail/postgresql.conf

conninfo host='db.example.com' user='maildba' password='OpenSMTPDRules!' dbname='opensmtpdb'
query_alias SELECT destination FROM virtuals WHERE email=$1;
query_credentials SELECT email, password FROM credentials WHERE email=$1;
query_domain SELECT domain FROM domains WHERE domain=$1;

/etc/mail/smtpd.conf

table domains postgres:/etc/mail/postgres.conf
table virtuals postgres:/etc/mail/postgres.conf
table credentials postgres:/etc/mail/postgres.conf
listen on egress port 25 tls pki mail.example.com
listen on egress port 587 tls-require pki mail.example.com auth <credentials>
accept from any for domain <domains> virtual <virtuals> deliver to mbox

MIGRATION DEPUIS POSTFIX (& POSTFIXADMIN)

/etc/mail/postgres.conf

conninfo host='db.example.com' user='postfix' password='...' dbname='postfix'
query_alias SELECT destination FROM alias WHERE email=$1;
query_credentials SELECT username, password FROM mailbox WHERE username=$1;
query_domain SELECT domain FROM domain WHERE domain=$1;

Le reste de la configuration reste inchangé.
