TAIL(1P) Manuel du programmeur POSIX TAIL(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

tail — copier la dernière partie d'un fichier

SYNTAXE

tail [-f] [-c nombre|-n nombre] [fichier]

DESCRIPTION

L'utilitaire tail copie son fichier d'entrée vers la sortie standard à partir d'un emplacement désigné.

La copie commencera à l'endroit du fichier indiqué par les options -c nombre ou -n nombre. L'argument de l'option nombre sera compté en unités de lignes ou d'octets, selon les options -n et -c. Les comptes de lignes et d'octets commencent à 1.

Les queues relatives à la fin du fichier peuvent être sauvegardées dans un tampon interne, et donc avoir une longueur limitée. Un tel tampon, s'il existe, ne sera pas plus petit que {LINE_MAX}*10 octets.

OPTIONS

L'utilitaire tail se conformera aux Définitions de base du volume POSIX.1‐2017, Section 12.2, Directives de syntaxe utilitaire, à l'exception du fait que '+' peut être reconnu comme délimiteur d'option ainsi que '-'.

Les options suivantes seront prises en charge :

-c nombre
L'application devra s'assurer que l'argument de l'option nombre est un entier décimal, incluant éventuellement un signe. Le signe affectera l'emplacement dans le fichier, mesuré en octets, à partir duquel la copie commence :
Signe La copie commence
+ Par rapport au début du fichier.
- Par rapport à la fin du fichier.
aucun Par rapport à la fin du fichier.

L'application devra s'assurer que si le signe de l'argument de l'option nombre est '+', l'argument de l'option nombre est un entier décimal non nul.

L'origine du comptage sera 1 ; c'est-à-dire que -c +1 représente le premier octet du fichier, -c -1 le dernier.

-f
Si le fichier d'entrée est un fichier régulier ou si l'opérande fichier spécifie un FIFO, ne pas terminer après la copie de la dernière ligne du fichier d'entrée, mais lire et copier les octets suivants du fichier d'entrée lorsqu'ils deviennent disponibles. Si aucun opérande fichier n'est spécifié et que l'entrée standard est un pipe ou un FIFO, l'option -f sera ignorée. Si le fichier d'entrée n'est pas un FIFO, un pipe ou un fichier régulier, il n'est pas spécifié si l'option -f sera ignorée ou non.
-n nombre
Cette option sera équivalente à -c nombre, sauf que l'emplacement de départ dans le fichier sera mesuré en lignes au lieu d'octets. L'origine du comptage sera 1 ; c'est-à-dire que -n +1 représente la première ligne du fichier, -n -1 la dernière.

Si ni -c ni -n ne sont spécifiés, -n 10 sera supposé.

OPÉRANDES

L'opérande suivant sera pris en charge :

fichier
Un nom de chemin d'un fichier d'entrée. Si aucun opérande fichier n'est spécifié, l'entrée standard sera utilisée.

ENTRÉE STANDARD

L'entrée standard sera utilisée si aucun opérande fichier n'est spécifié, et sera utilisée si l'opérande fichier est '-' et que l'implémentation traite le '-' comme signifiant l'entrée standard. Sinon, l'entrée standard ne sera pas utilisée. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Si l'option -c est spécifiée, le fichier d'entrée peut contenir des données arbitraires ; sinon, le fichier d'entrée devra être un fichier texte.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de tail :

LANG
Fournir une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, supplantera les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Déterminer la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Déterminer la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Déterminer l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Défaut.

SORTIE STANDARD

La partie désignée du fichier d'entrée sera écrite sur la sortie standard.

ERREUR STANDARD

L'erreur standard sera utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Défaut.

Les sections suivantes sont informatives.

USAGE PAR L'APPLICATION

L'option -c doit être utilisée avec prudence lorsque l'entrée est un fichier texte contenant des caractères multi-octets ; elle peut produire une sortie qui ne commence pas sur une frontière de caractère.

Bien que le fichier d'entrée de tail puisse être de n'importe quel type, les résultats pourraient ne pas être ceux attendus sur certains fichiers de périphériques spéciaux caractères ou sur des types de fichiers non décrits par le volume Interfaces système de POSIX.1‐2017. Comme ce volume de POSIX.1‐2017 ne spécifie pas la taille de bloc utilisée lors de la lecture, tail n'est pas tenu de lire toutes les données des périphériques qui effectuent uniquement des transferts par blocs.

Lors de l'utilisation de tail pour traiter des noms de chemin, et que l'option -c n'est pas spécifiée, il est recommandé que LC_ALL, ou au moins LC_CTYPE et LC_COLLATE, soient définis sur POSIX ou C dans l'environnement, car les noms de chemin peuvent contenir des séquences d'octets qui ne forment pas de caractères valides dans certaines locales, auquel cas le comportement de l'utilitaire serait affected

tail(1) — man pages

PROLOG

This page describes version 6.16 of the tail utility.

NAME

tail — display the last part of a file

SYNOPSIS

tail [-b | -c | -f | -l] [-n number] [file]...

tail [-b | -c | -f | -l] [+number] [file]...

DESCRIPTION

The tail utility shall write the last 10 lines, by the default, of each specified file to the standard output. When the -f option is used, the file is opened in a manner which allows tail to detect when more data has been added to the file, and tail shall write any data appended to the file to standard output as it becomes available. The default action is to display the last 10 lines of each file.

If a file is not specified, or if a file is specified as -, tail shall use the standard input.

The tail utility shall follow the guidelines in Utility Syntax Guidelines for the format of the command line. The -number and +number options have specific meanings and are described below.

If more than one file is specified, tail shall prepend each output group with a header indicating the file name, for example, ==>file<==. This header shall be written to standard output.

OPTIONS

The tail utility shall conform to the Base Definitions volume of POSIX.1‐2017, Section 12.2, Utility Syntax Guidelines.

The following options shall be supported:

-b
Equivalent to -n numberb, where the offset is in 512-byte blocks.
-c
Equivalent to -n numberc, where the offset is in bytes.
-f
Output shall be appended as the file grows. This option implies that the file is opened in a manner which allows tail to detect when more data has been added to the file. The file descriptor for the file shall be kept open, and the system shall be queried periodically for new data. If the file is rotated (renamed, and a new file created with the original name), tail shall continue writing to the new file. If the file is truncated, tail shall also detect this and continue writing from the beginning of the file.
-l
Equivalent to -n numberl, where the offset is in lines. This is the default behavior if -n is used without a suffix.
-n number
Start writing at the specified offset, in units specified by a suffix, from the end of the file. The default offset is 10. The default unit is lines.

The suffix characters used with -n are:

b
512-byte blocks.
c
Bytes.
l
Lines.

The -b, -c, and -l options are equivalent to using -n with the appropriate suffix and the default offset of 10.

The -f option can be combined with the -b, -c, or -l options.

A number argument shall be a decimal integer. If the first character of number is a '+' (plus sign), the offset shall be counted from the beginning of the input. Otherwise, the offset shall be counted from the end of the input.

Note that the offset is measured in units from the beginning or end of the file. If the offset is measured in bytes (-c or -n numberc), the offset is the number of bytes from the beginning or end of the file. If the offset is measured in lines (-l or -n numberl), the offset is the number of lines from the beginning or end of the file. If the offset is measured in 512-byte blocks (-b or -n numberb), the offset is the number of 512-byte blocks from the beginning or end of the file.

OPERANDS

The following operands shall be supported:

file
A pathname of a file to be processed. If no file operands are specified, the standard input shall be used.

STDIN

The standard input shall be used if no file operands are specified, or if a file operand is -. See the INPUT FILES section.

INPUT FILES

The input files shall be text files. The behavior is undefined if the input files are not text files unless the -c option is used.

If the POSIXLY_CORRECT environment variable is set, the behavior is undefined if the input files contain multi-byte characters and the LC_CTYPE locale is not the POSIX locale. In the POSIX locale each byte is a valid single-byte character, and therefore this problem is avoided.

ENVIRONMENT VARIABLES

The following environment variables shall affect the execution of tail:

LANG
Provide default values for the internationalization variables that are unset or null on entry. (See the Base Definitions volume of POSIX.1‐2017, Section 8.2, Internationalization Variables.)
LC_ALL
Determine the locale category for any of the following environment variables that are unset or null.
LC_CTYPE
Determine the locale for the interpretation of text as bytes in a file. See INPUT FILES.
LC_MESSAGES
Determine the locale that should be used to write diagnostic and informative messages and the descriptions of unrecognized options.
NLSPATH
Determine the locations of message catalogs for the processing of LC_MESSAGES.

ASYNCHRONOUS EVENTS

Default signal-handling shall apply.

STDOUT

The last 10 lines (or bytes, or blocks, depending on the option) of each file shall be written to standard output.

If the -f option is used, new data appended to the file shall be written to standard output as it becomes available.

If more than one file is specified, a header indicating the file name shall precede the output for each file.

STDERR

The standard error shall be used for diagnostic messages.

OUTPUT FILES

None.

EXTENDED DESCRIPTION

None.

EXIT STATUS

The following exit values shall be returned:

0
Successful completion.
>0
An error occurred.

CONSEQUENCES OF ERRORS

A write error on standard output shall cause the utility to exit with a non-zero exit status.

If any file cannot be opened, read, or closed, or if any other error occurs, tail shall write a diagnostic message to standard error and shall continue processing any remaining files. If the exit status is non-zero, it shall indicate that at least one error occurred.

APPLICATION USAGE

The -f option should not be used on binary files, as the notion of appending to a binary file is ill-defined. The behavior is undefined if the input files contain multi-byte characters and the LC_CTYPE locale is not the POSIX locale, unless the POSIXLY_CORRECT environment variable is set. In the POSIX locale each byte is a valid single-byte character, and therefore this problem is avoided.

EXAMPLES

The -f option can be used to monitor the growth of a file that is being written by some other process. For example, the command:

tail -f fred

prints the last ten lines of the file fred, followed by any lines that are appended to fred between the time tail is initiated and killed. As another example, the command:

tail -f -c 15 fred

prints the last 15 bytes of the file fred, followed by any bytes that are appended to fred between the time tail is initiated and killed.

RATIONALE

This version of tail was created to allow conformance to the Utility Syntax Guidelines. The historical -b option was omitted because of the general non-portability of block-sized units of text. The -c option historically meant ``characters'', but this volume of POSIX.1‐2017 indicates that it means ``bytes''. This was selected to allow reasonable implementations when multi-byte characters are possible; it was not named -b to avoid confusion with the historical -b.

The origin of counting both lines and bytes is 1, matching all widespread historical implementations. Hence tail -n +0 is not conforming usage because it attempts to output line zero; but note that tail -n 0 does conform, and outputs nothing.

Earlier versions of this standard allowed the following forms in the SYNOPSIS:

tail -[number][b|c|l][f] [file]
tail +[number][b|c|l][f] [file]

These forms are no longer specified by POSIX.1‐2008, but may be present in some implementations.

The restriction on the internal buffer is a compromise between the historical System V implementation of 4096 bytes and the BSD 32768 bytes.

The -f option has been implemented as a loop that sleeps for 1 second and copies any bytes that are available. This is sufficient, but if more efficient methods of determining when new data are available are developed, implementations are encouraged to use them.

Historical documentation indicates that tail ignores the -f option if the input file is a pipe (pipe and FIFO on systems that support FIFOs). On BSD-based systems, this has been true; on System V-based systems, this was true when input was taken from standard input, but it did not ignore the -f flag if a FIFO was named as the file operand. Since the -f option is not useful on pipes and all historical implementations ignore -f if no file operand is specified and standard input is a pipe, this volume of POSIX.1‐2017 requires this behavior. However, since the -f option is useful on a FIFO, this volume of POSIX.1‐2017 also requires that if a FIFO is named, the -f option shall not be ignored. Earlier versions of this standard did not state any requirement for the case where no file operand is specified and standard input is a FIFO. The standard has been updated to reflect current practice which is to treat this case the same as a pipe on standard input. Although historical behavior does not ignore the -f option for other file types, this is unspecified so that implementations are allowed to ignore the -f option if it is known that the file cannot be extended.
