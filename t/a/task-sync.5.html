NOM

task-sync - Discussion et tutoriel sur les diverses capacités de synchronisation de données de task(1).

INTRODUCTION

Taskwarrior peut synchroniser vos tâches vers un serveur. Cela présente plusieurs avantages :
- Rend vos tâches accessibles depuis plusieurs systèmes, appelés "répliques".
- Fournit une sauvegarde de vos tâches.
- Économise de l'espace disque.

Par exemple, vous pourriez vouloir une réplique de vos tâches sur votre ordinateur portable et sur votre téléphone.

NOTE : Un effet secondaire de la synchronisation est qu'une fois que les modifications ont été synchronisées, elles ne peuvent plus être annulées. Cela signifie que chaque fois que la synchronisation est exécutée, il n'est plus possible d'annuler les opérations précédentes.

GESTION DE LA SYNCHRONISATION

Ajouter une réplique

Pour ajouter une nouvelle réplique, configurez une nouvelle réplique vide de manière identique à la réplique existante, puis exécutez `task sync`.

Quand synchroniser

Pour la synchronisation vers un serveur, une solution courante consiste à exécuter

    $ task sync

périodiquement, par exemple via cron(8).

CONFIGURATION

Taskwarrior offre plusieurs options pour synchroniser vos tâches :


- Vers un serveur spécifiquement conçu pour gérer les données Taskwarrior.
+ Vers un fournisseur de stockage cloud. Actuellement, AWS et GCP sont pris en charge.
- Vers un fichier local sur disque.

Pour la plupart de ces options, vous aurez besoin d'un secret de chiffrement utilisé pour chiffrer et déchiffrer vos tâches. Il peut s'agir de n'importe quelle chaîne secrète et elle doit correspondre pour toutes les répliques qui partagent des tâches.

    $ task config sync.encryption_secret <secret_de_chiffrement>

Des outils tels que pwgen(1) peuvent générer des valeurs secrètes appropriées.

Serveur de synchronisation

Pour synchroniser vos tâches vers un serveur de synchronisation, vous aurez besoin des informations suivantes de la part de l'administrateur du serveur :


- L'URL du serveur (par exemple, "https://tw.example.com/path")
- Un identifiant client ("client_id") identifiant vos tâches

Configurez Taskwarrior avec ces détails :

    $ task config sync.server.url               <url>
    $ task config sync.server.client_id         <client_id>

Notez que l'URL doit inclure le schéma, tel que 'http://' ou 'https://'.


$ task config sync.server.origin <origine>

Est un synonyme obsolète pour "sync.server.url".

Plateforme Cloud Google

Pour synchroniser vos tâches vers GCP, utilisez la console GCP pour créer un nouveau projet, puis au sein de ce projet, un nouveau bucket Cloud Storage. Les paramètres par défaut du bucket sont suffisants.

Authentifiez-vous auprès du projet avec :

    $ gcloud config set project $PROJECT_NAME
    $ gcloud auth application-default login

Configurez ensuite Taskwarrior avec :

    $ task config sync.gcp.bucket               <nom-du-bucket>

Cependant, vous pouvez apporter vos propres identifiants de compte de service si votre `application-default` est déjà utilisé par une autre application.

Pour commencer, naviguez vers la section "IAM et administration" dans le menu de navigation, puis sélectionnez "Rôles".

Sur la barre de menu supérieure dans la section "Rôles", cliquez sur "CRÉER UN RÔLE". Fournissez un nom et une description appropriés pour le nouveau rôle.

Ajoutez des autorisations à votre nouveau rôle en utilisant le filtre "Service:storage" (pas la boîte de saisie "Filtrer les autorisations par rôle"). Sélectionnez les autorisations suivantes :


- storage.buckets.create
- storage.buckets.get
- storage.buckets.update
- storage.objects.create
- storage.objects.delete
- storage.objects.get
- storage.objects.list
- storage.objects.update

Créez votre nouveau rôle.

Dans la barre latérale gauche, naviguez vers "Comptes de service".

Sur la barre de menu supérieure dans la section "Comptes de service", cliquez sur "CRÉER UN COMPTE DE SERVICE". Fournissez un nom et une description appropriés pour le nouveau compte de service. Sélectionnez le rôle que vous venez de créer et terminez le processus de création du compte de service.

Maintenant, dans le tableau de bord du compte de service, cliquez sur le nouveau compte de service et sélectionnez "clés" dans la barre de menu supérieure. Cliquez sur "AJOUTER UNE CLÉ" pour créer et télécharger une nouvelle clé (une clé JSON).

Configurez ensuite Taskwarrior avec :

    $ task config sync.gcp.bucket               <nom-du-bucket>
    $ task config sync.gcp.credential_path      <chemin-absolu-vers-les-identifiants-telecharges>

Amazon Web Services

Pour synchroniser vos tâches vers AWS, sélectionnez une région proche de vous et utilisez la console AWS pour créer un nouveau bucket S3. Les paramètres par défaut du bucket sont suffisants. En particulier, assurez-vous qu'aucune politique de cycle de vie n'est activée, car elles pourraient supprimer ou déplacer automatiquement des objets, impactant potentiellement la disponibilité des données.

Vous aurez également besoin d'un utilisateur AWS IAM avec la politique suivante, où BUCKETNAME est le nom du bucket. Le même utilisateur peut être configuré pour plusieurs clients Taskwarrior.

    {
        "Version": "2012-10-17",
        "Statement": [
            {
                "Sid": "TaskChampion",
                "Effect": "Allow",
                "Action": [
                    "s3:PutObject",
                    "s3:GetObject",
                    "s3:ListBucket",
                    "s3:DeleteObject"
                ],
                "Resource": [
                    "arn:aws:s3:::BUCKETNAME",
                    "arn:aws:s3:::BUCKETNAME/*"
                ]
            }
        ]
    }

Pour créer un tel utilisateur, créez une nouvelle politique dans la console IAM, sélectionnez l'option JSON dans l'éditeur de politique et collez la politique. Cliquez sur "Suivant" et donnez un nom à la politique, par exemple "TaskwarriorSync". Ensuite, créez un nouvel utilisateur, avec le nom de votre choix, sélectionnez "Attacher directement les politiques", puis choisissez la politique nouvellement créée.

Vous aurez besoin de clés d'accès configurées pour le nouvel utilisateur. Trouvez l'utilisateur dans la liste des utilisateurs, ouvrez l'onglet "Identifiants de sécurité", puis cliquez sur "Créer une clé d'accès" et suivez les étapes.

À ce stade, vous pouvez choisir comment fournir ces identifiants à Taskwarrior. Le plus simple est de les inclure dans la configuration de Taskwarrior :

    $ task config sync.aws.region              <region>
    $ task config sync.aws.bucket              <nom-du-bucket>
    $ task config sync.aws.access_key_id       <id-cle-acces>
    $ task config sync.aws.secret_access_key   <cle-acces-secrete>

Alternativement, vous pouvez configurer un profil AWS CLI, en utilisant un nom de profil de votre choix tel que "taskwarrior-creds" :

    $ aws configure --profile taskwarrior-creds

Entrez l'ID de clé d'accès et la clé d'accès secrète. La région et le format par défaut ne sont pas importants. Configurez ensuite Taskwarrior avec :

    $ task config sync.aws.region              <region>
    $ task config sync.aws.bucket              <nom-du-bucket>
    $ task config sync.aws.profile             taskwarrior-creds

Pour utiliser les sources d'identifiants par défaut d'AWS, telles que les variables d'environnement, le profil par défaut ou un profil d'instance, définissez

    $ task config sync.aws.region              <region>
    $ task config sync.aws.bucket              <nom-du-bucket>
    $ task config sync.aws.default_credentials true

Synchronisation locale

Afin de tirer parti de l'effet secondaire de la synchronisation qui permet d'économiser de l'espace disque sans configurer de serveur distant, il est possible de synchroniser les tâches localement. Pour configurer la synchronisation locale :

    $ task config sync.local.server_dir /chemin/vers/sync

NAME

task-sync - synchronizing tasks

INTRODUCTION

Taskwarrior has built-in synchronization capabilities. This document describes how to set up and use these capabilities.

MANAGING SYNCHRONIZATION

Taskwarrior synchronization uses a client-server model. The Taskwarrior sync server is a peer-to-peer synchronization server. It does not require special client software, only that the client be Taskwarrior.

The sync server is available from https://github.com/GothenburgBitFactory/taskchampion-sync-server.

The client is Taskwarrior itself. A client ID is required, and this is specified in the Taskwarrior configuration file, ~/.taskrc.

The configuration variable is:

    sync.server=https://example.com:8080/

A UUID, generated using any UUID generator, should be used as the client ID.

    sync.uuid=92394638-5335-4140-970c-a219e92252b2

It is important that the client ID be unique for each user, or each client, if a single user is using multiple clients. The sync server will not work if the client ID is not unique. Client IDs should be of the UUID format.

The sync server requires client to use HTTPS, but can be run over HTTP. To use HTTPS, the server must be configured with an SSL certificate. To use HTTP, the sync server must be started with the --ssl off option.

The sync server configuration requires specifying a user ID, which is a UUID string that identifies the user. This user ID should be the same for all clients belonging to the same user. The sync server will automatically create a new user, if the user ID specified is not already known.

In addition, the sync server requires a secret. This is a string that is used to encrypt the data. This secret must be generated by the user and must be the same for all clients belonging to the same user. The sync server is developed in https://github.com/GothenburgBitFactory/taskchampion-sync-server.

The sync server can be run with the following options:

--user uuid
The user ID, a UUID.
--secret secret
The encryption secret.
--port port
The port to listen on. Defaults to 8080.
--ssl on|off
Enable or disable SSL. Defaults to on.
--host host
The host to bind to. Defaults to all interfaces.

For example, to run the sync server with user ID "92394638-5335-4140-970c-a219e92252b2" and secret "mysecret" on port 8080:

    $ task-sync-server --user 92394638-5335-4140-970c-a219e92252b2 --secret mysecret

When syncing, Taskwarrior will present its client ID to the server. The server will then look up the user ID and secret. If the user ID is not found, the server will create a new user with the provided user ID and secret.

CONFIGURATION

To configure Taskwarrior to use the sync server, you need to set the following configuration variables in your ~/.taskrc file:

sync.server
The URL of the sync server. For example: sync.server=https://example.com:8080/
sync.uuid
A unique UUID for this client. For example: sync.uuid=92394638-5335-4140-970c-a219e92252b2

When you run the sync command, Taskwarrior will use these configuration variables to connect to the sync server.

The sync server is developed in https://github.com/GothenburgBitFactory/taskchampion-sync-server.

The sync server stores data in a directory specified by the data.location configuration variable.

RUNNING TASKCHAMPION-SYNC-SERVER

The TaskChampion sync server is an HTTP server supporting multiple users. Users are identified by a client ID, and users with different client IDs are entirely independent. Task data is encrypted by Taskwarrior, and the sync server never sees un-encrypted data.

The server is developed in https://github.com/GothenburgBitFactory/taskchampion-sync-server.

Adding a New User

To add a new user to the server, invent a new client ID with a tool like uuidgen or an online UUID generator. There is no need to configure the server for this new client ID: the sync server will automatically create a new user whenever presented with a new client ID. Supply the ID, along with the URL, to the user for inclusion in their Taskwarrior config. The user should invent their own "encryption_secret".

AVOIDING DUPLICATE RECURRING TASKS

If you run multiple clients that sync to the same server, you will need to run this command on your primary client (the one you use most often):

    $ task config recurrence on

And on the other clients, run:

    $ task config recurrence off

This protects you against the effects of a sync/duplication bug.

ALTERNATIVE: FILE SHARING SERVICES

There are many file sharing services, such as DropBox, Amazon S3, Google Drive, SkyDrive and more. This technique involves storing your .task directory in a shared directory under the control of the file hosting services.

Syncing happens quickly, although it is possible to run into conflict situations when there is no network connectivity, and the tasks are modified in two separate locations. This is because the file hosting service knows only about files, and it has no idea how to merge tasks. Avoid this problem by never modifying the same task on two machines, without an intervening sync.

Setup simply involves creating the directory and modifying your data.location configuration variable like this:

    $ task config data.location /path/to/shared/directory

Strengths:
- Good client support
- Easy setup
- Transparent use

Weaknesses:
- Tasks are not properly merged
