TALLOC(3) Outils d'administration système TALLOC(3)

NOM

talloc - système de pool de mémoire hiérarchique à comptage de références avec destructeurs

SYNTAXE

#include <talloc.h>

DESCRIPTION

Si vous êtes habitué à talloc de Samba3, lisez attentivement car talloc a beaucoup changé.

Le nouveau talloc est un système de pool de mémoire hiérarchique, à comptage de références, avec destructeurs. C'est assez complexe, mais pas trop difficile une fois que vous vous y êtes habitué.

Le changement le plus important par rapport à Samba3 est qu'il n'y a pas de distinction entre un « contexte talloc » et un « pointeur talloc ». Tout pointeur retourné par talloc() est lui-même un contexte talloc valide. Cela signifie que vous pouvez faire ceci :

    struct foo *X = talloc(mem_ctx, struct foo);
    X->name = talloc_strdup(X, "foo");

et le pointeur X->name serait un « enfant » du contexte talloc X, qui est lui-même un enfant de mem_ctx. Donc, si vous faites talloc_free(mem_ctx), tout est détruit, tandis que si vous faites talloc_free(X), seuls X et X->name sont détruits, et si vous faites talloc_free(X->name), seul l'élément name de X est détruit.

Si vous y réfléchissez, cela vous donne effectivement un arbre n-aire, où vous pouvez libérer n'importe quelle partie de l'arbre avec talloc_free().

Si vous trouvez cela déroutant, je vous suggère d'exécuter le programme de la suite de tests pour observer talloc en action. Vous pourriez également vouloir ajouter vos propres tests à testsuite.c pour clarifier la manière dont une situation particulière est gérée.

API TALLOC

Ce qui suit est un guide complet de l'API talloc. Lisez-le tout au moins deux fois.

(type *)talloc(const void *ctx, type);

La macro talloc() est le cœur de la bibliothèque talloc. Elle prend un contexte de mémoire ctx et un type, et retourne un pointeur vers une nouvelle zone de mémoire du type donné.

Le pointeur retourné est lui-même un contexte talloc, vous pouvez donc l'utiliser comme argument ctx pour d'autres appels à talloc() si vous le souhaitez.

Le pointeur retourné est un « enfant » du contexte fourni. Cela signifie que si vous appelez talloc_free() sur ctx, l'enfant disparaît également. Alternativement, vous pouvez libérer uniquement l'enfant.

L'argument ctx pour talloc() peut être NULL, auquel cas un nouveau contexte de niveau supérieur est créé.

void *talloc_size(const void *ctx, size_t size);

La fonction talloc_size() doit être utilisée lorsque vous n'avez pas de type pratique à passer à talloc(). Contrairement à talloc(), elle n'est pas sûre en termes de types (car elle retourne un void *), vous êtes donc seul responsable de la vérification des types.

(typeof(ptr)) talloc_ptrtype(const void *ctx, ptr);

La macro talloc_ptrtype() doit être utilisée lorsque vous avez un pointeur et que vous souhaitez allouer de la mémoire à pointer avec ce pointeur. Lors de la compilation avec gcc >= 3, elle est sûre en termes de types. Notez qu'il s'agit d'un wrapper de talloc_size() et que talloc_get_name() retournera l'emplacement actuel dans le fichier source, et non le type.

int talloc_free(void *ptr);

La fonction talloc_free() libère une partie de la mémoire talloc, ainsi que tous ses enfants. Vous pouvez appeler talloc_free() sur n'importe quel pointeur retourné par talloc().

La valeur de retour de talloc_free() indique le succès ou l'échec, avec 0 retourné pour le succès et -1 pour l'échec. La seule condition d'échec possible est si ptr avait un destructeur attaché et que le destructeur a retourné -1. Voir « talloc_set_destructor() » pour les détails sur les destructeurs.

Si ce pointeur a un parent supplémentaire lorsque talloc_free() est appelé, alors la mémoire n'est pas réellement libérée, mais le parent établi le plus récemment est détruit. Voir « talloc_reference() » pour les détails sur l'établissement de parents supplémentaires.

Pour plus de contrôle sur le parent à supprimer, voir « talloc_unlink() ».

talloc_free() opère récursivement sur ses enfants.

À partir de la version 2.0 de talloc, à titre spécial, talloc_free() est refusé sur les pointeurs ayant plus d'un parent, car talloc n'aurait aucun moyen de savoir quel parent doit être supprimé. Pour libérer un pointeur ayant plus d'un parent, veuillez utiliser talloc_unlink().

Pour vous aider à trouver des problèmes dans votre code causés par ce comportement, si vous essayez de libérer un pointeur ayant plus d'un parent, la fonction de journalisation talloc sera appelée pour produire une sortie comme celle-ci :

    ERROR: talloc_free with references at some_dir/source/foo.c:123
	reference at some_dir/source/other.c:325
	reference at some_dir/source/third.c:121

Veuillez consulter la documentation de talloc_set_log_fn() et talloc_set_log_stderr() pour plus d'informations sur les fonctions de journalisation de talloc.

void *talloc_reference(const void *ctx, const void *ptr);

La fonction talloc_reference() fait de ctx un parent supplémentaire de ptr.

La valeur de retour de talloc_reference() est toujours le pointeur d'origine ptr, à moins que talloc n'ait manqué de mémoire lors de la création de la référence, auquel cas il retournera NULL (chaque référence supplémentaire consomme environ 48 octets de mémoire sur les plateformes Intel x86).

Si ptr est NULL, la fonction ne fait rien et retourne simplement NULL.

Après avoir créé une référence, vous pouvez la libérer de l'une des manières suivantes :

•vous pouvez appeler talloc_free() sur n'importe quel parent du pointeur d'origine. Cela réduira le nombre de parents de ce pointeur de 1, et provoquera la libération de ce pointeur s'il n'a plus de parents.
•vous pouvez appeler talloc_free() sur le pointeur lui-même s'il a au maximum un parent. Ce comportement a été modifié depuis la version 2.0. Plus d'informations dans la description de « talloc_free ».

Pour plus de contrôle sur le parent à supprimer, voir « talloc_unlink() ».

int talloc_unlink(const void *ctx, void *ptr);

La fonction talloc_unlink() supprime un parent spécifique de ptr. Le ctx passé doit soit être un contexte utilisé dans talloc_reference() avec ce pointeur, soit être un parent direct de ptr.

Notez que si le parent a déjà été supprimé à l'aide de talloc_free(), cette fonction échouera et retournera -1. De même, si ptr est NULL, la fonction n'apportera aucune modification et retournera -1.

Habituellement, vous pouvez simplement utiliser talloc_free() à la place de talloc_unlink(), mais il est parfois utile d'avoir un contrôle supplémentaire sur le parent à supprimer.

void talloc_set_destructor(const void *ptr, int (*destructor)(void *));

La fonction talloc_set_destructor() définit le destructeur pour le pointeur ptr. Un destructeur est une fonction qui est appelée lorsque la mémoire utilisée par un pointeur est sur le point d'être libérée. Le destructeur reçoit ptr comme argument et doit retourner 0 en cas de succès et -1 en cas d'échec.

Le destructeur peut faire tout ce qu'il veut, y compris libérer d'autres blocs de mémoire. Une utilisation courante des destructeurs est de nettoyer les ressources du système d'exploitation (telles que les descripteurs de fichiers ouverts) contenues dans la structure sur laquelle le destructeur est placé.

Vous ne pouvez placer qu'un seul destructeur sur un pointeur. Si vous avez besoin de plus d'un destructeur, vous pouvez créer un enfant de longueur zéro du pointeur et y placer un destructeur supplémentaire.

Pour supprimer un destructeur, appelez talloc_set_destructor() avec NULL pour le destructeur.

Si votre destructeur tente d'appeler talloc_free() sur le pointeur pour lequel il est le destructeur, talloc_free() retournera -1 et la libération sera ignorée. Ce serait b

int talloc_increase_ref_count(const void *ptr);

La fonction talloc_increase_ref_count(ptr) est exactement équivalente à :

talloc_reference(NULL, ptr);

Vous pouvez utiliser l'une ou l'autre syntaxe, selon celle qui vous semble la plus claire dans votre code.

Elle retourne 0 en cas de succès et -1 en cas d'échec.

size_t talloc_reference_count(const void *ptr);

Retourne le nombre de références vers le pointeur.

void talloc_set_name(const void *ptr, const char *fmt, ...);

Chaque pointeur talloc a un « nom ». Le nom est utilisé principalement à des fins de débogage, bien qu'il soit également possible de définir et d'obtenir le nom d'un pointeur comme moyen de « marquer » des pointeurs dans votre code.

L'utilisation principale des noms sur les pointeurs est pour les « rapports talloc ». Voir « talloc_report_depth_cb() », « talloc_report_depth_file() », « talloc_report() » « talloc_report() » et « talloc_report_full() » pour plus de détails. Voir également « talloc_enable_leak_report() » et « talloc_enable_leak_report_full() ».

La fonction talloc_set_name() alloue de la mémoire en tant qu'enfant du pointeur. Elle est logiquement équivalente à :

talloc_set_name_const(ptr, talloc_asprintf(ptr, fmt, ...));

Notez que plusieurs appels à talloc_set_name() alloueront plus de mémoire sans libérer le nom. Toute la mémoire est libérée lorsque le pointeur est libéré à l'aide de talloc_free().

void talloc_set_name_const(const void *ptr, const char *name);

La fonction talloc_set_name_const() est identique à talloc_set_name(), mais elle prend une chaîne constante et est beaucoup plus rapide. Elle est largement utilisée par les macros de « nommage automatique », telles que talloc_p().

Cette fonction n'alloue aucune mémoire. Elle copie simplement le pointeur fourni dans la représentation interne du pointeur talloc. Cela signifie que vous ne devez pas passer un pointeur name vers une mémoire qui disparaîtra avant que ptr ne soit libéré avec talloc_free().

void *talloc_named(const void *ctx, size_t size, const char *fmt, ...);

La fonction talloc_named() crée un pointeur talloc nommé. Elle est équivalente à :

ptr = talloc_size(ctx, size);
talloc_set_name(ptr, fmt, ....);

void *talloc_named_const(const void *ctx, size_t size, const char *name);

Ceci est équivalent à :

ptr = talloc_size(ctx, size);
talloc_set_name_const(ptr, name);

const char *talloc_get_name(const void *ptr);

Ceci retourne le nom actuel du pointeur talloc donné, ptr. Voir « talloc_set_name() » pour plus de détails.

void *talloc_init(const char *fmt, ...);

Cette fonction crée un contexte talloc nommé de longueur zéro comme contexte de niveau supérieur. Elle est équivalente à :

talloc_named(NULL, 0, fmt, ...);

void *talloc_new(void *ctx);

Ceci est une macro utilitaire qui crée un nouveau contexte mémoire rattaché à un contexte existant, le nommant automatiquement « talloc_new: __location__ » où __location__ est la ligne source d'où il est appelé. Elle est particulièrement utile pour créer un nouveau contexte de travail temporaire.

(type *)talloc_realloc(const void *ctx, void *ptr, type, count);

La macro talloc_realloc() change la taille d'un pointeur talloc. Elle a les équivalences suivantes :

talloc_realloc(ctx, NULL, type, 1) ==> talloc(ctx, type);
talloc_realloc(ctx, ptr, type, 0)  ==> talloc_free(ptr);

L'argument ctx n'est utilisé que si ptr n'est pas NULL, sinon il est ignoré.

talloc_realloc() retourne le nouveau pointeur, ou NULL en cas d'échec. L'appel échouera soit en raison d'un manque de mémoire, soit parce que le pointeur a plus d'un parent (voir « talloc_reference() »).

void *talloc_realloc_size(const void *ctx, void *ptr, size_t size);

La fonction talloc_realloc_size() est utile lorsque le type n'est pas connu, de sorte que le talloc_realloc() type-safe ne puisse pas être utilisé.

TYPE *talloc_steal(const void *new_ctx, const TYPE *ptr);

La fonction talloc_steal() change le contexte parent d'un pointeur talloc. Elle est généralement utilisée lorsque le contexte dont le pointeur est actuellement enfant va être libéré et que vous souhaitez conserver la mémoire plus longtemps.

La fonction talloc_steal() retourne le pointeur que vous lui passez. Elle n'a aucun mode d'échec.

Il est possible de produire des boucles dans la relation parent/enfant si vous n'êtes pas prudent avec talloc_steal(). Aucune garantie n'est fournie quant à votre santé mentale ou à la sécurité de vos données si vous faites cela.

Notez que si vous essayez d'appeler talloc_steal() sur un pointeur qui a plus d'un parent, le résultat est ambigu. Talloc choisira de supprimer le parent actuellement indiqué par talloc_parent() et de le remplacer par le parent choisi. Vous recevrez également un message comme celui-ci via les fonctions de journalisation talloc :

  WARNING: talloc_steal with references at some_dir/source/foo.c:123
	reference at some_dir/source/other.c:325
	reference at some_dir/source/third.c:121

Pour changer sans ambiguïté le parent d'un pointeur, voir la fonction « talloc_reparent() ». Voir la documentation de talloc_set_log_fn() pour plus d'informations sur la journalisation talloc.

TYPE *talloc_reparent(const void *old_parent, const void *new_parent, const TYPE *ptr);

La fonction talloc_reparent() change le contexte parent d'un pointeur talloc. Elle est généralement utilisée lorsque le contexte dont le pointeur est actuellement enfant va être libéré et que vous souhaitez conserver la mémoire plus longtemps.

La fonction talloc_reparent() retourne le pointeur que vous lui passez. Elle n'a aucun mode d'échec.

La différence entre talloc_reparent() et talloc_steal() est que talloc_reparent() peut spécifier quel parent vous souhaitez modifier. Ceci est utile lorsqu'un pointeur a plusieurs parents via des références.

TYPE *talloc_move(const void *new_ctx, TYPE **ptr);

La fonction talloc_move() est un wrapper autour de talloc_steal() qui met à zéro le pointeur source après le déplacement. Cela évite une source potentielle de bugs où un programmeur laisse un pointeur dans deux structures, et utilise le pointeur de l'ancienne structure après qu'il ait été déplacé vers une nouvelle.

size_t talloc_total_size(const void *ptr);

La fonction talloc_total_size() retourne la taille totale en octets utilisée par ce pointeur et tous les pointeurs enfants. Principalement utile pour le débogage.

Passer NULL est autorisé, mais cela ne donnera un résultat significatif que si talloc_enable_leak_report() ou talloc_enable_leak_report_full() a été appelé.

size_t talloc_total_blocks(const void *ptr);

La fonction talloc_total_blocks() retourne le nombre total de blocs de mémoire utilisés par ce pointeur et tous les pointeurs enfants. Principalement utile pour le débogage.

Passer NULL est autorisé, mais cela ne donnera un résultat significatif que si talloc_enable_leak_report() ou talloc_enable_leak_report_full() a été appelé.

NOM

talloc - Gestionnaire d'allocations de mémoire avec contexte

SYNOPSIS

#include <talloc.h>

void *talloc_realloc_fn(const void *ctx, void *ptr, size_t size);
void *talloc_autofree_context(void);
void *talloc_check_name(const void *ptr, const char *name);
(type *)talloc_get_type(const void *ptr, type);
talloc_set_type(const void *ptr, type);
talloc_set_log_fn(void (*log_fn)(const char *message));
talloc_set_log_stderr(void);

DESCRIPTION

Talloc est une bibliothèque qui fournit un système de gestion de la mémoire qui peut être utilisé pour gérer des structures de données liées entre elles. Chaque objet alloué avec talloc est un "child" d'un autre objet talloc, le "parent". Lorsqu'un objet parent est libéré, tous ses enfants sont également libérés.

Ceci permet de simplifier grandement la gestion de la mémoire pour les structures de données complexes. Par exemple, si vous avez une structure qui contient des chaînes de caractères allouées dynamiquement et d'autres structures, vous pouvez tout allouer à partir du même contexte talloc. Lorsqu'il est temps de libérer la structure principale, tout ce qui lui est associé sera libéré automatiquement.

Le système talloc est également utile pour créer des gestionnaires de ressources, tels que des connexions réseau ou des descripteurs de fichiers. Ces ressources peuvent être liées à un contexte talloc, garantissant qu'elles seront correctement libérées lorsqu'elles ne seront plus nécessaires.

void *talloc_realloc_fn(const void *ctx, void *ptr, size_t size);

Ceci est une version non-macro de talloc_realloc(), ce qui est utile car les bibliothèques veulent parfois un pointeur de fonction realloc. Une implémentation de realloc(3) encapsule les fonctionnalités de malloc(3), free(3) et realloc(3) en un seul appel, c'est pourquoi il est utile de pouvoir transmettre un seul pointeur de fonction.

void *talloc_autofree_context(void);

Ceci est une fonction utilitaire pratique qui renvoie un contexte talloc qui sera automatiquement libéré à la sortie du programme. Ceci peut être utilisé pour réduire le bruit dans les rapports de fuites de mémoire.

void *talloc_check_name(const void *ptr, const char *name);

Cette fonction vérifie si un pointeur a le nom spécifié name. Si c'est le cas, le pointeur est renvoyé. Sinon, NULL est renvoyé.

(type *)talloc_get_type(const void *ptr, type);

Cette macro vous permet de faire des vérifications de type sur les pointeurs talloc. Elle est particulièrement utile pour les pointeurs privés de type void*. Elle est équivalente à ceci:

(type *)talloc_check_name(ptr, #type)

talloc_set_type(const void *ptr, type);

Cette macro vous permet de forcer le nom d'un pointeur à être un type particulier. Ceci peut être utilisé en conjonction avec talloc_get_type() pour effectuer des vérifications de type sur les pointeurs void*.

Elle est équivalente à ceci:

talloc_set_name_const(ptr, #type)

talloc_set_log_fn(void (*log_fn)(const char *message));

Cette fonction définit une fonction de journalisation que talloc utilisera pour les avertissements et les erreurs. Par défaut, talloc n'imprime aucun avertissement ni erreur.

talloc_set_log_stderr(void);

Ceci définit la fonction de journalisation talloc pour écrire les messages de journal dans stderr.

PERFORMANCE

Toutes les fonctionnalités supplémentaires de talloc(3) par rapport à malloc(3) ont un coût. Nous avons un test de performance dans Samba qui mesure la performance de talloc() par rapport à malloc(), et il semble que talloc() soit environ 50% plus lent que malloc() (AMD Ryzen 9 3900X). Pour Samba, la grande réduction de la complexité du code que nous obtenons en utilisant talloc rend cela rentable, d'autant plus que la surcharge totale de talloc/malloc dans Samba est déjà assez faible.
