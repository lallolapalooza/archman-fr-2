TASKSET(1) Commandes utilisateur TASKSET(1)

NOM

taskset - définir ou récupérer l'affinité CPU d'un processus

SYNTAXE

taskset [options] masque commande [argument...]

taskset [options] -p [masque] pid

DESCRIPTION

La commande taskset est utilisée pour définir ou récupérer l'affinité CPU d'un processus en cours d'exécution donné par son pid, ou pour lancer une nouvelle commande avec une affinité CPU donnée. L'affinité CPU est une propriété de l'ordonnanceur qui "lie" un processus à un ensemble donné de CPUs sur le système. L'ordonnanceur Linux respectera l'affinité CPU donnée et le processus ne s'exécutera sur aucun autre CPU. Notez que l'ordonnanceur Linux prend également en charge l'affinité CPU naturelle : l'ordonnanceur tente de garder les processus sur le même CPU autant que possible pour des raisons de performance. Par conséquent, forcer une affinité CPU spécifique n'est utile que dans certaines applications. L'affinité de certains processus comme les threads par CPU du noyau ne peut pas être définie.

L'affinité CPU est représentée par un masque de bits, le bit d'ordre le plus bas correspondant au premier CPU logique et le bit d'ordre le plus élevé correspondant au dernier CPU logique. Tous les CPUs peuvent ne pas exister sur un système donné, mais un masque peut spécifier plus de CPUs qu'il n'y en a physiquement. Un masque récupéré ne reflétera que les bits correspondant aux CPUs physiquement présents sur le système. Si un masque invalide est donné (c'est-à-dire un masque qui ne correspond à aucun CPU valide sur le système actuel), une erreur est retournée. Les masques peuvent être spécifiés en hexadécimal (avec ou sans le préfixe "0x"), ou sous forme de liste de CPUs avec l'option --cpu-list. Par exemple,

0x00000001

est le processeur #0,

0x00000003

sont les processeurs #0 et #1,

FFFFFFFF

sont les processeurs #0 à #31,

0x32

sont les processeurs #1, #4 et #5,

--cpu-list 0-2,6

sont les processeurs #0, #1, #2 et #6.

--cpu-list 0-10:2

sont les processeurs #0, #2, #4, #6, #8 et #10. Le suffixe ":N" spécifie le pas dans la plage, par exemple 0-10:3 est interprété comme la liste 0,3,6,9.

Lorsque taskset retourne, il est garanti que le programme donné a été planifié sur un CPU légal.

OPTIONS

-a, --all-tasks

Définit ou récupère l'affinité CPU de toutes les tâches (threads) pour un PID donné.

-c, --cpu-list

Interprète masque comme une liste numérique de processeurs au lieu d'un masque de bits. Les nombres sont séparés par des virgules et peuvent inclure des plages. Par exemple : 0,5,8-11.

-p, --pid

Opère sur un PID existant et ne lance pas de nouvelle tâche.

-h, --help

Affiche le texte d'aide et quitte.

-V, --version

Affiche la version et quitte.

UTILISATION

Le comportement par défaut est d'exécuter une nouvelle commande avec un masque d'affinité donné :

taskset masque commande [arguments]

Vous pouvez également récupérer l'affinité CPU d'une tâche existante :

taskset -p pid

Ou la définir :

taskset -p masque pid

Lorsqu'une liste de CPUs est spécifiée pour un processus existant, les options -p et -c doivent être groupées :

taskset -pc liste-cpu pid

La forme --cpu-list est applicable uniquement lors du lancement de nouvelles commandes :

taskset --cpu-list liste-cpu commande

PERMISSIONS

Un utilisateur peut changer l'affinité CPU d'un processus lui appartenant.

Un utilisateur doit posséder CAP_SYS_NICE pour changer l'affinité CPU d'un processus appartenant à un autre utilisateur.

Un utilisateur peut récupérer le masque d'affinité de n'importe quel processus.

STATUT DE SORTIE

taskset retourne 0 en mode récupération d'affinité tant que le PID fourni existe.

taskset retourne 0 en mode définition d'affinité tant que l'appel système sched_setaffinity(2) sous-jacent le fait. Le succès de la commande ne garantit pas que le thread spécifié a effectivement migré vers le(s) CPU(s) indiqué(s), mais seulement que le thread ne migrera pas vers un CPU en dehors du nouveau masque d'affinité. Par exemple, l'affinité du thread du noyau kswapd peut être définie, mais le thread peut ne pas migrer immédiatement et il n'est pas garanti qu'il le fera un jour :

$ ps ax -o comm,psr,pid | grep kswapd
kswapd0 4 82
$ sudo taskset -p 1 82
pid 82’s current affinity mask: 1
pid 82’s new affinity mask: 1
$ echo $?
0
$ ps ax -o comm,psr,pid | grep kswapd
kswapd0 4 82
$ taskset -p 82
pid 82’s current affinity mask: 1

En revanche, lorsque l'utilisateur spécifie une affinité illégale, taskset affichera une erreur et retournera 1 :

$ ps ax -o comm,psr,pid | grep ksoftirqd/0
ksoftirqd/0 0 14
$ sudo taskset -p 1 14
pid 14’s current affinity mask: 1
taskset: failed to set pid 14’s affinity: Invalid argument
$ echo $?
1
