timer_getoverrun(2) Manuel des appels système timer_getoverrun(2)

NOM

timer_getoverrun - obtenir le nombre de dépassements pour un minuteur POSIX par processus

BIBLIOTHQUE

Bibliothèque temps réel (librt, -lrt)

SYNTAXE

#include <time.h>
int timer_getoverrun(timer_t timerid);
Exigences pour les macros de test de fonctionnalité dans glibc (voir feature_test_macros(7)):

timer_getoverrun():

    _POSIX_C_SOURCE >= 199309L

DESCRIPTION

timer_getoverrun() renvoie le "nombre de dépassements" pour le minuteur référencé par timerid. Une application peut utiliser le compte des dépassements pour calculer avec précision le nombre d'expirations de minuteur qui se seraient produites sur un intervalle de temps donné. Les dépassements de minuteur peuvent survenir à la fois lors de la réception de notifications d'expiration via des signaux (SIGEV_SIGNAL) et via des threads (SIGEV_THREAD).

Lorsque les notifications d'expiration sont délivrées via un signal, des dépassements peuvent survenir comme suit. Indépendamment de l'utilisation ou non d'un signal temps réel pour les notifications de minuteur, le système met en file d'attente au maximum un signal par minuteur. (C'est le comportement spécifié par POSIX.1. L'alternative, mettre en file d'attente un signal pour chaque expiration de minuteur, pourrait facilement dépasser les limites autorisées pour les signaux mis en file d'attente sur le système.) En raison des délais de planification du système, ou parce que le signal peut être temporairement bloqué, il peut y avoir un délai entre le moment où le signal de notification est généré et le moment où il est délivré (par exemple, intercepté par un gestionnaire de signal) ou accepté (par exemple, en utilisant sigwaitinfo(2)). Pendant cet intervalle, d'autres expirations de minuteur peuvent se produire. Le compte des dépassements de minuteur est le nombre d'expirations de minuteur supplémentaires qui se sont produites entre le moment où le signal a été généré et celui où il a été délivré ou accepté.

Des dépassements de minuteur peuvent également survenir lorsque des notifications d'expiration sont délivrées via l'invocation d'un thread, car il peut y avoir un délai arbitraire entre une expiration du minuteur et l'invocation du thread de notification, et pendant cet intervalle de délai, d'autres expirations de minuteur peuvent survenir.

VALEUR DE RETOUR

En cas de succès, timer_getoverrun() renvoie le compte des dépassements du minuteur spécifié ; ce compte peut être 0 si aucun dépassement ne s'est produit. En cas d'échec, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
timerid n'est pas un identifiant de minuteur valide.

VERSIONS

Lorsque les notifications de minuteur sont délivrées via des signaux (SIGEV_SIGNAL), sous Linux, il est également possible d'obtenir le compte des dépassements via le champ si_overrun de la structure siginfo_t (voir sigaction(2)). Cela permet à une application d'éviter le surcoût d'un appel système pour obtenir le compte des dépassements, mais il s'agit d'une extension non portable de POSIX.1.

POSIX.1 discute des dépassements de minuteur uniquement dans le contexte des notifications de minuteur utilisant des signaux.

NORMES

POSIX.1-2024.

HISTORIQUE

Linux 2.6. POSIX.1-2001.

BOGUES

POSIX.1 spécifie que si le compte des dépassements de minuteur est égal ou supérieur à un maximum défini par l'implémentation, DELAYTIMER_MAX, alors timer_getoverrun() doit renvoyer DELAYTIMER_MAX. Cependant, avant Linux 4.19, si la valeur de dépassement du minuteur dépasse le maximum entier représentable, le compteur boucle, recommençant à de faibles valeurs. Depuis Linux 4.19, timer_getoverrun() renvoie DELAYTIMER_MAX (défini comme INT_MAX dans <limits.h>) dans ce cas (et la valeur de dépassement est réinitialisée à 0).

EXEMPLES

Voir timer_create(2).
