TINC.CONF(5) Manuel des formats de fichiers TINC.CONF(5)

NOM

tinc.conf — configuration du démon tinc

DESCRIPTION

Les fichiers du répertoire /etc/tinc/ contiennent des informations d'exécution et de sécurité pour le démon tinc.

RÉSEAUX

Il est tout à fait possible d'exécuter plusieurs démons tinc. Cependant, dans sa forme par défaut, vous remarquerez bientôt que vous ne pouvez pas utiliser deux fichiers de configuration différents sans l'option -c.

Nous avons pensé à une autre façon de gérer cela : les noms de réseau. Cela signifie que vous appelez tinc.conf avec l'option -n, ce qui attribuera un nom à ce démon.

L'effet est que le démon définira sa racine de configuration à /etc/tinc/NOMRESEAU/, où NOMRESEAU est votre argument pour l'option -n. Vous remarquerez que les messages apparaissant dans syslog proviendront de tincd.NOMRESEAU.

Cependant, il n'est pas strictement nécessaire d'appeler tinc avec l'option -n. Dans ce cas, le nom du réseau sera simplement vide, et sera utilisé comme tel. tinc recherche maintenant les fichiers dans /etc/tinc/, au lieu de /etc/tinc/NOMRESEAU/ ; le fichier de configuration devrait être /etc/tinc/tinc.conf, et les fichiers de configuration d'hôte sont maintenant attendus dans /etc/tinc/hosts/.

Mais il est fortement recommandé d'utiliser cette fonctionnalité de tinc, car il sera beaucoup plus clair à qui votre démon parle. Par conséquent, nous supposerons que vous l'utilisez.

NOMS

Chaque démon tinc doit avoir un nom unique dans le réseau dont il fera partie. Le nom sera utilisé par d'autres démons tinc pour l'identification. Le nom doit être déclaré dans le fichier /etc/tinc/NOMRESEAU/tinc.conf.

Pour simplifier les choses, choisissez quelque chose qui donnera des noms uniques et faciles à retenir à votre ou vos démons tinc. Vous pourriez essayer des noms d'hôte, des noms de famille de propriétaires ou des noms de lieux.

CLÉS PUBLIQUES/PRIVÉES

Vous devriez utiliser tincd -K pour générer des paires de clés publique/privée. Cela générera deux clés. La clé privée devrait être stockée dans un fichier séparé /etc/tinc/NOMRESEAU/rsa_key.priv -- où NOMRESEAU représente le réseau (voir RÉSEAUX ci-dessus). La clé publique devrait être stockée dans le fichier de configuration d'hôte /etc/tinc/NOMRESEAU/hosts/NOM -- où NOM représente le nom du démon tinc local (voir NOMS).

CONFIGURATION SERVEUR

La configuration du serveur du démon se fait dans le fichier /etc/tinc/NOMRESEAU/tinc.conf. Ce fichier se compose de commentaires (lignes commençant par un #) ou d'affectations sous la forme :

Variable = Valeur.

Les noms de variables ne sont pas sensibles à la casse, et tous les espaces, tabulations, retours à la ligne et retours chariot sont ignorés. Remarque : il n'est pas obligatoire de mettre le signe =, mais le faire améliore la lisibilité. Si vous l'omettez, n'oubliez pas de le remplacer par au moins un espace.

La configuration du serveur est complétée par la configuration spécifique à l'hôte (voir la section suivante). Bien que toutes les options de configuration pour l'hôte local listées dans ce document puissent également être placées dans /etc/tinc/NOMRESEAU/tinc.conf, il est recommandé de placer les options de configuration spécifiques à l'hôte dans le fichier de configuration d'hôte, car cela facilite l'échange avec d'autres nœuds.

Voici toutes les variables valides, listées par ordre alphabétique. La valeur par défaut est indiquée entre parenthèses.

AddressFamily = ipv4 | ipv6 | any (any)
Cette option affecte la famille d'adresses des sockets d'écoute et de sortie. Si « any » est sélectionné, alors en fonction du système d'exploitation, des sockets d'écoute IPv4 et IPv6, ou seulement IPv6, seront créés.
BindToAddress = adresse [port] [experimental]
Si votre ordinateur possède plus d'une adresse IPv4 ou IPv6, tinc écoutera par défaut sur toutes ces adresses pour les connexions entrantes. Plusieurs variables BindToAddress peuvent être spécifiées, auquel cas des sockets d'écoute pour chaque adresse spécifiée seront créés.

Si aucun port n'est spécifié, le socket sera lié au port spécifié par l'option Port, ou au port 655 si aucun des deux n'est donné. Pour ne se lier qu'à un port spécifique mais pas à une adresse spécifique, utilisez * pour l'adresse.

Cette option peut ne pas fonctionner sur toutes les plateformes.

BindToInterface = interface [experimental]
Si votre ordinateur possède plus d'une interface réseau, tinc écoutera par défaut sur toutes ces interfaces pour les connexions entrantes. Il est possible de se lier à une seule interface avec cette variable.

Cette option peut ne pas fonctionner sur toutes les plateformes. De plus, sur certaines plateformes, elle ne se liera pas réellement à une interface, mais plutôt à l'adresse que l'interface possède au moment de la création d'un socket.

Broadcast = no | mst | direct (mst) [experimental]
Cette option sélectionne la manière dont les paquets de diffusion sont envoyés aux autres démons. NOTE : tous les nœuds d'un VPN doivent utiliser le même mode Broadcast, sinon des boucles de routage peuvent se former.
no
Les paquets de diffusion ne sont jamais envoyés aux autres nœuds.
mst
Les paquets de diffusion sont envoyés et acheminés via l'arbre couvrant minimum (Minimum Spanning Tree) du VPN. Cela garantit que les paquets de diffusion atteignent tous les nœuds.
direct
Les paquets de diffusion sont envoyés directement à tous les nœuds qui peuvent être atteints directement. Les paquets de diffusion reçus d'autres nœuds ne sont jamais acheminés. Si l'option IndirectData est également définie, les paquets de diffusion ne seront envoyés qu'aux nœuds avec lesquels nous avons une connexion méta.
ConnectTo = nom
Spécifie à quel autre démon tinc se connecter au démarrage. Plusieurs variables ConnectTo peuvent être spécifiées, auquel cas des connexions sortantes vers chaque démon tinc spécifié seront établies. Les noms doivent être connus de ce démon tinc (c'est-à-dire qu'il doit y avoir un fichier de configuration d'hôte pour le nom sur la ligne ConnectTo).

Si vous ne spécifiez pas d'hôte avec ConnectTo, tinc n'essaiera pas de se connecter à d'autres démons du tout, et se contentera d'écouter les connexions entrantes.

DecrementTTL = yes | no (no) [experimental]
Lorsqu'il est activé, tinc décrémentera le champ Time To Live (durée de vie) dans les paquets IPv4, ou le champ Hop Limit (limite de sauts) dans les paquets IPv6, avant d'acheminer un paquet reçu vers le périphérique réseau virtuel ou vers un autre nœud, et abandonnera les paquets ayant une valeur TTL de zéro, auquel cas il renverra un paquet ICMP Time Exceeded (Temps dépassé).

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

>N'utilisez pas cette option si vous utilisez le mode switch et que vous souhaitez utiliser IPv6.

Device = device (/dev/tap0, /dev/net/tun ou autre selon la plateforme)
Le périphérique réseau virtuel à utiliser. tinc détectera automatiquement son type. Notez que vous ne pouvez utiliser qu'un seul périphérique par démon. Sous Windows, utilisez Interface à la place de Device. Les pages d'information du package tinc contiennent plus d'informations sur la configuration du périphérique réseau virtuel.
DeviceType = type (dépendant de la plateforme)
Le type du périphérique réseau virtuel. Tinc sélectionne normalement automatiquement le bon type d'interface tun/tap, et cette option ne devrait pas être utilisée. Cependant, cette option peut être utilisée pour sélectionner l'un des types d'interface spéciaux, si le support pour ceux-ci est compilé.
dummy
Utilise une interface factice. Aucun paquet n'est jamais lu ou écrit sur un périphérique réseau virtuel. Utile pour les tests, ou lors de la mise en place d'un nœud qui ne fait que transférer des paquets pour d'autres nœuds.
raw_socket
Ouvre une socket brute, et la lie à une Interface préexistante (eth0 par défaut). Tous les paquets sont lus à partir de cette interface. Les paquets reçus pour le nœud local sont écrits dans la socket brute. Cependant, au moins sous Linux, le système d'exploitation ne traite pas les paquets IP destinés à l'hôte local.
multicast
Ouvre une socket UDP multicast et la lie à l'adresse et au port (séparés par des espaces) et éventuellement à une valeur TTL spécifiée à l'aide de Device. Les paquets sont lus et écrits à partir de cette socket multicast. Cela peut être utilisé pour se connecter à des instances UML, QEMU ou KVM écoutant sur la même adresse multicast. NE connectez PAS plusieurs démons tinc à la même adresse multicast, cela provoquera très probablement des boucles de routage. Notez également que cela peut entraîner l'envoi de paquets VPN déchiffrés sur un réseau réel s'il est mal configuré.
uml (non compilé par défaut)
Crée une socket UNIX avec le nom de fichier spécifié par Device, ou /var/run/NETNAME.umlsocket si non spécifié. tinc attendra qu'une instance User Mode Linux se connecte à cette socket.
vde (non compilé par défaut)
Utilise la bibliothèque libvdeplug pour se connecter à un commutateur Ethernet distribué virtuel (Virtual Distributed Ethernet), en utilisant la socket UNIX spécifiée par Device, ou /var/run/vde.ctl si non spécifié.
De plus, dans le cas où tinc ne semble pas interpréter correctement les paquets reçus du périphérique réseau virtuel, il peut être utilisé pour modifier la manière dont les paquets sont interprétés :
tun (BSD et Linux)
Définit le type sur tun. Selon la plateforme, cela peut être avec ou sans en-tête de famille d'adresses (voir ci-dessous).
tunnohead (BSD)
Définit le type sur tun sans en-tête de famille d'adresses. Tinc s'attendra à ce que les paquets lus depuis le périphérique réseau virtuel commencent par un en-tête IP. Sur certaines plateformes, les paquets IPv6 ne peuvent pas être lus ou écrits sur le périphérique dans ce mode.
tunifhead (BSD)
Définit le type sur tun avec un en-tête de famille d'adresses. Tinc s'attendra à ce que les paquets lus depuis le périphérique réseau virtuel commencent par un en-tête de quatre octets contenant la famille d'adresses, suivi d'un en-tête IP. Ce mode devrait prendre en charge les paquets IPv4 et IPv6.
utun (OS X)
Définit le type sur utun. Ceci n'est pris en charge que sur OS X version 10.6.8 et supérieure, mais ne nécessite pas le module tuntaposx. Ce mode devrait prendre en charge les paquets IPv4 et IPv6.
tap (BSD et Linux)
Définit le type sur tap. Tinc s'attendra à ce que les paquets lus depuis le périphérique réseau virtuel commencent par un en-tête Ethernet.
DirectOnly = yes | no (no) [expérimental]
Lorsque cette option est activée, les paquets qui ne peuvent pas être envoyés directement au nœud de destination, mais qui devraient être transférés par un nœud intermédiaire, sont ignorés. Lorsqu'elle est combinée avec l'option IndirectData, les paquets destinés aux nœuds avec lesquels nous n'avons pas de connexion méta sont également ignorés.
Forwarding = off | internal | kernel (internal) [expérimental]
Cette option sélectionne la manière dont les paquets indirects sont transférés.
off
Les paquets entrants qui ne sont pas destinés au nœud local, mais qui devraient être transférés à un autre nœud, sont ignorés.
internal
Les paquets entrants destinés à un autre nœud sont transférés en interne par tinc.

C'est le mode par défaut, et sauf si vous savez vraiment que vous avez besoin d'un autre mode de transfert, ne le modifiez pas.

kernel
Les paquets entrants sont toujours envoyés au périphérique TUN/TAP, même si les paquets ne sont pas destinés au nœud local. C'est moins efficace, mais cela permet au noyau d'appliquer ses règles de routage et de pare-feu, et peut également aider au débogage.
GraphDumpFile = nom_fichier [expérimental]
Si cette option est présente, tinc exportera le graphique réseau actuel dans le fichier nom_fichier toutes les minutes, sauf si le graphique n'a subi aucune modification. Le fichier est dans un format lisible par les outils graphviz. Si nom_fichier commence par un symbole pipe (|), alors le reste du nom de fichier est interprété comme une commande shell qui est exécutée, le graphique est ensuite envoyé à stdin.
Hostnames = yes | no (no)
Cette option sélectionne si les adresses IP (réelles et sur le VPN) doivent être résolues. Comme les recherches DNS bloquent, cela peut affecter l'efficacité de tinc, voire arrêter le démon pendant quelques secondes à chaque recherche si votre serveur DNS ne répond pas.

Cela n'affecte pas la résolution des noms d'hôte en adresses IP à partir des fichiers de configuration hôte, mais si les noms d'hôte doivent être résolus lors de la journalisation.

IffOneQueue = yes | no (no) [expérimental]
(Linux uniquement) Définit le drapeau IFF_ONE_QUEUE sur les périphériques TUN/TAP.
Interface = interface
Définit le nom de l'interface correspondant au périphérique réseau virtuel. Selon le système d'exploitation et le type de périphérique, cela peut ou peut ne pas définir réellement le nom de l'interface. Sous Windows, cette variable est utilisée pour sélectionner quelle interface réseau sera utilisée. Si vous avez spécifié un Device, cette variable est presque toujours déjà correctement définie.
KeyExpire = secondes (3600)
Cette option contrôle la période pendant laquelle les clés de chiffrement utilisées pour chiffrer les données sont valides. Il est courant de changer les clés à intervalles réguliers pour rendre la tâche encore plus difficile aux pirates, même s'il est considéré comme presque impossible de casser une seule clé.
LocalDiscovery = yes | no (no) [expérimental]
Lorsqu'elle est activée, tinc essaiera de détecter les pairs qui se trouvent sur le même réseau local. Cela permettra une communication directe en utilisant les adresses LAN, même si les deux pairs sont derrière un NAT et qu'ils ne se connectent qu'à un troisième nœud extérieur au NAT, ce qui normalement empêcherait les pairs d'apprendre l'adresse LAN de l'autre.

Actuellement, la découverte locale est implémentée en envoyant des paquets de diffusion au LAN lors de la découverte du MTU du chemin. Cette fonctionnalité peut ne pas fonctionner dans toutes les situations possibles.

MACExpire = secondes (600)
Cette option contrôle la durée pendant laquelle les adresses MAC sont conservées avant d'être supprimées. Cela n'a d'effet que lorsque Mode est défini sur « switch ».
MaxTimeout = secondes (900)
C'est le délai maximum avant d'essayer de se reconnecter à d'autres démons tinc.
Mode = router | switch | hub (router)
Cette option sélectionne la manière dont les paquets sont routés vers d'autres démons.
router
Dans ce mode, les variables Subnet des fichiers de configuration hôte seront utilisées pour former une table de routage. Seuls les paquets unicast de protocoles routables (IPv4 et IPv6) sont pris en charge dans ce mode.

C'est le mode par défaut, et sauf si vous savez vraiment que vous avez besoin d'un autre mode, ne le modifiez pas.

switch
Dans ce mode, les adresses MAC des paquets sur le VPN seront utilisées pour créer dynamiquement une table de routage, tout comme le fait un commutateur Ethernet. Les paquets unicast, multicast et broadcast de tous les protocoles qui s'exécutent sur Ethernet sont pris en charge dans ce mode, au prix de requêtes ARP broadcast fréquentes et de mises à jour de table de routage.

Ce mode est principalement utile si vous souhaitez interconnecter des segments Ethernet.

hub
Ce mode est presque identique au mode switch, mais au lieu de cela, chaque paquet sera diffusé aux autres démons sans qu'aucune table de routage ne soit gérée.
Name = nom [requis]
C'est le nom qui identifie ce démon tinc. Il doit être unique pour le réseau privé virtuel auquel ce démon se connectera. Le nom ne peut contenir que des caractères alphanumériques et des traits de soulignement. Si Name commence par un $, alors les contenus de la variable d'environnement qui suit seront utilisés. Dans ce cas, les caractères invalides seront convertis en tirets bas. Si Name est $HOST, mais qu'aucune variable d'environnement de ce nom n'existe, le nom d'hôte sera lu en utilisant l'appel système gethostname().
PingInterval = secondes (60)
Le nombre de secondes d'inactivité pendant lesquelles tinc attendra avant d'envoyer une sonde à l'autre extrémité.
PingTimeout = secondes (5)
Le nombre de secondes à attendre pour une réponse aux pings ou pour permettre aux connexions méta de bloquer. Si l'autre extrémité ne répond pas dans ce délai, la connexion est terminée et les autres seront notifiés de ce fait.
PriorityInheritance = yes | no (no) [expérimental]
Lorsque cette option est activée, la valeur du champ TOS des paquets IPv4 tunnelisés sera héritée par les paquets UDP qui sont envoyés.
PrivateKey = clé [obsolète]
La clé privée RSA de ce démon tinc. Elle permettra à ce démon tinc de s'authentifier auprès d'autres démons.
PrivateKeyFile = nom_de_fichier (/etc/tinc/NOMDURESEAU/rsa_key.priv)
Le fichier dans lequel réside la clé privée RSA de ce démon tinc.
ProcessPriority = low | normal | high
Lorsque cette option est utilisée, la priorité du processus tincd sera ajustée. Augmenter la priorité peut aider à réduire la latence et la perte de paquets sur le VPN.
Proxy = socks4 | socks5 | http | exec ... [expérimental]
Utilise un proxy lors des connexions sortantes. Les types de proxy suivants sont actuellement pris en charge :
socks4 adresse port [nom_utilisateur]
Se connecte au proxy en utilisant le protocole SOCKS version 4. Optionnellement, un nom_utilisateur peut être fourni et sera transmis au serveur proxy. Seules les connexions IPv4 peuvent être proxyfiées en utilisant SOCKS 4.
socks5 adresse port [nom_utilisateur mot_de_passe]
Se connecte au proxy en utilisant le protocole SOCKS version 5. Si un nom_utilisateur et un mot_de_passe sont donnés, une authentification basique par nom d'utilisateur/mot de passe sera utilisée, sinon aucune authentification ne sera utilisée.
http adresse port
Se connecte au proxy et envoie une requête HTTP CONNECT.
exec commande
Exécute la commande donnée qui doit établir la connexion sortante. Les variables d'environnement NAME, NODE, REMOTEADDRES et REMOTEPORT sont disponibles.
ReplayWindow = octets (16)
C'est la taille de la fenêtre de suivi de rejeu pour chaque nœud distant, en octets. La fenêtre est un champ de bits qui suit 1 paquet par bit, donc par exemple, le réglage par défaut de 16 suivra jusqu'à 128 paquets dans la fenêtre. Dans les scénarios à large bande passante, régler ceci à une valeur plus élevée peut réduire la perte de paquets due à l'interaction du suivi de rejeu avec la perte de paquets sous-jacente et/ou le réordonnancement. Régler ceci à zéro désactivera complètement le suivi de rejeu et laissera passer tout le trafic, mais laissera tinc vulnérable aux attaques par rejeu sur votre trafic.
StrictSubnets = yes | no (no) [expérimental]
Lorsque cette option est activée, tinc n'utilisera que les instructions Subnet qui sont présentes dans les fichiers de configuration d'hôtes du répertoire local /etc/tinc/NOMDURESEAU/hosts/. Les sous-réseaux appris via les connexions à d'autres nœuds et qui ne sont pas présents dans les fichiers de configuration d'hôtes locaux sont ignorés.
TunnelServer = yes | no (no) [expérimental]
Lorsque cette option est activée, tinc ne transférera plus d'informations entre d'autres démons tinc, et n'autorisera que les connexions avec les nœuds pour lesquels des fichiers de configuration d'hôtes sont présents dans le répertoire local /etc/tinc/NOMDURESEAU/hosts/. La définition de cette option définit également implicitement StrictSubnets.
UDPRcvBuf = octets (défaut OS)
Définit la taille du tampon de réception du socket pour le socket UDP, en octets. Si non défini, la taille de tampon par défaut sera utilisée par le système d'exploitation.
UDPSndBuf = octets (défaut OS)
Définit la taille du tampon d'envoi du socket pour le socket UDP, en octets. Si non défini, la taille de tampon par défaut sera utilisée par le système d'exploitation.

FICHIERS DE CONFIGURATION DES HÔTES

Les fichiers de configuration des hôtes contiennent toutes les informations nécessaires pour établir une connexion avec ces hôtes. Un fichier de configuration d'hôte est également requis pour le démon tinc local, il l'utilisera pour lire son port d'écoute, sa clé publique et ses sous-réseaux.

L'idée est que ces fichiers soient portables. Vous pouvez envoyer en toute sécurité votre propre fichier de configuration d'hôte à quelqu'un d'autre. Cette personne peut alors le copier dans son propre répertoire d'hôtes, et son démon tinc sera alors capable de se connecter à votre démon tinc. Étant donné que les fichiers de configuration d'hôtes ne contiennent que des clés publiques, aucun secret n'est révélé en envoyant ces informations.

Address = adresse [port] [recommandé]
L'adresse IP ou le nom d'hôte de ce démon tinc sur le réseau réel. Ceci ne sera utilisé que lors de la tentative d'établissement d'une connexion sortante vers ce démon tinc. Optionnellement, un port peut être spécifié pour être utilisé avec cette adresse. Plusieurs variables Address peuvent être spécifiées, auquel cas chaque adresse sera essayée jusqu'à ce qu'une connexion fonctionnelle ait été établie.
Cipher = chiffrement (aes-256-cbc)
L'algorithme de chiffrement symétrique utilisé pour chiffrer les paquets UDP. Tout chiffrement pris en charge par LibreSSL ou OpenSSL est reconnu. De plus, spécifier "none" désactivera le chiffrement des paquets. Il est préférable d'utiliser uniquement les chiffrements qui prennent en charge le mode CBC.
ClampMSS = yes | no (yes)
Cette option spécifie si tinc doit limiter la taille maximale du segment (MSS) des paquets TCP à la MTU du chemin. Ceci aide dans les situations où les messages ICMP Fragmentation Needed ou Packet too Big sont abandonnés par les pare-feux.
Compression = niveau (0)
Cette option définit le niveau de compression utilisé pour les paquets UDP. Les valeurs possibles sont 0 (désactivé), 1 (zlib rapide) et tout entier jusqu'à 9 (meilleur zlib), 10 (lzo rapide) et 11 (meilleur lzo).
Digest = hachage (sha256)
L'algorithme de hachage utilisé pour authentifier les paquets UDP. Tout hachage pris en charge par LibreSSL ou OpenSSL est reconnu. De plus, spécifier "none" désactivera l'authentification des paquets.
IndirectData = yes | no (no)
Lorsque défini sur yes, seuls les nœuds qui ont déjà une connexion méta avec vous tenteront d'établir une communication directe avec vous. Il est préférable de laisser cette option de côté ou de la régler sur no.
MACLength = longueur (4)
La longueur du code d'authentification de message utilisé pour authentifier les paquets UDP. Peut être n'importe quoi de "0" jusqu'à la longueur du hachage produit par l'algorithme de hachage.
PMTU = mtu (1514)
Cette option contrôle la MTU du chemin initiale vers ce nœud.
PMTUDiscovery = yes | no (yes)
Lorsque cette option est activée, tinc essaiera de découvrir la MTU du chemin vers ce nœud. Une fois la MTU du chemin découverte, elle sera appliquée sur le VPN.
Port = port (655)
Le numéro de port sur lequel ce démon tinc écoute les connexions entrantes, qui est utilisé si aucun numéro de port n'est spécifié dans une instruction Address.
PublicKey = clé [obsolète]
La clé publique RSA de ce démon tinc. Elle sera utilisée pour vérifier cryptographiquement son identité et pour établir une connexion sécurisée.
PublicKeyFile = nom_de_fichier [obsolète]
Le fichier dans lequel réside la clé publique RSA de ce démon tinc.

À partir de la version 1.0pre4, tinc stockera la clé publique directement dans le fichier de configuration d'hôte au format PEM, les deux options ci-dessus ne sont alors pas nécessaires. Soit le format PEM est utilisé, soit exactement une des deux options ci-dessus doit être spécifiée dans chaque fichier de configuration d'hôte, si vous voulez pouvoir établir

NAME

tincd.conf - configuration file for tinc

DESCRIPTION

This file contains the configuration for the tinc daemon. It is read when tinc is started. The configuration file is usually named tinc.conf and is located in /etc/tinc/NETNAME/, where NETNAME is the name of the tinc network. Several *.conf files can also be included from the conf.d directory.

The configuration file consists of keywords, followed by arguments. Keywords and arguments are separated by whitespace. Comments start with # and continue to the end of the line.

NETWORKS

If you want to run multiple tinc daemons on the same machine, you need to specify the network name. If you do not specify a name, tinc will assume the name is tinc.

netname = name
Sets the network name to name. If this option is present, tinc will also look for configuration files and scripts in /etc/tinc/name/ instead of /etc/tinc/tinc/.

NAMES

Each tinc daemon needs a unique name within its network. This name is used in the host configuration files. If no name is specified, the hostname is used.

name = name
Sets the name of this tinc daemon to name. This name is used in the host configuration files to identify this daemon.

PUBLIC/PRIVATE KEYS

Each tinc daemon needs a private key. This private key is used to authenticate the daemon. The corresponding public key is distributed to all other nodes in the network.

device = filename
Specifies the filename of the private key. The default is /etc/tinc/netname/rsa/netkey.

SERVER CONFIGURATION

mode = daemon | switch
Set the mode of operation. daemon is the default. switch is a mode for testing.
listenport = port
Specifies the port on which tinc should listen for incoming connections. If this option is not specified, tinc will not listen for connections.
listenaddress = address
Specifies the address on which tinc should listen for incoming connections. If this option is not specified, tinc will listen on all available addresses.
processpriority = priority
Sets the priority of the tinc daemon process. priority is a number between 0 and 100. Higher numbers mean higher priority. Default is 0.
సాయntpriority = priority
Sets the priority of the tinc networking stack. priority is a number between 0 and 100. Higher numbers mean higher priority. Default is 0.
dumpopenedports = yes | no
If set to yes, tinc will dump a list of all opened ports to /var/run/tinc.ports. This is useful for debugging.
pinginterval = seconds
Sets the interval for sending ping messages to check if the other side is still alive. Default is 60 seconds.
maxconntimeout = seconds
The maximum time to wait for a connection to be established. Default is 10 seconds.
indirectdata = yes | no
If set to yes, tinc will send data to other daemons via an indirect connection if possible. This is useful for running tinc behind a firewall. Default is no.
tunnelallways = yes | no
If set to yes, tinc will always try to establish a direct connection. Default is no.
connectto = host
Specifies a host to connect to. This is useful if you want to start tinc without having a listening port.

HOST CONFIGURATION FILES

Each host in the network is described in a separate file in the /etc/tinc/NETNAME/hosts/ directory. These files contain information about the host, such as its IP address and public key.

Subnet = address[/prefixlength[#weight]]
The subnet which this tinc daemon will serve. tinc tries to look up which other daemon it should send a packet to by searching the appropriate subnet. If the packet matches a subnet, it will be sent to the daemon who has this subnet in his host configuration file. Multiple Subnet variables can be specified.

Subnets can either be single MAC, IPv4 or IPv6 addresses, in which case a subnet consisting of only that single address is assumed, or they can be a IPv4 or IPv6 network address with a prefixlength. For example, IPv4 subnets must be in a form like 192.168.1.0/24, where 192.168.1.0 is the network address and 24 is the number of bits set in the netmask. Note that subnets like 192.168.1.1/24 are invalid! Read a networking HOWTO/FAQ/guide if you don't understand this. IPv6 subnets are notated like fec0:0:0:1::/64. MAC addresses are notated like 0:1a:2b:3c:4d:5e.

A Subnet can be given a weight to indicate its priority over identical Subnets owned by different nodes. The default weight is 10. Lower values indicate higher priority. Packets will be sent to the node with the highest priority, unless that node is not reachable, in which case the node with the next highest priority will be tried, and so on.

TCPOnly = yes | no (no [obsolete])
If this variable is set to yes, then the packets are tunnelled over the TCP connection instead of a UDP connection. This is especially useful for those who want to run a tinc daemon from behind a masquerading firewall, or if UDP packet routing is disabled somehow. Setting this options also implicitly sets IndirectData.

Since version 1.0.10, tinc will automatically detect whether communication via UDP is possible or not.

SCRIPTS

Apart from reading the server and host configuration files, tinc can also run scripts at certain moments. Below is a list of filenames of scripts and a description of when they are run. A script is only run if it exists and if it is executable.

Scripts are run synchronously; this means that tinc will temporarily stop processing packets until the called script finishes executing. This guarantees that scripts will execute in the exact same order as the events that trigger them. If you need to run commands asynchronously, you have to ensure yourself that they are being run in the background.

Under Windows (not Cygwin), the scripts must have the extension .bat.

/etc/tinc/NETNAME/tinc-up
This is the most important script. If it is present it will be executed right after the tinc daemon has been started and has connected to the virtual network device. It should be used to set up the corresponding network interface, but can also be used to start other things.

Under Windows you can use the Network Connections control panel instead of creating this script.

/etc/tinc/NETNAME/tinc-down
This script is started right before the tinc daemon quits.
/etc/tinc/NETNAME/hosts/HOST-up
This script is started when the tinc daemon with name HOST becomes reachable.
/etc/tinc/NETNAME/hosts/HOST-down
This script is started when the tinc daemon with name HOST becomes unreachable.
/etc/tinc/NETNAME/host-up
This script is started when any host becomes reachable.
/etc/tinc/NETNAME/host-down
This script is started when any host becomes unreachable.
/etc/tinc/NETNAME/subnet-up
This script is started when a Subnet becomes reachable. The Subnet and the node it belongs to are passed in environment variables.
/etc/tinc/NETNAME/subnet-down
This script is started when a Subnet becomes unreachable.

The scripts are started without command line arguments, but can make use of certain environment variables. Under UNIX like operating systems the names of environment variables must be preceded by a $ in scripts. Under Windows, in .bat files, they have to be put between % signs.

NETNAME
If a netname was specified, this environment variable contains it.
NAME
Contains the name of this tinc daemon.
DEVICE
Contains the name of the virtual network device that tinc uses.
INTERFACE
Contains the name of the virtual network interface that tinc uses. This should be used for commands like ifconfig.
NODE
When a host becomes (un)reachable, this is set to its name. If a subnet becomes (un)reachable, this is set to the owner of that subnet.
REMOTEADDRESS
When a host becomes (un)reachable, this is set to its real address.
REMOTEPORT
When a host becomes (un)reachable, this is set to the port number it uses for communication with other tinc daemons.
SUBNET
When a subnet becomes (un)reachable, this is set to the subnet.
WEIGHT
When a subnet becomes (un)reachable, this is set to the subnet weight.

Do not forget that under UNIX operating systems, you have to make the scripts executable, using the command chmod a+x script.
