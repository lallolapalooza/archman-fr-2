TIMES(3P) Manuel du programmeur POSIX TIMES(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

times — obtenir les temps d'exécution du processus et des processus fils attendus

SYNTAXE

#include <sys/times.h>
clock_t times(struct tms *buffer);

DESCRIPTION

La fonction times() remplit la structure tms pointée par buffer avec des informations de comptabilisation du temps. La structure tms est définie dans <sys/times.h>.

Tous les temps sont mesurés en termes du nombre de tics d'horloge utilisés.

Les temps d'un processus fils terminé seront inclus dans les éléments tms_cutime et tms_cstime du parent lorsque wait(), waitid(), ou waitpid() renverra l'identifiant de ce processus fils terminé. Si un processus fils n'a pas attendu ses fils, leurs temps ne seront pas inclus dans ses temps.

*
Le membre de la structure tms_utime est le temps CPU facturé pour l'exécution des instructions utilisateur du processus appelant.
*
Le membre de la structure tms_stime est le temps CPU facturé pour l'exécution par le système au nom du processus appelant.
*
Le membre de la structure tms_cutime est la somme des temps tms_utime et tms_cutime des processus fils.
*
Le membre de la structure tms_cstime est la somme des temps tms_stime et tms_cstime des processus fils.

VALEUR DE RETOUR

En cas de succès, times() renvoie le temps réel écoulé, en tics d'horloge, depuis un point arbitraire dans le passé (par exemple, l'heure de démarrage du système). Ce point ne change pas d'une invocation de times() à une autre au sein du processus. La valeur de retour peut déborder de la plage possible du type clock_t. Si times() échoue, (clock_t)-1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

La fonction times() échouera si :

EOVERFLOW
La valeur de retour dépasserait la plage de clock_t.

EXEMPLES

Temps d'une recherche dans une base de données

L'exemple suivant définit deux fonctions, start_clock() et end_clock(), qui sont utilisées pour chronométrer une recherche. Il définit également des variables de type clock_t et tms pour mesurer la durée des transactions. La fonction start_clock() enregistre les temps de début donnés par la fonction times(). La fonction end_clock() récupère les temps de fin et imprime la différence entre les deux temps.

#include <sys/times.h>
#include <stdio.h>
...
void start_clock(void);
void end_clock(char *msg);
...
static clock_t st_time;
static clock_t en_time;
static struct tms st_cpu;
static struct tms en_cpu;
...
void
start_clock()
{
    st_time = times(&st_cpu);
}
/* Cet exemple suppose que le résultat de chaque soustraction
   est dans la plage des valeurs qui peuvent être représentées dans
   un type entier. */
void
end_clock(char *msg)
{
    en_time = times(&en_cpu);
    fputs(msg,stdout);
    printf("Temps réel: %jd, Temps utilisateur %jd, Temps système %jd\n",
        (intmax_t)(en_time - st_time),
        (intmax_t)(en_cpu.tms_utime - st_cpu.tms_utime),
        (intmax_t)(en_cpu.tms_stime - st_cpu.tms_stime));
}

UTILISATION PAR APPLICATION

Les applications doivent utiliser sysconf(_SC_CLK_TCK) pour déterminer le nombre de tics d'horloge par seconde, car cela peut varier d'un système à l'autre.

RATIONALE

La précision des temps rapportés est intentionnellement laissée non spécifiée pour permettre aux implémentations une flexibilité de conception, des systèmes monoprocesseurs aux réseaux multiprocesseurs.

L'inclusion des temps des processus fils est récursive, de sorte qu'un processus parent puisse collecter les temps totaux de tous ses descendants. Mais les temps d'un fils ne sont ajoutés à ceux de son parent que lorsque son parent attend avec succès sur le fils. Ainsi, il n'est pas garanti qu'un processus parent puisse toujours voir les temps totaux de tous ses descendants; voir également la discussion du terme "temps réel" dans alarm().

Si le type clock_t est défini comme un entier signé de 32 bits, il déborde après un peu plus d'un an si le nombre de tics d'horloge par seconde est de 60, ou moins d'un an s'il est de 100. Il existe des systèmes individuels qui fonctionnent continuellement pendant plus longtemps. Ce volume de POSIX.1-2017 autorise une implémentation à faire du point de référence pour la valeur renvoyée le temps de démarrage du processus, plutôt que le temps de démarrage du système.

Le terme "facturé" dans ce contexte n'a rien à voir avec la facturation des services. Le système d'exploitation comptabilise le temps utilisé de cette manière. Ces informations doivent être correctes, quelle que soit la manière dont elles sont utilisées.

PROLOG

NOM

times — temps d'exécution des processus

SYNOPSIS

#include <sys/times.h>
clock_t times(clock_t *buffer);

DESCRIPTION

La fonction times() remplit la structure pointée par buffer avec des informations sur les temps d'exécution écoulés du processus appelant.

La structure tms est définie dans <sys/times.h> comme suit :

struct tms {
    clock_t tms_utime;  /* temps d'horloge en mode utilisateur */
    clock_t tms_stime;  /* temps d'horloge en mode noyau */
    clock_t tms_cutime; /* temps d'horloge des enfants en mode utilisateur */
    clock_t tms_cstime; /* temps d'horloge des enfants en mode noyau */
};

Les membres tms_utime et tms_stime indiquent le temps total passé par le processus appelant en mode utilisateur et en mode noyau, respectivement. Ces temps incluent le temps passé par les enfants du processus appelant qui ont terminé leur exécution et dont les temps ont été récupérés par leurs parents (par exemple, via wait()). Le temps est mesuré en unités de temps d'horloge, comme retourné par sysconf(_SC_CLK_TCK).

Les membres tms_cutime et tms_cstime indiquent le temps total passé par les enfants du processus appelant en mode utilisateur et en mode noyau, respectivement. Ces temps n'incluent que les enfants qui ont terminé leur exécution et dont les temps ont été récupérés par leurs parents. Les enfants qui n'ont pas encore terminé leur exécution ou dont les temps n'ont pas été récupérés ne sont pas inclus dans ces totaux.

L'heure de référence pour ces mesures est indéterminée, mais elle est cohérente au sein d'une exécution du programme. La valeur retournée par times() est le temps d'horloge écoulé depuis un point de référence indéterminé (qui peut être différent de celui utilisé pour les membres de la structure) au moment de l'appel à times(). Cette valeur retournée peut être utilisée pour calculer les intervalles de temps.

VALEUR DE RETOUR

En cas de succès, times() retourne le temps d'horloge écoulé du processus appelant depuis un point de référence indéterminé. En cas d'erreur, (clock_t) -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
Le pointeur buffer pointe vers une zone mémoire non valide.

EXEMPLES

```c #include <stdio.h> #include <sys/times.h> #include <unistd.h> #include <time.h> int main() { struct tms tms_start, tms_end; clock_t tms_start_wall, tms_end_wall; long clk_tck = sysconf(_SC_CLK_TCK); // Enregistrer le temps de départ et l'heure murale tms_end_wall = times(&tms_start); if (tms_end_wall == (clock_t) -1) { perror("times"); return 1; } // Simuler une tâche longue printf("Exécution d'une tâche..."); fflush(stdout); sleep(2); // Attend 2 secondes printf("Terminé.\n"); // Enregistrer le temps de fin et l'heure murale tms_end_wall = times(&tms_end); if (tms_end_wall == (clock_t) -1) { perror("times"); return 1; } // Calculer et afficher les temps d'exécution printf("Temps CPU utilisateur : %.2f secondes\n", (double)(tms_end.tms_utime - tms_start.tms_utime) / clk_tck); printf("Temps CPU noyau : %.2f secondes\n", (double)(tms_end.tms_stime - tms_start.tms_stime) / clk_tck); printf("Temps CPU enfants utilisateur : %.2f secondes\n", (double)(tms_end.tms_cutime - tms_start.tms_cutime) / clk_tck); printf("Temps CPU enfants noyau : %.2f secondes\n", (double)(tms_end.tms_cstime - tms_start.tms_cstime) / clk_tck); printf("Temps réel écoulé : %.2f secondes\n", (double)(tms_end_wall - tms_start_wall) / clk_tck); return 0; } ```

USAGE APPLICATIF

La fonction times() est principalement utilisée pour mesurer la consommation de ressources d'un processus ou d'une partie d'un programme. Elle permet de distinguer le temps passé en mode utilisateur (exécution du code de l'application) du temps passé en mode noyau (exécution des appels système). Elle est également utile pour suivre la consommation de temps CPU par les processus fils.

JUSTIFICATION

La fonction times() fait partie de la norme POSIX et est largement prise en charge sur les systèmes Unix-like. Elle fournit un moyen portable de mesurer les temps d'exécution, ce qui est essentiel pour l'optimisation des performances et le débogage.

ORIENTATIONS FUTURES

Bien que times() soit une fonction établie, des interfaces plus modernes comme clock_gettime() (avec CLOCK_PROCESS_CPUTIME_ID et CLOCK_THREAD_CPUTIME_ID) offrent une granularité et une précision potentiellement plus élevées, ainsi que la possibilité de mesurer des temps d'horloge spécifiques (par exemple, temps réel, temps CPU de thread). Cependant, times() reste une option fiable pour des mesures générales des temps d'exécution des processus.
