NOM

tinysparql-endpoint - Créer un point d'accès SPARQL

SYNTAXE

tinysparql endpoint [--dbus-service | -b] <nom_service>
                  [--database-path | -d] <chemin_base_de_donnees>
                  [[--ontology | -o] <nom_ontologie> |
                   [--ontology-path | -p] <chemin_ontologie>]
                  [--http-port] <port>
                  [--loopback]
                  [[--system | --session]]

DESCRIPTION

Cette commande permet de créer des points d'accès SPARQL. Le point d'accès sera capable de gérer les requêtes SPARQL select et update, et de notifier des changements.

Le point d'accès est exporté via DBus, accessible via le nom_service donné, soit en l'utilisant dans une clause SERVICE, soit en créant une connexion SPARQL dédiée basée sur le bus.

Lors de la création d'une base de données, le nom_ontologie (ou alternativement, un chemin_ontologie) doit être fourni afin de générer la base de données. Si nom_ontologie est utilisé, l'ontologie doit exister dans $datadir/tracker/ontologies

Les utilisateurs doivent être prudents avec l'option --http-port, envisagez de ne l'utiliser qu'en combinaison avec l'option --loopback.

La base de données elle-même sera stockée selon chemin_base_de_donnees.

OPTIONS

-b, --dbus-service=<nom_service>

Nom du service à utiliser sur le point d'accès.

-d, --database-path=<chemin_base_de_donnees>

Le chemin où la base de données sera stockée.

-o, --ontology

Le nom d'une ontologie dans $datadir/tracker/ontologies à utiliser sur la base de données construite.

-p, --ontology-path

Chemin complet vers une ontologie à utiliser sur la base de données construite.

--session

Utiliser le bus de session. C'est le comportement par défaut.

--system

Utiliser le bus système.

-l, --list

Lister tous les points d'accès SPARQL disponibles sur DBus

-L, --list-http

Lister les points d'accès SPARQL HTTP locaux sur le réseau

--http-port

Crée un point d'accès HTTP qui écoute sur le port spécifié

--loopback

Autorise uniquement les connexions HTTP sur le périphérique de boucle locale. Ne prend effet qu'avec les points d'accès HTTP.

EXEMPLES

Exporter un point d'accès Nepomuk avec le nom de bus org.example.Example1.

$ tinysparql endpoint -b org.example.Example1 -o nepomuk -d /tmp/example1

Accéder à ce point d'accès avec la sous-commande tinysparql-sparql(1).

$ tinysparql sparql --dbus-service org.example.Example1 -q "
  SELECT ?s ?o
  WHERE {
    ?u a ?o
  }"

Exporter un point d'accès Nepomuk via HTTP.

$ tinysparql endpoint --http-port 8080 -o nepomuk --loopback

Accéder à ce point d'accès via HTTP.

$ tinysparql sparql --remote-service http://127.0.0.1:8080/sparql -q "
  SELECT ?u {
    ?u a rdfs:Resource
  }"
