timerfd_create(2) Manuel des appels système timerfd_create(2)

NOM

timerfd_create, timerfd_settime, timerfd_gettime - minuteurs qui notifient via des descripteurs de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/timerfd.h>
int timerfd_create(int clockid, int flags);
int timerfd_settime(int fd, int flags,
                    const struct itimerspec *new_value,
                    struct itimerspec *_Nullable old_value);
int timerfd_gettime(int fd, struct itimerspec *curr_value);

DESCRIPTION

Ces appels système créent et opèrent sur un minuteur qui délivre des notifications d'expiration de minuteur via un descripteur de fichier. Ils fournissent une alternative à l'utilisation de setitimer(2) ou timer_create(2), avec l'avantage que le descripteur de fichier peut être surveillé par select(2), poll(2), et epoll(7).

L'utilisation de ces trois appels système est analogue à l'utilisation de timer_create(2), timer_settime(2), et timer_gettime(2). (Il n'y a pas d'analogue de timer_getoverrun(2), puisque cette fonctionnalité est fournie par read(2), comme décrit ci-dessous.)

timerfd_create()

timerfd_create() crée un nouvel objet minuteur, et retourne un descripteur de fichier qui fait référence à ce minuteur. L'argument clockid spécifie l'horloge utilisée pour marquer la progression du minuteur, et doit être l'une des suivantes :

CLOCK_REALTIME
Une horloge temps réel système réglable.
CLOCK_MONOTONIC
Une horloge non réglable qui augmente de manière monotone et mesure le temps depuis un point indéterminé dans le passé qui ne change pas après le démarrage du système.
CLOCK_BOOTTIME (Depuis Linux 3.15)
Comme CLOCK_MONOTONIC, c'est une horloge qui augmente de manière monotone. Cependant, tandis que l'horloge CLOCK_MONOTONIC ne mesure pas le temps pendant lequel un système est suspendu, l'horloge CLOCK_BOOTTIME inclut le temps pendant lequel le système est suspendu. Ceci est utile pour les applications qui doivent être conscientes des suspensions. CLOCK_REALTIME ne convient pas à de telles applications, car cette horloge est affectée par des changements discontinus de l'horloge système.
CLOCK_REALTIME_ALARM (Depuis Linux 3.11)
Cette horloge est comme CLOCK_REALTIME, mais réveillera le système s'il est suspendu. L'appelant doit avoir la capacité CAP_WAKE_ALARM pour régler un minuteur contre cette horloge.
CLOCK_BOOTTIME_ALARM (Depuis Linux 3.11)
Cette horloge est comme CLOCK_BOOTTIME, mais réveillera le système s'il est suspendu. L'appelant doit avoir la capacité CAP_WAKE_ALARM pour régler un minuteur contre cette horloge.

Voir clock_getres(2) pour quelques détails supplémentaires sur les horloges ci-dessus.

La valeur actuelle de chacune de ces horloges peut être récupérée en utilisant clock_gettime(2).

À partir de Linux 2.6.27, les valeurs suivantes peuvent être combinées par OR bitwise dans flags pour modifier le comportement de timerfd_create():

TFD_NONBLOCK
Définir le drapeau d'état de fichier O_NONBLOCK sur la description de fichier ouverte (voir open(2)) référencée par le nouveau descripteur de fichier. Utiliser ce drapeau évite des appels supplémentaires à fcntl(2) pour obtenir le même résultat.
TFD_CLOEXEC
Définir le drapeau close-on-exec (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description du drapeau O_CLOEXEC dans open(2) pour les raisons pour lesquelles cela peut être utile.

Dans les versions de Linux jusqu'à et incluant 2.6.26, flags doit être spécifié comme zéro.

timerfd_settime()

timerfd_settime() arme (démarre) ou désarme (arrête) le minuteur référencé par le descripteur de fichier fd.

L'argument new_value spécifie l'expiration initiale et l'intervalle pour le minuteur. La structure itimerspec utilisée pour cet argument est décrite dans itimerspec(3type).

new_value.it_value spécifie l'expiration initiale du minuteur, en secondes et nanosecondes. Définir l'un ou l'autre champ de new_value.it_value à une valeur non nulle arme le minuteur. Définir les deux champs de new_value.it_value à zéro désarme le minuteur.

Définir un ou deux champs de new_value.it_interval à des valeurs non nulles spécifie la période, en secondes et nanosecondes, pour les expirations répétées du minuteur après l'expiration initiale. Si les deux champs de new_value.it_interval sont zéro, le minuteur expire une seule fois, au moment spécifié par new_value.it_value.

Par défaut, l'heure d'expiration initiale spécifiée dans new_value est interprétée par rapport à l'heure actuelle de l'horloge du minuteur au moment de l'appel (c'est-à-dire que new_value.it_value spécifie une heure relative à la valeur actuelle de l'horloge spécifiée par clockid). Un délai absolu peut être sélectionné via l'argument flags.

L'argument flags est un masque de bits qui peut inclure les valeurs suivantes :

TFD_TIMER_ABSTIME
Interpréter new_value.it_value comme une valeur absolue sur l'horloge du minuteur. Le minuteur expirera lorsque la valeur de l'horloge du minuteur atteindra la valeur spécifiée dans new_value.it_value.
TFD_TIMER_CANCEL_ON_SET
Si ce drapeau est spécifié avec TFD_TIMER_ABSTIME et que l'horloge de ce minuteur est CLOCK_REALTIME ou CLOCK_REALTIME_ALARM, alors marquer ce minuteur comme annulable si l'horloge temps réel subit un changement discontinu (settimeofday(2), clock_settime(2), ou similaire). Lorsque de tels changements surviennent, une lecture (read(2)) actuelle ou future du descripteur de fichier échouera avec l'erreur ECANCELED.

Si l'argument old_value n'est pas NULL, alors la structure itimerspec à laquelle il pointe est utilisée pour retourner le réglage du minuteur qui était en cours au moment de l'appel ; voir la description de timerfd_gettime() ci-après.

timerfd_gettime()

timerfd_gettime() retourne, dans curr_value, une structure itimerspec qui contient le réglage actuel du minuteur référencé par le descripteur de fichier fd.

Le champ it_value retourne le temps restant avant la prochaine expiration du minuteur. Si les deux champs de cette structure sont zéro, alors le minuteur est actuellement désarmé. Ce champ contient toujours une valeur relative, indépendamment du fait que le drapeau TFD_TIMER_ABSTIME ait été spécifié lors du réglage du minuteur.

Le champ it_interval retourne l'intervalle du minuteur. Si les deux champs de cette structure sont zéro, alors le minuteur est réglé pour expirer une seule fois, au moment spécifié par curr_value.it_value.

Opération sur un descripteur de fichier de minuteur

Le descripteur de fichier retourné par timerfd_create() prend en charge les opérations supplémentaires suivantes :

read(2)
Si le minuteur a déjà expiré une ou plusieurs fois depuis que ses réglages ont été modifiés pour la dernière fois

édité à l'aide de timerfd_settime(), ou depuis la dernière lecture(read(2)) réussie, le tampon fourni à read(2) retourne un entier non signé de 8 octets (uint64_t) contenant le nombre d'expirations qui se sont produites. (La valeur retournée est dans l'ordre des octets de l'hôte, c'est-à-dire l'ordre natif des octets pour les entiers sur la machine hôte.)
Si aucune expiration de minuteur ne s'est produite au moment de la lecture (read(2)), l'appel se bloque jusqu'à la prochaine expiration du minuteur, ou échoue avec l'erreur EAGAIN si le descripteur de fichier a été rendu non bloquant (via l'utilisation de l'opération fcntl(2) F_SETFL pour définir le drapeau O_NONBLOCK).
Une lecture (read(2)) échoue avec l'erreur EINVAL si la taille du tampon fourni est inférieure à 8 octets.
Si l'horloge associée est CLOCK_REALTIME ou CLOCK_REALTIME_ALARM, que le minuteur est absolu (TFD_TIMER_ABSTIME), et que le drapeau TFD_TIMER_CANCEL_ON_SET a été spécifié lors de l'appel à timerfd_settime(), alors la lecture (read(2)) échoue avec l'erreur ECANCELED si l'horloge temps réel subit un changement discontinu. (Cela permet à l'application de lecture de détecter de tels changements discontinus de l'horloge.)
Si l'horloge associée est CLOCK_REALTIME ou CLOCK_REALTIME_ALARM, que le minuteur est absolu (TFD_TIMER_ABSTIME), et que le drapeau TFD_TIMER_CANCEL_ON_SET n'a *pas* été spécifié lors de l'appel à timerfd_settime(), alors un changement discontinu négatif de l'horloge (par exemple, clock_settime(2)) peut provoquer le déblocage de la lecture (read(2)), mais retourner une valeur de 0 (c'est-à-dire aucun octet lu), si le changement d'horloge survient après l'expiration du délai, mais avant la lecture (read(2)) sur le descripteur de fichier.
poll(2)
select(2)
(et similaire)
Le descripteur de fichier est lisible (l'argument readfds de select(2) ; le drapeau POLLIN de poll(2)) si une ou plusieurs expirations de minuteur se sont produites.
Le descripteur de fichier prend également en charge les autres API de multiplexage de descripteurs de fichiers : pselect(2), ppoll(2), et epoll(7).
ioctl(2)
La commande spécifique au minuteur suivante est prise en charge :
TFD_IOC_SET_TICKS (depuis Linux 3.17)
Ajuste le nombre d'expirations de minuteur qui se sont produites. L'argument est un pointeur vers un entier non nul de 8 octets (uint64_t*) contenant le nouveau nombre d'expirations. Une fois le nombre défini, tout attendant sur le minuteur est réveillé. Le seul but de cette commande est de restaurer les expirations à des fins de point de contrôle/restauration. Cette opération n'est disponible que si le noyau a été configuré avec l'option CONFIG_CHECKPOINT_RESTORE.
close(2)
Lorsque le descripteur de fichier n'est plus requis, il doit être fermé. Lorsque tous les descripteurs de fichiers associés au même objet minuteur ont été fermés, le minuteur est désarmé et ses ressources sont libérées par le noyau.

Sémantique de fork(2)

Après un fork(2), l'enfant hérite d'une copie du descripteur de fichier créé par timerfd_create(). Le descripteur de fichier fait référence au même objet minuteur sous-jacent que le descripteur de fichier correspondant dans le parent, et les lectures (read(2)) dans l'enfant retourneront des informations sur les expirations du minuteur.

Sémantique de execve(2)

Un descripteur de fichier créé par timerfd_create() est préservé lors d'un execve(2), et continue de générer des expirations de minuteur si le minuteur était armé.

VALEUR DE RETOUR

En cas de succès, timerfd_create() retourne un nouveau descripteur de fichier. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

timerfd_settime() et timerfd_gettime() retournent 0 en cas de succès ; en cas d'erreur, ils retournent -1 et définissent errno pour indiquer l'erreur.

ERREURS

timerfd_create() peut échouer avec les erreurs suivantes :

EINVAL
L'identifiant d'horloge (clockid) n'est pas valide.
EINVAL
Les flags sont invalides ; ou, sous Linux 2.6.26 ou antérieur, les flags sont non nuls.
EMFILE
La limite par processus sur le nombre de descripteurs de fichiers ouverts a été atteinte.
ENFILE
La limite globale du système sur le nombre total de fichiers ouverts a été atteinte.
ENODEV
Impossible de monter un périphérique d'inode anonyme (interne).
ENOMEM
Il n'y avait pas assez de mémoire noyau pour créer le minuteur.
EPERM
L'identifiant d'horloge (clockid) était CLOCK_REALTIME_ALARM ou CLOCK_BOOTTIME_ALARM mais l'appelant ne possédait pas la capacité CAP_WAKE_ALARM.

timerfd_settime() et timerfd_gettime() peuvent échouer avec les erreurs suivantes :

EBADF
fd n'est pas un descripteur de fichier valide.
EFAULT
new_value, old_value, ou curr_value n'est pas un pointeur valide.
EINVAL
fd n'est pas un descripteur de fichier timerfd valide.

timerfd_settime() peut également échouer avec les erreurs suivantes :

ECANCELED
Voir NOTES.
EINVAL
new_value n'est pas correctement initialisé (l'un des tv_nsec est en dehors de la plage zéro à 999 999 999).
EINVAL
Les flags sont invalides.

NORMES

Linux.

HISTORIQUE

Linux 2.6.25, glibc 2.8.

NOTES

Supposons le scénario suivant pour un minuteur CLOCK_REALTIME ou CLOCK_REALTIME_ALARM créé avec timerfd_create() :

(1)
Le minuteur a été démarré (timerfd_settime()) avec les drapeaux TFD_TIMER_ABSTIME et TFD_TIMER_CANCEL_ON_SET ;
(2)
Un changement discontinu (par exemple, settimeofday(2)) est ensuite apporté à l'horloge CLOCK_REALTIME ; et
(3)
l'appelant appelle à nouveau timerfd_settime() pour réarmer le minuteur (sans d'abord effectuer une lecture (read(2)) sur le descripteur de fichier).

Dans ce cas, il se produit ce qui suit :

•
Le timerfd_settime() retourne -1 avec errno défini à ECANCELED. (Cela permet à l'appelant de savoir que le minuteur précédent a été affecté par un changement discontinu de l'horloge.)
•
Le minuteur est *réarmé avec succès* avec les paramètres fournis dans le deuxième appel à timerfd_settime(). (C'était probablement un accident d'implémentation, mais ne sera pas corrigé maintenant, au cas où certaines applications dépendraient de ce comportement.)

BUGS

Actuellement, timerfd_create() prend en charge moins de types d'identifiants d'horloge que timer_create(2).

EXEMPLES

Le programme suivant crée un minuteur puis surveille sa progression. Le programme accepte jusqu'à trois arguments en ligne de commande. Le premier argument spécifie le nombre de secondes pour la première expiration du minuteur. Le deuxième argument spécifie l'intervalle du minuteur, en secondes. Le troisième argument spécifie le nombre de fois où le programme autorisera le minuteur à expirer avant de se terminer. Les deuxième et troisième arguments en ligne de commande sont facultatifs.

La session shell suivante démontre l'utilisation du programme :


$ a.out 3 1 100
0.000:	timer started
3.000:	read: 1; total=1
4.000:	read: 1; total=2
^Z                  # taper control-Z pour suspendre le programme
[1]+  Stopped                 ./timerfd3_demo 3 1 100
$ fg                # Reprendre l'exécution après quelques secondes
a.out 3 1 100
9.660:	read: 5; total=7
10.000:	read: 1; total=8
11.000:	read: 1; total=9
^C                  # taper control-C pour suspendre le programme

print_elapsed_time(void)
{
    int                     secs, nsecs;
    static int              first_call = 1;
    struct timespec         curr;
    static struct timespec  start;
    if (first_call) {
        first_call = 0;
        if (clock_gettime(CLOCK_MONOTONIC, &start) == -1)
            err(EXIT_FAILURE, "clock_gettime");
    }
    if (clock_gettime(CLOCK_MONOTONIC, &curr) == -1)
