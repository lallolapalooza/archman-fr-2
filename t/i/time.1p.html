TIME(1P) Manuel du programmeur POSIX TIME(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

time — chronométrer une commande simple

SYNTAXE

time [-p] utilitaire [argument...]

DESCRIPTION

L'utilitaire time invoquera l'utilitaire nommé par l'opérande utilitaire avec les arguments fournis en tant qu'opérandes argument et écrira un message sur la sortie d'erreur standard qui liste les statistiques de temps pour l'utilitaire. Le message inclura les informations suivantes :

*
Le temps écoulé (réel) entre l'invocation de utilitaire et sa terminaison.
*
Le temps CPU utilisateur, équivalent à la somme des champs tms_utime et tms_cutime renvoyés par la fonction times() définie dans le volume Interfaces système de POSIX.1‐2017 pour le processus dans lequel utilitaire est exécuté.
*
Le temps CPU système, équivalent à la somme des champs tms_stime et tms_cstime renvoyés par la fonction times() pour le processus dans lequel utilitaire est exécuté.

La précision du chronométrage ne sera pas inférieure à la granularité définie pour la taille de l'unité de tick d'horloge sur le système, mais les résultats seront rapportés en termes d'unités de temps standard (par exemple, 0.02 secondes, 00:00:00.02, 1m33.75s, 365.21 secondes), et non en nombre de ticks d'horloge.

Lorsque time est utilisé dans le cadre d'un pipeline, les temps rapportés ne sont pas spécifiés, sauf lorsqu'il s'agit de la seule commande dans une commande de groupement (voir Section 2.9.4.1, Commandes de groupement) dans ce pipeline. Par exemple, les commandes de gauche ne sont pas spécifiées ; celles de droite rapportent sur les utilitaires a et c, respectivement :

time a | b | c    { time a; } | b | c
a | b | time c    a | b | (time c)

OPTIONS

L'utilitaire time sera conforme aux directives de syntaxe des utilitaires du volume Définitions de base de POSIX.1‐2017, Section 12.2.

L'option suivante sera prise en charge :

-p
Écrit la sortie de chronométrage sur la sortie d'erreur standard dans le format indiqué dans la section STDERR.

OPÉRANDES

Les opérandes suivants seront pris en charge :

utilitaire
Le nom d'un utilitaire à invoquer. Si l'opérande utilitaire nomme l'un des utilitaires intégrés spéciaux de la Section 2.14, Utilitaires intégrés spéciaux, les résultats ne sont pas spécifiés.
argument
Toute chaîne à fournir en tant qu'argument lors de l'invocation de l'utilitaire nommé par l'opérande utilitaire.

ENTRÉE STANDARD

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de time :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères à un octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic et d'information écrits sur la sortie d'erreur standard.
LC_NUMERIC

Détermine la locale pour le formatage numérique.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
PATH
Détermine le chemin de recherche qui sera utilisé pour localiser l'utilitaire à invoquer ; voir le volume Définitions de base de POSIX.1‐2017, Chapitre 8, Variables d'environnement.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Non utilisé.

SORTIE D'ERREUR STANDARD

Si l'utilitaire utilitaire est invoqué, la sortie d'erreur standard sera utilisée pour écrire les statistiques de chronométrage et peut être utilisée pour écrire un message de diagnostic si l'utilitaire se termine anormalement ; sinon, la sortie d'erreur standard sera utilisée pour écrire des messages de diagnostic et peut également être utilisée pour écrire les statistiques de chronométrage.

Si -p est spécifié, le format suivant sera utilisé pour les statistiques de chronométrage dans la locale POSIX :

"real %f\nuser %f\nsys %f\n", <secondes réelles>, <secondes utilisateur>,
    <secondes système>

où chaque nombre à virgule flottante sera exprimé en secondes. La précision utilisée peut être inférieure aux six chiffres par défaut de %f, mais sera suffisamment précise pour accommoder la taille du tick d'horloge sur le système (par exemple, s'il y avait 60 ticks d'horloge par seconde, au moins deux chiffres suivraient le caractère radix). Le nombre de chiffres suivant le caractère radix ne sera pas inférieur à un, même si cela entraîne toujours un zéro final. L'implémentation peut ajouter des espaces blancs et des informations supplémentaires après le format indiqué ici. L'implémentation peut également précéder d'une seule ligne vide avant le format indiqué ici.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Si l'utilitaire utilitaire est invoqué, le statut de sortie de time sera le statut de sortie de utilitaire ; sinon, l'utilitaire time se terminera avec l'une des valeurs suivantes :

1‐125
Une erreur s'est produite dans l'utilitaire time.
  126
L'utilitaire spécifié par utilitaire a été trouvé mais n'a pas pu être invoqué.
  127
L'utilitaire spécifié par utilitaire n'a pas pu être trouvé.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Les utilitaires command, env, nice, nohup, time et xargs ont été spécifiés pour utiliser le code de sortie 127 en cas d'erreur afin que les applications puissent distinguer une « impossibilité de trouver un utilitaire » d'une « invocation d'utilitaire terminée avec une indication d'erreur ». La valeur 127 a été choisie car elle n'est pas couramment utilisée pour d'autres significations ; la plupart des utilitaires utilisent de petites valeurs pour les « erreurs normales.

time(1p) - Manuel en français

VALEUR DE SORTIE

Les valeurs supérieures à 128 sont destinées à indiquer des conditions d'erreur. Les valeurs supérieures à 128 peuvent être confondues avec la terminaison due à la réception d'un signal. La valeur 126 a été choisie de manière similaire pour indiquer que l'utilitaire pouvait être trouvé, mais pas invoqué. Certains scripts produisent des messages d'erreur significatifs différenciant les cas 126 et 127. La distinction entre les codes de sortie 126 et 127 est basée sur la pratique de KornShell qui utilise 127 lorsque toutes les tentatives pour exécuter l'utilitaire échouent avec [ENOENT], et utilise 126 lorsque toute tentative pour exécuter l'utilitaire échoue pour toute autre raison.

EXEMPLES

Il est souvent souhaitable d'appliquer time à des pipelines ou à des listes de commandes. Cela peut être fait en plaçant les pipelines et les listes de commandes dans un seul fichier ; ce fichier peut alors être invoqué comme un utilitaire, et time s'applique à tout dans le fichier.

Alternativement, la commande suivante peut être utilisée pour appliquer time à une commande complexe :

time sh -c 'commande-complexe'

JUSTIFICATION

Lorsque l'utilitaire time a été initialement proposé pour être inclus dans la norme ISO POSIX‐2:1993, des questions ont été soulevées quant à sa pertinence pour inclusion, au motif qu'il n'était pas utile pour les applications conformes, notamment :

*
Les définitions sous-jacentes de CPU du volume Interfaces Système de POSIX.1‐2017 sont vagues, de sorte que la sortie numérique ne pouvait pas être comparée avec précision entre les systèmes ou même entre les invocations.
*
La création de programmes de benchmark portables était en dehors du champ d'application de ce volume de POSIX.1‐2017.

Cependant, time correspond au champ d'application de la portabilité utilisateur. Le jugement humain peut être appliqué à l'analyse de la sortie, et elle pourrait être très utile dans le débogage interactif des applications ou dans la fourniture de mesures subjectives de la performance du système. Par conséquent, elle a été incluse dans ce volume de POSIX.1‐2017.

Le format de sortie par défaut a été laissé non spécifié car les implémentations historiques diffèrent grandement dans leur style de représentation de cette sortie numérique. L'option -p a été inventée pour fournir aux scripts un moyen commun d'obtenir ces informations.

Dans KornShell, time est un mot réservé du shell qui peut être utilisé pour chronométrer un pipeline entier, plutôt qu'une simple commande. La définition POSIX a été rédigée pour permettre cette implémentation. La possibilité d'invalider cette approche a été envisagée en raison du modèle historique du shell C et du shell System V. Cependant, comme l'utilitaire time de System V n'a historiquement pas produit de résultats précis dans le chronométrage de pipeline (car les processus constituants ne sont pas tous détenus par le même processus parent, comme autorisé par POSIX), il n'a pas semblé utile de rompre avec l'usage historique de KornShell.

Le terme utilitaire est utilisé, plutôt que commande, pour souligner le fait que les commandes composites du shell, les pipelines, les built-ins spéciaux, etc., ne peuvent pas être utilisés directement. Cependant, utilitaire comprend les programmes d'application utilisateur et les scripts shell, pas seulement les utilitaires standard.
