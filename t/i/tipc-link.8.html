NOM

tipc-link - afficher les liens ou modifier les propriétés des liens

SYNTAXE


tipc link set
[ { priorité PRIORITE | tolérance TOLERANCE | fenêtre FENETRE } lien LIEN ] |
[ { diffusion [ DIFFUSION | REDIFFUSION | SELECTIONAUTO [ ratio TAILLE ] ] } ]

tipc link get
[ { priorité | tolérance | fenêtre } lien LIEN ] |
[ { diffusion } ]

tipc link statistics { show [ lien LIEN ] | reset lien LIEN }

tipc link list

tipc link monitor set { seuil }

tipc link monitor get { seuil }

tipc link monitor summary

tipc link monitor list
[ media { eth | ib } device APPAREIL ] |
[ media udp name NOM ]

OPTIONS

Options (indicateurs) qui peuvent être passées n'importe où dans la chaîne de commandes.

-h, --help
Affiche l'aide sur la dernière commande valide. Par exemple tipc link --help affichera l'aide sur le lien et tipc --help affichera l'aide générale. La position de l'option dans la chaîne est sans importance.
-j, -json
Affiche les résultats au format JavaScript Object Notation (JSON).
-p, -pretty
Le format JSON par défaut est compact et plus efficace à analyser, mais difficile à lire pour la plupart des utilisateurs. Cet indicateur ajoute une indentation pour la lisibilité.

DESCRIPTION

Statistiques de lien

État de lien ACTIF

Un lien ACTIF sert le trafic. Deux liens vers le même nœud peuvent devenir ACTIFS s'ils ont la même priorité de lien. S'il y a plus de deux liens avec la même priorité, les liens supplémentaires seront mis à l'état EN ATTENTE.
État de lien EN ATTENTE

Un lien EN ATTENTE a une priorité de lien inférieure à celle d'un lien ACTIF. Un lien EN ATTENTE fait circuler le trafic de contrôle et est prêt à prendre le relais si le ou les liens ACTIFS tombent en panne.
MTU

Unité de Transmission Maximale. Les deux points d'extrémité annoncent leur MTU par défaut ou configurée lors de la configuration initiale du lien et accepteront d'utiliser la plus petite des deux valeurs si elles diffèrent.
Paquets

Quantité totale de paquets TIPC transmis ou reçus sur un lien. Incluant les paquets fragmentés et groupés.
Fragments

Représenté sous la forme fragments/fragmenté. Où fragmenté est la quantité de messages de données qui ont été décomposés en fragments. Par conséquent, les fragments sont la quantité totale de paquets dans lesquels les messages fragmentés ont été décomposés.
Groupements

Représenté sous la forme groupements/groupé. Si un lien devient congestionné, le lien tentera de regrouper les données de petits paquets groupés en groupements de paquets de taille MTU complète avant leur transmission.
Profil

Affiche la taille moyenne des paquets en octets pour un échantillon de paquets. Il affiche également la distribution de la taille des paquets des paquets échantillonnés dans les intervalles

0-64 octets
64-256 octets
256-1024 octets
1024-4096 octets
4096-16384 octets
16384-32768 octets
32768-66000 octets

Compteurs de messages

états - Nombre de messages d'état de lien

sondes - Messages d'état de lien avec l'indicateur de sonde défini. Généralement envoyés lorsqu'un lien est inactif

nacks - Nombre de paquets d'accusé de réception négatif (NACK) envoyés et reçus par le lien

defs - Nombre de paquets reçus dans le désordre

dups - Nombre de paquets dupliqués reçus

Lien de congestion
Nombre de fois où une application a tenté d'envoyer des données alors que le lien TIPC était congestionné
File d'attente d'envoi
Max est la quantité maximale de messages qui ont résidé dans la file d'attente de sortie pendant la période de collecte des statistiques d'un lien.

Moy est la taille moyenne de la file d'attente de sortie pendant la durée de vie d'un lien.

Propriétés des liens

priorité

La priorité entre les liens logiques TIPC vers un nœud particulier. La priorité du lien peut varier de 0 (la plus basse) à 31 (la plus haute).
tolérance

La tolérance du lien spécifie le temps maximum en millisecondes que TIPC autorisera à un problème de communication avant de désactiver le lien. La valeur par défaut est de 1500 millisecondes.
fenêtre

La fenêtre de lien contrôle le nombre de messages non acquittés que le point d'extrémité d'un lien peut avoir dans sa file d'attente d'émission avant que le mécanisme de contrôle de congestion de TIPC ne soit activé.

Propriétés du moniteur

seuil

Le seuil spécifie la taille du cluster au-delà de laquelle l'algorithme de surveillance des liens passe de la "maillage complet" à l'"anneau imbriqué". S'il est réglé sur 0, la surveillance par anneau imbriqué est toujours activée, et s'il est réglé sur une valeur supérieure à la taille de cluster anticipée, l'anneau imbriqué est désactivé. La valeur par défaut est 32.

Informations du moniteur

génération_table

Représente le compte d'événements dans la liste de surveillance locale d'un nœud. Il s'incrémente chaque fois que quelque chose change dans la liste de surveillance locale, y compris les changements dans le domaine local.
taille_cluster

Représente le nombre actuel de membres du cluster.
algorithme

L'algorithme de supervision actuel utilisé pour la surveillance des voisins pour le support. Les valeurs possibles sont maillage complet ou anneau imbriqué.
statut

Le statut du nœud dérivé par le nœud local. Les statuts possibles sont actif ou inactif.
supervisé

Représente le type de surveillance choisi par le nœud local. Les valeurs possibles sont direct ou indirect.
génération

Représente la génération de domaine, qui est le compte d'événements dans le domaine local d'un nœud. Chaque fois que quelque chose change (ajout/suppression/activation/désactivation d'un pair), la génération de domaine est incrémentée et une nouvelle version de l'enregistrement du nœud est envoyée pour informer les voisins de ce changement. La génération de domaine aide le récepteur d'un enregistrement de domaine à savoir s'il doit ignorer ou traiter l'enregistrement.
applied_node_statu

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

s">applied_node_status

L'état du nœud rapporté par le nœud pair pour les nœuds suivants dans la liste de nœuds. La liste de nœuds est une liste circulaire d'adresses croissantes commençant par le nœud local. Les statuts possibles sont : U ou D. Le statut U implique actif et D inactif.
[non_applied_node:status]

Représente les nœuds et leur statut tels que rapportés par le nœud pair. Ces nœuds n'ont pas été appliqués à la liste de surveillance pour ce nœud pair. Ils sont généralement transitoires et surviennent pendant la phase de démarrage du cluster ou la reconfiguration du réseau. Les statuts possibles sont : U ou D. Le statut U implique actif et D inactif.

Propriétés de diffusion

BROADCAST

Force tout le trafic de multidiffusion à être transmis uniquement par diffusion, quelle que soit la taille du cluster et le nombre de destinations.
REPLICAST

Force tout le trafic de multidiffusion à être transmis uniquement par réplication, quelle que soit la taille du cluster et le nombre de destinations.
AUTOSELECT

Sélection automatique par diffusion ou réplication en fonction de la taille du cluster et du nombre de nœuds de destination.
ratio TAILLE

Définit le critère AUTOSELECT, le pourcentage de nœuds de destination par rapport à la taille du cluster.

EXEMPLES

tipc link monitor list

Affiche les informations de surveillance des liens pour les membres du cluster sur le périphérique data0.

tipc link monitor summary

La commande de résumé du moniteur imprime les attributs de base.

STATUT DE SORTIE

Le statut de sortie est 0 si la commande a réussi ou un entier positif en cas d'échec.
