TIMESYNCD.CONF(5) timesyncd.conf TIMESYNCD.CONF(5)

NOM

timesyncd.conf, timesyncd.conf.d - Fichiers de configuration de la synchronisation horaire réseau

SYNTAXE

/etc/systemd/timesyncd.conf
/run/systemd/timesyncd.conf
/usr/local/lib/systemd/timesyncd.conf
/usr/lib/systemd/timesyncd.conf
/etc/systemd/timesyncd.conf.d/*.conf
/run/systemd/timesyncd.conf.d/*.conf
/usr/local/lib/systemd/timesyncd.conf.d/*.conf
/usr/lib/systemd/timesyncd.conf.d/*.conf

DESCRIPTION

Ces fichiers de configuration contrôlent la synchronisation horaire réseau NTP. Voir systemd.syntax(7) pour une description générale de la syntaxe.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, donc une configuration n'est nécessaire que lorsqu'il est nécessaire de s'écarter de ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés dans l'ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des substitutions locales peuvent également être créées en créant des fichiers de remplacement, comme décrit ci-dessous. Le fichier de configuration principal peut également être édité à cet effet (ou une copie dans /etc/ s'il est livré sous /etc/), cependant l'utilisation de fichiers de remplacement pour la configuration locale est recommandée plutôt que des modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des fragments de configuration de remplacement sont lus à partir de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces fichiers de remplacement ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier dans l'ordre lexicographique, quelle que soit la sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier a la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure qu'elles apparaissent dans les fichiers triés.

Lorsque des paquets doivent personnaliser la configuration, ils peuvent installer des fichiers de remplacement sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les fichiers de remplacement doivent être utilisés pour remplacer les fichiers de remplacement des paquets, car le fichier de configuration principal a une priorité inférieure. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires par un nombre à deux chiffres et un trait d'union, pour simplifier l'ordre. Cela définit également un concept de priorités de fichiers de remplacement pour permettre aux fournisseurs de systèmes d'exploitation de livrer des fichiers de remplacement dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les fichiers de remplacement des paquets remplacent accidentellement les fichiers de remplacement définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les fichiers de remplacement dans /usr/ et la plage 60-90 pour les fichiers de remplacement dans /etc/ et /run/, pour s'assurer que les fichiers de remplacement locaux et transitoires ont la priorité sur les fichiers de remplacement livrés par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS

Les paramètres suivants sont configurés dans la section [Time] :

NTP=

Une liste de noms d'hôtes ou d'adresses IP de serveurs NTP séparés par des espaces. Pendant l'exécution, cette liste est combinée avec les serveurs NTP par interface acquis depuis systemd-networkd.service(8). systemd-timesyncd contactera tous les serveurs système ou par interface configurés tour à tour, jusqu'à ce qu'un réponde. Lorsque la chaîne vide est assignée, la liste des serveurs NTP est réinitialisée et toutes les affectations précédentes n'auront aucun effet. Ce paramètre est vide par défaut.

Ajouté dans la version 216.

FallbackNTP=

Une liste de noms d'hôtes ou d'adresses IP de serveurs NTP de secours, séparés par des espaces. Tous les serveurs NTP par interface obtenus depuis systemd-networkd.service(8) ont la priorité sur ce paramètre, tout comme les serveurs définis via NTP= ci-dessus. Ce paramètre n'est donc pertinent que si aucune autre information de serveur NTP n'est connue. Lorsque la chaîne vide est assignée, la liste des serveurs NTP est réinitialisée et toutes les affectations précédentes n'auront aucun effet. Si cette option n'est pas fournie, une liste de serveurs NTP intégrée est utilisée.

Ajouté dans la version 216.

RootDistanceMaxSec=

Distance racine maximale acceptable, c'est-à-dire le temps estimé maximum requis pour qu'un paquet voyage vers le serveur auquel nous sommes connectés, depuis le serveur avec l'horloge de référence. Si le serveur actuel ne satisfait pas cette limite, systemd-timesyncd basculera vers un autre serveur.

Prend une valeur de durée. L'unité par défaut est la seconde, mais d'autres unités peuvent être spécifiées, voir systemd.time(7). Par défaut 5 secondes.

Ajouté dans la version 236.

PollIntervalMinSec=, PollIntervalMaxSec=

Les intervalles de sondage minimum et maximum pour les messages NTP. La sondage commence à l'intervalle de sondage minimum et est ajusté dans les limites spécifiées en réponse aux paquets reçus.

Chaque paramètre prend une valeur de durée. L'unité par défaut est la seconde, mais d'autres unités peuvent être spécifiées, voir systemd.time(7). PollIntervalMinSec= est par défaut 32 secondes et ne doit pas être inférieur à 16 secondes. PollIntervalMaxSec= est par défaut 34 minutes 8 secondes (2048 secondes) et doit être supérieur à PollIntervalMinSec=.

Ajouté dans la version 236.

ConnectionRetrySec=

Spécifie le délai minimum avant que les tentatives ultérieures de contact avec un nouveau serveur NTP ne soient effectuées.

Prend une valeur de durée. L'unité par défaut est la seconde, mais d'autres unités peuvent être spécifiées, voir systemd.time(7). Par défaut 30 secondes et ne doit pas être inférieur à 1 seconde.

Ajouté dans la version 248.

SaveIntervalSec=

L'intervalle auquel l'heure actuelle est périodiquement sauvegardée sur disque, en l'absence de synchronisation récente avec un serveur NTP. Ceci est particulièrement utile pour les systèmes hors ligne sans RTC locale, car cela garantit que l'horloge système reste à peu près monolineaire lors des redémarrages.

Prend une valeur de durée. L'unité par défaut est la seconde, mais d'autres unités peuvent être spécifiées, voir systemd.time(7). Par défaut 60 secondes.

Ajouté dans la version 250.

VOIR AUSSI

systemd(1), systemd-timesyncd.service(8), systemd-networkd.service(8)

timesyncd.conf.d(5)

NOM

timesyncd.conf.d - Fichiers de configuration pour le démon de synchronisation NTP de systemd

SYNTAXE

Le fichier de configuration principal est/etc/systemd/timesyncd.conf. Les fichiers de configuration supplémentaires sont placés dans le répertoire/etc/systemd/timesyncd.conf.d/.

Le fichier de configuration principal et les fichiers de configuration dans/etc/systemd/timesyncd.conf.d/sont analysés dans l'ordre alphabétique. Les paramètres définis dans un fichier ultérieur remplacent ceux définis dans les fichiers précédents.

Les fichiers peuvent contenir des sections qui commencent par[Section]. Les sections actuellement prises en charge sont :

  • [Time]
  • [Network]

Chaque section peut contenir des paires de clé-valeur.

Les options de configuration sont les suivantes :

DESCRIPTION

systemd-timesyncdest un démon système qui synchronise l'heure du système avec des serveurs de temps distants à l'aide du protocole NTP.

Les fichiers de configuration poursystemd-timesyncdsont analysés dans les emplacements suivants, dans l'ordre :

  1. /etc/systemd/timesyncd.conf
  2. Les fichiers dans/etc/systemd/timesyncd.conf.d/. Ces fichiers sont lus dans l'ordre alphabétique.
  3. Les fichiers dans/run/systemd/timesyncd.conf.d/. Ces fichiers sont lus dans l'ordre alphabétique.
  4. Les fichiers dans/usr/lib/systemd/timesyncd.conf.d/. Ces fichiers sont lus dans l'ordre alphabétique.

Les paramètres définis dans les fichiers lus ultérieurement remplacent ceux définis dans les fichiers lus précédemment. Si un fichier vide ou un symbole de lien symbolique est rencontré, la recherche est arrêtée.

Les valeurs peuvent être des chaînes de caractères, des entiers, des booléens ou des listes (séparées par des espaces).

Les booléens peuvent être l'une des valeurs suivantes :yes,no,true,false,1ou0.

Les commentaires peuvent être ajoutés en utilisant#ou;en tant que premier caractère d'une ligne.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration desystemd-timesyncdest définie dans plusieurs emplacements. Les paramètres peuvent être spécifiés dans le fichier/etc/systemd/timesyncd.confet/ou dans des fichiers*.confplacés dans le répertoire/etc/systemd/timesyncd.conf.d/. Les fichiers de configuration sont traités dans l'ordre alphabétique. Les valeurs définies dans un fichier ultérieur remplacent celles définies dans les fichiers précédents.

systemd-timesyncdrecherche les fichiers de configuration dans les répertoires suivants, par ordre de priorité décroissante :

  1. /etc/systemd/timesyncd.conf
  2. /etc/systemd/timesyncd.conf.d/*.conf
  3. /run/systemd/timesyncd.conf.d/*.conf
  4. /usr/lib/systemd/timesyncd.conf.d/*.conf

Si un fichier/etc/systemd/timesyncd.confn'existe pas, aucun fichier de configuration n'est chargé.

OPTIONS

Les options de configuration suivantes sont disponibles dans la section[Time]:

NTP=
Spécifie une liste de serveurs NTP pour la synchronisation de l'heure. Les noms d'hôtes et les adresses IP peuvent être utilisés. S'ils sont vides, le service utilise les serveurs NTP configurés dans le fichier/etc/resolv.conf.
FallbackNTP=
Spécifie une liste de serveurs NTP de secours à utiliser si les serveurs NTP principaux ne parviennent pas à se connecter. S'ils sont vides, le service n'utilise aucun serveur de secours.
RootDistance=
Spécifie la distance maximale de l'horloge racine pour que la synchronisation soit considérée comme valide. La valeur est en secondes. La valeur par défaut est 5 secondes.
PollInterval=
Spécifie l'intervalle de sondage pour la synchronisation NTP. La valeur est en secondes. La valeur minimale est 1 seconde et la valeur maximale est 3600 secondes (1 heure). La valeur par défaut est 32 secondes.
UpdateBroadcast=
Spécifie si les mises à jour de l'heure doivent être diffusées aux clients sur le réseau local. Les valeurs possibles sontyesouno. La valeur par défaut estno.

Les options de configuration suivantes sont disponibles dans la section[Network]:

LinkLocalAddressing=
Spécifie si l'adresse IP de liaison locale doit être configurée. Les valeurs possibles sontyesouno. La valeur par défaut estyes.
UseDNS=
Spécifie si le service doit utiliser les serveurs DNS configurés dans/etc/resolv.confpour résoudre les noms d'hôtes NTP. Les valeurs possibles sontyesouno. La valeur par défaut estyes.
