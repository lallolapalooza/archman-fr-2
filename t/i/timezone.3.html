tzset(3) Manuel des fonctions de bibliothèque tzset(3)

NOM

tzset, tzname, timezone, daylight - initialiser les informations de conversion de fuseau horaire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <time.h>
void tzset(void);
extern char *tzname[2];
extern long timezone;
extern int daylight;
Exigences de macro de test de fonctionnalité pour glibc (voir feature_test_macros(7)):

tzset():

    _POSIX_C_SOURCE

tzname:

    _POSIX_C_SOURCE

timezone, daylight:

    _XOPEN_SOURCE
        || /* glibc >= 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE

DESCRIPTION

La fonction tzset() initialise la variable tzname à partir de la variable d'environnement TZ. Cette fonction est appelée automatiquement par les autres fonctions de conversion de temps qui dépendent du fuseau horaire. Dans un environnement de type System-V, elle définit également les variables timezone (secondes à l'ouest de l'UTC) et daylight (à 0 si ce fuseau horaire n'a pas de règles d'heure d'été, ou à une valeur non nulle s'il y a un moment, passé, présent ou futur, où l'heure d'été s'applique).

La fonction tzset() initialise ces variables à des valeurs non spécifiées si ce fuseau horaire est un fuseau horaire géographique comme "America/New_York" (voir ci-dessous).

Si la variable TZ n'apparaît pas dans l'environnement, le fuseau horaire du système est utilisé. Le fuseau horaire du système est configuré en copiant, ou en créant un lien symbolique, un fichier au format tzfile(5) vers /etc/localtime. Une base de données de fuseaux horaires de ces fichiers peut se trouver dans le répertoire des fuseaux horaires du système (voir la section FICHIERS ci-dessous).

Si la variable TZ apparaît dans l'environnement, mais que sa valeur est vide, ou si sa valeur ne peut pas être interprétée en utilisant l'un des formats spécifiés ci-dessous, alors le Temps Universel Coordonné (UTC) est utilisé.

Une valeur non vide de TZ peut être l'un des deux formats, chacun pouvant être précédé d'un deux-points qui est ignoré. Le premier format est une chaîne de caractères qui représente directement le fuseau horaire à utiliser :


std decalage[ete[decalage][,debut[/heure],fin[/heure]]]

Il n'y a pas d'espaces dans la spécification. La chaîne std spécifie une abréviation pour le fuseau horaire et doit être composée de trois caractères alphabétiques ou plus. Lorsqu'elle est entourée des signes inférieur (<) et supérieur (>), l'ensemble de caractères est étendu pour inclure les signes plus (+) et moins (-) ainsi que les chiffres. La chaîne decalage suit immédiatement std et spécifie la valeur temporelle à ajouter au temps local pour obtenir le Temps Universel Coordonné (UTC). Le decalage est positif si le fuseau horaire local est à l'ouest du méridien de Greenwich et négatif s'il est à l'est. L'heure doit être comprise entre 0 et 24, et les minutes et secondes entre 00 et 59 :


[+|-]hh[:mm[:ss]]

La chaîne ete et le decalage spécifient le nom et le décalage pour le fuseau horaire d'heure d'été correspondant. Si le décalage est omis, il est par défaut d'une heure en avance sur l'heure standard.

Les champs debut spécifient quand l'heure d'été entre en vigueur et le champ fin spécifie quand le changement est effectué pour revenir à l'heure standard. Ces champs peuvent avoir les formats suivants :

Jn
Ceci spécifie le jour julien avec n compris entre 1 et 365. Les jours bissextiles ne sont pas comptés. Dans ce format, le 29 février ne peut pas être représenté ; le 28 février est le jour 59, et le 1er mars est toujours le jour 60.
n
Ceci spécifie le jour julien basé sur zéro avec n compris entre 0 et 365. Le 29 février est compté les années bissextiles.
Mm.s.j
Ceci spécifie le jour j (0 <= j <= 6) de la semaine s (1 <= s <= 5) du mois m (1 <= m <= 12). La semaine 1 est la première semaine au cours de laquelle le jour j se produit et la semaine 5 est la dernière semaine au cours de laquelle le jour j se produit. Le jour 0 est un dimanche.

Les champs heure spécifient quand, dans l'heure locale actuellement en vigueur, le changement vers l'autre heure se produit. Ils utilisent le même format que decalage, sauf que l'heure peut être dans la plage [-167, 167] pour représenter les heures avant et après le jour nommé. Si omis, la valeur par défaut est 02:00:00.

Voici un exemple pour la Nouvelle-Zélande, où l'heure standard (NZST) est 12 heures en avance sur l'UTC, et l'heure d'été (NZDT), 13 heures en avance sur l'UTC, s'étend du dernier dimanche de septembre, à l'heure par défaut 02:00:00, au premier dimanche d'avril à 03:00:00.


TZ="NZST-12:00:00NZDT-13:00:00,M9.5.0,M4.1.0/3"

Le second format — ou format "géographique" — spécifie que les informations de fuseau horaire doivent être lues à partir d'un fichier :


spécification_fichier

La spécification_fichier spécifie un fichier au format tzfile(5) à lire pour obtenir les informations de fuseau horaire. Si spécification_fichier ne commence pas par un '/', la spécification du fichier est relative au répertoire des fuseaux horaires du système. Si le fichier spécifié ne peut pas être lu ou interprété, le Temps Universel Coordonné (UTC) est utilisé ; cependant, les applications ne doivent pas dépendre de valeurs aléatoires de spécification_fichier pour représenter l'UTC, car les formats TZ peuvent être étendus à l'avenir.

Voici un exemple, encore une fois pour la Nouvelle-Zélande :


TZ="Pacific/Auckland"

ENVIRONNEMENT

TZ
Si cette variable est définie, sa valeur prime sur le fuseau horaire configuré par le système.
TZDIR
Si cette variable est définie, sa valeur prime sur le chemin du répertoire de la base de données des fuseaux horaires configuré par le système.

FICHIERS

/etc/localtime
Le fichier de fuseau horaire du système.
/usr/share/zoneinfo/
Le répertoire de la base de données des fuseaux horaires du système.
/usr/share/zoneinfo/posixrules
Lorsqu'une chaîne TZ inclut un fuseau horaire dst sans rien qui le suive, ce fichier est utilisé pour les règles de début/fin. Il est au format tzfile(5). Par défaut, le Makefile de zoneinfo crée un lien symbolique vers le fichier tzfile de America/New_York.

Ci-dessus se trouvent les emplacements standard actuels des fichiers, mais ils sont configurables lors de la compilation de glibc.

HISTORIQUE

POSIX.1-1988, SVr4, 4.3BSD.
timezone
daylight
POSIX.1-2001 (XSI), SVr4, 4.3BSD.

4.3BSD avait une fonction char *timezone(zone, dst) qui renvoyait le nom du fuseau horaire correspondant à son premier argument (minutes à l'ouest de l'UTC). Si le second argument était 0, le nom standard était utilisé, sinon la version heure d'été.

POINTS D'ATTENTION

Étant donné que les valeurs de tzname, timezone et daylight sont souvent non spécifiées, et que leur accès peut conduire à un comportement indéfini

C AVEATS

L'appel système tzset(3) is obsolete. In multithreaded applications, code should instead obtain time zone offset and abbreviations from the tm_gmtoff and tm_zone members of the broken-down time structure tm(3type).

B UGS

Since this function does not report errors, there's no way to know if the value of TZ represents a valid time zone.
