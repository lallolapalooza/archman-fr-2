timerfd_create(2) Manuel des appels système timerfd_create(2)

NOM

timerfd_create, timerfd_settime, timerfd_gettime - minuteurs qui notifient via des descripteurs de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/timerfd.h>
int timerfd_create(int clockid, int flags);
int timerfd_settime(int fd, int flags,
                    const struct itimerspec *new_value,
                    struct itimerspec *_Nullable old_value);
int timerfd_gettime(int fd, struct itimerspec *curr_value);

DESCRIPTION

Ces appels système créent et manipulent un minuteur qui délivre des notifications d'expiration de minuteur via un descripteur de fichier. Ils offrent une alternative à l'utilisation de setitimer(2) ou timer_create(2), avec l'avantage que le descripteur de fichier peut être surveillé par select(2), poll(2), et epoll(7).

L'utilisation de ces trois appels système est analogue à l'utilisation de timer_create(2), timer_settime(2), et timer_gettime(2). (Il n'y a pas d'équivalent à timer_getoverrun(2), car cette fonctionnalité est fournie par read(2), comme décrit ci-dessous.)

timerfd_create()

timerfd_create() crée un nouvel objet minuteur et retourne un descripteur de fichier qui référence ce minuteur. L'argument clockid spécifie l'horloge utilisée pour marquer la progression du minuteur et doit être l'une des suivantes :

CLOCK_REALTIME
Une horloge temps réel système, modifiable.
CLOCK_MONOTONIC
Une horloge monotone qui ne peut pas être modifiée et qui mesure le temps depuis un point indéterminé dans le passé qui ne change pas après le démarrage du système.
CLOCK_BOOTTIME (depuis Linux 3.15)
Comme CLOCK_MONOTONIC, il s'agit d'une horloge monotone. Cependant, alors que l'horloge CLOCK_MONOTONIC ne mesure pas le temps pendant une suspension du système, l'horloge CLOCK_BOOTTIME inclut le temps pendant lequel le système est suspendu. Ceci est utile pour les applications qui doivent être conscientes des suspensions. CLOCK_REALTIME n'est pas adapté à de telles applications, car cette horloge est affectée par les changements discontinus de l'horloge système.
CLOCK_REALTIME_ALARM (depuis Linux 3.11)
Cette horloge est similaire à CLOCK_REALTIME, mais elle réveillera le système s'il est suspendu. L'appelant doit posséder la capacité CAP_WAKE_ALARM pour pouvoir régler un minuteur sur cette horloge.
CLOCK_BOOTTIME_ALARM (depuis Linux 3.11)
Cette horloge est similaire à CLOCK_BOOTTIME, mais elle réveillera le système s'il est suspendu. L'appelant doit posséder la capacité CAP_WAKE_ALARM pour pouvoir régler un minuteur sur cette horloge.

Voir clock_getres(2) pour plus de détails sur les horloges mentionnées ci-dessus.

La valeur actuelle de chacune de ces horloges peut être récupérée en utilisant clock_gettime(2).

À partir de Linux 2.6.27, les valeurs suivantes peuvent être combinées par un OU binaire dans flags pour changer le comportement de timerfd_create():

TFD_NONBLOCK
Définit le statut de fichier O_NONBLOCK sur la description de fichier (voir open(2)) référencée par le nouveau descripteur de fichier. L'utilisation de ce drapeau évite des appels supplémentaires à fcntl(2) pour obtenir le même résultat.
TFD_CLOEXEC
Définit le drapeau close-on-exec (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description du drapeau O_CLOEXEC dans open(2) pour les raisons pour lesquelles cela peut être utile.

Dans les versions de Linux jusqu'à et incluant 2.6.26, flags doit être spécifié comme zéro.

timerfd_settime()

timerfd_settime() arme (démarre) ou désarme (arrête) le minuteur référencé par le descripteur de fichier fd.

L'argument new_value spécifie l'expiration initiale et l'intervalle du minuteur. La structure itimerspec utilisée pour cet argument est décrite dans itimerspec(3type).

new_value.it_value spécifie l'expiration initiale du minuteur, en secondes et nanosecondes. Définir l'un ou l'autre champ de new_value.it_value sur une valeur non nulle arme le minuteur. Définir les deux champs de new_value.it_value sur zéro désarme le minuteur.

Définir un ou les deux champs de new_value.it_interval sur des valeurs non nulles spécifie la période, en secondes et nanosecondes, pour les expirations répétées du minuteur après l'expiration initiale. Si les deux champs de new_value.it_interval sont zéro, le minuteur expire une seule fois, au moment spécifié par new_value.it_value.

Par défaut, le temps d'expiration initial spécifié dans new_value est interprété par rapport au temps actuel de l'horloge du minuteur au moment de l'appel (c'est-à-dire, new_value.it_value spécifie un temps relatif à la valeur actuelle de l'horloge spécifiée par clockid). Un délai d'expiration absolu peut être sélectionné via l'argument flags.

L'argument flags est un masque de bits qui peut inclure les valeurs suivantes :

TFD_TIMER_ABSTIME
Interprète new_value.it_value comme une valeur absolue sur l'horloge du minuteur. Le minuteur expirera lorsque la valeur de l'horloge du minuteur atteindra la valeur spécifiée dans new_value.it_value.
TFD_TIMER_CANCEL_ON_SET
Si ce drapeau est spécifié avec TFD_TIMER_ABSTIME et que l'horloge pour ce minuteur est CLOCK_REALTIME ou CLOCK_REALTIME_ALARM, alors marque ce minuteur comme annulable si l'horloge temps réel subit un changement discontinu (settimeofday(2), clock_settime(2), ou similaire). Lorsque de tels changements se produisent, une lecture actuelle ou future depuis le descripteur de fichier échouera avec l'erreur ECANCELED.

Si l'argument old_value n'est pas NULL, alors la structure itimerspec qu'il pointe est utilisée pour retourner le réglage du minuteur qui était actuel au moment de l'appel ; voir la description de timerfd_gettime() ci-dessous.

timerfd_gettime()

timerfd_gettime() retourne, dans curr_value, une structure itimerspec qui contient le réglage actuel du minuteur référencé par le descripteur de fichier fd.

Le champ it_value retourne le temps restant avant que le minuteur n'expire. Si les deux champs de cette structure sont zéro, alors le minuteur est actuellement désarmé. Ce champ contient toujours une valeur relative, quel que soit le drapeau TFD_TIMER_ABSTIME spécifié lors du réglage du minuteur.

Le champ it_interval retourne l'intervalle du minuteur. Si les deux champs de cette structure sont zéro, alors le minuteur est réglé pour expirer une seule fois, au moment spécifié par curr_value.it_value.

Opération sur un descripteur de minuteur

Le descripteur de fichier retourné par timerfd_create() prend en charge les opérations supplémentaires suivantes :

read(2)
Si le minuteur a déjà expiré une ou plusieurs fois depuis la dernière modification de ses paramètres

ed en utilisant timerfd_settime(), ou depuis la dernière lecture réussie de read(2), alors le tampon fourni à read(2) retourne un entier de 8 octets non signé (uint64_t) contenant le nombre d'expirations qui se sont produites. (La valeur retournée est dans l'ordre des octets hôte, c'est-à-dire l'ordre des octets natif pour les entiers sur la machine hôte.)
Si aucune expiration de minuteur ne s'est produite au moment de la lecture de read(2), alors l'appel bloque jusqu'à la prochaine expiration du minuteur, ou échoue avec l'erreur EAGAIN si le descripteur de fichier a été rendu non bloquant (via l'utilisation de l'opération fcntl(2) F_SETFL pour définir le drapeau O_NONBLOCK).
Une lecture de read(2) échoue avec l'erreur EINVAL si la taille du tampon fourni est inférieure à 8 octets.
Si l'horloge associée est soit CLOCK_REALTIME soit CLOCK_REALTIME_ALARM, le minuteur est absolu (TFD_TIMER_ABSTIME), et le drapeau TFD_TIMER_CANCEL_ON_SET a été spécifié lors de l'appel à timerfd_settime(), alors read(2) échoue avec l'erreur ECANCELED si l'horloge temps réel subit un changement discontinu. (Cela permet à l'application de lecture de découvrir de tels changements discontinus de l'horloge.)
Si l'horloge associée est soit CLOCK_REALTIME soit CLOCK_REALTIME_ALARM, le minuteur est absolu (TFD_TIMER_ABSTIME), et le drapeau TFD_TIMER_CANCEL_ON_SET n'a *pas* été spécifié lors de l'appel à timerfd_settime(), alors un changement négatif discontinu de l'horloge (par exemple, clock_settime(2)) peut provoquer le déblocage de read(2), mais retourner une valeur de 0 (c'est-à-dire aucune octet lu), si le changement d'horloge se produit après l'expiration du temps, mais avant la lecture de read(2) sur le descripteur de fichier.
poll(2)
select(2)
(et similaire)
Le descripteur de fichier est lisible (l'argument readfds de select(2) ; le drapeau POLLIN de poll(2)) si une ou plusieurs expirations de minuteur se sont produites.
Le descripteur de fichier prend également en charge les autres API de multiplexage de descripteurs de fichiers : pselect(2), ppoll(2) et epoll(7).
ioctl(2)
La commande spécifique au minuteur suivante est prise en charge :
TFD_IOC_SET_TICKS (depuis Linux 3.17)
Ajuste le nombre d'expirations de minuteur qui se sont produites. L'argument est un pointeur vers un entier non signé de 8 octets non nul (uint64_t*) contenant le nouveau nombre d'expirations. Une fois le nombre défini, tout attente sur le minuteur est réveillée. Le seul but de cette commande est de restaurer les expirations à des fins de checkpoint/restauration. Cette opération est disponible uniquement si le noyau a été configuré avec l'option CONFIG_CHECKPOINT_RESTORE.
close(2)
Lorsque le descripteur de fichier n'est plus nécessaire, il doit être fermé. Lorsque tous les descripteurs de fichiers associés au même objet minuteur ont été fermés, le minuteur est désarmé et ses ressources sont libérées par le noyau.

Sémantique de fork(2)

Après un fork(2), l'enfant hérite d'une copie du descripteur de fichier créé par timerfd_create(). Le descripteur de fichier fait référence au même objet minuteur sous-jacent que le descripteur de fichier correspondant dans le parent, et les lectures de read(2) dans l'enfant retourneront des informations sur les expirations du minuteur.

Sémantique de execve(2)

Un descripteur de fichier créé par timerfd_create() est préservé lors d'un execve(2), et continue de générer des expirations de minuteur si le minuteur était armé.

VALEUR DE RETOUR

En cas de succès, timerfd_create() retourne un nouveau descripteur de fichier. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

timerfd_settime() et timerfd_gettime() retournent 0 en cas de succès ; en cas d'erreur, ils retournent -1 et définissent errno pour indiquer l'erreur.

ERREURS

timerfd_create() peut échouer avec les erreurs suivantes :

EINVAL
Le clockid n'est pas valide.
EINVAL
flags est invalide ; ou, dans Linux 2.6.26 ou antérieur, flags est non nul.
EMFILE
La limite par processus sur le nombre de descripteurs de fichiers ouverts a été atteinte.
ENFILE
La limite globale du système sur le nombre total de fichiers ouverts a été atteinte.
ENODEV
Impossible de monter un périphérique d'inode anonyme (interne).
ENOMEM
Il y avait une insuffisance de mémoire noyau pour créer le minuteur.
EPERM
clockid était CLOCK_REALTIME_ALARM ou CLOCK_BOOTTIME_ALARM mais l'appelant n'avait pas la capacité CAP_WAKE_ALARM.

timerfd_settime() et timerfd_gettime() peuvent échouer avec les erreurs suivantes :

EBADF
fd n'est pas un descripteur de fichier valide.
EFAULT
new_value, old_value, ou curr_value n'est pas un pointeur valide.
EINVAL
fd n'est pas un descripteur de fichier timerfd valide.

timerfd_settime() peut également échouer avec les erreurs suivantes :

ECANCELED
Voir NOTES.
EINVAL
new_value n'est pas correctement initialisé (l'un des tv_nsec est en dehors de la plage de zéro à 999 999 999).
EINVAL
flags est invalide.

NORMES

Linux.

HISTORIQUE

Linux 2.6.25, glibc 2.8.

NOTES

Supposons le scénario suivant pour un minuteur CLOCK_REALTIME ou CLOCK_REALTIME_ALARM qui a été créé avec timerfd_create():

(1)
Le minuteur a été démarré (timerfd_settime()) avec les drapeaux TFD_TIMER_ABSTIME et TFD_TIMER_CANCEL_ON_SET ;
(2)
Un changement discontinu (par exemple, settimeofday(2)) est effectué ultérieurement sur l'horloge CLOCK_REALTIME ; et
(3)
l'appelant appelle à nouveau timerfd_settime() pour réarmer le minuteur (sans d'abord effectuer une lecture de read(2) sur le descripteur de fichier).

Dans ce cas, le comportement suivant se produit :

•
Le timerfd_settime() retourne -1 avec errno défini sur ECANCELED. (Cela permet à l'appelant de savoir que le minuteur précédent a été affecté par un changement discontinu de l'horloge.)
•
Le minuteur est *réarmé avec succès* avec les paramètres fournis dans le deuxième appel à timerfd_settime(). (C'était probablement un accident d'implémentation, mais ne sera pas corrigé maintenant, au cas où certaines applications dépendraient de ce comportement.)

BOGUES

Actuellement, timerfd_create() prend en charge moins de types d'identifiants d'horloge que timer_create(2).

LIBRARY

Library linked when using the pkg-config(1) macro: libc

SYNOPSIS

#include <sys/timerfd.h>

int timerfd_settime(int fd, int flags,
                    const struct itimerspec *new_value,
                    struct itimerspec *old_value);
int timerfd_gettime(int fd, struct itimerspec *curr_value);

DESCRIPTION

The timerfd_settime() function sets the time of the timer, relative to the clock specified in the -d flag of timerfd_create(2), associated with the timerfd file descriptor fd.

The new_value argument points to a struct itimerspec that specifies the new timer expiration timing. This structure contains two fields:

  • it_interval: Specifies the interval between successive timer expirations. If this is non-zero, then the timer generates a new expiration event every it_interval seconds.
  • it_value: Specifies the time of the first expiration.

The flags argument can be used to specify options. The only option currently supported is:

  • TFD_TIMER_ABSTIME: If set in flags, then new_value.it_value specifies an absolute time (an absolute value on the timer's clock). If not set, then new_value.it_value specifies a relative time (an offset from the current time).

If old_value is not NULL, then the struct itimerspec it points to is filled with the previous settings of the timer. If the timer was not set previously, it_value and it_interval will be set to zero.

The timerfd_gettime() function fills the struct itimerspec pointed to by curr_value with the current expiration time and interval of the timer associated with fd.

The time values in struct itimerspec are specified using struct timespec, which has two members: tv_sec for seconds and tv_nsec for nanoseconds.

A timer that is set with an it_value of {0, 0} is disarmed. If the timer was armed, this causes it to be stopped. An interval of {0, 0} also disables the interval timer, causing the timer to expire just once.

When a timer expires, if it has an interval greater than zero, it is automatically reset to the interval specified by it_interval, relative to the expiration time of the prior interval. If the interval is zero, the timer is disarmed after expiration.

When a timer expires, the caller is notified by making one or more uint64_t values available for reading (via read(2)) from the timerfd file descriptor. The number of timer expirations that have occurred since the last read(2) is returned as the number of `ticks` in the uint64_t value. The value read is the number of expirations. The timer is disarmed after the read, and the count of missed timer expirations is reset to zero.

The timerfd is created with timerfd_create(2). The file descriptor flags of the timerfd can be modified using fcntl(2).

The flags argument to timerfd_settime must be either 0 or TFD_TIMER_ABSTIME.

RETURN VALUE

On success, timerfd_settime() and timerfd_gettime() return 0. On failure, they return -1, and errno is set to indicate the error.

ERRORS

The following errors can occur:

  • EBADF: fd is not a valid file descriptor.
  • EINVAL: flags contains an unrecognized value.
  • EINVAL: The specified time values in new_value or curr_value are invalid (e.g., negative seconds or nanoseconds greater than or equal to 1,000,000,000).
  • ENOTSUP: The specified clock is not supported.
  • UNKNOWN_ERRNO: Unknown error.

STANDARDS

Linux. Linux does not provide timerfd_settime() and timerfd_gettime() in glibc.

HISTORY

Linux 2.6.27.

NOTES

The timerfd file descriptor is created using timerfd_create(2). The flags argument for timerfd_settime can be either 0 or TFD_TIMER_ABSTIME. The TFD_TIMER_ABSTIME flag specifies that the it_value member of struct itimerspec specifies an absolute time. Otherwise, it specifies a relative time.

The struct itimerspec is defined as:

struct itimerspec {
    struct timespec it_interval;  // Timer interval
    struct timespec it_value;     // Initial expiration time
};

The times are relative to the clock specified when the timerfd was created (e.g., CLOCK_REALTIME or CLOCK_MONOTONIC).

The timer expiration is signaled by making read operations on the timerfd file descriptor return a non-zero value. The number of "ticks" (expirations) that have occurred is returned in the buffer provided to read(2). The value read is a uint64_t.

A timer set with an it_value of {0, 0} is disarmed. If the timer was armed, this causes it to be stopped. An interval of {0, 0} also disables the interval timer, causing the timer to expire just once.

Example:

    struct itimerspec new_value;
    int fd;

    // Create a timer that expires after 5 seconds, and then every 2 seconds
    new_value.it_value.tv_sec = 5;
    new_value.it_value.tv_nsec = 0;
    new_value.it_interval.tv_sec = 2;
    new_value.it_interval.tv_nsec = 0;

    fd = timerfd_create(CLOCK_MONOTONIC, 0);
    if (fd == -1) {
        perror("timerfd_create");
        exit(EXIT_FAILURE);
    }

    if (timerfd_settime(fd, 0, &new_value, NULL) == -1) {
        perror("timerfd_settime");
        exit(EXIT_FAILURE);
    }

    // ... read from fd ...

The timerfd_gettime() function retrieves the current time remaining until the next expiration and the interval period.

For absolute timers (TFD_TIMER_ABSTIME), the it_value member of the struct itimerspec represents the absolute expiration time. This value is measured from the clock's epoch.

When using timerfd_settime with TFD_TIMER_ABSTIME, the new_value.it_value should be an absolute time value. If you get the current time using clock_gettime(3), you can add your desired delay to it to create an absolute expiration time.

The number of timer expirations that have occurred since the last read(2) call is returned as a uint64_t value. The caller is responsible for reading this value. The timer is disarmed after the read, and the count of missed timer expirations is reset to zero.

The timerfd file descriptor is suitable for use with I/O event multiplexing system calls such as select(2), poll(2), and epoll(7).

A timer is disarmed when its it_value is set to {0, 0}.

The number of timer expirations that have occurred since the last read(2) is returned as a uint64_t value. The value read is the number of expirations.

The timerfd_settime() function is used to set the expiration time and interval for the timer associated with the timerfd file descriptor fd.

The timerfd_gettime() function retrieves the current settings of the timer associated with the timerfd file descriptor fd.

The flags argument can be used to specify options for timerfd_settime(). The only supported flag is TFD_TIMER_ABSTIME, which indicates that the it_value in new_value is an absolute time.

If old_value is not NULL, it is used to return the previous timer settings.

A timer is disarmed by setting its it_value to {0, 0}.

The timerfd file descriptor can be used with select(2), poll(2), and epoll(7) for I/O event notification.

BUGS

The timerfd_settime and timerfd_gettime functions are not part of POSIX or other standards. They are Linux-specific.

EXAMPLES

The following program demonstrates the use of timerfd_settime() and timerfd_gettime() to create a timer that expires after an initial delay and then at regular intervals.

    #include <sys/timerfd.h>
    #include <stdio.h>
    #include <stdlib.h>
    #include <unistd.h>
    #include <stdint.h>
    #include <time.h>
    #include <err.h>

    // Helper function to print elapsed time
    static void print_elapsed_time(void) {
        static struct timespec start;
        struct timespec       curr;
        long long             secs, nsecs;

        if (start.tv_sec == 0) {
            if (clock_gettime(CLOCK_REALTIME, &start) == -1)
                err(EXIT_FAILURE, "clock_gettime");
            return;
        }

        if (clock_gettime(CLOCK_REALTIME, &curr) == -1)
            err(EXIT_FAILURE, "clock_gettime");

        secs = curr.tv_sec - start.tv_sec;
        nsecs = curr.tv_nsec - start.tv_nsec;

        if (nsecs < 0) {
            secs--;
            nsecs += 1000000000;
        }

        printf("%lld.%03lld:\t", secs, (nsecs + 500000) / 1000000);
    }

    int
    main(int argc, char *argv[]) {
        int                fd;
        ssize_t            s;
        uint64_t           expir, tot_expir, max_expir;
        struct timespec    now;
        struct itimerspec  new_value;

        if (argc != 2 && argc != 4) {
            fprintf(stderr, "%s init-secs [interval-secs max-num-expir]\n",
                    argv[0]);
            exit(EXIT_FAILURE);
        }

        if (clock_gettime(CLOCK_REALTIME, &now) == -1)
            err(EXIT_FAILURE, "clock_gettime");

        /* Create a CLOCK_REALTIME absolute timer with initial
           expiration and interval as specified in command line.  */
        new_value.it_value.tv_sec = now.tv_sec + atoi(argv[1]);
        new_value.it_value.tv_nsec = now.tv_nsec;

        if (argc == 2) {
            new_value.it_interval.tv_sec = 0;
            max_expir = 1;
        } else {
            new_value.it_interval.tv_sec = atoi(argv[2]);
            max_expir = atoi(argv[3]);
        }
        new_value.it_interval.tv_nsec = 0;

        fd = timerfd_create(CLOCK_REALTIME, 0);
        if (fd == -1)
            err(EXIT_FAILURE, "timerfd_create");

        if (timerfd_settime(fd, TFD_TIMER_ABSTIME, &new_value, NULL) == -1)
            err(EXIT_FAILURE, "timerfd_settime");

        print_elapsed_time();
        printf("timer started\n");

        for (tot_expir = 0; tot_expir < max_expir;) {
            s = read(fd, &expir, sizeof(uint64_t));
            if (s != sizeof(uint64_t))
                err(EXIT_FAILURE, "read");

            tot_expir += expir;
            print_elapsed_time();
            printf("read: %" PRIu64 "; total=%" PRIu64 "\n",
                   expir, tot_expir);
        }

        exit(EXIT_SUCCESS);
    }
