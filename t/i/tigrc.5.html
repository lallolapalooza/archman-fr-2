NOM

tigrc - Fichier de configuration de Tig

SYNTAXE

set   variable = valeur
bind  keymap touche action
color zone fgcolor bgcolor [attributs]
source chemin

DESCRIPTION

Vous pouvez définir une option de manière permanente en la plaçant dans le fichier ~/.tigrc. Le fichier se compose d'une série de commandes. Chaque ligne du fichier ne peut contenir qu'une seule commande. Les commandes peuvent s'étendre sur plusieurs lignes si chaque ligne est terminée par un caractère barre oblique inversée (\).

Le symbole dièse (#) est utilisé comme caractère de commentaire. Tout texte après le caractère de commentaire jusqu'à la fin de la ligne est ignoré. Vous pouvez utiliser des commentaires pour annoter votre fichier d'initialisation.

Certaines options peuvent être manipulées à l'exécution via le menu des options. De plus, les options peuvent également être basculées avec la commande de prompt :toggle ou en entrant la commande de configuration dans le prompt.

Dans certains environnements, la configuration d'un utilisateur sera stockée à l'emplacement alternatif $XDG_CONFIG_HOME/tig/config. Par souci de concision, ce document ne fera référence qu'à ~/.tigrc.

CONFIGURATION GIT

En alternative à l'utilisation de ~/.tigrc, les options de Tig peuvent être définies en les plaçant dans l'un des fichiers de configuration Git, qui sont lus par Tig au démarrage. Voir git-config(1) pour les fichiers à utiliser. L'exemple suivant montre la syntaxe de base à utiliser pour les paramètres, les liaisons et les couleurs.

[tig] show-changes = true
[tig "color"] cursor = yellow red bold
[tig "bind"] generic = P parent

En plus des options spécifiques à tig, les options Git suivantes sont lues à partir de la configuration Git :

color.*

Couleurs pour les différents types d'interface utilisateur. Peut être configuré via le paramètre git-colors.

core.abbrev

La largeur de l'ID de commit. Voir également l'option id-width.

core.editor

La commande de l'éditeur. Peut être remplacée en définissant TIG_EDITOR ou GIT_EDITOR.

core.worktree

Le chemin vers la racine de l'arborescence de travail.

gui.encoding

L'encodage à utiliser pour l'affichage du contenu des fichiers.

i18n.commitencoding

L'encodage utilisé pour les commits. La valeur par défaut est UTF-8.

COMMANDE SET

Quelques variables sélectives peuvent être configurées via la commande set. La syntaxe est :

set variables = valeur

Exemples :

set commit-order = topo         # Ordonner les commits topologiquement
set git-colors = no             # Ne pas lire les paramètres de couleur de Git.
set horizontal-scroll = 33%     # Faire défiler de 33% de la largeur de la vue
set blame-options = -C -C -C    # Blâmer les lignes d'autres fichiers
# Encadrer les noms de branches avec () et les tags avec <>
set reference-format = (branch) <tag>
# Configurer les colonnes de la vue de blame en utilisant une commande s'étendant sur plusieurs lignes.
set blame-view = \
        date:default \
        author:abbreviated \
        committer:abbreviated \
        file-name:auto \
        id:yes,color \
        line-number:yes,interval=5 text

Ou dans les fichiers de configuration Git :

[tig]
        line-graphics = no      # Désactiver les caractères graphiques
        tab-size = 8            # Nombre d'espaces par tabulation

Le type des variables est soit booléen, entier, chaîne, soit mixte.

Valeurs booléennes valides

Pour définir une variable booléenne sur vrai, utilisez soit "1", "true", soit "yes". Toute autre valeur définira la variable sur faux.

Valeurs entières valides

Un entier non négatif.

Valeurs de chaînes valides

Une chaîne de caractères. Optionnellement, utilisez ' ou " comme délimiteurs.

Valeurs mixtes valides

Ces valeurs sont des composites des types ci-dessus. Les valeurs valides sont spécifiées dans la description.

Variables

Les variables suivantes peuvent être définies :

diff-options (chaîne)

Une chaîne d'options de diff séparées par des espaces à utiliser dans la vue de diff. git-show(1) est utilisé pour le formatage et passe toujours --patch-with-stat. Peut contrôler l'affichage des métadonnées de l'en-tête du commit, en passant l'option --format. Cette option remplace toutes les options spécifiées dans la variable d'environnement TIG_DIFF_OPTS (décrite dans tig(1)), mais est elle-même remplacée par les indicateurs de diff donnés lors de l'invocation de la ligne de commande.

blame-options (chaîne)

Une chaîne d'options de blame par défaut séparées par des espaces. Peut être utilisée pour indiquer à git-blame(1) comment détecter l'origine des lignes. Les options sont ignorées lorsque Tig est démarré en mode blame et que des options de blame sont fournies sur la ligne de commande.

log-options (chaîne)

Une chaîne d'options par défaut séparées par des espaces qui devraient être passées à la commande git-log(1) utilisée par la vue de log. Les options peuvent être remplacées par des options de ligne de commande. Utilisé en interne pour remplacer les paramètres personnalisés de ‘pretty.format’ qui cassent la vue de log.

main-options (chaîne)

Une chaîne d'options par défaut séparées par des espaces qui devraient être passées à la commande git-log(1) utilisée par la vue principale. Les options peuvent être remplacées par des options de ligne de commande.

reference-format (chaîne)

Une chaîne de chaînes de format séparées par des espaces utilisées pour formater les noms de références. Encadrez le nom du type de référence avec les caractères que vous souhaitez utiliser pour le formatage, par exemple [tag] et <remote>. Si aucun format n'est spécifié pour local-tag, le format pour tag est utilisé. De même, si aucun format n'est spécifié pour tracked-remote, le format pour remote est utilisé, et si aucun format n'est spécifié pour tout autre type de référence, le format pour branch est utilisé. Préfixez avec hide: pour ne pas afficher ce type de référence, par exemple hide:remote. Types de référence pris en charge :
•head : Le HEAD actuel.
•tag : Un tag annoté.
•local-tag : Un tag léger.
•remote : Un remote.
•tracked-remote : Le remote suivi par le HEAD actuel.
•replace : Une référence remplacée.
•branch : Une branche.
•stash : Le stash.
•note : Notes.
•prefetch : Références préfatchées par la maintenance git.
•other : Toute autre référence.

line-graphics (mixte) [ascii|default|utf-8|auto|<bool>]

Quel type de graphiques de caractères pour le dessin de lignes. "auto" signifie "utf-8" si la locale est UTF-8, "default" sinon.

truncation-delimiter (mixte) [utf-8|<chaîne>]

Un seul caractère à dessiner là où les colonnes sont tronquées. Le défaut est "~". La valeur spéciale "utf-8" fait référence au caractère "..." ("Elipse horizontale médiane").

horizontal-scroll (mixte)

Intervalle pour faire défiler horizontalement à chaque étape. Peut être spécifié soit comme le nombre de colonnes, par exemple 5, soit comme un pourcentage de la largeur de la vue, par exemple 33%, où le maximum est 100%. Pour les pourcentages, il est toujours garanti qu'au moins une colonne est déplacée. Le défaut est de faire défiler 50% de la largeur de la vue.

git-colors (liste)

Une liste de paires "clé=valeur" séparées par des espaces où la clé est un nom de couleur Git et la valeur est un nom de couleur Tig, par exemple "branch.current=main-head" et "grep.filename=grep.file". Défini sur "no" pour désactiver.

show-notes (mixte) [<référence>|<bool>]

Indique s'il faut afficher les notes pour un commit. Lorsqu'il est défini sur une référence de note, la référence est passée à git show --notes=. Les notes sont activées par défaut.

show-changes (bool)

Indique s'il faut afficher les modifications stagées et non stagées dans la vue principale.

show-untracked (bool)

Indique s'il faut afficher également les modifications non suivies dans la vue principale.

vertical-split (mixte) [auto|<bool>]

Indique s'il faut diviser la vue horizontalement ou ver
tiquement. "auto" (qui est la valeur par défaut) signifie que cela dépendra des dimensions de la fenêtre. Lorsqu'une orientation verticale réelle est utilisée, et false définit l'orientation sur horizontale.

split-view-height (mixte)

La hauteur de la vue inférieure dans un affichage divisé horizontalement. Peut être spécifiée soit par le nombre de lignes, par exemple 5, soit par un pourcentage de la hauteur de la vue, par exemple 80 %, où le maximum est de 100 %. Il est toujours garanti que la plus petite des vues a au moins quatre lignes de haut. La valeur par défaut est 67 %.

split-view-width (mixte)

Largeur de la vue la plus à droite dans un affichage divisé verticalement. Peut être spécifiée soit par le nombre de colonnes, par exemple 5, soit par un pourcentage de la largeur de la vue, par exemple 80 %, où le maximum est de 100 %. Il est toujours garanti que la plus petite des vues a au moins quatre colonnes de large. La valeur par défaut est 50 %.

status-show-untracked-dirs (bool)

Affiche le contenu des répertoires non suivis dans la vue d'état (similaire à l'option git ls-files --directory). Activé par défaut.

status-show-untracked-files (bool)

Affiche les fichiers non suivis dans la vue d'état (reflète l'option status.showUntrackedFiles de Git). Activé par défaut.

tab-size (int)

Nombre d'espaces par tabulation. La valeur par défaut est de 8 espaces.

diff-context (int)

Nombre de lignes de contexte à afficher pour les diffs.

word-diff (bool)

Affiche un diff mot par mot. Seul le mode simple est pris en charge. Désactivé par défaut.

diff-highlight (mixte)

Indique s'il faut mettre en surbrillance les diffs à l'aide du programme diff-highlight de Git. Par défaut à false. Lorsqu'il est défini sur true, diff-highlight est utilisé, sinon la valeur de l'option est utilisée comme chemin d'accès. Lorsque cette option est active, les régions mises en surbrillance sont régies par les couleurs diff-add-highlight et diff-del-highlight.

diff-indicator (bool)

Affiche des signes +/- dans la vue diff. Activé par défaut.

ignore-space (mixte) [no|all|some|at-eol|]

Ignore les changements d'espaces dans la vue diff. Par défaut, aucun changement d'espace n'est ignoré. Changer cela à "all", "some" ou "at-eol" équivaut à passer respectivement "--ignore-all-space", "--ignore-space" ou "--ignore-space-at-eol" à git diff ou git show.

Attention : lorsque ignore-space est défini sur some, all ou at-eol, les commandes status-update et status-revert peuvent échouer lors de la mise à jour ou de l'annulation de blocs contenant des lignes avec des changements d'espaces. De même, stage-update-line peut échouer lors de la mise à jour d'une ligne adjacente à une ligne avec des changements d'espaces.

commit-order (enum) [auto|default|topo|date|author-date|reverse]

Ordre des commits en utilisant l'ordre par défaut (chronologique inversé), l'ordre topologique, l'ordre chronologique ou l'ordre inversé. Lorsqu'il est défini sur "auto" (qui est la valeur par défaut), l'ordre topologique est automatiquement utilisé dans la vue principale lorsque le graphe de commits est activé. Dans les dépôts avec un long historique de commits, il est conseillé de définir cette option sur "default" pour accélérer le chargement de la vue principale.

ignore-case (enum) [no|yes|smart-case]

Ignore la casse dans les recherches. "smart-case" ignore la casse si la chaîne de recherche ne contient aucune lettre majuscule. Par défaut, la recherche est sensible à la casse.

mailmap (bool)

Lit les noms canoniques et les adresses e-mail des auteurs et des committeurs à partir de .mailmap. Désactivé par défaut. Voir git-shortlog(1).

wrap-lines (bool)

Retourne les lignes longues. Par défaut, les lignes ne sont pas retournées. Non compatible avec les numéros de ligne activés.

wrap-search (bool)

Retourne au début/à la fin de la vue lors de la recherche. Activé par défaut.

focus-child (bool)

Indique s'il faut focaliser la vue enfant lorsqu'elle est ouverte. Lorsqu'elle est désactivée, la focalisation reste sur la vue parente, évitant ainsi les rechargements de la vue enfant lors de la navigation dans la vue parente. Vrai par défaut.

send-child-enter (bool)

Indique s'il faut envoyer les appuis sur la touche "entrée" à la vue enfant, même si la vue parente est active. Lorsqu'elle est désactivée, la vue enfant doit être explicitement focalisée pour recevoir les appuis sur la touche "entrée". En pratique, cela n'est pertinent que lorsque focus-child = no est défini. Vrai par défaut.

editor-line-number (bool)

Indique s'il faut passer le numéro de ligne sélectionné à la commande de l'éditeur. Le numéro de ligne est passé sous la forme +<numéro-de-ligne> avant le nom du fichier. Exemple : vim +10 tig.c

history-size (int)

Taille du fichier persistant ~/.tig_history lorsque compilé avec le support readline. La valeur par défaut est 500. Définir à 0 pour désactiver.

mouse (bool)

Indique s'il faut activer la prise en charge de la souris. Désactivé par défaut car cela rend la sélection de texte dans le terminal moins intuitive. Lorsqu'elle est activée, maintenez la touche Maj (ou Option sur Mac) enfoncée pour sélectionner du texte. La prise en charge de la souris nécessite que ncurses lui-même prenne en charge les événements de souris.

mouse-scroll (int)

Intervalle pour faire défiler vers le haut ou vers le bas à l'aide de la souris. La valeur par défaut est de 3 lignes. La prise en charge de la souris nécessite que ncurses lui-même prenne en charge les événements de souris et que vous ayez activé la prise en charge de la souris dans ~/.tigrc avec set mouse = true.

mouse-wheel-cursor (bool)

Indique s'il faut préférer déplacer le curseur plutôt que de faire défiler la vue lors de l'utilisation de la molette de la souris. Désactivé par défaut. Se combine bien avec set mouse-scroll = 1. La prise en charge de la souris nécessite que ncurses lui-même prenne en charge les événements de souris et que vous ayez activé la prise en charge de la souris dans ~/.tigrc avec set mouse = true.

pager-autoscroll (bool)

Indique s'il faut faire défiler automatiquement la vue du pagineur pendant le chargement. Déplacez le curseur hors de la dernière ligne pour arrêter le défilement et revenez-y pour reprendre.

pgrp (bool)

Fait de tig le leader du groupe de processus lors du démarrage et nettoie tous les processus lors de la sortie. Désactivé par défaut. N'activez pas cette option si vous utilisez une version de Zsh affectée par zsh-workers/43379. Exécutez xclip avec setsid pour conserver le contenu du presse-papiers après la sortie de tig. Si vous utilisez l'assistant git-credential-cache, définissez l'option credentialCache.ignoreSIGHUP.

start-on-head (bool)

Démarre avec le curseur sur le commit HEAD.

refresh-mode (mixte) [manual|auto|after-command|periodic|]

Configure comment les vues sont rafraîchies en fonction des modifications des fichiers surveillés dans le dépôt. Lorsqu'il est défini sur manual, rien n'est rafraîchi automatiquement. Lorsqu'il est défini sur auto, les vues sont rafraîchies lorsqu'une modification est détectée dans une autre vue. Lorsqu'il est défini sur after-command, seul un rafraîchissement a lieu après le retour d'une commande externe. Lorsqu'il est défini sur periodic, les vues visibles sont rafraîchies périodiquement en utilisant refresh-interval.

refresh-interval (int)

Intervalle en secondes entre les vérifications de mise à jour du rafraîchissement des vues lorsque refresh-mode est défini sur periodic.

file-args (args)

Arguments de ligne de commande faisant référence à des fichiers. Ceux-ci sont filtrés à l'aide de git-rev-parse(1).

rev-args (args)

Arguments de ligne de commande faisant référence à des révisions. Ceux-ci sont filtrés à l'aide de git-rev-parse(1).

Paramètres de vue

Les paramètres de vue définissent l'ordre et les options pour les différentes colonnes d'une vue. Chaque paramètre de vue attend une liste d' specificheurs de colonnes séparés par des espaces. Les specificheurs de colonnes commencent par le type de colonne et peuvent éventuellement être suivis d'un deux-points (:) et d'une liste d'options de colonne. Par exemple, la spécification de colonne suivante définit une colonne author affichant l'e-mail de l'auteur et avec une largeur fixe de 20 caractères : author:email,width=20.

La première valeur d'option dans une spécification de colonne est toujours l'option display. Lorsqu'aucune valeur display n'est donnée, yes est supposé. Pour les options display attendant une valeur énumérée, cela se résoudra automatiquement à la valeur énumérée par défaut. Par exemple, file-name résoudra automatiquement son paramètre display à auto.

Des specificheurs peuvent également être donnés pour une seule colonne, par exemple pour remplacer les valeurs par défaut dans le fichier tigrc système. Pour remplacer une seule colonne, utilisez le nom de la colonne comme suffixe après le nom du paramètre de vue, par exemple main-view-date permettra de définir la date dans la vue principale.

Exemples :

# Activer les ID et les numéros de ligne dans la vue blame
set blame-view = date:default author:full committer:no file-name:auto \
                 id:yes,color line-number:yes,interval=5 text
# Modifier la vue grep pour qu'elle ressemble au format `git grep`
set grep-view = file-name:yes line-number:yes,interval=1 text
# Afficher les tailles de fichiers en unités
set tree-view = line-number:no,interval=5 mode author:full committer:no \
                file-size:units date:default id:no file-name
# Afficher les numéros de ligne pour chaque 10ème ligne dans la vue pager
set pager-view = line-number:yes,interval=10 text
# Raccourcis pour modifier les paramètres de vue pour une colonne définie précédemment
set main-view-date = custom
set main-view-date-format = "%Y-%m-%d %H:%M"
set blame-view-line-number = no
# Utiliser l'ordre des commits par défaut de Git, même lorsque le graphe des commits est activé.
set commit-order = default

La liste suivante montre les paramètres de vue disponibles et les types de colonnes qu'ils prennent en charge :

blob-view, diff-view, log-view, pager-view, stage-view

line-number, text

blame-view

author, committer, date, file-name, id, line-number, text

grep-view

file-name, line-number, text

main-view, reflog-view

author, committer, date, commit-title, id, line-number, ref

refs-view

author, committer, date, commit-title, id, line-number, ref

stash-view

author, date, commit-title, id, line-number

status-view

file-name, line-number, status

tree-view

author, committer, date, id, file-name, file-size, line-number, mode

Types de colonnes pris en charge et leurs options de colonne respectives :

author, committer

•display (mixte) [full|abbreviated|email|email-user|] : Comment afficher les noms d'auteur/commiteur. Si défini sur "abbreviated", les initiales de l'auteur/commiteur seront affichées.
•width (int) : Largeur fixe pour la colonne. Lorsqu'elle est définie sur une valeur comprise entre 1 et 10, le nom de l'auteur/commiteur sera abrégé aux initiales de l'auteur/commiteur. Lorsqu'elle est définie sur zéro, le dimension est automatiquement ajustée pour s'adapter au contenu.
•maxwidth (int) : Largeur maximale de la colonne. Permet d'ajuster automatiquement le contenu, jusqu'à cette limite. Peut être spécifié soit comme un nombre de colonnes, par exemple 15, soit comme un pourcentage de la largeur de vue, par exemple 20%, où le maximum est 100%.

commit-title

•graph (mixed) [no|v2|v1] : Indique s'il faut afficher le graphique de révision dans la vue principale au démarrage. « v1 » fait référence au rendu graphique précédent, qui est moins précis mais plus rapide et donc recommandé dans les grands dépôts. Voir aussi les options line-graphics.
•refs (bool) : Indique s'il faut afficher les références (branches, tags et remotes) dans la vue principale. Peut être activé/désactivé.
•overflow (bool ou int) : Indique s'il faut mettre en surbrillance le texte des titres de commit dépassant une largeur donnée. Lorsqu'il est défini sur une valeur booléenne, il active ou désactive la mise en surbrillance en utilisant la largeur par défaut de 50 caractères. Lorsqu'il est défini sur un entier, la valeur attribuée est utilisée comme largeur maximale de caractères.

date

•display (mixed) [relative|relative-compact|custom|default|<bool>] : Mode d'affichage des dates. Si défini sur « relative » ou « relative-compact », une date relative sera utilisée, par exemple « il y a 2 minutes » ou « 2m ». Si défini sur « custom », le format de chaîne strftime(3) spécifié dans l'option « format » est utilisé.
•use-author (bool) : Indique s'il faut afficher la date de l'auteur au lieu de la date du committer.
•local (bool) : Si vrai, utilise localtime(3) pour convertir en fuseau horaire local. Notez que les dates relatives utilisent toujours les décalages locaux.
•format (string) : Chaîne de format à passer à strftime(3) lorsque le mode d'affichage custom a été sélectionné.
•width (int) : Largeur fixe pour la colonne. Lorsqu'elle est définie sur zéro, la largeur est automatiquement ajustée pour s'adapter au contenu.

file-name

•display (mixed) [auto|always|<bool>] : Moment où afficher les noms de fichiers. Si défini sur « auto », les noms de fichiers sont affichés uniquement lorsque nécessaire, par exemple lors de l'exécution de : tig blame -C <fichier>.
•width (int) : Largeur de la colonne. Lorsqu'elle est définie sur zéro, la largeur est automatiquement ajustée pour s'adapter au contenu.
•maxwidth (int) : Largeur maximale de la colonne. Permet d'ajuster automatiquement le contenu, jusqu'à cette limite. Peut être spécifié soit comme un nombre de colonnes, par exemple 15, soit comme un pourcentage de la largeur de vue, par exemple 20%, où le maximum est 100%.

file-size

•display (mixed) [default|units|<bool>] : Mode d'affichage des tailles de fichiers. Lorsqu'il est défini sur « units », les tailles sont affichées en utilisant des préfixes binaires, par exemple 12524 octets sont affichés comme « 12.2K ».
•width (int) : Largeur fixe pour la colonne du nom de fichier. Lorsqu'elle est définie sur zéro, la largeur est automatiquement ajustée pour s'adapter au contenu.

id

•display (bool) : Indique s'il faut afficher les identifiants de commit dans la vue principale.
•width (int) : Largeur fixe pour la colonne de l'identifiant de commit. Lorsqu'elle n'est pas définie, Tig utilisera la valeur de core.abbrev si elle est trouvée. Voir git-config(1) pour savoir comment définir core.abbrev. Lorsqu'elle est définie sur zéro, la largeur est automatiquement ajustée pour s'adapter au contenu des identifiants de reflog (par exemple, ref/stash@{4}) et sinon par défaut à 7.

line-number

•display (bool) : Indique s'il faut afficher les numéros de ligne.
•interval (int) : Intervalle entre les numéros de ligne.
•width (int) : Largeur fixe pour la colonne. Lorsqu'elle est définie sur zéro, la largeur est automatiquement ajustée pour s'adapter au contenu.

mode

•display (bool) : Indique s'il faut afficher les modes de fichier.
•width (int) : Largeur fixe pour la colonne. Lorsqu'elle est définie sur zéro, la largeur est automatiquement ajustée pour s'adapter au contenu.

ref

•display (bool) : Indique s'il faut afficher le nom de la référence.
•width (int) : Largeur fixe pour la colonne. Lorsqu'elle est définie sur zéro, la largeur est automatiquement ajustée pour s'adapter au contenu.
•maxwidth (int) : Largeur maximale de la colonne. Permet d'ajuster automatiquement le contenu, jusqu'à cette limite. Peut être spécifié soit comme un nombre de colonnes, par exemple 15, soit comme un pourcentage de la largeur de vue, par exemple 20%, où le maximum est 100%.

status

•display (mixed) [no|short|long|<bool>] : Mode d'affichage du libellé de statut.

text

•commit-title-overflow (bool ou int) : Indique s'il faut mettre en surbrillance les titres de commit dépassant une largeur donnée dans la vue de diff. Lorsqu'il est défini sur une valeur booléenne, il active ou désactive la mise en surbrillance en utilisant la largeur par défaut de 50 caractères. Lorsqu'il est défini sur un entier, la valeur attribuée est utilisée comme largeur maximale de caractères.

Toutes les options de colonne peuvent être activées/désactivées. Pour les options d'affichage, utilisez le nom de l'option comme préfixe suivi d'un tiret et du nom de la colonne. Par exemple, :toggle author-display activera/désactivera l'option display dans la colonne author. Pour toutes les autres options, utilisez le nom de la colonne suivi d'un tiret, puis le nom de l'option comme suffixe. Par exemple, :toggle commit-title-graph activera/désactivera l'option graph dans la colonne commit-title. Alternativement, utilisez le menu des options pour manipuler les options.

BIND COMMAND

En utilisant les commandes bind, les touches peuvent être mappées à une action lorsqu'elles sont pressées dans une configuration de touches donnée. La syntaxe est :

bind keymap key action

Exemples :

# Ajouter une liaison de touche pour sauter rapidement au prochain bloc de diff dans la vue de staging
bind stage <Enter> :/^@@
# Désactiver la liaison par défaut pour l'exécution de git-gc
bind generic G none
# Commande externe définie par l'utilisateur pour modifier le dernier commit
bind status + !git commit --amend
# Commande interne définie par l'utilisateur qui recharge ~/.tigrc
bind generic S :source ~/.tigrc
# Les caractères encodés en UTF8 peuvent être utilisés comme valeurs de touches.
bind generic ø @sh -c "printf '%s' %(commit) | pbcopy"

Ou dans les fichiers de configuration Git :

[tig "bind"]
        # 'Délier' la liaison de touche par défaut pour quitter
        generic = Q none
        # Cherrier-picker le commit actuel sur la branche actuelle
        main = C !git cherry-pick %(commit)

Les touches sont mappées en recherchant d'abord les liaisons de touches pour la vue actuelle, puis les liaisons de touches pour la configuration generic, et enfin les liaisons de touches intégrées. Ainsi, les liaisons de touches de la vue remplacent les liaisons de touches génériques qui remplacent les liaisons de touches intégrées.

Délier une liaison de touche (unbind) de toutes les configurations de touches en une seule fois avec bind generic key none.

Les liaisons de touches à l'invite de saisie de ligne sont généralement régies par la bibliothèque readline et sont configurées séparément dans ~/.inputrc. Voir readline(1). Tig respecte mais n'exige pas une section $if tig dans ~/.inputrc.

Keymaps

Les keymaps valides sont : main, diff, log, reflog, help, pager, status, stage, tree, blob, blame, refs, stash, grep et generic. Utilisez generic pour définir une liaison de touche dans toutes les keymaps (qui peuvent toujours être remplacées par une liaison de touche de vue spécifique). Utilisez search pour définir les touches permettant de naviguer dans les résultats de recherche pendant la recherche.

Valeurs des touches

Les valeurs des touches ne doivent jamais être mises entre guillemets. Utilisez soit un caractère codé en ASCII ou UTF8, soit l'un des noms de touches symboliques suivants. Les noms de touches symboliques ne sont pas sensibles à la casse et commencent par « < » et se terminent par « > ». Utilisez <Hash> pour lier à la touche #, car le symbole dièse est utilisé comme caractère de commentaire. Utilisez <LessThan> pour lier à la touche <.

<Enter>, <Space>, <Backspace>, <Tab>, <Escape> ou <Esc>, <Left>, <Right>, <Up>, <Down>, <Insert> ou <Ins>, <Delete> ou <Del>, <Hash>, <LessThan> ou <LT>, <Home>, <End>, <PageUp> ou <PgUp>, <PageDown> ou <PgDown>, <ScrollBack> ou <SBack>, <ScrollFwd> ou <SFwd>, <ShiftTab> ou <BackTab>, <ShiftLeft>, <ShiftRight>, <ShiftDelete> ou <ShiftDel>, <ShiftHome>, <ShiftEnd>, <SingleQuote>, <DoubleQuote>, <F1> ... <F19>

Pour définir des liaisons de touches avec la touche Ctrl, utilisez <Ctrl-key>. De plus, les combinaisons de touches constituées d'une touche Escape initiale suivie d'une valeur de touche normale peuvent être liées en utilisant <Esc>key.

Exemples :

bind main R             refresh
bind main <Down>        next
bind main <Ctrl-f>      scroll-page-down
bind main <Esc>o        options
bind main <ShiftTab>    parent

Notes

•Tig lit les frappes au clavier via ncurses et est soumis à diverses limitations. Voir ncurses(3x) et terminfo(5) (ou termcap).
•Ctrl-m et Ctrl-i ne peuvent pas être liés car ils entrent en conflit avec Enter et Tab respectivement.
•Les différences de casse ne peuvent pas être distinguées dans les séquences de contrôle telles que Ctrl-f et Ctrl-F.
•Ctrl-<Space> est généralement traduit en Ctrl-@, qui est disponible pour la liaison.
•Seul un sous-ensemble de touches symboliques spéciales telles que <ShiftTab> sera disponible dans un émulateur de terminal donné.
•Ctrl-z est automatiquement utilisé pour le contrôle de processus et suspendra Tig et ouvrira un sous-shell (utilisez fg pour rentrer dans Tig).

Actions

Les actions sont soit spécifiées comme des commandes définies par l'utilisateur (externes ou internes), soit en utilisant des noms d'action tels que décrits dans les sections suivantes.

Commande externes définies par l'utilisateur

Ces

EXTERNAL COMMANDS

Les actions commencent par un ou plusieurs des indicateurs d'option suivants, suivis de la commande à exécuter.

! Exécute la commande au premier plan avec l'affichage de la sortie.
@ Exécute la commande en arrière-plan sans sortie.
+ Exécute la commande de manière synchrone et affiche la première ligne de sortie dans la barre d'état.
? Demande à l'utilisateur avant d'exécuter la commande.
< Quitte Tig après avoir exécuté la commande.
> Rouvre Tig instantanément dans la dernière vue affichée après avoir exécuté la commande.

Sauf indication contraire, les commandes sont exécutées au premier plan avec leur sortie console affichée (comme si ! était spécifié). Lorsque plusieurs options de commande sont spécifiées, leur comportement est combiné, par exemple "?<git commit" demandera à l'utilisateur s'il souhaite exécuter la commande et quittera Tig une fois l'opération terminée.

Notez que si vous souhaitez utiliser des pipes ou une redirection dans vos commandes, vous devez les exécuter dans un sous-shell, c'est-à-dire intégrer vos commandes dans `sh -c '<commandes>'`.

Parcours des variables d'état

Les commandes définies par l'utilisateur peuvent éventuellement faire référence à l'état interne de Tig à l'aide des noms de variables suivants, qui sont substitués avant l'exécution des commandes :

%(head) L'identifiant de head actuellement affiché. Par défaut HEAD
%(commit) L'identifiant de commit actuellement sélectionné.
%(blob) L'identifiant de blob actuellement sélectionné.
%(branch) Le nom de la branche actuellement sélectionnée.
%(remote) Le nom du dépôt distant actuellement sélectionné. Pour les branches distantes, %(branch) contiendra le nom de la branche.
%(tag) Le nom du tag actuellement sélectionné.
%(refname) Le nom de référence actuellement sélectionné, y compris le nom du dépôt distant pour les branches distantes.
%(stash) Le nom du stash actuellement sélectionné.
%(directory) Le chemin du répertoire actuel dans la vue arbre ou "." s'il n'est pas défini.
%(file) Le fichier actuellement sélectionné.
%(file_old) L'ancien nom du fichier actuellement sélectionné.
%(lineno) Le numéro de ligne actuellement sélectionné. Par défaut 0.
%(lineno_old) Le numéro de ligne actuellement sélectionné, avant l'application du diff. Par défaut 0.
%(ref) La référence donnée à blame ou HEAD si non définie.
%(revargs) Les arguments de révision passés sur la ligne de commande.
%(fileargs) Les arguments de fichier passés sur la ligne de commande.
%(cmdlineargs) Toutes les autres options passées sur la ligne de commande.
%(diffargs) Options provenant de diff-options ou TIG_DIFF_OPTS utilisées par la vue diff et stage.
%(blameargs) Options provenant de blame-options utilisées par la vue blame.
%(logargs) Options provenant de log-options utilisées par la vue log.
%(mainargs) Options provenant de main-options utilisées par la vue principale.
%(prompt) Demande la valeur de l'argument. Vous pouvez facultativement spécifier une invite personnalisée en utilisant "%(prompt Entrez le nom de la branche : )"
%(text) La colonne de texte de la ligne actuellement sélectionnée.
%(repo:head) Le nom de la branche vérifiée, par exemple master
%(repo:head-id) L'identifiant de commit de la branche vérifiée.
%(repo:remote) Le nom du dépôt distant associé à la branche vérifiée, par exemple origin.
%(repo:upstream) La branche amont associée à la branche vérifiée, par exemple origin/master.
%(repo:cdup) Le chemin pour changer de répertoire vers la racine du dépôt, par exemple ../
%(repo:prefix) Le préfixe de chemin du répertoire de travail actuel, par exemple subdir/.
%(repo:git-dir) Le chemin du répertoire Git, par exemple /src/repo/.git.
%(repo:worktree) Le chemin du répertoire de travail, s'il est défini.
%(repo:is-inside-work-tree) Indique si Tig s'exécute dans un répertoire de travail, vrai ou faux.

Exemples:

# Sauvegarde le commit actuel dans un fichier patch lorsque l'utilisateur sélectionne un commit
# dans la vue principale et appuie sur 'S'.
bind main S !git format-patch -1 %(commit)
# Crée et vérifie une nouvelle branche ; spécifie une invite personnalisée
bind main B ?git checkout -b "%(prompt Entrez le nom de la nouvelle branche : )"
# Affiche les statistiques du commit pour l'auteur sous le curseur
bind main U +sh -c 'git --no-pager shortlog -s --author="$(git show -s --format=%aE %(commit))" </dev/tty'

Commandes avancées de type shell

Si votre commande nécessite l'utilisation de fonctionnalités dynamiques, telles que des sous-shells, l'expansion de variables d'environnement et le contrôle de processus, cela peut être réalisé en utilisant une commande shell :

Exemple 1. Configuration d'une liaison pour copier l'identifiant de commit actuel dans le presse-papiers.

bind generic I @sh -c "echo -n %(commit) | xclip -selection c"

Ou en utilisant une combinaison d'alias Git et de commandes externes Tig. Les exemples d'entrées suivants peuvent être placés dans le fichier .gitconfig ou .git/config :

Exemple 2. Configuration Git qui lie les clés Tig aux alias de commande Git.

[alias]
        gitk-bg = !"gitk HEAD --not $(git rev-parse --remotes) &"
        publish = !"for i in origin public; do git push $i; done"
[tig "bind"]
        generic = V @git gitk-bg
        generic = > !git publish

Commandes internes définies par l'utilisateur

Les actions commençant par : seront exécutées et interprétées comme des commandes internes et agiront de manière similaire aux commandes exécutées via l'invite de Tig. Les commandes internes valides sont les options du fichier de configuration (telles que décrites dans ce document) et les commandes de vue de pagination. Exemples :

# Recharge le fichier ~/.tigrc lorsque 'S' est pressé
bind generic S :source .tigrc
# Change la vue diff pour afficher toutes les modifications de commit indépendamment des limitations de fichier
bind diff F :set diff-options = --full-diff
# Affiche la sortie de git-reflog(1) dans la vue de pagination
bind generic W :!git reflog
# Recherche le chunk de diff précédent (c) et le prochain en-tête de diff
bind stage 2 :?^@@
bind stage D :/^diff --(git|cc)
bind main I :toggle id                          # Affiche/masque la colonne ID
bind diff D :toggle diff-options --minimal      # Utilise l'algorithme de diff minimal
bind diff [ :toggle diff-context -3             # Diminue le contexte (-U arg)
bind diff ] :toggle diff-context +3             # Augmente le contexte
bind generic V :toggle split-view-height -10%   # Diminue la hauteur de la vue divisée

Semblable aux commandes externes, les commandes de vue de pagination peuvent contenir des noms de variables qui seront substitués avant l'exécution de la commande.

COLOR COMMAND

Les commandes de couleur contrôlent la mise en surbrillance et les styles de l'interface utilisateur. Si votre terminal prend en charge la couleur, ces commandes peuvent être utilisées pour attribuer des combinaisons de premier plan et d'arrière-plan à certaines zones. Facultativement, un attribut peut être donné comme dernier paramètre. La syntaxe est :

color zone couleur-premier-plan couleur-arriere-plan [attributs]

Exemples :

# Remplacer les couleurs par défaut du terminal par blanc sur noir.
color default           white   black
# Couleurs de diff
color diff-header       yellow  default
color diff-index        blue    default
color diff-chunk        magenta default
color "Reported-by:"    green   default
# Couleur spécifique à la vue
color tree.date         black   cyan    bold
# Couleur personnalisée
color "/(note|warning|error):/" yellow  default bold

Ou dans les fichiers de configuration Git :

[tig "color"]
        # Une ligne de curseur à l'apparence étrange
        cursor          = red   default underline
        # Couleurs de l'interface utilisateur
        title-blur      = white blue
        title-focus     = white blue    bold
# Couleur spécifique à la vue
[tig "color.tree"]
        date            = cyan  default bold

Noms de zones

Peut être soit un nom de zone intégré, soit une chaîne personnalisée entre guillemets. Cette dernière permet d'ajouter des règles de couleur personnalisées pour les lignes correspondant à une chaîne entre guillemets. Les chaînes de la forme "/.../" sont interprétées comme des expressions régulières. Les noms de zones intégrés valides sont décrits ci-dessous. Notez que tous les noms ne sont pas sensibles à la casse, et vous pouvez utiliser - et _ de manière interchangeable, par exemple, "Diff-Header" et "DIFF_HEADER" sont les mêmes. Les couleurs spécifiques à la vue peuvent être définies en préfixant le nom de la vue au nom de la zone, par exemple "stage.diff-chunk" et "diff.diff-chunk".

Noms de couleurs

Les couleurs valides incluent : white, black, green, magenta, blue, cyan, yellow, red, default. Utilisez default pour faire référence aux couleurs par défaut du terminal, par exemple, pour garder l'arrière-plan transparent lorsque vous utilisez un terminal avec un arrière-plan transparent.

Les couleurs peuvent également être spécifiées en utilisant les mots-clés color0, color1, ..., colorN-1 (où N est le nombre de couleurs supportées par votre terminal). Ceci est utile lorsque vous remappez les couleurs pour votre affichage ou que vous voulez activer les couleurs supportées par les terminaux 88 couleurs et 256 couleurs. Notez que le préfixe color est facultatif. Si vous préférez, vous pouvez spécifier directement les couleurs par leurs numéros 0, 1, ..., N-1, tout comme dans le fichier de configuration de Git.

Noms d'attributs

Les attributs valides incluent : normal, blink, bold, dim, reverse, standout, et underline. Notez que tous les attributs ne peuvent pas être pris en charge par le terminal.

COMMANDE SOURCE

Les commandes source permettent de lire des fichiers de configuration supplémentaires. Les fichiers sourcés sont inclus en place, ce qui signifie qu'une commande source rencontrée lit immédiatement le fichier. Toutes les commandes ultérieures dans le fichier de configuration actuel auront la priorité.

Si le chemin donné n'existe pas, tig poursuivra avec un avertissement. Donnez le paramètre -q pour supprimer l'avertissement.

La syntaxe est :

source [-q] chemin

Exemples :

source ~/.tig/colorscheme.tigrc
source ~/.tig/keybindings.tigrc
