TIMEDATECTL(1) timedatectl TIMEDATECTL(1)

NOM

timedatectl - Contrôler l'heure et la date du système

SYNTAXE

timedatectl [OPTIONS...] {COMMANDE}

DESCRIPTION

timedatectl peut être utilisé pour interroger et modifier l'horloge système et ses paramètres, ainsi que pour activer ou désactiver les services de synchronisation horaire.

Utilisez systemd-firstboot(1) pour initialiser le fuseau horaire du système pour les images système montées (mais non démarrées).

timedatectl peut être utilisé pour afficher l'état actuel des services de synchronisation horaire, par exemple systemd-timesyncd.service(8).

COMMANDES

Les commandes suivantes sont comprises :

status

Affiche les paramètres actuels de l'horloge système et de l'horloge temps réel (RTC), y compris si la synchronisation horaire réseau est active. Si aucune commande n'est spécifiée, c'est celle par défaut.

Ajouté dans la version 195.

show

Affiche les mêmes informations que status, mais sous une forme lisible par machine. Cette commande est destinée à être utilisée lorsque des sorties analysables par ordinateur sont requises. Utilisez status si vous recherchez une sortie formatée lisible par l'homme.

Par défaut, les propriétés vides sont supprimées. Utilisez --all pour les afficher également. Pour sélectionner des propriétés spécifiques à afficher, utilisez --property=.

Ajouté dans la version 239.

set-time [TIME]

Définit l'horloge système sur l'horodatage spécifié. Ceci mettra également à jour l'heure de l'horloge temps réel en conséquence. L'horodatage peut être spécifié au format "2012-10-30 18:17:16". Voir systemd.time(7) pour plus de détails sur le format d'horodatage acceptable.

Ajouté dans la version 195.

set-timezone [TIMEZONE]

Définit le fuseau horaire du système à la valeur spécifiée. Les fuseaux horaires disponibles peuvent être listés avec list-timezones. Si l'horloge temps réel est configurée pour être en heure locale, cela mettra également à jour l'heure de l'horloge temps réel. Cet appel modifiera le lien symbolique /etc/localtime. Voir localtime(5) pour plus d'informations.

Ajouté dans la version 195.

list-timezones

Liste les fuseaux horaires disponibles, un par ligne. Les entrées de la liste peuvent être définies comme fuseau horaire du système avec set-timezone.

Ajouté dans la version 195.

set-local-rtc [BOOL]

Prend un argument booléen. Si "0", le système est configuré pour maintenir l'horloge temps réel en temps universel. Si "1", elle maintiendra l'horloge temps réel en heure locale à la place. Notez que le maintien de l'horloge temps réel dans le fuseau horaire local n'est pas entièrement pris en charge et créera divers problèmes avec les changements de fuseau horaire et les ajustements d'heure d'été. Dans la mesure du possible, conservez l'horloge temps réel en mode UTC. Notez que l'invocation de ceci synchronisera également l'horloge temps réel à partir de l'horloge système, à moins que --adjust-system-clock ne soit passé (voir ci-dessus). Cette commande modifiera la 3ème ligne de /etc/adjtime, comme documenté dans hwclock(8).

Ajouté dans la version 195.

set-ntp [BOOL]

Prend un argument booléen. Contrôle si la synchronisation horaire réseau est active et activée (si disponible). Si l'argument est vrai, cela active et démarre le premier service de synchronisation réseau existant. Si l'argument est faux, cela désactive et arrête les services de synchronisation réseau connus. La manière dont la liste des services est construite est décrite dans systemd-timedated.service(8).

Ajouté dans la version 195.

commandes systemd-timesyncd

Les commandes suivantes sont spécifiques à systemd-timesyncd.service(8).

timesync-status

Affiche l'état actuel de systemd-timesyncd.service(8). Si --monitor est spécifié, alors cela surveillera les mises à jour de statut.

Ajouté dans la version 239.

show-timesync

Affiche les mêmes informations que timesync-status, mais sous forme lisible par machine. Cette commande est destinée à être utilisée lorsque des sorties analysables par ordinateur sont requises. Utilisez timesync-status si vous recherchez une sortie formatée lisible par l'homme.

Par défaut, les propriétés vides sont supprimées. Utilisez --all pour les afficher également. Pour sélectionner des propriétés spécifiques à afficher, utilisez --property=.

Ajouté dans la version 239.

ntp-servers INTERFACE SERVER...

Définit les serveurs NTP spécifiques à l'interface. Cette commande peut être utilisée uniquement lorsque l'interface est gérée par systemd-networkd.

Ajouté dans la version 243.

revert INTERFACE

Rétablit les serveurs NTP spécifiques à l'interface. Cette commande peut être utilisée uniquement lorsque l'interface est gérée par systemd-networkd.

Ajouté dans la version 243.

OPTIONS

Les options suivantes sont comprises :

--adjust-system-clock

Si set-local-rtc est invoqué et que cette option est passée, l'horloge système est à nouveau synchronisée à partir de l'horloge temps réel, en tenant compte du nouveau paramètre. Sinon, l'horloge temps réel est synchronisée à partir de l'horloge système.

Ajouté dans la version 195.

--monitor

Si timesync-status est invoqué et que cette option est passée, alors timedatectl surveille l'état de systemd-timesyncd.service(8) et met à jour les sorties. Utilisez Ctrl+C pour terminer la surveillance.

Ajouté dans la version 239.

-a, --all

Lors de l'affichage des propriétés de systemd-timesyncd.service(8), affiche toutes les propriétés, qu'elles soient définies ou non.

Ajouté dans la version 239.

-p, --property=

Lors de l'affichage des propriétés de systemd-timesyncd.service(8), limite l'affichage à certaines propriétés telles que spécifiées dans l'argument. Si non spécifié, toutes les propriétés définies sont affichées. L'argument doit être un nom de propriété, tel que "ServerName". Si spécifié plusieurs fois, toutes les propriétés avec les noms spécifiés sont affichées.

Ajouté dans la version 239.

--value

Lors de l'affichage des propriétés avec show-timesync, affiche uniquement la valeur, et saute le nom de la propriété et "=".

Ajouté dans la version 239.

-P

Équivalent à --value --property=, c'est-à-dire affiche la valeur de la propriété sans le nom de la propriété ni le "=". Notez que l'utilisation de -P une seule fois affectera également toutes les propriétés listées avec -p/--property=.

Ajouté dans la version 256.

-H, --host=

Exécute l'opération à distance. Spécifiez un nom d'hôte, ou un nom d'utilisateur et un nom d'hôte séparés par "@", pour vous connecter. Le nom d'hôte peut éventuellement être suivi d'un port sur lequel ssh écoute, séparé par ":", puis d'un nom de conteneur, séparé par "/", ce qui se connecte directement à un conteneur spécifique sur la machine distante. Ceci utilisera SSH pour communiquer avec l'instance du gestionnaire de machine distante. Les noms de conteneurs peuvent être énumérés avec machinectl -H HOST. Placez les adresses IPv6 entre crochets.

-M, --machine=

Exécute l'opération sur un conteneur local. Spécifiez un nom de conteneur auquel se connecter, éventuellement précédé d'un nom d'utilisateur pour se connecter et d'un caractère "@" séparateur. Si la chaîne spéciale ".host" est utilisée à la place du nom du conteneur, une connexion au système local est établie (ce qui est utile pour se connecter au bus utilisateur d'un utilisateur spécifique : "--user --machine=lennart@.host"). Si la syntaxe "@" n'est pas utilisée, la connexion est établie en tant qu'utilisateur root. Si la syntaxe "@" est utilisée, soit la partie gauche, soit la partie droite peut être omise (mais pas les deux) auquel cas le nom d'utilisateur local et ".host" sont
implied.

--no-ask-password

Ne pas interroger l'utilisateur pour l'authentification lors d'opérations privilégiées.

-h, --help

Afficher un court texte d'aide et quitter.

--version

Afficher une courte chaîne de version et quitter.

--no-pager

Ne pas rediriger la sortie vers un paginator.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.

ENVIRONNEMENT

$SYSTEMD_LOG_LEVEL

Le niveau de journalisation maximal des messages émis (les messages d'un niveau de journalisation supérieur, c'est-à-dire moins importants, seront supprimés). Accepte une liste de valeurs séparées par des virgules. Une valeur peut être soit l'une des suivantes (par ordre d'importance décroissante) : emerg, alert, crit, err, warning, notice, info, debug, soit un entier compris entre 0 et 7. Voir syslog(3) pour plus d'informations. Chaque valeur peut éventuellement être précédée de console, syslog, kmsg ou journal suivi d'un deux-points pour définir le niveau de journalisation maximal pour cette cible de journalisation spécifique (par exemple, SYSTEMD_LOG_LEVEL=debug,console:info spécifie de journaliser au niveau debug sauf pour la journalisation vers la console qui devrait être au niveau info). Notez que le niveau de journalisation maximal global a la priorité sur tous les niveaux de journalisation maximaux par cible.

$SYSTEMD_LOG_COLOR

Un booléen. S'il est vrai, les messages écrits sur le tty seront colorés en fonction de leur priorité.

Ce paramètre n'est utile que lorsque les messages sont écrits directement dans le terminal, car journalctl(1) et d'autres outils d'affichage des journaux colorient les messages en fonction du niveau de journalisation par eux-mêmes.

$SYSTEMD_LOG_TIME

Un booléen. S'il est vrai, les messages de journalisation de la console seront préfixés par un horodatage.

Ce paramètre n'est utile que lorsque les messages sont écrits directement dans le terminal ou dans un fichier, car journalctl(1) et d'autres outils d'affichage des journaux ajoutent eux-mêmes des horodatages basés sur les métadonnées de l'entrée.

$SYSTEMD_LOG_LOCATION

Un booléen. S'il est vrai, les messages seront préfixés par le nom du fichier et le numéro de ligne dans le code source d'où provient le message.

Notez que l'emplacement du journal est souvent déjà attaché en tant que métadonnées aux entrées du journal. L'inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TID

Un booléen. S'il est vrai, les messages seront préfixés par l'identifiant numérique du thread (TID) actuel.

Notez que ces informations sont de toute façon attachées en tant que métadonnées aux entrées du journal. Les inclure directement dans le texte du message peut néanmoins être pratique lors du débogage de programmes.

$SYSTEMD_LOG_TARGET

La destination des messages de journalisation. L'une des options suivantes : console (journaliser vers le tty attaché), console-prefixed (journaliser vers le tty attaché mais avec des préfixes codant le niveau de journalisation et la "facility", voir syslog(3), kmsg (journaliser dans le tampon de journalisation circulaire du noyau), journal (journaliser dans le journal), journal-or-kmsg (journaliser dans le journal si disponible, et dans kmsg sinon), auto (déterminer automatiquement la cible de journalisation appropriée, par défaut), null (désactiver la sortie de journal).

$SYSTEMD_LOG_RATELIMIT_KMSG

Si les messages kmsg doivent être limités en débit ou non. Prend une valeur booléenne. La valeur par défaut est "true". Si désactivé, systemd ne limitera pas le débit des messages écrits dans kmsg.

$SYSTEMD_PAGER, $PAGER

Paginator à utiliser lorsque --no-pager n'est pas spécifié. $SYSTEMD_PAGER est utilisé s'il est défini ; sinon, $PAGER est utilisé. Si ni $SYSTEMD_PAGER ni $PAGER ne sont définis, une série d'implémentations de paginator connues sont essayées dans l'ordre, y compris less(1) et more(1), jusqu'à ce que l'une soit trouvée. Si aucune implémentation de paginator n'est découverte, aucun paginator n'est invoqué. Définir ces variables d'environnement sur une chaîne vide ou la valeur "cat" équivaut à passer --no-pager.

Note : si $SYSTEMD_PAGERSECURE n'est pas défini, $SYSTEMD_PAGER et $PAGER ne peuvent être utilisés que pour désactiver le paginator (avec "cat" ou ""), et sont sinon ignorés.

$SYSTEMD_LESS

Remplace les options passées à less (par défaut "FRSXMK").

Les utilisateurs pourraient vouloir modifier deux options en particulier :

K

Cette option indique au paginator de quitter immédiatement lorsque Ctrl+C est pressé. Pour permettre à less de gérer lui-même Ctrl+C afin de revenir à l'invite de commande du paginator, désactivez cette option.

Si la valeur de $SYSTEMD_LESS n'inclut pas "K", et que le paginator invoqué est less, Ctrl+C sera ignoré par l'exécutable et devra être géré par le paginator.

X

Cette option indique au paginator de ne pas envoyer les chaînes d'initialisation et de désinitialisation termcap au terminal. Elle est définie par défaut pour permettre à la sortie de la commande de rester visible dans le terminal même après la sortie du paginator. Néanmoins, cela empêche certaines fonctionnalités du paginator de fonctionner, en particulier la sortie paginée ne peut pas être défilée avec la souris.

Notez que la définition de la variable d'environnement $LESS régulière n'a aucun effet pour les invocations de less par les outils de systemd.

Voir less(1) pour plus de discussion.

$SYSTEMD_LESSCHARSET

Remplace le jeu de caractères passé à less (par défaut "utf-8", si le terminal appelant est déterminé comme étant compatible UTF-8).

Notez que la définition de la variable d'environnement $LESSCHARSET régulière n'a aucun effet pour les invocations de less par les outils de systemd.

$SYSTEMD_PAGERSECURE

Les commandes de paginator courantes comme less(1), en plus de la "pagination", c'est-à-dire le défilement de la sortie, permettent d'ouvrir ou d'écrire dans d'autres fichiers et d'exécuter des commandes shell arbitraires. Lorsque les commandes sont invoquées avec des privilèges élevés, par exemple sous sudo(8) ou pkexec(1), le paginator devient une frontière de sécurité. Il faut veiller à n'utiliser que des programmes aux fonctionnalités strictement limitées comme paginators, et à ne pas autoriser les fonctionnalités interactives involontaires comme l'ouverture ou la création de nouveaux fichiers ou le lancement de sous-processus. Le "mode sécurisé" pour le paginator peut être activé comme décrit ci-dessous, si le paginator le prend en charge (la plupart des paginators ne sont pas écrits de manière à en tenir compte). Il est recommandé d'activer explicitement le "mode sécurisé" ou de désactiver complètement le paginator en utilisant --no-pager ou PAGER=cat lorsque des utilisateurs non fiables sont autorisés à exécuter des commandes avec des privilèges élevés.

Cette option prend un argument booléen. Lorsqu'il est défini sur vrai, le "mode sécurisé" du paginator est activé. En "mode sécurisé", LESSSECURE=1 sera défini lors de l'invocation du paginator, ce qui indique au paginator de désactiver les commandes qui ouvrent ou créent de nouveaux fichiers ou lancent de nouveaux sous-processus. Actuellement, seul less(1) est connu pour comprendre cette variable et implémenter le "mode sécurisé".

Lorsqu'il est défini sur faux, aucune limitation n'est imposée au paginator. La définition de SYSTEMD_PAGERSECURE=0 ou le fait de ne pas le supprimer de l'environnement hérité peut permettre à l'utilisateur d'invoquer des commandes arbitraires.

Lorsque $SYSTEMD_PAGERSECURE n'est pas défini, les outils systemd tentent de déterminer automatiquement si le "mode sécurisé" doit être activé et si le paginator le prend en charge. Le "mode sécurisé" est activé si l'UID effectif n'est pas le même que le propriétaire de la session de connexion, voir geteuid(2) et sd_pid_get_owner_uid(3), ou lors de l'exécution sous sudo(8) ou des outils similaires ($SUDO_UID est défini [1]). Dans ces cas, SYSTEMD_PAGERSECURE=1 sera défini et les paginators qui ne sont pas connus pour implémenter le "mode sécurisé" ne seront pas utilisés du tout. Notez que cette autodétection ne couvre que les mécanismes les plus courants pour élever les privilèges et est destinée à la commodité. Il est recommandé de définir explicitement $SYSTEMD_PAGERSECURE ou de désactiver le paginator.

Notez que si les variables $SYSTEMD_PAGER ou $PAGER doivent être respectées, autre que pour désactiver le paginator, $SYSTEMD_PAGERSECURE doit également être défini.

$SYSTEMD_COLORS

Prend un argument booléen. Lorsqu'il est vrai, systemd et les utilitaires associés utiliseront des couleurs dans leur sortie, sinon la sortie sera monochrome. De plus, la variable peut prendre l'une des valeurs spéciales suivantes : "16", "256" pour restreindre l'utilisation des couleurs aux couleurs ANSI de base 16 ou 256, respectivement. Ceci peut être spécifié pour remplacer la décision automatique basée sur $TERM et ce à quoi le console est connectée.

$SYSTEMD_URLIFY

La valeur doit être un booléen. Contrôle si des liens cliquables doivent être générés dans la sortie pour les émulateurs de terminal qui le prennent en charge. Ceci peut être spécifié pour remplacer la décision prise par systemd en fonction de $TERM et d'autres conditions.

Afficher les paramètres actuels :

$ timedatectl

               Heure UTC : Jeu 2017-09-21 14:08:56 UTC

Horloge système synchronisée : oui
