TILDA(1) Commandes utilisateur TILDA(1)

NOM

tilda - émulateur de terminal hautement configurable

SYNTAXE

tilda [-b|--background-color couleur] [-c|--command commande] [-h|--hidden] [-f|--font police] [-g|--config-file fichier] [-l|--lines fichier] [-s|--scrollbar] [-w|--working-dir dossier] [-x|--x-pos pos_x] [-y|--y-pos pos_y] [-t|--background-alpha alpha] [-C|--config] [--display display]

tilda --dbus

tilda -T|--toggle-window [instance_id]

tilda --version

tilda --help

tilda --help-all

DESCRIPTION

Tilda est un émulateur de terminal hautement configurable. La principale caractéristique distinctive de tilda est qu'il utilise un raccourci configurable pour afficher et masquer la fenêtre tilda. Cela permet aux utilisateurs de basculer rapidement entre tilda et d'autres fenêtres uniquement via des raccourcis clavier. Lorsque tilda est masqué, il se déplace hors de l'écran jusqu'à ce que le raccourci de traction/basculement soit à nouveau pressé pour afficher la fenêtre tilda. Le comportement de tilda peut être configuré à l'aide de la boîte de dialogue des préférences, accessible via le menu contextuel. Un sous-ensemble des options peut également être configuré depuis la ligne de commande, comme documenté ci-dessous.

Veuillez noter que les options de la ligne de commande remplacent actuellement les paramètres du fichier de configuration et sont enregistrées dans le fichier de configuration.

Sur les bureaux basés sur Xorg, Tilda utilise une fonction de filtre X11 pour enregistrer ses raccourcis. Sur Wayland, cette méthode ne fonctionne que lorsque d'autres programmes basés sur X11 sont actifs, mais nous ne pouvons pas envoyer de raccourcis à tilda lorsque des applications Wayland natives ont le focus. Par conséquent, sur les bureaux Wayland, tilda doit être démarré avec le support D-Bus (c'est-à-dire avec --dbus) et un raccourci global doit être enregistré à l'aide des paramètres de l'environnement de bureau pour envoyer une action D-Bus afin d'afficher ou de masquer la fenêtre Tilda.

OPTIONS

Options d'aide :

-?, --help
Afficher les options d'aide
--help-all
Afficher toutes les options d'aide, y compris les options D-Bus et GTK.

Options d'application :

-b, --background-color couleur
Définir la couleur d'arrière-plan. La valeur peut être soit un nom de couleur standard X11, soit une valeur hexadécimale (c'est-à-dire #rgb, #rrggbb, etc.).
-c, --command commande
Exécuter une commande au démarrage au lieu du shell par défaut.
-h, --hidden
Démarrer Tilda masqué.
-f, --font police
Définir la police sur la description de police Pango spécifiée dans police. Par défaut : "Monospace 11".
-l, --lines lignes
Définir la taille du tampon de défilement à un maximum de lignes.
-s, --scrollbar
Afficher une barre de défilement sur le côté du terminal.
-v, --version
Afficher la version, puis quitter.
-w, --working-dir dossier
Définir le répertoire de travail initial sur dossier.
-x, --x-pos pos_x
Définir la position X de la fenêtre du terminal tilda sur pos_x.
-y, --y-pos pos_y
Définir la position Y de la fenêtre du terminal tilda sur pos_y.
-t, --background-alpha alpha
Définir la transparence de la fenêtre du terminal sur alpha (c'est-à-dire 0-100%). Des valeurs plus élevées augmentent le niveau de transparence.
-C, --config
Afficher l'assistant de configuration.
--display=DISPLAY
Définir l'affichage X à utiliser (c'est-à-dire :0, :0.0, etc.).

Options D-Bus :

--dbus
Active le support D-Bus (voir D-Bus).
-T, --toggle-window [instance_id]
Bascule une fenêtre Tilda avec instance_id et quitte. Si instance_id n'est pas spécifié, il prend par défaut l'instance 0. Cette option offre un moyen pratique de basculer les fenêtres tilda dans les environnements Wayland et est équivalente à la commande dbus-send plus longue décrite ci-dessous. Elle peut être utilisée pour configurer un raccourci clavier dans un environnement de bureau basé sur Wayland qui basculera alors la fenêtre Tilda. Notez que cette option est affectée par le paramètre "Comportement de traction sans focus".

NOTES

D-Bus

Si D-Bus est activé, Tilda propose une méthode sur D-Bus pour basculer la fenêtre Tilda. Chaque processus Tilda enregistre son propre nom D-Bus, il est donc possible d'exécuter plusieurs processus tilda avec leurs propres fichiers de configuration et de les contrôler séparément via D-Bus. Lorsque D-Bus est activé, le raccourci de traction n'est pas enregistré comme une fonction de filtre Xorg, et un raccourci global approprié doit être configuré dans l'environnement de bureau (voir --toggle-window). Vous pouvez éventuellement effacer le raccourci de traction dans les paramètres si le support D-Bus est activé.

Chaque instance Tilda s'enregistre en utilisant un nom de bus et un chemin d'objet générés dynamiquement en utilisant son numéro d'instance. La première instance Tilda sera sur le nom de bus :


com.github.lanoxx.tilda.Actions0

avec le chemin d'objet :


/com/github/lanoxx/tilda/Actions0

Le nom de l'interface est toujours :


com.github.lanoxx.tilda.Actions

Pour basculer la fenêtre tilda, vous pouvez utiliser l'option -T|--toggle-window de tilda :

    tilda -T    # basculer l'instance par défaut (c'est-à-dire 0)
    tilda -T 0  # basculer explicitement l'instance spécifiée (c'est-à-dire 0)

Alternativement, vous pouvez également utiliser la commande dbus-send.

    dbus-send --session --type=method_call \
       --dest=com.github.lanoxx.tilda.Actions0 \
       /com/github/lanoxx/tilda/Actions0 \
       com.github.lanoxx.tilda.Actions.Toggle

Pour chaque instance tilda supplémentaire, le nom de bus et le chemin d'objet seront incrémentés de un (par exemple, Actions1, Actions2, etc.).

Vous pouvez utiliser l'une des commandes ci-dessus pour enregistrer un raccourci global dans votre session Wayland. Sous Gnome, cela peut être fait dans Paramètres -> Clavier -> Raccourcis clavier.

FICHIERS

Tilda crée ses fichiers de configuration sous ~/.config/tilda/. Pour chaque instance, il créera un fichier de configuration nommé config_<N>, où <N> commence à 0 et est incrémenté pour chaque processus supplémentaire qui est démarré.

Tilda crée également un répertoire de cache sous ~/.cache/tilda/locks, où il créera un fichier de verrou global nommé lock_0_0 et des fichiers de verrouillage supplémentaires spécifiques à l'instance nommés lock_<PID>_<N>, où <PID> est l'identifiant du processus et <N> est l'identifiant de l'instance.

Vous pouvez éventuellement créer un fichier nommé style.css et le placer dans le répertoire de configuration de tilda si vous souhaitez personnaliser l'apparence de tilda.
