NOM

timesyncd.conf, timesyncd.conf.d — Fichiers de configuration de la synchronisation de l'heure du réseau

SYNTAXE

/etc/systemd/timesyncd.conf
/run/systemd/timesyncd.conf
/usr/local/lib/systemd/timesyncd.conf
/usr/lib/systemd/timesyncd.conf
/etc/systemd/timesyncd.conf.d/*.conf
/run/systemd/timesyncd.conf.d/*.conf
/usr/local/lib/systemd/timesyncd.conf.d/*.conf
/usr/lib/systemd/timesyncd.conf.d/*.conf

DESCRIPTION

Ces fichiers de configuration contrôlent la synchronisation de l'heure du réseau NTP. Voir systemd.syntax(7) pour une description générale de la syntaxe.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, donc une configuration n'est nécessaire que lorsqu'il est nécessaire de s'écarter de ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [1], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des remplacements locaux peuvent également être créés en créant des snippets, comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cette fin (ou une copie dans /etc/ s'il est fourni sous /usr/), cependant l'utilisation de snippets pour la configuration locale est recommandée plutôt que des modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des snippets de configuration sont lus à partir de /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces snippets ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier dans l'ordre lexicographique, indépendamment du sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la priorité, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées telles qu'elles apparaissent dans les fichiers triés.

Lorsque des paquets ont besoin de personnaliser la configuration, ils peuvent installer des snippets sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Les snippets doivent être utilisés pour remplacer les snippets de paquets, car le fichier de configuration principal a une priorité inférieure. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires avec un nombre à deux chiffres et un tiret, pour simplifier l'ordre. Cela définit également un concept de priorités de snippets pour permettre aux fournisseurs de systèmes d'exploitation de fournir des snippets dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les snippets de paquets remplacent accidentellement les snippets définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les snippets dans /usr/ et la plage 60-90 pour les snippets dans /etc/ et /run/, pour s'assurer que les snippets locaux et transitoires ont la priorité sur les snippets fournis par le fournisseur du système d'exploitation.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS

Les paramètres suivants sont configurés dans la section [Time] :

NTP=

Une liste d'adresses IP ou de noms d'hôtes de serveurs NTP séparés par des espaces. Pendant l'exécution, cette liste est combinée avec les serveurs NTP par interface obtenus à partir de systemd-networkd.service(8). systemd-timesyncd contactera tous les serveurs système ou par interface configurés tour à tour, jusqu'à ce qu'un réponde. Lorsque la chaîne vide est attribuée, la liste des serveurs NTP est réinitialisée et toutes les affectations précédentes n'auront aucun effet. Ce paramètre est vide par défaut.

Ajouté dans la version 216.

FallbackNTP=

Une liste d'adresses IP ou de noms d'hôtes de serveurs NTP de secours, séparés par des espaces. Tous les serveurs NTP par interface obtenus à partir de systemd-networkd.service(8) ont la priorité sur ce paramètre, tout comme les serveurs définis via NTP= ci-dessus. Ce paramètre n'est donc pertinent que si aucune autre information de serveur NTP n'est connue. Lorsque la chaîne vide est attribuée, la liste des serveurs NTP est réinitialisée et toutes les affectations précédentes n'auront aucun effet. Si cette option n'est pas fournie, une liste de serveurs NTP intégrée est utilisée.

Ajouté dans la version 216.

RootDistanceMaxSec=

Distance racine maximale acceptable, c'est-à-dire le temps maximum estimé nécessaire pour qu'un paquet voyage jusqu'au serveur auquel nous sommes connectés depuis le serveur possédant l'horloge de référence. Si le serveur actuel ne satisfait pas cette limite, systemd-timesyncd basculera vers un serveur différent.

Prend une valeur de durée. L'unité par défaut est les secondes, mais d'autres unités peuvent être spécifiées, voir systemd.time(7). Par défaut, 5 secondes.

Ajouté dans la version 236.

PollIntervalMinSec=, PollIntervalMaxSec=

Les intervalles de sondage minimum et maximum pour les messages NTP. La sondage commence à l'intervalle de sondage minimum et est ajusté dans les limites spécifiées en réponse aux paquets reçus.

Chaque paramètre prend une valeur de durée. L'unité par défaut est les secondes, mais d'autres unités peuvent être spécifiées, voir systemd.time(7). PollIntervalMinSec= est par défaut à 32 secondes et ne doit pas être inférieur à 16 secondes. PollIntervalMaxSec= est par défaut à 34 minutes et 8 secondes (2048 secondes) et doit être supérieur à PollIntervalMinSec=.

Ajouté dans la version 236.

ConnectionRetrySec=

Spécifie le délai minimum avant que les tentatives ultérieures de contact avec un nouveau serveur NTP ne soient effectuées.

Prend une valeur de durée. L'unité par défaut est les secondes, mais d'autres unités peuvent être spécifiées, voir systemd.time(7). Par défaut, 30 secondes et ne doit pas être inférieur à 1 seconde.

Ajouté dans la version 248.

SaveIntervalSec=

L'intervalle auquel l'heure actuelle est périodiquement sauvegardée sur disque, en l'absence de synchronisation récente à partir d'un serveur NTP. Ceci est particulièrement utile pour les systèmes hors ligne sans RTC local, car cela garantira que l'horloge système reste à peu près monotone entre les redémarrages.

Prend une valeur de durée. L'unité par défaut est les secondes, mais d'autres unités peuvent être spécifiées, voir systemd.time(7). Par défaut, 60 secondes.

Ajouté dans la version 250.

VOIR AUSSI

systemd(1), systemd-timesyncd.service(8), systemd-networkd.service(8)
