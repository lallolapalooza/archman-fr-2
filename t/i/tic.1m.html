tic(1M) Commandes utilisateur tic(1M)

NOM

tic - compile les descriptions de terminaux pour terminfo ou termcap

SYNTAXE

tic [-01acCDfgGIKLNqrstTUVWx] [-e liste-de-types-de-terminaux] [-o répertoire] [-Q[n]] [-R sous-ensemble] [-v[n]] [-w[n]] fichier

DESCRIPTION

La commande tic traduit un fichier terminfo du format source en format compilé. Le format compilé est nécessaire pour l'utilisation avec les routines de bibliothèque de ncurses(3X).

Comme décrit dans term(5), la base de données peut être soit une arborescence de répertoires (un fichier par entrée de terminal), soit une base de données hachée (un enregistrement par entrée). La commande tic n'écrit qu'un seul type d'entrée, en fonction de la façon dont elle a été construite :

  • Pour les arborescences de répertoires, le répertoire de niveau supérieur, par exemple /usr/share/terminfo, spécifie l'emplacement de la base de données.
  • Pour les bases de données hachées, un nom de fichier est nécessaire. Si le fichier donné n'est pas trouvé sous ce nom, mais peut être trouvé en ajoutant le suffixe « .db », alors celui-ci est utilisé.
Le nom par défaut pour la base de données hachée est le même que le nom du répertoire par défaut (en ajoutant seulement un suffixe « .db »).

Dans les deux cas (répertoire ou base de données hachée), tic créera le conteneur s'il n'existe pas. Pour un répertoire, ce serait la feuille « terminfo », par opposition à un fichier « terminfo.db ».

Les résultats sont normalement placés dans la base de données terminfo système /usr/share/terminfo. La description compilée du terminal peut être placée dans une base de données terminfo différente. Il existe deux façons d'y parvenir :

  • Premièrement, vous pouvez remplacer la valeur par défaut du système soit en utilisant l'option -o, soit en définissant la variable TERMINFO dans votre environnement shell à un emplacement de base de données valide.
  • Deuxièmement, si tic ne peut pas écrire dans /usr/share/terminfo ou dans l'emplacement spécifié par votre variable TERMINFO, il recherche le répertoire $HOME/.terminfo (ou la base de données hachée $HOME/.terminfo.db) ; si cet emplacement existe, l'entrée y est placée.

Les bibliothèques qui lisent les entrées terminfo sont censées vérifier dans l'ordre :

  • un emplacement spécifié avec la variable d'environnement TERMINFO,
  • $HOME/.terminfo,
  • les répertoires listés dans la variable d'environnement TERMINFO_DIRS,
  • une liste pré-compilée de répertoires (/usr/share/terminfo), et
  • la base de données terminfo système (/usr/share/terminfo).

La section Récupération des descriptions compilées du manuel terminfo(5) donne plus de détails.

Alias

C'est le même programme que infotocap et captoinfo ; généralement, ceux-ci sont liés ou copiés depuis ce programme :

  • Lorsqu'il est appelé en tant qu'infotocap, tic définit l'option -I.
  • Lorsqu'il est appelé en tant que captoinfo, tic définit l'option -C.

OPTIONS

-0
restreint la sortie à une seule ligne
-1
restreint la sortie à une seule colonne
-a
indique à tic de conserver les capacités commentées plutôt que de les ignorer. Les capacités sont commentées en les préfixant d'un point. Ceci définit l'option -x, car elle traite les entrées commentées comme des noms définis par l'utilisateur. Si la source est termcap, accepte les noms à 2 caractères requis par la version 6. Sinon, ils sont ignorés.
-C
Force la traduction source au format termcap. Remarque : ceci diffère de l'option -C de infocmp(1M) car elle ne se contente pas de traduire les noms de capacités, mais traduit également les chaînes terminfo au format termcap. Les capacités non traduisibles sont laissées dans l'entrée sous leurs noms terminfo mais commentées avec deux points précédents. Le format réel utilisé intègre quelques améliorations pour les caractères échappés du format terminfo. Pour une traduction plus stricte compatible BSD, ajoutez l'option -K.
Si ceci est combiné avec -c, tic effectue des vérifications supplémentaires pour signaler les cas où les valeurs terminfo n'ont pas d'équivalent exact sous forme termcap. Par exemple :
  • sgr ne convertira généralement pas, car termcap n'a pas la capacité de travailler avec plus de deux paramètres, et parce que termcap manque de nombreux opérateurs arithmétiques/logiques utilisés dans terminfo.
  • les capacités avec plus d'un délai ou avec des délais avant la fin de la chaîne ne seront pas entièrement converties.
-c
indique à tic de vérifier uniquement fichier pour les erreurs, y compris les problèmes de syntaxe et les mauvaises utilisations de liens. Si vous spécifiez -C (-I) avec cette option, le code imprimera des avertissements sur les entrées qui, après résolution des usages, sont plus longues que 1023 (4096) octets. En raison d'une longueur de tampon fixe dans les anciennes bibliothèques termcap, ainsi que d'une vérification défectueuse de la longueur du tampon (et d'une limite documentée dans terminfo), ces entrées peuvent provoquer des plantages mémoire avec d'autres implémentations.
tic vérifie les capacités de chaîne pour s'assurer que celles avec des paramètres seront des expressions valides. Il effectue cette vérification uniquement pour les capacités de chaîne prédéfinies ; celles définies avec l'option -x sont ignorées.
-D
indique à tic d'afficher les emplacements de base de données qu'il connaît, puis de quitter. Le premier emplacement affiché est celui vers lequel il écrirait les descriptions de terminaux compilées. Si tic ne parvient pas à trouver un emplacement de base de données inscriptible selon les règles résumées ci-dessus, il affichera un diagnostic et quittera avec une erreur plutôt que d'afficher une liste d'emplacements de base de données.
-e liste
Limite les écritures et les traductions à la liste de types de terminaux séparés par des virgules. Si un nom ou un alias de terminal correspond à l'un des noms de la liste, l'entrée sera écrite ou traduite normalement. Sinon, aucune sortie ne sera générée pour celui-ci. La valeur de l'option est interprétée comme un fichier contenant la liste si elle contient un '/'. (Remarque : selon la façon dont tic a été compilé, cette option peut nécessiter -I ou -C.)
-f
Affiche les chaînes terminfo complexes qui contiennent des expressions if/then/else/endif indentées pour la lisibilité.
-G
Affiche les littéraux constants sous forme décimale plutôt que leurs équivalents caractères.
-g
Affiche les littéraux caractères constants sous forme de guillemets plutôt que leurs équivalents décimaux.
-I
Force la traduction source au format terminfo.
-K
Supprime certaines extensions de longue date de ncurses au format termcap, par exemple « \s » pour l'espace.
-L
Force la traduction source au format terminfo en utilisant les noms de variables C longs listés dans <term.h>
-N
Désactive les valeurs par défaut intelligentes. Normalement, lors de la traduction de termcap vers terminfo, le compilateur fait un certain nombre d'hypothèses sur les valeurs par défaut des capacités de chaîne reset1_string, carriage_return, cursor_left, cursor_down, scroll_forward, tab, newline, key_backspace, key_left et key_down, puis tente d'utiliser des capacités termcap obsolètes pour déduire les valeurs correctes. Il supprime également normalement la sortie des capacités termcap obsolètes telles que bs. Cette option force une traduction plus littérale qui préserve également les capacités obsolètes.
-orépertoire
Écrit les entrées compilées dans l'emplacement de base de données donné. Remplace la variable d'environnement TERMINFO.
-Qn
Au lieu de montrer la source au format terminfo (texte), imprime le format compilé (binaire) en hexadécimal ou en base64.
-q
Affiche les capacités de chaîne de sortie dans un format lisible, par exemple en utilisant des octets hexadécimaux pour les caractères non imprimables. Ceci est l'opposé de l'option -x.
-r
Indique à tic de ne pas supprimer les capacités nommées qui ne sont pas utilisées. En général, les capacités non utilisées sont supprimées (parfois avec des avertissements).
-R sous-ensemble
Limite le jeu de capacités de sortie à un sous-ensemble de la base de données terminfo. Les valeurs de sous-ensemble sont actuellement :
T
capacités de base uniquement
T
avec quelques extensions pour les terminaux graphiques
A
avec des capacités pour les terminaux à écran complet
E
avec des extensions de souris, etc.
a
tout, y compris les capacités qui ne sont pas des courtes séquences de clavier
-s
Indique à tic de générer uniquement des chaînes de sortie qui sont des séquences de caractères courtes. Ceci est l'opposé de l'option -f et convient aux programmes qui ne peuvent pas gérer les chaînes de sortie complexes.
-t
Indique à tic de ne pas supprimer les capacités numérotées qui ne sont pas utilisées. En général, les capacités non utilisées sont supprimées (parfois avec des avertissements).
-T
Indique à tic de ne pas ajouter de nouveaux noms aux types de terminaux compilés lorsque la sortie est au format terminfo. Ceci est utile pour la génération de fichiers terminfo qui seront utilisés par d'anciennes applications terminfo.
-U
Indique à tic de supprimer les extensions des noms de variables C définies dans le fichier d'en-tête <term.h>. Ceci n'affecte pas la génération de la sortie. Au lieu de cela, cela affecte la manière dont les variables C sont produites, pour l'utilisation interne par les programmes ncurses.
-V
Affiche la version de tic et quitte.
-vn
Mode verbeux. L'option -v affiche le nombre de capacités, de chaînes et de tables de traduction trouvées dans le fichier d'entrée. Le niveau de détail de la sortie peut être augmenté en ajoutant une valeur numérique à l'option. Par exemple, -v2 affiche les extensions dans un format beaucoup plus détaillé.
-v0
silencieux
-v1
nombre de termes
-v2
nom de chaque terme traduit
-v3
nom de chaque capacité et de chaque chaîne traduite
-v4
nom de chaque caractère dans chaque chaîne traduite
-W
Affiche les avertissements sur les capacités inutilisées ou les problèmes potentiels. Ceci est l'opposé de l'option -r et -t.
-wn
Mode verbeux de sortie pour les capacités de chaîne. Par défaut, les chaînes sont formatées pour la lisibilité. L'option -w supprime cette mise en forme. L'option -w0 supprime la mise en forme, alors que l'option -w1 formate la sortie sous forme de chaînes d'échappement C. L'option -w2 formate la sortie sous forme de chaînes hexadécimales. L'option -w3 formate la sortie sous forme de chaînes base64.
-x
Indique à tic de traiter les chaînes comme des extensions xterm. Ceci est utilisé pour les chaînes qui contiennent des expressions conditionnelles ou d'autres constructions qui ne sont pas directement utilisables dans les systèmes termcap plus anciens. En mode -x, les chaînes sont traitées comme des entrées terminfo. Ceci est l'opposé de l'option -q.

FICHIERS

$HOME/.terminfo
Répertoire pour les descriptions de terminaux compilées personnelles.
$HOME/.terminfo.db
Base de données hachée pour les descriptions de terminaux compilées personnelles.
/usr/share/terminfo
Répertoire pour les descriptions de terminaux compilées système.
/usr/share/terminfo.db
Base de données hachée pour les descriptions de terminaux compilées système.

ENVIRONNEMENT

TERMINFO
Si cette variable est définie, elle spécifie le nom d'un répertoire (ou d'un fichier de base de données hachée) qui sera utilisé pour les entrées de terminal compilées, au lieu de /usr/share/terminfo.
TERMINFO_DIRS
Si cette variable est définie, elle contient une liste de répertoires (séparés par des deux-points) à rechercher pour les entrées de terminal compilées. Ces répertoires sont recherchés après $HOME/.terminfo et avant /usr/share/terminfo.

Les chaînes de capacités définies par l'utilisateur dont le nom commence par “k” sont traitées comme des touches de fonction.

Paramètres

fichier
contient une ou plusieurs descriptions de terminaux terminfo au format source [voir terminfo(5)]. Chaque description dans le fichier décrit les capacités d'un terminal particulier.
Si fichier est “-”, les données sont lues à partir de l'entrée standard. Le paramètre fichier peut également être le chemin d'un périphérique caractère.

Traitement

Toutes les capacités reconnues par tic, à l'exception d'une, sont documentées dans terminfo(5). L'exception est la capacité use.

Lorsqu'un champ use=nom-entrée est découvert dans une entrée de terminal en cours de compilation, tic lit le binaire de /usr/share/terminfo pour compléter l'entrée. (Les entrées créées à partir de fichier seront utilisées en premier. tic duplique les capacités de entrée-nom pour l'entrée actuelle, à l'exception des capacités explicitement définies dans l'entrée actuelle.

Lorsqu'une entrée, par exemple, nom_entrée_1, contient un champ use=nom_entrée_2, toutes les capacités annulées dans nom_entrée_2 doivent également apparaître dans nom_entrée_1 avant use= pour que ces capacités soient annulées dans nom_entrée_1.

Les entrées compilées au total ne peuvent pas dépasser 4096 octets dans le format de stockage hérité, ou 32768 en utilisant le format de nombre étendu. Le champ de nom ne peut pas dépasser 512 octets. Les noms de terminaux dépassant la longueur d'alias maximale (32 caractères sur les systèmes avec des noms de fichiers longs, 14 caractères sinon) seront tronqués à la longueur d'alias maximale et un message d'avertissement sera imprimé.

FICHIERS

/usr/share/terminfo
base de données des descriptions de terminaux compilées

NOTES

Il y a des preuves que les implémentations historiques de tic traitaient les champs de description sans espaces comme des alias supplémentaires ou des noms courts. Ce tic ne le fait pas, mais il avertit lorsque les champs de description peuvent être traités de cette manière et les vérifie pour les caractères dangereux.

EXTENSIONS

Contrairement à la commande tic de SVr4, cette implémentation peut réellement compiler des sources termcap. En fait, les entrées en syntaxe terminfo et termcap peuvent être mélangées dans un seul fichier source. Voir terminfo(5) pour la liste des noms termcap considérés comme équivalents aux noms terminfo.

Les pages de manuel SVr4 ne sont pas claires sur les règles de résolution des capacités use. Cette implémentation de tic trouvera les cibles use n'importe où dans le fichier source, ou n'importe où dans l'arborescence de fichiers enracinée à TERMINFO (si TERMINFO est défini), ou dans la base de données $HOME/.terminfo de l'utilisateur (si elle existe), ou (enfin) n'importe où dans l'arborescence de fichiers des entrées compilées du système.

Les messages d'erreur de ce tic ont le même format que les messages d'erreur de GNU C, et peuvent être analysés par la facilité de compilation d'Emacs GNU.

Outre -c et -v, les options ne sont pas portables :

•
La plupart des options de tic ne sont pas prises en charge par SVr4 tic :
-0 -1 -C -G -I -N -R -T -V -a -e -f -g -o -r -s -t -x
•
Le tic de NetBSD prend en charge quelques options de ncurses
-a -o -x
et ajoute -S (une fonctionnalité qui fait la même chose que les options -e et -E d'infocmp).

Le mode -c de SVr4 ne signale pas les mauvais liens “use=”.

System V ne compile pas les entrées à partir de, ni ne lit les entrées à partir de, la base de données $HOME/.terminfo de votre système, sauf si TERMINFO y est explicitement défini.

PORTABILITÉ

X/Open Curses, Issue 7 (2009) fournit une brève description de tic. Elle liste une seule option : -c. L'omission de -v est inattendue. L'historique des modifications indique que la description est dérivée de Tru64. Selon ses pages de manuel, ce système prenait également en charge l'option -v.

Peu de temps après la publication de l'Issue 7, Tru64 a été abandonné. En 2019, les implémentations survivantes de tic sont SVr4 (AIX, HP-UX et Solaris), ncurses et NetBSD curses. Les programmes tic de SVr4 prennent tous en charge l'option -v. Le programme tic de NetBSD suit la documentation de X/Open, omettant l'option -v.

La justification X/Open indique que certaines implémentations de tic lisent les descriptions de terminaux depuis l'entrée standard si le paramètre fichier est omis. Aucune de ces implémentations ne le fait. De plus, elle commente que certaines peuvent choisir de lire à partir de ”./terminfo.src” mais il s'agit d'un comportement obsolète de SVr2, et n'est pas (par exemple) une fonctionnalité documentée de SVr3.

HISTORIQUE

System V Release 2 fournissait un utilitaire tic. Il acceptait une seule option : -v (facultativement suivie d'un nombre). Selon le commentaire de Ross Ridge dans mytinfo, cette version de tic n'était pas capable de représenter les capacités annulées.

System V Release 3 fournissait un utilitaire tic différent, écrit par Pavel Curtis, (originellement nommé “compile” dans pcurses). Il ajoutait une option -c pour vérifier le fichier pour les erreurs, avec la réserve que er

rors dans les liens “use=” ne seraient pas signalés. System V Release 3 documentait quelques messages d'avertissement qui n'apparaissaient pas dans pcurses. Bien que le programme lui-même ait peu changé au fur et à mesure que le développement se poursuivait avec System V Release 4, le tableau des capacités est passé de 180 (pcurses) à 464 (Solaris).

Au début du développement de ncurses (1993), Zeyd Ben-Halim a utilisé le tableau de mytinfo pour étendre le tableau de pcurses à 469 capacités (456 correspondaient à SVr4, 8 étaient uniquement dans SVr4, 13 n'étaient pas dans SVr4). Parmi ces 13, 11 ont finalement été écartées (peut-être pour correspondre à l'ébauche de X/Open Curses). Les exceptions étaient memory_lock_above et memory_unlock (voir user_caps(5)).

Eric Raymond a incorporé des parties de mytinfo dans ncurses pour implémenter la conversion de source termcap vers terminfo, et a étendu cela pour commencer le développement de la conversion de source terminfo vers termcap correspondante, Thomas Dickey a complété ce développement sur plusieurs années.

En 1999, Thomas Dickey a ajouté l'option -x pour prendre en charge les capacités définies par l'utilisateur.

En 2010, Roy Marples a fourni un programme tic et une bibliothèque terminfo pour NetBSD. Cette implémentation adapte plusieurs fonctionnalités de ncurses, y compris l'option -x de tic.

L'option -c indique à tic de vérifier les problèmes dans le fichier source terminfo. Le développement continu fournit des vérifications supplémentaires :

  • pcurses avait 8 avertissements
  • ncurses en 1996 avait 16 avertissements
  • curses de Solaris (SVr4) a 28 avertissements
  • tic de NetBSD en 2019 a 19 avertissements.
  • ncurses en 2019 a 96 avertissements

Les vérifications effectuées dans le tic de ncurses aident à la conversion vers termcap, ainsi qu'à signaler les erreurs et les incohérences. Elles sont également utilisées pour garantir la cohérence avec les capacités définies par l'utilisateur. Il y a 527 capacités distinctes dans la base de données de terminaux de ncurses ; 128 d'entre elles sont définies par l'utilisateur.
