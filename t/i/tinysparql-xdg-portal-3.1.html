NOM

tinysparql-xdg-portal-3 - Portail vers les points d'accès Tracker

SYNOPSIS

tinysparql-xdg-portal-3 [--version | -v]

DESCRIPTION

Ce démon permet un accès contrôlé aux points d'accès TinySPARQL. Par défaut, l'accès à tous les services est refusé. Les services peuvent être mis sur liste blanche via une politique supplémentaire dans le fichier .flatpak-info.

Lors de la mise sur liste blanche de services, la politique peut définir des noms de graphes spécifiques à autoriser, le mot-clé default pour autoriser l'accès au graphe nommé par défaut, ou le mot-clé * pour autoriser l'accès à tous les graphes.

CONFIGURATION

Lors de l'interaction avec des clients cloisonnés, le service attend le format suivant dans le fichier .flatpak-info :

[Policy Tracker3]
dbus:org.example.SparqlEndpoint1=graphA;graphB;default
dbus:org.example.SparqlEndpoint2=*

Ceci autorisera l'accès aux points d'accès derrière les noms de bus org.example.SparqlEndpoint1 et org.example.SparqlEndpoint2. Uniquement aux IRIs de graphes graphA et graphB et au graphe non nommé par défaut sur le premier point d'accès, et à tous les graphes sur le second.

Cette politique peut être définie lors de la construction ou de l'exécution de l'application cloisonnée via l'option --add-policy. Elle peut être définie via finish-args dans le manifeste Flatpak, spécifiée le long de la chaîne de construction dans flatpak-build-finish(1), ou modifiée au moment de l'exécution avec flatpak-run(1). Par exemple :

$ flatpak run \
  --add-policy=Tracker3.dbus:org.example.SparqlEndpoint1=graphA \
  --add-policy=Tracker3.dbus:org.example.SparqlEndpoint1=graphB \
  --add-policy=Tracker3.dbus:org.example.SparqlEndpoint1=default \
  --add-policy=Tracker3.dbus:org.example.SparqlEndpoint2=* \
  org.freedesktop.ExampleSandbox

VOIR AUSSI

flatpak-build-finish(1), flatpak-override(1), flatpak-run(1)
