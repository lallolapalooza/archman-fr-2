NOM

tiffcp - copie (et éventuellement convertit) un fichier TIFF

SYNOPSIS

tiffcp [ options ] src1.tif … srcN.tif dst.tif

DESCRIPTION

tiffcp combine un ou plusieurs fichiers créés selon le format TIFF, révision 6.0, en un seul fichier TIFF. Parce que le fichier de sortie peut être compressé à l'aide d'un algorithme différent de celui des fichiers d'entrée, tiffcp est le plus souvent utilisé pour convertir entre différents schémas de compression.

Par défaut, tiffcp copiera toutes les balises comprises dans un répertoire TIFF d'un fichier d'entrée vers le répertoire associé dans le fichier de sortie.

tiffcp peut être utilisé pour réorganiser les caractéristiques de stockage des données dans un fichier, mais il est explicitement conçu pour ne pas altérer ou convertir le contenu des données de l'image d'aucune manière.

OPTIONS

-a
Ajoute à un fichier de sortie existant au lieu de l'écraser.
-b image
Soustrait l'image monochrome suivante de toutes les autres traitées. Ceci peut être utilisé pour supprimer un biais de bruit d'un ensemble d'images. Cette image de biais est typiquement une image de bruit que la caméra a vue avec son obturateur fermé.
-B
Force la sortie à être écrite avec un ordre des octets Big-Endian. Cette option n'a d'effet que lorsque le fichier de sortie est créé ou écrasé et non lorsqu'il est ajouté.
-C
Supprime l'utilisation du "strip chopping" lors de la lecture d'images qui ont une seule bande/tuile de données non compressées.
-c
Spécifie la compression à utiliser pour les données écrites dans le fichier de sortie : -c none pour aucune compression, -c packbits pour la compression PackBits, -c lzw pour la compression Lempel-Ziv & Welch, -c zip pour la compression Deflate, -c lzma pour la compression LZMA2, -c jpeg pour la compression JPEG de base, -c g3 pour la compression CCITT Group 3 (T.4), -c g4 pour la compression CCITT Group 4 (T.6), ou -c sgilog pour la compression SGILOG.

Par défaut, tiffcp compressera les données selon la valeur de la balise Compression trouvée dans le fichier source.

Les algorithmes de compression CCITT Group 3 et Group 4 ne peuvent être utilisés qu'avec des données bilevel.

La compression Group 3 peut être spécifiée avec plusieurs options spécifiques à T.4 :

  • 1d pour l'encodage 1 dimensionnel,
  • 2d pour l'encodage 2 dimensionnel, et
  • fill pour forcer chaque ligne de balayage encodée à être remplie de zéros de sorte que le code EOL de terminaison se trouve sur une limite d'octet.

Les options spécifiques au Group 3 sont spécifiées en ajoutant une liste séparée par des : à l'option g3 ; par exemple, -c g3:2d:fill pour obtenir des données encodées en 2D avec des EOL alignés sur les octets.

Les compressions LZW, Deflate et LZMA2 peuvent être spécifiées avec une valeur de predictor. Une valeur de prédicteur de 2 fait que chaque ligne de balayage de l'image de sortie subisse une différenciation horizontale avant d'être encodée ; une valeur de 1 force chaque ligne de balayage à être encodée sans différenciation. Une valeur de 3 est pour le prédicteur en virgule flottante que vous pouvez utiliser si les données encodées sont au format virgule flottante. Les options spécifiques à LZW sont spécifiées en ajoutant une liste séparée par des : à l'option lzw ; par exemple, -c lzw:2 pour la compression LZW avec différenciation horizontale.

Les encodeurs Deflate et LZMA2 supportent divers niveaux de compression (ou presets d'encodeur) définis comme un caractère p et un numéro de preset. p1 est le plus rapide avec le pire rapport de compression et p9 est le plus lent mais avec le meilleur ratio possible ; par exemple, -c zip:3:p9 pour un encodage Deflate avec niveau de compression maximum et prédicteur en virgule flottante.

Pour le codec Deflate, et dans une construction libtiff avec libdeflate activé, p12 est en fait le niveau maximum.

Pour le codec Deflate, et dans une construction libtiff avec libdeflate activé, s0 peut être utilisé pour exiger l'utilisation de zlib, et s1 pour libdeflate (par défaut libdeflate lorsqu'il est disponible).

-f fillorder
Spécifie l'ordre de remplissage des bits à utiliser lors de l'écriture des données de sortie. Par défaut, tiffcp créera un nouveau fichier avec le même ordre de remplissage que l'original. Spécifier -f lsb2msb forcera les données à être écrites avec la balise FillOrder définie à LSB2MSB, tandis que -f msb2lsb forcera les données à être écrites avec la balise FillOrder définie à MSB2LSB.
-i
Ignore les erreurs de lecture non fatales et continue le traitement du fichier d'entrée.
-l
Spécifie la longueur d'une tuile (en pixels).

tiffcp tente de définir les dimensions des tuiles de sorte qu'il n'y ait pas plus de 8 kilo-octets de données dans une tuile.

-L
Force la sortie à être écrite avec un ordre des octets Little-Endian. Cette option n'a d'effet que lorsque le fichier de sortie est créé ou écrasé et non lorsqu'il est ajouté.
-M
Supprime l'utilisation de fichiers mappés en mémoire lors de la lecture des images.
-o offset
Définit le décalage initial du répertoire.
-p
Spécifie la configuration planaire à utiliser lors de l'écriture des données d'image qui ont un échantillon de 8 bits par pixel. Par défaut, tiffcp créera un nouveau fichier avec la même configuration planaire que l'original. Spécifier -p contig forcera les données à être écrites avec des données multi-échantillons regroupées, tandis que -p separate forcera les échantillons à être écrits dans des plans séparés.
-r
Spécifie le nombre de lignes (lignes de balayage) dans chaque bande de données écrites dans le fichier de sortie. Par défaut (ou lorsque la valeur 0 est spécifiée), tiffcp tente de définir les lignes/bande de sorte qu'il n'y ait pas plus de 8 kilo-octets de données dans une bande. Si vous spécifiez la valeur spéciale -1, cela se traduira par un nombre infini de lignes par bande. L'image entière sera alors une seule bande.
-s
Force le fichier de sortie à être écrit avec les données organisées en bandes (plutôt qu'en tuiles).
-t
Force le fichier de sortie à être écrit avec les données organisées en tuiles (plutôt qu'en bandes). Les options peuvent être utilisées pour forcer l'image résultante à être écrite en bandes ou en tuiles de données, respectivement.
-w
Spécifie la largeur d'une tuile (en pixels). :program::tiffcp tente de définir les dimensions des tuiles de sorte qu'il n'y ait pas plus de 8 kilo-octets de données dans une tuile.
-x
Force le fichier de sortie à être écrit avec la valeur PAGENUMBER en séquence.
-8
Écrit BigTIFF au lieu du format TIFF classique.
-,= caractere
Substitue caractere à , lors de l'analyse des indices des répertoires d'images dans les fichiers. Ceci est nécessaire si les noms de fichiers contiennent des virgules. Notez que -,= suivi immédiatement d'un espace désactivera complètement la signification spéciale de la virgule. Voir les exemples.
-m s

tiffcp(1) - Arch Linux man pages

NOM

tiffcp — copie des fichiers TIFF

SYNOPSIS

tiffcp [options] input.tif… output.tif

DESCRIPTION

La commande tiffcp copie des images TIFF d'un ou plusieurs fichiers d'entrée vers un fichier de sortie. Les options peuvent être utilisées pour ré-encoder les images à la volée.

Le fichier de sortie peut contenir plusieurs images. Par défaut, toutes les images des fichiers d'entrée sont concaténées dans le fichier de sortie. Le nom de fichier d'entrée peut être immédiatement suivi d'une liste d'indices de répertoires d'images séparés par des virgules.

OPTIONS

-b file
Spécifie un fichier de calibration à utiliser pour les décodages associés à la compréhension. Le fichier de calibration doit contenir une seule image dans un format non compressé. Les valeurs de pixels du fichier de calibration sont soustraites des pixels des images d'entrée correspondantes. Ceci est typiquement utilisé pour soustraire un offset de bruit des images.
-c list
Spécifie le format de compréhension à utiliser pour le fichier de sortie. list est une liste séparée par des virgules de tags de compréhension. Les formats de compréhension supportés sont :
  • none : aucune compréhension (brut).
  • packbits : compréhension PackBits.
  • lzw : compréhension LZW.
  • jpeg : compréhension JPEG.
  • zip : compréhension Deflate.
  • g3 : compréhension CCITT Group 3 Fax.
  • g4 : compréhension CCITT Group 4 Fax.

Par exemple, -c lzw,jpeg utiliserait LZW pour les lignes et JPEG pour les tuiles. S'il n'y a pas de compréhension spécifiée, la compréhension d'origine est utilisée.

-r rows
Spécifie le nombre de lignes par image. Ceci est utilisé pour diviser une image source en plusieurs images de sortie, chacune ayant le nombre spécifié de lignes. L'option -r est utile pour convertir des images `fax-style' en une seule image de sortie.
-d
Désactive la décompression des images d'entrée. Ceci est utile lorsque vous souhaitez copier des images sans modifier leur compréhension d'origine.
-m maxmem
Définit la taille maximale d'allocation mémoire (en Mio). La valeur par défaut est 256 Mio. Définir à 0 pour désactiver la limite.

EXEMPLES

La commande suivante concatène deux fichiers et écrit le résultat en utilisant le codage LZW :

tiffcp -c lzw a.tif b.tif result.tif

Pour convertir un TIFF codé G3 1d en une seule bande de données codées G4, la commande suivante peut être utilisée :

tiffcp -c g4 -r 10000 g3.tif g4.tif

(10000 est juste un nombre plus grand que le nombre de lignes dans le fichier source.)

Pour extraire un ensemble sélectionné d'images d'un fichier TIFF multi-images, le nom de fichier peut être immédiatement suivi d'une liste d'indices de répertoires d'images séparés par des virgules. La première image est toujours dans le répertoire 0. Ainsi, pour copier la 1ère et la 3ème image du fichier image album.tif vers result.tif :

tiffcp album.tif,0,2 result.tif

Une virgule finale indique les images restantes en séquence. La commande suivante copiera toutes les images sauf la première :

tiffcp album.tif,1, result.tif

Pour le fichier CCD.tif dont la première image est un bruit de fond suivi d'images contenant ce bruit, soustraire le bruit de toutes les images suivantes (tout en décompressant) avec la commande :

tiffcp -c none -b CCD.tif CCD.tif,1, result.tif

Si le fichier ci-dessus était nommé CCD,X.tif, l'option -,= serait requise pour analyser correctement ce nom de fichier avec des numéros d'image, comme suit :

tiffcp -c none -,=% -b CCD,X.tif CCD,X%1%.tif result.tif
