times(2) Manuel des appels système times(2)

NOM

times - obtenir les temps du processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/times.h>
clock_t times(struct tms *buf);

DESCRIPTION

times() enregistre les temps actuels du processus dans la structure tms pointée par buf. La structure tms est définie dans <sys/times.h> comme suit :


struct tms {
    clock_t tms_utime;  /* temps utilisateur */
    clock_t tms_stime;  /* temps système */
    clock_t tms_cutime; /* temps utilisateur des enfants */
    clock_t tms_cstime; /* temps système des enfants */
};

Le champ tms_utime contient le temps CPU passé à exécuter les instructions du processus appelant. Le champ tms_stime contient le temps CPU passé à s'exécuter dans le noyau lors de l'exécution de tâches pour le compte du processus appelant.

Le champ tms_cutime contient la somme des valeurs tms_utime et tms_cutime pour tous les enfants terminés pour lesquels le processus attendait. Le champ tms_cstime contient la somme des valeurs tms_stime et tms_cstime pour tous les enfants terminés pour lesquels le processus attendait.

Les temps des enfants terminés (et de leurs descendants) sont ajoutés au moment où wait(2) ou waitpid(2) renvoie leur identifiant de processus. En particulier, les temps des petits-enfants pour lesquels les enfants n'ont pas attendu ne sont jamais vus.

Tous les temps rapportés sont en ticks d'horloge.

VALEUR DE RETOUR

times() renvoie le nombre de ticks d'horloge écoulés depuis un point arbitraire dans le passé. La valeur de retour peut dépasser la plage possible du type clock_t. En cas d'erreur, (clock_t) -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
tms pointe en dehors de l'espace d'adressage du processus.

VERSIONS

Sous Linux, l'argument buf peut être spécifié comme NULL, ce qui fait que times() renvoie simplement un résultat de fonction. Cependant, POSIX ne spécifie pas ce comportement, et la plupart des autres implémentations UNIX exigent une valeur non NULL pour buf.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4, 4.3BSD.

Dans POSIX.1-1996, le symbole CLK_TCK (défini dans <time.h>) est mentionné comme obsolète. Il l'est maintenant.

Avant Linux 2.6.9, si la disposition de SIGCHLD est définie sur SIG_IGN, alors les temps des enfants terminés sont automatiquement inclus dans les champs tms_cstime et tms_cutime, bien que POSIX.1-2001 indique que cela ne devrait se produire que si le processus appelant wait(2) sur ses enfants. Cette non-conformité a été corrigée dans Linux 2.6.9 et versions ultérieures.

Sous Linux, le « point arbitraire dans le passé » à partir duquel la valeur de retour de times() est mesurée a varié au cours des versions du noyau. Sous Linux 2.4 et antérieures, ce point est le moment où le système a été démarré. Depuis Linux 2.6, ce point est (2^32/HZ) - 300 secondes avant l'heure de démarrage du système. Cette variabilité entre les versions du noyau (et entre les implémentations UNIX), combinée au fait que la valeur retournée peut dépasser la plage de clock_t, signifie qu'une application portable ferait bien d'éviter d'utiliser cette valeur. Pour mesurer les changements de temps écoulé, utilisez plutôt clock_gettime(2).

SVr1-3 renvoie long et les membres de la structure sont de type time_t bien qu'ils stockent des ticks d'horloge, pas des secondes depuis l'Epoch. V7 utilisait long pour les membres de la structure, car il n'avait pas encore de type time_t.

NOTES

Le nombre de ticks d'horloge par seconde peut être obtenu en utilisant :


sysconf(_SC_CLK_TCK);

Notez que clock(3) renvoie également une valeur de type clock_t, mais cette valeur est mesurée en unités de CLOCKS_PER_SEC, et non en ticks d'horloge utilisés par times().

BOGUES

Une limitation des conventions d'appel système Linux sur certaines architectures (notamment i386) signifie que sous Linux 2.6, il existe une petite fenêtre temporelle (41 secondes) peu après le démarrage où times() peut retourner -1, indiquant faussement qu'une erreur s'est produite. Le même problème peut survenir lorsque la valeur de retour dépasse la valeur maximale pouvant être stockée dans clock_t.

VOIR AUSSI

time(1), getrusage(2), wait(2), clock(3), sysconf(3), time(7)
