NOM

tidy - vérifier, corriger et présenter joliment les fichiers HTML(5)

SYNTAXE

tidy [options] [fichier ...] [options] [fichier ...] ...

DESCRIPTION

Tidy lit les fichiers HTML, XHTML et XML et écrit le balisage nettoyé. Pour les variantes HTML, il détecte, signale et corrige de nombreuses erreurs de codage courantes et s'efforce de produire un balisage visuellement équivalent, conforme aux spécifications HTML et fonctionnel dans la plupart des navigateurs.

Une utilisation courante de Tidy est de convertir du HTML brut en XHTML. Pour les fichiers XML génériques, Tidy se limite à corriger les erreurs de base de bien-formé et à présenter joliment le code.

Si aucun fichier d'entrée n'est spécifié, Tidy lit l'entrée standard. Si aucun fichier de sortie n'est spécifié, Tidy écrit le balisage nettoyé dans la sortie standard. Si aucun fichier d'erreur n'est spécifié, Tidy écrit les messages dans la sortie d'erreur standard.

OPTIONS

Tidy prend en charge deux types d'options. Les options purement de ligne de commande, commençant par un seul tiret '-', ne peuvent être utilisées que sur la ligne de commande, pas dans les fichiers de configuration. Elles sont listées dans la première partie de cette section. Les options de configuration, en revanche, peuvent être passées sur la ligne de commande, commençant par deux tirets --, ou spécifiées dans un fichier de configuration, en utilisant le nom de l'option, suivi de deux points :, plus la valeur, sans les tirets de départ. Elles sont listées dans la seconde partie de cette section, avec un exemple de fichier de configuration.

Pour les options de ligne de commande qui attendent un argument numérique, une valeur par défaut est supposée si aucune valeur significative ne peut être trouvée. En revanche, les options de configuration ne peuvent pas être utilisées sans valeur ; une option de configuration sans valeur est simplement ignorée et signalée comme une erreur.

L'utilisation d'une option de ligne de commande est parfois équivalente à la définition de la valeur d'une option de configuration. L'option et la valeur équivalentes sont indiquées entre parenthèses dans la liste ci-dessous, telles qu'elles apparaîtraient dans un fichier de configuration. Par exemple, -quiet, -q (quiet: yes) signifie que l'utilisation de l'option de ligne de commande -quiet ou -q est équivalente à la définition de l'option de configuration quiet à yes.

Les options de ligne de commande à lettre unique sans valeur associée peuvent être combinées ; par exemple, '-i', '-m' et '-u' peuvent être combinés en '-imu'.

Les options de configuration peuvent être spécifiées en faisant précéder chaque option de -- sur la ligne de commande, suivie de la valeur souhaitée, OU en plaçant les options et les valeurs dans un fichier de configuration, et en demandant à tidy de lire ce fichier avec l'option -config :


tidy --option1 valeur1 --option2 valeur2 ...
tidy -config fichier-config ...

Les options de configuration peuvent être regroupées de manière pratique dans un seul fichier de configuration. Un fichier de configuration Tidy est simplement un fichier texte, où chaque option est listée sur une ligne distincte sous la forme


option1: valeur1
option2: valeur2
etc.

Les valeurs autorisées pour une option donnée dépendent du Type de l'option. Il existe cinq Types : Booléen, AutoBool, DocType, Enum et String. Les Types Booléen autorisent n'importe lequel de yes/no, y/n, true/false, t/f, 1/0. Les Types AutoBool autorisent auto en plus des valeurs autorisées par les Booléens. Les Types Entier acceptent des entiers non négatifs. Les Types String n'ont généralement pas de valeurs par défaut, et vous devriez les fournir sous forme non citée (sauf si vous souhaitez que la sortie contienne les guillemets littéraux).

Les Types Enum, Encoding et DocType ont un répertoire fixe d'éléments, qui sont listés dans les sections Valeurs prises en charge ci-dessous.

Vous n'avez besoin de fournir que les options et les valeurs pour celles dont vous souhaitez remplacer les valeurs par défaut, bien que vous puissiez souhaiter inclure certaines options et valeurs déjà par défaut pour des raisons de documentation et d'explicité.

Voici un exemple de fichier de configuration, avec au moins un exemple de chacun des cinq Types :


// exemples d'options de configuration Tidy
output-xhtml: yes
add-xml-decl: no
doctype: strict
char-encoding: ascii
indent: auto
wrap: 76
repeated-attributes: keep-last
error-file: errs.txt

Ci-dessous un résumé et une brève description de chacune des options. Elles sont listées par ordre alphabétique au sein de chaque catégorie.

Options d'affichage du document

--gnu-emacs Boolean (no si non défini)

Cette option spécifie que Tidy doit modifier le format de rapport des erreurs et avertissements pour qu'il soit plus facilement analysable par GNU Emacs ou un autre programme. Il les change du format par défaut


line <numéro de ligne> column <numéro de colonne> - (Error|Warning): <message>

à une forme qui inclut le nom du fichier d'entrée :


<nom du fichier>:<numéro de ligne>:<numéro de colonne>: (Error|Warning): <message>

Voir aussi : --show-filename

--markup Boolean (yes si non défini)

Cette option spécifie si Tidy doit générer une version joliment formatée du code source. Notez que Tidy ne générera pas une version joliment formatée s'il trouve des erreurs significatives (voir force-output).
--mute String

Utilisez cette option pour empêcher Tidy d'afficher certains types de rapports de sortie, par exemple, pour des conditions que vous souhaitez ignorer.

Cette option prend une liste d'une ou plusieurs clés indiquant le type de message à ignorer. Vous pouvez découvrir ces clés de message en utilisant l'option de configuration mute-id et en examinant la sortie de Tidy.

Voir aussi : --mute-id

--mute-id Boolean (no si non défini)

Cette option indique si Tidy doit afficher les identifiants de message avec chacun de ses rapports d'erreurs. Cela pourrait être utile si vous vouliez utiliser l'option de configuration mute pour filtrer certains messages de rapport.

Voir aussi : --mute

--quiet Boolean (no si non défini)

Lorsque activée, cette option limite la sortie non document de Tidy à ne signaler que les avertissements et erreurs de document.
--show-body-only Enum (no si non défini)

Valeurs prises en charge : no, yes, auto

Cette option spécifie si Tidy doit imprimer uniquement le contenu de la balise body sous forme de fragment HTML.

Si définie sur auto, cela est effectué uniquement si la balise body a été inférée.

Utile pour incorporer des pages entières existantes comme partie d'une autre page.

Cette option n'a aucun effet si une sortie XML est demandée.

--show-errors Integer (6 si non défini)

Cette option spécifie le nombre que Tidy utilise pour déterminer si des erreurs supplémentaires doivent être affichées. Si elle est définie sur 0, aucune erreur n'est affichée.
--show-filename Boolean (no si non défini)

Cette option spécifie si Tidy doit afficher le nom du fichier dans les messages. par exemple :


tidy -q -e --show-filename yes index.html


index.html: line 43 column 3 - Warning: replacing invalid UTF-8 bytes (char. code U+00A9)

Voir aussi : --gnu-emacs

--show-info Boolean (yes si non défini)

Cette option spécifie si Tidy doit afficher les messages de niveau information.
--show-warnings Boolean (yes si non défini)

Cette option spécifie si Tidy doit supprimer les avertissements. Cela peut être utile lorsque quelques erreurs sont masquées dans un flot d'avertissements.

Options d'entrée et de sortie du document

--add-meta-charset Boolean (no si non défini)

Cette option, lorsqu'elle est activée, ajoute un élément <meta> et définit l'attribut charset sur l'encodage du document. Définissez cette option sur yes pour l'activer.
--add-xml-decl Boolean (no si non défini)

Cette option spécifie si Tidy doit ajouter la déclaration XML lors de la sortie XML ou XHTML.

Notez que si l'entrée inclut déjà une déclaration <?xml ... ?>, cette option sera ignorée.

Si l'encodage de la sortie est différent de ascii, l'un des encodages utf*, ou raw, alors la déclaration est toujours ajoutée comme requis par la norme XML.

Voir aussi : --char-encoding, --output-encoding

--add-xml-space Boolean (no si non défini)

Cette option spécifie si Tidy doit ajouter xml:space="preserve" aux éléments tels que <pre>, <style> et <script> lors de la génération de XML.

Ceci est nécessaire si les espaces blancs dans de tels éléments doivent être analysés correctement sans avoir accès à la DTD.

--doctype String (auto si non défini)

Cette option spécifie la déclaration DOCTYPE générée par Tidy.

Si définie sur omit, la sortie ne contiendra pas de déclaration DOCTYPE. Notez que cela implique également que numeric-entities est défini sur yes.

Si définie sur html5, la DOCTYPE est définie sur <!DOCTYPE html>.

Si définie sur auto (par défaut), Tidy utilisera une estimation éclairée basée sur le contenu du document. Notez que la sélection de cette option ne modifiera pas la DOCTYPE du document actuel lors de la sortie.

Si définie sur strict, Tidy définira la DOCTYPE sur la DTD stricte HTML4 ou XHTML1.

Si définie sur loose, la DOCTYPE est définie sur la DTD lâche (transitoire) HTML4 ou XHTML1.

Alternativement, vous pouvez fournir une chaîne pour l'identifiant public formel (FPI).

Par exemple :

doctype: "-//ACME//DTD HTML 3.14159//EN"

Si vous spécifiez le FPI pour un document XHTML, Tidy définira l'identifiant système sur une chaîne vide. Pour un document HTML, Tidy ajoute un identifiant système uniquement s'il était déjà présent afin de préserver le mode de traitement de certains navigateurs. Tidy laisse la DOCTYPE pour les documents XML génériques inchangée.

Cette option n'offre pas de validation de la conformité du document.

--input-xml Boolean (no si non défini)

Cette option spécifie si Tidy doit utiliser l'analyseur XML plutôt que l'analyseur HTML à correction d'erreurs.
--output-html Booléen (non si non défini)

Cette option spécifie si Tidy doit générer une sortie formatée en HTML.
--output-xhtml Booléen (non si non défini)

Cette option spécifie si Tidy doit générer une sortie formatée en extensible HTML.

Cette option amène Tidy à définir le DOCTYPE et l'espace de noms par défaut appropriés à XHTML, et utilisera la valeur corrigée en sortie, quelle que soit la source.

Pour XHTML, les entités peuvent être écrites sous forme d'entités nommées ou numériques, conformément au réglage de numeric-entities.

La casse d'origine des balises et des attributs sera préservée, quelles que soient les autres options.

--output-xml Booléen (non si non défini)

Cette option spécifie si Tidy doit formater la sortie en XML bien formé.

Toutes les entités non définies dans XML 1.0 seront écrites sous forme d'entités numériques pour permettre leur analyse par un analyseur XML.

La casse d'origine des balises et des attributs sera préservée, quelles que soient les autres options.

Options d'entrée/sortie de fichiers

--error-file Chaîne

Cette option spécifie le fichier d'erreurs que Tidy utilise pour les erreurs et les avertissements. Normalement, les erreurs et les avertissements sont envoyés à stderr.

Voir aussi : --output-file

--keep-time Booléen (non si non défini)

Cette option spécifie si Tidy doit conserver l'heure de modification d'origine des fichiers que Tidy modifie sur place.

Régler l'option sur oui permet de nettoyer les fichiers sans modifier la date de modification du fichier, ce qui peut être utile avec certains outils qui utilisent la date de modification pour des choses comme le déploiement automatique sur serveur.

Notez que cette fonctionnalité n'est pas prise en charge sur certaines plateformes.

--output-file Chaîne

Cette option spécifie le fichier de sortie que Tidy utilise pour le balisage. Normalement, le balisage est écrit sur stdout.

Voir aussi : --error-file

--write-back Booléen (non si non défini)

Cette option spécifie si Tidy doit réécrire le balisage nettoyé dans le même fichier qu'il a lu.

Il est conseillé de conserver des copies des fichiers importants avant de les nettoyer, car dans de rares cas, le résultat peut ne pas être celui attendu.

Options de diagnostic

--accessibility-check Enum (0 (Tidy Classic) si non défini)

Valeurs prises en charge : 0 (Tidy Classic), 1 (Vérifications de priorité 1), 2 (Vérifications de priorité 2), 3 (Vérifications de priorité 3)

Cette option spécifie le niveau de vérification d'accessibilité, le cas échéant, que Tidy doit effectuer.

Le niveau 0 (Tidy Classic) est équivalent à la vérification d'accessibilité de Tidy Classic.

Pour plus d'informations sur la vérification d'accessibilité de Tidy, visitez la page Accessibilité de Tidy à l'adresse http://www.html-tidy.org/accessibility/.

--force-output Booléen (non si non défini)

Cette option spécifie si Tidy doit produire une sortie même en cas d'erreurs.

Utilisez cette option avec prudence ; si Tidy signale une erreur, cela signifie que Tidy n'a pas pu corriger l'erreur (ou n'est pas sûr de comment le faire), de sorte que la sortie résultante peut ne pas refléter votre intention.

--show-meta-change Booléen (non si non défini)

Cette option active un message chaque fois que Tidy modifie l'attribut content d'une déclaration meta charset pour correspondre à l'encodage du document. Définissez cette option sur oui pour l'activer.
--warn-proprietary-attributes Booléen (oui si non défini)

Cette option spécifie si Tidy doit émettre un avertissement sur les attributs propriétaires.

Options d'encodage

--char-encoding Encodage (utf8 si non défini)

Valeurs prises en charge : raw, ascii, latin0, latin1, utf8, iso2022, mac, win1252, ibm858, utf16le, utf16be, utf16, big5, shiftjis

Cette option spécifie l'encodage de caractères que Tidy utilise pour l'entrée, et lorsqu'il est défini, choisit automatiquement un encodage de caractères approprié pour la sortie. L'encodage de sortie choisi par Tidy peut être différent de l'encodage d'entrée.

Pour les encodages d'entrée ascii, latin0, ibm858, mac et win1252, l'option output-encoding sera automatiquement définie sur ascii. Vous pouvez définir manuellement output-encoding pour remplacer cela.

Pour les autres encodages d'entrée, l'option output-encoding sera automatiquement définie sur la même valeur.

Indépendamment de la valeur prédéfinie, vous pouvez définir manuellement output-encoding pour remplacer cela.

Tidy n'est pas un convertisseur d'encodage. Bien que les encodages Latin et UTF puissent être mélangés librement, il n'est pas possible de convertir les encodages asiatiques en encodages latins avec Tidy.

Voir aussi : --input-encoding, --output-encoding

--input-encoding Encodage (utf8 si non défini)

Valeurs prises en charge : raw, ascii, latin0, latin1, utf8, iso2022, mac, win1252, ibm858, utf16le, utf16be, utf16, big5, shiftjis

Cette option spécifie l'encodage de caractères que Tidy utilise pour l'entrée. Tidy fait certaines suppositions sur certains des encodages d'entrée.

Pour ascii, Tidy acceptera les valeurs de caractères Latin-1 (ISO-8859-1) et les convertira en entités si nécessaire.

Pour raw, Tidy ne fera aucune supposition sur les valeurs de caractères et les passera inchangées à la sortie.

Pour mac et win1252, les valeurs de caractères spécifiques au fournisseur seront acceptées et converties en entités si nécessaire.

Les encodages asiatiques tels que iso2022 seront traités de manière appropriée, à condition que le output-encoding correspondant soit également spécifié.

Tidy n'est pas un convertisseur d'encodage. Bien que les encodages Latin et UTF puissent être mélangés librement, il n'est pas possible de convertir les encodages asiatiques en encodages latins avec Tidy.

Voir aussi : --char-encoding

--newline Enum (LF si non défini)

Valeurs prises en charge : LF, CRLF, CR

La valeur par défaut est appropriée à la plateforme actuelle.

Généralement CRLF sur PC-DOS, Windows et OS/2 ; CR sur les systèmes Mac OS classiques ; et LF partout ailleurs (Linux, macOS et Unix).

--output-bom Enum (auto si non défini)

Valeurs prises en charge : no, yes, auto

Cette option spécifie si Tidy doit écrire un caractère Unicode Byte Order Mark (BOM ; également connu sous le nom d'espace insécable sans largeur ; valeur U+FEFF) au début de la sortie, et ne s'applique qu'aux encodages de sortie UTF-8 et UTF-16.

Si cette option est définie sur auto, Tidy écrira un BOM en sortie uniquement si un BOM était présent au début de l'entrée.

Un BOM est toujours écrit pour les sorties XML/XHTML utilisant les encodages de sortie UTF-16.

--output-encoding Encodage (utf8 si non défini)

Valeurs prises en charge : raw, ascii, latin0, latin1, utf8, iso2022, mac, win1252, ibm858, utf16le, utf16be, utf16, big5, shiftjis

Cette option spécifie l'encodage de caractères que Tidy utilise pour la sortie. Certains des encodages de sortie affectent si certains caractères sont traduits en entités, bien que dans tous les cas, certaines entités seront écrites conformément aux autres options de configuration de Tidy.

Pour les encodages de sortie ascii, mac et win1252, des entités seront utilisées pour tous les caractères de valeur supérieure à 127.

Pour la sortie raw, Tidy écrira les valeurs supérieures à 127 sans les traduire en entités.

La sortie en latin1 amènera Tidy à écrire les valeurs de caractères supérieures à 255 sous forme d'entités.

La famille UTF telle que utf8 écrira la sortie dans l'encodage UTF respectif.

Les encodages de sortie asiatiques tels que iso2022 écriront la sortie dans l'encodage spécifié, en supposant qu'un input-encoding correspondant a été spécifié.

Tidy n'est pas un convertisseur d'encodage. Bien que les encodages Latin et UTF puissent être mélangés librement, il n'est pas possible de convertir les encodages asiatiques en encodages latins avec Tidy.

Voir aussi : --char-encoding

Options de nettoyage

--bare Booléen (non si non défini)

Cette option spécifie si Tidy doit remplacer les guillemets intelligents et les tirets cadratins par des caractères ASCII, et sortir des espaces plutôt que des espaces insécables, là où ils existent dans l'entrée.
--clean Booléen (non si non défini)

Cette option spécifie si Tidy doit effectuer un nettoyage de certaines balises de présentation héritées (actuellement <i>, <b>, <center> avec

Options de nettoyage

--clean Boolean (yes if unset)

This option specifies if Tidy should move tags to the most logical place in the document. It is not intended to modify the markup itself, but rather to move tags around, for example, to move <b> tags out of <p> tags. Tidy tries to enforce the document structure implied by the HTML DTD.

This option is set to yes by default, and is intended to make clean HTML output.

In addition to moving tags, this option also handles the replacement of legacy tags with CSS <style> tags, and structural markup when appropriate.

--drop-empty-elements Boolean (yes if unset)

This option specifies if Tidy should discard empty elements.
--drop-empty-paras Boolean (yes if unset)

This option specifies if Tidy should discard empty paragraphs.
--drop-proprietary-attributes Boolean (no if unset)

This option specifies if Tidy should strip out proprietary attributes, such as Microsoft data binding attributes. Additionally attributes that aren't permitted in the output version of HTML will be dropped if used with strict-tags-attributes.
--gdoc Boolean (no if unset)

This option specifies if Tidy should enable specific behavior for cleaning up HTML exported from Google Docs.
--logical-emphasis Boolean (no if unset)

This option specifies if Tidy should replace any occurrence of <i> with <em> and any occurrence of <b> with <strong>. Any attributes are preserved unchanged.

This option can be set independently of the clean option.

--merge-divs Enum (auto if unset)

Supported values: no, yes, auto

This option can be used to modify the behavior of clean when set to yes.

This option specifies if Tidy should merge nested <div> such as <div><div>...</div></div>.

If set to auto the attributes of the inner <div> are moved to the outer one. Nested <div> with id attributes are not merged.

If set to yes the attributes of the inner <div> are discarded with the exception of class and style.

See also: --clean, --merge-spans

--merge-spans Enum (auto if unset)

Supported values: no, yes, auto

This option can be used to modify the behavior of clean when set to yes.

This option specifies if Tidy should merge nested <span> such as <span><span>...</span></span>.

The algorithm is identical to the one used by merge-divs.

See also: --clean, --merge-divs

--word-2000 Boolean (no if unset)

This option specifies if Tidy should go to great pains to strip out all the surplus stuff Microsoft Word 2000 inserts when you save Word documents as "Web pages". It doesn't handle embedded images or VML.

You should consider saving using Word's Save As..., and choosing Web Page, Filtered.

Options d'entités

--ascii-chars Boolean (no if unset)

Can be used to modify behavior of the clean option when set to yes.

If set to yes when using clean, &emdash;, &rdquo;, and other named character entities are downgraded to their closest ASCII equivalents.

See also: --clean

--ncr Boolean (yes if unset)

This option specifies if Tidy should allow numeric character references.
--numeric-entities Boolean (no if unset)

This option specifies if Tidy should output entities other than the built-in HTML entities (&amp;, &lt;, &gt;, and &quot;) in the numeric rather than the named entity form.

Only entities compatible with the DOCTYPE declaration generated are used.

Entities that can be represented in the output encoding are translated correspondingly.

See also: --doctype, --preserve-entities

--preserve-entities Boolean (no if unset)

This option specifies if Tidy should preserve well-formed entities as found in the input.
--quote-ampersand Boolean (yes if unset)

This option specifies if Tidy should output unadorned & characters as &amp;, in legacy doctypes only.
--quote-marks Boolean (no if unset)

This option specifies if Tidy should output " characters as &quot; as is preferred by some editing environments.

The apostrophe character ' is written out as &#39; since many web browsers don't yet support &apos;.

--quote-nbsp Boolean (yes if unset)

This option specifies if Tidy should output non-breaking space characters as entities, rather than as the Unicode character value 160 (decimal).

Options de réparation

--alt-text String

This option specifies the default alt= text Tidy uses for <img> attributes when the alt= attribute is missing.

Use with care, as it is your responsibility to make your documents accessible to people who cannot see the images.

--anchor-as-name Boolean (yes if unset)

This option controls the deletion or addition of the name attribute in elements where it can serve as anchor.

If set to yes a name attribute, if not already existing, is added along an existing id attribute if the DTD allows it.

If set to no any existing name attribute is removed if an id attribute exists or has been added.

--assume-xml-procins Boolean (no if unset)

This option specifies if Tidy should change the parsing of processing instructions to require ?> as the terminator rather than >.

This option is automatically set if the input is in XML.

--coerce-endtags Boolean (yes if unset)

This option specifies if Tidy should coerce a start tag into an end tag in cases where it looks like an end tag was probably intended; for example, given

<span>foo <b>bar<b> baz</span>

Tidy will output

<span>foo <b>bar</b> baz</span>

--css-prefix String (c if unset)

This option specifies the prefix that Tidy uses for styles rules.

By default, c will be used.

--custom-tags Enum (no if unset)

Supported values: no, blocklevel, empty, inline, pre

This option enables the use of tags for autonomous custom elements, e.g. <flag-icon> with Tidy. Custom tags are disabled if this value is no. Other settings - blocklevel, empty, inline, and pre will treat all detected custom tags accordingly.

The use of new-blocklevel-tags, new-empty-tags, new-inline-tags, or new-pre-tags will override the treatment of custom tags by this configuration option. This may be useful if you have different types of custom tags.

When enabled these tags are determined during the processing of your document using opening tags; matching closing tags will be recognized accordingly, and unknown closing tags will be discarded.

See also: --new-blocklevel-tags, --new-empty-tags, --new-inline-tags, --new-pre-tags

--enclose-block-text Boolean (no if unset)

This option specifies if Tidy should insert a <p> element to enclose any text it finds in any element that allows mixed content for HTML transitional but not HTML strict.
--enclose-text Boolean (no if unset)

This option specifies if Tidy should enclose any text it finds in the body element within a <p> element.

This is useful when you want to take existing HTML and use it with a style sheet.

--escape-scripts Boolean (yes if unset)

This option causes items that look like closing tags, like </g to be escaped to <\/g. Set this option to no if you do not want this.
--fix-backslash Boolean (yes if unset)

This option specifies if Tidy s
--fix-bad-backslash Boolean (yes if unset)

This option specifies that Tidy should replace backslash characters \ in URLs with forward slashes /.
--fix-bad-comments Enum (auto si non défini)

Valeurs supportées : no, yes, auto

Cette option spécifie si Tidy doit remplacer les tirets inattendus par des caractères = lorsqu'il rencontre des tirets adjacents.

La valeur par défaut est auto, qui agira comme no pour les types de documents HTML5 et comme yes pour tous les autres types de documents.

HTML a abandonné la syntaxe de commentaire SGML et autorise les tirets adjacents pour toutes les versions de HTML, bien que XML et XHTML ne le fassent pas. Si vous prévoyez de prendre en charge les anciens navigateurs qui nécessitent la syntaxe de commentaire SGML, envisagez de définir cette valeur sur yes.

--fix-style-tags Booléen (yes si non défini)

Cette option spécifie si Tidy doit déplacer toutes les balises de style vers l'en-tête du document.
--fix-uri Booléen (yes si non défini)

Cette option spécifie si Tidy doit vérifier les valeurs d'attributs qui transportent des URI pour les caractères illégaux et, si de tels caractères sont trouvés, les échapper comme le recommande HTML4.
--literal-attributes Booléen (no si non défini)

Cette option spécifie comment Tidy traite les caractères d'espacement dans les valeurs d'attributs.

Si la valeur est no, Tidy normalise les valeurs d'attributs en remplaçant toute nouvelle ligne ou tabulation par un seul espace, et en remplaçant en outre tout espacement contigu par un seul espace.

Pour forcer Tidy à préserver les valeurs originales et littérales de tous les attributs et à garantir que les espaces blancs dans les valeurs d'attributs sont transmis inchangés, définissez cette option sur yes.

--lower-literals Booléen (yes si non défini)

Cette option spécifie si Tidy doit convertir la valeur d'un attribut qui accepte une liste de valeurs prédéfinies en minuscules.

Ceci est requis pour les documents XHTML.

--repeated-attributes Enum (keep-last si non défini)

Valeurs supportées : keep-first, keep-last

Cette option spécifie si Tidy doit conserver le premier ou le dernier attribut, si un attribut est répété, par exemple, s'il y a deux attributs align.

Voir aussi : --join-classes, --join-styles

--skip-nested Booléen (yes si non défini)

Cette option spécifie que Tidy doit ignorer les balises imbriquées lors de l'analyse des données de script et de style.
--strict-tags-attributes Booléen (no si non défini)

Cette option garantit que les balises et les attributs sont applicables à la version de HTML que Tidy génère. Lorsqu'elle est définie sur yes et que le type de document de sortie est un doctype strict, Tidy signalera des erreurs. Si le type de document de sortie est un doctype lâche ou transitionnel, Tidy signalera des avertissements.

De plus, si drop-proprietary-attributes est activé, les attributs non applicables seront également supprimés.

Lorsque défini sur no, ces vérifications ne sont pas effectuées.

--uppercase-attributes Enum (no si non défini)

Valeurs supportées : no, yes, preserve

Cette option spécifie si Tidy doit afficher les noms d'attributs en majuscules.

Lorsque défini sur no, les noms d'attributs seront écrits en minuscules. La spécification de yes affichera les noms d'attributs en majuscules, et preserve peut être utilisé pour laisser les noms d'attributs inchangés.

Lors de l'utilisation d'une entrée XML, la casse d'origine est toujours préservée.

--uppercase-tags Booléen (no si non défini)

Cette option spécifie si Tidy doit afficher les noms de balises en majuscules.

La valeur par défaut est no, ce qui entraîne des noms de balises en minuscules, sauf pour les entrées XML où la casse d'origine est préservée.

Options de transformation

--decorate-inferred-ul Booléen (no si non défini)

Cette option spécifie si Tidy doit décorer les éléments <ul> inférés avec du balisage CSS pour éviter une indentation vers la droite.
--escape-cdata Booléen (no si non défini)

Cette option spécifie si Tidy doit convertir les sections <![CDATA[]]> en texte normal.
--hide-comments Booléen (no si non défini)

Cette option spécifie si Tidy ne doit pas afficher les commentaires.
--join-classes Booléen (no si non défini)

Cette option spécifie si Tidy doit combiner les noms de classe pour générer un seul nouveau nom de classe si plusieurs affectations de classe sont détectées sur un élément.
--join-styles Booléen (yes si non défini)

Cette option spécifie si Tidy doit combiner les styles pour générer un seul nouveau style si plusieurs valeurs de style sont détectées sur un élément.
--merge-emphasis Booléen (yes si non défini)

Cette option spécifie si Tidy doit fusionner les éléments <b> et <i> imbriqués ; par exemple, pour le cas

<b class="rtop-2">foo <b class="r2-2">bar</b> baz</b>,

Tidy affichera <b class="rtop-2">foo bar baz</b>.

--replace-color Booléen (no si non défini)

Cette option spécifie si Tidy doit remplacer les valeurs numériques dans les attributs de couleur par des noms de couleur HTML/XHTML là où ils sont définis, par exemple, remplacer #ffffff par white.

Options d'apprentissage de Tidy

--new-blocklevel-tags Noms de balises

Valeurs supportées : tagX, tagY, ...

Cette option spécifie de nouvelles balises de niveau bloc. Cette option prend une liste de noms de balises séparés par des espaces ou des virgules.

À moins que vous ne déclariez de nouvelles balises, Tidy refusera de générer un fichier nettoyé si l'entrée inclut des balises inconnues auparavant.

Notez que vous ne pouvez pas modifier le modèle de contenu pour des éléments tels que <table>, <ul>, <ol> et <dl>.

Cette option est ignorée en mode XML.

Voir aussi : --new-empty-tags, --new-inline-tags, --new-pre-tags, --custom-tags

--new-empty-tags Noms de balises

Valeurs supportées : tagX, tagY, ...

Cette option spécifie de nouvelles balises inline vides. Cette option prend une liste de noms de balises séparés par des espaces ou des virgules.

À moins que vous ne déclariez de nouvelles balises, Tidy refusera de générer un fichier nettoyé si l'entrée inclut des balises inconnues auparavant.

N'oubliez pas de déclarer également les balises vides comme étant soit inline, soit de niveau bloc.

Cette option est ignorée en mode XML.

Voir aussi : --new-blocklevel-tags, --new-inline-tags, --new-pre-tags, --custom-tags

--new-inline-tags Noms de balises

Valeurs supportées : tagX, tagY, ...

Cette option spécifie de nouvelles balises inline non vides. Cette option prend une liste de noms de balises séparés par des espaces ou des virgules.

À moins que vous ne déclariez de nouvelles balises, Tidy refusera de générer un fichier nettoyé si l'entrée inclut des balises inconnues auparavant.

Cette option est ignorée en mode XML.

Voir aussi : --new-blocklevel-tags, --new-empty-tags, --new-pre-tags, --custom-tags

--new-pre-tags Noms de balises

Valeurs supportées : tagX, tagY, ...

Cette option spécifie de nouvelles balises qui doivent être traitées exactement de la même manière que l'élément <pre> de HTML. Cette option prend une liste de noms de balises séparés par des espaces ou des virgules.

À moins que vous ne déclariez de nouvelles balises, Tidy refusera de générer un fichier nettoyé si l'entrée inclut des balises inconnues auparavant.

Notez que vous ne pouvez pas encore ajouter de nouveaux éléments CDATA.

Cette option est ignorée en mode XML.

Voir aussi : --new-blocklevel-tags, --new-empty-tags, --new-inline-tags, --custom-tags

Options de mise en page

--break-before-br Booléen (no si non défini)

Cette option spécifie si Tidy doit afficher un saut de ligne avant chaque élément <br>.
--indent Enum (no si non défini)

Valeurs supportées : no, yes, auto

Cette option spécifie si Tidy doit indenter les balises de niveau bloc.

Si définie sur auto, Tidy décidera s'il faut indenter ou non le contenu des balises telles que <title>, <h1>-<h6>, <li>, <td>, ou <p> en fonction du contenu.

incluant un élément de niveau bloc.

Régler indent à yes peut exposer des bugs de mise en page dans certains navigateurs.

Utilisez l'option indent-spaces pour contrôler le nombre d'espaces ou de tabulations par niveau d'indentation, et indent-with-tabs pour spécifier si des espaces ou des tabulations sont utilisés.

Voir aussi : --indent-spaces

--indent-attributes Boolean (no si non défini)

Cette option spécifie si Tidy doit commencer chaque attribut sur une nouvelle ligne.
--indent-cdata Boolean (no si non défini)

Cette option spécifie si Tidy doit indenter les sections <![CDATA[]]>.
--indent-spaces Integer (2 si non défini)

Cette option spécifie le nombre d'espaces ou de tabulations que Tidy utilise pour indenter le contenu lorsque indent est activé.

Notez que la valeur par défaut de cette option dépend de la valeur de indent-with-tabs (voir aussi).

Voir aussi : --indent

--indent-with-tabs Boolean (no si non défini)

Cette option spécifie si Tidy doit indenter avec des tabulations au lieu d'espaces, en supposant que indent est à yes.

Réglez-la à yes pour indenter en utilisant des tabulations au lieu des espaces par défaut.

Utilisez l'option indent-spaces pour contrôler le nombre de tabulations sorties par niveau d'indentation. Notez que lorsque indent-with-tabs est activé, la valeur par défaut de indent-spaces est réinitialisée à 1.

Notez que tab-size contrôle la conversion des tabulations d'entrée en espaces. Réglez-le à zéro pour conserver les tabulations d'entrée.

--keep-tabs Boolean (no si non défini)

Avec le no par défaut, Tidy remplacera toutes les tabulations sources par des espaces, contrôlé par l'option tab-size, et le décalage de la ligne actuelle. Bien sûr, sauf dans les blocs/éléments spéciaux énumérés ci-dessous, cela sera ensuite réduit à un seul espace.

Si réglé à yes, cette option spécifie que Tidy doit conserver certaines tabulations trouvées dans la source, mais uniquement dans les blocs préformatés comme <pre>, et d'autres éléments CDATA comme <script>, <style>, et d'autres pseudo-éléments comme <?php ... ?>. Comme toujours, toutes les autres tabulations, ou séquences de tabulations, dans la source continueront d'être remplacées par un espace.

--omit-optional-tags Boolean (no si non défini)

Cette option spécifie si Tidy doit omettre les balises de début et de fin optionnelles lors de la génération de la sortie.

La définition de cette option entraîne l'omission de toutes les balises pour les éléments <html>, <head> et <body> de la sortie, ainsi que les balises de fin comme </p>, </li>, </dt>, </dd>, </option>, </tr>, </td> et </th>.

Cette option est ignorée pour la sortie XML.

--priority-attributes Noms d'attributs

Valeurs supportées : attributeX, attributeY, ...

Cette option permet de prioriser l'écriture des attributs dans les documents nettoyés, permettant leur écriture avant les autres attributs d'un élément. Par exemple, vous pourriez spécifier que id et name soient écrits avant tout autre attribut.

Cette option prend une liste de noms d'attributs séparés par des espaces ou des virgules.

--punctuation-wrap Boolean (no si non défini)

Cette option spécifie si Tidy doit couper les lignes après certains caractères de ponctuation Unicode ou chinois.
--sort-attributes Enum (none si non défini)

Valeurs supportées : none, alpha

Cette option spécifie que Tidy doit trier les attributs au sein d'un élément en utilisant l'algorithme de tri spécifié. S'il est réglé sur alpha, l'algorithme est un tri alphabétique ascendant.

Lorsqu'il est utilisé avec priority-attributes, tout tri d'attributs aura lieu après que les attributs prioritaires aient été sortis.

Voir aussi : --priority-attributes

--tab-size Integer (8 si non défini)

Cette option spécifie le nombre de colonnes que Tidy utilise entre les arrêts de tabulation successifs. Il est utilisé pour mapper les tabulations en espaces lors de la lecture de l'entrée.
--tidy-mark Boolean (yes si non défini)

Cette option spécifie si Tidy doit ajouter un élément meta dans l'en-tête du document pour indiquer que le document a été nettoyé.

Tidy n'ajoutera pas d'élément meta s'il en existe déjà un.

--vertical-space Enum (no si non défini)

Valeurs supportées : no, yes, auto

Cette option spécifie si Tidy doit ajouter des lignes vides supplémentaires pour la lisibilité.

La valeur par défaut est no.

Si réglé sur auto, Tidy éliminera presque tous les caractères de nouvelle ligne.

--wrap Integer (68 si non défini)

Cette option spécifie la marge droite que Tidy utilise pour le retour à la ligne.

Tidy essaie de retourner à la ligne de manière à ne pas dépasser cette longueur.

Réglez wrap à 0 (zéro) si vous souhaitez désactiver le retour à la ligne.

--wrap-asp Boolean (yes si non défini)

Cette option spécifie si Tidy doit couper les lignes de texte contenu dans les pseudo-éléments ASP, qui ressemblent à : <% ... %>.
--wrap-attributes Boolean (no si non défini)

Cette option spécifie si Tidy doit couper les lignes des valeurs d'attributs, ce qui signifie que si la valeur d'un attribut provoque le dépassement d'une ligne par la largeur spécifiée par wrap, Tidy ajoutera un ou plusieurs sauts de ligne à la valeur, provoquant ainsi sa division sur plusieurs lignes.

Notez que cette option peut être définie indépendamment de wrap-script-literals. Par défaut, Tidy remplace tout saut de ligne ou tabulation par un seul espace et remplace toute séquence d'espaces blancs par un seul espace.

Pour forcer Tidy à conserver les valeurs littérales d'origine de tous les attributs, et pour s'assurer que les caractères d'espacement dans les valeurs d'attributs sont transmis tels quels, définissez literal-attributes à yes.

Voir aussi : --wrap-script-literals, --literal-attributes

--wrap-jste Boolean (yes si non défini)

Cette option spécifie si Tidy doit couper les lignes de texte contenu dans les pseudo-éléments JSTE, qui ressemblent à : <# ... #>.
--wrap-php Boolean (no si non défini)

Cette option spécifie si Tidy doit ajouter une nouvelle ligne après les pseudo-éléments PHP, qui ressemblent à : <?php ... ?>.
--wrap-script-literals Boolean (no si non défini)

Cette option spécifie si Tidy doit couper les lignes des littéraux de chaîne qui apparaissent dans les attributs de script.

Tidy coupe les longs littéraux de chaîne de script en insérant un caractère backslash avant le saut de ligne.

Voir aussi : --wrap-attributes

--wrap-sections Boolean (yes si non défini)

Cette option spécifie si Tidy doit couper les lignes de texte contenu dans les balises de section <![ ... ]>.

ENVIRONNEMENT

HTML_TIDY
Nom du fichier de configuration par défaut. Il doit s'agir d'un chemin absolu, car vous invoquerez probablement tidy à partir de différents répertoires. La valeur de HTML_TIDY sera analysée après la valeur par défaut compilée (définie avec -DTIDY_CONFIG_FILE), mais avant tous les fichiers spécifiés avec -config.
FICHIERS DE CONFIGURATION D'EXÉCUTION
Vous pouvez également spécifier des fichiers de configuration d'exécution à partir desquels tidy tentera de charger une configuration automatiquement.
Le fichier de configuration système d'exécution (/etc/tidy.conf), s'il existe, sera chargé et appliqué en premier, suivi du fichier de configuration d'exécution utilisateur (~/.tidyrc). L'utilisation ultérieure d'une option spécifique remplacera toute utilisation précédente.
Notez que si vous utilisez la variable d'environnement HTML_TIDY, le fichier de configuration d'exécution utilisateur ne sera pas utilisé. C'est une fonctionnalité, pas un bug.
