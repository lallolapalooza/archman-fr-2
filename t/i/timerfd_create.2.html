timerfd_create(2) Manuel des appels système timerfd_create(2)

NOM

timerfd_create, timerfd_settime, timerfd_gettime - minuteurs qui notifient via des descripteurs de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/timerfd.h>
int timerfd_create(int clockid, int flags);
int timerfd_settime(int fd, int flags,
                    const struct itimerspec *new_value,
                    struct itimerspec *_Nullable old_value);
int timerfd_gettime(int fd, struct itimerspec *curr_value);

DESCRIPTION

Ces appels système créent et manipulent un minuteur qui délivre des notifications d'expiration de minuteur via un descripteur de fichier. Ils offrent une alternative à l'utilisation de setitimer(2) ou timer_create(2), avec l'avantage que le descripteur de fichier peut être surveillé par select(2), poll(2) et epoll(7).

L'utilisation de ces trois appels système est analogue à l'utilisation de timer_create(2), timer_settime(2), et timer_gettime(2). (Il n'y a pas d'analogue à timer_getoverrun(2), car cette fonctionnalité est fournie par read(2), comme décrit ci-dessous.)

timerfd_create()

timerfd_create() crée un nouvel objet minuteur et renvoie un descripteur de fichier qui fait référence à ce minuteur. L'argument clockid spécifie l'horloge utilisée pour marquer la progression du minuteur, et doit être l'un des suivants :

CLOCK_REALTIME
Une horloge temps réel système configurable.
CLOCK_MONOTONIC
Une horloge monotone incrémentielle non configurable qui mesure le temps à partir d'un point indéterminé du passé qui ne change pas après le démarrage du système.
CLOCK_BOOTTIME (depuis Linux 3.15)
Comme CLOCK_MONOTONIC, c'est une horloge monotone incrémentielle. Cependant, tandis que l'horloge CLOCK_MONOTONIC ne mesure pas le temps pendant lequel un système est suspendu, l'horloge CLOCK_BOOTTIME inclut le temps pendant lequel le système est suspendu. Ceci est utile pour les applications qui doivent être conscientes de la suspension. CLOCK_REALTIME ne convient pas pour de telles applications, car cette horloge est affectée par des changements discontinus de l'horloge système.
CLOCK_REALTIME_ALARM (depuis Linux 3.11)
Cette horloge est similaire à CLOCK_REALTIME, mais réveillera le système s'il est suspendu. L'appelant doit posséder la capacité CAP_WAKE_ALARM pour pouvoir régler un minuteur contre cette horloge.
CLOCK_BOOTTIME_ALARM (depuis Linux 3.11)
Cette horloge est similaire à CLOCK_BOOTTIME, mais réveillera le système s'il est suspendu. L'appelant doit posséder la capacité CAP_WAKE_ALARM pour pouvoir régler un minuteur contre cette horloge.

Voir clock_getres(2) pour plus de détails sur les horloges mentionnées ci-dessus.

La valeur actuelle de chacune de ces horloges peut être obtenue en utilisant clock_gettime(2).

À partir de Linux 2.6.27, les valeurs suivantes peuvent être combinées par OR bit à bit dans flags pour modifier le comportement de timerfd_create():

TFD_NONBLOCK
Définit le drapeau d'état de fichier O_NONBLOCK sur la description de fichier ouverte (voir open(2)) référencée par le nouveau descripteur de fichier. L'utilisation de ce drapeau évite des appels supplémentaires à fcntl(2) pour obtenir le même résultat.
TFD_CLOEXEC
Définit le drapeau de fermeture à l'exécution (FD_CLOEXEC) sur le nouveau descripteur de fichier. Voir la description du drapeau O_CLOEXEC dans open(2) pour comprendre pourquoi cela peut être utile.

Dans les versions de Linux jusqu'à et y compris 2.6.26, flags doit être spécifié comme zéro.

timerfd_settime()

timerfd_settime() arme (démarre) ou désarme (arrête) le minuteur référencé par le descripteur de fichier fd.

L'argument new_value spécifie l'expiration initiale et l'intervalle pour le minuteur. La structure itimerspec utilisée pour cet argument est décrite dans itimerspec(3type).

new_value.it_value spécifie l'expiration initiale du minuteur, en secondes et nanosecondes. La définition de l'un ou l'autre champ de new_value.it_value à une valeur non nulle arme le minuteur. La définition des deux champs de new_value.it_value à zéro désarme le minuteur.

La définition d'un ou des deux champs de new_value.it_interval à des valeurs non nulles spécifie la période, en secondes et nanosecondes, pour les expirations répétées du minuteur après l'expiration initiale. Si les deux champs de new_value.it_interval sont nuls, le minuteur expire une seule fois, au moment spécifié par new_value.it_value.

Par défaut, le temps d'expiration initial spécifié dans new_value est interprété par rapport au temps actuel sur l'horloge du minuteur au moment de l'appel (c'est-à-dire, new_value.it_value spécifie un temps relatif à la valeur actuelle de l'horloge spécifiée par clockid). Un délai absolu peut être sélectionné via l'argument flags.

L'argument flags est un masque de bits qui peut inclure les valeurs suivantes :

TFD_TIMER_ABSTIME
Interprète new_value.it_value comme une valeur absolue sur l'horloge du minuteur. Le minuteur expirera lorsque la valeur de l'horloge du minuteur atteindra la valeur spécifiée dans new_value.it_value.
TFD_TIMER_CANCEL_ON_SET
Si ce drapeau est spécifié avec TFD_TIMER_ABSTIME et que l'horloge de ce minuteur est CLOCK_REALTIME ou CLOCK_REALTIME_ALARM, alors marquez ce minuteur comme annulable si l'horloge temps réel subit un changement discontinu (settimeofday(2), clock_settime(2), ou similaire). Lorsque de tels changements surviennent, une lecture actuelle ou future (read(2)) du descripteur de fichier échouera avec l'erreur ECANCELED.

Si l'argument old_value n'est pas NULL, alors la structure itimerspec sur laquelle il pointe est utilisée pour renvoyer le réglage du minuteur qui était actuel au moment de l'appel ; voir la description de timerfd_gettime() ci-après.

timerfd_gettime()

timerfd_gettime() renvoie, dans curr_value, une structure itimerspec qui contient le réglage actuel du minuteur référencé par le descripteur de fichier fd.

Le champ it_value renvoie le temps restant avant la prochaine expiration du minuteur. Si les deux champs de cette structure sont nuls, alors le minuteur est actuellement désarmé. Ce champ contient toujours une valeur relative, indépendamment du fait que le drapeau TFD_TIMER_ABSTIME ait été spécifié lors du réglage du minuteur.

Le champ it_interval renvoie l'intervalle du minuteur. Si les deux champs de cette structure sont nuls, alors le minuteur est réglé pour expirer une seule fois, au moment spécifié par curr_value.it_value.

Manipulation d'un descripteur de fichier de minuteur

Le descripteur de fichier renvoyé par timerfd_create() prend en charge les opérations supplémentaires suivantes :

read(2)
Si le minuteur a déjà expiré une ou plusieurs fois depuis que ses paramètres ont été modifiés pour la dernière fois à l'aide de timerfd_settime(), ou depuis la dernière opération de lecture(2) réussie, le tampon fourni à lecture(2) renvoie un entier non signé de 8 octets (uint64_t) contenant le nombre d'expirations qui se sont produites. (La valeur renvoyée est en ordre d'octets hôte, c'est-à-dire l'ordre d'octets natif pour les entiers sur la machine hôte.)
Si aucune expiration de minuteur ne s'est produite au moment de la lecture(2), l'appel se bloque jusqu'à la prochaine expiration du minuteur, ou échoue avec l'erreur EAGAIN si le descripteur de fichier a été rendu non bloquant (via l'utilisation de l'opération fcntl(2) F_SETFL pour définir le drapeau O_NONBLOCK).
Une lecture(2) échoue avec l'erreur EINVAL si la taille du tampon fourni est inférieure à 8 octets.
Si l'horloge associée est CLOCK_REALTIME ou CLOCK_REALTIME_ALARM, que le minuteur est absolu (TFD_TIMER_ABSTIME) et que le drapeau TFD_TIMER_CANCEL_ON_SET a été spécifié lors de l'appel à timerfd_settime(), alors lecture(2) échoue avec l'erreur ECANCELED si l'horloge temps réel subit un changement discontinu. (Cela permet à l'application de lecture de détecter de tels changements discontinus de l'horloge.)
Si l'horloge associée est soit CLOCK_REALTIME, soit CLOCK_REALTIME_ALARM, que le minuteur est absolu (TFD_TIMER_ABSTIME), et que le drapeau TFD_TIMER_CANCEL_ON_SET n'a pas été spécifié lors de l'appel à timerfd_settime(), alors un changement négatif discontinu de l'horloge (par exemple, clock_settime(2)) peut provoquer le déblocage de lecture(2), mais renvoyer une valeur de 0 (c'est-à-dire aucun octet lu), si le changement d'horloge se produit après l'expiration du temps, mais avant la lecture(2) sur le descripteur de fichier.
poll(2)
select(2)
(et similaires)
Le descripteur de fichier est lisible (l'argument readfds de select(2) ; le drapeau POLLIN de poll(2)) si une ou plusieurs expirations de minuteur se sont produites.
Le descripteur de fichier prend également en charge les autres API de multiplexage de descripteurs de fichiers : pselect(2), ppoll(2) et epoll(7).
ioctl(2)
La commande spécifique à timerfd suivante est prise en charge :
TFD_IOC_SET_TICKS (depuis Linux 3.17)
Ajuste le nombre d'expirations de minuteur qui se sont produites. L'argument est un pointeur vers un entier non signé de 8 octets non nul (uint64_t*) contenant le nouveau nombre d'expirations. Une fois le nombre défini, tout processus en attente sur le minuteur est réveillé. Le seul but de cette commande est de restaurer les expirations à des fins de checkpoint/restauration. Cette opération n'est disponible que si le noyau a été configuré avec l'option CONFIG_CHECKPOINT_RESTORE.
close(2)
Lorsque le descripteur de fichier n'est plus nécessaire, il doit être fermé. Lorsque tous les descripteurs de fichiers associés au même objet minuteur ont été fermés, le minuteur est désarmé et ses ressources sont libérées par le noyau.

Sémantique de fork(2)

Après un fork(2), l'enfant hérite d'une copie du descripteur de fichier créé par timerfd_create(). Le descripteur de fichier fait référence au même objet minuteur sous-jacent que le descripteur de fichier correspondant dans le parent, et les lectures(2) dans l'enfant renverront des informations sur les expirations du minuteur.

Sémantique de execve(2)

Un descripteur de fichier créé par timerfd_create() est conservé lors d'un execve(2), et continue de générer des expirations de minuteur si le minuteur était armé.

VALEUR DE RETOUR

En cas de succès, timerfd_create() renvoie un nouveau descripteur de fichier. En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

timerfd_settime() et timerfd_gettime() renvoient 0 en cas de succès ; en cas d'erreur, elles renvoient -1 et définissent errno pour indiquer l'erreur.

ERREURS

timerfd_create() peut échouer avec les erreurs suivantes :

EINVAL
L'id_horloge n'est pas valide.
EINVAL
Les drapeaux ne sont pas valides ; ou, sous Linux 2.6.26 ou antérieur, les drapeaux sont non nuls.
EMFILE
La limite par processus sur le nombre de descripteurs de fichiers ouverts a été atteinte.
ENFILE
La limite système sur le nombre total de fichiers ouverts a été atteinte.
ENODEV
Impossible de monter le périphérique inode anonyme (interne).
ENOMEM
Il n'y avait pas assez de mémoire noyau pour créer le minuteur.
EPERM
id_horloge était CLOCK_REALTIME_ALARM ou CLOCK_BOOTTIME_ALARM mais l'appelant ne possédait pas la capacité CAP_WAKE_ALARM.

timerfd_settime() et timerfd_gettime() peuvent échouer avec les erreurs suivantes :

EBADF
fd n'est pas un descripteur de fichier valide.
EFAULT
new_value, old_value, ou curr_value n'est pas un pointeur valide.
EINVAL
fd n'est pas un descripteur de fichier timerfd valide.

timerfd_settime() peut également échouer avec les erreurs suivantes :

ECANCELED
Voir NOTES.
EINVAL
new_value n'est pas correctement initialisé (l'un des tv_nsec se situe en dehors de la plage de zéro à 999 999 999).
EINVAL
Les drapeaux ne sont pas valides.

NORMES

Linux.

HISTORIQUE

Linux 2.6.25, glibc 2.8.

NOTES

Supposons le scénario suivant pour un minuteur CLOCK_REALTIME ou CLOCK_REALTIME_ALARM qui a été créé avec timerfd_create():

(1)
Le minuteur a été démarré (timerfd_settime()) avec les drapeaux TFD_TIMER_ABSTIME et TFD_TIMER_CANCEL_ON_SET;
(2)
Un changement discontinu (par exemple, settimeofday(2)) est effectué ultérieurement sur l'horloge CLOCK_REALTIME ; et
(3)
l'appelant appelle à nouveau timerfd_settime() pour réarmer le minuteur (sans effectuer d'abord une lecture(2) sur le descripteur de fichier).

Dans ce cas, le comportement suivant se produit :

•
timerfd_settime() renvoie -1 avec errno défini sur ECANCELED. (Cela permet à l'appelant de savoir que le minuteur précédent a été affecté par un changement discontinu de l'horloge.)
•
Le minuteur est réarmé avec succès avec les paramètres fournis dans le deuxième appel à timerfd_settime(). (C'était probablement un accident d'implémentation, mais ne sera pas corrigé maintenant, au cas où certaines applications dépendraient de ce comportement.)

BUGS

Actuellement, timerfd_create() ne prend en charge que moins de types d'ID d'horloge que timer_create(2).

EXEMPLES

Le programme suivant crée un minuteur, puis surveille sa progression. Le programme accepte jusqu'à trois arguments en ligne de commande. Le premier argument spécifie le nombre de secondes pour la première expiration du minuteur. Le deuxième argument spécifie l'intervalle du minuteur, en secondes. Le troisième argument spécifie le nombre de fois où le programme doit permettre au minuteur d'expirer avant de se terminer. Les deuxième et troisième arguments en ligne de commande sont facultatifs.

La session shell suivante démontre l'utilisation du programme :


$ a.out 3 1 100
0.000:	timer started
3.000:	read: 1; total=1
4.000:	read: 1; total=2
^Z                  # taper control-Z pour suspendre le programme
[1]+  Stopped                 ./timerfd3_demo 3 1 100
$ fg                # Reprendre l'exécution après quelques secondes
a.out 3 1 100
9.660:	read: 5; total=7
10.000:	read: 1; total=8
11.000:	read: 1; total=9
^C                  # taper control-C pour suspendre le programme

Source du programme

#include <err.h>
#include <inttypes.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/timerfd.h>
#include <sys/types.h>
#include <time.h>
#include <unistd.h>
static void
print_elapsed_time(void)
{
    int                     secs, nsecs;
    static int              first_call = 1;
    struct timespec         curr;
    static struct timespec  start;
    if (first_call) {
        first_call = 0;
        if (clock_gettime
(CLOCK_MONOTONIC, &start) == -1) err(EXIT_FAILURE, "clock_gettime"); } if (clock_gettime(CLOCK_MONOTONIC, &curr) == -1) err(EXIT_FAILURE, "clock_gettime"); secs = curr.tv_sec - start.tv_sec; nsecs = curr.tv_nsec - start.tv_nsec; if (nsecs < 0) { secs--; nsecs += 1000000000; } printf("%d.%03d:\t", secs, (nsecs + 500000) / 1000000); } int main(int argc, char *argv[]) { int fd; ssize_t s; uint64_t expir, tot_expir, max_expir; struct timespec now; struct itimerspec new_value; if (argc != 2 && argc != 4) { fprintf(stderr, "%s init-secs [interval-secs max-num-expir]\n", argv[0]); exit(EXIT_FAILURE); } if (clock_gettime(CLOCK_REALTIME, &now) == -1) err(EXIT_FAILURE, "clock_gettime"); /* Create a CLOCK_REALTIME absolute timer with initial expiration and interval as specified in command line. */ new_value.it_value.tv_sec = now.tv_sec + atoi(argv[1]); new_value.it_value.tv_nsec = now.tv_nsec; if (argc == 2) { new_value.it_interval.tv_sec = 0; max_expir = 1; } else { new_value.it_interval.tv_sec = atoi(argv[2]); max_expir = atoi(argv[3]); } new_value.it_interval.tv_nsec = 0; fd = timerfd_create(CLOCK_REALTIME, 0); if (fd == -1) err(EXIT_FAILURE, "timerfd_create"); if (timerfd_settime(fd, TFD_TIMER_ABSTIME, &new_value, NULL) == -1) err(EXIT_FAILURE, "timerfd_settime"); print_elapsed_time(); printf("timer started\n"); for (tot_expir = 0; tot_expir < max_expir;) { s = read(fd, &expir, sizeof(uint64_t)); if (s != sizeof(uint64_t)) err(EXIT_FAILURE, "read"); tot_expir += expir; print_elapsed_time(); printf("read: %" PRIu64 "; total=%" PRIu64 "\n", expir, tot_expir); } exit(EXIT_SUCCESS); }
