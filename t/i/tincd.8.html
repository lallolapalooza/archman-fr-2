NOM

tincd — démon VPN tinc

SYNOPSIS

tincd [-cdDkKnoLRU] [--config=DIR] [--no-detach] [--debug[=LEVEL]] [--kill[=SIGNAL]] [--net=NOM_RESEAU] [--generate-keys[=BITS]] [--option=[HOTE.]CLE=VALEUR] [--mlock] [--logfile[=FICHIER]] [--pidfile=FICHIER] [--bypass-security] [--chroot] [--user=UTILISATEUR] [--help] [--version]

DESCRIPTION

Ceci est le démon de tinc, un projet de réseau privé virtuel (VPN) sécurisé. Lorsqu'il est démarré, tincd lira ses fichiers de configuration pour déterminer quels sous-réseaux virtuels il doit desservir et à quels autres démons tinc il doit se connecter. Il se connectera au périphérique ethertap ou tun/tap et configurera un socket pour les connexions entrantes. Optionnellement, un script sera exécuté pour configurer davantage le périphérique virtuel. Si cela réussit, il se détachera du terminal de contrôle et continuera en arrière-plan, acceptant et établissant des connexions avec d'autres démons tinc qui font partie du réseau privé virtuel. Sous Windows (pas Cygwin), tinc s'installera comme un service, qui sera redémarré automatiquement après les redémarrages.

OPTIONS

-c, --config=DIR
Lire les fichiers de configuration depuis DIR au lieu de /etc/tinc/.
-D, --no-detach
Ne pas forker et détacher. Ceci désactivera également le mécanisme de redémarrage automatique en cas d'erreurs fatales. Sauf indication contraire, cela affichera les messages de log sur la sortie d'erreur standard.
-d, --debug[=LEVEL]
Augmenter le niveau de débogage ou le définir à LEVEL (voir ci-dessous).
-k, --kill[=SIGNAL]
Tenter de tuer un tincd en cours d'exécution (optionnellement avec le SIGNAL spécifié au lieu de SIGTERM) et quitter. Sous Windows (pas Cygwin), l'argument optionnel est ignoré, le service sera toujours arrêté et supprimé.
-n, --net=NOM_RESEAU
Se connecter au réseau NOM_RESEAU. Ceci permettra à tinc de lire tous les fichiers de configuration depuis /etc/tinc/ NOM_RESEAU. Spécifier . pour NOM_RESEAU équivaut à ne pas spécifier de NOM_RESEAU.
-K, --generate-keys[=BITS]
Générer une paire de clés publique/privée RSA et quitter. Si BITS est omis, la longueur par défaut sera de 2048 bits. Lors de l'enregistrement des clés dans des fichiers existants, tinc ne supprimera pas les anciennes clés, vous devrez les supprimer manuellement.
-o, --option=[HOTE.]CLE=VALEUR
Sans spécifier d'HOTE, ceci définira la variable de configuration du serveur CLE à VALEUR. Si spécifié comme HOTE.CLE=VALEUR, ceci définira la variable de configuration de l'hôte CLE de l'hôte nommé HOTE à VALEUR. Cette option peut être utilisée plusieurs fois pour spécifier plusieurs variables de configuration.
-L, --mlock
Verrouiller tinc dans la mémoire principale. Ceci empêchera les données sensibles comme les clés privées partagées d'être écrites dans les fichiers ou partitions de swap du système.
--logfile[=FICHIER]
Écrire les entrées de log dans un fichier au lieu du système de journalisation du système. Si FICHIER est omis, la valeur par défaut est /var/log/tinc.NOM_RESEAU.log.
--pidfile=FICHIER
Écrire le PID dans FICHIER au lieu de /var/run/tinc.NOM_RESEAU.pid. Sous Windows, cette option sera ignorée.
--bypass-security
Désactive le chiffrement et l'authentification du protocole méta. Utile uniquement pour le débogage.
-R, --chroot
Avec cette option, tinc se place dans le répertoire où se trouve la configuration réseau (/etc/tinc/NOM_RESEAU si l'option -n est utilisée, ou dans le répertoire spécifié avec l'option -c) après l'initialisation.
-U, --user=UTILISATEUR
Utiliser setuid sur l'UTILISATEUR spécifié après l'initialisation.
--help
Afficher une courte liste d'options.
--version
Afficher les informations de version et quitter.

SIGNALS

ALRM
Force tincd à tenter de se connecter immédiatement à tous les uplinks. Habituellement, tincd essaie de le faire lui-même, mais augmente le temps d'attente entre les tentatives à chaque échec, et si tincd n'a pas réussi à se connecter à un uplink lors de la première tentative après son démarrage, il utilise par défaut le temps maximum de 15 minutes.
HUP
Relit partiellement les fichiers de configuration. Les connexions aux hôtes dont le fichier de configuration est supprimé sont fermées. De nouvelles connexions sortantes spécifiées dans tinc.conf seront établies. Si l'option --logfile est utilisée, cela fermera et rouvrira également le fichier log, utile lors de la rotation des logs.
INT
Augmente temporairement le niveau de débogage à 5. Envoyer à nouveau ce signal pour revenir au niveau d'origine.
USR1
Envoie la liste des connexions à syslog.
USR2
Envoie les statistiques du périphérique réseau virtuel, tous les nœuds connus, les arêtes et les sous-réseaux à syslog.
WINCH
Supprime toutes les informations mémorisées sur les nœuds inaccessibles.

NIVEAUX DE DÉBOGAGE

Le démon tinc peut envoyer de nombreux messages à syslog. Plus le niveau de débogage est élevé, plus il enregistre de messages. Chaque niveau hérite de tous les messages du niveau précédent :

0
Ceci enregistrera un message indiquant que tincd a démarré ainsi qu'un numéro de version. Il enregistrera également toute erreur grave.
1
Ceci enregistrera toutes les connexions qui sont établies avec d'autres démons tinc.
2
Ceci enregistrera les messages de statut et d'erreur des scripts et d'autres démons tinc.
3
Ceci enregistrera toutes les requêtes qui sont échangées avec d'autres démons tinc. Celles-ci incluent l'authentification, l'échange de clés et les mises à jour de la liste de connexion.
4
Ceci enregistrera une copie de tout ce qui est reçu sur le socket méta.
5
Ceci enregistrera tout le trafic réseau sur le réseau privé virtuel.

BOGUES

L'option BindToInterface pourrait ne pas fonctionner correctement.

La cryptographie dans tinc n'a pas encore été bien testée. Utilisez-la à vos propres risques !

Si vous trouvez des bogues, signalez-les à tinc@tinc-vpn.org.
