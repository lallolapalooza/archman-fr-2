TINYPROXY.CONF(5) Manuel Tinyproxy TINYPROXY.CONF(5)

NOM

tinyproxy.conf - Fichier de configuration du démon proxy HTTP Tinyproxy

SYNTAXE

tinyproxy.conf

DESCRIPTION

tinyproxy(8) lit son fichier de configuration, généralement situé dans `/etc/tinyproxy/tinyproxy.conf` (ou passé à Tinyproxy avec -c sur la ligne de commande). Cette page de manuel décrit la syntaxe et le contenu du fichier de configuration.

Le fichier de configuration Tinyproxy contient des paires clé-valeur, une par ligne. Les lignes commençant par `#` et les lignes vides sont des commentaires et sont ignorées. Les mots-clés ne sont pas sensibles à la casse, tandis que les valeurs le sont. Certaines valeurs de chaîne doivent être entourées de guillemets doubles (") comme indiqué ci-dessous.

Les mots-clés possibles et leurs descriptions sont les suivants :

Utilisateur
L'utilisateur sous lequel le processus Tinyproxy doit s'exécuter, après que la liaison initiale au port a été effectuée en tant qu'utilisateur `root`. Le nom d'utilisateur ou l'UID peut être spécifié.
Groupe
Le groupe sous lequel le processus Tinyproxy doit s'exécuter, après que la liaison initiale au port a été effectuée en tant qu'utilisateur `root`. Le nom du groupe ou le GID peut être spécifié.
Port
Le port sur lequel le service Tinyproxy écoutera. Si le port est inférieur à 1024, vous devrez démarrer le processus Tinyproxy en tant qu'utilisateur `root`.
Écouter
Par défaut, Tinyproxy écoute les connexions sur toutes les interfaces disponibles (c'est-à-dire qu'il écoute sur l'adresse wildcard `0.0.0.0`). Avec ce paramètre de configuration, Tinyproxy peut être configuré pour n'écouter que sur une adresse spécifique.
Lier
Cela vous permet de spécifier l'adresse sur laquelle Tinyproxy se liera pour les connexions sortantes. Ce paramètre peut être spécifié plusieurs fois, Tinyproxy essaiera alors toutes les adresses spécifiées dans l'ordre.
LierMême
Si ce paramètre booléen est défini sur `oui`, alors Tinyproxy liera la connexion sortante à l'adresse IP de la connexion entrante qui a déclenché la requête sortante.
Délai
Le nombre maximum de secondes d'inactivité qu'une connexion est autorisée avant d'être fermée par Tinyproxy.
FichierErreur
Ce paramètre contrôle quel fichier HTML Tinyproxy retourne lorsqu'une erreur HTTP donnée se produit. Il prend deux arguments, le numéro d'erreur et l'emplacement du fichier d'erreur HTML. Entourez l'emplacement du fichier de guillemets doubles.
FichierErreurDéfaut
Le fichier modèle HTML retourné lorsqu'une erreur se produit pour laquelle aucun fichier d'erreur spécifique n'a été défini. Entourez de guillemets doubles.
HôteStat
Le nom d'hôte ou l'adresse IP qui est traité comme l'`hôte stat`. Entourez de guillemets doubles. Chaque fois que Tinyproxy reçoit une requête pour l'`hôte stat`, il retourne une page de statistiques interne au lieu de transférer la requête à cet hôte. Le modèle pour cette page peut être configuré avec l'option de configuration `FichierStat`. La valeur par défaut de `HôteStat` est `tinyproxy.stats`.
FichierStat
Le fichier HTML que Tinyproxy envoie en réponse à une requête pour l'`hôte stat`. Entourez de guillemets doubles. Si ce paramètre n'est pas défini, Tinyproxy retourne une page de statistiques basique codée en dur. Voir la section STATHOST de la page de manuel tinyproxy(8) pour les détails.

Notez que le FichierStat et les fichiers d'erreur configurés avec FichierErreur et FichierErreurDéfaut sont des fichiers modèles qui peuvent contenir quelques variables modèles que Tinyproxy développe avant la livraison. Les exemples sont "{cause}" pour une description abrégée de l'erreur et "{détail}" pour un message d'erreur détaillé. La page de manuel tinyproxy(8) contient une description de toutes les variables modèles.

FichierLog
L'emplacement du fichier auquel Tinyproxy écrit sa sortie de débogage. Entourez de guillemets doubles. Alternativement, Tinyproxy peut enregistrer dans syslog -- voir l'option Syslog.
Syslog
Lorsque ce paramètre est défini sur `Activé`, cette option indique à Tinyproxy d'écrire ses messages de débogage dans syslog au lieu d'un fichier journal configuré avec `FichierLog`. Ces deux options sont mutuellement exclusives.
NiveauLog
Définit le niveau de journalisation. Les messages du niveau défini et supérieurs sont enregistrés. Par exemple, si le NiveauLog était défini sur Warning, alors tous les messages de journalisation de Warning à Critical seraient affichés, mais Notice et inférieurs seraient supprimés. Les valeurs autorisées sont :
  • Critique (le moins verbeux)
  • Erreur
  • Avertissement
  • Notice
  • Connexion (journalise les connexions sans le bruit de Info)
  • Info (le plus verbeux)
FichierPID
L'emplacement du fichier où le processus principal Tinyproxy stocke son identifiant de processus à des fins de signalisation. Entourez de guillemets doubles.
XTinyproxy
Définir cette option sur `Oui` indique à Tinyproxy d'ajouter un en-tête `X-Tinyproxy` contenant l'adresse IP du client à la requête.
Amont
Cette option vous permet de définir un ensemble de règles pour décider si un serveur proxy amont doit être utilisé, en fonction de l'hôte ou du domaine du site accédé. Les règles sont stockées dans l'ordre rencontré dans le fichier de configuration et la DERNIÈRE règle correspondante l'emporte. Les formes suivantes pour spécifier les règles amont existent :
  • amont type:port active le support de proxy amont généralement.
  • amont type utilisateur:motdepasse@hôte:port fait de même, mais utilise les informations d'identification fournies pour l'authentification.
  • amont type hôte:port "spec_site" active le proxy amont pour les sites correspondant à `spec_site`.

    `type` peut être l'un de `http`, `socks4`, `socks5`, `none`.

  • amont none "spec_site" désactive le support amont pour les sites correspondant à `spec_site`, ce qui signifie que la connexion est établie directement.

Il est recommandé d'utiliser des adresses IP brutes pour spécifier l'hôte amont, afin qu'aucune recherche DNS coûteuse ne soit effectuée à chaque utilisation. Les adresses IPv6 doivent être entourées de crochets.

Le site peut être spécifié sous diverses formes sous forme de nom d'hôte, de nom de domaine ou de plage d'adresses IP :

  • nom correspond exactement à l'hôte
  • .nom correspond à n'importe quel hôte du domaine "nom"
  • . correspond à n'importe quel hôte sans domaine (dans le domaine 'vide')
  • IP/bits correspond au réseau/masque
  • IP/masque correspond au réseau/masque

Notez que la directive amont peut également être utilisée pour null-router un domaine/hôte cible spécifique, par exemple : `amont http 0.0.0.0:0 ".serveurpublicitaire.com"`

MaxClients
Tinyproxy crée un thread pour chaque client connecté. Cette option spécifie le nombre maximum absolu de processus qui seront créés. Autrement dit, seuls MaxClients clients peuvent être connectés à Tinyproxy simultanément.
Autoriser
Refuser
Les options `Autoriser` et `Refuser` fournissent un moyen de personnaliser quels clients sont autorisés à accéder à Tinyproxy. Les lignes `Autoriser` et `Refuser` peuvent être spécifiées plusieurs fois pour construire la liste de contrôle d'accès pour Tinyproxy. L'ordre dans le fichier de configuration est important. S'il n'y a pas de lignes `Autoriser` ou `Refuser`, alors tous les clients sont autorisés. Sinon, l'action par défaut est de refuser l'accès. L'argument de `Autoriser` ou `Refuser` peut être une adresse IP unique d'un hôte client, comme `127.0.0.1`, une plage d'adresses IP, comme `192.168.0.1/24` ou une chaîne qui sera comparée à la fin du nom d'hôte client, c'est-à-dire qu'il peut s'agir d'un nom d'hôte complet comme `hôte.exemple.com` ou d'un domaine na
tinyproxy.conf(5) — Tinyproxy — The fast, lightweight, non-caching proxy daemon.

NAME

tinyproxy.conf — tinyproxy configuration file format

SYNOPSIS

/etc/tinyproxy/tinyproxy.conf

DESCRIPTION

The Tinyproxy configuration file is divided into sections. Each section contains a number of directives which control the behaviour of Tinyproxy.

Port
Specifies the port number Tinyproxy listens on. The default is 8888.
Listen
Specifies an IP address for Tinyproxy to listen on. By default Tinyproxy listens on all available interfaces.
ListenHTTPS
Specifies an IP address for Tinyproxy to listen on for HTTPS connections. This is only used when Tinyproxy acts as a HTTPS proxy.
BindSame
When this option is set to `Yes`, Tinyproxy will use the same IP address for both HTTP and HTTPS connections. This is useful if you only have one IP address.
BindSameProxy
When this option is set to `Yes`, Tinyproxy will use the same IP address for incoming connections and outgoing connections.
User
Specifies the user Tinyproxy runs as. By default, Tinyproxy runs as the `tinyproxy` user. This directive must appear before any other directives that require file access or network access.
Group
Specifies the group Tinyproxy runs as. By default, Tinyproxy runs as the `tinyproxy` group.
DefaultFile
Specifies a file that is served when a directory is requested. By default, this is `index.html`.
LogFile
Specifies the file where Tinyproxy logs its activity. By default, logs are written to `stderr`.
LogLevel
Specifies the level of detail in the logs. Possible values are `Critical`, `Error`, `Warning`, `Notice`, `Connect`, `Info`.
PidFile
Specifies the file where Tinyproxy writes its process ID. By default, this is `/var/run/tinyproxy.pid`.
MaxClients
Specifies the maximum number of clients that Tinyproxy will handle simultaneously. The default is 100.
MinSpawns
Specifies the minimum number of child processes that Tinyproxy will keep running. The default is 5.
MaxSpawns
Specifies the maximum number of child processes that Tinyproxy will spawn. The default is 250.
MaxSpareServers
Specifies the maximum number of spare child processes that Tinyproxy will keep running. The default is 10.
MaxRequestsPerChild
Specifies the maximum number of requests that a child process will handle before it is terminated and replaced. The default is 0 (unlimited).
Allow
Specifies the network addresses that are allowed to connect to Tinyproxy. By default, all connections are allowed. You can specify an IP address, a network address (e.g. `192.168.0.0/24`), or a hostname.
Deny
Specifies the network addresses that are denied to connect to Tinyproxy. By default, no connections are denied. Rules are processed in the order they appear in the configuration file. The first matching rule wins.
Host
Specifies a list of hostnames that Tinyproxy will accept connections for. If this directive is used, Tinyproxy will ignore all other hostnames. This is useful for setting up a proxy for a specific virtual host. You can specify a hostname, like `www.example.com`, or a wildcard pattern, like `*.example.com`.
NoDNSLookup
If set to `On`, Tinyproxy will not perform DNS lookups for incoming connections. This can speed up the proxy if you are using hostnames in your `Allow` or `Deny` directives, but it means that you cannot use hostnames in those directives.
ReverseHttpProxy
If set to `On`, Tinyproxy will act as an HTTP reverse proxy. This means that it will forward requests to another web server. This is useful for load balancing or for serving content from multiple servers.
ReverseHttpsProxy
If set to `On`, Tinyproxy will act as an HTTPS reverse proxy. This means that it will forward requests to another web server. This is useful for load balancing or for serving content from multiple servers.
RemoteHTTPProxy
Specifies the hostname or IP address of a remote HTTP proxy server to use for outgoing connections. If this is set, Tinyproxy will act as a forward proxy.
RemoteHTTPProxyPort
Specifies the port number of the remote HTTP proxy server. The default is 8080.
RemoteHTTPSProxy
Specifies the hostname or IP address of a remote HTTPS proxy server to use for outgoing connections. If this is set, Tinyproxy will act as a forward proxy for HTTPS connections.
RemoteHTTPSProxyPort
Specifies the port number of the remote HTTPS proxy server. The default is 8080.
FollowFormForRedirect
If set to `Yes`, Tinyproxy will follow redirects automatically. This is useful when accessing websites that use redirects extensively.
FollowProxyRedirects
If set to `Yes`, Tinyproxy will follow redirects generated by other proxies. The default is `No`.
AlwaysXForwardedFor
If set to `Yes`, Tinyproxy will always add the `X-Forwarded-For` header to requests, even if the client is not using a CONNECT tunnel. The default is `No`.
XPoweredBy
If set to `Yes`, Tinyproxy will add a `X-Powered-By: Tinyproxy/version` header to all responses. The default is `Yes`.
Terracotta
If set to `Yes`, Tinyproxy will enable Terracotta support. Terracotta is a cache for Tinyproxy. The default is `No`.
MaxClientHeaderSize
The maximum size of client request headers in bytes. The default is 1024.
MaxClientRequestBufferSize
The maximum size of the client request buffer in bytes. The default is 64KB.
MaxBandwidthPerClient
The maximum bandwidth allowed per client in bytes/sec. The default is 0 (unlimited).
AverageBw.AllowClientGroups
Allows grouping clients together for bandwidth limiting. This is useful for limiting the total bandwidth used by a group of clients.
AverageBw.Rate
The average bandwidth rate for a client group in bytes/sec.
AverageBw.Period
The period in seconds over which the average bandwidth rate is calculated.
TrustIntegerRepresentationOfHostnames
If set to `Yes`, Tinyproxy will trust integer representations of hostnames. This is useful for systems that use numeric hostnames.
StatAlias
Allows you to specify an alias for a hostname. This is useful for reporting purposes.
Hostnames
Specifies a list of hostnames that Tinyproxy will accept connections for. If this directive is used, Tinyproxy will ignore all other hostnames. This is useful for setting up a proxy for a specific virtual host. You can specify a hostname, like `www.example.com`, or a wildcard pattern, like `*.example.com`. Note that by adding a rule using a host or domain name, a costly name lookup has to be done for every new connection, which could slow down the service considerably.
BasicAuth
Configure HTTP "Basic Authentication" username and password for accessing the proxy. If there are any entries specified, access is only granted for authenticated users. 
BasicAuth user password
AddHeader
Configure one or more HTTP request headers to be added to outgoing HTTP requests that Tinyproxy makes. Note that this option will not work for HTTPS traffic, as Tinyproxy has no control over what headers are exchanged. 
AddHeader "X-My-Header" "Powered by Tinyproxy"
ViaProxyName
RFC 2616 requires proxies to add a `Via` header to the HTTP requests, but using the real host name can be a security concern. If the `ViaProxyname` option is present, then its string value will be used as the host name in the Via header. Otherwise, the server's host name will be used. Enclose in double quotes.
DisableViaHeader
When this is set to yes, Tinyproxy does NOT add the `Via` header to the requests. This virtually puts Tinyproxy into stealth mode. Note that RFC 2616 requires proxies to set the `Via` header, so by enabling this option, you break compliance. Don't disable the `Via` header unless you know what you are doing...
Filter
Tinyproxy supports filtering of web sites based on URLs or domains. This option specifies the location of the file containing the filter rules, one rule per line.

Rules are specified as POSIX basic regular expressions (BRE), unless another FilterType is specified. Comment lines start with a `#` character.

Example filter file contents:

# filter exactly cnn.com
^cnn\.com$

# filter all subdomains of cnn.com, but not cnn.com itself
.*\.cnn.com$

# filter any domain that has cnn.com in it, like xcnn.comfy.org
cnn\.com

# filter any domain that ends in cnn.com
cnn\.com$

# filter any domain that starts with adserver
^adserver
FilterType
This option can be set to one of `bre`, `ere`, or `fnmatch`. If `bre` is set, the rules specified in the filter file are matched using POSIX basic regular expressions, when set to `ere`, using POSIX extended regular expressions, and when set to `fnmatch` using the `fnmatch` function as specified in the manpage `man 3p fnmatch`. `fnmatch` matching is identical to what's used in the shell to match filenames, so for example `*.google.com` matches everything that ends with `.google.com`. If you don't know what regular expressions are or you're using filter lists from 3rd party sources, `fnmatch` is probably what you want. It's also the fastest matching method of the three.
FilterURLs
If this boolean option is set to `Yes` or `On`, filtering is performed for URLs rather than for domains. The default is to filter based on domains.

Note that filtering for URLs works only in plain HTTP scenarios. Since HTTPS has become ubiquitous during the last years, this will only work on a tiny fraction of websites, so it is recommended not to use this option.

FilterExtended
Deprecated. Use `FilterType ere` instead. If this boolean option is set to `Yes`, then extended POSIX regular expressions are used for matching the filter rules. The default is to use basic POSIX regular expressions.
FilterCaseSensitive
If this boolean option is set to `Yes`, then the filter rules are matched in a case sensitive manner. The default is to match case-insensitively, unfortunately. If you set this to `Yes`, then your matching will be almost twice as fast. This setting affects only `bre` and `ere` FilterTypes, fnmatch is always case sensitive.
FilterDefaultDeny
The default filtering policy is to allow everything that is not matched by a filtering rule. Setting `FilterDefaultDeny` to `Yes` changes the policy do deny everything but the domains or URLs matched by the filtering rules. In other words, if set to `No` the Filter list acts as a blacklist, if set to `Yes` as a whitelist.
Anonymous
If an `Anonymous` keyword is present, then anonymous proxying is enabled. The headers listed with `Anonymous` are allowed through, while all others are denied. If no Anonymous keyword is present, then all headers are allowed through. You must include double quotes around the headers.

Most sites require cookies to be enabled for them to work correctly, so you will need to allow cookies through if you access those sites.

Example:

Anonymous "Host"
Anonymous "Authorization"
Anonymous "Cookie"
ConnectPort
This option can be used to specify the ports allowed for the CONNECT method. If no `ConnectPort` line is found, then all ports are allowed. To disable CONNECT altogether, include a single ConnectPort line with a value of `0`.
ReversePath
Configure one or more ReversePath directives to enable reverse proxy support. With reverse proxying it's possible to make a number of sites appear as if they were part of a single site.

If you uncomment the following two directives and run Tinyproxy on your own computer at port 8888, you can access example.com, using http://localhost:8888/example/.

ReversePath "/example/" "http://www.example.com/"
ReverseOnly
When using Tinyproxy as a reverse proxy, it is STRONGLY recommended that the normal proxy is turned off by setting this boolean option to `Yes`.
ReverseMagic
Setting this option to `Yes`, makes Tinyproxy use a cookie to track reverse proxy mappings. If you need to reverse proxy sites which have absolute links you must use this option.
ReverseBaseURL
The URL that is used to access this reverse proxy. The URL is used to rewrite HTTP redirects so that they won't escape the proxy. If you have a chain of reverse proxies, you'll need to put the outermost URL here (the address which the end user types into his/her browser). If this option is not set then no rewriting of redirects occurs.
