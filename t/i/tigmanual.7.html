TIGMANUAL(7) Tig Manual TIGMANUAL(7)

NOM

tigmanual - interface en mode texte pour Git

SYNTAXE

tig        [options] [révisions] [--] [chemins]
tig show   [options] [révisions] [--] [chemins]
tig blame  [options] [rev] [--] chemin
tig status
tig <      [Sortie de commande Git]

DESCRIPTION

Ceci est le manuel de Tig, l'interface en mode texte basée sur ncurses pour git. Tig vous permet de parcourir les modifications dans un dépôt Git et peut également servir de pagineur pour la sortie de diverses commandes Git. Lorsqu'il est utilisé comme pagineur, il affichera l'entrée de stdin et la colorisera.

Lors du parcours des dépôts, Tig utilise les commandes Git sous-jacentes pour présenter à l'utilisateur diverses vues, telles que le journal des commits résumé et l'affichage du commit avec le message du journal, le diffstat et le diff.

CONVENTIONS D'APPEL

Mode Pagineur

Si stdin est un pipe, toute option de log ou de diff sera ignorée et la vue pagineur s'ouvrira en chargeant les données depuis stdin. Le mode pagineur peut être utilisé pour coloriser la sortie de diverses commandes Git.

Exemple pour coloriser la sortie de git-show(1) :

$ git show | tig

Options de Commande Git

Toutes les options de commande Git spécifiées sur la ligne de commande seront passées à la commande donnée et toutes seront échappées pour le shell avant d'être transmises au shell.


Note

Si vous spécifiez des options pour la vue principale, vous ne devriez pas utiliser l'option --pretty car cette option sera automatiquement définie au format attendu par la vue principale.

Exemple pour afficher un commit et montrer les informations de l'auteur et du committer :

$ tig show --pretty=fuller

Consultez la section sur la spécification des révisions pour une introduction aux options de révision prises en charge par les commandes Git. Pour plus de détails sur les options spécifiques des commandes Git, reportez-vous au manuel de la commande concernée.

LE VISUALISEUR

L'affichage se compose d'une fenêtre d'état sur la dernière ligne de l'écran et d'une ou plusieurs vues. Par défaut, une seule vue est affichée à la fois, mais il est possible de diviser la vue principale et la vue du log pour afficher également le diff du commit.

Si vous êtes dans la vue du log et que vous appuyez sur Entrée lorsque la ligne actuelle est une ligne de commit, telle que :

commit 4d55caff4cc89335192f3e566004b4ceef572521

Vous diviserez la vue de sorte que la vue du log soit affichée dans la fenêtre supérieure et la vue du diff dans la fenêtre inférieure. Vous pouvez passer d'une vue à l'autre en appuyant sur Tab. Pour maximiser à nouveau la vue du log, appuyez simplement sur l.

Vues

Diverses vues d'un dépôt sont présentées. Chaque vue est basée sur la sortie d'une commande externe, le plus souvent git log, git diff, ou git show.

La vue principale

Est la vue par défaut, et elle montre un résumé d'une ligne de chaque commit dans la liste choisie de révisions. Le résumé inclut la date du committer ou de l'auteur, l'auteur, le committer et la première ligne du message du journal. De plus, toutes les références du dépôt, telles que les tags, seront affichées.

La vue du log

Présente une vue plus riche du journal des révisions, montrant le message du journal complet et le diffstat.

La vue reflog

Présente une vue du reflog permettant de naviguer dans l'historique du dépôt.

La vue diff

Affiche soit le diff de l'arbre de travail actuel, c'est-à-dire ce qui a changé depuis le dernier commit, soit le diff du commit complet avec message de journal, diffstat et diff.

La vue arbre

Liste les arbres de répertoires associés à la révision actuelle, permettant de descendre ou de monter dans les sous-répertoires et de visualiser les blobs de fichiers.

La vue blob

Affiche le contenu du fichier ou le "blob" de données associé à un nom de fichier.

La vue blame

Affiche le contenu du fichier annoté ou "blamed" par les commits.

La vue refs

Affiche les branches, les remotes et les tags dans le dépôt.

La vue status

Affiche le statut des fichiers dans l'arbre de travail et permet de mettre en staging/retirer des modifications, ainsi que d'ajouter des fichiers non suivis.

La vue stage

Affiche les modifications de diff pour les fichiers mis en staging ou non, suivis ou le contenu des fichiers non suivis.

La vue stash

Affiche la liste des stashes dans le dépôt.

La vue grep

Affiche une liste de fichiers et toutes les lignes qui correspondent à un modèle de recherche.

La vue pager

Est utilisée pour afficher à la fois l'entrée de stdin et la sortie des commandes Git saisies dans le prompt interne.

La vue aide

Affiche une référence rapide des liaisons de touches.

État de Navigation et Commandes Définies par l'Utilisateur

Le visualiseur garde une trace de l'identifiant de la tête et du commit que vous visualisez actuellement. L'identifiant du commit suit la ligne du curseur et change à chaque fois que vous surlignez un commit différent. Chaque fois que vous rouvrez la vue du diff, elle sera rechargée si l'identifiant du commit a changé. L'identifiant de la tête est utilisé lors de l'ouverture des vues principale et du log pour indiquer à partir de quelle révision afficher l'historique.

Certaines des commandes utilisées ou fournies par Tig peuvent être configurées. Cela concerne certaines variables d'environnement ainsi que les commandes externes. Ces commandes définies par l'utilisateur peuvent utiliser des arguments qui font référence à l'état de navigation actuel en utilisant l'une des variables suivantes.

Commandes personnalisées exemples :

•Permettre de modifier le dernier commit : 
bind generic + !git commit --amend
•Copier l'identifiant du commit dans le presse-papiers : 
bind generic 9 @sh -c "echo -n %(commit) | xclip -selection c"
•Ajouter/modifier des notes pour le commit actuel utilisé lors d'une revue : 
bind generic T !git notes edit %(commit)
•Entrer dans l'ajout interactif de Git pour une mise en scène granulaire du contenu des fichiers : 
bind generic I !git add -i %(file)
•Réinitialiser la branche actuelle sur le dessus de la branche sélectionnée : 
bind refs 3 !git rebase -i %(branch)

Fenêtres de Titre

Chaque vue possède une fenêtre de titre qui affiche le nom de la vue, l'identifiant du commit actuel si disponible, et la position de la vue :

[main] c622eefaa485995320bc743431bae0d497b1d875 - commit 1 sur 61             1%

Par défaut, le titre de la vue actuelle est mis en surbrillance en utilisant une police en gras. Pour les vues à chargement long (prenant plus de 3 secondes), le temps écoulé depuis le début du chargement sera ajouté :

[main] 77d9e40fbcea3238015aea403e06f61542df9a31 - commit 1 sur 779 chargement 5s 0%

VARIABLES D'ENVIRONNEMENT

Plusieurs options liées à l'interface avec Git peuvent être configurées via des variables d'environnement.

Fichiers de Configuration

Au démarrage, Tig lit d'abord le fichier de configuration global du système ({sysconfdir}/tigrc par défaut), puis lit le fichier de configuration de l'utilisateur (~/.tigrc ou $XDG_CONFIG_HOME/tig/config par défaut). Les chemins de ces deux fichiers peuvent être remplacés via les variables d'environnement suivantes :

TIGRC_USER

Chemin du fichier de configuration utilisateur.

TIGRC_SYSTEM

Chemin du fichier de configuration global du système.

Fichiers d'Historique

Si compilé avec le support readline, Tig écrit un historique persistant des commandes et des recherches dans ~/.tig_history ou $XDG_DATA_HOME/tig/history.

Références du Dépôt

Les commits référencés par des tags et des têtes de branche seront marqués par le nom de la référence entouré de [ et ] :

2006-03-26 19:42 Petr Baudis         | [cogito-0.17.1] Cogito 0.17.1

Si vous souhaitez limiter les branches affichées, par exemple n'afficher que les branches nommées master ou celles qui commencent par le préfixe feature/, vous pouvez le faire en définissant la variable suivante :

$ TIG_LS_REMOTE="git ls-remote . master feature/*" tig

Ou définir la variable de manière permanente dans votre environnement.

TIG_LS_REMOTE

Commande pour récupérer toutes les références du dépôt. La commande doit sortir des données dans le même format que git-ls-remote(1). Par défaut :
git ls-remote .

Options de Diff

Il est possible de modifier la façon dont les différences sont affichées par la vue diff. Si, par exemple, vous préférez que les dates de commit et d'auteur soient affichées comme des dates relatives, utilisez :

$ TIG_DIFF_OPTS="--relative-date" tig

Ou définissez la variable de manière permanente dans votre environnement.

Manipulation des Vues

Clé Action
q Ferme la vue, s'il y a plusieurs vues ouvertes, cela retournera à la vue précédente dans la pile des vues. S'il s'agit de la dernière vue ouverte, cela quittera. Utilisez Q pour quitter toutes les vues à la fois.
Entrée Cette touche est « sensible au contexte » en fonction de la vue dans laquelle vous vous trouvez actuellement. Dans la vue log sur une ligne de commit ou dans la vue principale, divisez la vue et affichez le diff du commit. Dans la vue diff, appuyer sur Entrée fera simplement défiler la vue d'une ligne vers le bas.
Tab Commute vers la vue suivante.
R Recharge et rafraîchit la vue actuelle.
O Maximise la vue actuelle pour remplir tout l'écran.
Haut Cette touche est « sensible au contexte » et déplacera le curseur d'une ligne vers le haut. Cependant, si vous avez ouvert une vue fractionnée, elle déplacera le curseur pour pointer vers le commit précédent dans la vue parente et mettra à jour la vue enfant pour l'afficher. Si vous préférez que cette touche déplace le curseur ou fasse défiler la vue diff, utilisez respectivement bind diff <Up> move-up ou bind diff <Up> scroll-line-up.
Bas Similaire à Haut mais se déplacera vers le bas.
, Aller au parent. Dans la vue arbre, cela signifie passer au répertoire parent. Dans la vue blame, cela chargera le blame pour le commit parent. Pour les fusions, le parent est interrogé.

Actions Spécifiques aux Vues

Clé Action
u Met à jour le statut d'un fichier. Dans la vue de statut, cela permet d'ajouter un fichier non suivi ou de mettre en attente les modifications d'un fichier pour le prochain commit (similaire à l'exécution de git-add <nom_fichier>). Dans la vue de mise en attente, lorsque l'on appuie sur cette touche sur une ligne de différence, seule cette partie est mise en attente pour le prochain commit. Si l'on n'est pas sur une ligne de différence, toutes les modifications dans la différence affichée sont mises en attente.
M Résout un fichier non fusionné en lançant git-mergetool(1). Notez que pour fonctionner correctement, cela peut nécessiter une configuration initiale de votre outil de fusion préféré. Voir la page de manuel de git-mergetool(1).
! Annule les modifications non mises en attente d'un fichier. Cela réinitialisera le fichier pour qu'il contienne le contenu qu'il avait lors du dernier commit.
1 Met en attente une seule ligne de différence.
@ Se déplace vers le prochain bloc dans la vue de mise en attente.
] Augmente le contexte de la différence.
[ Diminue le contexte de la différence.

SPÉCIFICATION DE RÉVISION

Cette section décrit diverses façons de spécifier quelles révisions afficher ou de limiter la vue. Tig ne analyse pas lui-même les options de révision décrites, alors référez-vous aux pages de manuel Git pertinentes pour plus d'informations. Les pages de manuel pertinentes en plus de git-log(1) sont git-diff(1) et git-rev-list(1).

Vous pouvez régler l'interaction avec Git en utilisant les options expliquées dans cette section. Par exemple, en configurant la variable d'environnement décrite dans la section sur les options de diff.

Limiter par nom de chemin

Si vous ne vous intéressez qu'aux révisions qui ont apporté des modifications à un fichier spécifique (ou même à plusieurs fichiers), listez les fichiers comme ceci :

$ tig Makefile README

Pour éviter toute ambiguïté avec les sous-commandes de Tig ou les références de dépôt telles que les noms de tags, assurez-vous de séparer les noms de fichiers des autres options Git en utilisant "--". Donc, si vous avez un fichier nommé status, il entrera en conflit avec la sous-commande status, et vous devrez donc utiliser :

$ tig -- status

Limiter par date ou numéro

Pour accélérer l'interaction avec Git, vous pouvez limiter le nombre de commits à afficher à la fois pour le journal et pour la vue principale. Limitez par date en utilisant, par exemple, --since=1.month ou par le nombre de commits en utilisant -n400.

Si vous ne vous intéressez qu'aux changements survenus entre deux dates, vous pouvez utiliser :

$ tig --after="May 5th" --before="2006-05-16 15:44"

Note

Si vous souhaitez éviter d'avoir à mettre entre guillemets des dates contenant des espaces, vous pouvez utiliser "." à la place, par exemple --after=May.5th.

Limiter par plages de commits

Alternativement, les commits peuvent être limités à une plage spécifique, comme "tous les commits entre tag-1.0 et tag-2.0". Par exemple :

$ tig tag-1.0..tag-2.0

Cette façon de limiter les commits rend trivial de ne parcourir que les commits qui n'ont pas été poussés vers une branche distante. En supposant que origin est votre branche distante en amont, en utilisant :

$ tig origin..HEAD

listará ce qui sera poussé vers la branche distante. Optionnellement, la partie HEAD à la fin peut être omise car elle est implicite.

Limiter par atteignabilité

Git interprète le spécificateur de plage "tag-1.0..tag-2.0" comme "tous les commits atteignables depuis tag-2.0 mais pas depuis tag-1.0". Où l'atteignabilité fait référence aux commits qui sont des ancêtres (ou font partie de l'historique) de la branche ou de la révision taguée en question.

Si vous préférez spécifier quel commit prévisualiser de cette manière, utilisez ce qui suit :

$ tig tag-2.0 ^tag-1.0

Vous pouvez considérer ^ comme un opérateur de négation. En utilisant cette syntaxe alternative, il est possible de réduire davantage les commits en spécifiant plusieurs coupures de branche.

Combiner les spécifications de révision

Les options de révision peuvent être combinées dans une certaine mesure, ce qui permet de dire "afficher au maximum 20 commits du dernier mois qui ont modifié des fichiers dans le répertoire Documentation/".

$ tig --since=1.month -n20 -- Documentation/

Examiner toutes les références du dépôt

Dans certains cas, il peut être utile d'interroger les changements sur toutes les références d'un dépôt. Un exemple est de demander "une quelconque ligne de développement dans ce dépôt a-t-elle modifié un fichier particulier au cours de la dernière semaine". Cela peut être accompli en utilisant :

$ tig --all --since=1.week -- Makefile
