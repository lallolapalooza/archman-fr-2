NOM

tmux — multiplexeur de terminaux

SYNTAXE

tmux [-2CDhlNuVv] [-c commande-shell] [-f fichier] [-L nom-socket] [-S chemin-socket] [-T fonctionnalités] [commande [options]]

DESCRIPTION

tmux est un multiplexeur de terminaux : il permet de créer, d'accéder et de contrôler plusieurs terminaux à partir d'un seul écran. tmux peut être détaché d'un écran tout en continuant de s'exécuter en arrière-plan, puis être rattaché ultérieurement.

Lorsque tmux est lancé, il crée une nouvelle session avec une unique fenêtre et l'affiche à l'écran. Une ligne de statut en bas de l'écran affiche des informations sur la session en cours et sert à entrer des commandes interactives.

Une session est un ensemble de terminaux pseudo gérés par tmux. Chaque session est liée à une ou plusieurs fenêtres. Une fenêtre occupe tout l'écran et peut être divisée en panneaux rectangulaires, chacun étant un pseudo terminal distinct (la page de manuel pty(4) documente les détails techniques des pseudo terminaux). N'importe quel nombre d'instances de tmux peut se connecter à la même session, et n'importe quel nombre de fenêtres peut exister dans la même session. Une fois que toutes les sessions sont terminées, tmux se quitte.

Chaque session est persistante et survivra aux déconnexions accidentelles (comme les timeouts de connexion ssh(1)) ou aux détachements intentionnels (avec les combinaisons de touches ‘C-b d’ ). tmux peut être rattaché en utilisant :

$ tmux attach

Dans tmux, une session est affichée à l'écran par un client et toutes les sessions sont gérées par un unique serveur. Le serveur et chaque client sont des processus distincts qui communiquent via un socket dans /tmp.

Les options sont les suivantes :

-2
Force tmux à supposer que le terminal supporte 256 couleurs. Ceci est équivalent à -T 256.
-C
Démarre en mode contrôle (voir la section MODE CONTRÔLE). Donné deux fois (-CC) désactive l'écho.
-c commande-shell
Exécute commande-shell en utilisant le shell par défaut. Si nécessaire, le serveur tmux sera lancé pour récupérer l'option default-shell. Cette option est pour la compatibilité avec sh(1) lorsque tmux est utilisé comme shell de connexion.
-D
Ne démarre pas le serveur tmux en tant que démon. Ceci désactive également l'option exit-empty. Avec -D, commande ne peut pas être spécifiée.
-f fichier
Spécifie un fichier de configuration alternatif. Par défaut, tmux charge le fichier de configuration système depuis /etc/tmux.conf, s'il est présent, puis recherche un fichier de configuration utilisateur à l'emplacement ~/.tmux.conf ou $XDG_CONFIG_HOME/tmux/tmux.conf.

Le fichier de configuration est un ensemble de commandes tmux qui sont exécutées séquentiellement lorsque le serveur est lancé pour la première fois. tmux charge les fichiers de configuration une fois que le processus serveur a démarré. La commande source-file peut être utilisée pour charger un fichier ultérieurement.

tmux affiche tous les messages d'erreur provenant des commandes dans les fichiers de configuration dans la première session créée, et continue de traiter le reste du fichier de configuration.

-h
Affiche les informations d'utilisation et quitte.
-L nom-socket
tmux stocke le socket du serveur dans un répertoire sous TMUX_TMPDIR ou /tmp s'il n'est pas défini. Le socket par défaut est nommé default. Cette option permet de spécifier un nom de socket différent, permettant à plusieurs serveurs tmux indépendants de fonctionner. Contrairement à -S, un chemin complet n'est pas nécessaire : les sockets sont tous créés dans un répertoire tmux-UID sous le répertoire donné par TMUX_TMPDIR ou dans /tmp. Le répertoire tmux-UID est créé par tmux et ne doit pas être lisible, inscriptible ou exécutable par tous.

Si le socket est accidentellement supprimé, le signal SIGUSR1 peut être envoyé au processus serveur tmux pour le recréer (notez que cela échouera si des répertoires parents sont manquants).

-l
Se comporte comme un shell de connexion. Ce drapeau n'a actuellement aucun effet et est là pour la compatibilité avec d'autres shells lors de l'utilisation de tmux comme shell de connexion.
-N
Ne démarre pas le serveur même si la commande le ferait normalement (par exemple new-session ou start-server).
-S chemin-socket
Spécifie un chemin alternatif complet vers le socket du serveur. Si -S est spécifié, le répertoire de socket par défaut n'est pas utilisé et tout drapeau -L est ignoré.
-T fonctionnalités
Définit les fonctionnalités du terminal pour le client. Ceci est une liste de fonctionnalités séparées par des virgules. Voir l'option terminal-features.
-u
Écrit la sortie UTF-8 vers le terminal même si la première variable d'environnement de LC_ALL, LC_CTYPE, ou LANG qui est définie ne contient pas "UTF-8" ou "UTF8".
-V
Rapporte la version de tmux.
-v
Demande une journalisation détaillée. Les messages de journal seront enregistrés dans des fichiers tmux-client-PID.log et tmux-server-PID.log dans le répertoire courant, où PID est le PID du processus serveur ou client. Si -v est spécifié deux fois, un fichier supplémentaire tmux-out-PID.log est généré avec une copie de tout ce que tmux écrit dans le terminal.

Le signal SIGUSR2 peut être envoyé au processus serveur tmux pour activer/désactiver la journalisation (comme si -v était donné).

commande [options]
Ceci spécifie l'une des commandes utilisées pour contrôler tmux, comme décrit dans les sections suivantes. Si aucune commande n'est spécifiée, la commande dans default-client-command est supposée, qui par défaut est new-session.

ANALYSE ET EXÉCUTION DES COMMANDES

tmux prend en charge un grand nombre de commandes qui peuvent être utilisées pour contrôler son comportement. Chaque commande est nommée et peut accepter zéro ou plusieurs indicateurs et arguments. Elles peuvent être liées à une touche avec la commande bind-key ou exécutées depuis l'invite de commande du shell, un script shell, un fichier de configuration ou l'invite de commande. Par exemple, la même commande set-option exécutée depuis l'invite de commande du shell, depuis ~/.tmux.conf et liée à une touche peut ressembler à ceci :

$ tmux set-option -g status-style bg=cyan

set-option -g status-style bg=cyan

bind-key C set-option -g status-style bg=cyan

Ici, le nom de la commande est « set-option », « -g » est un indicateur et « status-style » et « bg=cyan » sont des arguments.

tmux fait la distinction entre l'analyse et l'exécution des commandes. Pour exécuter une commande, tmux doit la décomposer en son nom et ses arguments. C'est l'analyse de commande. Si une commande est exécutée depuis le shell, le shell l'analyse ; depuis l'intérieur de tmux ou depuis un fichier de configuration, tmux le fait. Exemples de cas où tmux analyse des commandes :

  • dans un fichier de configuration ;
  • tapée à l'invite de commande (voir command-prompt) ;
  • donnée à bind-key ;
  • passée en arguments à if-shell ou confirm-before.

Pour exécuter des commandes, chaque client possède une « file d'attente de commandes ». Une file d'attente de commandes globale, non attachée à aucun client, est utilisée au démarrage pour les fichiers de configuration comme ~/.tmux.conf. Les commandes analysées ajoutées à la file d'attente sont exécutées dans l'ordre. Certaines commandes, comme if-shell et confirm-before, analysent leurs arguments pour créer une nouvelle commande qui est insérée immédiatement après elles. Cela signifie que les arguments peuvent être analysés deux fois ou plus - une fois lorsque la commande parente (comme if-shell) est analysée et une fois de plus lorsqu'elle analyse et exécute sa commande. Les commandes comme if-shell, run-shell et display-panes arrêtent l'exécution des commandes suivantes dans la file d'attente jusqu'à ce que quelque chose se produise - if-shell et run-shell jusqu'à ce qu'une commande shell se termine et display-panes jusqu'à ce qu'une touche soit pressée. Par exemple, les commandes suivantes :

new-session; new-window
if-shell "true" "split-window"
kill-session

Exécuteront new-session, new-window, if-shell, la commande shell true(1), split-window et kill-session dans cet ordre.

La section COMMANDES liste les commandes tmux et leurs arguments.

SYNTAXE D'ANALYSE

Cette section décrit la syntaxe des commandes analysées par tmux, par exemple dans un fichier de configuration ou à l'invite de commande. Notez que lorsque les commandes sont entrées dans le shell, elles sont analysées par le shell - voir par exemple ksh(1) ou csh(1).

Chaque commande est terminée par un retour à la ligne ou un point-virgule (;). Les commandes séparées par des points-virgules forment une « séquence de commandes » - si une commande de la séquence rencontre une erreur, aucune commande ultérieure n'est exécutée.

Il est recommandé qu'un point-virgule utilisé comme séparateur de commande soit écrit comme un jeton individuel, par exemple depuis sh(1) :

$ tmux neww \; splitw

Ou :

$ tmux neww ';' splitw

Ou depuis l'invite de commande tmux :

neww ; splitw

Cependant, un point-virgule final est également interprété comme un séparateur de commande, par exemple dans ces commandes sh(1) :

$ tmux neww\; splitw

Ou :

$ tmux 'neww;' splitw

Comme dans ces exemples, lors de l'exécution de tmux depuis le shell, il faut prendre des précautions supplémentaires pour bien échapper les points-virgules :

  1. Les points-virgules qui doivent être interprétés comme un séparateur de commande doivent être échappés conformément aux conventions du shell. Pour sh(1), cela signifie généralement qu'ils sont mis entre guillemets (comme « neww ';' splitw ») ou échappés (comme « neww \; splitw »).
  2. Les points-virgules individuels ou les points-virgules finaux qui doivent être interprétés comme des arguments doivent être échappés deux fois : une fois conformément aux conventions du shell et une seconde fois pour tmux ; par exemple : 
    $ tmux neww 'foo\;' bar
$ tmux neww foo\\\; bar
  3. Les points-virgules qui ne sont pas des jetons individuels ou qui ne terminent pas un autre jeton ne doivent être échappés qu'une seule fois conformément aux conventions du shell ; par exemple : 
    $ tmux neww 'foo-;-bar'
$ tmux neww foo-\;-bar

Les commentaires sont marqués par le caractère # non mis entre guillemets - tout texte restant après un commentaire est ignoré jusqu'à la fin de la ligne.

Si le dernier caractère d'une ligne est \, la ligne est jointe à la ligne suivante (le \ et le retour à la ligne sont complètement supprimés). Ceci est appelé continuation de ligne et s'applique aussi bien à l'intérieur qu'à l'extérieur des chaînes entre guillemets et dans les commentaires, mais pas à l'intérieur des accolades.

Les arguments de commande peuvent être spécifiés sous forme de chaînes entourées de guillemets simples (') ou doubles ("), ou sous forme de listes de commandes entourées d'accolades ({}). Ceci est requis lorsque l'argument contient un caractère spécial. Les chaînes entre guillemets simples et doubles ne peuvent pas s'étendre sur plusieurs lignes, sauf avec la continuation de ligne. Les accolades peuvent s'étendre sur plusieurs lignes.

En dehors des guillemets et à l'intérieur des doubl

e citations, ces remplacements sont effectués :

  • Les variables d'environnement précédées de $ sont remplacées par leur valeur provenant de l'environnement global (voir la section ENVIRONNEMENT GLOBAL ET DE SESSION).
  • Un tilde ~ ou ~utilisateur au début est développé en répertoire personnel de l'utilisateur actuel ou spécifié.
  • \uXXXX ou \uXXXXXXXX est remplacé par le point de code Unicode correspondant au nombre hexadécimal à quatre ou huit chiffres donné.
  • Lorsqu'ils sont précédés (échappés) par un \, les caractères suivants sont remplacés : \e par le caractère d'échappement ; \r par un retour chariot ; \n par un saut de ligne ; et \t par une tabulation.
  • \ooo est remplacé par un caractère de valeur octale ooo. Trois chiffres octaux sont requis, par exemple \001. Le caractère valide le plus élevé est \377.
  • Tout autre caractère précédé de \ est remplacé par lui-même (c'est-à-dire, le \ est supprimé) et n'est pas traité comme ayant une signification spéciale - ainsi par exemple \; ne marquera pas une séquence de commande et \$ n'étendra pas une variable d'environnement.

Les accolades sont analysées comme un fichier de configuration (ainsi les conditions telles que ‘%if’ sont traitées) puis converties en une chaîne. Elles sont conçues pour éviter la nécessité d'un échappement supplémentaire lors du passage d'un groupe de commandes tmux comme argument (par exemple à if-shell). Ces deux exemples produisent une commande identique - notez qu'aucun échappement n'est nécessaire lors de l'utilisation de {}:

if-shell true {
    display -p 'brace-dollar-foo: }$foo'
}

if-shell true "display -p 'brace-dollar-foo: }\$foo'"

Les accolades peuvent être imbriquées, par exemple :

bind x if-shell "true" {
    if-shell "true" {
        display "true!"
    }
}

Les variables d'environnement peuvent être définies en utilisant la syntaxe ‘nom=valeur’, par exemple ‘HOME=/home/user’. Les variables définies pendant l'analyse sont ajoutées à l'environnement global. Une variable cachée peut être définie avec ‘%hidden’, par exemple :

%hidden MYVAR=42

Les variables cachées ne sont pas transmises à l'environnement des processus créés par tmux. Voir la section ENVIRONNEMENT GLOBAL ET DE SESSION.

Les commandes peuvent être analysées conditionnellement en les entourant de ‘%if’, ‘%elif’, ‘%else’ et ‘%endif’. L'argument de ‘%if’ et ‘%elif’ est développé comme un format (voir FORMATS) et s'il évalue à faux (zéro ou vide), le texte suivant est ignoré jusqu'au ‘%elif’, ‘%else’ ou ‘%endif’ de fermeture. Par exemple :

%if "#{==:#{host},myhost}"
set -g status-style bg=red
%elif "#{==:#{host},myotherhost}"
set -g status-style bg=green
%else
set -g status-style bg=blue
%endif

Changera la ligne de statut en rouge si exécuté sur ‘myhost’, en vert si exécuté sur ‘myotherhost’, ou en bleu si exécuté sur un autre hôte. Les conditionnelles peuvent être sur une seule ligne, par exemple :

%if #{==:#{host},myhost} set -g status-style bg=red %endif

COMMANDES

Cette section décrit les commandes prises en charge par tmux. La plupart des commandes acceptent l'argument optionnel -t (et parfois -s) avec l'un des cible-client, cible-session, cible-fenêtre, ou cible-panneau. Ceux-ci spécifient le client, la session, la fenêtre ou le panneau que la commande doit affecter.

cible-client doit être le nom du client, typiquement le fichier pty(4) auquel le client est connecté, par exemple /dev/ttyp1 ou ttyp1 pour le client connecté à /dev/ttyp1. Si aucun client n'est spécifié, tmux essaie de déterminer le client actuellement utilisé ; si cela échoue, une erreur est signalée. Les clients peuvent être listés avec la commande list-clients.

cible-session est recherché dans l'ordre suivant :

  1. Un ID de session précédé d'un $.
  2. Un nom exact de session (tel que listé par la commande list-sessions).
  3. Le début d'un nom de session, par exemple ‘mysess’ correspondrait à une session nommée ‘mysession’.
  4. Un modèle glob(7) qui est comparé au nom de la session.

Si le nom de la session est précédé d'un ‘=’, seule une correspondance exacte est acceptée (ainsi ‘=mysess’ ne correspondra qu'à ‘mysess’ exactement, pas à ‘mysession’).

Si une seule session est trouvée, elle est utilisée comme session cible ; plusieurs correspondances produisent une erreur. Si une session est omis, la session actuelle est utilisée si disponible ; si aucune session actuelle n'est disponible, la plus récemment utilisée est choisie.

cible-fenêtre (ou src-fenêtre ou dst-fenêtre) spécifie une fenêtre sous la forme session:fenêtre. session suit les mêmes règles que pour cible-session, et fenêtre est recherchée dans l'ordre suivant :

  1. Un jeton spécial, listé ci-dessous.
  2. Un index de fenêtre, par exemple ‘mysession:1’ est la fenêtre 1 dans la session ‘mysession’.
  3. Un ID de fenêtre, tel que @1.
  4. Un nom de fenêtre exact, tel que ‘mysession:mywindow’.
  5. Le début d'un nom de fenêtre, tel que ‘mysession:mywin’.
  6. Comme un modèle glob(7) comparé au nom de la fenêtre.

Comme pour les sessions, un préfixe ‘=’ effectuera une correspondance exacte uniquement. Un nom de fenêtre vide spécifie le prochain index disponible si approprié (par exemple les commandes new-window et link-window) sinon la fenêtre actuelle dans session est choisie.

Les jetons spéciaux suivants sont disponibles pour indiquer des fenêtres particulières. Chacun a une forme alternative à un seul caractère.

Jeton Signification
{start} ^ La fenêtre avec le plus petit numéro
{end} $ La fenêtre avec le plus grand numéro
{last} ! La dernière fenêtre (précédemment actuelle)
{next} + La fenêtre suivante par numéro
{previous} - La fenêtre précédente par numéro

cible-panneau (ou src-panneau ou dst-panneau) peut être un ID de panneau ou prend une forme similaire à cible-fenêtre mais avec l'ajout optionnel d'un point suivi d'un index de panneau ou d'un ID de panneau, par exemple : ‘mysession:mywindow.1’. Si l'index du panneau est omis, le panneau actif actuel dans la fenêtre spécifiée est utilisé. Les jetons spéciaux suivants sont disponibles pour l'index du panneau :

Jeton Signification

{top} Le panneau supérieur
{bottom} Le panneau inférieur
{left} Le panneau le plus à gauche

Les jetons ‘+’ et ‘-’ peuvent être suivis d'un décalage, par exemple :

De plus, target-session, target-window ou target-pane peuvent être constitués entièrement du jeton ‘{mouse}’ (forme alternative ‘=’) pour spécifier la session, la fenêtre ou la fenêtre où le dernier événement de souris s'est produit (voir la section SUPPORT DE LA SOURIS) ou ‘{marked}’ (forme alternative ‘~’) pour spécifier la fenêtre marquée (voir select-pane -m).

Les sessions, les fenêtres et les fenêtres sont chacune numérotées avec un ID unique ; les ID de session sont préfixés par un ‘$’, les fenêtres par un ‘@’ et les fenêtres par un ‘%’. Ceux-ci sont uniques et restent inchangés pendant la durée de vie de la session, de la fenêtre ou de la fenêtre dans le serveur tmux. L'ID de la fenêtre est passé au processus enfant de la fenêtre dans la variable d'environnement TMUX_PANE. Les ID peuvent être affichés en utilisant les formats ‘session_id’, ‘window_id’ ou ‘pane_id’ (voir la section FORMATS) et les commandes display-message, list-sessions, list-windows ou list-panes.

shell-command les arguments sont des commandes sh(1). Il peut s'agir d'un seul argument passé au shell, par exemple :

new-window 'vi ~/.tmux.conf'

Exécutera :

/bin/sh -c 'vi ~/.tmux.conf'

De plus, les commandes new-window, new-session, split-window, respawn-window et respawn-pane permettent de fournir shell-command sous forme de plusieurs arguments et de l'exécuter directement (sans ‘sh -c’). Cela peut éviter des problèmes de guillemets du shell. Par exemple :

$ tmux new-window vi ~/.tmux.conf

Exécutera directement vi(1) sans invoquer le shell.

command [argument ...] fait référence à une commande tmux, soit passée avec la commande et les arguments séparément, par exemple :

bind-key F1 set-option status off

Soit passée sous forme d'une seule chaîne d'arguments dans .tmux.conf, par exemple :

bind-key F1 { set-option status off }

Les exemples de commandes tmux incluent :

refresh-client -t/dev/ttyp2

rename-session -tfirst newname

set-option -wt:0 monitor-activity on

new-window ; split-window -d

bind-key R source-file ~/.tmux.conf \; \
	display-message "source-file done"

Ou depuis sh(1) :

$ tmux kill-window -t :1

$ tmux new-window \; split-window -d

$ tmux new-session -d 'vi ~/.tmux.conf' \; split-window -d \; attach

CLIENTS ET SESSIONS

Le serveur tmux gère les clients, les sessions, les fenêtres et les fenêtres. Les clients sont attachés aux sessions pour interagir avec elles, soit lors de leur création avec la commande new-session, soit plus tard avec la commande attach-session. Chaque session a une ou plusieurs fenêtres liées à elle. Les fenêtres peuvent être liées à plusieurs sessions et sont composées d'une ou plusieurs fenêtres, chacune contenant un pseudo-terminal. Les commandes de création, de liaison et de manipulation des fenêtres sont traitées dans la section FENÊTRES ET FENÊTRES.

Les commandes suivantes sont disponibles pour gérer les clients et les sessions :

attach-session [-dErx] [-c répertoire-travail] [-f indicateurs] [-t session-cible]
(alias : attach)
Si exécuté depuis l'extérieur de tmux, attache la session cible dans le terminal courant. session-cible doit déjà exister - pour créer une nouvelle session, voir la commande new-session (avec -A pour créer ou attacher). Si utilisé de l'intérieur, change la session actuellement attachée à session-cible. Si -d est spécifié, tout autre client attaché à la session est détaché. Si -x est donné, envoie SIGHUP au processus parent du client et détache le client, provoquant typiquement sa sortie. -f définit une liste d'indicateurs de client séparés par des virgules. Les indicateurs sont :
active-pane
le client a une fenêtre active indépendante
ignore-size
le client n'affecte pas la taille des autres clients
no-detach-on-destroy
ne pas détacher le client lorsque la session à laquelle il est attaché est détruite s'il y a d'autres sessions
no-output
le client ne reçoit pas la sortie de la fenêtre en mode contrôle
pause-after=secondes
la sortie est mise en pause une fois que la fenêtre a secondes de retard en mode contrôle
read-only
le client est en lecture seule
wait-exit
attendre une ligne d'entrée vide avant de sortir en mode contrôle

Un ‘!’ en préfixe désactive un indicateur si le client est déjà attaché. -r est un alias pour -f read-only,ignore-size. Lorsqu'un client est en lecture seule, seules les touches liées aux commandes detach-client ou switch-client ont un effet. Un client avec l'indicateur active-pane permet de sélectionner la fenêtre active indépendamment de la fenêtre active de la fenêtre utilisée par les clients sans cet indicateur. Cela n'affecte que la position du curseur et les commandes émises par le client ; d'autres fonctionnalités telles que les hooks et les styles continuent d'utiliser la fenêtre active de la fenêtre.

Si aucun serveur n'est démarré, attach-session tentera de le démarrer ; cela échouera à moins que des sessions ne soient créées dans le fichier de configuration.

Les règles de session-cible pour attach-session sont légèrement ajustées : si tmux a besoin de sélectionner la session la plus récemment utilisée, il préférera la session non attachée la plus récemment utilisée.

-c définira le répertoire de travail de la session (utilisé pour les nouvelles fenêtres) à répertoire-travail.

Si -E est utilisé, l'option update-environment ne sera pas appliquée.

Détache le client courant s'il est lié à une touche, le client spécifié avec -t, ou tous les clients actuellement attachés à la session spécifiée par -s. L'option -a tue tous les clients sauf celui spécifié avec -t. Si -P est donné, envoie SIGHUP au processus parent du client, provoquant typiquement sa sortie. Avec -E, exécute shell-command pour remplacer le client.

new-session [-AdDEPX] [-c répertoire-de-démarrage] [-e environnement] [-f indicateurs] [-F format] [-n nom-fenêtre] [-s nom-session] [-t nom-groupe] [-x largeur] [-y hauteur] [commande-shell [argument ...]]
(alias : new)
Crée une nouvelle session avec le nom nom-session.

La nouvelle session est attachée au terminal actuel sauf si -d est donné. nom-fenêtre et commande-shell sont le nom et la commande shell à exécuter dans la fenêtre initiale. Avec -d, la taille initiale provient de l'option globale taille-par-défaut; -x et -y peuvent être utilisés pour spécifier une taille différente. ‘-’ utilise la taille du client actuel, le cas échéant. Si -x ou -y est donné, l'option taille-par-défaut est définie pour la session. -f définit une liste d'indicateurs client séparés par des virgules (voir attach-session).

Si exécuté depuis un terminal, tous les caractères spéciaux termios(4) sont sauvegardés et utilisés pour les nouvelles fenêtres dans la nouvelle session.

L'indicateur -A fait que new-session se comporte comme attach-session si nom-session existe déjà ; si -A est donné, -D se comporte comme -d pour attach-session, et -X se comporte comme -x pour attach-session.

Si -t est donné, il spécifie un groupe de sessions. Les sessions du même groupe partagent le même ensemble de fenêtres - les nouvelles fenêtres sont liées à toutes les sessions du groupe et toutes les fenêtres fermées sont retirées de toutes les sessions. La fenêtre actuelle et précédente, ainsi que toutes les options de session, restent indépendantes et toute session d'un groupe peut être tuée sans affecter les autres. Le argument nom-groupe peut être :

  1. le nom d'un groupe existant, auquel cas la nouvelle session est ajoutée à ce groupe ;
  2. le nom d'une session existante - la nouvelle session est ajoutée au même groupe que cette session, créant un nouveau groupe si nécessaire ;
  3. le nom d'un nouveau groupe ne contenant que la nouvelle session.

-n et commande-shell sont invalides si -t est utilisé.

L'option -P affiche des informations sur la nouvelle session après sa création. Par défaut, elle utilise le format ‘#{session_name}:’ mais un format différent peut être spécifié avec -F.

Si -E est utilisé, l'option mise-à-jour-environnement ne sera pas appliquée. -e prend la forme ‘VARIABLE=valeur’ et définit une variable d'environnement pour la session nouvellement créée ; elle peut être spécifiée plusieurs fois.

refresh-client [-cDLRSU] [-A pane:état] [-B nom:quoi:format] [-C taille] [-f indicateurs] [-l [pane-cible]] [-r pane:rapport] [-t client-cible] [ajustement]
(alias : refresh)
Rafraîchit le client actuel s'il est lié à une touche, ou un seul client s'il est spécifié avec -t. Si -S est spécifié, seule la ligne de statut du client est mise à jour.

Les indicateurs -U, -D, -L -R, et -c permettent de modifier la partie visible d'une fenêtre plus grande que le client. -U déplace la partie visible vers le haut de ajustement lignes et -D vers le bas, -L vers la gauche de ajustement colonnes et -R vers la droite. -c revient au suivi automatique du curseur. Si ajustement est omis, 1 est utilisé. Notez que la position visible est une propriété du client et non de la fenêtre ; changer la fenêtre actuelle dans la session attachée la réinitialisera.

-C définit la largeur et la hauteur d'un client en mode de contrôle ou d'une fenêtre pour un client en mode de contrôle, taille doit être l'une des formes ‘largeurxhauteur’ ou ‘ID-fenêtre:largeurxhauteur’, par exemple ‘80x24’ ou ‘@0:80x24’. -A permet à un client en mode de contrôle de déclencher des actions sur un pane. L'argument est un ID de pane (avec un ‘%’ préfixé), un deux-points, puis l'un de ‘on’, ‘off’, ‘continue’ ou ‘pause’. Si ‘off’, tmux n'enverra pas la sortie du pane au client et si tous les clients ont désactivé le pane, cessera de lire depuis le pane. Si ‘continue’, tmux reprendra l'envoi de la sortie vers le pane s'il était en pause (manuellement ou avec l'indicateur pause-après). Si ‘pause’, tmux mettra le pane en pause. -A peut être donné plusieurs fois pour différents panes.

-B définit un abonnement à un format pour un client en mode de contrôle. L'argument est divisé en trois éléments par des deux-points : nom est un nom pour l'abonnement ; quoi est un type d'élément auquel s'abonner ; format est le format. Après l'ajout d'un abonnement, les changements de format sont signalés avec la notification %changement-abonnement, au maximum une fois par seconde. Si seul le nom est donné, l'abonnement est supprimé. quoi peut être vide pour vérifier le format uniquement pour la session attachée, ou l'un des suivants : un ID de pane tel que ‘%0’ ; ‘%*’ pour tous les panes de la session attachée ; un ID de fenêtre tel que ‘@0’ ; ou ‘@*’ pour toutes les fenêtres de la session attachée.

-f définit une liste d'indicateurs client séparés par des virgules, voir attach-session. -r permet à un client en mode de contrôle de fournir des informations sur un pane via un rapport (tel que la réponse à OSC 10). L'argument est un ID de pane (avec un ‘%’ préfixé), un deux-points, puis une séquence d'échappement de rapport.

FENÊTRES ET PANES

Chaque fenêtre affichée par tmux peut être divisée en un ou plusieurs panes ; chaque pane occupe une certaine zone de l'affichage et est un terminal séparé. Une fenêtre peut être divisée en panes en utilisant la commande split-window. Les fenêtres peuvent être divisées horizontalement (avec l'indicateur -h) ou verticalement. Les panes peuvent être redimensionnés avec la commande resize-pane (liée par défaut à ‘C-Up’, ‘C-Down’, ‘C-Left’ et ‘C-Right’), le pane actuel peut être sélectionné avec la commande select-pane et les commandes rotate-window et swap-pane peuvent être utilisées pour échanger des panes sans changer leur position. Les panes sont numérotés à partir de zéro dans l'ordre où ils sont créés.

Par défaut, un pane tmux permet un accès direct au terminal contenu dans le pane. Un pane peut également être mis dans l'un des modes suivants :

  • Mode copie, qui permet de copier une section d'une fenêtre ou de son historique vers un tampon de collage pour une insertion ultérieure dans une autre fenêtre. Ce mode est entré avec la commande copy-mode, liée par défaut à ‘[’. Le texte copié peut être collé avec la commande paste-buffer, liée à ‘]’.
  • Mode vue, qui est similaire au mode copie mais est entré lorsqu'une commande produisant une sortie, telle que list-keys, est exécutée à partir d'une liaison de touche.
  • Mode choix, qui permet de choisir un élément dans une liste. Il peut s'agir d'un client, d'une session, d'une fenêtre ou d'un pane, ou d'un tampon. Ce mode est entré avec les commandes choose-buffer, choose-client et choose-tree.

En mode copie, un indicateur est affiché dans le coin supérieur droit du pane avec la position actuelle et le nombre de lignes dans l'historique.

Les commandes sont envoyées au mode copie en utilisant l'indicateur -X à la commande send-keys. Lorsqu'une touche est pressée, le mode copie utilise automatiquement l'une des deux tables de touches, en fonction de l'option mode-keys : copy-mode pour emacs, ou copy-mode-vi pour vi. Les tables de touches peuvent être visualisées avec la commande list-keys.

Les commandes de recherche sont de plusieurs types : ‘search-forward’ et ‘search-backward’ recherchent une expression régulière ; les variantes ‘-text’ recherchent une chaîne de texte brut plutôt qu'une expression régulière ; ‘-incremental’ effectuent une recherche incrémentielle et sont censées être utilisées avec le drapeau -i de la commande command-prompt. ‘search-again’ répète la dernière recherche et ‘search-reverse’ fait de même mais inverse la direction (avant devient arrière et arrière devient avant).

Les raccourcis clavier par défaut pour la recherche incrémentielle, ‘C-r’ et ‘C-s’, sont conçus pour émuler emacs(1). Lorsqu'ils sont pressés pour la première fois, ils permettent de saisir un nouveau terme de recherche ; s'ils sont pressés avec un terme de recherche vide, ils répètent le terme de recherche précédemment utilisé.

Les commandes ‘next-prompt’ et ‘previous-prompt’ se déplacent entre les invites du shell, mais nécessitent que le shell émette une séquence d'échappement (\033]133;A\033\\) pour indiquer à tmux où se trouvent les invites ; si le shell ne le fait pas, ces commandes ne feront rien. Le drapeau -o saute au début de la sortie de la commande au lieu de l'invite du shell. Trouver le début de la sortie de la commande nécessite que le shell émette une séquence d'échappement (\033]133;C\033\\) pour indiquer à tmux où commence la sortie. Si le shell n'envoie pas ces séquences d'échappement, ces commandes ne font rien.

Les commandes de copie peuvent être précédées d'un argument préfixe optionnel qui est utilisé pour générer le nom du tampon (le défaut est ‘buffer’ donc les tampons sont nommés ‘buffer0’, ‘buffer1’, etc.). Les commandes de pipe prennent un argument de commande qui est la commande à laquelle le texte sélectionné est pipé. Les variantes ‘copy-pipe’ copient également la sélection. Les variantes ‘-and-cancel’ de certaines commandes quittent le mode copie après leur achèvement (pour les commandes de copie) ou lorsque le curseur atteint le bas (pour les commandes de défilement). Les variantes ‘-no-clear’ n'effacent pas la sélection. Toutes les commandes de copie peuvent prendre les drapeaux -C et -P. Le drapeau -C supprime la définition du presse-papiers du terminal lors de la copie, tandis que le drapeau -P supprime l'ajout d'un tampon de collage avec le texte.

Les touches pour le mot suivant et le mot précédent sautent par-dessus les espaces blancs et traitent les séquences consécutives de séparateurs de mots ou d'autres lettres comme des mots. Les séparateurs de mots peuvent être personnalisés avec l'option de session word-separators. Le mot suivant se déplace au début du mot suivant, la fin du mot suivant à la fin du mot suivant et le mot précédent au début du mot précédent. Les trois touches d'espace suivant et précédent fonctionnent de manière similaire mais utilisent un seul espace comme séparateur de mot. Définir word-separators sur une chaîne vide rend les mots suivants/précédents équivalents aux espaces suivants/précédents.

Les commandes de saut permettent un déplacement rapide à l'intérieur d'une ligne. Par exemple, taper ‘f’ suivi de ‘/’ déplacera le curseur vers le prochain caractère ‘/’ sur la ligne actuelle. Un ‘;’ sautera alors à l'occurrence suivante.

Les commandes en mode copie peuvent être précédées d'un nombre de répétition optionnel. Avec les raccourcis clavier vi, un préfixe est entré en utilisant les touches numériques ; avec emacs, la touche Alt (meta) et un nombre commencent l'entrée du préfixe.

La syntaxe de la commande copy-mode est :

copy-mode [-deHMqSu] [-s src-pane] [-t target-pane]
Entrez en mode copie.

-u entre en mode copie et fait défiler d'une page vers le haut et -d d'une page vers le bas. -H masque l'indicateur de position en haut à droite. -q annule le mode copie et tous les autres modes.

-M commence un glisser-déposer de souris (uniquement valide si lié à un raccourci clavier de souris, voir SUPPORT DE LA SOURIS). -S défile lorsqu'il est lié à un événement de glisser-déposer de souris ; par exemple, copy-mode -Se est lié par défaut à MouseDrag1ScrollbarSlider.

-s copie depuis src-pane au lieu de target-pane.

-e spécifie que le défilement jusqu'en bas de l'historique (vers l'écran visible) doit quitter le mode copie. Pendant le mode copie, appuyer sur une touche autre que celles utilisées pour le défilement désactivera ce comportement. Ceci est destiné à permettre un défilement rapide de l'historique d'un panneau, par exemple avec :

bind PageUp copy-mode -eu
bind PageDown copy-mode -ed

Un certain nombre d'arrangements prédéfinis de panneaux sont disponibles, ceux-ci sont appelés des dispositions. Ceux-ci peuvent être sélectionnés avec la commande select-layout ou parcourus avec next-layout (lié à ‘Space’ par défaut) ; une fois une disposition choisie, les panneaux qu'elle contient peuvent être déplacés et redimensionnés normalement.

Les dispositions suivantes sont prises en charge :

even-horizontal
Les panneaux sont répartis uniformément de gauche à droite dans la fenêtre.
even-vertical
even-horizontal
Les panneaux sont répartis uniformément de haut en bas.
main-horizontal
Un grand panneau (principal) est affiché en haut de la fenêtre et les panneaux restants sont répartis de gauche à droite dans l'espace restant en bas. Utilisez l'option de fenêtre main-pane-height pour spécifier la hauteur du panneau supérieur.
main-horizontal-mirrored
Identique à main-horizontal mais inversé, de sorte que le panneau principal soit en bas de la fenêtre.
main-vertical
Un grand panneau (principal) est affiché à gauche de la fenêtre et les panneaux restants sont répartis de haut en bas dans l'espace restant à droite. Utilisez l'option de fenêtre main-pane-width pour spécifier la largeur du panneau de gauche.
main-vertical-mirrored
Identique à main-vertical mais inversé, de sorte que le panneau principal soit à droite de la fenêtre.
tiled
Les panneaux sont répartis aussi uniformément que possible sur la fenêtre, à la fois en lignes et en colonnes.

De plus, select-layout peut être utilisé pour appliquer une disposition précédemment utilisée - la commande list-windows affiche la disposition de chaque fenêtre sous une forme utilisable avec select-layout. Par exemple :

$ tmux list-windows
0: ksh [159x48]
    layout: bb62,159x48,0,0{79x48,0,0,79x48,80,0}
$ tmux select-layout 'bb62,159x48,0,0{79x48,0,0,79x48,80,0}'

tmux ajuste automatiquement la taille de la disposition à la taille actuelle de la fenêtre. Notez qu'une disposition ne peut pas être appliquée à une fenêtre comportant plus de panneaux que celle à partir de laquelle la disposition a été initialement définie.

Redimensionne un panneau, vers le haut, le bas, la gauche ou la droite de ajustement avec -U, -D, -L ou -R, ou à une taille absolue avec -x ou -y. L'ajustement est donné en lignes ou en colonnes (par défaut 1) ; -x et -y peuvent être un nombre de lignes ou de colonnes ou suivis de ‘%’ pour un pourcentage de la taille de la fenêtre (par exemple ‘-x 10%’). Avec -Z, le panneau actif est basculé entre zoomé (occupant toute la fenêtre) et dézoomé (sa position normale dans la mise en page).

-M démarre le redimensionnement à la souris (uniquement valide si lié à une liaison de touche souris, voir SUPPORT SOURIS).

-T coupe toutes les lignes sous la position actuelle du curseur et utilise les lignes de l'historique pour les remplacer.

resize-window [-aADLRU] [-t fenêtre-cible] [-x largeur] [-y hauteur] [ajustement]
(alias : resizew)
Redimensionne une fenêtre, vers le haut, le bas, la gauche ou la droite de ajustement avec -U, -D, -L ou -R, ou à une taille absolue avec -x ou -y. L'ajustement est donné en lignes ou en cellules (par défaut 1). -A définit la taille de la plus grande session contenant la fenêtre ; -a la taille de la plus petite. Cette commande définit automatiquement window-size à manuel dans les options de fenêtre.
respawn-pane [-k] [-c répertoire-de-démarrage] [-e environnement] [-t panneau-cible] [commande-shell [argument ...]]
(alias : respawnp)
Réactive un panneau dans lequel la commande s'est terminée (voir l'option de fenêtre remain-on-exit). Si commande-shell n'est pas donnée, la commande utilisée lors de la création du panneau ou lors de sa dernière réactivation est exécutée. Le panneau doit déjà être inactif, sauf si -k est donné, auquel cas la commande existante est tuée. -c spécifie un nouveau répertoire de travail pour le panneau. L'option -e a la même signification que pour la commande new-window.
respawn-window [-k] [-c répertoire-de-démarrage] [-e environnement] [-t fenêtre-cible] [commande-shell [argument ...]]
(alias : respawnw)
Réactive une fenêtre dans laquelle la commande s'est terminée (voir l'option de fenêtre remain-on-exit). Si commande-shell n'est pas donnée, la commande utilisée lors de la création de la fenêtre ou lors de sa dernière réactivation est exécutée. La fenêtre doit déjà être inactive, sauf si -k est donné, auquel cas la commande existante est tuée. -c spécifie un nouveau répertoire de travail pour la fenêtre. L'option -e a la même signification que pour la commande new-window.
rotate-window [-DUZ] [-t fenêtre-cible]
(alias : rotatew)
Fait pivoter les positions des panneaux dans une fenêtre, soit vers le haut (numériquement plus bas) avec -U soit vers le bas (numériquement plus haut) avec -D. -Z garde la fenêtre zoomée si elle l'était.
select-layout [-Enop] [-t panneau-cible] [nom-de-mise-en-page]
(alias : selectl)
Choisit une mise en page spécifique pour une fenêtre. Si nom-de-mise-en-page n'est pas donné, la dernière mise en page prédéfinie utilisée (le cas échéant) est réappliquée. -n et -p sont équivalents aux commandes next-layout et previous-layout. -o applique la dernière mise en page définie si possible (annule la dernière modification de mise en page). -E répartit le panneau actuel et tous les panneaux adjacents de manière égale.
select-pane [-DdeLlMmRUZ] [-T titre] [-t panneau-cible]
(alias : selectp)
Fait du panneau panneau-cible le panneau actif dans sa fenêtre. Si l'une des options -D, -L, -R, ou -U est utilisée, respectivement le panneau en dessous, à gauche, à droite, ou au-dessus du panneau cible est sélectionné. -Z garde la fenêtre zoomée si elle l'était. -l est identique à l'utilisation de la commande last-pane. -e active ou -d désactive l'entrée vers le panneau. -m et -M sont utilisés pour définir et effacer la fenêtre marquée. Il n'y a qu'une seule fenêtre marquée à la fois, la définition d'une nouvelle fenêtre marquée efface la précédente. La fenêtre marquée est la cible par défaut pour -s pour join-pane, move-pane, swap-pane et swap-window.

select-window [-lnpT] [-t cible-fenêtre]
(alias: selectw)
Sélectionne la fenêtre à cible-fenêtre. -l, -n et -p sont équivalents aux commandes last-window, next-window et previous-window. Si -T est donné et que la fenêtre sélectionnée est déjà la fenêtre actuelle, la commande se comporte comme last-window.
split-window [-bdfhIvPZ] [-c répertoire-de-démarrage] [-e environnement] [-F format] [-l taille] [-t cible-fenêtre] [commande-shell [argument ...]]
(alias: splitw)
Crée une nouvelle fenêtre en divisant cible-fenêtre : -h effectue une division horizontale et -v une division verticale ; si aucune n'est spécifiée, -v est supposée. L'option -l spécifie la taille de la nouvelle fenêtre en lignes (pour une division verticale) ou en colonnes (pour une division horizontale) ; taille peut être suivie de ‘%’ pour spécifier un pourcentage de l'espace disponible. L'option -b provoque la création de la nouvelle fenêtre à gauche ou au-dessus de cible-fenêtre. L'option -f crée une nouvelle fenêtre couvrant toute la hauteur de la fenêtre (avec -h) ou toute la largeur de la fenêtre (avec -v), au lieu de diviser la fenêtre active. -Z zoome si la fenêtre n'est pas zoomée, ou la maintient zoomée si elle l'est déjà.

Une commande-shell vide ('') créera une fenêtre sans commande en cours d'exécution. La sortie peut être envoyée à une telle fenêtre avec la commande display-message. Le drapeau -I (si commande-shell n'est pas spécifié ou est vide) créera une fenêtre vide et redirigera toute sortie de stdin vers celle-ci. Par exemple :

$ make 2>&1|tmux splitw -dI &

Toutes les autres options ont la même signification que pour la commande new-window.

swap-pane [-dDUZ] [-s fenêtre-source] [-t fenêtre-destination]
(alias: swapp)
Échange deux fenêtres. Si -U est utilisé et qu'aucune fenêtre source n'est spécifiée avec -s, fenêtre-destination est échangée avec la fenêtre précédente (numériquement avant) ; -D échange avec la fenêtre suivante (numériquement après). -d indique à tmux de ne pas changer la fenêtre active et -Z maintient la fenêtre zoomée si elle l'était.

Si -s est omis et qu'une fenêtre marquée est présente (voir select-pane -m), la fenêtre marquée est utilisée à la place de la fenêtre actuelle.

swap-window [-d] [-s fenêtre-source] [-t fenêtre-destination]
(alias: swapw)
Ceci est similaire à link-window, sauf que les fenêtres source et destination sont échangées. C'est une erreur si aucune fenêtre n'existe à fenêtre-source. Si -d est donné, la nouvelle fenêtre ne devient pas la fenêtre actuelle.

Si -s est omis et qu'une fenêtre marquée est présente (voir select-pane -m), la fenêtre contenant la fenêtre marquée est utilisée à la place de la fenêtre actuelle.

unlink-window [-k] [-t cible-fenêtre]
(alias: unlinkw)
Délivre cible-fenêtre. À moins que -k ne soit donné, une fenêtre ne peut être déliée que si elle est liée à plusieurs sessions - les fenêtres ne peuvent pas être liées à aucune session ; si -k est spécifié et que la fenêtre n'est liée qu'à une seule session, elle est déliée et détruite.

RACC`I DU CL`AVIER

tmux permet de lier une commande à la plupart des touches, avec ou sans touche de préfixe. Lors de la spécification des touches, la plupart se représentent elles-mêmes (par exemple, ‘A’ à ‘Z’). Les touches Ctrl peuvent être préfixées par ‘C-’ ou ‘^’, les touches Shift par ‘S-’ et Alt (meta) par ‘M-’. De plus, les noms de touches spéciaux suivants sont acceptés : Up, Down, Left, Right, BSpace, BTab, DC (Delete), End, Enter, Escape, F1 à F12, Home, IC (Insert), NPage/PageDown/PgDn, PPage/PageUp/PgUp, Space, et Tab. Notez que pour lier les touches ‘"’ ou ‘'’, des guillemets sont nécessaires, par exemple :

bind-key '"' split-window
bind-key "'" new-window

Une commande liée à la touche Toute s'exécutera pour toutes les touches qui n'ont pas de liaison plus spécifique.

Les commandes relatives aux liaisons de touches sont les suivantes :

bind-key [-nr] [-N note] [-T table-clés] clé [commande [argument ...]]
(alias: bind)
Lie la touche clé à la commande commande. Les touches sont liées dans une table de touches. Par défaut (sans -T), la touche est liée dans la table de touches préfixe. Cette table est utilisée pour les touches pressées après la touche de préfixe (par exemple, par défaut ‘c’ est liée à new-window dans la table préfixe, donc ‘C-b c’ crée une nouvelle fenêtre). La table racine est utilisée pour les touches pressées sans la touche de préfixe : lier ‘c’ à new-window dans la table racine (non recommandé) signifie qu'un simple ‘c’ créera une nouvelle fenêtre. -n est un alias pour -T racine. Les touches peuvent également être liées dans des tables de touches personnalisées et la commande switch-client -T utilisée pour passer de celles-ci à partir d'une liaison de touche. Le drapeau -r indique que cette touche peut se répéter, voir les options initial-repeat-time et repeat-time. -N attache une note à la touche (affichée avec list-keys -N), qui peut être effacée en passant une chaîne vide. Les drapeaux -r et -N peuvent être utilisés sans commande pour modifier une liaison existante.

Pour voir les liaisons par défaut et les commandes possibles, consultez la commande list-keys.

list-keys [-1aN] [-P chaîne-préfixe] [-T table-clés] [clé]
(alias: lsk)
Liste les liaisons de touches. Il existe deux formes : la forme par défaut liste les touches sous forme de commandes bind-key ; -N liste uniquement les touches avec des notes attachées et n'affiche que la touche et la note pour chaque touche.

Avec la forme par défaut, toutes les tables de touches sont listées par défaut. -T liste uniquement les touches dans la table .

Ar">table de clés.

Avec la forme -N, seules les clés des tables de clés root et prefix sont listées par défaut ; -T liste également seulement les clés de la table-de-clés. -P spécifie un préfixe à imprimer avant chaque clé et -1 ne liste que la première clé correspondante. -a liste la commande pour les clés qui n'ont pas de note au lieu de les sauter.

envoyer-clés [-FHKlMRX] [-c client-cible] [-N nombre-répétitions] [-t pane-cible] [clé ...]
(alias : envoyer)
Envoie une ou plusieurs touches à une fenêtre ou un client. Chaque argument clé est le nom de la touche (tel que ‘C-a’ ou ‘NPage’) à envoyer ; si la chaîne n'est pas reconnue comme une touche, elle est envoyée comme une série de caractères. Si -K est donné, les touches sont envoyées au client-cible, donc elles sont recherchées dans la table des clés du client, plutôt qu'au pane-cible. Tous les arguments sont envoyés séquentiellement du premier au dernier. Si aucune touche n'est donnée et que la commande est liée à une touche, alors cette touche est utilisée.

L'indicateur -l désactive la recherche du nom des touches et traite les touches comme des caractères UTF-8 littéraux. L'indicateur -H attend que chaque touche soit un nombre hexadécimal pour un caractère ASCII.

L'indicateur -R provoque la réinitialisation de l'état du terminal.

-M transmet un événement de souris (uniquement valide s'il est lié à une liaison de touche de souris, voir SUPPORT DE LA SOURIS).

-X est utilisé pour envoyer une commande en mode copie - voir la section FENÊTRES ET PANS. -N spécifie un nombre de répétitions et -F développe les formats dans les arguments le cas échéant.

envoyer-préfixe [-2] [-t pane-cible]
Envoie la touche préfixe, ou avec -2 la touche préfixe secondaire, à une fenêtre comme si elle avait été pressée.
déverrouiller-clé [-anq] [-T table-de-clés] clé
(alias : déverrouiller)
Déverrouille la commande liée à la clé. -n et -T sont identiques à ceux de verrouiller-clé. Si -a est présent, toutes les liaisons de touches sont supprimées. L'option -q empêche les erreurs.

OPTIONS

L'apparence et le comportement de tmux peuvent être modifiés en changeant la valeur de diverses options. Chaque option appartient à une ou plusieurs portées (serveur, session, fenêtre et pane) et a un type (chaîne, nombre, clé, couleur, indicateur, choix, ou commande). Les valeurs des options de type indicateur peuvent être l'une des suivantes : 1, on, yes, 0, off, ou no ; pour les valeurs choix possibles, voir l'option respective ; pour les options clé, la section LIAISONS DE CLÉS ; et pour les options couleur, la section STYLES.

Le serveur tmux a un ensemble d'options de serveur globales qui ne s'appliquent à aucune fenêtre, session ou pane particulier. Celles-ci sont modifiées avec la commande définir-option -s, ou affichées avec la commande afficher-options -s.

De plus, chaque session individuelle peut avoir un ensemble d'options de session, et il existe un ensemble distinct d'options de session globales. Les sessions qui n'ont pas d'option particulière configurée héritent de la valeur des options de session globales. Les options de session sont définies ou désactivées avec la commande définir-option et peuvent être listées avec la commande afficher-options. Les options de serveur et de session disponibles sont listées sous la commande définir-option.

De même, un ensemble d'options de fenêtre est attaché à chaque fenêtre et un ensemble d'options de pane à chaque pane. Les options de pane héritent des options de fenêtre. Cela signifie que toute option de pane peut être définie comme une option de fenêtre pour appliquer l'option à tous les panes de la fenêtre sans que l'option soit définie, par exemple, ces commandes définiront la couleur de fond en rouge pour tous les panes sauf le pane 0 :

définir -w style-fenêtre bg=rouge
définir -pt:.0 style-fenêtre bg=bleu

Il existe également un ensemble d'options de fenêtre globales dont toutes les options de fenêtre ou de pane non définies sont héritées. Les options de fenêtre et de pane sont modifiées avec les commandes définir-option -w et -p et affichées avec afficher-option -w et -p.

tmux prend également en charge les options utilisateur qui sont préfixées par un ‘@’. Les options utilisateur peuvent avoir n'importe quel nom, tant qu'elles sont préfixées par ‘@’, et être définies sur n'importe quelle chaîne. Par exemple :

$ tmux définir -wq @foo "abc123"
$ tmux montrer -wv @foo
abc123

Les options sont gérées avec ces commandes :

définir-option [-aFgopqsuUw] [-t pane-cible] option [valeur]
(alias : définir)
Définit une option de pane avec -p, une option de fenêtre avec -w, une option de serveur avec -s, sinon une option de session. Si l'option n'est pas une option utilisateur, -w ou -s peuvent être inutiles - tmux inférera la portée à partir du nom de l'option, en supposant -w pour les options de pane. Si -g est donné, l'option globale de session ou de fenêtre est définie.

-F développe les formats dans la valeur de l'option. L'indicateur -u désactive une option, donc une session hérite de l'option des options globales (ou avec -g, restaure une option globale à la valeur par défaut). -U désactive une option (comme -u) mais si l'option est une option de pane, désactive également l'option sur tous les panes de la fenêtre. La valeur dépend de l'option et de son type et peut être omise pour les options indicateur et choix afin de basculer sa valeur (les options choix basculent entre les deux premiers choix).

L'indicateur -o empêche la définition d'une option déjà définie et l'indicateur -q supprime les erreurs concernant des options inconnues ou ambiguës.

Avec -a, et si l'option attend une chaîne ou un style, la valeur est ajoutée au réglage existant. Par exemple :

définir -g status-gauche "foo"
définir -ag status-gauche "bar"

Résultera en ‘foobar’. Et :

définir -g style-statut "bg=rouge"
définir -ag style-statut "fg=bleu"

Résultera en un fond rouge et un premier plan bleu. Sans -a, le résultat serait le fond par défaut et un premier plan bleu.

montrer-options [-AgHpqsvw] [-t pane-cible] [option]
(alias : montrer)
Affiche les options de pane (ou une seule option si option est fournie) avec -p, les options de fenêtre avec -w, les options de serveur avec -s, sinon les options de session. Si l'option n'est pas une option utilisateur, -w ou -s peuvent être inutiles - tmux inférera la portée à partir du nom de l'option, en supposant -w pour les options de pane. Les options globales de session ou de fenêtre sont listées si -g est utilisé. -v affiche uniquement la valeur de l'option, pas le nom. Si -q est défini, aucune erreur ne sera renvoyée si option est non définie. -H inclut les crochets (omis par défaut). -A inclut les options héritées d'un ensemble d'options parent, ces options sont marquées d'un astérisque.

Les options de serveur disponibles sont :

retour-chariot clé
Définit la touche envoyée par tmux pour la touche retour chariot.
limite-tampon nombre
Définit le nombre de tampons ; lorsque de nouveaux tampons sont ajoutés en haut de la pile, les anciens sont supprimés du bas si nécessaire pour maintenir cette longueur maximale.
alias-commande[] nom=valeur
Ceci est un tableau d'alias personnalisés pour les commandes. Si une commande inconnue correspond au nom, elle est remplacée par valeur. Par exemple, après :
set -s command-alias[100] zoom='resize-pane -Z'

L'utilisation de :

zoom -t:.1

Est équivalente à :

resize-pane -Z -t:.1

Notez que les alias sont développés lors de l'analyse d'une commande plutôt que lors de son exécution, donc la liaison d'un alias avec bind-key liera la forme développée.

codepoint-widths[] chaîne
Une option de tableau permettant de remplacer les largeurs des points de code Unicode. Notez que la nouvelle largeur s'applique à tous les clients. Chaque entrée est de la forme pointdecodage=largeur, où pointdecodage peut être un caractère UTF-8 ou un identifiant de la forme « U+nombre », où le nombre est un nombre hexadécimal.
copy-command commande-shell
Définit la commande à utiliser lors d'un pipe si la commande de mode copie copy-pipe est utilisée sans arguments.
default-client-command commande
Définit la commande par défaut à exécuter lorsque tmux est appelé sans commande. La valeur par défaut est new-session.
default-terminal terminal
Définit le terminal par défaut pour les nouvelles fenêtres créées dans cette session - la valeur par défaut de la variable d'environnement TERM. Pour que tmux fonctionne correctement, cette option doit être définie sur « screen », « tmux » ou un dérivé de ceux-ci.
escape-time temps
Définit le temps en millisecondes pendant lequel tmux attend après qu'une échappatoire ait été saisie pour déterminer s'il fait partie d'une séquence de touches de fonction ou méta.
editor commande-shell
Définit la commande utilisée lorsque tmux exécute un éditeur.
exit-empty [on | off]
Si activé (par défaut), le serveur se terminera lorsqu'il n'y aura plus de sessions actives.
exit-unattached [on | off]
Si activé, le serveur se terminera lorsqu'il n'y aura plus de clients attachés.
extended-keys [on | off | always]
Contrôle la manière dont les touches modifiées (touches appuyées simultanément avec Control, Meta ou Shift) sont rapportées. Ceci est l'équivalent de la ressource modifyOtherKeys de xterm(1).

Lorsqu'il est défini sur on, le programme à l'intérieur du pane peut demander l'un des deux modes : le mode 1 qui modifie la séquence uniquement pour les touches qui n'ont pas de représentation bien connue existante ; ou le mode 2 qui modifie la séquence pour toutes les touches. Lorsqu'il est défini sur always, les modes 1 et 2 peuvent toujours être demandés par les applications, mais le mode 1 sera forcé au lieu du mode standard. Lorsqu'il est défini sur off, cette fonctionnalité est désactivée et seules les touches standard sont rapportées.

tmux demandera toujours les touches étendues lui-même si le terminal les prend en charge. Voir aussi la fonctionnalité extkeys pour l'option terminal-features, l'option extended-keys-format et la variable pane_key_mode.

extended-keys-format [csi-u | xterm]
Sélectionne l'un des deux formats possibles pour rapporter les touches modifiées aux applications. Ceci est l'équivalent de la ressource formatOtherKeys de xterm(1). Par exemple, C-S-a sera rapporté comme « ^[[27;6;65~ » lorsqu'il est défini sur xterm, et comme « ^[[65;6u » lorsqu'il est défini sur csi-u.
focus-events [on | off]
Lorsqu'il est activé, les événements de focus sont demandés au terminal s'il les prend en charge et transmis aux applications exécutées dans tmux. Les clients attachés doivent être détachés et réattachés après avoir modifié cette option.
history-file chemin
Si ce n'est pas vide, un fichier dans lequel tmux écrira l'historique des invites de commande à la sortie et le chargera au démarrage.
input-buffer-size octets
Nombre maximum d'octets autorisés à être lus dans les séquences d'échappement et de contrôle. Une fois atteint, la séquence sera rejetée.
message-limit nombre
Définit le nombre de messages d'erreur ou d'information à sauvegarder dans le journal des messages pour chaque client.
prompt-history-limit nombre
Définit le nombre d'éléments d'historique à sauvegarder dans le fichier d'historique pour chaque type d'invite de commande.
set-clipboard [on | external | off]
Tente de définir le contenu du presse-papiers du terminal à l'aide de la séquence d'échappement xterm(1), s'il existe une entrée Ms dans la description terminfo(5) (voir la section EXTENSIONS TERMINFO).

Si défini sur on, tmux acceptera la séquence d'échappement pour créer un tampon et tentera de définir le presse-papiers du terminal. S'il est défini sur external, tmux tentera de définir le presse-papiers du terminal mais ignorera les tentatives des applications de définir les tampons de tmux. Si défini sur off, tmux n'acceptera pas la séquence d'échappement du presse-papiers et ne tentera pas de définir le presse-papiers.

Notez que cette fonctionnalité doit être activée dans xterm(1) en définissant la ressource :

disallowedWindowOps: 20,21,SetXprop

Ou en modifiant cette propriété depuis le menu interactif de xterm(1) lorsque nécessaire.

terminal-features[] chaîne
Définit les fonctionnalités du terminal pour les types de terminaux lus depuis terminfo(5). tmux possède un ensemble de fonctionnalités de terminal nommées. Chacune apportera les modifications appropriées à l'entrée terminfo(5) utilisée.

tmux peut détecter les fonctionnalités de quelques terminaux courants ; cette option peut être utilisée pour informer facilement tmux des fonctionnalités prises en charge par les terminaux qu'il ne peut pas détecter. L'option terminal-overrides permet de définir des capacités individuelles de terminfo(5) à la place ; terminal-features est destiné aux classes de fonctionnalités prises en charge de manière standard mais non rapportées par terminfo(5). Il faut veiller à ne configurer ceci qu'avec des fonctionnalités que le terminal prend réellement en charge.

Il s'agit d'une option de tableau où chaque entrée est une chaîne séparée par des deux-points, composée d'un modèle de type de terminal (correspondant à l'aide de modèles glob(7)) suivi d'une liste de fonctionnalités de terminal. Les fonctionnalités disponibles sont :

256
Prend en charge 256 couleurs avec les séquences d'échappement SGR.
clipboard
Permet de définir le presse-papiers système.
ccolour
Permet de définir la couleur du curseur.
cstyle
Permet de définir le style du curseur.
extkeys
Prend en charge les touches étendues.
focus
Prend en charge le rapport de focus.
hyperlinks
Prend en charge les hyperliens OSC 8.
ignorefkeys
Ignore les touches de fonction de terminfo(5) et utilise uniquement le jeu interne de tmux.
margins
Prend en charge les marges DECSLRM.
mouse
Prend en charge les séquences de souris de xterm(1).
osc7
Prend en charge l'extension du répertoire de travail OSC 7.
overline
Prend en charge l'attribut SGR de surlignage.
rectfill
Prend en charge la séquence d'échappement de remplissage de rectangle DECFRA.
RGB
Prend en charge les couleurs RVB avec les séquences d'échappement SGR.
sixel
Prend en charge les graphiques SIXEL.
strikethrough
Prend en charge la séquence d'échappement SGR de barré.
sync
Prend en charge les mises à jour synchronisées.
title
Prend en charge la définition du titre de xterm(1).
usstyle
Permet le style de soulignement
re style et couleur à définir.
terminal-overrides[] string
Permet de remplacer les descriptions de terminal lues à l'aide de terminfo(5). Chaque entrée est une chaîne séparée par des deux-points composée d'un modèle de type de terminal (correspondant à l'aide de modèles glob(7)) et d'un ensemble d'entrées nom=valeur.

HOOKS

tmux permet d'exécuter des commandes sur divers déclencheurs, appelés hooks. La plupart des commandes tmux ont une hook after et il existe un certain nombre de hooks non associés à des commandes.

Les hooks sont stockés sous forme d'options tableau, les membres du tableau sont exécutés dans l'ordre lorsque le hook est déclenché. Comme les options, différents hooks peuvent être globaux ou appartenir à une session, une fenêtre ou une fenêtre. Les hooks peuvent être configurés avec les commandes set-hook ou set-option et affichés avec show-hooks ou show-options -H. Les deux commandes suivantes sont équivalentes :

set-hook -g pane-mode-changed[42] 'set -g status-left-style bg=red'
set-option -g pane-mode-changed[42] 'set -g status-left-style bg=red'

La définition d'un hook sans spécifier d'index de tableau efface le hook et définit le premier membre du tableau.

Le hook `after` d'une commande est exécuté après sa complétion, sauf lorsque la commande est exécutée dans le cadre d'un hook lui-même. Ils sont nommés avec un préfixe ‘after-’. Par exemple, la commande suivante ajoute un hook pour sélectionner la disposition verticale paire après chaque split-window :

set-hook -g after-split-window "selectl even-vertical"

Si une commande échoue, le hook ‘command-error’ sera déclenché. Par exemple, cela pourrait être utilisé pour écrire dans un fichier journal :

set-hook -g command-error "run-shell \"echo 'a tmux command failed' >>/tmp/log\""

FORMATS

Certaines commandes acceptent le drapeau -F avec un argument de format. Il s'agit d'une chaîne qui contrôle le format de sortie de la commande. Les variables de format sont entourées de ‘#{’ et ‘}’, par exemple ‘#{session_name}’. Les variables possibles sont listées dans le tableau ci-dessous, ou le nom d'une option tmux peut être utilisé pour la valeur d'une option, ou le nom d'une variable d'environnement. Certaines variables ont un alias plus court tel que ‘#S’; ‘##’ est remplacé par un seul ‘#’, ‘#,’ par une virgule ‘,’ et ‘#}’ par une accolade fermante ‘}’.

Les conditions sont disponibles en préfixant par ‘?’. Pour chaque paire de deux arguments, si la variable du premier de la paire existe et n'est pas zéro, le second de la paire est choisi, sinon il continue. Si aucune condition parmi les arguments appariés ne correspond, la valeur par défaut est choisie. S'il n'y a pas d'argument final impair, c'est la valeur par défaut. Sinon, la valeur par défaut est la chaîne vide. Par exemple ‘#{?session_attached,attached,not attached}’ inclura la chaîne ‘attached’ si la session est attachée et la chaîne ‘not attached’ si elle ne l'est pas, ou ‘#{?automatic-rename,yes,no}’ inclura ‘yes’ si automatic-rename est activé, ou ‘no’ sinon. ‘#{?#{n:window_name},#{window_name} - }’ inclura le nom de la fenêtre avec un séparateur trait d'union s'il y a un nom de fenêtre, ou la chaîne vide si le nom de la fenêtre est vide. ‘#{?session_format,format1,window_format,format2,format3}’ inclura format1 pour un format de session, format2 pour un format de fenêtre, ou format3 pour ni un format de session ni de fenêtre. Les conditions peuvent être imbriquées arbitrairement. Dans une condition, ‘,’ et ‘}’ doivent être échappés en tant que ‘#,’ et ‘#}’, sauf s'ils font partie d'un remplacement ‘#{...}’. Par exemple :

#{?pane_in_mode,#[fg=white#,bg=red],#[fg=red#,bg=white]}#W

Les comparaisons de chaînes peuvent être exprimées en préfixant deux alternatives séparées par des virgules par ‘==’, ‘!=’, ‘<’, ‘>’, ‘<=’ ou ‘>=’ et un deux-points. Par exemple ‘#{==:#{host},myhost}’ sera remplacé par ‘1’ si exécuté sur ‘myhost’, sinon par ‘0’. ‘||’ et ‘&&’ évaluent à vrai si une ou toutes les alternatives séparées par des virgules sont vraies, par exemple ‘#{||:#{pane_in_mode},#{alternate_on}}’. ‘!’ évalue à vrai si la valeur est fausse et vice versa, par exemple ‘#{!:#{pane_in_mode}}’. ‘!!’ convertit une valeur dans une forme booléenne canonique, 1 pour vrai et 0 pour faux, par exemple ‘#{!!:non-empty string}’ évalue à 1.

Un ‘m’ spécifie une comparaison de modèle glob(7) ou une expression régulière. Le premier argument est le modèle et le second la chaîne à comparer. Un argument optionnel spécifie des drapeaux : ‘r’ signifie que le modèle est une expression régulière au lieu du modèle par défaut glob(7), et ‘i’ signifie ignorer la casse. Par exemple : ‘#{m:*foo*,#{host}}’ ou ‘#{m/ri:^A,MYVAR}’. Un ‘C’ effectue une recherche d'un modèle glob(7) ou d'une expression régulière dans le contenu du volet et évalue à zéro si non trouvé, ou à un numéro de ligne si trouvé. Comme ‘m’, un drapeau ‘r’ signifie rechercher une expression régulière et ‘i’ ignore la casse. Par exemple : ‘#{C/r:^Start}’

Les opérateurs numériques peuvent être effectués en préfixant deux alternatives séparées par des virgules par un ‘e’ et un opérateur. Un drapeau optionnel ‘f’ peut être donné après l'opérateur pour utiliser des nombres à virgule flottante, sinon des entiers sont utilisés. Ceci peut être suivi d'un nombre donnant le nombre de décimales à utiliser pour le résultat. Les opérateurs disponibles sont : addition ‘+’, soustraction ‘-’, multiplication ‘*’, division ‘/’, modulo ‘m’ ou ‘%’ (notez que ‘%’ doit être échappé en tant que ‘%%’ dans les formats qui sont aussi développés par strftime(3)) et les opérateurs de comparaison numérique ‘==’, ‘!=’, ‘<’, ‘<=’, ‘>’ et ‘>=’. Par exemple, ‘#{e|*|f|4:5.5,3}’ multiplie 5.5 par 3 pour un résultat avec quatre décimales et ‘#{e|%%:7,3}’ retourne le reste de la division de 7 par 3. ‘a’ remplace un argument numérique par son équivalent ASCII, donc ‘#{a:98}’ résulte en ‘b’. ‘c’ remplace une couleur tmux par sa valeur RGB hexadécimale à six chiffres.

Une limite peut être placée sur la longueur de la chaîne résultante en la préfixant par un ‘=’, un nombre et un deux-points. Les nombres positifs comptent à partir du début de la chaîne et les négatifs à partir de la fin, donc ‘#{=5:pane_title}’ inclura au maximum les cinq premiers caractères du titre du volet, ou ‘#{=-5:pane_title}’ les cinq derniers caractères. Un suffixe ou un préfixe peut être donné comme second argument - s'il est fourni, il est alors ajouté ou préfixé à la chaîne si la longueur a été tronquée, par exemple ‘#{=/5/...:pane_title}’ ajoutera ‘...’ si le titre du volet a plus de cinq caractères. De même, ‘p’ remplit la chaîne jusqu'à une largeur donnée, par exemple ‘#{p10:pane_title}’ résultera en une largeur d'au moins 10 caractères. Une largeur positive remplit à gauche, une largeur négative à droite. ‘n’ développe la longueur de la variable et ‘w’ sa largeur lors de l'affichage, par exemple ‘#{n:window_name}’. ‘R’ répète le premier argument par un nombre de fois donné par le second argument, donc ‘#{R:a,3}’ résultera en ‘aaa’.

Préfixer une variable de temps par ‘t:’ la convertira en une chaîne, donc si ‘#{window_activity}’ donne ‘1445765102’, ‘#{t:window_activity}’ donne ‘Sun Oct 25 09:25:02 2015’. L'ajout de ‘p (’ ‘`t/p`’) utilisera un format de temps plus court mais moins précis pour

. fois dans le passé. Un format personnalisé peut être donné en utilisant un suffixe ‘f’ (notez que ‘%’ doit être échappé en ‘%%’ si le format est séparément passé par strftime(3), par exemple dans l'option status-left) : ‘#{t/f/%%H#:%%M:window_activity}’, voir strftime(3).

Les préfixes ‘b:’ et ‘d:’ sont respectivement le basename(3) et le dirname(3) de la variable. ‘q:’ échappera les caractères spéciaux de sh(1) ou avec un suffixe ‘h’, échappera les caractères hash (ainsi ‘#’ devient ‘##’). ‘E:’ étendra le format deux fois, par exemple ‘#{E:status-left}’ est le résultat de l'expansion du contenu de l'option status-left plutôt que l'option elle-même. ‘T:’ est comme ‘E:’ mais étend aussi les spécificateurs de strftime(3). ‘S:’, ‘W:’, ‘P:’ ou ‘L:’ itéreront sur chaque session, fenêtre, pane ou client et inséreront le format une fois pour chacun. ‘L:’, ‘S:’ et ‘W:’ peuvent prendre un argument de tri optionnel ‘/i’, ‘/n’, ‘/t’ pour trier par index, nom ou heure de dernière activité ; de plus ‘/r’ pour trier dans l'ordre inverse. ‘/r’ peut aussi être utilisé avec ‘P:’ pour inverser l'ordre de tri par index de pane. Par exemple, ‘S/nr:’ pour trier les sessions par nom en ordre inverse. Pour chacun, deux formats séparés par des virgules peuvent être donnés : le second est utilisé pour la fenêtre courante, le pane actif, ou la session active. Par exemple, pour obtenir une liste de fenêtres formatée comme la ligne de statut :

#{W:#{E:window-status-format} ,#{E:window-status-current-format} }

‘N:’ vérifie si un nom de fenêtre (sans suffixe ou avec le suffixe ‘w’) ou de session (avec le suffixe ‘s’) existe, par exemple ‘`N/w:foo`’ est remplacé par 1 si une fenêtre nommée ‘foo’ existe.

Un préfixe de la forme ‘s/foo/bar/:’ substituera ‘foo’ par ‘bar’ partout. Le premier argument peut être une expression régulière étendue et un argument final peut être ‘i’ pour ignorer la casse, par exemple ‘s/a(.)/\1x/i:’ changerait ‘abABab’ en ‘bxBxbx’. Un délimiteur différent peut aussi être utilisé, pour éviter les collisions avec les slashes littéraux dans le motif. Par exemple, ‘s|foo/|bar/|:’ substituera ‘foo/’ par ‘bar/’ partout.

Plusieurs modificateurs peuvent être séparés par un point-virgule (;) comme dans ‘#{T;=10:status-left}’, ce qui limite la chaîne résultante étendue par strftime(3) à 10 caractères au maximum.

De plus, la dernière ligne de la sortie d'une commande shell peut être insérée en utilisant ‘#()’. Par exemple, ‘#(uptime)’ insérera le temps de fonctionnement du système. Lors de la construction des formats, tmux n'attend pas que les commandes ‘#()’ se terminent ; au lieu de cela, le résultat précédent de l'exécution de la même commande est utilisé, ou un espace réservé si la commande n'a pas été exécutée auparavant. Si la commande n'est pas terminée, la dernière ligne de sortie sera utilisée, mais la ligne de statut ne sera pas mise à jour plus d'une fois par seconde. Les commandes sont exécutées en utilisant /bin/sh et avec l'environnement global de tmux défini (voir la section ENVIRONNEMENT GLOBAL ET DE SESSION).

Un ‘l’ spécifie qu'une chaîne doit être interprétée littéralement et non étendue. Par exemple ‘#{l:#{?pane_in_mode,yes,no}}’ sera remplacé par ‘#{?pane_in_mode,yes,no}’.

STYLES

tmux propose diverses options pour spécifier la couleur et les attributs des aspects de l'interface, par exemple status-style pour la ligne de statut. De plus, des styles intégrés peuvent être spécifiés dans les options de format, tels que status-left, en les entourant de ‘#[’ et ‘]’.

Un style peut être le terme unique ‘default’ pour spécifier le style par défaut (qui peut provenir d'une option, par exemple status-style dans la ligne de statut) ou une liste séparée par des espaces ou des virgules des éléments suivants :

fg=couleur
Définit la couleur de premier plan. La couleur est l'une des suivantes : black, red, green, yellow, blue, magenta, cyan, white ; si pris en charge, les variantes lumineuses brightblack, brightred, ... ; colour0 à colour255 de l'ensemble de 256 couleurs ; default pour la couleur par défaut ; terminal pour la couleur par défaut du terminal ; ou une chaîne RVB hexadécimale telle que ‘#ffffff’.
bg=couleur
Définit la couleur d'arrière-plan.
us=couleur
Définit la couleur du soulignement.
none
Définit aucun attribut (désactive tous les attributs actifs).
acs, bright (ou bold), dim, underscore, blink, reverse, hidden, italics, overline, strikethrough, double-underscore, curly-underscore, dotted-underscore, dashed-underscore
Définit un attribut. Tous les attributs peuvent être précédés de ‘no’ pour les désactiver. acs est l'ensemble de caractères alternatifs du terminal.
align=gauche (ou noalign), align=centre, align=droite
Aligner le texte à gauche, au centre ou à droite de l'espace disponible si approprié.
fill=couleur
Remplir l'espace disponible avec une couleur d'arrière-plan si approprié.
list=on, list=focus, list=left-marker, list=right-marker, nolist
Marquer la position des différents composants de la liste des fenêtres dans l'option status-format : list=on marque le début de la liste ; list=focus est la partie de la liste qui doit rester en évidence si toute la liste ne rentre pas dans l'espace disponible (généralement la fenêtre actuelle) ; list=left-marker et list=right-marker marquent le texte utilisé pour indiquer que du texte a été coupé à gauche ou à droite de la liste s'il n'y a pas assez d'espace.
noattr
Ne pas copier les attributs du style par défaut.
push-default, pop-default
Stocker les couleurs et attributs actuels comme défauts ou revenir au défaut précédent. Un push-default affecte toute utilisation ultérieure de default jusqu'à un pop-default. Un seul défaut peut être empilé (chaque push-default remplace le défaut sauvegardé précédent).
range=gauche, range=droite, range=session|X, range=window|X, range=pane|X, range=user|X, norange
Marquer une plage pour les événements souris dans l'option status-format. Lorsqu'un événement souris se produit dans la plage range=gauche ou range=droite, les liaisons de touches ‘StatusLeft’ et ‘StatusRight’ sont déclenchées.

range=session|X, range=window|X et range=pane|X sont des plages pour une session, une fenêtre ou un pane. Celles-ci déclenchent la souris ‘Status’ avec la session, la fenêtre ou le pane cible donné par l'argument ‘X’. ‘X’ est un ID de session, un index de fenêtre dans la session actuelle ou un ID de pane. Pour ceux-ci, la variable de format mouse_status_range sera définie à ‘session’, ‘window’ ou ‘pane’.

range=user|X est une plage définie par l'utilisateur ; elle déclenche la souris ‘Status’. L'argument ‘X’ sera disponible dans la variable de format mouse_status_range. ‘X’ doit avoir au maximum 15 octets de long.

set-default
Définit les couleurs et attributs actuels comme défauts, écrasant tout défaut précédent. Le défaut précédent ne peut pas être restauré.

Les exemples sont :

fg=yellow bold underscore blink
bg=black,fg=default,noreverse

NOMS ET TITRES

tmux fait la distinction entre les noms et les titres. Les fenêtres et les sessions ont des noms, qui peuvent être utilisés pour les spécifier dans des cibles et sont affichés dans la ligne de statut et diverses listes : le nom est l'identifiant tmux pour une fenêtre ou une session. Seuls les panes ont des titres. Le titre d'un pane est généralement défini par le programme exécuté à l'intérieur du pane à l'aide d'une séquence d'échappement (comme il définirait le titre de la fenêtre xterm(1) dans X(7)). Les fenêtres elles-mêmes n'ont pas de titres - le titre d'une fenêtre est le titre de son pane actif. tmux peut lui-même définir le titre du terminal dans lequel le client est en cours d'exécution, voir l'option set-titles.

Le nom d'une session est défini avec les commandes new-session et rename-session. Le nom d'une fenêtre est défini avec l'une des méthodes suivantes :

  1. Un argument de commande (tel que -n pour new-window ou new-session).
  2. Une séquence d'échappement (si l'option allow-rename est activée) : 
    $ printf '\033kWINDOW_NAME\033\\'
  3. Renommage automatique, qui définit le nom sur la commande active dans le pane actif de la fenêtre. Voir l'option automatic-rename.

Lorsqu'un pane est créé pour la première fois, son titre est le nom d'hôte. Le titre d'un pane peut être défini via la séquence d'échappement de définition du titre, par exemple :

$ printf '\033]2;Mon Titre\033\\'

Il peut également être modifié avec la commande select-pane -T.

ENVIRONNEMENT GLOBAL ET DE SESSION

Lorsque le serveur est démarré, tmux copie l'environnement dans l'environnement global ; de plus, chaque session possède un environnement de session. Lorsqu'une fenêtre est créée, les environnements de session et global sont fusionnés. Si une variable existe dans les deux, la valeur de l'environnement de session est utilisée. Le résultat est l'environnement initial passé au nouveau processus.

L'option de session update-environment peut être utilisée pour mettre à jour l'environnement de session à partir du client lorsqu'une nouvelle session est créée ou qu'une ancienne est réattachée. tmux initialise également la variable TMUX avec des informations internes pour permettre l'exécution de commandes depuis l'intérieur, et la variable TERM avec le paramètre de terminal correct de ‘screen’.

Les variables des environnements de session et global peuvent être marquées comme cachées. Les variables cachées ne sont pas transmises dans l'environnement des nouveaux processus et ne peuvent être utilisées que par tmux lui-même (par exemple dans les formats, voir la section FORMATS).

Les commandes pour modifier et afficher l'environnement sont :

set-environment [-Fhgru] [-t session-cible] variable [valeur]
(alias : setenv)
Définit ou désactive une variable d'environnement. Si -g est utilisé, la modification est effectuée dans l'environnement global ; sinon, elle est appliquée à l'environnement de session pour session-cible. Si -F est présent, alors valeur est développée comme un format. Le drapeau -u désactive une variable. -r indique que la variable doit être retirée de l'environnement avant de démarrer un nouveau processus. -h marque la variable comme cachée.
show-environment [-hgs] [-t session-cible] [variable]
(alias : showenv)
Affiche l'environnement pour session-cible ou l'environnement global avec -g. Si variable est omis, toutes les variables sont affichées. Les variables retirées de l'environnement sont préfixées par ‘-’. Si -s est utilisé, la sortie est formatée comme un ensemble de commandes Bourne shell. -h affiche les variables cachées (omis par défaut).

LIGNE DE STATUT

tmux inclut une ligne de statut optionnelle qui est affichée sur la dernière ligne de chaque terminal.

Par défaut, la ligne de statut est activée et a une hauteur d'une ligne (elle peut être désactivée ou étendue sur plusieurs lignes avec l'option de session status) et contient, de gauche à droite : le nom de la session actuelle entre crochets ; la liste des fenêtres ; le titre du pane actif entre guillemets doubles ; et l'heure et la date.

Chaque ligne de la ligne de statut est configurée avec l'option status-format. Le défaut i s composé de trois parties : des sections gauche et droite configurables (qui peuvent contenir du contenu dynamique tel que l'heure ou la sortie d'une commande shell, voir les options status-left, status-left-length, status-right et status-right-length ci-dessous), et une liste centrale de fenêtres. Par défaut, la liste des fenêtres affiche l'index, le nom et (le cas échéant) le drapeau des fenêtres présentes dans la session actuelle dans un ordre numérique ascendant. Elle peut être personnalisée avec les options window-status-format et window-status-current-format. Le drapeau est l'un des symboles suivants ajoutés au nom de la fenêtre :

Symbole Signification
* Désigne la fenêtre actuelle.
- Marque la dernière fenêtre (précédemment sélectionnée).
# L'activité de la fenêtre est surveillée et une activité a été détectée.
! Les alarmes de la fenêtre sont surveillées et une alarme s'est produite dans la fenêtre.
~ La fenêtre est restée silencieuse pendant l'intervalle de silence de surveillance.
M La fenêtre contient le panneau marqué.
Z Le panneau actif de la fenêtre est zoomé.

Le symbole # est lié à l'option de fenêtre monitor-activity. Le nom de la fenêtre est affiché avec des couleurs inversées s'il y a une alerte (sonnerie, activité ou silence).

La couleur et les attributs de la ligne de statut peuvent être configurés, l'ensemble de la ligne de statut à l'aide de l'option de session status-style et les fenêtres individuelles à l'aide de l'option de fenêtre window-status-style.

La ligne de statut est automatiquement rafraîchie à intervalles réguliers si elle a changé, l'intervalle pouvant être contrôlé avec l'option de session status-interval.

BUFFERS

tmux maintient un ensemble de buffers de collage nommés. Chaque buffer peut être nommé explicitement ou automatiquement. Les buffers nommés explicitement sont nommés lors de leur création avec les commandes set-buffer ou load-buffer, ou en renommant un buffer nommé automatiquement avec set-buffer -n. Les buffers nommés automatiquement reçoivent un nom tel que « buffer0001 », « buffer0002 » et ainsi de suite. Lorsque la limite d'options buffer-limit est atteinte, le buffer nommé automatiquement le plus ancien est supprimé. Les buffers nommés explicitement ne sont pas soumis à buffer-limit et peuvent être supprimés avec la commande delete-buffer.

Les buffers peuvent être ajoutés en utilisant copy-mode ou les commandes set-buffer et load-buffer, et collés dans une fenêtre en utilisant la commande paste-buffer. Si une commande de buffer est utilisée et aucun buffer n'est spécifié, le buffer nommé automatiquement le plus récemment ajouté est supposé.

Un historique de buffer configurable est également maintenu pour chaque fenêtre. Par défaut, jusqu'à 2000 lignes sont conservées ; cela peut être modifié avec l'option history-limit (voir la commande set-option ci-dessus).

Les commandes de buffer sont les suivantes :

MESSAGES DE SORTIE

Lorsqu'un client tmux se détache, il affiche un message. Il peut s'agir de l'un des suivants :

detached and SIGHUP
Le client s'est détaché et son processus parent lui a envoyé le signal SIGHUP (par exemple avec detach-client -P).

Le tty(4) ou le pty(4) du client a été inopinément détruit.
terminated
Le client a été tué avec SIGTERM.
too far behind
Le client est en mode de contrôle et n'arrive plus à suivre les données de tmux.
exited
Le serveur s'est terminé car il n'avait plus de sessions.

Le serveur s'est terminé car il a reçu SIGTERM.

Le serveur a planté ou s'est terminé autrement sans indiquer la raison au client.

MODE DE CONTRÔLE

tmux propose une interface textuelle appelée mode de contrôle. Cela permet aux applications de communiquer avec tmux en utilisant un simple protocole textuel.

En mode de contrôle, un client envoie des commandes ou des séquences de commandes tmux terminées par des retours à la ligne sur l'entrée standard. Chaque commande produira un bloc de sortie sur la sortie standard. Un bloc de sortie se compose d'une ligne %begin suivie de la sortie (qui peut être vide). Le bloc de sortie se termine par un %end ou %error. %begin et le %end ou %error correspondant ont trois arguments : un entier temporel (en secondes depuis l'époque), un numéro de commande et des indicateurs (actuellement non utilisés). Par exemple :

%begin 1363006971 2 1
0: ksh* (1 panneaux) [80x24] [agencement b25f,80x24,0,0,2] @2 (actif)
%end 1363006971 2 1

La commande refresh-client -C peut être utilisée pour définir la taille d'un client en mode de contrôle.

En mode de contrôle, tmux émet des notifications. Une notification ne se produira jamais à l'intérieur d'un bloc de sortie.

Les notifications suivantes sont définies :

%client-detached client
Le client s'est détaché.
%client-session-changed client session-id nom
Le client est maintenant attaché à la session avec l'ID session-id, qui est nommée nom.
%config-error erreur
Une erreur s'est produite dans un fichier de configuration.
%continue pane-id
Le panneau a été continué après avoir été mis en pause (si l'indicateur pause-after est défini, voir refresh-client -A).
%exit [raison]
Le client tmux se ferme immédiatement, soit parce qu'il n'est attaché à aucune session, soit parce qu'une erreur s'est produite. Si présent, raison décrit pourquoi le client s'est fermé.
%extended-output pane-id age ... : valeur
Nouvelle forme de %output envoyée lorsque l'indicateur pause-after est défini. age est le temps en millisecondes pendant lequel tmux a mis en mémoire tampon la sortie avant qu'elle ne soit envoyée. Tous les arguments suivants jusqu'à un unique ‘:’ sont pour une utilisation future et doivent être ignorés.
%layout-change window-id window-layout window-visible-layout window-flags
La disposition d'une fenêtre avec l'ID window-id a changé. La nouvelle disposition est window-layout. La disposition visible de la fenêtre est window-visible-layout et les indicateurs de fenêtre sont window-flags.
%message message
Un message envoyé avec la commande display-message.
%output pane-id valeur
Un panneau de fenêtre a produit une sortie. valeur échappe les caractères non imprimables et les antislashs en octal \xxx.
%pane-mode-changed pane-id

%paste-buffer-changed nom
Le tampon de collage nom a été modifié.
%paste-buffer-deleted nom
Le tampon de collage nom a été supprimé.
%pause pane-id
Le panneau a été mis en pause (si l'indicateur pause-after est défini).
%session-changed session-id nom
Le client est maintenant attaché à la session avec l'ID session-id, qui est nommée nom.
%session-renamed nom

%session-window-changed session-id window-id

%sessions-changed

La valeur du format associé à l'abonnement nom a changé pour valeur. Voir refresh-client -B. Tous les arguments après pane-id jusqu'à un unique ‘:’ sont pour une utilisation future et doivent être ignorés.

COMMANDS

The tmux command-line utility is used to start the tmux server, create new sessions, attach to existing sessions, and run arbitrary tmux commands.

The command-line arguments are parsed as follows:

tmux [-2] [-A] [-c start-directory] [-D] [-E] [-S socket-path]
    [command-template | -f file] [args...]

or

tmux [-2] [-A] [-c start-directory] [-D] [-E] [-S socket-path]
    -L socket-name
    [command-template | -f file] [args...]

or

tmux [-2] [-A] [-c start-directory] [-D] [-E] [-S socket-path]
    -l log-file
    [command-template | -f file] [args...]

or

tmux [-2] [-A] [-c start-directory] [-D] [-E] [-S socket-path]
    -m
    [command-template | -f file] [args...]

or

tmux [-2] [-A] [-c start-directory] [-D] [-E] [-S socket-path]
    -q
    [command-template | -f file] [args...]

or

tmux [-2] [-A] [-c start-directory] [-D] [-E] [-S socket-path]
    -S socket-path
    [command-template | -f file] [args...]

If tmux is invoked without arguments, it checks for an existing server; if none is found, it starts a new server and creates a session. If a server is found, the client attaches to the server's default session.

Commands can be passed to an existing server by supplying command-template followed by args.... If command-template is omitted, the show-messages command is assumed.

The tmux command may be aliased to tmate in the shell configuration file.

-2
Force tmux to use the 256 colour terminfo(5) entry rather than the default.
-A
All clients associated with the server are detached if the server is restarted.
-c start-directory
Set the starting directory for new windows.
-D
All clients associated with the server are detached if the server is restarted.
-E
Sets the TERM environment variable from the terminal terminfo(5) database. This option is ignored if the server is already running.
-f file
Specifies the configuration file to use. See the tmux.conf(5) manual page for details.
-l log-file
Log all tmux output to log-file. This is intended for debugging.
-L socket-name
Specifies the name of the server socket. The default is default. See the TMUX_TMPDIR environment variable description.
-m
Forces tmux to run in multi-window mode. This is primarily useful for debugging tmux itself.
-q
Do not print anything to standard output.
-S socket-path
Specifies the path to the server socket. This overrides the TMUX_TMPDIR environment variable. This is useful for running multiple non-connected tmux servers. See the TMUX_TMPDIR environment variable description.

SESSION OPTIONS

The following options control the behaviour of sessions:

default-command
The command to run when a new window is created. If unset, the default shell is used. If this option is set to an empty string, the default shell is used.
default-shell
The default shell to run in new windows. If unset, the user's login shell from the password database is used.
destroy-unattached
If set, sessions that are not attached by any client are destroyed. This is useful for ensuring that only attached sessions remain.
lock-after-time
If set, sessions are automatically locked after this many seconds of inactivity. If unset, sessions are never locked automatically.
lock-command
The command used to lock the session. The default is ฿LOCK. The command is passed the session name as an argument.
lock-contents
If set, the contents of the screen are cleared when the session is locked.
new-session-path
The directory to change to when a new session is created. If unset, the user's home directory is used.
set-titles
If set, tmux will attempt to set the window and icon titles to the current pane title.
set-titles-string
A format string used to set the window and icon titles. See the FORMATS section for details.
silence-activity
If set, windows that have been inactive for this many seconds will be marked as silent. The default is 10 seconds. Set to 0 to disable.
silence-buffers
If set, windows that have had no buffer changes for this many seconds will be marked as silent. The default is 10 seconds. Set to 0 to disable.
silence-command
If set, windows that have had no command output for this many seconds will be marked as silent. The default is 10 seconds. Set to 0 to disable.
start-directory
The directory to change to when a new window is created. If unset, the current directory is used.
user-keys
If set, user-defined key bindings are enabled. This is the default.

EXAMPLES

To create a new tmux session running vi(1):

$ tmux new-session vi

Most commands have a shorter form, known as an alias. For new-session, this is new:

$ tmux new vi

Alternatively, the shortest unambiguous form of a command is accepted. If there are several options, they are listed:

$ tmux n
ambiguous command: n, could be: new-session, new-window, next-window

Within an active session, a new window may be created by typing ‘C-b c’ (Ctrl followed by the ‘b’ key followed by the ‘c’ key).

Windows may be navigated with: ‘C-b 0’ (to select window 0), ‘C-b 1’ (to select window 1), and so on; ‘C-b n’ to select the next window; and ‘C-b p’ to select the previous window.

A session may be detached using ‘C-b d’ (or by an external event such as ssh(1) disconnection) and reattached with:

$ tmux attach-session

Typing ‘C-b ?’ lists the current key bindings in the current window; up and down may be used to navigate the list or ‘q’ to exit from it.

Commands to be run when the tmux server is started may be placed in the ~/.tmux.conf configuration file. Common examples include:

Changing the default prefix key:

set-option -g prefix C-a
unbind-key C-b
bind-key C-a send-prefix

Turning the status line off, or changing its colour:

set-option -g status off
set-option -g status-style bg=blue

Setting other options, such as the default command, or locking after 30 minutes of inactivity:

set-option -g default-command "exec /bin/ksh"
set-option -g lock-after-time 1800

Creating new key bindings:

bind-key b set-option status
bind-key / command-prompt "split-window 'exec man %%'"
bind-key S command-prompt "new-window -n %1 'ssh %1'"

NOM

tmux - multiplexeur de terminal

SYNTAXE

tmux [-aCefquvXY] [-c start-directory] [-L socket-name] [-S socket-path] [command args...]
tmux [-aCqu] [-L socket-name] [-S socket-path] attach-session [-d] [-t session-name]
tmux [-a] [-c start-directory] [-e environment-variable] [-F format] [-L socket-name] [-S socket-path] [-t target-session] new-session [-A] [-d] [-n window-name] [-s session-name] [-x width] [-y height] [shell-command]

DESCRIPTION

tmux est un multiplexeur de terminal qui permet de gérer plusieurs sessions de terminal à partir d'une seule fenêtre de terminal. Il permet de créer, de diviser et de basculer entre différentes fenêtres et panneaux, de maintenir les sessions actives même si le client est déconnecté, et de partager des sessions entre plusieurs utilisateurs.

OPTIONS

  • -a : Attacher à toutes les sessions disponibles.
  • -C : Mode compatibilité avec les anciennes versions.
  • -c start-directory : Spécifie le répertoire de départ pour les nouvelles fenêtres.
  • -e environment-variable : Définit une variable d'environnement pour le serveur.
  • -f file : Spécifie un fichier de configuration.
  • -q : Mode silencieux, n'affiche pas les messages d'erreur.
  • -S socket-path : Spécifie le chemin du socket du serveur.
  • -u : Utilise le mode UTF-8.
  • -v : Mode verbeux, affiche plus d'informations.
  • -X : Désactive les extensions du protocole client.
  • -Y : Active les extensions du protocole client.

COMMANDES

tmux peut exécuter une variété de commandes pour gérer les sessions, les fenêtres et les panneaux. Les commandes peuvent être préfixées par un préfixe (généralement Ctrl-b) suivi de :.

SESSION

  • new-session : Crée une nouvelle session.
  • attach-session : Attache à une session existante.
  • list-sessions : Liste toutes les sessions disponibles.
  • kill-session : Tue une session.

FENÊTRE

  • new-window : Crée une nouvelle fenêtre.
  • list-windows : Liste toutes les fenêtres d'une session.
  • kill-window : Tue une fenêtre.
  • select-window : Sélectionne une fenêtre.

PANNEAU

  • split-window : Divise un panneau en deux.
  • list-panes : Liste tous les panneaux d'une fenêtre.
  • kill-pane : Tue un panneau.
  • select-pane : Sélectionne un panneau.

CLIENT

  • list-clients : Liste tous les clients connectés.
  • kill-client : Tue un client.

SERVEUR

  • kill-server : Tue le serveur tmux.

RACCCOURCIS CLAVIER

Les raccourcis clavier par défaut utilisent Ctrl-b comme préfixe.

  • Ctrl-b c : Crée une nouvelle fenêtre.
  • Ctrl-b w : Liste les fenêtres.
  • Ctrl-b " : Divise le panneau horizontalement.
  • Ctrl-b % : Divise le panneau verticalement.
  • Ctrl-b <direction> : Se déplace vers un panneau dans la direction spécifiée (h, j, k, l).
  • Ctrl-b x : Tue le panneau actuel.
  • Ctrl-b d : Détache la session.

CONFIGURATION

Le fichier de configuration de tmux est généralement situé à ~/.tmux.conf. Il permet de personnaliser les raccourcis clavier, les options et le comportement de tmux.

LIGNE DE STATUT

La ligne de statut affiche des informations sur la session, les fenêtres et les panneaux. Elle peut être personnalisée dans le fichier de configuration.

BUFFERS

tmux dispose de tampons pour copier et coller du texte entre les panneaux. Les tampons sont accessibles via les commandes show-buffer et paste-buffer.

DIVERS

tmux prend en charge les sessions persistantes, ce qui signifie que les sessions restent actives même si le client est déconnecté. Il prend également en charge le partage de sessions entre plusieurs utilisateurs.

MESSAGES DE SORTIE

tmux affiche des messages pour informer l'utilisateur des événements importants, tels que la création ou la destruction de sessions, de fenêtres ou de panneaux.

EXTENSIONS TERMINFO

tmux utilise les informations du terminal pour afficher correctement le contenu des fenêtres et des panneaux. Il prend en charge certaines extensions TERMINFO pour améliorer la compatibilité.

MODE CONTRÔLE

Le mode contrôle est un mode spécial qui permet à une application d'interagir directement avec tmux pour manipuler les fenêtres et les panneaux.

ENVIRONNEMENT

tmux utilise certaines variables d'environnement pour configurer son comportement, telles que $TMUX et $TMUX_PANE.

FICHIERS

  • ~/.tmux.conf : Fichier de configuration utilisateur.
  • /etc/tmux.conf : Fichier de configuration système.

EXEMPLES

tmux new-session -s my_session : Crée une nouvelle session nommée "my_session".
tmux attach-session -t my_session : Attache à la session "my_session".
tmux split-window -h : Divise le panneau actuel horizontalement.
