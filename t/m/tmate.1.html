NOM

tmate — multiplexeur de terminaux

SYNOPIS

tmate [-2CluvV] [-c commande-shell] [-f fichier] [-L nom-socket] [-S chemin-socket] [commande [flags]]

DESCRIPTION

tmate est un multiplexeur de terminaux : il permet de créer, accéder et contrôler un certain nombre de terminaux à partir d'un seul écran. tmate peut être détaché d'un écran et continuer à s'exécuter en arrière-plan, puis être ré-attaché plus tard.

Lorsque tmate est lancé, il crée une nouvelle session avec une seule fenêtre et l'affiche à l'écran. Une ligne de statut en bas de l'écran affiche des informations sur la session courante et est utilisée pour entrer des commandes interactives.

Une session est une collection unique de pseudo-terminaux gérée par tmate. Chaque session a une ou plusieurs fenêtres qui y sont liées. Une fenêtre occupe tout l'écran et peut être divisée en panneaux rectangulaires, chacun étant un pseudo-terminal distinct (la page de manuel pty(4) documente les détails techniques des pseudo-terminaux). N'importe quel nombre d'instances de tmate peuvent se connecter à la même session, et n'importe quel nombre de fenêtres peuvent être présentes dans la même session. Une fois toutes les sessions tuées, tmate se termine.

Chaque session est persistante et survivra aux déconnexions accidentelles (telles que les timeouts de connexion ssh(1)) ou aux détachements intentionnels (avec les frappes ‘C-b d’). tmate peut être ré-attaché en utilisant :

$ tmate attach

Dans tmate, une session est affichée à l'écran par un client et toutes les sessions sont gérées par un unique serveur. Le serveur et chaque client sont des processus distincts qui communiquent via un socket dans /tmp.

Les options sont les suivantes :

-2
Force tmate à supposer que le terminal supporte 256 couleurs.
-C
Démarre en mode contrôle (voir la section MODE CONTRÔLE). Donné deux fois (-CC) désactive l'écho.
-c commande-shell
Exécute commande-shell en utilisant le shell par défaut. Si nécessaire, le serveur tmate sera démarré pour récupérer l'option default-shell. Cette option est pour la compatibilité avec sh(1) lorsque tmate est utilisé comme shell de connexion.
-f fichier
Spécifie un fichier de configuration alternatif. Par défaut, tmate charge le fichier de configuration système depuis /etc/tmux.conf, s'il est présent, puis recherche un fichier de configuration utilisateur à ~/.tmux.conf et ~/.tmate.conf.

Le fichier de configuration est un ensemble de commandes tmate qui sont exécutées séquentiellement lorsque le serveur est démarré pour la première fois. tmate charge les fichiers de configuration une fois lorsque le processus serveur est démarré. La commande source-file peut être utilisée pour charger un fichier plus tard.

tmate affiche tous les messages d'erreur des commandes dans les fichiers de configuration dans la première session créée, et continue à traiter le reste du fichier de configuration.

-L nom-socket
tmate stocke le socket serveur dans un répertoire sous TMUX_TMPDIR ou /tmp s'il est non défini. Le socket par défaut est nommé default. Cette option permet de spécifier un nom de socket différent, permettant à plusieurs serveurs tmate indépendants de fonctionner. Contrairement à -S, un chemin complet n'est pas nécessaire : les sockets sont tous créés dans le même répertoire.

Si le socket est accidentellement supprimé, le signal SIGUSR1 peut être envoyé au processus serveur tmate pour le recréer (notez que cela échouera si des répertoires parents manquent).

-l
Se comporter comme un shell de connexion. Ce drapeau n'a actuellement aucun effet et est destiné à la compatibilité avec d'autres shells lors de l'utilisation de tmate comme shell de connexion.
-S chemin-socket
Spécifie un chemin alternatif complet vers le socket serveur. Si -S est spécifié, le répertoire de socket par défaut n'est pas utilisé et tout drapeau -L est ignoré.
-u
tmate essaie de deviner si le terminal supporte probablement l'UTF-8 en vérifiant la première des variables d'environnement LC_ALL, LC_CTYPE et LANG définie avec la chaîne "UTF-8". Ce n'est pas toujours correct : le drapeau -u informe explicitement tmate que l'UTF-8 est supporté.

Notez que tmate lui-même accepte toujours l'UTF-8 ; cela contrôle s'il enverra des caractères UTF-8 au terminal qu'il exécute (sinon, ils sont remplacés par ‘_’).

-v
Demande une journalisation détaillée. Cette option peut être spécifiée plusieurs fois pour augmenter la verbosité. Les messages de journal seront enregistrés dans les fichiers tmux-client-PID.log et tmux-server-PID.log dans le répertoire courant, où PID est le PID du processus serveur ou client.
-V
Rapporte la version de tmate.
commande [flags]
Ceci spécifie une des commandes utilisées pour contrôler tmate, comme décrit dans les sections suivantes. Si aucune commande n'est spécifiée, la commande new-session est supposée.

COMMANDES

Cette section contient une liste des commandes prises en charge par tmate. La plupart des commandes acceptent l'argument optionnel -t (et parfois -s) avec l'un des arguments client-cible, session-cible fenêtre-cible, ou panneau-cible. Ceux-ci spécifient le client, la session, la fenêtre ou le panneau sur lesquels une commande doit agir.

client-cible est le nom du fichier pty(4) auquel le client est connecté, par exemple /dev/ttyp1 ou ttyp1 pour le client connecté à /dev/ttyp1. Si aucun client n'est spécifié, tmate tente de déterminer le client actuellement utilisé ; si cela échoue, une erreur est signalée. Les clients peuvent être listés avec la commande list-clients.

session-cible est recherchée dans l'ordre suivant :

  1. Un ID de session préfixé par un $.
  2. Un nom exact de session (tel que listé par la commande list-sessions).
  3. Le début d'un nom de session, par exemple « monsession » correspondrait à une session nommée « monsession ».
  4. Un motif fnmatch(3) qui est mis en correspondance avec le nom de la session.

Si le nom de la session est préfixé par un « = », seule une correspondance exacte est acceptée (ainsi « =monsess » ne correspondra qu'exactement à « monsess », pas à « monsession »).

Si une seule session est trouvée, elle est utilisée comme session cible ; plusieurs correspondances génèrent une erreur. Si une session est omise, la session actuelle est utilisée si elle est disponible ; si aucune session actuelle n'est disponible, la plus récemment utilisée est choisie.

fenêtre-cible (ou fenêtre-source ou fenêtre-destination) spécifie une fenêtre sous la forme session:fenêtre. session suit les mêmes règles que pour session-cible, et fenêtre est recherchée dans l'ordre comme suit :

  1. Un jeton spécial, listé ci-dessous.
  2. Un index de fenêtre, par exemple « monsession:1 » est la fenêtre 1 de la session « monsession ».
  3. Un ID de fenêtre, tel que @1.
  4. Un nom de fenêtre exact, tel que « monsession:mafenetre ».
  5. Le début d'un nom de fenêtre, tel que « monsession:mafen ».
  6. Comme un motif fnmatch(3) mis en correspondance avec le nom de la fenêtre.

Comme pour les sessions, un préfixe « = » effectuera une correspondance exacte uniquement. Un nom de fenêtre vide spécifie l'index inutilisé suivant si approprié (par exemple pour les commandes new-window et link-window), sinon la fenêtre actuelle dans session est choisie.

Les jetons spéciaux suivants sont disponibles pour indiquer des fenêtres particulières. Chacun a une forme alternative d'un seul caractère.

{start} ^ La fenêtre avec le plus petit numéro

{last} ! La dernière fenêtre (précédemment courante)
{next} + La fenêtre suivante par numéro
{previous} - La fenêtre précédente par numéro

panneau-cible (ou panneau-source ou panneau-destination) peut être un ID de panneau ou prend une forme similaire à fenêtre-cible mais avec l'ajout optionnel d'un point suivi d'un index de panneau ou d'un ID de panneau, par exemple : « monsession:mafenetre.1 ». Si l'index du panneau est omis, le panneau actif dans la fenêtre spécifiée est utilisé. Les jetons spéciaux suivants sont disponibles pour l'index du panneau :

En outre, session-cible, fenêtre-cible ou panneau-cible

">volet-cible peut être constitué uniquement du jeton ‘{souris}’ (forme alternative ‘=’) pour spécifier l'événement de souris le plus récent (voir la section SUPPORT DE LA SOURIS) ou ‘{marqué}’ (forme alternative ‘~’) pour spécifier le volet marqué (voir select-pane -m).

Les sessions, fenêtres et volets sont chacun numérotés avec un ID unique ; les ID de session sont précédés d'un ‘$’, les fenêtres d'un ‘@’, et les volets d'un ‘%’. Ils sont uniques et restent inchangés pendant toute la durée de vie de la session, de la fenêtre ou du volet sur le serveur tmate. L'ID du volet est passé au processus enfant du volet dans la variable d'environnement TMUX_PANE. Les ID peuvent être affichés à l'aide des formats ‘session_id’, ‘window_id’, ou ‘pane_id’ (voir la section FORMATS) et des commandes display-message, list-sessions, list-windows ou list-panes.

commandes-shell sont des commandes sh(1). Il peut s'agir d'un argument unique passé au shell, par exemple :

new-window 'vi /etc/passwd'

Exécutera :

/bin/sh -c 'vi /etc/passwd'

De plus, les commandes new-window, new-session, split-window, respawn-window et respawn-pane permettent de passer commandes-shell comme plusieurs arguments et de les exécuter directement (sans ‘sh -c’). Cela peut éviter les problèmes de citation du shell. Par exemple :

$ tmate new-window vi /etc/passwd

Exécutera vi(1) directement sans invoquer le shell.

commande [arguments] fait référence à une commande tmate, passée avec la commande et les arguments séparément, par exemple :

bind-key F1 set-window-option force-width 81

Ou si vous utilisez sh(1) :

$ tmate bind-key F1 set-window-option force-width 81

Plusieurs commandes peuvent être spécifiées ensemble dans le cadre d'une séquence de commandes. Chaque commande doit être séparée par des espaces et un point-virgule ; les commandes sont exécutées séquentiellement de gauche à droite et les lignes se terminant par une barre oblique inverse continuent sur la ligne suivante, sauf si elles sont échappées par une autre barre oblique inverse. Un point-virgule littéral peut être inclus en l'échappant avec une barre oblique inverse (par exemple, lors de la spécification d'une séquence de commandes pour bind-key).

Exemples de commandes tmate :

refresh-client -t/dev/ttyp2

rename-session -tfirst newname

set-window-option -t:0 monitor-activity on

new-window ; split-window -d

bind-key R source-file ~/.tmux.conf \; \
	display-message "source-file done"

Ou depuis sh(1) :

$ tmate kill-window -t :1

$ tmate new-window \; split-window -d

$ tmate new-session -d 'vi /etc/passwd' \; split-window -d \; attach

CLIENTS ET SESSIONS

Le serveur tmate gère les clients, les sessions, les fenêtres et les volets. Les clients sont attachés aux sessions pour interagir avec elles, soit lors de leur création avec la commande new-session, soit plus tard avec la commande attach-session. Chaque session a une ou plusieurs fenêtres liées. Les fenêtres peuvent être liées à plusieurs sessions et sont composées d'un ou plusieurs volets, chacun contenant un pseudo-terminal. Les commandes de création, de liaison et de manipulation des fenêtres sont décrites dans la section FENÊTRES ET VOLETS.

Les commandes suivantes sont disponibles pour gérer les clients et les sessions :

attach-session [-dEr] [-c répertoire-de-travail] [-t session-cible]
(alias : attach
) Si exécutée depuis l'extérieur de tmate, crée un nouveau client dans le terminal actuel et l'attache à session-cible. Si utilisée de l'intérieur, change le client actuel. Si -d est spécifié, tout autre client attaché à la session est détaché. -r indique que le client est en lecture seule (seules les touches liées aux commandes detach-client ou switch-client ont un effet)

Si aucun serveur n'est démarré, attach-session tentera de le démarrer ; cela échouera à moins que des sessions ne soient créées dans le fichier de configuration.

Les règles de session-cible pour attach-session sont légèrement ajustées : si tmate doit sélectionner la session utilisée le plus récemment, il préférera la session non attachée utilisée le plus récemment.

-c définira le répertoire de travail de la session (utilisé pour les nouvelles fenêtres) à répertoire-de-travail.

Si -E est utilisé, l'option update-environment ne sera pas appliquée.

detach-client [-aP] [-s session-cible] [-t client-cible]
(alias : detach
) Détache le client actuel s'il est lié à une touche, le client spécifié avec -t, ou tous les clients actuellement attachés à la session spécifiée par -s. L'option -a tue tous les clients sauf celui donné avec -t. Si -P est donné, envoie SIGHUP au processus parent du client, le faisant généralement se terminer.
has-session [-t session-cible]
(alias : has
) Signale une erreur et sort avec 1 si la session spécifiée n'existe pas. Si elle existe, sort avec 0.
kill-server
Tue le serveur tmate et les clients, et détruit toutes les sessions.
kill-session [-aC] [-t session-cible]
Détruit la session donnée, fermant toutes les fenêtres qui y sont liées et aucune autre session, et détachant tous les clients qui y sont attachés. Si -a est donné, toutes les sessions sauf celle spécifiée sont tuées. Le drapeau -C efface les alertes (sonnerie, activité ou silence) dans toutes les fenêtres liées à la session.
list-clients [-F format] [-t session-cible]
(alias : lsc
) Liste tous les clients attachés au serveur. Pour la signification de l'indicateur -F, voir la section FORMATS. Si session-cible est spécifié, liste uniquement les clients connectés à cette session.
list-commands
(alias : lscm
) Liste la syntaxe de toutes les commandes prises en charge par tmate.
list-sessions [-F format]
(alias : ls
) Liste toutes les sessions gérées par le serveur. Pour la signification de l'indicateur -F, voir la section FORMATS.
lock-client [-t client-cible]
(alias : lockc
) Verrouille client-cible, voir la commande lock-server.
lock-session [-t session-cible]
(alias : locks
) Verrouille tous les clients attachés à session-cible.
new-session [-AdDEP] [-c répertoire-de-démarrage] [-F format] [-n nom-fenêtre] [-s nom-session] [-t session-cible] [-x largeur] [-y hauteur] [commande-shell]
(alias : new
) Crée une nouvelle session nommée nom-session.

La nouvelle session est attachée au terminal actuel sauf si -d est donné. nom-fenêtre et nom-session peuvent contenir des espaces si la commande est entre guillemets.

(alias : neww

RACCOURCIS CLAVIER

tmate permet de lier une commande à la plupart des touches, avec ou sans touche préfixe. Lors de la spécification des touches, la plupart se représentent elles-mêmes (par exemple, ‘A’ à ‘Z’). Les touches Ctrl peuvent être préfixées par ‘C-’ ou ‘^’, et Alt (méta) par ‘M-’. De plus, les noms de touches spéciaux suivants sont acceptés : Up, Down, Left, Right, BSpace, BTab, DC (Suppr), End, Enter, Escape, F1 à F12, Home, IC (Inser), NPage/PageDown/PgDn, PPage/PageUp/PgUp, Space, et Tab. Notez que pour lier les touches ‘"’ ou ‘'’, des guillemets sont nécessaires, par exemple :

bind-key '"' split-window
bind-key "'" new-window

Les commandes relatives aux raccourcis clavier sont les suivantes :

bind-key [-cnr] [-t table-mode] [-T table-clavier] touche commande [arguments]
(alias: bind
) Lie la touche touche à la commande. Les touches sont liées dans une table de touches. Par défaut (sans -T), la touche est liée dans la table de touches prefix. Cette table est utilisée pour les touches pressées après la touche préfixe (par exemple, par défaut ‘c’ est lié à new-window dans la table prefix, donc ‘C-b c’ crée une nouvelle fenêtre). La table root est utilisée pour les touches pressées sans la touche préfixe : lier ‘c’ à new-window dans la table root (non recommandé) signifie qu'un simple ‘c’ créera une nouvelle fenêtre. -n est un alias pour -T root. Les touches peuvent également être liées dans des tables de touches personnalisées et la commande switch-client -T utilisée pour passer à ces tables depuis une liaison de touche. L'indicateur -r indique que cette touche peut se répéter, voir l'option repeat-time.

Si -t est présent, key est lié dans mode-table : la liaison pour le mode commande avec -c ou pour le mode normal sans. Voir la section FENÊTRES ET VOLETS et la commande list-keys pour des informations sur les liaisons de touches en mode.

Pour visualiser les liaisons par défaut et les commandes possibles, voir la commande list-keys.

list-keys [-t mode-table] [-T key-table]
(alias : lsk
) Liste toutes les liaisons de touches. Sans -T, toutes les tables de touches sont affichées. Avec -T, seule key-table.

Avec -t, les liaisons de touches dans mode-table sont listées ; il peut s'agir de : vi-edit, emacs-edit, vi-choice, emacs-choice, vi-copy ou emacs-copy.

send-keys [-lMR] [-t target-pane] key ...
(alias : send
) Envoie une ou plusieurs touches à une fenêtre. Chaque argument key est le nom de la touche (tel que ‘C-a’ ou ‘npage’) à envoyer ; si la chaîne n'est pas reconnue comme une touche, elle est envoyée comme une série de caractères. Le flag -l désactive la recherche du nom de la touche et envoie les touches littéralement. Tous les arguments sont envoyés séquentiellement du premier au dernier. Le flag -R réinitialise l'état du terminal.

-M transmet un événement de souris (uniquement valide si lié à une liaison de touche de souris, voir SUPPORT DES SOURIS).

send-prefix [-2] [-t target-pane]
Envoie la touche préfixe, ou avec -2 la touche préfixe secondaire, à une fenêtre comme si elle avait été pressée.
unbind-key [-acn] [-t mode-table] [-T key-table] key
(alias : unbind
) Annule la liaison de la commande liée à key. -c, -n, -T et -t sont les mêmes que pour bind-key. Si -a est présent, toutes les liaisons de touches sont supprimées.

OPTIONS

L'apparence et le comportement de tmate peuvent être modifiés en changeant la valeur de diverses options. Il existe trois types d'options : options serveur, options de session et options de fenêtre.

Le serveur tmate possède un ensemble d'options globales qui ne s'appliquent à aucune fenêtre ou session particulière. Celles-ci sont modifiées avec la commande set-option -s, ou affichées avec la commande show-options -s.

De plus, chaque session individuelle peut avoir un ensemble d'options de session, et il existe un ensemble distinct d'options de session globales. Les sessions qui n'ont pas d'option particulière configurée héritent de la valeur des options de session globales. Les options de session sont définies ou annulées avec la commande set-option et peuvent être listées avec la commande show-options. Les options serveur et session disponibles sont listées sous la commande set-option.

De même, un ensemble d'options de fenêtre est attaché à chaque fenêtre, et il existe un ensemble d'options de fenêtre globales à partir desquelles les options non définies sont héritées. Les options de fenêtre sont modifiées avec la commande set-window-option et peuvent être listées avec la commande show-window-options. Toutes les options de fenêtre sont documentées avec la commande set-window-option.

tmate prend également en charge les options utilisateur qui sont préfixées par un ‘@’. Les options utilisateur peuvent avoir n'importe quel nom, tant qu'elles sont préfixées par ‘@’, et être définies sur n'importe quelle chaîne. Par exemple :

$ tmate setw -q @foo "abc123"
$ tmate showw -v @foo
abc123

Les commandes qui définissent les options sont les suivantes :

set-option [-agoqsuw] [-t target-session | target-window] option value
(alias : set
) Définit une option de fenêtre avec -w (équivalent à la commande set-window-option), une option serveur avec -s, sinon une option de session. Si -g est donné, l'option globale de session ou de fenêtre est définie. Le flag -u annule une option, de sorte qu'une session hérite de l'option des options globales (ou avec -g, restaure une option globale à sa valeur par défaut).

Le flag -o empêche la définition d'une option déjà définie et le flag -q supprime les erreurs concernant des options inconnues ou ambiguës.

Avec -a, et si l'option attend une chaîne ou un style, value est ajouté au réglage existant. Par exemple :

set -g status-left "foo"
set -ag status-left "bar"

Résultera en ‘foobar’. Et :

set -g status-style "bg=red"
set -ag status-style "fg=blue"

Résultera en un arrière-plan rouge et un premier plan bleu. Sans -a, le résultat serait l'arrière-plan par défaut et un premier plan bleu.

Les options de fenêtre disponibles sont listées sous set-window-option.

value dépend de l'option et peut être un nombre, une chaîne ou un drapeau (activé, désactivé ou omis pour basculer).

Les options serveur disponibles sont :

buffer-limit number
Définit le nombre de tampons ; au fur et à mesure que de nouveaux tampons sont ajoutés en haut de la pile, les anciens sont retirés du bas si nécessaire pour maintenir cette longueur maximale.
default-terminal terminal
Définit le terminal par défaut pour les nouvelles fenêtres créées dans cette session - la valeur par défaut de la variable d'environnement TERM. Pour que tmate fonctionne correctement, cela doit être défini sur ‘screen’, ‘tmux’, ‘tmate’ ou une de leurs dérivées.
escape-time time
Définit le temps en millisecondes pendant lequel tmate attend après qu'une évasion soit entrée pour déterminer si elle fait partie d'une séquence de touches de fonction ou méta. La valeur par défaut est de 500 millisecondes.
exit-unattached [on | off]
Si activé, le serveur se terminera lorsqu'il n'y aura plus de clients connectés.
focus-events [on | off]
Lorsqu'il est activé, les événements de focus sont demandés au terminal si pris en charge et transmis aux applications exécutées dans tmate. Les clients connectés doivent être détachés et rattachés après avoir changé cette option.
history-file path
S'il n'est pas vide, un fichier dans lequel tmate écrira l'historique de la ligne de commande à la sortie et le chargera au démarrage.
message-limit number
Définit le nombre de messages d'erreur ou d'information à sauvegarder dans le journal des messages pour chaque client. La valeur par défaut est 100.
set-clipboard [on | off]
Tente de définir le contenu du presse-papiers du terminal en utilisant les séquences d'échappement \e]52;...\007 de xterm(1). Cette option est activée par défaut s'il existe une entrée Ms dans la description terminfo(5) pour le terminal client. Notez que cette fonctionnalité doit être activée dans xterm(1) en définissant la ressource : 
disallowedWindowOps: 20,21,SetXprop

Ou en changeant cette propriété à partir du menu interactif de xterm(1) lorsque nécessaire.

terminal-overrides string
Contient une liste d'entrées qui remplacent les descriptions de terminal lues à l'aide de ="/man/terminfo.5.fr">terminfo(5). string est une liste d'éléments séparés par des virgules, chacun étant une chaîne composée d'un modèle de type de terminal (comparé à l'aide de fnmatch(3)) et d'un ensemble d'entrées nom=valeur.

Par exemple, pour définir l'entrée ‘clear’ de terminfo(5) à ‘\e[H\e[2J’ pour tous les types de terminaux et l'entrée ‘dch1’ à ‘\e[P’ pour le type de terminal ‘rxvt’, l'option pourrait être définie à la chaîne :

"*:clear=\e[H\e[2J,rxvt:dch1=\e[P"

La valeur de l'entrée du terminal est passée par strunvis(3) avant interprétation. La valeur par défaut corrige de force l'entrée ‘colors’ pour les terminaux qui supportent 256 couleurs :

"*256col*:colors=256,xterm*:XT"

Les options de session disponibles sont :

assume-paste-time millisecondes
Si les touches sont entrées plus rapidement qu'une toutes les millisecondes, elles sont supposées avoir été collées plutôt que tapées et les raccourcis clavier de tmate ne sont pas traités. La valeur par défaut est une milliseconde et zéro désactive cette fonction.
base-index index
Définit l'index de base à partir duquel un index inutilisé sera recherché lors de la création d'une nouvelle fenêtre. La valeur par défaut est zéro.
bell-action [any | none | current | other]
Définit l'action lors d'une sonnerie de fenêtre. any signifie qu'une sonnerie dans n'importe quelle fenêtre liée à une session provoque une sonnerie dans la fenêtre actuelle de cette session, none signifie que toutes les sonneries sont ignorées, current signifie que seules les sonneries dans les fenêtres autres que la fenêtre actuelle sont ignorées et other signifie que les sonneries dans la fenêtre actuelle sont ignorées mais pas celles dans les autres fenêtres.
bell-on-alert [on | off]
Si activé, fait sonner la cloche du terminal lorsqu'une alerte se produit.
default-command commande-shell
Définit la commande utilisée pour les nouvelles fenêtres (si non spécifiée lors de la création de la fenêtre) à commande-shell, qui peut être n'importe quelle commande sh(1). La valeur par défaut est une chaîne vide, ce qui demande à tmate de créer un shell de connexion en utilisant la valeur de l'option default-shell.
default-shell chemin
Spécifie le shell par défaut. Il est utilisé comme shell de connexion pour les nouvelles fenêtres lorsque l'option default-command est définie sur vide, et doit être le chemin complet de l'exécutable. Au démarrage, tmate essaie de définir une valeur par défaut à partir de la première valeur appropriée de la variable d'environnement SHELL, du shell renvoyé par getpwuid(3), ou de /bin/sh. Cette option doit être configurée lorsque tmate est utilisé comme shell de connexion.
destroy-unattached [on | off]
Si activé et que la session n'est plus attachée à aucun client, elle est détruite.
detach-on-destroy [on | off]
Si activé (par défaut), le client est détaché lorsque la session à laquelle il est attaché est détruite. Si désactivé, le client est basculé vers la session la plus récemment active parmi les sessions restantes.
display-panes-active-colour couleur
Définit la couleur utilisée par la commande display-panes pour afficher l'indicateur de la fenêtre active.
display-panes-colour couleur
Définit la couleur utilisée par la commande display-panes pour afficher les indicateurs des fenêtres inactives.
display-panes-time temps
Définit le temps en millisecondes pendant lequel les indicateurs affichés par la commande display-panes apparaissent.
display-time temps
Définit la durée pendant laquelle les messages de la ligne de statut et autres indicateurs à l'écran sont affichés. Si défini à 0, les messages et indicateurs sont affichés jusqu'à ce qu'une touche soit pressée. temps est en millisecondes.
history-limit lignes
Définit le nombre maximum de lignes conservées dans l'historique des fenêtres. Ce réglage s'applique uniquement aux nouvelles fenêtres ; les historiques des fenêtres existantes ne sont pas redimensionnés et conservent la limite au moment de leur création.
key-table table-clavier
Définit la table de touches par défaut à table-clavier au lieu de root.
lock-after-time nombre
Verrouille la session (comme la commande lock-session) après nombre secondes d'inactivité. La valeur par défaut est de ne pas verrouiller (défini à 0).
lock-command commande-shell
Commande à exécuter lors du verrouillage de chaque client. Par défaut, exécute lock(1) avec -np.
message-command-style style
Définit le style des commandes de message de la ligne de statut, où style est une liste séparée par des virgules de caractéristiques à spécifier.

Il peut s'agir de ‘bg=couleur’ pour définir la couleur d'arrière-plan, ‘fg=couleur’ pour définir la couleur de premier plan, et d'une liste d'attributs comme spécifié ci-dessous.

La couleur est l'une des suivantes : black, red, green, yellow, blue, magenta, cyan, white, variantes vives aixterm (si supportées : brightred, brightgreen, etc.), colour0 à colour255 de l'ensemble 256 couleurs, default, ou une chaîne RVB hexadécimale telle que ‘#ffffff’, qui choisit la correspondance la plus proche de l'ensemble par défaut 256 couleurs.

Les attributs sont soit none soit une liste délimitée par des virgules d'un ou plusieurs des éléments suivants : bright (ou bold), dim, underscore, blink, reverse, hidden, ou italics, pour activer un attribut, ou un attribut préfixé par ‘no’ pour le désactiver.

Exemples :

fg=yellow,bold,underscore,blink
bg=black,fg=default,noreverse

Avec le drapeau -a de la commande set-option, le nouveau style est ajouté ; sinon, le style existant est remplacé.

message-style style
Définit le style des messages de la ligne de statut. Pour savoir comment spécifier style, voir l'option message-command-style.
mouse [on | off]
Si activé, tmate capture la souris et permet de lier des événements de souris en tant que raccourcis clavier. Voir la section SUPPORT DE LA SOURIS pour les détails.
prefix touche

SUPPORT DE LA SOURIS

Si l'option mouse est activée (la valeur par défaut est désactivée), tmate permet de lier des événements de souris comme des touches. Le nom de chaque touche est composé d'un événement de souris (tel que ‘MouseDown1’) et d'un suffixe de localisation (l'un parmi ‘Pane’ pour le contenu d'un panneau, ‘Border’ pour une bordure de panneau, ou ‘Status’ pour la barre d'état). Les événements de souris suivants sont disponibles :

MouseDown1 MouseUp1 MouseDrag1 MouseDragEnd1
MouseDown2 MouseUp2 MouseDrag2 MouseDragEnd2
MouseDown3 MouseUp3 MouseDrag3 MouseDragEnd3
WheelUp WheelDown

Chacun doit être suffixé par une localisation, par exemple ‘MouseDown1Status’.

Le jeton spécial ‘{mouse}’ ou ‘=’ peut être utilisé comme fenêtre-cible ou panneau-cible dans les commandes liées aux touches de souris. Il se résout en la fenêtre ou le panneau sur lequel l'événement de souris s'est produit (par exemple, la fenêtre dans la barre d'état sur laquelle le bouton 1 a été relâché pour une liaison ‘MouseUp1Status’, ou le panneau sur lequel la molette a défilé pour une liaison ‘WheelDownPane’).

Le drapeau -M de la commande send-keys peut être utilisé pour transmettre un événement de souris à un panneau.

Les liaisons de touches par défaut permettent d'utiliser la souris pour sélectionner et redimensionner les panneaux, copier du texte et changer de fenêtre à l'aide de la barre d'état. Celles-ci prennent effet si l'option mouse est activée.

FORMATS

Certaines commandes acceptent le drapeau -F avec un argument format. Il s'agit d'une chaîne qui contrôle le format de sortie de la commande. Les variables de remplacement sont entourées de ‘{’ et ‘}’, par exemple ‘#{session_name}’. Les variables possibles sont listées dans le tableau ci-dessous, ou le nom d'une option tmate peut être utilisé pour la valeur d'une option. Certaines variables ont un alias plus court tel que ‘#S’, et ‘##’ est remplacé par un seul ‘#’.

Les conditionnels sont disponibles en préfixant par ‘?’ et en séparant deux alternatives par une virgule ; si la variable spécifiée existe et n'est pas nulle, la première alternative est choisie, sinon la seconde est utilisée. Par exemple ‘#{?session_attached,attached,not attached}’ inclura la chaîne ‘attached’ si la session est attachée et la chaîne ‘not attached’ si elle est non attachée, ou ‘#{?automatic-rename,yes,no}’ inclura ‘yes’ si automatic-rename est activé, ou ‘no’ si ce n'est pas le cas.

Une limite peut être imposée à la longueur de la chaîne résultante en la préfixant par un ‘=’, un nombre et un deux-points. Les nombres positifs comptent à partir du début de la chaîne et les nombres négatifs à partir de la fin, ainsi ‘#{=5:pane_title}’ inclura au maximum les 5 premiers caractères du titre du panneau, ou ‘#{=-5:pane_title}’ les 5 derniers caractères. En préfixant une variable temporelle par ‘t:’ elle sera convertie en chaîne, ainsi si ‘#{window_activity}’ donne ‘1445765102’, ‘#{t:window_activity}’ donnera ‘Dim Oct 25 09:25:02 2015’. Les préfixes ‘b:’ et ‘d:’ sont respectivement le basename(3) et le dirname(3) de la variable. Un préfixe de la forme ‘s/foo/bar/:’ substituera ‘foo’ par ‘bar’ partout.

De plus, la première ligne de la sortie d'une commande shell peut être insérée en utilisant ‘#()’. Par exemple, ‘#(uptime)’ insérera le temps de fonctionnement du système. Lors de la construction des formats, tmate n'attend pas que les commandes ‘#()’ se terminent ; au lieu de cela, le résultat précédent de l'exécution de la même commande est utilisé, ou un espace réservé si la commande n'a pas été exécutée auparavant. Les commandes sont exécutées avec l'environnement global tmate défini (voir la section ENVIRONNEMENT).

NOMS ET TITRES

tmate distingue les noms des titres. Les fenêtres et les sessions ont des noms, qui peuvent être utilisés pour les spécifier dans les cibles et sont affichés dans la ligne de statut et dans diverses listes : le nom est l'identifiant tmate pour une fenêtre ou une session. Seuls les panneaux ont des titres. Le titre d'un panneau est généralement défini par le programme exécuté à l'intérieur du panneau et n'est pas modifié par tmate. C'est le même mécanisme utilisé pour définir par exemple le titre de fenêtre de xterm(1) dans un gestionnaire de fenêtres X(7). Les fenêtres elles-mêmes n'ont pas de titres - le titre d'une fenêtre est le titre de son panneau actif. tmate peut lui-même définir le titre du terminal dans lequel le client est en cours d'exécution, voir l'option set-titles.

Le nom d'une session est défini avec les commandes new-session et rename-session. Le nom d'une fenêtre est défini par l'un des moyens suivants :

  1. Un argument de commande (tel que -n pour new-window ou new-session).
  2. Une séquence d'échappement : 
    $ printf '\033kWINDOW_NAME\033\\'
  3. Renommage automatique, qui définit le nom sur la commande active dans le panneau actif de la fenêtre. Voir l'option automatic-rename.

Lorsqu'un panneau est créé pour la première fois, son titre est le nom d'hôte. Le titre d'un panneau peut être défini via la séquence de réglage de titre OSC, par exemple :

$ printf '\033]2;Mon Titre\033\\'

ENVIRONNEMENT

Lorsque le serveur est démarré, tmate copie l'environnement dans l'environnement global ; de plus, chaque session possède un environnement de session. Lorsqu'une fenêtre est créée, les environnements de session et global sont fusionnés. Si une variable existe dans les deux, la valeur de l'environnement de session est utilisée. Le résultat est l'environnement initial passé au nouveau processus.

L'option de session update-environment peut être utilisée pour mettre à jour l'environnement de session à partir du client lorsqu'une nouvelle session est créée ou qu'une ancienne est réattachée. tmate initialise également la variable TMUX avec certaines informations internes pour permettre l'exécution de commandes depuis l'intérieur, et la variable TERM avec le réglage de terminal correct de « screen ».

Les commandes pour modifier et afficher l'environnement sont :

set-environment [-gru] [-t session-cible] nom [valeur]
(alias : setenv
) Définit ou annule une variable d'environnement. Si -g est utilisé, la modification est apportée à l'environnement global ; sinon, elle est appliquée à l'environnement de session pour session-cible. L'indicateur -u annule une variable. -r indique que la variable doit être supprimée de l'environnement avant de démarrer un nouveau processus.
show-environment [-gs] [-t session-cible] [variable]
(alias : showenv
) Affiche l'environnement pour session-cible ou l'environnement global avec -g. Si variable est omis, toutes les variables sont affichées. Les variables supprimées de l'environnement sont précédées de « - ». Si -s est utilisé, la sortie est formatée comme un ensemble de commandes Bourne shell.

LIGNE DE STATUT

tmate inclut une ligne de statut optionnelle qui est affichée sur la dernière ligne de chaque terminal. Par défaut, la ligne de statut est activée (elle peut être désactivée avec l'option de session status) et contient, de gauche à droite : le nom de la session courante entre crochets ; la liste des fenêtres ; le titre du panneau actif entre guillemets doubles ; et l'heure et la date.

La ligne de statut est composée de trois parties : des sections gauche et droite configurables (qui peuvent contenir du contenu dynamique comme l'heure ou la sortie d'une commande shell, voir les options status-left, status-left-length, status-right, et status-right-length ci-dessous), et une liste de fenêtres centrale. Par défaut, la liste des fenêtres affiche l'indice, le nom et le (s) drapeau (s) des fenêtres présentes dans la session courante par ordre numérique croissant. Elle peut être personnalisée avec les options window-status-format et window-status-current-format. Le drapeau est l'un des symboles suivants ajoutés au nom de la fenêtre :

Symbole Signification
* Désigne la fenêtre courante.
- Marque la dernière fenêtre (précédemment sélectionnée).
# La fenêtre est surveillée et une activité a été détectée.
! Une alarme s'est produite dans la fenêtre.
~ La fenêtre est restée silencieuse pendant l'intervalle de surveillance du silence.
M La fenêtre contient le panneau marqué.
Z Le panneau actif de la fenêtre est zoomé.

Le symbole # est lié à l'option de fenêtre monitor-activity. Le nom de la fenêtre est affiché en couleurs inversées s'il y a une alerte (alarme, activité ou silence).

La couleur et les attributs de la ligne de statut peuvent être configurés, toute la ligne de statut à l'aide de l'option de session status-style et les fenêtres individuelles à l'aide de l'option de fenêtre window-status-style.

La ligne de statut est automatiquement rafraîchie à intervalles si elle a changé, l'intervalle peut être contrôlé avec l'option de session status-interval.

Les commandes liées à la ligne de statut sont les suivantes :

command-prompt [-I entrées] [-p invites] [-t client-cible] [modèle]
Ouvre l'invite de commande dans un client. Ceci peut être utilisé depuis l'intérieur de tmate pour exécuter des commandes interactivement.

Si modèle est spécifié, il est utilisé comme commande. S'il est présent, -I est une liste séparée par des virgules du texte initial pour chaque invite. Si -p est donné, invites est une liste séparée par des virgules des invites qui sont affichées dans l'ordre ; sinon une seule invite est affichée, construite à partir de modèle s'il est présent, ou de ‘:’ sinon.

Les deux entrées et invites peuvent contenir les séquences de caractères spéciaux prises en charge par l'option status-left.

Avant que la commande ne soit exécutée, la première occurrence de la chaîne ‘%%’ et toutes les occurrences de ‘%1’ sont remplacées par la réponse à la première invite, la deuxième occurrence de ‘%%’ et toutes les occurrences de ‘%2’ sont remplacées par la réponse à la deuxième invite, et ainsi de suite pour les invites supplémentaires. Jusqu'à neuf réponses d'invite peuvent être remplacées (‘%1’ à ‘%9’).

confirm-before [-p invite] [-t client-cible] commande
(alias : confirm
) Demande une confirmation avant d'exécuter commande. Si -p est donné, invite est l'invite à afficher ; sinon une invite est construite à partir de commande. Elle peut contenir les séquences de caractères spéciaux prises en charge par l'option status-left.

Cette commande ne fonctionne que depuis l'intérieur de tmate.

display-message [-p] [-c client-cible] [-t panneau-cible] [message]
(alias : display
) Affiche un message. Si -p est donné, la sortie est imprimée sur la sortie standard, sinon elle est affichée dans la ligne de statut du client-cible. Le format de message est décrit dans la section FORMATS ; les informations sont tirées du panneau-cible si -t est donné, sinon le panneau actif de la session attachée au client-cible.

BUFFERS

tmate maintient un ensemble de buffers de collage nommés. Chaque buffer peut être nommé explicitement ou automatiquement. Les buffers nommés explicitement sont nommés lors de leur création avec les commandes set-buffer ou load-buffer, ou en renommant un buffer nommé automatiquement avec set-buffer -n. Les buffers nommés automatiquement reçoivent un nom tel que ‘buffer0001’, ‘buffer0002’ et ainsi de suite. Lorsque la limite de l'option buffer-limit est atteinte, le buffer nommé automatiquement le plus ancien est supprimé. Les buffers nommés explicitement ne sont pas soumis à buffer-limit et peuvent être supprimés avec la commande delete-buffer.

Les buffers peuvent être ajoutés en utilisant copy-mode ou les commandes set-buffer et load-buffer, et collés dans une fenêtre en utilisant la commande paste-buffer. Si une commande de buffer est utilisée et qu'aucun buffer n'est spécifié, le buffer nommé automatiquement le plus récemment ajouté est supposé.

Un historique configurable est également maintenu pour chaque fenêtre. Par défaut, jusqu'à 2000 lignes sont conservées ; ceci peut être modifié avec l'option history-limit (voir la commande set-option ci-dessus).

Les commandes de buffer sont les suivantes :

choose-buffer [-F format] [-t fenêtre-cible] [modèle]
Met une fenêtre en mode de choix de buffer, où un buffer peut être choisi interactivement dans une liste. Après qu'un buffer a été sélectionné, ‘%%’ est remplacé par le nom du buffer dans modèle et le résultat est exécuté comme une commande. Si modèle n'est pas donné, "paste-buffer -b '%%'" est utilisé. Pour la signification du drapeau -F, voir la section FORMATS. Cette commande ne fonctionne que si au moins un client est attaché.
clear-history [-t panneau-cible]
(alias : clearhist
) Supprime et libère l'historique pour le panneau spécifié.
delete-buffer [-b nom-du-buffer]
(alias : deleteb
) Supprime le buffer nommé nom-du-buffer, ou le buffer nommé automatiquement le plus récemment ajouté s'il n'est pas spécifié.
list-buffers [-F format]
(alias : lsb
) Liste les buffers globaux. Pour la signification du drapeau -F, voir la section FORMATS.
load-buffer [-b nom-du-buffer] chemin
(alias : loadb
) Charge le contenu du buffer de collage spécifié depuis chemin.
paste-buffer [-dpr] [-b nom-du-buffer] [-s séparateur] [-t panneau-cible]
(alias : pasteb
) Insère le contenu d'un buffer de collage dans le panneau spécifié. Si non spécifié, colle dans le panneau courant. Avec -d, supprime également le buffer de collage. Lors de la sortie, tout caractère de retour à la ligne (LF) dans le buffer de collage est remplacé par un séparateur, par défaut retour chariot (CR). Un séparateur personnalisé peut être spécifié en utilisant le drapeau -s. Le drapeau -r signifie de ne faire aucun remplacement (équivalent à un séparateur de LF). Si -p est spécifié, des codes de contrôle de collage par parenthèses sont insérés autour du buffer si l'application a demandé le mode de collage par parenthèses.
save-buffer [-a] [-b nom-du-buffer] chemin
(alias : saveb
) Sauvegarde le contenu du buffer de collage spécifié dans chemin. L'option -a ajoute au fichier plutôt que de l'écraser.
set-buffer [-a] [-b nom-du-buffer] [-n nouveau-nom-de-buffer] données
(alias : setb
) Définit le contenu du buffer spécifié à données. L'option -a ajoute au buffer plutôt que de l'écraser. L'option -n renomme le buffer en nouveau-nom-de-buffer.
show-buffer [-b nom-du-buffer]
(alias : ass="Ic">showb
) Affiche le contenu du tampon spécifié.

DIVERS

Les commandes diverses sont les suivantes :

clock-mode [-t cible-pane]
Affiche une grande horloge.
if-shell [-bF] [-t cible-pane] commande-shell commande [commande]
(alias : if

Si -F est spécifié, commande-shell n'est pas exécutée mais considérée comme réussie si elle n'est ni vide ni zéro (après expansion des formats).

lock-server
(alias : lock

run-shell [-b] [-t cible-pane] commande-shell
(alias : run

Avec -b, la commande est exécutée en arrière-plan. Une fois terminée, toute sortie vers stdout est affichée en mode copie (dans le pane spécifié par -t ou le pane courant si omis). wait-for [-L | -S | -U] canal

EXTENSIONS TERMINFO

tmate comprend quelques extensions non officielles à terminfo(5) :

Cs, Cr
Définit la couleur du curseur. La première prend une seule chaîne de caractères en argument et est utilisée pour définir la couleur ; la seconde ne prend aucun argument et restaure la couleur par défaut du curseur. Si elle est définie, une séquence telle que celle-ci peut être utilisée pour changer la couleur du curseur depuis tmate : 
$ printf '\033]12;red\033\\'
Ss, Se
Définit ou réinitialise le style du curseur. S'il est défini, une séquence telle que celle-ci peut être utilisée pour changer le curseur en souligné : 
$ printf '\033[4 q'

Si Se n'est pas défini, Ss avec l'argument 0 sera utilisé pour réinitialiser le style du curseur à la place.

Tc
Indique que le terminal prend en charge la séquence d'échappement ‘couleur directe’ (par exemple, \e[38;2;255;255;255m).
Ms
Stocke le tampon courant dans la sélection du terminal hôte (presse-papiers). Voir l'option set-clipboard ci-dessus et la page de manuel xterm(1).

MODE CONTRÔLE

tmate offre une interface textuelle appelée mode contrôle. Cela permet aux applications de communiquer avec tmate en utilisant un protocole simple uniquement texte.

En mode contrôle, un client envoie des commandes ou des séquences de commandes tmate terminées par des retours à la ligne sur l'entrée standard. Chaque commande produira un bloc de sortie sur la sortie standard. Un bloc de sortie se compose d'une ligne %begin suivie de la sortie (qui peut être vide). Le bloc de sortie se termine par un %end ou %error. %begin et le %end ou %error correspondant ont deux arguments : un entier représentant le temps (en secondes depuis l'époque) et un numéro de commande. Par exemple :

%begin 1363006971 2
0: ksh* (1 panes) [80x24] [layout b25f,80x24,0,0,2] @2 (active)
%end 1363006971 2

En mode contrôle, tmate émet des notifications. Une notification ne se produit jamais à l'intérieur d'un bloc de sortie.

Les notifications suivantes sont définies :

%exit [raison]
Le client tmate se termine immédiatement, soit parce qu'il n'est attaché à aucune session, soit parce qu'une erreur s'est produite. Si elle est présente, raison décrit pourquoi le client s'est terminé.
%layout-change id-fenêtre agencement-fenêtre agencement-visible-fenêtre indicateurs-fenêtre
L'agencement d'une fenêtre avec l'ID id-fenêtre a changé. L'agencement nouveau est agencement-fenêtre. L'agencement visible de la fenêtre est agencement-visible-fenêtre et les indicateurs de la fenêtre sont indicateurs-fenêtre.
%output id-pane valeur
Un pane de fenêtre a produit une sortie. valeur échappe les caractères non imprimables et le backslash en octal \xxx.
%session-changed id-session nom
Le client est maintenant attaché à la session avec l'ID id-session, qui est nommée nom.
%session-renamed nom
La session courante a été renommée en nom.
%sessions-changed
Une session a été créée ou détruite.
%unlinked-window-add id-fenêtre
La fenêtre avec l'ID id-fenêtre a été créée mais n'est pas liée à la session courante.
%window-add id-fenêtre
La fenêtre avec l'ID id-fenêtre a été liée à la session courante.
%window-close id-fenêtre
La fenêtre avec l'ID id-fenêtre s'est fermée.
%window-renamed id-fenêtre nom
La fenêtre avec l'ID id-fenêtre a été renommée en nom.

EXEMPLES

Pour créer une nouvelle session tmate exécutant vi(1) :

$ tmate new-session vi

La plupart des commandes ont une forme plus courte, connue sous le nom d'alias. Pour new-session, il s'agit de new :

$ tmate new vi

Alternativement, la forme la plus courte et non ambiguë d'une commande est acceptée. S'il y a plusieurs options, elles sont listées :

$ tmate n
commande ambiguë : n, pourrait être : new-session, new-window, next-window

Dans une session active, une nouvelle fenêtre peut être créée en tapant ‘C-b c’ (Ctrl suivi de la touche ‘b’ puis de la touche ‘c’).

Les fenêtres peuvent être parcourues avec : ‘C-b 0’ (pour sélectionner la fenêtre 0), ‘C-b 1’ (pour sélectionner la fenêtre 1), etc. ; ‘C-b n’ pour sélectionner la fenêtre suivante ; et ‘C-b p’ pour sélectionner la fenêtre précédente.

Une session peut être détachée en utilisant ‘C-b d’ (ou par un événement externe tel que la déconnexion ssh(1)) et rattachée avec :

$ tmate attach-session

Taper ‘C -b ?’ liste les raccourcis clavier actuels dans la fenêtre en cours ; les flèches haut et bas peuvent être utilisées pour naviguer dans la liste ou ‘q’ pour en sortir.

Les commandes à exécuter lorsque le serveur tmate est démarré peuvent être placées dans le fichier de configuration ~/.tmux.conf. Exemples courants :

Changement de la touche préfixe par défaut :

set-option -g prefix C-a
unbind-key C-b
bind-key C-a send-prefix

Désactivation de la ligne de statut, ou changement de sa couleur :

set-option -g status off
set-option -g status-style bg=blue

Définition d'autres options, comme la commande par défaut, ou le verrouillage après 30 minutes d'inactivité :

set-option -g default-command "exec /bin/ksh"
set-option -g lock-after-time 1800

Création de nouveaux raccourcis clavier :

bind-key b set-option status
bind-key / command-prompt "split-window 'exec man %%'"
bind-key S command-prompt "new-window -n %1 'ssh %1'"
