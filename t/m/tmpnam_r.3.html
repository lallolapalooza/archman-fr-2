tmpnam(3) Manuel des fonctions de bibliothèque tmpnam(3)

NOM

tmpnam, tmpnam_r — créer un nom de fichier temporaire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdio.h>
[[deprecated]] char *tmpnam(char *s);
[[deprecated]] char *tmpnam_r(char *s);
Exigences relatives aux macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

tmpnam_r()

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    Jusqu'à glibc 2.19 inclus :
        _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Note : évitez d'utiliser ces fonctions ; utilisez plutôt mkstemp(3) ou tmpfile(3).

La fonction tmpnam() renvoie un pointeur vers une chaîne qui est un nom de fichier valide, et tel qu'un fichier portant ce nom n'a pas existé à un moment donné, de sorte que les programmeurs naïfs puissent penser qu'il s'agit d'un nom approprié pour un fichier temporaire. Si l'argument s est NULL, ce nom est généré dans un tampon statique interne et peut être écrasé par l'appel suivant à tmpnam(). Si s n'est pas NULL, le nom est copié dans le tableau de caractères (d'une longueur d'au moins L_tmpnam) pointé par s et la valeur s est renvoyée en cas de succès.

Le chemin du fichier créé a un préfixe de répertoire P_tmpdir. (Les deux L_tmpnam et P_tmpdir sont définis dans <stdio.h>, tout comme le TMP_MAX mentionné ci-dessous.)

La fonction tmpnam_r() effectue la même tâche que tmpnam(), mais renvoie NULL (pour indiquer une erreur) si s est NULL.

VALEUR RENVOYÉE

Ces fonctions renvoient un pointeur vers un nom de fichier temporaire unique, ou NULL si un nom unique ne peut pas être généré.

ERREURS

Aucune erreur n'est définie.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
tmpnam () Sécurité des threads MT-Unsafe race:tmpnam/!s
tmpnam_r () Sécurité des threads MT-Safe

STANDARDS

tmpnam()
C11, POSIX.1-2008.
tmpnam_r()
Aucun.

HISTORIQUE

tmpnam()
SVr4, 4.3BSD, C89, POSIX.1-2001. Obsolète dans POSIX.1-2008.
tmpnam_r()
Solaris.

NOTES

La fonction tmpnam() génère une chaîne différente à chaque appel, jusqu'à TMP_MAX fois. Si elle est appelée plus de TMP_MAX fois, le comportement est défini par l'implémentation.

Bien que ces fonctions génèrent des noms difficiles à deviner, il est néanmoins possible qu'entre le moment où le chemin est renvoyé et le moment où le programme l'ouvre, un autre programme puisse créer ce chemin en utilisant open(2), ou le créer comme un lien symbolique. Cela peut entraîner des failles de sécurité. Pour éviter de telles possibilités, utilisez le drapeau open(2) O_EXCL pour ouvrir le chemin. Ou mieux encore, utilisez mkstemp(3) ou tmpfile(3).

Les applications portables qui utilisent des threads ne peuvent pas appeler tmpnam() avec un argument NULL si _POSIX_THREADS ou _POSIX_THREAD_SAFE_FUNCTIONS est défini.

BOGUES

N'utilisez jamais ces fonctions. Utilisez plutôt mkstemp(3) ou tmpfile(3).

VOIR AUSSI

mkstemp(3), mktemp(3), tempnam(3), tmpfile(3)
