DESCRIPTION

Les fichiers de configuration tmpfiles.d fournissent un mécanisme générique pour définir la création de fichiers réguliers, de répertoires, de tubes et de nœuds de périphériques, l'ajustement de leur mode d'accès, de leur propriétaire, de leurs attributs, de leurs quotas d'attribution et de leur contenu, et enfin leur suppression basée sur le temps. Il est le plus couramment utilisé pour les fichiers et répertoires volatils et temporaires (tels que ceux situés sous /run/, /tmp/, /var/tmp/, les systèmes de fichiers API comme /sys/ ou /proc/, ainsi que certains autres répertoires sous /var/).

systemd-tmpfiles(8) utilise cette configuration pour créer des fichiers et répertoires volatils pendant le démarrage et pour effectuer un nettoyage périodique ensuite. Voir systemd-tmpfiles(8) pour la description de systemd-tmpfiles-setup.service, systemd-tmpfiles-clean.service, et des unités associées.

Les démons système nécessitent fréquemment des répertoires d'exécution privés sous /run/ pour stocker des sockets de communication et similaires. Pour ceux-ci, il est préférable d'utiliser RuntimeDirectory= dans leurs fichiers d'unité (voir systemd.exec(5) pour les détails), si la flexibilité offerte par tmpfiles.d n'est pas requise. Les avantages sont que la configuration requise par l'unité est centralisée en un seul endroit, et que la durée de vie du répertoire est liée à la durée de vie du service lui-même. De même, StateDirectory=, CacheDirectory=, LogsDirectory=, et ConfigurationDirectory= doivent être utilisés pour créer des répertoires sous /var/lib/, /var/cache/, /var/log/, et /etc/. tmpfiles.d doit être utilisé pour les fichiers dont la durée de vie est indépendante de tout service ou nécessite une configuration plus complexe.

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

Chaque fichier de configuration doit être nommé selon le style package.conf ou package-part.conf. La seconde variante doit être utilisée lorsqu'il est souhaitable de rendre facile la substitution de seulement cette partie de la configuration.

Les fichiers dans /etc/tmpfiles.d remplacent les fichiers portant le même nom dans /usr/lib/tmpfiles.d et /run/tmpfiles.d. Les fichiers dans /run/tmpfiles.d remplacent les fichiers portant le même nom dans /usr/lib/tmpfiles.d. Les paquets doivent installer leurs fichiers de configuration dans /usr/lib/tmpfiles.d. Les fichiers dans /etc/tmpfiles.d sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Tous les fichiers de configuration sont triés par leur nom de fichier dans l'ordre lexicographique, quelle que soit la répertoire dans lequel ils résident. Si plusieurs fichiers spécifient le même chemin, l'entrée du fichier ayant le nom lexicographiquement le plus précoce sera appliquée (notez que les lignes supprimées à cause du "!" sont filtrées avant l'application, ce qui signifie que si une ligne précoce porte le point d'exclamation et est supprimée à cause de cela, une ligne ultérieure correspondant au chemin sera appliquée). Toutes les autres entrées conflictuelles seront enregistrées comme des erreurs. Lorsque deux lignes sont respectivement le chemin préfixe et le chemin suffixe l'une de l'autre, la ligne préfixe est toujours créée en premier, la suffixe plus tard (et si la suppression s'applique à la ligne, l'ordre est inversé : le suffixe est supprimé en premier, le préfixe plus tard). Les lignes qui acceptent des jokers sont appliquées après celles qui n'en acceptent pas. Si plusieurs opérations doivent être appliquées au même fichier (telles que des ajustements d'ACL, de xattr, d'attributs de fichier), celles-ci sont toujours effectuées dans le même ordre fixe. Sauf dans ces cas, les fichiers/répertoires sont traités dans l'ordre où ils sont listés.

Si l'administrateur souhaite désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée est de placer un lien symbolique vers /dev/null dans /etc/tmpfiles.d/ portant le même nom de fichier.

FORMAT DES FICHIERS DE CONFIGURATION

Le format de configuration est une ligne par chemin, contenant des champs de type, chemin, mode, propriétaire, âge et argument. Les lignes sont séparées par des retours à la ligne, les champs par des espaces blancs :

#Type Chemin        Mode Utilisateur Groupe Age Argument...
d     /run/user   0755 root root  10d -
L     /tmp/foobar -    -    -     -   /dev/null

Les champs peuvent contenir des échappements de style C. À l'exception du septième champ (l'"argument"), tous les champs peuvent être entre guillemets. Notez que tout espace blanc trouvé sur la ligne après le début du champ argument sera considéré comme faisant partie du champ argument. Pour que le champ argument commence par un caractère d'espace blanc, utilisez des échappements de style C (par exemple, "\x20").

Type

Le type se compose d'une seule lettre et éventuellement d'un ou plusieurs caractères modificateurs : un signe plus ("+"), un point d'exclamation ("!"), un signe moins ("-"), un signe égal ("="), un tilde ("~") et/ou un accent circonflexe ("^").

Les types de ligne suivants sont compris :

f, f+

f créera un fichier s'il n'existe pas encore. Si le paramètre argument est donné et que le fichier n'existait pas encore, il sera écrit dans le fichier. f+ créera ou tronquera le fichier. Si le paramètre argument est donné, il sera écrit dans le fichier. Ne suit pas les liens symboliques.

w,

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

w+

Écrit le paramètre de l'argument dans un fichier, si le fichier existe. S'il est suffixé par +, la ligne sera ajoutée au fichier. Si votre configuration écrit plusieurs lignes dans le même fichier, utilisez w+. Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux. Le paramètre de l'argument sera écrit sans saut de ligne final. Les échappements de style C avec barre oblique inverse sont interprétés. Suit les liens symboliques.

d

Crée un répertoire. Le mode et la propriété seront ajustés s'ils sont spécifiés. Le contenu de ce répertoire est soumis à un nettoyage basé sur le temps si l'argument d'âge est spécifié.

D

Similaire à d, mais en plus le contenu du répertoire sera supprimé lorsque --remove est utilisé.

e

Ajuste le mode et la propriété des répertoires existants et supprime leur contenu en fonction de l'âge. Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux. Le contenu des répertoires est soumis à un nettoyage basé sur le temps si l'argument d'âge est spécifié. Si l'argument d'âge est "0", le contenu sera inconditionnellement supprimé à chaque fois que systemd-tmpfiles(8) --clean est exécuté.

Pour que cette entrée soit utile, au moins un des arguments mode, utilisateur, groupe ou âge doit être spécifié, car sinon cette entrée n'a aucun effet. Par exception, une entrée sans effet peut être utile lorsqu'elle est combinée avec !, voir les exemples.

Ajouté dans la version 230.

v

Crée un sous-volume si le chemin n'existe pas encore, si le système de fichiers prend en charge les sous-volumes (btrfs) et si le système lui-même est installé dans un sous-volume (spécifiquement : le répertoire racine / est lui-même un sous-volume). Sinon, crée un répertoire normal, de la même manière que d.

Un sous-volume créé avec ce type de ligne n'est assigné à aucun groupe de quotas de niveau supérieur. Pour cela, utilisez q ou Q, qui permettent de créer des hiérarchies de groupes de quotas simples, voir ci-dessous.

Ajouté dans la version 219.

q

Crée un sous-volume ou un répertoire comme v, mais assigne le sous-volume aux mêmes groupes de quotas de niveau supérieur que le parent. Cela garantit que les limites et la comptabilité de niveau supérieur appliquées au sous-volume parent incluent également le sous-volume spécifié. Sur les systèmes de fichiers autres que btrfs, ce type de ligne est identique à d.

Si le sous-volume existe déjà, aucune modification de la hiérarchie des quotas n'est effectuée, que le sous-volume soit déjà attaché à un groupe de quotas ou non. Voir également Q ci-dessous. Voir btrfs-qgroup(8) pour les détails sur le concept de groupe de quotas btrfs.

Ajouté dans la version 228.

Q

Crée le sous-volume ou le répertoire comme v, mais assigne le nouveau sous-volume à un nouveau groupe de quotas feuille. Au lieu de copier les assignations de groupes de quotas de niveau supérieur du parent comme cela est fait avec q, le groupe de quotas le plus bas du sous-volume parent est déterminé, qui n'est pas le groupe de quotas feuille. Ensuite, un groupe de quotas "intermédiaire" est inséré, qui est un niveau en dessous de ce niveau, et partage la même partie d'identifiant que le sous-volume spécifié. Si aucun groupe de quotas de niveau supérieur n'existe pour le sous-volume parent, un nouveau groupe de quotas au niveau 255 partageant le même identifiant que le sous-volume spécifié est inséré à la place. Ce nouveau groupe de quotas intermédiaire est alors assigné aux groupes de quotas de niveau supérieur du sous-volume parent, et le groupe de quotas feuille du sous-volume spécifié lui est assigné.

En pratique, cela a un effet similaire à q, mais introduit un nouveau groupe de quotas de niveau supérieur pour le sous-volume spécifié qui peut être utilisé pour appliquer des limites et de la comptabilité au sous-volume spécifié et aux sous-volumes enfants créés à l'intérieur. Ainsi, en créant des sous-volumes uniquement via q et Q, un concept de "quotas de sous-arborescence" est implémenté. Chaque sous-volume pour lequel Q est défini obtiendra un groupe de quotas de "sous-arborescence" créé, et tous les sous-volumes enfants créés à l'intérieur lui seront assignés. Chaque sous-volume pour lequel q est défini n'obtiendra pas un tel groupe de quotas de "sous-arborescence", mais il est garanti qu'ils seront ajoutés au même groupe de quotas de "sous-arborescence" que leurs parents immédiats.

Il est recommandé d'utiliser Q pour les sous-volumes qui contiennent généralement d'autres sous-volumes, et où il est souhaitable d'avoir de la comptabilité et des limites de quotas sur tous les sous-volumes enfants ensemble. Les exemples pour Q sont typiquement /home/ ou /var/lib/machines/. En revanche, q doit être utilisé pour les sous-volumes qui ne contiennent généralement pas d'autres sous-volumes ou pour lesquels aucune comptabilité et aucune limite de quotas ne sont nécessaires pour tous les sous-volumes enfants ensemble. Les exemples pour q sont typiquement /var/ ou /var/tmp/.

Comme avec q, Q n'a aucun effet sur la hiérarchie des groupes de quotas si le sous-volume existe déjà, que le sous-volume appartienne déjà à un groupe de quotas ou non.

Ajouté dans la version 228.

p, p+

Crée un tube nommé (FIFO) s'il n'existe pas encore. S'il est suffixé par + et qu'un fichier existe déjà là où le tube doit être créé, il sera supprimé et remplacé par le tube.

L, L+, L?

Crée un lien symbolique s'il n'existe pas encore. S'il est suffixé par + et qu'un fichier ou un répertoire existe déjà là où le lien symbolique doit être créé, il sera supprimé et remplacé par le lien symbolique. S'il est suffixé par ? et que le chemin source n'existe pas, le lien symbolique n'est pas créé. Si l'argument est omis, des liens symboliques vers des fichiers portant le même nom résidant dans le répertoire /usr/share/factory/ sont créés. Notez que les permissions sur les liens symboliques sont ignorées.

c, c+

Crée un nœud de périphérique caractère s'il n'existe pas encore. S'il est suffixé par + et qu'un fichier existe déjà là où le nœud de périphérique doit être créé, il sera supprimé et remplacé par le nœud de périphérique. Il est recommandé de suffixer cette entrée par un point d'exclamation pour ne créer des nœuds de périphériques statiques qu'au démarrage, car udev ne gérera pas les nœuds de périphériques statiques créés à l'exécution.

b, b+

Crée un nœud de périphérique bloc s'il n'existe pas encore. S'il est suffixé par + et qu'un fichier existe déjà là où le nœud de périphérique doit être créé, il sera supprimé et remplacé par le nœud de périphérique. Il est recommandé de suffixer cette entrée par un point d'exclamation pour ne créer des nœuds de périphériques statiques qu'au démarrage, car udev ne gérera pas les nœuds de périphériques statiques créés à l'exécution.

C, C+

Copie récursivement un fichier ou un répertoire, si les fichiers ou répertoires de destination n'existent pas encore ou si le répertoire de destination est vide. Notez que cette commande ne descendra pas dans les sous-répertoires si le répertoire de destination existe déjà et n'est pas vide, sauf si l'action est suffixée par +. Au lieu de cela, l'opération de copie entière sera ignorée. Si l'argument est omis, les fichiers du répertoire source /usr/share/factory/ portant le même nom sont copiés. Ne suit pas les liens symboliques. Le contenu des répertoires est soumis à un nettoyage basé sur le temps si l'argument d'âge est spécifié.

Ajouté dans la version 214.

x

Ignore un chemin lors du nettoyage. Utilisez ce type pour exclure des chemins du nettoyage tel que contrôlé par le paramètre Âge. Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux.

X

Ignore un chemin lors du nettoyage. Utilisez ce type pour exclure des chemins du nettoyage tel que contrôlé par le paramètre Âge. Contrairement à x, ce paramètre n'exclura pas le contenu si le chemin est un répertoire, mais seulement le répertoire lui-même. Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux.

Ajouté dans la version 198.

r

Supprime un fichier ou un répertoire s'il existe. Ceci ne peut pas être utilisé pour supprimer des répertoires non vides, utilisez R pour cela. Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux. Ne suit pas les liens symboliques.

R

Supprime récursivement un chemin et tous ses sous-répertoires (s'il s'agit d'un répertoire). Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux. Ne suit pas les liens symboliques.

z

Ajuste le mode d'accès, la propriété utilisateur et groupe, et restaure le contexte de sécurité SELinux d'un fichier ou d'un répertoire, s'il existe. Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux. Ne suit pas les liens symboliques.

Z

Définit récursivement le mode d'accès, la propriété utilisateur et groupe, et restaure le contexte de sécurité SELinux d'un fichier ou d'un répertoire s'il existe, ainsi que de ses sous-répertoires et des fichiers qu'ils contiennent (si applicable). Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux. Ne suit pas les liens symboliques.

t

Définit les attributs étendus, voir attr(5) pour les détails. Le champ argument doit contenir une ou plusieurs expressions d'assignation sous la forme namespace.attribute=value, pour des exemples voir ci-dessous. Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux. Ceci peut être utile pour définir des étiquettes SMACK. Ne suit pas les liens symboliques.

Veuillez noter que les attributs étendus configurables avec ce type de ligne sont un concept différent des attributs de fichier Linux configurables avec h/H, voir ci-dessous.

Ajouté dans la version 218.

T

Identique à t, mais opère récursivement.

Ajouté dans la version 219.

h

Définit les attributs de fichier/répertoire Linux. Les lignes de ce type acceptent des globs de style shell à la place des noms de chemin normaux.

Le format du champ argument est [+-=][aAcCdDeijPsStTu]. Le préfixe + (qui est le défaut) provoque l'ajout des attributs ; - provoque la suppression des attributs ; = provoque la définition exacte des attributs comme les lettres suivantes. Les lettres "aAcCdDeijPsStTu" sélectionnent les nouveaux attributs pour les fichiers, voir chattr(1) pour plus d'informations.

Passer uniquement = comme argument réinitialise tous les attributs de fichier listés ci-dessus. Il faut souligner que le préfixe = se limite aux attributs correspondant aux lettres listées ici. Tous les autres attributs resteront inchangés. Ne suit pas les liens symboliques.

Veuillez noter que les attributs de fichier Linux configurables avec ce type de ligne sont un concept différent des attributs étendus configurables avec t/T, voir ci-dessus.

H

Identique à h, mais opère récursivement.

Ajouté dans la version 220.

a, a+

Définit les ACL POSIX (listes de contrôle d'accès), voir acl(5). De plus, si 'X' est utilisé, le bit d'exécution est défini uniquement si le fichier est un répertoire ou a déjà la permission d'exécution pour
quelques utilisateurs, comme mentionné dans setfacl(1). S'il est suffixé par +, les entrées spécifiées seront ajoutées à l'ensemble existant. systemd-tmpfiles(8) ajoutera automatiquement les entrées de base requises pour l'utilisateur et le groupe en fonction du mode d'accès du fichier, à moins que des entrées de base n'existent déjà ou ne soient explicitement spécifiées. Le masque sera ajouté s'il n'est pas spécifié explicitement ou déjà présent. Les lignes de ce type acceptent des jokers de style shell à la place des noms de chemin normaux. Ceci peut être utile pour autoriser un accès supplémentaire à certains fichiers. Ne suit pas les liens symboliques.

Ajouté dans la version 219.

A, A+

Identique à a et a+, mais récursif. Ne suit pas les liens symboliques.

Modificateurs de type

Si le point d'exclamation ("!") est utilisé, cette ligne ne peut être exécutée en toute sécurité que pendant le démarrage et peut casser un système en cours d'exécution. Les lignes sans le point d'exclamation sont supposées pouvoir être exécutées à tout moment, par exemple lors des mises à niveau de paquets. systemd-tmpfiles(8) ne prendra en compte les lignes avec un point d'exclamation que si l'option --boot est donnée.

Par exemple :

# Assurez-vous que ceux-ci sont créés par défaut afin que personne d'autre ne puisse le faire
d /tmp/.X11-unix 1777 root root 10d
# Supprimez les fichiers de verrouillage X11
r! /tmp/.X[0-9]*-lock

La deuxième ligne, contrairement à la première, casserait un système en cours d'exécution et ne sera exécutée qu'avec --boot.

Si le signe moins ("-") est utilisé, l'échec de l'exécution de cette ligne lors de la création (et uniquement lors de la création) n'entraînera pas le retour d'une erreur par systemd-tmpfiles(8).

Par exemple :

# Modifier sysfs mais ne pas échouer si nous sommes dans un conteneur avec /proc en lecture seule
w- /proc/sys/vm/swappiness - - - - 10

Si le signe égal ("=") est utilisé, les types de fichiers des objets existants dans le chemin spécifié sont vérifiés et supprimés s'ils ne correspondent pas. Cela inclut tous les répertoires parents implicitement créés (qui peuvent être des répertoires ou des liens symboliques de répertoires). Par exemple, s'il y a un FIFO à la place d'un des composants du chemin parent, il sera remplacé par un répertoire.

Si le caractère tilde ("~") est utilisé, l'argument (c'est-à-dire la 6ème colonne) est décodé en Base64[1] avant utilisation. Ce modificateur n'est pris en charge que pour les types de lignes qui peuvent écrire le contenu des fichiers, c'est-à-dire f, f+, w, w+. Ceci est utile pour écrire des données binaires arbitraires (y compris des sauts de ligne et des octets NUL) dans des fichiers. Notez que si ce commutateur est utilisé, l'argument n'est soumis à aucune expansion de spécificateur, ni avant ni après le décodage Base64.

Si le caractère caret ("^") est utilisé, l'argument (c'est-à-dire la 6ème colonne) prend le nom d'une credential de service pour lire les données de l'argument. Voir Credentials système et de service[2] pour plus de détails sur le concept de credentials. Ce modificateur n'est pris en charge que pour les types de lignes qui peuvent écrire le contenu des fichiers, c'est-à-dire f, f+, w, w+. Ceci est utile pour écrire des fichiers arbitraires dont le contenu provient d'ailleurs, y compris de gestionnaires de VM ou de conteneurs en amont. Si la credential spécifiée n'est pas définie pour le service systemd-tmpfiles, la ligne est silencieusement ignorée. Si "^" et "~" sont combinés, le décodage Base64 est appliqué au contenu de la credential.

Si le signe dollar ("$") est utilisé, le fichier sera sujet à suppression lorsque systemd-tmpfiles est invoqué avec le commutateur --purge. Les lignes sans ce caractère ne sont pas affectées par ce commutateur.

Notez que pour tous les types de lignes qui entraînent la création de tout type de nœud de fichier (c'est-à-dire f, d/D/v/q/Q, p, L, c/b et C) les répertoires principaux sont implicitement créés si nécessaire, appartenant à root avec un mode d'accès de 0755. Afin de les créer avec des modes ou des propriétaires différents, assurez-vous d'ajouter des lignes d appropriées.

Chemin

La spécification du chemin du système de fichiers prend en charge l'expansion de spécificateurs simples, voir ci-dessous. Le chemin (après expansion) doit être absolu.

Mode

Le mode d'accès au fichier à utiliser lors de la création de ce fichier ou répertoire. S'il est omis ou défini sur "-", la valeur par défaut est utilisée : 0755 pour les répertoires, 0644 pour tous les autres objets de fichier. Pour les lignes z, Z, s'il est omis ou défini sur "-", le mode d'accès au fichier ne sera pas modifié. Ce paramètre est ignoré pour les lignes x, r, R, L, t et a.

Optionnellement, s'il est précédé de "~", le mode d'accès est masqué en fonction des bits d'accès déjà définis pour les fichiers ou répertoires existants : si le fichier existant n'a aucun bit exécutable, tous les bits exécutables sont également supprimés du nouveau mode d'accès. De même, si tous les bits de lecture sont supprimés de l'ancien mode d'accès, ils seront également supprimés du nouveau mode d'accès, et si tous les bits d'écriture sont supprimés, ils seront également supprimés du nouveau mode d'accès. De plus, le bit collant/SUID/SGID est supprimé sauf s'il est appliqué à un répertoire. Cette fonctionnalité est particulièrement utile en conjonction avec Z.

Par défaut, le mode d'accès des inodes listés est défini sur le mode spécifié, qu'il soit créé nouvellement ou qu'il existe déjà. Optionnellement, s'il est précédé de ":", le mode d'accès configuré n'est appliqué que lors de la création de nouveaux inodes, et si l'inode auquel la ligne fait référence existe déjà, son mode d'accès est laissé inchangé.

Utilisateur, Groupe

L'utilisateur et le groupe à utiliser pour ce fichier ou répertoire. Il peut s'agir d'un ID numérique ou d'un nom d'utilisateur/groupe. S'il est omis ou défini sur "-", l'utilisateur et le groupe de l'utilisateur qui invoque systemd-tmpfiles(8) sont utilisés. Pour les lignes z et Z, s'il est omis ou défini sur "-", la propriété du fichier ne sera pas modifiée. Ces paramètres sont ignorés pour les lignes x, r, R, t et a.

Ce champ ne doit généralement faire référence qu'à des utilisateurs/groupes système, c'est-à-dire des utilisateurs/groupes dont la résolution est garantie pendant le démarrage précoce. Si ce champ fait référence à des utilisateurs/groupes qui ne deviennent résolubles que plus tard dans le démarrage (c'est-à-dire après la disponibilité de NIS, LDAP ou un service d'annuaire réseau similaire), l'exécution des opérations déclarées par la ligne échouera probablement. Voir également Notes sur la résolubilité des noms d'utilisateur et de groupe[3] pour plus d'informations sur les exigences des définitions d'utilisateurs et de groupes système.

Par défaut, la propriété des inodes listés est définie sur l'utilisateur/groupe spécifié, qu'il soit créé nouvellement ou qu'il existe déjà. Optionnellement, s'il est précédé de ":", les informations utilisateur/groupe configurées ne sont appliquées que lors de la création de nouveaux inodes, et si l'inode auquel la ligne fait référence existe déjà, son utilisateur/groupe est laissé inchangé.

Âge

Le champ de date, lorsqu'il est défini, est utilisé pour décider quels fichiers supprimer lors du nettoyage. Si un fichier ou un répertoire est plus ancien que le temps actuel moins la durée spécifiée, il est supprimé. Le format du champ est une série d'entiers chacun suivi de l'un des suffixes suivants pour les unités de temps respectives : s, m ou min, h, d, w, ms et us, signifiant secondes, minutes, heures, jours, semaines, millisecondes et microsecondes, respectivement. Les noms complets des unités de temps peuvent également être utilisés.

Si plusieurs entiers et unités sont spécifiés, les valeurs temporelles sont additionnées. Si un entier est donné sans unité, s est supposé.

Lorsque la durée est fixée à zéro, les fichiers sont nettoyés inconditionnellement.

Le champ d'âge ne s'applique qu'aux lignes commençant par d, D, e, v, q, Q, C, x et X. S'il est omis ou défini sur "-", aucun nettoyage automatique n'est effectué.

Si le champ d'âge commence par un caractère tilde "~", le nettoyage ne s'applique qu'aux fichiers et répertoires situés un niveau en dessous du répertoire spécifié, mais pas aux fichiers et répertoires immédiatement en dessous.

L'âge d'une entrée du système de fichiers est déterminée à partir de son horodatage de dernière modification (mtime), de son horodatage de dernier accès (atime) et (sauf pour les répertoires) de son horodatage de dernier changement d'état (ctime). Par défaut, l'une de ces trois (ou deux) valeurs empêchera le nettoyage si elle est plus récente que le temps actuel moins la durée spécifiée. Pour restreindre la suppression en fonction d'un type particulier d'horodatages de fichiers, l'argument age-by peut être utilisé.

L'argument age-by remplace les types d'horodatages à utiliser pour la vérification de l'âge. Il peut être spécifié en préfixant l'argument d'âge avec une séquence de caractères pour spécifier les types d'horodatages et un deux-points (":") : "age-by...:cleanup-age". L'argument peut se composer de a (A pour les répertoires), b (B pour les répertoires), c (C pour les répertoires) ou m (M pour les répertoires). Ceux-ci indiquent respectivement l'accès, la création, le dernier changement d'état et la dernière modification d'un système de fichiers. La lettre minuscule signifie que le type d'horodatage donné doit être pris en compte pour les fichiers, tandis que la lettre majuscule signifie que le type d'horodatage donné doit être pris en compte pour les répertoires. Voir les champs d'horodatage de fichier de statx(2) pour plus de détails sur les types d'horodatages.

S'il n'est pas spécifié, le champ age-by est par défaut abcmABM, c'est-à-dire que par défaut tous les horodatages de fichiers sont pris en compte, à l'exception de l'horodatage du dernier changement d'état (ctime) pour les répertoires. En effet, la logique de vieillissement elle-même modifiera le ctime chaque fois qu'elle supprimera un fichier à l'intérieur. Pour s'assurer que l'exécution de la logique de vieillissement ne réinjecte pas dans la prochaine itération de celle-ci, le ctime des répertoires est ignoré par défaut.

Par exemple :

# Les fichiers créés et modifiés, et les répertoires consultés il y a plus d'une heure
# dans "/tmp/foo/bar", sont soumis à un nettoyage basé sur le temps.
d /tmp/foo/bar - - - bmA:1h -
