TYPE(1P) Manuel du programmeur POSIX TYPE(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

type — affiche une description du type d'une commande

SYNTAXE

type nom...

DESCRIPTION

L'utilitaire type indiquera comment chaque argument serait interprété s'il était utilisé comme nom de commande.

OPTIONS

Aucune.

OPÉRANDES

L'opérande suivant sera pris en charge :

nom
Un nom à interpréter.

ENTRÉE STANDARD

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de type :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume des Définitions de base de POSIX.1-2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini à une chaîne de caractères non vide, écrase les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
PATH
Détermine l'emplacement de nom, comme décrit dans le volume des Définitions de base de POSIX.1-2017, Chapitre 8, Variables d'environnement.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

La sortie standard de type contient des informations sur chaque opérande dans un format non spécifié. Les informations fournies identifient généralement l'opérande comme une commande intégrée du shell, une fonction, un alias ou un mot-clé, et lorsque cela est applicable, peuvent afficher le chemin d'accès de l'opérande.

SORTIE STANDARD D'ERREUR

La sortie standard d'erreur ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Exécution réussie.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Étant donné que type doit connaître le contenu de l'environnement d'exécution actuel du shell (comme les listes de commandes, de fonctions et de commandes intégrées traitées par hash), il est toujours fourni comme une commande intégrée régulière du shell. S'il est appelé dans un environnement d'exécution utilitaire distinct, tel que l'un des éléments suivants :

nohup type writer
find . -type f | xargs type

il pourrait ne pas produire de résultats précis.

EXEMPLES

Aucun.

JUSTIFICATION

Aucune.

ORIENTATIONS FUTURES
