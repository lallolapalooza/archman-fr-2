typst-watch(1) Manuel des commandes générales typst-watch(1)

NOM

typst-watch - Surveille un fichier d'entrée et recompilie lors des changements

SYNTAXE

typst-watch [-f|--format] [--root] [--input] [--font-path] [--ignore-system-fonts] [--ignore-embedded-fonts] [--package-path] [--package-cache-path] [--creation-timestamp] [--pages] [--pdf-standard] [--no-pdf-tags] [--ppi] [--deps] [--deps-format] [-j|--jobs] [--features] [--diagnostic-format] [--open] [--timings] [--no-serve] [--no-reload] [--port] [-h|--help] <ENTREE> [SORTIE]

DESCRIPTION

Surveille un fichier d'entrée et recompilie lors des changements

OPTIONS

-f, --format=FORMAT
Le format du fichier de sortie, inféré de l'extension par défaut

[valeurs possibles : pdf, png, svg, html]

--root=DIR
Configure la racine du projet (pour les chemins absolus)
Peut également être spécifié via la variable d'environnement TYPST_ROOT.
--input=clé=valeur
Ajoute une paire clé-valeur de chaîne visible via `sys.inputs`
--font-path=DIR
Ajoute des répertoires supplémentaires qui sont recherchés de manière récursive pour les polices.

Si plusieurs chemins sont spécifiés, ils sont séparés par le séparateur de chemin du système (`:` sur les systèmes de type Unix et `;` sur Windows).

Peut également être spécifié via la variable d'environnement TYPST_FONT_PATHS.
--ignore-system-fonts
Garantit que les polices système ne seront pas recherchées, sauf si elles sont explicitement incluses via `--font-path`
Peut également être spécifié via la variable d'environnement TYPST_IGNORE_SYSTEM_FONTS.
--ignore-embedded-fonts
Garantit que les polices intégrées dans Typst ne seront pas prises en compte
Peut également être spécifié via la variable d'environnement TYPST_IGNORE_EMBEDDED_FONTS.
--package-path=DIR
Chemin personnalisé vers les paquets locaux, par défaut à l'emplacement dépendant du système
Peut également être spécifié via la variable d'environnement TYPST_PACKAGE_PATH.
--package-cache-path=DIR
Chemin personnalisé vers le cache des paquets, par défaut à l'emplacement dépendant du système
Peut également être spécifié via la variable d'environnement TYPST_PACKAGE_CACHE_PATH.
--creation-timestamp=TIMESTAMPSOURCE
La date de création du document formatée en timestamp UNIX.

Pour plus d'informations, voir https://reproducible-builds.org/specs/source-date-epoch/.

Peut également être spécifié via la variable d'environnement SOURCE_DATE_EPOCH.
--pages=PAGES
Quelles pages exporter. Non spécifié, toutes les pages sont exportées.

Les pages à exporter sont séparées par des virgules, et peuvent être soit des numéros de page simples (par exemple, '2,5' pour exporter uniquement les pages 2 et 5) soit des plages de pages (par exemple, '2,3-6,8-' pour exporter la page 2, les pages 3 à 6 (incluses), la page 8 et toutes les pages suivantes).

Les numéros de page sont basés sur 1 et correspondent aux numéros de page physiques dans le document (n'étant donc pas affectés par le compteur de pages du document).

--pdf-standard=STANDARD_PDF
Une (ou plusieurs normes PDF séparées par des virgules) que Typst appliquera en termes de conformité

Valeurs possibles :

  • 1.4: PDF 1.4
  • 1.5: PDF 1.5
  • 1.6: PDF 1.6
  • 1.7: PDF 1.7
  • 2.0: PDF 2.0
  • a-1b: PDF/A-1b
  • a-1a: PDF/A-1a
  • a-2b: PDF/A-2b
  • a-2u: PDF/A-2u
  • a-2a: PDF/A-2a
  • a-3b: PDF/A-3b
  • a-3u: PDF/A-3u
  • a-3a: PDF/A-3a
  • a-4: PDF/A-4
  • a-4f: PDF/A-4f
  • a-4e: PDF/A-4e
  • ua-1: PDF/UA-1
--no-pdf-tags
Par défaut, même lorsque le document n'est pas un document `PDF/UA-1`, un PDF balisé est généré pour offrir une accessibilité de base. Dans certaines circonstances (par exemple, lors de la tentative de réduire la taille d'un document), il peut être souhaitable de désactiver le PDF balisé
--ppi=PPP [défaut : 144]
Le PPI (pixels par pouce) à utiliser pour l'exportation PNG
--deps=CHEMIN
Chemin du fichier vers lequel une liste des dépendances de la compilation actuelle sera écrite. Utiliser `-` pour écrire sur stdout
--deps-format=FORMAT_DEPS [défaut : json]
Format de fichier à utiliser pour les dépendances

Valeurs possibles :

  • json: Encode en JSON, échoue pour les chemins non-Unicode
  • zero: Sépare les chemins par des octets NULL et peut exprimer tous les chemins
  • make: Produit au format Make, omet les chemins inexprimables
-j, --jobs=JOBS
Nombre de travaux parallèles lancés pendant la compilation. Par défaut, le nombre de CPU. Le régler à 1 désactive le parallélisme
--features=FONCTIONNALITÉS
Active les fonctionnalités en cours de développement qui peuvent être modifiées ou supprimées à tout moment

[valeurs possibles : html, a11y-extras]

Peut également être spécifié via la variable d'environnement TYPST_FEATURES.
--diagnostic-format=FORMAT_DIAGNOSTIC [défaut : human]
Le format dans lequel émettre les diagnostics

[valeurs possibles : human, short]

--open=VISIONNEUSE
Ouvre le fichier de sortie avec le visionneur par défaut ou un programme spécifique après la compilation. Ignoré si la sortie est stdout
--timings=SORTIE_JSON
Produit des temps de performance du processus de compilation. (expérimental)

Le fichier JSON résultant peut être chargé dans un outil de traçage tel que https://ui.perfetto.dev. Il ne contient aucune information sensible à part les noms de fichiers et les numéros de ligne.

--no-serve
Désactive le serveur HTTP intégré pour l'exportation HTML
--no-reload
Désactive le script de rechargement en direct injecté pour l'exportation HTML. Le HTML écrit sur le disque n'est affecté ni dans un sens ni dans l'autre
--port=PORT
Le port sur lequel le HTML est servi.

Par défaut, le premier port libre dans la plage 3000-3005.

-h, --help
Imprimer l'aide (voir un résumé avec '-h')
<ENTREE>
Chemin du fichier Typst d'entrée. Utiliser `-` pour lire l'entrée depuis stdin
[SORTIE]
Chemin du fichier de sortie (PDF, PNG, SVG ou HTML). Utiliser `-` pour écrire la sortie sur stdout.

Pour les formats de sortie qui génèrent un fichier par page (PNG & SVG), un modèle de numéro de page doit être présent si le document source rend plusieurs pages. Utiliser `{p}` pour les numéros de page, `{0p}` pour les numéros de page avec remplissage de zéros et `{t}` pour le nombre total de pages. Par exemple, `page-{0p}-of-{t}.png` crée `page-01-of-10.png`, `page-02-of-10.png`, etc.
