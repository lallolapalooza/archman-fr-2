NOM

tlmgr - le gestionnaire TeX Live natif

SYNTAXE

tlmgr [option...] action [option...] [opérande...]

DESCRIPTION

tlmgr gère une installation TeX Live existante, tant pour les paquets que pour les options de configuration. Pour des informations sur le téléchargement et l'installation initiale de TeX Live, voir https://tug.org/texlive/acquire.html.

La version la plus à jour de cette documentation (mise à jour quotidiennement à partir des sources de développement) est disponible à l'adresse https://tug.org/texlive/tlmgr.html, ainsi que des procédures pour mettre à jour "tlmgr" lui-même et des informations sur les versions de test.

TeX Live est organisé en quelques schémas de haut niveau, chacun étant spécifié comme un ensemble différent de collections et de paquets, où une collection est un ensemble de paquets, et un paquet est ce qui contient les fichiers réels. Les schémas contiennent généralement un mélange de collections et de paquets, mais chaque paquet est inclus dans exactement une collection, ni plus ni moins. Une installation TeX Live peut être personnalisée et gérée à n'importe quel niveau.

Voir https://tug.org/texlive/doc pour toute la documentation TeX Live disponible.

EXEMPLES

Après avoir installé TeX Live avec succès, voici quelques opérations courantes avec "tlmgr" :

"tlmgr option repository ctan"
"tlmgr option repository https://mirror.ctan.org/systems/texlive/tlnet"
Indiquer à "tlmgr" d'utiliser un miroir CTAN proche pour les futures mises à jour ; utile si vous avez installé TeX Live depuis l'image DVD et souhaitez avoir des mises à jour continues. Les deux commandes sont équivalentes ; "ctan" est juste un alias pour l'URL donnée.

Attention : "mirror.ctan.org" résout en de nombreux hôtes différents, et ils ne sont pas parfaitement synchronisés ; nous recommandons de ne mettre à jour que quotidiennement (au maximum), et pas plus souvent. Vous pouvez choisir un miroir particulier en cas de problèmes ; la liste de tous les miroirs CTAN avec l'état de chacun est disponible à l'adresse https://ctan.org/mirrors/mirmon.

"tlmgr update --list"
Afficher ce qui serait mis à jour sans rien mettre à jour réellement.
"tlmgr update --all"
Faire correspondre votre installation TeX locale à ce qui se trouve dans le dépôt de paquets (typiquement utile lors de la mise à jour depuis CTAN).
"tlmgr info" quoi
Afficher des informations détaillées sur un paquet quoi, comme le statut d'installation et la description, ou rechercher quoi dans tous les paquets.
"tlmgr bug" quoi
Afficher les informations disponibles pour signaler un bug pour quoi, un nom de paquet ou de fichier.

Pour toutes les capacités et tous les détails de "tlmgr", veuillez lire les informations volumineuses suivantes.

OPTIONS

Les options suivantes de "tlmgr" sont des options globales, non spécifiques à une action particulière. Toutes les options, qu'elles soient globales ou spécifiques à une action, peuvent être données n'importe où sur la ligne de commande, et dans n'importe quel ordre. Le premier argument non-option sera l'action principale. Dans tous les cas, "--"option et "-"option sont équivalents, et un "=" est facultatif entre un nom d'option et sa valeur.

--repository url|chemin
Spécifier le dépôt de paquets à partir duquel les paquets doivent être installés ou mis à jour, soit un répertoire local, soit un emplacement réseau, comme ci-dessous. Ceci remplace le dépôt de paquets par défaut trouvé dans la base de données des paquets TeX Live de l'installation (également connue sous le nom de TLPDB, qui est entièrement contenue dans le fichier "tlpkg/texlive.tlpdb").

Cette option "--repository" modifie l'emplacement uniquement pour l'exécution actuelle ; pour un changement permanent, utiliser "option repository" (voir l'action "option").

Par exemple, vous pouvez choisir un miroir CTAN particulier avec quelque chose comme ceci :

-repository http://ctan.example.org/its/ctan/dir/systems/texlive/tlnet

Bien sûr, un vrai nom d'hôte et son répertoire racine CTAN particulier doivent être spécifiés. La liste des miroirs CTAN est disponible à l'adresse https://ctan.org/mirrors/mirmon.

Voici un exemple d'utilisation d'un répertoire local :

-repository /chemin/local/vers/depot

Pour des raisons de compatibilité ascendante et de commodité, "--location" et "--repo" sont acceptés comme alias pour cette option.

Les emplacements peuvent être spécifiés comme suit :

"/chemin/local/quelconque"
"file:/chemin/local/quelconque"
Manières équivalentes de spécifier un répertoire local.
"ctan"
"https://mirror.ctan.org/systems/texlive/tlnet"
Choisir automatiquement un miroir CTAN, en essayant d'en trouver un qui soit à la fois proche et à jour. Le miroir choisi est utilisé pour le téléchargement entier. Le simple "ctan" n'est qu'un alias pour l'URL complète. (Voir https://ctan.org pour plus d'informations sur CTAN et ses miroirs.)
"http://serveur/chemin/vers/tlnet"
HTTP standard. Si la méthode LWP (par défaut) est utilisée, les connexions persistantes sont supportées. TL peut également utiliser "curl" ou "wget" pour effectuer les téléchargements, ou un programme arbitraire spécifié par l'utilisateur, comme décrit dans la documentation de "tlmgr" (https://tug.org/texlive/doc/tlmgr.html#ENVIRONMENT-VARIABLES).
"https://serveur/chemin/vers/tlnet"
Encore une fois, si la méthode LWP (par défaut) est utilisée, cela prend en charge les connexions persistantes. Malheureusement, certaines versions de "wget" et "curl" ne prennent pas en charge https, et même lorsque "wget" prend en charge https, les certificats peuvent être rejetés même s'ils sont valides, en raison d'un manque de certificats racines locaux. La solution la plus simple à ce problème est d'utiliser http ou ftp.
"ftp://serveur/chemin/vers/tlnet"
Si la méthode LWP (par défaut) est utilisée, les connexions persistantes sont supportées.
"utilisateur@machine:/chemin/vers/tlnet"
"scp://utilisateur@machine/chemin/vers/tlnet"
"ssh://utilisateur@machine/chemin/vers/tlnet"
Ces formes sont équivalentes ; elles utilisent toutes "scp" pour transférer des fichiers. L'utilisation de "ssh-agent" est recommandée. (Info: https://fr.wikipedia.org/wiki/OpenSSH, https://fr.wikipedia.org/wiki/Ssh-agent.)

Si le dépôt se trouve sur le réseau, les caractères "/" finaux et/ou les composants finaux "/tlpkg" et/ou "/archive" sont ignorés.

--command-logfile fichier
"tlmgr" enregistre la sortie de tous les programmes invoqués (mktexlr, mtxrun, fmtutil, updmap) dans un fichier journal séparé, par défaut "TEXMFSYSVAR/web2c/tlmgr-commands.log". Cette option vous permet de spécifier un fichier différent pour le journal.
--debug-translation
En mode GUI, ce commutateur indique à "tlmgr" de signaler tous les messages non traduits (ou manquants) sur la sortie standard. Cela peut aider les traducteurs à voir ce qu'il reste à faire.
--machine-readable
Au lieu de la sortie normale destinée à la consommation humaine, écrire (sur la sortie standard) un format fixe plus adapté à l'analyse par machine. Voir la section "SORTIE LISIBLE PAR MACHINE" ci-dessous.
--no-execute-actions
Supprimer l'exécution des actions d'exécution telles que définies dans les fichiers tlpsrc. Sauf si vous effectuez vous-même le post-traitement (comme le fait par exemple "install-tl"), cela ne devrait pas être spécifié. Sinon, les fichiers de formatage et la base de données des noms de fichiers deviendront obsolètes, parmi d'autres problèmes.
--package-logfile fichier
"tlmgr" enregistre toutes les actions de paquet (installation, suppression, mise à jour, mises à jour échouées, restaurations échouées) dans un fichier journal séparé, par défaut "TEXMFSYSVAR/web2c/tlmgr.log". Cette option vous permet de spécifier un fichier différent pour le journal.
--pause
Cette option fait que "tlmgr" attend l'entrée de l'utilisateur avant de quitter. Utile sous Windows pour éviter la disparition des fenêtres de commande.
--persistent-downloads
--no-persistent-downloads
Pour les installations basées sur le réseau, cette option (activée par défaut) fait que "tlmgr" essaie d'établir une connexion persistante (en utilisant le module Perl "LWP"). L'idée est d'ouvrir et de réutiliser une seule connexion par session entre votre ordinateur et le serveur, au lieu d'initier un nouveau téléchargement pour chaque paquet.

Si cela n'est pas possible, "tlmgr" utilisera "wget". Pour désactiver ces connexions persistantes, utilisez "--no-persistent-downloads".

--pin-file
Change l'emplacement du fichier d'épinglage de "TEXMFLOCAL/tlpkg/pinning.txt" (voir "Épinglage" ci-dessous). Documenté uniquement par souci d'exhaustivité, car ceci n'est utile que pour le débogage.
--usermode
Active le mode utilisateur pour cette exécution de "tlmgr" ; voir "MODE UTILISATEUR" ci-dessous.
--usertree dir
Utilise dir pour l'arbre en mode utilisateur ; voir "MODE UTILISATEUR" ci-dessous.
--verify-repo=[none|main|all]
Définit le niveau de vérification effectué : Si "none" est spécifié, aucune vérification n'est effectuée. Si "main" est donné et qu'un binaire GnuPG fonctionnel ("gpg") est disponible, tous les dépôts sont vérifiés, mais seul le dépôt principal est requis pour être signé. Si "all" est donné, alors tous les dépôts doivent être signés. Voir "VÉRIFICATION CRYPTOGRAPHIQUE" ci-dessous pour plus de détails.

Les options standard des programmes TeX Live sont également acceptées : "--help/-h/-?", "--version", "-q" (pas de messages d'information), "-v" (messages de débogage, peut être répété). Pour plus de détails à leur sujet, voir la documentation de "TeXLive::TLUtils".

L'option "--version" affiche les informations de version sur la version de TeX Live et sur le script "tlmgr" lui-même. Si "-v" est également donné, les numéros de révision des modules Perl TeX Live chargés sont également affichés.

ACTIONS

help

Affiche ces informations d'aide et quitte (identique à "--help", et sur le web à https://tug.org/texlive/doc/tlmgr.html). Parfois, les programmes "perldoc" et/ou "PAGER" du système ont des problèmes, ce qui entraîne la sortie littérale de caractères de contrôle. Cela ne peut pas toujours être détecté, mais vous pouvez définir la variable d'environnement "NOPERLDOC" et "perldoc" ne sera pas utilisé.

version

Donne des informations sur la version (identique à "--version").

Si "-v" a été donné, les révisions des modules utilisés sont également signalées.

backup

backup [option...] --all
backup [option...] pkg...
Si l'option "--clean" n'est pas spécifiée, cette action sauvegarde les paquets donnés, ou tous les paquets spécifiés par "--all". Ces sauvegardes sont enregistrées dans la valeur de l'option "--backupdir", si ce répertoire existe et est accessible en écriture. Si "--backupdir" n'est pas donné, le réglage de l'option "backupdir" dans la TLPDB est utilisé, s'il est présent. Si les deux sont manquants, aucune sauvegarde n'est effectuée. (L'installeur définit "backupdir" à ".../tlpkg/backups", sous le répertoire d'installation racine de TL, donc il est généralement défini ; voir la description de l'option "option" pour plus d'informations.)

Si l'option "--clean" est spécifiée, les sauvegardes sont élaguées (supprimées) au lieu d'être enregistrées. La valeur entière facultative N peut être spécifiée pour définir le nombre de sauvegardes qui seront conservées lors de l'élagage. Si "N" n'est pas donné, la valeur de l'option "autobackup" est utilisée. Si les deux sont manquants, une erreur est signalée. Pour plus de détails sur l'élagage des sauvegardes, voir l'action "option".

Options :

--backupdir répertoire
Remplace le réglage de l'option "backupdir" dans la TLPDB. L'argument répertoire est requis et doit spécifier un répertoire existant et accessible en écriture où les sauvegardes doivent être placées.
--all
Si "--clean" n'est pas spécifié, effectue une sauvegarde de tous les paquets dans l'installation TeX Live ; cela prendra beaucoup d'espace et de temps. Si "--clean" est spécifié, tous les paquets sont élagués.
--clean[=N]
Au lieu de faire des sauvegardes, élague le répertoire de sauvegarde des anciennes sauvegardes, comme expliqué ci-dessus. L'argument entier facultatif N remplace l'option "autobackup" définie dans la TLPDB. Vous devez utiliser "--all" ou une liste de paquets ensemble avec cette option, selon vos besoins.
--dry-run
Rien n'est réellement sauvegardé ou supprimé ; au lieu de cela, les actions à effectuer sont écrites sur le terminal.

bug [chaîne-de-recherche]

Recherche la chaîne-de-recherche (demandée si non fournie) comme nom de paquet et dans les descriptions de paquets, comme mots entiers, et dans les noms de fichiers, comme n'importe quelle sous-chaîne, et affiche des informations sur le signalement de bugs et d'autres informations pour le paquet sélectionné parmi les résultats.

La recherche est équivalente à "tlmgr search --word --file" chaîne-de-recherche. Ainsi, chaîne-de-recherche est interprétée comme une expression régulière (Perl).

candidates pkg

Affiche les dépôts candidats disponibles pour le paquet pkg. Voir "DÉPÔTS MULTIPLES" ci-dessous.

check [option...] [depends|executes|files|runfiles|texmfdbs|all]

Exécute une (ou toutes les) vérification(s) de la cohérence de l'installation. Si aucun problème n'est trouvé, il n'y aura aucune sortie. (Pour voir ce qui est fait, lancez "tlmgr -v check".)

depends
Liste les paquets qui apparaissent comme dépendances dans une collection installée, mais qui ne sont pas eux-mêmes installés, ainsi que les paquets qui ne sont contenus dans aucune collection.

Si vous appelez "tlmgr check collections", ce test sera effectué à la place, car les versions précédentes de "tlmgr" l'appelaient ainsi.

executes
Vérifie que les fichiers référencés par les directives "execute" dans la base de données TeX Live sont présents.
files
Vérifie que tous les fichiers listés dans la TLPDB locale ("texlive.tlpdb") sont effectivement présents, et liste ceux qui manquent.
runfiles
Liste les noms de fichiers qui apparaissent plus d'une fois dans les sections runfiles, à l'exception des doublons connus.
texmfdbs
Vérifications relatives aux fichiers "ls-R". Si vous avez défini de nouveaux arbres, ou modifié les variables "TEXMF" ou "TEXMFDBS", il est utile d'exécuter cette commande. Elle vérifie que :
- tous les éléments dans "TEXMFDBS" ont le préfixe "!!".
- tous les éléments dans "TEXMFBDS" ont un fichier "ls-R" (s'ils existent).
- tous les éléments dans "TEXMF" avec "!!" sont listés dans "TEXMFDBS".
- tous les éléments dans "TEXMF" avec un fichier "ls-R" sont listés dans "TEXMFDBS".

Options :

--use-svn
Utilise la sortie de "svn status" au lieu de lister les fichiers ; pour vérifier le dépôt de développement TL. (Ceci est exécuté tous les soirs.)

conf

conf [texmf|tlmgr|updmap [--conffile fichier] [--delete] [clé [valeur]]]
conf auxtrees [--conffile fichier] [show|add|remove] [valeur]
Avec seulement "conf", affiche les informations générales de configuration pour TeX Live, y compris les fichiers de configuration actifs, les paramètres de chemin, et plus encore. Ceci est équivalent à exécuter "texconfig conf", mais fonctionne sur toutes les plateformes supportées.

Avec l'une des options "conf texmf", "conf tlmgr", ou "conf updmap", affiche toutes les paires clé/valeur (c'est-à-dire tous les paramètres) telles qu'elles sont enregistrées dans "ROOT/texmf.cnf", le fichier de configuration utilisateur "tlmgr" (voir ci-dessous), ou le premier fichier "updmap.cfg" trouvé (via "kpsewhich"), respectivement.

Si clé est fournie en plus, affiche uniquement la valeur de cette clé dans le fichier respectif. Si l'option --delete est également fournie, la valeur dans le fichier de configuration donné est entièrement supprimée (pas seulement commentée).

Si valeur est fournie en plus, la clé est définie à valeur dans le fichier respectif. Aucune vérification d'erreur n'est effectuée !

La valeur "PATH" affichée par "conf" est celle utilisée par "tlmgr". Le répertoire dans lequel l'exécutable "tlmgr" est trouvé est automatiquement ajouté au début de la valeur PATH héritée de l'environnement.

Voici un exemple pratique de modification des valeurs de configuration. Si l'exécution de (certaines ou toutes les) commandes système via "\write18" a été laissée activée pendant l'installation, vous pouvez la désactiver ensuite :

tlmgr conf texmf shell_escape 0

La sous-commande "auxtrees" permet d'ajouter et de supprimer des arbres texmf supplémentaires arbitraires, entièrement sous le contrôle de l'utilisateur. "auxtrees show" affiche la liste des arbres supplémentaires, "auxtrees add" arbre ajoute un arbre à la liste, et "auxtrees remove" arbre supprime un arbre de la liste (s'il est présent). Les arbres ne doivent pas contenir de fichier "ls-R" (sinon les fichiers ne seront pas trouvés si le "ls-R" devient obsolète). Cela fonctionne en manipulant la variable Kpathsea "TEXMFAUXTREES", dans (par défaut) "ROOT/texmf.cnf". Exemple :

tlmgr conf auxtrees add /quick/test/tree
tlmgr conf auxtrees remove /quick/test/tree

Dans tous les cas, le fichier de configuration peut être explicitement spécifié via l'option "--conffile" fichier, par exemple si vous ne souhaitez pas modifier la configuration système.

Attention : La facilité générale de modification des valeurs de configuration est ici, mais il est fortement déconseillé de modifier les paramètres de cette manière. Encore une fois, aucune vérification d'erreur sur les clés ou les valeurs n'est effectuée, donc toute sorte de dysfonctionnement est possible.

dump-tlpdb [option...] [--json]

Extrait la TLPDB locale ou distante complète vers la sortie standard, telle quelle. La sortie est analogue à la sortie "--machine-readable" ; voir la section "SORTIE LISIBLE PAR MACHINE".

Options :

--local
Extrait la TLPDB locale.
--remote
Extrait la TLPDB distante.
--json
Au lieu d'extraire le contenu réel, la base de données est extraite en JSON. Pour le format de sortie JSON, voir "tlpkg/doc/json-formats.txt", définition de format "TLPDB".

Exactement une des options "--local" et "--remote" doit être fournie.

Dans tous les cas, la première ligne de la sortie spécifie l'emplacement du dépôt, dans ce format :

"location-url" "\t" location

où "location-url" est le nom littéral du champ, suivi d'une tabulation, et location est le fichier ou l'URL du dépôt.

Les fins de ligne peuvent être LF ou CRLF selon la plateforme actuelle.

generate

generate [option...] language
generate [option...] language.dat
generate [option...] language.def
generate [option...] language.dat.lua

L'action "generate" écrase toute modification manuelle apportée aux fichiers respectifs : elle les recrée à partir de zéro en se basant sur les informations des paquets installés, plus les adaptations locales. L'installateur TeX Live et "tlmgr" appellent régulièrement "generate" pour tous ces fichiers.

Pour gérer vos propres polices, veuillez lire les informations de "updmap --help" et/ou https://tug.org/fonts/fontinstall.html.

Pour gérer vos propres formats, veuillez lire les informations de "fmtutil --help".

Plus en détail : "generate" recrée l'un des fichiers de configuration "language.dat", "language.def", et "language.dat.lua" à partir des informations présentes dans la TLPDB locale, plus les fichiers maintenus localement.

Les fichiers maintenus localement sont "language-local.dat", "language-local.def", ou "language-local.dat.lua", recherchés dans "TEXMFLOCAL" dans les répertoires respectifs. Si des ajouts locaux sont présents, le fichier final est créé en commençant par le fichier principal, en omettant toute entrée que le fichier local spécifie de désactiver, et en ajoutant enfin le fichier local.

(Note historique : les fichiers précédemment supportés "updmap-local.cfg" et "fmtutil-local.cnf" ne sont plus lus, car "updmap" et "fmtutil" lisent et supportent maintenant plusieurs fichiers de configuration. Ainsi, les ajouts locaux peuvent et doivent être placés dans un fichier "updmap.cfg" ou "fmtutil.cnf" dans "TEXMFLOCAL". Les actions "generate updmap" et "generate fmtutil" n'existent plus.)

Les fichiers locaux spécifient les entrées à désactiver avec une ligne de commentaire, à savoir l'une des suivantes :

%!NAME
--!NAME

où "language.dat" et

ass="Li">"langue.def" utilise "%", et "langue.dat.lua" utilise "--". Dans tous les cas, le nom est le nom de format ou l'identificateur de modèle de césure respectif. Exemples :

%!german
--!usenglishmax

(Bien sûr, il est peu probable que vous souhaitiez réellement désactiver ces éléments particuliers. Ce ne sont que des exemples.)

Après une telle ligne de désactivation, le fichier local peut inclure une autre entrée pour le même élément, si une définition différente est souhaitée. En général, à l'exception des lignes de désactivation spéciales, les fichiers locaux suivent la même syntaxe que les fichiers maîtres.

La forme "générer langue" recrée les trois fichiers "langue.dat", "langue.def" et "langue.dat.lua", tandis que les formes avec une extension recréent uniquement le fichier de langue donné.

Options :

--dest fichier_sortie
spécifie le fichier de sortie (par défaut, l'emplacement respectif dans "TEXMFSYSVAR"). Si "--dest" est donné à "générer langue", il sert de nom de base auquel ".dat" sera ajouté pour le nom du fichier de sortie "langue.dat", ".def" sera ajouté à la valeur pour le nom du fichier de sortie "langue.def", et ".dat.lua" au nom du fichier "langue.dat.lua". (Ceci est juste pour éviter d'écraser ; si vous souhaitez un nom spécifique pour chaque fichier de sortie, nous recommandons d'appeler "tlmgr" deux fois.)
--localcfg fichier_conf_local
spécifie les ajouts locaux (optionnels) (par défaut, l'emplacement respectif dans "TEXMFLOCAL").
--rebuild-sys
indique à "tlmgr" d'exécuter les programmes nécessaires après la régénération des fichiers de configuration. Ceux-ci sont : "fmtutil-sys --all" après "générer fmtutil", "fmtutil-sys --byhyphen .../langue.dat" après "générer langue.dat", et "fmtutil-sys --byhyphen .../langue.def" après "générer langue.def".

Ces appels subséquents font que les fichiers nouvellement générés prennent réellement effet. Ceci n'est pas fait par défaut car ces appels sont des processus longs et on pourrait vouloir apporter plusieurs modifications connexes successivement avant d'appeler ces programmes.

Les emplacements respectifs sont les suivants :

tex/generic/config/language.dat (et language-local.dat)
tex/generic/config/language.def (et language-local.def)
tex/generic/config/language.dat.lua (et language-local.dat.lua)

interface graphique

Lance l'interface utilisateur graphique. Voir **GUI** ci-dessous.

info

info [option...] paquet...
info [option...] collections
info [option...] schémas
Sans argument, liste tous les paquets disponibles au dépôt de paquets, précédant ceux déjà installés par "i".

Avec le mot unique "collections" ou "schémas" comme argument, liste le type de requête au lieu de tous les paquets.

Avec tout autre argument, affiche des informations sur paquet : le nom, la catégorie, la description courte et longue, les tailles, le statut d'installation et le numéro de révision TeX Live. Si paquet n'est pas installé localement, recherche dans la source d'installation distante.

Pour les paquets normaux (pas les collections ou les schémas), les tailles des quatre groupes de fichiers (exécutables/sources/documentation/binaires) sont affichées séparément. Pour les collections, la taille cumulée est affichée, incluant tous les paquets directement dépendants (mais pas les collections dépendantes). Pour les schémas, la taille cumulée est également affichée, incluant toutes les collections et tous les paquets directement dépendants.

Si paquet n'est pas trouvé localement ou à distance, l'action de recherche est utilisée et liste les paquets et fichiers correspondants.

Elle affiche également des informations provenant du Catalogue TeX, à savoir la version du paquet, la date et la licence. Considérez ces éléments, en particulier la version du paquet, comme des approximations seulement, en raison du décalage temporel des mises à jour des différentes pièces. En revanche, la valeur "révision" provient directement de TL et est fiable.

Les actions précédentes "show" et "list" sont fusionnées dans cette action, mais sont toujours supportées pour des raisons de compatibilité descendante.

Options :

--list
Si l'option "--list" est donnée avec un paquet, la liste des fichiers contenus est également affichée, y compris ceux des dépendances spécifiques à la plateforme. Lorsqu'elle est donnée avec des schémas et des collections, "--list" affiche leurs dépendances de manière similaire.
--only-files
Si cette option est donnée, seuls les fichiers d'un paquet donné sont listés, sans plus d'informations. Si plus d'un nom de paquet est donné, chaque liste de fichiers est précédée du nom du paquet.
--only-installed
Si cette option est donnée, la source d'installation ne sera pas utilisée ; seuls les paquets, collections ou schémas installés localement sont listés.
--only-remote
Liste uniquement les paquets du dépôt distant. Utile pour vérifier ce qui est disponible dans un dépôt distant en utilisant "tlmgr --repo ... --only-remote info". Notez que "--only-installed" et "--only-remote" ne peuvent pas être spécifiés simultanément.
--data "élément1,élément2,..."
Si l'option "--data" est donnée, son argument doit être une liste de noms de champs séparés par des virgules ou des deux-points parmi : "name", "category", "localrev", "remoterev", "shortdesc", "longdesc", "installed", "size", "relocatable", "depends", "cat-version", "cat-date", "cat-license", plus divers champs "cat-contact-*" (voir ci-dessous).

Les champs "cat-*" proviennent tous du Catalogue TeX (https://ctan.org/pkg/catalogue). Pour chacun, il existe deux variantes supplémentaires avec le préfixe "l" et "r", par exemple "lcat-version" et "rcat-version", qui indiquent respectivement les informations locales et distantes. Les variantes sans "l" et "r" montrent la plus actuelle, qui est normalement la valeur distante.

Les informations des paquets demandés sont listées au format CSV, un paquet par ligne, et les informations des colonnes sont données par les "itemN". La colonne "depends" contient les noms de toutes les dépendances séparés par des caractères ":".

À l'heure actuelle, les champs "cat-contact-*" incluent : "home", "repository", "support", "bugs", "announce", "development". Chacun peut être vide ou contenir une URL. Une brève description se trouve sur la page d'upload CTAN pour les nouveaux paquets : https://ctan.org/upload.

--json
Si "--json" est spécifié, la sortie est un tableau encodé en JSON où chaque élément du tableau est la représentation JSON d'un seul "TLPOBJ" mais avec des informations supplémentaires. Pour plus de détails, voir "tlpkg/doc/json-formats.txt", définition du format : "TLPOBJINFO". Si "--json" et "--data" sont tous deux donnés, "--json" a la priorité.

init-usertree

Configure un arbre texmf pour la gestion dite en mode utilisateur, soit l'arbre utilisateur par défaut ("TEXMFHOME"), soit celui spécifié sur la ligne de commande avec "--usertree". Voir « MODE UTILISATEUR » ci-dessous.

installer [option...] paquet...

Installe chaque paquet donné sur la ligne de commande, s'il n'est pas déjà installé. Il ne touche pas aux paquets existants ; voir l'action "mettre à jour" pour savoir comment obtenir la dernière version d'un paquet.

Par défaut, cela installe également tous les paquets dont les paquets donnés sont dépendants. Options :

--dry-run
Aucune installation réelle n'est effectuée ; au lieu de cela, les actions à réaliser sont écrites dans le terminal.
--file
Au lieu de télécharger un paquet depuis le dépôt d'installation, utilisez les fichiers de paquet fournis sur la ligne de commande. Ces fichiers doivent être des fichiers de paquet TeX Live standards (avec un fichier tlpobj inclus).
--force
Si des mises à jour de "tlmgr" lui-même (ou d'autres parties de l'infrastructure de base) sont présentes, "tlmgr" abandonnera et n'effectuera pas l'installation, sauf si cette option est fournie. Non recommandé.
--no-depends
N'installez pas les dépendances. (Par défaut, l'installation d'un paquet garantit que toutes les dépendances de ce paquet sont satisfaites.)
--no-depends-at-all
Normalement, lorsque vous installez un paquet qui contient des fichiers binaires, le paquet binaire correspondant sera également installé. C'est-à-dire, pour un paquet "foo", le paquet "foo.i386-linux" sera également installé sur un système "i386-linux". Cette option supprime ce comportement et implique également "--no-depends". Ne l'utilisez pas à moins d'être sûr de ce que vous faites.
--reinstall
Réinstallez un paquet (y compris les dépendances pour les collections) même s'il semble déjà installé (c'est-à-dire, s'il est présent dans la TLPDB). Ceci est utile pour récupérer de la suppression accidentelle de fichiers dans la hiérarchie.

Lors de la réinstallation, seules les dépendances sur les paquets normaux sont suivies (c'est-à-dire, pas celles de catégorie Scheme ou Collection).

--with-doc
--with-src
Bien que non recommandé, le programme "install-tl" offre une option pour omettre l'installation de toute la documentation et/ou des fichiers sources. (Par défaut, tout est installé.) Après une telle installation, vous pourriez trouver que vous désirez finalement la documentation ou les fichiers sources pour un paquet donné. Vous pouvez les obtenir en utilisant ces options conjointement avec "--reinstall", comme dans (en utilisant le paquet "fontspec" comme exemple) : 
tlmgr install --reinstall --with-doc --with-src fontspec

Cette action n'ajoute pas automatiquement de nouveaux liens symboliques dans les répertoires système ; vous devez exécuter vous-même "tlmgr path add" ("path") si vous utilisez cette fonctionnalité et souhaitez que de nouveaux liens symboliques soient ajoutés.

key

key list
key add file
key remove keyid
L'action "key" permet de lister, d'ajouter et de supprimer des clés GPG supplémentaires à l'ensemble des clés approuvées, c'est-à-dire celles utilisées pour vérifier les bases de données TeX Live.

Avec l'argument "list", "key" liste toutes les clés.

L'argument "add" nécessite un autre argument, soit un nom de fichier, soit "-" pour stdin, à partir duquel la clé est ajoutée. La clé est ajoutée à la trousse de clés locale "GNUPGHOME/repository-keys.gpg", qui est normalement "tlpkg/gpg/repository-keys.gpg".

L'argument "remove" nécessite un identifiant de clé et supprime l'identifiant demandé de la trousse de clés locale.

list

Synonyme de "info".

option

option [--json] [show]
option [--json] showall|help
option key [value]

La première forme, "show", affiche les paramètres globaux de TeX Live actuellement enregistrés dans la TLPDB avec une courte description et la "key" utilisée pour la modifier entre parenthèses.

La deuxième forme, "showall", est similaire, mais affiche également les options qui peuvent être définies mais qui n'ont actuellement aucune valeur ("help" est un synonyme).

Les deux formes "show..." acceptent une option "--json", qui exporte les informations d'option au format JSON. Dans ce cas, les deux formes exportent les mêmes données. Pour le format de la sortie JSON, consultez "tlpkg/doc/json-formats.txt", définition de format "TLOPTION".

Dans la troisième forme, avec key, si value n'est pas fourni, le réglage pour key est affiché. Si value est présent, key est défini à value.

Les valeurs possibles pour key sont (exécutez "tlmgr option showall" pour la liste définitive) :

repository (dépôt de paquets par défaut),
formats    (générer les formats lors de l'installation ou de la mise à jour),
postcode   (exécuter les codes post-installation)
docfiles   (installer les fichiers de documentation),
srcfiles   (installer les fichiers sources),
backupdir  (répertoire par défaut pour les sauvegardes),
autobackup (nombre de sauvegardes à conserver).
sys_bin    (répertoire vers lequel les exécutables sont liés par l'action path)
sys_man    (répertoire vers lequel les pages de manuel sont liées par l'action path)
sys_info   (répertoire vers lequel les fichiers Info sont liés par l'action path)
desktop_integration (Windows uniquement : créer des raccourcis dans le menu Démarrer)
fileassocs (Windows uniquement : modifier les associations de fichiers)
multiuser  (Windows uniquement : installer pour tous les utilisateurs)

Une utilisation courante de "option" est de changer définitivement l'installation pour obtenir des mises à jour supplémentaires via Internet, après une installation initiale depuis un DVD. Pour ce faire, vous pouvez exécuter

tlmgr option repository https://mirror.ctan.org/systems/texlive/tlnet

La documentation de "install-tl" contient plus d'informations sur les valeurs possibles pour "repository". (Pour des raisons de compatibilité ascendante, "location" peut être utilisé comme synonyme de "repository".)

Si "formats" est défini (ce qui est par défaut), alors les formats sont régénérés lorsque le moteur ou les fichiers de format ont changé. Désactivez cela uniquement lorsque vous savez comment et que vous souhaitez régénérer les formats vous-même chaque fois que nécessaire (ce qui est souvent, en pratique).

L'option "postcode" contrôle l'exécution des actions post-installation par paquet. Elle est activée par défaut, et désactiver cela n'est probablement pas d'intérêt sauf pour les développeurs effectuant du débogage.

Les options "docfiles" et "srcfiles" contrôlent l'installation de leurs groupes de fichiers respectifs (documentation, sources ; le regroupement est approximatif) par paquet. Par défaut, les deux sont activés (1). L'un ou l'autre ou les deux peuvent être désactivés (réglés à 0) si l'espace disque est limité ou pour des installations minimales de test, etc. Lorsque désactivés, les fichiers respectifs ne sont pas téléchargés du tout.

Les options "autobackup" et "backupdir" déterminent les valeurs par défaut pour les actions "update", "backup" et "restore". Ces trois actions nécessitent un répertoire dans lequel lire ou écrire les sauvegardes. Si "--backupdir" n'est pas spécifié sur la ligne de commande, la valeur de l'option "backupdir" est utilisée (si elle est définie). L'installateur TL définit "backupdir" à ".../tlpkg/backups", sous le répertoire d'installation racine de TL.

L'option "autobackup" (dés)active la génération automatique de sauvegardes. Sa valeur est un entier. Si la valeur "autobackup" est -1, aucune sauvegarde n'est supprimée. Si "autobackup" est 0 ou plus, elle spécifie le nombre de sauvegardes à conserver. Ainsi, les sauvegardes sont désactivées si la valeur est 0. En mode "--clean" de l'action "backup", cette option spécifie également le nombre à conserver. La valeur par défaut est 1, de sorte que des sauvegardes soient effectuées, mais une seule sauvegarde est conservée.

Pour configurer "autobackup" à -1 sur la ligne de commande, utilisez :

tlmgr option -- autobackup -1

Le "--" évite que le -1 ne soit traité comme une option. (Le "--" arrête l'analyse des options au point où il apparaît ; c'est une fonctionnalité générale commune à la plupart des programmes Unix.)

Les options "sys_bin", "sys_man", et "sys_info" sont utilisées sur les systèmes Unix pour contrôler la génération de liens pour les exécutables, les fichiers Info et les pages de manuel. Voir l'action "path" pour plus de détails.

Les trois dernières options affectent le comportement sur les installations Windows. Si "desktop_integration" est activé, alors certains paquets installeront des éléments dans un sous-dossier du menu Démarrer pour "tlmgr gui", la documentation, etc. Si "fileassocs" est activé, les associations de fichiers Windows sont créées (voir également l'action "postaction"). Enfin, si "multiuser" est activé, alors les modifications du registre et des menus sont effectuées pour tous les utilisateurs du système au lieu de seulement l'utilisateur actuel. Ces trois options sont activées par défaut.

paper

paper [a4|letter]
<[xdvi|pdftex|dvips|dvipdfmx|context|psutils] paper [papersize|--list]>
paper --json

Sans arguments ("tlmgr paper"), affiche le paramètre de taille de papier par défaut pour tous les programmes connus.

Avec un argument (par exemple, "tlmgr paper a4"), définit le défaut pour tous les programmes connus à cette taille de papier.

Avec un programme donné comme premier argument et aucune taille de papier spécifiée (par exemple, "tlmgr dvips paper"), affiche la taille de papier par défaut pour ce programme.

Avec un programme donné comme premier argument et une taille de papier comme dernier argument (par exemple, "tlmgr dvips paper a4"), définit le défaut pour ce programme à cette taille de papier.

Si "pdftex" ou "context" est l'un des arguments, que ce soit implicitement ou explicitement, les formats existants sont reconstruits (c'est-à-dire que "fmtutil --refresh" est appelé), à moins que "--no-execute-actions" ne soit spécifié.

Avec un programme donné comme premier argument et "--list" comme dernier argument (par exemple, "tlmgr dvips paper --list"), affiche toutes les tailles de papier valides pour ce programme. La première taille affichée est le défaut.

Si "--json" est spécifié sans autres options, la configuration du papier est déchargée au format JSON. Pour le format de sortie JSON, voir "tlpkg/doc/json-formats.txt", définition de format "TLPAPER".

Soit dit en passant, cette syntaxe consistant à avoir un nom de programme spécifique avant le mot-clé "paper" est inhabituelle. Elle est héritée du script de longue date "texconfig", qui prend en charge d'autres paramètres de configuration pour certains programmes, notamment "dvips". "tlmgr" ne prend pas en charge ces paramètres supplémentaires.

chemin

path [--windowsmode=user|admin] add

Sur Unix, ajoute ou supprime des liens symboliques pour les exécutables, les pages de manuel et les pages d'information dans les répertoires système spécifiés par les options respectives (voir la description de « option » ci-dessus). Ne modifie aucun fichier d'initialisation, ni système ni personnel. De plus, les exécutables ajoutés ou supprimés par les mises à jour futures ne sont pas pris en charge automatiquement ; cette commande doit être réexécutée si nécessaire.

Sous Windows, la partie du registre où le répertoire binaire est ajouté ou supprimé est déterminée comme suit :

Si l'utilisateur a des droits d'administrateur et que l'option "--windowsmode" n'est pas donnée, le paramètre w32_multi_user détermine l'emplacement (c'est-à-dire que si elle est activée, le chemin système, sinon le chemin utilisateur est modifié).

Si l'utilisateur a des droits d'administrateur et que l'option "--windowsmode" est donnée, cette option détermine le chemin à ajuster.

Si l'utilisateur n'a pas de droits d'administrateur et que l'option "--windowsmode" n'est pas donnée et que le paramètre w32_multi_user est désactivé, le chemin utilisateur est modifié, tandis que si le paramètre w32_multi_user est activé, un avertissement est émis indiquant que l'appelant n'a pas les privilèges suffisants.

Si un utilisateur sans droits d'administrateur utilise l'option "--windowsmode admin", un avertissement est émis indiquant que l'appelant n'a pas les privilèges suffisants.

Supprime chaque pkg spécifié. --all
Désinstalle tout TeX Live, en demandant confirmation sauf si "--force" est également spécifié.
--backup
--backupdir directory
Ces options se comportent exactement comme avec l'action update (voir ci-dessus), sauf qu'elles s'appliquent à la création de sauvegardes des paquets avant leur suppression. Le défaut est de créer une telle sauvegarde, c'est-à-dire de sauvegarder une copie des paquets avant leur suppression.

L'action « restore » explique comment restaurer à partir d'une sauvegarde.

--no-depends
Ne pas supprimer les paquets dépendants.
--no-depends-at-all
Voir ci-dessus sous install (et soyez prudent).

repository list
repository list path|url|tag
repository add path [tag]
repository remove path|tag
repository set path[#tag] [path[#tag] ...]
repository status
Cette action gère la liste des dépôts. Voir MULTIPLE REPOSITORIES ci-dessous pour des explications détaillées.

La première forme, "repository list", liste tous les dépôts configurés et les étiquettes respectives si elles sont définies. Si un chemin, une URL ou une étiquette est donné après le mot-clé "list", il est interprété comme la source à partir de laquelle initialiser une base de données TL et liste les paquets contenus. Il peut également s'agir d'un dépôt autrement inutilisé, local ou distant. Si l'option "--with-platforms" est spécifiée en plus, pour chaque paquet les plates-formes disponibles (le cas échéant) sont également listées.

La forme "repository status" rapporte l'état de vérification des dépôts chargés avec le format d'un dépôt par ligne avec des champs séparés par un seul espace :

L'étiquette (qui peut être la même que l'URL) ;
= l'URL ;

= si une sortie lisible par machine est spécifiée, le code de vérification (un nombre) ;

= une description textuelle de l'état de vérification, comme dernier champ s'étendant jusqu'à la fin de la ligne.

C'est-à-dire, en sortie normale (non lisible par machine), le troisième champ (état de vérification numérique) n'est pas présent.

Dans tous les cas, l'un des dépôts doit être étiqueté comme "main" ; sinon, toutes les opérations échoueront !

restore

restore [option...] pkg [rev]
restore [option...] --all
Restaure un paquet à partir d'une sauvegarde précédemment effectuée.

Lors de la liste des paquets disponibles, "tlmgr" affiche la révision, et entre parenthèses l'heure de création si disponible (au format yyyy-mm-dd hh:mm).

Si (et seulement si) pkg et un numéro de révision valide rev sont spécifiés, tente de restaurer le paquet à partir de la sauvegarde spécifiée.

--backupdir répertoire
Spécifie le répertoire où les sauvegardes doivent être trouvées. Si non donné, il sera pris du paramètre de configuration dans le TLPDB.

Rien n'est réellement restauré ; au lieu de cela, les actions à effectuer sont écrites dans le terminal.
--force
Ne pose pas de questions.
--json
Lors de la liste des sauvegardes, l'option "--json" écrit une sortie JSON. Le format est un tableau d'objets JSON ("name", "rev", "date"). Pour les détails, voir "tlpkg/doc/json-formats.txt", définition du format : "TLBACKUPS". Si "--json" et "--data" sont tous deux donnés, "--json" a la priorité.

update [option...] [pkg...]

Met à jour les paquets donnés en arguments vers la dernière version disponible à la source d'installation. Soit "--all", soit au moins un nom de pkg doit être spécifié. Options :

--all
Met à jour tous les paquets installés à l'exception de "tlmgr" lui-même. Si des mises à jour de "tlmgr" lui-même sont présentes, cela génère une erreur, sauf si l'option "--force" ou "--self" est également fournie. (Voir ci-dessous.)

En plus de la mise à jour des paquets installés, lors de la mise à jour d'une collection, l'installation locale est (par défaut) synchronisée avec l'état de la collection sur le serveur, pour les ajouts comme pour les suppressions.

Cela signifie que si un paquet a été supprimé sur le serveur (et a donc également été supprimé de la collection respective), "tlmgr" supprimera le paquet dans l'installation locale. C'est ce qu'on appelle le « retrait automatique » et c'est annoncé comme tel lorsqu'on utilise l'option "--list". Ce retrait automatique peut être supprimé en utilisant l'option "--no-auto-remove" (non recommandé, voir la description de l'option).

De manière analogue, si un paquet a été ajouté à une collection sur le serveur qui est également installée localement, il sera ajouté à l'installation locale. C'est ce qu'on appelle « l'installation automatique » et c'est annoncé comme tel lorsqu'on utilise l'option "--list". Cette installation automatique peut être supprimée en utilisant l'option "--no-auto-install" (également non recommandée).

Une exception aux vérifications de dépendances de collection (y compris l'installation automatique des paquets mentionnée ci-dessus) sont ceux qui ont été « retirés de force » par vous, c'est-à-dire que vous avez appelé "tlmgr remove --force" sur eux. (Voir la documentation de l'action "remove".) Pour réinstaller de tels paquets retirés de force, utilisez "--reinstall-forcibly-removed".

Pour répéter : les retraits et ajouts automatiques sont entièrement déterminés par la comparaison des collections. Ainsi, si vous installez manuellement un paquet individuel "foo" qui est plus tard retiré du serveur, "tlmgr" ne le remarquera pas et ne le retirera pas localement. (Il doit en être ainsi, sans travaux majeurs de réarchitecture, car la tlpdb n'enregistre pas le dépôt d'où proviennent les paquets.)

Si vous souhaitez exclure certains paquets de la présente exécution de mise à jour (par exemple, en raison d'une liaison lente), voir l'option "--exclude" ci-dessous.

--self
Met à jour "tlmgr" lui-même (c'est-à-dire les paquets d'infrastructure) si des mises à jour sont disponibles. Sous Windows, cela inclut les mises à jour de l'interpréteur Perl privé inclus dans TeX Live.

Si cette option est fournie avec soit "--all", soit une liste de paquets, alors "tlmgr" sera mis à jour en premier et, si cette mise à jour réussit, la nouvelle version sera relancée pour terminer le reste des mises à jour.

En bref :

tlmgr update --self        # met à jour uniquement l'infrastructure
tlmgr update --self --all  # met à jour l'infrastructure et tous les paquets
tlmgr update --force --all # met à jour tous les paquets mais *pas* l'infrastructure
                           # ... ce dernier à vos risques et périls, non recommandé !
--dry-run
Rien n'est réellement installé ; au lieu de cela, les actions à effectuer sont écrites dans le terminal. Il s'agit d'un rapport plus détaillé que "--list".
--list [pkg]
Liste de manière concise les paquets qui seraient mis à jour, nouvellement installés ou retirés, sans rien modifier réellement. Si "--all" est également fourni, toutes les mises à jour disponibles sont listées. Si "--self" est fourni, mais pas "--all", seules les mises à jour des paquets critiques (tlmgr, infrastructure texlive, perl sous Windows, etc.) sont listées. Si ni "--all" ni "--self" n'est fourni, et en outre aucun pkg n'est fourni, alors "--all" est supposé (ainsi, "tlmgr update --list" est identique à "tlmgr update --list --all"). Si ni "--all" ni "--self" n'est fourni, mais que des noms de paquets spécifiques sont fournis, ces paquets sont vérifiés pour les mises à jour.
--exclude pkg
Exclut pkg du processus de mise à jour. Si cette option est fournie plus d'une fois, ses arguments s'accumulent.

Un argument pkg exclut à la fois le paquet pkg lui-même et tous ses paquets associés spécifiques à la plateforme pkg.ARCH. Par exemple,

tlmgr update --all --exclude a2ping

ne mettra pas à jour "a2ping", "a2ping.i386-linux", ou tout autre paquet "a2ping."ARCH.

Si cette option spécifie un paquet qui serait normalement éligible à une installation automatique, un retrait automatique, ou une réinstallation d'un paquet retiré de force, "tlmgr" s'arrêtera avec un message d'erreur. Les exclusions ne sont pas prises en charge dans ces circonstances.

Cette option peut également être définie de manière permanente dans le fichier de configuration tlmgr avec la clé "update-exclude".

--no-auto-remove [pkg...]
Par défaut, "tlmgr" essaie de retirer les paquets d'une collection existante qui ont disparu sur le serveur, comme décrit ci-dessus sous "--all". Cette option empêche de tels retraits, soit pour tous les paquets (avec "--all"), soit uniquement pour les noms de pkg donnés. Cela peut conduire à une installation TeX incohérente, car les paquets sont fréquemment renommés ou remplacés par leurs auteurs. Par conséquent, ce n'est pas recommandé.
--no-auto-install [pkg...]
Dans des circonstances normales, "tlmgr" installera les paquets qui sont nouveaux sur le serveur, comme décrit ci-dessus sous "--all". Cette option empêche toute installation automatique de ce type, soit pour tous les paquets (avec "--all"), soit pour les pkg donnés.

De plus, une fois que l'exécution de "tlmgr" utilisant cette option est terminée, les paquets qui auraient dû être installés automatiquement seront considérés comme retirés de force. Ainsi, si "foobar" est le seul nouveau paquet sur le serveur, alors

tlmgr update --all --no-auto-install

est équivalent à

tlmgr update --all
tlmgr remove --force foobar

Encore une fois, étant donné que les paquets sont parfois renommés ou remplacés, l'utilisation de cette option n'est pas recommandée.

--reinstall-forcibly-removed
Dans des circonstances normales, "tlmgr" n'installera pas les paquets qui ont été retirés de force par l'utilisateur ; c'est-à-dire, retirés avec "remove --force", ou dont l'installation a été interdite par "--no-auto-install" lors d'une mise à jour précédente.

Cette option permet à "tlmgr" d'ignorer les retraits de force et de réinstaller tous ces paquets. Cela peut être utilisé pour synchroniser complètement une installation avec la vue du serveur de ce qui est disponible :

tlmgr update --reinstall-forcibly-removed --all
--backup
--backupdir directory
Ces deux options contrôlent la création de sauvegardes des paquets avant la mise à jour ; c'est-à-dire, la sauvegarde des paquets tels qu'ils sont actuellement installés. Si aucune des deux options n'est fournie, aucune sauvegarde ne sera effectuée. Si "--backupdir" est fournie et spécifie un répertoire accessible en écriture, alors une sauvegarde sera faite à cet endroit. Si seule "--backup" est fournie, alors une sauvegarde sera faite dans le répertoire précédemment défini via l'action "option" (voir ci-dessous). Si les deux sont fournies, une sauvegarde sera faite dans le répertoire spécifié.

Vous pouvez également définir des options via l'action "option" pour créer automatiquement des sauvegardes pour tous les paquets, et/ou conserver seulement un certain nombre de sauvegardes.

"tlmgr" effectue toujours une sauvegarde temporaire lors de la mise à jour des paquets, en cas de problème de téléchargement ou autre lors d'une mise à jour. En contraste, le but de cette option "--backup" est de sauvegarder une sauvegarde persistante au cas où le contenu réel de la mise à jour causerait des problèmes, par exemple, introduirait une incompatibilité TeX.

L'action "restore" explique comment restaurer à partir d'une sauvegarde.

--no-depends
Si vous demandez la mise à jour d'un paquet normalement, tous les paquets dépendants seront également vérifiés pour les mises à jour et mis à jour si nécessaire. Ce commutateur supprime ce comportement.
--no-depends-at-all
Voir ci-dessus sous install (et méfiez-vous).
--force
Force la mise à jour des paquets normaux, sans mettre à jour "tlmgr" lui-même (sauf si l'option "--self" est également fournie). Non recommandé.

De plus, "update --list" est toujours effectué indépendamment de cette option.

/dl>

Si le paquet sur le serveur est plus ancien que le paquet déjà installé (par exemple, si le miroir sélectionné est obsolète), "tlmgr" ne rétrograde pas. De plus, les paquets pour les plateformes désinstallées ne sont pas installés.

"tlmgr" sauvegarde une copie du fichier principal "texlive.tlpdb" utilisé pour une mise à jour avec un suffixe représentant l'URL du dépôt, comme dans "tlpkg/texlive.tlpdb.main."long-hash-string. Ainsi, même lorsque plusieurs miroirs sont utilisés, une seule sauvegarde principale de "tlpdb" est conservée. Pour les dépôts non principaux, qui n'ont généralement pas (beaucoup) de miroirs, aucun élagage des sauvegardes n'est effectué.

Cette action n'ajoute ni ne supprime automatiquement de nouveaux liens symboliques dans les répertoires système ; vous devez exécuter vous-même "tlmgr" "path" si vous utilisez cette fonctionnalité et souhaitez que de nouveaux liens symboliques soient ajoutés.

FICHIER DE CONFIGURATION POUR TLMGR

"tlmgr" lit deux fichiers de configuration : l'un est global au système, dans "TEXMFSYSCONFIG/tlmgr/config", et l'autre est spécifique à l'utilisateur, dans "TEXMFCONFIG/tlmgr/config". Celui spécifique à l'utilisateur est celui par défaut pour l'action "conf tlmgr". (Exécutez "kpsewhich -var-value=TEXMFSYSCONFIG" ou "... TEXMFCONFIG ..." pour voir les noms réels des répertoires.)

Quelques valeurs par défaut correspondant aux options de ligne de commande peuvent être définies dans ces fichiers de configuration. De plus, le fichier global au système peut contenir une directive pour restreindre les actions autorisées.

Dans ces fichiers de configuration, les lignes vides et les lignes commençant par # sont ignorées. Toutes les autres lignes doivent ressembler à ceci :

clé = valeur

où les espaces sont optionnels mais le "=" est requis.

Les clés autorisées sont :

"auto-remove =" 0 ou 1 (par défaut 1), identique à l'option de ligne de commande.
"gui-expertmode =" 0 ou 1 (par défaut 1). Ceci bascule entre l'interface graphique complète et une interface graphique simplifiée avec uniquement les paramètres les plus courants.
"gui-lang =" llcode, avec une valeur de code langue comme pour l'option de ligne de commande.
"no-checksums =" 0 ou 1 (par défaut 0, voir ci-dessous).
"persistent-downloads =" 0 ou 1 (par défaut 1), identique à l'option de ligne de commande.
"require-verification =" 0 ou 1 (par défaut 0), identique à l'option de ligne de commande.
"tkfontscale =" nombre à virgule flottante (par défaut 1.0) ; facteur d'échelle pour les polices dans les interfaces basées sur Tk.
"update-exclude =" liste de paquets séparés par des virgules (pas d'espaces autorisés). Identique à l'option de ligne de commande "--exclude" pour l'action "update".
"verify-downloads =" 0 ou 1 (par défaut 1), identique à l'option de ligne de commande.

Le fichier de configuration global au système peut contenir une clé supplémentaire :

"allowed-actions =" action1[,action2,...] La valeur est une liste séparée par des virgules (sans espaces) d'"actions tlmgr" qui sont autorisées à être exécutées lorsque "tlmgr" est appelé en mode système (c'est-à-dire, sans "--usermode"). Ceci permet aux distributeurs d'inclure "tlmgr" dans leurs paquets, mais d'autoriser uniquement un ensemble restreint d'actions qui n'interfèrent pas avec leur gestionnaire de paquets de distribution. Pour les installations natives de TeX Live, il n'est pas pertinent de définir ceci.

Enfin, la clé "no-checksums" nécessite plus d'explication. Par défaut, les sommes de contrôle des paquets calculées et stockées sur le serveur (dans le TLPDB) sont comparées aux sommes de contrôle calculées localement après téléchargement. "no-checksums" désactive ce processus. L'algorithme de somme de contrôle est SHA-512. Votre système doit disposer de l'un des éléments suivants (recherchés dans cet ordre) : le module Perl "Digest::SHA", le programme "openssl" (https://openssl.org), le programme "sha512sum" (de GNU Coreutils, https://www.gnu.org/software/coreutils), ou enfin le programme "shasum" (juste pour supporter les anciens Macs). Si aucun de ceux-ci n'est disponible, un avertissement est émis et "tlmgr" procède sans vérifier les sommes de contrôle. "no-checksums" évite l'avertissement. (Soit dit en passant, les autres implémentations SHA, telles que les modules purs Perl et purs Lua, sont beaucoup trop lentes pour être utilisables dans notre contexte.)

VÉRIFICATION CRYPTOGRAPHIQUE

"tlmgr" et "install-tl" effectuent une vérification cryptographique si possible. Si la vérification est effectuée et réussie, les programmes rapportent "(verified)" après le chargement du TLPDB ; sinon, ils rapportent "(not verified)". Mais dans les deux cas, par défaut, l'installation et/ou les mises à jour se poursuivent normalement.

Si un programme nommé "gpg" est disponible (c'est-à-dire, trouvé dans "PATH"), par défaut les signatures cryptographiques seront vérifiées : nous exigeons que le dépôt principal soit signé, mais pas les dépôts supplémentaires. Si "gpg" n'est pas disponible, par défaut les signatures ne sont pas vérifiées et aucune vérification n'est effectuée, mais "tlmgr" continue néanmoins normalement.

Le comportement de la vérification peut être contrôlé par la ligne de commande et l'option du fichier de configuration "verify-repo" qui accepte l'une des valeurs suivantes : "none", "main", ou "all". Avec "none", aucune vérification n'est tentée. Avec "main" (par défaut), la vérification n'est requise que pour le dépôt principal, et uniquement si "gpg" est disponible ; bien qu'tentée pour tous, les signatures manquantes des dépôts subsidiaires ne provoqueront pas d'erreur. Enfin, dans le cas de "all", "gpg" doit être disponible et tous les dépôts doivent être signés.

Dans tous les cas, si une signature est vérifiée et que la vérification échoue, une erreur est signalée.

La vérification cryptographique nécessite que la vérification des sommes de contrôle (décrite juste au-dessus) réussisse, et un programme GnuPG ("gpg") fonctionnel (voir ci-dessous pour la méthode de recherche). Ensuite, à moins que la vérification cryptographique n'ait été désactivée, un fichier de signature ("texlive.tlpdb.*.asc") du fichier de somme de contrôle est téléchargé et la signature est vérifiée. La signature est créée par la clé GPG de distribution TeX Live 0x0D5E5D9106BAB6BC, qui est à son tour signée par la clé de Karl Berry 0x0716748A30D155AD et la clé de Norbert Preining 0x6CACA448860CDC13. Toutes ces clés sont accessibles depuis les serveurs de clés standard.

Des clés de confiance supplémentaires peuvent être ajoutées en utilisant l'action "key".

Configuration de l'invocation de GnuPG

L'exécutable utilisé pour GnuPG est recherché comme suit : Si la variable d'environnement "TL_GNUPG" est définie, elle est testée et utilisée ; sinon, "gpg" est vérifié ; enfin, "gpg2" est vérifié.

Une adaptation supplémentaire de l'invocation de "gpg" peut être faite en utilisant les deux variables d'environnement "TL_GNUPGHOME", qui est passée à "gpg" comme valeur pour "--homedir", et "TL_GNUPGARGS", qui remplace les options par défaut "--no-secmem-warning --no-permission-warning".

MODE UTILISATEUR

"tlmgr" fournit un moyen restreint, appelé ``mode utilisateur'', pour gérer des arbres texmf arbitraires de la même manière que l'installation principale. Par exemple, cela permet aux personnes sans permissions d'écriture sur l'emplacement d'installation de mettre à jour/installer des paquets dans un arbre qui leur appartient.

"tlmgr" est basculé en mode utilisateur avec l'option de ligne de commande "--usermode". Il ne bascule pas automatiquement, et il n'y a pas de paramètre de fichier de configuration pour cela. Ainsi, cette option doit être explicitement donnée chaque fois que le mode utilisateur doit être activé.

Ce mode de "tlmgr" fonctionne sur un arbre utilisateur, par défaut la valeur de la variable "TEXMFHOME". Ceci peut être remplacé par l'option de ligne de commande "--usertree". Dans ce qui suit, lorsque nous parlons d'arbre utilisateur, nous entendons soit "TEXMFHOME", soit celui donné sur la ligne de commande.

Toutes les actions ne sont pas autorisées en mode utilisateur ; "tlmgr" vous avertira et n'effectuera aucune action problématique. Actuellement non supportée (et probablement ne le sera jamais) est l'action "platform". L'action "gui" n'est pas supportée actuellement, mais pourrait l'être dans une future version.

Certaines actions de "tlmgr" n'ont pas besoin de permissions d'écriture et fonctionnent donc de la même manière en mode utilisateur et en mode normal. Actuellement, ce sont : "check", "help", "list", "print-platform", "print-platform-info", "search", "show", "version".

En revanche, la plupart des actions concernant la gestion des paquets nécessitent des permissions d'écriture et se comportent donc différemment en mode utilisateur, comme décrit ci-dessous : "install", "update", "remove", "option", "paper", "generate", "backup", "restore", "uninstall", "symlinks".

Avant d'utiliser "tlmgr" en mode utilisateur, vous devez configurer l'arborescence utilisateur avec l'action "init-usertree". Cela crée usertree"/web2c" et usertree"/tlpkg/tlpobj", ainsi qu'un fichier minimal usertree"/tlpkg/texlive.tlpdb". À ce stade, vous pouvez indiquer à "tlmgr" d'effectuer les actions (supportées) en ajoutant l'option de ligne de commande "--usermode".

En mode utilisateur, le fichier usertree"/tlpkg/texlive.tlpdb" ne contient que les paquets qui ont été installés dans l'arborescence utilisateur via "tlmgr", ainsi que des options supplémentaires du paquet ``virtuel'' "00texlive.installation" (similaire à "texlive.tlpdb" de l'installation principale).

Toutes les actions sur les paquets en mode utilisateur ne peuvent être effectuées que sur les paquets connus comme "relocatable". Cela exclut tous les paquets contenant des exécutables et quelques autres paquets essentiels. Sur les quelque 2500 paquets actuellement dans TeX Live, la grande majorité sont déplaçables et peuvent être installés dans une arborescence utilisateur.

Description des changements des actions en mode utilisateur :

Installation en mode utilisateur

En mode utilisateur, l'action "install" vérifie que le paquet et toutes ses dépendances sont soit déplaçables, soit déjà installés dans l'installation système. Si c'est le cas, elle décompresse tous les conteneurs à installer dans l'arborescence utilisateur (pour répéter, c'est soit "TEXMFHOME" soit la valeur de "--usertree") et ajoute les paquets respectifs à "texlive.tlpdb" de l'arborescence utilisateur (en la créant si nécessaire).

Actuellement, l'installation d'une collection en mode utilisateur installe tous les paquets dépendants, mais contrairement au mode normal, elle n'installe *pas* les collections dépendantes. Par exemple, en mode normal "tlmgr install collection-context" installerait "collection-basic" et d'autres collections, tandis qu'en mode utilisateur, *seuls* les paquets mentionnés dans "collection-context" sont installés.

Si un paquet distribuant des fichiers de carte est installé en mode utilisateur, une sauvegarde du fichier "updmap.cfg" de l'utilisateur dans "USERTREE/web2c/" est effectuée, puis ce fichier est régénéré à partir de la liste des paquets installés.

Sauvegarde, restauration, suppression, mise à jour en mode utilisateur

En mode utilisateur, ces actions vérifient que tous les paquets sur lesquels on agit sont installés dans l'arborescence utilisateur avant de continuer ; sinon, elles se comportent comme en mode normal.

Générer, option, papier en mode utilisateur

En mode utilisateur, ces actions opèrent uniquement sur les fichiers de configuration de l'arborescence utilisateur et/ou sur "texlive.tlpdb".

Journaux en mode utilisateur

En mode utilisateur, "tlmgr.log" et "tlmgr-commands.log" sont écrits dans le répertoire "TEXMFVAR/web2c/" au lieu de "TEXMFSYSVAR/web2c/".

RÉPERTOIRES MULTIPLES

Le principal répertoire TeX Live contient une vaste gamme de paquets. Néanmoins, des dépôts locaux supplémentaires peuvent être utiles pour fournir des ressources installées localement, telles que des polices propriétaires et des styles maison. De plus, des dépôts de paquets alternatifs distribuent des paquets qui ne peuvent ou ne devraient pas être inclus dans TeX Live, pour quelque raison que ce soit.

La méthode la plus simple et la plus fiable consiste à définir temporairement la source d'installation sur n'importe quel dépôt (avec les options de ligne de commande ou "option repository"), et à effectuer vos opérations.

Cependant, lorsque vous utilisez plusieurs dépôts sur une longue période, basculer explicitement entre eux devient gênant. Ainsi, il est possible d'informer "tlmgr" des dépôts supplémentaires que vous souhaitez utiliser. La commande de base est "tlmgr repository add". Le reste de cette section explique plus en détail.

Lors de l'utilisation de plusieurs dépôts, l'un d'entre eux doit être défini comme dépôt principal, qui distribue la plupart des paquets installés. Lorsque vous passez d'une installation à dépôt unique à une installation à dépôts multiples, le dépôt unique précédent sera défini comme dépôt principal.

Par défaut, même si plusieurs dépôts sont configurés, les paquets sont *toujours* installés *uniquement* à partir du dépôt principal. Ainsi, ajouter simplement un second dépôt n'active pas réellement l'installation de quoi que ce soit à partir de là. Vous devez également spécifier quels paquets doivent être pris du nouveau dépôt, en spécifiant des règles dites de ``blocage'' (pinning), décrites ci-dessous.

Blocage (Pinning)

Lorsqu'un paquet "foo" est bloqué sur un dépôt, un paquet "foo" dans tout autre dépôt, même s'il a un numéro de révision plus élevé, ne sera pas considéré comme un candidat installable.

Comme mentionné ci-dessus, par défaut, tout est bloqué sur le dépôt principal. Examinons maintenant un exemple de configuration d'un second dépôt et d'activation des mises à jour d'un paquet à partir de celui-ci.

Tout d'abord, vérifiez que nous avons le support des dépôts multiples, et qu'un seul est activé (comme c'est le cas par défaut) :

$ tlmgr repository list
List of repositories (with tags if set):
  /var/www/norbert/tlnet

Ok. Ajoutons le dépôt "tlcontrib" (il s'agit d'un vrai dépôt hébergé sur http://contrib.texlive.info) avec le tag "tlcontrib" :

$ tlmgr repository add http://contrib.texlive.info/current tlcontrib

Vérifiez à nouveau la liste des dépôts :

$ tlmgr repository list
List of repositories (with tags if set):
   http://contrib.texlive.info/current (tlcontrib)
   /var/www/norbert/tlnet (main)

Maintenant, nous spécifions une entrée de blocage pour obtenir le paquet "classico" depuis "tlcontrib" :

$ tlmgr pinning add tlcontrib classico

Vérifiez que nous pouvons trouver "classico" :

$ tlmgr show classico
package:     classico
...
shortdesc:   URW Classico fonts
...

- Installer "classico" :

$ tlmgr install classico
tlmgr: package repositories:
...
[1/1,  ??:??/??:??] install: classico @tlcontrib [737k]

Dans la sortie ici, vous pouvez voir que le paquet "classico" a été installé depuis le dépôt "tlcontrib" (@tlcontrib).

Enfin, "tlmgr pinning" prend également en charge la suppression de certains ou de tous les paquets d'un dépôt donné :

$ tlmgr pinning remove tlcontrib classico # supprimer juste classico
$ tlmgr pinning remove tlcontrib --all    # ne rien prendre de tlcontrib

Un résumé des actions de "tlmgr pinning" est donné ci-dessus.

Interface graphique pour TLMGR

L'interface graphique de "tlmgr" nécessite Perl/Tk https://search.cpan.org/search?query=perl%2Ftk. Pour les systèmes basés sur Unix, Perl/Tk (ainsi que Perl bien sûr) doit être installé en dehors de TL. https://tug.org/texlive/distro.html#perltk contient une liste des invocations pour certaines distributions. Pour Windows, les modules nécessaires ne sont plus fournis dans TeX Live, vous devrez donc disposer d'un Perl externe qui les inclut.

Nous parlons ici de l'interface graphique intégrée à tlmgr lui-même, et non des autres interfaces graphiques de tlmgr, qui sont : tlshell (basé sur Tcl/Tk), tlcockpit (basé sur Java) et, uniquement sur Mac, TeX Live Utility. Ceux-ci sont invoqués comme des programmes séparés.

Le mode GUI de tlmgr est démarré avec l'invocation "tlmgr gui" ; en supposant que Tk peut être chargé, l'interface graphique sera affichée. La fenêtre principale contient une barre de menu, l'affichage principal et une zone de statut où les messages normalement affichés sur la console sont présentés.

Dans l'affichage principal, il y a trois parties principales : la zone "Configuration de l'affichage", la liste des paquets, et les boutons d'action.

De plus, en haut à droite, le dépôt actuellement chargé est affiché ; cela agit également comme un bouton et, lorsqu'il est cliqué, tentera de charger le dépôt par défaut. Pour charger un dépôt différent, voir l'élément de menu "tlmgr".

Enfin, la zone de statut en bas de la fenêtre fournit des informations supplémentaires sur ce qui se passe.

Affichage principal

Zone de configuration de l'affichage

La première partie de l'affichage principal vous permet de spécifier (filtrer) quels paquets sont affichés. Par défaut, tous sont affichés. Les changements ici sont immédiatement reflétés.

Statut
Sélectionnez si vous voulez afficher tous les paquets (par défaut), uniquement ceux installés, uniquement ceux *non* installés, ou uniquement ceux pour lesquels une mise à jour est disponible.
Catégorie
Sélectionnez quelles catégories sont affichées : paquets, collections et/ou schémas. Ceux-ci sont brièvement expliqués dans la section "DESCRIPTION" ci-dessus.
Correspondance
Sélectionne les paquets correspondant à un modèle spécifique. Par défaut, cela recherche dans les descriptions et les noms de fichiers. Vous pouvez également sélectionner un sous-ensemble pour la recherche.
Sélection
Sélectionne les paquets parmi ceux qui sont sélectionnés, ceux qui ne le sont pas, ou tous. Ici, « sélectionné » signifie que la case à cocher au début de la ligne d'un paquet est cochée.
Configuration des boutons d'affichage
À droite se trouvent trois boutons : sélectionner tous les paquets, ne sélectionner aucun (également appelé désélectionner tout), et réinitialiser tous ces filtres aux valeurs par défaut, c'est-à-dire afficher tout ce qui est disponible.

Zone de liste des paquets

La deuxième zone de l'affichage principal liste tous les paquets installés. Si un dépôt est chargé, ceux qui sont disponibles mais non installés sont également répertoriés.

Double-cliquer sur une ligne de paquet fait apparaître une fenêtre d'informations avec plus de détails : la description longue, les fichiers inclus, etc.

Chaque ligne de la liste des paquets se compose des éléments suivants :

une case à cocher
Utilisée pour sélectionner des paquets particuliers ; certains des boutons d'action (voir ci-dessous) ne fonctionnent que sur les paquets sélectionnés.
nom du paquet
Le nom (identifiant) du paquet tel qu'il est donné dans la base de données.
révision locale (et version)
Si le paquet est installé, le numéro de révision TeX Live pour le paquet installé sera affiché. S'il existe une version de catalogue donnée dans la base de données pour ce paquet, elle sera affichée entre parenthèses. Cependant, la version du catalogue, contrairement à la révision TL, n'est pas garantie de refléter ce qui est réellement installé.
révision distante (et version)
Si un dépôt a été chargé, la révision du paquet dans le dépôt (s'il est présent) est affichée. Comme pour la colonne locale, si une version de catalogue est fournie, elle sera affichée. Et comme pour la colonne locale, la version du catalogue peut être obsolète.
description courte
La description courte du paquet.

Boutons d'action d'affichage principal

Sous la liste des paquets se trouvent plusieurs boutons :

Mettre à jour tous les paquets installés
Ceci appelle "tlmgr update --all", c'est-à-dire qu'il tente de mettre à jour tous les paquets disponibles. Sous ce bouton se trouve un interrupteur pour permettre la réinstallation des paquets précédemment supprimés dans le cadre de cette action.

Les quatre autres boutons ne fonctionnent que sur les paquets sélectionnés, c'est-à-dire ceux dont la case à cocher au début de la ligne du paquet est cochée.

Mettre à jour
Met à jour uniquement les paquets sélectionnés.
Installer
Installe les paquets sélectionnés ; agit comme "tlmgr install", c'est-à-dire qu'il installe également les dépendances. Ainsi, l'installation d'une collection installe tous ses paquets constitutifs.
Supprimer
Supprime les paquets sélectionnés ; agit comme "tlmgr remove", c'est-à-dire qu'il supprimera également les dépendances des collections (mais pas les dépendances des paquets normaux).
Sauvegarde
Crée une sauvegarde des paquets sélectionnés ; agit comme "tlmgr backup". Cette action nécessite que l'option "backupdir" soit définie (voir "Options -" Général >).

Barre de menus

Les entrées suivantes se trouvent dans la barre de menus :

Menu "tlmgr"
Les éléments ici chargent divers dépôts : le dépôt par défaut tel que spécifié dans la base de données TeX Live, le dépôt réseau par défaut, le dépôt spécifié sur la ligne de commande (le cas échéant), et un dépôt arbitraire entré manuellement. Contient également l'indispensable opération "quit".
Menu "Options"
Permet d'accéder à plusieurs groupes d'options : "Papier" (configuration des tailles de papier par défaut), "Plateformes" (uniquement sur Unix, configuration des plateformes supportées/installées), "Langue de l'interface graphique" (sélection de la langue utilisée dans l'interface graphique), et "Général" (tout le reste).

Plusieurs basculeurs s'y trouvent également. Le premier est "Options expertes", qui est activé par défaut. Si vous le désactivez, la prochaine fois que vous démarrerez l'interface graphique, un écran simplifié s'affichera, ne montrant que la fonctionnalité la plus importante. Ce paramètre est enregistré dans le fichier de configuration de "tlmgr" ; voir "FICHIER DE CONFIGURATION POUR TLMGR" pour plus de détails.

Les autres basculeurs sont tous désactivés par défaut : pour la sortie de débogage, pour désactiver l'installation automatique de nouveaux paquets, et pour désactiver la suppression automatique des paquets supprimés du serveur. Jouer avec les choix de ce qui est installé ou non peut entraîner une installation TeX Live incohérente ; par exemple, lorsqu'un paquet est renommé.

Menu "Actions"
Permet d'accéder à plusieurs actions : mettre à jour la base de données des noms de fichiers (également appelée "ls-R", "mktexlsr", "texhash"), reconstruire tous les formats ("fmtutil-sys --all"), mettre à jour la base de données des cartes de polices ("updmap-sys"), restaurer à partir d'une sauvegarde d'un paquet, et utiliser des liens symboliques dans les répertoires système (pas sous Windows).

La dernière action est de supprimer l'installation complète de TeX Live (pas non plus sous Windows).

Menu "Aide"
Permet d'accéder au manuel TeX Live (également disponible sur le web à l'adresse https://tug.org/texlive/doc.html) et à la boîte de dialogue habituelle "À propos".

Options de l'interface graphique

Certaines options génériques Perl/Tk peuvent être spécifiées avec "tlmgr gui" pour contrôler l'affichage :

"-background" couleur
Définit la couleur d'arrière-plan.
"-font "" nom_police taille_police """
Définit la police, par exemple "tlmgr gui -font "helvetica 18"". L'argument de "-font" doit être entre guillemets, c'est-à-dire passé comme une seule chaîne.
"-foreground" couleur
Définit la couleur de premier plan.
"-geometry" spécification_géométrie
Définit la géométrie X, par exemple "tlmgr gui -geometry 1024x512-0+0" crée la fenêtre de taille (approximativement) donnée dans le coin supérieur droit de l'écran.
"-xrm" ressource_x
Passe la chaîne de ressource X arbitraire ressource_x.

Quelques autres options obscures sont reconnues mais ne sont pas mentionnées ici. Consultez la documentation Perl/Tk (https://search.cpan.org/perldoc?Tk) pour la liste complète, et toute documentation X pour des informations générales.

SORTIE LISIBLE PAR MACHINE

Avec l'option "--machine-readable", "tlmgr" écrit sur stdout dans le format fixe orienté ligne décrit ici, et les messages d'information habituels destinés à la consommation humaine sont écrits sur stderr (normalement, ils sont écrits sur stdout). L'idée est qu'un programme puisse obtenir toutes les informations dont il a besoin en lisant stdout.

Actuellement, cette option ne s'applique qu'aux actions de mise à jour, d'installation et de "gestion des options".

Sortie lisible par machine pour "update" et "install"

Le format de sortie est le suivant :

nom_champ "\t" valeur
...
"end-of-header"
nom_paquet statut rev_locale rev_serveur taille temps_execution temps_total_estime
...
"end-of-updates"
autre sortie des actions post-installation, non lisible par machine

La section d'en-tête comporte actuellement deux champs : "location-url" (la source du dépôt d'où proviennent les mises à jour) et "total-bytes" (le nombre total d'octets à télécharger).

Les champs rev_locale et rev_serveur pour chaque paquet sont les numéros de révision dans l'installation locale et le dépôt serveur, respectivement. Le champ taille est le nombre d'octets à télécharger, c'est-à-dire la taille du fichier tar compressé pour une installation réseau, pas la taille décompressée. Les champs temps_execution et temps_total_estime ne sont présents que pour les paquets mis à jour et installés automatiquement, et contiennent le temps écoulé depuis le début de l'installation/des mises à jour et le temps total estimé.

Les fins de ligne peuvent être LF ou CRLF en fonction de la plateforme actuelle.

"location-url" emplacement
L'emplacement peut être une URL (y compris "file:///foo/bar/..."), ou un nom de répertoire ("/foo/bar"). C'est le dépôt de paquets à partir duquel les nouvelles informations de paquet ont été tirées.
"total-bytes" compte
Le compte est simplement un nombre décimal, la somme des tailles de tous les paquets qui nécessitent une mise à jour ou une installation (qui sont listés par la suite).

Ensuite, une ligne avec uniquement la chaîne littérale "end-of-header".

Chaque ligne suivante jusqu'à une ligne avec la chaîne littérale "end-of-updates" rend compte d'un paquet. Les champs de chaque ligne sont séparés par une tabulation. Voici les champs.

nom_paquet
L'identifiant du paquet TeX Live, avec un suffixe de plateforme possible pour les exécutables. Par exemple, "pdftex" et "pdftex.i386-linux" sont donnés comme deux paquets distincts, un sur chaque ligne.
statut
Indique si le paquet doit être mis à jour (upd), installé (ins), déjà à jour (ok), ou supprimé (rem).

Notez que "ok" n'est affiché que si "tlmgr update --all" est utilisé. En mode "tlmgr install", seuls les paquets effectivement installés sont signalés.

révision locale
La révision locale du paquet, le cas échéant.
révision serveur
La révision du paquet dans le dépôt serveur, le cas échéant.
taille
La taille du fichier compressé, en octets.
temps d'exécution
Le temps d'exécution de l'action pour ce paquet.
temps total estimé
Le temps total estimé pour l'action entière.

Enfin, une ligne avec uniquement la chaîne littérale "end-of-updates".

La sortie pour l'action "option" est beaucoup plus simple :

optionname "\t" value
...
"end-of-options"

Par exemple, la sortie de "tlmgr option --machine-readable show" pourrait ressembler à ceci :

．．．
backupdir	/tmp/tlmgr-backups
．．．
end-of-options
tlmgr(1) — TeX Live Package Manager

Machine-readable "option" output

The output format is as follows:

key "\t" value

If a value is not saved in the database the string "(not set)" is shown.

If you are developing a program that uses this output, and find that changes would be helpful, do not hesitate to write the mailing list.

VARIABLES D'ENVIRONNEMENT

"tlmgr" utilise plusieurs variables d'environnement standard de TeX, comme rapporté par, par exemple, "tlmgr conf" ("conf").

De plus, pour faciliter le scripting et le débogage, "tlmgr" recherche les variables d'environnement suivantes. Celles-ci n'intéressent pas les installations utilisateur normales.

"TEXLIVE_COMPRESSOR"
Cette variable permet de sélectionner un programme de compression différent pour les sauvegardes et les conteneurs d'annulation intermédiaires. L'ordre de sélection est le suivant :
1.
Si la variable d'environnement "TEXLIVE_COMPRESSOR" est définie, utilisez-la ; abandonnez si elle ne fonctionne pas. Valeurs possibles : "lz4", "gzip", "xz". Les options nécessaires sont ajoutées en interne.
2.
Si lz4 est disponible (provenant du système ou de TL) et fonctionne, utilisez-le.
3.
Si gzip est disponible (provenant du système) et fonctionne, utilisez-le.
4.
Si xz est disponible (provenant du système ou de TL) et fonctionne, utilisez-le.

lz4 et gzip sont plus rapides pour créer les sauvegardes locales de tlmgr, donc ils sont préférés. L'utilisation inconditionnelle de xz pour les conteneurs tlnet n'est pas affectée, afin de minimiser les tailles de téléchargement.

"TEXLIVE_DOWNLOADER"
"TL_DOWNLOAD_PROGRAM"
"TL_DOWNLOAD_ARGS"
Ces options permettent de sélectionner des programmes de téléchargement différents de ceux sélectionnés automatiquement par l'installateur. L'ordre de sélection est le suivant :
1.
Si la variable d'environnement "TEXLIVE_DOWNLOADER" est définie, utilisez-la ; abandonnez si le programme spécifié ne fonctionne pas. Valeurs possibles : "lwp", "curl", "wget". Les options nécessaires sont ajoutées en interne.
2.
Si la variable d'environnement "TL_DOWNLOAD_PROGRAM" est définie (peut être n'importe quelle valeur), utilisez-la conjointement avec "TL_DOWNLOAD_ARGS" ; abandonnez si cela ne fonctionne pas.
3.
Si LWP est disponible et fonctionne, utilisez-le (méthode de loin la plus efficace, car elle prend en charge les téléchargements persistants).
4.
Si curl est disponible (provenant du système) et fonctionne, utilisez-le.
5.
Si wget est disponible (provenant du système ou de TL) et fonctionne, utilisez-le.

TL fournit des binaires "wget" pour les plateformes où c'est nécessaire, donc une méthode de téléchargement devrait toujours être disponible.

"TEXLIVE_PREFER_OWN"
Par défaut, les programmes de compression et de téléchargement fournis par le système, c'est-à-dire trouvés dans le "PATH", sont préférés à ceux livrés avec TeX Live.

Cela peut créer des problèmes avec les systèmes trop anciens, et peut donc être outrepassé en définissant la variable d'environnement "TEXLIVE_PREFER_OWN" à 1. Dans ce cas, les exécutables livrés avec TL seront préférés.

Les programmes de compression/téléchargement supplémentaires non fournis par TL, tels que gzip, lwp et curl, sont toujours recherchés sur le système et utilisés s'ils sont disponibles, conformément à ce qui précède. "TEXLIVE_PREFER_OWN" s'applique uniquement lorsque le programme recherché est livré avec TL, à savoir les compresseurs lz4 et xz, et le téléchargeur wget.

Exception : sous Windows, le "tar.exe" livré avec TL est toujours utilisé, quelle que soit la configuration.
