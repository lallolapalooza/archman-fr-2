NOM

tlsrpt-collectd - Un démon collectant les données de rapport TLSRPT depuis des instances de MTA via un socket de domaine Unix.

SYNOPIS

tlsrpt-collectd [OPTION]

DESCRIPTION

Le tlsrpt-collectd collecte les données des MTA concernant la livraison réussie d'emails cryptés ou les échecs survenus lors des tentatives de livraison. Les données sont pré-agrégées et seront récupérées par des tlsrpt-fetchers correspondants.

Les tlsrpt-collectd peuvent utiliser différents backends de stockage et pour chaque implémentation de ce type, une implémentation de fetcher correspondante doit être fournie si les données doivent être utilisées par un tlsrpt-reportd.

Il est également possible d'implémenter des backends de stockage qui ne sont pas interrogés par un tlsrpt-reportd. Ces backends de "stockage" collecteraient simplement les données à des fins d'analyse, mais ne fourniraient pas de moyens pour récupérer les données ultérieurement.

OPTIONS

--storage=URL

Utilise le stockage de données décrit par URL. Il peut s'agir d'une liste séparée par des virgules de plusieurs backends de stockage. Le schéma d'URL identifie le backend de stockage.

--socketname=chemin

Écoute sur le socket de domaine Unix chemin pour les données de rapport.

--socketuser=nom

Définit la propriété de l'utilisateur du socket à nom.

--socketgroup=nom

Définit la propriété du groupe du socket à nom.

--socketmode=octal

Définit les bits de mode du fichier du socket au mode numérique octal. Par exemple, 0200 pour autoriser uniquement l'accès en écriture pour le propriétaire.

--sockettimeout=n

Valide les données accumulées dans le stockage de données si n secondes se sont écoulées depuis la dernière validation.

--max_uncommited_datagrams=n

Valide les données accumulées dans le stockage de données après la réception de n datagrammes.

--retry_commit_datagram_count=n

Après un échec de validation des données accumulées, réessayez après la réception de n datagrammes supplémentaires au lieu de réessayer immédiatement après le datagramme suivant. Si une validation échoue en raison d'un délai d'attente, retenter après chaque datagramme pourrait risquer de rencontrer le même délai d'attente encore et encore. Ne retenter que tous les n datagrammes réduit le temps d'attente pour de tels délais d'attente.

--daily_rollover_script=script

Si cette option est définie, script sera exécuté après le passage de minuit UTC et après que les étapes de maintenance aient été effectuées. Ceci peut être utile pour pousser la base de données collectd vers un autre endroit dans les configurations où un TLSRPT-collectd distant ne peut pas être facilement interrogé depuis le TLSRPT-reportd, mais où le TLSRPT-collectd peut pousser des données vers le TLSRPT-reportd.

--dump_path_for_invalid_datagram=chemin

Si un datagramme invalide est reçu et que cette option est définie, le datagramme invalide sera enregistré dans le fichier nommé chemin.

Options générales

--config_file=nom_fichier

Lit les options à partir de la section tlsrpt_collectd du fichier de configuration de style INI nom_fichier. Les variables d'environnement remplacent les paramètres du fichier de configuration et les options de ligne de commande remplacent les deux.

--help

Affiche un message d'aide décrivant toutes les options.

--pidfilename=chemin

Spécifie le fichier contenant l'identifiant du processus du démon tlsrpt-collectd. Une chaîne vide n'entraînera la création d'aucun fichier PID.

Options de journalisation

--logfilename=nom_fichier

Utilise nom_fichier comme fichier journal.

--log_level=niveau

Définit le niveau de journalisation à niveau, valeurs autorisées : debug, info, warn, error.

ENVIRONNEMENT

Toutes les options de configuration sauf --help et --config_file peuvent également être définies via des variables d'environnement. La variable d'environnement pour une option de configuration est le préfixe TLSRPT_COLLECTD_ suivi du nom du paramètre de configuration en majuscules. Par exemple, l'option --log_level peut être configurée via la variable d'environnement TLSRPT_COLLECTD_LOG_LEVEL.

STATUT DE SORTIE

0

Succès.

1

Échec. Les données n'ont pas pu être livrées.

2

Échec. Les données n'ont pas pu être livrées.

3

Erreur d'utilisation.

EXEMPLES

Exécute tlsrpt-collectd avec un fichier de configuration spécial et redéfinit le paramètre du niveau de journalisation :

tlsrpt-collectd --config-file /chemin/vers/config.cfg --log_level info
