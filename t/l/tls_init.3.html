Paquet: libretls

TLS_INIT(3) Manuel des fonctions de bibliothèque TLS_INIT(3)

NOM

tls_init, tls_config_new, tls_config_free, tls_config_error — initialiser l'API client et serveur TLS

SYNOPSIS

#include <tls.h>

int
tls_init(void);

struct tls_config *
tls_config_new(void);

void
tls_config_free(struct tls_config *config);

const char *
tls_config_error(struct tls_config *config);

DESCRIPTION

Les fonctions de la famille tls établissent un canal de communication sécurisé utilisant le protocole socket TLS. Les clients et les serveurs sont pris en charge.

La fonction tls_init() initialise les structures de données globales. Il n'est plus nécessaire d'appeler cette fonction directement, car elle est appelée en interne lorsque nécessaire. Elle peut être appelée plusieurs fois et de manière concurrente.

Avant qu'une connexion ne soit créée, une configuration doit être établie. La fonction tls_config_new() alloue, initialise et renvoie un nouvel objet de configuration par défaut qui peut être utilisé pour les connexions futures. Plusieurs fonctions existent pour modifier les options de configuration ; voir tls_config_set_protocols(3), tls_load_file(3), tls_config_ocsp_require_stapling(3), et tls_config_verify(3).

La fonction tls_config_error() peut être utilisée pour récupérer une chaîne contenant plus d'informations sur la dernière erreur survenue concernant une configuration.

Un objet de connexion TLS est créé par tls_client(3) ou tls_server(3) et configuré avec tls_configure(3).

Une connexion client est initiée après configuration en appelant tls_connect(3). Un serveur peut accepter une nouvelle connexion client en appelant tls_accept_socket(3) sur une connexion socket déjà établie.

Deux fonctions sont fournies pour l'entrée et la sortie, tls_read(3) et tls_write(3). Les deux effectuent automatiquement le tls_handshake(3) en cas de besoin.

Les propriétés des connexions TLS établies peuvent être inspectées avec les fonctions décrites dans tls_conn_version(3) et tls_ocsp_process_response(3).

Après utilisation, une connexion TLS doit être fermée avec tls_close(3) puis libérée en appelant tls_free(3).

Lorsqu'aucun autre contexte ne doit être configuré, l'objet de configuration doit être libéré en appelant tls_config_free(). Il est sûr d'appeler tls_config_free() dès que le dernier appel à tls_configure() a été effectué. Si config est NULL, aucune action n'est effectuée.

VALEURS DE RETOUR

tls_init() retourne 0 en cas de succès ou -1 en cas d'erreur.

tls_config_new() retourne NULL en cas d'erreur ou de manque de mémoire.

tls_config_error() retourne NULL si aucune erreur ne s'est produite avec config du tout, ou si l'allocation mémoire a échoué lors de la tentative d'assemblage de la chaîne décrivant la dernière erreur liée à config.

VOIR AUSSI

tls_accept_socket(3), tls_client(3), tls_config_ocsp_require_stapling(3), tls_config_set_protocols(3), tls_config_verify(3), tls_conn_version(3), tls_connect(3), tls_load_file(3), tls_ocsp_process_response(3), tls_read(3)

HISTORIQUE

L'API tls est apparue pour la première fois dans OpenBSD 5.6 en réponse aux défis inutiles que présentaient d'autres API pour les utiliser en toute sécurité.

Toutes les fonctions ont été renommées de ressl_*() en tls_*() pour OpenBSD 5.7.

tls_config_error() est apparu dans OpenBSD 6.0.

ATTENTION

La fonction tls_config_error() retourne un pointeur interne. Il ne doit pas être libéré par l'application, sinon une erreur de double libération se produira. Le pointeur deviendra invalide lors de la prochaine erreur survenant avec config. Par conséquent, si l'application a besoin du message ultérieurement, elle doit copier la chaîne avant d'appeler la prochaine fonction de libtls impliquant config, ou un échec de segmentation ou une lecture de données non intentionnelles sera le résultat probable.
