TLSMGR(8) Manuel du gestionnaire système TLSMGR(8)

NOM

tlsmgr - Gestionnaire de cache de session TLS et de générateur de nombres aléatoires de Postfix

SYNTAXE

tlsmgr [options génériques de démon Postfix]

DESCRIPTION


Le programme tlsmgr(8) gère les caches de session TLS de Postfix. Il stocke et récupère les entrées du cache sur demande des processus smtpd(8) et smtp(8), et supprime périodiquement les entrées expirées.

Le programme tlsmgr(8) gère également le pool de générateur de nombres aléatoires (PRNG). Il répond aux requêtes des processus smtpd(8) et smtp(8) pour amorcer leurs pools PRNG internes.

Le pool PRNG de tlsmgr(8) est initialement amorcé à partir d'une source externe (EGD, /dev/urandom, ou fichier régulier). Il est mis à jour à des intervalles pseudo-aléatoires configurables avec des données provenant de la source externe. Il est mis à jour périodiquement avec des données provenant des entrées du cache de session TLS et avec l'heure de la journée, et il est mis à jour avec l'heure de la journée chaque fois qu'un processus demande un service de tlsmgr(8).

Le programme tlsmgr(8) sauvegarde l'état du PRNG dans un fichier d'échange périodiquement et lors de la terminaison du processus, et lit le fichier d'échange lors de l'initialisation de son PRNG.

SÉCURITÉ

Le programme tlsmgr(8) n'est pas sensible à la sécurité. Le code qui maintient les pools PRNG externes et internes ne « fait pas confiance » aux données qu'il manipule, et le code qui maintient le cache de session TLS ne touche pas au contenu des entrées mises en cache, sauf pour amorcer son pool PRNG interne.

Le programme tlsmgr(8) peut être exécuté en chroot et avec des privilèges réduits. Au démarrage du processus, il se connecte à la source d'entropie et au fichier d'échange, et crée ou tronque les fichiers optionnels du cache de session TLS.

Avec Postfix version 2.5 et ultérieures, tlsmgr(8) n'utilise plus les privilèges root lors de l'ouverture des fichiers de cache. Ces fichiers doivent maintenant être stockés sous le data_directory appartenant à Postfix. Comme aide à la migration, une tentative d'ouverture d'un fichier de cache sous un répertoire ne lui appartenant pas est redirigée vers le data_directory appartenant à Postfix, et un avertissement est consigné.

DIAGNOSTICS


Les problèmes et les transactions sont enregistrés dans syslogd(8) ou postlogd(8).

BOGUES


Il n'existe aucun moyen automatique de limiter le nombre d'entrées dans les caches de session TLS et/ou la taille des fichiers de cache TLS.

PARAMÈTRES DE CONFIGURATION

Les modifications apportées à main.cf ne sont pas prises en compte automatiquement, car tlsmgr(8) est un processus persistant. Utilisez la commande « postfix reload » après une modification de configuration.

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

tlsmgr(8)

NOM

tlsmgr - Postfix TLS session cache manager

SYNOPIS

    tlsmgr,
    tlsmgr [-q] [-t timeout]

DESCRIPTION

The Postfix tlsmgr(8) daemon process is available in Postfix 3.3 and later. It manages the Postfix TLS session cache. The cache stores session identifiers for TLS sessions, allowing subsequent connections between the same client and server to resume a previous TLS session.

The tlsmgr(8) daemon is started by the Postfix master(8) process when the parameter tls_session_cache_database is set to a non-empty value.

The cache is implemented as a database. The default database type is smtp(8), which is memory-based. This means the cache is lost when the tlsmgr daemon stops.

The tlsmgr daemon can be started with the following options:

-q
Tune the cache size based on the tls_session_cache_size parameter. This is the default behavior.
-t timeout
The default cache entry timeout value. Entries in the cache that are older than this value will be removed. The default value is 5 minutes.

SÉCURITÉ

The tlsmgr daemon does not receive any external network connections. It is only accessed by Postfix daemon processes via Unix domain sockets. Therefore, no special security precautions are needed.

DIAGNOSTIC

Problems will be reported via syslogd(8).

BOGUES

The tlsmgr daemon does not support cache persistence. This means the cache is lost when the daemon stops. For cache persistence, consider using a shared-memory database or a database that supports persistence, such as LMDB or Redis.

PARAMÈTRES DE CONFIGURATION

The following configuration parameters are available:

service_name (lecture seule)
Nom du service master.cf d'un processus démon Postfix.

These parameters are described in smtp(8), smtpd(8), postconf(5), and master(5).

CACHE DE SESSION TLS

The tlsmgr daemon manages the TLS session cache, which is used to store session identifiers for TLS sessions. This allows subsequent connections between the same client and server to resume a previous TLS session, which can improve performance by reducing the overhead of establishing a new TLS session.

The cache is implemented as a database. The default database type is memory-based, which means the cache is lost when the tlsmgr daemon stops.

The cache size can be tuned using the tls_session_cache_size parameter. The default cache entry timeout value can be set using the tls_session_cache_timeout parameter.

GÉNÉRATEUR DE NOMBRES PSEUDO-ALÉATOIRES

The tlsmgr daemon uses the system's pseudo-random number generator to generate session identifiers. This is important for security, as predictable session identifiers could be exploited by attackers.

CONTRÔLES DIVERS

The following controls are available in Postfix 3.3 and later:

service_name (lecture seule)
Le nom du service master.cf d'un processus démon Postfix.
