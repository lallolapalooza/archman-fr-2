TLS_CONNECT(3) Manuel des fonctions de bibliothèque TLS_CONNECT(3)

NOM

tls_connect, tls_connect_fds, tls_connect_servername, tls_connect_socket, tls_connect_cbs — instruire un client TLS à établir une connexion

SYNTAXE

#include <tls.h>

int
tls_connect(struct tls *ctx, const char *host, const char *port);

int
tls_connect_fds(struct tls *ctx, int fd_read, int fd_write, const char *servername);

int
tls_connect_servername(struct tls *ctx, const char *host, const char *port, const char *servername);

int
tls_connect_socket(struct tls *ctx, int s, const char *servername);

int
tls_connect_cbs(struct tls *ctx, ssize_t (*tls_read_cb)(struct tls *ctx, void *buf, size_t buflen, void *cb_arg), ssize_t (*tls_write_cb)(struct tls *ctx, const void *buf, size_t buflen, void *cb_arg), void *cb_arg, const char *servername);

DESCRIPTION

Après avoir créé un contexte client TLS avec tls_client(3) et l'avoir configuré avec tls_configure(3), une connexion client est initiée en appelant tls_connect(). Cette fonction créera un nouveau socket, se connectera à l'hôte et au port spécifiés, puis établira une connexion sécurisée. Le port peut être numérique ou un nom de service. S'il est NULL, alors un hôte au format « nomhôte:port » est autorisé. Le nom à utiliser pour la vérification est déduit de la valeur de l'hôte.

La fonction tls_connect_servername() a le même comportement, cependant le nom à utiliser pour la vérification est explicitement fourni, pour le cas où le nom du serveur TLS diffère du nom DNS.

Un socket déjà existant peut être mis à niveau vers une connexion sécurisée en appelant tls_connect_socket().

Alternativement, une connexion sécurisée peut être établie sur une paire de descripteurs de fichiers existants en appelant tls_connect_fds().

Appeler tls_connect_cbs() permet aux fonctions de rappel de lecture et d'écriture de gérer les transferts de données. Le paramètre cb_arg spécifié est renvoyé aux fonctions et peut contenir un pointeur vers des données spécifiées par l'appelant.

VALEURS DE RETOUR

Ces fonctions retournent 0 en cas de succès ou -1 en cas d'erreur.

VOIR AUSSI

tls_accept_socket(3), tls_client(3), tls_close(3), tls_config_ocsp_require_stapling(3), tls_configure(3), tls_handshake(3), tls_init(3)

HISTORIQUE

tls_connect() et tls_connect_socket() sont apparues dans OpenBSD 5.6 et ont reçu leurs noms définitifs dans OpenBSD 5.7.

tls_connect_fds() et tls_connect_servername() sont apparues dans OpenBSD 5.7 et tls_connect_cbs() dans OpenBSD 6.1.
