TNFTP(1) Manuel des commandes générales TNFTP(1)

NOM

tnftp — Programme de transfert de fichiers sur Internet

SYNTAXE

tnftp [-46AadefginpRtVv?] [-N netrc] [-o sortie] [-P port] [-q tempsdequitter] [-r reprise] [-s addr_source] [-T dir,max[,inc]] [-x tailletransfert] [[utilisateur@]hote [port]] [[utilisateur@]hote:[chemin][/]] [file:///chemin] [ftp://[utilisateur[:motdepasse]@]hote[:port]/chemin[/][;type=type]] [http://[utilisateur[:motdepasse]@]hote[:port]/chemin] [https://[utilisateur[:motdepasse]@]hote[:port]/chemin] ...

tnftp -u url fichier ...

DESCRIPTION

tnftp est l'interface utilisateur du protocole standard de transfert de fichiers Internet. Le programme permet à un utilisateur de transférer des fichiers vers et depuis un site réseau distant.

Les cinq derniers arguments permettront de récupérer un fichier en utilisant les protocoles FTP ou HTTP, ou par copie directe, dans le répertoire courant. Ceci est idéal pour les scripts. Référez-vous à AUTO-FETCHING FILES ci-dessous pour plus d'informations.

Les options peuvent être spécifiées en ligne de commande ou à l'interpréteur de commandes.

-4
Force tnftp à utiliser uniquement les adresses IPv4.
-6
Force tnftp à utiliser uniquement les adresses IPv6.
-A
Force le mode actif FTP. Par défaut, tnftp essaiera d'utiliser le mode passif FTP et se rabattra sur le mode actif si le mode passif n'est pas supporté par le serveur. Cette option fait en sorte que tnftp utilise toujours une connexion active. Elle n'est utile que pour se connecter à de très anciens serveurs qui n'implémentent pas correctement le mode passif.
-a
Force tnftp à contourner la procédure de connexion normale et à utiliser une connexion anonyme à la place.
-d
Active le débogage.
-e
Désactive l'édition en ligne de commande. Ceci est utile pour le mode Emacs ange-ftp.
-f
Force un rechargement du cache pour les transferts qui passent par les proxys FTP ou HTTP.
-g
Désactive le globage des noms de fichiers.
-i
Désactive les invites interactives pendant les transferts de fichiers multiples.
-N netrc
Utilise netrc au lieu de ~/.netrc. Référez-vous à THE .netrc FILE pour plus d'informations.
-n
Empêche tnftp de tenter une « connexion automatique » lors de la connexion initiale pour les transferts non automatiques. Si la connexion automatique est activée, tnftp vérifiera le fichier .netrc (voir ci-dessous) dans le répertoire personnel de l'utilisateur pour une entrée décrivant un compte sur la machine distante. Si aucune entrée n'existe, tnftp demandera le nom de connexion de la machine distante (par défaut, c'est l'identité de l'utilisateur sur la machine locale), et, si nécessaire, demandera un mot de passe et un compte avec lesquels se connecter. Pour outrepasser la connexion automatique pour les transferts automatiques, spécifiez le nom d'utilisateur (et éventuellement, le mot de passe) comme approprié.
-o sortie
Lors de la récupération automatique de fichiers, enregistre le contenu dans sortie. sortie est analysé conformément aux FILE NAMING CONVENTIONS ci-dessous. Si sortie n'est pas ‘-’ ou ne commence pas par ‘|’, alors seul le premier fichier spécifié sera récupéré dans sortie ; tous les autres fichiers seront récupérés dans le nom de base de leur nom distant.
-P port
Définit le numéro de port à port.
-p
Active le mode passif pour l'utilisation derrière des pare-feux filtrant les connexions. Cette option a été dépréciée car tnftp essaie maintenant d'utiliser le mode passif par défaut, se rabattant sur le mode actif si le serveur ne prend pas en charge les connexions passives.
-q tempsdequitter
Quitte si la connexion est restée inactive pendant tempsdequitter secondes.
-R
Redémarre toutes les récupérations automatiques non proxysées.
-r attente
Retente la tentative de connexion si elle a échoué, en faisant une pause de attente secondes.
-s addr_source
Utilise addr_source comme adresse IP locale pour toutes les connexions.
-t
Active le traçage des paquets.
-T direction,maximum[,incrément]
Définit le taux de transfert maximum pour la direction à maximum octets/seconde, et si spécifié, l'incrément à incrément octets/seconde. Référez-vous à rate pour plus d'informations.
-u url fichier ...
Téléverse les fichiers sur la ligne de commande vers url où url est l'un des types d'URL ‘ftp://’ pris en charge par la récupération automatique (avec un nom de fichier cible optionnel pour les téléversements de fichier unique), et fichier est un ou plusieurs fichiers locaux à téléverser.
-V
Désactive le mode verbeux et progression, outrepassant la valeur par défaut activée lorsque la sortie est dirigée vers un terminal.
-v
Active le mode verbeux et progression. C'est la valeur par défaut si la sortie est dirigée vers un terminal (et dans le cas de la progression, tnftp est le processus au premier plan). Force

-x xfersize
Définit la taille des tampons d'envoi et de réception du socket à xfersize. Voir xferbuf pour plus d'informations.
-?
Affiche l'aide sur la sortie standard et quitte.

L'hôte client avec lequel tnftp doit communiquer peut être spécifié sur la ligne de commande. Si cela est fait, tnftp tentera immédiatement d'établir une connexion avec un serveur FTP sur cet hôte; sinon, tnftp entrera dans son interpréteur de commandes et attendera les instructions de l'utilisateur. Lorsque tnftp attend des commandes de l'utilisateur, l'invite ‘ftp>’ est fournie à l'utilisateur. Les commandes suivantes sont reconnues par tnftp:

! [commande [arguments]]
Lance un shell interactif sur la machine locale. S'il y a des arguments, le premier est considéré comme une commande à exécuter directement, avec le reste des arguments comme ses arguments.
$ nom-macro [arguments]
Exécute la macro nom-macro définie avec la commande macdef. Les arguments sont passés à la macro sans expansion.
account [mot-de-passe]
Fournit un mot de passe supplémentaire requis par un système distant pour accéder aux ressources une fois qu'une connexion a été établie avec succès. Si aucun argument n'est fourni, l'utilisateur sera invité à saisir un mot de passe de compte en mode de saisie sans écho.
append fichier-local [fichier-distant]
Ajoute un fichier local à un fichier sur la machine distante. Si fichier-distant n'est pas spécifié, le nom du fichier local est utilisé pour nommer le fichier distant après avoir été modifié par les paramètres ntrans ou nmap. Le transfert de fichier utilise les paramètres actuels pour type, format, mode et structure.
ascii
Définit le type de transfert de fichier sur ASCII réseau. C'est le type par défaut.
bell
Arrange pour qu'une sonnerie retentisse après chaque commande de transfert de fichier terminée.
binary
Définit le type de transfert de fichier pour supporter le transfert d'image binaire.
bye
Termine la session FTP avec le serveur distant et quitte tnftp. Une fin de fichier terminera également la session et quittera.
case
Active ou désactive la mise en correspondance de la casse des noms de fichiers sur l'ordinateur distant pendant les commandes get, mget et mput. Lorsque case est activé (désactivé par défaut), les noms de fichiers sur l'ordinateur distant avec toutes les lettres en majuscules sont écrits dans le répertoire local avec les lettres converties en minuscules.
cd répertoire-distant
Change le répertoire de travail sur la machine distante pour répertoire-distant.
cdup
Change le répertoire de travail de la machine distante pour le parent du répertoire de travail distant actuel.
chmod mode fichier-distant
Change les permissions du fichier fichier-distant sur le système distant en mode.
close
Termine la session FTP avec le serveur distant et revient à l'interpréteur de commandes. Toutes les macros définies sont effacées.
cr
Active ou désactive la suppression des retours chariot lors de la récupération de fichiers de type ascii. Les enregistrements sont délimités par une séquence retour chariot/nouvelle ligne lors du transfert de fichiers de type ascii. Lorsque cr est activé (par défaut), les retours chariot sont supprimés de cette séquence pour se conformer au délimiteur d'enregistrement à une seule nouvelle ligne de UNIX. Les enregistrements sur les systèmes distants non-UNIX peuvent contenir des nouvelles lignes uniques ; lorsqu'un transfert de type ascii est effectué, ces nouvelles lignes ne peuvent être distinguées d'un délimiteur d'enregistrement que lorsque cr est désactivé.
debug [valeur-debug]
Active ou désactive le mode de débogage. Si une valeur-debug optionnelle est spécifiée, elle est utilisée pour définir le niveau de débogage. Lorsque le débogage est activé, tnftp affiche chaque commande envoyée à la machine distante, précédée de la chaîne ‘-->’.
delete fichier-distant
Supprime le fichier fichier-distant sur la machine distante.
dir [chemin-distant [fichier-local]]
Affiche une liste du contenu d'un répertoire sur la machine distante. La liste inclut toute information spécifique au système que le serveur choisit d'inclure ; par exemple, la plupart des systèmes UNIX produiront une sortie de la commande ‘ls -l’. Si chemin-distant n'est pas spécifié, le répertoire de travail actuel est utilisé. Si l'invite interactive est activée, tnftp demandera à l'utilisateur de vérifier que le dernier argument est bien le fichier local cible pour recevoir la sortie de dir. Si aucun fichier local n'est spécifié, ou si fichier-local est ‘-’, la sortie est envoyée au terminal.
disconnect
Un synonyme de close.
edit
Active ou désactive l'édition de ligne de commande et la complétion de commandes et de fichiers sensible au contexte. Ceci est automatiquement activé si l'entrée provient d'un terminal, et désactivé sinon.
epsv, epsv4, epsv6
Active ou désactive l'utilisation des commandes étendues EPSV et EPRT sur toutes les connexions IP, IPv4 et IPv6 respectivement. Essaye d'abord EPSV/EPRT, puis PASV/PORT. Ceci est activé par défaut. Si une commande étendue échoue, cette option sera temporairement désactivée pendant la durée de la connexion actuelle, ou jusqu'à ce que epsv, epsv4, ou epsv6 soit exécutée à nouveau.
exit
Un synonyme de bye.
features
Affiche les fonctionnalités prises en charge par le serveur distant (en utilisant la commande FEAT .).
fget fichier-local
Récupère les fichiers listés dans fichier-local, qui contient un nom de fichier par ligne.
form format
Définit le format de transfert de fichier sur format. Le format par défaut (et le seul supporté) est ‘non-print’.
ftp hôte [port]
Un synonyme de open.
gate [hôte [port]]
Active ou désactive le mode gate-ftp, qui était utilisé pour se connecter via les proxys FTP TIS FWTK et Gauntlet. Ceci ne sera pas autorisé si le serveur gate-ftp n'a pas été défini (soit explicitement par l'utilisateur, soit via la variable d'environnement FTPSERVER). Si hôte est donné, alors le mode gate-ftp sera activé, et le serveur gate-ftp sera défini sur hôte. Si port est également donné, il sera utilisé comme port de connexion sur le serveur gate-ftp.
get fichier-distant [fichier-local]
Récupère le fichier-distant et le stocke sur la machine locale. Si le nom du fichier local n'est pas spécifié, il reçoit le même nom qu'il avait sur la machine distante, sujet à modification par les paramètres actuels de case, ntrans et nmap. Les paramètres actuels pour type, form, mode et structure sont utilisés lors du transfert du fichier.
glob
Active ou désactive l'expansion des noms de fichiers pour mdelete, mget, mput et mreget. Si l'expansion est désactivée avec glob, les arguments de nom de fichier sont pris littéralement et non expansés. L'expansion pour mput se fait comme dans csh(1). Pour mdelete, mget et mreget, chaque nom de fichier distant est expansé séparément sur la machine distante et les listes ne sont pas fusionnées. L'expansion
du nom d'un répertoire est susceptible d'être différente de l'expansion du nom d'un fichier ordinaire : le résultat exact dépend du système d'exploitation étranger et du serveur FTP, et peut être prévisualisé en tapant ‘mls remote-files -’. Remarque : mget, mput et mreget ne sont pas conçus pour transférer des sous-arborescences entières de fichiers. Cela peut être fait en transférant une archive tar(1) de la sous-arborescence (en mode binaire).
hash [taille]
Active/désactive l'affichage du signe dièse (#) pour chaque bloc de données transféré. La taille d'un bloc de données est de 1024 octets par défaut. Cela peut être modifié en spécifiant taille en octets. L'activation de hash désactive progress.
help [commande]
Affiche un message informatif sur la signification de commande. Si aucun argument n'est fourni, tnftp affiche une liste des commandes connues.
idle [secondes]
Définit le minuteur d'inactivité sur le serveur distant à secondes secondes. Si secondes est omis, le minuteur d'inactivité actuel est affiché.
image
Un synonyme pour binary.
lcd [répertoire]
Change le répertoire de travail sur la machine locale. Si aucun répertoire n'est spécifié, le répertoire personnel de l'utilisateur est utilisé.
less fichier
Un synonyme pour page.
lpage fichier-local
Affiche fichier-local avec le programme spécifié par l'option set pager.
lpwd
Affiche le répertoire de travail sur la machine locale.
ls [chemin-distant [fichier-local]]
Un synonyme pour dir.
macdef nom-macro
Définit une macro. Les lignes suivantes sont stockées comme la macro nom-macro ; une ligne nulle (caractères de nouvelle ligne consécutifs dans un fichier ou retours chariot du terminal) termine le mode d'entrée de macro. Il y a une limite de 16 macros et 4096 caractères totaux dans toutes les macros définies. Les noms de macros peuvent comporter un maximum de 8 caractères. Les macros ne sont applicables qu'à la session actuelle dans laquelle elles sont définies (ou si définies en dehors d'une session, à la session invoquée avec la prochaine commande open), et restent définies jusqu'à ce qu'une commande close soit exécutée. Pour invoquer une macro, utilisez la commande $ (voir ci-dessus).

Le processeur de macro interprète ‘$’ et ‘\’ comme caractères spéciaux. Un ‘$’ suivi d'un ou plusieurs chiffres est remplacé par l'argument correspondant sur la ligne de commande d'invocation de macro. Un ‘$’ suivi d'un ‘i’ signale au processeur de macro que la macro en cours d'exécution doit être répétée en boucle. Lors du premier passage, ‘$i’ est remplacé par le premier argument sur la ligne de commande d'invocation de macro, lors du second passage, il est remplacé par le second argument, et ainsi de suite. Un ‘\’ suivi d'un caractère quelconque est remplacé par ce caractère. Utilisez le ‘\’ pour empêcher le traitement spécial du ‘$’.

mdelete [fichiers-distants]
Supprime les fichiers-distants sur la machine distante.
mdir fichiers-distants fichier-local
Semblable à dir, sauf que plusieurs fichiers distants peuvent être spécifiés. Si la demande interactive est activée, tnftp demandera à l'utilisateur de vérifier que le dernier argument est bien le fichier local cible pour la réception de la sortie de mdir.
mget fichiers-distants
Développe les fichiers-distants sur la machine distante et effectue un get pour chaque nom de fichier ainsi produit. Voir glob pour les détails sur l'expansion des noms de fichiers. Les noms de fichiers résultants seront ensuite traités selon les paramètres case, ntrans, et nmap. Les fichiers sont transférés dans le répertoire de travail local, qui peut être modifié avec lcd répertoire ; de nouveaux répertoires locaux peuvent être créés avec ! mkdir répertoire.
mkdir nom-répertoire
Crée un répertoire sur la machine distante.
mls fichiers-distants fichier-local
Semblable à ls, sauf que plusieurs fichiers distants peuvent être spécifiés, et le fichier-local doit être spécifié. Si la demande interactive est activée, tnftp demandera à l'utilisateur de vérifier que le dernier argument est bien le fichier local cible pour la réception de la sortie de mls.
mlsd [chemin-distant]
Affiche le contenu de chemin-distant (qui doit être le répertoire courant par défaut s'il n'est pas fourni) sous une forme analysable par machine, en utilisant MLSD. Le format d'affichage peut être modifié avec ‘remopts mlst ...’.
mlst [chemin-distant]
Affiche les détails sur chemin-distant (qui doit être le répertoire courant par défaut s'il n'est pas fourni) sous une forme analysable par machine, en utilisant MLST. Le format d'affichage peut être modifié avec ‘remopts mlst ...’.
mode nom-mode
Définit le mode de transfert de fichier à nom-mode. Le mode par défaut (et le seul supporté) est ‘stream’.
modtime fichier-distant
Affiche l'heure de dernière modification du fichier sur la machine distante, au format RFC 2822.
more fichier
Un synonyme pour page.
mput fichiers-locaux
Développe les caractères génériques dans la liste des fichiers locaux donnés en arguments et effectue un put pour chaque fichier de la liste résultante. Voir glob pour les détails de l'expansion des noms de fichiers. Les noms de fichiers résultants seront ensuite traités selon les paramètres ntrans et nmap.
mreget fichiers-distants
Comme mget, mais effectue un reget au lieu d'un get.
msend fichiers-locaux
Un synonyme pour mput.
newer fichier-distant [fichier-local]
Récupère le fichier uniquement si l'heure de modification du fichier distant est plus récente que le fichier sur le système actuel. Si le fichier n'existe pas sur le système actuel, le fichier distant est considéré comme newer. Sinon, cette commande est identique à get.
nlist [chemin-distant [fichier-local]]
Un synonyme pour ls.
nmap [motif-entree motif-sortie]
Définit ou annule le mécanisme de mappage des noms de fichiers. Si aucun argument n'est spécifié, le mécanisme de mappage des noms de fichiers est désactivé. Si des arguments sont spécifiés, les noms de fichiers distants sont mappés lors des commandes mput et des commandes put émises sans nom de fichier cible distant spécifié. Si des arguments sont spécifiés, les noms de fichiers locaux sont mappés lors des commandes mget et des commandes get émises sans nom de fichier cible local spécifié. Cette commande est utile lors de la connexion à un ordinateur distant non-UNIX avec des conventions ou pratiques de nommage de fichiers différentes. Le mappage suit le modèle défini par motif-entree et motif-sortie.

motif-entree est un modèle pour les noms de fichiers entrants (qui ont pu être traités selon les paramètres ntrans et case). Le templating de variable est réalisé en incluant les séquences ‘$1’, ‘$2’, ..., ‘$9’ dans motif-entree. Utilisez ‘\’ pour empêcher ce traitement spécial du caractère ‘$’. Tous les autres caractères sont traités littéralement et sont utilisés pour déterminer

<code class="Ic">nmap [inpattern] valeurs des variables. Par exemple, étant donné ‘$1.$2’ comme inpattern et ‘mydata.data’ comme nom de fichier distant, ‘$1’ aurait la valeur ‘mydata’, et ‘$2’ aurait la valeur ‘data’.

Le outpattern détermine le nom de fichier résultant de la mise en correspondance. Les séquences ‘$1’, ‘$2’, ..., ‘$9’ sont remplacées par toute valeur résultant du modèle inpattern. La séquence ‘$0’ est remplacée par le nom de fichier d'origine. De plus, la séquence [seq1,seq2] est remplacée par seq1 si seq1 n'est pas une chaîne nulle; sinon, elle est remplacée par seq2. Par exemple, la commande

nmap $1.$2.$3 [$1,$2].[$2,file]

produirait le nom de fichier de sortie ‘myfile.data’ pour les noms de fichiers d'entrée ‘myfile.data’ et ‘myfile.data.old’, ‘myfile.file’ pour le nom de fichier d'entrée ‘myfile’, et ‘myfile.myfile’ pour le nom de fichier d'entrée ‘.myfile’. Des espaces peuvent être inclus dans outpattern, comme dans l'exemple :

nmap $1 sed s/ *$// > $1

Utilisez le caractère ‘\’ pour empêcher le traitement spécial des caractères ‘$’, ‘[’, ‘]’ et ‘,’.

ntrans [inchars [outchars]]
Définit ou annule le mécanisme de traduction des caractères des noms de fichiers. Si aucun argument n'est spécifié, le mécanisme de traduction des caractères des noms de fichiers est annulé. Si des arguments sont spécifiés, les caractères des noms de fichiers distants sont traduits pendant les commandes mput et les commandes put émises sans nom de fichier distant spécifié. Si des arguments sont spécifiés, les caractères des noms de fichiers locaux sont traduits pendant les commandes mget et les commandes get émises sans nom de fichier local spécifié. Cette commande est utile lors de la connexion à un ordinateur distant non-UNIX avec des conventions ou pratiques de nommage de fichiers différentes. Les caractères d'un nom de fichier correspondant à un caractère de inchars sont remplacés par le caractère correspondant dans outchars. Si la position du caractère dans inchars est plus longue que la longueur de outchars, le caractère est supprimé du nom de fichier.
open host [port]
Établit une connexion au serveur FTP spécifié host. Un numéro de port optionnel peut être fourni, auquel cas, tnftp tentera de contacter un serveur FTP sur ce port. Si l'option set auto-login est activée (par défaut), tnftp tentera également de connecter automatiquement l'utilisateur au serveur FTP (voir ci-dessous).
page file
Récupère file et l'affiche avec le programme spécifié par l'option set pager.
passive [auto]
Active ou désactive le mode passif (si aucun argument n'est donné). Si auto est donné, agit comme si FTPMODE était défini sur ‘auto’. Si le mode passif est activé (par défaut), tnftp enverra une commande PASV pour toutes les connexions de données au lieu d'une commande PORT. La commande PASV demande au serveur distant d'ouvrir un port pour la connexion de données et de renvoyer l'adresse de ce port. Le serveur distant écoute sur ce port et le client s'y connecte. Lors de l'utilisation de la commande PORT plus traditionnelle, le client écoute sur un port et envoie cette adresse au serveur distant, qui s'y connecte. Le mode passif est utile lors de l'utilisation de tnftp via un routeur ou un hôte passerelle qui contrôle la directionnalité du trafic. (Notez que bien que les serveurs FTP soient requis de supporter la commande PASV par la RFC 1123, certains ne le font pas.)
pdir [remote-path]
Exécute dir [remote-path], et affiche le résultat avec le programme spécifié par l'option set pager.
pls [remote-path]
Exécute ls [remote-path], et affiche le résultat avec le programme spécifié par l'option set pager.
pmlsd [remote-path]
Exécute mlsd [remote-path], et affiche le résultat avec le programme spécifié par l'option set pager.
preserve
Active ou désactive la préservation des temps de modification sur les fichiers récupérés.
progress
Active ou désactive l'affichage de la barre de progression du transfert. La barre de progression sera désactivée pour un transfert dont le local-file est ‘-’ ou pour une commande commençant par ‘|’. Se référer à FILE NAMING CONVENTIONS pour plus d'informations. L'activation de progress désactive hash.
prompt
Active ou désactive la demande d'interaction. La demande d'interaction se produit lors des transferts de plusieurs fichiers pour permettre à l'utilisateur de sélectionner les fichiers à récupérer ou à stocker. Si la demande est désactivée (désactivée par défaut), tout mget ou mput transférera tous les fichiers, et tout mdelete supprimera tous les fichiers.

Lorsque la demande est activée, les commandes suivantes sont disponibles à l'invite :

a
Répond ‘oui’ au fichier actuel, et répond automatiquement ‘oui’ à tous les fichiers restants pour la commande actuelle.
n
Répond ‘non’, et ne transfère pas le fichier.
p
Répond ‘oui’ au fichier actuel, et désactive le mode de demande (comme si prompt off avait été exécuté).
q
Termine l'opération en cours.
y
Répond ‘oui’, et transfère le fichier.
?
Affiche un message d'aide.

Toute autre réponse répondra ‘oui’ au fichier actuel.

proxy ftp-command
Exécute une commande FTP sur une connexion de contrôle secondaire. Cette commande permet une connexion simultanée à deux serveurs FTP distants pour le transfert de fichiers entre les deux serveurs. La première commande proxy doit être un open, pour établir la connexion de contrôle secondaire. Entrez la commande ‘proxy ?’ pour voir les autres commandes FTP exécutables sur la connexion secondaire. Les commandes suivantes se comportent différemment lorsqu'elles sont précédées par proxy : open ne définira pas de nouvelles macros pendant le processus de connexion automatique, close n'effacera pas les définitions de macros existantes, get et mget transfèrent des fichiers de l'hôte sur la connexion de contrôle primaire vers l'hôte sur la connexion de contrôle secondaire, et put, mput et append transfèrent des fichiers de l'hôte sur la connexion de contrôle secondaire vers l'hôte sur la connexion de contrôle primaire. Les transferts de fichiers tiers dépendent du support de la commande PASV du protocole FTP par le serveur sur la connexion de contrôle secondaire.

TÉLÉCHARGEMENT AUTOMATIQUE DE FICHIERS

En plus des commandes standard, cette version de tnftp prend en charge une fonctionnalité de téléchargement automatique. Pour activer le téléchargement automatique, passez simplement la liste des noms d'hôtes/fichiers sur la ligne de commande.

Les formats suivants sont une syntaxe valide pour un élément de téléchargement automatique :

[user@]host:[path][/]
Format FTP « classique ».

Si path contient un caractère glob et que le globbing est activé (voir glob), alors l'équivalent de mget path est effectué.

Si le composant répertoire de path ne contient aucun caractère de globbing, il est stocké localement avec le nom de base (voir basename(1)) de path, dans le répertoire courant. Sinon, le nom distant complet est utilisé comme nom local, par rapport au répertoire racine local.

ftp://[user[:password]@]host[:port]/path[/][;type=type]
Une URL FTP, récupérée en utilisant le protocole FTP si set ftp_proxy n'est pas défini. Sinon, transférez l'URL en utilisant HTTP via le proxy défini dans set ftp_proxy. Si set ftp_proxy n'est pas défini et que user est fourni, connectez-vous en tant que user. Dans ce cas, utilisez password s'il est fourni, sinon demandez-le à l'utilisateur.

Si un suffixe de « ;type=A » ou « ;type=I » est fourni, alors le type de transfert sera en mode ascii ou binaire (respectivement). Le type de transfert par défaut est binaire.

Afin d'être conforme à la RFC 3986, tnftp interprète la partie path d'une URL de téléchargement automatique « ftp:// » comme suit :

  • Le « / » immédiatement après l'host[:port] est interprété comme un séparateur avant le path, et non comme faisant partie du path lui-même.
  • Le path est interprété comme une liste de composants de nom séparés par « / ». Pour tous les composants sauf le dernier, tnftp effectue l'équivalent d'une commande cd. Pour le dernier composant de chemin, tnftp effectue l'équivalent d'une commande get.
  • Les composants de nom vides, qui résultent de « // » dans le path, ou d'un « / » supplémentaire au début du path, provoqueront l'équivalent d'une commande cd sans nom de répertoire. Ceci est peu susceptible d'être utile.
  • Les codes « %XX » (selon la RFC 3986) dans les composants du chemin sont décodés, XX représentant un code de caractère en hexadécimal. Ce décodage a lieu après que le path a été divisé en composants, mais avant que chaque composant ne soit utilisé dans l'équivalent d'une commande cd ou get. Certains codes fréquemment utilisés sont « %2F » (qui représente « / ») et « %7E » (qui représente « ~ »).

L'interprétation ci-dessus a les conséquences suivantes :

  • Le chemin est interprété par rapport au répertoire de connexion par défaut de l'utilisateur spécifié ou de l'utilisateur « anonymous ». Si le répertoire / est requis, utilisez un chemin de début de « %2F ». Si le répertoire personnel d'un utilisateur est requis (et que le serveur distant prend en charge la syntaxe), utilisez un chemin de début de « %7Euser/ ». Par exemple, pour récupérer /etc/motd depuis « localhost » en tant qu'utilisateur « myname » avec le mot de passe « mypass », utilisez « ftp://myname:mypass@localhost/%2fetc/motd »
  • Les commandes exactes cd et get peuvent être contrôlées par un choix judicieux de l'endroit où utiliser « / » et où utiliser « %2F » (ou « %2f »). Par exemple, les URL suivantes correspondent aux équivalents des commandes indiquées :
    ftp://host/dir1/dir2/file
    cd dir1, cd dir2, get file.
    ftp://host/%2Fdir1/dir2/file
    cd /dir1, cd dir2, get file.
    ftp://host/dir1%2Fdir2/file
    cd dir1/dir2, get file.
  • Vous devez disposer des autorisations d'accès appropriées pour chacun des répertoires intermédiaires utilisés dans l'équivalent d'une commande cd.

FORMAT DES URL

Les URL suivantes sont comprises. Les éléments entre chevrons obliques (chevrons) sont des variables et les éléments entre crochets ([éléments]) sont optionnels.

http://[utilisateur[:mot de passe]@]hôte[:port]/chemin
Une URL HTTP, récupérée en utilisant le protocole HTTP. Si set http_proxy est définie, elle est utilisée comme une URL vers un serveur proxy HTTP. Si une autorisation HTTP est requise pour récupérer chemin, et que utilisateur (et optionnellement mot de passe) est dans l'URL, utilisez-les pour la première tentative d'authentification.
https://[utilisateur[:mot de passe]@]hôte[:port]/chemin
Une URL HTTPS, récupérée en utilisant le protocole HTTPS. Si set https_proxy est définie, elle est utilisée comme une URL vers un serveur proxy HTTPS. Si une autorisation HTTPS est requise pour récupérer chemin, et que utilisateur (et optionnellement mot de passe) est dans l'URL, utilisez-les pour la première tentative d'authentification. Il n'y a actuellement aucune validation ni vérification de certificat.
file:///chemin
Une URL locale, copiée depuis /chemin sur la machine locale.
about:sujet
Affiche des informations concernant sujet ; aucun fichier n'est récupéré pour cet élément auto-téléchargé. Les valeurs prises en charge incluent :
about:ftp
Informations sur tnftp.
about:version
La version de tnftp. Utile à fournir lors du signalement de problèmes.

Sauf indication contraire ci-dessus, et si -o sortie n'est pas donné, le fichier est stocké dans le répertoire courant sous le nom de basename(1) de chemin. Notez que si une redirection HTTP est reçue, le transfert est retenté en utilisant l'URL cible fournie par le serveur, avec un chemin correspondant. L'utilisation explicite de -o sortie est recommandée pour éviter d'écrire dans des noms de fichiers inattendus.

Si un format classique ou un format d'URL FTP a un ‘/’ final ou un composant chemin vide, alors tnftp se connectera au site et entrera dans le répertoire donné comme chemin, et laissera l'utilisateur en mode interactif prêt pour une entrée ultérieure. Cela ne fonctionnera pas si set ftp_proxy est utilisé.

Les transferts HTTP directs utilisent HTTP 1.1. Les transferts FTP et HTTP proxysés utilisent HTTP 1.0.

Si -R est donné, tous les auto-téléchargements qui ne passent pas par les proxies FTP ou HTTP seront redémarrés. Pour FTP, cela est implémenté en utilisant reget au lieu de get. Pour HTTP, cela est implémenté en utilisant la directive HTTP/1.1 ‘Range: bytes=’.

Si une authentification WWW ou proxy WWW est requise, vous serez invité à entrer un nom d'utilisateur et un mot de passe pour vous authentifier.

Lors de la spécification d'adresses numériques IPv6 dans une URL, vous devez entourer l'adresse de crochets. Par exemple : ‘ftp://[::1]:21/’. Ceci est dû au fait que les deux-points sont utilisés dans les adresses numériques IPv6 ainsi que comme séparateur pour le numéro de port.

INTERRUPTION D'UN TRANSFERT DE FICHIER

Pour interrompre un transfert de fichier, utilisez la touche d'interruption du terminal (généralement Ctrl-C). Les transferts sortants seront immédiatement stoppés. Les transferts entrants seront stoppés en envoyant une commande FTP ABOR au serveur distant, et en ignorant toute donnée supplémentaire reçue. La vitesse à laquelle cela est accompli dépend du support par le serveur distant du traitement de ABOR. Si le serveur distant ne supporte pas la commande ABOR, l'invite n'apparaîtra pas avant que le serveur distant ait fini d'envoyer le fichier demandé.

Si la séquence de touches d'interruption du terminal est utilisée pendant que tnftp attend une réponse du serveur distant pour le traitement de ABOR, la connexion sera fermée. Ceci est différent du comportement traditionnel (qui ignore l'interruption du terminal pendant cette phase), mais est considéré comme plus utile.

CONVENTIONS DE NOMMAGE DES FICHIERS

Les fichiers spécifiés comme arguments aux commandes tnftp sont traités selon les règles suivantes.

  1. Si le nom de fichier ‘-’ est spécifié, stdin (pour la lecture) ou stdout (pour l'écriture) est utilisé.
  2. Si le premier caractère du nom de fichier est ‘|’, le reste de l'argument est interprété comme une commande shell. tnftp lance alors un shell, en utilisant popen(3) avec l'argument fourni, et lit (écrit) depuis la sortie standard (entrée standard). Si la commande shell inclut des espaces, l'argument doit être mis entre guillemets ; par exemple : ‘"| ls -lt"’. Un exemple particulièrement utile de ce mécanisme est : ‘dir "" |more’.
  3. Si les vérifications ci-dessus échouent, et si le globbing est activé, les noms de fichiers locaux sont étendus selon les règles utilisées dans csh(1) ; voir la commande glob. Si la commande tnftp attend un seul fichier local (par exemple put), seul le premier nom de fichier généré par l'opération de globbing est utilisé.
  4. Pour les commandes mget et les commandes get avec des noms de fichiers locaux non spécifiés, le nom de fichier local est le nom de fichier distant, qui peut être modifié par un paramètre case, ntrans, ou nmap. Le nom de fichier résultant peut ensuite être modifié si runique est activé.
  5. Pour les commandes mput et les commandes put avec des noms de fichiers distants non spécifiés, le nom de fichier distant est le nom de fichier local, qui peut être modifié par un paramètre ntrans ou nmap. Le nom de fichier résultant peut ensuite être modifié par le serveur distant si sunique est activé.

PARAMETRES DE TRANSFERT DE FICHIER

La spécification FTP définit de nombreux paramètres qui peuvent affecter un transfert de fichier. Le type peut être l'un parmi “ascii”, “image” (binaire), “ebcdic”, et “taille en octets locale” (principalement pour les PDP-10 et PDP-20). tnftp supporte les types ascii et image de transfert de fichiers, plus la taille en octets locale 8 pour les transferts en mode tenex.

tnftp ne supporte que les valeurs par défaut pour les paramètres de transfert de fichiers restants : mode, form, et struct.

LE FICHIER .netrc

Le fichier .netrc contient des informations de connexion et d'initialisation utilisées par le processus de connexion automatique. Il réside dans le répertoire personnel de l'utilisateur, sauf s'il est remplacé par l'option -N netrc, ou spécifié dans la variable d'environnement NETRC. Les jetons suivants sont reconnus ; ils peuvent être séparés par des espaces, des tabulations ou des nouvelles lignes :

machine nom
Identifie une machine distante nom. Le processus de connexion automatique recherche dans le fichier .netrc un jeton machine qui correspond à la machine distante spécifiée sur la ligne de commande tnftp ou comme argument de commande open. Une fois une correspondance trouvée, les jetons .netrc suivants sont traités, s'arrêtant à la fin du fichier ou lorsqu'un autre jeton machine ou default est rencontré.
default
Ceci est identique à machine nom sauf que default correspond à n'importe quel nom. Il ne peut y avoir qu'un seul jeton default, et il doit être après tous les jetons machine. Ceci est normalement utilisé comme :
default login anonymous password user@site

donnant ainsi à l'utilisateur une connexion FTP anonyme automatique aux machines non spécifiées dans .netrc. Ceci peut être remplacé en utilisant le drapeau -n pour désactiver la connexion automatique.

login nom
Identifie un utilisateur sur la machine distante. Si ce jeton est présent, le processus de connexion automatique initiera une connexion en utilisant le nom spécifié.
password chaîne
Fournit un mot de passe. Si ce jeton est présent, le processus de connexion automatique fournira la chaîne spécifiée si le serveur distant requiert un mot de passe dans le cadre du processus de connexion. Notez que si ce jeton est présent dans le fichier .netrc pour un utilisateur autre qu'anonymous, tnftp interrompra le processus de connexion automatique si .netrc est lisible par quelqu'un d'autre que l'utilisateur.
account cha tring
Fournir un mot de passe de compte supplémentaire. Si ce jeton est présent, le processus de connexion automatique fournira la chaîne spécifiée si le serveur distant nécessite un mot de passe de compte supplémentaire, ou le processus de connexion automatique initiera une commande ACCT s'il n'en a pas besoin.
macdef name
Définir une macro. Ce jeton fonctionne comme la commande tnftp macdef. Une macro est définie avec le nom spécifié ; son contenu commence à la ligne .netrc suivante et se poursuit jusqu'à ce qu'une ligne vide (caractères de nouvelle ligne consécutifs) soit rencontrée. Comme les autres jetons du fichier .netrc, un macdef n'est applicable qu'à la définition machine qui le précède. Une entrée macdef ne peut pas être utilisée par plusieurs définitions machine ; elle doit plutôt être définie après chaque machine avec laquelle elle est censée être utilisée. Si une macro nommée init est définie, elle est automatiquement exécutée comme dernière étape du processus de connexion automatique. Par exemple, 
default
macdef init
epsv4 off

suivi d'une ligne vide.

MODIFICATION DE LIGNE DE COMMANDE

tnftp prend en charge la modification interactive de la ligne de commande, via la bibliothèque editline(3). Elle est activée avec la commande edit et est activée par défaut si l'entrée provient d'un tty. Les lignes précédentes peuvent être rappelées et modifiées avec les touches fléchées, et d'autres touches d'édition de style GNU Emacs peuvent également être utilisées.

La bibliothèque editline(3) est configurée avec un fichier .editrc ; reportez-vous à editrc(5) pour plus d'informations.

Une liaison de touche supplémentaire est disponible pour tnftp afin de fournir une complétion contextuelle des commandes et des noms de fichiers (y compris la complétion des fichiers distants). Pour l'utiliser, liez une touche à la commande editline(3) ftp-complete. Par défaut, celle-ci est liée à la touche TAB.

Par défaut, tnftp affiche une invite de commande ‘ftp> ’ à l'utilisateur. Celle-ci peut être modifiée avec la commande set prompt.

Une invite peut être affichée sur le côté droit de l'écran (après la saisie de la commande) avec la commande set rprompt.

Le nom d'hôte distant, jusqu'au premier point ‘.’.

Le nom d'utilisateur distant.

Un seul caractère pourcentage ‘%’.

URL du proxy FTP à utiliser lors de la création de requêtes d'URL FTP (si non défini, utilisez le protocole FTP standard).

Voir http_proxy pour des notes supplémentaires sur l'utilisation des proxys.

http_proxy
URL du proxy HTTP à utiliser lors de la création de requêtes d'URL HTTP. Si une authentification de proxy est requise et qu'il y a un nom d'utilisateur et un mot de passe dans cette URL, ils seront automatiquement utilisés lors de la première tentative d'authentification auprès du proxy.

Si des caractères d'URL « dangereux » sont requis dans le nom d'utilisateur ou le mot de passe (par exemple ‘@’ ou ‘/’), encodez-les avec l'encodage ‘%XX’ de la RFC 3986.

Notez que l'utilisation d'un nom d'utilisateur et d'un mot de passe dans ftp_proxy et http_proxy peut être incompatible avec d'autres programmes qui l'utilisent (comme lynx(1)).

NOTE: ceci n'est pas utilisé pour les sessions interactives, seulement pour les récupérations en ligne de commande.

https_proxy
URL du proxy HTTPS à utiliser lors de la création de requêtes d'URL HTTPS.

Voir http_proxy pour des notes supplémentaires sur l'utilisation des proxys.

no_proxy
Une liste d'hôtes (ou de domaines) séparés par des espaces ou des virgules pour lesquels le proxy ne doit pas être utilisé. Chaque entrée peut avoir un suffixe facultatif ‘:port’, qui restreint la correspondance aux connexions vers ce port.

MODE PASSIF ÉTENDU ET FIREWALLS

Certaines configurations de pare-feu ne permettent pas à tnftp d'utiliser le mode passif étendu. Si vous constatez que même un simple ls semble se bloquer après avoir affiché un message tel que celui-ci :

229 Entering Extended Passive Mode (|||58551|)

alors vous devrez désactiver le mode passif étendu avec epsv4 off. Voir la section ci-dessus Le fichier .netrc pour un exemple sur la façon de rendre cela automatique.

HISTORIQUE

tnftp est apparu dans 4.2BSD.

Diverses fonctionnalités telles que l'édition de ligne de commande, la complétion de commande et de fichier sensible au contexte, la barre de progression dynamique, la récupération automatique de fichiers et d'URL, la préservation de l'heure de modification, la limitation du taux de transfert, l'invite de commande configurable et d'autres améliorations par rapport à tnftp standard BSD ont été implémentées dans NetBSD 1.3 et les versions ultérieures par Luke Mewburn ⟨lukem@NetBSD.org⟩.

Le support IPv6 a été ajouté par le projet WIDE/KAME (mais peut ne pas être présent dans toutes les versions non-NetBSD de ce programme, selon que le système d'exploitation prend en charge IPv6 d'une manière similaire à KAME).

BOGUES

L'exécution correcte de nombreuses commandes dépend du comportement approprié du serveur distant.

Une erreur dans le traitement des retours chariot dans le code de transfert en mode ascii de 4.2BSD a été corrigée. Cette correction peut entraîner des transferts incorrects de fichiers binaires vers et depuis les serveurs 4.2BSD utilisant le type ascii. Évitez ce problème en utilisant le type image binaire.

tnftp suppose que toutes les adresses mappées IPv4 (adresses IPv6 de la forme ::ffff:10.1.1.1) indiquent des destinations IPv4 qui peuvent être gérées par des sockets AF_INET. Cependant, dans certaines configurations réseau IPv6, cette hypothèse n'est pas vraie. Dans un tel environnement, les adresses mappées IPv4 doivent être passées directement aux sockets AF_INET6. Par exemple, si votre site utilise un traducteur SIIT pour la traduction IPv6 vers IPv4, tnftp ne peut pas prendre en charge votre configuration.
