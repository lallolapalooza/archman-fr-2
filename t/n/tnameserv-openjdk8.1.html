tnameserv(1) Outils Java IDL et RMI-IIOP tnameserv(1)

NOM

tnameserv - Interface Definition Language (IDL).

SYNTAXE

tnameserve -ORBInitialPort [ port_serveur_de_noms ]
-ORBInitialPort port_serveur_de_noms

Le port initial où le serveur de noms écoute pour le protocole de démarrage utilisé pour implémenter les méthodes resolve_initial_references et list_initial_references de l'ORB.

DESCRIPTION

Java IDL inclut le démon ORBD (Object Request Broker Daemon). ORBD est un processus démon qui contient un service de démarrage, un service de nommage transitoire, un service de nommage persistant et un gestionnaire de serveur. Les tutoriels Java IDL utilisent tous ORBD, mais vous pouvez substituer la commande tnameserv à la commande orbd dans n'importe quel exemple utilisant un service de nommage transitoire.

Voir orbd(1) ou Service de Noms sur http://docs.oracle.com/javase/8/docs/technotes/guides/idl/jidlNaming.html

Le service de nommage COS (Common Object Services) de CORBA fournit un répertoire en structure arborescente pour les références d'objets, similaire à un système de fichiers qui fournit une structure de répertoire pour les fichiers. Le service de nommage transitoire fourni avec Java IDL, tnameserv, est une implémentation simple de la spécification du service de nommage COS.

Les références d'objets sont stockées dans l'espace de noms par nom, et chaque paire référence d'objet-nom est appelée une liaison de nom. Les liaisons de noms peuvent être organisées sous des contextes de nommage. Les contextes de nommage sont des liaisons de noms et servent la même fonction organisationnelle qu'un sous-répertoire de système de fichiers. Toutes les liaisons sont stockées sous le contexte de nommage initial. Le contexte de nommage initial est la seule liaison persistante dans l'espace de noms. Le reste de l'espace de noms est perdu lorsque le processus du service de nommage Java IDL s'arrête et redémarre.

Pour qu'une applet ou une application utilise le nommage COS, son ORB doit connaître le port d'une machine exécutant un service de nommage ou avoir accès à une chaîne de contexte de nommage initiale pour ce service de nommage. Le service de nommage peut être soit le service de nommage Java IDL, soit un autre service de nommage conforme COS.

DÉMARRER LE SERVICE DE NOMS

Vous devez démarrer le service de nommage Java IDL avant une application ou une applet qui utilise son service de nommage. L'installation du produit Java IDL crée un script (Oracle Solaris : tnameserv) ou un fichier exécutable (Windows : tnameserv.exe) qui démarre le service de nommage Java IDL. Démarrez le service de nommage de sorte qu'il s'exécute en arrière-plan.

Si vous ne spécifiez pas autrement, le service de nommage Java IDL écoute sur le port 900 pour le protocole de démarrage utilisé pour implémenter les méthodes ORB resolve_initial_references et list_initial_references, comme suit :

tnameserv -ORBInitialPort port_serveur_de_noms&

Si vous ne spécifiez pas le port du serveur de noms, le port 900 est utilisé par défaut. Lors de l'exécution du logiciel Oracle Solaris, vous devez devenir l'utilisateur root pour démarrer un processus sur un port inférieur à 1024. Pour cette raison, il est recommandé d'utiliser un numéro de port supérieur ou égal à 1024. Pour spécifier un autre port, par exemple, 1050, et pour exécuter le service de nommage en arrière-plan, tapez depuis un shell de commande UNIX :

tnameserv -ORBInitialPort 1050&

Depuis une invite de commande MS-DOS (Windows), tapez :

start tnameserv -ORBInitialPort 1050

Les clients du serveur de noms doivent être informés du nouveau numéro de port. Pour ce faire, définissez la propriété org.omg.CORBA.ORBInitialPort sur le nouveau numéro de port lors de la création de l'objet ORB.

EXÉCUTER LE SERVEUR ET LE CLIENT SUR DES HÔTES DIFFÉRENTS

Dans la plupart des tutoriels Java IDL et RMI-IIOP, le service de noms, le serveur et le client s'exécutent tous sur la machine de développement. En déploiement réel, le client et le serveur s'exécutent probablement sur des machines hôtes différentes de celles du service de noms.

Pour que le client et le serveur trouvent le service de noms, ils doivent être informés du numéro de port et de l'hôte sur lesquels le service de noms s'exécute. Pour ce faire, définissez les propriétés org.omg.CORBA.ORBInitialPort et org.omg.CORBA.ORBInitialHost dans les fichiers client et serveur avec le nom de la machine et le numéro de port sur lesquels le service de noms s'exécute. Un exemple de cela est montré dans Getting Started Using RMI-IIOP sur http://docs.oracle.com/javase/8/docs/technotes/guides/rmi-iiop/rmiiiopexample.html

Vous pourriez également utiliser les options de ligne de commande -ORBInitialPort port_serveur_de_noms# et -ORBInitialHost nom_hote_serveur_de_noms pour indiquer au client et au serveur où trouver le service de noms. Pour un exemple de la façon de le faire en utilisant l'option de ligne de commande, voir Java IDL : L'exemple Hello World sur deux machines sur http://docs.oracle.com/javase/8/docs/technotes/guides/idl/tutorial/jidl2machines.html

Par exemple, supposons que le service de noms transitoire, tnameserv, s'exécute sur le port 1050 sur l'hôte nom_hote_serveur. Le client s'exécute sur l'hôte nom_hote_client, et le serveur s'exécute sur l'hôte nom_hote_serveur.

Démarrez tnameserv sur l'hôte nom_hote_serveur :

tnameserv -ORBInitialPort 1050

Démarrez le serveur sur l'hôte nom_hote_serveur :

java Server -ORBInitialPort 1050 -ORBInitialHost nom_hote_serveur

Démarrez le client sur l'hôte nom_hote_client :

java Client -ORBInitialPort 1050 -ORBInitialHost nom_hote_serveur

ARRÊTER LE SERVICE DE NOMS

Pour arrêter le service de nommage Java IDL, utilisez la commande du système d'exploitation appropriée, telle que kill pour un processus Unix ou Ctrl+C pour un processus Windows. Le service de nommage continue d'attendre les invocations jusqu'à ce qu'il soit explicitement arrêté. Notez que les noms enregistrés auprès du service de nommage Java IDL disparaissent lorsque le service est terminé.

OPTIONS

-Joption

Transmet option à la machine virtuelle Java, où option est l'une des options décrites sur la page de référence du lanceur d'application Java. Par exemple, -J-Xms48m définit la mémoire de démarrage à 48 Mo. Voir java(1).

tnameserv(1) - Arch manual pages

NAME

tnameserv, the Java ORB Name Server

SYNOPSIS

tnameserv [ options ]

DESCRIPTION

tnameserv is the Java ORB Name Server. It provides the CORBA naming service. This service allows CORBA clients and servers to locate each other in a network.

OPTIONS

The Java ORB Name Server does not currently accept any command line arguments.

EXAMPLES

The following sample program shows how to bind objects to the name space.

import java.util.Properties;
import org.omg.CORBA.*;
import org.omg.CosNaming.*;

public class NameServer {

    public static void main(String args[]) {

        try {

// Start the Naming Service
            Properties props = new Properties();
            props.put("org.omg.CORBA.ORBInitialPort", "1050");
            ORB orb = ORB.init(args, props);

// obtain the initial naming context
            NamingContext ctx =
                NamingContextHelper.narrow(
                    orb.resolve_initial_references("NameService"));
             NamingContext objref = ctx;

// bind the name "plans" to the naming context
            NameComponent nc1 = new NameComponent("plans", "text");
            NameComponent[] name1 = {nc1};
            ctx.rebind(name1, objref);
            System.out.println("plans rebind successful!");

// create a new naming context called "Personal"
            NameComponent nc2 = new NameComponent("Personal", "directory");
            NameComponent[] name2 = {nc2};
            NamingContext ctx2 = ctx.bind_new_context(name2);
            System.out.println("new naming context added..");

// bind the name "schedule" and "calender" under the "Personal" context
            NameComponent nc3 = new NameComponent("schedule", "text");
            NameComponent[] name3 = {nc3};
            ctx2.rebind(name3, objref);
            System.out.println("schedule rebind successful!");

            NameComponent nc4 = new NameComponent("calender", "text");
            NameComponent[] name4 = {nc4};
            ctx2.rebind(name4, objref);
            System.out.println("calender rebind successful!");
        } catch (Exception e) {
            e.printStackTrace(System.err);
        }
    }
}

This code obtains the initial naming context and assigns it to ctx. The second line copies ctx into a dummy object reference objref that is attached to various names and added into the name space.

            NamingContext ctx =
                NamingContextHelper.narrow(
                    orb.resolve_initial_references("NameService"));
             NamingContext objref = ctx;

This code creates a name plans of type text and binds it to the dummy object reference. plans is then added under the initial naming context using the rebind method. The rebind method enables you to run this program over and over again without getting the exceptions from using the bind method.

            NameComponent nc1 = new NameComponent("plans", "text");
            NameComponent[] name1 = {nc1};
            ctx.rebind(name1, objref);
            System.out.println("plans rebind successful!");

This code creates a naming context called Personal of type directory. The resulting object reference, ctx2, is bound to the name and added under the initial naming context.

            NameComponent nc2 = new NameComponent("Personal", "directory");
            NameComponent[] name2 = {nc2};
            NamingContext ctx2 = ctx.bind_new_context(name2);
            System.out.println("new naming context added..");

The remainder of the code binds the dummy object reference using the names schedule and calendar under the Personal naming context (ctx2).

            NameComponent nc3 = new NameComponent("schedule", "text");
            NameComponent[] name3 = {nc3};
            ctx2.rebind(name3, objref);
            System.out.println("schedule rebind successful!");

            NameComponent nc4 = new NameComponent("calender", "text");
            NameComponent[] name4 = {nc4};
            ctx2.rebind(name4, objref);
            System.out.println("calender rebind successful!");
        } catch (Exception e) {
            e.printStackTrace(System.err);
        }
    }
}

import java.util.Properties;
import org.omg.CORBA.*;
import org.omg.CosNaming.*;

public class NameClientList {

        try {


In Start the Naming Service, the nameserver was started on
    port 1050. The following code ensures that the client program is aware of
    this port number.


            Properties props = new Properties();
            props.put("org.omg.CORBA.ORBInitialPort", "1050");
            ORB orb = ORB.init(args, props);




The following code obtains the initial naming context.


            NamingContext nc =
            NamingContextHelper.narrow(
                orb.resolve_initial_references("NameService"));




The list method lists the bindings in the naming context.
    In this case, up to 1000 bindings from the initial naming context will be
    returned in the BindingListHolder; any remaining bindings are
    returned in the BindingIteratorHolder.


            BindingListHolder bl = new BindingListHolder();
            BindingIteratorHolder blIt= new BindingIteratorHolder();
            nc.list(1000, bl, blIt);




This code gets the array of bindings out of the returned
    BindingListHolder. If there are no bindings, then the program
  ends.


            Binding bindings[] = bl.value;
            if (bindings.length == 0) return;




The remainder of the code loops through the bindings and prints
    outs the names.


            for (int i=0; i < bindings.length; i++) {

                // get the object reference for each binding
                org.omg.CORBA.Object obj = nc.resolve(bindings[i].binding_name);
                String objStr = orb.object_to_string(obj);
                int lastIx = bindings[i].binding_name.length-1;

                // check to see if this is a naming context
                if (bindings[i].binding_type == BindingType.ncontext) {
                    System.out.println("Context: " +
                        bindings[i].binding_name[lastIx].id);
                } else {
                    System.out.println("Object: " +
                        bindings[i].binding_name[lastIx].id);
                }
            }
        } catch (Exception e) {
            e.printStackTrace(System.err)
        }
    }
}
