BIBLIOTHÈQUE

Bibliothèque d'API compatible TrueCrypt (libtcplay, -ltcplay)

DESCRIPTION

La bibliothèque tcplay fournit une interface pour créer, interroger, monter et gérer des volumes compatibles TrueCrypt.

La fonction tc_api_init() initialise les mécanismes internes de la bibliothèque et la prépare à être utilisée via l'API. Cette fonction doit être appelée avant d'utiliser toute autre fonction de l'API. Si l'argument verbose est non nul, la bibliothèque affichera des informations, telles que les erreurs, via stdout et stderr.

La fonction tc_api_uninit() nettoie toute la mémoire sécurisée interne, telle que la mémoire utilisée pour les en-têtes décryptés, les phrases de passe, les fichiers clés, etc.

La fonction tc_api_has() vérifie si la bibliothèque tcplay chargée possède la fonctionnalité spécifiée par l'argument feature. La version actuelle de la bibliothèque tcplay prend en charge les fonctionnalités suivantes :

Fonctionnalité Description
trim Permet d'activer les suppressions/TRIM lors du montage d'un volume

La fonction tc_api_cipher_iterate() passe chaque chaîne de chiffrement disponible à la fonction de rappel fournie dans l'argument fn. L'argument priv est transmis à chaque appel de la fonction de rappel. Le nom de la chaîne de chiffrement est passé à la fonction de rappel dans l'argument name. De même, l'argument ciphers_in_chain contient le nombre de chiffrements dans la chaîne actuelle, et key_length_in_bits contient la longueur totale de la clé pour la chaîne de chiffrement, en bits.

La fonction tc_api_prf_iterate() passe chaque chaîne de chiffrement disponible à la fonction de rappel fournie dans l'argument fn. L'argument priv est transmis à chaque appel de la fonction de rappel. Le nom de l'algorithme PKBDF2 PRF est passé à la fonction de rappel dans l'argument name.

La fonction tc_api_task_init() initialise et renvoie un pointeur opaque tc_api_task qui peut être utilisé pour exécuter des commandes tcplay. Chaque tâche ne peut être utilisée que pour un seul appel à tc_api_task_do(), et doit être désallouée à l'aide de tc_api_task_uninit(). L'argument op peut être l'une des opérations suivantes :

create
Créer un nouveau volume TrueCrypt chiffré.
map
Monter un volume TrueCrypt existant.
info
Demander des informations sur un volume TrueCrypt chiffré.
info_mapped
Demander des informations sur un volume TrueCrypt monté.
unmap
Démonter un volume TrueCrypt monté.
modify
Modifier le volume TrueCrypt en changeant la phrase de passe, les fichiers clés, l'algorithme PRF, en restaurant à partir d'un en-tête de sauvegarde, en restaurant à partir d'un fichier d'en-tête ou en sauvegardant dans un fichier d'en-tête.
restore
Modifier le volume TrueCrypt comme le fait modify, mais sans changer la phrase de passe, les fichiers clés ou l'algorithme PRF.

La fonction tc_api_task_set() permet de définir un certain nombre d'options différentes pour la tâche en cours. Le tableau suivant montre les clés disponibles lors des appels à tc_api_task_set() pour chaque opération. La lettre M indique que le réglage est obligatoire, tandis que * indique que le réglage est optionnel.

Les arguments variables acceptés par la fonction tc_api_task_set() dépendent de la clé définie.

dev
L'argument variable est de type const char *. Il définit le périphérique qui contient le volume TrueCrypt à manipuler.
map_name
L'argument variable est de type const char *. Il définit le nom du volume mappé.
interactive
L'argument variable est de type int. Il détermine si l'utilisateur sera invité à saisir une phrase secrète ou si les paramètres seront pris à partir des arguments définis à l'aide de la fonction tc_api_task_set().
retries
L'argument variable est de type int. Il détermine le nombre de tentatives de phrase secrète si interactive est défini.
weak_keys_and_salt
L'argument variable est de type int. Il détermine si une source d'entropie faible doit être utilisée pour le matériel de clé et/ou le sel.
secure_erase
L'argument variable est de type int. Il détermine si une suppression sécurisée est effectuée dans le cadre de la création du volume.
hidden_size_bytes
L'argument variable est de type int64_t. S'il est défini sur 0, cela implique qu'aucun volume caché ne sera créé. Une valeur positive implique qu'un volume caché de la taille spécifiée en octets sera créé.
prf_algo
L'argument variable est de type const char * et doit être un algorithme PBKDF2 PRF valide. Il détermine quel algorithme PBKDF2 PRF est utilisé pour le volume externe.
h_prf_algo
L'argument variable est de type const char * et doit être un algorithme PBKDF2 PRF valide. Il détermine quel algorithme PBKDF2 PRF est utilisé pour le volume caché.
cipher_chain
L'argument variable est de type const char * et doit être une chaîne de chiffrements tcplay valide. Il détermine quelle chaîne de chiffrements est utilisée pour chiffrer le volume externe.
h_cipher_chain
L'argument variable est de type const char * et doit être une chaîne de chiffrements tcplay valide. Il détermine quelle chaîne de chiffrements est utilisée pour chiffrer le volume caché.
protect_hidden
L'argument variable est de type int. Il détermine si la taille du volume externe doit être ajustée pour protéger un éventuel volume caché. L'utilisation de ce mode nécessite des phrases secrètes et des fichiers clés pour le volume externe et le volume caché.
sys
L'argument variable est de type const char *. Il détermine si le volume est un volume chiffré système, et si oui, quel disque est le disque système et contient donc l'en-tête. S'il est défini sur NULL, le volume sera implicitement traité comme un volume non chiffré système.
fde
L'argument variable est de type int. Il détermine si le disque utilise le chiffrement complet du disque ou non. S'il est spécifié, le périphérique pointé par le paramètre dev doit être un périphérique de disque entier, et non une partition. Le périphérique sera mappé ou interrogé dans son intégralité. Pour accéder aux partitions individuelles, un utilitaire tel que kpartx(8) doit être utilisé, ce qui créera des mappages individuels supplémentaires pour chaque partition dans le volume mappé déchiffré. Pour plus de détails sur le chiffrement complet du disque, voir tcplay(8).
use_backup_header
L'argument variable est de type int. Il détermine si l'en-tête de sauvegarde doit être utilisé à la place de l'en-tête normal pour accéder au volume.
header_from_file
L'argument variable est de type const char *. S'il n'est pas NULL, il force tcplay à utiliser l'en-tête dans le fichier spécifié au lieu de l'en-tête normal du volume externe.
hidden_header_from_file
L'argument variable est de type const char *. S'il n'est pas NULL, il force tcplay à utiliser l'en-tête dans le fichier spécifié au lieu de l'en-tête normal du volume caché.
allow_trim
L'argument variable est de type int. Il spécifie si le volume mappé doit autoriser les suppressions (TRIM).
save_header_to_file
L'argument variable est de type const char *. S'il n'est pas NULL, il force tcplay à écrire l'en-tête (modifié) dans le f
pecified file instead of replacing the volume headers.
passphrase
Le vararg est de type const char *. Il définit la phrase secrète que tcplay utilise pour accéder au volume.
h_passphrase
Le vararg est de type const char *. Il définit la phrase secrète que tcplay utilise pour déverrouiller l'en-tête de volume caché. Cette option n'est utilisée que si un volume caché est en cours de création ou si le paramètre protect_hidden est activé. Sinon, tcplay utilisera d'abord la phrase secrète normale pour tenter de déverrouiller le volume extérieur, puis tentera de déverrouiller l'en-tête de volume caché avec la même phrase secrète sans jamais utiliser h_passphrase.
keyfiles
Le vararg est de type const char *. S'il n'est pas NULL, le fichier clé donné sera ajouté au pool de fichiers clés. Plusieurs appels pour définir cette option avec un argument non- NULL ajoutent des fichiers clés supplémentaires. S'il est NULL, tous les fichiers clés sont effacés.
h_keyfiles
Le vararg est de type const char *. S'il n'est pas NULL, le fichier clé donné sera ajouté au pool de fichiers clés. Plusieurs appels pour définir cette option avec un argument non- NULL ajoutent des fichiers clés supplémentaires. S'il est NULL, tous les fichiers clés sont effacés. Cette option n'est utilisée que si un volume caché est en cours de création ou si le paramètre protect_hidden est activé. Sinon, tcplay utilisera d'abord les fichiers clés normaux pour tenter de déverrouiller le volume extérieur, puis tentera de déverrouiller l'en-tête de volume caché avec les mêmes fichiers clés sans jamais utiliser h_keyfiles.
new_passphrase
Le vararg est de type const char *. Il spécifie la nouvelle phrase secrète à utiliser lors de la modification de l'en-tête de volume.
new_keyfiles
Le vararg est de type const char *. S'il n'est pas NULL, le fichier clé donné sera ajouté au nouveau pool de fichiers clés. Plusieurs appels pour définir cette option avec un argument non- NULL ajoutent des fichiers clés supplémentaires. S'il est NULL, tous les nouveaux fichiers clés sont effacés. Lorsque l'en-tête de volume est modifié, il sera réencrypté en utilisant les nouveaux fichiers clés.
new_prf_algo
Le vararg est de type const char * et doit être un algorithme PRF PBKDF2 valide. Il détermine quel algorithme PRF PBKDF2 est utilisé lors de la réencryption de l'en-tête de volume (modifié).
state_change_fn
Le premier vararg est de type tc_api_state_change_fn et le second vararg est de type void *. Il permet au consommateur de fournir une fonction de rappel qui sera appelée lors du démarrage et de l'arrêt d'une sous-opération intensive en temps, telle que la collecte d'entropie ou l'effacement d'un volume. Le second vararg est transmis comme argument priv à la fonction de rappel. L'argument enter_state de la fonction de rappel détermine si tcplay démarre ou arrête la tâche intensive en temps spécifiée dans l'argument state.

La fonction tc_api_task_do() exécute la tâche spécifiée dans l'argument task. Avant d'exécuter la tâche, tc_api_task_do() effectue une simple vérification de validité des arguments définis précédemment à l'aide de tc_api_task_set() avant d'effectuer l'opération réelle. Après un appel à tc_api_task_do() pour les opérations info ou info_mapped, les informations interrogées sont disponibles pour être accessibles via tc_api_task_info_get().

La fonction tc_api_task_info_get() peut être utilisée pour interroger le résultat d'une opération info ou info_mapped. L'argument task est la tâche utilisée dans un appel précédent à tc_api_task_do(). L'argument key peut être l'un des éléments suivants :

Clé Type Description
device char * Nœud de périphérique correspondant
cipher char * Chaîne de chiffrement utilisée
prf char * Algorithme PRF PBKDF2 utilisé
key_bits int * Nombre de bits de clé
size int64_t * Taille du volume en octets
iv_offset int64_t * Décalage IV du volume en octets
block_offset int64_t * Décalage de bloc du volume en octets

Le second argument vararg doit être du type spécifié dans le tableau ci-dessus. Le premier argument vararg est toujours la taille du stockage fourni dans le second argument. Pour un argument char *, la taille correspond à la taille du tampon à l'emplacement fourni et doit être de type size_t. Pour un argument int * ou int64_t *, ce doit être la taille du type sous-jacent.

La fonction tc_api_task_get_error() peut être utilisée pour obtenir un message d'erreur détaillé après un appel échoué à tc_api_task_do. L'argument task est la tâche utilisée dans un appel précédent à tc_api_task_do().

NOTES

TrueCrypt limite les phrases secrètes à 64 caractères (y compris le caractère nul de terminaison). Pour être compatible avec lui, tcplay fait de même. Toutes les phrases secrètes (à l'exception des fichiers clés) sont tronquées à 64 caractères. De même, les fichiers clés sont limités à une taille de 1 Mo, mais jusqu'à 256 fichiers clés peuvent être utilisés.

VALEURS DE RETOUR

Toutes les fonctions, à l'exception de tc_api_task_init() et tc_api_task_get_error(), retournent soit TC_OK pour indiquer que l'opération s'est terminée avec succès, soit TC_ERR_UNIMPL pour indiquer que l'opération n'est pas implémentée, soit TC_ERR pour indiquer qu'une autre erreur s'est produite.

La fonction tc_api_task_get_error() retourne toujours une chaîne de caractères valide, mais potentiellement vide (ou non pertinente, si elle n'est pas appelée après une erreur).

La fonction tc_api_task_init() retourne NULL si une erreur s'est produite et un tc_api_task opaque sinon.

COMPATIBILITÉ

La bibliothèque tcplay offre une compatibilité totale avec les volumes TrueCrypt, y compris les volumes cachés, le chiffrement système (map-only), les fichiers clés et le chaînage de chiffrements.
