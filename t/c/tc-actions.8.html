NOM

actions - actions définies indépendamment dans tc

SYNTAXE

tc [ OPTIONS_TC ] actions add | change | replace SPEC_ACTION

tc [ OPTIONS_TC ] actions get | delete SPEC_INDEX_ACTION

tc [ OPTIONS_TC ] actions flush SPEC_NOM_ACTION

tc [ OPTIONS_TC ] actions ls | list SPEC_NOM_ACTION [ FILTRE_ACTION ]


SPEC_ACTION := action DETAIL_ACTION [ SPEC_INDEX ] [ SPEC_COOKIE ] [ FLAGS ] [ SPEC_STATS_HW ] [ CONTROLE ] [ SPEC_SAUTER ]

SPEC_INDEX_ACTION := SPEC_NOM_ACTION SPEC_INDEX

SPEC_NOM_ACTION := action NOM_ACTION

SPEC_INDEX := index INDEX

FILTRE_ACTION := since TEMPS_MS

SPEC_COOKIE := cookie COOKIE

FLAGS := no_percpu

SPEC_STATS_HW := hw_stats { immediate | delayed | disabled }

DETAIL_ACTION := NOM_ACTION PARAMS_ACTION

NOM_ACTION peut être tout type d'action valide : gact, mirred, bpf, connmark, csum, police, etc.

TEMPS_MS Temps depuis la dernière mise à jour.

CONTROLE := { reclassify | pipe | drop | continue | ok }

SPEC_SAUTER := { skip_sw | skip_hw }

OPTIONS_TC Ce sont les options spécifiques à tc et pas seulement les options. Référez-vous à tc(8) pour plus d'informations.

DESCRIPTION

L'objet actions dans tc permet à un utilisateur de définir des actions indépendamment d'un classificateur (filtre). Ces actions peuvent ensuite être assignées à un ou plusieurs filtres, avec tous les paquets correspondant aux critères du classificateur qui auront cette action exécutée sur eux.

Chaque type d'action (mirred, police, etc.) aura sa propre table pour stocker toutes les actions créées.

OPÉRATIONS

add
Crée une nouvelle action dans la table de cette action.
change
replace
Modifie une action existante.
get
Affiche l'action avec la valeur d'index spécifiée. Lorsqu'elle est combinée avec l'option -s de tc, affiche les statistiques de cette action.
delete
Supprime l'action avec la valeur d'index spécifiée. Si l'action est déjà associée à un classificateur, elle ne supprime pas le classificateur.
ls
list
Liste toutes les actions dans la table spécifiée. Lorsqu'elle est combinée avec l'option -s de tc, affiche les statistiques de toutes les actions dans la table spécifiée. Lorsqu'elle est combinée avec l'option since permet de faire un filtre temporel en millisecondes depuis la dernière fois qu'une action a été utilisée dans le plan de données.
flush
Supprime toutes les actions stockées dans la table spécifiée.

OPTIONS D'ACTION

Notez que ces options sont disponibles pour tous les types d'actions.

index INDEX
Spécifie la valeur d'index de la table d'une action. INDEX est une valeur de 32 bits qui est unique au type d'action référencé.
Pour les opérations add, change et replace, l'index est optionnel. Lors de l'ajout d'une nouvelle action, spécifier une valeur d'index assignera l'action à cet index à moins que cette valeur d'index n'ait déjà été assignée. Omettre la valeur d'index pour une opération d'ajout entraînera l'attribution d'une valeur par le noyau à la nouvelle action.
Pour les opérations get et delete, l'index est requis pour identifier l'action spécifique à afficher ou à supprimer.
cookie COOKIE
En plus de l'action spécifique, marque le paquet correspondant avec la valeur spécifiée par COOKIE. Le COOKIE est une valeur de 128 bits qui ne sera absolument pas interprétée par le noyau. En tant que tel, il peut être utilisé comme une valeur de corrélation pour maintenir l'état de l'utilisateur. La valeur à stocker est complètement arbitraire et ne nécessite pas de format spécifique. Elle est stockée à l'intérieur de la structure d'action elle-même.
FLAGS
Indicateurs spécifiques à l'action. Actuellement, le seul indicateur supporté est no_percpu qui indique que l'action est censée avoir un trafic minimal dans le plan de données logiciel et n'a pas besoin d'allouer des compteurs de statistiques avec un allocateur percpu. Cette option est destinée à être utilisée par les actions déchargées par le matériel.
hw_stats STATS_HW
Spécifie le type de statistiques matérielles de la nouvelle action. Si omis, tout type de compteur de statistiques sera utilisé, selon le pilote et ses ressources. STATS_HW indique le type. Les éléments suivants sont valides :
immediate
Signifie que lors de la copie (dump), l'utilisateur obtient l'état actuel des statistiques matérielles du périphérique interrogé au moment de la copie.
delayed
Signifie que lors de la copie, l'utilisateur obtient des statistiques matérielles qui peuvent être obsolètes pendant un certain temps, peut-être quelques secondes. C'est le cas lorsque le pilote interroge les mises à jour des statistiques périodiquement ou lorsqu'il reçoit une mise à jour asynchrone des statistiques du périphérique.
disabled
Aucune statistique matérielle ne sera disponible lors de la copie.
since TEMPS_MS
Lors de la copie d'un grand nombre d'actions, un filtre temporel en millisecondes peut être spécifié TEMPS_MS. TEMPS_MS est un compte en millisecondes depuis la dernière fois qu'un paquet a touché l'action. Par exemple, spécifier "since 20000" implique de copier toutes les actions qui ont vu des paquets au cours des 20 dernières secondes. Cette option est utile lorsque le noyau a un grand nombre d'actions et que vous ne vous intéressez qu'aux actions récemment utilisées.
CONTROLE
Le CONTROLE indique comment tc doit procéder après avoir exécuté l'action. Les éléments suivants sont valides :
reclassify
Redémarre la classification en sautant vers le filtre suivant attaché au parent de l'action.
pipe
Continue avec l'action suivante. C'est le contrôle par défaut.
drop
Supprime le paquet sans exécuter d'autres actions.
continue
Continue la classification avec le filtre suivant.
pass
Retourne à la qdisc appelante pour le traitement du paquet, et termine la classification de ce paquet.
SPEC_SAUTER
Le SPEC_SAUTER indique comment tc doit procéder lors de l'exécution de l'action. Les éléments suivants sont valides :
skip_sw
Ne pas traiter l'action par le logiciel. Si le matériel n'a pas de support de déchargement pour cette action, l'opération échouera.
skip_hw
Ne pas traiter l'action par le matériel.
