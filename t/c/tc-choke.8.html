tc-choke(8)

Paquet: iproute2

TC(8) Linux TC(8)

NOM

choke - choisir et conserver le planificateur

SYNTAXE

tc qdisc ... choke limit paquets min paquets max paquets avpkt octets burst paquets [ ecn ] [ bandwidth taux ] probability chance

DESCRIPTION

CHOKe (CHOose and Keep for responsive flows, CHOose and Kill for unresponsive flows) est un qdisc sans classe conçu pour identifier et pénaliser les flux qui monopolisent la file d'attente. CHOKe est une variation de RED, et la configuration est similaire à RED.

ALGORITHME

Une fois que la file d'attente atteint une certaine longueur moyenne, un paquet aléatoire est tiré de la file. Si le paquet à mettre en file et le paquet tiré appartiennent au même flux, les deux paquets sont abandonnés. Sinon, si la longueur de la file est toujours inférieure à la longueur maximale, le nouveau paquet a une chance configurable d'être marqué (ce qui peut signifier abandonné). Si la longueur de la file dépasse max, le nouveau paquet sera toujours marqué (ou abandonné). Si la longueur de la file dépasse limit, le nouveau paquet est toujours abandonné.

Le calcul de la probabilité de marquage est le même que celui utilisé par le qdisc RED.

PARAMETRES

Les paramètres sont les mêmes que pour RED, sauf que RED utilise des octets tandis que choke compte des paquets. Voir tc-red(8) pour une description.

SOURCE

o
R. Pan, B. Prabhakar, et K. Psounis, "CHOKe, A Stateless Active Queue Management Scheme for Approximating Fair Bandwidth Allocation", IEEE INFOCOM, 2000.
o
A. Tang, J. Wang, S. Low, "Understanding CHOKe: Throughput and Spatial Characteristics", IEEE/ACM Transactions on Networking, 2004
