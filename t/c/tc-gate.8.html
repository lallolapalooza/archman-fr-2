GATE(8) Linux GATE(8)

NOM

gate - Action de portail de flux

SYNTAXE

tc ... action gate [ base-time TEMPS_DE_BASE ] [ clockid ID_HORLOGE ] sched-entry <état du portail> <intervalle 1> [ <priorité interne> <octets max> ] sched-entry <état du portail> <intervalle 2> [ <priorité interne> <octets max> ] sched-entry <état du portail> <intervalle 3> [ <priorité interne> <octets max> ] ...... sched-entry <état du portail> <intervalle N> [ <priorité interne> <octets max> ]

DESCRIPTION

L'action GATE permet de passer des trames d'entrée spécifiées à des intervalles de temps spécifiques, ou de les rejeter à des intervalles de temps spécifiques. Le filtre tc filtre les trames d'entrée, puis l'action tc gate spécifie à quel intervalle de temps et combien d'octets ces trames peuvent être transmises au périphérique et à quel intervalle de temps les trames seront rejetées. L'action Gate attribue également un temps de base pour indiquer quand la liste d'entrées commence. Ensuite, l'action Gate commencera à répéter la liste d'entrées de portail cycliquement à partir du temps de base de départ. Pour la simulation logicielle, l'action Gate demande à l'utilisateur d'assigner un type d'horloge de référence.

PARAMÈTRES

base-time

Spécifie l'instant en nanosecondes, définissant le moment où la planification commence. Si 'base-time' est un temps passé, la planification commencera à

temps_de_base + (N * durée_cycle)

où N est le plus petit entier tel que le temps résultant soit supérieur à « maintenant », et « durée_cycle » est la somme de tous les intervalles des entrées de la planification. Sans 'base-time' spécifié, la valeur par défaut sera 0.

clockid

Spécifie l'horloge à utiliser par le minuteur interne du qdisc pour mesurer le temps et planifier les événements. Non valide si l'action gate est utilisée pour décharger le filtre. Par exemple, la commande de filtre tc avec le paramètre skip_sw.
sched-entry

Il peut y avoir plusieurs paramètres sched-entry dans une seule planification. Chacun a le format suivant :

sched-entry <état du portail> <intervalle> [ <priorité interne> <octets max> ]

<état du portail> signifie les états du portail. 'open' garde le portail ouvert, 'close' garde le portail fermé.
<intervalle> signifie combien de nanosecondes pour cette tranche de temps.
<priorité interne> signifie la valeur de priorité interne. Présence de la file de réception interne pour ce flux. « -1 » signifie joker. <priorité interne> et <octets max> peuvent être omis, par défaut « -1 », ce qui signifie que les deux valeurs sont « -1 » pour cet <sched-entry>.
<octets max> signifie combien d'octets peuvent passer dans cette tranche de temps. Rejeté si la limite est dépassée. « -1 » signifie joker. <octets max> peut être omis, par défaut « -1 », ce qui signifie que la valeur est « -1 » pour cet <sched-entry>.
Notez que <priorité interne> et <octets max> n'ont aucune signification si l'état du portail est « close » dans un <sched-entry>. Toutes les trames sont rejetées lorsqu'un <sched-entry> a l'état « close ».

EXEMPLES

L'exemple suivant montre que le filtre tc filtre les trames dont l'adresse IP source correspond à 192.168.0.20, maintiendra le portail ouvert pendant 200 ms et limitera le trafic à 8 Mo dans cette entrée de planification. Ensuite, il maintiendra le portail de trafic fermé pendant 100 ms. Les trames arrivées à l'état de portail fermé seront rejetées. Ensuite, le cycle exécutera les entrées de portail périodiquement. La planification commencera à l'instant 200,0 s en utilisant la référence CLOCK_TAI. La planification est composée de deux entrées d'une durée de 300 ms chacune.

# tc qdisc add dev eth0 ingress
# tc filter add dev eth0 parent ffff: protocol ip \
           flower skip_hw src_ip 192.168.0.20 \
           action gate index 2 clockid CLOCK_TAI \
           base-time 200000000000ns \
           sched-entry open 200000000ns -1 8000000b \
           sched-entry close 100000000ns

Les commandes suivantes sont un exemple pour filtrer un flux dont l'adresse MAC source correspond à 10:00:80:00:00:00 et les trames ICMP seront rejetées à tout moment avec un cycle de 200 ms. Avec un temps de base par défaut de 0 et un clockid est CLOCK_TAI par défaut.

# tc qdisc add dev eth0 ingress
# tc filter add dev eth0 parent ffff:  protocol ip \
	flower ip_proto icmp dst_mac 10:00:80:00:00:00 \
	action gate index 12 sched-entry close 200000000ns
