NOM

tcpflow - enregistreur de flux TCP

SYNTAXE

tcpflow [-aBcCDIpsZ] [-b octets_max] [-d niveau_debug] [-[eE] scanner] [-f fds_max] [-F[ctTXMkmg]] [-h|--help] [-i interface] [-l fichier1.pcap fichier2.pcap...] [-L verrou_sem] [-m octets_min] [-o rep_sortie] [-r fichier1.pcap] [-R fichier0.pcap] [-S nom=valeur] [-T[nom_fichier modèle]] [-U|--relinquer-privileges nom_utilisateur] [-v|--verbeux] [-V|--version] [-w fichier] [-x scanner] [-X fichier.xml] [-z|--chroot répertoire] [expression]

DESCRIPTION

tcpflow est un programme qui capture les données transmises dans le cadre des connexions TCP (flux), et stocke les données d'une manière pratique pour l'analyse de protocole ou le débogage. Plutôt que d'afficher des informations paquet par paquet, tcpflow reconstruit les flux de données réels et stocke chaque flux dans un fichier séparé pour une analyse ultérieure. tcpflow comprend les numéros de séquence TCP et reconstruira correctement les flux de données quelles que soient les retransmissions ou la livraison hors séquence. tcpflow offre un contrôle sur les noms de fichiers pour le classement automatique des connexions par protocole, adresse IP ou numéro de connexion, et dispose d'un système de plugins sophistiqué pour décompresser les connexions HTTP compressées, annuler l'encodage MIME ou appeler des programmes fournis par l'utilisateur pour le post-traitement.

Par défaut, tcpflow stocke toutes les données capturées dans des fichiers dont les noms sont de la forme : 

192.168.101.102.02345-010.011.012.013.45103
... où le contenu du fichier ci-dessus serait les données transmises de l'hôte 192.168.101.102 port 2345, vers l'hôte 10.11.12.13 port 45103.

Si vous voulez simplement traiter quelques centaines de milliers de paquets et voir ce que vous avez, essayez ceci : 

tcpflow -a -o rep_sortie -Fk -r paquets.pcap
Cela amènera tcpflow à effectuer (-a) tout le traitement, stocker la sortie dans un répertoire appelé rep_sortie, classer la sortie dans des répertoires de 1000 connexions chacun, et lire son entrée depuis le fichier paquets.pcap. Un traitement plus sophistiqué est possible, bien sûr.

OPTIONS

-a
Activer tout le traitement. Identique à -e tout.
-B
Forcer la sortie binaire même lors de l'impression sur la console avec -C ou -c.
-b octets_max
Spécifie la taille maximale d'un flux capturé. Tous les octets au-delà de octets_max à partir du premier octet capturé seront supprimés. La valeur par défaut est de stocker un nombre illimité d'octets par flux. Note : avant la version 1.4, tcpflow ne pouvait stocker qu'un maximum de 4 Gio par flux.
-c
Affichage console. Imprimer le contenu des paquets sur la sortie standard au fur et à mesure de leur réception, sans stocker de données capturées dans des fichiers (implique -s).
-C
Affichage console sans les détails de la source et de la destination des paquets. Imprimer le contenu des paquets sur la sortie standard au fur et à mesure de leur réception, sans stocker de données capturées dans des fichiers (implique -s).
-D
La sortie console doit être en hexadécimal.
-d
Niveau de débogage. Définir le niveau des messages de débogage imprimés sur la sortie d'erreur standard à niveau_debug. Des nombres plus élevés produisent plus de messages. -d 0 rend l'opération complètement silencieuse. -d 1 , la valeur par défaut, produit des messages de statut minimaux. -d 10 produit une sortie détaillée équivalente à -v. Des nombres supérieurs à 10 peuvent produire une grande quantité d'informations de débogage utiles uniquement aux développeurs.
-E nom
Désactiver tous les scanners puis activer le scanner nom
-e nom
Activer le scanner nom.
-e tout
Active tous les scanners. Identique à -a
-e http
Effectuer un post-traitement HTTP ("Après" traitement). Si le fichier de sortie est 
208.111.153.175.00080-192.168.001.064.37314,

Alors le post-traitement créera les fichiers : 
208.111.153.175.00080-192.168.001.064.37314-HTTP
208.111.153.175.00080-192.168.001.064.37314-HTTPBODY

Si le HTTPBODY était compressé avec GZIP, vous pourriez obtenir un troisième fichier également : 
208.111.153.175.00080-192.168.001.064.37314-HTTPBODY-GZIP

Des informations supplémentaires sur ces flux, telles que leur valeur de hachage MD5, sont également écrites dans le fichier de rapport DFXML.
-e python -S py_path=chemin -S py_module=module -S py_function=foo
Post-traiter la charge utile TCP par une fonction python externe.

La fonction python doit accepter un seul paramètre de type chaîne. La fonction python peut retourner une chaîne (sinon, la fonction ne doit pas retourner). La chaîne retournée (le cas échéant) est écrite dans le fichier de rapport DFXML à l'intérieur de la balise XML <scan_python_result>...</scan_python_result>. Un script python d'exemple est disponible dans le code source de tcpflow dans le répertoire python/plugins.

Exemple :

    tcpflow -r mon.cap -e python -S py_path=python/plugins -S py_module=samplePlugin -S py_function=sampleFunction
-F[format]
Spécifie le format des noms de fichiers de sortie.
Spécificateurs de format :
c
Ajoute le compteur de connexions à TOUS les noms de fichiers.
t
Prépende chaque nom de fichier avec un horodatage Unix (secondes depuis l'époque).
T
Prépende chaque nom de fichier avec un horodatage ISO-8601.
X
Ne produire aucun fichier (autre que le fichier de rapport DFXML).
-FM
Inclure le MD5 de chaque flux dans le fichier de rapport DFXML.
-FX
Supprime complètement la sortie des fichiers, le fichier de rapport DFXML est toujours produit.
-Fk
Classe la sortie dans des répertoires de 1K
-Fm
Classe la sortie dans des répertoires de 1M (2 niveaux)
-Fg
Classe la sortie dans des répertoires de 1G (3 niveaux)
-ffds_max
Descripteurs de fichiers max utilisés. Limite le nombre de descripteurs de fichiers utilisés par tcpflow à fds_max. Des nombres plus élevés utilisent plus de ressources système, mais sont généralement plus performants. Si le système d'exploitation sous-jacent prend en charge l'appel système setrlimit(), le système d'exploitation sera invité à appliquer la limite demandée. Par défaut, tcpflow utilise le nombre maximum de descripteurs de fichiers autorisés par le système d'exploitation. L'option -v indiquera combien de descripteurs de fichiers tcpflow utilise.
-g
Affiche les informations de flux sur la console en plusieurs couleurs. (Bleu pour les flux client vers serveur, rouge pour les flux serveur vers client, vert pour les flux indécis.) Note : Cette option était différente de tcpflow 1.3 (-e) et 1.4.4 (-J).
-h --help
Aide. Imprime les informations d'utilisation et quitte.
-hh
Plus d'aide. Imprime plus d'informations d'utilisation et quitte.
-i interface
Nom de l'interface. Capture les paquets à partir de l'interface réseau nommée interface. Si aucune interface n'est spécifiée avec -i, une valeur par défaut raisonnable sera automatiquement utilisée par libpcap.
-I

..."

Stocke les horodatages de réception (des paquets TCP) dans un fichier compagnon *.findx. Ainsi, chaque flux aura deux fichiers : (1) le fichier habituel contenant les octets de charge utile et (2) le fichier texte contenant les horodatages correspondants. Ce dernier fichier *.findx comporte trois colonnes utilisant la barre verticale '|' comme séparateur : 
    index-octet|horodatage|longueur
La colonne index-octet représente la position dans le fichier contenant les octets de charge utile. La colonne horodatage représente le nombre de secondes depuis l'époque sous forme de nombre à virgule flottante. La précision est à la microseconde mais pourrait également être à la nanoseconde dans une future version de tcpflow. La colonne longueur représente le nombre d'octets successifs concernés par l'horodatage et peut inclure plusieurs trames TCP (paquets TCP). L'extension findx peut provenir du fait que les horodatages sont indexés par trame.
-L nom_semaphore
Spécifie que nom_semaphore doit être utilisé comme sémaphore Unix pour empêcher deux copies différentes de tcpflow exécutées dans deux processus différents mais écrivant sur la même sortie standard de ne pas écrire les unes par-dessus les autres. C'est une application des sémaphores nommés Unix ; vous n'en avez probablement jamais vu auparavant.
-l
Traite les arguments suivants comme des noms de fichiers avec une commande -r implicite avant chacun d'eux. Cela vous permet de lire plusieurs fichiers à la fois avec le globbing du shell. Par exemple, pour traiter tous les fichiers pcap du répertoire courant, utilisez : 
tcpflow -o out -a -l *.pcap

-m taille_min
Force la création d'un nouveau fichier de sortie de connexion lorsqu'il y a un saut dans la session TCP de taille_min octets ou plus.
-o répertoire_sortie
Spécifie le répertoire de sortie où les fichiers de transcription seront écrits.
-P
Pas de purge. Normalement, tcpflow supprime les connexions de la table de hachage une fois la connexion fermée avec un FIN. Cela économise de la mémoire mais consomme du temps CPU supplémentaire. Sélectionner cette option fait croître la std::tr1:unordered_map sans limites, comme le faisait tcpflow avant la version 1.1. Cela rend tcpflow plus rapide si le nombre de connexions est inférieur à 10 millions, mais peut entraîner des erreurs de manque de mémoire.
-p
Pas de mode promiscuous. Normalement, tcpflow tente de mettre l'interface réseau en mode promiscuous avant de capturer les paquets. L'option -p indique à tcpflow de ne pas mettre l'interface en mode promiscuous. Notez qu'elle pourrait déjà être en mode promiscuous pour une autre raison.
-q
Mode silencieux --- n'affiche pas les avertissements. Actuellement, le seul avertissement que tcpflow affiche est un avertissement lorsque plus de 10 000 fichiers sont créés, indiquant que l'utilisateur aurait dû fournir les options -Fk, -Fm, ou -Fg. Nous pourrions avoir d'autres avertissements à l'avenir.
--relinquish-privileges=nom_utilisateur
Lorsque tcpflow est exécuté en tant que root, cette option change l'ID utilisateur et l'ID de groupe pour écrire des fichiers appartenant à nom_utilisateur. L'ID de groupe est le premier de la liste des groupes de nom_utilisateur. Cette opération est effectuée juste après l'ouverture du périphérique de capture ou juste après l'ouverture du premier fichier PCAP d'entrée. Cette option ne prend pas en charge plusieurs fichiers d'entrée accessibles uniquement par root, car les privilèges root sont abandonnés après l'ouverture du premier fichier (par exemple, -r fichier_acces_root_seulement.pcap -R root-only.pcap -l root-only*.pcap). Cette option a le même comportement que l'option tcpdump(1) portant le même nom --relinquish-privileges
-r
Lire depuis un fichier. Lit les paquets depuis fichier, qui a été créé en utilisant l'option -w de tcpdump(1). Cette option peut être répétée autant de fois que nécessaire. L'entrée standard est utilisée si fichier est "-". Notez que pour que cette option soit utile, l'option -s de tcpdump doit être utilisée pour définir le snaplen à l'MTU de l'interface (par exemple, 1500) lors de la capture des paquets.
-R
Lire depuis un fichier, mais uniquement pour compléter les flux TCP. Cette option est utilisée lorsque tcpflow est utilisé pour traiter une série de fichiers capturés au fil du temps. Pour chaque période temporelle n, le fichier fichier(n).pcap doit être traité avec -R fichier(n).pcap, tandis que fichier(n-1).pcap doit être traité avec -r fichier(n-1).pcap.
-Snom=valeur
Définit un paramètre nom égal à valeur pour un plug-in. Utilisez -hh pour connaître tous les paramètres configurables.
-s
Supprimer les non-imprimables. Convertit tous les caractères non imprimables en le caractère "." avant d'afficher les paquets sur la console ou de les enregistrer dans un fichier.
-T[format]
Spécifie un modèle arbitraire pour les noms de fichiers.
%A
se développe en adresse IP source.
%a
se développe en port IP source.
%B
se développe en adresse IP destination.
%b
se développe en port IP destination.
%T
se développe en horodatage au format ISO8601.
%t
se développe en horodatage au format Unix time_t.
%V
se développe en "--" si un VLAN est présent.
%v
se développe en le numéro de VLAN si un VLAN est présent.
%C
se développe en "c" si le compteur de connexions>0.
%c
se développe en le compteur de connexions si le compteur de connexions>0.
%#
se développe toujours en le compteur de connexions.
%N
(numéro_de_connexion ) % 1000
%K
(numéro_de_connexion / 1000) % 1000
%M
(numéro_de_connexion / 1000000) % 1000
%G
(numéro_de_connexion / 1000000000) % 1000
%%
affiche un "%".

Lorsque l'option -T est utilisée, tcpflow ignore les options -Fk, -Fm et -Fg. Cependant, l'option -T gère les '/' dans le modèle de nom de fichier pour créer des sous-répertoires. Par exemple, la ligne suivante créera une arborescence de répertoires out/IP-src/port-src/IP-dst/port-dst.

    tcpflow -r packets.pcap -o out -T %A/%a/%B/%b/%c%N.flow
-V --version
Affiche le numéro de version et quitte.
-v --verbose
Fonctionnement verbeux. Décrit de manière détaillée l'opération de tcpflow. Équivalent à -d 10.
-w nom_fichier.pcap
Écrit les paquets qui n'ont pas été traités dans nom_fichier.pcap. Généralement, il s'agira de paquets UDP.
-X nom_fichier.xml
Écrit un rapport DFXML dans nom_fichier.xml. Le fichier contient un enregistrement de chaque connexion TCP, de la façon dont le programme tcpflow a été compilé, et de l'ordinateur sur lequel tcpflow a été exécuté. Par défaut, tcpflow écrit le rapport DFXML dans le fichier report.xml.
-Z
Ne décompresse pas les flux compressés gzip. -K Conserve la structure pcap isolée par flux.
expression
sélectionne les paquets qui seront capturés. Si aucune expression n'est donnée, tous les paquets du réseau seront capturés. Sinon, seuls les paquets pour lesquels l'expression est `vraie' seront capturés.
Pour la syntaxe de l'expression, voir pcap-filter(7).
L'argument expression peut être passé à tcpflow soit comme un seul argument shell, soit comme plusieurs arguments shell, selon ce qui est le plus pratique. Généralement, si l'expression contient des métacaractères du shell, tels que des barres obliques inversées utilisées pour échapper les noms de protocoles, il est plus facile de la passer comme un seul argument entre guillemets plutôt que d'échapper les métacaractères du shell. Les arguments multiples sont concaténés avec des espaces avant d'être analysés.

Rapport DFXML

Le rapport DFXML est le fichier XML écrit par tcpflow pour fournir les détails de construction de tcpflow, les arguments de la ligne de commande et des informations sur les flux traités.

Par défaut, le fichier DFXML est nommé report.xml. Mais ce nom de fichier peut être modifié en utilisant l'option de ligne de commande -X.

Le fichier DFXML respecte le schéma DFXML défini par le projet https://github.com/dfxml-working-group/dfxml_schema.
De plus, tcpflow ajoute deux balises XML supplémentaires, comme illustré par l'exemple suivant :


<tcpflow startime='2017-07-22T00:12:21.962782Z' endtime='2017-07-22T00:12:22.097591Z'
         family='2' mac_daddr='40:3d:78:57:ed:d4' mac_saddr='00:c5:42:d2:cb:f2'
         src_ipn='141.134.34.12' dst_ipn='192.168.0.40' srcport='80' dstport='38797'
         packets='4' len='677' caplen='611' />
<tcpflow:result scanner="python" path="python/plugins" module="samplePlugin"
                function="sampleFunction">bla bla bla</tcpflow:result>

La première balise XML <tcpflow> fournit des informations sur le flux capturé. Cette balise devrait être renommée <tcpflow:cap> dans une future version afin de mieux se conformer au schéma DFXML.

La seconde balise XML <tcpflow:result> collecte les résultats du traitement. Pour le moment, seul le scanner python utilise cette fonctionnalité.

Les attributs XML de <tcpflow> sont :

  • startime Heure de réception du premier paquet
  • endtime Heure de réception du dernier paquet
  • family
  • mac_daddr Adresse MAC destination du premier paquet (affiché s'il y en a)
  • mac_saddr Adresse MAC source du premier paquet (affiché s'il y en a)
  • src_ipn IP source
  • dst_ipn IP destination
  • srcport Port source TCP
  • dstport Port destination TCP
tcpflow(1) — Documentation d'Arch Linux

DFXML REPORT

Le rapport DFXML peut contenir les éléments suivants dans l'attribut <metadata> de <tcpflow:result>:

  • packets Nombre de paquets
  • out_of_order_count Nombre de fois que tcpflow a remplacé le contenu manquant par des zéros dans le fichier de flux, par exemple lorsque la capture ne contient pas le début de la session TCP (affiché si non nul)
  • violations Nombre de violations de protocole (affiché si non nul)
  • len Somme de la longueur non tronquée de toutes les données des paquets (en-têtes inclus, voir https://stackoverflow.com/q/1491660)
  • caplen Somme des octets capturés de toutes les données des paquets (en-têtes inclus, affiché si différent de len)

Les attributs XML de <tcpflow:result> sont :

  • scanner Nom du scanner
  • path Répertoire du module du scanner (affiché si pertinent)
  • module Nom du module (affiché si pertinent, utilisé pour indiquer le script python)
  • function Nom de la fonction (affiché si pertinent, utilisé pour indiquer la fonction dans le module python)

EXEMPLES

Pour enregistrer tous les paquets arrivant sur ou partant de sundown et extraire toutes les pièces jointes HTTP :

tcpflow -e http -o outdir host sundown

Pour enregistrer le trafic entre helios et soit hot, soit ace, et classer les résultats en 1000 fichiers par répertoire et calculer le MD5 de chaque flux :

tcpflow -X report.xml -e md5 -o outdir -Fk host helios and \( hot or ace \)

BOGUES

Veuillez envoyer les rapports de bogues à simsong@acm.org.

tcpflow ne comprend actuellement pas les fragments IP. Les flux contenant des fragments IP ne seront pas enregistrés correctement.
