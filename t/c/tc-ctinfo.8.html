NOM

ctinfo - action de traitement de connmark de tc

SYNOPSIS

tc ... action ctinfo [ dscp MASK [STATEMASK] ] [ cpmark [MASK] ] [ zone ZONE ] [ CONTROL ] [ index <INDEX> ]

DESCRIPTION

CTINFO (Conntrack Information) est une action tc pour récupérer des données des marques de conntrack vers divers champs. Actuellement, il dispose de deux modes de traitement indépendants qui peuvent être considérés comme des sous-fonctions.

Le mode DSCP copie un DSCP stocké dans le connmark de conntrack dans le champ diffserv de l'IPv4/v6. La copie peut avoir lieu conditionnellement en fonction d'un indicateur également stocké dans le connmark. Le mode DSCP a été conçu pour aider à restaurer les classifications de paquets à l'entrée, classifications qui peuvent ensuite être utilisées par des qdiscs comme CAKE. Il peut être utilisé dans toutes les circonstances où la classification à l'entrée doit être maintenue sur des liens qui autrement blanchissent ou remappent selon leurs propres politiques.

Le mode CPMARK (copymark) copie le connmark de conntrack dans le champ mark du paquet. Sans paramètres supplémentaires, il est fonctionnellement équivalent à l'action connmark existante. Un masque optionnel peut être spécifié pour masquer les bits du connmark qui sont restaurés. Cela peut être utile lorsque les modes DSCP et CPMARK sont combinés.

Des statistiques simples (tc -s) sur les restaurations DSCP et les copies CPMARK sont maintenues, où les valeurs de `set` indiquent un décompte des paquets modifiés pour ce mode. DSCP inclut un décompte d'erreurs lorsque le champ diffserv du paquet de destination n'était pas inscriptible.

PARAMETRES

Paramètres du mode DSCP :

mask
Un masque de 6 bits contigus indiquant où se trouve la valeur DSCP dans le champ de marque conntrack de 32 bits. Un masque doit être fourni pour ce mode. `mask` est une valeur entière non signée de 32 bits.
statemask
Un masque d'au moins 1 bit indiquant où se trouve un indicateur de restauration conditionnelle dans le champ de marque conntrack de 32 bits. Le/les bits `statemask` ne doivent PAS chevaucher les bits de `mask`. Le DSCP sera restauré si le conntrack mark logicalement ANDé avec le `statemask` donne un résultat non nul. `statemask` est une valeur entière optionnelle de 32 bits.

Paramètres du mode CPMARK :

mask
Stocke le résultat logicalement ANDé du connmark et du masque dans le champ mark du paquet. La valeur par défaut est 0xffffffff, c'est-à-dire tout le champ mark. `mask` est une valeur entière optionnelle de 32 bits.

Paramètres d'action globale :

zone
Spécifie la zone conntrack lors de la recherche conntrack pour les paquets. `zone` est une valeur décimale entière non signée de 16 bits. La valeur par défaut est 0.
CONTROL
Les mots-clés suivants permettent de contrôler comment l'arbre des qdiscs, des classes, des filtres et des actions est parcouru après cette action.
reclassify
Redémarre avec le premier filtre de la liste actuelle.
pipe
Continue avec l'action suivante attachée au même filtre.
drop
Écrase le paquet.
shot
synonyme de drop
continue
Continue la classification avec le filtre suivant dans la ligne.
pass
Termine le processus de classification et retourne au qdisc appelant pour un traitement ultérieur du paquet. C'est le comportement par défaut.
index
Spécifie un index pour cette action afin de pouvoir l'identifier dans les commandes ultérieures. `index` est une valeur décimale entière non signée de 32 bits.

EXEMPLES

Exemple montrant la restauration conditionnelle de DSCP à l'entrée via un IFB

#Configurer l'interface IFB
tc qdisc add dev ifb4eth0 handle ffff: ingress
#Placer le qdisc CAKE dessus
tc qdisc add dev ifb4eth0 root cake bandwidth 40mbit
#Mettre l'interface UP
ip link set dev ifb4eth0 up
#Ajouter 2 actions, ctinfo pour restaurer le dscp & mirred pour rediriger les paquets vers IFB
tc filter add dev eth0 parent ffff: protocol all prio 10 u32 \
    match u32 0 0 flowid 1:1 action    \
    ctinfo dscp 0xfc000000 0x01000000  \
    mirred egress redirect dev ifb4eth0

Exemple montrant la restauration conditionnelle de DSCP à la sortie

Cela peut sembler absurde étant donné que le marquage par iptables des paquets de sortie est facile à réaliser, mais les règles de classification de flux iptables peuvent être étendues et ainsi une sorte de "définir une fois et oublier" peut être utile, en particulier sur les appareils à ressources CPU limitées.

# Envoyer les connexions non marquées vers une chaîne de marquage qui doit stocker un DSCP
et définir le bit statemask dans le connmark
iptables -t mangle -A POSTROUTING -o eth0 -m connmark \
    --mark 0x00000000/0x01000000 -g CLASS_MARKING_CHAIN
# Appliquer le DSCP marqué aux paquets
tc filter add dev eth0 protocol all prio 10 u32 \
    match u32 0 0 flowid 1:1 action \
    ctinfo dscp 0xfc000000 0x01000000
