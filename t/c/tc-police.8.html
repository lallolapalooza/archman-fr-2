NOM

police - action de police

SYNTAXE


tc ... action police [ rate DÉBIT burst OCTETS[/OCTETS] ] [ pkts_rate DÉBIT pkts_burst PAQUETS] [ mtu OCTETS[/OCTETS] ] [ peakrate DÉBIT ] [ overhead OCTETS ] [ linklayer TYPE ] [ CONTRÔLE ]

tc ... filter ... [ estimator ÉCHANTILLON MOYENNE ] action police avrate DÉBIT [ CONTRÔLE ]

CONTRÔLE := conform-exceed ACTION_DÉPASSEMENT[/ACTION_NON_DÉPASSEMENT

ACTION_DÉPASSEMENT/ACTION_NON_DÉPASSEMENT := { pipe | ok | reclassify | drop | continue | goto chain INDEX_CHAINE }

DESCRIPTION

L'action police permet de limiter le débit en octets ou en paquets du trafic correspondant au filtre auquel elle est attachée.

Il existe deux algorithmes disponibles pour mesurer le débit en octets : Le premier utilise un double token bucket interne et est configuré à l'aide des paramètres rate, burst, mtu, peakrate, overhead et linklayer. Le second utilise un mécanisme d'échantillonnage en noyau. Il peut être affiné à l'aide du paramètre de filtre estimator.

Il existe un algorithme disponible pour mesurer le débit de paquets et il est similaire au premier algorithme décrit pour le débit en octets. Il est configuré à l'aide des paramètres pkt_rate et pkt_burst.

Au moins un des paramètres rate et pkt_rate doit être configuré.

OPTIONS

rate DÉBIT
Le débit maximal en octets des paquets passant par cette action. Ceux qui le dépassent seront traités comme défini par l'option conform-exceed.
burst OCTETS[/OCTETS]
Définit le burst maximal autorisé en octets, éventuellement suivi d'un signe slash ('/') et de la taille de cellule qui doit être une puissance de 2.
pkt_rate DÉBIT
Le débit maximal de paquets ou le nombre de paquets passant par cette action. Ceux qui le dépassent seront traités comme défini par l'option conform-exceed.
pkt_burst PAQUETS
Définit le burst maximal autorisé en paquets.
mtu OCTETS[/OCTETS]
Ceci est la taille maximale de paquet gérée par le policer (les paquets plus gros seront traités comme s'ils avaient dépassé le débit configuré). Définir cette valeur correctement améliorera la précision du planificateur. Le format de la valeur est identique à celui de burst ci-dessus. Par défaut, il est illimité.
peakrate DÉBIT
Définit le taux de décharge maximal du seau, dépassant le rate.
avrate DÉBIT
Utilise un estimateur de débit de bande passante en noyau et fait correspondre le DÉBIT donné avec celui-ci.
overhead OCTETS
Prend en compte le surcoût du protocole des périphériques de sortie d'encapsulation lors du calcul du rate et du peakrate.
linklayer TYPE
Spécifie le type de couche de liaison. TYPE peut être l'un de ethernet (par défaut), atm ou adsl (qui sont des synonymes). Il est utilisé pour aligner les tables de débit précalculées avec les tailles de cellule ATM, pour ethernet aucune action n'est effectuée.
estimator ÉCHANTILLON MOYENNE
Ajuste l'estimateur de débit de paquets en noyau. ÉCHANTILLON et MOYENNE sont des valeurs temporelles et contrôlent la fréquence à laquelle les échantillons sont pris et sur quelle période une moyenne est construite.
conform-exceed ACTION_DÉPASSEMENT[/ACTION_NON_DÉPASSEMENT]
Définit comment gérer les paquets qui dépassent ou respectent la limite de bande passante configurée. Les valeurs possibles sont :
continue
Ne rien faire, continuer simplement avec l'action suivante en ligne.
drop
Rejeter le paquet immédiatement.
shot
Ceci est un synonyme de drop.
ok
Accepter le paquet. C'est la valeur par défaut pour les paquets conformes.
pass
Ceci est un synonyme de ok.
reclassify
Traiter le paquet comme s'il ne correspondait pas au filtre auquel cette action est attachée et continuer avec le filtre suivant en ligne (s'il y en a). C'est la valeur par défaut pour les paquets dépassant la limite.
pipe
Transmettre le paquet à l'action suivante en ligne.

EXEMPLES

Une application typique de l'action police est de faire respecter le débit de trafic entrant en rejetant les paquets excédentaires. Bien que cela soit mieux fait du côté de l'expéditeur, surtout dans les scénarios sans contrôle de pair (par exemple, avec les fournisseurs d'accès à distance), c'est souvent le mieux que l'on puisse faire pour maintenir de faibles latences sous forte charge. Ce qui suit établit une police de bande passante entrante à 1 Mbit/s en utilisant la qdisc ingress et le filtre u32 :

# tc qdisc add dev eth0 handle ffff: ingress
# tc filter add dev eth0 parent ffff: u32 \
	match u32 0 0 \
	police rate 1mbit burst 100k

Comme une action ne peut pas exister seule, il doit toujours y avoir un filtre impliqué comme lien entre la qdisc et l'action. L'exemple ci-dessus utilise u32 pour cela, qui est configuré pour correspondre effectivement à n'importe quel paquet (le transmettant ainsi à l'action police).
