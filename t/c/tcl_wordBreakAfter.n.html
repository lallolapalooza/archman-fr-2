INTRODUCTION

Tcl inclut une bibliothèque de procédures Tcl pour des fonctions couramment requises. Les procédures définies dans la bibliothèque Tcl sont génériques et conviennent à de nombreuses applications différentes. L'emplacement de la bibliothèque Tcl est retourné par la commande info library. En plus de la bibliothèque Tcl, chaque application dispose normalement de sa propre bibliothèque de procédures de support ; l'emplacement de cette bibliothèque est normalement donné par la valeur de la variable globale $app_library, où app est le nom de l'application. Par exemple, l'emplacement de la bibliothèque Tk est conservé dans la variable tk_library.

Pour accéder aux procédures de la bibliothèque Tcl, une application doit sourcer le fichier init.tcl dans la bibliothèque, par exemple avec la commande Tcl

source [file join [info library] init.tcl]

Si la procédure de bibliothèque Tcl_Init est invoquée à partir de la procédure Tcl_AppInit d'une application, cela se fait automatiquement. Le code dans init.tcl définira la procédure unknown et organisera le chargement des autres procédures à la demande en utilisant le mécanisme d'auto-chargement défini ci-dessous.

PROCÉDURES DE COMMANDE

Les procédures suivantes sont fournies dans la bibliothèque Tcl :

auto_execok cmd
Détermine s'il existe un fichier exécutable ou une commande shell intégrée du nom de cmd. Si c'est le cas, elle retourne une liste d'arguments à passer à exec pour exécuter le fichier exécutable ou la commande shell intégrée nommée par cmd. Sinon, elle retourne une chaîne vide. Cette commande examine les répertoires dans le chemin de recherche actuel (donné par la variable d'environnement PATH) dans sa recherche d'un fichier exécutable nommé cmd. Sur les plateformes Windows, la recherche est étendue avec les mêmes répertoires et extensions de fichiers que ceux utilisés par exec. Auto_execok mémorise les informations sur les recherches précédentes dans un tableau nommé auto_execs ; cela évite la recherche dans le chemin lors d'appels ultérieurs pour le même cmd. La commande auto_reset peut être utilisée pour forcer auto_execok à oublier ses informations mises en cache.
auto_import pattern
Auto_import est invoquée pendant namespace import pour voir si les commandes importées spécifiées par pattern résident dans une bibliothèque auto-chargée. Si c'est le cas, les commandes sont chargées de manière à être disponibles pour l'interpréteur afin de créer les liens d'importation. Si les commandes ne résident pas dans une bibliothèque auto-chargée, auto_import ne fait rien. La correspondance de motif est effectuée selon les règles de correspondance de namespace import.
auto_load cmd
Cette commande tente de charger la définition d'une commande Tcl nommée cmd. Pour ce faire, elle recherche un chemin d'auto-chargement, qui est une liste d'un ou plusieurs répertoires. Le chemin d'auto-chargement est donné par la variable globale auto_path s'il existe. S'il n'y a pas de variable auto_path, alors la variable d'environnement TCLLIBPATH est utilisée, si elle existe. Sinon, le chemin d'auto-chargement se compose uniquement du répertoire de la bibliothèque Tcl. Dans chaque répertoire du chemin d'auto-chargement, il doit y avoir un fichier tclIndex qui décrit une ou plusieurs commandes définies dans ce répertoire et un script à évaluer pour charger chacune des commandes. Le fichier tclIndex doit être généré avec la commande auto_mkindex. Si cmd est trouvé dans un fichier d'index, alors le script approprié est évalué pour créer la commande. La commande auto_load retourne 1 si cmd a été créé avec succès. La commande retourne 0 s'il n'y avait pas d'entrée d'index pour cmd ou si le script n'a pas réellement défini cmd (par exemple, parce que les informations d'index sont obsolètes). Si une erreur se produit lors du traitement du script, cette erreur est retournée. Auto_load ne lit les informations d'index qu'une seule fois et les enregistre dans le tableau auto_index ; les appels ultérieurs à auto_load recherchent cmd dans le tableau plutôt que de relire les fichiers d'index. Les informations d'index mises en cache peuvent être supprimées avec la commande auto_reset. Cela forcera la prochaine commande auto_load à recharger la base de données d'index à partir du disque.
auto_mkindex dir pattern pattern ...
Génère un index adapté à l'utilisation par auto_load. La commande recherche dans dir tous les fichiers dont les noms correspondent à l'un des arguments pattern (la correspondance est effectuée avec la commande glob), génère un index de toutes les procédures de commande Tcl définies dans tous les fichiers correspondants, et stocke les informations d'index dans un fichier nommé tclIndex dans dir. Si aucun motif n'est donné, un motif *.tcl sera supposé. Par exemple, la commande
auto_mkindex foo *.tcl

lira tous les fichiers .tcl du sous-répertoire foo et générera un nouveau fichier d'index foo/tclIndex.

Auto_mkindex analyse les scripts Tcl en les sourçant dans un interpréteur enfant et en surveillant les commandes proc et namespace qui sont exécutées. Les extensions peuvent utiliser le package (non documenté) auto_mkindex_parser pour enregistrer d'autres commandes qui peuvent contribuer à l'index d'auto-chargement. Vous devrez lire auto.tcl pour voir comment cela fonctionne.

Auto_mkindex_old (qui a la même syntaxe que auto_mkindex) analyse les scripts Tcl d'une manière relativement peu sophistiquée : si une ligne contient le mot “proc” comme premiers caractères, elle est supposée être une définition de procédure et le mot suivant de la ligne est considéré comme le nom de la procédure. Les définitions de procédure qui n'apparaissent pas de cette manière (par exemple, s'il y a des espaces avant le proc) ne seront pas indexées. Si votre script contient du code “dangereux”, tel que du code d'initialisation global ou des noms de procédure avec des caractères spéciaux comme $, *, [ ou ], vous êtes plus en sécurité en utilisant auto_mkindex_old.

auto_reset
Détruit toutes les informations mises en cache par auto_execok et auto_load. Ces informations seront relues à partir du disque la prochaine fois qu'elles seront nécessaires. Auto_reset supprime également toutes les procédures répertoriées dans l'index d'auto-chargement, de sorte que de nouvelles copies d'elles seront chargées la prochaine fois qu'elles seront utilisées.
auto_qualify command namespace
Calcule une liste de noms complètement qualifiés pour command. Cette liste reflète le chemin qu'un interpréteur Tcl standard suit pour la recherche de commandes : d'abord, il recherche la commande dans le namespace courant, puis dans le namespace global. En conséquence, si command est relatif et namespace n'est pas ::, la liste retournée a deux éléments : command dans le scope de namespace, comme s'il s'agissait d'une commande dans le namespace namespace ; et command comme s'il s'agissait d'une commande dans le namespace global. Sinon, si command est absolu (il commence par ::), ou si namespace est ::, la liste ne contient que command comme s'il s'agissait d'une commande dans le namespace global.

Auto_qualify est utilisé par les installations d'auto-chargement en Tcl, à la fois pour produire des index d'auto-chargement comme pkgIndex.tcl, et pour effectuer l'auto-chargement réel des fonctions au moment de l'exécution.

tcl_findLibrary basename version patch initScript enVarName varName

Cette commande recherche dans le système de fichiers un répertoire contenant les fichiers Tcl nécessaires à l'exécution d'une bibliothèque. Elle cherche une bibliothèque dont le nom de base est basename, avec la version majeure version et la version mineure (ou patch) patch. Elle cherche d'abord dans les répertoires spécifiés par la variable globale auto_path. Si elle ne trouve pas la bibliothèque, elle utilise le chemin spécifié par la variable d'environnement TCLLIBPATH. Si elle ne trouve toujours pas la bibliothèque, elle la cherche dans le répertoire de la bibliothèque Tcl standard.

Lorsqu'une bibliothèque correspondante est trouvée, la commande écrit le chemin complet du répertoire de la bibliothèque dans la variable globale spécifiée par varName. Elle tente ensuite de sourcer le script spécifié par initScript, qui est normalement un fichier pkgIndex.tcl. Ce script est généralement responsable du chargement des commandes et des packages nécessaires à partir de la bibliothèque. Si la variable enVarName est spécifiée, le chemin complet de la bibliothèque y est également écrit. La commande retourne 1 si la bibliothèque a été trouvée et initialisée avec succès, et 0 sinon.

parray arrayName ?pattern?
Imprime toutes les variables d'un tableau nommé arrayName. Si le argument pattern est donné, alors seules les variables dont les noms correspondent au motif (selon les règles de correspondance de string match) sont imprimées. La sortie est formatée sous forme de commandes Tcl assignant les valeurs correspondantes aux variables. L'ordre dans lequel les tableaux sont imprimés n'est pas garanti.
tcl_endOfWord str start
Détermine la position du premier caractère après la fin du mot qui contient le caractère à l'index start dans la chaîne str. Un mot est défini comme une séquence de caractères alphanumériques ou de soulignements, ou une séquence de caractères non blancs. Si str ne contient pas de caractère alphanumérique ou de soulignement, et si le caractère à l'index start n'est pas un caractère blanc, alors le caractère est considéré comme étant dans un mot.
tcl_startOfNextWord str start
Détermine la position du premier caractère du mot suivant celui qui contient le caractère à l'index start dans la chaîne str. Un mot est défini comme une séquence de caractères alphanumériques ou de soulignements, ou une séquence de caractères non blancs. Si str ne contient pas de caractère alphanumérique ou de soulignement, et si le caractère à l'index start n'est pas un caractère blanc, alors le caractère est considéré comme étant dans un mot.
tcl_startOfPreviousWord str start
Détermine la position du premier caractère du mot contenant le caractère à l'index start dans la chaîne str. Un mot est défini comme une séquence de caractères alphanumériques ou de soulignements, ou une séquence de caractères non blancs. Si str ne contient pas de caractère alphanumérique ou de soulignement, et si le caractère à l'index start n'est pas un caractère blanc, alors le caractère est considéré comme étant dans un mot.
tcl_wordBreakAfter str start
Détermine la position où une coupure de mot devrait se produire après le caractère à l'index start dans la chaîne str. Une coupure de mot se produit après un caractère blanc, ou entre un caractère de mot et un caractère non mot.
tcl_wordBreakBefore str start
Détermine la position où une coupure de mot devrait se produire avant le caractère à l'index start dans la chaîne str. Une coupure de mot se produit avant un caractère blanc, ou entre un caractère de mot et un caractère non mot.

DESCRIPTION

Ces procédures sont principalement utilisées en interne par Tk.

PROCÉDURES DE RECHERCHE DE BIBLIOTHÈQUE

search_library varName initScript enVarName ?rootdir?
Ceci est une procédure de recherche standard à utiliser par les extensions lors de leur initialisation. Elles appellent cette procédure pour rechercher leur bibliothèque de scripts dans plusieurs répertoires standards. Le dernier composant du nom du répertoire de la bibliothèque est normalement basenameversion (par exemple, tk8.0), mais il pourrait être “library” dans les hiérarchies de construction. Le fichier initScript sera interprété dans l'interpréteur une fois qu'il sera trouvé. Le répertoire dans lequel ce fichier est trouvé est stocké dans la variable globale varName. Si cette variable est déjà définie (par exemple, par du code C lors de l'initialisation de l'application), aucune recherche n'est effectuée. Sinon, la recherche s'effectue dans ces répertoires : le répertoire nommé par la variable d'environnement enVarName ; relativement au répertoire de bibliothèque Tcl ; relativement au fichier exécutable dans le répertoire d'installation standard bin ou bin/arch ; relativement au fichier exécutable dans l'arborescence de construction actuelle ; relativement au fichier exécutable dans une arborescence de construction parallèle.
parray nomTableau ?motif?
Affiche sur la sortie standard les noms et les valeurs de tous les éléments du tableau nomTableau, ou seulement les noms qui correspondent au motif (en utilisant les règles de correspondance de string match) et leurs valeurs si motif est fourni. nomTableau doit être un tableau accessible à l'appelant de parray. Il peut être local ou global.

AIDE AUX LIMITES DE MOTS

Ces procédures sont principalement utilisées en interne par Tk.

tcl_endOfWord str debut
Retourne l'index du premier emplacement de fin de mot qui se produit après un index de départ debut dans la chaîne str. Un emplacement de fin de mot est défini comme étant le premier caractère non-mot suivant le premier caractère mot après le point de départ. Retourne -1 s'il n'y a plus d'emplacements de fin de mot après le point de départ. Voir la description de tcl_wordchars et tcl_nonwordchars ci-dessous pour plus de détails sur la manière dont Tcl détermine quels caractères sont des caractères mot.
tcl_startOfNextWord str debut
Retourne l'index du premier emplacement de début de mot qui se produit après un index de départ debut dans la chaîne str. Un emplacement de début de mot est défini comme étant le premier caractère mot suivant un caractère non-mot. Retourne -1 s'il n'y a plus d'emplacements de début de mot après le point de départ.
tcl_startOfPreviousWord str debut
Retourne l'index du premier emplacement de début de mot qui se produit avant un index de départ debut dans la chaîne str. Retourne -1 s'il n'y a plus d'emplacements de début de mot avant le point de départ.
tcl_wordBreakAfter str debut
Retourne l'index de la première limite de mot après l'index de départ debut dans la chaîne str. Retourne -1 s'il n'y a plus de limites après le point de départ dans la chaîne donnée. L'index retourné fait référence au deuxième caractère de la paire qui compose une limite.
tcl_wordBreakBefore str debut
Retourne l'index de la première limite de mot avant l'index de départ debut dans la chaîne str. Retourne -1 s'il n'y a plus de limites avant le point de départ dans la chaîne donnée. L'index retourné fait référence au deuxième caractère de la paire qui compose une limite.

VARIABLES

Les variables globales suivantes sont définies ou utilisées par les procédures de la bibliothèque Tcl. Elles appartiennent à deux grandes catégories, gérant les commandes inconnues et les paquets, et déterminant ce qui constitue des mots.

VARIABLES DE CHARGEMENT AUTOMATIQUE ET DE GESTION DES PAQUETS

auto_execs
Utilisé par auto_execok pour enregistrer des informations sur l'existence de commandes spécifiques en tant que fichiers exécutables.
auto_index
Utilisé par auto_load pour sauvegarder les informations d'index lues depuis le disque.
auto_noexec
S'il est défini à une quelconque valeur, alors unknown ne tentera pas d'exécuter automatiquement de commandes.
auto_noload
S'il est défini à une quelconque valeur, alors unknown ne tentera pas de charger automatiquement de commandes.
auto_path
S'il est défini, alors il doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations de chargement automatique (y compris pour les fichiers d'index de paquets lors de l'utilisation du gestionnaire par défaut package unknown). Cette variable est initialisée au démarrage pour contenir, dans l'ordre : les répertoires listés dans la variable d'environnement TCLLIBPATH, le répertoire nommé par la variable globale tcl_library, le répertoire parent de tcl_library, les répertoires listés dans la variable tcl_pkgPath. Des emplacements supplémentaires pour rechercher des fichiers et des index de paquets devraient normalement être ajoutés à cette variable en utilisant lappend.
env(TCL_LIBRARY)
S'il est défini, alors il spécifie l'emplacement du répertoire contenant les scripts de bibliothèque (la valeur de cette variable sera assignée à la variable tcl_library et donc retournée par la commande info library). Si cette variable n'est pas définie, une valeur par défaut est utilisée.
env(TCLLIBPATH)
S'il est défini, alors il doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations de chargement automatique. Les répertoires doivent être spécifiés au format Tcl, en utilisant “/” comme séparateur de chemin, indépendamment de la plateforme. Cette variable n'est utilisée que lors de l'initialisation de la variable auto_path.

VARIABLES DE DÉTERMINATION DES LIMITES DE MOTS

Ces variables ne sont utilisées que dans les commandes tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter et tcl_wordBreakBefore.

tcl_nonwordchars
Cette variable contient une expression régulière utilisée par des routines telles que tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non. Si le motif correspond à un caractère, le caractère est considéré comme un caractère non-mot. Sur les plateformes Windows, les espaces, les tabulations et les nouvelles lignes sont considérés comme des caractères non-mot. Sous Unix, tout ce qui n'est pas un nombre, une lettre ou un underscore est considéré comme un caractère non-mot.
tcl_wordchars
Cette variable contient une expression régulière utilisée par des routines telles que tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non. Si le motif correspond à un caractère, le caractère est considéré comme un caractère mot. Sur les plateformes Windows, les mots sont composés de tout caractère qui n'est pas un espace, une tabulation ou une nouvelle ligne. Sous Unix, les mots sont composés de nombres, de lettres ou d'underscores.
