NOM

CoDel - Algorithme de gestion active des files d'attente à délai contrôlé

SYNTAXE

tc qdisc ... codel [ limit PAQUETS ] [ target TEMPS ] [ interval TEMPS ] [ ecn | noecn ] [ ce_threshold TEMPS ]

DESCRIPTION

CoDel (prononcé "coddle") est un algorithme adaptatif de gestion active des files d'attente (AQM) "sans réglages" qui a été développé pour remédier aux lacunes de RED et de ses variantes. Il a été développé dans les objectifs suivants :

  • Il devrait être sans paramètre.
  • Il devrait maintenir des délais faibles tout en permettant des rafales de trafic.
  • Il devrait contrôler le délai.
  • Il devrait s'adapter dynamiquement aux débits de lien changeants sans impact sur l'utilisation.
  • Il devrait être simple et efficace et devrait pouvoir être adapté des routeurs simples aux routeurs complexes.

ALGORITHME

CoDel apporte trois innovations majeures. Au lieu d'utiliser la taille de la file d'attente ou sa moyenne, il utilise la file d'attente minimale locale comme mesure de la file d'attente permanente/persistante. Deuxièmement, il utilise une seule variable de suivi d'état du délai minimum pour déterminer sa position par rapport au délai de la file d'attente permanente. Troisièmement, au lieu de mesurer la taille de la file d'attente en octets ou en paquets, elle est mesurée en temps de séjour des paquets dans la file d'attente.

CoDel mesure le délai minimal de la file d'attente locale (c'est-à-dire le délai de la file d'attente permanente) et le compare à la valeur du délai acceptable de la file d'attente cible. Tant que le délai minimal de la file d'attente est inférieur à la cible ou que le tampon contient moins qu'un MTU d'octets, les paquets ne sont pas supprimés. Codel entre en mode de suppression lorsque le délai minimal de la file d'attente a dépassé la cible pendant un temps supérieur à l'intervalle. Dans ce mode, les paquets sont supprimés à différents moments, déterminés par une loi de commande. La loi de commande garantit que les suppressions de paquets provoquent un changement linéaire du débit. Une fois que le délai minimum descend en dessous de la cible, les paquets ne sont plus supprimés.

Des détails supplémentaires peuvent être trouvés dans l'article cité ci-dessous.

PARAMETRES

limit

est la limite stricte de la taille réelle de la file d'attente. Lorsque cette limite est atteinte, les paquets entrants sont supprimés. Si la valeur est abaissée, les paquets sont supprimés de manière à respecter la nouvelle limite. La valeur par défaut est 1000 paquets.

target

est le délai acceptable pour la file d'attente permanente/persistante minimale. Ce délai minimum est identifié en suivant le délai minimal local de la file d'attente que les paquets expérimentent. La valeur par défaut et recommandée est 5 ms.

interval

est utilisé pour garantir que le délai minimum mesuré ne devient pas trop obsolète. Le délai minimum doit être expérimenté dans la dernière époque de longueur intervalle. Il doit être réglé sur l'ordre du RTT du pire cas à travers le goulot d'étranglement pour donner aux points d'extrémité suffisamment de temps pour réagir. La valeur par défaut est 100 ms.

ecn | noecn

peut être utilisé pour marquer les paquets au lieu de les supprimer. Si ecn a été activé, noecn peut être utilisé pour le désactiver et vice versa. Par défaut, ecn est désactivé.

ce_threshold

définit un seuil au-dessus duquel tous les paquets sont marqués avec ECN Congestion Experienced. Ceci est utile pour les algorithmes de contrôle de congestion de type DCTCP qui nécessitent un marquage à des seuils de mise en file d'attente très faibles.

EXEMPLES


# tc qdisc add dev eth0 root codel
# tc -s qdisc show
qdisc codel 801b: dev eth0 root refcnt 2 limit 1000p target 5.0ms interval 100.0ms
Sent 245801662 bytes 275853 pkt (dropped 0, overlimits 0 requeues 24)
backlog 0b 0p requeues 24
count 0 lastcount 0 ldelay 2us drop_next 0us
maxpacket 7306 ecn_mark 0 drop_overlimit 0


# tc qdisc add dev eth0 root codel limit 100 target 4ms interval 30ms ecn
# tc -s qdisc show
qdisc codel 801c: dev eth0 root refcnt 2 limit 100p target 4.0ms interval 30.0ms ecn
Sent 237573074 bytes 268561 pkt (dropped 0, overlimits 0 requeues 5)
backlog 0b 0p requeues 5
count 0 lastcount 0 ldelay 76us drop_next 0us
maxpacket 2962 ecn_mark 0 drop_overlimit 0
