NOM

mirred - action de miroir/redirection

SYNTAXE


tc ... action mirred DIRECTION ACTION [ index INDEX ] TARGET

DIRECTION := { ingress | egress }

TARGET := { DEV | BLOCK }

DEV := dev NOM_DE_PERIPHERIQUE

BLOCK := blockid ID_BLOQUÉ

ACTION := { mirror | redirect }

DESCRIPTION

L'action mirred permet de dupliquer (miroir) ou de rediriger (voler) le paquet qu'elle reçoit. La duplication est ce que l'on appelle parfois un analyseur de port de commutation (SPAN) et est couramment utilisée pour analyser et/ou déboguer des flux. Lors de la duplication vers un bloc tc, le paquet sera dupliqué vers tous les ports du bloc à l'exception du port où le paquet est entré, si ce port fait partie du bloc tc. La redirection est similaire à la duplication, à la différence près que le comportement consiste à dupliquer vers les N-1 premiers ports du bloc et à rediriger vers le dernier (notez que le port où le paquet est arrivé ne sera ni dupliqué ni redirigé).

OPTIONS

ingress
egress
Spécifie la direction dans laquelle le paquet doit apparaître sur l'interface de destination.
mirror
redirect
Définit si le paquet doit être copié (mirror) ou déplacé (redirect) vers l'interface ou le bloc de destination.
index INDEX
Attribue un identifiant unique à cette action au lieu de laisser le noyau en choisir un automatiquement. INDEX est un entier non signé de 32 bits supérieur à zéro.
dev NOM_DE_PERIPHERIQUE
Spécifie l'interface réseau vers laquelle rediriger ou dupliquer.
blockid ID_BLOQUÉ
Spécifie le bloc tc vers lequel rediriger ou dupliquer.

EXEMPLES

Limiter la bande passante entrante sur eth0 à 1 Mbps, rediriger le trafic excédentaire vers lo à des fins de débogage :

# tc qdisc add dev eth0 handle ffff: clsact
# tc filter add dev eth0 ingress u32 \
	match u32 0 0 \
	action police rate 1mbit burst 100k conform-exceed pipe \
	action mirred egress redirect dev lo

Dupliquer tous les paquets ICMP entrants sur eth0 vers une interface factice pour examen avec par exemple tcpdump :

# ip link add dummy0 type dummy
# ip link set dummy0 up
# tc qdisc add dev eth0 handle ffff: clsact
# tc filter add dev eth0 ingress protocol ip \
	u32 match ip protocol 1 0xff \
	action mirred egress mirror dev dummy0

En utilisant une interface ifb, il est possible d'envoyer le trafic entrant à travers une instance de sfq :

# modprobe ifb
# ip link set ifb0 up
# tc qdisc add dev ifb0 root sfq
# tc qdisc add dev eth0 handle ffff: clsact
# tc filter add dev eth0 ingress u32 \
	match u32 0 0 \
	action mirred egress redirect dev ifb0

LIMITATIONS

Le noyau restreint l'imbrication à quatre niveaux pour éviter les boucles d'imbrication.

Ne redirigez pas d'un périphérique IFB vers un autre. IFB est un cas très spécialisé de périphérique de redirection de paquets. La redirection de ifbX vers ifbY entraînera le rejet de tous les paquets.
