NOM

tcpprep - Créer un fichier de cache tcpreplay à partir d'un fichier pcap.

SYNTAXE

tcpprep [-flags] [-flag [valeur]] [--nom-option[[=| ]valeur]]

Tous les arguments doivent être des options.

tcpprep est un pré-processeur de fichier pcap(3) qui crée un fichier de cache fournissant des « règles » pour tcprewrite(1) et tcpreplay(1) sur la façon de traiter et d'envoyer des paquets.

DESCRIPTION

L'opération de base de tcpreplay est de renvoyer tous les paquets des fichiers d'entrée vers un seul fichier. Tcpprep traite un fichier pcap et applique un ensemble de règles spécifiées par l'utilisateur pour créer un fichier de cache qui indique à tcpreplay si chaque paquet doit être envoyé et sur quelle interface le paquet doit être envoyé.

Pour plus de détails, veuillez consulter le Manuel Tcpreplay à l'adresse : http://tcpreplay.appneta.com

OPTIONS

-d nombre, --dbug=nombre

Activer la sortie de débogage. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est limitée à : 
dans l'intervalle 0 à 5

La valeur par défaut de nombre pour cette option est :
0

Si configuré avec --enable-debug, vous pouvez spécifier un niveau de verbosité pour la sortie de débogage. Des nombres plus élevés augmentent la verbosité.

-a chaîne, --auto=chaîne

Mode de division automatique. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : cidr, port, regex, mac.

Tcpprep essaiera de déterminer automatiquement la fonction principale des hôtes en fonction du trafic capturé et classera chaque hôte comme client ou serveur. Pour ce faire, vous devez fournir une indication à tcpprep sur la manière de rechercher les clients et les serveurs. Les indications valides sont :

bridge Le mode pont traite chaque paquet pour essayer de déterminer si l'expéditeur est un client ou un serveur. Une fois tous les paquets traités, les résultats sont pondérés en fonction du ratio serveur/client (--ratio) et les systèmes se voient attribuer une interface. Si tcpprep ne parvient pas à déterminer le rôle d'un système, tcpprep s'arrête.

router Le mode routeur fonctionne comme le mode pont, sauf qu'après la pondération, les systèmes indéterminés sont considérés comme des serveurs s'ils se trouvent à l'intérieur d'un réseau connu pour contenir d'autres serveurs. Le mode routeur a une plus grande chance de réussir à diviser les clients et les serveurs, mais n'est pas infaillible à 100 %.

client Le mode client fonctionne comme le mode pont, sauf que les systèmes non classifiés sont traités comme des clients. Le mode client devrait toujours se terminer avec succès.

server Le mode serveur fonctionne comme le mode pont, sauf que les systèmes non classifiés sont traités comme des serveurs. Le mode serveur devrait toujours se terminer avec succès.

first Le mode premier examine la première fois que chaque IP est vue dans les champs SRC et DST de l'en-tête IP. Si l'hôte est vu pour la première fois dans le champ SRC, il s'agit d'un client et s'il est vu pour la première fois dans le champ DST, il est marqué comme un serveur. Ceci reproduit efficacement le traitement de l'outil de test tomahawk. Le mode premier devrait toujours se terminer avec succès.

-c chaîne, --cidr=chaîne

Mode de division CIDR. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : auto, port, regex, mac.

Spécifiez une liste d'adresses réseau CIDR séparées par des virgules pour correspondre à l'adresse IP source de chaque paquet. Les paquets correspondant à l'un des CIDR sont classés comme serveurs.

Exemple IPv4 :

    --cidr=192.168.0.0/16,172.16.0.0/12,10.0.0.0/8
Exemple IPv6 : 
    --cidr=[::ffff:0:0/96],[fe80::/16]
-r chaîne, --regex=chaîne

Mode de division par expression régulière. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : auto, port, cidr, mac.

Spécifiez une expression régulière pour correspondre à l'adresse IP source de chaque paquet. Les paquets correspondant à l'expression régulière sont classés comme serveurs.

-p, --port

Mode de division par port. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : auto, regex, cidr, mac.

Spécifie que le trafic TCP et UDP sur IPv4 et IPv6 doit être classé comme client ou serveur en fonction du port de destination de l'en-tête.

-e chaîne, --mac=chaîne

Mode de division par adresse MAC source. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : auto, regex, cidr, port.

Spécifiez une liste d'adresses MAC pour correspondre à l'adresse MAC source de chaque paquet. Les paquets correspondant à l'une des valeurs sont classés comme serveurs.

--reverse

Correspondances pour être client au lieu de serveur. Cette option peut apparaître jusqu'à 1 fois.

Normalement, les indicateurs --mac, --regex et --cidr spécifient les serveurs et les paquets non-IP sont classés comme clients. En utilisant --reverse, ces fonctionnalités sont inversées afin que les indicateurs spécifient les clients et que les paquets non-IP soient classés comme serveurs.

-C chaîne, --comment=chaîne

Commentaire de fichier de cache intégré. Cette option peut apparaître jusqu'à 1 fois.

Spécifiez un commentaire à intégrer dans le fichier de cache de sortie et à visualiser ultérieurement.

--no-arg-comment

Ne pas intégrer de commentaire de fichier de cache. Cette option peut apparaître jusqu'à 1 fois.

Par défaut, tcpprep inclut les arguments passés sur la ligne de commande dans le commentaire du fichier de cache (en plus de tout commentaire spécifié par l'utilisateur avec --comment). Si, pour une raison quelconque, vous ne souhaitez pas l'inclure, spécifiez cette option.

-x chaîne, --include=chaîne

Inclure uniquement les paquets correspondant à la règle. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : exclude.

Remplace la valeur par défaut de traitement de tous les paquets stockés dans le fichier de capture et n'envoie/modifie que les paquets qui correspondent à la règle fournie. Les règles peuvent être l'une des suivantes :

S:<CIDR1>,... - L'adresse IP source doit correspondre aux CIDR IPv4/v6 spécifiés.

D:<CIDR1>,... - L'adresse IP de destination doit correspondre aux CIDR IPv4/v6 spécifiés.

B:<CIDR1>,... - L'adresse IP source et l'adresse IP de destination doivent correspondre aux CIDR IPv4/v6 spécifiés.

E:<CIDR1>,... - L'une des adresses IP doit correspondre aux CIDR IPv4/v6 spécifiés.

P:<LISTE> - Doit être l'un des paquets listés, où la liste correspond au numéro de paquet dans le fichier de capture.

    -x P:1-5,9,15,72-
traitera les paquets 1 à 5, le 9ème et le 15ème paquet, et les paquets 72 jusqu'à la fin du fichier.

F:'<bpf>' - Filtre BPF. Voir la page de manuel de tcpdump(8) pour la syntaxe.

-X chaîne, --exclude=chaîne

Exclure tout paquet correspondant à cette règle. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : include.

Remplace la valeur par défaut de traitement de tous les paquets stockés dans le fichier de capture et n'envoie/modifie que les paquets qui ne correspondent PAS à la règle fournie. Les règles peuvent être l'une des suivantes :

S:<CIDR1>,... - L'adresse IP source ne doit pas correspondre aux CIDR IPv4/v6 spécifiés.

D:<CIDR1>,... - L'adresse IP de destination ne doit pas correspondre aux CIDR IPv4/v6 spécifiés.

B:<CIDR1>,... - L'adresse IP source et l'adresse IP de destination ne doivent pas correspondre aux CIDR IPv4/v6 spécifiés.

E:<CIDR1>,... - Aucune des adresses IP ne doit correspondre aux CIDR IPv4/v6 spécifiés.

P:<LISTE> - Ne doit pas être l'un des paquets listés, où la liste correspond au numéro de paquet dans le fichier de capture.

    -X P:1-5,9,15,72-
exclura les paquets 1 à 5, le 9ème et le 15ème paquet, et les paquets 72 jusqu'à la fin du fichier.

F:'<bpf>' - Filtre BPF. Voir la page de manuel de tcpdump(8) pour la syntaxe.

-i fichier, --infile=fichier

Fichier d'entrée pcap. Cette option peut apparaître jusqu'à 1 fois.

Spécifie le fichier de capture pcap qui doit être lu. Si cette option n'est pas spécifiée, tcpprep lit à partir de stdin.

-o fichier, --outfile=fichier

Fichier de sortie cache. Cette option peut apparaître jusqu'à 1 fois.

Spécifie le nom du fichier de cache qui sera écrit. Si cette option n'est pas spécifiée, tcpprep écrit dans stdout.

--ratio=nombre

Ratio de clients/serveurs. Cette option peut apparaître jusqu'à 1 fois.

Cette option est utilisée en conjonction avec le mode de division automatique (`--auto`) et permet de spécifier le ratio minimum de paquets clients sur paquets serveurs pour que les systèmes indéterminés soient classés comme clients. La valeur par défaut est 1.0.

-I nombre, --interface=nombre

Identifiant de l'interface. Cette option peut apparaître jusqu'à 1 fois.

Par défaut, tcpprep génère un identifiant d'interface unique pour chaque paire de client/serveur détectée. Cette option permet de spécifier un identifiant pour chaque client et serveur afin de simplifier le traitement des paquets.

Si l'option --list-interfaces est utilisée, alors une seule interface peut être spécifiée.

--list-interfaces

Lister les interfaces. Cette option peut apparaître jusqu'à 1 fois.

Au lieu de créer un fichier de cache, cette option affiche une liste des interfaces détectées et des identifiants d'interface qui seront utilisés.

-h, --help

Afficher un message d'aide et quitter.
-V, --version

Afficher les informations de version et quitter.

EXEMPLES

Créer un fichier de cache nommé cache.db à partir du fichier input.pcap en utilisant le mode de division par port :

    tcpprep -i input.pcap -o cache.db -p

Créer un fichier de cache nommé cache.db à partir du fichier input.pcap en utilisant le mode de division automatique (pont) et en traitant uniquement les paquets dont l'adresse IP source se trouve dans le bloc CIDR 192.168.1.0/24 :

    tcpprep -i input.pcap -o cache.db -a bridge -x S:192.168.1.0/24

    NOM

    tcpprep - Filtre pour les paquets TCP/IP

    SYNTAXE

    tcpprep [-a|-A] [-d|-D] [-q|-Q] [-v|-V] [-h] [-i <fichier_entree>] [-o <fichier_sortie>] [-c <fichier_config>] [-p <protocole>] [-s <taille_tampon>] [-m <max_connexions>]

    DESCRIPTION

    tcpprep est un outil de filtrage de paquets TCP/IP conçu pour simplifier la gestion des règles de pare-feu et la surveillance du trafic réseau. Il permet de sélectionner des paquets basés sur divers critères tels que les adresses IP source et destination, les ports, les protocoles, et plus encore. Il peut être utilisé pour bloquer le trafic indésirable, autoriser le trafic légitime, ou simplement pour collecter des informations sur le trafic réseau.

    OPTIONS

    -a, --accept
    Accepte les paquets correspondant aux règles.
    -A, --accept-all
    Accepte tous les paquets.
    -d, --drop
    Rejette les paquets correspondant aux règles.
    -D, --drop-all
    Rejette tous les paquets.
    -q, --quiet
    Mode silencieux, n'affiche pas les messages d'information.
    -Q, --verbose
    Mode verbeux, affiche plus d'informations sur le traitement des paquets.
    -v, --version
    Affiche la version de tcpprep.
    -V, --usage
    Affiche les informations d'utilisation.
    -h, --help
    Affiche l'aide complète.
    -i <fichier_entree>, --input <fichier_entree>
    Spécifie le fichier d'entrée contenant les paquets à filtrer (par défaut, l'entrée standard).
    -o <fichier_sortie>, --output <fichier_sortie>
    Spécifie le fichier de sortie pour les paquets traités (par défaut, la sortie standard).
    -c <fichier_config>, --config <fichier_config>
    Spécifie le fichier de configuration contenant les règles de filtrage.
    -p <protocole>, --protocol <protocole>
    Spécifie le protocole à filtrer (par exemple, tcp, udp, icmp).
    -s <taille_tampon>, --buffer-size <taille_tampon>
    Définit la taille du tampon pour la lecture des paquets.
    -m <max_connexions>, --max-connections <max_connexions>
    Définit le nombre maximum de connexions à suivre simultanément.

    EXEMPLES

    Filtrer les paquets TCP entrants depuis 192.168.1.100 vers le port 80 et les rejeter :

    tcpprep -i capture.pcap -o dropped.pcap -c rules.conf -d -p tcp

    Accepter tous les paquets UDP provenant de n'importe quelle source vers le port 53 :

    tcpprep -i capture.pcap -o accepted.pcap -c rules.conf -a -p udp
