tcpbridge(1) Commandes utilisateur tcpbridge(1)

NOM

tcpbridge - Pont de trafic réseau entre deux interfaces

SYNOPIS

tcpbridge [-flags] [-flag [valeur]] [--option-name[[=| ]valeur]]

Tous les arguments doivent être des options.

tcpbridge est un outil pour relier sélectivement le trafic réseau entre deux interfaces et modifier éventuellement les paquets entre les deux.

DESCRIPTION

L'opération de base de tcpbridge est de servir de pont réseau entre deux sous-réseaux. Tous les paquets reçus sur une interface sont envoyés via l'autre.

Optionnellement, les paquets peuvent être modifiés de diverses manières selon vos besoins.

Pour plus de détails, veuillez consulter le Manuel de Tcpreplay à l'adresse : http://tcpreplay.appneta.com

OPTIONS

-r chaîne, --portmap=chaîne

Réécrit les ports TCP/UDP. Cette option peut apparaître jusqu'à 9999 fois.

Spécifie une liste de mappages de ports délimités par des virgules, constitués de paires de numéros de ports délimités par des deux-points. Chaque paire de ports délimitée par des deux-points consiste en le port à faire correspondre suivi du numéro de port à réécrire.

Exemples :

    --portmap=80:8000 --portmap=8080:80    # 80->8000 et 8080->80
    --portmap=8000,8080,88888:80           # 3 ports différents deviennent 80
    --portmap=8000-8999:80                 # les ports 8000 à 8999 deviennent 80
-s nombre, --seed=nombre

Randomise les adresses IPv4/v6 src/dst avec la graine donnée. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : fuzz-seed. Cette option prend un nombre entier comme argument.

Cause la pseudo-randomisation des adresses IPv4/v6 source et destination tout en maintenant les relations client/serveur. Étant donné que la randomisation est déterministe en fonction de la graine, vous pouvez réutiliser la même valeur de graine pour recréer le trafic.

-N chaîne, --pnat=chaîne

Réécrit les adresses IPv4/v6 en utilisant un pseudo-NAT. Cette option peut apparaître jusqu'à 2 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : srcipmap.

Prend une série de paires de blocs CIDR délimités par des virgules et des deux-points. Chaque paire de blocs est évaluée dans l'ordre par rapport aux adresses IP. Si l'adresse IP dans le paquet correspond au premier bloc, elle est réécrite en utilisant le second bloc comme masque sur les bits de poids fort.

Exemple IPv4 :

    --pnat=192.168.0.0/16:10.77.0.0/16,172.16.0.0/12:10.1.0.0/24
Exemple IPv6 : 
    --pnat=[2001:db8::/32]:[dead::/16],[2001:db8::/32]:[::ffff:0:0/96]
-S chaîne, --srcipmap=chaîne

Réécrit les adresses IP source IPv4/v6 en utilisant un pseudo-NAT. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : pnat.

Fonctionne comme l'option --pnat, mais n'affecte que les adresses IP source dans l'en-tête IPv4/v6.

-D chaîne, --dstipmap=chaîne

Réécrit les adresses IP de destination IPv4/v6 en utilisant un pseudo-NAT. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : pnat.

Fonctionne comme l'option --pnat, mais n'affecte que les adresses IP de destination dans l'en-tête IPv4/v6.

-e chaîne, --endpoints=chaîne

Réécrit les adresses IP pour qu'elles se situent entre deux points de terminaison. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : cachefile.

Prend une paire d'adresses IPv4/v6 délimitées par des deux-points qui seront utilisées pour réécrire tout le trafic afin qu'il apparaisse se situer entre les deux adresses IP.

Exemple IPv4 :

    --endpoints=172.16.0.1:172.16.0.2
Exemple IPv6 : 
    --endpoints=[2001:db8::dead:beef]:[::ffff:0:0:ac:f:0:2]
--tcp-sequence=nombre

Modifie les numéros de séquence (et ACK) TCP avec la graine donnée. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 1

La valeur par défaut de nombre pour cette option est :
0

Modifie tous les numéros de séquence TCP, et les numéros de séquence-accusé de réception associés. Ils seront décalés d'un montant aléatoire basé sur la graine fournie.

-b, --skipbroadcast

Ignore la réécriture des adresses IPv4/v6 de diffusion/multidiffusion.

Par défaut, --seed, --pnat et --endpoints réécrivent les adresses IPv4/v6 et MAC de diffusion et de multidiffusion. La définition de ce drapeau empêchera la réécriture des adresses IPv4/v6 et MAC de diffusion et de multidiffusion.

-C, --fixcsum

Force le recalcul des sommes de contrôle des en-têtes IPv4/TCP/UDP.

Fait en sorte que chaque paquet IPv4/v6 recalcule et corrige ses sommes de contrôle. Activé automatiquement pour les paquets modifiés avec --seed, --pnat, --endpoints ou --fixlen.

--fixhdrlen

Modifie la longueur des en-têtes IP/TCP pour correspondre à la longueur du paquet.

Par défaut, tcpreplay envoie les paquets avec la longueur d'origine du paquet. Cependant, vous voudrez peut-être que la longueur du paquet soit révisée à la taille minimale du paquet. En utilisant cette option, tcpreplay réécrira (corrige) la longueur du paquet et recalculera les sommes de contrôle lorsque la longueur du paquet change. Attention : des changements de paquet indésirables peuvent survenir lorsque cette option est spécifiée.

-m nombre, --mtu=nombre

Remplace la longueur MTU par défaut (1500 octets). Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage  1 à MAX_SNAPLEN

Remplace la taille MTU par défaut de 1500 octets pour déterminer la longueur de remplissage maximale (--fixlen=pad) ou lors de la troncature (--mtu-trunc).

--mtu-trunc

Tronque les paquets plus grands que la MTU spécifiée. Cette option peut apparaître jusqu'à 1 fois.

Similaire à --fixlen, cette option tronquera les données dans les paquets de la couche 3 et supérieure pour qu'elles ne dépassent pas la MTU.

-E, --efcs

Supprime les sommes de contrôle Ethernet (FCS) à la fin des trames.

Attention, cette option est assez dangereuse ! Nous ne vérifions pas réellement si une FCS existe dans la trame, nous supprimons simplement aveuglément les 4 derniers octets. Par conséquent, vous ne devriez l'utiliser que si vous savez que votre système d'exploitation fournit la FCS lors de la lecture des paquets bruts.

--ttl=chaîne

Modifie le TTL/Hop Limit IPv4/v6.

Permet de modifier le TTL/Hop Limit de tous les paquets IPv4/v6. Spécifiez un nombre pour coder en dur la valeur ou +/- une valeur pour augmenter ou diminuer de la valeur fournie (limité à 1-255).

Exemples :

    --ttl=10
    --ttl=+7
    --ttl=-64
--tos=nombre

Définit l'octet TOS/DiffServ/ECN IPv4. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage  0 à 255

Permet de remplacer la valeur TOS (également connue sous le nom de DiffServ/ECN) dans IPv4.

--tclass=nombre

Définit l'octet Traffic Class IPv6. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage  0 à 255

Vous permet de remplacer le champ Classe de trafic IPv6.

--flowlabel=nombre

Définit le label de flux IPv6. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 0 à 1048575

Vous permet de remplacer le champ 20 bits de label de flux IPv6. N'a aucun effet sur les paquets IPv4.

-F chaîne, --fixlen=chaîne

Remplit ou tronque les données du paquet pour correspondre à la longueur de l'en-tête. Cette option peut apparaître jusqu'à 1 fois.

Les paquets peuvent être tronqués pendant la capture si la snaplen est plus petite que le paquet. Cette option vous permet de modifier le paquet pour le remplir à la taille stockée dans l'en-tête IPv4/v6 ou de réécrire la longueur totale de l'en-tête IP pour refléter la longueur du paquet stockée.

pad Les paquets tronqués seront remplis de manière à ce que la longueur du paquet corresponde à la longueur totale IPv4.

trunc Les paquets tronqués auront leur champ de longueur totale IPv4 réécrit pour correspondre à la longueur réelle du paquet.

del Supprime le paquet.

--fuzz-seed=nombre

Fuzz 1 paquet sur X. Modifie les octets, la longueur, ou émule la perte de paquet. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 0

La valeur par défaut de nombre pour cette option est :
0

Ce "fuzzing" a été conçu pour tester les protocoles de couche 7 tels que les protocoles VoIP. Il modifie aléatoirement 1 paquet sur X (où X = --fuzz-factor) afin que les protocoles à états couvrent une plus grande partie de leur code. Les actions de "fuzzing" aléatoires se concentrent sur le début et la fin des données, car c'est souvent la partie des données sur laquelle les protocoles applicatifs basent leurs décisions.

Liste des actions de "fuzzing" possibles :
* abandonner le paquet
* réduire la taille du paquet
* modifier les octets du paquet :
* Tous les octets n'ont pas la même probabilité d'apparition dans la vie réelle.
Remplacer par 0x00, 0xFF, ou un octet aléatoire avec une probabilité égale.
* Tous les octets n'ont pas la même signification dans un paquet.
Remplacer le début, la fin ou le milieu du paquet avec une probabilité égale.
* ne rien faire (7 paquets sur 8)

--fuzz-factor=nombre

Définit le ratio de "Fuzz" 1 sur X paquets (par défaut 1 sur 8 paquets). Cette option doit apparaître en combinaison avec les options suivantes : fuzz-seed. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 1

La valeur par défaut de nombre pour cette option est :
8

Définit le ratio pour l'option --fuzz-seed. Par défaut, cette valeur est 8, ce qui signifie que 1 paquet sur 8 est modifié par le "fuzzing". Notez que ce ratio est basé sur le nombre aléatoire généré par la graine de "fuzz" fournie. Par conséquent, par défaut, vous ne pouvez pas vous attendre à ce qu'exactement tous les huit paquets soient modifiés.

--skipl2broadcast

Ignore la réécriture des adresses de couche 2 de diffusion/multidiffusion.

Par défaut, la modification des adresses de couche 2 réécrit les adresses MAC de diffusion et de multidiffusion. L'activation de ce drapeau empêchera la réécriture des adresses MAC de diffusion/multidiffusion.

--dlt=chaîne

Remplace le DLT d'encapsulation de sortie. Cette option peut apparaître jusqu'à 1 fois.

Par défaut, aucune conversion de DLT (type de liaison de données) ne sera effectuée. Pour changer le type DLT de la sortie pcap, sélectionnez l'une des valeurs suivantes :

enet Ethernet alias DLT_EN10MB

hdlc Cisco HDLC alias DLT_C_HDLC

jnpr_eth Juniper Ethernet DLT_C_JNPR_ETHER

pppserial PPP Série alias DLT_PPP_SERIAL

user En-tête de couche 2 et type DLT spécifiés par l'utilisateur

--enet-dmac=chaîne

Remplace les adresses MAC Ethernet de destination. Cette option peut apparaître jusqu'à 1 fois.

Prend une paire d'adresses MAC Ethernet délimitées par des virgules qui remplaceront l'adresse MAC de destination des paquets sortants. La première adresse MAC sera utilisée pour le trafic du serveur vers le client et la seconde adresse MAC optionnelle sera utilisée pour le trafic du client vers le serveur.

Exemple :

    --enet-dmac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-smac=chaîne

Remplace les adresses MAC Ethernet source. Cette option peut apparaître jusqu'à 1 fois.

Prend une paire d'adresses MAC Ethernet délimitées par des virgules qui remplaceront l'adresse MAC source des paquets sortants. La première adresse MAC sera utilisée pour le trafic du serveur vers le client et la seconde adresse MAC optionnelle sera utilisée pour le trafic du client vers le serveur.

Exemple :

    --enet-smac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-subsmac=chaîne

Substitue les adresses MAC. Cette option peut apparaître jusqu'à 9999 fois.

Vous permet de réécrire les adresses MAC Ethernet des paquets. Elle prend une paire d'adresses MAC délimitées par des virgules et réécrit toutes les occurrences de la première adresse MAC avec la valeur de la seconde adresse MAC. Exemple :

    --enet-subsmac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-mac-seed=nombre

Randomise les adresses MAC. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec aucune des options suivantes : enet-smac, enet-dmac, enet-subsmac. Cette option prend un nombre entier comme argument.

Vous permet de randomiser les adresses MAC Ethernet des paquets, un peu comme ce que fait l'option --seed pour les adresses IPv4/IPv6.

--enet-mac-seed-keep-bytes=nombre

Randomise les adresses MAC. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-mac-seed. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 1 à 6

Conserve certains octets intacts lors de l'utilisation de l'option --enet-mac-seed.

--enet-vlan=chaîne

Spécifie le mode de marquage VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois.

Vous permet de réécrire les trames Ethernet pour ajouter un en-tête 802.1q aux en-têtes Ethernet standard 802.3 ou pour supprimer les informations de marquage VLAN 802.1q.

add Ajoute un en-tête VLAN 802.1q à l'en-tête Ethernet 802.3 existant. Si un en-tête VLAN existe déjà, un nouvel en-tête VLAN est ajouté à l'extérieur de l'en-tête existant.

Notez que vous pourrez exécuter cette option plusieurs fois pour créer plus de 2 en-têtes VLAN, bien que ces paquets soient valides. Au maximum, vous devriez avoir 2 balises VLAN 802.1Q, ou une balise VLAN externe 802.1ad et une balise VLAN interne 802.1Q.

del Réécrit l'en-tête VLAN 802.1q existant en tant qu'en-tête Ethernet 802.3.

--enet-vlan-tag=nombre

Spécifie la nouvelle valeur de la balise VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-vlan. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 0 à 4095

--enet-vlan-cfi=nombre

Spécifie la valeur CFI du VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-vlan. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 0 à 1

--enet-vlan-pri=nombre

Spécifie la priorité VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-vlan. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 0 à 7

--enet-vlan-proto=chaîne

Spécifie le protocole de balisage VLAN 802.1q ou 802.1ad. Cette option peut apparaître jusqu'à 1 fois.

Vous permet de spécifier le protocole des balises VLAN ajoutées.

802.1q Spécifie que des en-têtes VLAN 802.1q doivent être ajoutés. C'est le comportement par défaut.

802.1ad Spécifie que des en-têtes VLAN Q-in-Q 802.1ad doivent être ajoutés. Pour créer des paquets valides, les paquets d'entrée doivent déjà avoir des en-têtes VLAN 802.1q.

--hdlc-control=nombre

Spécifie la valeur de contrôle HDLC. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

L'en-tête Cisco HDLC a un champ "contrôle" de 1 octet. Apparemment, cela devrait toujours être 0, mais vous pouvez utiliser n'importe quelle valeur de 1 octet.

--hdlc-address=nombre

Spécifie l'adresse HDLC. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

L'en-tête Cisco HDLC a un champ "adresse" de 1 octet qui a deux valeurs valides :

0x0F Unicast

0xBF Broadcast
Vous pouvez cependant spécifier n'importe quelle valeur d'un seul octet.

--user-dlt=nombre

Définit le type DLT du fichier de sortie. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

Définit la valeur DLT du fichier pcap de sortie.

--user-dlink=chaîne

Réécrire la couche de liaison de données avec les données spécifiées par l'utilisateur. Cette option peut apparaître jusqu'à 2 fois.

Fournissez une série de valeurs hexadécimales délimitées par des virgules qui seront utilisées pour réécrire ou créer l'en-tête de couche 2 des paquets. La première instance de cet argument réécrira le trafic du serveur et du client, mais si cet argument est spécifié une seconde fois, il sera utilisé pour le trafic du client.

Exemple:

    --user-dlink=01,02,03,04,05,06,00,1A,2B,3C,4D,5E,6F,08,00
-d nombre, --dbug=nombre

Activer la sortie de débogage. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
dans la plage 0 à 5

Le nombre par défaut pour cette option est :
0

Si configuré avec --enable-debug, vous pouvez spécifier un niveau de verbosité pour la sortie de débogage. Des nombres plus élevés augmentent la verbosité.

-i chaîne, --intf1=chaîne

Interface principale (écoute en mode unidirectionnel). Cette option peut apparaître jusqu'à 1 fois.
-I chaîne, --intf2=chaîne

Interface secondaire (envoi en mode unidirectionnel). Cette option peut apparaître jusqu'à 1 fois.
-u, --unidir

Envoyer et recevoir dans une seule direction. Cette option peut apparaître jusqu'à 1 fois.

Normalement, tcpbridge envoie et reçoit du trafic dans les deux directions (bidirectionnellement). Cependant, si vous choisissez cette option, le trafic sera envoyé de manière unidirectionnelle.

--listnics

Lister les interfaces réseau disponibles et quitter.
-L nombre, --limit=nombre

Limiter le nombre de paquets à envoyer. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
supérieur ou égal à 1

Le nombre par défaut pour cette option est :
-1

Par défaut, tcpbridge enverra des paquets indéfiniment ou jusqu'à Ctrl-C. Alternativement, vous pouvez spécifier un nombre maximum de paquets à envoyer.

-M chaîne, --mac=chaîne

Adresses MAC des NIC locales. Cette option peut apparaître jusqu'à 2 fois.

tcpbridge ne prend pas en charge la détection des adresses MAC des interfaces réseau locales sous Windows. Veuillez spécifier les deux adresses MAC des interfaces utilisées dans le pont : -M <mac_intf1> -M <mac_intf2>

-x chaîne, --include=chaîne

Inclure uniquement les paquets correspondant à la règle. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : exclude.

Remplacer la valeur par défaut d'envoi de tous les paquets stockés dans le fichier de capture et n'envoyer que les paquets qui correspondent à la règle fournie. Les règles peuvent être l'une des suivantes :

S:<CIDR1>,... - L'adresse IP source doit correspondre aux CIDR spécifiés.

D:<CIDR1>,... - L'adresse IP de destination doit correspondre aux CIDR spécifiés.

B:<CIDR1>,... - L'adresse IP source et de destination doit correspondre aux CIDR spécifiés.

E:<CIDR1>,... - L'une ou l'autre des adresses IP doit correspondre aux CIDR spécifiés.

P:<LISTE> - Doit être l'un des paquets listés, où la liste correspond au numéro de paquet dans le fichier de capture.

    --include=P:1-5,9,15,72-
enverrait les paquets 1 à 5, le 9e et le 15e paquet, et les paquets 72 jusqu'à la fin du fichier

F:'<bpf>' - Filtre BPF. Voir la page de manuel de tcpdump(8) pour la syntaxe.

-X chaîne, --exclude=chaîne

Exclure tout paquet correspondant à cette règle. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : include.

Remplacer la valeur par défaut d'envoi de tous les paquets stockés dans le fichier de capture et n'envoyer que les paquets qui ne correspondent pas à la règle fournie. Les règles peuvent être l'une des suivantes :

S:<CIDR1>,... - L'adresse IP source ne doit pas correspondre aux CIDR spécifiés.

D:<CIDR1>,... - L'adresse IP de destination ne doit pas correspondre aux CIDR spécifiés.

B:<CIDR1>,... - L'adresse IP source et de destination ne doit pas correspondre aux CIDR spécifiés.

E:<CIDR1>,... - L'une ou l'autre des adresses IP ne doit pas correspondre aux CIDR spécifiés.

P:<LISTE> - Ne doit pas être l'un des paquets listés, où la liste correspond au numéro de paquet dans le fichier de capture.

    --exclude=P:1-5,9,15,72-
ignorerait les paquets 1 à 5, le 9e et le 15e paquet, et les paquets 72 jusqu'à la fin du fichier
-P, --pid

Afficher le PID de tcpbridge au démarrage.
-v, --verbose

Afficher les paquets décodés via tcpdump sur STDOUT. Cette option peut apparaître jusqu'à 1 fois.
-A chaîne, --decode=chaîne

Arguments passés au décodeur tcpdump. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec les options suivantes : verbose.

Lors de l'activation du mode verbeux (-v), vous pouvez également spécifier un ou plusieurs arguments supplémentaires à passer à tcpdump pour modifier la façon dont les paquets sont décodés. Par défaut, -n et -l sont utilisés. Assurez-vous de mettre les arguments entre guillemets, comme : --verbose="-axxx", afin qu'ils ne soient pas interprétés par tcpbridge. Les arguments suivants sont valides :
[ -aAeNqRStuvxX ]
[ -E spi@ipaddr algo:secret,... ]
[ -s snaplen ]

-V, --version

Afficher les informations de version.
-h, --less-help

Afficher moins d'informations d'utilisation et quitter.
-w, --suppress-warnings

Supprimer l'affichage des messages d'avertissement.
-H, --help

Afficher les informations d'utilisation et quitter.
-!, --more-help

Transmettre les informations d'utilisation étendues à un paginateur.
--save-opts [=cfgfile]

Enregistrer l'état des options dans cfgfile. Par défaut, il s'agit du dernier fichier de configuration listé dans la section OPTION PRESETS ci-dessous. La commande se terminera après la mise à jour du fichier de configuration.
--load-opts=cfgfile, --no-load-opts

Charger les options depuis cfgfile. La forme no-load-opts désactivera le chargement des fichiers de configuration/RC/INI précédents. --no-load-opts est géré tôt, hors séquence.

PRÉRÉGLAGES D'OPTIONS

Toute option qui n'est pas marquée comme non présélectionnable peut être présélectionnée en chargeant des valeurs à partir de fichiers de configuration ("RC" ou ".INI"). Le fichier homerc est "$$/", sauf si c'est un répertoire. Dans ce cas, le fichier ".tcpbridgerc" est recherché dans ce répertoire.

FICHIERS

Voir PRÉRÉGLAGES D'OPTIONS pour les fichiers de configuration.

STATUT DE SORTIE

L'une des valeurs de sortie suivantes sera retournée :

0 (EXIT_SUCCESS)

Exécution réussie du programme.
1 (EXIT_FAILURE)

L'opération a échoué ou la syntaxe de la commande n'était pas valide.
66 (EX_NOINPUT)

tcpreplay(1)

NOM

tcpreplay - relire des paquets réseau à partir d'un fichier PCAP.

SYNTAXE

tcpreplay [ options ] pcapfile [ pcapfile ... ]

DESCRIPTION

tcpreplay est un utilitaire permettant de relire des paquets réseau enregistrés dans des fichiers PCAP. Il peut être utilisé pour tester des systèmes de détection d'intrusion (IDS), des outils d'analyse réseau, des serveurs, etc. en simulant du trafic réseau réel.

OPTIONS

-i, --interface <interface>
Spécifie l'interface réseau sur laquelle envoyer les paquets. Si non spécifié, tcpreplay tentera de trouver une interface appropriée.
-p, --pps <pps>
Définit le débit de paquets par seconde (packets per second - PPS). Utilise "auto" pour un débit automatique basé sur la capture originale.
-t, --topspeed
Relire les paquets le plus rapidement possible, sans tenir compte du débit original.
-l, --loop <nombre>
Spécifie le nombre de fois où le fichier PCAP doit être relu. 0 signifie une relecture infinie.
-K, --kill-on-complete
Arrête tcpreplay lorsque tous les paquets ont été relus.
-s, --snapshot-gap <nanosecondes>
Définit l'intervalle entre les captures de paquets (snapshot gap) pour les fichiers PCAP qui n'ont pas d'intervalles définis.
-M, --multiplier <facteur>
Multiplie la durée entre les paquets par ce facteur. Une valeur de 2.0 ralentira le trafic, une valeur de 0.5 l'accélérera.
-T, --timer <type>
Spécifie le type de minuterie à utiliser (realtime, monotonic, cpu).
-h, --help
Affiche l'aide et quitte.
-V, --version
Affiche les informations de version et quitte.

PRÉCONFIGURATIONS D'OPTIONS

tcpreplay prend en charge des préréglages d'options pour simplifier les commandes courantes. Par exemple, tcpreplay-edit (qui fait partie de la suite tcpreplay) peut être utilisé pour modifier les fichiers PCAP avant de les relire.

FICHIERS

/etc/tcpreplay.conf
Fichier de configuration par défaut pour tcpreplay.

0 en cas de succès, autre chose en cas d'erreur.
