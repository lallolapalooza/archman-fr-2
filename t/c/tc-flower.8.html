NOM

flower - filtre de contrôle de trafic basé sur les flux

SYNOPSIS


tc filter ... flower [ LISTE_MATCH ] [ action SPEC_ACTION ] [ classid ID_CLASSE ] [ hw_tc ID_TC ]

LISTE_MATCH := [ LISTE_MATCH ] MATCH

MATCH := { indev nom_interface | verbose | skip_sw | skip_hw | { dst_mac | src_mac } ADRESSE_LL_MASQUE | vlan_id VID | vlan_prio PRIORITE | vlan_ethtype { ipv4 | ipv6 | TYPE_ETH } | cvlan_id VID | cvlan_prio PRIORITE | cvlan_ethtype { ipv4 | ipv6 | TYPE_ETH } | pppoe_sid PSID | ppp_proto { ip | ipv6 | mpls_uc | mpls_mc | PROTO_PPP } | mpls LISTE_LSE | mpls_label LABEL | mpls_tc TC | mpls_bos BOS | mpls_ttl TTL | l2tpv3_sid LSID | ip_proto { tcp | udp | sctp | icmp | icmpv6 | l2tp | PROTO_IP } | ip_tos TOS_IP_MASQUE | ip_ttl TTL_IP_MASQUE | { dst_ip | src_ip } PREFIXE | { dst_port | src_port } { NOMBRE_MASQUE | port_min-port_max } | tcp_flags DRAPEAUX_TCP_MASQUE | type TYPE_MASQUE | code CODE_MASQUE | { arp_tip | arp_sip } PREFIXE_IPV4 | arp_op { request | reply | OP } | { arp_tha | arp_sha } ADRESSE_LL_MASQUE | enc_key_id ID-CLE | { enc_dst_ip | enc_src_ip } { adresse_ipv4 | adresse_ipv6 } | enc_dst_port numero_port | enc_tos TOS | enc_ttl TTL | { geneve_opts | vxlan_opts | erspan_opts | gtp_opts | pfcp_opts } OPTIONS | ip_flags DRAPEAUX_IP | l2_miss L2_MANQUE | cfm OPTIONS_CFM | enc_flags LISTE_DRAPEAUX_ENC }

LISTE_LSE := [ LISTE_LSE ] LSE

LSE := lse depth PROFONDEUR { label LABEL | tc TC | bos BOS | ttl TTL }

CFM := cfm mdl NIVEAU | op CODE_OP

LISTE_DRAPEAUX_ENC := [ LISTE_DRAPEAUX_ENC/ ] DRAPEAU_ENC

DRAPEAU_ENC := { [no]tuncsum | [no]tundf | [no]tunoam | [no]tuncrit }

DESCRIPTION

Le filtre flower fait correspondre les flux à l'ensemble des clés spécifiées et leur assigne un identifiant de classe choisi arbitrairement. De plus (ou alternativement), une action du framework d'actions génériques peut être appelée.

OPTIONS

action SPEC_ACTION
Applique une action du framework d'actions génériques sur les paquets correspondants.
classid ID_CLASSE
Spécifie une classe à laquelle passer les paquets correspondants. ID_CLASSE est sous la forme X:Y, où X et Y sont interprétés comme des nombres en format hexadécimal.
hw_tc ID_TC
Spécifie une classe de trafic matérielle à laquelle passer les paquets correspondants. ID_TC est dans la plage 0 à 15.
indev nom_interface
Correspond à l'interface entrante par son nom. Ceci est évidemment pertinent uniquement pour les flux routés. nom_interface est le nom d'une interface qui doit exister au moment de l'invocation de tc.
verbose
Active la journalisation détaillée, y compris les erreurs de déchargement lorsque le drapeau skip_sw n'est pas utilisé.
skip_sw
Ne traite pas le filtre par logiciel. Si le matériel n'a pas de support de déchargement pour ce filtre, ou si le déchargement TC n'est pas activé pour l'interface, l'opération échouera.
skip_hw
Ne traite pas le filtre par matériel.
dst_mac ADRESSE_LL_MASQUE
src_mac ADRESSE_LL_MASQUE
Correspond à l'adresse MAC source ou destination. Un masque peut être facultativement fourni pour limiter les bits de l'adresse qui sont correspondants. Un masque est fourni en ajoutant une barre oblique après l'adresse, suivie du masque. Il peut être fourni au format LLADDR, auquel cas il s'agit d'un masque bit à bit, ou comme nombre de bits de poids fort à correspondre. Si le masque est absent, une correspondance sur tous les bits est supposée.
num_of_vlans NB
Correspond au nombre de tags VLAN dans le paquet. NB peut être 0 ou un petit entier positif. Typiquement dans la plage 0-4.
vlan_id VID
Correspond à l'identifiant du tag VLAN. VID est une valeur de 12 bits non signée en format décimal.
vlan_prio PRIORITE
Correspond à la priorité du tag VLAN. PRIORITE est une valeur de 3 bits non signée en format décimal.
vlan_ethtype TYPE_ETH_VLAN
Correspond au protocole de couche trois. TYPE_ETH_VLAN peut être ipv4, ipv6 ou une valeur de 16 bits non signée en format hexadécimal. Pour correspondre à un paquet QinQ, il doit s'agir de 802.1Q ou 802.1AD.
cvlan_id VID
Correspond à l'identifiant du tag VLAN interne QinQ. VID est une valeur de 12 bits non signée en format décimal.
cvlan_prio PRIORITE
Correspond à la priorité du tag VLAN interne QinQ. PRIORITE est une valeur de 3 bits non signée en format décimal.
cvlan_ethtype TYPE_ETH_VLAN
Correspond au protocole de couche trois QinQ. TYPE_ETH_VLAN peut être ipv4, ipv6 ou une valeur de 16 bits non signée en format hexadécimal.
pppoe_sid PSID
Correspond à l'identifiant de session PPPoE. PSID est une valeur de 16 bits non signée en format décimal.
ppp_proto PROTO_PPP
Correspond au protocole de couche trois PPP. PROTO_PPP peut être ip, ipv6, mpls_uc, mpls_mc ou une valeur de 16 bits non signée en format hexadécimal.
mpls LISTE_LSE
Correspond à la pile d'étiquettes MPLS. LISTE_LSE est une liste d'entrées de pile d'étiquettes, chacune introduite par le mot-clé lse. Cette option ne peut pas être utilisée conjointement avec les options autonomes mpls_label, mpls_tc, mpls_bos et mpls_ttl.
lse OPTIONS_LSE
Correspond à une entrée de pile d'étiquettes MPLS. OPTIONS_LSE est une liste d'options décrivant les propriétés de l'LSE à faire correspondre.
depth PROFONDEUR
La profondeur de l'entrée de pile d'étiquettes à considérer. La profondeur commence à 1 (l'entrée de pile d'étiquettes la plus externe). La profondeur maximale utilisable peut être limitée par le noyau. Cette option est obligatoire. PROFONDEUR est une valeur de 8 bits non signée en format décimal.
label LABEL
Correspond au champ Étiquette MPLS à la profondeur spécifiée. LABEL est une valeur de 20 bits non signée en format décimal.
tc TC
Correspond au champ Classe de Trafic MPLS à la profondeur spécifiée. TC est une valeur de 3 bits non signée en format décimal.
bos BOS
Correspond au champ Fond de Pile (Bottom Of Stack) MPLS à la profondeur spécifiée. BOS est une valeur de 1 bit en format décimal.
ttl TTL
Correspond au champ Durée de Vie (Time To Live) MPLS à la profondeur spécifiée. TTL est une valeur de 8 bits non signée en format décimal.
mpls_label LABEL
Correspond à l'étiquette MPLS. LABEL est une valeur de 20 bits non signée en format décimal.
mpls_tc TC
Correspond au champ classe de trafic MPLS. TC est une valeur de 3 bits non signée en format décimal.
mpls_bos BOS
Correspond au champ Fond de Pile (Bottom Of Stack) MPLS. BOS est une valeur de 1 bit en format décimal.
mpls_ttl TTL
Correspond au champ Durée de Vie (Time To Live) MPLS. TTL est une valeur de 8 bits non signée en format décimal.
l2tpv3_sid LSID
Correspond à l'identifiant de session L2TPv3. LSID est une valeur de 32 bits non signée en format décimal.
ip_proto PROTO_IP
Correspond au protocole de couche 4 IP. PROTO_IP peut être tcp, udp, sctp, icmp, icmpv6, l2tp ou une valeur de 8 bits non signée en format décimal.
ip_tos TOS_IP_MASQUE
Correspond au champ Type of Service (ToS) IP. Il peut être spécifié avec un masque. Le masque est facultatif et il est fourni en ajoutant une barre oblique après la valeur ToS. Le masque est spécifié comme un nombre de bits de poids fort à prendre en compte. Le champ ToS est un champ de 8 bits, mais seuls les 6 premiers bits (DSCP) sont pris en compte par défaut. Pour correspondre au champ ECN (bits 7 et 8), il faut le spécifier explicitement.
ip_ttl TTL_IP_MASQUE
Correspond au champ Time To Live (TTL) IP. Il peut être spécifié avec un masque.
dst_ip PREFIXE
src_ip PREFIXE
Correspond à l'adresse IP source ou destination. PREFIXE est une adresse IP dans le format habituel, éventuellement suivie d'une barre oblique et d'un masque de sous-réseau CIDR (par exemple, 192.168.0.0/24).
dst_port NOMBRE_MASQUE
src_port NOMBRE_MASQUE
Correspond au port source ou destination TCP/UDP. NOMBRE_MASQUE est soit un nombre (port), soit un masque hexadécimal, soit une plage de ports (par exemple, 1000-2000). Un masque peut être spécifié en ajoutant une barre oblique après le nombre ou la plage, suivi du masque. Le masque est un nombre de 16 bits. Si le masque est absent, une correspondance sur tous les bits est supposée.
tcp_flags DRAPEAUX_TCP_MASQUE
Correspond aux drapeaux TCP. DRAPEAUX_TCP_MASQUE est une liste de drapeaux TCP séparés par des virgules (par exemple, SYN,ACK). Les drapeaux peuvent être préfixés par no pour inverser la correspondance. Un masque peut être spécifié en ajoutant une barre oblique après la liste des drapeaux, suivi du masque. Le masque est un nombre de 8 bits.
type TYPE_MASQUE
Correspond au type ICMP. TYPE_MASQUE est un nombre.
code CODE_MASQUE
Correspond au code ICMP. CODE_MASQUE est un nombre.
arp_tip PREFIXE_IPV4
arp_sip PREFIXE_IPV4
Correspond à l'adresse IP cible (TIP) ou source (SIP) ARP. PREFIXE_IPV4 est une adresse IPv4 dans le format habituel, éventuellement suivie d'une barre oblique et d'un masque de sous-réseau CIDR.
arp_op OP
Correspond à l'opération ARP. OP peut être request ou reply.
arp_tha ADRESSE_LL_MASQUE
arp_sha ADRESSE_LL_MASQUE
Correspond à l'adresse MAC cible (THA) ou source (SHA) ARP. ADRESSE_LL_MASQUE est une adresse MAC dans le format habituel, éventuellement suivie d'une barre oblique et d'un masque.
enc_key_id ID-CLE
Correspond à la clé d'identification du paquet encapsulé.
enc_dst_ip adresse_ipv4 | adresse_ipv6
enc_src_ip adresse_ipv4 | adresse_ipv6
Correspond à l'adresse IP destination ou source du paquet encapsulé.
enc_dst_port numero_port
Correspond au port destination du paquet encapsulé.
enc_tos TOS
Correspond au champ Type of Service (ToS) du paquet encapsulé.
enc_ttl TTL
Correspond au champ Time To Live (TTL) du paquet encapsulé.
geneve_opts OPTIONS
Correspond aux options GENEVE. OPTIONS est une liste de paires clé-valeur séparées par des virgules.
vxlan_opts OPTIONS
Correspond aux options VXLAN. OPTIONS est une liste de paires clé-valeur séparées par des virgules.
erspan_opts OPTIONS
Correspond aux options ERSPAN. OPTIONS est une liste de paires clé-valeur séparées par des virgules.
gtp_opts OPTIONS
Correspond aux options GTP. OPTIONS est une liste de paires clé-valeur séparées par des virgules.
pfcp_opts OPTIONS
Correspond aux options PFCP. OPTIONS est une liste de paires clé-valeur séparées par des virgules.
ip_flags DRAPEAUX_IP
Correspond aux drapeaux IP. DRAPEAUX_IP est une liste de drapeaux séparés par des virgules (par exemple, DF,MF). Les drapeaux peuvent être préfixés par no pour inverser la correspondance.
l2_miss L2_MANQUE
Active la correspondance des paquets sans entrée de table de correspondance de couche 2.
cfm OPTIONS_CFM
Correspond aux options CFM (Connectivity Fault Management). OPTIONS_CFM est une liste d'options séparées par des virgules.
cfm mdl NIVEAU
Correspond au niveau de niveau de domaine MD (Maintenance Domain). NIVEAU est un entier de 0 à 7.
op CODE_OP
Correspond au code d'opération CFM. CODE_OP est un entier.
enc_flags LISTE_DRAPEAUX_ENC
Correspond aux drapeaux d'encapsulation. LISTE_DRAPEAUX_ENC est une liste de drapeaux séparés par des barres obliques.
tuncsum
Le paquet encapsulé a une somme de contrôle valide.
tundf
Le paquet encapsulé a un champ "Don't Fragment" défini.
tunoam
Le paquet encapsulé a le bit "Options and More" défini.
tuncrit
Le paquet encapsulé a le bit "Critical" défini.

Les options [no]tuncsum, [no]tundf, [no]tunoam et [no]tuncrit correspondent aux drapeaux d'encapsulation IPv4.

EXEMPLES

Pour faire correspondre tous les paquets UDP provenant de 192.168.0.1 sur le port 1234 et les diriger vers la classe 1:10:


# tc filter add dev eth0 proto udp parent 1:0 prio 1 \ flower src_ip 192.168.0.1/32 dst_port 1234 \ classid 1:10

Pour faire correspondre tous les paquets TCP SYN provenant de l'interface eth1 et les envoyer vers l'action drop:


# tc filter add dev eth1 protocol ip parent ffff: prio 1 \ flower tcp_flags SYN/SYN \ action drop

Pour faire correspondre tous les paquets dont l'adresse MAC de destination est 00:11:22:33:44:55 et le champ ToS est 0x02:


# tc filter add dev eth0 parent ffff: prio 1 \ flower dst_mac 00:11:22:33:44:55/ff:ff:ff:ff:ff:ff ip_tos 0x02/0xff \ classid 1:1

Pour faire correspondre les paquets VXLAN avec une VNI de 1000:


# tc filter add dev eth0 parent ffff: prio 1 \ flower vxlan_opts vni=1000 \ classid 1:1

Pour faire correspondre les paquets MPLS avec une étiquette de 100 et le bit BOS à 1:


# tc filter add dev eth0 parent ffff: prio 1 \ flower mpls_label 100 mpls_bos 1 \ classid 1:1

Pour faire correspondre les paquets MPLS à la première entrée de pile (profondeur 1) avec une étiquette de 100:


# tc filter add dev eth0 parent ffff: prio 1 \ flower mpls lse depth 1 label 100 \ classid 1:1

dst_port { MASKED_NUMBER | MIN_VALUE-MAX_VALUE }
src_port { MASKED_NUMBER | MIN_VALUE-MAX_VALUE }
Correspond au numéro de port source ou destination du protocole de couche 4, avec un masque optionnel. Alternativement, les valeurs minimale et maximale peuvent être spécifiées pour correspondre à une plage de numéros de port source ou destination du protocole de couche 4. Uniquement disponible pour les valeurs ip_proto udp, tcp et sctp qui doivent être spécifiées au préalable.
tcp_flags MASKED_TCP_FLAGS
Correspond aux flags TCP représentés par un champ de bits de 12 bits au format hexadécimal. Un masque peut être fourni optionnellement pour limiter les bits qui sont comparés. Un masque est fourni en ajoutant une barre oblique après la valeur, suivie du masque. Si le masque est omis, une comparaison sur tous les bits est supposée.

Un masque est fourni en ajoutant une barre oblique après l'adresse, suivie du masque. Il peut être fourni sous forme d'une valeur hexadécimale non signée de 8 bits représentant un masque bit à bit. Si le masque est omis, une comparaison sur tous les bits est supposée. Uniquement disponible pour les valeurs ip_proto icmp et icmpv6 qui doivent être spécifiées au préalable.
arp_tip IPV4_PREFIX
arp_sip IPV4_PREFIX
Correspond à l'adresse IP source ou cible ARP ou RARP. IPV4_PREFIX doit être une adresse IPv4 valide éventuellement suivie d'une barre oblique et de la longueur du préfixe. Si le préfixe est omis, tc suppose une correspondance d'hôte sur toute la longueur.
arp_op ARP_OP
Correspond à l'opération ARP ou RARP. ARP_OP peut être request, reply ou une valeur entière 0, 1 ou 2. Un masque peut être fourni optionnellement pour limiter les bits de l'opération qui sont comparés. Un masque est fourni en ajoutant une barre oblique après l'adresse, suivie du masque. Il peut être fourni sous forme d'une valeur hexadécimale non signée de 8 bits représentant un masque bit à bit. Si le masque est omis, une comparaison sur tous les bits est supposée.

arp_tha MASKED_LLADDR
Correspond à l'adresse MAC source ou cible ARP ou RARP. Un masque peut être fourni optionnellement pour limiter les bits de l'adresse qui sont comparés. Un masque est fourni en ajoutant une barre oblique après l'adresse, suivie du masque. Il peut être fourni au format LLADDR, auquel cas il s'agit d'un masque bit à bit, ou par le nombre de bits de poids fort à comparer. Si le masque est omis, une comparaison sur tous les bits est supposée.
enc_key_id NUMBER
enc_dst_ip PREFIX
enc_src_ip PREFIX
enc_dst_port NUMBER
enc_tos NUMBER
enc_ttl NUMBER
ct_state CT_STATE
ct_zone CT_MASKED_ZONE
ct_mark CT_MASKED_MARK
ct_label CT_MASKED_LABEL
Correspond aux informations de suivi de connexion
CT_STATE
Correspond à l'état de la connexion, et peut être une combinaison de [{+|-}flag] flags, où flag peut être l'un des suivants :
trk - Connexion suivie.
new - Nouvelle connexion.
est - Connexion établie.
rpl - Le paquet est dans la direction de réponse, ce qui signifie qu'il est dans la direction opposée au paquet qui a initié la connexion.
inv - L'état est invalide. Le paquet n'a pas pu être associé à une connexion.
rel - Le paquet est lié à une connexion existante.
Exemple : +trk+est
CT_MASKED_ZONE
Correspond à la zone de connexion, et peut être masquée.
CT_MASKED_MARK
Correspondance de 32 bits sur le marqueur de connexion, et peut être masquée.
CT_MASKED_LABEL
Correspondance de 128 bits sur le label de connexion, et peut être masquée.
geneve_opts OPTIONS
vxlan_opts OPTIONS
erspan_opts OPTIONS
gtp_opts OPTIONS
pfcp_opts OPTIONS
Correspond aux métadonnées du tunnel IP. L'ID de clé NUMBER est un ID de clé de tunnel de 32 bits (par exemple, VNI pour un tunnel VXLAN). PREFIX doit être une adresse IPv4 ou IPv6 valide éventuellement suivie d'une barre oblique et de la longueur du préfixe. Si le préfixe est omis, tc suppose une correspondance d'hôte sur toute la longueur. Le port de destination NUMBER est un port UDP de destination de 16 bits. Tos NUMBER est une valeur tos (dscp+ecn) de 8 bits, ttl NUMBER est une valeur time-to-live de 8 bits. geneve_opts OPTIONS doit être une liste valide d'options séparées par des virgules, où chaque option se compose d'une clé éventuellement suivie d'une barre oblique et du masque correspondant. Si le masque est omis, tc suppose une correspondance sur toute la longueur. Les options peuvent être décrites sous la forme CLASS:TYPE:DATA/CLASS_MASK:TYPE_MASK:DATA_MASK, où CLASS est représenté par une valeur hexadécimale de 16 bits, TYPE par une valeur hexadécimale de 8 bits et DATA par une valeur hexadécimale de longueur variable. vxlan_opts OPTIONS ne supporte pas plusieurs options, et il se compose d'une clé suivie d'une barre oblique et du masque correspondant. Si le masque est omis, tc suppose une correspondance sur toute la longueur. L'option peut être décrite sous la forme GBP/GBP_MASK, où GBP est représenté par un nombre de 32 bits. erspan_opts OPTIONS ne supporte pas plusieurs options, et il se compose d'une clé suivie d'une barre oblique et du masque correspondant. Si le masque est omis, tc suppose une correspondance sur toute la longueur. L'option peut être décrite sous la forme VERSION:INDEX:DIR:HWID/VERSION:INDEX_MASK:DIR_MASK:HWID_MASK, où VERSION est représenté par un nombre de 8 bits, INDEX par un nombre de 32 bits, DIR et HWID par un nombre de 8 bits. Plusieurs options ne sont pas supportées. Notez que INDEX/INDEX_MASK est utilisé lorsque VERSION est 1, et DIR/DIR_MASK et HWID/HWID_MASK sont utilisés lorsque VERSION est 2. gtp_opts OPTIONS ne supporte pas plusieurs options, et il se compose d'une clé suivie d'une barre oblique et du masque correspondant. Si le masque est omis, tc suppose une correspondance complète. L'option peut être décrite sous la forme PDU_TYPE:QFI/PDU_TYPE_MASK:QFI_MASK où PDU_TYPE et QFI sont représentés comme des valeurs hexadécimales de 8 bits. pfcp_opts OPTIONS ne prend pas en charge plusieurs options. Il se compose d'une clé suivie d'une barre oblique et du masque correspondant. Si le masque est manquant, tc suppose une correspondance complète. L'option peut être décrite sous la forme TYPE:SEID/TYPE_MASK:SEID_MASK où TYPE est représenté par un nombre de 8 bits, SEID est représenté par 64 bits. TYPE et SEID sont tous deux fournis en hexadécimal.
ip_flags IP_FLAGS
IP_FLAGS peut être frag, nofrag, firstfrag ou nofirstfrag où frag et nofrag peuvent être utilisés pour correspondre aux paquets fragmentés ou non, respectivement. firstfrag et nofirstfrag peuvent être utilisés pour distinguer davantage les paquets fragmentés. firstfrag peut être utilisé pour indiquer le premier paquet fragmenté. nofirstfrag peut être utilisé pour indiquer les paquets fragmentés suivants ou les paquets non fragmentés.
l2_miss L2_MISS
Correspond à une erreur de couche 2 dans le FDB / MDB du pilote de pont. L2_MISS peut être 0 ou 1. Lorsque 1, correspond aux paquets qui ont rencontré une erreur de couche 2. Lorsque 0, correspond aux paquets qui ont été transférés à l'aide d'une entrée FDB / MDB. Notez que les paquets de diffusion ne rencontrent pas d'erreur car aucune recherche n'est effectuée pour eux.
cfm CFM_OPTIONS
Correspond aux champs CFM (Connectivity Fault Management). CFM_OPTIONS est une liste d'options décrivant les propriétés des champs d'informations CFM à faire correspondre.
mdl LEVEL
Correspond au champ Maintenance Domain (MD) level. LEVEL est une valeur non signée de 3 bits au format décimal.
op OPCODE
Correspond au champ CFM opcode. OPCODE est une valeur non signée de 8 bits au format décimal.
enc_flags ENCFLAG-LIST
Correspond aux drapeaux de contrôle de tunnel. ENCFLAG-LIST est une liste des drapeaux de contrôle de tunnel suivants : [no]tuncsum, [no]tundf, [no]tunoam, [no]tuncrit, chacun séparé par '/'.

NOTES

Comme indiqué ci-dessus lorsque cela est applicable, les correspondances d'une certaine couche dépendent implicitement des correspondances de la couche inférieure suivante. Précisément, les correspondances de couche un et deux (indev, dst_mac, src_mac et enc_flags) n'ont pas de dépendance, les correspondances MPLS et de couche trois (mpls, mpls_label, mpls_tc, mpls_bos, mpls_ttl, ip_proto, dst_ip, src_ip, arp_tip, arp_sip, arp_op, arp_tha, arp_sha et ip_flags) dépendent de l'option protocol du filtre tc, les correspondances de port de couche quatre (dst_port et src_port) dépendent de ip_proto étant défini sur tcp, udp ou sctp, et enfin les correspondances ICMP (code et type) dépendent de ip_proto étant défini sur icmp ou icmpv6.

Il ne peut y avoir qu'un seul masque par prio. Si l'utilisateur a besoin de spécifier un masque différent, il doit utiliser un prio différent.
