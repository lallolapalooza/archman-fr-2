NOM

ETF - Earliest TxTime First (ETF) Qdisc

SYNOPSIS

tc qdisc ... dev dev parent classid [ handle major: ] etf clockid clockid [ delta delta_nsecs ] [ deadline_mode ] [ offload ]

DESCRIPTION

Le qdisc ETF (Earliest TxTime First) permet aux applications de contrôler l'instant où un paquet doit être retiré de la couche de contrôle de trafic vers le périphérique réseau. Si offload est configuré et pris en charge par la carte d'interface réseau, il contrôlera également le moment où les paquets quittent le contrôleur réseau.

ETF atteint cela en mettant en mémoire tampon les paquets jusqu'à un moment configurable avant leur temps de transmission (c'est-à-dire txtime, ou deadline), ce qui peut être configuré via l'option delta.

Le qdisc utilise un arbre rb (red-black) en interne afin que les paquets soient toujours « ordonnés » par leur txtime et seront retirés en suivant le principe (prochain) plus petit txtime en premier.

Il s'appuie sur l'option de socket SO_TXTIME et le message CMSG SCM_TXTIME dans le champ de chaque paquet pour configurer le comportement des sockets dépendants du temps : le clockid à utiliser comme référence, si le mode attendu de txtime pour ce socket est le mode deadline ou strict, et si les chutes de paquets doivent être signalées dans la file d'erreurs du socket. Voir socket(7) pour plus d'informations.

Le qdisc etf supprimera tout paquet dont le txtime est dans le passé, ou si un paquet expire pendant l'attente d'être retiré.

Ce discipline de mise en file d'attente est destinée à être utilisée par les applications TSN (Time Sensitive Networking), et elle expose une fonctionnalité de façonnage du trafic qui est couramment documentée comme « Launch Time » ou « Time-Based Scheduling » par les fournisseurs et la documentation des contrôleurs d'interface réseau.

ETF est destiné à être installé sous un autre qdisc qui mappe les flux de paquets aux classes de trafic, un exemple est mqprio(8).

PARAMÈTRES

clockid

Spécifie l'horloge à utiliser par le minuteur interne du qdisc pour mesurer le temps et planifier les événements. Le qdisc s'attend à ce que les paquets qui le traversent utilisent ce même clockid comme référence de leurs horodatages txtime. Il supprimera les paquets provenant de sockets qui ne sont pas conformes à cela.

Pour plus d'informations sur le temps et les horloges sous Linux, veuillez vous référer à time(7) et clock_gettime(3).

delta

Après avoir mis en file d'attente ou retiré un paquet, le qdisc planifiera sa prochaine heure de réveil pour le prochain txtime moins cette valeur delta. Cela signifie que delta peut être utilisé comme un facteur de compensation pour la latence du planificateur d'un système. Cette valeur doit être spécifiée en nanosecondes. La valeur par défaut est de 0 nanosecondes.
deadline_mode

Lorsque deadline_mode est défini, le qdisc traitera txtime avec une sémantique différente, passant d'un temps de transmission « strict » à une échéance. En pratique, cela signifie que lors du flux de retrait, etf(8) définira le txtime du paquet en cours de retrait sur « maintenant ». Par défaut, cette option est désactivée.
offload

Lorsque offload est défini, etf(8) tentera de configurer l'interface réseau pour activer l'arbitrage de transmission basé sur le temps dans le contrôleur. Cette fonctionnalité est couramment appelée « Launch Time » ou « Time-Based Scheduling » par la documentation des contrôleurs d'interface réseau. Par défaut, cette option est désactivée.
skip_sock_check

etf(8) supprime actuellement tout paquet qui n'a pas de socket associé ou si le socket n'a pas l'option de socket SO_TXTIME définie. Cependant, cela ne fonctionnera pas si l'heure de lancement est définie par une autre entité dans le noyau (par exemple, un autre Qdisc). Définir skip_sock_check ignorera la vérification d'un socket associé au paquet.

EXEMPLES

ETF est utilisé pour faire respecter une Qualité de Service. Il contrôle quand chaque paquet doit être retiré et transmis, et peut être utilisé pour limiter le débit de données d'une classe de trafic. Pour séparer les paquets en classes de trafic, l'utilisateur peut choisir mqprio(8), et le configurer comme suit :

# tc qdisc add dev eth0 handle 100: parent root mqprio num_tc 3 \
	map 2 2 1 0 2 2 2 2 2 2 2 2 2 2 2 2 \
	queues 1@0 1@1 2@2 \
	hw 0

Pour remplacer la discipline de mise en file d'attente actuelle par ETF dans la classe de trafic numéro 0, exécutez :

# tc qdisc replace dev eth0 parent 100:1 etf \
	clockid CLOCK_TAI delta 300000 offload

Avec les options ci-dessus, etf sera configuré pour utiliser CLOCK_TAI comme son clockid_t, planifiera les paquets 300 µs avant leur txtime, et activera la fonctionnalité correspondante sur la carte d'interface réseau. Le mode deadline ne sera pas configuré pour ce mode.
