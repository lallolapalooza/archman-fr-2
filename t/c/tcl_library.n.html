tclvars(n) Commandes intégrées Tcl tclvars(n)

NOM

argc, argv, argv0, auto_path, env, errorCode, errorInfo, tcl_interactive, tcl_library, tcl_nonwordchars, tcl_patchLevel, tcl_pkgPath, tcl_platform, tcl_precision, tcl_rcFileName, tcl_traceCompile, tcl_traceExec, tcl_wordchars, tcl_version - Variables utilisées par Tcl

DESCRIPTION

Les variables globales suivantes sont créées et gérées automatiquement par la bibliothèque Tcl. Sauf indication contraire ci-dessous, ces variables doivent normalement être considérées comme étant en lecture seule par le code spécifique à l'application et par les utilisateurs.

auto_path
Si elle est définie, elle doit contenir une liste Tcl valide indiquant les répertoires à rechercher lors des opérations de chargement automatique (y compris les fichiers d'index de paquets lors de l'utilisation du gestionnaire par défaut package unknown). Cette variable est initialisée lors du démarrage pour contenir, dans l'ordre : les répertoires listés dans la variable d'environnement TCLLIBPATH, le répertoire nommé par la variable globale tcl_library, le répertoire parent de tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, les répertoires listés dans la variable tcl_pkgPath. Des emplacements supplémentaires pour rechercher des fichiers et des index de paquets devraient normalement être ajoutés à cette variable en utilisant lappend.

Des variables supplémentaires relatives à la gestion des paquets existent. Plus de détails sont listés dans la section VARIABLES de la page man library.

env
Cette variable est maintenue par Tcl en tant que tableau dont les éléments sont les variables d'environnement du processus. La lecture d'un élément renverra la valeur de la variable d'environnement correspondante. La définition d'un élément du tableau modifiera la variable d'environnement correspondante ou en créera une nouvelle si elle n'existe pas déjà. La suppression d'un élément de env supprimera la variable d'environnement correspondante. Les modifications apportées au tableau env affecteront l'environnement transmis aux enfants par des commandes telles que exec. Si l'intégralité du tableau env est supprimée, Tcl cessera de surveiller les accès à env et ne mettra pas à jour les variables d'environnement.

Sous Windows, les variables d'environnement PATH et COMSPEC, quelle que soit leur casse, sont automatiquement converties en majuscules. Par exemple, la variable PATH peut être exportée par le système d'exploitation sous forme de “path”, “Path”, “PaTh”, etc., obligeant un code Tcl autrement simple à supporter de nombreux cas spéciaux. Toutes les autres variables d'environnement héritées par Tcl restent inchangées. Définir une variable du tableau env sur une chaîne vide équivaut à la supprimer, car c'est le comportement du système d'exploitation Windows sous-jacent. Il convient de noter que s'appuyer sur une variable d'environnement existante et vide ne fonctionnera pas sous Windows et est déconseillé pour une utilisation multiplateforme.

Les éléments suivants de env sont spéciaux pour Tcl :

env(HOME)
Cette variable d'environnement, si elle est définie, indique l'emplacement du répertoire considéré comme le répertoire personnel de l'utilisateur actuel, et vers lequel un appel à cd sans argument ou avec seulement “~” comme argument se déplacera. La plupart des plateformes la définissent correctement par défaut ; elle n'a normalement pas besoin d'être définie par le code utilisateur.
env(TCL_LIBRARY)
Si elle est définie, elle spécifie l'emplacement du répertoire contenant les scripts de bibliothèque (la valeur de cette variable sera assignée à la variable tcl_library et donc renvoyée par la commande info library). Si cette variable n'est pas définie, une valeur par défaut est utilisée.

Notez que cette variable d'environnement ne devrait *normalement pas* être définie.

env(TCLLIBPATH)
Si elle est définie, elle doit contenir une liste Tcl valide indiquant les répertoires à rechercher lors des opérations de chargement automatique. Les répertoires doivent être spécifiés au format Tcl, en utilisant “/” comme séparateur de chemin, quelle que soit la plateforme. Cette variable est uniquement utilisée lors de l'initialisation de la variable auto_path.
env(TCL_TZ), env(TZ)
Ces variables spécifient le fuseau horaire par défaut utilisé pour analyser et formater les heures et les dates dans la commande clock. Sur de nombreuses plateformes, la variable d'environnement TZ est configurée par le système d'exploitation.
env(LC_ALL), env(LC_MESSAGES), env(LANG)
Ces variables d'environnement sont utilisées par le paquet msgcat pour déterminer dans quelle locale formater les messages.
env(TCL_INTERP_DEBUG_FRAME)
Si elle existe, elle a le même effet que l'exécution de interp debug {} -frame 1 comme toute première commande de chaque nouvel interpréteur Tcl.
errorCode
Cette variable contient la valeur de l'option de retour -errorcode définie par la dernière erreur survenue dans cet interpréteur. Cette valeur de liste représente des informations supplémentaires sur l'erreur dans un format facile à traiter par les programmes. Le premier élément de la liste identifie une classe générale d'erreurs et détermine le format du reste de la liste. Les formats suivants pour les options de retour -errorcode sont utilisés par le noyau Tcl ; les applications individuelles peuvent définir des formats supplémentaires.
ARITH code msg
Ce format est utilisé lorsqu'une erreur arithmétique survient (par exemple, une tentative de division par zéro dans la commande expr). Code identifie l'erreur précise et msg fournit une description lisible par l'homme de l'erreur. Code sera soit DIVZERO (pour une tentative de division par zéro), DOMAIN (si un argument est en dehors du domaine d'une fonction, tel que acos(-3)), IOVERFLOW (pour un dépassement de capacité entier), OVERFLOW (pour un dépassement de capacité en virgule flottante), ou UNKNOWN (si la cause de l'erreur ne peut être déterminée).

La détection de ces erreurs dépend en partie du matériel sous-jacent et des bibliothèques système.

CHILDKILLED pid sigName msg
Ce format est utilisé lorsqu'un processus enfant a été tué en raison d'un signal. L'élément pid sera l'identifiant du processus (en décimal). L'élément sigName sera le nom symbolique du signal qui a provoqué la terminaison du processus ; ce sera l'un des noms du fichier d'en-tête signal.h, tel que SIGPIPE. L'élément msg sera un court message lisible par l'homme décrivant le signal, tel que “write on pipe with no readers” pour SIGPIPE.
CHILDSTATUS pid code
Ce format est utilisé lorsqu'un processus enfant s'est terminé avec un code de sortie non nul. L'élément pid sera l'identifiant du processus (en décimal) et l'élément code sera le code de sortie renvoyé par le processus (également en décimal).
CHILDSUSP pid sigName msg
Ce format est utilisé lorsqu'un processus enfant a été suspendu en raison d'un signal. L'élément pid sera l'identifiant du processus, en décimal. L'élément sigName sera le nom symbolique du signal qui a provoqué la suspension du processus ; ce sera l'un des noms du fichier d'en-tête signal.h, tel que SIGTTIN. L'élément msg sera un court message lisible par l'homme décrivant le signal, tel que “background tty read” pour SIGTTIN.
NONE
Ce format est utilisé pour les erreurs pour lesquelles aucune information supplémentaire n'est disponible au-delà du message renvoyé avec l'erreur. Dans ces cas, l'option de retour -errorcode sera une liste contenant un seul élément dont le contenu est NONE.
POSIX errName msg
Si le premier élément est POSIX, alors l'erreur s'est produite lors d'un appel noyau POSIX. L'élément errName contiendra le nom symbolique de l'erreur survenue, tel que ENOENT ; ce sera l'une des valeurs définies dans le fichier d'en-tête errno.h. L'élément msg
sera un message lisible par l'homme correspondant à errName, tel que "aucun fichier ou répertoire de ce type" pour le cas ENOENT.
TCL ...
Indique une sorte de problème généré en relation avec Tcl lui-même, par exemple un échec de recherche d'un canal ou d'une variable.

Pour définir l'option de retour -errorcode, les applications doivent utiliser des procédures de bibliothèque telles que Tcl_SetObjErrorCode, Tcl_SetReturnOptions et Tcl_PosixError, ou elles peuvent invoquer l'option -errorcode de la commande return. Si aucune de ces méthodes pour définir le code d'erreur n'a été utilisée, l'interpréteur Tcl réinitialisera la variable à NONE après la prochaine erreur.

errorInfo
Cette variable contient la valeur de l'option de retour -errorinfo définie par la dernière erreur qui s'est produite dans cet interpréteur. Cette valeur de chaîne contiendra une ou plusieurs lignes identifiant les commandes et procédures Tcl qui étaient en cours d'exécution lorsque la dernière erreur s'est produite. Son contenu prend la forme d'une trace de pile montrant les diverses commandes Tcl imbriquées qui avaient été invoquées au moment de l'erreur.
tcl_library
Cette variable contient le nom d'un répertoire contenant la bibliothèque système de scripts Tcl, tels que ceux utilisés pour le chargement automatique. La valeur de cette variable est retournée par la commande info library. Voir l'entrée de manuel library pour les détails des installations fournies par la bibliothèque de scripts Tcl. Normalement, chaque application ou paquet aura sa propre bibliothèque de scripts spécifique à l'application en plus de la bibliothèque de scripts Tcl ; chaque application doit définir une variable globale avec un nom tel que $app_library (où app est le nom de l'application) pour contenir le nom de fichier réseau du répertoire de la bibliothèque de cette application. La valeur initiale de tcl_library est définie lors de la création d'un interpréteur en recherchant plusieurs répertoires différents jusqu'à ce qu'un soit trouvé qui contient un script de démarrage Tcl approprié. Si la variable d'environnement TCL_LIBRARY existe, alors le répertoire qu'elle nomme est vérifié en premier. Si TCL_LIBRARY n'est pas définie ou ne fait pas référence à un répertoire approprié, alors Tcl vérifie plusieurs autres répertoires en se basant sur un emplacement par défaut compilé, l'emplacement du binaire contenant l'application, et le répertoire de travail courant.
tcl_patchLevel
Lorsqu'un interpréteur est créé, Tcl initialise cette variable pour contenir une chaîne donnant le niveau de correctif actuel pour Tcl, tel que 8.4.16 pour Tcl 8.4 avec les seize premiers correctifs officiels, ou 8.5b3 pour la troisième version bêta de Tcl 8.5. La valeur de cette variable est retournée par la commande info patchlevel.
tcl_pkgPath
Cette variable contient une liste de répertoires indiquant où les paquets sont normalement installés. Elle n'est pas utilisée sous Windows. Elle contient typiquement une ou deux entrées ; si elle contient deux entrées, la première est normalement un répertoire pour les paquets dépendant de la plateforme (par exemple, les binaires de bibliothèques partagées) et la seconde est normalement un répertoire pour les paquets indépendants de la plateforme (par exemple, les fichiers de script). Typiquement, un paquet est installé en tant que sous-répertoire d'une des entrées de la variable tcl_pkgPath. Les répertoires de la variable tcl_pkgPath sont inclus par défaut dans la variable auto_path, donc ils et leurs sous-répertoires immédiats sont automatiquement recherchés pour les paquets lors des commandes package require. Remarque : tcl_pkgPath n'est pas destinée à être modifiée par l'application. Sa valeur est ajoutée à auto_path au démarrage ; les modifications apportées à tcl_pkgPath ne sont pas reflétées dans auto_path. Si vous souhaitez que Tcl recherche des répertoires supplémentaires pour les paquets, vous devez ajouter les noms de ces répertoires à auto_path, pas à tcl_pkgPath.
tcl_platform
Ceci est un tableau associatif dont les éléments contiennent des informations sur la plateforme sur laquelle l'application s'exécute, telles que le nom du système d'exploitation, son numéro de version actuel et l'ensemble d'instructions de la machine. Les éléments listés ci-dessous seront toujours définis, mais ils peuvent avoir des chaînes vides comme valeurs si Tcl n'a pas pu récupérer d'informations pertinentes. De plus, les extensions et les applications peuvent ajouter des valeurs supplémentaires au tableau. Les éléments prédéfinis sont :
byteOrder
L'ordre des octets natif de cette machine : soit littleEndian, soit bigEndian.
debug
Si cette variable existe, alors l'interpréteur a été compilé et lié à une bibliothèque d'exécution C activée pour le débogage. Cette variable n'existera que sous Windows, afin que les auteurs d'extensions puissent spécifier quel paquet charger en fonction de la bibliothèque d'exécution C utilisée. Ceci n'indique pas que ce cœur contient des symboles.
engine
Le nom de l'implémentation du langage Tcl. Lorsque l'interpréteur est créé pour la première fois, il est toujours défini à la chaîne Tcl.
machine
L'ensemble d'instructions exécuté par cette machine, tel que intel, PPC, 68k ou sun4m. Sur les machines UNIX, il s'agit de la valeur retournée par uname -m.
os
Le nom du système d'exploitation exécuté sur cette machine, tel que Windows NT ou SunOS. Sur les machines UNIX, il s'agit de la valeur retournée par uname -s.
osVersion
Le numéro de version du système d'exploitation exécuté sur cette machine. Sur les machines UNIX, il s'agit de la valeur retournée par uname -r.
pathSeparator
Le caractère qui doit être utilisé pour diviser les variables d'environnement de type PATH en leur liste correspondante de noms de répertoires.
platform
Soit windows, soit unix. Ceci identifie l'environnement d'exploitation général de la machine.
pointerSize
Ceci donne la taille du pointeur natif de la machine en octets (strictement, c'est la même chose que le résultat de l'évaluation de sizeof(void*) en C.)
threaded
Si cette variable existe, alors l'interpréteur a été compilé avec les threads activés.
user
Ceci identifie l'utilisateur courant en fonction des informations de connexion disponibles sur la plateforme. Cette valeur provient des appels système getuid() et getpwuid() sur Unix, et de la valeur de l'appel système GetUserName() sous Windows.
wordSize
Ceci donne la taille du mot natif de la machine en octets (strictement, c'est la même chose que le résultat de l'évaluation de sizeof(long) en C.)
tcl_precision
Cette variable contrôle le nombre de chiffres à générer lors de la conversion de valeurs en virgule flottante en chaînes de caractères. Elle est initialisée à 0. Les applications ne doivent pas modifier cette valeur ; elle est fournie pour la compatibilité avec le code hérité.
La valeur par défaut de 0 est spéciale, signifiant que Tcl doit convertir les nombres en utilisant le moins de chiffres possible tout en distinguant tout nombre à virgule flottante de ses plus proches voisins. Elle diffère de l'utilisation d'une valeur arbitrairement élevée pour tcl_precision en ce sens qu'un nombre inexact comme 1.4 sera converti en 1.4 plutôt qu'en 1.3999999999999999 même si ce dernier est plus proche de la valeur exacte du nombre binaire.
Si tcl_precision n'est pas zéro, alors lorsque Tcl convertit un nombre à virgule flottante, il crée une représentation décimale d'au plus tcl_precision chiffres significatifs ; le résultat peut être plus court si le résultat plus court représente le nombre d'origine exactement. Si aucun résultat d'au plus tcl_precision chiffres n'est une représentation exacte du nombre d'origine, celui qui est le plus proche du nombre d'origine est choisi. Si le nombre d'origine se situe précisément entre deux représentations décimales également précises, alors celle ayant une valeur paire pour le chiffre le moins significatif est choisie ; par exemple, si tcl_precision est 3, alors 0.3125 sera converti en 0.312, et non en 0.313, tandis que 0.6875 sera converti en 0.688, et non en 0.687. Toutes les chaînes de zéros de fin qui restent sont supprimées.
Une valeur tcl_precision de 17 chiffres est "parfaite" pour le flottant IEEE en ce sens qu'elle permet de convertir des valeurs en double précision en chaînes de caractères, puis de les reconvertir en binaire sans perte d'information. Pour cette raison, vous la verrez souvent comme valeur dans du code hérité qui doit fonctionner sur des versions de Tcl antérieures à 8.5. Elle n'est plus recommandée ; comme indiqué ci-dessus, une valeur zéro est la méthode préférée.
Tous les interpréteurs d'un thread partagent une seule valeur tcl_precision : la modifier dans un interpréteur affectera également tous les autres interpréteurs. Les interpréteurs sûrs ne sont pas autorisés à modifier la variable.
Les valeurs valides pour tcl_precision vont de 0 à 17.
tcl_rcFileName
Cette variable est utilisée lors de l'initialisation pour indiquer le nom d'un fichier de démarrage spécifique à l'utilisateur. Si elle est définie par une initialisation spécifique à l'application, alors le code de démarrage Tcl vérifiera l'existence de ce fichier et le sourcera s'il existe. Par exemple, pour wish la variable est définie à ~/.wishrc pour Unix et ~/wishrc.tcl pour Windows.
tcl_traceCompile
La valeur de cette variable peut être définie pour contrôler la quantité d'informations de trace affichées pendant la compilation en bytecode. Par défaut, tcl_traceCompile est zéro et aucune information n'est affichée. Définir tcl_traceCompile à 1 génère un résumé sur une ligne dans stdout chaque fois qu'une procédure ou une commande de niveau supérieur est compilée. La définir à 2 génère une liste détaillée dans stdout des instructions de bytecode émises lors de chaque compilation. Cette variable est utile pour détecter d'éventuels problèmes avec le compilateur Tcl.
Cette variable et cette fonctionnalité n'existent que si TCL_COMPILE_DEBUG a été défini lors de la compilation de Tcl.
tcl_library(n) — Tcl Library Variables

NAME

tcl_library, tcl_pathFile, auto_path, auto_index, auto_qualify, tcl_traceExec, tcl_wordchars, tcl_nonwordchars, tcl_version, argc, argv, argv0, tcl_interactive — Tcl Library Variables

DESCRIPTION

The Tcl library defines the following global variables:

tcl_library
The value of this variable is a string containing the name of the directory that contains the Tcl library scripts (e.g. "/usr/lib/tcl8.0"). The directory is normally determined when Tcl is compiled and installed.
tcl_pathFile
The value of this variable is a string containing the name of the directory that contains the Tcl library scripts. This is a deprecated variable, use tcl_library instead.
auto_path
The value of this variable is a Tcl list of directories to be searched by the auto-load facilities. The directories are searched in order. The list initially contains tcl_library and then any directories specified by the TCLLIBPATH environment variable. It may also contain other directories depending on the Tcl installation and platform. See also auto_index and auto_qualify.
auto_index
The value of this variable is a Tcl list containing script names that are used to pre-load Tcl packages. It is generally not useful to modify this variable directly. See auto_qualify for more information.
auto_qualify
The value of this variable is a boolean flag. If it is true (the default), then Tcl will automatically attempt to load packages. If it is false, then Tcl will not attempt to load packages automatically. When Tcl loads a package, it first checks to see if the package has already been loaded. If not, it then searches the directories in auto_path for a file named pkgname.tcl or pkgname.tcl. Tcl also consults auto_index for additional information on how to load packages. When Tcl finds a suitable script, it sources it. If the script successfully loads the package, then Tcl returns normally. Otherwise, Tcl raises an error.
tcl_traceExec
The value of this variable can be set to control how much tracing information is displayed during bytecode execution. By default, tcl_traceExec is zero and no information is displayed. Setting tcl_traceExec to 1 generates a one-line trace in stdout on each call to a Tcl procedure. Setting it to 2 generates a line of output whenever any Tcl command is invoked that contains the name of the command and its arguments. Setting it to 3 produces a detailed trace showing the result of executing each bytecode instruction. Note that when tcl_traceExec is 2 or 3, commands such as set and incr that have been entirely replaced by a sequence of bytecode instructions are not shown. Setting this variable is useful in tracking down suspected problems with the bytecode compiler and interpreter.
This variable and functionality only exist if TCL_COMPILE_DEBUG was defined during Tcl's compilation.
tcl_wordchars
The value of this variable is a regular expression that can be set to control what are considered “word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \S, meaning anything but a Unicode space character. Otherwise it defaults to \w, which is any Unicode word character (number, letter, or underscore).
tcl_nonwordchars
The value of this variable is a regular expression that can be set to control what are considered “non-word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \s, meaning any Unicode space character. Otherwise it defaults to \W, which is anything but a Unicode word character (number, letter, or underscore).
tcl_version
When an interpreter is created Tcl initializes this variable to hold the version number for this version of Tcl in the form x.y. Changes to x represent major changes with probable incompatibilities and changes to y represent small enhancements and bug fixes that retain backward compatibility. The value of this variable is returned by the info tclversion command.

OTHER GLOBAL VARIABLES

The following variables are only guaranteed to exist in tclsh and wish executables; the Tcl library does not define them itself but many Tcl environments do.

argc
The number of arguments to tclsh or wish.
argv
Tcl list of arguments to tclsh or wish.
argv0
The script that tclsh or wish started executing (if it was specified) or otherwise the name by which tclsh or wish was invoked.
tcl_interactive
Contains 1 if tclsh or wish is running interactively (no script was specified and standard input is a terminal-like device), 0 otherwise.

EXAMPLES

To add a directory to the collection of locations searched by package require, e.g., because of some application-specific packages that are used, the auto_path variable needs to be updated:

lappend ::auto_path [file join [pwd] "theLibDir"]

A simple though not very robust way to handle command line arguments of the form “-foo 1 -bar 2” is to load them into an array having first loaded in the default settings:

array set arguments {-foo 0 -bar 0 -grill 0}
array set arguments $::argv
puts "foo is $arguments(-foo)"
puts "bar is $arguments(-bar)"
puts "grill is $arguments(-grill)"

The argv0 global variable can be used (in conjunction with the info script command) to determine whether the current script is being executed as the main script or loaded as a library. This is useful because it allows a single script to be used as both a library and a demonstration of that library:

if {$::argv0 eq [info script]} {
    # running as: tclsh example.tcl
} else {
    package provide Example 1.0
}
