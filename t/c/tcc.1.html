NOM

tcc - Tiny C Compiler

SYNTAXE

utilisation : tcc [options] [fichier_entree1 fichier_entree2...] [-run fichier_entree args...]

DESCRIPTION

Les options de TCC ressemblent beaucoup à celles de gcc. La principale différence est que TCC peut aussi exécuter directement le programme résultant et lui donner des arguments d'exécution.

Voici quelques exemples pour comprendre la logique :

"tcc -run a.c"
Compile a.c et l'exécute directement
"tcc -run a.c arg1"
Compile a.c et l'exécute directement. arg1 est donné comme premier argument à la fonction main() de a.c.
"tcc -run a.c arg1"
Compile a.c et b.c, les lie ensemble et les exécute. arg1 est donné comme premier argument à la fonction main() du programme résultant.
"tcc -o monprog a.c b.c"
Compile a.c et b.c, les lie ensemble et génère l'exécutable monprog.
"tcc -o monprog a.o b.o"
Lie a.o et b.o ensemble et génère l'exécutable monprog.
"tcc -c a.c"
Compile a.c et génère le fichier objet a.o.
"tcc -c asmfile.S"
Prétraite avec le préprocesseur C et assemble asmfile.S et génère le fichier objet asmfile.o.
"tcc -c asmfile.s"
Assemble (mais ne prétraite pas) asmfile.s et génère le fichier objet asmfile.o.
"tcc -r -o ab.o a.c b.c"
Compile a.c et b.c, les lie ensemble et génère le fichier objet ab.o.

Scripting :

TCC peut être appelé depuis des scripts, tout comme les scripts shell. Il suffit d'ajouter "#!/usr/local/bin/tcc -run" au début de votre source C :

#!/usr/local/bin/tcc -run
#include <stdio.h>

int main() 
{
    printf("Bonjour le monde\n");
    return 0;
}

TCC peut lire du code source C depuis l'entrée standard lorsque - est utilisé à la place de fichier_entree. Exemple :

echo 'main(){puts("bonjour");}' | tcc -run -

OPTIONS

-c
Génère un fichier objet.
-o fichier_sortie
Place le fichier objet, l'exécutable, ou la dll dans le fichier de sortie fichier_sortie.
-run source [args...]
Compile le fichier source et l'exécute avec les arguments de ligne de commande args. Afin de pouvoir donner plus d'un argument à un script, plusieurs options TCC peuvent être données après l'option -run, séparées par des espaces : 
tcc "-run -L/usr/X11R6/lib -lX11" ex4.c

Dans un script, cela donne l'en-tête suivant :

#!/usr/local/bin/tcc -run -L/usr/X11R6/lib -lX11
-v
Affiche la version de TCC.
-vv
Affiche les fichiers inclus. Comme seul argument, affiche les répertoires de recherche. -vvv affiche aussi les tentatives.
-bench
Affiche les statistiques de compilation.

Options du préprocesseur :

-Idir
Spécifie un chemin d'inclusion supplémentaire. Les chemins d'inclusion sont recherchés dans l'ordre où ils sont spécifiés.

Les chemins d'inclusion système sont toujours recherchés après. Les chemins d'inclusion système par défaut sont : /usr/local/include, /usr/include et PREFIX/lib/tcc/include. (PREFIX est généralement /usr ou /usr/local).

-Dsym[=val]
Définit le symbole du préprocesseur sym à val. Si val n'est pas présent, sa valeur est 1. Les macros de type fonction peuvent également être définies : -DF(a)=a+1
-Usym
Annule la définition du symbole du préprocesseur sym.
-E
Ne traite qu'avec le préprocesseur, vers la sortie standard ou un fichier (avec -o).

Indicateurs de compilation :

Note : Chacune des options suivantes a une forme négative commençant par -fno-.

-funsigned-char
Laisse le type "char" être non signé.
-fsigned-char
Laisse le type "char" être signé.
-fno-common
Ne génère pas de symboles communs pour les données non initialisées.
-fleading-underscore
Ajoute un tiret bas au début de chaque symbole C.
-fms-extensions
Autorise les extensions du compilateur MS C au langage. Actuellement, cela suppose qu'une déclaration de structure nommée imbriquée sans identifiant se comporte comme une non nommée.
-fdollars-in-identifiers
Autorise les signes dollar dans les identificateurs
-ftest-coverage
Crée du code de couverture. Après avoir exécuté le code résultant, un fichier executable.tcov ou sofile.tcov est généré avec la couverture du code.

Options d'avertissement :

-w
Désactive tous les avertissements.

Note : Chacune des options d'avertissement suivantes a une forme négative commençant par -Wno-.

-Wimplicit-function-declaration
Avertit des déclarations de fonctions implicites.
-Wunsupported
Avertit des fonctionnalités GCC non prises en charge ignorées par TCC.
-Wwrite-strings
Rend les constantes de chaînes de caractères de type "const char *" au lieu de "char *".
-Werror
Arrête la compilation si un avertissement est émis. Peut prendre une option pour activer l'avertissement spécifié et le transformer en erreur, par exemple -Werror=unsupported.
-Wall
Active certains avertissements utiles.

Options de l'éditeur de liens :

-Ldir
Spécifie un chemin de bibliothèque statique supplémentaire pour l'option -l. Les chemins de bibliothèques par défaut sont /usr/local/lib, /usr/lib et /lib.
-lxxx
Lie votre programme avec la bibliothèque dynamique libxxx.so ou la bibliothèque statique libxxx.a. La bibliothèque est recherchée dans les chemins spécifiés par l'option -L et la variable LIBRARY_PATH.
-Bdir
Définit le chemin où les bibliothèques internes de tcc (et les fichiers d'inclusion) peuvent être trouvés (par défaut, c'est PREFIX/lib/tcc).
-shared
Génère une bibliothèque partagée au lieu d'un exécutable.
-soname nom
définit le nom de la bibliothèque partagée à utiliser à l'exécution
-static
Génère un exécutable lié statiquement (par défaut, c'est un exécutable lié dynamiquement).
-rdynamic
Export les symboles globaux vers l'éditeur de liens dynamique. C'est utile lorsqu'une bibliothèque ouverte avec dlopen() a besoin d'accéder aux symboles de l'exécutable.
-r
Génère un fichier objet combinant tous les fichiers d'entrée.
-Wl,-rpath=chemin
Ajoute un chemin de recherche personnalisé pour les bibliothèques dynamiques dans l'exécutable.
-Wl,--enable-new-dtags
Lors de l'ajout d'un chemin de recherche personnalisé pour les bibliothèques dynamiques dans l'exécutable, crée la nouvelle balise dynamique ELF DT_RUNPATH au lieu de l'ancienne balise légale

NOM

tcc — Tiny C Compiler

SYNOPSIS

tcc [option ...] [-c] [-o outfile] [infile ...]

tcc [option ...] [-o outfile] [infile ...]

tcc [option ...] -run infile [args ...]

DESCRIPTION

The Tiny C Compiler is a small, fast C compiler. It can compile C code quickly and run it directly. TCC is also an excellent tool for writing shell scripts in C.

It compiles C source files to object files or executable files.

When no options are given, tcc behaves like a cross-compiler. It needs to know the target architecture and operating system. This is usually done with options like -Blinux-arm for compiling for ARM Linux. See the TCC manual for a complete list of supported targets.

If the -run option is given, tcc compiles infile to a temporary file, runs it, and then deletes the temporary file. This is useful for writing shell scripts in C.

OPTIONS

TCC supports most GCC options and many more.

General options:

-h, --help
Display help message and exit.
-v, --version
Display version information and exit.
-run infile
Compile and run infile.
-B directory
Set the directory where tcc looks for its backend libraries and include files.
-b backend
Select backend. For example, -belf-arm selects the ARM ELF backend.
-c
Compile only; do not link.
-o outfile
Place the output into outfile.
-I dir
Add directory dir to the list of directories searched for include files.
-L dir
Add directory dir to the list of directories searched for libraries.
-l lib
Link with the library named lib. This is usually -lm for the math library.

Linker options:

-Wl,option
Pass option to the linker.
-Wl,--oformat=fmt
Use fmt as output format. The supported output formats are:
"elf32-i386"
ELF output format (default)
"binary"
Binary image (only for executable output)
"coff"
COFF output format (only for executable output for TMS320C67xx target)
-Wl,--export-all-symbols
-Wl,--export-dynamic
Export global symbols to the dynamic linker. It is useful when a library opened with dlopen() needs to access executable symbols.
-Wl,-subsystem=console/gui/wince/...
Set type for PE (Windows) executables.
-Wl,-[Ttext=# | section-alignment=# | file-alignment=# | image-base=# | stack=#]
Modify executable layout.
-Wl,-Bsymbolic
Set DT_SYMBOLIC tag.
-Wl,-(no-)whole-archive
Turn on/off linking of all objects in archives.

Debugger options:

-g
Generate run time stab debug information so that you get clear run time error messages: " test.c:68: in function 'test5()': dereferencing invalid pointer" instead of the laconic "Segmentation fault".
-gdwarf[-x]
Generate run time dwarf debug information instead of stab debug information.
-b
Generate additional support code to check memory allocations and array/pointer bounds. -g is implied.
-bt[N]
Display N callers in stack traces. This is useful with -g or -b. When activated, "__TCC_BACKTRACE__" is defined.

With executables, additional support for stack traces is included. A function
" int tcc_backtrace(const char *fmt, ...); " is provided to trigger a stack trace with a message on demand.

Misc options:

-M
Just output makefile fragment with dependencies
-MM
Like -M except mention only user header files, not system header files.
-MD
Generate makefile fragment with dependencies.
-MMD
Like -MD except mention only user header files, not system header files.
-MF depfile
Use depfile as output for -MD.
-print-search-dirs
Print the configured installation directory and a list of library and include directories tcc will search.
-dumpversion
Print version.

Target specific options:

-mms-bitfields
Use an algorithm for bitfield alignment consistent with MSVC. Default is gcc's algorithm.
-mfloat-abi (ARM only)
Select the float ABI. Possible values: "softfp" and "hard"
-mno-sse
Do not use sse registers on x86_64
-m32, -m64
Pass command line to the i386/x86_64 cross compiler.

Note: GCC options -Ox, -fx and -mx are ignored.

ENVIRONMENT

Environment variables that affect how tcc operates.

CPATH
C_INCLUDE_PATH
A colon-separated list of directories searched for include files, directories given with -I are searched first.
LIBRARY_PATH
A colon-separated list of directories searched for libraries for the -l option, directories given with -L are searched first.
