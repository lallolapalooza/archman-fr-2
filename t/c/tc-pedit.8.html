NOM

pedit - action générique d'édition de paquet

SYNTAXE


tc ... action pedit [ex] munge { OP_BRUTE | OP_CALQUEE | OP_CALQUEE_ETENDUE } [ CONTROLE ]

OP_BRUTE := offset DECALAGE { u8 | u16 | u32 } [ SPEC_AT ] SPEC_COMMANDE

SPEC_AT := at A offmask MASQUE shift DECALAGE

OP_CALQUEE := { ip CHAMP_EN_TETE_IP | ip CHAMP_AU_DELA_EN_TETE_IP } SPEC_COMMANDE

OP_CALQUEE_ETENDUE := { eth CHAMP_EN_TETE_ETH | ip CHAMP_EN_TETE_IP | ip CHAMP_EN_TETE_IP_ETENDU | ip6 CHAMP_EN_TETE_IP6 | tcp CHAMP_EN_TETE_TCP | udp CHAMP_EN_TETE_UDP } SPEC_COMMANDE

CHAMP_EN_TETE_ETH := { src | dst | type }

CHAMP_EN_TETE_IP := { src | dst | tos | dsfield | ihl | protocol | precedence | nofrag | firstfrag | ce | df }

CHAMP_AU_DELA_EN_TETE_IP := { dport | sport | icmp_type | icmp_code }

CHAMP_EN_TETE_IP_ETENDU := { ttl }

CHAMP_EN_TETE_IP6 := { src | dst | traffic_class | flow_lbl | payload_len | nexthdr | hoplimit }

CHAMP_EN_TETE_TCP := { sport | dport | flags }

CHAMP_EN_TETE_UDP := { sport | dport }

SPEC_COMMANDE := { clear | invert | set VALEUR | add VALEUR | decrement | preserve } [ retain VALEUR_RETOURNEE ]

CONTROLE := { reclassify | pipe | drop | shot | continue | pass | goto chain INDEX_CHAINE }

DESCRIPTION

L'action pedit peut être utilisée pour modifier des données arbitraires de paquet. L'emplacement des données à modifier peut être spécifié soit en donnant un décalage et une taille comme dans OP_BRUTE, soit pour les valeurs d'en-tête en nommant l'en-tête et le champ à modifier ; la taille est alors choisie automatiquement en fonction de la taille du champ d'en-tête.

OPTIONS

ex
Utiliser pedit étendu. OP_CALQUEE_ETENDUE et les spécifications de commande add/decrement ne sont autorisées que dans ce mode.
offset DECALAGE { u32 | u16 | u8 }
Spécifie le décalage auquel modifier les données. DECALAGE est un entier signé, sa base est choisie automatiquement (par exemple hexadécimale si préfixé par 0x ou octale si préfixé par 0). Le deuxième argument spécifie la longueur des données à modifier, c'est-à-dire quatre octets (u32), deux octets (u16) ou un seul octet (u8).
at A offmask MASQUE shift DECALAGE
Ceci est une partie optionnelle de OP_BRUTE qui permet d'avoir un DECALAGE variable dépendant des données du paquet à l'offset A, qui est combiné par ET binaire avec MASQUE et décalé vers la droite de DECALAGE avant d'être ajouté à DECALAGE.
eth CHAMP_EN_TETE_ETH
Modifie un champ d'en-tête ETH. Les mots-clés supportés pour CHAMP_EN_TETE_ETH sont :
src
dst
Adresse MAC source ou destination dans le format standard : XX:XX:XX:XX:XX:XX
type
Ether-type en valeur numérique
ip CHAMP_EN_TETE_IP
Modifie un champ d'en-tête IPv4. Les mots-clés supportés pour CHAMP_EN_TETE_IP sont :
src
dst
Adresse IP source ou destination, une valeur de quatre octets.
tos
dsfield
precedence
Champ Type Of Service, une valeur de huit bits.
ihl
Modifie le champ IP Header Length, une valeur de quatre bits.
protocol
Champ Next-layer Protocol, une valeur de huit bits.
nofrag
firstfrag
ce
df
mf
Modifie les drapeaux de l'en-tête IP. Notez que la valeur à passer à la commande set n'est pas juste une valeur de bit, mais l'octet complet incluant le champ des drapeaux. Bien que seuls les bits pertinents de cette valeur soient respectés, le reste est ignoré.
ip CHAMP_AU_DELA_EN_TETE_IP
Supporté uniquement pour l'opération calquée non étendue. Il est passé au noyau comme décalages par rapport au début de l'en-tête IP et suppose que l'en-tête IP est de taille minimale (20 octets). Les mots-clés supportés pour CHAMP_AU_DELA_EN_TETE_IP sont :
dport
sport
Numéros de port destination ou source, une valeur de 16 bits. En effet, les en-têtes IPv4 ne contiennent pas cette information. Au lieu de cela, cela définira un décalage qui convient au moins à TCP et UDP si l'en-tête IP est de taille minimale (20 octets). Sinon, cela produira des résultats inattendus.
icmp_type
icmp_code
Encore une fois, cela permet de modifier des données après l'en-tête IP lui-même. Il suppose qu'un en-tête ICMP est présent immédiatement après l'en-tête IP (de taille minimale). S'il n'y en a pas ou si ce dernier est plus grand que le minimum de 20 octets, cela produira des résultats inattendus. Ces champs sont des valeurs de huit bits.
ip CHAMP_EN_TETE_IP_ETENDU
Supporté uniquement lorsque ex est utilisé. Les mots-clés supportés pour CHAMP_EN_TETE_IP_ETENDU sont :
ttl
ip6 CHAMP_EN_TETE_IP6
Les mots-clés supportés pour CHAMP_EN_TETE_IP6 sont :
src
dst
traffic_class
flow_lbl
payload_len
nexthdr
hoplimit
tcp CHAMP_EN_TETE_TCP
Les mots-clés supportés pour CHAMP_EN_TETE_TCP sont :
sport
dport
Numéro de port source ou destination TCP, une valeur de 16 bits.
flags
udp CHAMP_EN_TETE_UDP
Les mots-clés supportés pour CHAMP_EN_TETE_UDP sont :
sport
dport
Numéro de port TCP source ou destination, une valeur de 16 bits.
clear
Efface les données adressées (c'est-à-dire les met à zéro).
invert
Inverse chaque bit dans les données adressées.
set VAL
Définit les données adressées à une valeur spécifique. La taille de VAL est définie par l'un des mots-clés u32, u16 ou u8 dans RAW_OP, ou par la taille du champ d'en-tête adressé dans LAYERED_OP.
add VAL
Ajoute aux données adressées une valeur spécifique. La taille de VAL est définie par la taille du champ d'en-tête adressé dans EXTENDED_LAYERED_OP. Cette opération n'est prise en charge que pour les opérations étendues en couches.
decrement
Diminue les données adressées d'une unité. Cette opération n'est prise en charge que pour le ip ttl et le ip6 hoplimit.
preserve
Conserve les données adressées telles quelles.
retain RVAL
Cette partie supplémentaire optionnelle de CMD_SPEC permet d'exclure des bits de la modification. Pris en charge uniquement pour les champs de 32 bits ou moins.
CONTROL
Les mots-clés suivants permettent de contrôler comment l'arbre des qdiscs, classes, filtres et actions est parcouru après cette action.
reclassify
Redémarre avec le premier filtre de la liste actuelle.
pipe
Continue avec l'action suivante attachée au même filtre.
drop
shot
Rejette le paquet.
continue
Continue la classification avec le filtre suivant dans la liste.
pass
Termine le processus de classification et retourne au qdisc appelant pour un traitement ultérieur du paquet. C'est le comportement par défaut.

EXEMPLES

En étant capable de modifier les données des paquets, on peut faire toutes sortes de choses, comme par exemple implémenter la redirection de port. Ce n'est certainement pas l'application la plus utile, mais à titre d'exemple, cela devrait suffire :

Premièrement, les qdiscs doivent être configurés pour y attacher des filtres. Pour le chemin de réception, un simple qdisc ingress suffira, pour le chemin de transmission un qdisc classful (ici HTB) est nécessaire :

tc qdisc replace dev eth0 root handle 1: htb
tc qdisc add dev eth0 ingress handle ffff:

Enfin, un filtre avec l'action pedit peut être ajouté pour chaque direction. Dans ce cas, u32 est utilisé pour correspondre au numéro de port à rediriger, tandis que pedit effectue la réécriture réelle :

tc filter add dev eth0 parent 1: u32 \
	match ip dport 23 0xffff \
	action pedit pedit munge ip dport set 22
tc filter add dev eth0 parent ffff: u32 \
	match ip sport 22 0xffff \
	action pedit pedit munge ip sport set 23
tc filter add dev eth0 parent ffff: u32 \
	match ip sport 22 0xffff \
	action pedit ex munge ip dst set 192.168.1.199
tc filter add dev eth0 parent ffff: u32 \
	match ip sport 22 0xffff \
	action pedit ex munge ip6 dst set fe80::dacb:8aff:fec7:320e
tc filter add dev eth0 parent ffff: u32 \
	match ip sport 22 0xffff \
	action pedit ex munge eth dst set 11:22:33:44:55:66
tc filter add dev eth0 parent ffff: u32 \
	match ip dport 23 0xffff \
	action pedit ex munge tcp dport set 22

Pour réécrire seulement une partie d'un champ, utilisez la directive retain. Par exemple, pour écraser la partie DSCP d'un champ dsfield avec $DSCP, sans toucher à ECN :

tc filter add dev eth0 ingress flower ... \
	action pedit ex munge ip dsfield set $((DSCP << 2)) retain 0xfc

Et vice versa, pour définir ECN à par exemple 1 sans impacter DSCP :

tc filter add dev eth0 ingress flower ... \
	action pedit ex munge ip dsfield set 1 retain 0x3
