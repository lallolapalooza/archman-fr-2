tcpreplay(1) Commandes utilisateur tcpreplay(1)

NOM

tcpreplay - Rejoue le trafic réseau stocké dans des fichiers pcap

SYNTAXE

tcpreplay [-indicateurs] [-indicateur [valeur]] [--nom-option[[=| ]valeur]] <fichiers_pcap(s)> | <répertoires_pcap(s)>

tcpreplay est un outil pour rejouer le trafic réseau à partir de fichiers sauvegardés avec tcpdump ou d'autres outils qui écrivent des fichiers pcap(3).

DESCRIPTION

L'opération de base de tcpreplay consiste à renvoyer tous les paquets du ou des fichiers d'entrée à la vitesse à laquelle ils ont été enregistrés, ou à un débit de données spécifié, jusqu'à la vitesse maximale de la capacité matérielle.

Optionnellement, le trafic peut être divisé entre deux interfaces, écrit dans des fichiers, filtré et modifié de diverses manières, fournissant ainsi les moyens de tester les pare-feux, les NIDS et autres périphériques réseau.

Pour plus de détails, veuillez consulter le Manuel Tcpreplay sur : http://tcpreplay.appneta.com

OPTIONS

-d nombre, --dbug=nombre

Active la sortie de débogage. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans l'intervalle 0 à 5

La valeur par défaut de nombre pour cette option est :
0

Si configuré avec --enable-debug, vous pouvez spécifier un niveau de verbosité pour la sortie de débogage. Des nombres plus élevés augmentent la verbosité.

-q, --quiet

Mode silencieux.

N'affiche rien sauf les statistiques à la fin de l'exécution.

-T chaîne, --timer=chaîne

Sélectionne le mode de temporisation des paquets : select, ioport, gtod, nano. Cette option peut apparaître jusqu'à 1 fois. La valeur par défaut de la chaîne pour cette option est :
gtod

Permet de sélectionner la méthode de temporisation des paquets à utiliser :

nano - Utilise l'API nanosleep()

select - Utilise l'API select()

ioport - Écrit dans le port d'E/S i386 0x80

gtod [défaut] - Utilise une boucle gettimeofday()

--maxsleep=nombre

Attend au maximum X millisecondes entre les paquets. Cette option prend un nombre entier comme argument. La valeur par défaut de nombre pour cette option est :
0

Définit une limite pour le nombre maximum de millisecondes que tcpreplay attendra entre les paquets. Empêche efficacement les longs délais entre les paquets sans affecter la majorité des paquets. Par défaut, désactivé.

-v, --verbose

Affiche les paquets décodés via tcpdump sur STDOUT. Cette option peut apparaître jusqu'à 1 fois.
-A chaîne, --decode=chaîne

Arguments passés au décodeur tcpdump. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec les options suivantes : verbose.

Lorsque vous activez le mode verbeux (-v), vous pouvez également spécifier un ou plusieurs arguments supplémentaires à passer à tcpdump pour modifier la façon dont les paquets sont décodés. Par défaut, -n et -l sont utilisés. Assurez-vous de mettre les arguments entre guillemets comme suit : -A "-axxx" afin qu'ils ne soient pas interprétés par tcpreplay. Veuillez consulter la page de manuel de tcpdump(1) pour une liste complète des options.

-K, --preload-pcap

Précharge les paquets en RAM avant l'envoi.

Cette option charge le(s) fichier(s) pcap spécifié(s) en RAM avant de commencer l'envoi afin d'améliorer les performances de rejeu, tout en introduisant un coût de démarrage. Le préchargement peut être utilisé avec ou sans --loop. Cette option supprime également la collecte de statistiques de flux pour chaque itération, ce qui peut réduire considérablement l'utilisation de la mémoire. Les statistiques de flux sont prédites en fonction des options fournies et des statistiques collectées lors de la première itération de la boucle.

-c chaîne, --cachefile=chaîne

Divise le trafic via un fichier cache tcpprep. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : intf2. Cette option ne doit pas apparaître en combinaison avec aucune des options suivantes : dualfile.

Si vous avez un fichier pcap que vous souhaitez utiliser pour envoyer du trafic bidirectionnel à travers un appareil (pare-feu, routeur, IDS, etc.), alors en utilisant tcpprep, vous pouvez créer un fichier cache que tcpreplay utilisera pour diviser le trafic entre deux interfaces réseau.

-2, --dualfile

Rejoue deux fichiers à la fois à partir d'un tap réseau. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : intf2. Cette option ne doit pas apparaître en combinaison avec aucune des options suivantes : cachefile.

Si vous avez capturé du trafic réseau à l'aide d'un tap réseau, vous pouvez vous retrouver avec deux fichiers pcap, un pour chaque direction. Cette option rejouera ces deux fichiers simultanément, un sur chaque interface, et les mélangera en utilisant les horodatages de chacun.

-i chaîne, --intf1=chaîne

Interface de sortie du client vers le serveur/RX/trafic primaire. Cette option peut apparaître jusqu'à 1 fois. Cette option est membre de la classe d'options intf1.

Interface réseau requise utilisée pour envoyer tout le trafic ou le trafic marqué comme 'primaire' via tcpprep. Le trafic primaire est généralement du client vers le serveur ou entrant (RX) sur les interfaces virtuelles khial.

-I chaîne, --intf2=chaîne

Interface de sortie du serveur vers le client/TX/trafic secondaire. Cette option peut apparaître jusqu'à 1 fois.

Interface réseau optionnelle utilisée pour envoyer le trafic marqué comme 'secondaire' via tcpprep. Le trafic secondaire est généralement du serveur vers le client ou sortant (TX) sur les interfaces virtuelles khial. Généralement, il n'est pertinent d'utiliser cette option qu'avec --cachefile.

-w chaîne, --write=chaîne

Fichier pcap pour recevoir les sorties de trafic. Cette option peut apparaître jusqu'à 1 fois. Cette option est membre de la classe d'options intf1. Cette option ne doit pas apparaître en combinaison avec aucune des options suivantes : intf2.

Nom de fichier pcap optionnel utilisé pour recevoir le trafic.

--include=chaîne

Envoie uniquement les numéros de paquets sélectionnés. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'option suivante : exclude.

Remplace le comportement par défaut de traitement de tous les paquets stockés dans le fichier de capture et envoie uniquement les paquets qui font partie d'une liste fournie de numéros de paquets.

    -x P:1-5,9,15,72-
ignorerait les paquets 1 à 5, le 9ème et le 15ème paquet, et les paquets 72 jusqu'à la fin du fichier
--exclude=chaîne

Envoie tous les paquets sauf ceux sélectionnés. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'option suivante : include.

Remplace le comportement par défaut de traitement de tous les paquets stockés dans le fichier de capture et envoie uniquement les paquets qui NE font PAS partie d'une liste fournie de numéros de paquets.

    -x P:1-5,9,15,72-
ignorerait les paquets 1 à 5, le 9ème et le 15ème paquet, et les paquets 72 jusqu'à la fin du fichier
--listnics

Liste les interfaces réseau disponibles et quitte.
-l nombre, --loop=nombre

Boucle sur le fichier de capture X fois. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 0

La valeur par défaut de nombre pour cette option est :
1
--loopdelay-ms=nombre

Délai entre les boucles en millisecondes. Cette option doit apparaître en combinaison avec l'option suivante : loop. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : loopdelay-ns. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 0

Le nombre par défaut pour cette option est :
0
--loopdelay-ns=nombre

Délai entre les boucles en nanosecondes. Cette option doit apparaître en combinaison avec l'option suivante : loop. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : loopdelay-ms. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 0

Le nombre par défaut pour cette option est :
0

Par défaut, tcpreplay utilisera un délai de boucle avec une précision à la microseconde (loopdelay-ms). Afin d'utiliser un délai de boucle avec une précision à la nanoseconde, vous devez utiliser le mode de chronométrage de paquets nano.

--pktlen

Remplace le snaplen et utilise la longueur réelle du paquet. Cette option peut apparaître jusqu'à 1 fois.

Par défaut, tcpreplay envoie les paquets en se basant sur la taille du "snaplen" stocké dans le fichier pcap, ce qui est généralement la bonne chose à faire. Cependant, occasionnellement, les outils stockent plus d'octets qu'ils ne sont censés le faire. En spécifiant cette option, tcpreplay ignorera le champ snaplen et essaiera plutôt d'envoyer les paquets en se basant sur la longueur d'origine du paquet. De mauvaises choses peuvent se produire si vous spécifiez cette option.

-L nombre, --limit=nombre

Limite le nombre de paquets à envoyer. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 1

Le nombre par défaut pour cette option est :
-1

Par défaut, tcpreplay enverra tous les paquets. Alternativement, vous pouvez spécifier un nombre maximum de paquets à envoyer.

--duration=nombre

Limite le nombre de secondes d'envoi. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 1

Le nombre par défaut pour cette option est :
-1

Par défaut, tcpreplay enverra tous les paquets. Alternativement, vous pouvez spécifier un nombre maximum de secondes à transmettre.

-x chaîne, --multiplier=chaîne

Modifie la vitesse de relecture à un multiple donné. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : pps, mbps, oneatatime, topspeed.

Spécifiez une valeur pour modifier la vitesse de relecture des paquets. Exemples :

        2.0 relira le trafic deux fois plus vite que capturé
        0.7 relira le trafic à 70% de la vitesse capturée
-p chaîne, --pps=chaîne

Relit les paquets à un taux donné de paquets/seconde. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : multiplier, mbps, oneatatime, topspeed.

Spécifiez une valeur pour réguler la relecture des paquets à un taux spécifique de paquets par seconde. Exemples :

        200 relira le trafic à 200 paquets par seconde
        0.25 relira le trafic à 15 paquets par minute
-M chaîne, --mbps=chaîne

Relit les paquets à un débit donné en Mbps. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : multiplier, pps, oneatatime, topspeed.

Spécifiez une valeur flottante pour le débit en Mbps auquel tcpreplay doit envoyer les paquets.

-t, --topspeed

Relit les paquets aussi vite que possible. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : mbps, multiplier, pps, oneatatime.
-o, --oneatatime

Relit un paquet à la fois pour chaque entrée utilisateur. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : mbps, pps, multiplier, topspeed.

Permet de parcourir un ou plusieurs paquets à la fois.

--pps-multi=nombre

Nombre de paquets à envoyer pour chaque intervalle de temps. Cette option doit apparaître en combinaison avec l'option suivante : pps. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 1

Le nombre par défaut pour cette option est :
1

Lorsqu'on essaie d'envoyer des paquets à des débits très élevés, le temps entre chaque paquet peut être si court qu'il est impossible de dormir avec précision pendant la période requise. Cette option permet d'envoyer plusieurs paquets à la fois, permettant ainsi des temps de sommeil plus longs qui peuvent être implémentés plus précisément.

--unique-ip

Modifie les adresses IP à chaque itération de boucle pour générer des flux uniques. Cette option doit apparaître en combinaison avec l'option suivante : loop.

Assure que les paquets IPv4 et IPv6 seront uniques pour chaque itération de --loop. Ceci est fait d'une manière qui n'altérera pas le CRC des paquets, et par conséquent n'affectera généralement pas les performances. Cette option augmentera considérablement les flux par seconde générés sur plusieurs itérations de boucle.

--unique-ip-loops=chaîne

Nombre de boucles avant d'attribuer une nouvelle IP unique. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : unique-ip.

Nombre d'itérations de --loop avant qu'une nouvelle IP unique ne soit attribuée. Par défaut, c'est 1. Suppose à la fois --loop et --unique-ip.

--netmap

Écrit les paquets directement sur un adaptateur réseau activé pour netmap.

Cette fonctionnalité détectera les pilotes de réseau compatibles avec netmap sur les systèmes Linux et BSD. S'ils sont détectés, le pilote réseau sera contourné pendant la durée d'exécution, et les tampons réseau seront écrits directement. Cela vous permettra d'atteindre le plein débit des lignes sur les adaptateurs réseau courants, de manière similaire aux débits atteints par les générateurs de trafic réseau commerciaux. Notez que le contournement du pilote réseau perturbera les autres applications connectées via l'interface de test. Voir INSTALL pour plus d'informations.

Cette fonctionnalité peut également être activée en spécifiant une interface comme 'netmap:<intf>' ou 'vale:<intf>'. Par exemple, 'netmap:eth0' spécifie netmap sur l'interface eth0.

--nm-delay=nombre

Délai de démarrage de Netmap. Cette option prend un nombre entier comme argument. Le nombre par défaut pour cette option est :
10

Nombre de secondes de délai après le chargement de netmap. Requis pour s'assurer que les interfaces sont complètement actives avant la transmission netmap. Nécessite l'option netmap. Par défaut, 10 secondes.

--no-flow-stats

Supprime l'impression et le suivi du nombre de flux, des débits et des expirations.

Supprime la collecte et l'impression des statistiques de flux. Cette option peut améliorer les performances lorsque l'option --preload-pcap n'est pas utilisée, sinon sa seule fonction est de supprimer l'impression.

La fonctionnalité de flux suit et imprime les statistiques des flux envoyés. Un flux est vaguement défini comme une combinaison unique d'un 5-tuple, c'est-à-dire l'IP source, l'IP destination, le port source, le port destination et le protocole.

Si --loop est spécifié, les flux d'une itération à l'autre ne seront pas uniques, sauf si les paquets sont modifiés. Utilisez --unique-ip ou tcpreplay-edit pour modifier les paquets entre les itérations.

--flow-expiry=nombre

Nombre de secondes d'inactivité avant qu'un flux ne soit considéré comme expiré. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : no-flow-stats. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 0

Le nombre par défaut pour cette option est :
0

Cette option suit et signale les expirations de flux en fonction des temps d'inactivité des flux. Les horodatages dans le fichier pcap sont utilisés pour déterminer l'expiration, et non l'horodatage réel des paquets rejoués. Par exemple, une valeur de 30 suggère que si aucun trafic n'est vu sur un flux pendant 30 secondes, tout trafic ultérieur serait considéré comme un nouveau flux, et par conséquent incrémenterait les statistiques de flux et de flux par seconde (fps).

Cette option peut être utilisée pour optimiser les paramètres de délai d'expiration des flux pour les produits de flux. Régler le délai d'expiration bas peut entraîner la suppression de flux alors qu'en réalité le flux répond lentement. Configurer vos délais d'expiration de flux trop élevés peut augmenter les ressources requises par votre produit de flux.

Notez que l'utilisation de cette option lors de la relecture à des vitesses supérieures aux vitesses d'origine peut entraîner une augmentation des comptages de flux et de fps.

Par défaut, c'est 0 (pas d'expiration) et une valeur typique est de 30 à 120 secondes.

-P, --pid

Affiche le PID de tcpreplay au démarrage.
--stats=nombre

Affiche les statistiques toutes les X secondes, ou à chaque boucle si '0'. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 0

Notez que les délais programmés sont un "meilleur effort" et que de longs délais entre l'envoi de paquets peuvent entraîner des délais tout aussi longs entre

des statistiques d'impression.

-W, --suppress-warnings

supprimer l'impression des messages d'avertissement.
--xdp

Écrire les paquets directement sur la carte réseau activée AF_XDP.

Cette fonctionnalité détectera les pilotes réseau compatibles AF_XDP sur les systèmes Linux sur lesquels 'libxdp-dev' et 'libbpf-dev' sont installés. Si détecté, la pile réseau est contournée et les paquets sont envoyés directement à un pilote activé par eBPF. Cela vous permettra d'atteindre des débits de ligne complets sur des cartes réseau courantes, similaires aux débits atteints par les générateurs de trafic réseau commerciaux.

--xdp-batch-size=nombre

Le nombre maximum de paquets pouvant être soumis à l'anneau TX AF_XDP à la fois. Cette option doit apparaître en combinaison avec les options suivantes : xdp, topspeed. Cette option ne doit pas apparaître en combinaison avec aucune des options suivantes : oneatatime, pps-multi. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage 1 à 4096

Le nombre par défaut pour cette option est :
1

Uniquement autorisé si l'envoi se fait à pleine vitesse. Des valeurs supérieures à 1 peuvent améliorer les performances au détriment de la précision.

-V, --version

Afficher les informations de version.
-h, --less-help

Afficher moins d'informations d'utilisation et quitter.
-H, --help

Afficher les informations d'utilisation et quitter.
-!, --more-help

Transmettre les informations d'utilisation étendues à un pager.
--save-opts [=cfgfile]

Sauvegarder l'état des options dans cfgfile. La valeur par défaut est le dernier fichier de configuration listé dans la section OPTION PRESETS, ci-dessous. La commande se terminera après la mise à jour du fichier de configuration.
--load-opts=cfgfile, --no-load-opts

Charger les options à partir de cfgfile. La forme no-load-opts désactivera le chargement des fichiers de configuration/rc/ini précédents. --no-load-opts est traité tôt, hors séquence.

PRÉSÉLECTIONS D'OPTIONS

Toute option qui n'est pas marquée comme non présélectionnable peut être présélectionnée en chargeant des valeurs à partir de fichiers de configuration ("RC" ou ".INI"). Le fichier homerc est "$$/", sauf si c'est un répertoire. Dans ce cas, le fichier ".tcpreplayrc" est recherché dans ce répertoire.
