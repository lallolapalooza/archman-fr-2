INTRODUCTION

Tcl inclut une bibliothèque de procédures Tcl pour les fonctions couramment nécessaires. Les procédures définies dans la bibliothèque Tcl sont génériques, adaptées à l'utilisation par de nombreuses applications différentes. L'emplacement de la bibliothèque Tcl est renvoyé par la commande info library. En plus de la bibliothèque Tcl, chaque application aura normalement sa propre bibliothèque de procédures de support ; l'emplacement de cette bibliothèque est normalement donné par la valeur de la variable globale $app_library, où app est le nom de l'application. Par exemple, l'emplacement de la bibliothèque Tk est conservé dans la variable tk_library.

Pour accéder aux procédures de la bibliothèque Tcl, une application doit sourcer le fichier init.tcl dans la bibliothèque, par exemple avec la commande Tcl

source [file join [info library] init.tcl]

Si la procédure de bibliothèque Tcl_Init est appelée depuis la procédure Tcl_AppInit d'une application, cela se produit automatiquement. Le code dans init.tcl définira la procédure unknown et organisera le chargement des autres procédures à la demande en utilisant le mécanisme de chargement automatique défini ci-dessous.

PROCÉDURES DE COMMANDE

Les procédures suivantes sont fournies dans la bibliothèque Tcl :

auto_execok cmd
Détermine s'il existe un fichier exécutable ou une commande shell intégrée du nom de cmd. Si c'est le cas, il renvoie une liste d'arguments à passer à exec pour exécuter le fichier exécutable ou la commande shell intégrée nommée par cmd. Sinon, il renvoie une chaîne vide. Cette commande examine les répertoires dans le chemin de recherche actuel (donné par la variable d'environnement PATH) pour rechercher un fichier exécutable nommé cmd. Sur les plateformes Windows, la recherche est étendue avec les mêmes répertoires et extensions de fichiers que ceux utilisés par exec. Auto_execok conserve des informations sur les recherches précédentes dans un tableau nommé auto_execs ; cela évite la recherche de chemin lors des appels ultérieurs pour le même cmd. La commande auto_reset peut être utilisée pour forcer auto_execok à oublier ses informations mises en cache.
auto_import motif
Auto_import est appelée pendant namespace import pour voir si les commandes importées spécifiées par motif résident dans une bibliothèque chargée automatiquement. Si c'est le cas, les commandes sont chargées de sorte qu'elles soient disponibles pour l'interpréteur afin de créer les liens d'importation. Si les commandes ne résident pas dans une bibliothèque chargée automatiquement, auto_import ne fait rien. La correspondance des motifs est effectuée selon les règles de correspondance de namespace import.
auto_load cmd
Cette commande tente de charger la définition d'une commande Tcl nommée cmd. Pour ce faire, elle recherche un *chemin de chargement automatique*, qui est une liste d'un ou plusieurs répertoires. Le chemin de chargement automatique est donné par la variable globale auto_path s'il existe. S'il n'y a pas de variable auto_path, alors la variable d'environnement TCLLIBPATH est utilisée, s'il existe. Sinon, le chemin de chargement automatique se compose uniquement du répertoire de la bibliothèque Tcl. Dans chaque répertoire du chemin de chargement automatique, il doit y avoir un fichier tclIndex qui décrit une ou plusieurs commandes définies dans ce répertoire et un script à évaluer pour charger chacune des commandes. Le fichier tclIndex doit être généré avec la commande auto_mkindex. Si cmd est trouvé dans un fichier d'index, alors le script approprié est évalué pour créer la commande. La commande auto_load renvoie 1 si cmd a été créé avec succès. La commande renvoie 0 s'il n'y avait pas d'entrée d'index pour cmd ou si le script n'a pas réellement défini cmd (par exemple, parce que les informations d'index sont obsolètes). Si une erreur se produit lors du traitement du script, cette erreur est renvoyée. Auto_load ne lit les informations d'index qu'une seule fois et les enregistre dans le tableau auto_index ; les appels ultérieurs à auto_load vérifient cmd dans le tableau plutôt que de relire les fichiers d'index. Les informations d'index mises en cache peuvent être supprimées avec la commande auto_reset. Cela forcera la prochaine commande auto_load à recharger la base de données d'index depuis le disque.
auto_mkindex dir motif motif ...
Génère un index adapté à l'utilisation par auto_load. La commande recherche dans dir tous les fichiers dont les noms correspondent à l'un des arguments motif (la correspondance est effectuée avec la commande glob), génère un index de toutes les procédures de commande Tcl définies dans tous les fichiers correspondants, et stocke les informations d'index dans un fichier nommé tclIndex dans dir. Si aucun motif n'est donné, un motif de *.tcl sera supposé. Par exemple, la commande
auto_mkindex foo *.tcl

lira tous les fichiers .tcl dans le sous-répertoire foo et générera un nouveau fichier d'index foo/tclIndex.

Auto_mkindex analyse les scripts Tcl en les sourçant dans un interpréteur enfant et en surveillant les commandes proc et namespace qui sont exécutées. Les extensions peuvent utiliser le paquet (non documenté) auto_mkindex_parser pour enregistrer d'autres commandes qui peuvent contribuer à l'index auto-chargé. Vous devrez lire auto.tcl pour voir comment cela fonctionne.

Auto_mkindex_old (qui a la même syntaxe que auto_mkindex) analyse les scripts Tcl d'une manière relativement peu sophistiquée : si une ligne contient le mot “proc” comme premiers caractères, alors elle est supposée être une définition de procédure et le mot suivant de la ligne est pris comme nom de la procédure. Les définitions de procédure qui n'apparaissent pas de cette manière (par exemple, elles ont des espaces avant le proc) ne seront pas indexées. Si votre script contient du code “dangereux”, tel que du code d'initialisation global ou des noms de procédure avec des caractères spéciaux tels que $, *, [ ou ], vous êtes plus en sécurité en utilisant auto_mkindex_old.

auto_reset
Détruit toutes les informations mises en cache par auto_execok et auto_load. Ces informations seront relues depuis le disque la prochaine fois qu'elles seront nécessaires. Auto_reset supprime également toutes les procédures listées dans l'index de chargement automatique, de sorte que de nouvelles copies seront chargées la prochaine fois qu'elles seront utilisées.
auto_qualify commande espace_nom
Calcule une liste de noms complètement qualifiés pour commande. Cette liste reflète le chemin qu'un interpréteur Tcl standard suit pour la recherche de commandes : d'abord, il recherche la commande dans l'espace de noms actuel, puis dans l'espace de noms global. En conséquence, si commande est relative et que espace_nom n'est pas ::, la liste renvoyée a deux éléments : commande, limité par espace_nom, comme si c'était une commande dans l'espace de noms espace_nom ; et commande, comme si c'était une commande dans l'espace de noms global. Sinon, si commande est absolue (elle commence par ::), ou si espace_nom est ::, la liste ne contient que commande, comme si c'était une commande dans l'espace de noms global.

Auto_qualify est utilisé par les installations de chargement automatique dans Tcl, à la fois pour produire des index de chargement automatique tels que pkgIndex.tcl, et pour effectuer le chargement automatique réel des fonctions à l'exécution.

tcl_findLibrary nom_base version patch script_init nom_var_env nom_var
t>
Il s'agit d'une procédure de recherche standard destinée à être utilisée par les extensions lors de leur initialisation. Elles appellent cette procédure pour rechercher leur bibliothèque de scripts dans plusieurs répertoires standard. Le dernier composant du nom du répertoire de la bibliothèque est normalement basenameversion (par exemple, tk8.0), mais il peut être « library » dans les hiérarchies de construction. Le fichier initScript sera sourcé dans l'interpréteur une fois qu'il sera trouvé. Le répertoire dans lequel ce fichier est trouvé est stocké dans la variable globale varName. Si cette variable est déjà définie (par exemple, par du code C lors de l'initialisation de l'application), aucune recherche n'est effectuée. Sinon, la recherche s'effectue dans ces répertoires : le répertoire nommé par la variable d'environnement enVarName ; par rapport au répertoire de la bibliothèque Tcl ; par rapport au fichier exécutable dans le répertoire standard d'installation bin ou bin/arch ; par rapport au fichier exécutable dans l'arborescence de construction actuelle ; par rapport au fichier exécutable dans une arborescence de construction parallèle.
parray nomTableau ?motif?
Affiche sur la sortie standard les noms et les valeurs de tous les éléments du tableau nomTableau, ou seulement les noms qui correspondent à motif (en utilisant les règles de correspondance de string match) et leurs valeurs si motif est donné. NomTableau doit être un tableau accessible à l'appelant de parray. Il peut être local ou global.

AIDE DE LIMITE DE MOT

Ces procédures sont principalement utilisées en interne par Tk.

tcl_endOfWord chaine debut
Retourne l'indice du premier emplacement de fin de mot qui se produit après un indice de début debut dans la chaîne chaine. Un emplacement de fin de mot est défini comme le premier caractère non-mot suivant le premier caractère-mot après le point de départ. Retourne -1 s'il n'y a plus d'emplacements de fin de mot après le point de départ. Voir la description de tcl_wordchars et tcl_nonwordchars ci-dessous pour plus de détails sur la façon dont Tcl détermine quels caractères sont des caractères-mot.
tcl_startOfNextWord chaine debut
Retourne l'indice du premier emplacement de début de mot qui se produit après un indice de début debut dans la chaîne chaine. Un emplacement de début de mot est défini comme le premier caractère-mot suivant un caractère non-mot. Retourne -1 s'il n'y a plus d'emplacements de début de mot après le point de départ.
tcl_startOfPreviousWord chaine debut
Retourne l'indice du premier emplacement de début de mot qui se produit avant un indice de début debut dans la chaîne chaine. Retourne -1 s'il n'y a plus d'emplacements de début de mot avant le point de départ.
tcl_wordBreakAfter chaine debut
Retourne l'indice de la première limite de mot après l'indice de début debut dans la chaîne chaine. Retourne -1 s'il n'y a plus de limites après le point de départ dans la chaîne donnée. L'indice retourné fait référence au deuxième caractère de la paire qui constitue une limite.
tcl_wordBreakBefore chaine debut
Retourne l'indice de la première limite de mot avant l'indice de début debut dans la chaîne chaine. Retourne -1 s'il n'y a plus de limites avant le point de départ dans la chaîne donnée. L'indice retourné fait référence au deuxième caractère de la paire qui constitue une limite.

VARIABLES

Les variables globales suivantes sont définies ou utilisées par les procédures de la bibliothèque Tcl. Elles appartiennent à deux grandes classes, gérant les commandes inconnues et les paquets, et déterminant ce que sont les mots.

VARIABLES DE CHARGEMENT AUTOMATIQUE ET DE GESTION DES PAQUETS

auto_execs
Utilisé par auto_execok pour enregistrer des informations sur l'existence de commandes particulières en tant que fichiers exécutables.
auto_index
Utilisé par auto_load pour sauvegarder les informations d'index lues depuis le disque.
auto_noexec
S'il est défini à n'importe quelle valeur, alors unknown n'essaiera pas d'exécuter automatiquement des commandes.
auto_noload
S'il est défini à n'importe quelle valeur, alors unknown n'essaiera pas de charger automatiquement des commandes.
auto_path
S'il est défini, alors il doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations de chargement automatique (y compris pour les fichiers d'index de paquets lors de l'utilisation du gestionnaire package unknown par défaut). Cette variable est initialisée au démarrage pour contenir, dans l'ordre : les répertoires listés dans la variable d'environnement TCLLIBPATH, le répertoire nommé par la variable globale tcl_library, le répertoire parent de tcl_library, les répertoires listés dans la variable tcl_pkgPath. Les emplacements supplémentaires pour rechercher des fichiers et des index de paquets doivent normalement être ajoutés à cette variable en utilisant lappend.
env(TCL_LIBRARY)
S'il est défini, alors il spécifie l'emplacement du répertoire contenant les scripts de bibliothèque (la valeur de cette variable sera attribuée à la variable tcl_library et retournée par conséquent par la commande info library). Si cette variable n'est pas définie, une valeur par défaut est utilisée.
env(TCLLIBPATH)
S'il est défini, alors il doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations de chargement automatique. Les répertoires doivent être spécifiés au format Tcl, en utilisant « / » comme séparateur de chemin, quelle que soit la plateforme. Cette variable n'est utilisée que lors de l'initialisation de la variable auto_path.

VARIABLES DE DETERMINATION DE LIMITE DE MOT

Ces variables sont uniquement utilisées dans les commandes tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter et tcl_wordBreakBefore.

tcl_nonwordchars
Cette variable contient une expression régulière utilisée par des routines comme tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non. Si le motif correspond à un caractère, le caractère est considéré comme un caractère non-mot. Sur les plateformes Windows, les espaces, les tabulations et les nouvelles lignes sont considérés comme des caractères non-mot. Sous Unix, tout ce qui n'est pas un nombre, une lettre ou un underscore est considéré comme un caractère non-mot.
tcl_wordchars
Cette variable contient une expression régulière utilisée par des routines comme tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non. Si le motif correspond à un caractère, le caractère est considéré comme un caractère mot. Sur les plateformes Windows, les mots sont composés de tout caractère qui n'est pas un espace, une tabulation ou une nouvelle ligne. Sous Unix, les mots sont composés de nombres, de lettres ou d'underscores.
