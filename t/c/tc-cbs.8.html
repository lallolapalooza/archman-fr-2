NOM

CBS - File d'attente Credit Based Shaper (CBS)

SYNOPSIS

tc qdisc ... dev dev parent classid [ handle major: ] cbs idleslope idleslope sendslope sendslope hicredit hicredit locredit locredit [ offload 0|1 ]

DESCRIPTION

Le qdisc CBS (Credit Based Shaper) implémente l'algorithme de mise en forme défini par la norme IEEE 802.1Q-2014 Section 8.6.8.2, qui applique une méthode de limitation de débit bien définie au trafic.

Cette discipline de mise en file d'attente est destinée à être utilisée par les applications TSN (Time Sensitive Networking). Les paramètres CBS sont dérivés directement de ce qui est décrit par l'Annexe L de la spécification IEEE 802.1Q-2014. L'algorithme et son impact sur la latence y sont détaillés.

CBS est censé être installé sous un autre qdisc qui mappe les flux de paquets aux classes de trafic, un exemple est mqprio(8).

PARAMÈTRES

idleslope
Idleslope est le taux de crédits qui est accumulé (en kilobits par seconde) lorsqu'il y a au moins un paquet en attente de transmission. Les paquets sont transmis lorsque la valeur actuelle des crédits est égale ou supérieure à zéro. Lorsqu'il n'y a pas de paquet à transmettre, le montant des crédits est mis à zéro. C'est le paramètre principal de l'algorithme CBS et il représente la bande passante qui sera consommée. Notez que lors du calcul de idleslope, la taille totale du paquet doit être prise en compte, y compris les en-têtes de toutes les couches (c'est-à-dire le tramage MAC et tout surcoût de la couche physique), comme décrit dans la section 34.4 de la norme IEEE 802.1Q-2014.

Par exemple, pour une trame Ethernet transportant 284 octets de charge utile, et sans VLAN, vous devez ajouter 14 octets pour les en-têtes Ethernet, 4 octets pour la séquence de contrôle de trame (CRC), et 20 octets pour le surcoût L1 : 12 octets d'interpacket gap, 7 octets de préambule et 1 octet de start of frame delimiter. Cela donne 322 octets pour la taille totale du paquet, qui est ensuite utilisée pour calculer l'idleslope.

sendslope
Sendslope est le taux de crédits qui est décrémenté (il devrait s'agir d'un nombre négatif de kilobits par seconde) lorsqu'une transmission a lieu. Il peut être calculé comme suit (Section 8.6.8.2, élément g, de la norme IEEE 802.1Q-2014) :

sendslope = idleslope - port_transmit_rate

hicredit
Hicredit définit le montant maximum de crédits (en octets) qui peuvent être accumulés. Hicredit dépend des caractéristiques du trafic interférant. 'max_interference_size' est la taille maximale de toute rafale de trafic qui peut retarder la transmission d'une trame disponible pour cette classe de trafic (Annexe L, Équation L-3, IEEE 802.1Q-2014) :

hicredit = max_interference_size * (idleslope / port_transmit_rate)

locredit
Locredit est le montant minimum de crédits qui peut être atteint. C'est une fonction du trafic circulant dans ce qdisc (Annexe L, Équation L-2, IEEE 802.1Q-2014) :

locredit = max_frame_size * (sendslope / port_transmit_rate)

offload
Lorsque offload est à 1, cbs(8) tentera de configurer l'interface réseau pour que l'algorithme CBS s'exécute dans le contrôleur. La valeur par défaut est 0.

EXEMPLES

CBS est utilisé pour faire respecter une Qualité de Service en limitant le débit de données d'une classe de trafic. Pour séparer les paquets en classes de trafic, l'utilisateur peut choisir mqprio(8) et le configurer comme suit :

# tc qdisc add dev eth0 handle 100: parent root mqprio num_tc 3 \
	map 2 2 1 0 2 2 2 2 2 2 2 2 2 2 2 2 \
	queues 1@0 1@1 2@2 \
	hw 0

Pour remplacer la discipline de mise en file d'attente actuelle par CBS dans la discipline de mise en file d'attente actuelle connectée à la classe de trafic numéro 0, exécutez :

# tc qdisc replace dev eth0 parent 100:4 cbs \
	locredit -1470 hicredit 30 sendslope -980000 idleslope 20000

Ces valeurs sont obtenues à partir des paramètres suivants : idleslope est de 20 Mbit/s, le taux de transmission est de 1 Gbit/s et la taille maximale de trame d'interférence est de 1500 octets.
