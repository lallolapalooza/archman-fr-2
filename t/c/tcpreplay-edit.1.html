tcpreplay-edit(1) Commandes utilisateur tcpreplay-edit(1)

NOM

tcpreplay-edit - Rejouer du trafic réseau stocké dans des fichiers pcap

SYNTAXE

tcpreplay-edit [-flags] [-flag [valeur]] [--option-name[[=| ]valeur]] <fichier(s)_pcap> | <répertoire(s)_pcap>

tcpreplay est un outil pour rejouer du trafic réseau à partir de fichiers sauvegardés avec tcpdump ou d'autres outils qui écrivent des fichiers pcap(3).

DESCRIPTION

L'opération de base de tcpreplay consiste à renvoyer tous les paquets des fichiers d'entrée à la vitesse à laquelle ils ont été enregistrés, ou à un débit de données spécifié, aussi rapidement que le matériel le permet.

Optionnellement, le trafic peut être divisé entre deux interfaces, écrit dans des fichiers, filtré et modifié de diverses manières, offrant ainsi les moyens de tester les pare-feu, les NIDS et autres périphériques réseau.

Pour plus de détails, veuillez consulter le manuel de Tcpreplay à l'adresse : http://tcpreplay.appneta.com

OPTIONS

-r chaîne, --portmap=chaîne

Réécrire les ports TCP/UDP. Cette option peut apparaître jusqu'à 9999 fois.

Spécifiez une liste de mappages de ports séparés par des virgules, composés de paires de numéros de port séparés par des deux-points. Chaque paire de ports séparée par des deux-points consiste en le port à faire correspondre suivi du numéro de port à réécrire.

Exemples :

    --portmap=80:8000 --portmap=8080:80    # 80->8000 et 8080->80
    --portmap=8000,8080,88888:80           # 3 ports différents deviennent 80
    --portmap=8000-8999:80                 # les ports 8000 à 8999 deviennent 80
-s nombre, --seed=nombre

Randomiser les adresses IPv4/v6 source/destination avec la graine donnée. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : fuzz-seed. Cette option prend un nombre entier comme argument.

Permet de randomiser de manière pseudo-aléatoire les adresses IPv4/v6 source et destination tout en maintenant les relations client/serveur. La randomisation étant déterministe en fonction de la graine, vous pouvez réutiliser la même valeur de graine pour recréer le trafic.

-N chaîne, --pnat=chaîne

Réécrire les adresses IPv4/v6 en utilisant pseudo-NAT. Cette option peut apparaître jusqu'à 2 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : srcipmap.

Prend une série de blocs réseau CIDR séparés par des virgules et des paires de blocs réseau séparés par des deux-points. Chaque paire de blocs réseau est évaluée dans l'ordre par rapport aux adresses IP. Si l'adresse IP dans le paquet correspond au premier bloc réseau, elle est réécrite en utilisant le second bloc réseau comme masque pour les bits de poids fort.

Exemple IPv4 :

    --pnat=192.168.0.0/16:10.77.0.0/16,172.16.0.0/12:10.1.0.0/24
Exemple IPv6 : 
    --pnat=[2001:db8::/32]:[dead::/16],[2001:db8::/32]:[::ffff:0:0/96]
-S chaîne, --srcipmap=chaîne

Réécrire les adresses IP source IPv4/v6 en utilisant pseudo-NAT. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : pnat.

Fonctionne exactement comme l'option --pnat, mais affecte uniquement les adresses IP source dans l'en-tête IPv4/v6.

-D chaîne, --dstipmap=chaîne

Réécrire les adresses IP de destination IPv4/v6 en utilisant pseudo-NAT. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'une des options suivantes : pnat.

Fonctionne exactement comme l'option --pnat, mais affecte uniquement les adresses IP de destination dans l'en-tête IPv4/v6.

-e chaîne, --endpoints=chaîne

Réécrire les adresses IP pour qu'elles soient comprises entre deux points de terminaison. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : cachefile.

Prend une paire d'adresses IPv4/v6 séparées par des deux-points qui seront utilisées pour réécrire tout le trafic afin qu'il apparaisse comme étant entre les deux adresses IP.

Exemple IPv4 :

    --endpoints=172.16.0.1:172.16.0.2
Exemple IPv6 : 
    --endpoints=[2001:db8::dead:beef]:[::ffff:0:0:ac:f:0:2]
--tcp-sequence=nombre

Modifier les numéros de séquence (et ACK) TCP avec la graine donnée. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 1

La valeur nombre par défaut pour cette option est :
0

Modifie tous les numéros de séquence TCP et les numéros de séquence-accusé de réception associés. Ils seront décalés d'un montant aléatoire basé sur la graine fournie.

-b, --skipbroadcast

Ignorer la réécriture des adresses IPv4/v6 de diffusion/multidiffusion.

Par défaut, --seed, --pnat et --endpoints réécriront les adresses IPv4/v6 et MAC de diffusion et de multidiffusion. La définition de ce drapeau empêchera la réécriture des adresses IPv4/v6 et MAC de diffusion/multidiffusion.

-C, --fixcsum

Forcer le recalcul des sommes de contrôle des en-têtes IPv4/TCP/UDP.

Permet de recalculer et corriger les sommes de contrôle de chaque paquet IPv4/v6. Activé automatiquement pour les paquets modifiés avec --seed, --pnat, --endpoints ou --fixlen.

--fixhdrlen

Modifier la longueur de l'en-tête IP/TCP pour correspondre à la longueur du paquet.

Par défaut, tcpreplay envoie des paquets avec la longueur originale du paquet. Cependant, vous pourriez vouloir que la longueur du paquet soit révisée à la taille minimale du paquet. En utilisant cette option, tcpreplay réécrira (corriger) la longueur du paquet et recalculera les sommes de contrôle lorsque la longueur du paquet change. Attention : des changements de paquet indésirables peuvent survenir lorsque cette option est spécifiée.

-m nombre, --mtu=nombre

Ignorer la taille MTU par défaut (1500 octets). Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage  1 à MAX_SNAPLEN

Ignorer la taille MTU par défaut de 1500 octets pour déterminer la longueur de remplissage maximale (--fixlen=pad) ou lors de la troncature (--mtu-trunc).

--mtu-trunc

Tronquer les paquets plus grands que la MTU spécifiée. Cette option peut apparaître jusqu'à 1 fois.

Similaire à --fixlen, cette option tronquera les données dans les paquets à partir de la couche 3 et au-dessus pour qu'ils ne dépassent pas la MTU.

-E, --efcs

Supprimer les sommes de contrôle Ethernet (FCS) à la fin des trames.

Attention, cette option est assez dangereuse ! Nous ne vérifions pas réellement si un FCS existe dans la trame, nous supprimons simplement aveuglément les 4 derniers octets. Par conséquent, vous ne devriez l'utiliser que si vous savez que votre système d'exploitation fournit le FCS lors de la lecture de paquets bruts.

--ttl=chaîne

Modifier le TTL/Hop Limit IPv4/v6.

Permet de modifier le TTL/Hop Limit de tous les paquets IPv4/v6. Spécifiez un nombre pour coder en dur la valeur ou +/-une valeur pour augmenter ou diminuer de la valeur fournie (limité à 1-255).

Exemples :

    --ttl=10
    --ttl=+7
    --ttl=-64
--tos=nombre

Définir l'octet TOS/DiffServ/ECN IPv4. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage  0 à 255

Permet d'ignorer la valeur TOS (également connue sous le nom de DiffServ/ECN) dans IPv4.

--tclass=nombre

Définir l'octet Traffic Class IPv6. Cette option peut apparaître jusqu'à 1

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 0 à 255

Permet de remplacer le champ Classe de trafic IPv6.

--flowlabel=nombre

Définit le label de flux IPv6. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 0 à 1048575

Permet de remplacer le champ de label de flux IPv6 de 20 bits. N'a aucun effet sur les paquets IPv4.

-F chaîne, --fixlen=chaîne

Remplit ou tronque les données du paquet pour correspondre à la longueur de l'en-tête. Cette option peut apparaître jusqu'à 1 fois.

Les paquets peuvent être tronqués lors de la capture si la longueur de capture (snaplen) est inférieure à la taille du paquet. Cette option permet de modifier le paquet pour le remplir à la taille stockée dans l'en-tête IPv4/v6 ou de réécrire la longueur totale de l'en-tête IP pour refléter la longueur du paquet stockée.

pad Les paquets tronqués seront complétés de manière à ce que la longueur du paquet corresponde à la longueur totale IPv4

trunc La longueur totale du champ IPv4 des paquets tronqués sera réécrite pour correspondre à la longueur réelle du paquet

del Supprime le paquet

--fuzz-seed=nombre

Perturbe 1 paquet sur X. Modifie les octets, la longueur ou émule la perte de paquets. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 0

La valeur par défaut de nombre pour cette option est :
0

Cette perturbation a été conçue pour tester les protocoles de couche 7 tels que les protocoles VoIP. Elle modifie aléatoirement 1 paquet sur X (où X = --fuzz-factor) afin que les protocoles d'état couvrent davantage leur code. Les actions de perturbation aléatoires se concentrent sur le début et la fin des données, car c'est souvent la partie sur laquelle les applications basent leurs décisions.

Liste des actions de perturbation possibles :
* Perte de paquet
* Réduction de la taille du paquet
* Modification des octets du paquet :
* Tous les octets n'ont pas la même probabilité d'apparaître dans la vie réelle.
Remplacer par 0x00, 0xFF, ou un octet aléatoire avec une probabilité égale.
* Tous les octets n'ont pas la même signification dans un paquet.
Remplacer le début, la fin ou le milieu du paquet avec une probabilité égale.
* Ne rien faire (7 paquets sur 8)

--fuzz-factor=nombre

Définit le ratio de perturbation (1 sur X paquets) (par défaut 1 sur 8 paquets). Cette option doit apparaître en combinaison avec les options suivantes : fuzz-seed. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
supérieure ou égale à 1

La valeur par défaut de nombre pour cette option est :
8

Définit le ratio pour l'option --fuzz-seed. Par défaut, cette valeur est de 8, ce qui signifie que 1 paquet sur 8 est modifié par perturbation. Notez que ce ratio est basé sur le nombre aléatoire généré par la graine de perturbation fournie. Par conséquent, par défaut, vous ne pouvez pas vous attendre à ce que exactement tous les huit paquets soient modifiés.

--skipl2broadcast

Ignore la réécriture des adresses de diffusion/multidiffusion de couche 2.

Par défaut, la modification des adresses de couche 2 réécrit les adresses MAC de diffusion et de multidiffusion. L'activation de ce drapeau empêchera la réécriture des adresses MAC de diffusion/multidiffusion.

--dlt=chaîne

Remplace le DLT d'encapsulation de sortie. Cette option peut apparaître jusqu'à 1 fois.

Par défaut, aucune conversion de DLT (type de liaison de données) n'est effectuée. Pour changer le type DLT de la sortie pcap, sélectionnez l'une des valeurs suivantes :

enet Ethernet, alias DLT_EN10MB

hdlc Cisco HDLC, alias DLT_C_HDLC

jnpr_eth Juniper Ethernet DLT_C_JNPR_ETHER

pppserial PPP Série, alias DLT_PPP_SERIAL

user En-tête de couche 2 et type DLT spécifiés par l'utilisateur

--enet-dmac=chaîne

Remplace les adresses MAC Ethernet de destination. Cette option peut apparaître jusqu'à 1 fois.

Prend une paire d'adresses MAC Ethernet séparées par des virgules qui remplaceront l'adresse MAC de destination des paquets sortants. La première adresse MAC sera utilisée pour le trafic serveur vers client et la seconde adresse MAC optionnelle sera utilisée pour le trafic client vers serveur.

Exemple :

    --enet-dmac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-smac=chaîne

Remplace les adresses MAC Ethernet sources. Cette option peut apparaître jusqu'à 1 fois.

Prend une paire d'adresses MAC Ethernet séparées par des virgules qui remplaceront l'adresse MAC source des paquets sortants. La première adresse MAC sera utilisée pour le trafic serveur vers client et la seconde adresse MAC optionnelle sera utilisée pour le trafic client vers serveur.

Exemple :

    --enet-smac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-subsmac=chaîne

Substitue des adresses MAC. Cette option peut apparaître jusqu'à 9999 fois.

Permet de réécrire les adresses MAC Ethernet des paquets. Elle prend une paire d'adresses MAC séparées par des virgules et réécrit toutes les occurrences de la première adresse MAC avec la valeur de la seconde adresse MAC. Exemple :

    --enet-subsmac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-mac-seed=nombre

Randomise les adresses MAC. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec les options suivantes : enet-smac, enet-dmac, enet-subsmac. Cette option prend un nombre entier comme argument.

Permet de randomiser les adresses MAC Ethernet des paquets, un peu comme l'option --seed le fait pour les adresses IPv4/IPv6.

--enet-mac-seed-keep-bytes=nombre

Randomise les adresses MAC. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-mac-seed. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 1 à 6

Conserve certains octets intacts lors de l'utilisation de l'option --enet-mac-seed.

--enet-vlan=chaîne

Spécifie le mode de marquage VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois.

Permet de réécrire les trames Ethernet pour ajouter un en-tête 802.1q aux en-têtes Ethernet standard 802.3 ou pour supprimer les informations de marquage VLAN 802.1q.

add Ajoute un en-tête VLAN 802.1q à l'en-tête Ethernet 802.3 existant. Si un en-tête VLAN existe déjà, un nouvel en-tête VLAN est ajouté à l'extérieur de l'en-tête existant.

Notez que vous pourrez exécuter cette option plusieurs fois pour créer plus de 2 en-têtes VLAN, mais ces paquets seront valides. Au maximum, vous devriez avoir 2 étiquettes VLAN 802.1q, ou une étiquette VLAN externe 802.1ad et une interne 802.1q.

del Réécrit l'en-tête VLAN 802.1q existant en tant qu'en-tête Ethernet 802.3

--enet-vlan-tag=nombre

Spécifie la nouvelle valeur de la balise VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-vlan. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 0 à 4095

--enet-vlan-cfi=nombre

Spécifie la valeur CFI du VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-vlan. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 0 à 1

--enet-vlan-pri=nombre

Spécifie la priorité VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-vlan. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à être : 
dans la plage de 0 à 7

--enet-vlan-proto=chaîne

Spécifie le protocole de balisage VLAN 802.1q ou 802.1ad. Cette option peut apparaître jusqu'à 1 fois.

Permet de spécifier le protocole des balises VLAN ajoutées.

802.1q Spécifie que des en-têtes VLAN 802.1q doivent être ajoutés. C'est la valeur par défaut.

802.1ad Spécifie que des en-têtes VLAN Q-in-Q 802.1ad doivent être ajoutés. Pour créer des paquets valides, les paquets d'entrée doivent déjà contenir des en-têtes VLAN 802.1q.

--hdlc-control=nombre

Spécifie la valeur de contrôle HDLC. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

L'en-tête Cisco HDLC contient un champ "contrôle" d'un octet. Apparemment, celui-ci devrait toujours être 0, mais vous pouvez utiliser n'importe quelle valeur d'un octet.

--hdlc-address=nombre

Spécifie l'adresse HDLC. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

L'en-tête Cisco HDLC contient un champ "adresse" d'un octet qui a deux valeurs valides :

0x0F Unicast

0xBF Diffusion
Vous pouvez cependant spécifier n'importe quelle valeur d'un seul octet.

--user-dlt=nombre

Définit le type DLT du fichier de sortie.Voici le contenu traduit en français, en conservant la structure du fichier : Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

Définit la valeur DLT du fichier pcap de sortie.

--user-dlink=chaîne

Réécrit la couche Data-Link avec des données spécifiées par l'utilisateur. Cette option peut apparaître jusqu'à 2 fois.

Fournit une série de valeurs hexadécimales séparées par des virgules qui seront utilisées pour réécrire ou créer l'en-tête de couche 2 des paquets. La première occurrence de cet argument réécrira le trafic serveur et client, mais si cet argument est spécifié une deuxième fois, il sera utilisé pour le trafic client.

Exemple :

    --user-dlink=01,02,03,04,05,06,00,1A,2B,3C,4D,5E,6F,08,00
-d nombre, --dbug=nombre

Active la sortie de débogage. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte : 
dans la plage de 0 à 5

Le nombre par défaut pour cette option est :
0

Si configuré avec --enable-debug, vous pouvez spécifier un niveau de verbosité pour la sortie de débogage. Des nombres plus élevés augmentent la verbosité.

-q, --quiet

Mode silencieux.

N'affiche rien sauf les statistiques à la fin de l'exécution.

-T chaîne, --timer=chaîne

Sélectionne le mode de temporisation des paquets : select, ioport, gtod, nano. Cette option peut apparaître jusqu'à 1 fois. La chaîne par défaut pour cette option est :
gtod

Permet de sélectionner la méthode de temporisation des paquets à utiliser :

nano - Utilise l'API nanosleep()

select - Utilise l'API select()

ioport - Écrit sur le port IO i386 0x80

gtod [par défaut] - Utilise une boucle gettimeofday()

--maxsleep=nombre

Ne pas dormir plus de X millisecondes entre les paquets. Cette option prend un nombre entier comme argument. Le nombre par défaut pour cette option est :
0

Définit une limite pour le nombre maximum de millisecondes que tcpreplay dormira entre les paquets. Empêche efficacement les longs délais entre les paquets sans affecter la majorité des paquets. Par défaut, désactivé.

-v, --verbose

Affiche les paquets décodés via tcpdump sur STDOUT. Cette option peut apparaître jusqu'à 1 fois.
-A chaîne, --decode=chaîne

Arguments passés au décodeur tcpdump. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : verbose.

Lorsque le mode verbeux est activé (-v), vous pouvez également spécifier un ou plusieurs arguments supplémentaires à passer à tcpdump pour modifier la façon dont les paquets sont décodés. Par défaut, -n et -l sont utilisés. Assurez-vous de mettre les arguments entre guillemets, par exemple : -A ""-axxx"", afin qu'ils ne soient pas interprétés par tcpreplay. Veuillez consulter la page de manuel de tcpdump(1) pour une liste complète des options.

-K, --preload-pcap

Précharge les paquets en RAM avant de les envoyer.

Cette option charge le(s) pcap spécifié(s) en RAM avant de commencer l'envoi afin d'améliorer les performances de rejeu, tout en introduisant un coût de performance au démarrage. Le préchargement peut être utilisé avec ou sans --loop. Cette option supprime également la collecte de statistiques de flux pour chaque itération, ce qui peut réduire considérablement l'utilisation de la mémoire. Les statistiques de flux sont prédites sur la base des options fournies et des statistiques collectées lors de la première itération de la boucle.

-c chaîne, --cachefile=chaîne

Divise le trafic via un fichier cache tcpprep. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : intf2. Cette option ne doit pas apparaître en combinaison avec les options suivantes : dualfile.

Si vous avez un fichier pcap que vous souhaitez utiliser pour envoyer du trafic bidirectionnel via un périphérique (pare-feu, routeur, IDS, etc.), vous pouvez utiliser tcpprep pour créer un fichier cache que tcpreplay utilisera pour diviser le trafic entre deux interfaces réseau.

-2, --dualfile

Relit deux fichiers à la fois à partir d'un "network tap". Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : intf2. Cette option ne doit pas apparaître en combinaison avec l'option suivante : cachefile.

Si vous avez capturé du trafic réseau à l'aide d'un "network tap", vous pouvez vous retrouver avec deux fichiers pcap - un pour chaque direction. Cette option rejouera ces deux fichiers en même temps, un sur chaque interface et les mélangera en utilisant les horodatages de chacun.

-i chaîne, --intf1=chaîne

Interface de sortie du trafic client vers serveur/RX/primaire. Cette option peut apparaître jusqu'à 1 fois. Cette option est membre de la classe d'options intf1.

Interface réseau requise utilisée pour envoyer tout le trafic ou le trafic marqué comme 'primaire' via tcpprep. Le trafic primaire est généralement du client vers le serveur ou entrant (RX) sur les interfaces virtuelles khial.

-I chaîne, --intf2=chaîne

Interface de sortie du trafic serveur vers client/TX/secondaire. Cette option peut apparaître jusqu'à 1 fois.

Interface réseau optionnelle utilisée pour envoyer le trafic marqué comme 'secondaire' via tcpprep. Le trafic secondaire est généralement du serveur vers le client ou sortant (TX) sur les interfaces virtuelles khial. En général, il n'est logique d'utiliser cette option qu'avec --cachefile.

-w chaîne, --write=chaîne

Fichier pcap pour recevoir les sorties de trafic. Cette option peut apparaître jusqu'à 1 fois. Cette option est membre de la classe d'options intf1. Cette option ne doit pas apparaître en combinaison avec l'option suivante : intf2.

Nom de fichier pcap optionnel utilisé pour recevoir le trafic.

--include=chaîne

Envoyer uniquement les numéros de paquets sélectionnés. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'option suivante : exclude.

Ignore la valeur par défaut de traitement de tous les paquets stockés dans le fichier de capture et n'envoie que les paquets faisant partie d'une liste fournie de numéros de paquets.

    -x P:1-5,9,15,72-
ignorerait les paquets 1 à 5, le 9ème et le 15ème paquet, et les paquets 72 jusqu'à la fin du fichier.
--exclude=chaîne

Envoyer tous les paquets sauf ceux sélectionnés. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'option suivante : include.

Ignore la valeur par défaut de traitement de tous les paquets stockés dans le fichier de capture et n'envoie que les paquets qui NE font PAS partie d'une liste fournie de numéros de paquets.

    -x P:1-5,9,15,72-
ignorerait les paquets 1 à 5, le 9ème et le 15ème paquet, et les paquets 72 jusqu'à la fin du fichier.
--listnics

Liste les interfaces réseau disponibles et quitte.
-l nombre, --loop=nombre

Boucle sur le fichier de capture X fois. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte : 
supérieure ou égale à 0

Le nombre par défaut pour cette option est :
1
