NOM

tunnel_key - Manipulation des métadonnées de tunnel

SYNTAXE


tc ... action tunnel_key { unset | SET }

SET := set src_ip ADRESSE dst_ip ADRESSE id CLÉ_ID dst_port PORT_UDP tos TOS ttl TTL [ csum | nocsum ]

DESCRIPTION

L'action tunnel_key, combinée à un périphérique tunnel IP partagé, permet d'effectuer l'encapsulation ou la décapsulation IP d'un paquet, reflétée par les modes d'opération UNSET et SET. Le mode UNSET est optionnel ; même sans l'utiliser, les informations de métadonnées seront libérées automatiquement une fois le traitement du paquet terminé. La fonction UNSET peut être utilisée dans les cas où le trafic est redirigé entre deux tunnels, où les métadonnées du premier tunnel seront utilisées pour l'encapsulation effectuée par le second tunnel. Le mode SET nécessite les adresses IP source et destination ADRESSE et l'identifiant de clé de tunnel CLÉ_ID qui seront utilisés par le périphérique tunnel IP partagé pour créer l'en-tête du tunnel. L'action tunnel_key n'est utile qu'en combinaison avec une action de redirection mirred vers un périphérique tunnel IP partagé qui utilisera les métadonnées (pour SET) et désactivera les métadonnées qu'il a créées (pour UNSET).

OPTIONS

unset
Désactive les métadonnées de tunnel créées par le périphérique tunnel IP. Cette fonction n'est pas obligatoire et ne peut être utilisée que dans des cas d'utilisation spécifiques (comme expliqué ci-dessus).
set
Définit les métadonnées de tunnel à utiliser par le périphérique tunnel IP. Nécessite les options src_ip et dst_ip. Les options id, dst_port, geneve_opts, vxlan_opts et erspan_opts sont optionnelles.
id
ID du tunnel (par exemple VNI dans un tunnel VXLAN)
src_ip
Adresse IP source de l'en-tête externe (IPv4 ou IPv6)
dst_ip
Adresse IP de destination de l'en-tête externe (IPv4 ou IPv6)
dst_port
Port UDP de destination de l'en-tête externe
geneve_opts
Options de longueur variable Geneve. geneve_opts est spécifié sous la forme CLASS:TYPE:DATA, où CLASS est représenté par une valeur hexadécimale de 16 bits, TYPE par une valeur hexadécimale de 8 bits et DATA par une valeur hexadécimale de longueur variable. De plus, plusieurs options peuvent être listées en utilisant un délimiteur de virgule.
vxlan_opts
Options de métadonnées Vxlan. vxlan_opts est spécifié sous la forme GBP, comme un nombre de 32 bits. Les options multiples ne sont pas prises en charge.
erspan_opts
Options de métadonnées Erspan. erspan_opts est spécifié sous la forme VERSION:INDEX:DIR:HWID, où VERSION est représenté par un nombre de 8 bits, INDEX par un nombre de 32 bits, DIR et HWID par un nombre de 8 bits. Les options multiples ne sont pas prises en charge. Notez que INDEX est utilisé lorsque VERSION est 1, et DIR et HWID sont utilisés lorsque VERSION est 2.
tos
TOS de l'en-tête externe
ttl
TTL de l'en-tête externe
[no]csum
Contrôle la somme de contrôle UDP externe. Lorsqu'elle est définie sur csum (par défaut), la somme de contrôle UDP externe est calculée et incluse dans les paquets. Lorsqu'elle est définie sur nocsum, la somme de contrôle UDP externe est nulle. Notez que lors de l'utilisation de sommes de contrôle UDP nulles avec IPv6, l'autre point de terminaison du tunnel doit être configuré pour accepter de tels paquets. Sous Linux, ce serait l'option udp6zerocsumrx pour l'interface tunnel VXLAN.
Si vous utilisez nocsum avec IPv6, assurez-vous de bien comprendre ce que vous faites. Les sommes de contrôle UDP nulles offrent une protection plus faible contre les paquets corrompus. Voir RFC6935 pour plus de détails.
nofrag
interdit la fragmentation IP.

EXEMPLES

L'exemple suivant encapsule les paquets ICMP entrants sur eth0 dans un tunnel vxlan, en définissant les métadonnées sur VNI 11, adresse IP source 11.11.0.1 et adresse IP destination 11.11.0.2, et en redirigeant le paquet avec les métadonnées vers le périphérique vxlan0, qui effectuera l'encapsulation réelle en utilisant les métadonnées :

#tc qdisc add dev eth0 handle ffff: ingress
#tc filter add dev eth0 protocol ip parent ffff: \
  flower \
    ip_proto icmp \
  action tunnel_key set \
    src_ip 11.11.0.1 \
    dst_ip 11.11.0.2 \
    id 11 \
  action mirred egress redirect dev vxlan0

Voici un exemple de la fonction unset : Le trafic VXLAN entrant avec les IP externes et le VNI 11 est décapsulé par vxlan0 et les métadonnées sont désactivées avant d'être redirigées vers le périphérique tunl1 :

#tc qdisc add dev eth0 handle ffff: ingress
#tc filter add dev vxlan0 protocol ip parent ffff:   flower \
	  enc_src_ip 11.11.0.2 enc_dst_ip 11.11.0.1 enc_key_id 11 	action tunnel_key unset 	action mirred egress redirect dev tunl1
