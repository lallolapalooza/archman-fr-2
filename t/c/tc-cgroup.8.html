NOM

cgroup - filtre de contrôle de trafic basé sur les groupes de contrôle

SYNTAXE


tc filter ... cgroup [ match EMATCH_TREE ] [ action ACTION_SPEC ]

DESCRIPTION

Ce filtre sert d'indicateur à tc pour que l'identifiant de classe assigné au groupe de contrôle net_cls auquel appartient le processus à l'origine du paquet soit utilisé pour la classification. Évidemment, il n'est utile que pour les paquets générés localement.

OPTIONS

action ACTION_SPEC
Applique une action du framework d'actions génériques sur les paquets correspondants.
match EMATCH_TREE
Correspond aux paquets en utilisant l'infrastructure de correspondance étendue. Voir tc-ematch(8) pour une description détaillée de la syntaxe autorisée dans EMATCH_TREE.

EXEMPLES

Pour utiliser ce filtre, un groupe de contrôle net_cls doit d'abord être créé et une classe ainsi qu'un ou plusieurs ID de processus lui être assignés. Ce qui suit crée un groupe de contrôle net_cls nommé "foobar" :

modprobe cls_cgroup
mkdir /sys/fs/cgroup/net_cls
mount -t cgroup -onet_cls net_cls /sys/fs/cgroup/net_cls
mkdir /sys/fs/cgroup/net_cls/foobar

Pour assigner un ID de classe au groupe de contrôle créé, un fichier nommé net_cls.classid doit être créé, contenant l'ID de classe à assigner sous forme de nombre hexadécimal de 64 bits. Les 32 bits supérieurs sont réservés au handle majeur, les bits restants contiennent le mineur. Ainsi, un ID de classe de, par exemple, ff:be doit être écrit ainsi : 0xff00be (les zéros initiaux peuvent être omis). Pour continuer l'exemple ci-dessus, ce qui suit assigne l'ID de classe 1:2 au groupe de contrôle foobar :

echo 0x10002 > /sys/fs/cgroup/net_cls/foobar/net_cls.classid

Enfin, des PID peuvent être assignés au groupe de contrôle donné :

echo 1234 > /sys/fs/cgroup/net_cls/foobar/tasks
echo 5678 > /sys/fs/cgroup/net_cls/foobar/tasks

Maintenant, en attachant simplement un filtre cgroup à une qdisc, les paquets des PID 1234 et 5678 seront poussés dans la classe 1:2.
