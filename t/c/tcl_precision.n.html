tclvars(n) Commandes intégrées Tcl tclvars(n)

NOM

argc, argv, argv0, auto_path, env, errorCode, errorInfo, tcl_interactive, tcl_library, tcl_nonwordchars, tcl_patchLevel, tcl_pkgPath, tcl_platform, tcl_precision, tcl_rcFileName, tcl_traceCompile, tcl_traceExec, tcl_wordchars, tcl_version - Variables utilisées par Tcl

DESCRIPTION

Les variables globales suivantes sont créées et gérées automatiquement par la bibliothèque Tcl. Sauf indication contraire ci-dessous, ces variables doivent normalement être considérées comme étant en lecture seule par le code spécifique à l'application et par les utilisateurs.

auto_path
Si elle est définie, elle doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations d'auto-chargement (y compris pour les fichiers d'index de paquets lors de l'utilisation du gestionnaire par défaut package unknown). Cette variable est initialisée au démarrage pour contenir, dans l'ordre : les répertoires listés dans la variable d'environnement TCLLIBPATH, le répertoire nommé par la variable globale tcl_library, le répertoire parent de tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, les répertoires listés dans la variable tcl_pkgPath. Les emplacements supplémentaires où chercher les fichiers et les index de paquets doivent normalement être ajoutés à cette variable en utilisant lappend.

Des variables supplémentaires relatives à la gestion des paquets existent. Plus de détails sont listés dans la section VARIABLES de la page de manuel library.

env
Cette variable est maintenue par Tcl en tant que tableau dont les éléments sont les variables d'environnement du processus. La lecture d'un élément renverra la valeur de la variable d'environnement correspondante. La définition d'un élément du tableau modifiera la variable d'environnement correspondante ou en créera une nouvelle si elle n'existe pas déjà. La suppression d'un élément de env supprimera la variable d'environnement correspondante. Les changements apportés au tableau env affecteront l'environnement passé aux processus enfants par des commandes comme exec. Si le tableau env entier est supprimé, Tcl cessera de surveiller les accès à env et ne mettra plus à jour les variables d'environnement.

Sous Windows, les variables d'environnement PATH et COMSPEC, quelle que soit leur casse, sont automatiquement converties en majuscules. Par exemple, la variable PATH peut être exportée par le système d'exploitation sous “path”, “Path”, “PaTh”, etc., ce qui oblige un code Tcl autrement simple à prendre en charge de nombreux cas particuliers. Toutes les autres variables d'environnement héritées par Tcl restent inchangées. La définition d'une variable de tableau env à une chaîne vide équivaut à sa suppression, car c'est le comportement du système d'exploitation Windows sous-jacent. Il convient de noter que s'appuyer sur une variable d'environnement existante et vide ne fonctionnera pas sous Windows et est déconseillé pour une utilisation multiplateforme.

Les éléments suivants de env sont spéciaux pour Tcl :

env(HOME)
Cette variable d'environnement, si elle est définie, donne l'emplacement du répertoire considéré comme le répertoire personnel de l'utilisateur actuel, et dans lequel un appel à cd sans argument ou avec seulement “~” comme argument se déplacera. La plupart des plateformes la définissent correctement par défaut ; elle n'a normalement pas besoin d'être définie par du code utilisateur.
env(TCL_LIBRARY)
Si elle est définie, elle spécifie l'emplacement du répertoire contenant les scripts de bibliothèque (la valeur de cette variable sera assignée à la variable tcl_library et donc renvoyée par la commande info library). Si cette variable n'est pas définie, une valeur par défaut est utilisée.

Notez que cette variable d'environnement ne devrait *normalement pas* être définie.

env(TCLLIBPATH)
Si elle est définie, elle doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations d'auto-chargement. Les répertoires doivent être spécifiés au format Tcl, en utilisant “/” comme séparateur de chemin, quelle que soit la plateforme. Cette variable n'est utilisée que lors de l'initialisation de la variable auto_path.
env(TCL_TZ), env(TZ)
Ces variables spécifient le fuseau horaire par défaut utilisé pour l'analyse et le formatage des heures et des dates dans la commande clock. Sur de nombreuses plateformes, la variable d'environnement TZ est configurée par le système d'exploitation.
env(LC_ALL), env(LC_MESSAGES), env(LANG)
Ces variables d'environnement sont utilisées par le package msgcat pour déterminer la locale à utiliser pour le formatage des messages.
env(TCL_INTERP_DEBUG_FRAME)
Si elle existe, elle a le même effet que d'exécuter interp debug {} -frame 1 comme toute première commande de chaque nouvel interpréteur Tcl.
errorCode
Cette variable contient la valeur de l'option de retour -errorcode définie par la dernière erreur survenue dans cet interpréteur. Cette valeur de liste représente des informations supplémentaires sur l'erreur sous une forme facile à traiter par les programmes. Le premier élément de la liste identifie une classe générale d'erreurs et détermine le format du reste de la liste. Les formats suivants pour les options de retour -errorcode sont utilisés par le noyau Tcl ; les applications individuelles peuvent définir des formats supplémentaires.
ARITH code message
Ce format est utilisé lorsqu'une erreur arithmétique se produit (par exemple, une tentative de division de zéro par zéro dans la commande expr). Code identifie l'erreur précise et message fournit une description lisible par l'homme de l'erreur. Code sera soit DIVZERO (pour une tentative de division par zéro), DOMAIN (si un argument est hors du domaine d'une fonction, tel que acos(-3)), IOVERFLOW (pour un dépassement de capacité entier), OVERFLOW (pour un dépassement de capacité en virgule flottante), soit UNKNOWN (si la cause de l'erreur ne peut être déterminée).

La détection de ces erreurs dépend en partie du matériel sous-jacent et des bibliothèques système.

CHILDKILLED pid nomSignal message
Ce format est utilisé lorsqu'un processus enfant a été tué en raison d'un signal. L'élément pid sera l'identifiant du processus (en décimal). L'élément nomSignal sera le nom symbolique du signal qui a provoqué la terminaison du processus ; ce sera l'un des noms du fichier d'inclusion signal.h, tel que SIGPIPE. L'élément message sera un court message lisible par l'homme décrivant le signal, tel que “write on pipe with no readers” pour SIGPIPE.
CHILDSTATUS pid code
Ce format est utilisé lorsqu'un processus enfant s'est terminé avec un code de sortie non nul. L'élément pid sera l'identifiant du processus (en décimal) et l'élément code sera le code de sortie renvoyé par le processus (également en décimal).
CHILDSUSP pid nomSignal message
Ce format est utilisé lorsqu'un processus enfant a été suspendu en raison d'un signal. L'élément pid sera l'identifiant du processus, en décimal. L'élément nomSignal sera le nom symbolique du signal qui a provoqué la suspension du processus ; ce sera l'un des noms du fichier d'inclusion signal.h, tel que SIGTTIN. L'élément message sera un court message lisible par l'homme décrivant le signal, tel que “background tty read” pour SIGTTIN.
NONE
Ce format est utilisé pour les erreurs pour lesquelles aucune information supplémentaire n'est disponible hormis le message renvoyé avec l'erreur. Dans ces cas, l'option de retour -errorcode consistera en une liste contenant un seul élément dont le contenu est NONE.
POSIX nomErreur message
Si le premier élément est POSIX, alors l'erreur s'est produite lors d'un appel noyau POSIX. L'élément nomErreur contiendra le nom symbolique de l'erreur qui s'est produite, tel que ENOENT ; ce sera l'une des valeurs définies dans le fichier d'inclusion errno.h. L'élément message
errorInfo
Cette variable contient des informations de débogage détaillées sur la dernière erreur survenue. Elle contient généralement une trace complète de la pile d'appels au moment de l'erreur. Cette variable est généralement ignorée, sauf lors du débogage d'une application.
tcl_interactive
Cette variable contient une valeur booléenne (0 ou 1) qui indique si le Tcl est en cours d'exécution dans un interpréteur interactif. Un interpréteur est considéré comme interactif s'il lit des commandes à partir d'un terminal (par exemple, s'il est lancé sans arguments, ou si son entrée standard est connectée à un terminal).
tcl_library
Cette variable globale contient le chemin du répertoire où les scripts de bibliothèque Tcl sont stockés. Les commandes Tcl telles que source utilisent cette variable pour trouver des scripts de bibliothèque. L'interpréteur peut être démarré avec une valeur différente pour cette variable via l'option -library de la ligne de commande.
tcl_nonwordchars
Cette variable contient une chaîne de caractères représentant tous les caractères qui ne sont pas considérés comme des caractères de mot. Elle est utilisée par les commandes qui effectuent une analyse de texte, telle que la commande string wordstart et string wordend. La valeur de cette variable peut être modifiée par l'utilisateur pour ajuster le comportement de ces commandes.
tcl_patchLevel
Cette variable contient une chaîne de caractères indiquant la version de patch de la bibliothèque Tcl. Elle est utile pour identifier des bogues spécifiques à une version.
tcl_pkgPath
Cette variable contient une liste Tcl de répertoires qui sont recherchés lorsque des packages sont chargés en utilisant la commande package require. Elle est initialisée à partir des répertoires spécifiés dans la variable d'environnement TCLLIBPATH et est également utilisée pour initialiser la variable auto_path. Les développeurs peuvent ajouter des chemins à cette variable pour spécifier des emplacements personnalisés pour les packages.
tcl_platform
Cette variable contient un enregistrement décrivant la plateforme sur laquelle Tcl est en cours d'exécution. Les champs de cet enregistrement incluent os (nom du système d'exploitation), osVersion (version du système d'exploitation), machine (type de processeur), et user (nom de l'utilisateur actuel). Cette information peut être utile pour écrire du code portable.
tcl_precision
Cette variable contrôle la précision utilisée lors de la conversion de nombres en chaînes de caractères en virgule flottante. Elle spécifie le nombre maximal de chiffres significatifs à conserver. La valeur par défaut est 12. Une valeur plus élevée peut être utilisée pour une précision accrue, mais peut également entraîner des chaînes de caractères plus longues. Cette variable est utilisée par la commande format.
tcl_rcFileName
Cette variable contient le nom du fichier qui est lu et exécuté lors de la démarrage d'un interpréteur Tcl interactif. Si ce fichier existe dans le répertoire personnel de l'utilisateur, son contenu sera exécuté comme des commandes Tcl. La valeur par défaut est « .tclshrc ».
tcl_traceCompile
Si cette variable est définie sur une valeur non nulle, Tcl tracera les étapes de compilation de chaque commande avant son exécution. Ceci est principalement utile pour le débogage de Tcl lui-même.
tcl_traceExec
Si cette variable est définie sur une valeur non nulle, Tcl tracera l'exécution de chaque commande dans le script. Ceci est principalement utile pour le débogage de Tcl lui-même.
tcl_wordchars
Cette variable contient une chaîne de caractères représentant tous les caractères qui sont considérés comme des caractères de mot. Elle est utilisée par les commandes qui effectuent une analyse de texte, telle que la commande string wordstart et string wordend. La valeur de cette variable peut être modifiée par l'utilisateur pour ajuster le comportement de ces commandes.
tcl_version
Cette variable contient une chaîne de caractères indiquant la version de la bibliothèque Tcl (par exemple, « 8.6.8 »). Elle est utile pour écrire du code compatible avec différentes versions de Tcl.

$ Tcl Variables Tcl Variables $ $ Tcl Variables Tcl Variables $ . .TH Tcl Variables 1 "17 March 2008" "Tcl " "Tcl Variables" . .SH "Tcl GLOBAL VARIABLES" . .PP Certain variables are available globally within every Tcl interpreter. This section describes some of the most common ones, along with some Tcl-specific ones that are not part of the Tcl command language itself. . .TP .B -errorcode When an error occurs, this variable is set to a code that indicates the nature of the error. If the error is POSIX-related, the code will be a list whose first element is the name of the POSIX error (e.g. ENOENT), and whose remaining elements are implementation-dependent. If the error is not POSIX-related, then the contents of the list are implementation-dependent. If no error code is available, the variable is set to the value NONE. .PP For example, if a file cannot be found, the error code might be {ENOENT no such file or directory}. The first element of the error code is intended to be used by applications to automatically determine the nature of the error, and may be used as an index into a hash table or to select a branch of a switch statement. .PP .TP .B -errorinfo This variable holds the value of the -errorinfo return option set by the most recent error that occurred in this interpreter. This string value will contain one or more lines identifying the Tcl commands and procedures that were being executed when the most recent error occurred. Its contents take the form of a stack trace showing the various nested Tcl commands that had been invoked at the time of the error. .PP The value of -errorcode and -errorinfo are set by the Tcl error handling mechanism. The -errorinfo value will be a human-readable message corresponding to errName, such as “no such file or directory” for the ENOENT case. .TP .B TCL Indicates some sort of problem generated in relation to Tcl itself, e.g. a failure to look up a channel or variable. .PP To set the -errorcode return option, applications should use library procedures such as Tcl_SetObjErrorCode, Tcl_SetReturnOptions, and Tcl_PosixError, or they may invoke the -errorcode option of the return command. If none of these methods for setting the error code has been used, the Tcl interpreter will reset the variable to NONE after the next error. . .TP .B errorInfo This variable holds the value of the -errorinfo return option set by the most recent error that occurred in this interpreter. This string value will contain one or more lines identifying the Tcl commands and procedures that were being executed when the most recent error occurred. Its contents take the form of a stack trace showing the various nested Tcl commands that had been invoked at the time of the error. .TP .B tcl_library This variable holds the name of a directory containing the system library of Tcl scripts, such as those used for auto-loading. The value of this variable is returned by the info library command. See the library(n) manual entry for details of the facilities provided by the Tcl script library. Normally each application or package will have its own application-specific script library in addition to the Tcl script library; each application should set a global variable with a name like $app_library (where app is the application's name) to hold the network file name for that application's library directory. The initial value of tcl_library is set when an interpreter is created by searching several different directories until one is found that contains an appropriate Tcl startup script. If the TCL_LIBRARY environment variable exists, then the directory it names is checked first. If TCL_LIBRARY is not set or doesn't refer to an appropriate directory, then Tcl checks several other directories based on a compiled-in default location, the location of the binary containing the application, and the current working directory. .TP .B tcl_patchLevel When an interpreter is created Tcl initializes this variable to hold a string giving the current patch level for Tcl, such as 8.4.16 for Tcl 8.4 with the first sixteen official patches, or 8.5b3 for the third beta release of Tcl 8.5. The value of this variable is returned by the info patchlevel command. .TP .B tcl_pkgPath This variable holds a list of directories indicating where packages are normally installed. It is not used on Windows. It typically contains either one or two entries; if it contains two entries, the first is normally a directory for platform-dependent packages (e.g., shared library binaries) and the second is normally a directory for platform-independent packages (e.g., script files). Typically a package is installed as a subdirectory of one of the entries in the tcl_pkgPath variable. The directories in the tcl_pkgPath variable are included by default in the auto_path variable, so they and their immediate subdirectories are automatically searched for packages during package require commands. Note: tcl_pkgPath is not intended to be modified by the application. Its value is added to auto_path at startup; changes to tcl_pkgPath are not reflected in auto_path. If you want Tcl to search additional directories for packages you should add the names of those directories to auto_path, not tcl_pkgPath. .TP .B tcl_platform This is an associative array whose elements contain information about the platform on which the application is running, such as the name of the operating system, its current release number, and the machine's instruction set. The elements listed below will always be defined, but they may have empty strings as values if Tcl could not retrieve any relevant information. In addition, extensions and applications may add additional values to the array. The predefined elements are: . .IP .TP .B byteOrder The native byte order of this machine: either littleEndian or bigEndian. .TP .B debug If this variable exists, then the interpreter was compiled with and linked to a debug-enabled C run-time. This variable will only exist on Windows, so extension writers can specify which package to load depending on the C run-time library that is in use. This is not an indication that this core contains symbols. .TP .B engine The name of the Tcl language implementation. When the interpreter is first created, this is always set to the string Tcl. .TP .B machine The instruction set executed by this machine, such as intel, PPC, 68k, or sun4m. On UNIX machines, this is the value returned by uname -m. .TP .B os The name of the operating system running on this machine, such as Windows NT or SunOS. On UNIX machines, this is the value returned by uname -s. .TP .B osVersion The version number for the operating system running on this machine. On UNIX machines, this is the value returned by uname -r. .TP .B pathSeparator The character that should be used to split PATH-like environment variables into their corresponding list of directory names. .TP .B platform Either windows, or unix. This identifies the general operating environment of the machine. .TP .B pointerSize This gives the size of the native-machine pointer in bytes (strictly, it is same as the result of evaluating sizeof(void*) in C.) .TP .B threaded If this variable exists, then the interpreter was compiled with threads enabled. .TP .B user This identifies the current user based on the login information available on the platform. This value comes from the getuid() and getpwuid() system calls on Unix, and the value from the GetUserName() system call on Windows. .TP .B wordSize This gives the size of the native-machine word in bytes (strictly, it is same as the result of evaluating sizeof(long) in C.) .TP .B tcl_precision This variable controls the number of digits to generate when converting floating-point values to strings. It defaults to 0. Applications should not change this value; it is provided for compatibility with legacy code. .PP The default value of 0 is special, meaning that Tcl should convert numbers using as few digits as possible while still distinguishing any floating point number from its nearest neighbours. It differs from using an arbitrarily high value for tcl_precision in that an inexact number like 1.4 will convert as 1.4 rather than 1.3999999999999999 even though the latter is nearer to the exact value of the binary number. .PP If tcl_precision is not zero, then when Tcl converts a floating point number, it creates a decimal representation of at most tcl_precision significant digits; the result may be shorter if the shorter result represents the original number exactly. If no result of at most tcl_precision digits is an exact representation of the original number, the one that is closest to the original number is chosen. If the original number lies precisely between two equally accurate decimal representations, then the one with an even value for the least significant digit is chosen; for instance, if tcl_precision is 3, then 0.3125 will convert to 0.312, not 0.313, while 0.6875 will convert to 0.688, not 0.687. Any string of trailing zeroes that remains is trimmed. .PP a tcl_precision value of 17 digits is “perfect” for IEEE floating-point in that it allows double-precision values to be converted to strings and back to binary with no loss of information. For this reason, you will often see it as a value in legacy code that must run on Tcl versions before 8.5. It is no longer recommended; as noted above, a zero value is the preferred method. .PP All interpreters in a thread share a single tcl_precision value: changing it in one interpreter will affect all other interpreters as well. Safe interpreters are not allowed to modify the variable. .PP Valid values for tcl_precision range from 0 to 17. .TP .B tcl_rcFileName This variable is used during initialization to indicate the name of a user-specific startup file. If it is set by application-specific initialization, then the Tcl startup code will check for the existence of this file and source it if it exists. For example, for wish the variable is set to ~/.wishrc for Unix and ~/wishrc.tcl for Windows. .TP .B tcl_traceCompile The value of this variable can be set to control how much tracing information is displayed during bytecode compilation. By default, tcl_traceCompile is zero and no information is displayed. Setting tcl_traceCompile to 1 generates a one-line summary in stdout whenever a procedure or top-level command is compiled. Setting it to 2 generates a detailed listing in stdout of the bytecode instructions emitted during every compilation. This variable is useful in tracking down suspected problems with the Tcl compiler. .PP This variable and functionality only exist if TCL_COMPILE_DEBUG was defined during Tcl's compilation. .TP .B tcl_traceExectcl_traceExec
La valeur de cette variable peut être définie pour contrôler la quantité d'informations de traçage affichées lors de l'exécution du bytecode. Par défaut, tcl_traceExec est à zéro et aucune information n'est affichée. Définir tcl_traceExec à 1 génère une traçage d'une ligne dans stdout à chaque appel d'une procédure Tcl. La définir à 2 génère une ligne de sortie chaque fois qu'une commande Tcl est invoquée, affichant le nom de la commande et ses arguments. La définir à 3 produit un traçage détaillé montrant le résultat de l'exécution de chaque instruction de bytecode. Notez que lorsque tcl_traceExec est à 2 ou 3, les commandes telles que set et incr qui ont été entièrement remplacées par une séquence d'instructions de bytecode ne sont pas affichées. Définir cette variable est utile pour détecter les problèmes potentiels avec le compilateur et l'interpréteur de bytecode.
Cette variable et cette fonctionnalité n'existent que si TCL_COMPILE_DEBUG a été défini lors de la compilation de Tcl.
tcl_wordchars
La valeur de cette variable est une expression régulière qui peut être définie pour contrôler ce qui est considéré comme des caractères de "mot", pour des instances comme la sélection d'un mot par double-clic sur du texte dans Tk. Elle dépend de la plateforme. Sur Windows, elle vaut par défaut \S, signifiant tout caractère sauf un espace Unicode. Sinon, elle vaut par défaut \w, qui est tout caractère de mot Unicode (chiffre, lettre ou underscore).
tcl_nonwordchars
La valeur de cette variable est une expression régulière qui peut être définie pour contrôler ce qui est considéré comme des caractères "non-mot", pour des instances comme la sélection d'un mot par double-clic sur du texte dans Tk. Elle dépend de la plateforme. Sur Windows, elle vaut par défaut \s, signifiant tout espace Unicode. Sinon, elle vaut par défaut \W, qui est tout caractère sauf un caractère de mot Unicode (chiffre, lettre ou underscore).
tcl_version
Lorsqu'un interpréteur est créé, Tcl initialise cette variable pour contenir le numéro de version de cette version de Tcl sous la forme x.y. Les changements à x représentent des changements majeurs avec des incompatibilités probables, et les changements à y représentent de petites améliorations et corrections de bugs qui maintiennent la compatibilité descendante. La valeur de cette variable est retournée par la commande info tclversion.

AUTRES VARIABLES GLOBALES

Les variables suivantes sont garanties d'exister uniquement dans les exécutables tclsh et wish; la bibliothèque Tcl ne les définit pas elle-même, mais de nombreux environnements Tcl le font.

argc
Le nombre d'arguments pour tclsh ou wish.
argv
Liste Tcl des arguments pour tclsh ou wish.
argv0
Le script que tclsh ou wish a commencé à exécuter (s'il a été spécifié) ou sinon, le nom par lequel tclsh ou wish a été invoqué.
tcl_interactive
Contient 1 si tclsh ou wish s'exécute de manière interactive (aucun script n'a été spécifié et l'entrée standard est un périphérique de type terminal), 0 sinon.

EXEMPLES

Pour ajouter un répertoire à la collection d'emplacements recherchés par package require, par exemple, en raison de packages spécifiques à une application utilisés, la variable auto_path doit être mise à jour :

lappend ::auto_path [file join [pwd] "theLibDir"]

Une manière simple, bien que pas très robuste, de gérer les arguments de ligne de commande de la forme « -foo 1 -bar 2 » est de les charger dans un tableau après avoir chargé les paramètres par défaut :

array set arguments {-foo 0 -bar 0 -grill 0}
array set arguments $::argv
puts "foo is $arguments(-foo)"
puts "bar is $arguments(-bar)"
puts "grill is $arguments(-grill)"

La variable globale argv0 peut être utilisée (en conjonction avec la commande info script) pour déterminer si le script actuel est exécuté comme script principal ou chargé comme bibliothèque. Ceci est utile car cela permet à un seul script d'être utilisé à la fois comme bibliothèque et comme démonstration de cette bibliothèque :

if {$::argv0 eq [info script]} {
    # en cours d'exécution comme : tclsh example.tcl
} else {
    package provide Example 1.0
}
