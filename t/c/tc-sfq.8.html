TC(8) Linux TC(8)

NOM

sfq - Stochastic Fairness Queueing (File d'attente à équité stochastique)

SYNOPIS

tc qdisc ... [ divisor taille_table_hachage ] [ limit paquets ] [ perturb secondes ] [ quantum octets ] [ flows nombre ] [ depth nombre ] [ headdrop ] [ redflowlimit octets ] [ min octets ] [ max octets ] [ avpkt octets ] [ burst paquets ] [ probability P ] [ ecn ] [ harddrop ]

DESCRIPTION

Stochastic Fairness Queueing est une discipline de mise en file d'attente sans classe disponible pour le contrôle de trafic avec la commande tc(8).

SFQ ne façonne pas le trafic, mais planifie seulement la transmission des paquets, basée sur des « flux ». L'objectif est d'assurer une équité telle que chaque flux puisse envoyer des données à tour de rôle, évitant ainsi qu'un seul flux n'étouffe les autres.

Cela peut en fait avoir un certain effet pour atténuer une tentative de déni de service.

SFQ est "work-conserving" (économe en travail) et par conséquent, il délivre toujours un paquet s'il en a un disponible.

ALGORITHME

Lors de l'ajout, chaque paquet est assigné à un compartiment de hachage, basé sur la valeur de hachage du paquet. Cette valeur de hachage est soit obtenue à partir d'un classificateur de flux externe (utilisez tc filter pour les configurer), soit un classificateur interne par défaut si aucun classificateur externe n'a été configuré.

Lorsque le classificateur interne est utilisé, sfq utilise

(i)
Adresse source
(ii)
Adresse destination
(iii)
Port source et destination

S'ils sont disponibles. SFQ connaît ipv4 et ipv6 ainsi que UDP, TCP et ESP. Les paquets avec d'autres protocoles sont hachés en utilisant la représentation 32 bits de leurs adresses de destination et source. Un flux correspond principalement à une connexion TCP/IP.

Chacun de ces compartiments devrait représenter un flux unique. Comme plusieurs flux peuvent être hachés dans le même compartiment, l'algorithme de hachage interne de sfq peut être perturbé à intervalles configurables afin que l'iniquité ne dure que peu de temps. La perturbation peut cependant entraîner un réordonnancement involontaire de certains paquets. Après linux-3.3, il n'y a plus de problème de réordonnancement de paquets, mais des pertes de paquets sont possibles si le re-hachage atteint une limite (nombre de flux ou paquets par flux)

Lors du retrait, chaque compartiment de hachage contenant des données est interrogé de manière tournante (round robin).

Avant linux-3.3, la longueur maximale de SFQ à la compilation est de 128 paquets, qui peuvent être répartis sur au plus 128 compartiments sur 1024 disponibles. En cas de dépassement, une suppression en fin de file (tail-drop) est effectuée sur le compartiment le plus plein, maintenant ainsi l'équité.

Après linux-3.3, la longueur maximale de SFQ est de 65535 paquets, et la limite du diviseur est de 65536. En cas de dépassement, une suppression en fin de file est effectuée sur le compartiment le plus plein, sauf si headdrop a été demandé.

PARAMÈTRES

divisor
Peut être utilisé pour définir une taille de table de hachage différente, disponible à partir du noyau 2.6.39. Le diviseur spécifié doit être une puissance de deux et ne peut pas être supérieur à 65536. Valeur par défaut : 1024.
limit
Limite supérieure de SFQ. Peut être utilisé pour réduire la longueur par défaut de 127 paquets. Après linux-3.3, elle peut être augmentée.
depth
Limite de paquets par flux (après linux-3.3). Par défaut à 127 et peut être abaissée.
perturb
Intervalle en secondes pour la perturbation de l'algorithme de file d'attente. Par défaut à 0, ce qui signifie qu'aucune perturbation ne se produit. Ne pas régler trop bas car chaque perturbation peut entraîner un réordonnancement ou des pertes de paquets. Valeur conseillée : 60. Cette valeur n'a aucun effet lorsque la classification de flux externe est utilisée. Il est préférable d'augmenter la valeur du diviseur pour réduire le risque de collisions de hachage.
quantum
Quantité d'octets qu'un flux est autorisé à retirer lors d'une tournée du processus de sélection tournante. Par défaut, c'est l'unité de transmission maximale (MTU) de l'interface, qui est également la valeur conseillée et la valeur minimale.
flows
Après linux-3.3, il est possible de modifier la limite par défaut des flux. Valeur par défaut : 127.
headdrop
Le comportement par défaut de SFQ est d'effectuer une suppression en fin de file des paquets d'un flux. Vous pouvez demander une suppression en tête (headdrop) à la place, car cela est connu pour fournir un meilleur retour aux flux TCP.
redflowlimit
Configure la limite dure sur la taille réelle de la file d'attente par flux SFQ en octets (pas la taille moyenne). 
redflowlimit configure la limite dure sur la taille réelle (pas la moyenne) de la file d'attente par flux SFQ en octets.
min
Taille moyenne de la file d'attente à partir de laquelle le marquage devient une possibilité. Par défaut : max /3.
max
À cette taille moyenne de file d'attente, la probabilité de marquage est maximale. Par défaut : redflowlimit /4.
probability
Probabilité maximale de marquage, spécifiée comme un nombre à virgule flottante de 0.0 à 1.0. Valeur par défaut : 0.02.
avpkt
Spécifié en octets. Utilisé avec burst pour déterminer la constante de temps pour les calculs de la taille moyenne de la file d'attente. Valeur par défaut : 1000.
burst
Utilisé pour déterminer la rapidité avec laquelle la taille moyenne de la file d'attente est influencée par la taille réelle de la file d'attente. 
Valeur par défaut :
(2 * min + max) / (3 * avpkt)
ecn
RED peut soit « marquer », soit « supprimer ». La notification explicite de congestion (ECN) permet à RED de notifier les hôtes distants que leur débit dépasse la bande passante disponible. Les hôtes non compatibles ECN ne peuvent être notifiés qu'en supprimant un paquet. Si ce paramètre est spécifié, les paquets indiquant que leurs hôtes prennent en charge ECN seront uniquement marqués et non supprimés, sauf si la taille de la file d'attente atteint depth paquets.
harddrop
Si la taille moyenne de la file d'attente du flux est supérieure à max octets, ce paramètre force une suppression au lieu d'un marquage ECN.

EXEMPLE & UTILISATION

Pour attacher à l'interface ppp0 :

# tc qdisc add dev ppp0 root sfq

Veuillez noter que SFQ, comme tous les qdiscs non-façonnant (work-conserving), n'est utile que s'il possède la file d'attente. C'est le cas lorsque la vitesse de la liaison est égale à la bande passante réellement disponible. Cela s'applique aux modems téléphoniques classiques, aux connexions ISDN et aux liaisons Ethernet directes non commutées.

La plupart du temps, les modems câble et les appareils DSL ne rentrent pas dans cette catégorie. Il en va de même lorsque vous êtes connecté à un commutateur et que vous essayez d'envoyer des données à un segment congestionné également connecté au commutateur.

Dans ce cas, la file d'attente effective ne réside pas dans Linux et n'est donc pas disponible pour la planification.

Intégrez SFQ dans un qdisc avec classes pour vous assurer qu'il possède la file d'attente.

Il est possible d'utiliser des classificateurs externes avec sfq, par exemple pour hacher le trafic basé uniquement sur les adresses IP source/destination :

# tc filter add ... flow hash keys src,dst perturb 30 divisor 1024

Notez que le diviseur donné doit correspondre à celui utilisé par sfq. Si vous avez modifié la valeur par défaut de sfq (1024), utilisez la même valeur pour le filtre de hachage de flux également.

Exemple de sfq avec le mode RED optionnel :

# tc qdisc add dev eth0 parent 1:1 handle 10: sfq limit 3000 flows 512 divisor 16384
redflowlimit 100000 min 8000 max 60000 probability 0.20 ecn headdrop

tc-sfq(8) — Linux manual pages

NOM

tc-sfq — File Queue Simple (SFQ)

SYNOPSIS

tc ... qdisc ... sfq [limit NUMBER] [quantum NUMBER] [perturb NUMBER] [flowid_hash TYPE] [ecn | noecn]

DESCRIPTION

SFQ est un algorithme de mise en file d'attente simple qui vise à fournir une bonne performance interactive pour une grande variété de charges de travail, sans nécessiter de configuration délicate.

Il distribue les paquets dans un ensemble de files d'attente (par défaut 1024). Le hachage est effectué sur l'adresse IP source et le port source (pour TCP et UDP) pour le trafic IPv4, et sur l'adresse IP source et le port source pour le trafic IPv6. Les paquets d'un même flux (défini par le hachage) sont mis en file d'attente dans la même file d'attente interne.

Une seule file d'attente est dépilée à la fois. L'algorithme sélectionne la prochaine file d'attente à dépiler en utilisant une approche d'horloge (ou d'incrémentation) qui se déplace à travers les files d'attente. Cela garantit que chaque flux obtient une part du débit, même s'il y a beaucoup de flux simultanés. Les files d'attente vides sont ignorées.

ALGORITHME

Le principe fondamental de SFQ est de maintenir une file d'attente active pour chaque flux identifié et de distribuer équitablement le temps de transmission entre ces flux actifs.

Le hachage est utilisé pour attribuer un flux à une file d'attente spécifique. Les paramètres par défaut utilisent un hachage basé sur les adresses IP source et de destination, ainsi que les ports source et de destination, ce qui est généralement suffisant pour les protocoles TCP et UDP.

L'algorithme tourne sur un ensemble de files d'attente, généralement de taille fixe (par défaut 1024). Un pointeur d'horloge avance à travers ces files d'attente. Lorsqu'un paquet arrive, il est haché pour déterminer sa file d'attente interne. S'il s'agit d'un nouveau flux, une nouvelle file d'attente lui est attribuée. Le paquet est ensuite ajouté à la fin de cette file d'attente.

Lorsqu'il est temps de transmettre un paquet, l'algorithme vérifie la file d'attente pointée par l'horloge. S'il y a des paquets dans cette file d'attente, un paquet est dépilé et transmis. L'horloge avance ensuite à la file d'attente suivante. Si la file d'attente est vide, l'horloge passe simplement à la file d'attente suivante sans transmettre de paquet.

Ce mécanisme de rotation garantit que même si un seul flux monopolise la bande passante, il ne peut le faire que pendant une courte période avant que l'horloge ne passe à une autre file d'attente, permettant ainsi à d'autres flux d'être transmis.

L'option perturb contrôle la fréquence à laquelle le hachage est mis à jour, ce qui peut aider à éviter les collisions de flux sur des réseaux à grande échelle.

PARAMÈTRES

limit NUMBER
Définit la taille maximale du tampon de paquets pour chaque file d'attente. Si une file d'attente dépasse cette limite, les paquets supplémentaires sont mis au rebut.
quantum NUMBER
Définit la quantité de données (en octets) qui peut être transmise à chaque fois qu'une file d'attente est dépilée. Ceci est utilisé pour ajuster la distribution de la bande passante.
perturb NUMBER
La fréquence (en secondes) à laquelle le hachage de flux est réinitialisé. Une valeur plus élevée signifie des collisions de flux moins fréquentes mais une configuration plus stable. Une valeur de 0 désactive la perturbation.
flowid_hash TYPE
Spécifie le type de fonction de hachage à utiliser pour l'identification des flux. Les types courants incluent default (utilisé par défaut), stable (moins de perturbations), dst (basé uniquement sur la destination), src (basé uniquement sur la source), etc. Consulter la documentation de tc pour les options disponibles.
ecn | noecn
Active ou désactive la prise en charge de l'Explicit Congestion Notification (ECN). Si ECN est activé, les paquets peuvent être marqués pour indiquer la congestion imminente, permettant ainsi aux expéditeurs de ralentir avant que la perte de paquets ne se produise.

EXEMPLE & UTILISATION

Ajouter une file d'attente SFQ à une interface :

tc qdisc add dev eth0 root sfq perturb 10s limit 100

Modifier une file d'attente SFQ existante :

tc qdisc change dev eth0 root sfq limit 200 quantum 1500

Supprimer une file d'attente SFQ :

tc qdisc del dev eth0 root sfq
