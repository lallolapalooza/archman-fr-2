NOM

tcplay — outil pour gérer les volumes TrueCrypt

SYNTAXE

tcplay -c -d périphérique [-g] [-z] [-w] [-a hash_pbkdf] [-b chiffrement] [-f fichier_clé_caché] [-k fichier_clé] [-x hash_pbkdf] [-y chiffrement]

tcplay -i -d périphérique [-e] [-p] [-f fichier_clé_caché] [-k fichier_clé] [-s périphérique_système] [--fde] [--use-backup] [--use-hdr-file fichier_hdr] [--use-hidden-hdr-file fichier_hdr]

tcplay -j mappage

tcplay -m mappage -d périphérique [-e] [-p] [-f fichier_clé_caché] [-k fichier_clé] [-s périphérique_système] [-t] [--fde] [--use-backup] [--use-hdr-file fichier_hdr] [--use-hidden-hdr-file fichier_hdr]

tcplay --modify -d périphérique [-k fichier_clé] [--new-keyfile nouveau_fichier_clé] [--new-pbkdf-prf hash_pbkdf] [-s périphérique_système] [--fde] [--use-backup] [--use-hdr-file fichier_hdr] [--use-hidden-hdr-file fichier_hdr] [--save-hdr-backup fichier_hdr] [-w]

tcplay --modify -d périphérique [-k fichier_clé] --restore-from-backup-hdr [-w]

tcplay -u mappage

tcplay -h | -v

DESCRIPTION

L'utilitaire tcplay fournit un support complet pour la création et l'ouverture/le mappage de volumes TrueCrypt. Il prend en charge les commandes suivantes, chacune avec un ensemble d'options détaillées ci-dessous :

-c, --create
Crée un nouveau volume TrueCrypt crypté sur le périphérique spécifié par --device.
-h, --help
Affiche le message d'aide et quitte.
-i, --info
Affiche les informations sur le périphérique crypté spécifié par --device.
-j mappage, --info-mapped=mappage
Affiche les informations sur le volume tcplay mappé spécifié par mappage. Les informations telles que le CRC de la clé et le PRF PBKDF2 ne sont pas disponibles via cette commande.
--modify
Modifie l'en-tête du volume. Ce mode permet de changer le mot de passe, les fichiers clés, le PRF PBKDF2 ainsi que de restaurer à partir d'un en-tête de sauvegarde.
-m mappage, --map=mappage
Mappe le volume TrueCrypt crypté sur le périphérique spécifié par --device comme un mappage dm(4) nommé mappage. L'argument mappage ne doit pas contenir d'espaces ni de caractères spéciaux.
-u mappage, --unmap=mappage
Supprime (démappe) le mappage dm(4) spécifié par mappage ainsi que tous les mappages en cascade associés. Si vous avez mappé un volume en utilisant le chiffrement de disque complet et créé des mappages pour des partitions individuelles à l'aide de kpartx(8), vous devez les supprimer avant de démapper le volume.
-v, --version
Affiche le message de version et quitte.

Options communes à toutes les commandes :

-d périphérique, --device=périphérique
Spécifie le périphérique disque sur lequel réside/résidera le volume TrueCrypt. Cette option est obligatoire pour toutes les commandes.
-f fichier_clé_caché, --keyfile-hidden=fichier_clé_caché
Spécifie un fichier clé à utiliser en plus du mot de passe lors de la création d'un volume caché ou lors de la protection d'un volume caché lors du mappage ou de la requête du volume extérieur. Si vous avez seulement l'intention de mapper un volume caché, l'option --keyfile doit être utilisée. Cette option peut apparaître plusieurs fois ; si c'est le cas, plusieurs fichiers clés seront utilisés. Cette option n'est pas valide en mode --modify.
-k fichier_clé, --keyfile=fichier_clé
Spécifie un fichier clé à utiliser en plus du mot de passe. Cette option peut apparaître plusieurs fois ; si c'est le cas, plusieurs fichiers clés seront utilisés.

Options supplémentaires pour la commande --create :

-a hash_pbkdf, --pbkdf-prf=hash_pbkdf
Spécifie quel algorithme de hachage utiliser pour la dérivation de mot de passe PBKDF2. Pour voir quels algorithmes sont supportés, spécifiez --pbkdf-prf=help.
-b chiffrement, --cipher=chiffrement
Spécifie quel algorithme de chiffrement ou cascade de chiffrements utiliser pour crypter le nouveau volume. Pour voir quels algorithmes sont supportés, spécifiez --cipher=help.
-g, --hidden
Spécifie que le volume nouvellement créé contiendra un volume caché. Les fichiers clés appliqués au mot de passe pour le volume caché sont ceux spécifiés par --keyfile-hidden. L'utilisateur sera invité à entrer la taille du volume caché
interagir avec.
-w, --weak-keys
Utilise urandom(4) pour le matériel de clé au lieu d'une source d'entropie forte. C'est généralement une très mauvaise idée et ne devrait être utilisé que pour les tests.
-x pbkdf_hash, --pbkdf-prf-hidden=pbkdf_hash
Spécifie quel algorithme de hachage utiliser pour la dérivation de mot de passe PBKDF2 pour le volume caché. Valide uniquement en conjonction avec --hidden. Si aucun algorithme n'est spécifié, le même que pour le volume externe sera utilisé. Pour voir quels algorithmes sont pris en charge, spécifiez --pbkdf-prf-hidden=help.
-y cipher, --cipher-hidden=cipher
Spécifie quel algorithme de chiffrement ou cascade de chiffrements utiliser pour chiffrer le volume caché sur le nouveau volume TrueCrypt. Valide uniquement en conjonction avec --hidden. Si aucun chiffrement n'est spécifié, le même que pour le volume externe sera utilisé. Pour voir quels algorithmes sont pris en charge, spécifiez --cipher-hidden=help.
-z, --insecure-erase
Ignore l'effacement sécurisé du disque. Utilisez cette option avec précaution car elle présente un risque de sécurité !

Options supplémentaires pour les commandes --info, --map et --modify :

-e, --protect-hidden
Spécifie qu'un volume externe sera interrogé ou mappé, mais sa taille signalée sera ajustée en conséquence à la taille du volume caché qu'il contient. Les deux, la phrase de passe et les fichiers clés du volume caché et du volume externe seront requis. Cette option s'applique uniquement aux commandes --info et --map.
-p, --prompt-passphrase
Cette option amène tcplay à demander immédiatement une phrase de passe, même si un fichier clé est fourni. Normalement, si un fichier clé est fourni, tcplay tentera d'abord de déverrouiller le volume en utilisant uniquement le fichier clé, et ne demandera une phrase de passe que si cette première tentative de déverrouillage échoue. Cependant, comme une tentative de déverrouillage échouée peut prendre un temps non négligeable, spécifier cette option peut réduire le temps total de déverrouillage si une phrase de passe et un fichier clé sont requis. Cette option n'a de sens que si -k ou -f sont utilisés.
-s system_device, --system-encryption=system_device
Cette option est requise si vous tentez d'accéder à un périphérique qui utilise le chiffrement du système, par exemple une partition système Windows chiffrée. Elle ne s'applique pas aux disques utilisant le chiffrement de disque complet. L'option --device pointera vers la partition chiffrée réelle, tandis que l'argument system_device pointera vers le périphérique parent (c'est-à-dire le disque physique sous-jacent) de la partition chiffrée.
--fde
Cette option est destinée à être utilisée avec des disques utilisant le chiffrement de disque complet (FDE). Lorsqu'un disque est chiffré à l'aide du FDE de TrueCrypt, le disque entier est chiffré à l'exception des 63 premiers secteurs. L'option --device doit pointer vers le périphérique de disque entier, et non vers une partition particulière. Le mappage résultant couvrira le disque entier et n'apparaîtra pas comme des partitions distinctes. Pour accéder aux partitions individuelles après le mappage, kpartx(8) peut être utilisé.
--use-backup
Cette option est destinée à être utilisée lorsque les en-têtes primaires d'un volume ont été corrompus. Cette option forcera tcplay à utiliser les en-têtes de sauvegarde, situés à la fin du périphérique, pour accéder au volume.

Options supplémentaires uniquement pour la commande --map :

-t, --allow-trim
Cette option active le support TRIM (discard) sur le volume mappé.

Options supplémentaires uniquement pour la commande --modify :

--new-pbkdf-prf=pbkdf_hash
Spécifie quel algorithme de hachage utiliser pour la dérivation de mot de passe PBKDF2 lors de la ré-écriture de l'en-tête du volume. Si cette option n'est pas spécifiée, l'en-tête ré-écrit utilisera le PRF actuel. Pour voir quels algorithmes sont pris en charge, spécifiez --pbkdf-prf=help.
--new-keyfile=keyfile
Spécifie un fichier clé keyfile à utiliser en plus de la nouvelle phrase de passe lors de la ré-écriture de l'en-tête du volume. Cette option peut apparaître plusieurs fois ; si c'est le cas, plusieurs fichiers clés seront utilisés.
--restore-from-backup-hdr
Si cette option est spécifiée, ni --new-pbkdf-prf ni --new-keyfile ne devraient être spécifiés. Cette option implique --use-backup. Utilisez cette option pour restaurer les en-têtes du volume à partir de l'en-tête de sauvegarde.

Envoi d'un signal SIGINFO ou SIGUSR1 à un processus tcplay en cours d'exécution lui fait afficher la progression sur des tâches plus lentes telles que la collecte d'entropie ou l'effacement du volume.

NOTES

TrueCrypt limite les phrases de passe à 64 caractères (y compris le caractère nul de fin). Pour être compatible avec lui, tcplay fait de même. Toutes les phrases de passe (à l'exclusion des fichiers clés) sont tronquées à 64 caractères. De même, les fichiers clés sont limités à une taille de 1 Mo, mais jusqu'à 256 fichiers clés peuvent être utilisés.

DENIABILITÉ PLAUSIBLE

tcplay offre une déniabilité plausible. Les volumes cachés sont créés à l'intérieur d'un volume externe. Quel volume est accédé dépend uniquement de la phrase de passe et du(des) fichier(s) clé(s) utilisé(s). Si la phrase de passe et les fichiers clés pour le volume externe sont spécifiés, aucune information sur l'existence du volume caché n'est exposée. Sans connaissance de la phrase de passe et du(des) fichier(s) clé(s) du volume caché, son existence reste inconnue. Le volume caché peut être protégé lors du mappage du volume externe en utilisant l'option --protect-hidden et en spécifiant la phrase de passe et les fichiers clés pour les volumes externe et caché.

SUPPORT VERACRYPT

tcplay offre un support à la fois pour le TrueCrypt hérité et pour VeraCrypt. Lors de la création d'un nouveau volume, le PRF PBKDF2 sélectionné détermine si le volume utilisera le format TrueCrypt ou VeraCrypt. Les formats sont identiques à l'exception des tours des fonctions de dérivation de clé, ainsi que des champs de signature de volume et de minver dans l'en-tête. La conversion des volumes d'un format à l'autre à l'aide de tcplay est simplement une question d'utilisation de l'option --modify en spécifiant un hachage PRF PBKDF2 correspondant au format cible prévu avec l'argument --new-pbkdf-prf.

Les PRF PBKDF2 suffixés par -VC sont des PRF VeraCrypt, tandis que tous les autres sont des PRF TrueCrypt hérités. Par défaut, les nouveaux volumes sont créés avec un PRF VeraCrypt pour offrir une meilleure sécurité.

NOTE : Les tentatives de déverrouillage échouées, même pour les volumes TrueCrypt hérités, prennent maintenant beaucoup plus de temps qu'auparavant, car tcplay parcourra tous les PRF, y compris les PRF VeraCrypt avec un nombre d'itérations PRF beaucoup plus élevé. Les tentatives réussies devraient toujours prendre le même temps qu'auparavant, car les paramètres PRF hérités sont d'abord essayés. Une exception notable est si un fichier clé et une phrase de passe sont tous deux requis. Normalement, tcplay tenterait d'abord un déverrouillage avec uniquement le fichier clé, et ne demanderait une phrase de passe qu'après l'échec de cette tentative. S'il est connu à l'avance que le fichier clé et la phrase de passe sont tous deux requis pour déverrouiller un volume, l'option -p pour --info et --map peut plus que diviser par deux le temps nécessaire pour déverrouiller le volume.

EXEMPLES

Créez un nouveau volume TrueCrypt sur /dev/vn0 en utilisant la cascade de chiffrements AES et Twofish et l'algorithme de hachage Whirlpool pour la dérivation de mot de passe PBKDF2 et deux fichiers clés, one.key et two.key :

tcplay --create --device=/dev/vn0 --cipher=TWOFISH-256-XTS,AES-256-XTS --pbkdf-prf=whirlpool --keyfile=one.key --keyfile=two.key

Mappe le volume externe sur le volume TrueCrypt sur /dev/vn0 sous le nom truecrypt1, mais protège le volume caché, en utilisant le fichier clé hidden.key, contre l'écrasement :

tcplay --map=truecrypt1 --device=/dev/vn0 --protect-hidden --keyfile-hidden=hidden.key

Mappe le volume caché sur le volume TrueCrypt sur /dev/vn0 sous le nom truecrypt2, en utilisant le fichier clé hidden.key :

NAME

tcplay — map and unmap volumes

SYNOPSIS

tcplay --create [--hidden] [--device=device] [--cipher=cipher] [--keyfile=keyfile] [--protect-hidden] [--cipher-hidden=cipher] [--keyfile-hidden=keyfile] [--pbkdf-prf=prf] [--pbkdf-prf-hidden=prf] [--password-file=password-file] [--password-file-hidden=password-file] [--length=length] [--length-hidden=length] [--mount-point=mount-point] [--fs-type=fs-type] [--mount-options=mount-options] [--volume-type=volume-type] [--fde] [--block-size=block-size] [--pages-per-block=pages-per-block] [--hash=hash] [--hash-hidden=hash] [--kdf=kdf] [--kdf-hidden=kdf] [--kdf-iterations=kdf-iterations] [--kdf-iterations-hidden=kdf-iterations] [--kdf-salt-size=kdf-salt-size] [--kdf-salt-size-hidden=kdf-salt-size] [--kdf-salt-file=kdf-salt-file] [--kdf-salt-file-hidden=kdf-salt-file] [--block-verify] [--block-verify-hidden]

tcplay --map [--fde] [--device=device] [--keyfile=keyfile] [--password-file=password-file] [--mount-point=mount-point] [--fs-type=fs-type] [--mount-options=mount-options] [--protect-hidden] [--map=name]

tcplay --unmap [--device=device]

tcplay --modify [--device=device] [--restore-from-backup-hdr] [--save-hdr-backup=backup-header-file] [-use-hdr-file=header-file] [-use-hidden-hdr-file=hidden-header-file]

DESCRIPTION

tcplay is a command-line utility to create, map, and unmap encrypted volumes. It supports volumes created by the TrueCrypt and VeraCrypt disk encryption systems.

The following options are supported:

  • --create: Create a new encrypted volume.
  • --map: Map an existing encrypted volume.
  • --unmap: Unmap a mapped encrypted volume.
  • --modify: Modify an existing encrypted volume (e.g., restore or save headers).
  • --hidden: Create a hidden volume.
  • --device: Specify the device or file to use for the volume.
  • --cipher: Specify the cipher to use for the volume.
  • --keyfile: Specify a keyfile to use for the volume.
  • --protect-hidden: Protect the hidden volume with a password and keyfile.
  • --cipher-hidden: Specify the cipher to use for the hidden volume.
  • --keyfile-hidden: Specify a keyfile to use for the hidden volume.
  • --pbkdf-prf: Specify the pseudo-random function to use for the PBKDF.
  • --pbkdf-prf-hidden: Specify the pseudo-random function to use for the hidden volume's PBKDF.
  • --password-file: Specify a file containing the password.
  • --password-file-hidden: Specify a file containing the password for the hidden volume.
  • --length: Specify the size of the volume.
  • --length-hidden: Specify the size of the hidden volume.
  • --mount-point: Specify the mount point for the mapped volume.
  • --fs-type: Specify the filesystem type.
  • --mount-options: Specify mount options.
  • --volume-type: Specify the volume type (e.g., normal, hidden).
  • --fde: Use full disk encryption.
  • --block-size: Specify the block size.
  • --pages-per-block: Specify the number of pages per block.
  • --hash: Specify the hash algorithm.
  • --hash-hidden: Specify the hash algorithm for the hidden volume.
  • --kdf: Specify the key derivation function.
  • --kdf-hidden: Specify the key derivation function for the hidden volume.
  • --kdf-iterations: Specify the number of iterations for the KDF.
  • --kdf-iterations-hidden: Specify the number of iterations for the hidden volume's KDF.
  • --kdf-salt-size: Specify the salt size for the KDF.
  • --kdf-salt-size-hidden: Specify the salt size for the hidden volume's KDF.
  • --kdf-salt-file: Specify a file containing the salt for the KDF.
  • --kdf-salt-file-hidden: Specify a file containing the salt for the hidden volume's KDF.
  • --block-verify: Enable block verification.
  • --block-verify-hidden: Enable block verification for the hidden volume.
  • --restore-from-backup-hdr: Restore the main volume header from the backup header.
  • --save-hdr-backup: Save a backup copy of the header.
  • -use-hdr-file: Use a header file for restoration.
  • -use-hidden-hdr-file: Use a hidden header file for restoration.

NOTES

When mapping a volume, tcplay creates a device-mapper target. The device name for the mapped volume is /dev/mapper/<name>, where <name> is the name specified with the --map option.

The --device option can specify either a block device (e.g., /dev/sda1) or a regular file.

The --keyfile option can be specified multiple times to use multiple keyfiles.

When creating a volume, tcplay will prompt for passphrases and other necessary information if they are not provided via options.

The --fde option is used for full disk encryption. In this case, the --device option should specify the entire disk (e.g., /dev/sda).

PLAUSIBLE DENIABILITY

A hidden volume whose existence can be plausibly denied can be created using the --hidden option during volume creation. The hidden volume resides within the outer volume, and its existence is concealed by using different credentials (passphrase and/or keyfiles) than the outer volume.

To access the hidden volume, the --protect-hidden option must be used when mapping, along with the credentials for the hidden volume.

VERACRYPT SUPPORT

tcplay supports volumes created with VeraCrypt, including features like XTS mode ciphers and PBKDF2 key derivation.

EXAMPLES

Create a new encrypted file container named myvolume.tc on Linux:

tcplay --create --device=myvolume.tc --cipher=AES-256-XTS --keyfile=my.key

Map the encrypted volume myvolume.tc to the device truecrypt2 on Linux:

tcplay --map=truecrypt2 --device=myvolume.tc --keyfile=my.key

Map and mount the volume in the file secvol on Linux:

losetup /dev/loop1 secvol
tcplay --map=secv --device=/dev/loop1
mount /dev/mapper/secv /mnt

Similarly on DragonFly:

vnconfig vn1 secvol
tcplay --map=secv --device=/dev/vn1
mount /dev/mapper/secv /mnt

Unmapping the volume truecrypt2 on both Linux and DragonFly after unmounting:

dmsetup remove truecrypt2

Or alternatively:

tcplay --unmap=truecrypt2

A hidden volume whose existance can be plausibly denied and its outer volume can for example be created with

tcplay --create --hidden --device=/dev/loop0 --cipher=TWOFISH-256-XTS,AES-256-XTS --pbkdf-prf=whirlpool --keyfile=one.key --cipher-hidden=AES-256-XTS --pbkdf-prf-hidden=whirlpool --keyfile-hidden=hidden.key

tcplay will prompt the user for the passphrase for both the outer and hidden volume as well as the size of the hidden volume inside the outer volume. The hidden volume will be created inside the area spanned by the outer volume. The hidden volume can optionally use a different cipher and prf function as specified by the --cipher-hidden and --pbkdf-prf-hidden options. Which volume is later accessed depends only on which passphrase and keyfile(s) are being used, so that the existance of the hidden volume remains unknown without knowledge of the passphrase and keyfile it is protected by since it is located within the outer volume. To map the outer volume without potentially damaging the hidden volume, the passphrase and keyfile(s) of the hidden volume must be known and provided alongside the --protect-hidden option.

A disk encrypted using full disk encryption can be mapped using

tcplay --map=tcplay_sdb --device=/dev/sdb --fde

To access individual partitions on the now mapped disk, the following command will generate mappings for each individual partition on the encrypted disk:

kpartx --av /dev/mapper/tcplay_sdb

To restore the main volume header from the backup header, the following command can be used:

tcplay --modify --device=/dev/sdb --restore-from-backup-hdr

As with most other commands, which header is saved (used as source) depends on the passphrase and keyfiles used.

To save a backup copy of a header, the following command can be used:

tcplay --modify --device=/dev/sdb --save-hdr-backup=/tmp/sdb_backup_header.hdr

As with most other commands, which header is saved (used as source) depends on the passphrase and keyfiles used.

To restore a header from a backup header file, the following command can be used:

tcplay --modify -use-hdr-file=/tmp/sdb_backup_header.hdr

Similarly, to restore a hidden header from a backup header file:

tcplay --modify -use-hidden-hdr-file=/tmp/sdb_backup_hidden_header.hdr

Which header is used as the source of the operation will still depend on the passphrase and keyfiles used. Even if you use the --use-hidden-hdr-file option, if you specify the passphrase and keyfiles for the main header, the main header will be used instead.
