NOM

tcldot - manipulation de graphes en Tcl

SYNTAXE

#!/usr/local/bin/tclsh
package require Tcldot

UTILISATION

Nécessite les facilités de chargement dynamique de tcl7.6 ou supérieur.

INTRODUCTION

tcldot est une extension chargée dynamiquement pour tcl qui intègre les facilités de graphes dirigés de dot(1) et les facilités de graphes non dirigés de neato(1) dans tcl, et fournit un ensemble de commandes pour contrôler ces facilités. tcldot transforme dot et neato d'outils de traitement par lots en un ensemble de facilités de manipulation de graphes interprétées et, si nécessaire, interactives.

COMMANDES

tcldot ajoute initialement seulement trois commandes à tcl, à savoir dotnew, dotread, et dotstring. Ces commandes renvoient un handle pour le graphe qui vient d'être créé et ce handle peut ensuite être utilisé comme une commande pour des actions ultérieures sur le graphe.

Toutes les autres « commandes » sont de la forme :

handle <méthode> paramètres

Plusieurs des méthodes renvoient des handles supplémentaires de graphes, de nœuds ou d'arêtes, qui sont eux-mêmes enregistrés comme des commandes.

Les méthodes sont décrites en détail ci-dessous, mais en résumé :

Les méthodes de graphe sont :

addedge, addnode, addsubgraph, countedges, countnodes, layout, listattributes, listedgeattributes, listnodeattributes, listedges, listnodes, listnodesrev, listsubgraphs, render, rendergd, queryattributes, queryedgeattributes, querynodeattributes, queryattributevalues, queryedgeattributevalues, querynodeattributevalues, setattributes, setedgeattributes, setnodeattributes, showname, write.

Les méthodes de nœud sont :

addedge, listattributes, listedges, listinedges, listoutedges, queryattributes, queryattributevalues, setattributes, showname.

Les méthodes d'arête sont :

delete, listattributes, listnodes, queryattributes, queryattributevalues, setattributes, showname.
dotnew typeGraphe ?nomAttribut valeurAttribut? ?...?

crée un nouveau graphe vide et retourne son handleGraphe.

typeGraphe peut être n'importe lequel supporté par dot(1) à savoir : "graph," "digraph," "graphstrict," ou "digraphstrict." (Dans les digraphs, les arêtes ont une direction de la queue à la tête. Les graphes ou digraphs « stricts » réduisent les arêtes multiples entre les mêmes paires de nœuds à une seule arête.)

Après le paramètre obligatoire typeGraphe, la commande dotnew acceptera un nombre arbitraire de paires nom/valeur d'attributs pour le graphe. Certains attributs de graphe spéciaux et leurs valeurs permises sont décrits dans dot(1), mais le programmeur peut inventer et assigner arbitrairement des valeurs à des attributs supplémentaires au-delà de ceux-ci. Dans dot, le nom de l'attribut est séparé de la valeur par un caractère « = ». Dans tcldot, le « = » a été remplacé par un « » (espace) pour être plus cohérent avec la syntaxe tcl. par exemple

    set g [dotnew digraph rankdir LR]
dotread handleFichier

lit une description du langage dot d'un graphe à partir d'un fichier précédemment ouvert identifié par le handleFichier. La commande retourne le handleGraphe du graphe nouvellement lu. par exemple

    set f [open test.dot r]
    set g [dotread $f]
dotstring chaine

lit une description du langage dot d'un graphe à partir d'une chaîne Tcl ; la commande retourne le handleGraphe du graphe nouvellement lu. par exemple

    set g [dotstring $chaineSyntaxeDot]
handleGraphe addnode ?nomNœud? ?nomAttribut valeurAttribut? ?...?

crée un nouveau nœud dans le graphe dont le handle est handleGraphe et retourne son handleNœud. Le handle d'un nœud est une chaîne comme : « node0 » où la valeur entière est différente pour chaque nœud. Il peut y avoir un nombre arbitraire de paires nom/valeur d'attributs pour le nœud. Certains attributs de nœud spéciaux et leurs valeurs permises sont décrits dans dot(1), mais le programmeur peut inventer et assigner arbitrairement des valeurs à des attributs supplémentaires au-delà de ceux-ci. par exemple

    set n [$g addnode "N" label "Nœud\nSupérieur" shape triangle eggs easyover]
Une cause possible de confusion dans tcldot est la distinction entre les handles, les noms, les étiquettes et les variables. La distinction réside principalement dans celui qui les possède. Les handles sont possédés par tcldot et sont garantis d'être uniques au sein d'une session d'interpréteur. Typiquement, les handles sont assignés à des variables, comme « n » ci-dessus, pour la manipulation au sein d'un script tcl. Les variables sont possédées par le programmeur. Les noms sont possédés par l'application qui utilise le graphe, généralement les noms sont importants lors de la lecture d'un graphe à partir d'un programme ou fichier externe. Les étiquettes sont le texte affiché avec le nœud (ou l'arête) lorsque le graphe est affiché ; les étiquettes sont significatives pour le lecteur du graphe. Seuls les handles et les variables sont essentiels à la capacité de tcldot de manipuler des graphes abstraits. Si un nom n'est pas spécifié, il prend par défaut la représentation sous forme de chaîne du handle ; si une étiquette n'est pas spécifiée, elle prend par défaut le nom.
handleGraphe addedge nœudQueue nœudTête ?nomAttribut valeurAttribut? ?...?

crée une nouvelle arête dans le graphe dont le handle est handleGraphe et retourne son handleArête. nœudQueue et nœudTête peuvent être spécifiés soit par leur handleNœud soit par leur nomNœud. par exemple

    set n [$g addnode]
    set m [$g addnode]
    $g addedge $n $m label "NM"
    $g addnode N
    $g addnode M
    $g addedge N M label "NM"
L'argument est reconnu comme un handle si possible et il est donc préférable d'éviter les noms comme « node6 » pour les nœuds. S'il y a un risque de conflit, utilisez findnode pour traduire explicitement des noms en handles. par exemple : 
    $g addnode "node6"
    $g addnode "node99"
    $g addedge [$g findnode "node6"] [$g findnode "node99"]
Il peut y avoir un nombre arbitraire de paires nom/valeur d'attributs pour l'arête. Certains attributs d'arête spéciaux et leurs valeurs permises sont décrits dans dot(1), mais le programmeur peut inventer et assigner arbitrairement des valeurs à des attributs supplémentaires au-delà de ceux-ci.
handleGraphe addsubgraph ?nomGraphe? ?nomAttribut valeurAttribut? ?...?

crée un nouveau sous-graphe dans le graphe et retourne son handleGraphe. Si le nomGraphe est omis, le nom du sous-graphe prend par défaut celui de son handleGraphe. Il peut y avoir un nombre arbitraire de paires nom/valeur d'attributs pour le sous-graphe. Certains attributs de graphe spéciaux et leurs valeurs permises sont décrits dans dot(1), mais le programmeur peut inventer et assigner arbitrairement des valeurs à des attributs supplémentaires au-delà de ceux-ci. par exemple

    set sg [$g addsubgraph dinglefactor 6]
Les clusters, tels que décrits dans dot(1), sont créés en donnant au sous-graphe un nom commençant par la chaîne : « cluster ». Les clusters peuvent être étiquetés en utilisant l'attribut label. par exemple 
    set cg [$g addsubgraph cluster_A label dongle dinglefactor 6]
handleNœud addedge nœudTête ?nomAttribut valeurAttribut? ?...?

crée une nouvelle arête du nœud de queue identifié par le handleNœud vers le nœudTête qui peut être spécifié soit par son handleNœud soit par son nomNœud (avec préférence pour la reconnaissance de l'argument comme handle). Le graphe dans lequel ceci est dessiné est le graphe dont les deux nœuds sont membres. Il peut y avoir un nombre arbitraire de paires nom/valeur d'attributs pour l'arête. graphHandle delete
nodeHandle delete
edgeHandle delete

Supprime toutes les structures de données associées au graphe, au nœud ou à l'arête du stockage interne de l'interpréteur. La suppression d'un nœud entraîne également la suppression de toutes les arêtes qui en dépendent. La suppression d'un graphe entraîne également la suppression de tous les nœuds et sous-graphes à l'intérieur de ce graphe (et donc de toutes les arêtes). Le retour de ces commandes de suppression est une chaîne nulle.

graphHandle countnodes
graphHandle countedges

Retourne le nombre de nœuds ou d'arêtes dans le graphe.

graphHandle listedges
graphHandle listnodes
graphHandle listnodesrev
graphHandle listsubgraphs
nodeHandle listedges
nodeHandle listinedges
nodeHandle listoutedges
edgeHandle listnodes

Chacun retourne une liste de handles de graphes, de nœuds ou d'arêtes, selon le cas.

graphHandle findnode nodeName
graphHandle findedge tailnodeName headNodeName
nodeHandle findedge nodeName

Chacun retourne le handle de l'élément s'il est trouvé, ou une erreur si aucun n'est trouvé. Pour les graphes non stricts où il existe plusieurs arêtes entre deux nœuds, findedge retournera une arête arbitraire de l'ensemble.

graphHandle showname
nodeHandle showname
edgeHandle showname

Chacun retourne le nom de l'élément. Les noms d'arêtes sont de la forme : "a->b" où "a" et "b" sont les noms des nœuds et le connecteur "->" indique la direction de l'arête de la queue vers la tête. Dans les graphes non dirigés, le connecteur "--" est utilisé.

graphHandle setnodeattributes attributeName attributeValue ?...?
graphHandle setedgeattributes attributeName attributeValue ?...?

Définit un ou plusieurs noms/valeurs d'attributs par défaut qui s'appliqueront à tous les nœuds (arêtes) sauf s'ils sont remplacés par des sous-graphes ou des attributs par nœud (par arête).

graphHandle listnodeattributes
graphHandle listedgeattributes

Retourne une liste de noms d'attributs.

graphHandle querynodeattributes attributeName ?...?
graphHandle queryedgeattributes attributeName ?...?

Retourne une liste de valeurs d'attributs par défaut, une valeur pour chacun des noms d'attributs fournis avec la commande.

graphHandle querynodeattributes attributeName ?...?
graphHandle queryedgeattributes attributeName ?...?

Retourne une liste de paires nom d'attribut et valeur d'attribut par défaut, une paire pour chacun des noms d'attributs fournis avec la commande.

graphHandle setattributes attributeName attributeValue ?...?
nodeHandle setattributes attributeName attributeValue ?...?
edgeHandle setattributes attributeName attributeValue ?...?

Définit une ou plusieurs paires nom d'attribut/valeur d'attribut pour une instance spécifique de graphe, de nœud ou d'arête.

graphHandle listattributes
nodeHandle listattributes
edgeHandle listattributes

Retourne une liste de noms d'attributs (les valeurs d'attributs sont fournies par queryattribute.

graphHandle queryattributes attributeName ?...?
nodeHandle queryattributes attributeName ?...?
edgeHandle queryattributes attributeName ?...?

Retourne une liste de valeurs d'attributs, une valeur pour chacun des noms d'attributs fournis avec la commande.

graphHandle queryattributevalues attributeName ?...?
nodeHandle queryattributevalues attributeName ?...?
edgeHandle queryattributevalues attributeName ?...?

Retourne une liste de paires nom d'attribut et valeur d'attribut, une valeur pour chacun des noms d'attributs fournis avec la commande.

graphHandle layout ?dot|neato|circo|twopi|fdp|nop?

Ajoute des informations de disposition au graphe. Cette commande prend un graphe abstrait et lui ajoute des informations de forme et de position selon les règles du moteur de disposition pour une disposition agréable à l'œil. Si le moteur de disposition n'est pas spécifié, il prend par défaut dot pour les graphes dirigés, et neato sinon. Si le moteur nop est spécifié, les informations de disposition du graphe d'entrée sont utilisées. Le résultat de la disposition est stocké sous forme de paires d'attributs nom/valeur supplémentaires dans le graphe, les nœuds et les arêtes. Ces attributs sont destinés à être interprétés par les commandes write ou render ultérieures.

graphHandle write fileHandle format ?dot|neato|circo|twopi|fdp|nop?

Écrit un graphe dans le fichier ouvert représenté par fileHandle dans un format spécifique. Les formats possibles sont : "ps" "mif" "plain" "dot" "gif" "ismap" Si la disposition n'a pas encore été effectuée, elle le sera dans le cadre de cette opération en utilisant les mêmes règles de sélection du moteur de disposition que pour la commande layout.

graphHandle rendergd gdHandle

Génère un rendu d'un graphe vers une structure gifImage nouvelle ou existante (voir gdTcl(1) ). Retourne le gdHandle de l'image. Si la disposition n'a pas encore été effectuée, elle le sera dans le cadre de cette opération en utilisant les mêmes règles de sélection du moteur de disposition que pour la commande layout.

graphHandle render ?canvas ?dot|neato|circo|twopi|fdp|nop??

Si aucun argument canvas n'est fourni, render retourne une chaîne de commandes qui, une fois évaluées, rendent le graphe dans un canevas Tk dont le canvasHandle est disponible dans la variable $c

Si un argument canvas est fourni, render produit un ensemble de commandes pour ce canvas au lieu de $c.

Si la disposition n'a pas encore été effectuée, elle le sera dans le cadre de cette opération en utilisant les mêmes règles de sélection du moteur de disposition que pour la commande layout.

    #!/usr/local/bin/wish
    package require Tcldot
    set c [canvas .c]
    pack $c
    set g [dotnew digraph rankdir LR]
    $g setnodeattribute style filled color white
    [$g addnode Hello] addedge [$g addnode World!]
    $g layout
    if {[info exists debug]} {
        puts [$g render]         ;# voir ce que render produit
    }
    eval [$g render]

Render génère une série de commandes de canevas pour chaque élément du graphe. Par exemple, un nœud est généralement constitué de deux éléments sur le canevas, l'un pour la forme et l'autre pour l'étiquette. Les éléments du canevas sont automatiquement étiquetés (voir canvas(n) ) par les commandes générées par render. Les étiquettes prennent l'une des deux formes : les éléments de texte sont étiquetés avec 0<handle> et les formes et les lignes sont rendues avec 1<handle>.

L'étiquetage peut être utilisé pour reconnaître quand un utilisateur souhaite interagir avec un graphe
