INTRODUCTION

Tcl inclut une bibliothèque de procédures Tcl pour les fonctions couramment nécessaires. Les procédures définies dans la bibliothèque Tcl sont génériques et adaptées à une utilisation par de nombreuses applications différentes. L'emplacement de la bibliothèque Tcl est retourné par la commande info library. En plus de la bibliothèque Tcl, chaque application dispose normalement de sa propre bibliothèque de procédures de support ; l'emplacement de cette bibliothèque est normalement donné par la valeur de la variable globale $app_library, où app est le nom de l'application. Par exemple, l'emplacement de la bibliothèque Tk est conservé dans la variable tk_library.

Pour accéder aux procédures de la bibliothèque Tcl, une application doit sourcer le fichier init.tcl dans la bibliothèque, par exemple avec la commande Tcl

source [file join [info library] init.tcl]

Si la procédure de bibliothèque Tcl_Init est appelée depuis la procédure Tcl_AppInit d'une application, cela se fait automatiquement. Le code dans init.tcl définira la procédure unknown et organisera le chargement des autres procédures à la demande en utilisant le mécanisme de chargement automatique défini ci-dessous.

PROCÉDURES DE COMMANDES

Les procédures suivantes sont fournies dans la bibliothèque Tcl :

auto_execok cmd
Détermine s'il existe un fichier exécutable ou une commande intégrée au shell du nom cmd. Si c'est le cas, il retourne une liste d'arguments à passer à exec pour exécuter le fichier exécutable ou la commande intégrée nommée par cmd. Sinon, il retourne une chaîne vide. Cette commande examine les répertoires dans le chemin de recherche actuel (donné par la variable d'environnement PATH) pour trouver un fichier exécutable nommé cmd. Sur les plateformes Windows, la recherche est étendue avec les mêmes répertoires et extensions de fichiers que ceux utilisés par exec. Auto_execok mémorise les informations sur les recherches précédentes dans un tableau nommé auto_execs ; cela évite la recherche dans le chemin lors des appels ultérieurs pour le même cmd. La commande auto_reset peut être utilisée pour forcer auto_execok à oublier ses informations mises en cache.
auto_import pattern
Auto_import est appelée pendant namespace import pour voir si les commandes importées spécifiées par pattern résident dans une bibliothèque chargée automatiquement. Si c'est le cas, les commandes sont chargées de manière à être disponibles pour l'interpréteur afin de créer les liens d'importation. Si les commandes ne résident pas dans une bibliothèque chargée automatiquement, auto_import ne fait rien. La correspondance des motifs est effectuée selon les règles de correspondance de namespace import.
auto_load cmd
Cette commande tente de charger la définition d'une commande Tcl nommée cmd. Pour ce faire, elle recherche un chemin de chargement automatique, qui est une liste d'un ou plusieurs répertoires. Le chemin de chargement automatique est donné par la variable globale auto_path si elle existe. S'il n'y a pas de variable auto_path, alors la variable d'environnement TCLLIBPATH est utilisée, si elle existe. Sinon, le chemin de chargement automatique se compose uniquement du répertoire de la bibliothèque Tcl. Dans chaque répertoire du chemin de chargement automatique, il doit y avoir un fichier tclIndex qui décrit une ou plusieurs commandes définies dans ce répertoire et un script à évaluer pour charger chacune des commandes. Le fichier tclIndex doit être généré avec la commande auto_mkindex. Si cmd est trouvé dans un fichier d'index, alors le script approprié est évalué pour créer la commande. La commande auto_load retourne 1 si cmd a été créée avec succès. La commande retourne 0 s'il n'y avait pas d'entrée d'index pour cmd ou si le script n'a pas réellement défini cmd (par exemple, parce que les informations d'index sont obsolètes). Si une erreur se produit lors du traitement du script, cette erreur est retournée. Auto_load ne lit les informations d'index qu'une seule fois et les enregistre dans le tableau auto_index ; les appels ultérieurs à auto_load recherchent cmd dans le tableau plutôt que de relire les fichiers d'index. Les informations d'index mises en cache peuvent être supprimées avec la commande auto_reset. Cela forcera la prochaine commande auto_load à recharger la base de données d'index depuis le disque.
auto_mkindex dir pattern pattern ...
Génère un index adapté à l'utilisation par auto_load. La commande recherche dans dir tous les fichiers dont les noms correspondent à l'un des arguments pattern (la correspondance est effectuée avec la commande glob), génère un index de toutes les procédures de commande Tcl définies dans tous les fichiers correspondants, et stocke les informations d'index dans un fichier nommé tclIndex dans dir. Si aucun motif n'est donné, un motif de *.tcl sera supposé. Par exemple, la commande
auto_mkindex foo *.tcl

lira tous les fichiers .tcl du sous-répertoire foo et générera un nouveau fichier d'index foo/tclIndex.

Auto_mkindex analyse les scripts Tcl en les sourçant dans un interpréteur enfant et en surveillant les commandes proc et namespace qui sont exécutées. Les extensions peuvent utiliser le paquet (non documenté) auto_mkindex_parser pour enregistrer d'autres commandes qui peuvent contribuer à l'index de chargement automatique. Vous devrez lire auto.tcl pour voir comment cela fonctionne.

Auto_mkindex_old (qui a la même syntaxe que auto_mkindex) analyse les scripts Tcl de manière relativement peu sophistiquée : si une ligne contient le mot “proc” comme premiers caractères, alors elle est supposée être une définition de procédure et le mot suivant de la ligne est pris comme nom de la procédure. Les définitions de procédures qui n'apparaissent pas de cette manière (par exemple, elles ont des espaces avant le proc) ne seront pas indexées. Si votre script contient du code « dangereux », tel qu'un code d'initialisation global ou des noms de procédures avec des caractères spéciaux comme $, *, [ ou ], vous êtes plus en sécurité en utilisant auto_mkindex_old.

auto_reset
Détruit toutes les informations mises en cache par auto_execok et auto_load. Ces informations seront relues sur disque la prochaine fois qu'elles seront nécessaires. Auto_reset supprime également toutes les procédures listées dans l'index de chargement automatique, de sorte que de nouvelles copies d'entre elles seront chargées la prochaine fois qu'elles seront utilisées.
auto_qualify command namespace
Calcule une liste de noms complètement qualifiés pour command. Cette liste reflète le chemin suivi par un interpréteur Tcl standard pour la recherche de commandes : d'abord, il recherche la commande dans le namespace courant, puis dans le namespace global. Par conséquent, si command est relative et namespace n'est pas ::, la liste retournée a deux éléments : command portée par namespace, comme si c'était une commande dans le namespace namespace ; et command comme si c'était une commande dans le namespace global. Sinon, si soit command est absolue (elle commence par ::), soit namespace est ::, la liste ne contient que command comme si c'était une commande dans le namespace global.

Auto_qualify est utilisé par les installations de chargement automatique de Tcl, à la fois pour produire des index de chargement automatique tels que pkgIndex.tcl, et pour effectuer le chargement automatique réel des fonctions au moment de l'exécution.

tcl_findLibrary basename version patch initScript enVarName varName

Cherche une bibliothèque Tcl. Le basename est le nom de base de la bibliothèque (par exemple, tcl). La version est le numéro de version de la bibliothèque (par exemple, 8.4). Le patch est le niveau de patch (par exemple, 2). Les autres arguments sont des noms de variables Tcl dans lesquelles les résultats seront stockés. Les résultats sont des chemins de fichiers et des variables d'environnement.

parray arrayName ?pattern?
Imprime toutes les valeurs des éléments d'un tableau nommé arrayName. Si le pattern est spécifié, seules les valeurs dont les noms d'éléments correspondent au pattern (en utilisant les règles de correspondance de string match) sont imprimées. Les sorties sont formatées avec la commande puts.
tcl_endOfWord str start
À partir de la position start dans la chaîne str, retourne la position du premier caractère qui n'est pas un caractère de mot Tcl. Si tous les caractères restants sont des caractères de mot Tcl, alors la longueur de la chaîne est retournée. Les caractères de mot Tcl sont définis dans le manuel Tcl et incluent les caractères alphanumériques et le caractère de soulignement.
tcl_startOfNextWord str start
À partir de la position start dans la chaîne str, retourne la position du premier caractère de mot Tcl. Si aucun caractère de mot Tcl ne se trouve à ou après la position start, alors la longueur de la chaîne est retournée. Les caractères de mot Tcl sont définis dans le manuel Tcl et incluent les caractères alphanumériques et le caractère de soulignement.
tcl_startOfPreviousWord str start
À partir de la position start dans la chaîne str, retourne la position du premier caractère de mot Tcl. Si aucun caractère de mot Tcl ne se trouve avant la position start, alors 0 est retourné. Les caractères de mot Tcl sont définis dans le manuel Tcl et incluent les caractères alphanumériques et le caractère de soulignement.
tcl_wordBreakAfter str start
À partir de la position start dans la chaîne str, retourne la position du premier caractère qui n'est pas un caractère de mot Tcl. Si tous les caractères restants sont des caractères de mot Tcl, alors la longueur de la chaîne est retournée. C'est le même que tcl_endOfWord.
tcl_wordBreakBefore str start
À partir de la position start dans la chaîne str, retourne la position du premier caractère de mot Tcl. Si aucun caractère de mot Tcl ne se trouve à ou après la position start, alors la longueur de la chaîne est retournée. C'est le même que tcl_startOfNextWord.
Ceci est une procédure de recherche standard à utiliser par les extensions lors de leur initialisation. Elles appellent cette procédure pour rechercher leur bibliothèque de scripts dans plusieurs répertoires standard. Le dernier composant du nom du répertoire de la bibliothèque est normalement basenameversion (par exemple, tk8.0), mais il peut être « library » lorsqu'il se trouve dans les hiérarchies de construction. Le fichier initScript sera sourcé dans l'interpréteur une fois qu'il sera trouvé. Le répertoire dans lequel ce fichier est trouvé est stocké dans la variable globale varName. Si cette variable est déjà définie (par exemple, par du code C lors de l'initialisation de l'application), aucune recherche n'est effectuée. Sinon, la recherche s'effectue dans les répertoires suivants : le répertoire nommé par la variable d'environnement enVarName ; par rapport au répertoire de la bibliothèque Tcl ; par rapport au fichier exécutable dans le répertoire d'installation standard bin ou bin/arch ; par rapport au fichier exécutable dans l'arbre de construction actuel ; par rapport au fichier exécutable dans un arbre de construction parallèle.
parray nomTableau ?motif?
Imprime sur la sortie standard les noms et les valeurs de tous les éléments du tableau nomTableau, ou seulement les noms qui correspondent au motif (en utilisant les règles de correspondance de string match) et leurs valeurs si le motif est fourni. nomTableau doit être un tableau accessible à l'appelant de parray. Il peut être local ou global.

AIDE AUX LIMITES DE MOTS

Ces procédures sont principalement utilisées en interne par Tk.

tcl_endOfWord str debut
Retourne l'indice de la première position de fin de mot qui se produit après un indice de départ debut dans la chaîne str. Une position de fin de mot est définie comme le premier caractère non-mot suivant le premier caractère mot après le point de départ. Retourne -1 s'il n'y a plus de positions de fin de mot après le point de départ. Voir la description de tcl_wordchars et tcl_nonwordchars ci-dessous pour plus de détails sur la manière dont Tcl détermine quels caractères sont des caractères mot.
tcl_startOfNextWord str debut
Retourne l'indice de la première position de début de mot qui se produit après un indice de départ debut dans la chaîne str. Une position de début de mot est définie comme le premier caractère mot suivant un caractère non-mot. Retourne -1 s'il n'y a plus de positions de début de mot après le point de départ.
tcl_startOfPreviousWord str debut
Retourne l'indice de la première position de début de mot qui se produit avant un indice de départ debut dans la chaîne str. Retourne -1 s'il n'y a plus de positions de début de mot avant le point de départ.
tcl_wordBreakAfter str debut
Retourne l'indice de la première limite de mot après l'indice de départ debut dans la chaîne str. Retourne -1 s'il n'y a plus de limites après le point de départ dans la chaîne donnée. L'indice retourné fait référence au deuxième caractère de la paire qui constitue une limite.
tcl_wordBreakBefore str debut
Retourne l'indice de la première limite de mot avant l'indice de départ debut dans la chaîne str. Retourne -1 s'il n'y a plus de limites avant le point de départ dans la chaîne donnée. L'indice retourné fait référence au deuxième caractère de la paire qui constitue une limite.

VARIABLES

Les variables globales suivantes sont définies ou utilisées par les procédures de la bibliothèque Tcl. Elles se répartissent en deux grandes catégories : la gestion des commandes et des paquets inconnus, et la détermination de ce qui constitue des mots.

VARIABLES DE CHARGEMENT AUTOMATIQUE ET DE GESTION DES PAQUETS

auto_execs
Utilisé par auto_execok pour enregistrer des informations sur l'existence de commandes particulières en tant que fichiers exécutables.
auto_index
Utilisé par auto_load pour enregistrer les informations d'index lues sur le disque.
auto_noexec
Si défini à n'importe quelle valeur, alors unknown ne tentera pas d'exécuter automatiquement de commandes.
auto_noload
Si défini à n'importe quelle valeur, alors unknown ne tentera pas de charger automatiquement de commandes.
auto_path
Si défini, il doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations de chargement automatique (y compris pour les fichiers d'index de paquets lors de l'utilisation du gestionnaire package unknown par défaut). Cette variable est initialisée lors du démarrage pour contenir, dans l'ordre : les répertoires listés dans la variable d'environnement TCLLIBPATH, le répertoire nommé par la variable globale tcl_library, le répertoire parent de tcl_library, les répertoires listés dans la variable tcl_pkgPath. Des emplacements supplémentaires pour rechercher des fichiers et des index de paquets doivent normalement être ajoutés à cette variable en utilisant lappend.
env(TCL_LIBRARY)
Si défini, il spécifie l'emplacement du répertoire contenant les scripts de bibliothèque (la valeur de cette variable sera assignée à la variable tcl_library et donc retournée par la commande info library). Si cette variable n'est pas définie, une valeur par défaut est utilisée.
env(TCLLIBPATH)
Si défini, il doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations de chargement automatique. Les répertoires doivent être spécifiés au format Tcl, en utilisant « / » comme séparateur de chemin, quelle que soit la plateforme. Cette variable n'est utilisée que lors de l'initialisation de la variable auto_path.

VARIABLES DE DETERMINATION DES LIMITES DE MOTS

Ces variables ne sont utilisées que dans les commandes tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter et tcl_wordBreakBefore.

tcl_nonwordchars
Cette variable contient une expression régulière utilisée par des routines comme tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non. Si le motif correspond à un caractère, le caractère est considéré comme un caractère non-mot. Sur les plateformes Windows, les espaces, les tabulations et les nouvelles lignes sont considérés comme des caractères non-mots. Sous Unix, tout ce qui n'est pas un nombre, une lettre ou un trait de soulignement est considéré comme un caractère non-mot.
tcl_wordchars
Cette variable contient une expression régulière utilisée par des routines comme tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non. Si le motif correspond à un caractère, le caractère est considéré comme un caractère mot. Sur les plateformes Windows, les mots sont composés de tout caractère qui n'est pas un espace, une tabulation ou une nouvelle ligne. Sous Unix, les mots sont composés de nombres, de lettres ou de traits de soulignement.
