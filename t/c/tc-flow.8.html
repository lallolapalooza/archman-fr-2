NOM

flow - filtre de contrôle de trafic basé sur les flux

SYNTAXE

Mode de mappage :

tc filter ... flow map key CLÉ [ OPS ] [ OPTIONS ]
Mode de hachage :

tc filter ... flow hash keys LISTE_CLÉS [ perturb sec ] [ OPTIONS ]


OPS := [ OPS ] OP

OPTIONS := [ divisor NB ] [ baseclass ID ] [ match ARBRE_EMATCH ] [ action ACTION_SPÉC ]

LISTE_CLÉS := [ LISTE_CLÉS ] CLÉ

OP := { or | and | xor | rshift | addend } NB

ID := X:Y

CLÉ := { src | dst | proto | proto-src | proto-dst | iif | priority | mark | nfct | nfct-src | nfct-dst | nfct-proto-src | nfct-proto-dst | rt-classid | sk-uid | sk-gid | vlan-tag | rxhash }

DESCRIPTION

Le classificateur flow est destiné à étendre les capacités de hachage de SFQ sans coder en dur de nouvelles fonctions de hachage. Il permet également des mappages déterministes de clés vers des classes.

OPTIONS

action ACTION_SPÉC
Applique une action du framework des actions génériques aux paquets correspondants.
baseclass ID
Un décalage pour l'ID de classe résultant. ID peut être root, none ou un ID de classe hexadécimal sous la forme [X:]Y. X doit correspondre au handle majeur du qdisc/classe (s'il est omis, la valeur correcte est choisie automatiquement). Si tout le baseclass est omis, Y vaut par défaut 1.
divisor NB
Nombre de buckets à utiliser pour le tri. Les clés sont calculées modulo NB.
hash keys LISTE_CLÉS
Effectue une opération jhash2 sur les clés de LISTE_CLÉS, le résultat (modulo le divisor s'il est donné) est pris comme ID de classe, éventuellement décalé par la valeur de baseclass. Il est possible de spécifier un intervalle (en secondes) après lequel la source d'entropie de jhash2 est recréée en utilisant le paramètre perturb.
map key CLÉ
Les données du paquet identifiées par CLÉ sont traduites en IDs de classe pour y pousser le paquet. La valeur peut être modifiée par OPS avant d'être utilisée pour le mappage. Ils sont appliqués dans l'ordre où ils sont listés ici :
and NB
Effectue une opération ET bit à bit avec la valeur numérique NB.
or NB
Effectue une opération OU bit à bit avec la valeur numérique NB.
xor NB
Effectue une opération XOR bit à bit avec la valeur numérique NB.
rshift NB
Décalage de la valeur de CLÉ vers la droite de NB bits.
addend NB
Ajoute NB à la valeur de CLÉ.
Pour les opérations or, and, xor et rshift, NB est supposé être un entier non signé de 32 bits. Pour l'opération addend, NB peut être beaucoup plus complexe : il peut être préfixé par un signe moins ('-') pour provoquer une soustraction au lieu d'une addition, et pour les clés src, dst, nfct-src et nfct-dst, il peut être donné en notation d'adresse IP. Voir ci-dessous pour un exemple illustratif.
match ARBRE_EMATCH
Fait correspondre les paquets en utilisant l'infrastructure de correspondance étendue. Voir tc-ematch(8) pour une description détaillée de la syntaxe autorisée dans ARBRE_EMATCH.

CLÉS

En mode mappage, une seule clé est utilisée (après permutation optionnelle) pour construire un ID de classe. L'ID résultant est déductible dans la plupart des cas. En mode hachage, plusieurs clés peuvent être spécifiées, qui sont ensuite hachées et la sortie est utilisée comme ID de classe. Cet ID n'est pas déductible à l'avance et peut même changer au fil du temps pour un flux donné si un intervalle perturb a été donné.

La plage des ID de classe peut être limitée par l'option divisor, qui est utilisée pour un modulo.

src, dst
Utilise l'adresse source ou destination comme clé. Dans le cas d'IPv4 et TIPC, il s'agit de la valeur de l'adresse réelle. Pour IPv6, l'adresse de 128 bits est pliée en une valeur de 32 bits en effectuant un XOR des quatre mots de 32 bits. Dans tous les autres cas, l'adresse du socket interne au noyau est utilisée (après avoir été pliée en 32 bits sur les systèmes 64 bits).
proto
Utilise le numéro de protocole de couche quatre comme clé.
proto-src
Utilise le port source de couche quatre comme clé. S'il n'est pas disponible, l'adresse du socket interne au noyau est utilisée à la place.
proto-dst
Utilise le port destination de couche quatre comme clé. S'il n'est pas disponible, l'adresse dst_entry interne au noyau associée est utilisée après un XOR avec le numéro de protocole de couche trois du paquet.
iif
Utilise l'indice de l'interface entrante comme clé.
priority
Utilise la priorité du paquet comme clé. Il s'agit généralement de la valeur DSCP/ECN de l'en-tête IP.
mark
Utilise le fwmark de netfilter comme clé.
nfct
Utilise l'adresse de l'entrée conntrack associée comme clé.
nfct-src, nfct-dst, nfct-proto-src, nfct-proto-dst
Ce sont des variantes sensibles à conntrack de src, dst, proto-src et proto-dst. En cas de NAT, ce sont essentiellement les valeurs de l'en-tête du paquet avant application du NAT.
rt-classid
Utilise le domaine de l'entrée de table de routage de destination du paquet comme clé.
sk-uid
sk-gid
Pour les paquets générés localement, utilise l'ID utilisateur ou groupe auquel appartient le socket d'origine comme clé.
vlan-tag
Utilise l'ID VLAN du paquet comme clé.
rxhash
Utilise le hash du flux comme clé.

EXEMPLES

Hachage SFQ classique :
tc filter add ... flow hash \
	keys src,dst,proto,proto-src,proto-dst divisor 1024
Hachage SFQ classique, mais en utilisant les informations de conntrack pour fonctionner correctement en combinaison avec le NAT :
tc filter add ... flow hash \
	keys nfct-src,nfct-dst,proto,nfct-proto-src,nfct-proto-dst \
	divisor 1024
Mapper les adresses IP de destination de 192.168.0.0/24 aux classids 1-256 :
tc filter add ... flow map \
	key dst addend -192.168.0.0 divisor 256
Alternative à ce qui précède :
tc filter add ... flow map \
	key dst and 0xff
