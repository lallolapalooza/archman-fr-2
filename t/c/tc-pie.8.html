NOM

PIE - Algorithme AQM Proportional Integral controller-Enhanced

SYNTAXE

tc qdisc ... pie [ limit PAQUETS ] [ target TEMPS ] [ tupdate TEMPS ] [ alpha int ] [ beta int ] [ ecn | noecn ] [ bytemode | nobytemode ] [ dq_rate_estimator | no_dq_rate_estimator ]

DESCRIPTION

Proportional Integral controller-Enhanced (PIE) est un schéma de gestion active de file d'attente basé sur la théorie du contrôle. Il est basé sur le contrôleur proportionnel intégral mais vise à contrôler le délai. Les principaux objectifs de conception sont :
o Contrôle de faible latence
o Utilisation élevée du lien
o Implémentation simple
o Stabilité garantie et réactivité rapide

ALGORITHME

PIE est conçu pour contrôler efficacement le délai. Premièrement, un taux de défilement moyen est estimé en fonction de la file d'attente existante. Le taux est utilisé pour calculer le délai actuel. Ensuite, sur une base périodique, le délai est utilisé pour calculer la probabilité de perte. Enfin, à l'arrivée, un paquet est perdu (ou marqué) en fonction de cette probabilité.

PIE ajuste la probabilité en fonction de la tendance du délai, c'est-à-dire s'il augmente ou diminue. Le délai converge rapidement vers la valeur cible spécifiée.

alpha et beta sont des paramètres choisis statiquement pour contrôler la croissance de la probabilité de perte et sont déterminés par des approches de théorie du contrôle. alpha détermine comment la déviation entre la latence actuelle et la latence cible change la probabilité. beta exerce des ajustements supplémentaires en fonction de la tendance de la latence.

La probabilité de perte est utilisée pour marquer les paquets en mode ecn. Cependant, comme dans RED, au-delà de 10% des paquets sont perdus en fonction de cette probabilité. Le mode bytemode est utilisé pour perdre des paquets proportionnellement à la taille du paquet.

Des détails supplémentaires peuvent être trouvés dans l'article cité ci-dessous.

PARAMETRES

limit

Limite de la taille de la file d'attente en paquets. Les paquets entrants sont perdus lorsque cette limite est atteinte. La valeur par défaut est de 1000 paquets.

target

est le délai de file d'attente attendu. Le délai cible par défaut est de 15 ms.

tupdate

est la fréquence à laquelle la probabilité de perte du système est calculée. La valeur par défaut est de 15 ms.

alpha

beta

alpha et beta sont des paramètres choisis pour contrôler la probabilité de perte. Ils doivent être compris entre 0 et 32.

ecn | noecn

est utilisé pour marquer les paquets au lieu de les perdre. ecn pour activer le mode ecn, noecn pour désactiver le mode ecn. Par défaut, ecn est désactivé.

bytemode | nobytemode

est utilisé pour mettre à l'échelle la probabilité de perte par rapport à la taille du paquet. bytemode pour activer le mode bytemode, nobytemode pour désactiver le mode bytemode. Par défaut, bytemode est désactivé.

dq_rate_estimator | no_dq_rate_estimator

est utilisé pour calculer le délai en utilisant la loi de Little. dq_rate_estimator pour activer dq_rate_estimator, no_dq_rate_estimator pour désactiver no_dq_rate_estimator. Par défaut, dq_rate_estimator est désactivé.

EXEMPLES


# tc qdisc add dev eth0 root pie
# tc -s qdisc show
qdisc pie 8036: dev eth0 root refcnt 2 limit 1000p target 15.0ms tupdate 16.0ms alpha 2 beta 20
Sent 31216108 bytes 20800 pkt (dropped 80, overlimits 0 requeues 0)
backlog 16654b 11p requeues 0
prob 0.006161 delay 15666us
pkts_in 20811 overlimit 0 dropped 80 maxq 50 ecn_mark 0


# tc qdisc add dev eth0 root pie dq_rate_estimator
# tc -s qdisc show
qdisc pie 8036: dev eth0 root refcnt 2 limit 1000p target 15.0ms tupdate 16.0ms alpha 2 beta 20
Sent 63947420 bytes 42414 pkt (dropped 41, overlimits 0 requeues 0)
backlog 271006b 179p requeues 0
prob 0.000092 delay 22200us avg_dq_rate 12145996
pkts_in 41 overlimit 343 dropped 0 maxq 50 ecn_mark 0


# tc qdisc add dev eth0 root pie limit 100 target 20ms tupdate 30ms ecn
# tc -s qdisc show

prob 0.008845 delay 11348us

# tc qdisc add dev eth0 root pie limit 100 target 50ms tupdate 30ms bytemode
