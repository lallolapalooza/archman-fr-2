NOM

FQ - Organisation de trafic Fair Queue

SYNTAXE

tc qdisc ... fq [ limit PAQUETS ] [ flow_limit PAQUETS ] [ quantum OCTETS ] [ initial_quantum OCTETS ] [ maxrate DEBIT ] [ buckets NOMBRE ] [ orphan_mask NOMBRE ] [ pacing | nopacing ] [ ce_threshold TEMPS ]

DESCRIPTION

FQ (Fair Queue) est un ordonnanceur de paquets sans classe conçu principalement pour le trafic généré localement. Il vise à réaliser une organisation par flux. FQ sépare les flux et est capable de respecter les exigences d'organisation définies par la pile TCP. Tous les paquets appartenant à un socket sont considérés comme un 'flux'. Pour les paquets non locaux (charge de travail du routeur), le hachage du paquet est utilisé comme solution de repli.

Une application peut spécifier un débit d'organisation maximum à l'aide de l'appel SO_MAX_PACING_RATE setsockopt. Cet ordonnanceur de paquets ajoute un délai entre les paquets pour respecter la limitation de débit définie sur chaque socket. Notez qu'après linux-4.20, Linux a adopté l'EDT (Earliest Departure Time) et TCP définit directement l'heure de départ appropriée pour chaque skb.

Le défilement se fait en mode round-robin. Une file FIFO spéciale est réservée aux paquets de haute priorité (priorité TC_PRIO_CONTROL), ces paquets sont toujours dépilés en premier.

FQ n'est pas économe en travail.

L'organisation TCP est bénéfique pour les flux ayant des périodes d'inactivité, car la fenêtre de congestion permet à la pile TCP de mettre en file d'attente un nombre potentiellement important de paquets. Cela élimine le choix du 'démarrage lent après une période d'inactivité', qui pénalise lourdement les flux BDP importants et les applications qui délivrent des blocs de données tels que les flux vidéo.

PARAMETRES

limit

Limite stricte de la taille réelle de la file d'attente. Lorsque cette limite est atteinte, les nouveaux paquets sont abandonnés. Si la valeur est abaissée, les paquets sont abandonnés de manière à respecter la nouvelle limite. La valeur par défaut est 10000 paquets.

flow_limit

Limite stricte du nombre maximum de paquets mis en file d'attente par flux. La valeur par défaut est 100.

quantum

Le crédit par tour de RR de défilement, c'est-à-dire la quantité d'octets qu'un flux est autorisé à dépiler à la fois. Une valeur plus élevée signifie une période plus longue avant que le flux suivant ne soit servi. La valeur par défaut est 2 * octets MTU de l'interface.

initial_quantum

Le crédit de débit d'envoi initial, c'est-à-dire la quantité d'octets qu'un nouveau flux est autorisé à dépiler initialement. Ceci est spécifiquement conçu pour permettre l'utilisation de IW10 sans délai supplémentaire. La valeur par défaut est 10 * MTU de l'interface, soit 15140 pour une Ethernet 'standard'.

maxrate

Débit d'envoi maximum d'un flux. La valeur par défaut est illimitée. Le paramètre spécifique à l'application via SO_MAX_PACING_RATE n'est ignoré que s'il est supérieur à cette valeur.

buckets

La taille de la table de hachage utilisée pour la recherche de flux. Chaque compartiment se voit attribuer un arbre rouge-noir pour un tri efficace des collisions. Par défaut : 1024.

orphan_mask

Pour les paquets n'appartenant pas à un socket, fq est capable de masquer une partie du hachage de skb et de réduire le nombre de compartiments associés au trafic. Il s'agit d'un mécanisme de prévention DDOS, et la valeur par défaut est 1023 (ce qui signifie qu'au plus 1024 flux sont alloués pour ces paquets).

[no]pacing

Active ou désactive l'organisation des flux. Par défaut, elle est activée.

ce_threshold

définit un seuil au-dessus duquel tous les paquets sont marqués avec ECN Congestion Experienced. Ceci est utile pour les algorithmes de contrôle de congestion de type DCTCP qui nécessitent un marquage à des seuils de mise en file d'attente très faibles.

EXEMPLES

#tc qdisc add dev eth0 root fq ce_threshold 4ms
#tc -s -d qdisc show dev eth0
qdisc fq 8001: dev eth0 root refcnt 2 limit 10000p flow_limit 100p buckets 1024 orphan_mask 1023 quantum 3028b initial_quantum 15140b low_rate_threshold 550Kbit refill_delay 40.0ms ce_threshold 4.0ms
