NOM

tclsh - Shell simple contenant l'interpréteur Tcl

SYNTAXE

tclsh ?-encoding nom? ?fichier nom nom ...?

DESCRIPTION

Tclsh est une application de type shell qui lit des commandes Tcl depuis son entrée standard ou depuis un fichier et les évalue. Si elle est invoquée sans arguments, elle s'exécute de manière interactive, lisant les commandes Tcl depuis l'entrée standard et affichant les résultats des commandes et les messages d'erreur sur la sortie standard. Elle s'exécute jusqu'à ce que la commande exit soit invoquée ou qu'elle atteigne la fin de fichier sur son entrée standard. S'il existe un fichier .tclshrc (ou tclshrc.tcl sur les plateformes Windows) dans le répertoire personnel de l'utilisateur, tclsh interactif évalue le fichier comme un script Tcl juste avant de lire la première commande depuis l'entrée standard.

FICHIERS DE SCRIPT

Si tclsh est invoqué avec des arguments, les premiers arguments spécifient le nom d'un fichier de script, et éventuellement, l'encodage des données textuelles stockées dans ce fichier de script. Tous les arguments supplémentaires sont rendus disponibles au script sous forme de variables (voir ci-dessous). Au lieu de lire des commandes depuis l'entrée standard, tclsh lira des commandes Tcl depuis le fichier nommé ; tclsh se terminera lorsqu'il atteindra la fin du fichier. La fin du fichier peut être marquée soit par la fin physique du support, soit par le caractère “\032” (“\u001a”, contrôle-Z). Si ce caractère est présent dans le fichier, l'application tclsh lira le texte jusqu'à ce caractère, sans l'inclure. Une application qui nécessite ce caractère dans le fichier peut l'encoder en toute sécurité comme “\032”, “\x1A”, ou “\u001a” ; ou peut le générer en utilisant des commandes telles que format ou binary. Il n'y a pas d'évaluation automatique de .tclshrc lorsque le nom d'un fichier de script est présenté sur la ligne de commande de tclsh, mais le fichier de script peut toujours le source s'il le souhaite.

Si vous créez un script Tcl dans un fichier dont la première ligne est

#!/usr/local/bin/tclsh

alors vous pouvez invoquer directement le fichier de script depuis votre shell si vous marquez le fichier comme exécutable. Cela suppose que tclsh a été installé dans l'emplacement par défaut /usr/local/bin ; s'il est installé ailleurs, vous devrez modifier la ligne ci-dessus pour qu'elle corresponde. De nombreux systèmes UNIX ne permettent pas à la ligne #! de dépasser environ 30 caractères de long, alors assurez-vous que l'exécutable tclsh est accessible avec un nom de fichier court.

Une approche encore meilleure consiste à commencer vos fichiers de script avec les trois lignes suivantes :

#!/bin/sh
# la ligne suivante redémarre en utilisant tclsh \
exec tclsh "$0" ${1+"$@"}

Cette approche présente trois avantages par rapport à l'approche du paragraphe précédent. Premièrement, l'emplacement du binaire tclsh n'a pas besoin d'être codé en dur dans le script : il peut se trouver n'importe où dans votre chemin de recherche shell. Deuxièmement, elle contourne la limite de 30 caractères pour le nom de fichier de l'approche précédente. Troisièmement, cette approche fonctionnera même si tclsh est lui-même un script shell (cela est fait sur certains systèmes afin de gérer plusieurs architectures ou systèmes d'exploitation : le script tclsh sélectionne l'un des plusieurs binaires à exécuter). Les trois lignes font que sh et tclsh traitent le script, mais l'instruction exec n'est exécutée que par sh. sh traite d'abord le script ; il traite la deuxième ligne comme un commentaire et exécute la troisième ligne. L'instruction exec amène le shell à arrêter le traitement et à démarrer tclsh pour retraiter l'intégralité du script. Lorsque tclsh démarre, il traite les trois lignes comme des commentaires, puisque la barre oblique inverse à la fin de la deuxième ligne fait que la troisième ligne est traitée comme faisant partie du commentaire de la deuxième ligne.

Vous devriez noter qu'il est également courant d'installer tclsh avec son numéro de version dans le nom. Cela a l'avantage de permettre à plusieurs versions de Tcl d'exister sur le même système en même temps, mais aussi l'inconvénient de rendre plus difficile l'écriture de scripts qui démarrent uniformément sur différentes versions de Tcl.

VARIABLES

Tclsh définit les variables globales Tcl suivantes en plus de celles créées par la bibliothèque Tcl elle-même (telles que env, qui mappe les variables d'environnement telles que PATH en Tcl) :

argc
Contient le nombre d'arguments nom (0 s'il n'y en a pas), sans inclure le nom du fichier de script.
argv
Contient une liste Tcl dont les éléments sont les arguments nom, dans l'ordre, ou une chaîne vide s'il n'y a pas d'arguments nom.
argv0
Contient nomFichier s'il a été spécifié. Sinon, contient le nom par lequel tclsh a été invoqué.
tcl_interactive
Contient 1 si tclsh s'exécute interactivement (aucun nomFichier n'a été spécifié et l'entrée standard est un périphérique de type terminal), 0 sinon.

INVITES DE COMMANDES

Lorsque tclsh est invoqué interactivement, il invite normalement chaque commande avec “% ”. Vous pouvez changer l'invite en définissant les variables globales tcl_prompt1 et tcl_prompt2. Si la variable tcl_prompt1 existe, elle doit contenir un script Tcl pour afficher une invite ; au lieu d'afficher une invite, tclsh évaluera le script dans tcl_prompt1. La variable tcl_prompt2 est utilisée de manière similaire lorsqu'une nouvelle ligne est tapée mais que la commande actuelle n'est pas encore terminée ; si tcl_prompt2 n'est pas définie, aucune invite n'est affichée pour les commandes incomplètes.
