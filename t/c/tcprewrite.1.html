tcprewrite(1) Commandes utilisateur tcprewrite(1)

NOM

tcprewrite - Réécrit les paquets dans un fichier pcap.

SYNTAXE

tcprewrite [-indicateurs] [-indicateur [valeur]] [--nom-option[[=| ]valeur]]

Tous les arguments doivent être des options.

DESCRIPTION

Tcprewrite est un outil permettant de réécrire les paquets stockés au format de fichier pcap(3), tels que ceux créés par des outils comme tcpdump(1) et wireshark(1). Une fois qu'un fichier pcap a vu ses paquets réécrits, ils peuvent être rejoués sur le réseau à l'aide de tcpreplay(1).

tcprewrite prend actuellement en charge la lecture des types DLT suivants :

DLT_C_HDLC alias Cisco HDLC

DLT_EN10MB alias Ethernet

DLT_LINUX_SLL alias Socket Cooked Linux

DLT_LINUX_SLL2 alias Socket Cooked Linux v2

DLT_RAW alias RAW IP

DLT_NULL alias Boucle de retour BSD

DLT_LOOP alias Boucle de retour OpenBSD

DLT_IEEE802_11 alias 802.11a/b/g

DLT_IEEE802_11_RADIO alias 802.11a/b/g avec en-têtes Radiotap

DLT_JUNIPER_ETHER alias Ethernet encapsulé Juniper

DLT_PPP_SERIAL alias PPP sur série

Veuillez consulter l'option --dlt pour les types DLT pris en charge pour l'écriture.

Les fonctionnalités d'édition de paquets de tcprewrite qui distinguent le trafic « client » et « serveur » nécessitent un fichier de cache tcpprep(1).

Pour plus de détails, veuillez consulter le manuel Tcpreplay à l'adresse : http://tcpreplay.appneta.com

OPTIONS

-r chaîne, --portmap=chaîne

Réécrit les ports TCP/UDP. Cette option peut apparaître jusqu'à 9999 fois.

Spécifie une liste de mappages de ports séparés par des virgules, composés de paires de numéros de port séparés par des deux-points. Chaque paire de ports séparée par des deux-points se compose du port à faire correspondre suivi du numéro de port à réécrire.

Exemples :

    --portmap=80:8000 --portmap=8080:80    # 80->8000 et 8080->80
    --portmap=8000,8080,88888:80           # 3 ports différents deviennent 80
    --portmap=8000-8999:80                 # les ports 8000 à 8999 deviennent 80
-s nombre, --seed=nombre

Randomise les adresses IPv4/v6 source/destination avec la graine donnée. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec les options suivantes : fuzz-seed. Cette option prend un nombre entier comme argument.

Les adresses IPv4/v6 source et destination sont pseudo-randomisées mais maintiennent les relations client/serveur. Étant donné que la randomisation est déterministe basée sur la graine, vous pouvez réutiliser la même valeur de graine pour recréer le trafic.

-N chaîne, --pnat=chaîne

Réécrit les adresses IPv4/v6 en utilisant pseudo-NAT. Cette option peut apparaître jusqu'à 2 fois. Cette option ne doit pas apparaître en combinaison avec l'option suivante : srcipmap.

Prend une série de paires de blocs réseau CIDR séparés par des virgules et des deux-points. Chaque paire de blocs réseau est évaluée dans l'ordre par rapport aux adresses IP. Si l'adresse IP dans le paquet correspond au premier bloc réseau, elle est réécrite en utilisant le second bloc réseau comme masque contre les bits de poids fort.

Exemple IPv4 :

    --pnat=192.168.0.0/16:10.77.0.0/16,172.16.0.0/12:10.1.0.0/24
Exemple IPv6 : 
    --pnat=[2001:db8::/32]:[dead::/16],[2001:db8::/32]:[::ffff:0:0/96]
-S chaîne, --srcipmap=chaîne

Réécrit les adresses IP source IPv4/v6 en utilisant pseudo-NAT. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'option suivante : pnat.

Fonctionne exactement comme l'option --pnat, mais n'affecte que les adresses IP source dans l'en-tête IPv4/v6.

-D chaîne, --dstipmap=chaîne

Réécrit les adresses IP de destination IPv4/v6 en utilisant pseudo-NAT. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec l'option suivante : pnat.

Fonctionne exactement comme l'option --pnat, mais n'affecte que les adresses IP de destination dans l'en-tête IPv4/v6.

-e chaîne, --endpoints=chaîne

Réécrit les adresses IP pour qu'elles soient entre deux points de terminaison. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : cachefile.

Prend une paire d'adresses IPv4/v6 séparées par des deux-points qui seront utilisées pour réécrire tout le trafic afin qu'il semble provenir d'entre les deux adresses IP.

Exemple IPv4 :

    --endpoints=172.16.0.1:172.16.0.2
Exemple IPv6 : 
    --endpoints=[2001:db8::dead:beef]:[::ffff:0:0:ac:f:0:2]
--tcp-sequence=nombre

Change les numéros de séquence (et ACK) TCP avec la graine donnée. Cette option prend un nombre entier comme argument. La valeur de nombre est limitée à : 
supérieur ou égal à 1

La valeur par défaut de nombre pour cette option est :
0

Change tous les numéros de séquence TCP et les numéros séquence-accusé de réception associés. Ils seront décalés d'un montant aléatoire basé sur la graine fournie.

-b, --skipbroadcast

Ignore la réécriture des adresses IPv4/v6 de diffusion/multidiffusion.

Par défaut, --seed, --pnat et --endpoints réécrivent les adresses IPv4/v6 et MAC de diffusion et de multidiffusion. La définition de cet indicateur empêchera la réécriture des adresses IPv4/v6 et MAC de diffusion/multidiffusion.

-C, --fixcsum

Force le recalcul des sommes de contrôle des en-têtes IPv4/TCP/UDP.

Re-calcule et corrige les sommes de contrôle de chaque paquet IPv4/v6. Automatiquement activé pour les paquets modifiés avec --seed, --pnat, --endpoints ou --fixlen.

--fixhdrlen

Modifie la longueur de l'en-tête IP/TCP pour correspondre à la longueur du paquet.

Par défaut, tcpreplay envoie des paquets avec la longueur de paquet d'origine. Cependant, vous voudrez peut-être que la longueur du paquet soit révisée à la taille minimale du paquet. En utilisant cette option, tcpreplay réécrit (corrige) la longueur du paquet et recalcule les sommes de contrôle lorsque la longueur du paquet change. Attention : des changements indésirables de paquets peuvent survenir lorsque cette option est spécifiée.

-m nombre, --mtu=nombre

Remplace la longueur MTU par défaut (1500 octets). Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est limitée à : 
dans la plage  1 jusqu'à MAX_SNAPLEN

Remplace la taille MTU par défaut de 1500 octets pour déterminer la longueur de remplissage maximale (--fixlen=pad) ou lors de la troncature (--mtu-trunc).

--mtu-trunc

Tronque les paquets plus grands que la MTU spécifiée. Cette option peut apparaître jusqu'à 1 fois.

Similaire à --fixlen, cette option tronquera les données dans les paquets à partir de la couche 3 et au-dessus pour qu'ils ne soient pas plus grands que la MTU.

-E, --efcs

Supprime les sommes de contrôle Ethernet (FCS) de la fin des trames.

Attention, cette option est assez dangereuse ! Nous ne vérifions pas réellement si un FCS existe dans la trame, nous supprimons simplement aveuglément les 4 derniers octets. Par conséquent, vous ne devriez l'utiliser que si vous savez que votre système d'exploitation fournit le FCS lors de la lecture de paquets bruts.

--ttl=chaîne

Modifie le TTL/Limite de sauts IPv4/v6.

Permet de modifier le TTL/Limite de sauts de tous les paquets IPv4/v6. Spécifiez un nombre pour coder en dur la valeur ou +/- une valeur pour augmenter ou diminuer

par la valeur fournie (limité à 1-255).

Exemples :

    --ttl=10
    --ttl=+7
    --ttl=-64
--tos=nombre

Définit l'octet TOS/DiffServ/ECN IPv4. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
dans l'intervalle de 0 à 255

Permet de remplacer la valeur TOS (également connue sous le nom de DiffServ/ECN) dans IPv4.

--tclass=nombre

Définit l'octet de classe de trafic IPv6. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
dans l'intervalle de 0 à 255

Permet de remplacer le champ de classe de trafic IPv6.

--flowlabel=nombre

Définit le label de flux IPv6. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
dans l'intervalle de 0 à 1048575

Permet de remplacer le champ de label de flux IPv6 de 20 bits. N'a aucun effet sur les paquets IPv4.

-F chaîne, --fixlen=chaîne

Remplit ou tronque les données du paquet pour correspondre à la longueur de l'en-tête. Cette option peut apparaître jusqu'à 1 fois.

Les paquets peuvent être tronqués lors de la capture si la longueur d'instantané (snaplen) est inférieure au paquet. Cette option permet de modifier le paquet pour le remplir à nouveau jusqu'à la taille stockée dans l'en-tête IPv4/v6 ou de réécrire la longueur totale de l'en-tête IP pour refléter la longueur du paquet stocké.

pad Les paquets tronqués seront remplis de sorte que la longueur du paquet corresponde à la longueur totale IPv4

trunc Les paquets tronqués auront leur champ de longueur totale IPv4 réécrit pour correspondre à la longueur réelle du paquet

del Supprime le paquet

--fuzz-seed=nombre

Perturbe 1 paquet sur X. Modifie les octets, la longueur ou émule la perte de paquet. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
supérieure ou égale à 0

La valeur par défaut de nombre pour cette option est :
0

Cette perturbation a été conçue pour tester les protocoles de couche 7 tels que les protocoles VoIP. Elle modifie aléatoirement 1 paquet sur X (où X = --fuzz-factor) afin que les protocoles stateful couvrent davantage leur code. Les actions de perturbation aléatoires se concentrent sur le début et la fin des données, car c'est souvent la partie des données sur laquelle les protocoles d'application basent leurs décisions.

Liste des actions de perturbation possibles :
* Perte de paquet
* Réduction de la taille du paquet
* Modification des octets du paquet :
* Tous les octets n'ont pas la même probabilité d'apparition dans la vie réelle.
Remplacer par 0x00, 0xFF, ou un octet aléatoire avec une probabilité égale.
* Tous les octets n'ont pas la même importance dans un paquet.
Remplacer le début, la fin ou le milieu du paquet avec une probabilité égale.
* Ne rien faire (7 paquets sur 8)

--fuzz-factor=nombre

Définit le ratio de perturbation 1 sur X paquets (par défaut 1 sur 8 paquets). Cette option doit apparaître en combinaison avec les options suivantes : fuzz-seed. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
supérieure ou égale à 1

La valeur par défaut de nombre pour cette option est :
8

Définit le ratio pour l'option --fuzz-seed. Par défaut, cette valeur est de 8, ce qui signifie que 1 paquet sur 8 est modifié par perturbation. Notez que ce ratio est basé sur le nombre aléatoire généré par la graine de perturbation fournie. Par conséquent, par défaut, vous ne pouvez pas vous attendre à ce que exactement tous les huitièmes paquets soient modifiés.

--skipl2broadcast

Ignore la réécriture des adresses de diffusion/multicast de couche 2.

Par défaut, la modification des adresses de couche 2 réécrit les adresses MAC de diffusion et de multicast. Définir ce drapeau empêchera la réécriture des adresses MAC de diffusion/multicast.

--dlt=chaîne

Remplace l'encapsulation DLT de sortie. Cette option peut apparaître jusqu'à 1 fois.

Par défaut, aucune conversion DLT (type de liaison de données) ne sera effectuée. Pour changer le type DLT du pcap de sortie, sélectionnez l'une des valeurs suivantes :

enet Ethernet, alias DLT_EN10MB

hdlc Cisco HDLC, alias DLT_C_HDLC

jnpr_eth Juniper Ethernet DLT_C_JNPR_ETHER

pppserial PPP Série, alias DLT_PPP_SERIAL

user En-tête de couche 2 et type DLT spécifiés par l'utilisateur

--enet-dmac=chaîne

Remplace les adresses MAC Ethernet de destination. Cette option peut apparaître jusqu'à 1 fois.

Prend une paire d'adresses MAC Ethernet délimitées par des virgules qui remplaceront l'adresse MAC de destination des paquets sortants. La première adresse MAC sera utilisée pour le trafic serveur vers client et la seconde adresse MAC optionnelle sera utilisée pour le trafic client vers serveur.

Exemple :

    --enet-dmac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-smac=chaîne

Remplace les adresses MAC Ethernet sources. Cette option peut apparaître jusqu'à 1 fois.

Prend une paire d'adresses MAC Ethernet délimitées par des virgules qui remplaceront l'adresse MAC source des paquets sortants. La première adresse MAC sera utilisée pour le trafic serveur vers client et la seconde adresse MAC optionnelle sera utilisée pour le trafic client vers serveur.

Exemple :

    --enet-smac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-subsmac=chaîne

Remplace les adresses MAC. Cette option peut apparaître jusqu'à 9999 fois.

Permet de réécrire les adresses MAC Ethernet des paquets. Elle prend une paire délimitée par des virgules d'adresses MAC et réécrit toutes les occurrences de la première adresse MAC avec la valeur de la seconde adresse MAC. Exemple :

    --enet-subsmac=00:12:13:14:15:16,00:22:33:44:55:66
--enet-mac-seed=nombre

Randomise les adresses MAC. Cette option peut apparaître jusqu'à 1 fois. Cette option ne doit pas apparaître en combinaison avec les options suivantes : enet-smac, enet-dmac, enet-subsmac. Cette option prend un nombre entier comme argument.

Permet de randomiser les adresses MAC Ethernet des paquets, un peu comme le fait l'option --seed pour les adresses IPv4/IPv6.

--enet-mac-seed-keep-bytes=nombre

Randomise les adresses MAC. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-mac-seed. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
dans l'intervalle de 1 à 6

Conserve certains octets intacts lors de l'utilisation de l'option --enet-mac-seed.

--enet-vlan=chaîne

Spécifie le mode d'étiquetage VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois.

Permet de réécrire les trames Ethernet pour ajouter un en-tête 802.1q aux en-têtes Ethernet 802.3 standard ou de supprimer les informations d'étiquetage VLAN 802.1q.

add Ajoute un en-tête VLAN 802.1q à l'en-tête Ethernet 802.3 existant. Si un en-tête VLAN existe déjà, un nouvel en-tête VLAN est ajouté à l'extérieur de l'en-tête existant.

Notez que vous serez autorisé à exécuter cette option plusieurs fois pour créer plus de 2 en-têtes VLAN, cependant ces paquets seront valides. Au maximum, vous devriez avoir 2 étiquettes VLAN 802.1q, ou une étiquette 802.1ad externe et une étiquette 802.1q interne.

del Réécrit l'en-tête VLAN 802.1q existant en un en-tête Ethernet 802.3.

--enet-vlan-tag=nombre

Spécifie la nouvelle valeur de l'étiquette VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-vlan. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
dans l'intervalle de 0 à 4095

--enet-vlan-cfi=nombre

Spécifie la valeur CFI VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-vlan. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
dans l'intervalle de 0 à 1

--enet-vlan-pri=nombre

Spécifie la priorité VLAN Ethernet 802.1q. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec l'option suivante : enet-vlan. Cette option prend un nombre entier comme argument. La valeur de nombre est contrainte à : 
dans l'intervalle de 0 à 7

--enet-vlan-proto=chaîne

Spécifie le protocole d'étiquetage VLAN 802.1q ou 802.1ad. Cette option peut apparaître jusqu'à 1 fois.

Permet de spécifier le protocole des étiquettes VLAN ajoutées.

802.1q Spécifie que des en-têtes VLAN 802.1q doivent être ajoutés. C'est le défaut.

802.1ad Spécifie que des en-têtes VLAN Q-in-Q 802.1ad doivent être ajoutés. Pour rendre les paquets valides, les paquets d'entrée doivent déjà avoir des en-têtes VLAN 802.1q.

--hdlc-control=nombre

Spécifie la valeur de contrôle HDLC. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

NOM

tcprewrite — réécrire l'en-tête des paquets capturés.

SYNOPSIS

tcprewrite [-c string] [-d number] [-h] [-i string] [-o string] [-v] [-A string] [--control=number] [--fragroute=string] [--fragdir=string] [--hdlc-address=number] [--load-opts=cfgfile] [--more-help] [--no-load-opts] [--save-opts[=cfgfile]] [--skip-soft-errors] [--user-dlink=string] [--user-dlt=number] [-V] [-w]

DESCRIPTION

tcprewrite is a utility for rewriting packet capture files. It is designed to simplify the process of modifying packet headers, making it easier to perform tasks such as changing IP addresses and ports, modifying TCP/UDP checksums, or updating other header fields. This is particularly useful for network testing, security analysis, and training purposes.

tcprewrite can process input from a pcap file or standard input, and it can write the modified packets to a pcap file or standard output. It supports a wide range of options for fine-grained control over header modifications.

OPTIONS

--control=number

Spécifier la valeur du champ de contrôle. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

Le champ "contrôle" de l'en-tête HDLC fait 1 octet. Apparemment, il devrait toujours être 0, mais vous pouvez utiliser n'importe quelle valeur d'1 octet.

--hdlc-address=number

Spécifier l'adresse HDLC. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

L'en-tête Cisco HDLC possède un champ "adresse" de 1 octet qui a deux valeurs valides :

0x0F Unicast

0xBF Broadcast
Vous pouvez cependant spécifier n'importe quelle valeur d'un seul octet.

--user-dlt=number

Définir le type DLT du fichier de sortie. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument.

Définit la valeur DLT du fichier pcap de sortie.

--user-dlink=string

Réécrire la couche Liaison de données avec des données spécifiées par l'utilisateur. Cette option peut apparaître jusqu'à 2 fois.

Fournir une série de valeurs hexadécimales séparées par des virgules qui seront utilisées pour réécrire ou créer l'en-tête de couche 2 des paquets. La première occurrence de cet argument réécrira le trafic du serveur et du client, mais si cet argument est spécifié une deuxième fois, il sera utilisé pour le trafic du client.

Exemple :

    --user-dlink=01,02,03,04,05,06,00,1A,2B,3C,4D,5E,6F,08,00
-d number, --dbug=number

Activer la sortie de débogage. Cette option peut apparaître jusqu'à 1 fois. Cette option prend un nombre entier comme argument. La valeur de number est contrainte à être : 
dans la plage 0 à 5

Le nombre number par défaut pour cette option est :
0

Si configuré avec --enable-debug, vous pouvez spécifier un niveau de verbosité pour la sortie de débogage. Des nombres plus élevés augmentent la verbosité.

-i string, --infile=string

Fichier pcap d'entrée à traiter. Cette option peut apparaître jusqu'à 1 fois.
-o string, --outfile=string

Fichier pcap de sortie. Cette option peut apparaître jusqu'à 1 fois.
-c string, --cachefile=string

Séparer le trafic via le fichier cache tcpprep. Cette option peut apparaître jusqu'à 1 fois.

Utiliser le fichier cache tcpprep pour séparer le trafic en fonction des relations client/serveur.

-v, --verbose

Afficher les paquets décodés via tcpdump sur STDOUT. Cette option peut apparaître jusqu'à 1 fois.
-A string, --decode=string

Arguments passés au décodeur tcpdump. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec les options suivantes : verbose.

Lors de l'activation du mode verbeux (-v), vous pouvez également spécifier un ou plusieurs arguments supplémentaires à passer à tcpdump pour modifier la façon dont les paquets sont décodés. Par défaut, -n et -l sont utilisés. Assurez-vous de mettre les arguments entre guillemets afin qu'ils ne soient pas interprétés par tcprewrite. Veuillez consulter la page man de tcpdump(1) pour une liste complète des options.

--fragroute=string

Analyser le fichier de configuration fragroute. Cette option peut apparaître jusqu'à 1 fois.

Activer des techniques d'évasion avancées en utilisant le moteur intégré fragroute(8). Voir la page man de fragroute(8) pour plus de détails. Important : tcprewrite ne prend pas en charge les commandes delay, echo ou print.

--fragdir=string

Quels flux appliquer fragroute : c2s, s2c, les deux. Cette option peut apparaître jusqu'à 1 fois. Cette option doit apparaître en combinaison avec les options suivantes : cachefile.

Appliquer le moteur fragroute aux paquets allant de c2s, s2c ou les deux lors de l'utilisation d'un fichier cache.

--skip-soft-errors

Ignorer l'écriture des paquets avec des erreurs douces. Cette option peut apparaître jusqu'à 1 fois.

Dans certains cas, les paquets ne peuvent pas être décodés ou la modification demandée n'est pas possible. Normalement, ces paquets sont écrits dans le fichier de sortie sans être modifiés afin que les fichiers cache tcpprep puissent toujours être utilisés, mais si vous le souhaitez, ces paquets peuvent être supprimés.

Un exemple de ceci sont les trames de gestion 802.11 qui ne contiennent pas de données.
