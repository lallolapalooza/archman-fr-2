NOM

sfb - Stochastic Fair Blue

SYNTAXE

tc qdisc ... blue rehash millisecondes db millisecondes limit paquets max paquets target paquets increment flottant decrement flottant penalty_rate paquets par seconde penalty_burst paquets

DESCRIPTION

Stochastic Fair Blue est un qdisc sans classe pour gérer la congestion en se basant sur l'historique des pertes de paquets et de l'utilisation de la liaison, tout en essayant d'empêcher les flux non réactifs (c'est-à-dire les flux qui ne réagissent pas au marquage de congestion ou aux paquets perdus) d'impacter les performances des flux réactifs. Contrairement à RED, où la probabilité de marquage doit être configurée, BLUE tente de déterminer automatiquement la probabilité de marquage idéale.

ALGORITHME

L'algorithme BLUE maintient une probabilité qui est utilisée pour marquer ou supprimer les paquets à mettre en file d'attente. Si la file d'attente déborde, la probabilité de marquage/suppression est augmentée. Si la file d'attente devient vide, la probabilité est diminuée. L'algorithme Stochastic Fair Blue (SFB) est conçu pour protéger les flux TCP contre les flux non réactifs.

Cette implémentation SFB maintient 8 niveaux de 16 bacs chacun pour la comptabilité. Chaque flux est mappé dans un bac de chaque niveau à l'aide d'une valeur de hachage par niveau.

Chaque bac maintient une probabilité de marquage, qui est augmentée ou diminuée en fonction de l'occupation du bac. Si le nombre de paquets dépasse la taille de ce bac, la probabilité de marquage est augmentée. Si le nombre tombe à zéro, elle est diminuée.

La probabilité de marquage est basée sur la valeur minimale de tous les bacs dans lesquels un flux est mappé, ainsi, lorsqu'un flux ne répond pas au marquage ou aux suppressions de paquets progressives, la probabilité de marquage atteint rapidement un.

Dans ce cas, le flux est limité en débit à penalty_rate paquets par seconde.

LIMITATIONS

En raison de la nature de SFB, il est possible que des flux réactifs partagent tous ses bacs avec un flux non réactif, amenant le flux réactif à être identifié à tort comme non réactif.

La probabilité qu'un flux réactif soit mal identifié dépend du nombre de flux non réactifs, M. Elle est de (1 - (1 - (1 / 16.0)) ** M) **8, donc, par exemple, avec 10 flux non réactifs, environ 0,2 % des flux réactifs seront mal identifiés.

Pour atténuer cela, SFB effectue un re-hachage périodique pour éviter une classification erronée pendant de longues périodes.

La méthode de hachage par défaut utilisera les adresses IP sources et de destination ainsi que les numéros de port si possible, et prend également en charge les protocoles de tunneling. Alternativement, un classificateur externe peut également être configuré.

PARAMETRES

rehash
Intervalle de temps en millisecondes où se produit une perturbation de la file d'attente pour éviter de détecter à tort des flux réactifs non liés comme faisant partie d'un flux non réactif pendant de longues périodes. Par défaut, 10 minutes.
db
Temps d'attente de préchauffage du double buffering, en millisecondes. Pour éviter de détruire l'historique des probabilités lors du re-hachage, cette implémentation maintient un deuxième ensemble de niveaux/bacs comme décrit dans la section 4.4 de la référence SFB. Pendant qu'un ensemble est utilisé pour gérer la file d'attente, un deuxième ensemble est préchauffé : chaque fois qu'un flux est alors déterminé comme non réactif, les probabilités de marquage dans le deuxième ensemble sont mises à jour. Lorsque le re-hachage se produit, ces bacs seront utilisés pour gérer la file d'attente et tous les flux non réactifs pourront être limités en débit immédiatement. Cette valeur détermine le temps qui doit s'écouler avant que le 2ème ensemble ne commence à être préchauffé. Par défaut, une minute, doit être inférieur à rehash.
limit
Limite stricte de la taille réelle (pas moyenne) de la file d'attente totale en paquets. Les paquets supplémentaires sont supprimés. Par défaut, la longueur de la file d'attente de transmission du périphérique auquel le qdisc est attaché.
max
Longueur maximale de la file d'attente d'un bac, en paquets, avant que les paquets ne commencent à être supprimés. Devrait être légèrement supérieur à target, mais ne devrait pas être défini à des valeurs dépassant 1,5 fois celle de target. Par défaut, 25.
target
La longueur moyenne souhaitée du bac. Si la longueur de la file d'attente du bac atteint cette valeur, la probabilité de marquage est augmentée de increment. La valeur par défaut dépend du réglage max, avec max réglé à 25, target sera par défaut à 20.
increment
Une valeur utilisée pour augmenter la probabilité de marquage lorsque la file d'attente semble surutilisée. Doit être compris entre 0 et 1.0. Par défaut, 0.00050.
decrement
Valeur utilisée pour diminuer la probabilité de marquage lorsque la file d'attente est trouvée vide. Doit être compris entre 0 et 1.0. Par défaut, 0.00005.
penalty_rate
Nombre maximum de paquets appartenant à des flux identifiés comme non réactifs qui peuvent être mis en file d'attente par seconde. Une fois ce nombre atteint, les paquets supplémentaires de ces flux non réactifs sont supprimés. Réglez-le à une fraction raisonnable de votre débit de liaison montante ; la valeur par défaut de 10 paquets est probablement trop petite.
penalty_burst
Nombre de paquets qu'un flux est autorisé à dépasser le taux de pénalité avant que les paquets ne commencent à être supprimés. Par défaut, 20 paquets.

STATISTIQUES

Ce qdisc expose des statistiques supplémentaires via la sortie 'tc -s qdisc'. Celles-ci sont :

earlydrop
Nombre de paquets supprimés avant qu'une file d'attente par flux ne soit pleine.
ratedrop
Nombre de paquets supprimés en raison de la limitation du débit. Si cette valeur est élevée, il y a de nombreux flux non réactifs envoyés via sfb. Dans de tels cas, il pourrait être préférable d'intégrer sfb dans un qdisc classful pour mieux contrôler ces flux à l'aide d'un autre qdisc de mise en forme.
bucketdrop
Nombre de paquets supprimés parce qu'une file d'attente par flux était pleine. Un bucketdrop élevé peut indiquer un grand nombre de flux agressifs et de courte durée.
queuedrop
Nombre de paquets supprimés en raison de l'atteinte de la limite. Cela devrait normalement être 0.
marked
Nombre de paquets marqués avec ECN.
maxqlen
La longueur actuelle de la file d'attente par flux (virtuelle) la plus longue.
maxprob
La probabilité de suppression maximale par flux. 1 signifie que certains flux ont été détectés comme non réactifs.

NOTES

SFB active automatiquement l'utilisation de l'Explicit Congestion Notification (ECN). De plus, cette implémentation SFB ne met pas elle-même les paquets en file d'attente. Au contraire, les paquets sont mis en file d'attente dans le qdisc interne (par défaut pfifo). Parce que sfb maintient des états de file d'attente virtuels, le qdisc interne ne doit pas supprimer un paquet précédemment mis en file d'attente. De plus, si la file d'attente d'un bac a un taux de marquage très élevé, cette implémentation commencera à supprimer des paquets, car une telle situation indique soit une mauvaise congestion, soit un flux non réactif.

EXEMPLE & UTILISATION

Pour s'attacher à l'interface $DEV, en utilisant les options par défaut :

# tc qdisc add dev $DEV handle 1: root sfb

Utiliser uniquement les adresses IP de destination pour attribuer les paquets aux bacs, en perturbant les résultats de hachage toutes les 10 minutes :

# tc filter add dev $DEV parent 1: handle 1 flow hash keys dst perturb 600
