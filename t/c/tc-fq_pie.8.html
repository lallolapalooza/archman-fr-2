NOM

FQ-PIE - Flow Queue Proportional Integral controller Enhanced (File d'attente à flux avec contrôleur proportionnel intégral amélioré)

SYNTAXE

tc qdisc ... fq_pie [ limit PAQUETS ] [ flows NOMBRE ]
[ target TEMPS ] [ tupdate TEMPS ]
[ alpha NOMBRE ] [ beta NOMBRE ]
[ quantum OCTETS ] [ memory_limit OCTETS ]
[ ecn_prob POURCENTAGE ] [ [no]ecn ]
[ [no]bytemode ] [ [no_]dq_rate_estimator ]

DESCRIPTION

FQ-PIE (Flow Queuing with Proportional Integral controller Enhanced) est une discipline de mise en file d'attente qui combine le Flow Queuing avec le schéma AQM PIE. FQ-PIE utilise une fonction de hachage Jenkins pour classifier les paquets entrants dans différents flux et est utilisé pour fournir une juste part de la bande passante à tous les flux utilisant le qdisc. Chaque flux est géré par l'algorithme PIE.

ALGORITHME

L'algorithme FQ-PIE se compose de deux parties logiques : le planificateur qui sélectionne à partir de quelle file d'attente un paquet doit être retiré, et l'AQM PIE qui agit sur chacune des files d'attente. La majeure partie du travail de FQ-PIE se situe dans la partie planification. L'interaction entre le planificateur et l'algorithme PIE est directe.

Lors de l'étape d'insertion (enqueue), un schéma basé sur le hachage est utilisé, où les flux sont hachés dans un certain nombre de compartiments, chaque compartiment ayant sa propre file d'attente. Le nombre de compartiments est configurable et par défaut à 1024 dans l'implémentation. Le hachage des flux est effectué sur le 5-uplet des adresses IP source et destination, des numéros de port et du numéro de protocole IP. Une fois que le paquet a été classifié avec succès dans une file d'attente, il est remis à l'algorithme PIE pour l'insertion en file d'attente. Il est ensuite ajouté à la fin de la file d'attente sélectionnée, et le nombre d'octets de la file d'attente est mis à jour par la taille du paquet. Si la file d'attente n'est pas activement utilisée (c'est-à-dire si elle ne figure ni dans la liste des nouvelles files d'attente ni dans la liste des anciennes), elle est ajoutée à la fin de la liste des nouvelles files d'attente, et son nombre de crédits est initialisé au quantum configuré. Sinon, la file d'attente est laissée dans sa liste de files d'attente actuelle.

Lors de l'étape de retrait (dequeue), le planificateur examine d'abord la liste des nouvelles files d'attente ; pour la file d'attente en tête de cette liste, si cette file d'attente a un nombre de crédits négatif (c'est-à-dire qu'elle a déjà retiré au moins un quantum d'octets), elle reçoit un quantum de crédits supplémentaire, la file d'attente est placée à la fin de la liste des anciennes files d'attente, et la routine sélectionne la file d'attente suivante et recommence. Sinon, cette file d'attente est sélectionnée à nouveau pour le retrait. Si la liste des nouvelles files d'attente est vide, le planificateur procède de la même manière dans la liste des anciennes files d'attente (en vérifiant les crédits, et soit en sélectionnant la file d'attente pour le retrait, soit en ajoutant des crédits et en remettant la file d'attente à la fin de la liste). Après avoir sélectionné une file d'attente à partir de laquelle retirer un paquet, l'algorithme PIE est invoqué sur cette file d'attente.

Enfin, si l'algorithme PIE ne renvoie pas de paquet, alors la file d'attente doit être vide et le planificateur fait l'une des deux choses suivantes :

Si la file d'attente sélectionnée pour le retrait provenait de la liste des nouvelles files d'attente, elle est déplacée à la fin de la liste des anciennes files d'attente. Si, au lieu de cela, elle provenait de la liste des anciennes files d'attente, cette file d'attente est retirée de la liste, pour être ajoutée à nouveau (en tant que nouvelle file d'attente) la prochaine fois qu'un paquet arrive et qui est haché vers cette file d'attente. Ensuite (puisqu'aucun paquet n'était disponible pour le retrait), tout le processus de retrait est redémarré depuis le début.

Si, au lieu de cela, le planificateur a récupéré un paquet de l'algorithme PIE, il soustrait la taille du paquet des crédits d'octets de la file d'attente sélectionnée et renvoie le paquet comme résultat de l'opération de retrait.

PARAMETRES

limit

C'est la limite de la taille de la file d'attente en paquets. Les paquets entrants sont abandonnés lorsque la limite est atteinte. La valeur par défaut est de 10240 paquets.

flows

C'est le nombre de flux dans lesquels les paquets entrants sont classifiés. En raison de la nature stochastique du hachage, plusieurs flux peuvent finir par être hachés dans le même emplacement. Les flux plus récents ont la priorité sur les plus anciens. Ce paramètre ne peut être défini qu'au chargement car de la mémoire doit être allouée pour la table de hachage. La valeur par défaut est 1024.

target

C'est le délai de file d'attente que l'algorithme PIE essaie de maintenir. Le délai cible par défaut est de 15 ms.

tupdate

C'est l'intervalle de temps auquel la probabilité d'abandon du système est calculée. La valeur par défaut est de 15 ms.

alpha

beta

alpha et beta sont des paramètres choisis pour contrôler la probabilité d'abandon. Ils doivent être compris entre 0 et 32.

quantum

quantum désigne le nombre d'octets qui peuvent être retirés d'une file d'attente avant de passer à la file d'attente suivante dans le schéma de round robin à déficit.

memory_limit

C'est la mémoire totale maximale autorisée pour les paquets de tous les flux. La valeur par défaut est de 32 Mo.

ecn_prob

C'est le seuil de probabilité d'abandon en dessous duquel les paquets seront marqués ECN au lieu d'être abandonnés. La valeur par défaut est de 10 %. La définition de ce paramètre nécessite que ecn soit activé.

[no]ecn

Il a la même sémantique que pie et peut être utilisé pour marquer les paquets au lieu de les abandonner. Si ecn a été activé, noecn peut être utilisé pour le désactiver et vice-versa.

[no]bytemode

Il est utilisé pour mettre à l'échelle la probabilité d'abandon proportionnellement à la taille du paquet. bytemode pour l'activer, nobytemode pour le désactiver. Par défaut, bytemode est désactivé.

[no_]dq_rate_estimator

dq_rate_estimator peut être utilisé pour calculer le délai de la file d'attente en utilisant la loi de Little, no_dq_rate_estimator peut être utilisé pour calculer le délai de la file d'attente en utilisant l'horodatage. Par défaut, dq_rate_estimator est désactivé.
