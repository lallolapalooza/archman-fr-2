NOM

HTB - Hierarchy Token Bucket

SYNTAXE

tc qdisc ... dev dev ( parent classid | root) [ handle major: ] htb [ default minor-id ] [ r2q divisor ] [ offload ]

tc class ... dev dev parent major:[minor] [ classid major:minor ] htb rate rate [ ceil rate ] burst bytes [ cburst bytes ] [ prio priority ] [ quantum bytes ]

DESCRIPTION

HTB permet de contrôler la bande passante sortante sur un lien donné. Il permet de simuler plusieurs liens plus lents et d'envoyer différents types de trafic sur différents liens simulés. Dans les deux cas, vous devez spécifier comment diviser le lien physique en liens simulés et comment décider quel lien simulé utiliser pour un paquet donné à envoyer.

HTB façonne le trafic en se basant sur l'algorithme Token Bucket Filter qui ne dépend pas des caractéristiques de l'interface et n'a donc pas besoin de connaître la bande passante sous-jacente de l'interface sortante.

ALGORITHME DE FAÇONNAGE

Le façonnage fonctionne comme documenté dans tc-tbf (8).

CLASSIFICATION

Au sein d'une instance HTB, de nombreuses classes peuvent exister. Chacune de ces classes contient une autre qdisc, par défaut tc-pfifo(8).

Lors de la mise en file d'attente d'un paquet, HTB commence à la racine et utilise diverses méthodes pour déterminer quelle classe doit recevoir les données.

En l'absence d'options de configuration inhabituelles, le processus est plutôt simple. À chaque nœud, nous recherchons une instruction, puis nous allons à la classe à laquelle l'instruction nous renvoie. Si la classe trouvée est un nœud feuille stérile (sans enfants), nous y mettons le paquet en file d'attente. Si ce n'est pas encore un nœud feuille, nous recommençons le processus à partir de ce nœud.

Les actions suivantes sont effectuées, dans l'ordre, à chaque nœud que nous visitons, jusqu'à ce que l'une d'elles nous renvoie à un autre nœud, ou termine le processus.

(i)
Consulter les filtres attachés à la classe. Si renvoyé à un nœud feuille, nous avons terminé. Sinon, recommencer.
(ii)
Si aucune des options ci-dessus n'a renvoyé d'instruction, mettre en file d'attente à ce nœud.

Cet algorithme garantit qu'un paquet finit toujours quelque part, même pendant que vous êtes occupé à construire votre configuration.

À COMPLÉTER

QDISC

La racine d'un arbre de classes HTB qdisc a les paramètres suivants :

parent major:minor | root
Ce paramètre obligatoire détermine l'emplacement de l'instance HTB, soit à la racine d'une interface, soit au sein d'une classe existante.
handle major:
Comme toutes les autres qdiscs, la HTB peut se voir attribuer un identifiant. Il doit se composer uniquement d'un numéro majeur, suivi de deux points. Facultatif, mais très utile si des classes seront générées au sein de cette qdisc.
default minor-id
Le trafic non classé est envoyé à la classe avec cet identifiant mineur.
r2q divisor
Diviseur utilisé pour calculer les valeurs quantum pour les classes. Les classes divisent le rate par ce nombre. La valeur par défaut est 10.
offload
Décharge l'algorithme HTB vers le matériel (nécessite la prise en charge du pilote et de l'appareil).

CLASSES

Les classes ont une multitude de paramètres pour configurer leur fonctionnement.

parent major:minor
Emplacement de cette classe dans la hiérarchie. Si elle est attachée directement à une qdisc et non à une autre classe, le mineur peut être omis. Obligatoire.
classid major:minor
Comme les qdiscs, les classes peuvent être nommées. Le numéro majeur doit être égal au numéro majeur de la qdisc à laquelle elle appartient. Facultatif, mais nécessaire si cette classe doit avoir des enfants.
prio priority
Dans le processus de rotation, les classes ayant le champ de priorité le plus bas sont d'abord essayées pour les paquets.
rate rate
Débit maximum garanti à cette classe et à tous ses enfants. Obligatoire.
ceil rate
Débit maximum auquel une classe peut envoyer, si son parent a de la bande passante à revendre. Par défaut, il correspond au débit configuré, ce qui implique aucun emprunt.
burst bytes
Quantité d'octets pouvant être transmise à la vitesse ceil, en excès par rapport au rate configuré. Doit être au moins aussi élevée que le burst le plus élevé de tous les enfants.
cburst bytes
Quantité d'octets pouvant être transmise à une vitesse « infinie », c'est-à-dire aussi rapidement que l'interface peut les transmettre. Pour une égalisation parfaite, elle doit être égale à un paquet moyen au maximum. Doit être au moins aussi élevée que le cburst le plus élevé de tous les enfants.
quantum bytes
Nombre d'octets à servir depuis cette classe avant que le planificateur ne passe à la classe suivante. La valeur par défaut est le rate divisé par le paramètre r2q de la qdisc. Si spécifié, r2q est ignoré.

NOTES

En raison des contraintes de synchronisation Unix, le débit maximal ceil n'est pas infini et peut en fait être assez faible. Sur Intel, il y a 100 événements de temporisation par seconde, le débit maximal est celui auquel 'burst' octets sont envoyés à chaque tick de temporisation. À partir de là, la taille minimale du burst pour un débit spécifié peut être calculée. Pour i386, un débit de 10 Mbit/s nécessite un burst de 12 kilo-octets car 100*12 Ko*8 équivaut à 10 Mbit/s.
