RED(8) Linux RED(8)

NOM

red - Random Early Detection (Détection Précoce Aléatoire)

SYNTAXE

tc qdisc ... red limit octets [ min octets ] [ max octets ] avpkt octets [ burst paquets ] [ ecn ] [ harddrop ] [ nodrop ] [ bandwidth débit ] [ probability chance ] [ adaptive ] [ qevent early_drop block index ] [ qevent mark block index ]

DESCRIPTION

Random Early Detection est un qdisc sans classe qui gère sa taille de file d'attente intelligemment. Les files d'attente ordinaires suppriment simplement les paquets de la fin lorsqu'elles sont pleines, ce qui n'est pas toujours le comportement optimal. RED effectue également la suppression en fin de file, mais de manière plus progressive.

Une fois que la file d'attente atteint une certaine longueur moyenne, les paquets mis en file d'attente ont une chance configurable d'être marqués (ce qui peut signifier supprimés). Cette chance augmente linéairement jusqu'à un point appelé la longueur moyenne de file d'attente max, bien que la file d'attente puisse devenir plus grande.

Cela présente de nombreux avantages par rapport à la simple suppression en fin de file, sans pour autant être coûteux en processeur. Cela évite les retransmissions synchronisées après un pic de trafic, qui provoquent d'autres retransmissions, etc.

L'objectif est d'avoir une petite taille de file d'attente, ce qui est bon pour l'interactivité, tout en ne perturbant pas le trafic TCP/IP avec trop de suppressions soudaines après un pic de trafic.

Selon que l'ECN est configuré ou non, le marquage signifie soit la suppression, soit simplement le marquage d'un paquet comme étant en surcharge.

ALGORITHME

La taille moyenne de la file d'attente est utilisée pour déterminer la probabilité de marquage. Elle est calculée à l'aide d'une moyenne mobile pondérée exponentiellement, qui peut être plus ou moins sensible aux pics.

Lorsque la taille moyenne de la file d'attente est inférieure à min octets, aucun paquet ne sera jamais marqué. Lorsqu'elle dépasse min, la probabilité de le faire augmente linéairement jusqu'à probability, jusqu'à ce que la taille moyenne de la file d'attente atteigne max octets. Comme probability n'est normalement pas défini à 100%, la taille de la file d'attente pourrait théoriquement dépasser max octets, d'où le paramètre limit pour définir une limite maximale stricte pour la taille de la file d'attente.

PARAMETRES

min
Taille moyenne de la file d'attente à partir de laquelle le marquage devient une possibilité. Par défaut : max /3.
max
À cette taille moyenne de file d'attente, la probabilité de marquage est maximale. Devrait être au moins le double de min pour éviter les retransmissions synchronisées, plus élevé pour un min faible. Par défaut : limit /4.
probability
Probabilité maximale de marquage, spécifiée comme un nombre flottant de 0.0 à 1.0. Valeurs suggérées : 0.01 ou 0.02 (1 ou 2 %, respectivement). Par défaut : 0.02.
limit
Limite stricte de la taille réelle (pas moyenne) de la file d'attente en octets. Les paquets supplémentaires sont supprimés. Devrait être défini plus haut que max+burst. Il est conseillé de le définir quelques fois plus haut que max.
burst
Utilisé pour déterminer la vitesse à laquelle la taille moyenne de la file d'attente est influencée par la taille réelle de la file d'attente. Des valeurs plus élevées rendent le calcul plus lent, permettant des rafales de trafic plus longues avant que le marquage ne commence. Des expériences réelles soutiennent la directive suivante : (min+min+max)/(3*avpkt).
avpkt
Spécifié en octets. Utilisé avec burst pour déterminer la constante de temps pour les calculs de la taille moyenne de la file d'attente. 1000 est une bonne valeur.
bandwidth
Ce débit est utilisé pour calculer la taille moyenne de la file d'attente après une période d'inactivité. Il doit être réglé sur la bande passante de votre interface. Cela ne signifie PAS que RED limitera pour vous ! Optionnel. Par défaut : 10Mbit.
ecn
Comme mentionné précédemment, RED peut soit 'marquer', soit 'supprimer'. La notification explicite de congestion (ECN) permet à RED de notifier les hôtes distants que leur débit dépasse la bande passante disponible. Les hôtes non compatibles ECN ne peuvent être notifiés qu'en supprimant un paquet. Si ce paramètre est spécifié, les paquets qui indiquent que leurs hôtes respectent l'ECN ne seront marqués et non supprimés, sauf si la taille de la file d'attente atteint limit octets. Recommandé.
harddrop
Si la taille moyenne de la file d'attente de flux est supérieure à max octets, ce paramètre force une suppression au lieu d'un marquage ecn.
nodrop
Avec ce paramètre, le trafic qui devrait être marqué, mais qui n'est pas compatible ECN, est mis en file d'attente. Sans le paramètre, il est supprimé précocement.
adaptive
(Ajouté dans linux-3.3) Met RED en mode adaptatif comme décrit dans http://icir.org/floyd/papers/adaptiveRed.pdf 
L'objectif de RED adaptatif est de rendre 'probability' une valeur dynamique comprise entre 1% et 50% pour atteindre la file d'attente moyenne cible :
(max - min) / 2

QEVENTS

Voir tc (8) pour des notes générales sur les qevents. Le qdisc RED prend en charge les qevents suivants :

early_drop
Le bloc associé est exécuté lorsque des paquets sont supprimés précocement. Cela inclut les paquets non-ECT en mode ECN.
mark
Le bloc associé est exécuté lorsque des paquets sont marqués en mode ECN.

EXEMPLE

# tc qdisc add dev eth0 parent 1:1 handle 10: red
limit 400000 min 30000 max 90000 avpkt 1000
burst 55 ecn adaptive bandwidth 10Mbit

tc-red(8)

NOM

tc-red — configuration d'un algorithme RED (Random Early Detection) sur une interface réseau

DESCRIPTION

L'algorithme RED (Random Early Detection) est une technique de gestion de file d'attente qui vise à éviter la congestion du réseau en détectant le début d'une congestion et en envoyant des paquets de manière aléatoire avant que la file ne soit complètement pleine. Ceci est censé inciter les expéditeurs à réduire leur débit avant que la congestion ne devienne sévère.

L'algorithme RED fonctionne en maintenant une moyenne de la longueur de la file d'attente. Lorsque la longueur moyenne dépasse un seuil minimum (min_th), l'algorithme commence à abandonner aléatoirement des paquets. Lorsque la longueur moyenne dépasse un seuil maximum (max_th), tous les paquets sont abandonnés. Si la longueur moyenne est inférieure au seuil minimum, aucun paquet n'est abandonné.

Les paramètres clés de l'algorithme RED sont :

  • min_th : Le seuil minimum de la longueur moyenne de la file d'attente.
  • max_th : Le seuil maximum de la longueur moyenne de la file d'attente.
  • max_p : La probabilité maximale d'abandon de paquet lorsque la longueur moyenne est égale à max_th.
  • ptc : Un paramètre lié au temps de réponse de la moyenne de la file d'attente.

OPTIONS

La commande tc est utilisée pour configurer les règles de mise en file d'attente du noyau Linux. La syntaxe pour configurer un algorithme RED est la suivante :

tc qdisc add dev <interface> parent <parent_qdisc> handle <handle>: red min_th <min_th> max_th <max_th> max_p <max_p> [ptc <ptc>]
<interface>
L'interface réseau sur laquelle configurer RED.
<parent_qdisc>
Le handle du "parent" qdisc. Généralement root pour la file d'attente racine.
<handle>
Un identifiant unique pour ce qdisc RED.
min_th
Le seuil minimum de la longueur moyenne de la file d'attente (en octets).
max_th
Le seuil maximum de la longueur moyenne de la file d'attente (en octets).
max_p
La probabilité maximale d'abandon de paquet. Un nombre compris entre 0 et 1.
ptc
(Optionnel) Un facteur de décroissance exponentielle pour le calcul de la moyenne de la longueur de la file d'attente. La valeur par défaut est 10.

EXEMPLE

Pour configurer un algorithme RED sur l'interface eth0 avec les paramètres suivants :

  • min_th = 10000 octets
  • max_th = 20000 octets
  • max_p = 0.02
  • ptc = 10

Utilisez la commande suivante :

tc qdisc add dev eth0 parent root handle 1: red min_th 10000 max_th 20000 max_p 0.02 ptc 10
