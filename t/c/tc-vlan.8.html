NOM

vlan - module de manipulation de VLAN

SYNTAXE


tc ... action vlan { pop | pop_eth | PUSH | MODIFY | PUSH_ETH } [ CONTROL ]

PUSH := push [ protocol VLANPROTO ] [ priority VLANPRIO ] id VLANID

MODIFY := modify [ protocol VLANPROTO ] [ priority VLANPRIO ] id VLANID

PUSH_ETH := push_eth dst_mac LLADDR src_mac LLADDR

CONTROL := { reclassify | pipe | drop | continue | pass | goto chain CHAIN_INDEX }

DESCRIPTION

L'action vlan permet d'effectuer un en- ou décapsulage 802.1Q sur un paquet, reflété par les modes d'opération POP, PUSH et MODIFY. Le mode POP est simple, aucune information supplémentaire n'étant requise pour simplement supprimer l'encapsulation VLAN la plus externe. Les modes PUSH et MODIFY nécessitent au moins un VLANID et permettent de choisir optionnellement le VLANPROTO à utiliser.

L'action vlan peut également être utilisée pour ajouter ou supprimer l'en-tête Ethernet de base. Le mode pop_eth, qui ne prend aucun argument, est utilisé pour supprimer l'en-tête Ethernet de base. Tous les VLAN existants doivent avoir été préalablement supprimés. L'opération inverse, l'ajout d'un en-tête Ethernet de base, est effectuée avec le mode push_eth. Dans ce cas, le paquet ne doit pas avoir d'en-tête MAC (l'empilement d'en-têtes MAC n'est pas autorisé). Ce mode est principalement utile lorsqu'une action précédente a encapsulé la trame originale entière derrière un en-tête réseau et qu'il est nécessaire de préfixer un en-tête Ethernet avant de transmettre le paquet résultant.

OPTIONS

pop
Mode de décapsulation, aucun argument supplémentaire n'est autorisé.
push
Mode d'encapsulation. Nécessite au moins l'option id.
modify
Mode de remplacement. La balise 802.1Q existante est remplacée. Nécessite au moins l'option id.
pop_eth
Mode de décapsulation de l'en-tête Ethernet. Ne fonctionne qu'avec un en-tête Ethernet simple : les VLAN, s'il y en a, doivent être supprimés au préalable.
push_eth
Mode d'encapsulation de l'en-tête Ethernet. L'Ethertype est automatiquement défini en utilisant le type d'en-tête réseau. L'enchaînement des en-têtes Ethernet n'est pas autorisé : le paquet ne doit pas avoir d'en-tête MAC lors de l'utilisation de ce mode. Nécessite les options dst_mac et src_mac.
id VLANID
Spécifie l'ID VLAN dans lequel encapsuler. VLANID est un entier de 16 bits non signé, le format est détecté automatiquement (par exemple, préfixez avec '0x' pour une interprétation hexadécimale, etc.).
protocol VLANPROTO
Choisit le protocole VLAN à utiliser. Au moment de la rédaction, le noyau accepte uniquement 802.1Q ou 802.1ad.
priority VLANPRIO
Choisit la priorité VLAN à utiliser. Nombre décimal dans la plage de 0 à 7.
dst_mac LLADDR
Choisit l'adresse MAC de destination à utiliser.
src_mac LLADDR
Choisit l'adresse MAC source à utiliser.
CONTROL
Comment continuer après l'exécution de cette action.
reclassify
Redémarre la classification en sautant vers le premier filtre attaché au parent de cette action.
pipe
Continue avec l'action suivante, c'est le comportement par défaut.
drop
Le paquet sera supprimé sans exécuter d'autres actions.
continue
Continue la classification avec le filtre suivant en ligne.
pass
Retourne au qdisc appelant pour le traitement du paquet. Ceci termine le processus de classification.

EXEMPLES

L'exemple suivant encapsule les paquets ICMP entrants sur eth0 provenant de 10.0.0.2 dans l'ID VLAN 123 :

#tc qdisc add dev eth0 handle ffff: ingress
#tc filter add dev eth0 parent ffff: pref 11 protocol ip \
	u32 match ip protocol 1 0xff flowid 1:1 \
	    match ip src 10.0.0.2 flowid 1:1 \
	action vlan push id 123

Voici un exemple de la fonction pop : Les paquets VLAN entrants sur eth0 sont décapsulés et le processus de classification est ensuite redémarré pour le paquet simple :

#tc qdisc add dev eth0 handle ffff: ingress
#tc filter add dev $ETH parent ffff: pref 1 protocol 802.1Q \
	u32 match u32 0 0 flowid 1:1 \
	action vlan pop reclassify

Pour un exemple des modes pop_eth et push_eth, voir tc-mpls(8).
