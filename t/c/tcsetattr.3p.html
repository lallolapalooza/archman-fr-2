TCSETATTR(3P) Manuel du programmeur POSIX TCSETATTR(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

tcsetattr — définir les paramètres associés au terminal

SYNTAXE

#include <termios.h>
int tcsetattr(int fildes, int optional_actions,
    const struct termios *termios_p);

DESCRIPTION

La fonction tcsetattr() définit les paramètres associés au terminal désigné par le descripteur de fichier ouvert fildes (un descripteur de fichier ouvert associé à un terminal) à partir de la structure termios référencée par termios_p comme suit :

*
Si optional_actions est TCSANOW, le changement s'effectue immédiatement.
*
Si optional_actions est TCSADRAIN, le changement s'effectue après que toutes les sorties écrites dans fildes ont été transmises. Cette fonction doit être utilisée lors de la modification de paramètres affectant la sortie.
*
Si optional_actions est TCSAFLUSH, le changement s'effectue après que toutes les sorties écrites dans fildes ont été transmises, et toutes les entrées reçues mais non lues jusqu'alors serontDiscardées avant que le changement ne soit effectué.

Si le débit en bauds de sortie stocké dans la structure termios pointée par termios_p est le débit en bauds zéro, B0, les lignes de contrôle du modem ne seront plus affirmées. Normalement, cela déconnectera la ligne.

Si le débit en bauds d'entrée stocké dans la structure termios pointée par termios_p est 0, le débit en bauds d'entrée donné au matériel est le même que le débit en bauds de sortie stocké dans la structure termios.

La fonction tcsetattr() renvoie succès si elle a pu effectuer l'une des actions demandées, même si certaines des actions demandées n'ont pas pu être effectuées. Elle définit tous les attributs que l'implémentation supporte comme demandé et laisse tous les attributs non supportés par l'implémentation inchangés. Si aucune partie de la requête ne peut être honorée, elle renvoie -1 et définit errno à [EINVAL]. Si les débits en bauds d'entrée et de sortie diffèrent et constituent une combinaison non supportée, aucun des débits en bauds ne sera modifié. Un appel ultérieur à tcgetattr() renverra l'état réel du périphérique terminal (reflétant les changements effectués et non effectués lors de l'appel précédent à tcsetattr()). La fonction tcsetattr() ne modifie en aucun cas les valeurs trouvées dans la structure termios.

L'effet de tcsetattr() est indéfini si la valeur de la structure termios pointée par termios_p n'a pas été dérivée du résultat d'un appel à tcgetattr() sur fildes; une application ne devrait modifier que les champs et les drapeaux définis par ce volume de POSIX.1-2017 entre l'appel à tcgetattr() et tcsetattr(), laissant tous les autres champs et drapeaux inchangés.

Aucune action définie par ce volume de POSIX.1-2017, autre qu'un appel à tcsetattr(), une fermeture du dernier descripteur de fichier dans le système associé à ce périphérique terminal, ou une ouverture du premier descripteur de fichier dans le système associé à ce périphérique terminal (en utilisant le drapeau O_TTY_INIT s'il est non nul et que le périphérique n'est pas un pseudo-terminal), ne provoquera le changement des attributs du terminal définis par ce volume de POSIX.1-2017.

Si tcsetattr() est appelée depuis un processus qui fait partie d'un groupe de processus en arrière-plan sur un fildes associé à son terminal de contrôle :

*
Si le thread appelant bloque les signaux SIGTTOU ou si le processus ignore SIGTTOU, l'opération s'achève normalement et aucun signal n'est envoyé.
*
Sinon, un signal SIGTTOU sera envoyé au groupe de processus.

VALEUR DE RETOUR

En cas de succès, 0 est renvoyé. Sinon, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

La fonction tcsetattr() échouera si :

EBADF
L'argument fildes n'est pas un descripteur de fichier valide.
EINTR
Un signal a interrompu tcsetattr().
EINVAL
L'argument optional_actions n'est pas une valeur supportée, ou une tentative a été faite pour changer un attribut représenté dans la structure termios à une valeur non supportée.
EIO
Le groupe de processus de l'écriture est orphelin, le thread appelant ne bloque pas SIGTTOU et le processus n'ignore pas SIGTTOU.
ENOTTY
Le fichier associé à fildes n'est pas un terminal.

UTILISATION PAR L'APPLICATION

Si vous essayez de changer les débits en bauds, les applications devraient appeler tcsetattr() puis tcgetattr() afin de déterminer quels débits en bauds ont été réellement sélectionnés.

En général, il y a deux raisons pour qu'une application modifie les paramètres associés à un périphérique terminal :

1.
Le périphérique possède déjà des paramètres fonctionnels, mais l'application a besoin d'un comportement différent, tel qu'un mode non canonique au lieu d'un mode canonique. L'application définit (ou efface) seulement quelques drapeaux ou valeurs c_cc[]. Typiquement, le périphérique terminal dans ce cas est soit le terminal de contrôle du processus, soit un pseudo-terminal.
2.
Le périphérique est un modem ou un équipement similaire connecté par une ligne série, et il n'était pas ouvert avant que l'application ne l'ouvre. Dans ce cas, l'application doit initialiser tous les paramètres "à partir de zéro". Cependant, étant donné que la structure termios peut inclure des paramètres standard et non standard, l'application ne peut pas simplement initialiser toute la structure de manière arbitraire (par exemple, en utilisant memset()) car cela pourrait entraîner la définition incorrecte de certains paramètres non standard, résultant en un comportement non conforme du périphérique terminal. Inversement, l'application ne peut pas simplement définir les paramètres standard, en supposant que les paramètres non standard auront déjà des valeurs appropriées, car le périphérique pourrait avoir été utilisé précédemment avec des paramètres non conformes (et certaines implémentations conservent les paramètres d'une utilisation à l'autre). La solution consiste à ouvrir le périphérique terminal en utilisant le drapeau O_TTY_INIT pour initialiser le périphérique terminal avec des paramètres conformes, obtenir ces paramètres en utilisant tcgetattr(), puis définir tous les paramètres standard aux paramètres souhaités.

RATIONNEMENT

La fonction tcsetattr() peut être interrompue dans les situations suivantes :

*
Elle est interrompue en attendant que la sortie se vide.
*
Elle est appelée depuis un processus dans un groupe de processus en arrière-plan et SIGTTOU est intercepté.

Voir aussi la section RATIONNEMENT de tcgetattr().

ORIENTATIONS FUTURES

L'utilisation d'un débit en bauds d'entrée de 0 pour définir le débit d'entrée égal au débit de sortie pourrait ne pas être supportée dans une future version de ce volume de POSIX.1-2017.
