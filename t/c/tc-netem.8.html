NOM

netem - Émulateur réseau

SYNOPSIS

tc qdisc ... dev DEVICE ] add netem OPTIONS

OPTIONS := [ LIMIT ] [ DELAY ] [ LOSS ] [ CORRUPT ] [ DUPLICATION ] [ REORDERING ] [ RATE ] [ SLOT ] [ SEED ]

LIMIT := limit packets

DELAY := delay TIME [ JITTER [ CORRELATION ]]]
[ distribution { uniform | normal | pareto | paretonormal } ]

LOSS := loss { random PERCENT [ CORRELATION ] |
state p13 [ p31 [ p32 [ p23 [ p14]]]] |
gemodel p [ r [ 1-h [ 1-k ]]] } [ ecn ]

CORRUPT := corrupt PERCENT [ CORRELATION ]]

DUPLICATION := duplicate PERCENT [ CORRELATION ]]

REORDERING := reorder PERCENT [ CORRELATION ] [ gap DISTANCE ]

RATE := rate RATE [ PACKETOVERHEAD [ CELLSIZE [ CELLOVERHEAD ]]]]

SLOT := slot { MIN_DELAY [ MAX_DELAY ] |
distribution { uniform | normal | pareto | paretonormal | FILE } DELAY JITTER }
[ packets PACKETS ] [ bytes BYTES ]

SEED := seed VALUE

DESCRIPTION

La discipline de file d'attente netem fournit des fonctionnalités d'émulation réseau pour tester des protocoles en émulant les propriétés des réseaux du monde réel.

La discipline de file d'attente fournit une ou plusieurs dégradations réseau aux paquets telles que : délai, perte, duplication et corruption de paquets.

OPTIONS

limit COUNT
Limite le nombre maximal de paquets que le qdisc peut contenir lors de l'application d'un délai.
delay
TIME [ JITTER [ CORRELATION ]]]
Retarde les paquets avant leur envoi. Les paramètres optionnels permettent d'introduire une variation du délai et une corrélation. Les valeurs de délai et de gigue sont exprimées en millisecondes ; la corrélation est définie en spécifiant un pourcentage de l'impact du délai précédent sur la valeur aléatoire actuelle.
distribution TYPE
Spécifie un schéma pour la distribution des délais.
uniform
Utilise une distribution uniforme des délais de paquets.
normal
Utilise une distribution gaussienne des délais. Parfois appelée Courbe en cloche.
pareto
Utilise une distribution de Pareto pour les délais de paquets. Ceci est utile pour émuler des distributions à longue traîne.
paretonormal
Ceci est un mélange des distributions pareto et normal qui possède les propriétés à la fois de la courbe en cloche et de la longue traîne.
loss MODEL
Supprime des paquets en fonction d'un modèle de perte. MODEL peut être l'un des suivants :
random PERCENT
Chaque perte de paquet est indépendante.
state P13 [ P31 [ P32 [ P23 P14 ]]]
Utilise une chaîne de Markov à 4 états pour décrire la perte de paquets.
P13 est la probabilité de perte de paquet. Les paramètres optionnels étendent le modèle à 2 états P31, 3 états P23, P32 et 4 états P14.

Les états de la chaîne de Markov sont :

1
bonne réception de paquet (aucune perte).
2
bonne réception au sein d'une rafale.
3
pertes en rafale.
4
pertes indépendantes.
gemodel PERCENT [ R [ 1-H [ 1-K ]]]
Utilise un modèle de Gilbert-Elliot (perte en rafale) basé sur :
PERCENT
probabilité de passer à un état "mauvais" (perte).
R
probabilité de sortir de l'état "mauvais".
1-H
probabilité de perte dans l'état "mauvais".
1-K
probabilité de perte dans l'état "bon".
ecn
Utilise le protocole Explicit Congestion Notification (ECN) pour marquer les paquets au lieu de les supprimer. Un modèle de perte doit être utilisé pour activer cette option.
corrupt PERCENT
Modifie le contenu du paquet à une position aléatoire en fonction du PERCENT.
duplicate PERCENT
Crée une copie du paquet avant sa mise en file d'attente.
reorder PERCENT
Modifie l'ordre des paquets dans la file d'attente.
gap DISTANCE
Envoie certains paquets immédiatement. Les premiers paquets (DISTANCE - 1) sont retardés et le paquet suivant est envoyé immédiatement.
rate RATE [ PACKETOVERHEAD [ CELLSIZE [ CELLOVERHEAD ]]]
Retarde les paquets en fonction de la taille du paquet pour émuler une vitesse de liaison fixe. Paramètres optionnels :
PACKETOVERHEAD
Spécifie une surcharge par paquet en octets. Utilisé pour simuler des en-têtes supplémentaires de couche liaison. Une valeur négative peut être utilisée pour simuler lorsque l'en-tête Ethernet est supprimé (par exemple, -14) ou que la compression d'en-tête est utilisée.
CELLSIZE
Simule des schémas de couche liaison comme ATM.
CELLOVERHEAD
Spécifie la surcharge par cellule.

Le ralentissement du débit est influencé par plusieurs facteurs, notamment la granularité de l'horloge du noyau. Cela se manifestera par une compression artificielle des paquets (rafales).

slot MIN_DELAY [ MAX_DELAY ]
Permet d'émuler des réseaux à créneaux horaires. Diffère la livraison des paquets accumulés à l'intérieur d'un créneau. Chaque créneau disponible est configuré avec un délai minimum pour l'acquisition et un délai maximum optionnel.
slot distribution
Permet la configuration basée sur une distribution similaire à l'option distribution pour les délais de paquets.

Ces options de créneaux peuvent fournir une approximation grossière des MACs en rafale tels que DOCSIS, WiFi et LTE.

L'émulation de créneau est limitée par plusieurs facteurs : la granularité de l'horloge du noyau, comme pour le débit, et les tentatives de livrer de nombreux paquets dans un créneau seront étalées par la résolution temporelle, ainsi que par la bande passante native sous-jacente.

Il est possible de combiner la gestion par créneaux avec un débit, auquel cas des comportements complexes où soit le débit, soit les limites de créneaux par octets ou par paquets par créneau, régissent le débit réel délivré.

seed VALUE
Spécifie une graine pour guider et reproduire les événements aléatoires de perte ou de corruption générés.

LIMITATIONS

Netem est limité par la granularité du chronomètre dans le noyau. Le débit et le délai peuvent être affectés par les interruptions d'horloge.

Le mélange de formes de réorganisation peut entraîner des résultats inattendus. Pour que toute méthode de réorganisation fonctionne, un certain délai est nécessaire. Si le délai est inférieur au temps d'arrivée inter-paquets, aucune réorganisation ne sera observée. En raison de mécanismes tels que TSQ (TCP Small Queues), pour que les résultats de performance TCP soient réalistes, netem doit être placé sur l'entrée de l'hôte récepteur.

NOM

tc-netem - Network Emulator

SYNTAXE

tc qdisc add ... netem ...
tc qdisc change ... netem ...

DESCRIPTION

Netem est utilisé pour introduire des défauts dans le réseau afin de tester les applications sur des réseaux non idéaux.

Les défauts qui peuvent être introduits sont :

  • Un délai fixe ou aléatoire.
  • Une perte de paquets aléatoire.
  • Une duplication de paquets aléatoire.
  • Un réordonnancement aléatoire de paquets.
  • Une corruption de paquets aléatoire.

Ces défauts peuvent être combinés et appliqués de manière aléatoire ou avec une corrélation. Netem est une discipline de mise en file d'attente qui est ajoutée à une interface réseau. Elle intercepte les paquets sortants et leur applique les défauts configurés.

OPTIONS

Les options suivantes peuvent être utilisées avec netem :

delay
Délai fixe ou aléatoire. Peut être spécifié comme suit :
  • delay base-time [variation] [probability] [distribution]
    • base-time : Délai de base en millisecondes.
    • variation : Variation aléatoire du délai en millisecondes. Si omise, la variation est 0.
    • probability : Probabilité que ce délai soit appliqué (par défaut 1.0).
    • distribution : Distribution du délai ('normal' pour une distribution normale, 'pareto' pour une distribution de Pareto, 'full_distro' pour une distribution complète). Par défaut, une distribution uniforme est utilisée.
loss
Perte de paquets aléatoire. Peut être spécifié comme suit :
  • loss probability [correlation]
    • probability : Probabilité de perte de paquet en pourcentage (0.1% = 0.001).
    • correlation : Corrélation en pourcentage. Si spécifié, la probabilité de perte du paquet suivant est influencée par la perte du paquet actuel.
duplicate
Duplication de paquets aléatoire.
  • duplicate probability [correlation]
    • probability : Probabilité de duplication de paquet en pourcentage.
    • correlation : Corrélation en pourcentage.
reorder
Réordonnancement aléatoire de paquets.
  • reorder probability correlation
    • probability : Probabilité de réordonnancement en pourcentage.
    • correlation : Corrélation en pourcentage.
corruption
Corruption de paquets aléatoire.
  • corruption probability [correlation]
    • probability : Probabilité de corruption en pourcentage.
    • correlation : Corrélation en pourcentage.
rate
Contrôle du débit des paquets.
  • rate rate [overhead] [cellsize] [celloverhead]
    • rate : Débit en bits par seconde (par défaut : 5000).
    • overhead : Surcharge par paquet en octets (par défaut : 0).
    • cellsize : Taille de cellule en octets (par défaut : 0).
    • celloverhead : Surcharge par cellule en octets (par défaut : 0).
gap number delay time
Réordonnancement de paquets basé sur une séquence fixe. Le N-ième paquet est envoyé immédiatement, les autres sont retardés de time.

LIMITATIONS

Il est possible de combiner netem avec d'autres qdisc mais cela ne fonctionnera pas toujours car netem utilise le bloc de contrôle skb pour définir les délais.

EXEMPLES

# tc qdisc add dev eth0 root netem delay 100ms
Ajoute un délai fixe à tous les paquets sortants sur le périphérique eth0. Chaque paquet aura un délai ajouté de 100 ms ± 10 ms.
# tc qdisc change dev eth0 root netem delay 100ms 10ms 25%
Ceci provoque un délai ajouté de 100 ms ± 10 ms et la valeur du délai du paquet suivant sera biaisée de 25% par rapport au délai le plus récent. Ce n'est pas une corrélation statistique réelle, mais une approximation.
# tc qdisc change dev eth0 root netem delay 100ms 20ms distribution normal
Ceci retarde les paquets selon une distribution normale (courbe en cloche) sur une plage de 100 ms ± 20 ms.
# tc qdisc change dev eth0 root netem loss 0.1%
Ceci provoque la perte aléatoire de 1/10ème de pourcent (soit 1 sur 1000) des paquets.

Une corrélation optionnelle peut également être ajoutée. Ceci rend le générateur de nombres aléatoires moins aléatoire et peut être utilisé pour émuler des pertes de paquets en rafales.

# tc qdisc change dev eth0 root netem duplicate 1%
Ceci provoque la duplication d'un pourcent des paquets envoyés sur eth0.
# tc qdisc change dev eth0 root netem loss 0.3% 25%
Ceci provoquera la perte de 0.3% des paquets, et la probabilité de chaque paquet successif dépendra de celle du paquet précédent biaisée de 25%.

Il existe deux façons différentes de spécifier le réordonnancement. La méthode gap utilise une séquence fixe et réordonnance tous les N-ièmes paquets.

# tc qdisc change dev eth0 root netem gap 5 delay 10ms
Ceci fait que tous les 5ème (10ème, 15ème, etc.) paquets sont envoyés immédiatement et tous les autres paquets sont retardés de 10 ms. Ceci est prévisible et utile pour les tests de protocoles de base comme le réassemblage.

La forme reorder utilise un pourcentage de paquets à mal ordonner.

# tc qdisc change dev eth0 root netem delay 10ms reorder 25% 50%

Dans cet exemple, 25% des paquets (avec une corrélation de 50%) seront envoyés immédiatement, les autres seront retardés de 10 ms.

Les paquets seront également réordonnés si le jitter est suffisamment important.

# tc qdisc change dev eth0 root netem delay 100ms 75ms
Si le premier paquet reçoit un délai aléatoire de 100 ms (100 ms de base - 0 ms de jitter) et que le second paquet est envoyé 1 ms plus tard et reçoit un délai de 50 ms (100 ms de base - 50 ms de jitter) ; le second paquet sera envoyé en premier. Ceci est dû au fait que la discipline de mise en file d'attente tfifo à l'intérieur de netem, conserve les paquets dans l'ordre selon le temps d'envoi.

Si vous ne souhaitez pas ce comportement, remplacez la discipline de mise en file d'attente interne tfifo par une simple discipline de file d'attente FIFO.

# tc qdisc add dev eth0 root handle 1: netem delay 10ms 100ms
# tc qdisc add dev eth0 parent 1:1 pfifo limit 1000

Exemple d'utilisation du contrôle de débit et de la taille des cellules.

# tc qdisc add dev eth0 root netem rate 5kbit 20 100 5
Retarde tous les paquets sortants sur le périphérique eth0 avec un débit de 5 kbit, une surcharge par paquet de 20 octets, une taille de cellule de 100 octets et une surcharge par cellule de 5 octets.

Il est possible d'appliquer sélectivement des dégradations en utilisant la classification du trafic.

# tc qdisc add dev eth0 root handle 1: prio
# tc qdisc add dev eth0 parent 1:3 handle 30:    tbf rate 20kbit buffer 1600 limit  3000
# tc qdisc add dev eth0 parent 30:1 handle 31:    netem delay 200ms 10ms distribution normal
# tc filter add dev eth0 protocol ip parent 1:0 prio 3 u32    match ip dst 65.172.181.4/32 flowid 1:3
Cet exemple utilise une discipline de mise en file d'attente prioritaire ; un TBF est ajouté pour le contrôle de débit ; et un simple délai netem. Un filtre classe tous les paquets destinés à 65.172.181.4 comme étant de priorité 3.
