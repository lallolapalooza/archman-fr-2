NOM

IFE - encapsuler/désencapsuler des métadonnées

SYNTAXE


tc ... action ife DIRECTION [ ACTION ] [ dst DMAC ] [ src SMAC ] [ type TYPE ] [ CONTROLE ] [ index INDEX ]

DIRECTION := { decode | encode }

ACTION := { allow ATTRIBUT | use ATTRIBUT valeur }

ATTRIBUT := { mark | prio | tcindex }

CONTROLE := { reclassify | use | pipe | drop | continue | ok | goto chain INDEX_CHAINE }

DESCRIPTION

L'action ife permet à un expéditeur d'encapsuler des métadonnées arbitraires, qui sont ensuite désencapsulées par le destinataire. L'expéditeur fonctionne en mode d'encodage et le destinataire en mode de décodage. L'expéditeur et le destinataire doivent spécifier le même ethertype. À l'avenir, un ethertype enregistré pourra être disponible par défaut.

OPTIONS

decode
Pour le destinataire ; décode les métadonnées si le paquet correspond.
encode
Pour l'expéditeur. Encode les métadonnées spécifiées si le paquet correspond.
allow
Mode d'encodage uniquement. Permet l'encodage des métadonnées spécifiées.
use
Mode d'encodage uniquement. Force l'encodage statique des métadonnées spécifiées.
mark [
valeur_u32 ] La valeur à définir pour la marque skb. La valeur u32 est requise uniquement lorsque use est spécifié. Si la valeur de mark est zéro, elle ne sera pas encodée, et les statistiques "overlimits" seront incrémentées et l'action CONTROLE sera effectuée.
prio [
valeur_u32 ] La valeur à définir pour la priorité dans la structure skb. La valeur u32 est requise uniquement lorsque use est spécifié.
tcindex [
valeur_u16 ] Valeur à définir pour l'index de contrôle de trafic dans la structure skb. La valeur u16 est requise uniquement lorsque use est spécifié.
dmac DMAC
smac SMAC
Adresse MAC de destination ou source optionnelle de six octets à encoder.
type TYPE
Ethertype optionnel de 16 bits à encoder. S'il n'est pas spécifié, la valeur 0xED3E sera utilisée.
CONTROLE
Action à entreprendre après un encodage/décodage.
index INDEX
Attribue un identifiant unique à cette action au lieu de laisser le noyau en choisir un automatiquement. INDEX est un entier non signé de 32 bits supérieur à zéro.

EXEMPLES

Du côté du destinataire, correspond aux paquets avec l'ethertype 0xdead et redémarre la classification afin qu'elle corresponde à l'ICMP lors de la règle suivante, à la priorité 3 :

# tc qdisc add dev eth0 handle ffff: ingress
# tc filter add dev eth0 parent ffff: prio 2 protocol 0xdead \
	u32 match u32 0 0 flowid 1:1 \
	action ife decode reclassify
# tc filter add dev eth0 parent ffff: prio 3 protocol ip \
	u32 match ip protocol 0xff flowid 1:1 \
	action continue

Correspondance avec la marque skb de 17 :

# tc filter add dev eth0 parent ffff: prio 4 protocol ip \
	handle 0x11 fw flowid 1:1 \
	action ok

Configurez le côté expéditeur pour encoder pour les filtres ci-dessus. Utilisez une adresse IP de destination de 192.168.122.237/24, puis étiquetez avec la marque skb de 17 en décimal. Encodez le paquet avec l'ethertype 0xdead, ajoutez skb->mark à la liste autorisée des métadonnées à envoyer, et réécrivez l'adresse MAC de destination à 02:15:15:15:15:15.

# tc qdisc add dev eth0 root handle 1: prio
# tc filter add dev eth0 parent 1: protocol ip prio 10 u32 \
	match ip dst 192.168.122.237/24 \
	match ip protocol 1 0xff \
	flowid 1:2 \
	action skbedit mark 17 \
	action ife encode \
	type 0xDEAD \
	allow mark \
	dst 02:15:15:15:15:15
