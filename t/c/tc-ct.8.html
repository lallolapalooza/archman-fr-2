NOM

ct - action de suivi de connexion tc

SYNTAXE


tc ... action ct commit [ force ] [ zone ZONE ] [ mark MASKED_MARK ] [ label MASKED_LABEL ] [ nat NAT_SPEC ]

tc ... action ct [ nat ] [ zone ZONE ]

tc ... action ct clear

DESCRIPTION

L'action ct est une action tc pour envoyer des paquets et interagir avec le module de suivi de connexion netfilter.

Elle peut (comme indiqué dans la syntaxe, dans l'ordre) :

Envoyer le paquet à conntrack, et valider la connexion, tout en configurant une marque de 32 bits, une étiquette de 128 bits et le NAT src/dst.

Envoyer le paquet à conntrack, qui marquera le paquet avec l'état de la connexion et les métadonnées configurées (marque/étiquette), et exécutera le NAT précédemment configuré.

Effacer l'état de suivi de connexion et les métadonnées du paquet.

OPTIONS

zone ZONE
Spécifie un numéro de zone conntrack auquel envoyer le paquet.
mark MASKED_MARK
Spécifie une marque masquée de 32 bits à définir pour la connexion (valide uniquement avec commit).
label MASKED_LABEL
Spécifie une étiquette masquée de 128 bits à définir pour la connexion (valide uniquement avec commit).
nat NAT_SPEC
Où NAT_SPEC := {src|dst} addr addr1[-addr2] [port port1[-port2]]

Spécifie le NAT src/dst et la plage à configurer pour la connexion (valide uniquement avec commit).

src/dst - configure le NAT src ou dst
addr1/addr2 - Adresses IPv4/IPv6
port1/port2 - Numéros de port
nat
Restaure tout NAT précédemment configuré.
clear
Supprime tout état conntrack et métadonnées (marque/étiquette) du paquet (doit être la seule option spécifiée).
force
Force la direction conntrack pour les connexions précédemment validées, de sorte que la direction actuelle devienne la direction d'origine (valide uniquement avec commit).

EXEMPLES

Exemple montrant un pare-feu NAT dans la zone conntrack 2, et l'utilisation de la marque conntrack :

#Ajouter la qdisc d'entrée sur les interfaces eth0 et eth1
$ tc qdisc add dev eth0 ingress
$ tc qdisc add dev eth1 ingress
#Configurer les filtres sur eth0, permettant d'ouvrir de nouvelles connexions dans la zone 2, et de faire du NAT src + marque pour chaque nouvelle connexion
$ tc filter add dev eth0 ingress prio 1 chain 0 proto ip flower ip_proto tcp ct_state -trk \
action ct zone 2 pipe action goto chain 2
$ tc filter add dev eth0 ingress prio 1 chain 2 proto ip flower ct_state +trk+new \
action ct zone 2 commit mark 0xbb nat src addr 5.5.5.7 pipe action mirred egress redirect dev eth1
$ tc filter add dev eth0 ingress prio 1 chain 2 proto ip flower ct_zone 2 ct_mark 0xbb ct_state +trk+est \
action ct nat pipe action mirred egress redirect dev eth1
#Configurer les filtres sur eth1, ne permettant que les connexions établies de la zone 2 de passer, et le NAT inverse (NAT dst dans ce cas)
$ tc filter add dev eth1 ingress prio 1 chain 0 proto ip flower ip_proto tcp ct_state -trk \
action ct zone 2 pipe action goto chain 1
$ tc filter add dev eth1 ingress prio 1 chain 1 proto ip flower ct_zone 2 ct_mark 0xbb ct_state +trk+est \
action ct nat pipe action mirred egress redirect dev eth0
