NOM

drr — ordonnanceur de liste d'attente à déficit

SYNTAXE

tc qdisc ... add drr [ quantum octets ]

DESCRIPTION

L'ordonnanceur Deficit Round Robin (DRR) est une discipline de mise en file d'attente classée, servant de remplacement plus flexible au Stochastic Fair Queuing (SFQ).

Contrairement à SFQ, il n'y a pas de files d'attente intégrées ; vous devez ajouter des classes puis configurer des filtres pour classifier les paquets en conséquence. Cela peut être utile par exemple pour utiliser des qdiscs RED avec des paramètres différents pour un trafic particulier. Il n'y a pas de classe par défaut ; si un paquet ne peut pas être classifié, il est rejeté.

ALGORITHME

Chaque classe se voit attribuer un compteur de déficit, initialisé à quantum.

DRR maintient une liste interne (non visible) de classes dont les qdiscs ne sont pas vides. Cette liste est utilisée pour le défilement. Un paquet est défilé de la classe en tête de liste si la taille du paquet est inférieure ou égale au compteur de déficit. Si le compteur est trop petit, il est augmenté de quantum et l'ordonnanceur passe à la classe suivante dans la liste des classes actives.

PARAMETRES

quantum
Quantité d'octets qu'une classe est autorisée à défiler avant que l'ordonnanceur ne passe à la classe suivante. La valeur par défaut est l'MTU de l'interface. La valeur minimale est 1.

EXEMPLE & UTILISATION

Pour attacher à l'interface eth0, en utilisant l'MTU de l'interface comme quantum :

# tc qdisc add dev eth0 handle 1 root drr

Ajout de deux classes :

# tc class add dev eth0 parent 1: classid 1:1 drr
# tc class add dev eth0 parent 1: classid 1:2 drr

Vous devez également ajouter au moins un filtre pour classifier les paquets.

# tc filter add dev eth0 protocol .. classid 1:1

Comme SFQ, DRR n'est utile que lorsqu'il possède la file d'attente ; c'est un ordonnanceur pur et il ne retarde pas les paquets. L'attachement de qdiscs non conservateurs de travail comme tbf à celui-ci n'a pas de sens ; d'autres qdiscs dans la liste des classes actives deviendront également inactifs jusqu'à ce que l'opération de défilement réussisse. Intégrez DRR dans un autre qdisc comme HTB ou HFSC pour vous assurer qu'il possède la file d'attente.

Vous pouvez imiter le comportement de SFQ en assignant des paquets aux classes attachées en utilisant le filtre de flux :

tc qdisc add dev .. drr

for i in .. 1024;do
tc class add dev .. classid $handle:$(print %x $i)
tc qdisc add dev .. fifo limit 16
done

tc filter add .. protocol ip .. $handle flow hash keys src,dst,proto,proto-src,proto-dst divisor 1024 perturb 10

SOURCE

o
M. Shreedhar et George Varghese "Efficient Fair Queuing using Deficit Round Robin", Proc. SIGCOMM 95.

NOTES

Cette implémentation ne rejette pas les paquets de la file d'attente la plus longue en cas de dépassement, car les limites sont gérées par les qdiscs enfants individuels.
