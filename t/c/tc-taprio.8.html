NOM

TAPRIO - Ordonnanceur basé sur les priorités temporelles

SYNTAXE

tc qdisc ... dev dev parent classid [ handle major: ] taprio num_tc tcs map P0 P1 P2 ... queues count1@offset1 count2@offset2 ... base-time base-time clockid clockid sched-entry <commande 1> <masque de grille 1> <intervalle 1> sched-entry <commande 2> <masque de grille 2> <intervalle 2> sched-entry <commande 3> <masque de grille 3> <intervalle 3> sched-entry <commande N> <masque de grille N> <intervalle N> [ max-sdu <queueMaxSDU[TC 0]> <queueMaxSDU[TC 1]> <queueMaxSDU[TC N]> ] [ fp <adminStatus[TC 0]> <adminStatus[TC 1]> <adminStatus[TC N]> ]

DESCRIPTION

Le qdisc TAPRIO implémente une version simplifiée de la machine d'état d'ordonnancement définie par la norme IEEE 802.1Q-2018 Section 8.6.9, qui permet la configuration d'une séquence d'états de grille, où chaque état de grille autorise le trafic sortant pour un sous-ensemble (potentiellement vide) des classes de trafic.

La manière dont le trafic est mappé aux différentes files matérielles est similaire à mqprio(8), ainsi les paramètres map et queues ont la même signification.

Les autres paramètres spécifient l'ordonnancement et le moment où il doit commencer (il peut se comporter comme si l'ordonnancement avait commencé dans le passé).

PARAMÈTRES

num_tc
Nombre de classes de trafic à utiliser. Jusqu'à 16 classes sont supportées.
map

La carte de priorité vers classe de trafic. Mappe les priorités 0..15 vers une classe de trafic spécifiée. Voir mqprio(8) pour plus de détails.
queues

Fournit le nombre et le décalage de la plage de files pour chaque classe de trafic. Au format count@offset. Les plages de files pour chaque classe de trafic ne peuvent pas se chevaucher et doivent former une plage contiguë de files.
base-time

Spécifie l'instant en nanosecondes, en utilisant la référence de clockid, définissant le moment où l'ordonnancement commence. Si 'base-time' est un moment dans le passé, l'ordonnancement commencera à

base-time + (N * cycle-time)

où N est le plus petit entier tel que le temps résultant soit supérieur à « maintenant », et « cycle-time » est la somme de tous les intervalles des entrées dans l'ordonnancement ;

clockid

Spécifie l'horloge à utiliser par le timer interne du qdisc pour mesurer le temps et planifier les événements. Cet argument doit être omis lors de l'utilisation de la fonctionnalité de déchargement complet (flags 0x2), car dans ce cas, le clockid est implicitement /dev/ptpN (où N est donné par ethtool -T eth0 | grep 'PTP Hardware Clock'), et donc pas nécessairement synchronisé avec le CLOCK_TAI du système.
sched-entry

Il peut y avoir plusieurs paramètres sched-entry dans un même ordonnancement. Chacun a le format

sched-entry <commande> <masque de grille> <intervalle>

.

<commande> supporte les valeurs suivantes :
S pour SetGateStates (Définir les états des grilles)
H pour Set-And-Hold-MAC (Définir et maintenir MAC)
R pour Set-And-Release-MAC (Définir et libérer MAC)
Ces commandes suivent la définition IEEE 802.1Q-2018 (Tableau 8-7).

<masque de grille> est un masque de bits où chaque bit est associé à une classe de trafic, de sorte que le bit 0 (le bit le moins significatif) étant « activé » signifie que la classe de trafic 0 est « active » pour cette entrée d'ordonnancement.

<intervalle> est une durée, en nanosecondes, qui spécifie combien de temps cet état défini par <commande> et <masque de grille> doit être maintenu avant de passer à l'entrée suivante.

flags

C'est un masque de bits qui spécifie différents modes pour taprio.
0x1
Active la fonctionnalité txtime-assist. Dans ce mode, taprio définira l'horodatage de transmission en fonction de l'intervalle pendant lequel le paquet doit être transmis. Il utilisera ensuite le qdisc etf(8) pour trier et transmettre les paquets au bon moment. Le second exemple peut servir de référence pour configurer ce mode.
0x2
Active la fonctionnalité de déchargement complet. Dans ce mode, taprio transmettra la liste de contrôle des grilles à la carte réseau, qui l'exécutera cycliquement en matériel. Lors de l'utilisation du déchargement complet, il n'est pas nécessaire de spécifier l'argument clockid.

Les fonctionnalités txtime-assist et de déchargement complet sont mutuellement exclusives, c'est-à-dire que définir les flags à 0x3 est invalide.

txtime-delay

Ce paramètre est spécifique au mode de déchargement txtime. Il spécifie le temps maximum qu'un paquet peut mettre pour atteindre la carte réseau depuis le qdisc taprio. La valeur doit toujours être supérieure au delta spécifié dans le qdisc etf(8).
max-sdu

Spécifie un tableau contenant au plus 16 éléments, un par classe de trafic, qui correspond au tableau queueMaxSDU de la norme IEEE 802.1Q-2018. Chaque élément du tableau représente la taille maximale de la charge utile L2 qui peut sortir de cette classe de trafic. Les éléments non remplis sont mis par défaut à 0. La valeur 0 signifie que la classe de trafic peut envoyer des paquets jusqu'à la taille MTU maximale du port.
fp

Sélectionne si les classes de trafic sont express ou préemptibles. Voir tc-mqprio(8) pour les détails.

EXEMPLES

L'exemple suivant montre comment un ordonnancement de trafic avec trois classes de trafic (« num_tc 3 »), qui sont séparées en différentes classes de trafic, nous allons appeler celles-ci TC 0, TC 1 et TC 2. Nous pouvons lire le paramètre « map » ci-dessous comme suit : le trafic avec la priorité 3 est classé comme TC 0, la priorité 2 est classée comme TC 1 et le reste est classé comme TC 2.

L'ordonnancement commencera à l'instant 1528743495910289987 en utilisant la référence CLOCK_TAI. L'ordonnancement est composé de trois entrées, chacune d'une durée de 300 µs.

# tc qdisc replace dev eth0 parent root handle 100 stab overhead 24 taprio \
              num_tc 3 \
              map 2 2 1 0 2 2 2 2 2 2 2 2 2 2 2 2 \
              queues 1@0 1@1 2@2 \
              base-time 1528743495910289987 \
              sched-entry S 01 300000 \
              sched-entry S 02 300000 \
              sched-entry S 04 300000 \
              clockid CLOCK_TAI

Voici un exemple pour activer le mode de déchargement txtime dans taprio. Voir etf(8) pour plus d'informations sur la configuration du qdisc ETF.

# tc qdisc replace dev eth0 parent root handle 100 stab overhead 24 taprio \
              num_tc 3 \
              map 2 2 1 0 2 2 2 2 2 2 2 2 2 2 2 2 \
              queues 1@0 1@0 1@0 \
              base-time 1528743495910289987 \
              sched-entry S 01 300000 \
              sched-entry S 02 300000 \
              sched-entry S 04 400000 \
              flags 0x1 \
              txtime-delay 200000 \
              clockid CLOCK_TAI
# tc qdisc replace dev $IFACE parent 100:1 etf skip_skb_check \
              offload delta 200000 clockid CLOCK_TAI

Ce qui suit est un ordonnancement en mode de déchargement complet. Le base-time est de 200 ns et le cycle-time est calculé implicitement comme la somme de toutes les durées des sched-entry (soit 20 µs + 20 µs + 60 µs = 100 µs). Bien que le base-time soit dans le passé, le matériel commencera à exécuter l'ordonnancement à un temps PTP égal au plus petit multiple entier de 100 µs, plus 200 ns, supérieur au temps PTP actuel de la carte réseau. De plus, le MTU pour la classe de trafic 5 est limité à 200 octets, de sorte que l'interférence qu'elle crée sur la classe de trafic 7 pendant la fenêtre temporelle où leurs grilles sont toutes deux ouvertes est limitée. L'interférence est déterminée par le temps de transmission du SDU maximum, plus la longueur de l'en-tête L2, plus la surcharge L1 (déterminée à partir du tableau de tailles spécifié à l'aide de tc-stab(8)).

# tc qdisc add dev eth0 parent root stab overhead
