DESCRIPTION

Tc est utilisé pour configurer le contrôle de trafic dans le noyau Linux. Le contrôle de trafic comprend les éléments suivants :

MODELAGE
Lorsque le trafic est modelé, son débit de transmission est sous contrôle. Le modelage peut être plus qu'une simple réduction de la bande passante disponible ; il est également utilisé pour lisser les pics de trafic afin d'améliorer le comportement du réseau. Le modelage se produit en sortie (egress).
ORDONNANCEMENT
En ordonnançant la transmission des paquets, il est possible d'améliorer l'interactivité pour le trafic qui en a besoin tout en garantissant la bande passante pour les transferts de masse. La réorganisation est aussi appelée priorisation et se produit uniquement en sortie (egress).
POLITIQUE
Alors que le modelage concerne la transmission du trafic, la politique concerne le trafic arrivant. La politique se produit donc en entrée (ingress).
REJET
Le trafic excédant une bande passante définie peut également être rejeté immédiatement, à la fois en entrée (ingress) et en sortie (egress).

Le traitement du trafic est contrôlé par trois types d'objets : les qdiscs, les classes et les filtres.

QDISCS

qdisc est l'abréviation de « queueing discipline » (discipline de mise en file d'attente) et il est essentiel à la compréhension du contrôle de trafic. Chaque fois que le noyau doit envoyer un paquet à une interface, il est mis en file d'attente dans le qdisc configuré pour cette interface. Immédiatement après, le noyau essaie de récupérer autant de paquets que possible du qdisc, pour les transmettre au pilote de la carte réseau.

Un qdisc simple est le « pfifo », qui n'effectue aucun traitement et est une simple file d'attente Premier Entré, Premier Sorti (First In, First Out). Il stocke cependant le trafic lorsque l'interface réseau ne peut pas le gérer momentanément.

CLASSES

Certains qdiscs peuvent contenir des classes, qui elles-mêmes contiennent d'autres qdiscs ; le trafic peut alors être mis en file d'attente dans n'importe lequel des qdiscs internes, qui se trouvent dans les classes. Lorsque le noyau essaie de dépiler un paquet d'un tel qdisc classful, il peut provenir de n'importe laquelle des classes. Un qdisc peut par exemple prioriser certains types de trafic en essayant de dépiler de certaines classes avant d'autres.

FILTRES

Un filtre est utilisé par un qdisc classful pour déterminer dans quelle classe un paquet sera mis en file d'attente. Chaque fois que du trafic arrive à une classe avec des sous-classes, il doit être classifié. Diverses méthodes peuvent être employées pour ce faire, dont les filtres font partie. Tous les filtres attachés à la classe sont appelés, jusqu'à ce que l'un d'eux retourne un verdict. Si aucun verdict n'est rendu, d'autres critères peuvent être disponibles. Ceci diffère selon le qdisc.

Il est important de noter que les filtres résident à l'intérieur des qdiscs ; ils ne sont pas maîtres de ce qui se passe.

Les filtres disponibles sont :

basic
Filtre les paquets en se basant sur une expression ematch. Voir tc-ematch(8) pour plus de détails.
bpf
Filtre les paquets en utilisant (e)BPF, voir tc-bpf(8) pour plus de détails.
cgroup
Filtre les paquets en se basant sur le groupe de contrôle de leur processus. Voir tc-cgroup(8) pour plus de détails.
flow, flower
Classificateurs basés sur les flux, filtrant les paquets en fonction de leur flux (identifié par des clés sélectionnables). Voir tc-flow(8) et tc-flower(8) pour plus de détails.
fw
Filtre basé sur fwmark. Mappe directement la valeur fwmark à la classe de trafic. Voir tc-fw(8).
route
Filtre les paquets en se basant sur la table de routage. Voir tc-route(8) pour plus de détails.
u32
Filtrage générique sur des données de paquet arbitraires, assisté par une syntaxe pour abstraire les opérations courantes. Voir tc-u32(8) pour plus de détails.
matchall
Filtre de contrôle de trafic qui correspond à chaque paquet. Voir tc-matchall(8) pour plus de détails.

QEVENTS

Les qdiscs peuvent déclencher des actions configurées par l'utilisateur lorsque certains événements intéressants se produisent dans le qdisc. Chaque qevent peut soit être inutilisé, soit avoir un bloc attaché. À ce bloc sont ensuite attachés des filtres en utilisant la syntaxe « tc block BLOCK_IDX ». Le bloc est exécuté lorsque le qevent associé au point d'attachement se produit. Par exemple, un paquet pourrait être rejeté ou retardé, etc., en fonction du qdisc et du qevent en question.

Par exemple :

tc qdisc add dev eth0 root handle 1: red limit 500K avpkt 1K \
qevent early_drop block 10
tc filter add block 10 matchall action mirred egress mirror dev eth1

codel
CoDel (prononcé « coddle ») est un algorithme de gestion de file d'attente active (AQM) adaptatif « sans réglages » (no-knobs) développé pour remédier aux lacunes de RED et de ses variantes.
[p|b]fifo
Le qdisc utilisable le plus simple, comportement pur First In, First Out. Limité en paquets ou en octets.
fq
Le Fair Queue Scheduler réalise le cadencement TCP et peut gérer des millions de flux simultanés par qdisc.
fq_codel
Fair Queuing Controlled Delay est une discipline de mise en file d'attente qui combine Fair Queuing avec le schéma AQM CoDel. FQ_Codel utilise un modèle stochastique pour classer les paquets entrants dans différents flux et est utilisé pour fournir une part équitable de la bande passante à tous les flux utilisant la file d'attente. Chaque flux est géré par la discipline de mise en file d'attente CoDel. La réorganisation au sein d'un flux est évitée car Codel utilise en interne une file FIFO.
fq_pie
FQ-PIE (Flow Queuing with Proportional Integral controller Enhanced) est une discipline de mise en file d'attente qui combine le Flow Queuing avec le schéma AQM PIE. FQ-PIE utilise une fonction de hachage Jenkins pour classer les paquets entrants dans différents flux et est utilisé pour fournir une part équitable de la bande passante à tous les flux utilisant le qdisc. Chaque flux est géré par l'algorithme PIE.
gred
Generalized Random Early Detection combine plusieurs files d'attente RED afin d'obtenir plusieurs priorités de chute. Ceci est requis pour réaliser l'Assured Forwarding (RFC 2597).
hhf
Heavy-Hitter Filter différencie les petits flux des gros émetteurs (heavy-hitters). L'objectif est de capturer les gros émetteurs et de les déplacer vers une file d'attente séparée avec moins de priorité, de sorte que le trafic volumineux n'affecte pas la latence du trafic critique.
ingress
Il s'agit d'un qdisc spécial car il s'applique au trafic entrant sur une interface, permettant son filtrage et sa régulation.
mqprio
Le qdisc Multiqueue Priority est une discipline de mise en file d'attente simple qui permet de mapper les flux de trafic à des plages de files d'attente matérielles en utilisant des priorités et une cartographie configurable des priorités vers les classes de trafic. Une classe de trafic dans ce contexte est un ensemble de classes qdisc contiguës qui correspondent 1:1 à un ensemble de files d'attente exposées par le matériel.
multiq
Multiqueue est un qdisc optimisé pour les périphériques avec plusieurs files d'attente Tx. Il a été ajouté pour le matériel qui souhaite éviter le blocage en tête de ligne. Il parcourt les bandes et vérifie que la file d'attente matérielle associée à la bande n'est pas arrêtée avant de dépiler un paquet.
netem
Network Emulator est une amélioration des facilités de contrôle de trafic Linux qui permet d'ajouter des délais, des pertes de paquets, des duplications et d'autres caractéristiques aux paquets sortants d'une interface réseau sélectionnée.
pfifo_fast
Qdisc standard pour les noyaux activés pour 'Advanced Router'. Il se compose d'une file d'attente à trois bandes qui respecte les drapeaux Type de Service, ainsi que la priorité qui peut être attribuée à un paquet.
pie
Proportional Integral controller-Enhanced (PIE) est un schéma de gestion active des files d'attente basé sur la théorie du contrôle. Il est basé sur le contrôleur proportionnel intégral mais vise à contrôler le délai.
red
Random Early Detection simule une congestion physique en abandonnant aléatoirement des paquets lorsqu'il approche de l'allocation de bande passante configurée. Convient bien aux applications à très large bande passante.
sfb
Stochastic Fair Blue est un qdisc sans classe pour gérer la congestion en fonction de l'historique des pertes de paquets et de l'utilisation de la liaison, tout en essayant d'éviter que les flux non réactifs (c'est-à-dire les flux qui ne réagissent pas au marquage de congestion ou aux paquets abandonnés) n'affectent les performances des flux réactifs. Contrairement à RED, où la probabilité de marquage doit être configurée, BLUE essaie de déterminer automatiquement la probabilité de marquage idéale.
sfq
Stochastic Fairness Queueing réorganise le trafic mis en file d'attente de sorte que chaque 'session' envoie un paquet à tour de rôle.
tbf
Le Token Bucket Filter est adapté pour ralentir le trafic à un débit précisément configuré. Il s'adapte bien aux larges bandes passantes.

CONFIGURATION DES QDISCS SANS CLASSE

En l'absence de qdiscs avec classes, les qdiscs sans classe ne peuvent être attachés qu'à la racine d'un périphérique. Syntaxe complète :

tc qdisc add dev DEV root QDISC QDISC-PARAMETERS

Pour supprimer, exécutez

tc qdisc del dev DEV root

Le qdisc pfifo_fast est le défaut automatique en l'absence d'un qdisc configuré.

QDISCS AVEC CLASSES

Les qdiscs avec classes sont :

ATM
Mappe les flux vers des circuits virtuels d'un périphérique sous-jacent de mode de transfert asynchrone.
DRR
Le Deficit Round Robin Scheduler est un remplacement plus flexible de Stochastic Fairness Queuing. Contrairement à SFQ, il n'y a pas de files d'attente intégrées - vous devez ajouter des classes, puis configurer des filtres pour classifier les paquets en conséquence. Cela peut être utile, par exemple, pour utiliser des qdiscs RED avec des paramètres différents pour un trafic particulier. Il n'y a pas de classe par défaut - si un paquet ne peut pas être classifié, il est abandonné.
ETS
Le qdisc ETS est une discipline de mise en file d'attente qui fusionne les fonctionnalités des qdiscs PRIO et DRR dans un seul ordonnanceur. ETS facilite la configuration d'un ensemble de bandes strictes et partageant la bande passante pour implémenter la sélection de transmission décrite dans 802.1Qaz.
HFSC
Hierarchical Fair Service Curve garantit une allocation précise de bande passante et de délai pour les classes feuilles et répartit équitablement la bande passante excédentaire. Contrairement à HTB, il utilise l'abandon de paquets pour obtenir de faibles délais dont bénéficient les sessions interactives.
HTB
Le Hierarchy Token Bucket implémente une hiérarchie riche de partage de liaison de classes en mettant l'accent sur la conformité avec les pratiques existantes. HTB facilite la garantie de bande passante aux classes, tout en permettant la spécification de limites supérieures au partage inter-classes. Il contient des éléments de façonnage, basés sur TBF et peut prioriser les classes.
PRIO
Le qdisc PRIO est un conteneur non façonnant pour un nombre configurable de classes qui sont dépilées dans l'ordre. Cela permet une priorisation facile du trafic, où les classes inférieures ne peuvent envoyer que si les classes supérieures n'ont pas de paquets disponibles. Pour faciliter la configuration, les bits de Type de Service sont respectés par défaut.
QFQ
Quick Fair Queueing est un ordonnanceur en O(1) qui offre des garanties quasi optimales, et est le premier à atteindre cet objectif avec un coût constant également par rapport au nombre de groupes et à la longueur du paquet. L'algorithme QFQ n'a pas de boucles et utilise des instructions et des structures de données très simples qui se prêtent très bien à une implémentation matérielle.

THÉORIE DE FONCTIONNEMENT

Les classes forment un arbre, où chaque classe a un parent unique. Une classe peut avoir plusieurs enfants. Certains qdiscs permettent l'ajout dynamique de classes (HTB) tandis que d'autres (PRIO) sont créés avec un nombre statique d'enfants.

Les qdiscs qui permettent l'ajout dynamique de classes peuvent avoir zéro ou plusieurs sous-classes vers lesquelles le trafic peut être mis en file d'attente.

De plus, chaque classe contient un qdisc feuille qui, par défaut, a un comportement pfifo, bien qu'un autre qdisc puisse être attaché à la place. Ce qdisc peut à nouveau contenir des classes, mais chaque classe ne peut avoir qu'un seul qdisc feuille.

Lorsqu'un paquet entre dans un qdisc avec classes, il peut être classifié vers l'une des classes internes. Trois critères sont disponibles, bien que tous les qdiscs n'utilisent pas les trois :

Filtres tc
Si des filtres tc sont attachés à une classe, ils sont consultés en premier pour des instructions pertinentes. Les filtres peuvent correspondre à tous les champs d'un en-tête de paquet, ainsi qu'à la marque de pare-feu appliquée par iptables.
Type de Service
Certains qdiscs ont des règles intégrées pour classifier les paquets en fonction du champ TOS.
skb->priority
Les programmes userspace peuvent encoder un identifiant de classe dans le champ 'skb->priority' en utilisant l'option SO_PRIORITY.

Chaque nœud de l'arbre peut avoir ses propres filtres, mais les filtres de niveau supérieur peuvent également pointer directement vers des classes inférieures.

Si la classification échoue, les paquets sont mis en file d'attente dans le qdisc feuille attaché à cette classe. Vérifiez les pages man spécifiques aux qdiscs pour plus de détails.

NOMMAGE

Tous les qdiscs, classes et filtres ont des identifiants, qui peuvent être spécifiés ou attribués automatiquement.

Les identifiants se composent d'un numéro principal et d'un numéro secondaire, séparés par un deux-points - principal:secondaire. Le principal et le secondaire sont des nombres hexadécimaux et sont limités à 16 bits. Il existe deux valeurs spéciales : la racine est représentée par des principal et secondaire de uns partout, et non spécifié est tout zéro.

QDISCS
Un qdisc, qui peut potentiellement avoir des enfants, se voit attribuer un numéro principal, appelé 'handle', laissant l'espace de noms secondaire disponible pour les classes. Le handle est exprimé sous la forme '10:'. Il est d'usage d'attribuer explicitement un handle aux qdiscs censés avoir des enfants.
CLASSES
Les classes résidant sous un qdisc partagent le numéro principal de leur qdisc, mais chacune a un numéro secondaire distinct appelé 'classid' qui n'a aucune relation avec les classes parentes, seulement avec leur qdisc parent. La même convention de nommage que pour les qdiscs s'applique.

COMMANDES TC

Les commandes suivantes sont disponibles pour les qdiscs, les classes et les filtres :

add
Ajoute un qdisc, une classe ou un filtre à un nœud. Pour toutes les entités, un parent doit être passé, soit en passant son ID, soit en l'attachant directement à la racine d'un périphérique. Lors de la création d'un qdisc ou d'un filtre, il peut être nommé avec le paramètre handle. Une classe est nommée avec le paramètre classid.
delete
Un qdisc peut être supprimé en spécifiant son handle, qui peut également être 'root'. Toutes les sous-classes et leurs qdiscs feuilles sont automatiquement supprimés, ainsi que tous les filtres qui leur sont attachés.
change
Certaines entités peuvent être modifiées 'en place'. Partage la syntaxe de 'add', à l'exception du fait que le handle ne peut pas être modifié, pas plus que le parent. En d'autres termes, change ne peut pas déplacer un nœud.
replace
Effectue une suppression/ajout quasi atomique sur un ID de nœud existant. Si le nœud n'existe pas encore, il est créé.
get
Affiche un filtre unique en fournissant l'interface DEV, l'ID du qdisc, la priorité, le protocole et l'ID du filtre.
show
Affiche tous les filtres attachés à l'interface donnée. Un ID de parent valide doit être passé.
link
Disponible uniquement pour les qdiscs, effectue un remplacement où le nœud doit déjà exister.

MONITOR

L'utilitaire  tc peut surveiller les événements générés par le noyau tels que l'ajout/suppression de qdiscs, de filtres ou d'actions, ou la modification de ceux existants.

La commande suivante est disponible pour  monitor :

file
Si l'option file est donnée, tc n'écoute pas les événements du noyau, mais ouvre le fichier donné et déverse son contenu. Le fichier doit être au format binaire et contenir des messages netlink.

OPTIONS

-b, -b filename, -batch, -batch filename
lit les commandes à partir du fichier fourni ou de l'entrée standard et les exécute. La première erreur entraînera la terminaison de tc.
-force
ne termine pas tc en cas d'erreurs en mode batch. S'il y a eu des erreurs lors de l'exécution des commandes, le code de retour de l'application sera différent de zéro.
-o, -oneline
affiche chaque enregistrement sur une seule ligne, en remplaçant les sauts de ligne par le caractère '\'. Ceci est pratique lorsque vous souhaitez compter les enregistrements avec wc(1) ou pour faire un grep(1) sur la sortie.
-n, -net, -netns <NETNS>
change tc dans l'espace de noms réseau spécifié NETNS. En fait, cela simplifie simplement l'exécution de :

ip netns exec NETNS tc [ OPTIONS ] OBJECT { COMMAND | help }

à

tc -n[etns] NETNS [ OPTIONS ] OBJECT { COMMAND | help }

-N, -Numeric
Affiche le nombre de protocole, scope, dsfield, etc directement au lieu de le convertir en nom lisible par l'homme.
-cf, -conf <FILENAME>
spécifie le chemin vers le fichier de configuration. Cette option est utilisée conjointement avec d'autres options (par exemple, -nm).
-t, -timestamp
Lorsque  tc monitor s'exécute, affiche un horodatage avant le message d'événement dans le format :
Timestamp: <Jour> <Mois> <JJ> <hh:mm:ss> <AAAA> <usecs> usec
-ts, -tshort
Lorsque  tc monitor s'exécute, affiche un horodatage court avant le message d'événement dans le format :
[<AAAA>-<MM>-<JJ>T<hh:mm:ss>.<ms>]
-echo
Demande au noyau de renvoyer la configuration appliquée.

FORMAT

La commande show a des options de formatage supplémentaires :

-s, -stats, -statistics
affiche plus de statistiques sur l'utilisation des paquets.
-d, -details
affiche des informations plus détaillées sur les débits et les tailles de cellules.
-r, -raw
affiche les valeurs hexadécimales brutes pour les handles.
-p, -pretty
pour le filtre u32, décode les valeurs d'offset et de masque en commandes de filtre équivalentes basées sur TCP/IP. En sortie JSON, ajoute des espaces pour améliorer la lisibilité.
-iec
affiche les débits en unités CEI (c'est-à-dire 1K = 1024).
-g, -graph
affiche les classes sous forme de graphique ASCII. Affiche des informations statistiques génériques sous chaque classe si l'option -s a été spécifiée. Les classes ne peuvent être filtrées que par l'option dev.
-c[color][={always|auto|never}
Configure la sortie couleur. Si le paramètre est omis ou always, la sortie couleur est activée quel que soit l'état de stdout. Si le paramètre est auto, stdout est vérifié pour être un terminal avant d'activer la sortie couleur. Si le paramètre est never, la sortie couleur est désactivée. Si spécifié plusieurs fois, le dernier prend le dessus. Ce drapeau est ignoré si -json est également donné.
-j, -json
Affiche les résultats au format JSON.
-nm, -name
résout le nom de classe à partir du fichier /etc/iproute2/tc_cls ou du fichier spécifié par l'option -cf. Ce fichier n'est qu'un mappage de classid au nom de classe.

DESCRIPTION

The tc utility is a tool to configure the Linux kernel traffic control subsystem. Traffic control is the part of network management that deals with the way packets are transmitted over a network interface. It allows you to tune and control the packet flow.

The main configuration objects are:

qdisc
stands for 'queueing discipline'. It's a piece of software inside the kernel that decides when and which packet to send next when a device is transmitting.
class
is used by classful qdiscs to classify packets into different classes. Each class can have its own qdisc.
filter
is used to direct packets to different qdiscs or classes based on packet properties (like IP address, port, etc.). Filters are evaluated in order.

QDISCS

Queueing disciplines are the core of traffic control. They determine how packets are queued and dequeued for transmission.

There are two main kinds of qdiscs:

Classless Qdiscs
These are simple qdiscs that do not classify packets. They only contain one queue and one shaping algorithm. Examples include pfifo_fast, htb, and tbf.
Classful Qdiscs
These qdiscs have the ability to create internal classes, and each class can have its own qdisc and associated shaping algorithm. This allows for more complex traffic management schemes. Examples include htb, cbq, and prio.

Each network device must have one qdisc attached, even if it's just the default pfifo_fast.

CLASSES

Classes are used by classful qdiscs to sub-divide traffic. A class is a handle to a qdisc, which can be configured to shape traffic independently. For example, you could have one class for VoIP traffic and another for web traffic, and apply different shaping rules to each.

Classes are attached to parent qdiscs or other classes.

FILTERS

Filters are used to classify packets and direct them to the appropriate qdisc or class. Filters are evaluated in order, and the first one that matches a packet determines where it goes. This allows for sophisticated routing of traffic based on various criteria.

Common filter types include:

u32
A powerful and flexible filter that can match on almost any packet field.
fw
Matches packets based on firewall marks.
route
Matches packets based on routing information.

QEVENTS

Qevents are used to notify userspace applications about traffic control events, such as changes in queue status or packet drops. This can be useful for monitoring and dynamic adjustment of traffic control parameters.

CLASSLESS QDISCS

These qdiscs do not support classification. They have a single queue and usually a single shaping algorithm.

bfifo
A simple FIFO (First-In, First-Out) queue. Packets are transmitted in the order they arrive.
pfifo
Similar to bfifo, but with a configurable maximum queue size.
sfq
Stochastic Fairness Queueing. Distributes bandwidth fairly among flows by hashing packets to different queues.
tbf
Token Bucket Filter. Implements a token bucket algorithm to limit the rate of traffic.
red
Random Early Detection. An algorithm to avoid network congestion by randomly dropping packets when the queue starts to fill up.
cobalt
A simple qdisc for testing.
fq
Fair Queueing. Distributes bandwidth fairly among different flows.
prio
Priority queueing. Transmits packets in order of priority.
htb
Hierarchical Token Bucket. A more advanced qdisc that allows for hierarchical bandwidth allocation and shaping.
cake
Common Applications Kept Enhanced. A modern qdisc that combines features of other qdiscs like FQ-CoDel and aims to provide good performance with minimal configuration.
choke
Conjunction of Hierarchical Obfuscation and Network Context Eavesdropping. A qdisc for managing network traffic.
codel
Controlled Delay. A queue management algorithm that aims to reduce queue delay.
drr
Deficit Round Robin. A fair queueing algorithm that provides bandwidth guarantees.
ets
Enhanced Transmission Selection. A qdisc for Ethernet Traffic Shaping.
fq_codel
Fair Queueing Controlled Delay. Combines Fair Queueing with CoDel to provide fair bandwidth distribution and low latency.
fq_pie
Fair Queueing with Proportional Integral Controller Enhanced. Another modern qdisc aiming for low latency and fair bandwidth distribution.
gact
Generic actions. Can be used to perform various actions on packets.
hfsc
Hierarchical Fair Service Curve. A classful qdisc that provides hierarchical service curves for guaranteed and best-effort traffic.
mqprio
Multi-Queue Priority. Allows setting different priorities for traffic on multi-queue network devices.
pfifo_fast
The default qdisc on most Linux systems. It's a three-band FIFO queue with a basic priority mechanism.
pie
Proportional Integral Controller Enhanced. A queue management algorithm that aims to maintain a target queue delay.
route
A filter that routes packets based on routing information.
sfb
Stochastic Fairness Buffered. A qdisc that provides weighted fair queueing.
stab
A simple qdisc for testing.
tc_basic
The basic qdisc, often used as a placeholder.

CONFIGURING CLASSLESS QDISCS

To configure a classless qdisc, you typically specify the device, the qdisc type, and its parameters.

tc qdisc add dev eth0 root tbf rate 10mbit burst 32kbit latency 50ms

This command adds a TBF qdisc to the root of the eth0 interface with specified rate, burst, and latency.

CLASSFUL QDISCS

Classful qdiscs allow for more complex traffic shaping by creating internal classes.

htb
Hierarchical Token Bucket. Allows for hierarchical bandwidth allocation.
cbq
Class-Based Queueing. Another classful qdisc for hierarchical bandwidth management.
prio
Priority queueing. Divides traffic into priority bands.

To configure a classful qdisc, you first add the root qdisc, then add classes to it, and finally add filters to direct traffic to those classes.

tc qdisc add dev eth0 root handle 1: htb default 1

tc class add dev eth0 parent 1: classid 1:1 htb rate 10mbit

tc class add dev eth0 parent 1:1 classid 1:2 htb rate 5mbit

tc filter add dev eth0 parent 1: protocol ip prio 1 u32 match ip sport 80 0xffff flowid 1:2

THEORY OF OPERATION

The tc utility interacts with the kernel's traffic control subsystem. When a packet is transmitted from a network interface, it passes through a queueing discipline (qdisc). The qdisc determines when and in what order packets are sent. Classful qdiscs allow for the creation of classes, which are sub-queues with their own shaping properties. Filters are used to classify incoming packets and direct them to the appropriate class or qdisc.

The basic flow is: Packet arrives -> Filter evaluates -> Packet is directed to a qdisc/class -> Qdisc determines transmission order -> Packet is transmitted.

NAMING

Objects in traffic control are identified by handles. A handle consists of a major and a minor number, separated by a colon (e.g., 1:, 1:1). The root qdisc typically has the handle 1:. Classes inherit handles from their parent qdiscs.

In addition, qdiscs and classes can be assigned names (e.g., root, 1:1).

Device names are also used to specify which interface to configure (e.g., eth0).

# Here is comment
1:40 voip # Here is another comment
1:50 web
1:60 ftp
1:2 home
tc will not fail if -nm was specified without -cf option but /etc/iproute2/tc_cls file does not exist, which makes it possible to pass -nm option for creating tc alias.

OPTIONS

-br, -brief
Print only essential data needed to identify the filter and action (handle, cookie, etc.) and stats. This option is currently only supported by tc filter show and tc actions ls commands.

FORMAT

The output format of tc commands can vary depending on the command and options used. Generally, it provides detailed information about the configured qdiscs, classes, and filters.

Example output for tc class show dev eth0:

class htb 1:1 parent 1: offset 87310
  rate 10Mbit ceil 10Mbit burst 32000b cburst 32000b
class htb 1:2 parent 1:1 offset 0
  rate 5Mbit ceil 5Mbit burst 16000b cburst 16000b

EXAMPLES

tc -g class show dev eth0

Shows classes as ASCII graph on eth0 interface.

tc -g -s class show dev eth0

Shows classes as ASCII graph with stats info under each class.
