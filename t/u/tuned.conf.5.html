tuned.conf(5) Description du format du fichier tuned.conf tuned.conf(5)

NOM

tuned.conf - Définition de profil TuneD

DESCRIPTION

Cette page de manuel documente le format des fichiers de définition de profils TuneD 2.0. La définition du profil est stockée dans /etc/tuned/profiles/<nom_profil>/tuned.conf ou dans /usr/lib/tuned/profiles/<nom_profil>/tuned.conf où le répertoire /etc/tuned/profiles/ a une priorité plus élevée.

Le fichier tuned.conf configure le profil et est au format ini.

SECTION PRINCIPALE

La section principale s'appelle « [main] » et peut contenir les options suivantes :

include=
Inclut un profil avec le nom donné. Cela vous permet de baser un nouveau profil sur un profil existant. En cas de paramètres conflictuels dans le nouveau profil et le profil de base, les paramètres du nouveau profil sont utilisés.

PLUGINS

Chaque autre section définit un plugin. Le nom de la section est utilisé comme nom pour le plugin et est utilisé dans les logs pour identifier le plugin. Il ne peut y avoir qu'un seul plugin d'un type particulier s'occupant d'un appareil particulier. Les conflits sont résolus par défaut en fusionnant les options des deux plugins. Cela peut être modifié par l'option « replace ».

Chaque section de plugin peut contenir les options suivantes :

type=
Type de plugin. Actuellement, il existe les plugins upstream suivants : audio, bootloader, cpu, disk, eeepc_she, modules, mounts, net, script, scsi_host, selinux, scheduler, sysctl, sysfs, systemd, usb, video, vm. Cette liste peut être incomplète. Si vous avez installé TuneD via RPM, vous pouvez lister les plugins upstream avec la commande suivante : rpm -ql tuned | grep 'plugins/plugin_.*.py$' Vérifiez le répertoire des plugins renvoyé par cette commande pour voir tous les plugins (par exemple, les plugins fournis par des paquets tiers).
devices=
Liste séparée par des virgules des périphériques qui doivent être optimisés par cette instance de plugin. Si vous omettez cette option, tous les périphériques trouvés seront optimisés.
replace=1
S'il y a un conflit entre deux plugins (ce qui signifie que deux plugins du même type essaient de configurer les mêmes périphériques), alors le plugin défini en dernier remplace toutes les options définies par le plugin précédemment défini.

Les plugins peuvent également avoir des options liées au plugin.

EXEMPLE

[main]
# Inclut les plugins définis dans le profil "included".
include=included
# Définit le plugin my_sysctl
[my_sysctl]
type=sysctl
# Ce plugin remplacera tout plugin sysctl défini dans le profil "included"
replace=1
# 256 Ko par défaut donne de bons résultats expérimentalement.
net.core.rmem_default = 262144
net.core.wmem_default = 262144
# Définit le plugin my_script
# Les deux scripts (profile.sh de ce profil et le script du profil "included"
# seront exécutés, car s'il n'y a pas d'option "replace=1", l'action par
# défaut est la fusion.
[my_script]
type=script
script=${i:PROFILE_DIR}/profile.sh
