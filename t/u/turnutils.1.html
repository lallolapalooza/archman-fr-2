INFORMATIONS GÉNÉRALES

Un ensemble de programmes turnutils_* fournit certaines fonctionnalités utilitaires à utiliser pour les tests et pour la configuration du serveur TURN.

1.
turnutils_uclient : émule plusieurs clients UDP, TCP, TLS ou DTLS. (ce programme est fourni uniquement à des fins de test !) L'image binaire compilée de ce programme se trouve dans le sous-répertoire bin/.
2.
turnutils_peer : un serveur "écho" simple et sans état, uniquement UDP, à utiliser comme serveur final dans le modèle de relais ("pair"). Pour chaque paquet UDP entrant, il le renvoie simplement. (ce programme est fourni uniquement à des fins de test !) Lorsque les clients de test communiquent en mode client-à-client (lorsque le programme turnutils_uclient est utilisé avec l'option "-y"), alors turnutils_peer n'est pas nécessaire.

L'image binaire compilée de ce programme se trouve dans le sous-répertoire bin/.

3.
turnutils_stunclient : un exemple simple de client STUN. L'image binaire compilée de ce programme se trouve dans le sous-répertoire bin/.
4.
turnutils_rfc5769check : un utilitaire qui vérifie l'exactitude de l'implémentation des protocoles STUN/TURN. Cet utilitaire est utilisé uniquement pour la procédure de vérification de compilation, il n'est pas copié à la destination d'installation.

Dans le sous-répertoire "examples/scripts", vous trouverez des exemples de lignes de commande pour exécuter les programmes. Les scripts sont destinés à être exécutés depuis le sous-répertoire examples/, par exemple :

$ cd examples

$ ./scripts/secure_relay.sh

5.
turnutils_natdiscovery : un utilitaire qui fournit la découverte du comportement NAT conformément à la RFC5780. Cet utilitaire découvre le mappage NAT réel et le comportement de filtrage, etc. Attention, du côté du serveur TURN, deux adresses IP d'écoute différentes doivent être configurées pour pouvoir fonctionner correctement !
6.
turnutils_oauth : un utilitaire qui fournit la génération d'access_token OAuth (chiffrement AEAD), la validation et le déchiffrement. Cet utilitaire prend en entrée toutes les clés et durées de vie ainsi que toute information connexe nécessaire à la création et à la validation d'un access_token. Il produit une sortie JSON avec tous les paramètres PoP OAuth qui doivent être transmis au client. La sortie est générée conformément à la RFC7635 Annexe B, Figure 8.

Pour plus de détails, et pour la structure de l'access_token, lisez la rfc7635, et regardez le script dans examples/scripts/oauth.sh.

NOM

turnutils_uclient - cette application d'émulation client est fournie uniquement à des fins de test.

SYNOPIS

$ turnutils_uclient [-tTSvsyhcxg] [options] <adresse-IP-du-serveur-TURN>

DESCRIPTION

Il a été conçu pour simuler plusieurs clients. Il utilise l'API d'E/S asynchrone de libevent pour gérer plusieurs clients. Un client se connecte au relais, négocie la session et envoie plusieurs messages (nombre configuré) au serveur (relais), attendant le même nombre de réponses. La longueur des messages est configurable. Le message est un flux d'octets arbitraire. Le nombre de messages à envoyer est configurable.

Options :

-t
Utiliser TCP pour les communications entre le client et le serveur TURN (par défaut, UDP).
-b
Utiliser SCTP pour les communications entre le client et le serveur TURN (par défaut, UDP).
-T
Utiliser TCP pour le transport de relais (par défaut - UDP). Implique les options -t, -y, -c, et ignore les options -s, -e, -r et -g. Peut être utilisé avec -b.
-P
TCP passif (RFC6062 avec pair actif). Implique -T.
-S
Connexion SSL sécurisée : SSL/TLS pour TCP, DTLS pour UDP, TLS/SCTP pour SCTP.
-U
Connexion sécurisée non chiffrée (suite eNULL) : SSL/TLS pour TCP, DTLS pour UDP.
-v
Verbose.
-s
Utiliser la méthode "Send" dans TURN ; par défaut, il utilise les canaux TURN.
-y
Utiliser les connexions client-à-client : paire de canaux RTP/RTCP vers une autre paire de canaux RTP/RTCP. Avec cette option, l'application turnutils_peer n'est pas utilisée, car les points d'extrémité de relais alloués communiquent entre eux.
-h
Rester indéfiniment après le dernier paquet envoyé.
-c
Ne pas créer de connexions rtcp.
-x
Demander une adresse de relais IPv6 (RFC6156).
-X
Adresse de relais IPv4 demandée explicitement.
-g
Définir le paramètre DONT_FRAGMENT dans les requêtes TURN.
-D
Effectuer un remplissage de canal obligatoire même pour UDP (comme pjnath).
-N
effectuer des tests négatifs (quelques cas limités uniquement).
-R
effectuer des tests de protocole négatifs.
-O
Mode attaque DOS.
-M
Utiliser la mobilité TURN ICE.
-I
Ne pas définir de permissions sur les points d'extrémité de relais TURN (pour tester la fonctionnalité de relais non standard du serveur).
-G
Générer des requêtes supplémentaires (créer des permissions, lier le canal).
-B
Déconnexion aléatoire après quelques paquets initiaux.
-Z
Double allocation (SSODA). Implique l'option -c.
-J
Utiliser OAuth avec la clé de test par défaut kid='north'.

Options avec valeurs requises :

-l
Longueur du message (Défaut : 100 octets).
-i
Fichier certificat (uniquement pour les connexions sécurisées, facultatif).
-k
Fichier de clé privée (uniquement pour les connexions sécurisées).
-E
Fichier CA pour la vérification du certificat serveur, si le certificat serveur doit être vérifié.
-p
Port du serveur TURN (Défauts : 3478 non sécurisé, 5349 sécurisé).
-n
Nombre de messages à envoyer (Défaut : 5).
-d
Périphérique d'interface locale (facultatif, uniquement Linux).
-L
Adresse IP locale (facultatif).
-m
Nombre de clients (Défaut : 1, 2 ou 4, selon les options).
-e
Adresse du pair.
-r
Port du pair (Défaut : 3480).
-z
Intervalle de paquets par session en millisecondes (Défaut : 20).
-u
Nom d'utilisateur STUN/TURN.
-w
Mot de passe utilisateur STUN/TURN.
-W
Secret de l'API REST TURN. Le secret "en texte clair", par ex. "north", qui est stocké dans la colonne de valeur de la table turn_secret.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

-C
C'est le symbole (caractère) séparateur de timestamp/nom d'utilisateur dans l'API REST TURN. La valeur par défaut est :.
-F
Suite de chiffrements pour TLS/DTLS. La valeur par défaut est DEFAULT.
-o
La valeur de l'attribut ORIGIN STUN.

Bande passante pour la requête de bande passante dans ALLOCATE. La valeur par défaut est zéro.

NOM

turnutils_stunclient - un client STUN de base.

SYNOPIS

$ turnutils_stunclient [options] <adresse-IP-du-serveur-STUN>

DESCRIPTION

Il envoie une requête STUN RFC 5389 "nouvelle" (via UDP) et affiche les informations de réponse.

Options avec valeurs requises :

-p
Port du serveur STUN (Défaut : 3478).
-L
Adresse locale à utiliser (optionnel).
-f
Forcer le traitement RFC 5780.

Le programme turnutils_stunclient vérifie les résultats de la première requête, et s'il constate que le serveur STUN prend en charge la RFC 5780 (la réponse de liaison le révèle), alors turnutils_stunclient effectue quelques requêtes supplémentaires avec des paramètres différents, pour démontrer les capacités de découverte de NAT.

Cet utilitaire ne prend pas en charge le protocole STUN "ancien" "classique" (RFC 3489).

turnutils_rfc5769check - un utilitaire qui teste la correction de l'implémentation du protocole STUN.

SYNOPIS

$ turnutils_rfc5769check

DESCRIPTION

turnutils_rfc5769check teste la correction de l'implémentation du protocole STUN par rapport aux vecteurs de test prédéfinis dans la RFC 5769 et affiche les résultats des tests à l'écran. Cet utilitaire est utilisé uniquement pour la procédure de vérification de compilation, il n'est pas copié vers la destination d'installation.

Utilisation :

$ turnutils_rfc5769check

NOM

turnutils_natdiscovery - un utilitaire qui découvre le mappage et le filtrage NAT conformément à la RFC 5780.

SYNOPIS

$ turnutils_natdiscovery [options] <FQDN ou adresse IP du serveur STUN>

DESCRIPTION

turnutils_natdiscovery découvre le comportement de mappage et de filtrage NAT, afin de déterminer si ce NAT utilise actuellement un mappage indépendant du point d'extrémité, dépendant de l'adresse, ou dépendant de l'adresse et du port, et/ou afin de déterminer si ce NAT utilise un filtrage indépendant du point d'extrémité, dépendant de l'adresse, ou dépendant de l'adresse et du port.

Utilisez l'un des indicateurs -m, -f, -c, -H pour découvrir le comportement NAT.

Indicateurs :

-m
Découverte du comportement de mappage NAT
-f
Découverte du comportement de filtrage NAT
-t
Découverte du comportement de durée de vie du mappage NAT Nécessite un minuteur (-T)
-c
Découverte du comportement de collision NAT
-H
Découverte du comportement d'épingle NAT
-P
Ajoute un remplissage de 1500 octets à la découverte de comportement Applicable avec toutes les découvertes sauf celle de la durée de vie du mappage NAT

Options avec valeurs requises :

-p
Port du serveur STUN (Défaut : 3478)
-L
Adresse locale à utiliser (optionnel)
-l
Port local à utiliser (à utiliser avec -L)
-A
Adresse locale secondaire (optionnel) Requise pour la découverte de collision
-T
Minuteur de durée de vie du mappage (sec) Utilisé par la découverte du comportement de durée de vie du mappage

Utilisation :

$ turnutils_natdiscovery -m -f stun.example.com

NOM

turnutils_oauth - un utilitaire qui aide à la génération/chiffrement et à la validation/déchiffrement de l'access_token OAuth

SYNOPIS

$ turnutils_oauth [options]

DESCRIPTION

L'utilitaire turnutils_oauth fournit une aide au chiffrement et/ou déchiffrement d'access_token OAuth avec AEAD (Authentification Encryption with Associated Data). Il aide un serveur d'authentification à créer des access_tokens, et également à des fins de débogage, il aide à la validation et au déchiffrement des access_tokens. Cet utilitaire saisit toutes les clés et durées de vie ainsi que toute information connexe nécessaires au chiffrement ou déchiffrement d'un access_token. Il produit une sortie JSON avec tous les paramètres OAuth PoP qui doivent être transmis au client. La sortie est générée conformément à la RFC 7635, Annexe B, Figure 8. Cet utilitaire pourrait aider à construire un service de serveur d'authentification, mais attention, cet utilitaire ne génère pas de "clé de session" / "clé mac" et ne vérifie pas la durée de vie de la "clé de session" / "clé mac" ou de la "clé d'authentification". Pour plus de détails et pour la structure de l'access_token, lisez la RFC 7635 et consultez l'exemple dans examples/scripts/oauth.sh.

Utilisez l'un des indicateurs -e et/ou -d pour chiffrer ou déchiffrer un access_token.

Indicateurs :

-h, --help
utilisation
-v, --verbose
mode verbeux
-e, --encrypt
chiffrer le jeton
-d, --decrypt
déchiffrer valider le jeton

Options avec valeurs requises :

-i, --server-name
nom du serveur (max. 255 caractères)
-j, --auth-key-id
id de la clé d'authentification (max. 32 caractères)
-k, --auth-key
clé d'authentification encodée en base64
-l
--auth-key-timestamp timestamp de la clé d'authentification (secondes depuis l'époque)
-m, --auth-key-lifetime
durée de vie de la clé d'authentification en secondes
-n, --auth-key-as-rs-alg
algorithme de chiffrement Serveur d'Authentification (AS) - Serveur de Ressources (RS)
-o, --token-nonce
nonce encodé en base64 base64(12 octets) = 16 caractères
-p, turnutils(1) - turnutils - man pages

NOM

nat discovery tool - client utility for the TURN server

SYNOPHIS

$ turnutils_natdiscovery [OPTIONS]

DESCRIPTION

This utility tests the user's public IP address and verifies that the server can discover it. The utility can be useful for debugging network issues.

This utility is part of the coturn package.

OPTIONS

-a, --server-addr
Set the server address. If not specified, the default is 127.0.0.1.
-c, --client-addr
Set the client address. If not specified, the default is 0.0.0.0.
-d, --debug
Enable debug logging.
-f, --filter
Filter value of received relay address.
-g, --no-tcp
Disable TCP.
-h, --help
Show help message.
-i, --interface
Network interface to use.
-l, --log
Log file path.
-m, --max-timeout
Set maximum timeout value.
-n, --no-udp
Disable UDP.
-p, --server-port
Set the server port. Default is 3478.
-P, --local-port
Set the local port. Default is 0 (random).
-r, --realm
Set realm. Default is "turnserver.org".
-s, --stun-only
Only perform STUN requests.
-t, --timeout
Set timeout value.
-u, --user
Set username.
-v, --verbose
Enable verbose logging.
-V, --version
Show version.

OPTIONS_TOKEN

-k, --token-mac-key
Clé MAC encodée en base64 base64(32 octets) = 44 caractères
-q, --token-timestamp
Timestamp au format 64 bits non signé (Format natif - Unix), donc 48 bits pour les secondes depuis l'époque UTC + 16 bits pour les fractions de seconde de 1/64000. Exemple : le timestamp Unix actuel décalé de 16 bits vers la gauche. (Défaut : l'heure UTC actuelle)
-r~2, --token-lifetime
Durée de vie en secondes (Défaut : 3600)
-t~3, --token
Jeton chiffré encodé en base64 pour validation et déchiffrement
-u~2, --hmac-alg
Algorithme hmac du client stun

Usage:

$ turnutils_natdiscovery
