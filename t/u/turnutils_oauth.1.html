INFORMATIONS GÉNÉRALES

Un ensemble de programmes `turnutils_*` fournit des fonctionnalités utilitaires pour tester et configurer le serveur TURN.

1.
turnutils_uclient : émule plusieurs clients UDP, TCP, TLS ou DTLS. (ce programme est fourni à des fins de test uniquement !) L'image binaire compilée de ce programme se trouve dans le sous-répertoire `bin/`.
2.
turnutils_peer : un serveur simple "écho" UDP uniquement, sans état, à utiliser comme serveur final dans le schéma de relais ("pair"). Pour chaque paquet UDP entrant, il le renvoie simplement. (ce programme est fourni à des fins de test uniquement !) Lorsque les clients de test communiquent en mode client-à-client (lorsque le programme `turnutils_uclient` est utilisé avec l'option "-y"), `turnutils_peer` n'est pas nécessaire.

L'image binaire compilée de ce programme se trouve dans le sous-répertoire `bin/`.

3.
turnutils_stunclient : un exemple simple de client STUN. L'image binaire compilée de ce programme se trouve dans le sous-répertoire `bin/`.
4.
turnutils_rfc5769check : un utilitaire qui vérifie la correction de l'implémentation du protocole STUN/TURN. Cet utilitaire est uniquement utilisé pour la procédure de vérification de compilation, il n'est pas copié vers la destination d'installation.

Dans le sous-répertoire "examples/scripts", vous trouverez des exemples de lignes de commande pour exécuter les programmes. Les scripts sont destinés à être exécutés depuis le sous-répertoire examples/, par exemple :

$ cd examples

$ ./scripts/secure_relay.sh

5.
turnutils_natdiscovery : un utilitaire qui fournit la découverte du comportement NAT conformément à la RFC5780. Cet utilitaire découvre le mappage NAT réel et le comportement de filtrage, etc. Sachez que côté serveur TURN, deux adresses IP d'écoute différentes doivent être configurées pour pouvoir fonctionner correctement !
6.
turnutils_oauth : un utilitaire qui fournit la **génération** (chiffrement AEAD), la validation et le déchiffrement de `access_token`. Cet utilitaire prend en entrée toutes les clés, durées de vie et toute information connexe nécessaires à la création et à la validation d'un `access_token`. Il génère une sortie JSON avec tous les paramètres OAuth PoP qui doivent être transmis au client. La sortie est générée conformément à la RFC7635 Annexe B, Figure 8.

Pour plus de détails, et pour la structure de `access_token`, lisez la rfc7635, et consultez le script dans examples/scripts/oauth.sh.

NOM

turnutils_uclient - cette application d'émulation client est fournie uniquement à des fins de test.

SYNOPSIS

$ turnutils_uclient [-tTSvsyhcxg] [options] <Adresse-IP-Serveur-TURN>

DESCRIPTION

Il a été conçu pour simuler plusieurs clients. Il utilise l'API d'E/S asynchrone de libevent pour gérer plusieurs clients. Un client se connecte au relais, négocie la session et envoie plusieurs messages (nombre configuré) au serveur (relais), attendant le même nombre de réponses. La longueur des messages est configurable. Le message est un flux d'octets arbitraire. Le nombre de messages à envoyer est configurable.

Options :

-t
Utiliser TCP pour les communications entre le client et le serveur TURN (par défaut, UDP).
-b
Utiliser SCTP pour les communications entre le client et le serveur TURN (par défaut, UDP).
-T
Utiliser TCP pour le transport de relais (par défaut - UDP). Implique les options -t, -y, -c, et ignore les options -s, -e, -r et -g. Peut être utilisé conjointement avec -b.
-P
TCP Passif (RFC6062 avec pair actif). Implique -T.
-S
Connexion sécurisée SSL : SSL/TLS pour TCP, DTLS pour UDP, TLS/SCTP pour SCTP.
-U
Connexion sécurisée non chiffrée (suite eNULL) : SSL/TLS pour TCP, DTLS pour UDP.
-v
Mode verbeux.
-s
Utiliser la méthode "Send" dans TURN ; par défaut, il utilise les canaux TURN.
-y
Utiliser des connexions client-à-client : une paire de canaux RTP/RTCP vers une autre paire de canaux RTP/RTCP. Avec cette option, l'application `turnutils_peer` n'est pas utilisée, car les points d'extrémité de relais alloués communiquent entre eux.
-h
Rester indéfiniment après le dernier paquet envoyé.
-c
Ne pas créer de connexions rtcp.
-x
Demander une adresse de relais IPv6 (RFC6156).
-X
Adresse de relais IPv4 explicitement demandée.
-g
Définir le paramètre DONT_FRAGMENT dans les requêtes TURN.
-D
Effectuer un remplissage de canal obligatoire même pour UDP (comme pjnath).
-N
Effectuer des tests négatifs (cas limités uniquement).
-R
Effectuer des tests de protocole négatifs.
-O
Mode attaque DOS.
-M
Utiliser la mobilité TURN ICE.
-I
Ne pas définir de permissions sur les points d'extrémité de relais TURN (pour tester la fonctionnalité de relais non standard du serveur).
-G
Générer des requêtes supplémentaires (créer des permissions, lier des canaux).
-B
Déconnexion aléatoire après quelques paquets initiaux.
-Z
Double allocation (SSODA). Implique l'option -c.
-J
Utiliser oAuth avec la clé de test par défaut kid='north'.

Options avec valeurs requises :

-l
Longueur du message (Défaut : 100 octets).
-i
Fichier certificat (pour les connexions sécurisées uniquement, facultatif).
-k
Fichier clé privée (pour les connexions sécurisées uniquement).
-E
Fichier CA pour la vérification du certificat serveur, si le certificat serveur doit être vérifié.
-p
Port du serveur TURN (Défauts : 3478 non sécurisé, 5349 sécurisé).
-n
Nombre de messages à envoyer (Défaut : 5).
-d
Interface locale (facultatif, Linux uniquement).
-L
Adresse IP locale (facultatif).
-m
Nombre de clients (Défaut : 1, 2 ou 4, selon les options).
-e
Adresse du pair.
-r
Port du pair (Défaut : 3480).
-z
Intervalle de paquets par session en millisecondes (Défaut : 20).
-u
Nom d'utilisateur STUN/TURN.
-w
Mot de passe utilisateur STUN/TURN.
-W
Secret de l'API REST TURN. Le secret "en texte clair" par exemple "north" qui est stocké dans la colonne de valeur du secret turn_secret

turnutils - a collection of utilities for testing of the TURN and STUN servers.

NAME

NAME

turnutils - a collection of utilities for testing of the TURN and STUN servers.

SYNOPSIS

$ turnutils_xxx [options]

DESCRIPTION

The turnutils package contains a number of utilities for testing of the TURN and STUN servers and NAT devices. These utilities are intended for manual testing and debugging purposes.

UTILITIES

The following utilities are included in the package:

turnutils_tserver
A STUN server for testing purposes.
turnutils_uclient
A TURN client for testing purposes.
turnutils_peer
A simple UDP-only echo backend server.
turnutils_stunclient
A basic STUN client.
turnutils_rfc5769check
A utility that tests the correctness of STUN protocol implementation.
turnutils_natdiscovery
A utility that discovers NAT mapping and filtering behavior according RFC5780.
turnutils_oauth
A utility that helps OAuth access_token generation/encryption and validation/decryption.

======================================

NAME

turnutils_tserver - a STUN server for testing purposes.

SYNOPSIS

$ turnutils_tserver [options]

DESCRIPTION

This utility is a STUN server implementation intended for testing purposes only. It is used as a counterpart for the turnutils_uclient application.

Options with required values:

-p
Listening UDP port. Default: 3478.
-d
Listening interface device (optional)
-L
Listening address of turnutils_tserver server. Multiple listening addresses can be used, IPv4 and IPv6. If no listener address(es) defined, then it listens on all IPv4 and IPv6 addresses.
-v
Verbose mode
-m
Allow relay.
-t
Set Realm value.
-s
Set Shared Secret value.
-S
Set Shared Secret value from the database table if dynamic, or the static-auth-secret value set in the configuration file if using static.
-C
This is the timestamp/username separator symbol (character) in TURN REST API. The default value is :.
-F
Cipher suite for TLS/DTLS. Default value is DEFAULT.
-o
the ORIGIN STUN attribute value.
-a
Bandwidth for the bandwidth request in ALLOCATE. The default value is zero.

See the examples in the "examples/scripts" directory.

NAME

turnutils_stunclient - a basic STUN client.

SYNOPSIS

$ turnutils_stunclient [options] <STUN-Server-IP-address>

DESCRIPTION

It sends a "new" STUN RFC 5389 request (over UDP) and shows the reply information.

Options with required values:

-p
STUN server port (Default: 3478).
-L
Local address to use (optional).
-f
Force RFC 5780 processing.

The turnutils_stunclient program checks the results of the first request, and if it finds that the STUN server supports RFC 5780 (the binding response reveals that) then the turnutils_stunclient makes a couple more requests with different parameters, to demonstrate the NAT discovery capabilities.

This utility does not support the "old" "classic" STUN protocol (RFC 3489).

========================================

NAME

turnutils_rfc5769check - a utility that tests the correctness of STUN protocol implementation.

SYNOPSIS

$ turnutils_rfc5769check

DESCRIPTION

turnutils_rfc5769check tests the correctness of STUN protocol implementation against the test vectors predefined in RFC 5769 and prints the results of the tests on the screen. This utility is used only for the compilation check procedure, it is not copied to the installation destination.

Usage:

$ turnutils_rfc5769check

NAME

turnutils_natdiscovery - a utility that discovers NAT mapping and filtering behavior according RFC5780.

SYNOPSIS

$ turnutils_natdiscovery [options] <STUN-Server-FQDN-or-IP-address>

DESCRIPTION

turnutils_natdiscovery discovers the NAT Mapping and Filtering behavior, to determine if that NAT is currently using Endpoint-Independent, Address-Dependent, or Address and Port-Dependent Mapping and/or to determine if that NAT is currently using Endpoint-Independent, Address-Dependent, or Address and Port-Dependent Filtering.

Use either -m, -f, -c, -H flag to discover NAT behavior.

Flags:

-m
NAT mapping behavior discovery
-f
NAT filtering behavior discovery
-t
NAT mapping lifetime behavior discovery Requires a timer (-T)
-c
NAT collision behavior discovery
-H
NAT hairpinning behavior discovery
-P
Add 1500 byte Padding to the behavior discovery Applicable with all except NAT mapping Lifetime discovery

Options with required values:

-p
STUN server port (Default: 3478)
-L
Local address to use (optional)
-l
Local port to use (use with -L)
-A
Secondary Local address (optional) Required for collision discovery
-T
Mapping lifetime timer (sec) Used by mapping lifetime behavior discovery

Usage:

$ turnutils_natdiscovery -m -f stun.example.com

NAME

turnutils_oauth - a utility that helps OAuth access_token generation/encryption and validation/decyption

SYNOPSIS

$ turnutils_oauth [options]

DESCRIPTION

turnutils_oauth utility provides help in OAuth access_token encryption and/or decryption with AEAD (Atuthenticated Encryption with Associated Data). It helps for an Auth Server in access_token creation, and also for debugging purposes it helps the access_token validation and decryption. This utility inputs all the keys and lifetimes and any related information that are needed for encryption or decryption of an access_token. It outputs a JSON with all OAuth PoP parameters that need to pass to the client. Output is generated accoriding RFC7635 Appendix B, Figure 8. This utility could help to build an Auth Server service, but be awere that this utility does not generate "session key" / "mac_key" and not verifies lifetime of "session key" / "mac_key" or "Auth key". For more details, and for the access_token structure, read rfc7635, and see the example in examples/scripts/oauth.sh.

Use either -e and/or -d flag to encrypt or decrypt access_token.

Flags:

-h, --help
usage
-v, --verbose
verbose mode
-e, --encrypt
encrypt token
-d, --decrypt
decrypt validate token

Options with required values:

-i, --server-name
server name (max. 255 char)
-j, --auth-key-id
Auth key id (max. 32 char)
-k, --auth-key
base64 encoded Auth key
-l, --auth-key-timestamp
Auth key timestamp (sec since epoch)
-m, --auth-key-lifetime
Auth key lifetime in sec
-n, --auth-key-as-rs-alg
Authorization Server(AS) - Resource Server(RS) encryption algorithm
-o, --token-nonce
base64 encoded nonce base64(12 octet) = 16 char
-p
This is the token's encryption key. (max. 255 char)
-q, --token-key-id
Token key id (max. 32 char)
-r, --token-key
base64 encoded Token key
-s, --token-key-timestamp
Token key timestamp (sec since epoch)
-t, --token-key-lifetime
Token key lifetime in sec
-u, --token-rs-alg
Token RS encryption algorithm
-z, --token-lifetime
Token lifetime in sec
