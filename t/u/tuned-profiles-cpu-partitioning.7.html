NOM

tuned-profiles-cpu-partitioning - Partitionner les CPU en cœurs isolés et en cœurs de gestion.

DESCRIPTION

Les profils cpu-partitioning* partitionnent les CPU du système en CPU isolés et en CPU de gestion. Ces profils sont destinés aux charges de travail sensibles à la latence.

Un CPU isolé entraîne une réduction de la gigue et des interruptions par le noyau. Ceci est réalisé en vidant le CPU des processus en espace utilisateur, des threads du noyau déplaçables, des gestionnaires d'interruptions, des minuteurs du noyau, etc. La seule source fixe d'interruptions est le tick 1Hz maintenu par le noyau pour conserver les statistiques d'utilisation du CPU. Autrement, la gigue et les interruptions engendrées, le cas échéant, dépendent des services du noyau utilisés par le thread s'exécutant sur le CPU isolé. Les threads qui exécutent une boucle active sans faire d'appels système, tels que les pilotes en espace utilisateur qui accèdent directement au matériel, ne sont supposés être interrompus qu'une fois par seconde par le tick 1Hz.

Un CPU de gestion est l'opposé d'un CPU isolé. Les CPU de gestion exécutent tous les démons, processus shell, threads du noyau, gestionnaires d'interruptions et travaux qui peuvent être envoyés depuis les CPU isolés, tels que les E/S disque, les travaux RCU, les minuteurs, etc.

PROFILS

Les profils suivants sont fournis :

cpu-partitioning
Profil partitionnant les CPU du système en CPU isolés et en CPU de gestion.
cpu-partitioning-powersave
Profil similaire au profil cpu-partitioning, mais avec plus de flexibilité sur la configuration des états C.

CONFIGURATION

Le profil cpu-partitioning est configuré en modifiant le fichier /etc/tuned/cpu-partitioning-variables.conf. Il existe deux options de configuration :

isolated_cores=<LISTE_CPU>
Liste des CPU à isoler. Cette option est obligatoire. Tous les CPU qui ne figurent pas dans cette liste sont automatiquement considérés comme des CPU de gestion.
no_balance_cores=<LISTE_CPU>
Liste des CPU qui ne seront pas pris en compte par le noyau lors de l'équilibrage de charge des processus à l'échelle du système. Généralement, cette liste doit être identique à isolated_cores=. Cette option est facultative.

Le profil cpu-partitioning-powersave est configuré en modifiant le fichier /etc/tuned/cpu-partitioning-powersave-variables.conf. Il prend en charge les mêmes options que le profil cpu-partitioning et une option supplémentaire :

max_power_state=<MAX_CSTATE>
État C maximal que les cœurs sont autorisés à atteindre. Peut être exprimé par son nom (C1E) ou sa latence minimale de réveil, en microsecondes. Ce paramètre est fourni tel quel à `force_latency`. La valeur par défaut est définie sur "cstate.name:C1|10" pour se comporter comme le profil cpu-partitioning.

NOTES IMPORTANTES

  • Le système doit être redémarré après avoir appliqué les profils cpu-partitioning* pour la première fois ou après avoir modifié leur configuration.
  • Les profils cpu-partitioning* peuvent être utilisés sur des machines physiques et des machines virtuelles.
  • Lors de l'utilisation des profils cpu-partitioning* sur une machine physique, il est fortement recommandé de "masquer" les services ksm et ksmtuned dans systemd (s'ils sont installés). Cela peut être fait avec la commande suivante :


    # systemctl mask ksm ksmtuned

  • Les profils cpu-partitioning* n'utilisent pas la fonctionnalité `isolcpus=` du noyau.
  • Sur un système NUMA, il est recommandé d'avoir au moins un CPU de gestion par nœud NUMA.
  • Les profils cpu-partitioning* ne prennent pas en charge l'isolement du cache L3. Cela signifie qu'un CPU de gestion peut toujours dégrader les entrées de cache appartenant aux CPU isolés. Il est recommandé d'utiliser des technologies d'isolement de cache pour remédier à ce problème, telles que la technologie d'allocation de cache d'Intel.
  • Le fait que le noyau puisse désactiver le tick sur les CPU isolés dépend de plusieurs facteurs concernant le comportement des threads en cours d'exécution. Veuillez consulter la documentation nohz_full du noyau pour en savoir plus.
  • Le projet Linux en temps réel a élaboré un document sur les meilleures pratiques pour écrire des applications en temps réel. Bien que les profils cpu-partitioning* ne garantissent pas un temps de réponse en temps réel, plusieurs des techniques d'écriture d'applications en temps réel s'appliquent également aux applications destinées à s'exécuter sous les profils cpu-partitioning*. Veuillez vous référer à ce document sur https://rt.wiki.kernel.org
