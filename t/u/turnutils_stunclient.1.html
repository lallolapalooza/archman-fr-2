INFORMATIONS GÉNÉRALES

Un ensemble de programmes turnutils_* fournit quelques fonctionnalités utilitaires à utiliser pour les tests et la mise en place du serveur TURN.

1.
turnutils_uclient: émule plusieurs clients UDP, TCP, TLS ou DTLS. (ce programme est fourni à des fins de test uniquement !) L'image binaire compilée de ce programme se trouve dans le sous-répertoire bin/.
2.
turnutils_peer: un serveur "écho" simple sans état, uniquement UDP, à utiliser comme serveur final dans le modèle de relais ("pair"). Pour chaque paquet UDP entrant, il le renvoie simplement. (ce programme est fourni à des fins de test uniquement !) Lorsque les clients de test communiquent en mode client-à-client (lorsque le programme "turnutils_uclient" est utilisé avec l'option "-y"), alors turnutils_peer n'est pas nécessaire.

L'image binaire compilée de ce programme se trouve dans le sous-répertoire bin/.

3.
turnutils_stunclient: un exemple simple de client STUN. L'image binaire compilée de ce programme se trouve dans le sous-répertoire bin/.
4.
turnutils_rfc5769check: un utilitaire qui vérifie la correction de l'implémentation du protocole STUN/TURN. Cet utilitaire est utilisé uniquement pour la procédure de vérification de compilation, il n'est pas copié à l'emplacement d'installation.

Dans le sous-répertoire "examples/scripts", vous trouverez des exemples de lignes de commande à utiliser pour exécuter les programmes. Les scripts sont destinés à être exécutés depuis le sous-répertoire examples/, par exemple :

$ cd examples

$ ./scripts/secure_relay.sh

5.
turnutils_natdiscovery: un utilitaire qui fournit la découverte du comportement NAT conformément à la RFC5780. Cet utilitaire découvre le mappage NAT réel et le comportement de filtrage, etc. Soyez conscient que du côté du serveur TURN, deux adresses IP d'écoute différentes doivent être configurées pour pouvoir fonctionner correctement !
6.
turnutils_oauth: un utilitaire qui fournit la génération d'access_token (chiffrement AEAD), la validation et le déchiffrement. Cet utilitaire prend en entrée toutes les clés, les durées de vie et toute information connexe nécessaire à la création et à la validation d'un access_token. Il génère une sortie JSON avec tous les paramètres OAuth PoP qui doivent être transmis au client. La sortie est générée conformément à la RFC7635 Annexe B, Figure 8.

Pour plus de détails, et pour la structure de l'access_token, lisez la rfc7635, et consultez le script dans examples/scripts/oauth.sh.

NOM

turnutils_uclient - cette application d'émulation client est fournie à des fins de test uniquement.

SYNOPIS

$ turnutils_uclient [-tTSvsyhcxg] [options] <adresse-IP-serveur-TURN>

DESCRIPTION

Il a été conçu pour simuler plusieurs clients. Il utilise l'API d'E/S asynchrone de libevent pour gérer plusieurs clients. Un client se connecte au relais, négocie la session et envoie plusieurs messages (nombre configuré) au serveur (relais), en attendant le même nombre de réponses. La longueur des messages est configurable. Le message est un flux d'octets arbitraire. Le nombre de messages à envoyer est configurable.

Options (Flags):

-t
Utiliser TCP pour les communications entre le client et le serveur TURN (par défaut UDP).
-b
Utiliser SCTP pour les communications entre le client et le serveur TURN (par défaut UDP).
-T
Utiliser TCP pour le transport de relais (par défaut - UDP). Implique les options -t, -y, -c, et ignore les options -s, -e, -r et -g. Peut être utilisé avec -b.
-P
TCP Passif (RFC6062 avec paire active). Implique -T.
-S
Connexion SSL sécurisée : SSL/TLS pour TCP, DTLS pour UDP, TLS/SCTP pour SCTP.
-U
Connexion sécurisée non chiffrée (suite eNULL) : SSL/TLS pour TCP, DTLS pour UDP.
-v
Verbeux.
-s
Utiliser la méthode "Send" dans TURN ; par défaut, il utilise les canaux TURN.
-y
Utiliser les connexions client-à-client : paire de canaux RTP/RTCP vers une autre paire de canaux RTP/RTCP. avec cette option, l'application turnutils_peer n'est pas utilisée, car les points d'extrémité de relais alloués communiquent entre eux.
-h
Rester indéfiniment après le dernier paquet envoyé.
-c
Ne pas créer de connexions rtcp.
-x
Demander une adresse de relais IPv6 (RFC6156).
-X
Adresse de relais IPv4 demandée explicitement.
-g
Définir le paramètre DONT_FRAGMENT dans les requêtes TURN.
-D
Effectuer un remplissage de paquets obligatoire même pour UDP (comme pjnath).
-N
Effectuer des tests négatifs (quelques cas limités uniquement).
-R
Effectuer des tests de protocole négatifs.
-O
Mode attaque DOS.
-M
Utiliser TURN ICE Mobility.
-I
Ne pas définir de permissions sur les points d'extrémité de relais TURN (pour tester la fonctionnalité de relais serveur non standard).
-G
Générer des requêtes supplémentaires (créer des permissions, lier des canaux).
-B
Déconnexion aléatoire après quelques paquets initiaux.
-Z
Double allocation (SSODA). Implique l'option -c.
-J
Utiliser oAuth avec la clé de test par défaut kid='north'.

Options avec valeurs requises :

-l
Longueur du message (Défaut : 100 octets).
-i
Fichier certificat (pour les connexions sécurisées uniquement, facultatif).
-k
Fichier clé privée (pour les connexions sécurisées uniquement).
-E
Fichier CA pour la vérification du certificat serveur, si le certificat serveur doit être vérifié.
-p
Port du serveur TURN (Défauts : 3478 non sécurisé, 5349 sécurisé).
-n
Nombre de messages à envoyer (Défaut : 5).
-d
Interface locale (facultatif, Linux uniquement).
-L
Adresse IP locale (facultatif).
-m
Nombre de clients (Défaut : 1, 2 ou 4, selon les options).
-e
Adresse du pair.
-r
Port du pair (Défaut : 3480).
-z
Intervalle de paquets par session en millisecondes (Défaut : 20).
-u
Nom d'utilisateur STUN/TURN.
-w
Mot de passe utilisateur STUN/TURN.
-W
Secret de l'API REST TURN. Le secret "texte brut" par exemple "north" qui est stocké dans la colonne de valeur du secret turn_secret
{ "file_content": "\n table dans la base de données si dynamique, ou la valeur static-auth-secret définie dans\n le fichier de configuration si utilisation de statique.\n
-C
\n
\n Ceci est le symbole (caractère) séparateur de timestamp/nom d'utilisateur dans l'API REST TURN.\n La valeur par défaut est :.\n
\n
-F
\n
\n Suite de chiffrement pour TLS/DTLS. La valeur par défaut est DEFAULT.\n
\n
-o
\n
\n La valeur de l'attribut STUN ORIGIN.\n
\n
-a
\n
\n Bande passante pour la demande de bande passante dans ALLOCATE. La valeur par défaut est\n zéro.\n
\n\n

Voir les exemples dans le répertoire "examples/scripts".

NAME

\n

turnutils_stunclient - un client STUN de base.

\n
\n
\n

SYNOPSIS

\n
$ turnutils_stunclient [options] <adresse-IP-du-serveur-STUN>
\n
\n
\n

DESCRIPTION

\n

Il envoie une requête STUN RFC 5389 "nouvelle" (sur UDP) et\n affiche les informations de réponse.

\n

Options avec valeurs requises :

\n
\n
-p
\n
Port du serveur STUN (Défaut : 3478).
\n
-L
\n
Adresse locale à utiliser (optionnel).
\n
-f
\n
Forcer le traitement RFC 5780.
\n
\n

Le programme turnutils_stunclient vérifie les résultats de\n la première requête et, s'il constate que le serveur STUN prend en charge la RFC\n 5780 (la réponse de liaison le révèle), alors turnutils_stunclient\n effectue quelques requêtes supplémentaires avec des paramètres différents,\n pour démontrer les capacités de découverte de NAT.

\n

Cet utilitaire ne prend pas en charge le protocole STUN "ancien"\n "classique" (RFC 3489).

NAME

turnutils_natdiscovery - un utilitaire qui découvre le mappage et le filtrage NAT comportement selon la RFC 5780.

\n
\n
\n

SYNOPSIS

\n
$ turnutils_natdiscovery [options] <FQDN ou adresse IP du serveur STUN>
\n
\n
\n

DESCRIPTION

\n

turnutils_natdiscovery découvre le comportement de mappage et de\n filtrage NAT, pour déterminer si ce NAT utilise actuellement un mappage\n Indépendant de l'endpoint, Dépendant de l'adresse, ou Dépendant de l'adresse\n et du port et/ou pour déterminer si ce NAT utilise actuellement un filtrage\n Indépendant de l'endpoint, Dépendant de l'adresse, ou Dépendant de l'adresse\n et du port.

\n

Utilisez l'un des indicateurs -m, -f, -c,\n -H pour découvrir le comportement NAT.

\n

Indicateurs :

\n
\n
-m
\n
Découverte du comportement de mappage NAT
\n
-f
\n
Découverte du comportement de filtrage NAT
\n
-t
\n
Découverte du comportement de durée de vie du mappage NAT. Nécessite un timer (-T)
\n
-c
\n
Découverte du comportement de collision NAT
\n
-H
\n
Découverte du comportement de retournement NAT
\n
-P
\n
Ajouter un rembourrage de 1500 octets à la découverte de comportement. Applicable avec tous sauf\n la découverte de durée de vie du mappage NAT.
\n
\n

Options avec valeurs requises :

\n
\n
-p
\n
Port du serveur STUN (Défaut : 3478)
\n
-L
\n
Adresse locale à utiliser (optionnel)
\n
-l
\n
Port local à utiliser (à utiliser avec -L)
\n
-A
\n
Adresse locale secondaire (optionnel). Requise pour la découverte de collision.
\n
-T
\n
Timer de durée de vie du mappage (sec). Utilisé par la découverte du comportement de durée de vie du mappage.
\n
\n

Utilisation :

\n

$ turnutils_natdiscovery -m -f\n stun.example.com

NAME

turnutils_stunclient — STUN/TURN client utilities

SYNOPSIS

turnutils_stunclient [-v] [-f CONFIG] [-p PORT] [-n LOCAL_IP] [-t TOKEN] [-l LIFETIME] [-a ALGORITHM] [-k KEY] [-r REALM] [-u USER] [-w PASSWORD] [-s SERVER] [-d DESTINATION] [-m PROTO]

DESCRIPTION

This is a simple STUN client. It can be used to discover the mapped address and port assigned by a NAT.

It can also be used to discover the relay address and port assigned by a TURN server. In this case, it acts as a TURN client.

The client can also be used for testing the authentication mechanism of the TURN server.

OPTIONS

-a, --hmac-alg
STUN client HMAC algorithm
-d, --destination
destination address of the client
-f, --config-file
configuration file
-k, --token-mac-key
base64 encoded MAC key base64(32 octet) = 44 char
-l, --lifetime
lifetime in sec (Default: 3600)
-m, --protocol
protocol to use (udp or tcp)
-n, --local-ip
local IP address
-p, --port
local port
-q, --token-timestamp
timestamp in format 64 bit unsigned (Native format - Unix), so 48 bit for secs since epoch UTC + 16 bit for 1/64000 fractions of a second. e.g.: the actual unixtimestamp 16 bit left shifted. (Default: actual gmtime)
-r, --realm
realm
-s, --server
server address
-t, --token
base64 encoded encrypted token for validation and decryption
-u, --user
user name
-v, --verbose
verbose mode
-w, --password
password

USAGE

$ turnutils_natdiscovery
