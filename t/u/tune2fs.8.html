TUNE2FS(8) Manuel de l'administrateur système TUNE2FS(8)

NOM

tune2fs - ajuster les paramètres ajustables du système de fichiers sur les systèmes de fichiers ext2/ext3/ext4

SYNTAXE

tune2fs [ -l ] [ -c nombre-maximal-de-montages ] [ -e comportement-erreurs ] [ -f ] [ -i intervalle-entre-vérifications ] [ -I nouvelle-taille-inode ] [ -j ] [ -J options-journal ] [ -m pourcentage-blocs-réservés ] [ -o [^]options-de-montage[,...] ] [ -r nombre-blocs-réservés ] [ -u utilisateur ] [ -g groupe ] [ -C nombre-de-montages ] [ -E options-étendues ] [ -L étiquette-volume ] [ -M dernier-répertoire-monté ] [ -O [^]caractéristique[,...] ] [ -Q options-quota ] [ -T heure-dernière-vérification ] [ -U UUID ] [ -z fichier-annulation ] périphérique

DESCRIPTION

tune2fs permet à l'administrateur système d'ajuster divers paramètres ajustables des systèmes de fichiers ext2, ext3 ou ext4 sous Linux. Les valeurs actuelles de ces options peuvent être affichées en utilisant l'option -l du programme tune2fs(8), ou en utilisant le programme dumpe2fs(8).

Le spécificateur de périphérique peut être soit un nom de fichier (c.-à-d. /dev/sda1), soit un spécificateur LABEL ou UUID : "LABEL=étiquette-volume" ou "UUID=uuid". (c.-à-d. LABEL=home ou UUID=e40486c6-84d5-4f2f-b99c-032281799c9d).

OPTIONS

-c nombre-maximal-de-montages
Ajuste le nombre de montages après lequel le système de fichiers sera vérifié par e2fsck(8). Si nombre-maximal-de-montages est la chaîne "random", tune2fs utilisera une valeur aléatoire entre 20 et 40. Si nombre-maximal-de-montages est 0 ou -1, le nombre de fois où le système de fichiers est monté sera ignoré par e2fsck(8) et le noyau.

L'étalement des nombres de montages auxquels les systèmes de fichiers sont forcés de vérifier permet d'éviter que tous les systèmes de fichiers ne soient vérifiés en même temps lors de l'utilisation de systèmes de fichiers journalisés.

La vérification dépendante du nombre de montages est désactivée par défaut pour éviter des redémarrages longs et imprévus pendant que e2fsck effectue son travail. Si vous êtes préoccupé par des corruptions du système de fichiers causées par de potentiels problèmes matériels ou des bugs du noyau, une meilleure solution que la vérification dépendante du nombre de montages est d'utiliser le programme e2scrub(8). Cela nécessite cependant de placer le système de fichiers sur un volume LVM.

-C nombre-de-montages
Définit le nombre de fois où le système de fichiers a été monté. S'il est défini à une valeur supérieure au paramètre nombre-maximal-de-montages défini par l'option -c, e2fsck(8) vérifiera le système de fichiers au prochain redémarrage.
-e comportement-erreurs
Change le comportement du code du noyau lorsque des erreurs sont détectées. Dans tous les cas, une erreur du système de fichiers entraînera une vérification du système de fichiers au prochain montage par e2fsck(8). comportement-erreurs peut être l'un des éléments suivants :
continue
Continuer l'exécution normale.
remount-ro
Remonter le système de fichiers en lecture seule.
panic
Provoquer un panic du noyau.
-E options-étendues
Définit des options étendues pour le système de fichiers. Les options étendues sont séparées par des virgules et peuvent prendre un argument utilisant le signe égal ('='). Les options étendues suivantes sont prises en charge :
clear_mmp
Réinitialiser le bloc MMP (le cas échéant) à l'état propre. À utiliser uniquement si vous êtes absolument certain que le périphérique n'est pas actuellement monté ou en cours de vérification fsck, sinon une corruption majeure du système de fichiers peut en résulter. Nécessite '-f'.
encoding=nom-encodage
Active la fonctionnalité casefold dans le superbloc et définit nom-encodage comme l'encodage à utiliser. Si nom-encodage n'est pas spécifié, utf8 est utilisé. L'encodage ne peut pas être modifié si casefold était précédemment activé.
encoding_flags=flags-encodage
Définit les paramètres des opérations d'encodage des noms de fichiers. Si un drapeau n'est pas modifié via ce paramètre, sa valeur par défaut est utilisée. flags-encodage doit être une liste de drapeaux séparés par des virgules à activer. Les drapeaux ne peuvent pas être modifiés si casefold était précédemment activé.

Le seul drapeau qui peut être défini actuellement est strict, ce qui signifie que les chaînes invalides doivent être rejetées par le système de fichiers. Dans la configuration par défaut, le drapeau strict est désactivé.

force_fsck
Définit un drapeau dans le superbloc du système de fichiers indiquant que des erreurs ont été trouvées. Cela forcera fsck à s'exécuter au prochain montage.
hash_alg=alg-hachage
Définit l'algorithme de hachage par défaut utilisé pour les systèmes de fichiers avec des répertoires b-tree hachés. Les algorithmes valides acceptés sont : legacy, half_md4, et tea.
mmp_update_interval=intervalle
Ajuste l'intervalle de mise à jour initial de MMP à intervalle secondes. Spécifier un intervalle de 0 signifie utiliser l'intervalle par défaut. L'intervalle spécifié doit être inférieur à 300 secondes. Nécessite que la fonctionnalité mmp soit activée.
mount_opts=chaîne-option-montage
Définit un ensemble d'options de montage par défaut qui seront utilisées lors du montage du système de fichiers. Contrairement aux options de montage par défaut basées sur un masque de bits qui peuvent être spécifiées avec l'option -o, chaîne-option-montage est une chaîne arbitraire d'une longueur maximale de 63 octets, qui est stockée dans le superbloc.
Le pilote de système de fichiers ext4 appliquera d'abord les options par défaut basées sur un masque de bits, puis analysera la chaîne-option-montage, avant d'analyser les options de montage passées par le programme mount(8).
Ce réglage du superbloc n'est pris en compte qu'à partir des noyaux 2.6.35+ ; et pas du tout par les pilotes de systèmes de fichiers ext2 et ext3.
orphan_file_size=taille
Définit la taille du fichier pour le suivi des inodes désindexés mais toujours ouverts et des inodes dont la troncature est en cours. Un fichier plus grand permet une meilleure scalabilité, réserver quelques blocs par processeur est idéal.
stride=taille-pas
Configure le système de fichiers pour un tableau RAID avec une taille-pas de blocs de système de fichiers. C'est le nombre de blocs lus ou écrits sur le disque avant de passer au disque suivant. Cela affecte principalement le placement des métadonnées du système de fichiers, comme les bitmaps, au moment de la création avec mke2fs(8) pour éviter de les placer sur un seul disque, ce qui pourrait nuire aux performances. Cela peut aussi être utilisé par l'allocateur de blocs.
stripe_width=largeur-stripe
Configure le système de fichiers pour un tableau RAID avec une largeur-stripe de blocs de système de fichiers par stripe. C'est typiquement taille-pas * N, où N est le nombre de disques de données dans le RAID (par exemple, RAID 5 N+1, RAID 6 N+2). Cela permet à l'allocateur de blocs d'éviter les opérations de lecture-modification-écriture de la parité dans un stripe RAID, si possible, lors de l'écriture des données.
test_fs
Définit un drapeau dans le superbloc du système de fichiers indiquant qu'il peut être monté en utilisant du code noyau expérimental, tel que le système de fichiers ext4dev.
^test_fs
Efface le drapeau test_fs, indiquant que le système de fichiers ne doit être monté qu'avec des systèmes de fichiers de niveau production.
-f
Force la désactivation de certaines vérifications de sécurité du système de fichiers. Normalement, tune2fs refusera de modifier un système de fichiers qui a été monté plus d'un certain nombre de fois (ce nombre est défini par l'option -c) ou qui n'a pas été vérifié depuis un certain temps (ceci est spécifié par l'option -i). L'option -f force tune2fs à procéder à la modification demandée, même si ces vérifications de sécurité échouent. Cette option n'est généralement utile qu'en conjonction avec l'option -j ou l'option -O pour ajouter un journal à un système de fichiers qui n'en a pas.
-g groupe
Change le groupe auquel les blocs réservés par défaut sont attribués. Le groupe peut être un nom ou un ID numérique.
-i intervalle-entre-vérifications
Ajuste le temps maximum autorisé entre deux vérifications de système de fichiers. Le intervalle-entre-vérifications est spécifié en jours (d), semaines (w), ou mois (m). Si intervalle-entre-vérifications est 0, les vérifications basées sur le temps sont désactivées. Si le temps entre les vérifications est supérieur à celui configuré, une vérification sera effectuée lors du prochain montage. Le réglage par défaut est de 0 jour (désactivé).
-I nouvelle-taille-inode
Change la taille des inodes sur le système de fichiers. Les inodes plus grands permettent de stocker plus d'informations d'attributs de fichier, notamment les extensions étendues POSIX. Les systèmes de fichiers ext3 et ext4 nécessitent des inodes d'au moins 256 octets. Le réglage par défaut est de 128 octets pour ext2 et 256 octets pour ext3 et ext4. Notez que les inodes plus petits peuvent être définis, mais ils sont généralement utilisés dans des contextes de développement et ne devraient pas être utilisés pour des systèmes de fichiers de production.
-j
Crée une nouvelle partition journal ext3 et ajoute des informations de journalisation au système de fichiers ext2 spécifié. Le système de fichiers doit d'abord être désactivé. Les paramètres du journal sont les paramètres par défaut, sauf s'ils sont modifiés par l'option -J.
-J options-journal
Définit les options du journal pour les systèmes de fichiers ext3. Ces options sont spécifiées sous la forme d'une liste d'options séparées par des virgules. Les options de journal prises en charge sont :
device=périphérique-journal
Crée un journal externe pour le système de fichiers spécifié. Le périphérique-journal est un nom de fichier d'un périphérique bloc de taille fixe (par exemple, /dev/sda3).
size=taille-journal
Définit la taille du journal en mégaoctets. La taille du journal doit être une puissance de 2, comprise entre 1 et 102400 Mo. La taille par défaut du journal est de 32 Mo.
-L étiquette-volume
Définit l'étiquette du volume du système de fichiers. L'étiquette peut être une chaîne de 1 à 16 caractères.
-m pourcentage-blocs-réservés
Définit le pourcentage de blocs réservés pour les utilisateurs privilégiés. Si ce pourcentage est trop élevé, il peut être réduit, permettant à l'espace supplémentaire d'être utilisé par les utilisateurs normaux. Ce réglage est généralement compris entre 0 et 10 %.
-M dernier-répertoire-monté
Définit le nom du dernier répertoire où le système de fichiers a été monté. Ceci est principalement utilisé par les utilitaires de récupération pour déterminer où tenter de monter le système de fichiers en cas d'erreur.
-O [^]caractéristique[,...]
Modifie la liste des fonctionnalités activées ou désactivées pour le système de fichiers. Les caractéristiques sont séparées par des virgules. Si une caractéristique est précédée du caractère `^', elle sera désactivée ; sinon, elle sera activée. La liste des caractéristiques possibles est disponible dans la page de manuel e2fsck(8). Certaines caractéristiques ne peuvent être ajoutées qu'au moment de la création du système de fichiers.

Les fonctionnalités suivantes peuvent être ajoutées ou supprimées:

dir_index
Utilise des arbres hachés pour indexer les répertoires, ce qui permet une recherche plus rapide des fichiers dans de grands répertoires.
has_journal
Active le support du journal pour ext3.
large_file
Permet de créer des fichiers de plus de 2 Go.
resize_inode
Permet de redimensionner le système de fichiers.
extents
Utilise des extents au lieu de pointeurs de blocs pour allouer de l'espace, ce qui améliore les performances et la gestion des fichiers volumineux.
flex_bg
Permet un meilleur regroupement des groupes de blocs, ce qui améliore les performances.
quota
Active le support des quotas de disque.
sparse_super
Réduit la taille du superbloc pour les grands systèmes de fichiers.
large_dir
Permet des répertoires contenant plus de 40 000 entrées.
filetype
Stocke le type de fichier dans les entrées de répertoire.
mmp
Active le mécanisme de surveillance et de protection des montages multiples (MMP).
encrypt
Active le chiffrement au niveau du système de fichiers.
extents_tree
Utilise des arbres d'extents pour une gestion plus efficace de l'allocation d'espace.
metadata_csum
Active les sommes de contrôle pour les métadonnées afin d'améliorer l'intégrité des données.
snapshot
Active la fonctionnalité d'instantanés de volume.
uninit_bg
Utilise des groupes de blocs non initialisés pour accélérer la création du système de fichiers.
verity
Active la vérification de l'intégrité des données via des arbres de hachage.
-o [^]options-de-montage[,...]
Définit les options de montage par défaut pour le système de fichiers. Ces options sont stockées dans le superbloc et sont utilisées par le système d'exploitation lors du montage du système de fichiers. Les options sont séparées par des virgules. Si une option est précédée du caractère `^', elle sera désactivée ; sinon, elle sera activée. Les options de montage supportées incluent :
acl
Active le support des listes de contrôle d'accès (ACL).
atime
Met à jour l'heure d'accès à chaque lecture de fichier.
noatime
Ne met pas à jour l'heure d'accès aux fichiers.
nodiratime
Ne met pas à jour l'heure d'accès aux répertoires.
relatime
Met à jour l'heure d'accès uniquement si l'heure d'accès précédente est plus ancienne que l'heure de modification ou de changement.
strictatime
Met à jour l'heure d'accès à chaque accès.
debug
Active les messages de débogage.
err=comportement-erreurs
Définit le comportement en cas d'erreur. Les valeurs possibles sont : continue, remount-ro, ou panic.
bsddf
Utilise l'algorithme BSD pour calculer l'espace libre.
minixdf
Utilise l'algorithme MINIX pour calculer l'espace libre.
localdir
Le répertoire racine est local.
-Q options-quota
Définit les options du système de quotas. Les options sont séparées par des virgules. Les options possibles sont :
usrquota
Active les quotas d'utilisateur.
grpquota
Active les quotas de groupe.
-r nombre-blocs-réservés
Définit le nombre absolu de blocs réservés pour les utilisateurs privilégiés. Ce réglage supprime le calcul basé sur un pourcentage.
-T heure-dernière-vérification
Définit l'heure de la dernière vérification du système de fichiers. L'heure est spécifiée en secondes depuis le début de l'époque (epoch).
-u utilisateur
Définit l'utilisateur auquel les blocs réservés par défaut sont attribués. Le utilisateur peut être un nom ou un ID numérique.
-U UUID
Définit l'UUID (Universally Unique Identifier) du système de fichiers. L'UUID est une chaîne de 128 bits représentée sous la forme hexadécimale (par exemple, e40486c6-84d5-4f2f-b99c-032281799c9d).
-z fichier-annulation
Crée un fichier d'annulation spécifié par fichier-annulation. Ce fichier peut être utilisé pour annuler les modifications apportées au système de fichiers par tune2fs. Il est destiné à être utilisé en cas de problèmes imprévus.

EXEMPLES

Pour afficher les paramètres du système de fichiers /dev/sda1 :

        tune2fs -l /dev/sda1

Pour désactiver la vérification du système de fichiers /dev/sda1 au démarrage :

        tune2fs -c 0 -i 0 /dev/sda1

Pour activer la fonctionnalité extents sur un système de fichiers ext2 existant :

        tune2fs -O extents /dev/sda1

Pour ajouter un journal ext3 à un système de fichiers ext2 existant : Notez que le système de fichiers doit être désactivé avant d'utiliser cette commande.

        tune2fs -j /dev/sda1

Pour ajouter un journal ext3 avec une taille de journal de 1024 Mo à un système de fichiers ext2 existant :

        tune2fs -j -J size=1024 /dev/sda1

Pour réduire le pourcentage de blocs réservés à 1% :

        tune2fs -m 1 /dev/sda1

Pour activer la fonctionnalité metadata_csum et vérifier les métadonnées au prochain montage :

        tune2fs -O metadata_csum,force_fsck /dev/sda1

VOIR AUSSI

dumpe2fs(8), e2fsck(8), mke2fs(8), mount(8)

-f
Force l'opération tune2fs à se terminer même en cas d'erreurs. Cette option est utile lors de la suppression de la fonctionnalité de système de fichiers has_journal d'un système de fichiers qui possède un journal externe (ou est corrompu de telle sorte qu'il semble avoir un journal externe), mais que ce journal externe n'est pas disponible. Si le système de fichiers semble nécessiter une relecture du journal, le flag -f doit être spécifié deux fois pour continuer.

AVERTISSEMENT : La suppression d'un journal externe d'un système de fichiers qui n'a pas été démonté proprement sans avoir au préalable rejoué le journal externe peut entraîner une perte de données sévère et une corruption du système de fichiers.

-g groupe
Définit le groupe qui peut utiliser les blocs réservés du système de fichiers. Le paramètre groupe peut être un gid numérique ou un nom de groupe. Si un nom de groupe est donné, il est converti en gid numérique avant d'être stocké dans le superbloc.
-i intervalle-entre-vérifications[d|m|w]
Ajuste le temps maximum entre deux vérifications du système de fichiers. Aucun suffixe ou d interprétera le nombre intervalle-entre-vérifications comme des jours, m comme des mois, et w comme des semaines. Une valeur de zéro désactivera la vérification dépendante du temps.

Il y a des avantages et des inconvénients à désactiver ces vérifications périodiques ; voir la discussion sous l'option -c (vérification dépendante du nombre de montages) pour plus de détails.

-I
Change la taille des inœuds utilisée par le système de fichiers. Cela nécessite de réécrire la table des inœuds, donc il faut d'abord vérifier la cohérence du système de fichiers à l'aide de e2fsck(8). Cette opération peut également prendre du temps et le système de fichiers peut être corrompu et des données perdues s'il est interrompu pendant la conversion du système de fichiers. Il est recommandé de sauvegarder le système de fichiers avant de modifier la taille des inœuds.
Les systèmes de fichiers avec une taille d'inœud de 128 octets ne prennent pas en charge les horodatages au-delà du 19 janvier 2038. Les inœuds de 256 octets ou plus supporteront les horodatages étendus, les identifiants de projet et la possibilité de stocker certains attributs étendus dans la table des inœuds pour améliorer les performances.
-j
Ajoute un journal ext3 au système de fichiers. Si l'option -J n'est pas spécifiée, les paramètres du journal par défaut seront utilisés pour créer un journal de taille appropriée (compte tenu de la taille du système de fichiers) stocké dans le système de fichiers. Notez que vous devez utiliser un noyau qui prend en charge ext3 pour pouvoir réellement utiliser le journal.
Si cette option est utilisée pour créer un journal sur un système de fichiers monté, un fichier immuable, .journal, sera créé dans le répertoire de plus haut niveau du système de fichiers, car c'est la seule manière sûre de créer l'inœud du journal pendant que le système de fichiers est monté. Tant que le journal ext3 est visible, il n'est pas sûr de le supprimer ou de le modifier pendant que le système de fichiers est monté ; pour cette raison, le fichier est marqué comme immuable. Lors de la vérification des systèmes de fichiers non montés, e2fsck(8) déplacera automatiquement les fichiers .journal vers l'inœud de journal réservé et invisible. Pour tous les systèmes de fichiers, sauf le système de fichiers racine, cela devrait se produire automatiquement et naturellement lors du prochain cycle de démarrage. Comme le système de fichiers racine est monté en lecture seule, e2fsck(8) doit être exécuté depuis une disquette de secours pour effectuer cette transition.
Sur certaines distributions, comme Debian, si un disque d'amorçage initial est utilisé, les scripts initrd convertiront automatiquement un système de fichiers racine ext2 en ext3 si le fichier /etc/fstab spécifie le système de fichiers ext3 pour le système de fichiers racine afin d'éviter d'avoir à utiliser une disquette de secours pour ajouter un journal ext3 au système de fichiers racine.
-J options-journal
Remplace les paramètres par défaut du journal ext3. Les options du journal sont séparées par des virgules et peuvent prendre un argument à l'aide du signe égal ('='). Les options de journal suivantes sont prises en charge :
device=journal-externe
Attache le système de fichiers au périphérique bloc de journal situé sur journal-externe. Le journal externe doit déjà avoir été créé en utilisant la commande
mke2fs -O journal_dev journal-externe
Notez que journal-externe doit être formaté avec la même taille de bloc que les systèmes de fichiers qui l'utiliseront. De plus, bien qu'il existe une prise en charge pour attacher plusieurs systèmes de fichiers à un seul journal externe, le noyau Linux et e2fsck(8) ne prennent pas encore en charge les journaux externes partagés.
Au lieu de spécifier directement un nom de périphérique, journal-externe peut également être spécifié par LABEL=label ou UUID=UUID pour localiser le journal externe par son étiquette de volume ou son UUID stocké dans le superbloc ext2 au début du journal. Utilisez dumpe2fs(8) pour afficher l'étiquette de volume et l'UUID d'un périphérique journal. Voir également l'option -L de tune2fs(8).
fast_commit_size=taille-commit-rapide
Crée une zone de journal de validation rapide supplémentaire de taille taille-commit-rapide kilo-octets. Cette option n'est valide que si la fonctionnalité fast_commit est activée sur le système de fichiers. Si cette option n'est pas spécifiée et si la fonctionnalité fast_commit est activée, la taille de la zone de validation rapide est par défaut de taille-journal / 64 méga-octets. La taille totale du journal avec la fonctionnalité fast_commit activée est taille-journal + ( taille-commit-rapide * 1024) méga-octets. La taille totale du journal ne peut pas dépasser 10 240 000 blocs de système de fichiers ou la moitié de la taille totale du système de fichiers (le plus petit des deux).
location=emplacement-journal
Spécifie l'emplacement du journal. L'argument emplacement-journal peut être spécifié comme un numéro de bloc, ou si le nombre a un suffixe d'unité (par exemple, 'M', 'G', etc.), il est interprété comme le décalage par rapport au début du système de fichiers.
size=taille-journal
Crée un journal stocké dans le système de fichiers de taille taille-journal méga-octets. La taille du journal doit être d'au moins 1024 blocs de système de fichiers (c'est-à-dire 1 MiB si vous utilisez des blocs de 1 Ko, 4 MiB si vous utilisez des blocs de 4 Ko, etc.) et ne peut pas dépasser 10 240 000 blocs de système de fichiers. Il doit y avoir suffisamment d'espace libre dans le système de fichiers pour créer un journal de cette taille.
Seule l'une des options size ou device peut être donnée pour un système de fichiers.
-l
Liste le contenu du superbloc du système de fichiers, y compris les valeurs actuelles des paramètres qui peuvent être définis via ce programme.
-L étiquette-volume
Définit l'étiquette de volume du système de fichiers. Les étiquettes de systèmes de fichiers ext2 ne peuvent pas dépasser 16 caractères ; si étiquette-volume est plus long que 16 caractères, tune2fs le tronquera et affichera un avertissement. Pour les autres systèmes de fichiers qui prennent en charge la manipulation d'étiquettes en ligne et qui sont montés, tune2fs fonctionnera également, mais il n'essaiera pas de tronquer l'étiquette-volume du tout. L'étiquette de volume peut être utilisée par mount(8), fsck(8), et /etc/fstab(5) (et potentiellement d'autres) en spécifiant LABEL=étiquette-volume au lieu d'un nom de périphérique bloc spécial comme /dev/hda5.
-m pourcentage-blocs-réservés
Définit le pourcentage du système de fichiers qui ne peut être alloué que par des processus privilégiés. Réserver un certain nombre de blocs du système de fichiers pour être utilisés par des processus privilégiés permet d'éviter la fragmentation du système de fichiers et de permettre aux démons système, tels que syslogd(8), de continuer à fonctionner correctement après que les processus non privilégiés ont été empêchés d'écrire sur le système de fichiers. Normalement, le pourcentage par défaut de blocs réservés est de 5 %.
-M répertoire-dernier-montage
Définit le répertoire de dernier montage pour le système de fichiers.
-o [^]option-montage[,...]
Définit ou efface les options de montage par défaut indiquées dans le système de fichiers. Les options de montage par défaut peuvent être remplacées par des options de montage spécifiées soit dans /etc/fstab(5) soit dans les arguments de ligne de commande de mount(8). Les anciens noyaux peuvent ne pas prendre en charge cette fonctionnalité ; en particulier, les noyaux précédant 2.4.20 ignoreront presque certainement le champ des options de montage par défaut dans le superbloc.
Plusieurs options de montage peuvent être effacées ou définies en séparant les fonctionnalités par des virgules. Les options de montage préfixées par un caractère circonflexe ('^') seront effacées du superbloc du système de fichiers ; les options de montage sans caractère préfixe ou préfixées par un signe plus ('+') seront ajoutées au système de fichiers.
Les options de montage suivantes peuvent être définies ou effacées à l'aide de tune2fs :
debug
Active le code de débogage pour ce système de fichiers.
bsdgroups
Émule le comportement BSD lors de la création de nouveaux fichiers : ils prendront l'identifiant de groupe du répertoire dans lequel ils ont été créés. Le comportement par défaut de System V est que les fichiers nouvellement créés prennent le fsgid du processus en cours, sauf si le répertoire a le bit setgid défini, auquel cas il prend le gid du répertoire parent et reçoit également le bit setgid s'il s'agit lui-même d'un répertoire.
user_xattr
Active les attributs étendus spécifiés par l'utilisateur.
acl
Active les listes de contrôle d'accès Posix.
uid16
Désactive les UID et GID 32 bits. Ceci est pour l'interopérabilité avec les anciens noyaux qui ne stockent et n'attendent que des valeurs 16 bits.
journal_data
Lorsque le système de fichiers est monté avec la journalisation e
enabled, toutes les données (pas uniquement les métadonnées) sont validées dans le journal avant d'être écrites dans le système de fichiers principal.
journal_data_ordered
Lorsque le système de fichiers est monté avec la journalisation activée, toutes les données sont forcées directement dans le système de fichiers principal avant que ses métadonnées ne soient validées dans le journal.
journal_data_writeback
Lorsque le système de fichiers est monté avec la journalisation activée, les données peuvent être écrites dans le système de fichiers principal après que ses métadonnées aient été validées dans le journal. Cela peut augmenter le débit, cependant, cela peut permettre à d'anciennes données d'apparaître dans les fichiers après un crash et une récupération de journal.
nobarrier
Le système de fichiers sera monté avec les opérations de barrière dans le journal désactivées. (Cette option n'est actuellement prise en charge que par le pilote de système de fichiers ext4 dans les noyaux 2.6.35+.)
block_validity
Le système de fichiers sera monté avec l'option block_validity activée, ce qui entraîne des vérifications supplémentaires après la lecture ou l'écriture depuis le système de fichiers. Cela empêche les blocs de métadonnées corrompus d'endommager le système de fichiers en écrasant des parties de la table d'inodes ou des descripteurs de groupe de blocs. Cela a un coût en termes de surcharge mémoire et CPU accrue, c'est pourquoi elle n'est activée qu'à des fins de débogage. (Cette option n'est actuellement prise en charge que par le pilote de système de fichiers ext4 dans les noyaux 2.6.35+.)
discard
Le système de fichiers sera monté avec l'option de montage discard. Cela obligera le pilote du système de fichiers à utiliser la fonctionnalité trim/discard de certains périphériques de stockage (tels que les SSD et les disques à provisionnement fin disponible sur certains baies de stockage d'entreprise) pour informer le périphérique de stockage que les blocs appartenant à des fichiers supprimés peuvent être réutilisés à d'autres fins. (Cette option n'est actuellement prise en charge que par le pilote de système de fichiers ext4 dans les noyaux 2.6.35+.)
nodelalloc
Le système de fichiers sera monté avec l'option de montage nodelalloc. Cela désactivera la fonctionnalité d'allocation retardée. (Cette option n'est actuellement prise en charge que par le pilote de système de fichiers ext4 dans les noyaux 2.6.35+.)
-O [^]fonctionnalité[,...]
Définit ou efface les fonctionnalités (options) du système de fichiers indiquées dans le système de fichiers. Plus d'une fonctionnalité de système de fichiers peut être effacée ou définie en séparant les fonctionnalités par des virgules. Les fonctionnalités de système de fichiers précédées d'un signe caret ('^') seront effacées dans le superbloc du système de fichiers ; les fonctionnalités de système de fichiers sans signe de préfixe ou précédées d'un signe plus ('+') seront ajoutées au système de fichiers. Pour une description détaillée des fonctionnalités du système de fichiers, veuillez consulter la page de manuel ext4(5).
Les fonctionnalités de système de fichiers suivantes peuvent être définies ou effacées à l'aide de tune2fs :
64bit
Permet au système de fichiers d'être plus grand que 2^32 blocs.
casefold
Active la prise en charge de la casse sensible aux majuscules/minuscules au niveau du système de fichiers. L'option ne peut être effacée que si le système de fichiers ne contient aucun répertoire avec l'attribut F.
dir_index
Utilise des arbres B hachés pour accélérer les recherches dans les grands répertoires.
dir_nlink
Permet plus de 65000 sous-répertoires par répertoire.
ea_inode
Permet que la valeur de chaque attribut étendu soit placée dans les blocs de données d'un inode séparé si nécessaire, augmentant ainsi la limite de taille et de nombre d'attributs étendus par fichier. Tune2fs ne prend actuellement en charge que la définition de cette fonctionnalité de système de fichiers.
encrypt
Active la prise en charge du chiffrement au niveau du système de fichiers. Tune2fs ne prend actuellement en charge que la définition de cette fonctionnalité de système de fichiers.
extent
Active l'utilisation d'arbres d'étendues pour stocker l'emplacement des blocs de données dans les inodes. Tune2fs ne prend actuellement en charge que la définition de cette fonctionnalité de système de fichiers.
extra_isize
Active les champs d'inodes étendus utilisés par ext4.
filetype
Stocke les informations de type de fichier dans les entrées de répertoire.
flex_bg
Permet aux bitmaps et aux tables d'inodes d'un groupe de blocs d'être placés n'importe où sur le support de stockage. Tune2fs ne réorganisera pas l'emplacement des tables d'inodes et des bitmaps d'allocation, comme le fera mke2fs(8) lors de la création d'un système de fichiers fraîchement formaté avec flex_bg activé.
has_journal
Utilise un journal pour assurer la cohérence du système de fichiers même après des arrêts inopinés. Définir la fonctionnalité du système de fichiers équivaut à utiliser l'option -j.
fast_commit
Active la fonctionnalité de journalisation de validation rapide pour améliorer la latence de fsync.
large_dir
Augmente la limite sur le nombre de fichiers par répertoire. Tune2fs ne prend actuellement en charge que la définition de cette fonctionnalité de système de fichiers.
huge_file
Prend en charge les fichiers de plus de 2 téraoctets.
large_file
Le système de fichiers peut contenir des fichiers de plus de 2 GiB.
metadata_csum
Stocke une somme de contrôle pour protéger le contenu de chaque bloc de métadonnées.
metadata_csum_seed
Permet au système de fichiers de stocker la graine de somme de contrôle des métadonnées dans le superbloc, permettant à l'administrateur de changer l'UUID d'un système de fichiers en utilisant la fonctionnalité metadata_csum lorsqu'il est monté.
mmp
Active ou désactive la fonctionnalité de protection de montage multiple (MMP).
orphan_file
Stocke la liste des inodes orphelins dans plusieurs blocs au lieu d'une seule chaîne pour éviter des goulots d'étranglement potentiels à l'échelle pour les charges de travail qui effectuent un grand nombre de troncations ou d'extensions de fichiers en parallèle.
project
Active le suivi des identifiants de projet. Ceci est utilisé pour le suivi des quotas de projet.
quota
Active les inodes internes de quota du système de fichiers.
read-only
Force le noyau à monter le système de fichiers en lecture seule.
resize_inode
Réserve de l'espace pour que la table des descripteurs de groupe de blocs puisse croître à l'avenir. Tune2fs ne prend en charge que l'effacement de cette fonctionnalité de système de fichiers.
sparse_super
Limite le nombre de superblocs de sauvegarde pour économiser de l'espace sur les grands systèmes de fichiers. Tune2fs ne prend actuellement en charge que la définition de cette fonctionnalité de système de fichiers.
stable_inodes
Empêche le système de fichiers d'être réduit ou son UUID d'être modifié, afin de permettre l'utilisation de paramètres de chiffrement spécialisés qui utilisent les numéros d'inode et l'UUID. Tune2fs ne prend actuellement en charge que la définition de cette fonctionnalité de système de fichiers.
uninit_bg
Permet au noyau d'initialiser les bitmaps et les tables d'inodes de manière paresseuse, et de maintenir un niveau élevé pour les inodes inutilisés dans un système de fichiers, afin de réduire le temps d'e2fsck(8). La première exécution de e2fsck après l'activation de cette fonctionnalité prendra le temps complet, mais les exécutions suivantes de e2fsck ne prendront qu'une fraction du temps d'origine, en fonction de la saturation du système de fichiers.
verity
Active la prise en charge des fichiers protégés par verity. Tune2fs ne prend actuellement en charge que la définition de cette fonctionnalité de système de fichiers.
Après avoir défini ou effacé les fonctionnalités de système de fichiers sparse_super, uninit_bg, filetype ou resize_inode, le système de fichiers peut nécessiter d'être vérifié à l'aide de e2fsck(8) pour le ramener à un état cohérent. Tune2fs affichera un message demandant à l'administrateur système d'exécuter e2fsck(8) si nécessaire. Après avoir défini la fonctionnalité dir_index, e2fsck -D peut être exécuté pour convertir les répertoires existants au format arbre B haché. L'activation de certaines fonctionnalités de système de fichiers peut empêcher le système de fichiers d'être monté par des noyaux qui ne prennent pas en charge ces fonctionnalités. En particulier, les fonctionnalités uninit_bg et flex_bg ne sont prises en charge que par le système de fichiers ext4.
-r nombre-de-blocs-réservés
Définit le nombre de blocs réservés du système de fichiers.
-Q options-de-quota
Définit la fonctionnalité 'quota' sur le superbloc et travaille sur les fichiers de quota pour le type de quota donné. Les options de quota peuvent être une ou plusieurs des suivantes :
[^]usrquota
Définit/efface l'inode de quota utilisateur dans le superbloc.
[^]grpquota
Définit/efface l'inode de quota de groupe dans le superbloc.
[^]prjquota
Définit/efface l'inode de quota de projet dans le superbloc.
-T temps-de-dernière-vérification
Définit l'heure de dernière vérification du système de fichiers à l'aide de e2fsck. L'heure est interprétée à l'aide du fuseau horaire local actuel. Cela peut être utile dans les scripts qui utilisent un gestionnaire de volumes logiques pour créer un instantané cohérent d'un système de fichiers, puis vérifier le système de fichiers pendant les heures creuses pour s'assurer qu'il n'a pas été corrompu en raison de problèmes matériels, etc. Si le système de fichiers était propre, alors cette option peut être utilisée pour définir le temps de dernière vérification sur le système de fichiers d'origine. Le format de temps
-last-checked est le format de date international, avec un spécificateur de temps facultatif, c'est-à-dire AAAA MM JJ [HH [MM [SS]]]. Le mot-clé now est également accepté, auquel cas l'heure de la dernière vérification sera définie à l'heure actuelle.
-u utilisateur
Définit l'utilisateur qui peut utiliser les blocs de système de fichiers réservés. utilisateur peut être un uid numérique ou un nom d'utilisateur. Si un nom d'utilisateur est donné, il est converti en uid numérique avant d'être stocké dans le superbloc.
-U UUID
Définit l'identifiant unique universel (UUID) du système de fichiers à UUID. Le format de l'UUID est une série de chiffres hexadécimaux séparés par des tirets, comme ceci : « c1b9d5a2-f162-11cf-9ece-0020afc76f16 ». Le paramètre UUID peut également être l'un des éléments suivants :
clear
effacer l'UUID du système de fichiers
random
générer un nouvel UUID aléatoire
time
générer un nouvel UUID basé sur le temps
L'UUID peut être utilisé par mount(8), fsck(8), et /etc/fstab(5) (et éventuellement d'autres) en spécifiant UUID=uuid au lieu d'un nom de périphérique bloc spécial comme /dev/hda1.
Voir uuidgen(8) pour plus d'informations. Si le système ne dispose pas d'un bon générateur de nombres aléatoires tel que /dev/random ou /dev/urandom, tune2fs utilisera automatiquement un UUID basé sur le temps au lieu d'un UUID généré aléatoirement.
-z undo_file
Avant de réécrire un bloc du système de fichiers, écrire le contenu précédent du bloc dans un fichier d'annulation. Ce fichier d'annulation peut être utilisé avec e2undo(8) pour restaurer le contenu précédent du système de fichiers en cas de problème. Si la chaîne vide est passée comme argument undo_file, le fichier d'annulation sera écrit dans un fichier nommé tune2fs-périphérique.e2undo dans le répertoire spécifié via la variable d'environnement E2FSPROGS_UNDO_DIR.

AVERTISSEMENT : Le fichier d'annulation ne peut pas être utilisé pour récupérer après une panne de courant ou un plantage système.
