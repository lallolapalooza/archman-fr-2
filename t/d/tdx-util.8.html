NOM

tdx-util - utilitaire de manipulation de la vue d'ensemble pour tradindexed

SYNOPIS

tdx-util [-AFcgioO] [-a article] [-f statut] [-n groupe_de_nouvelles] [-p chemin] [-R chemin]

DESCRIPTION

tdx-util est une interface administrative pour la méthode de vue d'ensemble tradindexed pour INN. Il ne fonctionne que sur les bases de données de vue d'ensemble tradindexed, pas sur tout autre type de vue d'ensemble INN. (Voir les programmes dédiés ovdb_stat(8) et ovsqlite-util(8) pour les méthodes de vue d'ensemble ovdb et ovqslite.) Il permet à l'administrateur de décharger diverses informations sur l'état interne de la vue d'ensemble, de l'auditer pour détecter des erreurs et de reconstruire des portions de la base de données de vue d'ensemble.

La méthode de vue d'ensemble tradindexed devrait se verrouiller correctement et il devrait donc être sûr d'exécuter cet utilitaire et d'effectuer toute opération qu'il effectue, y compris les réparations complètes ou les reconstructions de vue d'ensemble par groupe, pendant que le serveur est en cours d'exécution. Cependant, notez que certaines des opérations effectuées par cet utilitaire peuvent prendre une période prolongée et détiendront des verrous dans la base de données de vue d'ensemble pendant cette période, ce qui, selon ce que fait le serveur, peut provoquer le blocage du serveur jusqu'à ce que tdx-util termine son opération.

Les opérations de déchargement sont -i, qui décharge l'index maître de la base de données de vue d'ensemble, -g, qui décharge l'index d'un groupe individuel, et -o et -O, qui déchargent les informations de vue d'ensemble d'un groupe particulier (y compris les métadonnées supplémentaires stockées dans l'index) dans deux formats différents. Pour -g, -o et -O, l'option -n doit également être donnée pour spécifier un groupe de nouvelles sur lequel opérer.

Pour ajouter un nouveau groupe de nouvelles à la base de données de vue d'ensemble, utilisez -c. Un groupe doit être spécifié avec -n. Si le statut du groupe est autre que "y", il doit être spécifié avec -f, et les numéros d'articles bas et hauts peuvent être spécifiés avec -a. Si un seul numéro est donné plutôt qu'une plage, il sera considéré comme la marque haute et la marque basse sera réglée sur 1.

Pour auditer toute la base de données de vue d'ensemble à la recherche de problèmes, utilisez -A. Tout problème détecté sera signalé sur la sortie d'erreur standard. Utilisez -F pour corriger les erreurs détectées.

Pour reconstruire la base de données d'un groupe de nouvelles particulier, utilisez -R. L'option -R prend un chemin vers un répertoire qui contient tous les articles de ce groupe de nouvelles, un par fichier. Les noms des fichiers doivent être les numéros des articles de ce groupe. (Autrement dit, ce répertoire doit être un répertoire spool traditionnel pour ce groupe.) L'option -n doit également être donnée pour spécifier le groupe de nouvelles pour lequel la vue d'ensemble est reconstruite.

Pour toutes les opérations effectuées par tdx-util, une base de données de vue d'ensemble différente de celle spécifiée dans inn.conf peut être spécifiée en utilisant l'option -p.

Le nombre d'enregistrements de vue d'ensemble stockés dans la base de données peut être obtenu avec la commande "inndf -n".

OPTIONS

-a article
Le numéro ou les numéros d'article à traiter. article est une plage NNTP valide, ce qui signifie qu'il peut s'agir d'un seul numéro d'article ou d'une plage de numéros d'articles (comme "1-5"). Le début ou la fin (ou les deux) de la plage peuvent être omis, auquel cas ils seront définis sur le premier ou le dernier numéro d'article du groupe. Passer "-" pour article est donc équivalent à ne pas utiliser l'option -a du tout.

Uniquement utile en combinaison avec les options -o et -O pour décharger les informations de vue d'ensemble ou avec -c pour spécifier les numéros d'articles bas et hauts lors de la création d'un groupe.

-A
Auditer l'ensemble de la base de données de vue d'ensemble pour détecter les problèmes. Ceci exécute les vérifications de cohérence internes intégrées à l'implémentation de la vue d'ensemble tradindexed, vérifiant des éléments tels que la validité et l'accessibilité de toutes les entrées d'index de groupe, le format des entrées de vue d'ensemble individuelles, la correspondance des entrées d'index avec les données de vue d'ensemble, et des éléments similaires. Aucune modification ne sera apportée à la base de données, mais les problèmes seront signalés sur la sortie d'erreur standard.
-c
Créer un nouveau groupe dans la base de données de vue d'ensemble. Le groupe doit être spécifié avec -n. Le statut du groupe de nouvelles par défaut est "y" mais peut être défini avec -f. Les numéros d'articles bas et hauts sont par défaut 1 et 0 respectivement, mais peuvent être définis avec -a. Si un seul numéro est donné à -a, il est considéré comme le numéro d'article haut.
-F
Auditer l'ensemble de la base de données de vue d'ensemble pour détecter les problèmes, en les corrigeant lorsque cela est possible. Ceci exécute les vérifications de cohérence internes intégrées à l'implémentation de la vue d'ensemble tradindexed, vérifiant des éléments tels que la validité et l'accessibilité de toutes les entrées d'index de groupe, le format des entrées de vue d'ensemble individuelles, la correspondance des entrées d'index avec les données de vue d'ensemble, et des éléments similaires. La stratégie utilisée lors de la correction des problèmes consiste à supprimer les données irrécupérables, donc méfiez-vous que l'utilisation de cette option peut entraîner des articles inaccessibles si leurs données de vue d'ensemble ont été corrompues.

Pour voir ce qui serait modifié par -F, exécutez tdx-util d'abord avec -A.

-f statut
Lors de la création d'un groupe de nouvelles avec -c, définir le statut du groupe nouvellement créé sur statut au lieu de "y". Utile uniquement avec -c.
-g
Décharger l'index d'un groupe particulier. Les champs sont, dans l'ordre, le numéro d'article, le décalage des données pour cet article dans le fichier de données de vue d'ensemble pour ce groupe, la longueur de la vue d'ensemble, l'heure (en secondes depuis l'époque) d'arrivée de l'article sur le serveur, l'heure (en secondes depuis l'époque) d'expiration de l'article basée sur son champ d'en-tête Expires (ou 0 s'il n'y a pas de champ d'en-tête Expires), et le jeton de l'API de stockage de l'article.

Si cette option est donnée, l'option -n doit également être donnée pour spécifier le groupe de nouvelles sur lequel agir.

-i
Décharger l'index maître de la base de données de vue d'ensemble. Ceci contient des informations similaires au fichier active du serveur, telles que les marques haute et basse et le statut de modération, et c'est l'information que nnrpd distribue aux clients.

Les champs sont, dans l'ordre, le nom du groupe de nouvelles, la marque haute, la marque basse, le numéro d'article de base (le point à partir duquel l'index du groupe commence), le nombre d'articles dans le groupe, le statut du groupe, l'heure (en secondes depuis l'époque) à laquelle ce groupe de nouvelles a été supprimé ou 0 s'il ne l'a pas été, et l'inode du fichier d'index pour ce groupe.

Un groupe de nouvelles particulier peut être spécifié avec l'option -n. Si -n n'est pas donnée, l'index maître entier sera déchargé.

-n groupe_de_nouvelles
Spécifier le groupe de nouvelles sur lequel agir, requis pour les options -c, -g, -o, -O et -R, et optionnel pour l'option -i.
-o
Décharger les informations de vue d'ensemble pour un groupe de nouvelles, dans le même format qu'il serait renvoyé aux clients mais avec une modification. Quatre informations supplémentaires seront ajoutées à la fin de chaque entrée : le numéro d'article selon le fichier d'index pour ce groupe libellé avec "Article:", le jeton de l'API de stockage pour cet article libellé avec "Token:", la date d'arrivée de cet article sur le serveur au format de date RFC 5322 libellée avec "Arrived:", et la date d'expiration de cet article (provenant du champ d'en-tête Expires) au format de date RFC 5322 s'il y en a une, libellée avec "Expires:".

Si cette option est donnée, l'option -n doit également être donnée pour spécifier le groupe de nouvelles sur lequel agir. Par défaut, toutes les informations de vue d'ensemble pour ce groupe de nouvelles sont déchargées, mais l'option -a peut être donnée pour limiter le déchargement aux informations d'un seul article ou d'une plage d'a

-O
Décharger les informations de vue d'ensemble pour un groupe de nouvelles, dans le même format qu'il serait renvoyé aux clients mais avec une modification. Appliqué à la fin de chaque entrée seront quatre données supplémentaires : le numéro d'article tel qu'il est indiqué dans le fichier d'index pour ce groupe, précédé de "Article:" ; le jeton de l'API de stockage de cet article, précédé de "Token:" ; la date d'arrivée de cet article sur le serveur au format de date RFC 5322, précédée de "Arrived:" ; et la date d'expiration de cet article (provenant du champ d'en-tête Expires) au format de date RFC 5322 s'il y en a une, précédée de "Expires:".

Si cette option est donnée, l'option -n doit également être donnée pour spécifier le groupe de nouvelles sur lequel agir. Par défaut, toutes les informations de vue d'ensemble pour ce groupe de nouvelles sont déchargées, mais l'option -a peut être donnée pour restreindre le déchargement aux informations d'un seul article ou d'une plage d'a

-p chemin
Spécifier un chemin alternatif vers le répertoire de base de la base de données de vue d'ensemble tradindexed. Utile si vous avez plusieurs bases de données de vues d'ensemble sur votre système.
-R chemin
Reconstruire la base de données de vue d'ensemble pour un groupe de nouvelles particulier. L'option -R prend le chemin vers un répertoire qui contient tous les articles de ce groupe de nouvelles, un par fichier. Les noms des fichiers doivent être les numéros des articles de ce groupe. (Autrement dit, ce répertoire doit être un répertoire spool traditionnel pour ce groupe.) L'option -n doit également être donnée pour spécifier le groupe de nouvelles sur lequel agir.

EXEMPLES

Pour lister l'index maître de toutes les nouvelles:

tdx-util -i

Pour lister l'index maître du groupe de nouvelles "comp.lang.c":

tdx-util -i -n comp.lang.c

Pour lister l'index du groupe de nouvelles "fj.korea":

tdx-util -g -n fj.korea

Pour décharger le contenu de la vue d'ensemble pour l'article 123 du groupe "alt.sources":

tdx-util -o -n alt.sources -a 123

Pour auditer toute la base de données de vue d'ensemble pour des erreurs:

tdx-util -A

Pour créer le groupe de nouvelles "comp.test", avec un article de 1 à 100:

tdx-util -c -n comp.test -a 1-100

Pour reconstruire la base de données de vue d'ensemble pour le groupe "misc.test" à partir de spool dans "/var/spool/news/misc/test":

tdx-util -R /var/spool/news/misc/test -n misc.test

-O
Dump the overview information for a newsgroup in the format used by overchan as input. Each line will start with the storage API token, the arrival timestamp in seconds since epoch, the expires timestamp in the same format (or 0 if there is no Expires header field), and then the overview data.

If this option is given, the -n option must also be given to specify the newsgroup on which to act. By default, all of the overview information for that newsgroup is dumped, but the -a option may be given to restrict the dump to the information for a single article or a range of article numbers.

-p path
Act on the overview database rooted in path, overriding the overview path specified in inn.conf.
-R path
Rebuild the overview for a given group from the articles stored in path. The articles must be in the form of a traditional spool directory; in other words, each article must be in a separate file and the name of the file must match the article number of the article.

If this option is given, the -n option must also be given to specify the newsgroup on which to act.

EXAMPLES

Dump the master index for the overview database in /news/overview, regardless of the overview path specified in inn.conf:

tdx-util -i -p /news/overview

Dump the group index for example.test:

tdx-util -g -n example.test

Dump the complete overview information for example.test:

tdx-util -o -n example.test

Dump the overview information for articles 45 and higher in example.test:

tdx-util -o -n example.test -a 45-

Create an entry for example.test with mode m and low and high article numbers of 4 and 23, respectively.

tdx-util -c -n example.test -f m -a 4-23

Audit the entire overview database for any problems:

tdx-util -A

Rebuild the overview information for example.test from a traditional spool directory:

tdx-util -R <patharticles in inn.conf>/example/test -n example.test

The last command may be useful for recovering from a bad crash or corrupted overview information for a particular group, if you are also using the tradspool article storage method.
