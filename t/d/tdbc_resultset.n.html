tdbc::resultset(n) Connectivité base de données TDBC tdbc::resultset(n)

NOM

tdbc::resultset - Objet jeu de résultats TDBC

SYNTAXE

package require tdbc 1.0
package require tdbc::pilote version
tdbc::pilote::connection create db ?-option valeur...?
set stmt [db prepare code-sql]
set resultset [$stmt execute ?args...?]
$resultset columns
$resultset rowcount
$resultset nextrow ?-as lists|dicts? ?--? nom-variable
$resultset nextlist nom-variable
$resultset nextdict nom-variable
$resultset nextresults

$resultset allrows ?-as lists|dicts? ?-columnsvariable nom? ?--?
$resultset foreach ?-as lists|dicts? ?-columnsvariable nom? ?--? nom-variable script
$resultset close

DESCRIPTION

Chaque pilote de base de données pour TDBC (Tcl DataBase Connectivity) implémente un objet jeu de résultats qui représente les résultats renvoyés par l'exécution d'une instruction SQL dans une base de données. Les instances de cet objet sont créées en exécutant la commande objet execute sur un objet instruction.

La commande objet columns renvoie une liste des noms des colonnes du jeu de résultats. Les colonnes apparaîtront dans le même ordre qu'elles apparaissaient dans l'instruction SQL qui a effectué la requête de base de données. Si l'instruction SQL ne renvoie pas un ensemble de colonnes (par exemple, s'il s'agit d'une instruction INSERT, UPDATE ou DELETE), la commande columns renverra une liste vide.

La commande objet rowcount renvoie le nombre de lignes dans la base de données qui ont été affectées par l'exécution d'une instruction INSERT, UPDATE ou DELETE. Pour une instruction SELECT, le nombre de lignes n'est pas spécifié.

La commande objet nextlist attribue à la variable spécifiée par nom-variable dans la portée de l'appelant la ligne suivante des résultats, exprimée sous forme de liste de valeurs de colonnes. Les valeurs NULL sont remplacées par des chaînes vides. Les colonnes de la ligne de résultat apparaissent dans le même ordre qu'elles apparaissaient dans l'instruction SELECT. Le retour de nextlist est **1** si l'opération a réussi, et **0** si la fin du jeu de résultats a été atteinte.

La commande objet nextdict attribue à la variable spécifiée par nom-variable dans la portée de l'appelant la ligne suivante des résultats, exprimée sous forme de dictionnaire. Les clés du dictionnaire sont les noms de colonnes, et les valeurs sont les valeurs de ces colonnes dans la ligne. Si la valeur d'une colonne dans la ligne est NULL, sa clé est omise du dictionnaire. Les clés apparaissent dans le dictionnaire dans le même ordre qu'elles apparaissaient dans l'instruction SELECT. Le retour de nextdict est **1** si l'opération a réussi, et **0** si la fin du jeu de résultats a été atteinte.

La commande objet nextrow est précisément équivalente à la commande objet nextdict ou nextlist, selon que -as dicts (la valeur par défaut) ou -as lists est spécifié.

Certaines bases de données prennent en charge l'idée d'une seule instruction qui renvoie plusieurs ensembles de résultats. La commande objet nextresults est exécutée, généralement après que la commande nextlist ou nextdict a renvoyé **0**, pour passer au jeu de résultats suivant. Elle renvoie **1** s'il y a un autre jeu de résultats à traiter, et **0** si le jeu de résultats qui vient d'être traité était le dernier. Après avoir appelé nextresults et obtenu la valeur de retour de **1**, l'appelant peut à nouveau appeler columns pour obtenir les descriptions des colonnes du jeu de résultats suivant, puis revenir à l'appel de nextdict ou nextlist pour traiter les lignes du jeu de résultats suivant. Il est erroné d'appeler columns, nextdict, nextlist ou nextrow après que nextresults ait renvoyé **0**.

La commande objet allrows attribue à la variable désignée par l'option -columnsvariable (si elle est présente) le résultat de la commande objet columns. Elle exécute ensuite la commande objet nextrow de manière répétée jusqu'à ce que la fin du jeu de résultats soit atteinte. Si nextresults renvoie une valeur non nulle, elle exécute les deux étapes ci-dessus (columns suivi d'appels itératifs à nextrow) tant que d'autres résultats sont disponibles. Les lignes renvoyées par nextrow sont assemblées dans une liste Tcl et deviennent la valeur de retour de la commande allrows ; la dernière valeur renvoyée par columns est ce que l'application verra dans -columnsvariable.

La commande objet foreach attribue à la variable désignée par l'option -columnsvariable (si elle est présente) le résultat de la commande objet columns. Elle exécute ensuite la commande objet nextrow de manière répétée jusqu'à ce que la fin du jeu de résultats soit atteinte, stockant les lignes successives dans la variable désignée par nom-variable. Pour chaque ligne, elle exécute le script donné. Si le script se termine par une erreur, l'erreur est signalée par la commande foreach, et l'itération s'arrête. Si le script effectue une opération break, l'itération se termine prématurément. Si le script effectue une opération continue, l'itération reprend avec la ligne suivante. Si le script effectue un return, les résultats sont les mêmes que si un script hors du contrôle de foreach avait renvoyé. Tout autre code de retour inhabituel termine l'itération et est signalé par le foreach.

Une fois que nextrow renvoie **0**, la commande objet foreach tente de passer au jeu de résultats suivant en utilisant nextresults. Si nextresults renvoie **1**, les étapes ci-dessus (columns et nextrow, avec invocation de script) sont répétées tant qu'il reste des jeux de résultats. Le script verra toujours la description correcte des colonnes du jeu de résultats actuel dans la variable désignée par -columnsvariable. À la fin de l'appel, la variable désignée par -columnsvariable contiendra la description des colonnes du dernier jeu de résultats.

La commande objet close supprime le jeu de résultats et libère toutes les ressources système associées.
