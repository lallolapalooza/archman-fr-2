tdbc::odbc(n) Connectivité Base de Données Tcl tdbc::odbc(n)

NOM

tdbc::odbc - Pont TDBC-ODBC

SYNOPSIS

package require tdbc::odbc 1.0

tdbc::odbc::connection create db chaîneConnexion ?-option valeur...?
tdbc::odbc::connection new chaîneConnexion ?-option valeur...?

tdbc::odbc::datasources ?-system|-user?

tdbc::odbc::drivers

tdbc::odbc::datasource commande nomPilote ?motClé-valeur?...

DESCRIPTION

Le pilote tdbc::odbc fournit une interface de base de données qui est conforme à Tcl DataBase Connectivity (TDBC) et permet à un script Tcl de se connecter à n'importe quelle base de données SQL présentant une interface ODBC. Il est également fourni comme exemple de travail sur la façon d'écrire un pilote de base de données en C, afin que les auteurs de pilotes aient un point de départ pour le développement ultérieur.

La connexion à une base de données ODBC est établie en appelant tdbc::odbc::connection create, en lui passant le nom à utiliser comme handle de connexion, suivi d'une chaîne de connexion ODBC standard. Alternativement, tdbc::odbc::connection new peut être utilisé pour créer une connexion de base de données avec un nom attribué automatiquement. La valeur de retour de tdbc::odbc::connection new est le nom qui a été choisi pour le handle de connexion.

La chaîne de connexion comprendra au moins un mot-clé DRIVER ou DSN, et peut inclure d'autres mots-clés définis par un pilote ODBC particulier. (Si le système ODBC local prend en charge une interface utilisateur graphique, l'option -parent (voir ci-dessous) peut permettre d'appeler tdbc::odbc::connection create avec une chaîne de connexion vide.)

L'effet secondaire de tdbc::odbc::connection create est de créer une nouvelle connexion de base de données. Voir tdbc::connection(n) pour les détails sur la façon d'utiliser la connexion pour manipuler une base de données.

En plus d'une interface TDBC standard, tdbc::odbc prend en charge trois commandes supplémentaires. La première, tdbc::odbc::datasources, renvoie une liste Tcl énumérant les sources de données nommées disponibles pour le programme (pour la connexion avec le mot-clé DSN dans la chaîne de connexion). Le résultat de tdbc::odbc::datasources peut être limité pour ne retourner que les sources de données système ou uniquement les sources de données utilisateur en incluant respectivement les options -system ou -user.

La commande tdbc::odbc::drivers renvoie un dictionnaire dont les clés sont les noms des pilotes disponibles pour le mot-clé DRIVER dans la chaîne de connexion, et dont les valeurs sont des descriptions des pilotes.

La commande tdbc::odbc::datasource permet la configuration de sources de données nommées sur les systèmes qui prennent en charge l'interface de programmation d'application ODBC Installer. Elle accepte une commande, qui spécifie l'opération à effectuer, le nom d'un pilote pour la base de données en question, et un ensemble de paires mot-clé-valeur qui sont interprétées par le pilote donné. La commande doit être l'une des suivantes :

ajouter
Ajoute une source de données utilisateur. Les paires mot-clé-valeur doivent inclure au moins une option DSN nommant la source de données.
ajouter_systeme
Ajoute une source de données système. Les paires mot-clé-valeur doivent inclure au moins une option DSN nommant la source de données.
configurer
Configure une source de données utilisateur. Les paires mot-clé-valeur incluront généralement une option DSN nommant la source de données. Certains pilotes prendront en charge d'autres options, telles que l'option CREATE_DB pour le pilote Microsoft Access sous Windows.
configurer_systeme
Configure une source de données système.
supprimer
Supprime une source de données utilisateur. Les paires mot-clé-valeur doivent inclure une option DSN spécifiant la source de données à supprimer.
supprimer_systeme
Supprime une source de données système. Les paires mot-clé-valeur doivent inclure une option DSN spécifiant la source de données à supprimer.

OPTIONS DE CONNEXION

La commande d'objet tdbc::odbc::connection create prend en charge les options -encoding, -isolation, -readonly et -timeout communes à tous les pilotes TDBC. L'option -encoding ne réussira que si l'encodage demandé est le même que l'encodage système ; tdbc::odbc n'essaie pas de spécifier d'encodages alternatifs à un pilote ODBC. (Certains pilotes acceptent les spécifications d'encodage dans la chaîne de connexion.)

De plus, si Tk est présent dans l'interpréteur demandeur, et que le gestionnaire de pilotes ODBC du système local prend en charge une interface utilisateur graphique, la commande d'objet tdbc::odbc::connection create prend en charge une option -parent, dont la valeur est le nom du chemin d'une fenêtre Tk. Si cette option est spécifiée, et qu'une chaîne de connexion ne spécifie pas toutes les informations nécessaires pour se connecter à une interface, le gestionnaire de pilotes ODBC affichera une boîte de dialogue pour demander toutes les informations supplémentaires requises. L'interpréteur demandeur sera bloqué jusqu'à ce que l'utilisateur ferme la boîte de dialogue, moment auquel la connexion sera établie.

EXEMPLES

Les chaînes de connexion ODBC étant spécifiques au pilote, il est souvent difficile de trouver la documentation nécessaire pour les composer. Les exemples suivants sont connus pour fonctionner sur la plupart des systèmes Windows et fournissent au moins quelques éléments utiles qu'un programme peut faire.

tdbc::odbc::connection create db \
    "DSN={PAYROLL};UID={aladdin};PWD={Sesame}"
Se connecte à une source de données nommée "PAYROLL", fournissant "aladdin" comme nom d'utilisateur et "Sesame" comme mot de passe. Utilise db comme nom de la connexion. 
set connString {DRIVER={Microsoft Access Driver (*.mdb)};}
append connString {FIL={MS Access}\;}
append connString {DBQ=} \
    [file nativename [file normalize $fileName]]
tdbc::odbc::connection create db2 -readonly 1 $connString
Ouvre une connexion à un fichier de base de données Microsoft Access dont le nom est dans $fileName. La base de données est ouverte en mode lecture seule. La connexion résultante est appelée "db2". 
tdbc::odbc::connection create db3 \
    "DRIVER=SQLite3;DATABASE=$fileName"
Ouvre une connexion à une base de données SQLite3 dont le nom est dans "$fileName". 
tdbc::odbc::datasource add \
    {Microsoft Access Driver (*.mdb)} \
    DSN=MyTestDatabase \
    DBQ=[file native [file normalize $fileName]]
Crée une nouvelle source de données utilisateur nommée "MyTestDatabase" liée à un fichier Microsoft Access dont le chemin est dans "$fileName". Aucune connexion n'est établie à la source de données tant que le programme n'appelle pas tdbc::odbc::connection create. 
tdbc::odbc::datasource configure \
    {Microsoft Access Driver (*.mdb)} \
    CREATE_DB=[file native [file normalize $fileName]] \
    General
Crée une nouvelle base de données Microsoft Access vide dans le fichier identifié par "$fileName". Aucune connexion n'est établie à la base de données tant que le programme n'appelle pas tdbc::odbc::connection create.

METHODES DE CONNEXION ADDITIONNELLES

En plus des méthodes habituelles sur l'objet tdbc::connection(n), les connexions à une base de données ODBC prennent en charge une méthode supplémentaire :

$connection
Cette méthode prend le code SQL natif du pilote donné, sqlStatement, et l'évalue sans la préparer. L'instruction n'est pas tokenisée et ne doit pas contenir de substitutions de variables. L'évaluation de sqlStatement produit un ensemble de résultats de zéro ou plusieurs lignes. Le résultat de la commande est une liste de dictionnaires, avec un élément de liste par ligne dans l'ensemble de résultats (dans un format similaire à la liste renvoyée par $connection allrows -as dicts). Cette commande n'est pas recommandée pour tout ce où les méthodes habituelles prepare ou preparecall fonctionnent correctement. Elle est fournie afin que les instructions de langage de gestion de données qui ne sont pas implémentées par l'API de préparation de l'instruction du pilote (telles que CREATE DATABASE ou CREATE PROCEDURE), ou qui contiennent des caractères réservés par le tokeniseur, puissent être exécutées.
