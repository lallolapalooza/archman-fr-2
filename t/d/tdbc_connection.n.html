tdbc::connection(n) Connectivité aux bases de données TDBC tdbc::connection(n)

NOM

tdbc::connection - Objet de connexion TDBC

SYNTAXE

package require tdbc 1.0
package require tdbc::pilote version
tdbc::pilote::connection create db ?-option valeur...?
db configure ?-option valeur...?
db close
db foreignkeys ?-primary tableName? ?-foreign tableName?
db prepare code-sql
db preparecall appel
db primarykeys tableName
db statements
db resultsets
db tables ?motif?
db columns table ?motif?
db begintransaction
db commit
db rollback
db transaction script

db allrows ?-as listes|dicts? ?-columnsvariable nom? ?--? code-sql ?dictionnaire?
db foreach ?-as listes|dicts? ?-columnsvariable nom? ?--? varNom code-sql ?dictionnaire? script

DESCRIPTION

Chaque pilote de base de données pour TDBC (Tcl DataBase Connectivity) implémente un objet connection qui représente une connexion à une base de données. Par convention, cet objet est créé par la commande tdbc::pilote::connection create. Cette commande accepte le nom d'une commande Tcl qui représentera la connexion et un ensemble possible d'options (voir OPTIONS DE CONFIGURATION). Elle établit une connexion à la base de données et renvoie le nom de la commande Tcl nouvellement créée.

La commande objet configure sur une connexion de base de données, si elle est présentée sans arguments, renvoie une liste de mots-clés et de valeurs alternés représentant la configuration actuelle de la connexion. Si elle est présentée avec un seul argument -option, elle renvoie la valeur configurée de l'option donnée. Sinon, elle doit recevoir un nombre pair d'arguments qui sont des options et des valeurs alternées. Les options spécifiées reçoivent les valeurs spécifiées, et rien n'est renvoyé.

La commande objet close sur une connexion de base de données ferme la connexion. Toutes les instructions actives et tous les ensembles de résultats sur la connexion sont fermés. Toute transaction non validée est annulée. La commande objet est supprimée.

La commande objet prepare sur une connexion de base de données prépare une instruction SQL pour exécution. L'argument code-sql doit contenir une seule instruction SQL à exécuter. Des variables liées peuvent être incluses. La valeur de retour est une commande Tcl nouvellement créée qui représente l'instruction. Voir tdbc::statement pour une discussion plus détaillée du SQL accepté par la commande objet prepare et de l'interface acceptée par une instruction.

Sur une connexion de base de données où la base de données sous-jacente et le pilote prennent en charge les procédures stockées, la commande objet preparecall prépare un appel à une procédure stockée pour exécution. La syntaxe de l'appel de procédure stockée est :

?varRésultat =? nomProc(?arg ?, arg...?)

La valeur de retour est une commande Tcl nouvellement créée qui représente l'instruction. Voir tdbc::statement pour l'interface acceptée par une instruction.

La commande objet statements renvoie une liste d'instructions qui ont été créées par les instructions prepare et preparecall sur la connexion donnée et qui n'ont pas encore été fermées.

La commande objet resultsets renvoie une liste d'ensembles de résultats qui ont été obtenus en exécutant des instructions préparées à l'aide de la connexion donnée et qui n'ont pas encore été fermées.

La commande objet tables permet au programme d'interroger la connexion pour connaître les noms des tables qui existent dans la base de données. Le paramètre optionnel motif est un motif pour faire correspondre le nom d'une table. Il peut contenir les caractères génériques SQL '%' et '_' ainsi que des caractères littéraux. L'interrogation est sensible à la casse, sauf si le pilote de base de données sous-jacent ne l'est pas. La commande renvoie une liste de noms de tables.

La commande objet columns permet au programme d'interroger la connexion pour connaître les noms des colonnes qui existent dans une table donnée. Le paramètre optionnel motif est un motif pour faire correspondre le nom d'une colonne. Il peut contenir les caractères génériques SQL '%' et '_' ainsi que des caractères littéraux. La commande renvoie une liste de dictionnaires, où chaque dictionnaire contient des informations sur une colonne. Les clés du dictionnaire sont décrites ci-dessous. Certains pilotes peuvent renvoyer des informations supplémentaires sous forme de clés supplémentaires dans les dictionnaires. Le caractère générique '%' correspond à zéro ou plusieurs caractères, et '_' correspond à un seul caractère.

type
Contient le type de données de la colonne, et sera généralement choisi parmi l'ensemble : bigint, binary, bit, char, date, decimal, double, float, integer, longvarbinary, longvarchar, numeric, real, time, timestamp, smallint, tinyint, varbinary, et varchar. (Si la colonne a un type qui ne peut pas être représenté par l'un des ci-dessus, type contiendra une description du type spécifique au pilote.)
precision
Contient la précision de la colonne en bits, chiffres décimaux, ou la largeur en caractères, selon le type.
scale
Contient l'échelle de la colonne (le nombre de chiffres après la virgule), pour les types qui supportent ce concept.
nullable
Contient 1 si la colonne peut contenir des valeurs NULL, et 0 sinon.

La commande objet primarykeys permet au programme d'interroger la connexion pour connaître les clés primaires appartenant à une table donnée. Le paramètre tableName identifie la table interrogée. Le résultat est une liste de dictionnaires énumérant les clés (dans un format similaire à la liste renvoyée par $connection allrows -as dicts). Les clés du dictionnaire peuvent inclure au moins les suivantes. Les valeurs qui sont NULL ou dénuées de sens dans une base de données donnée sont omises.

tableCatalog
Nom du catalogue dans lequel la table apparaît.
tableSchema
Nom du schéma dans lequel la table apparaît.
tableName
Nom de la table propriétaire de la clé primaire.
constraintCatalog
Nom du catalogue dans lequel la contrainte de clé primaire apparaît. Dans certains systèmes de bases de données, il peut ne pas être le même que le catalogue de la table.
constraintSchema
Nom du schéma dans lequel la contrainte de clé primaire apparaît. Dans certains systèmes de bases de données, il peut ne pas être le même que le schéma de la table.
constraintName
Nom de la contrainte de clé primaire.
columnName
Nom d'une colonne qui fait partie de la clé primaire.
ordinalPosition
Position ordinale de la colonne au sein de la clé primaire.

À ces colonnes peuvent être ajoutées des colonnes supplémentaires spécifiques à un système de base de données particulier.

La commande objet foreignkeys permet au programme d'interroger la connexion pour connaître les relations de clés étrangères qui s'appliquent à une table particulière. Les relations peuvent être limitées aux clés qui apparaissent dans une table particulière (-foreign tableName), aux clés qui font référence à une table particulière (-primary tableName), ou aux deux. Au moins une des options -primary et -foreign doit être spécifiée, bien que certains pilotes énumèrent toutes les clés étrangères du catalogue courant si les deux options sont omises. Le résultat de la commande objet foreignkeys est une liste de dictionnaires, avec un élément de liste par clé (dans un format similaire à la liste renvoyée par $connection allrows -as dicts). Les clés du dictionnaire peuvent inclure au moins les suivantes. Les valeurs qui sont NULL ou dénuées de sens dans une base de données donnée sont omises.

foreignConstraintCatalog
Catalogue dans lequel apparaît la contrainte de clé étrangère.
foreignConstraintSchema
Schéma dans lequel la contrainte de clé étrangère apparaît.
foreignConstraintName
Nom de la contrainte de clé étrangère.
foreignTableName
Nom de la table contenant la clé étrangère.
foreignColumnName
Nom d'une colonne qui fait partie de la clé étrangère.
primaryTableCatalog
Nom du catalogue dans lequel apparaît la table référencée.
primaryTableSchema
Nom du schéma dans lequel apparaît la table référencée.
primaryTableName
Nom de la table référencée.
primaryColumnName
Nom d'une colonne de la table référencée qui fait partie de la clé primaire.
updateRule
La règle appliquée lors de la mise à jour des données dans la table référencée. Les valeurs possibles sont NONE, CASCADE, SET NULL, SET DEFAULT.
deleteRule
La règle appliquée lors de la suppression des données dans la table référencée. Les valeurs possibles sont NONE, CASCADE, SET NULL, SET DEFAULT.
deferrability
Indique si la contrainte de clé étrangère est vérifiée immédiatement ou différée. Les valeurs possibles sont UNDEFINED, IMMEDIATE, DEFERRABLE.

À ces colonnes peuvent être ajoutées des colonnes supplémentaires spécifiques à un système de base de données particulier.

Les commandes begintransaction, commit, et rollback sont utilisées pour gérer les transactions. La commande begintransaction démarre une nouvelle transaction. La commande commit valide la transaction courante. La commande rollback annule la transaction courante. La commande transaction prend un script Tcl et l'exécute dans le cadre d'une transaction. Si le script se termine normalement, la transaction est validée. Si le script lève une exception, la transaction est annulée.

Les commandes allrows et foreach sont des méthodes de commodité pour récupérer et traiter les résultats d'une requête SQL. La commande allrows récupère toutes les lignes d'un ensemble de résultats et les renvoie sous forme de liste de dictionnaires ou de listes. L'option -as spécifie le format des lignes renvoyées. L'option -columnsvariable permet de récupérer les noms des colonnes dans une variable Tcl.

La commande foreach est similaire à allrows, mais elle itère sur chaque ligne de l'ensemble de résultats et exécute un script Tcl pour chaque ligne. La variable spécifiée par varNom contiendra la ligne courante (sous forme de dictionnaire ou de liste selon l'option -as). L'option -columnsvariable fonctionne de la même manière que pour allrows.

Les arguments optionnels dictionnaire pour allrows et foreach sont utilisés pour spécifier les valeurs des paramètres liés dans la requête SQL. Le dictionnaire doit mapper les noms des paramètres aux valeurs à lier.

CONFIGURATION OPTIONS

Les options de configuration suivantes sont disponibles pour les connexions TDBC :

-datasource chemin
Le chemin d'accès au fichier de base de données (par exemple, pour SQLite) ou le nom du service de base de données (par exemple, pour PostgreSQL).
-user nomUtilisateur
Le nom d'utilisateur pour l'authentification auprès de la base de données.
-password motDePasse
Le mot de passe pour l'authentification auprès de la base de données.
-host hote
Le nom d'hôte du serveur de base de données.
-port port
Le numéro de port du serveur de base de données.
-database nomBaseDeDonnees
Le nom de la base de données à laquelle se connecter.
-readonly booléen
Si défini sur 1, la connexion sera ouverte en mode lecture seule.
-trace canal
Si défini, toutes les commandes SQL exécutées sur cette connexion seront écrites sur le canal Tcl spécifié.
-encoding encodage
L'encodage à utiliser pour la communication avec la base de données.

Les options disponibles peuvent varier en fonction du pilote de base de données spécifique utilisé.

EXEMPLE

Pour créer une connexion à une base de données SQLite :

package require tdbc::sqlite
set db [tdbc::sqlite::connection create mydatabase.db \
        -readonly 0 \
        -trace stdout]

Pour exécuter une requête et obtenir toutes les lignes sous forme de dictionnaires :

set results [$db allrows {SELECT name, email FROM users WHERE active = 1}]

Pour itérer sur les résultats :

$db foreach user {SELECT name, email FROM users WHERE active = 1} {
    puts "User: $user(name), Email: $user(email)"
}

Pour exécuter une requête avec des paramètres liés :

set userId 123
set params [list $userId]
set results [$db allrows -as dicts $params {SELECT name FROM users WHERE id = ?}]

Pour gérer les transactions :

$db begintransaction
# Effectuer des opérations de modification
$db commit
# Ou pour annuler :
# $db rollback

DESCRIPTION

The tdbc::connection command returns a new database connection object in the domain of the specified database driver. This object is used to perform database operations.

The initial set of methods defined for database connection objects are as follows:

tables
Returns a list of the names of all tables in the database. The list may be qualified with schema names as appropriate for the database.
columns tableName
Returns a list of the names of all columns in the table named tableName. The list may be qualified with schema names as appropriate for the database.
tableinfo tableName
Returns a list of lists, where each inner list contains information about a column in the table named tableName. The information includes the column name, its data type, whether it is nullable, and other information as returned by the database driver. This command is analogous to the PRAGMA table_info(tableName) command in SQLite.
primarykeys tableName
Returns a list of the names of the columns that make up the primary key of the table named tableName.
foreignkeys ?tableName?
Returns a list of lists, where each inner list describes a foreign key constraint. If tableName is specified, then only foreign keys referring to that table are returned. If tableName is not specified, then all foreign keys in the database are returned. Each inner list contains the following fields:
foreignConstraintCatalog
Catalog name of the foreign key constraint.
foreignConstraintSchema
Schema name of the foreign key constraint.
foreignConstraintName
Name of the foreign key constraint.
primaryConstraintCatalog
Catalog holding the primary key constraint (or unique key constraint) on the column to which the foreign key refers.
primaryConstraintSchema
Schema holding the primary key constraint (or unique key constraint) on the column to which the foreign key refers.
primaryConstraintName
Name of the primary key constraint (or unique key constraint) on the column to which the foreign key refers.
updateAction
Action to take when an UPDATE statement invalidates the constraint. The value will be CASCADE, SET DEFAULT, SET NULL, RESTRICT, or NO ACTION.
deleteAction
Action to take when a DELETE statement invalidates the constraint. The value will be CASCADE, SET DEFAULT, SET NULL, RESTRICT, or NO ACTION.
primaryCatalog
Catalog name in which the primary table (the one to which the foreign key refers) appears.
primarySchema
Schema name in which the primary table (the one to which the foreign key refers) appears.
primaryTable
Table name of the primary table (the one to which the foreign key refers).
primaryColumn
Name of the column to which the foreign key refers.
foreignCatalog
Name of the catalog in which the table containing the foreign key appears.
foreignSchema
Name of the schema in which the table containing the foreign key appears.
foreignTable
Name of the table containing the foreign key.
foreignColumn
Name of the column appearing in the foreign key.
ordinalPosition
Position of the column in the foreign key, if the key is a compound key.
begintransaction
Begins a new transaction on the database. The transaction is not committed until commit is called, and it is not undone until rollback is called. If the underlying database does not support transactions, this command will return an error. If called when a transaction is already in progress, it will return an error unless the database supports nested transactions.
commit
Commits the most recent transaction started by begintransaction. All changes made during the transaction are made permanent in the database.
rollback
Rolls back the most recent transaction started by begintransaction. All changes made during the transaction are discarded, and the database is returned to the state it was in before the transaction began.
transaction script
This command provides a convenient way to perform a series of operations within a single transaction. It begins a transaction, then evaluates the Tcl script in script in the caller's scope. If the script completes normally (including via return, break, or continue), the transaction is committed. If the script encounters an error or returns an unusual return code, the transaction is rolled back and the error or return code is re-raised. Any changes made to the database during the transaction are lost if the transaction is rolled back.
allrows sql-code ?arg ...?
Prepares and executes the SQL statement given by sql-code. This command binds any parameters specified in sql-code using the key-value pairs given by the optional arg arguments, and then executes the statement. The result set of the statement is then retrieved as a list of lists, where each inner list represents a row in the result set. The statement and result set are closed after the results are retrieved. The return value is the list of results. This is equivalent to calling tdbc::statement to create a statement, calling execute on the statement, calling tdbc::resultset to create a result set object from the results, calling allrows on the result set, and then closing the statement and result set.
foreach sql-code variable script ?arg ...?
Prepares and executes the SQL statement given by sql-code. This command binds any parameters specified in sql-code using the key-value pairs given by the optional arg arguments, and then executes the statement. The result set of the statement is then iterated over, with the variable being set to the current row (as a list) on each iteration, and the script being evaluated. The statement and result set are closed after the iteration is complete, even if the script terminates with a return, an error, or an unusual return code. This is equivalent to calling tdbc::statement to create a statement, calling execute on the statement, calling tdbc::resultset to create a result set object from the results, calling foreach on the result set, and then closing the statement and result set.

The begintransaction object command on a database connection begins a transaction on the database. If the underlying database does not support atomic, consistent, isolated, durable transactions, the begintransaction object command returns an error reporting the fact. Similarly, if multiple begintransaction commands are executed withough an intervening commit or rollback command, an error is returned unless the underlying database supports nested transactions.

The commit object command on a database connection ends the most recent transaction started by begintransaction and commits changes to the database.

The rollback object command on a database connection rolls back the most recent transaction started by begintransaction. The state of the database is as if nothing happened during the transaction.

The transaction object command on a database connection presents a simple way of bundling a database transaction. It begins a transaction, and evaluates the supplied script argument as a Tcl script in the caller's scope. If script terminates normally, or by break, continue, or return, the transaction is committed (and any action requested by break, continue, or return takes place). If the commit fails for any reason, the error in the commit is treated as an error in the script. In the case of an error in script or in the commit, the transaction is rolled back and the error is rethrown. Any nonstandard return code from the script causes the transaction to be rolled back and then is rethrown.

The allrows object command prepares a SQL statement (given by the sql-code parameter) to execute against the database. It then executes it (see tdbc::statement for details) with the optional dictionary parameter giving bind variables. Finally, it uses the allrows object command on the result set (see tdbc::resultset) to construct a list of the results. Finally, both result set and statement are closed. The return value is the list of results.

The foreach object command prepares a SQL statement (given by the sql-code parameter) to execute against the database. It then executes it (see tdbc::statement for details) with the optional dictionary parameter giving bind variables. Finally, it uses the foreach object command on the result set (see tdbc::resultset) to evaluate the given script for each row of the results. Finally, both result set and statement are closed, even if the given script results in a return, an error, or an unusual return code.

CONFIGURATION OPTIONS

The configuration options accepted when the connection is created and on the connection's configure object command include the following, and may include others specific to a database driver.

-encoding name
Specifies the encoding to be used in connecting to the database. The name should be one of the names accepted by the encoding command. This option is usually unnecessary; most database drivers can figure out the encoding in use by themselves.
-isolation level
Specifies the transaction isolation level needed for transactions on the database. The acceptable values for level are shown under TRANSACTION ISOLATION LEVELS.
-timeout ms
Specifies the maximum time to wait for a an operation database engine before reporting an error to the caller. The ms argument gives the maximum time in milliseconds. A value of zero (the default) specifies that the calling process is to wait indefinitely for database operations.
-readonly flag
Specifies that the connection will not modify the database (if the Boolean parameter flag is true), or that it may modify the database (if flag is false). If flag is true, this option may have the effect of raising the transaction isolation level to readonly.

TRANSACTION ISOLATION LEVELS

The acceptable values for the -isolation configuration option are as follows:

readuncommitted
Allows the transaction to read "dirty", that is, uncommitted data. This isolation level may compromise data integrity, does not guarantee that foreign keys or uniqueness constraints are satisfied, and in general does not guarantee data consistency.
readcommitted
Forbids the transaction from reading "dirty" data, but does not guarantee repeatable reads; if a transaction reads a row of a database at a given time, there is no guarantee that the same row will be available at a later time in the same transaction.
repeatableread
Guarantees that any row of the database, once read, will have the same values for the life of a transaction. Still permits "phantom reads" (that is, newly-added rows appearing if a table is queried a second time).
serializable
The most restrictive (and most expensive) level of transaction isolation. Any query to the database, if repeated, will return precisely the same results for the life of the transaction, exactly as if the transaction is the only user of the database.
readonly
Behaves like serializable in that the only results visible to the transaction are those that were committed prior to the start of the transaction, but forbids the transaction from modifying the database.

A database that does not implement one of these isolation levels will instead use the next more restrictive isolation level. If the given level of isolation cannot be obtained, the database interface throws an error reporting the fact. The default isolation level is readcommitted.

A script should not the isolation level when a transaction is in progress.
