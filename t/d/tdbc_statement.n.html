tdbc::statement(n) Connectivité base de données Tcl tdbc::statement(n)

NOM

tdbc::statement - Objet instruction TDBC

SYNOPIS

package require tdbc 1.0
package require tdbc::driver version
tdbc::driver::connection create db ?-option valeur...?
set stmt [db prepare code-sql]
set stmt [db preparecall appel]
$stmt params
$stmt paramtype ?direction? type ?precision? ?scale?
$stmt execute ?dict?
$stmt resultsets

$stmt allrows ?-as listes|dicts? ?-columnsvariable nom? ?--? ?dict
$stmt foreach ?-as listes|dicts? ?-columnsvariable nom? ?--? varName ?dict? script
$stmt close

DESCRIPTION

Chaque pilote de base de données pour TDBC (Tcl DataBase Connectivity) implémente un objet statement qui représente une instruction SQL dans une base de données. Les instances de cet objet sont créées en exécutant la commande objet prepare ou preparecall sur une connexion de base de données.

La commande objet prepare** contre la connexion accepte du code SQL arbitraire à exécuter contre la base de données. Le code SQL peut contenir des variables liées, qui sont des chaînes de caractères alphanumériques ou de traits de soulignement (le premier caractère de la chaîne ne peut pas être un chiffre), précédées de deux-points (:). Si une variable liée apparaît dans l'instruction SQL, et n'est pas dans une chaîne délimitée par des apostrophes ou des guillemets doubles, ni dans un commentaire introduit par --, elle devient une valeur qui est substituée lors de l'exécution de l'instruction. Une variable liée devient une valeur unique (chaîne ou nombre) dans l'instruction résultante. Les pilotes sont responsables de s'assurer que le mécanisme de liaison des variables empêche l'injection SQL.

La commande objet preparecall** contre la connexion accepte une instruction stylisée sous la forme :

nomproc (?:nomvar? ?,:nomvar...?)

ou

nomvar = nomproc (?:nomvar? ?,:nomvar...?)

Cette instruction représente un appel à une procédure stockée nomproc dans la base de données. Le nom de variable à gauche du signe égal (s'il est présent), et tous les noms de variables qui sont des paramètres à l'intérieur des parenthèses, deviennent des variables liées.

La commande objet params** sur un objet statement énumère les variables liées qui apparaissent dans l'instruction. Le résultat retourné par la commande params** est un dictionnaire dont les clés sont les noms des variables liées (listées dans l'ordre où les variables apparaissent pour la première fois dans l'instruction), et dont les valeurs sont des dictionnaires. Les sous-dictionnaires incluent au moins les clés suivantes (les pilotes de base de données peuvent ajouter des clés supplémentaires qui ne sont pas dans cette liste).

direction
Contient l'un des mots-clés, in, out** ou inout selon que la variable est une entrée ou une sortie de l'instruction. Seuls les appels de procédures stockées auront des paramètres out** ou inout.
type
Contient le type de données de la colonne, et sera généralement choisi parmi l'ensemble, bigint, binary, bit, char, date, decimal, double, float, integer, longvarbinary, longvarchar, numeric, real, time, timestamp, smallint, tinyint, varbinary, et varchar. (Si la variable a un type qui ne peut pas être représenté par l'un des éléments ci-dessus, type** contiendra une description du type dépendante du pilote.)
precision
Contient la précision de la colonne en bits, chiffres décimaux, ou la largeur en caractères, selon le type.
scale
Contient la mise à l'échelle de la colonne (le nombre de chiffres après le point décimal), pour les types qui supportent ce concept.
nullable
Contient 1 si la colonne peut contenir des valeurs NULL, et 0 sinon.

La commande objet paramtype** permet au script de spécifier le type et la direction de transmission des paramètres d'une variable dans une instruction. (Certaines bases de données ne fournissent aucun moyen de déterminer cette information automatiquement et chargent l'appelant de le faire.) Les arguments direction, type, precision, scale, et nullable ont la même signification que les valeurs de dictionnaire correspondantes dans la commande objet params.

La commande objet execute** exécute l'instruction. Avant d'exécuter l'instruction, des valeurs sont fournies pour les variables liées qui y apparaissent. Si le paramètre dict est fourni, il est recherché pour une clé dont le nom correspond au nom de la variable liée. Si la clé est présente, sa valeur devient la variable substituée. Sinon, la valeur de la variable liée devient un NULL SQL. Si le paramètre dict n'est pas fourni, la commande objet execute** recherche une variable dans la portée de l'appelant dont le nom correspond au nom de la variable liée. Si une est trouvée, sa valeur devient la valeur de la variable liée. Si aucune n'est trouvée, la variable liée se voit attribuer un NULL SQL comme valeur. Une fois la substitution terminée, l'instruction résultante est exécutée. La valeur de retour est un objet jeu de résultats (voir tdbc::resultset** pour les détails).

La commande objet resultsets** retourne une liste de tous les jeux de résultats qui ont été retournés en exécutant l'instruction et qui n'ont pas encore été fermés.

La commande objet allrows** exécute l'instruction comme avec la commande objet execute**, acceptant un paramètre dict optionnel donnant les variables liées. Après avoir exécuté l'instruction, elle utilise la commande objet allrows** sur le jeu de résultats (voir tdbc::resultset** pour construire une liste des résultats. Finalement, le jeu de résultats est fermé. La valeur de retour est la liste des résultats.

La commande objet foreach** exécute l'instruction comme avec la commande objet execute**, acceptant un paramètre dict optionnel donnant les variables liées. Après avoir exécuté l'instruction, elle utilise la commande objet foreach** sur le jeu de résultats (voir tdbc::resultset** pour évaluer le script donné pour chaque ligne des résultats. Finalement, le jeu de résultats est fermé, même si le script donné résulte en un return**, une erreur, ou un code de retour inhabituel.

La commande objet close** supprime une instruction et tous les jeux de résultats qu'elle a créés. Toutes les ressources système associées aux objets sont libérées.

EXEMPLES

Le code suivant rechercherait un numéro de téléphone dans un répertoire, en supposant un schéma SQL approprié :

package require tdbc::sqlite3
tdbc::sqlite3::connection create db phonebook.sqlite3
set statement [db prepare {
    select phone_num from directory
    where first_name = :firstname and last_name = :lastname
}]
set firstname Fred
set lastname Flintstone
$statement foreach row {
    puts [dict get $row phone_num]
}
$statement close
db close

NOM

tdbc_statement — Create and manipulate prepared statements for the TDBC database interface.

SYNOPSIS

package require tdbc::sqlite
namespace eval my_db {
    tdbc::sqlite3 dbname
    # ...
    set stmt [tdbc::statement create $db command ?arg ...?]
    # ...
    tdbc::statement bind $stmt ?arg ...?
    tdbc::statement execute $stmt ?arg ...?
    tdbc::statement next $stmt
    tdbc::statement columns $stmt
    tdbc::statement final_rows $stmt
    tdbc::statement reset $stmt
    tdbc::statement delete $stmt
}

DESCRIPTION

The tdbc::statement commands provide a mechanism for creating and manipulating prepared statements. Prepared statements can be more efficient than executing SQL directly, especially when the same statement is executed multiple times with different parameters.

tdbc::statement create db command ?arg ...?

Creates a prepared statement for the database connection db. The command is the SQL command to be prepared, and the optional arg arguments are the parameters to the command. These parameters will be substituted with placeholders when the statement is executed.

tdbc::statement bind stmt ?arg ...?

Binds the given arguments to the parameters of the prepared statement stmt. The arguments are substituted for the placeholders in the order they appear.

tdbc::statement execute stmt ?arg ...?

Executes the prepared statement stmt. If arguments are provided, they are bound to the statement's parameters before execution.

tdbc::statement next stmt

Fetches the next row from the result set of the prepared statement stmt. Returns an empty list if there are no more rows.

tdbc::statement columns stmt

Returns a list of column names for the result set of the prepared statement stmt.

tdbc::statement final_rows stmt

Returns the total number of rows affected by the last execution of the prepared statement stmt. This is typically used for INSERT, UPDATE, or DELETE statements.

tdbc::statement reset stmt

Resets the prepared statement stmt, making it ready for reuse with new parameters.

tdbc::statement delete stmt

Deletes the prepared statement stmt, freeing associated resources.

EXEMPLES

package require tdbc::sqlite
namespace eval my_db {
    tdbc::sqlite3 dbname

    # Create a table
    tdbc::db execute $dbname {
        CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT)
    }

    # Prepare an insert statement
    set insert_stmt [tdbc::statement create $dbname {INSERT INTO users (name) VALUES (?)}]

    # Bind and execute the statement
    tdbc::statement bind $insert_stmt "Alice"
    tdbc::statement execute $insert_stmt

    # Execute with different parameters
    tdbc::statement execute $insert_stmt "Bob"

    # Prepare a select statement
    set select_stmt [tdbc::statement create $dbname {SELECT id, name FROM users WHERE name = ?}]

    # Execute and fetch results
    tdbc::statement execute $select_stmt "Alice"
    while {[set row [tdbc::statement next $select_stmt]] ne ""} {
        puts "ID: [lindex $row 0], Name: [lindex $row 1]"
    }

    # Reset and reuse the select statement
    tdbc::statement reset $select_stmt
    tdbc::statement execute $select_stmt "Bob"
    while {[set row [tdbc::statement next $select_stmt]] ne ""} {
        puts "ID: [lindex $row 0], Name: [lindex $row 1]"
    }

    # Get column names
    puts "Columns: [tdbc::statement columns $select_stmt]"

    # Get number of final rows (for DML statements)
    set update_stmt [tdbc::statement create $dbname {UPDATE users SET name = ? WHERE id = ?}]
    tdbc::statement execute $update_stmt "Alicia" 1
    puts "Rows updated: [tdbc::statement final_rows $update_stmt]"

    # Clean up
    tdbc::statement delete $insert_stmt
    tdbc::statement delete $select_stmt
    tdbc::statement delete $update_stmt
    tdbc::close $dbname
}
