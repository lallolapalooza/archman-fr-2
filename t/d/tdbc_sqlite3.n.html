tdbc::sqlite3(n) Connectivité de base de données Tcl tdbc::sqlite3(n)

NOM

tdbc::sqlite3 - Pilote TDBC pour le gestionnaire de base de données SQLite3

SYNTAXE

package require tdbc::sqlite3 1.0

tdbc::sqlite3::connection create db fileName ?-option valeur...?

DESCRIPTION

Le pilote tdbc::sqlite3 fournit une interface de base de données qui est conforme à Tcl DataBase Connectivity (TDBC) et permet à un script Tcl de se connecter à une base de données SQLite3. Il est également fourni comme exemple de travail sur la façon d'écrire un pilote de base de données en Tcl, de sorte que les auteurs de pilotes aient un point de départ pour de futurs développements.

La connexion à une base de données SQLite3 est établie en invoquant tdbc::sqlite3::connection create, en lui passant une chaîne à utiliser comme handle de connexion suivi du nom du fichier de la base de données. L'effet secondaire de tdbc::sqlite3::connection create est de créer une nouvelle connexion de base de données. En alternative, tdbc::sqlite::connection new peut être utilisé pour créer une connexion de base de données avec un nom attribué automatiquement. La valeur de retour de tdbc::sqlite::connection new est le nom qui a été choisi pour le handle de connexion. Voir tdbc::connection(n) pour les détails sur l'utilisation de la connexion pour manipuler une base de données.

OPTIONS DE CONFIGURATION

Les options de configuration standard -encoding, -isolation, -readonly et -timeout sont toutes reconnues, à la fois sur tdbc::sqlite3::connection create et sur la méthode configure de la connexion résultante.

Comme l'encodage d'une base de données SQLite3 est toujours bien connu, l'option -encoding n'accepte que utf-8 comme encodage et retourne toujours utf-8 pour un encodage. L'encodage réel peut être défini à l'aide d'une instruction SQLite3 PRAGMA lors de la création d'une nouvelle base de données.

Seuls les niveaux d'isolation readuncommitted et serializable sont implémentés. Les autres niveaux d'isolation sont promus à serializable.

Le drapeau -readonly n'est pas implémenté. Une valeur booléenne false est acceptée silencieusement, tandis que toute autre valeur signale une erreur.

Le drapeau -keepcase est spécial et contrôle comment les noms de tables et de colonnes sont rapportés dans les différentes méthodes pour récupérer les métadonnées de la base de données. Par défaut, le drapeau est zéro, c'est-à-dire que les noms de tables et de colonnes sont rapportés entièrement en minuscules. Sinon, les noms de tables et de colonnes sont rapportés tels qu'ils sont définis dans la base de données.

BOGUES

Si le nom d'une colonne n'est pas unique parmi les colonnes d'un jeu de résultats, les résultats de -as dicts retournés seront privés de toutes les colonnes dupliquées à l'exception de la plus à droite. Cette limitation peut être contournée en ajoutant des clauses AS appropriées aux instructions SELECT pour garantir que tous les noms de colonnes retournés sont uniques. Il est prévu de corriger ce bogue en utilisant une implémentation C du pilote, ce qui améliorera également considérablement les performances.
