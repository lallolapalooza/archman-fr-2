NOM

toolbox - Outil pour les environnements de ligne de commande interactifs sur Linux

SYNOPSIS

toolbox [--assumeyes | -y]
[--help | -h]
[--log-level LEVEL]
[--log-podman]
[--verbose | -v]
COMMANDE [ARGUMENTS...]

DESCRIPTION

Toolbx est un outil pour Linux, qui permet l'utilisation d'environnements de ligne de commande interactifs pour le développement logiciel et le dépannage du système d'exploitation hôte, sans avoir à installer de logiciel sur l'hôte. Il est construit sur Podman et d'autres technologies de conteneurs standard d'OCI.

Les environnements Toolbx ont un accès transparent au répertoire personnel de l'utilisateur, aux sockets Wayland et X11, au réseau (y compris Avahi), aux périphériques amovibles (comme les clés USB), au journal systemd, à l'agent SSH, à D-Bus, aux limites d'utilisation (ulimits), à /dev et à la base de données udev, etc.

Ceci est particulièrement utile sur les systèmes d'exploitation basés sur OSTree comme Fedora CoreOS et Silverblue. L'intention de ces systèmes est de décourager l'installation de logiciels sur l'hôte, et d'installer plutôt des logiciels dans (ou en tant que) conteneurs — ils n'ont même pas de gestionnaires de paquets comme DNF ou YUM. Cela rend difficile la mise en place d'un environnement de développement ou le dépannage du système d'exploitation de manière habituelle.

Toolbx résout ce problème en fournissant un conteneur entièrement mutable dans lequel on peut installer ses outils de développement et de dépannage préférés, éditeurs et SDK. Par exemple, il est possible de faire yum install ansible sans affecter le système d'exploitation de base.

Cependant, cet outil n'oblige pas à utiliser un système basé sur OSTree. Il fonctionne aussi bien sur Fedora Workstation et Server, et c'est un moyen utile d'adopter progressivement la conteneurisation.

L'environnement Toolbx est basé sur une image OCI. Sur Fedora, il s'agit de l'image fedora-toolbox. Cette image est utilisée pour créer un conteneur Toolbx qui offre l'environnement de ligne de commande interactif.

Notez que Toolbx ne promet aucune sécurité au-delà de ce qui est déjà disponible dans l'environnement de ligne de commande habituel sur l'hôte, familier à tous.

Distributions systèmes d'exploitation supportées

Par défaut, Toolbx essaie d'utiliser une image correspondant à la distribution du système d'exploitation hôte pour créer des conteneurs. Si l'hôte n'est pas supporté, il utilise alors une image Fedora. Les systèmes d'exploitation hôtes supportés sont :

  • Arch Linux
  • Fedora
  • Red Hat Enterprise Linux >= 8.5
  • Ubuntu

Cependant, il est possible de créer des conteneurs pour une distribution différente en utilisant les options --distro et --release acceptées par les commandes pertinentes, ou leurs équivalents dans le fichier de configuration. L'option --distro spécifie le nom de la distribution, et --release spécifie sa version. Les combinaisons supportées sont :

Distribution Version
arch latest ou rolling
fedora <version> ou f<version> par ex., 36 ou f36
rhel <majeur>.<mineur> par ex., 8.5
ubuntu <AA>.<MM> par ex., 22.04

UTILISATION

Créer un conteneur Toolbx :

[utilisateur@hôte ~]$ toolbox create
Image requise pour créer le conteneur toolbox.
Télécharger registry.fedoraproject.org/fedora-toolbox:36 (294.1MB) ? [y/N]: y
Conteneur créé : fedora-toolbox-36
Entrer avec : toolbox enter
[utilisateur@hôte ~]$

Entrer dans le conteneur Toolbx :

[utilisateur@hôte ~]$ toolbox enter
⬢[utilisateur@toolbox ~]$

Supprimer le conteneur Toolbx :

[utilisateur@hôte ~]$ toolbox rm fedora-toolbox-36
[utilisateur@hôte ~]$

OPTIONS GLOBALES

Les options suivantes sont comprises :

--assumeyes, -y

Répondre automatiquement oui à toutes les questions.

--help, -h

Afficher un synopsis de ce manuel et quitter.

--log-level=niveau

Afficher les messages de log supérieurs au niveau spécifié : debug, info, warn, error, fatal ou panic (par défaut : error)

--log-podman

Afficher les messages de log des invocations de Podman en fonction du niveau de log spécifié par l'option log-level.

--verbose, -v

Identique à --log-level=debug. Utiliser -vv pour inclure --log-podman.

COMMANDES

Commandes pour travailler avec les conteneurs et images Toolbx :

toolbox-create(1)

Crée un nouveau conteneur Toolbx.

toolbox-enter(1)

Entre dans un conteneur Toolbx pour une utilisation interactive.

toolbox-help(1)

Affiche les informations d'aide sur Toolbx.

toolbox-init-container(1)

Initialise un conteneur en cours d'exécution.

toolbox-list(1)

Liste les conteneurs et images Toolbx existants.

toolbox-rm(1)

Supprime un ou plusieurs conteneurs Toolbx.

toolbox-rmi(1)

Supprime une ou plusieurs images Toolbx.

toolbox-run(1)

Exécute une commande dans un conteneur Toolbx existant.
