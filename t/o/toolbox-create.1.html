NOM

toolbox-create - Créer un nouveau conteneur Toolbx

SYNOPSIS

toolbox create [--authfile FICHIER]
[--distro DISTRIBUTION | -d DISTRIBUTION]
[--image NOM | -i NOM]
[--release VERSION | -r VERSION]
[CONTENEUR]

DESCRIPTION

Crée un nouveau conteneur Toolbx. Vous pouvez ensuite utiliser la commande toolbox enter pour interagir avec le conteneur à tout moment.

Un conteneur Toolbx est un conteneur OCI créé à partir d'une image OCI. Sur Fedora, l'image par défaut est connue sous le nom de fedora-toolbox:N, où N est la version du système hôte. Si l'image n'est pas présente localement, elle est tirée d'un registre bien connu comme registry.fedoraproject.org. D'autres images peuvent être utilisées sur d'autres systèmes d'exploitation hôtes. Si l'hôte n'est pas reconnu, l'image Fedora sera utilisée.

Le conteneur est créé avec podman create, et son point d'entrée est défini sur toolbox init-container.

Par défaut, un conteneur Toolbx est nommé d'après son image correspondante. Si l'image avait une étiquette (tag), alors l'étiquette est incluse dans le nom du conteneur, mais elle est séparée par un trait d'union, pas par deux-points. Un nom différent peut être attribué en utilisant l'argument CONTENEUR.

Configuration du conteneur

Un conteneur Toolbx s'intègre de manière transparente avec le reste du système d'exploitation en fournissant l'accès au répertoire personnel de l'utilisateur, aux sockets Wayland et X11, au réseau (y compris Avahi), aux périphériques amovibles (comme les clés USB), au journal systemd, à l'agent SSH, à D-Bus, aux ulimits, à /dev et à la base de données udev, etc.

L'identifiant utilisateur et les détails du compte de l'hôte sont propagés dans le conteneur Toolbx, la séparation des étiquettes SELinux est désactivée, et le système de fichiers de l'hôte est accessible par le conteneur à /run/host. Le conteneur a accès aux identifiants Kerberos de l'hôte s'il est configuré pour utiliser les caches KCM.

Un conteneur Toolbx peut être identifié par l'étiquette com.github.containers.toolbox ou par le fichier /run/.toolboxenv.

Le point d'entrée d'un conteneur Toolbx est la commande toolbox init-container qui joue un rôle dans la configuration du conteneur, avec les options passées à podman create.

Point d'entrée

Une caractéristique clé des conteneurs Toolbx est leur point d'entrée, la commande toolbox init-container.

Les conteneurs OCI sont intrinsèquement immuables. Les options de configuration passées via podman create sont intégrées à la définition du conteneur OCI et ne peuvent pas être modifiées ultérieurement. Cela signifie que les modifications et améliorations apportées dans les versions plus récentes de Toolbx ne peuvent pas être appliquées aux conteneurs Toolbx préexistants créés par des versions plus anciennes de Toolbx. Ceci est évité en utilisant le point d'entrée pour configurer le conteneur au moment de l'exécution.

Le point d'entrée d'un conteneur Toolbx personnalise le conteneur pour qu'il corresponde à l'utilisateur actuel en s'assurant qu'il possède un utilisateur qui correspond à celui de l'hôte, et lui accorde l'accès sudo et root.

Les fichiers de configuration cruciaux, tels que /etc/host.conf, /etc/hosts, /etc/localtime, /etc/resolv.conf et /etc/timezone, à l'intérieur du conteneur sont maintenus synchronisés avec l'hôte. Le point d'entrée monte également divers sous-ensembles de la hiérarchie du système de fichiers de l'hôte à leurs emplacements correspondants à l'intérieur du conteneur pour assurer une intégration transparente avec l'hôte. Cela inclut /run/libvirt, /run/systemd/journal, /run/udev/data, /var/lib/libvirt, /var/lib/systemd/coredump, /var/log/journal et autres.

Sur certains systèmes d'exploitation hôtes, des chemins importants comme /home, /media ou /mnt sont des liens symboliques vers d'autres emplacements. Le point d'entrée garantit que les chemins à l'intérieur du conteneur correspondent à ceux de l'hôte, afin d'éviter toute confusion inutile.

OPTIONS

--authfile FICHIER

Chemin d'accès à un FICHIER contenant les identifiants pour s'authentifier auprès du registre pour les images privées. Le FICHIER est généralement défini avec podman login, et sera utilisé par podman pull pour obtenir l'image.

L'emplacement par défaut pour FICHIER est $XDG_RUNTIME_DIR/containers/auth.json et son format est spécifié dans containers-auth.json(5).

--distro DISTRIBUTION, -d DISTRIBUTION

Crée un conteneur Toolbx pour un système d'exploitation DISTRIBUTION différent de celui de l'hôte. Ne peut pas être utilisé avec --image. Doit être associé à --release à moins que la DISTRIBUTION sélectionnée ne corresponde à l'hôte.

--image NOM, -i NOM

Change le NOM de l'image utilisée pour créer le conteneur Toolbx. Ceci est utile pour créer des conteneurs à partir d'images personnalisées. Ne peut pas être utilisé avec --distro et --release.

Si NOM ne contient pas de registre, le stockage d'images local sera consulté, et s'il n'est pas présent, il sera tiré d'un registre distant approprié.

--release VERSION, -r VERSION

Crée un conteneur Toolbx pour une VERSION de système d'exploitation différente de celle de l'hôte. Ne peut pas être utilisé avec --image.

EXEMPLES

Créer le conteneur Toolbx par défaut correspondant à l'OS hôte

$ toolbox create

Créer le conteneur Toolbx par défaut pour Fedora 36

$ toolbox create --distro fedora --release f36

Créer un conteneur Toolbx personnalisé à partir d'une image personnalisée

$ toolbox create --image bar foo

Créer un conteneur Toolbx personnalisé à partir d'une image personnalisée qui est privée

$ toolbox create --authfile ~/auth.json --image registry.example.com/bar
