NOM

torsocks — Bibliothèque pour intercepter les connexions réseau sortantes et les rediriger via le proxy SOCKS de Tor.

DESCRIPTION

La bibliothèque Torsocks surcharge les symboles libc utilisés pour la communication Internet, tels que l'appel système connect(2). Grâce à cette technique, la bibliothèque envoie tout via le réseau Tor, y compris la résolution DNS effectuée par l'application.

Pour le DNS, les fonctions de la famille gethostbyname(3) sont redirigées via Tor. Veuillez noter que l'API ISC res_* n'est actuellement pas prise en charge.

Voici un exemple d'utilisation de la bibliothèque torsocks avec ssh(1) :

$ LD_PRELOAD=/chemin/vers/libtorsocks.so ssh -l kalexander -p 1234 prism.nsa.gov [...]

UTILISATION DU SHELL

Définissez LD_PRELOAD pour charger la bibliothèque, puis utilisez les applications normalement. La syntaxe pour forcer le préchargement de la bibliothèque pour différents shells est spécifiée ci-dessous :

Bash, Ksh et Bourne shell :

$ export LD_PRELOAD=/chemin/vers/libtorsocks.so

C Shell :

$ setenv LD_PRELOAD=/chemin/vers/libtorsocks.so

Ce processus peut être automatisé (pour les utilisateurs de Bash, Bourne et Korn shell) pour une seule commande ou pour toutes les commandes d'une session shell en utilisant le script torsocks(1).

Vous pouvez également configurer torsocks(1) de manière à ce que tous les processus l'utilisent automatiquement, une configuration très utile. Veuillez vous référer à la documentation du script torsocks pour plus d'informations.

VARIABLES D'ENVIRONNEMENT

TORSOCKS_CONF_FILE
Cette variable d'environnement remplace l'emplacement par défaut du fichier de configuration de torsocks. Cette variable n'est pas prise en compte si le programme dans lequel torsocks est intégré est setuid.
TORSOCKS_LOG_LEVEL
Active le niveau de journalisation de la bibliothèque torsocks. Par défaut, les avertissements et les erreurs sont imprimés (niveau 3). Notez que chaque niveau inclut les niveaux inférieurs, sauf le niveau 1 qui désactive toute journalisation possible. (par défaut : 3)
1 Aucune journalisation.
2 Messages d'erreur.
3 Messages d'avertissement.
4 Messages de notification.
5 Messages de débogage.
TORSOCKS_LOG_TIME
Contrôle si l'heure est ajoutée à chaque ligne de journalisation ou non. (par défaut : 1)
TORSOCKS_LOG_FILE_PATH
Si défini, torsocks journalisera dans le fichier défini par cette variable. (par défaut : stderr)
TORSOCKS_USERNAME
Définit le nom d'utilisateur pour la méthode d'authentification SOCKS5. Le mot de passe DOIT également être défini avec la variable ci-dessous.
TORSOCKS_PASSWORD
Définit le mot de passe pour la méthode d'authentification SOCKS5. Le nom d'utilisateur DOIT également être défini avec la variable ci-dessus.
TORSOCKS_TOR_ADDRESS
Définit l'adresse Tor. (par défaut : 127.0.0.1)
TORSOCKS_TOR_PORT
Définit le port Tor. (par défaut : 9050)
TORSOCKS_ALLOW_INBOUND
Autorise les connexions entrantes afin que l'application puisse accepter et écouter les connexions.
TORSOCKS_ISOLATE_PID
Définit le nom d'utilisateur et le mot de passe pour la méthode d'authentification SOCKS5 sur une valeur basée sur le PID/temps actuel automatiquement. Le nom d'utilisateur et le mot de passe NE DOIVENT PAS être définis.

PROBLÈMES CONNUS

DNS

Torsocks n'est pas capable d'envoyer les requêtes DNS via Tor car l'UDP n'est pas pris en charge. Ainsi, tout socket UDP est refusé. Cependant, les requêtes DNS qui peuvent être interceptées sont envoyées à Tor et renvoyées à l'appelant.

ERREURS

Torsocks peut générer des messages d'erreur et les imprimer sur stderr en cas de problèmes avec le fichier de configuration ou la négociation SOCKS avec le démon Tor. La variable d'environnement TORSOCKS_LOG_LEVEL contrôle ce comportement ainsi que l'option de fichier journal. Gardez à l'esprit que cette bibliothèque peut sortir sur le stderr de l'application.

LIMITATIONS

Les connexions TCP sortantes ne peuvent être proxifiées qu'à travers le réseau Tor.

Torsocks force le résolveur libc à utiliser TCP pour les requêtes de noms ; s'il le fait, il le fait indépendamment du fait que le DNS interrogé soit local ou non. Cela introduit une surcharge et ne devrait être utilisé que lorsque nécessaire.

Torsocks utilise les fonctionnalités du chargeur dynamique ELF pour intercepter les appels de fonction dynamiques des programmes dans lesquels il est intégré. Par conséquent, les exécutables non-ELF, ou les exécutables qui effectuent des appels système directement avec le piège d'appel système (int 0x80) ne sont pas pris en charge.

FICHIERS
