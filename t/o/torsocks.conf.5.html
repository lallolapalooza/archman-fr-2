NOM

torsocks.conf — Fichier de configuration pour torsocks(8)

SOMMAIRE

Par défaut, torsocks supposera qu'il doit se connecter au proxy SOCKS de Tor s'exécutant à 127.0.0.1 sur le port 9050. C'est l'adresse et le port par défaut pour le serveur socks de Tor sur la plupart des installations. Si vous exécutez une installation normale de Tor et que vous n'avez pas d'exigences spéciales, vous ne devriez pas avoir besoin de créer, modifier ou invoquer un fichier de configuration lors de l'utilisation de torsocks.

Votre installation de torsocks inclut un fichier de configuration par défaut qui contient des valeurs judicieuses pour une utilisation avec la plupart des installations Tor. L'emplacement d'installation de votre fichier de configuration par défaut est :

/etc/tor/torsocks.conf

Afin d'utiliser un fichier de configuration, vous devez définir la variable d'environnement TORSOCKS_CONF_FILE avec l'emplacement du fichier.

Si TORSOCKS_CONF_FILE n'est pas définie, torsocks tentera de lire le fichier de configuration à l'adresse /etc/tor/torsocks.conf. Si ce fichier ne peut pas être lu, torsocks utilisera des valeurs par défaut judicieuses pour la plupart des installations Tor, c'est-à-dire qu'il supposera que vous souhaitez utiliser un proxy SOCKS s'exécutant à 127.0.0.1 (localhost) sur le port 9050.

CONFIGURATION

SYNTAXE

La structure de base de toutes les lignes du fichier de configuration est :

<directive> <paramètres>

Les lignes vides sont ignorées et toute entrée sur une ligne après un caractère '#' est ignorée.

DIRECTIVES

Les directives suivantes sont utilisées dans le fichier de configuration de torsocks :

TorAddress ip_addr
L'adresse IP du serveur SOCKS de Tor (par exemple, "server = 10.1.4.253"). Un seul serveur peut être spécifié. Actuellement, torsocks ne prend PAS en charge les noms d'hôtes. (par défaut : 127.0.0.1)
TorPort port
Le port sur lequel le serveur SOCKS de Tor reçoit les requêtes. (par défaut : 9050)
OnionAddrRange subnet/mask
Les sites cachés de Tor n'ont pas d'adresses IP réelles. Ceci spécifie quelle plage d'adresses IP sera transmise à l'application comme "cookies" pour les noms .onion. Bien sûr, vous devriez choisir un bloc d'adresses dont vous n'aurez jamais besoin de vous connecter réellement. Ceci est similaire à la fonctionnalité MapAddress du démon Tor principal. (par défaut : 127.42.42.0/24)
SOCKS5Username nom_utilisateur
Nom d'utilisateur à utiliser pour la méthode d'authentification SOCKS5 qui fait que les connexions à Tor utilisent un circuit différent des autres flux existants. S'il est défini, le mot de passe SOCKS5 doit également être spécifié. (Défaut : aucun).
SOCKS5Password mot_de_passe
Mot de passe à utiliser pour la méthode d'authentification SOCKS5 qui fait que les connexions à Tor utilisent un circuit différent des autres flux existants. S'il est défini, le nom d'utilisateur SOCKS5 doit également être spécifié. (Défaut : aucun).
AllowInbound 0|1
Autorise les connexions entrantes, ce qui signifie que listen() et accept()/accept4() seront autorisés pour les adresses autres que localhost afin que l'application puisse gérer les connexions entrantes. Notez que les sockets Unix sont autorisés. (Défaut : 0)
AllowOutboundLocalhost 0|1|2
Autorise les connexions sortantes vers l'interface de bouclage, ce qui signifie que connect() sera autorisé à se connecter aux adresses localhost en contournant Tor. S'il est défini sur 1, les connexions TCP seront autorisées. S'il est défini sur 2, les connexions TCP/IP et UDP seront autorisées. Cette option ne devrait pas être utilisée par la plupart des utilisateurs. (Défaut : 0)
IsolatePID 0|1
Définit Torsocks pour utiliser un nom d'utilisateur/mot de passe SOCKS5 généré automatiquement basé sur l'ID du processus et l'heure actuelle, ce qui fait que les connexions à Tor utilisent un circuit différent des autres flux dans Tor par processus. S'il est défini, les options SOCKS5Username et SOCKS5Password ne doivent pas être définies. (Défaut : 0)

EXEMPLE


$ export TORSOCKS_CONF_FILE=$PWD/torsocks.conf
$ torsocks ssh account@sshserver.com
