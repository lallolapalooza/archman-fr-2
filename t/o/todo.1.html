lister

Lister les tâches (par défaut). Filtre par défaut les tâches terminées ou annulées.

EXEMPLES

Lister toutes les tâches en attente :

$ todo

Lister toutes les tâches en attente de la liste "travail" :

$ todo list travail

Lister toutes les tâches qui sont dues dans les prochaines 24 heures :

$ todo --due 24

Créer une nouvelle tâche avec une date d'échéance et une priorité :

$ todo new "Faire les courses" --due tomorrow --priority high

Marquer la tâche avec l'ID 5 comme terminée :

$ todo done 5

Supprimer la tâche avec l'ID 3 :

$ todo delete 3

Annuler la tâche avec l'ID 7 :

$ todo cancel 7

Modifier la tâche avec l'ID 2 pour y ajouter une catégorie "personnel" :

$ todo edit 2 --category personnel

Rechercher les tâches contenant le mot "rapport" dans la liste "travail" :

$ todo search --grep rapport travail

Afficher les détails de la tâche avec l'ID 1 :

$ todo show 1

Afficher toutes les tâches (y compris terminées et annulées) :

$ todo list --all

Supprimer toutes les tâches terminées :

$ todo flush --yes

DESCRIPTION

Todoman est un gestionnaire de tâches simple, basé sur des standards, en ligne de commande. Les tâches sont stockées dans des fichiers icalendar, ce qui signifie que vous pouvez les synchroniser via CalDAV en utilisant, par exemple, vdirsyncer.

UTILISATION

L'action par défaut est list, qui affiche toutes les tâches de tous les calendriers, chacune avec un identifiant unique semi-permanent :

1 [ ] !!! 2015-04-30 Fermer le compte bancaire @travail (0%)
2 [ ] !              Renvoyer le minipimer sous garantie @maison (0%)
3 [X]     2015-03-29 Acheter du lait de soja @maison (100%)
4 [ ] !!             Réparer l'écran de l'iPad @maison (0%)
5 [ ] !!             Réparer la batterie du Touchpad @travail (0%)

Les colonnes, dans l'ordre, sont :

  • Un identifiant.
  • Indique si la tâche a été terminée ou non.
  • Un !!! indiquant une priorité haute, !! une priorité moyenne, ! une priorité faible.
  • La date d'échéance.
  • Le résumé de la tâche.
  • La liste d'où provient la tâche ; elle sera masquée lors du filtrage par une seule liste, ou si la base de données ne contient qu'une seule liste.
  • Le pourcentage d'achèvement.

L'identifiant est conservé par todoman jusqu'à la prochaine exécution de la commande flush.

Pour opérer sur une tâche, l'identifiant est ce qui est utilisé pour la référencer. Par exemple, pour modifier la tâche Acheter du lait de soja de l'exemple ci-dessus, la commande appropriée est todo edit 3, ou todo undo 3 pour marquer la tâche comme non terminée.

L'édition des tâches ne peut se faire que via l'interface TUI pour l'instant, et ne peut pas encore se faire via la ligne de commande.

INTÉGRATIONS

Lors de tentatives d'intégration de todoman dans d'autres systèmes ou d'analyse de sa sortie, il est conseillé d'utiliser l'indicateur --porcelain, qui affichera toute la sortie dans un format prédéfini qui restera stable quelle que soit la configuration de l'utilisateur ou la version.

Le format est JSON, avec un seul tableau contenant chaque tâche comme une entrée unique (objet). Les champs seront toujours présents ; si une tâche n'a pas de valeur pour un champ donné, elle sera affichée comme null.

Des champs POURRAIENT être ajoutés dans le futur, mais ne seront jamais supprimés.

Conky

Ajouter ${execi 30 todo} dans la section texte affichera la sortie de la commande et la mettra à jour toutes les 30 secondes.

TRI

Les tâches peuvent être triées avec l'argument --sort. Le tri peut être effectué selon les champs suivants :

  • description
  • location
  • status
  • summary
  • uid
  • rrule
  • percent_complete
  • priority
  • sequence
  • categories
  • completed_at
  • created_at
  • dtstamp
  • start
  • due
  • last_modified

Il est possible de préfixer un - à un champ pour trier par ce champ dans l'ordre croissant (par défaut, ils sont triés dans l'ordre décroissant).

Exemple :

todo list --sort due,-priority

CONFIGURATION

Vous devrez configurer Todoman avant la première utilisation, en utilisant son fichier de configuration simple de type ini.

FICHIER DE CONFIGURATION

Le fichier de configuration doit être placé dans $XDG_CONFIG_HOME/todoman/config.py. $XDG_CONFIG_HOME est par défaut ~/.config dans la plupart des situations, donc ce sera généralement ~/.config/todoman/config.py.

CONFIGURATION D'EXEMPLE

L'exemple ci-dessous devrait servir de référence. Il lira les fichiers ics de n'importe quel répertoire dans ~/.local/share/calendars/, utilise le format de date ISO-8601 et définit la date d'échéance des nouvelles tâches à 48 heures.

FUSEAU HORAIRE

Todoman utilisera le fuseau horaire configuré au niveau du système. Si cela ne vous convient pas, vous *pouvez* remplacer le fuseau horaire en spécifiant la variable d'environnement TZ.

Pour des instructions sur la modification du fuseau horaire de votre système, consultez la documentation de votre distribution.

LIMITATIONS

La prise en charge de l'attribut pourcentage-terminé est incomplète. Todoman ne peut marquer les tâches comme terminées (100%), et ne reflétera ni ne permettra la modification des valeurs pour pourcentage > 0 et pourcentage < 100.
