TSORT(1P) Manuel du programmeur POSIX TSORT(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

tsort — tri topologique

SYNTAXE

tsort [fichier]

DESCRIPTION

L'utilitaire tsort écrira sur la sortie standard une liste totalement ordonnée d'éléments cohérente avec un ordre partiel des éléments contenus dans l'entrée.

L'application doit s'assurer que l'entrée consiste en des paires d'éléments (chaînes non vides) séparées par des caractères <espace>. Les paires d'éléments différents indiquent un ordre. Les paires d'éléments identiques indiquent une présence, mais pas un ordre.

OPTIONS

Aucune.

OPÉRANDES

Le opérande suivant sera pris en charge :

fichier
Un nom de chemin d'accès à un fichier texte à trier. Si aucun opérande fichier n'est donné, l'entrée standard sera utilisée.

STDIN

L'entrée standard sera utilisée si aucun opérande fichier n'est spécifié, et sera utilisée si l'opérande fichier est '-' et que l'implémentation traite le '-' comme signifiant l'entrée standard. Sinon, l'entrée standard ne sera pas utilisée. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Le fichier d'entrée sera un fichier texte.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de tsort :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui ne sont pas définies ou sont vides. (Voir la section 8.2, Variables d'internationalisation du volume Définitions de base de POSIX.1‐2017 pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

La sortie standard sera un fichier texte contenant la liste ordonnée produite à partir de l'entrée partiellement ordonnée.

STDERR

La sortie d'erreur standard sera utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION DE L'APPLICATION

La variable LC_COLLATE n'a pas besoin d'affecter les actions de tsort. L'ordre de sortie n'est pas lexicographique, mais dépend des paires d'éléments données en entrée.

EXEMPLES

La commande :

tsort <<EOF
a b c c d e
g g
f g e f
h h
EOF

produit la sortie :

a
b
c
d
e
f
g
h

RATIONALE

Aucune.

DIRECTIONS FUTURES

Aucune.

NOM

tsort — tri topologique d'un fichier

SYNOPIS

tsort [FICHIER]...

DESCRIPTION

Ce manuel est une page de manuel pour Debian. Elle a été traduite par Chris Boot et mise à jour par Jochen Friedrich.

tsort implémente un algorithme de tri topologique. Il lit des paires de chaînes de caractères depuis un fichier d'entrée, les interprète comme des dépendances (la première chaîne dépend de la seconde), et imprime les chaînes triées de façon à ce que les dépendances soient respectées. Les chaînes en double sont ignorées.

Par exemple, si vous avez un fichier a.txt contenant :


1 2
2 3
3 4

tsort produira :


4
3
2
1

Ceci signifie que 1 dépend de 2, 2 de 3, et 3 de 4. Pour que 1 puisse être traité, il faut que 2 soit traité en premier, puis 3, puis 4. En inversant l'ordre, on obtient 4, 3, 2, 1, ce qui respecte toutes les dépendances.

Si plusieurs dépendances existent pour une même chaîne, celles-ci sont traitées comme étant équivalentes.

Si FICHIER est omis ou s'il est « - », l'entrée standard sera utilisée.

OPTIONS

Aucune option n'est prise en charge.

OPÉRANDES

FICHIER : Un fichier contenant les dépendances.

ENTRÉE STANDARD

L'entrée standard est utilisée si aucun FICHIER n'est spécifié ou s'il est « - ». Les lignes doivent être au format <élément1> <élément2>, où <élément1> dépend de <élément2>.

FICHIERS D'ENTRÉE

Les fichiers spécifiés comme opérandes. S'il y a plusieurs fichiers, leur contenu est concaténé avant le traitement.

VARIABLES D'ENVIRONNEMENT

LC_ALL, LC_CTYPE, LC_MESSAGES, NLSPATH et TZ sont utilisées pour l'internationalisation.

ÉVÉNEMENTS ASYNCHRONES

Aucun événement asynchrone spécifique n'est géré.

SORTIE STANDARD

La sortie standard contient les éléments triés de manière topologique, un par ligne.

ERREUR STANDARD

L'erreur standard est utilisée pour les messages d'erreur.

FICHIERS DE SORTIE

Aucun fichier de sortie spécifique n'est généré.

DESCRIPTION ÉTENDUE

Le programme tsort effectue un tri topologique. Il lit des paires de chaînes depuis le fichier d'entrée. Chaque ligne doit contenir deux chaînes séparées par des espaces blancs. Ces chaînes représentent une relation de dépendance, où la première chaîne dépend de la seconde. Par exemple, la ligne A B signifie que A dépend de B, c'est-à-dire que B doit être traité avant A. Le programme garantit que toutes les dépendances sont satisfaites dans la sortie imprimée sur la sortie standard.

Si le fichier d'entrée contient des cycles de dépendances (par exemple, A dépend de B et B dépend de A), tsort signalera une erreur.

Les chaînes en double dans les dépendances sont ignorées. Les éléments qui n'ont pas de dépendances sont traités comme des éléments dont les dépendances sont déjà satisfaites.

STATUT DE SORTIE

0 : Succès.

1 : Une erreur s'est produite (par exemple, cycle de dépendance).

CONSÉQUENCES DES ERREURS

En cas d'erreur (par exemple, un cycle de dépendance), un message d'erreur est affiché sur la sortie d'erreur standard et le programme se termine avec un code de sortie non nul.

UTILISATION DE L'APPLICATION

tsort est généralement utilisé pour déterminer l'ordre d'exécution de tâches ou de compilation de modules qui ont des dépendances entre eux. Par exemple, dans un système de construction, si le module A nécessite le module B pour être construit, vous auriez une ligne A B dans votre fichier de dépendances. tsort vous donnerait l'ordre correct dans lequel construire les modules.

EXEMPLES

Soit un fichier dependances.txt contenant :


installer_programme_a.exe installer_programme_b.exe
installer_programme_b.exe bibliotheque_c.dll
bibliotheque_c.dll systeme_base.dll

L'exécution de tsort dependances.txt produira :


systeme_base.dll
bibliotheque_c.dll
installer_programme_b.exe
installer_programme_a.exe

RATIONNEL

tsort fournit une manière standardisée de gérer les relations de dépendance dans les ensembles de données, ce qui est crucial pour de nombreuses applications logicielles et de gestion de configuration.

DIRECTIONS FUTURES

Peut-être l'ajout d'options pour gérer différemment les cycles ou pour spécifier des séparateurs personnalisés.
