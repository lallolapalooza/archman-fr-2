tss2_createseal(1) Manuel des commandes générales tss2_createseal(1)

NOM

tss2_createseal(1) -

SYNOPSIS

tss2_createseal [OPTIONS]

VOIR AUSSI

fapi-config(5) pour ajuster les paramètres Fapi tels que le profil cryptographique utilisé et le TCTI ou les répertoires pour les stockages de métadonnées Fapi.

fapi-profile(5) pour déterminer les algorithmes cryptographiques et les paramètres pour toutes les clés et opérations d'une interaction TPM spécifique comme l'algorithme de hachage de nom, l'algorithme de signature asymétrique, le schéma et les paramètres, et la sélection de la banque PCR.

DESCRIPTION

tss2_createseal(1) - Cette commande crée un objet scellé et le stocke dans le magasin de métadonnées Fapi. Si aucune donnée n'est fournie (c'est-à-dire un pointeur NULL) alors le TPM génère des données aléatoires et remplit l'objet scellé. Les schémas de signature du TPM sont utilisés comme spécifié dans le profil cryptographique (cf., fapi-profile(5)).

OPTIONS

Voici les options disponibles :

•
-p, --path=CHAÎNE:

Le chemin vers la nouvelle clé.

•
-t, --type=CHAÎNE:

Identifie l'utilisation prévue. Paramètre optionnel. Les types peuvent être une combinaison séparée par des virgules de :

- "exportable": Efface les attributs fixedTPM et fixedParent d'une clé ou
  d'un objet scellé.
- "noda": Définit l'attribut noda d'une clé ou d'un index NV.
- "system": Stocke les blobs de données et les métadonnées d'une clé
  créée ou d'un sceau dans le répertoire système au lieu du répertoire
  personnel de l'utilisateur.
- Un nombre hexadécimal (par exemple, "0x81000001"): Marque un objet
  clé comme devant être rendu persistant et définit le handle de l'objet
  persistant à cette valeur.
•
-P, --policyPath=CHAÎNE:

Identifie la politique à associer à la nouvelle clé. Paramètre optionnel. Si omis, aucune politique ne sera associée à la clé.

Un policyPath est composé de deux éléments, séparés par “/”. Un policyPath commence par “/policy”. Le deuxième élément identifie la politique ou le modèle de politique à l'aide d'un nom significatif.

•
-a, --authValue=CHAÎNE:

Le nouveau mot de passe UTF-8. Paramètre optionnel. S'il est négligé, l'utilisateur est invité interactivement à saisir un mot de passe. Pour ne pas définir de mot de passe, cette option doit être utilisée avec la chaîne vide (““). La taille maximale du mot de passe est déterminée par la taille du digest de l'algorithme de hachage de nom choisi dans le profil cryptographique (cf., fapi-profile(5)). Par exemple, choisir SHA256 comme algorithme de hachage permet des mots de passe d'une taille maximale de 32 caractères.

•
-i, --data=NOMFICHIER ou - (pour stdin):

Les données à sceller par le TPM. Paramètre optionnel. Ne doit pas être utilisé avec --size.

•
-s, --size=ENTIER:

Détermine le nombre d'octets aléatoires que le TPM doit générer et sceller. Paramètre optionnel. Ne doit pas être “0”. Ne doit pas être utilisé avec --data.

OPTIONS COMMUNES

Cette collection d'options est commune à tous les programmes tss2 et fournit des informations que de nombreux utilisateurs peuvent attendre.

•
-h, --help [man|no-man]: Affiche la page man de l'outil. Par défaut, il tente d'appeler le paginator man pour l'outil, cependant, en cas d'échec, il affichera un bref résumé de l'outil. C'est le même comportement si l'argument d'option “man” est spécifié, cependant si “man” est explicitement demandé, l'outil fournira les erreurs de man sur stderr. Si l'option “no-man” est spécifiée, ou si le paginator man échoue, les options courtes seront affichées sur stdout.

Pour utiliser correctement la fonctionnalité de pages man, il faut qu'elles soient installées ou présentes dans MANPATH. Voir man(1) pour plus de détails.

•
-v, --version: Affiche les informations de version de cet outil, les tctis supportés et quitte.

EXEMPLE

Créer une clé avec le mot de passe “abc” et lire les données de scellement depuis un fichier.

tss2_createseal --path=HS/SRK/mySealKey --type="noDa" --authValue=abc --data=data.file

RETOUR

0 en cas de succès ou 1 en cas d'échec.
