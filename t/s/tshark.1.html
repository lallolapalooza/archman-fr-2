NOM

tshark - Capturer et analyser le trafic réseau

SYNTAXE

tshark [ -i <interface de capture>|- ] [ -f <filtre de capture> ] [ -2 ] [ -r <fichier entré> ] [ -w <fichier sorti>|- ] [ options ] [ <filtre> ]

tshark -h|--help

tshark -v|--version

DESCRIPTION

TShark est un analyseur de protocoles réseau. Il vous permet de capturer des données de paquets à partir d'un réseau en direct, ou de lire des paquets à partir d'un fichier de capture précédemment enregistré, soit en affichant une forme décodée de ces paquets sur la sortie standard, soit en écrivant les paquets dans un fichier. Le format de fichier de capture natif de TShark est le format pcapng, qui est également le format utilisé par Wireshark et divers autres outils.

Sans aucune option définie, TShark fonctionnera de manière similaire à tcpdump. Il utilisera la bibliothèque pcap pour capturer le trafic de la première interface réseau disponible et affichera une ligne de résumé sur la sortie standard pour chaque paquet reçu.

Lorsqu'il est exécuté avec l'option -r, spécifiant un fichier de capture à lire, TShark fonctionnera à nouveau de manière similaire à tcpdump, lisant les paquets du fichier et affichant une ligne de résumé sur la sortie standard pour chaque paquet lu. TShark est capable de détecter, lire et écrire les mêmes fichiers de capture que ceux pris en charge par Wireshark. Le fichier d'entrée n'a pas besoin d'une extension de nom de fichier spécifique ; le format du fichier et une compression gzip, Zstandard ou LZ4 optionnelle seront automatiquement détectés. Près du début de la section DESCRIPTION de wireshark(1) ou de https://www.wireshark.org/docs/man-pages/wireshark.html se trouve une description détaillée de la manière dont Wireshark gère cela, ce qui est la même manière dont TShark gère cela.

Le support des fichiers compressés utilise (et nécessite donc) la bibliothèque zlib. Si la bibliothèque zlib n'est pas présente lors de la compilation de TShark, il sera possible de le compiler, mais le programme résultant sera incapable de lire les fichiers compressés. Similairement, LZ4 et ZStandard nécessitent également leurs bibliothèques respectives.

Lors de l'affichage des paquets sur la sortie standard, TShark écrit, par défaut, une ligne de résumé contenant les champs spécifiés par le fichier de préférences (qui sont également les champs affichés dans le volet de liste des paquets dans Wireshark), bien que s'il écrit les paquets au fur et à mesure de leur capture, plutôt que de les lire à partir d'un fichier de capture enregistré, il n'affichera pas le champ "numéro de trame". Si l'option -V est spécifiée, il écrit à la place une vue détaillée du paquet, montrant tous les champs de tous les protocoles dans le paquet. Si l'option -O est spécifiée, il ne montrera que les détails complets pour les protocoles spécifiés, et n'affichera que la ligne de détail de haut niveau pour tous les autres protocoles. Utilisez la sortie de "tshark -G protocols" pour trouver les abréviations des protocoles que vous pouvez spécifier. Si l'option -P est spécifiée avec l'une ou l'autre des options -V ou -O, la ligne de résumé ainsi que les détails seront affichés.

La capture de paquets est effectuée avec la bibliothèque pcap. Cette bibliothèque prend en charge la spécification d'une expression de filtre ; les paquets qui ne correspondent pas à ce filtre sont rejetés. L'option -f est utilisée pour spécifier un filtre de capture. La syntaxe d'un filtre de capture est définie par la bibliothèque pcap ; cette syntaxe est différente de la syntaxe des filtres d'affichage décrite ci-dessous, et le mécanisme de filtrage est limité dans ses capacités.

Les filtres d'affichage dans TShark, qui vous permettent de sélectionner les paquets à décoder ou à écrire dans un fichier, sont très puissants ; plus de champs sont filtrables dans TShark que dans d'autres analyseurs de protocoles, et la syntaxe que vous pouvez utiliser pour créer vos filtres est plus riche. Au fur et à mesure que TShark progresse, attendez-vous à ce que de plus en plus de champs de protocole soient autorisés dans les filtres d'affichage. Les filtres d'affichage utilisent la même syntaxe que les filtres d'affichage et de couleur dans Wireshark ; un filtre d'affichage est spécifié avec l'option -Y.

Les filtres d'affichage peuvent être spécifiés lors de la capture ou lors de la lecture à partir d'un fichier de capture. Notez que les filtres de capture sont beaucoup plus efficaces que les filtres d'affichage, et il peut être plus difficile pour TShark de suivre un réseau chargé si un filtre d'affichage est spécifié pour une capture en direct, vous pourriez donc être plus susceptible de perdre des paquets si vous utilisez un filtre d'affichage.

Un filtre de capture ou d'affichage peut être spécifié avec l'option -f ou -Y, respectivement, auquel cas l'expression de filtre entière doit être spécifiée comme un seul argument (ce qui signifie que si elle contient des espaces, elle doit être mise entre guillemets), ou peut être spécifiée avec des arguments de ligne de commande après les arguments de l'option, auquel cas tous les arguments après les arguments du filtre sont traités comme une expression de filtre. Si le filtre est spécifié avec des arguments de ligne de commande après les arguments de l'option, c'est un filtre de capture si une capture est en cours (c'est-à-dire si aucune option -r n'a été spécifiée) et un filtre d'affichage si un fichier de capture est lu (c'est-à-dire si une option -r a été spécifiée).

Si l'option -w est spécifiée lors de la capture de paquets ou de la lecture à partir d'un fichier de capture, TShark n'affiche pas les paquets sur la sortie standard. Au lieu de cela, il écrit les paquets dans un fichier de capture portant le nom spécifié par l'option -w. Notez que les filtres d'affichage ne sont actuellement pas pris en charge lors de la capture et de la sauvegarde des paquets capturés.

Si vous souhaitez écrire la forme décodée des paquets dans un fichier, exécutez TShark sans l'option -w, et redirigez sa sortie standard vers le fichier (n'utilisez *pas* l'option -w).

Si vous souhaitez que les paquets soient affichés sur la sortie standard et également sauvegardés dans un fichier, spécifiez l'option -P en plus de l'option -w pour afficher la ligne de résumé, spécifiez l'option -V en plus de l'option -w pour afficher les détails du paquet, et spécifiez l'option -O, avec une liste de protocoles, pour afficher les détails complets des protocoles spécifiés et la ligne de détail de haut niveau pour tous les autres protocoles. Si l'option -P est utilisée conjointement avec l'option -V ou -O, la ligne de résumé sera affichée avec les lignes de détail.

Lors de l'écriture de paquets dans un fichier, TShark écrit, par défaut, le fichier au format pcapng, et écrit tous les paquets qu'il voit dans le fichier de sortie. L'option -F peut être utilisée pour spécifier le format dans lequel écrire le fichier. La liste des formats de fichiers disponibles est affichée par l'option -F sans valeur. Cependant, pour une capture en direct, vous ne pouvez spécifier qu'un format de fichier pris en charge par dumpcap(1), à savoir pcapng ou pcap. L'option --compress peut être utilisée pour spécifier également une méthode de compression ; la liste des méthodes de compression prises en charge pour l'écriture peut être affichée par la méthode --compress sans argument. Si l'option --compress n'est pas donnée, alors la méthode de compression désirée, le cas échéant, est déduite de l'extension du nom de fichier donné en argument à l'option -w.

Lors de la capture de paquets, TShark écrit sur la sortie d'erreur une ligne initiale listant les interfaces à partir desquelles les paquets sont capturés et, si les informations sur les paquets ne sont pas affichées sur le terminal, écrit un compte continu des paquets capturés sur la sortie standard. Si l'option -q est spécifiée, ni le compte continu ni les informations sur les paquets ne seront affichés ; au lieu de cela, à la fin de la capture, un compte des paquets capturés sera affiché. Si l'option -Q est spécifiée, ni la ligne initiale, ni les informations sur les paquets, ni aucun compte de paquets ne seront affichés. Si les options -q ou -Q sont utilisées, l'option -P, -V ou -O peut être utilisée pour que la sortie correspondante soit affichée même si d'autres sorties sont supprimées.

Lors de la lecture de paquets, les options -q et -Q supprimeront l'affichage du résumé ou des détails des paquets ; cela serait utilisé si des options -z sont spécifiées afin d'afficher des statistiques, de sorte que seules les statistiques, et non les informations sur les paquets, soient affichées.

L'option -G est un mode spécial qui fait simplement en sorte que TShark vide l'un de plusieurs types de glossaires internes et quitte.

OPTIONS

-2

Effectuer une analyse en deux passes. Cela amène TShark à mettre en mémoire tampon la sortie jusqu'à ce que la première passe entière soit terminée, mais lui permet de remplir les champs qui t

hat nécessitent des connaissances futures, telles que les champs 'réponse dans l'image #'. Permet également de calculer correctement les dépendances d'images de réassemblage. Cela nécessite la capacité de remonter dans l'entrée et, par conséquent, ne peut pas être utilisé avec des captures en direct ou lors de la lecture depuis un tuyau ou un FIFO.

-a|--autostop <condition d'arrêt automatique de capture>

Spécifie un critère qui détermine quand TShark doit cesser d'écrire dans un fichier de capture. Le critère est de la forme test:valeur, où test est l'un des éléments suivants :

duration:valeur Arrête d'écrire dans un fichier de capture après l'écoulement de valeur secondes. Les valeurs flottantes (par exemple 0.5) sont autorisées.

files:valeur Arrête d'écrire dans les fichiers de capture après l'écriture de valeur fichiers.

filesize:valeur Arrête d'écrire dans un fichier de capture après qu'il ait atteint une taille de valeur Ko. Si cette option est utilisée avec l'option -b, TShark arrêtera d'écrire dans le fichier de capture actuel et passera au suivant si la taille de fichier est atteinte. Lors de la lecture d'un fichier de capture, TShark arrêtera de lire le fichier après que le nombre d'octets lus dépasse ce nombre (le paquet complet sera lu, donc plus d'octets que ce nombre peuvent être lus). Notez que la taille de fichier est limitée à une valeur maximale de 2 To, bien que vous puissiez rencontrer des problèmes avant cela si le nombre de paquets dépasse 2^32 (4294967296).

packets:valeur passe au fichier suivant après qu'il contienne valeur paquets. Cela n'inclut pas les paquets qui ne passent pas le filtre d'affichage, donc cela peut différer de -c<nombre de paquets capturés>.

-A <utilisateur>:<mot de passe>

Spécifie un nom d'utilisateur et un mot de passe lorsque TShark capture à partir d'une interface rpcap:// où l'authentification est requise.

Cette option est disponible avec libpcap avec le support distant activé.

-b|--ring-buffer <option de tampon circulaire de capture>

Force TShark à s'exécuter en mode « fichiers multiples ». En mode « fichiers multiples », TShark écrira dans plusieurs fichiers de capture. Lorsque le premier fichier de capture est plein, TShark passera à l'écriture dans le fichier suivant et ainsi de suite.

Les noms de fichiers créés sont basés sur le nom de fichier donné avec l'option -w, le numéro du fichier et la date et l'heure de création, par exemple outfile_00001_20250714120117.pcap, outfile_00002_20250714120523.pcap, ...

Avec l'option files, il est également possible de former un « tampon circulaire ». Celui-ci remplira de nouveaux fichiers jusqu'à ce que le nombre de fichiers spécifié soit atteint, moment auquel TShark abandonnera les données du premier fichier et commencera à écrire dans ce fichier, et ainsi de suite. Si l'option files n'est pas définie, de nouveaux fichiers seront remplis jusqu'à ce qu'une des conditions d'arrêt de capture soit remplie (ou jusqu'à ce que le disque soit plein).

Le critère est de la forme clé:valeur, où clé est l'un des éléments suivants :

duration:valeur passe au fichier suivant après l'écoulement de valeur secondes, même si le fichier actuel n'est pas complètement rempli. Les valeurs flottantes (par exemple 0.5) sont autorisées.

files:valeur recommence avec le premier fichier après l'écriture de valeur fichiers (forme un tampon circulaire). Cette valeur doit être inférieure à 100000. La prudence est de mise lors de l'utilisation d'un grand nombre de fichiers : certains systèmes de fichiers ne gèrent pas bien de nombreux fichiers dans un seul répertoire. Le critère files nécessite que duration, interval ou filesize soit spécifié pour contrôler quand passer au fichier suivant. Il convient de noter que chaque paramètre -b prend exactement un critère ; pour spécifier deux critères, chacun doit être précédé de l'option -b.

filesize:valeur passe au fichier suivant après qu'il ait atteint une taille de valeur Ko. Notez que la taille de fichier est limitée à une valeur maximale de 2 To, bien que vous puissiez rencontrer des problèmes avant cela si le nombre de paquets dépasse 2^32 (4294967296).

interval:valeur passe au fichier suivant lorsque l'heure est un multiple exact de valeur secondes. Par exemple, utilisez 3600 pour passer à un nouveau fichier chaque heure pile.

packets:valeur passe au fichier suivant après qu'il contienne valeur paquets.

printname:nomdefichier imprime le nom du fichier le plus récemment écrit dans nomdefichier après la fermeture du fichier. nomdefichier peut être stdout ou - pour la sortie standard, ou stderr pour la sortie d'erreur standard.

nametimenum:valeur Choisit entre deux modèles de nom de fichier de sauvegarde. Si valeur est 1, le numéro de fichier en cours apparaît avant la partie de l'heure de début ; c'est le comportement original et par défaut (par exemple, log_00001_20250714164426.pcap). Si valeur est supérieure à 1, la partie de l'heure de début apparaît avant la partie du numéro en cours (par exemple, log_20210828164426_00001.pcap). Cette dernière permet un tri alphabétique égal à l'ordre chronologique de création, et maintient les ensembles de fichiers multiples relatifs proches les uns des autres dans le même répertoire.

Exemple : tshark -b filesize:1000 -b files:5 résulte en un tampon circulaire de cinq fichiers d'un mégaoctet chacun.

-B|--buffer-size <taille du tampon de capture>

Définit la taille du tampon de capture (en MiB, par défaut 2 MiB). Ceci est utilisé par le pilote de capture pour mettre en tampon les données de paquets jusqu'à ce que ces données puissent être écrites sur disque. Si vous rencontrez des paquets perdus lors de la capture, essayez d'augmenter cette taille. Notez que, bien que TShark tente de définir la taille du tampon à 2 MiB par défaut, et peut être instruit pour la définir à une valeur plus grande, le système ou l'interface sur laquelle vous capturez peut silencieusement limiter la taille du tampon de capture à une valeur inférieure ou l'augmenter à une valeur supérieure.

Ceci est disponible sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, avec libpcap 1.0.0 ou une version ultérieure, et sur Windows. Il n'est pas disponible sur les systèmes compatibles UNIX avec des versions antérieures de libpcap.

Cette option peut apparaître plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, elle définit la taille du tampon de capture par défaut. Si elle est utilisée après une option -i, elle définit la taille du tampon de capture pour l'interface spécifiée par la dernière option -i survenant avant cette option. Si la taille du tampon de capture n'est pas spécifiquement définie, la taille du tampon de capture par défaut est utilisée à la place.

-c <nombre de paquets à capturer>

Définit le nombre maximum de paquets à lire lors de la capture de données en direct. Lors de la lecture d'un fichier de capture, définit le nombre maximum de paquets à lire. Cela inclut tous les paquets qui ne passent pas le filtre d'affichage, donc cela peut différer de -a packets:<nombre de paquets à capturer>.

-C <profil de configuration>

S'exécute avec le profil de configuration donné.

Si utilisé conjointement avec --global-profile, le profil spécifié sera chargé depuis le répertoire de configuration global au lieu du répertoire de configuration personnel de l'utilisateur. (typiquement sur UN*X '/usr/share/wireshark/profiles', Sur Windows, le répertoire est un sous-répertoire profiles du répertoire dans lequel Wireshark a été installé, par exemple, C:\Program Files\Wireshark\profiles. Sur macOS, lors de l'exécution à partir d'un paquet d'application, il s'agit du sous-répertoire Contents/Resources/share/wireshark/profiles dans le paquet d'application.)

Cette option est utile dans les environnements partagés ou les configurations de test automatisées où des configurations cohérentes sont nécessaires, et où les paramètres spécifiques à l'utilisateur doivent être évités.

-D|--list-interfaces

Imprime une liste des interfaces sur lesquelles TShark peut capturer, et quitte. Pour chaque interface réseau, un numéro et un nom d'interface, éventuellement suivis d'une description textuelle de l'interface, sont imprimés. Le nom de l'interface ou le numéro peuvent être fournis à l'indicateur -i pour spécifier une interface sur laquelle capturer. Le numéro peut être utile sur les systèmes Windows, où les interfaces ont des noms longs qui contiennent généralement un GUID.

-e <champ>

Ajoute un champ à la liste des champs à afficher si -T ek|fields|json|pdml est sélectionné. Cette option peut être utilisée plusieurs fois sur la ligne de commande. Au moins un champ doit être fourni si l'option -T fields est sélectionnée. Les types de colonnes peuvent être utilisés préfixés par « _ws.col. ». Préfixer le nom du champ par un signe arobase (@) affichera les données sous forme d'octets hexadécimaux.

Exemple : tshark -T fields -e frame.number -e ip.addr -e udp -e _ws.col.info

Les champs sont séparés par des tabulations par défaut. -E contrôle le format des champs imprimés. Donner un protocole plutôt qu'un seul champ imprimera le résumé du protocole (étiquette de sous-arbre) des détails du paquet sous forme d'un seul champ. Si le résumé du protocole ne contient que le nom du protocole (par exemple, « Hypertext Transfer Protocol »), alors le nom du filtre du protocole (« http ») sera imprimé.

-E <option d'impression de champ>

Définit une option contrôlant l'impression des champs lorsque -T fields est sélectionné.

Options :

bom=y|n Si y, précède la sortie avec le marqueur d'ordre des octets UTF-8 (hexadécimal ef, bb, bf). Par défaut n.

header=y|n Si y, imprime une liste des noms de champs donnés en utilisant -e comme première ligne de la sortie ; le nom du champ sera séparé en utilisant le même caractère que les valeurs des champs. Par défaut n.

separator=/t|/s|<caractère> Définit le caractère séparateur à utiliser pour les champs. Si /t, une tabulation sera utilisée (c'est le défaut), si /s, un seul espace sera utilisé. Sinon, tout caractère qui peut être accepté par la ligne de commande comme partie de l'option peut être utilisé.

occurrence=f|l|a Sélectionne quelle occurrence utiliser pour les champs qui ont plusieurs occurrences. Si f, la première occurrence sera utilisée, si l, la dernière occurrence sera utilisée et si a toutes les occurrences seront utilisées (c'est le défaut).

aggregator=,|/s|<caractère> Définit le caractère agrégateur à utiliser pour les champs qui ont plusieurs occurrences. Si , une virgule sera utilisée (c'est le défaut), si /s, un seul espace sera utilisé. Sinon, tout caractère qui peut être accepté par la ligne de commande comme partie de l'option peut être utilisé.

quote=d|s|n Définit le caractère de guillemet à utiliser pour entourer les champs. d utilise des guillemets doubles, s des guillemets simples, n pas de guillemets (par défaut). Si le caractère de guillemet apparaît dans une valeur de champ, il sera échappé en étant dupliqué.

escape=y|n Si y, les caractères de contrôle des espaces blancs (tabulation, saut de ligne, retour chariot, saut de page vertical et tabulation verticale) l'effacement arrière, et la barre oblique inverse seront remplacés dans les valeurs de champ par des échappements de style C, par exemple « \n » pour un saut de ligne. Si n, fi la chaîne de caractères de la valeur par défaut sera imprimée telle quelle. La valeur par défaut est y.

-f <filtre de capture>

Définit l'expression du filtre de capture.

Cette option peut être utilisée plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, elle définit l'expression du filtre de capture par défaut. Si elle est utilisée après une option -i, elle définit l'expression du filtre de capture pour l'interface spécifiée par la dernière option -i survenant avant cette option. Si l'expression du filtre de capture n'est pas définie spécifiquement, l'expression du filtre de capture par défaut est utilisée si elle est fournie.

Les noms de filtres de capture prédéfinis, tels qu'affichés dans le menu GUI Capture → Filtres de capture, peuvent être utilisés en préfixant l'argument avec « predef: ». Exemple : tshark -f « predef:MonFiltreHostSeulementPrédéfini »

-F <format de fichier>

Définit le format du fichier de sortie de capture écrit à l'aide de l'option -w. La sortie écrite avec l'option -w sont des données brutes de paquets, pas du texte, il n'y a donc pas d'option -F pour demander une sortie texte. L'option -F sans valeur listera les formats disponibles. Le format par défaut est pcapng (sauf si le format par défaut a été modifié dans les préférences.).

-g

Cette option permet aux fichiers de sortie d'être créés avec les permissions de lecture pour le groupe (ce qui signifie que les fichiers de sortie peuvent être lus par d'autres membres du groupe de l'utilisateur appelant).

-G <type de rapport>

L'option -G amènera TShark à décharger un ou plusieurs types de glossaires, puis à quitter. Le type de glossaire est maintenant obligatoire ; les versions précédentes généraient le rapport fields par défaut lorsqu'aucun type n'était donné. À une exception près, les rapports reflètent la configuration actuelle, y compris celle donnée par une option -C ou modifiée par d'autres options de ligne de commande. L'utilisation du type de rapport help liste tous les types de rapports actuels.

Les types de rapports disponibles incluent :

column-formats Décharge les formats de colonnes compris par TShark. Il y a un enregistrement par ligne. Les champs sont séparés par des tabulations.

Champ 1

chaîne de format (par exemple, « %rD »)

Champ 2

description textuelle de la chaîne de format (par exemple, « Port de destination (résolu) »)

Champ 3

abréviation de champ utilisée pour le texte de la colonne (par exemple, « _ws.col.res_dst_port »)

Ce rapport est suivi d'un exemple d'utilisation qui montre comment modifier les colonnes en surchargeant la valeur de préférence gui.column.format avec -o.

currentprefs Décharge une copie du fichier de préférences actuel sur stdout.

decodes Décharge les associations « type de couche »/« décoder comme » sur stdout. Il y a un enregistrement par ligne. Les champs sont séparés par des tabulations.

Champ 1

type de couche, par exemple « tcp.port »

Champ 2

sélecteur dans la base pour l'affichage

Champ 3

nom « décoder comme », par exemple « http »

defaultprefs Décharge un fichier de préférences par défaut sur stdout. Ce rapport n'est pas affecté par d'autres arguments de ligne de commande.

dissectors Décharge une liste des dissectors enregistrés sur stdout. Il y a un enregistrement par ligne. Les champs sont séparés par des tabulations.

Champ 1

nom du dissector

Champ 2

description du dissector

dissector-tables Décharge une liste des tables de dissectors sur stdout. Il y a un enregistrement par ligne. Les champs sont séparés par des tabulations.

Champ 1

nom de la table de dissectors, par exemple « tcp.port »

Champ 2

nom utilisé pour la table de dissectors dans l'interface graphique

Champ 3

type (représentation textuelle du type ftenum, ou « heuristic »)

Champ 4

base pour l'affichage (pour les types entiers)

Champ 5

nom du protocole

Champ 6

prise en charge de « décoder comme » (pour les tables non heuristiques)

elastic-mapping[,filtre] Décharge le fichier de mapping ElasticSearch sur stdout. Les champs relevant du cas par défaut (chaîne) ne seront pas mappés.

filtre est une liste facultative de noms de filtres de protocole séparés par des virgules qui limite le fichier de mapping généré aux protocoles spécifiés, afin d'éviter un fichier de mapping énorme qui pourrait bloquer certains logiciels (comme Kibana). Par exemple,

tshark -G elastic-mapping,ip,udp,dns

-h|--help

Affiche le numéro de version et les options, puis quitte.

-H <fichier d'hôtes d'entrée>

Lit une liste d'entrées à partir d'un fichier « hosts », qui sera ensuite écrite dans un fichier de capture. Implique -W n. Peut être appelé plusieurs fois.

Le format du fichier « hosts » est documenté sur <https://en.wikipedia.org/wiki/Hosts_(file)>.

-i|--interface <interface de capture> | -

Définit le nom de l'interface réseau ou du tuyau à utiliser pour la capture de paquets en direct.

Les noms d'interfaces réseau doivent correspondre à l'un des noms répertoriés dans « tshark -D » (décrit ci-dessus) ; un numéro, tel que rapporté par « tshark -D », peut également être utilisé.

Si aucune interface n'est spécifiée, TShark recherche dans la liste des interfaces, choisissant la première interface non-boucle si elle existe, et choisissant la première interface boucle si aucune interface non-boucle n'existe. S'il n'y a aucune interface, TShark signale une erreur et ne démarre pas la capture.

Les noms de tuyaux doivent être soit le nom d'un FIFO (tuyau nommé), soit « - » pour lire les données depuis l'entrée standard. Sur les systèmes Windows, les noms de tuyaux doivent être de la forme « \\.\pipe\nomdutuyau ». Les données lues à partir des tuyaux doivent être au format standard pcapng ou pcap. Les données pcapng doivent avoir la même endianité que l'hôte de capture.

« TCP@<hôte>:<port> » fait en sorte que TShark tente de se connecter au port spécifié sur l'hôte spécifié et de lire des données pcapng ou pcap.

Cette option peut être utilisée plusieurs fois. Lors de la capture à partir de plusieurs interfaces, le fichier de capture sera enregistré au format pcapng.

-I|--monitor-mode

Mettre l'interface en « mode moniteur » ; ceci n'est pris en charge que sur les interfaces Wi-Fi IEEE 802.11 et uniquement sur certains systèmes d'exploitation.

Notez qu'en mode moniteur, l'adaptateur peut se désassocier du réseau auquel il est associé, de sorte que vous ne pourrez pas utiliser les réseaux sans fil avec cet adaptateur. Cela pourrait empêcher l'accès aux fichiers sur un serveur réseau, ou la résolution de noms d'hôtes ou d'adresses réseau, si vous capturez en mode moniteur et n'êtes pas connecté à un autre réseau avec un autre adaptateur.

Cette option peut être utilisée plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, elle active le mode moniteur pour toutes les interfaces. Si elle est utilisée après une option -i, elle active le mode moniteur pour l'interface spécifiée par la dernière option -i précédant cette option.

-j <filtre de correspondance de protocole>

Filtre de correspondance de protocole utilisé pour les types de fichiers de sortie ek|json|jsonraw|pdml. Seul le nœud parent du protocole est inclus. Les nœuds enfants ne sont inclus que s'ils sont explicitement spécifiés dans le filtre.

Exemple : tshark -T json -j « ip ip.flags http »

-J <filtre de correspondance de protocole>

Filtre de niveau supérieur de protocole utilisé pour les types de fichiers de sortie ek|json|jsonraw|pdml. Le nœud parent du protocole et tous les nœuds enfants sont inclus. Les protocoles de niveau inférieur doivent être explicitement spécifiés dans le filtre.

Exemple : tshark -T pdml -J « tcp http »

-l

Vide la sortie standard après que les informations pour chaque paquet soient imprimées. (Ce n'est pas, à proprement parler, à buffer par ligne si -V a été spécifié ; cependant, c'est la même chose qu'à buffer par ligne si -V n'a pas été spécifié, car une seule ligne est imprimée pour chaque paquet, et, comme -l est normalement utilisé lors du piping d'une capture en direct vers un programme ou un script, afin que la sortie pour un paquet apparaisse dès que le paquet est vu et décodé, cela devrait fonctionner aussi bien qu'un véritable buffering par ligne. Nous faisons cela comme solution de contournement pour une lacune dans la bibliothèque C de Microsoft Visual C++.) Ceci définit également --update-interval à 0 ms.

Cela peut être utile lors du piping de la sortie de TShark vers un autre programme, car cela signifie que le programme auquel la sortie est dirigée verra les données décodées d'un paquet dès que TShark verra le paquet et générera cette sortie, plutôt que de la voir uniquement lorsque le tampon de sortie standard contenant ces données se remplira.

-L|--list-data-link-types

Liste les types de liaison de données pris en charge par l'interface et quitte. Les types de liaison rapportés peuvent être utilisés pour l'option -y.

-o <préférence>:<valeur>

Définit une valeur de préférence, remplaçant la valeur par défaut et toute valeur lue à partir d'un fichier de préférences. L'argument de l'option est une chaîne de la forme nom_pref:valeur, où nom_pref est le nom de la préférence (qui est le même nom qui apparaîtrait dans le fichier de préférences), et valeur est la valeur à laquelle elle doit être définie.


Note

TShark n'enregistre pas les préférences, utilisez donc cette option pour des changements temporaires pour une seule exécution. Pour définir définitivement une préférence, modifiez-la dans l'interface graphique Wireshark ou modifiez directement le fichier de préférences, en créant plusieurs profils de configuration si vous avez besoin d'ensembles de préférences différents pour différentes occasions.

-O <protocoles>

Similaire à l'option -V, mais fait en sorte que TShark n'affiche qu'une vue détaillée de la liste des protocoles spécifiés séparés par des virgules, et affiche seulement la ligne de détail de niveau supérieur pour tous les autres protocoles, plutôt qu'une vue détaillée de tous les protocoles. Utilisez la sortie de « tshark -G protocoles » pour trouver les abréviations des protocoles que vous pouvez spécifier.

-p|--no-promiscuous-mode

Ne pas mettre l'interface en mode promiscuous. Notez que l'interface peut être en mode promiscuous pour une autre raison ; par conséquent, -p ne peut pas être utilisé pour garantir que le seul trafic capturé est le trafic envoyé vers ou depuis la machine sur laquelle TShark s'exécute, le trafic de diffusion et le trafic multicast vers des adresses reçues par cette machine.

Cette option peut être utilisée plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, aucune interface ne sera mise en mode promiscuous. Si elle est utilisée après une option -i, l'interface spécifiée par la dernière option -i précédant cette option ne sera pas mise en mode promiscuous.

-P|--print

Décode et affiche le résumé ou les détails du paquet, même si vous écrivez des données de paquet brutes à l'aide de l'option -w, et même si la sortie de paquet est autrement supprimée avec -Q.

-q

Lors de la capture de paquets, n'affiche pas le compte continu de paquets capturés qui est normalement affiché lors de l'enregistrement d'une capture dans un fichier ; affiche plutôt, à la fin de la capture, un compte des paquets capturés. Sur les systèmes qui prennent en charge le signal SIGINFO, tels que divers BSD, vous pouvez afficher le compte actuel en tapant votre caractère « status » (typiquement control-T, bien qu'il puisse être réglé sur « désactivé » par défaut sur au moins certains BSD, donc vous devriez explicitement le définir pour l'utiliser).

Lors de la lecture d'un fichier de capture, ou lors de la capture sans enregistrement dans un fichier, n'imprime pas les informations sur les paquets ; c'est utile si vous utilisez une option -z pour calculer des statistiques et que vous ne voulez pas que les informations sur les paquets soient imprimées, seulement les statistiques.

-Q

Lors de la capture de paquets, n'affiche pas, sur la sortie d'erreur standard, le message initial indiquant sur quelles interfaces la capture est effectuée, le compte continu de paquets capturés affiché lors de l'enregistrement d'une capture dans un fichier, et le message final donnant le compte des paquets capturés. Seules les erreurs réelles sont affichées sur la sortie d'erreur standard.

Ceci génère moins de sortie que l'option -q, donc le nom de l'interface et le nombre total de paquets à la fin d'une capture ne sont pas envoyés à stderr.

Lors de la lecture d'un fichier de capture, ou lors de la capture sans enregistrement dans un fichier, n'imprime pas les informations sur les paquets ; c'est utile si vous utilisez une option -z pour calculer des statistiques et que vous ne voulez pas que les informations sur les paquets soient imprimées, seulement les statistiques.

-r|--read-file <fichier d'entrée>

Lit les données de paquets depuis fichier d'entrée, qui peut être n'importe quel format de fichier de capture pris en charge (y compris les fichiers compressés). Il est possible d'utiliser des tuyaux nommés ou l'entrée standard (-) ici mais uniquement avec certains formats de fichiers de capture (en particulier : ceux qui peuvent être lus sans reculer).


Astuce

Lire une capture en direct depuis la sortie standard d'un autre processus via un tuyau peut contourner les restrictions qui s'appliquent à TShark lors de la capture en direct, telles que les formats de fichiers ou la compression.

-R|--read-filter <Filtre de lecture>

Fait en sorte que le filtre spécifié (qui utilise la syntaxe des filtres de lecture/affichage, plutôt que celle des filtres de capture) soit appliqué lors de la première passe d'analyse. Les paquets ne correspondant pas au filtre ne sont pas pris en compte pour les passes futures. N'a de sens qu'avec plusieurs passes, voir -2. Pour le filtrage régulier sur une dissection en passe unique, utilisez plutôt -Y.

Notez que les champs prospectifs tels que « réponse dans l'image n° » ne peuvent pas être utilisés avec ce filtre, car ils n'auront pas été calculés lorsque ce filtre sera appliqué.

-s|--snapshot-length <longueur de capture>

Définit la longueur de capture par défaut à utiliser lors de la capture de données en direct. Pas plus de longueur_capture octets de chaque paquet réseau ne seront lus en mémoire, ou sauvegardés sur disque. Une valeur de 0 spécifie une longueur de capture de 262144, de sorte que le paquet complet soit capturé ; c'est la valeur par défaut.

Cette option peut être utilisée plusieurs fois. Si elle est utilisée avant la première occurrence de l'option -i, elle définit la longueur de capture par défaut. Si elle est utilisée après une option -i, elle définit la longueur de capture pour l'interface spécifiée par la dernière option -i précédant cette option. Si la longueur de capture n'est pas définie spécifiquement, la longueur de capture par défaut est utilisée si elle est fournie.

-S <séparateur>

Définit le séparateur de ligne à imprimer entre les paquets.

-T ek|fields|json|jsonraw|pdml|ps|psml|tabs|text

Définit le format de la sortie lors de l'affichage des données de paquet décodées. Les options sont l'une des suivantes :

ek Format JSON délimité par des nouvelles lignes pour l'importation en masse dans Elasticsearch. Il peut être utilisé avec -j ou -J pour spécifier quels protocoles inclure ou avec -x pour inclure les p encodés en hexadécimal.

acket données. Si -P est spécifié, il n'affichera que le résumé du paquet, et avec à la fois -P et -V, il affichera le résumé et les détails du paquet. Si ni -P ni -V ne sont utilisés, il n'affichera que les détails du paquet. Exemple d'utilisation pour importer des données dans Elasticsearch :

tshark -T ek -j "http tcp ip" -P -V -x -r file.pcap > file.json
curl -H "Content-Type: application/x-ndjson" -XPOST http://elasticsearch:9200/_bulk --data-binary "@file.json"

Elasticsearch nécessite qu'un fichier de mapping soit chargé en tant que modèle pour l'index packets-* afin de convertir les types Wireshark en types Elasticsearch. Ce fichier peut être généré automatiquement avec la commande "tshark -G elastic-mapping". Le fichier de mapping pouvant être très volumineux, les protocoles peuvent être sélectionnés en utilisant l'option --elastic-mapping-filter :

tshark -G elastic-mapping --elastic-mapping-filter ip,udp,dns

ou en ajoutant le filtre directement à l'option -G elastic-mapping :

tshark -G elastic-mapping,ip,udp,dns

fields Les valeurs des champs spécifiés avec l'option -e, dans un format spécifié par l'option -E. Par exemple,

tshark -T fields -E separator=, -E quote=d

générerait une sortie de valeurs séparées par des virgules (CSV) adaptée à l'importation dans votre tableur préféré.

json Format de fichier JSON. Il peut être utilisé avec -j ou -J pour spécifier quels protocoles inclure, ou avec l'option -x pour inclure les données brutes des paquets encodées en hexadécimal. Exemple d'utilisation :

tshark -T json -r file.pcap
tshark -T json -j "http tcp ip" -x -r file.pcap

jsonraw Format de fichier JSON incluant uniquement les données brutes des paquets encodées en hexadécimal. Il peut être utilisé avec -j ou -J pour spécifier quels protocoles inclure. Exemple d'utilisation :

tshark -T jsonraw -r file.pcap
tshark -T jsonraw -j "http tcp ip" -x -r file.pcap

pdml Packet Details Markup Language, un format basé sur XML pour les détails d'un paquet décodé. Ces informations sont équivalentes aux détails du paquet affichés avec l'option -V. L'utilisation de l'option --color ajoutera des attributs de couleur à la sortie pdml. Ces attributs sont non standards.

ps PostScript pour un résumé lisible par l'homme d'une ligne de chaque paquet, ou une vue multi-lignes des détails de chaque paquet, selon que l'option -V a été spécifiée ou non.

psml Packet Summary Markup Language, un format basé sur XML pour les informations de résumé d'un paquet décodé. Ces informations sont équivalentes aux informations affichées dans le résumé d'une ligne par défaut. L'utilisation de l'option --color ajoutera des attributs de couleur à la sortie pdml. Ces attributs sont non standards.

tabs Similaire au rapport text par défaut, sauf que le résumé lisible par l'homme de chaque paquet inclura un caractère de tabulation ASCII horizontal (0x09) comme délimiteur entre chaque colonne.

text Texte d'un résumé lisible par l'homme d'une ligne de chaque paquet, ou une vue multi-lignes des détails de chaque paquet, selon que l'option -V a été spécifiée ou non. C'est le mode par défaut.

--temp-dir <répertoire>

Spécifie le répertoire dans lequel les fichiers temporaires (y compris les fichiers de capture) doivent être écrits. Le comportement par défaut sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, est d'utiliser la variable d'environnement $TMPDIR si elle est définie, et le défaut du système, généralement /tmp, si elle ne l'est pas. Sur Windows, la variable d'environnement %TEMP% est utilisée, ce qui correspond généralement à %USERPROFILE%\AppData\Local\Temp.

-U <nom du tap>

Exportation PDUs, exporte les PDUs du fichier d'entrée vers le fichier de sortie selon le nom du tap donné. Utilisez -Y pour filtrer.

Entrez un nom de tap vide "" ou un nom de tap "?" pour obtenir une liste des noms disponibles.

-v|--version

Affiche les informations complètes de version et quitte.

-V

Demande à TShark d'afficher une vue des détails du paquet.

-w <fichier de sortie> | -

Écrit les données brutes des paquets dans fichier de sortie ou dans la sortie standard si fichier de sortie est '-'. Les options -F et --compress peuvent être utilisées pour contrôler le format du fichier et la méthode de compression. Si cette dernière n'est pas donnée, l'extension peut être utilisée pour déduire l'algorithme de compression souhaité, s'il est supporté, par exemple une archive gzip pour '.gz'.

-w fournit des données brutes de paquets, pas du texte. Si vous voulez une sortie texte
vous devez rediriger stdout (par exemple, en utilisant '>'), n'utilisez pas l'option -w pour cela.

-W <option de format de fichier>

Enregistre des informations supplémentaires dans le fichier si le format le prend en charge. Par exemple,

tshark -F pcapng -W n

enregistrera les enregistrements de résolution de noms d'hôtes avec les paquets capturés.

Les futures versions de TShark pourront modifier automatiquement le format de capture en pcapng si nécessaire.

L'argument est une chaîne qui peut contenir la lettre suivante :

n écrit les informations de résolution d'adresses réseau (pcapng uniquement)

-x

Demande à TShark d'afficher une décomposition hexadécimale et ASCII des données du paquet après avoir affiché le résumé et/ou les détails, si l'un ou l'autre est également affiché.

--hexdump <option hex>

Demande à TShark d'afficher une décomposition hexadécimale et ASCII des données du paquet avec la possibilité de sélectionner les sources de données à décomposer, comment formater ou exclure le texte de décomposition ASCII, et s'il faut afficher l'horodatage du paquet sous forme de préambule.

Cette option (et -x) peut apparaître plusieurs fois sur la ligne de commande, et la décomposition hexadécimale ne sera imprimée qu'une seule fois. En cas d'options conflictuelles, les dernières options fournies seront utilisées. Les valeurs possibles de <option hex> sont :

all

Active la décomposition hexadécimale, génère des blocs de décomposition hexadécimale pour toutes les sources de données associées à chaque paquet. Utilisé pour annuler une utilisation antérieure de --hexdump frames. L'option -x affiche toutes les sources de données par défaut.

frames

Active la décomposition hexadécimale, génère des blocs de décomposition hexadécimale uniquement pour les données du paquet. Utilisez cette option pour exclure de la sortie de décomposition hexadécimale tout bloc de décomposition hexadécimale pour des sources de données secondaires telles que 'Bitstring tvb', 'Reassembled TCP', 'De-chunked entity body', etc.

ascii

Active la décomposition hexadécimale, avec un texte de décomposition ASCII non délimité. Utilisé pour annuler une utilisation antérieure de --hexdump delimit ou --hexdump noascii. L'option -x affiche un texte de décomposition ASCII non délimité par défaut.

delimit

Active la décomposition hexadécimale avec le texte de décomposition ASCII délimité par des caractères '|'. Ceci est utile pour déterminer sans ambiguïté la fin du texte des octets hexadécimaux et le début du texte de décomposition ASCII.

noascii

Active la décomposition hexadécimale sans afficher de texte de décomposition ASCII.

time

Active la décomposition hexadécimale et affiche l'horodatage de chaque paquet en préambule. L'option -t peut être utilisée pour modifier le format de l'horodatage.

notime

Active la décomposition hexadécimale sans afficher l'horodatage de chaque paquet en préambule.

help

Affiche l'aide spécifique à --hexdump puis quitte.

L'utilisation de --hexdump <option hex> est particulièrement utile pour générer une sortie qui peut être utilisée pour créer un fichier pcap ou pcapng à partir d'un type de fichier de capture tel que Microsoft NetMon 2.x, que TShark et Wireshark peuvent lire mais pour lequel il n'est pas possible de faire directement un "Enregistrer sous" ni d'exporter des paquets.

Exemples :

Génère une sortie de décomposition hexadécimale, avec uniquement la source de données du paquet, avec un texte de décomposition ASCII délimité, et avec chaque bloc hexadécimal de paquet précédé d'un horodatage lisible par l'homme dans le fuseau horaire local, directement utilisable par l'utilitaire text2pcap :

tshark ... --hexdump frames --hexdump delimit --hexdump time -t ad \
    | text2pcap -t 'ISO' - MYNEWPCAPNG

Génère une sortie de décomposition hexadécimale, avec uniquement la source de données du paquet, avec le texte de décomposition ASCII par défaut sans délimiteur, et avec chaque bloc hexadécimal de paquet précédé d'un horodatage lisible par l'homme en UTC, directement utilisable par l'utilitaire text2pcap avec l'option -a :

    | text2pcap -a -t 'ISO' - MYNEWPCAPNG

-z io,stat,intervalle[,filtre][,filtre][,filtre]...

Collectez des statistiques sur les paquets/octets pour la capture par intervalles de intervalle secondes. Intervalle peut être spécifié comme une seconde entière ou fractionnaire et peut être spécifié avec une résolution en microsecondes (us). Si intervalle est 0, les statistiques seront calculées sur tous les paquets.

Si un ou plusieurs filtres sont spécifiés, les statistiques seront calculées pour tous les filtres et présentées avec une colonne de statistiques pour chaque filtre.

Cette option peut être utilisée plusieurs fois sur la ligne de commande.

Exemple : -z "io,stat,0.001,smb&&ip.addr==1.2.3.4" générera des statistiques sur 1 ms pour tous les paquets SMB vers/depuis l'hôte 1.2.3.4.

Les exemples ci-dessus utilisent tous la syntaxe standard pour générer des statistiques qui ne calculent que le nombre de paquets et d'octets dans chaque intervalle.

io,stat peut également effectuer beaucoup plus de statistiques et calculer COUNT(), SUM(), MIN(), MAX(), AVG() et LOAD() en utilisant une syntaxe de filtre légèrement différente :

-z io,stat,intervalle,"COUNT|SUM|MIN|MAX|AVG|LOAD(champ)filtre"


Note

Une chose importante à noter ici est que le filtre n'est pas facultatif
et que le champ sur lequel le calcul est basé DOIT faire partie de la chaîne de filtre, sinon le calcul échouera.

Ainsi : -z io,stat,0.010,AVG(smb.time) ne fonctionne pas. Utilisez -z io,stat,0.010,AVG(smb.time)smb.time à la place. Soyez également conscient qu'un champ peut exister plusieurs fois dans le même paquet et sera alors compté plusieurs fois dans ces paquets.


Note

Une deuxième chose importante à noter est que le paramètre système du
séparateur décimal doit être défini sur "." ! S'il est défini sur ",", les statistiques ne seront pas affichées par filtre.

COUNT - Calcule le nombre de fois que le champ nom (pas sa valeur) apparaît par intervalle dans la liste des paquets filtrés. ''champ'' peut être n'importe quel nom de filtre d'affichage.

Exemple : -z io,stat,0.010,"COUNT(smb.sid)smb.sid"

Cela comptera le nombre total de SID vus dans chaque intervalle de 10 ms.

SUM - Contrairement à COUNT, les valeurs du champ spécifié sont additionnées par intervalle de temps. ''champ'' ne peut être qu'un champ nommé entier, flottant, double ou temporel relatif.

Exemple : tshark -z io,stat,0.010,"SUM(frame.len)frame.len"

Indique le nombre total d'octets qui ont été transmis bidirectionnellement dans tous les paquets dans un intervalle de 10 millisecondes.

MIN/MAX/AVG - La valeur minimale, maximale ou moyenne du champ dans chaque intervalle est calculée. Le champ spécifié doit être un champ nommé entier, flottant, double ou temporel relatif. Pour les champs temporels relatifs, la sortie est présentée en secondes avec six chiffres de précision arrondis à la microseconde la plus proche.

-z scsi,srt,cmdset[,filtre]

Collecte des données SRT (délai de réponse du service) d'appel/réponse pour le jeu de commandes SCSI cmdset.

Jeux de commandes : 0:SBC 1:SSC 5:MMC

Les données collectées sont le nombre d'appels pour chaque procédure, MinSRT, MaxSRT et AvgSRT.

Exemple : -z scsi,srt,0 collectera des données pour les COMMANDES DE BLOC SCSI (SBC).

Cette option peut être utilisée plusieurs fois sur la ligne de commande.

Exemple : -z scsi,srt,0,ip.addr==1.2.3.4 collectera des statistiques SRT SCSI SBC pour un hôte iscsi/ifcp/fcip spécifique.

-z sctp,stat

Active un compteur pour les segments SCTP. En plus du nombre total de paquets SCTP, pour chaque combinaison d'adresse et de port source et destination, le nombre de segments des types les plus courants (DATA, SACK, HEARTBEAT, HEARTBEAT ACK, INIT, INIT ACK, COOKIE ECHO, COOKIE ACK, ABORT et ERROR) est affiché.

-z sip,stat[,filtre]

Cette option activera un compteur pour les messages SIP. Vous obtiendrez le nombre d'occurrences de chaque méthode SIP et de chaque code d'état SIP. De plus, vous obtiendrez également le nombre de messages SIP renvoyés (uniquement pour SIP sur UDP).

Exemple : -z sip,stat.

Cette option peut être utilisée plusieurs fois sur la ligne de commande.

Exemple : -z "sip,stat,ip.addr==1.2.3.4" ne collectera que les statistiques pour les paquets SIP échangés par l'hôte à l'adresse IP 1.2.3.4.

-z smb,sids

Lorsque cette fonctionnalité est utilisée, TShark imprimera un rapport avec toutes les associations SID et noms de compte découvertes. Seuls les SID pour lesquels le nom de compte est connu seront présentés dans le tableau.

Pour que cette fonctionnalité fonctionne, vous devrez soit activer "Édition/Préférences/Protocoles/SMB/Snoop SID to name mappings" dans les préférences, soit vous pouvez outrepasser les préférences en spécifiant -o "smb.sid_name_snooping:TRUE" sur la ligne de commande TShark.

La méthode actuelle utilisée par TShark pour trouver le mappage SID→nom est relativement restreinte, dans l'espoir d'une expansion future.

-z smb,srt[,filtre]

Collecte des données SRT (délai de réponse du service) d'appel/réponse pour SMB. Les données collectées sont le nombre d'appels pour chaque commande SMB, MinSRT, MaxSRT et AvgSRT.

Exemple : -z smb,srt

Les données seront présentées sous forme de tableaux séparés pour toutes les commandes SMB normales, toutes les commandes Transaction2 et toutes les commandes NT Transaction. Seules les commandes qui sont vues dans la capture verront leurs statistiques affichées. Seule la première commande d'une chaîne de commandes xAndX sera utilisée dans le calcul. Ainsi, pour les chaînes courantes SessionSetupAndX + TreeConnectAndX, seul l'appel SessionSetupAndX sera utilisé dans les statistiques. C'est un défaut qui pourrait être corrigé à l'avenir.

Cette option peut être utilisée plusieurs fois sur la ligne de commande.

Exemple : -z "smb,srt,ip.addr==1.2.3.4" ne collectera que les statistiques pour les paquets SMB échangés par l'hôte à l'adresse IP 1.2.3.4.

-z smb2,srt[,filtre]

Collecte des données SRT (délai de réponse du service) d'appel/réponse pour les versions SMB 2 et 3. Les données collectées pour chaque type de commande normal sont le nombre d'appels, MinSRT, MaxSRT, AvgSRT et SumSRT. Aucune donnée n'est collectée sur les requêtes d'annulation ou de rupture d'oplock, ni sur les commandes non appariées. Seule la première réponse à une requête donnée est utilisée ; les retransmissions ne sont pas incluses dans le calcul.

-z smpp_commands,tree[,filtre]

Calcule la distribution des commandes SMPP. Les valeurs affichées sont les identifiants de commande pour les requêtes et les réponses, ainsi que le statut pour les réponses.

-z snmp,srt[,filtre]

Collecte des données SRT (délai de réponse du service) d'appel/réponse pour SNMP. Les données collectées pour chaque type de PDU sont le nombre de paires requête/réponse, MinSRT, MaxSRT, AvgSRT et SumSRT. Aucune donnée n'est collectée sur les messages non appariés.

-z someip_messages,tree[,filtre]

Crée des statistiques sur les messages SOME/IP. Les messages sont comptés et affichés comme des messages regroupés par expéditeur/destinataire.

-z someipsd_entries,tree[,filtre]

Crée des statistiques sur les entrées SOME/IP-SD. Les entrées sont comptées et affichées comme des entrées regroupées par expéditeur/destinataire.

-z sv

Affiche le temps écoulé depuis le début de la capture et le nombre d'échantillons pour chaque paquet IEC 61850 Sampled Values.

-z ucp_messages,tree[,filtre]

Calcule la distribution des messages des paquets UCP. Les valeurs affichées sont les types d'opérations pour les opérations et les résultats, et si les résultats sont positifs ou négatifs, avec les codes d'erreur affichés pour les résultats négatifs.

-z wsp,stat[,filtre]

Compte les types de PDU et les codes d'état des paquets de réponse pour les paquets WSP.

OPTIONS DE DISSECTION

-d <type de couche>==<sélecteur>,<protocole de décodage>

Similaire à la fonctionnalité Décode comme... de Wireshark, cela vous permet de spécifier comment une couche doit être disséquée. Si le type de couche en question (par exemple, tcp.port ou udp.port pour un numéro de port TCP ou UDP) a la valeur de sélecteur spécifiée, les paquets doivent être disséqués comme le protocole spécifié.

Exemple 1. Décoder comme port

-d tcp.port==8888,http décodera tout trafic passant par le port TCP 8888 en tant que HTTP.

Exemple 2. Décoder comme plage de ports

-d tcp.port==8888-8890,http décodera tout trafic passant par les ports TCP 8888, 8889 ou 8890 en tant que HTTP.

Exemple 3. Décoder comme plage de ports via longueur

-d tcp.port==8888:3,http décodera tout trafic passant par les trois ports TCP 8888, 8889 ou 8890 en tant que HTTP.

L'utilisation d'un sélecteur ou d'un protocole invalide affichera une liste des sélecteurs et des noms de protocoles valides, respectivement.

Exemple 4. Décoder comme liste de sélecteurs

-d . est un moyen rapide d'obtenir une liste de sélecteurs valides.

Exemple 5. Décoder comme liste de valeurs pour un sélecteur

-d ethertype==0x0800,. est un moyen rapide d'obtenir une liste de protocoles qui peuvent être sélectionnés avec un ethertype.

--disable-all-protocols

Désactive la dissection de tous les protocoles.

--disable-protocol <nom_proto>[,<nom_proto>,...]

Désactive la dissection de nom_proto. Utilisez un nom_proto de ALL pour remplacer la liste de protocoles activés par défaut de votre profil choisi et désactiver temporairement tous les protocoles.

--disable-heuristic <nom_court>

Désactive la dissection du protocole heuristique.

--enable-protocol <nom_proto>[,<nom_proto>,...]

Active la dissection de nom_proto. Utilisez un nom_proto de ALL pour remplacer la liste de protocoles désactivés par défaut de votre profil choisi et activer temporairement tous les protocoles qui sont activés par défaut.

Si un protocole est impliqué à la fois dans --disable-protocol et --enable-protocol, le protocole est activé. Cela vous permet de désactiver temporairement tous les protocoles sauf une liste d'exceptions. Exemple : --disable-protocol ALL --enable-protocol eth,ip

--enable-heuristic <nom_court>

Active la dissection du protocole heuristique.

-K <keytab>

Charge les clés de chiffrement Kerberos à partir du fichier keytab spécifié. Cette option peut être utilisée plusieurs fois pour charger des clés à partir de plusieurs fichiers.

Exemple : -K krb5.keytab

-n

Désactive la résolution des noms d'objets réseau (tels que les noms d'hôtes, les ports TCP et UDP) ; l'option -N peut remplacer celle-ci.

-N <indicateurs de résolution de noms>

Active la résolution de noms uniquement pour certains types d'adresses et de numéros de port, tandis que la résolution de noms pour d'autres types d'adresses et de numéros de port est désactivée. Cette option (ainsi que -n) peut être spécifiée plusieurs fois ; la dernière valeur donnée remplace les précédentes. Cette option et -n remplacent les options des préférences, y compris les préférences définies via l'option -o. Si les options -N et -n ne sont pas présentes, les valeurs des préférences sont utilisées, qui par défaut sont -N dmN.

L'argument est une chaîne qui peut contenir les lettres :

d pour activer la résolution à partir des paquets DNS capturés

g pour activer la recherche d'informations de géolocalisation d'adresses IP à partir des bases de données MaxMind configurées

m pour activer la résolution d'adresses MAC

n pour activer la résolution d'adresses réseau

N pour activer l'utilisation de résolveurs externes (par exemple, DNS) pour la résolution d'adresses réseau ; aucun effet sans n également activé.

s pour activer la résolution d'adresses en utilisant les informations SNI trouvées dans les paquets de handshake capturés

t pour activer la résolution des numéros de port de couche transport

v pour activer la résolution des ID VLAN en noms


Attention

En mode de passage unique de tshark, la résolution externe et la recherche de géolocalisation sont
effectuées de manière synchrone. Pour les captures en direct, qui sont toujours en mode de passage unique, cela rend plus difficile pour la dissection de suivre une réseau très actif, ce qui peut entraîner des paquets perdus.

--only-protocols <protocoles>

Active uniquement la dissection de ces protocoles, séparés par des virgules. Désactive tout le reste.

-t (a|ad|adoy|d|dd|e|r|u|ud|udoy)[.[N]]|.[N]

Définit le format de l'horodatage des paquets affiché dans la colonne de temps par défaut. Le format peut être l'un des suivants :

a absolue : L'heure absolue, en heure locale de votre fuseau horaire, est l'heure réelle de capture du paquet, sans date affichée.

ad absolue avec date : La date absolue, affichée au format AAAA-MM-JJ, et l'heure, en heure locale de votre fuseau horaire, sont l'heure et la date réelles de capture du paquet.

adoy absolue avec date utilisant le jour de l'année : La date absolue, affichée au format AAAA/DOY, et l'heure, en heure locale de votre fuseau horaire, sont l'heure et la date réelles de capture du paquet.

d delta : L'heure delta est le temps écoulé depuis la capture du paquet précédent.

dd delta_affiché : L'heure delta_affiché est le temps écoulé depuis l'affichage du paquet précédent.

e epoch : Le temps en secondes depuis l'epoch (1er janvier 1970 00:00:00).

r relative : Le temps relatif est le temps écoulé entre le premier paquet et le paquet courant.

u UTC : L'heure absolue, en UTC avec un suffixe "Z", est l'heure réelle de capture du paquet, sans date affichée.

ud UTC avec date : La date absolue, affichée au format AAAA-MM-JJ, et l'heure, en UTC avec un suffixe "Z", sont l'heure et la date réelles de capture du paquet.

udoy UTC avec date utilisant le jour de l'année : La date absolue, affichée au format AAAA/DOY, et l'heure, en UTC avec un suffixe "Z", sont l'heure et la date réelles de capture du paquet.

.[N] Définit la précision : N est le nombre de décimales (0 à 9). Si vous utilisez "." sans N, la précision est déterminée automatiquement à partir du trace.

Le format par défaut est relatif avec une précision basée sur le format de capture.

-u <s|hms>

Spécifie comment les formats d'horodatage des paquets dans -t qui sont des temps relatifs (c'est-à-dire relative, delta et delta_affiché) sont affichés. Les choix valides sont :

s pour les secondes

hms pour les heures, minutes et secondes

Le format par défaut est les secondes.

FICHIERS

Ces fichiers contiennent divers paramètres de configuration de Wireshark.

Préférences

Les fichiers de préférences contiennent les paramètres de préférences globaux (pour tout le système) et personnels. Si le fichier de préférences global existe, il est lu en premier, remplaçant les paramètres par défaut. Si le fichier de préférences personnel existe, il est lu ensuite, remplaçant toute valeur précédente. Remarque : si l'indicateur de ligne de commande -o est utilisé (éventuellement plus d'une fois), il remplacera à son tour les valeurs des fichiers de préférences.

Les paramètres de préférences sont sous la forme nompref:valeur, un par ligne, où nompref est le nom de la préférence et valeur est la valeur à laquelle elle doit être définie ; les espaces blancs sont autorisés entre : et valeur. Un paramètre de préférence peut être poursuivi sur les lignes suivantes en indentant les lignes de continuation avec des espaces blancs. Un caractère # démarre un commentaire qui s'étend jusqu'à la fin de la ligne :

# Faut-il des barres de défilement verticales sur la droite ?
# VRAI ou FAUX (insensible à la casse).
gui.scrollbar_on_right: TRUE

Le fichier de préférences global est recherché dans le répertoire wireshark sous le sous-répertoire share du répertoire d'installation principal. Sur macOS, il s'agirait typiquement de /Application/Wireshark.app/Contents/Resources/share ; sur d'autres systèmes compatibles UNIX, tels que Linux, \*BSD, Solaris et AIX, il s'agirait typiquement de /usr/share/wireshark/preferences pour les paquets installés globalement et de /usr/local/share/wireshark/preferences pour les paquets installés localement ; sous Windows, il s'agirait typiquement de C:\Program Files\Wireshark\preferences.

Sur les systèmes compatibles UNIX, le fichier de préférences personnel est recherché dans $XDG_CONFIG_HOME/wireshark/preferences, (ou, si $XDG_CONFIG_HOME/wireshark n'existe pas alors que $HOME/.wireshark existe, $HOME/.wireshark/preferences) ; il s'agit typiquement de $HOME/.config/wireshark/preferences. Sous Windows, le fichier de préférences personnel est recherché dans %APPDATA%\Wireshark\preferences (ou, si %APPDATA% n'est pas défini, %USERPROFILE%\Application Data\Wireshark\preferences).

Protocoles désactivés (activés)

Les fichiers disabled_protos contiennent des listes globales et personnelles de protocoles qui ont été désactivés, de sorte que leurs dissections ne soient jamais appelées. Les fichiers contiennent des noms de protocoles, un par ligne, où le nom du protocole est le même nom qui serait utilisé dans un filtre d'affichage pour le protocole :

http
tcp     # un commentaire

Si un protocole est listé dans le fichier global disabled_protos, il ne peut pas être activé par l'utilisateur.

Le fichier global disabled_protos utilise le même répertoire que le fichier de préférences global.

Le fichier personnel disabled_protos utilise le même répertoire que le fichier de préférences personnel.

Les fichiers disabled_protos listent uniquement les protocoles qui sont activés par défaut mais qui ont été désactivés ; les protocoles qui sont désactivés par défaut (comme certains postdissectors) ne sont pas listés. Il existe des fichiers enabled_protos analogues pour les protocoles qui sont désactivés par défaut mais qui ont été activés.

Dissectors heuristiques

Les fichiers heuristic_protos contiennent des listes globales et personnelles de dissectors heuristiques et indiquent s'ils sont activés ou désactivés. Les fichiers contiennent des noms courts uniques de dissectors heuristiques, un par ligne, suivi d'une virgule et de 0 pour désactivé et 1 pour activé :

quic,1
rtcp_stun,1
rtcp_udp,1
rtp_stun,0
rtp_udp,0
tls_tcp,1

Le fichier global heuristic_protos utilise le même répertoire que le fichier de préférences global.

Le fichier personnel heuristic_protos utilise le même répertoire que le fichier de préférences personnel.

Résolution de noms (hôtes)

Les entrées dans les fichiers hosts dans le répertoire de préférences global et personnel sont utilisées pour résoudre les adresses IPv4 et IPv6 avant toute autre tentative de résolution. Le fichier a la syntaxe standard d'un fichier hosts ; chaque ligne contient une adresse IP et un nom, séparés par des espaces blancs. Le fichier personnel hosts, s'il est présent, remplace celui du répertoire global.

La résolution de noms des filtres de capture est gérée par libpcap sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, et par Npcap sous Windows. Par conséquent, le fichier hosts personnel de Wireshark ne sera pas consulté pour la résolution de noms des filtres de capture.

Résolution de noms (sous-réseaux)

Si une adresse IPv4 ne peut pas être traduite par résolution de noms (aucune correspondance exacte n'est trouvée), une correspondance partielle est tentée via le fichier subnets. Le fichier global subnets et les fichiers personnels subnets sont tous deux utilisés s'ils existent.

Chaque ligne de ce fichier se compose d'une adresse IPv4, d'une longueur de masque de sous-réseau séparée uniquement par un / et d'un nom séparé par des espaces blancs. Bien que l'adresse doive être une adresse IPv4 complète, toutes les valeurs au-delà de la longueur du masque seront ensuite ignorées.

Un exemple est :

# Les commentaires doivent être précédés du signe # ! 192.168.0.0/24 ws_test_network

Un nom partiellement correspondant sera imprimé sous la forme "nom-sous-réseau.adresse-restante". Par exemple, "192.168.0.1" sous le sous-réseau ci-dessus serait imprimé sous la forme "ws_test_network.1" ; si la longueur du masque ci-dessus était de 16 au lieu de 24, l'adresse imprimée serait "ws_test_network.0.1".

Résolution de noms (ethers)

Les fichiers ethers sont consultés pour corréler les adresses matérielles EUI-48 de 6 octets et EUI-64 de 8 octets avec des noms. D'abord, le fichier personnel ethers est essayé et si une adresse n'est pas trouvée là, le fichier global ethers est essayé ensuite.

Le fichier a un format similaire à celui défini par ethers(5) sur certains systèmes de type UNIX. Chaque ligne contient une adresse matérielle et un nom, séparés par des espaces blancs (tabulations ou espaces). Les chiffres hexadécimaux de l'adresse matérielle sont séparés par des deux-points (:), des tirets (-) ou des points (.). Le même caractère séparateur doit être utilisé de manière cohérente dans une adresse. Un caractère # indique un commentaire qui s'étend jusqu'à la fin de la ligne. Les adresses MAC de 6 octets et les adresses EUI-64 de 8 octets sont prises en charge. Les quatre lignes suivantes sont des lignes valides d'un fichier ethers :

ff:ff:ff:ff:ff:ff          Broadcast
c0-00-ff-ff-ff-ff          TR_broadcast
00.00.00.00.00.00          Zero_broadcast
00:00:00:00:00:00:00:00    EUI64_zero_broadcast

Notez que cela accepte une plus grande variété de formats que le fichier défini par ethers(5) sur la plupart des systèmes UN*X.

Le fichier global ethers est recherché dans le répertoire /etc sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, et dans le répertoire d'installation principal (par exemple, C:\Program Files\Wireshark) sous les systèmes Windows.

Le fichier personnel ethers est recherché dans le même répertoire que le fichier de préférences personnel.

La résolution de noms des filtres de capture est gérée par libpcap sur les systèmes compatibles UNIX et par Npcap sous Windows. Par conséquent, le fichier ethers personnel de Wireshark ne sera pas consulté pour la résolution de noms des filtres de capture.

Résolution de noms (manuf)

Le fichier manuf est utilisé pour faire correspondre la partie fournisseur de 3 octets d'une adresse matérielle de 6 octets avec le nom du fabricant ; il peut également contenir des adresses MAC bien connues et des plages d'adresses spécifiées avec un masque réseau. Le format du fichier est similaire à celui des fichiers ethers, sauf que des entrées telles que :

00:00:0C      Cisco     Cisco Systems, Inc

peuvent être fournies, avec l'OUI de 3 octets et un nom abrégé et un nom long pour un fournisseur, et des entrées telles que :

00-00-0C-07-AC/40     All-HSRP-routers

peuvent être spécifiées, avec une adresse MAC et un masque indiquant combien de bits de l'adresse doivent correspondre. L'entrée ci-dessus, par exemple, a 40 bits significatifs, soit 5 octets, et correspondra aux adresses de 00-00-0C-07-AC-00 à 00-00-0C-07-AC-FF. Le masque n'a pas besoin d'être un multiple de 8.

Un fichier global manuf est recherché dans le même répertoire que le fichier de préférences global, et un fichier personnel manuf est recherché dans le même répertoire que le fichier de préférences personnel.

Dans les versions antérieures de Wireshark, des informations officielles de l'IEEE Registration Authority étaient distribuées sous ce format comme fichier manuf global. Ces informations sont maintenant compilées pour accélérer le démarrage du programme, mais les informations internes peuvent être extraites dans ce format avec tshark -G manuf.

En plus du fichier manuf, un autre fichier de même format, wka, est recherché dans le répertoire global. Ce fichier est distribué avec Wireshark et contient des données sur les adresses MAC et les plages d'adresses bien connues, assemblées à partir de diverses sources non IEEE mais respectées.

Résolution de noms (services)

Le fichier services est utilisé pour traduire les numéros de port en noms. Le fichier global services et les fichiers personnels services sont tous deux utilisés s'ils existent.

Le fichier a la syntaxe standard d'un fichier services ; chaque ligne contient un nom (de service) et un identifiant de transport séparés par des espaces blancs. L'identifiant de transport comprend un numéro de port et un nom de protocole de transport (généralement tcp, udp ou sctp) séparés par un /.

Un exemple est :

mydns 5045/udp # Mon propre serveur de noms de domaine mydns 5045/tcp # Mon propre serveur de noms de domaine

Dans les versions antérieures de Wireshark, des informations officielles de l'IANA Registry étaient distribuées sous ce format comme fichier services global. Ces informations sont maintenant compilées pour accélérer le démarrage du programme, mais les informations internes peuvent être extraites dans ce format avec tshark -G services.

Résolution de noms (ipxnets)

Les fichiers ipxnets servent à faire correspondre les numéros de réseau IPX à 4 octets avec des noms. Le fichier global ipxnets est d'abord consulté et, si l'adresse n'y est pas trouvée, le fichier personnel est ensuite essayé.

Le format est identique à celui du fichier ethers, à la différence que chaque adresse fait 4 octets au lieu de 6. De plus, l'adresse peut être représentée comme un nombre hexadécimal unique, comme il est plus courant dans le monde IPX, plutôt que quatre octets hexadécimaux. Par exemple, ces quatre lignes sont des lignes valides d'un fichier ipxnets :

C0.A8.2C.00              HR
c0-a8-1c-00              CEO
00:00:BE:EF              IT_Server1
110f                     FileServer3

Le fichier global ipxnets est recherché dans le répertoire /etc sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, et dans le répertoire d'installation principal (par exemple, C:\Program Files\Wireshark) sur les systèmes Windows.

Le fichier personnel ipxnets est recherché dans le même répertoire que le fichier de préférences personnel.

Résolution de noms (ss7pcs)

Le fichier ss7pcs est utilisé pour traduire les codes de point SS7 en noms. Il est lu à partir du répertoire de configuration personnel.

Chaque ligne de ce fichier se compose d'un indicateur réseau suivi d'un tiret, suivi d'un code de point en décimal et d'un nom de nœud séparés par des espaces. Un exemple est :

2-1234 MyPointCode1

Résolution de noms (vlans)

Le fichier vlans est utilisé pour traduire les identifiants de tag VLAN en noms. Il est lu à partir du répertoire de configuration personnel.

Chaque ligne de ce fichier se compose d'un identifiant de tag VLAN séparé par des espaces d'un nom. Un exemple est :

123    Server-Lan
2049   HR-Client-LAN

Filtres de couleur (Règles de coloration)

Les fichiers colorfilters contiennent des filtres de couleur système et personnels. Chaque ligne contient un filtre, commençant par la chaîne affichée dans la boîte de dialogue, suivie du filtre d'affichage correspondant. Ensuite, les couleurs d'arrière-plan et de premier plan sont ajoutées :

# un commentaire
@tcp@tcp@[59345,58980,65534][0,0,0]
@udp@udp@[28834,57427,65533][0,0,0]

Le fichier global colorfilters utilise le même répertoire que le fichier de préférences global.

Le fichier personnel colorfilters utilise le même répertoire que le fichier de préférences personnel. Il est écrit via la boîte de dialogue Vue : Règles de coloration.

Si le fichier global colorfilters existe, il n'est utilisé que si le fichier personnel colorfilters n'existe pas ; les filtres de couleur globaux et personnels ne sont pas fusionnés.

Plugins

Wireshark recherche des plugins dans un dossier de plugins personnel et un dossier de plugins global.

Sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, le répertoire de plugins global est lib/wireshark/plugins/ (sur certains systèmes, remplacez lib64 par lib) sous le répertoire d'installation principal (par exemple, /usr/local/lib/wireshark/plugins/). Le répertoire de plugins personnel est $HOME/.local/lib/wireshark/plugins.

Sur macOS, si Wireshark est installé en tant que bundle d'application, le dossier de plugins global est à la place %APPDIR%/Contents/PlugIns/wireshark.

Sous Windows, le dossier de plugins global est plugins/ sous le répertoire d'installation principal (par exemple, C:\Program Files\Wireshark\plugins\). Le dossier de plugins personnel est %APPDATA%\Wireshark\plugins (ou, si %APPDATA% n'est pas défini, %USERPROFILE%\Application Data\Wireshark\plugins).

Les plugins Lua sont stockés dans les dossiers de plugins ; les plugins compilés sont stockés dans des sous-dossiers des dossiers de plugins, le nom du sous-dossier étant le numéro de version mineure de Wireshark (X.Y). Il existe un autre niveau hiérarchique pour chaque type de plugin Wireshark (libwireshark, libwiretap et codecs). Par exemple, l'emplacement d'un plugin libwireshark foo.so (foo.dll sous Windows) serait PLUGINDIR/X.Y/epan (libwireshark s'appelait auparavant libepan ; les autres noms de dossier sont codecs et wiretap).


Note

Sur les systèmes compatibles UNIX, les plugins Lua (mais pas les plugins binaires) peuvent également
être placés dans $XDG_CONFIG_HOME/wireshark/plugins, (ou, si $XDG_CONFIG_HOME/wireshark n'existe pas tandis que $HOME/.wireshark existe, $HOME/.wireshark/plugins.)

Notez qu'un module de plugin dissector peut prendre en charge plusieurs protocoles ; il n'y a pas nécessairement de correspondance univoque entre les modules de plugin dissector et les protocoles. Les protocoles pris en charge par un module de plugin dissector sont activés et désactivés de la même manière que les protocoles intégrés à Wireshark.

SORTIE

TShark utilise UTF-8 pour représenter les chaînes de caractères en interne. Dans certains cas, la sortie peut ne pas être valide. Par exemple, un dissector peut générer des séquences de caractères UTF-8 invalides. Les programmes qui lisent la sortie de TShark doivent s'attendre à de l'UTF-8 et être préparés à une sortie invalide.

Si TShark détecte qu'il écrit dans un TTY sur un système compatible UNIX, tel que Linux, macOS, \*BSD, Solaris et AIX, et que la locale ne prend pas en charge UTF-8, la sortie sera ré-encodée pour correspondre à la locale actuelle.

Si TShark détecte qu'il écrit sur la console sous Windows, la sortie de dissection sera encodée en UTF-16LE. Les autres sorties seront en UTF-8. Si les caractères étendus ne s'affichent pas correctement dans votre terminal, vous pouvez essayer de définir la page de code de votre console sur UTF-8 (chcp 65001) et d'utiliser une application de terminal moderne si possible.

VARIABLES D'ENVIRONNEMENT

WIRESHARK_CONFIG_DIR

Cette variable d'environnement remplace l'emplacement des fichiers de configuration personnels. Sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX, elle est par défaut $XDG_CONFIG_HOME/wireshark (ou, si ce répertoire n'existe pas mais que $HOME/.wireshark existe, $HOME/.wireshark) ; il s'agit généralement de $HOME/.config/wireshark. Sous Windows, elle est par défaut %APPDATA%\Wireshark (ou, si %APPDATA% n'est pas défini, %USERPROFILE%\Application Data\Wireshark). Disponible depuis Wireshark 3.0.

WIRESHARK_DEBUG_WMEM_OVERRIDE

Définir cette variable d'environnement force le framework wmem à utiliser le backend d'allocation spécifié pour toutes les allocations, quel que soit le backend normalement spécifié par le code. Ceci est principalement utile aux développeurs lors des tests ou du débogage. Voir README.wmem dans la distribution source pour plus de détails.

WIRESHARK_RUN_FROM_BUILD_DIRECTORY

Cette variable d'environnement permet de charger les plugins et autres fichiers de données à partir du répertoire de construction (où le programme a été compilé) plutôt que des emplacements standard. Elle n'a aucun effet lorsque le programme en question est exécuté avec des privilèges root (ou setuid) sur les systèmes compatibles UNIX, tels que Linux, macOS, \*BSD, Solaris et AIX.

WIRESHARK_DATA_DIR

Cette variable d'environnement permet de charger les différents fichiers de données à partir d'un répertoire autre que les emplacements standard. Elle n'a aucun effet lorsque le programme en question est exécuté avec des privilèges root (ou setuid) sur les systèmes compatibles UNIX.

WIRESHARK_EXTCAP_DIR

Cette variable d'environnement permet d'exécuter les différents programmes et scripts extcap à partir d'un répertoire autre que les emplacements standard. Elle n'a aucun effet lorsque le programme en question est exécuté avec des privilèges root (ou setuid) sur les systèmes compatibles UNIX.

WIRESHARK_PLUGIN_DIR

Cette variable d'environnement permet de charger les différents plugins à partir d'un répertoire autre que les emplacements standard. Elle n'a aucun effet lorsque le programme en question est exécuté avec des privilèges root (ou setuid) sur les systèmes compatibles UNIX.

ERF_RECORDS_TO_CHECK

Cette variable d'environnement contrôle le nombre d'enregistrements ERF vérifiés lors de la décision si un fichier est réellement au format ERF. Définir cette variable d'environnement à un nombre supérieur à la valeur par défaut (20) rendrait les faux positifs moins probables.

IPFIX_RECORDS_TO_CHECK

Cette variable d'environnement contrôle le nombre d'enregistrements IPFIX vérifiés lors de la décision si un fichier est réellement au format IPFIX. Définir cette variable d'environnement à un nombre supérieur à la valeur par défaut (20) rendrait les faux positifs moins probables.

WIRESHARK_ABORT_ON_DISSECTOR_BUG

Si cette variable d'environnement est définie, TShark appellera abort(3) lorsqu'un bug de dissector est rencontré. abort(3) provoquera une sortie anormale du programme ; si vous exécutez TShark dans un débogueur, il devrait s'arrêter dans le débogueur et permettre l'inspection du processus, et, si vous ne l'exécutez pas dans un débogueur, il générera, sur certains systèmes d'exploitation, en supposant que votre environnement est correctement configuré, un fichier de vidage principal (core dump). Ceci peut être utile aux développeurs tentant de résoudre un problème avec un dissector de protocole.

WIRESHARK_ABORT_ON_TOO_MANY_ITEMS

Si cette variable d'environnement est définie, TShark appellera abort(3) si un dissector tente d'ajouter trop d'éléments à un arbre (généralement, c'est une indication que le dissector ne sort pas d'une boucle assez rapidement). abort(3) provoquera une sortie anormale du programme ; si vous exécutez TShark dans un débogueur, il devrait s'arrêter dans le débogueur et permettre l'inspection du processus, et, si vous ne l'exécutez pas dans un débogueur, il générera, sur certains systèmes d'exploitation, en supposant que votre environnement est correctement configuré, un fichier de vidage principal (core dump). Ceci peut être utile aux développeurs tentant de résoudre un problème avec un dissector de protocole.

WIRESHARK_LOG_LEVEL

Cette variable d'environnement contrôle la verbosité des messages de diagnostic vers la console. Du moins verbeux au plus verbeux, les niveaux peuvent être critical, warning, message, info, debug ou noisy. Les niveaux supérieurs au niveau actuel sont également actifs. Les niveaux critical et error sont toujours actifs.

WIRESHARK_LOG_FATAL

Définit le niveau de journalisation fatal. Les niveaux de journalisation fatal provoquent l'arrêt du programme. Ce niveau peut être défini sur Error, critical ou warning. Error est toujours fatal et est la valeur par défaut.

WIRESHARK_LOG_DOMAINS

Cette variable d'environnement sélectionne les domaines de journalisation actifs. Le filtre est donné sous forme de liste insensible à la casse et séparée par des virgules.

NAME

tshark - capture and display packets from a live network or read packets from a capture file

SYNOPSIS

tshark [-i interface] [options] [filter]

tshark [-r file] [options] [filter]

DESCRIPTION

TShark is a network protocol analyzer. It, or one of its variants, can be used to list and sting the details of traffic on a network computer is connected to, or .. to analyze packets captured on a network computer is connected to. The packet information is decoded and displayed in a human-readable format. You can use the -V, -T, or -x flags to see packet information.

The filter expression syntax is identical to that used by Wireshark and tcpdump(8).

TShark is a command-line version of Wireshark. This makes TShark ideal for remote capture and for scripting.

The default interface is used if the -i or -r flags are not specified.

OPTIONS

The options are too numerous to list here. See the full documentation for details.

A complete list of options can be obtained using the -h or --help flags.

DISSECTION OPTIONS

-V, --display-protocol
Print a protocol hierarchy or a display filter list. See -T.

-T, --display-format
Set the output format for packet details. If this option is specified, the header of the packet is not printed. The available formats are:

ps Protocol-statistic: Print a protocol hierarchy.

pdml Packet-Detailed-Markup-Language: Print packet details in XML format.

json JavaScript Object Notation: Print packet details in JSON format.

fields Fields: Print packet details in a flat, easy-to-parse format. Use the -e option to specify which fields to print.

default Default: Print packet details in a free-form, human-readable format.

-e, --display-field
Print only the specified fields. This option can be specified multiple times to specify multiple fields. This option only has an effect when -Tfields is specified.

-x, --hex-chars
Print the packet in a hexadecimal and ASCII representation. This option is equivalent to -V. Note that this option is deprecated and will be removed in a future release. Use -V instead.

DIAGNOSTIC OPTIONS

-d, --debug
Enable debugging output. This option can be specified multiple times to increase the level of debugging output.

-v, --version
Print the version of TShark and exit.

-h, --help
Print the help message and exit.

CAPTURE FILTER SYNTAX

TShark supports capture filters, which are used to filter packets on the network interface before they are captured. The syntax of capture filters is identical to that used by tcpdump(8).

For example, to capture only TCP packets on port 80, you would use the following filter:

tcp port 80

Capture filters are applied using the -f flag.

READ FILTER SYNTAX

TShark supports read filters, which are used to filter packets from a capture file or from a live capture after they have been captured. The syntax of read filters is more powerful than that of capture filters and is identical to that used by Wireshark.

For example, to display only TCP packets with the SYN flag set, you would use the following filter:

tcp.flags.syn == 1

Read filters are applied by simply specifying them as the last argument on the command line.

FILES

/etc/wireshark/init.d/
Directory for initialization scripts.

~/.config/wireshark/init.d/
User-specific initialization scripts.

OUTPUT

The output of TShark can be customized using the following options:

-t, --time-stamp-format
Set the time stamp format. The available formats are:

a Absolute: Print the absolute time of day.

r Relative: Print the time of day relative to the first packet.

u UDP: Print the time of day in seconds since midnight.

n None: Don't print the time of day.

tarp: Print the time of day in seconds since the epoch.

-f, --capture-filter
Set the capture filter expression.

-R, --read-filter
Set the read filter expression.

ENVIRONMENT VARIABLES

The behavior of TShark can be customized using the following environment variables:

WIRESHARK_LOG_LEVEL
Set the global log level. This variable takes precedence over the active domains filter. If preceded by '!' this disables the specified log level instead.

WIRESHARK_LOG_DOMAIN
Set the active log domains. If set, only the included domains will be enabled. The default domain is always considered to be enabled. Domain filter lists can be preceded by '!' to invert the sense of the match.

WIRESHARK_LOG_DEBUG
List of domains with debug log level. This sets the level of the provided log domains and takes precedence over the active domains filter. If preceded by '!' this disables the debug level instead.

WIRESHARK_LOG_NOISY
Same as above but for noisy log level instead.
