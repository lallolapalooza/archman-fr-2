NOM

ts.conf - Fichier de configuration pour tslib, contrôlant les écrans tactiles pour les appareils embarqués.

DESCRIPTION

L'idée de tslib est d'avoir une bibliothèque centrale qui fournit des services standard, et un ensemble de plugins pour gérer la conversion et le filtrage selon les besoins.

Les plugins pour un écran tactile particulier sont chargés automatiquement par la bibliothèque sous le contrôle d'un fichier de configuration statique, /etc/ts.conf. /etc/ts.conf donne à la bibliothèque des informations de configuration de base. Chaque ligne spécifie un module et les paramètres de ce module. Les modules sont chargés dans l'ordre, le premier traitant les données de l'écran tactile en premier. Par exemple :

  module_raw input
  module variance delta=30
  module dejitter delta=100
  module linear

VARIABLES ENVIRONNEMENT

Les dernières versions du pilote d'entrée tslib Xorg utilisent hal pour configurer l'écran tactile dans Xorg. Les variables d'environnement ne sont nécessaires que pour les commandes tslib.

TSLIB_TSDEVICE

Si le périphérique d'écran tactile par défaut ne peut pas être trouvé, définissez la variable d'environnement TSLIB_TSDEVICE sur le périphérique d'écran tactile à utiliser.

Défaut lors de l'utilisation de ts_setup() : nous essayons d'ouvrir /dev/input/ts, /dev/input/touchscreen et /dev/touchscreen/ucb1x00 et sous Linux, nous scannons ensuite /dev/input/event* pour le premier périphérique avec la propriété INPUT_PROP_DIRECT.

TSLIB_CONSOLEDEVICE

Périphérique console par défaut de Tslib.

Défaut : /dev/tty

TSLIB_CALIBFILE

Stocke les données de calibration obtenues à l'aide de ts_calibrate.

Défaut : /etc/pointercal

TSLIB_CONFFILE

Définir un emplacement différent pour le fichier de configuration ts.conf lui-même.

Défaut ; /etc/ts.conf.

TSLIB_FBDEVICE

Périphérique framebuffer à utiliser pour le support de l'écran tactile.

Défaut : /dev/fb0.

TSLIB_PLUGINDIR

Répertoire des plugins pour tslib.

Défaut : /usr/lib/$triplet/ts0/ où triplet est le chemin MultiArch, par exemple arm-linux-gnueabi.

PARAMETRES MODULE

dejitter

Supprime le tremblement sur les coordonnées X et Y. Ceci est réalisé en appliquant un filtre de lissage pondéré. Les échantillons les plus récents ont le plus de poids ; les échantillons plus anciens ont moins de poids. Cela permet d'obtenir un taux d'entrée-sortie de 1:1.
•delta

Distance au carré entre deux échantillons ((X2-X1)^2 + (Y2-Y1)^2) qui définit le seuil de mouvement rapide. Si le stylet bouge rapidement, il n'est pas possible de lisser le mouvement du stylet, de plus le mouvement rapide n'est pas précis de toute façon ; donc si un mouvement rapide est détecté, le module rejette simplement le backlog et copie simplement l'entrée vers la sortie.

linear

Module de mise à l'échelle linéaire, principalement utilisé pour la conversion des coordonnées de l'écran tactile vers les coordonnées de l'écran.
•rot

Rotation des coordonnées tactiles. 0=non, 1=CW, 2=UD, 3=CCW. Défaut : la rotation de l'écran utilisée avec ts_calibrate (option -r).

•xyswap

Intervertir les coordonnées X et Y -- n'est plus utilisé ou nécessaire si le nouvel utilitaire de calibration linéaire ts_calibrate est utilisé.

•pressure_offset

Décalage appliqué à la valeur de pression. Défaut : 0.

•pressure_mul

Facteur pour multiplier la valeur de pression. Défaut : 1.

•pressure_div

Valeur pour diviser la valeur de pression. Défaut : 1.

iir

Filtre à réponse impulsionnelle infinie. Similaire à dejitter, c'est un filtre de lissage pour éliminer le bruit de bas niveau. Il y a un compromis entre l'élimination du bruit (lissage) et la réactivité. Les paramètres N et D spécifient le niveau de lissage sous la forme d'une fraction (N/D).
•N

numérateur de la fraction de lissage. Défaut : 0.

•D

dénominateur de la fraction de lissage. Défaut : 1.

pthres

Filtre de seuil de pression. Étant donné qu'un relâchement est toujours une pression de 0 et une pression est toujours >= 1, cela rejette les échantillons en dessous / au-dessus du seuil de pression spécifié.
•pmin

Valeur de pression minimale pour qu'un échantillon soit valide. Défaut : 1.

•pmax

Valeur de pression maximale pour qu'un échantillon soit valide. Défaut : INT_MAX.

crop

Ignore les points tactiles en dehors du framebuffer.

debounce

Mécanisme de filtrage simple qui supprime les événements d'entrée pendant la durée spécifiée après l'arrêt d'un geste tactile.
•drop_threshold

supprime les événements jusqu'à ce nombre de millisecondes après le dernier événement de relâchement. Défaut : 0.

skip

Saute nhead échantillons après la pression et ntail échantillons avant le relâchement. Cela devrait aider si pour l'appareil, les premiers ou les derniers échantillons ne sont pas fiables.
•nhead

Nombre d'événements à ignorer après la pression. Défaut : 1.

•ntail

Nombre d'événements à ignorer avant le relâchement. Défaut : 1.

median

Similaire à ce que fait le filtre de variance, le filtre médian supprime les pics dans le geste.
•depth

Nombre d'échantillons sur lesquels appliquer le filtre médian. Défaut : 3.

invert

Inverse les valeurs dans les directions X et/ou Y autour d'une valeur donnée.
•x0

Valeur sur l'axe X (horizontal) autour de laquelle inverser. Défaut : 0.

•y0

Valeur sur l'axe Y (horizontal) autour de laquelle inverser. Défaut : 0.

lowpass

filtre passe-bas à moyennage exponentiel simple
•factor

valeurs flottantes entre 0 et 1. Défaut : 0.4.

•threshold

distance minimale x ou y entre deux échantillons pour commencer à appliquer le filtre. Défaut : 2.

evthres

Nombre d'échantillons nécessaires du périphérique après avoir été considéré comme un contact valide. Ce filtre rejettera un tapotement s'il y a trop peu d'échantillons entre "down" et "up".
•N

Nombre minimum d'événements nécessaires entre "down" et "up". Défaut : 5.

variance

Essaye de faire de son mieux pour filtrer le bruit aléatoire provenant des ADC de l'écran tactile. Ceci est réalisé en limitant la vitesse de déplacement de l'échantillon à une certaine valeur (par exemple, le stylet n'est pas censé bouger plus vite qu'un certain seuil).

Ceci est un filtre glouton, c'est-à-dire qu'il donne moins d'échantillons en sortie qu'il en reçoit en entrée. Il n'y a pas de support multitouch pour ce filtre.

•delta

Définissez la distance au carré en unités d'écran tactile entre la position précédente et actuelle du stylet (par exemple, (X2-X1)^2 + (Y2-Y1)^2). Cela définit le critère pour déterminer si deux échantillons sont proches ou éloignés l'un de l'autre.

Si la distance entre l'échantillon précédent et l'échantillon actuel est grande, l'échantillon est marqué comme bruit potentiel. Cela ne signifie pas encore qu'il sera rejeté ; si la prochaine lecture sera proche de lui, cela sera considéré comme un simple événement de mouvement rapide, et il passera discrètement à la couche suivante. De plus, si l'échantillon après le bruit potentiel est éloigné des deux échantillons discutés précédemment, cela est également considéré comme un événement de mouvement rapide et l'échantillon passe discrètement dans le flux de sortie.

support matériel


Sous Linux, utilisez module_raw input si vous le pouvez. Les autres modules d'accès brut sont des pilotes en espace utilisateur spécifiques à chaque appareil. Si vous avez besoin de l'un d'eux, activez-le explicitement lors de la compilation de tslib. La liste des modules activés par défaut pourrait diminuer à l'avenir. module_raw input prend également en charge le multitouch (MT).
