TSOCKS(8) Manuel du gestionnaire système TSOCKS(8)

NOM

tsocks - Bibliothèque pour intercepter les connexions réseau sortantes et les rediriger via un serveur SOCKS.

SYNTAXE

Définissez LD_PRELOAD pour charger la bibliothèque puis utilisez les applications normalement

La syntaxe pour forcer le préchargement de la bibliothèque pour différents shells est spécifiée ci-dessous :

Bash, Ksh et Bourne shell -

export LD_PRELOAD=/lib/libtsocks.so

C Shell -

setenv LD_PRELOAD=/lib/libtsocks.so

Ce processus peut être automatisé (pour les utilisateurs de Bash, Bourne et Korn shell) pour une seule commande ou pour toutes les commandes d'une session shell en utilisant le script tsocks(1)

Vous pouvez également configurer tsocks de manière à ce que tous les processus l'utilisent automatiquement, une configuration très utile. Pour plus d'informations sur cette configuration, consultez la section CAVEATS de cette page de manuel.

DESCRIPTION

tsocks est une bibliothèque permettant le proxy SOCKS transparent. Elle encapsule la fonction connect() normale. Lorsqu'une connexion est tentée, elle consulte le fichier de configuration (qui est défini au moment de la compilation mais utilise par défaut /etc/tsocks.conf) et détermine si l'adresse IP spécifiée est locale. Si ce n'est pas le cas, la bibliothèque redirige la connexion vers un serveur SOCKS spécifié dans le fichier de configuration. Elle négocie ensuite cette connexion avec le serveur SOCKS et la transmet au programme appelant.

tsocks est conçu pour être utilisé sur des machines qui sont pare-feux de l'internet. Il évite d'avoir à recompiler des applications comme lynx ou telnet pour qu'elles puissent utiliser SOCKS pour accéder à l'internet. Il se comporte de manière similaire aux piles TCP/IP "SOCKSifiées" vues sur d'autres plateformes.

ARGUMENTS

La plupart des arguments de tsocks sont fournis dans le fichier de configuration (dont l'emplacement est défini au moment de la compilation par l'argument --with-conf=<fichier> mais utilise par défaut /etc/tsocks.conf). La structure de ce fichier est documentée dans tsocks.conf(8)

Certaines options de configuration peuvent être spécifiées à l'exécution à l'aide de variables d'environnement comme suit :

TSOCKS_CONFFILE
Cette variable d'environnement remplace l'emplacement par défaut du fichier de configuration tsocks. Cette variable n'est pas prise en compte si le programme dans lequel tsocks est intégré est setuid. De plus, cette variable d'environnement peut être désactivée lors de la compilation de tsocks avec l'argument --disable-envconf lors de la construction.
TSOCKS_DEBUG
Cette variable d'environnement définit le niveau de sortie de débogage qui devrait être généré par tsocks (la sortie de débogage est générée sous forme de sortie vers l'erreur standard). Si cette variable n'est pas présente par défaut, le niveau de journalisation est défini sur 0, ce qui indique que seuls les messages d'erreur doivent être affichés. La définir à des valeurs plus élevées entraînera la génération de plus de messages par tsocks décrivant ce qu'il fait. Si elle est définie sur -1, tsocks ne produira absolument aucun message d'erreur ou de débogage. Ceci n'est nécessaire que si la sortie de tsocks interfère avec un programme dans lequel il est intégré. La sortie des messages peut être définitivement désactivée lors de la compilation de tsocks en spécifiant l'option --disable-debug à configure lors de la construction.
TSOCKS_DEBUG_FILE
Cette option peut être utilisée pour rediriger la sortie de tsocks (qui serait normalement envoyée à l'erreur standard) vers un fichier. Cette variable n'est pas prise en compte si le programme dans lequel tsocks est intégré est setuid. Pour les programmes où la sortie de tsocks interfère avec le fonctionnement normal, cette option est généralement préférable à la désactivation des messages (avec TSOCKS_DEBUG = -1).
TSOCKS_USERNAME
Cette variable d'environnement peut être utilisée pour spécifier le nom d'utilisateur à utiliser lorsque les serveurs SOCKS version 5 demandent une authentification par nom d'utilisateur/mot de passe. Elle remplace le nom d'utilisateur par défaut qui peut être spécifié dans le fichier de configuration à l'aide de 'default_user', voir tsocks.conf(8) pour plus d'informations. Cette variable est ignorée pour les serveurs SOCKS version 4.
TSOCKS_PASSWORD
Cette variable d'environnement peut être utilisée pour spécifier le mot de passe à utiliser lorsque les serveurs SOCKS version 5 demandent une authentification par nom d'utilisateur/mot de passe. Elle remplace le mot de passe par défaut qui peut être spécifié dans le fichier de configuration à l'aide de 'default_pass', voir tsocks.conf(8) pour plus d'informations. Cette variable est ignorée pour les serveurs SOCKS version 4.

PROBLÈMES DNS

tsocks ne sera normalement pas capable d'envoyer des requêtes DNS via un serveur SOCKS car SOCKS V4 fonctionne sur TCP et DNS utilise normalement UDP. Les versions 1.5 et supérieures fournissent cependant une méthode pour forcer les recherches DNS à utiliser TCP, ce qui les rend alors proxyfiables. Cette option ne peut être activée qu'au moment de la compilation, consultez le fichier INSTALL pour plus d'informations.

ERREURS

tsocks générera des messages d'erreur et les affichera sur stderr en cas de problèmes avec le fichier de configuration ou la négociation SOCKS avec le serveur, si la variable d'environnement TSOCKS_DEBUG n'est pas définie sur -1 ou si --disable-debug n'a pas été spécifié lors de la compilation. Cette sortie peut causer des problèmes avec les programmes qui redirigent l'erreur standard.

CAVEATS

Dans la configuration ci-dessus, tsocks ne pourra pas fournir de proxy SOCKS aux applications setuid ou aux applications qui ne sont pas exécutées depuis un shell. Vous pouvez forcer toutes les applications à LD_PRELOAD la bibliothèque en plaçant le chemin vers libtsocks dans /etc/ld.so.preload. Assurez-vous d'entrer correctement le chemin complet de la bibliothèque dans ce fichier si vous le faites. Si vous vous trompez, vous ne pourrez PLUS RIEN faire avec la machine et devrez la démarrer avec un disque de secours et supprimer le fichier (ou essayer le programme saveme, voir le fichier INSTALL pour plus d'informations). C'EST UN ***AVERTISSEMENT***, soyez prudent. Assurez-vous également que la bibliothèque se trouve dans le système de fichiers racine, car tout ira mal si le répertoire dans lequel elle se trouve n'est pas disponible au démarrage.

BOGUES

tsocks ne peut que proxifier les connexions TCP sortantes

tsocks ne fonctionne PAS correctement avec les sockets asynchrones (bien qu'il fonctionne avec les sockets non bloquants). Ce bug serait très difficile à corriger et il ne semble pas y avoir de demande pour cela (je ne connais aucune application majeure qui utilise des sockets asynchrones).

tsocks n'est PAS entièrement conforme aux RFC dans son implémentation de la version 5 de SOCKS, il ne prend en charge que les méthodes d'authentification 'nom d'utilisateur et mot de passe' ou 'aucune authentification'. Le RFC spécifie que GSSAPI doit être pris en charge par toute implémentation conforme. Je ne l'ai pas fait, quelqu'un veut-il aider ?

tsocks peut forcer le résolveur libc à utiliser TCP pour les requêtes de nom, s'il le fait, il le fait quelle que soit la nécessité de faire la requête DNS locale ou non. Cela introduit une surcharge et ne doit être utilisé que lorsque nécessaire.

tsocks utilise les fonctionnalités du chargeur dynamique ELF pour intercepter les appels de fonction dynamiques des programmes dans lesquels il est intégré. Par conséquent, il ne peut pas tracer les actions des exécutables liés statiquement, des exécutables non-ELF, ou des exécutables qui font des appels système directement via le piège d'appel système ou via la routine syscall().

tsocks(8) - Arch Linux man pages

NAME

tsocks - Transparent SOCKS

SYNOPSIS

tsocks command [args]

DESCRIPTION

tsocks is a small program that allows you to use SOCKS (socks4, socks4a, socks5, socks5h) and SOCKS+UDP/TCP (socks5u) proxies transparently. This means that you can run any application through a SOCKS proxy without needing to recompile or modify it. This is achieved by intercepting socket-related system calls and redirecting them through the proxy.

BUGS

UDP support is limited. It works by sending UDP packets via TCP to a UDP-to-TCP relay on the proxy server. UDP is not truly supported. Some applications may not work as expected. Some applications may not work with tsocks at all, especially those which use non-standard socket behaviour, or attempt to connect to their own IP address.

FILES

/etc/tsocks.conf
Configuration file for tsocks.
