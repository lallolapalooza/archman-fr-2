TSOCKS.CONF(5) Manuel des formats de fichiers TSOCKS.CONF(5)

NOM

tsocks.conf - fichier de configuration pour tsocks(8)

APERÇU

La configuration de tsocks peut varier de deux lignes à des centaines de lignes, selon les besoins d'un site particulier. L'idée de base est de définir tous les réseaux auxquels la machine peut accéder directement (c'est-à-dire sans utiliser de serveur SOCKS) et de définir un ou plusieurs serveurs SOCKS à utiliser pour accéder à d'autres réseaux (y compris un serveur 'défaut').

Les réseaux locaux sont déclarés en utilisant le mot-clé 'local' dans le fichier de configuration. Lorsque les applications tentent de se connecter à des machines dans des réseaux marqués comme locaux, tsocks ne tentera pas d'utiliser un serveur SOCKS pour négocier la connexion.

Évidemment, si une connexion n'est pas à un réseau accessible localement, elle devra être redirigée via un serveur SOCKS. Cependant, de nombreuses installations ont plusieurs serveurs SOCKS différents à utiliser pour accéder à différents réseaux internes (et externes). Pour cette raison, le fichier de configuration permet la définition de

Les chemins sont déclarés sous forme de blocs dans le fichier de configuration. C'est-à-dire qu'ils commencent par une ligne 'path {' dans le fichier de configuration et se terminent par une ligne '}'. À l'intérieur de ce bloc, des directives doivent être utilisées pour déclarer un serveur SOCKS (tel que documenté plus loin dans cette page de manuel) et des directives 'reaches' doivent être utilisées pour déclarer les réseaux et même les ports de destination sur ces réseaux auxquels ce serveur doit être utilisé pour accéder. N.B. Chaque chemin DOIT définir un serveur SOCKS et contenir une ou plusieurs directives 'reaches'.

Les directives de déclaration de serveur SOCKS qui ne sont pas contenues dans un bloc 'path' définissent le serveur SOCKS par défaut. Si tsocks doit se connecter à une machine via un serveur SOCKS (c'est-à-dire que ce n'est pas un réseau déclaré comme 'local') et qu'aucun 'path' n'a déclaré pouvoir atteindre ce réseau via une directive 'reaches', ce serveur est utilisé pour négocier la connexion.

SYNTAXE DE LA CONFIGURATION

La structure de base de toutes les lignes du fichier de configuration est :

<directive> = <paramètres>

L'exception à cette règle concerne les blocs 'path' qui ressemblent à ceci :

path {
<directive> = <paramètres>
}

Les lignes vides sont ignorées et toute entrée sur une ligne après un caractère '#' est ignorée.

DIRECTIVES

Les directives suivantes sont utilisées dans le fichier de configuration tsocks :

serveur
L'adresse IP du serveur SOCKS (par exemple, "server = 10.1.4.253"). Un seul serveur peut être spécifié par bloc path, ou un en dehors d'un bloc path (pour définir le serveur par défaut). Sauf si --disable-hostnames a été spécifié lors de la compilation, le serveur peut être spécifié sous forme de nom d'hôte (par exemple, "server = socks.nec.com").
port_serveur
Le port sur lequel le serveur SOCKS reçoit les requêtes. Un seul port_serveur peut être spécifié par bloc path, ou un en dehors d'un bloc path (pour le serveur par défaut). Cette directive n'est pas requise si le serveur est sur le port standard (1080).
type_serveur
Version SOCKS utilisée par le serveur. Les versions 4 et 5 sont prises en charge (mais uniquement pour l'opération connect). La valeur par défaut est 4. Un seul type_serveur peut être spécifié par bloc path, ou un en dehors d'un bloc path (pour le serveur par défaut).

Vous pouvez utiliser l'utilitaire inspectsocks pour déterminer le type de serveur, voir la section 'UTILITAIRES' plus loin dans cette page de manuel.

utilisateur_par_defaut
Ceci spécifie l'utilisateur par défaut à utiliser pour l'authentification par nom d'utilisateur et mot de passe dans la version 5 de SOCKS. Afin de déterminer le nom d'utilisateur à utiliser (si le serveur socks nécessite une authentification par nom d'utilisateur et mot de passe), tsocks recherche d'abord la variable d'environnement TSOCKS_USERNAME, puis cherche cette option de configuration, puis essaie d'obtenir le nom d'utilisateur local. Cette option n'est pas valide pour les serveurs SOCKS version 4. Un seul utilisateur_par_defaut peut être spécifié par bloc path, ou un en dehors d'un bloc path (pour le serveur par défaut).
mot_de_passe_par_defaut
Ceci spécifie le mot de passe par défaut à utiliser pour l'authentification par nom d'utilisateur et mot de passe dans la version 5 de SOCKS. Afin de déterminer le mot de passe à utiliser (si le serveur socks nécessite une authentification par nom d'utilisateur et mot de passe), tsocks recherche d'abord la variable d'environnement TSOCKS_PASSWORD, puis cherche cette option de configuration. Cette option n'est pas valide pour les serveurs SOCKS version 4. Un seul mot_de_passe_par_defaut peut être spécifié par bloc path, ou un en dehors d'un bloc path (pour le serveur par défaut).
local
Une paire IP/Sous-réseau spécifiant un réseau accessible directement sans redirection via un serveur SOCKS (par exemple, "local = 10.0.0.0/255.0.0.0"). Évidemment, toutes les adresses IP des serveurs SOCKS doivent se trouver dans des réseaux spécifiés comme locaux, sinon tsocks aurait besoin d'un serveur SOCKS pour atteindre les serveurs SOCKS.
atteint
Cette directive n'est valide qu'à l'intérieur d'un bloc path. Son paramètre est formé comme IP[:port_début-port_fin]/Sous-réseau et spécifie un réseau (et une plage de ports sur ce réseau) accessible par le serveur SOCKS spécifié dans ce bloc path. Par exemple, dans un bloc path, "reaches = 150.0.0.0:80-1024/255.0.0.0" indique à tsocks que le serveur SOCKS spécifié dans le bloc path actuel doit être utilisé pour accéder à toute IP dans la plage 150.0.0.0 à 150.255.255.255 lorsque la requête de connexion concerne les ports 80-1024.

UTILITAIRES

tsocks est livré avec deux utilitaires qui peuvent être utiles pour créer et vérifier le fichier de configuration tsocks.

inspectsocks
inspectsocks peut être utilisé pour déterminer la version SOCKS supportée par un serveur. Inspectsocks prend comme arguments l'adresse IP/nom d'hôte du serveur SOCKS et éventuellement le numéro de port pour socks (par exemple, 'inspectsocks socks.nec.com 1080'). Il inspecte ensuite ce serveur pour tenter de déterminer la version qu'il supporte.
validateconf
validateconf peut être utilisé pour vérifier le fichier de configuration. Il vérifie le format du fichier ainsi que son contenu pour d'éventuelles erreurs. Après avoir lu le fichier, il affiche la configuration à l'écran d'une manière formatée et lisible. Ceci peut être extrêmement utile pour déboguer des problèmes.

validateconf peut lire un fichier de configuration à un emplacement différent de celui spécifié lors de la compilation avec l'option de ligne de commande -f <nom_fichier>.

Normalement, validateconf affiche simplement la configuration lue à l'écran (dans un format agréable et lisible), mais il dispose également d'un mode 'test' utile. Lorsqu'il reçoit un nom d'hôte/IP sur la ligne de commande comme -t <nom_hôte/ip>, validateconf détermine lequel des serveurs SOCKS spécifiés dans le fichier de configuration serait utilisé par tsocks pour accéder à l'hôte spécifié.

tsocks.conf(5)

NOM

tsocks.conf - Fichier de configuration pour tsocks

APERÇU

Le fichier tsocks.conf est utilisé par le programme tsocks pour déterminer comment et quand rediriger le trafic réseau via un proxy SOCKS. Il permet de définir des règles pour des applications spécifiques ou des hôtes cibles.

SYNTAXE DE CONFIGURATION

Le fichier de configuration est divisé en sections et utilise une syntaxe clé-valeur.

local <adresse_ip>/<masque>
Définit les adresses IP locales qui ne doivent pas être redirigées.
remote <adresse_ip>/<masque>
Définit les adresses IP distantes qui doivent être redirigées.
server <adresse_ip_proxy> [<port_proxy>]
Définit l'adresse IP et le port du serveur proxy SOCKS.
server_type [1|2|3]
Définit le type de serveur proxy SOCKS (1 pour SOCKS4, 2 pour SOCKS5, 3 pour SOCKS5 avec authentification).
user <nom_utilisateur>
Nom d'utilisateur pour l'authentification SOCKS5.
password <mot_de_passe>
Mot de passe pour l'authentification SOCKS5.
redirect_to <adresse_ip>
Redirige le trafic vers une adresse IP spécifique (utile pour les systèmes avec plusieurs interfaces réseau).
connect
Active la redirection pour les connexions sortantes.
listen
Active la redirection pour les connexions entrantes.

Les commentaires commencent par un caractère dièse (#).

UTILITAIRES

tsocks est l'utilitaire principal qui utilise ce fichier de configuration. Il peut être utilisé pour lancer des applications et rediriger leur trafic réseau via le proxy.

tsocks <commande>
