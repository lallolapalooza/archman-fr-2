tset(1) Commandes utilisateur tset(1)

NOM

tset, reset - initialiser ou réinitialiser l'état du terminal

SYNTAXE

tset [-IQVcqrsw] [-] [-e car] [-i car] [-k car] [-m mapping] [type-terminal]
reset [-IQVcqrsw] [-] [-e car] [-i car] [-k car] [-m mapping] [type-terminal]

DESCRIPTION

tset — initialisation

Ce programme initialise les terminaux.

Premièrement, tset récupère les paramètres actuels du mode terminal de votre terminal. Il fait cela en testant successivement

  • le descripteur d'erreur standard,
  • la sortie standard,
  • l'entrée standard et
  • en dernier recours “/dev/tty”

pour obtenir les paramètres du terminal. Ayant récupéré ces paramètres, tset se souvient quel descripteur de fichier utiliser lors de la mise à jour des paramètres.

Ensuite, tset détermine le type de terminal que vous utilisez. Cette détermination est faite comme suit, en utilisant le premier type de terminal trouvé.

1. L'argument terminal spécifié sur la ligne de commande.

2. La valeur de la variable d'environnement TERM.

3. (Systèmes BSD uniquement.) Le type de terminal associé au périphérique de sortie d'erreur standard dans le fichier /etc/ttys. (Sur les hôtes System V et les systèmes utilisant cette convention, getty(8) fait ce travail en définissant TERM selon le type qui lui est passé par /etc/inittab.)

4. Le type de terminal par défaut, “unknown”, n'est pas adapté aux applications curses.

Si le type de terminal n'a pas été spécifié sur la ligne de commande, les mappings de l'option -m sont appliqués ; voir la sous-section “Mapping des types de terminaux”. Ensuite, si le type de terminal commence par un point d'interrogation (“?”), l'utilisateur est invité à confirmer le type de terminal. Une réponse vide confirme le type, ou un autre type peut être entré pour spécifier un nouveau type. Une fois le type de terminal déterminé, la description du terminal est récupérée. Si aucune description de terminal n'est trouvée pour ce type, l'utilisateur est invité à fournir un autre type de terminal.

Une fois la description du terminal récupérée,

•
si l'option “-w” est activée, tset peut mettre à jour la taille de la fenêtre du terminal.
Si la taille de la fenêtre ne peut pas être obtenue du système d'exploitation, mais que la description du terminal (ou l'environnement, par exemple, les variables LINES et COLUMNS le spécifient), utilisez ceci pour définir la notion de taille de fenêtre du système d'exploitation.
  • si l'option “-c” est activée, les caractères d'effacement, d'interruption et d'annulation de ligne (entre autres choses) sont définis
  • sauf si l'option “-I” est activée, les chaînes d'initialisation du terminal et des tabulations sont envoyées à la sortie d'erreur standard, et tset attend une seconde (au cas où une réinitialisation matérielle aurait été effectuée).
  • Enfin, si les caractères d'effacement, d'interruption et d'annulation de ligne ont changé, ou ne sont pas définis à leurs valeurs par défaut, leurs valeurs sont affichées sur la sortie d'erreur standard.

reset — réinitialisation

Lorsqu'il est appelé en tant que reset, tset définit les modes du terminal à des valeurs “saines” :

  • définit les modes cook et echo,
  • désactive les modes cbreak et raw,
  • active la traduction de nouvelle ligne et
  • réinitialise tous les caractères spéciaux non définis à leurs valeurs par défaut

avant d'effectuer l'initialisation du terminal décrite ci-dessus. De plus, plutôt que d'utiliser les chaînes d'initialisation du terminal, il utilise les chaînes de réinitialisation du terminal.

La commande reset est utile après qu'un programme est mort en laissant un terminal dans un état anormal :

  • vous devrez peut-être taper


    <LF>reset<LF>

    (le caractère de saut de ligne est normalement Control-J) pour que le terminal fonctionne, car le retour chariot peut ne plus fonctionner dans l'état anormal.

  • De plus, le terminal n'affichera souvent pas la commande.

Définition de l'environnement

Il est souvent souhaitable d'entrer le type de terminal et les informations sur les capacités du terminal dans l'environnement du shell. Ceci est fait en utilisant l'option -s.

Lorsque l'option -s est spécifiée, les commandes pour entrer les informations dans l'environnement du shell sont écrites sur la sortie standard. Si la variable d'environnement SHELL se termine par “csh”, les commandes sont pour csh(1), sinon, elles sont pour sh(1). Les commandes csh définissent et désactivent la variable shell noglob, la laissant désactivée. La ligne suivante dans les fichiers .login ou .profile initialisera correctement l'environnement :


eval `tset -s options ... `

Mapping des types de terminaux

Lorsque le terminal n'est pas intégré au système (ou que les informations système actuelles sont incorrectes), le type de terminal dérivé du fichier /etc/ttys ou de la variable d'environnement TERM est souvent quelque chose de générique comme network, dialup, ou unknown. Lorsque tset est utilisé dans un script de démarrage, il est souvent souhaitable de fournir des informations sur le type de terminal utilisé sur de tels ports.

L'option -m mappe un ensemble de conditions à un type de terminal, c'est-à-dire, dire à tset “Si je suis sur ce port à une vitesse particulière, suppose que je suis sur ce type de terminal”.

L'argument de l'option -m se compose d'un type de port optionnel, d'un opérateur optionnel, d'une spécification de vitesse en bauds optionnelle, d'un caractère deux-points (“:”) optionnel et d'un type de terminal. Le type de port est une chaîne (délimitée par l'opérateur ou le caractère deux-points). L'opérateur peut être n'importe quelle combinaison de “>”, “<”, “@”, et “!”; “>” signifie supérieur à, “<” signifie inférieur à, “@” signifie égal à et “!” inverse le sens du test. La vitesse en bauds est spécifiée comme un nombre et est comparée à la vitesse de la sortie d'erreur standard (qui devrait être le terminal de contrôle). Le type de terminal est une chaîne.

Si le type de terminal n'est pas spécifié sur la ligne de commande, les mappings -m sont appliqués au type de terminal. Si le type de port et la vitesse en bauds correspondent au mapping, le type de terminal spécifié dans le mapping remplace le type courant. Si plus d'un mapping est spécifié, le premier mapping applicable est utilisé.

Par exemple, considérez le mapping suivant : dialup>9600:vt100. Le type de port est dialup, l'opérateur est >, la spécification de vitesse en bauds est 9600, et le type de terminal est vt100. Le résultat de ce mapping est de spécifier que si le type de terminal est dialup, et que la vitesse en bauds est supérieure à 9600 bauds, un type de terminal vt100 sera utilisé.

Si aucune vitesse en bauds n'est spécifiée, le type de terminal correspondra à n'importe quelle vitesse en bauds. Si aucun type de port n'est spécifié, le type de terminal correspondra à n'importe quel type de port. Par exemple, -m dialup:vt100 -m :?xterm fera en sorte que n'importe quel port dialup, quelle que soit sa vitesse en bauds, corresponde au type de terminal vt100, et n'importe quel type de port non-dialup corresponde au type de terminal ?xterm. Notez qu'en raison du point d'interrogation initial, l'utilisateur sera interrogé sur un port par défaut quant à savoir s'il utilise réellement un terminal xterm.

Aucun espace blanc n'est autorisé dans l'argument de l'option -m. De plus, pour éviter les problèmes avec les méta-caractères, il est suggéré de placer l'argument entier de l'option -m entre guillemets simples, et que les utilisateurs de csh insèrent une barre oblique inverse (“\”) avant tout point d'exclamation (“!”).

OPTIONS

Les options sont les suivantes :

-c
Définit les caractères et modes de contrôle.
-e car
Définit le caractère d'effacement à car.
>
Définit le caractère d'effacement à ch.
-I
N'envoie pas les chaînes d'initialisation du terminal ou de tabulation au terminal.
-i ch
Définit le caractère d'interruption à ch.
-k ch
Définit le caractère d'annulation de ligne à ch.
-m mapping
Spécifie une correspondance entre un type de port et un terminal ; voir la sous-section « Correspondance des types de terminaux ».
-Q
N'affiche aucune valeur pour les caractères d'effacement, d'interruption et d'annulation de ligne. Normalement, tset affiche les valeurs des caractères de contrôle qui diffèrent des valeurs par défaut du système.
-q
Le type de terminal est affiché sur la sortie standard et le terminal n'est initialisé d'aucune manière. L'option « - » seule est équivalente mais archaïque.
-r
Affiche le type de terminal sur la sortie d'erreur standard.
-s
Affiche la séquence de commandes shell pour initialiser la variable d'environnement TERM sur la sortie standard ; voir la sous-section « Définition de l'environnement ».
-V
rapporte la version de ncurses qui a été utilisée dans ce programme, et se termine.
-w
Redimensionne la fenêtre pour correspondre à la taille déduite via setupterm(3X). Normalement, cela n'a aucun effet, sauf si setupterm n'est pas capable de détecter la taille de la fenêtre.

Les arguments des options -e, -i et -k peuvent être saisis sous forme de caractères réels ou en utilisant la notation « chapeau », c'est-à-dire que control-h peut être spécifié sous forme « ^H » ou « ^h ».

Si ni -c ni -w n'est donné, les deux options sont supposées.

ENVIRONNEMENT

La commande tset utilise les variables d'environnement suivantes :

SHELL
indique à tset s'il faut initialiser TERM en utilisant la syntaxe sh(1) ou csh(1).
TERM
Désigne le type de votre terminal. Chaque type de terminal est distinct, bien que beaucoup soient similaires.
TERMCAP
peut désigner l'emplacement d'une base de données termcap. S'il ne s'agit pas d'un chemin absolu, par exemple, s'il commence par un « / », tset supprime la variable de l'environnement avant de rechercher la description du terminal.

FICHIERS

/etc/ttys
base de données de correspondance entre le nom du port système et le type de terminal (versions BSD uniquement).
/usr/share/terminfo
répertoire de la base de données des descriptions de terminaux compilées

PORTABILITE

Ni IEEE Std 1003.1/The Open Group Base Specifications Issue 7 (POSIX.1-2008) ni X/Open Curses Issue 7 ne documentent tset ou reset.

L'utilitaire AT&T tput (AIX, HP-UX, Solaris) a intégré la manipulation des modes de terminaux ainsi que des fonctionnalités basées sur tercap telles que la réinitialisation des tabulations depuis tset sous BSD (4.1c), probablement dans le but de rendre tset obsolète. Cependant, chacun de ces systèmes fournit toujours tset. En fait, l'utilitaire couramment utilisé reset est toujours un alias pour tset.

L'utilitaire tset assure la compatibilité descendante avec les environnements BSD ; sous la plupart des Unix modernes, /etc/inittab et getty(8) peuvent définir TERM de manière appropriée pour chaque ligne de télécopie, évitant ainsi ce qui était l'utilisation la plus importante de tset. Cette implémentation se comporte comme le tset de 4.4BSD, à quelques exceptions près que nous allons examiner maintenant.

Quelques options sont différentes car la variable TERMCAP n'est plus prise en charge sous ncurses basé sur terminfo :

  • L'option -S du tset de BSD ne fonctionne plus ; elle affiche un message d'erreur sur la sortie d'erreur et se termine.
  • L'option -s ne définit que TERM, pas TERMCAP.

Il existait une fonctionnalité non documentée de 4.4BSD qui, en invoquant tset via un lien nommé « TSET » (ou via tout autre nom commençant par une lettre majuscule), configurait le terminal pour utiliser uniquement les majuscules. Cette fonctionnalité a été omise.

Les options -A, -E, -h, -u et -v ont été supprimées de l'utilitaire tset dans 4.4BSD. Aucune d'entre elles n'était documentée dans 4.3BSD et toutes ont une utilité limitée au mieux. Les options -a, -d et -p ne sont pas non plus documentées ou utiles, mais ont été conservées car elles semblent être largement utilisées. Il est fortement recommandé que toute utilisation de ces trois options soit remplacée par l'option -m. Les options -a, -d et -p sont donc omises du résumé d'utilisation ci-dessus.

Les systèmes très anciens, par exemple 3BSD, utilisaient un pilote de terminal différent qui a été remplacé dans 4BSD au début des années 1980. Pour prendre en charge ces systèmes plus anciens, le tset de 4BSD fournissait une option -n pour spécifier que le nouveau pilote de terminal devait être utilisé. Cette implémentation ne fournit pas ce choix.

Il est toujours permis de spécifier les options -e, -i et -k sans arguments, bien qu'il soit fortement recommandé de corriger une telle utilisation pour spécifier explicitement le caractère.

Depuis 4.4BSD, l'exécution de tset en tant que reset n'implique plus l'option -Q. De plus, l'interaction entre l'option - et l'argument terminal dans certaines implémentations historiques de tset a été supprimée.

Les options -c et -w ne se trouvent pas dans les implémentations antérieures. Cependant, une fonctionnalité différente de changement de taille de fenêtre était fournie dans 4.4BSD.

  • Dans 4.4BSD, tset utilise la taille de la fenêtre de la description tercap pour définir la taille de la fenêtre si tset ne peut pas obtenir la taille de la fenêtre du système d'exploitation.
  • Dans ncurses, tset obtient la taille de la fenêtre en utilisant setupterm(3X), qui peut provenir du système d'exploitation, des variables d'environnement LINES et COLUMNS ou de la description du terminal.

L'obtention de la taille de la fenêtre à partir de la description du type d'un terminal est commune aux deux implémentations, mais considérée comme obsolète. Sa seule utilité pratique concerne les terminaux matériels. Généralement, la taille de la fenêtre restera non initialisée seulement s'il y a eu un problème pour obtenir la valeur du système d'exploitation (et setupterm échouerait toujours). Les variables d'environnement LINES et COLUMNS peuvent donc être utiles pour contourner les problèmes de taille de fenêtre, mais elles présentent l'inconvénient que si la fenêtre est redimensionnée, leurs valeurs doivent être recalculées et réattribuées. Le programme resize(1) distribué avec xterm(1) facilite cette activité.

HISTORIQUE

Une commande reset écrite par Kurt Shoens est apparue dans 1BSD (mars 1978). Elle définissait les caractères erase et kill à ^H (retour arrière) et @ respectivement. Mark Horton a amélioré ce reset dans 3BSD (octobre 1979), ajoutant les caractères intr, quit, start/stop et eof, ainsi que la modification du programme pour éviter de modifier les paramètres de l'utilisateur. Cette version de reset n'utilisait pas termcap.

Eric Allman a écrit une commande tset distincte pour 1BSD, utilisant un précurseur de termcap appelé ttycap. Les commentaires d'Allman dans le code source indiquent qu'il a commencé le travail en octobre 1977, continuant le développement pendant les quelques années suivantes. Fin 1979, il avait migré vers termcap et gérait la variable TERMCAP. Des commentaires ultérieurs indiquent que tset a été modifié en septembre 1980 pour utiliser une logique copiée du programme « reset » de 3BSD lorsqu'il était invoqué comme reset. Cette version est apparue dans 4.1cBSD, fin 1982. D'autres développeurs tels que Keith Bostic et Jim Bloom ont continué à modifier tset jusqu'à la sortie de 4.4BSD en 1993.

L'implémentation ncurses a été légèrement adaptée des sources de 4.4BSD pour utiliser l'API terminfo par Eric S. Raymond <esr@snark.thyrsus.com>.

tset(1) - Manuel Arch Linux

DESCRIPTION

Initialise le terminal.

OPTIONS

tset utilise par défaut le fichier `~/.termcap` pour déterminer les capacités du terminal. Si cela n'existe pas, il utilise la variable d'environnement `$TERM` pour trouver une entrée dans la base de données termcap.

Si aucune de ces méthodes ne fonctionne, tset tente d'utiliser les valeurs par défaut du système.

L'option `-e` permet de spécifier un caractère d'effacement. Par exemple, `tset -e '\017'` utilise le caractère Ctrl-O comme caractère d'effacement.

L'option `-i` permet de spécifier un caractère de suppression de ligne. Par exemple, `tset -i '\025'` utilise le caractère Ctrl-U comme caractère de suppression de ligne.

L'option `-s` permet de rendre la sortie de tset compatible avec le shell.

L'option `-m TERM` permet de spécifier le type de terminal. Par exemple, `tset -m vt100` force le type de terminal à être `vt100`.

EXEMPLES

Pour initialiser le terminal avec les paramètres par défaut du système et rendre la sortie compatible avec le shell:

tset -s

Pour initialiser le terminal en spécifiant le type `xterm` et rendre la sortie compatible avec le shell:

tset -s -m xterm
