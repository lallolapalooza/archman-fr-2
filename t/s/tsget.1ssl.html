NOM

tsget - Client HTTP/HTTPS d'horodatage

SYNTAXE

tsget -h url_serveur [-e extension] [-o sortie] [-v] [-d] [-k cle_privee.pem] [-p mot_de_passe_cle] [-c cert_client.pem] [-C certs_CA.pem] [-P chemin_CA] [-r fichiers] [-g socket_EGD] [requete ...]

DESCRIPTION

Cette commande peut être utilisée pour envoyer une requête d'horodatage, telle que spécifiée dans la RFC 3161, à un serveur d'horodatage via HTTP ou HTTPS et pour stocker la réponse d'horodatage dans un fichier. Elle ne peut pas être utilisée pour créer les requêtes et vérifier les réponses, vous devez utiliser openssl-ts(1) pour cela. Cette commande peut envoyer plusieurs requêtes au serveur sans fermer la connexion TCP si plusieurs requêtes sont spécifiées sur la ligne de commande.

Cette commande envoie la requête HTTP suivante pour chaque requête d'horodatage :

POST url HTTP/1.1
User-Agent: OpenTSA tsget.pl/<version>
Host: <hote>:<port>
Pragma: no-cache
Content-Type: application/timestamp-query
Accept: application/timestamp-reply
Content-Length: longueur du corps
...requête binaire spécifiée par l'utilisateur...

Elle attend une réponse de type application/timestamp-reply, qui est écrite dans un fichier sans aucune interprétation.

OPTIONS

-h url_serveur
L'URL du serveur HTTP/HTTPS écoutant les requêtes d'horodatage.
-e extension
Si l'option -o n'est pas donnée, cet argument spécifie l'extension des fichiers de sortie. Le nom de base du fichier de sortie sera le même que celui des fichiers d'entrée. L'extension par défaut est .tsr. (Optionnel)
-o sortie
Cette option ne peut être spécifiée que lorsqu'une seule requête est envoyée au serveur. La réponse d'horodatage sera écrite dans le fichier de sortie spécifié. '-' signifie la sortie standard. En cas de requêtes d'horodatage multiples ou d'absence de cet argument, les noms des fichiers de sortie seront dérivés des noms des fichiers d'entrée et de l'argument d'extension par défaut ou spécifié. (Optionnel)
-v
Le nom de la requête actuellement traitée est affiché sur la sortie d'erreur standard. (Optionnel)
-d
Active le mode verbeux pour le module sous-jacent Perl WWW::Curl::Easy. Vous pouvez voir des messages de débogage détaillés pour la connexion. (Optionnel)
-k cle_privee.pem
(HTTPS) En cas d'authentification client basée sur un certificat via HTTPS, cle_privee.pem doit contenir la clé privée de l'utilisateur. Le fichier de clé privée peut éventuellement être protégé par une phrase secrète. L'option -c doit également être spécifiée. (Optionnel)
-p mot_de_passe_cle
(HTTPS) Spécifie la phrase secrète pour la clé privée spécifiée par l'argument -k. Si cette option est omise et que la clé est protégée par une phrase secrète, il sera demandé de la saisir. (Optionnel)
-c cert_client.pem
(HTTPS) En cas d'authentification client basée sur un certificat via HTTPS, cert_client.pem doit contenir le certificat X.509 de l'utilisateur. L'option -k doit également être spécifiée. Si cette option n'est pas spécifiée, aucune authentification client basée sur un certificat n'aura lieu. (Optionnel)
-C certs_CA.pem
(HTTPS) Le magasin de certificats CA de confiance. La chaîne de certificats du certificat du pair doit inclure l'un des certificats CA spécifiés dans ce fichier. L'option -C ou l'option -P doit être donnée dans le cas de HTTPS. (Optionnel)
-P chemin_CA
(HTTPS) Le chemin contenant les certificats CA de confiance pour vérifier le certificat du pair. Le répertoire doit être préparé avec openssl-rehash(1). L'option -C ou l'option -P doit être donnée dans le cas de HTTPS. (Optionnel)
-r fichiers
Voir "Options d'état aléatoire" dans openssl(1) pour plus d'informations.
-g socket_EGD
Le nom d'un socket EGD pour obtenir des données aléatoires. (Optionnel)
requete ...
Liste des fichiers contenant des requêtes d'horodatage encodées en DER selon la RFC 3161. Si aucune requête n'est spécifiée, une seule requête sera envoyée au serveur et elle sera lue depuis l'entrée standard. (Optionnel)

VARIABLES D'ENVIRONNEMENT

La variable d'environnement TSGET peut éventuellement contenir des arguments par défaut. Le contenu de cette variable est ajouté à la liste des arguments de la ligne de commande.

EXEMPLES

Les exemples ci-dessous supposent que file1.tsq et file2.tsq contiennent des requêtes d'horodatage valides, que tsa.opentsa.org écoute sur le port 8080 pour les requêtes HTTP et sur le port 8443 pour les requêtes HTTPS, et que le service TSA est disponible au chemin absolu /tsa.

Obtenir une réponse d'horodatage pour file1.tsq via HTTP, la sortie est écrite dans file1.tsr :

tsget -h http://tsa.opentsa.org:8080/tsa file1.tsq

Obtenir une réponse d'horodatage pour file1.tsq et file2.tsq via HTTP en affichant la progression, la sortie est écrite respectivement dans file1.reply et file2.reply :

tsget -h http://tsa.opentsa.org:8080/tsa -v -e .reply \
      file1.tsq file2.tsq

Créer une requête d'horodatage, l'écrire dans file3.tsq, l'envoyer au serveur et écrire la réponse dans file3.tsr :

openssl ts -query -data file3.txt -cert | tee file3.tsq \
      | tsget -h http://tsa.opentsa.org:8080/tsa \
      -o file3.tsr

Obtenir une réponse d'horodatage pour file1.tsq via HTTPS sans authentification client :

tsget -h https://tsa.opentsa.org:8443/tsa \
      -C cacerts.pem file1.tsq

Obtenir une réponse d'horodatage pour file1.tsq via HTTPS avec authentification client basée sur un certificat (il demandera la phrase secrète si client_key.pem est protégé) :

tsget -h https://tsa.opentsa.org:8443/tsa -C cacerts.pem \
      -k client_key.pem -c client_cert.pem file1.tsq

Vous pouvez raccourcir la ligne de commande précédente si vous utilisez la variable d'environnement TSGET. Les commandes suivantes font la même chose que l'exemple précédent :

TSGET='-h https://tsa.opentsa.org:8443/tsa -C cacerts.pem \
      -k client_key.pem -c client_cert.pem'
export TSGET
tsget file1.tsq
