NOM

tsv - Fait partie de l'extension de threading Tcl permettant la manipulation au niveau du script de données partagées entre threads.

DESCRIPTION

Cette section décrit les commandes implémentant les variables partagées entre threads. Une variable partagée entre threads est très similaire à un tableau Tcl, mais contrairement à un tableau Tcl, elle est créée dans la mémoire partagée et peut être accédée par plusieurs threads simultanément. Une caractéristique importante des variables partagées entre threads est que chaque accès à la variable est protégé en interne par un mutex, de sorte que le programmeur de script n'a pas à s'occuper du verrouillage de la variable lui-même.

Les variables partagées entre threads ne sont liées à aucun thread explicitement. Cela signifie que lorsqu'un thread qui a créé l'une des variables partagées entre threads se termine, la variable et la mémoire associée ne sont pas désaffectées/récupérées. L'utilisateur doit explicitement désaffecter la variable pour récupérer la mémoire consommée par la variable.

COMMANDES ÉLÉMENTS

tsv::names ?pattern?
Retourne les noms des variables partagées correspondant au ?pattern? optionnel ou toutes les variables connues si le motif est omis.
tsv::object varname element
Crée une commande d'accès à l'objet pour l'élément dans la variable partagée varname. En utilisant cette commande, on peut appliquer la plupart des autres commandes de variables partagées comme des fonctions méthodes de la commande d'objet élément. La commande objet est automatiquement supprimée lorsque l'élément auquel cette commande pointe est désaffecté.
    % tsv::set foo bar "Une chaîne partagée"
    % set string [tsv::object foo bar]
    % $string append " ajoutée"
    => Une chaîne partagée ajoutée
tsv::set varname element ?value?
Définit la valeur de l'élément dans la variable partagée varname à value et retourne la valeur à l'appelant. La value peut être omise, auquel cas la commande retournera la valeur actuelle de l'élément. Si l'élément ne peut être trouvé, une erreur est déclenchée.
tsv::get varname element ?namedvar?
Récupère la valeur de l'élément de la variable partagée varname. Si l'argument optionnel namedvar est donné, la valeur est stockée dans la variable nommée. La valeur de retour de la commande dépend de l'existence de l'argument optionnel namedvar. Si l'argument est omis et que l'élément demandé ne peut être trouvé dans le tableau partagé, la commande déclenche une erreur. Si, cependant, l'argument optionnel est donné dans la ligne de commande, la commande retourne vrai (1) si l'élément est trouvé ou faux (0) si l'élément n'est pas trouvé.
tsv::unset varname ?element?
Désaffecte l'élément de la variable partagée varname. Si l'élément optionnel n'est pas donné, il supprime la variable.
tsv::exists varname element
Vérifie si l'élément existe dans la variable partagée varname et retourne vrai (1) s'il existe ou faux (0) s'il n'existe pas.
tsv::pop varname element
Retourne la valeur de l'élément dans la variable partagée varname et désaffecte l'élément, le tout en une seule opération atomique.
tsv::move varname oldname newname
Renomme l'élément oldname en newname dans la variable partagée varname. Ceci effectue efficacement une séquence d'opérations get/unset/set, mais tout en une seule étape atomique.
tsv::incr varname element ?count?
Similaire à la commande Tcl standard incr, mais incrémente la valeur de l'élément dans la variable partagée varname au lieu de la variable Tcl.
tsv::append varname element value ?value ...?
Similaire à la commande Tcl standard append, mais ajoute une ou plusieurs valeurs à l'élément dans la variable partagée varname au lieu de la variable Tcl.
tsv::lock varname arg ?arg ...?
Cette commande concatène les arguments passés et évalue le script résultant sous la protection interne d'un mutex. Pendant l'évaluation du script, la variable partagée entière est verrouillée. Pour les commandes de variables partagées dans le script, le verrouillage interne est désactivé afin qu'aucun interblocage ne puisse se produire. Il est également permis de désaffecter la variable partagée depuis l'intérieur du script. La variable partagée est automatiquement créée si elle n'existait pas au moment de la première opération de verrouillage.
    % tsv::lock foo {
        tsv::lappend foo bar 1
        tsv::lappend foo bar 2
        puts stderr [tsv::set foo bar]
        tsv::unset foo
    }
tsv::handlers
Retourne les noms de tous les gestionnaires de stockage persistant activés au moment de la compilation. Voir COMMANDES ARRAY pour plus de détails.

COMMANDES LISTE

Ces commandes sont similaires aux commandes Tcl de nom équivalent. La différence est qu'elles opèrent sur des éléments de tableaux partagés.

tsv::lappend varname element value ?value ...?
Similaire à la commande Tcl standard lappend, mais ajoute une ou plusieurs valeurs à l'élément dans la variable partagée varname au lieu de la variable Tcl.
tsv::linsert varname element index va
Similaire à la commande Tcl standard linsert, mais insère une ou plusieurs valeurs dans l'élément element de la variable partagée varname à l'index spécifié.
tsv::lreplace varname element first last ?value ...?
Similaire à la commande Tcl standard lreplace, mais remplace les éléments entre first et last de l'élément element de la variable partagée varname par les nouvelles value.
tsv::llength varname element
Retourne la longueur (nombre d'éléments) de la liste contenue dans l'élément element de la variable partagée varname.
tsv::lindex varname element ?index?
Retourne l'élément à l'index spécifié dans la liste contenue dans l'élément element de la variable partagée varname. Si aucun index n'est spécifié, retourne toute la liste.
tsv::lrange varname element from to
Retourne une sous-liste des éléments compris entre l'index from et l'index to (inclus) de la liste contenue dans l'élément element de la variable partagée varname.
tsv::lsearch varname element ?options? pattern
Recherche dans la liste contenue dans l'élément element de la variable partagée varname les éléments correspondant au pattern. Les options possibles sont : -exact, -glob, -regexp, -integer, -real, -forall.
tsv::lset varname element index ?index ...? value
Définit la valeur de l'élément à l'index spécifié (ou plusieurs niveaux d'index pour des listes imbriquées) dans la liste contenue dans l'élément element de la variable partagée varname à la nouvelle value.
tsv::lpop varname element ?index?
Supprime et retourne l'élément à l'index spécifié (le dernier par défaut) dans la liste contenue dans l'élément element de la variable partagée varname.
tsv::lpush varname element ?index?
Insère et retourne l'élément à l'index spécifié (le premier par défaut) dans la liste contenue dans l'élément element de la variable partagée varname.

COMMANDES ARRAY

tsv::array set varname list
Initialise le tableau partagé varname avec les paires clé-valeur contenues dans la list Tcl.
tsv::array get varname ?pattern?
Retourne une liste de paires clé-valeur pour toutes les clés du tableau partagé varname correspondant au pattern optionnel.
tsv::array names varname ?pattern?
Retourne une liste de toutes les clés du tableau partagé varname correspondant au pattern optionnel.
tsv::array size varname
Retourne le nombre d'éléments dans le tableau partagé varname.
tsv::array reset varname list
Supprime toutes les entrées du tableau partagé varname et l'initialise avec les paires clé-valeur contenues dans la list Tcl.
tsv::array bind varname handle
Lie un gestionnaire de stockage persistant (par exemple, un fichier) au tableau partagé varname. Les modifications apportées au tableau seront écrites dans le handle.
tsv::array unbind varname
Désactive la liaison d'un gestionnaire de stockage persistant pour le tableau partagé varname.
tsv::array isbound varname
Retourne vrai (1) si un gestionnaire de stockage persistant est lié au tableau partagé varname, faux (0) sinon.

COMMANDES KEYLIST

Ces commandes permettent de gérer des structures de données imbriquées où les clés sont elles-mêmes des listes.

tsv::keyldel varname keylist key
Supprime l'élément spécifié par key dans la structure imbriquée définie par keylist du tableau partagé varname.
tsv::keylget varname keylist key ?retvar?
Récupère la valeur de l'élément spécifié par key dans la structure imbriquée définie par keylist du tableau partagé varname. Si retvar est spécifié, la valeur est stockée dans cette variable.
tsv::keylkeys varname keylist ?key?
Retourne les clés de la structure imbriquée définie par keylist du tableau partagé varname. Si key est spécifié, retourne les clés de la sous-structure.
tsv::keylset varname keylist key value ?key value..??
Définit la valeur de l'élément spécifié par key dans la structure imbriquée définie par keylist du tableau partagé varname à value. Peut définir plusieurs paires clé-valeur.

Similaire à la commande Tcl standard linsert, mais insère une ou plusieurs valeurs à la position d'indice index dans l'element de la variable partagée varname au lieu de la variable Tcl.
tsv::lreplace varname element first last ?value ...?

tsv::lpush varname element ?index?
Cette commande effectue l'opération inverse de la commande tsv::lpop. Comme son homologue, elle ne retourne aucune valeur à l'appelant.

COMMANDES ARRAY

Cette commande prend en charge la plupart des options de la commande Tcl standard array. En plus de celles-ci, elle permet de lier une variable partagée à des bases de données de stockage persistantes. Actuellement, les options persistantes prises en charge sont les célèbres Gdbm GNU et LMDB. Ces options doivent être sélectionnées lors de la compilation du package. L'implémentation fournit des points d'ancrage pour définir d'autres couches de persistance, si nécessaire.

tsv::array set varname list
Fait la même chose que la commande Tcl standard array set.
tsv::array get varname ?pattern?
Fait la même chose que la commande Tcl standard array get.
tsv::array names varname ?pattern?
Fait la même chose que la commande Tcl standard array names.
tsv::array size varname
Fait la même chose que la commande Tcl standard array size.
tsv::array reset varname list
Fait la même chose que la commande Tcl standard array set, mais elle efface varname et définit de nouvelles valeurs à partir de la liste de manière atomique.
tsv::array bind varname handle
Lie varname au stockage persistant handle. Le format du handle est <handler>:<address>, où <handler> est "gdbm" pour GNU Gdbm et "lmdb" pour LMDB et <address> est le chemin d'accès au fichier de la base de données.
tsv::array unbind varname
Délie le tableau partagé de son stockage persistant lié.
tsv::array isbound varname
Retourne vrai (1) si le nom de variable partagé est lié à un stockage persistant ou zéro (0) sinon.

COMMANDES DE LISTES CLÉS

Les commandes de listes clés sont empruntées au package TclX. Les listes clés fournissent un type de données structuré basé sur des listes Tcl standard. Cette fonctionnalité est similaire aux structures dans le langage de programmation C.

Une liste clé est une liste dans laquelle chaque élément contient une paire clé-valeur. Ces paires d'éléments sont stockées sous forme de listes elles-mêmes, où la clé est le premier élément de la liste et la valeur est le second. Les paires clé-valeur sont appelées champs. Voici un exemple de liste clé :

    {{NAME  {Frank  Zappa}} {JOB {musicien et compositeur}}}
Les champs peuvent contenir des sous-champs ; `.' est le caractère séparateur. Les sous-champs sont en fait des champs dont la valeur est une autre liste clé. Ainsi, la liste suivante a les champs de haut niveau ID et NAME, et les sous-champs NAME.FIRST et NAME.LAST : 
    {ID 106} {NAME {{FIRST Frank} {LAST Zappa}}}
Il n'y a aucune limite à la profondeur récursive des sous-champs, permettant de construire des structures de données complexes. Les listes clés sont construites et accessibles via un certain nombre de commandes. Toutes les commandes de gestion de listes clés prennent le nom de la variable contenant la liste clé comme argument (c'est-à-dire passé par référence), plutôt que de passer la liste directement.
tsv::keyldel varname keylist key
Supprime le champ spécifié par key de la liste clé keylist dans la variable partagée varname. Ceci supprime à la fois la clé et la valeur de la liste clé.
tsv::keylget varname keylist key ?retvar?
Retourne la valeur associée à key à partir de la liste clé keylist dans la variable partagée varname. Si le paramètre optionnel retvar n'est pas spécifié, la valeur sera retournée comme résultat de la commande. Dans ce cas, si la clé n'est pas trouvée dans la liste, une erreur se produira.

Si retvar est spécifié et que key est dans la liste, alors la valeur est retournée dans la variable retvar et la commande retourne 1 si la clé était présente dans la liste. Si key n'est pas dans la liste, la commande retourne 0, et retvar reste inchangé. Si {} est spécifié pour retvar, la valeur n'est pas retournée, permettant au programmeur Tcl de déterminer si une key est présente dans une liste clé sans définir de variable comme effet secondaire.

tsv::keylkeys varname keylist ?key?
Retourne une liste des clés dans la liste clé keylist dans la variable partagée varname. Si key est spécifié, alors c'est le nom d'un champ clé dont les sous-champs clés doivent être récupérés.
tsv::keylset varname keylist key value ?key value..?
Définit la valeur associée à key, dans la liste clé keylist à value. Si la keylist n'existe pas, elle est créée. Si key n'est pas actuellement dans la liste, elle sera ajoutée. Si elle existe déjà, value remplace la valeur existante. Plusieurs mots-clés et valeurs peuvent être spécifiés, si désiré.

DISCUSSION

L'implémentation actuelle des variables partagées par threads permet un accès facile et pratique aux données partagées entre différents threads. En interne, les données sont stockées dans des objets Tcl et toutes les commandes du package opèrent sur la représentation interne des données, minimisant ainsi le scintillement et améliorant les performances. Un soin particulier a été apporté pour garantir que toutes les données des objets soient correctement verrouillées et copiées en profondeur lors du déplacement d'objets entre threads.

En raison de la conception interne du cœur de Tcl, il n'y a malheureusement pas de disposition pour une intégration complète des variables partagées dans la syntaxe Tcl. Tous les accès aux données partagées doivent être effectués avec les commandes du package fournies. De plus, les traces de variables ne sont pas prises en charge. Mais même ainsi, les avantages d'une manipulation des données partagées facile, simple et sûre l'emportent sur les limitations imposées.

CRÉDITS

Les variables partagées par threads sont inspirées par l'interface nsv trouvée dans AOLserver, un serveur Web hautement évolutif d'America Online.
