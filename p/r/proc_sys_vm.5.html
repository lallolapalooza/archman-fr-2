proc_sys_vm(5) Manuel des formats de fichiers proc_sys_vm(5)

NOM

/proc/sys/vm/ - sous-système de mémoire virtuelle

DESCRIPTION

/proc/sys/vm/
Ce répertoire contient des fichiers pour le réglage de la gestion de la mémoire, des tampons et du cache.
/proc/sys/vm/admin_reserve_kbytes (depuis Linux 3.10)
Ce fichier définit la quantité de mémoire libre (en KiB) sur le système qui doit être réservée aux utilisateurs ayant la capacité CAP_SYS_ADMIN.
La valeur par défaut dans ce fichier est le minimum de [3% des pages libres, 8MiB] exprimé en KiB. La valeur par défaut est conçue pour fournir suffisamment de mémoire pour que le superutilisateur puisse se connecter et tuer un processus, si nécessaire, dans le mode de dépassement par défaut 'guess' (c'est-à-dire 0 dans /proc/sys/vm/overcommit_memory).
Les systèmes fonctionnant en mode 'overcommit never' (c'est-à-dire 2 dans /proc/sys/vm/overcommit_memory) devraient augmenter la valeur de ce fichier pour tenir compte de la taille mémoire virtuelle complète des programmes utilisés pour récupérer (par exemple, login(1) ssh(1), et top(1)). Sinon, le superutilisateur pourrait ne pas être en mesure de se connecter pour récupérer le système. Par exemple, sur x86-64, une valeur appropriée est 131072 (128MiB réservés).
Changer la valeur dans ce fichier prend effet chaque fois qu'une application demande de la mémoire.
/proc/sys/vm/compact_memory (depuis Linux 2.6.35)
Lorsque 1 est écrit dans ce fichier, toutes les zones sont compactées de sorte que la mémoire libre soit disponible en blocs contigus dans la mesure du possible. L'effet de cette action peut être vu en examinant /proc/buddyinfo.
Présent uniquement si le noyau a été configuré avec CONFIG_COMPACTION.
/proc/sys/vm/drop_caches (depuis Linux 2.6.16)
Écrire dans ce fichier provoque le nettoyage par le noyau des caches, dentries et inodes en mémoire, rendant cette mémoire libre. Cela peut être utile pour tester la gestion de la mémoire et effectuer des benchmarks de système de fichiers reproductibles. Comme l'écriture dans ce fichier fait perdre les avantages de la mise en cache, cela peut dégrader les performances globales du système.
Pour libérer le pagecache, utilisez :

echo 1 > /proc/sys/vm/drop_caches

Pour libérer les dentries et les inodes, utilisez :

echo 2 > /proc/sys/vm/drop_caches

Pour libérer le pagecache, les dentries et les inodes, utilisez :

echo 3 > /proc/sys/vm/drop_caches

Comme écrire dans ce fichier est une opération non destructive et que les objets modifiés ne peuvent pas être libérés, l'utilisateur doit exécuter sync(1) au préalable.
/proc/sys/vm/hugetlb_shm_group (depuis Linux 2.6.7)
Ce fichier inscriptible contient un identifiant de groupe autorisé à allouer de la mémoire en utilisant des pages énormes (huge pages). Si un processus a un identifiant de groupe de système de fichiers ou un identifiant de groupe supplémentaire qui correspond à cet identifiant de groupe, il peut effectuer des allocations de pages énormes sans détenir la capacité CAP_IPC_LOCK ; voir memfd_create(2), mmap(2), et shmget(2).
/proc/sys/vm/legacy_va_layout (depuis Linux 2.6.9)
Si non nul, cela désactive la nouvelle disposition de mappage mémoire 32 bits ; le noyau utilisera la disposition héritée (2.4) pour tous les processus.
/proc/sys/vm/memory_failure_early_kill (depuis Linux 2.6.32)
Contrôle comment tuer les processus lorsqu'une erreur de mémoire non corrigée (généralement une erreur à 2 bits dans un module de mémoire) qui ne peut pas être gérée par le noyau est détectée en arrière-plan par le matériel. Dans certains cas (comme si la page a toujours une copie valide sur le disque), le noyau gérera l'échec de manière transparente sans affecter les applications. Mais s'il n'y a pas d'autre copie à jour des données, il tuera les processus pour éviter toute propagation de corruption de données.
Le fichier a l'une des valeurs suivantes :
1
Tuer tous les processus qui ont la page corrompue et non rechargeable mappée dès que la corruption est détectée. Notez que cela n'est pas pris en charge pour quelques types de pages, comme les données allouées en interne par le noyau ou le cache d'échange (swap cache), mais cela fonctionne pour la majorité des pages utilisateur.
0
Désmapper la page corrompue de tous les processus et tuer un processus uniquement s'il tente d'accéder à la page.
Le meurtre est effectué en utilisant un signal SIGBUS avec si_code défini sur BUS_MCEERR_AO. Les processus peuvent gérer cela s'ils le souhaitent ; voir sigaction(2) pour plus de détails.
Cette fonctionnalité n'est active que sur les architectures/plateformes avec une gestion avancée des erreurs machine et dépend des capacités matérielles.
Les applications peuvent outrepasser le paramètre memory_failure_early_kill individuellement avec l'opération prctl(2) PR_MCE_KILL.
Présent uniquement si le noyau a été configuré avec CONFIG_MEMORY_FAILURE.
/proc/sys/vm/memory_failure_recovery (depuis Linux 2.6.32)
Activer la récupération des erreurs mémoire (lorsque cela est pris en charge par la plateforme).
1
Tenter la récupération.
0
Paniquer toujours en cas d'échec mémoire.
Présent uniquement si le noyau a été configuré avec CONFIG_MEMORY_FAILURE.
/proc/sys/vm/oom_dump_tasks (depuis Linux 2.6.25)
Active un vidage de toutes les tâches du système (à l'exception des threads du noyau) à produire lorsque le noyau effectue une action OOM-killing. Le vidage inclut les informations suivantes pour chaque tâche (thread, processus) : identifiant du thread, identifiant utilisateur réel, identifiant du groupe de threads (identifiant du processus), taille mémoire virtuelle, taille du jeu résident, CPU sur lequel la tâche est planifiée, score oom_adj (voir la description de /proc/pid/oom_adj) et nom de la commande. Ceci est utile pour déterminer pourquoi le tueur OOM a été invoqué et pour identifier la tâche fautive qui l'a provoqué.
Si cela contient la valeur zéro, ces informations sont supprimées. Sur les systèmes très volumineux avec des milliers de tâches, il peut ne pas être réalisable de vider les informations d'état mémoire de chacune d'elles. De tels systèmes ne devraient pas être contraints de subir une pénalité de performance dans les situations OOM lorsque les informations peuvent ne pas être souhaitées.
Si cela est défini sur une valeur non nulle, ces informations sont affichées chaque fois que le tueur OOM tue effectivement une tâche qui consomme beaucoup de mémoire.
La valeur par défaut est 0.
/proc/sys/vm/oom_kill_allocating_task (depuis Linux 2.6.24)
Active ou désactive le meurtre de la tâche déclenchant l'OOM dans les situations de manque de mémoire (out-of-memory).
Si cela est défini sur zéro, le tueur OOM parcourt toute la liste des tâches et sélectionne une tâche à tuer en fonction d'heuristiques. Cela sélectionne normalement une tâche fautive qui consomme beaucoup de mémoire et qui libère une grande quantité de mémoire lorsqu'elle est tuée.
Si cela est défini sur une valeur non nulle, le tueur OOM tue simplement la tâche qui a déclenché la condition de manque de mémoire. Cela évite un balayage potentiellement coûteux de la liste des tâches.
Si /proc/sys/vm/panic_on_oom est non nul, il a la priorité sur la valeur utilisée dans /proc/sys/vm/oom_kill_allocating_task.
La valeur par défaut est 0.
/proc/sys/vm/overcommit_kbytes (depuis Linux 3.14)
Ce fichier inscriptible offre une alternative à /proc/sys/vm/overcommit_ratio pour contrôler la CommitLimit lorsque /proc/sys/vm/overcommit_memory a la valeur 2. Il permet de spécifier la quantité de mémoire à surallouer (overcommit) comme une valeur absolue (en kB), plutôt qu'en pourcentage, comme c'est le cas avec overcommit_ratio. Cela permet un contrôle plus fin de la CommitLimit sur les systèmes avec de très grandes tailles mémoire.
Seuls overcommit_kbytes ou overcommit_ratio peuvent avoir un effet : si overcommit_kbytes a une valeur non nulle, alors il est utilisé pour calculer la CommitLim
proc_sys_vm.5.fr - Pages de manuel Linux

NOM

proc_sys_vm — informations et paramètres du noyau relatifs à la gestion de la mémoire virtuelle

DESCRIPTION

Les fichiers de ce répertoire sont utilisés pour contrôler divers aspects du comportement de gestion de la mémoire virtuelle du noyau Linux. Les changements apportés à ces fichiers ont un effet immédiat sur le comportement du noyau. Notez que l'écriture dans ces fichiers nécessite généralement des privilèges root.

/proc/sys/vm/admin_reserve_kbytes (depuis Linux 3.10)
Ce fichier spécifie une quantité de mémoire (en KiB) à réserver pour les processus administrateur. Ce mécanisme est destiné à éviter qu'un processus utilisateur ne consomme toute la mémoire disponible, rendant le système instable. Cette valeur n'a d'effet que lorsque /proc/sys/vm/overcommit_memory est réglé sur 2 (mode "overcommit jamais"). Dans ce cas, le système réserve une quantité de mémoire égale à la valeur de admin_reserve_kbytes.
/proc/sys/vm/compact_memory (depuis Linux 2.6.35)
L'écriture de n'importe quelle valeur dans ce fichier déclenche une tentative de défragmentation de la mémoire physique.
/proc/sys/vm/hugetlb_free_kbytes (depuis Linux 2.6.33)
Ce fichier permet de contrôler la quantité de mémoire réservée pour les pages mémoire énormes (Huge Pages) qui est libérée. L'écriture d'une valeur non nulle dans ce fichier libère le nombre spécifié de pages énormes. L'écriture de 0 libère toutes les pages énormes non utilisées. Une valeur maximale peut être définie via /proc/sys/vm/hugetlb_shm_max_leaks.
/proc/sys/vm/overcommit_kbytes (depuis Linux 3.14)
Si ce fichier contient une valeur non nulle, le noyau l'utilise comme limite d'allocation de mémoire virtuelle. La limite d'allocation totale est alors calculée comme la somme de cette valeur et de la mémoire swap totale disponible. Si ce fichier contient une valeur nulle, le noyau utilise la méthode de calcul basée sur overcommit_ratio.

L'écriture dans /proc/sys/vm/overcommit_kbytes entraîne la mise à zéro de la valeur dans /proc/sys/vm/overcommit_ratio et vice-versa.

/proc/sys/vm/overcommit_memory
Ce fichier contient le mode de comptabilité de la mémoire virtuelle du noyau. Les valeurs possibles sont :
0 : overcommit heuristique (c'est la valeur par défaut)
1 : toujours overcommit, jamais de vérification
2 : toujours vérifier, jamais de overcommit
En mode 0, les appels à mmap(2) avec MAP_NORESERVE ne sont pas vérifiés, et la vérification par défaut est très faible, ce qui risque de faire planter un processus par le mécanisme OOM ("OOM-killed").
En mode 1, le noyau fait semblant qu'il y a toujours assez de mémoire, jusqu'à ce que la mémoire vienne à manquer réellement. Un cas d'utilisation pour ce mode est celui des applications de calcul scientifique qui utilisent de grands tableaux dispersés (sparse arrays). Avant Linux 2.6.0, toute valeur non nulle impliquait le mode 1.
En mode 2 (disponible depuis Linux 2.6), l'espace d'adressage virtuel total pouvant être alloué (CommitLimit dans /proc/meminfo) est calculé comme suit :

CommitLimit = (total_RAM - total_huge_TLB) *
	      overcommit_ratio / 100 + total_swap

où :
•
total_RAM est la quantité totale de RAM du système ;
•
total_huge_TLB est la quantité de mémoire réservée pour les pages énormes ;
•
overcommit_ratio est la valeur dans /proc/sys/vm/overcommit_ratio ; et
•
total_swap est la quantité d'espace swap.
Par exemple, sur un système avec 16 Go de RAM physique, 16 Go de swap, aucun espace dédié aux pages énormes et un overcommit_ratio de 50, cette formule donne un CommitLimit de 24 Go.
Depuis Linux 3.14, si la valeur dans /proc/sys/vm/overcommit_kbytes est non nulle, alors CommitLimit est calculé comme suit :

CommitLimit = overcommit_kbytes + total_swap

Voir aussi la description de /proc/sys/vm/admin_reserve_kbytes et /proc/sys/vm/user_reserve_kbytes.
/proc/sys/vm/overcommit_ratio (depuis Linux 2.6.0)
Ce fichier accessible en écriture définit un pourcentage par lequel la mémoire peut être en surallocation (overcommit). La valeur par défaut dans le fichier est 50. Voir la description de /proc/sys/vm/overcommit_memory.
/proc/sys/vm/panic_on_oom (depuis Linux 2.6.18)
Ceci active ou désactive un panic du noyau en cas de situation de manque de mémoire (out-of-memory).
Si ce fichier est réglé sur la valeur 0, le mécanisme OOM-killer du noyau tuera un processus dévoyé. Généralement, l'OOM-killer parvient à tuer un processus dévoyé et le système survit.
Si ce fichier est réglé sur la valeur 1, le noyau panique normalement lorsqu'une situation de manque de mémoire survient. Cependant, si un processus limite les allocations à certains nœuds en utilisant des politiques mémoire (mbind(2) MPOL_BIND) ou des cpusets (cpuset(7)) et que ces nœuds atteignent un état d'épuisement mémoire, un processus peut être tué par l'OOM-killer. Aucun panic ne se produit dans ce cas : parce que la mémoire des autres nœuds peut être libre, cela signifie que le système dans son ensemble n'a peut-être pas encore atteint une situation de manque de mémoire.
Si ce fichier est réglé sur la valeur 2, le noyau panique toujours lorsqu'une condition de manque de mémoire survient.
La valeur par défaut est 0. Les valeurs 1 et 2 sont destinées au basculement de clusters. Choisissez l'une ou l'autre selon votre politique de basculement.
/proc/sys/vm/swappiness
La valeur dans ce fichier contrôle la manière dont le noyau échangera agressivement les pages mémoire. Des valeurs plus élevées augmentent l'agressivité, des valeurs plus basses la diminuent. La valeur par défaut est 60.
/proc/sys/vm/user_reserve_kbytes (depuis Linux 3.10)
Spécifie une quantité de mémoire (en KiB) à réserver pour les processus utilisateurs. Ceci est destiné à empêcher un utilisateur de démarrer un seul processus gourmand en mémoire, de telle sorte qu'il ne puisse pas récupérer (en tuant le gourmand). La valeur dans ce fichier n'a d'effet que lorsque /proc/sys/vm/overcommit_memory est réglé sur 2 (mode "overcommit jamais"). Dans ce cas, le système réserve une quantité de mémoire qui est le minimum entre [3% de la taille actuelle du processus, user_reserve_kbytes].
La valeur par défaut dans ce fichier est le minimum entre [3% des pages libres, 128MiB] exprimé en KiB.
Si la valeur dans ce fichier est réglée sur zéro, alors un utilisateur sera autorisé à allouer toute la mémoire libre avec un seul processus (moins la quantité réservée par /proc/sys/vm/admin_reserve_kbytes). Toute tentative ultérieure d'exécuter une commande entraînera un message "fork: Cannot allocate memory".
Changer la valeur dans ce fichier prend effet chaque fois qu'une application demande de la mémoire.
/proc/sys/vm/unprivileged_userfaultfd (depuis Linux 5.2)
Ce fichier (accessible en écriture) expose un drapeau qui contrôle si les processus non privilégiés sont autorisés à utiliser userfaultfd(2). Si ce fichier a la valeur 1, alors les processus non privilégiés peuvent utiliser userfaultfd(2). Si ce fichier a la valeur 0, alors seuls les processus ayant la capacité CAP_SYS_PTRACE peuvent utiliser userfaultfd(2). La valeur par défaut dans ce fichier est 1.
