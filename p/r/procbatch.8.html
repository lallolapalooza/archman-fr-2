NOM

procbatch - Traiter un fichier de funnel INN ou un fichier déposé par innfeed

SYNTAXE

procbatch [-hquv] [-c [-s spooldir]] [-d outdir] [-e peer] [-m [-t backlogdir]] batchfile

DESCRIPTION

procbatch prendra un fichier de funnel INN ou un fichier innfeed-dropped et le divisera par hôte pour un traitement direct avec innfeed ou innxmit.

Bien que les fichiers de funnel ne soient normalement intéressants qu'après un plantage, innfeed peut déposer des articles pour diverses raisons, dont toutes n'indiquent pas un problème fondamental. Par exemple, innfeed peut déposer des articles lorsque démarré et arrêté rapidement pendant que INN traite un grand nombre de messages de contrôle (une indisposition temporaire), ou lorsque INN lui transmet des articles pour un site qui n'est pas dans innfeed.conf (une mauvaise configuration).

Chaque innfeed en cours d'exécution ouvre un fichier nommé innfeed-dropped.<id>, qui ne devrait normalement jamais être de longueur zéro et être supprimé à la sortie. S'il existe des fichiers de longueur non nulle, innfeed a déposé des articles, et ces fichiers d'articles déposés doivent être traités ou ces articles ne seront jamais envoyés aux pairs. Bien que news.daily traite automatiquement ces fichiers (en invoquant procbatch), il est également possible de le faire manuellement. Assurez-vous d'abord que le fichier ne correspond pas à un innfeed en cours d'exécution, par exemple en appelant "ctlinnd flush innfeed!".

Un fichier de funnel INN, ou un fichier innfeed-dropped, aura généralement le format :

pathname message-id peer1 peer2 peer3 ...

où pathname peut alternativement être un jeton d'API de stockage.

procbatch divisera ce fichier en fichiers nommés peer1.tmp, peer2.tmp, peer3.tmp, etc. du format :

pathname message-id

Ces fichiers de bande seront triés et les doublons seront supprimés. Les renommer simplement en peer1, peer2, peer3, etc. dans le répertoire de backlog d'un innfeed en cours d'exécution les fera récupérer automatiquement par innfeed toutes les backlog-newfile-period secondes (définie dans innfeed.conf). Utilisez l'indicateur -m pour que procbatch les renomme et les déplace automatiquement en place.

Après avoir exécuté procbatch, vous voudrez peut-être vous assurer que chaque fichier de backlog généré a un fichier ".lock" correspondant. Sinon, innfeed n'a pas ce site configuré comme pair, ce qui signifie que votre innfeed.conf pourrait nécessiter une correction.

OPTIONS

-c
Vérifier l'existence d'un article avant d'écrire des références à celui-ci dans les fichiers de bande. Actuellement, cette option ne peut être utilisée qu'avec un magasin d'articles tradspool. Son utilisation avec tout autre format de spool entraînera le rejet de tous les articles.
-d outdir
Placer le(s) fichier(s) de sortie dans le répertoire outdir (par défaut pathtmp tel que défini dans inn.conf). Lorsque -m est également spécifié, les fichiers de sortie temporaires seront toujours placés ici avant d'être déplacés vers leur emplacement final.
-e peer
Traiter uniquement les entrées pour peer.
-h
Afficher un bref écran d'aide.
-m
Ajouter directement aux fichiers de bande dans le répertoire de backlog d'innfeed.
-q
Mode silencieux : afficher uniquement les messages d'erreur.
-s spooldir
Utiliser spooldir comme emplacement du spool d'articles (par défaut patharticles tel que défini dans inn.conf). Cette option n'a d'effet que sur un système de stockage tradspool lorsque -c est également spécifié.
-t backlogdir
Utiliser backlogdir comme emplacement du répertoire de backlog d'innfeed (le répertoire où seront placés les fichiers de bande créés). Par défaut, pathspool/innfeed. Cette option n'a d'effet que lorsque -m est également spécifié.
-u
Supprimer le fichier batch d'entrée après traitement.
-v
Ajouter la verbosité.

EXEMPLES

Prendre le fichier innfeed-dropped.B012345, traiter ses lignes en ajoutant aux fichiers de bande dans le répertoire de backlog d'innfeed, et le supprimer une fois terminé. Être verbeux pendant ce processus :

procbatch -umv innfeed-dropped.B012345

Parcourir innfeed-dropped.B012345 en enregistrant les entrées pour "peer1" dans /tmp/peer1.tmp, mais uniquement si les articles sont toujours disponibles dans le spool local :

procbatch -e peer1 -d /tmp -c innfeed-dropped.B012345

BOGUES

procbatch devrait être capable de vérifier l'existence des articles avec n'importe quel type de magasin d'articles, éventuellement en utilisant grephistory.
