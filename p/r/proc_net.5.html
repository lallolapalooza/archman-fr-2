proc_pid_net(5) Manuel des formats de fichiers proc_pid_net(5)

NOM

/proc/pid/net/, /proc/net/ - informations de la couche réseau

DESCRIPTION

/proc/pid/net/ (depuis Linux 2.6.25)
Voir la description de /proc/net.
/proc/net/
Ce répertoire contient divers fichiers et sous-répertoires contenant des informations sur la couche réseau. Les fichiers contiennent des structures ASCII et sont donc lisibles avec cat(1). Cependant, la suite standard netstat(8) fournit un accès plus propre à ces fichiers.
Avec l'avènement des espaces de noms réseau, diverses informations relatives à la pile réseau sont virtualisées (voir network_namespaces(7)). Ainsi, depuis Linux 2.6.25, /proc/net est un lien symbolique vers le répertoire /proc/self/net, qui contient les mêmes fichiers et répertoires que ceux listés ci-dessous. Cependant, ces fichiers et répertoires exposent désormais des informations pour l'espace de noms réseau dont le processus est membre.
/proc/net/arp
Contient une sauvegarde lisible en ASCII de la table ARP du noyau utilisée pour les résolutions d'adresses. Elle affichera les entrées ARP apprises dynamiquement et pré-programmées. Le format est le suivant :

Adresse IP    Type Matériel   Flags     Adresse Matériel     Masque   Périphérique
192.168.0.50   0x1       0x2       00:50:BF:25:68:F3   *      eth0
192.168.0.250  0x1       0xc       00:00:00:00:00:00   *      eth0

Ici, "Adresse IP" est l'adresse IPv4 de la machine et le "Type Matériel" est le type matériel de l'adresse d'après la RFC 826. Les flags sont les flags internes de la structure ARP (tels que définis dans /usr/include/linux/if_arp.h) et l'"Adresse Matériel" est la mappage de la couche liaison de données pour cette adresse IP si elle est connue.
/proc/net/dev
Le pseudo-fichier dev contient des informations sur l'état des périphériques réseau. Il donne le nombre de paquets reçus et envoyés, le nombre d'erreurs et de collisions, ainsi que d'autres statistiques de base. Celles-ci sont utilisées par le programme ifconfig(8) pour afficher l'état du périphérique. Le format est le suivant :
Inter-|   Réception                                              |  Transmission
 face |octets   paquets errs chutes fifo trames compilés multdif|octets   paquets errs chutes fifo colls porteur compilés
    lo: 2776770   11307    0    0    0     0          0         0  2776770   11307    0    0    0     0       0          0
  eth0: 1215645    2751    0    0    0     0          0         0  1782404    4324    0    0    0   427       0          0
  ppp0: 1622270    5552    1    0    0     0          0         0   354130    5669    0    0    0     0       0          0
  tap0:    7714      81    0    0    0     0          0         0     7714      81    0    0    0     0       0          0
/proc/net/dev_mcast
Défini dans /usr/src/linux/net/core/dev_mcast.c :

indx nom_interface  dmi_u dmi_g dmi_adresse
2    eth0            1     0     01005e000001
3    eth1            1     0     01005e000001
4    eth2            1     0     01005e000001

/proc/net/igmp
Internet Group Management Protocol. Défini dans /usr/src/linux/net/core/igmp.c.
/proc/net/rarp
Ce fichier utilise le même format que le fichier arp et contient la base de données de mappage inverse actuelle utilisée pour fournir les services de recherche d'adresses inverses de rarp(8). Si RARP n'est pas configuré dans le noyau, ce fichier ne sera pas présent.
/proc/net/raw
Contient une sauvegarde de la table des sockets RAW. Une grande partie des informations n'est pas utile, sauf pour le débogage. La valeur "sl" est la case de hachage du noyau pour le socket, l'"adresse locale" est l'adresse locale et la paire de numéros de protocole. "St" est l'état interne du socket. Les "tx_queue" et "rx_queue" sont les files d'attente de données sortantes et entrantes en termes d'utilisation de la mémoire du noyau. Les champs "tr", "tm->when" et "rexmits" ne sont pas utilisés par RAW. Le champ "uid" contient l'UID effectif du créateur du socket.
/proc/net/snmp
Ce fichier contient les données ASCII nécessaires pour les bases d'informations de gestion IP, ICMP, TCP et UDP pour un agent SNMP.
/proc/net/tcp
Contient une sauvegarde de la table des sockets TCP. Une grande partie des informations n'est pas utile, sauf pour le débogage. La valeur "sl" est la case de hachage du noyau pour le socket, l'"adresse locale" est l'adresse locale et la paire de numéros de port. L'"adresse distante" est l'adresse distante et la paire de numéros de port (si connectée). "St" est l'état interne du socket. Les "tx_queue" et "rx_queue" sont les files d'attente de données sortantes et entrantes en termes d'utilisation de la mémoire du noyau. Les champs "tr", "tm->when" et "rexmits" contiennent des informations internes de l'état du socket du noyau et ne sont utiles que pour le débogage. Le champ "uid" contient l'UID effectif du créateur du socket.
/proc/net/udp
Contient une sauvegarde de la table des sockets UDP. Une grande partie des informations n'est pas utile, sauf pour le débogage. La valeur "sl" est la case de hachage du noyau pour le socket, l'"adresse locale" est l'adresse locale et la paire de numéros de port. L'"adresse distante" est l'adresse distante et la paire de numéros de port (si connectée). "St" est l'état interne du socket. Les "tx_queue" et "rx_queue" sont les files d'attente de données sortantes et entrantes en termes d'utilisation de la mémoire du noyau. Les champs "tr", "tm->when" et "rexmits" ne sont pas utilisés par UDP. Le champ "uid" contient l'UID effectif du créateur du socket. Le format est le suivant :
sl  adresse_locale  adresse_distante   st tx_queue rx_queue tr rexmits  tm->when uid
 1: 01642C89:0201 0C642C89:03FF 01 00000000:00000001 01:000071BA 00000000 0
 1: 00000000:0801 00000000:0000 0A 00000000:00000000 00:00000000 6F000100 0
 1: 00000000:0201 00000000:0000 0A 00000000:00000000 00:00000000 00000000 0
/proc/net/unix
Liste les sockets de domaine UNIX présents dans le système et leur état. Le format est le suivant :
Num RefCount Protocole Flags    Type St Inode Chemin
 0: 00000002 00000000 00000000 0001 03    42
 1: 00000001 00000000 00010000 0001 01  1948 /dev/printer
Les champs sont les suivants :
Num:
le numéro de l'emplacement dans la table du noyau.
RefCount:
le nombre d'utilisateurs du socket.
Protocole:
actuellement toujours 0.
Flags:
les flags internes du noyau indiquant l'état du socket.
Type:
le type de socket. Pour les sockets SOCK_STREAM, c'est 0001 ; pour les sockets SOCK_DGRAM, c'est 0002 ; et pour les sockets SOCK_SEQPACKET, c'est 0005.
St:
l'état interne du socket.
Inode:
le numéro d'inode du socket.
Chemin:
le chemin d'accès lié (s'il y en a un) du socket. Les sockets dans l'espace de noms abstrait sont inclus dans la liste et sont affichés avec un Chemin commençant par le caractère '@'.
/proc/net/netfilter/nfnetlink_queue
Ce fichier contient des informations sur la mise en file d'attente user-space de netfilter, si elle est utilisée. Chaque ligne représente une file d'attente. Les files d'attente auxquelles aucun processus user-space ne s'est abonné ne sont pas affichées.

   1   4207     0  2 65535     0     0        0  1
  (1)   (2)    (3)(4)  (5)    (6)   (7)      (8)

Les champs dans chaque ligne sont :
(1)
L'identifiant de la file d'attente. Il correspond à ce qui est spécifié dans les options --queue-num ou --queue-balance de la cible NFQUEUE de iptables(8). Voir iptables-extensions(8) pour plus d'informations.
(2)
Th
e netlink port ID souscrit à la file d'attente.
(3)
Le nombre de paquets actuellement mis en file d'attente et en attente d'être traités par l'application.
(4)
Le mode de copie de la file d'attente. Il est soit 1 (métadonnées uniquement), soit 2 (copie également les données de charge utile dans l'espace utilisateur).
(5)
Plage de copie ; c'est-à-dire combien d'octets de la charge utile du paquet doivent être copiés dans l'espace utilisateur au maximum.
(6)
paquets mis en file d'attente abandonnés. Nombre de paquets qui ont dû être abandonnés par le noyau car trop de paquets sont déjà en attente que l'espace utilisateur renvoie les verdicts d'acceptation/abandon obligatoires.
(7)
paquets abandonnés par l'utilisateur de la file d'attente. Nombre de paquets qui ont été abandonnés au sein du sous-système netlink. Ces abandons se produisent généralement lorsque le tampon de socket correspondant est plein ; c'est-à-dire que l'espace utilisateur n'est pas capable de lire les messages assez rapidement.
(8)
numéro de séquence. Chaque paquet mis en file d'attente est associé à un numéro de séquence (32 bits) qui augmente de manière monotone. Ceci indique l'ID du paquet le plus récent mis en file d'attente.
Le dernier nombre existe uniquement pour des raisons de compatibilité et est toujours 1.
