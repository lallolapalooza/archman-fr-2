NOM

provider-encoder - Fonctions entre la bibliothèque OSSL_ENCODER et le fournisseur

SYNOPIS

#include <openssl/core_dispatch.h>
/*
 * Aucune de ces fonctions ne sont de vraies fonctions, mais elles sont affichées de cette façon pour
 * les signatures de fonctions qui sont proposées sous forme de pointeurs de fonction dans des tableaux OSSL_DISPATCH.
 */
/* Accesseur et descripteur de paramètres de l'encodeur */
const OSSL_PARAM *OSSL_FUNC_encoder_gettable_params(void *provctx);
int OSSL_FUNC_encoder_get_params(OSSL_PARAM params[]);
/* Fonctions pour construire / détruire / manipuler le contexte de l'encodeur */
void *OSSL_FUNC_encoder_newctx(void *provctx);
void OSSL_FUNC_encoder_freectx(void *ctx);
int OSSL_FUNC_encoder_set_ctx_params(void *ctx, const OSSL_PARAM params[]);
const OSSL_PARAM *OSSL_FUNC_encoder_settable_ctx_params(void *provctx);
/* Fonctions pour vérifier la prise en charge de la sélection */
int OSSL_FUNC_encoder_does_selection(void *provctx, int selection);
/* Fonctions pour encoder les données de l'objet */
int OSSL_FUNC_encoder_encode(void *ctx, OSSL_CORE_BIO *out,
                             const void *obj_raw,
                             const OSSL_PARAM obj_abstract[],
                             int selection,
                             OSSL_PASSPHRASE_CALLBACK *cb,
                             void *cbarg);
/* Fonctions pour importer et libérer un objet temporaire à encoder */
void *OSSL_FUNC_encoder_import_object(void *ctx, int selection,
                                      const OSSL_PARAM params[]);
void OSSL_FUNC_encoder_free_object(void *obj);

DESCRIPTION

Nous utilisons le terme large "encoder" dans ce manuel. Cela inclut, mais sans s'y limiter, la sérialisation.

L'opération ENCODEUR est une méthode générique pour encoder un objet natif du fournisseur (obj_raw) ou une abstraction d'objet (object_abstract, voir provider-object(7)) dans une forme encodée, et écrire le résultat dans le OSSL_CORE_BIO donné. Si l'appelant souhaite obtenir le flux encodé en mémoire, il doit fournir un BIO_s_mem(3) BIO.

L'encodeur n'a pas besoin de connaître plus sur le pointeur OSSL_CORE_BIO que de pouvoir le passer aux appels appropriés du BIO (voir « Fonctions de base » dans provider-base(7)).

L'implémentation de l'ENCODEUR peut faire partie d'une chaîne, où les données sont transmises d'une à l'autre. Par exemple, il peut y avoir une implémentation pour encoder un objet en DER (cet objet est supposé être natif du fournisseur et donc passé via obj_raw), et une autre qui encode le DER en PEM (celle-ci recevrait l'encodage DER via obj_abstract).

L'encodage utilisant la forme du tableau OSSL_PARAM(3) permet à un encodeur d'être utilisé pour des données qui ont été exportées par un autre fournisseur, et ainsi leur permettre d'exister indépendamment les uns des autres.

L'encodage utilisant un objet côté fournisseur ne peut être utilisé en toute sécurité qu'avec des données fournisseur provenant du même fournisseur, par exemple des clés avec le fournisseur KEYMGMT.

Toutes les « fonctions » mentionnées ici sont passées sous forme de pointeurs de fonction entre libcrypto et le fournisseur dans des tableaux OSSL_DISPATCH(3) via des tableaux OSSL_ALGORITHM(3) qui sont retournés par la fonction provider_query_operation() du fournisseur (voir « Fonctions du fournisseur » dans provider-base(7)).

Toutes ces « fonctions » ont un type de fonction correspondant défini nommé OSSL_FUNC_{name}_fn, et une fonction d'aide pour récupérer le pointeur de fonction à partir d'un élément OSSL_DISPATCH(3) nommé OSSL_FUNC_{name}. Par exemple, la « fonction » OSSL_FUNC_encoder_encode() a ceci :

typedef int
    (OSSL_FUNC_encoder_encode_fn)(void *ctx, OSSL_CORE_BIO *out,
                                  const void *obj_raw,
                                  const OSSL_PARAM obj_abstract[],
                                  int selection,
                                  OSSL_PASSPHRASE_CALLBACK *cb, void *cbarg);
static ossl_inline OSSL_FUNC_encoder_encode_fn
    OSSL_FUNC_encoder_encode(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) Les tableaux sont indexés par des numéros qui sont fournis sous forme de macros dans openssl-core_dispatch.h(7), comme suit :

OSSL_FUNC_encoder_get_params          OSSL_FUNC_ENCODER_GET_PARAMS
OSSL_FUNC_encoder_gettable_params     OSSL_FUNC_ENCODER_GETTABLE_PARAMS
OSSL_FUNC_encoder_newctx              OSSL_FUNC_ENCODER_NEWCTX
OSSL_FUNC_encoder_freectx             OSSL_FUNC_ENCODER_FREECTX
OSSL_FUNC_encoder_set_ctx_params      OSSL_FUNC_ENCODER_SET_CTX_PARAMS
OSSL_FUNC_encoder_settable_ctx_params OSSL_FUNC_ENCODER_SETTABLE_CTX_PARAMS
OSSL_FUNC_encoder_does_selection      OSSL_FUNC_ENCODER_DOES_SELECTION
OSSL_FUNC_encoder_encode              OSSL_FUNC_ENCODER_ENCODE
OSSL_FUNC_encoder_import_object       OSSL_FUNC_ENCODER_IMPORT_OBJECT
OSSL_FUNC_encoder_free_object         OSSL_FUNC_ENCODER_FREE_OBJECT

Noms et propriétés

Le nom d'une implémentation doit correspondre au type d'objet qu'elle gère. Par exemple, une implémentation qui encode une clé RSA devrait être nommée « RSA ». De même, une implémentation qui encode en plus du DER devrait être nommée « DER ».

Les propriétés, telles que définies dans l'élément de tableau OSSL_ALGORITHM(3) de chaque implémentation de décodeur, peuvent être utilisées pour spécifier davantage de détails sur une implémentation :

output
Cette propriété est utilisée pour spécifier le type de sortie produit par l'implémentation.

Cette propriété est obligatoire.

Les fournisseurs OpenSSL reconnaissent les types de sortie suivants :

text
Une implémentation avec ce type de sortie produit du texte lisible par l'homme, ce qui rend cette implémentation adaptée à la sortie "-text" dans diverses commandes openssl(1).
pem
Une implémentation avec ce type de sortie produit des données au format PEM.
der
Une implémentation avec ce type de sortie produit des données au format DER.
msblob
Une implémentation avec ce type de sortie produit des données au format MSBLOB.
pvk
Une implémentation avec ce type de sortie produit des données au format PVK.
structure
Cette propriété est utilisée pour spécifier la structure utilisée pour l'objet encodé. Un exemple pourrait être "pkcs8", pour spécifier explicitement qu'un objet (probablement une paire de clés asymétriques, dans ce cas) sera encapsulé dans une structure PKCS#8 dans le cadre de l'encodage.

Cette propriété est facultative.

Les valeurs possibles de ces deux propriétés sont ouvertes. Un fournisseur peut très bien spécifier des types de sortie et des structures que libcrypto ne connaît pas.

Sélections de sous-ensembles

Parfois, un objet a plus d'un sous-ensemble de données qu'il est intéressant de traiter séparément ou ensemble. Il est possible de spécifier quels sous-ensembles doivent être encodés, avec un ensemble de bits selection qui sont passés dans un int.

Cet ensemble de bits dépend entièrement du type d'objet côté fournisseur passé. Par exemple, ces bits sont supposés être les mêmes que ceux utilisés avec provider-keymgmt(7) (voir « Objets Clés » dans provider-keymgmt(7)) lorsque l'objet est une paire de clés asymétriques.

Les implémentations d'ENCODEUR sont libres de considérer la selection comme un ensemble d'indices, mais doivent le faire avec prudence. Au final, le résultat doit avoir du sens, et s'il existe un décodeur correspondant, l'objet décodé résultant doit correspondre à l'objet d'origine qui a été encodé.

OSSL_FUNC_encoder_does_selection() doit indiquer si une implémentation particulière prend en charge l'une des combinaisons données par selection.

Fonctions de contexte

OSSL_FUNC_encoder_newctx() retourne un contexte à utiliser avec le reste des fonctions.

OSSL_FUNC_encoder_freectx() libère le contexte donné ctx, s'il a été créé par OSSL_FUNC_encoder_newctx().

OSSL_FUNC_encoder_set_ctx_params() définit les données de contexte en fonction des paramètres de params qu'il reconnaît. Les paramètres non reconnus doivent être ignorés. Passer NULL pour params devrait renvoyer vrai.

OSSL_FUNC_encoder_settable_ctx_params() renvoie un tableau constant de OSSL_PARAM(3) décrivant les paramètres que OSSL_FUNC_encoder_set_ctx_params() peut gérer.

Voir OSSL_PARAM(3) pour plus de détails sur la structure des paramètres utilisée par OSSL_FUNC_encoder_set_ctx_params() et OSSL_FUNC_encoder_settable_ctx_params().

Fonctions d'importation

Un objet natif du fournisseur peut être associé à un fournisseur étranger, et peut donc ne pas convenir à une utilisation directe avec une implémentation ENCODER donnée. À condition que l'implémentation du fournisseur étranger pour gérer l'objet dispose d'une fonction pour exporter cet objet sous forme de tableau OSSL_PARAM(3), l'implémentation ENCODER devrait être capable d'importer ce tableau et de créer un objet approprié à passer à obj_raw de OSSL_FUNC_encoder_encode().

OSSL_FUNC_encoder_import_object() devrait importer le sous-ensemble de params donné avec selection pour créer un objet natif du fournisseur qui peut être passé comme obj_raw à OSSL_FUNC_encoder_encode().

OSSL_FUNC_encoder_free_object() devrait libérer l'objet qui a été créé avec OSSL_FUNC_encoder_import_object().

Fonctions d'encodage

OSSL_FUNC_encoder_encode() devrait prendre un objet natif du fournisseur (dans obj_raw) ou une abstraction d'objet (dans obj_abstract), et devrait sortir l'objet sous forme encodée vers le OSSL_CORE_BIO. Les bits de selection, le cas échéant, devraient déterminer plus en détail ce qui sera produit. Les fonctions d'encodage prennent également un pointeur de fonction OSSL_PASSPHRASE_CALLBACK(3) ainsi qu'un pointeur vers des données d'application cbarg, qui devraient être utilisés lorsqu'une invite de phrase de passe est nécessaire.

Paramètres de l'opération de l'encodeur

Les paramètres d'opération actuellement reconnus par les encodeurs intégrés sont les suivants :

"cipher" (OSSL_ENCODER_PARAM_CIPHER) <chaîne UTF8>
Le nom du chiffrement de chiffrement à utiliser lors de la génération d'un encodage chiffré. Ceci est utilisé lors de l'encodage des clés privées, ainsi que d'autres objets qui nécessitent une protection.

Si ce nom est invalide pour l'implémentation de l'encodage, l'implémentation doit refuser d'effectuer l'encodage, c'est-à-dire que OSSL_FUNC_encoder_encode_data() et OSSL_FUNC_encoder_encode_object() devraient renvoyer une erreur.

"properties" (OSSL_ENCODER_PARAM_PROPERTIES) <chaîne UTF8>
Les propriétés à interroger lors de la tentative de récupération de l'algorithme donné avec le paramètre "cipher". Ceci doit être donné avec le paramètre "cipher" pour être considéré comme valide.

L'implémentation de l'encodage n'est pas obligée d'utiliser cette valeur. Cependant, il est recommandé que les implémentations qui ne gèrent pas les chaînes de propriétés renvoient une erreur à la réception de ce paramètre, sauf si sa valeur est NULL ou une chaîne vide.

"save-parameters" (OSSL_ENCODER_PARAM_SAVE_PARAMETERS) <entier>
Si défini sur 0, désactive l'enregistrement des paramètres de domaine de clé. Par défaut, c'est 1. Cela n'a actuellement d'effet que sur les clés DSA.

Paramètres actuellement reconnus par le rappel de phrase de passe intégré :

"info" (OSSL_PASSPHRASE_PARAM_INFO) <chaîne UTF8>
Une chaîne d'informations qui fera partie de l'invite de phrase de passe. Cela pourrait être utilisé pour donner à l'utilisateur des informations sur le type d'objet pour lequel il est invité.

VALEURS DE RETOUR

OSSL_FUNC_encoder_newctx() renvoie un pointeur vers un contexte, ou NULL en cas d'échec.

OSSL_FUNC_encoder_set_ctx_params() renvoie 1, à moins qu'un paramètre reconnu n'ait été invalide ou n'ait provoqué une erreur, auquel cas 0 est renvoyé.

OSSL_FUNC_encoder_settable_ctx_params() renvoie un pointeur vers un tableau d'éléments OSSL_PARAM(3) constants.

OSSL_FUNC_encoder_does_selection() renvoie 1 si l'implémentation de l'encodeur prend en charge l'un des bits de selection, sinon 0.

OSSL_FUNC_encoder_encode() renvoie 1 en cas de succès, ou 0 en cas d'échec.
