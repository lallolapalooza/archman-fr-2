printf(3) Manuel des fonctions de bibliothèque printf(3)

NOM

printf, fprintf, dprintf, sprintf, snprintf, vprintf, vfprintf, vdprintf, vsprintf, vsnprintf - conversion de sortie formatée

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

DESCRIPTION

Les fonctions de la famille printf() produisent une sortie selon un format comme décrit ci-dessous. Les fonctions printf() et vprintf() écrivent la sortie sur stdout, le flux de sortie standard ; fprintf() et vfprintf() écrivent la sortie sur le flux de sortie donné ; sprintf(), snprintf(), vsprintf() et vsnprintf() écrivent dans la chaîne de caractères str.

La fonction dprintf() est identique à fprintf() sauf qu'elle produit la sortie vers un descripteur de fichier, fd, au lieu d'un flux stdio(3).

Les fonctions snprintf() et vsnprintf() écrivent au plus size octets (y compris le caractère nul final ('\0')) dans str.

Les fonctions vprintf(), vfprintf(), vdprintf(), vsprintf(), vsnprintf() sont équivalentes aux fonctions printf(), fprintf(), dprintf(), sprintf(), snprintf(), respectivement, sauf qu'elles sont appelées avec une va_list au lieu d'un nombre variable d'arguments. Ces fonctions n'appellent pas la macro va_end. Comme elles invoquent la macro va_arg, la valeur de ap est indéfinie après l'appel. Voir stdarg(3).

Toutes ces fonctions écrivent la sortie sous le contrôle d'une chaîne de format qui spécifie comment les arguments suivants (ou les arguments accessibles via les facilités d'arguments de longueur variable de stdarg(3)) sont convertis pour la sortie.

C99 et POSIX.1-2001 spécifient que les résultats sont indéfinis si un appel à sprintf(), snprintf(), vsprintf() ou vsnprintf() entraîne une copie entre des objets qui se chevauchent (par exemple, si le tableau de chaînes de destination et l'un des arguments fournis font référence au même tampon). Voir CAVEATS.

Format de la chaîne de format

La chaîne de format est une chaîne de caractères, commençant et se terminant dans son état de décalage initial, le cas échéant. La chaîne de format est composée de zéro ou plusieurs directives : caractères ordinaires (pas %), qui sont copiés tels quels vers le flux de sortie ; et des spécifications de conversion, chacune résultant en la récupération de zéro ou plusieurs arguments suivants. Chaque spécification de conversion est introduite par le caractère % et se termine par un spécificateur de conversion. Entre les deux, il peut y avoir (dans cet ordre) zéro ou plusieurs indicateurs, une largeur de champ minimale optionnelle, une précision optionnelle et un modificateur de longueur optionnel.

La syntaxe globale d'une spécification de conversion est :


%[argument$][indicateurs][largeur][.précision][modificateur de longueur]conversion

Les arguments doivent correspondre correctement (après promotion de type) au spécificateur de conversion. Par défaut, les arguments sont utilisés dans l'ordre donné, où chaque '*' (voir Largeur de champ et Précision ci-dessous) et chaque spécificateur de conversion demandent l'argument suivant (et c'est une erreur si un nombre insuffisant d'arguments est donné). On peut également spécifier explicitement quel argument est pris, à chaque endroit où un argument est requis, en écrivant "%m$" au lieu de '%' et "*m$" au lieu de '*', où l'entier décimal m désigne la position dans la liste d'arguments de l'argument désiré, indexée à partir de 1. Ainsi,


printf("%*d", largeur, nombre);

et


printf("%2$*1$d", largeur, nombre);

sont équivalents. Le second style permet des références répétées au même argument. La norme C99 n'inclut pas le style utilisant '$', qui provient de la Single UNIX Specification. Si le style utilisant '$' est utilisé, il doit être utilisé partout pour toutes les conversions prenant un argument et tous les arguments de largeur et de précision, mais il peut être mélangé avec les formats "%%", qui ne consomment pas d'argument. Il ne doit y avoir aucun vide dans les numéros d'arguments spécifiés à l'aide de '$'; par exemple, si les arguments 1 et 3 sont spécifiés, l'argument 2 doit également être spécifié quelque part dans la chaîne de format.

Pour certaines conversions numériques, un caractère de base ("point décimal") ou un caractère de regroupement des milliers est utilisé. Le caractère réel utilisé dépend de la partie LC_NUMERIC de la locale. (Voir setlocale(3).) La locale POSIX utilise '.' comme caractère décimal et n'a pas de caractère de groupement. Ainsi,


printf("%'.2f", 1234567.89);

résulte en "1234567.89" dans la locale POSIX, en "1234567,89" dans la locale nl_NL, et en "1.234.567,89" dans la locale da_DK.

Caractères indicateurs

Le caractère % est suivi de zéro ou plusieurs des indicateurs suivants :

#
La valeur doit être convertie en une forme "alternative". Pour les conversions o, le premier caractère de la chaîne de sortie est mis à zéro (en ajoutant un 0 s'il n'était pas déjà zéro). Pour les conversions x et X, un résultat non nul a la chaîne "0x" (ou "0X" pour les conversions X) préfixée. Pour les conversions a, A, e, E, f, F, g, et G, le résultat contiendra toujours un point décimal, même si aucun chiffre ne le suit (normalement, un point décimal apparaît dans les résultats de ces conversions seulement si un chiffre suit). Pour les conversions g et G, les zéros de fin ne sont pas supprimés du résultat comme ils le seraient autrement. Pour les conversions m, si errno contient un code d'erreur valide, la sortie de strerrorname_np(errno) est imprimée ; sinon, la valeur stockée dans errno est imprimée comme un nombre décimal. Pour d'autres conversions, le résultat est indéfini.
0
La valeur doit être complétée par des zéros. Pour les conversions d, i, o, u, x, X, a, A, e, E, f, F, g, et G, la valeur convertie est complétée à gauche par des zéros plutôt que par des espaces. Si les indicateurs 0 et - apparaissent tous deux, l'indicateur 0 est ignoré. Si une précision est donnée avec une conversion entière (d, i, o, u, x, et X), l'indicateur 0 est

-
La valeur convertie doit être alignée à gauche sur la limite de champ. (Le défaut est l'alignement à droite.) La valeur convertie est complétée à droite par des espaces, plutôt qu'à gauche par des espaces ou des zéros. Un - supplante un 0 si les deux sont donnés.
' '
(un espace) Un espace doit être laissé avant un nombre positif (ou une chaîne vide) produit par une conversion signée.
+
Un signe (+ ou -) doit toujours être placé avant un nombre produit par une conversion signée. Par défaut, un signe est utilisé uniquement pour les nombres négatifs. Un + supplante un espace si les deux sont utilisés.

Les cinq caractères de drapeau ci-dessus sont définis dans la norme C99. POSIX spécifie un caractère de drapeau supplémentaire.

'
Pour la conversion décimale (i, d, u, f, F, g, G) la sortie doit être groupée avec des caractères de regroupement par milliers comme quantité non monétaire. De manière trompeuse, ce n'est pas nécessairement tous les mille : par exemple Karbi ("mjw_IN"), groupe ses chiffres par 3 une fois, puis par 2 de manière répétée. Voir locale(7) grouping et thousands_sep, à comparer avec mon_grouping/mon_thousands_sep et strfmon(3). Ceci est une opération nulle dans la locale "C" par défaut.

glibc 2.2 ajoute un caractère de drapeau supplémentaire.

I
Pour la conversion d'entier décimal (i, d, u) la sortie utilise les chiffres de sortie alternatifs de la locale, le cas échéant. Par exemple, depuis glibc 2.2.3, cela donnera des chiffres arabo-indiens dans la locale persane ("fa_IR").

Largeur de champ

Une chaîne de chiffres décimaux facultative (avec un premier chiffre non nul) spécifiant une largeur de champ minimale. Si la valeur convertie contient moins de caractères que la largeur de champ, elle sera complétée par des espaces à gauche (ou à droite, si le drapeau d'alignement à gauche a été donné). Au lieu d'une chaîne de chiffres décimaux, on peut écrire "*" ou "*m$" (pour un entier décimal m) pour spécifier que la largeur du champ est donnée dans l'argument suivant, ou dans le m-ième argument, respectivement, qui doit être de type int. Une largeur de champ négative est interprétée comme un drapeau '-' suivi d'une largeur de champ positive. Dans aucun cas, une largeur de champ inexistante ou petite ne provoque la troncature d'un champ ; si le résultat d'une conversion est plus large que la largeur du champ, le champ est agrandi pour contenir le résultat de la conversion.

Précision

Une précision facultative, sous la forme d'un point ('.') suivi d'une chaîne de chiffres décimaux facultative. Au lieu d'une chaîne de chiffres décimaux, on peut écrire "*" ou "*m$" (pour un entier décimal m) pour spécifier que la précision est donnée dans l'argument suivant, ou dans le m-ième argument, respectivement, qui doit être de type int. Si la précision est donnée uniquement comme '.', la précision est considérée comme zéro. Une précision négative est traitée comme si la précision était omise. Ceci donne le nombre minimum de chiffres à apparaître pour les conversions d, i, o, u, x, et X, le nombre de chiffres à apparaître après le caractère de radix pour les conversions a, A, e, E, f, et F, le nombre maximum de chiffres significatifs pour les conversions g et G, ou le nombre maximum de caractères à imprimer à partir d'une chaîne pour les conversions s et S.

Modificateur de longueur

Ici, "conversion d'entier" signifie une conversion d, i, o, u, x, ou X.

hh
Une conversion d'entier suivante correspond à un argument signed char ou unsigned char, ou une conversion n suivante correspond à un pointeur vers un argument signed char.
h
Une conversion d'entier suivante correspond à un argument short ou unsigned short, ou une conversion n suivante correspond à un pointeur vers un argument short.
l
(ell) Une conversion d'entier suivante correspond à un argument long ou unsigned long, ou une conversion n suivante correspond à un pointeur vers un argument long, ou une conversion c suivante correspond à un argument wint_t, ou une conversion s suivante correspond à un pointeur vers un argument wchar_t. Sur une conversion a, A, e, E, f, F, g, ou G suivante, ce modificateur de longueur est ignoré (C99 ; pas dans SUSv2).
ll
(ell-ell). Une conversion d'entier suivante correspond à un argument long long ou unsigned long long, ou une conversion n suivante correspond à un pointeur vers un argument long long.
q
Un synonyme de ll. Ceci est une extension non standard, dérivée de BSD ; évitez son utilisation dans du nouveau code.
L
Une conversion a, A, e, E, f, F, g, ou G suivante correspond à un argument long double. (C99 autorise %LF, mais SUSv2 non.)
j
Une conversion d'entier suivante correspond à un argument intmax_t ou uintmax_t, ou une conversion n suivante correspond à un pointeur vers un argument intmax_t.
z
Une conversion d'entier suivante correspond à un argument size_t ou ssize_t, ou une conversion n suivante correspond à un pointeur vers un argument size_t.
Z
Un synonyme non standard de z qui précède l'apparition de z. N'utilisez pas dans du nouveau code.
t
Une conversion d'entier suivante correspond à un argument ptrdiff_t, ou une conversion n suivante correspond à un pointeur vers un argument ptrdiff_t.

SUSv3 spécifie tous les éléments ci-dessus, à l'exception des modificateurs explicitement notés comme extensions non standard. SUSv2 spécifiait uniquement les modificateurs de longueur h (dans hd, hi, ho, hx, hX, hn) et l (dans ld, li, lo, lx, lX, ln, lc, ls) et L (dans Le, LE, Lf, Lg, LG).

En tant qu'extension non standard, les implémentations GNU traitent ll et L comme des synonymes, de sorte que l'on puisse, par exemple, écrire llg (en tant que synonyme de Lg conforme aux normes) et Ld (en tant que synonyme de lld conforme aux normes). Une telle utilisation n'est pas portable.

Spécificateurs de conversion

Un caractère qui spécifie le type de conversion à appliquer. Les spécificateurs de conversion et leurs significations sont :

d, i
L'argument int est converti en notation décimale signée. La précision, le cas échéant, indique le nombre minimum de chiffres qui doivent apparaître ; si la valeur convertie nécessite moins de chiffres, elle est complétée à gauche par des zéros. La précision par défaut est 1. Lorsque 0 est imprimé avec une précision explicite de 0, la sortie est vide.
o, u, x, X
L'argument unsigned int est converti en notation octale non signée (o), décimale non signée (u) ou hexadécimale non signée (x et X). Les lettres abcdef sont utilisées pour les conversions x ; les lettres ABCDEF sont utilisées pour les conversions X. La précision, le cas échéant, indique le nombre minimum de chiffres qui doivent apparaître ; si la valeur convertie nécessite moins de chiffres, elle est complétée à gauche par des zéros. La précision par défaut est 1. Lorsque 0 est imprimé avec une précision explicite de 0, la sortie est vide.
e, E
L'argument double est arrondi et converti dans le style [-]d.ddde±dd où il y a un chiffre (qui est non nul si l'argument est non nul) avant le caractère point décimal et le nombre de chiffres après est égal à la précision ; si la précision est manquante, elle est prise comme 6 ; si la précision est zéro, aucun caractère point décimal n'apparaît. Une conversion E utilise la lettre E (plutôt que e) pour introduire l'exposant. L'exposant contient toujours au moins deux chiffres ; si la valeur est zéro, l'exposant est 00.
f, F
L'argument double est arrondi et converti en notation décimale dans le style [-]ddd.ddd, où le nombre de chiffres après le caractère point décimal est égal à la spécification de précision. Si la précision est manquante, elle est prise comme 6 ; si la précision est explicitement zéro, aucun caractère point décimal n'apparaît. Si un point décimal apparaît, au moins un chiffre apparaît avant.
(SUSv2 ne connaît pas F et dit que des représentations sous forme de chaîne de caractères pour l'infini et NaN peuvent être disponibles. SUSv3 ajoute une spécification pour F. La norme C99 spécifie "[-]inf" ou "[-]infinity" pour l'infini, et une chaîne commençant par "nan" pour NaN, dans le cas de la conversion f, et "[-]INF" ou "[-]INFINITY" ou "NAN" dans le cas de la conversion F.)
g, G
L'argument double est converti dans le style f ou e (ou F ou E pour les conversions G). La précision spécifie le nombre de chiffres significatifs. Si la précision est manquante, 6 chiffres sont donnés ; si la précision est zéro, elle est traitée comme 1. Le style e est utilisé si l'exposant de sa conversion est inférieur à -4 ou supérieur ou égal à la précision. Les zéros finaux sont supprimés de la partie fractionnaire du résultat ; un point décimal n'apparaît que s'il est suivi d'au moins un chiffre.
a, A
(C99 ; pas dans SUSv2, mais ajouté dans SUSv3) Pour la conversion a, le double
i> l'argument est converti en notation hexadécimale (utilisant les lettres abcdef) dans le style [-]0xh.hhhhp±d ; pour la conversion A, le préfixe 0X, les lettres ABCDEF et le séparateur d'exposant P sont utilisés. Il y a un chiffre hexadécimal avant le point décimal, et le nombre de chiffres après celui-ci est égal à la précision. La précision par défaut suffit pour une représentation exacte de la valeur si une représentation exacte en base 2 existe et sinon est suffisamment grande pour distinguer les valeurs de type double. Le chiffre avant le point décimal n'est pas spécifié pour les nombres non normalisés, et non nul mais sinon non spécifié pour les nombres normalisés. L'exposant, d, est l'exposant approprié de 2 exprimé en entier décimal ; il contient toujours au moins un chiffre ; si la valeur est zéro, l'exposant est 0.
c
Si aucun modificateur l n'est présent, l'argument int est converti en un unsigned char, et le caractère résultant est écrit. Si un modificateur l est présent, l'argument wint_t (caractère large) est converti en une séquence multi-octets par un appel à la fonction wcrtomb(3), avec un état de conversion commençant dans l'état initial, et la chaîne multi-octets résultante est écrite.
s
Si aucun modificateur l n'est présent : l'argument const char * est censé être un pointeur vers un tableau de type caractère (pointeur vers une chaîne). Les caractères du tableau sont écrits jusqu'à (mais sans inclure) un octet nul de terminaison ('\0') ; si une précision est spécifiée, pas plus que le nombre spécifié n'est écrit. Si une précision est donnée, aucun octet nul n'est nécessaire ; si la précision n'est pas spécifiée, ou est supérieure à la taille du tableau, le tableau doit contenir un octet nul de terminaison.
Si un modificateur l est présent : l'argument const wchar_t * est censé être un pointeur vers un tableau de caractères larges. Les caractères larges du tableau sont convertis en caractères multi-octets (chacun par un appel à la fonction wcrtomb(3), avec un état de conversion commençant dans l'état initial avant le premier caractère large), jusqu'à et y compris un caractère large nul de terminaison. Les caractères multi-octets résultants sont écrits jusqu'à (mais sans inclure) l'octet nul de terminaison. Si une précision est spécifiée, pas plus d'octets que le nombre spécifié ne sont écrits, mais aucun caractère multi-octet partiel n'est écrit. Notez que la précision détermine le nombre d'octets écrits, et non le nombre de caractères larges ou de positions d'écran. Le tableau doit contenir un caractère large nul de terminaison, à moins qu'une précision ne soit donnée et qu'elle soit si petite que le nombre d'octets écrits la dépasse avant que la fin du tableau ne soit atteinte.
C
(Pas dans C99 ou C11, mais dans SUSv2, SUSv3 et SUSv4.) Synonyme de lc. Ne pas utiliser.
S
(Pas dans C99 ou C11, mais dans SUSv2, SUSv3 et SUSv4.) Synonyme de ls. Ne pas utiliser.
p
L'argument pointeur void * est imprimé en hexadécimal (comme avec %#x ou %#lx).
n
Le nombre de caractères écrits jusqu'à présent est stocké dans l'entier pointé par l'argument correspondant. Cet argument doit être un int *, ou une variante dont la taille correspond au modificateur de longueur d'entier (éventuellement) fourni. Aucun argument n'est converti. (Ce spécificateur n'est pas pris en charge par la bibliothèque C bionic.) Le comportement est indéfini si la spécification de conversion inclut des indicateurs, une largeur de champ ou une précision.
m
(Extension glibc ; pris en charge par uClibc et musl, et sur Android à partir de l'API niveau 29.) Imprime la sortie de strerror(errno) (ou strerrorname_np(errno) dans la forme alternative). Aucun argument n'est requis.
%
Un '%' est écrit. Aucun argument n'est converti. La spécification de conversion complète est '%%'.

VALEUR DE RETOUR

Lors d'un retour réussi, ces fonctions retournent le nombre d'octets imprimés (à l'exclusion de l'octet nul utilisé pour terminer la sortie vers les chaînes).

Les fonctions snprintf() et vsnprintf() n'écrivent pas plus de size octets (y compris l'octet nul de terminaison ('\0')). Si la sortie a été tronquée en raison de cette limite, alors la valeur de retour est le nombre de caractères (à l'exclusion de l'octet nul de terminaison) qui auraient été écrits dans la chaîne finale si suffisamment d'espace avait été disponible. Ainsi, une valeur de retour de size ou plus signifie que la sortie a été tronquée. (Voir aussi ci-dessous dans MISES EN GARDE.)

En cas d'erreur, une valeur négative est retournée et errno est définie pour indiquer l'erreur.

ERREURS

Voir write(2) et putwc(3). De plus, l'erreur suivante peut survenir :

EOVERFLOW
La valeur à retourner est supérieure à INT_MAX.

La fonction dprintf() peut échouer en outre si :

EBADF
L'argument fd n'est pas un descripteur de fichier valide.

MISES EN GARDE

Certains programmes s'appuient imprudemment sur du code tel que le suivant :


sprintf(buf, "%s un autre texte", buf);

pour ajouter du texte à buf. Cependant, les normes indiquent explicitement que les résultats sont indéfinis si les tampons source et destination se chevauchent lors de l'appel à sprintf(), snprintf(), vsprintf() et vsnprintf(). Selon la version de gcc(1) utilisée et les options du compilateur employées, des appels tels que ceux ci-dessus ne produiront pas les résultats attendus.

L'implémentation glibc des fonctions snprintf() et vsnprintf() est conforme à la norme C99, c'est-à-dire qu'elle se comporte comme décrit ci-dessus, depuis glibc 2.1. Jusqu'à glibc 2.0.6, elles retournaient -1 lorsque la sortie était tronquée.

BOGUES

Étant donné que sprintf() et vsprintf() supposent une chaîne de longueur arbitraire, les appelants doivent veiller à ne pas dépasser l'espace réel ; il est souvent impossible de l'assurer. Notez que la longueur des chaînes produites dépend de la locale et est difficile à prévoir. Utilisez plutôt snprintf() et vsnprintf() (ou asprintf(3) et vasprintf(3)).

Un code tel que printf(foo); indique souvent un bogue, car foo peut contenir un caractère %. Si <

i>foo provient d'une entrée utilisateur non fiable, il peut contenir %n, ce qui fait que l'appel printf() écrit dans la mémoire et crée une faille de sécurité.

EXEMPLES

Pour afficher Pi avec cinq décimales :


#include <math.h>
#include <stdio.h>
fprintf(stdout, "pi = %.5f\n", 4 * atan(1.0));

Pour afficher une date et une heure sous la forme "Dimanche, Juillet 3, 10:02", où jour_semaine et mois sont des pointeurs vers des chaînes de caractères :


#include <stdio.h>
fprintf(stdout, "%s, %s %d, %.2d:%.2d\n",
        jour_semaine, mois, jour, heure, min);

De nombreux pays utilisent l'ordre jour-mois-année. Par conséquent, une version internationalisée doit être capable d'afficher les arguments dans un ordre spécifié par le format :


#include <stdio.h>
fprintf(stdout, format,
        jour_semaine, mois, jour, heure, min);

où format dépend de la locale et peut permuter les arguments. Avec la valeur :


"%1$s, %3$d. %2$s, %4$d:%5$.2d\n"

on pourrait obtenir "Sonntag, 3. Juli, 10:02".

Pour allouer une chaîne suffisamment grande et y écrire (code correct pour glibc 2.0 et glibc 2.1) :

#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
char *
make_message(const char *fmt, ...)
{
    int n = 0;
    size_t size = 0;
    char *p = NULL;
    va_list ap;
    /* Déterminer la taille requise.  */
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0)
        return NULL;
    size = (size_t) n + 1;      /* Un octet supplémentaire pour '\0' */
    p = malloc(size);
    if (p == NULL)
        return NULL;
    va_start(ap, fmt);
    n = vsnprintf(p, size, fmt, ap);
    va_end(ap);
    if (n < 0) {
        free(p);
        return NULL;
    }
    return p;
}

Si une troncature se produit dans les versions de glibc antérieures à glibc 2.0.6, cela est traité comme une erreur au lieu d'être géré correctement.
