proc_sys_fs(5) Manuel des formats de fichiers proc_sys_fs(5)

NOM

/proc/sys/fs/ - variables du noyau relatives aux systèmes de fichiers

DESCRIPTION

/proc/sys/fs/
Ce répertoire contient les fichiers et sous-répertoires pour les variables du noyau relatives aux systèmes de fichiers.
/proc/sys/fs/aio-max-nr
/proc/sys/fs/aio-nr (tous deux depuis Linux 2.6.4)
aio-nr est le total des événements spécifiés par les appels io_setup(2) pour tous les contextes AIO actuellement actifs. Si aio-nr atteint aio-max-nr, alors io_setup(2) échouera avec l'erreur EAGAIN. Augmenter aio-max-nr n'entraîne pas la préallocation ou le redimensionnement de structures de données du noyau.
/proc/sys/fs/binfmt_misc
La documentation pour les fichiers de ce répertoire se trouve dans la source du noyau Linux dans le fichier Documentation/admin-guide/binfmt-misc.rst (ou dans Documentation/binfmt_misc.txt sur les anciens noyaux).
/proc/sys/fs/dentry-state (depuis Linux 2.2)
Ce fichier contient des informations sur l'état du cache de répertoires (dcache). Le fichier contient six nombres : nr_dentry, nr_unused, age_limit (âge en secondes), want_pages (pages demandées par le système) et deux valeurs factices.
•
nr_dentry est le nombre de dentries alloués (entrées dcache). Ce champ est inutilisé dans Linux 2.2.
•
nr_unused est le nombre de dentries inutilisées.
•
age_limit est l'âge en secondes après lequel les entrées dcache peuvent être récupérées lorsque la mémoire est faible.
•
want_pages est non nul lorsque le noyau a appelé shrink_dcache_pages() et que le dcache n'est pas encore élagué.
/proc/sys/fs/dir-notify-enable
Ce fichier peut être utilisé pour désactiver ou activer l'interface dnotify décrite dans fcntl(2) sur l'ensemble du système. Une valeur de 0 dans ce fichier désactive l'interface, et une valeur de 1 l'active.
/proc/sys/fs/dquot-max
Ce fichier affiche le nombre maximum d'entrées de quota disque mises en cache. Sur certains systèmes (2.4), il n'est pas présent. Si le nombre d'entrées de quota disque libres mises en cache est très faible et que vous avez un nombre impressionnant d'utilisateurs système simultanés, vous pourriez vouloir augmenter la limite.
/proc/sys/fs/dquot-nr
Ce fichier affiche le nombre d'entrées de quota disque allouées et le nombre d'entrées de quota disque libres.
/proc/sys/fs/epoll/ (depuis Linux 2.6.28)
Ce répertoire contient le fichier max_user_watches, qui peut être utilisé pour limiter la quantité de mémoire du noyau consommée par l'interface epoll. Pour plus de détails, voir epoll(7).
/proc/sys/fs/file-max
Ce fichier définit une limite globale sur le nombre de fichiers ouverts pour tous les processus. Les appels système qui échouent en rencontrant cette limite échouent avec l'erreur ENFILE. (Voir aussi setrlimit(2), qui peut être utilisé par un processus pour définir la limite par processus, RLIMIT_NOFILE, sur le nombre de fichiers qu'il peut ouvrir.) Si vous obtenez de nombreux messages d'erreur dans le journal du noyau concernant le manque de descripteurs de fichiers (descriptions de fichiers ouvertes) (recherchez "VFS: file-max limit <nombre> reached"), essayez d'augmenter cette valeur :

echo 100000 > /proc/sys/fs/file-max

Les processus privilégiés (CAP_SYS_ADMIN) peuvent outrepasser la limite file-max.
/proc/sys/fs/file-nr
Ce fichier (en lecture seule) contient trois nombres : le nombre de descripteurs de fichiers alloués (c'est-à-dire le nombre de descriptions de fichiers ouvertes ; voir open(2)) ; le nombre de descripteurs de fichiers libres ; et le nombre maximum de descripteurs de fichiers (c'est-à-dire la même valeur que /proc/sys/fs/file-max). Si le nombre de descripteurs de fichiers alloués est proche du maximum, vous devriez envisager d'augmenter le maximum. Avant Linux 2.6, le noyau allouait dynamiquement les descripteurs de fichiers, mais ne les libérait pas. Au lieu de cela, les descripteurs de fichiers libres étaient conservés dans une liste pour réallocation ; la valeur "descripteurs de fichiers libres" indique la taille de cette liste. Un grand nombre de descripteurs de fichiers libres indique qu'il y a eu un pic passé dans l'utilisation des descripteurs de fichiers ouverts. Depuis Linux 2.6, le noyau déalloue les descripteurs de fichiers libérés, et la valeur "descripteurs de fichiers libres" est toujours zéro.
/proc/sys/fs/inode-max (présent uniquement jusqu'à Linux 2.2)
Ce fichier contient le nombre maximum d'inodes en mémoire. Cette valeur devrait être 3 à 4 fois supérieure à la valeur de file-max, car stdin, stdout et les sockets réseau ont également besoin d'un inode pour être gérés. Lorsque vous manquez régulièrement d'inodes, vous devez augmenter cette valeur.
À partir de Linux 2.4, il n'y a plus de limite statique au nombre d'inodes, et ce fichier est supprimé.
/proc/sys/fs/inode-nr
Ce fichier contient les deux premières valeurs de inode-state.
/proc/sys/fs/inode-state
Ce fichier contient sept nombres : nr_inodes, nr_free_inodes, preshrink, et quatre valeurs factices (toujours zéro).
nr_inodes est le nombre d'inodes que le système a alloués. nr_free_inodes représente le nombre d'inodes libres.
preshrink est non nul lorsque nr_inodes > inode-max et que le système doit élaguer la liste d'inodes au lieu d'en allouer davantage ; depuis Linux 2.4, ce champ est une valeur factice (toujours zéro).
/proc/sys/fs/inotify/ (depuis Linux 2.6.13)
Ce répertoire contient les fichiers max_queued_events, max_user_instances, et max_user_watches, qui peuvent être utilisés pour limiter la quantité de mémoire du noyau consommée par l'interface inotify. Pour plus de détails, voir inotify(7).
/proc/sys/fs/lease-break-time
Ce fichier spécifie le délai de grâce que le noyau accorde à un processus détenant un bail sur un fichier (fcntl(2)) après avoir envoyé un signal à ce processus pour l'avertir qu'un autre processus attend pour ouvrir le fichier. Si le détenteur du bail ne retire ou ne rétrograde pas le bail pendant ce délai de grâce, le noyau rompt le bail de force.
/proc/sys/fs/leases-enable
Ce fichier peut être utilisé pour activer ou désactiver les baux sur fichiers (fcntl(2)) sur l'ensemble du système. Si ce fichier contient la valeur 0, les baux sont désactivés. Une valeur non nulle active les baux.
/proc/sys/fs/mount-max (depuis Linux 4.9)
La valeur dans ce fichier spécifie le nombre maximum de montages qui peuvent exister dans un espace de noms de montage. La valeur par défaut dans ce fichier est 100 000.
/proc/sys/fs/mqueue/ (depuis Linux 2.6.6)
Ce répertoire contient les fichiers msg_max, msgsize_max, et queues_max, contrôlant les ressources utilisées par les files d'attente de messages POSIX. Voir mq_overview(7) pour les détails.
/proc/sys/fs/nr_open (depuis Linux 2.6.25)
Ce fichier impose un plafond à la valeur à laquelle la limite de ressource RLIMIT_NOFILE peut être augmentée (voir getrlimit(2)). Ce plafond est appliqué aux processus non privilégiés et privilégiés. La valeur par défaut dans ce fichier est 1048576. (Avant Linux 2.6.25, le plafond pour RLIMIT_NOFILE était codé en dur à la même valeur.)
/proc/sys/fs/overflowgid
/proc/sys/fs/overflowuid
Ces fichiers vous permettent de modifier la valeur de l'UID et du GID fixes. La valeur par défaut est 65534. Certains systèmes de fichiers ne prennent en charge que les UID et GID de 16 bits, bien qu'en Linux les UID et GID soient de 32 bits. Lorsqu'un de ces systèmes de fichiers est monté avec les écritures activées, tout UID ou GID qui dépasserait 65535 est traduit à la valeur de dépassement avant d'être écrit sur le disque.
/proc/sys/fs/pipe-max-size (depuis Linux 2.6.35)
Voir pipe(7).
/proc/sys/fs/pipe-user-pages-hard (depuis Linux 4.5)
Voir pipe(7).
/proc/sys/fs/pipe-user-pages-soft (depuis Linux 4.5)
Voir pipe(7).
/proc/sys/fs/protected_fifos (depuis Linux 4.19
)
La valeur dans ce fichier est/peut être définie sur l'un des éléments suivants :
0
L'écriture dans les FIFO n'est pas restreinte.
1
N'autorisez pas open(2) avec O_CREAT sur des FIFO que l'appelant ne possède pas dans des répertoires collants mondiaux inscriptibles, à moins que le FIFO n'appartienne au propriétaire du répertoire.
2
Comme pour la valeur 1, mais la restriction s'applique également aux répertoires collants inscriptibles par groupe.
L'intention des protections ci-dessus est d'éviter des écritures non intentionnelles dans un FIFO contrôlé par un attaquant lorsqu'un programme s'attendait à créer un fichier ordinaire.
/proc/sys/fs/protected_hardlinks (depuis Linux 3.6)
Lorsque la valeur dans ce fichier est 0, aucune restriction n'est imposée à la création de liens durs (c'est-à-dire le comportement historique avant Linux 3.6). Lorsque la valeur dans ce fichier est 1, un lien dur ne peut être créé vers un fichier cible que si l'une des conditions suivantes est vraie :
•
Le processus appelant possède la capacité CAP_FOWNER dans son espace de noms utilisateur et l'UID du fichier a une correspondance dans l'espace de noms.
•
L'UID du système de fichiers du processus créant le lien correspond au propriétaire (UID) du fichier cible (comme décrit dans credentials(7), l'UID du système de fichiers d'un processus est normalement le même que son UID effectif).
•
Toutes les conditions suivantes sont vraies :
•
la cible est un fichier régulier ;
•
le fichier cible n'a pas son bit de mode set-user-ID activé ;
•
le fichier cible n'a pas à la fois ses bits de mode set-group-ID et group-executable activés ; et
•
l'appelant a la permission de lire et d'écrire dans le fichier cible (soit via le masque de permissions du fichier, soit parce qu'il possède les capacités appropriées).
La valeur par défaut dans ce fichier est 0. Définir la valeur sur 1 empêche une classe de problèmes de sécurité de longue date causés par des courses de type "temps de vérification, temps d'utilisation" basées sur les liens durs, le plus souvent observées dans les répertoires mondiaux inscriptibles comme /tmp. La méthode courante d'exploitation de cette faille est de traverser les limites de privilèges lors du suivi d'un lien dur donné (c'est-à-dire qu'un processus root suit un lien dur créé par un autre utilisateur). De plus, sur les systèmes sans partitions séparées, cela empêche les utilisateurs non autorisés d'"épingler" les fichiers vulnérables set-user-ID et set-group-ID contre les mises à jour par l'administrateur, ou de créer des liens vers des fichiers spéciaux.
/proc/sys/fs/protected_regular (depuis Linux 4.19)
La valeur dans ce fichier est/peut être définie sur l'un des éléments suivants :
0
L'écriture dans les fichiers réguliers n'est pas restreinte.
1
N'autorisez pas open(2) avec O_CREAT sur des fichiers réguliers que l'appelant ne possède pas dans des répertoires collants mondiaux inscriptibles, à moins que le fichier régulier n'appartienne au propriétaire du répertoire.
2
Comme pour la valeur 1, mais la restriction s'applique également aux répertoires collants inscriptibles par groupe.
L'intention des protections ci-dessus est similaire à protected_fifos, mais permet à une application d'éviter d'écrire dans un fichier régulier contrôlé par un attaquant, là où l'application s'attendait à en créer un.
/proc/sys/fs/protected_symlinks (depuis Linux 3.6)
Lorsque la valeur dans ce fichier est 0, aucune restriction n'est placée sur le suivi des liens symboliques (c'est-à-dire le comportement historique avant Linux 3.6). Lorsque la valeur dans ce fichier est 1, les liens symboliques ne sont suivis que dans les circonstances suivantes :
•
l'UID du système de fichiers du processus qui suit le lien correspond au propriétaire (UID) du lien symbolique (comme décrit dans credentials(7), l'UID du système de fichiers d'un processus est normalement le même que son UID effectif) ;
•
le lien ne se trouve pas dans un répertoire collant mondial inscriptible ; ou
•
le lien symbolique et son répertoire parent ont le même propriétaire (UID)
Un appel système qui ne parvient pas à suivre un lien symbolique en raison des restrictions ci-dessus renvoie l'erreur EACCES dans errno.
La valeur par défaut dans ce fichier est 0. Définir la valeur sur 1 évite une classe de problèmes de sécurité de longue date basés sur des courses de type "temps de vérification, temps d'utilisation" lors de l'accès aux liens symboliques.
/proc/sys/fs/suid_dumpable (depuis Linux 2.6.13)
La valeur dans ce fichier est assignée au drapeau "dumpable" d'un processus dans les circonstances décrites dans prctl(2). En effet, la valeur dans ce fichier détermine si des fichiers de vidage de mémoire (core dump) sont produits pour des binaires set-user-ID ou autrement protégés/tainted. Le paramètre "dumpable" affecte également la propriété des fichiers dans le répertoire /proc/pid d'un processus, comme décrit ci-dessus.
Trois valeurs entières différentes peuvent être spécifiées :
0 (par défaut)
Ceci fournit le comportement traditionnel (avant Linux 2.6.13). Un vidage de mémoire ne sera pas produit pour un processus qui a changé d'identifiants (en appelant seteuid(2), setgid(2), ou similaire, ou en exécutant un programme set-user-ID ou set-group-ID) ou dont le binaire n'a pas l'autorisation de lecture activée.
1 ("debug")
Tous les processus vidangent en mémoire si possible. (Les raisons pour lesquelles un processus pourrait néanmoins ne pas vidanger en mémoire sont décrites dans core(5).) Le vidage de mémoire appartient à l'UID du système de fichiers du processus qui vide et aucune sécurité n'est appliquée. Ceci est prévu pour des situations de débogage système uniquement : ce mode est non sécurisé car il permet aux utilisateurs non privilégiés d'examiner le contenu de la mémoire des processus privilégiés.
2 ("suidsafe")
Tout binaire qui ne serait normalement pas vidé (voir "0" ci-dessus) est vidé lisible par root uniquement. Ceci permet à l'utilisateur de supprimer le fichier de vidage de mémoire mais pas de le lire. Pour des raisons de sécurité, les vidages de mémoire dans ce mode ne se remplaceront pas mutuellement ni n'écraseront d'autres fichiers. Ce mode est approprié lorsque les administrateurs tentent de déboguer des problèmes dans un environnement normal.
De plus, depuis Linux 3.6, /proc/sys/kernel/core_pattern doit être un chemin absolu ou une commande de pipe, comme détaillé dans core(5). Des avertissements seront écrits dans le journal du noyau si core_pattern ne suit pas ces règles, et aucun vidage de mémoire ne sera produit.
Pour plus de détails sur l'effet du paramètre "dumpable" d'un processus sur la vérification du mode d'accès ptrace, voir ptrace(2).
/proc/sys/fs/super-max
Ce fichier contrôle le nombre maximum de superblocs, et donc le nombre maximum de systèmes de fichiers montés que le noyau peut avoir. Vous n'avez besoin d'augmenter super-max que si vous avez besoin de monter plus de systèmes de fichiers que la valeur actuelle dans super-max ne vous le permet.
/proc/sys/fs/super-nr
Ce fichier contient le nombre de systèmes de fichiers actuellement montés.
