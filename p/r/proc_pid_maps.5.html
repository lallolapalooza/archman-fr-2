proc_pid_maps(5) Manuel des formats de fichiers proc_pid_maps(5)

NOM

/proc/pid/maps - régions mémoire mappées

DESCRIPTION

/proc/pid/maps
Un fichier contenant les régions mémoire actuellement mappées et leurs permissions d'accès. Voir mmap(2) pour plus d'informations sur les mappages mémoire.
La permission d'accéder à ce fichier est régie par une vérification du mode d'accès ptrace PTRACE_MODE_READ_FSCREDS ; voir ptrace(2).
Le format du fichier est :

adresse           perms offset  dev   inode       chemin_fichier
00400000-00452000 r-xp 00000000 08:02 173521      /usr/bin/dbus-daemon
00651000-00652000 r--p 00051000 08:02 173521      /usr/bin/dbus-daemon
00652000-00655000 rw-p 00052000 08:02 173521      /usr/bin/dbus-daemon
00e03000-00e24000 rw-p 00000000 00:00 0           [heap]
00e24000-011f7000 rw-p 00000000 00:00 0           [heap]
...
35b1800000-35b1820000 r-xp 00000000 08:02 135522  /usr/lib64/ld-2.15.so
35b1a1f000-35b1a20000 r--p 0001f000 08:02 135522  /usr/lib64/ld-2.15.so
35b1a20000-35b1a21000 rw-p 00020000 08:02 135522  /usr/lib64/ld-2.15.so
35b1a21000-35b1a22000 rw-p 00000000 00:00 0
35b1c00000-35b1dac000 r-xp 00000000 08:02 135870  /usr/lib64/libc-2.15.so
35b1dac000-35b1fac000 ---p 001ac000 08:02 135870  /usr/lib64/libc-2.15.so
35b1fac000-35b1fb0000 r--p 001ac000 08:02 135870  /usr/lib64/libc-2.15.so
35b1fb0000-35b1fb2000 rw-p 001b0000 08:02 135870  /usr/lib64/libc-2.15.so
...
f2c6ff8c000-7f2c7078c000 rw-p 00000000 00:00 0    [stack:986]
...
7fffb2c0d000-7fffb2c2e000 rw-p 00000000 00:00 0   [stack]
7fffb2d48000-7fffb2d49000 r-xp 00000000 00:00 0   [vdso]

Le champ adresse est l'espace d'adressage dans le processus que le mappage occupe. Le champ perms est un ensemble de permissions :

r = lecture
w = écriture
x = exécution
s = partagé
p = privé (copie sur écriture)

Le champ offset est le décalage dans le fichier/quelque chose ; dev est le périphérique (majeur:mineur) ; inode est l'inode sur ce périphérique. 0 indique qu'aucun inode n'est associé à la région mémoire, comme ce serait le cas pour BSS (données non initialisées).
Le champ chemin_fichier sera généralement le fichier qui est à la base du mappage. Pour les fichiers ELF, vous pouvez facilement coordonner avec le champ offset en examinant le champ Offset dans les en-têtes de programme ELF (readelf -l).
Il existe des pseudo-chemins supplémentaires utiles :
[stack]
La pile du processus initial (également connue sous le nom de pile du thread principal).
[stack:tid] (de Linux 3.4 à Linux 4.4)
La pile d'un thread (où tid est un identifiant de thread). Il correspond au chemin /proc/pid/task/tid/. Ce champ a été supprimé dans Linux 4.5, car la fourniture de cette information pour un processus avec un grand nombre de threads est coûteuse.
[vdso]
L'objet partagé virtuellement lié dynamiquement. Voir vdso(7).
[heap]
Le tas du processus.
[anon:nom] (depuis Linux 5.17)
Un mappage anonyme privé nommé. Défini avec prctl(2) PR_SET_VMA_ANON_NAME.
[anon_shmem:nom] (depuis Linux 6.2)
Un mappage anonyme partagé nommé. Défini avec prctl(2) PR_SET_VMA_ANON_NAME.
Si le champ chemin_fichier est vide, il s'agit d'un mappage anonyme tel qu'obtenu via mmap(2). Il n'y a pas de moyen simple de le relier à la source d'un processus, sauf en l'exécutant via gdb(1), strace(1), ou des outils similaires.
chemin_fichier est affiché sans échappement sauf pour les caractères de nouvelle ligne, qui sont remplacés par une séquence d'échappement octale. Par conséquent, il n'est pas possible de déterminer si le chemin d'origine contenait un caractère de nouvelle ligne ou la séquence de caractères littérale \012.
Si le mappage est lié à un fichier et que le fichier a été supprimé, la chaîne " (deleted)" est ajoutée au chemin du fichier. Notez que ceci est également ambigu.
Sous Linux 2.0, il n'y a pas de champ indiquant le chemin du fichier.
