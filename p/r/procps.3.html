PROCPS(3) Manuel des fonctions de bibliothèque PROCPS(3)

NOM

procps - API pour accéder aux informations de niveau système dans le système de fichiers /proc

SYNTAXE

Cinq interfaces distinctes sont représentées dans cette syntaxe et nommées d'après les fichiers auxquels elles accèdent dans le pseudo-système de fichiers /proc : diskstats, meminfo, slabinfo, stat et vmstat.

#include <libproc2/named_interface.h>
int procps_new   (struct info **info);
int procps_ref   (struct info  *info);
int procps_unref (struct info **info);
struct result *procps_get (
    struct info *info,
[   const char *name,      ]   api diskstats uniquement
    enum item item);
struct stack *procps_select (
    struct info *info,
[   const char *name,      ]   api diskstats uniquement
    enum item *items,
    int numitems);
struct reaped *procps_reap (
    struct info *info,
[   enum reap_type what,   ]   api stat uniquement
    enum item *items,
    int numitems);
struct stack **procps_sort (
    struct info *info,
    struct stack *stacks[],
    int numstacked,
    enum item sortitem,
    enum sort_order order);

Les fonctions et structures ci-dessus sont génériques, mais la named_interface spécifique ferait également partie de tous les identificateurs. Par exemple, ‘procps_new’ serait en réalité ‘procps_meminfo_new’ et ‘info’ serait en réalité ‘diskstats_info’, etc.

Le même named_interface est utilisé dans le nom de chaque fichier d'en-tête avec le suffixe ‘.h’ ajouté.

Liez avec -lproc2.

DESCRIPTION

Aperçu

Au cœur de ces interfaces se trouve une simple structure ‘result’ reflétant un ‘item’ plus sa valeur (dans une union avec des types C standard comme membres). Toutes les structures ‘result’ sont allouées automatiquement et fournies par la bibliothèque.

En spécifiant un tableau d'‘items’, ces structures peuvent être organisées en un ‘stack’, produisant potentiellement de nombreux résultats en un seul appel de fonction. Ainsi, un ‘stack’ peut être considéré comme un enregistrement de longueur variable dont le contenu et l'ordre sont déterminés uniquement par l'utilisateur.

Dans le cadre de chaque interface, il existe deux énumérateurs uniques. Les éléments ‘noop’ et ‘extra’ existent pour stocker des valeurs utilisateur. Ils ne sont jamais définis par la bibliothèque, mais le résultat ‘extra’ sera remis à zéro à chaque interaction avec la bibliothèque.

Le fichier d'en-tête named_interface sera un document essentiel lors du développement de programmes utilisateur. Vous y trouverez les éléments disponibles, leur type de retour (le nom du membre de la structure ‘result’) et la source de ces valeurs. Des énumérateurs et structures supplémentaires y sont également documentés.

Utilisation

La séquence d'appels suivante serait typique pour ces interfaces.

1. procps_new()
2. procps_get(), procps_select() ou procps_reap()
3. procps_unref()

La fonction get est utilisée pour récupérer une structure ‘result’ pour un seul ‘item’. Alternativement, une macro GET est disponible lorsqu'on ne s'intéresse qu'à la valeur de retour.

La fonction select peut récupérer plusieurs structures ‘result’ dans un seul ‘stack’.

Pour des résultats variables imprévisibles, les interfaces diskstats, slabinfo et stat exportent une fonction reap. Elle est utilisée pour récupérer plusieurs ‘stacks’ contenant chacun plusieurs structures ‘result’. Optionnellement, un utilisateur peut choisir de sort ces résultats.

Pour exploiter un ‘stack’ et accéder aux structures ‘result’ individuelles, un relative_enum est requis, comme montré dans la macro VAL définie dans le fichier d'en-tête. Ces valeurs pourraient être codées en dur comme : 0 à numitems-1. Cependant, ce besoin est généralement satisfait en créant vos propres énumérateurs correspondant à l'ordre du tableau ‘items’.

Remarques

Les fonctions new, ref, unref, get et select sont disponibles dans les cinq interfaces.

Pour les fonctions new et unref, l'adresse d'un pointeur de struct info doit être fournie. Avec new, il doit avoir été initialisé à NULL. Avec unref, il sera réinitialisé à NULL si le compteur de références atteint zéro.

Dans le cas de l'interface diskstats, un paramètre name sur les fonctions get et select identifie un nom de disque ou de partition.

Pour l'interface stat, un paramètre what sur la fonction reap identifie si les données doivent être collectées uniquement pour les CPU ou pour les CPU et les nœuds NUMA.

Lors de l'utilisation de la fonction sort, les paramètres stacks et numstacked seraient normalement ceux retournés dans la structure ‘reaped’.

VALEUR DE RETOUR

Fonctions retournant un ‘int’

Une erreur sera indiquée par un nombre négatif qui est toujours l'inverse d'une valeur bien connue de errno.h.

Le succès est indiqué par une valeur de retour de zéro. Cependant, les fonctions ref et unref retournent le compteur de références actuel de la structure info.

Fonctions retournant une ‘adresse’

Une erreur sera indiquée par un pointeur de retour NULL avec la raison trouvée dans la valeur errno formelle.

Le succès est indiqué par un pointeur vers la structure nommée.

DÉBOGAGE

Pour aider au développement de programmes, il existe une disposition qui peut aider à s'assurer que les références aux membres ‘result’ correspondent aux attentes de la bibliothèque. Elle suppose qu'une macro fournie dans le fichier d'en-tête est utilisée pour accéder à la valeur ‘result’.

Cette fonctionnalité peut être activée par l'une des méthodes suivantes et toute divergence sera écrite sur stderr.

1)
Ajoutez CFLAGS='-DXTRA_PROCPS_DEBUG' à toutes les autres options ./configure employées.
2)
Ajoutez #include <libproc2/xtra-procps-debug.h> à tout programme après les inclusions de l'interface nommée.

Cette fonctionnalité de vérification entraîne des surcoûts substantiels. Par conséquent, il est important qu'elle ne soit pas activée pour une compilation de production/version.

VOIR AUSSI

procps_misc(3), procps_pids(3), proc(5).

procps — utilitaires pour l'inspection des processus

SYNTAXE

ps, top, htop, pstree, pgrep, pkill, skill, pidof, pmap, tty, uptime, kill, killall, nice, renice, w

DESCRIPTION

Le paquet procps fournit une collection d'utilitaires en ligne de commande pour inspecter et manipuler les processus en cours d'exécution sous Linux. Ces outils interagissent avec le système de fichiers procfs (/proc) pour obtenir des informations sur les processus.

OPTIONS

Chaque utilitaire de procps a ses propres options. Veuillez consulter leurs pages de manuel respectives pour une liste complète des options.

  • ps: Affiche des informations sur les processus en cours.
  • top: Affiche une liste dynamique des processus en cours d'exécution, triée par utilisation du processeur.
  • htop: Une alternative interactive à top.
  • pstree: Affiche les processus sous forme d'arbre.
  • pgrep: Recherche des processus en fonction de leurs noms ou d'autres attributs.
  • pkill: Envoie un signal aux processus en fonction de leurs noms ou d'autres attributs.
  • skill: Envoie un signal aux processus en fonction de leurs noms ou d'autres attributs (obsolète, utiliser pkill).
  • pidof: Trouve les ID de processus des programmes nommés.
  • pmap: Affiche l'utilisation de la mémoire d'un processus.
  • tty: Affiche le nom du terminal connecté à l'entrée standard.
  • uptime: Affiche depuis combien de temps le système est en marche, le nombre d'utilisateurs connectés et la charge moyenne du système.
  • kill: Envoie un signal à un processus spécifié par son PID.
  • killall: Envoie un signal à tous les processus correspondant à un nom spécifié.
  • nice: Modifie la priorité d'exécution d'un processus.
  • renice: Modifie la priorité d'exécution d'un ou plusieurs processus en cours d'exécution.
  • w: Affiche des informations sur les utilisateurs connectés et ce qu'ils font.

SORTIE

La sortie de ces utilitaires varie en fonction de l'outil utilisé et des options spécifiées. Elle comprend généralement des informations telles que les PID, les noms des processus, l'utilisation du CPU et de la mémoire, l'état du processus, les utilisateurs propriétaires, etc.

EXEMPLES

Afficher tous les processus en cours d'exécution avec leurs PID et leurs noms :

ps aux

Afficher la charge du système et le temps de fonctionnement :

uptime

Tuer un processus avec un PID spécifique :

kill -9 1234

FICHIERS

  • /proc: Système de fichiers virtuel contenant des informations sur les processus.

VOIR AUSSI

top(1), ps(1), htop(1), pstree(1), pgrep(1), pkill(1), pidof(1), pmap(1), kill(1), killall(1), nice(1), renice(1), w(1), proc(5)

DÉPANNAGE

Si vous rencontrez des problèmes avec ces utilitaires, assurez-vous qu'ils sont correctement installés et que vous avez les permissions nécessaires pour inspecter les processus.

Pour des problèmes spécifiques avec un outil particulier, consultez sa page de manuel dédiée.
