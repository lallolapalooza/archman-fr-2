NOM

privoxy - Proxy d'amélioration de la confidentialité

SYNTAXE

privoxy [--chroot ] [--config-test ] [--help ] [--no-daemon ] [--pidfile pidfile ] [--pre-chroot-nslookup hostname ] [--user utilisateur[.groupe] ] [--version ] [fichier_config ]

OPTIONS

Privoxy peut être invoqué avec les options de ligne de commande suivantes :

--chroot
Avant de changer l'ID utilisateur donné dans l'option --user, effectuez un chroot vers le répertoire personnel de cet utilisateur, c'est-à-dire faites croire au noyau que l'arborescence de répertoires commence là pour le processus Privoxy. Si configuré soigneusement, cela peut limiter l'impact d'éventuelles vulnérabilités dans Privoxy aux fichiers contenus dans cette hiérarchie.
--config-test
Quitte après avoir chargé les fichiers de configuration avant de se lier à l'adresse d'écoute. Le code de sortie indique si les fichiers de configuration ont été chargés avec succès ou non.

Si le code de sortie est 1, au moins un des fichiers de configuration est invalide. S'il est 0, tous les fichiers de configuration ont été chargés avec succès (mais peuvent toujours contenir des erreurs qui ne peuvent être détectées qu'à l'exécution).

Cette option n'affecte pas le réglage du journal. Il est recommandé de la combiner avec "--no-daemon" si un fichier journal configuré ne doit pas être utilisé.

--help
Affiche des informations d'utilisation brèves et quitte.
--no-daemon
Ne devient pas un démon, c'est-à-dire ne se détache pas, ne devient pas le chef de groupe de processus, ne se détache pas du tty de contrôle et effectue tous les journaux là.
--pidfile pidfile
Au démarrage, écrit l'ID du processus dans pidfile. Supprime le pidfile à la sortie. L'échec de création ou de suppression du pidfile n'est pas fatal. Si aucune option --pidfile n'est donnée, aucun fichier PID ne sera utilisé.
--pre-chroot-nslookup hostname
Initialise la bibliothèque de résolution en utilisant hostname avant le chroot. Sur certains systèmes, cela réduit le nombre de fichiers qui doivent être copiés dans l'arborescence chroot.
--user utilisateur[.groupe]
Après (éventuellement) avoir écrit le fichier PID, prend l'ID utilisateur de utilisateur et l'ID de groupe de groupe, ou, si le groupe optionnel n'a pas été donné, le groupe par défaut de utilisateur. Quitte si les privilèges ne sont pas suffisants pour le faire.
--version
Affiche les informations de version et quitte.

Si le fichier_config n'est pas spécifié sur la ligne de commande, Privoxy cherchera un fichier nommé config dans le répertoire courant. Si aucun fichier_config n'est trouvé, Privoxy échouera au démarrage.

DESCRIPTION

Privoxy est un proxy Web sans cache avec des capacités de filtrage avancées pour améliorer la confidentialité, modifier les données de pages Web et les en-têtes HTTP, contrôler l'accès et supprimer les publicités et autres indésirables d'Internet. Privoxy possède une configuration flexible et peut être personnalisé pour répondre aux besoins et goûts individuels. Il est adapté aussi bien aux systèmes autonomes qu'aux réseaux multi-utilisateurs.

INSTALLATION ET UTILISATION

Les navigateurs peuvent soit être configurés individuellement pour utiliser Privoxy comme proxy HTTP (recommandé), soit Privoxy peut être combiné avec un filtre de paquets pour construire un proxy intercepteur (voir config). Le réglage par défaut est pour localhost, sur le port 8118 (configurable dans le fichier de configuration principal). Pour définir le proxy HTTP dans Firefox, allez dans : Outils ; Options ; Général ; Paramètres de connexion ; Configuration manuelle du proxy.

Pour Internet Explorer, allez dans : Outils ; Options Internet ; Connexions ; Paramètres réseau LAN.

Le proxy sécurisé (SSL) doit également être réglé sur les mêmes valeurs, sinon les URL https: ne seront pas proxyfiées. Note : Privoxy ne peut proxyfier que le trafic HTTP et HTTPS. N'essayez pas de l'utiliser avec FTP ou d'autres protocoles. HTTPS présente certaines limitations, et toutes les fonctionnalités ne fonctionneront pas avec les connexions HTTPS.

Pour les autres navigateurs, consultez la documentation.

CONFIGURATION

Privoxy peut être configuré avec divers fichiers de configuration. Les fichiers de configuration par défaut sont : config, default.filter, default.action et default.action. user.action doit être utilisé pour les exceptions définies localement aux règles par défaut dans match-all.action et default.action, et user.filter pour les filtres définis localement. Ceux-ci sont bien commentés. Sur les systèmes Unix et Unix-like, ils se trouvent par défaut dans /etc/privoxy/.

Privoxy utilise le concept d'actions pour manipuler le flux de données entre le navigateur et les sites distants. Diverses actions sont disponibles avec des fonctions spécifiques pour bloquer les sites Web, gérer les cookies, etc. Ces actions peuvent être invoquées individuellement ou combinées, et utilisées contre des URL individuelles, ou des groupes d'URL qui peuvent être définis à l'aide de caractères génériques et d'expressions régulières. Le résultat est que l'utilisateur a un contrôle et une liberté grandement améliorés.

La liste des actions (blocages de publicités, etc.) peut également être configurée avec votre navigateur Web à l'adresse http://config.privoxy.org/ (en supposant que la configuration le permette). Les paramètres de configuration de Privoxy peuvent également être consultés à la même adresse. De plus, Privoxy peut être activé/désactivé. Il s'agit d'une page interne, qui ne nécessite pas d'accès à Internet.

Consultez le Manuel utilisateur pour une explication détaillée de l'installation, de l'utilisation générale, de toutes les options de configuration, des nouvelles fonctionnalités et des notes sur la mise à jour.

SIGNaux

Privoxy se termine lors des signaux SIGINT et SIGTERM. Les scripts de rotation des journaux peuvent provoquer une réouverture du fichier journal en envoyant un SIGHUP à Privoxy. Notez que contrairement aux autres démons, Privoxy n'a pas besoin d'être informé des changements de fichier de configuration par SIGHUP -- il les détectera automatiquement. Les signaux autres que ceux listés ci-dessus ne sont pas explicitement gérés et entraînent l'action par défaut définie par le système d'exploitation.
