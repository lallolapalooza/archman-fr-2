NOM

provider-kdf - Fonctions de bibliothèque KDF <-> fournisseur

SYNTAXE

#include <openssl/core_dispatch.h>
#include <openssl/core_names.h>
/*
 * Aucune de ces fonctions ne sont de véritables fonctions, mais sont affichées
 * comme ceci pour les signatures de fonctions qui sont proposées comme pointeurs
 * de fonctions dans des tableaux OSSL_DISPATCH.
 */
/* Gestion du contexte */
void *OSSL_FUNC_kdf_newctx(void *provctx);
void OSSL_FUNC_kdf_freectx(void *kctx);
void *OSSL_FUNC_kdf_dupctx(void *src);
/* Chiffrement/déchiffrement */
int OSSL_FUNC_kdf_reset(void *kctx);
int OSSL_FUNC_kdf_derive(void *kctx, unsigned char *key, size_t keylen,
                         const OSSL_PARAM params[]);
void *OSSL_FUNC_kdf_derive_skey(void *ctx, const char *key_type, void *provctx,
                                OSSL_FUNC_skeymgmt_import_fn *import,
                                size_t keylen, const OSSL_PARAM params[]);
/* Descripteurs de paramètres KDF */
const OSSL_PARAM *OSSL_FUNC_kdf_gettable_params(void *provctx);
const OSSL_PARAM *OSSL_FUNC_kdf_gettable_ctx_params(void *kcxt, void *provctx);
const OSSL_PARAM *OSSL_FUNC_kdf_settable_ctx_params(void *kcxt, void *provctx);
/* Paramètres KDF */
int OSSL_FUNC_kdf_get_params(OSSL_PARAM params[]);
int OSSL_FUNC_kdf_get_ctx_params(void *kctx, OSSL_PARAM params[]);
int OSSL_FUNC_kdf_set_ctx_params(void *kctx, const OSSL_PARAM params[]);
int OSSL_FUNC_kdf_set_skey(void *kctx, void *skeydata, const char *paramname);

DESCRIPTION

Cette documentation s'adresse principalement aux auteurs de fournisseurs. Voir provider(7) pour plus d'informations.

L'opération KDF permet aux fournisseurs d'implémenter des algorithmes KDF et de les rendre disponibles aux applications via les fonctions de l'API EVP_KDF_CTX_reset(3) et EVP_KDF_derive(3).

Toutes les « fonctions » mentionnées ici sont passées sous forme de pointeurs de fonctions entre libcrypto et le fournisseur dans des tableaux OSSL_DISPATCH(3) via des tableaux OSSL_ALGORITHM(3) qui sont retournés par la fonction provider_query_operation() du fournisseur (voir « Fonctions du fournisseur » dans provider-base(7)).

Toutes ces « fonctions » ont un type de fonction correspondant nommé OSSL_FUNC_{nom}_fn, et une fonction d'aide pour récupérer le pointeur de fonction à partir d'un élément OSSL_DISPATCH(3) nommé OSSL_FUNC_{nom}. Par exemple, la « fonction » OSSL_FUNC_kdf_newctx() a ceci :

typedef void *(OSSL_FUNC_kdf_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_kdf_newctx_fn
    OSSL_FUNC_kdf_newctx(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) les entrées du tableau sont identifiées par des numéros qui sont fournis sous forme de macros dans openssl-core_dispatch.h(7), comme suit :

OSSL_FUNC_kdf_newctx               OSSL_FUNC_KDF_NEWCTX
OSSL_FUNC_kdf_freectx              OSSL_FUNC_KDF_FREECTX
OSSL_FUNC_kdf_dupctx               OSSL_FUNC_KDF_DUPCTX
OSSL_FUNC_kdf_reset                OSSL_FUNC_KDF_RESET
OSSL_FUNC_kdf_derive               OSSL_FUNC_KDF_DERIVE
OSSL_FUNC_kdf_derive_skey          OSSL_FUNC_KDF_DERIVE_SKEY
OSSL_FUNC_kdf_get_params           OSSL_FUNC_KDF_GET_PARAMS
OSSL_FUNC_kdf_get_ctx_params       OSSL_FUNC_KDF_GET_CTX_PARAMS
OSSL_FUNC_kdf_set_ctx_params       OSSL_FUNC_KDF_SET_CTX_PARAMS
OSSL_FUNC_kdf_gettable_params      OSSL_FUNC_KDF_GETTABLE_PARAMS
OSSL_FUNC_kdf_gettable_ctx_params  OSSL_FUNC_KDF_GETTABLE_CTX_PARAMS
OSSL_FUNC_kdf_settable_ctx_params  OSSL_FUNC_KDF_SETTABLE_CTX_PARAMS
OSSL_FUNC_kdf_set_skey             OSSL_FUNC_KDF_SET_SKEY

Une implémentation d'algorithme KDF peut ne pas implémenter toutes ces fonctions. Afin d'avoir un ensemble cohérent de fonctions, au moins les fonctions suivantes doivent être implémentées : OSSL_FUNC_kdf_newctx(), OSSL_FUNC_kdf_freectx(), OSSL_FUNC_kdf_set_ctx_params(), et au moins l'une de OSSL_FUNC_kdf_derive() ou OSSL_FUNC_kdf_derive_skey(). Toutes les autres fonctions sont facultatives.

Fonctions de gestion du contexte

OSSL_FUNC_kdf_newctx() doit créer et retourner un pointeur vers une structure côté fournisseur pour contenir les informations de contexte pendant une opération KDF. Un pointeur vers ce contexte sera renvoyé dans un certain nombre d'autres appels de fonction d'opération KDF. Le paramètre provctx est le contexte du fournisseur généré lors de l'initialisation du fournisseur (voir provider(7)).

OSSL_FUNC_kdf_freectx() reçoit un pointeur vers le contexte KDF côté fournisseur dans le paramètre kctx. Si elle reçoit NULL comme valeur kctx, elle ne doit rien faire d'autre que de retourner. Cette fonction doit libérer toutes les ressources associées à ce contexte.

OSSL_FUNC_kdf_dupctx() doit dupliquer le contexte KDF côté fournisseur dans le paramètre kctx et retourner la copie dupliquée.

Fonctions de chiffrement/déchiffrement

OSSL_FUNC_kdf_reset() initialise une opération KDF après avoir traité les params conformément à OSSL_FUNC_kdf_set_ctx_params(). Le paramètre kctx contient un pointeur vers le contexte côté fournisseur. La clé résultante de la longueur keylen souhaitée doit être écrite dans key. Si l'algorithme ne prend pas en charge la longueur keylen demandée, la fonction doit retourner une erreur.

OSSL_FUNC_kdf_derive_skey() est similaire à OSSL_FUNC_kdf_derive() mais utilise un objet opaque pour stocker la clé dérivée. Il accepte le paramètre key_type pour donner un indice au fournisseur sur le type de clé (par exemple, générique ou AES) qui serait généré et la fonction import de l'objet EVP_SKEYMGMT à associer à la clé. L'objet EVP_SKEYMGMT provient du même fournisseur que le KDF lui-même.

Paramètres KDF

Voir OSSL_PARAM(3) pour plus de détails sur la structure des paramètres utilisée par ces fonctions.

OSSL_FUNC_kdf_get_params() obtient les détails des valeurs de paramètres associées à l'algorithme du fournisseur et les stocke dans params.

OSSL_FUNC_kdf_set_ctx_params() définit les paramètres KDF associés au contexte KDF côté fournisseur donné kctx à params. Tous les réglages de paramètres sont supplémentaires à ceux qui avaient été précédemment définis. Passer NULL pour params devrait retourner vrai.

OSSL_FUNC_kdf_get_ctx_params() récupère les valeurs de paramètres récupérables associées au contexte KDF côté fournisseur donné kctx et les stocke dans params. Passer NULL pour params devrait retourner vrai.

OSSL_FUNC_kdf_gettable_params(), OSSL_FUNC_kdf_gettable_ctx_params(), et OSSL_FUNC_kdf_settable_ctx_params() retournent tous des tableaux OSSL_PARAM(3) constants comme descripteurs des paramètres que OSSL_FUNC_kdf_get_params(), OSSL_FUNC_kdf_get_ctx_params(), et OSSL_FUNC_kdf_set_ctx_params() peuvent gérer, respectivement. OSSL_FUNC_kdf_gettable_ctx_params() et OSSL_FUNC_kdf_settable_ctx_params() retourneront les paramètres associés au contexte côté fournisseur kctx dans son état actuel s'il n'est pas NULL. Sinon, ils retourneront les paramètres associés à l'algorithme côté fournisseur provctx.

OSSL_FUNF_kdf_set_skey() définit la clé d'entrée pour les fonctions KDF qui prennent une clé en entrée.

Les paramètres actuellement reconnus par les KDF intégrés sont les suivants. Tous les paramètres ne sont pas pertinents ou compris par tous les KDF :

"size" (OSSL_KDF_PARAM_SIZE) <entier non signé>
Obtient la taille de sortie du contexte KDF associé. Si l'algorithme produit une quantité variable de sortie, SIZE_MAX doit être retourné. Si les paramètres d'entrée nécessaires pour calculer la taille de sortie fixe n'ont pas encore été fournis, 0 doit être retourné, indiquant une erreur.
"key" (OSSL_KDF_PARAM_KEY) <chaîne d'octets>
Définit la clé dans le contexte KDF associé.
"secret" (OSSL_KDF_PARAM_SECRET) <chaîne d'octets>
Définit le secret dans le contexte KDF associé.
"pass" (OSSL_KDF_PARAM_PASSWORD) <chaîne d'octets>
Définit le mot de passe dans le contexte KDF associé.

NAME

provider-kdf - OpenSSL KDF provider interface

SYNOPSIS

This manual page describes the KDF functions and parameters supported by the OpenSSL provider.

DESCRIPTION

The KDF (Key Derivation Function) functionality is implemented in the OpenSSL provider. Providers that implement KDFs should support the following functions:

OSSL_FUNC_KDF_NEWCTX
Create a new KDF context.
OSSL_FUNC_KDF_DUPCTX
Duplicate a KDF context.
OSSL_FUNC_KDF_FREECTX
Free a KDF context.
OSSL_FUNC_KDF_RESET
Reset a KDF context.
OSSL_FUNC_KDF_DERIVE
Derive key data from a KDF context.
OSSL_FUNC_KDF_GET_PARAMS
Get parameters from a KDF context.
OSSL_FUNC_KDF_GET_CTX_PARAMS
Get context specific parameters from a KDF context.
OSSL_FUNC_KDF_SET_CTX_PARAMS
Set context specific parameters in a KDF context.
OSSL_FUNC_KDF_GETTABLE_PARAMS
Get a constant parameter descriptor array for parameters that can be set/got on the KDF.
OSSL_FUNC_KDF_GETTABLE_CTX_PARAMS
Get a constant parameter descriptor array for context specific parameters that can be got from the KDF.
OSSL_FUNC_KDF_SETTABLE_CTX_PARAMS
Get a constant parameter descriptor array for context specific parameters that can be set on the KDF.
OSSL_FUNC_KDF_DERIVE_SKEY
Derive a standalone key using a KDF.
OSSL_FUNC_KDF_SET_SKEY
Set a standalone key for use in KDF operations.

The following parameters are supported by various KDFs. The exact set of supported parameters depends on the specific KDF implementation.

"digest" (OSSL_KDF_PARAM_DIGEST) <UTF8 string>
"mac" (OSSL_KDF_PARAM_MAC) <UTF8 string>
Définit le nom du chiffrement sous-jacent, du digest ou du MAC à utiliser. Il doit nommer un algorithme approprié pour le KDF utilisé.
"maclen" (OSSL_KDF_PARAM_MAC_SIZE) <octet string>
Définit la longueur du MAC dans le ctx KDF associé.
"properties" (OSSL_KDF_PARAM_PROPERTIES) <UTF8 string>
Définit les propriétés à interroger lors de la tentative de récupération de l'algorithme sous-jacent. Ceci doit être fourni avec le paramètre de nommage de l'algorithme pour être considéré comme valide.
"iter" (OSSL_KDF_PARAM_ITER) <unsigned integer>
Définit le nombre d'itérations dans le ctx KDF associé.
"mode" (OSSL_KDF_PARAM_MODE) <UTF8 string>
Définit le mode dans le ctx KDF associé.
"pkcs5" (OSSL_KDF_PARAM_PKCS5) <integer>
Active ou désactive les vérifications de conformité SP800-132. Un mode de 0 active les vérifications de conformité.

Les vérifications effectuées sont :

- le nombre d'itérations est au moins 1000.
- la longueur du salt est d'au moins 128 bits.
- la longueur de la clé dérivée est d'au moins 112 bits.
"ukm" (OSSL_KDF_PARAM_UKM) <octet string>
Définit une chaîne aléatoire facultative fournie par l'expéditeur appelée "partyAInfo". En CMS, il s'agit du matériel de clé utilisateur.
"cekalg" (OSSL_KDF_PARAM_CEK_ALG) <UTF8 string>
Définit le nom de l'algorithme de chiffrement CEK dans le ctx KDF associé.
"n" (OSSL_KDF_PARAM_SCRYPT_N) <unsigned integer>
Définit le paramètre de facteur de travail scrypt N dans le ctx KDF associé.
"r" (OSSL_KDF_PARAM_SCRYPT_R) <unsigned integer>
Définit le paramètre de facteur de travail scrypt r dans le ctx KDF associé.
"p" (OSSL_KDF_PARAM_SCRYPT_P) <unsigned integer>
Définit le paramètre de facteur de travail scrypt p dans le ctx KDF associé.
"maxmem_bytes" (OSSL_KDF_PARAM_SCRYPT_MAXMEM) <unsigned integer>
Définit le paramètre de facteur de travail scrypt maxmem dans le ctx KDF associé.
"prefix" (OSSL_KDF_PARAM_PREFIX) <octet string>
Définit la chaîne de préfixe utilisée par la version TLS 1.3 de HKDF dans le ctx KDF associé.
"label" (OSSL_KDF_PARAM_LABEL) <octet string>
Définit la chaîne de label utilisée par la version TLS 1.3 de HKDF dans le ctx KDF associé.
"data" (OSSL_KDF_PARAM_DATA) <octet string>
Définit la chaîne de contexte utilisée par la version TLS 1.3 de HKDF dans le ctx KDF associé.
"info" (OSSL_KDF_PARAM_INFO) <octet string>
Définit les informations partagées facultatives dans le ctx KDF associé.
"seed" (OSSL_KDF_PARAM_SEED) <octet string>
Définit l'IV dans le ctx KDF associé.
"xcghash" (OSSL_KDF_PARAM_SSHKDF_XCGHASH) <octet string>
Définit le xcghash dans le ctx KDF associé.
"session_id" (OSSL_KDF_PARAM_SSHKDF_SESSION_ID) <octet string>
Définit l'ID de session dans le ctx KDF associé.
"type" (OSSL_KDF_PARAM_SSHKDF_TYPE) <UTF8 string>
Définit le paramètre de type SSH KDF dans le ctx KDF associé. Six types sont pris en charge :
EVP_KDF_SSHKDF_TYPE_INITIAL_IV_CLI_TO_SRV
L'IV initial du client au serveur. Un seul caractère de valeur 65 (caractère ASCII 'A').
EVP_KDF_SSHKDF_TYPE_INITIAL_IV_SRV_TO_CLI
L'IV initial du serveur au client. Un seul caractère de valeur 66 (caractère ASCII 'B').
EVP_KDF_SSHKDF_TYPE_ENCRYPTION_KEY_CLI_TO_SRV
La clé de chiffrement du client au serveur. Un seul caractère de valeur 67 (caractère ASCII 'C').
EVP_KDF_SSHKDF_TYPE_ENCRYPTION_KEY_SRV_TO_CLI
La clé de chiffrement du serveur au client. Un seul caractère de valeur 68 (caractère ASCII 'D').
EVP_KDF_SSHKDF_TYPE_INTEGRITY_KEY_CLI_TO_SRV
La clé d'intégrité du client au serveur. Un seul caractère de valeur 69 (caractère ASCII 'E').
EVP_KDF_SSHKDF_TYPE_INTEGRITY_KEY_SRV_TO_CLI
La clé d'intégrité du client au serveur. Un seul caractère de valeur 70 (caractère ASCII 'F').
"constant" (OSSL_KDF_PARAM_CONSTANT) <octet string>
Définit la valeur constante dans le ctx KDF associé.
"id" (OSSL_KDF_PARAM_PKCS12_ID) <integer>
Définit l'utilisation prévue des bits de sortie dans le ctx KDF associé. Il est défini conformément à la RFC 7292 section B.3.

RETURN VALUES

OSSL_FUNC_kdf_newctx() et OSSL_FUNC_kdf_dupctx() devraient retourner le contexte KDF nouvellement créé côté fournisseur, ou NULL en cas d'échec.

OSSL_FUNC_kdf_derive(), OSSL_FUNC_kdf_derive_skey(), OSSL_FUNC_kdf_get_params(), OSSL_FUNC_kdf_get_ctx_params(), OSSL_FUNC_kdf_set_ctx_params() et OSSL_FUNC_kdf_set_skey() devraient retourner 1 en cas de succès ou 0 en cas d'erreur.

OSSL_FUNC_kdf_gettable_params(), OSSL_FUNC_kdf_gettable_ctx_params() et OSSL_FUNC_kdf_settable_ctx_params() devraient retourner un tableau constant d'OSSL_PARAM(3), ou NULL si aucun n'est offert.

NOTES

Le cycle de vie des KDF est décrit dans life_cycle-kdf(7). Les fournisseurs doivent s'assurer que les différentes transitions y sont prises en charge. À un moment donné, la couche EVP commencera à appliquer les transitions répertoriées.

SEE ALSO

provider(7), life_cycle-kdf(7), EVP_KDF(3).

HISTORY

L'interface du fournisseur KDF a été introduite dans OpenSSL 3.0.

OSSL_FUNC_kdf_derive_skey() et OSSL_FUNC_kdf_set_skey() ont été ajoutés dans OpenSSL 3.6.
