pread(2) Manuel des appels système pread(2)

NOM

pread, pwrite - lire depuis ou écrire vers un descripteur de fichier à un décalage donné

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
ssize_t pread(int fd, void buf[count], size_t count,
              off_t offset);
ssize_t pwrite(int fd, const void buf[count], size_t count,
               off_t offset);
Exigences relatives aux macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

pread(), pwrite() :

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.12 : */ _POSIX_C_SOURCE >= 200809L

DESCRIPTION

pread() lit jusqu'à count octets depuis le descripteur de fichier fd au décalage offset (depuis le début du fichier) dans le tampon commençant à buf. Le décalage du fichier n'est pas modifié.

pwrite() écrit jusqu'à count octets depuis le tampon commençant à buf vers le descripteur de fichier fd au décalage offset. Le décalage du fichier n'est pas modifié.

Le fichier référencé par fd doit être capable de rechercher.

VALEUR DE RETOUR

En cas de succès, pread() retourne le nombre d'octets lus (un retour de zéro indique la fin du fichier) et pwrite() retourne le nombre d'octets écrits.

Notez qu'il n'est pas considéré comme une erreur qu'un appel réussi transfère moins d'octets que demandé (voir read(2) et write(2)).

En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

pread() peut échouer et définir errno avec n'importe quelle erreur spécifiée pour read(2) ou lseek(2). pwrite() peut échouer et définir errno avec n'importe quelle erreur spécifiée pour write(2) ou lseek(2).

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001.

Ajouté dans Linux 2.1.60 ; les entrées dans la table des appels système i386 ont été ajoutées dans Linux 2.1.69. Le support de la bibliothèque C (y compris l'émulation utilisant lseek(2) sur les anciens noyaux sans les appels système) a été ajouté dans glibc 2.1.

Différences bibliothèque C/noyau

Sur Linux, les appels système sous-jacents ont été renommés dans Linux 2.6 : pread() est devenu pread64() et pwrite() est devenu pwrite64(). Les numéros d'appel système sont restés les mêmes. Les fonctions d'encapsulation pread() et pwrite() de glibc gèrent de manière transparente le changement.

Sur certaines architectures 32 bits, la signature d'appel pour ces appels système diffère, pour les raisons décrites dans syscall(2).

NOTES

Les appels système pread() et pwrite() sont particulièrement utiles dans les applications multithread. Ils permettent à plusieurs threads d'effectuer des E/S sur le même descripteur de fichier sans être affectés par les changements de décalage du fichier par d'autres threads.

BOGUES

POSIX exige que l'ouverture d'un fichier avec le drapeau O_APPEND n'ait aucun effet sur l'emplacement où pwrite() écrit les données. Cependant, sous Linux, si un fichier est ouvert avec O_APPEND, pwrite() ajoute les données à la fin du fichier, quelle que soit la valeur de offset.

VOIR AUSSI

lseek(2), read(2), readv(2), write(2)
