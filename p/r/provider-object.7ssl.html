NOM

provider-object - Une spécification pour une abstraction d'objet natif du fournisseur

SYNOPIS

#include <openssl/core_object.h>
#include <openssl/core_names.h>

DESCRIPTION

L'abstraction d'objet natif du fournisseur est un ensemble de clés et de valeurs OSSL_PARAM(3) qui peuvent être utilisées pour passer des objets natifs du fournisseur au code de la bibliothèque OpenSSL ou entre différentes implémentations d'opérations du fournisseur avec l'aide du code de la bibliothèque OpenSSL.

L'intention est que certaines opérations natives du fournisseur puissent passer n'importe quel type d'objet appartenant à d'autres opérations, ou au code de la bibliothèque OpenSSL.

Un objet peut être passé de la manière suivante :

1.
Par valeur

Cela signifie que les données de l'objet sont passées sous forme de chaîne d'octets ou de chaîne UTF8, ce qui peut être géré de diverses manières par d'autres implémentations fournies. L'encodage de l'objet dépend du contexte dans lequel il est utilisé ; par exemple, OSSL_DECODER(3) autorise plusieurs encodages, en fonction des décodeurs existants. Si les fonctionnalités centrales de la bibliothèque OpenSSL doivent traiter directement les données, elles doivent être encodées en DER pour tous les types d'objets, à l'exception de OSSL_OBJECT_NAME (voir "Référence des paramètres" ci-dessous), où elles sont supposées être une simple chaîne UTF8.

2.
Par référence

Cela signifie que les données de l'objet ne sont pas passées directement, une référence d'objet est passée à la place. Il s'agit d'une chaîne d'octets que seul le fournisseur correct comprend correctement.

Les objets par valeur peuvent être utilisés par tout ce qui gère des objets encodés en DER.

Les objets par référence nécessitent un niveau de coopération plus élevé de la part de l'implémentation d'où provient l'objet (appelons-la X) et de son implémentation cible (appelons-la Y) :

1.
Une fonction de chargement d'objet dans l'implémentation cible

L'implémentation cible (Y) peut avoir une fonction qui accepte une référence d'objet. Cela ne peut être utilisé que si l'implémentation cible provient du même fournisseur que celui qui est à l'origine de l'abstraction d'objet en question (X).

L'implémentation cible exacte à utiliser est déterminée par le type d'objet et potentiellement par le type de données de l'objet. Par exemple, lorsque la bibliothèque OpenSSL reçoit une abstraction d'objet avec le type d'objet OSSL_OBJECT_PKEY, elle récupérera un provider-keymgmt(7) en utilisant le type de données de l'objet comme type de clé (le deuxième argument dans EVP_KEYMGMT_fetch(3)).

2.
Un exportateur d'objets dans l'implémentation d'origine

L'implémentation d'origine (X) peut avoir une fonction d'exportation. Cette fonction d'exportation peut être utilisée pour exporter l'objet sous forme de OSSL_PARAM(3), qui pourra ensuite être importé par la fonction importée de l'implémentation cible.

Cela peut être utilisé lorsqu'il n'est pas possible de récupérer l'implémentation cible (Y) du même fournisseur.

Référence des paramètres

Une abstraction d'objet natif du fournisseur est un OSSL_PARAM(3) avec une sélection des paramètres suivants :

"data" (OSSL_OBJECT_PARAM_DATA) <chaîne d'octets> ou <chaîne UTF8>
Les données de l'objet passées par valeur.
"reference" (OSSL_OBJECT_PARAM_REFERENCE) <chaîne d'octets>
Les données de l'objet passées par référence.
"type" (OSSL_OBJECT_PARAM_TYPE) <entier>
Le type d'objet, un nombre qui peut avoir l'une des valeurs suivantes (toutes définies dans <openssl/core_object.h>) :
OSSL_OBJECT_NAME
Les données de l'objet ne peuvent être passées que par valeur et doivent être une chaîne UTF8.

Ceci est utile pour provider-storemgmt(7) lorsqu'un chargement d'URI aboutit à de nouveaux URI.

OSSL_OBJECT_PKEY
Les données de l'objet conviennent en tant que données de clé EVP_PKEY natives du fournisseur. Les données de l'objet peuvent être passées par valeur ou passées par référence.
OSSL_OBJECT_CERT
Les données de l'objet conviennent en tant que données X509. Les données de l'objet pour ce type d'objet ne peuvent être passées que par valeur et doivent être une chaîne d'octets.

Comme il n'existe pas d'objet X.509 natif du fournisseur, les bibliothèques OpenSSL qui reçoivent cette abstraction d'objet sont censées convertir les données en un objet X509 avec d2i_X509().

OSSL_OBJECT_CRL
Les données de l'objet conviennent en tant que données X509_CRL. Les données de l'objet ne peuvent être passées que par valeur et doivent être une chaîne d'octets.

Comme il n'existe pas d'objet CRL X.509 natif du fournisseur, les bibliothèques OpenSSL qui reçoivent cette abstraction d'objet sont censées convertir les données en un objet X509_CRL avec d2i_X509_CRL().

"data-type" (OSSL_OBJECT_PARAM_DATA_TYPE) <chaîne UTF8>
Le type spécifique du contenu de l'objet. Les valeurs légitimes dépendent du type d'objet ; s'il s'agit de OSSL_OBJECT_PKEY, le type de données est censé être un type de clé approprié pour récupérer un provider-keymgmt(7) capable de gérer les données.
"data-structure" (OSSL_OBJECT_PARAM_DATA_STRUCTURE) <chaîne UTF8>
La structure externe du contenu de l'objet. Les valeurs légitimes dépendent du type d'objet.
"desc" (OSSL_OBJECT_PARAM_DESC) <chaîne UTF8>
Un texte lisible par l'homme qui décrit des détails supplémentaires sur l'objet.

Lorsqu'une abstraction d'objet natif du fournisseur est utilisée, elle doit contenir des données d'objet dans au moins une forme (données d'objet passées par valeur, c'est-à-dire l'élément "data", ou données d'objet passées par référence, c'est-à-dire l'élément "reference"). Les deux peuvent être présents simultanément, auquel cas le code de la bibliothèque OpenSSL qui reçoit ceci utilisera la variante la plus optimale.

Pour les objets avec le type d'objet OSSL_OBJECT_NAME, ce type d'objet doit être donné.
