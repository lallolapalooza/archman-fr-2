PROXYMAP(8) Manuel de l'administrateur système PROXYMAP(8)

NOM

proxymap - Serveur proxy de table de recherche Postfix

SYNTAXE

proxymap [options génériques de démon Postfix]

DESCRIPTION


Le serveur proxymap(8) fournit un service de recherche de tables en lecture seule ou en lecture/écriture aux processus Postfix. Ces services sont implémentés avec des noms de services distincts : proxymap et proxywrite, respectivement. Le but de ces services est :

  • De surmonter les restrictions de chroot. Par exemple, un serveur SMTP chrooté a besoin d'accéder au fichier passwd du système afin de rejeter le courrier destiné aux adresses locales inexistantes, mais il n'est pas pratique de maintenir une copie du fichier passwd dans le jail chroot. La solution : 
    local_recipient_maps =
    proxy:unix:passwd.byname $alias_maps
  • De consolider le nombre de tables de recherche ouvertes en partageant une table ouverte entre plusieurs processus. Par exemple, établir des connexions mysql depuis chaque processus démon Postfix entraîne des erreurs de type "trop de connexions". La solution : 
    virtual_alias_maps =
    proxy:mysql:/etc/postfix/virtual_alias.cf

    Le nombre total de connexions est limité par le nombre de processus serveur proxymap.

  • De fournir une fonctionnalité de mise à jour unique pour les tables de recherche qui ne supportent pas de manière fiable les écritures multiples (c'est-à-dire toutes les tables basées sur des fichiers qui ne sont pas basées sur lmdb).

Le serveur proxymap(8) implémente les requêtes suivantes :

open type_carte:nom_carte indicateurs
Ouvre la table avec le type type_carte et le nom nom_carte, tels que contrôlés par indicateurs. La réponse inclut les indicateurs dépendants du type_carte (pour distinguer une table de chaînes fixes d'une table d'expressions régulières).
lookup type_carte:nom_carte indicateurs clé
Recherche les données stockées sous la clé demandée. La réponse est le code d'état d'achèvement de la requête et la valeur du résultat de la recherche. Le type_carte:nom_carte et les indicateurs sont les mêmes qu'avec la requête open.
update type_carte:nom_carte indicateurs clé valeur
Met à jour les données stockées sous la clé demandée. La réponse est le code d'état d'achèvement de la requête. Le type_carte:nom_carte et les indicateurs sont les mêmes qu'avec la requête open.

Pour implémenter des cartes à mise à jour unique, spécifiez une limite de processus de 1 dans l'entrée master.cf pour le service proxywrite.

Cette requête est prise en charge à partir de Postfix 2.5.

delete type_carte:nom_carte indicateurs clé
Supprime les données stockées sous la clé demandée. La réponse est le code d'état d'achèvement de la requête. Le type_carte:nom_carte et les indicateurs sont les mêmes qu'avec la requête open.

Cette requête est prise en charge à partir de Postfix 2.5.

sequence type_carte:nom_carte indicateurs fonction
Itère sur la base de données spécifiée. La fonction est l'une des DICT_SEQ_FUN_FIRST ou DICT_SEQ_FUN_NEXT. La réponse est le code d'état d'achèvement de la requête et une clé de recherche et une valeur de résultat, si trouvées.

Cette requête est prise en charge à partir de Postfix 2.9.

Le statut d'achèvement de la requête est l'un des suivants : OK, RETRY, NOKEY (recherche échouée car la clé n'a pas été trouvée), BAD (requête malformée) ou DENY (la table n'est pas approuvée pour l'accès en lecture ou écriture proxy).

Il n'y a pas de commande close, et les tables ne sont pas non plus fermées implicitement lorsqu'un client se déconnecte. Le but est de partager les tables entre plusieurs processus clients.

GESTION DES PROCESSUS SERVEUR

Les serveurs proxymap(8) sont exécutés sous le contrôle du serveur master(8) de Postfix. Chaque serveur peut gérer plusieurs connexions simultanées. Lorsque tous les serveurs sont occupés pendant qu'un client se connecte, le serveur master(8) crée un nouveau processus serveur proxymap(8), à condition que la limite de processus ne soit pas dépassée. Chaque serveur se termine après avoir servi au moins $max_use clients ou après $max_idle secondes d'inactivité.

SÉCURITÉ

proxymap(8) n'ouvre que les tables approuvées via les paramètres de configuration proxy_read_maps ou proxy_write_maps, ne communique pas avec les utilisateurs et peut être exécuté avec des privilèges bas fixes, chrooté ou non. Cependant, l'exécution du serveur proxymap en chroot limite sévèrement son utilité, car il ne peut ouvrir que des tables chrootées.

Le serveur proxymap(8) n'est pas un processus démon de confiance, et ne doit pas être utilisé pour rechercher des informations sensibles telles que les identifiants d'utilisateur ou de groupe UNIX, les noms de fichiers/répertoires de boîtes aux lettres ou les commandes externes.

Dans Postfix version 2.2 et ultérieures, le client proxymap reconnaît les requêtes visant à accéder à une table à des fins de sécurité sensibles et ouvre la table directement. Cela permet d'utiliser le même paramètre main.cf par des processus sensibles et non sensibles.

Les fichiers de données modifiables par Postfix doivent être stockés dans un répertoire dédié qui n'est accessible en écriture que par le système de messagerie Postfix, tel que le data_directory appartenant à Postfix.

En particulier, les fichiers modifiables par Postfix ne doivent jamais exister dans des répertoires appartenant à root. Cela ouvrirait une faille de sécurité particulière où la propriété d'un fichier ou d'un répertoire ne correspondrait pas au fournisseur de son contenu.

DIAGNOSTICS


Les problèmes et les transactions sont enregistrés dans syslogd(8) ou postlogd(8).

BOGUES


Le serveur proxymap(8) fournit un service à plusieurs clients, et ne doit donc pas être utilisé pour des tables dont les recherches ont une latence élevée.

Le service de lecture/écriture de proxymap(8) ne ferme pas explicitement les tables de recherche (même s'il le faisait, cela ne pourrait pas être fiable, car le processus pourrait être terminé entre les mises à jour des tables). Le service de lecture/écriture ne doit donc pas être utilisé avec des tables qui laissent le stockage persistant dans un état incohérent entre les mises à jour (par exemple, CDB). Les tables qui supportent la "synchronisation à la mise à jour" devraient être sûres (par exemple, Berkeley DB), tout comme les tables implémentées par un véritable SGBD.

PARAMÈTRES DE CONFIGURATION

Sur les systèmes de messagerie très chargés, un long délai peut s'écouler avant que les changements pertinents de main.cf ne soient pris en compte par proxymap(8). Utilisez la commande "postfix reload" pour accélérer une modification.

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
data_directory (voir la sortie de 'postconf -d')
Le répertoire contenant les fichiers de données modifiables par Postfix (par exemple : caches, nombres pseudo-aléatoires).
daemon_timeout (18000s)
Le temps dont dispose un processus démon Postfix pour traiter une requête avant d'être terminé par un mécanisme de surveillance intégré.
ipc_timeout (3600s)
La limite de temps pour l'envoi ou la réception d'informations sur un canal de communication interne.
max_idle (100s)
La durée maximale pendant laquelle un processus démon Postfix inactif attend une connexion entrante avant de se terminer volontairement.
max_use (100)
Le nombre maximal de connexions entrantes qu'un processus démon Postfix traitera avant de se terminer volontairement.
process_id
L'identifiant de processus du démon.

proxymap(8) — Postfix proxy daemon

NAME

proxymap - Postfix proxy lookup server

SYNOPSIS

    proxymap, bounce, confirm, filter, forward, proba, scache, trace, verify

DESCRIPTION

The proxymap(8) server implements the Postfix proxy lookup table interface. It is used to access external lookup tables, such as those provided by network databases (e.g. LDAP, SQL) or by other Postfix lookup table types that are not directly supported by the main Postfix MTA.

The proxymap(8) server acts as a client to the Postfix lookup service. It receives lookup requests from Postfix, queries one or more external lookup tables, and returns the results to Postfix. The set of accessible lookup tables is controlled by the proxy_read_maps and proxy_write_maps parameters.

The proxymap(8) server supports the following lookup table types:

hash:
Standard hash tables.
btree:
Standard btree tables.
nis:
Network Information Service (NIS) maps.
ldap:
Lightweight Directory Access Protocol (LDAP) directories.
mysql:
MySQL databases.
pgsql:
PostgreSQL databases.
tcp:
TCP socket based lookup services.
unix:
UNIX domain socket based lookup services.
memcache:
Memcached distributed memory caching system.
redis:
Redis key-value store.

The actual lookup service is implemented by a separate process. proxymap(8) forwards lookup requests to this service. The supported service types are determined by the Postfix build configuration. Consult the output of postconf -m for a list of supported lookup table types.

SERVER PROCESS MANAGEMENT

The proxymap(8) server is started and managed by the Postfix master(5) process. The master(5) process spawns new proxymap(8) servers as needed to handle incoming lookup requests. The number of proxymap(8) servers is controlled by the max_proc parameter in the master.cf file.

SECURITY

The proxymap(8) server runs as a non-privileged user, typically postfix. It accesses lookup tables via the Postfix lookup service interface. This interface provides an abstraction layer that shields the proxymap(8) server from direct access to sensitive data. The proxy_read_maps and proxy_write_maps parameters control which lookup tables the proxymap(8) server is allowed to access.

DIAGNOSTICS

Error messages are logged to the Postfix log file, typically /var/log/mail.log. The log level can be adjusted using the debugger_token parameter in the main.cf file.

BUGS

The proxymap(8) server supports a limited number of lookup table types. For a full list of supported types, consult the Postfix documentation.

The proxymap(8) server does not support all features of all lookup table types. For example, some lookup table types may not support wildcard lookups or ordered iteration.

CONFIGURATION PARAMETERS

The following configuration parameters are available:

process_id (read-only)
L'identifiant du processus d'une commande ou d'un processus démon Postfix.
process_name (read-only)
Le nom du processus d'une commande ou d'un processus démon Postfix.
proxy_read_maps (voir la sortie de 'postconf -d')
Les tables de correspondance auxquelles le serveur proxymap(8) est autorisé à accéder pour le service en lecture seule.

Disponible dans Postfix 2.5 et versions ultérieures :

data_directory (voir la sortie de 'postconf -d')
Le répertoire contenant les fichiers de données inscriptibles par Postfix (par exemple : caches, nombres pseudo-aléatoires).
proxy_write_maps (voir la sortie de 'postconf -d')
Les tables de correspondance auxquelles le serveur proxymap(8) est autorisé à accéder pour le service en lecture-écriture.

Disponible dans Postfix 3.3 et versions ultérieures :

service_name (read-only)
Le nom du service master.cf d'un processus démon Postfix.
