NOM

projinfo - Requêtes d'objets géodésiques et d'opérations de coordonnées

SYNTAXE

projinfo
[-o formats] [-k crs|operation|datum|ensemble|ellipsoid] [--summary] [-q]
[[--area nom_ou_code] | [--bbox ouest_long,sud_lat,est_long,nord_lat]]
[--spatial-test contains|intersects]
[--crs-extent-use none|both|intersection|smallest]
[--grid-check none|discard_missing|sort|known_available]
[--pivot-crs always|if_no_direct_transformation|never|{auth:code[,auth:code]*}]
[--show-superseded] [--hide-ballpark] [--accuracy {précision}]
[--allow-ellipsoidal-height-as-vertical-crs]
[--boundcrs-to-wgs84]
[--authority nom]
[--main-db-path chemin] [--aux-db-path chemin]*
[--dump-db-structure]
[--identify] [--3d]
[--output-id AUTH:CODE]
[--c-ify] [--single-line]
--searchpaths | --remote-data |
--list-crs [filtre-liste-crs] |
--dump-db-structure [{définition-objet} | {référence-objet}] |
{définition-objet} | {référence-objet} |
(-s {déf-sr} [--s_epoch {époque}] -t {déf-sr} [--t_epoch {époque}]) |
({déf-sr} {déf-sr})

où {définition-objet} ou {déf-sr} est une des possibilités acceptées par proj_create()

  • une chaîne proj,
  • une chaîne WKT,
  • un code d'objet (comme "EPSG:4326", "urn:ogc:def:crs:EPSG::4326", "urn:ogc:def:coordinateOperation:EPSG::1671"),
  • un nom d'objet. Par ex. "WGS 84", "WGS 84 / UTM zone 31N". Dans ce cas, comme l'unicité n'est pas garantie, des heuristiques sont appliquées pour déterminer la meilleure correspondance appropriée.
  • un nom de CRS et une époque de coordonnées, séparés par "@". Par exemple "ITRF2014@2025.0". (ajouté en 9.2)
  • une URN OGC combinant des références pour des systèmes de coordonnées référentiels composés (par ex. "urn:ogc:def:crs,crs:EPSG::2393,crs:EPSG::5717" ou syntaxe abrégée personnalisée "EPSG:2393+5717"),
  • une URN OGC combinant des références pour des références pour des CRS projetés ou dérivés, par ex. pour un CRS 3D projeté "UTM zone 31N / WGS 84 (3D)": "urn:ogc:def:crs,crs:EPSG::4979,cs:PROJ::ENh,coordinateOperation:EPSG::16031" (ajouté en 6.2)
  • Extension de l'URN OGC pour CoordinateMetadata. Par ex. "urn:ogc:def:CoordinateMetadata:NRCAN::NAD83_CSRS_1997_MTM11_HT2_1997"
  • une URN OGC combinant des références pour des opérations concaténées (par ex. "urn:ogc:def:coordinateOperation,coordinateOperation:EPSG::3895,coordinateOperation:EPSG::1618")
  • une chaîne PROJJSON. Le schéma est disponible sur https://proj.org/schemas/v0.4/projjson.schema.json (ajouté en 6.2)
  • un CRS composé à partir de deux noms d'objet séparés par " + ". Par ex. "WGS 84 + hauteur EGM96" (ajouté en 7.1)

{référence-objet} est un nom de fichier précédé du caractère '@'. Le fichier référencé par {référence-objet} doit contenir une {définition-objet} valide.

L'utilisation de "{déf-sr} {déf-sr}" est équivalente à "-s {déf-sr} -t {déf-sr}" (ajouté en 9.5).

DESCRIPTION

projinfo est un programme qui peut interroger des informations sur un objet géodésique, un système de coordonnées référentielles (CRS) ou une opération de coordonnées, lorsque les options -s et -t sont spécifiées, et l'afficher sous différents formats (chaîne PROJ, chaîne WKT ou chaîne PROJJSON).

Il peut également être utilisé pour interroger les opérations de coordonnées disponibles entre deux CRS.

Les paramètres de contrôle suivants peuvent apparaître dans n'importe quel ordre :

-o formats
formats est une combinaison séparée par des virgules de : all, default, PROJ, WKT_ALL, WKT2:2015, WKT2:2019, WKT1:GDAL, WKT1:ESRI, PROJJSON, SQL.

Sauf all et default, d'autres formats peuvent être précédés de - pour les désactiver.

NOTE :

WKT2_2019 était précédemment appelé WKT2_2018.

NOTE :

Avant PROJ 6.3.0, WKT1:GDAL appelait implicitement --boundcrs-to-wgs84. Ce n'est plus le cas.

NOTE :

Lorsque SQL est spécifié, --output-id doit être spécifié.
-k crs|operation|datum|ensemble|ellipsoid
Lorsqu'il est utilisé pour interroger un objet unique avec un CODE:AUTORITE, détermine le (k) type d'objet dans le cas où il existe des CRS, des opérations de coordonnées ou des ellipsoïdes avec le même CODE. La valeur par défaut est crs.
--summary
Lors de la liste des opérations de coordonnées disponibles entre 2 CRS, renvoie le résultat sous forme de résumé, ne mentionnant que le nom de l'opération de coordonnées, sa précision et sa zone d'utilisation.

NOTE :

utilisé uniquement pour le calcul d'opérations de coordonnées
-q
Active le mode silencieux. Le mode silencieux n'est disponible que pour les requêtes sur des objets uniques, et un seul format de sortie est sélectionné. Dans ce mode, seule la chaîne PROJ, WKT ou PROJJSON est affichée, sans autre introduction. La sortie peut alors potentiellement être redirigée vers d'autres utilitaires.
--area nom_ou_code
Spécifie une zone d'intérêt pour restreindre les résultats lors de la recherche d'opérations de coordonnées entre 2 CRS. La zone d'intérêt peut être spécifiée soit par un nom (par ex. "Danemark - terrestre") soit par un CODE:AUTORITE (EPSG:3237). Cette option est exclusive de --bbox.

NOTE :

utilisé uniquement pour le calcul d'opérations de coordonnées
--bbox ouest_long,sud_lat,est_long,nord_lat
Spécifie une zone d'intérêt pour restreindre les résultats lors de la recherche d'opérations de coordonnées entre 2 CRS. La zone d'intérêt est spécifiée comme une boîte englobante avec des coordonnées géographiques, exprimées en degrés dans un CRS géographique non spécifié. ouest_long et est_long doivent être dans la plage [-180,180], et sud_lat et nord_lat dans la plage [-90,90]. ouest_long est généralement inférieur à est_long, sauf dans le cas où la zone d'intérêt traverse l'antiméridien.

NOTE :

utilisé uniquement pour le calcul d'opérations de coordonnées
--spatial-test contains|intersects
Spécifie comment les zones d'utilisation des opérations de coordonnées trouvées dans la base de données sont comparées aux zones d'utilisation spécifiées explicitement avec --area ou --bbox, ou dérivées implicitement des zones d'utilisation des CRS source et cible. Par défaut, projinfo ne conservera que les opérations de coordonnées dont la zone d'utilisation est strictement comprise dans la zone d'intérêt (stratégie contains). En utilisant la stratégie intersects, le test spatial est assoupli, et toute opération de coordonnées dont la zone d'utilisation croise au moins partiellement la zone d'intérêt sera listée.

NOTE :

utilisé uniquement pour le calcul d'opérations de coordonnées
--crs-extent-use none|both|intersection|smallest
Spécifie quelle zone d'intérêt considérer lorsqu'aucune zone explicite n'est spécifiée avec les options --area ou --bbox. Par défaut (stratégie smallest), la zone d'utilisation du CRS source ou cible sera recherchée, et celle qui est la plus petite en termes de surface sera utilisée comme zone d'intérêt. En utilisant none, aucune zone d'intérêt n'est utilisée. En utilisant both, seules les opérations de coordonnées qui se rapportent (contiennent ou intersectent selon la stratégie --spatial-test) aux zones d'utilisation des deux CRS sont sélectionnées.

NOTE :

utilisé uniquement pour le calcul des opérations de coordonnées
--grid-check none|discard_missing|sort|known_available
Spécifie comment la présence ou l'absence d'une grille de décalage horizontale ou verticale requise pour une opération de coordonnées affecte les résultats retournés lors de la recherche d'opérations de coordonnées entre 2 CRS. La stratégie par défaut est sort (si PROJ_NETWORK n'est pas défini). Dans ce cas, toutes les opérations candidates sont retournées, mais la disponibilité réelle des grilles est utilisée pour déterminer l'ordre de tri. C'est-à-dire que si une opération de coordonnées implique l'utilisation d'une grille qui n'est pas disponible dans les répertoires de ressources PROJ (déterminé par la variable d'environnement PROJ_DATA), elle sera listée en bas des résultats. La stratégie none désactive complètement les vérifications de présence des grilles et retourne les résultats comme si toutes les grilles étaient disponibles. La stratégie discard_missing rejette les résultats qui impliquent des grilles non présentes dans les répertoires de ressources PROJ. La stratégie known_available rejette les résultats qui impliquent des grilles non présentes dans les répertoires de ressources PROJ et qui ne sont pas connues du CDN. C'est la stratégie par défaut si PROJ_NETWORK est défini sur ON.

NOTE :

utilisé uniquement pour le calcul des opérations de coordonnées
--pivot-crs always|if_no_direct_transformation|never|{auth:code[,auth:code]*}
Détermine si des CRS intermédiaires (pivot) peuvent être utilisés lors de la recherche d'une opération de coordonnées entre 2 CRS. Un exemple typique est le pivot WGS84. Par défaut, projinfo considérera tout pivot potentiel s'il n'y a pas de transformation directe ( if_no_direct_transformation). Si vous utilisez la stratégie never, seules les transformations directes entre le CRS source et cible seront utilisées. Si vous utilisez la stratégie always, des CRS intermédiaires seront considérés même s'il existe des transformations directes. Il est également possible de limiter les CRS pivots à considérer en spécifiant un ou plusieurs CRS par leur AUTORITÉ:CODE.

NOTE :

utilisé uniquement pour le calcul des opérations de coordonnées
--show-superseded
Lorsqu'activé, les opérations de coordonnées qui sont remplacées par d'autres seront listées. Notez que le remplacement n'est pas équivalent à la dépréciation : les opérations remplacées sont toujours considérées comme valides bien qu'elles aient un équivalent meilleur, tandis que les opérations dépréciées ont été jugées erronées et ne sont pas du tout considérées.

NOTE :

utilisé uniquement pour le calcul des opérations de coordonnées
--hide-ballpark
Ajouté dans la version 7.1.

Masque toute opération de coordonnées qui est, ou contient, une transformation Ballpark.

NOTE :

utilisé uniquement pour le calcul des opérations de coordonnées
--accuracy {accuracy}
Ajouté dans la version 8.0.

Définit la précision minimale souhaitée pour les opérations de coordonnées retournées.

NOTE :

utilisé uniquement pour le calcul des opérations de coordonnées
--allow-ellipsoidal-height-as-vertical-crs
Ajouté dans la version 8.0.

Permet d'exporter un CRS géographique ou projeté 3D comme un CRS composé dont le CRS vertical représente la hauteur ellipsoïdale.

NOTE :

utilisé uniquement pour les CRS, et avec le format de sortie WKT1:GDAL
--boundcrs-to-wgs84
Lorsqu'elle est spécifiée, cette option recherche une opération de coordonnées du CRS géographique de base du CRS unique, source ou cible, vers le CRS géographique WGS84, et si elle est trouvée, encapsule ces CRS dans un objet BoundCRS. Ceci est principalement destiné à être utilisé pour les approches de liaison anticipée.
--authority name
Spécifie le nom de l'autorité dans laquelle restreindre les recherches d'objets, lors de la spécification d'un objet par nom ou lors du calcul des opérations de coordonnées. Par défaut, toutes les autorités sont autorisées.

Lorsqu'il est utilisé avec la sortie SQL, cela restreint les autorités auxquelles les objets intermédiaires peuvent appartenir (par défaut EPSG et PROJ). Notez que l'autorité de l'option --output-id sera également ajoutée implicitement.

--main-db-path path
Spécifie le nom et le chemin de la base de données à utiliser par projinfo. Par défaut, il s'agit de proj.db dans les répertoires de ressources PROJ.
--aux-db-path path
Spécifie le nom et le chemin des bases de données auxiliaires, qui doivent être combinées avec la base de données principale. Ces bases de données auxiliaires doivent avoir une structure de table identique à celle de la base de données principale, mais peuvent être partiellement remplies et leurs entrées peuvent faire référence à des entrées de la base de données principale. L'option peut être répétée pour spécifier plusieurs bases de données auxiliaires.
--identify
Lorsqu'il est utilisé avec une définition d'objet, cela interroge la base de données PROJ pour trouver des objets connus, généralement des CRS, qui sont proches ou identiques à l'objet. Chaque objet candidat est associé à un pourcentage de probabilité approximatif. Ceci est utile lorsqu'il est utilisé avec une chaîne WKT qui manque un identifiant EPSG, comme le WKT1 ESRI. Cela peut également être utilisé avec des chaînes PROJ. Par exemple, +proj=utm +zone=31 +datum=WGS84 +type=crs sera identifié avec une probabilité de 70% à EPSG:32631
--dump-db-structure
Ajouté dans la version 8.1.

Affiche la séquence d'instructions SQL pour créer une nouvelle base de données auxiliaire vide valide. Cette option peut être spécifiée comme le seul commutateur de l'utilitaire. Si vous spécifiez également un objet CRS et l'option --output-id, la définition de l'objet sous forme d'instructions SQL sera ajoutée.

--list-crs [list-crs-filter]
Ajouté dans la version 8.1.

Affiche une liste (nom d'autorité:code et nom du CRS) des CRS filtrés de la base de données. Si aucun filtre n'est fourni, tous les noms d'autorité et types de CRS non dépréciés sont affichés. list-crs-filter est une combinaison séparée par des virgules de : allow_deprecated,geodetic,geocentric, geographic,geographic_2d,geographic_3d,vertical,projected,compound. Est affecté par les options --authority, --area, --bbox et --spatial-test.

--3d
Ajouté dans la version 6.3.

"Promouvoir" les CRS 2D en leur version 3D, où l'axe vertical est la hauteur ellipsoïdale en mètres, en utilisant l'ellipsoïde du CRS géodésique de base. Selon les versions de PROJ et la nature exacte des CRS impliqués, en particulier avant PROJ 9.1, un mélange de CRS 2D et 3D pourrait conduire à des transformations 2D ou 3D. À partir de PROJ 9.1, les deux CRS doivent être 3D pour qu'une transformation verticale puisse se produire.

--output-id=AUTH:NAME
Ajouté dans la version 8.1.

Identifiant à attribuer à l'objet (pour la sortie SQL).

Combiné avec --dump-db-structure, les utilisateurs peuvent créer des bases de données auxiliaires, au lieu de modifier directement la base de données principale proj.db. Voir l'exemple comment exporter vers une base de données auxiliaire.

Ces bases de données auxiliaires peuvent être spécifiées via proj_context_set_database_path() ou la variable d'environnement PROJ_AUX_DB.

--c-ify
Pour les développeurs uniquement. Modifie la sortie texte de l'utilitaire de manière à ce qu'il soit facile d'insérer ces chaînes dans du code C/C++.
--single-line
Affiche les chaînes PROJ, WKT ou PROJJSON sur une seule ligne, au lieu de plusieurs lignes indentées par défaut.
--searchpaths
Ajouté dans la version 7.0.

Affiche les répertoires dans lesquels les ressources PROJ seront recherchées (si vous n'utilisez pas l'API C telle que proj_context_set_search_paths() qui les remplacera).

--remote-data
Ajouté dans la version 7.0.

Affiche des informations concernant l'activation des capacités réseau et l'URL associée.

--s_epoch
/dt>
Ajouté dans la version 9.4.

Époque des coordonnées dans le SCR source, en année décimale. S'applique uniquement à un SCR dynamique.

--t_epoch
Ajouté dans la version 9.4.

Époque des coordonnées dans le SCR cible, en année décimale. S'applique uniquement à un SCR dynamique.
