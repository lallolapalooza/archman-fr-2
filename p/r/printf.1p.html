PRINTF(1P) Manuel du programmeur POSIX PRINTF(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

printf — écrire une sortie formatée

SYNTAXE

printf format [argument...]

DESCRIPTION

L'utilitaire printf écrit les opérandes formatés sur la sortie standard. Les opérandes argument sont formatés sous le contrôle de l'opérande format.

OPTIONS

Aucune.

OPÉRANDES

Les opérandes suivants sont pris en charge :

format
Une chaîne décrivant le format à utiliser pour écrire les opérandes restants. Voir la section DESCRIPTION ÉTENDUE.
argument
Les chaînes à écrire sur la sortie standard, sous le contrôle de format. Voir la section DESCRIPTION ÉTENDUE.

ENTRÉE STANDARD

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de printf :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1-2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories locales.)
LC_ALL
Si définie à une chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
LC_NUMERIC

Détermine la locale pour le formatage numérique. Elle affecte le format des nombres écrits à l'aide des caractères de spécification de conversion e, E, f, g et G (si pris en charge).
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Voir la section DESCRIPTION ÉTENDUE.

ERREUR STANDARD

La sortie d'erreur standard est utilisée uniquement pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

L'opérande format est utilisé comme chaîne de format décrite dans le volume Définitions de base de POSIX.1-2017, Chapitre 5, Notation de format de fichier avec les exceptions suivantes :

1.
Un <espace> dans la chaîne de format, dans un contexte autre qu'un indicateur d'une spécification de conversion, est traité comme un caractère ordinaire qui est copié dans la sortie.
2.
Un caractère '' dans la chaîne de format est traité comme un caractère '', et non comme un <espace>.
3.
En plus des séquences d'échappement indiquées dans le volume Définitions de base de POSIX.1-2017, Chapitre 5, Notation de format de fichier ('\\', '\a', '\b', '\f', '\n', '\r', '\t', '\v'), "\ddd", où ddd est un nombre octal de un, deux ou trois chiffres, est écrit comme un octet avec la valeur numérique spécifiée par le nombre octal.
4.
L'implémentation ne doit pas précéder ou suivre la sortie des spécificateurs de conversion d ou u avec des caractères <espace> non spécifiés par l'opérande format.
5.
L'implémentation ne doit pas précéder la sortie du spécificateur de conversion o avec des zéros non spécifiés par l'opérande format.
6.
Les spécificateurs de conversion a, A, e, E, f, F, g et G ne sont pas obligatoirement pris en charge.
7.
Un caractère de spécification de conversion supplémentaire, b, est pris en charge comme suit. L'argument est considéré comme une chaîne pouvant contenir des séquences d'échappement <backslash>. Les séquences d'échappement <backslash> suivantes sont prises en charge :
--
Les séquences d'échappement indiquées dans le volume Définitions de base de POSIX.1-2017, Chapitre 5, Notation de format de fichier ('\\', '\a', '\b', '\f', '\n', '\r', '\t', '\v'), qui sont converties en caractères qu'elles représentent.
--
"\0ddd", où ddd est un nombre octal de zéro, un, deux ou trois chiffres qui est converti en un octet avec la valeur numérique spécifiée par le nombre octal.
--
'\c', qui n'est pas écrit et provoque l'arrêt de printf en ignorant tous les caractères restants dans l'opérande chaîne qui le contient, tous les opérandes chaîne restants, et tous les caractères supplémentaires dans l'opérande format.

L'interprétation d'un <backslash> suivi de toute autre séquence de caractères n'est pas spécifiée.

Les octets de la chaîne convertie sont écrits jusqu'à la fin de la chaîne ou jusqu'à ce que le nombre d'octets indiqué par la spécification de précision soit atteint. Si la précision est omise, elle est considérée comme infinie, donc tous les octets jusqu'à la fin de la chaîne convertie sont écrits.

8.
Pour chaque spécification de conversion qui consomme un argument, l'opérande argument suivant est évalué et converti dans le type approprié pour la conversion comme spécifié ci-dessous.
9.
L'opérande format est réutilisé autant de fois que nécessaire pour satisfaire les opérandes argument. Toute spécification de conversion b, c ou s supplémentaire est évaluée comme si un opérande chaîne nul était fourni ; d'autres spécifications de conversion supplémentaires sont évaluées comme si un argument zéro était fourni. Si l'opérande format ne contient aucune spécification de conversion et que des opérandes argument sont présents, les résultats ne sont pas spécifiés.
10.
Si une séquence de caractères dans l'opérande format commence par un caractère '%', mais ne forme pas une spécification de conversion valide, le comportement n'est pas spécifié.
11.
L'argument de la spécification de conversion c peut être une chaîne contenant zéro ou plusieurs octets. Si elle contient un ou plusieurs octets, le premier octet est écrit et tous les octets supplémentaires sont ignorés. Si l'argument est une chaîne vide, il n'est pas spécifié si rien n'est écrit ou si un octet nul est écrit.

Les opérandes argument sont traités comme des chaînes si la spécification de conversion correspondante est b, c ou s, et sont évalués comme par la fonction strtod() si la spécification de conversion correspondante est a, A, e, E, f, F, g ou G. Sinon, ils sont évalués

*
Un signe plus ou un trait d'union précédant la valeur est autorisé.
*
Si le caractère de tête est une apostrophe ou un guillemet, la valeur correspondra à la valeur numérique dans la table de codes sous-jacente du caractère suivant l'apostrophe ou le guillemet.

Si un opérande argument ne peut pas être entièrement converti en une valeur interne appropriée à la spécification de conversion correspondante, un message de diagnostic sera écrit sur la sortie d'erreur standard et l'utilitaire ne se terminera pas avec un statut de sortie nul, mais continuera le traitement de tout opérande restant et écrira la valeur accumulée au moment où l'erreur a été détectée sur la sortie standard.

Le fait qu'un opérande argument ne soit pas entièrement utilisé pour une conversion b, c ou s ne sera pas considéré comme une erreur.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION APPLICATIVE

Les spécifications de conversion de formatage à virgule flottante de printf() ne sont pas requises car tout calcul dans le shell est un calcul entier. L'utilitaire awk effectue des calculs à virgule flottante et fournit sa propre fonction printf. L'utilitaire bc peut effectuer des calculs à virgule flottante de précision arbitraire, mais ne fournit pas de capacités de formatage étendues. (Cet utilitaire printf ne peut pas vraiment être utilisé pour formater la sortie de bc ; il ne prend pas en charge la précision arbitraire.) Les implémentations sont encouragées à prendre en charge les conversions à virgule flottante en tant qu'extension.

Notez que cet utilitaire printf, comme la fonction printf() définie dans le volume Interfaces système de POSIX.1-2017 sur lequel il est basé, ne prend aucune disposition spéciale pour traiter les caractères multibytes lors de l'utilisation de la spécification de conversion %c ou lorsqu'une précision est spécifiée dans une spécification de conversion %b ou %s. Les applications doivent être extrêmement prudentes lors de l'utilisation de l'une ou l'autre de ces fonctionnalités lorsqu'il y a des caractères multibytes dans le jeu de caractères.

Aucune disposition n'est prise dans ce volume de POSIX.1-2017 qui permet de spécifier des largeurs de champ et des précisions sous forme de '*' car le '*' peut être remplacé directement dans l'opérande format à l'aide de la substitution de variable shell. Les implémentations peuvent également fournir cette fonctionnalité en tant qu'extension si elles le souhaitent.

Les constantes de caractères hexadécimaux telles que définies dans la norme ISO C ne sont pas reconnues dans l'opérande format car il n'y a pas de moyen cohérent de détecter la fin de la constante. Les constantes de caractères octaux sont limitées à, au plus, trois chiffres octaux, mais les constantes de caractères hexadécimaux ne sont terminées que par un caractère non hexadécimal. Dans la norme ISO C, l'opérateur de concaténation "##" peut être utilisé pour terminer une constante et y suivre un caractère hexadécimal à écrire. Dans le shell, la concaténation se produit avant que l'utilitaire printf n'ait la possibilité d'analyser la fin de la constante hexadécimale.

La spécification de conversion %b ne fait pas partie de la norme ISO C ; elle a été ajoutée ici comme moyen portable de traiter les séquences d'échappement <barre oblique inverse> développées dans les opérandes de chaîne tels que fournis par l'utilitaire echo. Voir également la section UTILISATION APPLICATIVE de echo pour des façons d'utiliser printf comme remplacement pour toutes les versions traditionnelles de l'utilitaire echo.

Si un argument ne peut pas être analysé correctement pour la spécification de conversion correspondante, l'utilitaire printf est tenu de signaler une erreur. Ainsi, le dépassement de capacité et les caractères superflus à la fin d'un argument utilisé pour une conversion numérique seront signalés comme des erreurs.

EXEMPLES

Pour alerter l'utilisateur, puis afficher et lire une série d'invites :

printf "\aVeuillez remplir les informations suivantes : \nNom : "
read nom
printf "Numéro de téléphone : "
read telephone

Pour lire une liste de réponses correctes et incorrectes à partir d'un fichier, calculer le pourcentage correctement et les afficher. Les nombres sont justifiés à droite et séparés par une seule tabulation <tab>. Le pourcentage est écrit avec une décimale de précision :

while read juste faux ; do
    percent=$(echo "scale=1;($juste*100)/($juste+$faux)" | bc)
    printf "%2d juste\t%2d faux\t(%s%%)\n" \
        $juste $faux $percent
done < fichier_base_de_données

La commande :

printf "%5d%4d\n" 1 21 321 4321 54321

produit :

    1  21
  3214321
54321   0

Notez que l'opérande format est utilisé trois fois pour afficher toutes les chaînes données et qu'un '0' a été fourni par printf pour satisfaire la dernière spécification de conversion %4d.

L'utilitaire printf est tenu d'informer l'utilisateur lorsque des erreurs de conversion sont détectées lors de la production d'une sortie numérique ; par conséquent, les résultats suivants seraient attendus sur une implémentation avec des entiers en complément à deux sur 32 bits lorsque %d est spécifié comme opérande format :

Standard
Argument Sortie Sortie de diagnostic
5a 5 printf : "5a" non complètement converti
9999999999 2147483647 printf : "9999999999" dépassement arithmétique
-9999999999 -2147483648 printf : "-9999999999" dépassement arithmétique
ABC 0 printf : "ABC" valeur numérique attendue

Le format du message de diagnostic n'est pas spécifié, mais ces exemples transmettent le type d'informations qui devraient être signalées. Notez que la valeur affichée sur la sortie standard correspond à ce qui serait attendu comme valeur de retour de la fonction strtol() telle que définie dans le volume Interfaces système de POSIX.1-2017. Une correspondance similaire existe entre %u et strtoul() et entre %e, %f et %g (si l'implémentation prend en charge les conversions à virgule flottante) et strtod().

Dans une locale utilisant la norme ISO/IEC 646:1991 comme table de codes sous-jacente, la commande :

printf "%d\n" 3 +3 -3 \'3 \"+3 "'-3"

produit :

3
Valeur numérique de la constante 3
3
Valeur numérique de la constante 3
-3
Valeur numérique de la constante -3
51
Valeur numérique du caractère '3' dans la table de codes ISO/IEC 646:1991
43
Valeur numérique du caractère '+' dans la table de codes ISO/IEC 646:1991
45
Valeur numérique du caractère '-' dans la table de codes ISO/IEC 646:1991

Notez que dans une locale avec des caractères multibytes, la valeur d'un caractère est censée être la valeur de l'équivalent de la représentation wchar_t du caractère, comme décrit dans le volume Interfaces système de POSIX.1-2017.

JUSTIFICATION

L'utilitaire printf a été ajouté pour fournir des fonctionnalités qui étaient historiquement fournies par echo. Cependant, en raison de différences irréconciliables entre les différentes versions d'echo existantes, cette version a peu de fonctionnalités spéciales, laissant celles-ci à ce nouvel utilitaire printf, qui est basé sur celui du système de Neuvième Édition.

La section DESCRIPTION ÉTENDUE correspond presque exactement à la fonction printf() de la norme ISO C, bien qu'elle soit décrite en termes de notation de format de fichier du volume Définitions de base de POSIX.1-2017, Chapitre 5, Notation de format de fichier.

Les versions antérieures de cette norme spécifiaient que les arguments pour toutes les conversions autres que b, c et s étaient évalués de la même manière (comme des constantes C, mais avec les exceptions indiquées). Pour les implémentations prenant en charge les conversions à virgule flottante, il n'était pas clair si les conversions entières ne devaient accepter que des constantes entières et les conversions à virgule flottante que des constantes à virgule flottante, ou si les deux types de conversions devaient accepter les deux types de constantes. De plus, en ne les distinguant pas, l'exigence relative à une apostrophe ou un guillemet de tête s'appliquait aux conversions à virgule flottante même si cela n'apportait aucune fonctionnalité utile aux applications qui n'était pas déjà disponible par le biais des conversions entières. La norme actuelle clarifie la situation en spécifiant que les arguments pour les conversions à virgule flottante sont évalués comme par strtod(), et les arguments pour les conversions entières sont évalués comme des constantes entières C, avec le traitement spécial des apostrophes et guillemets de tête ne s'appliquant qu'aux conversions entières.
