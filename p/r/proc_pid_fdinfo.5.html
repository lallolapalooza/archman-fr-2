proc_pid_fdinfo(5) Manuel des formats de fichiers proc_pid_fdinfo(5)

NOM

proc_pid_fdinfo(5) — informations sur les descripteurs de fichiers

DESCRIPTION

Ceci est un sous-répertoire contenant une entrée pour chaque fichier que le processus a ouvert, nommé par son descripteur de fichier. Les fichiers de ce répertoire sont lisibles uniquement par le propriétaire du processus. Le contenu de chaque fichier peut être lu pour obtenir des informations sur le descripteur de fichier correspondant. Le contenu dépend du type de fichier référencé par le descripteur de fichier correspondant.

Pour les fichiers et répertoires ordinaires, nous voyons quelque chose comme ceci :


$ cat /proc/12015/fdinfo/4
pos:    1000
flags:  01002002
mnt_id: 21

Les champs sont les suivants :

pos
C'est un nombre décimal indiquant la position dans le fichier.
flags
C'est un nombre octal qui affiche le mode d'accès au fichier et les drapeaux d'état du fichier (voir open(2)). Si le drapeau de descripteur de fichier à fermer à l'exécution est activé, alors flags inclura également la valeur O_CLOEXEC.
Avant Linux 3.1, ce champ affichait incorrectement le réglage de O_CLOEXEC au moment de l'ouverture du fichier, plutôt que le réglage actuel du drapeau de fermeture à l'exécution.
mnt_id
Ce champ, présent depuis Linux 3.15, est l'identifiant du point de montage contenant ce fichier. Voir la description de /proc/pid/mountinfo.

Pour les descripteurs de fichier eventfd (voir eventfd(2)), nous voyons (depuis Linux 3.8) les champs suivants :


pos:	0
flags:	02
mnt_id:	10
eventfd-count:               40

eventfd-count est la valeur actuelle du compteur eventfd, en hexadécimal.

Pour les descripteurs de fichier epoll (voir epoll(7)), nous voyons (depuis Linux 3.8) les champs suivants :


pos:	0
flags:	02
mnt_id:	10
tfd:        9 events:       19 data: 74253d2500000009
tfd:        7 events:       19 data: 74253d2500000007

Chacune des lignes commençant par tfd décrit l'un des descripteurs de fichier surveillés via le descripteur de fichier epoll (voir epoll_ctl(2) pour quelques détails). Le champ tfd est le numéro du descripteur de fichier. Le champ events est un masque hexadécimal des événements surveillés pour ce descripteur de fichier. Le champ data est la valeur de données associée à ce descripteur de fichier.

Pour les descripteurs de fichier signalfd (voir signalfd(2)), nous voyons (depuis Linux 3.8) les champs suivants :


pos:	0
flags:	02
mnt_id:	10
sigmask:	0000000000000006

sigmask est le masque hexadécimal des signaux acceptés via ce descripteur de fichier signalfd. (Dans cet exemple, les bits 2 et 3 sont activés, correspondant aux signaux SIGINT et SIGQUIT ; voir signal(7).)

Pour les descripteurs de fichier inotify (voir inotify(7)), nous voyons (depuis Linux 3.8) les champs suivants :


pos:	0
flags:	00
mnt_id:	11
inotify wd:2 ino:7ef82a sdev:800001 mask:800afff ignored_mask:0 fhandle-bytes:8 fhandle-type:1 f_handle:2af87e00220ffd73
inotify wd:1 ino:192627 sdev:800001 mask:800afff ignored_mask:0 fhandle-bytes:8 fhandle-type:1 f_handle:27261900802dfd73

Chacune des lignes commençant par « inotify » affiche des informations sur un fichier ou un répertoire surveillé. Les champs de cette ligne sont les suivants :

wd
Un numéro de descripteur de surveillance (en décimal).
ino
Le numéro d'inode du fichier cible (en hexadécimal).
sdev
L'identifiant du périphérique où réside le fichier cible (en hexadécimal).
mask
Le masque des événements surveillés pour le fichier cible (en hexadécimal).

Si le noyau a été compilé avec le support exportfs, le chemin d'accès au fichier cible est exposé sous forme de handle de fichier, via trois champs hexadécimaux : fhandle-bytes, fhandle-type, et f_handle.

Pour les descripteurs de fichier fanotify (voir fanotify(7)), nous voyons (depuis Linux 3.8) les champs suivants :


pos:	0
flags:	02
mnt_id:	11
fanotify flags:0 event-flags:88002
fanotify ino:19264f sdev:800001 mflags:0 mask:1 ignored_mask:0 fhandle-bytes:8 fhandle-type:1 f_handle:4f261900a82dfd73

La quatrième ligne affiche les informations définies lors de la création du groupe fanotify via fanotify_init(2) :

flags
L'argument flags passé à fanotify_init(2) (exprimé en hexadécimal).
event-flags
L'argument event_f_flags passé à fanotify_init(2) (exprimé en hexadécimal).

Chaque ligne supplémentaire affichée dans le fichier contient des informations sur l'une des marques du groupe fanotify. La plupart de ces champs sont identiques à ceux d'inotify, sauf :

mflags
Les drapeaux associés à la marque (exprimés en hexadécimal).
mask
Le masque d'événements pour cette marque (exprimé en hexadécimal).
ignored_mask
Le masque des événements ignorés pour cette marque (exprimé en hexadécimal).

Pour plus de détails sur ces champs, voir fanotify_mark(2).

Pour les descripteurs de fichier timerfd (voir timerfd(2)), nous voyons (depuis Linux 3.17) les champs suivants :


pos:    0
flags:  02004002
mnt_id: 13
clockid: 0
ticks: 0
settime flags: 03
it_value: (7695568592, 640020877)
it_interval: (0, 0)
clockid
C'est la valeur numérique de l'identifiant d'horloge (correspondant à l'une des constantes CLOCK_* définies via <time.h>) qui est utilisée pour marquer la progression du minuteur (dans cet exemple, 0 est CLOCK_REALTIME).
ticks
C'est le nombre d'expirations du minuteur qui se sont produites, (c'est-à-dire la valeur que read(2) sur celui-ci retournerait).
settime flags
Ce champ liste les drapeaux avec lesquels le timerfd a été armé pour la dernière fois (voir timerfd_settime(2)), en octal (dans cet exemple, à la fois TFD_TIMER_ABSTIME et TFD_TIMER_CANCEL_ON_SET sont activés).
it_value
Ce champ contient le temps avant la prochaine expiration du minuteur, exprimé en secondes et nanosecondes. Ceci est toujours exprimé comme une valeur relative, indépendamment du fait que le minuteur ait été créé en utilisant le drapeau TFD_TIMER_ABSTIME.
it_interval
Ce champ contient l'intervalle du minuteur, en secondes et nanosecondes. (Les champs it_value et it_interval contiennent les valeurs que timerfd_gettime(2) sur ce descripteur de fichier retournerait.)

HISTORIQUE
