DESCRIPTION

Cette documentation s'adresse principalement aux auteurs de fournisseurs. Voir provider(7) pour plus d'informations.

L'opération CIPHER permet aux fournisseurs d'implémenter des algorithmes de chiffrement et de les rendre disponibles aux applications via les fonctions API EVP_EncryptInit_ex(3), EVP_EncryptUpdate(3) et EVP_EncryptFinal(3) (ainsi que leurs équivalents de déchiffrement et d'autres fonctions associées).

Toutes les "fonctions" mentionnées ici sont passées sous forme de pointeurs de fonction entre libcrypto et le fournisseur dans les tableaux OSSL_DISPATCH(3) via les tableaux OSSL_ALGORITHM(3) qui sont renvoyés par la fonction provider_query_operation() du fournisseur (voir "Fonctions du fournisseur" dans provider-base(7)).

Toutes ces "fonctions" ont un type de fonction correspondant nommé OSSL_FUNC_{name}_fn, et une fonction d'aide pour récupérer le pointeur de fonction d'un élément OSSL_DISPATCH(3) nommé OSSL_FUNC_{name}. Par exemple, la "fonction" OSSL_FUNC_cipher_newctx() a ceci :

typedef void *(OSSL_FUNC_cipher_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_cipher_newctx_fn
    OSSL_FUNC_cipher_newctx(const OSSL_DISPATCH *opf);

Une implémentation d'algorithme de chiffrement peut ne pas implémenter toutes ces fonctions. Pour former un ensemble cohérent de fonctions, il doit y avoir au moins un ensemble complet de fonctions "encrypt", ou un ensemble complet de fonctions "decrypt", ou une seule fonction "cipher". De même, il peut y avoir un ensemble complet de fonctions "encrypt" de pipeline, et/ou un ensemble complet de fonctions "decrypt" de pipeline. Dans tous les cas, les fonctions OSSL_FUNC_cipher_get_params et les deux fonctions OSSL_FUNC_cipher_newctx et OSSL_FUNC_cipher_freectx doivent être présentes. Toutes les autres fonctions sont facultatives.

Fonctions de gestion du contexte

OSSL_FUNC_cipher_newctx() doit créer et renvoyer un pointeur vers une structure côté fournisseur pour conserver les informations de contexte lors d'une opération de chiffrement. Un pointeur vers ce contexte sera renvoyé dans un certain nombre d'autres appels de fonction d'opération de chiffrement. Le paramètre provctx est le contexte du fournisseur généré lors de l'initialisation du fournisseur (voir provider(7)).

OSSL_FUNC_cipher_freectx() reçoit un pointeur vers le contexte de chiffrement côté fournisseur dans le paramètre cctx. Cette fonction doit libérer toutes les ressources associées à ce contexte.

OSSL_FUNC_cipher_dupctx() doit dupliquer le contexte de chiffrement côté fournisseur dans le paramètre cctx et renvoyer la copie dupliquée.

Fonctions de chiffrement/déchiffrement

OSSL_FUNC_cipher_encrypt_init() initialise une opération de chiffrement pour le chiffrement étant donné un contexte de chiffrement côté fournisseur nouvellement créé dans le paramètre cctx. La clé à utiliser est fournie dans key, qui a une longueur de keylen octets. L'IV à utiliser est fourni dans iv, qui a une longueur de ivlen octets. Les params, s'ils ne sont pas NULL, doivent être définis sur le contexte d'une manière similaire à l'utilisation de OSSL_FUNC_cipher_set_ctx_params().

OSSL_FUNC_cipher_decrypt_init() est identique à OSSL_FUNC_cipher_encrypt_init() sauf qu'elle initialise le contexte pour une opération de déchiffrement.

DESCRIPTION

These are the cipher operation functions that a provider can implement for the EVP_Cipher(3) family of functions. A provider needing to implement cipher functionality should populate an OSSL_PROVIDER-cipher(7) structure with function pointers to its implementations.

Core Operations

OSSL_FUNC_cipher_newctx() is used to create a new cipher context for the provider. The context should store any implementation-specific information needed for cipher operations.

OSSL_FUNC_cipher_dupctx() duplicates an existing cipher context.

OSSL_FUNC_cipher_freectx() frees a cipher context.

OSSL_FUNC_cipher_encrypt_init() and OSSL_FUNC_cipher_decrypt_init() initialise a cipher context for encryption and decryption respectively. The params parameter is a pointer to an array of OSSL_PARAM(3) structures. This allows the application to pass algorithm-specific parameters such as keys, IVs, modes, etc., to the provider. For a full description of parameters, see the documentation for the specific cipher algorithm, for example, EVP_CIPHER-AES(7).

OSSL_FUNC_cipher_encrypt_update() and OSSL_FUNC_cipher_decrypt_update() are called to supply data to be encrypted/decrypted as part of a previously initialised cipher operation. The cctx parameter contains a pointer to a previously initialised provider side context. OSSL_FUNC_cipher_encrypt_update() should encrypt inl bytes of data at the location pointed to by in. The encrypted data should be stored in out and the amount of data written to *outl which should not exceed outsize bytes. OSSL_FUNC_cipher_encrypt_update() may be called multiple times for a single cipher operation. It is the responsibility of the cipher implementation to handle input lengths that are not multiples of the block length. In such cases a cipher implementation will typically cache partial blocks of input data until a complete block is obtained. The pointers out and in may point to the same location, in which case the encryption must be done in-place. If out and in point to different locations, the requirements of EVP_EncryptUpdate(3) guarantee that the two buffers are disjoint. Similarly, the requirements of EVP_EncryptUpdate(3) ensure that the buffer pointed to by out contains sufficient room for the operation being performed.

OSSL_FUNC_cipher_encrypt_final() and OSSL_FUNC_cipher_decrypt_final() complete an encryption or decryption started through previous OSSL_FUNC_cipher_encrypt_init() or OSSL_FUNC_cipher_decrypt_init(), and OSSL_FUNC_cipher_encrypt_update() or OSSL_FUNC_cipher_decrypt_update() calls. The cctx parameter contains a pointer to the provider side context. Any final encryption/decryption output should be written to out and the amount of data written to *outl which should not exceed outsize bytes. The same expectations apply to outsize as documented for EVP_EncryptFinal(3).

OSSL_FUNC_cipher_cipher() performs encryption/decryption using the provider side cipher context in the cctx parameter that should have been previously initialised via a call to OSSL_FUNC_cipher_encrypt_init() or OSSL_FUNC_cipher_decrypt_init(). This should call the raw underlying cipher function without any padding. This will be invoked in the provider as a result of the application calling EVP_Cipher(3). The application is responsible for ensuring that the input is a multiple of the block length. The data to be encrypted/decrypted will be in in, and it will be inl bytes in length. The output from the encryption/decryption should be stored in out and the amount of data stored should be put in *outl which should be no more than outsize bytes.

OSSL_FUNC_cipher_encrypt_skey_init() and OSSL_FUNC_cipher_decrypt_skey_init() are variants of OSSL_FUNC_cipher_encrypt_init() and OSSL_FUNC_cipher_decrypt_init() for working with opaque objects containing provider-specific key handles instead of raw bytes.

OSSL_FUNC_cipher_pipeline_encrypt_init(), OSSL_FUNC_cipher_pipeline_decrypt_init() OSSL_FUNC_cipher_pipeline_encrypt_update(), and OSSL_FUNC_cipher_pipeline_decrypt_final() are similar to the non-pipeline variants, but are used when the application is using cipher pipelining. The nkeys parameter is the number of keys in the pipeline. The params parameter is an array of OSSL_PARAM structures. The requested_ops parameter is the number of operations to perform. The iv parameter is an array of buffers with IVs, each ivlen bytes long. The in and out are arrays of buffer pointers. The inl and outl, outsize are arrays of size_t representing corresponding buffer length as similar to the non-pipeline variants. All arrays are of length numpipes. See EVP_CipherPipelineEncryptInit(3) for more information.

Cipher Parameters

See OSSL_PARAM(3) for further details on the parameters structure used by these functions.

OSSL_FUNC_cipher_get_params() gets details of the algorithm implementation and stores them in params.

OSSL_FUNC_cipher_set_ctx_params() sets cipher operation parameters for the provider side cipher context cctx to params. Any parameter settings are additional to any that were previously set. Passing NULL for params should return true.

OSSL_FUNC_cipher_get_ctx_params() gets cipher operation details details from the given provider side cipher context cctx and stores them in params. Passing NULL for params should return true.

OSSL_FUNC_cipher_gettable_params(), OSSL_FUNC_cipher_gettable_ctx_params(), and OSSL_FUNC_cipher_settable_ctx_params() all return constant OSSL_PARAM(3) arrays as descriptors of the parameters that OSSL_FUNC_cipher_get_params(), OSSL_FUNC_cipher_get_ctx_params(), and OSSL_FUNC_cipher_set_ctx_params() can handle, respectively. OSSL_FUNC_cipher_gettable_ctx_params() and OSSL_FUNC_cipher_settable_ctx_params() will return the parameters associated with the provider side context cctx in its current state if it is not NULL. Otherwise, they return the parameters associated with the provider side algorithm provctx.

Parameters currently recognised by built-in ciphers are listed in "PARAMETERS" in EVP_EncryptInit(3). Not all parameters are relevant to, or are understood by all ciphers.

RETURN VALUES

OSSL_FUNC_cipher_newctx() and OSSL_FUNC_cipher_dupctx() should return the newly created provider side cipher context, or NULL on failure.

OSSL_FUNC_cipher_gettable_params(), OSSL_FUNC_cipher_gettable_ctx_params() and OSSL_FUNC_cipher_settable_ctx_params() should return a constant OSSL_PARAM(3) array, or NULL if none is offered.
