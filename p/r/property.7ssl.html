NOM

property - Propriétés, un mécanisme de sélection pour les implémentations d'algorithmes

DESCRIPTION

Depuis OpenSSL 3.0, une nouvelle méthode a été introduite pour décider quelle implémentation d'un algorithme sera utilisée parmi plusieurs. Cette méthode est centrée sur le concept de propriétés. Chaque implémentation définit un certain nombre de propriétés et, lors de la sélection d'un algorithme, des filtres basés sur ces propriétés peuvent être utilisés pour choisir l'implémentation la plus appropriée de l'algorithme.

Les propriétés sont comme des variables, elles sont référencées par leur nom et une valeur leur est assignée.

Noms de Propriétés

Les noms de propriétés appartiennent à deux catégories : ceux réservés par le projet OpenSSL et ceux définis par l'utilisateur. Un nom de propriété réservé consiste en un seul identifiant de style C (à l'exception des identifiants commençant par des underscores, qui ne sont pas autorisés), qui commence par une lettre et peut être suivi par n'importe quel nombre de lettres, de chiffres et d'underscores. Les noms de propriétés ne sont pas sensibles à la casse, mais OpenSSL utilisera uniquement des lettres minuscules.

Un nom de propriété défini par l'utilisateur est similaire, mais il doit consister en deux identifiants ou plus de style C, séparés par des points. Le dernier identifiant du nom peut être considéré comme le 'vrai' nom de propriété, qui est préfixé par une sorte d'espace de noms. Les fournisseurs, par exemple, pourraient inclure leur nom dans le préfixe et utiliser des noms de propriétés comme

<nom_du_fournisseur>.<nom_de_la_propriete>
<nom_du_fournisseur>.<nom_de_l_algorithme>.<nom_de_la_propriete>

Propriétés

Une propriété est une paire nom=valeur. Une définition de propriété est une séquence de propriétés séparées par des virgules. Il peut y avoir n'importe quel nombre de propriétés dans une définition, cependant chaque nom doit être unique. Par exemple : "" définit une définition de propriété vide (c'est-à-dire aucune restriction) ; "my.foo=bar" définit une propriété nommée my.foo qui a une valeur chaîne bar et "iteration.count=3" définit une propriété nommée iteration.count qui a une valeur numérique de 3. La syntaxe complète des définitions de propriétés apparaît ci-dessous.

Implémentations

Chaque implémentation d'un algorithme peut définir n'importe quel nombre de propriétés. Par exemple, le fournisseur par défaut définit la propriété provider=default pour tous ses algorithmes. De même, le fournisseur FIPS d'OpenSSL définit provider=fips et le fournisseur legacy définit provider=legacy pour tous ses algorithmes.

Requêtes

Une clause de requête de propriété est un test conditionnel unique. Par exemple, "fips=yes", "provider!=default" ou "?iteration.count=3". Les deux premiers représentent des clauses obligatoires ; de telles clauses doivent correspondre pour qu'un algorithme soit même considéré. La troisième clause représente une clause facultative. La correspondance de telles clauses n'est pas une exigence, mais chaque correspondance facultative supplémentaire compte en faveur de l'algorithme. Plus de détails à ce sujet dans la section Recherches. Une requête de propriété est une séquence de clauses de requête de propriété séparées par des virgules. C'est une erreur si un nom de propriété apparaît dans plus d'une clause de requête. La syntaxe complète des requêtes de propriété apparaît ci-dessous, mais les fonctionnalités syntaxiques disponibles sont :

  • = est un opérateur infixé fournissant un test d'égalité.
  • != est un opérateur infixé fournissant un test d'inégalité.
  • ? est un opérateur préfixé qui signifie que la clause suivante est facultative mais préférée.
  • - est un opérateur préfixé qui signifie que toute clause de requête globale impliquant le nom de propriété suivant doit être ignorée.
  • "..." est une chaîne entre guillemets. Les guillemets ne sont pas inclus dans le corps de la chaîne.
  • '...' est une chaîne entre apostrophes. Les apostrophes ne sont pas incluses dans le corps de la chaîne.

Recherches

Lorsqu'un algorithme est recherché, une requête de propriété est utilisée pour déterminer l'algorithme le mieux adapté. Toutes les clauses de requête obligatoires doivent être présentes et l'implémentation qui, en plus, a le plus grand nombre de clauses de requête facultatives correspondantes sera utilisée. S'il y a plus d'un candidat optimal de ce type, le résultat sera choisi parmi eux de manière indéterminée. L'ordre des clauses facultatives n'est pas significatif.

Raccourci

Afin de permettre une expression plus concise des propriétés booléennes, il existe un raccourci : un nom de propriété seul (par exemple, "my.property") est exactement équivalent à "my.property=yes" dans les définitions et les requêtes.

Global et Local

Deux niveaux de requête de propriété sont pris en charge. Une requête de propriété basée sur le contexte qui s'applique à toutes les opérations de récupération et une requête de propriété locale. Lorsque les requêtes contextuelle et locale incluent une clause portant le même nom, la clause locale remplace la clause contextuelle.

Il est possible pour une requête de propriété locale de supprimer une clause dans la requête de propriété contextuelle en faisant précéder le nom de la propriété d'un '-'. Par exemple, une requête de propriété contextuelle contenant "fips=yes" entraînerait normalement des implémentations ayant "fips=yes".

Cependant, si le réglage de la propriété "fips" est sans importance pour les opérations en cours, la requête de propriété locale peut inclure la clause "-fips". Notez que la requête de propriété locale ne pourrait pas utiliser "fips=no" car cela interdirait toute implémentation avec "fips=yes" plutôt que de ne pas se soucier du réglage.

SYNTAXE

La syntaxe lexicale en EBNF est donnée par :

Définition     ::= NomPropriete ( '=' Valeur )?
                       ( ',' NomPropriete ( '=' Valeur )? )*
Requête          ::= ClauseRequetePropriete ( ',' ClauseRequetePropriete )*
ClauseRequetePropriete  ::= '-' NomPropriete
                 | '?'? ( NomPropriete (( '=' | '!=' ) Valeur)?)
Valeur          ::= LiteralNombre | LiteralChaine
LiteralChaine   ::= ChaineAvecGuillemets | ChaineSansGuillemets
ChaineAvecGuillemets ::= '"' [^"]* '"' | "'" [^']* "'"
ChaineSansGuillemets ::= [A-Za-z] [^{espace},]+
LiteralNombre   ::= '0' ( [0-7]* | 'x' [0-9A-Fa-f]+ ) | '-'? [1-9] [0-9]+
NomPropriete    ::= [A-Za-z] [A-Za-z0-9_]* ( '.' [A-Za-z] [A-Za-z0-9_]* )*

La forme d'EBNF utilisée est définie par : https://www.w3.org/TR/2010/REC-xquery-20101214/#EBNFNotation.

    NOM

    ssl - Wrapper SSL/TLS

    DESCRIPTION

    Le wrapper ssl fournit une interface pour la bibliothèque OpenSSL, permettant aux applications de créer des wrappers SSL/TLS autour des descripteurs de fichiers arbitraires. Il prend en charge une variété de méthodes SSL/TLS, notamment SSLv2, SSLv3, TLSv1, TLSv1.1 et TLSv1.2, ainsi que diverses options de configuration pour la gestion des certificats, des clés privées et des paramètres de négociation.
