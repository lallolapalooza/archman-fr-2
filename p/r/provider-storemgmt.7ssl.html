NOM

provider-storemgmt - Fonctions de la bibliothèque OSSL_STORE <-> fournisseur

SYNOPIS

#include <openssl/core_dispatch.h>
/*
 * Aucune de ces fonctions n'est réelle, mais elles sont affichées comme ceci pour
 * les signatures de fonctions qui sont proposées comme pointeurs de fonction dans les tableaux OSSL_DISPATCH.
 */
void *OSSL_FUNC_store_open(void *provctx, const char *uri);
void *OSSL_FUNC_store_attach(void *provctx, OSSL_CORE_BIO *bio);
const OSSL_PARAM *store_settable_ctx_params(void *provctx);
int OSSL_FUNC_store_set_ctx_params(void *loaderctx, const OSSL_PARAM[]);
int OSSL_FUNC_store_load(void *loaderctx,
                         OSSL_CALLBACK *object_cb, void *object_cbarg,
                         OSSL_PASSPHRASE_CALLBACK *pw_cb, void *pw_cbarg);
int OSSL_FUNC_store_eof(void *loaderctx);
int OSSL_FUNC_store_close(void *loaderctx);
int OSSL_FUNC_store_export_object
    (void *loaderctx, const void *objref, size_t objref_sz,
     OSSL_CALLBACK *export_cb, void *export_cbarg);
void *OSSL_FUNC_store_open_ex(void *provctx, const char *uri,
                              const OSSL_PARAM params[],
                              OSSL_PASSPHRASE_CALLBACK *pw_cb,
                              void *pw_cbarg);
int OSSL_FUNC_store_delete(void *provctx, const char *uri,
                   const OSSL_PARAM params[],
                   OSSL_PASSPHRASE_CALLBACK *pw_cb, void *pw_cbarg);

DESCRIPTION

L'opération STORE est le côté fournisseur de l'API ossl_store(7).

La responsabilité principale de l'opération STORE est de charger toutes sortes d'objets à partir d'un conteneur indiqué par URI. Ces objets sont fournis à la bibliothèque OpenSSL sous forme d'abstraction d'objet native du fournisseur (voir provider-object(7)). La bibliothèque OpenSSL est alors responsable de transmettre cette abstraction aux fonctions fournies adéquates.

Parmi les exemples de fonctions auxquelles la bibliothèque OpenSSL peut transmettre l'abstraction, on trouve OSSL_FUNC_keymgmt_load() (provider-keymgmt(7)), OSSL_FUNC_store_export_object() (qui exporte l'objet sous forme paramétrée).

Toutes les « fonctions » mentionnées ici sont transmises sous forme de pointeurs de fonction entre libcrypto et le fournisseur dans des tableaux OSSL_DISPATCH(3) via des tableaux OSSL_ALGORITHM(3) qui sont retournés par la fonction provider_query_operation() du fournisseur (voir « Fonctions du fournisseur » dans provider-base(7)).

Toutes ces « fonctions » ont une définition de type de fonction correspondante nommée OSSL_FUNC_{name}_fn, et une fonction d'aide pour récupérer le pointeur de fonction à partir d'un élément OSSL_DISPATCH(3) nommé OSSL_get_{name}. Par exemple, la « fonction » OSSL_FUNC_store_attach() a ceci :

typedef void *(OSSL_FUNC_store_attach_fn)(void *provctx,
                                          OSSL_CORE_BIO * bio);
static ossl_inline OSSL_FUNC_store_attach_fn
    OSSL_FUNC_store_attach(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) Les tableaux sont indexés par des nombres fournis sous forme de macros dans openssl-core_dispatch.h(7), comme suit :

OSSL_FUNC_store_open                 OSSL_FUNC_STORE_OPEN
OSSL_FUNC_store_attach               OSSL_FUNC_STORE_ATTACH
OSSL_FUNC_store_settable_ctx_params  OSSL_FUNC_STORE_SETTABLE_CTX_PARAMS
OSSL_FUNC_store_set_ctx_params       OSSL_FUNC_STORE_SET_CTX_PARAMS
OSSL_FUNC_store_load                 OSSL_FUNC_STORE_LOAD
OSSL_FUNC_store_eof                  OSSL_FUNC_STORE_EOF
OSSL_FUNC_store_close                OSSL_FUNC_STORE_CLOSE
OSSL_FUNC_store_export_object        OSSL_FUNC_STORE_EXPORT_OBJECT
OSSL_FUNC_store_delete               OSSL_FUNC_STORE_DELETE
OSSL_FUNC_store_open_ex              OSSL_FUNC_STORE_OPEN_EX

Fonctions

OSSL_FUNC_store_open() doit créer un contexte côté fournisseur avec des données basées sur l'uri d'entrée. L'implémentation est entièrement responsable de l'interprétation de l'URI.

OSSL_FUNC_store_attach() doit créer un contexte côté fournisseur avec le BIO principal bio attaché. C'est une alternative à l'utilisation d'une URI pour trouver le stockage, supportant OSSL_STORE_attach(3).

OSSL_FUNC_store_settable_ctx_params() doit retourner un tableau constant de descripteurs OSSL_PARAM(3), pour les paramètres que OSSL_FUNC_store_set_ctx_params() peut gérer.

OSSL_FUNC_store_set_ctx_params() doit définir des paramètres supplémentaires, tels que le type de données à attendre, les critères de recherche, etc. Plus d'informations à ce sujet ci-dessous, dans « Paramètres de chargement ». Que les paramètres non reconnus soient une erreur ou simplement ignorés est à la discrétion de l'implémentation. Passer NULL pour params doit renvoyer vrai.

OSSL_FUNC_store_load() charge le prochain objet de l'URI ouverte par OSSL_FUNC_store_open(), crée une abstraction d'objet pour celui-ci (voir provider-object(7)), et appelle object_cb avec celui-ci ainsi qu'avec object_cbarg. object_cb interprétera alors l'abstraction de l'objet et fera ce qu'il peut pour l'envelopper ou le décoder en une structure OpenSSL. Dans le cas où une phrase de passe doit être demandée pour déverrouiller un objet, pw_cb doit être appelée.

OSSL_FUNC_store_eof() indique si la fin de l'ensemble des objets de l'URI a été atteinte. Lorsque cela se produit, il est inutile d'essayer de charger davantage.

OSSL_FUNC_store_close() libère le contexte côté fournisseur ctx.

Lorsqu'un objet natif du fournisseur est créé par un gestionnaire de magasin, il serait inadapté à une utilisation directe avec un fournisseur étranger. La fonction d'exportation permet d'exporter l'objet vers ce fournisseur étranger si le fournisseur étranger prend en charge le type de l'objet et fournit une fonction d'importation.

OSSL_FUNC_store_export_object() doit exporter l'objet de taille objref_sz référencé par objref sous forme de tableau OSSL_PARAM(3) et le transmettre à export_cb ainsi qu'à export_cbarg.

OSSL_FUNC_store_delete() supprime l'objet identifié par l'uri. L'implémentation est entièrement responsable de l'interprétation de l'URI. Dans le cas où une phrase de passe doit être demandée pour supprimer un objet, pw_cb doit être appelée.

OSSL_FUNC_store_open_ex() est une variante étendue de OSSL_FUNC_store_open(). Si le fournisseur n'implémente pas cette fonction, le code revient en interne à l'utilisation de OSSL_FUNC_store_open() original. Cette variante accepte en plus un objet OSSL_PARAM(3) et une fonction de rappel pw_cb qui peut être utilisée pour demander une phrase de passe dans les cas où tout le magasin doit être déverrouillé avant d'effectuer toute opération de chargement.

Paramètres de chargement

"expect" (OSSL_STORE_PARAM_EXPECT) <entier>
Est un indice sur le type de données que la bibliothèque OpenSSL s'attend à recevoir. Ceci n'est utile que pour l'optimisation, car la bibliothèque vérifiera également que les types d'objets correspondent à l'attente.

Le nombre qui peut être donné via ce paramètre se trouve dans <openssl/store.h>, avec les macros dont les noms commencent par "OSSL_STORE_INFO_". Ceux-ci sont plus amplement décrits dans « OBJETS SUPPORTÉS » dans OSSL_STORE_INFO(3).

"subject" (OSSL_STORE_PARAM_SUBJECT) <chaîne d'octets>
Indique que l'appelant souhaite rechercher un objet avec le sujet donné associé. Ceci peut être utilisé pour sélectionner des certificats spécifiques par sujet.

Le contenu de la chaîne d'octets est attendu en format DER.

"issuer" (OSSL_STORE_PARAM_ISSUER) <chaîne d'octets>
Indique que l'appelant souhaite rechercher un objet avec l'émetteur donné associé. Ceci peut être utilisé pour sélectionner des certificats spécifiques par émetteur.

Le contenu de la chaîne d'octets est attendu en format DER.

"serial" (OSSL_STORE_PARAM_SERIAL) <entier>
Indique que l'appelant souhaite rechercher un objet avec le numéro de série donné associé.
"digest" (OSSL_STORE_PARAM_DIGEST) <chaîne UTF8>
"fingerprint" (OSSL_STORE_PARAM_FINGERPRINT) <octet string>

provider-storemgmt - Store Management Functions

SYNOPSIS

DESCRIPTION

The Store management functions provide a generic interface for accessing collections of cryptographic objects. These objects can include certificates, CRLs, private keys, etc. The interface allows for opening a store, iterating over its contents, and retrieving individual objects. It also supports searching for specific objects based on various criteria and deleting objects.

The functions are primarily used by providers to implement their object storage capabilities, but they can also be used by applications that need to manage collections of cryptographic objects.

The following parameters can be passed to OSSL_STORE_load, OSSL_STORE_find, and OSSL_STORE_open using OSSL_STORE_ctrl:

"search" (OSSL_STORE_PARAM_SEARCH) <string>
A general search string. The exact interpretation depends on the store implementation.
"object-type" (OSSL_STORE_PARAM_OBJECT_TYPE) <string>
Specifies the type of object to search for (e.g., "cert", "privkey").
"subject" (OSSL_STORE_PARAM_SUBJECT) <string>
Indicates that the caller wants to search for an object with the given subject name.
"issuer" (OSSL_STORE_PARAM_ISSUER) <string>
Indicates that the caller wants to search for an object with the given issuer name.
"serial" (OSSL_STORE_PARAM_SERIAL) <string>
Indicates that the caller wants to search for an object with the given serial number.
"fingerprint" (OSSL_STORE_PARAM_FINGERPRINT) <string>
Indicates that the caller wants to search for an object with the given fingerprint, computed with the given digest.
"alias" (OSSL_STORE_PARAM_ALIAS) <UTF8 string>
Indicates that the caller wants to search for an object with the given alias (some call it a "friendly name").
"properties" (OSSL_STORE_PARAM_PROPERTIES) <utf8 string>
Property string to use when querying for algorithms such as the OSSL_DECODER decoder implementations.
"input-type" (OSSL_STORE_PARAM_INPUT_TYPE) <utf8 string>
Type of the input format as a hint to use when decoding the objects in the store.

Several of these search criteria may be combined. For example, to search for a certificate by issuer+serial, both the "issuer" and the "serial" parameters will be given.

The following parameters can be passed to OSSL_STORE_delete using OSSL_STORE_ctrl:

"delete-by-subject" (OSSL_STORE_PARAM_DELETE_BY_SUBJECT) <string>
Deletes objects matching the given subject name.
"delete-by-issuer" (OSSL_STORE_PARAM_DELETE_BY_ISSUER) <string>
Deletes objects matching the given issuer name.
"delete-by-serial" (OSSL_STORE_PARAM_DELETE_BY_SERIAL) <string>
Deletes objects matching the given serial number.
"delete-by-fingerprint" (OSSL_STORE_PARAM_DELETE_BY_FINGERPRINT) <string>
Deletes objects matching the given fingerprint.
"delete-by-alias" (OSSL_STORE_PARAM_DELETE_BY_ALIAS) <UTF8 string>
Deletes objects matching the given alias.
