NOM

provider-decoder - Fonctions de la bibliothèque OSSL_DECODER <-> fournisseur

SYNOPIS

#include <openssl/core_dispatch.h>
/*
 * Aucune de ces fonctions n'est une fonction réelle, mais elles sont présentées
 * comme des signatures de fonction pour les fonctions qui sont proposées comme
 * pointeurs de fonction dans les tableaux OSSL_DISPATCH.
 */
/* Accesseur et descripteur de paramètre du décodeur */
const OSSL_PARAM *OSSL_FUNC_decoder_gettable_params(void *provctx);
int OSSL_FUNC_decoder_get_params(OSSL_PARAM params[]);
/* Fonctions pour construire / détruire / manipuler le contexte du décodeur */
void *OSSL_FUNC_decoder_newctx(void *provctx);
void OSSL_FUNC_decoder_freectx(void *ctx);
const OSSL_PARAM *OSSL_FUNC_decoder_settable_ctx_params(void *provctx);
int OSSL_FUNC_decoder_set_ctx_params(void *ctx, const OSSL_PARAM params[]);
/* Fonctions pour vérifier le support de sélection */
int OSSL_FUNC_decoder_does_selection(void *provctx, int selection);
/* Fonctions pour décoder les données d'objet */
int OSSL_FUNC_decoder_decode(void *ctx, OSSL_CORE_BIO *in,
                             int selection,
                             OSSL_CALLBACK *data_cb, void *data_cbarg,
                             OSSL_PASSPHRASE_CALLBACK *cb, void *cbarg);
/* Fonctions pour exporter un objet décodé */
int OSSL_FUNC_decoder_export_object(void *ctx,
                                      const void *objref, size_t objref_sz,
                                      OSSL_CALLBACK *export_cb,
                                      void *export_cbarg);

DESCRIPTION

Le terme "décoder" est utilisé dans ce manuel. Il inclut, mais ne se limite pas à, la désérialisation car les décodeurs individuels peuvent également effectuer un décodage vers des formats de données intermédiaires.

L'opération DECODER est une méthode générique pour créer une référence d'objet native du fournisseur ou des données décodées intermédiaires à partir d'une forme encodée lue depuis le OSSL_CORE_BIO fourni. Si l'appelant souhaite décoder des données depuis la mémoire, il doit fournir un BIO_s_mem(3) BIO. Les données décodées ou la référence d'objet sont transmises avec les métadonnées éventuelles au *metadata_cb* sous forme de paramètres OSSL_PARAM(3).

Le décodeur n'a pas besoin d'en savoir plus sur le pointeur OSSL_CORE_BIO que de pouvoir le passer aux appels système BIO appropriés (voir "Fonctions du noyau" dans provider-base(7)).

L'implémentation du DECODEUR peut faire partie d'une chaîne, où les données sont passées d'un décodeur à l'autre. Par exemple, il peut y avoir une implémentation pour décoder un objet de PEM vers DER, et une autre qui décode DER vers un objet natif du fournisseur.

La dernière étape de décodage dans la chaîne est généralement supposée créer un objet natif du fournisseur référencé par une référence d'objet. Pour importer cet objet dans un fournisseur différent, OSSL_FUNC_decoder_export_object() peut être appelé comme étape finale du processus de décodage.

Toutes les "fonctions" mentionnées ici sont passées sous forme de pointeurs de fonction entre *libcrypto* et le fournisseur dans des tableaux OSSL_DISPATCH(3) via des tableaux OSSL_ALGORITHM(3) qui sont retournés par la fonction provider_query_operation() du fournisseur (voir "Fonctions du fournisseur" dans provider-base(7)).

Toutes ces "fonctions" ont un type de fonction correspondant nommé OSSL_FUNC_{name}_fn, et une fonction d'aide pour récupérer le pointeur de fonction à partir d'un élément OSSL_DISPATCH(3) nommé OSSL_FUNC_{name}. Par exemple, la "fonction" OSSL_FUNC_decoder_decode() a ceci :

typedef int
    (OSSL_FUNC_decoder_decode_fn)(void *ctx, OSSL_CORE_BIO *in,
                                  int selection,
                                  OSSL_CALLBACK *data_cb, void *data_cbarg,
                                  OSSL_PASSPHRASE_CALLBACK *cb, void *cbarg);
static ossl_inline OSSL_FUNC_decoder_decode_fn*
    OSSL_FUNC_decoder_decode(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) les tableaux sont indexés par des numéros qui sont fournis sous forme de macros dans openssl-core_dispatch.h(7), comme suit :

OSSL_FUNC_decoder_get_params          OSSL_FUNC_DECODER_GET_PARAMS
OSSL_FUNC_decoder_gettable_params     OSSL_FUNC_DECODER_GETTABLE_PARAMS
OSSL_FUNC_decoder_newctx              OSSL_FUNC_DECODER_NEWCTX
OSSL_FUNC_decoder_freectx             OSSL_FUNC_DECODER_FREECTX
OSSL_FUNC_decoder_set_ctx_params      OSSL_FUNC_DECODER_SET_CTX_PARAMS
OSSL_FUNC_decoder_settable_ctx_params OSSL_FUNC_DECODER_SETTABLE_CTX_PARAMS
OSSL_FUNC_decoder_does_selection      OSSL_FUNC_DECODER_DOES_SELECTION
OSSL_FUNC_decoder_decode              OSSL_FUNC_DECODER_DECODE
OSSL_FUNC_decoder_export_object       OSSL_FUNC_DECODER_EXPORT_OBJECT

Noms et propriétés

Le nom d'une implémentation doit correspondre au type cible de l'objet qu'elle décode. Par exemple, une implémentation qui décode une clé RSA devrait être nommée "RSA". De même, une implémentation qui décode des données DER à partir d'une entrée PEM devrait être nommée "DER".

Les propriétés, telles que définies dans l'élément de tableau OSSL_ALGORITHM(3) de chaque implémentation de décodeur, peuvent être utilisées pour spécifier plus en détail une implémentation :

entrée
Cette propriété est utilisée pour spécifier quel format d'entrée l'implémentation peut décoder.

Cette propriété est obligatoire.

Les fournisseurs OpenSSL reconnaissent les types d'entrée suivants :

pem
Une implémentation avec ce type d'entrée décode des données au format PEM.
der
Une implémentation avec ce type d'entrée décode des données au format DER.
msblob
Une implémentation avec ce type d'entrée décode des données au format MSBLOB.
pvk
Une implémentation avec ce type d'entrée décode des données au format PVK.
structure
Cette propriété est utilisée pour spécifier la structure que les données décodées sont censées avoir.

Cette propriété est facultative.

Structures actuellement reconnues par les décodeurs intégrés :

"type-specific"
Structure spécifique au type.
"pkcs8"
Structure conforme à la spécification PKCS#8.
"SubjectPublicKeyInfo"
Encodage des clés publiques conformément au Subject Public Key Info de la RFC 5280.

Les valeurs possibles de ces deux propriétés sont ouvertes. Un fournisseur peut très bien spécifier des types d'entrée et des structures dont libcrypto n'a aucune connaissance.

Sélections de sous-ensembles

Parfois, un objet a plus d'un sous-ensemble de données qui est intéressant à traiter séparément ou ensemble. Il est possible de spécifier quels sous-ensembles doivent être décodés, avec un ensemble de bits *selection* qui sont passés dans un int.

Cet ensemble de bits dépend entièrement du type d'objet côté fournisseur à décoder. Par exemple, ces bits sont supposés être les mêmes que ceux utilisés avec provider-keymgmt(7) (voir "Objets clés" dans provider-keymgmt(7)) lorsque l'objet est une paire de clés asymétriques - par exemple, OSSL_KEYMGMT_SELECT_PRIVATE_KEY si l'objet à décoder est censé contenir des composants de clé privée.

OSSL_FUNC_decoder_does_selection() devrait indiquer si une implémentation particulière supporte l'une des combinaisons données par *selection*.

Fonctions de contexte

OSSL_FUNC_decoder_newctx() renvoie un contexte à utiliser avec le reste des fonctions.

OSSL_FUNC_decoder_freectx() libère le *ctx* donné tel que créé par OSSL_FUNC_decoder_newctx().

OSSL_FUNC_decoder_set_ctx_params() définit les données de contexte conformément aux paramètres de *params* qu'il reconnaît. Les paramètres non reconnus doivent être ignorés. Passer NULL pour *params* devrait retourner vrai.

OSSL_FUNC_decoder_settable_ctx_params() renvoie un tableau constant OSSL_PARAM(3) décrivant les paramètres que OSSL_FUNC_decoder_set_ctx_params() peut gérer.

Voir OSSL_PARAM(3) pour plus de détails sur la structure des paramètres utilisée par OSSL_FUNC_decoder_set_ctx_params() et OSSL_FUNC_decoder_settable_ctx_params().

Fonction d'exportation

Lorsqu'un objet natif d'un fournisseur est créé par un décodeur, il serait inapproprié pour une utilisation directe avec un fournisseur étranger. La fonction d'exportation permet d'exporter l'objet vers ce fournisseur étranger si celui-ci prend en charge le type de l'objet et fournit une fonction d'importation.

OSSL_FUNC_decoder_export_object() devrait exporter l'objet de taille objref_sz référencé par objref sous forme de tableau OSSL_PARAM(3) et le passer à export_cb ainsi qu'à export_cbarg donné.

Fonctions de décodage

OSSL_FUNC_decoder_decode() doit décoder les données lues depuis le OSSL_CORE_BIO in pour produire des données décodées ou un objet à passer comme référence dans un tableau OSSL_PARAM(3) avec éventuellement d'autres métadonnées décodées à partir de l'entrée. Ce tableau OSSL_PARAM(3) est ensuite passé au rappel data_cb. Les bits de selection, si pertinents, doivent déterminer ce que les données d'entrée doivent contenir. Les fonctions de décodage prennent également un pointeur de fonction OSSL_PASSPHRASE_CALLBACK(3) avec un pointeur vers les données de l'application cbarg, qui doit être utilisé lorsqu'une invite de phrase secrète est nécessaire.

Il est important de comprendre que la valeur de retour de cette fonction est interprétée comme suit :

Vrai (1)
Cela signifie « continuer le processus de décodage », et est pertinent même si cette fonction n'a pas pu décoder l'entrée en quoi que ce soit, car il peut y avoir une autre implémentation de décodeur qui peut la décoder en quelque chose.

Le rappel data_cb ne doit jamais être appelé lorsque cette fonction ne peut pas décoder l'entrée en quoi que ce soit.

Faux (0)
Cela signifie « arrêter le processus de décodage », et est pertinent lorsque l'entrée a pu être décodée en une sorte d'objet que cette fonction comprend, mais que le traitement ultérieur de cet objet entraîne des erreurs qu'une autre implémentation de décodeur ne pourra pas obtenir un résultat différent.

Les conditions pour arrêter le processus de décodage sont à la discrétion de l'implémentation.

Paramètres de fonctionnement du décodeur

Il n'y a actuellement aucun paramètre de fonctionnement reconnu par les décodeurs intégrés.

Paramètres actuellement reconnus par le rappel de phrase secrète intégré :

"info" (OSSL_PASSPHRASE_PARAM_INFO) <chaîne UTF8>
Une chaîne d'informations qui fera partie de l'invite de phrase secrète. Elle pourrait être utilisée pour fournir à l'utilisateur des informations sur le type d'objet pour lequel une invite est demandée.

VALEURS DE RETOUR

OSSL_FUNC_decoder_newctx() renvoie un pointeur vers un contexte, ou NULL en cas d'échec.

OSSL_FUNC_decoder_set_ctx_params() renvoie 1, sauf si un paramètre reconnu était invalide ou a causé une erreur, auquel cas 0 est renvoyé.

OSSL_FUNC_decoder_settable_ctx_params() renvoie un pointeur vers un tableau d'éléments constants OSSL_PARAM(3).

OSSL_FUNC_decoder_does_selection() renvoie 1 si l'implémentation du décodeur prend en charge certains des bits de selection, sinon 0.

OSSL_FUNC_decoder_decode() renvoie 1 pour signaler que le processus de décodage doit continuer, ou 0 pour signaler qu'il doit s'arrêter.
