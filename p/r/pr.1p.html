PR(1P) Manuel du programmeur POSIX PR(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pr — imprimer des fichiers

SYNTAXE

pr [+page] [-colonne] [-adFmrt] [-e[char][gap]] [-h en-tête] [-i[char][gap]]
    [-l lignes] [-n[char][largeur]] [-o décalage] [-s[char]] [-w largeur] [-fp]
    [fichier...]

DESCRIPTION

L'utilitaire pr est un filtre d'impression et de pagination. Si plusieurs fichiers d'entrée sont spécifiés, chacun sera lu, formaté et écrit sur la sortie standard. Par défaut, l'entrée sera séparée en pages de 66 lignes, chacune comprenant :

*
Un en-tête de 5 lignes incluant le numéro de page, la date, l'heure et le chemin du fichier
*
Un pied de page de 5 lignes composé de lignes vides

Si la sortie standard est associée à un terminal, les messages de diagnostic seront différés jusqu'à ce que l'utilitaire pr ait terminé son traitement.

Lorsque des options spécifiant une sortie multi-colonnes sont sélectionnées, les colonnes de texte de sortie auront une largeur égale ; les lignes d'entrée qui ne rentrent pas dans une colonne de texte seront tronquées. Par défaut, les colonnes de texte seront séparées par au moins un <espace>.

OPTIONS

L'utilitaire pr doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires, à l'exception du fait que : l'option page a un délimiteur '+' ; page et colonne peuvent être des nombres multi-chiffres ; certains des arguments d'option sont facultatifs ; et certains des arguments d'option ne peuvent pas être spécifiés comme arguments séparés de la lettre d'option précédente. En particulier, l'option -s ne permet pas de séparer la lettre d'option de son argument, et les options -e, -i et -n exigent que les deux arguments, s'ils sont présents, ne soient pas séparés de la lettre d'option.

Les options suivantes doivent être prises en charge. Dans les descriptions d'options suivantes, colonne, lignes, décalage, page et largeur sont des entiers décimaux positifs ; gap est un entier décimal non négatif.

+page
Commencer la sortie à la page numéro page de l'entrée formatée.
-colonne
Produire une sortie multi-colonnes qui est organisée en colonne colonnes (la valeur par défaut est 1) et qui est écrite ligne par ligne dans chaque colonne, dans l'ordre où le texte est reçu du fichier d'entrée. Cette option ne doit pas être utilisée avec -m. Les options -e et -i seront supposées pour la sortie multi-colonnes de texte. Il n'est pas spécifié si les colonnes de texte ont des longueurs verticales identiques, mais une colonne de texte ne dépassera jamais la longueur de la page (voir l'option -l). Lorsqu'elle est utilisée avec -t, utiliser le nombre minimum de lignes pour écrire la sortie.
-a
Modifier l'effet de l'option -colonne afin que les colonnes soient remplies à travers la page dans un ordre cyclique (par exemple, lorsque colonne est 2, la première ligne d'entrée tête la colonne 1, la deuxième tête la colonne 2, la troisième est la deuxième ligne de la colonne 1, et ainsi de suite).
-d
Produire une sortie en double interligne ; ajouter une <nouvelle ligne> supplémentaire après chaque <nouvelle ligne> trouvée dans l'entrée.
-e[char][gap]

Développer chaque <tabulation> d'entrée à la position de colonne supérieure suivante spécifiée par la formule n*gap+1, où n est un entier > 0. Si gap est zéro ou omis, il prendra par défaut la valeur 8. Tous les caractères <tabulation> de l'entrée seront développés en un nombre approprié d'<espace>. Si un caractère non numérique, char, est spécifié, il sera utilisé comme <tabulation> d'entrée. Si le premier caractère de l'argument d'option -e est un chiffre, l'argument d'option entier sera supposé être gap.
-f
Utiliser un <saut de page> pour les nouvelles pages, au lieu du comportement par défaut qui utilise une séquence de caractères <nouvelle ligne>. Faire une pause avant de commencer la première page si la sortie standard est associée à un terminal.
-F
Utiliser un <saut de page> pour les nouvelles pages, au lieu du comportement par défaut qui utilise une séquence de caractères <nouvelle ligne>.
-h en-tête
Utiliser la chaîne en-tête pour remplacer le contenu de l'opérande fichier dans l'en-tête de page.
-i[char][gap]
En sortie, remplacer les caractères <espace> par des caractères <tabulation> chaque fois qu'un ou plusieurs caractères <espace> adjacents atteignent les positions de colonne gap+1, 2* gap+1, 3* gap+1, et ainsi de suite. Si gap est zéro ou omis, les paramètres de tabulation par défaut à chaque huitième position de colonne seront supposés. Si un caractère non numérique, char, est spécifié, il sera utilisé comme <tabulation> de sortie. Si le premier caractère de l'argument d'option -i est un chiffre, l'argument d'option entier sera supposé être gap.
-l lignes
Remplacer la valeur par défaut de 66 lignes et réinitialiser la longueur de la page à lignes. Si lignes n'est pas supérieur à la somme des profondeurs de l'en-tête et du pied de page (en lignes), l'utilitaire pr supprimera l'en-tête et le pied de page, comme si l'option -t était en vigueur.
-m
Fusionner les fichiers. La sortie standard sera formatée de manière à ce que l'utilitaire pr écrive une ligne de chaque fichier spécifié par un opérande fichier, côte à côte dans des colonnes de texte de largeur fixe égale, en termes de nombre de positions de colonne. Les implémentations doivent prendre en charge la fusion d'au moins neuf opérandes fichier.
-n[char][largeur]

Fournir une numérotation de ligne sur largeur chiffres (par défaut pour largeur, 5). Le nombre occupera les largeur premières positions de colonne de chaque colonne de texte de la sortie par défaut ou de chaque ligne de la sortie -m. Si char (tout caractère non numérique) est donné, il sera ajouté à la ligne numéro pour la séparer de ce qui suit (par défaut pour char, une <tabulation>).
-o décalage
Chaque ligne de sortie sera précédée d'un décalage de caractères <espace>. Si l'option -o n'est pas spécifiée, le décalage par défaut sera de zéro. L'espace occupé s'ajoute à la largeur de la ligne de sortie (voir l'option -w ci-dessous).
-p
Faire une pause avant de commencer chaque page si la sortie standard est dirigée vers un terminal (pr écrira une <alerte> sur la sortie d'erreur standard et attendra qu'un <retour chariot> soit lu sur /dev/tty).
-r
Ne pas écrire de rapports de diagnostic en cas d'échec d'ouverture de fichiers.
-s[char]
Séparer les colonnes de texte par le caractère unique char au lieu du nombre approprié de caractères <espace> (par défaut pour char, <tabulation>).
-t
Ne pas écrire l'en-tête d'identification de cinq lignes ni le pied de page de cinq lignes normalement fournis pour chaque page. Arrêter l'écriture après la dernière ligne de chaque fichier sans espacer jusqu'à la fin de la page.
-w largeur
Définir la largeur de la ligne à largeur positions de colonne uniquement pour la sortie multi-colonnes. Si l'option -w n'est pas spécifiée et que l'option -s n'est pas spécifiée, la largeur par défaut sera de 72. Si l'option -w n'est pas spécifiée et que l'option -s est spécifiée, la largeur par défaut sera de 512.

Pour

OPERANDES

Le ou les opérandes suivants sont pris en charge :

fichier
Un chemin d'accès à un fichier dans lequel écrire. Si aucun opérande fichier n'est spécifié, ou si un opérande fichier est '-', l'entrée standard sera utilisée.

ENTRÉE STANDARD

L'entrée standard est utilisée uniquement si aucun opérande fichier n'est spécifié, ou si un opérande fichier est '-'. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Les fichiers d'entrée sont des fichiers texte.

Le fichier /dev/tty est utilisé pour lire les réponses requises par l'option -p.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de pr :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui ne sont pas définies ou qui sont nulles. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données texte en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée) et quels caractères sont définis comme imprimables (classe de caractères print). Les caractères non imprimables sont toujours écrits sur la sortie standard, mais ne sont pas comptés pour le calcul de la largeur des colonnes et de la longueur des lignes.
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
LC_TIME
Détermine le format de la date et de l'heure pour l'écriture des lignes d'en-tête.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
TZ
Détermine le fuseau horaire utilisé pour calculer les chaînes de date et d'heure écrites dans les lignes d'en-tête. Si TZ n'est pas défini ou est nul, un fuseau horaire par défaut non spécifié est utilisé.

ÉVÉNEMENTS ASYNCHRONES

Si pr reçoit une interruption lors de l'écriture sur un terminal, il vide tous les messages d'erreur accumulés sur l'écran avant de se terminer.

SORTIE STANDARD

La sortie de l'utilitaire pr est une version paginée du fichier (ou des fichiers) d'origine. Cette pagination est réalisée soit par des caractères de <saut de page>, soit par une séquence de caractères de <nouvelle ligne>, contrôlée par l'option -F ou -f. Des en-têtes de page sont générés sauf si l'option -t est spécifiée. Les en-têtes de page sont de la forme :

"
"\n\n%s %s Page %d\n\n\n", <sortie de date>, <fichier>, <numéro de page>

Dans la locale POSIX, le champ <sortie&#x00A0;de&#x00A0;date>, représentant la date et l'heure de dernière modification du fichier d'entrée (ou la date et l'heure actuelles si le fichier d'entrée est l'entrée standard), est équivalent à la sortie de la commande suivante telle qu'elle apparaîtrait si exécutée au moment donné :

date "+%b %e %H:%M %Y"

sans la <nouvelle ligne> finale, si la page en cours d'écriture provient de l'entrée standard. Si la page en cours d'écriture ne provient pas de l'entrée standard, dans la locale POSIX, le même format est utilisé, mais l'heure utilisée est l'heure de modification du fichier correspondant à fichier au lieu de l'heure actuelle. Lorsque la catégorie de locale LC_TIME n'est pas définie sur la locale POSIX, un format et un ordre de présentation différents de ce champ peuvent être utilisés.

Si l'entrée standard est utilisée à la place d'un opérande fichier, le champ <fichier> est remplacé par une chaîne nulle.

Si l'option -h est spécifiée, le champ <fichier> est remplacé par l'argument en-tête.

ERREUR STANDARD

La sortie d'erreur standard est utilisée pour les messages de diagnostic et pour alerter le terminal lorsque -p est spécifié.

Les sections suivantes sont informatives.

UTILISATION DE L'APPLICATION

Une application conforme doit protéger son premier opérande, s'il commence par un <signe plus>, en le faisant précéder de l'argument "--" qui indique la fin des options. Par exemple, pr+x pourrait être interprété comme un nombre de page invalide ou un opérande fichier.

EXEMPLES

1.
Afficher une liste numérotée de tous les fichiers du répertoire courant :
ls -a | pr -n -h "Fichiers dans $(pwd)."
2.
Afficher file1 et file2 sous forme de liste à trois colonnes, double espacée, avec l'en-tête « liste de fichiers » :
pr -3d -h "liste de fichiers" file1 file2
3.
Écrire file1 dans file2, en développant les tabulations vers les colonnes 10, 19, 28, ... :
pr -e9 -t <file1 >file2

RATIONALE

Cet utilitaire est l'un de ceux qui ne suivent pas les directives de syntaxe des utilitaires en raison de ses origines historiques. Les développeurs du standard auraient pu ajouter de nouvelles options qui respectaient les directives (et marquer les anciennes options comme obsolètes) ou concevoir un utilitaire entièrement nouveau ; il existe des exemples des deux actions dans ce volume de POSIX.1‐2017. En raison de son utilisation généralisée par les applications historiques, les développeurs du standard ont décidé d'exempter cette version de pr de nombreuses directives.

Les implémentations sont tenues d'accepter les arguments d'option pour les options -h, -l, -o et -w, qu'ils soient présentés comme faisant partie du même argument ou comme un argument séparé de pr, comme suggéré par les directives de syntaxe des utilitaires. Les options -n et -s, cependant, sont spécifiées comme dans la pratique historique car elles sont souvent spécifiées sans leurs arguments optionnels. Si un <espace> était autorisé avant l'argument d'option dans ces cas, un opérande fichier pourrait être mal interprété comme un argument d'option dans les applications historiques.

Le texte concernant le nombre minimum de lignes en sortie multi-colonnes a été inclus pour garantir que le meilleur effort soit fait pour équilibrer la longueur des colonnes. Il existe des implémentations historiques connues dans lesquelles, par exemple, des fichiers de 60 lignes sont listés par pr -2 comme une colonne de 56 lignes et une seconde de 4. Bien que ce ne soit pas un problème lorsqu'une page complète avec en-têtes et pieds de page est produite, ce serait relativement inutile lorsqu'utilisé avec -t.

Les implémentations historiques de l'utilitaire pr ont divergé dans l'action entreprise pour l'option -f. BSD l'utilise comme décrit ici pour l'option -F ; System V l'utilise pour remplacer les caractères de <nouvelle ligne> de fin de page par un <saut de page> et, si la sortie standard est un périphérique TTY, envoie une <alerte> sur la sortie d'erreur standard et lit une ligne depuis /dev/tty avant la première page. Il y avait de forts arguments des deux côtés de cette question concernant la pratique historique et, par conséquent, l'option -F a été ajoutée. Les systèmes conformes XSI prennent en charge les actions historiques de System V pour l'option -f.

Le champ <sortie&#x00A0;de&#x00A0;date> dans le format -l est spécifié uniquement pour la locale POSIX. Comme noté, le format peut être différent dans d'autres locales. Aucun mécanisme pour définir cela n'est présent dans ce volume de POSIX.1‐2017, car le véhicule approprié est un catalogue de messages ; c'est-à-dire que le format doit être spécifié comme un « message ».
