proc_timer_stats(5) Manuel des formats de fichiers proc_timer_stats(5)

NOM

/proc/timer_stats - statistiques de minuterie

DESCRIPTION

/proc/timer_stats (depuis Linux 2.6.21 jusqu'à Linux 4.10)
Il s'agit d'un mécanisme de débogage permettant de rendre visible aux développeurs du noyau et de l'espace utilisateur l'utilisation (abusive ou non) des minuteries dans un système Linux. Il peut être utilisé par les développeurs du noyau et de l'espace utilisateur pour vérifier que leur code ne fait pas une utilisation excessive des minuteries. L'objectif est d'éviter les réveils inutiles, optimisant ainsi la consommation d'énergie.
S'il est activé dans le noyau (CONFIG_TIMER_STATS), mais non utilisé, il a un impact quasi nul sur les performances d'exécution et une surcharge relativement faible des structures de données. Même si la collecte est activée à l'exécution, la surcharge est faible : toutes les verrous sont par CPU et la recherche est hachée.
Le fichier /proc/timer_stats est utilisé à la fois pour contrôler le mécanisme d'échantillonnage et pour lire les informations échantillonnées.
La fonctionnalité timer_stats est inactive au démarrage. Une période d'échantillonnage peut être lancée en utilisant la commande suivante :

# echo 1 > /proc/timer_stats

La commande suivante arrête une période d'échantillonnage :

# echo 0 > /proc/timer_stats

Les statistiques peuvent être récupérées en :

$ cat /proc/timer_stats

Tant que l'échantillonnage est activé, chaque lecture de /proc/timer_stats affichera les statistiques mises à jour. Une fois l'échantillonnage désactivé, les informations échantillonnées sont conservées jusqu'à ce qu'une nouvelle période d'échantillonnage soit démarrée. Cela permet plusieurs lectures.
Exemple de sortie de /proc/timer_stats :

$ cat /proc/timer_stats
Timer Stats Version: v0.3
Sample period: 1.764 s
Collection: active
  255,     0 swapper/3        hrtimer_start_range_ns (tick_sched_timer)
   71,     0 swapper/1        hrtimer_start_range_ns (tick_sched_timer)
   58,     0 swapper/0        hrtimer_start_range_ns (tick_sched_timer)
    4,  1694 gnome-shell      mod_delayed_work_on (delayed_work_timer_fn)
   17,     7 rcu_sched        rcu_gp_kthread (process_timeout)
...
    1,  4911 kworker/u16:0    mod_delayed_work_on (delayed_work_timer_fn)
   1D,  2522 kworker/0:0      queue_delayed_work_on (delayed_work_timer_fn)
1029 total events, 583.333 events/sec

Les colonnes de sortie sont :
[1]
un compte du nombre d'événements, éventuellement (depuis Linux 2.6.23) suivi de la lettre 'D' s'il s'agit d'une minuterie différable ;
[2]
l'ID du processus qui a initialisé la minuterie ;
[3]
le nom du processus qui a initialisé la minuterie ;
[4]
la fonction où la minuterie a été initialisée ; et (entre parenthèses) la fonction de rappel associée à la minuterie.
Pendant le cycle de développement de Linux 4.11, ce fichier a été supprimé en raison de préoccupations de sécurité, car il expose des informations entre les espaces de noms. De plus, il est possible d'obtenir les mêmes informations via les mécanismes de traçage du noyau comme ftrace.
