proc_pid_map_files(5) Manuel des formats de fichiers proc_pid_map_files(5)

NOM

/proc/pid/map_files/ - fichiers mappés en mémoire

DESCRIPTION

/proc/pid/map_files/ (depuis Linux 3.3)
Ce sous-répertoire contient des entrées correspondant aux fichiers mappés en mémoire (voir mmap(2)). Les entrées sont nommées par la paire d'adresses de début et de fin de la région mémoire (exprimée en nombres hexadécimaux), et sont des liens symboliques vers les fichiers mappés eux-mêmes. Voici un exemple, avec la sortie mise en forme pour tenir sur un écran de 80 colonnes :

# ls -l /proc/self/map_files/
lr-------- 1 root root 64 Apr 16 21:31
            3252e00000-3252e20000 -> /usr/lib64/ld-2.15.so
...

Bien que ces entrées soient présentes pour les régions mémoire qui ont été mappées avec le drapeau MAP_FILE, la manière dont la mémoire partagée anonyme (régions créées avec les drapeaux MAP_ANON | MAP_SHARED) est implémentée sous Linux fait que ces régions apparaissent également dans ce répertoire. Voici un exemple où le fichier cible est le fichier supprimé /dev/zero :

lrw------- 1 root root 64 Apr 16 21:33
            7fc075d2f000-7fc075e6f000 -> /dev/zero (deleted)

L'autorisation d'accéder à ce fichier est régie par une vérification du mode d'accès ptrace PTRACE_MODE_READ_FSCREDS ; voir ptrace(2).
Jusqu'à Linux 4.3, ce répertoire apparaissait uniquement si l'option de configuration du noyau CONFIG_CHECKPOINT_RESTORE était activée.
Des capacités sont requises pour lire le contenu des liens symboliques dans ce répertoire : avant Linux 5.9, le processus de lecture nécessite CAP_SYS_ADMIN dans l'espace utilisateur initial ; depuis Linux 5.9, le processus de lecture doit posséder soit CAP_SYS_ADMIN, soit CAP_CHECKPOINT_RESTORE dans l'espace utilisateur initial (c'est-à-dire root).
