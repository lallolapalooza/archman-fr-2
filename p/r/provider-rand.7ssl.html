DESCRIPTION

Cette documentation s'adresse principalement aux auteurs de fournisseurs. Voir provider(7) pour plus d'informations.

L'opération RAND permet aux fournisseurs d'implémenter des algorithmes de génération de nombres aléatoires et des sources de nombres aléatoires et de les rendre disponibles aux applications via la fonction API EVP_RAND(3).

Fonctions de gestion de contexte

OSSL_FUNC_rand_newctx() doit créer et retourner un pointeur vers une structure côté fournisseur pour contenir les informations de contexte lors d'une opération de rand. Un pointeur vers ce contexte sera renvoyé dans un certain nombre des autres appels de fonction d'opération de rand. Le paramètre provctx est le contexte du fournisseur généré lors de l'initialisation du fournisseur (voir provider(7)). Le paramètre parent spécifie une autre instance de rand à utiliser à des fins d'amorçage. S'il est NULL et que l'instance spécifique le prend en charge, le système d'exploitation sera utilisé pour l'amorçage. Le paramètre parent_calls pointe vers la table de dispatch pour parent. Ainsi, le parent n'a pas besoin d'appartenir au même fournisseur que la nouvelle instance.

OSSL_FUNC_rand_freectx() reçoit un pointeur vers le contexte de rand côté fournisseur dans le paramètre mctx. S'il reçoit NULL comme valeur pour ctx, il ne doit rien faire d'autre que de retourner. Cette fonction doit libérer toutes les ressources associées à ce contexte.

Fonctions de générateur de nombres aléatoires : NIST

Ces fonctions correspondent à celles définies dans NIST SP 800-90A et SP 800-90C.

OSSL_FUNC_rand_instantiate() est utilisé pour instancier le DRBG ctx avec une strength de sécurité demandée. De plus, la prediction_resistance peut être demandée. Une entrée supplémentaire addin de longueur addin_len octets peut éventuellement être fournie. Les paramètres spécifiés dans params configurent le DRBG et ceux-ci doivent être traités avant l'instanciation.

OSSL_FUNC_rand_uninstantiate() est utilisé pour désinstancier le DRBG ctx. Après avoir été désinstancié, un DRBG est incapable de produire une sortie jusqu'à ce qu'il soit réinstancié.

OSSL_FUNC_rand_generate() est utilisé pour générer des octets aléatoires à partir du DRBG ctx. Il générera outlen octets en les plaçant dans le tampon pointé par out. Les octets générés répondront à la strength de sécurité spécifiée et, si prediction_resistance est vrai, les octets seront produits après réamorçage à partir d'une source d'entropie active. Une entrée supplémentaire addin de longueur addin_len octets peut éventuellement être fournie.

Fonctions de générateur de nombres aléatoires : supplémentaires

OSSL_FUNC_rand_nonce() est utilisé pour générer un nonce de la strength donnée avec une longueur comprise entre min_noncelen et max_noncelen. Si le tampon de sortie out est NULL, la longueur du nonce doit être retournée.

OSSL_FUNC_rand_get_seed() est utilisé par les générateurs déterministes pour obtenir leur matériel d'amorçage de leurs parents. Les octets d'amorçage répondront au niveau de sécurité spécifié de entropy bits et il y aura entre min_len et max_len octets au total. Si prediction_resistance est vrai, les octets seront produits à partir d'une source d'entropie active. Une entrée supplémentaire addin de longueur addin_len octets peut éventuellement être fournie. Un pointeur vers le matériel d'amorçage est renvoyé dans *buffer et celui-ci doit être libéré par un appel ultérieur à OSSL_FUNC_rand_clear_seed().

OSSL_FUNC_rand_clear_seed() libère un tampon d'amorçage buffer d'une longueur de b_len octets qui a été précédemment alloué par OSSL_FUNC_rand_get_seed().

OSSL_FUNC_rand_verify_zeroization() est utilisé pour déterminer si l'état interne du DRBG est zéro. Cette capacité est mandatée par le NIST dans le cadre des auto-tests, elle est peu susceptible d'être utile dans d'autres circonstances.

Verrouillage du contexte

Lorsque les DRBG sont utilisés par plusieurs threads, des verrous doivent être employés pour garantir leur bon fonctionnement. Parce que le verrouillage introduit une surcharge, il est désactivé par défaut.

OSSL_FUNC_rand_enable_locking() permet d'activer le verrouillage pour un DRBG et tous ses DRBG parents. À partir de cet appel, le DRBG peut être utilisé de manière thread-safe.

OSSL_FUNC_rand_lock() est utilisé pour verrouiller un DRBG. Une fois verrouillé, un accès exclusif est garanti.

OSSL_FUNC_rand_unlock() est utilisé pour déverrouiller un DRBG.

Paramètres Rand

Voir OSSL_PARAM(3) pour plus de détails sur la structure des paramètres utilisée par ces fonctions.

OSSL_FUNC_rand_get_params() obtient des détails sur les valeurs des paramètres associées à l'algorithme du fournisseur et les stocke dans params.

OSSL_FUNC_rand_set_ctx_params() définit les paramètres de rand associés au contexte de rand côté fournisseur ctx donné à params. Tous les réglages de paramètres sont supplémentaires à ceux qui étaient précédemment définis. Passer NULL pour params doit retourner vrai.

OSSL_FUNC_rand_get_ctx_params() obtient des détails sur les valeurs de paramètres actuellement définies associées au contexte de rand côté fournisseur ctx donné et les stocke dans params. Passer NULL pour params doit retourner vrai.

OSSL_FUNC_rand_gettable_params(), OSSL_FUNC_rand_gettable_ctx_params(), et OSSL_FUNC_rand_settable_ctx_params() retournent tous des tableaux constants OSSL_PARAM(3) en tant que descripteurs des paramètres que OSSL_FUNC_rand_get_params(), OSSL_FUNC_rand_get_ctx_params(), et OSSL_FUNC_rand_set_ctx_params() peuvent gérer, respectivement. NOM

provider-rand - Interface de fournisseur pour la génération de nombres aléatoires

DESCRIPTION

Chaque fournisseur OpenSSL implémente une interface de fournisseur pour les fonctions de génération de nombres aléatoires (RAND). Cette interface est définie dans le fichier d'en-tête openssl/rand.h et est accessible via la table de dispatch OSSL_DISPATCH du fournisseur.

Les fonctions fournies sont destinées à être appelées par la couche EVP d'OpenSSL.

RAND_newctx

Crée et initialise un nouveau contexte de fournisseur pour une source RAND.

RAND_freectx

Libère un contexte de fournisseur RAND.

RAND_dupctx

Duplique un contexte de fournisseur RAND.

RAND_init

Initialise un contexte de fournisseur RAND.

RAND_gettable_params

Retourne un tableau OSSL_PARAM(3) contenant les paramètres qui peuvent être lus ou définis sur le contexte du fournisseur RAND global. Voir la description de OSSL_FUNC_rand_gettable_ctx_params pour plus de détails.

RAND_gettable_ctx_params

Retourne un tableau OSSL_PARAM(3) contenant les paramètres qui peuvent être lus ou définis sur le contexte spécifique du fournisseur RAND (donné par vctx). Si vctx est NULL, cela retourne les paramètres qui peuvent être lus ou définis sur le contexte global du fournisseur.

RAND_settable_ctx_params

Retourne un tableau OSSL_PARAM(3) contenant les paramètres qui peuvent être définis sur le contexte spécifique du fournisseur RAND (donné par vctx). Si vctx est NULL, cela retourne les paramètres qui peuvent être définis sur le contexte global du fournisseur.

Les paramètres actuellement reconnus par les générateurs de nombres aléatoires intégrés sont les suivants. Tous les paramètres ne sont pas pertinents pour tous les générateurs de nombres aléatoires, ni compris par tous:

"state" (OSSL_RAND_PARAM_STATE) <integer>
Retourne l'état du générateur de nombres aléatoires.
"strength" (OSSL_RAND_PARAM_STRENGTH) <unsigned integer>
Retourne la force en bits du générateur de nombres aléatoires.
"fips-indicator" (OSSL_RAND_PARAM_FIPS_APPROVED_INDICATOR) <integer>
Un getter qui retourne 1 si l'opération est approuvée FIPS, ou 0 sinon. Cette option est utilisée par le fournisseur FIPS d'OpenSSL et n'est pas prise en charge par toutes les sources EVP_RAND.

Pour les générateurs de nombres aléatoires qui sont également des générateurs de bits aléatoires déterministes (DRBG), ces paramètres supplémentaires sont reconnus. Tous les paramètres ne sont pas pertinents pour, ni compris par, tous les générateurs de nombres aléatoires DRBG:

"reseed_requests" (OSSL_DRBG_PARAM_RESEED_REQUESTS) <unsigned integer>
Lit ou définit le nombre de requêtes de génération avant de réamorcer le contexte RAND associé.
"reseed_time_interval" (OSSL_DRBG_PARAM_RESEED_TIME_INTERVAL) <integer>
Lit ou définit le nombre de secondes écoulées avant de réamorcer le contexte RAND associé.
"max_request" (OSSL_DRBG_PARAM_MAX_REQUEST) <unsigned integer>
Spécifie le nombre maximum d'octets qui peuvent être générés en un seul appel à OSSL_FUNC_rand_generate.
"min_entropylen" (OSSL_DRBG_PARAM_MIN_ENTROPYLEN) <unsigned integer>
"max_entropylen" (OSSL_DRBG_PARAM_MAX_ENTROPYLEN) <unsigned integer>
Spécifie le nombre minimum et maximum d'octets de matériel aléatoire qui peuvent être utilisés pour amorcer le DRBG.
"min_noncelen" (OSSL_DRBG_PARAM_MIN_NONCELEN) <unsigned integer>
"max_noncelen" (OSSL_DRBG_PARAM_MAX_NONCELEN) <unsigned integer>
Spécifie le nombre minimum et maximum d'octets de nonce qui peuvent être utilisés pour instancier le DRBG.
"max_perslen" (OSSL_DRBG_PARAM_MAX_PERSLEN) <unsigned integer>
"max_adinlen" (OSSL_DRBG_PARAM_MAX_ADINLEN) <unsigned integer>
Spécifie le nombre minimum et maximum d'octets de chaîne de personnalisation qui peuvent être utilisés avec le DRBG.
"reseed_counter" (OSSL_DRBG_PARAM_RESEED_COUNTER) <unsigned integer>
Spécifie le nombre de fois que le DRBG a été amorcé ou réamorcé.
"digest" (OSSL_DRBG_PARAM_DIGEST) <UTF8 string>
"cipher" (OSSL_DRBG_PARAM_CIPHER) <UTF8 string>
"mac" (OSSL_DRBG_PARAM_MAC) <UTF8 string>
Définit le nom du chiffrement sous-jacent, du digest ou du MAC à utiliser. Il doit nommer un algorithme approprié pour le DRBG utilisé.
"properties" (OSSL_DRBG_PARAM_PROPERTIES) <UTF8 string>
Définit les propriétés à interroger lors de la tentative de récupération d'un algorithme sous-jacent. Ceci doit être donné avec le paramètre de nommage de l'algorithme pour être considéré comme valide.

Le fournisseur FIPS d'OpenSSL prend également en charge les paramètres suivants:

"fips-indicator" (OSSL_DRBG_PARAM_FIPS_APPROVED_INDICATOR) <integer>
Un getter qui retourne 1 si l'opération est approuvée FIPS, ou 0 sinon. Ceci peut être utilisé après l'appel à OSSL_FUNC_rand_generate(). Il peut retourner 0 si "digest-check" est défini sur 0.
"digest-check" (OSSL_DRBG_PARAM_FIPS_DIGEST_CHECK) <integer>
Si requis, ce paramètre doit être défini avant que le digest ne soit défini. La valeur par défaut de 1 provoque une erreur lorsque le digest est défini si le digest n'est pas approuvé FIPS (par exemple, digests tronqués). Définir ceci à 0 ignorera l'erreur et définira "fips-indicator" approuvé sur 0. Cette option enfreint la conformité FIPS si elle provoque le retour de 0 pour "fips-indicator" approuvé.

RAND_get_params

Lit les paramètres du contexte RAND.

RAND_set_ctx_params

Définit les paramètres du contexte RAND.

RAND_generate

Génère des octets aléatoires. Le paramètre priv indique si les octets aléatoires sont demandés pour une utilisation dans des opérations cryptographiques privilégiées (par exemple, la génération de clés). Le paramètre entropy indique si des octets d'entropie supplémentaires doivent être collectés auprès du système.

RAND_nonce

Génère un nonce aléatoire.

RAND_enable_locking

Active les verrous pour la génération de nombres aléatoires. Ceci est principalement utile pour les générateurs de nombres aléatoires globaux qui pourraient être utilisés par plusieurs threads.

RAND_disable_locking

Désactive les verrous pour la génération de nombres aléatoires.

RAND_seed

Amorce le générateur de nombres aléatoires avec des données d'entropie. Le paramètre params peut contenir des informations d'amorçage.

RAND_get_seed

Récupère les données d'amorçage actuelles du générateur de nombres aléatoires.

RAND_reseed

Réamorce le générateur de nombres aléatoires avec des données d'entropie. Le paramètre params peut contenir des informations de réamorçage.

RAND_get_reseed_counter

Récupère le compteur de réamorçage actuel du générateur de nombres aléatoires.

RAND_set_DRBG_type

Définit le type de DRBG à utiliser. Ceci est utilisé par le fournisseur FIPS pour sélectionner un algorithme DRBG approuvé.

RAND_set_DRBG_seed_material

Définit le matériel d'amorçage pour un DRBG.

RAND_set_DRBG_len

Définit la longueur de sortie du DRBG.

RAND_set_DRBG_stdout_check

Active ou désactive la vérification de la sortie standard pour le DRBG. Ceci est utilisé à des fins de test et de débogage.

RAND_set_fips_indicator

Définit l'indicateur d'approbation FIPS pour le générateur de nombres aléatoires.

RAND_get_fips_indicator

Récupère l'indicateur d'approbation FIPS pour le générateur de nombres aléatoires.

VALEURS DE RETOUR

OSSL_FUNC_rand_newctx() doit retourner le contexte du fournisseur RAND nouvellement créé, ou NULL en cas d'échec.

OSSL_FUNC_rand_gettable_params(), OSSL_FUNC_rand_gettable_ctx_params() et OSSL_FUNC_rand_settable_ctx_params() doivent retourner un tableau constant OSSL_PARAM(3), ou NULL si aucun n'est proposé.

OSSL_FUNC_rand_nonce() retourne la taille du nonce généré, ou 0 en cas d'erreur.

OSSL_FUNC_rand_get_seed() retourne la taille de l'amorce générée, ou 0 en cas d'erreur.

Toutes les fonctions restantes doivent retourner 1 en cas de succès ou 0 en cas d'erreur.

NOTES

Le cycle de vie RAND est décrit dans life_cycle-rand(7). Les fournisseurs doivent s'assurer que les diverses transitions listées sont prises en charge. À un moment donné, la couche EVP commencera à appliquer les transitions listées.
