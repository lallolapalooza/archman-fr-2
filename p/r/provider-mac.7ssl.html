NOM

provider-mac - Fonctions de bibliothèque MAC <-> fournisseur

SYNOPSIS

#include <openssl/core_dispatch.h>
#include <openssl/core_names.h>
/*
 * Aucune de ces fonctions n'est une fonction réelle, mais elles sont présentées ainsi
 * pour les signatures de fonctions qui sont proposées comme pointeurs de fonction dans les tableaux OSSL_DISPATCH.
 */
/* Gestion du contexte */
void *OSSL_FUNC_mac_newctx(void *provctx);
void OSSL_FUNC_mac_freectx(void *mctx);
void *OSSL_FUNC_mac_dupctx(void *src);
/* Chiffrement/déchiffrement */
int OSSL_FUNC_mac_init(void *mctx, unsigned char *key, size_t keylen,
                       const OSSL_PARAM params[]);
int OSSL_FUNC_mac_init_skey(void *mctx, const void *key, const OSSL_PARAM params[]);
int OSSL_FUNC_mac_update(void *mctx, const unsigned char *in, size_t inl);
int OSSL_FUNC_mac_final(void *mctx, unsigned char *out, size_t *outl, size_t outsize);
/* Descripteurs de paramètres MAC */
const OSSL_PARAM *OSSL_FUNC_mac_gettable_params(void *provctx);
const OSSL_PARAM *OSSL_FUNC_mac_gettable_ctx_params(void *mctx, void *provctx);
const OSSL_PARAM *OSSL_FUNC_mac_settable_ctx_params(void *mctx, void *provctx);
/* Paramètres MAC */
int OSSL_FUNC_mac_get_params(OSSL_PARAM params[]);
int OSSL_FUNC_mac_get_ctx_params(void *mctx, OSSL_PARAM params[]);
int OSSL_FUNC_mac_set_ctx_params(void *mctx, const OSSL_PARAM params[]);

DESCRIPTION

Cette documentation s'adresse principalement aux auteurs de fournisseurs. Voir provider(7) pour plus d'informations.

L'opération MAC permet aux fournisseurs d'implémenter des algorithmes MAC et de les rendre disponibles aux applications via les fonctions d'API EVP_MAC_init(3), EVP_MAC_update(3) et EVP_MAC_final(3).

Toutes les « fonctions » mentionnées ici sont passées sous forme de pointeurs de fonction entre libcrypto et le fournisseur dans les tableaux OSSL_DISPATCH(3) via des tableaux OSSL_ALGORITHM(3) qui sont retournés par la fonction provider_query_operation() du fournisseur (voir « Fonctions du fournisseur » dans provider-base(7)).

Toutes ces « fonctions » ont un type de fonction correspondant nommé OSSL_FUNC_{name}_fn, et une fonction d'aide pour récupérer le pointeur de fonction d'un élément OSSL_DISPATCH(3) nommé OSSL_FUNC_{name}. Par exemple, la « fonction » OSSL_FUNC_mac_newctx() a ceci :

typedef void *(OSSL_FUNC_mac_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_mac_newctx_fn
    OSSL_FUNC_mac_newctx(const OSSL_DISPATCH *opf);

Les tableaux OSSL_DISPATCH(3) sont indexés par des nombres qui sont fournis sous forme de macros dans openssl-core_dispatch.h(7), comme suit :

OSSL_FUNC_mac_newctx               OSSL_FUNC_MAC_NEWCTX
OSSL_FUNC_mac_freectx              OSSL_FUNC_MAC_FREECTX
OSSL_FUNC_mac_dupctx               OSSL_FUNC_MAC_DUPCTX
OSSL_FUNC_mac_init                 OSSL_FUNC_MAC_INIT
OSSL_FUNC_mac_init_skey            OSSL_FUNC_MAC_INIT_SKEY
OSSL_FUNC_mac_update               OSSL_FUNC_MAC_UPDATE
OSSL_FUNC_mac_final                OSSL_FUNC_MAC_FINAL
OSSL_FUNC_mac_get_params           OSSL_FUNC_MAC_GET_PARAMS
OSSL_FUNC_mac_get_ctx_params       OSSL_FUNC_MAC_GET_CTX_PARAMS
OSSL_FUNC_mac_set_ctx_params       OSSL_FUNC_MAC_SET_CTX_PARAMS
OSSL_FUNC_mac_gettable_params      OSSL_FUNC_MAC_GETTABLE_PARAMS
OSSL_FUNC_mac_gettable_ctx_params  OSSL_FUNC_MAC_GETTABLE_CTX_PARAMS
OSSL_FUNC_mac_settable_ctx_params  OSSL_FUNC_MAC_SETTABLE_CTX_PARAMS

Une implémentation d'algorithme MAC peut ne pas implémenter toutes ces fonctions. Afin d'avoir un ensemble cohérent de fonctions, au moins les fonctions suivantes doivent être implémentées : OSSL_FUNC_mac_newctx(), OSSL_FUNC_mac_freectx(), au moins une parmi OSSL_FUNC_mac_init() ou OSSL_FUNC_mac_init_skey(), OSSL_FUNC_mac_update(), OSSL_FUNC_mac_final(). Toutes les autres fonctions sont optionnelles.

Fonctions de gestion du contexte

OSSL_FUNC_mac_newctx() doit créer et retourner un pointeur vers une structure côté fournisseur pour contenir les informations de contexte pendant une opération MAC. Un pointeur vers ce contexte sera renvoyé dans un certain nombre d'autres appels de fonction d'opération MAC. Le paramètre provctx est le contexte du fournisseur généré lors de l'initialisation du fournisseur (voir provider(7)).

OSSL_FUNC_mac_freectx() reçoit un pointeur vers le contexte MAC côté fournisseur dans le paramètre mctx. Si elle reçoit NULL comme valeur mctx, elle ne doit rien faire d'autre que de retourner. Cette fonction doit libérer toutes les ressources associées à ce contexte.

OSSL_FUNC_mac_dupctx() doit dupliquer le contexte MAC côté fournisseur dans le paramètre mctx et retourner la copie dupliquée.

Fonctions de chiffrement/déchiffrement

OSSL_FUNC_mac_init() initialise une opération MAC étant donné un contexte MAC côté fournisseur nouvellement créé dans le paramètre mctx. Les params sont définis avant de définir la clé MAC de keylen octets.

OSSL_FUNC_mac_init_skey() est similaire mais utilise un objet opaque spécifique au fournisseur pour initialiser le contexte MAC.

OSSL_FUNC_mac_update() est appelé pour fournir des données pour le calcul MAC d'une opération MAC préalablement initialisée. Le paramètre mctx contient un pointeur vers un contexte fournisseur préalablement initialisé. OSSL_FUNC_mac_update() peut être appelé plusieurs fois pour une seule opération MAC.

OSSL_FUNC_mac_final() termine le calcul MAC commencé par les appels précédents OSSL_FUNC_mac_init() et OSSL_FUNC_mac_update(). Le paramètre mctx contient un pointeur vers le contexte fournisseur. Le MAC résultant doit être écrit dans out et la quantité de données écrites dans *outl, qui ne doit pas dépasser outsize octets. Les mêmes attentes s'appliquent à outsize que celles documentées pour EVP_MAC_final(3).

Paramètres MAC

Voir OSSL_PARAM(3) pour plus de détails sur la structure de paramètres utilisée par ces fonctions.

OSSL_FUNC_mac_get_params() obtient des détails sur les valeurs de paramètres associées à l'algorithme fournisseur et les stocke dans params.

OSSL_FUNC_mac_set_ctx_params() définit les paramètres MAC associés au contexte MAC fournisseur donné mctx à params. Tous les paramètres définis sont supplémentaires à ceux qui étaient précédemment définis. Passer NULL pour params devrait retourner vrai.

OSSL_FUNC_mac_get_ctx_params() obtient des détails sur les valeurs de paramètres actuellement définies associées au contexte MAC fournisseur donné mctx et les stocke dans params. Passer NULL pour params devrait retourner vrai.

OSSL_FUNC_mac_gettable_params(), OSSL_FUNC_mac_gettable_ctx_params(), et OSSL_FUNC_mac_settable_ctx_params() retournent tous des tableaux OSSL_PARAM(3) constants comme descripteurs des paramètres que OSSL_FUNC_mac_get_params(), OSSL_FUNC_mac_get_ctx_params(), et OSSL_FUNC_mac_set_ctx_params() peuvent gérer, respectivement. OSSL_FUNC_mac_gettable_ctx_params() et OSSL_FUNC_mac_settable_ctx_params() retourneront les paramètres associés au contexte fournisseur mctx dans son état actuel s'il n'est pas NULL. Sinon, ils retournent les paramètres associés à l'algorithme fournisseur provctx.

Toutes les implémentations MAC sont censées gérer les paramètres suivants :

avec OSSL_FUNC_set_ctx_params():
"key" (OSSL_MAC_PARAM_KEY) <chaîne d'octets>
Définit la clé dans le contexte MAC associé. Ceci est identique à passer un argument key à la fonction OSSL_FUNC_mac_init().
avec OSSL_FUNC_get_params():
"size" (OSSL_MAC_PARAM_SIZE) <entier>
Peut être utilisé pour obtenir la taille MAC par défaut (qui pourrait être la seule taille MAC autorisée pour l'implémentation).

Peut être utilisé pour obtenir la taille du bloc MAC (si elle est prise en charge par l'algorithme).

Le fournisseur OpenSSL FIPS peut prendre en charge les paramètres suivants :

"fips-indicator" (OSSL_MAC_PARAM_FIPS_APPROVED_INDICATOR) <entier>
Un récupérateur qui renvoie 1 si l'opération est approuvée par FIPS, ou 0 sinon. Ceci peut être utilisé après avoir appelé la fonction finale. Il peut renvoyer 0 si "no-short-mac" ou "key-check" sont définis à 0.
"no-short-mac" (OSSL_MAC_PARAM_FIPS_NO_SHORT_MAC) <entier>
Si requis, ce paramètre doit être défini tôt via une fonction d'initialisation. La valeur par défaut de 1 provoque une erreur lorsqu'une sortie MAC trop courte est demandée. Le définir à 0 ignorera l'erreur et définira l'"fips-indicator" approuvé à 0. Cette option enfreint la conformité FIPS si elle amène l'"fips-indicator" approuvé à renvoyer 0.
"key-check" (OSSL_MAC_PARAM_FIPS_KEY_CHECK) <entier>
Si requis, ce paramètre doit être défini avant OSSL_FUNC_mac_init. La valeur par défaut de 1 provoque une erreur lorsqu'on demande des tailles de clé petites. Le définir à 0 ignorera l'erreur et définira l'"fips-indicator" approuvé à 0. Cette option enfreint la conformité FIPS si elle amène l'"fips-indicator" approuvé à renvoyer 0.

NOTES

Le cycle de vie du MAC est décrit dans life_cycle-rand(7). Les fournisseurs doivent s'assurer que les différentes transitions énumérées sont prises en charge. À un moment donné, la couche EVP commencera à faire respecter les transitions énumérées.

VALEURS DE RETOUR

OSSL_FUNC_mac_newctx() et OSSL_FUNC_mac_dupctx() devraient renvoyer le contexte MAC côté fournisseur nouvellement créé, ou NULL en cas d'échec.

OSSL_FUNC_mac_init(), OSSL_FUNC_mac_init_skey(), OSSL_FUNC_mac_update(), OSSL_FUNC_mac_final(), OSSL_FUNC_mac_get_params(), OSSL_FUNC_mac_get_ctx_params() et OSSL_FUNC_mac_set_ctx_params() devraient renvoyer 1 en cas de succès ou 0 en cas d'erreur.

OSSL_FUNC_mac_gettable_params(), OSSL_FUNC_mac_gettable_ctx_params() et OSSL_FUNC_mac_settable_ctx_params() devraient renvoyer un tableau constant OSSL_PARAM(3), ou NULL si aucun n'est proposé.

HISTORIQUE

L'interface du fournisseur MAC a été introduite dans OpenSSL 3.0. Les paramètres "no-short-mac" et "fips-indicator" ont été ajoutés dans OpenSSL 3.4.

La fonction OSSL_FUNC_mac_init_skey() a été introduite dans OpenSSL 3.5.
