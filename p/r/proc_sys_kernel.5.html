proc_sys_kernel(5) Manuel des formats de fichiers proc_sys_kernel(5)

NOM

proc_sys_kernel(5) - contrôle une gamme de paramètres du noyau

DESCRIPTION

/proc/sys/kernel/
Ce répertoire contient des fichiers contrôlant une gamme de paramètres du noyau, tels que décrits ci-dessous.
/proc/sys/kernel/acct
Ce fichier contient trois nombres : highwater, lowwater et frequency. Si la comptabilité des processus de style BSD est activée, ces valeurs contrôlent son comportement. Si l'espace libre sur le système de fichiers où se trouve le journal descend en dessous de lowwater pour cent, la comptabilité est suspendue. Si l'espace libre dépasse highwater pour cent, la comptabilité reprend. frequency détermine à quelle fréquence le noyau vérifie la quantité d'espace libre (la valeur est en secondes). Les valeurs par défaut sont 4, 2 et 30. C'est-à-dire, suspendez la comptabilité si 2% ou moins d'espace est libre ; reprenez-la si 4% ou plus d'espace est libre ; considérez les informations sur la quantité d'espace libre comme valides pendant 30 secondes.
/proc/sys/kernel/auto_msgmni (Linux 2.6.27 à Linux 3.18)
De Linux 2.6.27 à Linux 3.18, ce fichier était utilisé pour contrôler le recalcul de la valeur dans /proc/sys/kernel/msgmni lors de l'ajout ou de la suppression de mémoire ou lors de la création/suppression d'un espace de noms IPC. Écho de "1" dans ce fichier activait le recalcul automatique de msgmni (et déclenchait un recalcul de msgmni basé sur la quantité actuelle de mémoire disponible et le nombre d'espaces de noms IPC). Écho de "0" désactivait le recalcul automatique. (Le recalcul automatique était également désactivé si une valeur était explicitement assignée à /proc/sys/kernel/msgmni.) La valeur par défaut dans auto_msgmni était 1.
Depuis Linux 3.19, le contenu de ce fichier n'a aucun effet (car msgmni est par défaut proche de la valeur maximale possible), et les lectures de ce fichier retournent toujours la valeur "0".
/proc/sys/kernel/cap_last_cap (depuis Linux 3.2)
Voir capabilities(7).
/proc/sys/kernel/cap-bound (de Linux 2.2 à Linux 2.6.24)
Ce fichier contient la valeur de l'ensemble de limites de capacités du noyau (exprimée sous forme de nombre décimal signé). Cet ensemble est combiné par AND avec les capacités autorisées pour un processus lors d'execve(2). À partir de Linux 2.6.25, l'ensemble de limites de capacités au niveau du système a disparu et a été remplacé par un ensemble de limites par thread ; voir capabilities(7).
/proc/sys/kernel/core_pattern
Voir core(5).
/proc/sys/kernel/core_pipe_limit
Voir core(5).
/proc/sys/kernel/core_uses_pid
Voir core(5).
/proc/sys/kernel/ctrl-alt-del
Ce fichier contrôle la gestion de Ctrl-Alt-Suppr depuis le clavier. Lorsque la valeur de ce fichier est 0, Ctrl-Alt-Suppr est intercepté et envoyé au programme init(1) pour gérer un redémarrage gracieux. Lorsque la valeur est supérieure à zéro, la réaction de Linux à un Pincement Nerveux Vulcain (tm) sera un redémarrage immédiat, sans même synchroniser ses tampons sales. Note : lorsqu'un programme (comme dosemu) a le clavier en mode "brut", le Ctrl-Alt-Suppr est intercepté par le programme avant même d'atteindre la couche tty du noyau, et c'est au programme de décider quoi en faire. il.
/proc/sys/kernel/dmesg_restrict (depuis Linux 2.6.37)
La valeur de ce fichier détermine qui peut voir le contenu du syslog du noyau. Une valeur de 0 dans ce fichier n'impose aucune restriction. Si la valeur est 1, seuls les utilisateurs privilégiés peuvent lire le syslog du noyau. (Voir syslog(2) pour plus de détails.) Depuis Linux 3.4, seuls les utilisateurs ayant la capacité CAP_SYS_ADMIN peuvent modifier la valeur de ce fichier.
/proc/sys/kernel/domainname
/proc/sys/kernel/hostname
peuvent être utilisés pour définir le nom de domaine NIS/YP et le nom d'hôte de votre machine exactement de la même manière que les commandes domainname(1) et hostname(1), c'est-à-dire :

# echo 'darkstar' > /proc/sys/kernel/hostname
# echo 'mydomain' > /proc/sys/kernel/domainname

a le même effet que

# hostname 'darkstar'
# domainname 'mydomain'

Notez cependant que le darkstar.frop.org classique a le nom d'hôte "darkstar" et le domaine DNS (Domain Name Server) "frop.org", à ne pas confondre avec le nom de domaine NIS (Network Information Service) ou YP (Yellow Pages). Ces deux noms de domaine sont généralement différents. Pour une discussion détaillée, consultez la page de manuel de hostname(1).
/proc/sys/kernel/hotplug
Ce fichier contient le chemin d'accès de l'agent de politique de hotplug. La valeur par défaut de ce fichier est /sbin/hotplug.
/proc/sys/kernel/htab-reclaim (avant Linux 2.4.9.2)
(PowerPC uniquement) Si ce fichier est défini sur une valeur non nulle, le htab PowerPC (voir le fichier du noyau Documentation/powerpc/ppc_htab.txt) est purgé chaque fois que le système entre dans la boucle d'inactivité.
/proc/sys/kernel/keys/
Ce répertoire contient divers fichiers qui définissent les paramètres et les limites du mécanisme de gestion des clés. Ces fichiers sont décrits dans keyrings(7).
/proc/sys/kernel/kptr_restrict (depuis Linux 2.6.38)
La valeur de ce fichier détermine si les adresses du noyau sont exposées via les fichiers /proc et d'autres interfaces. Une valeur de 0 dans ce fichier n'impose aucune restriction. Si la valeur est 1, les pointeurs du noyau imprimés avec le spécificateur de format %pK seront remplacés par des zéros, à moins que l'utilisateur ne possède la capacité CAP_SYSLOG. Si la valeur est 2, les pointeurs du noyau imprimés avec le spécificateur de format %pK seront remplacés par des zéros, quelle que soit la capacité de l'utilisateur. La valeur initiale par défaut pour ce fichier était 1, mais la valeur par défaut a été changée à 0 dans Linux 2.6.39. Depuis Linux 3.4, seuls les utilisateurs ayant la capacité CAP_SYS_ADMIN peuvent modifier la valeur de ce fichier.
/proc/sys/kernel/l2cr
(PowerPC uniquement) Ce fichier contient un drapeau qui contrôle le cache L2 des cartes processeur G3. Si 0, le cache est désactivé. Activé si non nul.
/proc/sys/kernel/modprobe
Ce fichier contient le chemin d'accès du chargeur de modules du noyau. La valeur par défaut est /sbin/modprobe. Le fichier est présent uniquement si le noyau est compilé avec l'option CONFIG_MODULES (CONFIG_KMOD dans Linux 2.6.26 et antérieur) activée. Il est décrit par le fichier source du noyau Linux Documentation/kmod.txt (présent uniquement dans Linux 2.4 et antérieurs).
/proc/sys/kernel/modules_disabled (depuis Linux 2.6.31)
Une valeur basculante indiquant si les modules sont autorisés à être chargés dans un noyau autrement modulaire. Ce basculement est désactivé par défaut (0), mais peut être activé (1). Une fois activé, les modules ne peuvent être ni chargés ni déchargés, et le basculement ne peut pas être remis à false. Le fichier est présent uniquement si le noyau est compilé avec l'option CONFIG_MODULES activée.
/proc/sys/kernel/msgmax (depuis Linux 2.2)
Ce fichier définit une limite système spécifiant le nombre maximum d'octets dans un seul message écrit sur une file d'attente de messages System V.
/proc/sys/kernel/msgmni (depuis Linux 2.4)
Ce fichier définit la limite système sur le nombre d'identifiants de files d'attente de messages. Voir aussi /proc/sys/kernel/auto_msgmni.
/proc/sys/kernel/msgmnb (depuis Linux 2.2)
Ce fichier définit un paramètre système utilisé pour initialiser le réglage msg_qbytes pour les files d'attente de messages créées ultérieurement. Le réglage msg_qbytes spécifie le nombre maximum d'octets qui peuvent être écrits dans la file d'attente de messages.
/proc/sys/kernel/ngroups_max (depuis Linux 2.6.4)
Ceci est un fichier en lecture seule qui affiche la limite supérieure du nombre d'appartenances aux groupes d'un processus.
/proc/sys/kernel/ns_last_pid (depuis Linux 3.3)
Voir pid_namespaces(7).
/proc/sys/kernel/ostype
/proc/sys/kernel/osrelease
Ces fichiers donnent des sous-chaînes de /proc/version.
/proc/sys/kernel/overflowgid
/proc/sys/kernel/overflowuid
Ces fichiers dupliquent les fichiers /proc/sys/fs/overflowgid et /proc/sys/fs/overflowuid.
/proc/sys/kernel/panic
Ce fichier donne un accès en lecture/écriture à la variable noyau panic_timeout. Si celle-ci est à zéro, le noyau bouclera lors d'une panique ; si elle est non nulle, elle indique que le noyau doit redémarrer automatiquement après ce nombre de secondes. Lorsque vous utilisez le pilote de périphérique watchdog logiciel, le paramètre recommandé est 60.
/proc/sys/kernel/panic_on_oops (depuis Linux 2.5.68)
Ce fichier contrôle le comportement du noyau lorsqu'un "oops" ou un BUG est rencontré. Si ce fichier contient 0, le système essaie de continuer son fonctionnement. S'il contient 1, le système attend quelques secondes (pour laisser le temps à klogd d'enregistrer la sortie de l'oops) puis panique. Si le fichier /proc/sys/kernel/panic est également non nul, la machine sera redémarrée.
/proc/sys/kernel/pid_max (depuis Linux 2.5.34)
Ce fichier spécifie la valeur à laquelle les PID reviennent à zéro (c'est-à-dire que la valeur de ce fichier est supérieure de un au PID maximum). Les PID supérieurs à cette valeur ne sont pas alloués ; par conséquent, la valeur de ce fichier sert également de limite globale du système au nombre total de processus et de threads. La valeur par défaut pour ce fichier, 32768, correspond à la même plage de PID que sur les noyaux précédents. Sur les plates-formes 32 bits, 32768 est la valeur maximale pour pid_max. Sur les systèmes 64 bits, pid_max peut être défini à toute valeur jusqu'à 2^22 (PID_MAX_LIMIT, environ 4 millions).
/proc/sys/kernel/powersave-nap (PowerPC uniquement)
Ce fichier contient un drapeau. S'il est activé, Linux-PPC utilisera le mode "nap" de gestion de l'énergie, sinon le mode "doze" sera utilisé.
/proc/sys/kernel/printk
Voir syslog(2).
/proc/sys/kernel/pty (depuis Linux 2.6.4)
Ce répertoire contient deux fichiers relatifs au nombre de pseudoterminals UNIX 98 (voir pts(4)) sur le système.
/proc/sys/kernel/pty/max
Ce fichier définit le nombre maximum de pseudoterminals.
/proc/sys/kernel/pty/nr
Ce fichier en lecture seule indique le nombre de pseudoterminals actuellement en utilisation.
/proc/sys/kernel/random/
Ce répertoire contient divers paramètres contrôlant le fonctionnement du fichier /dev/random. Voir random(4) pour plus d'informations.
/proc/sys/kernel/random/uuid (depuis Linux 2.4)
Chaque lecture de ce fichier en lecture seule renvoie un UUID aléatoire de 128 bits, sous forme de chaîne dans le format UUID standard.
/proc/sys/kernel/randomize_va_space (depuis Linux 2.6.12)
Sélectionne la politique de randomisation de l'espace d'adressage (ASLR) pour le système (sur les architectures qui supportent l'ASLR). Trois valeurs sont prises en charge pour ce fichier :
0
Désactive l'ASLR. C'est le comportement par défaut pour les architectures qui ne supportent pas l'ASLR, et lorsque le noyau est démarré avec le paramètre norandmaps.
1
Randomise les adresses des allocations mmap(2), de la pile et de la page VDSO. Entre autres, cela signifie que les bibliothèques partagées seront chargées à des adresses randomisées. Le segment de texte des binaires liés par PIE sera également chargé à une adresse randomisée. Cette valeur est le comportement par défaut si le noyau a été configuré avec CONFIG_COMPAT_BRK.
2
(Depuis Linux 2.6.25) Prend également en charge la randomisation du tas. Cette valeur est le comportement par défaut si le noyau n'a pas été configuré avec CONFIG_COMPAT_BRK.
/proc/sys/kernel/real-root-dev
Ce fichier est documenté dans le fichier source du noyau Linux Documentation/admin-guide/initrd.rst (ou Documentation/initrd.txt avant Linux 4.10).
/proc/sys/kernel/reboot-cmd (Sparc uniquement)
Ce fichier semble être un moyen de passer un argument au chargeur de démarrage ROM/Flash SPARC. Peut-être pour lui dire quoi faire après le redémarrage ?
/proc/sys/kernel/rtsig-max
(Jusqu'à Linux 2.6.7 inclus ; voir setrlimit(2)) Ce fichier peut être utilisé pour régler le nombre maximal de signaux temps réel POSIX (en file d'attente) qui peuvent être en attente dans le système.
/proc/sys/kernel/rtsig-nr
(Jusqu'à Linux 2.6.7 inclus.) Ce fichier indique le nombre de signaux temps réel POSIX actuellement en file d'attente.
/proc/pid/sched_autogroup_enabled (depuis Linux 2.6.38)
Voir sched(7).
/proc/sys/kernel/sched_child_runs_first (depuis Linux 2.6.23)
Si ce fichier contient la valeur zéro, alors, après un fork(2), le parent est le premier à être planifié sur le CPU. Si le fichier contient une valeur non nulle, alors l'enfant est planifié en premier sur le CPU. (Bien sûr, sur un système multiprocesseur, le parent et l'enfant peuvent tous deux être planifiés immédiatement sur un CPU.)
/proc/sys/kernel/sched_rr_timeslice_ms (depuis Linux 3.9)
Voir sched_rr_get_interval(2).
/proc/sys/kernel/sched_rt_period_us (depuis Linux 2.6.25)
Voir sched(7).
/proc/sys/kernel/sched_rt_runtime_us (depuis Linux 2.6.25)
Voir sched(7).
/proc/sys/kernel/seccomp/ (depuis Linux 4.14)
Ce répertoire fournit des informations et une configuration supplémentaires sur seccomp. Voir seccomp(2) pour plus de détails.
/proc/sys/kernel/sem (depuis Linux 2.4)
Ce fichier contient 4 nombres définissant les limites pour les sémaphores IPC System V. Ces champs sont, dans l'ordre :
SEMMSL
Le nombre maximum de sémaphores par ensemble de sémaphores.
SEMMNS
Une limite globale du système sur le nombre de sémaphores dans tous les ensembles de sémaphores.
SEMOPM
Le nombre maximum d'opérations qui peuvent être spécifiées dans un appel semop(2).
SEMMNI
Une limite globale du système sur le nombre maximum d'identificateurs de sémaphores.
/proc/sys/kernel/sg-big-buff
Ce fichier affiche la taille du tampon du périphérique SCSI générique (sg). Vous ne pouvez pas le régler pour le moment, mais vous pourriez le modifier à la compilation en éditant include/scsi/sg.h et en changeant la valeur de SG_BIG_BUFF. Cependant, il ne devrait y avoir aucune raison de changer cette valeur.
/proc/sys/kernel/shm_rmid_forced (depuis Linux 3.1)
Si ce fichier est défini à 1, tous les segments de mémoire partagée System V seront marqués pour destruction dès que le nombre de processus attachés tombe à zéro ; en d'autres termes, il n'est plus possible de créer des segments de mémoire partagée qui existent indépendamment de tout processus attaché.
L'effet est comme si un shmctl(2) IPC_RMID était effectué sur tous les segments existants ainsi que sur tous les segments créés à l'avenir (jusqu'à ce que ce fichier soit remis à 0). Notez que les segments existants qui ne sont attachés à aucun processus seront détruits immédiatement lorsque ce fichier est mis à 1. La définition de cette option détruira également les segments qui ont été créés, mais jamais attachés, lors de la terminaison du processus qui a créé le segment avec shmget(2).
Définir ce fichier à 1 fournit un moyen de s'assurer que tous les segments de mémoire partagée System V sont comptabilisés dans l'utilisation des ressources et les limites de ressources (voir la description de RLIMIT_AS dans getrlimit(2)) d'au moins un processus.
Étant donné que la définition de ce fichier à 1 produit un comportement non standard et pourrait également casser des applications existantes, la valeur par défaut de ce fichier est 0. Définissez ce fichier à 1 uniquement si vous avez une bonne compréhension de la sémantique des applications utilisant la mémoire partagée System V sur votre système.
/proc/sys/kernel/shmall (depuis Linux 2.2)
Ce fichier contient la limite globale du système sur le nombre total de pages de mémoire partagée System V.
/proc/sys/kernel/shmmax (depuis Linux 2.2)
Ce fichier peut être utilisé pour interroger et définir la limite d'exécution sur la taille maximale du segment de mémoire partagée (IPC System V) qui peut être créé. Les segments de mémoire partagée jusqu'à 1 Go sont maintenant pris en charge dans le noyau. Cette valeur est par défaut à SHMMAX.
/proc/sys/kernel/shmmni (depuis Linux 2.4)
Ce fichier spécifie le nombre maximum global du système de segments de mémoire partagée System V qui peuvent être créés.
/proc/sys/kernel/sysctl_writes_strict (depuis Linux 3.16)
La valeur de ce fichier détermine comment le décalage de fichier affecte le comportement de la mise à jour des entrées dans les fichiers sous /proc/sys. Le fichier a trois valeurs possibles :
-1
Ceci fournit un traitement hérité, sans avertissements printk. Chaque write(2) doit contenir entièrement la valeur à écrire, et des écritures multiples sur le même descripteur de fichier écraseront la valeur entière, indépendamment de la position dans le fichier.
0
(par défaut) Ceci fournit le même comportement qu'avec -1, mais des avertissements printk sont écrits pour les processus qui effectuent des écritures lorsque le décalage de fichier n'est pas 0.
1
Respecte le décalage de fichier lors de l'écriture de chaînes dans les fichiers /proc/sys. Les écritures multiples ajouteront au tampon de valeur. Tout ce qui est écrit au-delà de la longueur maximale du tampon de valeur sera ignoré. Les écritures sur des entrées numériques /proc/sys doivent toujours être au décalage de fichier 0 et la valeur doit être entièrement contenue dans le tampon fourni à write(2).
/proc/sys/kernel/sysrq
Ce fichier contrôle les fonctions autorisées à être invoquées par la touche SysRq. Par défaut, le fichier contient 1, ce qui signifie que toutes les requêtes SysRq possibles sont autorisées (dans les anciennes versions du noyau, SysRq était désactivé par défaut, et il était nécessaire de l'activer explicitement à l'exécution, mais ce n'est plus le cas). Les valeurs possibles dans ce fichier sont :
0
Désactive complètement sysrq
1
Active toutes les fonctions de sysrq
> 1
Masque de bits des fonctions sysrq autorisées, comme suit :
  2
Active le contrôle du niveau de journalisation de la console
  4
Active le contrôle du clavier (SAK, unraw)
  8
Active les dumps de débogage des processus, etc.
 16
Active la commande sync
 32
Active le remontage en lecture seule
& proc_sys_kernel.5.fr - man pages

NOM

proc_sys_kernel - informations sur le noyau sous /proc/sys/kernel

DESCRIPTION

Ce fichier est uniquement présent si l'option de configuration du noyau CONFIG_MAGIC_SYSRQ est activée. Pour plus de détails, voir le fichier source du noyau Linux Documentation/admin-guide/sysrq.rst (ou Documentation/sysrq.txt avant Linux 4.10).

Le fichier /proc/sys/kernel/version contient une chaîne du type :

#5 Wed Feb 25 21:49:24 MET 1998

Le "#5" signifie qu'il s'agit du cinquième noyau compilé à partir de cette base source, et la date qui suit indique l'heure de compilation du noyau.

Ce fichier spécifie la limite globale du système sur le nombre de threads (tâches) qui peuvent être créés sur le système.

Depuis Linux 4.1, la valeur qui peut être écrite dans threads-max est bornée. La valeur minimale qui peut être écrite est 20. La valeur maximale qui peut être écrite est donnée par la constante FUTEX_TID_MASK (0x3fffffff). Si une valeur en dehors de cette plage est écrite dans threads-max, l'erreur EINVAL se produit.

La valeur écrite est vérifiée par rapport aux pages RAM disponibles. Si les structures de threads occupent trop (plus d'1/8ème) des pages RAM disponibles, threads-max est réduit en conséquence.

Voir ptrace(2).

Ce fichier contient un drapeau. Lorsqu'il est activé (non nul), Linux-PPC pré-zéro les pages dans la boucle d'inactivité, ce qui peut accélérer get_free_pages.
