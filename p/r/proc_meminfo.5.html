proc_meminfo(5) Manuel des formats de fichiers proc_meminfo(5)

NOM

/proc/meminfo - utilisation de la mémoire

DESCRIPTION

/proc/meminfo
Ce fichier rapporte des statistiques sur l'utilisation de la mémoire système. Il est utilisé par free(1) pour rapporter la quantité de mémoire libre et utilisée (physique et swap) sur le système, ainsi que la mémoire partagée et les tampons utilisés par le noyau. Chaque ligne du fichier se compose d'un nom de paramètre, suivi de deux points, la valeur du paramètre et une unité de mesure optionnelle (par exemple, "kB"). La liste ci-dessous décrit les noms des paramètres et le spécificateur de format requis pour lire la valeur du champ. Sauf indication contraire, tous les champs sont présents depuis au moins Linux 2.6.0. Certains champs ne sont affichés que si le noyau a été configuré avec diverses options ; ces dépendances sont notées dans la liste.
MemTotal %lu
RAM totale utilisable (c'est-à-dire la RAM physique moins quelques bits réservés et le code binaire du noyau).
MemFree %lu
La somme de LowFree + HighFree.
MemAvailable %lu (depuis Linux 3.14)
Une estimation de la quantité de mémoire disponible pour lancer de nouvelles applications, sans swapper.
Buffers %lu
Stockage relativement temporaire pour les blocs disque bruts qui ne devraient pas devenir très volumineux (environ 20 Mo).
Cached %lu
Cache en mémoire pour les fichiers lus depuis le disque (le cache de pages). N'inclut pas SwapCached.
SwapCached %lu
Mémoire qui a été swappée, puis re-swappée mais qui se trouve toujours dans le fichier swap. (Si la pression mémoire est forte, ces pages n'ont pas besoin d'être re-swappées car elles sont déjà dans le fichier swap. Cela économise des opérations d'E/S.)
Active %lu
Mémoire qui a été utilisée plus récemment et qui n'est généralement pas récupérée sauf nécessité absolue.
Inactive %lu
Mémoire qui a été utilisée moins récemment. Elle est plus susceptible d'être récupérée à d'autres fins.
Active(anon) %lu (depuis Linux 2.6.28)
[À documenter.]
Inactive(anon) %lu (depuis Linux 2.6.28)
[À documenter.]
Active(file) %lu (depuis Linux 2.6.28)
[À documenter.]
Inactive(file) %lu (depuis Linux 2.6.28)
[À documenter.]
Unevictable %lu (depuis Linux 2.6.28)
(De Linux 2.6.28 à Linux 2.6.30, CONFIG_UNEVICTABLE_LRU était requis.) [À documenter.]
Mlocked %lu (depuis Linux 2.6.28)
(De Linux 2.6.28 à Linux 2.6.30, CONFIG_UNEVICTABLE_LRU était requis.) [À documenter.]
HighTotal %lu
(À partir de Linux 2.6.19, CONFIG_HIGHMEM est requis.) Quantité totale de highmem. Le highmem est toute mémoire au-dessus d'environ 860 Mo de mémoire physique. Les zones highmem sont destinées à être utilisées par les programmes en espace utilisateur, ou pour le cache de pages. Le noyau doit utiliser des astuces pour accéder à cette mémoire, ce qui rend son accès plus lent que celui du lowmem.
HighFree %lu
(À partir de Linux 2.6.19, CONFIG_HIGHMEM est requis.) Quantité de highmem libre.
LowTotal %lu
(À partir de Linux 2.6.19, CONFIG_HIGHMEM est requis.) Quantité totale de lowmem. Le lowmem est la mémoire qui peut être utilisée pour tout ce pour quoi le highmem peut être utilisé, mais elle est également disponible pour l'utilisation du noyau pour ses propres structures de données. Entre autres choses, c'est là que tout est alloué à partir de Slab. Des problèmes surviennent lorsque l'on manque de lowmem.
LowFree %lu
(À partir de Linux 2.6.19, CONFIG_HIGHMEM est requis.) Quantité de lowmem libre.
MmapCopy %lu (depuis Linux 2.6.29)
(CONFIG_MMU est requis.) [À documenter.]
SwapTotal %lu
Quantité totale d'espace d'échange disponible.
SwapFree %lu
Quantité d'espace d'échange actuellement inutilisée.
Dirty %lu
Mémoire en attente d'être écrite sur le disque.
Writeback %lu
Mémoire en cours d'écriture sur le disque.
AnonPages %lu (depuis Linux 2.6.18)
Pages non liées à des fichiers mappées dans les tables de pages de l'espace utilisateur.
Mapped %lu
Fichiers qui ont été mappés en mémoire (avec mmap(2)), tels que les bibliothèques.
Shmem %lu (depuis Linux 2.6.32)
Quantité de mémoire consommée dans les systèmes de fichiers tmpfs(5), la mémoire partagée System V et POSIX, ainsi que les mappages anonymes partagés (MAP_SHARED|MAP_ANONYMOUS).
KReclaimable %lu (depuis Linux 4.20)
Allocations du noyau que le noyau tentera de récupérer sous pression mémoire. Comprend SReclaimable (ci-dessous) et d'autres allocations directes avec un nettoyeur.
Slab %lu
Cache des structures de données internes au noyau. (Voir slabinfo(5).)
SReclaimable %lu (depuis Linux 2.6.19)
Partie de Slab qui peut être récupérée, comme les caches.
SUnreclaim %lu (depuis Linux 2.6.19)
Partie de Slab qui ne peut pas être récupérée en cas de pression mémoire.
KernelStack %lu (depuis Linux 2.6.32)
Quantité de mémoire allouée aux piles du noyau.
PageTables %lu (depuis Linux 2.6.18)
Quantité de mémoire dédiée au plus bas niveau des tables de pages.
Quicklists %lu (depuis Linux 2.6.27)
(CONFIG_QUICKLIST est requis.) [À documenter.]
NFS_Unstable %lu (depuis Linux 2.6.18)
Pages NFS envoyées au serveur, mais pas encore validées dans un stockage stable.
Bounce %lu (depuis Linux 2.6.18)
Mémoire utilisée pour les "bounce buffers" des périphériques blocs.
WritebackTmp %lu (depuis Linux 2.6.26)
Mémoire utilisée par FUSE pour les tampons d'écriture temporaires.
CommitLimit %lu (depuis Linux 2.6.10)
C'est la quantité totale de mémoire actuellement disponible pour être allouée sur le système, exprimée en kilo-octets. Cette limite n'est respectée que si la comptabilité de sur-allocation stricte est activée (mode 2 dans /proc/sys/vm/overcommit_memory). La limite est calculée selon la formule décrite sous /proc/sys/vm/overcommit_memory. Pour plus de détails, voir le fichier source du noyau Documentation/vm/overcommit-accounting.rst.
Committed_AS
(depuis Linux 2.6.10) Somme de toutes les pages qui ont été allouées, qu'elles soient déjà utilisées ou non. Ces pages sont garanties à l'application. Plus d'informations sous /proc/sys/vm/overcommit_memory.

/i> %lu
La quantité de mémoire actuellement allouée sur le système. La mémoire engagée est la somme de toute la mémoire qui a été allouée par les processus, même si elle n'a pas encore été « utilisée » par ceux-ci. Un processus qui alloue 1 Go de mémoire (en utilisant malloc(3) ou similaire), mais qui n'utilise que 300 Mo de cette mémoire sera considéré comme utilisant seulement 300 Mo de mémoire, même s'il a l'espace d'adressage alloué pour l'intégralité du 1 Go.
Ce 1 Go est de la mémoire qui a été « engagée » par le noyau et qui peut être utilisée à tout moment par l'application qui l'a allouée. Avec une politique stricte de dépassement de la capacité (overcommit) activée sur le système (mode 2 dans /proc/sys/vm/overcommit_memory), les allocations qui dépasseraient la CommitLimit ne seront pas autorisées. Ceci est utile si l'on veut garantir que les processus ne tomberont pas en panne faute de mémoire une fois que cette mémoire aura été allouée avec succès.
VmallocTotal %lu
Taille totale de la zone mémoire vmalloc.
VmallocUsed %lu
Quantité de la zone vmalloc qui est utilisée. Depuis Linux 4.4, ce champ n'est plus calculé et est codé en dur à 0. Voir /proc/vmallocinfo.
VmallocChunk %lu
Plus grand bloc contigu de la zone vmalloc qui est libre. Depuis Linux 4.4, ce champ n'est plus calculé et est codé en dur à 0. Voir /proc/vmallocinfo.
HardwareCorrupted %lu (depuis Linux 2.6.32)
(CONFIG_MEMORY_FAILURE est requis.) [À documenter.]
LazyFree %lu (depuis Linux 4.12)
Indique la quantité de mémoire marquée par madvise(2) MADV_FREE.
AnonHugePages %lu (depuis Linux 2.6.38)
(CONFIG_TRANSPARENT_HUGEPAGE est requis.) Pages énormes non basées sur des fichiers mappées dans les tables de pages de l'espace utilisateur.
ShmemHugePages %lu (depuis Linux 4.8)
(CONFIG_TRANSPARENT_HUGEPAGE est requis.) Mémoire utilisée par la mémoire partagée (shmem) et tmpfs(5) allouée avec des pages énormes.
ShmemPmdMapped %lu (depuis Linux 4.8)
(CONFIG_TRANSPARENT_HUGEPAGE est requis.) Mémoire partagée mappée dans l'espace utilisateur avec des pages énormes.
CmaTotal %lu (depuis Linux 3.1)
Pages CMA (Contiguous Memory Allocator) totales. (CONFIG_CMA est requis.)
CmaFree %lu (depuis Linux 3.1)
Pages CMA (Contiguous Memory Allocator) libres. (CONFIG_CMA est requis.)
HugePages_Total %lu
(CONFIG_HUGETLB_PAGE est requis.) Taille du pool de pages énormes.
HugePages_Free %lu
(CONFIG_HUGETLB_PAGE est requis.) Nombre de pages énormes dans le pool qui ne sont pas encore allouées.
HugePages_Rsvd %lu (depuis Linux 2.6.17)
(CONFIG_HUGETLB_PAGE est requis.) C'est le nombre de pages énormes pour lesquelles un engagement d'allocation à partir du pool a été fait, mais aucune allocation n'a encore été effectuée. Ces pages énormes réservées garantissent qu'une application sera capable d'allouer une page énorme à partir du pool de pages énormes au moment de l'échec.
HugePages_Surp %lu (depuis Linux 2.6.24)
(CONFIG_HUGETLB_PAGE est requis.) C'est le nombre de pages énormes dans le pool au-dessus de la valeur dans /proc/sys/vm/nr_hugepages. Le nombre maximum de pages énormes excédentaires est contrôlé par /proc/sys/vm/nr_overcommit_hugepages.
Hugepagesize %lu
(CONFIG_HUGETLB_PAGE est requis.) La taille des pages énormes.
DirectMap4k %lu (depuis Linux 2.6.27)
Nombre d'octets de RAM mappés linéairement par le noyau en pages de 4 Ko. (x86.)
DirectMap4M %lu (depuis Linux 2.6.27)
Nombre d'octets de RAM mappés linéairement par le noyau en pages de 4 Mo. (x86 avec CONFIG_X86_64 ou CONFIG_X86_PAE activé.)
DirectMap2M %lu (depuis Linux 2.6.27)
Nombre d'octets de RAM mappés linéairement par le noyau en pages de 2 Mo. (x86 sans CONFIG_X86_64 ni CONFIG_X86_PAE activé.)
DirectMap1G %lu (depuis Linux 2.6.27)
(x86 avec CONFIG_X86_64 et CONFIG_X86_DIRECT_GBPAGES activé.)
