FBB::Process(3bobcat) Exécution de processus enfants FBB::Process(3bobcat)

NOM

FBB::Process - Exécute des programmes externes

SYNTAXE

#include <bobcat/process>
Option de liaison : -lbobcat

DESCRIPTION

La classe FBB::Process offre une interface étendue pour appeler des programmes externes et/ou des scripts depuis un programme C++ (appelés processus enfants). La classe offre une interface facile à utiliser, basée sur les flux, pour les flux d'entrée standard, de sortie standard et d'erreur standard des processus enfants.

Les objets de la classe Process utilisent des fonctions standard d'exécution de processus, comme les membres de la famille execl(2) ou sh(1) pour exécuter des processus enfants. Ainsi, les processus enfants peuvent être des programmes exécutables ou des scripts shell.

Les flux standard d'entrée, de sortie et d'erreur des processus enfants peuvent être accédés via leurs objets parents Process. Les entrées attendues par les processus enfants peuvent être insérées par les objets Process, et les sorties générées par les processus enfants peuvent être extraites des objets Process.

Lors de l'utilisation de la redirection (de sortie) avec la spécification de chemin USE_SHELL (voir ci-dessous pour les spécifications de chemin et de mode d'E/S), le mode IGNORE_COUT IOMode (et éventuellement aussi IGNORE_CERR) devrait normalement être spécifié.

Les objets Process peuvent être utilisés de manière répétée pour exécuter des processus enfants identiques ou différents. Avant que le prochain processus enfant ne soit démarré, l'objet Process termine d'abord son processus enfant actuellement actif. Alternativement, un processus enfant actuellement actif est automatiquement terminé si l'objet Process sort de sa portée, si son membre stop ou eoi (fin d'information) est appelé, ou si le manipulateur eoi est inséré dans l'objet Process.

Les programmes appelés en tant que processus enfants peuvent être spécifiés lors de la construction d'un objet Process ou en utilisant le membre setCommand de Process. Les constructeurs de Process (ou les membres Process set) ne démarrent jamais de processus enfants. Les processus enfants sont démarrés via les membres start ou l'opérateur d'assignation.

Les processus enfants peuvent recevoir des informations sur leurs flux d'entrée standard via des informations insérées dans les objets Process. Dans ces cas, les objets Process doivent informer leurs processus enfants qu'ils ont reçu toutes les entrées. Pour cela, les membres close ou eoi ou le manipulateur eoi peuvent être utilisés. Après avoir appelé le membre close, le membre waitForChild doit également être appelé. Ce n'est pas nécessaire si le membre eoi ou le manipulateur eoi est utilisé.

Si waitForChild n'est pas appelé (mais que des informations ont été envoyées à l'enfant qui n'ont pas pu être entièrement traitées par le processus enfant dans le cas où le processus enfant s'est terminé à la suite de la sortie de l'objet Process de sa portée), alors le système d'exploitation émet un message Broken pipe, indiquant que des informations dans un tuyau ont été perdues.

Les arguments passés aux processus enfants peuvent être entourés de guillemets doubles ou simples. Les arguments entourés de guillemets doubles voient leurs guillemets retirés, tout en interprétant les séquences d'échappement qui ont pu être utilisées à l'intérieur. Les arguments entourés de guillemets simples voient leurs guillemets retirés, tout en acceptant leur contenu tel quel. De plus, des séquences d'échappement non citées peuvent être spécifiées : ces séquences d'échappement sont évaluées et remplacées par leurs caractères prévus (par exemple, \100 est converti en @).

Une spécification de commande complète peut être entourée de backticks (caractères `). Ces caractères backticks sont supprimés par l'objet Process lorsque la commande est démarrée.

Les processus enfants peuvent se voir accorder une durée limitée (en secondes) pour se terminer. Par défaut, aucune limite de temps n'est imposée aux processus enfants.

Par défaut, les flux d'entrée standard, de sortie standard et d'erreur standard des processus enfants sont accessibles via leurs processus parents Process : les informations insérées dans l'objet Process sont transmises au flux d'entrée standard du processus enfant, les informations envoyées par le processus enfant à son flux de sortie standard peuvent être extraites de l'objet Process parent, et les informations envoyées par le processus enfant à son flux d'erreur standard peuvent être obtenues via le membre childErrStream de Process.

Si les processus parent et enfant ont convenu d'un processus de communication, alors des informations peuvent être envoyées et reçues alternativement du processus enfant via les facilités ostream et istream de Process. Alternativement, des quantités non spécifiées d'informations écrites par les processus enfants peuvent être traitées par des threads séparés (voir la section EXEMPLES de cette page de manuel).

Les objets Process utilisent des objets Pipe (voir pipe(3bobcat)) pour communiquer avec leurs processus enfants. Pour s'assurer que ces tuyaux sont correctement fermés, les membres waitForChild, stop ou le manipulateur eoi doivent être utilisés. Une fois qu'un objet Process cesse d'exister, les tuyaux vers son processus enfant sont également fermés.

enum ProcessType :

L'énumération enum ProcessType définit comment un processus enfant est démarré ou localisé. Ses valeurs sont spécifiées au moment de la construction ou via le membre setProcessType. Cette énumération définit les constantes symboliques suivantes :

o
NO_PATH :
Le programme spécifié comme processus enfant est démarré tel quel, sans rechercher les éléments de la variable d'environnement PATH.
o
USE_PATH :
Les éléments de la variable d'environnement PATH sont utilisés lors de la localisation du programme spécifié comme processus enfant.
o
USE_SHELL :
Le programme spécifié comme processus enfant est appelé en utilisant /bin/sh -c. Lors de l'utilisation de la redirection (de sortie) avec la commande spécifiée, le mode IGNORE_COUT IOMode (et éventuellement aussi le mode IGNORE_CERR IOMode) devrait être spécifié.

Les valeurs de l'énumération enum IOMode sont utilisées pour définir lesquels des flux standard du processus enfant peuvent être accédés via l'objet Process. Ses constantes symboliques peuvent être combinées à l'aide de l'opérateur bit_or. Par défaut, CIN | COUT | CERR est utilisé (voir ci-dessous).

L'objet Process n'extrait ni n'insère d'informations dans les flux standards de son processus fils. enum ChildOutput :
L'énumération ChildOutput définit les valeurs retournées par le membre available (voir ci-dessous) indiquant sur quel flux standard le processus fils a écrit des informations. Cette énumération définit les valeurs suivantes :

o
NOTHING_AVAILABLE :
Le processus fils n'a (pas encore) écrit d'informations sur ses flux standards ;
o
CHILD_COUT :
Le processus fils a écrit des informations sur son flux de sortie standard qui attendent d'être extraites.
o
CHILD_CERR :
Le processus fils a écrit des informations sur son flux d'erreur standard qui attendent d'être extraites. Ces deux dernières valeurs peuvent être combinées à l'aide de l'opérateur bit_or. L'opérateur bit_and, retournant une valeur bool, peut être utilisé pour tester si des informations sur un flux de sortie spécifique sont disponibles.

PARAMÈTRES DU PROCESSUS

Quatre paramètres de processus peuvent être spécifiés : les tailles des buffers de flux utilisés lors de la communication avec les processus fils ; pour spécifier lesquels des flux standards des processus fils sont accessibles depuis l'objet Process, des combinaisons de valeurs IOMode sont utilisées ; pour spécifier comment les programmes fils sont trouvés, une valeur ProcessType est utilisée ; pour spécifier le temps maximum (en secondes) pendant lequel le programme fils est autorisé à s'exécuter, des valeurs size_t sont utilisées.

Par défaut, les buffers de flux contiennent 200 octets ; tous les flux standards du fils (entrée standard, sortie standard et erreur standard) sont accessibles depuis le processus Parent ; la variable d'environnement PATH n'est pas utilisée pour localiser le programme fils ; et les processus fils auront un temps illimité pour s'exécuter.

Après la construction d'un objet Process, tous les paramètres par défaut peuvent être modifiés. Ces paramètres peuvent être modifiés soit pour un seul processus, soit les valeurs par défaut générales d'un objet Process peuvent être modifiées. Les membres set* (voir ci-dessous) peuvent être utilisés pour modifier les paramètres par défaut du processus. Lorsque des paramètres sont spécifiés autrement, ils ne seront actifs que pour le prochain processus.

CONSTRUCTEURS

La commande fournie aux constructeurs suivants peut être la (partie initiale de la) spécification d'un programme externe à exécuter. Lorsque le programme est finalement démarré, il peut commencer et se terminer par des apostrophes inversées (`). Les apostrophes inversées seront supprimées juste avant que le programme spécifié ne soit exécuté.

Les processus fils ne sont pas démarrés automatiquement après la construction d'un objet Process. Un membre start ou l'opérateur d'assignation (voir ci-dessous) est utilisé pour démarrer le processus fils spécifié.

Les constructeurs qui attendent un argument IOMode peuvent se voir fournir plusieurs valeurs IOMode en les combinant avec l'opérateur bit à bit OR.

Après la construction d'un objet Process, ses paramètres peuvent être modifiés en utilisant les fonctions membres set, les opérateurs de fonction ou les membres start.

OPÉRATEURS REDÉFINIS

o
Process &operator<<(Type value) :
Cet opérateur insère value dans le flux d'entrée standard du fils. C'est-à-dire que le processus fils lit value depuis son entrée standard. Une valeur de n'importe quel type qui peut être inséré dans un ostream peut être insérée dans un objet Process. Rien ne se passe si le membre est utilisé lorsque le processus fils a terminé. Les manipulateurs comme std::endl sont également supportés. Le comportement de cet opérateur est indéfini sauf si IOMode CIN a été spécifié.
o
Process &operator>>(Type value) :
Cet opérateur extrait value du flux de sortie standard du fils et optionnellement (si IOMode MERGE_COUT_CERR a été spécifié) du flux d'erreur du fils. C'est-à-dire que value peut être extrait des objets Process. Une valeur de n'importe quel type qui peut être extraite d'un istream peut être extraite d'un objet Process. Rien ne se passe si le membre est utilisé lorsque le processus fils a terminé. Le comportement de cet opérateur est indéfini sauf si IOMode COUT ou MERGE_COUT_CERR a été spécifié.
o
Process &operator+=(std::string const &) :
Cet opérateur ajoute l'objet std::string fourni à la spécification de commande actuellement définie d'un objet Process. Le membre operator+= n'ajoute pas d'espace séparateur entre la spécification de commande stockée actuellement et le texte à ajouter. Il ajoute simplement sa chaîne de droite à la commande stockée jusqu'à présent. Il n'affecte pas un processus fils en cours d'exécution.
o
int operator=(std::string const &cmd) :
Le membre operator= définit cmd comme la commande stockée dans un objet Process.
Avant de démarrer le processus fils, un processus fils potentiellement actif est d'abord arrêté en appelant stop. Il retourne la valeur de retour de stop. Immédiatement après avoir appelé stop, la nouvelle commande (cmd) est démarrée. Si l'arrêt et le redémarrage d'une autre commande doivent être des actions séparées, utilisez stop, suivi de setCommand, suivi de l'appel d'une version surchargée appropriée du membre start (start() utilise le IOMode, ProcessType, et la limite de temps actuels de l'objet).
o
Process &operator()(IOMode mode) :
Cet opérateur modifie le paramètre IOMode de l'objet Process. Une référence à l'objet Process est retournée, permettant des constructions comme 
    process(Process::COUT) = "/bin/cat";
pour démarrer un nouveau processus fils avec le IOMode spécifié.
o
Process &operator()(IOMode mode, ProcessType type) :
Cet opérateur modifie les paramètres de processus IOMode et ProcessType de l'objet Process.

Cet opérateur modifie les paramètres du processus de l'objet Process mentionné. La taille par défaut actuellement spécifiée des tampons de flux est conservée telle quelle.
o
Process &operator()(IOMode mode, ProcessType type, size_t timeLimit, size_t bufferSize):
Cet opérateur modifie tous les paramètres du processus de l'objet Process.
o
Process &operator|(Process &lhs, Process &rhs):
Cet opérateur implémente le piping de processus : les informations envoyées par lhs à sa sortie standard deviennent l'entrée standard de rhs. L'opérateur retourne rhs.
Cet opérateur imite l'opérateur de piping pris en charge par la plupart des programmes de shell, et ne doit pas être confondu avec l'opérateur OU binaire. L'opérateur démarre le processus fils de lhs, mais le processus fils de rhs (et donc le traitement du pipe) doit être explicitement démarré.
Comme operator| est associatif à gauche et que rhs est retourné, le piping peut être enchaîné, permettant des constructions comme p1 | p2 | p3, où p1, p2 et p3 sont des objets Process.
L'idiome suivant peut être utilisé pour démarrer l'exécution d'une chaîne de processus : (p1 | p2 | p3).start(). Alternativement, la procédure en deux étapes suivante peut être utilisée : 
    p1 | p2 | p3;
    p3.start();
Si p1 spécifie Process::CIN, alors ce IOMode est transmis au processus final de la chaîne de processus. Il n'est pas nécessaire de spécifier Process::CIN pour p3. En fait, la plupart des indicateurs IOMode des processus passés à operator| sont ignorés ou modifiés. Les IOModes acceptables sont Process::IGNORE_CERR et Process::CERR (acceptés pour tous les processus), Process::CIN (accepté pour le premier processus de la chaîne), et Process::COUT (pour le dernier processus de la chaîne).
Note : lors de la connexion d'une série de processus à l'aide de operator|, toutes les entrées et sorties (à l'exception des flux d'erreur standard) sont gérées via le dernier processus : si Process::CIN est spécifié pour le premier processus, alors ce mode est transféré au dernier processus, de sorte que les informations insérées dans le dernier processus entrent dans le pipe via l'entrée standard du premier processus.
L'exemple suivant illustre comment l'entrée peut être insérée dans le premier processus à partir d'un processus principal et envoyée au flux de sortie standard par le processus final : 
    using namespace std;
    using namespace FBB;
    Process p1(Process::CIN, "/bin/cat");
    Process p2("/bin/cat");
    Process p3(Process::NONE, "/bin/cat");
    p1 | p2 | p3;
    p3.start();
    p3 << cin.rdbuf() << eoi;
Lors de la jonction de plusieurs commandes à l'aide de l'opérateur de piping ('|'), le type de processus USE_SHELL n'est pas requis, même si le piping de processus est couramment utilisé comme une fonctionnalité de shell. L'opérateur Process::operator| gère le piping d'E/S lui-même, et peut ainsi éviter le processus shell supplémentaire.

MEMBRES

o
bool active():
Ce membre retourne true si le processus fils est actuellement en cours d'exécution et false sinon.
o
size_t available():
Ce membre retourne immédiatement. Sa valeur de retour indique si des informations peuvent être obtenues du processus fils sous forme de valeur(s) de l'enum ChildOutput. NOTHING_AVAILABLE est retourné si aucune information n'est prête à être extraite. CHILD_COUT est retourné si des informations du flux de sortie standard du processus fils sont disponibles ; CHILD_CERR est retourné si des informations du flux d'erreur standard du processus fils sont disponibles ; CHILD_COUT | CHILD_CERR est retourné si des informations des flux de sortie standard et d'erreur standard sont disponibles. L'opérateur bit_and, retournant une valeur bool, peut être utilisé pour déterminer quel flux a des informations en attente. Par exemple, 
    if (process.available() & Process::CHILD_COUT)
        cout << "Process has child standard output available";
o
size_t bufSize() const:
Ce membre retourne la taille par défaut des tampons de flux utilisés pour la communication avec les processus fils. Si appelé pendant qu'un processus fils est effectivement en cours d'exécution, la valeur retournée par ce membre peut différer de la valeur qui a été réellement utilisée lors du démarrage du processus fils, car la valeur par défaut peut être modifiée par un appel de fonction juste avant le démarrage du processus fils.
o
std::istream &childErrStream():
Si Process::CERR a été spécifié, ce membre s'interface avec le flux d'erreur standard du fils. En extrayant les informations de childErrStream, le processus parent récupère les informations envoyées par son processus fils à son flux d'erreur standard.
o
std::istream &childOutStream():
Si Process::COUT ou Process::MERGE_COUT_CERR a été spécifié, ce membre s'interface avec le flux de sortie standard du fils. En extrayant les informations de childOutStream, le processus parent récupère les informations envoyées par son processus fils à son flux de sortie standard. Alternativement, ces informations peuvent être extraites directement de l'objet Process lui-même, mais ce membre ne nécessite pas l'utilisation d'un static_cast pour désambiguïser le tampon de flux visé dans des énoncés comme 
    cout << process.childOutStream().rdbbuf()
o
void close():
Ce membre ferme le flux d'entrée du fils. Dans les situations où le fils lit continuellement des informations de son flux d'entrée standard, ce membre peut être utilisé pour informer le processus fils que l'entrée est terminée. Ce membre ne doit être utilisé que si IOMode CIN a été spécifié pour le processus fils actuellement en cours d'exécution ; sinon, son comportement est indéfini. Alternativement, le membre eoi ou le manipulateur peuvent être utilisés.
o
int eoi():
Ce membre ferme le flux d'entrée du fils, puis appelle waitForChild pour attendre la fin du processus fils. Dans les situations où le fils lit continuellement des informations de son flux d'entrée standard, ce membre peut être utilisé pour informer le processus fils que l'entrée est terminée. Ce membre ne doit être utilisé que si IOMode CIN a été spécifié pour le processus fils actuellement en cours d'exécution ; sinon, son comportement est indéfini. Alternativement, le membre close ou le manipulateur eoi peuvent être utilisés. Le statut de sortie du processus fils appelé est retourné.
o
int exitStatus() const:
Après avoir appelé eoi ou inséré le manipulateur eoi dans l'objet Process, ce membre retourne le statut de sortie du processus fils. Dans d'autres cas, la valeur retournée par exitStatus n'est pas définie, et waitForChild devrait être utilisé.
o
IOMode ioMode() const:
Ce membre retourne l'IOMode par défaut. Si appelé pendant qu'un processus fils est effectivement en cours d'exécution, la valeur retournée par ce membre peut différer de la valeur qui a été réellement utilisée lors du démarrage du processus fils, car la valeur par défaut peut être modifiée par un appel de fonction juste avant le démarrage du processus fils.
o
ProcessType processType() const:
Ce membre retourne le ProcessType par défaut des processus fils. Si appelé pendant qu'un processus fils est effectivement en cours d'exécution, la valeur retournée par ce membre peut différer de la valeur qui a été réellement utilisée lors du démarrage du processus fils, car la valeur par défaut peut être modifiée par un appel de fonction juste avant le démarrage du processus fils.
o
size_t timeLimit() const:
Ce membre retourne la limite de temps par défaut (en secondes) des processus fils. Une valeur de retour de zéro indique qu'aucune limite de temps n'est appliquée. Si appelé pendant qu'un processus fils est effectivement en cours d'exécution, la valeur retournée par ce membre peut différer de la valeur qui a été réellement utilisée lors du démarrage du processus fils, car la valeur par défaut peut être modifiée par un appel de fonction juste avant le démarrage du processus fils.
o
void setBufSize(size_t bufSize):
Ce membre modifie la taille par défaut du tampon de flux utilisée pour la communication avec les processus fils. Une taille de tampon de zéro octet est silencieusement remplacée par un. La nouvelle valeur par défaut sera utilisée lors du démarrage du prochain processus fils.
o
void setCommand(std::string const &cmd):
Le membre setCommand redéfinit la spécification de commande (partie initiale) d'un processus fils.
Ce membre ne démarre pas réellement le processus fils, et operator+= peut être utilisé pour ajouter du texte supplémentaire à la spécification de commande. De plus, ce membre peut être utilisé lorsqu'un processus fils est actuellement actif : son utilisation n'affecte pas un processus fils en cours d'exécution.
o

Ce membre modifie l'IOMode par défaut. La nouvelle valeur par défaut sera utilisée lors du démarrage du prochain processus fils.

Ce membre modifie le ProcessType par défaut. La nouvelle valeur par défaut sera utilisée lors du démarrage du prochain processus fils.

Ce membre modifie la limite d'exécution par défaut (en secondes). Aucune limite de temps ne sera imposée aux processus fils si timeLimit 0 est spécifié. La nouvelle valeur par défaut sera utilisée lors du démarrage du prochain processus fils.
o
void start():
La commande actuellement spécifiée est démarrée en utilisant l'objet Process objet’s.
2019 ; paramètres du processus.
Après avoir spécifié une commande de démarrage, le premier élément délimité par des espaces blancs de la commande spécifiée est utilisé comme nom du programme à démarrer. Si le programme doit être appelé via sh(1), le membre USE_SHELL ProcessType ou un membre system doit être utilisé.
Si un processus enfant ne se termine pas de lui-même, il est arrêté lorsqu'il a dépassé son temps alloué ; lorsque les membres start ou stop de l'objet Process sont appelés ; lorsque l'opérateur d'affectation de l'objet est utilisé ; ou lorsque l'objet sort de sa portée.

void system() :
Ce membre exécute la commande actuellement stockée comme commande pour sh(1). Lors de l'utilisation de system, les redirections peuvent être incluses dans la commande elle-même (ce qui rend inutiles les flux redirigés impliqués par le IOMode actuel). Les paramètres du processus actuellement définis sont utilisés lors de l'exécution de sh(1).

Ce membre exécute la commande actuellement stockée comme commande pour sh(1) (cf. system ci-dessus) en utilisant le IOMode spécifié plutôt que le réglage IOMode par défaut actuel.
o
void system(IOMode mode, size_t timeLimit) :
Ce membre exécute la commande actuellement stockée comme commande pour sh(1) (cf. system ci-dessus) en utilisant le IOMode et la limite de temps spécifiés.
o
void system(IOMode mode, size_t timeLimit, size_t bufSize) :
Ce membre exécute la commande actuellement stockée comme commande pour sh(1) (cf. system ci-dessus) en utilisant le IOMode, la limite de temps et les valeurs de taille du tampon de flux spécifiés.
o
int stop() :
Ce membre arrête un processus enfant actuellement actif. Le processus enfant reçoit deux fois un signal SIG_TERM, suivi d'un signal SIG_KILL. Ce membre renvoie la valeur de sortie du processus enfant qui a été arrêté. Son fonctionnement et sa valeur de retour sont indéfinis s'il est appelé sans processus enfant en cours d'exécution.
Après stop, une nouvelle commande peut être appelée en utilisant start, system ou l'opérateur d'affectation (voir plus haut). Ces membres appellent d'abord stop. Lorsque l'intention est de démarrer un autre processus enfant, il n'est pas nécessaire d'appeler stop explicitement. De plus, stop est appelé lorsque l'objet Process sort de sa portée.
o
int waitForChild() :
Ce membre appelle le membre de même nom de la classe FBB::Fork, attendant qu'un processus enfant se termine. Il est appelé pour éviter la terminaison prématurée d'un processus enfant avant d'appeler stop. Il n'est pas toujours nécessaire d'appeler waitForChild. Par exemple, lorsqu'un processus écrit dans son flux de sortie standard et que toute la sortie a été lue, le processus enfant peut être arrêté sans appeler waitForChild.

MANIPULATEUR

o
FBB::eoi :
Ce manipulateur peut être inséré dans un objet Process pour lequel IOMode CIN a été spécifié. Il ferme le flux d'entrée de l'enfant, puis appelle waitForChild pour attendre la fin du processus enfant. Dans les situations où l'enfant lit continuellement des informations de son flux d'entrée standard, ce membre peut être utilisé pour informer l'enfant que l'entrée est terminée. Alternativement, les membres close ou eoi de l'objet Process peuvent être utilisés.

EXEMPLES

Le premier exemple montre comment un programme produisant uniquement de la sortie peut être appelé. Son processus enfant est simplement /bin/ls :

int main()
{
    Process process(Process::COUT, "/bin/ls -Fla");
    process.start();
    cout << process.childOutStream().rdbuf();
}

L'exemple suivant montre comment un programme enfant peut se voir attribuer une durée d'exécution limitée : les lignes saisies au clavier sont renvoyées sur le flux de sortie standard pendant au plus 5 secondes :

int main()
{
    Process process(Process::CIN | Process::COUT, "/bin/cat");
    process.setTimeLimit(5);
    process.start();
    while (true)
    {
        cout << "? ";
        string line;
        if (not getline(cin, line))
            return 0;
        process << line << endl;           // vers /bin/cat
        line.clear();
        if (not getline(process, line))    // depuis /bin/cat
            break;
        cout << "Reçu : " << line << endl;
    }
    cout << "La limite de temps de 5 secondes de /bin/cat est atteinte : le processus enfant s'est terminé\n";
}

Le dernier exemple montre comment le multithreading peut être utilisé pour accéder aux flux de sortie standard et d'erreur du programme enfant via l'objet Process :

void collect(ostream *outStream, streambuf *rdbuf)
{
    *outStream << rdbuf << flush;
}
int main()
{
    string cmd(getcwd(0, 0));
    cmd += "/cincoutcerr";
    Process all(Process::ALL, cmd);
    all.start();
    thread outThread(collect, &cout, all.childOutStream().rdbuf());
    thread errThread(collect, &cerr, all.childErrStream().rdbuf());
    all << cin.rdbuf() << eoi;
    outThread.join();
    errThread.join();
}

NOM

process — une classe pour représenter des processus

SYNTAXE

class process

DESCRIPTION

La classe process est conçue pour gérer les processus et leurs flux d'E/S. Elle fournit des méthodes pour démarrer, arrêter, surveiller et interagir avec des processus externes.

ESPACE DE NOMMAGE

Aucun espace de nommage spécifique n'est requis pour cette classe.

HÉRITE DE

Cette classe n'hérite d'aucune autre classe.

ÉNUMÉRATIONS

Aucune énumération n'est définie dans cette classe.

PARAMÈTRES DU PROCESSUS

La classe process peut être configurée avec divers paramètres, tels que le chemin de l'exécutable, les arguments de la ligne de commande, les variables d'environnement et les répertoires de travail.

CONSTRUCTEURS

Le constructeur par défaut initialise un objet process prêt à être configuré.

OPÉRATEURS SURCHARGÉS

Aucun opérateur surchargé n'est défini.

MEMBRES

Les membres de la classe process permettent de contrôler le cycle de vie du processus.

  • start() : Démarre le processus.
  • stop() : Arrête le processus.
  • isRunning() : Vérifie si le processus est en cours d'exécution.
  • getStdout() : Récupère la sortie standard du processus.
  • getStderr() : Récupère la sortie d'erreur standard du processus.
  • writeStdin(const std::string& data) : Écrit des données dans l'entrée standard du processus.

MANIPULATEUR

Aucun manipulateur spécifique n'est disponible.

EXEMPLES

Voici un exemple d'utilisation de la classe process :


#include <bobcat/process>
#include <iostream>

int main() {
    bobcat::process p;
    p.setExecutable("ls");
    p.setArguments({"-l"});
    p.start();
    p.waitForExit();
    std::cout << p.getStdout();
    return 0;
}
