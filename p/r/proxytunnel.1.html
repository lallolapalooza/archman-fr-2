PROXYTUNNEL(1)   PROXYTUNNEL(1)

NOM

proxytunnel - programme pour tunneler une connexion via un proxy HTTPS standard

SYNTAXE

proxytunnel [OPTION...] [hôte:port]

DESCRIPTION

proxytunnel est un programme pour tunneler toute connexion via un proxy HTTPS standard, contournant ainsi les mécanismes de filtrage HTTP standards. Il est principalement utilisé comme backend pour ProxyCommand d'OpenSSH, et comme backend proxy pour Putty. Il peut également être utilisé pour d'autres besoins de traversée de proxy comme le rebond de proxy.

OPTIONS

-i, --inetd

Exécuter depuis inetd (par défaut : désactivé).

-a, --standalone=[adresse:]port

Exécuter comme démon autonome sur l'adresse et le port spécifiés. L'adresse peut être une adresse IPv4, une adresse IPv6 entre crochets ou une combinaison d'adresse IPv6 entre crochets, '%' et nom d'interface. Ce dernier format n'est requis qu'avec les adresses IPv6 locales au lien. Le démon écoute sur n'importe quelle adresse si l'adresse n'est pas fournie.

Exemples

22, 123.45.67.89:22, [2001:db8::123:4567:89ab:cdef]:22, [2001:db8::123:4567:89ab:cdef%eth0]:22

-p, --proxy=hôte:port

Utiliser hôte et port comme proxy local pour se connecter, sinon la variable d'environnement HTTP_PROXY, si elle est définie, sera utilisée à la place.

-r, --remproxy=hôte:port

Utiliser hôte et port comme proxy distant (secondaire) pour se connecter.

-d, --dest=hôte:port

Utiliser hôte et port comme destination du tunnel, vous pouvez également les spécifier comme arguments de la commande proxytunnel.

-e, --encrypt

Chiffrer SSL les données entre le proxy local et la destination.

-E, --encrypt-proxy

Chiffrer SSL les données entre le client et le proxy local.

-X, --encrypt-remproxy

Chiffrer SSL les données entre le proxy local et le proxy distant (secondaire).

OPTIONS ADDITIONNELLES

-W, --wa-bug-29744

Solution de contournement du bug ASF Bugzilla 29744 : si le SSL est utilisé (par les options -e, -E, -X), arrêter de l'utiliser immédiatement après l'échange CONNECT pour contourner les bugs du serveur Apache (cela pourrait ne pas fonctionner dans toutes les configurations).

-B, --buggy-encrypt-proxy

Équivalent à -E -W (fourni pour la compatibilité descendante).

-z, --no-check-certificate

Ne pas vérifier le certificat SSL du serveur lors de l'établissement d'une connexion SSL. Par défaut, le certificat SSL du serveur est vérifié et le nom d'hôte cible est vérifié par rapport aux noms alternatifs du sujet du certificat s'il y en a, ou au nom commun s'il n'y a pas de noms alternatifs du sujet.

-C, --cacert=nom_fichier/répertoire

Spécifier un fichier de certificat d'autorité de certification (ou un répertoire contenant des certificats d'autorité de certification) à faire confiance lors de la vérification d'un certificat SSL serveur. Si un répertoire est fourni, il doit être préparé avec l'outil c_rehash d'OpenSSL (par défaut, sauf indication contraire lors de la compilation avec les options DEFAULT_CA_FILE ou DEFAULT_CA_DIR : /etc/ssl/certs).

-4, --ipv4

Forcer l'utilisation d'IPv4 lors de la connexion au proxy local.

-6, --ipv6

Forcer l'utilisation d'IPv6 lors de la connexion au proxy local.

-F, --passfile=nom_fichier

Utiliser nom_fichier pour lire le nom d'utilisateur et le mot de passe pour l'authentification proxy HTTPS, le fichier utilise le même format que .wgetrc et peut être partagé avec wget. Utilisez cette option, ou les variables d'environnement pour masquer le mot de passe aux autres utilisateurs.

-P, --proxyauth=nom_utilisateur:mot_de_passe

Utiliser nom_utilisateur et mot_de_passe comme identifiants pour s'authentifier auprès d'un proxy HTTPS local, le nom d'utilisateur et le mot de passe peuvent également être spécifiés dans les variables d'environnement PROXYUSER et PROXYPASS pour les masquer aux autres utilisateurs. Si le mot_de_passe est omis et qu'aucune variable d'environnement PROXYPASS n'est définie, proxytunnel demandera un mot de passe.

-R, --remproxyauth=nom_utilisateur:mot_de_passe

Utiliser nom_utilisateur et mot_de_passe comme identifiants pour s'authentifier auprès d'un proxy HTTPS distant (secondaire), le nom d'utilisateur et le mot de passe peuvent également être spécifiés dans les variables d'environnement REMPROXYUSER et REMPROXYPASS pour les masquer aux autres utilisateurs. Si le mot_de_passe est omis et qu'aucune variable d'environnement REMPROXYPASS n'est définie, proxytunnel demandera un mot de passe.

-c, --cert=nom_fichier

Fournir le nom du fichier contenant le certificat client SSL pour s'authentifier par certificat client auprès du proxy local, du proxy distant ou de la destination. Le fichier doit être au format PEM. En plus de cela, il peut contenir un ou plusieurs certificats intermédiaires manquants côté serveur, formant ainsi une chaîne de certificats. Nécessite la spécification de -k, --key en plus. Ignoré si ni -e, --encrypt, ni -E, --encrypt-proxy, ni -X, --encrypt-remproxy n'est spécifié.

-k, --key=nom_fichier

Fournir le nom du fichier contenant la clé client SSL pour s'authentifier par certificat client auprès du proxy local, du proxy distant ou de la destination. Le fichier doit être au format PEM. Nécessite la spécification de -c, --cert en plus. Ignoré si ni -e, --encrypt, ni -E, --encrypt-proxy, ni -X, --encrypt-remproxy n'est spécifié.

-N, --ntlm

Utiliser l'authentification basée sur NTLM.

-t, --domain=CHAÎNE

Spécifier le domaine NTLM (par défaut : détection automatique).

-H, --header=CHAÎNE

Ajouter des en-têtes HTTP supplémentaires à envoyer au proxy.

-o, --host=hôte[:port]

Envoyer un en-tête Host personnalisé. Avec les connexions SSL, l'hôte est également envoyé sous forme de SNI.

-x, --proctitle=CHAÎNE

Utiliser un titre de processus différent.

OPTIONS DIVERSES

-v, --verbose

Activer la verbosité.

-q, --quiet

Supprimer les messages.

-h, --help

Afficher l'aide et quitter.

-V, --version

Afficher la version et quitter.

ARGUMENTS

hôte:port est la combinaison du nom d'hôte et du numéro de port de destination.


Remarque

Spécifier la destination comme arguments est exactement la même chose que de la spécifier en utilisant l'option -d ou --dest.

UTILISATION

Selon votre situation, vous pourriez vouloir faire l'une des choses suivantes :

•Se connecter via un proxy local à votre système domestique sur le port 22 
$ proxytunnel -v -p proxy.company.com:8080 -d system.home.nl:22
•Se connecter via un proxy local (avec authentification) à votre système domestique 
$ proxytunnel -v -p proxy.company.com:8080 -P username:password -d system.home.nl:22
•Se connecter via un proxy local (avec authentification) en masquant votre mot de passe 
$ export PROXYPASS=password
$ proxytunnel -v -p proxy.company.com:8080 -P username -d system.home.nl:22
•Se connecter via un proxy local à un proxy distant et rebondir vers n'importe quel système 
$ proxytunnel -v -p proxy.company.com:8080 -r proxy.athome.nl:443 -d system.friend.nl:22
•Se connecter en utilisant SSL via un proxy local à votre système domestique

NAME

proxytunnel - SSHv2 tunnel over an HTTP/HTTPS proxy

SYNOPSIS

proxytunnel [-v] [-E] [-e] [-4] [-6] [-p host:port] [-P user:pass] [-R user:pass] [-l localport] [-d dest] [command]

DESCRIPTION

The proxytunnel program tunnels an SSHv2 connection over an HTTP/HTTPS proxy. It can be used as a SOCKS server, or to connect to remote hosts via the proxy, or to remotely tunnel specific ports.

It can also be used as a standalone SSH client, for example, to access a shell on a remote host that is accessible via an HTTP/HTTPS proxy.

The program connects to the specified proxy server and then establishes an SSH connection to the desired destination host. The SSH connection is then tunneled through the proxy.

OPTIONS

-v, --verbose
Verbose mode. Prints debugging messages about the connection and proxy negotiation.
-E, --encrypt
Encrypts the connection to the proxy server. This option is typically used when connecting to an HTTPS proxy.
-e, --escalate
Escalates the connection to the proxy server. This option is typically used when the proxy requires authentication.
-4, --ipv4
Use IPv4 addresses only.
-6, --ipv6
Use IPv6 addresses only.
-p, --proxy host:port
Specifies the proxy server address and port. If not provided, proxytunnel will try to use the value of the HTTP_PROXY environment variable.
-P, --proxyauth user:pass
Specifies the username and password for proxy authentication. If not provided, proxytunnel will try to use the values of the PROXYUSER and PROXYPASS environment variables.
-R, --remproxyauth user:pass
Specifies the username and password for remote (secondary) proxy authentication. If not provided, proxytunnel will try to use the values of the REMPROXYUSER and REMPROXYPASS environment variables.
-l, --localport port
Specifies the local port to listen on for SOCKS proxying. If not specified, proxytunnel will try to use port 1080.
-d, --dest host:port
Specifies the destination host and port to connect to. This is typically used when proxytunnel is not used as a SOCKS server.

ADDITIONAL OPTIONS

These options are passed directly to the underlying SSH client.

-o, --ssh-option option
Specifies an option to be passed to the SSH client. For example, -o StrictHostKeyChecking=no.

MISCELLANEOUS OPTIONS

-h, --help
Show a help message and exit.
-V, --version
Show version information and exit.

ARGUMENTS

If command is specified, proxytunnel will execute it remotely via SSH. If no command is specified, proxytunnel will act as a SOCKS proxy server on the port specified by -l.

USAGE

To tunnel an SSH connection to system.home.nl on port 22 through a proxy at proxy.company.com on port 8080, use:

$ proxytunnel -v -E -p proxy.company.com:8080 -d system.home.nl:22

OPENSSH CONFIGURATION

To use this program with OpenSSH to connect to a host somewhere, create a ~/.ssh/config file with the following content:

Host system.athome.nl
    ProxyCommand proxytunnel -p proxy.company.com:8080 -d %h:%p
    ServerAliveInterval 30

Note

The ServerAliveInterval directive makes sure that idle connections are not being dropped by intermediate firewalls that remove active sessions aggressively. If you see your connection dropping out, try to lower the value even more.

To use the dynamic (SOCKS) portforwarding capability of the SSH client, you can specify the DynamicForward directive in your ssh_config file like:

Host system.athome.nl
    DynamicForward 1080
    ProxyCommand proxytunnel -p proxy.company.com:8080 -d %h:%p
    ServerAliveInterval 30

NOTES


Important

Most HTTPS proxies do not allow access to ports other than HTTPS (tcp/443) and SNEWS (tcp/563). In this case you need to make sure the SSH daemon or remote proxy on the destination system is listening on either tcp/443 or tcp/563 to get through.

ENVIRONMENT

Proxytunnel can be influenced by setting one of the following environment variables:

HTTP_PROXY

If this environment variable is set, proxytunnel will use it as the local proxy if -p or --proxy is not provided.

PROXYUSER

If this environment variable is set, proxytunnel will use it as the username for proxy authentication, unless specified using the -P or --proxyauth option.

PROXYPASS

If this environment variable is set, proxytunnel will use it as the password for proxy authentication, unless specified using the -P or --proxyauth option.

REMPROXYUSER

If this environment variable is set, proxytunnel will use it as the username for remote (secondary) proxy authentication, unless specified using the -R or --remproxyauth option.

REMPROXYPASS

If this environment variable is set, proxytunnel will use it as the password for remote (secondary) proxy authentication, unless specified using the -R or --remproxyauth option.
