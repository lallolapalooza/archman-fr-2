PRIMUSRUN(1) Manuel des commandes générales PRIMUSRUN(1)

NOM

primusrun - exécute une application sur une carte vidéo NVIDIA discrète

SYNTAXE

primusrun commande

DESCRIPTION

Primus implémente le déchargement OpenGL côté client avec un faible overhead, local uniquement, via le forking GLX.

Il est actuellement prévu pour être utilisé avec Bumblebee et fournit un remplacement direct pour optirun (c'est-à-dire "primusrun").

VARIABLES

Voici une liste des variables d'environnement affectant la bibliothèque primus qui peuvent être pertinentes pour les utilisateurs finaux :

PRIMUS_SYNC
Méthode de synchronisation de la lecture d'écran (par défaut : 0)
0 : aucune synchronisation, 1 : synchronisé, affiche l'image précédente, 2 : synchronisé, affiche l'image la plus récente
PRIMUS_VERBOSE
Niveau de verbosité (par défaut : 1)
0 : uniquement les erreurs, 1 : avertissements, 2 : profilage
PRIMUS_DISPLAY
Le numéro d'affichage du serveur Xorg secondaire (par défaut : :8)

EXEMPLES

primusrun glxgears -info
Exécute la démo graphique fournie par mesa-utils pour confirmer si la carte discrète est utilisée pour le rendu GL.
PRIMUS_VERBOSE=2 primusrun glxgears
Exécute la démo graphique fournie par mesa-utils avec une sortie verbeuse de primus.
vblank_mode=0 primusrun glxgears
Désactive la synchronisation vblank, généralement utilisée à des fins de benchmark.

PROBLEMES

Comme la composition nuit aux performances, l'invocation de primus lorsqu'un gestionnaire de fenêtres compositeur est actif n'est pas recommandée. Si vous avez besoin d'utiliser primus avec la composition et que vous constatez des scintillements ou de mauvaises performances, la synchronisation du thread d'affichage de primus avec le thread de rendu de l'application peut aider.

PRIMUS_SYNC=1 primusrun ...

Cela fait que primus affiche l'image précédemment rendue. Alternativement, avec PRIMUS_SYNC=2, primus affichera la dernière image rendue, échangeant le taux d'images contre une latence visuelle réduite.
