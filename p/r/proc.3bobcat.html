FBB::Proc(3bobcat) Exécution de processus fils FBB::Proc(3bobcat)

NOM

FBB::Proc - Exécute des programmes externes

SYNOPSIS

#include <bobcat/proc>
Option de liaison : -lbobcat

DESCRIPTION

FBB::Proc offre une alternative à la classe FBB::Process. FBB::Proc propose une interface complète pour appeler des programmes et/ou scripts externes depuis un programme C++ (les soi-disant processus fils). La classe offre une interface facile à utiliser, basée sur les flux, pour communiquer avec les flux d'entrée, de sortie et d'erreur standard des processus fils.

Les objets de la classe Proc utilisent les fonctions standard d'exécution de processus, comme les membres de la famille execl(2) ou sh(1) pour exécuter des processus fils. Ainsi, les processus fils peuvent être des programmes exécutables ou des scripts shell.

Les flux d'entrée, de sortie et d'erreur standard des processus fils peuvent être accédés via leurs objets parents Proc. Les entrées attendues par les processus fils peuvent être insérées dans les objets Proc. La sortie standard et l'erreur standard générées par les processus fils sont insérées et traitées par des objets std::ostream, par défaut std::cout et std::cerr.

Lors de l'utilisation de la redirection (de sortie) lors de l'exécution de processus fils en utilisant la spécification de chemin USE_SHELL (voir ci-dessous pour les spécifications de chemin et de mode d'E/S), le mode IOMode IGNORE_COUT (et éventuellement IGNORE_CERR) devrait normalement être spécifié (cf. section ÉNUMÉRATIONS pour une description de l'énumération IOMode).

Les objets Proc peuvent être utilisés de manière répétée pour exécuter des processus fils identiques ou différents. Avant le démarrage du processus fils suivant, l'objet Proc s'assure que son processus fils actuellement actif se termine. Alternativement, un processus fils actuellement actif se termine si l'objet Proc sort de portée, si le temps d'exécution alloué du processus fils est écoulé, si un nouveau processus est démarré en utilisant l'opérateur d'affectation de Proc, ou si son membre stop est appelé. Sinon, les processus fils se poursuivent jusqu'à leur achèvement lors de l'appel à finish ou, si le processus fils lit son flux d'entrée standard, lorsque le manipulateur eoi est inséré dans l'objet Proc.

Les programmes appelés en tant que processus fils peuvent être spécifiés lors de la construction d'un objet Proc ou en utilisant le membre setCommand de Proc. Les constructeurs de Proc (ou le membre setCommand de Proc) ne démarrent pas les processus fils. Pour démarrer des processus fils, les membres start ou l'opérateur d'affectation doivent être utilisés.

Les processus fils peuvent recevoir des informations sur leurs flux d'entrée standard via des informations insérées dans les objets Proc. Dans ces cas, les objets Proc doivent informer leurs processus fils qu'ils ont reçu toutes les entrées. Pour cela, le manipulateur eoi peut être inséré dans les objets Proc, ou le membre finish de Proc peut être appelé.

Si les informations envoyées au processus fils ne sont pas entièrement traitées par celui-ci, le système d'exploitation émet un message de « Tuyau brisé » (Broken pipe), indiquant que des informations dans un tuyau ont été perdues, ce qui termine le programme. Le membre pipeSignal de la classe Proc peut être utilisé pour supprimer le message « Tuyau brisé ».

Les arguments passés aux processus fils peuvent être entourés de guillemets doubles ou simples. Les arguments entourés de guillemets doubles ont leurs guillemets retirés, tout en interprétant les séquences d'échappement qui auraient pu être utilisées à l'intérieur. Les arguments entourés de guillemets simples ont leurs guillemets retirés, tout en acceptant leur contenu tel quel. De plus, des séquences d'échappement non citées peuvent être spécifiées : ces séquences d'échappement sont évaluées et remplacées par leurs caractères prévus (par exemple, \100 est converti en @).

Une spécification de commande complète peut également être entourée de backticks (caractères `). Ces caractères backticks sont retirés par l'objet Proc au démarrage de la commande.

Les processus fils peuvent se voir allouer une quantité de temps limitée (en secondes) pour s'achever. Par défaut, aucune limite de temps n'est imposée aux processus fils. Si une limite de temps est spécifiée, le processus fils, s'il est encore en cours d'exécution après le nombre de secondes spécifié, est terminé en lui envoyant un signal SIGTERM, suivi d'un signal SIGKILL (cf. signal(7)).

Par défaut, les flux d'entrée, de sortie et d'erreur standard des processus fils sont gérés par leurs processus parents Proc : les informations insérées dans l'objet Proc sont transmises au flux d'entrée standard du processus fils, les informations envoyées par le processus fils à ses flux de sortie et d'erreur standard sont soit transmises aux flux correspondants du processus parent, soit traitées par des flux configurés par l'objet Proc.

Plusieurs processus Proc peuvent être combinés en utilisant l'opérateur pipe (c'est-à-dire, l'opérateur |). Lorsqu'il est utilisé, le flux de sortie standard de l'objet Proc de gauche (lhs) est utilisé comme flux d'entrée standard de l'objet Proc de droite (rhs). Puisque les objets Proc démarrent leurs propres processus fils, cela se traduit effectivement par la sortie du processus fils du lhs étant utilisée comme entrée du processus fils du rhs. L'objet Proc le plus à gauche peut également lire son entrée (en utilisant l'opérateur pipe) à partir d'un objet istream ou d'un fichier dont le nom (chemin) est spécifié comme argument le plus à gauche d'une expression pipe. De même, l'objet Proc le plus à droite peut rediriger sa sortie standard vers un objet ostream existant ou vers un fichier dont le nom (chemin) est spécifié comme argument le plus à droite d'une expression pipe.

Les objets Proc utilisent des objets Pipe (cf. pipe(3bobcat)) pour la communication avec leurs processus fils. Pour s'assurer que ces pipes sont correctement fermés, les membres waitForChild, stop ou le manipulateur eoi doivent être utilisés. Une fois qu'un objet Proc cesse d'exister, les pipes vers son processus fils sont également fermés.

ÉNUMÉRATIONS

Les énumérations suivantes sont définies par la classe Proc :

enum ProcType :

L'énumération enum ProcType définit comment un processus fils est démarré ou localisé. Ses valeurs sont spécifiées au moment du constructeur ou via le membre setProcType. Cette énumération définit les constantes symboliques suivantes :

o
NO_PATH :
Le programme spécifié comme processus fils est démarré tel quel, sans rechercher les éléments de la variable d'environnement PATH.
o
USE_PATH :
Les éléments de la variable d'environnement PATH sont utilisés pour localiser le programme spécifié comme processus fils.
o
USE_SHELL :
Le programme spécifié comme processus fils est appelé en utilisant /bin/sh -c. Lorsque la redirection (de sortie) est utilisée avec la commande spécifiée, le mode IOMode IGNORE_COUT (et éventuellement aussi le mode IGNORE_CERR) doit être spécifié.

enum IOMode :

Les valeurs de l'énumération enum IOMode sont utilisées pour définir lesquels des flux standard du processus fils peuvent être accédés via l'objet Proc. Ses constantes symboliques peuvent être combinées en utilisant l'opérateur bit_or. Par défaut, CIN | COUT | CERR est utilisé (voir ci-dessous).

Les arguments IOMode peuvent être combinés avec des opérateurs bit_or.

Les constantes symboliques suivantes sont disponibles :

o
ALL :
Raccourci pour CIN | COUT | CERR.
o
CIN :
Les informations insérées dans l'objet Proc sont transmises à son processus fils. Si ce n'est pas requis, CIN ne devrait pas être spécifié.
o
CERR :
Les informations écrites par le processus fils sur son flux d'erreur standard sont rendues disponibles en tant que flux d'erreur standard de Proc. Si les informations écrites par le processus fils sur son flux d'erreur standard ne doivent pas être traitées par l'objet Proc, alors CERR ne devrait pas être spécifié.
o
COUT :
Les informations écrites par le processus fils sur son flux de sortie standard sont rendues disponibles en tant que flux de sortie standard de Proc. Si les informations écrites par le processus fils sur son flux de sortie standard ne doivent pas être traitées par l'objet Proc, alors COUT ne devrait pas être spécifié.
o
IGNORE_ALL :
Raccourci pour IGNORE_CIN | IGNORE_COUT | IGNORE_CERR.
o
IGNORE_CIN :
L'entrée standard du processus fils n'est pas mise à disposition. Si un processus fils n'a pas besoin d'entrées, mais que son processus parent doit quand même envoyer des informations, alors IGNORE_CIN peut être spécifié.
o
IGNORE_CERR :
L'erreur standard du processus fils n'est pas mise à disposition. Voir également la description de CERR.
o
IGNORE_COUT :
La sortie standard du processus fils n'est pas mise à disposition. Voir également la description de COUT.

MEMBRES SPÉCIFIQUES À PROC

Proc
Constructeur. Les arguments du constructeur définissent le chemin et le nom du programme à exécuter, l'éventuel objet IOMode, l'éventuel temps limite en secondes et le mode ProcType.
~Proc
Destructeur. Si le processus fils est toujours actif, il est terminé en lui envoyant un signal SIGTERM, suivi d'un signal SIGKILL.
eoi
Manipulateur d'E/S. Envoie un signal EOF au processus fils, puis attend la fin du processus fils.
finish
Attend que le processus fils se termine. Si le processus fils n'est pas terminé après le nombre de secondes spécifié, il est terminé en lui envoyant un signal SIGTERM, suivi d'un signal SIGKILL.
pipeSignal
Définit si les signaux Broken pipe doivent être ignorés.
setCommand
Permet de définir le programme à exécuter ainsi que ses arguments. Les valeurs spécifiées dans la spécification du programme sont séparées par des espaces. Les guillemets doubles ou simples peuvent être utilisés pour inclure des espaces ou des caractères spéciaux dans des arguments individuels. Si le processus fils est déjà actif, il est terminé avant que le nouveau programme ne soit exécuté.
setIOMode
Définit les modes d'E/S pour l'objet Proc.
setProcType
Définit le type de processus (voir ProcType ci-dessus).
setTimeout
Définit le temps limite (en secondes) imparti au processus fils pour s'achever.
start
Démarre le processus fils. Le processus fils est démarré comme spécifié par les arguments du constructeur ou par le membre setCommand.
stop
Termine le processus fils en lui envoyant d'abord un signal SIGTERM, puis un signal SIGKILL si le processus fils n'est pas terminé dans les 5 secondes suivantes.
waitForChild
Attend que le processus fils se termine.

Opérateur d'insertion. Les données spécifiées sont transmises au flux d'entrée standard du processus fils.

IOMODE

This section describes the IOMode options that can be used to control the way in which child processes communicate with their parent process.

o
ALL:
This is the default IOMode. It means that standard input, standard output and standard error are all available.
o
CIN:
Information written by the child process to its standard input stream is made available as Proc’s standard input stream. If this is not required then CIN should not be specified.
o
CERR:
Information written by the child process to its standard error stream is made available as Proc’s standard error stream. If this is not required then CERR should not be specified.
o
COUT:
Information written by the child process to its standard output stream is made available as Proc’s standard output stream. If this is not required then CERR should not be specified.
o
IGNORE_CERR:
Information written by the child proc to its standard error stream is ignored (i.e., not made available). An std::invalid_argument exception is thrown if this mode is specified in combination with CERR, MERGE_COUT_CERR, and/or REPLACE.
o
IGNORE_COUT:
Information written by the child proc to its standard output stream is ignored. An std::invalid_argument exception is thrown if this mode is specified in combination with COUT, MERGE_COUT_CERR and/or REPLACE.
o
IGNORE_COUT_CERR:
Shortcut for IGNORE_CERR | IGNORE_COUT.
o
MERGE_COUT_CERR:
Information written by the child process to its standard output and standard error streams is made available at the Proc object’s standard output stream. An std::invalid_argument exception is thrown if this mode is specified in combination with COUT, CERR, IGNORE_COUT, IGNORE_CERR or REPLACE.
o
NONE:
The Proc object does not insert information into the standard input streams of its child process and information written by the child process to its standard output or error streams is not forwarded to the Proc object. Instead, the child process processes its standard streams by itself. When this mode is specified in combination with other IOMode values it is silently ignored.
o
REPLACE:
When starting a child proc (see below at the member start) the current process (i.e., the program defining the Proc object) is replaced by the child process, inheriting the current process’s standard input and output streams. If this mode is specified in combination with any other IOMode (except for NONE, see below) an std::invalid_argument exception is thrown.

CONSTRUCTEUR

Notez que les processus enfants ne sont *pas* démarrés automatiquement suite à la construction des objets t(Proc). Un membre start ou l'opérateur d'affectation (voir ci-dessous) est utilisé pour démarrer les processus enfants.

Une fois qu'un objet Proc a été construit, ses paramètres peuvent être modifiés en utilisant les membres set ou les membres start.

o
explicit Proc(std::string const &command = "", IOMode mode = ALL, ProcType type = NO_PATH, size_t bufSize = 200, size_t timeLimit = 0, bool pipeSignal = true):
Le paramètre bufSize définit la taille des tampons streambuf utilisés par l'objet Proc. Le timeLimit spécifie le temps d'exécution maximum d'un processus enfant en secondes ; lorsque timeLimit == 0 aucune limite de temps d'exécution n'est utilisée. Lorsque pipeSignal == true un traitement incomplet des informations envoyées ou lues depuis le processus enfant entraîne une exception de type Broken pipe, terminant le programme. En spécifiant false, l'exception Broken pipe est supprimée, et les flux d'entrée et/ou de sortie n'ont pas besoin d'être complètement traités (voir aussi la description de pipeSignal).

Les constructeurs par copie et par déplacement (ainsi que les opérateurs d'affectation) ne sont pas disponibles.

OPÉRATEURS SURCHARGÉS

o
Proc &operator<<(Type value):
Cet opérateur insère value dans le flux d'entrée standard du processus enfant. C'est-à-dire, le processus enfant lit value depuis son entrée standard. Une valeur de n'importe quel type pouvant être inséré dans un ostream peut être insérée dans un objet Proc. Rien ne se passe si le membre est utilisé alors que le processus enfant a terminé. Les manipulateurs comme std::endl sont également supportés. Le comportement de cet opérateur est indéfini lorsque le mode IOMode CIN n'a pas été spécifié.
o
Proc &operator+=(std::string const &):
Cet opérateur ajoute l'objet std::string fourni à la spécification de commande actuellement définie pour un objet Proc. Le membre operator+= n'ajoute pas d'espace blanc séparateur entre la commande actuellement stockée et le texte à ajouter. Il ajoute simplement sa chaîne de caractères de droite à la commande stockée jusqu'à présent. Il n'affecte pas un processus enfant en cours d'exécution.
o
int operator=(std::string const &cmd):
Le membre operator= définit cmd comme la commande stockée dans un objet Proc, puis démarre `cmd` comme son processus enfant.
Avant de démarrer le processus enfant, un processus enfant potentiellement actif est d'abord arrêté en appelant stop. Il renvoie la valeur de retour de stop. Immédiatement après l'appel à stop, la nouvelle commande (cmd) est démarrée. Si terminer et redémarrer une autre commande doivent être des actions distinctes, utilisez finish ou stop suivi de setCommand, suivi de l'appel à une version surchargée appropriée du membre start.
o
Return operator|(Proc &lhs, Proc &rhs):
Cet opérateur implémente le piping. Les informations envoyées par lhs vers sa sortie standard sont utilisées comme entrée standard du processus enfant de rhs. La valeur Return est rhs si l'expression est suivie d'un autre opérateur de pipe, sinon elle est void.
o
Return operator|(std::istream &in, Proc &proc):
Cet opérateur implémente le piping. Les informations lues depuis in sont lues par le processus enfant de proc. La valeur Return est proc si l'expression est suivie d'un autre opérateur de pipe, sinon elle est void.
o
Return operator|(std::string const &fname, Proc &proc):
Cet opérateur implémente le piping. Les informations contenues dans le fichier dont le nom (chemin) est fname sont lues par le processus enfant de proc. La valeur Return est proc si l'expression est suivie d'un autre opérateur de pipe, sinon elle est void.
o
void operator|(Proc &proc, std::ostream &out):
Cet opérateur implémente le piping. Les informations envoyées par le processus enfant de proc vers son flux de sortie standard sont écrites dans out.
o
void operator|(Proc &proc, std::string &fname):
Cet opérateur implémente le piping. Les informations envoyées par le processus enfant de proc vers son flux de sortie standard sont écrites dans le fichier dont le nom (chemin) est fname.

L'opérateur pipe (|) imite l'opérateur pipe supporté par la plupart des programmes shells et ne doit pas être confondu avec l'opérateur bit à bit OU. L'opérateur pipe permet des constructions comme

    p1 | p2 | p3            // piping de 3 objets Proc
    cin | p1 | p2 | cout    // p1 lit cin, p2 écrit cout
    inName | p1 | outName   // inName : nom du fichier lu par p1
                            // outName : nom du fichier écrit par p1

Lors de l'utilisation de l'opérateur pipe, les objets Proc qui lisent une entrée spécifient automatiquement leurs modes CIN, tandis que les objets Proc qui écrivent leur sortie standard spécifient automatiquement leurs modes COUT. Suite à l'expression pipe, les spécifications IOMode qui étaient spécifiées avant l'expression pipe sont restaurées.

void pipeSignal(bool on) :
Lorsqu'on transmet des informations de manière incomplète à un processus fils ou qu'on lit des informations de manière incomplète d'un processus fils, un tube brisé (Broken pipe) peut en résulter, mettant fin au programme en cours d'exécution. Pour éviter cela, on peut appeler pipeSignal(false). Pour réactiver la reconnaissance des tubes brisés, on peut appeler pipeSignal(true). Après avoir utilisé pipeSignal(false), les insertions échouées dans un objet Proc entraîneront le retour de son membre good à false, et le retour de ses membres bad et fail à true.
o

Chaque objet Proc construit reçoit son propre indice d'ordre de construction. Le premier objet Proc construit dans un programme reçoit la valeur d'indice 0.

Le ProcType utilisé lors du démarrage des processus fils est retourné.
o

o

La partie (initiale) de la spécification de commande du processus fils est définie à cmd. Après avoir appelé ce membre, l'opérateur += peut être utilisé pour ajouter du texte supplémentaire à la spécification de commande.
o

void setTimeLimit(size_t timeLimit) :
La limite de temps d'exécution des processus fils est définie à timeLimit (en secondes). Aucune limite de temps n'est utilisée lorsque timeLimit 0 est spécifié. La limite de temps définie par setTimeLimit est utilisée lors du démarrage du prochain processus fils. Lors de l'appel de setTimeLimit, pipeSignal(timeLimit == 0) est automatiquement appelé. Si ce n'est pas l'intention, appelez explicitement pipeSignal après avoir appelé setTimeLimit.

La commande actuellement spécifiée est démarrée en utilisant les arguments timeLimit, IOMode, ProcType et bufSize spécifiés. Les membres start ne modifient pas les valeurs par défaut actuellement configurées de leurs arguments.
Si un processus fils est toujours actif lorsque start est appelé, il appelle d'abord stop pour terminer le processus fils en cours d'exécution.

La limite de temps d'exécution actuellement configurée du processus fils du Proc est retournée. Une valeur de retour de zéro indique qu'aucune limite de temps n'est utilisée.
o
void useErr(std::ostream &out) :
La sortie d'erreur standard produite par le processus fils est envoyée à out. Si l'objet Proc avait spécifié IGNORE_CERR, alors ce IOMode est désactivé, et le mode CERR est activé.
o
void useErr(std::string const &fname) :
Identique au membre précédent, mais la sortie d'erreur standard du fils est écrite dans le fichier (chemin) fname.
o
void useMerge(std::ostream &out) :
La sortie standard et la sortie d'erreur standard produites par le processus fils sont envoyées à out. Si l'objet Proc avait spécifié CERR, COUT, IGNORE_CERR, ou IGNORE_COUT, alors ces IOModes sont désactivés, et le mode MERGE_COUT_CERR est activé.
o
void useMerge(std::string const &fname) :
Identique au membre précédent, mais la sortie standard et la sortie d'erreur standard du fils sont écrites dans le fichier (chemin) fname.
o
void useOut(std::ostream &out) :
La sortie standard produite par le processus fils est envoyée à out. Si l'objet Proc avait spécifié IGNORE_COUT, alors ce IOMode est désactivé, et le mode COUT est activé.
o
void useOut(std::string const &fname) :
Identique au membre précédent, mais la sortie standard du fils est écrite dans le fichier (chemin) fname.
o
int waitForChild() :
Ce membre appelle le membre du même nom de la classe FBB::Fork, attendant qu'un processus fils se termine. Lors de l'appel de finish ou de l'utilisation d'expressions de tube, waitForChild est automatiquement appelé.

EXEMPLES

Tous les exemples devraient commencer par :

    #include <iostream>
    #include <bobcat/proc>
    using namespace std;
    using namespace FBB;

Le premier exemple illustre comment un programme qui produit uniquement de la sortie peut être appelé. Son processus fils est simplement /bin/ls :

int main()
{
    Proc proc("/bin/ls -Fla", Proc::COUT);
    proc.start();
}

L'exemple suivant illustre un programme fils auquel une quantité limitée de temps d'exécution est allouée : les lignes saisies au clavier sont renvoyées sur le flux de sortie standard pendant au plus 5 secondes :

int main()
{
    Proc proc("/bin/cat", Proc::CIN | Proc::COUT);
    proc.setTimeLimit(5);
    proc.start();
    while (true)
    {
        cout << "? ";
        string line;
        if (not getline(cin, line))
            return 0;
        proc << line << endl;           // vers /bin/cat
        if (not proc.good())
        {
            cout << "délai d'exécution du fils dépassé\n";
            break;
        }
    }
    cout << "délai de 5 secondes atteint pour /bin/cat : processus fils terminé\n";
}

Le passage en tube est illustré ensuite : les informations sur l'entrée standard du programme sont envoyées en tube à un deuxième objet Proc, dont la sortie standard est écrite sur le flux de sortie standard du programme :

int main()
{
    Proc proc1{ "/bin/cat" };
    Proc proc2{ "/bin/cat" };
    cin | proc1 | proc2;            // Par défaut, passage en tube vers cout. Pour ce faire
                                    // explicitement, utiliser ’... | proc2 | cout’
}
