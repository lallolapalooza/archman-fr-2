process_madvise(2) Manuel des appels système process_madvise(2)

NOM

process_madvise - donner des conseils sur l'utilisation de la mémoire à un processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/mman.h>
ssize_t process_madvise(size_t n;
                        int pidfd, const struct iovec iovec[n],
                        size_t n, int advice, unsigned int flags);

DESCRIPTION

L'appel système process_madvise() est utilisé pour donner des conseils ou des instructions au noyau concernant les plages d'adresses d'un autre processus ou du processus appelant. Il fournit les conseils pour les plages d'adresses décrites par iovec et n. Le but de ces conseils est d'améliorer les performances du système ou de l'application.

L'argument pidfd est un descripteur de fichier PID (voir pidfd_open(2)) qui spécifie le processus auquel les conseils doivent être appliqués.

Le pointeur iovec pointe vers un tableau de structures iovec, décrites dans iovec(3type).

n spécifie le nombre d'éléments dans le tableau de structures iovec. Cette valeur doit être inférieure ou égale à IOV_MAX (défini dans <limits.h> ou accessible via l'appel sysconf(_SC_IOV_MAX)).

Si vous manipulez un autre processus, ou avant Linux 6.13, l'argument advice est l'une des valeurs suivantes :

MADV_COLD
Voir madvise(2).
MADV_COLLAPSE
Voir madvise(2).
MADV_PAGEOUT
Voir madvise(2).
MADV_WILLNEED
Voir madvise(2).

Depuis Linux 6.13, lors de la manipulation du processus appelant, tout drapeau de conseil est autorisé.

L'argument flags est réservé pour une utilisation future ; actuellement, cet argument doit être spécifié comme 0.

Les arguments n et iovec sont vérifiés avant d'appliquer tout conseil. Si n est trop grand ou si iovec est invalide, une erreur sera retournée immédiatement et aucun conseil ne sera appliqué.

Les conseils peuvent être appliqués à seulement une partie de iovec si l'un de ses éléments pointe vers une région mémoire invalide dans le processus distant. Aucun élément supplémentaire ne sera traité au-delà de ce point. (Voir la discussion sur les conseils partiels dans VALEUR RENVOYÉE.)

Depuis Linux 5.12, la permission d'appliquer des conseils à un autre processus est régie par une vérification du mode d'accès ptrace PTRACE_MODE_READ_FSCREDS (voir ptrace(2)) ; de plus, en raison des implications de performance de l'application des conseils, l'appelant doit posséder la capacité CAP_SYS_NICE (voir capabilities(7)).

VALEUR RENVOYÉE

En cas de succès, process_madvise() renvoie le nombre d'octets pour lesquels des conseils ont été donnés. Cette valeur de retour peut être inférieure au nombre total d'octets demandés, si une erreur s'est produite après que certains éléments iovec aient déjà été traités. L'appelant doit vérifier la valeur de retour pour déterminer si un conseil partiel s'est produit.

En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
pidfd n'est pas un descripteur de fichier PID valide.
EFAULT
La mémoire décrite par iovec se trouve en dehors de l'espace d'adressage accessible du processus référencé par pidfd.
EINVAL
flags n'est pas 0.
EINVAL
La somme des valeurs iov_len de iovec dépasse la valeur d'un ssize_t.
EINVAL
n est trop grand.
ENOMEM
Impossible d'allouer de la mémoire pour les copies internes des structures iovec.
EPERM
L'appelant n'a pas la permission d'accéder à l'espace d'adressage du processus pidfd.
ESRCH
Le processus cible n'existe pas (c'est-à-dire qu'il s'est terminé et a été attendu).

Voir madvise(2) pour les erreurs spécifiques à advice.

NORMES

Linux.

HISTORIQUE

Linux 5.10. glibc 2.36.

Le support de cet appel système est optionnel, en fonction du paramètre de l'option de configuration CONFIG_ADVISE_SYSCALLS.

Lorsque cet appel système est apparu pour la première fois sous Linux 5.10, la permission d'appliquer des conseils à un autre processus était entièrement régie par la vérification du mode d'accès ptrace PTRACE_MODE_ATTACH_FSCREDS (voir ptrace(2)). Cette exigence a été assouplie dans Linux 5.12 afin que l'appelant n'ait pas besoin d'un contrôle total sur le processus cible.

VOIR AUSSI

madvise(2), pidfd_open(2), process_vm_readv(2), process_vm_write(2)
