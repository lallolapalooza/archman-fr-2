process_vm_readv(2) Manuel des appels système process_vm_readv(2)

NOM

process_vm_readv, process_vm_writev - transférer des données entre les espaces d'adressage de processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/uio.h>
ssize_t process_vm_readv(pid_t pid,
                       const struct iovec *local_iov,
                       unsigned long liovcnt,
                       const struct iovec *remote_iov,
                       unsigned long riovcnt,
                       unsigned long flags);
ssize_t process_vm_writev(pid_t pid,
                       const struct iovec *local_iov,
                       unsigned long liovcnt,
                       const struct iovec *remote_iov,
                       unsigned long riovcnt,
                       unsigned long flags);
Exigences pour les macros de test de fonctionnalité dans glibc (voir feature_test_macros(7)):

process_vm_readv(), process_vm_writev():

    _GNU_SOURCE

DESCRIPTION

Ces appels système transfèrent des données entre l'espace d'adressage du processus appelant (« le processus local ») et le processus identifié par pid (« le processus distant »). Les données transitent directement entre les espaces d'adressage des deux processus, sans passer par l'espace noyau.

L'appel système process_vm_readv() transfère des données du processus distant vers le processus local. Les données à transférer sont identifiées par remote_iov et riovcnt : remote_iov est un pointeur vers un tableau décrivant des plages d'adresses dans le processus pid, et riovcnt spécifie le nombre d'éléments dans remote_iov. Les données sont transférées vers les emplacements spécifiés par local_iov et liovcnt : local_iov est un pointeur vers un tableau décrivant des plages d'adresses dans le processus appelant, et liovcnt spécifie le nombre d'éléments dans local_iov.

L'appel système process_vm_writev() est l'inverse de process_vm_readv() : il transfère des données du processus local vers le processus distant. Outre la direction du transfert, les arguments liovcnt, local_iov, riovcnt et remote_iov ont la même signification que pour process_vm_readv().

Les arguments local_iov et remote_iov pointent vers un tableau de structures iovec, décrit dans iovec(3type).

Les tampons sont traités dans l'ordre du tableau. Cela signifie que process_vm_readv() remplit complètement local_iov[0] avant de passer à local_iov[1], et ainsi de suite. De même, remote_iov[0] est lu complètement avant de passer à remote_iov[1], et ainsi de suite.

De même, process_vm_writev() écrit le contenu entier de local_iov[0] avant de passer à local_iov[1], et il remplit complètement remote_iov[0] avant de passer à remote_iov[1].

Les longueurs de remote_iov[i].iov_len et local_iov[i].iov_len n'ont pas à être identiques. Il est donc possible de diviser un tampon local unique en plusieurs tampons distants, ou vice versa.

L'argument flags est actuellement inutilisé et doit être mis à 0.

Les valeurs spécifiées dans les arguments liovcnt et riovcnt doivent être inférieures ou égales à IOV_MAX (défini dans <limits.h> ou accessible via l'appel sysconf(_SC_IOV_MAX)).

Les arguments de compte et local_iov sont vérifiés avant tout transfert. Si les comptes sont trop grands, ou si local_iov est invalide, ou si les adresses font référence à des zones inaccessibles au processus local, aucun des vecteurs ne sera traité et une erreur sera retournée immédiatement.

Notez cependant que ces appels système ne vérifient les zones mémoire du processus distant qu'au moment de la lecture/écriture. Par conséquent, une lecture/écriture partielle (voir VALEUR RENVOYÉE) peut survenir si l'un des éléments remote_iov pointe vers une zone mémoire invalide dans le processus distant. Aucune lecture/écriture supplémentaire ne sera tentée au-delà de ce point. Gardez cela à l'esprit lorsque vous tentez de lire des données de longueur inconnue (comme des chaînes C terminées par un caractère nul) à partir d'un processus distant, en évitant de chevaucher des pages mémoire (typiquement 4 KiB) dans un seul élément iovec distant. (Au lieu de cela, divisez la lecture distante en deux éléments remote_iov et faites-les fusionner en une seule entrée d'écriture local_iov. La première entrée de lecture va jusqu'à la frontière de la page, tandis que la seconde commence à la frontière de page suivante.)

La permission de lire ou d'écrire dans un autre processus est régie par une vérification de mode d'accès ptrace PTRACE_MODE_ATTACH_REALCREDS ; voir ptrace(2).

VALEUR RENVOYÉE

En cas de succès, process_vm_readv() renvoie le nombre d'octets lus et process_vm_writev() renvoie le nombre d'octets écrits. Cette valeur de retour peut être inférieure au nombre total d'octets demandés, si une lecture/écriture partielle s'est produite. (Les transferts partiels s'appliquent à la granularité des éléments iovec. Ces appels système ne réaliseront pas de transfert partiel qui divise un seul élément iovec.) L'appelant doit vérifier la valeur de retour pour déterminer si une lecture/écriture partielle s'est produite.

En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
La mémoire décrite par local_iov se trouve en dehors de l'espace d'adressage accessible de l'appelant.
EFAULT
La mémoire décrite par remote_iov se trouve en dehors de l'espace d'adressage accessible du processus pid.
EINVAL
La somme des valeurs iov_len de local_iov ou de remote_iov dépasse la valeur d'un ssize_t.
EINVAL
flags n'est pas 0.
EINVAL
liovcnt ou riovcnt est trop grand.
ENOMEM
Impossible d'allouer de la mémoire pour des copies internes des structures iovec.
EPERM
L'appelant n'a pas la permission d'accéder à l'espace d'adressage du processus pid.
ESRCH
Aucun processus avec l'ID pid n'existe.

NORMES

Linux.

HISTORIQUE

Linux 3.2, glibc 2.15.

NOTES

Les transferts de données effectués par process_vm_readv() et process_vm_writev() ne sont garantis comme étant atomiques d'aucune manière.

Ces appels système ont été conçus pour permettre une communication rapide par messages en autorisant l'échange de messages avec une seule opération de copie (plutôt que la double copie qui serait requise en utilisant, par exemple, la mémoire partagée ou les pipes).

EXEMPLES

L'exemple de code suivant démontre l'utilisation de process_vm_readv(). Il lit 20 octets à l'adresse 0x10000 du processus avec le PID 10 et écrit les 10 premiers octets dans buf1 et les 10 octets suivants dans buf2.

#define _GNU_SOURCE
#include <stdlib.h>
#include <sys/types.h>
#include <sys/uio.h>
int
main(void)
{
    char          buf1[10];
    char          buf2[10];
    pid_t         pid = 10;    /* PID du processus distant */
    ssize_t       nread;
    struct iovec  local[2];
    struct iovec  remote[1];
    local[0].iov_base = buf1;

process_vm_readv(2) — man pages

NAME

process_vm_readv, process_vm_writev - scatter/gather I/O across a process's VM address space

LIBRARY

Linux C Library (glibc), since version 2.16

SYNOPSIS

#include <sys/uio.h>

ssize_t process_vm_readv(pid_t pid, const struct iovec *local_iov,
                           unsigned long liovcnt, const struct iovec *remote_iov,
                           unsigned long riovcnt, unsigned long flags);
ssize_t process_vm_writev(pid_t pid, const struct iovec *local_iov,
                            unsigned long liovcnt, const struct iovec *remote_iov,
                            unsigned long riovcnt, unsigned long flags);

DESCRIPTION

The process_vm_readv() and process_vm_writev() system calls perform scatter/gather I/O between the address space of the calling process and another process specified by pid. The operations are similar to readv(2) and writev(2), but instead of operating on buffers within the calling process, they operate on buffers within the memory space of the process indicated by pid.

The local_iov and remote_iov arguments are arrays of struct iovec. Each structure specifies a buffer and its size:

struct iovec {
    void  *iov_base;  /* Starting address of buffer */
    size_t iov_len;   /* Size of buffer in bytes */
};

liovcnt specifies the number of elements in the local_iov array, and riovcnt specifies the number of elements in the remote_iov array.

For process_vm_readv(), data is read from the memory space of the process specified by pid into the buffers specified by local_iov. The remote buffers are specified by remote_iov.

For process_vm_writev(), data is written from the buffers specified by local_iov into the memory space of the process specified by pid. The remote buffers are specified by remote_iov.

The flags argument is currently unused and must be set to 0.

The total number of bytes transferred is the sum of iov_len for all structures in the local_iov array and all structures in the remote_iov array. The system attempts to transfer exactly this many bytes. The transfer proceeds through the buffers in the order specified by the arrays. For process_vm_readv(), the transfer proceeds from remote_iov[0] to local_iov[0], then remote_iov[1] to local_iov[1], and so on. For process_vm_writev(), the transfer proceeds from local_iov[0] to remote_iov[0], then local_iov[1] to remote_iov[1], and so on.

The number of bytes actually transferred might be less than the total requested if an error occurs or if the target process encounters an exception (e.g., segmentation fault) while accessing its memory.

The target process is identified by its process ID (pid). The calling process must have appropriate privileges to access the address space of the target process. Typically, this means that the calling process must be run as root, or have the CAP_SYS_PTRACE capability.

RETURN VALUE

On success, process_vm_readv() and process_vm_writev() return the total number of bytes transferred. On failure, they return -1, and errno is set to indicate the error.

If the target process is debugged (e.g., using ptrace(2)), the return value might be less than the total requested bytes. In this case, the caller should check the value of errno. If errno is set to EIO, it means that the target process experienced a page fault or other signal that interrupted the memory access. The number of bytes successfully transferred up to that point is returned.

ERRORS

EAGAIN
Could not allocate sufficient memory for the operation.
EBADF
Either local_iov or remote_iov is not a valid pointer, or one of the iovec structures points to an invalid address.
EFAULT
An attempt was made to access an invalid user address in the local address space.
EINVAL
liovcnt or riovcnt is less than or equal to 0, or greater than the system limit. The sum of iov_len for all structures exceeds the system limit.
EIO
An I/O error occurred. This can happen if the target process generates a signal (e.g., SIGSEGV) while accessing memory.
ENOMEM
Could not allocate sufficient kernel memory for the operation.
ESRCH
The process specified by pid does not exist.
EPERM
The calling process does not have permission to access the address space of the target process.

STANDARDS

These system calls are specific to Linux and are available since kernel version 3.2.

HISTORY

process_vm_readv() and process_vm_writev() first appeared in Linux kernel 3.2.

NOTES

The behavior of these system calls is undefined if the target process exits or generates a signal during the operation. However, if the operation is interrupted by a signal, the system call may return prematurely with a short count and errno set to EIO.

The flags argument is reserved for future extensions and must be specified as 0.

EXAMPLES

The following example reads 20 bytes from the memory of process with PID pid into two local buffers, `buf1` and `buf2`, each of 10 bytes. The data is read from two remote buffers, each of 10 bytes, starting at address 0x10000.

    char buf1[10];
    char buf2[10];
    struct iovec local[2];
    struct iovec remote[1];
    ssize_t nread;
    pid_t pid;

    /* Assume pid is the PID of the target process */

    local[0].iov_base = buf1;
    local[0].iov_len = 10;
    local[1].iov_base = buf2;
    local[1].iov_len = 10;
    remote[0].iov_base = (void *) 0x10000;
    remote[0].iov_len = 20;
    nread = process_vm_readv(pid, local, 2, remote, 1, 0);
    if (nread != 20)
        exit(EXIT_FAILURE);
    exit(EXIT_SUCCESS);
