DESCRIPTION

Cette documentation s'adresse principalement aux auteurs de fournisseurs. Voir provider(7) pour plus d'informations.

L'opération de signature (OSSL_OP_SIGNATURE) permet aux fournisseurs d'implémenter des algorithmes de signature et de les rendre disponibles aux applications via les fonctions d'API EVP_PKEY_sign(3), EVP_PKEY_verify(3), et EVP_PKEY_verify_recover(3) (ainsi que d'autres fonctions connexes).

Toutes les "fonctions" mentionnées ici sont passées sous forme de pointeurs de fonction entre libcrypto et le fournisseur dans les tableaux OSSL_DISPATCH(3) via des tableaux OSSL_ALGORITHM(3) qui sont retournés par la fonction provider_query_operation() du fournisseur (voir "Fonctions du fournisseur" dans provider-base(7)).

Toutes ces "fonctions" ont une définition de type de fonction correspondante nommée OSSL_FUNC_{nom}_fn, et une fonction d'aide pour récupérer le pointeur de fonction à partir d'un élément OSSL_DISPATCH(3) nommé OSSL_FUNC_{nom}. Par exemple, la "fonction" OSSL_FUNC_signature_newctx() a ceci:

typedef void *(OSSL_FUNC_signature_newctx_fn)(void *provctx, const char *propq);
static ossl_inline OSSL_FUNC_signature_newctx_fn
    OSSL_FUNC_signature_newctx(const OSSL_DISPATCH *opf);

Les fonctions OSSL_FUNC_signature_set_ctx_params() et OSSL_FUNC_signature_settable_ctx_params() sont facultatives, mais si l'une d'elles est fournie, l'autre doit également l'être. Il en va de même pour les fonctions OSSL_FUNC_signature_get_ctx_params() et OSSL_FUNC_signature_gettable_ctx_params(), ainsi que pour les fonctions « md_params ».

La fonction OSSL_FUNC_signature_dupctx() est facultative. Elle n'est pas encore utilisée par OpenSSL.

La fonction OSSL_FUNC_signature_query_key_types() est facultative. Lorsqu'elle est présente, elle doit retourner un tableau de chaînes de caractères se terminant par NULL, indiquant les types de clés pris en charge par le fournisseur pour les opérations de signature. Sinon, le nom de l'algorithme de signature doit correspondre à la clé donnée ou au nom de l'algorithme de signature par défaut de la clé, tous deux vérifiés à l'aide de EVP_SIGNATURE_is_a(3).

Un algorithme de signature doit également implémenter un mécanisme pour générer, charger ou importer des clés via l'opération de gestion des clés (OSSL_OP_KEYMGMT). Voir provider-keymgmt(7) pour plus de détails.

Fonctions de gestion du contexte

OSSL_FUNC_signature_newctx() doit créer et retourner un pointeur vers une structure côté fournisseur pour contenir les informations de contexte pendant une opération de signature. Un pointeur vers ce contexte sera renvoyé dans plusieurs autres appels de fonctions d'opération de signature. Le paramètre provctx est le contexte du fournisseur généré lors de l'initialisation du fournisseur (voir provider(7)). Le paramètre propq est une chaîne de requête de propriétés qui peut être (facultativement) utilisée par le fournisseur lors de toute « récupération » qu'il pourrait effectuer (s'il en effectue).

OSSL_FUNC_signature_freectx() reçoit un pointeur vers le contexte de signature côté fournisseur dans le paramètre ctx. Cette fonction doit libérer toutes les ressources associées à ce contexte.

OSSL_FUNC_signature_dupctx() doit dupliquer le contexte de signature côté fournisseur dans le paramètre ctx et retourner la copie dupliquée.

Fonctions de signature

OSSL_FUNC_signature_sign_init() initialise un contexte pour la signature à l'aide d'un contexte de signature côté fournisseur dans le paramètre ctx, et d'un pointeur vers un objet clé fournisseur dans le paramètre provkey. Le paramètre params, s'il n'est pas NULL, doit être défini sur le contexte d'une manière similaire à l'utilisation de OSSL_FUNC_signature_set_ctx_params(). L'objet clé doit avoir été précédemment généré, chargé ou importé dans le fournisseur en utilisant l'opération de gestion des clés (OSSL_OP_KEYMGMT) (voir provider-keymgmt(7)).

OSSL_FUNC_signature_sign() effectue la signature elle-même. Un contexte de signature préalablement initialisé est passé dans le paramètre ctx. Les données à signer sont pointées par le paramètre tbs, qui est de tbslen octets. Sauf si sig est NULL, la signature doit être écrite à l'emplacement pointé par le paramètre sig et ne doit pas dépasser sigsize octets. La longueur de la signature doit être écrite dans *siglen. Si sig est NULL, la longueur maximale de la signature doit être écrite dans *siglen.

Fonctions de signature de message

Ces fonctions conviennent aux fournisseurs qui implémentent des algorithmes qui accumulent un message complet et signent le résultat de cette accumulation, tels que RSA-SHA256.

OSSL_FUNC_signature_sign_message_init() initialise un contexte pour signer un message à l'aide d'un contexte de signature côté fournisseur dans le paramètre ctx, et d'un pointeur vers un objet clé fournisseur dans le paramètre provkey. Le paramètre params, s'il n'est pas NULL, doit être défini sur le contexte d'une manière similaire à l'utilisation de OSSL_FUNC_signature_set_ctx_params(). L'objet clé doit avoir été préalablement généré, chargé ou importé dans le fournisseur en utilisant l'opération de gestion des clés (OSSL_OP_KEYMGMT) (voir provider-keymgmt(7)).

OSSL_FUNC_signature_sign_message_update() rassemble les données pointées par in, qui sont de inlen octets.

OSSL_FUNC_signature_sign_message_final() effectue la signature réelle sur les données qui ont été rassemblées avec OSSL_FUNC_signature_sign_message_update().

OSSL_FUNC_signature_sign() peut être utilisé pour des appels de signature en une seule passe. Dans ce cas, tbs est attendu comme étant le message complet à signer, long de tbslen octets.

Pour OSSL_FUNC_signature_sign_message_final() et OSSL_FUNC_signature_sign(), si sig n'est pas NULL, la signature doit être écrite à l'emplacement pointé par sig, et elle ne doit pas dépasser sigsize octets. La longueur de la signature doit être écrite dans *siglen. Si sig est NULL, la longueur maximale de la signature doit être écrite dans *siglen.

Fonctions de vérification

OSSL_FUNC_signature_verify_init() initialise un contexte pour vérifier une signature à l'aide d'un contexte de signature côté fournisseur dans le paramètre ctx, et d'un pointeur vers un objet clé fournisseur dans le paramètre provkey. Le paramètre params, s'il n'est pas NULL, doit être défini sur le contexte d'une manière similaire à l'utilisation de OSSL_FUNC_signature_set_ctx_params(). L'objet clé doit avoir été préalablement généré, chargé ou importé dans le fournisseur en utilisant l'opération de gestion des clés (OSSL_OP_KEYMGMT) (voir provider-keymgmt(7)).

OSSL_FUNC_signature_verify() effectue la vérification elle-même. Un contexte de signature préalablement initialisé est passé dans le paramètre ctx. Les données couvertes par la signature sont pointées par le paramètre tbs, qui est de tbslen octets. La signature est pointée par le paramètre sig, qui est de siglen octets.

Fonctions de vérification de message

Ces fonctions conviennent aux fournisseurs qui implémentent des algorithmes qui accumulent un message complet et vérifient une signature sur le résultat de cette accumulation, tels que RSA-SHA256.

OSSL_FUNC_signature_verify_message_init() initialise un contexte pour vérifier une signature sur un message à l'aide d'un contexte de signature côté fournisseur dans le paramètre ctx, et d'un pointeur vers un objet clé fournisseur dans le paramètre provkey. Le paramètre params, s'il n'est pas NULL, doit être défini sur le contexte d'une manière similaire à l'utilisation de OSSL_FUNC_signature_set_ctx_params(). L'objet clé doit avoir été préalablement généré, chargé ou importé dans le fournisseur en utilisant l'opération de gestion des clés (OSSL_OP_KEYMGMT) (voir provider-keymgmt(7)).

OSSL_FUNC_signature_verify_message_update() rassemble les données pointées par in, qui sont de inlen octets.

OSSL_FUNC_signature_verify_message_final() effectue la vérification réelle sur les données qui ont été rassemblées avec OSSL_FUNC_signature_verify_message_update(). La signature elle-même doit avoir été passée via le paramètre de signature « signature » (OSSL_SIGNATURE_PARAM_SIGNATURE) avant que cette fonction ne soit appelée.

OSSL_FUNC_signature_verify() peut être utilisé pour des appels de vérification en une seule passe. Dans ce cas, tbs est attendu comme étant le message complet à vérifier, long de tbslen octets.

OSSL_FUNC_signature_verify_recover() effectue la récupération de la signature elle-même. Un contexte de signature préalablement initialisé est passé dans le paramètre ctx. Fonctions de signature de digest

OSSL_FUNC_signature_digest_sign_init() initialise un contexte pour la signature en utilisant un contexte de signature côté fournisseur dans le paramètre ctx, et un pointeur vers un objet clé du fournisseur dans le paramètre provkey. Les params, s'ils ne sont pas NULL, doivent être définis sur le contexte d'une manière similaire à l'utilisation de OSSL_FUNC_signature_set_ctx_params() et OSSL_FUNC_signature_set_ctx_md_params(). L'objet clé doit avoir été généré, chargé ou importé précédemment dans le fournisseur en utilisant l'opération de gestion de clés (OSSL_OP_KEYMGMT) (voir provider-keymgmt(7)). Le nom du digest à utiliser sera dans le paramètre mdname.

OSSL_FUNC_signature_digest_sign_update() fournit les données à signer dans le paramètre data qui doit avoir une longueur de datalen. Un contexte de signature préalablement initialisé est passé dans le paramètre ctx. Cette fonction peut être appelée plusieurs fois pour ajouter cumulativement des données à signer.

OSSL_FUNC_signature_digest_sign_final() finalise une opération de signature précédemment commencée par des appels à OSSL_FUNC_signature_digest_sign_init() et OSSL_FUNC_signature_digest_sign_update(). Une fois finalisée, aucune autre donnée ne sera ajoutée par OSSL_FUNC_signature_digest_sign_update(). Un contexte de signature préalablement initialisé est passé dans le paramètre ctx. À moins que sig ne soit NULL, la signature doit être écrite à l'emplacement pointé par le paramètre sig et ne doit pas dépasser sigsize octets en longueur. La longueur de la signature doit être écrite dans *siglen. Si sig est NULL, alors la longueur maximale de la signature doit être écrite dans *siglen.

OSSL_FUNC_signature_digest_sign() implémente une opération de signature de digest en "un coup" précédemment commencée par OSSL_FUNC_signature_digest_sign_init(). Un contexte de signature préalablement initialisé est passé dans le paramètre ctx. Les données à signer se trouvent dans tbs qui doit faire tbslen octets de long. À moins que sig ne soit NULL, la signature doit être écrite à l'emplacement pointé par le paramètre sig et ne doit pas dépasser sigsize octets en longueur. La longueur de la signature doit être écrite dans *siglen. Si sig est NULL, alors la longueur maximale de la signature doit être écrite dans *siglen.

Paramètres de signature

Voir OSSL_PARAM(3) pour plus de détails sur la structure des paramètres utilisée par les fonctions OSSL_FUNC_signature_get_ctx_params() et OSSL_FUNC_signature_set_ctx_params().

OSSL_FUNC_signature_get_ctx_params() récupère les paramètres de signature associés au contexte de signature côté fournisseur donné ctx et les stocke dans params. Passer NULL pour params devrait retourner vrai.

OSSL_FUNC_signature_set_ctx_params() définit les paramètres de signature associés au contexte de signature côté fournisseur donné ctx à params. Tout réglage de paramètre est supplémentaire à ceux qui ont été précédemment définis. Passer NULL pour params devrait retourner vrai.

Les paramètres courants actuellement reconnus par les algorithmes de signature intégrés sont les suivants.

"digest" (OSSL_SIGNATURE_PARAM_DIGEST) <chaîne UTF8>
Obtient ou définit le nom de l'algorithme de digest utilisé pour l'entrée des fonctions de signature. Il est requis pour calculer l'"identifiant d'algorithme".
"properties" (OSSL_SIGNATURE_PARAM_PROPERTIES) <chaîne UTF8>
Définit le nom de la requête de propriétés associée à l'algorithme "digest". NULL est utilisé si cette valeur facultative n'est pas définie.

Notez que lors de l'implémentation d'un algorithme de signature qui rassemble un message complet, comme RSA-SHA256, les paramètres "digest" et "properties" ne doivent pas être utilisés. Pour de telles implémentations, il est acceptable de les ignorer s'ils sont passés dans un appel à OSSL_FUNC_signature_set_ctx_params(). Pour de telles implémentations, cependant, il n'est pas acceptable de les avoir dans le tableau OSSL_PARAM renvoyé par OSSL_FUNC_signature_settable_ctx_params().

"signature" (OSSL_SIGNATURE_PARAM_SIGNATURE) <chaîne d'octets>
Définit la signature à vérifier, spécifiquement lorsque OSSL_FUNC_signature_verify_message_final() est utilisé.
"digest-size" (OSSL_SIGNATURE_PARAM_DIGEST_SIZE) <entier non signé>
Obtient ou définit la taille de sortie de l'algorithme de digest utilisé pour l'entrée des fonctions de signature. La longueur du paramètre "digest-size" ne doit pas dépasser celle d'un size_t.
"algorithm-id" (OSSL_SIGNATURE_PARAM_ALGORITHM_ID) <chaîne d'octets>
Obtient l'identifiant d'algorithme encodé en DER pour l'opération de signature. Cela correspond généralement à la combinaison d'un algorithme de digest avec un algorithme de signature purement asymétrique, tel que SHA256WithECDSA.

La fonction ASN1_item_sign_ctx(3) dépend de cette opération et est utilisée par de nombreuses autres fonctions qui signent des structures ASN.1 telles que les certificats X.509, les demandes de certificats et les CRL, ainsi que les messages OCSP, CMP et CMS.

"nonce-type" (OSSL_SIGNATURE_PARAM_NONCE_TYPE) <entier non signé>
Définissez ceci à 1 pour utiliser la génération de signature numérique déterministe avec ECDSA ou DSA, telle que définie dans la RFC 6979 (voir la section 3.2 "Generation of k"). Dans ce cas, le paramètre "digest" doit être explicitement défini (sinon, la génération de nonce déterministe échouera). Avant d'utiliser la génération de signature numérique déterministe, veuillez lire la RFC 6979 Section 4 "Security Considerations". La valeur par défaut pour "nonce-type" est 0 et résulte en l'utilisation d'une valeur aléatoire pour le nonce k tel que défini dans la norme FIPS 186-4 Section 6.3 "Secret Number Generation".

Le fournisseur FIPS prend en charge la génération de signature numérique déterministe pour ECDSA.

NAME

provider-signature — Provider signature functions

SYNOPSIS

#include <openssl/core_dispatch.h>
#include <openssl/params.h>

typedef void *(*OSSL_FUNC_signature_newctx)(void *provctx);
typedef void (*OSSL_FUNC_signature_freectx)(void *ctx);
typedef void *(*OSSL_FUNC_signature_dupctx)(void *ctx);
typedef int (*OSSL_FUNC_signature_sign)(void *ctx, unsigned char *sig,
                                     size_t *siglen, const unsigned char *tbs,
                                     size_t tbslen);
typedef int (*OSSL_FUNC_signature_verify)(void *ctx, const unsigned char *sig,
                                       size_t siglen, const unsigned char *tbs,
                                       size_t tbslen);
typedef int (*OSSL_FUNC_signature_verify_recover)(void *ctx, unsigned char *rout,
                                              size_t *routlen,
                                              const unsigned char *sig,
                                              size_t siglen);
typedef int (*OSSL_FUNC_signature_digest_sign)(void *ctx, unsigned char *sig,
                                             size_t *siglen,
                                             const unsigned char *data,
                                             size_t datalen);
typedef int (*OSSL_FUNC_signature_digest_verify)(void *ctx,
                                               const unsigned char *sig,
                                               size_t siglen,
                                               const unsigned char *data,
                                               size_t datalen);
typedef int (*OSSL_FUNC_signature_get_ctx_params)(void *ctx,
                                                OSSL_PARAM params[]);
typedef int (*OSSL_FUNC_signature_get_ctx_params)(void *ctx,
                                                OSSL_PARAM params[]);
typedef int (*OSSL_FUNC_signature_gettable_ctx_params)(OSSL_PARAM params[]);
typedef int (*OSSL_FUNC_signature_settable_ctx_params)(OSSL_PARAM params[]);
typedef int (*OSSL_FUNC_signature_get_md_ctx_params)(void *ctx,
                                                   OSSL_PARAM params[]);
typedef int (*OSSL_FUNC_signature_set_md_ctx_params)(void *ctx,
                                                   OSSL_PARAM params[]);
typedef int (*OSSL_FUNC_signature_gettable_md_ctx_params)(OSSL_PARAM params[]);
typedef int (*OSSL_FUNC_signature_settable_md_ctx_params)(OSSL_PARAM params[]);
typedef int (*OSSL_FUNC_signature_query_key_types)(const char **keytypes);

DESCRIPTION

Providers can implement signature algorithms. These functions are part of the provider signature interface.

Core Functions

OSSL_FUNC_signature_newctx()
Creates a new signature context. This context is provider-specific and is used to hold state for the signature algorithm.
OSSL_FUNC_signature_freectx()
Frees a signature context created by OSSL_FUNC_signature_newctx().
OSSL_FUNC_signature_dupctx()
Duplicates a signature context. This can be used to potentially speed up operations where the same context is used multiple times.
OSSL_FUNC_signature_sign()
Signs the digest of the data (the digest is expected to have been computed already).
OSSL_FUNC_signature_verify()
Verifies the signature against the digest of the data.
OSSL_FUNC_signature_verify_recover()
Recovers the original data from the signature.
OSSL_FUNC_signature_digest_sign()
Signs the given data. The digest is computed internally.
OSSL_FUNC_signature_digest_verify()
Verifies the signature against the given data. The digest is computed internally.

Context Parameters

The following functions allow getting and setting of parameters associated with the signature context.

OSSL_FUNC_signature_get_ctx_params()
Gets parameters associated with the given provider side signature context ctx and stores them in params.
OSSL_FUNC_signature_set_ctx_params()
Sets the parameters associated with the given provider side signature context ctx to params.
OSSL_FUNC_signature_gettable_ctx_params()
Returns an array of parameters that can be retrieved from the context. See OSSL_PARAM(3).
OSSL_FUNC_signature_settable_ctx_params()
Returns an array of parameters that can be set in the context. See OSSL_PARAM(3).

The following parameters are currently supported by the signature algorithm:

"fips-indicator" (OSSL_SIGNATURE_PARAM_FIPS_INDICATOR) <integer>
This is a read-only parameter. It indicates whether the signature algorithm and its parameters are FIPS approved. A value of 1 means approved, and 0 means not approved.
"key-check" (OSSL_SIGNATURE_PARAM_FIPS_KEY_CHECK) <integer>
If required this parameter should be set before the key is set (e.g. via OSSL_FUNC_signature_sign_init() or OSSL_FUNC_signature_verify_init()). The default value of 1 causes an error during the init if the key is not FIPS approved (e.g. The key has a security strength of less than 112 bits). Setting this to 0 will ignore the error and set the approved "indicator" to 0. This option breaks FIPS compliance if it causes the approved "fips-indicator" to return 0.
"digest-check" (OSSL_SIGNATURE_PARAM_FIPS_DIGEST_CHECK) <integer>
If required this parameter should be set before the signature digest is set. The default value of 1 causes an error when the digest is set if the digest is not FIPS approved (e.g. SHA1 is used for signing). Setting this to 0 will ignore the error and set the approved "fips-indicator" to 0. This option breaks FIPS compliance if it causes the approved "fips-indicator" to return 0.
"sign-check" (OSSL_SIGNATURE_PARAM_FIPS_SIGN_CHECK) <integer>
If required this parameter should be set early via an init function. The default value of 1 causes an error when a signing algorithm is used. (This is triggered by deprecated signing algorithms). Setting this to 0 will ignore the error and set the approved "fips-indicator" to 0. This option breaks FIPS compliance if it causes the approved "fips-indicator" to return 0.
"sign-x931-pad-check" (OSSL_SIGNATURE_PARAM_FIPS_SIGN_X931_PAD_CHECK) <integer>
If required this parameter should be set before the padding mode is set. The default value of 1 causes an error if the padding mode is set to X9.31 padding for a RSA signing operation. Setting this to 0 will ignore the error and set the approved "fips-indicator" to 0. This option breaks FIPS compliance if it causes the approved "fips-indicator" to return 0.

OSSL_FUNC_signature_gettable_ctx_params() and OSSL_FUNC_signature_settable_ctx_params() get a constant OSSL_PARAM(3) array that describes the gettable and settable parameters, i.e. parameters that can be used with OSSL_FUNC_signature_get_ctx_params() and OSSL_FUNC_signature_set_ctx_params() respectively.

MD parameters

See OSSL_PARAM(3) for further details on the parameters structure used by the OSSL_FUNC_signature_get_md_ctx_params() and OSSL_FUNC_signature_set_md_ctx_params() functions.

OSSL_FUNC_signature_get_md_ctx_params() gets digest parameters associated with the given provider side digest signature context ctx and stores them in params. Passing NULL for params should return true.

OSSL_FUNC_signature_set_ms_ctx_params() sets the digest parameters associated with the given provider side digest signature context ctx to params. Any parameter settings are additional to any that were previously set. Passing NULL for params should return true.

Parameters currently recognised by built-in signature algorithms are the same as those for built-in digest algorithms. See "Digest Parameters" in provider-digest(7) for further information.

OSSL_FUNC_signature_gettable_md_ctx_params() and OSSL_FUNC_signature_settable_md_ctx_params() get a constant OSSL_PARAM(3) array that describes the gettable and settable digest parameters, i.e. parameters that can be used with OSSL_FUNC_signature_get_md_ctx_params() and OSSL_FUNC_signature_set_md_ctx_params() respectively.

RETURN VALUES

OSSL_FUNC_signature_newctx() and OSSL_FUNC_signature_dupctx() should return the newly created provider side signature context, or NULL on failure.

OSSL_FUNC_signature_gettable_ctx_params(), OSSL_FUNC_signature_settable_ctx_params(), OSSL_FUNC_signature_gettable_md_ctx_params() and OSSL_FUNC_signature_settable_md_ctx_params(), return the gettable or settable parameters in a constant OSSL_PARAM(3) array.

OSSL_FUNC_signature_query_key_types() should return a NULL-terminated array of strings.

All verification functions should return 1 for success, 0 for a non-matching signature, and a negative value for operation failure.

All other functions should return 1 for success and 0 or a negative value for failure.

HISTORY

The provider SIGNATURE interface was introduced in OpenSSL 3.0.

The Signature Parameters "fips-indicator", "key-check" and "digest-check" were added in OpenSSL 3.4.

Deterministic digital signature generation for ECDSA was added to the FIPS provider in OpenSSL 3.6.
