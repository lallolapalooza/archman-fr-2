NOM

provider-kem - Fonctions de bibliothèque KEM <-> fournisseur

SYNTAXE

#include <openssl/core_dispatch.h>
#include <openssl/core_names.h>
/*
 * Aucune de ces fonctions n'est une fonction réelle, mais elles sont affichées
 * comme ceci pour les signatures de fonctions qui sont proposées comme pointeurs
 * de fonction dans les tableaux OSSL_DISPATCH.
 */
/* Gestion du contexte */
void *OSSL_FUNC_kem_newctx(void *provctx);
void OSSL_FUNC_kem_freectx(void *ctx);
void *OSSL_FUNC_kem_dupctx(void *ctx);
/* Encapsulation */
int OSSL_FUNC_kem_encapsulate_init(void *ctx, void *provkey,
                                   const OSSL_PARAM params[]);
int OSSL_FUNC_kem_auth_encapsulate_init(void *ctx, void *provkey,
                                        void *provauthkey,
                                        const OSSL_PARAM params[]);
int OSSL_FUNC_kem_encapsulate(void *ctx, unsigned char *out, size_t *outlen,
                              unsigned char *secret, size_t *secretlen);
/* Décapsulation */
int OSSL_FUNC_kem_decapsulate_init(void *ctx, void *provkey);
int OSSL_FUNC_kem_auth_decapsulate_init(void *ctx, void *provkey,
                                        void *provauthkey,
                                        const OSSL_PARAM params[]);
int OSSL_FUNC_kem_decapsulate(void *ctx, unsigned char *out, size_t *outlen,
                              const unsigned char *in, size_t inlen);
/* Paramètres KEM */
int OSSL_FUNC_kem_get_ctx_params(void *ctx, OSSL_PARAM params[]);
const OSSL_PARAM *OSSL_FUNC_kem_gettable_ctx_params(void *ctx, void *provctx);
int OSSL_FUNC_kem_set_ctx_params(void *ctx, const OSSL_PARAM params[]);
const OSSL_PARAM *OSSL_FUNC_kem_settable_ctx_params(void *ctx, void *provctx);

DESCRIPTION

Cette documentation s'adresse principalement aux auteurs de fournisseurs. Voir provider(7) pour plus d'informations.

L'opération KEM asymétrique (OSSL_OP_KEM) permet aux fournisseurs d'implémenter des algorithmes KEM asymétriques et de les rendre disponibles aux applications via les fonctions API EVP_PKEY_encapsulate(3), EVP_PKEY_decapsulate(3) et autres fonctions associées.

Toutes les "fonctions" mentionnées ici sont passées sous forme de pointeurs de fonction entre libcrypto et le fournisseur dans des tableaux OSSL_DISPATCH(3) via des tableaux OSSL_ALGORITHM(3) qui sont retournés par la fonction provider_query_operation() du fournisseur (voir "Fonctions du fournisseur" dans provider-base(7)).

Toutes ces "fonctions" ont un type de fonction correspondant nommé OSSL_FUNC_{name}_fn, et une fonction d'aide pour récupérer le pointeur de fonction à partir d'un élément OSSL_DISPATCH(3) nommé OSSL_FUNC_{name}. Par exemple, la "fonction" OSSL_FUNC_kem_newctx() a ceci :

typedef void *(OSSL_FUNC_kem_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_kem_newctx_fn
    OSSL_FUNC_kem_newctx(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) les tableaux sont indexés par des nombres qui sont fournis sous forme de macros dans openssl-core_dispatch.h(7), comme suit :

OSSL_FUNC_kem_newctx                OSSL_FUNC_KEM_NEWCTX
OSSL_FUNC_kem_freectx               OSSL_FUNC_KEM_FREECTX
OSSL_FUNC_kem_dupctx                OSSL_FUNC_KEM_DUPCTX
OSSL_FUNC_kem_encapsulate_init      OSSL_FUNC_KEM_ENCAPSULATE_INIT
OSSL_FUNC_kem_auth_encapsulate_init OSSL_FUNC_KEM_AUTH_ENCAPSULATE_INIT
OSSL_FUNC_kem_encapsulate           OSSL_FUNC_KEM_ENCAPSULATE
OSSL_FUNC_kem_decapsulate_init      OSSL_FUNC_KEM_DECAPSULATE_INIT
OSSL_FUNC_kem_auth_decapsulate_init OSSL_FUNC_KEM_AUTH_DECAPSULATE_INIT
OSSL_FUNC_kem_decapsulate           OSSL_FUNC_KEM_DECAPSULATE
OSSL_FUNC_kem_get_ctx_params        OSSL_FUNC_KEM_GET_CTX_PARAMS
OSSL_FUNC_kem_gettable_ctx_params   OSSL_FUNC_KEM_GETTABLE_CTX_PARAMS
OSSL_FUNC_kem_set_ctx_params        OSSL_FUNC_KEM_SET_CTX_PARAMS
OSSL_FUNC_kem_settable_ctx_params   OSSL_FUNC_KEM_SETTABLE_CTX_PARAMS

Une implémentation d'algorithme KEM asymétrique peut ne pas implémenter toutes ces fonctions. Pour former un ensemble cohérent de fonctions, un fournisseur doit implémenter OSSL_FUNC_kem_newctx et OSSL_FUNC_kem_freectx. Il doit également implémenter soit OSSL_FUNC_kem_encapsulate_init et OSSL_FUNC_kem_encapsulate, soit OSSL_FUNC_kem_decapsulate_init et OSSL_FUNC_kem_decapsulate. OSSL_FUNC_kem_auth_encapsulate_init est facultatif mais s'il est présent, OSSL_FUNC_kem_auth_decapsulate_init doit l'être aussi. OSSL_FUNC_kem_get_ctx_params est facultatif mais s'il est présent, OSSL_FUNC_kem_gettable_ctx_params doit l'être aussi. De même, OSSL_FUNC_kem_set_ctx_params est facultatif mais s'il est présent, OSSL_FUNC_kem_settable_ctx_params doit également être présent.

Un algorithme KEM asymétrique doit également implémenter un mécanisme pour générer, charger ou importer des clés via l'opération de gestion de clés (OSSL_OP_KEYMGMT). Voir provider-keymgmt(7) pour plus de détails.

Fonctions de gestion du contexte

OSSL_FUNC_kem_newctx() doit créer et retourner un pointeur vers une structure côté fournisseur pour contenir les informations de contexte pendant une opération KEM asymétrique. Un pointeur vers ce contexte sera renvoyé dans un certain nombre d'autres appels de fonction KEM asymétriques. Le paramètre provctx est le contexte du fournisseur généré lors de l'initialisation du fournisseur (voir provider(7)).

OSSL_FUNC_kem_freectx() reçoit un pointeur vers le contexte KEM asymétrique côté fournisseur dans le paramètre ctx. Cette fonction doit libérer toutes les ressources associées à ce contexte.

OSSL_FUNC_kem_dupctx() doit dupliquer le contexte KEM asymétrique côté fournisseur dans le paramètre ctx et retourner la copie dupliquée.

Fonctions d'encapsulation de clés asymétriques

OSSL_FUNC_kem_encapsulate_init() initialise un contexte pour une encapsulation asymétrique étant donné un contexte KEM asymétrique côté fournisseur dans le paramètre ctx, un pointeur vers un objet clé du fournisseur dans le paramètre provkey et le nom de l'algorithme. Les params, s'ils ne sont pas NULL, doivent être définis sur le contexte d'une manière similaire à l'utilisation de OSSL_FUNC_kem_set_ctx_params(). L'objet clé doit avoir été précédemment généré, chargé ou importé dans le fournisseur en utilisant l'opération de gestion de clés (OSSL_OP_KEYMGMT) (voir provider-keymgmt(7)>.

OSSL_FUNC_kem_auth_encapsulate_init() est similaire à OSSL_FUNC_kem_encapsulate_init(), mais transmet également une clé d'authentification supplémentaire provauthkey qui ne peut pas être NULL.

OSSL_FUNC_kem_encapsulate() effectue l'encapsulation réelle. Un contexte KEM asymétrique précédemment initialisé est passé dans le paramètre ctx. Sauf si out est NULL, les données à encapsuler sont générées en interne et retournées dans le tampon pointé par le paramètre secret, et les données encapsulées doivent également être écrites à l'emplacement pointé par le paramètre out. La longueur des données encapsulées doit être écrite dans *outlen et la longueur du secret généré doit être écrite dans *secretlen.

Si out est NULL, alors la longueur maximale des données encapsulées doit être écrite dans *outlen, et la longueur maximale du secret généré doit être écrite dans *secretlen.

Fonctions de décapsulation

OSSL_FUNC_kem_decapsulate_init() initialise un contexte pour une décapsulation asymétrique étant donné un contexte KEM asymétrique côté fournisseur dans le paramètre ctx, un pointeur vers un objet clé du fournisseur dans le paramètre provkey, et un nom de l'algorithme. provider-kem - Provider Asymmetric Key Encapsulation (KEM) interface

DESCRIPTION

This manual page describes the Asymmetric Key Encapsulation (KEM) interface for OpenSSL providers.

The KEM interface is the provider-side interface for performing asymmetric key encapsulation operations.

The general structure of an OpenSSL provider is described in provider(7).

The provider must implement the functions listed in the SYNOPSIS section if it wishes to offer KEM capabilities.

The OpenSSL library uses these functions through the EVP_KEM(3) functions.

Asymmetric Key Encapsulation Functions

OSSL_FUNC_kem_newctx
This function is called by the library to create a new KEM context. The prov parameter is the provider itself. The libctx parameter is the library context. The name parameter is the name of the KEM algorithm being requested (e.g. "ecdh", "rsa-oaep").
OSSL_FUNC_kem_freectx
This function is called by the library to free a KEM context created by OSSL_FUNC_kem_newctx.
OSSL_FUNC_kem_flushctx
This function is called by the library to flush sensitive information from a KEM context. The action parameter specifies what action to take. See EVP_CIPHER_CTX_flush(3) for details.
OSSL_FUNC_kem_dupctx
This function is called by the library to duplicate a KEM context. The tctx parameter is the new context to be created, and sctx is the context to be duplicated.
OSSL_FUNC_kem_encapsulate_init
Initialises the KEM context ctx for encapsulation. The key parameter is the public key to use for encapsulation. The keylen parameter is the length of the public key. The params parameter is an optional array of parameters. If key is NULL, then any provided parameters are used to configure the context for encapsulation without a specific key.
OSSL_FUNC_kem_encapsulate
Encapsulates a shared secret using the KEM context ctx. The encapsulated data should be written to the location pointed to by the out parameter. The length of the encapsulated data should be written to *outlen. The shared secret should be written to the location pointed to by the secret parameter. The length of the shared secret should be written to *secretlen. If out is NULL then the maximum length of the encapsulated data should be written to *outlen. If secret is NULL then the maximum length of the shared secret should be written to *secretlen.
OSSL_FUNC_kem_decapsulate_init
Initialises the KEM context ctx for decapsulation. The key parameter is the private key to use for decapsulation. The keylen parameter is the length of the private key. The params parameter is an optional array of parameters. If key is NULL, then any provided parameters are used to configure the context for decapsulation without a specific key.
OSSL_FUNC_kem_decapsulate
Decapsulates a shared secret using the KEM context ctx. The decapsulated data should be written to the location pointed to by the secret parameter. The length of the decapsulated data should be written to *secretlen. The encapsulated data is read from the location pointed to by the in parameter, and its length is specified by inlen. If secret is NULL then the maximum length of the decapsulated data should be written to *secretlen.
OSSL_FUNC_kem_get_ctx_params
Retrieves the KEM parameters associated with the context ctx. The parameters are returned in the params array.
OSSL_FUNC_kem_set_ctx_params
Sets the KEM parameters associated with the context ctx. The parameters are provided in the params array.
OSSL_FUNC_kem_gettable_ctx_params
Returns an array of OSSL_PARAM(3) describing which parameters can be retrieved from the KEM context.
OSSL_FUNC_kem_settable_ctx_params
Returns an array of OSSL_PARAM(3) describing which parameters can be set for the KEM context.
OSSL_FUNC_kem_query_operationname
Queries the operation name associated with the KEM context ctx. The operation name is written to the location pointed to by opname.

Asymmetric Key Encapsulation Parameters

See OSSL_PARAM(3) for further details on the parameters structure used by the OSSL_FUNC_kem_get_ctx_params() and OSSL_FUNC_kem_set_ctx_params() functions.

The OpenSSL FIPS provider also supports the following parameters:

"fips-indicator" (OSSL_KEM_PARAM_FIPS_APPROVED_INDICATOR) <integer>
A getter that returns 1 if the operation is FIPS approved, or 0 otherwise. This may be used after calling either OSSL_FUNC_kem_encapsulate() or OSSL_FUNC_kem_decapsulate(). It may return 0 if the "key-check" is set to 0.
"key-check" (OSSL_KEM_PARAM_FIPS_KEY_CHECK) <integer>
If required this parameter should be set using OSSL_FUNC_kem_encapsulate_init() or OSSL_FUNC_kem_decapsulate_init(). The default value of 1 causes an error during the init if the key is not FIPS approved (e.g. The key has a security strength of less than 112 bits). Setting this to 0 will ignore the error and set the approved "fips-indicator" to 0. This option breaks FIPS compliance if it causes the approved "fips-indicator" to return 0.

Asymmetric Key Encapsulation Parameter Functions

OSSL_FUNC_kem_get_ctx_params() gets asymmetric KEM parameters associated with the given provider side asymmetric kem context ctx and stores them in params. Passing NULL for params should return true.

OSSL_FUNC_kem_set_ctx_params() sets the asymmetric KEM parameters associated with the given provider side asymmetric kem context ctx to params. Any parameter settings are additional to any that were previously set. Passing NULL for params should return true.

No parameters are currently recognised by built-in asymmetric kem algorithms.

OSSL_FUNC_kem_gettable_ctx_params() and OSSL_FUNC_kem_settable_ctx_params() get a constant OSSL_PARAM(3) array that describes the gettable and settable parameters, i.e. parameters that can be used with OSSL_FUNC_kem_get_ctx_params() and OSSL_FUNC_kem_set_ctx_params() respectively.

RETURN VALUES

OSSL_FUNC_kem_newctx() and OSSL_FUNC_kem_dupctx() should return the newly created provider side asymmetric kem context, or NULL on failure.

All other functions should return 1 for success or 0 on error.

HISTORY

The provider KEM interface was introduced in OpenSSL 3.0.

OSSL_FUNC_kem_auth_encapsulate_init() and OSSL_FUNC_kem_auth_decapsulate_init() were added in OpenSSL 3.2.

The Asymmetric Key Encapsulation Parameters "fips-indicator" and "key-check" were added in OpenSSL 3.4.
