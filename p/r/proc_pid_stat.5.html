proc_pid_stat(5) Manuel des formats de fichiers proc_pid_stat(5)

NOM

/proc/pid/stat - informations sur l'état

DESCRIPTION

/proc/pid/stat
Informations sur l'état du processus. Utilisé par ps(1). Défini dans le fichier source du noyau fs/proc/array.c.
Les champs, dans l'ordre, avec leurs spécificateurs de format scanf(3) appropriés, sont listés ci-dessous. La validité de certaines de ces informations est régie par une vérification du mode d'accès ptrace PTRACE_MODE_READ_FSCREDS | PTRACE_MODE_NOAUDIT (voir ptrace(2)). Si la vérification refuse l'accès, la valeur du champ est affichée comme 0. Les champs concernés sont indiqués par la mention [PT].
(1) pid %d

L'identifiant du processus.
(2) comm %s
Le nom de fichier de l'exécutable, entre parenthèses. Les chaînes de caractères plus longues que TASK_COMM_LEN (16) caractères (y compris le caractère nul de fin) sont silencieusement tronquées. Ceci est visible que l'exécutable soit échangé sur disque ou non.
(3) state %c
Un des caractères suivants, indiquant l'état du processus :
R
En cours d'exécution
S
En sommeil dans une attente interruptible
D
En attente dans un sommeil disque ininterruptible
Z
Zombie
T
Arrêté (par un signal) ou (avant Linux 2.6.33) arrêté par trace
t
Arrêt de traçage (Linux 2.6.33 et suivants)
W
Pagination (seulement avant Linux 2.6.0)
X
Mort (depuis Linux 2.6.0)
x
Mort (Linux 2.6.33 à 3.13 uniquement)
K
Wakekill (Linux 2.6.33 à 3.13 uniquement)
W
Réveil (Linux 2.6.33 à 3.13 uniquement)
P
Garé (Linux 3.9 à 3.13 uniquement)
I
Inactif (Linux 4.14 et suivants)
(4) ppid %d
Le PID du parent de ce processus.
(5) pgrp %d
L'identifiant du groupe de processus.
(6) session %d
L'identifiant de session du processus.
(7) tty_nr %d
Le terminal de contrôle du processus. (Le numéro de périphérique mineur est contenu dans la combinaison des bits 31 à 20 et 7 à 0 ; le numéro de périphérique majeur est dans les bits 15 à 8.)
(8) tpgid %d
L'identifiant du groupe de processus en avant du terminal de contrôle du processus.
(9) flags %u
Le mot des drapeaux du noyau du processus. Pour la signification des bits, voir les définitions PF_* dans le fichier source du noyau Linux include/linux/sched.h. Les détails dépendent de la version du noyau.
Le format pour ce champ était %lu avant Linux 2.6.
(10) minflt %lu
Le nombre de fautes mineures commises par le processus qui n'ont pas nécessité de charger une page mémoire depuis le disque.
(11) cminflt %lu
Le nombre de fautes mineures commises par les enfants attendus du processus.
(12) majflt %lu
Le nombre de fautes majeures commises par le processus qui ont nécessité le chargement d'une page mémoire depuis le disque.
(13) cmajflt %lu
Le nombre de fautes majeures commises par les enfants attendus du processus.
(14) utime %lu
Temps pendant lequel ce processus a été planifié en mode utilisateur, mesuré en cycles d'horloge (diviser par sysconf(_SC_CLK_TCK)). Ceci inclut le temps invité, guest_time (temps passé à exécuter un CPU virtuel, voir ci-dessous), afin que les applications qui ne sont pas conscientes du champ de temps invité ne perdent pas ce temps dans leurs calculs.
(15) stime %lu
Temps pendant lequel ce processus a été planifié en mode noyau, mesuré en cycles d'horloge (diviser par sysconf(_SC_CLK_TCK)).
(16) cutime %ld
Temps pendant lequel les enfants attendus de ce processus ont été planifiés en mode utilisateur, mesuré en cycles d'horloge (diviser par sysconf(_SC_CLK_TCK)). (Voir aussi times(2).) Ceci inclut le temps invité, cguest_time (temps passé à exécuter un CPU virtuel, voir ci-dessous).
(17) cstime %ld
Temps pendant lequel les enfants attendus de ce processus ont été planifiés en mode noyau, mesuré en cycles d'horloge (diviser par sysconf(_SC_CLK_TCK)).
(18) priority %ld
(Explication pour Linux 2.6) Pour les processus exécutant une politique de planification temps réel (policy ci-dessous ; voir sched_setscheduler(2)), il s'agit de la priorité de planification négativée, moins un ; c'est-à-dire un nombre dans la plage de -2 à -100, correspondant aux priorités temps réel de 1 à 99. Pour les processus exécutant sous une politique de planification non temps réel, il s'agit de la valeur nice brute (setpriority(2)) telle que représentée dans le noyau. Le noyau stocke les valeurs nice sous forme de nombres dans la plage de 0 (élevée) à 39 (basse), correspondant à la plage visible par l'utilisateur de -20 à 19.
Avant Linux 2.6, il s'agissait d'une valeur mise à l'échelle basée sur le poids du planificateur accordé à ce processus.
(19) nice %ld
La valeur nice (voir setpriority(2)), une valeur dans la plage de 19 (basse priorité) à -20 (haute priorité).
(20) num_threads %ld
Nombre de threads dans ce processus (depuis Linux 2.6). Avant Linux 2.6, ce champ était codé en dur à 0 comme espace réservé pour un champ précédemment supprimé.
(21) itrealvalue %ld
Le temps en jiffies avant le prochain SIGALRM envoyé au processus à cause d'un minuteur d'intervalle. Depuis Linux 2.6.17, ce champ n'est plus maintenu et est codé en dur à 0.
(22) starttime %llu
Le moment où le processus a démarré après le démarrage du système. Avant Linux 2.6, cette valeur était exprimée en jiffies. Depuis Linux 2.6, la valeur est exprimée en cycles d'horloge (diviser par sysconf(_SC_CLK_TCK)).
Le format pour ce champ était %lu avant Linux 2.6.
(23) vsize %lu
Taille de la mémoire virtuelle en octets.
(24) rss %ld
Resident Set Size : nombre de pages que le processus a en mémoire réelle. Ce ne sont que les pages qui comptent pour l'espace texte, données ou pile. Cela n'inclut pas les pages qui n'ont pas été chargées à la demande ou qui sont échangées. Cette valeur est imprécise ; voir /proc/pid/statm ci-dessous.
(25) rsslim %lu
Limite logicielle actuelle en octets pour le RSS du processus ; voir la description de RLIMIT_RSS dans getrlimit(2).
(26) startcode %lu [PT]
L'adresse au-dessus de laquelle le texte du programme peut s'exécuter.
(27) endcode %lu [PT]
L'adresse en dessous de laquelle le texte du programme peut s'exécuter.
(28) startstack%lu [PT]
L'adresse de début (c'est-à-dire le bas) de la pile.
(29) kstkesp %lu [PT]
La valeur actuelle de ESP (pointeur de pile), telle que trouvée dans la page de pile du noyau pour le processus.
(30) kstkeip %lu [PT]
Le pointeur d'instruction actuel (EIP).
(31) signal %lu
Le masque de bits des signaux en attente, affiché sous forme de nombre décimal. Obsolète, car il ne fournit pas d'informations sur les signaux temps réel ; utilisez /proc/pid/status à la place.
(32) blocked %lu
Le masque de bits des signaux bloqués, affiché sous forme de nombre décimal. Obsolète, car il ne fournit pas d'informations sur les signaux temps réel ; utilisez /proc/pid/status à la pla

DESCRIPTION

The file /proc/pid/stat contains real-time information about the process with the given PID. This file is read by the top(1) command, for example.

The fields are separated by spaces. Some fields may contain spaces as part of their contents and are enclosed in parentheses in that case. Otherwise, parentheses are not used.

The fields are:

(1) pid %d
The process ID.
(2) comm %s
The filename of the executable, in parentheses, or blank if kernel-command-line parameters are available.
(3) state %c
One character indicating the state of the process. See proc(5) for a list of possible values.
(4) ppid %d
The PID of the parent process.
(5) pgrp %d
The process group ID.
(6) sid %d
The session ID.
(7) tty_nr %d
The terminal number. The controlling terminal of the process.
(8) tty_pgrp %d
The process group ID of the foreground process group on the controlling terminal.
(9) flags %u
The shell language, see siginfo(7). Shell capabilities, see proc(5).
(10) minflt %lu
The number of minor faults. This is the number of times this process has been involved in page faults which did not require physical memory (Reclaimed pages, etc.).
(11) cminflt %lu
The number of minor faults of the children.
(12) majflt %lu
The number of major faults. This is the number of times this process has been involved in page faults which did require physical memory.
(13) cmajflt %lu
The number of major faults of the children.
(14) utime %lu
User mode time. This is the number of clock ticks that this process has spent in user mode.
(15) stime %lu
Kernel mode time. This is the number of clock ticks that this process has spent in kernel mode.
(16) cutime %ld
Children user mode time. This is the number of clock ticks that this process's waited-for children have spent in user mode.
(17) cstime %ld
Children kernel mode time. This is the number of clock ticks that this process's waited-for children have spent in kernel mode.
(18) priority %ld
The dynamic priority. See renice(2).
(19) nice %ld
The nice value (used in old Linux kernels). A value from 0 to 39, where 0 is the highest priority.
(20) num_threads %ld
Number of threads in this process. This field is not present in older kernels.
(21) alarm %lu
The time in clock ticks of the next timer alarm to be raised. In kernel 2.6.10, the alarm timer was made per-thread and this field was removed.
(22) clockmax %lu
The maximum signal number allowed on this system.
(23) clockmsecs %lu
The number of clock ticks in a second.
(24) start_time %llu
The time the process started after system boot.
(25) vsize %lu
The virtual memory size in bytes.
(26) rss %ld
The resident set size. This is the non-swapped physical memory a task has used (in pages).
(27) rsslim %lu
The current soft limit on the resident set size.
(28) start_code %lu
The address above which program text (code) is placed.
(29) end_code %lu
The address below which program text (code) is placed.
(30) start_stack %lu
The address of the start of the stack segment.
(31) kstk_esp %lu
The kernel stack pointer.
(32) kstk_eip %lu
The kernel instruction pointer.
(33) sigignore %lu
The bitmap of ignored signals, displayed as a decimal number. Obsolete, because it does not provide information on real-time signals; use /proc/pid/status instead.
(34) sigcatch %lu
The bitmap of caught signals, displayed as a decimal number. Obsolete, because it does not provide information on real-time signals; use /proc/pid/status instead.
(35) wchan %lu [PT]
This is the "channel" in which the process is waiting. It is the address of a location in the kernel where the process is sleeping. The corresponding symbolic name can be found in /proc/pid/wchan.
(36) nswap %lu
Number of pages swapped (not maintained).
(37) cnswap %lu
Cumulative nswap for child processes (not maintained).
(38) exit_signal %d (since Linux 2.1.22)
Signal to be sent to parent when we die.
(39) processor %d (since Linux 2.2.8)
CPU number last executed on.
(40) rt_priority %u (since Linux 2.5.19)
Real-time scheduling priority, a number in the range 1 to 99 for processes scheduled under a real-time policy, or 0, for non-real-time processes (see sched_setscheduler(2)).
(41) policy %u (since Linux 2.5.19)
Scheduling policy (see sched_setscheduler(2)). Decode using the SCHED_* constants in linux/sched.h.
The format for this field was %lu before Linux 2.6.22.
(42) delayacct_blkio_ticks %llu (since Linux 2.6.18)
Aggregated block I/O delays, measured in clock ticks (centiseconds).
(43) guest_time %lu (since Linux 2.6.24)
Guest time of the process (time spent running a virtual CPU for a guest operating system), measured in clock ticks (divide by sysconf(_SC_CLK_TCK)).
(44) cguest_time %ld (since Linux 2.6.24)
Guest time of the process's children, measured in clock ticks (divide by sysconf(_SC_CLK_TCK)).
(45) start_data %lu (since Linux 3.3) [PT]
Address above which program initialized and uninitialized (BSS) data are placed.
(46) end_data %lu (since Linux 3.3) [PT]
Address below which program initialized and uninitialized (BSS) data are placed.
(47) start_brk %lu (since Linux 3.3) [PT]
Address above which program heap can be expanded with brk(2).
(48) arg_start %lu (since Linux 3.5) [PT]
Address above which program command-line arguments (argv) are placed.
(49) arg_end %lu (since Linux 3.5) [PT]
Address below program command-line arguments (argv) are placed.
(50) env_start %lu (since Linux 3.5) [PT]
Address above which program environment is placed.
(51) env_end %lu (since Linux 3.5) [PT]
Address below which program environment is placed.
(52) exit_code %d (since Linux 3.5) [PT]
The thread's exit status in the form reported by waitpid(2).
