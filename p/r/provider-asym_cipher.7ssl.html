NAME

provider-asym_cipher - Fonctions de bibliothèque asym_cipher <-> fournisseur

SYNOPSIS

#include <openssl/core_dispatch.h>
#include <openssl/core_names.h>
/*
 * Aucune de ces fonctions n'est une fonction réelle, mais elles sont affichées comme telles pour
 * les signatures de fonctions qui sont proposées comme pointeurs de fonction dans les tableaux OSSL_DISPATCH.
 */
/* Gestion de contexte */
void *OSSL_FUNC_asym_cipher_newctx(void *provctx);
void OSSL_FUNC_asym_cipher_freectx(void *ctx);
void *OSSL_FUNC_asym_cipher_dupctx(void *ctx);
/* Chiffrement */
int OSSL_FUNC_asym_cipher_encrypt_init(void *ctx, void *provkey,
                                       const OSSL_PARAM params[]);
int OSSL_FUNC_asym_cipher_encrypt(void *ctx, unsigned char *out, size_t *outlen,
                                  size_t outsize, const unsigned char *in,
                                  size_t inlen);
/* Déchiffrement */
int OSSL_FUNC_asym_cipher_decrypt_init(void *ctx, void *provkey,
                                       const OSSL_PARAM params[]);
int OSSL_FUNC_asym_cipher_decrypt(void *ctx, unsigned char *out, size_t *outlen,
                                  size_t outsize, const unsigned char *in,
                                  size_t inlen);
/* Paramètres du chiffrement asymétrique */
int OSSL_FUNC_asym_cipher_get_ctx_params(void *ctx, OSSL_PARAM params[]);
const OSSL_PARAM *OSSL_FUNC_asym_cipher_gettable_ctx_params(void *provctx);
int OSSL_FUNC_asym_cipher_set_ctx_params(void *ctx, const OSSL_PARAM params[]);
const OSSL_PARAM *OSSL_FUNC_asym_cipher_settable_ctx_params(void *provctx);

DESCRIPTION

Cette documentation s'adresse principalement aux auteurs de fournisseurs. Voir provider(7) pour plus d'informations.

L'opération de chiffrement asymétrique (OSSL_OP_ASYM_CIPHER) permet aux fournisseurs d'implémenter des algorithmes de chiffrement asymétrique et de les rendre disponibles aux applications via les fonctions API EVP_PKEY_encrypt(3), EVP_PKEY_decrypt(3) et autres fonctions associées).

Toutes les "fonctions" mentionnées ici sont transmises sous forme de pointeurs de fonction entre libcrypto et le fournisseur dans des tableaux OSSL_DISPATCH(3) via des tableaux OSSL_ALGORITHM(3) qui sont retournés par la fonction provider_query_operation() du fournisseur (voir "Fonctions du fournisseur" dans provider-base(7)).

Toutes ces "fonctions" ont un type de fonction correspondant nommé OSSL_FUNC_{name}_fn, et une fonction d'aide pour récupérer le pointeur de fonction à partir d'un élément OSSL_DISPATCH(3) nommé OSSL_FUNC_{name}. Par exemple, la "fonction" OSSL_FUNC_asym_cipher_newctx() possède les éléments suivants :

typedef void *(OSSL_FUNC_asym_cipher_newctx_fn)(void *provctx);
static ossl_inline OSSL_FUNC_asym_cipher_newctx_fn
    OSSL_FUNC_asym_cipher_newctx(const OSSL_DISPATCH *opf);

OSSL_DISPATCH(3) Les tableaux sont indexés par des nombres fournis sous forme de macros dans openssl-core_dispatch.h(7), comme suit :

OSSL_FUNC_asym_cipher_newctx               OSSL_FUNC_ASYM_CIPHER_NEWCTX
OSSL_FUNC_asym_cipher_freectx              OSSL_FUNC_ASYM_CIPHER_FREECTX
OSSL_FUNC_asym_cipher_dupctx               OSSL_FUNC_ASYM_CIPHER_DUPCTX
OSSL_FUNC_asym_cipher_encrypt_init         OSSL_FUNC_ASYM_CIPHER_ENCRYPT_INIT
OSSL_FUNC_asym_cipher_encrypt              OSSL_FUNC_ASYM_CIPHER_ENCRYPT
OSSL_FUNC_asym_cipher_decrypt_init         OSSL_FUNC_ASYM_CIPHER_DECRYPT_INIT
OSSL_FUNC_asym_cipher_decrypt              OSSL_FUNC_ASYM_CIPHER_DECRYPT
OSSL_FUNC_asym_cipher_get_ctx_params       OSSL_FUNC_ASYM_CIPHER_GET_CTX_PARAMS
OSSL_FUNC_asym_cipher_gettable_ctx_params  OSSL_FUNC_ASYM_CIPHER_GETTABLE_CTX_PARAMS
OSSL_FUNC_asym_cipher_set_ctx_params       OSSL_FUNC_ASYM_CIPHER_SET_CTX_PARAMS
OSSL_FUNC_asym_cipher_settable_ctx_params  OSSL_FUNC_ASYM_CIPHER_SETTABLE_CTX_PARAMS

Une implémentation d'algorithme de chiffrement asymétrique peut ne pas implémenter toutes ces fonctions. Pour constituer un ensemble cohérent de fonctions, un fournisseur doit implémenter OSSL_FUNC_asym_cipher_newctx et OSSL_FUNC_asym_cipher_freectx. Il doit également implémenter soit OSSL_FUNC_asym_cipher_encrypt_init et OSSL_FUNC_asym_cipher_encrypt, soit OSSL_FUNC_asym_cipher_decrypt_init et OSSL_FUNC_asym_cipher_decrypt. OSSL_FUNC_asym_cipher_get_ctx_params est facultatif, mais s'il est présent, OSSL_FUNC_asym_cipher_gettable_ctx_params doit également l'être. De même, OSSL_FUNC_asym_cipher_set_ctx_params est facultatif, mais s'il est présent, OSSL_FUNC_asym_cipher_settable_ctx_params doit également l'être.

Un algorithme de chiffrement asymétrique doit également implémenter un mécanisme pour générer, charger ou importer des clés via l'opération de gestion de clés (OSSL_OP_KEYMGMT). Voir provider-keymgmt(7) pour plus de détails.

Fonctions de gestion du contexte

OSSL_FUNC_asym_cipher_newctx() doit créer et retourner un pointeur vers une structure côté fournisseur pour conserver les informations de contexte pendant une opération de chiffrement asymétrique. Un pointeur vers ce contexte sera renvoyé dans plusieurs des autres appels de fonction d'opération de chiffrement asymétrique. Le paramètre provctx est le contexte du fournisseur généré lors de l'initialisation du fournisseur (voir provider(7)).

OSSL_FUNC_asym_cipher_freectx() reçoit un pointeur vers le contexte de chiffrement asymétrique côté fournisseur dans le paramètre ctx. Cette fonction doit libérer toutes les ressources associées à ce contexte.

OSSL_FUNC_asym_cipher_dupctx() doit dupliquer le contexte de chiffrement asymétrique côté fournisseur dans le paramètre ctx et retourner la copie dupliquée.

Fonctions de chiffrement

OSSL_FUNC_asym_cipher_encrypt_init() initialise un contexte pour un chiffrement asymétrique donné un contexte de chiffrement asymétrique côté fournisseur dans le paramètre ctx, et un pointeur vers un objet clé fournisseur dans le paramètre provkey. Les params, s'ils ne sont pas NULL, doivent être définis sur le contexte d'une manière similaire à l'utilisation de OSSL_FUNC_asym_cipher_set_ctx_params(). L'objet clé doit avoir été précédemment généré, chargé ou importé dans le fournisseur en utilisant l'opération de gestion de clés (OSSL_OP_KEYMGMT) (voir provider-keymgmt(7)). OSSL_FUNC_asym_cipher_encrypt() effectue le chiffrement réel. Un contexte de chiffrement asymétrique préalablement initialisé est passé dans le paramètre ctx. Les données à chiffrer sont pointées par le paramètre in qui fait inlen octets de long. Sauf si out est NULL, les données chiffrées doivent être écrites à l'emplacement pointé par le paramètre out et ne doivent pas dépasser outsize octets. La longueur des données chiffrées doit être écrite dans *outlen. Si out est NULL, la longueur maximale des données chiffrées doit être écrite dans *outlen.

Fonctions de déchiffrement

OSSL_FUNC_asym_cipher_decrypt_init() initialise un contexte pour un déchiffrement asymétrique donné un contexte de chiffrement asymétrique côté fournisseur dans le paramètre ctx, et un pointeur vers un objet clé fournisseur dans le paramètre provkey. Les params, s'ils ne sont pas NULL, doivent être définis sur le contexte d'une manière similaire à l'utilisation de OSSL_FUNC_asym_cipher_set_ctx_params(). L'objet clé doit avoir été précédemment généré, chargé ou importé dans le fournisseur en utilisant l'opération de gestion de clés (OSSL_OP_KEYMGMT) (voir provider-keymgmt(7)).

OSSL_FUNC_asym_cipher_decrypt() effectue le déchiffrement réel. Un contexte de chiffrement asymétrique préalablement initialisé est passé dans le paramètre ctx. Les données à déchiffrer sont pointées par le paramètre in qui fait inlen octets de long. Sauf si out est NULL, les données déchiffrées doivent être écrites à l'emplacement pointé par le paramètre out et ne doivent pas dépasser outsize octets. La longueur des données déchiffrées doit être écrite dans *outlen. Si out est NULL, la longueur maximale des données déchiffrées doit être écrite dans *outlen.

Paramètres du chiffrement asymétrique

Voir OSSL_PARAM(3) pour plus de détails sur la structure des paramètres utilisée par les fonctions OSSL_FUNC_asym_cipher_get_ctx_params()

et les fonctions OSSL_FUNC_asym_cipher_set_ctx_params().

OSSL_FUNC_asym_cipher_get_ctx_params() récupère les paramètres de chiffrement asymétrique associés au contexte de chiffrement asymétrique côté fournisseur donné, ctx, et les stocke dans params. Passer NULL pour params doit renvoyer true.

OSSL_FUNC_asym_cipher_set_ctx_params() définit les paramètres de chiffrement asymétrique associés au contexte de chiffrement asymétrique côté fournisseur donné, ctx, à params. Tous les paramètres définis sont supplémentaires à ceux qui ont été précédemment définis. Passer NULL pour params doit renvoyer true.

Les paramètres actuellement reconnus par les algorithmes de chiffrement asymétrique intégrés sont les suivants. Tous les paramètres ne sont pas pertinents pour tous les algorithmes de chiffrement asymétrique, ou ne sont pas compris par tous les algorithmes de chiffrement asymétrique :

"pad-mode" (OSSL_ASYM_CIPHER_PARAM_PAD_MODE) <chaîne UTF8> OU <entier>
Le type de remplissage à utiliser. L'interprétation de cette valeur dépendra de l'algorithme utilisé.
"digest" (OSSL_ASYM_CIPHER_PARAM_OAEP_DIGEST) <chaîne UTF8>
Obtient ou définit le nom de l'algorithme de hachage OAEP utilisé lorsque le remplissage OAEP est en cours d'utilisation.
"digest" (OSSL_ASYM_CIPHER_PARAM_DIGEST) <chaîne UTF8>
Obtient ou définit le nom de l'algorithme de hachage utilisé par l'algorithme (le cas échéant).
"digest-props" (OSSL_ASYM_CIPHER_PARAM_OAEP_DIGEST_PROPS) <chaîne UTF8>
Obtient ou définit les propriétés à utiliser lors de la récupération de l'algorithme de hachage OAEP.
"digest-props" (OSSL_ASYM_CIPHER_PARAM_DIGEST_PROPS) <chaîne UTF8>
Obtient ou définit les propriétés à utiliser lors de la récupération de l'algorithme de hachage du chiffrement.
"mgf1-digest" (OSSL_ASYM_CIPHER_PARAM_MGF1_DIGEST) <chaîne UTF8>
Obtient ou définit le nom de l'algorithme de hachage MGF1 utilisé lorsque le remplissage OAEP ou PSS est en cours d'utilisation.
"mgf1-digest-props" (OSSL_ASYM_CIPHER_PARAM_MGF1_DIGEST_PROPS) <chaîne UTF8>
Obtient ou définit les propriétés à utiliser lors de la récupération de l'algorithme de hachage MGF1.
"oaep-label" (OSSL_ASYM_CIPHER_PARAM_OAEP_LABEL) <pointeur vers une chaîne d'octets>
Obtient le libellé OAEP utilisé lorsque le remplissage OAEP est en cours d'utilisation.
"oaep-label" (OSSL_ASYM_CIPHER_PARAM_OAEP_LABEL) <chaîne d'octets>
Définit le libellé OAEP utilisé lorsque le remplissage OAEP est en cours d'utilisation.
"tls-client-version" (OSSL_ASYM_CIPHER_PARAM_TLS_CLIENT_VERSION) <entier non signé>
La version du protocole TLS initialement demandée par le client.
"tls-negotiated-version" (OSSL_ASYM_CIPHER_PARAM_TLS_CLIENT_VERSION) <entier non signé>
La version du protocole TLS négociée.
"implicit-rejection" (OSSL_ASYM_CIPHER_PARAM_IMPLICIT_REJECTION) <entier non signé>
Obtient ou définit l'utilisation du mécanisme de rejet implicite pour le déchiffrement RSA PKCS#1 v1.5. Lorsqu'il est défini (valeur non nulle), l'API de déchiffrement renverra une valeur aléatoire déterministe si la vérification du remplissage PKCS#1 v1.5 échoue. Cela rend l'exploitation de Bleichenbacher beaucoup plus difficile, même si le code utilisant l'API de déchiffrement RSA n'est pas implémenté de manière à éviter les canaux auxiliaires. Défini par défaut dans les fournisseurs OpenSSL.

Le fournisseur FIPS d'OpenSSL prend également en charge les paramètres suivants :

"fips-indicator" (OSSL_ASYM_CIPHER_PARAM_FIPS_APPROVED_INDICATOR) <entier>
Un récupérateur qui renvoie 1 si l'opération est approuvée par FIPS, ou 0 sinon. Cela peut être utilisé après avoir appelé OSSL_FUNC_asym_cipher_encrypt() ou OSSL_FUNC_asym_cipher_decrypt(). Il peut renvoyer 0 si "key-check" est défini à 0.
"key-check" (OSSL_ASYM_CIPHER_PARAM_FIPS_KEY_CHECK) <entier>
Si requis, ce paramètre doit être défini à l'aide de OSSL_FUNC_asym_cipher_encrypt_init() ou de OSSL_FUNC_asym_cipher_decrypt_init(). La valeur par défaut de 1 provoque une erreur lors de l'initialisation si la clé n'est pas approuvée par FIPS (par exemple, la clé a une force de sécurité inférieure à 112 bits). La définition à 0 ignorera l'erreur et définira "fips-indicator" approuvé à 0. Cette option enfreint la conformité FIPS si elle amène "fips-indicator" approuvé à renvoyer 0.

OSSL_FUNC_asym_cipher_gettable_ctx_params() et OSSL_FUNC_asym_cipher_settable_ctx_params() obtiennent un tableau constant OSSL_PARAM(3) qui décrit les paramètres récupérables et définissables, c'est-à-dire les paramètres qui peuvent être utilisés avec OSSL_FUNC_asym_cipherget_ctx_params() et OSSL_FUNC_asym_cipher_set_ctx_params() respectivement.

VALEURS DE RETOUR

OSSL_FUNC_asym_cipher_newctx() et OSSL_FUNC_asym_cipher_dupctx() doivent renvoyer le contexte de chiffrement asymétrique côté fournisseur nouvellement créé, ou NULL en cas d'échec.

Toutes les autres fonctions doivent renvoyer 1 en cas de succès ou 0 en cas d'erreur.

HISTORIQUE

L'interface ASYM_CIPHER du fournisseur a été introduite dans OpenSSL 3.0. Les paramètres de chiffrement asymétrique "fips-indicator" et "key-check" ont été ajoutés dans OpenSSL 3.4.
