PBMTOJBG(1) Manuel des commandes générales PBMTOJBG(1)

NOM

pbmtojbg - convertisseur portable de bitmap vers fichier JBIG1

SYNTAXE

pbmtojbg [ options ] [ fichier-entrée | - [ fichier-sortie ]]

DESCRIPTION

Lit une bitmap portable (PBM) depuis un fichier ou l'entrée standard, la compresse et produit l'image sous forme d'une entité de fichier bi-niveau JBIG1 (BIE).

JBIG1 est un algorithme de compression sans perte très efficace pour les images bi-niveaux (un bit par pixel), particulièrement adapté aux pages de documents numérisés.

Une image codée JBIG1 peut être stockée dans plusieurs résolutions (mode progressif). Ces couches de résolution peuvent être stockées toutes dans un seul BIE ou elles peuvent être stockées dans plusieurs fichiers BIE séparés. Toutes les couches de résolution, sauf la plus basse, sont stockées simplement comme des différences par rapport à la couche de résolution inférieure, car cela nécessite moins d'espace que de coder l'image entière à chaque fois. Chaque couche de résolution a deux fois plus de pixels horizontaux et verticaux que la couche inférieure. Les fichiers JBIG1 peuvent également stocker plusieurs bits par pixel sous forme de plans de bitmap séparés, et pbmtojbg peut lire un fichier PGM et le transformer en un BIE à plusieurs plans de bits.

OPTIONS

-
Un simple trait d'union à la place d'un nom de fichier d'entrée fera que pbmtojbg lira les données depuis l'entrée standard au lieu d'un fichier.
-q
Code l'image dans une seule couche de résolution (mode séquentiel). C'est généralement la méthode de compression la plus efficace. Par défaut, le nombre de couches de résolution est choisi automatiquement de sorte que l'image de la couche la plus basse ne dépasse pas 640 x 480 pixels. C'est un raccourci pour -d 0.
-x nombre
Spécifie la taille horizontale maximale de la couche de résolution la plus basse. La valeur par défaut est de 640 pixels.
-y nombre
Spécifie la taille verticale maximale de la couche de résolution la plus basse. La valeur par défaut est de 480 pixels.
-l nombre
Sélectionne la couche de résolution la plus basse qui sera écrite dans le BIE. Il est possible de stocker les différentes couches de résolution d'une image JBIG1 en mode progressif dans différents BIE. Les options -l et -h permettent de sélectionner l'intervalle de couches de résolution qui apparaîtra dans le BIE créé. La couche de résolution la plus basse porte le numéro 0 et c'est également la valeur par défaut. Par défaut, toutes les couches seront écrites.
-h nombre
Sélectionne la couche de résolution la plus haute qui sera écrite dans le BIE. Par défaut, toutes les couches seront écrites. Voir aussi l'option -l.
-b
Utilise des valeurs binaires au lieu de mots de code Gray pour coder les valeurs des pixels dans plusieurs plans de bits. Cette option n'a d'effet que si l'entrée est un fichier PGM et si plus d'un plan de bits est produit. Notez que le décodeur doit faire la même sélection mais ne peut pas déterminer à partir du BIE si des mots de code Gray ou binaires ont été utilisés par l'encodeur.
-d nombre
Spécifie le nombre total de couches de résolution différentielles dans lesquelles l'image d'entrée sera divisée en plus de la couche la plus basse. Chaque couche supplémentaire réduit la taille de la couche 0 de 50 %. Cette option remplace les options -x et -y qui sont généralement un moyen plus pratique de sélectionner le nombre de couches de résolution.
-s nombre
L'algorithme JBIG1 divise chaque image en un certain nombre de bandes horizontales. Cette option spécifie que chaque bande doit avoir nombre lignes dans la couche 0. La valeur par défaut est sélectionnée de manière à utiliser environ 35 bandes pour l'image entière.
-m nombre
Sélectionne le décalage horizontal maximal du pixel de modèle adaptatif. L'encodeur JBIG1 utilise dix pixels voisins pour estimer la probabilité que le pixel suivant soit noir ou blanc. Il peut déplacer l'un de ces dix pixels. Ceci est particulièrement utile pour les images tramées, tant que la distance de ce pixel adaptatif peut être ajustée à la période du motif de tramage. Par défaut, le pixel de modèle adaptatif est autorisé à se déplacer jusqu'à 8 pixels horizontalement. Cet encodeur prend en charge des distances jusqu'à 127 pixels. L'annexe A de la norme suggère que les décodeurs doivent prendre en charge au moins une distance horizontale de 16 pixels, donc l'utilisation de valeurs ne dépassant pas 16 pour nombre pourrait augmenter les chances d'interopérabilité avec d'autres implémentations JBIG1. D'autre part, le profil d'application fax T.85 exige que les décodeurs prennent en charge des décalages horizontaux allant jusqu'à 127 pixels, ce qui est la valeur maximale autorisée par la norme. (Le décalage vertical maximal du pixel de modèle adaptatif est toujours zéro pour cet encodeur.)
-t nombre
Ne code que le nombre spécifié de plans de bits les plus significatifs. Cette option permet de réduire la profondeur d'un fichier PGM d'entrée si tous les bits par pixel ne sont pas nécessaires en sortie.
-o nombre
JBIG1 sépare une image en plusieurs bandes horizontales, couches de résolution et plans, où chaque plan contient un bit par pixel. Une seule bande dans un plan et une couche est codée sous forme d'une unité de données appelée entité de données de bande (SDE) dans le BIE. Il existe 12 ordres possibles différents dans lesquels les SDE peuvent être stockées dans le BIE et nombre sélectionne celui qui doit être utilisé. L'ordre des SDE n'est pertinent que pour les applications qui souhaitent décoder un fichier JBIG1 qui n'est pas encore complètement arrivé depuis, par exemple, une connexion réseau lente. Par exemple, certaines applications préfèrent que la boucle extérieure des trois boucles (bandes, couches, plans) soit sur toutes les couches, de sorte que toutes les données de la couche de résolution la plus basse soient transmises en premier.


0 plans, couches, bandes
2 couches, plans, bandes
3 couches, bandes, plans
4 bandes, plans, couches
5 plans, bandes, couches
6 bandes, couches, plans

Toutes les boucles commencent à zéro, cependant en ajoutant 8 à l'ordre ci-dessus, la boucle de couches peut être inversée de sorte qu'elle décroisse vers zéro et que les couches de résolution plus élevées soient alors stockées avant les couches inférieures. L'ordre par défaut est 3, qui écrit d'abord tous les plans de la première bande, puis complète la couche 0 avant de continuer avec la couche suivante, et ainsi de suite.

-p nombre
Cette option permet d'activer ou de désactiver divers algorithmes optionnels définis dans la norme JBIG1. Ajoutez simplement les numéros des options suivantes que vous souhaitez activer pour obtenir la valeur nombre :


4 prédiction déterministe (DPON)
8 prédiction typique de la couche 0 (TPBON)
16 prédiction typique de couche diff. (TPDON)
64 modèle à deux lignes de la couche 0 (LRLTWO)

Sauf pour des applications spéciales (comme la communication avec des implémentations sous-ensembles de JBIG1) et à des fins de débogage, vous ne voudrez normalement rien changer ici. La valeur par défaut est 28, ce qui fournit le meilleur résultat de compression.

-C chaîne
Ajoute la chaîne dans un segment marqueur de commentaire au flux de données produit. (Il n'y a actuellement aucun support pour ajouter des commentaires contenant le caractère nul.)
-c
Détermine le déplacement du modèle adaptatif comme suggéré dans l'annexe C de la norme. Par défaut, le changement de modèle a lieu directement dans la ligne suivante, ce qui est le plus efficace. Cependant, quelques exemples de tests de conformité dans la norme exigent que le changement de modèle adaptatif soit retardé jusqu'à la première ligne de la bande suivante. Cette option sélectionne ce comportement spécial, qui n'est normalement pas requis sauf pour réussir certains tests de conformité.
-r
Utilise le marqueur SDRST au lieu du marqueur normal SDNORM. La seule application probablement utile de cette option est de générer des données de test pour vérifier si un décodeur JBIG1 a implémen

pbmtojbg(1) - Arch manual pages

NAME

pbmtojbg - convert an existing PBM image to the JBIG 1 format

SYNOPSIS

pbmtojbg [options] [pbmfile]

DESCRIPTION

The pbmtojbg utility converts a PBM image to the JBIG 1 format. The input image must be a plain PBM image (either P1 or P4 format). The output is written to standard output by default.

OPTIONS

-S
This option forces the use of the SDRST marker instead of the normal SDNORM marker to terminate stripe data entities. The SDRST marker resets the state of the arithmetic encoder and other internal data structures. This is not required for correctly generated JBIG1 data stream. In a normal JBIG1 data stream, each stripe data entity (SDE) is terminated by an SDNORM marker, which preserves the state of the arithmetic encoder (and more) for the next stripe in the same layer. The alternative SDRST marker resets this state at the end of the stripe.
-Y number
A long time ago, there were fax machines that couldn't even hold a single page in memory. They had to start transmitting data before the page was scanned in completely and the length of the image was known. The authors of the standard added a rather ugly hack to the otherwise beautiful JBIG1 format to support this. The NEWLEN marker segment can override the image height stated in the BIE header anywhere later in the data stream. Normally pbmtojbg never generates NEWLEN marker segments, as it knows the correct image height when it outputs the header. This option is solely intended for the purpose of generating test files with NEWLEN marker segments. It can be used to specify a higher initial image height for use in the BIE header, and pbmtojbg will then add a NEWLEN marker segment at the latest possible opportunity to the data stream to signal the correct final height.
-f
This option makes the output file comply to the "facsimile application profile" defined in ITU-T Recommendation T.85. It is a shortcut for -q -o 0 -p 8 -s 128 -t 1 -m 127.
-v
After the BIE has been created, a few technical details of the created file will be listed (verbose mode).

BUGS

Using standard input and standard output for binary data works only on systems where there is no difference between binary and text streams (e.g., Unix). On other systems (e.g., MS-DOS), using standard input or standard output may cause control characters like CR or LF to be inserted or deleted and this will damage the binary data.

STANDARDS

This program implements the JBIG1 image coding algorithm as specified in ISO/IEC 11544:1993 and ITU-T T.82(1993).

AUTHOR

The pbmtojbg program is part of the JBIG-KIT package, which has been developed by Markus Kuhn. The most recent version of this portable JBIG1 library and tools set is available from http://www.cl.cam.ac.uk/~mgk25/jbigkit/.
