readv(2) Manuel des appels système readv(2)

NOM

readv, writev, preadv, pwritev, preadv2, pwritev2 - lire ou écrire des données dans plusieurs tampons

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/uio.h>
ssize_t readv(int fd, const struct iovec *iov, int iovcnt);
ssize_t writev(int fd, const struct iovec *iov, int iovcnt);
ssize_t preadv(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t pwritev(int fd, const struct iovec *iov, int iovcnt,
                off_t offset);
ssize_t preadv2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);
ssize_t pwritev2(int fd, const struct iovec *iov, int iovcnt,
                off_t offset, int flags);
Exigences des macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

preadv(), pwritev() :

    Depuis glibc 2.19 :
        _DEFAULT_SOURCE
    glibc 2.19 et versions antérieures :
        _BSD_SOURCE

DESCRIPTION

L'appel système readv() lit iovcnt tampons à partir du fichier associé au descripteur de fichier fd dans les tampons décrits par iov (« entrée dispersée »).

L'appel système writev() écrit iovcnt tampons de données décrits par iov dans le fichier associé au descripteur de fichier fd (« sortie groupée »).

Le pointeur iov pointe vers un tableau de structures iovec, décrites dans iovec(3type).

L'appel système readv() fonctionne comme read(2) sauf que plusieurs tampons sont remplis.

L'appel système writev() fonctionne comme write(2) sauf que plusieurs tampons sont écrits.

Les tampons sont traités dans l'ordre du tableau. Cela signifie que readv() remplit complètement iov[0] avant de passer à iov[1], et ainsi de suite. (S'il n'y a pas assez de données, il est possible que tous les tampons pointés par iov ne soient pas remplis.) De même, writev() écrit le contenu complet de iov[0] avant de passer à iov[1], et ainsi de suite.

Les transferts de données effectués par readv() et writev() sont atomiques : les données écrites par writev() sont écrites comme un seul bloc qui ne s'entremêle pas avec les sorties des écritures d'autres processus ; de manière analogue, readv() est garanti de lire un bloc de données contigu du fichier, indépendamment des opérations de lecture effectuées dans d'autres threads ou processus qui ont des descripteurs de fichier faisant référence à la même description de fichier ouverte (voir open(2)).

preadv() et pwritev()

L'appel système preadv() combine les fonctionnalités de readv() et pread(2). Il effectue la même tâche que readv(), mais ajoute un quatrième argument, offset, qui spécifie l'offset du fichier auquel l'opération de lecture doit être effectuée.

L'appel système pwritev() combine les fonctionnalités de writev() et pwrite(2). Il effectue la même tâche que writev(), mais ajoute un quatrième argument, offset, qui spécifie l'offset du fichier auquel l'opération d'écriture doit être effectuée.

L'offset du fichier n'est pas modifié par ces appels système. Le fichier référencé par fd doit être capable de se déplacer.

preadv2() et pwritev2()

Ces appels système sont similaires aux appels preadv() et pwritev(), mais ajoutent un cinquième argument, flags, qui modifie le comportement par appel.

Contrairement à preadv() et pwritev(), si l'argument offset est -1, l'offset actuel du fichier est utilisé et mis à jour.

L'argument flags contient un OR bit à bit de zéro ou plusieurs des indicateurs suivants :

RWF_DSYNC (depuis Linux 4.7)
Fournit un équivalent par écriture de l'indicateur O_DSYNC de open(2). Cet indicateur n'est significatif que pour pwritev2(), et son effet ne s'applique qu'à la plage de données écrite par l'appel système.
RWF_HIPRI (depuis Linux 4.6)
Lecture/écriture à haute priorité. Permet aux systèmes de fichiers basés sur des blocs d'utiliser le sondage de l'appareil, ce qui offre une latence plus faible, mais peut utiliser des ressources supplémentaires. (Actuellement, cette fonctionnalité n'est utilisable qu'avec un descripteur de fichier ouvert en utilisant l'indicateur O_DIRECT.)
RWF_SYNC (depuis Linux 4.7)
Fournit un équivalent par écriture de l'indicateur O_SYNC de open(2). Cet indicateur n'est significatif que pour pwritev2(), et son effet ne s'applique qu'à la plage de données écrite par l'appel système.
RWF_NOWAIT (depuis Linux 4.14)
N'attendez pas les données qui ne sont pas immédiatement disponibles. Si cet indicateur est spécifié, l'appel système preadv2() retournera instantanément s'il devait lire des données du stockage sous-jacent ou attendre un verrou. Si des données ont été lues avec succès, il retournera le nombre d'octets lus. S'il n'y a eu aucune lecture d'octets, il retournera -1 et définira errno à EAGAIN (mais voir BUGS). Actuellement, cet indicateur n'est significatif que pour preadv2().
RWF_APPEND (depuis Linux 4.16)
Fournit un équivalent par écriture de l'indicateur O_APPEND de open(2). Cet indicateur n'est significatif que pour pwritev2(), et son effet ne s'applique qu'à la plage de données écrite par l'appel système. L'argument offset n'affecte pas l'opération d'écriture ; les données sont toujours ajoutées à la fin du fichier. Cependant, si l'argument offset est -1, l'offset actuel du fichier est mis à jour.
RWF_NOAPPEND (depuis Linux 6.9)
N'honore pas l'indicateur O_APPEND de open(2). Cet indicateur n'est significatif que pour pwritev2(). Historiquement, Linux honorait l'indicateur O_APPEND s'il était défini et ignorait l'argument offset, ce qui est un bug. Pour pwritev2(), l'argument offset est honoré comme prévu si l'indicateur RWF_NOAPPEND est défini, de la même manière que si l'indicateur O_APPEND n'était pas défini.
RWF_ATOMIC (depuis Linux 6.11)
Exige que les écritures dans les fichiers réguliers des systèmes de fichiers basés sur des blocs soient effectuées avec une protection contre les écritures en déchirure. La protection contre les écritures en déchirure signifie que pour une panne de courant ou toute autre défaillance matérielle, la totalité ou aucune des données de l'écriture ne sera stockée, mais jamais un mélange d'anciennes et de nouvelles données. Cet indicateur n'est significatif que pour pwritev2(), et son effet ne s'applique qu'à la plage de données écrite par l'appel système. La longueur totale de l'écriture doit être une puissance de 2 et doit être dimensionnée dans la plage [stx_atomic_write_unit_min, stx_atomic_write_unit_max]. L'écriture doit se faire à un décalage naturellement aligné dans le fichier par rapport à la longueur totale de l'écriture. Par exemple, une écriture de 32 Kio à un décalage de fichier de 32 Kio est autorisée, mais une écriture de 32 Kio à un décalage de fichier de 48 Kio n'est pas autorisée. La limite supérieure de iovcnt pour pwritev2() est donnée par la valeur de stx_atomic_write_segments_max. La protection contre les écritures en déchirure ne fonctionne qu'avec l'indicateur O_DIRECT, c'est-à-dire que les écritures mises en cache ne sont pas prises en charge. Pour garantir la cohérence entre l'état en mémoire du fichier et le périphérique de stockage, O_SYNC ou O_DSYNC doit être spécifié pour open(2). Les mêmes garanties d'E/S synchronisées que celles décrites dans open(2) sont fournies lorsque ces indicateurs ou leurs équivalents et appels système sont utilisés (par exemple, si RWF_SYNC est spécifié pour pwritev2()).
RWF_DONTCACHE (depuis Linux 6.14)

pwritev2(2) — Read/write data into multiple buffers from/to a specific offset

NAME

pwritev2, preadv2, pwritev, preadv, writev, readv - read/write data into multiple buffers from/to a specific offset

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/uio.h>

ssize_t readv(int fd, const struct iovec *iov, int iovcnt);

ssize_t writev(int fd, const struct iovec *iov, int iovcnt);

ssize_t preadv(int fd, const struct iovec *iov, int iovcnt, off_t offset);

ssize_t pwritev(int fd, const struct iovec *iov, int iovcnt, off_t offset);


#define _GNU_SOURCE /* See feature_test_macros(7) */

ssize_t preadv2(int fd, const struct iovec *iov, int iovcnt, off_t offset, unsigned int flags);

ssize_t pwritev2(int fd, const struct iovec *iov, int iovcnt, off_t offset, unsigned int flags);

DESCRIPTION

The readv() and writev() system calls perform input/output operations on a file descriptor fd, operating on multiple buffers specified by the array of structures iov. The argument iovcnt specifies the number of elements in the array iov.

Each structure in the iov array must contain a pointer to a buffer (iov_base) and the number of bytes to transfer from or into that buffer (iov_len). The readv() function reads data from the file descriptor fd into the buffers specified by iov, and the writev() function writes data from the buffers specified by iov to the file descriptor fd.

The operations are performed sequentially: the first iov_len bytes from the first buffer in iov are read/written, then the next iov_len bytes from the second buffer, and so on, until all buffers have been processed or the requested number of bytes has been transferred. The total number of bytes transferred is the sum of the iov_len values for all structures in iov.

The preadv() and pwritev() functions are similar to readv() and writev(), respectively, except that they perform I/O operations at an offset specified by offset, rather than at the file offset that would be updated by the calls. They do not change the file offset. This is useful for multithreaded applications that need to perform I/O without a shared file offset.

The preadv2() and pwritev2() functions are similar to preadv() and pwritev(), respectively, but they accept an additional argument, flags, which modifies the behavior of the I/O operation. The flags argument is a bitmask composed of zero or more of the following values:

RWF_APPEND
Append data to the end of the file. This flag is only meaningful for regular files and should be used with appropriate permissions. The offset argument is ignored. This flag is a hint, and may not be supported by all file systems.
RWF_NOWAIT
Do not wait for I/O to complete. If the I/O cannot be performed immediately (e.g., if data needs to be fetched from disk), the call returns immediately with EAGAIN. This flag is a hint and may not be supported by all file systems or I/O operations. For read operations, this flag is only supported when used with preadv2(), not readv().
RWF_DATASYNC
Perform a synchronized I/O data integrity completion. This means that the call will not return until the data has been transferred to the physical media. This is a hint and may not be supported by all file systems.
RWF_SYNC
Perform a synchronized I/O data and metadata completion. This means that the call will not return until both the data and the associated metadata have been transferred to the physical media. This is a hint and may not be supported by all file systems.
RWF_HIPRI
Make the I/O request high priority. This is a hint and may not be supported by all file systems.
RWF_DSYNC
Perform a synchronized I/O data completion, similar to RWF_DATASYNC. This flag is a synonym for RWF_DATASYNC.
RWF_FDISCARD
If the operation is a read, it will discard the data from the page cache after it has been copied into user space. This means that subsequent reads of the same data will require fetching it from the underlying storage again. If the operation is a write, it will discard the data from the page cache after it has been written out to the underlying storage. This is a hint, and no hard guarantees are given on the state of the page cache once the operation completes.
RWF_NOWRITETHROUGH
Do not write data through the page cache. This means that data written may remain in the page cache and not be immediately written to the underlying storage. This flag can be used to prevent unnecessary writes to storage when data is expected to be rewritten soon. This is a hint, and no hard guarantees are given on the state of the page cache once the operation completes.
RWF_ATOMIC
Perform an atomic write operation. This means that the entire write operation must succeed or fail as a single unit. If the write operation would cross a torn-write boundary (e.g., writing across a block boundary in a way that could leave the file in an inconsistent state if the write is interrupted), the operation will fail with EINVAL. This flag is only valid for write operations and requires filesystem support.
RWF_DONTCACHE
Do not cache the data in the page cache. Reads or writes to a regular file will prune instantiated page cache content when the operation completes. This is different than normal buffered I/O, where the data usually remains in cache until such time that it gets reclaimed due to memory pressure. If ranges of the read or written I/O were already in cache before this read or write, then those ranges will not be pruned at I/O completion time.
Additionally, any range dirtied by a write operation with RWF_DONTCACHE set will get kicked off for writeback. This is similar to calling sync_file_range(2) with SYNC_FILE_RANGE_WRITE to start writeback on the given range. RWF_DONTCACHE is a hint, or best effort, where no hard guarantees are given on the state of the page cache once the operation completes.
If used on a file system or block device that doesn't support it, it will return -1, and errno will be set to EOPNOTSUPP.

RETURN VALUE

On success, readv(), preadv(), and preadv2() return the number of bytes read; writev(), pwritev(), and pwritev2() return the number of bytes written.

Note that it is not an error for a successful call to transfer fewer bytes than requested (see read(2) and write(2)).

On error, -1 is returned, and errno is set to indicate the error.

ERRORS

The errors are as given for read(2) and write(2). Furthermore, preadv(), preadv2(), pwritev(), and pwritev2() can also fail for the same reasons as lseek(2). Additionally, the following errors are defined:

EINVAL
The sum of the iov_len values overflows an ssize_t value.
EINVAL
If RWF_ATOMIC is specified, the combination of the sum of the iov_len values and the offset value does not comply with the length and offset torn-write protection rules.
EINVAL
The vector count, iovcnt, is less than zero or greater than the permitted maximum. If RWF_ATOMIC is specified, this maximum is given by the stx_atomic_write_segments_max value from statx.
EOPNOTSUPP
RWF_DONTCACHE was set in flags and the file doesn't support it.
EOPNOTSUPP
An unknown flag is specified in flags.

VERSIONS

C library/kernel differences

The raw preadv() and pwritev() system calls have call signatures that differ slightly from that of the corresponding GNU C library wrapper functions shown in the SYNOPSIS. The final argument, offset, is unpacked by the wrapper functions into two arguments in the system calls:

unsigned long pos_l, unsigned long pos

These arguments contain, respectively, the low order and high order 32 bits of offset.

Historical C library/kernel differences

To deal with the fact that IOV_MAX was so low on early versions of Linux, the glibc wrapper functions for readv() and writev() did some extra work if they detected that the underlying kernel system call failed because this limit was exceeded. In the case of readv(), the wrapper function allocated a temporary buffer large enough for all of the items specified by iov, passed that buffer in a call to read(2), copied data from the buffer to the locations specified by the iov_base fields of the elements of iov, and then freed the buffer. The wrapper function for writev() performed the analogous task using a temporary buffer and a call to write(2).

The need for this extra effort in the glibc wrapper functions went away with Linux 2.2 and later. However, glibc continued to provide this behavior until glibc 2.10. Starting with glibc 2.9, the wrapper functions provide this behavior only if the library detects that the system is running a Linux kernel older than Linux 2.6.18 (an arbitrarily selected kernel version). And since glibc 2.20 (which requires a minimum of Linux 2.6.32), the glibc wrapper functions always just directly invoke the system calls.

NOTES

POSIX.1 allows an implementation to place a limit on the number of items that can be passed in iov. An implementation can advertise its limit by defining IOV_MAX in <limits.h> or at run time via the return value from sysconf(_SC_IOV_MAX). On modern Linux systems, the limit is 1024. Back in Linux 2.0 days, this limit was 16.

BUGS

Linux 5.9 and Linux 5.10 have a bug where preadv2() with the RWF_NOWAIT flag may return 0 even when not at end of file.

EXAMPLES

The following code sample demonstrates the use of writev():


char          *str0 = "hello ";
char          *str1 = "world\n";
ssize_t       nwritten;
struct iovec  iov[2];
iov[0].iov_base = str0;
iov[0].iov_len = strlen(str0);
iov[1].iov_base = str1;
iov[1].iov_len = strlen(str1);
nwritten = writev(STDOUT_FILENO, iov, 2);
