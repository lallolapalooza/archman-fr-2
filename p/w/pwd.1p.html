PWD(1P) Manuel du programmeur POSIX PWD(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pwd — retourne le nom du répertoire de travail

SYNTAXE

pwd [-L|-P]

DESCRIPTION

L'utilitaire pwd écrira sur la sortie standard un chemin absolu du répertoire de travail courant, qui ne contient pas les noms de fichiers point et double-point.

OPTIONS

L'utilitaire pwd doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

Les options suivantes doivent être prises en charge par l'implémentation :

-L
Si la variable d'environnement PWD contient un chemin absolu du répertoire courant et que le chemin ne contient aucun composant qui soit point ou double-point, pwd écrira ce chemin sur la sortie standard, sauf si la variable d'environnement PWD est plus longue que {PATH_MAX} octets, y compris le caractère nul de fin, auquel cas il est indéterminé si pwd écrira ce chemin sur la sortie standard ou se comportera comme si l'option -P avait été spécifiée. Sinon, l'option -L se comportera comme l'option -P.
-P
Le chemin écrit sur la sortie standard ne doit contenir aucun composant faisant référence à des fichiers de type lien symbolique. S'il existe plusieurs chemins que l'utilitaire pwd pourrait écrire sur la sortie standard, un commençant par un seul caractère <barre oblique> et un ou plusieurs commençant par deux <barres obliques>, alors il écrira le chemin commençant par un seul <barre oblique>. Le chemin ne doit pas contenir de <barre oblique> inutiles après le ou les deux <barres obliques> de début.

Si les deux -L et -P sont spécifiés, la dernière s'applique. Si ni -L ni -P n'est spécifié, l'utilitaire pwd se comportera comme si -L avait été spécifié.

OPÉRANDES

Aucun.

ENTRÉE STANDARD

Non utilisé.

FICHIERS ENTRANTS

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de pwd :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation, la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini avec une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
PWD
Un chemin absolu du répertoire de travail courant. Si une application définit ou annule la valeur de PWD, le comportement de pwd est indéterminé.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

La sortie de l'utilitaire pwd est un chemin absolu du répertoire de travail courant :

"%s\n", <chemin du répertoire>

ERREUR STANDARD

La sortie d'erreur standard ne sera utilisée que pour les messages de diagnostic.

FICHIERS SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucun.

STATUT SORTIE

Les valeurs de sortie suivantes doivent être retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Si une erreur est détectée, aucune sortie ne sera écrite sur la sortie standard, un message de diagnostic sera écrit sur la sortie d'erreur standard, et le statut de sortie ne sera pas zéro.

Les sections suivantes sont informatives.

USAGE APPLICATIF

Si le chemin obtenu de pwd est plus long que {PATH_MAX} octets, cela pourrait produire une erreur s'il est passé à cd. Par conséquent, pour revenir à ce répertoire, il peut être nécessaire de diviser le chemin en sections plus courtes que {PATH_MAX} et d'appeler cd sur chaque section tour à tour (la première section étant un chemin absolu et les sections suivantes des chemins relatifs).

EXEMPLES

Aucun.

RATIONALE

Certaines implémentations ont historiquement fourni pwd comme commande interne de shell.

Dans la plupart des utilitaires, si une erreur se produit, une sortie partielle peut être écrite sur la sortie standard. Ce n'est pas le cas dans les implémentations historiques de pwd. Étant donné que pwd est fréquemment utilisé dans les scripts shell historiques sans vérifier le statut de sortie, il est important que le comportement historique soit requis ici ; par conséquent, la section CONSÉQUENCES DES ERREURS interdit spécifiquement toute sortie partielle sur la sortie standard.

Une version antérieure de cette norme indiquait que la variable d'environnement PWD était affectée lorsque l'option -P était en vigueur. C'était incorrect ; les implémentations conformes ne font pas cela.
