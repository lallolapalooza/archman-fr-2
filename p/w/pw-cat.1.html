pw-cat(1) Manuel des commandes générales pw-cat(1)

NOM

pw-cat - Jouer et enregistrer des médias avec PipeWire

SYNTAXE

pw-cat [options] [FICHIER | -]

pw-play [options] [FICHIER | -]

pw-record [options] [FICHIER | -]

pw-midiplay [options] [FICHIER | -]

pw-midirecord [options] [FICHIER | -]

pw-dsdplay [options] [FICHIER | -]

DESCRIPTION

pw-cat est un outil simple pour lire ou capturer des fichiers média bruts ou encodés sur un serveur PipeWire. Il comprend tous les formats de fichiers audio pris en charge par libsndfile pour la capture et la lecture PCM. Lors de la capture PCM, l'extension du nom de fichier est utilisée pour deviner le format de fichier, le format WAV étant le défaut.

Il comprend les fichiers MIDI standard pour la lecture et l'enregistrement. Cet outil ne rendra pas les fichiers MIDI, il rendra simplement les événements MIDI disponibles dans le graphe. Vous avez besoin d'un moteur de rendu MIDI tel que qsynth, timidity ou un moteur de rendu MIDI matériel pour entendre le MIDI.

La lecture DSD est prise en charge avec le format de fichier DSF. Cet outil ne fonctionnera qu'avec du matériel capable de gérer le DSD natif et produira une erreur si aucun matériel de ce type n'est trouvé.

Lorsque FICHIER est -, l'entrée et la sortie proviendront respectivement de STDERR et STDOUT.

OPTIONS

-h | --help

Afficher l'aide.

--version

Afficher les informations de version.

-v | --verbose

Opération détaillée.

-R | --remote=NOM

Le nom de l'instance distante à laquelle se connecter. Si non spécifié, une connexion est établie à l'instance PipeWire par défaut.

-p | --playback

Mode de lecture. Lire les données à partir du fichier spécifié et les lire. Si l'outil est appelé sous le nom pw-play ou pw-midiplay, c'est le comportement par défaut.

-r | --record

Mode d'enregistrement. Capturer les données et les écrire dans le fichier spécifié. Si l'outil est appelé sous le nom pw-record ou pw-midirecord, c'est le comportement par défaut.

-m | --midi

Mode MIDI. FICHIER est un fichier MIDI. Si l'outil est appelé sous le nom pw-midiplay ou pw-midirecord, c'est le comportement par défaut. Notez que ce programme ne *rendra pas* les événements MIDI en échantillons audibles, il fournira simplement les événements MIDI dans le graphe. Vous avez besoin d'un moteur de rendu MIDI séparé comme qsynth, timidity ou un moteur de rendu matériel pour entendre le MIDI.

-d | --dsd

Mode DSD. FICHIER est un fichier DSF. Si l'outil est appelé sous le nom pw-dsdplay, c'est le comportement par défaut. Notez que ce programme ne *rendra pas* l'audio DSD. Vous avez besoin d'un appareil compatible DSD pour lire le contenu DSD, sinon ce programme se terminera avec une erreur.

--media-type=VALEUR

Définir la propriété du type de média (Audio/Midi par défaut selon le mode). Le type de média est utilisé par le gestionnaire de session pour sélectionner une cible appropriée à laquelle se connecter.

--media-category=VALEUR

Définir la propriété de la catégorie média (Lecture/Capture par défaut selon le mode). Le type de média est utilisé par le gestionnaire de session pour sélectionner une cible appropriée à laquelle se connecter.

--media-role=VALEUR

Définir la propriété du rôle média (Musique par défaut). Le type de média est utilisé par le gestionnaire de session pour sélectionner une cible appropriée à laquelle se connecter.

--target=VALEUR

Définir une cible de nœud (auto par défaut). La valeur peut être :
  • auto : Sélectionner automatiquement (Défaut)
  • 0 : N'essaie pas de lier ce nœud
  • <id> : Le serial de l'objet ou le nom du nœud d'un nœud cible

--latency=VALEUR[unités]

Définir la latence du nœud (100 ms par défaut)

La latence détermine le temps minimum nécessaire à un échantillon pour voyager de l'application vers l'appareil (lecture) et de l'appareil vers l'application (capture).

La latence détermine la taille des tampons que l'application sera capable de remplir. Une latence plus faible signifie des tampons plus petits mais une surcharge plus élevée. Une latence plus élevée signifie des tampons plus grands et une surcharge plus faible.

Les unités peuvent être s pour secondes, ms pour millisecondes, us pour microsecondes, ns pour nanosecondes. Si aucune unité n'est donnée, la valeur de latence est en échantillons avec le taux d'échantillonnage du fichier.

-P | --properties=VALEUR

Définir des propriétés de flux supplémentaires sous forme d'objet JSON.

-q | --quality=VALEUR

Qualité du ré-échantillonneur. Lorsque le taux d'échantillonnage du fichier source ou de destination ne correspond pas au taux d'échantillonnage du serveur, les données seront ré-échantillonnées. Une qualité plus élevée utilise plus de CPU. Les valeurs entre 0 et 15 sont autorisées, la qualité par défaut est 4.

--rate=VALEUR

Le taux d'échantillonnage, par défaut 48000.

--channels=VALEUR

Le nombre de canaux, par défaut 2.

--channel-map=VALEUR

La carte des canaux. Les valeurs possibles incluent : mono, stereo, surround-21, quad, surround-22, surround-40, surround-31, surround-41, surround-50, surround-51, surround-51r, surround-70, surround-71 ou une liste de noms de canaux séparés par des virgules : FL, FR, FC, LFE, SL, SR, FLC, FRC, RC, RL, RR, TC, TFL, TFC, TFR, TRL, TRC, TRR, RLC, RRC, FLW, FRW, LFE2, FLH, FCH, FRH, TFLC, TFRC, TSL, TSR, LLFR, RLFE, BC, BLC, BRC

--format=VALEUR

Le format d'échantillon à utiliser. L'un des suivants : u8, s8, s16 (défaut), s24, s32, f32, f64.

--volume=VALEUR

Le volume du flux, 1.000 par défaut. Selon les paramètres régionaux que vous avez configurés, "," ou "." peut être utilisé comme séparateur décimal. Vérifiez avec la commande locale.
