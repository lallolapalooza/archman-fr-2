DESCRIPTION

objdump affiche des informations sur un ou plusieurs fichiers objet. Les options contrôlent quelles informations spécifiques sont affichées. Ces informations sont principalement utiles aux programmeurs qui travaillent sur les outils de compilation, par opposition aux programmeurs qui veulent simplement que leur programme compile et fonctionne.

fichier_objet... sont les fichiers objet à examiner. Lorsque vous spécifiez des archives, objdump affiche des informations sur chacun des fichiers objet membres.

OPTIONS

Les formes longues et courtes des options, présentées ici comme des alternatives, sont équivalentes. Au moins une option de la liste -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x doit être fournie.

-a
--archive-header
Si l'un des fichiers fichier_objet est une archive, affiche les informations de l'en-tête de l'archive (dans un format similaire à ls -l). En plus des informations que vous pourriez lister avec ar tv, objdump -a montre le format du fichier objet de chaque membre de l'archive.
--adjust-vma=decalage
Lors de l'affichage des informations, ajoute d'abord decalage à toutes les adresses de section. Ceci est utile si les adresses de section ne correspondent pas à la table des symboles, ce qui peut arriver lors de la mise de sections à des adresses spécifiques lorsque l'on utilise un format qui ne peut pas représenter les adresses de section, comme a.out.
-b nom_bfd
--target=nom_bfd
Spécifie que le format du code objet pour les fichiers objet est nom_bfd. Cette option peut ne pas être nécessaire ; objdump peut reconnaître automatiquement de nombreux formats.

Par exemple,

objdump -b oasys -m vax -h fu.o

affiche des informations récapitulatives des en-têtes de section (-h) de fu.o, qui est explicitement identifié (-m) comme un fichier objet VAX dans le format produit par les compilateurs Oasys. Vous pouvez lister les formats disponibles avec l'option -i.

-C
--demangle[=style]
Décode (demangle) les noms de symboles de bas niveau en noms de niveau utilisateur. En plus de supprimer le trait de soulignement initial ajouté par le système, cela rend les noms de fonctions C++ lisibles. Différents compilateurs ont différents styles de mangling. L'argument optionnel du style de déchiffrement peut être utilisé pour choisir un style de déchiffrement approprié pour votre compilateur.
--recursion-limit
--no-recursion-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du déchiffrement des chaînes. Comme les formats de mangling de noms permettent un niveau infini de récursion, il est possible de créer des chaînes dont le décodage épuisera l'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite essaie d'éviter que cela ne se produise en limitant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais sa désactivation peut être nécessaire pour déchiffrer des noms véritablement compliqués. Notez cependant que si la limite de récursion est désactivée, l'épuisement de la pile est possible et tout rapport de bug concernant un tel événement sera rejeté.

-g
--debugging
Affiche les informations de débogage. Ceci tente d'analyser les informations de débogage au format STABS stockées dans le fichier et de les imprimer en utilisant une syntaxe de type C. Si aucun débogage STABS n'a été trouvé, cette option se rabat sur l'option -W pour imprimer toute information DWARF dans le fichier.
-e
--debugging-tags
Comme -g, mais les informations sont générées dans un format compatible avec l'outil ctags.
-d
--disassemble
--disassemble=symbole
Affiche les mnémoniques de l'assembleur pour les instructions machine du fichier d'entrée. Cette option ne désassemble que les sections qui sont censées contenir des instructions. Si l'argument optionnel symbole est donné, alors affiche les mnémoniques de l'assembleur en commençant à symbole. Si symbole est un nom de fonction, le désassemblage s'arrêtera à la fin de la fonction, sinon il s'arrêtera lors de la rencontre du symbole suivant. S'il n'y a pas de correspondance pour symbole, rien ne sera affiché.

Notez que si l'option --dwarf=follow-links est activée, toutes les tables de symboles des fichiers d'informations de débogage liés seront lues et utilisées lors du désassemblage.

-D
--disassemble-all
Comme -d, mais

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

-d
--disassemble
Désassemblez le contenu de toutes les sections non vides qui ne sont pas dans la section BSS, pas seulement celles censées contenir des instructions. -j peut être utilisé pour sélectionner des sections spécifiques.

Cette option a également un effet subtil sur le désassemblage des instructions dans les sections de code. Lorsque l'option -d est activée, objdump suppose que tous les symboles présents dans une section de code se trouvent à la limite entre les instructions et refuse de désassembler au-delà d'une telle limite. Cependant, lorsque l'option -D est activée, cette hypothèse est supprimée. Cela signifie que la sortie de -d et -D peut différer si, par exemple, des données sont stockées dans des sections de code.

Si la cible est une architecture ARM, ce commutateur a également pour effet de forcer le désassembleur à décoder des morceaux de données trouvés dans les sections de code comme s'il s'agissait d'instructions.

Notez que si l'option --dwarf=follow-links est activée, toutes les tables de symboles dans les fichiers d'informations de débogage liés seront lus et utilisés lors du désassemblage.

--no-addresses
Lors du désassemblage, n'affichez pas les adresses sur chaque ligne, ni pour les symboles et les décalages de relocalisation. En combinaison avec --no-show-raw-insn, cela peut être utile pour comparer la sortie du compilateur.
--prefix-addresses
Lors du désassemblage, affichez l'adresse complète sur chaque ligne. C'est l'ancien format de désassemblage.
-EB
-EL
--endian={big|little}
Spécifiez l'endianness des fichiers objet. Ceci n'affecte que le désassemblage. Cela peut être utile lors du désassemblage d'un format de fichier qui ne décrit pas les informations d'endianness, tel que les S-records.
-f
--file-headers
Affiche les informations récapitulatives de l'en-tête général de chacun des fichiers objfile.
-F
--file-offsets
Lors du désassemblage de sections, chaque fois qu'un symbole est affiché, affichez également le décalage du fichier de la région de données sur le point d'être déversée. Si des zéros sont ignorés, lorsque le désassemblage reprend, informez l'utilisateur du nombre de zéros ignorés et du décalage du fichier de l'emplacement à partir duquel le désassemblage reprend. Lors du déversement de sections, affichez le décalage du fichier de l'emplacement à partir duquel le déversement commence.
--file-start-context
Spécifiez que lors de l'affichage du code source/désassemblage entrelacé (suppose -S) à partir d'un fichier qui n'a pas encore été affiché, étendez le contexte au début du fichier.
-h
--section-headers
--headers
Affiche les informations récapitulatives des en-têtes de section du fichier objet.

Les segments de fichier peuvent être déplacés vers des adresses non standard, par exemple en utilisant les options -Ttext, -Tdata, ou -Tbss de ld. Cependant, certains formats de fichiers objet, tels que a.out, ne stockent pas l'adresse de départ des segments de fichier. Dans ces situations, bien que ld déplace correctement les sections, l'utilisation de objdump -h pour lister les en-têtes de section du fichier ne peut pas afficher les bonnes adresses. Au lieu de cela, elle affiche les adresses habituelles, qui sont implicites pour la cible.

Notez que, dans certains cas, il est possible qu'une section ait à la fois les attributs READONLY et NOREAD définis. Dans de tels cas, l'attribut NOREAD a la priorité, mais objdump affichera les deux car le réglage exact des bits du drapeau peut être important.

-H
--help
Affiche un résumé des options de objdump et quitte.
-i
--info
Affiche une liste montrant tous les architectures et formats d'objets disponibles pour la spécification avec -b ou -m.
-j name
--section=name
Affiche les informations pour la section name. Cette option peut être spécifiée plusieurs fois.
-L
--process-links
Affiche le contenu des sections non de débogage trouvées dans des fichiers d'informations de débogage séparés qui sont liés au fichier principal. Cette option implique automatiquement l'option -WK, et seules les sections demandées par d'autres options de ligne de commande seront affichées.
-l
--line-numbers
Étiquette l'affichage (en utilisant les informations de débogage) avec le nom du fichier et les numéros de ligne source correspondant au code objet ou aux relocations affichés. Utile uniquement avec -d, -D, ou -r.
-m machine
--architecture=machine
Spécifiez l'architecture à utiliser lors du désassemblage des fichiers objet. Cela peut être utile lors du désassemblage de fichiers objet qui ne décrivent pas les informations d'architecture, tels que les S-records. Vous pouvez lister les architectures disponibles avec l'option -i.

Pour la plupart des architectures, il est possible de fournir un nom d'architecture et un nom de machine, séparés par deux points. Par exemple, foo:bar ferait référence au type de machine bar dans l'architecture foo. Cela peut être utile si objdump a été configuré pour prendre en charge plusieurs architectures.

Si la cible est une architecture ARM, ce commutateur a un effet supplémentaire. Il limite le désassemblage à uniquement les instructions prises en charge par l'architecture spécifiée par machine. S'il est nécessaire d'utiliser ce commutateur car le fichier d'entrée ne contient aucune information d'architecture, mais que vous souhaitez également désassembler toutes les instructions, utilisez -marm.

-M options
--disassembler-options=options
Passe des informations spécifiques à la cible au désassembleur. Uniquement pris en charge sur certaines cibles. S'il est nécessaire de spécifier plus d'une option de désassembleur, plusieurs options -M peuvent être utilisées ou placées ensemble dans une liste séparée par des virgules.

Pour ARC, dsp contrôle l'affichage des instructions DSP, spfp sélectionne l'affichage des instructions FP à virgule flottante simple précision FPX, dpfp sélectionne l'affichage des instructions FP à virgule flottante double précision FPX, quarkse_em sélectionne l'affichage des instructions spéciales QuarkSE-EM, fpuda sélectionne l'affichage des instructions d'assistance à virgule flottante double précision, fpus sélectionne l'affichage des instructions FP à virgule flottante simple précision FPU, tandis que fpud sélectionne l'affichage des instructions FP à virgule flottante double précision FPU. De plus, on peut choisir d'afficher toutes les immédiates en hexadécimal en utilisant hex. Par défaut, les immédiates courtes sont affichées en représentation décimale, tandis que les valeurs immédiates longues sont affichées en hexadécimal.

cpu=... permet de forcer un ISA particulier lors du désassemblage d'instructions, remplaçant la valeur de -m ou ce qui est dans le fichier ELF. Cela peut être utile pour sélectionner l'ISA ARC EM ou HS, car l'architecture est la même pour ceux-ci et le désassembleur s'appuie sur des données d'en-tête ELF privées pour décider si le code est pour EM ou HS. Cette option peut être spécifiée plusieurs fois - seule la dernière valeur sera utilisée. Les valeurs valides sont les mêmes que pour l'option -mcpu=... de l'assembleur.

Si la cible est une architecture ARM, ce commutateur peut être utilisé pour sélectionner quel jeu de noms de registres est utilisé pendant le désassemblage. Spécifier -M reg-names-std (par défaut) sélectionnera les noms de registres tels qu'utilisés dans la documentation de l'ensemble d'instructions ARM, mais avec le registre 13 appelé 'sp', le registre 14 appelé 'lr' et le registre 15 appelé 'pc'. Spécifier -M reg-names-apcs sélectionnera le jeu de noms utilisé par l'ARM Procedure Call Standard, tandis que spécifier -M reg-names-raw utilisera simplement r suivi du numéro de registre.

Il existe également deux variantes du schéma de nommage des registres APCS activées par -M reg-names-atpcs et -M reg-names-special-atpcs qui utilisent les conventions de nommage de l'ARM/Thumb Procedure Call Standard. (Soit avec les noms de registres normaux, soit avec les noms de registres spéciaux).

Cette option peut également être utilisée pour les architectures ARM afin de forcer le désassembleur à interpréter toutes les instructions comme des instructions Thumb en utilisant le commutateur --disassembler-options=force-thumb. Cela peut être utile lors de la tentative de désassemblage de code Thumb produit par d'autres compilateurs.

Pour les cibles AArch64, ce commutateur peut être utilisé pour définir si les instructions sont désassemblées comme l'instruction la plus générale en utilisant l'option -M no-aliases ou si les notes d'instruction doivent être générées sous forme de commentaires dans le désassemblage en utilisant -M notes.

Pour le x86, certaines des options dupliquent les fonctions du commutateur -m, mais permettent un contrôle plus fin.

"x86-64"
"i386"
"i8086"
Sélectionne le désassemblage pour l'architecture donnée.
"intel"
"att"
Sélectionne entre le mode syntaxe Intel et le mode syntaxe AT&T.
"amd64"
"intel64"
Sélectionne entre l'ISA AMD64 et l'ISA Intel64.
"intel-mnemonic"
"att-mnemonic"
Sélectionne entre le mode mnemonique Intel et le mode mnemonique AT&T. Note : "intel-mnemonic" implique "intel" et "att-mnemonic" implique "att".
"addr64"
"addr32"
"addr16"
"data32"
>
"data16"
Spécifie la taille d'adresse et la taille d'opérande par défaut. Ces cinq options seront ignorées si "x86-64", "i386" ou "i8086" apparaissent plus tard dans la chaîne d'options.
"suffix"
En mode AT&T et également pour un ensemble limité d'instructions en mode Intel, demande au désassembleur d'afficher un suffixe mnémonique même lorsque le suffixe peut être déduit des opérandes ou, pour certaines instructions, des valeurs par défaut du mode d'exécution.

Pour PowerPC, l'argument -M raw sélectionne la désassemblage des instructions matérielles plutôt que des alias. Par exemple, vous verrez "rlwinm" plutôt que "clrlwi", et "addi" plutôt que "li". Tous les arguments -m pour gas qui sélectionnent un CPU sont pris en charge. Il s'agit de : 403, 405, 440, 464, 476, 601, 603, 604, 620, 7400, 7410, 7450, 7455, 750cl, 821, 850, 860, a2, booke, booke32, cell, com, e200z2, e200z4, e300, e500, e500mc, e500mc64, e500x2, e5500, e6500, efs, power4, power5, power6, power7, power8, power9, power10, ppc, ppc32, ppc64, ppc64bridge, ppcps, pwr, pwr2, pwr4, pwr5, pwr5x, pwr6, pwr7, pwr8, pwr9, pwr10, pwrx, titan, vle, et future. 32 et 64 modifient la sélection de CPU par défaut ou antérieure, désactivant et activant respectivement les instructions 64 bits. De plus, altivec, any, lsp, htm, vsx, spe et spe2 ajoutent des fonctionnalités à une sélection de CPU précédente ou ultérieure. any désassemblera tout opcode connu de binutils, mais dans les cas où un opcode a deux significations différentes ou des arguments différents, vous pourriez ne pas obtenir le désassemblage attendu. Si vous désassemblez sans spécifier de sélection de CPU, une valeur par défaut sera choisie à partir des informations obtenues par BFD dans les en-têtes des fichiers objet, mais le résultat pourrait là encore ne pas être celui que vous attendez.

Pour MIPS, cette option contrôle l'affichage des noms mnémoniques d'instructions et des noms de registres dans les instructions désassemblées. Plusieurs sélections parmi les suivantes peuvent être spécifiées sous forme de chaîne séparée par des virgules, et les options invalides sont ignorées :

"no-aliases"
Affiche le mnémonique d'instruction 'brut' au lieu de certains mnémoniques d'instructions pseudo. C'est-à-dire, affiche 'daddu' ou 'or' au lieu de 'move', 'sll' au lieu de 'nop', etc.
"msa"
Désassemble les instructions MSA.
"virt"
Désassemble les instructions ASE de virtualisation.
"xpa"
Désassemble les instructions eXtended Physical Address (XPA) ASE.
"gpr-names=ABI"
Affiche les noms des registres GPR (registres à usage général) appropriés pour l'ABI spécifié. Par défaut, les noms des GPR sont sélectionnés en fonction de l'ABI du binaire désassemblé.
"fpr-names=ABI"
Affiche les noms des registres FPR (registres à virgule flottante) appropriés pour l'ABI spécifié. Par défaut, les numéros des FPR sont affichés plutôt que les noms.
"cp0-names=ARCH"
Affiche les noms des registres CP0 (coprocesseur de contrôle système ; coprocesseur 0) appropriés pour le CPU ou l'architecture spécifié par ARCH. Par défaut, les noms des registres CP0 sont sélectionnés en fonction de l'architecture et du CPU du binaire désassemblé.
"hwr-names=ARCH"
Affiche les noms des HWR (registres matériels, utilisés par l'instruction "rdhwr") appropriés pour le CPU ou l'architecture spécifié par ARCH. Par défaut, les noms des HWR sont sélectionnés en fonction de l'architecture et du CPU du binaire désassemblé.
"reg-names=ABI"
Affiche les noms des GPR et FPR appropriés pour l'ABI sélectionné.
"reg-names=ARCH"
Affiche les noms de registres spécifiques au CPU (registres CP0 et noms HWR) appropriés pour le CPU ou l'architecture sélectionné.

Pour l'une des options listées ci-dessus, ABI ou ARCH peut être spécifié comme numeric pour que les nombres soient affichés plutôt que les noms, pour les types de registres sélectionnés. Vous pouvez lister les valeurs disponibles de ABI et ARCH en utilisant l'option --help.

Pour VAX, vous pouvez spécifier les adresses d'entrée de fonction avec -M entry:0xf00ba. Vous pouvez l'utiliser plusieurs fois pour désassembler correctement les fichiers binaires VAX qui ne contiennent pas de tables de symboles (comme les dumps ROM). Dans ces cas, le masque d'entrée de fonction serait sinon décodé comme des instructions VAX, ce qui entraînerait probablement un désassemblage erroné du reste de la fonction.

-p
--private-headers
Affiche les informations spécifiques au format du fichier objet. Les informations exactes affichées dépendent du format du fichier objet. Pour certains formats de fichiers objets, aucune information supplémentaire n'est affichée.
-P options
--private=options
Affiche les informations spécifiques au format du fichier objet. L'argument options est une liste séparée par des virgules qui dépend du format (la liste des options est affichée avec l'aide).

Pour XCOFF, les options disponibles sont :

"header"
"aout"
"sections"
"syms"
"relocs"
"lineno,"
"loader"
"except"
"typchk"
"traceback"
"toc"
"ldinfo"

Pour PE, les options disponibles sont :

"header"
"sections"

Tous les formats d'objets ne prennent pas en charge cette option. En particulier, le format ELF ne l'utilise pas.

-r
--reloc
Affiche les entrées de relocalisation du fichier. Si utilisé avec -d ou -D, les relocalisations sont affichées intercalées avec le désassemblage.
-R
--dynamic-reloc
Affiche les entrées de relocalisation dynamiques du fichier. Ceci n'est pertinent que pour les objets dynamiques, tels que certains types de bibliothèques partagées. Comme pour -r, si utilisé avec -d ou -D, les relocalisations sont affichées intercalées avec le désassemblage.
-s
--full-contents
Affiche le contenu complet des sections, souvent utilisé en combinaison avec -j pour demander des sections spécifiques. Par défaut, toutes les sections non vides et non BSS sont affichées. Par défaut, toute section compressée sera affichée sous sa forme compressée. Pour voir le contenu sous forme décompressée, ajoutez l'option -Z à la ligne de commande.
-S
--source
Affiche le code source entremêlé avec le désassemblage, si possible. Implique -d.
--show-all-symbols
Lors du désassemblage, affiche tous les symboles correspondant à une adresse donnée, pas seulement le premier.
--source-comment[=txt]
Comme l'option -S, mais toutes les lignes de code source sont affichées avec un préfixe de txt. Généralement txt sera une chaîne de commentaire qui peut être utilisée pour distinguer le code assembleur du code source. Si txt n'est pas fourni, une chaîne par défaut "# " (dièse suivi d'un espace) sera utilisée.
--prefix=prefix
Spécifie prefix à ajouter aux chemins absolus lorsqu'il est utilisé avec -S.
--prefix-strip=level
Indique combien de noms de répertoires initiaux doivent être supprimés des chemins absolus codés en dur. N'a aucun effet sans --prefix=prefix.
--show-raw-insn
Lors du désassemblage d'instructions, affiche l'instruction en hexadécimal ainsi qu'en forme symbolique. C'est la valeur par défaut sauf lorsque --prefix-addresses est utilisé.
--no-show-raw-insn
Lors du désassemblage d'instructions, n'affiche pas les octets de l'instruction. C'est la valeur par défaut lorsque --prefix-addresses est utilisé.
--insn-width=width
Affiche width octets sur une seule ligne lors du désassemblage d'instructions.
--visualize-jumps[=color|=extended-color|=off]
Visualise les sauts qui restent à l'intérieur d'une fonction en dessinant des dessins ASCII entre l'adresse de début et l'adresse cible. L'argument optionnel =color ajoute de la couleur à la sortie en utilisant des couleurs de terminal simples. Alternativement, l'argument =extended-color ajoutera de la couleur en utilisant des couleurs 8 bits, mais celles-ci pourraient ne pas fonctionner sur tous les terminaux.

S'il est nécessaire de désactiver l'option visualize-jumps après qu'elle ait été activée précédemment, utilisez visualize-jumps=off.

--disassembler-color=off
--disassembler-color=terminal
--disassembler-color=on|color|colour
--disassembler-color=extened|extended-color|extened-colour
Active ou désactive l'utilisation de la coloration syntaxique dans la sortie du désassemblage. La valeur par défaut
ault. L'option de configuration détermine le comportement. Notez que toutes les architectures ne prennent pas en charge la mise en évidence de la syntaxe colorée, et en fonction du terminal utilisé, la sortie colorée peut ne pas être réellement lisible.

L'argument on ajoute des couleurs en utilisant des couleurs de terminal simples.

L'argument terminal fait de même, mais uniquement si le périphérique de sortie est un terminal.

L'argument extended-color est similaire à l'argument on, mais il utilise des couleurs 8 bits. Celles-ci peuvent ne pas fonctionner sur tous les terminaux.

L'argument off désactive le désassemblage coloré.

NOM

objdump — affiche des informations sur les fichiers objet

SYNTAXE

objdump [-a|--all-headers] [-A|--disassemble-all] [-b|--target OBJFORMAT] [-C|--demangle[=style]] [-d|--disassemble] [-D|--disassemble-dynamic] [-e|--debugging] [-f|--headers] [-g|--debugging] [-h|--section-headers] [-i|--info] [-l|--line-numbers] [-m|--architecture MÊME] [-p|--private-headers] [-P|--dynamic-list SYM…] [-r|--relocs] [-R|--dynamic-relocs] [-s|--full-contents] [-S|--source] [-t|--syms] [-T|--dynamic-syms] [-u|--unwind-info] [-v|--version] [-w|--wide] [-x|--all-headers] [-z|--disassemble-zeroes] [-Z|--decompress] [objfile...]]

DESCRIPTION

objdump est un utilitaire pour afficher des informations sur divers types de fichiers objet. Il peut être utilisé pour afficher le contenu de divers fichiers objet, pour transformer le code assembleur et le désassembler, pour afficher des informations sur les sections, les symboles et les relocations.

objdump peut afficher les informations dans un format spécifique à chaque cible, ou dans un format plus générique.

La section suivante fournit des détails sur les diverses options de ligne de commande et leurs formats de sortie associés.

Le format de sortie par défaut pour les fichiers ELF, lorsque ni l‘option -g, -S, -t, ni -T n‘est utilisée, est le même que pour l‘option -g.

Lorsque l‘option -g est utilisée, les informations suivantes sont affichées pour chaque entrée de la table des symboles : le numéro de section sec, la valeur des bits de drapeau du symbole fl, le type de symbole ty, la classe de stockage du symbole scl et le nombre d‘entrées auxiliaires nx associées au symbole. Les deux derniers champs sont la valeur et le nom du symbole.

L‘autre format de sortie courant, généralement observé avec les fichiers basés sur ELF, ressemble à ceci :

00000000 l    d  .bss   00000000 .bss
00000000 g       .text  00000000 fred

Ici, le premier nombre est la valeur du symbole (parfois appelée son adresse). Le champ suivant est en fait un ensemble de caractères et d‘espaces indiquant les bits de drapeau définis sur le symbole. Ces caractères sont décrits ci-dessous. Ensuite vient la section à laquelle le symbole est associé ou \*ABS\* si la section est absolue (c‘est-à-dire non connectée à une section), ou \*UND\* si la section est référencée dans le fichier en cours de déchargement, mais non définie là.

Après le nom de la section vient un autre champ, un nombre, qui pour les symboles communs est l‘alignement et pour les autres symboles est la taille. Finalement, le nom du symbole est affiché.

Les caractères de drapeau sont divisés en 7 groupes comme suit :
