PPPOE-RELAY(8) Manuel de l'administrateur système PPPOE-RELAY(8)

NOM

pppoe-relay - agent relais PPPoE (Point-to-Point Protocol over Ethernet) en espace utilisateur.

SYNTAXE

pppoe-relay [options]

DESCRIPTION

pppoe-relay est un agent relais en espace utilisateur pour PPPoE (Point-to-Point Protocol over Ethernet) sous Linux. pppoe-relay fonctionne en concertation avec le client pppoe et le serveur pppoe-server. Voir la section OPERATION plus loin dans ce manuel pour les détails sur le fonctionnement de pppoe-relay.

OPTIONS

-S interface
Ajoute l'interface Ethernet interface à la liste des interfaces gérées par pppoe-relay. Seuls des serveurs PPPoE peuvent être connectés à cette interface.
-C interface
Ajoute l'interface Ethernet interface à la liste des interfaces gérées par pppoe-relay. Seuls des clients PPPoE peuvent être connectés à cette interface.
-B interface
Ajoute l'interface Ethernet interface à la liste des interfaces gérées par pppoe-relay. Des clients et des serveurs PPPoE peuvent être connectés à cette interface.
-n nombre
Autorise au maximum nombre sessions PPPoE simultanées. Si non spécifié, la valeur par défaut est 5000. nombre peut varier de 1 à 65534.
-i délai
Spécifie le délai d'inactivité de la session. Si les deux pairs d'une session sont inactifs pendant plus de délai secondes, la session est terminée. Si délai est spécifié comme zéro, les sessions ne seront jamais terminées en raison de l'inactivité.

Notez que la routine d'expiration des sessions inactives n'est jamais exécutée plus fréquemment que toutes les 30 secondes, donc le délai est approximatif. La valeur par défaut pour délai est de 600 secondes (10 minutes.)

-F
L'option -F fait que pppoe-relay ne se détache pas en arrière-plan ; au lieu de cela, il reste au premier plan.
-h
L'option -h affiche un bref message d'utilisation et quitte.

FONCTIONNEMENT

pppoe-relay écoute les trames PADI PPPoE entrantes sur toutes les interfaces spécifiées avec les options -B ou -C. Lorsqu'une trame PADI apparaît, pppoe-relay ajoute une balise Relay-Session-ID et diffuse la PADI sur toutes les interfaces spécifiées avec les options -B ou -S (sauf l'interface sur laquelle la trame est arrivée.)

Toutes les trames PADO reçues sont retransmises au client qui a envoyé la PADI (en supposant qu'elles contiennent des balises Relay-Session-ID valides.) De même, les trames PADR des clients sont retransmises au concentrateur d'accès correspondant.

Lorsqu'une trame PADS est reçue, pppoe-relay ajoute les adresses MAC et les ID de session des deux pairs à une table de hachage. (L'ID de session vu par le concentrateur d'accès peut être différent de celui vu par le client ; pppoe-relay doit renommer les sessions pour éviter la possibilité d'ID de session dupliqués.) Chaque fois qu'un pair envoie une trame de session, pppoe-relay recherche l'entrée de session dans la table de hachage et retransmet la trame au pair correct.

Lorsqu'une trame PADT est reçue, pppoe-relay la retransmet au pair et supprime l'entrée de session de sa table de hachage.

Si un client et un serveur plantent (ou si des trames sont perdues), des trames PADT peuvent ne jamais être envoyées, et la table de hachage de pppoe-relay peut se remplir de sessions obsolètes. Par conséquent, une routine de nettoyage des sessions s'exécute périodiquement et supprime les anciennes sessions de la table de hachage. Une session est considérée comme "ancienne" si aucun trafic n'a été vu pendant délai secondes. Lorsqu'une session est supprimée en raison d'un délai d'attente, une trame PADT est envoyée à chaque pair pour s'assurer qu'ils sont conscients que la session a été tuée.

EXEMPLES INVOCATIONS

pppoe-relay -C eth0 -S eth1

L'exemple ci-dessus relaie les trames entre des clients PPPoE sur le réseau eth0 et des serveurs PPPoE sur le réseau eth1.

pppoe-relay -B eth0 -B eth1

Cet exemple est un relais transparent -- les trames sont relayées entre n'importe quel mélange de clients et de serveurs sur les réseaux eth0 et eth1.

pppoe-relay -S eth0 -C eth1 -C eth2 -C eth3

Cet exemple relaie les trames entre les serveurs sur le réseau eth0 et les clients sur les réseaux eth1, eth2 et eth3.
