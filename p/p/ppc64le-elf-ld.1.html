LD(1) Outils de développement GNU LD(1)

NOM

ld - L'éditeur de liens GNU

SYNTAXE

ld [options] fichier-objet ...

DESCRIPTION

ld combine un certain nombre de fichiers objets et d'archives, relocalise leurs données et résout les références de symboles. Habituellement, la dernière étape de la compilation d'un programme est d'appeler ld.

ld accepte des fichiers de langage de commande de liaison écrits dans un sur-ensemble de la syntaxe du langage de commande de l'éditeur de liens AT&T, afin de fournir un contrôle explicite et total sur le processus de liaison.

Cette page de manuel ne décrit pas le langage de commande ; voir l'entrée ld dans "info" pour les détails complets sur le langage de commande et sur d'autres aspects de l'éditeur de liens GNU.

Cette version de ld utilise les bibliothèques BFD à usage général pour opérer sur les fichiers objets. Cela permet à ld de lire, combiner et écrire des fichiers objets dans de nombreux formats différents — par exemple, COFF ou "a.out". Différents formats peuvent être liés ensemble pour produire n'importe quel type de fichier objet disponible.

Outre sa flexibilité, l'éditeur de liens GNU est plus utile que d'autres éditeurs de liens pour fournir des informations diagnostiques. De nombreux éditeurs de liens abandonnent l'exécution immédiatement en cas d'erreur ; lorsque c'est possible, ld continue l'exécution, vous permettant d'identifier d'autres erreurs (ou, dans certains cas, d'obtenir un fichier de sortie malgré l'erreur).

L'éditeur de liens GNU ld est conçu pour couvrir un large éventail de situations, et pour être aussi compatible que possible avec d'autres éditeurs de liens. Par conséquent, vous avez de nombreux choix pour contrôler son comportement.

OPTIONS

L'éditeur de liens prend en charge une pléthore d'options en ligne de commande, mais en pratique peu d'entre elles sont utilisées dans un contexte particulier. Par exemple, une utilisation fréquente de ld consiste à lier des fichiers objets Unix standard sur un système Unix standard supporté. Sur un tel système, pour lier un fichier "hello.o" :

ld -o <sortie> /lib/crt0.o hello.o -lc

Cela indique à ld de produire un fichier nommé sortie comme résultat de la liaison du fichier "/lib/crt0.o" avec "hello.o" et la bibliothèque "libc.a", qui proviendra des répertoires de recherche standards. (Voir la discussion de l'option -l ci-dessous.)

Certaines des options en ligne de commande de ld peuvent être spécifiées à n'importe quel point de la ligne de commande. Cependant, les options qui font référence à des fichiers, telles que -l ou -T, entraînent la lecture du fichier au point où l'option apparaît dans la ligne de commande, par rapport aux fichiers objets et autres options de fichier. Répéter des options non liées à des fichiers avec un argument différent n'aura soit aucun effet supplémentaire, soit remplacera les occurrences précédentes (celles plus à gauche sur la ligne de commande) de cette option. Les options qui peuvent être spécifiées plusieurs fois de manière significative sont notées dans les descriptions ci-dessous.

Les arguments non-option sont des fichiers objets ou des archives qui doivent être liés ensemble. Ils peuvent suivre, précéder ou être mélangés avec les options de ligne de commande, à l'exception du fait qu'un argument de fichier objet ne peut pas être placé entre une option et son argument.

Habituellement, l'éditeur de liens est invoqué avec au moins un fichier objet, mais vous pouvez spécifier d'autres formes de fichiers d'entrée binaires en utilisant -l, -R et le langage de commande de script. Si aucun fichier d'entrée binaire n'est spécifié du tout, l'éditeur de liens ne produit aucune sortie et émet le message No input files.

Si l'éditeur de liens ne peut pas reconnaître le format d'un fichier objet, il suppose qu'il s'agit d'un script d'éditeur de liens. Un script spécifié de cette manière augmente le script principal de l'éditeur de liens utilisé pour la liaison (soit le script de liaison par défaut, soit celui spécifié avec -T). Cette fonctionnalité permet à l'éditeur de liens de lier avec un fichier qui ressemble à un objet ou à une archive, mais qui définit en réalité certaines valeurs de symboles, ou utilise "INPUT" ou "GROUP" pour charger d'autres objets. La spécification d'un script de cette manière ne fait qu'augmenter le script principal de l'éditeur de liens, les commandes supplémentaires étant placées après le script principal ; utilisez l'option -T pour remplacer entièrement le script de liaison par défaut, mais notez l'effet de la commande "INSERT".

Pour les options dont les noms sont une seule lettre, les arguments d'option doivent soit suivre la lettre d'option sans espace blanc intermédiaire, soit être fournis comme arguments séparés immédiatement après l'option qui les requiert.

Pour les options dont les noms sont composés de plusieurs lettres, un seul trait d'union ou deux peuvent précéder le nom de l'option ; par exemple, -trace-symbol et --trace-symbol sont équivalents. Notez qu'il existe une exception à cette règle. Les options composées de plusieurs lettres commençant par une lettre minuscule 'o' ne peuvent être précédées que de deux traits d'union. Ceci afin de réduire la confusion avec l'option -o. Ainsi, par exemple, -omagic définit le nom du fichier de sortie sur magic tandis que --omagic définit le drapeau NMAGIC sur la sortie.

Les arguments des options composées de plusieurs lettres doivent soit être séparés du nom de l'option par un signe égal, soit être fournis comme arguments séparés immédiatement après l'option qui les requiert. Par exemple, --trace-symbol foo et --trace-symbol=foo sont équivalents. Des abréviations uniques des noms des options composées de plusieurs lettres sont acceptées.

Notez que si l'éditeur de liens est invoqué indirectement, via un pilote de compilateur (par exemple, gcc), alors toutes les options de ligne de commande de l'éditeur de liens doivent être préfixées par -Wl, (ou ce qui est approprié pour le pilote de compilateur particulier) comme ceci :

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Ceci est important, car sinon le programme pilote de compilateur peut ignorer silencieusement les options de l'éditeur de liens, ce qui entraîne une liaison incorrecte. Une confusion peut également survenir lors du passage d'options nécessitant des valeurs via un pilote, car l'utilisation d'un espace entre l'option et son argument agit comme un séparateur, et fait que le pilote transmet uniquement l'option à l'éditeur de liens et l'argument au compilateur. Dans ce cas, il est plus simple d'utiliser les formes jointes des options à une seule lettre et à plusieurs lettres, telles que :

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

Voici une table des commutateurs génériques en ligne de commande acceptés par l'éditeur de liens GNU :

@fichier
Lit les options de ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas, ou ne peut pas être lu, alors l'option sera traitée littéralement, et ne sera pas supprimée.

Les options dans fichier sont séparées par des espaces blancs. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière d'apostrophes simples ou doubles. N'importe quel caractère (y compris une barre oblique inverse) peut être inclus en préfixant le caractère à inclure avec une barre oblique inverse. Le fichier peut lui-même contenir des options @fichier supplémentaires ; toutes ces options seront traitées récursivement.

-a mot-clé
Cette option est supportée pour la compatibilité HP/UX. L'argument mot-clé doit être l'une des chaînes archive, shared, ou default. -aarchive est fonctionnellement équivalent à -Bstatic, et les deux autres mots-clés sont fonctionnellement équivalents à -Bdynamic. Cette option peut être utilisée un nombre quelconque de fois.
--audit BIBLIOAUDIT
Ajoute BIBLIOAUDIT à l'entrée "DT_AUDIT" de la section dynamique. BIBLIOAUDIT n'est pas vérifié pour son existence, et n'utilisera pas non plus le DT_SONAME spécifié dans la bibliothèque. S'il est spécifié plusieurs fois, "DT_AUDIT" contiendra une liste d'interfaces d'audit séparées par des deux-points à utiliser. Si l'éditeur de liens trouve un objet avec une entrée d'audit lors de la recherche de bibliothèques partagées, il ajoutera une entrée "DT_DEPAUDIT" correspondante dans le fichier de sortie. Cette option n'est significative que sur les plateformes ELF supportant l'interface rtld-audit.
-b format-entrée
--format=format-entrée
ld peut être configuré pour supporter plus d'un type de fichier objet. Si votre ld est configuré de cette façon, vous pouvez utiliser l'option -b pour spécifier le format binaire pour les fichiers objets qui suivent cette option sur la ligne de commande. Même lorsque ld est configuré pour supporter des formats d'objets alternatifs, vous n'avez généralement pas besoin de le spécifier, car ld devrait être configuré pour attendre comme
un format d'entrée par défaut, le format le plus courant sur chaque machine. format-entrée est une chaîne de caractères, le nom d'un format particulier pris en charge par les bibliothèques BFD. (Vous pouvez lister les formats binaires disponibles avec objdump -i.)

Vous voudrez peut-être utiliser cette option si vous liez des fichiers avec un format binaire inhabituel. Vous pouvez également utiliser -b pour changer explicitement de format (lors de la liaison de fichiers objets de formats différents), en incluant -b format-entrée avant chaque groupe de fichiers objets d'un format particulier.

Le format par défaut est pris de la variable d'environnement "GNUTARGET".

Vous pouvez également définir le format d'entrée à partir d'un script, en utilisant la commande "TARGET" ;

-c fichier-commande-MRI
--mri-script=fichier-commande-MRI
Pour la compatibilité avec les éditeurs de liens produits par MRI, ld accepte des fichiers script écrits dans un langage de commande alternatif et restreint, décrit dans la section Fichiers script compatibles MRI de la documentation GNU ld. Introduisez les fichiers script MRI avec l'option -c ; utilisez l'option -T pour exécuter des scripts d'éditeur de liens écrits dans le langage de script ld à usage général. Si fichier-commande-MRI n'existe pas, ld le recherche dans les répertoires spécifiés par les options -L.
-d
-dc
-dp
Ces trois options sont équivalentes ; plusieurs formes sont prises en charge pour la compatibilité avec d'autres éditeurs de liens. Elles allouent de l'espace aux symboles communs même si un fichier de sortie relogeable est spécifié (avec -r). La commande script "FORCE_COMMON_ALLOCATION" a le même effet.
--depaudit BIBLIOTHEQUE-AUDIT
-P BIBLIOTHEQUE-AUDIT
Ajoute BIBLIOTHEQUE-AUDIT à l'entrée "DT_DEPAUDIT" de la section dynamique. BIBLIOTHEQUE-AUDIT n'est pas vérifié pour son existence, ni n'utilisera le DT_SONAME spécifié dans la bibliothèque. Si spécifié plusieurs fois, "DT_DEPAUDIT" contiendra une liste d'interfaces d'audit à utiliser, séparée par des deux-points. Cette option n'est pertinente que sur les plateformes ELF prenant en charge l'interface rtld-audit. L'option -P est fournie pour la compatibilité Solaris.
--enable-linker-version
Active la directive de script d'éditeur de liens "LINKER_VERSION", décrite dans Données de section de sortie. Si cette directive est utilisée dans un script d'éditeur de liens et que cette option a été activée, une chaîne contenant la version de l'éditeur de liens sera insérée au point actuel.

Notez que l'emplacement de cette option sur la ligne de commande de l'éditeur de liens est significatif. Elle n'affectera que les scripts d'éditeur de liens qui viennent après elle sur la ligne de commande, ou qui sont intégrés à l'éditeur de liens.

--disable-linker-version
Désactive la directive de script d'éditeur de liens "LINKER_VERSION", de sorte qu'elle n'insère pas de chaîne de version. C'est le comportement par défaut.
--enable-non-contiguous-regions
Cette option évite de générer une erreur si une section d'entrée ne correspond pas à une section de sortie correspondante. L'éditeur de liens essaie d'allouer la section d'entrée aux sections de sortie correspondantes suivantes et ne génère une erreur que si aucune section de sortie n'est assez grande. Ceci est utile lorsque plusieurs régions de mémoire non contiguës sont disponibles et que la section d'entrée ne nécessite pas une région particulière. L'ordre dans lequel les sections d'entrée sont évaluées ne change pas, par exemple : 
MEMORY {
  MEM1 (rwx) : ORIGIN = 0x1000, LENGTH = 0x14
  MEM2 (rwx) : ORIGIN = 0x1000, LENGTH = 0x40
  MEM3 (rwx) : ORIGIN = 0x2000, LENGTH = 0x40
}
SECTIONS {
  mem1 : { *(.data.*); } > MEM1
  mem2 : { *(.data.*); } > MEM2
  mem3 : { *(.data.*); } > MEM3
}

avec des sections d'entrée :
.data.1: taille 8
.data.2: taille 0x10
.data.3: taille 4

résulte en .data.1 attribué à mem1, et .data.2 et .data.3
attribués à mem2, même si .data.3 rentre dans mem3.

Cette option est incompatible avec les instructions INSERT car elle modifie la manière dont les sections d'entrée sont mappées aux sections de sortie.

--enable-non-contiguous-regions-warnings
Cette option active les avertissements lorsque "--enable-non-contiguous-regions" permet des correspondances potentiellement inattendues dans le mappage des sections, conduisant potentiellement à l'abandon silencieux d'une section au lieu d'un échec car elle ne rentre dans aucune région de sortie.
-e entrée
--entry=entrée
Utilise entrée comme symbole explicite pour le début de l'exécution de votre programme, plutôt que le point d'entrée par défaut. S'il n'y a pas de symbole nommé entrée, l'éditeur de liens essaiera d'analyser entrée comme un nombre et l'utilisera comme adresse d'entrée (le nombre sera interprété en base 10 ; vous pouvez utiliser un préfixe 0x pour la base 16, ou un préfixe 0 pour la base 8).
--exclude-libs lib,lib,...
Spécifie une liste de bibliothèques d'archives à partir desquelles les symboles ne doivent pas être exportés automatiquement. Les noms de bibliothèques peuvent être délimités par des virgules ou des deux-points. Spécifier "--exclude-libs ALL" exclut les symboles de toutes les bibliothèques d'archives de l'exportation automatique. Cette option n'est disponible que pour le port cible i386 PE de l'éditeur de liens et pour les ports cibles ELF. Pour i386 PE, les symboles explicitement listés dans un fichier .def sont toujours exportés, quelle que soit cette option. Pour les ports cibles ELF, les symboles affectés par cette option seront traités comme cachés.
--exclude-modules-for-implib module,module,...
Spécifie une liste de fichiers objets ou de membres d'archive, à partir desquels les symboles ne doivent pas être exportés automatiquement, mais qui doivent être copiés intégralement dans la bibliothèque d'importation générée lors de la liaison. Les noms de modules peuvent être délimités par des virgules ou des deux-points, et doivent correspondre exactement aux noms de fichiers utilisés par ld pour ouvrir les fichiers ; pour les membres d'archive, il s'agit simplement du nom du membre, mais pour les fichiers objets, le nom indiqué doit inclure et correspondre précisément à tout chemin utilisé pour spécifier le fichier d'entrée sur la ligne de commande de l'éditeur de liens. Cette option n'est disponible que pour le port cible i386 PE de l'éditeur de liens. Les symboles explicitement listés dans un fichier .def sont toujours exportés, quelle que soit cette option.
-E
--export-dynamic
--no-export-dynamic
Lors de la création d'un exécutable lié dynamiquement, l'utilisation de l'option -E ou de l'option --export-dynamic entraîne l'ajout de tous les symboles à la table des symboles dynamiques par l'éditeur de liens. La table des symboles dynamiques est l'ensemble des symboles qui sont visibles à partir des objets dynamiques au moment de l'exécution.

Si vous n'utilisez aucune de ces options (ou si vous utilisez l'option --no-export-dynamic pour rétablir le comportement par défaut), la table des symboles dynamiques contiendra normalement uniquement les symboles référencés par un objet dynamique mentionné dans la liaison.

Si vous utilisez "dlopen" pour charger un objet dynamique qui doit se référer aux symboles définis par le programme, plutôt qu'à un autre objet dynamique, vous devrez probablement utiliser cette option lors de la liaison du programme lui-même.

Vous pouvez également utiliser la liste dynamique pour contrôler quels symboles doivent être ajoutés à la table des symboles dynamiques si le format de sortie le prend en charge. Voir la description de --dynamic-list.

Notez que cette option est spécifique aux ports cibles ELF. Les cibles PE prennent en charge une fonction similaire pour exporter tous les symboles d'une DLL ou d'un EXE ; voir la description de --export-all-symbols ci-dessous.

--export-dynamic-symbol=glob
Lors de la création d'un exécutable lié dynamiquement, les symboles correspondant à glob seront ajoutés à la table des symboles dynamiques. Lors de la création d'une bibliothèque partagée, les références aux symboles correspondant à glob ne seront pas liées aux définitions à l'intérieur de la bibliothèque partagée. Cette option n'a aucun effet lors de la création d'une bibliothèque partagée et si -Bsymbolic ou --dynamic-list ne sont pas spécifiés. Cette option n'est pertinente que sur les plateformes ELF prenant en charge les bibliothèques partagées.
--export-dynamic-symbol-list=fichier
Spécifie un --export-dynamic-symbol pour chaque modèle dans le fichier. Le format du fichier est le même que celui du nœud de version sans portée et nom de nœud. Voir VERSION pour plus d'informations.
-EB
Lier des objets big-endian. Cela affecte le format de sortie par défaut.
-EL
Lier des objets little-endian. Cela affecte le format de sortie par défaut.
-f nom
--auxiliary=nom
Lors de la création d'un objet partagé ELF, définit le champ interne DT_AUXILIARY sur le nom spécifié. Cela indique à l'éditeur de liens dynamique que la table des symboles de l'objet partagé doit être utilisée comme filtre auxiliaire sur la table des symboles de l'objet partagé nom.

Si vous liez plus tard un programme à cet objet filtre, lorsque vous exécutez le programme, l'éditeur de liens dynamique verra le champ DT_AUXILIARY. Si l'éditeur de liens dynamique résout des symboles à partir de l'objet filtre, il vérifiera d'abord s'il existe une définition dans l'objet partagé nom. S'il y en a une, elle sera utilisée à la place de la définition dans l'objet filtre. L'objet partagé nom n'a pas besoin d'exister. Ainsi, l'objet partagé nom peut être utilisé pour fournir une implémentation alternative de certaines fonctions, peut-être pour le débogage ou pour des performances spécifiques à la machine.

Cette option peut être spécifiée plusieurs fois. Les entrées DT_AUXILIARY seront créées dans l'ordre où elles apparaissent sur la ligne de commande.

-F nom
--filter=nom
Lors de la création d'un objet partagé ELF, définissez le champ interne DT_FILTER à le nom spécifié. Cela indique à l'éditeur de liens dynamique que la table des symboles de l'objet partagé qui est en cours de création doit être utilisée comme filtre sur la table des symboles de l'objet partagé nom.

Si vous liez ultérieurement un programme à cet objet filtre, alors, lorsque vous exécutez le programme, l'éditeur de liens dynamique verra le champ DT_FILTER. L'éditeur de liens dynamique résoudra les symboles conformément à la table des symboles de l'objet filtre comme d'habitude, mais il se liera en fait aux définitions trouvées dans l'objet partagé nom. Ainsi, l'objet filtre peut être utilisé pour sélectionner un sous-ensemble des symboles fournis par l'objet nom.

Certains éditeurs de liens plus anciens utilisaient l'option -F tout au long d'une chaîne d'outils de compilation pour spécifier le format du fichier objet pour les fichiers objets d'entrée et de sortie. L'éditeur de liens GNU utilise d'autres mécanismes pour cela à cette fin : les options -b, --format, --oformat, la commande "TARGET" dans les scripts de l'éditeur de liens, et la variable d'environnement "GNUTARGET". L'éditeur de liens GNU ignorera l'option -F lorsqu'il ne créera pas d'objet partagé ELF.

-fini=nom
Lors de la création d'un exécutable ou d'un objet partagé ELF, appelez NOM lorsque l'exécutable ou l'objet partagé est déchargé, en définissant DT_FINI à l'adresse de la fonction. Par défaut, l'éditeur de liens utilise "_fini" comme fonction à appeler.
-g
Ignoré. Fourni pour la compatibilité avec d'autres outils.
-G valeur
--gpsize=valeur
Définir la taille maximale des objets à optimiser en utilisant le registre GP à taille. Ceci n'est pertinent que pour les formats de fichiers objets tels que MIPS ELF qui prennent en charge le placement d'objets grands et petits dans différentes sections. Ceci est ignoré pour les autres formats de fichiers objets.
-h nom
-soname=nom
Lors de la création d'un objet partagé ELF, définissez le champ interne DT_SONAME à le nom spécifié. Lorsqu'un exécutable est lié à un objet partagé qui possède un champ DT_SONAME, alors lorsque l'exécutable est exécuté, l'éditeur de liens dynamique tentera de charger l'objet partagé spécifié par le champ DT_SONAME plutôt que d'utiliser le nom de fichier donné à l'éditeur de liens.
-i
Effectuer une liaison incrémentielle (équivalent à l'option -r).
-init=nom
Lors de la création d'un exécutable ou d'un objet partagé ELF, appelez NOM lorsque l'exécutable ou l'objet partagé est chargé, en définissant DT_INIT à l'adresse de la fonction. Par défaut, l'éditeur de liens utilise "_init" comme fonction à appeler.
-l spécification_nom
--library=spécification_nom
Ajoutez l'archive ou le fichier objet spécifié par spécification_nom à la liste des fichiers à lier. Cette option peut être utilisée un nombre quelconque de fois. Si spécification_nom est de la forme :nom_de_fichier, ld recherchera dans le chemin de la bibliothèque un fichier appelé nom_de_fichier, sinon il recherchera dans le chemin de la bibliothèque un fichier appelé libspécification_nom.a.

Sur les systèmes qui prennent en charge les bibliothèques partagées, ld peut également rechercher des fichiers autres que libspécification_nom.a. Spécifiquement, sur les systèmes ELF et SunOS, ld recherchera dans un répertoire une bibliothèque appelée libspécification_nom.so avant de rechercher une appelée libspécification_nom.a. (Par convention, une extension ".so" indique une bibliothèque partagée.) Notez que ce comportement ne s'applique pas à :nom_de_fichier, qui spécifie toujours un fichier appelé nom_de_fichier.

L'éditeur de liens ne recherchera dans une archive qu'une seule fois, à l'endroit où elle est spécifiée sur la ligne de commande. Si l'archive définit un symbole qui était indéfini dans un objet qui apparaissait avant l'archive sur la ligne de commande, l'éditeur de liens inclura les fichiers appropriés de l'archive. Cependant, un symbole indéfini dans un objet apparaissant plus tard sur la ligne de commande n'entraînera pas une nouvelle recherche de l'archive par l'éditeur de liens.

Voir l'option -( pour une méthode permettant de forcer l'éditeur de liens à rechercher les archives plusieurs fois.

Vous pouvez lister la même archive plusieurs fois sur la ligne de commande.

Ce type de recherche d'archives est standard pour les éditeurs de liens Unix. Cependant, si vous utilisez ld sur AIX, notez qu'il est différent du comportement de l'éditeur de liens AIX.

-L repertoire_recherche
--library-path=repertoire_recherche
Ajoute le chemin repertoire_recherche à la liste des chemins que ld recherchera pour les bibliothèques d'archives et les scripts de contrôle ld. Vous pouvez utiliser cette option un nombre quelconque de fois. Les répertoires sont recherchés dans l'ordre où ils sont spécifiés sur la ligne de commande. Les répertoires spécifiés sur la ligne de commande sont recherchés avant les répertoires par défaut. Toutes les options -L s'appliquent à toutes les options -l, indépendamment de l'ordre dans lequel les options apparaissent. Les options -L n'affectent pas la manière dont ld recherche un script d'éditeur de liens, sauf si l'option -T est spécifiée.

Si repertoire_recherche commence par "=" ou $SYSROOT, alors ce préfixe sera remplacé par le préfixe sysroot, contrôlé par l'option --sysroot, ou spécifié lors de la configuration de l'éditeur de liens.

L'ensemble par défaut des chemins recherchés (sans être spécifié avec -L) dépend du mode d'émulation utilisé par ld, et dans certains cas également de la manière dont il a été configuré.

Les chemins peuvent également être spécifiés dans un script de liaison avec la commande "SEARCH_DIR". Les répertoires spécifiés de cette manière sont recherchés au point où le script de liaison apparaît sur la ligne de commande.

-m émulation
Émuler l'éditeur de liens émulation. Vous pouvez lister les émulations disponibles avec les options --verbose ou -V.

Si l'option -m n'est pas utilisée, l'émulation est prise de la variable d'environnement "LDEMULATION", si elle est définie.

Sinon, l'émulation par défaut dépend de la manière dont l'éditeur de liens a été configuré.

--remap-inputs=motif=nom_de_fichier
--remap-inputs-file=fichier
Ces options permettent de modifier les noms des fichiers d'entrée avant que l'éditeur de liens ne tente de les ouvrir. L'option --remap-inputs=foo.o=bar.o fera en sorte que toute tentative de chargement d'un fichier appelé foo.o tente à la place de charger un fichier appelé bar.o. Les motifs génériques sont autorisés dans le premier nom de fichier, donc --remap-inputs=foo*.o=bar.o renommera tout fichier d'entrée correspondant à foo*.o en bar.o.

Une forme alternative de l'option --remap-inputs-file=nom_de_fichier permet de lire les remappages à partir d'un fichier. Chaque ligne du fichier peut contenir un seul remappage. Les lignes vides sont ignorées. Tout ce qui va d'un caractère dièse (#) à la fin d'une ligne est considéré comme un commentaire et est également ignoré. Le motif de mappage peut être séparé du nom de fichier par un espace blanc ou un signe égal (=).

Les options peuvent être spécifiées plusieurs fois. Leur contenu s'accumule. Les remappages seront traités dans l'ordre où ils apparaissent sur la ligne de commande, et s'ils proviennent d'un fichier, dans l'ordre où ils apparaissent dans le fichier. Si une correspondance est trouvée, aucune vérification supplémentaire pour ce nom de fichier ne sera effectuée.

Si le nom de fichier de remplacement est /dev/null ou simplement NUL, alors le remappage entraînera l'ignorance effective du fichier d'entrée. Cela peut être un moyen pratique d'expérimenter la suppression de fichiers d'entrée d'un environnement de build complexe.

Notez que cette option dépend de la position et n'affecte que les noms de fichiers qui la suivent sur la ligne de commande. Ainsi :

ld foo.o --remap-inputs=foo.o=bar.o

N'aura aucun effet, alors que :

ld --remap-inputs=foo.o=bar.o foo.o

Renommera le fichier d'entrée foo.o en bar.o.

Remarque : ces options affectent également les fichiers référencés par les instructions INPUT dans les scripts de l'éditeur de liens. Mais comme les scripts de l'éditeur de liens sont traités après que toute la ligne de commande a été lue, la position des options de remappage sur la ligne de commande n'est pas significative.

Si l'option verbose est activée, les correspondances trouvées seront signalées, bien que là encore l'option verbose doive être activée sur la ligne de commande avant l'apparition des noms de fichiers remappés.

Si les options -Map ou --print-map sont activées, la liste des remappages sera incluse dans la sortie de la carte.

-M
--print-map
Imprimer une carte de liaison sur la sortie standard. Une carte de liaison fournit des informations sur la liaison, notamment :
  • Où les fichiers objets sont mappés en mémoire.
  • Comment les symboles communs sont alloués.
  • Tous les membres d'archive inclus dans la liaison, avec mention du symbole qui a causé l'inclusion du membre d'archive.
  • Les valeurs attribuées aux symboles.

    Remarque : les symboles dont les valeurs sont calculées par une expression qui implique une référence à une valeur précédente du même symbole peuvent ne pas avoir le résultat correct affiché dans la carte de liaison. En effet, l'éditeur de liens ignore les résultats intermédiaires et ne conserve que la valeur finale d'une expression. Dans de telles circonstances, l'éditeur de liens affichera la valeur finale entourée de crochets. Ainsi, par exemple, un script d'éditeur de liens contenant :

    foo = 1
foo = foo * 4
foo = foo + 8

    produira la sortie suivante dans la carte de liaison si l'option -M est utilisée :

    0x00000001                foo = 0x1
[0x0000000c]                foo = (foo * 0x4)
[0x0000000c]                foo = (foo + 0x8)

    Voir Expressions pour

plus d'informations sur les expressions dans les scripts de liaison.

  • Comment les propriétés GNU sont fusionnées.

    Lorsque le lieur fusionne les sections .note.gnu.property d'entrée en une seule section de sortie .note.gnu.property, certaines propriétés sont supprimées ou mises à jour. Ces actions sont signalées dans la carte de liaison. Par exemple :

    Removed property 0xc0000002 to merge foo.o (0x1) and bar.o (not found)

    Cela indique que la propriété 0xc0000002 est supprimée de la sortie lors de la fusion des propriétés dans foo.o, dont la valeur de la propriété 0xc0000002 est 0x1, et bar.o, qui ne possède pas la propriété 0xc0000002.

    Updated property 0xc0010001 (0x1) to merge foo.o (0x1) and bar.o (0x1)

    Cela indique que la valeur de la propriété 0xc0010001 est mise à jour à 0x1 dans la sortie lors de la fusion des propriétés dans foo.o, dont la valeur de la propriété 0xc0010001 est 0x1, et bar.o, dont la valeur de la propriété 0xc0010001 est 0x1.

  • Sur certaines cibles ELF, une liste de corrections insérées par --relax 
    foo.o: Adjusting branch at 0x00000008 towards "far" in section .text

    Cela indique que le branchement à l'adresse 0x00000008 dans foo.o, ciblant le symbole « far » dans la section .text, a été remplacé par un trampoline.

    --no-print-map-discarded
    Affiche (ou n'affiche pas) la liste des sections rejetées et collectées par le garbage collector dans la carte de liaison. Activé par défaut.

    --no-print-map-locals

    -n
    --nmagic
    Désactive l'alignement de page des sections et désactive la liaison avec les bibliothèques partagées. Si le format de sortie prend en charge les nombres magiques de style Unix, marque la sortie comme "NMAGIC".
    -N
    --omagic
    Définit les sections de texte et de données comme lisibles et inscriptibles. De plus, n'aligne pas le segment de données sur les pages, et désactive la liaison avec les bibliothèques partagées. Si le format de sortie prend en charge les nombres magiques de style Unix, marque la sortie comme "OMAGIC". Remarque : Bien qu'une section de texte inscriptible soit autorisée pour les cibles PE-COFF, elle n'est pas conforme à la spécification du format publiée par Microsoft.
    --no-omagic
    Cette option annule la plupart des effets de l'option -N. Elle définit la section de texte comme étant en lecture seule, et force le segment de données à être aligné sur les pages. Remarque : cette option n'active pas la liaison avec les bibliothèques partagées. Utilisez -Bdynamic pour cela.
    -o output
    --output=output
    Utilise output comme nom du programme produit par ld ; si cette option n'est pas spécifiée, le nom a.out est utilisé par défaut. La commande de script "OUTPUT" peut également spécifier le nom du fichier de sortie.
    --dependency-file=depfile
    Écrit un fichier de dépendances dans depfile. Ce fichier contient une règle appropriée pour "make" décrivant le fichier de sortie et tous les fichiers d'entrée qui ont été lus pour le produire. La sortie est similaire à la sortie du compilateur avec -M -MP. Notez qu'il n'existe pas d'option comme le -MM du compilateur, pour exclure les « fichiers système » (ce qui n'est pas un concept bien défini dans le lieur, contrairement aux « en-têtes système » dans le compilateur). Ainsi, la sortie de --dependency-file est toujours spécifique à l'état exact de l'installation où elle a été produite, et ne doit pas être copiée dans les makefiles distribués sans édition minutieuse.
    -O level
    Si level est une valeur numérique supérieure à zéro, ld optimise la sortie. Cela peut prendre beaucoup plus de temps et ne devrait donc probablement être activé que pour le binaire final. Pour le moment, cette option n'affecte que la génération de bibliothèques partagées ELF. Les futures versions du lieur pourront utiliser davantage cette option. De plus, il n'y a actuellement aucune différence dans le comportement du lieur pour différentes valeurs non nulles de cette option. Cela peut également changer dans les futures versions.
    -plugin name
    Implique un plugin dans le processus de liaison. Le paramètre name est le nom de fichier absolu du plugin. Généralement, ce paramètre est automatiquement ajouté par le compilateur lors de l'utilisation de l'optimisation au moment de la liaison, mais les utilisateurs peuvent également ajouter leurs propres plugins s'ils le souhaitent.

    Notez que l'emplacement des plugins issus du compilateur est différent de l'endroit où les programmes ar, nm et ranlib recherchent leurs plugins. Pour que ces commandes utilisent un plugin basé sur le compilateur, il doit d'abord être copié dans le répertoire ${libdir}/bfd-plugins. Tous les plugins de lieur basés sur gcc sont rétrocompatibles, il suffit donc de copier le plus récent.

    --push-state
    L'option --push-state permet de préserver l'état actuel des indicateurs qui régissent la gestion des fichiers d'entrée afin qu'ils puissent tous être restaurés avec une option --pop-state correspondante.

    Les options couvertes sont : -Bdynamic, -Bstatic, -dn, -dy, -call_shared, -non_shared, -static, -N, -n, --whole-archive, --no-whole-archive, -r, -Ur, --copy-dt-needed-entries, --no-copy-dt-needed-entries, --as-needed, --no-as-needed, et -a.

    Une cible pour cette option sont les spécifications pour pkg-config. Lorsqu'elle est utilisée avec l'option --libs, toutes les bibliothèques potentiellement nécessaires sont listées puis potentiellement liées à chaque fois. Il est préférable de retourner quelque chose comme suit :

    -Wl,--push-state,--as-needed -libone -libtwo -Wl,--pop-state
    --pop-state
    Annule l'effet de --push-state, restaure les valeurs précédentes des indicateurs régissant la gestion des fichiers d'entrée.
    -q
    --emit-relocs
    Laisse les sections et le contenu de relocalisation dans les exécutables entièrement liés. Les outils d'analyse et d'optimisation post-liaison peuvent avoir besoin de ces informations pour effectuer des modifications correctes des exécutables. Cela entraîne des exécutables plus volumineux.

    Cette option n'est actuellement prise en charge que sur les plateformes ELF.

    --force-dynamic
    Force le fichier de sortie à avoir des sections dynamiques. Cette option est spécifique aux cibles VxWorks.
    -r
    --relocatable
    Génère une sortie relocalisable, c'est-à-dire un fichier de sortie qui peut à son tour servir d'entrée à ld. C'est souvent appelé liaison partielle. Par effet secondaire, dans les environnements qui prennent en charge les nombres magiques Unix standard, cette option définit également le nombre magique du fichier de sortie sur "OMAGIC". Si cette option n'est pas spécifiée, un fichier absolu est produit. Lors de la liaison de programmes C++, cette option ne résout pas les références aux constructeurs ; pour ce faire, utilisez -Ur.

    Lorsqu'un fichier d'entrée n'a pas le même format que le fichier de sortie, la liaison partielle n'est prise en charge que si ce fichier d'entrée ne contient aucune relocalisation. Différents formats de sortie peuvent avoir des restrictions supplémentaires ; par exemple, certains formats basés sur "a.out" ne prennent pas en charge la liaison partielle avec des fichiers d'entrée dans d'autres formats.

    Cette option fait la même chose que -i.

    -R filename
    --just-symbols=filename
    Lit les noms de symboles et leurs adresses à partir de filename, mais ne les relocalise pas et ne les inclut pas dans la sortie. Cela permet à votre fichier de sortie de faire référence symboliquement à des emplacements absolus de mémoire définis dans d'autres programmes. Vous pouvez utiliser cette option plusieurs fois.

    Par compatibilité avec d'autres lieurs ELF, si l'option -R est suivie d'un nom de répertoire, plutôt que d'un nom de fichier, elle est traitée comme l'option -rpath.

    -s
    --strip-all
    Omits toutes les informations de symbole du fichier de sortie.
    -S
    --strip-debug
    Omits les informations de symbole de débogage (mais pas tous les symboles) du fichier de sortie.
    --strip-discarded
    --no-strip-discarded
    Omet (ou n'omet pas) les symboles globaux définis dans les sections rejetées. Activé par défaut.
    -t
    --trace
    Affiche les noms des fichiers d'entrée à mesure que ld les traite. Si -t est donné deux fois, les membres des archives sont également affichés. La sortie de -t est utile pour générer une liste de tous les fichiers objets et scripts impliqués dans la liaison, par exemple, lors de la création de paquets de fichiers pour un rapport de bogue du lieur.
    -T scriptfile
    --script=scriptfile
    Utilise scriptfile comme script de liaison. Ce script remplace le script de liaison par défaut de ld (plutôt que de s'y ajouter), sauf si le script contient "INSERT", donc commandfile doit spécifier tout ce qui est nécessaire pour describe le fichier de sortie. Si scriptfile n'existe pas dans le répertoire courant, "ld" le recherche dans les répertoires spécifiés par les options -L précédentes. Les options -T multiples s'accumulent.
    -dT scriptfile
    --default-script=scriptfile
    Utilise scriptfile comme script de lieur par défaut.

    Cette option est similaire à l'option --script, sauf que le traitement du script est retardé jusqu'après le reste de la ligne de commande. Cela permet aux options placées après l'option --default-script sur la ligne de commande d'affecter le comportement du script de lieur, ce qui peut être important lorsque la ligne de commande du lieur ne peut pas être directement contrôlée par l'utilisateur. (par exemple, parce que la ligne de commande est construite par un autre outil, tel que gcc).

    -u symbole
    --undefined=symbole
    Force l'entrée de symbole dans le fichier de sortie en tant que symbole non défini. Faire cela peut, par exemple, déclencher la liaison de modules supplémentaires à partir des bibliothèques standard. -u peut être répétée avec différents arguments d'option pour entrer des symboles non définis supplémentaires. Cette option est équivalente à la commande de script de lieur "EXTERN".

    Si cette option est utilisée pour forcer l'inclusion de modules supplémentaires dans la liaison, et s'il est erroné que le symbole reste non défini, alors l'option --require-defined doit être utilisée à la place.

    --require-defined=symbole
    Exige que symbole soit défini dans le fichier de sortie. Cette option est la même que l'option --undefined, sauf que si symbole n'est pas défini dans le fichier de sortie, le lieur émettra une erreur et se terminera. Le même effet peut être obtenu dans un script de lieur en utilisant "EXTERN", "ASSERT" et "DEFINED" ensemble. Cette option peut être utilisée plusieurs fois pour exiger des symboles supplémentaires.
    -Ur
    Pour les programmes qui n'utilisent pas de constructeurs ou de destructeurs, ou pour les systèmes basés sur ELF, cette option est équivalente à -r : elle génère une sortie relocalisable, c'est-à-dire un fichier de sortie qui peut à son tour servir d'entrée à ld. Pour d'autres binaires cependant, l'option -Ur est similaire à -r mais elle résout également les références aux constructeurs et destructeurs.

    Pour les systèmes où -r et -Ur se comportent différemment, il ne fonctionne pas d'utiliser -Ur sur des fichiers qui ont eux-mêmes été liés avec -Ur ; une fois la table des constructeurs construite, elle ne peut pas être augmentée. Utilisez -Ur uniquement pour la dernière liaison partielle, et -r pour les autres.

    --orphan-handling=MODE
    Contrôle comment les sections orphelines sont traitées. Une section orpheline est une section qui n'est pas spécifiquement mentionnée dans un script de lieur.

    MODE peut prendre l'une des valeurs suivantes :

    "place"
    Les sections orphelines sont placées dans une section de sortie appropriée en suivant la stratégie décrite dans Sections orphelines. L'option --unique affecte également la manière dont les sections sont placées.
    "discard"
    Toutes les sections orphelines sont écartées, en les plaçant dans la section /DISCARD/.
    "warn"
    Le lieur placera la section orpheline comme pour "place" et émettra également un avertissement.
    "error"
    Le lieur se terminera avec une erreur si une section orpheline est trouvée.

    La valeur par défaut si --orphan-handling n'est pas donnée est "place".

    --unique[=SECTION]
    Crée une section de sortie séparée pour chaque section d'entrée correspondant à SECTION, ou si l'argument générique facultatif SECTION est manquant, pour chaque section d'entrée orpheline. Une section orpheline est une section qui n'est pas spécifiquement mentionnée dans un script de lieur. Vous pouvez utiliser cette option plusieurs fois sur la ligne de commande ; elle empêche la fusion normale des sections d'entrée portant le même nom, remplaçant les affectations de sections de sortie dans un script de lieur.

    -z mot-clé
    Les mots-clés reconnus sont :
    call-nop=prefix-addr
    call-nop=suffix-nop
    call-nop=prefix-byte
    call-nop=suffix-byte
    Spécifie le remplissage "NOP" d'1 octet lors de la transformation d'un appel indirect vers une fonction définie localement, foo, via son slot GOT. call-nop=prefix-addr génère "0x67 call foo". call-nop=suffix-nop génère "call foo 0x90". call-nop=prefix-byte génère "byte call foo". call-nop=suffix-byte génère "call foo byte".     cet-report=none
    cet-report=warning
    cet-report=error
    Spécifie comment signaler les propriétés manquantes GNU_PROPERTY_X86_FEATURE_1_IBT et GNU_PROPERTY_X86_FEATURE_1_SHSTK dans la section d'entrée .note.gnu.property. cet-report=none, qui est la valeur par défaut, fait que le lieur ne signale pas les propriétés manquantes dans les fichiers d'entrée. cet-report=warning fait que le lieur émet un avertissement pour les propriétés manquantes dans les fichiers d'entrée. cet-report=error fait que le lieur émet une erreur pour les propriétés manquantes dans les fichiers d'entrée. Notez que ibt désactivera le rapport de propriété GNU_PROPERTY_X86_FEATURE_1_IBT manquante et shstk désactivera le rapport de propriété GNU_PROPERTY_X86_FEATURE_1_SHSTK manquante. Pris en charge pour Linux/i386 et Linux/x86_64.
    combreloc
    nocombreloc
    Combine plusieurs sections de relocalisation dynamiques et les trie pour améliorer la mise en cache de la recherche de symboles dynamiques. Ne pas le faire si nocombreloc.
    common
    nocommon
    Génère des symboles communs de type STT_COMMON lors d'une liaison relocalisable. Utilise le type STT_OBJECT si nocommon.
    common-page-size=valeur
    Définit la taille de page la plus couramment utilisée à valeur. La disposition de l'image mémoire sera optimisée pour minimiser les pages mémoire si le système utilise des pages de cette taille.
    defs
    Signale les références de symboles non résolues provenant de fichiers objets réguliers. Ceci est fait même si le lieur crée une bibliothèque partagée non symbolique. Cette option est l'inverse de -z undefs.
    dynamic-undefined-weak
    nodynamic-undefined-weak
    Rend les symboles faibles non définis dynamiques lors de la construction d'un objet dynamique, s'ils sont référencés à partir d'un fichier objet régulier et ne sont pas forcés locaux par visibilité de symbole ou versioning. Ne les rend pas dynamiques si nodynamic-undefined-weak. Si aucune des deux options n'est donnée, une cible peut utiliser par défaut l'une ou l'autre option, ou faire un autre choix de symboles faibles non définis comme dynamiques. Toutes les cibles ne prennent pas en charge ces options.
    execstack
    Marque l'objet comme nécessitant une pile exécutable.
    global
    Cette option n'est significative que lors de la construction d'un objet partagé. Elle rend les symboles définis par cet objet partagé disponibles pour la résolution de symboles des bibliothèques chargées ultérieurement.
    globalaudit
    Cette option n'est significative que lors de la construction d'un exécutable dynamique. Elle marque l'exécutable comme nécessitant une auditabilité globale en définissant le bit "DF_1_GLOBAUDIT" dans le "DT_FLAGS
    _1" balise dynamique. L'audit global exige que toute bibliothèque d'audit définie via les options de ligne de commande --depaudit ou -P soit exécutée pour tous les objets dynamiques chargés par l'application.
    ibtplt
    Génère des entrées PLT compatibles avec Intel Indirect Branch Tracking (IBT). Pris en charge pour Linux/i386 et Linux/x86_64.
    ibt

    indirect-extern-access
    noindirect-extern-access
    Génère GNU_PROPERTY_1_NEEDED_INDIRECT_EXTERN_ACCESS dans la section .note.gnu.property pour indiquer que le fichier objet nécessite des pointeurs de fonction canoniques et ne peut pas être utilisé avec la relocalisation de copie.     initfirst
    Cette option n'est significative que lors de la création d'un objet partagé. Elle marque l'objet de sorte que son initialisation à l'exécution se produise avant l'initialisation à l'exécution de tout autre objet introduit dans le processus au même moment. De même, la finalisation à l'exécution de l'objet se produira après la finalisation à l'exécution de tout autre objet.
    interpose
    Spécifie que le chargeur dynamique doit modifier son ordre de recherche de symboles de sorte que les symboles de cette bibliothèque partagée s'interposent à toutes les autres bibliothèques partagées non marquées de cette manière.
    unique
    nounique
    Lors de la création d'une bibliothèque partagée ou d'un autre objet ELF chargeable dynamiquement, il est marqué comme ne devant (par défaut) être chargé qu'une seule fois, et uniquement dans l'espace de noms principal (lors de l'utilisation de "dlmopen"). Ceci est principalement utilisé pour marquer des bibliothèques fondamentales telles que libc, libpthread et autres, qui ne fonctionnent généralement pas correctement à moins d'être les seules instances d'elles-mêmes. Ce comportement peut être annulé par l'appelant "dlmopen" et ne s'applique pas à certains mécanismes de chargement (tels que les bibliothèques d'audit).

    -( archives -)
    --start-group archives --end-group
    Les archives doivent être une liste de fichiers archive. Ils peuvent être soit des noms de fichiers explicites, soit des options -l.

    Les archives spécifiées sont recherchées de manière répétée jusqu'à ce qu'aucune nouvelle référence non résolue ne soit créée. Normalement, une archive n'est recherchée qu'une seule fois dans l'ordre où elle est spécifiée sur la ligne de commande. Si un symbole de cette archive est nécessaire pour résoudre un symbole non résolu référencé par un objet dans une archive qui apparaît plus tard dans la ligne de commande, l'éditeur de liens ne pourrait pas résoudre cette référence. En groupant les archives, elles seront toutes recherchées de manière répétée jusqu'à ce que toutes les références possibles soient résolues.

    L'utilisation de cette option a un coût de performance significatif. Il est préférable de l'utiliser uniquement lorsqu'il existe des références circulaires inévitables entre deux ou plusieurs archives.

    --as-needed
    --no-as-needed
    Cette option affecte les étiquettes DT_NEEDED ELF pour les bibliothèques dynamiques mentionnées sur la ligne de commande après l'option --as-needed. Normalement, l'éditeur de liens ajoutera une étiquette DT_NEEDED pour chaque bibliothèque dynamique mentionnée sur la ligne de commande, qu'elle soit réellement nécessaire ou non. --as-needed fait en sorte qu'une étiquette DT_NEEDED ne soit émise que pour une bibliothèque qui, à ce stade de la liaison, satisfait une référence de symbole non faible non résolu provenant d'un fichier objet régulier ou, si la bibliothèque n'est pas trouvée dans les listes DT_NEEDED d'autres bibliothèques nécessaires, une référence de symbole non faible non résolu provenant d'une autre bibliothèque dynamique nécessaire. Les fichiers objets ou les bibliothèques apparaissant sur la ligne de commande après la bibliothèque en question n'affectent pas si la bibliothèque est considérée comme nécessaire. Ceci est similaire aux règles d'extraction de fichiers objets des archives. --no-as-needed restaure le comportement par défaut.

    --cref
    Produire une table de références croisées. Si un fichier de carte de l'éditeur de liens est généré, la table de références croisées est imprimée dans le fichier de carte. Sinon, elle est imprimée sur la sortie standard.

    Le format de la table est intentionnellement simple, afin qu'il puisse être facilement traité par un script si nécessaire. Les symboles sont imprimés, triés par nom. Pour chaque symbole, une liste de noms de fichiers est donnée. Si le symbole est défini, le premier fichier listé est l'emplacement de la définition. Si le symbole est défini comme une valeur commune, alors tous les fichiers où cela se produit apparaissent ensuite. Enfin, tous les fichiers qui référencent le symbole sont listés.

    --ctf-variables
    --no-ctf-variables
    Le format d'informations de débogage CTF prend en charge une section qui encode les noms et les types de variables trouvées dans le programme qui n'apparaissent dans aucune table de symboles. Ces variables ne peuvent clairement pas être recherchées par adresse par les débogueurs conventionnels, de sorte que l'espace utilisé pour leurs types et noms est généralement perdu : les types sont généralement petits mais les noms ne le sont souvent pas. --ctf-variables provoque la génération d'une telle section. Le comportement par défaut peut être rétabli avec --no-ctf-variables.

    share-unconflicted

Les types avec des définitions ambiguës dans plusieurs unités de traduction vont toujours dans des dictionnaires par unité de traduction. Cela a tendance à rendre le CTF plus grand, mais peut réduire la quantité de CTF dans le dictionnaire partagé. Pour les projets très volumineux, cela peut accélérer l'ouverture du CTF et économiser de la mémoire dans le consommateur de CTF à l'exécution.

    Cette option inhibe l'attribution d'adresses aux symboles communs. La commande de script "INHIBIT_COMMON_ALLOCATION" a le même effet.

    L'option --no-define-common permet de découpler la décision d'attribuer des adresses aux symboles communs du choix du type de fichier de sortie ; sinon, un type de sortie non déplaçable force l'attribution d'adresses aux symboles communs. L'utilisation de --no-define-common permet aux symboles communs référencés à partir d'une bibliothèque partagée de se voir attribuer des adresses uniquement dans le programme principal. Cela élimine l'espace dupliqué inutilisé dans la bibliothèque partagée, et empêche également toute confusion possible lors de la résolution vers le mauvais doublon lorsqu'il existe plusieurs modules dynamiques avec des chemins de recherche spécialisés pour la résolution des symboles à l'exécution.

C'est le comportement par défaut pour un lien final, mais cette option peut être utilisée pour modifier le comportement d'un lien déplaçable (-r). La commande de script "FORCE_GROUP_ALLOCATION" a le même effet.
    --defsym=symbole=expression
    Crée un symbole global dans le fichier de sortie, contenant l'adresse absolue donnée par expression. Vous pouvez utiliser cette option autant de fois que nécessaire pour définir plusieurs symboles dans la ligne de commande. Une forme limitée d'arithmétique est prise en charge pour l'expression dans ce contexte : vous pouvez donner une constante hexadécimale ou le nom d'un symbole existant, ou utiliser "+" et "-" pour ajouter ou soustraire des constantes ou des symboles hexadécimaux. Si vous avez besoin d'expressions plus élaborées, envisagez d'utiliser le langage de commande de l'éditeur de liens à partir d'un script. Note : il ne doit pas y avoir d'espace blanc entre symbole, le signe égal ("="), et expression.

    L'éditeur de liens traite les arguments --defsym et -T dans l'ordre, plaçant --defsym avant -T définira le symbole avant que le script de l'éditeur de liens de -T ne soit traité, tandis que placer --defsym après -T définira le symbole après que le script de l'éditeur de liens ait été traité. Cette différence a des conséquences pour les expressions dans le script de l'éditeur de liens qui utilisent les symboles --defsym, l'ordre correct dépendra de ce que vous essayez d'accomplir.

    --demangle[=style]

Lorsque l'éditeur de liens est invité à démêler, il essaie de présenter les noms de symboles de manière lisible : il supprime les traits de soulignement initiaux s'ils sont utilisés par le format de fichier objet et convertit les noms de symboles C++ "manglés" en noms lisibles par l'utilisateur. Différents compilateurs ont des styles de "mangling" différents. L'argument optionnel de style de démêlage peut être utilisé pour choisir un style de démêlage approprié pour votre compilateur. L'éditeur de liens démêlera par défaut, sauf si la variable d'environnement COLLECT_NO_DEMANGLE est définie. Ces options peuvent être utilisées pour outrepasser le comportement par défaut.

    --no-warnings
    Ne pas afficher de messages d'avertissement ou d'erreur. Cela remplace --fatal-warnings s'il a été activé. Cette option peut être utilisée lorsqu'il est connu que le binaire de sortie ne fonctionnera pas, mais qu'il est toujours nécessaire de le créer.
    --force-exe-suffix
    S'assurer qu'un fichier de sortie a un suffixe .exe.

    Si un fichier de sortie entièrement lié et construit avec succès n'a pas de suffixe ".exe" ou ".dll", cette option force l'éditeur de liens à copier le fichier de sortie vers un autre fichier du même nom avec un suffixe ".exe". Cette option est utile lors de l'utilisation de makefiles Unix non modifiés sur un hôte Microsoft Windows, car certaines versions de Windows n'exécuteront pas une image sauf si elle se termine par un suffixe ".exe".

    --gc-sections
    --no-gc-sections
    Activer la collecte des sections d'entrée inutilisées. Elle est ignorée sur les cibles qui ne prennent pas en charge cette option. Le comportement par défaut (ne pas effectuer cette collecte) peut être restauré en spécifiant --no-gc-sections dans la ligne de commande. Notez que la collecte pour les cibles au format COFF et PE est prise en charge, mais l'implémentation est actuellement considérée comme expérimentale.

    --gc-sections décide quelles sections d'entrée sont utilisées en examinant les symboles et les relocations. La section contenant le symbole d'entrée et toutes les sections contenant des symboles indéfinis dans la ligne de commande seront conservées, tout comme les sections contenant des symboles référencés par des objets dynamiques. Notez que lors de la construction de bibliothèques partagées, l'éditeur de liens doit supposer que tout symbole visible est référencé. Une fois cet ensemble initial de sections déterminé, l'éditeur de liens marque récursivement comme utilisées toutes les sections référencées par leurs relocations. Voir --entry, --undefined et --gc-keep-exported.

    Cette option peut être définie lors d'une liaison partielle (activée avec l'option -r). Dans ce cas, la racine des symboles conservés doit être explicitement spécifiée soit par l'une des options --entry, --undefined ou --gc-keep-exported, soit par une commande "ENTRY" dans le script de l'éditeur de liens.

    En tant qu'extension GNU, les sections d'entrée ELF marquées avec le drapeau "SHF_GNU_RETAIN" ne seront pas collectées.

    --print-gc-sections
    --no-print-gc-sections
    Lister toutes les sections supprimées par la collecte. La liste est imprimée sur stderr. Cette option n'est effective que si la collecte a été activée via l'option --gc-sections. Le comportement par défaut (ne pas lister les sections supprimées) peut être restauré en spécifiant --no-print-gc-sections dans la ligne de commande.
    --gc-keep-exported
    Lorsque --gc-sections est activé, cette option empêche la collecte des sections d'entrée inutilisées contenant des symboles globaux ayant une visibilité par défaut ou protégée. Cette option est destinée à être utilisée pour les exécutables où les sections non référencées seraient autrement collectées, quelle que soit la visibilité externe des symboles contenus. Notez que cette option n'a aucun effet lors de la liaison d'objets partagés, car c'est déjà le comportement par défaut. Cette option n'est prise en charge que pour les cibles au format ELF.
    --print-output-format
    Afficher le nom du format de sortie par défaut (éventuellement influencé par d'autres options de ligne de commande). C'est la chaîne qui apparaîtrait dans une commande de script d'éditeur de liens "OUTPUT_FORMAT".
    --print-memory-usage
    Afficher la taille utilisée, la taille totale et la taille utilisée des régions mémoire créées avec la commande MEMORY. C'est utile sur les cibles embarquées pour avoir une vue rapide de la quantité de mémoire libre. Le format de la sortie comporte une ligne d'en-tête et une ligne par région. Il est à la fois lisible par l'homme et facilement analysable par les outils. Voici un exemple de sortie : 
    Région mémoire       Taille utilisée  Taille de la région  % utilisée
             ROM:        256 Ko         1 Mo     25.00%
             RAM:          32 B         2 Go      0.00%
    --help
    Afficher un résumé des options de ligne de commande sur la sortie standard et quitter.
    --target-help
    Afficher un résumé de toutes les options spécifiques à la cible sur la sortie standard et quitter.
    -Map=fichier_map
    Afficher une carte de liaison dans le fichier fichier_map. Voir la description de l'option -M, ci-dessus. Si fichier_map est juste le caractère "-", la carte sera écrite sur stdout.

    Spécifier un répertoire comme fichier_map entraîne l'écriture de la carte de l'éditeur de liens dans un fichier à l'intérieur du répertoire. Normalement, le nom du fichier à l'intérieur du répertoire est calculé comme la partie de base du nom du fichier de sortie avec ".map" ajouté. Si cependant le caractère spécial "%" est utilisé, il sera remplacé par le chemin complet du fichier de sortie. De plus, s'il y a des caractères après le symbole "%", alors ".map" ne sera plus ajouté.

    -o foo.exe -Map=bar                  [Crée ./bar]
-o ../dir/foo.exe -Map=bar           [Crée ./bar]
-o foo.exe -Map=../dir               [Crée ../dir/foo.exe.map]
-o ../dir2/foo.exe -Map=../dir       [Crée ../dir/foo.exe.map]
-o foo.exe -Map=%                    [Crée ./foo.exe.map]
-o ../dir/foo.exe -Map=%             [Crée ../dir/foo.exe.map]
-o foo.exe -Map=%.bar                [Crée ./foo.exe.bar]
-o ../dir/foo.exe -Map=%.bar         [Crée ../dir/foo.exe.bar]
-o ../dir2/foo.exe -Map=../dir/%     [Crée ../dir/../dir2/foo.exe.map]
-o ../dir2/foo.exe -Map=../dir/%.bar [Crée ../dir/../dir2/foo.exe.bar]

    Il est interdit de spécifier plus d'un caractère "%".

    Si le fichier carte existe déjà, il sera écrasé par cette opération.

    --no-keep-memory
    ld optimise normalement pour la vitesse plutôt que pour l'utilisation de la mémoire en mettant en cache les tables de symboles des fichiers d'entrée en mémoire. Cette option indique à ld d'optimiser plutôt pour l'utilisation de la mémoire, en relisant les tables de symboles si nécessaire. Cela peut être requis si ld manque d'espace mémoire lors de la liaison d'un grand exécutable.
    --no-undefined
    -z defs
    Signaler les références de symboles non résolues provenant des fichiers objets réguliers. Ceci est fait même si l'éditeur de liens crée une bibliothèque partagée non symbolique. Le commutateur --[no-]allow-shlib-undefined contrôle le comportement pour signaler les références non résolues trouvées dans les bibliothèques partagées en cours de liaison.

    Les effets de cette option peuvent être annulés en utilisant "-z undefs".

    --allow-multiple-definition
    -z muldefs
    Normalement, lorsqu'un symbole est défini plusieurs fois, l'éditeur de liens signalera une erreur fatale. Ces options autorisent plusieurs définitions et la première définition sera utilisée.
    --allow-shlib-undefined
    --no-allow-shlib-undefined
    Autorise ou interdit les symboles indéfinis dans les bibliothèques partagées. Ce commutateur est similaire à --no-undefined, sauf qu'il détermine le comportement lorsque les symboles indéfinis se trouvent dans une bibliothèque partagée plutôt que dans un fichier objet régulier. Il n'affecte pas la manière dont les symboles indéfinis dans les fichiers objets réguliers sont gérés.

    Le comportement par défaut est de signaler les erreurs pour tout symbole indéfini référencé dans les bibliothèques partagées si l'éditeur de liens est utilisé pour créer un exécutable, mais de les autoriser si l'éditeur de liens est utilisé pour créer une bibliothèque partagée.

    Les raisons pour autoriser les références de symboles indéfinis dans les bibliothèques partagées spécifiées au moment de la liaison sont que :

    • Une bibliothèque partagée spécifiée au moment de la liaison peut ne pas être la même que celle qui est disponible au moment du chargement, de sorte que le symbole peut en fait être résoluble au moment du chargement.
    • Il existe certains systèmes d'exploitation, par exemple BeOS et HPPA, où les symboles indéfinis dans les bibliothèques partagées sont normaux.

      Le noyau BeOS, par exemple, patch les bibliothèques partagées au moment du chargement pour sélectionner la fonction la plus appropriée à l'architecture actuelle. Ceci est utilisé, par exemple, pour sélectionner dynamiquement une fonction memset appropriée.

    --error-handling-script=nom_script
    Si cette option est fournie, l'éditeur de liens invoquera nom_script chaque fois qu'une erreur est rencontrée. Actuellement, seuls deux types d'erreurs sont pris en charge : symboles manquants et bibliothèques manquantes. Deux arguments seront passés au script : le mot-clé "undefined-symbol" ou "missing-lib" et le nom du symbole indéfini ou de la bibliothèque manquante. L'intention est que le script fournisse des suggestions à l'utilisateur quant à l'endroit où le symbole ou la bibliothèque pourrait être trouvée. Une fois le script terminé, le message d'erreur normal de l'éditeur de liens sera affiché.

    La disponibilité de cette option est contrôlée par un commutateur de configuration, elle peut donc ne pas être présente dans certaines implémentations spécifiques.

    --no-undefined-version
    Normalement, lorsqu'un symbole a une version indéfinie, l'éditeur de liens l'ignore. Cette option interdit les symboles avec une version indéfinie et une erreur fatale sera émise à la place.
    --default-symver
    Créer et utiliser une version de symbole par défaut (le soname) pour les symboles exportés non versionnés.
    --no-shared-lib
    Ne pas lier avec des bibliothèques partagées. L'éditeur de liens tentera de résoudre tous les symboles en utilisant des fichiers objets statiques ou des bibliothèques statiques. Le comportement par défaut peut être rétabli en spécifiant --shared-lib.
    --shared-lib
    dt id="default~3">--default-imported-symver
    Crée et utilise une version de symbole par défaut (le soname) pour les symboles importés non versionnés.
    --no-warn-mismatch
    Normalement, ld génère une erreur si vous essayez de lier ensemble des fichiers d'entrée qui sont incompatibles pour une raison quelconque, par exemple parce qu'ils ont été compilés pour des processeurs différents ou pour des endiannesses différentes. Cette option indique à ld qu'il doit autoriser silencieusement de telles erreurs potentielles. Cette option ne doit être utilisée qu'avec précaution, dans les cas où vous avez pris des mesures spéciales qui garantissent que les erreurs du lieur sont inappropriées.
    --no-warn-search-mismatch
    Normalement, ld émet un avertissement s'il trouve une bibliothèque incompatible lors d'une recherche de bibliothèque. Cette option supprime l'avertissement.
    --no-whole-archive
    Désactive l'effet de l'option --whole-archive pour les fichiers d'archive suivants.
    --noinhibit-exec
    Conserve le fichier de sortie exécutable tant qu'il est encore utilisable. Normalement, le lieur ne produit pas de fichier de sortie s'il rencontre des erreurs pendant le processus de liaison ; il se termine sans écrire de fichier de sortie lorsqu'il émet une erreur quelconque.
    -nostdlib
    Ne recherche les répertoires de bibliothèques que ceux explicitement spécifiés sur la ligne de commande. Les répertoires de bibliothèques spécifiés dans les scripts de lieur (y compris les scripts de lieur spécifiés sur la ligne de commande) sont ignorés.
    --oformat=format-sortie
    ld peut être configuré pour prendre en charge plus d'un type de fichier objet. Si votre ld est configuré de cette manière, vous pouvez utiliser l'option --oformat pour spécifier le format binaire du fichier objet de sortie. Même lorsque ld est configuré pour prendre en charge des formats d'objets alternatifs, vous n'avez généralement pas besoin de le spécifier, car ld doit être configuré pour produire en tant que format de sortie par défaut le format le plus courant sur chaque machine. format-sortie est une chaîne de caractères, le nom d'un format particulier pris en charge par les bibliothèques BFD. (Vous pouvez lister les formats binaires disponibles avec objdump -i.) La commande de script "OUTPUT_FORMAT" peut également spécifier le format de sortie, mais cette option la remplace.
    --out-implib fichier
    Crée une bibliothèque d'importation dans fichier correspondant à l'exécutable que le lieur génère (par exemple, un programme DLL ou ELF). Cette bibliothèque d'importation (qui devrait s'appeler "*.dll.a" ou "*.a" pour les DLL) peut être utilisée pour lier des clients à l'exécutable généré ; ce comportement permet d'éviter une étape distincte de création de bibliothèque d'importation (par exemple, "dlltool" pour les DLL). Cette option n'est disponible que pour les ports du lieur ciblant i386 PE et ELF.
    -pie
    --pic-executable
    Crée un exécutable indépendant de la position. Ceci n'est actuellement pris en charge que sur les plateformes ELF. Les exécutables indépendants de la position sont similaires aux bibliothèques partagées en ce sens qu'ils sont déplacés par le lieur dynamique à l'adresse virtuelle que le système d'exploitation leur choisit (ce qui peut varier entre les invocations). Comme les exécutables liés dynamiquement normaux, ils peuvent être exécutés et les symboles définis dans l'exécutable ne peuvent pas être remplacés par des bibliothèques partagées.
    -no-pie
    Crée un exécutable dépendant de la position. C'est le comportement par défaut.
    -qmagic
    Cette option est ignorée pour la compatibilité Linux.
    -Qy
    Cette option est ignorée pour la compatibilité SVR4.
    --relax
    --no-relax
    Une option avec des effets dépendants de la machine. Cette option n'est prise en charge que sur quelques cibles.

    Sur certaines plateformes, l'option --relax effectue des optimisations globales spécifiques à la cible qui deviennent possibles lorsque le lieur résout l'adressage dans le programme, telles que le relâchement des modes d'adresse, la synthèse de nouvelles instructions, la sélection de versions plus courtes des instructions actuelles et la combinaison de valeurs constantes.

    Sur certaines plateformes, ces optimisations globales au moment de la liaison peuvent rendre le débogage symbolique de l'exécutable résultant impossible. C'est le cas connu pour la famille de processeurs Matsushita MN10200 et MN10300.

    Sur les plateformes où la fonctionnalité est prise en charge, l'option --no-relax la désactive.

    Sur les plateformes où la fonctionnalité n'est pas prise en charge, --relax et --no-relax sont acceptés, mais ignorés.

    --retain-symbols-file=nom-fichier
    Conserve *uniquement* les symboles listés dans le fichier nom-fichier, en rejetant tous les autres. nom-fichier est simplement un fichier plat, avec un nom de symbole par ligne. Cette option est particulièrement utile dans les environnements (comme VxWorks) où une grande table de symboles globale est accumulée progressivement, afin de préserver la mémoire d'exécution.

    --retain-symbols-file ne rejette *pas* les symboles indéfinis, ni les symboles nécessaires aux relocations.

    Vous ne pouvez spécifier --retain-symbols-file qu'une seule fois sur la ligne de commande. Elle remplace -s et -S.

    -rpath=rep
    Ajoute un répertoire au chemin de recherche des bibliothèques d'exécution. Ceci est utilisé lors de la liaison d'un exécutable ELF avec des objets partagés. Tous les arguments -rpath sont concaténés et passés au lieur d'exécution, qui les utilise pour localiser les objets partagés au moment de l'exécution.

    L'option -rpath est également utilisée lors de la localisation des objets partagés requis par des objets partagés inclus explicitement dans la liaison ; voir la description de l'option -rpath-link. La recherche de -rpath de cette manière n'est prise en charge que par les lieurs natifs et les lieurs croisés qui ont été configurés avec l'option --with-sysroot.

    Si -rpath n'est pas utilisé lors de la liaison d'un exécutable ELF, le contenu de la variable d'environnement "LD_RUN_PATH" sera utilisé s'il est défini.

    L'option -rpath peut également être utilisée sur SunOS. Par défaut, sur SunOS, le lieur forme un chemin de recherche d'exécution à partir de toutes les options -L qui lui sont fournies. Si une option -rpath est utilisée, le chemin de recherche d'exécution sera formé exclusivement en utilisant les options -rpath, ignorant les options -L. Cela peut être utile lors de l'utilisation de gcc, qui ajoute de nombreuses options -L qui peuvent se trouver sur des systèmes de fichiers montés NFS.

    Pour la compatibilité avec d'autres lisseurs ELF, si l'option -R est suivie d'un nom de répertoire, plutôt que d'un nom de fichier, elle est traitée comme l'option -rpath.

    -rpath-link=rep
    Lors de l'utilisation d'ELF ou de SunOS, une bibliothèque partagée peut en nécessiter une autre. Cela se produit lorsque une liaison "ld -shared" inclut une bibliothèque partagée comme l'un des fichiers d'entrée.

    Lorsque le lieur rencontre une telle dépendance lors d'une liaison non partagée et non déplaçable, il essaie automatiquement de localiser la bibliothèque partagée requise et de l'inclure dans la liaison, si elle n'est pas incluse explicitement. Dans un tel cas, l'option -rpath-link spécifie le premier ensemble de répertoires à rechercher. L'option -rpath-link peut spécifier une séquence de noms de répertoires soit en spécifiant une liste de noms séparés par des deux-points, soit en apparaissant plusieurs fois.

    Les jetons $ORIGIN et $LIB peuvent apparaître dans ces répertoires de recherche. Ils seront remplacés par le chemin complet du répertoire contenant le programme ou l'objet partagé dans le cas de $ORIGIN et soit lib - pour les binaires 32 bits - soit lib64 - pour les binaires 64 bits - dans le cas de $LIB.

    La forme alternative de ces jetons - ${ORIGIN} et ${LIB} - peut également être utilisée. Le jeton $PLATFORM n'est pas pris en charge.

    Cette option doit être utilisée avec prudence car elle remplace le chemin de recherche qui aurait pu être codé en dur dans une bibliothèque partagée. Dans un tel cas, il est possible d'utiliser involontairement un chemin de recherche différent de celui que le lieur d'exécution utiliserait.

    Le lieur utilise les chemins de recherche suivants pour localiser les bibliothèques partagées requises :

    1.
    Tous les répertoires spécifiés par les options -rpath-link.
    2.
    Tous les répertoires spécifiés par les options -rpath. La différence entre -rpath et -rpath-link est que les répertoires spécifiés par les options -rpath sont inclus dans l'exécutable et utilisés au moment de l'exécution, tandis que l'option -rpath-link n'est effective qu'au moment de la liaison. La recherche de -rpath de cette manière n'est prise en charge que par les lieurs natifs et les lieurs croisés qui ont été configurés avec l'option --with-sysroot.
    3.
    Sur un système ELF, pour les lieurs natifs, si les options -rpath et -rpath-link n'ont pas été utilisées, rechercher le contenu de la variable d'environnement "LD_RUN_PATH".
    4.
    Sur SunOS, si l'option -rpath n'a pas été utilisée, rechercher tous les répertoires spécifiés à l'aide des options -L.
    5.
    Pour un lieur natif, rechercher le contenu de la variable d'environnement "LD_LIBRARY_PATH".
    6.
    Pour un lieur ELF natif, les répertoires dans "DT_RUNPATH" ou "DT_RPATH" d'une bibliothèque partagée sont recherchés pour les bibliothèques partagées dont elle a besoin. Les entrées "DT_RPATH" sont ignorées si des entrées "DT_RUNPATH" existent.
    7.
    Pour un lieur pour un système Linux, si le fichier /etc/ld.so.conf existe, la liste des répertoires trouvés dans ce fichier. Note : le chemin vers ce fichier est précédé de la valeur "sysroot", si elle est définie, puis de toute chaîne "prefix" si le lieur a été configuré avec le
    --prefix=<chemin> option.
    8.
    Pour un éditeur de liens natif sur un système FreeBSD, tous les répertoires spécifiés par la macro "_PATH_ELF_HINTS" définie dans le fichier d'en-tête elf-hints.h.
    9.
    Tous les répertoires spécifiés par une commande "SEARCH_DIR" dans un script d'éditeur de liens donné sur la ligne de commande, y compris les scripts spécifiés par -T (mais pas -dT).
    10.
    Les répertoires par défaut, normalement /lib et /usr/lib.
    11.
    Tous les répertoires spécifiés par un plugin LDPT_SET_EXTRA_LIBRARY_PATH.
    12.
    Tous les répertoires spécifiés par une commande "SEARCH_DIR" dans un script d'éditeur de liens par défaut.

    Notez cependant que sur les systèmes basés sur Linux, il existe une mise en garde supplémentaire : Si l'option --as-needed est active et qu'une bibliothèque partagée est trouvée qui satisferait normalement la recherche et que cette bibliothèque n'a pas de balise DT_NEEDED pour libc.so et qu'il existe une bibliothèque partagée plus loin dans l'ensemble des répertoires de recherche qui satisfait également la recherche et que cette seconde bibliothèque partagée a une balise DT_NEEDED pour libc.so, alors la seconde bibliothèque sera sélectionnée à la place de la première.

    Si la bibliothèque partagée requise n'est pas trouvée, l'éditeur de liens émettra un avertissement et poursuivra la liaison.

    -Bshareable

    --sort-common

Les alignements de symboles considérés sont de seize octets ou plus, huit octets, quatre octets, deux octets et un octet. Ceci est fait pour éviter les écarts entre les symboles dus aux contraintes d'alignement. Si aucun ordre de tri n'est spécifié, alors l'ordre décroissant est présumé.

    --split-by-reloc[=nombre]
    Tente de créer des sections supplémentaires dans le fichier de sortie de sorte qu'aucune section de sortie unique dans le fichier ne contienne plus de nombre relocations. Ceci est utile lors de la génération de fichiers relocalisables volumineux pour le téléchargement dans certains noyaux temps réel avec le format de fichier objet COFF ; car COFF ne peut pas représenter plus de 65535 relocations dans une seule section. Notez que cela échouera avec les formats de fichiers objet qui ne supportent pas les sections arbitraires. L'éditeur de liens ne divisera pas les sections d'entrée individuelles pour redistribution, donc si une seule section d'entrée contient plus de nombre relocations, une section de sortie contiendra ce nombre de relocations. nombre a pour valeur par défaut 32768.
    --stats
    Calcule et affiche des statistiques sur le fonctionnement de l'éditeur de liens, telles que le temps d'exécution et l'utilisation de la mémoire.
    --sysroot=répertoire
    Utilise répertoire comme emplacement du sysroot, remplaçant la valeur par défaut configurée lors de la compilation. Cette option n'est supportée que par les éditeurs de liens qui ont été configurés à l'aide de --with-sysroot.
    --task-link
    Ceci est utilisé par les cibles basées sur COFF/PE pour créer un fichier objet lié par tâche où tous les symboles globaux ont été convertis en statiques.
    --traditional-format
    Pour certaines cibles, la sortie de ld diffère à certains égards de celle de certains éditeurs de liens existants. Ce commutateur demande à ld d'utiliser le format traditionnel à la place.

    Par exemple, sur SunOS, ld combine les entrées dupliquées dans la table des chaînes de symboles. Cela peut réduire la taille d'un fichier de sortie avec des informations de débogage complètes de plus de 30 %. Malheureusement, le programme "dbx" de SunOS ne peut pas lire le programme résultant ("gdb" n'a aucun problème). Le commutateur --traditional-format indique à ld de ne pas combiner les entrées dupliquées.

    --section-start=nomsection=origine
    Localise une section dans le fichier de sortie à l'adresse absolue donnée par origine. Vous pouvez utiliser cette option autant de fois que nécessaire pour localiser plusieurs sections dans la ligne de commande. origine doit être un entier hexadécimal unique ; pour la compatibilité avec d'autres éditeurs de liens, vous pouvez omettre le préfixe 0x généralement associé aux valeurs hexadécimales. Note : il ne doit pas y avoir d'espace blanc entre nomsection, le signe égal ("="), et origine.
    -Tbss=origine
    -Tdata=origine
    -Ttext=origine
    Identique à --section-start, avec ".bss", ".data" ou ".text" comme nomsection.
    -Ttext-segment=origine
    Lors de la création d'un exécutable ELF, cela définit l'adresse du premier octet du segment de texte.
    -Trodata-segment=origine
    Lors de la création d'un exécutable ELF ou d'un objet partagé pour une cible où les données en lecture seule se trouvent dans leur propre segment séparé du texte exécutable, cela définit l'adresse du premier octet du segment de données en lecture seule.
    -Tldata-segment=origine
    Lors de la création d'un exécutable ELF ou d'un objet partagé pour le modèle de mémoire moyenne x86-64, cela définit l'adresse du premier octet du segment ldata.
    --unresolved-symbols=méthode
    Détermine comment gérer les symboles non résolus. Il existe quatre valeurs possibles pour méthode :
    ignore-all
    Ne signale aucun symbole non résolu.
    report-all
    Signale tous les symboles non résolus. C'est la valeur par défaut.
    ignore-in-object-files
    Signale les symboles non résolus contenus dans les bibliothèques partagées, mais les ignore s'ils proviennent de fichiers objets réguliers.
    ignore-in-shared-libs
    Signale les symboles non résolus provenant de fichiers objets réguliers, mais les ignore s'ils proviennent de bibliothèques partagées. Cela peut être utile lors de la création d'une binaire dynamique et qu'il est connu que toutes les bibliothèques partagées qu'elle devrait référencer sont incluses dans la ligne de commande de l'éditeur de liens.

    Le comportement pour les bibliothèques partagées seules peut également être contrôlé par l'option --[no-]allow-shlib-undefined.

    Normalement, l'éditeur de liens générera un message d'erreur pour chaque symbole non résolu signalé, mais l'option --warn-unresolved-symbols peut changer cela en un avertissement.

    --dll-verbose
    --verbose[=NOMBRE]
    Affiche le numéro de version de ld et liste les émulations d'éditeur de liens supportées. Affiche quels fichiers d'entrée peuvent être ouverts et lesquels ne le peuvent pas. Affiche le script de l'éditeur de liens utilisé par l'éditeur de liens. Si l'argument facultatif NOMBRE > 1, le statut des symboles des plugins sera également affiché.
    --version-script=fichier-script-version
    Spécifie le nom d'un script de version à l'éditeur de liens. Ceci est généralement utilisé lors de la création de bibliothèques partagées pour spécifier des informations supplémentaires sur la hiérarchie des versions de la bibliothèque en cours de création. Cette option n'est entièrement supportée que sur les plateformes ELF qui supportent les bibliothèques partagées ; voir VERSION. Elle est partiellement supportée sur les plateformes PE, qui peuvent utiliser des scripts de version pour filtrer la visibilité des symboles en mode d'exportation automatique : tous les symboles marqués comme local dans le script de version ne seront pas exportés.
    --warn-common
    Avertit lorsqu'un symbole commun est combiné avec un autre symbole commun ou avec une définition de symbole. Les éditeurs de liens Unix autorisent cette pratique quelque peu laxiste, mais les éditeurs de liens sur certains autres systèmes d'exploitation ne le font pas. Cette option vous permet de détecter les problèmes potentiels liés à la combinaison de symboles globaux. Malheureusement, certaines bibliothèques C utilisent cette pratique, vous pourriez donc recevoir des avertissements concernant les symboles des bibliothèques ainsi que ceux de vos programmes.

    Il existe trois types de symboles globaux, illustrés ici par des exemples C :

    int i = 1;
    Une définition, qui va dans la section des données initialisées du fichier de sortie.
    extern int i;
    Une référence indéfinie, qui
    h n'alloue pas d'espace. Il doit y avoir soit une définition, soit un symbole commun pour la variable quelque part.
    int i;
    Un symbole commun. S'il n'y a que (un ou plusieurs) symboles communs pour une variable, elle est placée dans la zone de données non initialisées du fichier de sortie. L'éditeur de liens fusionne plusieurs symboles communs pour la même variable en un seul symbole. S'ils sont de tailles différentes, il choisit la plus grande taille. L'éditeur de liens transforme un symbole commun en une déclaration, s'il existe une définition de la même variable.

    L'option --warn-common peut produire cinq types d'avertissements. Chaque avertissement consiste en une paire de lignes : la première décrit le symbole qui vient d'être rencontré, et la seconde décrit le symbole précédent rencontré portant le même nom. Un ou les deux symboles seront un symbole commun.

    1.
    Transformation d'un symbole commun en référence, car il existe déjà une définition pour le symbole. 
    <fichier>(<section>): avertissement : commun de `<symbole>'
   remplacé par une définition
<fichier>(<section>): avertissement : défini ici
    2.
    Transformation d'un symbole commun en référence, car une définition ultérieure du symbole est rencontrée. Ceci est identique au cas précédent, sauf que les symboles sont rencontrés dans un ordre différent. 
    <fichier>(<section>): avertissement : définition de `<symbole>'
   remplaçant un commun
<fichier>(<section>): avertissement : le commun est ici
    3.
    Fusion d'un symbole commun avec un symbole commun précédent de même taille. 
    <fichier>(<section>): avertissement : multiples communs
   de `<symbole>'
<fichier>(<section>): avertissement : le commun précédent est ici
    4.
    Fusion d'un symbole commun avec un symbole commun précédent plus grand. 
    <fichier>(<section>): avertissement : commun de `<symbole>'
   remplacé par un commun plus grand
<fichier>(<section>): avertissement : le commun plus grand est ici
    5.
    Fusion d'un symbole commun avec un symbole commun précédent plus petit. Ceci est identique au cas précédent, sauf que les symboles sont rencontrés dans un ordre différent. 
    <fichier>(<section>): avertissement : commun de `<symbole>'
   remplaçant un commun plus petit
<fichier>(<section>): avertissement : le commun plus petit est ici
    --warn-constructors
    Avertir si des constructeurs globaux sont utilisés. Ceci n'est utile que pour quelques formats de fichiers objets. Pour des formats comme COFF ou ELF, l'éditeur de liens ne peut pas détecter l'utilisation de constructeurs globaux.
    --warn-execstack
    --warn-execstack-objects
    --no-warn-execstack
    Sur les plateformes ELF, l'éditeur de liens peut générer des messages d'avertissement s'il est invité à créer un fichier de sortie contenant une pile exécutable. Il y a trois états possibles :
    1.
    Ne générer aucun avertissement.
    2.
    Générer toujours des avertissements, même si la pile exécutable est demandée via l'option de ligne de commande -z execstack.
    3.
    Ne générer un avertissement que si un fichier objet demande une pile exécutable, mais pas si l'option -z execstack est utilisée.

    L'état par défaut dépend de la manière dont l'éditeur de liens a été configuré lors de sa construction. L'option --no-warn-execstack place toujours l'éditeur de liens dans l'état "pas d'avertissements". L'option --warn-execstack place l'éditeur de liens dans l'état "avertir toujours". L'option --warn-execstack-objects place l'éditeur de liens dans l'état "avertir uniquement pour les fichiers objets".

    Remarque : les fichiers d'entrée au format ELF peuvent spécifier qu'ils nécessitent une pile exécutable en ayant une section .note.GNU-stack avec le bit exécutable activé dans ses indicateurs de section. Ils peuvent spécifier qu'ils n'ont pas besoin d'une pile exécutable en ayant la même section, mais sans le bit d'indicateur exécutable activé. Si un fichier d'entrée n'a pas de section .note.GNU-stack, le comportement par défaut est spécifique à la cible. Pour certaines cibles, l'absence d'une telle section implique qu'une pile exécutable *est* requise. C'est souvent un problème pour les fichiers assembleur créés à la main.

    --error-execstack
    --no-error-execstack
    Si l'éditeur de liens doit générer un message d'avertissement concernant une pile exécutable, l'option --error-execstack transformera cet avertissement en erreur. Remarque : cette option ne modifie pas l'état de génération des avertissements d'execstack de l'éditeur de liens. Utilisez --warn-execstack ou --warn-execstack-objects pour définir un état d'avertissement spécifique.

    L'option --no-error-execstack rétablira le comportement par défaut de génération de messages d'avertissement.

    --warn-multiple-gp
    Avertir si plusieurs valeurs de pointeur global sont nécessaires dans le fichier de sortie. Ceci n'est significatif que pour certains processeurs, comme l'Alpha. Plus précisément, certains processeurs placent des constantes de grande valeur dans une section spéciale. Un registre spécial (le pointeur global) pointe vers le milieu de cette section, de sorte que les constantes puissent être chargées efficacement via un mode d'adressage relatif au registre de base. L'offset en mode relatif au registre de base étant fixe et relativement petit (par exemple, 16 bits), cela limite la taille maximale du pool de constantes. Ainsi, dans les grands programmes, il est souvent nécessaire d'utiliser plusieurs valeurs de pointeur global pour pouvoir adresser toutes les constantes possibles. Cette option provoque un avertissement chaque fois que ce cas se produit.
    --warn-once
    N'émettre un avertissement qu'une seule fois pour chaque symbole non résolu, plutôt qu'une fois par module qui y fait référence.
    --warn-rwx-segments
    --no-warn-rwx-segments
    Avertir si l'éditeur de liens crée un segment chargeable de taille non nulle qui possède les trois indicateurs d'autorisation lecture, écriture et exécution. Un tel segment représente une vulnérabilité de sécurité potentielle. De plus, des avertissements seront générés si un segment de stockage local à thread est créé avec l'indicateur d'autorisation d'exécution activé, qu'il ait ou non les indicateurs de lecture et/ou d'écriture activés.

    Ces avertissements sont activés par défaut. Ils peuvent être désactivés via l'option --no-warn-rwx-segments et réactivés via l'option --warn-rwx-segments.

    --error-rwx-segments
    --no-error-rwx-segments
    Si l'éditeur de liens doit générer un message d'avertissement concernant un segment exécutable et inscriptible, ou un segment TLS exécutable, alors l'option --error-rwx-segments transformera cet avertissement en erreur. L'option --no-error-rwx-segments rétablira le comportement par défaut de génération d'un simple message d'avertissement.

    Remarque : l'option --error-rwx-segments n'active pas en elle-même les avertissements concernant ces segments. Ces avertissements sont soit activés par défaut, si l'éditeur de liens a été configuré ainsi, soit via l'option de ligne de commande --warn-rwx-segments.

    --warn-section-align
    Avertir si l'adresse d'une section de sortie est modifiée en raison de l'alignement. Typiquement, l'alignement sera défini par une section d'entrée. L'adresse ne sera modifiée que si elle n'est pas explicitement spécifiée ; c'est-à-dire, si la commande "SECTIONS" ne spécifie pas d'adresse de départ pour la section.
    --warn-textrel
    Avertir si l'éditeur de liens ajoute DT_TEXTREL à un exécutable indépendant de la position ou à un objet partagé.
    --warn-alternate-em
    Avertir si un objet a un code machine ELF alternatif.
    --warn-unresolved-symbols
    Si l'éditeur de liens doit signaler un symbole non résolu (voir l'option --unresolved-symbols), il générera normalement une erreur. Cette option fait en sorte qu'il génère un avertissement à la place.
    --error-unresolved-symbols
    Ceci rétablit le comportement par défaut de l'éditeur de liens qui consiste à générer des erreurs lorsqu'il signale des symboles non résolus.
    --whole-archive
    Pour chaque archive mentionnée sur la ligne de commande après l'option --whole-archive, inclure chaque fichier objet de l'archive dans la liaison, plutôt que de rechercher dans l'archive les fichiers objets requis. Ceci est normalement utilisé pour transformer un fichier archive en une bibliothèque partagée, forçant chaque objet à être inclus dans la bibliothèque partagée résultante. Cette option peut être utilisée plusieurs fois.

    Deux notes lors de l'utilisation de cette option avec gcc : Premièrement, gcc ne connaît pas cette option, vous devez donc utiliser -Wl,-whole-archive. Deuxièmement, n'oubliez pas d'utiliser -Wl,-no-whole-archive après votre liste d'archives, car gcc ajoutera sa propre liste d'archives à votre liaison et vous pourriez ne pas vouloir que ce drapeau affecte celles-ci également.

    --wrap=symbole
    Utiliser une fonction d'encapsulation pour symbole. Toute référence non définie à symbole sera résolue en "__wrap_symbole". Toute référence non définie à "__real_symbole" sera résolue en symbole.

    Ceci peut être utilisé pour fournir une fonction d'encapsulation pour une fonction système. La fonction d'encapsulation doit être appelée "__wrap_symbole". Si elle souhaite appeler la fonction système, elle doit appeler "__real_symbole".

    Voici un exemple trivial :

    void *
__wrap_malloc (size_t c)
{
  printf ("malloc appelé avec %zu\n", c);
  return __real_malloc (c);
}

    Si vous liez d'autres codes avec ce fichier en utilisant --wrap malloc, alors tous les appels à "malloc" appelleront la fonction "__wrap_malloc" à la place. L'appel à "__real_malloc" dans "__wrap_malloc"

    /span> appellera la fonction "malloc" réelle.

    Vous pouvez également souhaiter fournir une fonction "__real_malloc", de sorte que les liens sans l'option --wrap réussissent. Si vous le faites, vous ne devez pas placer la définition de "__real_malloc" dans le même fichier que "__wrap_malloc" ; si vous le faites, l'assembleur peut résoudre l'appel avant que l'éditeur de liens n'ait la possibilité de le lier à "malloc".

    Seules les références indéfinies sont remplacées par l'éditeur de liens. Ainsi, les références internes à l'unité de traduction vers symbole ne sont pas résolues en "__wrap_symbole". Dans l'exemple suivant, l'appel à "f" dans "g" n'est pas résolu en "__wrap_f".

    int
f (void)
{
  return 123;
}

int
g (void)
{
  return f();
}
    --eh-frame-hdr
    --no-eh-frame-hdr
    Demande (--eh-frame-hdr) ou supprime (--no-eh-frame-hdr) la création de la section ".eh_frame_hdr" et de l'en-tête de segment ELF "PT_GNU_EH_FRAME".
    --no-ld-generated-unwind-info
    Demande la création d'informations de déroulement (unwind info) ".eh_frame" pour les sections de code générées par l'éditeur de liens comme PLT. Cette option est activée par défaut si les informations de déroulement générées par l'éditeur de liens sont prises en charge. Cette option contrôle également la génération d'informations de trace de pile ".sframe" pour les sections de code générées par l'éditeur de liens comme PLT.
    --enable-new-dtags
    --disable-new-dtags
    Cet éditeur de liens peut créer les nouvelles balises dynamiques en ELF. Mais les anciens systèmes ELF peuvent ne pas les comprendre. Si vous spécifiez --enable-new-dtags, les nouvelles balises dynamiques seront créées au besoin et les anciennes balises dynamiques seront omises. Si vous spécifiez --disable-new-dtags, aucune nouvelle balise dynamique ne sera créée. Par défaut, les nouvelles balises dynamiques ne sont pas créées. Notez que ces options ne sont disponibles que pour les systèmes ELF.
    --hash-size=nombre
    Définit la taille par défaut des tables de hachage de l'éditeur de liens à un nombre premier proche de nombre. Augmenter cette valeur peut réduire le temps nécessaire à l'éditeur de liens pour effectuer ses tâches, au prix d'une augmentation des besoins en mémoire de l'éditeur de liens. Inversement, réduire cette valeur peut réduire les besoins en mémoire au détriment de la vitesse.
    --hash-style=style
    Définit le type de table(s) de hachage de l'éditeur de liens. style peut être soit "sysv" pour la section ELF classique ".hash", "gnu" pour la nouvelle section ELF GNU ".gnu.hash", soit "both" pour les deux tables de hachage, la classique ELF ".hash" et la nouvelle GNU ".gnu.hash". La valeur par défaut dépend de la configuration de l'éditeur de liens, mais pour la plupart des systèmes basés sur Linux, ce sera "both".
    --compress-debug-sections=none
    --compress-debug-sections=zlib
    --compress-debug-sections=zlib-gnu
    --compress-debug-sections=zlib-gabi
    --compress-debug-sections=zstd
    Sur les plates-formes ELF, ces options contrôlent la compression des sections de débogage DWARF à l'aide de zlib.

    --compress-debug-sections=none ne compresse pas les sections de débogage DWARF. --compress-debug-sections=zlib-gnu compresse les sections de débogage DWARF et les renomme en commençant par .zdebug au lieu de .debug. --compress-debug-sections=zlib-gabi compresse également les sections de débogage DWARF, mais au lieu de les renommer, il définit le drapeau SHF_COMPRESSED dans les en-têtes des sections.

    L'option --compress-debug-sections=zlib est un alias pour --compress-debug-sections=zlib-gabi.

    --compress-debug-sections=zstd compresse les sections de débogage DWARF à l'aide de zstd.

    Notez que cette option remplace toute compression dans les sections de débogage d'entrée, donc si un binaire est lié avec --compress-debug-sections=none, par exemple, alors toutes les sections de débogage compressées dans les fichiers d'entrée seront décompressées avant d'être copiées dans le binaire de sortie.

    Le comportement de compression par défaut varie en fonction de la cible impliquée et des options de configuration utilisées pour construire la chaîne d'outils. La valeur par défaut peut être déterminée en examinant la sortie de l'option --help de l'éditeur de liens.

    --reduce-memory-overheads
    Cette option réduit les besoins en mémoire de ld au moment de l'exécution, au détriment de la vitesse de liaison. Elle a été introduite pour sélectionner l'ancien algorithme O(n^2) pour la génération du fichier de carte de lien, plutôt que le nouvel algorithme O(n) qui utilise environ 40% de mémoire en plus pour le stockage des symboles.

    Un autre effet de ce commutateur est de définir la taille par défaut de la table de hachage à 1021, ce qui permet d'économiser de la mémoire au prix d'un temps d'exécution plus long pour l'éditeur de liens. Cependant, cela n'est pas fait si le commutateur --hash-size a été utilisé.

    Le commutateur --reduce-memory-overheads peut également être utilisé pour activer d'autres compromis dans les futures versions de l'éditeur de liens.

    --max-cache-size=taille
    ld met normalement en cache les informations de relocalisation et les tables de symboles des fichiers d'entrée en mémoire avec une taille illimitée. Cette option définit la taille maximale du cache à taille.
    --build-id
    --build-id=style
    Demande la création d'une section de note ELF ".note.gnu.build-id" ou d'une section COFF ".buildid". Le contenu de la note contient des bits uniques identifiant ce fichier lié. style peut être "uuid" pour utiliser 128 bits aléatoires, "sha1" pour utiliser un hachage SHA1 de 160 bits sur les parties normatives du contenu de sortie, "md5" pour utiliser un hachage MD5 de 128 bits sur les parties normatives du contenu de sortie, ou "0xchaînehex" pour utiliser une chaîne de bits choisie spécifiée comme un nombre pair de chiffres hexadécimaux (les caractères "-" et ":" entre les paires de chiffres sont ignorés). Si style est omis, "sha1" est utilisé.

    Les styles "md5" et "sha1" produisent un identifiant qui est toujours le même dans un fichier de sortie identique, mais qui sera unique parmi tous les fichiers de sortie non identiques. Il n'est pas destiné à être comparé comme une somme de contrôle du contenu du fichier. Un fichier lié peut être modifié ultérieurement par d'autres outils, mais la chaîne de bits d'identifiant de construction identifiant le fichier lié d'origine ne change pas.

    Passer "none" pour style désactive le paramètre défini par toute option "--build-id" précédente sur la ligne de commande.

    --package-metadata=JSON
    Demande la création d'une section de note ELF ".note.package". Le contenu de la note est au format JSON, conformément à la spécification des métadonnées de package. Pour plus d'informations, voir : https://systemd.io/ELF_PACKAGE_METADATA/ Si l'argument JSON est manquant/vide, cela désactivera la création de la note de métadonnées, si elle avait été activée par une occurrence antérieure de l'option --package-metadata. Si l'éditeur de liens a été construit avec libjansson, la chaîne JSON sera validée.

    L'éditeur de liens i386 PE prend en charge l'option -shared, qui fait que la sortie est une bibliothèque liée dynamiquement (DLL) au lieu d'un exécutable normal. Vous devriez nommer la sortie "*.dll" lorsque vous utilisez cette option. De plus, l'éditeur de liens prend entièrement en charge les fichiers "*.def" standard, qui peuvent être spécifiés sur la ligne de commande de l'éditeur de liens comme un fichier objet (en fait, il devrait précéder les archives dont il exporte les symboles, pour s'assurer qu'ils sont liés, comme un fichier objet normal).

    En plus des options communes à toutes les cibles, l'éditeur de liens i386 PE prend en charge des options de ligne de commande supplémentaires qui sont spécifiques à la cible i386 PE. Les options qui prennent des valeurs peuvent être séparées de leurs valeurs par un espace ou un signe égal.

    --add-stdcall-alias
    Si elle est fournie, les symboles avec un suffixe stdcall (@nn) seront exportés tels quels et également avec le suffixe supprimé. [Cette option est spécifique au port i386 PE ciblé de l'éditeur de liens]
    --base-file fichier
    Utilise fichier comme nom d'un fichier dans lequel enregistrer les adresses de base de toutes les relocalisations nécessaires pour générer des DLL avec dlltool. [Ceci est une option spécifique à i386 PE]
    --dll
    Crée une DLL au lieu d'un exécutable régulier. Vous pouvez également utiliser -shared ou spécifier une "LIBRARY" dans un fichier ".def" donné. [Cette option est spécifique au port i386 PE ciblé de l'éditeur de liens]
    --enable-long-section-names
    --disable-long-section-names
    Les variantes PE du format d'objet COFF ajoutent une extension qui permet l'utilisation de noms de section plus longs que huit caractères, la limite normale pour COFF. Par défaut, ces noms sont activés
    autorisé dans les fichiers objets, car les images exécutables entièrement liées ne transportent pas la table de chaînes COFF requise pour prendre en charge les noms plus longs. En tant qu'extension GNU, il est possible de permettre leur utilisation dans les images exécutables également, ou de (probablement inutilement !) les interdire dans les fichiers objets, en utilisant ces deux options. Les images exécutables générées avec ces longs noms de sections sont légèrement non standard, transportant une table de chaînes, et peuvent générer une sortie confuse lors de l'examen avec des outils non-GNU connaissant le format PE, tels que les visualiseurs et les dumpers de fichiers. Cependant, GDB s'appuie sur l'utilisation des noms de sections longs PE pour trouver les sections d'informations de débogage Dwarf-2 dans une image exécutable à l'exécution, et donc si aucune des options n'est spécifiée sur la ligne de commande, ld activera les noms de sections longs, remplaçant le comportement par défaut et techniquement correct, lorsqu'il détecte la présence d'informations de débogage lors de la liaison d'une image exécutable et sans supprimer les symboles. [Cette option est valide pour tous les ports du lieur ciblant le format PE]
    --enable-stdcall-fixup
    --disable-stdcall-fixup
    Si la liaison trouve un symbole qu'elle ne peut pas résoudre, elle tentera de faire une "liaison approximative" en recherchant un autre symbole défini qui ne diffère que par le format du nom du symbole (cdecl vs stdcall) et résoudra ce symbole en le liant à la correspondance. Par exemple, le symbole indéfini "_foo" pourrait être lié à la fonction "_foo@12", ou le symbole indéfini "_bar@16" pourrait être lié à la fonction "_bar". Lorsque le lieur fait cela, il affiche un avertissement, car normalement il aurait dû échouer à la liaison, mais parfois les bibliothèques d'importation générées à partir de DLL tierces peuvent nécessiter que cette fonctionnalité soit utilisable.     Si --insert-timestamp est actif, alors l'heure insérée est soit l'heure à laquelle la liaison a lieu, soit, si la variable d'environnement "SOURCE_DATE_EPOCH" est définie, le nombre de secondes depuis l'époque Unix tel que spécifié par cette variable.

    --disable-reloc-section
    Crée la table de relocalisation de base, qui est nécessaire si l'image est chargée à une base d'image différente de celle spécifiée dans l'en-tête PE. Cette option est activée par défaut.

    La cible C6X uClinux utilise un format binaire appelé DSBT pour prendre en charge les bibliothèques partagées. Chaque bibliothèque partagée dans le système doit avoir un index unique ; tous les exécutables utilisent un index de 0.

    --dsbt-size taille
    Cette option définit le nombre d'entrées dans le DSBT de l'exécutable ou de la bibliothèque partagée actuelle à taille. Le défaut est de créer une table avec 64 entrées.
    --dsbt-index index
    Cette option définit l'index DSBT de l'exécutable ou de la bibliothèque partagée actuelle à index. Le défaut est 0, ce qui est approprié pour générer des exécutables. Si une bibliothèque partagée est générée avec un index DSBT de 0, les relocalisations "R_C6000_DSBT_INDEX" sont copiées dans le fichier de sortie.

    Le commutateur --no-merge-exidx-entries désactive la fusion des entrées exidx adjacentes dans les informations de déroulement de trame.

    --branch-stub
    Cette option active la relaxation des branchements par l'éditeur de liens en insérant des sections de "stub" de branchement lorsque nécessaire pour étendre la portée des branchements. Cette option n'est généralement pas requise car C-SKY prend en charge les instructions de branchement et d'appel qui peuvent accéder à toute la plage mémoire et la relaxation des branchements est normalement gérée par le compilateur ou l'assembleur.
    --stub-group-size=N
    Cette option permet un contrôle plus fin de la création des "stub" de branchement par l'éditeur de liens. Elle définit la taille maximale d'un groupe de sections d'entrée qui peuvent être gérées par une section de "stub". Une valeur négative de N place les sections de "stub" après leurs branchements, tandis qu'une valeur positive permet aux sections de "stub" d'apparaître avant ou après les branchements. Les valeurs 1 ou -1 indiquent que l'éditeur de liens doit choisir des valeurs par défaut appropriées.

    Les éditeurs de liens 68HC11 et 68HC12 prennent en charge des options spécifiques pour contrôler le mappage de la commutation de banque mémoire et la génération de code "trampoline".

    --no-trampoline
    Cette option désactive la génération de "trampoline". Par défaut, une "trampoline" est générée pour chaque fonction lointaine qui est appelée en utilisant une instruction "jsr" (cela se produit lorsqu'un pointeur vers une fonction lointaine est pris).
    --bank-window nom
    Cette option indique à l'éditeur de liens le nom de la région mémoire dans la spécification MEMORY qui décrit la fenêtre de banque mémoire. La définition d'une telle région est alors utilisée par l'éditeur de liens pour calculer le pagination et les adresses dans la fenêtre mémoire.

    Les options suivantes sont prises en charge pour contrôler la gestion de la génération du GOT lors de la liaison pour les cibles 68K.

    --got=type
    Cette option indique à l'éditeur de liens quel schéma de génération GOT utiliser. type doit être l'un des suivants : single, negative, multigot ou target. Pour plus d'informations, consultez l'entrée Info pour ld.

    Les options suivantes sont prises en charge pour contrôler la génération d'instructions microMIPS et les vérifications de relocalisation de branchement pour les transitions de mode ISA lors de la liaison pour les cibles MIPS.

    --insn32
    --no-insn32
    Ces options contrôlent le choix des instructions microMIPS utilisées dans le code généré par l'éditeur de liens, comme dans le PLT ou les "stub" de liaison paresseuse, ou dans la relaxation. Si --insn32 est utilisé, alors l'éditeur de liens utilise uniquement des encodages d'instructions de 32 bits. Par défaut ou si --no-insn32 est utilisé, tous les encodages d'instructions sont utilisés, y compris ceux de 16 bits lorsque possible.
    --ignore-branch-isa
    --no-ignore-branch-isa
    Ces options contrôlent les vérifications de relocalisation de branchement pour les transitions de mode ISA invalides. Si --ignore-branch-isa est utilisé, alors l'éditeur de liens accepte toutes les relocalisations de branchement et toute transition de mode ISA requise est perdue dans le calcul de relocalisation, sauf dans certains cas d'instructions "BAL" qui satisfont aux conditions de relaxation et sont converties en instructions "JALX" équivalentes au fur et à mesure du calcul de la relocalisation associée. Par défaut ou si --no-ignore-branch-isa est utilisé, une vérification est effectuée, entraînant la perte d'une transition de mode ISA et produisant une erreur.
    --compact-branches
    --no-compact-branches
    Ces options contrôlent la génération d'instructions compactes par l'éditeur de liens dans les entrées PLT pour MIPS R6.

    Pour la cible pdp11-aout, trois variantes du format de sortie peuvent être produites, sélectionnées par les options suivantes. La variante par défaut pour pdp11-aout est l'option --omagic, tandis que pour les autres cibles, --nmagic est le défaut. L'option --imagic est définie uniquement pour la cible pdp11-aout, tandis que les autres sont décrites ici telles qu'elles s'appliquent à la cible pdp11-aout.

    -N
    --omagic
    Marque la sortie comme "OMAGIC" (0407) dans l'en-tête a.out pour indiquer que le segment de texte ne doit pas être protégé en écriture et partagé. Étant donné que les segments de texte et de données sont tous deux lisibles et inscriptibles, le segment de données est alloué immédiatement après le segment de texte. C'est le plus ancien format pour les programmes exécutables PDP11 et c'est le défaut de ld sur les systèmes Unix PDP11 depuis le début jusqu'à la version 2.11BSD.
    -n
    --nmagic
    Marque la sortie comme "NMAGIC" (0410) dans l'en-tête a.out pour indiquer que lors de l'exécution du fichier de sortie, la portion de texte sera en lecture seule et partageable entre tous les processus exécutant le même fichier. Cela implique de déplacer les zones de données jusqu'à la première limite de page de 8 Ko possible après la fin du texte. Cette option crée un format d'exécutable pur.
    -z
    --imagic
    Marque la sortie comme "IMAGIC" (0411) dans l'en-tête a.out pour indiquer que lors de l'exécution du fichier de sortie, les zones de texte et de données du programme seront chargées dans des espaces d'adressage séparés en utilisant la fonctionnalité d'espace d'instructions et de données séparés de l'unité de gestion mémoire dans les modèles plus grands du PDP11. Cela double l'espace d'adressage disponible pour le programme. Le segment de texte est à nouveau pur, protégé en écriture et partageable. La seule différence dans le format de sortie entre cette option et les autres, outre le nombre magique, est que les segments de texte et de données commencent tous deux à l'emplacement 0. L'option -z sélectionnait ce format dans 2.11BSD. Cette option crée un format d'exécutable séparé.
    --no-omagic
    Équivalent à --nmagic pour pdp11-aout.

    ENVIRONNEMENT

    Vous pouvez modifier le comportement de ld avec les variables d'environnement "GNUTARGET", "LDEMULATION" et "COLLECT_NO_DEMANGLE".

    "GNUTARGET" détermine le format d'objet des fichiers d'entrée si vous n'utilisez pas -b (ou son synonyme --format). Sa valeur doit être l'un des noms BFD pour un format d'entrée. S'il n'y a pas de "GNUTARGET" dans l'environnement, ld utilise le format naturel de la cible. Si "GNUTARGET" est défini sur "default", alors BFD tente de découvrir le format d'entrée en examinant les fichiers binaires d'entrée ; cette méthode réussit souvent, mais il y a des ambiguïtés potentielles, car il n'y a pas de méthode pour garantir que le nombre magique utilisé pour spécifier les formats de fichiers objet est unique. Cependant, la procédure de configuration de BFD sur chaque système place le format conventionnel pour ce système en tête de la liste de recherche, de sorte que les ambiguïtés sont résolues en faveur de la convention.

    "LDEMULATION" détermine l'émulation par défaut si vous n'utilisez pas l'option -m. L'émulation peut affecter divers aspects du comportement de l'éditeur de liens, en particulier le script d'éditeur de liens par défaut. Vous pouvez lister les émulations disponibles avec les options --verbose ou -V. Si l'option -m n'est pas utilisée et que la variable d'environnement "LDEMULATION" n'est pas définie, l'émulation par défaut dépend de la manière dont l'éditeur de liens a été configuré.

    Normalement, l'éditeur de liens ne désémangle pas les symboles par défaut. Cependant, si "COLLECT_NO_DEMANGLE" est défini dans l'environnement, alors il sera par défaut de ne pas démangler les symboles. Cette variable d'environnement est utilisée de manière similaire par le programme enveloppe de l'éditeur de liens "gcc". La valeur par défaut peut être remplacée par les options --demangle et --no-demangle.
