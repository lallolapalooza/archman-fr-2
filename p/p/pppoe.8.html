NOM

pppoe - client PPPoE en espace utilisateur.

SYNTAXE

pppd pty 'pppoe [options_pppoe]' [options_pppd]

pppoe -A [options_pppoe]

DESCRIPTION

pppoe est un client en espace utilisateur pour PPPoE (Point-to-Point Protocol over Ethernet) pour Linux et autres systèmes UNIX. pppoe fonctionne en collaboration avec le démon PPP pppd pour fournir une connexion PPP sur Ethernet, telle qu'utilisée par de nombreux fournisseurs de services DSL.

OPTIONS

-I interface
L'option -I spécifie l'interface Ethernet à utiliser. Sous Linux, il s'agit généralement de eth0 ou eth1. L'interface doit être "up" (activée) avant de démarrer pppoe, mais elle ne doit pas être configurée avec une adresse IP.
-T timeout
L'option -T provoque la sortie de pppoe si aucun trafic de session n'est détecté pendant timeout secondes. Je recommande d'utiliser cette option comme mesure de sécurité supplémentaire, mais si vous le faites, assurez-vous que PPP génère suffisamment de trafic pour que le timeout ne soit pas déclenché normalement. La meilleure façon de le faire est d'utiliser l'option lcp-echo-interval de pppd. Vous devriez définir le timeout PPPoE à environ quatre fois l'intervalle d'écho LCP.
-D nom_fichier
L'option -D provoque le vidage de chaque paquet dans le nom_fichier spécifié. Ceci est uniquement destiné au débogage ; cela produit une quantité énorme de sortie et réduit considérablement les performances.
-V
L'option -V provoque l'affichage du numéro de version de pppoe et sa sortie.
-A
L'option -A provoque l'envoi d'un paquet PADI par pppoe, puis l'affichage des noms des concentrateurs d'accès dans chaque paquet PADO reçu. N'utilisez pas cette option en conjonction avec pppd ; l'option -A est destinée à être utilisée interactivement pour fournir des informations intéressantes sur le concentrateur d'accès.
-S nom_service
Spécifie le nom du service souhaité. pppoe n'initiera des sessions qu'avec les concentrateurs d'accès pouvant fournir le service spécifié. Dans la plupart des cas, vous ne devriez pas spécifier cette option. Utilisez-la uniquement si vous savez qu'il existe plusieurs concentrateurs d'accès ou si vous savez que vous avez besoin d'un nom de service spécifique.
-C nom_ac
Spécifie le nom du concentrateur d'accès souhaité. pppoe n'initiera des sessions qu'avec le concentrateur d'accès spécifié. Dans la plupart des cas, vous ne devriez pas spécifier cette option. Utilisez-la uniquement si vous savez qu'il existe plusieurs concentrateurs d'accès. Si les options -S et -C sont toutes deux spécifiées, elles doivent toutes deux correspondre pour que pppoe initie une session.
-U
Force pppoe à utiliser la balise Host-Uniq dans ses paquets de découverte. Cela vous permet d'exécuter plusieurs démons pppoe sans que leurs paquets de découverte n'interfèrent les uns avec les autres. Vous devez fournir cette option à tous les démons pppoe si vous prévoyez d'exécuter plusieurs démons simultanément. La valeur spécifique Host-Uniq utilisée est la représentation hexadécimale du PID du processus pppoe.
-W valeur
Force pppoe à utiliser la balise Host-Uniq dans ses paquets de découverte, et de plus, à définir la valeur de Host-Uniq à valeur. À utiliser avec prudence. Notez que -W et -U sont mutuellement incompatibles.
-s
Force pppoe à utiliser l'encapsulation PPP synchrone. Si vous utilisez cette option, vous devez utiliser l'option sync avec pppd. Il est recommandé d'utiliser cette option si elle fonctionne, car elle réduit considérablement la charge CPU de pppoe. Cependant, elle PEUT être peu fiable sur les machines lentes -- il y a une condition de concurrence entre pppd qui écrit des données et pppoe qui les lit. Pour cette raison, le réglage par défaut est asynchrone. Si vous rencontrez des bugs ou des plantages avec PPP synchrone, désactivez-la -- ne m'envoyez pas d'e-mail pour obtenir de l'aide !
-m MSS
Force pppoe à limiter la taille maximale de segment TCP à la valeur spécifiée. En raison de la surcharge PPPoE, la taille maximale de segment pour PPPoE est plus petite que pour l'encapsulation Ethernet normale. Cela pourrait causer des problèmes aux machines sur un LAN derrière une passerelle utilisant PPPoE. Si vous avez un LAN derrière une passerelle, et que la passerelle se connecte à Internet via PPPoE, il est fortement recommandé d'utiliser l'option -m 1412. Cela évite d'avoir à définir le MTU sur tous les hôtes du LAN.
-p fichier
Force pppoe à écrire son ID de processus dans le fichier spécifié. Cela peut être utilisé pour localiser et tuer les processus pppoe.
-e sess:mac
Force pppoe à sauter la phase de découverte et à passer directement à la phase de session. La session est donnée par sess et l'adresse MAC du pair par mac. Ce mode n'est pas destiné à un usage normal ; il est conçu uniquement pour pppoe-server(8).
-n
Force pppoe à ne pas ouvrir de socket de découverte. Ce mode n'est pas destiné à un usage normal ; il est conçu uniquement pour pppoe-server(8).
-k
Force pppoe à terminer une session existante en envoyant une trame PADT, puis à sortir. Vous devez utiliser l'option -e en conjonction avec cette option pour spécifier la session à tuer. Cela peut être utile pour tuer des sessions lorsqu'un pair défectueux ne réalise pas que la session est terminée.
-d
Force pppoe à effectuer la découverte, puis à sortir, après avoir affiché les informations de session sur la sortie standard. Les informations de session sont affichées exactement dans le format attendu par l'option -e. Cette option vous permet d'initier une découverte PPPoE, d'effectuer d'autres tâches, puis de démarrer la session PPP réelle. Soyez prudent ; si vous utilisez cette option dans une boucle, vous pouvez créer de nombreuses sessions, ce qui pourrait agacer votre pair.
-f disc:sess
L'option -f définit les types de trames Ethernet pour la découverte PPPoE et les trames de session. Les types sont spécifiés sous forme de nombres hexadécimaux séparés par un deux-points. PPPoE standard utilise les types de trames 8863:8864. Vous ne devriez pas utiliser cette option à moins d'être absolument sûr que le pair avec lequel vous traitez utilise des types de trames non standard. Si votre FAI utilise des types de trames non standard, plaignez-vous !
-h
L'option -h provoque l'affichage des informations d'utilisation par pppoe et sa sortie.

ARRIÈRE-PLAN PPPOE

PPPoE (Point-to-Point Protocol over Ethernet) est décrit dans la RFC 2516 et est un protocole qui permet à l'abstraction de session d'être maintenue sur des réseaux Ethernet pontés.

PPPoE fonctionne en encapsulant des trames PPP dans des trames Ethernet. Le protocole a deux étapes distinctes : la découverte et la session.

Lors de l'étape de découverte, l'hôte diffuse une trame PADI spéciale (PPPoE Active Discovery Initiation) pour découvrir tous les concentrateurs d'accès. Les concentrateurs d'accès (généralement, un seul concentrateur d'accès) répondent avec des paquets PADO (PPPoE Active Discovery Offer), annonçant leur présence et les services qu'ils proposent. L'hôte choisit l'un des concentrateurs d'accès et transmet un paquet PADR (PPPoE Active Discovery Request), demandant une session. Le concentrateur d'accès répond avec un paquet PADS (PPPoE Active Discovery Session-Confirmation). Le protocole passe alors à l'étape de session.

Lors de l'étape de session, l'hôte et le concentrateur d'accès échangent des trames PPP incorporées dans des trames Ethernet. Le MTU Ethernet normal est de 1500 octets, mais la surcharge PPPoE plus deux octets de surcharge pour la trame PPP encapsulée signifient que le MTU de l'interface PPP est au maximum de 1492 octets. NOM

pppoe - un client PPPoE (Point-to-Point Protocol over Ethernet)

SYNTAXE

pppoe [ options ] [ pppd options ]

DESCRIPTION

pppoe est un client PPPoE qui permet à un utilisateur de se connecter à un fournisseur d'accès à Internet via PPPoE. Il lance ensuite pppd pour gérer la connexion PPP.

pppoe recherche des équipements PPPoE sur l'interface Ethernet spécifiée et lance ensuite une session PPPoE avec l'équipement trouvé.

OPTIONS

Les options de ligne de commande suivantes sont disponibles:

-i interface
Spécifie l'interface Ethernet à utiliser pour la connexion PPPoE.
-U
Démarre pppoe en arrière-plan. Par défaut, pppoe s'exécute au premier plan.
-P pidfile
Écrit l'ID du processus de pppoe dans le fichier spécifié.
-V
Affiche la version et quitte.
-h
Affiche un message d'aide et quitte.

Toutes les autres options sont passées directement à pppd.

PPPOE BACKGROUND

PPPoE (Point-to-Point Protocol over Ethernet) est un protocole qui permet à un réseau d'accéder à Internet en utilisant le protocole PPP. Il est généralement utilisé par les fournisseurs d'accès à Internet pour connecter leurs clients.

PPPoE utilise deux phases: la phase de découverte et la phase de session. La phase de découverte permet à un client de trouver des concentrateurs PPPoE et d'établir une session. La phase de session est une session PPP normale.

Il peut y avoir des problèmes si vous utilisez une machine Linux comme pare-feu et que les interfaces derrière le pare-feu ont un MTU supérieur à 1492. En fait, pour être sûr, je recommande de régler le MTU des machines derrière le pare-feu à 1412, pour permettre les options TCP et IP du pire cas dans leurs en-têtes respectifs.

Normalement, PPP utilise le protocole LCP (Link Control Protocol) pour arrêter une liaison PPP. Cependant, la spécification PPPoE permet d'arrêter la liaison avec un paquet spécial PADT (PPPoE Active Discovery Terminate). Ce client reconnaît ce paquet et se terminera correctement si une demande de terminaison est reçue pour la session PPP.

OBJECTIFS DE CONCEPTION

Mes objectifs de conception pour ce client PPPoE étaient les suivants, par ordre d'importance décroissant:

o
Il doit fonctionner.
o
Il doit s'agir d'un programme utilisateur et non d'un patch noyau.
o
Le code doit être facile à lire et à maintenir.
o
Il doit être entièrement conforme à la RFC 2516, la norme PPPoE proposée.
o
Il ne doit jamais raccrocher indéfiniment — si la connexion est rompue, il doit le détecter et se terminer, permettant à un script wrapper de redémarrer la connexion.
o
Il doit être assez efficace.

Je crois avoir atteint tous ces objectifs, mais je suis (bien sûr) ouvert aux suggestions, correctifs et idées. Voir ma page d'accueil, https://dianne.skoll.ca/projects/rp-pppoe/, pour les informations de contact.

NOTES

Pour de meilleurs résultats, vous devez donner à pppd une option mtu de 1492. J'ai observé des problèmes avec des trames excessivement grandes à moins de définir cette option. De plus, si pppoe s'exécute sur une machine pare-feu, toutes les machines derrière le pare-feu doivent avoir des MTU de 1412.

En cas de problèmes, vérifiez vos journaux système. pppoe enregistre des informations intéressantes dans syslog. Vous devrez peut-être activer l'enregistrement des messages de niveau debug pour un diagnostic complet.
