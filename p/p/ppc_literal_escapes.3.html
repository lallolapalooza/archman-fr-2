pca_lookup_file(3) Manuel des fonctions de bibliothèque pca_lookup_file(3)

NOM

pca_lookup_file, del_PathCache, del_PcaPathConf, new_PathCache, new_PcaPathConf, pca_last_error, pca_path_completions, pca_scan_path, pca_set_check_fn, ppc_file_start, ppc_literal_escapes - recherche un fichier dans une liste de répertoires

SYNOPSIS

#include <libtecla.h>
PathCache *new_PathCache(void);
PathCache *del_PathCache(PathCache *pc);
int pca_scan_path(PathCache *pc, const char *path);
void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                      void *data);
char *pca_lookup_file(PathCache *pc, const char *name,
                      int name_len, int literal);
const char *pca_last_error(PathCache *pc);
CPL_MATCH_FN(pca_path_completions);

DESCRIPTION

L'objet PathCache fait partie de la bibliothèque tecla (voir la page man libtecla(3)).

Les objets PathCache permettent à une application de rechercher des fichiers dans n'importe quelle liste de répertoires séparés par des deux-points, telle que la variable d'environnement PATH d'exécution unix. Les fichiers dans des répertoires absolus sont mis en cache dans un objet PathCache, tandis que les répertoires relatifs sont analysés si nécessaire. En utilisant un objet PathCache, vous pouvez rechercher le chemin complet d'un nom de fichier simple, ou obtenir une liste des complétions possibles d'un préfixe de nom de fichier donné. Par défaut, tous les fichiers dans la liste des répertoires sont des cibles pour la recherche et la complétion, mais un mécanisme polyvalent est fourni pour ne sélectionner que des types spécifiques de fichiers. L'application évidente de cette facilité est de fournir la complétion par tabulation et la recherche de commandes exécutables dans le PATH unix, ainsi une fonction de rappel optionnelle qui rejette tout sauf les fichiers exécutables, est fournie.

UN EXEMPLE

Sous UNIX, l'exemple de programme suivant recherche et affiche les chemins complets de chaque nom de commande sur la ligne de commande.

  #include <stdio.h>
  #include <stdlib.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    int i;
  /*
   * Crée un cache pour les fichiers exécutables.
   */
    PathCache *pc = new_PathCache();
    if(!pc)
      exit(1);
  /*
   * Analyse le PATH de l'utilisateur pour les exécutables.
   */
    if(pca_scan_path(pc, getenv("PATH"))) {
      fprintf(stderr, "%s\n", pca_last_error(pc));
      exit(1);
    }
  /*
   * S'arrange pour ne rapporter que les fichiers exécutables.
   */
   pca_set_check_fn(pc, cpl_check_exe, NULL);
  /*
   * Recherche et affiche le chemin complet de chacune des
   * commandes listées sur la ligne de commande.
   */
    for(i=1; i<argc; i++) {
      char *cmd = pca_lookup_file(pc, argv[i], -1, 0);
      printf("Le chemin complet de '%s' est %s\n", argv[i],
             cmd ? cmd : "inconnu");
    }
    pc = del_PathCache(pc);  /* Nettoyage */
    return 0;
  }

Voici un exemple de ce que cela donne sur mon ordinateur portable sous linux :

  $ ./exemple less more blob
  Le chemin complet de 'less' est /usr/bin/less
  Le chemin complet de 'more' est /bin/more
  Le chemin complet de 'blob' est inconnu
  $

DESCRIPTIONS DE FONCTION

Pour utiliser les facilités de ce module, vous devez d'abord allouer un objet PathCache en appelant la fonction constructeur new_PathCache().

  PathCache *new_PathCache(void)

Cette fonction crée les ressources nécessaires pour mettre en cache et rechercher des fichiers dans une liste de répertoires. Elle renvoie NULL en cas d'erreur.

POPULER LE CACHE

Une fois que vous avez créé un cache, il doit être rempli de fichiers. Pour ce faire, appelez la fonction pca_scan_path().

  int pca_scan_path(PathCache *pc, const char *path);

Chaque fois que cette fonction est appelée, elle écarte le contenu actuel du cache, puis analyse la liste des répertoires spécifiés dans son argument path à la recherche de fichiers. L'argument path doit être une chaîne contenant une liste de répertoires séparés par des deux-points, telle que "/usr/bin:/home/mcs/bin:.". Cela peut inclure des répertoires spécifiés par des chemins absolus tels que "/usr/bin", ainsi que des sous-répertoires spécifiés par des chemins relatifs tels que "." ou "bin". Les fichiers dans les répertoires absolus sont immédiatement mis en cache dans l'objet PathCache spécifié, tandis que les sous-répertoires, dont l'identité change évidemment chaque fois que le répertoire de travail courant est changé, sont marqués pour être analysés à la volée chaque fois qu'un fichier est recherché.

En cas de succès, cette fonction renvoie 0. En cas d'erreur, elle renvoie 1, et une description de l'erreur peut être obtenue en appelant pca_last_error(pc).

RECHERCHE DE FICHIERS

Une fois que le cache a été rempli de fichiers, vous pouvez rechercher le chemin complet d'un fichier, simplement en spécifiant son nom de fichier à pca_lookup_file().

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal);

Pour permettre de passer à cette fonction un nom de fichier qui est en fait une partie d'une chaîne plus longue, l'argument name_len peut être utilisé pour spécifier la longueur du nom de fichier au début de l'argument name[]. Si vous passez -1 pour cette longueur, la longueur de la chaîne sera déterminée avec strlen(). Si la chaîne name[] peut contenir des antislashs qui échappent la signification spéciale des espaces et des tabulations dans le nom de fichier, donnez à l'argument literal la valeur 0. Sinon, si les antislashs doivent être traités comme des caractères normaux, passez 1 pour la valeur de l'argument literal.

COMPLETION DE NOM DE FICHIER

Rechercher les complétions potentielles d'un préfixe de nom de fichier dans le cache de noms de fichiers, est réalisé en passant la fonction de rappel fournie pca_path_completions() à la fonction cpl_complete_word() (voir la page man cpl_complete_word(3)).

  CPL_MATCH_FN(pca_path_completions);

Ce rappel nécessite que son argument data soit un pointeur vers un objet PcaPathConf. Les objets de configuration de ce type sont alloués en appelant new_PcaPathConf().

  PcaPathConf *new_PcaPathConf(PathCache *pc);

Cette fonction renvoie un objet initialisé avec des paramètres de configuration par défaut, qui déterminent le comportement de la fonction de rappel cpl_path_completions(). Les fonctions qui permettent de modifier individuellement ces paramètres sont décrites ci-dessous.

Par défaut, la fonction de rappel pca_path_completions() recherche en arrière le début du nom de fichier en cours de complétion, à la recherche du premier espace non échappé ou du début de la ligne d'entrée. Si vous souhaitez spécifier un emplacement différent, appelez ppc_file_start() avec l'index où commence le nom de fichier dans la ligne d'entrée. Passer start_index=-1 réactive le comportement par défaut.

  void ppc_file_start(PcaPathConf *ppc, int start_index);

Par défaut, lorsque pca_path_completions() examine un nom de fichier dans la ligne d'entrée, chaque antislash isolé dans la ligne d'entrée est interprété comme un caractère spécial qui supprime toute signification spéciale du caractère qui le suit, comme un espace qui doit être considéré comme faisant partie du nom de fichier plutôt que comme délimitant le début du nom de fichier. Ces antislashs sont donc ignorés lors de la recherche de complétions, et sont ensuite ajoutés avant les espaces, tabulations et antislashs littéraux dans la liste des complétions. Pour que les antislashs non échappés soient traités comme des caractères normaux, appelez ppc_literal_escapes() avec une valeur non nulle dans son argument literal.

  void ppc_literal_escapes(PcaPathConf *ppc, int literal);

Lorsque vous avez terminé avec une variable PcaPathConf, vous pouvez la passer à la fonction destructeur del_PcaPathConf() pour récupérer sa mémoire.

  PcaPathConf *del_PcaPathConf(PcaPathConf *ppc);

SE SOUCIER D'ÊTRE SÉLECTIF

Si vous ne vous intéressez qu'à certains types de fichiers, tels que, par exemple, des fichiers exécutables, ou des fichiers dont les noms se terminent par un suffixe particulier, vous pouvez faire en sorte que les fonctions de complétion et de recherche de noms de fichiers soient sélectives quant aux noms de fichiers qu'elles retournent. Ceci est fait en enregistrant une fonction de rappel auprès de votre objet PathCache. NOM

ppc_literal_escapes — fonction de complétion de chemin pour la bibliothèque tecla

SYNOPSIS

#define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
typedef CPL_CHECK_FN(CplCheckFn);

void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

DESCRIPTION

Cette page man décrit les fonctions permettant de gérer la mise en cache et la complétion des noms de fichiers et de répertoires dans la bibliothèque tecla. Ces fonctions sont particulièrement utiles pour implémenter des mécanismes de complétion de ligne de commande interactifs.

Le cœur du système repose sur un objet PathCache. Cet objet stocke des informations sur les chemins et les fichiers, permettant une complétion rapide et efficace. Pour utiliser la fonctionnalité de mise en cache des chemins, vous devez d'abord créer une instance de PathCache en utilisant la fonction new_PathCache() (non documentée ici mais implicitement nécessaire).

Une fois le cache créé, vous pouvez le peupler en appelant pca_scan_path(), qui analyse un chemin spécifié et ajoute les fichiers et répertoires correspondants au cache. La complétion réelle des mots se fait ensuite via cpl_complete_word() (également non documentée ici mais le contexte l'implique).

Le comportement de la complétion peut être personnalisé en fournissant une fonction de rappel (callback) à pca_set_check_fn(). Cette fonction est appelée pour chaque fichier trouvé lors d'une opération de complétion. Elle détermine si un fichier doit être considéré comme une correspondance potentielle.

UN EXEMPLE

Un exemple d'utilisation de ces fonctions est donné plus haut dans cette page man (non reproduit ici). Il démontre comment utiliser une fonction de rappel personnalisée pour filtrer les résultats de la complétion en fonction des permissions d'exécution d'un fichier.

DESCRIPTIONS DES FONCTIONS

Les fonctions couvertes ici sont pca_set_check_fn(), pca_last_error() et del_PathCache().

REMPLISSAGE DU CACHE

La fonction pca_scan_path() (non documentée ici mais essentielle) est responsable du remplissage du cache. Elle prend un pointeur vers un objet PathCache et une chaîne représentant le chemin à scanner.

RECHERCHE DE FICHIERS

Les opérations de recherche et de complétion utilisent le cache pour retourner rapidement les correspondances. Les détails de ces opérations sont gérés par d'autres fonctions de la bibliothèque tecla.

COMPLÉTION DE NOMS DE FICHIERS

Lorsqu'une opération de complétion de nom de fichier est effectuée, la bibliothèque tecla parcourt le cache. Pour chaque entrée correspondante dans le cache, la fonction de rappel enregistrée sera appelée.

ÊTRE SELECTIONNE

La fonction de rappel sera appelée avec le chemin complet du fichier, ainsi que toute donnée spécifique à l'application que vous fournissez. Si le rappel retourne 1, le nom du fichier sera signalé comme une correspondance, et s'il retourne 0, il sera ignoré. Les fonctions de rappel appropriées et leurs prototypes doivent être déclarées avec le macro suivant. Le CplCheckFn typedef est également fourni au cas où vous souhaiteriez déclarer des pointeurs vers de telles fonctions.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);

L'enregistrement d'une de ces fonctions implique l'appel de la fonction pca_set_check_fn(). En plus de la fonction de rappel, passée via l'argument check_fn, vous pouvez passer un pointeur vers n'importe quoi via l'argument data. Ce pointeur sera passé à votre fonction de rappel, via son propre argument data, chaque fois qu'elle sera appelée, ce qui fournit un moyen de passer des données spécifiques à l'application à votre rappel.

  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

Notez que ces rappels reçoivent le chemin complet de chaque fichier correspondant, de sorte que la décision de savoir si un fichier est d'intérêt peut être basée sur n'importe quelle propriété du fichier, pas seulement son nom. Par exemple, la fonction de rappel fournie cpl_check_exe() examine les permissions d'exécution du fichier et les permissions de ses répertoires parents, et ne retourne 1 que si l'utilisateur a la permission d'exécuter le fichier. Cette fonction de rappel peut ainsi être utilisée pour rechercher ou compléter des noms de commandes trouvés dans les répertoires listés dans la variable d'environnement PATH de l'utilisateur. L'exemple de programme donné plus tôt dans cette page man fournit une démonstration de cela.

Attention, si quelqu'un essaie de compléter une chaîne vide, votre rappel sera appelé une fois pour chaque fichier dans le cache, ce qui peut se chiffrer par milliers. Si votre rappel effectue quelque chose de long, cela pourrait entraîner un délai inacceptable pour l'utilisateur, les rappels doivent donc être courts.

Pour améliorer les performances, chaque fois que l'un de ces rappels est appelé, le choix qu'il fait est mis en cache, et la prochaine fois que le fichier correspondant est recherché, au lieu d'appeler à nouveau le rappel, l'enregistrement mis en cache de son acceptation ou de son rejet est utilisé. Ainsi, si quelqu'un essaie de compléter une chaîne vide, et appuie sur tab une seconde fois alors que rien ne semble se passer, il n'y aura qu'un seul long délai, car la seconde passe fonctionnera entièrement à partir des dispositions mises en cache des fichiers. Ces dispositions mises en cache sont supprimées chaque fois que pca_scan_path() est appelé, et chaque fois que pca_set_check_fn() est appelé avec une fonction de rappel ou des arguments de données modifiés.

GESTION DES ERREURS

Si pca_scan_path() signale qu'une erreur s'est produite en retournant 1, vous pouvez obtenir une description concise de l'erreur en appelant pca_last_error(pc). Cela retourne une chaîne interne contenant un message d'erreur.

  const char *pca_last_error(PathCache *pc);

NETTOYAGE

Une fois que vous avez terminé d'utiliser un objet PathCache, vous pouvez récupérer ses ressources en le passant à la fonction destructeur del_PathCache(). Cela prend un pointeur vers l'un de ces objets et retourne toujours NULL.

  PathCache *del_PathCache(PathCache *pc);

SÉCURITÉ DES THREADS

Dans les programmes multi-threads, vous devriez utiliser la version libtecla_r.a de la bibliothèque. Celle-ci utilise des fonctions POSIX réentrantes lorsque disponibles (d'où le suffixe _r) et désactive les fonctionnalités qui reposent sur des fonctions système non réentrantes. Dans le cas de ce module, la seule fonctionnalité désactivée est la complétion de nom d'utilisateur dans les expressions ~username/, dans cpl_path_completions().

En utilisant la version libtecla_r.a de la bibliothèque, il est sûr d'utiliser les facilités de ce module dans plusieurs threads, à condition que chaque thread utilise un objet PathCache alloué séparément. Autrement dit, si deux threads veulent effectuer des recherches de chemins, ils devraient chacun appeler new_PathCache() pour allouer leurs propres caches.
