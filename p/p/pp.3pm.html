NOM

pp - PAR Packager

SYNOPIS

pp [ -ABCEFILMPTSVXacdefghilmnoprsuvxz ] [ fichier_par | fichier_script ]...

EXEMPLES

Remarque : Lors de l'exécution sous Microsoft Windows, le a.out ci-dessous sera remplacé par a.exe.

% pp hello.pl               # Empaquette 'hello.pl' dans l'exécutable 'a.out'
% pp -o hello hello.pl      # Empaquette 'hello.pl' dans l'exécutable 'hello'
                            # (ou 'hello.exe' sous Win32)
% pp -o foo foo.pl bar.pl   # Empaquette 'foo.pl' et 'bar.pl' dans 'foo'
% ./foo                     # Exécute 'foo.pl' à l'intérieur de 'foo'
% mv foo bar; ./bar         # Exécute 'bar.pl' à l'intérieur de 'foo'
% mv bar baz; ./baz         # Erreur : Impossible d'ouvrir le script perl "baz"
% pp -p file                # Crée un fichier PAR, 'a.par'
% pp -o hello a.par         # Empaquette 'a.par' en exécutable 'hello'
% pp -S -o hello file       # Combine les deux étapes ci-dessus
% pp -p -o out.par file     # Crée 'out.par' à partir de 'file'
% pp -B -p -o out.par file  # Identique à ci-dessus, mais regroupe les modules de base
                            # et supprime les chemins locaux de @INC
% pp -P -o out.pl file      # Crée 'out.pl' à partir de 'file'
% pp -B -p -o out.pl file   # Identique à ci-dessus, mais regroupe les modules de base
                            # et supprime les chemins locaux de @INC
                            # (-B est supposé lors de la création d'exécutables)
% pp -e "print 123"         # Empaquette une ligne de commande dans 'a.out'
% pp -p -e "print 123"      # Crée un fichier PAR 'a.par'
% pp -P -e "print 123"      # Crée un script perl 'a.pl'
% pp -c hello               # Vérifie les dépendances avec "perl -c hello"
% pp -x hello               # Vérifie les dépendances avec "perl hello"
% pp -n -x hello            # Identique à ci-dessus, mais ignore l'analyse statique
% pp -I /foo hello          # Chemins d'inclusion supplémentaires
% pp -M Foo::Bar hello      # Modules supplémentaires dans le chemin d'inclusion
% pp -M abbrev.pl hello     # Bibliothèques supplémentaires dans le chemin d'inclusion
% pp -X Foo::Bar hello      # Exclure les modules
% pp -a data.txt hello      # Fichiers de données supplémentaires
% pp -r hello               # Empaquette 'hello' dans 'a.out', exécute 'a.out'
% pp -r hello a b c         # Empaquette 'hello' dans 'a.out', exécute 'a.out'
                            # avec les arguments 'a b c'
% pp hello --log=c          # Empaquette 'hello' dans 'a.out', enregistre
                            # les messages dans 'c'
# Empaquette 'hello' dans un 'out.exe' sans console (Win32 uniquement)
% pp --gui -o out.exe hello
% pp @file hello.pl         # Empaquette 'hello.pl' mais lit des options _supplémentaires_
                            # à partir du fichier 'file'

DESCRIPTION

pp crée des exécutables autonomes à partir de programmes Perl, en utilisant le packager compressé fourni par PAR, et les heuristiques de détection de dépendances offertes par Module::ScanDeps. Les fichiers source sont compressés tels quels sans compilation.

Vous pouvez considérer pp comme "perlcc qui fonctionne sans tracas". :-)

Une interface graphique est également disponible sous le nom de commande tkpp.

Il ne fournit pas l'accélération de l'étape de compilation fournie par perlcc (cependant, voir -f ci-dessous pour les techniques de compilation en bytecode masquant la source), mais il compense cela par une meilleure fiabilité, une taille d'exécutable plus petite et une récupération complète du code source original.

Lorsqu'un seul programme d'entrée est spécifié, l'exécutable résultant se comportera de manière identique à ce programme. Cependant, lorsque plusieurs programmes sont empaquetés, l'exécutable produit exécutera celui dont le nom de base correspond à $0 (c'est-à-dire le nom du fichier utilisé pour l'invoquer). Si rien ne correspond, il meurt avec l'erreur "Can't open perl script \"$0\"".

OPTIONS

Les options sont disponibles sous forme courte et longue. Par exemple, les trois lignes ci-dessous sont toutes équivalentes :

% pp -o output.exe input.pl
% pp --output output.exe input.pl
% pp --output=output.exe input.pl

Comme les lignes de commande peuvent devenir suffisamment longues pour atteindre les limites imposées par certains shells, il est possible de faire lire à pp certaines de ses options à partir d'un ou plusieurs fichiers texte. L'utilisation de base consiste simplement à inclure un argument commençant par un sigil 'at' (@). Cet argument sera interprété comme un fichier à partir duquel lire les options. Le mélange d'options ordinaires et d'options @fichier est possible. Ceci est implémenté à l'aide du module Getopt::ArgvFile, lisez donc sa documentation pour une utilisation avancée. Notez que Getopt::ArgvFile est utilisé ici avec le paramètre "resolveEnvVars=1", c'est-à-dire que les sous-chaînes de la forme ${FOO"}" dans le contenu de @fichier sont remplacées par la valeur de la variable d'environnement FOO.

-a, --addfile=FICHIER|DIR
Ajouter un fichier supplémentaire dans le paquet. Si le fichier est un répertoire, ajoute récursivement tous les fichiers à l'intérieur de ce répertoire, en transformant les liens en fichiers réels.

Par défaut, les fichiers sont placés sous "/" à l'intérieur du paquet avec leurs noms d'origine. Vous pouvez outrepasser cela en ajoutant le nom du fichier cible après un ";", comme ceci :

% pp -a "ancien_nom_fichier.txt;nouveau_nom_fichier.txt"
% pp -a "ancien_nom_repertoire;nouveau_nom_repertoire"

Vous pouvez spécifier "-a" plusieurs fois.

-A, --addlist=FICHIER
Lire une liste de noms de fichiers/répertoires à partir de FICHIER, en les ajoutant au paquet. Chaque ligne dans FICHIER est traitée comme un argument pour -a ci-dessus.

Vous pouvez spécifier "-A" plusieurs fois.

-B, --bundle
Regrouper les modules de base dans le paquet résultant. Cette option est activée par défaut, sauf lorsque "-p" ou "-P" est spécifié.

Depuis la version 0.953 de PAR, cela supprime également tous les chemins locaux de la liste des chemins de recherche de modules @INC avant d'exécuter le script contenu.

-C, --clean
Nettoyer les fichiers temporaires extraits de l'application à l'exécution. Par défaut, ces fichiers sont mis en cache dans le répertoire temporaire ; cela permet au programme de démarrer plus rapidement la prochaine fois.
-c, --compile
Exécuter "perl -c fichier_entree" pour déterminer les dépendances d'exécution supplémentaires.
-cd, --cachedeps=FICHIER
Utiliser FICHIER pour mettre en cache les dépendances détectées. Crée FICHIER s'il est absent. Cela accélérera le processus d'analyse lors des exécutions ultérieures.
-d, --dependent
Réduire la taille de l'exécutable en n'incluant pas une copie de l'interpréteur Perl. Les exécutables construits de cette manière auront besoin d'un perl5x.dll ou libperl.so séparé pour fonctionner correctement. Cette option n'est disponible que si Perl est construit en tant que bibliothèque partagée.
-e, --eval=CHAINE
Empaqueter une ligne de commande, très similaire à "perl -e '...'"
-E, --evalfeature=CHAINE
Se comporte comme "-e", sauf qu'il active implicitement toutes les fonctionnalités optionnelles (dans l'unité de compilation principale) avec Perl 5.10 et versions ultérieures. Voir feature.
-x, --execute
Exécuter "perl fichier_entree" pour déterminer les dépendances d'exécution supplémentaires.

En utilisant cette option, pp peut être capable de détecter l'utilisation de modules qui ne peuvent pas être déterminés par une analyse statique de "fichier_entree". Les exemples incluent des éléments chargés par des chargeurs d'exécution comme Module::Runtime ou des chargeurs de type "plugin" comme Module::Loader. Notez que les modules détectés dépendent des parties de votre programme qui sont exercées lors de l'exécution de "fichier_entree". Par exemple, si votre programme se termine immédiatement lorsqu'il est exécuté comme "perl fichier_entree" parce qu'il manque d'arguments obligatoires, cette option n'aura probablement aucun effet. Vous pouvez utiliser --xargs pour fournir des arguments dans ce cas.

--xargs=ARGS
Fournit des arguments d'exécution à pp lors de l'utilisation de "-x". Par exemple, "--xargs -- 'arg1' 'arg2'" transmettra "arg1" et "arg2" à l'exécution de votre script.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

--xargs=CHAÎNE
Si -x est donné, divise la "CHAÎNE" en utilisant la fonction "shellwords" de Text::ParseWords et passe le résultat à @ARGV lors de l'exécution de "perl inputfile".
-X, --exclude=MODULE
Exclut le module donné du chemin de recherche des dépendances et du package. Si le fichier donné est un fichier zip, par ou exécutable par, tous les fichiers contenus dans le fichier donné (sauf MANIFEST, META.yml et script/*) seront exclus et le fichier de sortie "utilisera" le fichier donné à l'exécution.
-f, --filter=FILTRE
Filtre les scripts source avec une sous-classe de PAR::Filter. Vous pouvez spécifier plusieurs filtres de ce type.

Si vous souhaitez masquer le code source à la légère, voici comment faire :

% pp -f Bleach source.pl

Si vous êtes plus soucieux de masquer votre code source, vous devriez consulter le module PAR::Filter::Crypto de Steve Hay. Assurez-vous de comprendre les mises en garde de Filter::Crypto !

Remarque : La plupart des filtres sont incompatibles avec les sections "__DATA__" de votre source. L'exécutable packagé se termine généralement par un message d'erreur tel que

readline() on unopened filehandle DATA at (eval 13) line 3.
-g, --gui
Crée un exécutable qui n'a pas de fenêtre de console. Cette option est ignorée sur les plateformes autres que MSWin32 ou lorsque "-p" est spécifié.
-h, --help
Affiche les informations d'utilisation de base.
-I, --lib=DIR
Ajoute le répertoire donné au chemin de recherche des modules perl. Peut être spécifié plusieurs fois.
-l, --link=FICHIER|BIBLIOTHÈQUE
Ajoute la bibliothèque partagée donnée (également appelée objet partagé ou DLL) dans le fichier packagé. Accepte également les noms sous les chemins de bibliothèque ; c'est-à-dire "-l ncurses" signifie la même chose que "-l libncurses.so" ou "-l /usr/local/lib/libncurses.so" sur la plupart des systèmes Unix. Peut être spécifié plusieurs fois.
-L, --log=FICHIER
Journalise la sortie de l'empaquetage dans un fichier plutôt que sur stdout.
-F, --modfilter=FILTRE[=REGEX],
Filtre les modules perl inclus avec une sous-classe de PAR::Filter. Vous pouvez spécifier plusieurs filtres de ce type.

Par défaut, le filtre PodStrip est appliqué. Si cela pose problème, vous pouvez le désactiver en définissant la variable d'environnement "PAR_VERBATIM" sur 1.

Depuis PAR 0.958, vous pouvez utiliser une expression régulière optionnelle (REGEX ci-dessus) pour sélectionner les fichiers dans l'archive qui doivent être filtrés. L'expression régulière est mise en correspondance avec les noms de modules tels qu'ils apparaîtraient comme clés dans %INC, par exemple "Foo/Bar.pm" pour le module "Foo::Bar". Exemples :

pp -o foo.exe -F 'Bleach=warnings\.pm$' foo.pl

Ceci crée un exécutable binaire foo.exe à partir de foo.pl, empaquetant tous les fichiers comme d'habitude sauf ceux se terminant par "warnings.pm" qui sont filtrés avec PAR::Filter::Bleach.

pp -o foo.exe -F 'Bleach=^(?!Win32/)' foo.pl

Ceci "nettoie" tous les modules sauf ceux du namespace "Win32::".

Remarque : La même restriction sur les sections "__DATA__" s'applique que pour --filter.

-M, --module=MODULE
Ajoute le module spécifié dans le package, ainsi que ses dépendances.

Les variantes suivantes peuvent être utilisées pour ajouter des namespaces de modules entiers :

-M Foo::**
Ajoute chaque module dans le namespace "Foo" sauf "Foo" lui-même, c'est-à-dire ajoute "Foo::Bar", "Foo::Bar::Quux" etc jusqu'à n'importe quelle profondeur.
-M Foo::*
Ajoute chaque module au niveau 1 du namespace "Foo", c'est-à-dire ajoute "Foo::Bar", mais ni "Foo::Bar::Quux" ni "Foo".
-M Foo::
Raccourci pour "-M Foo -M Foo:**" : chaque module du namespace "Foo" incluant "Foo" lui-même.

Au lieu d'un nom de module, MODULE peut également être spécifié comme un nom de fichier relatif au chemin @INC, c'est-à-dire "-M Module/ScanDeps.pm" signifie la même chose que "-M Module::ScanDeps".

Si MODULE a une extension autre que ".pm"/".ix"/".al", il ne sera pas analysé pour les dépendances et sera placé sous "/" au lieu de "/lib/" dans le fichier PAR. Cette utilisation est dépréciée -- envisagez plutôt d'utiliser l'option -a.

Vous pouvez spécifier "-M" plusieurs fois.

-m, --multiarch
Crée un fichier PAR multi-architecture. Implique -p.
-n, --noscan
Ignore complètement l'analyse statique par défaut, en utilisant uniquement les dépendances d'exécution de -c ou -x.
-N, --namespace=NAMESPACE
Ajoute tous les modules du namespace dans le package, avec leurs dépendances. Si "NAMESPACE" est quelque chose comme "Foo::Bar" alors cela ajoutera tous les modules "Foo/Bar/Quux.pm", "Foo/Bar/Fred/Barnie.pm" etc qui peuvent être trouvés dans votre chemin de recherche de modules. Cela imite le comportement des chargeurs de "plugins" comme Module::Loader.

C'est différent de l'utilisation de "-M Foo::Bar::", car cette dernière insiste pour ajouter "Foo/Bar.pm" qui pourrait ne pas exister dans le scénario "plugin" ci-dessus.

Vous pouvez spécifier "-N" plusieurs fois.

-o, --output=FICHIER
Nom du fichier pour l'exécutable final packagé.
-p, --par
Crée uniquement des archives PAR ; n'empaquette pas en exécutable autonome.
-P, --perlscript
Crée un script perl autonome ; n'empaquette pas en exécutable autonome.
-r, --run
Exécute le script packagé résultant après l'avoir packagé.
--reusable
EXPÉRIMENTAL

Rend l'exécutable packagé réutilisable pour exécuter des scripts Perl externes arbitraires comme s'ils faisaient partie du package :

pp -o myapp --reusable someapp.pl
./myapp --par-options --reuse otherapp.pl

La deuxième ligne exécutera otherapp.pl au lieu de someapp.pl.

-S, --save
Ne supprime pas le fichier PAR généré après l'empaquetage.
-s, --sign
Signe cryptographiquement le fichier PAR ou binaire généré en utilisant Module::Signature.
-T, --tempcache
Définit la partie unique du programme du nom du répertoire de cache qui est utilisé si le programme est exécuté sans -C. Si non défini, un hachage de l'exécutable est utilisé.

Lorsque le programme est exécuté, son contenu est extrait dans un répertoire temporaire. Sur les systèmes Unix, il s'agit couramment de /tmp/par-USER/cache-XXXXXXX. USER est remplacé par le nom de l'utilisateur exécutant le programme, mais "épelé" en hexadécimal. XXXXXXX est soit un hachage de l'exécutable, soit la valeur passée au commutateur "-T" ou "--tempcache".

-u, --unicode
Remarque : Cette option est ignorée pour Perl 5.32 et supérieur.

Empaquette le support Unicode (essentiellement utf8_heavy.pl et tout ce qui se trouve sous le répertoire unicore dans votre bibliothèque perl).

Cette option existe car il est impossible de détecter par analyse statique si votre programme nécessite un support Unicode à l'exécution. (Remarque : Si votre programme contient "use utf8", cela n'implique pas qu'il nécessite un support Unicode. Cela dit simplement que votre code source est écrit en UTF-8.)

Si votre programme packagé se termine par un message d'erreur tel que

Can't locate utf8_heavy.pl in @INC (@INC contains: ...)

essayez de le packager avec "-u" (ou utilisez "-x").

-v, --verbose[=NOMBRE]
Augmente la verbosité de la sortie ; NOMBRE est un entier de 1 à 3, 3 étant le plus verbeux. Par défaut à 1 s'il est spécifié sans argument. Alternativement, -vv définit le niveau de verbosité à 2, et -vvv le définit à 3.
-V, --version
Affiche le numéro de version et les droits d'auteur de ce programme.
-z, --compress
b>=NUMÉRO
Définit le niveau de compression zip ; NUMÉRO est un entier de 0 à 9, 0 = aucune compression, 9 = compression maximale. La valeur par défaut est 6 si -z n'est pas utilisé.

ENVIRONNEMENT

PP_OPTS
Options de ligne de commande (commutateurs). Les commutateurs de cette variable sont traités comme s'ils figuraient sur chaque ligne de commande pp.

NOTES

Voici quelques recettes montrant comment utiliser pp pour regrouper source.pl avec toutes ses dépendances, sur des machines cibles avec différents paramètres attendus :

Configuration autonome :
Pour créer un exécutable autonome, adapté à l'exécution sur une machine qui n'a pas perl installé : 
% pp -o packed.exe source.pl        # crée packed.exe
# Maintenant, déployez 'packed.exe' sur la machine cible...
% packed.exe                        # exécutez-le
Interpréteur Perl uniquement, sans modules de base :
Pour créer un fichier .pl empaqueté incluant les modules de base, adapté à l'exécution sur une machine qui possède un interpréteur perl, mais où vous souhaitez être sûr des versions des modules de base que votre programme utilise : 
% pp -B -P -o packed.pl source.pl   # crée packed.pl
# Maintenant, déployez 'packed.pl' sur la machine cible...
% perl packed.pl                    # exécutez-le
Perl avec les modules de base installés :
Pour créer un fichier .pl empaqueté sans modules de base, en s'appuyant sur l'interpréteur perl de la machine cible et ses bibliothèques de base. Cela produit un fichier significativement plus petit que la version précédente : 
% pp -P -o packed.pl source.pl      # crée packed.pl
# Maintenant, déployez 'packed.pl' sur la machine cible...
% perl packed.pl                    # exécutez-le
Perl avec PAR.pm et ses dépendances installées :
Créez une archive et un exécutable séparés qui utilisent l'archive. Cela repose sur l'interpréteur perl et les bibliothèques de la machine cible. 
% pp -p source.pl                   # crée source.par
% echo "use PAR 'source.par';" > packed.pl;
% cat source.pl >> packed.pl;       # crée packed.pl
# Maintenant, déployez 'source.par' et 'packed.pl' sur la machine cible...
% perl packed.pl                    # exécutez-le, perl + modules de base requis

Notez que même si votre perl a été compilé avec une bibliothèque partagée, l'exécutable autonome ci-dessus n'aura pas besoin d'une perl5x.dll ou libperl.so séparée pour fonctionner correctement. Mais même dans ce cas, les bibliothèques système sous-jacentes telles que libc doivent être compatibles entre les machines hôte et cible. Utilisez "--dependent" si vous êtes prêt à expédier la bibliothèque partagée avec l'application, ce qui peut réduire considérablement la taille de l'exécutable.
