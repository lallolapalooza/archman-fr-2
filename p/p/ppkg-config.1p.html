NOM

PkgConfig - Remplacement Pure-Perl Core-Only pour pkg-config

SYNTAXE

En remplacement de "pkg-config"

$ ppkg-config --libs --cflags --static gio-2.0
#sortie (lignes artificiellement coupées pour la lisibilité) :
# -I/usr/include/glib-2.0 -I/usr/lib/glib-2.0/include
# -pthread -lgio-2.0 -lz -lresolv -lgobject-2.0
# -lgmodule-2.0 -ldl -lgthread-2.0 -pthread -lrt -lglib-2.0

"pkg-config.pl" peut être utilisé comme alias pour "ppkg-config" sur les plateformes qui le supportent. Il peut également être installé en tant que "pkg-config", bien que cela ne soit pas recommandé si votre système possède un "pkg-config" natif.

Comparaison avec :
$ pkg-config --libs --cflags --static gio-2.0

#sortie ( "" ) :
# -pthread -I/usr/include/glib-2.0 -I/usr/lib/glib-2.0/include
# -pthread -lgio-2.0 -lz -lresolv -lgobject-2.0 -lgmodule-2.0
# -ldl -lgthread-2.0 -lrt -lglib-2.0

Depuis un autre module Perl

use PkgConfig;
my $o = PkgConfig->find('gio');
if($o->errmsg) {
    # gérer l'erreur
} else {
    my $prefix = $o->get_var('prefix');
    my @cflags = $o->get_cflags;
    my @ldflags = $o->get_ldflags;
}

DESCRIPTION

"PkgConfig" fournit un remplacement pure-Perl, core-only, pour l'utilitaire "pkg-config".

Ceci n'est pas une description des utilisations de "pkg-config", mais plutôt une description des différences entre la version C et la version Perl.

Tandis que "pkg-config" est un binaire compilé lié à glib, la version pure-Perl n'a pas une telle exigence et fonctionnera partout où Perl ( >= 5.6 ) est disponible.

Les principales options supportées sont les options communes "--libs", "--cflags", "--static", "--exists" et "--modversion".

OPTIONS DU SCRIPT

UTILISATION

<nomdepaqueta1 nomdepaqueta2..> [ --options ]

ARGUMENTS

Par défaut, un nom de bibliothèque doit être fourni, sauf si l'une des options --version ou --real-version est spécifiée.

La sortie devrait normalement être appropriée pour être passée à votre compilateur préféré.

--libs

(Aussi) affiche les options de l'éditeur de liens. Les dépendances sont parcourues dans l'ordre. Les dépendances de haut niveau apparaîtront plus tôt dans la ligne de commande que les dépendances de bas niveau.

--libs-only-L

Affiche la partie -L/-R de "--libs". Elle définit le chemin de recherche des bibliothèques mais sans les bibliothèques à lier.

--libs-only-l

Affiche la partie -l de "--libs".

--libs-only-other

Affiche la partie de "--libs" qui n'est pas couverte par "--libs-only-L" et "--libs-only-l", comme "--pthread".

--list-all

Liste tous les paquets connus.

--cflags

(Aussi) affiche les options du compilateur et du préprocesseur C.

--cflags-only-I

Affiche la partie -I de "--cflags".

--cflags-only-other

Affiche les parties de "--cflags" qui ne sont pas couvertes par "--cflags-only-I".

--modversion

Affiche la version d'un paquet donné.

--static

Utilise des dépendances et des bibliothèques supplémentaires si on lie à une version statique de la bibliothèque demandée.

--exists

Retourne succès (0) si le paquet existe dans le chemin de recherche.

--with-path=CHEMIN

Ajoute "CHEMIN" au début de la liste des chemins de recherche contenant les fichiers ".pc".

Cette option peut être spécifiée plusieurs fois avec différents chemins, et ils seront tous ajoutés.

--env-only

Avec cette option, seuls les chemins spécifiés dans "PKG_CONFIG_PATH" sont reconnus et tous les défauts codés en dur sont ignorés.

--guess-paths

Appelle "gcc" et "ld" pour déterminer les chemins par défaut de l'éditeur de liens et des inclusions. Les chemins par défaut seront exclus des options explicites -L et -I.

--define-variable=VARIABLE=VALEUR

Définit une variable, remplaçant toute définition de variable de ce type dans le fichier .pc, et permettant à votre valeur d'interpoler avec des utilisations ultérieures.

--variable=VARIABLE

Retourne la valeur d'une variable définie dans le fichier .pc d'un paquet.

--print-variables

Affiche toutes les variables définies trouvées dans les fichiers .pc.

--version

La version cible de "pkg-config" émulée par ce script.

--real-version

La version réelle de ce script.

--debug

Affiche les informations de débogage.

--silence-errors

Désactive les erreurs. C'est le comportement par défaut pour les arguments autres que --libs/--cflags/--modversion.

--print-errors

Affiche les erreurs sur STDERR et a la priorité sur "--silence-errors".

--short-errors

Ignoré, mais reconnu pour des raisons de compatibilité.

--errors-to-stdout

Affiche les erreurs sur STDOUT et a la priorité sur "--print-errors".

ENVIRONNEMENT

Les variables "PKG_CONFIG_PATH" et "PKG_CONFIG_LIBDIR" sont respectées et utilisées comme une liste de répertoires délimités par des deux-points (ou points-virgules sous Windows) contenant les fichiers ".pc".

D'autres variables d'environnement reconnues par "pkg-config" et PkgConfig incluent :

PKG_CONFIG_ALLOW_SYSTEM_CFLAGS
PKG_CONFIG_ALLOW_SYSTEM_LIBS

Si Win32API::Registry est installé, sous Windows (mais pas Cygwin), PkgConfig consultera également ces clés de registre. Les noms sont ignorés, mais les valeurs sont des chemins contenant des fichiers ".pc".

HKEY_CURRENT_USER\Software\pkgconfig\PKG_CONFIG_PATH
HKEY_LOCAL_MACHINE\Software\pkgconfig\PKG_CONFIG_PATH

Le support du registre doit être considéré comme quelque peu expérimental, sujet à changement à l'avenir, bien que pas sans bonne raison. La justification de cette mise en garde est que cette fonctionnalité est documentée à plusieurs endroits, mais je n'ai pas encore trouvé de version fonctionnelle implémentant cette fonctionnalité.

OPTIONS DU MODULE

PkgConfig->find

my $result = PkgConfig->find($bibliotheque, %options);

Trouve une bibliothèque et retourne un objet résultat. $bibliotheque peut être soit un nom de bibliothèque unique, soit une référence à un tableau de noms de bibliothèques.

Les options sont sous forme de clés et valeurs de hachage, et les suivantes sont reconnues :

"search_path"
"search_path_override"
Ajoute des chemins de recherche en plus de ceux spécifiés dans $ENV{PKG_CONFIG_PATH}. La valeur est une référence de tableau.

La variante "_override" ignore les valeurs par défaut (comme "PKG_CONFIG_PATH").

"file_path"
Spécifie le chemin complet du fichier .pc que vous souhaitez charger. Il n'a pas besoin d'être dans le chemin de recherche (bien que ses dépendances doivent l'être). Utile si vous connaissez le chemin complet du fichier .pc exact que vous voulez.
"exclud

NOM

ppkg-config — interface Perl pour pkg-config

SYNOPIS

use PkgConfig;

my $o = PkgConfig->new('gtk+-2.0');
print $o->get_cflags;
print $o->get_ldflags;

my $exists = PkgConfig->exists('gtk+-2.0');
my $version = PkgConfig->version('gtk+-2.0');
my $cflags = PkgConfig->cflags('gtk+-2.0');
my $ldflags = PkgConfig->ldflags('gtk+-2.0');

my $o = PkgConfig->new(
    'gtk+-2.0',
    'glib-2.0',
    VARS => {
        'prefix' => '/opt/gtk',
        'exec_prefix' => '/opt/gtk',
    },
    no_recurse => 1,
    static => 1,
);

my $o = PkgConfig->new(qw(
    gtk+-2.0
    glib-2.0
));

DESCRIPTION

Ce module vous permet d'obtenir les indicateurs du compilateur et de l'éditeur de liens nécessaires pour construire des applications qui dépendent de bibliothèques spécifiques. Il utilise le programme pkg-config en arrière-plan pour interroger les fichiers .pc.

Vous pouvez créer un objet PkgConfig avec:

PkgConfig->new(PACKAGE, ... [, OPTIONS])
Crée un nouvel objet PkgConfig pour les paquets spécifiés. Les paquets peuvent être fournis sous forme d'arguments discrets ou sous forme de liste.
PkgConfig->exists(PACKAGE, ... [, OPTIONS])
Renvoie vrai si tous les paquets spécifiés existent.
PkgConfig->version(PACKAGE, ... [, OPTIONS])
Renvoie la chaîne de version la plus basse parmi les paquets spécifiés.
PkgConfig->cflags(PACKAGE, ... [, OPTIONS])
Renvoie les indicateurs du compilateur pour les paquets spécifiés.
PkgConfig->ldflags(PACKAGE, ... [, OPTIONS])
Renvoie les indicateurs de l'éditeur de liens pour les paquets spécifiés.
PkgConfig->vars(PACKAGE, ... [, OPTIONS])
Renvoie une table de hachage des variables définies dans les fichiers .pc pour les paquets spécifiés.

Les options suivantes peuvent être transmises à new, exists, version, cflags, ldflags et vars:

"exclude_cflags"
"exclude_ldflags"
"exclude_cflags_override"
"exclude_ldflags_override"
Certains fichiers .pc spécifient des chemins de recherche par défaut pour le compilateur et l'éditeur de liens, par exemple "-I/usr/include -L/usr/lib". Les spécifier en ligne de commande peut être problématique car cela modifie considérablement l'ordre de recherche.

Les options ci-dessus ajouteront ou remplaceront les options qui sont exclues et filtrées.

Les options par défaut exclues pour l'éditeur de liens et le compilateur peuvent être obtenues via @PkgConfig::DEFAULT_EXCLUDE_LFLAGS et @PkgConfig::DEFAULT_EXCLUDE_CFLAGS, respectivement.

"static"
Spécifier également les bibliothèques statiques.
"no_recurse"
Ne pas récursivité les dépendances. Ceci est utile pour simplement vérifier les versions.
"VARS"
Définit une table de hachage de variables pour remplacer toute définition de variable dans les fichiers .pc. Ceci est équivalent à l'option de ligne de commande "--define-variable".

Un objet PkgConfig est retourné et peut être interrogé sur les résultats:

$o->errmsg

Un message d'erreur, le cas échéant. C'est une chaîne de caractères qui indique une erreur.

$o->pkg_exists

Valeur booléenne, vrai si le paquet existe.

$o->pkg_version

La version du paquet

$o->get_cflags

$o->get_ldflags

Renvoie respectivement les indicateurs du compilateur et de l'éditeur de liens.

En contexte de liste, ces méthodes renvoient une liste avec chaque argument divisé par des espaces non échappés.

En contexte de liste, renvoie une liste d'indicateurs du compilateur et de l'éditeur de liens, respectivement.

En contexte scalaire, renvoie une chaîne d'indicateurs du compilateur et de l'éditeur de liens avec les espaces et les guillemets correctement échappés.

$o->get_var($name)

Obtenir la variable avec le nom donné.

PkgConfig->Guess

Il s'agit d'une méthode de classe, et elle remplacera les chemins par défaut de l'éditeur de liens et d'inclusion codés en dur par ceux découverts en invoquant ld(1) et cpp(1).

Actuellement, cela ne fonctionne qu'avec les "ld" fournis par GCC et le "ld" GNU.

INSTALL

Le "Makefile.PL" fourni avec "PkgConfig" peut accepter une ou plusieurs options "--script" pour modifier le nom du ou des scripts installés.

--script ppkg-config
C'est la valeur par défaut et cela fonctionne sur toutes les plateformes
--script pkg-config.pl
Ceci est installé par défaut sur toutes les plateformes sauf Windows, où le .pl peut confondre le shell et faire en sorte que le script soit ouvert dans un éditeur de texte.
--script pkg-config
C'est le nom par défaut du véritable "pkg-config" et vous devez donc l'activer spécifiquement si vous le souhaitez.
--script none
Ne pas installer de scripts.

Exemple, installation de tous les noms de scripts:

% perl Makefile.PL --script ppkg-config --script pkg-config.pl --script pkg-config

Exemple, ne pas installer de scripts:

% perl Makefile.PL --script none

Vous pouvez également définir la variable d'environnement PERL_PKG_CONFIG_SCRIPTS à la valeur --script désirée (en séparant chaque nom de script par une virgule ",") pour garantir que les mises à jour de PkgConfig fassent de même.

CAVEATS

Sur Strawberry Perl, "ppkg-config" agit comme si Strawberry était le système. Cela signifie que

  • Les fichiers .pc fournis avec Strawberry sont recherchés par défaut.
  • Les répertoires d'inclusion et de bibliothèque de Strawberry sont utilisés pour calculer les listes d'exclusion.

À partir de Strawberry 5.20.0.1, PkgConfig est fourni avec Strawberry et "pkg-config" est installé par défaut (en plus de "ppkg-config", bien que l'alias "ppkg-config" ne soit PAS fourni avec Strawberry lui-même).

Pour plus de détails sur la façon de patcher les fichiers .pc fournis avec les anciennes versions de Strawberry, voir le "README.win32" fourni avec cette distribution.

BUGS

L'ordre des indicateurs ne correspond pas exactement à celui de "pkg-config". D'après mes observations, il semble que ce module fasse un meilleur travail, mais je pourrais avoir tort.

Contrairement à "pkg-config", la fonction de script "--exists" renverra une valeur non nulle si un paquet ou l'une de ses dépendances est manquant. Ceci diffère du comportement de "pkg-config" qui vérifie uniquement la définition du paquet lui-même (sans les dépendances).
