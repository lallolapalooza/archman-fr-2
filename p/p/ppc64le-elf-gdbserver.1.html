GDBSERVER(1) Outils de développement GNU GDBSERVER(1)

NOM

gdbserver - Serveur distant pour le débogueur GNU

SYNTAXE

gdbserver comm prog [args...]

gdbserver --attach comm pid

gdbserver --multi comm

DESCRIPTION

gdbserver est un programme qui permet d'exécuter GDB sur une machine différente de celle qui exécute le programme en cours de débogage.

Utilisation (côté serveur (cible)) :

Premièrement, vous devez avoir une copie du programme que vous souhaitez déboguer sur le système cible. Le programme peut être dépouillé pour économiser de l'espace si nécessaire, car gdbserver ne se soucie pas des symboles. Toute la gestion des symboles est prise en charge par le GDB exécuté sur le système hôte.

Pour utiliser le serveur, connectez-vous au système cible et exécutez le programme gdbserver. Vous devez lui indiquer (a) comment communiquer avec GDB, (b) le nom de votre programme, et (c) ses arguments. La syntaxe générale est :

cible> gdbserver <comm> <programme> [<args> ...]

Par exemple, en utilisant un port série, vous pourriez dire :

cible> gdbserver /dev/com1 emacs foo.txt

Cela indique à gdbserver de déboguer emacs avec l'argument foo.txt, et de communiquer avec GDB via /dev/com1. gdbserver attend maintenant patiemment que le GDB hôte communique avec lui.

Pour utiliser une connexion TCP, vous pourriez dire :

cible> gdbserver hôte:2345 emacs foo.txt

Cela dit à peu près la même chose que l'exemple précédent, sauf que nous allons communiquer avec le GDB de l'"hôte" via TCP. L'argument "hôte:2345" signifie que nous nous attendons à voir une connexion TCP de "hôte" sur le port TCP local 2345. (Actuellement, la partie "hôte" est ignorée.) Vous pouvez choisir n'importe quel numéro de port tant qu'il ne conflit pas avec d'autres ports TCP existants sur le système cible. Ce même numéro de port doit être utilisé dans la commande "target remote" du GDB hôte, qui sera décrite sous peu. Notez que si vous choisissez un numéro de port qui entre en conflit avec un autre service, gdbserver affichera un message d'erreur et se terminera.

gdbserver peut également s'attacher à des programmes en cours d'exécution. Ceci est réalisé via l'argument --attach. La syntaxe est :

cible> gdbserver --attach <comm> <pid>

pid est l'identifiant de processus d'un processus en cours d'exécution. Il n'est pas nécessaire de pointer gdbserver vers un binaire pour le processus en cours d'exécution.

Pour démarrer "gdbserver" sans fournir de commande initiale à exécuter ou d'identifiant de processus à attacher, utilisez l'option de ligne de commande --multi. Dans ce cas, vous devriez vous connecter en utilisant "target extended-remote" pour démarrer le programme que vous souhaitez déboguer.

cible> gdbserver --multi <comm>

Utilisation (côté hôte) :

Vous avez besoin d'une copie non dépouillée du programme cible sur votre système hôte, car GDB doit examiner ses tables de symboles et autres. Démarrez GDB comme vous le feriez normalement, avec le programme cible comme premier argument. (Vous devrez peut-être utiliser l'option --baud si la ligne série fonctionne à autre chose que 9600 bauds.) C'est "gdb PROGRAMME-CIBLE", ou "gdb --baud BAUD PROGRAMME-CIBLE". Après cela, la seule nouvelle commande que vous devez connaître est "target remote" (ou "target extended-remote"). Son argument est soit un nom de périphérique (généralement un périphérique série, comme /dev/ttyb), soit un descripteur "HÔTE:PORT". Par exemple :

(gdb) target remote /dev/ttyb

communique avec le serveur via la ligne série /dev/ttyb, et :

(gdb) target remote cible:2345

communique via une connexion TCP au port 2345 sur l'hôte `cible', où vous avez précédemment lancé gdbserver avec le même numéro de port. Notez que pour les connexions TCP, vous devez lancer gdbserver avant d'utiliser la commande `target remote', sinon vous pourriez obtenir une erreur comme `Connection refused'.

gdbserver peut également déboguer plusieurs inférieurs à la fois, comme décrit dans le manuel GDB au nœud "Inferiors Connections and Programs" -- commande shell "info -f gdb -n 'Inferiors Connections and Programs'". Dans ce cas, utilisez la variante de commande GDB "extended-remote" :

(gdb) target extended-remote cible:2345

L'option --multi de gdbserver peut ou peut ne pas être utilisée dans ce cas.

OPTIONS

Il existe trois modes différents pour invoquer gdbserver :

  • Déboguer un programme spécifique spécifié par son nom de programme : 
    gdbserver <comm> <prog> [<args>...]

    Le paramètre comm spécifie comment le serveur doit communiquer avec GDB ; il s'agit soit d'un nom de périphérique (pour utiliser une ligne série), d'un numéro de port TCP (":1234"), soit de "-" ou "stdio" pour utiliser stdin/stdout de "gdbserver". Spécifiez le nom du programme à déboguer dans prog. Tous les arguments restants seront passés au programme tels quels. Lorsque le programme se termine, GDB fermera la connexion, et "gdbserver" se terminera.

  • Déboguer un programme spécifique en spécifiant l'ID de processus d'un programme en cours d'exécution : 
    gdbserver --attach <comm> <pid>

    Le paramètre comm est tel que décrit ci-dessus. Fournissez l'identifiant de processus d'un programme en cours d'exécution dans pid ; GDB fera le reste. Comme pour le mode précédent, lorsque le processus pid se termine, GDB fermera la connexion, et "gdbserver" se terminera.

  • Mode multi-processus -- déboguer plus d'un programme/processus : 
    gdbserver --multi <comm>

    Dans ce mode, GDB peut indiquer à gdbserver quelle(s) commande(s) exécuter. Contrairement aux 2 autres modes, GDB ne fermera pas la connexion lorsqu'un processus débogué se termine, vous pouvez donc déboguer plusieurs processus dans la même session.

Dans chacun des modes, vous pouvez spécifier ces options :

--help
Lister toutes les options, avec de brèves explications.
--version
Cette option fait afficher à gdbserver son numéro de version et quitter.
--attach
gdbserver s'attachera à un programme en cours d'exécution. La syntaxe est : 
cible> gdbserver --attach <comm> <pid>

pid est l'identifiant de processus d'un processus en cours d'exécution. Il n'est pas nécessaire de pointer gdbserver vers un binaire pour le processus en cours d'exécution.

--multi
Pour démarrer "gdbserver" sans fournir de commande initiale à exécuter ou d'identifiant de processus à attacher, utilisez cette option de ligne de commande. Ensuite, vous pouvez vous connecter en utilisant "target extended-remote" et démarrer le programme que vous souhaitez déboguer. La syntaxe est : 
cible> gdbserver --multi <comm>
--debug[=option1,option2,...]
Indique à "gdbserver" d'afficher des informations de statut supplémentaires sur le processus de débogage. Cette option est destinée au développement de "gdbserver" et aux rapports de bogues aux développeurs.

Chaque option est le nom d'un composant pour lequel le débogage doit être activé. La liste des options possibles est all, threads, event-loop, remote. L'option spéciale all active tous les composants. La liste des options est traitée de gauche à droite, et une option peut être préfixée par le caractère "-" pour désactiver la sortie pour ce composant, ainsi vous pourriez écrire :

cible> gdbserver --debug=all,-event-loop

pour activer la sortie de débogage pour tous les composants sauf event-loop. Si aucune option n'est passée à --debug, cela est traité comme équivalent à --debug=thre

gdbserver(1) — ppc64le-elf-gdbserver — Arch Linux manual pages

NOM

gdbserver — un outil pour déboguer des programmes sur une machine distante.

SYNTAXE

gdbserver [--authority=file] [--debug] [--debug-file=filename]
    [--debug-format=option1[,option2,...]] [--wrapper] [--once]
    [host:]port program [args ...]
gdbserver --multi [host:]port program [args ...]

DESCRIPTION

gdbserver est un programme qui s'exécute sur la machine cible et qui vous permet de déboguer un programme s'exécutant sur cette machine distante depuis un GDB sur votre machine hôte. Il écoute les connexions GDB sur un port TCP spécifié, lance le programme spécifié, puis utilise les fonctionnalités de débogage à distance de GDB pour permettre à GDB de contrôler l'exécution du programme.

gdbserver prend en charge le mode multi-connexions via l'option --multi. Dans ce mode, gdbserver ne quitte pas après la déconnexion d'une session GDB, mais continue d'écouter les connexions GDB entrantes, permettant à plusieurs sessions GDB de déboguer le même processus.

OPTIONS

--debug
Active la sortie de débogage interne de "gdbserver". Le format de cette sortie peut changer dans les futures versions de "gdbserver".
--debug-file=filename
Demande à "gdbserver" d'envoyer toute sortie de débogage au fichier filename spécifié. Cette option est destinée au développement de "gdbserver" et aux rapports de bugs aux développeurs.
--debug-format=option1[,option2,...]
Demande à "gdbserver" d'inclure des informations supplémentaires dans chaque ligne de sortie de débogage.
--wrapper
Spécifie un wrapper pour lancer des programmes à des fins de débogage. L'option doit être suivie du nom du wrapper, puis de tous les arguments de ligne de commande à passer au wrapper, puis de "--" indiquant la fin des arguments du wrapper.
--once
Par défaut, gdbserver maintient le port TCP d'écoute ouvert, de sorte que des connexions supplémentaires sont possibles. Cependant, si vous lancez "gdbserver" avec l'option --once, il cessera d'écouter toute nouvelle tentative de connexion après s'être connecté à la première session GDB.

VOIR AUSSI

La documentation complète de GDB est maintenue sous forme de manuel Texinfo. Si les programmes "info" et "gdb" ainsi que la documentation Texinfo de GDB sont correctement installés sur votre site, la commande

info gdb

devrait vous donner accès au manuel complet.

Using GDB: A Guide to the GNU Source-Level Debugger, Richard M. Stallman et Roland H. Pesch, juillet 1991.
