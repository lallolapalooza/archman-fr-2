DESCRIPTION

GNU as est vraiment une famille d'assembleurs. Si vous utilisez (ou avez utilisé) l'assembleur GNU sur une architecture, vous devriez trouver un environnement assez similaire lorsque vous l'utilisez sur une autre architecture. Chaque version a beaucoup en commun avec les autres, y compris les formats de fichiers objets, la plupart des directives d'assembleur (souvent appelées pseudo-ops) et la syntaxe de l'assembleur.

as est principalement destiné à assembler la sortie du compilateur C GNU "gcc" pour une utilisation par l'éditeur de liens "ld". Néanmoins, nous avons essayé de faire en sorte que as assemble correctement tout ce que d'autres assembleurs pour la même machine assembleraient. Toute exception est documentée explicitement. Cela ne signifie pas que as utilise toujours la même syntaxe qu'un autre assembleur pour la même architecture ; par exemple, nous connaissons plusieurs versions incompatibles de la syntaxe du langage d'assemblage 680x0.

Chaque fois que vous exécutez as, il assemble un seul programme source. Le programme source est composé d'un ou plusieurs fichiers. (L'entrée standard est également un fichier.)

Vous donnez à as une ligne de commande qui contient zéro ou plusieurs noms de fichiers d'entrée. Les fichiers d'entrée sont lus (du premier nom de fichier au dernier). Un argument de ligne de commande (n'importe où) qui n'a pas de signification spéciale est considéré comme un nom de fichier d'entrée.

Si vous ne donnez aucun nom de fichier à as, il tente de lire un fichier d'entrée à partir de l'entrée standard de as, qui est normalement votre terminal. Vous devrez peut-être taper ctl-D pour indiquer à as qu'il n'y a plus de programme à assembler.

Utilisez -- si vous devez explicitement nommer le fichier d'entrée standard dans votre ligne de commande.

Si la source est vide, as produit un petit fichier objet vide.

as peut écrire des avertissements et des messages d'erreur dans le fichier d'erreur standard (généralement votre terminal). Cela ne devrait pas arriver lorsqu'un compilateur exécute as automatiquement. Les avertissements signalent une hypothèse faite pour que as puisse continuer à assembler un programme défectueux ; les erreurs signalent un problème grave qui arrête l'assemblage.

Si vous invoquez as via le compilateur C GNU, vous pouvez utiliser l'option -Wa pour transmettre des arguments à l'assembleur. Les arguments de l'assembleur doivent être séparés les uns des autres (et de -Wa) par des virgules. Par exemple :

gcc -c -g -O -Wa,-alh,-L file.c

Cela transmet deux options à l'assembleur : -alh (émettre une liste sur la sortie standard avec la source de haut niveau et la source d'assemblage) et -L (conserver les symboles locaux dans la table des symboles).

Généralement, vous n'avez pas besoin d'utiliser ce mécanisme -Wa, car de nombreuses options de ligne de commande du compilateur sont automatiquement transmises à l'assembleur par le compilateur. (Vous pouvez appeler le pilote du compilateur GNU avec l'option -v pour voir précisément quelles options il transmet à chaque passe de compilation, y compris l'assembleur.)

OPTIONS

@file
Lit les options de la ligne de commande depuis file. Les options lues sont insérées à la place de l'option @file d'origine. Si file n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans file sont séparées par des espaces. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière soit de guillemets simples, soit de guillemets doubles. N'importe quel caractère (y compris un backslash) peut être inclus en précédant le caractère à inclure d'un backslash. Le file peut lui-même contenir des options @file supplémentaires ; toutes les options de ce type seront traitées récursivement.

--alternate
Commencer en mode macro alternatif.
--compress-debug-sections
Compresser les sections de débogage DWARF en utilisant zlib avec SHF_COMPRESSED de l'ABI ELF. Le fichier objet résultant peut ne pas être compatible avec les anciens linkers et utilitaires de fichiers objet. Notez que si la compression rend une section donnée plus grande, elle n'est pas compressée.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Ces options contrôlent la compression des sections de débogage DWARF. --compress-debug-sections=none est équivalent à --nocompress-debug-sections. --compress-debug-sections=zlib et --compress-debug-sections=zlib-gabi sont équivalents à --compress-debug-sections. --compress-debug-sections=zlib-gnu compresse les sections de débogage DWARF en utilisant le format obsolète zlib-gnu. Les sections de débogage sont renommées pour commencer par .zdebug. --compress-debug-sections=zstd compresse les sections de débogage DWARF en utilisant zstd. Notez que si la compression rend une section plus grande, elle n'est ni compressée ni renommée.
--nocompress-debug-sections
Ne pas compresser les sections de débogage DWARF. C'est généralement la valeur par défaut pour toutes les cibles sauf x86/x86_64, mais une option de configuration peut être utilisée pour outrepasser cela.
-D
Activer le débogage dans les backends spécifiques à la cible, si pris en charge. Sinon, ignoré. Même s'il est ignoré, cette option est acceptée pour la compatibilité des scripts avec les appels à d'autres assembleurs.
--debug-prefix-map ancien=nouveau
Lors de l'assemblage de fichiers dans le répertoire ancien, enregistrez les informations de débogage les décrivant comme étant dans nouveau à la place.
--defsym sym=valeur
Définir le symbole sym à valeur avant d'assembler le fichier d'entrée. valeur doit être une constante entière. Comme en C, un 0x préfixant indique une valeur hexadécimale, et un 0 préfixant indique une valeur octale. La valeur du symbole peut être remplacée à l'intérieur d'un fichier source via l'utilisation d'une pseudo-instruction ".set".
--dump-config
Affiche la configuration de l'assembleur puis quitte.
--elf-stt-common=no
--elf-stt-common=yes
Ces options contrôlent si l'assembleur ELF doit générer des symboles communs avec le type "STT_COMMON". La valeur par défaut peut être contrôlée par une option de configuration --enable-elf-stt-common.
--emulation=nom
Si l'assembleur est configuré pour prendre en charge plusieurs configurations de cible différentes, cette option peut être utilisée pour sélectionner la forme désirée.
-f
"fast"---sauter le pré-traitement des espaces blancs et des commentaires (supposer que la source est la sortie du compilateur).
-g
--gen-debug
Générer des informations de débogage pour chaque ligne source de l'assembleur en utilisant le format de débogage préféré par la cible. Cela signifie actuellement soit STABS, ECOFF ou DWARF2. Lorsque le format de débogage est DWARF, une section ".debug_info" et une section ".debug_line" ne sont émises que si le fichier d'assemblage n'en génère pas lui-même.
--gstabs
Générer des informations de débogage stabs pour chaque ligne de l'assembleur. Cela peut aider à déboguer le code de l'assembleur, si le débogueur peut le gérer.
--gstabs+
Générer des informations de débogage stabs pour chaque ligne de l'assembleur, avec des extensions GNU que probablement seul gdb peut gérer, et qui pourraient faire planter d'autres débogueurs ou refuser de lire votre programme. Cela peut aider à déboguer le code de l'assembleur. Actuellement, la seule extension GNU est l'emplacement du répertoire de travail courant au moment de l'assemblage.
--gdwarf-2
Générer des informations de débogage DWARF2 pour chaque ligne de l'assembleur. Cela peut aider à déboguer le code de l'assembleur, si le débogueur peut le gérer. Notez que cette option n'est prise en charge que par certaines cibles, pas toutes.
--gdwarf-3
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires conformément à la version 3 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire est spécifique à chaque cible.
--gdwarf-4
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires conformément à la version 4 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire est spécifique à chaque cible.
--gdwarf-5
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires conformément à la version 5 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire est spécifique à chaque cible.
--gdwarf-sections
Au lieu de créer une section .debug_line, créer une série de sections .debug_line.foo où foo est le nom de la section de code correspondante. Par exemple, une section de code appelée .text.func aura ses informations de ligne de débogage placées dans une section appelée .debug_line.text.func. Si la section de code est simplement appelée .text, la section de ligne de débogage sera toujours appelée simplement .debug_line sans suffixe.
--gdwarf-cie-version=version
Contrôle quelle version des entrées d'informations communes DWARF (CIE) est produite. Lorsque ce drapeau n'est pas spécifié, la valeur par défaut est la version 1, bien que certaines cibles puissent modifier cette valeur par défaut. D'autres valeurs possibles pour version sont 3 ou 4.
--generate-missing-build-notes=yes
--generate-missing-build-notes=no
Ces options contrôlent si l'assembleur ELF doit générer des notes d'attributs GNU Build s'il n'y en a pas dans les sources d'entrée. La valeur par défaut peut être contrôlée par l'option de configuration --enable-generate-build-notes.

--gsframe
Créer une section .sframe à partir des directives CFI.
--hash-size N
Ignoré. Pris en charge pour la compatibilité de la ligne de commande avec d'autres assembleurs.
--help
Imprimer un résumé des options de la ligne de commande et quitter.

-J

-march=CPU[-EXT...][+EXT...]
Cette option spécifie le processeur cible. L'assembleur émettra un message d'erreur si une tentative est faite pour assembler une instruction qui ne s'exécutera pas sur le processeur cible. Les noms de processeurs suivants sont reconnus : "z80", "z180", "ez80", "gbz80", "z80n", "r800". En plus de l'ensemble d'instructions de base, l'assembleur peut être invité à accepter certaines extensions de mnémoniques. Par exemple, "-march=z180+sli+infc" étend z180 avec les instructions SLI et IN F,(C). Les extensions suivantes sont actuellement prises en charge : "full" (toutes les instructions connues), "adl" (mode CPU ADL par défaut, eZ80 uniquement), "sli" (instruction connue sous le nom de SLI, SLL ou SL1), "xyhl" (instructions avec les moitiés des registres d'index : IXL, IXH, IYL, IYH), "xdcb" (instructions comme RotOp (II+d),R et BitOp n,(II+d),R), "infc" (instruction IN F,(C) ou IN (C)), "outc0" (instruction OUT (C),0). Notez qu'au lieu d'étendre un ensemble d'instructions de base, les mnémoniques d'extension commençant par "-" révoquent la fonctionnalité respective : "-march=z80-full+xyhl" supprime d'abord toutes les extensions par défaut et ajoute uniquement la prise en charge des moitiés de registres d'index.

Si cette option n'est pas spécifiée, "-march=z80+xyhl+infc" est supposée.

-local-prefix=prefixe
Marque toutes les étiquettes avec le préfixe spécifié comme locales. Mais une telle étiquette peut être marquée comme globale explicitement dans le code. Cette option ne modifie pas le préfixe d'étiquette locale par défaut ".L", elle en ajoute simplement un nouveau.
-colonless
Accepte les étiquettes sans deux-points. Tous les symboles au début d'une ligne sont traités comme des étiquettes.
-sdcc
Accepte le code assembleur produit par SDCC.
-fp-s=FORMAT
Format des nombres à virgule flottante de précision simple. Par défaut : ieee754 (32 bits).
-fp-d=FORMAT
Format des nombres à virgule flottante de précision double. Par défaut : ieee754 (64 bits).
