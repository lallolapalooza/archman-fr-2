PPTPD.CONF(5) Manuel des formats de fichiers PPTPD.CONF(5)

NOM

pptpd.conf - Configuration du démon VPN PPTP

DESCRIPTION

pptpd(8) lit les options de ce fichier, généralement /etc/pptpd.conf. La plupart des options peuvent être remplacées par la ligne de commande. Les adresses IP locales et distantes pour les clients doivent provenir du fichier de configuration ou des fichiers de configuration de pppd(8).

OPTIONS

option fichier-options
le nom d'un fichier d'options à passer à pppd(8) à la place du fichier par défaut /etc/ppp/options afin que des options spécifiques à PPTP puissent être données. Équivalent à l'option de ligne de commande --option.
stimeout secondes
nombre de secondes à attendre un paquet PPTP avant de lancer le programme pptpctrl(8) pour gérer le client. La valeur par défaut est 10 secondes. Il s'agit d'une mesure de protection contre le déni de service. Équivalent à l'option de ligne de commande --stimeout.
logwtmp
met à jour wtmp(5) lors de la connexion et de la déconnexion des utilisateurs. Voir wtmp(1).
debug
active le mode de débogage, envoyant des informations de débogage à syslog(3). N'a aucun effet sur le débogage de pppd(8). Équivalent à l'option de ligne de commande --debug.
bcrelay interface-interne
active le mode relais de diffusion, envoyant toutes les diffusions reçues sur l'interface interne du serveur aux clients. Équivalent à l'option de ligne de commande --bcrelay.
connections n
limite le nombre de connexions client pouvant être acceptées. Si pptpd alloue des adresses IP (par exemple, si delegate n'est pas utilisé), le nombre de connexions est également limité par l'option remoteip. La valeur par défaut est 100.
delegate
délègue l'allocation des adresses IP client à pppd(8). Sans cette option, qui est le comportement par défaut, pptpd gère la liste des adresses IP pour les clients et transmet la prochaine adresse libre à pppd. Avec cette option, pptpd ne transmet pas d'adresse, et pppd peut donc utiliser radius ou chap-secrets pour allouer une adresse.
localip spécification-ip
une ou plusieurs adresses IP à utiliser à l'extrémité locale des liens PPP tunnelisés entre le serveur et le client. Si une seule adresse est donnée, cette adresse est utilisée pour tous les clients. Sinon, une adresse par client doit être donnée, et s'il n'y a pas d'adresses libres, tout nouveau client sera refusé. localip sera ignoré si l'option delegate est utilisée.
remoteip spécification-ip
une liste d'adresses IP à attribuer aux clients PPTP distants. Chaque client connecté doit avoir une adresse différente, il doit donc y avoir au moins autant d'adresses que vous avez de clients simultanés, et de préférence quelques-unes en réserve, car vous ne pouvez pas modifier cette liste sans redémarrer pptpd. Un avertissement sera envoyé à syslog(3) lorsque le pool d'adresses IP est épuisé. remoteip sera ignoré si l'option delegate est utilisée.
noipparam
par défaut, l'adresse IP d'origine du client est fournie aux scripts ip-up en utilisant l'option ipparam de pppd(8). L'option noipparam empêche cela. Équivalent à l'option de ligne de commande --noipparam option.
listen adresse-ip
l'adresse IP de l'interface locale sur laquelle écouter les connexions PPTP entrantes (port TCP 1723). Équivalent à l'option de ligne de commande --listen option.
vrf nom-vrf
VRF à utiliser pour le socket d'écoute TCP ainsi que pour les paquets GRE. Équivalent à l'option de ligne de commande --vrf.
pidfile fichier-pid
spécifie un emplacement alternatif pour stocker le fichier d'identifiant de processus (par défaut /var/run/pptpd.pid). Équivalent à l'option de ligne de commande --pidfile option.
speed vitesse
spécifie une vitesse (en bits par seconde) à passer au démon PPP comme vitesse de l'interface pour la paire tty/pty. Ceci est ignoré par certains démons PPP, comme pppd(8) de Linux. La valeur par défaut est 115200 octets par seconde, ce qui est interprété par certaines implémentations comme signifiant "aucune limite". Équivalent à l'option de ligne de commande --speed.

NOTES

Une spécification-ip ci-dessus (pour les balises localip et remoteip) peut être une liste d'adresses IP (par exemple 192.168.0.2,192.168.0.3), une plage (par exemple 192.168.0.1-254 ou 192.168.0-255.2) ou une combinaison (par exemple 192.168.0.2,192.168.0.5-8). Voici quelques exemples de paires valides (selon l'utilisation du VPN) :

localip 192.168.0.1
remoteip 192.168.0.2-254

ou

localip 192.168.1.2-254
remoteip 192.168.0.2-254

LISTE DE VÉRIFICATION ROUTAGE - PROXYARP

Allouez une section de vos adresses LAN pour une utilisation par les clients.

Dans /etc/ppp/options.pptpd., définissez l'option proxyarp. Dans pptpd.conf, ne définissez pas l'option localip, mais définissez remoteip sur la plage d'adresses allouée. Activez le transfert de paquets par le noyau (par exemple, en utilisant /proc/sys/net/ipv4/ip_forward ).

Le serveur annoncera les clients au LAN en utilisant ARP, en fournissant sa propre adresse Ethernet. bcrelay(8) ne devrait pas être nécessaire.

LISTE DE VÉRIFICATION ROUTAGE - TRANSFERT

Allouez un sous-réseau pour les clients qui est routable depuis votre LAN, mais qui n'en fait pas partie.

Dans pptpd.conf, définissez localip sur une adresse unique ou une plage dans le sous-réseau alloué, définissez remoteip sur une plage dans le sous-réseau alloué. Activez le transfert de paquets par le noyau (par exemple, en utilisant /proc/sys/net/ipv4/ip_forward ). Le LAN doit avoir une route vers les clients en utilisant le serveur comme passerelle.

Le serveur transférera les paquets inchangés entre les clients et le LAN. bcrelay(8) sera nécessaire pour prendre en charge les protocoles de diffusion tels que NETBIOS.

LISTE DE VÉRIFICATION ROUTAGE - MASQUERADE

Allouez un sous-réseau pour les clients qui n'est pas routable depuis votre LAN, et qui n'est pas autrement routable depuis le serveur (par exemple, 10.0.0.0/24).

Définissez localip sur une adresse unique dans le sous-réseau (par exemple, 10.0.0.1), définissez remoteip sur une plage pour le reste du sous-réseau (par exemple, 10.0.0.2-200). Activez le transfert de paquets par le noyau (par exemple, en utilisant /proc/sys/net/ipv4/ip_forward ). Activez le masquage sur eth0 (par exemple, iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE ).

Le serveur traduira les paquets entre les clients et le LAN. Les clients apparaîtront au LAN comme ayant l'adresse correspondant au serveur. Le LAN n'a pas besoin d'avoir une route explicite vers les clients. bcrelay(8) sera nécessaire pour prendre en charge les protocoles de diffusion tels que NETBIOS.

RÈGLES PARE-FEU

pptpd(8) accepte les connexions de contrôle sur le port TCP 1723, puis utilise GRE (protocole 47) pour échanger des paquets de données. Ajoutez ces règles à votre configuration iptables(8), ou utilisez-les comme base pour vos propres règles :

iptables --append INPUT --protocol 47 --jump ACCEPT 

iptables --append INPUT --protocol tcp --match tcp \
         --destinat
pptpd.conf(5) — pptpd 1.5.0-1 — Arch Linux

NAME

pptpd.conf - configuration file for the Point-to-Point Protocol Daemon

DESCRIPTION

The pptpd daemon allows arbitrary clients to connect to arbitrary servers via the Point-to-Point Protocol (PPP). It uses the standard TCP port 1723.

The configuration file is divided into global options and per-server options.

The configuration file syntax is a subset of the sendmail configuration language. You should consult the sendmail documentation for details on how to write configuration files.

Comments start with a # character and continue to the end of the line.

OPTIONS

The following options may be specified in the global section of the configuration file:

[global]
debug
Enable debugging.
logwtmp
Log connections in wtmp.
local
Allow connections from the local machine.
remoteip=ip range
Specify the range of IP addresses to be assigned to clients. The IP addresses must be in the same subnet as the server's IP address. The range can be specified as a comma separated list of IP addresses or network addresses.
domain=domain name
Specify the domain name to be used for clients.
bcrelay=ip address
Specify the IP address of a broadcast relay agent.
delegate=yes|no
Delegate control of the connection to the PPP daemon. Defaults to yes.
proxyarp=yes|no
Enable or disable proxy ARP. Defaults to no.
msdomain=domain name
Specify the domain name to be used for clients. This option is equivalent to domain but is used by Microsoft clients.
msencrypt=yes|no
Enable or disable Microsoft encryption. Defaults to yes.
mschap=yes|no
Enable or disable MS-CHAP authentication. Defaults to yes.
mschap-retry=seconds
Specify the number of times to retry MS-CHAP authentication.
mschap-interval=seconds
Specify the interval between MS-CHAP authentication retries.
refuse-pap
Refuse PAP authentication.
refuse-chap
Refuse CHAP authentication.
refuse-mschap
Refuse MS-CHAP authentication.
refuse-mschap-v2
Refuse MS-CHAPv2 authentication.
require-pap
Require PAP authentication.
require-chap
Require CHAP authentication.
require-mschap
Require MS-CHAP authentication.
require-mschap-v2
Require MS-CHAPv2 authentication.
[server]
server name
Specify the name of the server. This is used to identify the server in log messages.
ip address
Specify the IP address of the server. This is used to identify the server in log messages.
ip range
Specify the range of IP addresses to be assigned to clients. This is used to identify the server in log messages.
domain name
Specify the domain name to be used for clients. This is used to identify the server in log messages.
max connections
Specify the maximum number of connections allowed for this server.
require authentication
Specify the type of authentication required for this server.
require encryption
Specify the type of encryption required for this server.

NOTES

The pptpd.conf file is read by the pptpd daemon at startup. Changes to the configuration file will not take effect until the daemon is restarted.

The pptpd daemon uses the /etc/ppp/chap-secrets file for user authentication. This file should contain the username, password, and any other options for each user.

The pptpd daemon uses the /etc/ppp/options file for PPP options. This file should contain the PPP options that will be used for each connection.

ROUTING CHECKLIST - PROXYARP

If you are using proxyarp, you should have the following in your /etc/sysctl.conf file:

net.ipv4.ip_forward = 1
net.ipv4.conf.default.proxy_arp = 1
net.ipv4.conf.all.proxy_arp = 1
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0

And run the following commands:

sysctl -w net.ipv4.ip_forward=1
sysctl -w net.ipv4.conf.default.proxy_arp=1
sysctl -w net.ipv4.conf.all.proxy_arp=1
sysctl -w net.ipv4.conf.all.send_redirects=0
sysctl -w net.ipv4.conf.default.send_redirects=0

ROUTING CHECKLIST - FORWARDING

If you are not using proxyarp, you should have the following in your /etc/sysctl.conf file:

net.ipv4.ip_forward = 1
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0

And run the following commands:

sysctl -w net.ipv4.ip_forward=1
sysctl -w net.ipv4.conf.all.send_redirects=0
sysctl -w net.ipv4.conf.default.send_redirects=0

ROUTING CHECKLIST - MASQUERADE

If you are using masquerade (NAT), you should have the following in your /etc/sysctl.conf file:

net.ipv4.ip_forward = 1
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0

And run the following commands:

sysctl -w net.ipv4.ip_forward=1
sysctl -w net.ipv4.conf.all.send_redirects=0
sysctl -w net.ipv4.conf.default.send_redirects=0

And add the following rule to your firewall:

iptables -t nat -A POSTROUTING -j MASQUERADE

FIREWALL RULES

You need to allow incoming connections on TCP port 1723:

iptables -A INPUT -p tcp --syn --dport 1723 -j ACCEPT

You also need to allow GRE protocol traffic:

iptables -A INPUT -p gre -j ACCEPT

If you are using proxyarp, you should also allow traffic from the clients to the internet:

iptables -A FORWARD -p tcp --syn -s 192.168.0.0/24 -j ACCEPT
iptables -A FORWARD -p udp -s 192.168.0.0/24 -j ACCEPT
iptables -A FORWARD -p icmp -s 192.168.0.0/24 -j ACCEPT
iptables -t nat -A POSTROUTING -s 192.168.0.0/24 -j MASQUERADE

Replace 192.168.0.0/24 with the IP range of your clients.

If you are not using proxyarp, you will need to set up static routes on your clients to route traffic to the server.

The following example allows connections from clients with IP address range 192.168.0.0/24 to access the internet through the server:

iptables -A FORWARD -i ppp0 -o eth0 -s 192.168.0.0/24 -j ACCEPT
iptables -A FORWARD -i eth0 -o ppp0 -d 192.168.0.0/24 -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -t nat -A POSTROUTING -o eth0 -s 192.168.0.0/24 -j MASQUERADE

Replace ppp0 with the PPP interface name and eth0 with your internet-facing interface name.

If you want to block all other traffic, you can add the following rule at the end:

iptables -A FORWARD -j REJECT

To allow clients to access the internet through the server, you need to enable IP forwarding and masquerading. You can do this by adding the following lines to your /etc/sysctl.conf file:

net.ipv4.ip_forward = 1
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0

Then, run the following commands:

sysctl -w net.ipv4.ip_forward=1
sysctl -w net.ipv4.conf.all.send_redirects=0
sysctl -w net.ipv4.conf.default.send_redirects=0

And add the following rule to your firewall:

iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

Replace eth0 with your internet-facing interface name.

This example shows how to allow only PPTP traffic to pass through the firewall and be NATed.

iptables -A INPUT -i eth0 -p tcp --dport 1723 -j ACCEPT
iptables -A INPUT -i eth0 -p gre -j ACCEPT
iptables -A FORWARD -i ppp0 -o eth0 -j ACCEPT
iptables -A FORWARD -i eth0 -o ppp0 -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

This example allows only PPTP traffic from a specific client IP address 192.168.0.100 to pass through the firewall and be NATed.

iptables -A INPUT -i eth0 -p tcp --dport 1723 -s 192.168.0.100 -j ACCEPT
iptables -A INPUT -i eth0 -p gre -s 192.168.0.100 -j ACCEPT
iptables -A FORWARD -i ppp0 -o eth0 -s 192.168.0.100 -j ACCEPT
iptables -A FORWARD -i eth0 -o ppp0 -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -t nat -A POSTROUTING -o eth0 -s 192.168.0.100 -j MASQUERADE

This example denies PPTP traffic from a specific client IP address 192.168.0.100.

iptables -A INPUT -i eth0 -p tcp --dport 1723 -s 192.168.0.100 -j REJECT
iptables -A INPUT -i eth0 -p gre -s 192.168.0.100 -j REJECT

This example allows only PPTP traffic to pass through the firewall and be NATed for specific port 1723.

iptables -A INPUT -p tcp --dport 1723 -j ACCEPT
iptables -A INPUT -p gre -j ACCEPT
iptables -A FORWARD -i ppp0 -o eth0 -j ACCEPT
iptables -A FORWARD -i eth0 -o ppp0 -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

This example denies all traffic except PPTP traffic from the specific port 1723.

iptables -A INPUT -p tcp --dport 1723 -j ACCEPT
iptables -A INPUT -p gre -j ACCEPT
iptables -A FORWARD -i ppp0 -o eth0 -j ACCEPT
iptables -A FORWARD -i eth0 -o ppp0 -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

This example allows only PPTP traffic from a specific client IP address 192.168.0.100 to pass through the firewall and be NATed for the specific port 1723.

iptables -A INPUT -p tcp --dport 1723 -s 192.168.0.100 -j ACCEPT
iptables -A INPUT -p gre -s 192.168.0.100 -j ACCEPT
iptables -A FORWARD -i ppp0 -o eth0 -s 192.168.0.100 -j ACCEPT
iptables -A FORWARD -i eth0 -o ppp0 -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -t nat -A POSTROUTING -o eth0 -s 192.168.0.100 -j MASQUERADE

This example denies PPTP traffic from a specific client IP address 192.168.0.100 for the specific port 1723.

iptables -A INPUT -p tcp --dport 1723 -s 192.168.0.100 -j REJECT
iptables -A INPUT -p gre -s 192.168.0.100 -j REJECT
