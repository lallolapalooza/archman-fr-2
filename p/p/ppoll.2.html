poll(2) Manuel des appels système poll(2)

NOM

poll, ppoll - attendre un événement sur un descripteur de fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <poll.h>
int poll(struct pollfd *fds, nfds_t nfds, int timeout);
#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <poll.h>
int ppoll(struct pollfd *fds, nfds_t nfds,
          const struct timespec *_Nullable tmo_p,
          const sigset_t *_Nullable sigmask);

DESCRIPTION

poll() effectue une tâche similaire à select(2) : il attend qu'un descripteur de fichier parmi un ensemble devienne prêt pour effectuer des opérations d'E/S. L'API spécifique à Linux, epoll(7), effectue une tâche similaire, mais offre des fonctionnalités qui vont au-delà de celles de poll().

L'ensemble des descripteurs de fichiers à surveiller est spécifié dans l'argument fds, qui est un tableau de structures de la forme suivante :


struct pollfd {
    int   fd;         /* descripteur de fichier */
    short events;     /* événements demandés */
    short revents;    /* événements retournés */
};

L'appelant doit spécifier le nombre d'éléments dans le tableau fds via nfds.

Le champ fd contient un descripteur de fichier pour un fichier ouvert. Si ce champ est négatif, alors le champ events correspondant est ignoré et le champ revents retourne zéro. (Ceci fournit un moyen simple d'ignorer un descripteur de fichier pour un seul appel à poll() : il suffit de définir le champ fd à son complément bit à bit.)

Le champ events est un paramètre d'entrée, un masque de bits spécifiant les événements auxquels l'application s'intéresse pour le descripteur de fichier fd. Ce champ peut être défini à zéro, auquel cas les seuls événements qui peuvent être retournés dans revents sont POLLHUP, POLLERR et POLLNVAL (voir ci-dessous).

Le champ revents est un paramètre de sortie, rempli par le noyau avec les événements qui se sont réellement produits. Les bits retournés dans revents peuvent inclure n'importe lequel de ceux spécifiés dans events, ou l'une des valeurs POLLERR, POLLHUP, ou POLLNVAL. (Ces trois bits sont sans signification dans le champ events, et seront définis dans le champ revents chaque fois que la condition correspondante est vraie.)

Si aucun des événements demandés (et aucune erreur) ne s'est produit pour l'un des descripteurs de fichiers, alors poll() bloque jusqu'à ce qu'un des événements se produise.

Être "prêt" signifie que l'opération demandée ne bloquera pas ; par conséquent, l'appel à poll() sur des fichiers réguliers, des périphériques de blocage et d'autres fichiers sans sémantique de polling raisonnable retourne *toujours* instantanément comme étant prêt à lire et à écrire.

Notez que l'intervalle de timeout sera arrondi à la granularité de l'horloge système, et que les délais de planification du noyau signifient que l'intervalle de blocage peut dépasser ce délai d'une petite quantité. Spécifier une valeur négative pour timeout signifie un timeout infini. Spécifier un timeout de zéro provoque un retour immédiat de poll(), même si aucun descripteur de fichier n'est prêt.

Les bits qui peuvent être définis/retournés dans events et revents sont définis dans <poll.h> :

POLLIN
Il y a des données à lire.
POLLPRI
Il y a une condition exceptionnelle sur le descripteur de fichier. Les possibilités incluent :
•
Il y a des données hors bande sur une socket TCP (voir tcp(7)).
•
Un maître de pseudo-terminal en mode paquet a vu un changement d'état sur l'esclave (voir ioctl_tty(2)).
•
Un fichier cgroup.events a été modifié (voir cgroups(7)).
POLLOUT
L'écriture est maintenant possible, bien qu'une écriture plus grande que l'espace disponible dans une socket ou un pipe bloquera toujours (sauf si O_NONBLOCK est défini).
POLLRDHUP (depuis Linux 2.6.17)
La paire de la socket de flux a fermé la connexion, ou a arrêté la moitié d'écriture de la connexion. Le macro de test de fonctionnalité _GNU_SOURCE doit être défini (avant d'inclure *quel* que soit les fichiers d'en-tête) afin d'obtenir cette définition.
POLLERR
Condition d'erreur (seulement retourné dans revents ; ignoré dans events). Ce bit est également défini pour un descripteur de fichier faisant référence à l'extrémité d'écriture d'un pipe lorsque l'extrémité de lecture a été fermée.
POLLHUP
Raccrochement (seulement retourné dans revents ; ignoré dans events). Notez que lors de la lecture d'un canal tel qu'un pipe ou une socket de flux, cet événement indique simplement que la paire a fermé son extrémité du canal. Les lectures ultérieures du canal retourneront 0 (fin de fichier) uniquement après que toutes les données en attente dans le canal aient été consommées.
POLLNVAL
Requête invalide : fd non ouvert (seulement retourné dans revents ; ignoré dans events).

Lors de la compilation avec _XOPEN_SOURCE défini, on a également les éléments suivants, qui ne véhiculent pas plus d'informations que les bits listés ci-dessus :

POLLRDNORM
Équivalent à POLLIN.
POLLRDBAND
Des données de bande prioritaire peuvent être lues (généralement non utilisé sous Linux).
POLLWRNORM
Équivalent à POLLOUT.
POLLWRBAND
Des données prioritaires peuvent être écrites.

Linux connaît également, mais n'utilise pas, POLLMSG.

ppoll()

La relation entre poll() et ppoll() est analogue à la relation entre select(2) et pselect(2) : comme pselect(2), ppoll() permet à une application d'attendre de manière sûre jusqu'à ce qu'un descripteur de fichier devienne prêt ou jusqu'à ce qu'un signal soit capturé.

À part la différence de précision de l'argument timeout, l'appel ppoll() suivant :


ready = ppoll(&fds, nfds, tmo_p, &sigmask);

est presque équivalent à l'exécution *atomique* des appels suivants :


sigset_t origmask;
int timeout;
timeout = (tmo_p == NULL) ? -1 :
          (tmo_p->tv_sec * 1000 + tmo_p->tv_nsec / 1000000);
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = poll(&fds, nfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

Le segment de code ci-dessus est décrit comme *presque* équivalent parce que, alors qu'une valeur négative de timeout pour poll() est interprétée comme un timeout infini, une valeur négative exprimée dans *tmo_p entraîne une erreur de ppoll().

Voir la description de pselect(2) pour une explication de la nécessité de ppoll().

Si l'argument sigmask est spécifié comme NULL, alors aucune manipulation de masque de signal n'est effectuée (et donc ppoll() ne diffère de poll() que par la précision de l'argument timeout).

L'argument tmo_p spécifie une limite supérieure sur la durée pendant laquelle ppoll() bloquera. Cet argument est un pointeur vers une structure timespec(3).

Si tmo_p est spécifié comme NULL, alors ppoll() peut bloquer indéfiniment.

VALEUR DE RETOUR

Au succès, poll() et ppoll() retournent le nombre de structures de descripteurs de fichiers dont le champ revents n'est pas nul (c'est-à-dire les descripteurs de fichiers qui sont prêts ou qui ont une condition d'erreur). Ce nombre peut être zéro si un timeout a été spécifié et qu'aucun événement ne s'est produit.

En cas d'échec, poll() et ppoll() retournent -1 et définissent errno pour indiquer l'erreur.

ERREURS

Les erreurs peuvent inclure :

EBADF
Un des descripteurs de fichiers dans fds n'est pas valide.
EINTR
Un appel système a été interrompu par un signal avant que l'un des descripteurs de fichiers ne soit prêt et que le timeout n'expire.
EINVAL
L'argument nfds est plus grand que le nombre maximal de descripteurs de fichiers autorisés pour ce processus, ou l'argument fds est NULL, ou la valeur de timeout est invalide (par exemple, négative pour ppoll()).
ENOMEM
Mémoire insuffisante.
POLLERR
Une erreur s'est produite sur le descripteur de fichier spécifié.

CONFORMITÉ

poll() est conforme à POSIX.1-2001. Les bits POLLRDHUP et POLLMSG sont spécifiques à Linux.

ppoll() est une extension GNU, introduite dans la version 2.6.16 du noyau.

EXEMPLES

Exemple simple

    #include <stdio.h>
    #include <stdlib.h>
    #include <poll.h>
    #include <errno.h>

    int main(void) {
        struct pollfd fds[2];
        int ret;

        /* Surveiller stdin et stdout */
        fds[0].fd = 0; /* stdin */
        fds[0].events = POLLIN;
        fds[1].fd = 1; /* stdout */
        fds[1].events = POLLOUT;

        ret = poll(fds, 2, -1); /* -1 = timeout infini */

        if (ret == -1) {
            perror("poll");
            exit(EXIT_FAILURE);
        }

        if (ret > 0) {
            if (fds[0].revents & POLLIN)
                printf("stdin est prêt à être lu\n");
            if (fds[1].revents & POLLOUT)
                printf("stdout est prêt à être écrit\n");
        } else {
            printf("Timeout expiré (ne devrait pas arriver ici)\n");
        }

        exit(EXIT_SUCCESS);
    }

Exemple avec ppoll()

L'exemple suivant montre comment utiliser ppoll() pour attendre que des données soient disponibles sur stdin tout en masquant temporairement un ensemble de signaux.

    #include <stdio.h>
    #include <stdlib.h>
    #include <poll.h>
    #include <errno.h>
    #include <time.h>
    #include <signal.h>

    int main(void) {
        struct pollfd fds;
        struct timespec ts;
        sigset_t mask, orig_mask;

        /* Initialiser le descripteur de fichier à surveiller (stdin) */
        fds.fd = 0; /* stdin */
        fds.events = POLLIN;

        /* Initialiser le timeout (par exemple, 5 secondes) */
        ts.tv_sec = 5;
        ts.tv_nsec = 0;

        /* Initialiser le masque de signaux pour masquer SIGINT et SIGTERM */
        sigemptyset(&mask);
        sigaddset(&mask, SIGINT);
        sigaddset(&mask, SIGTERM);

        /* Appeler ppoll en attendant les données sur stdin et en gérant les signaux */
        int ret = ppoll(&fds, 1, &ts, &mask);

        if (ret == -1) {
            /* Vérifier si l'erreur est due à un signal interrompant ou autre chose */
            if (errno == EINTR) {
                printf("ppoll interrompu par un signal.\n");
                /* Ici, vous pouvez vérifier quel signal a été reçu si nécessaire */
            } else {
                perror("ppoll");
                exit(EXIT_FAILURE);
            }
        } else if (ret == 0) {
            printf("Timeout expiré.\n");
        } else {
            /* Vérifier si des données sont disponibles sur stdin */
            if (fds.revents & POLLIN) {
                printf("Des données sont disponibles sur stdin.\n");
                /* Procéder à la lecture des données */
            }
        }

        /* Le masque de signaux original est restauré automatiquement après l'appel à ppoll */

        exit(EXIT_SUCCESS);
    }

ALUE'>VALEUR DE RETOUR

En cas de succès, poll() renvoie une valeur non négative qui est le nombre d'éléments dans pollfds dont les champs revents ont été définis à une valeur non nulle (indiquant un événement ou une erreur). Une valeur de retour de zéro indique que l'appel système a expiré avant que tout descripteur de fichier ne soit prêt.

En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
fds pointe en dehors de l'espace d'adressage accessible du processus. Le tableau fourni en argument n'était pas contenu dans l'espace d'adressage du programme appelant.
EINTR
Un signal s'est produit avant qu'un événement demandé ne se produise ; voir signal(7).
EINVAL
La valeur nfds dépasse la valeur RLIMIT_NOFILE.
EINVAL
(ppoll()) La valeur du délai d'attente exprimée dans *tmo_p est invalide (négative).
ENOMEM
Impossible d'allouer de la mémoire pour les structures de données du noyau.

VERSIONS

Sur certains autres systèmes UNIX, poll() peut échouer avec l'erreur EAGAIN si le système ne parvient pas à allouer de ressources internes au noyau, plutôt qu'avec ENOMEM comme le fait Linux. POSIX autorise ce comportement. Les programmes portables peuvent souhaiter vérifier EAGAIN et boucler, tout comme avec EINTR.

Certaines implémentations définissent la constante non standard INFTIM avec la valeur -1 pour l'utiliser comme timeout pour poll(). Cette constante n'est pas fournie dans glibc.

Différences C library/noyau

L'appel système Linux ppoll() modifie son argument tmo_p. Cependant, la fonction wrapper glibc masque ce comportement en utilisant une variable locale pour l'argument de délai d'attente qui est passé à l'appel système. Ainsi, la fonction glibc ppoll() ne modifie pas son argument tmo_p.

L'appel système brut ppoll() a un cinquième argument, size_t sigsetsize, qui spécifie la taille en octets de l'argument sigmask. La fonction wrapper glibc ppoll() spécifie cet argument comme une valeur fixe (égale à sizeof(kernel_sigset_t)). Voir sigprocmask(2) pour une discussion sur les différences entre la notion de sigset du noyau et celle de libc.

NORMES

HISTORIQUE

POSIX.1-2001. Linux 2.1.23.
Sur les anciens noyaux qui ne disposent pas de cet appel système, la fonction wrapper glibc poll() fournit une émulation utilisant select(2).
ppoll()
POSIX.1-2024. Linux 2.6.16, glibc 2.4.

NOTES

L'opération de poll() et ppoll() n'est pas affectée par le flag O_NONBLOCK.

Pour une discussion sur ce qui peut se produire si un descripteur de fichier surveillé par poll() est fermé dans un autre thread, voir select(2).

BOGUES

Voir la discussion sur les notifications de disponibilité fallacieuses dans la section BUGS de select(2).

EXEMPLES

Le programme ci-dessous ouvre chacun des fichiers nommés dans ses arguments de ligne de commande et surveille les descripteurs de fichiers résultants pour la disponibilité en lecture (POLLIN). Le programme boucle, utilisant répétitivement poll() pour surveiller les descripteurs de fichiers, affichant le nombre de descripteurs de fichiers prêts au retour. Pour chaque descripteur de fichier prêt, le programme :

•
affiche le champ revents retourné sous une forme lisible ;
•
si le descripteur de fichier est lisible, lit certaines données à partir de celui-ci et affiche ces données sur la sortie standard ; et
•
si le descripteur de fichier n'était pas lisible, mais qu'un autre événement s'est produit (probablement POLLHUP), ferme le descripteur de fichier.

Supposons que nous exécutons le programme dans un terminal, en lui demandant d'ouvrir un FIFO :


$ mkfifo myfifo;
$ ./poll_input myfifo;

Dans une seconde fenêtre de terminal, nous ouvrons ensuite le FIFO en écriture, écrivons des données dedans et fermons le FIFO :


$ echo aaaaabbbbbccccc > myfifo;

Dans le terminal où nous exécutons le programme, nous verrions alors :


Opened "myfifo" on fd 3
About to poll()
Ready: 1
  fd=3; events: POLLIN POLLHUP
    read 10 bytes: aaaaabbbbb
About to poll()
Ready: 1
  fd=3; events: POLLIN POLLHUP
    read 6 bytes: ccccc
About to poll()
Ready: 1
  fd=3; events: POLLHUP
    closing fd 3
All file descriptors closed.  Bye.

Dans la sortie ci-dessus, nous voyons que poll() a renvoyé trois fois :

•
Lors du premier retour, les bits retournés dans le champ revents étaient POLLIN, indiquant que le descripteur de fichier est lisible, et POLLHUP, indiquant que l'autre extrémité du FIFO a été fermée. Le programme a ensuite consommé une partie de l'entrée disponible.
•
Le deuxième retour de poll() a également indiqué POLLIN et POLLHUP ; le programme a ensuite consommé la dernière entrée disponible.
•
Lors du dernier retour, poll() a indiqué uniquement POLLHUP sur le FIFO, moment auquel le descripteur de fichier a été fermé et le programme s'est terminé.

Source du programme

/* poll_input.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <fcntl.h>
#include <poll.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int            ready;
    char           buf[10];
    nfds_t         num_open_fds, nfds;
    ssize_t        s;
    struct pollfd  *pfds;
    if (argc < 2) {
       fprintf(stderr, "Usage: %s file...\n", argv[0]);
       exit(EXIT_FAILURE);
    }
    num_open_fds = nfds = argc - 1;
    pfds = calloc(nfds, sizeof(struct pollfd));
    if (pfds == NULL)
        err(EXIT_FAILURE, "malloc");
    /* Open each file on command line, and add it to 'pfds' array.  */
    for (nfds_t j = 0; j < nfds; j++) {
        pfds[j].fd = open(argv[j + 1], O_RDONLY);
        if (pfds[j].fd == -1)
            err(EXIT_FAILURE, "open");
        printf("Opened \"%s\" on fd %d\n", argv[j + 1], pfds[j].fd);
        pfds[j].events = POLLIN;
    }
    /* Keep calling poll() as long as at least one file descriptor is
       open.  */
    while (num_open_fds > 0) {
        printf("About to poll()\n");
        ready = poll(pfds, nfds, -1);
        if (ready == -1)
            err(EXIT_FAILURE, "poll");
        printf("Ready: %d\n", ready);
        /* Deal with array returned by poll().  */
        for (nfds_t j = 0; j < nfds; j++) {
            if (pfds[j].revents != 0) {
                printf("  fd=%d; events: %s%s%s\n", pfds[j].fd,
                       (pfds[j].revents & POLLIN)  ? "POLLIN "  : "",
                       (pfds[j].revents & POLLHUP) ? "POLLHUP " : "",
                       (pfds[j].revents & POLLERR) ? "POLLERR " : "");
                if (pfds[j].revents & POLLIN) {
                    s = read(pfds[j].fd, buf, sizeof(buf));
                    if (s == -1)
                        err(EXIT_FAILURE, "read");
                    printf("    read %zd bytes: %.*s\n",
                           s, (int) s, buf);
                } else {                /* POLLERR | POLLHUP */
                    printf("    closing fd %d\n", pfds[j].fd);
                    if (close(pfds[j].fd) == -1)
                        err(EXIT_FAILURE, "close");
                    num_open_fds--;
                }
            }
        }
    }
    printf("All file descriptors closed.  Bye.\n");
    exit(EXIT_SUCCESS);
}
