NOM

ppmtoxpm - convertir une image PPM en une pixmap X11

SYNTAXE

ppmtoxpm [-nom=nomxpm] [-hexseulement] [-rgb=fichiertexte-rgb] [-masquealpha=fichierpgm] [fichierppm]

L'abréviation unique minimale d'une option est acceptable. Vous pouvez utiliser des doubles tirets au lieu d'un simple tiret pour indiquer les options. Vous pouvez utiliser des espaces blancs à la place du signe égal pour séparer un nom d'option de sa valeur.

DESCRIPTION

Ce programme fait partie de Netpbm(1)

ppmtoxpm lit une image PPM en entrée et produit une pixmap X11 (version 3) en sortie. Ce format peut être chargé par la bibliothèque XPM.

Dans la sortie XPM, les couleurs peuvent être identifiées par leur nom, comme "Rouge", ou en hexadécimal, par exemple "#FF0000". En format hexadécimal, il peut y avoir de 1 à 4 chiffres hexadécimaux par composante RVB.

Par défaut, ppmtoxpbm essaie de trouver un nom pour chaque couleur de l'image dans le dictionnaire de couleurs système, et s'il en trouve un, il l'utilise. Sinon, il utilise l'hexadécimal. Vous pouvez forcer ppmtoxpbm à utiliser uniquement l'hexadécimal avec l'option -hexseulement. Vous pouvez spécifier un dictionnaire de couleurs différent avec l'option -rgb.

Lorsque ppmtoxpm utilise le format hexadécimal pour identifier une couleur, il utilise celui qui nécessite le moins de chiffres hexadécimaux pour représenter la valeur maximale de l'image PPM d'entrée. Par exemple, si la valeur maximale de l'image PPM d'entrée est 100, ppmtoxpm utilise 2 chiffres par composante, comme dans "#FF0000".

Certains programmes ne gèrent pas correctement les spécificateurs de couleur hexadécimaux à un chiffre par composante. Ils voient les mauvaises couleurs. Pour produire un XPM qu'un tel programme peut gérer, assurez-vous que la valeur maximale de l'image PPM d'entrée est supérieure à 15, par exemple en la traitant avec pamdepth 255.

Longueurs de codes de couleur - Taille d'image

Dans le format XPM, il y a une palette ('table des couleurs') qui associe chaque couleur de l'image à une séquence unique de caractères imprimables appelée code de couleur, et un raster qui identifie la couleur de chaque pixel de l'image avec l'un de ces codes de couleur. La longueur du code de couleur affecte la taille du flux d'images.

Tous les codes de couleur d'une image ont la même longueur, et ppmtoxpm essaie de la rendre aussi courte que possible. Cette longueur est, bien sûr, déterminée par le nombre de couleurs dans l'image. ppmtoxpm compte les couleurs dans l'image, en excluant celles qui seront transparentes dans la sortie à cause de votre masque alpha, et choisit une longueur de code de couleur en conséquence. Il y a 92 caractères imprimables qui peuvent être utilisés dans un code de couleur. Par conséquent, si vous avez 92 couleurs ou moins, vos codes de couleur auront un caractère. Si vous avez plus de 92 mais pas plus de 92 * 92, vos codes de couleur auront deux caractères. Et ainsi de suite.

Il y a une exception à ce qui précède : si vous spécifiez un masque alpha (l'option -alpha), un code de couleur unique représente 'transparent'. C'est vrai même si le masque alpha ne produit réellement aucun pixel transparent. Soustrayez donc un du nombre de couleurs possibles si vous utilisez -alpha.

OPTIONS

-nom=nomxpm
Cette option spécifie la chaîne de préfixe qui est spécifiée dans la sortie XPM résultante. Si vous n'utilisez pas l'option -nom, ppmtoxpm utilise par défaut le nom du fichier (sans extension) du paramètre fichierppm. Si vous ne spécifiez ni -nom ni fichierppm (c'est-à-dire que votre entrée provient de l'entrée standard), la chaîne de préfixe prendra par défaut la chaîne noname.
-hexseulement
Cette option indique de ne jamais mettre de noms de couleur dans le fichier XPM, mais plutôt d'identifier les noms par des chaînes hexadécimales qui identifient explicitement les intensités des composantes RVB. Cela signifie que le lecteur du fichier n'a pas besoin d'avoir accès à un dictionnaire de couleurs approprié pour l'interpréter.

Cette option a été introduite dans Netpbm 10.15 (avril 2003). Avant cela, c'était le comportement par défaut, remplacé par la spécification de -rgb.

-rgb=fichiertexte-rgb
Cette option nomme le fichier dans lequel réside le dictionnaire de couleurs que vous souhaitez utiliser. Par défaut, ppmtoxpm utilise le dictionnaire de couleurs système, et s'il ne peut pas ouvrir ce fichier, il utilise des spécificateurs de couleur hexadécimaux.

Cette option est dénuée de sens lorsque vous spécifiez -hexseulement.

Avant Netpbm 10.15 (avril 2003), ppmtoxpm n'utilisait pas le dictionnaire de couleurs système par défaut. Si vous ne spécifiiez pas -rgb, ppmtoxpbm utilisait uniquement des spécificateurs de couleur hexadécimaux.

-masquealpha=fichierpgm

Cette option nomme un fichier PGM à utiliser comme masque alpha (transparence). Le fichier doit contenir une image de mêmes dimensions que l'image d'entrée. ppmtoxpm marque comme transparente toute position de pixel dans l'image du masque alpha qui est au plus à moitié blanche.

Si vous ne spécifiez pas -masquealpha, ppmtoxpm rend tous les pixels de la sortie opaques.

ppmcolormask est une façon de générer un fichier de masque alpha. Vous pourriez également le générer en extrayant des informations de transparence d'un fichier XPM avec l'option -alphaout de xpmtoppm.

Il existe des options similaires sur d'autres convertisseurs Netpbm qui convertissent également à partir de formats incluant des informations de transparence.
