NOM

pidfile_open, pidfile_write, pidfile_close, pidfile_remove, pidfile_fileno — bibliothèque de gestion des fichiers PID

BIBLIOTHÈQUE

bibliothèque « libbsd »

SYNTAXE

#include <libutil.h> (Voir libbsd(7) pour l'utilisation des inclusions.)
struct pidfh *
pidfile_open(const char *path, mode_t mode, pid_t *pidptr);

int
pidfile_write(struct pidfh *pfh);

int
pidfile_close(struct pidfh *pfh);

int
pidfile_remove(struct pidfh *pfh);

int
pidfile_fileno(struct pidfh *pfh);

DESCRIPTION

La famille de fonctions pidfile permet aux démons de gérer les fichiers PID. Elle utilise flopen(3bsd) pour verrouiller un fichier PID et détecter les démons déjà en cours d'exécution.

La fonction pidfile_open() ouvre (ou crée) un fichier spécifié par l'argument path et le verrouille. Si l'argument pidptr n'est pas NULL et que le fichier ne peut pas être verrouillé, la fonction l'utilisera pour stocker le PID d'un démon déjà en cours d'exécution ou -1 dans le cas où le démon n'a pas encore écrit son PID. La fonction n'écrit pas le PID du processus dans le fichier à ce stade, elle peut donc être utilisée avant de faire un fork() et de sortir avec un message d'erreur approprié si nécessaire. Si l'argument path est NULL, le fichier /var/run/⟨nomprog⟩.pid sera utilisé. La fonction pidfile_open() définit l'indicateur close-on-exec (fermeture à l'exécution) O_CLOEXEC lors de l'ouverture du fichier PID.

La fonction pidfile_write() écrit le PID du processus dans un fichier précédemment ouvert. Le fichier est tronqué avant l'écriture, donc l'appel de la fonction pidfile_write() plusieurs fois est supporté.

La fonction pidfile_close() ferme un fichier PID. Elle doit être utilisée après que le démon a fait un fork() pour démarrer un processus enfant.

La fonction pidfile_remove() ferme et supprime un fichier PID.

La fonction pidfile_fileno() renvoie le descripteur de fichier du fichier PID ouvert.

VALEURS DE RETOUR

La fonction pidfile_open() renvoie un pointeur valide vers une structure pidfh en cas de succès, ou NULL en cas d'erreur. En cas d'erreur, errno sera défini.


Les fonctions pidfile_write(), pidfile_close() et pidfile_remove() renvoient la valeur 0 en cas de succès ; sinon, la valeur -1 est renvoyée et la variable globale errno est définie pour indiquer l'erreur.

La fonction pidfile_fileno() renvoie le descripteur de fichier de bas niveau. Elle renvoie -1 et définit errno si un pidfh NULL est spécifié, ou si le fichier PID n'est plus ouvert.

EXEMPLES

L'exemple suivant montre dans quel ordre ces fonctions doivent être utilisées. Notez qu'il est sûr de passer NULL aux fonctions pidfile_write(), pidfile_remove(), pidfile_close() et pidfile_fileno().

struct pidfh *pfh;
pid_t otherpid, childpid;

pfh = pidfile_open("/var/run/daemon.pid", 0600, &otherpid);
if (pfh == NULL) {
	if (errno == EEXIST) {
		errx(EXIT_FAILURE, "Daemon already running, pid: %jd.",
		    (intmax_t)otherpid);
	}
	/* Si nous ne pouvons pas créer le fichier PID pour d'autres raisons, nous avertissons seulement. */
	warn("Cannot open or create pidfile");
	/*
	 * Même si pfh est NULL, nous pouvons continuer, car les autres fonctions pidfile_*
	 * peuvent gérer une telle situation en ne faisant rien sauf définir
	 * errno à EINVAL.
	 */
}

if (daemon(0, 0) == -1) {
	warn("Cannot daemonize");
	pidfile_remove(pfh);
	exit(EXIT_FAILURE);
}

pidfile_write(pfh);

for (;;) {
	/* Faire le travail. */
	childpid = fork();
	switch (childpid) {
	case -1:
		syslog(LOG_ERR, "Cannot fork(): %s.", strerror(errno));
		break;
	case 0:
		pidfile_close(pfh);
		/* Faire le travail enfant. */
		break;
	default:
		syslog(LOG_INFO, "Child %jd started.", (intmax_t)childpid);
		break;
	}
}

pidfile_remove(pfh);
exit(EXIT_SUCCESS);

ERREURS

La fonction pidfile_open() échouera si :

[EEXIST]
Un processus détient déjà le verrou sur le fichier PID donné, ce qui signifie qu'un démon est déjà en cours d'exécution. Si l'argument pidptr n'est pas NULL, la fonction l'utilisera pour stocker le PID d'un démon déjà en cours d'exécution ou -1 dans le cas où le démon n'a pas encore écrit son PID.
[ENAMETOOLONG]
Le nom du fichier PID spécifié est trop long.
[EINVAL]
Un processus détient déjà le verrou sur le fichier PID donné, mais le PID lu est invalide.

La fonction pidfile_open() peut également échouer et définir errno pour toutes les erreurs spécifiées pour les appels fstat(2), open(2) et read(2).

La fonction pidfile_write() échouera si :

[EINVAL]
Mauvaise utilisation de la fonction. Probablement appelée avant pidfile_open().

La fonction pidfile_write() peut également échouer et définir errno pour toutes les erreurs spécifiées pour les appels fstat(2), ftruncate(2) et write(2).

La fonction pidfile_close() peut échouer et définir errno pour toutes les erreurs spécifiées pour les appels close(2) et fstat(2).

La fonction pidfile_remove() échouera si :

[EINVAL]
Mauvaise utilisation de la fonction. Probablement appelée depuis un processus autre que celui qui a fait pidfile_write().

La fonction pidfile_remove() peut également échouer et définir errno pour toutes les erreurs spécifiées pour les appels close(2), fstat(2), write(2), et pidfile_write(3bsd) — libbsd documentation

NAME

pidfile_write, pidfile_close, pidfile_remove, pidfile_fileno — create and manage pid files

LIBRARY

Support library (libbsd)

SYNOPSIS

#include <pidfile.h>

FILE *
pidfile_open(const char *path, mode_t mode, int *fdp);

int
pidfile_write(FILE *fp);

int
pidfile_close(FILE *fp);

int
pidfile_remove(FILE *fp);

int
pidfile_fileno(FILE *fp);

DESCRIPTION

The pidfile functions provide an interface to create and manage pid files. A pid file is a file containing the process ID of a running program. It is used to ensure that only one instance of a program is running at any given time.

The pidfile_open() function creates a pid file at the specified path. The mode argument is the mode with which the file will be created. If the file already exists, pidfile_open() will fail. The fdp argument is a pointer to an integer where the file descriptor of the created pid file will be stored. This file descriptor can later be used with the unlink(2) system calls and the flopen(3bsd) library function.

The pidfile_write() function writes the process ID of the calling process to the given pid file. It should be called after pidfile_open().

The pidfile_close() function closes the pid file and removes it. It should be called when the program is exiting normally.

The pidfile_remove() function closes the pid file but does not remove it. It should be called when the program is terminated abnormally.

The pidfile_fileno() function returns the file descriptor associated with the given pid file pointer. It is useful when you need to use the file descriptor directly, for example, with the unlink(2) system calls and the flopen(3bsd) library function.

RETURN VALUES

The pidfile_open() function returns a pointer to a FILE object on success, or NULL on failure.

The pidfile_write(), pidfile_close(), pidfile_remove() and pidfile_fileno() functions return 0 on success, and -1 on failure.

EXAMPLES

The following example shows how to use the pidfile functions to create a pid file:

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <pidfile.h>

int
main(void) {
    FILE *fp;
    int fd;

    fp = pidfile_open("/var/run/myprogram.pid", 0644, &fd);
    if (fp == NULL) {
        perror("pidfile_open");
        exit(EXIT_FAILURE);
    }

    if (pidfile_write(fp) == -1) {
        perror("pidfile_write");
        pidfile_close(fp);
        exit(EXIT_FAILURE);
    }

    printf("Pid file created successfully.\n");

    /* Program logic here */

    if (pidfile_close(fp) == -1) {
        perror("pidfile_close");
        exit(EXIT_FAILURE);
    }

    printf("Pid file removed successfully.\n");

    return EXIT_SUCCESS;
}

ERRORS

[EACCES]
The directory containing the pid file does not allow writing.
[EEXIST]
The pid file already exists.
[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().
[EINVAL]
The specified path is NULL.
[EISDIR]
The specified path is a directory.
[ENAMETOOLONG]
The specified path is too long.
[ENOENT]
A component of the specified path does not exist, or the path is an empty string.
[ENOMEM]
Not enough memory to complete the operation.
[ENOSPC]
The directory containing the pid file does not have enough space to create the file.
[ENOTDIR]
A component of the specified path is not a directory.
[EROFS]
The pid file resides on a read-only file system.

HISTORY

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() first appeared in FreeBSD 5.5.

The function pidfile_fileno() first appeared in FreeBSD 10.0.
