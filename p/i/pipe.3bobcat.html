FBB::Pipe(3bobcat) Tube de communication au niveau système FBB::Pipe(3bobcat)

NOM

FBB::Pipe - Définit un tube de communication au niveau système

SYNTAXE

#include <bobcat/pipe>
Option de liaison : -lbobcat

DESCRIPTION

Les objets FBB::Pipe peuvent être utilisés pour construire un tube. Les objets Pipe offrent une interface simple aux extrémités de lecture et d'écriture des tubes. Les objets Pipe sont des enveloppes d'objets autour de l'appel système pipe(2).

Un objet Pipe créé juste avant qu'un programme ne se divise (fork) peut être utilisé pour établir une ligne de communication entre le processus parent et le processus enfant. Les informations écrites par le processus enfant sur son flux de sortie standard peuvent être redirigées vers l'extrémité d'écriture du tube (en utilisant le membre writtenBy). Les informations apparaissant à l'extrémité de lecture du tube peuvent alors être extraites à l'aide, par exemple, d'un objet IFdStream, initialisé avec le descripteur de fichier de lecture du Pipe, ou l'extrémité de lecture du tube peut être redirigée vers un flux existant dont le descripteur de fichier est connu, comme cin (qui utilise le descripteur de fichier STDIN_FILENO).

Lorsqu'un objet Pipe sort de sa portée, aucune opération close(2) n'est effectuée sur les descripteurs de fichiers du tube. Après avoir configuré le tube à l'aide des fonctions membres du Pipe et passé les descripteurs de fichiers du Pipe à du code qui utilise les descripteurs du Pipe, l'objet Pipe peut même être détruit. Le code utilisateur est responsable de la fermeture du tube. Si le tube doit être fermé au moment de la destruction, une classe peut être dérivée de Pipe(3bobcat), dont le destructeur peut alors fermer le tube. Alternativement, la fonction membre close du Pipe peut être appelée.

La valeur -1 indique qu'un descripteur de fichier ne fait pas référence à un descripteur de fichier de pipe(2).

CONSTRUCTEURS

o
Pipe() :
Le constructeur Pipe par défaut construit un tube, en appelant pipe(2).
Ce constructeur lance une exception Exception si le constructeur Pipe par défaut ne s'est pas correctement terminé. La méthode which() de l'objet Exception lancé affiche la valeur errno du système définie par la fonction pipe(2) échouée.
o
Pipe(Pipe &&tmp) :
Le constructeur de déplacement déplace les descripteurs de fichiers de l'objet temporaire vers l'objet Pipe en cours de construction.
o
Pipe(int const *fd) :
Ce constructeur attend deux descripteurs de fichiers, faisant référence aux descripteurs de lecture et d'écriture tels que retournés par pipe(2).
o
Pipe(bool initialize) :
Ce constructeur peut être utilisé lorsqu'il ne faut pas associer l'objet Pipe à un tube existant. Au lieu de cela, lorsque initialize == false, il initialise ses descripteurs de lecture et d'écriture à -1. Ce constructeur peut être utilisé par des classes qui définissent des membres de données Pipe qui ne peuvent ouvrir leurs tubes qu'après la construction de l'objet. Après avoir construit un objet Pipe obj{ false }, il peut être associé à un tube ouvert en utilisant obj = Pipe{}. ou obj.reset(). En passant l'argument true, il initialise son tube (cf. pipe(2)). La construction et l'affectation par copie ne sont pas définies.

Notez que le destructeur de Pipe ne ferme pas les descripteurs de fichiers du tube. Pour fermer les tubes, close doit être appelé.

OPÉRATEUR SURCHARGÉ

o
Pipe &operator=(Pipe &&tmp) :
L'opérateur d'affectation de déplacement surchargé ferme le tube actuel et déplace les tubes de tmp vers l'objet Pipe actuel.

FONCTIONS MEMBRES

o
void close() :
Les deux descripteurs de fichiers de l'objet Pipe sont fermés ;
o
void closeReadFd() :
Le descripteur de fichier de l'objet Pipe associé à l'extrémité de lecture du tube est fermé ;
o
void closeWriteFd() :
Le descripteur de fichier de l'objet Pipe associé à l'extrémité d'écriture du tube est fermé ;
o
int readFd() const :
Retourne le descripteur de fichier du tube utilisé pour la lecture.
o
void readFrom(int filedescriptor) :
Configure la redirection à partir du descripteur de fichier interne de lecture vers le descripteur de fichier donné : les informations écrites à l'extrémité d'écriture du tube peuvent être récupérées en extrayant les informations du flux associé au descripteur de fichier indiqué. Par exemple, après l'appel readFrom(STDIN_FILENO), les informations insérées dans l'extrémité d'écriture du tube peuvent être récupérées à partir de cin. Le descripteur de fichier de lecture d'origine et le descripteur de fichier d'écriture du tube sont fermés.
o
void readFrom(int const *filedescriptors, size_t n) :
Configure la redirection à partir du descripteur de fichier interne de lecture vers les descripteurs de fichiers donnés : les informations sont lues à partir de l'objet Pipe lors de la lecture à partir de l'un des n descripteurs de fichiers fournis. Le descripteur de fichier de lecture d'origine et le descripteur de fichier d'écriture du tube sont fermés.
o
int readOnly() :
Ferme l'extrémité d'écriture du tube, retourne le descripteur de fichier de l'extrémité de lecture. Cette fonction membre peut être utilisée, par exemple, pour construire un objet IFdStream afin d'extraire les informations insérées dans l'extrémité d'écriture du tube.
o
int readOnlyFd() :
Identique à la fonction membre précédente, mais définit le descripteur de fichier de lecture utilisé en interne à -1 (cette fonction membre peut être utilisée, par exemple, pour passer le descripteur de fichier de lecture à un autre objet qui ferme éventuellement l'extrémité de lecture du tube).
o
void reset() :
Ferme le tube actuel et le rouvre avec de nouveaux descripteurs de lecture et d'écriture pour le tube.
o
void reset(int const *fds) :
Ferme le tube actuel et le rouvre avec les descripteurs de lecture et d'écriture fournis par les deux premiers éléments de fds.
o
void swap(Pipe &other) :
Les objets Pipe actuels et autres sont échangés. Après cet appel, les objets Pipe actuels font référence aux descripteurs de fichiers du tube de l'autre objet et vice versa.
o
int writeFd() const :
Retourne le descripteur de fichier du tube utilisé pour l'écriture.
o
void writtenBy(int filedescriptor) :
Configure la redirection à partir du descripteur de fichier interne d'écriture vers le descripteur de fichier donné : les informations sont écrites dans l'objet Pipe lors de l'écriture dans le descripteur de fichier fourni. Par exemple, après l'appel writtenBy(STDOUT_FILENO), les informations envoyées au flux de sortie standard (par cout ou par un processus enfant (cf. exec(3))) sont insérées dans l'extrémité d'écriture du tube. Le descripteur de fichier d'écriture d'origine et le descripteur de fichier de lecture du tube

FONCTION DE MEMBRE PROTÉGÉE

o
void writtenBy(int const *filedescriptors, size_t n):
Configure la redirection du descripteur de fichier interne de write vers les descripteurs de fichier donnés : les informations sont insérées dans l'extrémité d'écriture du Pipe lorsque vous écrivez dans chacun des n descripteurs de fichier fournis. Par exemple, en passant un tableau de deux valeurs int, respectivement égales à STDOUT_FILENO et STDERR_FILENO à ce membre, toutes les informations qui sont ensuite envoyées aux flux de sortie ou d'erreur standard sont insérées dans l'extrémité d'écriture du tuyau. Le descripteur de fichier d'écriture d'origine et le descripteur de fichier de lecture du tuyau sont fermés.
o
int writeOnly():
Ferme l'extrémité de lecture du tuyau, retourne le descripteur de fichier de l'extrémité d'écriture.
o
int writeOnlyFd():
Identique au membre précédent, mais définit le descripteur de fichier d'écriture utilisé en interne à -1 (ce membre peut être utilisé pour, par exemple, passer le descripteur de fichier d'écriture à un autre objet qui ferme éventuellement l'extrémité d'écriture du tuyau).

ENUMÉRATION PROTÉGÉE

L'énumération RW protégée a les éléments suivants :

o
READ:
L'index dans d_fd[] (voir ci-dessous) de l'élément contenant le descripteur de fichier de lecture du tuyau ;
o
WRITE:
L'index dans d_fd[] (voir ci-dessous) de l'élément contenant le descripteur de fichier d'écriture du tuyau.

FONCTION DE MEMBRE PROTÉGÉE

o
void close(RW rw):
Lorsque l'argument RW::READ est passé à ce membre, l'extrémité de lecture du tuyau de l'objet Pipe est fermée. Lorsque l'argument RW::WRITE est passé, l'extrémité d'écriture du tuyau de l'objet Pipe est fermée.
o
int *fd():
Retourne un pointeur vers les deux descripteurs de fichier (respectivement READ et WRITE) actuellement utilisés par l'objet Pipe.

EXEMPLE

    #include <bobcat/pipe>
    #include <sys/types.h>
    #include <sys/wait.h>
    #include <unistd.h>
    #include <iostream>
    #include <string>
    using namespace std;
    using namespace FBB;
    int main()
    {
        Pipe pipe;                         // construit un tuyau
        cout << "Descripteur de fichier de lecture : " << pipe.readFd() << "\n"
                "Descripteur de fichier d'écriture : " << pipe.writeFd() << endl;
        int pid = fork();
        if (pid == -1)
            return 1;
        if (pid == 0)                       // enfant
        {
            pipe.readFrom(STDIN_FILENO);    // lit ce qui entre dans le tuyau
            string s;
            getline(cin, s);
            cout << "ENFANT : Reçu `" << s << "’\n";
            getline(cin, s);
            cout << "ENFANT : Reçu `" << s << "’\n";
            return 0;
        }
        pipe.writtenBy(STDOUT_FILENO);      // écrit dans le tuyau via cout
        cout << "première ligne" << "\n"
                "deuxième ligne" << ’\n’;
        waitpid(pid, 0, 0);
    }

BOGUES

Notez que lorsqu'un objet Pipe sort de la portée, aucune opération close(2) n'est effectuée sur les extrémités du tuyau. Si le tuyau doit être fermé par le destructeur, dérivez une classe de Pipe(3bobcat), dont le destructeur effectuera l'opération de fermeture requise.
