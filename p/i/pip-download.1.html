NOM

pip-download - description de la commande pip download

DESCRIPTION

Télécharge des paquets depuis :

  • PyPI (et autres index) en utilisant des spécificateurs de dépendances.
  • URL de projets VCS.
  • Répertoires de projets locaux.
  • Archives sources locales ou distantes.

pip supporte également le téléchargement depuis des "fichiers de dépendances" (requirements files), qui offrent un moyen simple de spécifier un environnement complet à télécharger.

UTILISATION

python -m pip download [options] <spécificateur de dépendance> [options d'index de paquet] ...
python -m pip download [options] -r <fichier de dépendances> [options d'index de paquet] ...
python -m pip download [options] <url de projet vcs> ...
python -m pip download [options] <chemin de projet local> ...
python -m pip download [options] <url/chemin d'archive> ...

OPTIONS

-c, --constraint <fichier>
Contraint les versions en utilisant le fichier de contraintes donné. Cette option peut être utilisée plusieurs fois.

(variable d'environnement : PIP_CONSTRAINT)

--build-constraint <fichier>
Contraint les dépendances de compilation en utilisant le fichier de contraintes donné. Cette option peut être utilisée plusieurs fois.

(variable d'environnement : PIP_BUILD_CONSTRAINT)

-r, --requirement <fichier>
Installe depuis le fichier de dépendances donné. Cette option peut être utilisée plusieurs fois.

(variable d'environnement : PIP_REQUIREMENT)

--no-deps
N'installe pas les dépendances du paquet.

(variables d'environnement : PIP_NO_DEPS, PIP_NO_DEPENDENCIES)

--no-binary <format_control>
N'utilise pas les paquets binaires. Peut être fourni plusieurs fois, et chaque fois s'ajoute à la valeur existante. Accepte soit ":all:" pour désactiver tous les paquets binaires, ":none:" pour vider l'ensemble (remarquez les deux points), soit un ou plusieurs noms de paquets séparés par des virgules (sans deux points). Notez que certains paquets sont difficiles à compiler et peuvent échouer à l'installation lorsque cette option est utilisée sur eux.

(variable d'environnement : PIP_NO_BINARY)

--only-binary <format_control>
N'utilise pas les paquets sources. Peut être fourni plusieurs fois, et chaque fois s'ajoute à la valeur existante. Accepte soit ":all:" pour désactiver tous les paquets sources, ":none:" pour vider l'ensemble, soit un ou plusieurs noms de paquets séparés par des virgules. Les paquets sans distributions binaires échoueront à l'installation lorsque cette option est utilisée sur eux.

(variable d'environnement : PIP_ONLY_BINARY)

--prefer-binary
Préfère les paquets binaires aux paquets sources, même si les paquets sources sont plus récents.

(variable d'environnement : PIP_PREFER_BINARY)

--src <rép>
Répertoire dans lequel cloner les projets modifiables. La valeur par défaut dans un environnement virtuel est "<chemin de l'venv>/src". La valeur par défaut pour les installations globales est "<répertoire courant>/src".

(variables d'environnement : PIP_SRC, PIP_SOURCE, PIP_SOURCE_DIR, PIP_SOURCE_DIRECTORY)

--pre
Inclut les versions pré-release et de développement. Par défaut, pip ne trouve que les versions stables.

(variable d'environnement : PIP_PRE)

--require-hashes
Exige un hash pour vérifier chaque dépendance, pour des installations reproductibles. Cette option est implicite lorsqu'un paquet dans un fichier de dépendances a une option --hash.

(variable d'environnement : PIP_REQUIRE_HASHES)

--progress-bar <barre_de_progression>
Spécifie si la barre de progression doit être utilisée. En mode 'auto', --quiet supprimera toutes les barres de progression. [auto, on, off, raw] (par défaut : auto)

(variable d'environnement : PIP_PROGRESS_BAR)

--no-build-isolation
Désactive l'isolement lors de la compilation d'une distribution source moderne. Les dépendances de compilation spécifiées par la PEP 518 doivent déjà être installées si cette option est utilisée.

(variable d'environnement : PIP_NO_BUILD_ISOLATION)

--check-build-dependencies
Vérifie les dépendances de compilation.

(variable d'environnement : PIP_CHECK_BUILD_DEPENDENCIES)

--ignore-requires-python
Ignore les informations de Requires-Python.

(variable d'environnement : PIP_IGNORE_REQUIRES_PYTHON)

-d, --dest <rép>
Télécharge les paquets dans <rép>.

(variables d'environnement : PIP_DEST, PIP_DESTINATION_DIR, PIP_DESTINATION_DIRECTORY)

--platform <plateforme>
N'utilise que les wheels compatibles avec la <plateforme>. Par défaut, utilise la plateforme du système en cours. Utilisez cette option plusieurs fois pour spécifier plusieurs plateformes supportées par l'interpréteur cible.

(variable d'environnement : PIP_PLATFORM)

--python-version <version_python>
La version de l'interpréteur Python à utiliser pour les wheels et les vérifications de compatibilité "Requires-Python". Par défaut, utilise une version dérivée de l'interpréteur en cours. La version peut être spécifiée en utilisant jusqu'à trois entiers séparés par des points (par exemple, "3" pour 3.0.0, "3.7" pour 3.7.0, ou "3.7.3"). Une version majeure-mineure peut également être donnée sous forme de chaîne sans points (par exemple, "37" pour 3.7.0).

(variable d'environnement : PIP_PYTHON_VERSION)

--implementation <implémentation>
N'utilise que les wheels compatibles avec l'implémentation Python <implémentation>, par exemple 'pp', 'jy', 'cp', ou 'ip'. Si non spécifié, alors l'implémentation de l'interpréteur actuel est utilisée. Utilisez 'py' pour forcer les wheels indépendantes de l'implémentation.

(variable d'environnement : PIP_IMPLEMENTATION)

--abi <abi>
N'utilise que les wheels compatibles avec l'ABI Python <abi>, par exemple 'pypy_41'. Si non spécifié, alors l'ABI tag de l'interpréteur actuel est utilisée. Utilisez cette option plusieurs fois pour spécifier plusieurs ABIs supportées par l'interpréteur cible. Généralement, vous devrez spécifier --implementation, --platform et --python-version lorsque vous utilisez cette option.

DESCRIPTION

Est utilisé pour télécharger des paquets depuis PyPI, les construire si nécessaire, et les stocker dans le cache de téléchargement.

USAGE

pip download [options] <requirement specifier> ...
pip download [options] -r <requirements file> ...
pip download [options] –all-projects

OPTIONS

--dest dir
Adresse du répertoire où stocker les paquets téléchargés.

(variable d'environnement : PIP_DEST)

--no-deps
Ne pas télécharger les dépendances.

(variable d'environnement : PIP_NO_DEPS)

--platform platform
Si spécifié, ne télécharger que les paquets compatibles avec la plateforme spécifiée.

(variable d'environnement : PIP_PLATFORM)

--python-version python_version
Si spécifié, ne télécharger que les paquets compatibles avec la version Python spécifiée.

(variable d'environnement : PIP_PYTHON_VERSION)

--only-binary format
Ne pas construire de paquets sources binaires, seulement ceux du format spécifié. Par exemple : ‘--only-binary=:all:’ ou ‘--only-binary=:none:’.

(variable d'environnement : PIP_ONLY_BINARY)

--no-binary format
Ne pas construire de paquets binaires, seulement ceux du format spécifié. Par exemple : ‘--no-binary=:all:’ ou ‘--no-binary=:none:’.

(variable d'environnement : PIP_NO_BINARY)

--prefer-binary
Préférer les binaires aux sources.

(variable d'environnement : PIP_PREFER_BINARY)

--no-cache-dir
Ne pas utiliser le répertoire de cache.

(variable d'environnement : PIP_NO_CACHE_DIR)

--no-clean
Ne pas nettoyer les répertoires de construction.

(variable d'environnement : PIP_NO_CLEAN)
