pipewire-jack.conf(5) Manuel des formats de fichiers pipewire-jack.conf(5)

NOM

pipewire-jack.conf - jack.conf

DESCRIPTION

Fichier de configuration du client JACK de PipeWire.

SYNTAXE

$XDG_CONFIG_HOME/pipewire/jack.conf

/etc/pipewire/jack.conf

/usr/share/pipewire/jack.conf

/usr/share/pipewire/jack.conf.d/

/etc/pipewire/jack.conf.d/

$XDG_CONFIG_HOME/pipewire/jack.conf.d/

DESCRIPTION

Configuration pour les clients JACK de PipeWire.

Le format du fichier de configuration et la logique de recherche sont les mêmes que pour pipewire.conf(5).

Des fichiers de configuration de type « drop-in » jack.conf.d/*.conf peuvent être utilisés et sont recommandés. Voir pipewire.conf(5).

SECTIONS DU FICHIER DE CONFIGURATION

jack.properties

Configuration du client JACK.

jack.rules

Règles de correspondance pour les clients JACK.

En outre, les sections de configuration du contexte PipeWire peuvent également être spécifiées, voir pipewire.conf(5).

PROPRIÉTÉS JACK

Le fichier de configuration peut contenir une section supplémentaire spécifique à JACK appelée jack.properties comme suit :

# ~/.config/pipewire/jack.conf.d/custom.conf
jack.properties = {
    #rt.prio             = 88
    #node.latency        = 1024/48000
    #node.lock-quantum   = true
    #node.force-quantum  = 0
    #jack.show-monitor   = true
    #jack.merge-monitor  = true
    #jack.show-midi      = true
    #jack.short-name     = false
    #jack.filter-name    = false
    #jack.filter-char    = " "
    #
    # allow:           Ne restreint pas les requêtes d'auto-connexion
    # fail-external:   Échoue les requêtes d'auto-connexion vers les ports externes uniquement
    # ignore-external: Ignore les requêtes d'auto-connexion vers les ports externes uniquement
    # fail-all:        Échoue toutes les requêtes d'auto-connexion
    # ignore-all:      Ignore toutes les requêtes d'auto-connexion
    #jack.self-connect-mode  = allow
    #jack.locked-process     = true
    #jack.default-as-system  = false
    #jack.fix-midi-events    = true
    #jack.global-buffer-size = false
    #jack.passive-links      = false
    #jack.max-client-ports   = 768
    #jack.fill-aliases       = false
    #jack.writable-input     = false
    #jack.flag-midi2         = false
}

Voir stream.properties dans pipewire-client.conf(5) pour une explication des propriétés génériques de nœud.

Il est également possible d'avoir des paramètres par client, voir les Règles de correspondance ci-dessous.

rt.prio

Pour limiter la priorité temps réel que les clients JACK peuvent acquérir.

node.latency

Pour forcer une taille de tampon minimale spécifique pour les applications JACK, configurez : 
node.latency = 1024/48000


Ceci configure une taille de tampon de 1024 échantillons à 48 kHz. Si le graphique fonctionne à un taux d'échantillonnage différent, la taille du tampon sera ajustée en conséquence.

node.lock-quantum

Pour s'assurer qu'aucun changement automatique de quantum ne se produit pendant que les applications JACK sont en cours d'exécution, configurez : 
node.lock-quantum = true


Le quantum ne peut alors être modifié que par métadonnées ou lorsqu'une application est démarrée avec node.force-quantum. Les applications JACK pourront également utiliser jack_set_buffersize() pour remplacer le quantum.

node.force-quantum

Pour forcer le quantum à une certaine valeur et éviter les changements : 
node.force-quantum = 1024


Le quantum ne peut alors être modifié que par métadonnées ou lorsqu'une application est démarrée avec node.force-quantum (ou des applications JACK qui utilisent jack_set_buffersize() pour remplacer le quantum).

jack.show-monitor

Affiche le client Moniteur et ses ports.

jack.merge-monitor

Expose les ports de capture et les ports de moniteur sur le même client de périphérique JACK. C'est ainsi que JACK présente les ports de moniteur aux clients. La valeur par défaut est cependant *ne pas* les fusionner car cela donne généralement des interfaces utilisateur plus conviviales. Un client supplémentaire avec un suffixe Moniteur est créé et contient les ports de moniteur.

Par exemple, voici (une partie de) la sortie de jack_lsp avec le paramètre par défaut (jack.merge-monitor = false) :

Comparer :

jack.merge-monitor = true jack.merge-monitor = false Built-in Audio Analog Stereo:playback_FL Built-in Audio Analog Stereo:playback_FL Built-in Audio Analog Stereo:monitor_FL Built-in Audio Analog Stereo Monitor:monitor_FL Built-in Audio Analog Stereo:playback_FR Built-in Audio Analog Stereo:playback_FR Built-in Audio Analog Stereo:monitor_FR Built-in Audio Analog Stereo Monitor:monitor_FR

jack.show-midi

Affiche les clients MIDI et leurs ports.

jack.short-name

Pour utiliser des noms plus courts pour les noms des clients de périphériques, utilisez jack.short-name = true. Comparer :

jack.short-name = true jack.short-name = false HDA Intel PCH:playback_FL Built-in Audio Analog Stereo:playback_FL HDA Intel PCH Monitor:monitor_FL Built-in Audio Analog Stereo Monitor:monitor_FL HDA Intel PCH:playback_FR Built-in Audio Analog Stereo:playback_FR HDA Intel PCH Monitor:monitor_FR Built-in Audio Analog Stereo Monitor:monitor_FR

jack.filter-name

jack.filter-char

Remplace tous les caractères spéciaux par jack.filter-char. Pour les clients, les caractères spéciaux sont ()[].:*$ et pour les ports, ce sont ()[].*$. Utilisez cette option lorsqu'un client n'est pas capable de gérer les caractères spéciaux. (une ancienne version de PortAudio était connue pour utiliser les noms de clients et de ports comme expressions régulières, et échouait donc en présence de caractères spéciaux d'expression régulière dans le nom).

jack.self-connect-mode

Restreint un client de faire des connexions vers et depuis lui-même. Les valeurs possibles et leur signification sont résumées comme suit :

Valeur Comportement allow Ne restreint pas les requêtes d'auto-connexion. fail-external Échoue les requêtes d'auto-connexion vers les ports externes uniquement. ignore-external Ignore les requêtes d'auto-connexion vers les ports externes uniquement. fail-all Échoue toutes les requêtes d'auto-connexion. ignore-all Ignore toutes les requêtes d'auto-connexion.

jack.locked-process

Assure que le processus et les rappels ne peuvent pas être appelés en même temps. C'est le fonctionnement normal mais il peut être désactivé si un client spécifique peut le gérer.

jack.default-as-system

Nomme la source et le puits par défaut comme « system » et numérote les ports pour maximiser la compatibilité avec les programmes JACK.

jack.default-as-system = false jack.default-as-system = true HDA Intel PCH:playback_FL system:playback_1 HDA Intel PCH Monitor:monitor_FL system:monitor_1 HDA Intel PCH:playback_FR system:playback_2 HDA Intel PCH Monitor:monitor_FR system:monitor_2

jack.fix-midi-events

Corrige les événements NoteOn avec une vélocité de 0 en NoteOff. C'est le comportement standard dans JACK et il est donc activé par défaut pour maximiser la compatibilité. Les plugins LV2 en particulier n'autorisent pas NoteOn avec une vélocité de 0.

jack.global-buffer-size

Lorsqu'un client a cette option, les changements de taille de tampon seront appliqués globalement et de manière permanente à tous les clients PipeWire utilisant les métadonnées.

jack.passive-links

Fait en sorte que les clients JACK créent des liens passifs. Cette option ne fonctionne que lorsque le serveur link-factory a été configuré avec l'option allow.link.passive.

jack.max-client-ports

Limite le nombre de ports autorisés par client à cette valeur.

jack.fill-aliases

Définit automatiquement les alias de port alias1 et alias2 sur les ports.

jack.writable-input

Rend les tampons d'entrée inscriptibles. C'est le comportement par défaut car certains clients JACK écrivent dans le tampon d'entrée. Cependant, cela peut entraîner une corruption dans d'autres clients lorsqu'ils lisent également dans le tampon.

Réglez cette option sur true pour éviter la corruption des tampons si vous ne traitez que des clients non défectueux.

jack.flag-midi2

Utilise le nouveau drapeau JACK MIDI2 sur les ports MIDI2 (UMP). Ceci est désactivé par défaut

fault car la plupart des applications JACK ne connaissent pas encore ce drapeau et refusent d'afficher le port.

Définissez cette valeur à true pour les applications qui savent gérer les ports MIDI2.

RÈGLES DE CORRESPONDANCE

jack.rules fournit une action update-props qui prend un objet avec des propriétés qui sont mises à jour sur l'objet client et l'objet nœud du client JACK.

Ajoutez une section jack.rules dans le fichier de configuration comme ceci :

# ~/.config/pipewire/jack.conf.d/custom.conf
jack.rules = [
    {
        matches = [
            {
                # toutes les clés doivent correspondre à la valeur. ! nie. ~ commence une regex.
                application.process.binary = "jack_simple_client"
            }
        ]
        actions = {
            update-props = {
                node.latency = 512/48000
            }
        }
    }
    {
        matches = [
            {
                client.name = "catia"
            }
        ]
        actions = {
            update-props = {
                jack.merge-monitor = true
            }
        }
    }
]


Définira la latence de jack_simple_client à 512/48000 et fera en sorte que Catia voie le client moniteur fusionné avec le client de lecture.

VARIABLES D'ENVIRONNEMENT

Voir pipewire(1) pour les variables d'environnement courantes. Beaucoup d'entre elles s'appliquent également aux applications clientes JACK.

Les variables d'environnement peuvent être utilisées pour contrôler le comportement de la bibliothèque cliente JACK de PipeWire.

PIPEWIRE_NOJACK

PIPEWIRE_INTERNAL

Lorsque l'une de ces variables est définie, la bibliothèque cliente JACK refusera d'ouvrir un client. La variable PIPEWIRE_INTERNAL est définie par le démon principal de PipeWire pour éviter les auto-connexions.

PIPEWIRE_PROPS

Ajoute/remplace les propriétés spécifiées dans le fichier jack.conf. Vérifiez la sortie de ceci : 
> PIPEWIRE_PROPS='{ jack.short-name=true jack.merge-monitor=true }' jack_lsp
...
HDA Intel PCH:playback_FL
HDA Intel PCH:monitor_FL
HDA Intel PCH:playback_FR
HDA Intel PCH:monitor_FR
...

PIPEWIRE_LATENCY 

PIPEWIRE_LATENCY=<échantillons>/<taux> <application>


Un moyen rapide de configurer la taille maximale du tampon pour un client. Il exécutera ce client avec la taille de tampon spécifiée (ou plus petite).

PIPEWIRE_LATENCY=256/48000 jack_lsp est équivalent à PIPEWIRE_PROPS='{ node.latency=256/48000 }' jack_lsp

Une meilleure façon de démarrer une session JACK dans une taille de tampon spécifique est de la forcer avec :

pw-metadata -n settings 0 clock.force-quantum <quantum>


Cela fonctionne toujours immédiatement et la taille du tampon ne changera pas tant que le quantum ne sera pas remis à 0.

PIPEWIRE_RATE 

PIPEWIRE_RATE=1/<taux> <application>

Un moyen rapide de configurer le taux du graphe. Il essaiera de changer la fréquence d'échantillonnage du graphe. Cela ne peut généralement être fait que lorsque le graphe est inactif et que le taux fait partie des fréquences d'échantillonnage autorisées.

PIPEWIRE_RATE=1/48000 jack_lsp est équivalent à PIPEWIRE_PROPS='{ node.rate=1/48000 }' jack_lsp

Une meilleure façon de démarrer une session JACK dans un taux spécifique est de forcer le taux avec :

pw-metadata -n settings 0 clock.force-rate <taux>


Cela fonctionne toujours et la fréquence d'échantillonnage n'a pas besoin d'être dans les taux autorisés. Le taux ne changera pas non plus tant qu'il ne sera pas remis à 0.

PIPEWIRE_QUANTUM 

PIPEWIRE_QUANTUM=<taille_tampon>/<taux> <application>

Est similaire à l'utilisation de PIPEWIRE_LATENCY=<taille_tampon>/<taux> et PIPEWIRE_RATE=1/<taux> (voir ci-dessus), sauf qu'il ne s'agit pas seulement d'une suggestion, mais qu'il force activement le graphe à changer le taux et le quantum. Il peut être utilisé pour définir à la fois une taille de tampon et une fréquence d'échantillonnage en même temps.

Lorsque 2 applications forcent un quantum, la dernière l'emporte. Lorsque l'application gagnante est arrêtée, le quantum de l'application précédente est restauré.

PIPEWIRE_LINK_PASSIVE 

PIPEWIRE_LINK_PASSIVE=true qjackctl


Faire en sorte que ce client ne crée que des liaisons passives. Toutes les liaisons créées par le client seront marquées comme passives et ne maintiendront pas le récepteur/source actif.

Vous pouvez utiliser cela pour lier des filtres à des périphériques. Lorsqu'aucun client n'est connecté au filtre, seules les liaisons passives subsistent entre le filtre et le périphérique, et le périphérique deviendra inactif et sera suspendu.

PIPEWIRE_NODE 

PIPEWIRE_NODE=<id> <application>


Trier les ports de sorte que seuls les ports du nœud avec <id> soient listés. Vous pouvez l'utiliser pour forcer une application à ne traiter que les ports d'un nœud spécifique, par exemple lors de la connexion automatique.
