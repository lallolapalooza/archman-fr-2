pipe(2) Manuel des appels système pipe(2)

NOM

pipe, pipe2 - créer un tuyau

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int pipe(int pipefd[2]);
#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#include <fcntl.h>              /* Définition des constantes O_* */
#include <unistd.h>
int pipe2(int pipefd[2], int flags);
/* Sur Alpha, IA-64, MIPS, SuperH, et SPARC/SPARC64, pipe() a le
   prototype suivant ; voir VERSIONS */
#include <unistd.h>
struct fd_pair {
    long fd[2];
};
struct fd_pair pipe(void);

DESCRIPTION

pipe() crée un tuyau, un canal de données unidirectionnel pouvant être utilisé pour la communication interprocessus. Le tableau pipefd est utilisé pour retourner deux descripteurs de fichiers se référant aux extrémités du tuyau. pipefd[0] se réfère à l'extrémité de lecture du tuyau. pipefd[1] se réfère à l'extrémité d'écriture du tuyau. Les données écrites à l'extrémité d'écriture du tuyau sont mises en mémoire tampon par le noyau jusqu'à ce qu'elles soient lues à l'extrémité de lecture du tuyau. Pour plus de détails, voir pipe(7).

Si flags est 0, alors pipe2() est identique à pipe(). Les valeurs suivantes peuvent être combinées par OR bit à bit dans flags pour obtenir un comportement différent :

O_CLOEXEC
Définir le drapeau close-on-exec (FD_CLOEXEC) sur les deux nouveaux descripteurs de fichiers. Voir la description du même drapeau dans open(2) pour les raisons pour lesquelles cela peut être utile.
O_DIRECT (depuis Linux 3.4)
Créer un tuyau qui effectue les E/S en mode "paquet". Chaque write(2) vers le tuyau est traité comme un paquet distinct, et les read(2) depuis le tuyau liront un paquet à la fois. Notez les points suivants :
•
Les écritures de plus de PIPE_BUF octets (voir pipe(7)) seront divisées en plusieurs paquets. La constante PIPE_BUF est définie dans <limits.h>.
•
Si un read(2) spécifie une taille de tampon plus petite que le paquet suivant, les octets demandés sont lus et les octets excédentaires du paquet sont écartés. Spécifier une taille de tampon de PIPE_BUF sera suffisant pour lire les plus grands paquets possibles (voir le point précédent).
•
Les paquets de longueur zéro ne sont pas pris en charge. (Un read(2) qui spécifie une taille de tampon de zéro est une opération nulle et retourne 0.)
Les anciens noyaux qui ne prennent pas en charge ce drapeau l'indiqueront par une erreur EINVAL.
Depuis Linux 4.5, il est possible de modifier le paramètre O_DIRECT d'un descripteur de fichier de tuyau en utilisant fcntl(2).
O_NONBLOCK
Définir le drapeau d'état de fichier O_NONBLOCK sur les descriptions de fichiers ouvertes référencées par les nouveaux descripteurs de fichiers. L'utilisation de ce drapeau évite des appels supplémentaires à fcntl(2) pour obtenir le même résultat.
O_NOTIFICATION_PIPE
Depuis Linux 5.8, un mécanisme général de notification est construit au-dessus du tuyau où le noyau insère les messages de notification dans les tuyaux ouverts par l'espace utilisateur. Le propriétaire du tuyau doit indiquer au noyau quelles sources d'événements surveiller et des filtres peuvent également être appliqués pour sélectionner quels sous-événements doivent être placés dans le tuyau.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, errno est défini pour indiquer l'erreur, et pipefd reste inchangé.

Sur Linux (et d'autres systèmes), pipe() ne modifie pas pipefd en cas d'échec. Une exigence standardisant ce comportement a été ajoutée dans POSIX.1-2008 TC2. L'appel système spécifique à Linux pipe2() ne modifie pas non plus pipefd en cas d'échec.

ERREURS

EFAULT
pipefd n'est pas valide.
EINVAL
(pipe2()) Valeur invalide dans flags.
EMFILE
La limite par processus du nombre de descripteurs de fichiers ouverts a été atteinte.
ENFILE
La limite globale du système sur le nombre total de fichiers ouverts a été atteinte.
ENFILE
La limite dure de l'utilisateur sur la mémoire pouvant être allouée aux tuyaux a été atteinte et l'appelant n'est pas privilégié ; voir pipe(7).
ENOPKG
(pipe2()) O_NOTIFICATION_PIPE a été passé dans flags et la prise en charge des notifications (CONFIG_WATCH_QUEUE) n'est pas compilée dans le noyau.

VERSIONS

L'ABI System V sur certaines architectures permet l'utilisation de plusieurs registres pour retourner plusieurs valeurs ; plusieurs architectures (à savoir, Alpha, IA-64, MIPS, SuperH, et SPARC/SPARC64) utilisent (ab)usivement cette fonctionnalité pour implémenter l'appel système pipe() d'une manière fonctionnelle : l'appel ne prend aucun argument et retourne une paire de descripteurs de fichiers comme valeur de retour en cas de succès. La fonction wrapper pipe() de glibc gère cela de manière transparente. Voir syscall(2) pour des informations concernant les registres utilisés pour stocker le second descripteur de fichier.

Après le fork(2), chaque processus ferme les descripteurs de fichiers dont il n'a pas besoin pour le tuyau (voir pipe(7)). Le parent écrit ensuite la chaîne contenue dans l'argument de la ligne de commande du programme dans le tuyau, et l'enfant lit cette chaîne octet par octet depuis le tuyau et l'affiche sur la sortie standard.
