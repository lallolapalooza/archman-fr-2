NOM

pip-lock - description de la commande pip lock

DESCRIPTION

EXPÉRIMENTAL - Verrouiller les paquets et leurs dépendances à partir de :

  • PyPI (et autres index) en utilisant des spécificateurs d'exigences.
  • URL de projets VCS.
  • Répertoires de projets locaux.
  • Archives sources locales ou distantes.

pip prend également en charge le verrouillage à partir de "fichiers d'exigences", qui fournissent un moyen simple de spécifier un environnement entier à installer.

Le fichier de verrouillage généré n'est garanti valide que pour la version actuelle de Python et la plateforme.

UTILISATION

python -m pip lock [options] [-e] <chemin projet local> ...
python -m pip lock [options] <spécificateur de paquet> [options index de paquet] ...
python -m pip lock [options] -r <fichier d'exigences> [options index de paquet] ...
python -m pip lock [options] <url/chemin archive> ...

OPTIONS

-o, --output <chemin>
Nom du fichier de verrouillage (défaut=pylock.toml). Utiliser - pour stdout.

(variable d'environnement : PIP_OUTPUT)

-r, --requirement <fichier>
Installer à partir du fichier d'exigences donné. Cette option peut être utilisée plusieurs fois.

(variable d'environnement : PIP_REQUIREMENT)

-c, --constraint <fichier>
Contre-restreindre les versions en utilisant le fichier de contraintes donné. Cette option peut être utilisée plusieurs fois.

(variable d'environnement : PIP_CONSTRAINT)

--build-constraint <fichier>
Contre-restreindre les dépendances de build en utilisant le fichier de contraintes donné. Cette option peut être utilisée plusieurs fois.

(variable d'environnement : PIP_BUILD_CONSTRAINT)

--no-deps
Ne pas installer les dépendances du paquet.

(variables d'environnement : PIP_NO_DEPS, PIP_NO_DEPENDENCIES)

--pre
Inclure les versions pré-release et de développement. Par défaut, pip ne trouve que les versions stables.

(variable d'environnement : PIP_PRE)

-e, --editable <chemin/url>
Installer un projet en mode éditable (c'est-à-dire le mode "develop" de setuptools) à partir d'un chemin de projet local ou d'une URL VCS.

(variable d'environnement : PIP_EDITABLE)

--src <répertoire>
Répertoire dans lequel cloner les projets éditables. La valeur par défaut dans un environnement virtuel est "<chemin venv>/src". La valeur par défaut pour les installations globales est "<répertoire courant>/src".

(variables d'environnement : PIP_SRC, PIP_SOURCE, PIP_SOURCE_DIR, PIP_SOURCE_DIRECTORY)

--ignore-requires-python
Ignorer les informations Requires-Python.

(variable d'environnement : PIP_IGNORE_REQUIRES_PYTHON)

--no-build-isolation
Désactiver l'isolation lors de la construction d'une distribution source moderne. Les dépendances de build spécifiées par PEP 518 doivent déjà être installées si cette option est utilisée.

(variable d'environnement : PIP_NO_BUILD_ISOLATION)

--check-build-dependencies
Vérifier les dépendances de build.

(variable d'environnement : PIP_CHECK_BUILD_DEPENDENCIES)

-C, --config-settings <settings>
Paramètres de configuration à passer au backend de build. Les paramètres sont de la forme CLÉ=VALEUR. Utilisez plusieurs options --config-settings pour passer plusieurs clés au backend.

(variable d'environnement : PIP_CONFIG_SETTINGS)

--no-binary <format_control>
Ne pas utiliser de paquets binaires. Peut être fourni plusieurs fois, et chaque fois s'ajoute à la valeur existante. Accepte soit ":all:" pour désactiver tous les paquets binaires, soit ":none:" pour vider l'ensemble (remarquez les deux points), soit un ou plusieurs noms de paquets séparés par des virgules (sans deux points). Notez que certains paquets sont difficiles à compiler et peuvent échouer à s'installer lorsque cette option est utilisée sur eux.

(variable d'environnement : PIP_NO_BINARY)

--only-binary <format_control>
Ne pas utiliser de paquets sources. Peut être fourni plusieurs fois, et chaque fois s'ajoute à la valeur existante. Accepte soit ":all:" pour désactiver tous les paquets sources, soit ":none:" pour vider l'ensemble, soit un ou plusieurs noms de paquets séparés par des virgules. Les paquets sans distributions binaires échoueront à l'installation lorsque cette option est utilisée sur eux.

(variable d'environnement : PIP_ONLY_BINARY)

--prefer-binary
Préférer les paquets binaires aux paquets sources, même si les paquets sources sont plus récents.

(variable d'environnement : PIP_PREFER_BINARY)

--require-hashes
Exiger un hachage pour vérifier chaque exigence, pour des installations répétables. Cette option est implicite lorsque tout paquet dans un fichier d'exigences a une option --hash.

(variable d'environnement : PIP_REQUIRE_HASHES)

--progress-bar <barre_progression>
Spécifie si la barre de progression doit être utilisée. En mode "auto", --quiet supprimera toutes les barres de progression. [auto, on, off, raw] (défaut : auto)

(variable d'environnement : PIP_PROGRESS_BAR)

--group <[chemin:]groupe>
Installer un groupe de dépendances nommé à partir d'un fichier "pyproject.toml". Si un chemin est donné, le nom du fichier doit être "pyproject.toml". La valeur par défaut est d'utiliser "pyproject.toml" dans le répertoire courant.

(variable d'environnement : PIP_GROUP)

--no-clean
Ne pas nettoyer les répertoires de build.

(variable d'environnement : PIP_NO_CLEAN)

NOM

pip-lock - Verrouiller les dépendances de votre projet Python

DESCRIPTION

pip-lock est un outil qui vous aide à gérer et à verrouiller les dépendances de votre projet Python. Il crée un fichier de verrouillage qui enregistre les versions exactes de tous les paquets nécessaires à votre projet, garantissant ainsi que vos environnements de développement et de production sont cohérents.

UTILISATION

Pour installer pip-lock :

pip install pip-lock

Pour générer un fichier de verrouillage pour votre projet :

pip-lock

Cela créera un fichier Pipfile.lock par défaut dans le répertoire courant.

Pour installer les dépendances à partir d'un fichier de verrouillage :

pip-lock --lock

ou si vous utilisez Pipenv :

pipenv install --ignore-pipfile

OPTIONS

--lock
Installe les dépendances à partir du fichier de verrouillage.
--generate
Génère un nouveau fichier de verrouillage.
--file <fichier>
Spécifie le chemin vers le fichier de verrouillage (par défaut Pipfile.lock).
--help
Affiche l'aide.
