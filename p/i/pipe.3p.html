PIPE(3P) Manuel du programmeur POSIX PIPE(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pipe — créer un canal inter-processus

SYNTAXE

#include <unistd.h>
int pipe(int fildes[2]);

DESCRIPTION

La fonction pipe() crée un tube (pipe) et place deux descripteurs de fichiers, l'un dans fildes[0] et l'autre dans fildes[1], qui font référence aux descriptions de fichiers ouvertes pour les extrémités de lecture et d'écriture du tube. Les descripteurs de fichiers sont alloués comme décrit dans la Section 2.14, Allocation des descripteurs de fichiers. Les indicateurs O_NONBLOCK et FD_CLOEXEC sont effacés sur les deux descripteurs de fichiers. (La fonction fcntl() peut être utilisée pour définir ces deux indicateurs.)

Des données peuvent être écrites sur le descripteur de fichier fildes[1] et lues depuis le descripteur de fichier fildes[0]. Une lecture sur le descripteur de fichier fildes[0] accède aux données écrites sur le descripteur de fichier fildes[1] selon le principe premier entré, premier sorti (FIFO). Il est indéterminé si fildes[0] est également ouvert en écriture et si fildes[1] est également ouvert en lecture.

Un processus a le tube ouvert en lecture (respectivement en écriture) s'il possède un descripteur de fichier ouvert qui fait référence à l'extrémité de lecture, fildes[0] (extrémité d'écriture, fildes[1]).

L'ID utilisateur du tube est défini sur l'ID utilisateur effectif du processus appelant.

L'ID de groupe du tube est défini sur l'ID de groupe effectif du processus appelant.

En cas de succès, pipe() marque pour mise à jour les horodatages d'accès aux données, de modification des données et de changement d'état du fichier du tube.

VALEUR RENVOYÉE

En cas de succès, 0 est renvoyé ; sinon, -1 est renvoyé et errno est défini pour indiquer l'erreur. Aucun descripteur de fichier n'est alloué et le contenu de fildes reste inchangé.

ERREURS

La fonction pipe() échouera si :

EMFILE
Tous les descripteurs de fichiers disponibles pour le processus, ou tous sauf un, sont actuellement ouverts.
ENFILE
Le nombre de fichiers simultanément ouverts dans le système dépasserait une limite imposée par le système.

Les sections suivantes sont informatives.

EXEMPLES

Utilisation d'un Tube pour Passer des Données entre un Processus Parent et un Processus Enfant

L'exemple suivant démontre l'utilisation d'un tube pour transférer des données entre un processus parent et un processus enfant. La gestion des erreurs est exclue, mais sinon, ce code démontre les bonnes pratiques lors de l'utilisation des tubes : après le fork(), les deux processus ferment les extrémités inutilisées du tube avant de commencer le transfert de données.

#include <stdlib.h>
#include <unistd.h>
...
int fildes[2];
const int BSIZE = 100;
char buf[BSIZE];
ssize_t nbytes;
int status;
status = pipe(fildes);
if (status == -1 ) {
    /* une erreur s'est produite */
    ...
}
switch (fork()) {
case -1: /* Gérer l'erreur */
    break;
case 0:  /* Enfant - lit depuis le tube */
    close(fildes[1]);                       /* L'extrémité d'écriture est inutilisée */
    nbytes = read(fildes[0], buf, BSIZE);   /* Obtenir les données du tube */
    /* À ce stade, une lecture ultérieure verrait la fin du fichier ... */
    close(fildes[0]);                       /* Terminé avec le tube */
    exit(EXIT_SUCCESS);
default:  /* Parent - écrit dans le tube */
    close(fildes[0]);                       /* L'extrémité de lecture est inutilisée */
    write(fildes[1], "Hello world\n", 12);  /* Écrire les données sur le tube */
    close(fildes[1]);                       /* L'enfant verra EOF */
    exit(EXIT_SUCCESS);
}

UTILISATION APPLICATIVE

Aucune.

JUSTIFICATION

La formulation évite soigneusement d'utiliser le verbe « ouvrir » afin d'éviter toute implication d'utilisation de open() ; voir aussi write().
