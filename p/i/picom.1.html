PICOM(1) Commandes utilisateur PICOM(1)

NOM

picom - un compositeur pour X11

SYNTAXE

picom [OPTIONS]

DESCRIPTION

picom est un compositeur basé sur la version de xcompmgr de Dana Jansens (qui elle-même a été écrite par Keith Packard). Il inclut quelques améliorations par rapport au xcompmgr original, comme l'opacité des bordures de fenêtres et la transparence des fenêtres inactives.

OPTIONS

-h, --help

Obtenir le texte d'utilisation intégré au code du programme, qui peut être plus à jour que cette page de manuel.

-r, --shadow-radius=RAYON

Le rayon de flou pour les ombres, en pixels. (par défaut 12)

-o, --shadow-opacity=OPACITE

L'opacité des ombres. (0.0 - 1.0, par défaut 0.75)

-l, --shadow-offset-x=DECALAGE

Le décalage gauche pour les ombres, en pixels. (par défaut -15)

-t, --shadow-offset-y=DECALAGE

Le décalage supérieur pour les ombres, en pixels. (par défaut -15)

-I, --fade-in-step=PAS_OPACITE

Changement d'opacité entre les étapes lors du fondu en entrée. (0.01 - 1.0, par défaut 0.028)

-O, --fade-out-step=PAS_OPACITE

Changement d'opacité entre les étapes lors du fondu en sortie. (0.01 - 1.0, par défaut 0.03)

-D, --fade-delta=MILLISECONDES

Le temps entre les étapes de fondu, en millisecondes. (> 0, par défaut 10)

-c, --shadow

Active les ombres côté client sur les fenêtres. Notez que les fenêtres de bureau (fenêtres avec _NET_WM_WINDOW_TYPE_DESKTOP) n'obtiennent jamais d'ombre, sauf si explicitement demandé en utilisant l'option wintypes.

-f, --fading

Fait apparaître/disparaître les fenêtres lors de leur ouverture/fermeture et lors des changements d'opacité, sauf si --no-fading-openclose est utilisé.

-i, --inactive-opacity=OPACITE

Opacité des fenêtres inactives. (0.1 - 1.0, par défaut 1.0). L'utilisation de cette option est déconseillée, consultez la section RÈGLES DE FENÊTRES pour la méthode recommandée de définition de l'opacité spécifique aux fenêtres.

-e, --frame-opacity=OPACITE

Opacité des barres de titre et des bordures de fenêtre. (0.1 - 1.0, désactivé par défaut)

-b, --daemon

Daemonize le processus. Passe en arrière-plan après l'initialisation. Cette option ne peut être définie qu'en ligne de commande, la définir dans le fichier de configuration n'aura aucun effet.

--log-level

Définit le niveau de journalisation. Les valeurs possibles sont "TRACE", "DEBUG", "INFO", "WARN", "ERROR", par ordre croissant d'importance. La casse n'a pas d'importance. Si vous utilisez le niveau de journalisation "TRACE", il est préférable de journaliser dans un fichier en utilisant --log-file, car cela peut générer un flux énorme de logs.

--log-file

Définit le fichier de journalisation. Si --log-file n'est jamais spécifié, les journaux seront écrits sur stderr. Sinon, les journaux seront écrits dans le fichier donné, bien que certains logs initiaux puissent encore être écrits sur stderr. Lors de la définition de cette option à partir du fichier de configuration, il est recommandé d'utiliser un chemin absolu.

--legacy-backends

Utilise l'ancienne version des backends. Cette option ne peut pas être définie à partir du fichier de configuration.

--show-all-xerrors

Affiche toutes les erreurs X (pour le débogage).

--config CHEMIN

Recherche le fichier de configuration au chemin spécifié. Voir la section FICHIERS DE CONFIGURATION ci-dessous pour savoir où picom recherche un fichier de configuration par défaut. Utilisez /dev/null pour éviter de charger le fichier de configuration.

--write-pid-path CHEMIN

Écrit l'ID du processus dans un fichier. Il est recommandé d'utiliser un chemin absolu.

--plugins CHEMIN

Spécifie les plugins à charger. Les plugins seront d'abord recherchés dans le répertoire de travail courant (sauf s'ils sont spécifiés dans le fichier de configuration, auquel cas cette étape est ignorée), puis dans $XDG_CONFIG_HOME/picom/plugins, puis dans $XDG_CONFIG_DIRS/picom/plugins. Si tout ce qui précède échoue, le nom du plugin est passé directement au chargeur dynamique. Peut être spécifié plusieurs fois pour charger plus d'un plugin.

--shadow-color CHAINE

Couleur de l'ombre, sous forme de chaîne hexadécimale (par exemple #000000)

--shadow-red VALEUR

Valeur de la couleur rouge de l'ombre (0.0 - 1.0, par défaut 0).

--shadow-green VALEUR

Valeur de la couleur verte de l'ombre (0.0 - 1.0, par défaut 0).

--shadow-blue VALEUR

Valeur de la couleur bleue de l'ombre (0.0 - 1.0, par défaut 0).

--inactive-opacity-override

Laisse l'opacité inactive définie par -i écraser les valeurs _NET_WM_WINDOW_OPACITY des fenêtres. L'utilisation de ceci est déconseillée, voir la section RÈGLES DE FENÊTRES pour la manière recommandée de définir l'opacité spécifique aux fenêtres.

--active-opacity OPACITE

Opacité par défaut pour les fenêtres actives. (0.0 - 1.0, par défaut 1.0). L'utilisation de ceci est déconseillée, voir la section RÈGLES DE FENÊTRES pour la manière recommandée de définir l'opacité spécifique aux fenêtres.

--inactive-dim VALEUR

Assombrit les fenêtres inactives. (0.0 - 1.0, par défaut 0.0). L'utilisation de cette option est déconseillée, voir la section RÈGLES DE FENÊTRES pour la méthode recommandée de définition des niveaux d'assombrissement spécifiques aux fenêtres.

--corner-radius VALEUR

Définit le rayon des coins arrondis des fenêtres. Lorsque > 0, le compositeur arrondira les coins des fenêtres. N'interagit pas bien avec --transparent-clipping. (par défaut 0).

--corner-radius-rules RAYON:CONDITION

Spécifie une liste de règles pour les rayons des coins. Remplace les rayons des coins des fenêtres correspondantes. Cette option a la priorité sur l'option --rounded-corners-exclude, et écrase également l'exclusion par défaut des fenêtres plein écran. La condition a le même format que --opacity-rule. L'utilisation de ceci est déconseillée, voir la section RÈGLES DE FENÊTRES pour la méthode recommandée de définition du rayon des coins spécifique aux fenêtres.

--rounded-corners-exclude CONDITION

Conditions d'exclusion pour les coins arrondis. L'utilisation de ceci est déconseillée, voir la section RÈGLES DE FENÊTRES pour la méthode recommandée de définition du rayon des coins spécifique aux fenêtres.

--no-frame-pacing

Désactive la cadence d'images synchronisée avec le VSync. Par défaut, le compositeur essaie de s'assurer qu'il ne rend qu'une fois par intervalle de synchronisation verticale, et le rendu se fait le plus tard possible pour minimiser la latence des mises à jour vers l'écran. Cependant, cela peut parfois causer des saccades, voire une fréquence d'images abaissée. Cette option peut être utilisée pour désactiver la cadence d'images.

--mark-wmwin-focused

Essaie de détecter les fenêtres WM (une fenêtre sans redirection de remplacement sans enfant ayant WM_STATE) et de les marquer comme actives. L'utilisation de ceci est déconseillée, voir la section RÈGLES DE FENÊTRES pour la méthode recommandée de définition de règles spécifiques aux fenêtres.

--mark-ovredir-focused

Marque les fenêtres avec redirection de remplacement qui n'ont pas d'enfant avec WM_STATE comme étant focalisées. L'utilisation de ceci est déconseillée, voir la section RÈGLES DE FENÊTRES pour la méthode recommandée de définition de règles spécifiques aux fenêtres.

--no-fading-openclose

Ne pas faire de fondu lors de l'ouverture/fermeture des fenêtres.

--no-fading-destroyed-argb

Ne pas faire de fondu des fenêtres ARGB détruites avec bordure WM. Solution de contournement pour les bogues dans Openbox, Fluxbox, etc.

--shadow-ignore-shaped

Ne pas dessiner d'ombres sur les fenêtres de forme spécifique. Notez que les fenêtres de forme spécifique ici signifient les fenêtres définissant leur forme via l'extension X Shape. Celles utilisant un fond ARGB échappent à notre contrôle. Obsolète, voir la section RÈGLES DE FENÊTRES pour la méthode recommandée de définition d'ombres spécifiques aux fenêtres.

--detect-rounded-corners

Essaie de détecter les fenêtres avec des coins arrondis et ne pas les considérer comme des fenêtres de forme spécifique. La précision n'est malheureusement pas très élevée.

--detect-client-opacity

Détecte _NET_WM_WINDOW_OPACITY sur les fenêtres clientes, utile pour les gestionnaires de fenêtres qui ne transmettent pas _NET_WM_WINDOW_OPACITY des clients.
t fenêtres pour encadrer les fenêtres.

--vsync, --no-vsync

Active/désactive la synchronisation verticale (VSync).

--use-ewmh-active-win

Utilise _NET_ACTIVE_WINDOW d'EWMH pour déterminer la fenêtre actuellement focalisée, plutôt que d'écouter l'événement 'FocusIn'/'FocusOut'. Peut avoir plus de précision, à condition que le gestionnaire de fenêtres (WM) le prenne en charge.

--unredir-if-possible

Annule le dé-redirectionnement de toutes les fenêtres dans certains cas. Connu pour causer du scintillement lors du dé-redirectionnement/redirectionnement des fenêtres. Actuellement, l'annulation du dé-redirectionnement est déclenchée par les conditions suivantes :
• Si la fenêtre de niveau supérieur occupe tout l'écran. En configuration multi-moniteurs, cela signifie TOUS les moniteurs.
• S'il n'y a pas de fenêtre.
• Si une fenêtre est en plein écran selon ses indices WM. (peut être désactivé avec --no-ewmh-fullscreen).
• Si une fenêtre demande de contourner le compositeur (_NET_WM_BYPASS_COMPOSITOR). Les fenêtres sont également dé-redirectionnées inconditionnellement lorsque les moniteurs sont éteints, que --unredir-if-possible soit défini ou non.

--unredir-if-possible-delay MILLISECONDS

Délai avant de dé-redirectionner la fenêtre, en millisecondes. Par défaut : 0.

--unredir-if-possible-exclude CONDITION

Conditions des fenêtres qui ne devraient pas être considérées comme plein écran pour le dé-redirectionnement de l'écran. L'utilisation de cette option est déconseillée, consultez la section RÈGLES DE FENÊTRES pour la manière recommandée de définir le dé-redirectionnement spécifique à une fenêtre.

--shadow-exclude CONDITION

Spécifie une liste de conditions de fenêtres qui ne devraient pas avoir d'ombre. L'utilisation de cette option est déconseillée, consultez la section RÈGLES DE FENÊTRES pour la manière recommandée de définir l'ombre spécifique à une fenêtre.

--clip-shadow-above CONDITION

Spécifie une liste de conditions de fenêtres qui ne devraient pas avoir d'ombre peinte par-dessus, comme une fenêtre de barre des tâches (dock). L'utilisation de cette option est déconseillée, consultez la section RÈGLES DE FENÊTRES pour la manière recommandée de définir le découpage d'ombre spécifique à une fenêtre.

--fade-exclude CONDITION

Spécifie une liste de conditions de fenêtres qui ne devraient pas être estompées. L'utilisation de cette option est déconseillée, consultez la section RÈGLES DE FENÊTRES pour la manière recommandée de définir l'estompage spécifique à une fenêtre.

--focus-exclude CONDITION

Spécifie une liste de conditions de fenêtres qui devraient toujours être considérées comme focalisées. L'utilisation de cette option est déconseillée, consultez la section RÈGLES DE FENÊTRES pour la manière recommandée de faire cela.

--inactive-dim-fixed

Utilise une valeur de réduction d'inactivité fixe, au lieu de l'ajuster en fonction de l'opacité de la fenêtre.

--detect-transient

Utilise WM_TRANSIENT_FOR pour regrouper les fenêtres, et considère les fenêtres du même groupe comme focalisées en même temps.

--detect-client-leader

Utilise WM_CLIENT_LEADER pour regrouper les fenêtres, et considère les fenêtres du même groupe comme focalisées en même temps. Cela signifie généralement que les fenêtres de la même application seront considérées comme focalisées ou non focalisées en même temps. WM_TRANSIENT_FOR a une priorité plus élevée si --detect-transient est également activé.

--blur-method, --blur-size, --blur-deviation, --blur-strength

Paramètres pour le flou de fond, consultez la section FLOU pour plus d'informations.

--blur-background

Floute le fond des fenêtres semi-transparentes / ARGB. Mauvais pour les performances, comportement dépendant du pilote. Le nom de l'option peut changer sans préavis.

--blur-background-frame

Floute le fond des fenêtres lorsque le cadre de la fenêtre n'est pas opaque. Implique --blur-background. Mauvais pour les performances, comportement dépendant du pilote. Le nom peut changer.

--blur-background-fixed

Utilise une force de flou fixe au lieu de l'ajuster en fonction de l'opacité de la fenêtre.

--blur-kern MATRICE

Spécifie le noyau de convolution de flou, avec le format suivant : 
LARGEUR,HAUTEUR,ELE1,ELE2,ELE3,ELE4,ELE5...

En d'autres termes, la matrice est formatée comme une liste de nombres séparés par des virgules. Les deux premiers nombres doivent être des entiers, qui spécifient la largeur et la hauteur de la matrice. Ils doivent être des nombres impairs. Ensuite, les largeur * hauteur - 1 nombres suivants spécifient les nombres dans la matrice, ligne par ligne, en excluant l'élément central.

Les éléments sont des nombres flottants finis. Le point décimal doit être . (un point), la notation scientifique n'est pas prise en charge.

L'élément du centre sera soit 1.0, soit variable en fonction de l'opacité, selon que vous ayez activé --blur-background-fixed. Cependant, l'ajustement automatique du facteur de flou peut ne pas bien fonctionner avec un noyau de flou personnalisé.

Un noyau de flou gaussien 7x7 (sigma = 0.84089642) ressemble à ceci :

--blur-kern '7,7,0.000003,0.000102,0.000849,0.001723,0.000849,0.000102,0.000003,0.000102,0.003494,0.029143,0.059106,0.029143,0.003494,0.000102,0.000849,0.029143,0.243117,0.493069,0.243117,0.029143,0.000849,0.001723,0.059106,0.493069,0.493069,0.059106,0.001723,0.000849,0.029143,0.243117,0.493069,0.243117,0.029143,0.000849,0.000102,0.003494,0.029143,0.059106,0.029143,0.003494,0.000102,0.000003,0.000102,0.000849,0.001723,0.000849,0.000102,0.000003'

Peut également être l'un des noyaux prédéfinis : 3x3box (par défaut), 5x5box, 7x7box, 3x3gaussian, 5x5gaussian, 7x7gaussian, 9x9gaussian, 11x11gaussian. Tous les noyaux gaussiens sont générés avec sigma = 0.84089642. Si vous avez besoin de générer des noyaux de flou personnalisés, vous pourriez essayer la nouvelle configuration de flou (Voir FLOU).

--blur-background-exclude CONDITION

Conditions d'exclusion pour le flou de fond.

--resize-damage ENTIER

Redimensionne la région endommagée d'un nombre spécifique de pixels. Une valeur positive l'agrandit tandis qu'une valeur négative la réduit. Si la valeur est positive, ces pixels supplémentaires ne seront pas réellement peints à l'écran, seulement utilisés dans le calcul du flou, etc. (En raison de limitations techniques, avec --use-damage, ces pixels seront toujours incorrectement peints à l'écran.) Principalement utilisé pour corriger les problèmes de corruption de ligne du flou, auquel cas vous devriez utiliser le rayon de flou ici (par exemple, avec un noyau 3x3, vous devriez utiliser --resize-damage 1, avec un noyau 5x5 vous utilisez --resize-damage 2, et ainsi de suite). Peut ou ne peut pas fonctionner avec --glx-no-stencil. Fonctionne uniquement avec --legacy-backends. La réduction ne fonctionne pas correctement.

--invert-color-include CONDITION

Spécifie une liste de conditions de fenêtres qui devraient être peintes avec des couleurs inversées. Gourmand en ressources, et pas bien testé. L'utilisation de cette option est déconseillée, consultez la section RÈGLES DE FENÊTRES pour la manière recommandée de le faire.

--opacity-rule OPACITÉ:CONDITION

Spécifie une liste de règles d'opacité, au format POURCENTAGE:MOTIF, comme 50:name *= "Firefox". picom-trans est recommandé par rapport à cela. Notez que nous ne donnons aucune garantie concernant d'éventuels conflits avec d'autres programmes qui définissent _NET_WM_WINDOW_OPACITY sur les cadres ou les fenêtres clients. L'utilisation de cette option est déconseillée, consultez la section RÈGLES DE FENÊTRES pour la manière recommandée de définir l'opacité spécifique à une fenêtre.

--crop-shadow-to-monitor

Recadre l'ombre d'une fenêtre entièrement sur un moniteur particulier vers ce moniteur. Ceci est actuellement implémenté en utilisant l'extension X RandR.

--backend BACKEND

Spécifie le backend à utiliser : xrender, glx, ou xr_glx_hybrid. xrender est le backend par défaut.
•xrender effectue toutes les opérations de rendu avec l'extension X Render. C'est ce qu'utilise xcompmgr, et c'est généralement une solution de repli sûre lorsque vous rencontrez des artefacts de rendu ou une instabilité.
•glx (OpenGL) effectue toutes les opérations de rendu avec OpenGL. Il est plus convivial pour certaines méthodes VSync, et a des performances considérablement supérieures pour l'inversion des couleurs (--invert-color-include) ou le flou (--blur-background). Il nécessite un support OpenGL 2.0 approprié de la part de votre pilote et de votre matériel. Vous pourriez vouloir consulter les options d'optimisation des performances GLX ci-dessous. --xrender-sync-fence pourrait être nécessaire sur certains systèmes pour éviter les retards dans les changements de contenu de l'écran.
•xr_glx_hybrid effectue le rendu du contenu de l'écran mis à jour avec X Render et le présente à l'écran avec GLX. Il tente de résoudre les problèmes de rendu que certains utilisateurs ont rencontrés avec le backend GLX et permet le meilleur VSync des backends GLX. --vsync-use-glfinish pourrait résoudre certains problèmes de rendu avec ce backend.

--glx-no-stencil

Backend GLX : Évite d'utiliser le tampon stencil, utile si vous n'avez pas de tampon stencil. Pourrait causer une opacité incorrecte lors du rendu de contenu transparent (mais cela n'est jamais arrivé en pratique) et pourrait ne pas fonctionner avec --blur-background. Mes tests montrent une amélioration des performances de 15 %. Recommandé.

--glx-no-rebind-pixmap

Backend GLX : Évite de re-lier les pixmaps lors des dommages à la fenêtre. Pourrait probablement améliorer les performances lors de changements rapides de contenu de fenêtre, mais est connu pour casser des choses sur certains pilotes (LLVMpipe, xf86-video-intel, etc.). Recommandé si cela fonctionne.

--no-use-damage

Désactive l'utilisation des informations de dommage. Cela oblige tout l'écran à être redessiné à chaque fois, au lieu de la partie de l'écran qui a réellement changé. Potentiellement dégrade les performances, mais pourrait corriger certains artefacts.

--xrender-sync-fence

Utilise une clôture de synchronisation X pour synchroniser les appels de dessin des clients, afin de s'assurer que tous les appels de dessin sont terminés avant que picom ne commence à dessiner. Nécessaire sur les pilotes nvidia avec le backend GLX pour certains utilisateurs.

--glx-fshader-win SHADER

Backend GLX : Utilise le shader de fragment GLSL spécifié pour le rendu du contenu des fenêtres. Voir compton-default-fshader-win.glsl et compton-fake-transparency-fshader-win.glsl dans l'arbre source pour des exemples. Ne fonctionne qu'avec --legacy-backends activé.

--force-win-blend

Force toutes les fenêtres à être peintes avec un mélange. Utile si vous avez un --glx-fshader-win

--dbus

Active le contrôle à distance via D-Bus. Voir la section API D-BUS ci-dessous pour plus de détails.

--benchmark CYCLES

Mode benchmark. Peint à plusieurs reprises jusqu'à atteindre le nombre de cycles spécifié.

--benchmark-wid ID_FENETRE

Spécifie l'ID de la fenêtre à repeindre en mode benchmark. Si omis ou égal à 0, l'écran entier est repeint.

--no-ewmh-fullscreen

N'utilise pas EWMH pour détecter les fenêtres plein écran. Revient à vérifier si une fenêtre est en plein écran uniquement en fonction de sa taille et de ses coordonnées.

--max-brightness

Assombrit les fenêtres lumineuses afin que leur luminosité ne dépasse pas cette valeur définie. La luminosité d'une fenêtre est estimée en faisant la moyenne de tous les pixels de la fenêtre, ce qui peut affecter les performances. Définir cette valeur à 1.0 désactive ce comportement. Nécessite que --use-damage soit désactivé. (par défaut : 1.0)

--transparent-clipping

Fait en sorte que les fenêtres transparentes coupent les autres fenêtres comme le font les fenêtres opaques, au lieu de se fondre par-dessus elles.

--transparent-clipping-exclude CONDITION

Spécifie une liste de conditions de fenêtres auxquelles le découpage transparent ne doit jamais être appliqué. Utile pour les outils de capture d'écran, où vous devez pouvoir voir à travers les parties transparentes de la fenêtre.

--window-shader-fg SHADER

Spécifie le chemin du shader de fragment GLSL pour le rendu du contenu des fenêtres. Ne fonctionne pas lorsque --legacy-backends est activé. Le shader est recherché d'abord par rapport au répertoire du fichier de configuration, puis aux emplacements habituels pour un fichier de configuration. Voir la section INTERFACE DE SHADER ci-dessous pour plus de détails sur l'interface.

--window-shader-fg-rule SHADER:CONDITION

Spécifie le chemin du shader de fragment GLSL pour le rendu du contenu des fenêtres en utilisant des motifs. Similaire à --opacity-rule, les arguments doivent être au format SHADER:CONDITION, par exemple « shader.frag:name = 'fenetre' ». Les espaces blancs en début et fin de SHADER seront supprimés. Si SHADER est « default », le shader par défaut sera utilisé pour les fenêtres correspondantes. (Cela signifie malheureusement également que vous ne pouvez pas utiliser un fichier shader nommé « default »). Ne fonctionne pas lorsque --legacy-backends est activé. Son utilisation est déconseillée, voir la section RÈGLES DE FENÊTRE pour la méthode recommandée pour définir des shaders spécifiques aux fenêtres.

--dithered-present

Utilise une précision plus élevée lors du rendu et applique un tramage lors de la présentation de l'écran rendu. Réduit les artefacts de bande, mais peut entraîner une dégradation des performances. Ne fonctionne qu'avec OpenGL.

RÈGLES DE FENÊTRE

Les règles de fenêtre vous permettent de définir des options spécifiques aux fenêtres qui peuvent être utilisées pour modifier l'apparence des fenêtres en fonction de certaines conditions. Notez qu'il existe d'autres options qui couvrent également une partie des fonctionnalités des règles de fenêtre, mais les règles de fenêtre sont plus flexibles et puissantes. Si vous créez un nouveau fichier de configuration, il est recommandé d'utiliser les règles de fenêtre plutôt que les autres options.

Voici une liste de toutes les options qui sont remplacées par les règles de fenêtre :

--shadow-ignore-shaped, -i, --inactive-opacity=OPACITÉ, --active-opacity OPACITÉ, --inactive-opacity-override, --inactive-dim VALEUR, --mark-wmwin-focused, --mark-ovredir-focused, --invert-color-include CONDITION, --shadow-exclude CONDITION, --fade-exclude CONDITION, --focus-exclude CONDITION, --rounded-corners-exclude CONDITION, --blur-background-exclude CONDITION, --opacity-rule OPACITÉ:CONDITION, --corner-radius-rules RAYON:CONDITION, --window-shader-fg-rule SHADER:CONDITION, --clip-shadow-above CONDITION. Ainsi que l'option de fichier de configuration wintypes.

Si l'option des règles de fenêtre est utilisée, aucune des options ci-dessus n'aura d'effet. Des messages d'avertissement seront émis. Lorsque l'option des règles de fenêtre est utilisée, le compositeur se comportera également différemment dans certains cas. L'un de ces cas est que les fenêtres plein écran n'auront plus leurs coins arrondis désactivés par défaut.

Si vous utilisez actuellement certaines de ces options et souhaitez passer aux règles de fenêtre, ou si vous souhaitez conserver le comportement existant, consultez la section Migration des anciennes règles pour savoir comment les convertir.

Syntaxe

Les règles de fenêtre ne sont disponibles que dans le fichier de configuration. Pour définir les règles de fenêtre, définissez l'option rules dans le fichier de configuration comme ceci :

rules = (
        { match = "focused"; opacity = 1; },
        { match = "name = 'firefox'"; shadow = true; },
        # ... et ainsi de suite
)

rules = ( ... ) définit l'option sur une liste, qui peut contenir plusieurs sous-éléments. Pour rules, chaque sous-élément doit être un groupe (c'est-à-dire { clé = valeur; ... }), représentant une condition et un ensemble d'options à appliquer lorsque la condition est remplie. Ces sous-éléments sont comparés dans l'ordre où ils apparaissent dans le fichier de configuration, les options sont appliquées à mesure que les conditions sont remplies. Si la même option est définie plusieurs fois, la dernière prendra effet.

Dans chaque sous-élément, les clés suivantes sont disponibles :

match

La chaîne de condition pour faire correspondre les fenêtres. Voir la section FORMAT DES CONDITIONS ci-dessous pour la syntaxe des chaînes de condition. Si non spécifié, la règle correspondra toujours.

shadow

Si une ombre doit être dessinée sous la fenêtre correspondante.

full-shadow

Contrôle si l'ombre est dessinée sous les parties de la fenêtre que vous ne pourrez normalement pas voir. Utile lorsque la fenêtre a des parties transparentes et que vous souhaitez des ombres dans ces zones.

fade

Si la fenêtre correspondante doit apparaître/disparaître en fondu lors de son ouverture/fermeture. Lorsque des animations sont utilisées, cela n'aura aucun effet. Cela ne peut être utilisé que pour désactiver les animations de fondu activées par l'option -f, --fading.

opacity

Opacité de la fenêtre correspondante. (0.0 - 1.0). Si elle n'est pas explicitement définie par une règle, la valeur d'opacité des propriétés de la fenêtre (par exemple, _NET_WM_WINDOW_OPACITY) sera utilisée.

dim

Niveau d'assombrissement de la fenêtre correspondante. Une valeur plus élevée signifie plus d'assombrissement. (0.0 - 1.0)

corner-radius

Rayon des coins de la fenêtre correspondante en nombre de pixels. 0 signifie aucun arrondi de coin.

blur-background

Si l'arrière-plan de la fenêtre correspondante doit être flouté.

invert-color

Si la couleur de la fenêtre correspondante doit être inversée.

clip-shadow-above

Si la fenêtre correspondante doit être empêchée d'être peinte par des ombres.

unredir

Si la fenêtre correspondante doit amener le compositeur à désenregistrer l'écran, et si elle doit déclencher le réenregistrement de l'écran s'il est actuellement désenregistré. Il peut s'agir d'une valeur booléenne, si true, l'écran sera désenregistré si la fenêtre correspondante remplit certaines conditions ; si false, elle ne provoquera jamais le désenregistrement de l'écran. Si l'écran est actuellement désenregistré et qu'aucune autre fenêtre ne déclenchera le désenregistrement, ces deux choix provoqueront le réenregistrement de l'écran. Pour contrôler également ce comportement, vous pouvez définir unredir sur preferred, de telles fenêtres ne provoqueront pas le réenregistrement de l'écran dans cette situation et se comporteront comme true sinon ; ou passive, qui non seulement ne provoquera pas de réenregistrement dans ce cas, mais ne provoquera pas non plus activement le réenregistrement de l'écran. La dernière valeur possible pour cette option est forced, toutes les fenêtres ayant leur unredir défini sur forced provoqueront le désenregistrement inconditionnel de l'écran. La valeur de la propriété _NET_WM_BYPASS_COMPOSITOR sur la fenêtre sera prise en compte si unredir n'est pas explicitement défini par une règle.

transparent-clipping

Si la fenêtre correspondante doit couper les autres fenêtres comme le font les fenêtres opaques, au lieu de se fondre par-dessus elles. Lorsqu'elle est appliquée aux fenêtres transparentes, cela signifie que rien ne sera peint sous les parties transparentes de la fenêtre, créant essentiellement un trou dans l'écran.

shader

Chemin du shader de fragment GLSL pour le rendu du contenu des fenêtres. Voir la section INTERFACE DE SHADER ci-dessous pour plus de détails sur l'interface.

animations

Définit des scripts d'animation spécifiques aux fenêtres. Le format de cette option est le même que l'option animations de niveau supérieur. Vous pouvez trouver plus d'informations dans la section ANIMATIONS. Si des scripts d'animation sont définis dans plusieurs règles correspondantes, ils seront fusionnés. Si plusieurs règles correspondantes contiennent des scripts d'animation pour le même déclencheur, la dernière prendra effet, tout comme les autres options.

Migration des anciennes règles

La plupart des options de règles devraient correspondre 1:1 aux nouvelles règles de fenêtre. Voici une liste des options non triviales et comment obtenir le même effet avec les règles de fenêtre.

Assombrissement et opacité inactifs

Cela inclut les options -i, --inactive-opacity=OPACITÉ, --inactive-dim VALEUR, --active-opacity OPACITÉ, --inactive-opacity-override, --mark-wmwin-focused et --mark-ovredir-focused. Lors de l'utilisation des règles de fenêtre, le compositeur n'a plus de concept de « fenêtre active », car c'est facile à obtenir avec les règles de fenêtre. Vous pouvez utiliser match = "focused || group_focused" pour faire correspondre les fenêtres qui auraient été considérées comme actives avec les anciennes options. Ensuite, vous pouvez définir l'opacité et le niveau d'assombrissement pour les fenêtres correspondantes en conséquence. --mark-wmwin-focused et --mark-ovredir-focused peuvent être obtenus en ajoutant || wmwin et || override_redirect à la chaîne de correspondance, respectivement. --inactive-opacity-override peut être obtenu en définissant opacity-override = true.

Note

Définir explicitement opacity avec une règle remplacera la valeur d'opacité de la propriétés de fenêtre (c'est-à-dire _NET_WM_WINDOW_OPACITY), qui est utilisé par des outils comme picom-trans pour définir l'opacité de la fenêtre. Si vous souhaitez continuer à utiliser des outils comme picom-trans, vous pouvez choisir de définir l'opacité uniquement pour les fenêtres sans propriété d'opacité en faisant correspondre ! _NET_WM_WINDOW_OPACITY.

Fenêtre active

Cela inclut l'option --focus-exclude CONDITION. Cette option était uniquement utilisée pour influencer quelles fenêtres sont considérées comme actives, afin d'appliquer l'opacité et le fondu des fenêtres inactives. Comme avec les règles de fenêtre, vous n'avez plus besoin du compositeur pour vous aider à décider ce qui est actif et ce qui ne l'est pas (voir ci-dessus), cette option n'est plus nécessaire.

Coins arrondis et fenêtres en plein écran

Les coins arrondis ne sont plus automatiquement désactivés pour les fenêtres en plein écran. Si vous souhaitez désactiver les coins arrondis pour les fenêtres en plein écran, vous pouvez utiliser la règle suivante : 
rules = (
        { match = "fullscreen"; corner-radius = 0; },
)

FORMAT DES CONDITIONS

Certaines options acceptent une chaîne de condition pour faire correspondre certaines fenêtres. Une chaîne de condition est formée d'une ou plusieurs conditions, reliées par des opérateurs logiques.

La grammaire formelle d'une condition ressemble à ceci :

Condition <- Term ('||' Term)*
Term <- Item ('&&' Item)*
Item <- '!'? Target '@'? ('[' Index ']')? (Operator Pattern)? | '(' Condition ')'

Concrètement, une condition est une séquence d'un ou plusieurs motifs simples correspondant à des Items, reliés par les opérateurs logiques && (et) et || (ou). && a une priorité plus élevée que ||. Les deux opérateurs sont associatifs à gauche. Les parenthèses peuvent être utilisées pour augmenter la priorité. Si un Item a un opérateur de négation en préfixe (!), le résultat de l'élément est nié.

À l'intérieur d'un Item :

Target

est soit un nom de cible prédéfini, soit le nom d'une propriété de fenêtre à faire correspondre.

Les cibles prédéfinies prises en charge sont :

x, y, x2, y2

Coordonnées de la fenêtre, du coin supérieur gauche de la fenêtre (x, y) au coin inférieur droit (x2, y2).

width, height

Taille de la fenêtre.

widthb, heightb

Comme width et height, mais incluant la bordure de la fenêtre.

border_width

Largeur de la bordure de la fenêtre.

fullscreen

Indique si la fenêtre est en plein écran. Si --no-ewmh-fullscreen est défini, cela est déterminé par la taille et la position de la fenêtre ; sinon, cela est déterminé par la propriété _NET_WM_STATE_FULLSCREEN.

override_redirect

Indique si la fenêtre est override-redirect.

argb

Indique si la fenêtre a une visualisation ARGB.

focused

Indique si la fenêtre a le focus.

group_focused

Indique si la fenêtre est dans le même groupe de fenêtres que la fenêtre focalisée. Cela nécessite --detect-transient ou --detect-client-leader.

wmwin

Indique si la fenêtre ressemble à une fenêtre WM, c'est-à-dire qu'elle n'a pas de fenêtre cliente et n'est pas override-redirectée.

bounding_shaped

Indique si la fenêtre a une forme de délimitation.

rounded_corners

Indique si la forme de délimitation de la fenêtre n'a que des coins arrondis et est par ailleurs rectangulaire. Cela implique bounding_shaped. Nécessite --detect-rounded-corners. Ceci n'a aucun rapport avec --corner-radius VALUE.

window_type

Type de fenêtre, tel que défini par _NET_WM_WINDOW_TYPE. Nom uniquement, par exemple, normal signifie _NET_WM_WINDOW_TYPE_NORMAL. Comme une fenêtre peut avoir plusieurs types, le test d'égalité réussit si l'un des types de la fenêtre correspond.

name

Nom de la fenêtre. Il s'agit soit de _NET_WM_NAME, soit de _WM_NAME.

class_i, class_g

Instance et classe générale de la fenêtre. Il s'agit respectivement de la première et de la deuxième valeur de _WM_CLASS.

role

Rôle de la fenêtre. Il s'agit de la valeur de _WM_WINDOW_ROLE.

Target peut être suivi d'un @ optionnel si l'attribut de la fenêtre doit être recherché sur la fenêtre cliente. Sinon, la fenêtre de cadre sera utilisée.

Index

est le numéro d'index de la propriété à rechercher. Par exemple, [2] renvoie la troisième valeur de la propriété. Si non spécifié, la première valeur (index [0]) est utilisée implicitement. Utilisez la valeur spéciale [*] pour effectuer une correspondance avec toutes les valeurs de propriété disponibles en utilisant un OU logique. Aucune des cibles prédéfinies n'a de valeurs multiples, donc n'utilisez pas cela avec elles.

Operator et Pattern

définissent comment Target sera mis en correspondance. Ils peuvent être omis ensemble, auquel cas l'existence de la propriété de fenêtre est vérifiée lorsque Target n'est pas une cible prédéfinie ; pour une Target prédéfinie, omettre Operator et Pattern équivaut à écrire != 0.

Les opérateurs disponibles dépendent du type de Target correspondant. Si la cible est un nombre, les opérateurs sont =, >, <, >=, <=, ainsi que leur négation, obtenue en préfixant l'opérateur avec ! (par exemple, !=, !>, etc.). Si la cible est une chaîne de caractères, les opérateurs sont = (égal strict), *= (correspondance de sous-chaîne), ^= (commence par), %= (correspondance avec glob), ~= (correspondance avec regex), ainsi que leurs variantes insensibles à la casse ?=, *?=, ^?=, %?=, ~?=. Les opérateurs de chaîne peuvent également être niés en préfixant l'opérateur avec ! (par exemple, !=, !*=, etc.).

Pattern est soit un entier, soit une chaîne de caractères entourée de guillemets simples ou doubles. Les séquences d'échappement de style Python 3 sont prises en charge pour les chaînes. Les valeurs booléennes sont interprétées comme des entiers, c'est-à-dire que l'écriture true est équivalente à 1, et false à 0.

Exemples :

# Si la fenêtre a le focus
focused
focused = 1
# Si la fenêtre n'est pas override-redirectée
!override_redirect
override_redirect = false
override_redirect != true
override_redirect != 1
# Si la fenêtre est un menu
window_type *= "menu"
_NET_WM_WINDOW_TYPE@ *= "MENU"
# Si la fenêtre est marquée comme cachée : _NET_WM_STATE contient _NET_WM_STATE_HIDDEN
_NET_WM_STATE@[*] = "_NET_WM_STATE_HIDDEN"
# Si la fenêtre est marquée comme "sticky" : _NET_WM_STATE contient un atome qui contient
# "sticky", ignorant la casse
_NET_WM_STATE@[*] *?= "sticky"
# Si le nom de la fenêtre contient "Firefox", ignorant la casse
name *?= "Firefox"
_NET_WM_NAME@ *?= "Firefox"
# Si le nom de la fenêtre se termine par "Firefox"
name %= "*Firefox"
name ~= "Firefox$"
# Si la fenêtre a une propriété _COMPTON_SHADOW avec la valeur 0, type CARDINAL,
# format 32, valeur 0, sur sa fenêtre de cadre
_COMPTON_SHADOW = 0
# Si la troisième valeur de _NET_FRAME_EXTENTS est inférieure à 20, ou s'il n'y a pas
# de propriété _NET_FRAME_EXTENTS sur la fenêtre cliente
_NET_FRAME_EXTENTS@[2] < 20 || !_NET_FRAME_EXTENTS@
# Le motif ici sera analysé comme "dd4"
name = "\x64\x64\o64"
# Ces deux-là sont équivalents
name = 'Firefox' || name = 'Chromium' && class_i = 'Navigator'
name = 'Firefox' || (name = 'Chromium' && class_i = 'Navigator')

ANIMATIONS

picom prend en charge l'animation de fondu lors de l'ouverture ou de la fermeture d'une fenêtre. En plus de cela, picom dispose également d'un système de scripts d'animation très puissant, qui peut être utilisé pour animer de nombreux aspects d'une fenêtre en fonction de certains déclencheurs. Les scripts d'animation peuvent être définis dans votre fichier de configuration en définissant l'option animations. Il est également possible de définir des animations par fenêtre en utilisant le système de **RÈGLES DE FENÊTRE**, en définissant l'option animations dans une règle. (Lisez le reste de cette section avant d'y aller.)

La syntaxe de base de l'option animations est la suivante :

animations = ({
        triggers = [ ... ];
        suppressions = [ ... ];
        # d'autres options suivent
        ...
}, {
        # un autre script d'animation
}, ...)

animations = ( ... ) définit animations sur une liste, qui peut contenir plusieurs sous-éléments, chaque élément étant un script d'animation. Un script d'animation est un groupe contenant plusieurs entrées (c'est-à-dire { clé = valeur; ... }). Tous les scripts d'animation partagent certaines options communes, comme triggers et suppressions, ils contiennent également d'autres options qui définissent l'animation réelle ou sélectionnent un préréglage d'animation.

Options communes

triggers

Une liste de déclencheurs spécifiant quand cette animation doit être lancée. Chaque déclencheur ne peut avoir qu'un seul script d'animation associé, sinon le comportement est indéfini et un avertissement sera émis.

Les déclencheurs valides sont :

open

Lorsqu'une fenêtre est ouverte.

close

Lorsqu'une fenêtre est fermée.

show

Lorsqu'une fenêtre minimisée ou iconifiée est affichée.

hide

Triggers

An animation is activated by a trigger. This is a specific event that happens during the lifecycle of a window. The following events are available:

open

When a window is opened.

close

When a window is closed.

destroy

When a window is destroyed. This is usually called right after close.

map

When a window is mapped. This happens when the window becomes visible on the screen.

unmap

When a window is unmapped. This happens when the window becomes invisible on the screen.

focus-in

When a window gains keyboard focus.

focus-out

When a window loses keyboard focus.

enter-pointer

When the mouse pointer enters the window.

leave-pointer

When the mouse pointer leaves the window.

minimize

When a window is minimized or iconified.

increase-opacity

When the opacity of a window is increased.

decrease-opacity

When the opacity of a window is decreased.

geometry

When the geometry of a window is changed. (EXPERIMENTAL)

Warning

The geometry trigger is experimental. Using this means you accept the caveat that geometry animations will also trigger when you manually resize or move a window, like when you drag the window around with your mouse.

suppressions

Which other animations should be suppressed when this animation is running. Normally, if another trigger is activated while an animation is already running, the animation in progress will be interrupted and the new animation will start. If you want to prevent this, you can set the suppressions option to a list of triggers that should be suppressed. This is optional, the default value for this is an empty list.

Presets

Defining an animation is a bit involved. To make animations more approachable, without you having to learn the nitty-gritty details of the script system, picom provides a number of presets that you can use by just specifying a handful of options.

To choose a preset, add a preset option to an animation script group, like this:

animations = ({
        triggers = [ "close", "hide" ];
        preset = "slide-out";
        direction = "down";
        ...
}, ...)

Some presets have additional options that you can set to customize the animation. In this example, the slide-out preset has a direction option specifying the direction of the sliding animation.


Note

Describing animations with only words is difficult. We have short video clips showing off each preset, but sadly they cannot be included in this manpage. The web version of this document hosted on our website at
https://picom.app on the other hand, does have those clips.

The following presets are available:

slide-in, slide-out

Show/hide the window with a sliding animation.

Options

direction

The sliding direction, valid values are up, down, left, right.

duration

Duration of the animation in seconds. (Can be fractional).

fly-in, fly-out

Show/hide the window with a flying animation.

Options

direction

The flying direction, valid values are up, down, left, right.

duration

Duration of the animation in seconds.

appear, disappear

Show/hide the window with a combination of scaling and fading.

Options

scale

The scaling factor of the window, 1.0 means no scaling.

duration

Duration of the animation in seconds.

geometry-change

Animate the geometry (i.e. size and position) change of the window.


Warning

This makes use of both the geometry trigger, and the saved-image-blend output variable. Both of these features are experimental and may not work as expected.

Options

duration

Duration of the animation in seconds.

Advanced

If the existing presets don’t meet your needs, it is always possible to define your own animations. To put it simply, an animation script is just a collection of variables, and how their values should be computed. Animation scripts, when running, are evaluated once per frame, and the values of some of the variables are then used to animate the window.

Basic syntax

To concretely illustrate what the above means, here is an example:

# this animation script does nothing to your windows by the way.
animations = ({
        # common options, these are not part of the collection of variables
        triggers = [ "open" ];
        # variables
        a = 10;
        b = "a * 10";
        c = "a + b";
        d = {
                curve = "cubic-bezier(0.25, 0.1, 0.25, 1.0)";
                duration = 0.5;
                delay = 0;
                start = 0;
                end = 1;
        };
        # more options follow
        # ...
}, ...)

A variable can be defined as a number, an expression, or a timing function. In the example above, a is defined to be a number (10), b is defined to be the result of the expression a * 10, and c similarly. Expression used to define one variable can refer to other variables in the same script. This is how you can create complex animations. Where the variables are defined in the script does not matter, as long as no circular references exist.


Note

Because variable names can contain dashes (-), minus signs in expressions must be surrounded by spaces. For example, a - 10 means a minus 10, whereas a-10 is a variable named a-10.

d is a timing function, which is a group with several options specifying its behavior. Timing functions are what drives an animation. If no timing function is defined in an animation script, nothing will be animated and the animation will end instantly.

These options are valid for a timing function:

curve

Type of the curve and its parameters. It can be linear, which takes no parameters and defines a linear curve; or cubic-bezier, which takes four parameters for the four control points of the cubic bezier curve; or step, which takes one or two parameters, the first is the number of steps, the second is the "jumpterm", which can be jump-start, jump-end, jump-none, or jump-both. This option is optional, is not specified, the curve will be linear.

delay

The number of seconds to wait before the value starts changing. Optional, defaults to 0.

duration

The number of seconds it will take for the value to go from start to end once it starts changing. Mandatory. And must be greater than 0.

start

The start value of the variable. Mandatory.

end

The end value of the variable. Mandatory.

All options except curve can be set to expressions. Timing function options are not variables themselves.


Note

If any of delay, duration, start, or end is defined with an expression, the expression will be evaluated only once when the animation starts. The values of delay, duration, start, and end will then be fixed for the duration of the animation.

The total duration of an animation is determined by the duration of the timing function with the longest duration. The animation will end when the longest timing function ends. Once an animation ends, its effects on the window will be removed.

There isn’t any restriction on what you can name the variables. Obviously they cannot conflict with the names of common options (triggers, suppressions, and preset), but other than that, you can name them whatever you want as long as libconfig allows it. Some variable names have special meanings as we will see below.

Output variables

Now you know how to write an animation script. But what we just wrote doesn’t actually do anything to the window. To animate a window, we define a set of special variable names which we will call "output variables". If you define variables with these names, their values will be used to animate the window.

For example, if you define an animation script like this:

animations = ({
        triggers = [ "open" ];
        offset-x = {
                duration = 2;
                start = 0;
                end = 100;
        };
}, ...)

Then when a window opens, it will move 100 pixels to the right over the course of 2 seconds.


Warning

Although we did say you can name your variables whatever you want, if some of them become output variables in the future, your animation script will behave unexpectedly. To avoid this kind of problems, we reserve several classes of variable names which we will never use for special variables. These are: 1) any names that start with a single letter followed by a dash (e.g. a-, b-, etc.); 2) any names that start with var-, tmp-, or user-. If you need to define a non-output variable, use one of these names.

Currently, these output variables are supported:

offset-x, offset-y

The offset of the window in the X and Y direction, respectively. The window body will be moved by this amount. Note this does not affect the shadow, so if you define these but not shadow-offset-x or shadow-offset-y, the shadow will remain where the window was without the animation.

shadow-offset-x, shadow-offset-y

The offset of the shadow in the X and Y direction, respectively. The shadow will be moved by this amount.

opacity

The opacity of the window. This is a number between 0 and 1.

blur-opacity

The opacity of the blur behind the window. This is a number between 0 and 1.
nombre entre 0 et 1.

shadow-opacity

L'opacité de l'ombre. C'est un nombre entre 0 et 1.

scale-x, scale-y, shadow-scale-x, shadow-scale-y

Le facteur d'échelle de la fenêtre et de l'ombre dans les directions X et Y, respectivement. 1.0 signifie aucune mise à l'échelle. Le corps de la fenêtre et l'ombre sont mis à l'échelle indépendamment.

crop-x, crop-y, crop-width, crop-height

Ces quatre valeurs définissent ensemble un rectangle sur l'écran. La fenêtre et son ombre seront recadrées à ce rectangle. Si elles ne sont pas définies, la fenêtre et l'ombre ne seront pas recadrées.

saved-image-blend

Lorsque la géométrie de la fenêtre change, son contenu change souvent de façon drastique, créant une discontinuité choquante. Cette variable de sortie vous permet de mélanger le contenu de la fenêtre avant et après le changement de géométrie, les images avant et après seront étirées de manière appropriée pour correspondre à l'animation. Ainsi, vous pouvez animer en douceur les changements de géométrie. C'est un nombre entre 0 et 1. 0 signifie que l'image sauvegardée n'est pas utilisée, tandis que 1 signifie que vous ne verrez que l'image sauvegardée. (EXPÉRIMENTAL)

Attention

La variable saved-image-blend est expérimentale. Elle peut fonctionner incorrectement, provoquer des artefacts visuels ou ralentir votre système. Vous êtes invité à ouvrir un problème sur GitHub si vous rencontrez des problèmes pour nous aider à l'améliorer, bien que la résolution ne soit pas garantie.

Toutes les coordonnées sont en pixels et sont dans le système de coordonnées de l'écran. Les tailles sont également en pixels.


Important

Si le nom d'une variable de sortie n'est pas défini dans votre script d'animation, il prendra la valeur par défaut pour l'état dans lequel se trouve la fenêtre. Plus précisément, si vous ne définissez pas de variable opacity dans le script d'animation pour le déclencheur "close" ou "hide", une fenêtre fermée aura, par défaut, une opacité de 0. Vous la verrez donc disparaître instantanément. Souvent, vous voudrez définir opacity à 1 pour rendre la fenêtre visible pendant la durée de l'animation.

Variables de contexte

Vous savez maintenant comment animer une fenêtre. Mais cela reste insuffisant pour supporter la plupart des animations que vous pourriez vouloir définir. Par exemple, si vous voulez que votre fenêtre sorte du côté droit de votre écran, la quantité de pixels qu'elle doit déplacer dépend de sa position à l'écran et de sa largeur. Pour la dernière pièce du puzzle, nous avons les variables de contexte.

Une variable de contexte est une variable que picom définit pour vous, et vous pouvez l'utiliser dans des expressions comme n'importe quelle autre variable. Leurs valeurs reflètent certains attributs de la fenêtre que vous animez.


Attention

Si vous définissez une variable portant le même nom qu'une variable de contexte, votre variable masquera la variable de contexte. Comme d'autres variables de contexte peuvent être ajoutées à l'avenir, cela peut être difficile à éviter. Par conséquent, la même règle que pour les variables de sortie s'applique ici : si vous avez besoin de définir une variable temporaire, utilisez l'un des noms réservés.

Actuellement, ces variables de contexte sont définies :

window-x, window-y

Les coordonnées du coin supérieur gauche de la fenêtre.

window-width, window-height

La taille de la fenêtre.

window-x-before, window-y-before, window-width-before, window-height-before

La taille et les coordonnées de la fenêtre par rapport à l'image précédente. Celles-ci ne sont significativement différentes des variables de géométrie de fenêtre normales qu'à l'intérieur des animations déclenchées par le déclencheur geometry.

window-monitor-x, window-monitor-y, window-monitor-width, window-monitor-height

Définit le rectangle qui reflète l'écran sur lequel se trouve la fenêtre. Si la fenêtre n'est pas entièrement contenue dans un écran, le rectangle reflétera l'écran virtuel entier.

window-raw-opacity-before, window-raw-opacity

Les déclencheurs d'animation sont généralement accompagnés d'un changement dans l'opacité de la fenêtre. Par exemple, lorsqu'une fenêtre est ouverte, son opacité passe de 0 à 1. Ces deux variables reflètent l'opacité de la fenêtre pour l'image précédente et l'image actuelle. Elles sont utiles si vous souhaitez faire une transition en douceur de l'opacité de la fenêtre.

Important

Toutes les variables window-*-before sont mises à jour à chaque image et reflètent l'état de la fenêtre dans l'image précédente. Cela signifie qu'elles ne seront significatives que pour une seule image, lorsqu'une animation vient d'être déclenchée. Vous ne devriez donc les utiliser que pour définir les valeurs start, end, duration, ou delay d'une fonction de synchronisation, car ces valeurs ne sont évaluées qu'une seule fois au début de l'animation.

Partagez vos animations

Si vous avez créé un script d'animation que vous trouvez particulièrement cool, vous êtes encouragé à le partager avec la communauté. Vous pouvez soumettre un problème ou une demande de tirage à picom sur GitHub, et avoir une chance de voir votre animation incluse parmi les préréglages, afin qu'elle puisse être utilisée par tout le monde.

INTERFACE DU SHADER

Cette section décrit l'interface d'un shader personnalisé, comment il est utilisé par picom, et quels paramètres sont passés par picom au shader. Cela ne s'applique pas aux anciens backends.

Un shader personnalisé est un programme de shader de fragment GLSL, qui peut être utilisé pour remplacer la manière par défaut de rendu d'une fenêtre. Si un shader personnalisé est utilisé, les effets par défaut de picom (par exemple, assombrissement, inversion des couleurs, etc.) ne seront plus appliqués automatiquement. Il serait de la responsabilité du shader personnalisé d'appliquer ces effets.

L'interface entre picom et un shader personnalisé dépend du backend utilisé. Le backend xrender ne prend pas en charge les shaders du tout. Ici, nous décrivons l'interface fournie par le backend glx.

Le shader doit définir une fonction, vec4 window_shader(), qui serait le point d'entrée du shader. Le vec4 retourné sera utilisé pour définir gl_FragColor. Une fonction, vec4 default_post_processing(vec4 c), est fournie pour appliquer les effets par défaut de picom à la couleur d'entrée 'c'.

Les variables uniformes/d'entrée suivantes sont mises à disposition du shader :

in vec2 texcoord;             // coordonnée de texture du fragment
uniform float opacity;        // opacité de la fenêtre (0.0 - 1.0)
uniform float dim;            // facteur d'assombrissement de la fenêtre (0.0 - 1.0, plus élevé signifie plus sombre)
uniform float corner_radius;  // rayon des coins de la fenêtre (pixels)
uniform float border_width;   // largeur estimée des bords de la fenêtre (pixels)
uniform bool invert_color;    // si la couleur de la fenêtre doit être inversée
uniform sampler2D tex;        // texture de la fenêtre
uniform vec2 effective_size;  // dimensions effectives de la texture (répète les pixels si plus grande que tex)
uniform sampler2D brightness; // luminosité estimée de la fenêtre, texture 1x1
uniform float max_brightness; // luminosité maximale configurée de la fenêtre (0.0 - 1.0)
uniform float time;           // temps en millisecondes, compté à partir d'un point de départ non spécifié

Le comportement par défaut du rendu des fenêtres picom peut être reproduit par le shader suivant :

#version 330
in vec2 texcoord;             // coordonnée de texture du fragment
uniform sampler2D tex;        // texture de la fenêtre
// Post-traitement par défaut de la fenêtre :
// 1) inversion de couleur
// 2) opacité / transparence
// 3) écrêtage de la luminosité maximale
// 4) coins arrondis
vec4 default_post_processing(vec4 c);
// Shader de fenêtre par défaut :
// 1) récupération du pixel spécifié
// 2) application du post-traitement par défaut
vec4 window_shader() {
    vec2 texsize = textureSize(tex, 0);
    vec4 c = texture2D(tex, texcoord / texsize, 0);
    return default_post_processing(c);
}

L'interface devrait rester globalement stable.

FICHIERS DE CONFIGURATION

picom peut lire à partir d'un fichier de configuration si le support de libconfig est compilé. Si --config n'est pas utilisé, picom recherchera un fichier de configuration dans $XDG_CONFIG_HOME/picom.conf (~/.config/picom.conf, généralement), puis $XDG_CONFIG_HOME/picom/picom.conf, puis $XDG_CONFIG_DIRS/picom.conf (souvent /etc/xdg/picom.conf), puis $XDG_CONFIG_DIRS/picom/picom.conf.

Lorsque la directive @include est utilisée dans le fichier de configuration, picom recherchera d'abord le fichier inclus dans le répertoire parent de picom.conf, puis dans $XDG_CONFIG_HOME/picom/include/, puis dans $XDG_CONFIG_DIRS/picom/include.

picom utilise le format général de fichier de configuration libconfig. Un exemple de fichier de configuration est disponible sous le nom picom.sample.conf dans l'arborescence source. La plupart des options de ligne de commande peuvent également être utilisées comme options dans le fichier de configuration. Par exemple, l'option --vsync documentée ci-dessus peut être définie dans le fichier de configuration en utilisant `vsync = `. Les options de ligne de commande remplaceront toujours les paramètres du fichier de configuration.

Certaines options ne peuvent être définies que dans le fichier de configuration. Ces options incluent rules (voir RÈGLES DE FENÊTRE), animations (voir ANIMATIONS), wintypes (voir ci-dessous).

Les paramètres spécifiques au type de fenêtre vous permettent de définir des options spécifiques à la fenêtre en fonction du type de fenêtre. Ces paramètres ne sont exposés que dans le fichier de configuration. Le format de cette option est le suivant :

wintypes:
{
  TYPE_FENETRE = { fade = BOOL; shadow = BOOL; opacity = FLOAT; focus = BOOL; blur-background = BOOL; full-shadow = BOOL; clip-shadow-above = BOOL; redir-ignore = BOOL; };
};

Attention

Son utilisation est fortement déconseillée, voir la section RÈGLES DE FENÊTRE pour la manière recommandée de définir les options spécifiques aux fenêtres.


Important

Conformément à la spécification du gestionnaire de fenêtres, une fenêtre peut avoir plusieurs types. Mais en raison des limitations de l'implémentation de wintypes, si une fenêtre a plusieurs types, alors pour l'application des options wintypes, l'un des types de fenêtre sera choisi au hasard. Encore une fois, il est recommandé d'utiliser plutôt les RÈGLES DE FENÊTRE.

WINDOW RULES

Les règles de fenêtres permettent de configurer les effets de manière plus granulaire, par exemple pour désactiver les ombres pour une fenêtre spécifique.

La syntaxe d'une règle est la suivante:

[condition] = [setting]

Les conditions possibles sont:

class_g : La classe de fenêtre (WM_CLASS) en majuscules.

class_c : La classe de fenêtre (WM_CLASS) en minuscules.

title : Le titre de la fenêtre.

id : L'ID de la fenêtre (par exemple, 0x12345678).

xid : L'ID de la fenêtre X11.

window_type : Le type de fenêtre selon la spécification EWMH.

parent_class_g, parent_class_c, parent_title, parent_id, parent_xid : Comme ci-dessus, mais pour la fenêtre parente.

follow : Si la fenêtre doit suivre la souris.

opacity : L'opacité de la fenêtre.

pinned : Si la fenêtre est épinglée.

mapped : Si la fenêtre est mappée.

urgent : Si la fenêtre est marquée comme urgente.

urgency : Le niveau d'urgence de la fenêtre.

x, y, w, h : La position et la taille de la fenêtre.

desktop : Le bureau sur lequel se trouve la fenêtre.

state : L'état de la fenêtre (par exemple, _NET_WM_STATE_MAXIMIZED_VERT).

pid : L'ID du processus qui a créé la fenêtre.

cliente_id : L'ID client de la fenêtre.

z_order : L'ordre z de la fenêtre.

monitor : Le numéro du moniteur sur lequel se trouve la fenêtre.

monitor_name : Le nom du moniteur sur lequel se trouve la fenêtre.

all : Une condition toujours vraie.

Les réglages possibles sont:

opacity : Définit l'opacité de la fenêtre.

fade : Active ou désactive le fondu pour la fenêtre.

shadow : Active ou désactive l'ombre pour la fenêtre.

clip-shadow-above : Désactive le dessin de l'ombre au-dessus de la fenêtre.

blur-background : Active ou désactive le flou de l'arrière-plan de la fenêtre.

focus : Indique si la fenêtre doit toujours être considérée comme focalisée.

full-shadow : Dessine des ombres même sous les parties normalement invisibles de la fenêtre.

redir-ignore : Ignore le redimensionnement de l'écran pour cette fenêtre.

mark : Ajoute une marque à la fenêtre.

Les conditions peuvent être combinées avec les opérateurs logiques && (ET) et || (OU).

Les types de fenêtres définis dans EWMH sont : "unknown", "desktop", "dock", "toolbar", "menu", "utility", "splash", "dialog", "normal", "dropdown_menu", "popup_menu", "tooltip", "notification", "combo", et "dnd".

Les options par type de fenêtre suivantes sont disponibles:

fade, shadow

Contrôle les paramètres d'ombre et de fondu spécifiques au type de fenêtre.

opacity

Contrôle l'opacité par défaut du type de fenêtre.

focus

Contrôle si la fenêtre de ce type doit toujours être considérée comme focalisée. (Par défaut, tous les types de fenêtres sauf "normal" et "dialog" l'ont activée.)

blur-background

Contrôle si l'arrière-plan transparent de la fenêtre doit être flouté.

full-shadow

Contrôle si une ombre doit être dessinée sous les parties de la fenêtre que vous ne pouvez normalement pas voir. Utile lorsque la fenêtre a des parties transparentes et que vous souhaitez des ombres dans ces zones.

clip-shadow-above

Contrôle si les ombres qui auraient dû être dessinées au-dessus de la fenêtre doivent être coupées. Utile pour les fenêtres de type dock qui ne devraient pas avoir d'ombre peinte par-dessus.

redir-ignore

Contrôle si ce type de fenêtre doit provoquer une nouvelle redirection de l'écran après avoir été non redirigé. Si vous avez défini --unredir-if-possible et que vous ne voulez pas qu'une certaine fenêtre provoque une redirection d'écran inutile, vous pouvez définir ceci sur true.

BLUR

Vous pouvez configurer la manière dont l'arrière-plan de la fenêtre est flouté en utilisant une section 'blur' dans votre fichier de configuration. Voici un exemple:

blur:
{
  method = "gaussian";
  size = 10;
  deviation = 5.0;
};

Les options disponibles de la section blur sont:

method

Une chaîne de caractères. Contrôle la méthode de floutage. Correspond à l'option de ligne de commande --blur-method. Les choix disponibles sont : none pour désactiver le floutage ; gaussian pour le floutage gaussien ; box pour le floutage par boîte ; kernel pour le floutage par convolution avec un noyau personnalisé ; dual_kawase pour le floutage kawase à double filtre. Note : les méthodes de floutage gaussian, box et dual_kawase ne sont pas prises en charge par les backends hérités. (par défaut : none)

size

Un entier. La taille du noyau de floutage, requise par les méthodes de floutage gaussian et box. Pour la méthode kernel, la taille est incluse dans le noyau. Correspond à l'option de ligne de commande --blur-size (par défaut : 3).

deviation

Un nombre à virgule flottante. L'écart type pour la méthode de floutage gaussian. Correspond à l'option de ligne de commande --blur-deviation (par défaut : 0.84089642).

strength

Un entier dans la plage 0-20. La force de la méthode de floutage dual_kawase. Correspond à l'option de ligne de commande --blur-strength. Si défini sur zéro, la valeur demandée par --blur-size est approximée (par défaut : 5).

kernel

Une chaîne de caractères. Le noyau à utiliser pour la méthode de floutage kernel, spécifié dans le même format que l'option --blur-kern. Correspond à l'option de ligne de commande --blur-kern.

SIGNALS

• picom se réinitialise à la réception de SIGUSR1.

D-BUS API

Il est possible de contrôler picom via des messages D-Bus, en exécutant picom avec --dbus et en envoyant des messages à com.github.chjj.compton.<DISPLAY>. <DISPLAY> est l'affichage utilisé par picom, avec tous les caractères non alphanumériques transformés en underscores. Pour DISPLAY=:0.0 vous devriez utiliser com.github.chjj.compton._0_0, par exemple.

Les méthodes et signaux D-Bus ne sont pas encore stables, donc non documentés pour le moment.

EXAMPLES

• Désactiver l'analyse du fichier de configuration : 
$ picom --config /dev/null
• Exécuter picom avec ombre côté client et fondu : 
$ picom -cf
• Identique à ci-dessus, plus rendre les fenêtres inactives transparentes à 80%, rendre le cadre transparent à 80%, ne pas faire de fondu à l'ouverture/fermeture des fenêtres, et forker en arrière-plan : 
$ picom -bcf -i 0.8 -e 0.8 --no-fading-openclose
• Dessiner des ombres blanches : 
$ picom -c --shadow-red 1 --shadow-green 1 --shadow-blue 1
• Éviter de dessiner des ombres sur la fenêtre wbar : 
$ picom -c --shadow-exclude 'class_g = "wbar"'
• Activer la synchronisation verticale avec le backend GLX : 
$ picom --backend glx --vsync
