pidfd_send_signal(2) Manuel des appels système pidfd_send_signal(2)

NOM

pidfd_send_signal - envoyer un signal à un processus spécifié par un descripteur de fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/signal.h>     /* Définition des constantes SIG* */
#include <signal.h>           /* Définition des constantes SI_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_pidfd_send_signal, int pidfd, int sig,
            siginfo_t *_Nullable info, unsigned int flags);

Note : glibc ne fournit pas d'enveloppe pour pidfd_send_signal(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

L'appel système pidfd_send_signal() envoie le signal sig au processus cible référencé par pidfd, un descripteur de fichier PID qui fait référence à un processus.

Si l'argument info pointe vers un tampon siginfo_t, ce tampon doit être rempli comme décrit dans rt_sigqueueinfo(2).

Si l'argument info est un pointeur nul, cela équivaut à spécifier un pointeur vers un tampon siginfo_t dont les champs correspondent aux valeurs qui sont implicitement fournies lorsqu'un signal est envoyé à l'aide de kill(2) :

•
si_signo est défini sur le numéro du signal ;
•
si_errno est défini sur 0 ;
•
si_code est défini sur SI_USER ;
•
si_pid est défini sur le PID de l'appelant ; et
•
si_uid est défini sur l'ID utilisateur réel de l'appelant.

Le processus appelant doit être dans le même espace de noms PID que le processus référencé par pidfd, ou être un ancêtre de cet espace de noms.

L'argument flags permet de modifier la portée du signal. Par défaut, la portée du signal sera déduite de l'argument pidfd. Par exemple, si pidfd fait référence à un thread spécifique – c'est-à-dire que le pidfd a été créé via pidfd_open(2) en utilisant le drapeau PIDFD_THREAD ou via clone3(2) en utilisant le drapeau CLONE_PIDFD conjointement avec le drapeau CLONE_THREAD –, alors passer pidfd à pidfd_send_signal(2) et laisser l'argument flags à 0 entraînera l'envoi du signal au thread spécifique référencé par le pidfd.

PIDFD_SIGNAL_THREAD (depuis Linux 6.9)
Assure que le signal est envoyé au thread spécifique référencé par pidfd.
PIDFD_SIGNAL_THREAD_GROUP (depuis Linux 6.9)
Si pidfd fait référence à un leader de groupe de threads, assure que le signal est envoyé au groupe de threads, même si pidfd a été créé pour faire référence à un thread spécifique.
PIDFD_SIGNAL_PROCESS_GROUP (depuis Linux 6.9)
Si pidfd fait référence à un leader de groupe de processus, assure que le signal est envoyé au groupe de processus, même si pidfd a été créé pour faire référence à un thread spécifique ou à un leader de groupe de threads.

VALEUR DE RETOUR

En cas de succès, pidfd_send_signal() retourne 0. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
pidfd n'est pas un descripteur de fichier PID valide.
EINVAL
sig n'est pas un signal valide.
EINVAL
Le processus appelant n'est pas dans un espace de noms PID depuis lequel il peut envoyer un signal au processus cible.
EINVAL
flags n'est pas valide.
EPERM
Le processus appelant n'a pas la permission d'envoyer le signal au processus cible.
EPERM
pidfd ne fait pas référence au processus appelant, et info.si_code est invalide (voir rt_sigqueueinfo(2)).
ESRCH
Le processus cible n'existe pas (c'est-à-dire qu'il s'est terminé et a été attendu).

NORMES

Linux.

HISTORIQUE

Linux 5.1.

NOTES

DESCRIPTEURS DE FICHIER PID

L'argument pidfd est un descripteur de fichier PID, un descripteur de fichier qui fait référence à un processus. Un tel descripteur de fichier peut être obtenu de l'une des manières suivantes :

•
en ouvrant un répertoire /proc/pid ;
•
en utilisant pidfd_open(2) ; ou
•
via le descripteur de fichier PID qui est retourné par un appel à clone(2) ou clone3(2) qui spécifie le drapeau CLONE_PIDFD.

L'appel système pidfd_send_signal() permet d'éviter les conditions de concurrence qui se produisent lors de l'utilisation d'interfaces traditionnelles (comme kill(2)) pour signaler un processus. Le problème est que les interfaces traditionnelles spécifient le processus cible via un identifiant de processus (PID), avec pour conséquence que l'expéditeur peut accidentellement envoyer un signal au mauvais processus si le processus initialement visé s'est terminé et que son PID a été recyclé pour un autre processus. En revanche, un descripteur de fichier PID est une référence stable à un processus spécifique ; si ce processus se termine, pidfd_send_signal() échoue avec l'erreur ESRCH.

EXEMPLES

#define _GNU_SOURCE
#include <fcntl.h>
#include <limits.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/syscall.h>
#include <unistd.h>
static int
pidfd_send_signal(int pidfd, int sig, siginfo_t *info,
                  unsigned int flags)
{
    return syscall(SYS_pidfd_send_signal, pidfd, sig, info, flags);
}
int
main(int argc, char *argv[])
{
    int        pidfd, sig;
    char       path[PATH_MAX];
    siginfo_t  info;
    if (argc != 3) {
        fprintf(stderr, "Usage: %s <pid> <signal>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    sig = atoi(argv[2]);
    /* Obtenir un descripteur de fichier PID en ouvrant le répertoire /proc/PID
       du processus cible.  */
    snprintf(path, sizeof(path), "/proc/%s", argv[1]);
    pidfd = open(path, O_RDONLY);
    if (pidfd == -1) {
        perror("open");
        exit(EXIT_FAILURE);
    }
    /* Remplir une structure 'siginfo_t' à utiliser avec
       pidfd_send_signal().  */
    memset(&info, 0, sizeof(info));
    info.si_code = SI_QUEUE;
    info.si_signo = sig;
    info.si_errno = 0;
    info.si_uid = getuid();
    info.si_pid = getpid();
    info.si_value.sival_int = 1234;
    /* Envoyer le signal.  */
    if (pidfd_send_signal(pidfd, sig, &info, 0) == -1) {
        perror("pidfd_send_signal");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS);
}

pidfd_send_signal(2) - pages de manuel Linux

envoyer un signal à un processus via un descripteur de fichier de processus

NAME

pidfd_send_signal - envoyer un signal à un processus via un descripteur de fichier de processus

LIBRARY

Bibliothèque C standard (libc), depuis version 2.27

SYNOPSIS


#include <sys/pidfd.h>

int pidfd_send_signal(int pidfd, int sig, siginfo_t *info, unsigned int flags);

DESCRIPTION

La fonction pidfd_send_signal() envoie le signal sig au processus spécifié par le descripteur de fichier de processus pidfd. Le descripteur de fichier de processus doit avoir été créé avec l'appel système pidfd_open(2).

Le paramètre sig est le numéro du signal à envoyer (par exemple, SIGTERM, SIGKILL). Le signal 0 peut être utilisé pour effectuer une vérification d'existence sans envoyer de signal.

Le paramètre info est un pointeur vers une structure siginfo_t qui spécifie des informations supplémentaires à transmettre avec le signal. Si info est NULL, aucune information supplémentaire n'est envoyée.

Le paramètre flags est actuellement réservé et doit être défini à 0.

L'utilisation d'un descripteur de fichier de processus pour envoyer un signal présente plusieurs avantages par rapport à l'utilisation de kill(2) avec un PID :

  • Elle évite les conditions de concurrence où un PID pourrait être réutilisé pour un nouveau processus après la terminaison du processus d'origine.
  • Elle permet d'envoyer un signal à un processus spécifique sans avoir à connaître son PID, seulement son descripteur de fichier de processus.

RETURN VALUE

En cas de succès, pidfd_send_signal() renvoie 0. En cas d'erreur, elle renvoie -1 et définit $errno pour indiquer l'erreur.

ERRORS

EBADF
pidfd n'est pas un descripteur de fichier valide.
EINVAL
sig n'est pas un signal valide ou flags n'est pas 0.
ENOMEM
Pas assez de mémoire pour allouer les structures nécessaires.
ESRCH
Le processus associé à pidfd n'existe pas.
EPERM
Le processus appelant n'a pas la permission d'envoyer le signal au processus cible.

STANDARDS

Cette fonction est spécifique à Linux et a été introduite dans le noyau Linux 5.1.

HISTORY

pidfd_send_signal() a été ajoutée dans le noyau Linux 5.1.

NOTES

Pour utiliser pidfd_send_signal(), vous devez inclure l'en-tête <sys/pidfd.h>.

Le paramètre sig peut également être un signal non standard défini par l'application.

EXAMPLES

L'exemple suivant montre comment envoyer le signal SIGTERM à un processus dont le descripteur de fichier de processus est connu.


#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/pidfd.h>
#include <signal.h>
#include <errno.h>

int main(int argc, char *argv[]) {
    if (argc != 3) {
        fprintf(stderr, "Usage: %s <pidfd> <signal>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    int pidfd = atoi(argv[1]);
    int sig = atoi(argv[2]);

    if (pidfd_send_signal(pidfd, sig, NULL, 0) == -1) {
        perror("pidfd_send_signal failed");
        exit(EXIT_FAILURE);
    }

    printf("Signal %d sent successfully to process with pidfd %d.\n", sig, pidfd);

    return 0;
}
