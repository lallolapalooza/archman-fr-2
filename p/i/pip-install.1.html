PIP-INSTALL(1) pip PIP-INSTALL(1)

NOM

pip-install - description de la commande pip install

DESCRIPTION

Installe des paquets depuis :

  • PyPI (et d'autres index) en utilisant des spécificateurs d'exigences.
  • URL de projets VCS (Système de Contrôle de Version).
  • Répertoires de projets locaux.
  • Archives sources locales ou distantes.

pip supporte également l'installation depuis des « fichiers d'exigences », qui fournissent un moyen simple de spécifier un environnement complet à installer.

USAGE

python -m pip install [options] <spécificateur d'exigence> [options-index-paquets] ...
python -m pip install [options] -r <fichier d'exigences> [options-index-paquets] ...
python -m pip install [options] [-e] <url-projet-vcs> ...
python -m pip install [options] [-e] <chemin-projet-local> ...
python -m pip install [options] <url/chemin-archive> ...

OPTIONS

-r, --requirement <fichier>
Installe à partir du fichier d'exigences donné. Cette option peut être utilisée plusieurs fois.

(variable d'environnement : PIP_REQUIREMENT)

-c, --constraint <fichier>
Contraint les versions en utilisant le fichier de contraintes donné. Cette option peut être utilisée plusieurs fois.

(variable d'environnement : PIP_CONSTRAINT)

--build-constraint <fichier>
Contraint les dépendances de construction en utilisant le fichier de contraintes donné. Cette option peut être utilisée plusieurs fois.

(variable d'environnement : PIP_BUILD_CONSTRAINT)

--no-deps
N'installe pas les dépendances du paquet.

(variable d'environnement : PIP_NO_DEPS, PIP_NO_DEPENDENCIES)

--pre
Inclut les versions pré-release et de développement. Par défaut, pip ne trouve que les versions stables.

(variable d'environnement : PIP_PRE)

-e, --editable <chemin/url>
Installe un projet en mode éditable (c'est-à-dire le mode « develop » de setuptools) depuis un chemin de projet local ou une URL VCS.

(variable d'environnement : PIP_EDITABLE)

--dry-run
N'installe rien réellement, affiche seulement ce qui serait fait. Peut être utilisé en combinaison avec --ignore-installed pour « résoudre » les exigences.

(variable d'environnement : PIP_DRY_RUN)

-t, --target <répertoire>
Installe les paquets dans <répertoire>. Par défaut, cela ne remplacera pas les fichiers/dossiers existants dans <répertoire>. Utilisez --upgrade pour remplacer les paquets existants dans <répertoire> par de nouvelles versions.

(variable d'environnement : PIP_TARGET)

--platform <plateforme>
Utilise uniquement les roues (wheels) compatibles avec <plateforme>. Par défaut, utilise la plateforme du système en cours d'exécution. Utilisez cette option plusieurs fois pour spécifier plusieurs plateformes prises en charge par l'interpréteur cible.

(variable d'environnement : PIP_PLATFORM)

--python-version <version-python>
La version de l'interpréteur Python à utiliser pour les vérifications de compatibilité des roues (wheels) et de "Requires-Python". Par défaut, une version dérivée de l'interpréteur en cours d'exécution est utilisée. La version peut être spécifiée en utilisant jusqu'à trois entiers séparés par des points (par exemple, "3" pour 3.0.0, "3.7" pour 3.7.0, ou "3.7.3"). Une version majeure-mineure peut également être donnée sous forme de chaîne sans points (par exemple, "37" pour 3.7.0).

(variable d'environnement : PIP_PYTHON_VERSION)

--implementation <implémentation>
Utilise uniquement les roues (wheels) compatibles avec l'implémentation Python <implémentation>, par exemple 'pp', 'jy', 'cp', ou 'ip'. Si non spécifié, l'implémentation de l'interpréteur actuel est utilisée. Utilisez 'py' pour forcer les roues agnostiques d'implémentation.

(variable d'environnement : PIP_IMPLEMENTATION)

--abi <abi>
Utilise uniquement les roues (wheels) compatibles avec l'ABI Python <abi>, par exemple 'pypy_41'. Si non spécifié, alors l'étiquette ABI de l'interpréteur actuel est utilisée. Utilisez cette option plusieurs fois pour spécifier plusieurs ABI prises en charge par l'interpréteur cible. Généralement, vous devrez spécifier --implementation, --platform et --python-version lors de l'utilisation de cette option.

(variable d'environnement : PIP_ABI)

--user
Installe dans le répertoire d'installation utilisateur Python de votre plateforme. Typiquement ~/.local/, ou %APPDATA%Python sous Windows. (Voir la documentation Python pour site.USER_BASE pour tous les détails.)

(variable d'environnement : PIP_USER)

--root <répertoire>
Installe tout par rapport à ce répertoire racine alternatif.

(variable d'environnement : PIP_ROOT)

--prefix <répertoire>
Préfixe d'installation où les dossiers lib, bin et autres dossiers de premier niveau sont placés. Notez que l'installation résultante peut contenir des scripts et d'autres ressources qui font référence à l'interpréteur Python de pip, et non à celui de --prefix. Voir aussi l'option --python si l'intention est d'installer des paquets dans un autre environnement (potentiellement sans pip).

(variable d'environnement : PIP_PREFIX)

--src <répertoire>
Répertoire dans lequel cloner les projets éditables. Par défaut dans un environnement virtuel (virtualenv) est « <chemin-venv>/src ». Par défaut pour les installations globales est « <répertoire-actuel>/src ».

(variable d'environnement : PIP_SRC, PIP_SOURCE, PIP_SOURCE_DIR, PIP_SOURCE_DIRECTORY)

-U, --upgrade
Met à jour tous les paquets spécifiés vers la version la plus récente disponible. La gestion des dépendances dépend de la stratégie de mise à niveau utilisée.

(variable d'environnement : PIP_UPGRADE)

--upgrade-strategy <stratégie-mise-à-niveau>
Détermine comment les mises à niveau des dépendances doivent être gérées [par défaut: only-if-needed]. « eager » - les dépendances sont mises à niveau indépendamment du fait que la version actuellement installée satisfasse ou non les exigences des paquets mis à niveau. « only-if-needed » - sont mises à niveau uniquement lorsqu'elles ne satisfont pas les exigences des paquets mis à niveau.

(variable d'environnement : PIP_UPGRADE_STRATEGY)

--force-reinstall
Réinstalle tous les paquets même s'ils sont déjà à jour.

(variable d'environnement : PIP_FORCE_REINSTALL)

-I, --ignore-installed
Ignore les paquets installés, en les écrasant. Cela peut casser votre système si le paquet existant est d'une version différente ou a été installé avec un autre gestionnaire de paquets !

(variable d'environnement : PIP_I

pip-install(1) — Installation de paquets

Nom

pip-install, pip — installe des paquets Python

Description

pip est le système de gestion de paquets standard pour Python. Il vous permet d’installer et de gérer des paquets logiciels supplémentaires qui ne font pas partie de la bibliothèque standard Python.

Lors de l’installation de paquets depuis des sources, pip exécutera pip dans un environnement virtuel, afin de construire le paquet dans un environnement propre et prévisible. Cela permet une meilleure reproductibilité et évite de corrompre votre installation Python.

Utilisation

pip install [options] <requirement specifier> ...

pip install --help

Options

-q, --quiet
Moins de verbosité. Peut être utilisé plusieurs fois pour augmenter le niveau de silence.
-v, --verbose
Plus de verbosité. Peut être utilisé plusieurs fois pour augmenter le niveau de verbosité.
--no-input
Ignorer les invites d’entrée.
--log <file>
Utiliser un fichier journal spécifié.

(variable d’environnement : PIP_LOG)

--cache-dir <dir>
Utiliser un répertoire de cache spécifié.

(variable d’environnement : PIP_CACHE_DIR)

--no-cache-dir
Désactiver le cache des paquets.
--disable-pip-version-check
Ignorer la vérification de la version de pip.
--no-deps
N’installez pas les dépendances spécifiées.
--force-reinstall
Réinstaller les paquets déjà installés.
--ignore-installed
Ignorer les paquets déjà installés.
--ignore-requires-python
Ignorer les informations Requires-Python.

(variable d’environnement : PIP_IGNORE_REQUIRES_PYTHON)

--no-build-isolation
Désactiver l’isolation lors de la construction d’une distribution source moderne. Les dépendances de build spécifiées par PEP 518 doivent déjà être installées si cette option est utilisée.

(variable d’environnement : PIP_NO_BUILD_ISOLATION)

--check-build-dependencies
Vérifier les dépendances de build.

(variable d’environnement : PIP_CHECK_BUILD_DEPENDENCIES)

--break-system-packages
Permettre à pip de modifier une installation Python Gérée_Externement

(variable d’environnement : PIP_BREAK_SYSTEM_PACKAGES)

-C, --config-settings <settings>
Paramètres de configuration à passer au backend de build. Les paramètres prennent la forme CLÉ=VALEUR. Utilisez plusieurs options --config-settings pour passer plusieurs clés au backend.

(variable d’environnement : PIP_CONFIG_SETTINGS)

--compile
Compiler les fichiers source Python en bytecode

(variable d’environnement : PIP_COMPILE)

--no-compile
Ne pas compiler les fichiers source Python en bytecode

(variable d’environnement : PIP_NO_COMPILE)

--no-warn-script-location
Ne pas avertir lors de l’installation de scripts en dehors du PATH

(variable d’environnement : PIP_NO_WARN_SCRIPT_LOCATION)

--no-warn-conflicts
Ne pas avertir des dépendances rompues

(variable d’environnement : PIP_NO_WARN_CONFLICTS)

--no-binary <format_control>
Ne pas utiliser de paquets binaires. Peut être fourni plusieurs fois, et chaque fois s’ajoute à la valeur existante. Accepte soit « :all: » pour désactiver tous les paquets binaires, « :none: » pour vider l’ensemble (remarquez les deux-points), soit un ou plusieurs noms de paquets séparés par des virgules (sans deux-points). Notez que certains paquets sont difficiles à compiler et peuvent échouer à s’installer lorsque cette option leur est appliquée.

(variable d’environnement : PIP_NO_BINARY)

--only-binary <format_control>
Ne pas utiliser de paquets source. Peut être fourni plusieurs fois, et chaque fois s’ajoute à la valeur existante. Accepte soit « :all: » pour désactiver tous les paquets source, « :none: » pour vider l’ensemble, soit un ou plusieurs noms de paquets séparés par des virgules. Les paquets sans distributions binaires échoueront à s’installer lorsque cette option leur sera appliquée.

(variable d’environnement : PIP_ONLY_BINARY)

--prefer-binary
Préférer les paquets binaires aux paquets source, même si les paquets source sont plus récents.

(variable d’environnement : PIP_PREFER_BINARY)

--require-hashes
Exiger un hachage pour vérifier chaque exigence, pour des installations reproductibles. Cette option est implicite lorsqu’un paquet dans un fichier d’exigences a une option --hash.

(variable d’environnement : PIP_REQUIRE_HASHES)

--progress-bar <progress_bar>
Spécifier si la barre de progression doit être utilisée. En mode « auto », --quiet supprimera toutes les barres de progression. [auto, on, off, raw] (par défaut : auto)

(variable d’environnement : PIP_PROGRESS_BAR)

--root-user-action <root_user_action>
Action si pip est exécuté en tant qu’utilisateur root [warn, ignore] (par défaut : warn)

(variable d’environnement : PIP_ROOT_USER_ACTION)

--report <file>
Générer un fichier JSON décrivant ce que pip a fait pour installer les exigences fournies. Peut être utilisé en combinaison avec --dry-run et --ignore-installed pour « résoudre » les exigences. Lorsque - est utilisé comme nom de fichier, il écrit sur stdout. Lors de l’écriture sur stdout, veuillez combiner avec l’option --quiet pour éviter de mélanger la sortie de journalisation de pip avec la sortie JSON.

(variable d’environnement : PIP_REPORT)

--group <[path:]group>
Installer un groupe de dépendances nommé à partir d’un fichier « pyproject.toml ». Si un chemin est donné, le nom du fichier doit être « pyproject.toml ». Par défaut, utilise « pyproject.toml » dans le répertoire courant.

(variable d’environnement : PIP_GROUP)

--no-clean
Ne pas nettoyer les répertoires de build.

(variable d’environnement : PIP_NO_CLEAN)
