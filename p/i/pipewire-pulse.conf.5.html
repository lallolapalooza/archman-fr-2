DESCRIPTION

Le fichier de configuration du serveur Pulseaudio de PipeWire

SYNTAXE

DESCRIPTION

Configuration du démon compatible PulseAudio de PipeWire.

Le format du fichier de configuration et la logique de recherche sont identiques à ceux de pipewire.conf(5).

Les fichiers de configuration "drop-in" pipewire-pulse.conf.d/*.conf peuvent être utilisés et sont recommandés. Voir pipewire.conf(5).

SECTIONS DU FICHIER DE CONFIGURATION

stream.properties

Dictionnaire. Ces propriétés configurent les propriétés du serveur Pulseaudio de PipeWire.

stream.rules

Dictionnaire. Ces propriétés configurent les propriétés du serveur Pulseaudio de PipeWire.

pulse.properties

Dictionnaire. Ces propriétés configurent les propriétés du serveur Pulseaudio de PipeWire.

pulse.cmd

Tableau de dictionnaires. Un ensemble de commandes à exécuter au démarrage.

pulse.rules

Tableau de dictionnaires. Un ensemble de règles de correspondance et d'actions à appliquer aux clients.

Voir libpipewire-module-protocol-pulse(7) pour la description détaillée.

En outre, les sections de configuration du contexte PipeWire peuvent également être spécifiées, voir pipewire.conf(5).

PROPRIÉTÉS DE FLUX

La section stream.properties contient les propriétés des flux créés par le serveur pipewire-pulse.

Les options disponibles sont décrites dans pipewire-client.conf(5) stream.properties.

Certaines de ces propriétés correspondent aux entrées de configuration PulseAudio /etc/pulse/default.pa comme suit :

PulseAudio PipeWire Notes remixing-use-all-sink-channels channelmix.upmix remixing-produce-lfe channelmix.lfe-cutoff Définir sur > 0 pour activer remixing-consume-lfe channelmix.mix-lfe lfe-crossover-freq channelmix.lfe-cutoff

Exemple

# ~/.config/pipewire/pipewire-pulse.conf.d/custom.conf
stream.properties = {
    #node.latency = 1024/48000
    #node.autoconnect = true
    #resample.disable = false
    #resample.quality = 4
    #monitor.channel-volumes = false
    #channelmix.disable = false
    #channelmix.min-volume = 0.0
    #channelmix.max-volume = 10.0
    #channelmix.normalize = false
    #channelmix.mix-lfe = true
    #channelmix.upmix = true
    #channelmix.upmix-method = psd  # none, simple
    #channelmix.lfe-cutoff = 150.0
    #channelmix.fc-cutoff = 12000.0
    #channelmix.rear-delay = 12.0
    #channelmix.stereo-widen = 0.0
    #channelmix.hilbert-taps = 0
    #dither.noise = 0
    #dither.method = none # rectangular, triangular, triangular-hf, wannamaker3, shaped5
    #debug.wav-path = ""
}

RÈGLES DE FLUX

La section stream.rules fonctionne de la même manière que pipewire-client.conf(5) stream.rules.

PROPRIÉTÉS PULSEAUDIO

Pour la section pulse.properties, voir libpipewire-module-protocol-pulse(7) pour les options disponibles.

RÈGLES PULSEAUDIO

Pour chaque client, un ensemble de règles peut être écrit dans la section pulse.rules pour configurer des particularités du client ou pour forcer une configuration de flux spécifique à Pulse.

L'aspect général de cette section est le suivant et suit la disposition des règles de correspondance, voir pipewire(1).

Voir libpipewire-module-protocol-pulse(7) pour les options disponibles.

Exemple

# ~/.config/pipewire/pipewire-pulse.conf.d/custom.conf
pulse.rules = [
    {
        # skype ne veut pas utiliser d'appareils qui n'ont pas de format d'échantillon S16.
        matches = [
             { application.process.binary = "teams" }
             { application.process.binary = "teams-insiders" }
             { application.process.binary = "skypeforlinux" }
        ]
        actions = { quirks = [ force-s16-info ] }
    }
    {
        # speech dispatcher demande une latence trop faible et provoque ensuite des sous-dépassements.
        matches = [ { application.name = "~speech-dispatcher*" } ]
        actions = {
            update-props = {
                pulse.min.req          = 1024/48000     # 21ms
                pulse.min.quantum      = 1024/48000     # 21ms
            }
        }
    }
]

COMMANDES PULSEAUDIO

Dans le cadre de la procédure de démarrage du serveur, vous pouvez exécuter des commandes supplémentaires avec la section pulse.cmd dans pipewire-pulse.conf.

# ~/.config/pipewire/pipewire-pulse.conf.d/custom.conf
pulse.cmd = [
    { cmd = "load-module" args = "module-always-sink" flags = [ ] }
    { cmd = "load-module" args = "module-switch-on-connect" }
    { cmd = "load-module" args = "module-gsettings" flags = [ "nofail" ] }
]
...

Des commandes supplémentaires peuvent également être exécutées via la section context.exec, voir pipewire.conf(5).

Commandes prises en charge :

load-module

Charge le module Pulseaudio spécifié au démarrage, comme si vous utilisiez pactl(1) pour charger le module.

MODULES PULSEAUDIO

Pour le contenu de la section pulse.modules, voir pipewire-pulse-modules(7).
