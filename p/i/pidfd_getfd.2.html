pidfd_getfd(2) Manuel des appels système pidfd_getfd(2)

NOM

pidfd_getfd - obtenir un duplicata d'un descripteur de fichier d'un autre processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_pidfd_getfd, int pidfd, int targetfd,
            unsigned int flags);

Note : glibc ne fournit pas d'enveloppement pour pidfd_getfd(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

L'appel système pidfd_getfd() alloue un nouveau descripteur de fichier dans le processus appelant. Ce nouveau descripteur de fichier est un duplicata d'un descripteur de fichier existant, targetfd, dans le processus référencé par le descripteur de fichier PID pidfd.

Le descripteur de fichier dupliqué fait référence à la même description de fichier ouverte (voir open(2)) que le descripteur de fichier original dans le processus référencé par pidfd. Les deux descripteurs de fichier partagent donc les drapeaux d'état du fichier et l'offset du fichier. De plus, les opérations sur l'objet de fichier sous-jacent (par exemple, l'affectation d'une adresse à un objet socket à l'aide de bind(2)) peuvent être effectuées via le descripteur de fichier dupliqué.

Le drapeau close-on-exec (FD_CLOEXEC ; voir fcntl(2)) est défini sur le descripteur de fichier retourné par pidfd_getfd().

L'argument flags est réservé pour une utilisation future. Actuellement, il doit être spécifié comme 0.

La permission de dupliquer le descripteur de fichier d'un autre processus est régie par une vérification du mode d'accès ptrace PTRACE_MODE_ATTACH_REALCREDS (voir ptrace(2)).

VALEUR DE RETOUR

En cas de succès, pidfd_getfd() retourne un descripteur de fichier (un entier non négatif). En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
pidfd n'est pas un descripteur de fichier PID valide.
EBADF
targetfd n'est pas un descripteur de fichier ouvert dans le processus référencé par pidfd.
EINVAL
flags n'est pas 0.
EMFILE
La limite par processus sur le nombre de descripteurs de fichiers ouverts a été atteinte (voir la description de RLIMIT_NOFILE dans getrlimit(2)).
ENFILE
La limite globale du système sur le nombre total de fichiers ouverts a été atteinte.
EPERM
Le processus appelant ne disposait pas des permissions PTRACE_MODE_ATTACH_REALCREDS (voir ptrace(2)) sur le processus référencé par pidfd.
ESRCH
Le processus référencé par pidfd n'existe pas (c'est-à-dire qu'il s'est terminé et qu'on a attendu sa fin).

NORMES

Linux.

HISTORIQUE

Linux 5.6.

NOTES

Pour une description des descripteurs de fichiers PID, voir pidfd_open(2).

L'effet de pidfd_getfd() est similaire à l'utilisation des messages SCM_RIGHTS décrits dans unix(7), mais diffère par les points suivants :

•
Afin de transmettre un descripteur de fichier à l'aide d'un message SCM_RIGHTS, les deux processus doivent d'abord établir une connexion de socket de domaine UNIX.
•
L'utilisation de SCM_RIGHTS nécessite la coopération du processus dont le descripteur de fichier est copié. En revanche, aucune coopération de ce type n'est nécessaire lors de l'utilisation de pidfd_getfd().
•
La capacité d'utiliser pidfd_getfd() est limitée par une vérification du mode d'accès ptrace PTRACE_MODE_ATTACH_REALCREDS.

VOIR AUSSI

clone3(2), dup(2), kcmp(2), pidfd_open(2)
