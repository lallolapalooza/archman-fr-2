Paquet: iputils

PING(8) iputils PING(8)

NOM

ping - envoyer des datagrammes ICMP ECHO_REQUEST à des hôtes sur le réseau

SYNTAXE

ping [-aAbBdCDfhHLnOqrRUvV346] [-c nombre] [-e identifiant] [-F label_flux] [-i intervalle] [-I interface] [-l prechargement] [-m marqueur] [-M option_pmtudisc] [-N option_nodeinfo] [-w délai] [-W délai_expiration] [-p motif] [-Q tos] [-s taille_paquet] [-S sndbuf] [-t ttl] [-T option_horodatage] [saut...] {destination}

DESCRIPTION

ping utilise le datagramme obligatoire ICMP ECHO_REQUEST du protocole ICMP pour obtenir une réponse ICMP ECHO_RESPONSE d'un hôte ou d'une passerelle. Les datagrammes ECHO_REQUEST (“pings”) contiennent un en-tête IP et ICMP, suivis d'une structure timeval, puis d'un nombre arbitraire d'octets de “remplissage” utilisés pour compléter le paquet.

ping fonctionne avec IPv4 et IPv6. L'utilisation d'un seul protocole explicitement peut être forcée en spécifiant -4 ou -6.

ping peut également envoyer des requêtes d'information de nœud IPv6 (RFC4620). Les sauts intermédiaires peuvent ne pas être autorisés, car le routage source IPv6 a été déprécié (RFC5095).

OPTIONS

-3

Précision du RTT (n'arrondit pas le temps de résultat).

-4

Utiliser uniquement IPv4.

-6

Utiliser uniquement IPv6.

-a

Ping audible.

-A

Ping adaptatif. L'intervalle entre les paquets s'adapte au temps de réponse (RTT), de sorte qu'effectivement pas plus d'une sonde sans réponse (ou plus, si le préchargement est défini) n'est présente sur le réseau. L'intervalle par défaut est de 2 ms, pour plus d'informations, voir l'option -i. Sur les réseaux à faible RTT, ce mode est essentiellement équivalent au mode flood.

-b

Permettre de pinger une adresse de diffusion.

-B

Ne pas permettre à ping de changer l'adresse source des sondes. L'adresse est liée à celle sélectionnée au démarrage de ping.

-c nombre

Arrêter après l'envoi de nombre paquets ECHO_REQUEST. Avec l'option délai, ping attend nombre paquets ECHO_REPLY, jusqu'à l'expiration du délai.

-C

Appeler la fonction connect() lors de la création du socket.

-d

Définir l'option SO_DEBUG sur le socket utilisé. Essentiellement, cette option de socket n'est pas utilisée par le noyau Linux.

-D

Afficher un horodatage (heure Unix + microsecondes comme dans gettimeofday) avant chaque ligne.

-e identifiant

Définir le champ d'identification de ECHO_REQUEST. La valeur 0 implique l'utilisation d'un socket brut (non pris en charge sur un socket de datagramme ICMP). La valeur du champ peut être affichée avec l'option -v.

-f

Ping flood. Pour chaque ECHO_REQUEST envoyé, un point “.” est affiché, tandis que pour chaque ECHO_REPLY reçu, un retrait arrière est affiché. Cela permet un affichage rapide du nombre de paquets perdus. Si l'intervalle n'est pas donné, il est défini à zéro et les paquets sont envoyés aussi vite qu'ils reviennent ou cent fois par seconde, le plus rapide des deux. Seul le super-utilisateur peut utiliser cette option avec un intervalle de zéro.

-F label_flux

Uniquement IPv6. Alloue et définit une étiquette de flux de 20 bits (en hexadécimal) sur les paquets echo request. Si la valeur est zéro, le noyau alloue une étiquette de flux aléatoire.

-h

Afficher l'aide.

-H

Forcer la résolution de nom DNS pour la sortie. Utile pour une destination numérique, ou l'option -f, qui par défaut n'effectue pas de résolution. Cela peut également aider à contourner les problèmes de résolution DNS. Annule l'option -n précédemment définie. Voir également la variable d'environnement IPUTILS_PING_PTR_LOOKUP.

-i intervalle

Attendre intervalle secondes entre l'envoi de chaque paquet. Les nombres réels sont autorisés avec un point comme séparateur décimal (quel que soit le paramètre régional). L'attente par défaut est d'une seconde entre chaque paquet normalement, ou aucune attente en mode flood. Seul le super-utilisateur peut définir un intervalle inférieur à 2 ms. Le ping de diffusion et de multidiffusion a une limitation encore plus élevée pour les utilisateurs réguliers : le minimum est de 1 seconde.

-I interface

interface est une adresse, un nom d'interface ou un nom VRF. Si interface est une adresse, elle définit l'adresse source sur l'adresse de l'interface spécifiée. Si interface est un nom d'interface, elle définit l'interface source sur l'interface spécifiée. Si interface est un nom VRF, chaque paquet est routé en utilisant la table de routage correspondante ; dans ce cas, l'option -I peut être répétée pour spécifier une adresse source. NOTE : Pour IPv6, lors du ping d'une adresse de portée lien local, la spécification du lien (par la notation '%'-notation dans destination, ou par cette option) peut être utilisée mais n'est plus obligatoire.

-l prechargement

Si prechargement est spécifié, ping envoie ce nombre de paquets sans attendre de réponse. Seul le super-utilisateur peut sélectionner un préchargement supérieur à 3.

-L

Supprimer la boucle de retour des paquets de multidiffusion. Ce drapeau ne s'applique que si la destination du ping est une adresse de multidiffusion.

-m marqueur

Utiliser marqueur pour étiqueter les paquets sortants. Ceci est utile pour diverses raisons au sein du noyau, telles que l'utilisation du routage basé sur des politiques pour sélectionner un traitement sortant spécifique. La capacité CAP_NET_ADMIN ou CAP_NET_RAW (depuis Linux 5.17) est requise, voir socket(7).

-M option_pmtudisc

Sélectionne la stratégie de découverte de la MTU du chemin (Path MTU Discovery). option_pmtudisc peut être soit do (définit le drapeau DF mais soumis aux vérifications PMTU par le noyau, les paquets trop gros seront rejetés), want (effectue la découverte PMTU, fragmente localement lorsque la taille du paquet est grande), probe (définit le drapeau DF et contourne les vérifications PMTU, utile pour sonder), ou dont (ne définit pas le drapeau DF).

-N option_nodeinfo

Uniquement IPv6. Envoie des requêtes d'information de nœud IPv6 (RFC4620), au lieu de Echo Request. La capacité CAP_NET_RAW est requise.

help

Affiche l'aide pour la prise en charge NI.

name

Interroge les noms de nœuds.

ipv6

Interroge les adresses IPv6. Il existe plusieurs drapeaux spécifiques à IPv6.

ipv6-global

Demande les adresses IPv6 de portée globale.

ipv6-sitelocal

Demande les adresses IPv6 de portée site local.

ipv6-linklocal

Demande les adresses IPv6 de portée lien local.

ipv6-all

Demande les adresses IPv6 sur d'autres interfaces.

ipv4

Interroge les adresses IPv4. Il existe un drapeau spécifique à IPv4.

ipv4-all

Demande les adresses IPv4 sur d'autres interfaces.

subject-ipv6=ipv6addr

Adresse sujet IPv6.

subject-ipv4=ipv4addr

Adresse sujet IPv4.

subject-name=nom_noeud

Nom sujet. S'il contient plus d'un point, un nom de domaine entièrement qualifié est supposé.

subject-fqdn=nom_noeud

Nom sujet. Un nom de domaine entièrement qualifié est toujours supposé.

-n

Sortie numérique uniquement. Aucune tentative de résolution de nom DNS.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

t sera fait pour rechercher des noms symboliques pour les adresses d'hôtes (aucune résolution DNS inverse). C'est le comportement par défaut pour une destination numérique ou l'option -f. Annule l'option -H définie précédemment. Voir également la variable d'environnement IPUTILS_PING_PTR_LOOKUP.

-O

Signale les réponses ICMP ECHO en attente avant d'envoyer le paquet suivant. Ceci est utile en combinaison avec l'horodatage -D pour enregistrer la sortie dans un fichier de diagnostic et rechercher les réponses manquantes.

-p motif

Vous pouvez spécifier jusqu'à 16 octets de "remplissage" pour compléter le paquet que vous envoyez. Ceci est utile pour diagnostiquer des problèmes dépendants des données sur un réseau. Par exemple, -p ff provoquera le remplissage du paquet envoyé avec des uns partout.

-q

Sortie silencieuse. Rien n'est affiché à l'exception des lignes de résumé au démarrage et à la fin.

-Q tos

Définit les bits liés à la Qualité de Service dans les datagrammes ICMP. tos peut être un nombre décimal (uniquement ping) ou hexadécimal.

Dans la RFC2474, ces champs sont interprétés comme 8 bits de Services Différenciés (DS), composés de : bits 0-1 (2 bits les plus bas) de données séparées, et bits 2-7 (6 bits les plus hauts) de Codepoint de Services Différenciés (DSCP). Dans les RFC2481 et RFC3168, les bits 0-1 sont utilisés pour ECN.

Historiquement (RFC1349, obsolète par RFC2474), ils étaient interprétés comme : bit 0 (bit le plus bas) réservé (actuellement redéfini comme contrôle de congestion), 1-4 pour Type de Service et bits 5-7 (bits les plus hauts) pour la Précédence.

-r

Ignore les tables de routage normales et envoie directement à un hôte sur une interface connectée. Si l'hôte n'est pas sur un réseau directement connecté, une erreur est retournée. Cette option peut être utilisée pour pinguer un hôte local via une interface qui n'a pas de route via elle, à condition que l'option -I soit également utilisée.

-R

Uniquement ping. Enregistre la route. Inclut l'option RECORD_ROUTE dans le paquet ECHO_REQUEST et affiche le tampon de route sur les paquets renvoyés. Notez que l'en-tête IP n'est suffisant que pour neuf routes de ce type. De nombreux hôtes ignorent ou rejettent cette option.

-s taille_paquet

Spécifie le nombre d'octets de données à envoyer. La valeur par défaut est 56, ce qui se traduit par 64 octets de données ICMP lorsqu'elle est combinée avec les 8 octets de données d'en-tête ICMP. La valeur maximale autorisée est de 65507 pour IPv4 (65467 avec -R ou -T ou des sauts intermédiaires) ou 65527 pour IPv6, mais la plupart des systèmes la limitent à un nombre plus petit, dépendant du système.

-S taille_buffer_envoi

Définit la taille du buffer d'envoi du socket. Si non spécifié, il est sélectionné pour ne pas bufferiser plus d'un paquet.

-t ttl

Uniquement ping. Définit la durée de vie (Time to Live) de l'IP.

-T option_horodatage

Définit des options spéciales d'horodatage IP. option_horodatage peut être soit tsonly (seulement horodatages), tsandaddr (horodatages et adresses) ou tsprespec hôte1 [hôte2 [hôte3 [hôte4]]] (sauts présélectionnés pour l'horodatage).

-U

Affiche la latence utilisateur à utilisateur complète (l'ancien comportement). Normalement, ping affiche le temps aller-retour réseau, qui peut être différent, par exemple, en raison d'échecs DNS.

-v

Sortie détaillée. Ne supprime pas les réponses DUP lors du ping d'une adresse multicast.

-V

Affiche la version et quitte.

-w délai

Spécifie un délai d'attente, en secondes, avant que ping ne se termine, indépendamment du nombre de paquets envoyés ou reçus. Dans ce cas, ping ne s'arrête pas après l'envoi de count paquets, il attend soit que le délai expire, soit que count sondes soient répondues, soit une notification d'erreur du réseau.

-W délai_attente

Temps d'attente d'une réponse, en secondes. L'option affecte uniquement le délai en l'absence de toute réponse, sinon ping attend deux RTT. Un nombre réel est autorisé avec un point comme séparateur décimal (indépendamment de la configuration locale). 0 signifie un délai d'attente infini.

Lorsque vous utilisez ping pour l'isolation des pannes, il doit d'abord être exécuté sur l'hôte local, pour vérifier que l'interface réseau locale est active et opérationnelle. Ensuite, les hôtes et les passerelles de plus en plus éloignés doivent être "pingués". Les temps aller-retour et les statistiques de perte de paquets sont calculés. Si des paquets dupliqués sont reçus, ils ne sont pas inclus dans le calcul de la perte de paquets, bien que le temps aller-retour de ces paquets soit utilisé pour calculer les nombres de temps aller-retour minimum/moyen/maximum/mdev.

L'écart-type de la population (mdev), essentiellement une moyenne de la distance entre chaque RTT de ping et le RTT moyen. Plus le mdev est élevé, plus la variabilité du RTT est importante (au fil du temps). Avec une forte variabilité du RTT, vous aurez des problèmes de vitesse avec les transferts de gros volumes (ils prendront plus de temps que strictement nécessaire, car la variabilité finira par faire attendre l'expéditeur pour les accusés de réception) et vous aurez une qualité VoIP médiocre à moyenne.

Lorsque le nombre spécifié de paquets a été envoyé (et reçu) ou si le programme est terminé par un SIGINT, un bref résumé est affiché. Des statistiques courantes plus courtes peuvent être obtenues sans terminer le processus avec le signal SIGQUIT.

Ce programme est destiné à être utilisé dans les tests, la mesure et la gestion de réseau. En raison de la charge qu'il peut imposer au réseau, il est déconseillé d'utiliser ping pendant les opérations normales ou à partir de scripts automatisés.

ENVIRONNEMENT

La variable d'environnement IPUTILS_PING_PTR_LOOKUP définie sur 0 désactive la résolution DNS inverse (recherche PTR) par défaut. Elle sera annulée par les options -H ou -n.

STATUT DE SORTIE

Si ping ne reçoit aucune réponse, il se terminera avec le code 1. Si un nombre de paquets et un délai sont tous deux spécifiés, et que moins de count paquets sont reçus au moment où le délai est atteint, il se terminera également avec le code 1. En cas d'autre erreur, il se terminera avec le code 2. Sinon, il se terminera avec le code 0. Cela permet d'utiliser le code de sortie pour savoir si un hôte est actif ou non.

DESTINATIONS IPv6 LIEN LOCAL

Pour IPv6, lorsque l'adresse de destination a une portée de lien local et que ping utilise des sockets de datagrammes ICMP, l'interface de sortie doit être spécifiée. Lorsque ping utilise des sockets bruts, il n'est pas strictement nécessaire de spécifier l'interface de sortie, mais cela doit être fait pour éviter toute ambiguïté lorsqu'il existe plusieurs interfaces de sortie possibles.

Il existe deux façons de spécifier l'interface de sortie :

• en utilisant la notation %

L'adresse de destination est suffixée par % et le nom de l'interface de sortie ou son indice, par exemple :

ping fe80::5054:ff:fe70:67bc%eth0

ping fe80::5054:ff:fe70:67bc%2

• en utilisant l'option -I

Lors de l'utilisation de sockets de datagrammes ICMP, cette méthode est prise en charge depuis les versions de noyau suivantes : 5.17, 5.15.19, 5.10.96, 5.4.176, 4.19.228, 4.14.265. Elle n'est pas non plus prise en charge sur musl libc.

DÉTAILS PAQUET ICMP

Un en-tête IP sans options mesure 20 octets. Un paquet ICMP ECHO_REQUEST contient 8 octets supplémentaires d'en-tête ICMP suivis d'une quantité arbitraire de données. Lorsqu'une taille_paquet est donnée, cela indique la taille de ce morceau de données supplémentaire (la valeur par défaut est 56). Ainsi, la quantité de données reçues à l'intérieur d'un paquet IP de type ICMP ECHO_REPLY sera toujours de 8 octets de plus que l'espace de données demandé (l'en-tête ICMP).

Si l'espace de données est au moins de la taille de la structure timeval, ping utilise les premiers octets de cet espace pour inclure un horodatage qu'il utilise dans le calcul des temps aller-retour. Si l'espace de données est plus court, aucun temps aller-retour n'est fourni.

PAQUETS DUPLIQUÉS ET ENDOMMAGÉS

ping signalera les paquets dupliqués et endommagés. Les paquets dupliqués ne devraient jamais se produire et semblent être causés par des retransmissions inappropriées au niveau de la liaison. Les duplications peuvent survenir dans de nombreuses situations et ne sont rarement (voire jamais) un bon signe, bien que la présence de faibles niveaux de duplications ne soit pas toujours une source d'inquiétude.

Les paquets endommagés sont évidemment une cause sérieuse d'alarme et indiquent souvent un matériel défectueux quelque part sur le chemin du paquet ping (sur le réseau ou dans les hôtes).

COLLISIONS D'ID

Contrairement à TCP et UDP, qui utilisent des ports pour identifier de manière unique le destinataire pour délivrer les données, ICMP utilise un champ identificateur (ID) pour l'identification. Par conséquent, si sur la même machine, en même temps, deux processus ping utilisent le même ID, la réponse echo peut être délivrée à un mauvais destinataire. C'est un problème connu dû à la taille limitée du champ ID de 16 bits. C'est une limitation historique du protocole qui ne peut pas être corrigée pour le moment, à moins d'encoder un ID dans la charge utile du paquet ping. ping affiche une erreur ADRESSE DIFFÉRENTE et la perte de paquets est négative.

ping utilise PID pour obtenir un nombre unique. La valeur par défaut de /proc/sys/kernel/pid_max est 32768. Sur les systèmes qui utilisent intensivement ping et avec pid_max supérieur à 65535, des collisions sont susceptibles de se produire.

ESSAI DE MOTIFS DE DONNÉES DIFFÉRENTS

La couche (inter)réseau ne devrait jamais traiter les paquets différemment en fonction des données contenues dans la partie données. Malheureusement, des problèmes dépendants des données ont été connus pour s'introduire dans les réseaux et rester indétectés pendant de longues périodes. Dans de nombreux cas, le motif particulier qui pose problème est quelque chose qui ne contient pas suffisamment de "transitions", comme des uns partout ou des zéros partout, ou un motif juste à la limite, comme presque tous des zéros. Il n'est pas nécessairement suffisant de spécifier un motif de données de zéros partout (par exemple) sur la ligne de commande car le motif qui est intéressant se situe au niveau de la couche de données, et la relation entre ce que vous tapez et ce que les contrôleurs transmettent peut être compliquée.

Cela signifie que si vous avez un problème dépendant des données, vous devrez probablement faire beaucoup de tests pour le trouver. Si vous avez de la chance, vous pourrez peut-être trouver un fichier qui ne peut pas être envoyé sur votre réseau ou qui prend beaucoup plus de temps.

pour transférer que d'autres fichiers de longueur similaire. Vous pouvez ensuite examiner ce fichier pour les motifs répétés que vous pouvez tester à l'aide de l'option -p de ping.

DÉTAILS TTL

La valeur TTL d'un paquet IP représente le nombre maximum de routeurs IP que le paquet peut traverser avant d'être supprimé. Dans la pratique actuelle, vous pouvez vous attendre à ce que chaque routeur de l'Internet décrémente le champ TTL d'exactement un.

Le champ TTL pour les paquets TCP peut prendre différentes valeurs. La valeur maximale possible de ce champ est 255, une valeur initiale recommandée est 64. Pour plus d'informations, consultez la section TCP/Lower-Level Interface de la RFC9293.

En fonctionnement normal, ping affiche la valeur TTL du paquet qu'il reçoit. Lorsqu'un système distant reçoit un paquet ping, il peut faire l'une des trois choses suivantes avec le champ TTL dans sa réponse :

• Ne pas le modifier ; c'est ce que faisaient les systèmes Unix Berkeley avant la sortie de 4.3BSD Tahoe. Dans ce cas, la valeur TTL du paquet reçu sera de 255 moins le nombre de routeurs dans le chemin aller-retour.
• Le régler sur 255 ; c'est ce que font les systèmes Unix Berkeley actuels. Dans ce cas, la valeur TTL du paquet reçu sera de 255 moins le nombre de routeurs dans le chemin du système distant vers l'hôte pingant.
• Le régler sur une autre valeur. Certaines machines utilisent la même valeur pour les paquets ICMP que pour les paquets TCP, par exemple 30 ou 60. D'autres peuvent utiliser des valeurs complètement aléatoires.

BOGUES

• De nombreux hôtes et passerelles ignorent l'option RECORD_ROUTE.
• La longueur maximale de l'en-tête IP est trop faible pour que des options comme RECORD_ROUTE soient entièrement utiles. Il n'y a pas grand-chose à faire à ce sujet, cependant.
• Le ping en mode flood n'est pas recommandé en général, et le ping en mode flood sur l'adresse de diffusion ne devrait être effectué que dans des conditions très contrôlées.

HISTORIQUE

La commande ping est apparue dans 4.3BSD.

La version décrite ici est son descendant spécifique à Linux.

Depuis la version s20150815, le binaire ping6 n'existe plus. Il a été fusionné dans ping. La création d'un lien symbolique nommé ping6 pointant vers ping produira la même fonctionnalité qu'auparavant.

SÉCURITÉ

ping nécessite la capacité CAP_NET_RAW pour être exécuté 1) si le programme est utilisé pour des requêtes non-écho (voir l'option -N) ou lorsque le champ d'identification est réglé sur 0 pour ECHO_REQUEST (voir -e), ou 2) si le noyau ne prend pas en charge les sockets de datagrammes ICMP, ou 3) si l'utilisateur n'est pas autorisé à créer un socket d'écho ICMP. Le programme peut être utilisé comme root set-uid.
