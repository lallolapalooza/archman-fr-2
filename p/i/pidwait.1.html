pidwait(1)

Paquet: procps-ng

Licences: GPL, LGPL

PGREP(1) Manuel des commandes générales PGREP(1)

NOM

pgrep, pkill, pidwait — rechercher, signaler ou attendre des processus en fonction du nom et d'autres attributs

SYNTAXE

pgrep [option ...] motif

pkill [option ...] motif

pidwait [option ...] motif

DESCRIPTION

pgrep parcourt les processus en cours d'exécution et liste les identifiants de processus qui correspondent aux critères de sélection sur la sortie standard. Tous les critères doivent correspondre. Par exemple,

$ pgrep -u root sshd

ne listera que les processus dont le nom inclut sshd ET qui sont détenus par root. D'un autre côté,

$ pgrep -u root,daemon

listera les processus détenus par root OU daemon.

pkill enverra le signal spécifié (par défaut SIGTERM) à chaque processus au lieu de les lister sur la sortie standard.

pidwait attendra chaque processus au lieu de les lister sur la sortie standard.

OPTIONS

-signal
--signal signal
Définit le signal à envoyer à chaque processus correspondant. Le nom numérique ou symbolique du signal peut être utilisé. En mode pgrep ou pidwait, seule l'option longue peut être utilisée et n'a aucun effet sauf si elle est utilisée en conjonction avec --require-handler pour filtrer les processus ayant un gestionnaire de signal en espace utilisateur présent pour un signal particulier.
-c, --count
Supprime la sortie normale ; affiche à la place un décompte des processus correspondants. Lorsque le décompte ne correspond à rien, par exemple retourne zéro, la commande retournera une valeur non nulle. Notez que pour pkill et pidwait, le décompte est le nombre de processus correspondants, pas les processus qui ont été signalés ou attendus avec succès.
-d, --delimiter séparateur
Définit la chaîne utilisée pour séparer chaque identifiant de processus dans la sortie (par défaut, une nouvelle ligne). (pgrep seulement.)
-e, --echo
Affiche le nom et le PID du processus en cours de suppression. (pkill seulement.)
-f, --full
Le motif est normalement uniquement mis en correspondance avec le nom du processus. Lorsque -f est défini, la ligne de commande complète est utilisée.
-g, --pgroup pgid,...
Ne correspond qu'aux processus dans les identifiants de groupe de processus listés. Le groupe de processus 0 est traduit en son propre groupe de processus pour pgrep, pkill ou pidwait.
-G, --group gid,...
Ne correspond qu'aux processus dont l'identifiant de groupe réel est listé. La valeur numérique ou symbolique peut être utilisée.
-i, --ignore-case
Correspond aux processus sans tenir compte de la casse.
-l, --list-name
Liste le nom du processus ainsi que l'identifiant du processus. (pgrep seulement.)
-a, --list-full
Liste la ligne de commande complète ainsi que l'identifiant du processus. (pgrep seulement.)
-n, --newest
Sélectionne uniquement le plus récent (démarré le plus récemment) des processus correspondants.
-o, --oldest
Sélectionne uniquement le plus ancien (démarré le moins récemment) des processus correspondants.
-O, --older secs
Sélectionne les processus plus anciens que secs.
-P, --parent ppid,...
Ne correspond qu'aux processus dont l'identifiant de processus parent est listé.
-s, --session sid,...
Ne correspond qu'aux processus dont l'identifiant de session de processus est listé. L'identifiant de session 0 est traduit en son propre identifiant de session pour pgrep, pkill, ou pidwait.
-t, --terminal term,...
Ne correspond qu'aux processus dont le terminal de contrôle est listé. Le nom du terminal doit être spécifié sans le préfixe "/dev/".
-u, --euid euid,...
Ne correspond qu'aux processus dont l'identifiant d'utilisateur effectif est listé. La valeur numérique ou symbolique peut être utilisée.
-U, --uid uid,...
Ne correspond qu'aux processus dont l'identifiant d'utilisateur réel est listé. La valeur numérique ou symbolique peut être utilisée.
-v, --inverse
Inverse la correspondance. Cette option est généralement utilisée dans le contexte de pgrep ou pidwait. Dans le contexte de pkill, l'option courte est désactivée pour éviter une utilisation accidentelle de l'option.
-w, --lightweight
Affiche tous les identifiants de threads au lieu des PIDs dans le contexte de pgrep ou pidwait. Dans le contexte de pkill, cette option est désactivée.
-x, --exact
Ne correspond qu'aux processus dont les noms (ou les lignes de commande si -f est spécifié) correspondent exactement au motif.
-F, --pidfile fichier
Lit les PID à partir du fichier. Cette option est plus utile pour pkill ou pidwait que pour pgrep. Le nom de fichier "-" peut être utilisé pour lire depuis STDIN.
-L, --logpidfile
Échoue si le fichier PID (voir -F) n'est pas verrouillé.
-r, --runstates D,R,S,Z,...
Ne correspond qu'aux processus dont l'état correspond.
-A, --ignore-ancestors
Ignore tous les ancêtres de pgrep, pkill ou pidwait. Par exemple, cela peut être utile lors de l'élévation avec sudo ou des outils similaires.
-H, --require-handler
Ne correspond qu'aux processus ayant un gestionnaire de signal en espace utilisateur présent pour le signal à envoyer.
--cgroup nom,...
Correspond au groupe de contrôle (cgroup) v2 fourni. Voir cgroups(8)
--env nom[=valeur],...
Correspond aux processus qui ont ces variables d'environnement. Si le paramètre =valeur n'est pas défini, seul le nom de la variable est correspondant.
--ns pid
Correspond aux processus qui appartiennent aux mêmes espaces de noms. Nécessite d'être exécuté en tant que root pour correspondre aux processus d'autres utilisateurs. Voir --nslist pour savoir comment limiter les espaces de noms à correspondre.
--nslist nom,...
Ne correspond qu'aux espaces de noms fournis. Espaces de noms disponibles : ipc, mnt, net, pid, user, uts.
-q, --queue valeur
Utilise sigqueue(3) plutôt que kill(2) et l'argument valeur est utilisé pour spécifier un entier à envoyer avec le signal. Si le processus récepteur a installé un gestionnaire pour ce signal en utilisant le drapeau SA_SIGINFO avec sigaction(2), alors il peut obtenir ces données via le champ si_value de la structure siginfo_t.
-V, --version
Affiche les informations de version et quitte.
-h, --help
Affiche l'aide et quitte.

OPÉRANDES

motif
Spécifie une Expression Régulière Étendue pour correspondre aux noms de processus ou aux lignes de commande.

    EXAMPLES

    Example 1: Trouver l'ID du processus du démon named :

    $ pgrep -u root named

    Exemple 2 : Faire relire à syslog son fichier de configuration :

    $ pkill -HUP syslogd

    Exemple 3 : Donner des informations détaillées sur tous les processus xterm :

    $ ps -fp $(pgrep -d, -x xterm)

    Exemple 4 : Faire fonctionner tous les processus chrome plus gentiment :

    $ renice +4 $(pgrep chrome)

    Exemple 5 : Attendre qu'un processus avec un PID connu se termine :

    $ echo ${PID} | pidwait -F -

    ÉTAT DE SORTIE

    0
    Un ou plusieurs processus correspondent aux critères. Pour pkill et pidwait, un ou plusieurs processus doivent également avoir été signalés ou attendus avec succès.
    1
    Aucun processus ne correspond ou aucun d'entre eux n'a pu être signalé.
    2
    Erreur de syntaxe dans la ligne de commande.
    3
    Erreur fatale : manque de mémoire, etc.

    NOTES

    Le nom du processus utilisé pour la correspondance est limité aux 15 caractères présents dans la sortie de /proc/pid/stat. Utilisez l'option -f pour correspondre à la ligne de commande complète, /proc/pid/cmdline. Les threads peuvent ne pas avoir le même nom de processus que le processus parent, mais auront la même ligne de commande.

    Le processus pgrep, pkill ou pidwait en cours d'exécution ne se signalera jamais lui-même comme une correspondance.

    L'option -O --older échouera silencieusement si /proc est monté avec l'option subset=pid.

    BOGUES

    Les options -n, -o et -v ne peuvent pas être combinées. Faites-moi savoir si vous devez le faire.

    Les processus inactifs sont signalés.

    pidwait nécessite l'appel système pidfd_open(2) qui est apparu pour la première fois sous Linux 5.3.
