pipe(2) Manuel des appels système pipe(2)

NOM

pipe, pipe2 - créer un tube (pipe)

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int pipe(int pipefd[2]);
#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#include <fcntl.h>              /* Définition des constantes O_* */
#include <unistd.h>
int pipe2(int pipefd[2], int flags);
/* Sur Alpha, IA-64, MIPS, SuperH et SPARC/SPARC64, pipe() a le
   prototype suivant ; voir VERSIONS */
#include <unistd.h>
struct fd_pair {
    long fd[2];
};
struct fd_pair pipe(void);

DESCRIPTION

pipe() crée un tube (pipe), un canal de communication unidirectionnel qui peut être utilisé pour la communication inter-processus. Le tableau pipefd est utilisé pour retourner deux descripteurs de fichiers faisant référence aux extrémités du tube. pipefd[0] fait référence à l'extrémité de lecture du tube. pipefd[1] fait référence à l'extrémité d'écriture du tube. Les données écrites à l'extrémité d'écriture du tube sont mises en tampon par le noyau jusqu'à ce qu'elles soient lues à l'extrémité de lecture du tube. Pour plus de détails, voir pipe(7).

Si flags est 0, alors pipe2() est identique à pipe(). Les valeurs suivantes peuvent être combinées par un OU bit à bit dans flags pour obtenir un comportement différent :

O_CLOEXEC
Définit le drapeau close-on-exec (FD_CLOEXEC) sur les deux nouveaux descripteurs de fichiers. Voir la description du même drapeau dans open(2) pour les raisons pour lesquelles cela peut être utile.
O_DIRECT (depuis Linux 3.4)
Crée un tube qui effectue des E/S en mode "paquet". Chaque write(2) dans le tube est traité comme un paquet séparé, et les read(2) du tube liront un paquet à la fois. Notez les points suivants :
•
Les écritures de plus de PIPE_BUF octets (voir pipe(7)) seront divisées en plusieurs paquets. La constante PIPE_BUF est définie dans <limits.h>.
•
Si un read(2) spécifie une taille de tampon inférieure au paquet suivant, alors le nombre d'octets demandé est lu, et les octets excédentaires dans le paquet sont ignorés. Spécifier une taille de tampon de PIPE_BUF sera suffisant pour lire les paquets les plus volumineux (voir le point précédent).
•
Les paquets de longueur nulle ne sont pas pris en charge. (Un read(2) spécifiant une taille de tampon de zéro est une opération nulle et renvoie 0.)
Les anciens noyaux qui ne prennent pas en charge ce drapeau l'indiqueront par une erreur EINVAL.
Depuis Linux 4.5, il est possible de modifier le paramètre O_DIRECT d'un descripteur de tube en utilisant fcntl(2).
O_NONBLOCK
Définit le drapeau d'état de fichier O_NONBLOCK sur les descriptions de fichiers ouvertes référencées par les nouveaux descripteurs de fichiers. L'utilisation de ce drapeau permet d'éviter des appels supplémentaires à fcntl(2) pour obtenir le même résultat.
O_NOTIFICATION_PIPE
Depuis Linux 5.8, un mécanisme général de notification est construit au-dessus du tube où le noyau transfère les messages de notification dans les tubes ouverts par l'espace utilisateur. Le propriétaire du tube doit indiquer au noyau quelles sources d'événements surveiller et des filtres peuvent également être appliqués pour sélectionner quels sous-événements doivent être placés dans le tube.

VALEUR RENVOYÉE

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé, errno est défini pour indiquer l'erreur, et pipefd reste inchangé.

Sur Linux (et d'autres systèmes), pipe() ne modifie pas pipefd en cas d'échec. Une exigence normalisant ce comportement a été ajoutée dans POSIX.1-2008 TC2. L'appel système spécifique à Linux pipe2() ne modifie pas non plus pipefd en cas d'échec.

ERREURS

EFAULT
pipefd n'est pas valide.
EINVAL
(pipe2()) Valeur invalide dans flags.
EMFILE
La limite par processus du nombre de descripteurs de fichiers ouverts a été atteinte.
ENFILE
La limite système du nombre total de fichiers ouverts a été atteinte.
ENFILE
La limite dure de mémoire allouable pour les tubes a été atteinte et l'appelant n'est pas privilégié ; voir pipe(7).
ENOPKG
(pipe2()) O_NOTIFICATION_PIPE a été passé dans flags et le support des notifications (CONFIG_WATCH_QUEUE) n'est pas compilé dans le noyau.

VERSIONS

L'ABI System V sur certaines architectures permet l'utilisation de plusieurs registres pour renvoyer plusieurs valeurs ; plusieurs architectures (notamment Alpha, IA-64, MIPS, SuperH et SPARC/SPARC64) abusent de cette fonctionnalité pour implémenter l'appel système pipe() de manière fonctionnelle : l'appel ne prend aucun argument et renvoie une paire de descripteurs de fichiers comme valeur de retour en cas de succès. La fonction enveloppe glibc pipe() gère cela de manière transparente. Voir syscall(2) pour des informations concernant les registres utilisés pour stocker le second descripteur de fichier.

EXEMPLES

Le programme suivant crée un tube, puis utilise fork(2) pour créer un processus enfant ; l'enfant hérite d'un ensemble dupliqué de descripteurs de fichiers qui font référence au même tube. Après le fork(2), chaque processus ferme les descripteurs de fichiers dont il n'a pas besoin pour le tube (voir pipe(7)). Le parent écrit ensuite la chaîne contenue dans l'argument de la ligne de commande du programme dans le tube, et l'enfant lit cette chaîne octet par octet depuis le tube et l'affiche sur la sortie standard.

Source du programme

#include <err.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int    pipefd[2];
    char   buf;
    pid_t  cpid;
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <string>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    if (pipe(pipefd) == -1)
        err(EXIT_FAILURE, "pipe");
    cpid = fork();
    if (cpid == -1)
        err(EXIT_FAILURE, "fork");
    if (cpid == 0) {    /* L'enfant lit depuis le tube */
        if (close(pipefd[1]) == -1)  /* Fermer l'extrémité d'écriture inutilisée */
            err(EXIT_FAILURE, "close");
        while (read(pipefd[0], &buf, 1) > 0) {
            if (write(STDOUT_FILENO, &buf, 1) != 1)
                err(EXIT_FAILURE, "write");
        }
        if (write(STDOUT_FILENO, "\n", 1) != 1)
            err(EXIT_FAILURE, "write");
        if (close(pipefd[0]) == -1)
            err(EXIT_FAILURE, "close");
        _exit(EXIT_SUCCESS);
    } else {            /* Le parent écrit argv[1] dans le tube */
        if (close(pipefd[0]) == -1)  /* Fermer l'extrémité de lecture inutilisée */
            err(EXIT_FAILURE, "close");
        if (write(pipefd[1], argv[1], strlen(argv[1])) != strlen(argv[1]))
            err(EXIT_FAILURE, "write");
        if (close(pipefd[1]) == -1)
            err(EXIT_FAILURE, "close");
        wait(NULL);
        exit(EXIT_SUCCESS);
    }
}
