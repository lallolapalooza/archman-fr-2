NOM

pipewire-props - Référence des propriétés des objets PipeWire.

DESCRIPTION

PipeWire décrit et configure les éléments audio et vidéo avec des objets des types principaux suivants :

Noeud

Point de terminaison de sortie/entrée audio ou vidéo

Périphérique

Cartes son, périphériques Bluetooth, caméras, etc. Peuvent avoir plusieurs nœuds.

Moniteur

Détection des périphériques et gestion de la connexion à chaud

Port

Point de terminaison audio/vidéo dans un nœud

Lien

Connexion entre les ports, qui transporte l'audio/vidéo entre eux.

Client

Application connectée à PipeWire.

Tous les objets ont des propriétés (« props »), dont la plupart peuvent être définies dans des fichiers de configuration ou à l'exécution lors de la création de l'objet.

Certaines propriétés sont des « propriétés communes » (par exemple node.description) et peuvent être définies sur tous les objets du type donné. D'autres propriétés contrôlent les paramètres d'un type spécifique de périphérique ou de nœud (ALSA, Bluetooth, ...), et n'ont de sens que pour ces objets.

Généralement, toutes les propriétés sont configurées dans la configuration du gestionnaire de session. Pour savoir comment les configurer, consultez la documentation du gestionnaire de session. Dans les configurations minimales de PipeWire sans gestionnaire de session, elles peuvent être configurées via context.objects dans pipewire.conf(5).

PROPRIÉTÉS COMMUNES DES PÉRIPHÉRIQUES

Ce sont les propriétés communes pour les périphériques.

device.name # chaîne

Un nom (unique) pour le périphérique. Il peut être utilisé par la ligne de commande et d'autres outils pour identifier le périphérique.

device.param.PARAM = { ... } # JSON

Définit la valeur d'un Param de périphérique à une valeur JSON lors du chargement du périphérique. Cela fonctionne de manière similaire à la commande set-param de pw-cli(1). Le PARAM doit être remplacé par le nom du Param à définir, par exemple, device.Param.Props = { ... } pour définir les Props.

device.plugged # entier

lorsque le périphérique a été créé.

Sous forme d'un uint64 en nanosecondes.

device.nick # chaîne

un surnom court pour le périphérique

device.description # chaîne

description lisible par l'homme et localisée du périphérique en une ligne.

Ex. « Casque USB Foobar »

device.serial # chaîne

Numéro de série le cas échéant.

device.vendor.id # entier

ID du vendeur le cas échéant

device.vendor.name # chaîne

Nom du vendeur le cas échéant

device.product.id # entier

Nom du produit le cas échéant

device.product.name # chaîne

ID du produit le cas échéant

device.class # chaîne

Classe du périphérique

device.form-factor # chaîne

Facteur de forme le cas échéant.

L'un des suivants : « internal », « speaker », « handset », « tv », « webcam », « microphone », « headset », « headphone », « hands-free », « car », « hifi », « computer », « portable »

device.icon # chaîne

Icône pour le périphérique.

Un blob base64 contenant des données d'image PNG

device.icon-name # chaîne

Un nom d'icône XDG pour le périphérique.

Ex. « sound-card-speakers-usb »

device.intended-roles # chaîne

Utilisation prévue.

Une liste d'utilisations (voir media.role) séparée par des espaces pour lesquelles ce périphérique est particulièrement bien adapté, en raison de sa latence, de sa qualité ou de son facteur de forme.

device.disabled = false # booléen

Désactive la création de ce périphérique dans le gestionnaire de session.

Il existe d'autres propriétés communes de type device.* à des fins techniques et généralement non configurables par l'utilisateur.

PROPRIÉTÉS COMMUNES DES NŒUDS

Les propriétés ici s'appliquent aux flux audio ou vidéo généraux, et à d'autres nœuds tels que les sorties ou les entrées correspondant à des périphériques réels ou virtuels.

Propriétés d'Identification

Ces propriétés servent à identifier le nœud ou à l'afficher dans une application graphique.

node.name

Un nom (unique) pour le nœud. Il est généralement défini sur les sorties et les entrées pour les identifier comme cibles de liaison par le gestionnaire de session.

node.description

Une description lisible par l'homme du nœud ou du flux.

media.name

Un nom de média lisible par l'utilisateur, généralement l'artiste et le titre. Ceux-ci sont généralement affichés dans les applications destinées aux utilisateurs pour les informer des médias actuellement lus.

media.title

Un titre de flux lisible par l'utilisateur.

media.artist

Un artiste de flux lisible par l'utilisateur

media.copyright

Informations sur les droits d'auteur du flux lisibles par l'utilisateur

media.software

Informations sur le logiciel générateur du flux lisibles par l'utilisateur

media.language

Langue du flux au format POSIX. Ex : fr_FR

media.filename

Nom du fichier pour le flux

media.icon

Icône pour le média, un blob base64 avec des données d'image PNG

media.icon-name

Un nom d'icône XDG pour le média. Ex : audio-x-mp3

media.comment

Commentaire supplémentaire sur le flux

media.date

Date du média

media.format

Informations sur le format du flux lisibles par l'utilisateur

object.linger = false

Si l'objet doit survivre à son créateur.

device.id

ID du périphérique auquel le nœud appartient.

Propriétés de Classification

Les propriétés de classification d'un nœud sont utilisées pour acheminer le signal vers sa destination et pour configurer les paramètres.

media.type

Le type de média contient une catégorie générale du média traité par le nœud. Les valeurs possibles incluent « Audio », « Vidéo », « Midi »

media.category

Quel type de traitement est effectué avec le média. Les valeurs possibles incluent :
  • Lecture : lecture de médias.
  • Capture : capture de médias.
  • Duplex : capture et lecture de médias ou traitement de médias en général.
  • Moniteur : une application de surveillance de médias. Ne modifie pas activement les données multimédias mais surveille l'activité.
  • Gestionnaire : Gérera le graphe des médias.

media.role

Le cas d'utilisation du média. Les valeurs possibles incluent :
  • Film : Lecture de films avec audio et vidéo.
  • Musique : Écoute de musique.
  • Caméra : Enregistrement vidéo à partir d'une caméra.
  • Écran : Enregistrement ou partage de l'écran du bureau.
  • Communication : VOIP ou autre application de chat vidéo.
  • Jeu : Jeu.
  • Notification : Sons de notification système.
  • DSP : Traitement audio ou vidéo et effets.
  • Production : Traitement et production audio professionnelle.
  • Accessibilité : Aide audio et visuelle pour l'accessibilité.
  • Test : Programme de test.

media.class

La classe média sert à classifier la fonction du flux. Les valeurs possibles incluent :
  • Vidéo/Source : un producteur de vidéo, comme une webcam.
  • Vidéo/Sortie : un consommateur de vidéo, comme une fenêtre d'affichage.
  • Audio/Source : une source d'échantillons audio comme un microphone. pipewire-props(7) — Pages de manuel Arch

Propriétés de planification

node.latency = 1024/48000

Définit une latence suggérée sur le nœud sous forme de fraction. Il ne s'agit que d'une suggestion, le graphique essaiera de configurer cette latence ou moins pour le graphique. Il est cependant possible que le graphique soit forcé à une latence plus élevée.

node.lock-quantum = false

Lorsque ce nœud est actif, le quantum du graphique est verrouillé et ne peut pas changer automatiquement. Il peut toujours être modifié de force avec des métadonnées ou lorsqu'un nœud force un quantum.

Les clients JACK utilisent cette propriété pour éviter les changements de quantum inattendus.

node.force-quantum = INTEGER

Pendant que le nœud est actif, force un quantum dans le graphique. Le dernier nœud activé avec cette propriété l'emporte.

Une valeur de 0 déverrouille le quantum.

node.rate = RATE

Suggère un débit (taux d'échantillonnage) pour le graphique. Le débit suggéré ne sera appliqué que lorsque cela ne provoquera pas d'interruptions (les périphériques sont inactifs) et lorsque le débit fait partie de la liste des débits autorisés dans le serveur.

node.lock-rate = false

Lorsque le nœud est actif, le débit du graphique ne changera pas automatiquement. Il est toujours possible de forcer un changement de débit avec des métadonnées ou avec une propriété de nœud.

node.force-rate = RATE

Lorsque le nœud est actif, force un taux d'échantillonnage spécifique sur le graphique. Le dernier nœud activé avec cette propriété l'emporte.

Une valeur RATE de 0 signifie forcer le débit dans le dénominateur de node.rate.

node.always-process = false

Lorsque le nœud est actif, il sera toujours joint à un nœud pilote, même lorsque rien n'est connecté au nœud. Définir cette propriété sur vrai implique également node.want-driver = true.

C'est le comportement par défaut pour les nœuds JACK, qui ont toujours besoin que leur callback de traitement soit appelé.

node.want-driver = true

Le nœud souhaite être connecté à un pilote afin de pouvoir commencer le traitement. C'est le comportement par défaut pour les flux et les filtres depuis la version 0.3.51. Les nœuds qui ne sont connectés à rien seront toujours mis en état inactif, sauf si node.always-process est défini sur vrai.

node.pause-on-idle = false

node.suspend-on-idle = false

Lorsque le nœud n'est plus connecté, il devient inactif. Normalement, les nœuds inactifs continuent de traiter et sont suspendus par le gestionnaire de session après un certain délai. Il est possible de mettre immédiatement en pause un nœud lorsqu'il est inactif avec cette propriété.

Lorsque le gestionnaire de session ne suspend pas les nœuds (ou lorsqu'il n'y a pas de gestionnaire de session), la propriété node.suspend-on-idle peut être utilisée à la place.

node.loop.name = null

node.loop.class = data.rt

Ajoute le nœud à un nom de boucle ou à une classe de boucle spécifique. Par défaut, le nœud est ajouté à la classe de boucle data.rt. Vous pouvez créer des boucles de données plus spécifiques, puis y assigner les nœuds.

D'autres noms bien connus sont main-loop.0 et la classe principale node.loop.class qui exécute le traitement des données du nœud dans la boucle principale.

priority.driver # integer

La priorité pour choisir ce périphérique comme pilote dans le graphique. Le pilote est sélectionné parmi tous les périphériques connectés en sélectionnant le périphérique avec la priorité la plus élevée.

Normalement, le gestionnaire de session attribue une priorité plus élevée aux sources afin qu'elles deviennent le pilote dans le graphique. La raison en est que le rééchantillonnage adaptatif doit être effectué sur les collecteurs plutôt que sur la source pour éviter la distorsion du signal lors de la capture audio.

clock.name # string

Le nom de l'horloge. Ce nom est généré automatiquement à partir de l'index de la carte et de la direction du flux. Les périphériques portant le même nom d'horloge n'utiliseront pas de rééchantillonneur pour synchroniser les horloges. Cela peut être utilisé pour lier des périphériques ensemble avec une horloge commune.

En mode Pro Audio, les nœuds du même périphérique sont supposés avoir la même horloge et aucun rééchantillonnage ne se produira lors de leur connexion. Ainsi, la connexion d'un port de capture à un port de lecture n'utilisera aucun rééchantillonnage adaptatif en mode Pro Audio.

Dans le profil Non Pro Audio, aucune hypothèse n'est faite et le rééchantillonnage adaptatif est effectué dans tous les cas par défaut. Cela peut également être désactivé en définissant le même nom clock.name sur les nœuds.

Propriétés du gestionnaire de session

node.autoconnect = true

Indique au gestionnaire de session de connecter automatiquement ce nœud à un autre nœud, généralement un collecteur ou une source.

node.exclusive = false

Si ce nœud souhaite être lié exclusivement au collecteur/à la source.

Où ce nœud doit être connecté. Il peut s'agir d'un node.name ou d'un object.id d'un nœud. Cette propriété est obsolète, la propriété target.object doit être utilisée à la place, qui utilise l'object.serial plus unique comme cible possible.

Où le nœud doit se connecter, cela peut être un node.name ou un object.serial.

Lorsque le nœud a une cible configurée et que la cible est détruite, détruisez également le nœud. Cette propriété empêche également que le nœud ne soit déplacé vers un autre collecteur/source.

Notez que si un flux doit apparaître/disparaître en synchronisation avec la cible, un script de gestionnaire de session (WirePlumber) doit être écrit à la place.

node.passive = false

Ceci est un nœud passif et ne doit donc pas maintenir les collecteurs/sources occupés. Cette propriété permet au gestionnaire de session de créer des liaisons passives vers les collecteurs/sources. Si le nœud n'est pas autrement connecté (via une liaison non passive), le nœud et le collecteur auquel il est connecté sont inactifs (et éventuellement suspendus).

Ceci est utilisé pour les nœuds de filtrage qui se trouvent devant les collecteurs/sources et qui doivent être suspendus en même temps que le collecteur/la source.

node.link-group = ID

Ajoute le nœud à un groupe de liaisons spécifique. Les nœuds du même groupe de liaisons ne sont pas automatiquement liés entre eux par le gestionnaire de session. Par exemple, un flux couplé où vous ne voulez pas que la sortie se connecte aux flux d'entrée, créant ainsi une boucle inutile.

stream.dont-remix = false

Indique au gestionnaire de session de ne pas remixer les canaux d'un flux. Normalement, la configuration des canaux du flux est modifiée pour correspondre au collecteur/à la source auquel il est connecté. Avec cette propriété définie sur vrai, le flux conservera sa disposition de canaux d'origine et le gestionnaire de session liera les canaux correspondants au collecteur.

priority.session # integer

La priorité pour sélectionner ce nœud comme source ou collecteur par défaut.

PROPRIÉTÉS DE L'ADAPTATEUR AUDIO

La plupart des nœuds audio (ALSA, Bluetooth, flux audio d'applications, ...) ont des propriétés communes pour l'adaptateur audio. L'adaptateur effectue des opérations de format d'échantillon, de taux d'échantillonnage et de mixage de canaux.

Toutes les propriétés listées ci-dessous sont des propriétés de nœud.

Paramètres du fusionneur

Le fusionneur est utilisé comme entrée pour un nœud de périphérique de destination (sink) ou un flux de capture. Il prend les différents canaux et les fusionne en un seul flux pour un traitement ultérieur.

Le fusionneur fournira également les ports de surveillance des canaux d'entrée et peut appliquer un volume logiciel sur le signal de surveillance.

monitor.channel-volumes = false

Le volume des canaux d'entrée est appliqué au volume des ports de surveillance. Normalement, les ports de surveillance exposent le signal brut non modifié sur les ports d'entrée.

Paramètres du rééchantillonneur

Les sources, les destinations, les flux de capture et de lecture contiennent un rééchantillonneur adaptatif de haute qualité. Il utilise un rééchantillonnage basé sur sinc avec interpolation linéaire des bancs de filtres pour effectuer des facteurs de rééchantillonnage arbitraires. Le rééchantillonneur est activé dans les cas suivants :

  • Le matériel d'un nœud de périphérique ne prend pas en charge le taux d'échantillonnage du graphique. Le rééchantillonnage se produira du taux d'échantillonnage du graphique au taux d'échantillonnage matériel.
  • L'horloge matérielle d'un périphérique ne fonctionne pas à la même vitesse que l'horloge du graphique et un rééchantillonnage adaptatif est requis pour synchroniser les horloges.
  • Un flux n'a pas le même taux d'échantillonnage que le graphique et doit être rééchantillonné.
  • Une application souhaite activer le rééchantillonnage adaptatif dans un flux pour le faire correspondre à une autre horloge.

PipeWire

effectue la plupart des conversions et des rééchantillonnages dans le client (ou dans le cas du serveur PulseAudio, dans le serveur pipewire-pulse qui crée les flux). Cela garantit que toutes les conversions sont déchargées vers les clients et que le serveur peut gérer un seul format pour des raisons de performance.

Ci-dessous se trouve une explication des options qui peuvent être ajustées dans le convertisseur d'échantillons.

resample.quality = 4

La qualité du rééchantillonneur. De 0 à 14, la valeur par défaut est 4.

Augmenter la qualité entraînera une meilleure coupure et moins de repliement spectral au détriment d'une consommation CPU (beaucoup) plus élevée. La qualité par défaut de 4 a été sélectionnée comme un bon compromis entre qualité et performance sans artefacts qui se situent bien en dessous de la plage audible.

Voir Infinite Wave pour une comparaison des performances.

resample.disable = false

Désactive complètement le rééchantillonneur. Le nœud ne pourra négocier avec le graphe que lorsque les fréquences d'échantillonnage seront compatibles.

Paramètres du mixeur de canaux

Les flux de sortie, d'entrée, de capture et de lecture peuvent appliquer un mixage de canaux sur le signal entrant.

Normalement, le mixeur de canaux n'est pas utilisé pour les appareils, les canaux de l'appareil sont généralement exposés tels quels. Cette politique est généralement appliquée par le gestionnaire de session, nous renvoyons donc à sa documentation.

Les flux de lecture et de capture sont généralement configurés pour la disposition des canaux de la sortie/entrée à laquelle ils se connectent et effectuent donc un mixage de canaux.

Le mixeur de canaux implémente également un volume logiciel. Ce réglage de volume est effectué sur la disposition des canaux d'origine. ex : Un flux de lecture stéréo qui est amplifié en 5.1 a un contrôle de volume gauche et droit.

channelmix.disable = false

Désactive complètement le mixeur de canaux. Le flux ne pourra se connecter qu'à des entrées/sorties compatibles avec la même disposition de canaux exacte.

channelmix.min-volume = 0.0

channelmix.max-volume = 10.0

Donne les valeurs de volume minimum et maximum autorisées. Tout volume défini sera limité à ces valeurs.

channelmix.normalize = false

Assure que lors de ce mixage et rééchantillonnage, le niveau original de 0 dB est préservé, donc rien ne sonne de manière excessivement faible/fort.

Bien que cette option empêche le clipping, elle peut dans certains cas produire un volume trop faible. Augmentez le volume dans ce cas ou désactivez la normalisation.

channelmix.lock-volumes = false

Désactive complètement les changements de volume ou de mute. Par défaut : false.

channelmix.mix-lfe = true

Mixe le canal d'effets basse fréquence dans le canal central avant ou la paire stéréo. Cela pourrait améliorer la plage dynamique du signal s'il n'y a pas de subwoofer et que les haut-parleurs peuvent reproduire le signal basse fréquence.

channelmix.upmix = true

Active l'amplification du canal central avant (FC) lorsque la cible possède un canal FC. La somme des canaux stéréo est utilisée et un filtre passe-bas optionnel peut être utilisé (voir channelmix.fc-cutoff).

Active également l'amplification du LFE lorsque channelmix.lfe-cutoff est défini sur autre chose que 0 et que la cible possède un canal LFE. Le canal LFE est produit en ajoutant les canaux stéréo.

Si channelmix.upmix est vrai, l'amplification des canaux arrière est également activée et contrôlée par la propriété channelmix-upmix-method.

channelmix.upmix-method = psd

3 méthodes sont fournies pour produire les canaux arrière dans un son surround :
1.
none. Aucun canal arrière n'est produit.
2.
simple. Les canaux avant sont copiés vers l'arrière. C'est rapide mais peut produire des effets de phase.
3.
psd. Les canaux arrière sont produits à partir du son ambiant gauche et droit avant (la différence entre les canaux). Un délai et un déphasage optionnel sont ajoutés au signal arrière pour rendre le son plus ample.

channelmix.lfe-cutoff = 150

Applique un filtre passe-bas aux basses fréquences. La valeur est exprimée en Hz. Les subwoofers typiques ont une coupure autour de 150 et 200. La valeur par défaut de 0 désactive la fonctionnalité.

channelmix.fc-cutoff = 12000

Applique un filtre passe-bas à la fréquence centrale avant. La valeur est exprimée en Hz.

Étant donné que le canal central avant contient les dialogues, une fréquence de coupure typique est de 12000 Hz.

Cette option n'est active que lorsque l'amplification est activée.

channelmix.rear-delay = 12.0

Applique un délai en millisecondes lors de l'amplification des canaux arrière. Cela améliore la spécialisation du son. Un délai typique de 12 millisecondes est la valeur par défaut.

Ceci n'est actif que lorsque la méthode d'amplification psd est utilisée.

channelmix.stereo-widen = 0.0

Soustraie une partie du signal du canal central avant des canaux stéréo. Cela déplace les dialogues vers le haut-parleur central et laisse le son ambiant dans les canaux stéréo.

Ceci n'est actif que lorsque l'amplification est activée et qu'un canal central avant est mixé.

channelmix.hilbert-taps = 0

Cette option appliquera un déphasage de 90 degrés aux canaux arrière pour améliorer la spécialisation. Les taps doivent être compris entre 15 et 255 pour des résultats plus précis (et une consommation CPU plus élevée) pour des valeurs plus élevées.

Ceci n'est actif que lorsque la méthode d'amplification psd est utilisée.

dither.noise = 0

Cette option ajoutera N bits de données aléatoires au signal. Lorsque aucune méthode dither.method n'est spécifiée, les données aléatoires basculeront entre [-(1<<(N-1)), 0] toutes les 1024 échantillons. Avec une dither.method, le bruit de dither est amplifié avec 1<<(N-1) bits.

Cela peut être utilisé pour maintenir certains amplificateurs actifs pendant les périodes de silence. Un ou deux bits de bruit suffisent généralement, sinon le bruit deviendra audible. Ceci est généralement utilisé conjointement avec session.suspend-timeout-seconds pour désactiver la mise en veille dans le gestionnaire de session.

Notez que PipeWire utilise des opérations en virgule flottante avec une précision de 24 bits pour tout le traitement audio. La conversion vers des formats d'échantillons entiers de 24 bits est sans perte et la conversion vers des formats d'échantillons entiers de 32 bits est simplement complétée avec des 0 bits à la fin. Cela signifie que le bruit de dither ne se trouve toujours que dans les 24 bits les plus significatifs.

dither.method = none

Un dither optionnel peut être effectué sur le signal de sortie quantifié.

Il y a 6 modes disponibles :

1.
none. Aucun dither n'est effectué.
2.
rectangular Dithering avec une distribution de bruit rectangulaire. Ajoute des bits aléatoires dans la plage [-0.5, 0.5] au signal avec une distribution uniforme.
3.
triangular Dithering avec une distribution de bruit triangulaire. Ajoute des bits aléatoires dans la plage [-1.0, 1.0] au signal avec une distribution triangulaire autour de 0.0.
4.
triangular-hf Dithering avec une distribution de bruit triangulaire inclinée.
5.
wannamaker3 Un bruit supplémentaire est mis en forme sur le dither triangulaire incliné pour déplacer le bruit vers la plage plus inaudible. Utilise le filtre de bruit "F-Weighted" décrit par Wannamaker.
6.
shaped5 Un bruit supplémentaire est mis en forme sur le dither triangulaire pour déplacer le bruit vers la plage plus inaudible. Utilise le filtre de Lipshitz.

Le dither n'est utile que pour la conversion vers un format de moins de 24 bits et sera désactivé sinon.

Paramètres de débogage

debug.wav-path = ""

Fait en sorte que le flux écrive également les échantillons bruts dans un fichier WAV à des fins de débogage.

api.acp.auto-port = true # boolean

Sélectionne automatiquement le port de priorité la plus élevée disponible ("port" est un terme PulseAudio/ACP, équivalent à une "Route" dans PipeWire). Le gestionnaire de session désactive généralement cette option, car il s'en charge. Elle peut être activée dans des configurations personnalisées sans que le gestionnaire de session ne gère cette tâche.

Définit la fréquence d'échantillonnage utilisée pour sonder les périphériques ALSA et collecter les profils et les ports.

audio.channels # integer

Le nombre de canaux audio avec lesquels ouvrir le périphérique. Les valeurs par défaut dépendent du profil du périphérique.

La fréquence audio avec laquelle ouvrir le périphérique. La valeur par défaut est 0, ce qui signifie ouvrir le périphérique avec une fréquence aussi proche que possible de la fréquence du graphe.

api.alsa.headroom # integer

api.alsa.start-delay = 0 # integer

Certains périphériques ont besoin d'un certain temps avant de pouvoir signaler des positions de pointeurs matériels précises. Dans ces cas, un délai de démarrage supplémentaire peut être ajouté pour compenser ce délai de démarrage. Ceci définit le délai de démarrage en échantillons.

api.alsa.disable-mmap = false # boolean

Désactive l'opération mmap du périphérique et utilise à la place l'API de lecture/écriture ALSA. La valeur par défaut est false, mmap est préférée.

api.alsa.disable-batch # boolean

Ignore le drapeau de lot ALSA. Si le drapeau de lot est défini, ALSA aura besoin d'une période supplémentaire pour mettre à jour les pointeurs de lecture/écriture. Ignorer ce drapeau d'ALSA peut réduire la latence. La valeur par défaut est false.

api.alsa.use-chmap # boolean

Utilise la carte de canaux fournie par le pilote. La valeur par défaut est true lors de l'utilisation de UCM, false sinon car de nombreux pilotes ne signalent pas cela correctement.

api.alsa.multi-rate # boolean

Permet aux périphériques de la même carte d'être ouverts à plusieurs fréquences d'échantillonnage. La valeur par défaut est true. api.alsa.htimestamp = false # boolean

api.alsa.htimestamp.max-errors # integer

Spécifie le nombre d'erreurs consécutives avant que le htimestamp ne soit désactivé. Le réglage de cette valeur sur 0 fait en sorte que le htimestamp ne soit jamais désactivé.

api.alsa.disable-tsched = false # boolean

api.alsa.auto-link = false # boolean

Lien des périphériques PCM suiveurs au périphérique PCM du pilote lors de l'utilisation de la planification basée sur IRQ. Le profil "Pro Audio" activera généralement ce paramètre, s'il est censé fonctionner sur le matériel.

Définit statiquement la latence systémique du périphérique, en échantillons à la fréquence de lecture.

latency.internal.ns # integer

Définit statiquement la latence systémique du périphérique, en nanosecondes.

PARAMÈTRES D'EXÉCUTION

Les objets tels que les périphériques et les nœuds ont également des paramètres qui peuvent être modifiés après la création de l'objet. Par exemple, le profil de périphérique actif, les volumes des canaux, etc.

Pour certains objets, les paramètres permettent également de modifier certaines propriétés. Les paramètres de la plupart des périphériques ALSA et virtuels peuvent également être configurés à l'exécution.

Ces paramètres sont disponibles dans le paramètre du périphérique appelé Props dans son champ params. Ils peuvent être consultés, par exemple, en utilisant pw-dump <id> pour un périphérique ALSA :

NOM

pipewire-props - propriétés des objets PipeWire

DESCRIPTION

Ce document décrit les propriétés communes que vous pouvez définir sur les objets PipeWire. Ces propriétés sont utilisées pour configurer le comportement de PipeWire et de ses divers composants.

Les propriétés peuvent être définies dans des fichiers de configuration, via des variables d'environnement ou par des applications utilisant l'API PipeWire.

Les propriétés sont généralement des paires clé-valeur. Les clés sont des chaînes de caractères, et les valeurs peuvent être des chaînes de caractères, des entiers, des booléens ou d'autres types de données, selon le contexte de la propriété.

PROPRIÉTÉS COMMUNES DES PÉRIPHÉRIQUES

  • device.class: La classe du périphérique (par exemple, audio, vidéo).
  • device.description: Une description lisible par l'homme du périphérique.
  • device.name: Le nom interne du périphérique.
  • device.icon: Une icône pour représenter le périphérique.
  • device.vendor.id: L'ID du vendeur du périphérique.
  • device.product.id: L'ID du produit du périphérique.
  • device.plugged: Indique si le périphérique est branché.
  • device.profile: Le profil du périphérique à utiliser.

PROPRIÉTÉS COMMUNES DES NOEUDS

  • node.name: Le nom interne du nœud.
  • node.description: Une description lisible par l'homme du nœud.
  • node.rate: Le taux d'échantillonnage du nœud.
  • node.latency: La latence du nœud.
  • node.pause-on-idle: Mettre en pause le nœud lorsqu'il est inactif.
  • node.suspend-on-idle: Suspendre le nœud lorsqu'il est inactif.
  • media.class: La classe du média traité par le nœud.
  • media.role: Le rôle du média traité par le nœud.

PROPRIÉTÉS DE L'ADAPTATEUR AUDIO

  • adapter.auto-port-config: Configurer automatiquement les ports de l'adaptateur.

PROPRIÉTÉS ALSA

  • api.alsa.path: Le chemin du périphérique ALSA.
  • api.alsa.use-ucm: Utiliser les définitions UCM (Use Case Manager) pour ALSA.
  • api.alsa.disable-mixer-path: Désactiver la gestion des chemins du mixeur ALSA.

PROPRIÉTÉS BLUETOOTH

  • bluez5.hw-volume: Activer le contrôle du volume matériel Bluetooth.
  • bluez5.profile: Le profil Bluetooth à utiliser.
  • bluez5.a2dp.opus.pro.application: Utiliser le codec Opus pour A2DP pro.

PROPRIÉTÉS DE PORT

  • port.name: Le nom du port.
  • port.alias: Un alias pour le nom du port.

PROPRIÉTÉS DE LIEN

Les liens sont créés entre les ports des nœuds. Il n'y a pas de propriétés spécifiques aux liens qui sont généralement modifiées par l'utilisateur.

PROPRIÉTÉS CLIENT

  • application.name: Le nom de l'application cliente.
  • application.process.id: L'ID du processus de l'application cliente.

RÉGLAGES D'EXÉCUTION

Certains paramètres de PipeWire peuvent être configurés au moment de l'exécution, sans avoir à modifier les fichiers de configuration. Cela peut se faire via des variables d'environnement ou des appels API.

Par exemple, la propriété PipeWire_DEBUG peut être utilisée pour activer le débogage.

Les fichiers de configuration peuvent être placés dans les répertoires ACP sous ~/.config ou /etc.

PROFILS DE CARTE ALSA

PipeWire peut utiliser des profils pour configurer les cartes sonores ALSA. Ces profils définissent quels ports et quelles fonctionnalités sont activés pour une carte donnée.

Les profils ALSA sont généralement gérés via le système UCM et peuvent être sélectionnés en définissant la propriété device.profile sur la carte ALSA correspondante.

AUTRES TYPES D'OBJETS

Techniquement, les objets PipeWire sont ce qui est manipulé par les applications utilisant l'API PipeWire.

La liste des types d'objets qui sont habituellement « exportés » (c'est-à-dire qui apparaissent dans la sortie de pw-dump(1)) est plus grande que celles considérées ci-dessus :

  • Nœud (Node)
  • Périphérique (Device)
  • Port (Port)
  • Lien (Link)
  • Client (Client)
  • Métadonnées (Metadata)
  • Module (Module)
  • Profileur (Profiler)
  • Contexte de sécurité (SecurityContext)

Les moniteurs n'apparaissent pas dans cette liste ; ils ne sont généralement pas exportés, et techniquement ce sont aussi des objets Périphérique. Ils sont considérés ci-dessus comme un type d'objet distinct car ils ont des propriétés configurables.

Les objets Métadonnées sont ce qui est manipulé avec pw-metadata(1)

Les Modules peuvent être chargés dans des fichiers de configuration, ou par des applications PipeWire.

Les objets Profileur et Contexte de sécurité fournissent uniquement les APIs PipeWire correspondantes.
