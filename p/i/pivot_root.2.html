pivot_root(2) Manuel des appels système pivot_root(2)

NOM

pivot_root - changer le point de montage racine

BIBLIOTHÉQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_pivot_root, const char *new_root, const char *put_old);

Note : glibc ne fournit pas d'enveloppe pour pivot_root(), nécessitant l'utilisation de syscall(2).

DESCRIPTION

pivot_root() change le montage racine dans l'espace de noms de montage du processus appelant. Plus précisément, il déplace le montage racine vers le répertoire put_old et fait de new_root le nouveau montage racine. Le processus appelant doit posséder la capacité CAP_SYS_ADMIN dans l'espace de noms utilisateur qui possède l'espace de noms de montage de l'appelant.

pivot_root() change le répertoire racine et le répertoire de travail courant de chaque processus ou thread dans le même espace de noms de montage vers new_root s'ils pointent vers l'ancien répertoire racine. (Voir aussi NOTES.) D'autre part, pivot_root() ne change pas le répertoire de travail courant de l'appelant (sauf s'il se trouve sur l'ancien répertoire racine), et doit donc être suivi d'un appel chdir("/").

Les restrictions suivantes s'appliquent :

•
new_root et put_old doivent être des répertoires.
•
new_root et put_old ne doivent pas être sur le même montage que la racine actuelle.
•
put_old doit être au niveau ou en dessous de new_root ; c'est-à-dire que l'ajout d'un nombre non négatif de suffixes "/.." au chemin pointé par put_old doit produire le même répertoire que new_root.
•
new_root doit être un point de montage, mais ne peut pas être "/". Un chemin qui n'est pas déjà un point de montage peut être converti en un en montant le chemin sur lui-même par liaison.
•
Le type de propagation du montage parent de new_root et le montage parent du répertoire racine courant ne doivent pas être MS_SHARED ; similairement, si put_old est un point de montage existant, son type de propagation ne doit pas être MS_SHARED. Ces restrictions assurent que pivot_root() ne propage jamais de changements à un autre espace de noms de montage.
•
Le répertoire racine courant doit être un point de montage.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

pivot_root() peut échouer avec les mêmes erreurs que stat(2). De plus, il peut échouer avec les erreurs suivantes :

EBUSY
new_root ou put_old se trouve sur le montage racine courant. (Cette erreur couvre le cas pathologique où new_root est "/".)
EINVAL
new_root n'est pas un point de montage.
EINVAL
put_old n'est pas au niveau ou en dessous de new_root.
EINVAL
Le répertoire racine courant n'est pas un point de montage (en raison d'un chroot(2) antérieur).
EINVAL
La racine actuelle se trouve sur le montage rootfs (initrd) ; voir NOTES.
EINVAL
Soit le point de montage à new_root, soit le montage parent de ce point de montage, a un type de propagation MS_SHARED.
EINVAL
put_old est un point de montage et a le type de propagation MS_SHARED.
ENOTDIR
new_root ou put_old n'est pas un répertoire.
EPERM
Le processus appelant ne possède pas la capacité CAP_SYS_ADMIN.

NORMES

Linux.

HISTORIQUE

Linux 2.3.41.

NOTES

Une interface en ligne de commande pour cet appel système est fournie par pivot_root(8).

pivot_root() permet à l'appelant de passer à un nouveau système de fichiers racine tout en plaçant le montage racine précédent à un endroit sous new_root à partir duquel il peut être ultérieurement démonté. (Le fait qu'il déplace tous les processus ayant un répertoire racine ou un répertoire de travail courant sur l'ancien répertoire racine vers la nouvelle racine les libère de la charge de maintenir l'ancien répertoire racine monté, permettant ainsi un démontage plus facile.)

Une utilisation de pivot_root() a lieu lors du démarrage du système, lorsque le système monte un système de fichiers racine temporaire (par exemple, un initrd(4)), puis monte le système de fichiers racine réel, et finit par transformer ce dernier en répertoire racine de tous les processus et threads pertinents. Une utilisation moderne consiste à configurer un système de fichiers racine lors de la création d'un conteneur.

Le fait que pivot_root() modifie les répertoires racine et de travail courant des processus comme indiqué dans DESCRIPTION est nécessaire pour empêcher les threads du noyau de garder occupé l'ancien montage racine avec leurs répertoires racine et de travail courant, même s'ils n'accèdent jamais au système de fichiers d'aucune manière.

Le rootfs (initrd initial) ne peut pas être pivot_root()é. La méthode recommandée pour changer le système de fichiers racine dans ce cas est de supprimer tout dans rootfs, de recouvrir rootfs avec la nouvelle racine, de connecter stdin/stdout/stderr à la nouvelle /dev/console, et d'exécuter la nouvelle init(1). Des programmes d'aide pour ce processus existent ; voir switch_root(8).

pivot_root(".", ".")

new_root et put_old peuvent être le même répertoire. En particulier, la séquence suivante permet une opération de pivot-root sans avoir besoin de créer et supprimer un répertoire temporaire :


chdir(new_root);
pivot_root(".", ".");
umount2(".", MNT_DETACH);

Cette séquence réussit car l'appel pivot_root() empile l'ancien point de montage racine sur le nouveau point de montage racine à /. À ce stade, le répertoire racine du processus appelant et le répertoire de travail courant font référence au nouveau point de montage racine (new_root). Lors de l'appel umount() suivant, la résolution de "." commence avec new_root puis remonte la liste des montages empilés à /, ce qui a pour effet de démonter l'ancien point de montage racine.

Notes historiques

Pendant de nombreuses années, cette page de manuel comportait le texte suivant :

pivot_root() peut ou peut ne pas changer la racine courante et le répertoire de travail courant de tout processus ou thread utilisant l'ancien répertoire racine. L'appelant de pivot_root() doit s'assurer que les processus dont la racine ou le répertoire de travail courant est sur l'ancien répertoire racine fonctionnent correctement dans les deux cas. Un moyen simple d'assurer cela est de changer leur racine et leur répertoire de travail courant vers new_root avant d'invoquer pivot_root().

Ce texte, écrit avant même que l'implémentation de l'appel système ne soit finalisée dans le noyau, visait probablement à avertir les utilisateurs à l'époque que l'implémentation pourrait changer avant la publication finale. Cependant, le comportement indiqué dans DESCRIPTION est resté cohérent depuis que cet appel système a été implémenté pour la première fois et ne changera pas maintenant.

EXEMPLES

Le programme ci-dessous montre l'utilisation de pivot_root() dans un espace de noms de montage créé à l'aide de clone(2). Après avoir pivoté vers le répertoire racine nommé dans le premier argument de ligne de commande du programme, l'enfant créé par clone(2) exécute ensuite le programme nommé dans les arguments restants de la ligne de commande.

Nous démontrons le programme en créant un répertoire qui servira de nouveau système de fichiers racine et en y plaçant une copie de l'exécutable (liée statiquement) busybox(1).


$ mkdir /tmp/rootfs;
$ ls -id /tmp/rootfs;    # Afficher le numéro d'inode du nouveau répertoire racine
319459 /tmp/rootfs
$ cp $(which busybox) /tmp/rootfs;
$ PS1='bbsh$ ' sudo ./pivot_root_demo /tmp/rootfs /busybox sh;
bbsh$ PATH=/;
bbsh$ busybox ln busybox ln;
bbsh$ ln busybox echo;
bbsh$ ln busybox ls;
bbsh$ ls;
busybox  echo     ln       ls
bbsh$ ls -id /;          # Comparer avec le numéro d'inode ci-dessus
319459 /
bbsh$ echo 'hello world';
hello world

Source du programme

/* pivot_root_demo.c */
#define _GNU_SOURCE
#include <err.h>
#include <limits.h>
#include <sched.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <sys/mount.h>
#include <sys/stat.h>
#include <sys/syscall.h>
#include <sys/wait.h>
#include <unistd.h>
static int
pivot_root(const char *new_root, const char *put_old)
{
    return syscall(SYS_pivot_root, new_root, put_old);
}
#define STACK_SIZE (1024 * 1024)
static int              /* Fonction de démarrage pour l'enfant cloné */
child(void *arg)
{
    char        path[PATH_MAX];
    char        **args = arg;
    char        *new_root = args[0];
    const char  *put_old = "/oldrootfs";
    /* S'assurer que 'new_root' et son montage parent n'ont pas
       de propagation partagée (ce qui provoquerait une erreur de pivot_root() ),
       et empêcher la propagation des événements de montage
       vers l'espace de noms de montage initial.  */
    if (mount(NULL, "/", NULL, MS_REC | MS_PRIVATE, NULL) == -1)
        err(EXIT_FAILURE, "mount-MS_PRIVATE");
    /* S'assurer que 'new_root' est un point de montage.  */
    if (mount(new_root, new_root, NULL, MS_BIND, NULL) == -1)
        err(EXIT_FAILURE, "mount-MS_BIND");
    /* Créer le répertoire vers lequel l'ancien root sera pivoté.  */
    snprintf(path, sizeof(path), "%s/%s", new_root, put_old);
    if (mkdir(path, 0777) == -1)
        err(EXIT_FAILURE, "mkdir");
    /* Et pivoter le système de fichiers racine.  */
    if (pivot_root(new_root, path) == -1)
        err(EXIT_FAILURE, "pivot_root");
    /* Changer le répertoire de travail courant vers "/".  */
    if (chdir("/") == -1)
        err(EXIT_FAILURE, "chdir");
    /* Démonter l'ancien root et supprimer le point de montage.  */
    if (umount2(put_old, MNT_DETACH) == -1)
        perror("umount2");
    if (rmdir(put_old) == -1)
        perror("rmdir");
    /* Exécuter la commande spécifiée dans argv[1]...  */
    execv(args[1], &args[1]);
    err(EXIT_FAILURE, "execv");
}
int
main(int argc, char *argv[])
{
    char *stack;
    /* Créer un processus enfant dans un nouvel espace de noms de montage.  */
    stack = mmap(NULL, STACK_SIZE, PROT_READ | PROT_WRITE,
                 MAP_PRIVATE | MAP_ANONYMOUS | MAP_STACK, -1, 0);
    if (stack == MAP_FAILED)
        err(EXIT_FAILURE, "mmap");
    if (clone(child, stack + STACK_SIZE,
              CLONE_NEWNS | SIGCHLD, &argv[1]) == -1)
        err(EXIT_FAILURE, "clone");
    /* Le parent continue ici ; attend l'enfant.  */
    if (wait(NULL) == -1)
        err(EXIT_FAILURE, "wait");
    exit(EXIT_SUCCESS);
}
