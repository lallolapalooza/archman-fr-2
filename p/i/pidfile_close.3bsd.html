pidfile(3bsd) 3bsd pidfile(3bsd)

NOM

pidfile_open, pidfile_write, pidfile_close, pidfile_remove, pidfile_fileno — bibliothèque pour la gestion des fichiers PID

BIBLIOTHÈQUE

bibliothèque « libbsd »

SYNTAXE

#include <libutil.h> (Voir libbsd(7) pour l'utilisation des includes.)
struct pidfh *
pidfile_open(const char *path, mode_t mode, pid_t *pidptr);

int
pidfile_write(struct pidfh *pfh);

int
pidfile_close(struct pidfh *pfh);

int
pidfile_remove(struct pidfh *pfh);

int
pidfile_fileno(struct pidfh *pfh);

DESCRIPTION

La famille de fonctions pidfile permet aux démons de gérer les fichiers PID. Elle utilise flopen(3bsd) pour verrouiller un fichier PID et détecter les démons déjà en cours d'exécution.

La fonction pidfile_open() ouvre (ou crée) un fichier spécifié par l'argument path et le verrouille. Si l'argument pidptr n'est pas NULL et que le fichier ne peut pas être verrouillé, la fonction l'utilisera pour stocker un PID d'un démon déjà en cours d'exécution ou -1 si le démon n'a pas encore écrit son PID. La fonction n'écrit pas le PID du processus dans le fichier ici, elle peut donc être utilisée avant fork() et sortir avec un message d'erreur approprié si nécessaire. Si l'argument path est NULL, le fichier /var/run/⟨nom_programme⟩.pid sera utilisé. La fonction pidfile_open() définit le drapeau de fermeture lors de l'exécution (O_CLOEXEC) lors de l'ouverture du fichier PID.

La fonction pidfile_write() écrit le PID du processus dans un fichier précédemment ouvert. Le fichier est tronqué avant l'écriture, donc l'appel de la fonction pidfile_write() plusieurs fois est pris en charge.

La fonction pidfile_close() ferme un fichier PID. Elle doit être utilisée après que le démon ait fork()é pour démarrer un processus enfant.

La fonction pidfile_remove() ferme et supprime un fichier PID.

La fonction pidfile_fileno() retourne le descripteur de fichier pour le fichier PID ouvert.

VALEURS DE RETOUR

La fonction pidfile_open() retourne un pointeur valide vers une structure pidfh en cas de succès, ou NULL si une erreur se produit. Si une erreur se produit, errno sera défini.


Les fonctions pidfile_write(), pidfile_close(), et pidfile_remove() retournent la valeur 0 en cas de succès ; sinon, la valeur -1 est retournée et la variable globale errno est définie pour indiquer l'erreur.

La fonction pidfile_fileno() retourne le descripteur de fichier de bas niveau. Elle retourne -1 et définit errno si un pidfh nul est spécifié, ou si le fichier PID n'est plus ouvert.

EXEMPLES

L'exemple suivant montre dans quel ordre ces fonctions doivent être utilisées. Notez qu'il est sûr de passer NULL aux fonctions pidfile_write(), pidfile_remove(), pidfile_close() et pidfile_fileno().

struct pidfh *pfh;
pid_t otherpid, childpid;

pfh = pidfile_open("/var/run/daemon.pid", 0600, &otherpid);
if (pfh == NULL) {
	if (errno == EEXIST) {
		errx(EXIT_FAILURE, "Daemon déjà en cours d'exécution, pid : %jd.",
		    (intmax_t)otherpid);
	}
	/* Si nous ne pouvons pas créer le fichier PID pour d'autres raisons, nous avertissons seulement. */
	warn("Impossible d'ouvrir ou de créer le fichier PID");
	/*
	 * Même si pfh est NULL, nous pouvons continuer, car les autres fonctions pidfile_*
	 * peuvent gérer une telle situation en ne faisant rien sauf définir
	 * errno à EINVAL.
	 */
}

if (daemon(0, 0) == -1) {
	warn("Impossible de daemoniser");
	pidfile_remove(pfh);
	exit(EXIT_FAILURE);
}

pidfile_write(pfh);

for (;;) {
	/* Faire le travail. */
	childpid = fork();
	switch (childpid) {
	case -1:
		syslog(LOG_ERR, "Impossible de fork(): %s.", strerror(errno));
		break;
	case 0:
		pidfile_close(pfh);
		/* Faire le travail de l'enfant. */
		break;
	default:
		syslog(LOG_INFO, "Enfant %jd démarré.", (intmax_t)childpid);
		break;
	}
}

pidfile_remove(pfh);
exit(EXIT_SUCCESS);

ERREURS

La fonction pidfile_open() échouera si :

[EEXIST]
Un processus détient déjà le verrou sur le fichier PID donné, ce qui signifie qu'un démon est déjà en cours d'exécution. Si l'argument pidptr n'est pas NULL, la fonction l'utilisera pour stocker le PID d'un démon déjà en cours d'exécution ou -1 si le démon n'a pas encore écrit son PID.
[ENAMETOOLONG]
Le nom du fichier PID spécifié est trop long.
[EINVAL]
Un processus détient déjà le verrou sur le fichier PID donné, mais le PID lu à partir de là est invalide.

La fonction pidfile_open() peut également échouer et définir errno pour toutes les erreurs spécifiées pour les appels fstat(2), open(2), et read(2).

La fonction pidfile_write() échouera si :

[EINVAL]
Utilisation incorrecte de la fonction. Probablement appelée avant pidfile_open().

La fonction pidfile_write() peut également échouer et définir errno pour toutes les erreurs spécifiées pour les appels fstat(2), ftruncate(2), et write(2).

La fonction pidfile_close() peut échouer et définir errno pour toutes les erreurs spécifiées pour les appels close(2) et fstat(2).

La fonction pidfile_remove() échouera si :

[EINVAL]
Utilisation incorrecte de la fonction. Probablement appelée par un processus autre que celui qui a effectué pidfile_write().

La fonction pidfile_remove() peut également échouer et définir errno pour toutes les erreurs spécifiées pour les appels close(2), fstat(2), write(2), et unlink(2).

pidfile_close(3bsd) — libbsd — The BSD Reference Manual

NAME

pidfile_close, pidfile_fileno, pidfile_open, pidfile_remove, pidfile_write — utilities for writing and managing PID files

LIBRARY

This set of functions is available in the libbsd library.

SYNOPSIS

#include <pidfile.h>

FILE *pidfile_open(const char *path, mode_t mode, const char *exclusive);

int pidfile_write(FILE *pidfile);

int pidfile_close(FILE *pidfile);

int pidfile_remove(FILE *pidfile);

int pidfile_fileno(FILE *pidfile);

DESCRIPTION

The pidfile family of functions provides a convenient way to create and manage PID files. A PID file is a file that contains the process ID (PID) of a running daemon or service. It is commonly used to prevent multiple instances of a daemon from running simultaneously and to provide a way for other processes to find the PID of a running daemon.

The pidfile_open() function creates a PID file at the specified path. The mode argument specifies the file permissions for the PID file. If exclusive is non-NULL, it must be a string representing a PID. If exclusive is non-NULL and the file at path already exists, pidfile_open() will attempt to lock the file exclusively. If it cannot obtain the lock, it will check if the PID in the file corresponds to a running process. If the PID corresponds to a running process, pidfile_open() returns NULL and sets errno to EBUSY. If the PID does not correspond to a running process, the existing PID file is removed and a new one is created. If exclusive is NULL, the PID file is created if it does not exist, and truncated if it does. This behavior can be used to prevent multiple instances of a daemon from running simultaneously.

The pidfile_write() function writes the current process ID to the specified PID file. This should be called after successfully opening the PID file.

The pidfile_close() function closes the PID file. If the PID file was created by pidfile_open(), it will be automatically removed when the file is closed.

The pidfile_remove() function explicitly removes the PID file. This is useful if you need to remove the PID file before closing it, for example, when shutting down the daemon.

The pidfile_fileno() function returns the underlying file descriptor for the given PID file stream. This can be useful for performing operations on the file descriptor directly, such as using flock(2) or dup(2).

RETURN VALUES

The pidfile_open() function returns a pointer to a FILE structure on success, or NULL on failure. If NULL is returned, errno is set to indicate the error.

The pidfile_write(), pidfile_close(), pidfile_remove() and pidfile_fileno() functions return 0 on success, and -1 on failure. If -1 is returned, errno is set to indicate the error.

EXAMPLES

The following example demonstrates how to use the pidfile functions to create and manage a PID file:

FILE *pidfile;
pidfile = pidfile_open("/var/run/mydaemon.pid", 0600, NULL);
if (pidfile == NULL) {
    if (errno == EBUSY)
        fprintf(stderr, "mydaemon is already running.\n");
    else
        perror("pidfile_open");
    exit(EXIT_FAILURE);
}
if (pidfile_write(pidfile) == -1) {
    perror("pidfile_write");
    pidfile_close(pidfile);
    exit(EXIT_FAILURE);
}
/* Daemonize here */
printf("mydaemon running with PID %d\n", getpid());
/* ... */
/* When shutting down: */
pidfile_remove(pidfile);
pidfile_close(pidfile);

ERRORS

[EBUSY]
The PID file already exists and is locked by a running process.
[EINVAL]
An invalid argument was provided to the function. For pidfile_open(), this may occur if the path is invalid. For pidfile_write(), pidfile_close(), and pidfile_remove(), this may occur if the pidfile argument is not a valid FILE pointer obtained from pidfile_open().
[ENOENT]
The specified path does not exist and could not be created (e.g., the directory does not exist).
[ENOMEM]
Insufficient memory available.
[ENOSPC]
The device is full.

In addition to the errors described above, the pidfile functions may also return the errors associated with the underlying system calls they use, such as open(2), write(2), close(2), unlink(2) system calls and the flopen(3bsd) library function.

The pidfile_fileno() function will fail if:

[EINVAL]
Improper function use. Probably called not from the process which used pidfile_open().

SEE ALSO

open(2), daemon(3), flopen(3bsd)

HISTORY

The functions pidfile_open(), pidfile_write(), pidfile_close() and pidfile_remove() first appeared in FreeBSD 5.5.

The function pidfile_fileno() first appeared in FreeBSD 10.0.
