pthread_join(3) Manuel des fonctions de bibliothèque pthread_join(3)

NOM

pthread_join - joindre un thread terminé

BIBLIOTHÈQUE

Bibliothèque POSIX threads (libpthread, -lpthread)

SYNOPSIS

#include <pthread.h>
int pthread_join(pthread_t thread, void **retval);

DESCRIPTION

La fonction pthread_join() attend la fin du thread spécifié par thread. Si ce thread a déjà terminé, pthread_join() retourne immédiatement. Le thread spécifié par thread doit être jointsible.

Si retval n'est pas NULL, alors pthread_join() copie le statut de sortie du thread cible (c'est-à-dire la valeur que le thread cible a fournie à pthread_exit(3)) dans l'emplacement pointé par retval. Si le thread cible a été annulé, alors PTHREAD_CANCELED est placé dans l'emplacement pointé par retval.

Si plusieurs threads tentent simultanément de rejoindre le même thread, les résultats ne sont pas définis. Si le thread appelant pthread_join() est annulé, le thread cible restera jointsible (c'est-à-dire qu'il ne sera pas détaché).

VALEUR DE RETOUR

En cas de succès, pthread_join() retourne 0 ; en cas d'erreur, elle retourne un numéro d'erreur.

ERREURS

EDEADLK
Une interdépendance (deadlock) a été détectée (par exemple, deux threads ont tenté de se joindre mutuellement) ; ou thread spécifie le thread appelant.
EINVAL
thread n'est pas un thread jointsible.
EINVAL
Un autre thread attend déjà de se joindre à ce thread.
ESRCH
Aucun thread avec l'identifiant thread n'a pu être trouvé.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
pthread_join () Thread safety MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001.

NOTES

Après un appel réussi à pthread_join(), l'appelant est garanti que le thread cible a terminé. L'appelant peut alors choisir de effectuer toute action de nettoyage nécessaire après la fin du thread (par exemple, libérer la mémoire ou d'autres ressources allouées au thread cible).

Tenter de joindre un thread qui a déjà été joint auparavant entraîne un comportement indéfini.

Ne pas joindre un thread jointsible (c'est-à-dire un thread non détaché) produit un "thread zombie". Évitez cela, car chaque thread zombie consomme des ressources système, et lorsque suffisamment de threads zombies se sont accumulés, il ne sera plus possible de créer de nouveaux threads (ou processus).

Il n'y a pas d'équivalent pthreads à waitpid(-1, &status, 0), c'est-à-dire, "joindre avec n'importe quel thread terminé". Si vous pensez avoir besoin de cette fonctionnalité, vous devriez probablement revoir la conception de votre application.

Tous les threads d'un processus sont des pairs : n'importe quel thread peut se joindre à n'importe quel autre thread du processus.

EXEMPLES

Voir pthread_create(3).

VOIR AUSSI

pthread_cancel(3), pthread_create(3), pthread_detach(3), pthread_exit(3), pthread_tryjoin_np(3), pthreads(7)
