pthread_key_create(3) Manuel des fonctions de bibliothèque pthread_key_create(3)

NOM

pthread_key_create, pthread_key_delete, pthread_setspecific, pthread_getspecific - gestion des données spécifiques aux threads

SYNOPSIS

#include <pthread.h>
int pthread_key_create(pthread_key_t *key,
                       typeof(void (void *)) *destr_function;
int pthread_key_delete(pthread_key_t key);
int pthread_setspecific(pthread_key_t key, const void *pointer);
void * pthread_getspecific(pthread_key_t key);

DESCRIPTION

Les programmes ont souvent besoin de variables globales ou statiques ayant des valeurs différentes dans différents threads. Comme les threads partagent un seul espace mémoire, cela ne peut pas être réalisé avec des variables normales. Les données spécifiques aux threads sont la réponse POSIX threads à ce besoin.

Chaque thread possède un bloc de mémoire privé, la zone de données spécifiques aux threads, ou zone TSD pour faire court. Cette zone associe des valeurs de type void * aux clés TSD. Les clés TSD sont communes à tous les threads, mais la valeur associée à une clé TSD donnée peut être différente dans chaque thread.

Pour être concret, les zones TSD peuvent être vues comme des tableaux de pointeurs void *, les clés TSD comme des indices entiers dans ces tableaux, et la valeur d'une clé TSD comme la valeur de l'élément de tableau correspondant dans le thread appelant.

Lorsqu'un thread est créé, sa zone TSD associe initialement NULL à toutes les clés.

pthread_key_create() alloue une nouvelle clé TSD. La clé est stockée à l'emplacement pointé par key. Il y a une limite de PTHREAD_KEYS_MAX sur le nombre de clés allouées à un instant donné. La valeur initialement associée à la clé retournée est NULL dans tous les threads en cours d'exécution.

L'argument destr_function, s'il n'est pas NULL, spécifie une fonction destructrice associée à la clé. Lorsqu'un thread se termine via pthread_exit() ou par annulation, destr_function est appelée avec comme argument la valeur associée à la clé dans ce thread. Le destr_function n'est pas appelé si cette valeur est NULL. L'ordre dans lequel les fonctions destructrices sont appelées lors de la terminaison du thread n'est pas spécifié.

Avant que la fonction destructrice ne soit appelée, la valeur NULL est associée à la clé dans le thread courant. Une fonction destructrice peut cependant réassocier des valeurs non-NULL à cette clé ou à une autre clé. Pour gérer cela, si après que toutes les destructeurs aient été appelés pour toutes les valeurs non-NULL, il reste encore des valeurs non-NULL avec des destructeurs associés, alors le processus est répété. L'implémentation glibc arrête le processus après PTHREAD_DESTRUCTOR_ITERATIONS itérations, même si des valeurs non-NULL avec des descripteurs associés subsistent. D'autres implémentations peuvent boucler indéfiniment.

pthread_key_delete() désalloue une clé TSD. Elle ne vérifie pas si des valeurs non-NULL sont associées à cette clé dans les threads en cours d'exécution, ni n'appelle la fonction destructrice associée à la clé.

pthread_setspecific() change la valeur associée à key dans le thread appelant, en stockant le pointer donné à la place.

pthread_getspecific() retourne la valeur actuellement associée à key dans le thread appelant.

VALEUR DE RETOUR

pthread_key_create(), pthread_key_delete(), et pthread_setspecific() retournent 0 en cas de succès et un code d'erreur non nul en cas d'échec. En cas de succès, pthread_key_create() stocke la clé nouvellement allouée à l'emplacement pointé par son argument key.

pthread_getspecific() retourne la valeur associée à key en cas de succès, et NULL en cas d'erreur.

ERREURS

pthread_key_create() retourne le code d'erreur suivant en cas d'erreur :

EAGAIN
PTHREAD_KEYS_MAX clés sont déjà allouées.

pthread_key_delete() et pthread_setspecific() retournent le code d'erreur suivant en cas d'erreur :

EINVAL
key n'est pas une clé TSD valide et allouée.

pthread_getspecific() retourne NULL si key n'est pas une clé TSD valide et allouée.

VOIR AUSSI

pthread_create(3), pthread_exit(3), pthread_testcancel(3).

EXEMPLE

Le fragment de code suivant alloue un tampon de 100 caractères spécifique au thread, avec une récupération automatique à la sortie du thread :

/* Clé pour le tampon spécifique au thread */
static pthread_key_t buffer_key;
/* Initialisation de la clé une seule fois */
static pthread_once_t buffer_key_once = PTHREAD_ONCE_INIT;
/* Alloue le tampon spécifique au thread */
void buffer_alloc(void)
{
  pthread_once(&buffer_key_once, buffer_key_alloc);
  pthread_setspecific(buffer_key, malloc(100));
}
/* Retourne le tampon spécifique au thread */
char * get_buffer(void)
{
  return (char *) pthread_getspecific(buffer_key);
}
/* Alloue la clé */
static void buffer_key_alloc()
{
  pthread_key_create(&buffer_key, buffer_destroy);
}
/* Libère le tampon spécifique au thread */
static void buffer_destroy(void * buf)
{
  free(buf);
}
