PTHREAD_GETCONCURRENCY(3P) Manuel du programmeur POSIX PTHREAD_GETCONCURRENCY(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_getconcurrency, pthread_setconcurrency — obtenir et définir le niveau de concurrence

SYNTAXE

#include <pthread.h>
int pthread_getconcurrency(void);
int pthread_setconcurrency(int nouveau_niveau);

DESCRIPTION

Les threads non liés d'un processus peuvent ou non être nécessaires pour être simultanément actifs. Par défaut, l'implémentation des threads garantit qu'un nombre suffisant de threads sont actifs pour que le processus continue à progresser. Bien que cela permette d'économiser les ressources système, cela peut ne pas produire le niveau de concurrence le plus efficace.

La fonction pthread_setconcurrency() permet à une application d'informer l'implémentation des threads de son niveau de concurrence souhaité, nouveau_niveau. Le niveau de concurrence réel fourni par l'implémentation à la suite de cet appel de fonction n'est pas spécifié.

Si nouveau_niveau est zéro, cela amène l'implémentation à maintenir le niveau de concurrence à sa discrétion, comme si pthread_setconcurrency() n'avait jamais été appelée.

La fonction pthread_getconcurrency() renvoie la valeur définie par un appel précédent à la fonction pthread_setconcurrency(). Si la fonction pthread_setconcurrency() n'a pas été appelée précédemment, cette fonction renvoie zéro pour indiquer que l'implémentation maintient le niveau de concurrence.

Un appel à pthread_setconcurrency() informe l'implémentation de son niveau de concurrence souhaité. L'implémentation utilise cela comme un indice, pas comme une exigence.

Si une implémentation ne prend pas en charge le multiplexage de threads utilisateur sur plusieurs entités planifiées par le noyau, les fonctions pthread_setconcurrency() et pthread_getconcurrency() sont fournies pour la compatibilité du code source, mais elles n'ont aucun effet lorsqu'elles sont appelées. Pour maintenir la sémantique de la fonction, le paramètre nouveau_niveau est sauvegardé lorsque pthread_setconcurrency() est appelée, de sorte qu'un appel ultérieur à pthread_getconcurrency() renvoie la même valeur.

VALEUR DE RETOUR

En cas de succès, la fonction pthread_setconcurrency() renvoie zéro ; sinon, un numéro d'erreur est renvoyé pour indiquer l'erreur.

La fonction pthread_getconcurrency() renvoie toujours le niveau de concurrence défini par un appel précédent à pthread_setconcurrency(). Si la fonction pthread_setconcurrency() n'a jamais été appelée, pthread_getconcurrency() renvoie zéro.

ERREURS

La fonction pthread_setconcurrency() échoue si :

EINVAL
La valeur spécifiée par nouveau_niveau est négative.
EAGAIN
La valeur spécifiée par nouveau_niveau dépasserait une ressource système.

La fonction pthread_setconcurrency() ne doit pas renvoyer le code d'erreur [EINTR].

EXEMPLES

Aucun.

UTILISATION APPLICATION

Les développeurs d'applications doivent noter qu'une implémentation peut toujours ignorer tous les appels à pthread_setconcurrency() et renvoyer une constante pour pthread_getconcurrency(). Pour cette raison, il n'est pas recommandé que les applications portables utilisent cette fonction.
