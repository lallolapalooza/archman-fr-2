NOM

ptsematest - Lance deux threads et mesure la latence de la communication inter-processus avec un mutex POSIX.

SYNTAXE

ptsematest [-a|--affinity [PROC]] [-b|--breaktrace USEC] [-d|--distance DIST] [-D|--duration TIME] [-h|--help] [-i|--interval INTV] [--json FILENAME] [-l|--loops LOOPS] [-p|--prio PRIO] [-q|--quiet] [-S|--smp] [-t|--threads [NUM]]

DESCRIPTION

Le programme ptsematest démarre deux threads qui sont synchronisés via pthread_mutex_unlock()/pthread_mutex_lock() et mesure la latence entre la libération et l'obtention du verrou.

OPTIONS

-a, --affinity[=PROC]
Exécuter sur le processeur numéro PROC. Si PROC n'est pas spécifié, exécuter sur le processeur courant.
-b, --breaktrace=USEC
Envoyer une commande de rupture de trace lorsque la latence est supérieure à USEC. Ceci est une option de débogage pour contrôler le traceur de latence dans le patch de préemption temps réel. Il est utile pour identifier les latences inattendues d'un système.
-d, --distance=DIST
Définir la distance des intervalles de threads en microsecondes (par défaut est 500 us). Lorsque cyclictest est appelé avec l'option -t et que plus d'un thread est créé, cette valeur de distance est ajoutée à l'intervalle des threads : Interval(thread N) = Interval(thread N-1) + DIST
-D, --duration=TIME
Spécifier une durée pour l'exécution du test.
Ajouter 'm', 'h', ou 'd' pour spécifier des minutes, heures ou jours.
-h, --help
Afficher le message d'aide.
-i, --interval=INTV
Définir l'intervalle de base du(des) thread(s) en microsecondes (par défaut est 1000 us). Ceci définit l'intervalle du premier thread. Voir aussi -d.
--json=FILENAME
Écrire les résultats finaux dans FILENAME, formaté en JSON.
-l, --loops=LOOPS
Définir le nombre de boucles. Par défaut est 0 (sans fin). Cette option est utile pour les tests automatisés avec un nombre donné de cycles de test. ptsematest est arrêté une fois que le nombre d'intervalles de minuteur a été atteint.
-p, --prio=PRIO
Définir la priorité du processus.
-q, --quiet
Afficher un résumé seulement à la sortie. Utile pour les tests automatisés, où seul le résumé de sortie doit être capturé.
-S, --smp
Test SMP : options -a -t et priorité identique
-t, --threads[=NUM]
Définir le nombre de threads de test (par défaut est 1, si cette option n'est pas donnée). Si NUM est spécifié, créer NUM threads de test. Si NUM n'est pas spécifié, NUM est défini au nombre de CPU disponibles.

EXEMPLES

L'exemple suivant a été exécuté sur un processeur à 4 cœurs :

#4: ID8676, P97, CPU2, I150; #5: ID8677, P97, CPU2, Cycles 668130
#6: ID8678, P96, CPU3, I175; #7: ID8679, P96, CPU3, Cycles 589423
