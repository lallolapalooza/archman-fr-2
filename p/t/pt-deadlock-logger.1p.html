NOM

pt-deadlock-logger - Enregistre les interblocages MySQL.

SYNTAXE

Utilisation : pt-deadlock-logger [OPTIONS] DSN

pt-deadlock-logger enregistre les informations sur les interblocages MySQL sur le DSN donné. Les informations sont imprimées sur "STDOUT", et peuvent également être sauvegardées dans une table en spécifiant "--dest". L'outil fonctionne indéfiniment à moins que "--run-time" ou "--iterations" ne soit spécifié.

Imprimer les interblocages sur l'hôte1 :

pt-deadlock-logger h=host1

Imprimer les interblocages sur l'hôte1 une fois puis quitter :

pt-deadlock-logger h=host1 --iterations 1

Sauvegarder les interblocages sur l'hôte1 dans percona_schema.deadlocks sur l'hôte2 :

pt-deadlock-logger h=host1 --dest h=host2,D=percona_schema,t=deadlocks

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Consulter les "BUGS" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-deadlock-logger imprime les informations sur les interblocages MySQL en interrogeant et en analysant "SHOW ENGINE INNODB STATUS". Lorsqu'un nouvel interblocage se produit, il est imprimé sur "STDOUT" et, si spécifié, sauvegardé dans "--dest".

Seuls les nouveaux interblocages sont imprimés. Une empreinte digitale pour chaque interblocage est créée en utilisant les valeurs serveur, ts et thread de l'interblocage (même si ces colonnes ne sont pas spécifiées par "--columns"). Un interblocage est imprimé si son empreinte digitale est différente de celle du dernier interblocage.

L'instruction "--dest" utilise "INSERT IGNORE" pour éliminer les interblocages dupliqués, donc chaque interblocage est sauvegardé pour chaque "--iterations".

SORTIE

Les nouveaux interblocages sont imprimés sur "STDOUT", sauf si "--quiet" est spécifié. Les erreurs et avertissements sont imprimés sur "STDERR".

Voir aussi "--columns" et "--tab".

CAVEATS ET DÉTAILS INNODB

La sortie d'InnoDB est difficile à analyser et parfois il n'y a aucun moyen de le faire correctement.

Parfois, toutes les informations (par exemple, le nom d'utilisateur ou l'adresse IP) ne sont pas incluses dans les informations sur l'interblocage. Dans ce cas, il n'y a rien que l'outil puisse placer dans ces colonnes. Il se peut également que la sortie de l'interblocage soit si longue (car il y avait beaucoup de verrous) que l'ensemble est tronqué.

Bien qu'il y ait généralement deux transactions impliquées dans un interblocage, il y a plus de verrous que cela ; au minimum, un verrou de plus que de transactions est nécessaire pour créer un cycle dans le graphique des attentes. pt-deadlock-logger imprime les transactions (toujours deux dans la sortie InnoDB, même lorsqu'il y a plus de transactions dans le graphique des attentes) et remplit les verrous. Il préfère le verrou attendu au verrou détenu lors du choix des informations de verrouillage à afficher, mais vous pouvez déduire le reste avec un peu de réflexion. Si vous voyez un verrou attendu et un verrou détenu, vous regardez le même verrou, donc bien sûr vous préféreriez voir les deux verrous attendus et obtenir plus d'informations. Si les deux verrous attendus ne sont pas sur la même table, plus de deux transactions étaient impliquées dans l'interblocage.

Enfin, gardez à l'esprit que, comme les noms d'utilisateur avec des espaces ne sont pas cités par InnoDB, l'outil rapportera généralement le second mot de ces noms d'utilisateur comme étant le nom d'hôte.

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Référez-vous à la "SYNTAXE" et aux informations d'utilisation pour plus de détails.

--ask-pass
Demander un mot de passe lors de la connexion à MySQL.
--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, définit le mode binaire de Perl sur STDOUT en utf8, passe l'option mysql_enable_utf8 à DBD::mysql et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur définit le mode binaire sur STDOUT sans la couche utf8 et exécute SET NAMES après la connexion à MySQL.

--clear-deadlocks
type : chaîne

Utilisez cette table pour créer un petit interblocage. Cela a généralement pour effet de purger un interblocage énorme, qui consomme autrement toute la sortie de "SHOW INNODB STATUS". La table ne doit pas exister. pt-deadlock-logger la créera avec la structure suivante :

CREATE TABLE percona_schema.clear_deadlocks (
  a INT PRIMARY KEY
) ENGINE=InnoDB

Après avoir créé la table et provoqué un petit interblocage, l'outil supprimera à nouveau la table.

--columns
type : Tableau ; par défaut : server, ts, thread, txn_id, txn_time, user, hostname, ip, db, tbl, idx, lock_type, lock_mode, wait_hold, victim, query

Les colonnes sont :

server
Le serveur (source) sur lequel l'interblocage s'est produit. Cela peut être utile si vous suivez les interblocages sur plusieurs serveurs.
ts
La date et l'heure du dernier interblocage détecté.
thread
Le numéro de thread MySQL, qui est identique à l'identifiant de connexion dans SHOW FULL PROCESSLIST.
txn_id
L'identifiant de transaction InnoDB, que InnoDB exprime comme deux entiers non signés. L'outil les multiplie pour obtenir un seul nombre.
txn_time
Combien de temps la transaction a été active lorsque l'interblocage s'est produit.
user
Le nom d'utilisateur de la base de données de la connexion.
hostname
L'hôte de la connexion.
ip
L'adresse IP de la connexion. Si vous spécifiez "--numeric-ip", elle est convertie en un entier non signé.
db
La base de données dans laquelle l'interblocage s'est produit.
tbl
La table sur laquelle l'interblocage s'est produit.
idx
L'index sur lequel l'interblocage s'est produit.
lock_type
Le type de verrou que la transaction détenait sur le verrou qui a causé l'interblocage.
lock_mode
Le mode de verrou du verrou qui a causé l'interblocage.
wait_hold
Si la transaction attendait le verrou ou le détenait. Généralement, vous verrez les deux verrous attendus.
victim
Si la transaction a été sélectionnée comme victime de l'interblocage et annulée.
query
La requête qui a causé l'interblocage.
--config
type : Tableau

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, cela doit être la première option sur la ligne de commande.

--create-dest-table
Créer la table spécifiée par "--dest".

Normalement, la table "--dest" est censée exister déjà. Cette option amène pt-deadlock-logger à créer automatiquement la table en utilisant la structure de table suggérée.

--daemonize
Forquer vers l'arrière-plan et se détacher du shell. Uniquement pour les systèmes d'exploitation POSIX.

NOM

pt-deadlock-logger - Detect and log MySQL deadlocks

SYNOPSIS

pt-deadlock-logger --dest ["h=host,D=database,t=table"] [OPTIONS]

DESCRIPTION

The pt-deadlock-logger tool monitors MySQL servers for deadlocks and logs them to a table in a specified MySQL database. When a deadlock is detected, it extracts information about the transactions and queries involved and stores it in the specified table. This information is crucial for diagnosing and resolving performance issues and application logic errors.

The tool runs continuously, checking for deadlocks at regular intervals. It can be configured to run for a specific duration or indefinitely. The output can be directed to a file or logged to a MySQL table.

OPTIONS

--config
type: string

Read configuration from this file. The file must be Percona Toolkit's standard configuration file format.

Configuration files are the first place the tool looks for options. If the option is not found in the configuration file, the tool looks for it on the command line. This means that command-line options override options in configuration files. Options in the file are specified in a "[toolname]" section. For example:

[pt-deadlock-logger]
dest=h=127.0.0.1,D=log,t=deadlocks
user=root
password=secret

You can specify multiple configuration files, separated by commas. The first file is the primary configuration file. Subsequent files are included in order, with options being overridden by later files. For example:

--config=~/.my.cnf,~/.pt-deadlock-logger.cnf

For more information about configuration files, see the Percona Toolkit documentation.

--columns
type: string; default: ALL

Comma-separated list of columns to store in the deadlocks table. If not specified, all columns are stored. See the description of "--dest" for a sample table structure.

--daemonize

Run the tool as a background daemon. This option is only available on Unix-like systems. When daemonized, the tool forks into the background and detaches from the controlling terminal. The standard output and standard error are redirected to the file specified by "--log", or to "/dev/null" if no log file is specified. The PID file is created as specified by "--pid".

--defaults-file
short form: -F; type: string

Read only mysql options from the given file. You must give an absolute pathname.

--dest
type: DSN

DSN for where to store deadlocks; specify at least a database (D) and table (t).

Missing values are filled in with the same values from the source host, so you can usually omit most parts of this argument if you're storing deadlocks on the same server on which they happen.

The following table structure is suggested if you want to store all the information pt-deadlock-logger can extract about deadlocks:

CREATE TABLE deadlocks (
  server char(20) NOT NULL,
  ts timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  thread int unsigned NOT NULL,
  txn_id bigint unsigned NOT NULL,
  txn_time smallint unsigned NOT NULL,
  user char(16) NOT NULL,
  hostname char(20) NOT NULL,
  ip char(15) NOT NULL, -- alternatively, ip int unsigned NOT NULL
  db char(64) NOT NULL,
  tbl char(64) NOT NULL,
  idx char(64) NOT NULL,
  lock_type char(16) NOT NULL,
  lock_mode char(1) NOT NULL,
  wait_hold char(1) NOT NULL,
  victim tinyint unsigned NOT NULL,
  query text NOT NULL,
  PRIMARY KEY  (server,ts,thread)
) ENGINE=InnoDB

If you use "--columns", you can omit whichever columns you don't want to store.

--help
Show help and exit.
--host
short form: -h; type: string

Connect to host.

--interval
type: time; default: 30

How often to check for deadlocks. If no "--run-time" is specified, pt-deadlock-logger runs forever, checking for deadlocks at every interval. See also "--run-time".

--iterations
type: int

How many times to check for deadlocks. By default, this option is undefined which means an infinite number of iterations. The tool always exits for "--run-time", regardless of the value specified for this option. For example, the tool will exit after 1 minute with "--run-time 1m --iterations 4 --interval 30" because 4 iterations at 30 second intervals would take 2 minutes, longer than the 1 minute run-time.

--log
type: string

Print all output to this file when daemonized.

--numeric-ip
Express IP addresses as integers.
--password
short form: -p; type: string

Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

--pid
type: string

Create the given PID file. The tool won't start if the PID file already exists and the PID it contains is different than the current PID. However, if the PID file exists and the PID it contains is no longer running, the tool will overwrite the PID file with the current PID. The PID file is removed automatically when the tool exits.

--port
short form: -P; type: int

Port number to use for connection.

--quiet
Do not deadlocks; only print errors and warnings to "STDERR".
--run-time
type: time

How long to run before exiting. By default pt-deadlock-logger runs forever, checking for deadlocks every "--interval" seconds.

--set-vars
type: Array

Set the MySQL variables in this comma-separated list of "variable=value" pairs.

By default, the tool sets:

wait_timeout=10000

Variables specified on the command line override these defaults. For example, specifying "--set-vars wait_timeout=500" overrides the default value of 10000.

The tool prints a warning and continues if a variable cannot be set.

--socket
short form: -S; type: string

Socket file to use for connection.

--tab
Use tabs to separate columns instead of spaces.
--user
short form: -u; type: string

User for login if not current user.

--version
Show version and exit.
--[no]version-check
default: yes

Check for the latest version of Percona Toolkit, MySQL, and other programs.

This is a standard "check for updates automatically" feature, with two additional features. First, the tool checks its own version and also the versions of the following software: operating system, Percona Monitoring and Management (PMM), MySQL, Perl, MySQL driver for Perl (DBD::mysql), and Percona Toolkit. Second, it checks for and warns about versions with known problems. For example, MySQL 5.5.25 had a critical bug and was re-released as 5.5.25a.

A secure connection to Percona's Version Check database server is done to perform these checks. Each request is logged by the server, including software version numbers and unique ID of the checked system. The ID is generated by the Percona Toolkit installation script or when the Version Check database call is done for the first time.

Any updates or known problems are printed to STDOUT before the tool's normal output. This feature should never interfere with the normal operation of the tool.

For more information, visit https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

OPTIONS DSN

Ces options DSN sont utilisées pour créer un DSN. Chaque option est donnée sous la forme "option=valeur". Les options sont sensibles à la casse, donc P et p ne sont pas la même option. Il ne doit pas y avoir d'espace avant ou après le "=" et si la valeur contient des espaces, elle doit être mise entre guillemets. Les options DSN sont séparées par des virgules. Voir la page de manuel percona-toolkit pour plus de détails.

  • A

    dsn: charset; copy: yes

    Jeu de caractères par défaut.

  • D

    dsn: database; copy: yes

    Base de données par défaut.

  • F

    dsn: mysql_read_default_file; copy: yes

    Ne lire que les options par défaut à partir du fichier donné.

  • h

    dsn: host; copy: yes

    Se connecter à l'hôte.

  • p

    dsn: password; copy: yes

    Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

  • P

    dsn: port; copy: yes

    Numéro de port à utiliser pour la connexion.

  • S

    dsn: mysql_socket; copy: yes

    Fichier socket à utiliser pour la connexion.

  • t

    Table dans laquelle stocker les informations de verrouillage mutuel.

  • u

    dsn: user; copy: yes

    Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

  • s

    dsn: mysql_ssl; copy: yes

    Créer une connexion SSL.

ENVIRONNEMENT

La variable d'environnement "PTDEBUG" active la sortie de débogage verbeuse sur STDERR. Pour activer le débogage et capturer toute la sortie dans un fichier, exécutez l'outil comme suit :

PTDEBUG=1 pt-deadlock-logger ... > FICHIER 2>&1

Faites attention : la sortie de débogage est volumineuse et peut générer plusieurs mégaoctets de sortie.

ATTENTION

L'utilisation de <PTDEBUG> peut exposer les mots de passe. Lorsque le débogage est activé, tous les paramètres de la ligne de commande sont affichés dans la sortie.

CONFIGURATION REQUISE

Vous avez besoin de Perl, DBI, DBD::mysql, et de certains packages de base qui devraient être installés dans toute version raisonnablement récente de Perl.
