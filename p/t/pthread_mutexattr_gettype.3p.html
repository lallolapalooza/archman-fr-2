PTHREAD_MUTEXATTR_GETTYPE(3P) Manuel du programmeur POSIX PTHREAD_MUTEXATTR_GETTYPE(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour connaître le comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_mutexattr_gettype, pthread_mutexattr_settype — obtenir et définir l'attribut du type de mutex

SYNOPSIS

#include <pthread.h>
int pthread_mutexattr_gettype(const pthread_mutexattr_t *restrict attr,
    int *restrict type);
int pthread_mutexattr_settype(pthread_mutexattr_t *attr, int type);

DESCRIPTION

Les fonctions pthread_mutexattr_gettype() et pthread_mutexattr_settype() obtiennent et définissent respectivement l'attribut du type de mutex. Cet attribut est défini dans le paramètre type de ces fonctions. La valeur par défaut de l'attribut type est PTHREAD_MUTEX_DEFAULT.

Le type de mutex est contenu dans l'attribut type des attributs du mutex. Les types de mutex valides incluent :

PTHREAD_MUTEX_NORMAL PTHREAD_MUTEX_ERRORCHECK PTHREAD_MUTEX_RECURSIVE PTHREAD_MUTEX_DEFAULT

Le type de mutex affecte le comportement des appels qui verrouillent et déverrouillent le mutex. Voir pthread_mutex_lock() pour plus de détails. Une implémentation peut mapper PTHREAD_MUTEX_DEFAULT à l'un des autres types de mutex.

Le comportement est indéfini si la valeur spécifiée par l'argument attr à pthread_mutexattr_gettype() ou pthread_mutexattr_settype() ne fait pas référence à un objet d'attributs de mutex initialisé.

VALEUR DE RETOUR

En cas de succès, la fonction pthread_mutexattr_gettype() retourne zéro et stocke la valeur de l'attribut type de attr dans l'objet référencé par le paramètre type. Sinon, une erreur est retournée pour indiquer l'erreur.

En cas de succès, la fonction pthread_mutexattr_settype() retourne zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_mutexattr_settype() échoue si :

EINVAL
La valeur type est invalide.

Ces fonctions ne retourneront pas un code d'erreur de [EINTR].

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

USAGE APPLICATIF

Il est conseillé qu'une application n'utilise pas un mutex PTHREAD_MUTEX_RECURSIVE avec des variables de condition car le déverrouillage implicite effectué pour un pthread_cond_timedwait() ou pthread_cond_wait() peut ne pas libérer réellement le mutex (s'il avait été verrouillé plusieurs fois). Si cela se produit, aucun autre thread ne peut satisfaire la condition du prédicat.

JUSTIFICATION

Si une implémentation détecte que la valeur spécifiée par l'argument attr à pthread_mutexattr_gettype() ou pthread_mutexattr_settype() ne fait pas référence à un objet d'attributs de mutex initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].
