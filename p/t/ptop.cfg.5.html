ptop.cfg(5) Fichier de configuration du beautifier de code ptop ptop.cfg(5)

NOM

ptop.cfg - Le fichier de configuration du beautifier de code ptop.

ptop est le beautifier de code du projet FreePascal.

Origine probablement Pascal-TO-Pascal.cfg

DESCRIPTION

Ceci est le fichier de configuration principal du beautifier de code FPC ptop

Le fichier de configuration de ptop(1) n'est pas nécessairement appelé ptop.cfg, et n'est pas non plus chargé automatiquement, donc le nom n'a pas beaucoup d'importance. Cette page de manuel décrit la structure d'un tel fichier de configuration pour ptop(1)

STRUCTURE

La structure d'un fichier de configuration ptop est un bloc de construction simple répété plusieurs (60-70) fois, une fois pour chaque mot-clé Pascal connu du programme ptop. (voir le fichier de configuration par défaut ou la source de ptopu.pp pour savoir quels mots-clés sont connus)

Le bloc de construction de base du fichier de configuration se compose d'une, deux ou trois lignes, décrivant comment ptop doit réagir à un mot-clé spécifique. D'abord une ligne sans crochets avec le format suivant :

motcle=option1,option2,option3,...

Si l'une des options est "dindonkey" (voir plus loin), une deuxième ligne (avec des crochets) est nécessaire comme ceci :

[motcle]=autre_motcle1,autre_motcle2,autre_motcle3,...

Ensuite, si l'une des options est "gobsym", une troisième ligne (avec des chevrons) est nécessaire comme ceci :

<motcle>=mot_terminal1,mot_terminal2,mot_terminal3,...

Comme vous pouvez le voir, le bloc contient deux types d'identifiants, des mots-clés (motcle, autre_motcle1..3 et mot_terminal1..3 dans l'exemple ci-dessus) et des options (option1..3 ci-dessus).

Les mots-clés sont les identifiants de structure Pascal valides intégrés comme BEGIN, END, CASE, IF, THEN, ELSE, IMPLEMENTATION. Le fichier de configuration par défaut liste la plupart de ceux-ci.

En plus des vrais mots-clés Pascal, certains autres mots-codes sont utilisés pour les opérateurs et les expressions de commentaires. Ceux-ci sont listés dans le tableau suivant :

Nom du mot-code opérateur
------------- -----
casevar : dans une étiquette de case (<>'deux-points')
becomes :=
delphicomment //
opencomment { ou (*
closecomment } ou *)
semicolon ;
colon :
equals =
openparen [
closeparen ]
period .

Les mots-codes Options définissent les actions à entreprendre lorsque le mot-clé avant le signe égal est trouvé.

Option fait quoi
------- ---------
crsupp supprime le retour chariot avant le mot-clé.
crbefore force le retour chariot avant le mot-clé
(ne va pas avec crsupp :) )
blinbefore ligne blanche avant le mot-clé.
dindonkey désindente sur les mots-clés associés (voir ci-dessous)
dindent désindente (toujours)
spbef espace avant
spaft espace après
gobsym Affiche les symboles qui suivent un mot-clé,
mais qui n'affectent pas la mise en page.
Affiche jusqu'à ce que les terminateurs se produisent.
inbytab indente par tabulation.
crafter force le retour chariot après le mot-clé.
upper affiche le mot-clé en majuscules
lower affiche le mot-clé en minuscules
capital met le mot-clé en majuscule : 1ère lettre
en majuscule, reste en minuscule.

L'option "dindonkey" nécessite des paramètres supplémentaires, qui sont définis par une deuxième ligne pour ce mot-clé (celle avec les crochets), qui n'est donc nécessaire que si les options contiennent "dinkdonkey" (contraction de désindentation sur mot-clé associé).

"dinkdonkey" désindente si l'un des mots-clés spécifiés par les options supplémentaires de la ligne entre crochets est trouvé.

De manière similaire, l'option "gobsym", abrégé pour gobble symbols, nécessite des informations supplémentaires afin d'accomplir sa fonction. L'option "gobsym" indique que tous les symboles suivant le mot-clé doivent être passés tels quels jusqu'à ce qu'un symbole terminal soit atteint. La liste des symboles terminaux acceptables est fournie par la ligne entre chevrons.

EXEMPLES

Le bloc

else=crbefore,dindonkey,inbytab,upper
[else]=if,then,else

Signifie :

Le mot-clé concerné est else, il est à GAUCHE des deux signes égal.

Lorsque le parseur ptop trouve ELSE, les options lui disent de faire les choses suivantes :

- (crbefore) Ne pas autoriser d'autre code sur la ligne avant
  le mot-clé. (ELSE seul sur une ligne)
- (dindonkey) Désindenter sur les mots-clés de la ligne
  entre crochets (if,then,else)
- (inbytab) Indenter par tabulation.
- (upper) Mettre le mot-clé en majuscules (ELSE)

Le bloc

case=spaft,gobsym,inbytab,crafter,capital
<case>=ofsym

Signifie :

Le mot-clé concerné est case, il est à GAUCHE des deux signes égal.

Lorsque case est trouvé, les options lui disent de faire les choses suivantes :

- (spaft) S'assurer qu'il y a un espace
  après le mot-clé. (case)
- (gobsym) passer les symboles sans changement jusqu'à ce que l'un des
  mots de la ligne entre chevrons (of) soit trouvé.
- (crafter) S'assurer que le terminateur (of) termine la ligne.
- (inbytab) Indenter par tabulation.
- (capital) Mettre le mot-clé en majuscule (case devient Case).

Essayez de jouer avec le fichier de configuration jusqu'à obtenir l'effet désiré. La configurabilité et les possibilités de ptop sont assez grandes par rapport à d'autres beautifiers de code shareware trouvés sur, par exemple, SIMTEL.
