NOM

pty - interfaces de pseudoterminal

DESCRIPTION

Un pseudoterminal (parfois abrégé en « pty ») est une paire d'appareils caractère virtuels qui fournissent un canal de communication bidirectionnel. Une extrémité du canal est appelée le maître ; l'autre extrémité est appelée l' esclave.

L'extrémité esclave du pseudoterminal fournit une interface qui se comporte exactement comme un terminal classique. Un processus qui s'attend à être connecté à un terminal peut ouvrir l'extrémité esclave d'un pseudoterminal et être ensuite piloté par un programme qui a ouvert l'extrémité maître. Tout ce qui est écrit sur l'extrémité maître est fourni au processus sur l'extrémité esclave comme s'il s'agissait d'une entrée tapée sur un terminal. Par exemple, écrire le caractère d'interruption (généralement Ctrl-C) sur le périphérique maître provoquerait la génération d'un signal d'interruption (SIGINT) pour le groupe de processus de premier plan connecté à l'esclave. Inversement, tout ce qui est écrit sur l'extrémité esclave du pseudoterminal peut être lu par le processus connecté à l'extrémité maître.

Le flux de données entre le maître et l'esclave est géré de manière asynchrone, de manière similaire au flux de données avec un terminal physique. Les données écrites sur l'esclave seront disponibles au maître rapidement, mais peuvent ne pas l'être immédiatement. De même, il peut y avoir un petit délai de traitement entre une écriture sur le maître et l'effet visible sur l'esclave.

Historiquement, deux API de pseudoterminal ont évolué : BSD et System V. SUSv1 a standardisé une API de pseudoterminal basée sur l'API System V, et cette API devrait être employée dans tous les nouveaux programmes qui utilisent des pseudoterminals.

Linux fournit des pseudoterminals de style BSD et de style System V (standardisé). Les terminaux de style System V sont couramment appelés pseudoterminals UNIX 98 sur les systèmes Linux.

Depuis Linux 2.6.4, les pseudoterminals de style BSD sont considérés comme obsolètes : le support peut être désactivé lors de la compilation du noyau en désactivant l'option CONFIG_LEGACY_PTYS. (Depuis Linux 2.6.30, cette option est désactivée par défaut dans le noyau principal.) Les pseudoterminals UNIX 98 devraient être utilisés dans les nouvelles applications.

Pseudoterminals UNIX 98

Un pseudoterminal UNIX 98 non utilisé est ouvert en appelant posix_openpt(3). (Cette fonction ouvre le périphérique maître de clonage, /dev/ptmx ; voir pts(4).) Après avoir effectué toutes les initialisations spécifiques au programme, modifié la propriété et les permissions du périphérique esclave à l'aide de grantpt(3), et déverrouillé l'esclave à l'aide de unlockpt(3)), le périphérique esclave correspondant peut être ouvert en passant le nom renvoyé par ptsname(3) dans un appel à open(2).

Le noyau Linux impose une limite au nombre de pseudoterminals UNIX 98 disponibles. Jusqu'à et y compris Linux 2.6.3, cette limite est configurée au moment de la compilation du noyau (CONFIG_UNIX98_PTYS), et le nombre autorisé de pseudoterminals peut aller jusqu'à 2048, avec un réglage par défaut de 256. Depuis Linux 2.6.4, la limite est dynamiquement ajustable via /proc/sys/kernel/pty/max, et un fichier correspondant, /proc/sys/kernel/pty/nr, indique combien de pseudoterminals sont actuellement en cours d'utilisation. Pour plus de détails sur ces deux fichiers, voir proc(5).

Pseudoterminals BSD

Les pseudoterminals de style BSD sont fournis sous forme de paires précréées, avec des noms de la forme /dev/ptyXY (maître) et /dev/ttyXY (esclave), où X est une lettre de l'ensemble de 16 caractères [p-za-e], et Y est une lettre de l'ensemble de 16 caractères [0-9a-f]. (L'ensemble précis de lettres dans ces deux ensembles varie selon les implémentations UNIX.) Par exemple, /dev/ptyp1 et /dev/ttyp1 constituent une paire de pseudoterminal BSD. Un processus recherche une paire de pseudoterminal inutilisée en essayant d'open(2) chaque maître de pseudoterminal jusqu'à ce qu'un open réussisse. L'esclave de pseudoterminal correspondant (remplacer « tty » par « pty » dans le nom du maître) peut alors être ouvert.

FICHIERS

/dev/ptmx
Périphérique maître de clonage UNIX 98
/dev/pts/*
Périphériques esclaves UNIX 98
/dev/pty[p-za-e][0-9a-f]
Périphériques maîtres BSD
/dev/tty[p-za-e][0-9a-f]
Périphériques esclaves BSD

NOTES

Les pseudoterminals sont utilisés par des applications telles que les services de connexion réseau (ssh(1), rlogin(1), telnet(1)), les émulateurs de terminal tels que xterm(1), script(1), screen(1), tmux(1), unbuffer(1), et expect(1).

Une description de l'opération TIOCPKT de ioctl(2), qui contrôle le mode opérationnel par paquets, peut être trouvée dans ioctl_tty(2).

Les opérations ioctl(2) BSD TIOCSTOP, TIOCSTART, TIOCUCNTL, et TIOCREMOTE n'ont pas été implémentées sous Linux.
