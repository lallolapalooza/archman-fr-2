pthread_attr_setscope(3) Manuel des fonctions de bibliothèque pthread_attr_setscope(3)

NOM

pthread_attr_setscope, pthread_attr_getscope - définir/obtenir l'attribut de portée de compétition dans l'objet d'attributs de thread

BIBLIOTHÈQUE

Bibliothèque POSIX threads (libpthread, -lpthread)

SYNOPSIS

#include <pthread.h>
int pthread_attr_setscope(pthread_attr_t *attr, int scope);
int pthread_attr_getscope(const pthread_attr_t *restrict attr,
                          int *restrict scope);

DESCRIPTION

La fonction pthread_attr_setscope() définit l'attribut de portée de compétition de l'objet d'attributs de thread référencé par attr à la valeur spécifiée dans scope. L'attribut de portée de compétition définit l'ensemble des threads contre lesquels un thread entre en compétition pour les ressources telles que le CPU. POSIX.1 spécifie deux valeurs possibles pour scope :

PTHREAD_SCOPE_SYSTEM
Le thread entre en compétition pour les ressources avec tous les autres threads de tous les processus du système qui se trouvent dans le même domaine d'allocation d'ordonnancement (un groupe d'un ou plusieurs processeurs). Les threads PTHREAD_SCOPE_SYSTEM sont ordonnancés les uns par rapport aux autres selon leur politique et leur priorité d'ordonnancement.
PTHREAD_SCOPE_PROCESS
Le thread entre en compétition pour les ressources avec tous les autres threads du même processus qui ont également été créés avec la portée de compétition PTHREAD_SCOPE_PROCESS. Les threads PTHREAD_SCOPE_PROCESS sont ordonnancés par rapport aux autres threads du processus selon leur politique et leur priorité d'ordonnance‐ ment. POSIX.1 laisse non spécifié comment ces threads entrent en com‐ pétition avec d'autres threads d'autres processus sur le système ou avec d'autres threads du même processus qui ont été créés avec la portée de compétition PTHREAD_SCOPE_SYSTEM.

POSIX.1 exige qu'une implémentation prenne en charge au moins l'une de ces portées de compétition. Linux prend en charge PTHREAD_SCOPE_SYSTEM, mais pas PTHREAD_SCOPE_PROCESS.

Sur les systèmes qui prennent en charge plusieurs portées de compétition, alors, pour que le paramètre défini par pthread_attr_setscope() ait un effet lors de l'appel à pthread_create(3), l'appelant doit utiliser pthread_attr_setinheritsched(3) pour définir l'attribut d'héritage de l'ordonnanceur de l'objet d'attributs attr à PTHREAD_EXPLICIT_SCHED.

La fonction pthread_attr_getscope() renvoie l'attribut de portée de compétition de l'objet d'attributs de thread référencé par attr dans le tampon pointé par scope.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0 ; en cas d'erreur, elles retournent un numéro d'erreur non nul.

ERREURS

pthread_attr_setscope() peut échouer avec les erreurs suivantes :

EINVAL
Une valeur invalide a été spécifiée dans scope.
ENOTSUP
scope a spécifié la valeur PTHREAD_SCOPE_PROCESS, qui n'est pas prise en charge sous Linux.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
pthread_attr_setscope (), pthread_attr_getscope () Sécurité des threads MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001.

NOTES

La portée de compétition PTHREAD_SCOPE_SYSTEM indique généralement qu'un thread utilisateur est directement lié à une seule entité de planification du noyau. C'est le cas sous Linux pour l'implémentation obsolète LinuxThreads et l'implémentation moderne NPTL, qui sont toutes deux des implémentations de threading 1:1.

POSIX.1 spécifie que la portée de compétition par défaut est définie par l'implémentation.
