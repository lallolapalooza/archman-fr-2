NOM

pt-table-usage - Analyse comment les requêtes utilisent les tables.

SYNOPSIS

Utilisation : pt-table-usage [OPTIONS] [FICHIERS]

pt-table-usage lit les requêtes à partir d'un journal et analyse comment elles utilisent les tables. Si aucun FICHIER n'est spécifié, il lit depuis la STDIN. Il imprime un rapport pour chaque requête.

RISQUES

Percona Toolkit est mature, éprouvé en conditions réelles et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Consulter les "BOGUES" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-table-usage lit les requêtes à partir d'un journal et analyse comment elles utilisent les tables. Le journal doit être au format du journal des requêtes lentes de MySQL.

L'utilisation des tables est plus qu'une simple indication des tables que la requête lit ou écrit. Elle indique également le flux de données : entrées et sorties de données. L'outil détermine le flux de données par les contextes dans lesquels les tables apparaissent. Une seule requête peut utiliser une table dans plusieurs contextes différents simultanément. La sortie de l'outil liste chaque contexte pour chaque table. Cette liste CONTEXTE-TABLE indique comment les données circulent entre les tables. La section "OUTPUT" liste les contextes possibles et décrit comment lire un rapport d'utilisation des tables.

L'outil analyse le flux de données jusqu'au niveau des colonnes individuelles, il est donc utile que les colonnes soient identifiées sans ambiguïté dans la requête. Si une requête utilise une seule table, alors toutes les colonnes doivent provenir de cette table, et il n'y a aucune difficulté. Mais si une requête utilise plusieurs tables et que les noms de colonnes ne sont pas qualifiés par le nom de la table, alors il est nécessaire d'utiliser "EXPLAIN EXTENDED", suivi de "SHOW WARNINGS", pour déterminer à quelles tables appartiennent les colonnes.

Si l'outil ne connaît pas la base de données par défaut de la requête, ce qui peut se produire lorsque la base de données n'est pas imprimée dans le journal, alors "EXPLAIN EXTENDED" peut échouer. Dans ce cas, vous pouvez spécifier une base de données par défaut avec "--database". Vous pouvez également utiliser l'option "--create-table-definitions" pour aider à résoudre les ambiguïtés.

SORTIE

L'outil imprime un rapport d'utilisation pour chaque table dans chaque requête, similaire à ce qui suit :

Query_id: 0x1CD27577D202A339.1
UPDATE t1
SELECT DUAL
JOIN t1
JOIN t2
WHERE t1
Query_id: 0x1CD27577D202A339.2
UPDATE t2
SELECT DUAL
JOIN t1
JOIN t2
WHERE t1

La première ligne contient l'ID de la requête, qui par défaut est le même que ceux affichés dans les rapports pt-query-digest. C'est une somme de contrôle MD5 de "l'empreinte" de la requête, qui est ce qui reste après avoir supprimé les littéraux, fusionné les espaces blancs et effectué une variété d'autres transformations. L'ID de la requête a deux parties séparées par un point : l'ID de la requête et le numéro de la table. Si vous souhaitez utiliser une valeur différente pour identifier la requête, vous pouvez spécifier l'option "--id-attribute".

L'exemple précédent montre deux paragraphes pour une seule requête, et non deux requêtes. Notez que l'ID de la requête est identique pour les deux, mais le numéro de la table diffère. Le numéro de la table s'incrémente de 1 pour chaque table que la requête met à jour. Seules les requêtes UPDATE multi-tables peuvent mettre à jour plusieurs tables avec une seule requête, le numéro de table est donc 1 pour tous les autres types de requêtes. (L'outil ne prend pas en charge les requêtes DELETE multi-tables.) L'exemple de sortie ci-dessus provient de cette requête :

UPDATE t1 AS a JOIN t2 AS b USING (id)
SET a.foo="bar", b.foo="bat"
WHERE a.id=1;

La clause "SET" indique que la requête met à jour deux tables : "a" alias "t1", et "b" alias "t2".

Après la première ligne, l'outil imprime un nombre variable de lignes CONTEXTE-TABLE. Les contextes possibles sont les suivants :

  • SELECT

    SELECT signifie que la requête récupère des données de la table pour l'une des deux raisons. La première est d'être retournée à l'utilisateur dans le cadre d'un ensemble de résultats. Seules les requêtes SELECT retournent des ensembles de résultats, le rapport affiche donc toujours un contexte SELECT pour les requêtes SELECT.

    Le deuxième cas est lorsque les données circulent vers une autre table dans le cadre d'un INSERT ou d'un UPDATE. Par exemple, la requête UPDATE dans l'exemple ci-dessus a l'utilisation :

    SELECT DUAL

    Ceci se réfère à :

    SET a.foo="bar", b.foo="bat"

    L'outil utilise DUAL pour toutes les valeurs qui ne proviennent pas d'une table, dans ce cas les valeurs littérales "bar" et "bat". Si cette clause "SET" était "SET a.foo=b.foo" à la place, alors l'utilisation complète serait :

    Query_id: 0x1CD27577D202A339.1
UPDATE t1
SELECT t2
JOIN t1
JOIN t2
WHERE t1

    La présence d'un contexte SELECT après un autre contexte, comme UPDATE ou INSERT, indique d'où l'UPDATE ou l'INSERT récupère ses données. L'exemple ci-dessus reflète une requête UPDATE qui met à jour des lignes dans la table "t1" avec des données de la table "t2".

  • Toute autre verbe

    Tout autre verbe, tel que INSERT, UPDATE, DELETE, etc., peut être un contexte. Ces verbes indiquent que la requête modifie les données d'une manière ou d'une autre. Si un contexte SELECT suit l'un de ces verbes, alors la requête lit les données de la table SELECT et les écrit dans cette table. Cela se produit, par exemple, avec INSERT..SELECT ou les requêtes UPDATE qui utilisent des valeurs provenant de tables au lieu de valeurs constantes.

    Ces types de requêtes ne sont pas pris en charge : SET, LOAD et DELETE multi-tables.

  • JOIN

    Le contexte JOIN liste les tables qui sont jointes, soit avec un JOIN explicite dans la clause FROM, soit implicitement dans la clause WHERE, par exemple "t1.id = t2.id".

  • WHERE

    Le contexte WHERE liste les tables qui sont utilisées dans la clause WHERE pour filtrer les résultats. Cela n'inclut pas les tables qui sont jointes implicitement dans la clause WHERE ; celles-ci sont listées comme contextes JOIN. Par exemple :

    WHERE t1.id > 100 AND t1.id < 200 AND t2.foo IS NOT NULL

    Résulte en :

    WHERE t1
WHERE t2

    L'outil ne liste que les tables distinctes ; c'est pourquoi la table "t1" n'est listée qu'une seule fois.

  • TLIST

    Le contexte TLIST liste les tables auxquelles la requête accède, mais qui n'apparaissent dans aucun autre contexte. Ces tables sont généralement un produit cartésien implicite. Par exemple, la requête "SELECT * FROM t1, t2" résulte en :

    Query_id: 0xBDDEB6EDA41897A8.1
SELECT t1
SELECT t2
TLIST t1
TLIST t2

    Tout d'abord, il y a deux contextes SELECT, car "SELECT *" sélectionne des lignes de toutes les tables ; "t1" et "t2" dans ce cas. Deuxièmement, les tables sont jointes implicitement, mais sans aucune condition de jointure, ce qui entraîne un produit cartésien comme indiqué par le contexte TLIST pour chacune.

STATUT DE SORTIE

pt-table-usage se termine avec 1 en cas d'erreur, ou 0 si aucune erreur.

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Reportez-vous à la "SYNOPSIS" et aux informations d'utilisation pour plus de détails.

--ask-pass
Demander un mot de passe lors de la connexion à MySQL.
--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, définit le mode binaire de Perl sur STDOUT à utf8, passe l'option mysql_enable_utf8 à DBD::mysql et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur définit le mode binaire sur STDOUT sans la couche utf8 et exécute SET NAMES après la connexion à MySQL.

--config
type : Tableau

Lire ceci, séparé par des virgules

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

liste de fichiers de configuration ; si spécifié, ce doit être la première option sur la ligne de commande.

--constant-data-value
type : chaîne ; défaut : DUAL

Table à imprimer comme source pour les données constantes (littéraux). Il s'agit de toutes les données non récupérées à partir de tables (ou de sous-requêtes, car les sous-requêtes ne sont pas prises en charge). Cela inclut les valeurs littérales telles que les chaînes de caractères ("foo") et les nombres (42), ou les fonctions telles que NOW(). Par exemple, dans la requête "INSERT INTO t (c) VALUES ('a')", la chaîne 'a' sont des données constantes, donc le rapport d'utilisation des tables est :

INSERT t
SELECT DUAL

La première ligne indique que la requête insère des données dans la table "t", et la deuxième ligne indique que les données insérées proviennent d'une valeur constante.

--[no]continue-on-error
défaut : oui

Continuer à travailler même en cas d'erreur.

--create-table-definitions
type : tableau

Lire les définitions de "CREATE TABLE" à partir de cette liste de fichiers séparés par des virgules. Si vous ne pouvez pas utiliser "--explain-extended" pour qualifier entièrement les noms de tables et de colonnes, vous pouvez enregistrer la sortie de "mysqldump --no-data" dans un ou plusieurs fichiers et spécifier ces fichiers avec cette option. L'outil analysera toutes les définitions "CREATE TABLE" des fichiers et utilisera ces informations pour qualifier les noms de tables et de colonnes. Si un nom de colonne apparaît dans plusieurs tables, ou si un nom de table apparaît dans plusieurs bases de données, les ambiguïtés ne pourront pas être résolues.

--daemonize
Faire un fork en arrière-plan et se détacher du shell. Systèmes d'exploitation POSIX uniquement.
--database
forme courte : -D ; type : chaîne

Base de données par défaut.

--defaults-file
forme courte : -F ; type : chaîne

Lire uniquement les options mysql à partir du fichier spécifié. Vous devez fournir un chemin absolu.

--explain-extended
type : DSN

Un serveur pour exécuter des requêtes EXPLAIN EXTENDED. Ceci peut être nécessaire pour résoudre les noms de colonnes et de tables ambigus (non qualifiés).

--filter
type : chaîne

Ignorer les événements pour lesquels ce code Perl ne renvoie pas vrai.

Cette option est une chaîne de code Perl ou un fichier contenant du code Perl qui est compilé en une sous-routine avec un argument : $event. Si la valeur donnée est un fichier lisible, alors pt-table-usage lit le fichier entier et utilise son contenu comme code.

Les filtres sont implémentés de la même manière que dans l'outil pt-query-digest, veuillez donc consulter sa documentation pour plus d'informations.

--help
Afficher l'aide et quitter.
--host
forme courte : -h ; type : chaîne

Se connecter à l'hôte.

--id-attribute
type : chaîne

Identifier chaque événement en utilisant cet attribut. Par défaut, il utilise un identifiant de requête, qui est un checksum MD5 de l'empreinte digitale de la requête.

--log
type : chaîne

Imprimer toute la sortie dans ce fichier lorsque le processus est daemonisé.

--password
forme courte : -p ; type : chaîne

Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

--pid
type : chaîne

Créer le fichier PID spécifié. L'outil ne démarrera pas si le fichier PID existe déjà et que le PID qu'il contient est différent du PID actuel. Cependant, si le fichier PID existe et que le PID qu'il contient n'est plus en cours d'exécution, l'outil écrasera le fichier PID avec le PID actuel. Le fichier PID est automatiquement supprimé lorsque l'outil se termine.

--port
forme courte : -P ; type : entier

Numéro de port à utiliser pour la connexion.

--progress
type : tableau ; défaut : time,30

Imprimer les rapports de progression sur STDERR. La valeur est une liste séparée par des virgules avec deux parties. La première partie peut être percentage, time ou iterations ; la deuxième partie spécifie la fréquence à laquelle une mise à jour doit être imprimée, en pourcentage, secondes ou nombre d'itérations.

--query
type : chaîne

Analyser la requête spécifiée au lieu de lire un fichier journal.

--read-timeout
type : temps ; défaut : 0

Attendre ce temps pour un événement de l'entrée ; 0 pour attendre éternellement.

Cette option définit le temps maximum d'attente d'un événement de l'entrée. Si un événement n'est pas reçu après le temps spécifié, l'outil arrête de lire l'entrée et imprime ses rapports.

Cette option nécessite le module Perl POSIX.

--run-time
type : temps

Combien de temps exécuter avant de quitter. Par défaut, l'outil s'exécute indéfiniment (vous pouvez l'interrompre avec CTRL-C).

--set-vars
type : Tableau

Définir les variables MySQL dans cette liste séparée par des virgules de paires "variable=valeur".

Par défaut, l'outil définit :

wait_timeout=10000

Les variables spécifiées sur la ligne de commande remplacent ces valeurs par défaut. Par exemple, spécifier "--set-vars wait_timeout=500" remplace la valeur par défaut de 10000.

L'outil imprime un avertissement et continue si une variable ne peut pas être définie.

--socket
forme courte : -S ; type : chaîne

Fichier socket à utiliser pour la connexion.

--user
forme courte : -u ; type : chaîne

Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

--version
Afficher la version et quitter.

OPTIONS DSN

Ces options DSN sont utilisées pour créer un DSN. Chaque option est donnée sous la forme "option=valeur". Les options sont sensibles à la casse, donc P et p ne sont pas la même option. Il ne doit pas y avoir d'espace avant ou après le "=" et si la valeur contient des espaces, elle doit être mise entre guillemets. Les options DSN sont séparées par des virgules. Voir la page man de percona-toolkit pour plus de détails.

  • A

    dsn: charset ; copy: yes

    Jeu de caractères par défaut.

  • D

    copy: no

    Base de données par défaut.

  • F

    dsn: mysql_read_default_file ; copy: no

    Lire uniquement les options par défaut à partir du fichier spécifié

  • h

    dsn: host ; copy: yes

    Se connecter à l'hôte.

  • p

    dsn: password ; copy: yes

    Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

  • P

    dsn: port ; copy: yes

    Numéro de port à utiliser pour la connexion.

  • S

    dsn: mysql_socket ; copy: no

    Fichier socket à utiliser pour la connexion.

  • u

    dsn: user ; copy: yes

    Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

  • s

    dsn: mysql_ssl ; copy: yes

    Créer une connexion SSL

ENVIRONNEMENT

La variable d'environnement "PTDEBUG" active la sortie de débogage détaillée sur STDERR. Pour activer le débogage et capturer toute la sortie dans un fichier, exécutez l'outil comme suit :

PTDEBUG=1 pt-table-usage ... > FICHIER 2>&1

Attention : la sortie de débogage est volumineuse et peut générer plusieurs mégaoctets de sortie.

ATTENTION

L'utilisation de <PTDEBUG> peut exposer des mots de passe. Lorsque le débogage est activé, tous les paramètres de la ligne de commande sont affichés dans la sortie.

EXIGENCES SYSTÈME

Vous avez besoin de Perl, DBI, DBD::mysql, et de certains packages de base qui devraient être installés dans toute version raisonnablement récente de Perl.
