NOM

pt-replica-restart - Surveille et redémarre la réplication MySQL après des erreurs.

SYNTAXE

Utilisation : pt-replica-restart [OPTIONS] [DSN]

pt-replica-restart surveille une ou plusieurs répliques de réplication MySQL pour les erreurs et tente de redémarrer la réplication si elle s'arrête.

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Examiner les "BUGS" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-replica-restart surveille une ou plusieurs répliques de réplication MySQL et tente de sauter les instructions qui provoquent des erreurs. Il interroge les répliques intelligemment avec un temps de sommeil variant exponentiellement. Vous pouvez spécifier les erreurs à ignorer et exécuter les répliques jusqu'à une certaine position du binlog.

Bien que cet outil puisse aider une réplique à dépasser les erreurs, vous ne devez pas vous y fier pour "réparer" la réplication. Si des erreurs de réplication se produisent fréquemment ou de manière inattendue, vous devez identifier et corriger la cause profonde.

SORTIE

pt-replica-restart imprime une ligne chaque fois qu'il constate que la réplique a une erreur. Par défaut, cette ligne est : un horodatage, des informations de connexion, relay_log_file, relay_log_pos et last_errno. Vous pouvez ajouter plus d'informations en utilisant l'option "--verbose". Vous pouvez supprimer toute sortie en utilisant l'option "--quiet".

SOMMEIL

pt-replica-restart dort intelligemment entre les interrogations de la réplique. Le temps de sommeil actuel varie.

  • Le temps de sommeil initial est donné par "--sleep".
  • S'il vérifie et trouve une erreur, il divise par deux le temps de sommeil précédent.
  • S'il ne trouve aucune erreur, il double le temps de sommeil précédent.
  • Le temps de sommeil est borné inférieurement par "--min-sleep" et supérieurement par "--max-sleep".
  • Immédiatement après avoir trouvé une erreur, pt-replica-restart suppose qu'une autre erreur est très susceptible de se produire ensuite, il dort donc le temps de sommeil actuel ou le temps de sommeil initial, le moindre des deux.

IDS TRANSACTION GLOBAUX

Depuis Percona Toolkit 2.2.8, pt-replica-restart prend en charge les identifiants de transaction globaux introduits dans MySQL 5.6.5. Il est important de garder à l'esprit que :

  • pt-replica-restart ne sautera pas les transactions lorsque plusieurs threads de réplication sont utilisés (replica_parallel_workers > 0). pt-replica-restart ne connaît pas l'événement GTID de la transaction échouée d'un thread de réplique spécifique.
  • Le comportement par défaut est de sauter la transaction suivante de la source de la réplique. Les écritures peuvent provenir de différents serveurs, chacun avec son propre UUID.

    Voir "--source-uuid".

STATUT DE SORTIE

Un statut de sortie de 0 (parfois aussi appelé valeur de retour ou code de retour) indique le succès. Toute autre valeur représente le statut de sortie du processus Perl lui-même, ou du dernier processus lancé qui s'est terminé s'il y avait plusieurs serveurs à surveiller.

COMPATIBILITÉ

pt-replica-restart devrait fonctionner sur de nombreuses versions de MySQL. La casse des nombreuses colonnes de sortie de SHOW REPLICA STATUS a changé au fil du temps, il les traite donc toutes en minuscules.

Démarre les répliques même en l'absence d'erreur. Avec cette option activée, pt-replica-restart ne vous permettra pas d'arrêter la réplique manuellement si vous le souhaitez !

--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. --[no]check-relay-log

Vérifie le dernier fichier de journal relais et la dernière position avant de vérifier les erreurs de réplication.

Par défaut, pt-replica-restart ne fera rien (il dormira simplement) si ni le fichier de journal relais ni la position du journal relais n'ont changé depuis la dernière vérification. Cela empêche les boucles infinies (c'est-à-dire le redémarrage de la même erreur dans le même fichier de journal relais à la même position du journal relais).

Pour certaines erreurs de réplication, cependant, cette vérification doit être désactivée en spécifiant "--no-check-relay-log". Ne le faites pas sauf si vous savez ce que vous faites !

Longueur maximale du message d'erreur à afficher. Lorsque "--verbose" est réglé suffisamment haut pour afficher l'erreur, cette option tronquera le texte de l'erreur à la longueur spécifiée. Ceci peut être utile pour éviter le retour à la ligne sur le terminal.

type : hash

Ne redémarre que cette liste d'erreurs séparées par des virgules. Fait en sorte que pt-replica-restart n'essaie de redémarrer que si le numéro d'erreur se trouve dans cette liste d'erreurs séparées par des virgules. S'il voit une erreur qui n'est pas dans la liste, il se terminera.

type : chaîne

Ne redémarre que les erreurs correspondant à ce motif. Une expression régulière Perl à laquelle le texte de l'erreur, le cas échéant, est mis en correspondance. Si le texte de l'erreur existe et correspond, pt-replica-restart tentera de redémarrer la réplique. S'il existe mais ne correspond pas, pt-replica-restart se terminera.

--recurse
type : entier ; par défaut : 0

Surveille les répliques du serveur spécifié, jusqu'au nombre spécifié de serveurs dans la hiérarchie. La profondeur par défaut de 0 signifie « surveiller uniquement la réplique spécifiée ».

pt-replica-restart examine "SHOW PROCESSLIST" et tente de déterminer quelles connexions proviennent de répliques, puis s'y connecte. Voir "--recursion-method".

La récursion fonctionne en trouvant toutes les répliques au démarrage du programme, puis en les surveillant. S'il y a plus d'une réplique, "pt-replica-restart" utilise fork() pour les surveiller.

Cela fonctionne également si vous avez configuré vos répliques pour qu'elles apparaissent dans "SHOW REPLICAS". La configuration minimale pour cela est le paramètre "report_host", mais il existe d'autres paramètres "report" pour le port, le nom d'utilisateur et le mot de passe.

--recursion-method
type : tableau ; par défaut : processlist,hosts

Méthode de récursion préférée utilisée pour trouver les répliques.

Les méthodes possibles sont :

METHOD       USES
===========  ==================
processlist  SHOW PROCESSLIST
hosts        SHOW REPLICAS (SHOW SLAVE HOSTS avant MySQL 8.1)
none         Ne pas trouver de répliques

La méthode processlist est préférée car SHOW REPLICAS n'est pas fiable. Cependant, la méthode hosts est requise si le serveur utilise un port non standard (pas 3306). Généralement, pt-replica-restart fait ce qu'il faut et trouve les répliques, mais vous pouvez spécifier une méthode préférée et elle sera utilisée en premier. Si elle ne trouve aucune réplique, les autres méthodes seront essayées.

--skip-count
type : entier ; par défaut : 1

Nombre d'instructions à ignorer lors du redémarrage de la réplique.

--source-uuid
type : chaîne

Lors de l'utilisation de GTID, une transaction vide doit être créée afin de l'ignorer. Si des écritures proviennent de différents nœuds dans l'arbre de réplication supérieur, il n'est pas possible de savoir quel événement de quel UUID ignorer.

Par défaut, les transactions de la source de la réplique ('Source_UUID' de "SHOW REPLICA STATUS") sont ignorées.

Par exemple, avec

source1 -> replica1 -> replica2

Lors de l'ignorance des événements sur replica2 qui ont été écrits sur source1, vous devez spécifier l'UUID de source1, sinon l'outil utilisera par défaut l'UUID de replica1.

Voir "GLOBAL TRANSACTION IDS".

--sleep
type : entier ; par défaut : 1

Secondes de sommeil initiales entre chaque vérification de la réplique.

Voir "SLEEP".

--socket
forme courte : -S ; type : chaîne

Fichier de socket à utiliser pour la connexion.

--stop
Arrête les instances en cours d'exécution en créant le fichier sentinelle.

Induit "pt-replica-restart" à créer le fichier sentinelle spécifié par "--sentinel". Cela devrait avoir pour effet d'arrêter toutes les instances en cours d'exécution qui surveillent le même fichier sentinelle. Si "--monitor" n'est pas spécifié, "pt-replica-restart" se terminera après la création du fichier. S'il est spécifié, "pt-replica-restart" attendra l'intervalle donné par "--max-sleep", puis supprimera le fichier et continuera à fonctionner.

Vous trouverez cela utile pour arrêter gracieusement les tâches cron si nécessaire, ou pour remplacer une instance en cours d'exécution par une autre. Par exemple, si vous souhaitez arrêter et redémarrer "pt-replica-restart" toutes les heures (juste pour vous assurer qu'il est redémarré chaque heure, en cas de crash du serveur ou d'un autre problème), vous pouvez utiliser une ligne "crontab" comme celle-ci :

0 * * * * pt-replica-restart --monitor --stop --sentinel /tmp/pt-replica-restartup

Le "--sentinel" non par défaut garantira que le travail "cron" horaire n'arrête que les instances précédemment démarrées avec les mêmes options (c'est-à-dire, du même travail "cron").

Voir également "--sentinel".

--until-master
type : chaîne

Cette option est obsolète et sera supprimée dans les futures versions. Utilisez "--until-source" à la place.

--until-source
type : chaîne

Exécute jusqu'à ce fichier binaire de log source et cette position. Démarre la réplique, et retente si elle échoue, jusqu'à ce qu'elle atteigne les coordonnées de réplication données. Les coordonnées sont le fichier log et la position sur la source, donnés par relay_source_log_file, exec_source_log_pos. L'argument doit être au format "fichier,position". Séparez le nom du fichier et la position par une seule virgule et aucun espace.

Cela provoquera également l'ajout d'une clause UNTIL à START REPLICA.

Après avoir atteint ce point, la réplique doit être arrêtée et pt-replica-restart se terminera.

--until-relay
type : chaîne

Exécute jusqu'à ce fichier de log relais et cette position. Similaire à "--until-source", mais dans les logs relais de la réplique à la place. Les coordonnées sont données par relay_log_file, relay_log_pos.

--user
forme courte : -u ; type : chaîne

Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

--verbose
forme courte : -v ; cumulatif : oui ; par défaut : 1

Ajoute plus d'informations à la sortie. Ce drapeau peut être spécifié plusieurs fois. par ex. -v -v OU -vv. Par défaut (aucun drapeau verbose) l'outil affiche les informations de connexion, un horodatage, relay_log_file, relay_log_pos, et last_errno. Un drapeau (-v) ajoute last_error. Voir également "--error-length". Deux drapeaux (-vv) impriment le temps de sommeil actuel à chaque fois que pt-replica-restart dort. Pour supprimer toute sortie, utilisez l'option "--quiet".

NAME

pt-slave-restart — Automatically restart MySQL replication slaves

SYNOPSIS

perl pt-slave-restart --host <host> [OPTIONS]

  perl pt-slave-restart --config=my.cnf --user=root --password=... [OPTIONS]
  perl pt-slave-restart --dsn=D:... --dsn=h:... [OPTIONS]

RISKS

This tool automatically restarts replication slaves. It may restart slaves that are already running, which is harmless but wastes resources. It may restart slaves that are already broken, so use it only when you are certain that the slave needs to be restarted.

This tool is designed to avoid restarting slaves that are already stopped. It is designed to avoid restarting slaves that are broken in ways it doesn’t understand, such as when the slave is already broken. Always test this tool thoroughly in a non-production environment before using it on production servers.

Do not run this tool on slaves that are already being managed by another tool, such as Percona Management. If you do, the tools might interfere with each other, with potentially disastrous results.

DESCRIPTION

Replication slaves are fragile. Sometimes they stop replicating and will not restart without intervention. This tool monitors replication slaves and restarts them automatically when they stop replicating.

This tool connects to MySQL and executes the following actions:

  • It checks if the slave is running. If not, it restarts it.
  • It checks if the slave is replicating. If not, it restarts it.
  • It checks if the slave is lagging. If not, it restarts it.
  • It checks if the slave is broken. If not, it restarts it.

This tool is designed to be run as a cron job or a daemon. It continuously monitors replication slaves and restarts them when necessary.

OUTPUT

The tool prints a status message to STDOUT for each slave it monitors. The status message includes the slave's host, user, and whether it is running, replicating, lagging, or broken. If the tool restarts a slave, it prints a message to STDERR indicating that it is restarting the slave.

The tool also prints a summary message to STDOUT at the end of each pass, indicating the total number of slaves monitored, the number of slaves restarted, and the number of slaves that are still broken.

The tool also supports Percona's Version Check feature. This feature periodically checks Percona's Version Check database server for updates or known problems with Percona Toolkit. Any updates or known problems are printed to STDOUT before the tool's normal output.

Version
Checks for version updates.
MySQL
Checks for known MySQL problems.

A secure connection to Percona’s Version Check database server is done to perform these checks. Each request is logged by the server, including software version numbers and unique ID of the checked system. The ID is generated by the Percona Toolkit installation script or when the Version Check database call is done for the first time.

Any updates or known problems are printed to STDOUT before the tool's normal output. This feature should never interfere with the normal operation of the tool.

For more information, visit https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

SLEEP

This option specifies the time in seconds that the tool should sleep between checks. The default is 60 seconds.

GLOBAL TRANSACTION IDS

If this option is enabled, the tool will check for GTID inconsistencies. This is a more advanced check and should only be enabled if you are using GTID replication.

EXIT STATUS

This tool exits with a status of 0 if all slaves are running and replicating correctly. It exits with a status of 1 if any slave is stopped or not replicating. It exits with a status of 2 if there was an error.

COMPATIBILITY

This tool is compatible with MySQL 5.0 and later.

It may also be compatible with other database systems that support replication, but this has not been tested.

ENVIRONMENT

Be careful: debugging output is voluminous and can generate several megabytes of output.

ATTENTION

Using <PTDEBUG> might expose passwords. When debug is enabled, all command line parameters are shown in the output.
