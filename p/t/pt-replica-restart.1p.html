NOM

pt-replica-restart - Surveille et redémarre la réplication MySQL après les erreurs.

SYNTAXE

Utilisation : pt-replica-restart [OPTIONS] [DSN]

pt-replica-restart surveille une ou plusieurs répliques de réplication MySQL pour détecter les erreurs et tente de redémarrer la réplication si elle s'arrête.

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Vérifier les "BOGUES" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-replica-restart surveille une ou plusieurs répliques de réplication MySQL et tente de sauter les instructions qui provoquent des erreurs. Il interroge les répliques intelligemment avec un temps de pause variant exponentiellement. Vous pouvez spécifier les erreurs à ignorer et exécuter les répliques jusqu'à une certaine position du binlog.

Bien que cet outil puisse aider une réplique à dépasser les erreurs, vous ne devriez pas vous fier à lui pour "réparer" la réplication. Si des erreurs de réplication surviennent fréquemment ou de manière inattendue, vous devriez identifier et corriger la cause profonde.

SORTIE

pt-replica-restart imprime une ligne chaque fois qu'il constate une erreur dans la réplique. Par défaut, cette ligne contient : un horodatage, les informations de connexion, le fichier relay_log, la position relay_log, et last_errno. Vous pouvez ajouter plus d'informations en utilisant l'option "--verbose". Vous pouvez supprimer toute sortie en utilisant l'option "--quiet".

PAUSE

pt-replica-restart fait une pause intelligente entre les interrogations de la réplique. Le temps de pause actuel varie.

  • Le temps de pause initial est donné par "--sleep".
  • S'il vérifie et trouve une erreur, il divise par deux le temps de pause précédent.
  • S'il ne trouve pas d'erreur, il double le temps de pause précédent.
  • Le temps de pause est borné inférieurement par "--min-sleep" et supérieurement par "--max-sleep".
  • Immédiatement après avoir trouvé une erreur, pt-replica-restart suppose qu'une autre erreur est très susceptible de se produire ensuite, il fait donc une pause du temps de pause actuel ou du temps de pause initial, le plus petit des deux.

IDENTIFIANTS DE TRANSACTIONS GLOBALES

Depuis Percona Toolkit 2.2.8, pt-replica-restart prend en charge les identifiants de transactions globales introduits dans MySQL 5.6.5. Il est important de garder à l'esprit que :

  • pt-replica-restart ne sautera pas les transactions lorsque plusieurs threads de réplication sont utilisés (replica_parallel_workers > 0). pt-replica-restart ne connaît pas l'événement GTID de la transaction échouée d'un thread de réplique spécifique.
  • Le comportement par défaut est de sauter la prochaine transaction de la source de la réplique. Les écritures peuvent provenir de différents serveurs, chacun avec son propre UUID.

    Voir "--source-uuid".

STATUT DE FIN

Un statut de fin de 0 (parfois aussi appelé valeur de retour ou code de retour) indique le succès. Toute autre valeur représente le statut de fin du processus Perl lui-même, ou du dernier processus qui s'est terminé s'il y avait plusieurs serveurs à surveiller.

COMPATIBILITÉ

pt-replica-restart devrait fonctionner sur de nombreuses versions de MySQL. La casse de nombreuses colonnes de sortie de SHOW REPLICA STATUS a changé au fil du temps, il les traite donc toutes en minuscules.

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Consultez la "SYNTAXE" et les informations d'utilisation pour plus de détails.

--toujours
Démarre les répliques même en l'absence d'erreur. Avec cette option activée, pt-replica-restart ne vous permettra pas d'arrêter manuellement la réplique si vous le souhaitez !
--demander-mot-de-passe
Demande un mot de passe lors de la connexion à MySQL.
--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, définit le mode binaire de Perl sur STDOUT en utf8, passe l'option mysql_enable_utf8 à DBD::mysql et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur définit le mode binaire sur STDOUT sans la couche utf8 et exécute SET NAMES après la connexion à MySQL.

--[no]verifier-journal-relai
par défaut : oui

Vérifie le dernier fichier de journal de relais et la position avant de vérifier les erreurs de réplication.

Par défaut, pt-replica-restart ne fera rien (il se contentera de dormir) si ni le fichier de journal de relais ni la position du journal de relais n'ont changé depuis la dernière vérification. Cela évite les boucles infinies (c'est-à-dire le redémarrage de la même erreur dans le même fichier de journal de relais à la même position du journal de relais).

Pour certaines erreurs de réplication, cependant, cette vérification doit être désactivée en spécifiant "--no-verifier-journal-relai". Ne le faites pas à moins de savoir ce que vous faites !

--config
type : Tableau

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, cela doit être la première option sur la ligne de commande.

--daemonize
Créer un processus fils et le détacher du terminal. Systèmes d'exploitation POSIX uniquement.
--database
forme courte : -D ; type : chaîne

Base de données à utiliser.

--fichier-parametres
forme courte : -F ; type : chaîne

Lire uniquement les options mysql à partir du fichier donné. Vous devez fournir un chemin absolu.

--longueur-erreur
type : entier

Longueur maximale du message d'erreur à imprimer. Lorsque "--verbose" est défini suffisamment haut pour imprimer l'erreur, cette option tronquera le texte de l'erreur à la longueur spécifiée. Cela peut être utile pour éviter le retour à la ligne dans le terminal.

--numeros-erreur
type : hash

Ne redémarre que cette liste d'erreurs séparées par des virgules. Permet à pt-replica-restart de tenter de redémarrer uniquement si le numéro d'erreur figure dans cette liste d'erreurs séparées par des virgules. S'il rencontre une erreur qui n'est pas dans la liste, il s'arrêtera.

Le numéro d'erreur se trouve dans la colonne "last_errno" de "SHOW REPLICA STATUS".

--texte-erreur
type : chaîne

Ne redémarre que les erreurs correspondant à ce modèle. Une expression régulière Perl contre laquelle le texte de l'erreur, le cas échéant, est comparé. Si le texte de l'erreur existe et correspond, pt-replica-restart tentera de redémarrer la réplique. S'il existe mais ne correspond pas, pt-replica-restart s'arrêtera.

Le texte de l'erreur se trouve dans la colonne "last_error" de "SHOW REPLICA STATUS".

--aide
Affiche l'aide et quitte.
--hote
forme courte : -h ; type : chaîne

Se connecter à l'hôte.

--journal
type : chaîne

Imprimer toute la sortie dans ce fichier lorsqu'il est exécuté en mode démon.

--uuid-maitre
type : chaîne

Cette option est dépréciée et sera supprimée dans les futures versions. Utilisez "--utilisateur-source" à la place.

--max-pause
type : flottant ; par défaut : 64

Temps de pause maximal en secondes.

C'est le temps maximum que pt-replica-restart attendra avant de réinterroger la réplique. C'est aussi le temps que pt-replica-restart attendra que toutes les autres instances en cours d'exécution s'arrêtent si à la fois "--stop"

Voir « SLEEP ».

--min-sleep
type: float ; valeur par défaut : 0.015625

Le temps minimum que pt-replica-restart va attendre avant de sonder à nouveau la réplique. Voir « SLEEP ».

--monitor
Permet de surveiller la réplique (par défaut). Sauf si vous spécifiez explicitement « --monitor », « --stop » le désactivera.
--password
forme courte : -p ; type : string

Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : « exam\,ple »

--pid
type : string

Crée le fichier PID spécifié. L'outil ne démarrera pas si le fichier PID existe déjà et que le PID qu'il contient est différent du PID actuel. Cependant, si le fichier PID existe et que le PID qu'il contient n'est plus en cours d'exécution, l'outil écrasera le fichier PID avec le PID actuel. Le fichier PID est supprimé automatiquement lorsque l'outil se termine.

--port
forme courte : -P ; type : int

Numéro de port à utiliser pour la connexion.

--quiet
forme courte : -q

Supprime la sortie normale (désactive « --verbose »).

--recurse
type : int ; valeur par défaut : 0

Surveille les répliques du serveur spécifié, jusqu'au nombre spécifié de serveurs en profondeur dans la hiérarchie. La profondeur par défaut de 0 signifie « surveiller uniquement la réplique spécifiée ».

pt-replica-restart examine « SHOW PROCESSLIST » et essaie de déterminer quelles connexions proviennent des répliques, puis s'y connecte. Voir « --recursion-method ».

La récursion fonctionne en trouvant toutes les répliques au démarrage du programme, puis en les surveillant. S'il y a plus d'une réplique, « pt-replica-restart » utilise fork() pour les surveiller.

Cela fonctionne également si vous avez configuré vos répliques pour qu'elles apparaissent dans « SHOW REPLICAS ». La configuration minimale pour cela est le paramètre « report_host », mais il existe d'autres paramètres « report » pour le port, le nom d'utilisateur et le mot de passe.

--recursion-method
type : array ; valeur par défaut : processlist,hosts

Méthode de récursion préférée utilisée pour trouver les répliques.

Méthodes possibles :

MÉTHODE       UTILISE
===========  ==================
processlist  SHOW PROCESSLIST
hosts        SHOW REPLICAS (SHOW SLAVE HOSTS avant MySQL 8.1)
none         Ne pas trouver les répliques

La méthode processlist est préférée car SHOW REPLICAS n'est pas fiable. Cependant, la méthode hosts est requise si le serveur utilise un port non standard (pas 3306). Normalement, pt-replica-restart fait ce qu'il faut et trouve les répliques, mais vous pouvez donner une méthode préférée et elle sera utilisée en premier. Si elle ne trouve aucune réplique, les autres méthodes seront essayées.

--run-time
type : time

Temps d'exécution avant de quitter. Fait en sorte que pt-replica-restart s'arrête une fois le temps spécifié écoulé. Suffixe optionnel : s=secondes, m=minutes, h=heures, d=jours ; si aucun suffixe, s est utilisé.

--sentinel
type : string ; valeur par défaut : /tmp/pt-replica-restart-sentinel

Quitte si ce fichier existe.

--slave-user
type : string

Cette option est dépréciée et sera supprimée dans les futures versions. Utilisez « --replica-user » à la place.

--slave-password
type : string

Cette option est dépréciée et sera supprimée dans les futures versions. Utilisez « --replica-password » à la place.

--replica-user
type : string

Définit l'utilisateur à utiliser pour se connecter aux répliques. Ce paramètre vous permet d'avoir un utilisateur différent avec moins de privilèges sur les répliques, mais cet utilisateur doit exister sur toutes les répliques.

--replica-password
type : string

Définit le mot de passe à utiliser pour se connecter aux répliques. Il peut être utilisé avec --replica-user et le mot de passe de l'utilisateur doit être le même sur toutes les répliques.

--set-vars
type : Array

Définit les variables MySQL dans cette liste séparée par des virgules de paires « variable=valeur ».

Par défaut, l'outil définit :

wait_timeout=10000

Les variables spécifiées en ligne de commande remplacent ces valeurs par défaut. Par exemple, spécifier « --set-vars wait_timeout=500 » remplace la valeur par défaut de 10000.

L'outil affiche un avertissement et continue si une variable ne peut pas être définie.

--skip-count
type : int ; valeur par défaut : 1

Nombre d'instructions à ignorer lors du redémarrage de la réplique.

--source-uuid
type : string

Lors de l'utilisation de GTID, une transaction vide doit être créée afin de l'ignorer. Si des écritures proviennent de différents nœuds dans l'arbre de réplication au-dessus, il n'est pas possible de savoir quel événement de quel UUID ignorer.

Par défaut, les transactions provenant de la source de la réplique ( « Source_UUID » de « SHOW REPLICA STATUS ») sont ignorées.

Par exemple, avec

source1 -> replica1 -> replica2

Lors de l'ignorance des événements sur replica2 qui ont été écrits sur source1, vous devez spécifier l'UUID de source1, sinon l'outil utilisera l'UUID de replica1 par défaut.

Voir « GLOBAL TRANSACTION IDS ».

--sleep
type : int ; valeur par défaut : 1

Secondes de veille initiales entre chaque vérification de la réplique.

Voir « SLEEP ».

--socket
forme courte : -S ; type : string

Fichier socket à utiliser pour la connexion.

--stop
Arrête les instances en cours d'exécution en créant le fichier sentinelle.

Fait en sorte que « pt-replica-restart » crée le fichier sentinelle spécifié par « --sentinel ». Cela devrait avoir pour effet d'arrêter toutes les instances en cours qui surveillent le même fichier sentinelle. Si « --monitor » n'est pas spécifié, « pt-replica-restart » se terminera après avoir créé le fichier. S'il est spécifié, « pt-replica-restart » attendra l'intervalle donné par « --max-sleep », puis supprimera le fichier et continuera à fonctionner.

Vous pourriez trouver cela utile pour arrêter gracieusement les tâches cron si nécessaire, ou pour remplacer une instance en cours d'exécution par une autre. Par exemple, si vous souhaitez arrêter et redémarrer « pt-replica-restart » toutes les heures (juste pour vous assurer qu'il est redémarré toutes les heures, en cas de crash du serveur ou d'un autre problème), vous pourriez utiliser une ligne « crontab » comme celle-ci :

0 * * * * pt-replica-restart --monitor --stop --sentinel /tmp/pt-replica-restartup

Le « --sentinel » non par défaut s'assurera que le travail « cron » horaire arrête uniquement les instances précédemment démarrées avec les mêmes options (c'est-à-dire, à partir du même travail « cron »).

Voir également « --sentinel ».

--until-master
type : string

Cette option est dépréciée et sera supprimée dans les futures versions. Utilisez « --until-source » à la place.

--until-source
type : string

Exécute jusqu'à ce fichier de journal binaire de source et cette position. Démarre la réplique, et retente si elle échoue, jusqu'à ce qu'elle atteigne les coordonnées de réplication données. Les coordonnées sont le fichier journal et la position sur la source, donnés par relay_source_log_file, exec_source_log_pos. L'argument doit être au format « file,pos ». Séparez le nom de fichier et la position par une seule virgule et aucun espace.

Cela entraînera également l'ajout d'une clause UNTIL à START REPLICA.

Après avoir atteint ce point, la réplique doit être arrêtée et pt-replica-restart se terminera.

--until-relay
type : string

Exécute jusqu'à ce fichier de journal relais et cette position. Comme « --until-source », mais dans les journaux relais de la réplique à la place. Les coordonnées sont données par relay_log_file, relay_log_pos.

--user
forme courte : -u ; type : string

Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

--verbose
forme courte : -v ; cumulatif : oui ; valeur par défaut : 1

Ajoute plus d'informations à la sortie. Ce drapeau peut être spécifié plusieurs fois. par exemple -v -v ou -vv. Par défaut (aucun drapeau verbose), l'outil affiche les informations de connexion, un horodatage, relay_log_file, relay_log_pos, et last_errno. Un drapeau (-v) ajoute last_error. Voir également « --error-length ». Deux drapeaux (-vv) affichent le temps de veille actuel chaque fois que pt-replica-restart attend. Pour supprimer toute sortie, utilisez l'option « --quiet ».

--version
Affiche la version et quitte.
--[no]version-check
valeur par défaut : yes

Vérifie la dernière version de Percona Toolkit, MySQL et d'autres programmes.

Il s'agit d'une fonctionnalité standard de « vérifier les mises à jour automatiquement », avec deux fonctionnalités supplémentaires. Premièrement, l'outil vérifie sa propre version ainsi que les versions des logiciels suivants : système d'exploitation, Percona Monitoring and Management (PMM), MySQL, pilote MySQL pour Perl (DBD::mysql) et Percona Toolkit. Deuxièmement, il vérifie pour

et met en garde contre les versions présentant des problèmes connus. Par exemple, MySQL 5.5.25 avait un bug critique et a été réédité sous la version 5.5.25a.

Une connexion sécurisée au serveur de base de données Version Check de Percona est établie pour effectuer ces vérifications. Chaque requête est enregistrée par le serveur, y compris les numéros de version des logiciels et l'ID unique du système vérifié. L'ID est généré par le script d'installation de Percona Toolkit ou lorsque l'appel à la base de données Version Check est effectué pour la première fois.

Toutes les mises à jour ou les problèmes connus sont imprimés sur STDOUT avant la sortie normale de l'outil. Cette fonctionnalité ne doit jamais interférer avec le fonctionnement normal de l'outil.

Pour plus d'informations, visitez https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

Affiche la version et quitte.

OPTIONS DSN

Ces options DSN sont utilisées pour créer un DSN. Chaque option est donnée sous la forme "option=valeur". Les options sont sensibles à la casse, donc P et p ne sont pas la même option. Il ne doit pas y avoir d'espace avant ou après le signe "=" et si la valeur contient des espaces, elle doit être mise entre guillemets. Les options DSN sont séparées par des virgules. Voir la page man de percona-toolkit pour tous les détails.

  • A

    dsn: charset; copy: yes

    Jeu de caractères par défaut.

  • D

    dsn: database; copy: yes

    Base de données par défaut.

  • F

    dsn: mysql_read_default_file; copy: yes

    Ne lire les options par défaut qu'à partir du fichier donné.

  • h

    dsn: host; copy: yes

    Se connecter à l'hôte.

  • p

    dsn: password; copy: yes

    Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

  • P

    dsn: port; copy: yes

    Numéro de port à utiliser pour la connexion.

  • S

    dsn: mysql_socket; copy: yes

    Fichier socket à utiliser pour la connexion.

  • u

    dsn: user; copy: yes

    Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

  • s

    dsn: mysql_ssl; copy: yes

    Établir une connexion SSL.

ENVIRONNEMENT

La variable d'environnement "PTDEBUG" active la sortie de débogage détaillée sur STDERR. Pour activer le débogage et capturer toute la sortie dans un fichier, exécutez l'outil comme suit :

PTDEBUG=1 pt-replica-restart ... > FICHIER 2>&1

Attention : la sortie de débogage est volumineuse et peut générer plusieurs mégaoctets de données.

ATTENTION

L'utilisation de <PTDEBUG> peut exposer les mots de passe. Lorsque le débogage est activé, tous les paramètres de la ligne de commande sont affichés dans la sortie.
