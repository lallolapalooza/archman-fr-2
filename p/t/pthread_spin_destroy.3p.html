PTHREAD_SPIN_DESTROY(3P) Manuel du programmeur POSIX PTHREAD_SPIN_DESTROY(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_spin_destroy, pthread_spin_init — détruit ou initialise un objet de verrouillage par rotation

SYNOPSIS

#include <pthread.h>
int pthread_spin_destroy(pthread_spinlock_t *lock);
int pthread_spin_init(pthread_spinlock_t *lock, int pshared);

DESCRIPTION

La fonction pthread_spin_destroy() détruit le verrou par rotation référencé par lock et libère toutes les ressources utilisées par le verrou. L'effet d'une utilisation ultérieure du verrou est indéfini jusqu'à ce que le verrou soit réinitialisé par un autre appel à pthread_spin_init(). Les résultats sont indéfinis si pthread_spin_destroy() est appelé lorsqu'un thread détient le verrou, ou si cette fonction est appelée avec un verrou par rotation de thread non initialisé.

La fonction pthread_spin_init() alloue toutes les ressources nécessaires pour utiliser le verrou par rotation référencé par lock et initialise le verrou à un état déverrouillé.

Si l'option de synchronisation partagée entre processus de threads est supportée et que la valeur de pshared est PTHREAD_PROCESS_SHARED, l'implémentation doit permettre que le verrou par rotation soit manipulé par tout thread ayant accès à la mémoire où le verrou par rotation est alloué, même s'il est alloué dans une mémoire partagée par plusieurs processus.

Voir Section 2.9.9, Copies d'objets de synchronisation et mappings alternatifs pour des exigences supplémentaires.

Les résultats sont indéfinis si pthread_spin_init() est appelé en spécifiant un verrou par rotation déjà initialisé. Les résultats sont indéfinis si un verrou par rotation est utilisé sans avoir été préalablement initialisé.

Si la fonction pthread_spin_init() échoue, le verrou n'est pas initialisé et le contenu de lock est indéfini.

Seul l'objet référencé par lock peut être utilisé pour effectuer la synchronisation.

Le résultat de la référence à des copies de cet objet dans les appels à pthread_spin_destroy(), pthread_spin_lock(), pthread_spin_trylock(), ou pthread_spin_unlock() est indéfini.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_spin_init() échoue si :

EAGAIN
Le système manque des ressources nécessaires pour initialiser un autre verrou par rotation.
ENOMEM
Il n'y a pas assez de mémoire pour initialiser le verrou.

Ces fonctions ne retournent pas de code d'erreur [EINTR].

RATIONALE

Si une implémentation détecte que la valeur spécifiée par l'argument lock à pthread_spin_destroy() ne fait pas référence à un objet de verrou par rotation initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].

Si une implémentation détecte que la valeur spécifiée par l'argument lock à pthread_spin_destroy() ou pthread_spin_init() fait référence à un objet de verrou par rotation verrouillé, ou détecte que la valeur spécifiée par l'argument lock à pthread_spin_init() fait référence à un objet de verrou par rotation déjà initialisé, il est recommandé que la fonction échoue et signale une erreur [EBUSY].
