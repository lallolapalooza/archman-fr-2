pthread_exit(3) Manuel des fonctions de bibliothèque pthread_exit(3)

NOM

pthread_exit - terminer le thread appelant

BIBLIOTHÈQUE

Bibliothèque POSIX threads (libpthread, -lpthread)

SYNTAXE

#include <pthread.h>
[[noreturn]] void pthread_exit(void *retval);

DESCRIPTION

La fonction pthread_exit() termine le thread appelant et retourne une valeur via retval qui, si le thread est joinable, sera disponible pour un autre thread du même processus qui appellera pthread_join(3).

Tous les gestionnaires de nettoyage établis par pthread_cleanup_push(3) qui n'ont pas encore été dépilés, sont dépilés (dans l'ordre inverse de leur empilement) et exécutés. Si le thread possède des données spécifiques au thread, alors, après l'exécution des gestionnaires de nettoyage, les fonctions destructrices correspondantes sont appelées, dans un ordre non spécifié.

Lorsqu'un thread se termine, les ressources partagées par le processus (par exemple, mutex, variables de condition, sémaphores et descripteurs de fichiers) ne sont pas libérées, et les fonctions enregistrées avec atexit(3) ne sont pas appelées.

Après la terminaison du dernier thread d'un processus, le processus se termine comme s'il avait appelé exit(3) avec un code de sortie de zéro ; ainsi, les ressources partagées par le processus sont libérées et les fonctions enregistrées avec atexit(3) sont appelées.

VALEUR DE RETOUR

Cette fonction ne retourne pas à l'appelant.

ERREURS

Cette fonction réussit toujours.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
pthread_exit () Sécurité des threads MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001.

NOTES

Effectuer un retour à partir de la fonction de démarrage de tout thread autre que le thread principal entraîne un appel implicite à pthread_exit(), en utilisant la valeur de retour de la fonction comme statut de sortie du thread.

Pour permettre à d'autres threads de continuer leur exécution, le thread principal doit se terminer en appelant pthread_exit() plutôt que exit(3).

La valeur pointée par retval ne doit pas être située sur la pile du thread appelant, car le contenu de cette pile est indéfini après la terminaison du thread.

BOGUES

Actuellement, il existe des limitations dans la logique d'implémentation du noyau pour l'attente (wait(2)) sur un groupe de threads arrêté avec un leader de groupe de threads mort. Cela peut se manifester par des problèmes tels qu'un terminal bloqué si un signal d'arrêt est envoyé à un processus de premier plan dont le leader de groupe de threads a déjà appelé pthread_exit().

VOIR AUSSI

pthread_create(3), pthread_join(3), pthreads(7)
