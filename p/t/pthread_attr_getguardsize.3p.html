PTHREAD_ATTR_GETGUARDSIZE(3P) Manuel du programmeur POSIX PTHREAD_ATTR_GETGUARDSIZE(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_attr_getguardsize, pthread_attr_setguardsize — obtenir et définir l'attribut guardsize du thread

SYNOPIS

#include <pthread.h>
int pthread_attr_getguardsize(const pthread_attr_t *restrict attr,
    size_t *restrict guardsize);
int pthread_attr_setguardsize(pthread_attr_t *attr,
    size_t guardsize);

DESCRIPTION

La fonction pthread_attr_getguardsize() récupère l'attribut guardsize dans l'objet attr. Cet attribut est retourné dans le paramètre guardsize.

La fonction pthread_attr_setguardsize() définit l'attribut guardsize dans l'objet attr. La nouvelle valeur de cet attribut est obtenue à partir du paramètre guardsize. Si guardsize est zéro, aucune zone de garde ne sera fournie pour les threads créés avec attr. Si guardsize est supérieur à zéro, une zone de garde d'au moins guardsize octets sera fournie pour chaque thread créé avec attr.

L'attribut guardsize contrôle la taille de la zone de garde pour la pile du thread créé. L'attribut guardsize offre une protection contre le dépassement du pointeur de pile. Si la pile d'un thread est créée avec une protection de garde, l'implémentation alloue de la mémoire supplémentaire à l'extrémité de débordement de la pile comme tampon contre le dépassement de pile du pointeur de pile. Si une application déborde dans ce tampon, une erreur se produit (possiblement un signal SIGSEGV délivré au thread).

Une implémentation conforme peut arrondir la valeur contenue dans guardsize à un multiple de la variable système configurable {PAGESIZE} (voir <sys/mman.h>). Si une implémentation arrondit la valeur de guardsize à un multiple de {PAGESIZE}, un appel à pthread_attr_getguardsize() spécifiant attr stockera dans le paramètre guardsize la taille de garde spécifiée par l'appel précédent à la fonction pthread_attr_setguardsize().

La valeur par défaut de l'attribut guardsize est définie par l'implémentation.

Si l'attribut stackaddr a été défini (c'est-à-dire que l'appelant alloue et gère ses propres piles de threads), l'attribut guardsize sera ignoré et aucune protection ne sera fournie par l'implémentation. Il incombe à l'application de gérer le dépassement de pile ainsi que l'allocation et la gestion de la pile dans ce cas.

Le comportement est indéfini si la valeur spécifiée par l'argument attr à pthread_attr_getguardsize() ou pthread_attr_setguardsize() ne fait pas référence à un objet d'attributs de thread initialisé.

VALEUR DE RETOUR

En cas de succès, les fonctions pthread_attr_getguardsize() et pthread_attr_setguardsize() retourneront zéro ; sinon, un numéro d'erreur sera retourné pour indiquer l'erreur.

ERREURS

Ces fonctions échoueront si :

EINVAL
Le paramètre guardsize est invalide.

Ces fonctions ne retourneront pas le code d'erreur [EINTR].

Les sections suivantes sont informatives.

EXEMPLES

Récupération de l'attribut guardsize

Cet exemple montre comment obtenir l'attribut guardsize d'un objet d'attributs de thread.

#include <pthread.h>
pthread_attr_t thread_attr;
size_t  guardsize;
int     rc;
/* code initialisant thread_attr */
...
rc = pthread_attr_getguardsize (&thread_attr, &guardsize);
if (rc != 0)  {
    /* gérer l'erreur */
    ...
}
else {
    if (guardsize > 0) {
    /* une zone de garde d'au moins guardsize octets est fournie */
    ...
    }
    else {
    /* aucune zone de garde fournie */
    ...
    }
}

USAGE APPLICATIF

Aucun.

RATIONALE

L'attribut guardsize est fourni à l'application pour deux raisons :

1.
La protection contre les dépassements peut entraîner un gaspillage de ressources système. Une application qui crée un grand nombre de threads, et qui sait que ses threads ne dépassent jamais leur pile, peut économiser des ressources système en désactivant les zones de garde.
2.
Lorsque les threads allouent de grandes structures de données sur la pile, de grandes zones de garde peuvent être nécessaires pour détecter le dépassement de pile.

La taille par défaut de la zone de garde est laissée à la discrétion de l'implémentation, car sur les systèmes prenant en charge des tailles de page très grandes, le surcoût peut être important si au moins une page de garde est requise par défaut.

Si une implémentation détecte que la valeur spécifiée par l'argument attr à pthread_attr_getguardsize() ou pthread_attr_setguardsize() ne fait pas référence à un objet d'attributs de thread initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].
