NOM

pt-slave-delay - Faire en sorte qu'un serveur esclave MySQL prenne du retard par rapport à son maître.

Cet outil est déprécié et sera supprimé dans les futures versions. Il ne prend pas en charge MySQL 8.1 ou plus récent.

Utilisez la réplication retardée intégrée à la place : https://dev.mysql.com/doc/refman/en/replication-delayed.html

SYNTAXE

Usage: pt-slave-delay [OPTIONS] SLAVE_DSN [MASTER_DSN]

pt-slave-delay démarre et arrête un serveur esclave selon les besoins pour le faire prendre du retard par rapport au maître. SLAVE_DSN et MASTER_DSN utilisent la syntaxe DSN, et les valeurs sont copiées de SLAVE_DSN à MASTER_DSN si elles sont omises.

Pour maintenir le serveur esclave avec un retard d'une minute par rapport à son maître pendant dix minutes :

pt-slave-delay --delay 1m --interval 15s --run-time 10m slavehost

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Vérifier les "BOGUES" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

"pt-slave-delay" surveille un esclave et démarre et arrête son thread SQL de réplication au besoin pour le maintenir à un retard d'au moins le délai que vous demandez par rapport au maître. En pratique, il fera généralement en sorte que l'esclave prenne un retard compris entre "--delay" et "--delay" + "--interval" par rapport au maître.

Par défaut, il base le délai sur les positions du binlog dans les journaux relais de l'esclave, il n'est donc pas nécessaire de se connecter au maître. Cela fonctionne bien si le thread IO ne prend pas beaucoup de retard par rapport au maître, ce qui est typique dans la plupart des configurations de réplication ; le retard du thread IO est généralement de quelques millisecondes sur un réseau rapide. Si le retard de votre thread IO est trop important pour vos besoins, "pt-slave-delay" peut également se connecter au maître pour obtenir des informations sur les positions du binlog.

Si le thread I/O de l'esclave signale qu'il attend que le thread SQL libère de l'espace dans le journal relais, "pt-slave-delay" se connectera automatiquement au maître pour trouver les positions du journal binaire. Si "--ask-pass" et "--daemonize" sont donnés, il est possible que cela lui fasse demander un mot de passe lorsqu'il est démoniaqué. Dans ce cas, il se termine. Par conséquent, si vous pensez que votre esclave pourrait rencontrer cette condition, assurez-vous soit de spécifier explicitement "--use-master" lors de la démoniaisation, soit de ne pas spécifier "--ask-pass".

Les DSN SLAVE_DSN et MASTER_DSN optionnels sont tous deux des DSN. Voir "OPTIONS DSN". Les valeurs MASTER_DSN manquantes sont remplies avec les valeurs de SLAVE_DSN, vous n'avez donc pas besoin de les spécifier dans les deux endroits. "pt-slave-delay" lit tous les fichiers d'options MySQL normaux, tels que ~/.my.cnf, vous n'avez donc peut-être pas besoin de spécifier du tout le nom d'utilisateur, le mot de passe et d'autres options courantes.

"pt-slave-delay" tente de se terminer proprement en interceptant des signaux tels que Ctrl-C. Vous ne pouvez pas contourner "--[no]continue" avec un signal trappable.

PRIVILÈGES

pt-slave-delay nécessite les privilèges suivants : PROCESS, REPLICATION CLIENT et SUPER.

SORTIE

Si vous spécifiez "--quiet", il n'y a aucune sortie. Sinon, la sortie normale est un message d'état composé d'un horodatage et d'informations sur ce que "pt-slave-delay" fait : démarrage de l'esclave, arrêt de l'esclave ou simple observation.

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Référez-vous à la "SYNTAXE" et aux informations d'utilisation pour les détails.

--ask-pass
Inviter à entrer un mot de passe lors de la connexion à MySQL.
--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, définit le binmode de Perl sur STDOUT en utf8, passe l'option mysql_enable_utf8 à DBD::mysql et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur définit le binmode sur STDOUT sans la couche utf8 et exécute SET NAMES après la connexion à MySQL.

--config
type : Tableau

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, cela doit être la première option sur la ligne de commande.

--[no]continue
par défaut : oui

Continuer la réplication normalement à la sortie. Après la sortie, redémarrer le thread SQL de l'esclave sans condition UNTIL, afin qu'il fonctionne comme d'habitude et rattrape le maître. Ceci est activé par défaut et fonctionne même si vous terminez "pt-slave-delay" avec Control-C.

--daemonize
Faire un fork en arrière-plan et se détacher du shell. Systèmes d'exploitation POSIX uniquement.
--database
forme courte : -D ; type : chaîne

La base de données à utiliser pour la connexion.

--defaults-file
forme courte : -F ; type : chaîne

Ne lire que les options mysql à partir du fichier donné. Vous devez fournir un chemin absolu.

--delay
type : temps ; par défaut : 1h

Jusqu'à quel point l'esclave doit prendre du retard sur son maître.

--help
Afficher l'aide et quitter.
--host
forme courte : -h ; type : chaîne

Se connecter à l'hôte.

--interval
type : temps ; par défaut : 1m

À quelle fréquence "pt-slave-delay" doit vérifier si l'esclave doit être démarré ou arrêté.

--log
type : chaîne

Imprimer toute la sortie dans ce fichier lorsqu'il est démoniaqué.

--password
forme courte : -p ; type : chaîne

Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

--pid
type : chaîne

Créer le fichier PID donné. L'outil ne démarrera pas si le fichier PID existe déjà et que le PID qu'il contient est différent du PID actuel. Cependant, si le fichier PID existe et que le PID qu'il contient n'est plus en cours d'exécution, l'outil écrasera le fichier PID avec le PID actuel. Le fichier PID est supprimé automatiquement lorsque l'outil se termine.

--port
forme courte : -P ; type : entier

Numéro de port à utiliser pour la connexion.

--quiet
forme courte : -q

Ne pas imprimer de messages d'information sur le fonctionnement. Voir SORTIE pour les détails.

--run-time
type : temps

Combien de temps "pt-slave-delay" doit s'exécuter avant de se terminer. Par défaut, il s'exécute indéfiniment.

--set-vars
type : Tableau

Définir les variables MySQL dans cette liste séparée par des virgules de paires "variable=valeur".

Par défaut, l'outil définit :

wait_timeout=10000

Les variables spécifiées sur la ligne de commande remplacent ces valeurs par défaut. Par exemple, spécifier "--set-vars wait_timeout=500" remplace la valeur par défaut de 10000.

L'outil imprime un avertissement et continue si une variable ne peut pas être définie.

--socket
forme courte : -S ; type : chaîne

Fichier socket à utiliser pour la connexion.

--use-master

If you specify this option without giving a MASTER_DSN on the command line, "pt-slave-delay" examines the slave's SHOW SLAVE STATUS to determine the hostname and port for connecting to the master.

"pt-slave-delay" uses only the MASTER_HOST and MASTER_PORT values from SHOW SLAVE STATUS for the master connection. It does not use the MASTER_USER value. --user
forme courte : -u ; type : string

Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

--version
Afficher la version et quitter.
--[no]version-check
par défaut : yes

Vérifie la dernière version de Percona Toolkit, MySQL et d'autres programmes.

Il s'agit d'une fonctionnalité standard de "vérification automatique des mises à jour", avec deux fonctionnalités supplémentaires. Premièrement, l'outil vérifie sa propre version ainsi que les versions des logiciels suivants : système d'exploitation, Percona Monitoring and Management (PMM), MySQL, Perl, pilote MySQL pour Perl (DBD::mysql) et Percona Toolkit. Deuxièmement, il vérifie et signale les versions présentant des problèmes connus. Par exemple, MySQL 5.5.25 présentait un bug critique et a été réédité sous la version 5.5.25a.

Une connexion sécurisée au serveur de base de données de vérification des versions de Percona est établie pour effectuer ces vérifications. Chaque requête est enregistrée par le serveur, y compris les numéros de version des logiciels et l'identifiant unique du système vérifié. L'identifiant est généré par le script d'installation de Percona Toolkit ou lors du premier appel à la base de données de vérification des versions.

Toutes les mises à jour ou les problèmes connus sont imprimés sur STDOUT avant la sortie normale de l'outil. Cette fonctionnalité ne doit jamais interférer avec le fonctionnement normal de l'outil.

Pour plus d'informations, visitez https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

OPTIONS DSN

Ces options DSN sont utilisées pour créer un DSN. Chaque option est donnée sous la forme "option=valeur". Les options sont sensibles à la casse, donc P et p ne sont pas la même option. Il ne peut y avoir d'espace avant ou après le "=" et si la valeur contient des espaces, elle doit être mise entre guillemets. Les options DSN sont séparées par des virgules. Voir la page de manuel de percona-toolkit pour plus de détails.

  • A

    dsn: charset; copy: yes

    Jeu de caractères par défaut.

  • D

    dsn: database; copy: yes

    Base de données par défaut.

  • F

    dsn: mysql_read_default_file; copy: yes

    Lire uniquement les options par défaut à partir du fichier donné

  • h

    dsn: host; copy: yes

    Se connecter à l'hôte.

  • p

    dsn: password; copy: yes

    Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

  • P

    dsn: port; copy: yes

    Numéro de port à utiliser pour la connexion.

  • S

    dsn: mysql_socket; copy: yes

    Fichier de socket à utiliser pour la connexion.

  • u

    dsn: user; copy: yes

    Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

ENVIRONNEMENT

La variable d'environnement "PTDEBUG" active la sortie de débogage détaillée sur STDERR. Pour activer le débogage et capturer toute la sortie dans un fichier, exécutez l'outil comme suit :

PTDEBUG=1 pt-slave-delay ... > FICHIER 2>&1

Attention : la sortie de débogage est volumineuse et peut générer plusieurs mégaoctets de sortie.

ATTENTION

L'utilisation de <PTDEBUG> peut exposer les mots de passe. Lorsque le débogage est activé, tous les paramètres de la ligne de commande sont affichés dans la sortie.
