NOM

pt-find - Trouve des tables MySQL et exécute des actions, comme GNU find.

SYNTAXE

Utilisation : pt-find [OPTIONS] [BASES_DE_DONNÉES]

pt-find recherche des tables MySQL et exécute des actions, comme GNU find. L'action par défaut est d'afficher la base de données et le nom de la table.

Trouver toutes les tables créées il y a plus d'un jour, qui utilisent le moteur MyISAM, et afficher leurs noms :

pt-find --ctime +1 --engine MyISAM

Trouver les tables MyISAM et les convertir en InnoDB :

pt-find --engine MyISAM --exec "ALTER TABLE %D.%N ENGINE=InnoDB"

Trouver les tables créées par un processus qui n'existe plus, en suivant la convention de nommage name_sid_pid, et les supprimer.

pt-find --connection-id '\D_\d+_(\d+)$' --server-id '\D_(\d+)_\d+$' --exec-plus "DROP TABLE %s"

Trouver les tables vides dans les bases de données test et junk, et les supprimer :

pt-find --empty junk test --exec-plus "DROP TABLE %s"

Trouver les tables dont la taille totale dépasse cinq gigaoctets :

pt-find --tablesize +5G

Trouver toutes les tables et afficher leur taille totale de données et d'index, et trier les plus grandes tables en premier (le tri est un programme différent, soit dit en passant).

pt-find --printf "%T\t%D.%N\n" | sort -rn

Comme ci-dessus, mais cette fois, insérer les données dans la base de données pour la postérité :

pt-find --noquote --exec "INSERT INTO sysdata.tblsize(db, tbl, size) VALUES('%D', '%N', %T)"

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Consulter les " BUGS " connus de l'outil
  • Tester l'outil sur un serveur non productif
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-find recherche des tables MySQL qui satisfont aux tests que vous spécifiez, et exécute les actions que vous spécifiez. L'action par défaut est d'écrire la base de données et le nom de la table sur STDOUT.

pt-find est plus simple que GNU find. Il ne vous permet pas de spécifier des expressions compliquées sur la ligne de commande.

pt-find utilise SHOW TABLES lorsque c'est possible, et SHOW TABLE STATUS lorsque c'est nécessaire.

TYPES D'OPTIONS

Il existe trois types d'options : les options normales, qui déterminent un comportement ou un réglage ; les tests, qui déterminent si une table doit être incluse dans la liste des tables trouvées ; et les actions, qui font quelque chose aux tables que pt-find trouve.

pt-find utilise l'analyse standard des options Getopt::Long, vous devriez donc utiliser des doubles tirets devant les noms d'options longues, contrairement à GNU find.

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Reportez-vous à la section " SYNTAXE " et aux informations d'utilisation pour plus de détails.

--ask-pass
Demande un mot de passe lors de la connexion à MySQL.
--case-insensitive
Spécifie que toutes les recherches par expressions régulières ne tiennent pas compte de la casse.
--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, définit le mode binaire de Perl sur STDOUT en utf8, passe l'option mysql_enable_utf8 à DBD::mysql, et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur définit le mode binaire sur STDOUT sans la couche utf8, et exécute SET NAMES après la connexion à MySQL.

--config
type : Tableau

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, cela doit être la première option sur la ligne de commande.

--database
forme courte : -D ; type : chaîne

Se connecter à cette base de données.

--day-start
Mesurer les temps (pour "--mmin", etc.) depuis le début de la journée plutôt que depuis l'heure actuelle.
--defaults-file
forme courte : -F ; type : chaîne

Lire uniquement les options mysql du fichier donné. Vous devez fournir un chemin absolu.

--help
Afficher l'aide et quitter.
--host
forme courte : -h ; type : chaîne

Se connecter à l'hôte.

--mysql_ssl
forme courte : -s ; type : entier

Créer une connexion SSL MySQL.

--or
Combiner les tests avec OU, pas ET.

Par défaut, les tests sont évalués comme s'il y avait un ET entre eux. Cette option passe à OU.

L'analyse des options n'est pas implémentée par pt-find lui-même, vous ne pouvez donc pas spécifier des expressions compliquées avec des parenthèses et des mélanges de OU et de ET.

--password
forme courte : -p ; type : chaîne

Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

--pid
type : chaîne

Créer le fichier PID donné. L'outil ne démarrera pas si le fichier PID existe déjà et que le PID qu'il contient est différent du PID actuel. Cependant, si le fichier PID existe et que le PID qu'il contient n'est plus en cours d'exécution, l'outil écrasera le fichier PID avec le PID actuel. Le fichier PID est supprimé automatiquement lorsque l'outil se termine.

--port
forme courte : -P ; type : entier

Numéro de port à utiliser pour la connexion.

--[no]quote
défaut : oui

Entoure les noms d'identifiants MySQL avec le caractère de backtick standard de MySQL.

L'encadrement se produit après l'exécution des tests et avant l'exécution des actions.

--set-vars
type : Tableau

Définir les variables MySQL dans cette liste séparée par des virgules de paires "variable=valeur".

Par défaut, l'outil définit :

wait_timeout=10000

Les variables spécifiées sur la ligne de commande remplacent ces valeurs par défaut. Par exemple, spécifier "--set-vars wait_timeout=500" remplace la valeur par défaut de 10000.

L'outil affiche un avertissement et continue si une variable ne peut pas être définie.

--socket
forme courte : -S ; type : chaîne

Fichier socket à utiliser pour la connexion.

--user
forme courte : -u ; type : chaîne

Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

--version
Afficher la version et quitter.
--[no]version-check
défaut : oui

Vérifie la dernière version de Percona Toolkit, MySQL et d'autres programmes.

Il s'agit d'une fonction standard de "vérification automatique des mises à jour", avec deux fonctionnalités supplémentaires. Premièrement, l'outil vérifie sa propre version ainsi que les versions des logiciels suivants : système d'exploitation, Percona Monitoring and Management (PMM), MySQL, Perl, driver MySQL pour Perl (DBD::mysql) et Percona Toolkit. Deuxièmement, il vérifie et avertit sur les versions ayant des problèmes connus. Par exemple, MySQL 5.5.25 avait un bug critique et a été republié sous la version 5.5.25a.

Une connexion sécurisée au serveur de base de données de vérification des versions de Percona est effectuée pour effectuer ces vérifications. Chaque requête est enregistrée par le serveur, y compris les numéros de version des logiciels et l'identifiant unique du système vérifié. L'identifiant est généré par le script d'installation de Percona Toolkit ou lors du premier appel à la base de données de vérification des versions.

Toutes les mises à jour ou problèmes connus sont affichés sur STDOUT avant la sortie normale de l'outil. Cette fonctionnalité ne devrait jamais interférer avec le fonctionnement normal de l'outil.

TESTS

La plupart des tests vérifient un certain critère par rapport à une colonne de la sortie de SHOW TABLE STATUS. Les arguments numériques peuvent être spécifiés comme +n pour supérieur à n, -n pour inférieur à n, et n pour exactement n. Toutes les options numériques peuvent accepter un multiplicateur de suffixe facultatif de k, M ou G (respectivement 1 024, 1 048 576 et 1 073 741 824). Tous les modèles sont des expressions régulières Perl (voir 'man perlre') sauf indication contraire en tant que modèles SQL LIKE.

Les dates et heures sont toutes mesurées par rapport au même instant, lorsque pt-find demande au serveur de base de données quelle heure il est. Toutes les manipulations de dates et d'heures sont effectuées en SQL, donc si vous dites de trouver les tables modifiées il y a 5 jours, cela se traduit par SELECT DATE_SUB(CURRENT_TIMESTAMP, INTERVAL 5 DAY). Si vous spécifiez "--day-start", bien sûr, c'est relatif à CURRENT_DATE.

Cependant, les tailles de table et autres métriques ne sont pas cohérentes à un instant donné. Il peut falloir du temps à MySQL pour traiter toutes les requêtes SHOW, et pt-find ne peut rien y faire. Ces mesures datent du moment où elles sont prises.

Si vous avez besoin d'un test qui n'est pas dans cette liste, déposez une demande de fonctionnalité sur https://jira.percona.com/projects/PT.

--autoinc
type: chaîne ; groupe: Tests

La prochaine valeur AUTO_INCREMENT de la table est n. Ceci teste la colonne Auto_increment.

--avgrowlen
type: taille ; groupe: Tests

La longueur moyenne des lignes de la table est n octets. Ceci teste la colonne Avg_row_length. La taille spécifiée peut être "NULL" pour tester lorsque Avg_row_length EST NULL.

--checksum
type: chaîne ; groupe: Tests

La somme de contrôle de la table est n. Ceci teste la colonne Checksum.

--cmin
type: taille ; groupe: Tests

La table a été créée il y a n minutes. Ceci teste la colonne Create_time.

--collation
type: chaîne ; groupe: Tests

Le classement de la table correspond au modèle. Ceci teste la colonne Collation.

--column-name
type: chaîne ; groupe: Tests

Un nom de colonne dans la table correspond au modèle.

--column-type
type: chaîne ; groupe: Tests

Une colonne de la table correspond à ce type (insensible à la casse).

Exemples de types : varchar, char, int, smallint, bigint, decimal, year, timestamp, text, enum.

--comment
type: chaîne ; groupe: Tests

Le commentaire de la table correspond au modèle. Ceci teste la colonne Comment.

--connection-id
type: chaîne ; groupe: Tests

Le nom de la table contient un ID de connexion MySQL inexistant. Ceci teste le nom de la table pour un modèle. L'argument de ce test doit être une expression régulière Perl qui capture des chiffres comme ceci : (\d+). Si le nom de la table correspond au modèle, ces chiffres capturés sont considérés comme l'ID de connexion MySQL d'un processus. Si la connexion n'existe pas selon SHOW FULL PROCESSLIST, le test renvoie vrai. Si l'ID de connexion est supérieur à l'ID de connexion de pt-find lui-même, le test renvoie faux par mesure de sécurité.

Pourquoi voudriez-vous faire cela ? Si vous utilisez la réplication basée sur les instructions MySQL, vous connaissez probablement les problèmes que les tables temporaires peuvent causer. Vous pourriez choisir de contourner cela en créant de vraies tables avec des noms uniques, au lieu de tables temporaires. Une façon de faire cela est d'ajouter votre ID de connexion à la fin de la table, ainsi : scratch_table_12345. Cela garantit l'unicité du nom de la table et vous permet d'identifier à quelle connexion elle était associée. Et peut-être le plus important, si la connexion n'existe plus, vous pouvez supposer que la connexion est morte sans nettoyer ses tables, et cette table est candidate à la suppression.

L'argument à utiliser pour "--connection-id" est "\D_(\d+)$". Cela trouve les tables avec une série de chiffres à la fin, précédée d'un trait de soulignement et d'un caractère non numérique (ce dernier critère empêche l'examen des tables avec une date à la fin, ce que les gens ont tendance à faire : baron_scratch_2007_05_07 par exemple). Il est préférable de garder les tables temporaires séparées.

Si vous faites cela, assurez-vous que l'utilisateur sous lequel pt-find s'exécute a le privilège PROCESS ! Sinon, il ne verra que les connexions du même utilisateur et pourrait penser que certaines tables sont prêtes à être supprimées alors qu'elles sont encore utilisées. Par mesure de sécurité, pt-find le vérifie pour vous.

Voir aussi "--server-id".

--server-id
type: chaîne ; groupe: Tests

Le nom de la table contient l'ID du serveur. Si vous créez des tables temporaires avec la convention de nommage expliquée dans "--connection-id", mais que vous ajoutez également l'ID du serveur sur lequel les tables sont créées, alors vous pouvez utiliser cette correspondance de modèle pour vous assurer que les tables ne sont supprimées que sur le serveur sur lequel elles ont été créées. Cela évite qu'une table ne soit accidentellement supprimée sur une réplique alors qu'elle est en cours d'utilisation (à condition que vos ID de serveur soient tous uniques, ce qu'ils devraient être pour que la réplication fonctionne).

Par exemple, sur la source de réplication (ID de serveur 22) vous créez une table appelée scratch_table_22_12345. Si vous voyez cette table sur la réplique (ID de serveur 23), vous pourriez penser qu'elle peut être supprimée en toute sécurité s'il n'existe pas de connexion 12345. Mais si vous forcez également le nom à correspondre à l'ID du serveur avec "--server-id '\D_(\d+)_\d+$'", la table ne sera pas supprimée sur la réplique.

ACTIONS

L'action « --exec-plus » se produit après tout le reste, mais sinon les actions se produisent dans un ordre indéterminé. Si vous avez besoin de déterminisme, déposez une demande de fonctionnalité sur https://jira.percona.com/projects/PT.

--exec
type : chaîne ; groupe : Actions

Exécutez ce SQL avec chaque élément trouvé. Le SQL peut contenir des échappements et des directives de formatage (voir « --printf »).

--exec-dsn
type : chaîne ; groupe : Actions

Spécifiez un DSN au format clé-valeur à utiliser lors de l'exécution de SQL avec « --exec » et « --exec-plus ».

--exec-plus
type : chaîne ; groupe : Actions

Exécutez ce SQL avec tous les éléments à la fois. Cette option est différente de « --exec ». Il n'y a pas d'échappements ni de directives de formatage ; il n'y a qu'un seul espace réservé spécial pour la liste des noms de bases de données et de tables, %s. La liste des tables trouvées sera jointe avec des virgules et substituée partout où vous placerez %s.

Vous pourriez l'utiliser, par exemple, pour supprimer toutes les tables que vous avez trouvées :

DROP TABLE %s

C'est un peu comme la syntaxe « -exec command {} + » de GNU find.

--print
groupe : Actions

Imprimez le nom de la base de données et de la table, suivi d'un saut de ligne. C'est l'action par défaut si aucune autre action n'est spécifiée.

--printf
type : chaîne ; groupe : Actions

Imprimez le format sur la sortie standard, en interprétant les échappements '\' et les directives '%'. Les échappements sont des caractères précédés d'une barre oblique inverse, comme \n et \t. Perl les interprète, vous pouvez donc utiliser tous les échappements que Perl connaît. Les directives sont remplacées par %s, et à l'heure actuelle, vous ne pouvez pas ajouter d'instructions de formatage spéciales, comme des largeurs de champ ou un alignement.

Voici une liste des directives. Notez que la plupart d'entre elles proviennent simplement des colonnes de SHOW TABLE STATUS. Si la colonne est NULL ou n'existe pas, vous obtenez une chaîne vide dans la sortie. Un caractère % suivi d'un caractère qui ne figure pas dans la liste suivante est ignoré (mais l'autre caractère est imprimé).

OPTIONS DSN

Ces options DSN sont utilisées pour créer un DSN. Chaque option est donnée sous la forme « option=valeur ». Les options sont sensibles à la casse, donc P et p ne sont pas la même option. Il ne peut y avoir d'espace blanc avant ou après le « = » et si la valeur contient des espaces blancs, elle doit être entre guillemets. Les options DSN sont séparées par des virgules. Voir la page de manuel percona-toolkit pour plus de détails.

  • A

    dsn: charset; copy: yes

    Jeu de caractères par défaut.

  • D

    dsn: database; copy: yes

    Base de données par défaut.

  • F

    dsn: mysql_read_default_file; copy: yes

    Ne lire les options par défaut que dans le fichier donné

  • h

    dsn: host; copy: yes

    Se connecter à l'hôte.

  • p

    dsn: password; copy: yes

    Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : « exam\,ple »

  • P

    dsn: port; copy: yes

    Numéro de port à utiliser pour la connexion.

  • S

    dsn: mysql_socket; copy: yes

    Fichier socket à utiliser pour la connexion.

  • u

    dsn: user; copy: yes

    Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

  • s

    dsn: mysql_ssl; copy: yes

    Créer une connexion SSL

ENVIRONNEMENT

La variable d'environnement "PTDEBUG" active la sortie de débogage détaillée sur STDERR. Pour activer le débogage et capturer toute la sortie dans un fichier, exécutez l'outil comme suit :

PTDEBUG=1 pt-find ... > FICHIER 2>&1

Attention : la sortie de débogage est volumineuse et peut générer plusieurs mégaoctets de sortie.

ATTENTION

L'utilisation de <PTDEBUG> peut exposer les mots de passe. Lorsque le débogage est activé, tous les paramètres de la ligne de commande sont affichés dans la sortie.

    pt-find(1p) — Documentation Percona Toolkit

    NOM

    pt-find — trouve et analyse les fichiers de log de table dans les tables de bases de données MySQL.

    SYNTAXE

    pt-find [--defaults-file master.cnf] [OPTIONS] [DSN]

    DESCRIPTION

    pt-find est un utilitaire de ligne de commande qui recherche des tables qui utilisent le moteur de stockage ARCHIVE, CSV, ERICSSON, FEDERATED, MERGE, MRG_MYISAM, MyISAM, MyISAM CPG, RAW, SPIDER, SQL_PARTITION, STATS_TEMPORARY ou TOKUDB.

    Ces moteurs de stockage ne sont généralement pas utilisés pour les données transactionnelles, mais ils peuvent être utilisés pour des logs ou des données temporaires. pt-find est conçu pour aider à identifier ces tables afin que vous puissiez décider si elles doivent être nettoyées ou gérées différemment.

    OPTIONS

    pt-find accepte des options supplémentaires de la ligne de commande, ainsi que les options générales de Percona Toolkit.

    Options spécifiques à l'outil

    --ask-pass
    Demande le mot de passe pour la connexion.
    --config=fichier
    Spécifie le fichier de configuration à utiliser.
    --database=db
    Spécifie la base de données à rechercher.
    --dsn=dsn
    Spécifie le DSN de connexion à la base de données.
    --defaults-file=fichier
    Spécifie le fichier de configuration par défaut à utiliser. Par défaut, il utilise le premier fichier trouvé dans l'ordre suivant : my.cnf, .my.cnf.
    --host=hôte
    Spécifie l'hôte de la base de données.
    --no-defaults
    Ne lit pas les fichiers de configuration par défaut.
    --password=mot_de_passe
    Spécifie le mot de passe pour la connexion.
    --port=port
    Spécifie le port de la base de données.
    --quiet
    Supprime la sortie des informations de progression.
    --run-check
    Exécute pt-table-checksum sur les tables trouvées.
    --run-checksum-options=options
    Spécifie les options à passer à pt-table-checksum.
    --user=utilisateur
    Spécifie l'utilisateur pour la connexion.

    Options générales de Percona Toolkit

    Pour une liste complète des options générales, consultez la documentation de Percona Toolkit.

    EXEMPLE

    L'exemple suivant recherche des tables de log dans la base de données `mydatabase` sur l'hôte `localhost` avec l'utilisateur `root` et le mot de passe `mypassword` :

    pt-find --user=root --password=mypassword --host=localhost --database=mydatabase

    L'exemple suivant recherche des tables de log dans toutes les bases de données et exécute pt-table-checksum sur les tables trouvées avec des options spécifiques :

    pt-find --run-check --run-checksum-options="--no-check-binlog-format"

    PERFORMANCE

    pt-find est conçu pour être rapide et efficace. Il utilise des requêtes SQL optimisées pour récupérer les informations sur les tables.

    RESSOURCES

    Pour plus d'informations, consultez les ressources suivantes :

    • Documentation officielle de pt-find
    • Blog Percona

    ATTENTION

    Utilisez pt-find avec prudence. La modification ou la suppression de tables peut entraîner une perte de données. Assurez-vous de bien comprendre les implications avant d'effectuer des actions sur les tables trouvées.

    CONFIGURATION REQUISE

    pt-find nécessite Perl et les modules Perl suivants : DBI, DBD::mysql, Percona::Toolkit::Util.
