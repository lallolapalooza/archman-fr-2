NOM

pt-variable-advisor - Analyse les variables MySQL et conseille sur les problèmes possibles.

SYNTAXE

Utilisation : pt-variable-advisor [OPTIONS] [DSN]

pt-variable-advisor analyse les variables et conseille sur les problèmes possibles.

Obtenir SHOW VARIABLES de localhost :

pt-variable-advisor localhost

Obtenir la sortie SHOW VARIABLES enregistrée dans vars.txt :

pt-variable-advisor --source-of-variables vars.txt

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Consulter les "BOGUES" connus de l'outil
  • Tester l'outil sur un serveur non productif
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-variable-advisor examine "SHOW VARIABLES" pour les valeurs et les configurations incorrectes selon les "RÈGLES" décrites ci-dessous. Il signale les variables qui correspondent aux règles, vous permettant ainsi de trouver les mauvaises configurations sur votre serveur MySQL.

RÈGLES

Ce sont les règles que pt-variable-advisor appliquera à SHOW VARIABLES. Chaque règle comprend trois parties : un identifiant, une sévérité et une description.

L'identifiant de la règle est un nom court et unique pour la règle. Il se rapporte généralement à la variable examinée par la règle. Si une variable est examinée par plusieurs règles, les identifiants des règles sont numérotés comme "-1", "-2", "-N".

La sévérité de la règle indique l'importance de la correspondance de cette règle avec une requête. Nous utilisons NOTE, WARN et CRIT pour désigner ces niveaux.

La description de la règle est une explication textuelle et lisible par l'homme de ce que signifie une variable qui correspond à cette règle. Selon la verbosité du rapport que vous générez, vous verrez plus ou moins de texte dans la description. Par défaut, vous ne verrez que la première phrase, qui est en quelque sorte un résumé concis de la signification de la règle. À un niveau de verbosité plus élevé, vous verrez les phrases suivantes.

innodb_fast_shutdown
sévérité : avertissement

Le comportement d'arrêt d'InnoDB n'est pas celui par défaut. Cela peut entraîner de mauvaises performances, ou la nécessité d'effectuer une récupération après incident au démarrage.

innodb_flush_log_at_trx_commit-1
sévérité : avertissement

Si vous essayez de la changer de 1 pour des raisons de performance, vous devriez la définir à 2 plutôt qu'à 0.

innodb_force_recovery
sévérité : avertissement

InnoDB est en mode de récupération forcée ! Ceci ne devrait être utilisé que temporairement lors de la récupération d'une corruption de données ou d'autres bogues, pas pour une utilisation normale.

innodb_log_file_size

MySQL Server Status

archive
severity: note

L'option ARCHIVE est activée. Ceci est une bonne option pour les tables qui sont souvent lues mais rarement écrites, car elle permet d'économiser de l'espace disque.

archive_mode
severity: note

L'option ARCHIVE est activée. Ceci est une bonne option pour les tables qui sont souvent lues mais rarement écrites, car elle permet d'économiser de l'espace disque.

aria_page_checksum
severity: note

Les sommes de contrôle de page Aria sont activées.

aria_sync_log_dir
severity: note

Le répertoire de journal Aria est synchronisé.

binlog_format
severity: note

Le format du journal binaire est défini sur ROW. Ce format est généralement recommandé pour la réplication, car il garantit la cohérence des données entre le maître et le réplica, même si des déclarations non déterministes sont exécutées.

innodb_buffer_pool_size
severity: note

La taille du pool de tampons InnoDB est définie sur 128 Mo, ce qui est inférieur à la taille recommandée de 1 Go. Pour de meilleures performances, augmentez cette valeur à au moins 1 Go, ou même à 70% de la mémoire vive totale de votre serveur, si le serveur est dédié à MySQL.

innodb_doublewrite
severity: warn

L'option doublewrite d'InnoDB est activée. Ceci est une bonne chose pour la durabilité des données, mais cela peut avoir un impact sur les performances d'écriture. Si vous avez un système de stockage très performant et que vous êtes prêt à accepter un risque légèrement accru de corruption de données en cas de crash, vous pouvez envisager de désactiver cette option.

innodb_flush_log_at_trx_commit
severity: warn

L'option innodb_flush_log_at_trx_commit est définie sur 2. Bien que cela améliore les performances par rapport à la valeur par défaut de 1, cela peut entraîner une perte de données en cas de crash du serveur. Pour une durabilité maximale des données, définissez cette valeur sur 1.

innodb_log_file_size
severity: note

La taille des fichiers journaux InnoDB est définie sur 512 Mo, ce qui est inférieur à la taille recommandée de 1 Go. Pour de meilleures performances, augmentez cette valeur à 1 Go ou plus.

innodb_log_buffer_size
severity: note

La taille du tampon de journal InnoDB est définie sur 16 Mo, ce qui est supérieur à la taille par défaut de 8 Mo. Cette valeur est généralement appropriée pour des charges de travail importantes.

innodb_flush_neighbors
severity: note

L'option innodb_flush_neighbors est désactivée. Ceci est généralement une bonne idée sur les systèmes de stockage basés sur SSD, car cela peut réduire les performances d'écriture.

key_buffer_size
severity: warn

La taille du tampon de clé est définie sur 16 Mo, ce qui est inférieur à la taille recommandée de 128 Mo pour les serveurs utilisant MyISAM. Si vous utilisez MyISAM, augmentez cette valeur pour améliorer les performances des tables MyISAM.

large_pages
severity: note

Les grandes pages sont activées.

locked_in_memory
severity: note

Le serveur est verrouillé en mémoire avec --memlock.

log_warnings-1
severity: note

Log_warnings est désactivé, de sorte que les événements inhabituels tels que les instructions non sécurisées pour la réplication et les connexions abandonnées ne seront pas consignés dans le journal d'erreurs.

log_warnings-2
severity: note

Log_warnings doit être défini sur une valeur supérieure à 1 pour enregistrer les événements inhabituels tels que les connexions abandonnées.

low_priority_updates
severity: note

Le serveur fonctionne avec une priorité de verrouillage non par défaut pour les mises à jour. Cela pourrait amener les requêtes de mise à jour à attendre de manière inattendue les requêtes de lecture.

max_binlog_size

max_connect_errors

Si le serveur a jamais plus d'un millier de threads en cours d'exécution, le système consacrera probablement plus de temps à la planification des threads qu'à l'exécution d'un travail utile. La valeur de cette variable doit être considérée en fonction de votre charge de travail.

myisam_repair_threads > 1 active la réparation multithread, qui est relativement peu testée et toujours considérée comme bêta dans la documentation officielle.

relay_log_space_limit
severity: warn

La définition de relay_log_space_limit peut entraîner l'arrêt immédiat des réplicas dans la récupération des journaux binaires de leur maître. Cela pourrait augmenter le risque de perte de données si le maître de réplication tombe en panne. Si les réplicas ont rencontré une limite d'espace de journal relais, il est possible que les dernières transactions n'existent que sur le maître et qu'aucun réplica ne les ait récupérées.

Il est également conseillé d'utiliser pt-heartbeat pour s'assurer que la connexion ne semble pas expirer lorsque le maître est simplement inactif.

Il est également conseillé d'utiliser pt-heartbeat pour s'assurer que la connexion ne semble pas expirer lorsque le maître est simplement inactif.

--version
Afficher la version et quitter.
--[no]version-check
defaut : yes

Verifier la derniere version de Percona Toolkit, MySQL et d'autres programmes.

Il s'agit d'une fonction standard de "verifier les mises a jour automatiquement", avec deux fonctionnalites supplementaires. Premiere, l'outil verifie sa propre version ainsi que les versions des logiciels suivants : systeme d'exploitation, Percona Monitoring and Management (PMM), MySQL, Perl, driver MySQL pour Perl (DBD::mysql) et Percona Toolkit. Deuxieme, il verifie et avertit des versions ayant des problemes connus. Par exemple, MySQL 5.5.25 avait un bug critique et a ete re-publie sous le nom 5.5.25a.

Une connexion securisee au serveur de base de donnees de verification des versions de Percona est etablie pour effectuer ces verifications. Chaque requete est enregistree par le serveur, y compris les numeros de version des logiciels et l'ID unique du systeme verifie. L'ID est genere par le script d'installation de Percona Toolkit ou lors du premier appel a la base de donnees de verification des versions.

Toutes les mises a jour ou problemes connus sont imprimes sur STDOUT avant la sortie normale de l'outil. Cette fonction ne devrait jamais interferer avec le fonctionnement normal de l'outil.

Pour plus d'informations, visitez https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

OPTIONS DSN

Ces options DSN sont utilisees pour creer un DSN. Chaque option est donnee sous la forme "option=valeur". Les options sont sensibles a la casse, donc P et p ne sont pas la meme option. Il ne doit pas y avoir d'espace avant ou apres le signe "=" et si la valeur contient un espace, elle doit etre mise entre guillemets. Les options DSN sont separees par des virgules. Voir la page man de percona-toolkit pour tous les details.

  • A

    dsn: charset; copy: yes

    Jeu de caracteres par defaut.

  • D

    dsn: database; copy: yes

    Base de donnees par defaut.

  • F

    dsn: mysql_read_default_file; copy: yes

    Lire uniquement les options par defaut du fichier donne

  • h

La variable d'environnement "PTDEBUG" active une sortie de debogage verbose sur STDERR. Pour activer le debogage et capturer toute la sortie dans un fichier, executez l'outil comme suit :

PTDEBUG=1 pt-variable-advisor ... > FICHIER 2>&1

Attention : la sortie de debogage est volumineuse et peut generer plusieurs megabytes de sortie.

ATTENTION

L'utilisation de <PTDEBUG> peut exposer des mots de passe. Lorsque le debogage est actif, tous les parametres de la ligne de commande sont affiches dans la sortie.

NOM

pt-variable-advisor — suggère des modifications des variables MySQL

SYNOPSIS

pt-variable-advisor [OPTIONS]

RISQUES

Ce script peut modifier les variables de configuration MySQL. Lisez attentivement la sortie avant de faire quoi que ce soit.

DESCRIPTION

Percona Toolkit est une collection d'outils de ligne de commande avancés pour MySQL. Ce script est le conseiller de variables de Percona Toolkit. Il analyse les valeurs des variables de configuration MySQL et suggère des modifications basées sur des règles heuristiques.

RÈGLES

Les règles sont intégrées à l'outil et peuvent être mises à jour dans les futures versions.

OPTIONS

Le programme accepte les options et arguments supplémentaires suivants :

--help, -h
Affiche le message d'aide et quitte.
--host, -H
Hôte sur lequel se connecter. Par défaut : localhost.
--password, -p
Mot de passe à utiliser pour la connexion. S'il est indiqué, le programme vous demandera le mot de passe.
--port, -P
Port à utiliser pour la connexion TCP/IP. Par défaut : 3306.
--user, -u
Nom d'utilisateur à utiliser pour la connexion. Par défaut : aucun (connexion anonyme).
--version
Affiche les informations de version et quitte.

OPTIONS DSN

Les options DSN sont des options de connexion qui peuvent être spécifiées sous la forme d'une chaîne DSN. Par exemple : DSN=dbi:mysql:mysql:localhost:3306.

ENVIRONNEMENT

L'outil utilise l'environnement pour déterminer les valeurs des options.

ATTENTION

Soyez prudent lorsque vous modifiez les variables de configuration de MySQL. Des modifications incorrectes peuvent nuire aux performances de votre serveur ou le rendre instable.

CONFIGURATION SYSTÈME

L'outil nécessite Perl et les modules Perl suivants : DBI, DBD::mysql. Il nécessite également un accès à un serveur MySQL.
