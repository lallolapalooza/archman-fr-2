PT-FK-ERROR-LOGGER(1) Documentation Perl fournie par l'utilisateur PT-FK-ERROR-LOGGER(1)

NOM

pt-fk-error-logger - Journalise les erreurs de clé étrangère MySQL.

SYNOPSIS

Usage : pt-fk-error-logger [OPTIONS] [DSN]

pt-fk-error-logger journalise les informations sur les erreurs de clé étrangère sur le DSN donné. Les informations sont imprimées sur "STDOUT", et peuvent également être sauvegardées dans une table en spécifiant "--dest". L'outil s'exécute indéfiniment à moins que "--run-time" ou "--iterations" ne soit spécifié.

Imprimer les erreurs de clé étrangère sur l'hôte1 :

pt-fk-error-logger h=host1

Imprimer les erreurs de clé étrangère sur l'hôte1 une fois puis quitter :

pt-fk-error-logger h=host1 --iterations 1

Sauvegarder les erreurs de clé étrangère sur l'hôte1 dans percona_schema.fke sur l'hôte2 :

pt-fk-error-logger h=host1 --dest h=host2,D=percona_schema,t=fke

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Examiner les "BUGS" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-fk-error-logger imprime ou sauvegarde le texte des erreurs de clé étrangère provenant de "SHOW INNODB STATUS". Les erreurs ne sont pas analysées ou interprétées d'une quelconque manière. Les erreurs de clé étrangère sont identifiées de manière unique par leur horodatage. Seules les erreurs nouvelles (plus récentes) sont imprimées ou sauvegardées.

Par défaut, l'outil s'exécute indéfiniment, vérifiant toutes les "--interval" secondes pour de nouvelles erreurs de clé étrangère. Spécifiez "--run-time" et/ou "--iterations" pour limiter la durée d'exécution de l'outil.

SORTIE

Le texte des erreurs de clé étrangère de "SHOW ENGINE INNODB STATUS" est imprimé sur "STDOUT", sauf si "--quiet" est spécifié. Les erreurs et les avertissements sont imprimés sur "STDERR".

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Se référer à la "SYNOPSIS" et aux informations d'utilisation pour les détails.

--ask-pass
Demander un mot de passe lors de la connexion à MySQL.
--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, définit le mode binaire de Perl sur STDOUT en utf8, passe l'option mysql_enable_utf8 à DBD::mysql, et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur définit le mode binaire sur STDOUT sans la couche utf8, et exécute SET NAMES après la connexion à MySQL.

--config
type : Tableau

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, ceci doit être la première option sur la ligne de commande.

--daemonize
Détacher le processus dans l'arrière-plan et le détacher du terminal. Systèmes d'exploitation POSIX uniquement.
--database
forme courte : -D ; type : chaîne

Se connecter à cette base de données.

--defaults-file
forme courte : -F ; type : chaîne

Lire uniquement les options mysql du fichier donné. Vous devez fournir un chemin absolu.

--dest
type : DSN

Sauvegarder les erreurs de clé étrangère dans cette table. Le DSN doit spécifier une base de données (D) et une table (t).

Les valeurs de DSN manquantes sont héritées du DSN surveillé, vous pouvez donc omettre la plupart des valeurs si vous sauvegardez les erreurs de clé étrangère sur le même hôte.

Le tableau suivant est suggéré :

CREATE TABLE foreign_key_errors (
  ts datetime NOT NULL,
  error text NOT NULL,
  PRIMARY KEY (ts)
)

Les seules informations sauvegardées sont l'horodatage et le texte de l'erreur de clé étrangère.

--help
Afficher l'aide et quitter.
--host
forme courte : -h ; type : chaîne

Se connecter à l'hôte.

--interval
type : temps ; défaut : 30

Fréquence de vérification des erreurs de clé étrangère.

--iterations
type : entier

Nombre de fois où vérifier les erreurs de clé étrangère. Par défaut, cette option n'est pas définie, ce qui signifie un nombre infini d'itérations. L'outil quitte toujours pour "--run-time", indépendamment de la valeur spécifiée pour cette option. Par exemple, l'outil quittera après 1 minute avec "--run-time 1m --iterations 4 --interval 30" car 4 itérations à des intervalles de 30 secondes prendraient 2 minutes, ce qui est plus long que le temps d'exécution de 1 minute.

--log
type : chaîne

Imprimer toute la sortie dans ce fichier lors de la démonisation.

--password
forme courte : -p ; type : chaîne

Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

--pid
type : chaîne

Créer le fichier PID donné. L'outil ne démarrera pas si le fichier PID existe déjà et que le PID qu'il contient est différent du PID actuel. Cependant, si le fichier PID existe et que le PID qu'il contient ne s'exécute plus, l'outil écrasera le fichier PID avec le PID actuel. Le fichier PID est supprimé automatiquement lorsque l'outil se termine.

--port
forme courte : -P ; type : entier

Numéro de port à utiliser pour la connexion.

--quiet
Ne pas imprimer les erreurs de clé étrangère ; imprimer uniquement les erreurs et les avertissements sur "STDERR".
--run-time
type : temps

Durée d'exécution avant de quitter. Par défaut, l'outil s'exécute indéfiniment.

--set-vars
type : Tableau

Définir les variables MySQL dans cette liste séparée par des virgules de paires "variable=valeur".

Par défaut, l'outil définit :

wait_timeout=10000

Les variables spécifiées sur la ligne de commande remplacent ces valeurs par défaut. Par exemple, spécifier "--set-vars wait_timeout=500" remplace la valeur par défaut de 10000.

L'outil imprime un avertissement et continue si une variable ne peut pas être définie.

--socket
forme courte : -S ; type : chaîne

Fichier socket à utiliser pour la connexion.

--user
forme courte : -u ; type : chaîne

Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

--version
Afficher la version et quitter.
--[no]version-check
défaut : yes

Vérifier la dernière version de Percona Toolkit, MySQL et d'autres programmes.

Ceci est une fonctionnalité standard de "vérification des mises à jour automatiquement", avec deux fonctionnalités supplémentaires. Premièrement, l'outil vérifie sa propre version ainsi que les versions des logiciels suivants : système d'exploitation, Percona Monitoring and Management (PMM), MySQL, pilote MySQL pour Perl (DBD::mysql), et Percona Toolkit. Deuxièmement, il vérifie et avertit des versions présentant des problèmes connus. Par exemple, MySQL 5.5.25 avait un bug critique et a été réédité sous le nom 5.5.25a.

Une connexion sécurisée au serveur de base de données de vérification de version de Percona est effectuée pour effectuer ces vérifications. Chaque requête est enregistrée par le serveur, incluant les numéros de version des logiciels et l'identifiant unique du système vérifié. pt-fk-error-logger(1p) — Outils Percona

NOM

pt-fk-error-logger - Enregistre les erreurs de clé étrangère dans une table.

SYNOPIS

pt-fk-error-logger --databases DSN,... [OPTION]...

RISQUES

Ce script vérifie les erreurs de clé étrangère en exécutant des requêtes sur des tables et en vérifiant les tables des erreurs de clé étrangère. Soyez prudent lorsque vous exécutez des requêtes sur de grandes tables. Si le script est exécuté accidentellement sur le serveur de production, il peut consommer de grandes quantités de ressources, ralentissant considérablement le serveur. Lisez attentivement le script avant de l'exécuter.

Ce script est conçu pour s'exécuter une seule fois. Il est conçu pour être utilisé pour corriger des problèmes spécifiques de clé étrangère. Si vous l'exécutez en continu, il peut rapidement saturer votre table d'erreurs.

Il existe une version de ce script qui fonctionne sur un serveur distinct afin que vous puissiez effectuer des recherches sur les données sans affecter votre serveur de production. Vous pouvez trouver ce script à l'adresse suivante : https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

DESCRIPTION

Ce script recherche les erreurs de clé étrangère en utilisant des requêtes sur les tables et en vérifiant les tables des erreurs de clé étrangère. Il peut être utilisé pour détecter les contraintes de clé étrangère manquantes et pour enregistrer les erreurs de clé étrangère en temps réel.

Le script recherche les erreurs de clé étrangère dans les bases de données spécifiées et enregistre les résultats dans la table spécifiée. Il est conçu pour être utilisé une seule fois pour identifier et corriger les problèmes de clé étrangère.

SORTIE

Le script ne produit aucune sortie normale à STDOUT. S'il y a des problèmes avec le script ou des mises à jour disponibles, ils sont imprimés à STDOUT. Des informations détaillées sur les erreurs sont imprimées à STDERR.

OPTIONS

--databases
Spécifie les bases de données à vérifier. Ceci est une option requise.
--daemonize
Exécute le script en arrière-plan.
--dry-run
Affiche les modifications qui seraient apportées sans réellement les apporter.
--help
Affiche l'aide et quitte.
--interval
L'intervalle en secondes entre les vérifications. Ceci est utilisé lorsque le script est exécuté en mode daemon.
--log-table
La table dans laquelle enregistrer les erreurs de clé étrangère. Ceci est une option requise.
--pid
Enregistre l'ID du processus dans le fichier spécifié. Ceci est utilisé lorsque le script est exécuté en mode daemon.
--print-interval
L'intervalle en secondes entre l'impression de messages de statut. Ceci est utilisé lorsque le script est exécuté en mode daemon.
--version-check
Vérifie si une nouvelle version du script est disponible. Ceci est activé par défaut.

Les options DSN sont décrites dans la section DSN OPTIONS.

OPTIONS DSN

Ces options DSN sont utilisées pour créer un DSN. Chaque option est donnée comme "option=valeur". Les options ne respectent pas la casse, donc P et p ne sont pas la même option. Il ne peut y avoir d'espace avant ou après le "=" et si la valeur contient des espaces, elle doit être mise entre guillemets. Les options DSN sont séparées par des virgules. Voir la page de manuel percona-toolkit pour plus de détails.

  • charset

    Jeu de caractères par défaut.

  • database

    Base de données par défaut.

  • mysql_read_default_file

    Ne lit que les options par défaut du fichier donné.

  • host

    Se connecte à l'hôte.

  • password

    Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple".

  • port

    Numéro de port à utiliser pour la connexion.

  • mysql_socket

    Fichier socket à utiliser pour la connexion.

  • t

    Table dans laquelle stocker les erreurs de clé étrangère.

  • user

    Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

  • mysql_ssl

    Crée une connexion SSL.

ENVIRONNEMENT

La variable d'environnement "PTDEBUG" active la sortie de débogage détaillée sur STDERR. Pour activer le débogage et capturer toute la sortie dans un fichier, exécutez l'outil comme suit :

PTDEBUG=1 pt-fk-error-logger ... > FICHIER 2>&1

Attention : la sortie de débogage est volumineuse et peut générer plusieurs mégaoctets de sortie.

ATTENTION

L'utilisation de <PTDEBUG> peut exposer des mots de passe. Lorsque le débogage est activé, tous les paramètres de la ligne de commande sont affichés dans la sortie.

EXIGENCES SYSTEME

Vous avez besoin de Perl, DBI, DBD::mysql et de certains packages de base qui devraient être installés dans toute version raisonnablement récente de Perl.

BOGUES

Pour une liste des bogues connus, voir https://jira.percona.com/projects/PT/issues.

Veuillez signaler les bogues à https://jira.percona.com/projects/PT. Incluez les informations suivantes dans votre rapport de bogue :

  • Fichiers d'entrée (fichiers log/dump/config, etc.)

Si possible, incluez la sortie de débogage en exécutant l'outil avec "PTDEBUG" ; voir "ENVIRONNEMENT".
