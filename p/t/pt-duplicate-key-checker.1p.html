PT-DUPLICATE-KEY-CHECKER(1) Documentation Perl fournie par l'utilisateur PT-DUPLICATE-KEY-CHECKER(1)

NOM

pt-duplicate-key-checker - Trouver les index et clés étrangères en double sur les tables MySQL.

SYNTAXE

Utilisation : pt-duplicate-key-checker [OPTIONS] [DSN]

pt-duplicate-key-checker examine les tables MySQL à la recherche d'index et de clés étrangères en double ou redondants. Les options de connexion sont lues à partir des fichiers d'options MySQL.

pt-duplicate-key-checker --host host1

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Examiner les "BUGS" connus de l'outil
  • Tester l'outil sur un serveur non opérationnel
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

Ce programme examine la sortie de SHOW CREATE TABLE sur les tables MySQL, et s'il trouve des index qui couvrent les mêmes colonnes qu'un autre index dans le même ordre, ou qui couvrent un préfixe gauche exact d'un autre index, il affiche les index suspects. Par défaut, les index doivent être du même type, donc un index BTREE n'est pas un duplicata d'un index FULLTEXT, même s'ils ont les mêmes colonnes. Vous pouvez outrepasser ce comportement.

Il recherche également les clés étrangères en double. Une clé étrangère en double couvre les mêmes colonnes qu'une autre dans la même table et référence la même table parente.

La sortie se termine par un bref résumé qui comprend une estimation de la taille totale, en octets, utilisée par les index en double. Ceci est calculé en multipliant la longueur de l'index par le nombre de lignes dans leurs tables respectives.

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Référez-vous à la "SYNTAXE" et aux informations d'utilisation pour les détails.

--all-structs
Comparer les index avec des structures différentes (BTREE, HASH, etc).

Par défaut, cette option est désactivée, car un index BTREE qui couvre les mêmes colonnes qu'un index FULLTEXT n'est pas vraiment un duplicata, par exemple.

--ask-pass
Demander un mot de passe lors de la connexion à MySQL.
--charset
forme courte : -A; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, définit le mode binaire de Perl sur STDOUT en utf8, passe l'option mysql_enable_utf8 à DBD::mysql et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur définit le mode binaire sur STDOUT sans la couche utf8 et exécute SET NAMES après la connexion à MySQL.

--[no]clustered
par défaut : oui

Les colonnes PK ajoutées à la clé secondaire sont en double.

Détecte lorsqu'un suffixe d'une clé secondaire est un préfixe gauche de la clé primaire, et le traite comme une clé en double. Ne détecte cette condition que sur les moteurs de stockage dont les clés primaires sont groupées (actuellement InnoDB, TokuDB et MyRocks).

Les moteurs de stockage groupés ajoutent les colonnes de la clé primaire aux nœuds feuilles de toutes les clés secondaires de toute façon, vous pourriez donc considérer redondant qu'elles apparaissent également dans les nœuds internes. Bien sûr, vous pouvez également les vouloir dans les nœuds internes, car leur seule présence dans les nœuds feuilles n'aide pas pour certaines requêtes. Cependant, cela aide pour les requêtes d'index de couverture.

Voici un exemple de clé considérée comme redondante avec cette option :

PRIMARY KEY  (`a`)
KEY `b` (`b`,`a`)

L'utilisation de tels index est plutôt subtile. Par exemple, supposons que vous ayez la requête suivante :

SELECT ... WHERE b=1 ORDER BY a;

Cette requête effectuera un filesort si nous supprimons l'index sur "b,a". Mais si nous raccourcissons l'index sur "b,a" pour qu'il ne devienne que "b" et supprimons également ORDER BY, la requête devrait retourner les mêmes résultats.

L'outil suggère de raccourcir les clés groupées en double en supprimant la clé et en la réajoutant sans le préfixe de la clé primaire. La clé groupée raccourcie peut toujours dupliquer une autre clé, mais l'outil ne peut pas actuellement détecter quand cela se produit sans être exécuté une seconde fois pour vérifier à nouveau les clés groupées nouvellement raccourcies. Par conséquent, si vous raccourcissez des clés groupées en double, vous devriez réexécuter l'outil.

--config
type : Tableau

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, cela doit être la première option sur la ligne de commande.

--databases
forme courte : -d; type : hachage

Vérifier uniquement cette liste de bases de données séparées par des virgules.

--defaults-file
forme courte : -F; type : chaîne

Lire uniquement les options mysql à partir du fichier donné. Vous devez fournir un chemin absolu.

--engines
forme courte : -e; type : hachage

Vérifier uniquement les tables dont le moteur de stockage est dans cette liste séparée par des virgules.

--help
Afficher l'aide et quitter.
--host
forme courte : -h; type : chaîne

Se connecter à l'hôte.

--ignore-databases
type : Hachage

Ignorer cette liste de bases de données séparées par des virgules.

--ignore-engines
type : Hachage

Ignorer cette liste de moteurs de stockage séparés par des virgules.

--ignore-order
Ignorer l'ordre des index, donc KEY(a,b) duplique KEY(b,a).
--ignore-tables
type : Hachage

Ignorer cette liste de tables séparées par des virgules. Les noms de tables peuvent être qualifiés avec le nom de la base de données.

--key-types
type : chaîne; par défaut : fk

Vérifier les clés étrangères en double (f=foreign keys), les clés (k=keys) ou les deux (fk=both).

--password
forme courte : -p; type : chaîne

Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

--pid
type : chaîne

Créer le fichier PID donné. L'outil ne démarrera pas si le fichier PID existe déjà et que le PID qu'il contient est différent du PID actuel. Cependant, si le fichier PID existe et que le PID qu'il contient n'est plus en cours d'exécution, l'outil remplacera le fichier PID par le PID actuel. Le fichier PID est supprimé automatiquement à la sortie de l'outil.

--port
forme courte : -P; type : entier

Numéro de port à utiliser pour la connexion.

--set-vars
type : Tableau

Définir les variables MySQL dans cette liste de paires "variable=valeur" séparées par des virgules.

Par défaut, l'outil définit :

wait_timeout=10000

Les variables spécifiées sur la ligne de commande remplacent ces valeurs par défaut. Par exemple, spécifier "--set-vars wait_timeout=500" remplace la valeur par défaut de 10000.

L'outil affiche un avertissement et continue si une variable ne peut pas être définie.

--socket
forme courte : -S; type : chaîne

Fichier socket à utiliser pour la connexion.

--[no]sql
par défaut : oui

Afficher l'instruction DROP KEY pour chaque clé en double. Par défaut, une instruction ALTER TABLE DROP KEY est imprimée sous chaque clé en double afin que, si vous souhaitez supprimer la clé en double, vous puissiez copier-coller l'instruction dans MySQL.

Pour désactiver l'impression de ces instructions, spécifiez "--no-sql".

--[no]summary
par défaut : oui

Afficher un résumé des index à la fin de la sortie.

--
type : Hash

Vérifier uniquement les tables de cette liste séparée par des virgules. Les noms de tables peuvent être qualifiés avec le nom de la base de données.

--user
forme courte : -u; type : chaîne

Nom d'utilisateur à utiliser lors de la connexion.

--version
Afficher les informations de version et quitter.
--where
type : chaîne

Condition WHERE pour exclure les lignes des tables. Notez que cela ne s'applique pas aux clés étrangères.

EXEMPLES

Pour trouver tous les index et clés étrangères en double dans toutes les bases de données sur l'hôte local, exécutez la commande suivante :

pt-duplicate-key-checker --user=root

Pour trouver uniquement les index en double dans la base de données `test` sur l'hôte `db1` :

pt-duplicate-key-checker --host db1 --user root --databases test --key-types k

Pour trouver tous les index et clés étrangères en double sur toutes les tables de toutes les bases de données, sauf `mysql` et `information_schema`, et pour imprimer les instructions `DROP KEY` :

pt-duplicate-key-checker --user=root --ignore-databases mysql,information_schema

Pour trouver les index en double sur toutes les tables dont le moteur de stockage est InnoDB, sauf pour les tables `t1` et `t2` de la base de données `db1` :

pt-duplicate-key-checker --user=root --engines innodb --ignore-tables db1.t1,db1.t2

Pour trouver les index en double dont l'ordre des colonnes est ignoré :

pt-duplicate-key-checker --user=root --ignore-order

pt-duplicate-key-checker(1p) — Percona Toolkit Documentation

NAME

pt-duplicate-key-checker

finds duplicate and redundant indexes in MySQL tables

SYNOPSIS

pt-duplicate-key-checker [OPTIONS] [DSN]

RISKS

This tool is safe to run on production servers. It never makes changes to your data or schema. However, it's always a good idea to back up your database before making any changes to your schema.

DESCRIPTION

This tool finds duplicate and redundant indexes in MySQL tables. It can also find redundant indexes that are not duplicate, such as when an index is composed of the first N columns of another index.

This tool is useful for cleaning up your database schema. Redundant indexes can slow down write operations, increase disk space usage, and generally make your database harder to manage.

The tool works by examining the schema of your tables and identifying indexes that are either duplicates or redundant. It then reports these indexes, along with the SQL statements required to remove them.

It can connect to a MySQL server using a DSN (Data Source Name) or by specifying connection options on the command line.

OPTIONS

--databases DB1,DB2,...
short form: -d; type: string

Check only the specified comma-separated list of databases.

--dry-run
type: boolean

Print the ALTER TABLE statements that would drop redundant indexes, but do not execute them.

--execute
type: boolean

Execute the ALTER TABLE statements that would drop redundant indexes. This option implies "--dry-run".

--index-prefix
type: string

If specified, the tool will only consider indexes that start with this prefix.

--isolate-unique-indexes
type: boolean

When checking for redundant indexes, do not consider unique indexes. This is useful if you want to keep unique indexes for data integrity purposes, even if they are redundant.

--isolate-schemas
type: boolean

Check each database independently. This is useful when working with servers that have a large number of databases, as it can prevent excessive memory usage.

--no-check-replication
type: boolean

Do not check if the server is a primary or replica. This is useful when running the tool on a replica server, or when you do not want to check replication status.

--no-check-table-schema
type: boolean

Do not check table schema. This is useful when working with very large tables, as it can speed up the process.

--only-check-unique-indexes
type: boolean

Only check unique indexes. This is useful if you want to ensure that your unique indexes are not redundant.

--print-sql
type: boolean

Print the ALTER TABLE statements that would drop redundant indexes. This option is implied by "--dry-run" and "--execute".

--queries-per-second
short form: -q; type: integer

The rate at which to execute queries per second. Default is 1.0.

--skip-databases
short form: -D; type: string

Check all databases except the specified comma-separated list of databases.

--skip-tables
short form: -t; type: hash

Check only this comma-separated list of tables.

Table names may be qualified with the database name.

--user
short form: -u; type: string

User for login if not current user.

--verbose
short form: -v

Output all keys and/or foreign keys found, not just redundant ones.

--version
Show version and exit.
--[no]version-check
default: yes

Check for the latest version of Percona Toolkit, MySQL, and other programs.

This is a standard "check for updates automatically" feature, with two additional features. First, the tool checks its own version and also the versions of the following software: operating system, Percona Monitoring and Management (PMM), MySQL, Perl, MySQL driver for Perl (DBD::mysql), and Percona Toolkit. Second, it checks for and warns about versions with known problems. For example, MySQL 5.5.25 had a critical bug and was re-released as 5.5.25a.

A secure connection to Percona’s Version Check database server is done to perform these checks. Each request is logged by the server, including software version numbers and unique ID of the checked system. The ID is generated by the Percona Toolkit installation script or when the Version Check database call is done for the first time.

Any updates or known problems are printed to STDOUT before the tool's normal output. This feature should never interfere with the normal operation of the tool.

For more information, visit https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

DSN OPTIONS

These DSN options are used to create a DSN. Each option is given like "option=value". The options are case-sensitive, so P and p are not the same option. There cannot be whitespace before or after the "=" and if the value contains whitespace it must be quoted. DSN options are comma-separated. See the percona-toolkit manpage for full details.

  • A

    dsn: charset; copy: yes

    Default character set.

  • D

    dsn: database; copy: yes

    Default database.

  • F

    dsn: mysql_read_default_file; copy: yes

    Only read default options from the given file

  • h

    dsn: host; copy: yes

    Connect to host.

  • p

    dsn: password; copy: yes

    Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

  • P

    dsn: port; copy: yes

    Port number to use for connection.

  • S

    dsn: mysql_socket; copy: yes

    Socket file to use for connection.

  • u

    dsn: user; copy: yes

    User for login if not current user.

  • s

    dsn: mysql_ssl; copy: yes

    Create SSL connection

ENVIRONMENT

The environment variable "PTDEBUG" enables verbose debugging output to STDERR. To enable debugging and capture all output to a file, run the tool like:

PTDEBUG=1 pt-duplicate-key-checker ... > FILE 2>&1

Be careful: debugging output is voluminous and can generate several megabytes of output.

ATTENTION

Using <PTDEBUG> might expose passwords. When debug is enabled, all command line parameters are shown in the output.

SYSTEM REQUIREMENTS

You need Perl, DBI, DBD::mysql, and some core packages that ought to be installed in any reasonably new version of Perl.
