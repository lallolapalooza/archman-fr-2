PTHREAD_SETSCHEDPRIO(3P) Manuel du programmeur POSIX PTHREAD_SETSCHEDPRIO(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_setschedprio — accès aux paramètres dynamiques de planification des threads (THREADS TEMPS RÉEL)

SYNTAXE

#include <pthread.h>
int pthread_setschedprio(pthread_t thread, int prio);

DESCRIPTION

La fonction pthread_setschedprio() définit la priorité de planification pour le thread dont l'identifiant de thread est thread à la valeur donnée par prio. Voir Politiques de planification pour une description de la manière dont cet appel de fonction affecte l'ordre du thread dans la liste des threads pour sa nouvelle priorité.

Si la fonction pthread_setschedprio() échoue, la priorité de planification du thread cible ne sera pas modifiée.

VALEUR RENVOYÉE

En cas de succès, la fonction pthread_setschedprio() renvoie zéro ; sinon, un numéro d'erreur est renvoyé pour indiquer l'erreur.

ERREURS

La fonction pthread_setschedprio() peut échouer si :

EINVAL
La valeur de prio est invalide pour la politique de planification du thread spécifié.
EPERM
L'appelant n'a pas les privilèges appropriés pour définir la priorité de planification du thread spécifié.

La fonction pthread_setschedprio() ne doit pas renvoyer le code d'erreur [EINTR].

JUSTIFICATION

La fonction pthread_setschedprio() offre un moyen à une application d'augmenter temporairement sa priorité, puis de la réduire à nouveau, sans avoir l'effet secondaire indésirable de céder à d'autres threads de même priorité. Ceci est nécessaire si l'application doit implémenter ses propres stratégies pour limiter l'inversion de priorité, telles que l'héritage de priorité ou les plafonds de priorité. Cette capacité est particulièrement importante si l'implémentation ne prend pas en charge les options de protection de priorité des threads ou d'héritage de priorité des threads, mais même si ces options sont prises en charge, elle est nécessaire si l'application doit limiter l'héritage de priorité pour d'autres ressources, telles que les sémaphores.

Les développeurs du standard ont estimé que, bien qu'il puisse être conceptuellement préférable de résoudre ce problème en modifiant la spécification de pthread_setschedparam(), il était trop tard pour apporter un tel changement, car il pourrait y avoir des implémentations qui devraient être modifiées. Par conséquent, cette nouvelle fonction a été introduite.

Si une implémentation détecte l'utilisation d'un identifiant de thread après la fin de sa durée de vie, il est recommandé que la fonction échoue et signale une erreur [ESRCH].
