PTHREAD_DETACH(3P) Manuel du programmeur POSIX PTHREAD_DETACH(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_detach — détacher un thread

SYNOPSIS

#include <pthread.h>
int pthread_detach(pthread_t thread);

DESCRIPTION

La fonction pthread_detach() indique à l'implémentation que l'espace alloué au thread thread peut être récupéré lorsque ce thread se termine. Si thread ne s'est pas encore terminé, pthread_detach() ne le fera pas terminer.

Le comportement est indéfini si la valeur spécifiée par l'argument thread de pthread_detach() ne fait pas référence à un thread joignable.

VALEUR DE RETOUR

Si l'appel réussit, pthread_detach() renvoie 0 ; sinon, un numéro d'erreur est renvoyé pour indiquer l'erreur.

ERREURS

La fonction pthread_detach() ne renverra pas le code d'erreur [EINTR].

RATIONALE

Les fonctions pthread_join() ou pthread_detach() devraient éventuellement être appelées pour chaque thread créé afin que l'espace associé au thread puisse être récupéré.

Il a été suggéré qu'une fonction de « détachement » n'est pas nécessaire ; l'attribut de création de thread detachstate est suffisant, car un thread n'a jamais besoin d'être détaché dynamiquement. Cependant, le besoin se fait sentir dans au moins deux cas :

1.
Dans un gestionnaire d'annulation de pthread_join(), il est presque essentiel d'avoir une fonction pthread_detach() afin de détacher le thread sur lequel pthread_join() attendait. Sans elle, il serait nécessaire que le gestionnaire effectue un autre pthread_join() pour tenter de détacher le thread, ce qui retarderait le traitement de l'annulation pendant une période illimitée et introduirait un nouvel appel à pthread_join(), qui pourrait lui-même nécessiter un gestionnaire d'annulation. Un détachement dynamique est presque essentiel dans ce cas.
2.
Afin de détacher le « thread initial » (ce qui peut être souhaitable dans les processus qui configurent des threads serveur).

Si une implémentation détecte que la valeur spécifiée par l'argument thread de pthread_detach() ne fait pas référence à un thread joignable, il est recommandé que la fonction échoue et signale une erreur [EINVAL].

Si une implémentation détecte l'utilisation d'un identifiant de thread après la fin de sa durée de vie, il est recommandé que la fonction échoue et signale une erreur [ESRCH].
