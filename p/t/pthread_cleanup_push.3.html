pthread_cleanup_push(3) Manuel des fonctions de bibliothèque pthread_cleanup_push(3)

NOM

pthread_cleanup_push, pthread_cleanup_pop - pousser et dépiler des gestionnaires de nettoyage d'annulation de thread

BIBLIOTHÈQUE

Bibliothèque POSIX threads (libpthread, -lpthread)

SYNTAXE

#include <pthread.h>
void pthread_cleanup_push(typeof(void (void *)) *routine, void *arg);
void pthread_cleanup_pop(int execute);

DESCRIPTION

Ces fonctions manipulent la pile des gestionnaires de nettoyage d'annulation du thread appelant. Un gestionnaire de nettoyage est une fonction qui est automatiquement exécutée lorsqu'un thread est annulé (ou dans diverses autres circonstances décrites ci-dessous) ; il peut, par exemple, déverrouiller un mutex afin qu'il devienne disponible pour d'autres threads du processus.

La fonction pthread_cleanup_push() pousse routine sur le sommet de la pile des gestionnaires de nettoyage. Lorsque routine est appelée plus tard, elle recevra arg comme argument.

La fonction pthread_cleanup_pop() retire le gestionnaire au sommet de la pile des gestionnaires de nettoyage et l'exécute éventuellement si execute est différent de zéro.

Un gestionnaire de nettoyage d'annulation est dépilé et exécuté dans les circonstances suivantes :

•
Lorsqu'un thread est annulé, tous les gestionnaires de nettoyage empilés sont dépilés et exécutés dans l'ordre inverse de celui dans lequel ils ont été poussés sur la pile.
•
Lorsqu'un thread se termine en appelant pthread_exit(3), tous les gestionnaires de nettoyage sont exécutés comme décrit dans le point précédent. (Les gestionnaires de nettoyage ne sont *pas* appelés si le thread se termine en effectuant un return de la fonction de démarrage du thread.)
•
Lorsqu'un thread appelle pthread_cleanup_pop() avec un argument execute non nul, le gestionnaire de nettoyage le plus haut est dépilé et exécuté.

POSIX.1 autorise pthread_cleanup_push() et pthread_cleanup_pop() à être implémentées comme des macros qui s'étendent en texte contenant respectivement '{' et '}'. Pour cette raison, l'appelant doit s'assurer que les appels à ces fonctions sont appariés au sein de la même fonction et au même niveau d'imbrication lexical. (Autrement dit, un gestionnaire de nettoyage n'est établi que pendant l'exécution d'une section de code spécifiée.)

L'appel à longjmp(3) (siglongjmp(3)) produit des résultats indéfinis si un appel à pthread_cleanup_push() ou pthread_cleanup_pop() a été effectué sans l'appel correspondant de la paire depuis que le tampon de saut a été rempli par setjmp(3) (sigsetjmp(3)). De même, l'appel à longjmp(3) (siglongjmp(3)) à l'intérieur d'un gestionnaire de nettoyage produit des résultats indéfinis, sauf si le tampon de saut a également été rempli par setjmp(3) (sigsetjmp(3)) à l'intérieur du gestionnaire.

VALEUR DE RETOUR

Ces fonctions ne retournent aucune valeur.

ERREURS

Il n'y a pas d'erreurs.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
pthread_cleanup_push (), pthread_cleanup_pop () Sécurité des threads MT-Safe

VERSIONS

Sur glibc, les fonctions pthread_cleanup_push() et pthread_cleanup_pop() sont implémentées comme des macros qui s'étendent en texte contenant respectivement '{' et '}'. Cela signifie que les variables déclarées dans la portée des appels appariés à ces fonctions ne seront visibles que dans cette portée.

POSIX.1 indique que l'effet de l'utilisation de return, break, continue ou goto pour quitter prématurément un bloc encadré par pthread_cleanup_push() et pthread_cleanup_pop() est indéfini. Les applications portables doivent éviter de faire cela.

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001. glibc 2.0.

EXEMPLES

Le programme ci-dessous fournit un exemple simple d'utilisation des fonctions décrites dans cette page. Le programme crée un thread qui exécute une boucle encadrée par pthread_cleanup_push() et pthread_cleanup_pop(). Cette boucle incrémente une variable globale, cnt, une fois par seconde. Selon les arguments de ligne de commande fournis, le thread principal envoie une requête d'annulation à l'autre thread, ou définit une variable globale qui amène l'autre thread à quitter sa boucle et à se terminer normalement (en effectuant un return).

Dans la session shell suivante, le thread principal envoie une requête d'annulation à l'autre thread :


$ ./a.out;
Nouveau thread démarré
cnt = 0
cnt = 1
Annulation du thread
Gestionnaire de nettoyage appelé
Thread annulé ; cnt = 0

D'après ce qui précède, nous constatons que le thread a été annulé et que le gestionnaire de nettoyage d'annulation a été appelé et a réinitialisé la valeur de la variable globale cnt à 0.

Lors de la prochaine exécution, le programme principal définit une variable globale qui amène l'autre thread à se terminer normalement :


$ ./a.out x;
Nouveau thread démarré
cnt = 0
cnt = 1
Thread terminé normalement ; cnt = 2

D'après ce qui précède, nous constatons que le gestionnaire de nettoyage n'a pas été exécuté (car cleanup_pop_arg était 0), et par conséquent, la valeur de cnt n'a pas été réinitialisée.

Lors de la prochaine exécution, le programme principal définit une variable globale qui amène l'autre thread à se terminer normalement, et fournit une valeur non nulle pour cleanup_pop_arg :


$ ./a.out x 1;
Nouveau thread démarré
cnt = 0
cnt = 1
Gestionnaire de nettoyage appelé
Thread terminé normalement ; cnt = 0

Dans ce qui précède, nous constatons que bien que le thread n'ait pas été annulé, le gestionnaire de nettoyage a été exécuté, car l'argument donné à pthread_cleanup_pop() était non nul.

Source du programme

#include <err.h>
#include <errno.h>
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
static int done = 0;
static int cleanup_pop_arg = 0;
static int cnt = 0;
static void
cleanup_handler(void *arg)
{
    printf("Gestionnaire de nettoyage appelé\n");
    cnt = 0;
}
static void *
thread_start(void *arg)
{
    time_t curr;
    printf("Nouveau thread démarré\n");
    pthread_cleanup_push(cleanup_handler, NULL);
    curr = time(NULL);
    while (!done) {
        pthread_testcancel();           /* Un point d'annulation */
        if (curr < time(NULL)) {
            curr = time(NULL);
            printf("cnt = %d\n", cnt);  /* Un point d'annulation */
            cnt++;
        }
    }
    pthread_cleanup_pop(cleanup_pop_arg);
    return NULL;
}
int
main(int argc, char *argv[])
{
    pthread_t thr;
    int s;
    void *res;
    s = pthread_create(&thr, NULL, thread_start, NULL);
    if (s != 0)
        errc(EXIT_FAILURE, s, "pthread_create");
    sleep(2);           /* Laisser le nouveau thread s'exécuter un moment */
    if (argc > 1) {
        if (argc > 2)
            cleanup_pop_arg = atoi(argv[2]);
        done = 1;
    } else {
        printf("Annulation du thread\n");
        s = pthread_cancel(thr);
        if (s != 0)
            errc(EXIT_FAILURE, s, "pthread_cancel");
    }
    s = pthread_join(thr, &res);
    if (s != 0)
        errc(EXIT_FAILURE, s, "pthread_join");
    if (res == PTHREAD_CANCELED)
        printf("Thread annulé ; cnt = %d\n", cnt);
    else
        printf("Thread terminé normalement ; cnt = %d\n", cnt);
    exit(EXIT_SUCCESS);
}
