NOM

pt-mysql-summary - Résume les informations MySQL de manière agréable.

SYNTAXE

Usage : pt-mysql-summary [OPTIONS]

pt-mysql-summary résume de manière pratique l'état et la configuration d'un serveur de base de données MySQL afin que vous puissiez en apprendre l'essentiel d'un coup d'œil. Ce n'est pas un outil de réglage ou de diagnostic. Il produit un rapport facile à comparer et qui peut être collé dans des e-mails sans perdre le formatage. Il devrait bien fonctionner sur tous les systèmes UNIX modernes.

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Consulter les " BUGS " connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-mysql-summary fonctionne en se connectant à un serveur de base de données MySQL et en interrogeant celui-ci pour obtenir des informations de statut et de configuration. Il enregistre ces données dans des fichiers dans un répertoire temporaire, puis les formate proprement à l'aide d'awk et d'autres langages de script.

Pour l'utiliser, exécutez-le simplement. Vous pouvez éventuellement ajouter un double trait d'union suivi des mêmes options de ligne de commande que vous utiliseriez pour vous connecter à MySQL, comme suit :

pt-mysql-summary --user=root

L'outil interagit de manière minimale avec le serveur sur lequel il s'exécute. Il suppose que vous l'exécuterez sur le même serveur que vous inspectez, et par conséquent, il suppose qu'il pourra trouver le fichier de configuration my.cnf, par exemple. Cependant, il devrait se dégrader gracieusement si ce n'est pas le cas. Notez toutefois que sa sortie n'indique pas quelles informations proviennent de la base de données MySQL et quelles informations proviennent du système d'exploitation hôte, il est donc possible que des sorties confuses soient générées si vous exécutez l'outil sur un serveur et vous connectez à un serveur de base de données MySQL s'exécutant sur un autre serveur.

SORTIE

De nombreuses sorties de cet outil sont délibérément arrondies pour montrer leur magnitude mais pas le détail exact. C'est ce qu'on appelle l'arrondi flou (fuzzy-rounding). L'idée est qu'il n'est pas important que un serveur exécute 918 requêtes par seconde ou 921 requêtes par seconde ; une variation si faible est insignifiante et rend seulement la sortie difficile à comparer à d'autres serveurs. L'arrondi flou arrondit par plus grands incréments à mesure que l'entrée augmente. Il commence par arrondir au plus proche 5, puis au plus proche 10, puis 25, et répète ensuite par un facteur de 10 plus grand (50, 100, 250), et ainsi de suite, à mesure que l'entrée augmente.

Cette section est un résumé de la sortie de SHOW PROCESSLIST. Chaque sous-section est agrégée par un élément différent, qui est indiqué comme en-tête de la première colonne. Lorsqu'elle est résumée par Commande, chaque ligne de SHOW PROCESSLIST est incluse, mais sinon, les lignes dont la Commande est Sleep sont exclues des colonnes SUM et MAX, afin qu'elles ne faussent pas trop les nombres. Dans l'exemple montré, le serveur est inactif à l'exception de cet outil lui-même, et d'une réplique connectée, qui exécute Binlog Dump.

Les colonnes sont le nombre de lignes incluses, le nombre qui n'est pas en état Sleep, la somme de la colonne Temps, et le Temps maximum de la colonne. Les nombres sont arrondis de manière floue.

Cette section montre des compteurs sélectionnés à partir de deux instantanés de SHOW GLOBAL STATUS, recueillis à environ 10 secondes d'intervalle et arrondis de manière floue. Elle n'inclut que les éléments qui sont des compteurs incrémentiels ; elle n'inclut pas les nombres absolus tels que la variable de statut Threads_running, qui représente une valeur actuelle, plutôt qu'un nombre accumulé sur le temps.

La première colonne est le nom de la variable, et la deuxième colonne est le compteur du premier instantané divisé par 86400 (le nombre de secondes dans une journée), vous pouvez donc voir l'ampleur de la modification du compteur par jour. 86400 s'arrondit de manière floue à 90000, donc le compteur Uptime devrait toujours être d'environ 90000.

La troisième colonne est la valeur du premier instantané, divisée par Uptime puis arrondie de manière floue, elle représente donc approximativement la vitesse à laquelle le compteur croît par seconde sur le temps de fonctionnement du serveur.

La quatrième colonne est la différence incrémentielle entre le premier et le second instantané, divisée par la différence de temps de fonctionnement puis arrondie de manière floue. Par conséquent, elle montre à quelle vitesse le compteur croît par seconde au moment où le rapport a été généré.

pt-mysql-summary(1p) — Arch Linux

NAME

pt-mysql-summary

collects summary information about MySQL servers

SYNOPSIS

pt-mysql-summary [OPTIONS] [DSN]

RISKS

This tool may very slowly query information_schema tables. The information_schema can be slow on some MySQL versions.

DESCRIPTION

pt-mysql-summary is a command-line tool that collects summary information about a MySQL server, including configuration, status variables, variables, features, replication status, etc.

It collects information from various sources:

  • `SHOW GLOBAL STATUS`
  • `SHOW GLOBAL VARIABLES`
  • `SHOW SLAVE STATUS`
  • `SHOW MASTER STATUS`
  • `SHOW ENGINES`
  • `SHOW PLUGINS`
  • `SHOW VARIABLES LIKE '%version%'`
  • MySQL version and uptime
  • Data directory information
  • InnoDB status
  • Configuration file (my.cnf)

The tool can run in two primary modes: live collection and sample-based collection. Live collection connects to the server and gathers data directly. Sample-based collection uses pre-collected data files, which is useful for analyzing historical data or when direct access to the server is not possible.

OUTPUT

The tool outputs a summary of the collected information to standard output. The format is designed to be human-readable and can also be parsed by other tools.

When using the --save-samples option, the tool saves collected data into files in the specified directory. These files can later be used with the --read-samples option to generate a report without accessing the live server.

OPTIONS

--ask-pass
Prompt for a password.
--config
type: string

Read configuration from this file. Any DSN options on the command line override options in this file.

--defaults-file
type: string

Only read defaults from the given file. See "Using Defaults Files" below.

--dry-run
type: boolean; default: false

Do not connect to the database or do anything, just show what would have been done.

--help
Show help and exit.
--host
short form: -h; type: string

Host name or IP address of the server.

--ignore-conditions
type: string array

Do not report on these conditions. Conditions are case-insensitive.

--ignore-innodb-table-monitor
type: boolean; default: false

When gathering InnoDB status, do not check the information_schema.innodb_table_monitor table, as this can be slow.

--interval
type: int; default: 1

Seconds to sleep between samples.

--limit-to-table-monitor
type: string array

Only run the table monitor for these tables.

--log
type: string

Log MySQL commands and output to the specified file.

--log-stderr
type: boolean; default: false

Log all output to stderr as well as stdout.

--long-query-time
type: float; default: 10

The value of the long_query_time system variable. This is used to analyze queries that have run longer than this value.

--memlock
type: boolean; default: false

Lock the tool's code and data in memory. This may prevent the tool from being swapped out and may improve performance.

--no-version-check
type: boolean; default: false

Do not check for a newer version of the tool.

--password
short form: -p; type: string

Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

--port
short form: -P; type: int

Port number to use for connection.

--read-samples
type: string

Create a report from the files found in this directory.

--save-samples
type: string

Save the data files used to generate the summary in this directory.

--sleep
type: int; default: 10

Seconds to sleep when gathering status counters.

--socket
short form: -S; type: string

Socket file to use for connection.

--user
short form: -u; type: string

User for login if not current user.

--version
Print tool's version and exit.

ENVIRONMENT

This tool does not use any environment variables.

SYSTEM REQUIREMENTS

This tool requires Bash v3 or newer, Perl 5.8 or newer, and binutils. These are generally already provided by most distributions. On BSD systems, it may require a mounted procfs.
