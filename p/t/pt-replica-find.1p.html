NOM

pt-replica-find - Trouve et affiche l'arbre de la hiérarchie de réplication des répliques MySQL.

SYNTAXE

Usage : pt-replica-find [OPTIONS] [DSN]

pt-replica-find trouve et affiche un arbre hiérarchique des répliques MySQL.

Exemples :

pt-replica-find --host source-host

RISQUES

Percona Toolkit est mature, éprouvé dans le monde réel et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Examiner les "BOGUES" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-replica-find se connecte à une source de réplication MySQL et trouve ses répliques. Actuellement, la seule chose qu'il puisse faire est d'afficher une vue arborescente de la hiérarchie de réplication.

L'hôte source peut être spécifié de deux manières. La première méthode consiste à utiliser les options de ligne de commande standard liées à la connexion : "--defaults-file", "--password", "--host", "--port", "--socket" ou "--user".

La deuxième méthode pour spécifier l'hôte source est un DSN. Un DSN est une syntaxe spéciale qui peut être soit juste un nom d'hôte (comme "serveur.domaine.com" ou 1.2.3.4), soit une chaîne "clé=valeur,clé=valeur". Les clés sont une seule lettre :

CLÉ SIGNIFICATION
=== ============
h   Se connecter à l'hôte
P   Port à utiliser pour la connexion
S   Fichier socket à utiliser pour la connexion
u   Utilisateur pour la connexion si différent de l'utilisateur courant
p   Mot de passe à utiliser lors de la connexion
F   Lire uniquement les options par défaut du fichier donné

"pt-replica-find" lit tous les fichiers d'options MySQL normaux, tels que ~/.my.cnf, vous n'aurez donc peut-être pas besoin de spécifier du tout le nom d'utilisateur, le mot de passe et d'autres options courantes.

STATUT DE SORTIE

Un statut de sortie de 0 (parfois aussi appelé valeur de retour ou code de retour) indique le succès. Toute autre valeur représente le statut de sortie du processus Perl lui-même.

OPTIONS

Cet outil accepte des arguments supplémentaires en ligne de commande. Reportez-vous à la "SYNTAXE" et aux informations d'utilisation pour plus de détails.

--ask-pass
Demander un mot de passe lors de la connexion à MySQL.
--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, active le mode binaire de Perl sur la sortie standard avec utf8, passe l'option mysql_enable_utf8 à DBD::mysql et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur active le mode binaire sur la sortie standard sans la couche utf8 et exécute SET NAMES après la connexion à MySQL.

--config
type : Tableau

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, cela doit être la première option sur la ligne de commande.

--database
type : chaîne ; forme courte : -D

Base de données à utiliser.

--defaults-file
forme courte : -F ; type : chaîne

Lire uniquement les options mysql du fichier donné. Vous devez fournir un chemin absolu.

--help
Afficher l'aide et quitter.
--host
forme courte : -h ; type : chaîne

Se connecter à l'hôte.

--password
forme courte : -p ; type : chaîne

Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

--pid
type : chaîne

Créer le fichier PID donné. L'outil ne démarrera pas si le fichier PID existe déjà et si le PID qu'il contient est différent du PID courant. Cependant, si le fichier PID existe et que le PID qu'il contient n'est plus en cours d'exécution, l'outil écrasera le fichier PID avec le PID courant. Le fichier PID est supprimé automatiquement lorsque l'outil se termine.

--port
forme courte : -P ; type : entier

Numéro de port à utiliser pour la connexion.

--recurse
type : entier

Nombre de niveaux à parcourir dans la hiérarchie. Par défaut, infini.

Voir "--recursion-method".

--recursion-method
type : tableau ; par défaut : processlist,hosts

Méthode de récursion préférée utilisée pour trouver les répliques.

Les méthodes possibles sont :

MÉTHODE       UTILISE
===========  ==================
processlist  SHOW PROCESSLIST
hosts        SHOW REPLICAS (SHOW SLAVE HOSTS avant MySQL 8.1)
none         Ne pas trouver de répliques

La méthode processlist est préférée car SHOW REPLICAS n'est pas fiable. Cependant, la méthode hosts est nécessaire si le serveur utilise un port non standard (pas 3306). Habituellement, pt-replica-find fait ce qu'il faut et trouve les répliques, mais vous pouvez donner une méthode préférée et elle sera utilisée en premier. Si aucune réplique n'est trouvée, les autres méthodes seront essayées.

--report-format
type : chaîne ; par défaut : summary

Définit les informations sur les répliques qui seront affichées. Le format du rapport peut être l'un des suivants :

  • hostname

    Affiche uniquement le nom d'hôte des répliques. Cela ressemble à :

    127.0.0.1:12345
+- 127.0.0.1:12346
   +- 127.0.0.1:12347
  • summary

    Affiche un résumé des paramètres de chaque réplique. Ce rapport montre plus d'informations sur chaque réplique, comme :

    127.0.0.1:12345
Version         5.1.34-log
Server ID       12345
Uptime          04:56 (démarré le 2010-06-17T11:21:22)
Réplication     N'est pas une réplique, a 1 répliques connectées
Filtres
Journal binaire  STATEMENT
Statut esclave
Mode esclave    STRICT
Auto-incrément  incrément 1, décalage 1
+- 127.0.0.1:12346
   Version         5.1.34-log
   Server ID       12346
   Uptime          04:54 (démarré le 2010-06-17T11:21:24)
   Réplication     Est une réplique, a 1 répliques connectées
   Filtres
   Journal binaire  STATEMENT
   Statut esclave  0 secondes de retard, en cours, aucune erreur
   Mode esclave    STRICT
   Auto-incrément  incrément 1, décalage 1
--resolve-address
Résout l'adresse IP en nom d'hôte. Le rapport affichera l'IP et le nom d'hôte.

Exemple :

10.10.7.14 (dbase1.sample.net)

Peut ralentir l'exécution de quelques secondes.

--slave-user
type : chaîne

Cette option est obsolète et sera supprimée dans les futures versions. Utilisez "--replica-user" à la place.

--slave-password
type : chaîne

Cette option est obsolète et sera supprimée dans les futures versions. Utilisez "--replica-password" à la place.

--replica-user
type : chaîne

Définit l'utilisateur à utiliser pour se connecter aux répliques. Ce paramètre vous permet d'avoir un utilisateur différent avec moins de privilèges sur les répliques, mais cet utilisateur doit exister sur toutes les répliques.

--replica-password
type : chaîne

Définit le mot de passe à utiliser pour se connecter aux répliques. Il peut être utilisé avec --replica-user et le mot de passe de l'utilisateur doit être le même sur toutes les répliques.

--set-vars
type : Tableau

Définit les variables MySQL dans cette liste de paires "variable=valeur" séparées par des virgules.

Par défaut, l'outil définit :

wait_timeout=10000

pt-replica-find(1p) — Percona Toolkit Documentation

NAME

pt-replica-find - find replication replicas

SYNOPSIS

pt-replica-find [OPTIONS] [DSN]

RISKS

This tool requires privileges to connect to MySQL servers and to query replication status. It is recommended to run this tool on a replica that has been thoroughly tested. It is also recommended to back up any critical data before running this tool.

DESCRIPTION

This tool finds replication replicas on a MySQL server. It is useful for discovering and managing replication topologies. It can be used to identify master servers, replica servers, and their relationships.

EXIT STATUS

This tool exits with a status of 0 if successful, and non-zero otherwise.

OPTIONS

--ask-pass
Prompt for a password when connecting to MySQL. Percona Toolkit uses this option to prompt for passwords interactively. If you use this option, you will be prompted for the password on the command line.

This option is not used by pt-replica-find. Use --password instead.

--charset, -A
short form: -A; type: string

Default character set. All character sets that the MySQL client uses to communicate with the MySQL server. See "SET NAMES" in the MySQL manual for more information.

--config
type: string

Read this tool's options from a file.

If the file contains options that are also specified on the command line, the command-line options take precedence.

The file is a comma-separated list of DSNs, each of which is a comma-separated list of `name=value` pairs. For example: `host=127.0.0.1,user=root,password=secret`.

See also: "DSN OPTIONS".

--defaults-file
type: string

Only read default options from the given file. The file is typically named my.cnf. The options in the file are applied to the connection. See the MySQL manual for the exact format and behavior of this file.

If you specify this option on the command line, pt-replica-find only reads options from that file and no other defaults files. If you do not specify this option, pt-replica-find reads options from the standard MySQL defaults files in the standard order.

--defaults-extra-file
type: string

Read default options from the given file in addition to the standard options files. The options from this file are read after the standard options files.

--host, -h
short form: -h; type: string

Connect to host. This option is passed to the MySQL client library.

--password, -p
short form: -p; type: string

Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple".

--port, -P
short form: -P; type: integer

Connect to port. The default is 3306.

--set-vars
type: string

Set the MySQL session variables. For example, "--set-vars wait_timeout=500" overrides the default value of 10000.

The tool prints a warning and continues if a variable cannot be set.

--socket
short form: -S; type: string

Socket file to use for connection.

--user, -u
short form: -u; type: string

User for login if not current user.

--version
Show version and exit.

DSN OPTIONS

These DSN options are used to create a DSN. Each option is given like "option=value". The options are case-sensitive, so P and p are not the same option. There cannot be whitespace before or after the "=" and if the value contains whitespace it must be quoted. DSN options are comma-separated. See the percona-toolkit manpage for full details.

  • A

    dsn: charset; copy: yes

    Default character set.

  • D

    dsn: database; copy: yes

    Default database.

  • F

    dsn: mysql_read_default_file; copy: yes

    Only read default options from the given file

  • h

    dsn: host; copy: yes

    Connect to host.

  • p

    dsn: password; copy: yes

    Password to use when connecting. If password contains commas they must be escaped with a backslash: "exam\,ple"

  • P

    dsn: port; copy: yes

    Port number to use for connection.

  • S

    dsn: mysql_socket; copy: yes

    Socket file to use for connection.

  • u

    dsn: user; copy: yes

    User for login if not current user.

  • s

    dsn: mysql_ssl; copy: yes

    Create SSL connection

ENVIRONMENT

The environment variable "PTDEBUG" enables verbose debugging output to STDERR. To enable debugging and capture all output to a file, run the tool like:

PTDEBUG=1 pt-replica-find ... > FILE 2>&1

Be careful: debugging output is voluminous and can generate several megabytes of output.

ATTENTION

Using <PTDEBUG> might expose passwords. When debug is enabled, all command line parameters are shown in the output.

SYSTEM REQUIREMENTS

You need Perl, DBI, DBD::mysql, and some core packages that ought to be installed in any reasonably new version of Perl.
