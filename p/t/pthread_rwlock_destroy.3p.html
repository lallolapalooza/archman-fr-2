PTHREAD_RWLOCK_DESTROY(3P) Manuel du programmeur POSIX PTHREAD_RWLOCK_DESTROY(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_rwlock_destroy, pthread_rwlock_init — détruire et initialiser un objet de verrou de lecture-écriture

SYNTAXE

#include <pthread.h>
int pthread_rwlock_destroy(pthread_rwlock_t *rwlock);
int pthread_rwlock_init(pthread_rwlock_t *restrict rwlock,
    const pthread_rwlockattr_t *restrict attr);
pthread_rwlock_t rwlock = PTHREAD_RWLOCK_INITIALIZER;

DESCRIPTION

La fonction pthread_rwlock_destroy() détruit l'objet de verrou de lecture-écriture référencé par rwlock et libère toutes les ressources utilisées par le verrou. L'effet d'une utilisation ultérieure du verrou est indéfini jusqu'à ce que le verrou soit réinitialisé par un autre appel à pthread_rwlock_init(). Une implémentation peut faire en sorte que pthread_rwlock_destroy() place l'objet référencé par rwlock dans un état invalide. Les résultats sont indéfinis si pthread_rwlock_destroy() est appelé alors qu'un thread détient rwlock. Tenter de détruire un verrou de lecture-écriture non initialisé entraîne un comportement indéfini.

La fonction pthread_rwlock_init() alloue toutes les ressources nécessaires à l'utilisation du verrou de lecture-écriture référencé par rwlock et initialise le verrou dans un état déverrouillé avec les attributs référencés par attr. Si attr est NULL, les attributs par défaut du verrou de lecture-écriture sont utilisés ; l'effet est le même que de passer l'adresse d'un objet d'attributs de verrou de lecture-écriture par défaut. Une fois initialisé, le verrou peut être utilisé un nombre illimité de fois sans être réinitialisé. Les résultats sont indéfinis si pthread_rwlock_init() est appelé en spécifiant un verrou de lecture-écriture déjà initialisé. Les résultats sont indéfinis si un verrou de lecture-écriture est utilisé sans avoir été préalablement initialisé.

Si la fonction pthread_rwlock_init() échoue, rwlock ne sera pas initialisé et le contenu de rwlock sera indéfini.

Voir la Section 2.9.9, Copies d'objets de synchronisation et mappages alternatifs pour des exigences supplémentaires.

Dans les cas où les attributs par défaut du verrou de lecture-écriture sont appropriés, la macro PTHREAD_RWLOCK_INITIALIZER peut être utilisée pour initialiser les verrous de lecture-écriture. L'effet sera équivalent à une initialisation dynamique par un appel à pthread_rwlock_init() avec le paramètre attr spécifié comme NULL, à l'exception du fait qu'aucun contrôle d'erreur n'est effectué.

Le comportement est indéfini si la valeur spécifiée par l'argument attr de pthread_rwlock_init() ne fait pas référence à un objet d'attributs de verrou de lecture-écriture initialisé.

VALEUR DE RETOUR

En cas de succès, les fonctions pthread_rwlock_destroy() et pthread_rwlock_init() retournent zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_rwlock_init() échoue si :

EAGAIN
Le système manquait des ressources nécessaires (autres que la mémoire) pour initialiser un autre verrou de lecture-écriture.
ENOMEM
La mémoire insuffisante existe pour initialiser le verrou de lecture-écriture.
EPERM
L'appelant n'a pas les privilèges nécessaires pour effectuer l'opération.

Ces fonctions ne doivent pas retourner de code d'erreur [EINTR].

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION APPLICATIVE

Les applications utilisant ces fonctions et les fonctions associées de verrou de lecture-écriture peuvent être sujettes à l'inversion de priorité, comme discuté dans le volume Définitions de base de POSIX.1-2017, Section 3.291, Inversion de priorité.

RATIONALE

Si une implémentation détecte que la valeur spécifiée par l'argument rwlock à pthread_rwlock_destroy() ne fait pas référence à un objet de verrou de lecture-écriture initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].

Si une implémentation détecte que la valeur spécifiée par l'argument attr à pthread_rwlock_init() ne fait pas référence à un objet d'attributs de verrou de lecture-écriture initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].

Si une implémentation détecte que la valeur spécifiée par l'argument rwlock à pthread_rwlock_destroy() ou pthread_rwlock_init() fait référence à un objet de verrou de lecture-écriture verrouillé, ou détecte que la valeur spécifiée par l'argument rwlock à pthread_rwlock_init() fait référence à un objet de verrou de lecture-écriture déjà initialisé, il est recommandé que la fonction échoue et signale une erreur [EBUSY].
