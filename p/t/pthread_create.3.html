pthread_create(3) Manuel des fonctions de bibliothèque pthread_create(3)

NOM

pthread_create - créer un nouveau thread

BIBLIOTHÈQUE

Bibliothèque POSIX threads (libpthread, -lpthread)

SYNTAXE

#include <pthread.h>
int pthread_create(pthread_t *restrict thread,
                   const pthread_attr_t *restrict attr,
                   typeof(void *(void *)) *start_routine,
                   void *restrict arg);

DESCRIPTION

La fonction pthread_create() démarre un nouveau thread dans le processus appelant. Le nouveau thread commence son exécution en appelant start_routine(); arg est passé comme unique argument de start_routine().

Le nouveau thread se termine de l'une des manières suivantes :

•
Il appelle pthread_exit(3), en spécifiant une valeur de statut de sortie qui est disponible pour un autre thread dans le même processus qui appelle pthread_join(3).
•
Il retourne de start_routine(). Ceci est équivalent à appeler pthread_exit(3) avec la valeur fournie dans l'instruction return.
•
Il est annulé (voir pthread_cancel(3)).
•
N'importe lequel des threads du processus appelle exit(3), ou le thread principal effectue un retour de main(). Ceci provoque la terminaison de tous les threads du processus.

L'argument attr pointe vers une structure pthread_attr_t dont le contenu est utilisé au moment de la création du thread pour déterminer les attributs du nouveau thread ; cette structure est initialisée en utilisant pthread_attr_init(3) et les fonctions associées. Si attr est NULL, alors le thread est créé avec les attributs par défaut.

Avant de retourner, un appel réussi à pthread_create() stocke l'identifiant du nouveau thread dans le tampon pointé par thread ; cet identifiant est utilisé pour faire référence au thread dans les appels ultérieurs aux autres fonctions pthreads.

Le nouveau thread hérite d'une copie du masque de signaux du thread appelant (pthread_sigmask(3)). L'ensemble des signaux en attente pour le nouveau thread est vide (sigpending(2)). Le nouveau thread n'hérite pas de la pile de signaux alternative du thread appelant (sigaltstack(2)).

Le nouveau thread hérite de l'environnement flottant du thread appelant (fenv(3)).

La valeur initiale de l'horloge CPU du nouveau thread est de 0 (voir pthread_getcpuclockid(3)).

Détails spécifiques à Linux

Le nouveau thread hérite de copies des ensembles de capacités du thread appelant (voir capabilities(7)) et du masque d'affinité CPU (voir sched_setaffinity(2)).

VALEUR DE RETOUR

En cas de succès, pthread_create() retourne 0 ; en cas d'erreur, elle retourne un numéro d'erreur, et le contenu de *thread est indéfini.

ERREURS

EAGAIN
Ressources insuffisantes pour créer un autre thread.
EAGAIN
Une limite imposée par le système sur le nombre de threads a été rencontrée. Il existe un certain nombre de limites qui peuvent déclencher cette erreur : la limite de ressource douce RLIMIT_NPROC (définie via setrlimit(2)), qui limite le nombre de processus et de threads pour un ID utilisateur réel, a été atteinte ; la limite globale du noyau sur le nombre de processus et de threads, /proc/sys/kernel/threads-max, a été atteinte (voir proc(5)) ; ou le nombre maximum de PID, /proc/sys/kernel/pid_max, a été atteint (voir proc(5)).
EINVAL
Paramètres invalides dans attr.
EPERM
Aucune permission pour définir la politique et les paramètres d'ordonnancement spécifiés dans attr.

NOTES

Voir pthread_self(3) pour plus d'informations sur l'identifiant de thread retourné dans *thread par pthread_create(). Sauf si des politiques d'ordonnancement temps réel sont employées, après un appel à pthread_create(), il est indéterminé quel thread—l'appelant ou le nouveau thread—s'exécutera ensuite.

Un thread peut être soit rejoignable soit détaché. Si un thread est rejoignable, alors un autre thread peut appeler pthread_join(3) pour attendre la fin du thread et récupérer son statut de sortie. C'est seulement lorsqu'un thread terminé et rejoignable a été rejoint que ses dernières ressources sont libérées et retournées au système. Lorsqu'un thread détaché se termine, ses ressources sont automatiquement libérées et retournées au système : il n'est pas possible de rejoindre le thread afin d'obtenir son statut de sortie. Rendre un thread détaché est utile pour certains types de threads démons dont le statut de sortie n'a pas besoin d'être pris en compte par l'application. Par défaut, un nouveau thread est créé dans un état rejoignable, sauf si attr a été défini pour créer le thread dans un état détaché (en utilisant pthread_attr_setdetachstate(3)).

Sous l'implémentation de threads NPTL, si la limite de ressource douce RLIMIT_STACK au moment où le programme a démarré a une valeur autre que "illimitée", alors elle détermine la taille de pile par défaut des nouveaux threads. En utilisant pthread_attr_setstacksize(3), la taille de pile peut être explicitement définie dans l'argument attr utilisé pour créer un thread, afin d'obtenir une taille de pile autre que la taille par défaut. Si la limite de ressource RLIMIT_STACK est définie à "illimitée", une valeur par architecture est utilisée pour la taille de pile : 2 Mo sur la plupart des architectures ; 4 Mo sur POWER et Sparc-64.

BOGUES

Dans l'implémentation obsolète LinuxThreads, chacun des threads d'un processus a un identifiant de processus différent. Ceci est en violation de la spécification POSIX threads, et est la source de nombreuses autres non-conformités avec la norme ; voir pthreads(7).

Le programme ci-dessous démontre l'utilisation de pthread_create(), ainsi que plusieurs autres fonctions de l'API pthreads.

Lors de l'exécution suivante, sur un système fournissant l'implémentation de threads NPTL, la taille de pile par défaut est la valeur donnée par la limite de ressource "taille de pile" :


$ ulimit -s
8192            # La limite de taille de pile est de 8 Mo (0x800000 octets)
$ ./a.out hola salut servus

Thread 2: top of stack near 0xb75cf3b8; argv_string=salut
Thread 3: top of stack near 0xb6dce3b8; argv_string=servus
Joined with thread 1; returned value was HOLA
Joined with thread 2; returned value was SALUT
Joined with thread 3; retur
ned value was SERVUS

Dans la prochaine exécution, le programme définit explicitement une taille de pile de 1 Mo (en utilisant pthread_attr_setstacksize(3)) pour les threads créés :


$ ./a.out -s 0x100000 hola salut servus
Thread 1: top of stack near 0xb7d723b8; argv_string=hola
Thread 2: top of stack near 0xb7c713b8; argv_string=salut
Thread 3: top of stack near 0xb7b703b8; argv_string=servus
Joined with thread 1; returned value was HOLA
Joined with thread 2; returned value was SALUT
Joined with thread 3; returned value was SERVUS

Source du programme

#include <ctype.h>
#include <err.h>
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/types.h>
#include <unistd.h>
struct thread_info {    /* Used as argument to thread_start() */
    pthread_t thread_id;        /* ID returned by pthread_create() */
    int       thread_num;       /* Application-defined thread # */
    char     *argv_string;      /* From command-line argument */
};
/* Thread start function: display address near top of our stack,
   and return upper-cased copy of argv_string.  */
static void *
thread_start(void *arg)
{
    struct thread_info *tinfo = arg;
    char *uargv;
    printf("Thread %d: top of stack near %p; argv_string=%s\n",
           tinfo->thread_num, (void *) &tinfo, tinfo->argv_string);
    uargv = strdup(tinfo->argv_string);
    if (uargv == NULL)
        err(EXIT_FAILURE, "strdup");
    for (char *p = uargv; *p != '\0'; p++)
        *p = toupper(*p);
    return uargv;
}
int
main(int argc, char *argv[])
{
    int                 s, opt;
    void                *res;
    size_t              num_threads;
    ssize_t             stack_size;
    pthread_attr_t      attr;
    struct thread_info  *tinfo;
    /* The "-s" option specifies a stack size for our threads.  */
    stack_size = -1;
    while ((opt = getopt(argc, argv, "s:")) != -1) {
        switch (opt) {
        case 's':
            stack_size = strtoul(optarg, NULL, 0);
            break;
        default:
            fprintf(stderr, "Usage: %s [-s stack-size] arg...\n",
                    argv[0]);
            exit(EXIT_FAILURE);
        }
    }
    num_threads = argc - optind;
    /* Initialize thread creation attributes.  */
    s = pthread_attr_init(&attr);
    if (s != 0)
        errc(EXIT_FAILURE, s, "pthread_attr_init");
    if (stack_size > 0) {
        s = pthread_attr_setstacksize(&attr, stack_size);
        if (s != 0)
            errc(EXIT_FAILURE, s, "pthread_attr_setstacksize");
    }
    /* Allocate memory for pthread_create() arguments.  */
    tinfo = calloc(num_threads, sizeof(*tinfo));
    if (tinfo == NULL)
        err(EXIT_FAILURE, "calloc");
    /* Create one thread for each command-line argument.  */
    for (size_t tnum = 0; tnum < num_threads; tnum++) {
        tinfo[tnum].thread_num = tnum + 1;
        tinfo[tnum].argv_string = argv[optind + tnum];
        /* The pthread_create() call stores the thread ID into
           corresponding element of tinfo[].  */
        s = pthread_create(&tinfo[tnum].thread_id, &attr,
                           &thread_start, &tinfo[tnum]);
        if (s != 0)
            errc(EXIT_FAILURE, s, "pthread_create");
    }
    /* Destroy the thread attributes object, since it is no
       longer needed.  */
    s = pthread_attr_destroy(&attr);
    if (s != 0)
        errc(EXIT_FAILURE, s, "pthread_attr_destroy");
    /* Now join with each thread, and display its returned value.  */
    for (size_t tnum = 0; tnum < num_threads; tnum++) {
        s = pthread_join(tinfo[tnum].thread_id, &res);
        if (s != 0)
            errc(EXIT_FAILURE, s, "pthread_join");
        printf("Joined with thread %d; returned value was %s\n",
               tinfo[tnum].thread_num, (char *) res);
        free(res);      /* Free memory allocated by thread */
    }
    free(tinfo);
    exit(EXIT_SUCCESS);
}
