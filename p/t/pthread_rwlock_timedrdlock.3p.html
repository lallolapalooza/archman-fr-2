PTHREAD_RWLOCK_TIMEDRDLOCK(3P) Manuel du programmeur POSIX PTHREAD_RWLOCK_TIMEDRDLOCK(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_rwlock_timedrdlock — verrouiller un verrou lecture-écriture en lecture

SYNTAXE

#include <pthread.h>
#include <time.h>
int pthread_rwlock_timedrdlock(pthread_rwlock_t *restrict rwlock,
    const struct timespec *restrict abstime);

DESCRIPTION

La fonction pthread_rwlock_timedrdlock() applique un verrou de lecture à l'objet verrou lecture-écriture référencé par rwlock, comme dans la fonction pthread_rwlock_rdlock(). Cependant, si le verrou ne peut pas être acquis sans attendre que d'autres threads déverrouillent le verrou, cette attente sera terminée lorsque le délai d'attente spécifié expire. Le délai d'attente expirera lorsque l'heure absolue spécifiée par abstime sera atteinte (c'est-à-dire lorsque la valeur de cette horloge sera égale ou supérieure à abstime), ou si l'heure absolue spécifiée par abstime a déjà été dépassée au moment de l'appel.

Le délai d'attente est basé sur l'horloge CLOCK_REALTIME. La résolution du délai d'attente est la résolution de l'horloge CLOCK_REALTIME. Le type de données timespec est défini dans l'en-tête <time.h>. En aucun cas la fonction ne doit échouer avec un délai d'attente si le verrou peut être acquis immédiatement. La validité du paramètre abstime n'a pas besoin d'être vérifiée si le verrou peut être acquis immédiatement.

Si un signal qui provoque l'exécution d'un gestionnaire de signaux est délivré à un thread bloqué sur un verrou lecture-écriture via un appel à pthread_rwlock_timedrdlock(), après le retour du gestionnaire de signaux, le thread reprendra l'attente du verrou comme s'il n'avait pas été interrompu.

Le thread appelant peut se retrouver dans une situation d'interblocage si, au moment de l'appel, il détient un verrou d'écriture sur rwlock. Les résultats sont indéfinis si cette fonction est appelée avec un verrou lecture-écriture non initialisé.

VALEUR DE RETOUR

La fonction pthread_rwlock_timedrdlock() retourne zéro si le verrou en lecture sur l'objet verrou lecture-écriture référencé par rwlock est acquis. Sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_rwlock_timedrdlock() échouera si :

ETIMEDOUT
Le verrou n'a pas pu être acquis avant l'expiration du délai spécifié.

La fonction pthread_rwlock_timedrdlock() peut échouer si :

EAGAIN
Le verrou de lecture n'a pas pu être acquis car le nombre maximum de verrous de lecture pour le verrou serait dépassé.
EDEADLK
Une condition d'interblocage a été détectée ou le thread appelant détient déjà un verrou d'écriture sur rwlock.
EINVAL
La valeur nanoseconde de abstime est inférieure à zéro ou supérieure ou égale à 1000 millions.

Cette fonction ne retournera pas le code d'erreur [EINTR].

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

USAGE APPLICATIF

Les applications utilisant cette fonction peuvent être sujettes à l'inversion de priorité, comme discuté dans le volume Base Definitions de POSIX.1‐2017, Section 3.291, Inversion de priorité.

RATIONALE

Si une implémentation détecte que la valeur spécifiée par l'argument rwlock à pthread_rwlock_timedrdlock() ne fait pas référence à un objet verrou lecture-écriture initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].
