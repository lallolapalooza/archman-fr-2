PTHREAD_MUTEXATTR_GETROBUST(3P) Manuel du programmeur POSIX PTHREAD_MUTEXATTR_GETROBUST(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_mutexattr_getrobust, pthread_mutexattr_setrobust — obtenir et définir l'attribut de robustesse d'un mutex

SYNOPSIS

#include <pthread.h>
int pthread_mutexattr_getrobust(const pthread_mutexattr_t *restrict
    attr, int *restrict robust);
int pthread_mutexattr_setrobust(pthread_mutexattr_t *attr,
    int robust);

DESCRIPTION

Les fonctions pthread_mutexattr_getrobust() et pthread_mutexattr_setrobust() obtiennent et définissent respectivement l'attribut de robustesse du mutex. Cet attribut est défini dans le paramètre robust. Les valeurs valides pour robust incluent :

PTHREAD_MUTEX_STALLED

Aucune action spéciale n'est effectuée si le propriétaire du mutex est terminé en détenant le verrou du mutex. Cela peut entraîner des interblocages si aucun autre thread ne peut déverrouiller le mutex.
C'est la valeur par défaut.
PTHREAD_MUTEX_ROBUST

Si le processus contenant le thread propriétaire d'un mutex robuste est terminé tout en détenant le verrou du mutex, le prochain thread qui acquiert le mutex sera informé de la terminaison par la valeur de retour [EOWNERDEAD] provenant de la fonction de verrouillage. Si le thread propriétaire d'un mutex robuste est terminé tout en détenant le verrou du mutex, le prochain thread qui tente d'acquérir le mutex peut être informé de la terminaison par la valeur de retour [EOWNERDEAD]. Le thread notifié peut alors tenter de rendre l'état protégé par le mutex cohérent, et s'il réussit, il peut marquer l'état du mutex comme cohérent en appelant pthread_mutex_consistent(). Après un appel réussi ultérieur à pthread_mutex_unlock(), le verrou du mutex sera libéré et pourra être utilisé normalement par d'autres threads. Si le mutex est déverrouillé sans appel à pthread_mutex_consistent(), il sera dans un état définitivement inutilisable et toutes les tentatives de verrouillage du mutex échoueront avec l'erreur [ENOTRECOVERABLE]. La seule opération autorisée sur un tel mutex est pthread_mutex_destroy().

Le comportement est indéfini si la valeur spécifiée par l'argument attr à pthread_mutexattr_getrobust() ou pthread_mutexattr_setrobust() ne fait pas référence à un objet d'attributs de mutex initialisé.

VALEUR DE RETOUR

En cas de succès, la fonction pthread_mutexattr_getrobust() retournera zéro et stockera la valeur de l'attribut robustesse de attr dans l'objet référencé par le paramètre robust. Sinon, une valeur d'erreur sera retournée pour indiquer l'erreur. En cas de succès, la fonction pthread_mutexattr_setrobust() retournera zéro ; sinon, un numéro d'erreur sera retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_mutexattr_setrobust() échouera si :

EINVAL
La valeur de robustesse est invalide.

Ces fonctions ne retourneront pas de code d'erreur [EINTR].

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION APPLICATIVE

Les actions requises pour rendre l'état protégé par le mutex cohérent dépendent entièrement de l'application. S'il n'est pas possible de rendre l'état d'un mutex cohérent, les mutex robustes peuvent être utilisés pour signaler cette situation en appelant pthread_mutex_unlock() sans appel préalable à pthread_mutex_consistent().

Si l'état est déclaré incohérent en appelant pthread_mutex_unlock() sans appel préalable à pthread_mutex_consistent(), une approche possible pourrait être de détruire le mutex puis de le réinitialiser. Cependant, il convient de noter que cela n'est possible que dans certaines situations où l'état protégé par le mutex doit être réinitialisé et la coordination obtenue avec d'autres threads bloqués sur le mutex, car sinon un appel à une fonction de verrouillage avec une référence à un objet mutex invalidé par un appel à pthread_mutex_destroy() entraîne un comportement indéfini.

RATIONALE

Si une implémentation détecte que la valeur spécifiée par l'argument attr à pthread_mutexattr_getrobust() ou pthread_mutexattr_setrobust() ne fait pas référence à un objet d'attributs de mutex initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].
