PTHREAD_JOIN(3P) Manuel du programmeur POSIX PTHREAD_JOIN(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_join — attendre la fin d'un thread

SYNOPSIS

#include <pthread.h>
int pthread_join(pthread_t thread, void **value_ptr);

DESCRIPTION

La fonction pthread_join() suspend l'exécution du thread appelant jusqu'à ce que le thread cible thread se termine, à moins que le thread cible thread ne se soit déjà terminé. Au retour d'un appel réussi à pthread_join() avec un argument value_ptr non nul, la valeur passée à pthread_exit() par le thread se terminant sera mise à disposition dans l'emplacement référencé par value_ptr. Lorsqu'un pthread_join() retourne avec succès, le thread cible a été terminé. Les résultats de plusieurs appels simultanés à pthread_join() spécifiant le même thread cible sont indéfinis. Si le thread appelant pthread_join() est annulé, alors le thread cible ne doit pas être détaché.

Il n'est pas spécifié si un thread qui est sorti mais reste non joint compte dans {PTHREAD_THREADS_MAX}.

Le comportement est indéfini si la valeur spécifiée par l'argument thread à pthread_join() ne fait pas référence à un thread joignable.

Le comportement est indéfini si la valeur spécifiée par l'argument thread à pthread_join() fait référence au thread appelant.

VALEUR DE RETOUR

En cas de succès, la fonction pthread_join() retourne zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_join() peut échouer si :

EDEADLK
Une situation d'interblocage a été détectée.

La fonction pthread_join() ne doit pas retourner le code d'erreur [EINTR].

EXEMPLES

Un exemple de création et de suppression de thread suit :

typedef struct {
    int *ar;
    long n;
} subarray;
void *
incer(void *arg)
{
    long i;
    for (i = 0; i < ((subarray *)arg)->n; i++)
        ((subarray *)arg)->ar[i]++;
}
int main(void)
{
    int        ar[1000000];
    pthread_t  th1, th2;
    subarray   sb1, sb2;
    sb1.ar = &ar[0];
    sb1.n  = 500000;
    (void) pthread_create(&th1, NULL, incer, &sb1);
    sb2.ar = &ar[500000];
    sb2.n  = 500000;
    (void) pthread_create(&th2, NULL, incer, &sb2);
    (void) pthread_join(th1, NULL);
    (void) pthread_join(th2, NULL);
    return 0;
}

RATIONALE

La fonction pthread_join() est une commodité qui s'est avérée utile dans les applications multithread. Il est vrai qu'un programmeur pourrait simuler cette fonction si elle n'était pas fournie en passant un état supplémentaire dans le cadre de l'argument de la start_routine(). Le thread se terminant définirait un indicateur pour signaler la terminaison et diffuserait une condition faisant partie de cet état ; un thread rejoignant attendrait cette variable de condition. Bien qu'une telle technique permettrait à un thread d'attendre des conditions plus complexes (par exemple, attendre la fin de plusieurs threads), l'attente de la fin de threads individuels est considérée comme largement utile. De plus, inclure la fonction pthread_join() n'empêche en aucun cas un programmeur de coder de telles attentes complexes. Ainsi, bien qu'elle ne soit pas une primitive, l'inclusion de pthread_join() dans ce volume de POSIX.1‐2017 a été jugée précieuse.

La fonction pthread_join() fournit un mécanisme simple permettant à une application d'attendre la fin d'un thread. Après la fin du thread, l'application peut choisir de nettoyer les ressources utilisées par le thread. Par exemple, après le retour de pthread_join(), tout espace de pile fourni par l'application pourrait être récupéré.

La fonction pthread_join() ou pthread_detach() devrait éventuellement être appelée pour chaque thread créé avec l'attribut detachstate défini sur PTHREAD_CREATE_JOINABLE afin que le stockage associé au thread puisse être récupéré.

L'interaction entre pthread_join() et l'annulation est bien définie pour les raisons suivantes :

*
La fonction pthread_join(), comme toutes les autres fonctions non sûres pour l'annulation asynchrone, ne peut être appelée qu'avec un type d'annulabilité différée.
*
L'annulation ne peut pas se produire dans un état d'annulabilité désactivé.

Ainsi, seul l'état d'annulabilité par défaut doit être pris en compte. Comme spécifié, soit l'appel pthread_join() est annulé, soit il réussit, mais pas les deux. La différence est évidente pour l'application, car soit un gestionnaire d'annulation est exécuté, soit pthread_join() retourne. Il n'y a pas de conditions de concurrence puisque pthread_join() a été appelé dans l'état d'annulabilité différée.

Si une implémentation détecte que la valeur spécifiée par l'argument thread à pthread_join() ne fait pas référence à un thread joignable, il est recommandé que la fonction échoue et signale une erreur [EINVAL].

Si une implémentation détecte que la valeur spécifiée par l'argument thread à pthread_join() fait référence au thread appelant, il est recommandé que la fonction échoue et signale une erreur [EDEADLK].

Si une implémentation détecte une utilisation d'un ID de thread après la fin de sa durée de vie, il est recommandé que la fonction échoue et signale une erreur [ESRCH].
