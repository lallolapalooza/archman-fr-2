PTHREAD_SIGMASK(3P) Manuel du programmeur POSIX PTHREAD_SIGMASK(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_sigmask, sigprocmask — examiner et modifier les signaux bloqués

SYN。
OPSIS

#include <signal.h>
int pthread_sigmask(int how, const sigset_t *restrict set,
    sigset_t *restrict oset);
int sigprocmask(int how, const sigset_t *restrict set,
    sigset_t *restrict oset);

DESCRIPTION

La fonction pthread_sigmask() examine ou modifie (ou les deux) le masque de signaux du thread appelant, quel que soit le nombre de threads dans le processus. La fonction est équivalente à sigprocmask(), sans la restriction que l'appel soit effectué dans un processus mono-thread.

Dans un processus mono-thread, la fonction sigprocmask() examine ou modifie (ou les deux) le masque de signaux du thread appelant.

Si l'argument set n'est pas un pointeur nul, il pointe vers un ensemble de signaux à utiliser pour modifier l'ensemble actuellement bloqué.

L'argument how indique la manière dont l'ensemble est modifié, et l'application doit s'assurer qu'il contient l'une des valeurs suivantes :

SIG_BLOCK
L'ensemble résultant sera l'union de l'ensemble courant et de l'ensemble de signaux pointé par set.
SIG_SETMASK
L'ensemble résultant sera l'ensemble de signaux pointé par set.
SIG_UNBLOCK
L'ensemble résultant sera l'intersection de l'ensemble courant et du complément de l'ensemble de signaux pointé par set.

Si l'argument oset n'est pas un pointeur nul, le masque précédent sera stocké à l'emplacement pointé par oset. Si set est un pointeur nul, la valeur de l'argument how n'est pas significative et le masque de signaux du thread ne sera pas modifié ; l'appel peut ainsi être utilisé pour interroger les signaux actuellement bloqués.

Si des signaux non bloqués et en attente existent après l'appel à sigprocmask(), au moins l'un de ces signaux sera délivré avant que l'appel à sigprocmask() ne retourne.

Il n'est pas possible de bloquer les signaux qui ne peuvent pas être ignorés. Ceci sera appliqué par le système sans provoquer d'erreur.

Si l'un des signaux SIGFPE, SIGILL, SIGSEGV ou SIGBUS est généré alors qu'ils sont bloqués, le résultat est indéfini, sauf si le signal a été généré par l'action d'un autre processus, ou par l'une des fonctions kill(), pthread_kill(), raise() ou sigqueue().

Si sigprocmask() échoue, le masque de signaux du thread ne sera pas modifié.

L'utilisation de la fonction sigprocmask() est indéfinie dans un processus multi-thread.

VALEUR DE RETOUR

En cas de succès, pthread_sigmask() retournera 0 ; sinon, elle retournera le numéro d'erreur correspondant.

En cas de succès, sigprocmask() retournera 0 ; sinon, -1 sera retourné, errno sera défini pour indiquer l'erreur, et le masque de signaux du processus restera inchangé.

ERREURS

Les fonctions pthread_sigmask() et sigprocmask() échoueront si :

EINVAL
La valeur de l'argument how n'est pas égale à l'une des valeurs définies.

La fonction pthread_sigmask() ne retournera pas un code d'erreur [EINTR].

EXEMPLES

Signalisation dans un Processus Multi-Thread

Cet exemple montre l'utilisation de pthread_sigmask() afin de gérer les signaux dans un processus multi-thread. Il fournit un cadre assez général qui pourrait être facilement adapté/étendu.

#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <signal.h>
#include <string.h>
#include <errno.h>
...
static sigset_t   signal_mask;  /* signaux à bloquer         */
int main (int argc, char *argv[])
{
    pthread_t  sig_thr_id;      /* ID du thread de gestion des signaux */
    int        rc;              /* code de retour              */
    sigemptyset (&signal_mask);
    sigaddset (&signal_mask, SIGINT);
    sigaddset (&signal_mask, SIGTERM);
    rc = pthread_sigmask (SIG_BLOCK, &signal_mask, NULL);
    if (rc != 0) {
        /* gérer l'erreur */
        ...
    }
    /* tout nouveau thread créé hérite du masque de signaux */
    rc = pthread_create (&sig_thr_id, NULL, signal_thread, NULL);
    if (rc != 0) {
        /* gérer l'erreur */
        ...
    }

    /* CODE DE L'APPLICATION */
    ...
}
void *signal_thread (void *arg)
{
    int       sig_caught;    /* signal capturé       */
    int       rc;            /* code retourné       */
    rc = sigwait (&signal_mask, &sig_caught);
    if (rc != 0) {
        /* gérer l'erreur */
    }
    switch (sig_caught)
    {
    case SIGINT:     /* traiter SIGINT  */
        ...
        break;
    case SIGTERM:    /* traiter SIGTERM */
        ...
        break;
    default:         /* ne devrait normalement pas arriver */
        fprintf (stderr, "\nSignal inattendu %d\n", sig_caught);
        break;
    }
}

UTILISATION APPLICATIVE

Aucune.

RATIONALE

Lorsque le masque de signaux d'un thread est modifié dans une fonction de réception de signal installée par sigaction(), la restauration du masque de signaux au retour de cette fonction de réception de signal remplace cette modification (voir sigaction()). Si la fonction de réception de signal a été installée avec signal(), il est indéfini si cela se produit.

Voir kill() pour une discussion sur l'exigence de livraison des signaux.
