pthread_setschedparam(3) Manuel des fonctions de bibliothèque pthread_setschedparam(3)

NOM

pthread_setschedparam, pthread_getschedparam - définir/obtenir la politique et les paramètres de planification d'un thread

BIBLIOTHÈQUE

Bibliothèque POSIX threads (libpthread, -lpthread)

SYNOPSIS

#include <pthread.h>
int pthread_setschedparam(pthread_t thread, int policy,
                          const struct sched_param *param);
int pthread_getschedparam(pthread_t thread, int *restrict policy,
                          struct sched_param *restrict param);

DESCRIPTION

La fonction pthread_setschedparam() définit la politique et les paramètres de planification du thread thread.

policy spécifie la nouvelle politique de planification pour thread. Les valeurs prises en charge pour policy, et leurs sémantiques, sont décrites dans sched(7).

La structure pointée par param spécifie les nouveaux paramètres de planification pour thread. Les paramètres de planification sont maintenus dans la structure suivante :


struct sched_param {
    int sched_priority;     /* Priorité de planification */
};

Comme on peut le voir, un seul paramètre de planification est pris en charge. Pour les détails sur les plages autorisées pour les priorités de planification dans chaque politique de planification, voir sched(7).

La fonction pthread_getschedparam() renvoie la politique et les paramètres de planification du thread thread, dans les buffers pointés par policy et param, respectivement. La valeur de priorité renvoyée est celle définie par le dernier appel à pthread_setschedparam(), pthread_setschedprio(3), ou pthread_create(3) qui a affecté thread. La priorité renvoyée ne reflète aucun ajustement temporaire de priorité résultant d'appels à des fonctions d'héritage de priorité ou de plafond de priorité (voir, par exemple, pthread_mutexattr_setprioceiling(3) et pthread_mutexattr_setprotocol(3)).

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient 0 ; en cas d'erreur, elles renvoient un numéro d'erreur non nul. Si pthread_setschedparam() échoue, la politique et les paramètres de planification de thread ne sont pas modifiés.

ERREURS

Les deux fonctions peuvent échouer avec l'erreur suivante :

ESRCH
Aucun thread avec l'identifiant thread n'a été trouvé.

pthread_setschedparam() peut également échouer avec les erreurs suivantes :

EINVAL
policy n'est pas une politique reconnue, ou param n'a pas de sens pour la policy.
EPERM
L'appelant n'a pas les privilèges appropriés pour définir la politique et les paramètres de planification spécifiés.

POSIX.1 documente également une erreur ENOTSUP (« une tentative a été faite pour définir la politique ou les paramètres de planification à une valeur non prise en charge ») pour pthread_setschedparam().

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
pthread_setschedparam (), pthread_getschedparam () Thread safety MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

glibc 2.0 POSIX.1-2001.

NOTES

Pour une description des permissions requises et de l'effet de la modification de la politique et de la priorité de planification d'un thread, ainsi que des détails sur les plages autorisées pour les priorités dans chaque politique de planification, voir sched(7).

EXEMPLES

Le programme ci-dessous démontre l'utilisation de pthread_setschedparam() et pthread_getschedparam(), ainsi que l'utilisation d'un certain nombre d'autres fonctions pthreads liées à la planification.

Dans l'exécution suivante, le thread principal définit sa politique de planification sur SCHED_FIFO avec une priorité de 10, et initialise un objet d'attributs de thread avec un attribut de politique de planification de SCHED_RR et un attribut de priorité de planification de 20. Le programme définit ensuite (en utilisant pthread_attr_setinheritsched(3)) l'attribut d'héritage de planificateur de l'objet d'attributs de thread sur PTHREAD_EXPLICIT_SCHED, ce qui signifie que les threads créés à l'aide de cet objet d'attributs doivent prendre leurs attributs de planification à partir de l'objet d'attributs de thread. Le programme crée ensuite un thread à l'aide de l'objet d'attributs de thread, et ce thread affiche sa politique et sa priorité de planification.


$ su;      # Nécessite des privilèges pour définir les politiques de planification temps réel
Password:
# ./a.out -mf10 -ar20 -i e;
Paramètres du planificateur du thread principal
    policy=SCHED_FIFO, priority=10
Paramètres du planificateur dans 'attr'
    policy=SCHED_RR, priority=20
    inheritsched est EXPLICIT
Attributs du planificateur du nouveau thread
    policy=SCHED_RR, priority=20

Dans la sortie ci-dessus, on peut voir que la politique et la priorité de planification ont été prises à partir des valeurs spécifiées dans l'objet d'attributs du thread.

La prochaine exécution est identique à la précédente, sauf que l'attribut d'héritage du planificateur est défini sur PTHREAD_INHERIT_SCHED, ce qui signifie que les threads créés à l'aide de l'objet d'attributs de thread ignoreront les attributs de planification spécifiés dans l'objet d'attributs et prendront plutôt leurs attributs de planification à partir du thread créateur.


# ./a.out -mf10 -ar20 -i i;
Paramètres du planificateur du thread principal
    policy=SCHED_FIFO, priority=10
Paramètres du planificateur dans 'attr'
    policy=SCHED_RR, priority=20
    inheritsched est INHERIT
Attributs du planificateur du nouveau thread
    policy=SCHED_FIFO, priority=10

Dans la sortie ci-dessus, on peut voir que la politique et la priorité de planification ont été prises à partir du thread créateur, plutôt que de l'objet d'attributs du thread.

Notez que si nous avions omis l'option -i i, la sortie aurait été la même, car PTHREAD_INHERIT_SCHED est la valeur par défaut pour l'attribut d'héritage du planificateur.
