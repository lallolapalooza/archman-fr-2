PTHREAD_EXIT(3P) Manuel du programmeur POSIX PTHREAD_EXIT(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_exit — terminaison de thread

SYNOPIS

#include <pthread.h>
void pthread_exit(void *value_ptr);

DESCRIPTION

La fonction pthread_exit() termine le thread appelant et rend la valeur value_ptr disponible pour toute jointure réussie avec le thread qui se termine. Tous les gestionnaires de nettoyage d'annulation qui ont été poussés et non encore dépilés seront dépilés dans l'ordre inverse de leur empilement, puis exécutés. Après l'exécution de tous les gestionnaires de nettoyage d'annulation, si le thread possède des données spécifiques au thread, les destructeurs appropriés seront appelés dans un ordre non spécifié. La terminaison d'un thread ne libère aucune ressource visible par l'application, y compris, mais sans s'y limiter, les mutex et les descripteurs de fichiers, et n'effectue aucune action de nettoyage au niveau du processus, y compris, mais sans s'y limiter, l'appel des routines atexit() qui peuvent exister.

Un appel implicite à pthread_exit() est effectué lorsqu'un thread autre que celui dans lequel main() a été initialement invoqué retourne de la routine de démarrage utilisée pour sa création. La valeur de retour de la fonction servira de statut de sortie du thread.

Le comportement de pthread_exit() est indéfini s'il est appelé à partir d'un gestionnaire de nettoyage d'annulation ou d'une fonction destructeur qui a été invoqué à la suite d'un appel implicite ou explicite à pthread_exit().

Après qu'un thread a terminé, le résultat de l'accès aux variables locales (automatiques) du thread est indéfini. Par conséquent, les références aux variables locales du thread qui se termine ne doivent pas être utilisées pour le paramètre value_ptr de pthread_exit().

Le processus se terminera avec un statut de sortie de 0 après que tous les threads ont été terminés. Le comportement sera comme si l'implémentation appelait exit() avec un argument zéro au moment de la terminaison du thread.

VALEUR DE RETOUR

La fonction pthread_exit() ne peut pas retourner à son appelant.

ERREURS

Aucune erreur n'est définie.

RATIONALE

Le mécanisme normal par lequel un thread se termine est de retourner de la routine qui a été spécifiée dans l'appel pthread_create() qui l'a démarré. La fonction pthread_exit() offre la possibilité à un thread de se terminer sans avoir besoin de retourner de la routine de démarrage de ce thread, fournissant ainsi une fonction analogue à exit().

Indépendamment de la méthode de terminaison du thread, tous les gestionnaires de nettoyage d'annulation qui ont été empilés et non encore dépilés sont exécutés, et les destructeurs pour toutes les données spécifiques au thread existantes sont exécutés. Ce volume de POSIX.1-2017 exige que les gestionnaires de nettoyage d'annulation soient dépilés et appelés dans l'ordre. Après l'exécution de tous les gestionnaires de nettoyage d'annulation, les destructeurs de données spécifiques au thread sont appelés, dans un ordre non spécifié, pour chaque élément de données spécifiques au thread qui existe dans le thread. Cet ordre est nécessaire car les gestionnaires de nettoyage d'annulation peuvent dépendre des données spécifiques au thread.

Comme la signification du statut est déterminée par l'application (sauf lorsque le thread a été annulé, auquel cas il est PTHREAD_CANCELED), l'implémentation n'a aucune idée de ce qu'est une valeur de statut illégale, c'est pourquoi aucune vérification d'erreur d'adresse n'est effectuée.
