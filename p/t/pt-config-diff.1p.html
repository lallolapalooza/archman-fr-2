NOM

pt-config-diff - Compare les fichiers de configuration MySQL et les variables serveur.

SYNTAXE

Usage : pt-config-diff [OPTIONS] CONFIG CONFIG [CONFIG...]

pt-config-diff compare les fichiers de configuration MySQL et les variables serveur. CONFIG peut être un nom de fichier ou un DSN. Au moins deux sources CONFIG doivent être fournies. Comme la commande diff standard de Unix, il n'y a pas de sortie s'il n'y a pas de différences.

Compare la configuration de host1 issue de SHOW VARIABLES avec host2 :

pt-config-diff h=host1 h=host2

Compare la configuration de la section [mysqld] de my.cnf avec la configuration de host1 :

pt-config-diff /etc/my.cnf h=host1

Compare la section [mysqld] de deux fichiers d'options :

pt-config-diff /etc/my-small.cnf /etc/my-large.cnf

RISQUES

Percona Toolkit est mature, éprouvé sur le terrain et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Consulter les "BUGS" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-config-diff compare les configurations MySQL en examinant les valeurs des variables système du serveur provenant de deux ou plusieurs sources CONFIG spécifiées sur la ligne de commande. Une source CONFIG peut être un DSN ou un fichier contenant la sortie de "mysqld --help --verbose", "my_print_defaults", "SHOW VARIABLES", ou un fichier d'options (par exemple, my.cnf).

Pour chaque DSN CONFIG, pt-config-diff se connecte à MySQL et récupère les variables et leurs valeurs en exécutant "SHOW /*!40103 GLOBAL*/ VARIABLES". Il s'agit d'une "configuration active" car elle montre les valeurs avec lesquelles le serveur est actuellement en cours d'exécution.

Seules les variables présentes dans toutes les sources CONFIG sont comparées, car si une variable est absente, nous ne pouvons pas connaître ou deviner sa valeur en toute sécurité. Par exemple, si vous comparez un fichier d'options (par exemple, my.cnf) à une configuration active (c'est-à-dire SHOW VARIABLES d'une source DSN CONFIG), le fichier d'options n'aura probablement que quelques variables, tandis que la configuration active en a toutes. Seules les valeurs des variables présentes dans les deux configurations sont comparées.

Les fichiers d'options et les configurations DSN fournissent les meilleurs résultats.

SORTIE

Il n'y a pas de sortie lorsqu'il n'y a pas de différences. En cas de différences, pt-config-diff imprime un rapport sur STDOUT qui ressemble à ceci :

2 config differences
Variable                  my.source.cnf   my.replica.cnf
========================= =============== ===============
datadir                   /tmp/12345/data /tmp/12346/data
port                      12345           12346

Comparer les variables MySQL est difficile car il existe de nombreuses variations et subtilités entre les nombreuses versions et distributions de MySQL. Lorsqu'une comparaison échoue, l'outil imprime un avertissement sur STDERR, tel que le suivant :

Comparing log_error values (mysqld.log, /tmp/12345/data/mysqld.log)
caused an error: Argument "/tmp/12345/data/mysqld.log" isn't numeric
in numeric eq (==) at ./pt-config-diff line 2311.

Veuillez signaler ces avertissements afin que les fonctions de comparaison puissent être améliorées.

STATUT DE SORTIE

pt-config-diff se termine avec un statut de sortie zéro lorsqu'il n'y a pas de différences, et 1 s'il y en a.

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Reportez-vous à la "SYNTAXE" et aux informations d'utilisation pour plus de détails.

--ask-pass
Demande un mot de passe lors de la connexion à MySQL.
--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, définit le binmode de Perl sur STDOUT en utf8, transmet l'option mysql_enable_utf8 à DBD::mysql et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur définit le binmode sur STDOUT sans la couche utf8 et exécute SET NAMES après la connexion à MySQL.

--config
type : Tableau

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, cela doit être la première option sur la ligne de commande. (Cette option ne spécifie pas une CONFIG ; elle est équivalente à "--defaults-file".)

--database
forme courte : -D ; type : chaîne

Se connecter à cette base de données.

--defaults-file
forme courte : -F ; type : chaîne

Ne lire que les options mysql du fichier donné. Vous devez fournir un chemin absolu.

--help
Afficher l'aide et quitter.
--host
forme courte : -h ; type : chaîne

Se connecter à l'hôte.

--[no]ignore-case
défaut : oui

Comparer les variables sans tenir compte de la casse.

--ignore-variables
type : tableau

Ignorer, ne pas comparer, ces variables.

--password
forme courte : -p ; type : chaîne

Mot de passe à utiliser pour la connexion.

--pid
type : chaîne

Créer le fichier PID donné. L'outil ne démarrera pas si le fichier PID existe déjà et que le PID qu'il contient est différent du PID actuel. Cependant, si le fichier PID existe et que le PID qu'il contient n'est plus en cours d'exécution, l'outil remplacera le fichier PID par le PID actuel. Le fichier PID est automatiquement supprimé lorsque l'outil se termine.

--port
forme courte : -P ; type : entier

Numéro de port à utiliser pour la connexion.

--[no]report
défaut : oui

Imprimer le rapport de différence de configuration MySQL sur STDOUT. Si vous voulez simplement vérifier si les configurations données sont différentes ou non en examinant le statut de sortie de l'outil, spécifiez "--no-report" pour supprimer le rapport.

--report-width
type : entier ; défaut : 78

Tronquer les lignes du rapport à ce nombre de caractères. Étant donné que certaines valeurs de variables peuvent être longues, ou lors de la comparaison de plusieurs configurations, il peut être utile d'augmenter la largeur du rapport afin que les valeurs ne soient pas tronquées au-delà de la lisibilité.

--set-vars
type : Tableau

Définir les variables MySQL dans cette liste de paires "variable=valeur" séparées par des virgules.

Par défaut, l'outil définit :

wait_timeout=10000

Les variables spécifiées sur la ligne de commande remplacent ces valeurs par défaut. Par exemple, spécifier "--set-vars wait_timeout=500" remplace la valeur par défaut de 10000.

L'outil imprime un avertissement et continue si une variable ne peut pas être définie.

--socket
forme courte : -S ; type : chaîne

Fichier de socket à utiliser pour la connexion.

--user
forme courte : -u ; type : chaîne

Utilisateur MySQL s'il n'est pas l'utilisateur actuel.

--version
Afficher la version et quitter.
--[no]version-check
défaut : oui

Vérifier la dernière version de Percona Toolkit, MySQL et d'autres programmes.

Il s'agit d'une fonctionnalité standard de "vérification automatique des mises à jour", avec deux fonctionnalités supplémentaires. Premièrement, l'outil vérifie sa propre version ainsi que les versions des logiciels suivants : système d'exploitation, Percona Monitoring and Management (PMM), MySQL, Perl, pilote MySQL pour Perl (DBD::mysql) et Percona Toolkit. Deuxièmement, il vérifie et avertit sur les versions présentant des problèmes connus. Par exemple, MySQL 5.5.25 avait un problème critique
