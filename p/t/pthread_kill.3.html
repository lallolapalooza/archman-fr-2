pthread_kill(3) Manuel des fonctions de bibliothèque pthread_kill(3)

NOM

pthread_kill - envoyer un signal à un thread

BIBLIOTHÈQUE

Bibliothèque POSIX threads (libpthread, -lpthread)

SYNTAXE

#include <signal.h>
int pthread_kill(pthread_t thread, int sig);
Exigences relatives aux macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

pthread_kill():

    _POSIX_C_SOURCE >= 199506L || _XOPEN_SOURCE >= 500

DESCRIPTION

La fonction pthread_kill() envoie le signal sig au thread thread, un thread du même processus que l'appelant. Le signal est dirigé de manière asynchrone vers thread.

Si sig est 0, aucun signal n'est envoyé, mais la vérification des erreurs est toujours effectuée.

VALEUR DE RETOUR

En cas de succès, pthread_kill() retourne 0 ; en cas d'erreur, elle retourne un numéro d'erreur et aucun signal n'est envoyé.

ERREURS

EINVAL
Un signal invalide a été spécifié.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
pthread_kill () Sécurité des threads MT-Safe

VERSIONS

L'implémentation glibc de pthread_kill() renvoie une erreur (EINVAL) lors des tentatives d'envoi des signaux temps réel utilisés en interne par l'implémentation des threads NPTL. Voir nptl(7) pour plus de détails.

POSIX.1-2008 recommande que si une implémentation détecte l'utilisation d'un ID de thread après la fin de sa durée de vie, pthread_kill() doive retourner l'erreur ESRCH. L'implémentation glibc retourne cette erreur dans les cas où un ID de thread invalide peut être détecté. Mais notez également que POSIX indique qu'une tentative d'utilisation d'un ID de thread dont la durée de vie est terminée produit un comportement indéfini, et qu'une tentative d'utilisation d'un ID de thread invalide dans un appel à pthread_kill() peut, par exemple, provoquer une violation d'accès mémoire.

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001.

NOTES

Les dispositions de signaux sont globales au processus : si un gestionnaire de signaux est installé, le gestionnaire sera appelé dans le thread thread, mais si la disposition du signal est "stop", "continue" ou "terminate", cette action affectera l'ensemble du processus.

VOIR AUSSI

kill(2), sigaction(2), sigpending(2), pthread_self(3), pthread_sigmask(3), raise(3), pthreads(7), signal(7)
