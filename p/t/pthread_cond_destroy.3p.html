PTHREAD_COND_DESTROY(3P) Manuel du programmeur POSIX PTHREAD_COND_DESTROY(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_cond_destroy, pthread_cond_init — détruire et initialiser des variables de condition

SYNTAXE

#include <pthread.h>
int pthread_cond_destroy(pthread_cond_t *cond);
int pthread_cond_init(pthread_cond_t *restrict cond,
    const pthread_condattr_t *restrict attr);
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

DESCRIPTION

La fonction pthread_cond_destroy() détruit la variable de condition spécifiée par cond ; l'objet devient, en effet, non initialisé. Une implémentation peut amener pthread_cond_destroy() à définir l'objet référencé par cond à une valeur invalide. Une variable de condition détruite peut être réinitialisée à l'aide de pthread_cond_init() ; les résultats d'une référence ultérieure à l'objet après sa destruction sont indéfinis.

Il doit être sûr de détruire une variable de condition initialisée sur laquelle aucun thread n'est actuellement bloqué. Tenter de détruire une variable de condition sur laquelle d'autres threads sont actuellement bloqués entraîne un comportement indéfini.

La fonction pthread_cond_init() initialise la variable de condition référencée par cond avec les attributs référencés par attr. Si attr est NULL, les attributs par défaut de la variable de condition sont utilisés ; l'effet est le même que de passer l'adresse d'un objet d'attributs de variable de condition par défaut. Après une initialisation réussie, l'état de la variable de condition devient initialisé.

Voir Section 2.9.9, Copies d'objets de synchronisation et mappings alternatifs pour des exigences supplémentaires.

Tenter d'initialiser une variable de condition déjà initialisée entraîne un comportement indéfini.

Dans les cas où les attributs par défaut de la variable de condition sont appropriés, la macro PTHREAD_COND_INITIALIZER peut être utilisée pour initialiser les variables de condition. L'effet est équivalent à une initialisation dynamique par un appel à pthread_cond_init() avec le paramètre attr spécifié comme NULL, sauf qu'aucun contrôle d'erreur n'est effectué.

Le comportement est indéfini si la valeur spécifiée par l'argument cond à pthread_cond_destroy() ne fait pas référence à une variable de condition initialisée.

Le comportement est indéfini si la valeur spécifiée par l'argument attr à pthread_cond_init() ne fait pas référence à un objet d'attributs de variable de condition initialisé.

VALEUR DE RETOUR

En cas de succès, les fonctions pthread_cond_destroy() et pthread_cond_init() retournent zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_cond_init() échouera si :

EAGAIN
Le système n'a pas les ressources nécessaires (autres que la mémoire) pour initialiser une autre variable de condition.
ENOMEM
La mémoire est insuffisante pour initialiser la variable de condition.

Ces fonctions ne retourneront pas de code d'erreur [EINTR].

Les sections suivantes sont informatives.

EXEMPLES

Une variable de condition peut être détruite immédiatement après le réveil de tous les threads qui y sont bloqués. Par exemple, considérez le code suivant :

struct list {
    pthread_mutex_t lm;
    ...
}
struct elt {
    key k;
    int busy;
    pthread_cond_t notbusy;
    ...
}
/* Trouver un élément de liste et le réserver. */
struct elt *
list_find(struct list *lp, key k)
{
    struct elt *ep;
    pthread_mutex_lock(&lp->lm);
    while ((ep = find_elt(l, k) != NULL) && ep->busy)
        pthread_cond_wait(&ep->notbusy, &lp->lm);
    if (ep != NULL)
        ep->busy = 1;
    pthread_mutex_unlock(&lp->lm);
    return(ep);
}
delete_elt(struct list *lp, struct elt *ep)
{
    pthread_mutex_lock(&lp->lm);
    assert(ep->busy);
    ... supprimer ep de la liste ...
    ep->busy = 0;  /* Paranoïaque. */
(A) pthread_cond_broadcast(&ep->notbusy);
    pthread_mutex_unlock(&lp->lm);
(B) pthread_cond_destroy(&ep->notbusy);
    free(ep);
}

Dans cet exemple, la variable de condition et son élément de liste peuvent être libérés (ligne B) immédiatement après le réveil de tous les threads qui attendaient dessus (ligne A), car le mutex et le code garantissent qu'aucun autre thread ne peut toucher l'élément à supprimer.

USAGE APPLICATIF

Aucun.

RATIONALE

Si une implémentation détecte que la valeur spécifiée par l'argument cond à pthread_cond_destroy() ne fait pas référence à une variable de condition initialisée, il est recommandé que la fonction échoue et signale une erreur [EINVAL].

Si une implémentation détecte que la valeur spécifiée par l'argument cond à pthread_cond_destroy() ou pthread_cond_init() fait référence à une variable de condition en cours d'utilisation (par exemple, dans un appel pthread_cond_wait()) par un autre thread, ou détecte que la valeur spécifiée par l'argument cond à pthread_cond_init() fait référence à une variable de condition déjà initialisée, il est recommandé que la fonction échoue et signale une erreur [EBUSY].

Si une implémentation détecte que la valeur spécifiée par l'argument attr à pthread_cond_init() ne fait pas référence à un objet d'attributs de variable de condition initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].

Voir aussi pthread_mutex_destroy().
