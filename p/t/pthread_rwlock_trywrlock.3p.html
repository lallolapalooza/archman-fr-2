PTHREAD_RWLOCK_TRYWRLOCK(3P) Manuel du programmeur POSIX PTHREAD_RWLOCK_TRYWRLOCK(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_rwlock_trywrlock, pthread_rwlock_wrlock — verrouiller un objet de verrou lecture-écriture pour écriture

SYNTAXE

#include <pthread.h>
int pthread_rwlock_trywrlock(pthread_rwlock_t *rwlock);
int pthread_rwlock_wrlock(pthread_rwlock_t *rwlock);

DESCRIPTION

La fonction pthread_rwlock_trywrlock() applique un verrou en écriture, comme la fonction pthread_rwlock_wrlock(), à l'exception près que la fonction échoue si un thread détient actuellement rwlock (en lecture ou en écriture).

La fonction pthread_rwlock_wrlock() applique un verrou en écriture au verrou lecture-écriture référencé par rwlock. Le thread appelant acquiert le verrou en écriture si aucun thread (lecteur ou rédacteur) ne détient le verrou lecture-écriture rwlock. Sinon, si un autre thread détient le verrou lecture-écriture rwlock, le thread appelant se bloque jusqu'à ce qu'il puisse acquérir le verrou. Si une condition d'interblocage se produit ou si le thread appelant possède déjà le verrou lecture-écriture pour l'écriture ou la lecture, l'appel se bloque ou retourne [EDEADLK].

Les résultats ne sont pas définis si l'une de ces fonctions est appelée avec un verrou lecture-écriture non initialisé.

Si un signal est délivré à un thread en attente d'un verrou lecture-écriture pour l'écriture, au retour du gestionnaire de signal, le thread reprend son attente du verrou lecture-écriture pour l'écriture comme s'il n'avait pas été interrompu.

VALEUR DE RETOUR

La fonction pthread_rwlock_trywrlock() retourne zéro si le verrou en écriture sur l'objet verrou lecture-écriture référencé par rwlock est acquis. Sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

En cas de succès, la fonction pthread_rwlock_wrlock() retourne zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_rwlock_trywrlock() échoue si :

EBUSY
Le verrou lecture-écriture n'a pas pu être acquis pour l'écriture car il était déjà verrouillé en lecture ou en écriture.

La fonction pthread_rwlock_wrlock() peut échouer si :

EDEADLK
Une condition d'interblocage a été détectée ou le thread courant possède déjà le verrou lecture-écriture pour l'écriture ou la lecture.

Ces fonctions ne retournent pas de code d'erreur [EINTR].

EXEMPLES

Aucun.

UTILISATION APPLICATIVE

Les applications utilisant ces fonctions peuvent être sujettes à l'inversion de priorité, comme discuté dans le volume Base Definitions de POSIX.1-2017, Section 3.291, Inversion de Priorité.

RATIONALE

Si une implémentation détecte que la valeur spécifiée par l'argument rwlock dans pthread_rwlock_trywrlock() ou pthread_rwlock_wrlock() ne fait pas référence à un objet verrou lecture-écriture initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].
