PTHREAD_SETCANCELSTATE(3P) Manuel du programmeur POSIX PTHREAD_SETCANCELSTATE(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_setcancelstate, pthread_setcanceltype, pthread_testcancel — définir l'état d'annulabilité

SYNOPSIS

#include <pthread.h>
int pthread_setcancelstate(int state, int *oldstate);
int pthread_setcanceltype(int type, int *oldtype);
void pthread_testcancel(void);

DESCRIPTION

La fonction pthread_setcancelstate() définit de manière atomique l'état d'annulabilité du thread appelant à l'état indiqué et retourne l'état d'annulabilité précédent à l'emplacement référencé par oldstate. Les valeurs légales pour state sont PTHREAD_CANCEL_ENABLE et PTHREAD_CANCEL_DISABLE.

La fonction pthread_setcanceltype() définit de manière atomique le type d'annulabilité du thread appelant au type indiqué et retourne le type d'annulabilité précédent à l'emplacement référencé par oldtype. Les valeurs légales pour type sont PTHREAD_CANCEL_DEFERRED et PTHREAD_CANCEL_ASYNCHRONOUS.

L'état et le type d'annulabilité de tous les threads nouvellement créés, y compris le thread dans lequel main() a été invoqué pour la première fois, seront respectivement PTHREAD_CANCEL_ENABLE et PTHREAD_CANCEL_DEFERRED.

La fonction pthread_testcancel() crée un point d'annulation dans le thread appelant. La fonction pthread_testcancel() n'aura aucun effet si l'annulabilité est désactivée.

VALEUR DE RETOUR

En cas de succès, les fonctions pthread_setcancelstate() et pthread_setcanceltype() retournent zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_setcancelstate() peut échouer si :

EINVAL
L'état spécifié n'est ni PTHREAD_CANCEL_ENABLE ni PTHREAD_CANCEL_DISABLE.

La fonction pthread_setcanceltype() peut échouer si :

EINVAL
Le type spécifié n'est ni PTHREAD_CANCEL_DEFERRED ni PTHREAD_CANCEL_ASYNCHRONOUS.

Ces fonctions ne doivent pas retourner le code d'erreur [EINTR].

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION APPLICATION

Afin d'écrire un gestionnaire de signal pour un signal asynchrone qui peut s'exécuter en toute sécurité dans un thread annulable, pthread_setcancelstate() doit être utilisé pour désactiver l'annulation pour la durée de tous les appels que le gestionnaire de signal effectue et qui sont des points d'annulation. Cependant, la norme ne permet pas aux applications strictement conformes d'appeler pthread_setcancelstate() depuis un gestionnaire de signal car il n'est pas actuellement requis d'être sûr pour les signaux asynchrones. Sur les implémentations où pthread_setcancelstate() n'est pas sûr pour les signaux asynchrones, les alternatives consistent à s'assurer que les signaux correspondants sont bloqués pendant l'exécution des fonctions qui ne sont pas sûres pour l'annulation asynchrone ou que l'annulation est désactivée pendant les moments où ces signaux pourraient être délivrés. Les implémentations sont fortement encouragées à rendre pthread_setcancelstate() sûr pour les signaux asynchrones.

RATIONALE

Les fonctions pthread_setcancelstate() et pthread_setcanceltype() contrôlent les points auxquels un thread peut être annulé de manière asynchrone. Pour que le contrôle d'annulation soit utilisable de manière modulaire, certaines règles doivent être suivies.

Un objet peut être considéré comme une généralisation d'une procédure. C'est un ensemble de procédures et de variables globales écrites comme une unité et appelées par des clients inconnus de l'objet. Les objets peuvent dépendre d'autres objets.

Premièrement, l'annulabilité ne doit être désactivée qu'à l'entrée d'un objet, jamais explicitement activée. À la sortie d'un objet, l'état d'annulabilité doit toujours être restauré à sa valeur à l'entrée de l'objet.

Cela découle d'un argument de modularité : si le client d'un objet (ou le client d'un objet qui utilise cet objet) a désactivé l'annulabilité, c'est parce que le client ne veut pas avoir à se soucier du nettoyage si le thread est annulé pendant l'exécution d'une séquence d'actions. Si un objet est appelé dans un tel état et qu'il active l'annulabilité et qu'une requête d'annulation est en attente pour ce thread, alors le thread est annulé, contrairement au souhait du client qui l'a désactivée.

Deuxièmement, le type d'annulabilité peut être explicitement défini sur différé ou asynchrone à l'entrée d'un objet. Mais comme pour l'état d'annulabilité, à la sortie d'un objet, le type d'annulabilité doit toujours être restauré à sa valeur à l'entrée de l'objet.

Enfin, seules les fonctions qui sont sûres pour l'annulation peuvent être appelées à partir d'un thread qui est annulable de manière asynchrone.

DIRECTIONS FUTURES

La fonction pthread_setcancelstate() pourrait être ajoutée au tableau des fonctions sûres pour les signaux asynchrones dans la Section 2.4.3, Actions de signal.

pthread_setcancelstate(3) — pthreads — ARCHLINUX

NOM

pthread_setcancelstate — définir l'état d'annulation et le type d'annulation d'un thread

SYNOPIS

#include <pthread.h>

int pthread_setcancelstate(int state, int *oldstate);
int pthread_setcanceltype(int type, int *oldtype);

DESCRIPTION

La fonction pthread_setcancelstate définit l'état d'annulation du thread appelant. L'état d'annulation peut être PTHREAD_CANCEL_ENABLE (l'annulation est activée) ou PTHREAD_CANCEL_DISABLE (l'annulation est désactivée). La valeur initiale de l'état d'annulation est PTHREAD_CANCEL_ENABLE.

Si oldstate n'est pas un pointeur NULL, le réglage de l'état d'annulation précédent est stocké dans l'emplacement pointé par oldstate.

La fonction pthread_setcanceltype définit le type d'annulation du thread appelant. Le type d'annulation peut être PTHREAD_CANCEL_DEFERRED (les annulations sont reportées jusqu'à ce que le thread atteigne un point de désactivation d'annulation) ou PTHREAD_CANCEL_ASYNCHRONOUS (l'annulation peut se produire à tout moment).

La valeur initiale du type d'annulation est PTHREAD_CANCEL_DEFERRED.

Si oldtype n'est pas un pointeur NULL, le réglage du type d'annulation précédent est stocké dans l'emplacement pointé par oldtype.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient 0. En cas d'erreur, elles renvoient un numéro d'erreur positif.

ERREURS

EINVAL

La valeur spécifiée pour state ou type n'est pas valide.

EXEMPLES

pthread_setcancelstate(PTHREAD_CANCEL_DISABLE, NULL);
// Effectuer des opérations critiques ici...
pthread_setcancelstate(PTHREAD_CANCEL_ENABLE, NULL);

UTILISATION DANS UNE APPLICATION

Ces fonctions sont utilisées pour contrôler quand et comment un thread peut être annulé. L'état d'annulation est utilisé pour activer ou désactiver temporairement l'annulation, tandis que le type d'annulation contrôle le moment où une annulation peut se produire.

RAISON D'ÊTRE

Les fonctions pthread_setcancelstate et pthread_setcanceltype fournissent aux développeurs un contrôle fin sur la gestion de l'annulation des threads. Ceci est particulièrement important dans les scénarios où un thread exécute des opérations critiques qui ne doivent pas être interrompues ou lorsque des ressources doivent être nettoyées avant que le thread ne se termine.

ORIENTATIONS FUTURES

Aucune orientation future n'est spécifiée pour ces fonctions.
