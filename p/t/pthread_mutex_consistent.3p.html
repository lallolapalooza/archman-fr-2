PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_mutex_consistent — marquer l'état protégé par un mutex robuste comme étant cohérent

SYNTAXE

#include <pthread.h>
int pthread_mutex_consistent(pthread_mutex_t *mutex);

DESCRIPTION

Si mutex est un mutex robuste dans un état incohérent, la fonction pthread_mutex_consistent() peut être utilisée pour marquer l'état protégé par le mutex référencé par mutex comme étant à nouveau cohérent.

Si un propriétaire d'un mutex robuste se termine tout en détenant le mutex, le mutex devient incohérent et le prochain thread qui acquiert le verrou du mutex doit être notifié de l'état par la valeur de retour [EOWNERDEAD]. Dans ce cas, le mutex ne redevient normalement utilisable qu'une fois l'état marqué comme cohérent.

Si le thread qui a acquis le verrou du mutex avec la valeur de retour [EOWNERDEAD] se termine avant d'appeler soit pthread_mutex_consistent(), soit pthread_mutex_unlock(), le prochain thread qui acquiert le verrou du mutex doit être notifié de l'état du mutex par la valeur de retour [EOWNERDEAD].

Le comportement est indéfini si la valeur spécifiée par l'argument mutex à pthread_mutex_consistent() ne fait pas référence à un mutex initialisé.

VALEUR DE RETOUR

En cas de succès, la fonction pthread_mutex_consistent() renvoie zéro. Sinon, une valeur d'erreur est renvoyée pour indiquer l'erreur.

ERREURS

La fonction pthread_mutex_consistent() échouera si :

EINVAL
L'objet mutex référencé par mutex n'est pas robuste ou ne protège pas un état incohérent.

Ces fonctions ne renverront pas de code d'erreur [EINTR].

EXEMPLES

Aucun.

UTILISATION PAR L'APPLICATION

La fonction pthread_mutex_consistent() est uniquement responsable de notifier l'implémentation que l'état protégé par le mutex a été récupéré et que les opérations normales avec le mutex peuvent reprendre. Il incombe à l'application de récupérer l'état afin qu'il puisse être réutilisé. Si l'application n'est pas en mesure d'effectuer la récupération, elle peut notifier l'implémentation que la situation n'est pas récupérable par un appel à pthread_mutex_unlock() sans un appel préalable à pthread_mutex_consistent(), auquel cas les threads ultérieurs qui tentent de verrouiller le mutex échoueront à acquérir le verrou et recevront [ENOTRECOVERABLE].

JUSTIFICATION

Si une implémentation détecte que la valeur spécifiée par l'argument mutex à pthread_mutex_consistent() ne fait pas référence à un mutex initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].
