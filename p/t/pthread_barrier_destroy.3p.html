PTHREAD_BARRIER_DESTROY(3P) Manuel du programmeur POSIX PTHREAD_BARRIER_DESTROY(3P)

PROLOG

Cette page de manuel fait partie du manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_barrier_destroy, pthread_barrier_init — détruire et initialiser un objet barrière

SYNTAXE

#include <pthread.h>
int pthread_barrier_destroy(pthread_barrier_t *barrier);
int pthread_barrier_init(pthread_barrier_t *restrict barrier,
    const pthread_barrierattr_t *restrict attr, unsigned count);

DESCRIPTION

La fonction pthread_barrier_destroy() détruit la barrière référencée par barrier et libère toutes les ressources utilisées par la barrière. L'effet d'une utilisation ultérieure de la barrière est indéfini jusqu'à ce que la barrière soit réinitialisée par un autre appel à pthread_barrier_init(). Une implémentation peut utiliser cette fonction pour définir barrier à une valeur invalide. Les résultats sont indéfinis si pthread_barrier_destroy() est appelée alors qu'un thread est bloqué sur la barrière, ou si cette fonction est appelée avec une barrière non initialisée.

La fonction pthread_barrier_init() alloue toutes les ressources nécessaires à l'utilisation de la barrière référencée par barrier et initialise la barrière avec les attributs référencés par attr. Si attr est NULL, les attributs de barrière par défaut sont utilisés ; l'effet est le même que de passer l'adresse d'un objet d'attributs de barrière par défaut. Les résultats sont indéfinis si pthread_barrier_init() est appelée alors qu'un thread est bloqué sur la barrière (c'est-à-dire qu'il n'est pas revenu de l'appel pthread_barrier_wait()). Les résultats sont indéfinis si une barrière est utilisée sans être préalablement initialisée. Les résultats sont indéfinis si pthread_barrier_init() est appelée en spécifiant une barrière déjà initialisée.

L'argument count spécifie le nombre de threads qui doivent appeler pthread_barrier_wait() avant que l'un d'entre eux ne retourne avec succès de l'appel. La valeur spécifiée par count doit être supérieure à zéro.

Si la fonction pthread_barrier_init() échoue, la barrière ne sera pas initialisée et le contenu de barrier est indéfini.

Voir la Section 2.9.9, Copies d'objets de synchronisation et mappings alternatifs pour des exigences supplémentaires.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_barrier_init() échouera si :

EAGAIN
Le système manque des ressources nécessaires pour initialiser une autre barrière.
EINVAL
La valeur spécifiée par count est égale à zéro.
ENOMEM
Il n'y a pas assez de mémoire pour initialiser la barrière.

Ces fonctions ne retourneront pas de code d'erreur [EINTR].

RATIONALE

Si une implémentation détecte que la valeur spécifiée par l'argument barrier pour pthread_barrier_destroy() ne fait pas référence à un objet barrière initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].

Si une implémentation détecte que la valeur spécifiée par l'argument attr pour pthread_barrier_init() ne fait pas référence à un objet attributs barrière initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].

Si une implémentation détecte que la valeur spécifiée par l'argument barrier pour pthread_barrier_destroy() ou pthread_barrier_init() fait référence à une barrière en cours d'utilisation (par exemple, dans un appel pthread_barrier_wait()) par un autre thread, ou détecte que la valeur spécifiée par l'argument barrier pour pthread_barrier_init() fait référence à un objet barrière déjà initialisé, il est recommandé que la fonction échoue et signale une erreur [EBUSY].
