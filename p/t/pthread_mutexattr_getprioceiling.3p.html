PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_mutexattr_getprioceiling, pthread_mutexattr_setprioceiling — obtenir et définir l'attribut prioceiling de l'objet d'attributs de mutex (THREADS TEMPS RÉEL)

SYNTAXE

#include <pthread.h>
int pthread_mutexattr_getprioceiling(const pthread_mutexattr_t
    *restrict attr, int *restrict prioceiling);
int pthread_mutexattr_setprioceiling(pthread_mutexattr_t *attr,
    int prioceiling);

DESCRIPTION

Les fonctions pthread_mutexattr_getprioceiling() et pthread_mutexattr_setprioceiling() obtiennent et définissent respectivement l'attribut prioceiling (plafond de priorité) d'un objet d'attributs de mutex pointé par attr qui a été précédemment créé par la fonction pthread_mutexattr_init().

L'attribut prioceiling contient le plafond de priorité des mutex initialisés. Les valeurs de prioceiling sont comprises dans la plage maximale des priorités définies par SCHED_FIFO.

L'attribut prioceiling définit le plafond de priorité des mutex initialisés, qui est le niveau de priorité minimum auquel la section critique protégée par le mutex est exécutée. Afin d'éviter l'inversion de priorité, le plafond de priorité du mutex doit être défini à une priorité supérieure ou égale au niveau de priorité le plus élevé de tous les threads qui peuvent verrouiller ce mutex. Les valeurs de prioceiling sont comprises dans la plage maximale des priorités définies sous la politique de planification SCHED_FIFO.

Le comportement est indéfini si la valeur spécifiée par l'argument attr à pthread_mutexattr_getprioceiling() ou pthread_mutexattr_setprioceiling() ne fait pas référence à un objet d'attributs de mutex initialisé.

VALEUR DE RETOUR

En cas de succès, les fonctions pthread_mutexattr_getprioceiling() et pthread_mutexattr_setprioceiling() retournent zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

Ces fonctions peuvent échouer si :

EINVAL
La valeur spécifiée par prioceiling est invalide.
EPERM
L'appelant n'a pas le privilège d'effectuer l'opération.

Ces fonctions ne doivent pas retourner le code d'erreur [EINTR].

UTILISATION APPLICATION

RATIONALE

Si une implémentation détecte que la valeur spécifiée par l'argument attr à pthread_mutexattr_getprioceiling() ou pthread_mutexattr_setprioceiling() ne fait pas référence à un objet d'attributs de mutex initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].
