NOM

pt-diskstats - Un outil de surveillance I/O interactif pour GNU/Linux.

SYNTAXE

Utilisation : pt-diskstats [OPTIONS] [FICHIERS]

pt-diskstats affiche les statistiques d'I/O disque pour GNU/Linux. Il est quelque peu similaire à iostat, mais il est interactif et plus détaillé. Il peut analyser des échantillons collectés à partir d'une autre machine.

RISQUES

Percona Toolkit est mature, éprouvé dans le monde réel et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Examiner les "BUGS" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

L'outil pt-diskstats est similaire à iostat, mais présente des avantages. Il affiche les statistiques de lecture et d'écriture séparément, et possède plus de colonnes. Il est piloté par menu et interactif, avec plusieurs façons différentes d'agréger les données. Il s'intègre bien avec l'outil pt-stalk. Il fait également la bonne chose" par défaut, comme masquer les disques inactifs. Ces propriétés le rendent très pratique pour analyser rapidement les performances I/O et inspecter le comportement des disques.

Ce programme fonctionne en deux modes. Le mode par défaut consiste à collecter des échantillons de /proc/diskstats et à afficher les statistiques formatées à intervalles réguliers. L'autre mode consiste à traiter un fichier contenant des échantillons sauvegardés de /proc/diskstats ; il y a un script shell plus loin dans cette documentation qui montre comment collecter un tel fichier.

Dans les deux cas, l'outil est contrôlé interactivement par des frappes de clavier, vous pouvez donc réafficher et découper les données de manière flexible et facile. Il boucle indéfiniment, jusqu'à ce que vous sortiez avec la touche 'q'. Si vous appuyez sur la touche '?', vous ouvrirez le menu d'aide interactif qui montre quelles touches contrôlent le programme.

Lorsque le programme collecte des échantillons de /proc/diskstats et rafraîchit son affichage, il affiche des informations sur le nouvel échantillon chaque fois qu'il se rafraîchit. Lorsqu'il travaille sur un fichier d'échantillons sauvegardés, il redessine tout le contenu du fichier chaque fois que vous modifiez une option.

Le programme n'affiche pas d'informations sur tous les périphériques blocs du système. Il masque les périphériques pour lesquels il n'a jamais observé d'activité. Vous pouvez activer et désactiver cela en appuyant sur la touche 'i'.

SORTIE

Dans le reste de cette documentation, nous essaierons de clarifier la distinction entre les périphériques blocs (/dev/sda1, par exemple), que le noyau présente à l'application via un système de fichiers, et le périphérique (généralement physique) sous-jacent au périphérique bloc, qui pourrait être un disque, un contrôleur RAID, etc. Nous ferons parfois référence à des opérations I/O logiques, qui se produisent au niveau du périphérique bloc, par rapport aux I/O physiques qui sont effectuées sur le périphérique sous-jacent. Lorsque nous parlons de la file d'attente, nous parlons de la file d'attente associée au périphérique bloc, qui contient les requêtes jusqu'à ce qu'elles soient émises au périphérique physique.

#ts
Le contenu de cette colonne varie en fonction du mode d'agrégation de l'outil. En mode par défaut, lorsque chaque ligne contient des informations sur un seul disque mais agrège éventuellement plusieurs échantillons de ce disque, cette colonne montre le nombre d'échantillons qui ont été inclus dans la ligne de sortie, entre {accolades}. Dans l'exemple montré, chaque ligne de sortie agrège {10} échantillons de /proc/diskstats.

En mode "tout" groupé par, cette colonne affiche les décalages temporels, relatifs à l'heure à laquelle l'outil a commencé l'agrégation ou à l'horodatage des lignes précédentes imprimées, selon le mode. La sortie peut être déroutante à expliquer, mais elle est assez intuitive lorsque vous voyez les lignes apparaître périodiquement sur votre écran.

De même, en mode groupé par "échantillon", le nombre indique la durée totale qui est regroupée dans chaque échantillon.

Si vous spécifiez "--show-timestamps", ce champ affiche à la place l'horodatage auquel l'échantillon a été pris ; si plusieurs horodatages sont présents dans une seule ligne de sortie, alors le premier horodatage est utilisé.

appareil
Le nom de l'appareil. S'il y a plus d'un appareil, le nombre d'appareils agrégés dans la ligne est affiché, entre {accolades}.
rd_s
Le nombre moyen de lectures par seconde. C'est le nombre de requêtes I/O qui ont été envoyées à l'appareil sous-jacent. C'est généralement un nombre plus petit que le nombre de requêtes I/O logiques effectuées par les applications. Plus de requêtes pourraient avoir été mises en file d'attente pour le périphérique bloc, mais certaines d'entre elles sont généralement fusionnées avant d'être envoyées au disque.

Ce champ est calculé à partir du contenu de /proc/diskstats comme suit. Voir "DOCUMENTATION DU NOYAU" ci-dessous pour la signification des numéros de champ :

delta[champ1] / delta[temps]
rd_avkb
La taille moyenne des lectures, en kilooctets. Ce champ est calculé comme suit : 
2 * delta[champ3] / delta[champ1]
rd_mb_s
Le nombre moyen de mégaoctets lus par seconde. Calculé comme suit : 
2 * delta[champ3] / delta[temps]
rd_mrg
Le pourcentage de requêtes de lecture qui ont été fusionnées dans le planificateur de file d'attente avant d'être envoyées au périphérique physique. Le champ est calculé comme suit : 
100 * delta[champ2] / (delta[champ2] + delta[champ1])
rd_cnc
La concurrence moyenne des opérations de lecture, calculée selon la loi de Little. C'est la concurrence de bout en bout sur le périphérique bloc, pas la concurrence du disque sous-jacent. Elle inclut le temps passé dans la file d'attente. Le champ est calculé comme suit : 
delta[champ4] / delta[temps] / 1000 / appareils-dans-le-groupe
rd_rt
Le temps de réponse moyen des opérations de lecture, en millisecondes. C'est le temps de réponse de bout en bout, y compris le temps passé dans la file d'attente. C'est le temps de réponse que l'application effectuant des requêtes I/O voit, pas le temps de réponse du disque physique sous-jacent au périphérique bloc. Il est calculé comme suit : 
delta[champ4] / (delta[champ1] + delta[champ2])
wr_s, wr_avkb, wr_mb_s, wr_mrg, wr_cnc, wr_rt
Ces colonnes montrent l'activité d'écriture, et elles correspondent aux colonnes correspondantes pour l'activité de lecture.
occupé
La fraction du temps d'horloge pendant laquelle l'appareil avait au moins une requête en cours ; c'est ce que iostat appelle %util, et en effet c'est l'utilisation, selon la façon dont vous définissez l'utilisation, mais c'est parfois ambigu dans le langage courant. Cela peut aussi être appelé temps de résidence ; le temps pendant lequel au moins une requête était résidente dans le système. Il est calculé comme suit : 
100 * delta[champ10] / (1000 * delta[temps])

Ce champ ne peut pas dépasser 100 % sauf en cas d'erreur d'arrondi, mais c'est une erreur courante de penser qu'un appareil qui est occupé tout le temps est saturé. Un appareil tel qu'un volume RAID devrait supporter une concurrence supérieure à 1, et les disques SSD peuvent supporter une concurrence très élevée. DESCRIPTION

Ce script est un outil pour l'analyse des statistiques de disque collectées à partir de /proc/diskstats. Il peut produire les mêmes informations que iostat(1) mais avec des noms de colonnes plus descriptifs et une sortie formatée.

Voici une description des colonnes que vous trouverez dans la sortie de pt-diskstats:

rd_s
Le débit moyen de lecture du périphérique physique, en opérations d'E/S par seconde (IOPS).
rd_avkb
La taille moyenne des lectures, en kilo-octets par secteur. (Voir aussi avgrq-sz dans la section Comparaison avec iostat).
rd_mb_s
Le débit de lecture en mégaoctets par seconde.
rd_mrg
Le pourcentage de lectures qui ont été fusionnées. La fusion se produit lorsque le périphérique reçoit plusieurs requêtes de lecture adjacentes et les fusionne en une seule requête physique. Un pourcentage élevé ici est une bonne chose, car cela signifie que le périphérique essaie de minimiser le nombre d'opérations physiques.
rd_cnc
Le nombre moyen de lectures en cours d'exécution. Il s'agit d'une moyenne de la concurrence des opérations de lecture. Plus ce nombre est élevé, plus le périphérique est sollicité par des lectures.
rd_rt
Le temps de réponse moyen pour les lectures, en millisecondes. Il s'agit du temps total nécessaire pour terminer une opération de lecture, y compris le temps d'attente dans la file d'attente et le temps de traitement par le périphérique.
wr_s
Le débit moyen d'écriture du périphérique physique, en opérations d'E/S par seconde (IOPS).
wr_avkb
La taille moyenne des écritures, en kilo-octets par secteur.
wr_mb_s
Le débit d'écriture en mégaoctets par seconde.
wr_mrg
Le pourcentage d'écritures qui ont été fusionnées.
wr_cnc
Le nombre moyen d'écritures en cours d'exécution.
wr_rt
Le temps de réponse moyen pour les écritures, en millisecondes.
busy
Le pourcentage de temps pendant lequel le périphérique était occupé à traiter des E/S. C'est l'équivalent de la colonne %util de iostat(1). Une utilisation élevée indique que le périphérique est fortement sollicité.
in_prg
Le nombre de requêtes en cours. Contrairement aux concurrences de lecture et d'écriture, qui sont des moyennes générées à partir de chiffres fiables, ce nombre est un échantillon instantané, et vous pouvez voir qu'il peut représenter un pic de requêtes, plutôt que la vraie moyenne à long terme. Si ce nombre est élevé, cela signifie essentiellement que le périphérique est fortement sollicité. Il est calculé comme suit : 
field9
ios_s
Le débit moyen du périphérique physique, en opérations d'E/S par seconde (IOPS). Cette colonne montre le total des IOPS gérés par le périphérique sous-jacent. C'est la somme de rd_s et wr_s.
qtime
Le temps moyen d'attente dans la file ; c'est-à-dire le temps qu'une requête passe dans la file d'attente du planificateur du périphérique avant d'être envoyée au périphérique physique. C'est une moyenne sur les lectures et les écritures.

Il est calculé d'une manière légèrement complexe : le temps de réponse moyen vu par l'application, moins le temps de service moyen (voir la description de la colonne suivante). Ceci est dérivé de la formule de théorie des files d'attente pour le temps de réponse, R = W + S : temps de réponse = temps d'attente + temps de service. Ceci est résolu pour W, bien sûr, pour donner W = R - S. Le calcul suit :

delta[field11] / (delta[field1, 2, 5, 6] + delta[field9])
   - delta[field10] / delta[field1, 2, 5, 6]

Voir la description de "stime" pour plus de détails et de précautions.

stime
Le temps de service moyen ; c'est-à-dire le temps écoulé pendant que le périphérique physique traite la requête, après que la requête a fini d'attendre dans la file d'attente. C'est une moyenne sur les lectures et les écritures. Il est calculé à partir de la formule d'utilisation de la théorie des files d'attente, U = SX, résolu pour S. Cela signifie que l'utilisation divisée par le débit donne le temps de service : 
delta[field10] / (delta[field1, 2, 5, 6])

Notez, cependant, qu'il peut y avoir des bugs dans le noyau qui provoquent des valeurs négatives pour le champ 9 dans /proc/diskstats, et cela peut rendre le champ 10 incorrect, rendant ainsi le calcul du temps de service pas entièrement fiable.

Notez que dans la formule ci-dessus, nous utilisons l'utilisation très spécifiquement. Il s'agit d'une durée, pas d'un pourcentage.

Vous pouvez comparer les colonnes stime et qtime pour voir si le temps de réponse pour les lectures et les écritures est passé dans la file d'attente ou sur le périphérique physique. Cependant, vous ne pouvez pas voir la différence entre les lectures et les écritures. Changer l'algorithme du planificateur de périphériques de bloc peut grandement améliorer le temps d'attente dans la file. L'algorithme par défaut, cfq, est très mauvais pour les serveurs, et ne devrait être utilisé que sur les ordinateurs portables et les postes de travail qui effectuent des tâches telles que travailler avec des feuilles de calcul et naviguer sur Internet.

La correspondance entre les colonnes n'est pas univoque. En particulier :

rrqm/s, wrqm/s
Ces colonnes dans iostat(1) sont remplacées par rd_mrg et wr_mrg dans pt-diskstats.
avgrq-sz
Cette colonne est en secteurs dans iostat(1), et est une combinaison de lectures et d'écritures. La sortie de pt-diskstats les sépare et les affiche en Ko. Vous pouvez en déduire une moyenne pondérée de rd_avkb et wr_avkb dans pt-diskstats, puis multiplier par 2 pour obtenir des secteurs (chaque secteur fait 512 octets).
avgqu-sz
Cette colonne représente réellement la concurrence au niveau du planificateur de périphériques de bloc. La sortie de pt-diskstats affiche la concurrence pour les lectures et les écritures séparément : rd_cnc et wr_cnc.
await
Cette colonne est le temps de réponse moyen du début à la fin d'une requête vers le périphérique de bloc, y compris le temps d'attente et le temps de service, et n'est pas affichée dans pt-diskstats. Au lieu de cela, pt-diskstats affiche les temps de réponse individuels au niveau du disque pour les lectures et les écritures (rd_rt et wr_rt), ainsi que le temps d'attente par rapport au temps de service pour les lectures et les écritures en agrégat.
svctm
Cette colonne est le temps de service moyen au niveau du disque, et est affichée comme stime dans pt-diskstats.
%util
Cette colonne est appelée busy dans pt-diskstats. L'utilisation est généralement définie comme la portion de temps pendant laquelle il y avait au moins une requête active, et non comme un pourcentage, c'est pourquoi nous avons choisi d'éviter ce terme confus.

COLLECTING DATA

Il est simple de collecter un échantillon de données pour cet outil. Les fichiers doivent avoir ce format, avec une ligne d'horodatage précédant chaque échantillon de statistiques :

TS <timestamp>
<contenu de /proc/diskstats>
TS <timestamp>
<contenu de /proc/diskstats>
... et ainsi de suite

Vous pouvez simplement utiliser pt-diskstats avec "--save-samples" pour collecter ces données pour vous. Si vous souhaitez capturer des échantillons dans le cadre d'un autre outil, et utiliser pt-diskstats pour les analyser, vous pouvez inclure un extrait de script shell comme suit :

INTERVAL=1
while true; do
   sleep=$(date +%s.%N | awk "{print $INTERVAL - (\$1 % $INTERVAL)}")
   sleep $sleep
   date +"TS %s.%N %F %T" >> diskstats-samples.txt
   cat /proc/diskstats >> diskstats-samples.txt
done

KERNEL DOCUMENTATION

Cette documentation complète la documentation officielle http://www.kernel.org/doc/Documentation/iostats.txt sur le contenu de /proc/diskstats. Cette documentation peut parfois être difficile à comprendre pour ceux qui ne sont pas familiarisés avec les internes du noyau Linux. Le contenu de /proc/diskstats est généré par la fonction diskstats_show() dans le fichier source du noyau block/genhd.c.

Voici un exemple de /proc/diskstats sur un noyau récent.

8 1 sda1 426 243 3386 2056 3 0 18 87 0 2135 2142

Les champs de cet exemple sont les suivants. Les trois premiers champs sont les numéros de périphérique majeur et mineur (8, 1), et le nom du périphérique (sda1). Ils sont suivis de 11 champs de statistiques :

1.
Le nombre de lectures terminées. C'est le nombre de lectures physiques effectuées par le disque sous-jacent, pas le nombre de lectures que les applications ont faites à partir du périphérique de bloc. Cela signifie que 426 lectures réelles ont été effectuées avec succès sur le disque sur lequel réside /dev/sda1. Les lectures ne sont comptées qu'à leur achèvement.
2.
Le nombre de lectures fusionnées car elles étaient adjacentes. Dans l'exemple, 243 lectures ont été fusionnées. Cela signifie que /dev/sda1 a effectivement reçu 869 lectures logiques, mais n'a envoyé que 426 lectures physiques au périphérique physique sous-jacent.
3.
Le nombre de secteurs lus avec succès. Les 426 lectures physiques sur le disque ont lu 3386 secteurs. Les secteurs font 512 octets, donc un total d'environ 1,65 Mo a été lu depuis /dev/sda1.
4.
Le nombre de millisecondes passées à lire. Cela ne compte que les lectures terminées, pas celles en cours. Il compte le temps passé depuis que les requêtes sont mises dans la file d'attente jusqu'à ce qu'elles se terminent, pas le temps que le disque sous-jacent passe à traiter les requêtes. C'est-à-dire qu'il mesure le temps de réponse total vu par les applications, pas les temps de réponse du disque.
5.
Idem pour le champ 1, mais pour les écritures.
6.
Idem pour le champ 2, mais pour les écritures.
7.
Idem pour le champ 3, mais pour les écritures.
8.
Idem pour le champ 4, mais pour les écritures.
9.
Le nombre d'E/S actuellement en cours, c'est-à-dire qu'elles ont été planifiées par le planificateur de file d'attente et émises vers le disque (soumises à la file d'attente du disque sous-jacent), mais pas encore terminées. Il y a des bugs dans certains noyaux qui font que ce nombre, et donc les champs 10 et 11, sont parfois incorrects.
10.
Le nombre total de millisecondes passées à effectuer des E/S. Ce n'est **pas** le temps de réponse total vu par les applications ; c'est la durée totale pendant laquelle au moins une E/S était en cours. Si une E/S est émise au temps 100, une autre arrive à 101, et les deux se terminent à 102, alors ce champ s'incrémente de 2, pas de 3.
11.
Ce champ compte le temps de réponse total de toutes les E/S. Contrairement au champ 10, il compte double lorsque deux E/S se chevauchent. Dans notre exemple précédent, ce champ s'incrémenterait de 3, pas de 2.

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Reportez-vous à la section "SYNOPSIS" et aux informations d'utilisation pour plus de détails.

--columns-regex
type : chaîne ; par défaut : .

Imprimer les colonnes qui correspondent à cette expression régulière Perl.

x.

--config
type : Array

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, ce doit être la première option de la ligne de commande.

--devices-regex
type : string

Imprimer les périphériques qui correspondent à cette expression régulière Perl.

--group-by
type : string ; défaut : all

Mode de regroupement : disk, sample, ou all. En mode disk, chaque ligne de sortie affiche un périphérique de disque, avec les statistiques calculées depuis le démarrage de l'outil. En mode sample, chaque ligne de sortie affiche un échantillon de statistiques, avec tous les disques moyennés ensemble. En mode all, chaque ligne de sortie affiche un échantillon et un périphérique de disque.

--headers
type : Hash ; défaut : group,scroll

Si "group" est présent, chaque échantillon sera séparé par une ligne vide, sauf si l'échantillon n'est qu'une seule ligne. Si "scroll" est présent, l'outil imprimera les en-têtes aussi souvent que nécessaire pour éviter qu'ils ne défilent hors de la vue. Notez que vous pouvez appuyer sur la barre d'espace, ou la touche Entrée, pour réimprimer les en-têtes à volonté.

--help
Afficher l'aide et quitter.
--interval
type : int ; défaut : 1

En mode interactif, attendre N secondes avant d'imprimer à l'écran. C'est aussi la fréquence à laquelle l'outil doit échantillonner /proc/diskstats.

L'outil tente de collecter les statistiques exactement à des intervalles réguliers de temps horloge. C'est-à-dire, si vous spécifiez un intervalle de 5 secondes, il essaiera de capturer des échantillons à 12:00:00, 12:00:05, et ainsi de suite ; il ne collectera pas à 12:00:01, 12:00:06 et ainsi de suite.

Cela peut entraîner des retards légèrement inhabituels dans certaines circonstances, car l'outil attend un cycle complet avant d'imprimer le premier ensemble de lignes. (Contrairement à iostat et vmstat, pt-diskstats ne commence pas par une ligne représentant les moyennes depuis le démarrage de l'ordinateur.) Par conséquent, la règle a une exception pour éviter des délais très longs. Supposons que vous spécifiez un intervalle de 10 secondes, mais que vous démarrez l'outil à 12:00:00.01. L'outil pourrait attendre jusqu'à 12:00:20 pour imprimer ses premières lignes de sortie, et pendant les 19,99 secondes intermédiaires, il semblerait ne rien faire.

Pour atténuer cela, l'outil attend le prochain intervalle de temps régulier pour collecter, à moins qu'il ne reste plus de 20 % de cet intervalle. Cela signifie que l'outil n'attendra jamais plus de 120 % de l'intervalle d'échantillonnage pour produire une sortie, par exemple si vous démarrez l'outil à 12:00:53 avec un intervalle d'échantillonnage de 10 secondes, alors le premier échantillon ne durera que 7 secondes, pas 10 secondes.

--iterations
type : int

En mode interactif, arrêter après N échantillons. S'exécute indéfiniment par défaut.

--sample-time
type : int ; défaut : 1

En mode --group-by sample, inclure N secondes d'échantillons par groupe.

--save-samples
type : string

Fichier où enregistrer les échantillons de diskstats ; ceux-ci peuvent être utilisés pour une analyse ultérieure.

--show-inactive
Afficher les périphériques inactifs.
--show-timestamps
Afficher un horodatage 'HH:MM:SS' dans la colonne "#ts". Si plusieurs horodatages sont agrégés dans une seule ligne, le premier horodatage est affiché.
--version
Afficher la version et quitter.
--[no]version-check
défaut : yes

Vérifier la dernière version de Percona Toolkit, MySQL et d'autres programmes.

Il s'agit d'une fonctionnalité standard de « vérifier les mises à jour automatiquement », avec deux fonctionnalités supplémentaires. Premièrement, l'outil vérifie sa propre version ainsi que les versions des logiciels suivants : système d'exploitation, Percona Monitoring and Management (PMM), MySQL, Perl, pilote MySQL pour Perl (DBD::mysql) et Percona Toolkit. Deuxièmement, il vérifie et avertit des versions présentant des problèmes connus. Par exemple, MySQL 5.5.25 avait un bug critique et a été réédité sous la version 5.5.25a.

Une connexion sécurisée au serveur de base de données de vérification de version de Percona est établie pour effectuer ces vérifications. Chaque requête est enregistrée par le serveur, y compris les numéros de version des logiciels et l'identifiant unique du système vérifié. L'identifiant est généré par le script d'installation de Percona Toolkit ou lors du premier appel à la base de données de vérification de version.

Toutes les mises à jour ou problèmes connus sont imprimés sur STDOUT avant la sortie normale de l'outil. Cette fonctionnalité ne devrait jamais interférer avec le fonctionnement normal de l'outil.

Pour plus d'informations, visitez https://www.percona.com/doc/percona-toolkit/LATEST/version-check.html.

ENVIRONNEMENT

La variable d'environnement "PTDEBUG" active la sortie de débogage détaillée sur STDERR. Pour activer le débogage et capturer toutes les sorties dans un fichier, exécutez l'outil comme suit :

PTDEBUG=1 pt-diskstats ... > FICHIER 2>&1

Attention : la sortie de débogage est volumineuse et peut générer plusieurs mégaoctets de sortie.

ATTENTION

L'utilisation de <PTDEBUG> peut exposer des mots de passe. Lorsque le débogage est activé, tous les paramètres de la ligne de commande sont affichés dans la sortie.

EXIGENCES DU SYSTÈME

Cet outil nécessite Perl v5.8.0 ou une version ultérieure et le système de fichiers /proc, sauf s'il lit à partir de fichiers.
