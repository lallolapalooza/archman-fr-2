PTHREAD_ONCE(3P) Manuel du programmeur POSIX PTHREAD_ONCE(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

pthread_once — initialisation dynamique de paquet

SYNTAXE

#include <pthread.h>
int pthread_once(pthread_once_t *once_control,
    void (*init_routine)(void));
pthread_once_t once_control = PTHREAD_ONCE_INIT;

DESCRIPTION

Le premier appel à pthread_once() par n'importe quel fil d'exécution dans un processus, avec un once_control donné, appellera la init_routine sans arguments. Les appels ultérieurs à pthread_once() avec le même once_control n'appelleront pas la init_routine. Au retour de pthread_once(), la init_routine sera terminée. Le paramètre once_control déterminera si la routine d'initialisation associée a été appelée.

La fonction pthread_once() n'est pas un point d'annulation. Cependant, si init_routine est un point d'annulation et est annulé, l'effet sur once_control sera comme si pthread_once() n'avait jamais été appelée.

Si l'appel à init_routine est terminé par un appel à longjmp(), _longjmp(), ou siglongjmp(), le comportement est indéfini.

La constante PTHREAD_ONCE_INIT est définie dans l'en-tête <pthread.h>.

Le comportement de pthread_once() est indéfini si once_control a une durée de vie automatique ou n'est pas initialisé par PTHREAD_ONCE_INIT.

VALEUR DE RETOUR

En cas de succès, pthread_once() retournera zéro ; sinon, un numéro d'erreur sera retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_once() ne retournera pas le code d'erreur [EINTR].

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

USAGE APPLICATION

Si init_routine appelle récursivement pthread_once() avec le même once_control, l'appel récursif n'appellera pas la init_routine spécifiée, et donc la init_routine spécifiée ne se terminera pas, et donc l'appel récursif à pthread_once() ne retournera pas. L'utilisation de longjmp(), _longjmp(), ou siglongjmp() dans une init_routine pour sauter vers un point extérieur à init_routine empêche init_routine de retourner.

RATIONALE

Certaines bibliothèques C sont conçues pour l'initialisation dynamique. C'est-à-dire que l'initialisation globale de la bibliothèque est effectuée lorsque la première procédure de la bibliothèque est appelée. Dans un programme mono-fil, cela est normalement implémenté à l'aide d'une variable statique dont la valeur est vérifiée à l'entrée d'une routine, comme suit :

static int random_is_initialized = 0;
extern void initialize_random(void);
int random_function()
{
    if (random_is_initialized == 0) {
        initialize_random();
        random_is_initialized = 1;
    }
    ... /* Opérations effectuées après l'initialisation. */
}

Pour conserver la même structure dans un programme multi-fils, un nouveau primitif est nécessaire. Sinon, l'initialisation de la bibliothèque doit être réalisée par un appel explicite à une fonction d'initialisation exportée par la bibliothèque avant toute utilisation de la bibliothèque.

Pour l'initialisation dynamique de bibliothèque dans un processus multi-fils, si un indicateur d'initialisation est utilisé, l'indicateur doit être protégé contre la modification par plusieurs fils appelant simultanément la bibliothèque. Cela peut être fait en utilisant un mutex (initialisé en attribuant PTHREAD_MUTEX_INITIALIZER). Cependant, la meilleure solution est d'utiliser pthread_once() qui est conçu précisément à cet effet, comme suit :

#include <pthread.h>
static pthread_once_t random_is_initialized = PTHREAD_ONCE_INIT;
extern void initialize_random(void);
int random_function()
{
    (void) pthread_once(&random_is_initialized, initialize_random);
    ... /* Opérations effectuées après l'initialisation. */
}

Si une implémentation détecte que la valeur spécifiée par le paramètre once_control à pthread_once() ne fait pas référence à un objet pthread_once_t initialisé par PTHREAD_ONCE_INIT, il est recommandé que la fonction échoue et signale une erreur [EINVAL].
