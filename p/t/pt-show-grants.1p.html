NOM

pt-show-grants - Canonicalise et affiche les privilèges MySQL pour pouvoir les répliquer, comparer et contrôler en version efficacement.

SYNOPIS

Utilisation : pt-show-grants [OPTIONS] [DSN]

pt-show-grants affiche les privilèges (autorisations utilisateur) d'un serveur MySQL.

Exemples :

pt-show-grants
pt-show-grants --separate --revoke | diff othergrants.sql -

RISQUES

Percona Toolkit est mature, éprouvé en conditions réelles et bien testé, mais tous les outils de base de données peuvent présenter un risque pour le système et le serveur de base de données. Avant d'utiliser cet outil, veuillez :

  • Lire la documentation de l'outil
  • Consulter les "BUGS" connus de l'outil
  • Tester l'outil sur un serveur non-production
  • Sauvegarder votre serveur de production et vérifier les sauvegardes

DESCRIPTION

pt-show-grants extrait, ordonne, puis affiche les privilèges des comptes utilisateurs MySQL.

Pourquoi voudriez-vous cela ? Il y a plusieurs raisons.

La première est de répliquer facilement des utilisateurs d'un serveur à un autre ; vous pouvez simplement extraire les privilèges du premier serveur et rediriger la sortie directement vers un autre serveur.

La deuxième utilisation est de placer vos privilèges sous contrôle de version. Si vous effectuez un vidage automatisé quotidien de vos privilèges dans un système de contrôle de version, vous obtiendrez de nombreux jeux de modifications non pertinents pour les privilèges qui ne changent pas, car MySQL affiche les privilèges réels dans un ordre apparemment aléatoire. Par exemple, un jour il affichera

GRANT DELETE, INSERT, UPDATE ON `test`.* TO 'foo'@'%';

Et un autre jour, il affichera

GRANT INSERT, DELETE, UPDATE ON `test`.* TO 'foo'@'%';

Les privilèges n'ont pas changé, mais l'ordre si. Ce script trie les privilèges à l'intérieur de la ligne, entre 'GRANT' et 'ON'. S'il y a plusieurs lignes issues de SHOW GRANTS, il trie également les lignes, sauf qu'il affiche toujours la ligne contenant le mot de passe de l'utilisateur en premier, si elle existe. Cela élimine trois types d'incohérences que vous obtiendrez en exécutant SHOW GRANTS, et évite les jeux de modifications non pertinents dans le contrôle de version.

Troisièmement, si vous souhaitez comparer les privilèges entre serveurs, ce sera difficile sans les "canonicaliser", ce que fait pt-show-grants. La sortie est entièrement diff-able.

Avec les options "--revoke", "--separate" et autres, pt-show-grants facilite également la révocation de privilèges spécifiques aux utilisateurs. C'est fastidieux autrement.

OPTIONS

Cet outil accepte des arguments de ligne de commande supplémentaires. Référez-vous à la "SYNOPIS" et aux informations d'utilisation pour plus de détails.

--ask-pass
Demander un mot de passe lors de la connexion à MySQL.
--charset
forme courte : -A ; type : chaîne

Jeu de caractères par défaut. Si la valeur est utf8, définit le mode binaire de Perl sur STDOUT en utf8, passe l'option mysql_enable_utf8 à DBD::mysql, et exécute SET NAMES UTF8 après la connexion à MySQL. Toute autre valeur définit le mode binaire sur STDOUT sans la couche utf8, et exécute SET NAMES après la connexion à MySQL.

--config
type : Tableau

Lire cette liste de fichiers de configuration séparés par des virgules ; si spécifié, cela doit être la première option sur la ligne de commande.

--database
forme courte : -D ; type : chaîne

La base de données à utiliser pour la connexion.

--defaults-file
forme courte : -F ; type : chaîne

Lire uniquement les options mysql du fichier donné. Vous devez spécifier un chemin absolu.

--drop
Ajouter DROP USER avant chaque utilisateur dans la sortie.
--flush
Ajouter FLUSH PRIVILEGES après la sortie.

Vous pourriez en avoir besoin sur les serveurs pré-4.1.1 si vous voulez supprimer complètement un utilisateur.

--[no]header
par défaut : oui

Afficher l'en-tête du vidage.

L'en-tête précède les privilèges vidés. Il ressemble à ceci :

-- Grants dumped by pt-show-grants 1.0.19
-- Dumped from server Localhost via UNIX socket, MySQL 5.0.82-log at 2009-10-26 10:01:04

Voir aussi "--[no]timestamp".

--help
Afficher l'aide et quitter.
--host
forme courte : -h ; type : chaîne

Se connecter à l'hôte.

--ignore
type : tableau

Ignorer cette liste d'utilisateurs séparés par des virgules.

--only
type : tableau

Afficher uniquement les privilèges pour cette liste d'utilisateurs séparés par des virgules.

--convert-MariaDB
Convertir la syntaxe propriétaire de MariaDB en une forme MySQL valide
--password
forme courte : -p ; type : chaîne

Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

--pid
type : chaîne

Créer le fichier PID donné. L'outil ne démarrera pas si le fichier PID existe déjà et que le PID qu'il contient est différent du PID actuel. Cependant, si le fichier PID existe et que le PID qu'il contient n'est plus en cours d'exécution, l'outil écrasera le fichier PID avec le PID actuel. Le fichier PID est supprimé automatiquement à la sortie de l'outil.

--port
forme courte : -P ; type : entier

Numéro de port à utiliser pour la connexion.

--revoke
Ajouter des instructions REVOKE pour chaque instruction GRANT.
--separate
Lister chaque GRANT ou REVOKE séparément.

La sortie par défaut de la commande SHOW GRANTS de MySQL liste de nombreux privilèges sur une seule ligne. Avec "--flush", place un FLUSH PRIVILEGES après chaque utilisateur, au lieu d'une seule fois à la fin de toute la sortie.

--set-vars
type : Tableau

Définir les variables MySQL dans cette liste de paires "variable=valeur" séparées par des virgules.

Par défaut, l'outil définit :

wait_timeout=10000

Les variables spécifiées sur la ligne de commande remplacent ces valeurs par défaut. Par exemple, spécifier "--set-vars wait_timeout=500" remplace la valeur par défaut de 10000.

L'outil affiche un avertissement et continue si une variable ne peut pas être définie.

--[no]include-unused-roles
Lors du vidage des rôles MySQL 8+, inclure les rôles non utilisés.
--socket
forme courte : -S ; type : chaîne

Fichier socket à utiliser pour la connexion.

--[no]timestamp
par défaut : oui

Ajouter un horodatage à l'en-tête du vidage.

Voir aussi "--[no]header".

--user
forme courte : -u ; type : chaîne

Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

--version
Afficher la version et quitter.

OPTIONS DSN

Ces options DSN sont utilisées pour créer un DSN. Chaque option est donnée sous la forme "option=valeur". Les options sont sensibles à la casse, donc P et p ne sont pas la même option. Il ne peut y avoir d'espace avant ou après le "=" et si la valeur contient des espaces, elle doit être mise entre guillemets. Les options DSN sont séparées par des virgules. Voir la page man percona-toolkit pour tous les détails.

  • A

    dsn : charset ; copie : oui

    Jeu de caractères par défaut.

  • D

    dsn : database ; copie : oui

    Base de données par défaut.

  • F

    dsn : mysql_read_default_file ; copie : oui

    Lire uniquement les options par défaut du fichier donné

  • h

    dsn : host ; copie : ou s

    Connect to host.

  • p

    dsn: password; copy: yes

    Mot de passe à utiliser lors de la connexion. Si le mot de passe contient des virgules, elles doivent être échappées avec une barre oblique inverse : "exam\,ple"

  • P

    dsn: port; copy: yes

    Numéro de port à utiliser pour la connexion.

  • S

    dsn: mysql_socket; copy: yes

    Fichier de socket à utiliser pour la connexion.

  • u

    dsn: user; copy: yes

    Utilisateur pour la connexion si ce n'est pas l'utilisateur actuel.

  • s

    dsn: mysql_ssl; copy: yes

    Créer une connexion SSL

ENVIRONNEMENT

La variable d'environnement "PTDEBUG" active une sortie de débogage verbeuse sur STDERR. Pour activer le débogage et capturer toute la sortie dans un fichier, exécutez l'outil comme suit :

PTDEBUG=1 pt-show-grants ... > FICHIER 2>&1

Attention : la sortie de débogage est volumineuse et peut générer plusieurs mégaoctets de sortie.

ATTENTION

L'utilisation de <PTDEBUG> peut exposer les mots de passe. Lorsque le débogage est activé, tous les paramètres de la ligne de commande sont affichés dans la sortie.

EXIGENCES SYSTÈME

Vous avez besoin de Perl, DBI, DBD::mysql, et de certains paquets de base qui devraient être installés dans toute version raisonnablement récente de Perl.
