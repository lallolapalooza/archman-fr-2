pthread_setcancelstate(3) Manuel des fonctions de bibliothèque pthread_setcancelstate(3)

NOM

pthread_setcancelstate, pthread_setcanceltype - définir l'état et le type d'annulabilité

BIBLIOTHÈQUE

Bibliothèque POSIX threads (libpthread, -lpthread)

SYNOPSIS

#include <pthread.h>
int pthread_setcancelstate(int state, int *oldstate);
int pthread_setcanceltype(int type, int *oldtype);

DESCRIPTION

La fonction pthread_setcancelstate() définit l'état d'annulabilité du thread appelant à la valeur indiquée par state. L'état d'annulabilité précédent du thread est retourné dans le buffer pointé par oldstate. L'argument state doit avoir l'une des valeurs suivantes :

PTHREAD_CANCEL_ENABLE
Le thread est annulable. C'est l'état d'annulabilité par défaut de tous les nouveaux threads, y compris le thread initial. Le type d'annulabilité du thread détermine quand un thread annulable répondra à une demande d'annulation.
PTHREAD_CANCEL_DISABLE
Le thread n'est pas annulable. Si une demande d'annulation est reçue, elle est bloquée jusqu'à ce que l'annulabilité soit activée.

La fonction pthread_setcanceltype() définit le type d'annulabilité du thread appelant à la valeur indiquée par type. Le type d'annulabilité précédent du thread est retourné dans le buffer pointé par oldtype. L'argument type doit avoir l'une des valeurs suivantes :

PTHREAD_CANCEL_DEFERRED
Une demande d'annulation est différée jusqu'à ce que le thread appelle une fonction qui est un point d'annulation (voir pthreads(7)). C'est le type d'annulabilité par défaut de tous les nouveaux threads, y compris le thread initial.
Même avec l'annulation différée, un point d'annulation dans un gestionnaire de signaux asynchrone peut encore être traité et l'effet est comme s'il s'agissait d'une annulation asynchrone.
PTHREAD_CANCEL_ASYNCHRONOUS
Le thread peut être annulé à tout moment. (Généralement, il sera annulé immédiatement à la réception d'une demande d'annulation, mais le système ne garantit pas cela.)

L'opération de définition et d'obtention effectuée par chacune de ces fonctions est atomique par rapport aux autres threads du processus appelant la même fonction.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent 0 ; en cas d'erreur, elles retournent un numéro d'erreur non nul.

ERREURS

La fonction pthread_setcancelstate() peut échouer avec l'erreur suivante :

EINVAL
Valeur invalide pour state.

La fonction pthread_setcanceltype() peut échouer avec l'erreur suivante :

EINVAL
Valeur invalide pour type.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
pthread_setcancelstate (), pthread_setcanceltype () Thread safety MT-Safe
pthread_setcancelstate (), pthread_setcanceltype () Async-cancel safety AC-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

glibc 2.0 POSIX.1-2001.

NOTES

Pour plus de détails sur ce qui se passe lorsqu'un thread est annulé, voir pthread_cancel(3).

Désactiver brièvement l'annulabilité est utile si un thread effectue une action critique qui ne doit pas être interrompue par une demande d'annulation. Méfiez-vous de désactiver l'annulabilité pendant de longues périodes, ou autour d'opérations qui peuvent bloquer pendant de longues périodes, car cela rendra le thread insensible aux demandes d'annulation.

Annulabilité asynchrone

Définir le type d'annulabilité à PTHREAD_CANCEL_ASYNCHRONOUS est rarement utile. Étant donné que le thread peut être annulé à tout moment, il ne peut pas réserver en toute sécurité des ressources (par exemple, allouer de la mémoire avec malloc(3)), acquérir des mutex, des sémaphores, des verrous, etc. La réservation de ressources est dangereuse car l'application n'a aucun moyen de savoir quel est l'état de ces ressources lorsque le thread est annulé ; c'est-à-dire, l'annulation s'est-elle produite avant la réservation des ressources, pendant leur réservation, ou après leur libération ? De plus, certaines structures de données internes (par exemple, la liste chaînée de blocs libres gérée par la famille de fonctions malloc(3)) peuvent être laissées dans un état incohérent si l'annulation se produit au milieu de l'appel de fonction. Par conséquent, les gestionnaires de nettoyage cessent d'être utiles.

Les fonctions qui peuvent être annulées de manière asynchrone en toute sécurité sont appelées fonctions sûres pour l'annulation asynchrone. POSIX.1-2001 et POSIX.1-2008 exigent uniquement que pthread_cancel(3), pthread_setcancelstate() et pthread_setcanceltype() soient sûres pour l'annulation asynchrone. En général, d'autres fonctions de bibliothèque ne peuvent pas être appelées en toute sécurité depuis un thread avec annulabilité asynchrone.

L'une des rares circonstances où l'annulabilité asynchrone est utile est pour l'annulation d'un thread qui est dans une boucle de calcul pure.

Notes de portabilité

Les implémentations de threading Linux permettent que l'argument oldstate de pthread_setcancelstate() soit NULL, auquel cas les informations sur l'état d'annulabilité précédent ne sont pas retournées à l'appelant. De nombreuses autres implémentations permettent également un argument oldstat NULL, mais POSIX.1 ne spécifie pas ce point, donc les applications portables devraient toujours spécifier une valeur non NULL pour oldstate. Un ensemble de déclarations précisément analogue s'applique à l'argument oldtype de pthread_setcanceltype().
