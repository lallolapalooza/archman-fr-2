PTHREAD_RWLOCK_RDLOCK(3P) Manuel du programmeur POSIX PTHREAD_RWLOCK_RDLOCK(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pthread_rwlock_rdlock, pthread_rwlock_tryrdlock — verrouiller un objet de verrouillage lecture-écriture pour la lecture

SYNTAXE

#include <pthread.h>
int pthread_rwlock_rdlock(pthread_rwlock_t *rwlock);
int pthread_rwlock_tryrdlock(pthread_rwlock_t *rwlock);

DESCRIPTION

La fonction pthread_rwlock_rdlock() applique un verrou de lecture à l'objet de verrouillage lecture-écriture référencé par rwlock. Le thread appelant acquiert le verrou de lecture si aucun écrivain ne détient le verrou et s'il n'y a pas d'écrivains bloqués sur le verrou.

Si l'option de planification d'exécution des threads est prise en charge, et que les threads impliqués dans le verrou exécutent avec les politiques de planification SCHED_FIFO ou SCHED_RR, le thread appelant n'acquiert pas le verrou si un écrivain le détient ou si des écrivains de priorité plus élevée ou égale sont bloqués sur le verrou ; sinon, le thread appelant acquiert le verrou.

Si l'option de planification d'exécution des threads est prise en charge, et que les threads impliqués dans le verrou exécutent avec la politique de planification SCHED_SPORADIC, le thread appelant n'acquiert pas le verrou si un écrivain le détient ou si des écrivains de priorité plus élevée ou égale sont bloqués sur le verrou ; sinon, le thread appelant acquiert le verrou.

Si l'option de planification d'exécution des threads n'est pas prise en charge, il est défini par l'implémentation si le thread appelant acquiert le verrou lorsqu'un écrivain ne détient pas le verrou et qu'il y a des écrivains bloqués sur le verrou. Si un écrivain détient le verrou, le thread appelant n'acquiert pas le verrou de lecture. Si le verrou de lecture n'est pas acquis, le thread appelant se bloque jusqu'à ce qu'il puisse acquérir le verrou. Le thread appelant peut se bloquer indéfiniment si, au moment de l'appel, il détient un verrou d'écriture.

Un thread peut détenir plusieurs verrous de lecture simultanés sur rwlock (c'est-à-dire appeler avec succès la fonction pthread_rwlock_rdlock() n fois). Si c'est le cas, l'application doit s'assurer que le thread effectue des déverrouillages correspondants (c'est-à-dire qu'il appelle la fonction pthread_rwlock_unlock() n fois).

Le nombre maximum de verrous de lecture simultanés qu'une implémentation garantit pouvoir être appliqués à un verrou de lecture-écriture est défini par l'implémentation. La fonction pthread_rwlock_rdlock() peut échouer si ce maximum est dépassé.

La fonction pthread_rwlock_tryrdlock() applique un verrou de lecture comme dans la fonction pthread_rwlock_rdlock(), à l'exception du fait que la fonction échoue si l'appel équivalent à pthread_rwlock_rdlock() aurait bloqué le thread appelant. Dans aucun cas la fonction pthread_rwlock_tryrdlock() ne se bloque ; elle acquiert toujours le verrou ou échoue et retourne immédiatement.

Les résultats ne sont pas définis si l'une de ces fonctions est appelée avec un objet de verrouillage lecture-écriture non initialisé.

Si un signal est délivré à un thread attendant un verrou de lecture-écriture pour la lecture, au retour du gestionnaire de signal, le thread reprend l'attente du verrou de lecture-écriture pour la lecture comme s'il n'avait pas été interrompu.

VALEUR DE RETOUR

En cas de succès, la fonction pthread_rwlock_rdlock() retourne zéro ; sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

La fonction pthread_rwlock_tryrdlock() retourne zéro si le verrou de lecture sur l'objet de verrouillage lecture-écriture référencé par rwlock est acquis. Sinon, un numéro d'erreur est retourné pour indiquer l'erreur.

ERREURS

La fonction pthread_rwlock_tryrdlock() échoue si :

EBUSY
Le verrou lecture-écriture n'a pas pu être acquis pour la lecture car un écrivain détient le verrou ou un écrivain de priorité appropriée était bloqué dessus.

Les fonctions pthread_rwlock_rdlock() et pthread_rwlock_tryrdlock() peuvent échouer si :

EAGAIN
Le verrou de lecture n'a pas pu être acquis car le nombre maximum de verrous de lecture pour rwlock a été dépassé.

La fonction pthread_rwlock_rdlock() peut échouer si :

EDEADLK
Une condition d'interblocage a été détectée ou le thread courant détient déjà le verrou lecture-écriture pour l'écriture.

Ces fonctions ne retourneront pas de code d'erreur [EINTR].

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

USAGE APPLICATION

Les applications utilisant ces fonctions peuvent être sujettes à l'inversion de priorité, comme discuté dans le volume des Définitions de base de POSIX.1-2017, Section 3.291, Inversion de priorité.

RATIONALE

Si une implémentation détecte que la valeur spécifiée par l'argument rwlock à pthread_rwlock_rdlock() ou pthread_rwlock_tryrdlock() ne fait pas référence à un objet de verrouillage lecture-écriture initialisé, il est recommandé que la fonction échoue et signale une erreur [EINVAL].
