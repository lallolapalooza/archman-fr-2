NOM

pcap_get_required_select_timeout - obtenir un délai d'attente à utiliser lors de l'appel à select() pour une capture en direct

SYNTAXE

#include <pcap/pcap.h>
const struct timeval *pcap_get_required_select_timeout(pcap_t *p);

DESCRIPTION

pcap_get_required_select_timeout() renvoie, sous UNIX, un pointeur vers une structure struct timeval contenant une valeur qui doit être utilisée comme délai d'attente minimum dans les appels select(2), poll(2), epoll_wait(2) et kevent(2), ou NULL s'il n'y a pas de délai d'attente. Si une valeur non-NULL est renvoyée, elle doit être utilisée quel que soit le descripteur renvoyé par pcap_get_selectable_fd(3PCAP) (-1) sur lequel ces appels sont effectués. pcap_get_required_select_timeout() doit être appelé pour tous les pcap_t avant un appel à select(), poll(), epoll_wait() ou kevent(), et tout délai d'attente utilisé pour ces appels doit être mis à jour en conséquence de la nouvelle valeur du délai d'attente.

Pour kevent(), un filtre EVFILT_TIMER par descripteur sélectionnable peut être utilisé, plutôt que l'argument délai d'attente de kevent(); si l'événement EVFILT_TIMER pour un descripteur sélectionnable particulier signale un événement, pcap_dispatch(3PCAP) doit être appelé pour le pcap_t correspondant.

Sur les systèmes Linux avec timerfd_create(2), un objet timer créé par timerfd_create() par descripteur sélectionnable peut être utilisé, plutôt que l'argument délai d'attente de epoll_wait(); si l'objet timer pour un descripteur sélectionnable particulier signale un événement, pcap_dispatch(3PCAP) doit être appelé pour le pcap_t correspondant.

Sinon, une valeur de délai d'attente ne dépassant pas la plus petite de toutes les valeurs de délai d'attente renvoyées par pcap_get_required_select_timeout() pour les périphériques à partir desquels les paquets seront capturés et tout autre délai d'attente à utiliser dans l'appel doit être utilisé comme délai d'attente pour l'appel, et, lorsque l'appel renvoie, pcap_dispatch(3PCAP) doit être appelé pour tous les pcap_t pour lesquels un délai d'attente non-NULL a été renvoyé, qu'il soit indiqué ou non qu'il y a quelque chose à lire.

Tous les périphériques avec un délai d'attente non-NULL doivent être mis en mode non bloquant avec pcap_setnonblock(3PCAP).

Notez qu'un périphérique sur lequel une lecture peut être effectuée sans blocage peut, sur certaines plateformes, ne pas avoir de paquets à lire si le délai d'attente du tampon de paquets a expiré. Un appel à pcap_dispatch() ou pcap_next_ex(3PCAP) renverra 0 dans ce cas, mais ne bloquera pas.

pcap_get_required_select_timeout() n'est pas disponible sous Windows.

VALEUR RENVOYÉE

Un pointeur vers une structure struct timeval est renvoyé si le délai d'attente est requis ; sinon, NULL est renvoyé.

COMPATIBILITÉ ASCENDANTE

Cette fonction est devenue disponible dans la version 1.9.0 de libpcap. Dans les versions précédentes, select(), poll(), epoll_wait() et kevent() ne pouvaient pas être utilisés pour les périphériques qui ne fournissent pas un descripteur de fichier sélectionnable (en d'autres termes, sur toute source de capture pour laquelle pcap_get_selectable_fd() renvoie -1).

Dans la version 1.10.0 et ultérieures de libpcap, la valeur du délai d'attente peut changer d'un appel à l'autre, de sorte que pcap_get_required_select_timeout() doit être appelé avant chaque appel à select(), poll(), epoll_wait() ou kevent(), et la nouvelle valeur doit être utilisée pour calculer les délais d'attente pour l'appel. Le code qui fait cela fonctionnera également avec les versions 1.9.x de libpcap, donc le code utilisant pcap_get_required_select_timeout() doit être modifié pour l'appeler pour chaque appel à select(), poll(), epoll_wait() ou kevent() même si le code doit également fonctionner avec libpcap 1.9.x.
