PMSTAT(1) Manuel des commandes générales PMSTAT(1)

NOM

pcp-vmstat, pmstat - vue d'ensemble des performances système de haut niveau

SYNTAXE

pcp [options pcp] vmstat [intervalle [échantillons]]

pmstat [-gLlPVxz?] [-a archives] [-A alignement] [-D debug] [-h hôte] [-H fichier] [-n fichier pmns] [-O décalage] [-p port] [-s échantillons] [-S heure début] [-t intervalle] [-T heure fin] [-Z fuseau horaire]

pcp-vmstat ...

DESCRIPTION

pmstat fournit un résumé en une ligne des performances système toutes les intervalles unités de temps (la valeur par défaut est 5 secondes). pmstat est destiné à surveiller les performances système au plus haut niveau, après quoi d'autres outils peuvent être utilisés pour examiner les sous-systèmes dans lesquels des problèmes de performance potentiels peuvent être observés plus en détail.

pcp-vmstat est un simple wrapper destiné à être utilisé avec la commande pcp(1), offrant un format de ligne de commande plus familier à certains utilisateurs. Il active également l'option de rapport étendu par défaut, voir l'option -x ci-dessous.

Plusieurs hôtes peuvent être surveillés en fournissant plusieurs hôtes avec plusieurs indicateurs -h (pour la surveillance en direct) ou en fournissant le nom d'un fichier de liste d'hôtes, où chaque ligne contient un nom d'hôte, avec -H, ou plusieurs indicateurs -a (pour la surveillance rétrospective à partir d'ensembles d'archives).

Par défaut, pmstat récupère les métriques en se connectant au démon collecteur de métriques de performance (PMCD) sur l'hôte local. Si l'option -L est spécifiée, alors pmcd(1) est contourné, et les métriques sont récupérées des PMDA sur l'hôte local en utilisant la variante autonome PM_CONTEXT_LOCAL de pmNewContext(3). Lorsque l'option -h est spécifiée, pmstat se connecte au pmcd(1) sur hôte et y récupère les métriques. Comme mentionné ci-dessus, plusieurs hôtes peuvent être surveillés en fournissant plusieurs indicateurs -h.

Alternativement, si l'option -a est utilisée, les métriques sont retrouvées à partir des fichiers d'archives Performance Co-Pilot identifiés par archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives. Plusieurs ensembles d'archives peuvent être rejoués en fournissant plusieurs options -a. Lorsque l'option -a est utilisée, l'option -P peut également être utilisée pour mettre en pause la sortie après chaque intervalle.

Le mode autonome ne peut se connecter qu'à l'hôte local, l'utilisation d'un ensemble d'archives implique un nom d'hôte, et la nomination d'un hôte empêche l'utilisation d'une archive, donc les options -L, -a et -h sont mutuellement exclusives.

pmstat peut céder son propre contrôle temporel, et fonctionner sous le contrôle d'un processus pmtime(1) qui utilise une boîte de dialogue graphique pour fournir un contrôle temporel. Dans ce cas, soit l'option -g devrait être utilisée pour lancer pmstat comme client unique d'une nouvelle instance pmtime(1), soit -p devrait être utilisé pour attacher pmstat à une instance pmtime(1) existante via le canal IPC identifié par l'argument port.

Les options -S, -T, -O et -A peuvent être utilisées pour définir une fenêtre temporelle afin de restreindre les échantillons récupérés, définir une origine initiale dans la fenêtre temporelle, ou spécifier un alignement « naturel » des temps d'échantillonnage ; référez-vous à PCPIntro(1) pour une description complète de ces options.

OPTIONS

Les options de ligne de commande disponibles sont :

-a archives, --archive=archives
Les valeurs des métriques de performance sont récupérées de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archives, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Forcer l'échantillon initial à être aligné sur la limite d'une unité de temps naturelle alignement. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe pour alignement.
-g, --guimode
Lancer pmstat comme client d'un nouveau processus serveur pmtime(1) pour la relecture des données de performance archivées en utilisant l'interface graphique de pmtime(1).
-h hôte, --host=hôte
Récupérer les métriques de performance depuis pmcd(1) sur hôte, plutôt que depuis localhost par défaut.
-H chemin, --hostsfile=chemin
Spécifier le chemin vers un fichier contenant un ensemble de noms d'hôtes où pmcd(1) est en cours d'exécution, plutôt que d'utiliser localhost par défaut.
-K spec, --spec-local=spec
Lors de la récupération de métriques depuis un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui devraient être rendus accessibles. L'argument spec est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peut être utilisée.
-l, --suffix
Imprime les 7 derniers caractères d'un nom d'hôte dans les résumés impliquant plus d'un hôte (lorsque plusieurs options -h ont été spécifiées sur la ligne de commande).
-L, --local-PMDA
Utiliser un contexte local pour collecter les métriques des PMDA DSO sur l'hôte local sans PMCD. Voir aussi -K.
-n fichier pmns, --namespace=fichier pmns
Charger un espace de noms de métriques de performance (PMNS) alternatif (PMNS(5)) à partir du fichier fichier pmns.
-O origine, --origin=origine
Lors du rapport de métriques archivées, commencer le rapport à origine dans la fenêtre temporelle (voir -S et -T). Référez-vous à PCPIntro(1) pour une description complète de la syntaxe pour origine.
-p port, --guiport=port
Attacher pmstat à une instance existante de processus de contrôle temporel pmtime(1) via le canal IPC identifié par l'argument port. Cette option est normalement utilisée uniquement par d'autres outils, par exemple pmchart(1), lorsqu'ils lancent pmstat avec un contrôle temporel synchronisé.
-P, --pause
Pause entre les mises à jour pour la relecture d'archives.
-s échantillons, --samples=échantillons
L'option échantillons définit le nombre d'échantillons à récupérer et à rapporter. Si échantillons est 0 ou si -s n'est pas spécifié, pmstat échantillonnera et rapportera en continu - c'est le comportement par défaut.
-S heure début, --start=heure début
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements journalisés à partir de heure début. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe pour heure début.
-t intervalle, --interval=intervalle
Définir l'intervalle de rapport à quelque chose d'autre que les 5 secondes par défaut. L'argument intervalle suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes).
-T heure fin, --finish=heure fin
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements journalisés avant ou à heure fin.
-V, --version
Affiche le numéro de version et quitte.
pmstat(1) — archlinux.org

NAME

pmstat

Performance Metrics System statistics

SYNOPSIS

pmstat [-h host] [-a archive] [-s socket] [-l logfile] [-p pmns_file] [-t interval] [-T count] [-Z timezone] [-D debug] [-v] [metric ...]

DESCRIPTION

pmstat is a performance metrics (PM) **interface** to the facilities that are used by the pmtime, pmtrace and pmval commands. It displays the performance metrics associated with the performance metrics system (see PMAPI(3)) in a format that is similar to that produced by the vmstat(1) utility.

By default pmstat selects a default set of metrics and displays them every 5 seconds. The -t and -T options may be used to control the reporting interval and the number of reports.

The default set of metrics that are reported are:

        loadavg memory swap io system cpu

The performance metrics that are reported may be changed by the use of the optional command line arguments, which must be valid Performance Metrics Names (PMNS) names (see PMNS(5)).

The metrics are described in the OUTPUT section.

OPTIONS

-h host, --host=host
Connect to PMCD (the Performance Metrics Collection Daemon) on the specified host. If this option is not specified, then the default value is used, namely the value of the PCP_HOST environment variable, or "localhost" if that is not set.
-a archive
Read performance metrics from the specified archive (see pmlogger(1)). The default archive is a set of daily archives named "host/YYYYMMDD" in the current directory.
-s socket
Connect to the PMCD named socket. This may be a host name, or a host name prepended with a protocol specifier and "://". For example, "unix:/path/to/socket" for a local UNIX domain socket, or "tcp://host:port" for a TCP socket.
-l logfile
Write the archive specified by the -a option to the specified logfile. This is used primarily for debugging.
-p pmns_file
Use the specified pmns_file to interpret the performance metric names. The default PMNS is described in PMNS(5).
-t interval
Set the reporting interval to interval seconds. The default is 5 seconds.
-T count
Produce count reports. The default is to produce reports indefinitely.
-x, --xcpu
The extended CPU metrics option, causes three additional CPU metrics to be reported, namely wait for I/O ("wa"), virtualisation steal time ("st"), and virtual guest time ("gu").
-z, --hostzone
Change the reporting timezone to the local timezone at the host that is the source of the performance metrics, as identified via either the -h or -a options.
-Z timezone, --timezone=timezone
By default, pmtime reports the time of day according to the local timezone on the system where pmstat is run. The -Z option changes the timezone to timezone in the format of the environment variable TZ as described in environ(7).
-?, --help
Display usage message and exit.

OUTPUT

The output from pmstat is directed to standard output, and the columns in the report are interpreted as follows:

loadavg
The 1 minute load average.
memory
The swpd column indicates average swap space used during the interval, in Kbytes. The free column indicates average free memory during the interval, in Kbytes. The buff column indicates average buffer memory in use during the interval, in Kbytes. The cache column indicates average cached memory in use during the interval, in Kbytes.

If the values become large, they are reported as Mbytes (m suffix) or Gbytes (g suffix).

swap
The metrics in this area of the kernel instrumentation are of varying value. We try to report the average number of pages that are paged in (pi) and out (po) per second during the interval. If the corresponding page swapping metrics are unavailable, we report the average rate per second of swap operations in (si) and out (so) during the interval. It is normal for the ``in'' values to be non-zero, but the system is suffering memory stress if the ``out'' values are non-zero over an extended period.

If the values become large, they are reported as thousands of operations per second (K suffix) or millions of operations per second (M suffix).

io
The bi and bo columns indicate the average rate per second of block input and block output operations (respectfully) during the interval. Unless all file systems have a 1 Kbyte block size, these rates do not directly indicate Kbytes transferred.

If the values become large, they are reported as thousands of operations per second (K suffix) or millions of operations per second (M suffix).

system
Interrupt rate (in) and context switch rate (cs). Rates are expressed as average operations per second during the interval. Note that the interrupt rate is normally at least HZ (the clock interrupt rate, usually 100) interrupts per second.

If the values become large, they are reported as thousands of operations per second (K suffix) or millions of operations per second (M suffix).

cpu
Percentage of CPU time spent executing user and "nice user" code (us), system and interrupt processing code (sy), idle loop (id).

If any values for the associated performance metrics are unavailable, the value appears as ``?'' in the output.

FILES

$PCP_VAR_DIR/pmns/*
default PMNS specification files
$PCP_VAR_DIR/config/pmlogger/config.pmstat
pmlogger(1) configuration for creating an archive suitable for replay with pmstat

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.
