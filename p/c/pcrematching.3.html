NOM

PCRE - expressions régulières compatibles Perl

ALGORITHMES DE RECHERCHE PCRE

Ce document décrit les deux algorithmes différents disponibles dans PCRE pour rechercher une expression régulière compilée dans une chaîne sujet donnée. L'algorithme « standard » est celui fourni par les fonctions pcre_exec(), pcre16_exec() et pcre32_exec(). Celles-ci fonctionnent de la même manière que la fonction de recherche de Perl et fournissent une opération de recherche compatible avec Perl. L'optimisation juste-à-temps (JIT) décrite dans la documentation pcrejit est compatible avec ces fonctions.

Un algorithme alternatif est fourni par les fonctions pcre_dfa_exec(), pcre16_dfa_exec() et pcre32_dfa_exec() ; elles fonctionnent différemment et ne sont pas compatibles avec Perl. Cette alternative présente des avantages et des inconvénients par rapport à l'algorithme standard, qui sont décrits ci-dessous.

Lorsqu'il n'y a qu'une seule façon possible pour qu'une chaîne sujet donnée corresponde à un motif, les deux algorithmes donnent le même résultat. Une différence survient cependant lorsqu'il existe plusieurs possibilités. Par exemple, si le motif


^<.*>

est recherché dans la chaîne


<quelque chose> <quelque chose d'autre> <encore quelque chose>

il y a trois réponses possibles. L'algorithme standard n'en trouve qu'une seule, tandis que l'algorithme alternatif les trouve toutes les trois.

EXPRESSIONS RÉGULIÈRES SOUS FORME D'ARBRE

L'ensemble des chaînes correspondant à une expression régulière peut être représenté sous forme de structure arborescente. Une répétition illimitée dans le motif rend l'arbre de taille infinie, mais cela reste un arbre. La recherche du motif dans une chaîne sujet donnée (à partir d'un point de départ donné) peut être considérée comme une recherche dans l'arbre. Il existe deux façons de parcourir un arbre : en profondeur d'abord (depth-first) et en largeur d'abord (breadth-first), et celles-ci correspondent aux deux algorithmes de recherche fournis par PCRE.

L'ALGORITHME DE RECHERCHE STANDARD

Dans la terminologie du livre de Jeffrey Friedl « Mastering Regular Expressions », l'algorithme standard est un « algorithme NFA ». Il effectue une recherche en profondeur d'abord dans l'arbre du motif. C'est-à-dire qu'il suit un unique chemin dans l'arbre, vérifiant que le sujet correspond à ce qui est demandé. En cas d'inadéquation, l'algorithme essaie les alternatives au point actuel, et si elles échouent toutes, il revient au point de branchement précédent dans l'arbre, et essaie la branche d'alternative suivante à ce niveau. Cela implique souvent de revenir en arrière (se déplacer vers la gauche) dans la chaîne sujet également. L'ordre dans lequel les branches de répétition sont essayées est contrôlé par la nature gourmande ou peu gourmande du quantificateur.

Si un nœud feuille est atteint, une chaîne correspondante a été trouvée, et l'algorithme s'arrête à ce stade. Ainsi, s'il existe plus d'une correspondance possible, cet algorithme retourne la première qu'il trouve. Qu'il s'agisse de la plus courte, de la plus longue ou d'une longueur intermédiaire dépend de la manière dont les quantificateurs de répétition gourmands et peu gourmands sont spécifiés dans le motif.

Parce qu'il aboutit à un chemin unique dans l'arbre, il est relativement simple pour cet algorithme de garder une trace des sous-chaînes qui sont correspondants par des portions du motif entre parenthèses. Cela fournit un support pour les parenthèses de capture et les références arrière.

L'ALGORITHME DE RECHERCHE ALTERNATIF

Cet algorithme effectue une recherche en largeur d'abord dans l'arbre. En partant du premier point de correspondance dans le sujet, il parcourt la chaîne sujet de gauche à droite, une fois, caractère par caractère, et pendant ce temps, il mémorise tous les chemins dans l'arbre qui représentent des correspondances valides. Dans la terminologie de Friedl, il s'agit d'une sorte d'« algorithme DFA », bien qu'il ne soit pas implémenté comme une machine à états finis traditionnelle (il maintient plusieurs états actifs simultanément).

Bien que le principe général de cet algorithme de recherche soit qu'il parcourt la chaîne sujet une seule fois, sans retour arrière, il y a une exception : lorsqu'une assertion de regard (lookaround) est rencontrée, les caractères qui suivent ou précèdent le point actuel doivent être inspectés indépendamment.

La recherche se poursuit jusqu'à ce que soit la fin du sujet soit atteinte, soit qu'il n'y ait plus de chemins non terminés. À ce stade, les chemins terminés représentent les différentes possibilités de correspondance (s'il n'y en a aucune, la recherche a échoué). Ainsi, s'il existe plus d'une correspondance possible, cet algorithme les trouve toutes, et en particulier, il trouve la plus longue. Les correspondances sont retournées par ordre décroissant de longueur. Il existe une option pour arrêter l'algorithme après la découverte de la première correspondance (qui est nécessairement la plus courte).

Notez que toutes les correspondances trouvées commencent au même point dans le sujet. Si le motif


chat(er(pillar)?)?

est recherché dans la chaîne « le chatouillement attrape » (en supposant que le mot anglais soit « caterpillar catchment »), le résultat sera les trois chaînes « caterpillar », « cater », et « cat » qui commencent au cinquième caractère du sujet. L'algorithme ne passe pas automatiquement à la recherche de correspondances qui commencent à des positions ultérieures.

L'optimisation « auto-possessification » de PCRE s'applique généralement aux répétitions de caractères à la fin d'un motif (ainsi qu'en interne). Par exemple, le motif « a\d+ » est compilé comme s'il était « a\d++ » car il n'y a aucun intérêt à envisager la possibilité de revenir en arrière dans les chiffres répétés. Pour la recherche DFA, cela signifie qu'une seule correspondance possible est trouvée. Si vous souhaitez vraiment plusieurs correspondances dans de tels cas, utilisez soit une répétition non gourmande (« a\d+? »), soit définissez l'option PCRE_NO_AUTO_POSSESS lors de la compilation.

Il existe un certain nombre de fonctionnalités des expressions régulières PCRE qui ne sont pas prises en charge par l'algorithme de recherche alternatif. Elles sont les suivantes :

1. Comme l'algorithme trouve toutes les correspondances possibles, la nature gourmande ou peu gourmande des quantificateurs de répétition n'est pas pertinente. Les quantificateurs gourmands et peu gourmands sont traités exactement de la même manière. Cependant, les quantificateurs possessifs peuvent faire une différence lorsque ce qui suit pourrait également correspondre à ce qui est quantifié, par exemple dans un motif comme celui-ci :


^a++\w!

Ce motif correspond à « aaab! » mais pas à « aaa! », qui serait correspondant par un quantificateur non possessif. De même, si un groupe atomique est présent, il est recherché comme s'il s'agissait d'un motif autonome au point actuel, et la correspondance la plus longue est alors « verrouillée » pour le reste du motif global.

2. Lors du traitement simultané de plusieurs chemins dans l'arbre, il n'est pas simple de garder une trace des sous-chaînes capturées pour les différentes possibilités de correspondance, et l'implémentation de PCRE de cet algorithme ne tente pas de le faire. Cela signifie qu'aucune sous-chaîne capturée n'est disponible.

3. Comme aucune sous-chaîne n'est capturée, les références arrière dans le motif ne sont pas prises en charge et provoquent des erreurs si elles sont rencontrées.

4. Pour la même raison, les expressions conditionnelles qui utilisent une référence arrière comme condition ou test pour une récursion de groupe spécifique ne sont pas prises en charge.

5. Comme de nombreux chemins dans l'arbre peuvent être actifs, la séquence d'échappement \K, qui réinitialise le début de la correspondance lors de sa rencontre (mais peut être présente sur certains chemins et pas sur d'autres), n'est pas prise en charge. Elle provoque une erreur si elle est rencontrée.

6. Les appels (callouts) sont pris en charge, mais la valeur du champ capture_top est toujours 1, et la valeur du champ capture_last est toujours -1.

7. La séquence d'échappement \C, qui (dans l'algorithme standard) correspond toujours à une seule unité de données, même en mode UTF-8, UTF-16 ou UTF-32, n'est pas prise en charge dans ces modes, car l'algorithme alternatif se déplace dans la chaîne sujet un caractère (pas une unité de données) à la fois, pour tous les chemins actifs dans l'arbre.

8. À l'exception de (*FAIL), les verbes de contrôle de retour arrière tels que (*PRUNE) ne sont pas pris en charge. (*FAIL) est pris en charge et se comporte comme une assertion négative échouée.

PCRE MATCHING ALGORITHMS

PCRE uses two different algorithms for matching patterns against subject strings. The standard algorithm is used by default. The alternative algorithm can be selected by setting the PCRE_EXTENDED flag when calling pcre_compile() or pcre_compile_ நிரல்().

REGULAR EXPRESSIONS AS TREES

Both algorithms work by evaluating the regular expression as a tree. The internal representation of a regular expression is a tree structure that reflects the nesting of groups and the order of alternatives. For example, the expression a(b|c)d is represented as a grouping node with two alternatives: the first alternative is the sequence 'a', 'b', 'd', and the second alternative is the sequence 'a', 'c', 'd'.

THE STANDARD MATCHING ALGORITHM

The standard algorithm is based on the algorithm used in Perl. It is a backtracking algorithm. It tries to find the first possible match by starting at the beginning of the subject string and trying to match the pattern. If it can't find a match starting at the current position, it moves on to the next position in the subject string and tries again. If it finds a match, it continues to try and find longer matches if the pattern contains alternatives or possessive quantifiers. If the pattern contains capturing parentheses, it remembers the substrings that match them. If a match is found, it returns the result. If no match is found after trying all possible starting positions, it returns no match.

The standard algorithm is generally fast, especially for patterns that are not ambiguous. However, it can be slow for certain patterns that have a lot of backtracking, such as nested quantifiers or alternations.

THE ALTERNATIVE MATCHING ALGORITHM

The alternative algorithm is a non-backtracking algorithm. It scans the subject string once, and for each position, it checks if the pattern can match starting at that position. It finds all possible matches, and then returns the first one that is found. This algorithm is based on the algorithm used in the Graham Scan.

The alternative algorithm is generally slower than the standard algorithm, but it can be faster for certain patterns that have a lot of backtracking. It is also possible to use this algorithm to find partial matches, which can be useful for matching large files or streams.

ADVANTAGES OF THE ALTERNATIVE ALGORITHM

The alternative algorithm has a number of advantages over the standard algorithm:

1. It is possible to find all possible matches, not just the first one. This is useful for patterns that have multiple possible matches, such as a|a. With the standard algorithm, you have to do kludgy things with callouts to find more than one match.

2. Because the alternative algorithm scans the subject string just once, and never needs to backtrack (except for lookbehinds), it is possible to pass very long subject strings to the matching function in several pieces, checking for partial matching each time. Although it is possible to do multi-segment matching using the standard algorithm by retaining partially matched substrings, it is more complicated. The pcrepartial documentation gives details of partial matching and discusses multi-segment matching.

DISADVANTAGES OF THE ALTERNATIVE ALGORITHM

The alternative algorithm suffers from a number of disadvantages:

1. It is substantially slower than the standard algorithm. This is partly because it has to search for all possible matches, but is also because it is less susceptible to optimization.

2. Capturing parentheses and back references are not supported.

3. Although atomic groups are supported, their use does not provide the performance advantage that it does for the standard algorithm.
