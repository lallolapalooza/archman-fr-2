NOM

PCRE2 - expressions régulières compatibles Perl (API révisée)

INTRODUCTION

PCRE2 est le nom utilisé pour une API révisée de la bibliothèque PCRE, qui est un ensemble de fonctions, écrites en C, qui implémentent la correspondance de motifs d'expressions régulières en utilisant la même syntaxe et sémantique que Perl, avec seulement quelques différences. Après près de deux décennies, les limitations de l'API originale rendaient le développement de plus en plus difficile. La nouvelle API est plus extensible, et elle a été simplifiée en supprimant la fonction d'optimisation séparée "study" ; dans PCRE2, les motifs sont automatiquement optimisés lorsque c'est possible. Depuis le fork de PCRE1, le code a été largement refactorisé et de nouvelles fonctionnalités ont été introduites. L'ancienne bibliothèque est maintenant obsolète et n'est plus maintenue.

Outre les motifs d'expressions régulières de style Perl, certaines fonctionnalités qui sont apparues dans Python et PCRE original avant d'apparaître dans Perl sont disponibles en utilisant la syntaxe Python. Il y a également un support pour certains éléments de syntaxe .NET et Oniguruma, et il existe des options pour demander des changements mineurs qui améliorent la compatibilité ECMAScript (JavaScript).

Le code source de PCRE2 peut être compilé pour supporter des chaînes d'unités de code de 8, 16 ou 32 bits, ce qui signifie que jusqu'à trois bibliothèques distinctes peuvent être installées, une pour chaque taille d'unité de code. La taille d'une unité de code n'est pas liée à la taille en bits du matériel sous-jacent. Dans un environnement 64 bits qui supporte également les applications 32 bits, des versions de PCRE2 compilées en modes 64 bits et 32 bits peuvent être nécessaires.

Le travail original d'extension de PCRE aux unités de code de 16 et 32 bits a été effectué par Zoltan Herczeg et Christian Persch, respectivement. Dans les trois cas, les chaînes peuvent être interprétées soit comme un caractère par unité de code, soit comme de l'Unicode encodé en UTF, avec un support des propriétés générales des caractères Unicode. Le support Unicode est optionnel au moment de la compilation (mais est par défaut). Cependant, le traitement des chaînes comme unités de code UTF doit être activé explicitement au moment de l'exécution. La version d'Unicode utilisée peut être découverte en exécutant


pcre2test -C

Les trois bibliothèques contiennent des ensembles de fonctions identiques, avec des noms se terminant par _8, _16 ou _32, respectivement (par exemple, pcre2_compile_8()). Cependant, en définissant PCRE2_CODE_UNIT_WIDTH à 8, 16 ou 32, un programme qui utilise une seule taille d'unité de code peut être écrit en utilisant des noms génériques tels que pcre2_compile(), et la documentation est écrite en supposant que c'est le cas.

En plus de la fonction de correspondance de style Perl, PCRE2 contient une fonction alternative qui correspond aux mêmes motifs compilés d'une manière différente. Dans certaines circonstances, la fonction alternative présente des avantages. Pour une discussion des deux algorithmes de correspondance, voir la page pcre2matching.

Les détails sur les fonctionnalités des expressions régulières Perl qui sont supportées ou non par PCRE2 sont donnés dans des documents séparés. Voir les pages pcre2pattern et pcre2compat. Il y a un résumé de la syntaxe sur la page pcre2syntax.

Certaines fonctionnalités de PCRE2 peuvent être incluses, exclues ou modifiées lors de la compilation de la bibliothèque. La fonction pcre2_config() permet à un client de découvrir quelles fonctionnalités sont disponibles. Les fonctionnalités elles-mêmes sont décrites sur la page pcre2build. La documentation sur la compilation de PCRE2 pour divers systèmes d'exploitation se trouve dans les fichiers README et NON-AUTOTOOLS-BUILD de la distribution source.

Les bibliothèques contiennent un certain nombre de fonctions et de tables de données internes non documentées qui sont utilisées par plusieurs des fonctions externes exportées, mais qui ne sont pas destinées à être utilisées par des appelants externes. Leurs noms commencent tous par "_pcre2", ce qui, espérons-le, n'entraînera aucun conflit de noms. Dans certains environnements, il est possible de contrôler quels symboles externes sont exportés lors de la construction d'une bibliothèque partagée, et dans ces cas, les symboles non documentés ne sont pas exportés.

CONSIDÉRATIONS DE SÉCURITÉ

Si vous utilisez PCRE2 dans une application non-UTF qui permet aux utilisateurs de fournir des motifs arbitraires pour la compilation, vous devez être conscient d'une fonctionnalité qui permet aux utilisateurs d'activer le support UTF à partir d'un motif. Par exemple, un motif 8 bits qui commence par "(*UTF)" active le mode UTF, qui interprète les motifs et les sujets comme des chaînes d'unités de code UTF-8 au lieu de caractères individuels de 8 bits. Cela amène à vérifier la validité UTF-8 du motif et des données sur lesquelles il est mis en correspondance. Si la chaîne de données est très longue, une telle vérification peut consommer suffisamment de ressources pour faire perdre des performances à votre application.

Une façon de se prémunir contre cette possibilité est d'utiliser la fonction pcre2_pattern_info() pour vérifier les options du motif compilé pour PCRE2_UTF. Alternativement, vous pouvez définir l'option PCRE2_NEVER_UTF lors de l'appel à pcre2_compile(). Cela provoque une erreur de compilation si le motif contient une séquence de réglage UTF.

L'utilisation de propriétés Unicode pour des types de caractères tels que \d peut également être activée à partir du motif, en spécifiant "(*UCP)". Cette fonctionnalité peut être désactivée en définissant l'option PCRE2_NEVER_UCP.

Si votre application supporte l'UTF, sachez que la vérification de validité peut prendre du temps. Si la même chaîne de données doit être mise en correspondance plusieurs fois, vous pouvez utiliser l'option PCRE2_NO_UTF_CHECK pour la deuxième correspondance et les suivantes afin d'éviter d'exécuter des vérifications redondantes.

L'utilisation de la séquence d'échappement \C dans un motif UTF-8 ou UTF-16 peut entraîner des problèmes, car elle peut laisser le point de correspondance actuel au milieu d'un caractère multi-unités de code. L'option PCRE2_NEVER_BACKSLASH_C peut être utilisée par une application pour interdire l'utilisation de \C, provoquant une erreur de compilation si elle est rencontrée. Il est également possible de construire PCRE2 avec l'utilisation de \C désactivée en permanence.

Une autre façon de réduire les performances est d'exécuter un motif qui a un arbre de recherche très large sur une chaîne qui ne correspondra jamais. Les répétitions illimitées imbriquées dans un motif en sont un exemple courant. PCRE2 offre une certaine protection contre cela : voir la fonction pcre2_set_match_limit() dans la page pcre2api. Il existe une fonction similaire appelée pcre2_set_depth_limit() qui peut être utilisée pour limiter la quantité de mémoire utilisée.

DOCUMENTATION UTILISATEUR

La documentation utilisateur de PCRE2 comprend un certain nombre de sections différentes. Dans le format "man", chacune d'elles est une "man page" distincte. Au format HTML, chacune est une page distincte, liée depuis la page d'index. Au format texte brut, les descriptions des programmes pcre2grep et pcre2test se trouvent dans les fichiers appelés pcre2grep.txt et pcre2test.txt, respectivement. Les sections restantes, à l'exception de la section pcre2demo (qui est une liste de programme) et des pages courtes pour les fonctions individuelles, sont concaténées dans pcre2.txt, pour faciliter la recherche. Les sections sont les suivantes :


pcre2 ce document
pcre2-config informations de configuration de l'installation PCRE2
pcre2api détails de l'API C native de PCRE2
pcre2build compilation de PCRE2
pcre2callout détails de la fonctionnalité de rappel de motif
pcre2compat discussion de la compatibilité Perl
pcre2convert détails des fonctions de conversion de motifs
pcre2demo un programme C de démonstration qui utilise PCRE2
pcre2grep description de la commande pcre2grep (8 bits seulement)
pcre2jit discussion du support d'optimisation juste-à-temps
pcre2limits détails des limites de taille et autres
pcre2matching discussion des deux algorithmes de correspondance
pcre2partial détails de la facilité de correspondance partielle
pcre2pattern syntaxe et sémantique des motifs d'expressions
régulières supportés
pcre2perform discussion des problèmes de performance
pcre2posix l'API C compatible POSIX pour la bibliothèque 8 bits
pcre2sample discussion du programme pcre2demo
pcre2serialize détails de la sérialisation des motifs
pcre2syntax référence rapide de la syntaxe
pcre2test description de la commande pcre2test
pcre2unicode discussion du support Unicode et UTF

Dans les formats "man" et HTML, il y a également une page courte pour chaque fonction de bibliothèque C, listant ses arguments et ses résultats.
