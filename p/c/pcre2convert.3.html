NOM

PCRE2 - Expressions régulières compatibles Perl (API révisée)

FONCTIONS EXPÉRIMENTALES DE CONVERSION DE MOTIFS

Ce document décrit un ensemble de fonctions qui peuvent être utilisées pour convertir des motifs "étrangers" en expressions régulières PCRE2. Cette fonctionnalité est actuellement expérimentale et peut être modifiée dans les futures versions. Deux types de motifs, les globs et les motifs POSIX, sont pris en charge.

LE CONTEXTE DE CONVERSION

pcre2_convert_context *pcre2_convert_context_create(
  pcre2_general_context *gcontext);

pcre2_convert_context *pcre2_convert_context_copy(
  pcre2_convert_context *cvcontext);

void pcre2_convert_context_free(pcre2_convert_context *cvcontext);

int pcre2_set_glob_escape(pcre2_convert_context *cvcontext,
  uint32_t escape_char);

int pcre2_set_glob_separator(pcre2_convert_context *cvcontext,
  uint32_t separator_char);

Un contexte de conversion est utilisé pour contenir les paramètres qui affectent la manière dont la conversion des motifs fonctionne. Comme tous les contextes PCRE2, vous devez utiliser un contexte uniquement si vous souhaitez remplacer les valeurs par défaut. Il existe les fonctions habituelles de création, de copie et de libération. Si des fonctions de gestion de mémoire personnalisées sont définies dans un contexte général passé à pcre2_convert_context_create(), elles sont utilisées pour toute la gestion de mémoire au sein des fonctions de conversion.

Il n'y a que deux paramètres dans le contexte de conversion pour le moment. Les deux s'appliquent uniquement aux conversions de globs. Le caractère d'échappement est par défaut l'accent grave sous Windows, sinon la barre oblique inverse. Il peut être défini à zéro, signifiant aucun caractère d'échappement, ou à n'importe quel caractère de ponctuation avec un point de code inférieur à 256. Le caractère séparateur est par défaut la barre oblique inverse sous Windows, sinon la barre oblique. Il peut être défini à la barre oblique, la barre oblique inverse, ou au point.

Les deux fonctions de réglage retournent zéro en cas de succès, ou PCRE2_ERROR_BADDATA si leur deuxième argument est invalide.

LA FONCTION DE CONVERSION

int pcre2_pattern_convert(PCRE2_SPTR pattern, PCRE2_SIZE length,
  uint32_t options, PCRE2_UCHAR **buffer,
  PCRE2_SIZE *blength, pcre2_convert_context *cvcontext);

void pcre2_converted_pattern_free(PCRE2_UCHAR *converted_pattern);

Les deux premiers arguments de pcre2_pattern_convert() définissent le motif étranger à convertir. La longueur peut être indiquée comme PCRE2_ZERO_TERMINATED. L'argument options définit comment le motif doit être traité. Si l'entrée est en UTF, l'option PCRE2_CONVERT_UTF doit être définie. PCRE2_CONVERT_NO_UTF_CHECK peut également être définie si vous êtes sûr que l'entrée est valide. Une ou plusieurs des options de glob, ou l'une des options POSIX suivantes, doivent être définies pour spécifier le type de conversion requis :


PCRE2_CONVERT_GLOB
PCRE2_CONVERT_GLOB_NO_WILD_SEPARATOR
PCRE2_CONVERT_GLOB_NO_STARSTAR
PCRE2_CONVERT_POSIX_BASIC
PCRE2_CONVERT_POSIX_EXTENDED

Les détails des conversions sont donnés ci-dessous. Les arguments buffer et blength définissent comment la sortie est gérée :

Si buffer est NULL, la fonction retourne simplement la longueur du motif converti via blength. C'est un de moins que la longueur du tampon nécessaire, car un zéro de terminaison est toujours ajouté à la sortie.

Si buffer pointe vers un pointeur NULL, un tampon de sortie est obtenu en utilisant l'allocateur dans le contexte ou malloc() si aucun contexte n'est fourni. Un pointeur vers ce tampon est placé dans la variable vers laquelle buffer pointe. Quand il n'est plus nécessaire, le tampon de sortie doit être libéré en appelant pcre2_converted_pattern_free(). Si cette fonction est appelée avec un argument NULL, elle retourne immédiatement sans rien faire.

Si buffer pointe vers un pointeur non-NULL, blength doit être défini à la longueur réelle du tampon fourni (en unités de code).

Dans tous les cas, après une conversion réussie, la variable pointée par blength est mise à jour à la longueur réellement utilisée (en unités de code), excluant le zéro de terminaison toujours ajouté.

Si une erreur survient, la longueur (via blength) est définie à l'offset dans le motif d'entrée où l'erreur a été détectée. Seules les erreurs syntaxiques grossières sont interceptées ; de nombreuses erreurs seront transmises pour que pcre2_compile() les découvre.

Le retour de pcre2_pattern_convert() est zéro en cas de succès ou un code d'erreur PCRE2 non nul. Notez que les codes d'erreur PCRE2 peuvent être positifs ou négatifs : pcre2_compile() utilise principalement des codes positifs et pcre2_match() des codes négatifs ; pcre2_convert() utilise des codes existants des deux types. Un message d'erreur textuel peut être obtenu en appelant pcre2_get_error_message().

CONVERSION DES GLOBS

Les globs sont utilisés pour faire correspondre des noms de fichiers et, par conséquent, ont le concept d'un "séparateur de chemin", qui est par défaut la barre oblique inverse sous Windows et la barre oblique sinon. Si PCRE2_CONVERT_GLOB est défini, les jokers * et ? ne sont pas autorisés à correspondre aux séparateurs de chemin, mais la fonctionnalité double-étoile (**) (qui correspond aux séparateurs) est prise en charge.

PCRE2_CONVERT_GLOB_NO_WILD_SEPARATOR correspond aux globs avec les jokers autorisés à correspondre aux séparateurs de chemin. PCRE2_CONVERT_GLOB_NO_STARSTAR correspond aux globs avec la fonctionnalité double-étoile désactivée. Ces options peuvent être utilisées ensemble.

CONVERSION DES MOTIFS POSIX

POSIX définit deux types de motifs d'expressions régulières : basiques et étendus. Ceux-ci peuvent être traités en définissant respectivement PCRE2_CONVERT_POSIX_BASIC ou PCRE2_CONVERT_POSIX_EXTENDED.

Dans les motifs POSIX, la barre oblique inverse n'est pas spéciale dans une classe de caractères. Les parenthèses fermantes non appariées sont traitées comme littérales.

Dans les motifs basiques, ? + | {} et () doivent être échappés pour être reconnus comme métacaractères en dehors d'une classe de caractères. Si le premier caractère du motif est *, il est traité comme littéral. ^ est un métacaractère uniquement au début d'une branche.

Dans les motifs étendus, une barre oblique inverse qui n'est pas dans une classe de caractères rend toujours le caractère suivant littéral, quel qu'il soit. Il n'y a pas de rétro-références.

Note : POSIX exige que la correspondance la plus longue possible à la première position correspondante soit trouvée. Ce n'est pas ce que fait pcre2_match() ; il renvoie la première correspondance trouvée. Une application peut utiliser pcre2_dfa_match() pour trouver la correspondance la plus longue, mais cela ne prend pas en charge les rétro-références (mais les motifs étendus POSIX non plus).
