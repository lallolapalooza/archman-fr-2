PCREGREP(1) Manuel des commandes générales PCREGREP(1)

NOM

pcregrep - un grep avec des expressions régulières compatibles Perl.

SYNTAXE

pcregrep [options] [options longues] [motif] [chemin1 chemin2 ...]

DESCRIPTION

pcregrep recherche des motifs de caractères dans des fichiers, de la même manière que d'autres commandes grep, mais il utilise la bibliothèque d'expressions régulières PCRE pour prendre en charge des motifs compatibles avec les expressions régulières de Perl 5. Voir pcresyntax(3) pour un résumé rapide de la syntaxe des motifs, ou pcrepattern(3) pour une description complète de la syntaxe et de la sémantique des expressions régulières prises en charge par PCRE.

Les motifs, qu'ils soient fournis en ligne de commande ou dans un fichier séparé, sont donnés sans délimiteurs. Par exemple :


pcregrep Jeudi /etc/motd

Si vous essayez d'utiliser des délimiteurs (par exemple, en entourant un motif avec des barres obliques, comme c'est courant dans les scripts Perl), ils sont interprétés comme faisant partie du motif. Les guillemets peuvent bien sûr être utilisés pour délimiter les motifs sur la ligne de commande car ils sont interprétés par le shell, et en fait, les guillemets sont requis si un motif contient des espaces blancs ou des caractères spéciaux du shell.

Le premier argument qui suit les paramètres d'option est traité comme le motif unique à faire correspondre lorsqu'aucun des options -e ni -f n'est présent. Inversement, lorsqu'une ou plusieurs de ces options sont utilisées pour spécifier des motifs, tous les arguments sont traités comme des noms de chemins. Au moins l'une des options -e, -f ou un motif d'argument doit être fournie.

Si aucun fichier n'est spécifié, pcregrep lit l'entrée standard. L'entrée standard peut également être référencée par un nom constitué d'un seul tiret. Par exemple :


pcregrep un-motif /fichier1 - /fichier3

Par défaut, chaque ligne qui correspond à un motif est copiée dans la sortie standard, et s'il y a plus d'un fichier, le nom du fichier est affiché au début de chaque ligne, suivi de deux points. Cependant, il existe des options qui peuvent modifier le comportement de pcregrep. En particulier, l'option -M permet de rechercher des motifs qui s'étendent sur plusieurs lignes. Ce qui définit une limite de ligne est contrôlé par l'option -N (--newline).

La quantité de mémoire utilisée pour la mise en tampon des fichiers qui sont scannés est contrôlée par un paramètre qui peut être défini par l'option --buffer-size. La valeur par défaut de ce paramètre est spécifiée lorsque pcregrep est compilé, la valeur par défaut étant de 20 Ko. Un bloc de mémoire trois fois cette taille est utilisé (pour permettre la mise en tampon des lignes « avant » et « après »). Une erreur se produit si une ligne dépasse le tampon.

Les motifs ne peuvent pas dépasser 8 Ko ou BUFSIZ octets, le plus grand des deux. BUFSIZ est défini dans <stdio.h>. Lorsqu'il y a plus d'un motif (spécifié par l'utilisation de -e et/ou -f), chaque motif est appliqué à chaque ligne dans l'ordre où ils sont définis, à l'exception que tous les motifs -e sont essayés avant les motifs -f.

Par défaut, dès qu'un motif correspond à une ligne, aucun autre motif n'est considéré. Cependant, si --colour (ou --color) est utilisé pour colorer les sous-chaînes correspondantes, ou si --only-matching, --file-offsets, ou --line-offsets est utilisé pour afficher uniquement la partie de la ligne qui a correspondu (affichée littéralement ou sous forme d'offset), l'analyse reprend immédiatement après la correspondance, de sorte que d'autres correspondances sur la même ligne puissent être trouvées. S'il y a plusieurs motifs, ils sont tous essayés sur le reste de la ligne, mais les motifs qui suivent celui qui a correspondu ne sont pas essayés sur la partie antérieure de la ligne.

Ce comportement signifie que l'ordre dans lequel les motifs multiples sont spécifiés peut affecter la sortie lorsque l'une des options ci-dessus est utilisée. Ce n'est plus le même comportement que GNU grep, qui parvient maintenant à afficher les correspondances antérieures pour les motifs ultérieurs (tant qu'il n'y a pas de chevauchement).

Les motifs qui peuvent correspondre à une chaîne vide sont acceptés, mais les correspondances de chaînes vides ne sont jamais reconnues. Un exemple est le motif « (super)?(man)? », dans lequel tous les composants sont optionnels. Ce motif trouve toutes les occurrences de « super » et « man » ; la sortie diffère de la correspondance avec « super|man » lorsque seules les sous-chaînes correspondantes sont affichées.

Si la variable d'environnement LC_ALL ou LC_CTYPE est définie, pcregrep utilise la valeur pour définir une locale lors de l'appel à la bibliothèque PCRE. L'option --locale peut être utilisée pour outrepasser cela.

PRISE EN CHARGE DES FICHIERS COMPRIMÉS

Il est possible de compiler pcregrep de manière à ce qu'il utilise libz ou libbz2 pour lire les fichiers dont les noms se terminent par .gz ou .bz2, respectivement. Vous pouvez savoir si votre binaire prend en charge un ou les deux types de fichiers en l'exécutant avec l'option --help. Si le support approprié n'est pas présent, les fichiers sont traités comme du texte brut. L'entrée standard est toujours traitée ainsi.

FICHIERS BINAIRES

Par défaut, un fichier contenant un octet nul binaire dans les 1024 premiers octets est identifié comme un fichier binaire et est traité spécialement. (GNU grep identifie également les fichiers binaires de cette manière.) Voir l'option --binary-files pour un moyen de modifier la manière dont les fichiers binaires sont gérés.

OPTIONS

L'ordre dans lequel certaines options apparaissent peut affecter la sortie. Par exemple, les options -h et -l affectent toutes deux l'affichage des noms de fichiers. La dernière qui apparaît sur la ligne de commande sera celle qui prendra effet. De même, sauf indication contraire ci-dessous, si une option est donnée deux fois, le dernier réglage est utilisé. Les valeurs numériques pour les options peuvent être suivies de K ou M, pour signifier une multiplication par 1024 ou 1024*1024, respectivement.

--
Ceci termine la liste des options. C'est utile si l'élément suivant sur la ligne de commande commence par un tiret mais n'est pas une option. Cela permet de traiter les motifs et les noms de fichiers qui commencent par des tirets.
-A nombre, --after-context=nombre
Affiche nombre lignes de contexte après chaque ligne correspondante. Si des noms de fichiers et/ou des numéros de ligne sont affichés, un séparateur de tiret est utilisé à la place des deux points pour les lignes de contexte. Une ligne contenant « -- » est affichée entre chaque groupe de lignes, à moins qu'elles ne soient en fait contiguës dans le fichier d'entrée. La valeur de nombre est censée être relativement petite. Cependant, pcregrep garantit de disposer de jusqu'à 8 Ko de texte suivant disponible pour la sortie de contexte.
-a, --text
Traite les fichiers binaires comme du texte. Ceci est équivalent à --binary-files=text.
-B nombre, --before-context=nombre
Affiche nombre lignes de contexte avant chaque ligne correspondante. Si des noms de fichiers et/ou des numéros de ligne sont affichés, un séparateur de tiret est utilisé à la place des deux points pour les lignes de contexte. Une ligne contenant « -- » est affichée entre chaque groupe de lignes, à moins qu'elles ne soient en fait contiguës dans le fichier d'entrée. La valeur de nombre est censée être relativement petite. Cependant, pcregrep garantit de disposer de jusqu'à 8 Ko de texte précédent disponible pour la sortie de contexte.
--binary-files=mot
Spécifie comment les fichiers binaires doivent être traités. Si le mot est « binary » (par défaut), la recherche de motifs est effectuée sur les fichiers binaires, mais la seule sortie est « Fichier binaire <nom> correspondant » lorsqu'une correspondance réussit. Si le mot est « text », ce qui est équivalent à l'option -a ou --text, les fichiers binaires sont traités de la même manière que tout autre fichier. Dans ce cas, lorsqu'une correspondance réussit, la sortie peut être du contenu binaire illisible, ce qui peut avoir des effets désagréables si elle est envoyée à un terminal. Si le mot est « without-match », ce qui est équivalent à l'option -I, les fichiers binaires ne sont pas traités du tout ; ils sont supposés ne pas être d'intérêt.
--buffer-size=nombre
Définit le paramètre qui contrôle la quantité de mémoire utilisée pour la mise en tampon des fichiers qui sont scannés.
-C nombre, --context=nombre
Affiche numéro lignes de contexte avant et après chaque ligne correspondante. Ceci est équivalent à spécifier les options -B et -A avec la même valeur.
--colour[=when], --color[=when]
Colorie les parties de la ligne qui correspondent au motif. L'argument optionnel when peut être « always », « auto », ou « never ». « auto » est le comportement par défaut ; le coloriage est effectué uniquement si la sortie standard est un terminal. « always » effectue le coloriage indépendamment de la destination de la sortie. « never » désactive le coloriage. Les couleurs utilisées sont définies par les variables d'environnement GREP_COLOR ou PCREGREP_COLOR. Si elles ne sont pas définies, les couleurs par défaut du système sont utilisées.
-c, --count
Au lieu des lignes correspondantes, affiche un compte des lignes qui correspondent à chaque fichier. Si seulement une partie de la ligne correspond (par exemple, avec -o), ce décompte peut être supérieur au nombre total de lignes du fichier.
-d action, --directories=action
Spécifie comment traiter les répertoires. L'action peut être « read » (par défaut), « skip », ou « recurse ». « read » lit les fichiers dans les répertoires. « skip » ignore les répertoires. « recurse » lit les répertoires récursivement.
-e motif, --regexp=motif
Spécifie le motif à rechercher. Cette option peut être utilisée plusieurs fois pour spécifier plusieurs motifs. S'il n'y a pas d'argument pour cette option, elle est ignorée. Si cette option est utilisée, aucun argument suivant n'est traité comme un motif.
-f fichier, --file=fichier
Lit les motifs un par ligne à partir du fichier spécifié. Cette option peut être utilisée plusieurs fois. Si le fichier est vide, cette option est ignorée. Si cette option est utilisée, aucun argument suivant n'est traité comme un motif.
-F, --fixed-strings
Interprète le motif comme une série de chaînes fixes plutôt que comme une expression régulière. Les métacaractères d'expressions régulières sont traités littéralement.
-H
Imprime toujours le nom du fichier avant chaque ligne correspondante, même s'il n'y a qu'un seul fichier spécifié. Ceci est l'opposé de l'option -h qui supprime les noms de fichiers.
-h, --no-filename
Supprime le préfixe du nom de fichier de la sortie. Ceci est l'opposé de l'option -H.
-I
Traite les fichiers binaires comme s'ils ne contenaient pas de données correspondantes. Ceci est équivalent à --binary-files=without-match.
-i, --ignore-case
Ignore la casse dans les motifs et les données d'entrée.
--line-buffered
Sortie par ligne. Cela peut ralentir la commande s'il y a beaucoup de lignes qui correspondent.
-l, --files-with-matches
Imprime uniquement les noms des fichiers qui contiennent des lignes correspondantes. Dès qu'une correspondance est trouvée dans un fichier, le nom du fichier est imprimé et l'analyse de ce fichier est arrêtée.
-L, --files-without-match
Imprime uniquement les noms des fichiers qui ne contiennent aucune ligne correspondante. Dès qu'une correspondance est trouvée dans un fichier, l'analyse de ce fichier est arrêtée.
-m nombre, --max-count=nombre
Arrête la recherche dans chaque fichier après avoir trouvé nombre correspondances.
-M, --multiline
Permet aux motifs de correspondre à des séquences qui s'étendent sur plusieurs lignes. Par défaut, le point (« . ») ne correspond qu'à un seul caractère, et les ancres (par exemple, « ^ » et « $ ») ne correspondent qu'au début et à la fin d'une ligne entière. Avec cette option, les ancres peuvent correspondre à des positions au début ou à la fin de la chaîne, et le délimiteur de ligne est traité comme un caractère normal par le point. Ceci est l'opposé de l'option --single-line.
-N chaîne, --newline=chaîne
Spécifie la séquence de caractères qui représente un saut de ligne. La chaîne peut être « CR » (retour chariot), « LF » (saut de ligne), « CRLF » (retour chariot suivi d'un saut de ligne), ou « ANY » (n'importe lequel des trois précédents). La valeur par défaut est « ANY ». Cette option n'affecte que le comportement de l'option -M.
-o, --only-matching
Affiche uniquement la partie correspondante de la ligne, et non la ligne entière. Si une ligne contient plusieurs correspondances, chaque partie correspondante est affichée sur une nouvelle ligne.
-q, --quiet, --silent
Aucune sortie n'est produite. La valeur de sortie indique seulement si une correspondance a été trouvée (0) ou non (1). Ceci est utile pour l'utiliser dans des scripts.
-r, --recursive
Lit tous les fichiers dans les sous-répertoires de manière récursive. Ceci est l'équivalent de l'option -d recurse.
-S, --no-recursive
Ne recherche pas de manière récursive dans les sous-répertoires. Ceci est l'opposé de l'option -r.
-s, --no-messages
Supprime les messages d'erreur sur les fichiers inexistants ou illisibles.
--single-line
Traite toutes les lignes d'entrée comme s'il s'agissait d'une seule longue ligne. Ceci est l'opposé de l'option -M. Dans ce mode, le délimiteur de ligne est traité comme un caractère normal par le point (« . »).
-u, --line-buffered
Sortie par ligne. Cela peut ralentir la commande s'il y a beaucoup de lignes qui correspondent.
-v, --invert-match
Sélectionne les lignes qui ne correspondent pas au motif.
-w, --word-regexp
Force le motif à correspondre uniquement à des mots complets. Un mot est défini comme une séquence de lettres, de chiffres et de traits de soulignement.
-x, --line-regexp
Force le motif à correspondre uniquement à des lignes entières.
-Z, --null
Termine les noms de fichiers de sortie par un caractère nul au lieu d'un saut de ligne. Ceci est utile pour traiter les noms de fichiers dans des scripts qui peuvent contenir des sauts de ligne.

EXEMPLES

Pour rechercher toutes les lignes contenant le mot « ERROR » dans le fichier log.txt :


pcregrep ERROR log.txt

Pour rechercher toutes les lignes contenant « ERROR » ou « WARN » dans le fichier log.txt, en ignorant la casse :


pcregrep -i 'ERROR|WARN' log.txt

Pour rechercher les lignes commençant par « Start » dans le fichier data.txt et afficher les 5 lignes suivantes :


pcregrep -A 5 '^Start' data.txt

Pour rechercher les lignes contenant une adresse e-mail valide dans le fichier contacts.txt :


pcregrep '[_a-z0-9-]+@[_a-z0-9-]+(\.[_a-z0-9-]+)*' contacts.txt

-c, --count
Ne pas afficher les lignes individuelles des fichiers analysés ; afficher à la place le nombre de lignes qui auraient autrement été montrées. Si aucune ligne n'est sélectionnée, le nombre zéro est affiché. Si plusieurs fichiers sont en cours d'analyse, un décompte est affiché pour chacun d'eux. Lorsque -c est utilisé, les options -A, -B et -C sont ignorées.
--colour, --color
Si cette option est fournie sans aucune donnée, elle est équivalente à « --colour=auto ». Si des données sont requises, elles doivent être fournies dans le même élément de shell, séparées par un signe égal.
--colour=valeur, --color=valeur
Cette option spécifie dans quelles circonstances les parties d'une ligne qui correspondent à un motif doivent être colorées dans la sortie. Par défaut, la sortie n'est pas colorée. La valeur (qui est facultative, voir ci-dessus) peut être « never », « always », ou « auto ». Dans ce dernier cas, la coloration se produit uniquement si la sortie standard est connectée à un terminal. Plus de ressources sont utilisées lorsque la coloration est activée, car pcregrep doit rechercher toutes les correspondances possibles dans une ligne, pas seulement une, afin de les colorer toutes.

La couleur utilisée peut être spécifiée en définissant la variable d'environnement PCREGREP_COLOUR ou PCREGREP_COLOR. La valeur de cette variable doit être une chaîne de deux nombres, séparés par un point-virgule. Ils sont copiés directement dans la chaîne de contrôle pour la définition de la couleur sur un terminal, il vous incombe donc de vous assurer qu'ils sont logiques. Si aucune des variables d'environnement n'est définie, la valeur par défaut est « 1;31 », ce qui donne du rouge.

-D action, --devices=action
Si un chemin d'entrée n'est pas un fichier ordinaire ou un répertoire, « action » spécifie comment il doit être traité. Les valeurs valides sont « read » (la valeur par défaut) ou « skip » (ignorer silencieusement le chemin).
-d action, --directories=action
Si un chemin d'entrée est un répertoire, « action » spécifie comment il doit être traité. Les valeurs valides sont « read » (la valeur par défaut dans les environnements non Windows, pour la compatibilité avec grep GNU), « recurse » (équivalent à l'option -r), ou « skip » (ignorer silencieusement le chemin, la valeur par défaut dans les environnements Windows). Dans le cas « read », les répertoires sont lus comme s'ils étaient des fichiers ordinaires. Sur certains systèmes d'exploitation, l'effet de la lecture d'un répertoire de cette manière est une fin de fichier immédiate ; sur d'autres, cela peut provoquer une erreur.
-e motif, --regex=motif, --regexp=motif
Spécifie un motif à faire correspondre. Cette option peut être utilisée plusieurs fois pour spécifier plusieurs motifs. Elle peut également être utilisée pour spécifier un seul motif commençant par un trait d'union. Lorsque -e est utilisé, aucun motif argument n'est pris de la ligne de commande ; tous les arguments sont traités comme des noms de fichiers. Il n'y a aucune limite au nombre de motifs. Ils sont appliqués à chaque ligne dans l'ordre où ils sont définis jusqu'à ce qu'un corresponde.

Si -f est utilisé avec -e, les motifs de la ligne de commande sont comparés en premier, suivis des motifs du ou des fichiers, indépendamment de l'ordre dans lequel ces options sont spécifiées. Notez que l'utilisation multiple de -e n'est pas la même qu'un seul motif avec des alternatives. Par exemple, X|Y trouve le premier caractère d'une ligne qui est X ou Y, alors que si les deux motifs sont donnés séparément, avec X en premier, pcregrep trouve X s'il est présent, même s'il suit Y dans la ligne. Il trouve Y seulement s'il n'y a pas de X dans la ligne. Ceci n'est important que si vous utilisez -o ou --colo(u)r pour montrer la ou les parties de la ligne qui ont correspondu.

--exclude=motif
Les fichiers (mais pas les répertoires) dont les noms correspondent au motif sont ignorés sans être traités. Ceci s'applique à tous les fichiers, qu'ils soient listés sur la ligne de commande, obtenus à partir de --file-list, ou en analysant un répertoire. Le motif est une expression régulière PCRE, et il est comparé au composant final du nom de fichier, pas au chemin complet. Les options -F, -w et -x ne s'appliquent pas à ce motif. L'option peut être donnée un nombre quelconque de fois pour spécifier plusieurs motifs. Si un nom de fichier correspond à la fois à un motif --include et à un motif --exclude, il est exclu. Il n'y a pas de forme courte pour cette option.
--exclude-from=nom_fichier
Traite chaque ligne non vide du fichier comme données pour une option --exclude. Ce qui constitue une nouvelle ligne lors de la lecture du fichier est la valeur par défaut du système d'exploitation. L'option --newline n'a aucun effet sur cette option. Cette option peut être donnée plus d'une fois pour spécifier un nombre de fichiers à lire.
--exclude-dir=motif
Les répertoires dont les noms correspondent au motif sont ignorés sans être traités, quelle que soit la valeur de l'option --recursive. Ceci s'applique à tous les répertoires, qu'ils soient listés sur la ligne de commande, obtenus à partir de --file-list, ou en analysant un répertoire parent. Le motif est une expression régulière PCRE, et il est comparé au composant final du nom de répertoire, pas au chemin complet. Les options -F, -w et -x ne s'appliquent pas à ce motif. L'option peut être donnée un nombre quelconque de fois pour spécifier plus d'un motif. Si un répertoire correspond à la fois à --include-dir et à --exclude-dir, il est exclu. Il n'y a pas de forme courte pour cette option.
-F, --fixed-strings
Interprète chaque motif de correspondance de données comme une liste de chaînes fixes, séparées par des sauts de ligne, au lieu d'une expression régulière. Ce qui constitue un saut de ligne à cette fin est contrôlé par l'option --newline. Les options -w (correspondre comme un mot) et -x (correspondre à la ligne entière) peuvent être utilisées avec -F. Elles s'appliquent à chacune des chaînes fixes. Une ligne est sélectionnée si l'une des chaînes fixes s'y trouve (sous réserve de -w ou -x, le cas échéant). Cette option ne s'applique qu'aux motifs qui sont comparés au contenu des fichiers ; elle ne s'applique pas aux motifs spécifiés par les options --include ou --exclude.
-f nom_fichier, --file=nom_fichier
Lit les motifs à partir du fichier, un par ligne, et les compare à chaque ligne d'entrée. Ce qui constitue un saut de ligne lors de la lecture du fichier est la valeur par défaut du système d'exploitation. L'option --newline n'a aucun effet sur cette option. Les espaces blancs de fin sont supprimés de chaque ligne, et les lignes vides sont ignorées. Un fichier vide ne contient aucun motif et donc ne correspond à rien. Voir également les commentaires sur les motifs multiples par rapport à un seul motif avec alternatives dans la description de -e ci-dessus.

Si cette option est fournie plus d'une fois, tous les fichiers spécifiés sont lus. Une ligne de données est affichée si l'un des motifs y correspond. Un nom de fichier peut être donné comme « - » pour faire référence à l'entrée standard. Lorsque -f est utilisé, les motifs spécifiés sur la ligne de commande à l'aide de -e peuvent également être présents ; ils sont testés avant les motifs du fichier. Cependant, aucun autre motif n'est pris de la ligne de commande ; tous les arguments sont traités comme des noms de chemins à rechercher.

--file-list=nom_fichier
Lit une liste de fichiers et/ou de répertoires à analyser à partir du fichier donné, un par ligne. Les espaces blancs de fin sont supprimés de chaque ligne, et les lignes vides sont ignorées. Ces chemins sont traités avant ceux qui sont listés sur la ligne de commande. Le nom de fichier peut être donné comme « - » pour faire référence à l'entrée standard. Si --file et --file-list sont tous deux spécifiés comme « - », les motifs sont lus en premier. Ceci n'est utile que lorsque l'entrée standard est un terminal, à partir duquel des lignes supplémentaires (la liste des fichiers) peuvent être lues après une indication de fin de fichier. Si cette option est donnée plus d'une fois, tous les fichiers spécifiés sont lus.
--file-offsets
Au lieu d'afficher les lignes ou les parties de lignes qui correspondent, affiche chaque correspondance comme un décalage par rapport au début du fichier et une longueur, séparés par une virgule. Dans ce mode, aucun contexte n'est affiché. C'est-à-dire que les options -A, -B et -C sont ignorées. S'il y a plus d'une correspondance dans une ligne, chacune d'elles est affichée séparément. Cette option est mutuellement exclusive avec --line-offsets et --only-matching.
-H, --with-filename
Force l'inclusion du nom de fichier au début des lignes de sortie lors de l'analyse d'un seul fichier. Par défaut, le nom de fichier n'est pas affiché dans ce cas. Pour les lignes correspondantes, le nom de fichier est suivi d'un deux-points ; pour les lignes de contexte, un séparateur de trait d'union est utilisé. Si un numéro de ligne est également affiché, il suit le nom du fichier.
-h, --no-filename
Supprime les noms de fichiers de sortie lors de l'analyse de plusieurs fichiers. Par défaut, les noms de fichiers sont affichés lorsque plusieurs fichiers sont analysés. Pour les lignes correspondantes, le nom de fichier est suivi d'un deux-points ; pour les lignes de contexte, un séparateur de trait d'union est utilisé. Si un numéro de ligne est également affiché, il suit le nom du fichier. nom de fichier.
--help
Affiche un message d'aide, donnant des détails succincts sur les options de commande et la prise en charge des types de fichiers, puis quitte. Tout le reste sur la ligne de commande est ignoré.
-I
Traite les fichiers binaires comme s'ils ne correspondaient jamais. Ceci est équivalent à --binary-files=without-match.
-i, --ignore-case
Ignore les distinctions majuscules/minuscules pendant les comparaisons.
--include=motif
Si des motifs --include sont spécifiés, les seuls fichiers qui sont traités sont ceux qui correspondent à l'un des motifs (et ne correspondent pas à un motif --exclude). Cette option n'affecte pas les répertoires, mais elle s'applique à tous les fichiers, qu'ils soient listés sur la ligne de commande
, obtenu à partir de --file-list, ou en analysant un répertoire. Le modèle est une expression régulière PCRE, et il est comparé au dernier composant du nom de fichier, et non au chemin complet. Les options -F, -w et -x ne s'appliquent pas à ce modèle. L'option peut être utilisée un nombre quelconque de fois. Si un nom de fichier correspond à la fois à un modèle --include et à un modèle --exclude, il est exclu. Il n'y a pas de forme courte pour cette option.
--include-from=nomdefichier
Traiter chaque ligne non vide du fichier comme les données d'une option --include. Ce qui constitue une nouvelle ligne dans ce but est la valeur par défaut du système d'exploitation. L'option --newline n'a aucun effet sur cette option. Cette option peut être utilisée un nombre quelconque de fois ; tous les fichiers sont lus.
--include-dir=modèle
Si des modèles --include-dir sont spécifiés, les seuls répertoires traités sont ceux qui correspondent à l'un des modèles (et qui ne correspondent pas à un modèle --exclude-dir). Ceci s'applique à tous les répertoires, qu'ils soient listés sur la ligne de commande, obtenus à partir de --file-list, ou en analysant un répertoire parent. Le modèle est une expression régulière PCRE, et il est comparé au dernier composant du nom du répertoire, et non au chemin complet. Les options -F, -w et -x ne s'appliquent pas à ce modèle. L'option peut être utilisée un nombre quelconque de fois. Si un répertoire correspond à la fois à --include-dir et à --exclude-dir, il est exclu. Il n'y a pas de forme courte pour cette option.
-L, --files-without-match
Au lieu de sortir les lignes des fichiers, sortir uniquement les noms des fichiers qui ne contiennent aucune ligne qui aurait dû être sortie. Chaque nom de fichier est sorti une fois, sur une ligne séparée.
-l, --files-with-matches
Au lieu de sortir les lignes des fichiers, sortir uniquement les noms des fichiers contenant des lignes qui auraient dû être sorties. Chaque nom de fichier est sorti une fois, sur une ligne séparée. La recherche s'arrête normalement dès qu'une ligne correspondante est trouvée dans un fichier. Cependant, si l'option -c (compte) est également utilisée, la recherche continue afin d'obtenir le compte correct, et les fichiers qui ont au moins une correspondance sont listés avec leur compte. L'utilisation de cette option avec -c permet de supprimer la liste des fichiers sans correspondance.
--label=nom
Cette option fournit un nom à utiliser pour l'entrée standard lorsque les noms de fichiers sont sortis. Si non fourni, "(entrée standard)" est utilisé. Il n'y a pas de forme courte pour cette option.
--line-buffered
Lorsque cette option est donnée, l'entrée est lue et traitée ligne par ligne, et la sortie est vidée après chaque écriture. Par défaut, l'entrée est lue par gros morceaux, à moins que pcregrep ne puisse déterminer qu'il lit à partir d'un terminal (ce qui n'est actuellement possible que dans les environnements de type Unix). La sortie vers le terminal est normalement automatiquement vidée par le système d'exploitation. Cette option peut être utile lorsque l'entrée ou la sortie est connectée à un pipe et que vous ne voulez pas que pcregrep mette en mémoire tampon de grandes quantités de données. Cependant, son utilisation affectera les performances, et l'option -M (multiligne) cessera de fonctionner.
--line-offsets
Au lieu d'afficher les lignes ou des parties de lignes qui correspondent, afficher chaque correspondance sous forme de numéro de ligne, de décalage par rapport au début de la ligne, et d'une longueur. Le numéro de ligne est terminé par deux points (comme d'habitude ; voir l'option -n), et le décalage et la longueur sont séparés par une virgule. Dans ce mode, aucun contexte n'est affiché. C'est-à-dire que les options -A, -B et -C sont ignorées. S'il y a plus d'une correspondance dans une ligne, chacune d'elles est affichée séparément. Cette option est mutuellement exclusive avec --file-offsets et --only-matching.
--locale=nomdelocalisation
Cette option spécifie une locale à utiliser pour la correspondance des modèles. Elle remplace la valeur des variables d'environnement LC_ALL ou LC_CTYPE. Si aucune locale n'est spécifiée, la valeur par défaut de la bibliothèque PCRE (généralement la locale "C") est utilisée. Il n'y a pas de forme courte pour cette option.
--match-limit=nombre
Le traitement de certains modèles d'expressions régulières peut nécessiter une très grande quantité de mémoire, entraînant dans certains cas un crash du programme si la mémoire disponible n'est pas suffisante. D'autres modèles peuvent prendre beaucoup de temps pour rechercher toutes les chaînes correspondantes possibles. La fonction pcre_exec() appelée par pcregrep pour effectuer la correspondance a deux paramètres qui peuvent limiter les ressources qu'elle utilise.

L'option --match-limit fournit un moyen de limiter l'utilisation des ressources lors du traitement de modèles qui ne vont pas correspondre, mais qui ont un très grand nombre de possibilités dans leurs arbres de recherche. L'exemple classique est un modèle qui utilise des répétitions illimitées imbriquées. En interne, PCRE utilise une fonction appelée match() qu'il appelle de manière répétée (parfois récursive). La limite définie par --match-limit est imposée au nombre de fois que cette fonction est appelée pendant une correspondance, ce qui a pour effet de limiter la quantité de backtracking qui peut avoir lieu.

L'option --recursion-limit est similaire à --match-limit, mais au lieu de limiter le nombre total de fois que match() est appelée, elle limite la profondeur des appels récursifs, ce qui limite à son tour la quantité de mémoire qui peut être utilisée. La profondeur de récursion est un nombre plus petit que le nombre total d'appels, car tous les appels à match() ne sont pas récursifs. Cette limite n'est utile que si elle est définie à une valeur inférieure à --match-limit.

Il n'y a pas de formes courtes pour ces options. Les paramètres par défaut sont spécifiés lors de la compilation de la bibliothèque PCRE, avec la valeur par défaut de 10 millions.

-M, --multiline
Permettre aux modèles de correspondre à plus d'une ligne. Lorsque cette option est donnée, les modèles peuvent contenir utilement des caractères de nouvelle ligne littéraux et des occurrences internes de caractères ^ et $. La sortie pour une correspondance réussie peut comprendre plus d'une ligne, la dernière étant celle où la correspondance s'est terminée. Si la chaîne correspondante se termine par une séquence de nouvelle ligne, la sortie se termine à la fin de cette ligne.

Lorsque cette option est activée, la bibliothèque PCRE est appelée en mode "multiligne". Il y a une limite au nombre de lignes qui peuvent être mises en correspondance, imposée par la manière dont pcregrep met en mémoire tampon le fichier d'entrée lors de son analyse. Cependant, pcregrep garantit qu'au moins 8 Ko de caractères ou le reste du document (selon ce qui est le plus court) sont disponibles pour la correspondance avant, et de manière similaire, les 8 Ko de caractères précédents (ou tous les caractères précédents, s'ils sont moins de 8 Ko) sont garantis d'être disponibles pour les assertions lookbehind. Cette option ne fonctionne pas lorsque l'entrée est lue ligne par ligne (voir --line-buffered.)

-N typetenouvelleligne, --newline=typetenouvelleligne
La bibliothèque PCRE prend en charge cinq conventions différentes pour indiquer les fins de ligne. Il s'agit des séquences à un seul caractère CR (retour chariot) et LF (saut de ligne), de la séquence à deux caractères CRLF, d'une convention "anycrlf", qui reconnaît l'un des trois types précédents, et d'une convention "any", dans laquelle toute séquence de fin de ligne Unicode est supposée terminer une ligne. Les séquences Unicode sont les trois mentionnées ci-dessus, plus VT (tabulation verticale, U+000B), FF (saut de page, U+000C), NEL (nouvelle ligne, U+0085), LS (séparateur de ligne, U+2028) et PS (séparateur de paragraphe, U+2029).

Lorsque la bibliothèque PCRE est construite, une séquence de fin de ligne par défaut est spécifiée. Il s'agit normalement de la séquence standard du système d'exploitation. Sauf indication contraire par cette option, pcregrep utilise la valeur par défaut de la bibliothèque. Les valeurs possibles pour cette option sont CR, LF, CRLF, ANYCRLF ou ANY. Cela permet d'utiliser pcregrep pour analyser des fichiers provenant d'autres environnements sans avoir à modifier leurs fins de ligne. Si les données analysées ne correspondent pas à la convention définie par cette option, pcregrep peut se comporter de manière étrange. Notez que cette option ne s'applique pas aux fichiers spécifiés par les options -f, --exclude-from ou --include-from, qui sont censés utiliser la séquence de nouvelle ligne standard du système d'exploitation.

-n, --line-number
Précéder chaque ligne de sortie de son numéro de ligne dans le fichier, suivi d'un deux-points pour les lignes correspondantes ou d'un trait d'union pour les lignes de contexte. Si le nom du fichier est également sorti, il précède le numéro de ligne. Cette option est forcée si --line-offsets est utilisé.
--no-jit
Si la bibliothèque PCRE est compilée avec le support de la compilation juste-à-temps (qui accélère la correspondance), pcregrep l'utilise automatiquement, sauf si elle a été explicitement désactivée lors de la compilation. Cette option peut être utilisée pour désactiver l'utilisation du JIT à l'exécution. Elle est fournie pour les tests et pour contourner des problèmes. Elle ne devrait jamais être nécessaire en utilisation normale.
-o, --only-matching
Afficher uniquement la partie de la ligne qui correspond à un modèle au lieu de la ligne entière. Dans ce mode, aucun contexte n'est affiché. C'est-à-dire que les options -A, -B et -C sont ignorées. S'il y a plus d'une correspondance dans une ligne, chacune d'elles est affichée séparément. Si -o est combiné avec -v (inverser le sens de la correspondance pour trouver les lignes non correspondantes), aucune sortie n'est générée, mais le code de retour est correctement défini. Si la partie correspondante de la ligne est vide, rien n'est sorti à moins que le nom du fichier ou le numéro de ligne ne soient imprimés, auquel cas ils sont affichés sur une ligne autrement vide. Cette option est mutuellement exclusive avec --file-offsets et --line-offsets.
-onombre, --only-matching=nombre
Afficher uniquement la partie de la ligne qui correspond aux parenthèses de captage du numéro donné. Jusqu'à 32 parenthèses de captage sont prises en charge, et -o0 équivaut à -o sans numéro. Comme ces options peuvent être données sans argument (voir ci-dessus), si un argument est présent, il doit être donné dans le même élément de shell, par exemple, -o3 ou --only-matching=2. Les commentaires donnés pour le cas sans argument ci-dessus s'appliquent également à ce cas. Si le p capturant spécifié
les parenthèses n'existent pas dans le motif, ou n'ont pas été définies dans la correspondance, rien n'est affiché sauf si le nom du fichier ou le numéro de ligne sont imprimés.

Si cette option est donnée plusieurs fois, plusieurs sous-chaînes sont affichées, dans l'ordre où les options sont données. Par exemple, -o3 -o1 -o3 provoque l'affichage des sous-chaînes correspondant aux parenthèses capturantes 3 et 1 puis à nouveau 3. Par défaut, il n'y a pas de séparateur (mais voir l'option suivante).

--om-separator=texte
Spécifie une chaîne de séparation pour les occurrences multiples de -o. La valeur par défaut est une chaîne vide. Les chaînes de séparation ne sont jamais colorées.
-q, --quiet
Fonctionne silencieusement, c'est-à-dire, n'affiche rien sauf les messages d'erreur. Le code de sortie indique si des correspondances ont été trouvées ou non.
-r, --recursive
Si un chemin donné est un répertoire, analyse récursivement les fichiers qu'il contient, en tenant compte des paramètres --include et --exclude. Par défaut, un répertoire est lu comme un fichier normal ; sur certains systèmes d'exploitation, cela entraîne une fin de fichier immédiate. Cette option est un raccourci pour définir l'option -d sur "recurse".
--recursion-limit=nombre
Voir --match-limit ci-dessus.
-s, --no-messages
Supprime les messages d'erreur concernant les fichiers inexistants ou illisibles. Ces fichiers sont silencieusement ignorés. Cependant, le code de retour est toujours 2, même si des correspondances ont été trouvées dans d'autres fichiers.
-u, --utf-8
Fonctionne en mode UTF-8. Cette option n'est disponible que si PCRE a été compilé avec le support UTF-8. Tous les motifs (y compris ceux des options --exclude et --include) et toutes les lignes de sujet analysées doivent être des chaînes UTF-8 valides.
-V, --version
Affiche les numéros de version de pcregrep et de la bibliothèque PCRE sur la sortie standard, puis quitte. Tout le reste sur la ligne de commande est ignoré.
-v, --invert-match
Inverse le sens de la correspondance, de sorte que ce soient les lignes qui ne correspondent *pas* à l'un des motifs qui soient trouvées.
-w, --word-regex, --word-regexp
Force les motifs à ne correspondre qu'à des mots entiers. Ceci est équivalent à avoir \b au début et à la fin du motif. Cette option ne s'applique qu'aux motifs qui sont mis en correspondance avec le contenu des fichiers ; elle ne s'applique pas aux motifs spécifiés par les options --include ou --exclude.
-x, --line-regex, --line-regexp
Force les motifs à être ancrés (chacun doit commencer à correspondre au début d'une ligne) et, en plus, exige qu'ils correspondent à des lignes entières. Ceci est équivalent à avoir les caractères ^ et $ au début et à la fin de chaque branche alternative dans chaque motif. Cette option ne s'applique qu'aux motifs qui sont mis en correspondance avec le contenu des fichiers ; elle ne s'applique pas aux motifs spécifiés par les options --include ou --exclude.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement LC_ALL et LC_CTYPE sont examinées, dans cet ordre, pour une locale. La première qui est définie est utilisée. Cela peut être outrepassé par l'option --locale. Si aucune locale n'est définie, la locale par défaut de la bibliothèque PCRE (généralement la locale "C") est utilisée.

NOUVELLES LIGNES

L'option -N (--newline) permet à pcregrep d'analyser des fichiers avec des conventions de nouvelle ligne différentes de la valeur par défaut. Toutes les parties des fichiers d'entrée qui sont écrites sur la sortie standard sont copiées identiquement, avec les séquences de nouvelle ligne qu'elles ont dans l'entrée. Cependant, le réglage de cette option n'affecte pas l'interprétation des fichiers spécifiés par les options -f, --exclude-from ou --include-from, qui sont supposés utiliser la séquence de nouvelle ligne standard du système d'exploitation, ni la manière dont pcregrep écrit les messages d'information sur les flux d'erreur et de sortie standard. Pour ceux-ci, il utilise la chaîne "\n" pour indiquer les nouvelles lignes, s'appuyant sur la bibliothèque d'E/S C pour convertir cela en une séquence appropriée.

COMPATIBILITÉ DES OPTIONS

Beaucoup des formes courtes et longues des options de pcregrep sont les mêmes que dans le programme GNU grep. Toute option longue de la forme --xxx-regexp (terminologie GNU) est également disponible sous forme --xxx-regex (terminologie PCRE). Cependant, les options --file-list, --file-offsets, --include-dir, --line-offsets, --locale, --match-limit, -M, --multiline, -N, --newline, --om-separator, --recursion-limit, -u, et --utf-8 sont spécifiques à pcregrep, tout comme l'utilisation de l'option --only-matching avec un numéro de parenthèse capturante.

Bien que la plupart des options communes fonctionnent de la même manière, certaines diffèrent dans pcregrep. Par exemple, l'argument de l'option --include est un glob pour GNU grep, mais une expression régulière pour pcregrep. Si les options -c et -l sont toutes deux données, GNU grep liste uniquement les noms de fichiers, sans les comptages, mais pcregrep donne les comptages.

OPTIONS AVEC DONNÉES

Il existe quatre manières différentes de spécifier une option avec des données. Si une option courte est utilisée, les données peuvent suivre immédiatement, ou (sauf une exception) dans l'élément suivant de la ligne de commande. Par exemple :


-f/mon/fichier
-f /mon/fichier

L'exception est l'option -o, qui peut apparaître avec ou sans données. Pour cette raison, si des données sont présentes, elles doivent suivre immédiatement dans le même élément, par exemple -o3.

Si une option longue est utilisée, les données peuvent apparaître dans le même élément de ligne de commande, séparées par un signe égal, ou (sauf deux exceptions) elles peuvent apparaître dans l'élément suivant de la ligne de commande. Par exemple :


--file=/mon/fichier
--file /mon/fichier

Notez, cependant, que si vous voulez fournir un nom de fichier commençant par ~ comme donnée dans une commande shell, et que le shell développe ~ en un répertoire personnel, vous devez séparer le nom du fichier de l'option, car le shell ne traite pas ~ spécial sauf s'il est au début d'un élément.

Les exceptions à ce qui précède sont les options --colour (ou --color) et --only-matching, pour lesquelles les données sont facultatives. Si l'une de ces options a des données, elle doit être donnée dans la première forme, en utilisant un signe égal. Sinon, pcregrep supposera qu'elle n'a pas de données.

ERREURS DE CORRESPONDANCE

Il est possible de fournir une expression régulière qui prend très longtemps à ne pas correspondre à certaines lignes. De tels motifs impliquent normalement des répétitions indéfinies imbriquées, par exemple : (a+)*\d lorsqu'elle est mise en correspondance avec une ligne de a sans chiffre final. La fonction de correspondance PCRE a une limite de ressources qui la fait avorter dans ces circonstances. Si cela se produit, pcregrep affiche un message d'erreur et la ligne qui a causé le problème sur le flux d'erreur standard. S'il y a plus de 20 telles erreurs, pcregrep abandonne.

L'option --match-limit de pcregrep peut être utilisée pour définir la limite de ressources globale ; il existe une deuxième option appelée --recursion-limit qui définit une limite sur la quantité de mémoire (généralement la pile) utilisée (voir la discussion de ces options ci-dessus).

DIAGNOSTICS

Le code de sortie est 0 si des correspondances ont été trouvées, 1 si aucune correspondance n'a été trouvée, et 2 pour les erreurs de syntaxe, les lignes trop longues, les fichiers inexistants ou inaccessibles (même si des correspondances ont été trouvées dans d'autres fichiers) ou trop d'erreurs de correspondance. L'utilisation de l'option -s pour supprimer les messages d'erreur concernant les fichiers inaccessibles n'affecte pas le code de retour.

    SYNOPSIS

    pcregrep [options] [pattern [file...]]

    DESCRIPTION

    pcregrep is a command-line utility that behaves like GNU grep, but uses the Perl Compatible Regular Expressions (PCRE) library for matching. This provides a more powerful and flexible pattern matching syntax.

    The basic operation is to search for lines containing a match for a given pattern within one or more files. If no files are specified, standard input is used.

    The pattern can be a PCRE regular expression. Options can be used to control the behavior of the search, such as case insensitivity, line numbering, and output formatting.

    OPTIONS

    The following options are supported by pcregrep:

    -A, --after-context=NUM
    Print NUM lines of trailing context after matching lines.
    -B, --before-context=NUM
    Print NUM lines of leading context before matching lines.
    -C, --context=NUM
    Print NUM lines of output context. This is equivalent to using both -A and -B.
    -c, --count
    Suppress the normal output; instead print a count of matching lines for each input file.
    -d, --directories=ACTION
    Specify how to handle directories. ACTION can be read (default) or skip.
    -e, --regexp=PATTERN
    Use PATTERN as the regular expression. This option is useful when the pattern starts with a hyphen or when searching for multiple patterns.
    -F, --fixed-strings
    Interpret PATTERN as a list of fixed strings, separated by newlines, any of which is to be matched. This disables the use of regular expressions.
    -f, --file=FILE
    Obtain patterns from FILE, one per line.
    -H, --with-filename
    Print the file name for each match.
    -h, --without-filename
    Suppress the prefixing of file names on output.
    -i, --ignore-case
    Ignore case distinctions in patterns and input data.
    -L, --files-without-match
    Suppress normal output; instead print the name of each input file from which no output would normally have been printed. The scanning will stop on the first match.
    -l, --files-with-match
    Suppress normal output; instead print the name of each input file from which output would normally have been printed. The scanning will stop on the first match.
    -m, --mmap=NUM
    Limit the number of matches per file to NUM.
    -N, --regex-type=NUM
    Use PCRE regex type NUM. Type 1 is default. Other types are available depending on the PCRE library version.
    -n, --line-number
    Prefix each line of output with the 1-based line number within its input file.
    -o, --only-matching
    Show only the part of a line that matches the pattern.
    -P, --perl-regexp
    Interpret PATTERN as a Perl regular expression (this is the default).
    -Q, --quiet, --silent
    Nothing is ever printed, and the exit status is zero if an instance agrees; this is useful for using grep as a filter into test.
    -R, --recursive
    Read all files under each directory, recursively.
    -r, --recursive
    Read all files under each directory, recursively.
    -S, --separator=STRING
    Use STRING as the separator between output records when using context options.
    -U, --binary
    Treat the file(s) as binary.
    -u, --text
    Treat the file(s) as text.
    -V, --version
    Output version information and exit.
    -w, --word-regexp
    Select only those lines containing matches that form whole words.
    -x, --line-regexp
    Select only those matching lines that comprise the entire line.
    --
    Optionally, a double-dash -- may be used to separate the options and arguments from the file list. If it is used, then "--" is treated literally, and any subsequent arguments are treated as filenames, even if they begin with a hyphen.

    PCRE REGULAR EXPRESSIONS

    pcregrep uses the PCRE library for regular expression matching. PCRE supports a rich set of features inspired by Perl, including:

    • Character classes (e.g., \d for digits, \s for whitespace)
    • Quantifiers (e.g., *, +, ?, {n,m})
    • Anchors (e.g., ^ for start of line, $ for end of line)
    • Grouping and capturing (e.g., (...))
    • Alternation (e.g., a|b)
    • Lookarounds (e.g., (?=...), (?!...))
    • And many more advanced features.

    For a full description of PCRE syntax, refer to the pcre(3) man page.

    EXIT STATUS

    The exit status is 0 if any matches were found, 1 if no matches were found, and 2 if an error occurred.

    EXAMPLES

    pcregrep 'example' file.txt
    Find lines containing the string "example" in "file.txt".
    pcregrep -i 'error' log.txt
    Find lines containing "error" (case-insensitive) in "log.txt".
    pcregrep -v '^\s*#' config.conf
    Print lines in "config.conf" that do not start with optional whitespace followed by '#'.
    pcregrep -A 2 'warning' system.log
    Print lines containing "warning" and the two lines following each match in "system.log".
