pcilib(7) Les utilitaires PCI pcilib(7)

NOM

pcilib - une bibliothèque pour accéder aux périphériques PCI

DESCRIPTION

La bibliothèque PCI (également connue sous le nom de pcilib et libpci) est une bibliothèque portable pour accéder aux périphériques PCI et à leur espace de configuration.

MÉTHODES D'ACCÈS

La bibliothèque prend en charge une variété de méthodes pour accéder à l'espace de configuration sur différents systèmes d'exploitation. Par défaut, la première méthode correspondante dans cette liste est utilisée, mais vous pouvez spécifier de remplacer la décision (voir le commutateur -A de lspci).

linux-sysfs
Le système de fichiers /sys sous Linux 2.6 et versions ultérieures. L'en-tête standard de l'espace de configuration est disponible pour tous les utilisateurs, le reste uniquement pour root. Prend en charge l'espace de configuration étendu, les domaines PCI, le VPD (depuis Linux 2.6.26), les slots physiques (également depuis Linux 2.6.26) et les informations sur les pilotes noyau attachés.
linux-proc
L'interface /proc/bus/pci prise en charge par Linux 2.1 et versions ultérieures. L'en-tête standard de l'espace de configuration est disponible pour tous les utilisateurs, le reste uniquement pour root.
intel-conf1
Accès matériel direct via le mécanisme de configuration Intel 1. Disponible sur i386 et compatibles sous Linux, Solaris/x86, GNU Hurd, Windows, BeOS et Haiku. Nécessite des privilèges root.
intel-conf2
Accès matériel direct via le mécanisme de configuration Intel 2. Disponible sur i386 et compatibles sous Linux, Solaris/x86, GNU Hurd, Windows, BeOS et Haiku. Nécessite des privilèges root. Attention : Cette méthode ne peut adresser que les 16 premiers périphériques sur n'importe quel bus et elle semble très peu fiable dans de nombreux cas.
mmio-conf1
Accès matériel direct via le mécanisme de configuration Intel 1 via I/O mappé en mémoire. Principalement utilisé sur les plateformes non-i386. Nécessite des privilèges root. Attention : Cette méthode doit être correctement configurée via le paramètre mmio-conf1.addrs.
mmio-conf1-ext
Accès matériel direct via le mécanisme de configuration étendu PCIe Intel 1 via I/O mappé en mémoire. Principalement utilisé sur les plateformes non-i386. Nécessite des privilèges root. Attention : Cette méthode doit être correctement configurée via le paramètre mmio-conf1-ext.addrs.
ecam
Accès matériel direct via ECAM PCIe (Enhanced Configuration Access Mechanism). Disponible sur tout matériel conforme PCIe. Nécessite des privilèges root et l'accès à la mémoire physique (sous Linux, option CONFIG_STRICT_DEVMEM désactivée). Sur les systèmes compatibles ACPI, le mapping ECAM est lu depuis la table MCFG spécifiée par le paramètre ecam.acpimcfg. Sur les systèmes compatibles EFI, la table ACPI MCFG peut être située en mémoire physique via la table système EFI spécifiée par le paramètre ecam.efisystab. Sur les systèmes FreeBSD/NetBSD, l'adresse physique de la table ACPI MCFG peut être trouvée par kenv ou l'interface sysctl lorsque le paramètre ecam.bsd n'est pas désactivé. Sur les systèmes compatibles BIOS x86, la table ACPI MCFG peut être située en mémoire physique en scannant la mémoire BIOS x86 lorsque le paramètre ecam.x86bios n'est pas désactivé. Alternativement, les mappings ECAM peuvent être spécifiés par le paramètre ecam.addrs qui a la priorité sur la table ACPI MCFG. Cette option est requise sur les systèmes sans ACPI ainsi que sur les systèmes sans EFI ou BIOS x86.
fbsd-device
Le périphérique /dev/pci sous FreeBSD. Nécessite des privilèges root.
aix-device
Méthode d'accès utilisée sous AIX. Nécessite des privilèges root.
nbsd-libpci
Le périphérique /dev/pci0 sous NetBSD accédé via la bibliothèque locale libpci.
obsd-device
Le périphérique /dev/pci sous OpenBSD. Nécessite des privilèges root.
dump
Lire le contenu des registres de configuration à partir d'un fichier spécifié dans le paramètre dump.name. Le format correspond à la sortie de lspci -x.
darwin
Méthode d'accès utilisée sous Mac OS X / Darwin. Doit être exécuté en tant que root et le système doit avoir démarré avec debug=0x144.
win32-cfgmgr32
Liste des périphériques sous Windows utilisant le Gestionnaire de configuration Windows via la bibliothèque système cfgmgr32.dll. Cette méthode ne nécessite aucun droit ou privilège d'administrateur spécial. Le Gestionnaire de configuration fournit uniquement des informations de base sur les périphériques, les ressources attribuées et la structure de l'arbre des périphériques. Il n'y a pas d'accès à l'espace de configuration PCI, mais libpci essaie soit d'utiliser une autre méthode d'accès pour accéder à l'espace de configuration, soit de fournir une émulation virtuelle en lecture seule basée sur les informations du Gestionnaire de configuration. Une autre méthode d'accès peut être choisie par le paramètre win32.cfgmethod. Par défaut, la première qui fonctionne est sélectionnée (le cas échéant). À partir de Windows 8 (NT 6.2), il n'est pas possible de récupérer les ressources depuis une application ou une bibliothèque 32 bits sur un système 64 bits.
win32-sysdbg
Accès à l'espace de configuration PCI via l'interface NT SysDbg sous Windows. Le processus doit avoir le privilège Debug, que les Administrateurs locaux possèdent par défaut. Non disponible sur les systèmes 64 bits ni sur les systèmes 32 bits récents. Seuls les périphériques du premier domaine sont accessibles et seuls les 256 premiers octets de l'espace de configuration PCI sont accessibles via cette méthode.
win32-kldbg
Accès à l'espace de configuration PCI via le pilote de débogage local du noyau kldbgdrv.sys. Ce pilote ne fait pas partie du système Windows mais fait partie de l'outil Microsoft WinDbg. Il est nécessaire d'avoir le pilote kldbgdrv.sys installé dans le répertoire system32 ou d'avoir le binaire windbg.exe ou kd.exe dans le PATH. Le binaire windbg.exe ou kd.exe contient un pilote kldbgdrv.sys intégré que libpci peut automatiquement décompresser et enregistrer. En raison de l'utilisation du pilote intégré, il est requis que l'architecture du binaire windbg.exe ou kd.exe corresponde à l'architecture du système, et non à l'architecture de l'application libpci. Par conséquent, pour exécuter une application libpci i386 sur un système AMD64, il est requis d'avoir la version AMD64 du pilote kldbgdrv.sys dans le répertoire system32 natif ou la version AMD64 du binaire windbg.exe ou kd.exe dans le PATH. Les versions i386 de ces binaires ne fonctionneraient pas. La méthode d'accès win32-kldbg compilée pour les applications 32 bits prend en charge les systèmes d'exploitation hôtes 32 bits et 64 bits, par conséquent une application libpci i386 avec la méthode win32-kldbg peut accéder à l'espace de configuration PCI également sur un système hôte AMD64. Le pilote kldbgdrv.sys a certaines restrictions. Le processus doit avoir le privilège Debug et le système Windows doit être démarré avec l'option de débogage. L'option de débogage peut être activée en appelant (prend effet après le prochain démarrage) : bcdedit /debug on

pcilib(7) — Méthodes d'accès PCI

NOM

pcilib — Méthodes d'accès PCI

DESCRIPTION

La bibliothèque pcilib fournit une interface commune pour l'accès à la configuration PCI sur divers systèmes d'exploitation et architectures. Elle abstrait les différences entre les différentes méthodes d'accès aux données de configuration PCI, permettant ainsi aux applications comme lspci et setpci de fonctionner de manière transparente sur différentes plateformes.

La bibliothèque peut être configurée pour utiliser différentes méthodes d'accès, qui sont sélectionnées automatiquement ou spécifiées par l'utilisateur. Ces méthodes varient en fonction du système d'exploitation et du matériel.

Méthodes d'accès disponibles

Voici une liste des méthodes d'accès prises en charge par pcilib :

default
Méthode d'accès par défaut. Elle tente de trouver la meilleure méthode disponible automatiquement.
linux-sysfs
Accès via le système de fichiers sysfs sous Linux (par exemple, /sys/bus/pci). Nécessite que le noyau ait le support de sysfs activé et que les attributs PCI soient accessibles.
linux-proc
Accès via le système de fichiers /proc/bus/pci sous Linux. Cette méthode est considérée comme obsolète et est déconseillée au profit de sysfs.
bsd-ktrace
Utilisé sur certains systèmes BSD pour accéder aux informations PCI via des traces de noyau.
freebsd
Accès aux périphériques PCI sur FreeBSD via les entrées spéciales dans /dev.
netbsd
Accès aux périphériques PCI sur NetBSD via les entrées spéciales dans /dev.
openbsd
Accès aux périphériques PCI sur OpenBSD via les entrées spéciales dans /dev.
solaris
Accès aux périphériques PCI sur Solaris. Utilise les mécanismes spécifiques à Solaris pour l'introspection du matériel.
irix
Accès aux périphériques PCI sur IRIX (système d'exploitation d'SGI).
windows-cfgmgr32
Accès aux informations de configuration PCI sous Windows en utilisant l'API CfgMgr32. Cette méthode est souvent en lecture seule.
windows-ntapi
Accès plus direct au noyau Windows pour lire la configuration PCI. Peut requérir des privilèges élevés.
ddk
Utilisation des pilotes et des routines du Device Driver Kit (DDK) de Microsoft pour accéder à la configuration PCI sous Windows.
bios-mmio
Accès à la configuration PCI via les mécanismes de mappage mémoire (MMIO) exposés par le BIOS système, notamment pour l'accès à l'espace de configuration étendu (ECAM).
mem
Accès direct à la mémoire physique via un périphérique de mappage mémoire (par exemple, /dev/mem sous Linux, ou des sections de mémoire physique sous Windows). Nécessite des privilèges élevés.
dump
Lecture de la configuration PCI à partir d'un fichier de vidage (dump) préalablement créé.
aos-expansion
Méthode d'accès utilisée sur Amiga sous OS4+. L'accès se fait via Expansion.library. Elle offre un accès en lecture et écriture à l'espace de configuration.
rt-thread-smart
Le système de fichiers /proc/pci fourni par RT-Thread Smart OS. Cette méthode requiert que le support PCI (avec la fonction procfs activée) soit disponible dans le sous-système du pilote, et que le procfs basé sur DFS v2 soit monté dans un environnement avec rootfs activé. Il fournit un accès à l'espace de configuration PCI standard, avec des informations limitées disponibles.

PARAMÈTRES

La bibliothèque est contrôlée par plusieurs paramètres. Ils devraient avoir des valeurs par défaut raisonnables, mais au cas où vous voudriez faire quelque chose d'inhabituel (ou même d'étrange), vous pouvez les remplacer (voir le commutateur -O de lspci).

Paramètres des méthodes d'accès spécifiques

dump.name
Nom du fichier de vidage du bus à lire.
fbsd.path
Chemin vers le périphérique PCI FreeBSD.
nbsd.path
Chemin vers le périphérique PCI NetBSD.
obsd.path
Chemin vers le périphérique PCI OpenBSD.
proc.path
Chemin vers l'arborescence du bus dans procfs.
sysfs.path
Chemin vers l'arborescence des périphériques sysfs.
rt-thread-smart-dm.path
Chemin vers l'arborescence des périphériques dm procfs rt-thread smart.
devmem.path
Chemin vers le périphérique /dev/mem ou chemin vers la section de section physique \Device\PhysicalMemory NT ou nom de la méthode d'accès à l'adresse physique spécifique à la plateforme. Généralement, sur les systèmes POSIX, il s'agit du chemin vers le périphérique mémoire et, sur les systèmes Windows, du chemin vers la section mémoire NT. De plus, sur les systèmes Windows 32 bits, les méthodes de plateforme suivantes sont également reconnues : vxdcall, w32skrnl. Sur les systèmes DOS/DJGPP, seules les méthodes de plateforme suivantes sont reconnues : auto, devmap, physmap. La méthode devmap de DJGPP utilise les fonctions DPMI 1.0 0508H (Map Device in Memory Block) et 0509H (Map Conventional Memory in Memory Block). La méthode physmap de DJGPP utilise la fonction DPMI 0.9 0800H (Physical Address Mapping). Le paramètre auto de DJGPP choisit automatiquement l'une des méthodes mentionnées supportées par le système.
mmio-conf1.addrs
Adresses physiques des ports d'E/S mappés en mémoire pour le mécanisme de configuration Intel 1. Les adresses de ports d'E/S CF8 (adresse) et CFC (données) sont séparées par une barre oblique et plusieurs adresses pour différents domaines PCI sont séparées par des virgules. Format : 0xaddr1/0xdata1,0xaddr2/0xdata2,...
mmio-conf1-ext.addrs
Adresses physiques des ports d'E/S mappés en mémoire pour le mécanisme de configuration Intel PCIe étendu 1. Il a le même format que le paramètre mmio-conf1.addrs.
ecam.addrs
Adresses physiques des mappages ECAM PCIe. Chaque mappage doit contenir le numéro de bus PCI initial et l'adresse physique où le mappage commence. Il peut ensuite contenir la longueur du mappage, le dernier numéro de bus PCI et le numéro de domaine PCI. Lorsque le dernier numéro de bus PCI n'est pas fourni, il est calculé à partir de la longueur du mappage ou est supposé être 0xff. Lorsque la longueur du mappage est fournie, elle est calculée à partir du dernier numéro de bus PCI. Et lorsque le domaine PCI n'est pas fourni, 0x0 est supposé. Tous les nombres doivent être fournis sous forme hexadécimale (le préfixe 0x n'est pas requis). Plusieurs mappages sont séparés par des virgules. Format : [domaine:]bus_debut[-bus_fin]:addr_debut[+longueur],...
ecam.acpimcfg
Chemin vers la table ACPI MCFG. Traité par la fonction glob(3), il peut donc contenir des caractères génériques (*).
ecam.efisystab
Chemin vers la table système EFI.
ecam.bsd
Lorsque non défini à 0, utilise kenv ou sysctl BSD pour trouver la table ACPI MCFG. La valeur par défaut est 1 sur les systèmes BSD.
ecam.x86bios
Lorsque non défini à 0, analyse la mémoire du BIOS x86 pour trouver la table ACPI MCFG. La valeur par défaut est 1 sur les systèmes x86.
win32.cfgmethod
Méthode d'accès à l'espace de configuration à utiliser avec win32-cfgmgr32 sur les systèmes Windows. La valeur auto ou une chaîne vide sélectionne la première méthode d'accès qui prend en charge l'accès à l'espace de configuration sous Windows. La valeur win32-cfgmgr32 ou none construit uniquement un espace de configuration émulé en lecture seule avec les informations du Gestionnaire de configuration.

Paramètres pour la résolution d'ID via DNS

net.domain
Domaine DNS contenant la base de données des ID.
net.cache_name
Nom du fichier utilisé pour la mise en cache des ID résolus. Un préfixe ~/ est développé en répertoire personnel de l'utilisateur.

Paramètres pour la résolution d'ID via HWDB d'UDEV

hwdb.disable
Désactive l'utilisation de HWDB si défini à une valeur non nulle.

VOIR AUSSI

lspci(8), setpci(8), pci.ids(5), update-pciids(8)
