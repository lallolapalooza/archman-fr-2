SYNOPIS

#include <libtecla.h>
PathCache *new_PathCache(void);
PathCache *del_PathCache(PathCache *pc);
int pca_scan_path(PathCache *pc, const char *path);
void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                      void *data);
char *pca_lookup_file(PathCache *pc, const char *name,
                      int name_len, int literal);
const char *pca_last_error(PathCache *pc);
CPL_MATCH_FN(pca_path_completions);

DESCRIPTION

L'objet PathCache fait partie de la bibliothèqueTecla (voir la page de manuel libtecla(3)).

Les objets PathCache permettent à une application de rechercher des fichiers dans n'importe quelle liste de répertoires séparés par des deux-points, comme la variable d'environnement PATH d'exécution Unix. Les fichiers dans des répertoires absolus sont mis en cache dans un objet PathCache, tandis que les répertoires relatifs sont analysés au besoin. En utilisant un objet PathCache, vous pouvez rechercher le nom de chemin complet d'un nom de fichier simple, ou obtenir une liste des complétions possibles d'un préfixe de nom de fichier donné. Par défaut, tous les fichiers dans la liste des répertoires sont des cibles de recherche et de complétion, mais un mécanisme polyvalent est fourni pour ne sélectionner que certains types de fichiers. L'application évidente de cette fonctionnalité est de fournir la complétion par tabulation et la recherche de commandes exécutables dans le PATH Unix, ainsi une fonction de rappel optionnelle qui rejette tout sauf les fichiers exécutables est fournie.

UN EXEMPLE

Sous UNIX, l'exemple de programme suivant recherche et affiche les chemins complets de chaque nom de commande sur la ligne de commande.

  #include <stdio.h>
  #include <stdlib.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    int i;
  /*
   * Crée un cache pour les fichiers exécutables.
   */
    PathCache *pc = new_PathCache();
    if(!pc)
      exit(1);
  /*
   * Analyse le PATH de l'utilisateur à la recherche d'exécutables.
   */
    if(pca_scan_path(pc, getenv("PATH"))) {
      fprintf(stderr, "%s\n", pca_last_error(pc));
      exit(1);
    }
  /*
   * Configure pour ne signaler que les fichiers exécutables.
   */
   pca_set_check_fn(pc, cpl_check_exe, NULL);
  /*
   * Recherche et affiche le chemin complet de chacune des
   * commandes listées sur la ligne de commande.
   */
    for(i=1; i<argc; i++) {
      char *cmd = pca_lookup_file(pc, argv[i], -1, 0);
      printf("Le chemin complet de '%s' est %s\n", argv[i],
             cmd ? cmd : "inconnu");
    }
    pc = del_PathCache(pc);  /* Nettoyage */
    return 0;
  }

Voici un exemple de ce que cela fait sur mon ordinateur portable sous linux :

  $ ./exemple less more blob
  Le chemin complet de 'less' est /usr/bin/less
  Le chemin complet de 'more' est /bin/more
  Le chemin complet de 'blob' est inconnu
  $

DESCRIPTIONS DES FONCTIONS

Afin d'utiliser les fonctionnalités de ce module, vous devez d'abord allouer un objet PathCache en appelant la fonction constructeur new_PathCache().

  PathCache *new_PathCache(void)

Cette fonction crée les ressources nécessaires pour mettre en cache et rechercher des fichiers dans une liste de répertoires. Elle renvoie NULL en cas d'erreur.

POUPLEMENT DU CACHE

Une fois que vous avez créé un cache, il doit être peuplé de fichiers. Pour ce faire, appelez la fonction pca_scan_path().

  int pca_scan_path(PathCache *pc, const char *path);

Chaque fois que cette fonction est appelée, elle rejette le contenu actuel du cache, puis analyse la liste des répertoires spécifiés dans son argument path à la recherche de fichiers. L'argument path doit être une chaîne contenant une liste de répertoires séparés par des deux-points, telle que "/usr/bin:/home/mcs/bin:.". Cela peut inclure des répertoires spécifiés par des noms de chemin absolus tels que "/usr/bin", ainsi que des sous-répertoires spécifiés par des noms de chemin relatifs tels que "." ou "bin". Les fichiers dans les répertoires absolus sont immédiatement mis en cache dans l'objet PathCache spécifié, tandis que les sous-répertoires, dont les identités changent évidemment chaque fois que le répertoire de travail actuel est modifié, sont marqués pour être analysés à la volée chaque fois qu'un fichier est recherché.

En cas de succès, cette fonction renvoie 0. En cas d'erreur, elle renvoie 1, et une description de l'erreur peut être obtenue en appelant pca_last_error(pc).

RECHERCHE DE FICHIERS

Une fois le cache peuplé de fichiers, vous pouvez rechercher le nom de chemin complet d'un fichier, simplement en spécifiant son nom de fichier à pca_lookup_file().

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal);

Pour permettre de passer à cette fonction un nom de fichier qui fait en fait partie d'une chaîne plus longue, l'argument name_len peut être utilisé pour spécifier la longueur du nom de fichier au début de l'argument name[]. Si vous passez -1 pour cette longueur, la longueur de la chaîne sera déterminée avec strlen(). Si la chaîne name[] peut contenir des barres obliques inverses qui échappent aux significations spéciales des espaces et des tabulations dans le nom de fichier, donnez à l'argument literal la valeur 0. Sinon, si les barres obliques inverses doivent être traitées comme des caractères normaux, passez 1 pour la valeur de l'argument literal.

COMPLETION DE NOM DE FICHIER

La recherche des complétions potentielles d'un préfixe de nom de fichier dans le cache de noms de fichiers est réalisée en passant la fonction de rappel fournie pca_path_completions() à la fonction cpl_complete_word() (voir la page de manuel cpl_complete_word(3)).

  CPL_MATCH_FN(pca_path_completions);

Cette fonction de rappel nécessite que son argument data soit un pointeur vers un objet PcaPathConf. Les objets de configuration de ce type sont alloués en appelant new_PcaPathConf().

  PcaPathConf *new_PcaPathConf(PathCache *pc);

Cette fonction renvoie un objet initialisé avec des paramètres de configuration par défaut, qui déterminent le comportement de la fonction de rappel cpl_path_completions(). Les fonctions qui permettent de changer individuellement ces paramètres sont discutées ci-dessous.

Par défaut, la fonction de rappel pca_path_completions() recherche en arrière le début du nom de fichier en cours de complétion, à la recherche du premier espace non échappé ou du début de la ligne d'entrée. Si vous souhaitez spécifier un emplacement différent, appelez ppc_file_start() avec l'indice où commence le nom de fichier dans la ligne d'entrée. Passer start_index=-1 réactive le comportement par défaut.

  void ppc_file_start(PcaPathConf *ppc, int start_index);

Par défaut, lorsque pca_path_completions() examine un nom de fichier dans la ligne d'entrée, chaque barre oblique inverse isolée dans la ligne d'entrée est interprétée comme un caractère spécial qui supprime toute signification spéciale du caractère qui la suit, comme un espace qui doit être considéré comme faisant partie du nom de fichier plutôt que de délimiter le début du nom de fichier. Ces barres obliques inverses sont donc ignorées lors de la recherche de complétions, et ajoutées ensuite avant les espaces, les tabulations et les barres obliques inverses littérales dans la liste des complétions. Pour que les barres obliques inverses non échappées soient traitées comme des caractères normaux, appelez ppc_literal_escapes() avec une valeur non nulle dans son argument literal.

  void ppc_literal_escapes(PcaPathConf *ppc, int literal);

Lorsque vous avez terminé avec une variable PcaPathConf, vous pouvez la passer à la fonction destructeur del_PcaPathConf() pour récupérer sa mémoire.

  PcaPathConf *del_PcaPathConf(PcaPathConf *ppc);

ETRE SELECTIF

Si vous ne vous intéressez qu'à certains types de fichiers, comme, par exemple, les fichiers exécutables, ou les fichiers dont les noms se terminent par un suffixe particulier, vous pouvez faire en sorte que les fonctions de complétion et de recherche de fichiers soient sélectives quant aux noms de fichiers qu'elles retournent. Ceci est fait en enregistrant une fonction de rappel auprès de votre objet PathCache. NOM

pca_lookup_file — rechercher des fichiers dans un cache

SYNOPSIS

  #include <tecla.h>

    PathCache *
    new_PathCache(void);

    int
    pca_scan_path(PathCache *pc, const char *path,
        int flags);

    int
    pca_lookup_file(PathCache *pc, const char *name,
        char *buf, size_t bufsiz);

    int
    pca_lookup_file_partial(PathCache *pc, const char *name,
        char *buf, size_t bufsiz);

    void
    pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
        void *data);

    const char *
    pca_last_error(PathCache *pc);

    PathCache *
    del_PathCache(PathCache *pc);

DESCRIPTION

Le module pca maintient un cache des fichiers trouvés dans un ensemble de chemins, et permet de les interroger efficacement. Les chemins d'accès à rechercher sont spécifiés à l'aide de la fonction pca_scan_path, et les fichiers sont ensuite recherchés en utilisant pca_lookup_file ou pca_lookup_file_partial.

UN EXEMPLE

Voici un exemple de la façon dont vous pourriez utiliser ce module pour trouver des fichiers dans le chemin de recherche de commandes de l'utilisateur:

  #include <tecla.h>
    #include <stdlib.h>
    #include <stdio.h>

    int
    main(int argc, char **argv)
    {
        PathCache *pc;
        char buf[PATH_MAX];
        int ret;

        pc = new_PathCache();
        if (pc == NULL) {
            fprintf(stderr, "Out of memory\n");
            return 1;
        }

        /* Scan the PATH environment variable */
        if (pca_scan_path(pc, getenv("PATH"), PCA_FOLLOW_LINKS)) {
            fprintf(stderr, "Error scanning path: %s\n", pca_last_error(pc));
            del_PathCache(pc);
            return 1;
        }

        /* Look for the "ls" command */
        ret = pca_lookup_file(pc, "ls", buf, sizeof(buf));
        if (ret == 1) {
            printf("Found: %s\n", buf);
        } else if (ret == 0) {
            printf("Not found.\n");
        } else {
            fprintf(stderr, "Error looking up file: %s\n", pca_last_error(pc));
        }

        del_PathCache(pc);
        return 0;
    }

DESCRIPTIONS DE FONCTIONS

Un PathCache est un objet qui contient les informations sur les fichiers qui ont été recherchés. Vous pouvez créer un nouveau cache en appelant new_PathCache, et le détruire en appelant del_PathCache.

La fonction pca_scan_path prend un chemin d'accès (qui peut être une liste de répertoires séparés par des deux points, comme la variable d'environnement PATH) et remplit le cache avec les fichiers trouvés dans ces répertoires. L'argument flags peut être utilisé pour modifier le comportement de la fonction. Actuellement, seul le flag PCA_FOLLOW_LINKS est défini, qui indique de suivre les liens symboliques lors de la recherche des fichiers.

La fonction pca_lookup_file recherche un fichier portant le nom name dans le cache et, s'il est trouvé, copie son chemin d'accès complet dans le tampon buf d'une taille de bufsiz. La fonction renvoie 1 si le fichier est trouvé, 0 s'il n'est pas trouvé, et -1 en cas d'erreur.

La fonction pca_lookup_file_partial est similaire à pca_lookup_file, mais elle renvoie le premier nom de fichier correspondant trouvé qui commence par name.

PEUPLEMENT DU CACHE

La fonction pca_scan_path est utilisée pour remplir le cache. Elle prend un PathCache, un chemin d'accès, et un ensemble de drapeaux. Le chemin d'accès est une chaîne de caractères contenant un ou plusieurs noms de répertoires, séparés par des deux points. La fonction parcourt chaque répertoire du chemin et ajoute tous les fichiers qu'elle y trouve au cache.

Les drapeaux suivants sont disponibles:

PCA_FOLLOW_LINKS
Indique à pca_scan_path de suivre les liens symboliques lors de la recherche des fichiers. Si ce drapeau n'est pas spécifié, les liens symboliques seront ignorés.

RECHERCHE DE FICHIERS

Une fois que le cache a été rempli par pca_scan_path, vous pouvez rechercher des fichiers à l'aide des fonctions pca_lookup_file et pca_lookup_file_partial.

La fonction pca_lookup_file recherche un fichier portant le nom exact spécifié par name. Si le fichier est trouvé, son chemin d'accès complet est copié dans le tampon fourni par buf. La fonction renvoie 1 si le fichier est trouvé, 0 s'il n'est pas trouvé, et -1 en cas d'erreur.

La fonction pca_lookup_file_partial recherche le premier fichier trouvé dont le nom commence par la chaîne spécifiée par name. Si un tel fichier est trouvé, son chemin d'accès complet est copié dans buf. La fonction renvoie 1 si un fichier est trouvé, 0 s'il n'y en a pas, et -1 en cas d'erreur.

COMPLETION DE NOMS DE FICHIERS

Pour des scénarios de complétion de noms de fichiers plus complexes, vous pouvez fournir une fonction de rappel personnalisée à pca_set_check_fn. Cette fonction de rappel sera appelée pour chaque fichier trouvé dans le cache, et décidera si le fichier doit être inclus dans les résultats de la complétion.

La fonction de rappel recevra le chemin d'accès complet du fichier, ainsi que toute donnée spécifique à l'application que vous fournissez. Si la fonction de rappel renvoie 1, le nom du fichier sera signalé comme une correspondance, et s'il renvoie 0, il sera ignoré. Les fonctions de rappel appropriées et leurs prototypes doivent être déclarés avec le macro suivant. Le typedef CplCheckFn est également fourni au cas où vous souhaiteriez déclarer des pointeurs vers de telles fonctions.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);

L'enregistrement de l'une de ces fonctions implique l'appel de la fonction pca_set_check_fn. En plus de la fonction de rappel, passée via l'argument check_fn, vous pouvez passer un pointeur vers n'importe quoi via l'argument data. Ce pointeur sera passé à votre fonction de rappel, via son propre argument data, chaque fois qu'elle sera appelée, offrant ainsi un moyen de passer des données spécifiques à l'application à votre rappel.

  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

Notez que ces rappels reçoivent le chemin d'accès complet de chaque fichier correspondant, de sorte que la décision de savoir si un fichier est d'intérêt peut être basée sur n'importe quelle propriété du fichier, pas seulement son nom. À titre d'exemple, la fonction de rappel fournie cpl_check_exe examine les permissions exécutables du fichier et les permissions de ses répertoires parents, et ne renvoie 1 que si l'utilisateur a la permission d'exécuter le fichier. Cette fonction de rappel peut ainsi être utilisée pour rechercher ou compléter des noms de commandes trouvés dans les répertoires listés dans la variable d'environnement PATH de l'utilisateur. Le programme d'exemple donné précédemment dans cette page de manuel en fournit une démonstration.

Attention, si quelqu'un essaie de compléter une chaîne vide, votre rappel sera appelé une fois pour chaque fichier dans le cache, ce qui pourrait représenter des milliers de fichiers. Si votre rappel effectue des opérations longues, cela pourrait entraîner un délai inacceptable pour l'utilisateur, les rappels doivent donc être courts.

Pour améliorer les performances, chaque fois que l'un de ces rappels est appelé, le choix qu'il fait est mis en cache, et la prochaine fois que le fichier correspondant est recherché, au lieu d'appeler à nouveau le rappel, l'enregistrement mis en cache de son acceptation ou de son rejet est utilisé. Ainsi, si quelqu'un essaie de compléter une chaîne vide, et appuie sur tabulation une seconde fois alors que rien ne semble se passer, il n'y aura qu'un seul long délai, la seconde passe fonctionnant entièrement à partir des dispositions mises en cache des fichiers. Ces dispositions mises en cache sont supprimées chaque fois que pca_scan_path est appelé, et chaque fois que pca_set_check_fn est appelé avec une fonction de rappel ou des arguments de données modifiés.

GESTION DES ERREURS

Si pca_scan_path signale qu'une erreur s'est produite en renvoyant 1, vous pouvez obtenir une brève description de l'erreur en appelant pca_last_error(pc). Ceci renvoie une chaîne interne contenant un message d'erreur.

  const char *pca_last_error(PathCache *pc);

NETTOYAGE

Une fois que vous avez fini d'utiliser un objet PathCache, vous pouvez libérer ses ressources en le passant à la fonction destructeur del_PathCache(). Celle-ci prend un pointeur vers l'un de ces objets, et renvoie toujours NULL.

  PathCache *del_PathCache(PathCache *pc);

SURETÉ DES THREADS

Dans les programmes multithreads, vous devriez utiliser la version de la bibliothèque libtecla_r.a. Celle-ci utilise les fonctions réentrantes POSIX lorsque disponibles (d'où le suffixe _r), et désactive les fonctionnalités qui dépendent de fonctions système non réentrantes. Dans le cas de ce module, la seule fonctionnalité désactivée est la complétion des noms d'utilisateur dans les expressions ~username/, dans cpl_path_completions().

En utilisant la version libtecla_r.a de la bibliothèque, il est sûr d'utiliser les facilités de ce module dans plusieurs threads, à condition que chaque thread utilise un objet PathCache alloué séparément. En d'autres termes, si deux threads veulent effectuer des recherches de chemins, ils devraient chacun appeler new_PathCache() pour allouer leurs propres caches.
