PCRE2SERIALIZE(3) Manuel des fonctions de bibliothèque PCRE2SERIALIZE(3)

NOM

PCRE2 - expressions régulières compatibles Perl (API révisée)

SAUVEGARDER ET RÉUTILISER LES MOTIFS PCRE2 PRÉCOMPILÉS

int32_t pcre2_serialize_decode(pcre2_code **codes,
  int32_t number_of_codes, const uint8_t *bytes,
  pcre2_general_context *gcontext);

int32_t pcre2_serialize_encode(const pcre2_code **codes,
  int32_t number_of_codes, uint8_t **serialized_bytes,
  PCRE2_SIZE *serialized_size, pcre2_general_context *gcontext);

void pcre2_serialize_free(uint8_t *bytes);

int32_t pcre2_serialize_get_number_of_codes(const uint8_t *bytes);

Si vous exécutez une application qui utilise un grand nombre de motifs d'expressions régulières, il peut être utile de les stocker sous une forme précompilée au lieu de devoir les compiler à chaque exécution de l'application. Cependant, si vous utilisez la fonction d'optimisation juste à temps (JIT), il n'est pas possible de sauvegarder et recharger les données JIT, car elles dépendent de la position. L'hôte sur lequel les motifs sont rechargés doit exécuter la même version de PCRE2, avec la même largeur d'unités de code, et doit également avoir la même endianness, la même largeur de pointeur et le même type PCRE2_SIZE. Par exemple, les motifs compilés sur un système 32 bits utilisant la bibliothèque 16 bits de PCRE2 ne peuvent pas être rechargés sur un système 64 bits, ni ne peuvent être rechargés en utilisant la bibliothèque 8 bits.

Notez que la « sérialisation » dans PCRE2 ne convertit pas les motifs compilés en un format abstrait comme la sérialisation Java ou .NET. La sortie sérialisée est en réalité juste une vidange de code octet, c'est pourquoi elle ne peut être rechargée que dans le même environnement que celui qui l'a créée. D'où les restrictions mentionnées ci-dessus. Les applications qui ne sont pas liées statiquement à une version fixe de PCRE2 doivent être prêtes à recompiler les motifs à partir de leurs sources, afin d'être à l'abri des mises à niveau de PCRE2.

PRÉOCCUPATIONS DE SÉCURITÉ

La fonctionnalité de sauvegarde et de restauration des motifs compilés est destinée à être utilisée au sein d'applications individuelles. À ce titre, les données fournies à pcre2_serialize_decode() sont supposées être des données de confiance, et non des données provenant de sources externes arbitraires. Il n'y a que des vérifications de cohérence simples, pas une validation complète de ce qui est rechargé. Des données corrompues peuvent entraîner des résultats indéfinis. Par exemple, si le champ de longueur d'un motif dans les données sérialisées est corrompu, le code de désérialisation peut lire au-delà de la fin du flux d'octets qui lui est transmis.

SAUVEGARDER LES MOTIFS COMPILÉS

Avant que les motifs compilés puissent être sauvegardés, ils doivent être sérialisés, ce qui dans PCRE2 signifie convertir le motif en un flux d'octets. Un seul flux d'octets peut contenir un nombre quelconque de motifs compilés, mais ils doivent tous utiliser les mêmes tables de caractères. Une copie unique des tables est incluse dans le flux d'octets (sa taille est de 1088 octets). Pour plus de détails sur les tables de caractères, voir la section sur la prise en charge des locales dans la documentation pcre2api.

La fonction pcre2_serialize_encode() crée un flux d'octets sérialisé à partir d'une liste de motifs compilés. Ses deux premiers arguments spécifient la liste, étant un pointeur vers un vecteur de pointeurs vers des motifs compilés, et la longueur du vecteur. Les troisième et quatrième arguments pointent vers des variables qui sont définies pour pointer vers le flux d'octets créé et sa longueur, respectivement. Le dernier argument est un pointeur vers un contexte général, qui peut être utilisé pour spécifier des fonctions de gestion de mémoire personnalisées. Si cet argument est NULL, malloc() est utilisé pour obtenir de la mémoire pour le flux d'octets. Le résultat de la fonction est le nombre de motifs sérialisés, ou l'un des codes d'erreur négatifs suivants :


PCRE2_ERROR_BADDATA le nombre de motifs est zéro ou moins
PCRE2_ERROR_BADMAGIC incompatibilité des octets d'identification dans l'un des motifs
PCRE2_ERROR_NOMEMORY échec de l'allocation mémoire
PCRE2_ERROR_MIXEDTABLES les motifs n'utilisent pas tous les mêmes tables
PCRE2_ERROR_NULL le 1er, 3ème ou 4ème argument est NULL

PCRE2_ERROR_BADMAGIC signifie soit que le code d'un motif a été corrompu, soit qu'une position dans le vecteur ne pointe pas vers un motif compilé.

Une fois qu'un ensemble de motifs a été sérialisé, vous pouvez sauvegarder les données de manière appropriée. Voici un exemple de code qui compile deux motifs et les écrit dans un fichier. Il suppose que la variable fd fait référence à un fichier ouvert en sortie. La vérification des erreurs qui devrait être présente dans une application réelle a été omise par souci de simplicité.


int errorcode;
uint8_t *bytes;
PCRE2_SIZE erroroffset;
PCRE2_SIZE bytescount;
pcre2_code *list_of_codes[2];
list_of_codes[0] = pcre2_compile("premier motif",
PCRE2_ZERO_TERMINATED, 0, &errorcode, &erroroffset, NULL);
list_of_codes[1] = pcre2_compile("deuxième motif",
PCRE2_ZERO_TERMINATED, 0, &errorcode, &erroroffset, NULL);
errorcode = pcre2_serialize_encode(list_of_codes, 2, &bytes,
&bytescount, NULL);
errorcode = fwrite(bytes, 1, bytescount, fd);

Notez que les données sérialisées sont des données binaires qui peuvent contenir n'importe laquelle des 256 valeurs d'octets possibles. Sur les systèmes qui font une distinction entre les données binaires et non binaires, assurez-vous que le fichier est ouvert en mode sortie binaire.

La sérialisation d'un ensemble de motifs laisse les données originales intactes, elles peuvent donc toujours être utilisées pour la mise en correspondance. Leur mémoire doit finalement être libérée de la manière habituelle en appelant pcre2_code_free(). Lorsque vous avez terminé avec le flux d'octets, il doit également être libéré en appelant pcre2_serialize_free(). Si cette fonction est appelée avec un argument NULL, elle retourne immédiatement sans rien faire.

RÉUTILISER LES MOTIFS PRÉCOMPILÉS

Pour réutiliser un ensemble de motifs sauvegardés, vous devez d'abord rendre le flux d'octets sérialisé disponible en mémoire principale (par exemple, en le lisant à partir d'un fichier). La gestion de ce bloc mémoire incombe à l'application. Vous pouvez utiliser la fonction pcre2_serialize_get_number_of_codes() pour savoir combien de motifs compilés se trouvent dans les données sérialisées sans décoder réellement les motifs :


uint8_t *bytes = <données sérialisées>;
int32_t number_of_codes = pcre2_serialize_get_number_of_codes(bytes);

La fonction pcre2_serialize_decode() lit un flux d'octets et recrée les motifs compilés dans de nouveaux blocs mémoire, en définissant des pointeurs vers ceux-ci dans un vecteur. Les deux premiers arguments sont un pointeur vers un vecteur approprié et sa longueur, et le troisième argument pointe vers un flux d'octets. Le dernier argument est un pointeur vers un contexte général, qui peut être utilisé pour spécifier des fonctions de gestion de mémoire personnalisées pour les motifs décodés. Si cet argument est NULL, malloc() et free() sont utilisés. Après la désérialisation, le flux d'octets n'est plus nécessaire et peut être ignoré.


pcre2_code *list_of_codes[2];
uint8_t *bytes = <données sérialisées>;
int32_t number_of_codes =
pcre2_serialize_decode(list_of_codes, 2, bytes, NULL);

Si le vecteur n'est pas assez grand pour tous les motifs du flux d'octets, il est rempli avec ceux qui rentrent, et le reste est ignoré. Le résultat de la fonction est le nombre de motifs décodés, ou l'un des codes d'erreur négatifs suivants :


PCRE2_ERROR_BADDATA le deuxième argument est zéro ou moins
PCRE2_ERROR_BADMAGIC incompatibilité des octets d'identification dans les données
PCRE2_ERROR_BADMODE incompatibilité de la taille des unités de code ou de la version PCRE2
PCRE2_ERROR_BADSERIALIZEDDATA autre échec de vérification de santé
PCRE2_ERROR_MEMORY échec de l'allocation mémoire
PCRE2_ERROR_NULL le premier ou troisième argument est NULL

PCRE2_ERROR_BADMAGIC peut signifier que les données sont corrompues, ou qu'elles ont été compilées sur un système avec une endianness différente.

Les motifs décodés peuvent être utilisés pour la mise en correspondance comme d'habitude, et doivent être libérés en appelant pcre2_code_free(). Cependant, gardez à l'esprit qu'il existe un problème potentiel de concurrence si vous utilisez plusieurs motifs décodés à partir d'un seul flux d'octets dans une application multithread. Une copie unique des tables de caractères est utilisée par tous les motifs décodés et un compteur de références est utilisé pour organiser la libération automatique de sa mémoire lorsque le dernier motif est libéré, mais il n'y a pas de verrouillage sur ce compteur de références. Par conséquent, si vous souhaitez appeler pcre2_code_free() pour ces motifs dans différents threads, vous devez organiser votre propre verrouillage, et vous assurer que pcre2_code_free() ne peut pas être

appelées par deux threads en même temps.

Si un motif a été traité par pcre2_jit_compile() avant d'être sérialisé, les données JIT sont supprimées et ne sont donc plus disponibles après un cycle de sauvegarde/restauration. Vous pouvez cependant traiter un motif restauré avec pcre2_jit_compile() si vous le souhaitez.
