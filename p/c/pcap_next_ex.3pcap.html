PCAP_NEXT_EX(3PCAP) PCAP_NEXT_EX(3PCAP)

NOM

pcap_next_ex, pcap_next - lire le paquet suivant d'un pcap_t

SYNOPSIS

#include <pcap/pcap.h>
int pcap_next_ex(pcap_t *p, struct pcap_pkthdr **pkt_header,
    const u_char **pkt_data);
const u_char *pcap_next(pcap_t *p, struct pcap_pkthdr *h);

DESCRIPTION

pcap_next_ex() lit le paquet suivant et retourne une indication de succès/échec. Si le paquet a été lu sans problème, le pointeur pointé par l'argument pkt_header est défini pour pointer vers la structure pcap_pkthdr du paquet, et le pointeur pointé par l'argument pkt_data est défini pour pointer vers les données du paquet. La struct pcap_pkthdr et les données du paquet ne doivent pas être libérées par l'appelant, et ne sont pas garanties d'être valides après le prochain appel à pcap_next_ex(), pcap_next(), pcap_loop(3PCAP), ou pcap_dispatch(3PCAP); si le code a besoin qu'elles restent valides, il doit en faire une copie.

pcap_next() lit le paquet suivant (en appelant pcap_dispatch() avec un cnt de 1) et retourne un pointeur u_char vers les données de ce paquet. Les données du paquet ne doivent pas être libérées par l'appelant, et ne sont pas garanties d'être valides après le prochain appel à pcap_next_ex(), pcap_next(), pcap_loop(), ou pcap_dispatch(); si le code a besoin qu'elles restent valides, il doit en faire une copie. La structure pcap_pkthdr pointée par h est remplie avec les valeurs appropriées pour le paquet.

Les octets de données du paquet commencent par un en-tête de liaison de données. Le format de l'en-tête de liaison de données est indiqué par la valeur de retour de la routine pcap_datalink(3PCAP) lorsqu'elle reçoit la valeur pcap_t également passée à pcap_loop() ou pcap_dispatch(). https://www.tcpdump.org/linktypes.html liste les valeurs que pcap_datalink() peut retourner et décrit les formats de paquet qui correspondent à ces valeurs. La valeur qu'elle retourne sera valide pour tous les paquets reçus sauf si et jusqu'à ce que pcap_set_datalink(3PCAP) soit appelée; après un appel réussi à pcap_set_datalink(), tous les paquets suivants auront un en-tête de liaison de données du type spécifié par la valeur du type d'en-tête de liaison de données passée à pcap_set_datalink().

Ne PAS supposer que les paquets pour une capture ou un ``savefile`` donné auront un type d'en-tête de liaison de données quelconque, tel que DLT_EN10MB pour Ethernet. Par exemple, le périphérique "any" sous Linux aura un type d'en-tête de liaison de données de DLT_LINUX_SLL ou DLT_LINUX_SLL2 même si tous les périphériques du système au moment où le périphérique "any" est ouvert ont un autre type de liaison de données, tel que DLT_EN10MB pour Ethernet.

VALEUR DE RETOUR

pcap_next_ex() retourne 1 si le paquet a été lu sans problème, 0 si les paquets sont lus à partir d'une capture en direct et que le délai d'attente du tampon de paquet a expiré, PCAP_ERROR_BREAK si les paquets sont lus à partir d'un ``savefile'' et qu'il n'y a plus de paquets à lire dans le savefile, PCAP_ERROR_NOT_ACTIVATED si appelée sur un handle de capture qui a été créé mais non activé, ou PCAP_ERROR si une erreur s'est produite lors de la lecture du paquet. Si PCAP_ERROR est retourné, pcap_geterr(3PCAP) ou pcap_perror(3PCAP) peut être appelé avec p comme argument pour récupérer ou afficher le texte d'erreur.

pcap_next() retourne un pointeur vers les données du paquet en cas de succès, et retourne NULL si une erreur s'est produite, ou si aucun paquet n'a été lu à partir d'une capture en direct (si, par exemple, ils ont été rejetés parce qu'ils n'ont pas passé le filtre de paquet, ou si, sur les plateformes qui prennent en charge un délai d'attente de tampon de paquet qui commence avant que les paquets n'arrivent, le délai d'attente expire avant que les paquets n'arrivent, ou si le descripteur de fichier pour le périphérique de capture est en mode non bloquant et qu'aucun paquet n'était disponible à lire), ou si plus aucun paquet n'est disponible dans un ``savefile''. Malheureusement, il n'y a aucun moyen de déterminer si une erreur s'est produite ou non.
