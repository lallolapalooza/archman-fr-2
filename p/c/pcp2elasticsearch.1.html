pcp2elasticsearch(1)

PCP2ELASTICSEARCH(1) Manuel des commandes générales PCP2ELASTICSEARCH(1)

NOM

pcp2elasticsearch - Exportateur de métriques pcp vers elasticsearch

SYNTAXE

pcp2elasticsearch [-5CGHIjLmnrRvV?] [-4 action] [-8|-9 limite] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c config] [--container conteneur] [-D debug] [--daemonize] [-e dérivé] [-g URL] [-h hôte] [-i instances] [-J rang] [-K spécification] [-N prédicat] [-O origine] [-p type] [-P|-0 précision] [-q|-Q échelle-count] [-s échantillons] [-S heure_début] [-t intervalle] [-T heure_fin] [-x index] [-X id_hôte] [-y|-Y échelle-temps] spécification-métrique [...]

DESCRIPTION

pcp2elasticsearch est un outil exportateur de métriques de performance personnalisable de PCP vers Elasticsearch. Toute métrique de performance disponible, en direct ou archivée, système et/ou application, peut être sélectionnée pour l'exportation en utilisant soit des arguments de ligne de commande, soit un fichier de configuration.

pcp2elasticsearch est un proche parent de pmrep(1). Se référer à pmrep(1) pour la description de spécification-métrique acceptée sur la ligne de commande de pcp2elasticsearch. Voir pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2elasticsearch.conf. Cette page décrit les options spécifiques à pcp2elasticsearch et les différences de fichier de configuration avec pmrep.conf(5). pmrep(1) liste également quelques exemples d'utilisation dont la plupart sont applicables avec pcp2elasticsearch également.

Seules les options de ligne de commande listées sur cette page sont supportées, les autres options disponibles pour pmrep(1) ne sont pas supportées.

Les options via des valeurs d'environnement (voir pmGetOptions(3)) remplacent les valeurs par défaut intégrées correspondantes (s'il y en a). Les options du fichier de configuration remplacent les variables d'environnement correspondantes (s'il y en a). Les options de ligne de commande remplacent les options du fichier de configuration correspondantes (s'il y en a).

FICHIER DE CONFIGURATION

pcp2elasticsearch utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. Le reste des options de pmrep.conf est reconnu mais ignoré par compatibilité.

options spécifiques à pcp2elasticsearch

es_server (string)

Spécifie l'URL du serveur Elasticsearch de destination pour les métriques. L'option de ligne de commande correspondante est -g. La valeur par défaut est http://localhost:9200/.

es_auth (string)

Spécifie le nom d'utilisateur à utiliser avec les requêtes Elasticsearch. La valeur par défaut est aucune.

es_password (string)

Spécifie le mot de passe à utiliser avec les requêtes Elasticsearch. La valeur par défaut est aucune.

es_index (string)

Spécifie l'index Elasticsearch pour les noms de métriques. L'option de ligne de commande correspondante est -x. La valeur par défaut est pcp.

es_hostid (string)

Spécifie l'ID d'hôte Elasticsearch pour les mesures. L'option de ligne de commande correspondante est -X. La valeur par défaut est l'hôte source des métriques.

es_search_type (string)

Spécifie le type de recherche Elasticsearch pour les mesures. L'option de ligne de commande correspondante est -p. La valeur par défaut est pcp-metric.

OPTIONS

Les options de ligne de commande disponibles sont :

-0 précision, --precision-force=précision
Comme -P mais cette option remplacera les spécifications par m étrique.
-4 action, --names-change=action
Spécifie quelle action entreprendre lors de la réception d'un événement de changement de nom de métrique pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques quelque temps après son démarrage, et informe les outils clients en cours d'exécution comme pcp2elasticsearch. Les valeurs valides pour action sont update (rafraîchir les métriques échantillonnées), ignore (ne rien faire - comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignore-unknown
Ignore silencieusement toute métrique dont le nom ne peut être résolu. Au moins une métrique doit être trouvée pour que l'outil puisse démarrer.
-8 limite, --limit-filter=limite
Limite les résultats aux instances dont les valeurs sont supérieures/inférieures à limite. Un entier positif inclura les instances avec des valeurs égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances avec des valeurs égales ou inférieures à la limite dans le rapport. Une valeur de zéro n'effectue aucun filtrage de limite. Cette option ne remplacera pas les spécifications par métrique. Voir aussi -J et -N.
-9 limite, --limit-filter-force=limite
Comme -8 mais cette option remplacera les spécifications par m étrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives PCP (Performance Co-Pilot) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Force l'échantillon initial à être aligné sur la limite d'une unité de temps naturelle alignement. Se référer à PCPIntro(1) pour une description complète de la syntaxe pour alignement.
--archive-folio=folio
Lire les archives sources de métriques à partir du folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b échelle, --space-scale=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, et ainsi de suite. Cette option ne remplacera pas les spécifications par m étrique. Voir aussi pmParseUnitsStr(3).
-B échelle, --space-scale-force=échelle
Comme -b mais cette option remplacera les spécifications par m étrique.
-c config, --config=config
Spécifie le fichier ou répertoire de config à utiliser. Dans le cas où config est un répertoire, tous les fichiers se terminant par .conf seront inclus. La valeur par défaut est le premier trouvé parmi : ./pcp2elasticsearch.conf, $HOME/.pcp2elasticsearch.conf, $HOME/pcp/pcp2elasticsearch.conf, et $PCP_SYSCONF_DIR/pcp2elasticsearch.conf. Pour plus de détails, voir la section ci-dessus et pmrep.conf(5).
--container=conteneur
Récupérer les métriques de performance à partir du conteneur spécifié, local ou distant (voir -h).
-C, --check
Quitter avant de rapporter toute valeur, mais après avoir analysé la configuration et les métriques et imprimé
possible en-têtes.
--daemonize
Daemonise au démarrage.
-e dérivé, --derived=dérivé
Spécifiez les métriques de performance dérivées. Si dérivé commence par une barre oblique (« / ») ou par un point (« . »), il sera interprété comme un fichier de configuration de métriques dérivées PCP, sinon il sera interprété comme des expressions de métriques dérivées séparées par des virgules ou des points-virgules. Pour une description complète des métriques dérivées et des fichiers de configuration des métriques dérivées PCP, voir pmLoadDerivedConfig(3) et pmRegisterDerived(3). Alternativement, l'utilisation de la syntaxe de configuration de pmrep.conf(5) permet de définir des métriques dérivées dans le cadre des ensembles de métriques.

En cas de problèmes avec les métriques dérivées, consultez en détail les pages de manuel susmentionnées et assurez-vous que toutes les métriques requises sont disponibles, en particulier lors de l'utilisation d'archives. Utilisez -Dderive pour voir des informations de débogage supplémentaires sur l'analyse des métriques dérivées.

-g URL, --es-host=URL
URL du serveur Elasticsearch de destination des métriques URL.
-G, --no-globals
N'inclut pas les métriques globales dans le reporting (voir pmrep.conf(5)).
-h hôte, --host=hôte
Récupère les métriques de performance de pmcd(1) sur hôte, plutôt que de la machine locale par défaut.
-H, --no-header
N'imprime aucun en-tête.
-i instances, --instances=instances
Récupère et rapporte uniquement les instances de métrique instances spécifiées. Par défaut, toutes les instances, présentes et futures, sont rapportées.

Reportez-vous à pmrep(1) pour une description complète de cette option.

-I, --ignore-incompat
Ignore les métriques incompatibles. Par défaut, les métriques incompatibles (c'est-à-dire, dont le type n'est pas pris en charge ou qui ne peuvent pas être mises à l'échelle comme demandé) feront que pcp2elasticsearch se terminera avec un message d'erreur. Avec cette option, toutes les métriques incompatibles sont silencieusement omises du reporting. Cela peut être particulièrement utile lors de la demande de nœuds non feuilles de l'arbre PMNS pour le reporting.
-j, --live-filter
Effectue un filtrage d'instances en direct. Cela permet de capturer toutes les instances nommées même si les processus sont redémarrés à un moment donné (contrairement à l'absence de filtrage en direct). Effectuer un filtrage en direct sur un grand nombre d'instances entraînera une certaine surcharge interne, donc un peu de prudence de la part de l'utilisateur est conseillée. Voir aussi -n.
-J rang, --rank=rang
Limite les résultats aux instances les mieux/moins bien classées rang des métriques à valeurs d'ensemble. Un entier positif inclura les instances de plus grande valeur dans le reporting. Un entier négatif inclura les instances de plus petite valeur dans le reporting. Une valeur de zéro n'effectue aucun classement. Le classement n'implique pas le tri, voir -6. Voir aussi -8.
-K spéc, --spec-local=spéc
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spéc est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peut être utilisée.
-L, --local-PMDA
Utilise un contexte local pour collecter les métriques des PMDA DSO sur la machine locale sans PMCD. Voir aussi -K.
-m, --include-labels
Inclut les libellés de métriques PCP dans la sortie.
-n, --invert-filter
Effectue le classement avant le filtrage en direct. Par défaut, le filtrage d'instances en direct (lorsqu'il est demandé, voir -j) se produit avant le classement d'instances (lorsqu'il est demandé, voir -J). Avec cette option, la logique est inversée et le classement se produit avant le filtrage en direct.
-N prédicat, --predicate=prédicat
Spécifie une liste séparée par des virgules de métriques de référence de filtre de prédicat. Par défaut, le classement (voir -J) se produit pour chaque métrique individuellement. Avec les prédicats, le classement ne se fait que pour les métriques de prédicat spécifiées. Lors du reporting, les autres métriques partageant le même domaine d'instances (voir PCPIntro(1)) que le prédicat incluront uniquement les instances les plus/moins bien classées du prédicat correspondant. Le classement n'implique pas le tri, voir -6.

Ainsi, par exemple, en utilisant proc.memory.rss (taille de la mémoire résidente d'un processus) comme métrique de prédicat, conjointement avec proc.io.total_bytes et mem.util.used comme métriques à rapporter, seuls les processus utilisant le plus/le moins (conformément à -J) de mémoire seront inclus lors du rapport des octets totaux écrits par les processus. Étant donné que mem.util.used est une métrique à valeur unique (ne partageant donc pas le même domaine d'instances que les métriques liées aux processus), elle sera rapportée comme d'habitude.

-O origine, --origin=origine
Lors du reporting de métriques archivées, le reporting commence à origine dans la fenêtre temporelle (voir -S et -T). Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de origine.
-p type, --es-search-type=type
Type de recherche Elasticsearch type pour les mesures.
-P précision, --precision=précision
Utilise précision pour les valeurs de sortie numériques non entières. Par défaut, 3 décimales sont utilisées (le cas échéant). Cette option ne remplacera pas les spécifications possibles par métrique.
-q échelle, --count-scale=échelle
Unité/échelle pour les métriques de comptage, les valeurs possibles incluent count x 10^-1, count, count x 10, count x 10^2, et ainsi de suite de 10^-8 à 10^7. (Ces valeurs sont actuellement sensibles aux espaces.) Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-Q échelle, --count-scale-force=échelle
Comme -q, mais cette option remplacera les spécifications par métrique.
-r, --raw
Affiche les valeurs brutes des métriques, ne convertit pas les compteurs cumulatifs en taux. Cette option remplacera les spécifications possibles par métrique.
-R, --raw-prefer
Comme -r, mais cette option ne remplacera pas les spécifications par métrique.
-s échantillons, --samples=échantillons
L'argument échantillons définit le nombre d'échantillons à récupérer et à rapporter. Si échantillons est 0 ou si -s n'est pas spécifié, pcp2elasticsearch échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive). Voir aussi -T.
-S heure_début, --start=heure_début
Lors du reporting de métriques archivées, le rapport sera limité aux enregistrements enregistrés à partir de heure_début. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de heure_début.
-t intervalle, --interval=intervalle
Définit l'intervalle de reporting à autre chose que la seconde par défaut. L'argument intervalle suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes). Voir aussi l'option -T.
-T heure_fin, --finish=heure_fin
Lors du reporting de métriques archivées, le rapport sera limité aux enregistrements enregistrés avant ou à heure_fin. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de heure_fin.

Lorsqu'elle est utilisée pour définir le temps d'exécution avant que pcp2elasticsearch ne se termine, si aucun échantillon n'est donné (voir -s), le nombre d'échantillons rapportés dépend de lintervalle (voir -t). Si des échantillons sont donnés, lintervalle sera ajusté pour permettre le reporting de échantillons pendant le temps d'exécution. Si -T, -s et -t sont tous donnés, heure_fin déterminera l'heure réelle à laquelle pcp2elasticsearch s'exécutera.

-v, --omit-flat
Rapporte uniquement les métriques à valeurs d'ensemble avec instances (par exemple, disk.dev.read) et omet les métriques « plates » à valeur unique sans instances (par exemple, kernel.all.sysfork). Voir -i et -I.
-V, --version
Affiche le numéro de version et quitte.
-x index, --es-index=index
Index Elasticsearch index pour les noms de métriques.
-X hostid, --es-hostid=hostid
Identifiant d'hôte Elasticsearch hostid pour les mesures.
-y échelle, --time-scale=échelle
Unité/échelle pour les métriques temporelles, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-Y échelle, --time-scale-force=échelle
Comme -y, mais cette option remplacera les spécifications par métrique.
-?, --help

SORT ORDER

The order in which documents are written to Elasticsearch is determined by the PCP fetch and store semantics. By default, this means that metrics are sorted by hostname, then by metric name, then by instance (if applicable), and finally by value.

EXIT STATUS

A zero exit status is returned on success, or a non-zero value in case of an error.

DIAGNOSTICS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.

Display usage message and exit.

OUTPUT FORMAT

First, pcp2elasticsearch sends this type definition to Elasticsearch:


{
"mappings": {
"properties": {
"@timestamp": {
"type": "long"
},
"host-id": {
"type": "text"
}
}
}
}

The actual metrics data document is similar to this example:


{
"@host-id": "bozo",
"@timestamp": 1507637520,
"mem": {
"util": {
"used": 4525820,
"free": 3344000
}
},
"disk": {
"partitions": {
"@instances": [
{
"read": 1121,
"@id": "sda1"
},
{
"read": 77306,
"@id": "sda2"
},
{
"read": 131,
"@id": "sda3"
}
]
}
}
}

FILES

pcp2elasticsearch.conf
pcp2elasticsearch configuration file (see -c)
$PCP_SYSCONF_DIR/pmrep/*.conf
system provided default pmrep configuration files

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

Of particular note, PCP_DISCRETE_ONCE can be set to ensure that discrete metric values are reported only once, unless they change at some point.

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.
