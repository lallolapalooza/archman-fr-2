PCP-ATOPSAR(1) Manuel des commandes générales PCP-ATOPSAR(1)

NOM

pcp-atopsar - Rapport d'activité système avancé (lié à pcp-atop)

SYNTAXE

pcp [options pcp] atopsar [options atop] [-r fichier|date] [-h hôte] [-R nb] [-b [AAAAMMJJ]HH:MM[SS]] [-e [AAAAMMJJ]HH:MM[SS]]
pcp [options pcp] atopsar [options atop] intervalle [échantillons]

DESCRIPTION

Le programme pcp-atopsar peut être utilisé pour signaler des statistiques au niveau du système.

Dans la première ligne de syntaxe (sans intervalle d'échantillonnage spécifié), pcp-atopsar extrait les données d'un fichier journal brut qui a été enregistré précédemment par pmlogger(1) (ou via l'option -w du programme pcp-atop).
Vous pouvez spécifier le nom du fichier journal avec l'option -r du programme pcp-atopsar. Lorsqu'un fichier journal quotidien de pmlogger est utilisé, nommé $PCP_LOG_DIR/pmlogger/[hôte]/AAAAMMJJ (où AAAAMMJJ reflète la date), la date requise sous la forme AAAAMMJJ peut être spécifiée avec l'option -r au lieu du nom de fichier, ou le nom symbolique 'y' peut être utilisé pour le fichier journal quotidien d'hier (cela peut être répété, donc 'yyyy' indique le fichier journal d'il y a quatre jours). Si l'option -r n'est pas spécifiée du tout, le fichier journal quotidien d'aujourd'hui est utilisé par défaut.
Par défaut, le nom d'hôte de la machine locale sera utilisé lors de la résolution des archives pmlogger, cependant un hôte alternatif peut être spécifié en utilisant l'option -h.
Les heures de début et de fin du rapport peuvent être définies en utilisant les options -b et -e suivies d'un argument de temps de la forme [AAAAMMJJ]HH:MM[SS].

Dans la deuxième ligne de syntaxe, pcp-atopsar lit les compteurs d'activité réels du noyau avec l'intervalle spécifié (en secondes) et le nombre d'échantillons spécifié (facultatif). Lorsque pcp-atopsar est activé de cette manière, il envoie immédiatement la sortie pour chaque rapport demandé à la sortie standard. Si un seul type de rapport est demandé, l'en-tête est imprimé une fois et après chaque intervalle secondes, les compteurs statistiques sont affichés pour cette période. Si plusieurs rapports sont demandés, un en-tête est imprimé par échantillon suivi des compteurs statistiques pour cette période.

Lorsqu'il est appelé via la commande pcp(1), les options -h/--host, -a/--archive, -O/--origin, -s/--samples, -t/--interval, -Z/--timezone et plusieurs autres options pcp de PCPIntro(1) deviennent indirectement disponibles, voir PCPIntro(1) pour leurs descriptions.

Certains indicateurs génériques peuvent être spécifiés pour influencer le comportement du programme pcp-atopsar:

-S
Par défaut, l'horodatage au début d'une ligne est supprimé si plusieurs lignes sont affichées pour un intervalle. Avec cet indicateur, un horodatage est fourni pour chaque ligne de sortie (plus facile pour le post-traitement).
-a
Par défaut, certaines ressources comme les disques et les interfaces réseau ne sont affichées que lorsqu'elles étaient actives pendant l'intervalle. Avec cet indicateur, toutes les ressources d'un type donné sont affichées, même si elles étaient inactives pendant l'intervalle.
-x
Par défaut, pcp-atopsar n'utilise les couleurs que si la sortie est dirigée vers un terminal (fenêtre). Ces couleurs peuvent indiquer qu'un pourcentage d'occupation critique a été atteint (rouge) ou a presque été atteint (cyan) pour une ressource particulière. Voir la page de manuel de atop pour une description détaillée de cette fonctionnalité (section COLORS).
Avec l'indicateur -x, l'utilisation des couleurs est supprimée inconditionnellement.
-C
Par défaut, pcp-atopsar n'utilise les couleurs que si la sortie est dirigée vers un terminal (fenêtre). Ces couleurs peuvent indiquer qu'un pourcentage d'occupation critique a été atteint (rouge) ou a presque été atteint (cyan) pour une ressource particulière. Voir la page de manuel de atop pour une description détaillée de cette fonctionnalité (section COLORS).
Avec l'indicateur -C, les couleurs seront toujours utilisées, même si la sortie n'est pas dirigée vers un terminal.
-M
Utiliser des marqueurs à la fin d'une ligne pour indiquer qu'un pourcentage d'occupation critique a été atteint ('*') ou a presque été atteint ('+') pour des ressources particulières. Le marqueur '*' est similaire à la couleur rouge et le marqueur '+' à la couleur cyan. Voir la page de manuel de atop pour une description détaillée de ces couleurs (section COLORS).
-H
Répéter la ligne d'en-tête dans un rapport pour chaque N lignes de détail. La valeur de N est déterminée dynamiquement en cas de sortie vers un tty/fenêtre (en fonction du nombre de lignes) ; pour la sortie vers un fichier ou un pipe, cette valeur est de 23.
-R
Synthétiser cnt échantillons en un seul échantillon. Lorsque le fichier journal contient par exemple des échantillons de 10 minutes, l'utilisation de l'indicateur '-R 6' affiche un rapport avec un échantillon par heure.

PCP OPTIONS ATOPSAR

Les options longues de ligne de commande PCP supplémentaires suivantes sont également disponibles :

--align=align
Force le premier échantillon à être aligné sur la limite d'une unité de temps naturelle align. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de align.
--archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
--finish=endtime
Lors du rapport sur les métriques archivées, le rapport sera limité aux enregistrements consignés avant ou à endtime. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de endtime.
--host=host
Récupère les métriques de performance depuis pmcd(1) sur host, plutôt que depuis le localhost par défaut.
--hostzone
Utilise le fuseau horaire local de l'hôte source des métriques de performance, tel qu'identifié par les options --host ou --archive. Par défaut, utilise le fuseau horaire de l'hôte local.
--hotproc
Utilise les métriques hotproc de pmdaproc(1).
--interval=interval
Définit l'intervalle de rapport sur une valeur autre que la valeur par défaut de 1 seconde. L'argument interval suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes).
--samples=samples
L'option samples définit le nombre d'échantillons à récupérer et à rapporter.
--start=starttime
Lors du rapport sur les métriques archivées, le rapport sera limité aux enregistrements consignés à partir de starttime. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de starttime.
--timezone=timezone
Utilise timezone pour la date et l'heure. Timezone est au format de la variable d'environnement TZ tel que décrit dans environ(7).
--version
Affiche le numéro de version et quitte.

DESCRIPTION DE LA SORTIE

Selon le rapport demandé, plusieurs colonnes de valeurs de sortie sont produites. Les valeurs sont principalement présentées sous forme d'un nombre d'événements par seconde.

La sortie pour l'indicateur -c contient les colonnes suivantes par cpu :

usr%
Pourcentage de temps cpu consommé en mode utilisateur (code du programme) pour tous les processus actifs s'exécutant avec une valeur de nice de zéro (par défaut) ou une valeur de nice négative (ce qui signifie une priorité plus élevée que la normale). La consommation cpu en mode utilisateur des processus dont la valeur de nice est supérieure à zéro (priorité plus faible) est indiquée dans la colonne nice %.
nice%
Pourcentage de temps cpu consommé en mode utilisateur (c'est-à-dire code du programme) pour tous les processus s'exécutant avec une valeur de nice supérieure à zéro (ce qui signifie une priorité plus faible que la moyenne).
sys%
Pourcentage de temps cpu consommé en mode système (code du noyau) pour tous les processus actifs. Un pourcentage élevé indique généralement un grand nombre d'appels système.
irq%
Pourcentage de temps cpu consommé pour la gestion des interruptions matérielles.
softirq%
Pourcentage de temps cpu consommé pour la gestion des interruptions logicielles.
steal%
Pourcentage de temps cpu volé par d'autres machines virtuelles s'exécutant sur le même matériel.
guest%
Pourcentage de temps cpu utilisé par d'autres machines virtuelles s'exécutant sur le même matériel (chevauchement avec usr%/nice%).
wait%
Pourcentage de temps cpu inutilisé pendant qu'au moins un des processus en état d'attente attend l'achèvement des E/S disque.
idle%
Pourcentage de temps cpu inutilisé car tous les processus sont en état d'attente, mais n'attendent pas les E/S disque.

La sortie pour l'indicateur -g contient les colonnes suivantes par GPU :

busaddr
Numéro et ID de bus du GPU (séparés par '/').
gpubusy
Pourcentage d'utilisation du GPU pendant l'intervalle.
membusy
Pourcentage d'utilisation de la mémoire du GPU pendant l'intervalle, c'est-à-dire le temps consacré aux opérations de lecture et d'écriture en mémoire.
memocc
Pourcentage d'occupation de la mémoire à l'instant T.
memtot
Mémoire totale disponible.
memuse
Mémoire GPU utilisée à l'instant T.
gputype
Type de GPU.

La sortie pour l'indicateur -p contient les valeurs suivantes :

pswch/s
Nombre de changements de processus (également appelés changements de contexte) par seconde sur ce cpu. Un changement de processus se produit au moment où un fil d'exécution actif (c'est-à-dire le fil d'exécution utilisant un cpu) entre en état d'attente ou a complètement utilisé sa tranche de temps ; un autre fil d'exécution sera alors choisi pour utiliser le cpu.
devintr/s
Nombre d'interruptions matérielles traitées par seconde sur ce cpu.
clones/s
Nombre de nouveaux fils d'exécution démarrés par seconde.
loadavg1
Charge moyenne reflétant le nombre moyen de fils d'exécution dans la file d'attente d'exécution ou en attente non interruptible (généralement en attente d'E/S disque ou bande) pendant la dernière minute.
loadavg5
Charge moyenne reflétant le nombre moyen de fils d'exécution dans la file d'attente d'exécution ou en attente non interruptible (généralement en attente d'E/S disque ou bande) pendant les 5 dernières minutes.
loadavg15
Charge moyenne reflétant le nombre moyen de fils d'exécution dans la file d'attente d'exécution ou en attente non interruptible (généralement en attente d'E/S disque ou bande) pendant les 15 dernières minutes.

La sortie pour l'indicateur -P contient des informations sur les processus et les fils d'exécution :

clones/s
Le nombre de nouveaux fils d'exécution démarrés par seconde.
pexit/s
curproc
Nombre total de processus présents dans le système.
curzomb
Nombre de processus zombies présents dans le système.
trun
Nombre total de fils d'exécution présents dans le système en état 'running' (en cours d'exécution).
tslpi
Nombre total de fils d'exécution présents dans le système en état 'interruptible sleeping' (en attente interruptible).
tslpu
Nombre total de fils d'exécution présents dans le système en état 'uninterruptible sleeping' (en attente non interruptible).
tidle
Nombre total de fils d'exécution présents dans le système en état 'idle' (en attente non interruptible mais non comptabilisés dans la charge moyenne).

La sortie pour l'indicateur -m contient des informations sur l'utilisation de la mémoire et du swap :

memtotal
Taille totale utilisable de la mémoire principale.
memfree
Taille de la mémoire principale disponible à l'instant T (instantané).
buffers
Mémoire principale utilisée à l'instant T pour mettre en cache les blocs de métadonnées (instantané).
cached
Mémoire principale utilisée à l'instant T pour mettre en cache les blocs de données (instantané).
dirty
Quantité de mémoire dans le cache de pages qui doit encore être écrite sur le disque à l'instant T (instantané).
slabmem
Mémoire principale utilisée à l'instant T pour la mémoire allouée dynamiquement par le noyau (instantané).
swptotal
Taille totale de l'espace de swap à l'instant T (instantané).
swpfree
Espace de swap disponible
p espace à ce moment (instantané).

La sortie pour le drapeau -s contient des informations sur la fréquence d'échange mémoire:

pagescan/s
Nombre de pages analysées par seconde en raison de la baisse de la mémoire libre en dessous d'un seuil particulier.
swapin/s
Le nombre de pages mémoire que le système a lues depuis le périphérique d'échange par seconde.
swapout/s
Le nombre de pages mémoire que le système a écrites sur le périphérique d'échange par seconde.
oomkill
Le nombre de processus tués lors du dernier intervalle en raison d'un manque de mémoire/d'échange. La valeur -1 signifie que ce compteur n'est pas pris en charge par la version actuelle du noyau.
commitspc
L'espace mémoire virtuel validé, c'est-à-dire l'espace virtuel réservé pour toutes les allocations d'espace mémoire privé pour les processus.
commitlim
La limite maximale pour l'espace validé, qui est par défaut la taille de l'espace d'échange plus 50% de la taille de la mémoire. Le noyau vérifie uniquement si l'espace validé dépasse la limite si une gestion stricte du dépassement est configurée (vm.overcommit_memory est 2).

La sortie pour le drapeau -B contient les informations sur la pression (PSI) :

cpusome
Pourcentage moyen de pression pendant l'intervalle pour la catégorie 'CPU some'.
memsome
Pourcentage moyen de pression pendant l'intervalle pour la catégorie 'memory some'.
memfull
Pourcentage moyen de pression pendant l'intervalle pour la catégorie 'memory full'.
iosome
Pourcentage moyen de pression pendant l'intervalle pour la catégorie 'I/O some'.
iofull
Pourcentage moyen de pression pendant l'intervalle pour la catégorie 'I/O full'.

La sortie pour les drapeaux -l (LVM), -f (MD) et -d (disque dur) contient les colonnes suivantes par unité active :

disk
Nom.
busy
Pourcentage d'utilisation de l'unité (c'est-à-dire la portion de temps pendant laquelle le périphérique était occupé à traiter des requêtes).
read/s
Nombre de requêtes de lecture émises par seconde sur cette unité.
KB/read
Nombre moyen de Kbytes transférés par requête de lecture pour cette unité.
writ/s
Nombre de requêtes d'écriture (y compris les requêtes de suppression) émises par seconde sur cette unité.
KB/writ
Nombre moyen de Kbytes transférés par requête d'écriture pour cette unité.
avque
Nombre moyen de requêtes en attente dans la file d'attente pendant que l'unité est occupée.
avserv
Nombre moyen de millisecondes nécessaires pour une requête sur cette unité (recherche, latence et transfert de données).

La sortie pour le drapeau -n contient des informations sur l'activité sur les systèmes de fichiers montés NFS (client) :

mounted_device
Périphérique monté contenant le nom du serveur et le répertoire du serveur en cours de montage.
physread/s
Kilo-octets de données physiquement lus depuis le serveur NFS par les processus s'exécutant sur le client NFS.
KBwrite/s
Kilo-octets de données physiquement écrits sur le serveur NFS par les processus s'exécutant sur le client NFS.
Lorsque le système de fichiers NFS a été monté pendant l'intervalle, l'état 'M' est affiché.

La sortie pour le drapeau -j contient des informations sur l'activité du client NFS :

rpc/s
Nombre d'appels RPC par seconde émis vers le(s) serveur(s) NFS.
rpcread/s
Nombre d'appels RPC de lecture par seconde émis vers le(s) serveur(s) NFS.
rpcwrite/s
Nombre d'appels RPC d'écriture par seconde émis vers le(s) serveur(s) NFS.
retrans/s
Nombre d'appels RPC retransmis par seconde.
autrefresh/s
Nombre de rafraîchissements d'autorisation par seconde.

La sortie pour le drapeau -J contient des informations sur l'activité du serveur NFS :

rpc/s

rpcread/s

rpcwrite/s
Nombre d'appels RPC d'écriture par seconde reçus du ou des clients NFS.

Nombre de Méga-octets par seconde renvoyés pour les requêtes de lecture par les clients.
MBcw/s
Nombre de Méga-octets par seconde passés dans les requêtes d'écriture par les clients.
nettcp/s
Nombre de requêtes par seconde traitées via TCP.
netudp/s
Nombre de requêtes par seconde traitées via UDP.

interf
Nom de l'interface.

Pourcentage d'utilisation de cette interface. Si la vitesse de liaison de cette interface n'a pas pu être déterminée (par exemple, pour les interfaces virtuelles), un point d'interrogation est affiché.
ipack/s
Nombre de paquets reçus de cette interface par seconde.
opack/s
Nombre de paquets transmis vers cette interface par seconde.
iKbyte/s
Nombre de Kbytes reçus de cette interface par seconde.
oKbyte/s
Nombre de Kbytes transmis via cette interface par seconde.
imbps/s
Nombre effectif de mégabits reçus par seconde.
ombps/s
Nombre effectif de mégabits transmis par seconde.
maxmbps/s
Vitesse de liaison en nombre de mégabits par seconde. Si la vitesse de liaison n'a pas pu être déterminée (par exemple, interfaces virtuelles), la valeur 0 est affichée.
La vitesse de liaison est suivie de l'indication 'f' (full duplex) ou 'h' (half duplex).

La sortie pour le drapeau -I fournit des informations sur les défaillances qui ont été détectées pour les interfaces réseau :

interf
Nom de l'interface.
ierr/s
Nombre de paquets erronés reçus de cette interface par seconde.
oerr/s
Nombre de fois où la transmission de paquets vers cette interface a échoué par seconde.

Nombre de collisions rencontrées par seconde lors de la transmission de paquets.

La sortie pour le drapeau -w fournit des informations sur l'utilisation de la couche IPv4 (noms SNMP formels entre crochets) :

inrecv/s
Nombre de datagrammes IP reçus des interfaces par seconde, y compris ceux reçus avec erreur (ipInReceives).
outreq/s
Nombre de datagrammes IP que les protocoles de couche supérieure locaux ont fournis à IP pour des demandes de transmission par seconde (ipOutRequests).
indeliver/s
Nombre de datagrammes IP reçus qui ont été livrés avec succès aux couches protocole supérieures par seconde (ipInDelivers).
forward/s
Nombre de datagrammes IP reçus par seconde pour lesquels cette entité n'était pas leur destination IP finale, entraînant une tentative de transfert (ipForwDatagrams).
reasmok/s
Nombre de datagrammes IP réassemblés avec succès par seconde (ipReasmOKs).
fragcreat/s
Nombre de fragments de datagrammes IP générés par seconde à cette entité (ipFragCreates).

La sortie pour le drapeau -W fournit des informations sur les défaillances qui ont été détectées dans la couche IPv4 (noms SNMP formels entre crochets) :

in: dsc/s
Nombre de datagrammes IP d'entrée par seconde pour lesquels aucun problème n'a été
ere rencontrés pour empêcher leur traitement continu mais qui ont été rejetés, par exemple, par manque d'espace tampon (ipInDiscards).
en: hder/s
Nombre de datagrammes IP d'entrée par seconde rejetés en raison d'erreurs dans l'en-tête IP (ipInHdrErrors).
en: ader/s
Nombre de datagrammes IP d'entrée par seconde rejetés car l'adresse IP dans le champ de destination n'était pas valide pour être reçue par cette entité (ipInAddrErrors).

La sortie de l'indicateur -y fournit des informations sur l'utilisation générale de la couche ICMPv4 et quelques informations par type de message ICMP (noms SNMP formels entre crochets) :

intot/s
Nombre de messages ICMP (tous types) reçus par seconde à cette entité (icmpInMsgs).
outtot/s

inecho/s

inerep/s

otecho/s
Nombre de messages ICMP Echo (demande) transmis par seconde (icmpOutEchos).
oterep/s

La sortie de l'indicateur -z fournit des informations sur l'utilisation de la couche IPv6 (noms SNMP formels entre crochets) :

inrecv/s
Nombre de datagrammes IPv6 entrants reçus des interfaces par seconde, y compris ceux reçus en erreur (ipv6IfStatsInReceives).
outreq/s
Nombre de datagrammes IPv6 par seconde que les couches supérieures locales ont fournis à IP dans des requêtes de transmission (ipv6IfStatsOutRequests). Ce compteur n'inclut pas les datagrammes transférés.
inmc/s

outmc/s
Nombre de paquets multicast par seconde transmis à l'interface (ipv6IfStatsOutMcastPkts).
indeliv/s
Nombre de datagrammes IP livrés avec succès par seconde aux protocoles utilisateurs IPv6, y compris ICMP (ipv6IfStatsInDelivers).
reasmok/s
Nombre de datagrammes IPv6 réassemblés avec succès par seconde (ipv6IfStatsReasmOKs).
fragcre/s
Nombre de fragments de datagrammes IPv6 générés par seconde à cette entité (ipv6IfStatsOutFragCreates).

La sortie de l'indicateur -Z fournit des informations sur les échecs détectés dans la couche IPv6 (noms SNMP formels entre crochets) :

en: dsc/s
Nombre de datagrammes IPv6 entrants par seconde pour lesquels aucun problème n'a été rencontré pour empêcher leur traitement continu mais qui ont été rejetés, par exemple, par manque d'espace tampon (ipv6IfStatsInDiscards).
en: hder/s
Nombre de datagrammes entrants par seconde rejetés en raison d'erreurs dans l'en-tête IPv6 (ipv6IfStatsInHdrErrors).
en: ader/s
Nombre de datagrammes entrants par seconde rejetés car l'adresse IPv6 dans le champ de destination n'était pas valide pour être reçue par cette entité (ipv6IfStatsInAddrErrors).
en: unkp/s
Nombre de datagrammes à adressage local par seconde qui ont été rejetés en raison d'un protocole inconnu ou non pris en charge (ipv6IfStatsInUnknownProtos).
en: ratim/s
Nombre de situations de délai d'attente par seconde pendant que d'autres fragments IPv6 étaient attendus pour un réassemblage réussi (ipv6ReasmTimeout).
en: rfail/s
Nombre d'échecs détectés par seconde par l'algorithme de réassemblage IPv6 (ipv6IfStatsReasmFails).
out: dsc/s
Nombre de datagrammes IPv6 sortants par seconde pour lesquels aucun problème n'a été rencontré pour empêcher leur traitement continu mais qui ont été rejetés, par exemple, par manque d'espace tampon (ipv6IfStatsOutDiscards).
out: nrt/s
Nombre de datagrammes IPv6 par seconde rejetés car aucune route n'a pu être trouvée (ipv6IfStatsInNoRoutes).

La sortie de l'option -D fournit des informations sur le top-3 des processus qui effectuent le plus d'accès en lecture et écriture sur le disque :

command

Pourcentage de transferts de sockets par rapport au nombre total de transferts effectués par tous les processus. Ainsi, un pourcentage élevé n'implique pas une charge réseau élevée au niveau du système.

EXEMPLES

Pour afficher l'activité CPU d'aujourd'hui jusqu'à présent (en supposant que atop enregistre en arrière-plan) :

  pcp-atopsar

Pour afficher l'occupation mémoire du 5 juin 2018 entre 10h00 et 12h30 (en supposant que pmlogger a enregistré quotidiennement en arrière-plan sur l'hôte acme.com) :

  pcp-atopsar -m -r $PCP_LOG_DIR/pmlogger/acme.com/20180605 -b 10:00 -e 12:30

 
ou
  pcp-atopsar -m -r 20180605 -b 10:00 -e 12:30

 
ou, en supposant que nous sommes le 8 juin 2018 actuellement
  pcp-atopsar -m -r yyy -b 10:00 -e 12:30

Pour écrire un fichier journal avec atop afin d'enregistrer le comportement du système pendant 30 minutes (30 échantillons d'une minute) et produire tous les rapports disponibles par la suite :

  pcp-atop -w /tmp/atoplog 60 30
  pcp-atopsar -A -r /tmp/atoplog

Pour observer l'évolution de l'activité TCP pendant dix minutes (10 échantillons avec un intervalle de soixante secondes) :

  pcp-atopsar -t 60 10

Pour observer les lignes d'en-tête ('_' comme dernier caractère) de tous les rapports avec uniquement les lignes de détail affichant une consommation critique de ressources (marque '*' ou '+' comme dernier caractère) :

  pcp-atopsar -AM | grep '[_*+]$'

FICHIERS

/etc/atoprc
Fichier de configuration contenant les valeurs par défaut au niveau du système (principalement les options). Voir la page de manuel associée.
~/.atoprc
Fichier de configuration contenant les valeurs par défaut personnelles (principalement les options). Voir la page de manuel associée.
$PCP_LOG_DIR/pmlogger/HOST/YYYYMMDD
Fichier de données quotidien, où YYYYMMDD sont des chiffres représentant la date, et HOST est le nom d'hôte de la machine enregistrée.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

OPTIONS DE DÉBOGAGE

L'option pcp -D ou --debug active la sortie de

des diagnostics supplémentaires sur stderr pour aider au dépannage, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste séparée par des virgules d'options de débogage ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
