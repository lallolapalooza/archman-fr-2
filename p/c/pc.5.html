PC(5) Manuel des formats de fichiers PC(5)

NOM

file.pc — Format de fichier pkg-config

DESCRIPTION

Les fichiers .pc fournissent un mécanisme utile pour stocker diverses informations sur les bibliothèques et les paquets sur un système donné. Les informations stockées par les fichiers .pc comprennent les indicateurs de compilateur et d'éditeur de liens nécessaires pour utiliser une bibliothèque donnée, ainsi que toute autre métadonnée pertinente.

Ces fichiers .pc sont traités par un utilitaire appelé pkg-config, dont pkgconf est une implémentation.

SYNTAXE DU FICHIER

Le fichier .pc suit un format inspiré par RFC822. Les commentaires sont préfixés par un signe dièse, un signe hash ou un octothorpe (#), et l'affectation de variables est similaire à celle du shell POSIX. Les propriétés sont définies à l'aide de strophes de style RFC822.

VARIABLES

Les définitions de variables commencent par une chaîne alphanumérique, suivie d'un signe égal, puis de la valeur que la variable doit contenir.

Les références aux variables sont toujours écrites comme "${variable}". Il est possible d'échapper un littéral "${" en "$${".

PROPRIÉTÉS

Les propriétés sont définies à l'aide de strophes de style RFC822 qui consistent en un mot-clé, suivi d'un deux-points (:) et de la valeur à laquelle la propriété doit être définie. La substitution de variables est toujours effectuée quel que soit le type de propriété.

Il existe trois types de propriétés :

Littéral
La propriété sera définie sur le texte de la valeur.
Liste de dépendances
La propriété sera définie sur une liste de dépendances analysées à partir du texte. Les listes de dépendances sont définies par cette syntaxe ABNF : 
package-list = *WSP *( package-spec *( package-sep ) )
package-sep  = WSP / ","
package-spec = package-key [ ver-op package-version ]
ver-op       = "<" / "<=" / "=" / "!=" / ">=" / ">"
Liste de fragments
La propriété sera définie sur une liste de fragments analysés à partir du texte. Le texte d'entrée doit être dans un format approprié pour être passé à un shell POSIX sans aucune expansion de shell après que la substitution de variables ait été effectuée.

MOTS-CLÉS DE PROPRIÉTÉ

Name
Le nom affiché du paquet. (obligatoire ; littéral)
Version
La version du paquet. (obligatoire ; littéral)
Description
Une description du paquet. (obligatoire ; littéral)
URL
Une URL vers une page web pour le paquet. Elle est utilisée pour recommander où acquérir des versions plus récentes du paquet. (obligatoire ; littéral)
Cflags
Indicateurs de compilation requis. Ces indicateurs sont toujours utilisés, indépendamment du fait qu'une compilation statique soit demandée ou non. (optionnel ; liste de fragments)
Cflags.private
Indicateurs de compilation requis pour la compilation statique. (optionnel ; liste de fragments ; extension pkgconf)
Copyright
Une déclaration de copyright. (optionnel ; littéral ; extension pkgconf)
Libs
Indicateurs d'édition de liens requis pour ce paquet. Les bibliothèques dont ce paquet dépend pour l'édition de liens contre lui, qui ne sont pas décrites comme des dépendances, doivent être spécifiées ici. (optionnel ; liste de fragments)
Libs.private
Indicateurs d'édition de liens requis pour ce paquet qui ne sont nécessaires que lors de l'édition de liens statique. Les bibliothèques dont ce paquet dépend pour l'édition de liens statique contre lui, qui ne sont pas décrites comme des dépendances, doivent être spécifiées ici. (optionnel ; liste de fragments)
License
L'étiquette de licence SPDX affirmée qui doit être appliquée au paquet donné. (optionnel ; littéral ; extension pkgconf)
Maintainer
Le contact privilégié pour le mainteneur. Il doit être sous la forme d'un nom suivi d'une adresse e-mail ou d'un site web. (optionnel ; littéral ; extension pkgconf)
Requires
Les dépendances requises qui doivent être satisfaites pour que le paquet soit utilisable. Toutes les dépendances doivent être satisfaites ou l'implémentation pkg-config ne doit pas utiliser le paquet. (optionnel ; liste de dépendances)
Requires.private
Les dépendances requises qui doivent être satisfaites pour que le paquet soit utilisable pour l'inclusion d'en-têtes et l'édition de liens statique. Toutes les dépendances doivent être satisfaites ou l'implémentation pkg-config ne doit pas utiliser le paquet pour l'inclusion d'en-têtes et l'édition de liens statique. (optionnel ; liste de dépendances)
Conflicts
Les dépendances qui ne doivent pas être satisfaites pour que le paquet soit utilisable. Si un paquet dans la solution de dépendance proposée correspond à une dépendance dans la liste Conflicts, le paquet considéré n'est pas utilisable. (optionnel ; liste de dépendances)
Provides
Les dépendances qui peuvent être fournies par un paquet alternatif. Si un paquet ne peut être trouvé, l'ensemble des paquets est scanné à la recherche de fournisseurs capables de correspondre à la dépendance demandée. (optionnel ; liste de dépendances ; extension pkgconf)

EXTENSIONS

Les fonctionnalités marquées comme extension pkgconf ne sont garanties de fonctionner qu'avec l'implémentation pkgconf de pkg-config. D'autres implémentations peuvent ou non supporter ces extensions.

Par conséquent, il est suggéré que les fichiers .pc qui dépendent absolument de ces extensions déclarent une exigence sur le virtuel pkgconf.

EXEMPLES

Un exemple de fichier .pc :

# Ceci est un commentaire
prefix=/home/kaniini/pkg   # ceci définit une variable
exec_prefix=${prefix}      # définition d'une autre variable avec substitution
libdir=${exec_prefix}/lib
includedir=${prefix}/include

Name: libfoo                                  # nom lisible par l'homme
Description: une bibliothèque exemple appelée libfoo # description lisible par l'homme
Copyright: Copyright (c) 2022 auteurs du projet pkgconf
License: Apache-2.0
Maintainer: le projet pkgconf <http://www.pkgconf.org>
Version: 1.0
URL: http://www.pkgconf.org
Requires: libbar > 2.0.0
Conflicts: libbaz <= 3.0.0
Libs: -L${libdir} -lfoo
Libs.private: -lm
Cflags: -I${includedir}/libfoo
