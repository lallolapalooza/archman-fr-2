PCP2INFLUXDB(1) Manuel des commandes générales PCP2INFLUXDB(1)

NOM

pcp2influxdb - Exportateur de métriques pcp vers influxdb

SYNTAXE

pcp2influxdb [-CGHIjLnrRvV?] [-4 action] [-8|-9 limite] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c config] [--container conteneur] [-D débogage] [--daemonize] [-e dérivé] [-E motdepasse] [-g serveur] [-h hôte] [-i instances] [-J rang] [-K spécification] [-N prédicat] [-O origine] [-P|-0 précision] [-q|-Q échelle-compte] [-s échantillons] [-S heuredebut] [-t intervalle] [-T heurefin] [-U nomutilisateur] [-x base-de-données] [-X tags] [-y|-Y échelle-temps] spécification-métrique [...]

DESCRIPTION

pcp2influxdb est un outil personnalisable d'exportation de métriques de performance de PCP vers InfluxDB. Toute métrique de performance disponible, en direct ou archivée, système et/ou application, peut être sélectionnée pour l'exportation en utilisant soit des arguments en ligne de commande, soit un fichier de configuration.

pcp2influxdb est un parent proche de pmrep(1). Reportez-vous à pmrep(1) pour la description de spécification-métrique acceptée sur la ligne de commande de pcp2influxdb. Voir pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2influxdb.conf. Cette page décrit les options spécifiques à pcp2influxdb et les différences de fichier de configuration avec pmrep.conf(5). pmrep(1) liste également quelques exemples d'utilisation dont la plupart sont également applicables avec pcp2influxdb.

Seules les options en ligne de commande listées sur cette page sont supportées, les autres options disponibles pour pmrep(1) ne sont pas supportées.

Les options via les valeurs d'environnement (voir pmGetOptions(3)) remplacent les valeurs par défaut intégrées correspondantes (s'il y en a). Les options du fichier de configuration remplacent les variables d'environnement correspondantes (s'il y en a). Les options en ligne de commande remplacent les options du fichier de configuration correspondantes (s'il y en a).

FICHIER DE CONFIGURATION

pcp2influxdb utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf : version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. Le reste des options de pmrep.conf est reconnu mais ignoré pour des raisons de compatibilité.

options spécifiques à pcp2influxdb

influx_server (string)

Spécifie le serveur InfluxDB de destination. L'option en ligne de commande correspondante est -g. La valeur par défaut est http://127.0.0.1:8086.

influx_db (string)

Spécifie la base de données des métriques. L'option en ligne de commande correspondante est -x. La valeur par défaut est pcp.

influx_user (string)

Spécifie le nom d'utilisateur pour la base de données. L'option en ligne de commande correspondante est -U. Non défini par défaut (aucune authentification tentée).

influx_pass (string)

Spécifie le mot de passe pour la base de données. L'option en ligne de commande correspondante est -E. Non défini par défaut (aucune authentification tentée).

influx_tags (string)

Spécifie une chaîne de tags à ajouter aux métriques. L'option en ligne de commande correspondante est -X. Non défini par défaut.

OPTIONS

Les options disponibles en ligne de commande sont :

-0 précision, --precision-force=précision
Similaire à -P mais cette option remplacera les spécifications par métrique.
-4 action, --names-change=action
Spécifie quelle action entreprendre lors de la réception d'un événement de changement de noms de métriques pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques quelque temps après son démarrage, et informe les outils clients en exécution comme pcp2influxdb. Les valeurs valides pour action sont update (rafraîchir les métriques échantillonnées), ignore (ne rien faire - le comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignore-unknown
Ignore silencieusement tout nom de métrique qui ne peut être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-8 limite, --limit-filter=limite
Limite les résultats aux instances avec des valeurs supérieures/inférieures à limite. Un entier positif inclura les instances avec des valeurs égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances avec des valeurs égales ou inférieures à la limite dans le rapport. Une valeur de zéro n'effectue aucun filtrage par limite. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi -J et -N.
-9 limite, --limit-filter-force=limite
Similaire à -8 mais cette option remplacera les spécifications par métrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Force le premier échantillon à être aligné sur la limite d'une unité de temps naturelle alignement. Se référer à PCPIntro(1) pour une description complète de la syntaxe de alignement.
--archive-folio=folio
Lit les archives sources de métriques depuis le folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b échelle, --space-scale=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, et ainsi de suite. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-B échelle, --space-scale-force=échelle
Similaire à -b mais cette option remplacera les spécifications par métrique.
-c config, --config=config
Spécifie le fichier ou répertoire de configuration à utiliser. Dans le cas où config est un répertoire, tous les fichiers se terminant par .conf seront inclus. La valeur par défaut est le premier trouvé parmi : ./pcp2influxdb.conf, $HOME/.pcp2influxdb.conf, $HOME/pcp/pcp2influxdb.conf, et $PCP_SYSCONF_DIR/pcp2influxdb.conf. Pour plus de détails, voir la section ci-dessus et pmrep.conf(5).
--container=conteneur
Récupère les métriques de performance à partir du conteneur spécifié, local ou distant (voir -h).
-C, --check
Quitte avant de rapporter des valeurs, mais après avoir analysé la configuration et les métriques et imprimé les éventuels en-têtes.
--daemonize
Daemonise au démarrage.
-e dérivé, --derived=

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

OPTIONS

-d derived, --derived=derived
Spécifier les métriques de performance dérivées. Si derived commence par une barre oblique (/) ou par un point (.) il sera interprété comme un fichier de configuration des métriques dérivées PCP, sinon il sera interprété comme des expressions de métriques dérivées séparées par des virgules ou des points-virgules. Pour une description complète des métriques dérivées et des fichiers de configuration des métriques dérivées PCP, voir pmLoadDerivedConfig(3) et pmRegisterDerived(3). Alternativement, l'utilisation de la syntaxe de configuration pmrep.conf(5) permet de définir des métriques dérivées dans le cadre des ensembles de métriques.

En cas de problèmes avec les métriques dérivées, examinez en détail les pages de manuel susmentionnées et assurez-vous que toutes les métriques requises sont disponibles, en particulier lors de l'utilisation d'archives. Utilisez -Dderive pour voir des informations de débogage supplémentaires sur l'analyse des métriques dérivées.

-E password, --db-pass=password
Spécifier le mot de passe de la base de données password.
-g server, --db-server=server
Serveur InfluxDB de destination server.
-G, --no-globals
Ne pas inclure les métriques globales dans le rapport (voir pmrep.conf(5)).
-h host, --host=host
Récupérer les métriques de performance depuis pmcd(1) sur host, plutôt que depuis localhost par défaut.
-H, --no-header
Ne pas imprimer d'en-têtes.
-i instances, --instances=instances
Récupérer et rapporter uniquement les instances de métriques spécifiées instances. Par défaut, toutes les instances, présentes et futures, sont rapportées.

Consulter pmrep(1) pour une description complète de cette option.

-I, --ignore-incompat
Ignorer les métriques incompatibles. Par défaut, les métriques incompatibles (c'est-à-dire dont le type n'est pas supporté ou qui ne peuvent pas être mises à l'échelle comme demandé) feront que pcp2influxdb se terminera avec un message d'erreur. Avec cette option, toutes les métriques incompatibles sont silencieusement omises du rapport. Cela peut être particulièrement utile lors de la demande de nœuds non feuilles de l'arbre PMNS pour le rapport.
-j, --live-filter
Effectuer un filtrage en direct des instances. Cela permet de capturer toutes les instances nommées même si les processus sont redémarrés à un moment donné (contrairement à l'absence de filtrage en direct). L'exécution du filtrage en direct sur un grand nombre d'instances entraînera une surcharge interne, une certaine prudence est donc conseillée à l'utilisateur. Voir également -n.
-J rank, --rank=rank
Limiter les résultats aux instances les mieux classées/les moins bien classées des métriques à valeurs d'ensemble. Un entier positif inclura les instances les mieux classées dans le rapport. Un entier négatif inclura les instances les moins bien classées dans le rapport. Une valeur de zéro n'effectue aucun classement. Le classement n'implique pas le tri, voir -6. Voir également -8.
-K spec, --spec-local=spec
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spec est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peuvent être utilisées.
-L, --local-PMDA
Utiliser un contexte local pour collecter les métriques des PMDA DSO sur l'hôte local sans PMCD. Voir également -K.
-n, --invert-filter
Effectuer le classement avant le filtrage en direct. Par défaut, le filtrage en direct des instances (lorsqu'il est demandé, voir -j) se produit avant le classement des instances (lorsqu'il est demandé, voir -J). Avec cette option, la logique est inversée et le classement se produit avant le filtrage en direct.
-N predicate, --predicate=predicate
Spécifier une liste de métriques de référence de filtre prédicat séparées par des virgules. Par défaut, le classement (voir -J) se fait pour chaque métrique individuellement. Avec les prédicats, le classement ne se fait que pour les métriques prédicats spécifiées. Lors du rapport, les autres métriques partageant le même domaine d'instance (voir PCPIntro(1)) que le prédicat incluront uniquement les instances les mieux classées/les moins bien classées du prédicat correspondant. Le classement n'implique pas le tri, voir -6.

Par exemple, en utilisant proc.memory.rss (taille de la mémoire résidente du processus) comme métrique prédicat avec proc.io.total_bytes et mem.util.used comme métriques à rapporter, seuls les processus utilisant le plus/le moins de mémoire (conformément à -J) seront inclus lors du rapport des octets totaux écrits par les processus. Comme mem.util.used est une métrique à valeur unique (ne partageant donc pas le même domaine d'instance que les métriques liées aux processus), elle sera rapportée comme d'habitude.

-O origin, --origin=origin
Lors du rapport de métriques archivées, commencer le rapport à origin dans la fenêtre temporelle (voir -S et -T). Consulter PCPIntro(1) pour une description complète de la syntaxe d'origin.
-P precision, --precision=precision
Utiliser la précision pour les valeurs numériques de sortie non entières. Par défaut, 3 décimales sont utilisées (lorsque applicable). Cette option ne remplacera pas les spécifications possibles par métrique.
-q scale, --count-scale=scale
Unité/échelle pour les métriques de comptage, les valeurs possibles incluent count x 10^-1, count, count x 10, count x 10^2, et ainsi de suite de 10^-8 à 10^7. (Ces valeurs sont actuellement sensibles aux espaces.) Cette option ne remplacera pas les spécifications possibles par métrique. Voir également pmParseUnitsStr(3).
-Q scale, --count-scale-force=scale
Similaire à -q, mais cette option remplacera les spécifications par métrique.
-r, --raw
Sortie des valeurs de métriques brutes, ne pas convertir les compteurs cumulatifs en taux. Cette option remplacera les spécifications possibles par métrique.
-R, --raw-prefer
Similaire à -r, mais cette option ne remplacera pas les spécifications par métrique.
-s samples, --samples=samples
L'argument samples définit le nombre d'échantillons à récupérer et à rapporter. Si samples est 0 ou si -s n'est pas spécifié, pcp2influxdb échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive). Voir également -T.
-S starttime, --start=starttime
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements enregistrés à partir de starttime. Consulter PCPIntro(1) pour une description complète de la syntaxe de starttime.
-t interval, --interval=interval
Définir l'intervalle de rapport interval à autre chose que la seconde par défaut. L'argument interval suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes). Voir également l'option -T.
-T endtime, --finish=endtime
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements enregistrés avant ou à endtime. Consulter PCPIntro(1) pour une description complète de la syntaxe d'endtime.

Lorsqu'il est utilisé pour définir la durée de fonctionnement avant que pcp2influxdb ne se termine, si aucun samples n'est donné (voir -s), le nombre d'échantillons rapportés dépend de interval (voir -t). Si samples est donné, alors interval sera ajusté pour permettre le rapport de samples pendant la durée de fonctionnement. Si -T, -s et -t sont tous donnés, endtime déterminera l'heure réelle à laquelle pcp2influxdb s'exécutera.

-U username, --db-user=username
Spécifier le nom d'utilisateur de la base de données username.
-v, --omit-flat
Rapporter uniquement les métriques à valeurs d'ensemble avec des instances (par exemple, disk.dev.read) et omettre les métriques "plates" à valeur unique sans instances (par exemple, kernel.all.sysfork). Voir -i et -I.
-V, --version
Afficher le numéro de version et quitter.
-x database, --db-name=database
Spécifier le nom de la base de données de métriques database.
-X tags, --db-tags=tags
Spécifier des chaînes de tags à ajouter aux métriques.
-y scale, --time-scale=scale
Unité/échelle pour les métriques temporelles, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option ne remplacera pas les spécifications possibles par métrique. Voir également pmParseUnitsStr(3).
-Y scale, --time-scale-force=scale
Similaire à -y, mais cette option remplacera les spécifications par métrique.
-?, --help
Afficher le message d'utilisation et quitter.

FICHIERS

pcp2influxdb.conf
Fichier de configuration pcp2influxdb (voir -c)
$PCP_SYSCONF_DIR/pmrep/*.conf
Fichiers de configuration pmrep par défaut fournis par le système

ENVIRONNEMENT PCP

Les variables d'environnement commençant par le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

Il est particulièrement intéressant de noter que PCP_DISCRETE_ONCE peut être défini pour garantir que les valeurs de métriques discrètes ne soient signalées qu'une seule fois, sauf si elles changent à un moment donné.

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
