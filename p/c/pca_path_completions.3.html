NOM

pca_lookup_file, del_PathCache, del_PcaPathConf, new_PathCache, new_PcaPathConf, pca_last_error, pca_path_completions, pca_scan_path, pca_set_check_fn, ppc_file_start, ppc_literal_escapes - recherche un fichier dans une liste de répertoires

SYNOPIS

#include <libtecla.h>
PathCache *new_PathCache(void);
PathCache *del_PathCache(PathCache *pc);
int pca_scan_path(PathCache *pc, const char *path);
void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                      void *data);
char *pca_lookup_file(PathCache *pc, const char *name,
                      int name_len, int literal);
const char *pca_last_error(PathCache *pc);
CPL_MATCH_FN(pca_path_completions);

DESCRIPTION

L'objet PathCache fait partie de la bibliothèque tecla (voir la page de manuel libtecla(3)).

Les objets PathCache permettent à une application de rechercher des fichiers dans toute liste de répertoires séparés par des deux-points, telle que la variable d'environnement PATH d'exécution Unix. Les fichiers dans les répertoires absolus sont mis en cache dans un objet PathCache, tandis que les répertoires relatifs sont analysés au besoin. En utilisant un objet PathCache, vous pouvez rechercher le chemin complet d'un nom de fichier simple, ou vous pouvez obtenir une liste des complétions possibles d'un préfixe de nom de fichier donné. Par défaut, tous les fichiers dans la liste des répertoires sont des cibles pour la recherche et la complétion, mais un mécanisme polyvalent est fourni pour ne sélectionner que certains types de fichiers. L'application évidente de cette installation est de fournir la complétion par tabulation et la recherche de commandes exécutables dans le PATH Unix, donc une fonction de rappel optionnelle qui rejette tout sauf les fichiers exécutables est fournie.

UN EXEMPLE

Sous UNIX, le programme d'exemple suivant recherche et affiche les chemins complets de chaque nom de commande sur la ligne de commande.

  #include <stdio.h>
  #include <stdlib.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    int i;
  /*
   * Créer un cache pour les fichiers exécutables.
   */
    PathCache *pc = new_PathCache();
    if(!pc)
      exit(1);
  /*
   * Analyser le PATH de l'utilisateur pour les exécutables.
   */
    if(pca_scan_path(pc, getenv("PATH"))) {
      fprintf(stderr, "%s\n", pca_last_error(pc));
      exit(1);
    }
  /*
   * S'arranger pour ne rapporter que les fichiers exécutables.
   */
   pca_set_check_fn(pc, cpl_check_exe, NULL);
  /*
   * Rechercher et afficher le chemin complet de chacune des
   * commandes listées sur la ligne de commande.
   */
    for(i=1; i<argc; i++) {
      char *cmd = pca_lookup_file(pc, argv[i], -1, 0);
      printf("Le chemin complet de '%s' est %s\n", argv[i],
             cmd ? cmd : "inconnu");
    }
    pc = del_PathCache(pc);  /* Nettoyage */
    return 0;
  }

Voici un exemple de ce que cela fait sur mon ordinateur portable sous linux :

  $ ./example less more blob
  Le chemin complet de 'less' est /usr/bin/less
  Le chemin complet de 'more' est /bin/more
  Le chemin complet de 'blob' est inconnu
  $

DESCRIPTIONS DES FONCTIONS

Pour utiliser les fonctionnalités de ce module, vous devez d'abord allouer un objet PathCache en appelant la fonction constructeur new_PathCache().

  PathCache *new_PathCache(void)

Cette fonction crée les ressources nécessaires pour mettre en cache et rechercher des fichiers dans une liste de répertoires. Elle retourne NULL en cas d'erreur.

POPULATION DU CACHE

Une fois le cache créé, il doit être peuplé de fichiers. Pour ce faire, appelez la fonction pca_scan_path().

  int pca_scan_path(PathCache *pc, const char *path);

Chaque fois que cette fonction est appelée, elle écarte le contenu actuel du cache, puis analyse la liste des répertoires spécifiés dans son argument path à la recherche de fichiers. L'argument path doit être une chaîne contenant une liste de répertoires séparés par des deux-points, telle que "/usr/bin:/home/mcs/bin:.". Cela peut inclure des répertoires spécifiés par des chemins absolus tels que "/usr/bin", ainsi que des sous-répertoires spécifiés par des chemins relatifs tels que "." ou "bin". Les fichiers dans les répertoires absolus sont immédiatement mis en cache dans l'objet PathCache spécifié, tandis que les sous-répertoires, dont l'identité change évidemment chaque fois que le répertoire de travail actuel est changé, sont marqués pour être analysés à la volée chaque fois qu'un fichier est recherché.

En cas de succès, cette fonction retourne 0. En cas d'erreur, elle retourne 1, et une description de l'erreur peut être obtenue en appelant pca_last_error(pc).

RECHERCHE DE FICHIERS

Une fois que le cache a été peuplé de fichiers, vous pouvez rechercher le chemin complet d'un fichier, simplement en spécifiant son nom de fichier à pca_lookup_file().

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal);

Pour permettre de passer à cette fonction un nom de fichier qui fait en réalité partie d'une chaîne plus longue, l'argument name_len peut être utilisé pour spécifier la longueur du nom de fichier au début de l'argument name[]. Si vous passez -1 pour cette longueur, la longueur de la chaîne sera déterminée avec strlen(). Si la chaîne name[] peut contenir des barres obliques inverses qui échappent le sens spécial des espaces et des tabulations dans le nom de fichier, donnez à l'argument literal la valeur 0. Sinon, si les barres obliques inverses doivent être traitées comme des caractères normaux, passez 1 pour la valeur de l'argument literal.

COMPLETION DE NOM DE FICHIER

La recherche des complétions possibles d'un préfixe de nom de fichier dans le cache de noms de fichiers est réalisée en passant la fonction de rappel fournie pca_path_completions() à la fonction cpl_complete_word() (voir la page de manuel cpl_complete_word(3)).

  CPL_MATCH_FN(pca_path_completions);

Cette fonction de rappel nécessite que son argument data soit un pointeur vers un objet PcaPathConf. Les objets de configuration de ce type sont alloués en appelant new_PcaPathConf().

  PcaPathConf *new_PcaPathConf(PathCache *pc);

Cette fonction retourne un objet initialisé avec des paramètres de configuration par défaut, qui déterminent le comportement de la fonction de rappel cpl_path_completions(). Les fonctions qui permettent de modifier individuellement ces paramètres sont décrites ci-dessous.

Par défaut, la fonction de rappel pca_path_completions() recherche en arrière à partir du début du nom de fichier en cours de complétion, à la recherche du premier espace non échappé ou du début de la ligne d'entrée. Si vous souhaitez spécifier un emplacement différent, appelez ppc_file_start() avec l'indice auquel le nom de fichier commence dans la ligne d'entrée. Passer start_index=-1 réactive le comportement par défaut.

  void ppc_file_start(PcaPathConf *ppc, int start_index);

Par défaut, lorsque pca_path_completions() examine un nom de fichier dans la ligne d'entrée, chaque barre oblique inverse isolée dans la ligne d'entrée est interprétée comme un caractère spécial qui supprime toute signification spéciale du caractère qui la suit, comme un espace qui doit être pris comme faisant partie du nom de fichier plutôt que comme délimitant le début du nom de fichier. Ces barres obliques inverses sont donc ignorées lors de la recherche de complétions, et ajoutées par la suite avant les espaces, tabulations et barres obliques inverses littérales dans la liste des complétions. Pour que les barres obliques inverses non échappées soient traitées comme des caractères normaux, appelez ppc_literal_escapes() avec une valeur non nulle pour son argument literal.

  void ppc_literal_escapes(PcaPathConf *ppc, int literal);

Lorsque vous avez terminé avec une variable PcaPathConf, vous pouvez la passer à la fonction destructeur del_PcaPathConf() pour libérer sa mémoire.

  PcaPathConf *del_PcaPathConf(PcaPathConf *ppc);

POUR ETRE SELECTIF

Si vous n'êtes intéressé que par certains types ou fichiers, par exemple des fichiers exécutables, ou des fichiers dont les noms se terminent par un suffixe particulier, vous pouvez faire en sorte que les fonctions de complétion et de recherche de fichiers ne renvoient que certains fichiers. Ceci est réalisé en enregistrant une fonction de rappel auprès de votre objet PathCache. Par la suite, chaque fois qu'un nom de fichier est trouvé qui correspond soit à un nom de fichier recherché, soit à un préfixe en cours de complétion, votre rappel

la fonction ack sera appelée avec le chemin d'accès complet du fichier, ainsi que toute donnée spécifique à l'application que vous fournissez, et si la fonction de rappel renvoie 1 le nom du fichier sera signalé comme une correspondance, et si elle renvoie 0, il sera ignoré. Les fonctions de rappel appropriées et leurs prototypes doivent être déclarés avec le macro suivant. Le CplCheckFn typedef est également fourni au cas où vous souhaiteriez déclarer des pointeurs vers de telles fonctions.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);

L'enregistrement d'une de ces fonctions implique l'appel de la fonction pca_set_check_fn(). En plus de la fonction de rappel, passée via l'argument check_fn, vous pouvez passer un pointeur vers n'importe quoi via l'argument data. Ce pointeur sera transmis à votre fonction de rappel, via son propre argument data, chaque fois qu'elle sera appelée, cela fournit donc un moyen de passer des données spécifiques à l'application à votre rappel.

  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

Notez que ces rappels reçoivent le chemin d'accès complet de chaque fichier correspondant, de sorte que la décision de savoir si un fichier est d'intérêt peut être basée sur n'importe quelle propriété du fichier, pas seulement sur son nom de fichier. Par exemple, la fonction de rappel fournie cpl_check_exe() examine les autorisations d'exécution du fichier et les autorisations de ses répertoires parents, et ne renvoie 1 que si l'utilisateur a l'autorisation d'exécuter le fichier. Cette fonction de rappel peut ainsi être utilisée pour rechercher ou compléter des noms de commandes trouvés dans les répertoires listés dans la variable d'environnement PATH de l'utilisateur. L'exemple de programme donné précédemment dans cette page de manuel en fournit une démonstration.

Attention, si quelqu'un essaie de compléter une chaîne vide, votre rappel sera appelé une fois pour chaque fichier dans le cache, ce qui pourrait représenter des milliers de fichiers. Si votre rappel effectue des opérations coûteuses en temps, cela pourrait entraîner un délai inacceptable pour l'utilisateur, les rappels doivent donc être courts.

Pour améliorer les performances, chaque fois qu'un de ces rappels est appelé, le choix qu'il fait est mis en cache, et la prochaine fois que le fichier correspondant est recherché, au lieu d'appeler à nouveau le rappel, l'enregistrement mis en cache de son acceptation ou de son rejet est utilisé. Ainsi, si quelqu'un essaie de compléter une chaîne vide, et appuie sur tabulation une seconde fois alors que rien ne semble se passer, il n'y aura qu'un seul long délai, puisque la seconde passe opérera entièrement à partir des dispositions mises en cache des fichiers. Ces dispositions mises en cache sont supprimées chaque fois que pca_scan_path() est appelée, et chaque fois que pca_set_check_fn() est appelée avec des arguments de fonction de rappel ou de données modifiés.

GESTION DES ERREURS

Si pca_scan_path() signale qu'une erreur s'est produite en renvoyant 1, vous pouvez obtenir une description succincte de l'erreur en appelant pca_last_error(pc). Cela renvoie une chaîne interne contenant un message d'erreur.

  const char *pca_last_error(PathCache *pc);

NETTOYAGE

Une fois que vous avez terminé d'utiliser un objet PathCache, vous pouvez récupérer ses ressources en le passant à la fonction destructeur del_PathCache(). Celle-ci prend un pointeur vers un de ces objets, et renvoie toujours NULL.

  PathCache *del_PathCache(PathCache *pc);

SÉCURITÉ DES THREADS

Dans les programmes multithreadés, vous devez utiliser la version libtecla_r.a de la bibliothèque. Celle-ci utilise des fonctions POSIX réentrantes lorsque disponibles (d'où le suffixe _r) et désactive les fonctionnalités qui dépendent de fonctions système non réentrantes. Dans le cas de ce module, la seule fonctionnalité désactivée est la complétion des noms d'utilisateur dans les expressions ~username/, dans cpl_path_completions().

En utilisant la version libtecla_r.a de la bibliothèque, il est sûr d'utiliser les fonctionnalités de ce module dans plusieurs threads, à condition que chaque thread utilise un objet PathCache alloué séparément. En d'autres termes, si deux threads veulent effectuer des recherches de chemins, ils devraient chacun appeler new_PathCache() pour allouer leurs propres caches.
