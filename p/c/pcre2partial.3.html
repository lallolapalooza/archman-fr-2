CORRESPONDANCES PARTIELLES DANS PCRE2

Dans l'utilisation normale de PCRE2, s'il y a une correspondance jusqu'à la fin d'une chaîne sujet, mais que des caractères supplémentaires sont nécessaires pour faire correspondre le motif entier, PCRE2_ERROR_NOMATCH est renvoyé, comme pour toute autre correspondance échouée. Il existe des circonstances où il peut être utile de distinguer ce cas de "correspondance partielle".

Un exemple est une application où la chaîne sujet est très longue et n'est pas disponible en une seule fois. L'exigence est de pouvoir effectuer la correspondance segment par segment, mais une action spéciale est nécessaire lorsqu'une sous-chaîne correspondante chevauche la frontière entre deux segments.

Un autre exemple est la vérification d'une chaîne entrée par l'utilisateur au fur et à mesure qu'elle est tapée, afin de s'assurer qu'elle respecte un format requis. Les caractères invalides peuvent être immédiatement diagnostiqués et rejetés, donnant un retour d'information instantané.

La correspondance partielle est une fonctionnalité spécifique à PCRE2 ; elle n'est pas compatible avec Perl. Elle est demandée en définissant l'une des options PCRE2_PARTIAL_HARD ou PCRE2_PARTIAL_SOFT lors de l'appel d'une fonction de correspondance. La différence entre les deux options est de savoir si une correspondance partielle est préférée à une correspondance complète alternative, bien que les détails diffèrent entre les deux types de fonctions de correspondance. Si les deux options sont définies, PCRE2_PARTIAL_HARD a la priorité.

Si vous souhaitez utiliser la correspondance partielle avec du code optimisé juste-à-temps, en plus de définir une option de correspondance partielle pour la fonction de correspondance, vous devez également appeler pcre2_jit_compile() avec l'une ou l'autre de ces options :


PCRE2_JIT_PARTIAL_HARD
PCRE2_JIT_PARTIAL_SOFT

PCRE2_JIT_COMPLETE doit également être défini si vous allez exécuter des correspondances non partielles sur le même motif. Un code distinct est compilé pour chaque mode. Si le mode JIT approprié n'a pas été compilé, le code de correspondance interprétatif est utilisé.

La définition d'une option de correspondance partielle désactive deux des indices d'optimisation standard de PCRE2. PCRE2 mémorise la dernière unité de code littérale dans un motif et abandonne immédiatement la correspondance si elle n'est pas présente dans la chaîne sujet. Cette optimisation ne peut pas être utilisée pour une chaîne sujet qui pourrait ne correspondre que partiellement. PCRE2 mémorise également une longueur minimale d'une chaîne correspondante et ne s'embête pas à exécuter la fonction de correspondance sur des chaînes plus courtes. Cette optimisation est également désactivée pour la correspondance partielle.

EXIGENCES POUR UNE CORRESPONDANCE PARTIELLE

Une correspondance partielle possible se produit pendant la correspondance lorsque la fin de la chaîne sujet est atteinte avec succès, mais soit des caractères supplémentaires sont nécessaires pour compléter la correspondance, soit l'ajout de caractères supplémentaires pourrait modifier ce qui est trouvé.

Exemple 1 : si le motif est /abc/ et le sujet est "ab", des caractères supplémentaires sont définitivement nécessaires pour compléter une correspondance. Dans ce cas, les options de correspondance dure et douce donnent une correspondance partielle.

Exemple 2 : si le motif est /ab+/ et le sujet est "ab", une correspondance complète peut être trouvée, mais l'ajout de caractères supplémentaires pourrait modifier ce qui est trouvé. Dans ce cas, seule PCRE2_PARTIAL_HARD renvoie une correspondance partielle ; PCRE2_PARTIAL_SOFT renvoie la correspondance complète.

En atteignant la fin du sujet, lorsque PCRE2_PARTIAL_HARD est défini, si le prochain élément du motif est \z, \Z, \b, \B, ou $, il y a toujours une correspondance partielle. Sinon, pour les deux options, le prochain élément du motif doit être un élément qui inspecte un caractère, et au moins l'une des conditions suivantes doit être vraie :

(1) Au moins un caractère a déjà été inspecté. Un caractère inspecté n'a pas besoin de faire partie de la chaîne de correspondance finale ; les assertions de recherche en arrière et la séquence d'échappement \K fournissent des moyens d'inspecter des caractères avant le début d'une chaîne de correspondance.

(2) Le motif contient une ou plusieurs assertions de recherche en arrière. Cette condition existe au cas où il y aurait une recherche en arrière qui inspecte des caractères avant le début de la correspondance.

(3) Il existe un cas spécial lorsque le motif entier peut faire correspondre une chaîne vide. Lorsque le point de départ est à la fin du sujet, la correspondance de la chaîne vide est une possibilité, et si PCRE2_PARTIAL_SOFT est défini et que ni l'une ni l'autre des conditions ci-dessus n'est vraie, elle est renvoyée. Cependant, comme l'ajout de caractères supplémentaires pourrait entraîner une correspondance non vide, PCRE2_PARTIAL_HARD renvoie une correspondance partielle, ce qui dans ce cas signifie "il va y avoir une correspondance à ce point, mais jusqu'à ce que des caractères supplémentaires soient ajoutés, nous ne savons pas si ce sera une chaîne vide ou quelque chose de plus long".

UTILISATION DE LA CORRESPONDANCE PARTIELLE AVEC pcre2_match()

Lorsqu'une option de correspondance partielle est définie, le résultat de l'appel de pcre2_match() peut être l'un des éléments suivants :

UNE CORRESPONDANCE COMPLETE
Une correspondance complète a été trouvée, commençant et se terminant dans ce sujet.
PCRE2_ERROR_NOMATCH
Aucune correspondance ne peut commencer n'importe où dans ce sujet.
PCRE2_ERROR_PARTIAL
L'ajout de caractères supplémentaires peut entraîner une correspondance complète utilisant un ou plusieurs caractères de la fin de ce sujet.

Lorsqu'une correspondance partielle est renvoyée, les deux premiers éléments de l'ovector pointent vers la portion du sujet qui a été trouvée, mais les valeurs dans le reste de l'ovector ne sont pas définies. L'apparition de \K dans le motif n'a aucun effet pour une correspondance partielle. Considérons ce motif :


/abc\K123/

S'il est mis en correspondance avec "456abc123xyz", le résultat est une correspondance complète, et l'ovector définit la chaîne correspondante comme "123", car \K réinitialise le point de "début de la correspondance". Cependant, si une correspondance partielle est demandée et que la chaîne sujet est "456abc12", une correspondance partielle est trouvée pour la chaîne "abc12", car tous ces caractères sont nécessaires pour une re-correspondance ultérieure avec des caractères supplémentaires.

S'il y a plus d'une correspondance partielle, la première qui a été trouvée fournit les données renvoyées. Considérons ce motif :


/123\w+X|dogY/

S'il est mis en correspondance avec la chaîne sujet "abc123dog", les deux alternatives échouent à correspondre, mais la fin du sujet est atteinte pendant la correspondance, donc PCRE2_ERROR_PARTIAL est renvoyé. Les décalages sont définis à 3 et 9, identifiant "123dog" comme la première correspondance partielle. (Dans cet exemple, il y a deux correspondances partielles, car "dog" à lui seul correspond partiellement à la deuxième alternative.)

Comment une correspondance partielle est traitée par pcre2_match()

Ce qui se passe lorsqu'une correspondance partielle est identifiée dépend de l'option de correspondance partielle définie.

Si PCRE2_PARTIAL_HARD est défini, PCRE2_ERROR_PARTIAL est renvoyé dès qu'une correspondance partielle est trouvée, sans continuer à rechercher d'éventuelles correspondances complètes. Cette option est "dure" car elle préfère une correspondance partielle antérieure à une correspondance complète ultérieure. Pour cette raison, on suppose que la fin de la chaîne sujet fournie n'est pas la vraie fin des données disponibles, ce qui explique pourquoi \z, \Z, \b, \B et $ donnent toujours une correspondance partielle.

Si PCRE2_PARTIAL_SOFT est défini, la correspondance partielle est mémorisée, mais la correspondance continue normalement, et d'autres alternatives dans le motif sont essayées. Si aucune correspondance complète ne peut être trouvée, PCRE2_ERROR_PARTIAL est renvoyé au lieu de PCRE2_ERROR_NOMATCH. Cette option est "douce" car elle préfère une correspondance complète à une correspondance partielle. Tous les différents éléments de correspondance d'un motif se comportent comme si la chaîne sujet était potentiellement complète ; \z, \Z, et $ correspondent à la fin du sujet, comme d'habitude, et pour \b et \B, la fin du sujet est traitée comme non alphanumérique.

La différence entre les deux options de correspondance partielle peut être illustrée par un motif tel que :


/dog(sbody)?/

Cela correspond soit à "dog", soit à "dogsbody", de manière gourmande (c'est-à-dire qu'il préfère la chaîne la plus longue si possible). S'il est mis en correspondance avec la chaîne "dog" avec PCRE2_PARTIAL_SOFT, il renvoie une correspondance complète pour "dog". Cependant, si PCRE2_PARTIAL_HARD est défini, le résultat est PCRE2_ERROR_PARTIAL. D'un autre côté, si le motif est rendu non gourmand, le résultat est différent :


/dog(sbody)??/

PARTIAL MATCHING

When the PCRE2_PARTIAL flag is set, pcre2_match() may return PCRE2_ERROR_PARTIAL if the end of the subject string is reached while the regular expression is still partially matched. This is only done if no complete match has been found. If a complete match has been found, it is returned normally.

The difference between PCRE2_PARTIAL_HARD and PCRE2_PARTIAL_SOFT is what happens when a complete match is found. With PCRE2_PARTIAL_SOFT, a complete match is returned, even if a partial match was also possible. With PCRE2_PARTIAL_HARD, a partial match is returned if it is longer than a complete match.

Consider the pattern /dog(sbody)?/. This matches the string "dog" and also "dogsbody". The parenthesized group is optional. If the flag PCRE2_PARTIAL_HARD is set, and the subject is "dogsbody", the function will match "dogsbody" and return it. If the subject is "dog", it will match "dog" and return it. The pattern /dog(sbody)??/ is different. The second question mark makes the group possessively optional. PCRE never continues after finding a complete match. It might be easier to follow this explanation by thinking of the two patterns like this:


/dog(sbody)?/ is the same as /dogsbody|dog/
/dog(sbody)??/ is the same as /dog|dogsbody/

The second pattern will never match "dogsbody", because it will always find the shorter match first.

Example of partial matching using pcre2test

The pcre2test data modifiers partial_hard (or ph) and partial_soft (or ps) set PCRE2_PARTIAL_HARD and PCRE2_PARTIAL_SOFT, respectively, when calling pcre2_match(). Here is a run of pcre2test using a pattern that matches the whole subject in the form of a date:


re> /^\d?\d(jan|feb|mar|apr|may|jun|jul|aug|sep|oct|nov|dec)\d\d$/
data> 25dec3=ph
Partial match: 23dec3
data> 3ju=ph
Partial match: 3ju
data> 3juj=ph
No match

This example gives the same results for both hard and soft partial matching options. Here is an example where there is a difference:


re> /^\d?\d(jan|feb|mar|apr|may|jun|jul|aug|sep|oct|nov|dec)\d\d$/
data> 25jun04=ps
0: 25jun04
1: jun
data> 25jun04=ph
Partial match: 25jun04

With PCRE2_PARTIAL_SOFT, the subject is matched completely. For PCRE2_PARTIAL_HARD, however, the subject is assumed not to be complete, so there is only a partial match.

MULTI-SEGMENT MATCHING WITH pcre2_match()

PCRE was not originally designed with multi-segment matching in mind. However, over time, features (including partial matching) that make multi-segment matching possible have been added. A very long string can be searched segment by segment by calling pcre2_match() repeatedly, with the aim of achieving the same results that would happen if the entire string was available for searching all the time. Normally, the strings that are being sought are much shorter than each individual segment, and are in the middle of very long strings, so the pattern is normally not anchored.

Special logic must be implemented to handle a matched substring that spans a segment boundary. PCRE2_PARTIAL_HARD should be used, because it returns a partial match at the end of a segment whenever there is the possibility of changing the match by adding more characters. The PCRE2_NOTBOL option should also be set for all but the first segment.

When a partial match occurs, the next segment must be added to the current subject and the match re-run, using the startoffset argument of pcre2_match() to begin at the point where the partial match started. For example:


re> /\d?\d(jan|feb|mar|apr|may|jun|jul|aug|sep|oct|nov|dec)\d\d/
data> ...the date is 23ja=ph
Partial match: 23ja
data> ...the date is 23jan19 and on that day...=offset=15
0: 23jan19
1: jan

Note the use of the offset modifier to start the new match where the partial match was found. In this example, the next segment was added to the one in which the partial match was found. This is the most straightforward approach, typically using a memory buffer that is twice the size of each segment. After a partial match, the first half of the buffer is discarded, the second half is moved to the start of the buffer, and a new segment is added before repeating the match as in the example above. After a no match, the entire buffer can be discarded.

If there are memory constraints, you may want to discard text that precedes a partial match before adding the next segment. Unfortunately, this is not at present straightforward. In cases such as the above, where the pattern does not contain any lookbehinds, it is sufficient to retain only the partially matched substring. However, if the pattern contains a lookbehind assertion, characters that precede the start of the partial match may have been inspected during the matching process. When pcre2test displays a partial match, it indicates these characters with '<' if the allusedtext modifier is set:


re> "(?<=123)abc"
data> xx123ab=ph,allusedtext
Partial match: 123ab
<<<

However, the allusedtext modifier is not available for JIT matching, because JIT matching does not record the first (or last) consulted characters. For this reason, this information is not available via the API. It is therefore not possible in general to obtain the exact number of characters that must be retained in order to get the right match result. If you cannot retain the entire segment, you must find some heuristic way of choosing.

If you know the approximate length of the matching substrings, you can use that to decide how much text to retain. The only lookbehind information that is currently available via the API is the length of the longest individual lookbehind in a pattern, but this can be misleading if there are nested lookbehinds. The value returned by calling pcre2_pattern_info() with the PCRE2_INFO_MAXLOOKBEHIND option is the maximum number of characters (not code units) that any individual lookbehind moves back when it is processed. A pattern such as "(?<=(?<!b)a)" has a maximum lookbehind value of one, but inspects two characters before its starting point.

In a non-UTF or a 32-bit case, moving back is just a subtraction, but in UTF-8 or UTF-16 you have to count characters while moving back through the code units.

PARTIAL MATCHING USING pcre2_dfa_match()

The DFA function moves along the subject string character by character, without backtracking, searching for all possible matches simultaneously. If the end of the subject is reached before the end of the pattern, there is the possibility of a partial match.

When PCRE2_PARTIAL_SOFT is set, PCRE2_ERROR_PARTIAL is returned only if there have been no complete matches. Otherwise, the complete matches are returned. If PCRE2_PARTIAL_HARD is set, a partial match takes precedence over any complete matches. The portion of the string that was matched when the longest partial match was found is set as the first matching string.

Because the DFA function always searches for all possible matches, and there is no difference between greedy and ungreedy repetition, its behaviour is different from the pcre2_match(). Consider the string "dog" matched against this ungreedy pattern:


/dog(sbody)??/

Whereas the standard function stops as soon as it finds the complete match for "dog", the DFA function also finds the partial match for "dogsbody", and so returns that when PCRE2_PARTIAL_HARD is set.

MULTI-SEGMENT MATCHING WITH pcre2_dfa_match()

When a partial match has been found using the DFA matching function, it is possible to continue the match by providing additional subject data and calling the function again with the same compiled regular expression, this time setting the PCRE2_DFA_RESTART option. You must pass the same working space as before, because this is where details of the previous partial match are stored. You can set the PCRE2_PARTIAL_SOFT or PCRE2_PARTIAL_HARD options with PCRE2_DFA_RESTART to continue partial matching over multiple segments. Here is an example using pcre2test:


re> /^\d?\d(jan|feb|mar|apr|may|jun|jul|aug|sep|oct|nov|dec)\d\d$/
data> 23ja=dfa,ps
Partial match: 23ja
data> n05=dfa,dfa_restart
0: n05

The first call has "23ja" as the subject, and requests partial matching; the second call has "n05" as the subject for the continued (restarted) match. Notice that when the match is complete, only the last part is shown; PCRE2 does not retain the previously partially-matched string. It is up to the calling program to do that if it needs to. This means that, for an unanchored pattern, if a continued match fails, it is not possible to try again at a new starting point. All this facility is capable of doing is continuing with the previous match attempt. For example, consider this pattern:


1234|3789

If the first part of the subject is "ABC123", a partial match of the first alternative is found at offset 3. There is no partial match for the second alternative, because such a match does not start at the same point in the subject string. Attempting to continue with the string "7890" does not yield a match because only those alternatives that match at one point in the subject are remembered. Depending on the application, this may or may not be what you want.

If you do want to allow for starting again at the next character, one way of doing it is to retain some or all of the segment and try a new complete match, as described for pcre2_match() above. Another possibility is to work with two buffers. If a partial match at offset n in the first buffer is followed by "no match" when PCRE2_DFA_RESTART is used on the second buffer, you can then try a new match starting at offset n+1 in the first buffer.

NOM

pcre2partial - correspondance partielle dans les chaînes avec PCRE2

CORRESPONDANCE PARTIELLE DANS PCRE2

La correspondance partielle se produit lorsque l'on recherche un motif dans une chaîne, mais que la correspondance entière n'est pas requise. Par exemple, la recherche du motif "abc" dans la chaîne "abcdefg" aboutit à une correspondance partielle car "abc" est trouvé, même si la chaîne se poursuit. La correspondance complète, par défaut, recherche une correspondance de toute la chaîne.

EXIGENCES POUR UNE CORRESPONDANCE PARTIELLE

Pour obtenir une correspondance partielle, vous devez demander explicitement ce comportement. Ceci peut être fait soit via une option spéciale lors de la compilation du motif, soit en appelant une fonction de correspondance qui prend en charge la correspondance partielle.

CORRESPONDANCE PARTIELLE AVEC pcre2_match()

La fonction pcre2_match() peut être utilisée pour la correspondance partielle en utilisant le groupe d'options PCRE2_PARTIAL. Cette option indique à la fonction d'arrêter la recherche de motif dès qu'une correspondance est trouvée, même si ce n'est pas une correspondance complète de la chaîne.

Voici un exemple d'utilisation de pcre2_match() pour une correspondance partielle :

int rc;
pcre2_code *re;
PCRE2_SPARE_SIZE_T length;
PCRE2_SPARE_SIZE_T *ovec;
char error_buffer[256];

re = pcre2_compile("abc", 3, 0, NULL, NULL, NULL);
if (re == NULL) {
    pcre2_get_error(NULL, error_buffer, sizeof(error_buffer));
    fprintf(stderr, "Erreur de compilation : %s\n", error_buffer);
    return 1;
}

ovec = pcre2_get_ovector_pointer(re);
length = pcre2_match(re, "abcdefg", 7, 0, PCRE2_PARTIAL, ovec, 0);

if (length < 0) {
    fprintf(stderr, "Correspondance échouée (code : %ld)\n", length);
} else {
    printf("Correspondance partielle trouvée de longueur %ld\n", length);
    printf("Début: %ld, Fin: %ld\n", ovec[0], ovec[1]);
}

pcre2_code_free(re);

CORRESPONDANCE MULTI-SEGMENT AVEC pcre2_match()

La fonction pcre2_match() prend également en charge la correspondance multi-segment avec l'option PCRE2_PARTIAL. Cela signifie que vous pouvez faire correspondre plusieurs segments d'une chaîne avec un seul motif. Par exemple, si vous recherchez un motif qui correspond à "a" et "c" dans la chaîne "abcde", la fonction trouvera "a" et ensuite "c" comme des correspondances séparées.

Pour activer la correspondance multi-segment, vous devez utiliser l'option PCRE2_NOTEMPTY et PCRE2_PARTIAL lors de l'appel de pcre2_match().

CORRESPONDANCE PARTIELLE AVEC pcre2_dfa_match()

La fonction pcre2_dfa_match(), utilisée pour la correspondance avec les automates finis déterministes (DFA), peut également être utilisée pour la correspondance partielle. L'option PCRE2_PARTIAL a le même effet que pour pcre2_match(), arrêtant la recherche dès qu'une correspondance est trouvée.

Voici un exemple avec pcre2_dfa_match() :

int rc;
pcre2_code *re;
PCRE2_SPARE_SIZE_T length;
PCRE2_SPARE_SIZE_T *ovec;
char error_buffer[256];

re = pcre2_compile("abc", 3, 0, NULL, NULL, NULL);
if (re == NULL) {
    pcre2_get_error(NULL, error_buffer, sizeof(error_buffer));
    fprintf(stderr, "Erreur de compilation : %s\n", error_buffer);
    return 1;
}

ovec = pcre2_get_ovector_pointer(re);
length = pcre2_dfa_match(re, "abcdefg", 7, 0, PCRE2_PARTIAL, ovec, 0);

if (length < 0) {
    fprintf(stderr, "Correspondance échouée (code : %ld)\n", length);
} else {
    printf("Correspondance partielle trouvée de longueur %ld\n", length);
    printf("Début: %ld, Fin: %ld\n", ovec[0], ovec[1]);
}

pcre2_code_free(re);

CORRESPONDANCE MULTI-SEGMENT AVEC pcre2_dfa_match()

Comme pour pcre2_match(), pcre2_dfa_match() supporte la correspondance multi-segment avec PCRE2_PARTIAL. Cela permet de trouver plusieurs occurrences d'un motif dans une chaîne, même si elles ne sont pas contiguës.

Utilisez les options PCRE2_NOTEMPTY et PCRE2_PARTIAL pour activer la correspondance multi-segment avec pcre2_dfa_match().
