NOM

pcap_get_selectable_fd - obtenir un descripteur de fichier sur lequel un select() peut être effectué pour une capture en direct

SYNTAXE

#include <pcap/pcap.h>
int pcap_get_selectable_fd(pcap_t *p);

DESCRIPTION

Sur UNIX, pcap_get_selectable_fd() retourne le numéro d'un descripteur de fichier sur lequel on peut effectuer un appel à select(2), poll(2), epoll_wait(2), kevent(2), ou un appel similaire pour attendre qu'il soit possible de lire des paquets sans bloquer, si un tel descripteur existe, ou -1 s'il n'existe aucun descripteur de ce type.

Certains périphériques réseau ouverts avec pcap_create(3PCAP) et pcap_activate(3PCAP), ou avec pcap_open_live(3PCAP), ne supportent pas ces appels (par exemple, les périphériques réseau classiques sous FreeBSD 4.3 et 4.4, et les périphériques Endace DAG), donc -1 est retourné pour ces périphériques. Dans ce cas, les appels doivent recevoir un délai d'attente inférieur ou égal au délai d'attente retourné par pcap_get_required_select_timeout(3PCAP) pour le périphérique pour lequel pcap_get_selectable_fd() a retourné -1, le périphérique doit être mis en mode non bloquant avec un appel à pcap_setnonblock(3PCAP), et une tentative doit toujours être faite pour lire les paquets du périphérique lorsque l'appel retourne. Si pcap_get_required_select_timeout() retourne NULL, il n'est pas possible d'attendre l'arrivée des paquets sur le périphérique dans une boucle d'événements.

Notez qu'un périphérique sur lequel une lecture peut être effectuée sans bloquer peut, sur certaines plateformes, ne pas avoir de paquets à lire si le délai d'attente du tampon de paquets a expiré. Un appel à pcap_dispatch(3PCAP) ou pcap_next_ex(3PCAP) retournera 0 dans ce cas, mais ne bloquera pas.

Notez que dans :

FreeBSD avant FreeBSD 4.6 ;
NetBSD avant NetBSD 3.0 ;
OpenBSD avant OpenBSD 2.4 ;
Mac OS X avant Mac OS X 10.7 ;

select(), poll(), et kevent() ne fonctionnent pas correctement sur les périphériques BPF ; pcap_get_selectable_fd() retournera un descripteur de fichier sur la plupart de ces versions (les exceptions étant FreeBSD 4.3 et 4.4), mais un simple appel à select(), poll(), ou kevent() n'indiquera pas que le descripteur est lisible avant qu'un tampon complet de paquets ne soit reçu, même si le délai d'attente des paquets expire avant. Pour contourner ce problème, le code qui utilise ces appels pour attendre l'arrivée des paquets doit mettre le pcap_t en mode non bloquant, et doit s'arranger pour que l'appel ait un délai d'attente inférieur ou égal au délai d'attente du tampon de paquets, et doit essayer de lire des paquets après l'expiration de ce délai, indépendamment du fait que l'appel ait indiqué ou non que le descripteur de fichier du pcap_t est prêt à être lu. (Ce contournement ne fonctionnera pas sous FreeBSD 4.3 et versions ultérieures ; cependant, sous FreeBSD 4.6 et versions ultérieures, ces appels fonctionnent correctement sur les périphériques BPF, donc le contournement n'est pas nécessaire, bien qu'il ne nuise pas.)

Notez également que poll() et kevent() ne fonctionnent pas sur les fichiers spéciaux de caractères, y compris les périphériques BPF, sous Mac OS X 10.4 et 10.5, donc, bien que select() puisse être utilisé sur le descripteur retourné par pcap_get_selectable_fd(), poll() et kevent() ne peuvent pas être utilisés sur celui-ci dans ces versions de Mac OS X. poll(), mais pas kevent(), fonctionne sur ce descripteur dans les versions de Mac OS X antérieures à 10.4 ; poll() et kevent() fonctionnent sur ce descripteur dans Mac OS X 10.6 et versions ultérieures.

pcap_get_selectable_fd() n'est pas disponible sous Windows.

VALEUR DE RETOUR

Un descripteur de fichier sélectionnable est retourné s'il en existe un ; sinon, -1 est retourné.
