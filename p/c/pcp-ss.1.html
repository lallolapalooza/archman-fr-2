PCP-SS(1) Manuel des commandes générales PCP-SS(1)

NOM

pcp-ss - rapport des statistiques de sockets

SYNOPSIS

pcp [options pcp] ss [options ss]

DESCRIPTION

pcp-ss rapporte les statistiques de sockets collectées par l'agent PMDA pmdasockets(1). La commande vise à être raisonnablement compatible avec de nombreuses options de ligne de commande et formats de rapport de ss(8), mais offre également les avantages de la surveillance locale ou distante (en mode live) et aussi de la relecture historique à partir d'une archive PCP préalablement enregistrée. Notez que puisque ss(1) possède de nombreuses options de ligne de commande, dont beaucoup sont identiques aux options de ligne de commande PCP standard telles que décrites dans PCPIntro(1), l'outil pcp-ss doit toujours être invoqué par les utilisateurs en utilisant le frontal pcp. Cela permet aux options de ligne de commande PCP standard telles que -h, -a, -S, -T, -O, -z, etc. d'être passées sans conflit avec les options de ss(1). Voir les sections EXEMPLES ci-dessous pour une utilisation et des lignes de commande typiques.

Le mode live utilise l'option pcp -h hôte et nécessite que le PMDA pmdasockets(1) soit installé et activé sur l'hôte cible (local ou distant). Voir pmdasockets(1) pour les détails sur la façon d'activer le PMDA sockets sur un hôte particulier. La source par défaut est les métriques live collectées sur localhost, si aucune des options -h ou -a n'est donnée.

La relecture historique/archive utilise l'option pcp -a archive, où archive est le nom de base d'une archive PCP enregistrée précédemment. La fonction de relecture d'archive est particulièrement utile car les statistiques de sockets peuvent être rapportées pour une heure désignée en utilisant l'option pcp --origin (qui par défaut est l'heure de début de l'archive).

EXEMPLES

pcp ss
Affiche les informations de base par défaut sur les sockets pour l'hôte local. Cela inclut Netid (tcp, udp, etc.), State (ESTAB, TIME_WAIT, etc.), les files d'attente Recv-Q et Send-Q, ainsi que l'adresse et le port locaux et pairs pour chaque socket.
pcp -h hotequelconque ss -noemitauO
Affiche les mêmes informations de base sur les sockets que ci-dessus pour l'hôte hotequelconque, qui peut être le localhost par défaut. Les arguments supplémentaires de ligne de commande (-noemitauO) affichent une ligne par socket (-O), les noms de services numériques (-n) (par défaut), les informations de temporisation (-o), les détails étendus des sockets (-e), l'utilisation de la mémoire des sockets (-m), les informations internes TCP (-i), les sockets udp (-u) et tcp (-t) ainsi que les sockets en écoute et non en écoute (-a).
pcp -a archivequelconque -S'@Wed 16 Jun 2021 12:57:21' ss -noemitauO
Affiche les mêmes informations que l'exemple ci-dessus, mais pour l'archive archivequelconque à partir de l'heure donnée Wed 16 Jun 2021 12:57:21. Notez que le préfixe littéral @ est requis pour une heure absolue. Voir PCPIntro(1) pour les détails. L'archive doit bien sûr contenir des données pour l'heure demandée. Vous pouvez utiliser pmlogdump -l archivequelconque pour examiner les limites temporelles de archivequelconque.
pcp -a archivequelconque -O-0 ss -noemitauO
Comme ci-dessus, mais avec un décalage de zéro seconde (-O-0) avant la fin actuelle de archivequelconque, c'est-à-dire les données les plus récemment enregistrées. Notez que archivequelconque peut être en cours de croissance (c'est-à-dire enregistré avec pmlogger(1)).

OPTIONS

En raison du grand nombre d'options prises en charge par pcp-ss, la commande pcp(1) doit toujours être utilisée pour invoquer pcp-ss afin de spécifier des options telles que la source des métriques (hôte ou archive) et également (en mode archive), l'heure de début ou le décalage demandé, et le fuseau horaire en utilisant les options suivantes :

-h, --host
Le nom d'hôte distant auquel se connecter en mode live.
-a, --archive
Le fichier d'archive à utiliser pour l'échantillonnage historique
-O, --origin
Le décalage temporel à utiliser dans une archive (implique -a)
-S, --start
L'heure de début (par exemple au format ctime(3)) à utiliser lors de la relecture d'une archive.
-Z, --timezone
Utiliser un fuseau horaire spécifique. Puisque pcp-ss n'affiche pas d'horodatages, cela n'affecte que l'interprétation d'une heure de début absolue (-S) ou d'un décalage (-O).
-z, --hostzone
En mode archive, utiliser le fuseau horaire de l'archive plutôt que le fuseau horaire de la machine locale exécutant pcp-ss. Le fuseau horaire, les heures de début et de fin de l'archive peuvent être examinés en utilisant pmlogdump(1) avec l'option -L.

Les options pcp ci-dessus deviennent indirectement disponibles pour la commande pcp-ss via des variables d'environnement - référez-vous à PCPIntro(1) pour une description complète de ces options.

Les options de ligne de commande supplémentaires disponibles pour pcp-ss lui-même sont :

-h, --help
afficher le message d'aide et quitter
-V, --version
informations sur la version de sortie
-n, --numeric
ne pas résoudre les noms de services (actuellement toujours défini)
-a, --all
afficher tous les sockets
-l, --listening
afficher les sockets en écoute
-o, --options
afficher les informations de temporisation
-e, --extended
afficher les informations détaillées sur les sockets
-m, --memory
afficher l'utilisation de la mémoire des sockets
-i, --info
afficher les informations internes TCP
-4, --ipv4
afficher uniquement les sockets IP version 4
-6, --ipv6
afficher uniquement les sockets IP version 6
-t, --tcp
afficher uniquement les sockets TCP
-u, --udp
afficher uniquement les sockets UDP
-H, --noheader
supprimer la ligne d'en-tête
-O, --oneline
les données du socket sont imprimées sur une seule ligne

RAPPORT

Les colonnes dans le rapport pcp-ss varient en fonction des options de ligne de commande et ont la même interprétation que décrite dans ss(8).

Une différence avec pcp-ss est que la première ligne du rapport commence par '# Horodatage' suivi de l'horodatage (dans le fuseau horaire demandé, voir -z et -Z ci-dessus) des données d'échantillon provenant de l'hôte ou de la source d'archive. Après l'horodatage se trouve la chaîne de filtre actuellement active pour la source de métriques. En mode archive, le filtre actif peut être modifié dynamiquement, même pendant que l'archive est enregistrée. Ceci est différent de ss(8) où le filtre est optionnellement spécifié sur la ligne de commande de l'outil et est toujours 'live', c'est-à-dire que ss(8) ne prend pas en charge la relecture rétrospective. Avec pcp-ss, le filtre est stocké dans le PMDA back-end, voir pmdasockets(1), dans la métrique network.persocket.filter. Le filtre par défaut est state connected, qui peut être changé

pcp-ss(1) — man pages de PCP — Arch Linux

DESCRIPTION

Le PMDA de sockets PCP (Performance Co-Pilot) affiche diverses métriques sur l'état des sockets TCP et UDP.

Par défaut, la métrique network.persocket affiche les informations relatives à tous les sockets présents sur le système. Si le filtre activé par la métrique network.persocket.filter est vide, toutes les informations sur les sockets seront rapportées. Si ce filtre est défini, seules les informations des sockets qui correspondent au filtre seront rapportées.

La métrique network.persocket s'appuie sur les informations provenant du programme ss(8). L'ensemble de la sortie de ss(8) est analysé.

Le filtre pour la métrique network.persocket.filter est stocké dans une valeur de métrique et peut être appliqué en utilisant l'outil pmstore(1). Par exemple, pmstore network.persocket.filter "state established" appliquera un filtre pour ne montrer que les sockets dans l'état « established ». Ceci remplacera le filtre persistant par défaut, qui est stocké dans un fichier de configuration PMDA et chargé à chaque démarrage du PMDA de sockets. Voir pmdasockets(1) pour plus de détails et voir ss(8) pour les détails de la syntaxe du filtre et des exemples.

PCP ENVIRONMENT

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).
