NOM

pcap_findalldevs, pcap_freealldevs - obtenir une liste des périphériques de capture, et libérer cette liste

SYNTAXE

#include <pcap/pcap.h>
char errbuf[PCAP_ERRBUF_SIZE];
int pcap_findalldevs(pcap_if_t **alldevsp, char *errbuf);
void pcap_freealldevs(pcap_if_t *alldevs);

DESCRIPTION

pcap_findalldevs() construit une liste des périphériques réseau qui peuvent être ouverts avec pcap_create(3PCAP) et pcap_activate(3PCAP) ou avec pcap_open_live(3PCAP). (Notez qu'il peut y avoir des périphériques réseau qui ne peuvent pas être ouverts par le processus appelant pcap_findalldevs(), parce que, par exemple, ce processus n'a pas les privilèges suffisants pour les ouvrir pour la capture ; si c'est le cas, ces périphériques n'apparaîtront pas sur la liste.) alldevsp est un pointeur vers un pcap_if_t * ; errbuf est un tampon suffisamment grand pour contenir au moins PCAP_ERRBUF_SIZE caractères.

Si pcap_findalldevs() réussit, le pointeur pointé par alldevsp est mis à jour pour pointer vers le premier élément de la liste, ou vers NULL si aucun périphérique n'a été trouvé (ceci est considéré comme un succès). Chaque élément de la liste est de type pcap_if_t et possède les membres suivants :

next
s'il n'est pas NULL, un pointeur vers l'élément suivant de la liste ; NULL pour le dernier élément de la liste
name
un pointeur vers une chaîne donnant un nom pour le périphérique à passer à pcap_open_live()
description
s'il n'est pas NULL, un pointeur vers une chaîne donnant une description lisible par l'homme du périphérique
addresses
un pointeur vers le premier élément d'une liste d'adresses réseau pour le périphérique, ou NULL si le périphérique n'a pas d'adresses
flags
indicateurs de périphérique :
PCAP_IF_LOOPBACK
défini si le périphérique est une interface de bouclage
PCAP_IF_UP
défini si le périphérique est actif
PCAP_IF_RUNNING
défini si le périphérique est en cours d'exécution
PCAP_IF_WIRELESS
défini si le périphérique est une interface sans fil ; cela inclut IrDA ainsi que les réseaux basés sur les ondes radio comme IEEE 802.15.4 et IEEE 802.11, donc cela ne signifie pas seulement le Wi-Fi
PCAP_IF_CONNECTION_STATUS
un masque de bits indiquant si l'adaptateur est connecté ou non ; pour les interfaces sans fil, « connecté » signifie « associé à un réseau »
Les valeurs possibles pour les bits d'état de connexion sont :
PCAP_IF_CONNECTION_STATUS_UNKNOWN
on ignore si l'adaptateur est connecté ou non
PCAP_IF_CONNECTION_STATUS_CONNECTED
l'adaptateur est connecté
PCAP_IF_CONNECTION_STATUS_DISCONNECTED
l'adaptateur est déconnecté
PCAP_IF_CONNECTION_STATUS_NOT_APPLICABLE
la notion de « connecté » et « déconnecté » ne s'applique pas à cette interface ; par exemple, elle ne s'applique pas à un périphérique de bouclage

Chaque élément de la liste d'adresses est de type pcap_addr_t et possède les membres suivants :

next
s'il n'est pas NULL, un pointeur vers l'élément suivant de la liste ; NULL pour le dernier élément de la liste
addr
un pointeur vers une struct sockaddr contenant une adresse
netmask
s'il n'est pas NULL, un pointeur vers une struct sockaddr qui contient le masque de réseau correspondant à l'adresse pointée par addr
broadaddr
s'il n'est pas NULL, un pointeur vers une struct sockaddr qui contient l'adresse de diffusion correspondante à l'adresse pointée par addr ; peut être NULL si le périphérique ne prend pas en charge les diffusions
dstaddr
s'il n'est pas NULL, un pointeur vers une struct sockaddr qui contient l'adresse de destination correspondante à l'adresse pointée par addr ; peut être NULL si le périphérique n'est pas une interface point à point

Notez que les adresses dans la liste des adresses peuvent être des adresses IPv4, des adresses IPv6, ou un autre type d'adresses, vous devez donc vérifier le membre sa_family de la struct sockaddr avant d'interpréter le contenu de l'adresse ; ne supposez pas que toutes les adresses sont des adresses IPv4, ou même toutes des adresses IPv4 ou IPv6. Les adresses IPv4 ont la valeur AF_INET, les adresses IPv6 ont la valeur AF_INET6 (que les anciens systèmes d'exploitation ne prenant pas en charge IPv6 pourraient ne pas définir), et les autres adresses ont d'autres valeurs. Le retour ou non d'autres adresses, et leurs types, dépendent de la plateforme. Notamment, les adresses de couche lien, comme les adresses MAC Ethernet, ont la valeur AF_PACKET (sous Linux) ou AF_LINK (sous AIX, FreeBSD, Haiku, illumos, macOS, NetBSD et OpenBSD) ou ne sont pas retournées du tout (sous GNU/Hurd et Solaris).

Pour les adresses IPv4, le pointeur struct sockaddr peut être interprété comme pointant vers une struct sockaddr_in ; pour les adresses IPv6, il peut être interprété comme pointant vers une struct sockaddr_in6. Pour les adresses de couche lien, il peut être interprété comme pointant vers une struct sockaddr_ll (pour AF_PACKET) ou une struct sockaddr_dl (pour AF_LINK).

La liste des périphériques doit être libérée avec pcap_freealldevs(3PCAP), qui libère la liste pointée par alldevs.

VALEUR DE RETOUR

pcap_findalldevs() retourne 0 en cas de succès et PCAP_ERROR en cas d'échec ; comme indiqué, ne trouver aucun périphérique est considéré comme un succès, plutôt qu'un échec, donc 0 sera retourné dans ce cas. Si PCAP_ERROR est retourné, errbuf est rempli avec un message d'erreur approprié, et le pointeur pointé par alldevsp est mis à NULL.

COMPATIBILITÉ ASCENDANTE

Les constantes PCAP_IF_UP et PCAP_IF_RUNNING sont disponibles depuis la sortie 1.6.1 de libpcap. Les constantes PCAP_IF_WIRELESS, PCAP_IF_CONNECTION_STATUS, PCAP_IF_CONNECTION_STATUS_UNKNOWN, PCAP_IF_CONNECTION_STATUS_CONNECTED, PCAP_IF_CONNECTION_STATUS_DISCONNECTED et PCAP_IF_CONNECTION_STATUS_NOT_APPLICABLE sont disponibles depuis la sortie 1.9.0 de libpcap.

NOM

pcap_findalldevs, pcap_findalldevs_ex - liste des périphériques d'interface réseau d'un système

SYNOPIS

#include <pcap.h>

char *pcap_lookupdev(char *errbuf);

int pcap_findalldevs(pcap_if_t **alldevs, char *errbuf);

int pcap_findalldevs_ex(const char *source, pcap_matchname_handler callback, void *user, char *errbuf);

void pcap_freealldevs(pcap_if_t *alldevs);

DESCRIPTION

La fonction pcap_findalldevs() construit une liste chaînée de tous les périphériques d'interface réseau disponibles sur le système local, les stocke dans la structure alldevs et retourne le nombre de périphériques trouvés. Si aucun périphérique n'est trouvé, elle retourne 0. Si une erreur se produit, elle retourne -1 et errbuf est rempli d'une chaîne décrivant l'erreur.

La structure pcap_if_t est définie comme suit :

struct pcap_if {
    struct pcap_if *next;       // Pointeur vers le périphérique suivant dans la liste
    char *name;                 // Nom du périphérique
    char *description;          // Description conviviale du périphérique
    struct pcap_addr *addresses; // Liste chaînée des adresses du périphérique
    u_int flags;                // Indicateurs du périphérique (par exemple, PCAP_IF_UP)
};

La fonction pcap_lookupdev() retourne le nom du premier périphérique d'interface réseau "approprié" sur le système local. La notion de "approprié" dépend du système d'exploitation et peut inclure des interfaces actives, des interfaces avec une adresse IP assignée, etc. Si aucun périphérique approprié n'est trouvé, elle retourne NULL.

La fonction pcap_findalldevs_ex() est une version plus avancée qui permet de rechercher des périphériques à partir d'une source spécifique (par exemple, un fichier de traces). Elle utilise un gestionnaire de rappel pour traiter chaque périphérique trouvé.

La fonction pcap_freealldevs() libère la mémoire allouée pour la liste des périphériques retournée par pcap_findalldevs().

VALEUR DE RETOUR

pcap_findalldevs() retourne le nombre de périphériques trouvés, ou -1 en cas d'erreur.

pcap_lookupdev() retourne le nom du périphérique trouvé, ou NULL en cas d'erreur.

pcap_findalldevs_ex() retourne 0 si le traitement s'est déroulé sans erreur, ou -1 en cas d'erreur. La valeur de retour du gestionnaire de rappel détermine si la recherche doit continuer ou s'arrêter.

COMPATIBILITÉ ASCENDANTE

L'utilisation de pcap_lookupdev() est déconseillée au profit de pcap_findalldevs() car cette dernière fournit une liste plus complète d'informations sur les interfaces.
