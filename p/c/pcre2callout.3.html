PCRE2CALLOUT(3) Manuel des fonctions de bibliothèque PCRE2CALLOUT(3)

NOM

PCRE2 - Expressions régulières compatibles Perl (API révisée)

SYNTAXE

#include <pcre2.h>

int (*pcre2_callout)(pcre2_callout_block *, void *);

int pcre2_callout_enumerate(const pcre2_code *code,
  int (*callback)(pcre2_callout_enumerate_block *, void *),
  void *user_data);

DESCRIPTION

PCRE2 offre une fonctionnalité appelée "callout", qui permet de transférer temporairement le contrôle à l'appelant de PCRE2 au milieu de la correspondance de motif. L'appelant de PCRE2 fournit une fonction externe en plaçant son point d'entrée dans un contexte de correspondance (voir pcre2_set_callout() dans la documentation pcre2api).

Lors de l'utilisation de la fonction pcre2_substitute(), une fonctionnalité de callout supplémentaire est disponible. Celle-ci effectue un appel après chaque modification de la chaîne sujette et est décrite dans la documentation pcre2api ; le reste de ce document concerne les callouts pendant la correspondance de motif.

Dans une expression régulière, (?C<arg>) indique un point auquel la fonction externe doit être appelée. Différents points de callout peuvent être identifiés en plaçant un nombre inférieur à 256 après la lettre C. La valeur par défaut est zéro. Alternativement, l'argument peut être une chaîne délimitée. Le délimiteur de départ doit être l'un des caractères ` ' " ^ % # $ { et le délimiteur de fin est le même que celui de début, sauf pour {, où le délimiteur de fin est }. Si le délimiteur de fin est nécessaire dans la chaîne, il doit être doublé. Par exemple, ce motif comporte deux points de callout :


(?C1)abc(?C"some ""arbitrary"" text")def

Si le bit d'option PCRE2_AUTO_CALLOUT est défini lors de la compilation d'un motif, PCRE2 insère automatiquement des callouts, tous numérotés 255, avant chaque élément du motif, sauf juste avant ou après un callout explicite. Par exemple, si PCRE2_AUTO_CALLOUT est utilisé avec le motif


A(?C3)B

il est traité comme s'il s'agissait de


(?C255)A(?C3)B(?C255)

Voici un exemple plus complexe :


A(\d{2}|--)

Avec PCRE2_AUTO_CALLOUT, ce motif est traité comme s'il s'agissait de


(?C255)A(?C255)((?C255)\d{2}(?C255)|(?C255)-(?C255)-(?C255))(?C255)

Notez qu'il y a un callout avant et après chaque parenthèse et chaque barre d'alternance. Si le motif contient un groupe conditionnel dont la condition est une assertion, un callout automatique est inséré juste avant la condition. Un tel callout peut également être inséré explicitement, par exemple :


(?(?C9)(?=a)ab|de) (?(?C%text%)(?!=d)ab|de)

Ceci ne s'applique qu'aux conditions d'assertion (car ce sont elles-mêmes des groupes indépendants).

Les callouts peuvent être utiles pour suivre la progression de la correspondance des motifs. Le programme pcre2test dispose d'un qualificatif de motif (/auto_callout) qui active les callouts automatiques. Lorsque des callouts sont présents, la sortie de pcre2test indique comment le motif est mis en correspondance. Ces informations sont utiles pour optimiser les performances d'un motif particulier.

CALLOUTS MANQUANTS

Vous devez savoir que, en raison des optimisations dans la manière dont PCRE2 compile et fait correspondre les motifs, les callouts ne se produisent parfois pas exactement comme vous pourriez vous y attendre.

Auto-possessification

Au moment de la compilation, PCRE2 "auto-possessifie" les éléments répétés lorsqu'il sait que ce qui suit ne peut pas faire partie de la répétition. Par exemple, a+[bc] est compilé comme s'il s'agissait de a++[bc]. La sortie de pcre2test lorsque ce motif est compilé avec PCRE2_ANCHORED et PCRE2_AUTO_CALLOUT puis appliqué à la chaîne "aaaa" est :


--->aaaa
+0 ^ a+
+2 ^ ^ [bc]
No match

Cela indique que lorsque la correspondance de [bc] échoue, il n'y a pas de retour arrière dans a+ (car il est traité comme a++) et donc les callouts qui seraient déclenchés pour les retours arrière ne se produisent pas. Vous pouvez désactiver la fonctionnalité d'auto-possessification en passant PCRE2_NO_AUTO_POSSESS à pcre2_compile(), ou en commençant le motif par (*NO_AUTO_POSSESS). Dans ce cas, la sortie change comme suit :


--->aaaa
+0 ^ a+
+2 ^ ^ [bc]
+2 ^ ^ [bc]
+2 ^ ^ [bc]
+2 ^^ [bc]
No match

Cette fois, lorsque la correspondance de [bc] échoue, le moteur de correspondance revient en arrière dans a+ et réessaie, de manière répétée, jusqu'à ce que a+ lui-même échoue.

Ancrage automatique de .*

Par défaut, une optimisation est appliquée lorsque .* est le premier élément significatif d'un motif. Si PCRE2_DOTALL est défini, de sorte que le point puisse correspondre à n'importe quel caractère, le motif est automatiquement ancré. Si PCRE2_DOTALL n'est pas défini, une correspondance ne peut commencer qu'après une nouvelle ligne interne ou au début du sujet, et pcre2_compile() s'en souvient. Si un motif comporte plus d'une branche de haut niveau, un ancrage automatique se produit si toutes les branches sont ancrables.

Cependant, cette optimisation est désactivée si .* se trouve dans un groupe atomique ou s'il existe une référence arrière vers le groupe de capture dans lequel il apparaît. Elle est également désactivée si le motif contient (*PRUNE) ou (*SKIP). La présence de callouts ne l'affecte pas.

Par exemple, si le motif .*\d est compilé avec PCRE2_AUTO_CALLOUT et appliqué à la chaîne "aa", la sortie de pcre2test est :


--->aa
+0 ^ .*
+2 ^ ^ \d
+2 ^^ \d
+2 ^ \d
No match

Cela montre que toutes les tentatives de correspondance commencent au début du sujet. En d'autres termes, le motif est ancré. Vous pouvez désactiver cette optimisation en passant PCRE2_NO_DOTSTAR_ANCHOR à pcre2_compile(), ou en commençant le motif par (*NO_DOTSTAR_ANCHOR). Dans ce cas, la sortie change comme suit :


--->aa
+0 ^ .*
+2 ^ ^ \d
+2 ^^ \d
+2 ^ \d
+0 ^ .*
+2 ^^ \d
+2 ^ \d
No match

Cela montre davantage de tentatives de correspondance, commençant au deuxième caractère du sujet. Une autre optimisation, décrite dans la section suivante, signifie qu'il n'y aura pas de tentative ultérieure de correspondance avec un sujet vide.

Autres optimisations

D'autres optimisations qui fournissent des résultats rapides de "non correspondance" affectent également les callouts. Par exemple, si le motif est


ab(?C4)cd

PCRE2 sait que toute chaîne correspondante doit contenir la lettre "d". Si la chaîne sujette est "abyz", l'absence de "d" signifie que la correspondance ne commence jamais, et le callout n'est jamais atteint. Cependant, avec "abyd", bien que le résultat soit toujours une non-correspondance, le callout est respecté.

Pour la plupart des motifs, PCRE2 connaît également la longueur minimale d'une chaîne correspondante et donnera immédiatement un retour "non correspondance" sans exécuter réellement une correspondance si le sujet n'est pas assez long, ou, pour les motifs non ancrés, s'il a été scanné suffisamment loin.

Vous pouvez désactiver ces optimisations en passant l'option PCRE2_NO_START_OPTIMIZE à pcre2_compile(), ou en commençant le motif par (*NO_START_OPT). Cela ralentit le processus de correspondance, mais garantit que les callouts, comme celui de l'exemple ci-dessus, sont respectés.

INTERFACE DU CALLOUT

Pendant la correspondance, lorsque PCRE2 atteint un point de callout, si une fonction externe est fournie dans le contexte de correspondance, elle est appelée. Ceci s'applique aux correspondances normales, DFA et JIT. Le premier argument de la fonction de callout est un pointeur vers un bloc pcre2_callout. Le second argument est la donnée de callout void * qui a été fournie lors de la configuration du callout en appelant pcre2_set_callout() (voir la documentation pcre2api). La structure du bloc de callout contient les champs suivants, pas nécessairement dans cet ordre :


uint32_t version;
uint32_t callout_number;
uint32_t capture_top;
uint32_t capture_last;
uint32_t callout_flags;
PCRE2_SIZE *offset_vector;
PCRE2_SPTR mark;
PCRE2_SPTR subject;

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

PCRE2_SIZE subject_length;
PCRE2_SIZE start_match;
PCRE2_SIZE current_position;
PCRE2_SIZE pattern_position;
PCRE2_SIZE next_item_length;
PCRE2_SIZE callout_string_offset;
PCRE2_SIZE callout_string_length;
PCRE2_SPTR callout_string;

Le champ version contient le numéro de version du format de bloc. La version actuelle est 2 ; les trois champs de chaîne de rappel ont été ajoutés pour la version 1, et le champ callout_flags pour la version 2. Si vous écrivez une application qui pourrait utiliser une version antérieure de PCRE2, vous devez vérifier le numéro de version avant d'accéder à l'un de ces champs. Le numéro de version augmentera à l'avenir si d'autres champs sont ajoutés, mais l'intention est de ne jamais supprimer aucun des champs existants.

Champs pour les appels numériques

Pour un appel numérique, callout_string est NULL, et callout_number contient le numéro de l'appel, dans la plage 0-255. C'est le nombre qui suit (?C pour les appels qui font partie du motif ; il est de 255 pour les appels générés automatiquement.

Champs pour les appels par chaîne

Pour les appels avec des arguments de chaîne, callout_number est toujours zéro, et callout_string pointe vers la chaîne contenue dans le motif compilé. Sa longueur est donnée par callout_string_length. Les délimiteurs de fin dupliqués présents dans le motif d'origine ont été transformés en caractères uniques, mais il n'y a aucun autre traitement de l'argument de chaîne de rappel. Une unité de code supplémentaire contenant un zéro binaire est présente après la chaîne, mais n'est pas incluse dans la longueur. Le délimiteur utilisé pour commencer la chaîne est également stocké dans le motif, juste avant la chaîne elle-même. Vous pouvez y accéder comme callout_string[-1] si nécessaire.

Le champ callout_string_offset est le décalage de l'unité de code vers le début de la chaîne d'argument de rappel dans le motif d'origine. Ceci est fourni pour les applications telles que les langages de script qui pourraient avoir besoin de signaler des erreurs dans la chaîne de rappel dans le motif.

Champs pour tous les appels

Les champs restants dans le bloc de rappel sont les mêmes pour les deux types d'appels.

Le champ offset_vector est un pointeur vers un vecteur d'offsets de capture (l'"ovector"). Vous pouvez lire les éléments de ce vecteur, mais vous ne devez pas en modifier aucun.

Pour les appels à pcre2_match(), le champ offset_vector n'est pas (depuis la version 10.30) un pointeur vers l'ovector réel qui a été passé à la fonction de correspondance dans le bloc de données de correspondance. Il pointe plutôt vers un ovector interne d'une taille suffisante pour contenir toutes les sous-chaînes capturées possibles dans le motif. Notez que chaque fois qu'une récursion ou un appel de sous-motif dans un motif se termine, l'état de capture est réinitialisé à ce qu'il était auparavant.

Le champ capture_last contient le numéro de la sous-chaîne capturée la plus récente, et le champ capture_top contient un de plus que le numéro de la sous-chaîne capturée la plus haute jusqu'à présent. Si aucune sous-chaîne n'a encore été capturée, la valeur de capture_last est 0 et la valeur de capture_top est 1. Les valeurs de ces champs ne diffèrent pas toujours d'un, par exemple, lorsque le rappel dans le motif ((a)(b))(?C2) est pris, capture_last est 1 mais capture_top est 4.

Le contenu de ovector[2] à ovector[<capture_top>*2-1] peut être inspecté afin d'extraire les sous-chaînes qui ont été mises en correspondance jusqu'à présent, de la même manière que l'extraction des sous-chaînes après qu'une correspondance a été terminée. Les valeurs dans ovector[0] et ovector[1] sont toujours PCRE2_UNSET car la correspondance n'est par définition pas terminée. Les sous-chaînes qui n'ont pas été capturées mais dont les numéros sont inférieurs à capture_top ont également leurs deux emplacements ovector définis sur PCRE2_UNSET.

Pour la correspondance DFA, le champ offset_vector pointe vers l'ovector qui a été passé à la fonction de correspondance dans le bloc de données de correspondance pour les appels au niveau supérieur, mais vers un ovector interne lors du traitement des récursions de motif, des lookarounds et des groupes atomiques. Cependant, ces ovectors ne contiennent aucune information utile car pcre2_dfa_match() ne prend pas en charge la capture de sous-chaînes. La valeur de capture_top est toujours 1 et la valeur de capture_last est toujours 0 pour la correspondance DFA.

Les champs subject et subject_length contiennent des copies des valeurs qui ont été passées à la fonction de correspondance.

Le champ start_match contient normalement le décalage dans le sujet où la tentative de correspondance actuelle a commencé. Cependant, si la séquence d'échappement \K a été rencontrée, cette valeur est modifiée pour refléter le point de départ modifié. Si le motif n'est pas ancré, la fonction de rappel peut être appelée plusieurs fois à partir du même point dans le motif pour différents points de départ dans le sujet.

Le champ current_position contient le décalage dans le sujet du pointeur de correspondance actuel.

Le champ pattern_position contient le décalage dans la chaîne de motif de l'élément suivant à faire correspondre.

Le champ next_item_length contient la longueur de l'élément suivant à traiter dans la chaîne de motif. Lorsque le rappel est à la fin du motif, la longueur est zéro. Lorsque le rappel précède une parenthèse ouvrante, la longueur inclut les méta-caractères qui suivent la parenthèse. Par exemple, dans un appel avant une assertion telle que (?=ab), la longueur est de 3. Pour une barre d'alternance ou une parenthèse fermante, la longueur est d'un, sauf si une parenthèse fermante est suivie d'un quantificateur, auquel cas sa longueur est incluse. (Cela a changé dans la version 10.23. Dans les versions précédentes, avant une parenthèse ouvrante, la longueur était celle de tout le groupe, et avant une barre d'alternance ou une parenthèse fermante, la longueur était zéro.)

Les champs pattern_position et next_item_length sont destinés à aider à distinguer les différents appels automatiques, qui ont tous le même numéro d'appel. Cependant, ils sont définis pour tous les appels, et sont utilisés par pcre2test pour afficher l'élément suivant à faire correspondre lors de l'affichage des informations d'appel.

Dans les appels de pcre2_match(), le champ mark contient un pointeur vers le nom terminé par zéro de l'élément le plus récemment passé (*MARK), (*PRUNE), ou (*THEN) dans la correspondance, ou NULL si aucun de ces éléments n'a été passé. Les instances de (*PRUNE) ou (*THEN) sans nom n'effacent pas un (*MARK) précédent. Dans les appels de la fonction de correspondance DFA, ce champ contient toujours NULL.

Le champ callout_flags est toujours zéro dans les appels de pcre2_dfa_match() ou lorsque JIT est utilisé. Lorsque pcre2_match() est utilisé sans JIT, les bits suivants peuvent être définis :


PCRE2_CALLOUT_STARTMATCH

Ceci est défini pour le premier appel après le début de la correspondance pour chaque nouvelle position de départ dans le sujet.


PCRE2_CALLOUT_BACKTRACK

Ceci est défini s'il y a eu un retour arrière de correspondance depuis l'appel précédent, ou depuis le début de la correspondance si c'est le premier appel d'une exécution pcre2_match().

Les deux bits sont définis lorsqu'un retour arrière a provoqué un "bumpalong" vers une nouvelle position de départ dans le sujet. La sortie de pcre2test n'indique pas la présence de ces bits à moins que le modificateur callout_extra ne soit défini.

Les informations contenues dans le champ callout_flags sont fournies afin que les applications puissent suivre et informer leurs utilisateurs de la manière dont la correspondance avec retour arrière est effectuée. Cela peut être utile lors de l'optimisation des motifs, ou simplement pour comprendre le fonctionnement de PCRE2. Il n'y a pas de support dans pcre2_dfa_match() car il n'y a pas de retour arrière dans la correspondance DFA, et il n'y a pas de support dans JIT car JIT vise à maximiser les performances de correspondance. Dans ces deux cas, le champ callout_flags est toujours zéro.

VALEURS DE RETOUR DES APPELS

La fonction de rappel externe retourne un entier à PCRE2. Si la valeur est zéro, la correspondance continue normalement. Si la valeur est supérieure à zéro, la correspondance échoue au point actuel, mais le test d'autres possibilités de correspondance se poursuit, tout comme si une assertion de lookahead avait échoué. Si la valeur est inférieure à zéro, la correspondance est abandonnée et la fonction de correspondance retourne la valeur négative.

Les valeurs négatives doivent normalement être choisies parmi l'ensemble des valeurs PCRE2_ERROR_xxx. En particulier, PCRE2_ERROR_NOMATCH force un échec standard de type "aucune correspondance". Le numéro d'erreur PCRE2_ERROR_CALLOUT est réservé à l'usage des fonctions de rappel ; il ne sera jamais utilisé par PCRE2 lui-même.

ENUMÉRATION DES APPELS

int pcre2_callout_enumerate(const pcre2_code *code,
  int (*callback)(pcre2_callout_enumerate_block *, void *),
  void *user_data);

Un langage de script qui prend en charge l'utilisation d'arguments de chaîne dans les appels pourrait vouloir scanner tous les appels dans un motif avant d'exécuter la correspondance. Ceci peut être fait en appelant pcre2_callout_enumerate(). Le premier argument est un pointeur vers un motif compilé, le second pointe vers une fonction de rappel, et le troisième est des données utilisateur arbitraires. La fonction de rappel est appelée pour chaque appel dans le motif, dans l'ordre où ils apparaissent. Son premier argument est un pointeur vers un bloc d'énumération d'appels, et son second argument est la valeur user_data passée à pcre2_callout_enumerate(). Le bloc de données contient les champs suivants :


version Numéro de version du bloc
pattern_position Décalage vers l'élément suivant dans le motif
next_item_length Longueur de l'élément suivant dans le motif
callout_number Numéro pour les appels numérotés
callout_string_offset Décalage vers la chaîne dans le motif
callout_string_length Longueur de la chaîne de rappel
callout_string Pointeur vers la chaîne de rappel ou est NULL

Le numéro de version est actuellement 0. Il augmentera si de nouveaux champs sont ajoutés au bloc. Les champs restants sont identiques à leurs homologues dans le bloc pcre2_callout utilisé pour les appels pendant la correspondance, comme décrit ci-dessus.

Notez que la valeur de pattern_position est unique pour chaque appel. Cependant, si un appel se produit à l'intérieur d'un groupe quantifié avec un minimum non nul ou un maximum fixe, le groupe est répliqué à l'intérieur du motif compilé

NOM

pcre2callout - interface de rappel PCRE2

SYNOPSIS

#include <pcre2.h>

int pcre2_callout_enumerate(pcre2_code *code,
    int (*callback)(int, void *), void *data);

DESCRIPTION

Cette fonction énumère toutes les fonctionnalités d'appel de rappel définies dans un motif PCRE2 compilé. Le motif doit avoir été compilé avec l'option PCRE2_CALLOUT activée. La fonction passe l'index de chaque appel de rappel et les données fournies par l'utilisateur à la fonction de rappel spécifiée. La fonction de rappel est appelée pour chaque appel de rappel dans le motif. L'index de l'appel de rappel est passé en premier argument à la fonction de rappel, et les données fournies par l'utilisateur sont passées en deuxième argument. La fonction de rappel doit normalement retourner zéro. Si elle retourne une valeur non nulle, la recherche du motif s'arrête et cette valeur est retournée par pcre2_callout_enumerate().

Si le motif compilé contient des appels de rappel qui ne sont pas réellement exécutés (par exemple, un appel de rappel dans une branche d'alternative qui n'est pas prise), ils ne seront pas énumérés par cette fonction. Si le motif compilé contient des groupes capturants répétés, comme /(a){2}/, cela est compilé comme si c'était /(a)(a)/. Cela signifie que l'appel de rappel sera énuméré plus d'une fois, mais avec la même valeur pour pattern_position dans chaque cas.

CALLOUTS MANQUANTS

Si le motif compilé contient des appels de rappel qui ne sont pas réellement exécutés (par exemple, un appel de rappel dans une branche d'alternative qui n'est pas prise), ils ne seront pas énumérés par cette fonction.

L'INTERFACE DE RAPPEL

L'interface de rappel est définie comme suit :

int callback(int reason, void *data);

Où reason est un entier indiquant la raison pour laquelle le rappel est appelé. Les valeurs possibles pour reason sont :

PCRE2_CALLOUT_MATCH
Un appel de rappel a été atteint pendant la correspondance d'un motif.
PCRE2_CALLOUT_REPLACE
Un appel de rappel a été atteint pendant le remplacement d'un motif.
PCRE2_CALLOUT_SEARCH
Un appel de rappel a été atteint pendant la recherche d'un motif.

Le pointeur data pointe vers la structure pcre2_callout_data, qui contient des informations supplémentaires sur le contexte du rappel.

VALEURS DE RETOUR DES RAPPELS

La fonction de rappel doit normalement retourner zéro. Si elle retourne une valeur non nulle, le traitement de la chaîne s'arrête et cette valeur est retournée par la fonction PCRE2 appelée (par exemple, pcre2_match() ou pcre2_replace()).

ENUMÉRATION DES RAPPELS

L'exemple suivant montre comment utiliser pcre2_callout_enumerate() :

#include <stdio.h>
#include <string.h>
#include <pcre2.h>

static int my_callback(int reason, void *data) {
    pcre2_callout_data *callout_data = (pcre2_callout_data *)data;
    if (reason == PCRE2_CALLOUT_MATCH) {
        printf("Callout reached at offset %d\n", callout_data->pattern_offset);
    }
    return 0; // Continue matching
}

int main() {
    pcre2_code *re;
    PCRE2_SPTR pattern = (PCRE2_SPTR) "\\K(abc)(def)";
    int errorcode;
    PCRE2_SIZE erroroffset;
    const char *text = "xyzabcdefghi";

    re = pcre2_compile(pattern, PCRE2_ZERO_TERMINATED, PCRE2_CALLOUT,
                       &errorcode, &erroroffset, NULL);
    if (re == NULL) {
        fprintf(stderr, "PCRE2 compilation failed at offset %zu: %d\n",
                erroroffset, errorcode);
        return 1;
    }

    pcre2_callout_enumerate(re, my_callback, NULL);

    // Now perform a match to see the callback in action
    pcre2_match_data *match_data = pcre2_match_data_create_from_pattern(pattern, re);
    int rc = pcre2_match(re, (PCRE2_SPTR)text, strlen(text), 0, 0, match_data, NULL);
    if (rc < 0) {
        fprintf(stderr, "PCRE2 match failed: %d\n", rc);
        pcre2_match_data_free(match_data);
        pcre2_code_free(re);
        return 1;
    }
    pcre2_match_data_free(match_data);
    pcre2_code_free(re);
    return 0;
}

L'exemple ci-dessus définit une fonction de rappel nommée my_callback qui est appelée chaque fois qu'un appel de rappel est rencontré dans le motif compilé. La fonction de rappel imprime l'offset du motif où le rappel a été atteint. Ensuite, le motif est compilé avec PCRE2_CALLOUT activé. La fonction pcre2_callout_enumerate() est appelée pour énumérer les appels de rappel et les imprimer. Enfin, une correspondance est effectuée sur la chaîne de texte pour démontrer l'appel de rappel en action.

Notez que si un groupe capturant est répété, tel que /(a){2}/, il est compilé comme s'il s'agissait de /(a)(a)/. Cela signifie que l'appel de rappel sera énuméré plus d'une fois, mais avec la même valeur pour pattern_position dans chaque cas.

La fonction de rappel doit normalement retourner zéro. Si elle retourne une valeur non nulle, la recherche du motif s'arrête et cette valeur est retournée par pcre2_callout_enumerate().
