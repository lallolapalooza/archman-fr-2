PCP2JSON(1) Manuel des commandes générales PCP2JSON(1)

NOM

pcp2json - exportateur de métriques pcp vers json

SYNTAXE

pcp2json [-5CEGHIjLmnrRvVxXz?] [-4 action] [-8|-9 limite] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c config] [--container conteneur] [-D débogage] [--daemonize] [-e dérivé] [-f format] [-F fichier-sortie] [-h hôte] [-i instances] [-J rang] [-K spécification] [-N prédicat] [-o délai] [-O origine] [-p mot-de-passe] [-P|-0 précision] [-q|-Q échelle-compte] [-s échantillons] [-S heure-début] [-t intervalle] [-T heure-fin] [-u url] [-U nom-utilisateur] [-y|-Y échelle-temps] [-Z fuseau-horaire] spécification-métrique [...]

DESCRIPTION

pcp2json est un outil personnalisable d'exportation de métriques de performance de PCP vers JSON. Toute métrique de performance disponible, en direct ou archivée, système et/ou application, peut être sélectionnée pour l'exportation en utilisant soit les options de la ligne de commande, soit un fichier de configuration.

pcp2json est un parent proche de pmrep(1). Se référer à pmrep(1) pour la description de metricspec acceptée sur la ligne de commande de pcp2json. Voir pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2json.conf. Cette page décrit les options spécifiques à pcp2json et les différences de fichier de configuration avec pmrep.conf(5). pmrep(1) liste également quelques exemples d'utilisation dont la plupart sont également applicables à pcp2json.

Seules les options de ligne de commande listées sur cette page sont prises en charge, les autres options disponibles pour pmrep(1) ne sont pas prises en charge.

Les options via les valeurs d'environnement (voir pmGetOptions(3)) écrasent les valeurs par défaut intégrées correspondantes (le cas échéant). Les options du fichier de configuration écrasent les variables d'environnement correspondantes (le cas échéant). Les options de ligne de commande écrasent les options du fichier de configuration correspondantes (le cas échéant).

FICHIER DE CONFIGURATION

pcp2json utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf : version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. Le reste des options de pmrep.conf est reconnu mais ignoré pour des raisons de compatibilité.

options spécifiques à pcp2json

extended (booléen)

Écrit des informations étendues sur les métriques. L'option correspondante de la ligne de commande est -x. Par défaut à non.

everything (booléen)

Écrit tout ce qui est connu des métriques, y compris les identifiants internes de PCP. Les étiquettes sont cependant omises pour des raisons de compatibilité descendante. Activez include_labels pour les inclure également. L'option correspondante de la ligne de commande est -X. Par défaut à non.

exact_types (booléen)

Écrit les nombres comme des types de données numériques, et non comme des chaînes de caractères, perdant potentiellement une partie de la précision. L'option correspondante de la ligne de commande est -E. Par défaut à non.

url (chaîne)

Envoie la sortie JSON sous forme de POST HTTP à l'URL url donnée. L'option correspondante de la ligne de commande est -u. Par défaut à None.

http_pass (chaîne)

Utilise le mot de passe donné pour l'authentification de base lors de l'envoi d'un POST HTTP. L'option correspondante de la ligne de commande est -p. Par défaut à None.

http_user (chaîne)

Utilise le nom d'utilisateur donné pour l'authentification de base lors de l'envoi d'un POST HTTP. L'option correspondante de la ligne de commande est -U. Par défaut à None.

http_timeout (nombre)

Temps maximum (en secondes) lors de l'envoi d'un POST HTTP. L'option correspondante de la ligne de commande est -o. Par défaut à 2.5 secondes.

OPTIONS

Les options de ligne de commande disponibles sont :

-0 précision, --precision-force=précision
Comme -P mais cette option écrasera les spécifications par métrique.
-4 action, --names-change=action
Spécifie quelle action entreprendre lors de la réception d'un événement de changement de nom de métrique pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques après son démarrage et informe les outils clients en cours d'exécution comme pcp2json. Les valeurs valides pour action sont update (rafraîchir les métriques échantillonnées), ignore (ne rien faire - le comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignore-unknown
Ignore silencieusement tout nom de métrique qui ne peut pas être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-8 limite, --limit-filter=limite
Limite les résultats aux instances dont les valeurs sont supérieures/inférieures à la limite. Un entier positif inclura les instances dont les valeurs sont égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances dont les valeurs sont égales ou inférieures à la limite dans le rapport. Une valeur nulle n'effectue aucun filtrage par limite. Cette option n'écrasera pas les spécifications possibles par métrique. Voir aussi -J et -N.
-9 limite, --limit-filter-force=limite
Comme -8 mais cette option écrasera les spécifications par métrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Force le premier échantillon à être aligné sur la limite d'une unité de temps naturelle alignement. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe pour alignement.
--archive-folio=folio
Lit les archives sources de métriques à partir du folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b échelle, --space-scale=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, etc. Cette option n'écrasera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-B échelle, --space-scale-force=échelle
Comme -b mais cette option écrasera les spécifications par métrique.
-c config, --config=config
Spécifie le fichier ou répertoire config à utiliser. Si config est un répertoire, tous les fichiers se terminant par .conf seront inclus. Le défaut est le premier trouvé parmi : ./pcp2json.conf, $HOME/.pcp2json.conf, $HOME/pcp/pcp2json.conf, et $PCP_SYSCONF_DIR/pcp2json.conf. Pour plus de détails, voir la section ci-dessus et pmrep.conf(5).
--container=conteneur
Récupère les métriques de performance du conteneur spécifié, local ou à distance (voir -h).
-C, --check
Quitte avant de signaler des valeurs, mais après avoir analysé la configuration et les métriques, et imprimé les en-têtes possibles.
--daemonize
Se daemonise au démarrage.
-e dérivé, --derived=dérivé
Spécifie les métriques de performance dérivées. Si dérivé commence par une barre oblique (``/'') ou par un point (``.''), il sera interprété comme un fichier de configuration de métriques dérivées PCP ; sinon, il sera interprété comme des expressions de métriques dérivées séparées par des virgules ou des points-virgules. Pour une description complète des métriques dérivées et des fichiers de configuration de métriques dérivées PCP, voir pmLoadDerivedConfig(3) et pmRegisterDerived(3). Alternativement, l'utilisation de la syntaxe de configuration pmrep.conf(5) permet de définir des métriques dérivées dans le cadre des jeux de métriques.

En cas de problèmes avec les métriques dérivées, consultez en détail les pages de manuel susmentionnées et assurez-vous que toutes les métriques requises sont disponibles, en particulier lors de l'utilisation d'archives. Utilisez -Dderive pour voir des informations de débogage supplémentaires sur l'analyse des métriques dérivées.

-E, --exact-types
Écrit les nombres sous forme de types de données numériques, et non de chaînes de caractères, ce qui peut entraîner une perte de précision.
-f format, --timestamp-format=format
Utilise la chaîne de format pour formater l'horodatage. Le format sera utilisé avec la méthode datetime.strftime de Python, qui est très similaire à celle décrite dans strftime(3). Le format par défaut est %Y-%m-%d %H:%M:%S.
-F fichier_sortie, --output-file=fichier_sortie
Spécifie le fichier de sortie fichier_sortie.
-G, --no-globals
N'inclut pas les métriques globales dans le rapport (voir pmrep.conf(5)).
-h hôte, --host=hôte
Récupère les métriques de performance depuis pmcd(1) sur hôte, plutôt que depuis localhost par défaut.
-H, --no-header
N'imprime aucun en-tête.
-i instances, --instances=instances
Récupère et rapporte uniquement les instances de métriques spécifiées. Par défaut, toutes les instances, présentes et futures, sont rapportées.

Reportez-vous à pmrep(1) pour une description complète de cette option.

-I, --ignore-incompat
Ignore les métriques incompatibles. Par défaut, les métriques incompatibles (c'est-à-dire dont le type n'est pas pris en charge ou qui ne peuvent pas être mises à l'échelle comme demandé) entraîneront l'arrêt de pcp2json avec un message d'erreur. Avec cette option, toutes les métriques incompatibles sont silencieusement omises du rapport. Cela peut être particulièrement utile lors de la demande de nœuds non feuilles de l'arbre PMNS pour le rapport.
-j, --live-filter
Effectue un filtrage en direct des instances. Cela permet de capturer toutes les instances nommées même si des processus sont redémarrés à un moment donné (contrairement à l'absence de filtrage en direct). L'exécution du filtrage en direct sur un grand nombre d'instances entraînera une surcharge interne, une certaine prudence de la part de l'utilisateur est donc conseillée. Voir également -n.
-J rang, --rank=rang
Limite les résultats aux instances les mieux/moins bien classées de métriques à valeurs multiples. Un entier positif inclura les instances les mieux classées dans le rapport. Un entier négatif inclura les instances les moins bien classées dans le rapport. Une valeur de zéro n'effectue aucun classement. Le classement n'implique pas de tri, voir -6. Voir également -8.
-K spécification, --spec-local=spécification
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spécification est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peut être utilisée.
-L, --local-PMDA
Utilise un contexte local pour collecter les métriques des PMDA DSO sur l'hôte local sans PMCD. Voir également -K.
-n, --invert-filter
Effectue le classement avant le filtrage en direct. Par défaut, le filtrage en direct des instances (lorsqu'il est demandé, voir -j) se produit avant le classement des instances (lorsqu'il est demandé, voir -J). Avec cette option, la logique est inversée et le classement se produit avant le filtrage en direct.
-m, --include-labels
Inclut les étiquettes de métriques PCP dans la sortie.
-N prédicat, --predicate=prédicat
Spécifie une liste de métriques de référence de filtre prédicat séparées par des virgules. Par défaut, le classement (voir -J) est effectué pour chaque métrique individuellement. Avec des prédicats, le classement n'est effectué que pour les métriques prédicats spécifiées. Lors du rapport, les autres métriques partageant le même domaine d'instance (voir PCPIntro(1)) que le prédicat incluront uniquement les instances les mieux/moins bien classées du prédicat correspondant. Le classement n'implique pas de tri, voir -6.

Ainsi, par exemple, en utilisant proc.memory.rss (taille de la mémoire résidente du processus) comme métrique prédicat, ainsi que proc.io.total_bytes et mem.util.used comme métriques à rapporter, seuls les processus utilisant le plus/moins (selon -J) de mémoire seront inclus lors du rapport des octets totaux écrits par les processus. Étant donné que mem.util.used est une métrique à valeur unique (et ne partage donc pas le même domaine d'instance que les métriques liées aux processus), elle sera rapportée comme d'habitude.

-o, --http-timeout
Délai d'attente (en secondes) lors de l'envoi d'un POST HTTP avec l'option -u. La valeur par défaut est 2,5 secondes.
-O origine, --origin=origine
Lors du rapport des métriques archivées, le rapport commencera à origine dans la fenêtre temporelle (voir -S et -T). Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de origine.
-p, --http-pass
Mot de passe lors de l'utilisation de l'authentification de base HTTP avec l'option -u.
-P précision, --precision=précision
Utilise la précision pour les valeurs de sortie numériques non entières. La valeur par défaut est de 3 décimales (lorsque applicable). Cette option n'annulera pas les spécifications possibles par métrique.
-q échelle, --count-scale=échelle
Unité/échelle pour les métriques de comptage, les valeurs possibles incluent count x 10^-1, count, count x 10, count x 10^2, et ainsi de suite de 10^-8 à 10^7. (Ces valeurs sont actuellement sensibles aux espaces.) Cette option n'annulera pas les spécifications possibles par métrique. Voir également pmParseUnitsStr(3).
-Q échelle, --count-scale-force=échelle
Similaire à -q, mais cette option annulera les spécifications par métrique.
-r, --raw
Sortie des valeurs brutes des métriques, ne convertit pas les compteurs cumulatifs en taux. Cette option annulera les spécifications possibles par métrique.
-R, --raw-prefer
Similaire à -r, mais cette option n'annulera pas les spécifications par métrique.
-s échantillons, --samples=échantillons
L'argument échantillons définit le nombre d'échantillons à récupérer et à rapporter. Si échantillons est 0 ou si -s n'est pas spécifié, pcp2json échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive). Voir également -T.
-S heure_début, --start=heure_début
Lors du rapport des métriques archivées, le rapport sera limité aux enregistrements datant d'au moins heure_début. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de heure_début.
-t intervalle, --interval=intervalle
Définit l'intervalle de rapport sur une valeur autre que la seconde par défaut. L'argument intervalle suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes). Voir également l'option -T.
-T heure_fin, --finish=heure_fin
Lors du rapport des métriques archivées, le rapport sera limité aux enregistrements datant d'avant ou à heure_fin. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de heure_fin.

Lorsqu'utilisé pour définir le temps d'exécution avant que pcp2json ne quitte, si aucun échantillons n'est donné (voir -s), le nombre d'échantillons rapportés dépend de l'intervalle (voir -t). Si des échantillons sont donnés, l'intervalle sera ajusté pour permettre le rapport de échantillons pendant le temps d'exécution. Dans le cas où -T, -s, et -t sont tous donnés, heure_fin déterminera le temps réel pendant lequel pcp2json s'exécutera.

-u, --url
URL pour envoyer un POST HTTP (au lieu de la sortie standard par défaut).
-U, --http-user
Nom d'utilisateur lors de l'utilisation de l'authentification de base HTTP avec l'option -u.
-v, --omit-fl
pcp2json(1) — Page de manuel PCP

NAME

pcp2json — transformer la sortie de pmrep en JSON

SYNOPSIS

pcp2json [-a | -h ] [-c config ] [-D flag ] [-e ] [-f ] [-F ] [-i ] [-I ] [-k ] [-K subset ] [-l logalign ] [-m ] [-n pmns_file ] [-O fmt ] [-P precision ] [-q ] [-s samples ] [-S start_time ] [-t interval ] [-T end_time ] [-u ] [-U time_units ] [-V ] [-x ] [-X ] [-y scale ] [-Y scale ] [-z ] [-Z timezone ] [metric ... ]

DESCRIPTION

pcp2json est un utilitaire qui permet de convertir la sortie de pmrep en format JSON. Il lit les métriques spécifiées par l'argument metric (ou toutes les métriques si aucun argument n'est fourni) depuis un système distant ou un fichier d'archive, et les formate en une structure JSON. Les options de pcp2json sont largement compatibles avec celles de pmrep.

Le format JSON produit est structuré pour représenter les métriques et leurs valeurs au fil du temps, ce qui le rend utile pour l'intégration avec d'autres applications ou services qui consomment des données JSON.

CONFIGURATION FILE

Le comportement de pcp2json peut être configuré à l'aide d'un fichier de configuration spécifié par l'option -c. Ce fichier peut contenir des paramètres pour personnaliser le format de sortie, les métriques à inclure, et d'autres options de comportement.

Les fichiers de configuration par défaut fournis par le système sont situés dans $PCP_SYSCONF_DIR/pmrep/.

OPTIONS

-a archive
Spécifie le nom du fichier d'archive des métriques à lire. Si cette option est utilisée, les métriques sont lues à partir de l'archive spécifiée plutôt que d'un système distant.
-c config
Spécifie le chemin d'accès au fichier de configuration à utiliser pour personnaliser le comportement de pcp2json.
-D flag
Active les options de débogage spécifiées par flag. Voir la section DEBUGGING OPTIONS pour plus de détails.
-e
Ne rapportez que les métriques qui sont des valeurs multiples avec des instances (par exemple, disk.dev.read) et omettez les métriques « plates » à valeur unique sans instances (par exemple, kernel.all.sysfork). Voir -i et -I.
-f
Forcer l'utilisation des identifiants numériques des métriques plutôt que de leurs noms textuels. Ceci est utile pour garantir la compatibilité lorsque les noms des métriques peuvent changer.
-F
Filtre les métriques pour n'inclure que celles dont la valeur a changé depuis la dernière fois qu'elles ont été rapportées. Utile pour réduire la quantité de données rapportées lorsque la plupart des métriques restent stables.
-i
Inclure les noms des instances pour les métriques à valeur multiple. Par exemple, pour disk.dev.read, cela pourrait inclure des instances comme sda, sdb, etc.
-I
Inclure tous les identifiants des instances pour les métriques. Cela inclut les identifiants numériques bruts des instances, en plus de leurs noms symboliques.
-k
Ne rapportez que les métriques qui sont des valeurs simples sans instances (par exemple, kernel.all.sysfork) et omettez les métriques à valeur multiple avec des instances (par exemple, disk.dev.read). Ceci est l'inverse de l'option -e.
-K subset
Ne rapportez que les métriques appartenant au sous-ensemble spécifié par subset. Le nom du sous-ensemble est une chaîne de caractères qui peut contenir des métriques séparées par des virgules, des jokers ou des noms de fichiers contenant des métriques.
-l logalign
Définit la largeur de champ pour l'alignement des logs. Ceci est utile pour formater la sortie de manière lisible, en particulier lorsque vous travaillez avec des noms de métriques longs.
-m
Inclure les étiquettes (labels) pour les métriques. Les étiquettes fournissent des informations supplémentaires sur une métrique, comme son unité ou sa description.
-n pmns_file
Utiliser pmns_file pour le fichier PMNS (Performance Metrics Namespace). Cela permet de spécifier un fichier PMNS personnalisé pour résoudre les noms des métriques.
-O fmt
Spécifie le format de sortie. Les valeurs possibles pour fmt sont : json, flat, table, csv, tree, text.
-P precision
Définit le nombre de chiffres après la virgule pour l'affichage des nombres à virgule flottante. Utile pour contrôler la précision de la sortie numérique.
-q
Ne rapportez que les métriques qui sont des valeurs simples sans instances (par exemple, kernel.all.sysfork) et omettez les métriques à valeur multiple avec des instances (par exemple, disk.dev.read). C'est l'inverse de l'option -e.
-s samples
Spécifie le nombre d'échantillons à collecter. Si non spécifié, pcp2json continuera à collecter des échantillons jusqu'à ce qu'il soit arrêté manuellement.
-S start_time
Spécifie l'heure de début de la collecte des métriques. L'heure peut être spécifiée dans divers formats, y compris des timestamps Unix ou des chaînes lisibles par l'homme.
-t interval
Spécifie l'intervalle de temps entre chaque échantillon de métrique. L'intervalle peut être spécifié en secondes, minutes, heures, etc. (par exemple, 10s, 5m, 1h).
-T end_time
Spécifie l'heure de fin de la collecte des métriques. L'heure peut être spécifiée dans divers formats, y compris des timestamps Unix ou des chaînes lisibles par l'homme.
-u
Ne rapportez que les métriques qui sont des valeurs simples sans instances (par exemple, kernel.all.sysfork) et omettez les métriques à valeur multiple avec des instances (par exemple, disk.dev.read). C'est l'inverse de l'option -e.
-U time_units
Spécifie les unités de temps à utiliser pour les métriques temporelles. Les unités possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option ne remplacera pas les spécifications possibles par métrique. Voir également pmParseUnitsStr(3).
-V, --version
Affiche le numéro de version et quitte.
-x, --with-extended
Écrit des informations étendues.
-X, --with-everything
Écrit tout ce qui est connu des métriques, y compris les identifiants internes de PCP. Les étiquettes sont cependant omises pour des raisons de compatibilité ascendante, utilisez -m pour les inclure également.
-y scale, --time-scale=scale
Unité/échelle pour les métriques temporelles, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option ne remplacera pas les spécifications possibles par métrique. Voir également pmParseUnitsStr(3).
-Y scale, --time-scale-force=scale
Similaire à -y mais cette option remplacera les spécifications par métrique.
-z, --hostzone
Utilise le fuseau horaire local de l'hôte source des métriques de performance, tel qu'identifié par les options -h ou -a. Par défaut, utilise le fuseau horaire de l'hôte local.
-Z timezone, --timezone=timezone
Utilise timezone pour la date et l'heure. Timezone est au format de la variable d'environnement TZ tel que décrit dans environ(7). Notez que lors de l'inclusion d'une chaîne de fuseau horaire dans la sortie, les décalages UTC de style ISO 8601 sont utilisés (donc quelque chose comme -Z EST+5 deviendra UTC-5).
-?, --help
Affiche le message d'utilisation et quitte.

FILES

pcp2json.conf
Fichier de configuration pcp2json (voir -c)
$PCP_SYSCONF_DIR/pmrep/*.conf
Fichiers de configuration pmrep par défaut fournis par le système

PCP ENVIRONMENT

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

Notamment, PCP_DISCRETE_ONCE peut être défini pour s'assurer que les valeurs de métriques discrètes ne sont rapportées qu'une seule fois, sauf si elles changent à un moment donné.

DEBUGGING OPTIONS

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider au dépannage, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
