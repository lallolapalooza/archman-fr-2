PCP2GRAPHITE(1) Manuel des commandes générales PCP2GRAPHITE(1)

NOM

pcp2graphite - exportateur de métriques pcp vers graphite

SYNOPIS

pcp2graphite [-5CGHIjLnrRvV?] [-4 action] [-8|-9 limite] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c config] [--container conteneur] [-D débogage] [--daemonize] [-e dérivé] [-E port-texte] [-g serveur] [-h hôte] [-i instances] [-J rang] [-K spéc] [-N prédicat] [-O origine] [-p port-pickle] [-P|-0 précision] [-q|-Q échelle-compte] [-s échantillons] [-S heure-début] [-t intervalle] [-T heure-fin] [-x préfixe] [-X protocole-pickle] [-y|-Y échelle-temps] métriques [...]

DESCRIPTION

pcp2graphite est un outil personnalisable d'exportation de métriques de performance de PCP vers Graphite. Toutes les métriques de performance disponibles, en direct ou archivées, système et/ou application, peuvent être sélectionnées pour l'exportation en utilisant soit des options en ligne de commande, soit un fichier de configuration.

pcp2graphite est un parent proche de pmrep(1). Référez-vous à pmrep(1) pour la description de métriques acceptée en ligne de commande par pcp2graphite. Voir pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2graphite.conf. Cette page décrit les options spécifiques à pcp2graphite et les différences de fichiers de configuration avec pmrep.conf(5). pmrep(1) liste également quelques exemples d'utilisation dont la plupart sont applicables à pcp2graphite également.

Seules les options en ligne de commande listées sur cette page sont supportées, les autres options disponibles pour pmrep(1) ne sont pas supportées.

Les options via des valeurs d'environnement (voir pmGetOptions(3)) remplacent les valeurs par défaut intégrées correspondantes (le cas échéant). Les options du fichier de configuration remplacent les variables d'environnement correspondantes (le cas échéant). Les options en ligne de commande remplacent les options correspondantes du fichier de configuration (le cas échéant).

FICHIER DE CONFIGURATION

pcp2graphite utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf: version, source, speclocal, dérivé, en-tête, globales, échantillons, intervalle, type, type_préféré, ignorer_incompatibles, noms_changent, instances, filtre_live, rang, filtre_limite, force_filtre_limite, inverser_filtre, prédicat, omettre_plat, précision, force_précision, échelle_compte, force_échelle_compte, échelle_espace, force_échelle_espace, échelle_temps, force_échelle_temps. Le reste des options de pmrep.conf est reconnu mais ignoré par souci de compatibilité.

options spécifiques à pcp2graphite

graphite_host (chaîne)

Spécifie le nom d'hôte ou l'adresse IP du serveur Graphite de destination. L'option en ligne de commande correspondante est -g. Par défaut, localhost.

graphite_port (entier)

Spécifie le numéro de port du serveur Graphite (texte brut ou pickle). Les options en ligne de commande correspondantes sont -p et -E. Par défaut, 2004.

pickle (booléen)

Spécifie s'il faut utiliser le protocole pickle. Les options en ligne de commande correspondantes sont -p et -E. Par défaut, oui.

pickle_protocol (entier)

Spécifie la version du protocole pickle. L'option en ligne de commande correspondante est -X. Par défaut, 0.

prefix (chaîne)

Spécifie le préfixe pour les métriques envoyées au serveur. L'option en ligne de commande correspondante est -x. Par défaut, pcp..

OPTIONS

Les options en ligne de commande disponibles sont :

-0 précision, --précision-force=précision
Identique à -P mais cette option remplacera les spécifications par métrique.
-4 action, --changement-noms=action
Spécifie quelle action entreprendre lors de la réception d'un événement de changement de nom de métrique pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques peu après le démarrage et informe les outils clients en cours d'exécution comme pcp2graphite. Les valeurs valides pour action sont update (rafraîchir les métriques échantillonnées), ignore (ne rien faire - comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignorer-inconnues
Ignore silencieusement tout nom de métrique qui ne peut pas être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-8 limite, --filtre-limite=limite
Limite les résultats aux instances dont les valeurs sont supérieures/inférieures à limite. Un entier positif inclura les instances dont les valeurs sont égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances dont les valeurs sont égales ou inférieures à la limite dans le rapport. Une valeur de zéro n'effectue aucun filtrage par limite. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi -J et -N.
-9 limite, --force-filtre-limite=limite
Identique à -8 mais cette option remplacera les spécifications par métrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --alignement=alignement
Force le premier échantillon à être aligné sur la limite d'une unité de temps naturelle alignement. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe de alignement.
--archive-folio=folio
Lit les archives sources de métriques du folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b échelle, --échelle-espace=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, et ainsi de suite. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-B échelle, --force-échelle-espace=échelle
Identique à -b mais cette option remplacera les spécifications par métrique.
-c config, --config=config
Spécifie le fichier ou répertoire de config à utiliser. Si config est un répertoire, tous les fichiers qui s'y trouvent et se terminent par .conf seront inclus. Par défaut, c'est le premier trouvé parmi : ./pcp2graphite.conf, $HOME/.pcp2graphite.conf, $HOME/pcp/pcp2graphite.conf, et $PCP_SYSCONF_DIR/pcp2graphite.conf. Pour plus de détails, voir la section ci-dessus et pmrep.conf(5).
--container=conteneur
Récupère les métriques de performance du conteneur spécifié, local ou distant (voir -h).
-C, --vérifier
Quitte avant de rapporter des valeurs, mais après avoir analysé la configuration et les métriques et imprimé les éventuels en-têtes.
--daemonize
Se démonise au démarrage.

OPTIONS

--derived=derived
Specify derived performance metrics. If derived starts with a slash (``/'') or with a dot (``.'') it will be interpreted as a PCP derived metrics configuration file, otherwise it will be interpreted as comma- or semicolon-separated derived metric expressions. For complete description of derived metrics and PCP derived metrics configuration files see pmLoadDerivedConfig(3) and pmRegisterDerived(3). Alternatively, using pmrep.conf(5) configuration syntax allows defining derived metrics as part of metricsets.

In case of issues with derived metrics, review the aforementioned manual pages in detail and ensure all the required metrics are available, especially when using archives. Use -Dderive to see additional debug information about parsing derived metrics.

-E port, --text-port=port
Graphite server plaintext port. Using this option disables the pickle protocol.
-g server, --graphite-host=server
Destination Graphite server hostname or IP address.
-G, --no-globals
Do not include global metrics in reporting (see pmrep.conf(5)).
-h host, --host=host
Fetch performance metrics from pmcd(1) on host, rather than from the default localhost.
-H, --no-header
Do not print any headers.
-i instances, --instances=instances
Retrieve and report only the specified metric instances. By default all instances, present and future, are reported.

Refer to pmrep(1) for complete description of this option.

-I, --ignore-incompat
Ignore incompatible metrics. By default incompatible metrics (that is, their type is unsupported or they cannot be scaled as requested) will cause pcp2graphite to terminate with an error message. With this option all incompatible metrics are silently omitted from reporting. This may be especially useful when requesting non-leaf nodes of the PMNS tree for reporting.
-j, --live-filter
Perform instance live filtering. This allows capturing all named instances even if processes are restarted at some point (unlike without live filtering). Performing live filtering over a huge number of instances will add some internal overhead so a bit of user caution is advised. See also -n.
-J rank, --rank=rank
Limit results to highest/lowest ranked instances of set-valued metrics. A positive integer will include highest valued instances in reporting. A negative integer will include lowest valued instances in reporting. A value of zero performs no ranking. Ranking does not imply sorting, see -6. See also -8.
-K spec, --spec-local=spec
When fetching metrics from a local context (see -L), the -K option may be used to control the DSO PMDAs that should be made accessible. The spec argument conforms to the syntax described in pmSpecLocalPMDA(3). More than one -K option may be used.
-L, --local-PMDA
Use a local context to collect metrics from DSO PMDAs on the local host without PMCD. See also -K.
-n, --invert-filter
Perform ranking before live filtering. By default instance live filtering (when requested, see -j) happens before instance ranking (when requested, see -J). With this option the logic is inverted and ranking happens before live filtering.
-N predicate, --predicate=predicate
Specify a comma-separated list of predicate filter reference metrics. By default ranking (see -J) happens for each metric individually. With predicates, ranking is done only for the specified predicate metrics. When reporting, rest of the metrics sharing the same instance domain (see PCPIntro(1)) as the predicate will include only the highest/lowest ranking instances of the corresponding predicate. Ranking does not imply sorting, see -6.

So for example, using proc.memory.rss (resident memory size of process) as the predicate metric together with proc.io.total_bytes and mem.util.used as metrics to be reported, only the processes using most/least (as per -J) memory will be included when reporting total bytes written by processes. Since mem.util.used is a single-valued metric (thus not sharing the same instance domain as the process related metrics), it will be reported as usual.

-O origin, --origin=origin
When reporting archived metrics, start reporting at origin within the time window (see -S and -T). Refer to PCPIntro(1) for a complete description of the syntax for origin.
-p port, --pickle-port=port
Graphite server pickle port. Using this option enables the pickle protocol.
-P precision, --precision=precision
Use precision for numeric non-integer output values. The default is to use 3 decimal places (when applicable). This option will not override possible per-metric specifications.
-q scale, --count-scale=scale
Unit/scale for count metrics, possible values include count x 10^-1, count, count x 10, count x 10^2, and so forth from 10^-8 to 10^7. (These values are currently space-sensitive.) This option will not override possible per-metric specifications. See also pmParseUnitsStr(3).
-Q scale, --count-scale-force=scale
Like -q but this option will override per-metric specifications.
-r, --raw
Output raw metric values, do not convert cumulative counters to rates. This option will override possible per-metric specifications.
-R, --raw-prefer
Like -r but this option will not override per-metric specifications.
-s samples, --samples=samples
The samples argument defines the number of samples to be retrieved and reported. If samples is 0 or -s is not specified, pcp2graphite will sample and report continuously (in real time mode) or until the end of the set of PCP archives (in archive mode). See also -T.
-S starttime, --start=starttime
When reporting archived metrics, the report will be restricted to those records logged at or after starttime. Refer to PCPIntro(1) for a complete description of the syntax for starttime.
-t interval, --interval=interval
Set the reporting interval to something other than the default 1 second. The interval argument follows the syntax described in PCPIntro(1), and in the simplest form may be an unsigned integer (the implied units in this case are seconds). See also the -T option.
-T endtime, --finish=endtime
When reporting archived metrics, the report will be restricted to those records logged before or at endtime. Refer to PCPIntro(1) for a complete description of the syntax for endtime.

When used to define the runtime before pcp2graphite will exit, if no samples is given (see -s) then the number of reported samples depends on interval (see -t). If samples is given then interval will be adjusted to allow reporting of samples during runtime. In case all of -T, -s, and -t are given, endtime determines the actual time pcp2graphite will run.

-v, --omit-flat
Report only set-valued metrics with instances (e.g. disk.dev.read) and omit single-valued ``flat'' metrics without instances (e.g. kernel.all.sysfork). See -i and -I.
-V, --version
Display version number and exit.
-x prefix, --prefix=prefix
Metrics prefix for measurements sent to the server.
-X protocol, --pickle-protocol=protocol
Pickle protocol version number.
-y scale, --time-scale=scale
Unit/scale for time metrics, possible values include nanosec, ns, microsec, us, millisec, ms, and so forth up to hour, hr. This option will not override possible per-metric specifications. See also pmParseUnitsStr(3).
-Y scale, --time-scale-force=scale
Like -y but this option will override per-metric specifications.
-?, --help
Display usage message and exit.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

Il est particulièrement important de noter que PCP_DISCRETE_ONCE peut être définie pour s'assurer que les valeurs métriques discrètes ne sont rapportées qu'une seule fois, sauf si elles changent à un moment donné.

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à résoudre les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir la liste des options de débogage disponibles et leur signification.
