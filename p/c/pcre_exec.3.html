pcre_exec(3)

Paquet: pcre

Licences: BSD

PCRE_EXEC(3) Manuel des fonctions de bibliothèque PCRE_EXEC(3)

NOM

PCRE - expressions régulières compatibles Perl

SYNTAXE

#include <pcre.h>

int pcre_exec(const pcre *code, const pcre_extra *extra,
     const char *subject, int length, int startoffset,
     int options, int *ovector, int ovecsize);

int pcre16_exec(const pcre16 *code, const pcre16_extra *extra,
     PCRE_SPTR16 subject, int length, int startoffset,
     int options, int *ovector, int ovecsize);

int pcre32_exec(const pcre32 *code, const pcre32_extra *extra,
     PCRE_SPTR32 subject, int length, int startoffset,
     int options, int *ovector, int ovecsize);

DESCRIPTION

Cette fonction recherche une expression régulière compilée dans une chaîne de sujet donnée, en utilisant un algorithme de correspondance similaire à celui de Perl. Elle retourne les décalages des sous-chaînes capturées. Ses arguments sont :


code Pointeur vers le motif compilé
extra Pointeur vers une structure pcre[16|32]_extra associée,
ou NULL
subject Pointeur vers la chaîne de sujet
length Longueur de la chaîne de sujet
startoffset Décalage dans le sujet où commencer la recherche
options Bits d'options
ovector Pointeur vers un vecteur d'entiers pour les décalages de résultat
ovecsize Nombre d'éléments dans le vecteur (un multiple de 3)

Les unités pour length et startoffset sont des octets pour pcre_exec(), des éléments de données de 16 bits pour pcre16_exec(), et des éléments de 32 bits pour pcre32_exec(). Les options sont :


PCRE_ANCHORED Recherche uniquement à la première position
PCRE_BSR_ANYCRLF \R recherche uniquement CR, LF ou CRLF
PCRE_BSR_UNICODE \R recherche toutes les terminaisons de ligne Unicode
PCRE_NEWLINE_ANY Reconnaît toute séquence de fin de ligne Unicode
PCRE_NEWLINE_ANYCRLF Reconnaît CR, LF et CRLF comme séquences de fin de ligne
PCRE_NEWLINE_CR Reconnaît CR comme seule séquence de fin de ligne
PCRE_NEWLINE_CRLF Reconnaît CRLF comme seule séquence de fin de ligne
PCRE_NEWLINE_LF Reconnaît LF comme seule séquence de fin de ligne
PCRE_NOTBOL La chaîne de sujet n'est pas le début d'une ligne
PCRE_NOTEOL La chaîne de sujet n'est pas la fin d'une ligne
PCRE_NOTEMPTY Une chaîne vide n'est pas une correspondance valide
PCRE_NOTEMPTY_ATSTART Une chaîne vide au début du sujet
n'est pas une correspondance valide
PCRE_NO_START_OPTIMIZE Ne pas effectuer les optimisations de "début de correspondance"
PCRE_NO_UTF16_CHECK Ne pas vérifier la validité UTF-16 du sujet
(uniquement pertinent si PCRE_UTF16
a été défini lors de la compilation)
PCRE_NO_UTF32_CHECK Ne pas vérifier la validité UTF-32 du sujet
(uniquement pertinent si PCRE_UTF32
a été défini lors de la compilation)
PCRE_NO_UTF8_CHECK Ne pas vérifier la validité UTF-8 du sujet
(uniquement pertinent si PCRE_UTF8
a été défini lors de la compilation)
PCRE_PARTIAL ) Retourner PCRE_ERROR_PARTIAL pour une correspondance partielle
PCRE_PARTIAL_SOFT ) si aucune correspondance complète n'est trouvée
PCRE_PARTIAL_HARD Retourner PCRE_ERROR_PARTIAL pour une correspondance partielle
si elle est trouvée avant une correspondance complète

Pour plus de détails sur la correspondance partielle, voir la page pcrepartial. Une structure pcre_extra contient les champs suivants :


flags Bits indiquant quels champs sont définis
study_data Données opaques provenant de pcre[16|32]_study()
match_limit Limite d'utilisation des ressources internes
match_limit_recursion Limite de profondeur de récursion interne
callout_data Données opaques retournées aux appels externes
tables Pointeur vers les tables de caractères ou NULL
mark Pour retourner un pointeur *MARK
executable_jit Données opaques provenant de la compilation JIT

Les bits de drapeau sont PCRE_EXTRA_STUDY_DATA, PCRE_EXTRA_MATCH_LIMIT, PCRE_EXTRA_MATCH_LIMIT_RECURSION, PCRE_EXTRA_CALLOUT_DATA, PCRE_EXTRA_TABLES, PCRE_EXTRA_MARK et PCRE_EXTRA_EXECUTABLE_JIT.

Une description complète de l'API native de PCRE se trouve sur la page pcreapi et une description de l'API POSIX se trouve sur la page pcreposix.
