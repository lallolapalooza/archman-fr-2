PCRE2SYNTAX(3) Manuel des fonctions de bibliothèque PCRE2SYNTAX(3)

NOM

PCRE2 - expressions régulières compatibles Perl (API révisée)

PCRE2 RÉSUMÉ DE LA SYNTAXE DES EXPRESSIONS RÉGULIÈRES

La syntaxe complète et la sémantique des motifs d'expressions régulières supportés par PCRE2 sont décrites dans la documentation pcre2pattern. Ce document contient un résumé de référence rapide de la syntaxe des motifs, suivi de la syntaxe des chaînes de remplacement dans la fonction de substitution. La description complète de cette dernière se trouve dans la documentation pcre2api.

ÉCHAPPEMENT


\x où x n'est pas alphanumérique est un littéral x
\Q...\E traite les caractères inclus comme des littéraux

Notez que les espaces blancs à l'intérieur de \Q...\E sont toujours traités comme des littéraux, même si PCRE2_EXTENDED est défini, ce qui fait qu'ils sont ignorés la plupart du temps. Notez également que la gestion de \Q...\E par PCRE2 présente quelques différences par rapport à celle de Perl. Voir la documentation pcre2pattern pour les détails.

ÉLÉMENTS ENTRE ACCOLADES

À une exception près, partout où les caractères d'accolade { et } sont requis pour encapsuler des données pour des constructions telles que \g{2} ou \k{nom}, les caractères d'espace et/ou de tabulation horizontale qui suivent { ou précèdent } sont autorisés et sont ignorés. Dans le cas des quantificateurs, ils peuvent également apparaître avant ou après la virgule. L'exception est \u{...} qui n'est pas compatible avec Perl et n'est reconnue que lorsque PCRE2_EXTRA_ALT_BSUX est défini. Il s'agit d'une fonctionnalité de compatibilité ECMAScript, et elle suit le comportement d'ECMAScript.

CARACTÈRES ÉCHAPPÉS

Ce tableau s'applique aux environnements ASCII et Unicode. Une séquence d'échappement non reconnue provoque une erreur.


\a alarme, c'est-à-dire le caractère BEL (hex 07)
\cx « contrôle-x », où x est un caractère ASCII non-contrôle
\e échappement (hex 1B)
\f saut de page (hex 0C)
\n nouvelle ligne (hex 0A)
\r retour chariot (hex 0D)
\t tabulation (hex 09)
\0dd caractère avec code octal 0dd
\ddd caractère avec code octal ddd, ou référence arrière
\o{ddd..} caractère avec code octal ddd..
\N{U+hh..} caractère avec le point de code Unicode hh.. (mode Unicode uniquement)
\xhh caractère avec code hexadécimal hh
\x{hh..} caractère avec code hexadécimal hh..

\N{U+hh..} est synonyme de \x{hh..} mais n'est pas supporté dans les environnements utilisant le code EBCDIC (principalement les mainframes IBM). Notez que \N non suivi d'une accolade ouvrante a un sens différent (voir ci-dessous).

Si PCRE2_ALT_BSUX ou PCRE2_EXTRA_ALT_BSUX est défini (« mode ALT_BSUX »), les éléments suivants sont également reconnus :


\U le caractère « U »
\uhhhh caractère avec code hexadécimal hhhh
\u{hh..} caractère avec code hexadécimal hh.. mais uniquement pour EXTRA_ALT_BSUX

Lorsque \x n'est pas suivi de {, un ou deux chiffres hexadécimaux sont lus, mais en mode ALT_BSUX, \x doit être suivi de deux chiffres hexadécimaux pour être reconnu comme une échappatoire hexadécimale ; sinon, il correspond à un littéral « x ». De même, si \u (en mode ALT_BSUX) n'est pas suivi de quatre chiffres hexadécimaux ou (en mode EXTRA_ALT_BSUX) d'une séquence de chiffres hexadécimaux entre accolades, il correspond à un littéral « u ».

Notez que \0dd est toujours un code octal. Le traitement de la barre oblique inverse suivie d'un chiffre non nul est compliqué ; pour plus de détails, voir la section « Caractères non imprimables » de la documentation pcre2pattern, où les détails du traitement des échappatoires dans les environnements EBCDIC sont également donnés.

TYPES DE CARACTÈRES


. n'importe quel caractère sauf une nouvelle ligne ;
en mode dotall, n'importe quel caractère quel qu'il soit
\C une unité de code, même en mode UTF (à éviter)
\d un chiffre décimal
\D un caractère qui n'est pas un chiffre décimal
\h un espace blanc horizontal
\H un caractère qui n'est pas un espace blanc horizontal
\N un caractère qui n'est pas une nouvelle ligne
\p{xx} un caractère avec la propriété xx
\P{xx} un caractère sans la propriété xx
\R une séquence de nouvelle ligne
\s un caractère d'espacement
\S un caractère qui n'est pas un espace blanc
\v un espace blanc vertical
\V un caractère qui n'est pas un espace blanc vertical
\w un caractère de « mot »
\W un caractère de « non-mot »
\X un cluster de graphèmes étendu Unicode

\C est dangereux car il peut laisser le point de correspondance actuel au milieu d'un caractère UTF-8 ou UTF-16. L'application peut interdire l'usage de \C en définissant l'option PCRE2_NEVER_BACKSLASH_C. Il est également possible de compiler PCRE2 avec l'usage de \C désactivé en permanence.

Par défaut, \d, \s et \w ne correspondent qu'aux caractères ASCII, même en mode UTF-8 ou dans les bibliothèques 16 bits et 32 bits. Cependant, si une correspondance basée sur la locale est effectuée, \s et \w peuvent également correspondre à des caractères avec des points de code dans la plage 128-255. Si l'option PCRE2_UCP est définie, le comportement de ces séquences d'échappement est modifié pour utiliser les propriétés Unicode et elles correspondent à beaucoup plus de caractères, mais certains paramètres d'options peuvent restreindre les séquences individuelles à ne correspondre qu'aux caractères ASCII.

Les descriptions de propriétés dans \p et \P sont comparées sans tenir compte de la casse ; les traits d'union, les tirets bas et les espaces blancs ASCII sont ignorés, conformément aux règles de « comparaison lâche » de l'Unicode. Par exemple, \p{Bidi_Class=al} est identique à \p{ bidi class = AL }.

PROPRIÉTÉS BINAIRES POUR \p ET \P

Unicode définit un certain nombre de propriétés binaires, c'est-à-dire des propriétés dont les seules valeurs sont vrai ou faux. Vous pouvez obtenir une liste de celles qui sont reconnues par \p et \P, ainsi que leurs abréviations, en exécutant cette commande :


pcre2test -LP

CORRESPONDANCE DE SCRIPTS AVEC \p ET \P

De nombreux noms de scripts et leurs abréviations à 4 lettres sont reconnus dans les éléments \p{sc:...} ou \p{scx:...}, ou seuls avec \p (et aussi \P bien sûr). Vous pouvez obtenir une liste de ces scripts en exécutant cette commande :


pcre2test -LS

Dans PCRE2, les noms d'ensembles de caractères POSIX reconnaissent par défaut uniquement les caractères ASCII, mais certains d'entre eux utilisent des propriétés Unicode si PCRE2_UCP est défini. Vous pouvez utiliser \Q...\E à l'intérieur d'une classe de caractères.

Lorsque PCRE2_ALT_EXTENDED_CLASS est défini, les classes de caractères étendues UTS#18 peuvent être utilisées, permettant des classes de caractères imbriquées, combinées à l'aide d'opérateurs d'ensemble.


[x&&[^y]] classe de caractères étendue UTS#18


x||y union d'ensembles (OU)
x&&y intersection d'ensembles (ET)
x--y différence d'ensembles (ET NON)
x~~y différence symétrique d'ensembles (XOR)

CLASSES DE CARACTÈRES ÉTENDUES PERL


(?[...]) classe de caractères étendue Perl
(?[\p{Thai} & \p{Nd}]) opérateurs ; les espaces blancs sont ignorés
(?[(x - y) & z]) parenthèses pour le regroupement


(?[ [^3] & \p{Nd} ]) [...] est une classe ordinaire imbriquée
(?[ [:alpha:] - [z] ]) l'ensemble POSIX est autorisé en dehors de [...]
(?[ \d - [3] ]) l'ensemble échappé par antislash est autorisé en dehors de [...]
(?[ !\n & [:ascii:] ]) le caractère échappé par antislash est autorisé en dehors de [...]
tous les autres caractères ou intervalles doivent être entourés de [...]


x|y, x+y union d'ensembles (OU)
x&y intersection d'ensembles (ET)
x-y différence d'ensembles (ET NON)
x^y différence symétrique d'ensembles (XOR)
!x complément d'ensemble (NON)

À l'intérieur d'une classe de caractères étendue Perl, [...] passe le mode pour être interprété comme une classe de caractères ordinaire. En dehors d'une classe imbriquée [...], les seuls éléments autorisés sont les échappements par antislash, les ensembles POSIX, les opérateurs et les parenthèses. À l'intérieur d'une classe ordinaire imbriquée, ^ a sa signification habituelle (inverse la classe lorsqu'elle est utilisée comme premier caractère) ; en dehors d'une classe imbriquée, ^ est l'opérateur XOR.

RÉGLAGE DU POINT DE CORRESPONDANCE RAPPORTÉ


\K définit le début du match rapporté

Depuis la version 10.38, \K n'est pas autorisé par défaut dans les assertions de recherche avant/arrière, pour la compatibilité avec Perl. Cependant, si l'option PCRE2_EXTRA_ALLOW_LOOKAROUND_BSK est définie, le comportement précédent est réactivé. Lorsque cette option est définie, \K est respecté dans les assertions positives, mais ignoré dans les assertions négatives.

RÉGLAGE DES OPTIONS

Les changements de ces options à l'intérieur d'un groupe sont automatiquement annulés à la fin du groupe.


(?a) toutes les options ASCII
(?aD) restreint \d à ASCII en mode UCP
(?aS) restreint \s à ASCII en mode UCP
(?aW) restreint \w à ASCII en mode UCP
(?aP) restreint toutes les classes POSIX à ASCII en mode UCP
(?aT) restreint les classes de chiffres POSIX à ASCII en mode UCP
(?i) insensible à la casse
(?J) autorise les groupes nommés en double
(?m) multiligne
(?n) pas de capture automatique
(?r) restreint l'insensibilité à la casse soit à ASCII, soit à non-ASCII
(?s) ligne unique (dotall)
(?U) paresseux par défaut
(?x) ignore les espaces blancs sauf dans les classes ou \Q...\E
(?xx) comme (?x) mais ignore aussi l'espace et la tabulation dans les classes
(?-...) désactive l'option donnée
(?^) désactive les options imnrsx

(?aP) implique également (?aT), bien que cela n'ait aucun effet supplémentaire. Cependant, cela signifie que (?-aP) implique également (?-aT) et désactive toutes les restrictions ASCII pour les classes POSIX.

La désactivation de x ou xx désactive les deux. Plusieurs options peuvent être définies en même temps, et un mélange de définition et de désactivation comme (?i-x) est autorisé, mais il ne peut y avoir qu'un seul trait d'union. La définition (mais aucune désactivation) est autorisée après (?^ par exemple (?^in). Une définition d'option peut apparaître au début d'un groupe sans capture, par exemple (?i:...).

Les éléments suivants ne sont reconnus qu'au tout début d'un motif ou après l'une des séquences de saut de ligne ou \R, ou des options de syntaxe similaire. Plusieurs d'entre eux peuvent apparaître. Pour les trois premiers, d est un nombre décimal.


(*LIMIT_DEPTH=d) définit la limite de backtracking à d
(*LIMIT_HEAP=d) définit la limite de taille du tas à d * 1024 octets
(*LIMIT_MATCH=d) définit la limite de correspondance à d
(*CASELESS_RESTRICT) définit PCRE2_EXTRA_CASELESS_RESTRICT lors de la correspondance
(*NOTEMPTY) définit PCRE2_NOTEMPTY lors de la correspondance
(*NOTEMPTY_ATSTART) définit PCRE2_NOTEMPTY_ATSTART lors de la correspondance
(*NO_AUTO_POSSESS) pas de posséssification automatique (PCRE2_NO_AUTO_POSSESS)
(*NO_DOTSTAR_ANCHOR) pas d'ancrage de .* (PCRE2_NO_DOTSTAR_ANCHOR)
(*NO_JIT) désactive l'optimisation JIT
(*NO_START_OPT) pas d'optimisation de début de correspondance (PCRE2_NO_START_OPTIMIZE)
(*TURKISH_CASING) définit PCRE2_EXTRA_TURKISH_CASING lors de la correspondance
(*UTF) définit le mode UTF approprié pour la bibliothèque utilisée
(*UCP) définit PCRE2_UCP (utilise les propriétés Unicode pour \d etc.)

Notez que LIMIT_DEPTH, LIMIT_HEAP et LIMIT_MATCH ne peuvent que réduire la valeur des limites définies par l'appelant de pcre2_match() ou pcre2_dfa_match(), pas les augmenter. LIMIT_RECURSION est un synonyme obsolète de LIMIT_DEPTH. L'application peut bloquer l'utilisation de (*UTF) et (*UCP) en définissant respectivement les options PCRE2_NEVER_UTF ou PCRE2_NEVER_UCP au moment de la compilation.

ASSERTIONS DE RECHERCHE AVANT ET ARRIÈRE


(?=...) )

ASSERTIONS DE PORTÉE

Ces assertions ne consomment pas de caractères dans la chaîne d'entrée. Elles se contentent de vérifier s'il y a une correspondance ou non à leur emplacement.


(*pl:...) ) assertion de portée positive
(*positive_lookahead:...) )


(?!...) )
(*nla:...) ) assertion de portée négative
(*negative_lookahead:...) )


(?<=...) )
(*plb:...) ) assertion de portée arrière positive
(*positive_lookbehind:...) )


(?<!...) )
(*nlb:...) ) assertion de portée arrière négative
(*negative_lookbehind:...) )

Chaque branche de niveau supérieur d'une assertion de portée arrière doit avoir une limite pour le nombre de caractères qu'elle correspond. Si une branche peut correspondre à un nombre variable de caractères, le maximum pour chaque branche est limité à une valeur définie par l'appelant de pcre2_compile() ou par défaut. La valeur par défaut est définie lors de la compilation de PCRE2 (valeur par défaut ultime 255). Si toutes les branches correspondent à un nombre fixe de caractères, la limite pour chaque branche est de 65535 caractères.

ASSERTIONS DE PORTÉE NON ATOMIQUES

Ces assertions sont spécifiques à PCRE2 et ne sont pas compatibles avec Perl.


(?*...) )
(*napla:...) ) synonymes
(*non_atomic_positive_lookahead:...) )


(?<*...) )
(*naplb:...) ) synonymes
(*non_atomic_positive_lookbehind:...) )

(?R(grouplist)) récursion de tout le motif, retournant les groupes de capture
(extension PCRE2)
(?n(grouplist)) )
(?+n(grouplist)) ) appel de sous-routine, retournant les groupes de capture
(?-n(grouplist)) ) (extension PCRE2)
(?&nom(grouplist)) )
(?P>nom(grouplist)) )

La liste "grouplist" séparée par des virgules utilise la même syntaxe que (*scan_substring:(grouplist)...), et peut identifier les groupes de l'une des manières suivantes :


n référence absolue
+n référence relative
-n référence relative
<nom> nom
'nom' nom

(?(n) condition de référence absolue

Notez l'ambiguïté de (?(R) et (?(Rn) qui pourraient être des conditions de référence nommée ou des tests de récursion. Une telle condition est interprétée comme une condition de référence si le groupe nommé pertinent existe.

Les parties entre crochets pour la syntaxe conditionnelle VERSION pourraient être omises. La partie fractionnaire du numéro de version est alors par défaut à 0.

CONTRÔLE DU RETOUR ARRIÈRE

Tous les verbes de contrôle de retour arrière peuvent être sous la forme (*VERB:NOM). Pour (*MARK), le nom est obligatoire, pour les autres il est facultatif. (*SKIP) change son comportement si :NOM est présent. Les autres définissent simplement un nom à renvoyer à l'appelant, mais ce n'est pas un nom que (*SKIP) peut voir. Les suivants agissent immédiatement dès qu'ils sont atteints :


(*ACCEPT) forcer une correspondance réussie
(*FAIL) forcer le retour arrière ; synonyme (*F)
(*MARK:NOM) définir un nom à renvoyer ; synonyme (*:NOM)

Les verbes suivants n'agissent que lorsqu'une défaillance de correspondance ultérieure provoque un retour arrière jusqu'à eux. Ils forcent tous une défaillance de correspondance, mais diffèrent dans ce qui se passe ensuite. Ceux qui font avancer le point de départ de la correspondance ne le font que si le motif n'est pas ancré.


(*COMMIT) échec global, aucun avancement du point de départ
(*PRUNE) avancer au prochain caractère de départ
(*SKIP) avancer à la position de correspondance actuelle
(*SKIP:NOM) avancer à la position correspondant à un précédent
(*MARK:NOM) ; si non trouvé, le (*SKIP) est ignoré
(*THEN) échec local, retour arrière à la prochaine alternance

L'effet de l'un de ces verbes dans un groupe appelé comme sous-routine est confiné à l'appel de sous-routine.

APPELS EXTERNES


(?C) appel externe (numéro supposé 0)
(?Cn) appel externe avec données numériques n
(?C"texte") appel externe avec données textuelles

Les délimiteurs de chaînes autorisés sont ` ' " ^ % # $ (qui sont les mêmes pour le début et la fin), et le délimiteur de début { correspondant au délimiteur de fin }. Pour encoder le délimiteur de fin dans la chaîne, doublez-le.

CHAÎNES DE REMPLACEMENT

Si l'option PCRE2_SUBSTITUTE_LITERAL est définie, une chaîne de remplacement pour pcre2_substitute() n'est pas interprétée. Sinon, par défaut, le seul caractère spécial est le caractère dollar sous l'une des formes suivantes :


$$ insérer un caractère dollar
$n ou ${n} insérer le contenu du groupe n
$<nom> insérer le contenu du groupe nommé
$0 ou $& insérer la sous-chaîne entière correspondante
$` insérer la sous-chaîne qui précède la correspondance
$' insérer la sous-chaîne qui suit la correspondance
$_ insérer la chaîne d'entrée entière
$+ insérer le groupe de capture le plus élevé qui a correspondu
$*MARK ou ${*MARK} insérer un nom de verbe de contrôle

Pour ${n}, n peut être un nom ou un numéro. Si PCRE2_SUBSTITUTE_EXTENDED est défini, il y a une interprétation supplémentaire :

1. La barre oblique inverse est un caractère d'échappement, et les formes décrites dans "CARACTÈRES ÉCHAPPÉS" ci-dessus sont reconnues. Également :


\Q...\E peut être utilisé pour supprimer l'interprétation
\l forcer le caractère suivant en minuscules
\u forcer le caractère suivant en majuscules
\L forcer les caractères suivants en minuscules
\U forcer les caractères suivants en majuscules
\u\L forcer le caractère suivant en majuscules, puis tous en minuscules
\l\U forcer le caractère suivant en minuscules, puis tous en majuscules
\E terminer le forçage de casse \L ou \U
\b caractère de retour chariot (note : comme dans une classe de caractères dans le motif)
\v caractère de tabulation verticale (note : pas la même chose que dans un motif)

2. La forme Python \g<n>, où les chevrons font partie de la syntaxe et n est soit un nom de groupe soit un numéro, est reconnue comme une manière alternative d'insérer le contenu d'un groupe, par exemple \g<3>.

3. La substitution de capture prend en charge les formes supplémentaires suivantes :


${n:-chaîne} défaut pour groupe non défini
${n:+chaîne1:chaîne2} valeurs pour groupe défini/non défini

Les chaînes de substitution elles-mêmes sont développées. La barre oblique inverse peut être utilisée pour échapper les deux-points et les accolades fermantes.
