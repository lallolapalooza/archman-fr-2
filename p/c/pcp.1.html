pcp(1)

PCP(1) Manuel des commandes générales PCP(1)

NOM

pcp, pcp-summary - exécute une commande ou résume une installation

SYNTAXE

pcp [options pcp...] commande-pcp [options de commande...]
pcp [-LPV?] [-a archive] [-D debug] [-h hote] [-O origine] [-n fichier-pmns]

DESCRIPTION

La commande pcp est utilisée dans l'un des deux modes. Par défaut, elle résume l'installation de Performance Co-Pilot (PCP) sur l'hôte local. Ce mode peut également être utilisé pour résumer l'installation depuis un hote distant, ou une installation historique à partir d'un ensemble d'archives PCP. Ce mode invoque indirectement la commande pcp-summary (en l'absence de toute autre commande demandée).

Alternativement, une commande peut être passée à pcp pour exécution, de nouveau éventuellement dans le contexte d'un hote distant ou d'un ensemble d'archives historiques.

MODE COMMANDE

Lorsque pcp est invoqué avec une commande à exécuter, il recherche la commande nommée dans $PCP_BINADM_DIR ainsi que dans $HOME/.pcp/bin (il s'agit généralement de scripts, et ils sont installés avec un préfixe "pcp-"). Ce mode de fonctionnement permet de mettre en œuvre des outils de performance système à l'aide des services PMAPI(3), tout en conservant toutes leurs options de ligne de commande habituelles. Ces options sont ainsi (indirectement) augmentées de l'ensemble d'options PCP standard, tel que décrit dans PCPIntro(1).

Cela fournit un mécanisme pratique pour obtenir des capacités de surveillance rétrospectives ou distantes tout en préservant le comportement des outils système.

Par exemple, l'utilitaire pcp-free(1) peut être invoqué comme suit, pour des données enregistrées de l'hôte munch :

$ pcp -a $PCP_LOG_DIR/pmlogger/munch/20140317 -O 11:35:50am free -m
             total       utilisé     libre      partagé    tampons     mis en cache
Mem:         23960      14554       9406          0        176       2137
-/+ tampons/cache:      12240      11720
Swap         12047          0      12047

Une liste complète des outils disponibles et installés est fournie avec le message d'utilisation de pcp(1), mais certains exemples incluent : pcp-free(1), pcp-uptime(1) et pcp-numastat(1).

MODE RÉSUMÉ

Le rapport de résumé inclut : la version de l'OS, un résumé de l'inventaire matériel, le fuseau horaire local, la version du logiciel PCP, l'état du processus pmcd(1) et les agents de domaine de métriques de performance (PMDA) associés, ainsi que des informations sur tous les archiveurs PCP locaux (pmlogger(1)), les archiveurs PCP distants (pmproxy(1)) et les moteurs d'inférence PCP (pmie(1)) qui sont en cours d'exécution.

Toutes les valeurs affichées sont des valeurs de métrique de performance et des informations supplémentaires pour chacune peuvent être obtenues en utilisant la commande : 

$ pminfo -dtT métrique
L'ensemble complet des métriques requis par pcp pour produire sa sortie est contenu dans $PCP_VAR_DIR/config/pmlogconf/tools/pcp-summary.

OPTIONS MODE RÉSUMÉ

Sans arguments, pcp fait un rapport sur l'hôte local, cependant les options suivantes sont acceptées :

-a archive, --archive=archive
Rapport sur la configuration PCP telle que décrite dans l'ensemble des archives PCP, archive, qui est une liste séparée par des virgules de noms, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-h hote, --host=hote
Rapport sur la configuration PCP sur l'hôte hote plutôt que sur l'hôte local.
-L, --local-PMDA
Utiliser un contexte local pour collecter des métriques des PMDA DSO sur l'hôte local sans PMCD.
-n fichier-pmns, --namespace=fichier-pmns
Charger un Espace de Noms de Métriques de Performance (PMNS) alternatif (PMNS(5)) depuis le fichier fichier-pmns.
-O origine, --origin=origine
Lors du rapport sur les métriques archivées, commencer le rapport à origine dans la fenêtre temporelle.
-P, --pmie
Afficher les informations de performance de pmie(1) - comptes des règles évaluées à vrai, faux ou indéterminé, ainsi que le taux attendu de calcul des règles, pour chaque processus pmie en cours d'exécution sur l'hôte par défaut. Se référer à l'aide de chaque métrique pour les détails complets sur ces valeurs.
-V, --version
Afficher le numéro de version et quitter.
-?, --help
Afficher le message d'utilisation et quitter.

DIAGNOSTICS

pcp se terminera avec un statut de sortie de 1 si pmcd sur l'hôte cible n'a pas pu être atteint ou si l'ensemble des archives n'a pas pu être ouvert, ou 2 pour toute autre erreur.

FICHIERS

$HOME/.pcp/bin
Emplacement par utilisateur pour les scripts de commande.
$PCP_BINADM_DIR
Emplacement système pour les scripts de commande installés.
$PCP_VAR_DIR/config/pmlogconf/tools/pcp-summary
Fichier de configuration pmlogconf(1) pour collecter toutes les métriques requises par pcp

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, tel que décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

OPTIONS DEBOGAGE

L'option -D ou --debug active l'affichage de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste séparée par des virgules d'options de débogage ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
