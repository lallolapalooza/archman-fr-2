SYNTAXE

#include <libtecla.h>
PathCache *new_PathCache(void);
PathCache *del_PathCache(PathCache *pc);
int pca_scan_path(PathCache *pc, const char *path);
void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                      void *data);
char *pca_lookup_file(PathCache *pc, const char *name,
                      int name_len, int literal);
const char *pca_last_error(PathCache *pc);
CPL_MATCH_FN(pca_path_completions);

DESCRIPTION

L'objet PathCache fait partie de la bibliothèque tecla (voir la page de manuel libtecla(3)).

Les objets PathCache permettent à une application de rechercher des fichiers dans n'importe quelle liste de répertoires séparés par des deux-points, comme la variable d'environnement d'exécution UNIX PATH. Les fichiers dans des répertoires absolus sont mis en cache dans un objet PathCache, tandis que les répertoires relatifs sont analysés au besoin. En utilisant un objet PathCache, vous pouvez rechercher le nom de chemin complet d'un nom de fichier simple, ou vous pouvez obtenir une liste des complétions possibles d'un préfixe de nom de fichier donné. Par défaut, tous les fichiers dans la liste des répertoires sont des cibles pour la recherche et la complétion, mais un mécanisme polyvalent est fourni pour ne sélectionner que des types de fichiers spécifiques. L'application évidente de cette fonctionnalité est de fournir la complétion par tabulation et la recherche des commandes exécutables dans le PATH UNIX, ainsi une fonction de rappel optionnelle qui rejette tous les fichiers sauf les exécutables, est fournie.

UN EXEMPLE

Sous UNIX, l'exemple de programme suivant recherche et affiche les noms de chemin complet de chaque nom de commande sur la ligne de commande.

  #include <stdio.h>
  #include <stdlib.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    int i;
  /*
   * Crée un cache pour les fichiers exécutables.
   */
    PathCache *pc = new_PathCache();
    if(!pc)
      exit(1);
  /*
   * Analyse le PATH de l'utilisateur pour les exécutables.
   */
    if(pca_scan_path(pc, getenv("PATH"))) {
      fprintf(stderr, "%s\n", pca_last_error(pc));
      exit(1);
    }
  /*
   * Dispose pour ne signaler que les fichiers exécutables.
   */
   pca_set_check_fn(pc, cpl_check_exe, NULL);
  /*
   * Recherche et affiche le nom de chemin complet de chacun des
   * commandes listées sur la ligne de commande.
   */
    for(i=1; i<argc; i++) {
      char *cmd = pca_lookup_file(pc, argv[i], -1, 0);
      printf("Le nom de chemin complet de '%s' est %s\n", argv[i],
             cmd ? cmd : "inconnu");
    }
    pc = del_PathCache(pc);  /* Nettoyage */
    return 0;
  }

Voici un exemple de ce que cela fait sur mon ordinateur portable sous Linux :

  $ ./example less more blob
  Le nom de chemin complet de 'less' est /usr/bin/less
  Le nom de chemin complet de 'more' est /bin/more
  Le nom de chemin complet de 'blob' est inconnu
  $

DESCRIPTIONS DES FONCTIONS

Pour utiliser les fonctionnalités de ce module, vous devez d'abord allouer un objet PathCache en appelant la fonction constructeur new_PathCache().

  PathCache *new_PathCache(void)

Cette fonction crée les ressources nécessaires pour mettre en cache et rechercher des fichiers dans une liste de répertoires. Elle retourne NULL en cas d'erreur.

REMPLIR LE CACHE

Une fois que vous avez créé un cache, il doit être rempli avec des fichiers. Pour ce faire, appelez la fonction pca_scan_path().

  int pca_scan_path(PathCache *pc, const char *path);

Chaque fois que cette fonction est appelée, elle jette le contenu actuel du cache, puis analyse la liste des répertoires spécifiés dans son argument path pour y trouver des fichiers. L'argument path doit être une chaîne contenant une liste de répertoires séparés par des deux-points, comme "/usr/bin:/home/mcs/bin:.". Cela peut inclure des répertoires spécifiés par des chemins absolus comme "/usr/bin", ainsi que des sous-répertoires spécifiés par des chemins relatifs comme "." ou "bin". Les fichiers dans les répertoires absolus sont immédiatement mis en cache dans l'objet PathCache spécifié, tandis que les sous-répertoires, dont l'identité change évidemment à chaque fois que le répertoire de travail courant est changé, sont marqués pour être analysés à la volée chaque fois qu'un fichier est recherché.

En cas de succès, cette fonction retourne 0. En cas d'erreur, elle retourne 1, et une description de l'erreur peut être obtenue en appelant pca_last_error(pc).

RECHERCHER DES FICHIERS

Une fois que le cache a été rempli de fichiers, vous pouvez rechercher le nom de chemin complet d'un fichier, simplement en spécifiant son nom de fichier à pca_lookup_file().

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal);

Pour permettre à cette fonction de passer un nom de fichier qui est en fait partie d'une chaîne plus longue, l'argument name_len peut être utilisé pour spécifier la longueur du nom de fichier au début de l'argument name[]. Si vous passez -1 pour cette longueur, la longueur de la chaîne sera déterminée avec strlen(). Si la chaîne name[] peut contenir des antislashs qui échappent la signification spéciale des espaces et des tabulations dans le nom de fichier, donnez à l'argument literal la valeur 0. Sinon, si les antislashs doivent être traités comme des caractères normaux, passez 1 pour la valeur de l'argument literal.

COMPLETION DE NOM DE FICHIER

La recherche des complétions potentielles d'un préfixe de nom de fichier dans le cache de noms de fichiers, est réalisée en passant la fonction de rappel fournie pca_path_completions() à la fonction cpl_complete_word() (voir la page de manuel cpl_complete_word(3)).

  CPL_MATCH_FN(pca_path_completions);

Cette fonction de rappel nécessite que son argument data soit un pointeur vers un objet PcaPathConf. Les objets de configuration de ce type sont alloués en appelant new_PcaPathConf().

  PcaPathConf *new_PcaPathConf(PathCache *pc);

Cette fonction retourne un objet initialisé avec des paramètres de configuration par défaut, qui déterminent le comportement de la fonction de rappel cpl_path_completions(). Les fonctions qui vous permettent de modifier individuellement ces paramètres sont décrites ci-dessous.

Par défaut, la fonction de rappel pca_path_completions() recherche en arrière le début du nom de fichier en cours de complétion, à la recherche du premier espace non échappé ou du début de la ligne d'entrée. Si vous souhaitez spécifier un emplacement différent, appelez ppc_file_start() avec l'index où commence le nom de fichier dans la ligne d'entrée. Passer start_index=-1 réactive le comportement par défaut.

  void ppc_file_start(PcaPathConf *ppc, int start_index);

Par défaut, lorsque pca_path_completions() examine un nom de fichier dans la ligne d'entrée, chaque antislash isolé dans la ligne d'entrée est interprété comme un caractère spécial qui supprime toute signification spéciale du caractère qui le suit, comme un espace qui doit être considéré comme faisant partie du nom de fichier plutôt que de délimiter le début du nom de fichier. Ces antislashs sont donc ignorés lors de la recherche de complétions, et ajoutés ensuite avant les espaces, les tabulations et les antislashs littéraux dans la liste des complétions. Pour que les antislashs non échappés soient traités comme des caractères normaux, appelez ppc_literal_escapes() avec une valeur non nulle dans son argument literal.

  void ppc_literal_escapes(PcaPathConf *ppc, int literal);

Lorsque vous avez terminé avec une variable PcaPathConf, vous pouvez la passer à la fonction destructeur del_PcaPathConf() pour libérer sa mémoire.

  PcaPathConf *del_PcaPathConf(PcaPathConf *ppc);

ETRE SELECTIF

Si vous n'êtes intéressé que par certains types de fichiers, comme, par exemple, les fichiers exécutables, ou les fichiers dont les noms se terminent par un suffixe particulier, vous pouvez faire en sorte que les fonctions de complétion et de recherche de noms de fichiers soient sélectives quant aux noms de fichiers qu'elles retournent. Ceci est fait en enregistrant une fonction de rappel avec votre objet PathCache. pca_last_error(3) — libtecla — Arch Linux man pages

NAME

pca_last_error — retrieve the last error message

SYNOPSIS

  const char *pca_last_error(PathCache *pc);

DESCRIPTION

The pca_last_error() function returns a pointer to a string containing a terse description of the last error to have occurred in the specified PathCache object. If no error has occurred, it returns a pointer to an empty string.

The purpose of this function is to allow the caller to obtain more information when the functions of this module report an error by returning 1. This is primarily used in the case of pca_scan_path(), but may also be used by other functions if they fail.

The string returned by pca_last_error() is internal to the PathCache object, and may be overwritten by subsequent calls to the functions of this module. If you wish to keep the error message, you should copy it to your own buffer.

AN EXAMPLE

  PathCache *pc;
  const char *error;

  pc = new_PathCache();
  if (pca_scan_path(pc, PATH, 0) == 1) {
    error = pca_last_error(pc);
    fprintf(stderr, "Error scanning path: %s\n", error);
    exit(1);
  }

FUNCTION DESCRIPTIONS

The functions for manipulating the PathCache object are as follows:

PathCache *new_PathCache(void);
Allocates and returns a new PathCache object.
void del_PathCache(PathCache *pc);
Frees all resources associated with the PathCache object, and sets the pointer to NULL.
int pca_scan_path(PathCache *pc, const char *path, int flags);
Scans the directories specified in the path argument, and adds any matching files to the cache. Returns 1 if an error occurred, 0 otherwise. The flags argument is unused.
const char *pca_last_error(PathCache *pc);
Returns a pointer to a string describing the last error to have occurred in the PathCache object.
int pca_add_path(PathCache *pc, const char *pathname);
Adds a file to the cache, without scanning. Returns 1 if an error occurred, 0 otherwise.
int pca_match(PathCache *pc, const char *pattern);
Returns the number of files in the cache that match the given pattern.
int pca_match_first(PathCache *pc, const char *pattern);
Returns the first file in the cache that matches the given pattern, or NULL if no match is found.
int pca_match_next(PathCache *pc);
Returns the next file in the cache that matches the pattern specified in the previous call to pca_match_first(), or NULL if no more matches are found.
void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn, void *data);
Sets a callback function that will be called for each file that is added to the cache. The callback function should return 1 if the file should be considered a match, and 0 otherwise. The data argument can be used to pass application-specific data to the callback function.

POPULATING THE CACHE

The cache is populated by calling pca_scan_path(). This function takes a pointer to a PathCache object, a path string, and a set of flags. The path string can contain a list of directories separated by colons, similar to the PATH environment variable. The flags argument is currently unused.

When pca_scan_path() is called, it iterates through each directory in the path, and adds all files in each directory to the cache. If an error occurs during the scan (e.g., a directory does not exist or is inaccessible), pca_scan_path() will return 1, and the last error message can be retrieved using pca_last_error().

Alternatively, individual files can be added to the cache using pca_add_path().

LOOKING UP FILES

Files can be looked up in the cache using pca_match(), pca_match_first(), and pca_match_next().

pca_match() returns the total number of files in the cache that match the given pattern. The pattern is a shell-style wildcard string.

pca_match_first() and pca_match_next() can be used to iterate through the matching files. pca_match_first() initializes the search and returns the first matching file, or NULL if no match is found. Subsequent calls to pca_match_next() will return the next matching file, or NULL when the end of the matches is reached.

FILENAME COMPLETION

The primary purpose of the PathCache object is to facilitate filename completion. When used in conjunction with a line editing library like readline or gl_get_line(), it can be used to provide efficient filename completion.

The cache is populated with files from directories specified in the PATH environment variable. When the user requests completion, the library uses pca_match() to find matching files and presents them to the user.

BEING SELECTIVE

It is possible to provide a callback function that will be called for each file that is added to the cache. This callback function will be called with the full pathname of the file, plus any application-specific data that you provide, and if the callback returns 1 the filename will be reported as a match, and if it returns 0, it will be ignored. Suitable callback functions and their prototypes should be declared with the following macro. The CplCheckFn typedef is also provided in case you wish to declare pointers to such functions.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);

Registering one of these functions involves calling the pca_set_check_fn() function. In addition to the callback function, passed via the check_fn argument, you can pass a pointer to anything via the data argument. This pointer will be passed on to your callback function, via its own data argument, whenever it is called, so this provides a way to pass appplication specific data to your callback.

  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

Note that these callbacks are passed the full pathname of each matching file, so the decision about whether a file is of interest can be based on any property of the file, not just its filename. As an example, the provided cpl_check_exe() callback function looks at the executable permissions of the file and the permissions of its parent directories, and only returns 1 if the user has execute permission to the file. This callback function can thus be used to lookup or complete command names found in the directories listed in the user's PATH environment variable. The example program given earlier in this man page provides a demonstration of this.

Beware that if somebody tries to complete an empty string, your callback will get called once for every file in the cache, which could number in the thousands. If your callback does anything time consuming, this could result in an unacceptable delay for the user, so callbacks should be kept short.

To improve performance, whenever one of these callbacks is called, the choice that it makes is cached, and the next time the corresponding file is looked up, instead of calling the callback again, the cached record of whether it was accepted or rejected is used. Thus if somebody tries to complete an empty string, and hits tab a second time when nothing appears to happen, there will only be one long delay, since the second pass will operate entirely from the cached dispositions of the files. These cached dipositions are discarded whenever pca_scan_path() is called, and whenever pca_set_check_fn() is called with changed callback function or data arguments.

ERROR HANDLING

If pca_scan_path() reports that an error occurred by returning 1, you can obtain a terse description of the error by calling pca_last_error(pc). This returns an internal string containing an error message.

  const char *pca_last_error(PathCache *pc);

CLEANING UP

Once you have finished using a PathCache object, you can reclaim its resources by passing it to the del_PathCache() destructor function. This takes a pointer to one of these objects, and always returns NULL.

  PathCache *del_PathCache(PathCache *pc);

THREAD SAFETY

In multi-threaded programs, you should use the libtecla_r.a version of the library. This uses POSIX reentrant functions where available (hence the _r suffix), and disables features that rely on non-reentrant system functions. In the case of this module, the only disabled feature is username completion in ~username/ expressions, in cpl_path_completions().

Using the libtecla_r.a version of the library, it is safe to use the facilities of this module in multiple threads, provided that each thread uses a separately allocated PathCache object. In other words, if two threads want to do path searching, they should each call new_PathCache() to allocate their own caches.
