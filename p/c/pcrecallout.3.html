PCRECALLOUT(3) Manuel des fonctions de bibliothèque PCRECALLOUT(3)

NOM

PCRE - expressions régulières compatibles Perl

SYNOPSIS

#include <pcre.h>

int (*pcre_callout)(pcre_callout_block *);

int (*pcre16_callout)(pcre16_callout_block *);

int (*pcre32_callout)(pcre32_callout_block *);

DESCRIPTION

PCRE fournit une fonctionnalité appelée « appel externe » (callout), qui permet de passer temporairement le contrôle à l'appelant de PCRE pendant la correspondance de motifs. L'appelant de PCRE fournit une fonction externe en plaçant son point d'entrée dans la variable globale pcre_callout (pcre16_callout pour la bibliothèque 16 bits, pcre32_callout pour la bibliothèque 32 bits). Par défaut, cette variable contient NULL, ce qui désactive tous les appels externes.

Dans une expression régulière, (?C) indique les points où la fonction externe doit être appelée. Différents points d'appel externe peuvent être identifiés en plaçant un nombre inférieur à 256 après la lettre C. La valeur par défaut est zéro. Par exemple, ce motif a deux points d'appel externe :


(?C1)abc(?C2)def

Si le bit d'option PCRE_AUTO_CALLOUT est défini lors de la compilation d'un motif, PCRE insère automatiquement des appels externes, tous avec le numéro 255, avant chaque élément du motif. Par exemple, si PCRE_AUTO_CALLOUT est utilisé avec le motif


A(\d{2}|--)

il est traité comme s'il était

(?C255)A(?C255)(\d{2}(?C255)|(?C255)-(?C255)-(?C255))(?C255)

Remarquez qu'il y a un appel externe avant et après chaque parenthèse et chaque barre d'alternance. Si le motif contient un groupe conditionnel dont la condition est une assertion, un appel externe automatique est inséré immédiatement avant la condition. Un tel appel externe peut également être inséré explicitement, par exemple :


(?(?C9)(?=a)ab|de)

Ceci ne s'applique qu'aux conditions d'assertion (car elles sont elles-mêmes des groupes indépendants).

Les appels externes automatiques peuvent être utilisés pour suivre la progression de la correspondance de motifs. Le programme pcretest dispose d'un qualificateur de motif (/C) qui définit les appels externes automatiques ; lorsqu'il est utilisé, la sortie indique comment le motif est mis en correspondance. C'est une information utile lorsque vous essayez d'optimiser les performances d'un motif particulier.

APPELS EXTERNES MANQUANTS

Vous devez être conscient qu'en raison des optimisations dans la manière dont PCRE compile et fait correspondre les motifs, les appels externes ne se produisent parfois pas exactement comme vous pourriez vous y attendre.

Au moment de la compilation, PCRE « auto-possessifie » les éléments répétés lorsqu'il sait que ce qui suit ne peut pas faire partie de la répétition. Par exemple, a+[bc] est compilé comme s'il s'agissait de a++[bc]. La sortie de pcretest lorsque ce motif est ancré puis appliqué avec des appels externes automatiques à la chaîne « aaaa » est :


--->aaaa
+0 ^ ^
+1 ^ a+
+3 ^ ^ [bc]
Aucune correspondance

Cela indique que lorsque [bc] ne correspond pas, il n'y a pas de retour arrière dans a+ et par conséquent les appels externes qui seraient pris pour les retours arrière ne se produisent pas. Vous pouvez désactiver la fonctionnalité d'auto-possessification en passant PCRE_NO_AUTO_POSSESS à pcre_compile(), ou en commençant le motif par (*NO_AUTO_POSSESS). Si cela est fait dans pcretest (en utilisant le qualificateur /O), la sortie change pour ceci :


--->aaaa
+0 ^ ^
+1 ^ a+
+3 ^ ^ [bc]
+3 ^ ^ [bc]
+3 ^ ^ [bc]
+3 ^^ [bc]
Aucune correspondance

Cette fois, lorsque [bc] ne correspond pas, le moteur de recherche revient en arrière dans a+ et essaie à nouveau, de manière répétée, jusqu'à ce que a+ échoue lui-même.

D'autres optimisations qui fournissent des résultats rapides de « pas de correspondance » affectent également les appels externes. Par exemple, si le motif est


ab(?C4)cd

PCRE sait que toute chaîne correspondante doit contenir la lettre « d ». Si la chaîne sujet est « abyz », l'absence de « d » signifie que la correspondance ne commence jamais, et l'appel externe n'est jamais atteint. Cependant, avec « abyd », bien que le résultat soit toujours une absence de correspondance, l'appel externe est respecté.

Si le motif est étudié, PCRE connaît la longueur minimale d'une chaîne correspondante, et renverra immédiatement un résultat de « aucune correspondance » sans réellement exécuter de correspondance si le sujet n'est pas assez long, ou, pour les motifs non ancrés, s'il a été suffisamment parcouru.

Vous pouvez désactiver ces optimisations en passant l'option PCRE_NO_START_OPTIMIZE à la fonction de correspondance, ou en commençant le motif par (*NO_START_OPT). Cela ralentit le processus de correspondance, mais garantit que les appels externes tels que l'exemple ci-dessus sont respectés.

L'INTERFACE D'APPEL EXTERNE

Pendant la correspondance, lorsque PCRE atteint un point d'appel externe, la fonction externe définie par pcre_callout ou pcre[16|32]_callout est appelée (si elle est définie). Ceci s'applique à la correspondance normale et à la correspondance DFA. Le seul argument de la fonction d'appel externe est un pointeur vers un bloc pcre_callout ou pcre[16|32]_callout. Ces structures contiennent les champs suivants :


int version;
int callout_number;
int *offset_vector;
const char *subject; (version 8 bits)
PCRE_SPTR16 subject; (version 16 bits)
PCRE_SPTR32 subject; (version 32 bits)
int subject_length;
int start_match;
int current_position;
int capture_top;
int capture_last;
void *callout_data;
int pattern_position;
int next_item_length;
const unsigned char *mark; (version 8 bits)
const PCRE_UCHAR16 *mark; (version 16 bits)
const PCRE_UCHAR32 *mark; (version 32 bits)

Le champ version est un entier contenant le numéro de version du format du bloc. La version initiale était 0 ; la version actuelle est 2. Le numéro de version changera à nouveau à l'avenir si des champs supplémentaires sont ajoutés, mais l'intention est de ne jamais supprimer aucun des champs existants.

Le champ callout_number contient le numéro de l'appel externe, tel qu'il a été compilé dans le motif (c'est-à-dire le numéro après ?C pour les appels externes manuels, et 255 pour les appels externes générés automatiquement).

Le champ offset_vector est un pointeur vers le vecteur d'offsets qui a été passé par l'appelant à la fonction de correspondance. Lorsque pcre_exec() ou pcre[16|32]_exec() est utilisé, le contenu peut être inspecté, afin d'extraire les sous-chaînes qui ont été correspondant jusqu'à présent, de la même manière que pour l'extraction des sous-chaînes après la fin d'une correspondance. Pour les fonctions de correspondance DFA, ce champ n'est pas utile.

Les champs subject et subject_length contiennent des copies des valeurs qui ont été passées à la fonction de correspondance.

Le champ start_match contient normalement le décalage dans le sujet où la tentative de correspondance actuelle a commencé. Cependant, si la séquence d'échappement \K a été rencontrée, cette valeur est modifiée pour refléter le point de départ modifié. Si le motif n'est pas ancré, la fonction d'appel externe peut être appelée plusieurs fois à partir du même point du motif pour différents points de départ dans le sujet.

Le champ current_position contient le décalage dans le sujet du pointeur de correspondance actuel.

Lorsque pcre_exec() ou pcre[16|32]_exec() est utilisé, le champ capture_top contient une valeur supérieure au numéro de la sous-chaîne capturée la plus élevée jusqu'à présent. Si aucune sous-chaîne n'a été capturée, la valeur de capture_top est un. C'est toujours le cas lorsque les fonctions DFA sont utilisées, car elles ne prennent pas en charge les sous-chaînes capturées.

Le champ capture_last contient le numéro de la sous-chaîne la plus récemment capturée. Cependant, lorsqu'une récursion se termine, la valeur revient à ce qu'elle était en dehors de la récursion, tout comme les valeurs de toutes les sous-chaînes capturées. Si aucune sous-chaîne n'a été capturée, la valeur de capture_last est -1. C'est toujours le cas pour les fonctions de correspondance DFA.

Le champ callout_data contient une valeur qui est passée à une fonction de correspondance spécifiquement pour qu'elle puisse être renvoyée dans les appels externes. Elle est passée dans le champ callout_data d'une structure de données pcre_extra ou pcre[16|32]_extra. Si aucune donnée de ce type n'a été passée, la valeur de callout_data dans un bloc d'appel externe est NULL. Une description de la structure pcre_extra se trouve dans la documentation pcreapi.

Le champ pattern_position

pcrecallout(3) — PCRE 8.34

NAME

pcrecallout — PCRE callout interface

SYNOPSIS

#include <pcre.h>

int callback_function(int type, void *data, void *user_data);

DESCRIPTION

PCRE supports an optional callout mechanism that allows C code to be executed during the matching process. This is described in the pcrecallout manual page.

This page describes the interface between PCRE and the external callout function.

The callout function is called when a match is in progress. Its address is passed to the matching function via the callout_data argument.

The callout function is called with three arguments:

type
An integer specifying the type of callout. It is always PCRE_CALLOUT_SYMBOLIC for the symbolic callouts described here, unless the matching function was called with the PCRE_CALLOUT option, in which case the callout number is passed directly.
data
A pointer to a structure containing information about the current state of the match. The exact type of this structure depends on the version of PCRE and the version of the callout interface. The structure is always passed as a pointer to a pcre_callout_block structure. See below.
user_data
The same pointer that was passed as the user_data argument to the matching function (pcre_exec(), pcre16_exec(), or pcre32_exec()).

The callout function must return an integer value. The interpretation of this value is described in the RETURN VALUES section.

MISSING CALLOUTS

If PCRE is not compiled with PCRE_HAS_CALLOUT_SUPPORT defined, then the callout mechanism is not available. In this case, the callout_data argument to the matching function is ignored, and any callout function provided will never be called.

THE CALLOUT INTERFACE

The data argument to the callout function is a pointer to a structure of type pcre_callout_block, which is defined in the <pcre.h> header file. The structure's layout depends on the version of the callout interface that is being used. PCRE supports version 0, 1, and 2 of the interface.

The pcre_callout_block structure contains the following fields:

version
The version number of the callout block structure. This is 0, 1 or 2.
callout_number
The number specified in the pattern for this callout. For a simple callout like (?C), the number is 1. For (?123C) the number is 123.
pattern
A pointer to the start of the compiled regex string.
pattern_length
The length of the compiled regex string.
next_item_length
This field is present from version 1 of the callout structure. It contains the length of the next item to be matched in the pattern string. When the callout immediately precedes an alternation bar, a closing parenthesis, or the end of the pattern, the length is zero. When the callout precedes an opening parenthesis, the length is that of the entire subpattern.
pattern_position
This field is present from version 1 of the callout structure. It contains the offset to the next item to be matched in the pattern string.
next_item_length
The next_item_length field is present from version 1 of the callout structure. It contains the length of the next item to be matched in the pattern string. When the callout immediately precedes an alternation bar, a closing parenthesis, or the end of the pattern, the length is zero. When the callout precedes an opening parenthesis, the length is that of the entire subpattern.
pattern_position
The pattern_position and next_item_length fields are intended to help in distinguishing between different automatic callouts, which all have the same callout number. However, they are set for all callouts.
mark
The mark field is present from version 2 of the callout structure. In callouts from pcre_exec() or pcre[16|32]_exec() it contains a pointer to the zero-terminated name of the most recently passed (*MARK), (*PRUNE), or (*THEN) item in the match, or NULL if no such items have been passed. Instances of (*PRUNE) or (*THEN) without a name do not obliterate a previous (*MARK). In callouts from the DFA matching functions this field always contains NULL.

RETURN VALUES

The external callout function returns an integer to PCRE. If the value is zero, matching proceeds as normal. If the value is greater than zero, matching fails at the current point, but the testing of other matching possibilities goes ahead, just as if a lookahead assertion had failed. If the value is less than zero, the match is abandoned, the matching function returns the negative value.

Negative values should normally be chosen from the set of PCRE_ERROR_xxx values. In particular, PCRE_ERROR_NOMATCH forces a standard "no match" failure. The error number PCRE_ERROR_CALLOUT is reserved for use by callout functions; it will never be used by PCRE itself.
