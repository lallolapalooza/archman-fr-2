DESCRIPTION

L'objet PathCache fait partie de la bibliothèque tecla (voir la page de manuel libtecla(3)).

Les objets PathCache permettent à une application de rechercher des fichiers dans n'importe quelle liste de répertoires séparés par des deux-points, telle que la variable d'environnement PATH d'exécution Unix. Les fichiers dans les répertoires absolus sont mis en cache dans un objet PathCache, tandis que les répertoires relatifs sont analysés au besoin. En utilisant un objet PathCache, vous pouvez rechercher le chemin complet d'un nom de fichier simple, ou vous pouvez obtenir une liste des complétions possibles d'un préfixe de nom de fichier donné. Par défaut, tous les fichiers dans la liste des répertoires sont des cibles pour la recherche et la complétion, mais un mécanisme polyvalent est fourni pour ne sélectionner que des types de fichiers spécifiques. L'application évidente de cette fonctionnalité est de fournir la complétion par tabulation et la recherche de commandes exécutables dans le PATH Unix, donc une fonction de rappel optionnelle qui rejette tous les fichiers sauf les fichiers exécutables, est fournie.

UN EXEMPLE

Sous UNIX, l'exemple de programme suivant recherche et affiche les chemins complets de chaque nom de commande sur la ligne de commande.

  #include <stdio.h>
  #include <stdlib.h>
  #include <libtecla.h>
  int main(int argc, char *argv[])
  {
    int i;
  /*
   * Crée un cache pour les fichiers exécutables.
   */
    PathCache *pc = new_PathCache();
    if(!pc)
      exit(1);
  /*
   * Analyse le PATH de l'utilisateur à la recherche d'exécutables.
   */
    if(pca_scan_path(pc, getenv("PATH"))) {
      fprintf(stderr, "%s\n", pca_last_error(pc));
      exit(1);
    }
  /*
   * Configure pour ne signaler que les fichiers exécutables.
   */
   pca_set_check_fn(pc, cpl_check_exe, NULL);
  /*
   * Recherche et affiche le chemin complet de chacune des
   * commandes listées sur la ligne de commande.
   */
    for(i=1; i<argc; i++) {
      char *cmd = pca_lookup_file(pc, argv[i], -1, 0);
      printf("Le chemin complet de '%s' est %s\n", argv[i],
             cmd ? cmd : "inconnu");
    }
    pc = del_PathCache(pc);  /* Nettoyage */
    return 0;
  }

Voici un exemple de ce que cela fait sur mon ordinateur portable sous Linux :

  $ ./example less more blob
  Le chemin complet de 'less' est /usr/bin/less
  Le chemin complet de 'more' est /bin/more
  Le chemin complet de 'blob' est inconnu
  $

DESCRIPTIONS DES FONCTIONS

Pour utiliser les fonctionnalités de ce module, vous devez d'abord allouer un objet PathCache en appelant la fonction constructeur new_PathCache().

  PathCache *new_PathCache(void)

Cette fonction crée les ressources nécessaires pour mettre en cache et rechercher des fichiers dans une liste de répertoires. Elle retourne NULL en cas d'erreur.

POPOLATION DU CACHE

Une fois que vous avez créé un cache, il doit être peuplé de fichiers. Pour ce faire, appelez la fonction pca_scan_path().

  int pca_scan_path(PathCache *pc, const char *path);

Chaque fois que cette fonction est appelée, elle rejette le contenu actuel du cache, puis analyse la liste des répertoires spécifiés dans son argument path à la recherche de fichiers. L'argument path doit être une chaîne contenant une liste de répertoires séparés par des deux-points, telle que "/usr/bin:/home/mcs/bin:.". Cela peut inclure des répertoires spécifiés par des chemins absolus tels que "/usr/bin", ainsi que des sous-répertoires spécifiés par des chemins relatifs tels que "." ou "bin". Les fichiers dans les répertoires absolus sont immédiatement mis en cache dans l'objet PathCache spécifié, tandis que les sous-répertoires, dont l'identité change évidemment chaque fois que le répertoire de travail actuel est modifié, sont marqués pour être analysés à la volée chaque fois qu'un fichier est recherché.

En cas de succès, cette fonction retourne 0. En cas d'erreur, elle retourne 1, et une description de l'erreur peut être obtenue en appelant pca_last_error(pc).

RECHERCHE DE FICHIERS

Une fois que le cache a été peuplé de fichiers, vous pouvez rechercher le chemin complet d'un fichier, simplement en spécifiant son nom de fichier à pca_lookup_file().

  char *pca_lookup_file(PathCache *pc, const char *name,
                        int name_len, int literal);

Pour permettre de passer à cette fonction un nom de fichier qui fait en fait partie d'une chaîne plus longue, l'argument name_len peut être utilisé pour spécifier la longueur du nom de fichier au début de l'argument name[]. Si vous passez -1 pour cette longueur, la longueur de la chaîne sera déterminée avec strlen(). Si la chaîne name[] peut contenir des antislashs qui échappent à la signification spéciale des espaces et des tabulations dans le nom de fichier, donnez à l'argument literal la valeur 0. Sinon, si les antislashs doivent être traités comme des caractères normaux, passez 1 pour la valeur de l'argument literal.

COMPLETION DE NOMS DE FICHIER

La recherche des complétions potentielles d'un préfixe de nom de fichier dans le cache de noms de fichiers est réalisée en passant la fonction de rappel fournie pca_path_completions() à la fonction cpl_complete_word() (voir la page de manuel cpl_complete_word(3)).

  CPL_MATCH_FN(pca_path_completions);

Cette fonction de rappel nécessite que son argument data soit un pointeur vers un objet PcaPathConf. Les objets de configuration de ce type sont alloués en appelant new_PcaPathConf().

  PcaPathConf *new_PcaPathConf(PathCache *pc);

Cette fonction retourne un objet initialisé avec des paramètres de configuration par défaut, qui déterminent le comportement de la fonction de rappel cpl_path_completions(). Les fonctions qui vous permettent de modifier individuellement ces paramètres sont décrites ci-dessous.

Par défaut, la fonction de rappel pca_path_completions() recherche en arrière le début du nom de fichier en cours de complétion, en cherchant le premier espace non échappé ou le début de la ligne d'entrée. Si vous souhaitez spécifier un emplacement différent, appelez ppc_file_start() avec l'index où commence le nom de fichier dans la ligne d'entrée. Passer start_index=-1 réactive le comportement par défaut.

  void ppc_file_start(PcaPathConf *ppc, int start_index);

Par défaut, lorsque pca_path_completions() examine un nom de fichier dans la ligne d'entrée, chaque antislash isolé dans la ligne d'entrée est interprété comme un caractère spécial qui supprime toute signification spéciale du caractère qui le suit, tel qu'un espace qui doit être considéré comme faisant partie du nom de fichier plutôt que comme délimitant le début du nom de fichier. Ces antislashs sont donc ignorés lors de la recherche de complétions, et sont ensuite ajoutés avant les espaces, les tabulations et les antislashs littéraux dans la liste des complétions. Pour que les antislashs non échappés soient traités comme des caractères normaux, appelez ppc_literal_escapes() avec une valeur non nulle pour son argument literal.

  void ppc_literal_escapes(PcaPathConf *ppc, int literal);

Lorsque vous avez terminé avec une variable PcaPathConf, vous pouvez la passer à la fonction destructeur del_PcaPathConf() pour récupérer sa mémoire.

  PcaPathConf *del_PcaPathConf(PcaPathConf *ppc);

ÊTRE SÉLECTIF

Si vous n'êtes intéressé que par certains types de fichiers, tels que, par exemple, les fichiers exécutables, ou les fichiers dont le nom se termine par un suffixe particulier, vous pouvez faire en sorte que les fonctions de complétion et de recherche de fichiers soient sélectives dans les noms de fichiers qu'elles retournent. Ceci est fait en enregistrant une fonction de rappel avec votre objet PathCache. pca_set_check_fn(3)

NAME

pca_set_check_fn, CplCheckFn - pca_set_check_fn() sets a callback function used to filter files for completion.

SYNOPSIS

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);

  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

DESCRIPTION

The pca_set_check_fn() function allows the application to register a callback function with a PathCache object. This callback function is invoked when the cache is being populated by pca_scan_path(), or when file lookups are being performed by functions such as pca_find_files(). The purpose of this callback is to allow the application to selectively filter the files that are stored in the cache, or that are returned as potential completions.

AN EXAMPLE

  /* A callback that accepts only files that the current user can execute. */
  int my_check_exe(void *data, const char *pathname)
  {
    /* data is unused in this example */
    return (access(pathname, X_OK) == 0);
  }

  /* ... somewhere later ... */
  PathCache *pc = new_PathCache();
  if (pc) {
    pca_set_check_fn(pc, my_check_exe, NULL);
    pca_scan_path(pc, getenv("PATH"), PCA_FOLLOW_LINKS);
    /* ... use the cache ... */
    del_PathCache(pc);
  }

FUNCTION DESCRIPTIONS

The callback function will be called with the full pathname of the file, plus any application-specific data that you provide, and if the callback returns 1 the filename will be reported as a match, and if it returns 0, it will be ignored. Suitable callback functions and their prototypes should be declared with the following macro. The CplCheckFn typedef is also provided in case you wish to declare pointers to such functions.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);

Registering one of these functions involves calling the pca_set_check_fn() function. In addition to the callback function, passed via the check_fn argument, you can pass a pointer to anything via the data argument. This pointer will be passed on to your callback function, via its own data argument, whenever it is called, so this provides a way to pass appplication specific data to your callback.

  void pca_set_check_fn(PathCache *pc, CplCheckFn *check_fn,
                        void *data);

Note that these callbacks are passed the full pathname of each matching file, so the decision about whether a file is of interest can be based on any property of the file, not just its filename. As an example, the provided cpl_check_exe() callback function looks at the executable permissions of the file and the permissions of its parent directories, and only returns 1 if the user has execute permission to the file. This callback function can thus be used to lookup or complete command names found in the directories listed in the user's PATH environment variable. The example program given earlier in this man page provides a demonstration of this.

Beware that if somebody tries to complete an empty string, your callback will get called once for every file in the cache, which could number in the thousands. If your callback does anything time consuming, this could result in an unacceptable delay for the user, so callbacks should be kept short.

To improve performance, whenever one of these callbacks is called, the choice that it makes is cached, and the next time the corresponding file is looked up, instead of calling the callback again, the cached record of whether it was accepted or rejected is used. Thus if somebody tries to complete an empty string, and hits tab a second time when nothing appears to happen, there will only be one long delay, since the second pass will operate entirely from the cached dispositions of the files. These cached dipositions are discarded whenever pca_scan_path() is called, and whenever pca_set_check_fn() is called with changed callback function or data arguments.

ERROR HANDLING

If pca_scan_path() reports that an error occurred by returning 1, you can obtain a terse description of the error by calling pca_last_error(pc). This returns an internal string containing an error message.

  const char *pca_last_error(PathCache *pc);

CLEANING UP

Once you have finished using a PathCache object, you can reclaim its resources by passing it to the del_PathCache() destructor function. This takes a pointer to one of these objects, and always returns NULL.

  PathCache *del_PathCache(PathCache *pc);

THREAD SAFETY

In multi-threaded programs, you should use the libtecla_r.a version of the library. This uses POSIX reentrant functions where available (hence the _r suffix), and disables features that rely on non-reentrant system functions. In the case of this module, the only disabled feature is username completion in ~username/ expressions, in cpl_path_completions().

Using the libtecla_r.a version of the library, it is safe to use the facilities of this module in multiple threads, provided that each thread uses a separately allocated PathCache object. In other words, if two threads want to do path searching, they should each call new_PathCache() to allocate their own caches.
