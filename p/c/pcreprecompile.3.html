NOM

PCRE - Expressions régulières compatibles Perl

SAUVEGARDER ET RÉUTILISER LES MOTIFS PCRE PRÉCOMPILÉS

Si vous exécutez une application qui utilise un grand nombre de motifs d'expressions régulières, il peut être utile de les stocker sous une forme précompilée au lieu de devoir les compiler à chaque exécution de l'application. Si vous n'utilisez aucune table de caractères privées (voir la documentation de pcre_maketables()), cela est relativement simple. Si vous utilisez des tables privées, c'est un peu plus compliqué. Cependant, si vous utilisez la fonctionnalité d'optimisation "just-in-time", il n'est pas possible de sauvegarder et de recharger les données JIT.

Si vous sauvegardez des motifs compilés dans un fichier, vous pouvez les copier sur un autre hôte et les exécuter là-bas. Si les deux hôtes ont une endianness (ordre des octets) différente, vous devriez exécuter la fonction pcre[16|32]_pattern_to_host_byte_order() sur le nouvel hôte avant d'essayer de faire correspondre le motif. Les fonctions de correspondance retournent PCRE_ERROR_BADENDIANNESS si elles détectent un motif avec la mauvaise endianness.

Compiler des expressions régulières avec une version de PCRE pour une utilisation avec une autre version n'est pas garanti de fonctionner et peut provoquer des plantages, et sauvegarder et restaurer un motif compilé perd toutes les données d'optimisation JIT.

SAUVEGARDER UN MOTIF COMPILÉ

La valeur retournée par pcre[16|32]_compile() pointe vers un bloc de mémoire unique qui contient le motif compilé et les données associées. Vous pouvez trouver la longueur de ce bloc en octets en appelant pcre[16|32]_fullinfo() avec l'argument PCRE_INFO_SIZE. Vous pouvez ensuite sauvegarder les données de manière appropriée. Voici un exemple de code pour la bibliothèque 8 bits qui compile un motif et l'écrit dans un fichier. Il suppose que la variable fd fait référence à un fichier ouvert en sortie :


int erroroffset, rc, size;
char *error;
pcre *re;


re = pcre_compile("mon motif", 0, &error, &erroroffset, NULL);
if (re == NULL) { ... gérer les erreurs ... }
rc = pcre_fullinfo(re, NULL, PCRE_INFO_SIZE, &size);
if (rc < 0) { ... gérer les erreurs ... }
rc = fwrite(re, 1, size, fd);
if (rc != size) { ... gérer les erreurs ... }

Dans cet exemple, les octets qui composent le motif compilé sont copiés exactement. Notez qu'il s'agit de données binaires qui peuvent contenir n'importe laquelle des 256 valeurs d'octets possibles. Sur les systèmes qui font une distinction entre les données binaires et non binaires, assurez-vous que le fichier est ouvert pour une sortie binaire.

Si vous souhaitez écrire plus d'un motif dans un fichier, vous devrez concevoir un moyen de les séparer. Pour les données binaires, précéder chaque motif de sa longueur est probablement l'approche la plus simple. Une autre possibilité est d'écrire les données en hexadécimal au lieu de binaire, un motif par ligne.

La sauvegarde de motifs compilés dans un fichier n'est qu'une façon possible de les stocker pour une utilisation ultérieure. Ils pourraient tout aussi bien être sauvegardés dans une base de données, ou dans la mémoire d'un processus démon qui les transmettrait via des sockets aux processus qui les souhaitent.

Si le motif a été étudié, il est également possible de sauvegarder les données d'étude normales de la même manière que le motif compilé lui-même. Cependant, si PCRE_STUDY_JIT_COMPILE a été utilisé, les données "just-in-time" créées ne peuvent pas être sauvegardées car elles dépendent trop de l'environnement actuel. Lorsque l'étude génère des informations supplémentaires, pcre[16|32]_study() retourne un pointeur vers un bloc de données pcre[16|32]_extra. Son format est défini dans la section sur la correspondance d'un motif dans la documentation pcreapi. Le champ study_data pointe vers les données d'étude binaires, et c'est ce que vous devez sauvegarder (pas le bloc pcre[16|32]_extra lui-même). La longueur des données d'étude peut être obtenue en appelant pcre[16|32]_fullinfo() avec l'argument PCRE_INFO_STUDYSIZE. N'oubliez pas de vérifier que pcre[16|32]_study() a bien retourné une valeur non NULL avant d'essayer de sauvegarder les données d'étude.

RÉUTILISER UN MOTIF PRÉCOMPILÉ

La réutilisation d'un motif précompilé est simple. Après l'avoir rechargé en mémoire principale, appelé pcre[16|32]_pattern_to_host_byte_order() si nécessaire, vous passez son pointeur à pcre[16|32]_exec() ou pcre[16|32]_dfa_exec() comme d'habitude.

Cependant, si vous avez passé un pointeur vers des tables de caractères personnalisées lors de la compilation du motif (l'argument tableptr de pcre[16|32]_compile()), vous devez maintenant passer un pointeur similaire à pcre[16|32]_exec() ou pcre[16|32]_dfa_exec(), car la valeur sauvegardée avec le motif compilé sera évidemment absurde. Un champ dans un bloc pcre[16|32]_extra() est utilisé pour passer ces données, comme décrit dans la section sur la correspondance d'un motif dans la documentation pcreapi.

Attention: Les tables utilisées par pcre_exec() et pcre_dfa_exec() doivent être les mêmes que celles utilisées lors de la compilation du motif. Si ce n'est pas le cas, le comportement est indéfini.

Si vous n'avez pas fourni de tables de caractères personnalisées lors de la compilation du motif, le pointeur dans le motif compilé est NULL, ce qui amène les fonctions de correspondance à utiliser les tables internes de PCRE. Ainsi, vous n'avez pas besoin de prendre de mesures spéciales au moment de l'exécution dans ce cas.

Si vous avez sauvegardé des données d'étude avec le motif compilé, vous devez créer votre propre bloc de données pcre[16|32]_extra et définir le champ study_data pour qu'il pointe vers les données d'étude rechargées. Vous devez également définir le bit PCRE_EXTRA_STUDY_DATA dans le champ flags pour indiquer que les données d'étude sont présentes. Ensuite, passez le bloc pcre[16|32]_extra à la fonction de correspondance comme d'habitude. Si le motif a été étudié pour l'optimisation "just-in-time", ces données ne peuvent pas être sauvegardées et sont donc perdues lors d'un cycle de sauvegarde/restauration.

COMPATIBILITÉ AVEC DIFFÉRENTES VERSIONS DE PCRE

En général, il est plus sûr de recompiler tous les motifs sauvegardés lorsque vous mettez à jour vers une nouvelle version de PCRE, bien que toutes les mises à jour ne l'exigent pas.
