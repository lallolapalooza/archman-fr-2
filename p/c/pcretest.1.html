PCRETEST(1) Manuel des commandes générales PCRETEST(1)

NOM

pcretest - un programme pour tester les expressions régulières compatibles Perl.

SYNTAXE

pcretest [options] [fichier d'entrée [fichier de sortie]]

pcretest a été écrit comme un programme de test pour la bibliothèque d'expressions régulières PCRE elle-même, mais il peut également être utilisé pour expérimenter avec des expressions régulières. Ce document décrit les fonctionnalités du programme de test ; pour les détails sur les expressions régulières elles-mêmes, voir la documentation pcrepattern. Pour les détails sur les appels de fonction de la bibliothèque PCRE et leurs options, voir la documentation pcreapi, pcre16 et pcre32.

L'entrée de pcretest est une séquence de motifs d'expression régulière et de chaînes à faire correspondre, comme décrit ci-dessous. La sortie montre le résultat de chaque correspondance. Les options sur la ligne de commande et les motifs contrôlent les options PCRE et exactement ce qui est affiché.

Alors que PCRE a évolué, il a acquis de nombreuses fonctionnalités différentes, et en conséquence, pcretest a maintenant pas mal d'options obscures pour tester toutes les fonctionnalités possibles. Certaines de ces options sont spécifiquement conçues pour être utilisées en conjonction avec le script de test et les fichiers de données distribués dans le cadre de PCRE, et ne sont probablement pas utiles autrement. Elles sont toutes documentées ici, mais sans beaucoup de justification.

FORMAT DES DONNÉES D'ENTRÉE

L'entrée de pcretest est traitée ligne par ligne, soit en appelant la fonction fgets() de la bibliothèque C, soit via la bibliothèque libreadline (voir ci-dessous). Dans les environnements de type Unix, fgets() traite tous les octets autres que la nouvelle ligne comme des caractères de données. Cependant, dans certains environnements Windows, le caractère 26 (hex 1A) provoque une fin de fichier immédiate, et aucune donnée supplémentaire n'est lue. Pour une portabilité maximale, il est donc préférable de n'utiliser que des caractères ASCII dans les fichiers d'entrée pcretest.

L'entrée est traitée à l'aide des fonctions de chaînes de caractères de C, elle ne doit donc pas contenir de zéros binaires, même si dans les environnements de type Unix, fgets() traite tous les octets autres que la nouvelle ligne comme des caractères de données.

BIBLIOTHÈQUES 8-BITS, 16-BITS ET 32-BITS DE PCRE

À partir de la version 8.30, deux bibliothèques PCRE distinctes peuvent être compilées. L'originale prend en charge les chaînes de caractères 8 bits, tandis que la nouvelle bibliothèque 16 bits prend en charge les chaînes de caractères encodées en unités de 16 bits. À partir de la version 8.32, une troisième bibliothèque peut être compilée, prenant en charge les chaînes de caractères encodées en unités de 32 bits. Le programme pcretest peut être utilisé pour tester les trois bibliothèques. Cependant, il s'agit lui-même toujours d'un programme 8 bits, lisant une entrée 8 bits et écrivant une sortie 8 bits. Lors du test de la bibliothèque 16 bits ou 32 bits, les motifs et les chaînes de données sont convertis au format 16 ou 32 bits avant d'être passés aux fonctions de la bibliothèque PCRE. Les résultats sont convertis en 8 bits pour la sortie.

Les références aux fonctions et structures de la forme pcre[16|32]_xx ci-dessous signifient "pcre_xx lors de l'utilisation de la bibliothèque 8 bits, pcre16_xx lors de l'utilisation de la bibliothèque 16 bits, ou pcre32_xx lors de l'utilisation de la bibliothèque 32 bits".

OPTIONS DE LA LIGNE DE COMMANDE

-8
Si la bibliothèque 8 bits a été compilée, cette option l'utilise (c'est le défaut). Si la bibliothèque 8 bits n'a pas été compilée, cette option provoque une erreur.
-16
Si la bibliothèque 16 bits a été compilée, cette option l'utilise. Si seule la bibliothèque 16 bits a été compilée, c'est le défaut. Si la bibliothèque 16 bits n'a pas été compilée, cette option provoque une erreur.
-32
Si la bibliothèque 32 bits a été compilée, cette option l'utilise. Si seule la bibliothèque 32 bits a été compilée, c'est le défaut. Si la bibliothèque 32 bits n'a pas été compilée, cette option provoque une erreur.
-b
Se comporte comme si chaque motif avait le modificateur /B (afficher le code octet) ; la forme interne est affichée après compilation.
-C
Affiche le numéro de version de la bibliothèque PCRE, ainsi que toutes les informations disponibles sur les fonctionnalités optionnelles incluses, puis quitte avec un code de sortie zéro. Toutes les autres options sont ignorées.
-C option
Affiche des informations sur une option de compilation spécifique, puis quitte. Cette fonctionnalité est destinée à être utilisée dans des scripts tels que RunTest. Les options suivantes affichent la valeur et définissent le code de sortie comme indiqué :

code de sortie défini sur la taille de lien

Si une option inconnue est donnée, un message d'erreur est affiché ; le code de sortie est 0.

-d
Se comporte comme si chaque motif avait le modificateur /D (débogage) ; la forme interne et les informations sur le motif compilé sont affichées après compilation ; -d équivaut à -b -i.
-dfa
Se comporte comme si chaque ligne de données contenait la séquence d'échappement \D ; cela provoque l'utilisation de la fonction de correspondance alternative, pcre[16|32]_dfa_exec(), au lieu de la fonction standard pcre[16|32]_exec() (plus de détails ci-dessous).
-help
Affiche un bref résumé de ces options puis quitte.
-i
Se comporte comme si chaque motif avait le modificateur /I ; des informations sur le motif compilé sont fournies après compilation.
-M
Se comporte comme si chaque ligne de données contenait la séquence d'échappement \M ; cela provoque la découverte par PCRE des limites minimales MATCH_LIMIT et MATCH_LIMIT_RECURSION en appelant pcre[16|32]_exec() de manière répétée avec des limites différentes.
-m
Affiche la taille de chaque motif compilé après sa compilation. Ceci est équivalent à ajouter /M à chaque expression régulière. La taille est donnée en octets pour les deux bibliothèques.
-O
Se comporte comme si chaque motif avait le modificateur /O, c'est-à-dire désactive la posséssification automatique pour tous les motifs.
-o taille_sortie
Définit le nombre d'éléments dans le vecteur de sortie utilisé lors de l'appel de pcre[16|32]_exec() ou pcre[16|32]_dfa_exec() à taille_sortie. La valeur par défaut est 45, ce qui est suffisant pour 14 sous-expressions capturantes pour pcre[16|32]_exec() ou 22 correspondances différentes pour pcre[16|32]_dfa_exec(). La taille du vecteur peut être modifiée pour des appels de correspondance individuels en incluant \O dans la ligne de données (voir ci-dessous).
-p
Se comporte comme si chaque motif avait le modificateur /P, c'est-à-dire l'API wrapper POSIX est utilisée pour appeler PCRE. Aucune des autres options n'a d'effet lorsque -p est défini. Cette option ne peut être utilisée qu'avec la bibliothèque 8 bits.

N'affiche pas le numéro de version de pcretest au début de l'exécution.
-S taille
Sur les systèmes de type Unix, définit la taille de la pile d'exécution à taille mégaoctets.

Ce comportement signifie que la sortie des tests exécutés avec et sans -s doit être identique, sauf lorsque les options qui affichent des informations sur l'exécution réelle d'une correspondance sont définies.

Les options -M, -t et -tm, qui donnent des informations sur les ressources utilisées, sont susceptibles de produire une sortie différente avec et sans -s. La sortie peut également différer si l'option /C est présente sur un modèle individuel. Celle-ci utilise des appels pour suivre le processus de correspondance, et cela peut différer entre les modèles étudiés et non étudiés. Si le modèle contient des éléments (*MARK), il peut également y avoir des différences, pour la même raison. L'option de ligne de commande -s peut être remplacée pour des modèles spécifiques qui ne doivent jamais être étudiés (voir le modificateur de modèle /S ci-dessous).

-t
Exécute chaque compilation, étude et correspondance plusieurs fois avec un chronomètre, et affiche les temps résultants par compilation, étude ou correspondance (en millisecondes). Ne définissez pas -m avec -t, car vous obtiendrez alors la sortie de la taille une foule de fois, et le chronométrage sera faussé. Vous pouvez contrôler le nombre d'itérations utilisées pour le chronométrage en faisant suivre -t d'un nombre (comme élément séparé sur la ligne de commande). Par exemple, « -t 1000 » itère 1000 fois. La valeur par défaut est d'itérer 500000 fois.
-tm
Ceci est similaire à -t sauf qu'il ne chronomètre que la phase de correspondance, pas les phases de compilation ou d'étude.
-T -TM
Ceux-ci se comportent comme -t et -tm, mais en plus, à la fin d'une exécution, les temps totaux pour toutes les compilations, études et correspondances sont affichés.

DESCRIPTION

Si pcretest reçoit deux arguments de nom de fichier, il lit depuis le premier et écrit dans le second. S'il ne reçoit qu'un seul argument de nom de fichier, il lit depuis ce fichier et écrit sur stdout. Sinon, il lit depuis stdin et écrit sur stdout, et demande chaque ligne d'entrée, en utilisant « re> » pour demander les expressions régulières et « data> » pour demander les lignes de données.

Lorsque pcretest est construit, une option de configuration peut spécifier qu'il doit être lié à la bibliothèque libreadline. Lorsque cela est fait, si l'entrée provient d'un terminal, elle est lue à l'aide de la fonction readline(). Cela fournit des fonctionnalités d'édition de ligne et d'historique. La sortie de l'option -help indique si readline() sera utilisé ou non.

Le programme gère un nombre quelconque d'ensembles d'entrées sur un seul fichier d'entrée. Chaque ensemble commence par une expression régulière et se poursuit avec un nombre quelconque de lignes de données à faire correspondre à ce modèle.

Chaque ligne de données est mise en correspondance séparément et indépendamment. Si vous souhaitez effectuer des correspondances multilignes, vous devez utiliser la séquence d'échappement \n (ou \r ou \r\n, etc., selon le réglage de la nouvelle ligne) dans une seule ligne d'entrée pour encoder les séquences de nouvelle ligne. Il n'y a pas de limite à la longueur des lignes de données ; le tampon d'entrée est automatiquement étendu s'il est trop petit.

Une ligne vide signale la fin des lignes de données, moment auquel une nouvelle expression régulière est lue. Les expressions régulières sont fournies entourées de délimiteurs non alphanumériques autres que l'antislash, par exemple :


/(a|bc)x+yz/

Les espaces avant le délimiteur initial sont ignorés. Une expression régulière peut être étendue sur plusieurs lignes d'entrée, auquel cas les caractères de nouvelle ligne y sont inclus. Il est possible d'inclure le délimiteur dans le modèle en l'échappant, par exemple


/abc\/def/

Si vous le faites, l'échappement et le délimiteur font partie du modèle, mais comme les délimiteurs sont toujours non alphanumériques, cela n'affecte pas leur interprétation. Si le délimiteur de terminaison est immédiatement suivi d'un antislash, par exemple,


/abc/\

alors un antislash est ajouté à la fin du modèle. Ceci est fait pour fournir un moyen de tester la condition d'erreur qui survient si un modèle se termine par un antislash, car


/abc\/

est interprété comme la première ligne d'un modèle qui commence par « abc/ », provoquant la lecture par pcretest de la ligne suivante comme une continuation de l'expression régulière.

Trouver toutes les correspondances dans une chaîne

La recherche de toutes les correspondances possibles dans chaque chaîne sujet peut être demandée par le modificateur /g ou /G. Après avoir trouvé une correspondance, PCRE est rappelé pour rechercher dans le reste de la chaîne sujet. La différence entre /g et /G est que le premier utilise l'argument startoffset de pcre[16|32]_exec() pour commencer la recherche à un nouveau point dans la chaîne entière (ce qui est en effet ce que fait Perl), tandis que le second passe outre une sous-chaîne raccourcie. Cela fait une différence pour le processus de correspondance si le modèle commence par une assertion lookbehind (y compris \b ou \B).

Si un appel à pcre[16|32]_exec() dans une séquence /g ou /G correspond à une chaîne vide, le prochain appel est effectué avec les indicateurs PCRE_NOTEMPTY_ATSTART et PCRE_ANCHORED définis afin de rechercher une autre correspondance non vide, au même point. Si cette seconde correspondance échoue, le décalage de départ est avancé, et la correspondance normale est retentée. Cela imite la façon dont Perl gère de tels cas lorsqu'il utilise le modificateur /g ou la fonction split(). Normalement, le décalage de départ est avancé d'un caractère, mais si la convention de nouvelle ligne reconnaît CRLF comme nouvelle ligne, et que le caractère actuel est CR suivi de LF, une avance de deux est utilisée.

Autres modificateurs

Il existe encore d'autres modificateurs pour contrôler le fonctionnement de pcretest.

Le modificateur /+ demande qu'en plus de la sortie de la sous-chaîne qui correspond au modèle entier, pcretest sorte également le reste de la chaîne sujet. Ceci est utile pour les tests où le sujet contient plusieurs copies de la même sous-chaîne. Si le modificateur + apparaît deux fois, la même action est effectuée pour les sous-chaînes capturées. Dans chaque cas, le reste est affiché sur la ligne suivante avec un caractère plus suivant le numéro de capture. Notez que ce modificateur ne doit pas suivre immédiatement le modificateur /S car /S+ et /S++ ont d'autres significations.

Le modificateur /= demande que les valeurs de tous les parenthèses capturées potentielles soient affichées après une correspondance. Par défaut, seules celles jusqu'à la plus haute effectivement utilisée dans la correspondance sont affichées (correspondant au code de retour de pcre[16|32]_exec()). Les valeurs dans le vecteur des décalages correspondant aux nombres plus élevés doivent être définies sur -1, et celles-ci sont affichées comme "<non défini>". Ce modificateur donne un moyen de vérifier que cela se produit.

Le modificateur /B est une fonctionnalité de débogage. Il demande que pcretest affiche une représentation du code compilé après la compilation. Normalement, ces informations contiennent des valeurs de longueur et de décalage ; cependant, si /Z est également présent, ces données sont remplacées par des espaces. Ceci est une fonctionnalité spéciale pour une utilisation dans les scripts de test automatiques ; elle garantit que la même sortie est générée pour différentes tailles de liens internes.

Le modificateur /D est une fonctionnalité de débogage PCRE, et est équivalent à /BI, c'est-à-dire aux modificateurs /B et /I.

Le modificateur /F fait que pcretest inverse l'ordre des octets des champs de 2 et 4 octets dans le modèle compilé. Cette facilité est destinée à tester la fonctionnalité de PCRE qui lui permet d'exécuter des modèles compilés sur un hôte avec une endiannité différente. Cette fonctionnalité n'est pas disponible lorsque l'interface POSIX de PCRE est utilisée, c'est-à-dire lorsque le modificateur de modèle /P est spécifié. Voir également la section sur la sauvegarde et le rechargement des modèles compilés ci-dessous.

Le modificateur /I demande que pcretest affiche des informations sur le modèle compilé (s'il est ancré, s'il a un premier caractère fixe, etc.). Il le fait en appelant pcre[16|32]_fullinfo() après la compilation d'un modèle. Si le modèle est étudié, les résultats de cela sont également affichés. Dans cette sortie, le mot "char" signifie un caractère non-UTF, c'est-à-dire la valeur d'un élément de données unique (8 bits, 16 bits ou 32 bits, selon la bibliothèque testée).

Le modificateur /K demande à pcretest d'afficher les noms des verbes de contrôle de backtracking qui sont retournés par les appels à pcre[16|32]_exec(). Il fait créer à pcretest un bloc pcre[16|32]_extra s'il n'en a pas déjà été créé par un appel à pcre[16|32]_study(), et de définir l'indicateur PCRE_EXTRA_MARK et le champ mark à l'intérieur de celui-ci, chaque fois que pcre[16|32]_exec() est appelé. Si la variable vers laquelle pointe le champ mark est non-NULL lors d'une correspondance, d'une non-correspondance, ou d'une correspondance partielle, pcretest imprime la chaîne à laquelle il pointe. Pour une correspondance, cela est montré sur une ligne séparée, étiquetée avec "MK:". Pour une non-correspondance, cela est ajouté au message.

Le modificateur /L doit être suivi directement du nom d'une locale, par exemple,


/pattern/Lfr_FR

Pour cette raison, il doit être le dernier modificateur. La locale donnée est définie, pcre[16|32]_maketables() est appelée pour construire un ensemble de tables de caractères pour la locale, et cela est ensuite passé à pcre[16|32]_compile() lors de la compilation de l'expression régulière. Sans modificateur /L (ou /T), NULL est passé comme pointeur de tables ; c'est-à-dire que /L ne s'applique qu'à l'expression sur laquelle il apparaît.

Le modificateur /M demande que la taille en octets du bloc mémoire utilisé pour contenir le modèle compilé soit affichée. Cela n'inclut pas la taille du bloc pcre[16|32] ; il s'agit uniquement des données compilées réelles. Si le modèle est étudié avec succès avec l'option PCRE_STUDY_JIT_COMPILE, la taille du code compilé JIT est également affichée.

Le modificateur /Q est utilisé pour tester l'utilisation de pcre_stack_guard. Il doit être suivi de '0' ou '1', spécifiant le code de retour à donner par une fonction externe passée à PCRE et utilisée pour la vérification de la pile pendant la compilation (voir la documentation de pcreapi pour plus de détails).

Le modificateur /S fait que pcre[16|32]_study() soit appelé après la compilation de l'expression, et les résultats sont utilisés lors de la correspondance de l'expression. Il existe un certain nombre de caractères qualifiants qui peuvent suivre /S. Ils peuvent apparaître dans n'importe quel ordre.

Si /S est suivi d'un point d'exclamation, pcre[16|32]_study() est appelé avec l'option PCRE_STUDY_EXTRA_NEEDED, ce qui fait qu'il retourne toujours un bloc pcre_extra, même lorsque l'étude ne découvre aucune information utile.

Si /S est suivi d'un second caractère S, il supprime l'étude, même si elle a été demandée en externe par l'option de ligne de commande -s. Cela permet de spécifier que certains modèles sont toujours étudiés, et d'autres jamais, indépendamment de -s. Cette fonctionnalité est utilisée dans les fichiers de test dans quelques cas où la sortie est différente lorsque le modèle est étudié.

Si le modificateur /S est suivi d'un caractère +, l'appel à pcre[16|32]_study() est effectué avec toutes les options d'étude JIT, demandant le support d'optimisation juste-à-temps si disponible, pour la correspondance normale et partielle. Si vous souhaitez restreindre les modes de compilation JIT, vous pouvez suivre /S+ d'un chiffre dans la plage de 1 à 7 :


1 correspondance normale uniquement
2 correspondance partielle douce uniquement
3 correspondance normale et partielle douce
4 correspondance partielle dure uniquement
6 correspondance partielle douce et dure
7 tous les trois modes (par défaut)

Si /S++ est utilisé au lieu de /S+ (avec ou sans chiffre suivant), le texte "(JIT)" est ajouté à la première ligne de sortie après une correspondance ou une non-correspondance lorsque le code compilé JIT a effectivement été utilisé.

Notez qu'il existe également un modificateur indépendant /+ ; il ne doit pas être donné immédiatement après /S ou /S+ car cela serait mal interprété.

Si l'étude JIT réussit, le code JIT compilé sera automatiquement utilisé lorsque pcre[16|32]_exec() est exécuté, sauf lorsque des options d'exécution incompatibles sont spécifiées. Pour plus de détails, voir la documentation de pcrejit. Voir également la séquence d'échappement \J ci-dessous pour un moyen de définir la taille de la pile JIT.

Enfin, si /S est suivi d'un caractère moins, la compilation JIT est supprimée, même si elle a été demandée en externe par l'option de ligne de commande -s. Cela permet de spécifier que JIT ne doit jamais être utilisé pour certains modèles.

Le modificateur /T doit être suivi d'un seul chiffre. Il fait passer un ensemble spécifique de tables de caractères intégrées à pcre[16|32]_compile(). Il est utilisé dans les tests PCRE standard pour vérifier le comportement avec différentes tables de caractères. Le chiffre spécifie les tables comme suit :


0 les tables ASCII par défaut, telles que distribuées dans
pcre_chartables.c.dist
1 un ensemble de tables définissant les caractères ISO 8859

Dans la table 1, certains caractères dont les codes sont supérieurs à 128 sont identifiés comme lettres, chiffres, espaces, etc.

Utilisation de l'API d'encapsulation POSIX

Le modificateur /P fait que pcretest appelle PCRE via l'API d'encapsulation POSIX plutôt que son API native. Cela ne prend en charge que la bibliothèque 8 bits. Lorsque /P est défini, les modificateurs suivants définissent les options pour la fonction regcomp() :


/i REG_ICASE
/m REG_NEWLINE
/N REG_NOSUB
/s REG_DOTALL )
/U REG_UNGREEDY ) Ces options ne font pas partie
/W REG_UCP ) de la norme POSIX
/8 REG_UTF8 )

Le modificateur /+ fonctionne comme décrit ci-dessus. Tous les autres modificateurs sont ignorés.

Exclusion de certains modificateurs

PCRE peut être compilé avec ou sans prise en charge de certaines fonctionnalités telles que UTF-8/16/32 ou les propriétés Unicode. En conséquence, les tests standard sont divisés en un certain nombre de fichiers différents qui sont sélectionnés pour l'exécution en fonction des fonctionnalités disponibles. Lors de la mise à jour des tests, il est très facile de placer par erreur un nouveau test dans le mauvais fichier ; par exemple, de placer un test qui nécessite le support UTF dans un fichier utilisé lorsqu'il n'est pas disponible. Pour aider à détecter de telles erreurs le plus tôt possible, il existe une facilité pour interdire des modificateurs spécifiques. Si une ligne d'entrée pour pcretest commence par la chaîne "< forbid ", la séquence de caractères suivante est considérée comme une liste de modificateurs interdits. Par exemple, dans les fichiers de test qui ne doivent pas utiliser le support UTF ou des propriétés Unicode, cette ligne apparaît :


< forbid 8W

Cela interdit les modificateurs /8 et /W. Une erreur immédiate est donnée s'ils sont ensuite rencontrés. Si le ch aracter string contient < mais pas >, tous les modificateurs multi-caractères qui commencent par < sont désactivés. Sinon, de tels modificateurs doivent être explicitement listés, par exemple :


< interdire <JS><cr>

Il doit y avoir un seul espace entre < et « interdire » pour que cette fonctionnalité soit reconnue. S'il n'y en a pas, la ligne est interprétée soit comme une demande de recharger un modèle précompilé (voir « SAUVEGARDER ET RELOADER LES MODÈLES COMPILÉS » ci-dessous), soit, s'il y a un autre caractère <, comme un modèle qui utilise < comme délimiteur.

Notez que \xhh spécifie un octet plutôt qu'un caractère en mode UTF-8 ; cela permet de construire des séquences UTF-8 invalides à des fins de test. D'autre part, \x{hh} est interprété comme un caractère UTF-8 en mode UTF-8, générant plus d'un octet si la valeur est supérieure à 127. Lors du test de la bibliothèque 8 bits non en mode UTF-8, \x{hh} génère un octet pour les valeurs inférieures à 256 et provoque une erreur pour les valeurs supérieures.

En mode UTF-16, toutes les valeurs \x{hhhh} à 4 chiffres sont acceptées. Cela permet de construire des séquences UTF-16 invalides à des fins de test.

En mode UTF-32, toutes les valeurs \x{...} à 4 à 8 chiffres sont acceptées. Cela permet de construire des séquences UTF-32 invalides à des fins de test.

Les séquences d'échappement qui spécifient les séquences de fin de ligne sont des chaînes littérales, exactement comme indiqué. Pas plus d'un réglage de nouvelle ligne ne doit être présent dans une ligne de données.

Un antislash suivi de n'importe quoi d'autre échappe simplement ce n'importe quoi d'autre. Si le tout dernier caractère est un antislash, il est ignoré. Cela permet de passer une ligne vide comme donnée, car une vraie ligne vide termine l'entrée des données.

Le séquence d'échappement \J fournit un moyen de définir la taille maximale de la pile utilisée par le code d'optimisation juste-à-temps. Elle est ignorée si l'optimisation JIT n'est pas utilisée. Fournir une pile plus grande que la valeur par défaut de 32 Ko n'est nécessaire que pour des modèles très compliqués.

Si \M est présent, pcretest appelle pcre[16|32]_exec() plusieurs fois, avec différentes valeurs dans les champs match_limit et match_limit_recursion de la structure de données pcre[16|32]_extra, jusqu'à ce qu'il trouve les nombres minimums pour chaque paramètre qui permettent à pcre[16|32]_exec() de se terminer sans erreur. Parce que cela teste une fonctionnalité spécifique de l'exécution interprétative normale de pcre[16|32]_exec(), l'utilisation de toute optimisation JIT qui aurait pu être mise en place par le qualificateur /S+ de l'option -s+ est désactivée.

Le nombre match_limit mesure la quantité de retour arrière qui se produit, et son contrôle peut être instructif. Pour la plupart des correspondances simples, le nombre est assez petit, mais pour les modèles avec un très grand nombre de possibilités de correspondance, il peut devenir très grand rapidement avec l'augmentation de la longueur de la chaîne sujet. Le nombre match_limit_recursion mesure la quantité de pile (ou, si PCRE est compilé avec NO_RECURSE, la quantité de tas) de mémoire nécessaire pour terminer la tentative de correspondance.

Lorsque \O est utilisé, la valeur spécifiée peut être supérieure ou inférieure à la taille définie par l'option de ligne de commande -O (ou par défaut à 45) ; \O s'applique uniquement à l'appel de pcre[16|32]_exec() pour la ligne dans laquelle il apparaît.

Si le modificateur /P était présent sur le modèle, provoquant l'utilisation de l'API wrapper POSIX, seules les séquences de définition d'options qui ont un effet sont \B, \N et \Z, provoquant le passage de REG_NOTBOL, REG_NOTEMPTY et REG_NOTEOL, respectivement, à regexec().

LA FONCTION DE CORRESPONDANCE ALTERNATIVE

Par défaut, pcretest utilise la fonction de correspondance PCRE standard, pcre[16|32]_exec(), pour faire correspondre chaque ligne de données. PCRE prend également en charge une fonction de correspondance alternative, pcre[16|32]_dfa_test(), qui fonctionne différemment et présente certaines restrictions. Les différences entre les deux fonctions sont décrites dans la documentation pcrematching.

Si une ligne de données contient la séquence d'échappement \D, ou si la ligne de commande contient l'option -dfa, la fonction de correspondance alternative est utilisée. Cette fonction trouve toutes les correspondances possibles à un point donné. Si, cependant, la séquence d'échappement \F est présente dans la ligne de données, elle s'arrête après la première correspondance trouvée. Il s'agit toujours de la correspondance la plus courte possible.

SORTIE PAR DÉFAUT DE PCRETEST

Cette section décrit la sortie lorsque la fonction de correspondance normale, pcre[16|32]_exec(), est utilisée.

Lorsqu'une correspondance réussit, pcretest affiche la liste des sous-chaînes capturées que pcre[16|32]_exec() renvoie, en commençant par le numéro 0 pour la chaîne qui correspond à l'ensemble du modèle. Sinon, il affiche « Pas de correspondance » lorsque le retour est PCRE_ERROR_NOMATCH, et « Correspondance partielle : » suivi de la sous-chaîne partiellement correspondante lorsque pcre[16|32]_exec() renvoie PCRE_ERROR_PARTIAL. (Notez qu'il s'agit de la sous-chaîne entière qui a été inspectée pendant la correspondance partielle ; elle peut inclure des caractères avant le début réel de la correspondance si une assertion lookbehind, \K, \b ou \B était impliquée.) Pour tout autre retour, pcretest affiche le numéro d'erreur négatif PCRE et une courte phrase descriptive. Si l'erreur est une vérification de chaîne UTF échouée, l'offset du début du caractère défaillant et le code de raison sont également affichés, à condition que la taille du vecteur de sortie soit d'au moins deux. Voici un exemple d'exécution interactive de pcretest.


$ pcretest
Version PCRE 8.13 2011-04-30


re> /^abc(\d+)/
data> abc123
0: abc123
1: 123
data> xyz
Pas de correspondance

Les sous-chaînes de capture non définies qui ne sont pas suivies par une sous-chaîne définie ne sont pas renvoyées par pcre[16|32]_exec() et ne sont pas affichées par pcretest. Dans l'exemple suivant, il y a deux sous-chaînes de capture, mais lorsque la première ligne de données correspond, la deuxième sous-chaîne non définie i

n'est pas affiché. Une sous-chaîne interne "non définie" est affichée comme "<unset>", comme pour la deuxième ligne de données.


re> /(a)|(b)/
data> a
0: a
1: a
data> b
0: b
1: <unset>
2: b

Si les chaînes contiennent des caractères non imprimables, ils sont affichés sous forme d'échappements \xhh si la valeur est inférieure à 256 et que le mode UTF n'est pas défini. Sinon, ils sont affichés sous forme d'échappements \x{hh...}. Voir ci-dessous pour la définition des caractères non imprimables. Si le motif a le modificateur /+, la sortie pour la sous-chaîne 0 est suivie par le reste de la chaîne sujet, identifiée par "0+" comme suit :


re> /cat/+
data> cataract
0: cat
0+ aract

Si le motif a le modificateur /g ou /G, les résultats des tentatives de correspondance successives sont affichés en séquence, comme suit :


re> /\Bi(\w\w)/g
data> Mississippi
0: iss
1: ss
0: iss
1: ss
0: ipp
1: pp

« No match » n'est affiché que si la première tentative de correspondance échoue. Voici un exemple de message d'échec (l'offset 4 spécifié par \>4 est au-delà de la fin de la chaîne sujet) :


re> /xyz/
data> xyz\>4
Error -24 (bad offset value)

Si l'une des séquences \C, \G ou \L est présente dans une ligne de données qui correspond avec succès, les sous-chaînes extraites par les fonctions utilitaires sont affichées avec C, G ou L après le numéro de chaîne au lieu d'un deux-points. Ceci est en plus de la liste complète normale. La longueur de la chaîne (c'est-à-dire le retour de la fonction d'extraction) est donnée entre parenthèses après chaque chaîne pour \C et \G.

Notez que si les motifs peuvent être étendus sur plusieurs lignes (une invite ">" simple est utilisée pour les continuations), les lignes de données ne le peuvent pas. Cependant, les nouvelles lignes peuvent être incluses dans les données au moyen de l'échappement \n (ou \r, \r\n, etc., en fonction du réglage de la séquence de nouvelle ligne).

SORTIE DE LA FONCTION DE CORRESPONDANCE ALTERNATIVE

Lorsque la fonction de correspondance alternative, pcre[16|32]_dfa_exec(), est utilisée (au moyen de la séquence d'échappement \D ou de l'option de ligne de commande -dfa), la sortie consiste en une liste de toutes les correspondances qui commencent au premier point du sujet où il y a au moins une correspondance. Par exemple :


re> /(tang|tangerine|tan)/
data> yellow tangerine\D
0: tangerine
1: tang
2: tan

(En utilisant la fonction de correspondance normale sur ces données, on ne trouve que "tang".) La chaîne correspondante la plus longue est toujours donnée en premier (et numérotée zéro). Après un retour PCRE_ERROR_PARTIAL, la sortie est "Partial match:", suivie de la sous-chaîne partiellement correspondante. (Notez qu'il s'agit de la sous-chaîne entière qui a été inspectée lors de la correspondance partielle ; elle peut inclure des caractères avant le début de la correspondance réelle si une assertion de lookbehind, \K, \b ou \B était impliquée.)

Si /g est présent dans le motif, la recherche de correspondances supplémentaires reprend à la fin de la correspondance la plus longue. Par exemple :


re> /(tang|tangerine|tan)/g
data> yellow tangerine and tangy sultana\D
0: tangerine
1: tang
2: tan
0: tang
1: tan
0: tan

Étant donné que la fonction de correspondance ne prend pas en charge la capture de sous-chaînes, les séquences d'échappement relatives aux sous-chaînes capturées ne sont pas pertinentes.

REDÉMARRAGE APRÈS UNE CORRESPONDANCE PARTIELLE

Lorsque la fonction de correspondance alternative a renvoyé PCRE_ERROR_PARTIAL, indiquant que le sujet a partiellement correspondu au motif, vous pouvez redémarrer la correspondance avec des données de sujet supplémentaires au moyen de la séquence d'échappement \R. Par exemple :


re> /^\d?\d(jan|feb|mar|apr|may|jun|jul|aug|sep|oct|nov|dec)\d\d$/
data> 23ja\P\D
Partial match: 23ja
data> n05\R\D
0: n05

Pour plus d'informations sur la correspondance partielle, consultez la documentation pcrepartial.

APPELS DE RETOUR

Si le motif contient des demandes d'appel de retour, la fonction d'appel de retour de pcretest est appelée pendant la correspondance. Cela fonctionne avec les deux fonctions de correspondance. Par défaut, la fonction appelée affiche le numéro de l'appel de retour, les positions de début et actuelle dans le texte au moment de l'appel de retour, et le prochain élément du motif à tester. Par exemple :


--->pqrabcdef
0 ^ ^ \d

Cette sortie indique que l'appel de retour numéro 0 s'est produit pour une tentative de correspondance commençant au quatrième caractère de la chaîne sujet, lorsque le pointeur était au septième caractère des données, et lorsque le prochain élément du motif était \d. Un seul accent circonflexe est affiché si les positions de début et actuelle sont identiques.

Les appels de retour numérotés 255 sont considérés comme des appels de retour automatiques, insérés à la suite du modificateur de motif /C. Dans ce cas, au lieu d'afficher le numéro de l'appel de retour, l'offset dans le motif, précédé d'un plus, est affiché. Par exemple :


re> /\d?[A-E]\*/C
data> E*
--->E*
+0 ^ \d?
+3 ^ [A-E]
+8 ^^ \*
+10 ^ ^
0: E*

Si un motif contient des éléments (*MARK), une ligne supplémentaire est affichée chaque fois qu'un changement de la dernière marque est transmis à la fonction d'appel de retour. Par exemple :


re> /a(*MARK:X)bc/C
data> abc
--->abc
+0 ^ a
+1 ^^ (*MARK:X)
+10 ^^ b
Latest Mark: X
+11 ^ ^ c
+12 ^ ^
0: abc

La marque change entre la correspondance de "a" et "b", mais reste la même pour le reste de la correspondance, donc rien d'autre n'est affiché. Si, suite à un retour arrière, la marque redevient non définie, le texte "<unset>" est affiché.

La fonction d'appel de retour dans pcretest renvoie zéro (continuer la correspondance) par défaut, mais vous pouvez utiliser un élément \C dans une ligne de données (comme décrit ci-dessus) pour changer cela et d'autres paramètres de l'appel de retour.

L'insertion d'appels de retour peut être utile lors de l'utilisation de pcretest pour vérifier des expressions régulières complexes. Pour plus d'informations sur les appels de retour, consultez la documentation pcrecallout.

CARACTÈRES NON IMPRIMABLES

Lorsque pcretest affiche du texte dans la version compilée d'un motif, les octets autres que 32-126 sont toujours traités comme des caractères non imprimables et sont donc affichés sous forme d'échappements hexadécimaux.

Lorsque pcretest affiche du texte qui fait partie d'une chaîne sujet correspondante, il se comporte de la même manière, sauf si une locale différente a été définie pour le motif (en utilisant le modificateur /L). Dans ce cas, la fonction isprint() est utilisée pour distinguer les caractères imprimables et non imprimables.

SAUVEGARDE ET RECHARGEMENT DES MOTIFS COMPILÉS

Les fonctionnalités décrites dans cette section ne sont pas disponibles lorsque l'interface POSIX de PCRE est utilisée, c'est-à-dire lorsque le modificateur de motif /P est spécifié.

Lorsque l'interface POSIX n'est pas utilisée, vous pouvez faire en sorte que pcretest écrive un motif compilé dans un fichier, en ajoutant > et un nom de fichier après les modificateurs. Par exemple :


/pattern/im >/some/file

Voir la documentation pcreprecompile pour une discussion sur la sauvegarde et la réutilisation des motifs compilés. Notez que si le motif a été étudié avec succès avec l'optimisation JIT, les données JIT ne peuvent pas être sauvegardées.

Les données qui sont écrites sont binaires. Les huit premiers octets sont la longueur des données du motif compilé suivie de la longueur des données d'étude optionnelles, chacune écrite sur quatre octets en ordre big-endian (octet le plus significatif en premier). S'il n'y a pas de données d'étude (soit le motif n'a pas été étudié, soit l'étude n'a renvoyé aucune donnée), la deuxième longueur est zéro. Les longueurs sont suivies d'une copie exacte du motif compilé. S'il y a des données d'étude supplémentaires, celles-ci (à l'exclusion de toute donnée JIT) suivent immédiatement après le motif compilé. Après avoir écrit le fichier, pcretest s'attend à lire un nouveau motif.

Un motif sauvegardé peut être rechargé dans pcretest en spécifiant < et un nom de fichier au lieu d'un motif. Il ne doit pas y avoir d'espace entre < et le nom du fichier, qui ne doit pas contenir de caractère <, sinon pcretest interprétera la ligne comme un motif délimité par des caractères <. Par exemple :


re> </some/file
Compiled pattern loaded from /some/file
No study data

Si le motif a été précédemment étudié avec l'optimisation JIT, les informations JIT ne peuvent pas être sauvegardées et restaurées, et sont donc perdues. Une fois le motif chargé, pcretest procède à la lecture des lignes de données comme d'habitude.

Vous pouvez copier un fichier écrit par pcretest vers un autre hôte et le recharger là-bas, même si le nouvel hôte a une endianness opposée à celle sur laquelle le motif a été compilé. Par exemple, vous pouvez compiler sur une machine i86 et exécuter sur une machine SPARC. Lorsqu'un motif est rechargé sur un hôte avec une endianness différente, le message de confirmation est modifié en :


Compiled pattern (byte-inverted) loaded from /some/file

La suite de tests contient des motifs pré-compilés sauvegardés avec une endianness différente. Ceux-ci sont rechargés en utilisant "<!" au lieu de simplement "<". Cela supprime le texte "(byte-inverted)" afin que la sortie soit la même sur tous les hôtes. Cela force également la sortie de débogage une fois que le motif a été rechargé.

Les noms de fichiers pour la sauvegarde et le rechargement peuvent être absolus ou relatifs, mais notez que la facilité du shell pour développer un nom de fichier qui commence par un tilde (~) n'est pas disponible.

La capacité de sauvegarder et de recharger des fichiers dans pcretest est destinée aux tests et à l'expérimentation. Elle n'est pas destinée à une utilisation en production car un seul motif peut être écrit dans un fichier. De plus, il n'y a pas de mécanisme pour fournir des tables de caractères personnalisées à utiliser avec un motif rechargé. Si le motif d'origine a été compilé avec des tables personnalisées, une tentative de correspondance d'une chaîne sujet à l'aide d'un motif rechargé est susceptible de provoquer un plantage de pcretest.
