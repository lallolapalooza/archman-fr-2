LA BIBLIOTHÈQUE PCRE 16 BITS

À partir de la version 8.30, il est possible de compiler une bibliothèque PCRE qui prend en charge les chaînes de caractères 16 bits, y compris les chaînes UTF-16, ainsi que la bibliothèque originale 8 bits ou à leur place. La majorité du travail pour rendre cela possible a été effectuée par Zoltan Herczeg. Les deux bibliothèques contiennent un ensemble identique de fonctions, utilisées exactement de la même manière. Seuls les noms des fonctions et les types de données de leurs arguments et résultats sont différents. Pour éviter une complexification excessive et réduire la charge de maintenance de la documentation, la plupart de la documentation PCRE décrit la bibliothèque 8 bits, avec seulement des références occasionnelles à la bibliothèque 16 bits. Cette page décrit ce qui est différent lorsque vous utilisez la bibliothèque 16 bits.

AVERTISSEMENT : Une application unique peut être liée avec les deux bibliothèques, mais vous devez faire attention lorsque vous traitez un motif particulier à utiliser des fonctions d'une seule bibliothèque. Par exemple, si vous souhaitez étudier un motif qui a été compilé avec pcre16_compile(), vous devez le faire avec pcre16_study(), pas avec pcre_study(), et vous devez libérer les données d'étude avec pcre16_free_study().

LE FICHIER D'ENTÊTE

Il n'y a qu'un seul fichier d'en-tête, pcre.h. Il contient les prototypes de toutes les fonctions de toutes les bibliothèques, ainsi que les définitions des indicateurs, des structures, des codes d'erreur, etc.

LE NOM DE LA BIBLIOTHÈQUE

Sur les systèmes de type Unix, la bibliothèque 16 bits s'appelle libpcre16, et peut normalement être accessible en ajoutant -lpcre16 à la commande pour lier une application qui utilise PCRE.

TYPES DE CHAÎNES

Dans la bibliothèque 8 bits, les chaînes sont passées aux fonctions de bibliothèque PCRE sous forme de vecteurs d'octets avec le type C « char * ». Dans la bibliothèque 16 bits, les chaînes sont passées sous forme de vecteurs de quantités 16 bits non signées. La macro PCRE_UCHAR16 spécifie un type de données approprié, et PCRE_SPTR16 est défini comme « const PCRE_UCHAR16 * ». Dans de très nombreux environnements, « short int » est un type de données 16 bits. Lorsque PCRE est construit, il définit PCRE_UCHAR16 comme « unsigned short int », mais vérifie qu'il s'agit bien d'un type de données 16 bits. Si ce n'est pas le cas, la construction échoue avec un message d'erreur indiquant au mainteneur de modifier la définition de manière appropriée.

TYPES DE STRUCTURES

Les types des structures opaques utilisées pour les motifs 16 bits compilés et les piles JIT sont respectivement pcre16 et pcre16_jit_stack. Le type de la structure accessible par l'utilisateur renvoyée par pcre16_study() est pcre16_extra, et le type de la structure utilisée pour passer des données à une fonction d'appel est pcre16_callout_block. Ces structures contiennent les mêmes champs, avec les mêmes noms, que leurs homologues 8 bits. La seule différence est que les pointeurs vers les chaînes de caractères sont de type 16 bits au lieu de 8 bits.

FONCTIONS 16 BITS

Pour chaque fonction de la bibliothèque 8 bits, il existe une fonction correspondante dans la bibliothèque 16 bits avec un nom qui commence par pcre16_ au lieu de pcre_. Les prototypes sont listés ci-dessus. De plus, il existe une fonction supplémentaire, pcre16_utf16_to_host_byte_order(). Il s'agit d'une fonction utilitaire qui convertit une chaîne de caractères UTF-16 en ordre d'octets hôte si nécessaire. Les autres fonctions 16 bits attendent que les chaînes qui leur sont passées soient en ordre d'octets hôte.

Les arguments input et output de pcre16_utf16_to_host_byte_order() peuvent pointer vers la même adresse, c'est-à-dire que la conversion sur place est prise en charge. Le tampon de sortie doit être au moins aussi long que l'entrée.

L'argument length spécifie le nombre d'unités de données 16 bits dans la chaîne d'entrée ; une valeur négative spécifie une chaîne terminée par un zéro.

pcre16 - Manuel d'utilisation de PCRE 16 bits

NOM

pcre16 – une bibliothèque d'expressions régulières compatible Perl pour Unicode 16 bits.

FONCTIONS DE BASE DE L'API PCRE 16 BITS

Les fonctions de compilation et d'exécution des expressions régulières pour les chaînes de caractères 16 bits sont préfixées par pcre16_, par exemple pcre16_compile(), pcre16_exec() et pcre16_study().

FONCTIONS D'EXTRACTION DE CHAÎNES DE L'API PCRE 16 BITS

Les fonctions pour extraire des sous-chaînes correspondent à leurs homologues 8 bits, mais sont préfixées par pcre16_. Par exemple, pcre16_get_substring() et pcre16_get_substring_list().

FONCTIONS AUXILIAIRES DE L'API PCRE 16 BITS

Les fonctions pour obtenir des informations sur les chaînes de caractères correspondantes, comme pcre16_get_stringtable_entries() et pcre16_utf16_to_host_byte_order(), ont également le préfixe pcre16_.

FONCTIONS INDIRECTES DE L'API PCRE 16 BITS

Les fonctions qui permettent de gérer les correspondances de noms de sous-modèles, comme pcre16_get_stringnumber(), ont également le préfixe pcre16_.

FONCTION EXCLUSIVE À L'API PCRE 16 BITS

pcre16_utf16_to_host_byte_order() est une fonction utilitaire qui gère les marques d'ordre des octets au début des chaînes UTF-16.

LA BIBLIOTHÈQUE PCRE 16 BITS

La bibliothèque PCRE 16 bits est conçue pour travailler avec des chaînes de caractères Unicode qui utilisent des unités de code de 16 bits. La plupart des fonctions de l'API C sont disponibles dans une version 16 bits, avec le préfixe pcre16_.

LE FICHIER D'EN-TÊTE

L'en-tête pcre16.h doit être inclus lorsque vous utilisez la bibliothèque 16 bits. Il contient les déclarations de toutes les fonctions et structures spécifiques à la bibliothèque 16 bits.

LE NOM DE LA BIBLIOTHÈQUE

Lors de la liaison de votre programme, vous devez lier avec la bibliothèque libpcre16.so (ou son équivalent statique).

TYPES DE CHAÎNES

Les chaînes de caractères utilisées avec l'API 16 bits sont des tableaux de caractères 16 bits non signés (type uint16_t). La fin de chaîne est marquée par un caractère nul (valeur 0).

TYPES DE STRUCTURES

Les structures utilisées par l'API 16 bits, telles que pcre16_match_data, sont conçues pour gérer des données de 16 bits.

FONCTIONS 16 BITS

Toutes les fonctions qui traitent des chaînes de caractères acceptent des pointeurs vers des tableaux de PCRE_UCHAR16 (qui est un alias pour uint16_t). Les longueurs sont spécifiées en nombre d'unités de 16 bits. Les correspondances retournées sont également en unités de 16 bits.

La fonction pcre16_utf16_to_host_byte_order() est fournie pour convertir les chaînes UTF-16 du format réseau (ou d'un autre format) à l'ordre des octets de l'hôte. Elle peut être appelée avant d'utiliser d'autres fonctions PCRE 16 bits.

Les paramètres byte_order et keep_boms de pcre16_utf16_to_host_byte_order() contrôlent la façon dont l'ordre des octets est géré et si les marques d'ordre des octets (BOM) sont conservées dans la sortie. Les BOM peuvent changer le comportement de l'analyse des chaînes, même s'ils ne sont pas présents au début.

Si byte_order n'est pas NULL, une valeur non nulle signifie que l'entrée commence dans l'ordre des octets de l'hôte. Sinon, l'ordre opposé est supposé. Les BOM dans la chaîne peuvent modifier cela. L'ordre des octets final est renvoyé à la fin du traitement.

Si keep_boms n'est pas zéro, les caractères de marque d'ordre des octets (0xfeff) sont copiés dans la chaîne de sortie. Sinon, ils sont supprimés.

Le résultat de la fonction est le nombre d'unités de 16 bits placées dans le tampon de sortie, y compris le terminateur nul si la chaîne était terminée par un nul.

DÉCALAGES DES CHAÎNES SUJET

Les longueurs et les décalages de départ des chaînes sujet doivent être spécifiés en unités de données de 16 bits, et les décalages dans les chaînes sujet retournés par les fonctions de correspondance sont également en unités de 16 bits plutôt qu'en octets.

SOUS-MODÈLES NOMMÉS

La table de traduction nom-à-numéro maintenue pour les sous-modèles nommés utilise des caractères de 16 bits. La fonction pcre16_get_stringtable_entries() renvoie la longueur de chaque entrée de la table comme nombre d'unités de données de 16 bits.

NOMS D'OPTIONS

Il existe deux nouveaux noms d'options générales, PCRE_UTF16 et PCRE_NO_UTF16_CHECK, qui correspondent à PCRE_UTF8 et PCRE_NO_UTF8_CHECK dans la bibliothèque 8 bits. En fait, ces nouvelles options définissent les mêmes bits dans le mot d'options. Une discussion sur la validité des chaînes UTF-16 se trouve dans la page pcreunicode.

Pour la fonction pcre16_config(), il existe une option PCRE_CONFIG_UTF16 qui renvoie 1 si le support UTF-16 est configuré, sinon 0. Si cette option est donnée à pcre_config() ou pcre32_config(), ou si l'option PCRE_CONFIG_UTF8 ou PCRE_CONFIG_UTF32 est donnée à pcre16_config(), le résultat est l'erreur PCRE_ERROR_BADOPTION.

CODES DE CARACTÈRES

En mode 16 bits, lorsque PCRE_UTF16 n'est pas défini, les valeurs de caractères sont traitées de la même manière qu'en mode 8 bits non UTF-8, sauf, bien sûr, qu'elles peuvent aller de 0 à 0xffff au lieu de 0 à 0xff. Les types de caractères pour les caractères inférieurs à 0xff peuvent donc être influencés par la locale de la même manière qu'auparavant. Les caractères supérieurs à 0xff n'ont qu'un seul cas, et pas de "type" (tel que lettre ou chiffre).

En mode UTF-16, le code de caractère est Unicode, dans la plage 0 à 0x10ffff, à l'exception des valeurs dans la plage 0xd800 à 0xdfff car ce sont des valeurs "de substitution" utilisées par paires pour encoder des valeurs supérieures à 0xffff.

Une chaîne UTF-16 peut indiquer son boutisme par un code spécial connu sous le nom de marque d'ordre des octets (BOM). Les fonctions PCRE ne gèrent pas cela, attendant des chaînes dans l'ordre des octets de l'hôte. Une fonction utilitaire appelée pcre16_utf16_to_host_byte_order() est fournie pour aider à cela (voir ci-dessus).

NOMS D'ERREURS

Les erreurs PCRE_ERROR_BADUTF16_OFFSET et PCRE_ERROR_SHORTUTF16 correspondent à leurs homologues 8 bits. L'erreur PCRE_ERROR_BADMODE est donnée lorsqu'un modèle compilé est passé à une fonction qui traite les modèles dans l'autre mode, par exemple, si un modèle compilé avec pcre_compile() est passé à pcre16_exec().

Il existe de nouveaux codes d'erreur dont les noms commencent par PCRE_UTF16_ERR pour les chaînes UTF-16 invalides, correspondant aux codes PCRE_UTF8_ERR pour les chaînes UTF-8 décrits dans la section intitulée "Codes de raison pour les chaînes UTF-8 invalides" de la page principale pcreapi. Les erreurs UTF-16 sont :


PCRE_UTF16_ERR1 Substitution basse manquante à la fin de la chaîne
PCRE_UTF16_ERR2 Substitution basse invalide suit une substitution haute
PCRE_UTF16_ERR3 Substitution basse isolée
PCRE_UTF16_ERR4 Pas un caractère

TEXTES D'ERREURS

En cas d'erreur lors de la compilation d'un modèle, le texte d'erreur renvoyé par pcre16_compile() ou pcre16_compile2() est toujours une chaîne de caractères 8 bits, terminée par un nul.

APPELS DE RETOUR

Les champs subject et mark dans le bloc d'appel de retour passé à une fonction d'appel de retour pointent vers des vecteurs de 16 bits.

TEST

Le programme pcretest continue de fonctionner avec des fichiers d'entrée et de sortie 8 bits, mais il peut être utilisé pour tester la bibliothèque 16 bits. S'il est exécuté avec l'option de ligne de commande -16, les modèles et les chaînes sujet sont convertis de 8 bits en 16 bits avant d'être passés à PCRE, et les fonctions de la bibliothèque 16 bits sont utilisées à la place de celles de 8 bits. Les chaînes 16 bits retournées sont converties en 8 bits pour la sortie. Si les bibliothèques 8 bits et 32 bits n'ont pas été compilées, pcretest utilise par défaut la 16 bits et l'option -16 est ignorée.

Lorsque PCRE est en cours de construction, le script RunTest appelé par "make check" utilise l'option -C de pcretest pour découvrir quelles bibliothèques 8 bits, 16 bits et 32 bits ont été construites, et exécute les tests de manière appropriée.

NON PRIS EN CHARGE EN MODE 16 BITS

Toutes les fonctionnalités de la bibliothèque 8 bits ne sont pas disponibles avec la bibliothèque 16 bits. Les fonctions d'encapsulation C++ et POSIX ne prennent en charge que la bibliothèque 8 bits, et le programme pcregrep est actuellement uniquement en 8 bits.
