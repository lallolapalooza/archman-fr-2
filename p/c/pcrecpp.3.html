PCRECPP(3) Manuel des fonctions de bibliothèque PCRECPP(3)

NOM

PCRE - Expressions régulières compatibles Perl.

SYNOPIS DE L'EMBALLAGE C++

#include <pcrecpp.h>

DESCRIPTION

L'emballage C++ pour PCRE a été fourni par Google Inc. Des fonctionnalités supplémentaires ont été ajoutées par Giuseppe Maxia. Cette brève page de manuel a été construite à partir des notes du fichier pcrecpp.h, qui doit être consulté pour plus de détails. Notez que l'emballage C++ ne prend en charge que la bibliothèque PCRE originale de 8 bits. Il n'y a actuellement aucun support pour 16 bits ou 32 bits.

INTERFACE DE CORRESPONDANCE

L'opération "FullMatch" vérifie que le texte fourni correspond exactement à un motif fourni. Si des pointeurs sont fournis, elle copie les sous-chaînes correspondantes qui correspondent aux sous-motifs dans ceux-ci.


Exemple : correspondance réussie
pcrecpp::RE re("h.*o");
re.FullMatch("hello");


Exemple : correspondance échouée (nécessite une correspondance complète) :
pcrecpp::RE re("e");
!re.FullMatch("hello");


Exemple : création d'un objet RE temporaire :
pcrecpp::RE("h.*o").FullMatch("hello");

Vous pouvez passer un "const char*" ou une "string" pour "text". Les exemples ci-dessous ont tendance à utiliser un const char*. Vous pouvez, comme dans les différents exemples ci-dessus, stocker l'objet RE explicitement dans une variable ou utiliser un objet RE temporaire. Les exemples ci-dessous utilisent l'un ou l'autre mode de manière arbitraire. L'un ou l'autre pourrait être utilisé correctement pour n'importe lequel de ces exemples.

Vous devez fournir des arguments de pointeur supplémentaires pour extraire les sous-pièces correspondantes.


Exemple : extrait "ruby" dans "s" et 1234 dans "i"
int i;
string s;
pcrecpp::RE re("(\\w+):(\\d+)");
re.FullMatch("ruby:1234", &s, &i);


Exemple : n'essaie pas d'extraire de sous-motifs supplémentaires
re.FullMatch("ruby:1234", &s);


Exemple : n'essaie pas d'extraire dans NULL
re.FullMatch("ruby:1234", NULL, &i);


Exemple : le dépassement d'entier provoque un échec
!re.FullMatch("ruby:1234567891234", NULL, &i);


Exemple : échoue car il n'y a pas assez de sous-motifs :
!pcrecpp::RE("\\w+:\\d+").FullMatch("ruby:1234", &s);


Exemple : échoue car la chaîne ne peut pas être stockée dans un entier
!pcrecpp::RE("(.*)").FullMatch("ruby", &i);

Les arguments de pointeur fournis peuvent être des pointeurs vers tout type numérique scalaire, ou l'un des éléments suivants :


string (la pièce correspondante est copiée dans la chaîne)
StringPiece (StringPiece est modifié pour pointer vers la pièce correspondante)
T (où "bool T::ParseFrom(const char*, int)" existe)
NULL (le sous-motif correspondant correspondant n'est pas copié)

La fonction renvoie vrai si toutes les conditions suivantes sont remplies :


a. "text" correspond exactement à "pattern" ;


b. Le nombre de sous-motifs correspondants est >= au nombre de pointeurs fournis ;


c. L'argument "i" a un type approprié pour contenir la chaîne capturée en tant que "i"-ème sous-motif. Si vous passez void * NULL pour le "i"-ème argument, ou un non-void * NULL du type correct, ou si vous passez moins d'arguments que le nombre de sous-motifs, le "i"-ème sous-motif capturé est ignoré.

ATTENTION : Un sous-motif optionnel qui n'existe pas dans la chaîne correspondante se voit attribuer une chaîne vide. Par conséquent, l'appel suivant renverra faux (car la chaîne vide n'est pas un nombre valide) :


int number;
pcrecpp::RE::FullMatch("abc", "[a-z]+(\\d+)?", &number);

L'interface de correspondance prend en charge au maximum 16 arguments par appel. Si vous en avez besoin de plus, envisagez d'utiliser l'interface plus générale pcrecpp::RE::DoMatch. Voir pcrecpp.h pour la signature de DoMatch.

NOTE : N'utilisez pas no_arg, qui est utilisé en interne pour marquer la fin d'une liste d'arguments optionnels, comme espace réservé pour les arguments manquants, car cela peut entraîner des segfaults.

METTRE LES MÉTACARACTÈRES ENTRE GUILLEMETS

Vous pouvez utiliser l'opération "QuoteMeta" pour insérer des barres obliques inverses avant tous les caractères potentiellement significatifs d'une chaîne. La chaîne renvoyée, utilisée comme expression régulière, correspondra exactement à la chaîne d'origine.


Exemple :
string quoted = RE::QuoteMeta(unquoted);

Notez qu'il est légal d'échapper un caractère même s'il n'a pas de signification spéciale dans une expression régulière -- cette fonction le fait donc. (Cela la rend également identique à la fonction Perl du même nom ; voir "perldoc -f quotemeta".) Par exemple, "1.5-2.0?" devient "1\.5\-2\.0\?".

MATCHES PARTIELLES

Vous pouvez utiliser l'opération "PartialMatch" lorsque vous souhaitez que le motif corresponde à n'importe quelle sous-chaîne du texte.


Exemple : recherche simple d'une chaîne :
pcrecpp::RE("ell").PartialMatch("hello");


Exemple : trouver le premier nombre dans une chaîne :
int number;
pcrecpp::RE re("(\\d+)");
re.PartialMatch("x*100 + 20", &number);
assert(number == 100);

UTF-8 ET L'INTERFACE DE CORRESPONDANCE

Par défaut, le motif et le texte sont du texte brut, un octet par caractère. L'indicateur UTF8, passé au constructeur, fait que le motif et la chaîne sont traités comme du texte UTF-8, toujours un flux d'octets mais potentiellement plusieurs octets par caractère. En pratique, le texte est plus susceptible d'être en UTF-8 que le motif, mais la correspondance renvoyée peut dépendre de l'indicateur UTF8, utilisez-le donc toujours lors de la correspondance de texte UTF8. Par exemple, "." correspondra normalement à un octet, mais avec UTF8 activé, il peut correspondre jusqu'à trois octets d'un caractère multi-octets.


Exemple :
pcrecpp::RE_Options options;
options.set_utf8();
pcrecpp::RE re(utf8_pattern, options);
re.FullMatch(utf8_string);


Exemple : utilisation de la fonction pratique UTF8() :
pcrecpp::RE re(utf8_pattern, pcrecpp::UTF8());
re.FullMatch(utf8_string);

NOTE : L'indicateur UTF8 est ignoré si pcre n'a pas été configuré avec l'indicateur
--enable-utf8.

PCRE définit certains modificateurs pour modifier le comportement du moteur d'expression régulière. L'emballage C++ définit une classe auxiliaire, RE_Options, comme véhicule pour passer de tels modificateurs à une classe RE. Actuellement, les modificateurs suivants sont pris en charge :


modificateur description Correspondant Perl


PCRE_CASELESS correspondance insensible à la casse /i
PCRE_MULTILINE correspondance de plusieurs lignes /m
PCRE_DOTALL point correspond aux nouvelles lignes /s
PCRE_DOLLAR_ENDONLY $ ne correspond qu'à la fin N/A
PCRE_EXTRA analyse stricte des échappements N/A
PCRE_EXTENDED ignore les espaces blancs /x
PCRE_UTF8 gère les caractères UTF8 intégré
PCRE_UNGREEDY inverse * et *? N/A
PCRE_NO_AUTO_CAPTURE désactive les parenthèses de capture N/A (*)

(*) Perl et PCRE autorisent les parenthèses sans capture au moyen du modificateur "?:" dans le motif lui-même. par ex. (?:ab|cd) ne capture pas, tandis que (ab|cd) capture.

NAME

pcrecpp - C++ wrapper for PCRE regular expression functions

SYNOPSIS OF C++ WRAPPER 

#include <pcrecpp.h>

DESCRIPTION

This manual page describes the C++ wrapper class for the PCRE regular expression library. It is intended to provide a more C++-like interface to PCRE.

MATCHING INTERFACE

The primary class is RE. It is constructed with a regular expression pattern. For example:

  pcrecpp::RE re("^http://");

Matching methods include:

  • Match(): Checks if the expression matches anywhere in the string.

  • PartialMatch(): Checks if the expression matches at the beginning of the string.

  • FullMatch(): Checks if the expression matches the entire string.

These methods may take arguments to capture submatches. For example:

  string url = "http://www.example.com";
  string protocol;
  string domain;
  if (pcrecpp::RE("^(http://|https://)([^/]+)")
      .PartialMatch(url, &protocol, &domain)) {
    // protocol == "http://"
    // domain == "www.example.com"
  }

QUOTING METACHARACTERS

If you need to match a literal string that contains PCRE metacharacters, you can use the QuoteMeta() function:

  string pattern = pcrecpp::QuoteMeta("C:\\Program Files\\*");
  // pattern is now "C:\\\\Program Files\\\\*"
  pcrecpp::RE re(pattern);

PARTIAL MATCHES

The PartialMatch() method is useful for matching at the beginning of a string. For example, parsing configuration files or log files.

The Match() method checks if the expression matches anywhere in the string. It returns true if a match is found, and false otherwise. It can also capture submatches.

UTF-8 AND THE MATCHING INTERFACE

By default, PCRE operates in 8-bit mode. To enable UTF-8 mode, you can pass the PCRE_UTF8 option when creating the RE object, or use the UTF8() convenience function.

  pcrecpp::RE re1("[[:lower:]]", pcrecpp::UTF8());
  pcrecpp::RE re2("[[:lower:]]", pcrecpp::RE_Options().set_utf8(true));

PASSING MODIFIERS TO THE REGULAR EXPRESSION ENGINE

You can pass various PCRE modifiers to the regular expression engine using the RE_Options class or the convenience functions like CASELESS(), UTF8(), MULTILINE(), DOTALL(), and EXTENDED().

The set_match_limit() and match_limit() member functions. Setting match_limit to a non-zero value will limit the execution of pcre to keep it from doing bad things like blowing the stack or taking an eternity to return a result. A value of 5000 is good enough to stop stack blowup in a 2MB thread stack. Setting match_limit to zero disables match limiting. Alternatively, you can call match_limit_recursion() which uses PCRE_EXTRA_MATCH_LIMIT_RECURSION to limit how much PCRE recurses. match_limit() limits the number of matches PCRE does; match_limit_recursion() limits the depth of internal recursion, and therefore the amount of stack that is used.

Normally, to pass one or more modifiers to a RE class, you declare a RE_Options object, set the appropriate options, and pass this object to a RE constructor. Example:


RE_Options opt;
opt.set_caseless(true);
if (RE("HELLO", opt).PartialMatch("hello world")) ...

RE_options has two constructors. The default constructor takes no arguments and creates a set of flags that are off by default. The optional parameter option_flags is to facilitate transfer of legacy code from C programs. This lets you do


RE(pattern,
RE_Options(PCRE_CASELESS|PCRE_MULTILINE)).PartialMatch(str);

However, new code is better off doing


RE(pattern,
RE_Options().set_caseless(true).set_multiline(true))
.PartialMatch(str);

If you are going to pass one of the most used modifiers, there are some convenience functions that return a RE_Options class with the appropriate modifier already set: CASELESS(), UTF8(), MULTILINE(), DOTALL(), and EXTENDED().

If you need to set several options at once, and you don't want to go through the pains of declaring a RE_Options object and setting several options, there is a parallel method that give you such ability on the fly. You can concatenate several set_xxxxx() member functions, since each of them returns a reference to its class object. For example, to pass PCRE_CASELESS, PCRE_EXTENDED, and PCRE_MULTILINE to a RE with one statement, you may write:


RE(" ^ xyz \\s+ .* blah$",
RE_Options()
.set_caseless(true)
.set_extended(true)
.set_multiline(true)).PartialMatch(sometext);

SCANNING TEXT INCREMENTALLY

The "Consume" operation may be useful if you want to repeatedly match regular expressions at the front of a string and skip over them as they match. This requires use of the "StringPiece" type, which represents a sub-range of a real string. Like RE, StringPiece is defined in the pcrecpp namespace.


Example: read lines of the form "var = value" from a string.
string contents = ...; // Fill string somehow
pcrecpp::StringPiece input(contents); // Wrap in a StringPiece


string var;
int value;
pcrecpp::RE re("(\\w+) = (\\d+)\n");
while (re.Consume(&input, &var, &value)) {
...;
}

Each successful call to "Consume" will set "var/value", and also advance "input" so it points past the matched text.

The "FindAndConsume" operation is similar to "Consume" but does not anchor your match at the beginning of the string. For example, you could extract all words from a string by repeatedly calling


pcrecpp::RE("(\\w+)").FindAndConsume(&input, &word)

PARSING HEX/OCTAL/C-RADIX NUMBERS

By default, if you pass a pointer to a numeric value, the corresponding text is interpreted as a base-10 number. You can instead wrap the pointer with a call to one of the operators Hex(), Octal(), or CRadix() to interpret the text in another base. The CRadix operator interprets C-style "0" (base-8) and "0x" (base-16) prefixes, but defaults to base-10.


Example:
int a, b, c, d;
pcrecpp::RE re("(.*) (.*) (.*) (.*)");
re.FullMatch("100 40 0100 0x40",
pcrecpp::Octal(&a), pcrecpp::Hex(&b),
pcrecpp::CRadix(&c), pcrecpp::CRadix(&d));

will leave 64 in a, b, c, and d.

REPLACING PARTS OF STRINGS

You can replace the first match of "pattern" in "str" with "rewrite". Within "rewrite", backslash-escaped digits (\1 to \9) can be used to insert text matching corresponding parenthesized group from the pattern. \0 in "rewrite" refers to the entire matching text. For example:


string s = "yabba dabba doo";
pcrecpp::RE("b+").Replace("d", &s);

will leave "s" containing "yada dabba doo". The result is true if the pattern matches and a replacement occurs, false otherwise.

GlobalReplace is like Replace except that it replaces all occurrences of the pattern in the string with the rewrite. Replacements are not subject to re-matching. For example:


string s = "yabba dabba doo";
pcrecpp::RE("b+").GlobalReplace("d", &s);

will leave "s" containing "yada dada doo". It returns the number of replacements made.

Extract is like Replace, except that if the pattern matches, "rewrite" is copied into "out" (an additional argument) with substitutions. The non-matching portions of "text" are ignored. Returns true iff a match occurred and the extraction happened successfully; if no match occurs, the string is left unaffected.
