PCP2OPENTELEMETRY(1) Manuel des commandes générales PCP2OPENTELEMETRY(1)

NOM

pcp2opentelemetry - exportateur pcp vers opentelemetry

SYNTAXE

pcp2opentelemetry [-5CEGHIjLmnrRvVxXz?] [-4 action] [-8|-9 limite] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c configuration] [--container conteneur] [-D débogage] [--daemonize] [-e dérivé] [-f format] [-F fichier-sortie] [-h hôte] [-i instances] [-J rang] [-K spécification] [-N prédicat] [-o délai] [-O origine] [-p mot-de-passe] [-P|-0 précision] [-q|-Q échelle-compte] [-s échantillons] [-S heure-début] [-t intervalle] [-T heure-fin] [-u url] [-U nom-utilisateur] [-y|-Y échelle-temps] [-Z fuseau-horaire] spécification-métrique [...]

DESCRIPTION

pcp2opentelemetry est un outil personnalisable d'exportation de métriques de performance de PCP vers le format OpenTelemetry - https://opentelemetry.io. Toutes les métriques de performance disponibles, en direct ou archivées, système et/ou application, peuvent être sélectionnées pour l'exportation à l'aide d'arguments de ligne de commande ou d'un fichier de configuration.

pcp2opentelemetry est un proche parent de pmrep(1). Se référer à pmrep(1) pour la description de spécification-métrique acceptée sur la ligne de commande de pcp2opentelemetry. Voir pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2opentelemetry.conf. Cette page décrit les options spécifiques à pcp2opentelemetry et les différences de fichiers de configuration avec pmrep.conf(5). pmrep(1) liste également quelques exemples d'utilisation dont la plupart sont applicables à pcp2opentelemetry également.

Seules les options de ligne de commande listées sur cette page sont supportées, les autres options disponibles pour pmrep(1) ne sont pas supportées.

Les options via variables d'environnement (voir pmGetOptions(3)) remplacent les valeurs par défaut intégrées correspondantes (le cas échéant). Les options du fichier de configuration remplacent les variables d'environnement correspondantes (le cas échéant). Les options de ligne de commande remplacent les options du fichier de configuration correspondantes (le cas échéant).

FICHIER DE CONFIGURATION

pcp2opentelemetry utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf: version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. Le reste des options de pmrep.conf est reconnu mais ignoré pour des raisons de compatibilité.

options spécifiques pcp2opentelemetry

url (chaîne)

Envoie la sortie OpenTelemetry sous forme de requête HTTP POST à l'url donnée. Option de ligne de commande correspondante: -u. Par défaut : None.

http_pass (chaîne)

Utilise le mot de passe donné pour l'authentification de base lors de l'envoi d'une requête HTTP POST. Option de ligne de commande correspondante: -p. Par défaut : None.

http_user (chaîne)

Utilise le nom d'utilisateur donné pour l'authentification de base lors de l'envoi d'une requête HTTP POST. Option de ligne de commande correspondante: -U. Par défaut : None.

http_timeout (nombre)

Temps maximum (en secondes) lors de l'envoi d'une requête HTTP POST. Option de ligne de commande correspondante: -o. Par défaut : 2.5 secondes.

OPTIONS

Les options de ligne de commande disponibles sont :

-0 précision, --precision-force=précision
Comme -P mais cette option remplacera les spécifications par métrique.
-4 action, --names-change=action
Spécifie quelle action entreprendre lors de la réception d'un événement de changement de nom de métrique pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques après le démarrage, et informe les outils clients en cours d'exécution comme pcp2opentelemetry. Les valeurs valides pour action sont update (rafraîchir les métriques échantillonnées), ignore (ne rien faire - comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignore-unknown
Ignore silencieusement toute métrique dont le nom ne peut être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-8 limite, --limit-filter=limite
Limite les résultats aux instances dont les valeurs sont supérieures/inférieures à la limite. Un entier positif inclura les instances dont les valeurs sont égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances dont les valeurs sont égales ou inférieures à la limite dans le rapport. Une valeur nulle n'effectue aucun filtrage par limite. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi -J et -N.
-9 limite, --limit-filter-force=limite
Comme -8 mais cette option remplacera les spécifications par métrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archive Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Force le premier échantillon à être aligné sur la frontière d'une unité de temps naturelle alignement. Se référer à PCPIntro(1) pour une description complète de la syntaxe de alignement.
--archive-folio=folio
Lit les archives sources de métriques depuis le folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b échelle, --space-scale=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, et ainsi de suite. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-B échelle, --space-scale-force=échelle
Comme -b mais cette option remplacera les spécifications par métrique.
-c configuration, --config=configuration
Spécifie le fichier ou le répertoire de configuration à utiliser. Dans le cas où configuration est un répertoire, tous les fichiers qui s'y trouvent et se terminent par .conf seront inclus. Le défaut est le premier trouvé parmi : ./pcp2opentelemetry.conf, $HOME/.pcp2opentelemetry.conf, $HOME/pcp/pcp2opentelemetry.conf, et $PCP_SYSCONF_DIR/pcp2opentelemetry.conf. Pour plus de détails, voir la section ci-dessus et pmrep.conf(5).
--container=conteneur
Récupère les métriques de performance du conteneur spécifié, local ou distant (voir -h).
-C, --check
Quitte avant de rapporter toute valeur, mais après avoir analysé la configuration et les métriques et imprimé les éventuels en-têtes.
--daemonize
Se transforme en démon au démarrage.

-e dérivé, --derived=dérivé
Spécifier les métriques de performance dérivées. Si dérivé commence par une barre oblique (``/'') ou par un point (``.''), il sera interprété comme un fichier de configuration PCP pour les métriques dérivées, sinon il sera interprété comme des expressions de métriques dérivées séparées par des virgules ou des points-virgules. Pour une description complète des métriques dérivées et des fichiers de configuration des métriques dérivées PCP, voir pmLoadDerivedConfig(3) et pmRegisterDerived(3). Alternativement, utiliser la syntaxe de configuration pmrep.conf(5) permet de définir des métriques dérivées dans le cadre de groupes de métriques.
-E, --exact-types
Écrire les nombres en tant que types de données numériques, et non en tant que chaînes de caractères, ce qui peut potentiellement entraîner une perte de précision.
-f format, --timestamp-format=format
Utiliser la chaîne de caractères format pour formater l'horodatage. Le format sera utilisé avec la méthode datetime.strftime de Python, qui est très similaire à celle décrite dans strftime(3). La valeur par défaut est %Y-%m-%d %H:%M:%S.
-F fichier_sortie, --output-file=fichier_sortie
Spécifier le fichier de sortie fichier_sortie.
-G, --no-globals
Ne pas inclure les métriques globales dans le rapport (voir pmrep.conf(5)).
-h hôte, --host=hôte
Récupérer les métriques de performance depuis pmcd(1) sur hôte, plutôt que depuis localhost par défaut.
-H, --no-header
Ne pas imprimer d'en-têtes.
-i instances, --instances=instances
Récupérer et rapporter uniquement les instances de métriques spécifiées. Par défaut, toutes les instances, présentes et futures, sont rapportées.

Voir pmrep(1) pour une description complète de cette option.

-I, --ignore-incompat
Ignorer les métriques incompatibles. Par défaut, les métriques incompatibles (c'est-à-dire dont le type n'est pas pris en charge ou qui ne peuvent pas être mises à l'échelle comme demandé) provoqueront l'arrêt de pcp2opentelemetry avec un message d'erreur. Avec cette option, toutes les métriques incompatibles sont silencieusement omises du rapport. Cela peut être particulièrement utile lors de la demande de nœuds non feuilles de l'arbre PMNS pour le rapport.
-j, --live-filter
Effectuer un filtrage dynamique des instances. Cela permet de capturer toutes les instances nommées même si les processus sont redémarrés à un moment donné (contrairement à l'absence de filtrage dynamique). L'exécution d'un filtrage dynamique sur un très grand nombre d'instances entraînera une certaine surcharge interne, une certaine prudence de la part de l'utilisateur est donc conseillée. Voir également -n.
-J rang, --rank=rang
Limiter les résultats aux rangs les plus élevés/bas des instances de métriques à valeurs d'ensemble. Un entier positif inclura les instances les plus valorisées dans le rapport. Un entier négatif inclura les instances les moins valorisées dans le rapport. Une valeur de zéro n'effectue aucun classement. Le classement n'implique pas le tri, voir -6. Voir également -8.
-K spéc, --spec-local=spéc
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spéc est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peuvent être utilisées.
-L, --local-PMDA
Utiliser un contexte local pour collecter les métriques des PMDA DSO sur l'hôte local sans PMCD. Voir également -K.
-n, --invert-filter
Effectuer le classement avant le filtrage dynamique. Par défaut, le filtrage dynamique des instances (lorsqu'il est demandé, voir -j) se produit avant le classement des instances (lorsqu'il est demandé, voir -J). Avec cette option, la logique est inversée et le classement se produit avant le filtrage dynamique.
-m, --include-labels
Inclure les étiquettes des métriques PCP dans la sortie.
-N prédicat, --predicate=prédicat
Spécifier une liste séparée par des virgules de métriques de référence prédicat de filtrage. Par défaut, le classement (voir -J) se fait pour chaque métrique individuellement. Avec des prédicats, le classement ne se fait que pour les métriques prédicats spécifiées. Lors du rapport, le reste des métriques partageant le même domaine d'instance (voir PCPIntro(1)) que le prédicat inclura uniquement les instances les plus élevées/basses du prédicat correspondant. Le classement n'implique pas le tri, voir -6.

Ainsi, par exemple, en utilisant proc.memory.rss (taille de la mémoire résidente du processus) comme métrique prédicat, en combinaison avec proc.io.total_bytes et mem.util.used comme métriques à rapporter, seuls les processus utilisant le plus/le moins (selon -J) de mémoire seront inclus lors du rapport des octets totaux écrits par les processus. Comme mem.util.used est une métrique à valeur unique (ne partageant donc pas le même domaine d'instance que les métriques liées aux processus), elle sera rapportée comme d'habitude.

-o, --http-timeout
Délai d'attente (en secondes) lors de l'envoi d'une requête HTTP POST avec l'option -u. La valeur par défaut est 2.5 secondes.
-O origine, --origin=origine
Lors du rapport de métriques archivées, le rapport commencera à origine dans la fenêtre temporelle (voir -S et -T). Référez-vous à PCPIntro(1) pour une description complète de la syntaxe d'origine.
-p, --http-pass
Mot de passe lors de l'utilisation de l'authentification basique HTTP avec l'option -u.
-P précision, --precision=précision
Utiliser la précision pour les valeurs numériques de sortie non entières. Par défaut, 3 décimales sont utilisées (lorsque applicable). Cette option ne modifiera pas les spécifications possibles par métrique.
-q échelle, --count-scale=échelle
Unité/échelle pour les métriques de comptage, les valeurs possibles incluent count x 10^-1, count, count x 10, count x 10^2, et ainsi de suite de 10^-8 à 10^7. (Ces valeurs sont actuellement sensibles aux espaces.) Cette option ne modifiera pas les spécifications possibles par métrique. Voir également pmParseUnitsStr(3).
-Q échelle, --count-scale-force=échelle
Similaire à -q, mais cette option modifiera les spécifications par métrique.
-r, --raw
Sortie des valeurs brutes des métriques, sans convertir les compteurs cumulatifs en taux. Cette option modifiera les spécifications possibles par métrique.
-R, --raw-prefer
Similaire à -r, mais cette option ne modifiera pas les spécifications par métrique.
-s échantillons, --samples=échantillons
L'argument échantillons définit le nombre d'échantillons à récupérer et à rapporter. Si échantillons est 0 ou si -s n'est pas spécifié, pcp2opentelemetry échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive). Voir également -T.
-S heure_debut, --start=heure_debut
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements enregistrés à partir de heure_debut. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe de heure_debut.
-t intervalle, --interval=intervalle
Définir l'intervalle de rapport à une valeur autre que la seconde par défaut. L'argument intervalle suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes). Voir également l'option -T.
-T heure_fin, --finish=heure_fin
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements enregistrés avant ou à heure_fin. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe de heure_fin.

Lorsqu'il est utilisé pour définir le temps d'exécution avant que pcp2opentelemetry ne se termine, si aucun échantillon n'est donné (voir -s), alors le nombre d'échantillons rapportés dépend de l'intervalle (voir -t). Si des échantillons sont donnés, l'intervalle sera ajusté pour permettre le rapport de ces échantillons pendant le temps d'exécution. Dans le cas où -T, -s, et -t sont tous donnés, heure_fin déterminera le temps réel pendant lequel pcp2opentelemetry s'exécutera.

-u, --url
URL pour envoyer une requête HTTP POST (au lieu de la sortie standard par défaut).
-U, --http-user
Nom d'utilisateur lors de l'utilisation de l'authentification basique HTTP avec l'option -u.
-v, --omit-flat
Rapporter uniquement les métriques à valeurs d'ensemble avec instances (par exemple, disk.dev.read) et omettre les métriques "plates" à valeur unique sans instances (par exemple, kernel.all.sysfork). Voir -i et -I.
-V, --version
Afficher le numéro de version et quitter.
-x, --with-extended
Écrire des informations étendues.
-X, --with-everything
Écrire tout ce qui est connu sur les métriques, y compris les identifiants internes PCP. Les étiquettes sont cependant omises pour des raisons de compatibilité ascendante, utilisez -m pour les inclure également.

pcp2opentelemetry(1)

OpenTelemetry Exporter for PCP metrics

NAME

pcp2opentelemetry — OpenTelemetry Exporter for PCP metrics

SYNOPSIS

pcp2opentelemetry [-c config...][-D debuglist][-h host|-a archive][-?]

DESCRIPTION

The pcp2opentelemetry utility is a frontend to the PCP framework that connects to a PCP metrics source (either a live PMCD or an archive), and exports the collected metrics in OpenTelemetry format to a specified endpoint.

The configuration file dictates which metrics are exported and how they are mapped to OpenTelemetry metrics.

CONFIGURATION FILE

The configuration file is used to specify which PCP metrics should be exported to OpenTelemetry and how they should be mapped. The format is described in pmrep.conf(5).

The default configuration file is $PCP_SYSCONF_DIR/pmrep/pcp2opentelemetry.conf.

OPTIONS

-c config, --config=config

Load metrics configuration from the specified file config. Multiple -c options can be used to cascade configuration files. The order is important, later files override earlier ones.

If no -c options are specified, then pcp2opentelemetry.conf is searched for in the current directory and then in $PCP_SYSCONF_DIR/pmrep/.

The configuration file format is described in pmrep.conf(5).

-D debuglist, --debug=debuglist

Set the PCP debugging flags to those specified in debuglist. This is a comma-separated list of options. Use pmdbg -l to get a list of available debugging options and their meanings.

Example: -D pmtime,pmresult

-h host, --host=host

Connect to the PCP metrics collector (PMCD) specified by host. The default is to connect to localhost.

-a archive, --archive=archive

Extract performance metrics from an archive or set of archives, specified by the comma-separated list of filenames in archive. See pmcd(1) for a more detailed description of the archive format.

-y scale, --time-scale=scale

Unité/échelle pour les métriques de temps, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option ne* override pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).

-Y scale, --time-scale-force=scale

Comme -y mais cette option va* override les spécifications par métrique.

-z, --hostzone

Utilise le fuseau horaire local de l'hôte source des métriques de performance, tel qu'identifié par les options -h ou -a. Par défaut, utilise le fuseau horaire de l'hôte local.

-Z timezone, --timezone=timezone

Utilise timezone pour la date et l'heure. Timezone est dans le format de la variable d'environnement TZ tel que décrit dans environ(7). Notez que lors de l'inclusion d'une chaîne de fuseau horaire dans la sortie, les décalages UTC de style ISO 8601 sont utilisés (donc quelque chose comme -Z EST+5 deviendra UTC-5).

-?, --help

Affiche le message d'utilisation et quitte.

FILES

pcp2opentelemetry.conf

Fichier de configuration de pcp2opentelemetry (voir -c)

$PCP_SYSCONF_DIR/pmrep/*.conf

Fichiers de configuration par défaut fournis par le système pour pmrep.

PCP ENVIRONMENT

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

DEBUGGING OPTIONS

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
