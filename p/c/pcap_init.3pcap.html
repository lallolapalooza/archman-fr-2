NOM

pcap_init - initialiser la bibliothèque

SYNTAXE

#include <pcap/pcap.h>
char errbuf[PCAP_ERRBUF_SIZE];
int pcap_init(unsigned int opts, char *errbuf);

DESCRIPTION

pcap_init() est utilisé pour initialiser la bibliothèque Packet Capture. opts spécifie les options pour la bibliothèque ; errbuf est un tampon suffisamment grand pour contenir au moins PCAP_ERRBUF_SIZE caractères.

Actuellement, les options pouvant être spécifiées dans opts sont :

PCAP_CHAR_ENC_LOCAL
Traiter toutes les chaînes fournies en tant qu'arguments, et retourner toutes les chaînes à l'appelant, comme étant dans le codage de caractères local.
PCAP_CHAR_ENC_UTF_8
Traiter toutes les chaînes fournies en tant qu'arguments, et retourner toutes les chaînes à l'appelant, comme étant en UTF-8.

Sur les systèmes de type UNIX, le codage de caractères local est supposé être UTF-8, donc aucune transformation de codage de caractères n'est effectuée.

Sous Windows, le codage de caractères local est la page de codes ANSI locale.

Si pcap_init() n'est pas appelée, les chaînes sont traitées comme étant dans la page de codes ANSI locale sous Windows, pcap_lookupdev(3PCAP) réussira s'il existe un périphérique sur lequel capturer, et pcap_create(3PCAP) tente de vérifier si la chaîne passée en argument est une chaîne UTF-16LE - notez que cette tentative est dangereuse, car elle peut dépasser la fin de la chaîne - pour gérer le fait que pcap_lookupdev() retourne une chaîne UTF-16LE. Les programmes qui n'appellent pas pcap_init() devraient, sous Windows, appeler pcap_wsockinit() pour initialiser Winsock ; ce n'est pas nécessaire si pcap_init() est appelée, car pcap_init() initialisera Winsock elle-même sous Windows.

VALEUR DE RETOUR

pcap_init() retourne 0 en cas de succès et PCAP_ERROR en cas d'échec. Si PCAP_ERROR est retourné, errbuf est rempli avec un message d'erreur approprié.

COMPATIBILITÉ ASCENDANTE

Cette fonction est devenue disponible dans la version 1.9.0 de libpcap. Dans les versions précédentes, sous Windows, toutes les chaînes fournies en tant qu'arguments, et toutes les chaînes retournées à l'appelant, sont dans le codage de caractères local.
