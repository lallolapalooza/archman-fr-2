PCLOSE(3P) Manuel du programmeur POSIX PCLOSE(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pclose — fermer un flux de pipe vers ou depuis un processus

SYNOPSIS

#include <stdio.h>
int pclose(FILE *stream);

DESCRIPTION

La fonction pclose() ferme un flux qui a été ouvert par popen(), attend la fin de l'exécution de la commande et renvoie l'état de terminaison du processus qui exécutait l'interpréteur de commandes. Cependant, si un appel a rendu l'état de terminaison indisponible pour pclose(), alors pclose() renvoie -1 avec errno défini à [ECHILD] pour signaler cette situation. Cela peut se produire si l'application appelle l'une des fonctions suivantes :

*
wait()
*
waitpid() avec un argument pid inférieur ou égal à 0 ou égal à l'identifiant de processus de l'interpréteur de commandes
*
Toute autre fonction non définie dans ce volume de POSIX.1‐2017 qui pourrait effectuer l'une des actions ci-dessus

Dans tous les cas, pclose() ne doit pas retourner avant que le processus fils créé par popen() ne se soit terminé.

Si l'interpréteur de commandes ne peut pas être exécuté, l'état de terminaison du processus fils renvoyé par pclose() sera comme si l'interpréteur de commandes s'était terminé en utilisant exit(127) ou _exit(127).

La fonction pclose() n'affecte pas l'état de terminaison d'un fils du processus appelant autre que celui créé par popen() pour le flux associé.

Si l'argument stream à pclose() n'est pas un pointeur vers un flux créé par popen(), le résultat de pclose() est indéfini.

Si un thread est annulé pendant l'exécution de pclose(), le comportement est indéfini.

VALEUR RENVOYÉE

En cas de succès, pclose() renvoie l'état de terminaison de l'interpréteur de commandes. Sinon, pclose() renvoie -1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction pclose() échoue si :

ECHILD
L'état du processus fils n'a pas pu être obtenu, comme décrit ci-dessus.

RATIONALE

Il est exigé que pclose() ne retourne pas avant que le processus fils ne se termine. Ceci vise à interdire les implémentations qui renvoient [EINTR] si un signal est reçu pendant l'attente. Si pclose() retournait avant que le fils ne se termine, il n'y aurait aucun moyen pour l'application de découvrir quel fils était associé au flux, et elle ne pourrait pas effectuer le nettoyage elle-même.

Si le flux pointé par stream n'a pas été créé par popen(), les implémentations historiques de pclose() renvoient -1 sans définir errno. Pour éviter d'exiger que pclose() définisse errno dans ce cas, POSIX.1‐2008 rend le comportement non spécifié. Une application ne doit pas utiliser pclose() pour fermer un flux qui n'a pas été créé par popen().

Certaines implémentations historiques de pclose() bloquent ou ignorent les signaux SIGINT, SIGQUIT et SIGHUP lors de l'attente de la terminaison du processus fils. Comme ce comportement n'est pas décrit pour la fonction pclose() dans POSIX.1‐2008, de telles implémentations ne sont pas conformes. De plus, certaines implémentations historiques renvoient [EINTR] si un signal est reçu, même si le processus fils ne s'est pas terminé. Ces implémentations sont également considérées comme non conformes.

Considérez, par exemple, une application qui utilise :

popen("commande", "r")

pour démarrer commande, qui fait partie de la même application. Le processus père écrit une invite sur sa sortie standard (probablement le terminal) puis lit à partir du flux ouvert par popen(). Le processus fils lit la réponse de l'utilisateur, effectue une transformation sur la réponse (expansion de chemin, par exemple) et écrit le résultat sur sa sortie standard. Le processus père lit le résultat depuis le pipe, fait quelque chose avec, et affiche une autre invite. Le cycle se répète. En supposant que les deux processus effectuent des vidages de tampon appropriés, cela devrait fonctionner.

Pour être conforme à POSIX.1‐2008, pclose() doit utiliser waitpid(), ou une fonction similaire, au lieu de wait().

L'exemple de code ci-dessous illustre comment la fonction pclose() pourrait être implémentée sur un système conforme à POSIX.1‐2008.

int pclose(FILE *stream)
{
    int stat;
    pid_t pid;
    pid = <pid du processus créé pour le flux par popen()>
    (void) fclose(stream);
    while (waitpid(pid, &stat, 0) == -1) {
        if (errno != EINTR){
            stat = -1;
            break;
        }
    }
    return(stat);
}
