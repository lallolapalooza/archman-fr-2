PCP2SPARK(1) Manuel des commandes générales PCP2SPARK(1)

NOM

pcp2spark - Exportateur de métriques pcp-vers-spark

SYNTAXE

pcp2spark [-5CGHIjLmnrRvV?] [-4 action] [-8|-9 limite] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c config] [--container conteneur] [-D débogage] [--daemonize] [-e dérivé] [-g serveur] [-h hôte] [-i instances] [-J rang] [-K spécification] [-N prédicat] [-O origine] [-p port] [-P|-0 précision] [-q|-Q échelle-nombre] [-s échantillons] [-S heure-début] [-t intervalle] [-T heure-fin] [-y|-Y échelle-temps] spécification-métrique [...]

DESCRIPTION

pcp2spark est un outil personnalisable d'exportation de métriques de performance de PCP vers Apache Spark. Toute métrique de performance disponible, en direct ou archivée, système et/ou application, peut être sélectionnée pour l'exportation en utilisant soit des arguments de ligne de commande, soit un fichier de configuration.

pcp2spark agit comme un pont qui fournit un flux de socket réseau sur une adresse/port donné auquel une tâche worker Apache Spark peut se connecter pour récupérer les métriques PCP configurées depuis pcp2spark, en les exportant via les extensions de streaming de l'API Apache Spark.

pcp2spark est un proche parent de pmrep(1). Référez-vous à pmrep(1) pour la description de spécification-métrique acceptée sur la ligne de commande de pcp2spark. Voir pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2spark.conf. Cette page décrit les options spécifiques à pcp2spark et les différences de fichier de configuration avec pmrep.conf(5). pmrep(1) liste également quelques exemples d'utilisation dont la plupart sont applicables également avec pcp2spark.

Seules les options de ligne de commande listées sur cette page sont supportées, les autres options disponibles pour pmrep(1) ne le sont pas.

Les options via les variables d'environnement (voir pmGetOptions(3)) écrasent les valeurs par défaut intégrées correspondantes (le cas échéant). Les options du fichier de configuration écrasent les variables d'environnement correspondantes (le cas échéant). Les options de ligne de commande écrasent les options correspondantes du fichier de configuration (le cas échéant).

UTILISATION GÉNÉRALE

Une configuration générale pour utiliser pcp2spark impliquerait que l'utilisateur configure pcp2spark pour les métriques PCP à exporter, puis démarre l'application pcp2spark. L'application pcp2spark attendrait alors et écouterait sur l'adresse/port donné pour une connexion d'un thread worker Apache Spark. Le thread worker se connecterait alors à pcp2spark.

Lorsqu'un thread worker Apache Spark s'est connecté, pcp2spark commencera à streamer les données de métriques PCP vers Apache Spark jusqu'à ce que le thread worker termine ou que la connexion soit interrompue. Si la connexion est interrompue ou si le socket est fermé par le thread worker Apache Spark, pcp2spark se terminera.

Pour un exemple de job worker Apache Spark qui se connectera à une instance pcp2spark sur une adresse/port donné et récupérera les données de métriques PCP, consultez l'exemple fourni dans le répertoire des exemples PCP pour pcp2spark (souvent fourni par le paquet de développement PCP) ou la version en ligne sur https://github.com/performancecopilot/pcp/blob/main/src/pcp2spark/.

FICHIER DE CONFIGURATION

pcp2spark utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf : version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. Le reste des options de pmrep.conf sont reconnues mais ignorées par souci de compatibilité.

options spécifiques à pcp2spark

spark_server (chaîne)

Spécifie l'adresse sur laquelle pcp2spark écoutera les connexions d'un thread worker Apache Spark. Option de ligne de commande correspondante : -g. Par défaut : 127.0.0.1.

spark_port (entier)

Spécifie le port sur lequel pcp2spark écoutera les connexions. Option de ligne de commande correspondante : -p. Par défaut : 44325.

OPTIONS

Les options de ligne de commande disponibles sont :

-0 précision, --precision-force=précision
Comme -P mais cette option écrasera les spécifications par métrique.
-4 action, --names-change=action
Spécifie quelle action entreprendre lors de la réception d'un événement de changement de nom de métrique pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques peu après son démarrage et informe les outils clients en cours d'exécution comme pcp2spark. Les valeurs valides pour action sont update (rafraîchir les métriques échantillonnées), ignore (ne rien faire - le comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignore-unknown
Ignore silencieusement tout nom de métrique qui ne peut pas être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-8 limite, --limit-filter=limite
Limite les résultats aux instances dont les valeurs sont supérieures/inférieures à limite. Un entier positif inclura les instances avec des valeurs égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances avec des valeurs égales ou inférieures à la limite dans le rapport. Une valeur de zéro n'effectue aucun filtrage par limite. Cette option n'écrasera pas les spécifications possibles par métrique. Voir aussi -J et -N.
-9 limite, --limit-filter-force=limite
Comme -8 mais cette option écrasera les spécifications par métrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Force le premier échantillon à être aligné sur la limite d'une unité de temps naturelle alignement. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe de alignement.
--archive-folio=folio
Lit les archives sources de métriques du folio d'archives PCP créé par des outils comme pmchart(1) ou, moins fréquemment, manuellement avec mkaf(1).
-b échelle, --space-scale=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, etc. Cette option n'écrasera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-B échelle, --space-scale-force=échelle
Comme -b mais cette option écrasera les spécifications par métrique.
-c config, --config=config
Spécifie le fichier ou répertoire config à utiliser. Au cas où config est un répertoire, tous les fichiers qui s'y trouvent se terminant par
.conf sera inclus. La valeur par défaut est la première trouvée parmi : ./pcp2spark.conf, $HOME/.pcp2spark.conf, $HOME/pcp/pcp2spark.conf, et $PCP_SYSCONF_DIR/pcp2spark.conf. Pour plus de détails, voir la section ci-dessus et pmrep.conf(5).
--container=conteneur
Récupérer les métriques de performance à partir du conteneur spécifié, local ou distant (voir -h).
-C, --check
Quitter avant de rapporter toute valeur, mais après avoir analysé la configuration et les métriques et imprimé les éventuels en-têtes.
--daemonize
Démoniser au démarrage.
-e dérivé, --derived=dérivé
Spécifier les métriques de performance dérivées. Si dérivé commence par un slash (``/'') ou par un point (``.'') il sera interprété comme un fichier de configuration des métriques dérivées PCP, sinon il sera interprété comme des expressions de métriques dérivées séparées par des virgules ou des points-virgules. Pour une description complète des métriques dérivées et des fichiers de configuration des métriques dérivées PCP, voir pmLoadDerivedConfig(3) et pmRegisterDerived(3). Alternativement, l'utilisation de la syntaxe de configuration pmrep.conf(5) permet de définir les métriques dérivées dans le cadre des ensembles de métriques.

En cas de problèmes avec les métriques dérivées, examinez en détail les pages de manuel susmentionnées et assurez-vous que toutes les métriques requises sont disponibles, en particulier lors de l'utilisation d'archives. Utilisez -Dderive pour afficher des informations de débogage supplémentaires sur l'analyse des métriques dérivées.

-g serveur, --spark-server=serveur
Adresse du serveur local de pcp2spark.
-G, --no-globals
Ne pas inclure les métriques globales dans le rapport (voir pmrep.conf(5)).
-h hôte, --host=hôte
Récupérer les métriques de performance à partir de pmcd(1) sur hôte, plutôt que de localhost par défaut.
-H, --no-header
Ne pas imprimer d'en-têtes.
-i instances, --instances=instances
Récupérer et rapporter uniquement les instances de métriques spécifiées. Par défaut, toutes les instances, présentes et futures, sont rapportées.

Se référer à pmrep(1) pour une description complète de cette option.

-I, --ignore-incompat
Ignorer les métriques incompatibles. Par défaut, les métriques incompatibles (c'est-à-dire dont le type n'est pas pris en charge ou qui ne peuvent pas être mises à l'échelle comme demandé) provoqueront la terminaison de pcp2spark avec un message d'erreur. Avec cette option, toutes les métriques incompatibles sont silencieusement omises du rapport. Cela peut être particulièrement utile lors de la demande de nœuds non feuilles de l'arbre PMNS pour le rapport.
-j, --live-filter
Effectuer un filtrage en direct des instances. Cela permet de capturer toutes les instances nommées même si des processus sont redémarrés à un moment donné (contrairement à sans filtrage en direct). L'exécution d'un filtrage en direct sur un grand nombre d'instances entraînera une certaine surcharge interne, une certaine prudence de la part de l'utilisateur est donc conseillée. Voir aussi -n.
-J rang, --rank=rang
Limiter les résultats aux instances les plus hautes/basses parmi les métriques de type ensemble. Un entier positif inclura les instances de plus grande valeur dans le rapport. Un entier négatif inclura les instances de plus petite valeur dans le rapport. Une valeur de zéro n'effectue aucun classement. Le classement n'implique pas le tri, voir -6. Voir aussi -8.
-K spéc, --spec-local=spéc
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spéc est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peut être utilisée.
-L, --local-PMDA
Utiliser un contexte local pour collecter les métriques des PMDA DSO sur l'hôte local sans PMCD. Voir aussi -K.
-m, --include-labels
Inclure les étiquettes de métriques PCP dans la sortie.
-n, --invert-filter
Effectuer le classement avant le filtrage en direct. Par défaut, le filtrage en direct des instances (lorsqu'il est demandé, voir -j) se produit avant le classement des instances (lorsqu'il est demandé, voir -J). Avec cette option, la logique est inversée et le classement se produit avant le filtrage en direct.
-N prédicat, --predicate=prédicat
Spécifier une liste de métriques de référence de filtre prédicat séparées par des virgules. Par défaut, le classement (voir -J) est effectué individuellement pour chaque métrique. Avec des prédicats, le classement n'est effectué que pour les métriques prédicats spécifiées. Lors du rapport, le reste des métriques partageant le même domaine d'instance (voir PCPIntro(1)) que le prédicat inclura uniquement les instances les plus hautes/basses du prédicat correspondant. Le classement n'implique pas le tri, voir -6.

Ainsi, par exemple, en utilisant proc.memory.rss (taille de la mémoire résidente d'un processus) comme métrique prédicat avec proc.io.total_bytes et mem.util.used comme métriques à rapporter, seuls les processus utilisant le plus/le moins de mémoire (selon -J) seront inclus lors du rapport des octets totaux écrits par les processus. Comme mem.util.used est une métrique à valeur unique (ne partageant donc pas le même domaine d'instance que les métriques liées aux processus), elle sera rapportée comme d'habitude.

-O origine, --origin=origine
Lors du rapport de métriques archivées, le rapport commencera à origine dans la fenêtre temporelle (voir -S et -T). Se référer à PCPIntro(1) pour une description complète de la syntaxe de origine.
-p port, --spark-port=port
Port local de pcp2spark.
-P précision, --precision=précision
Utiliser précision pour les valeurs numériques de sortie non entières. Par défaut, 3 décimales sont utilisées (lorsque applicable). Cette option ne remplacera pas les spécifications par métrique possibles.
-q échelle, --count-scale=échelle
Unité/échelle pour les métriques de comptage, les valeurs possibles incluent count x 10^-1, count, count x 10, count x 10^2, et ainsi de suite de 10^-8 à 10^7. (Ces valeurs sont actuellement sensibles aux espaces.) Cette option ne remplacera pas les spécifications par métrique possibles. Voir aussi pmParseUnitsStr(3).
-Q échelle, --count-scale-force=échelle
Similaire à -q, mais cette option remplacera les spécifications par métrique.
-r, --raw
Sortie des valeurs brutes des métriques, ne pas convertir les compteurs cumulatifs en taux. Cette option remplacera les spécifications par métrique possibles.
-R, --raw-prefer
Similaire à -r, mais cette option ne remplacera pas les spécifications par métrique.
-s échantillons, --samples=échantillons
L'argument échantillons définit le nombre d'échantillons à récupérer et à rapporter. Si échantillons est 0 ou si -s n'est pas spécifié, pcp2spark échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive). Voir aussi -T.
-S heure_début, --start=heure_début
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements effectués à partir de heure_début. Se référer à PCPIntro(1) pour une description complète de la syntaxe de heure_début.
-t intervalle, --interval=intervalle
Définir l'intervalle de rapport à autre chose que la seconde par défaut. L'argument intervalle suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes). Voir aussi l'option -T.
-T heure_fin, --finish=heure_fin
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements effectués avant ou à heure_fin. Se référer à PCPIntro(1) pour une description complète de la syntaxe de heure_fin.

Lorsqu'utilisé pour définir le temps d'exécution avant que pcp2spark ne quitte, si aucun échantillon n'est donné (voir -s), le nombre d'échantillons rapportés dépend de l'intervalle (voir -t). Si échantillons est donné, alors l'intervalle sera ajusté pour permettre le rapport de échantillons pendant le temps d'exécution. Si -T, -s et -t sont tous donnés, heure_fin déterminera le moment réel où pcp2spark s'exécutera.

-v, --omit-flat
Rapporter uniquement les métriques de type ensemble avec instances (par ex. disk.dev.read) et omettre les métriques "plates" à valeur unique sans instances (par ex. kernel.all.sysfork). Voir -i et -I.
-V, --version
Afficher le numéro de version et quitter.
-y échelle, --time-scale=échelle
Unité/échelle pour les métriques de temps, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Ce
s option aura ne prévaudra pas sur les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-Y échelle, --time-scale-force=échelle
Comme -y mais cette option prévaudra sur les spécifications par métrique.
-?, --help
Affiche le message d'utilisation et quitte.

Fichier de configuration pcp2spark (voir -c)

Fichiers de configuration pmrep par défaut fournis par le système

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

Il convient de noter en particulier que PCP_DISCRETE_ONCE peut être défini pour garantir que les valeurs de métriques discrètes ne sont signalées qu'une seule fois, à moins qu'elles ne changent à un moment donné.

OPTIONS DE DEBOURRAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider au dépannage, bien que les informations soient parfois cryptiques et principalement destinées aux développeurs plutôt qu'aux utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
