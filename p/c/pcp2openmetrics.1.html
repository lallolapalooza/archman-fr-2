PCP2OPENMETRICS(1) Manuel des commandes générales PCP2OPENMETRICS(1)

NOM

pcp2openmetrics - exportateur pcp vers openmetrics

SYNTAXE

pcp2openmetrics [-5CEGHIjLmnrRvVxXz?] [-4 action] [-8|-9 limite] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c config] [--container conteneur] [-D débogage] [--daemonize] [-e dérivé] [-f format] [-F fichier-sortie] [-h hôte] [-i instances] [-J rang] [-K spéc] [-N prédicat] [-o délai] [-O origine] [-p mot-de-passe] [-P|-0 précision] [-q|-Q échelle-compte] [-s échantillons] [-S heure-début] [-t intervalle] [-T heure-fin] [-u url] [-U nom-utilisateur] [-y|-Y échelle-temps] [-Z fuseau-horaire] spécification-métrique [...]

DESCRIPTION

pcp2openmetrics est un outil personnalisable d'exportation de métriques de performance de PCP vers le format Open Metrics - https://openmetrics.io. Toute métrique de performance disponible, en direct ou archivée, système et/ou application, peut être sélectionnée pour l'exportation en utilisant soit des arguments en ligne de commande, soit un fichier de configuration.

pcp2openmetrics est un proche parent de pmrep(1). Se référer à pmrep(1) pour la description de spécification-métrique acceptée en ligne de commande sur pcp2openmetrics. Voir pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2openmetrics.conf. Cette page décrit les options spécifiques à pcp2openmetrics et les différences de fichier de configuration avec pmrep.conf(5). pmrep(1) liste également quelques exemples d'utilisation dont la plupart sont applicables à pcp2openmetrics également.

Seules les options en ligne de commande listées sur cette page sont supportées, les autres options disponibles pour pmrep(1) ne sont pas supportées.

Les options via les valeurs d'environnement (voir pmGetOptions(3)) remplacent les valeurs par défaut intégrées correspondantes (s'il y en a). Les options du fichier de configuration remplacent les variables d'environnement correspondantes (s'il y en a). Les options en ligne de commande remplacent les options du fichier de configuration correspondantes (s'il y en a).

FICHIER DE CONFIGURATION

pcp2openmetrics utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf : version, source, speclocal, dérivé, en-tête, globaux, échantillons, intervalle, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rang, limit_filter, limit_filter_force, invert_filter, prédicat, omit_flat, include_labels, précision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. Le reste des options pmrep.conf est reconnu mais ignoré pour des raisons de compatibilité.

options spécifiques à pcp2openmetrics

everything (booléen)

Écrit tout ce que l'on sait sur les métriques, y compris les identifiants internes de PCP. Les étiquettes sont cependant omises pour des raisons de compatibilité ascendante. Activer include_labels pour les inclure également. L'option en ligne de commande correspondante est -X. Par défaut : non.

exact_types (booléen)

Écrit les nombres en tant que types de données numériques, et non comme des chaînes, perdant potentiellement une certaine précision. L'option en ligne de commande correspondante est -E. Par défaut : non.

url (chaîne)

Envoie la sortie OPENMETRICS sous forme de POST HTTP à l'URL donnée. L'option en ligne de commande correspondante est -u. Par défaut : Aucun.

http_pass (chaîne)

Utilise le mot de passe donné pour l'authentification de base lors de l'envoi d'un POST HTTP. L'option en ligne de commande correspondante est -p. Par défaut : Aucun.

http_user (chaîne)

Utilise le nom d'utilisateur donné pour l'authentification de base lors de l'envoi d'un POST HTTP. L'option en ligne de commande correspondante est -U. Par défaut : Aucun.

http_timeout (nombre)

Temps maximum (en secondes) lors de l'envoi d'un POST HTTP. L'option en ligne de commande correspondante est -o. Par défaut : 2.5 secondes.

no-comment (booléen)

Omet la ligne de commentaire # PCP5. Omet l'en-tête pour certaines données de métriques telles que le type, le domaine d'instance et la sémantique. L'option en ligne de commande correspondante est -x. Par défaut : non.

OPTIONS

Les options en ligne de commande disponibles sont :

-0 précision, --precision-force=précision
Comme -P mais cette option remplacera les spécifications par métrique.
-4 action, --names-change=action
Spécifie quelle action entreprendre lors de la réception d'un événement de changement de nom de métrique pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques peu après son démarrage, et informe les outils clients en cours d'exécution comme pcp2openmetrics. Les valeurs valides pour action sont update (actualiser les métriques échantillonnées), ignore (ne rien faire - le comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignore-unknown
Ignore silencieusement tout nom de métrique qui ne peut pas être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-8 limite, --limit-filter=limite
Limite les résultats aux instances dont les valeurs sont supérieures/inférieures à la limite. Un entier positif inclura les instances dont les valeurs sont égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances dont les valeurs sont égales ou inférieures à la limite dans le rapport. Une valeur de zéro n'effectue aucun filtrage de limite. Cette option ne remplacera pas les spécifications possibles par métrique. Voir également -J et -N.
-9 limite, --limit-filter-force=limite
Comme -8 mais cette option remplacera les spécifications par métrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archive Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Force le premier échantillon à être aligné sur la limite d'une unité de temps naturelle alignement. Se référer à PCPIntro(1) pour une description complète de la syntaxe de alignement.
--archive-folio=folio
Lit les archives sources de métriques à partir du folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b échelle, --space-scale=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, etc. Cette option ne remplacera pas les spécifications possibles par métrique. Voir également pmParseUnitsStr(3).
-B échelle, --space-scale-force=échelle
Comme -b mais cette option remplacera les spécifications par métrique.
-c config, --config=config
Spécifie le fichier ou répertoire de config à utiliser. Si config est un répertoire, tous les fichiers qui s'y trouvent et qui se terminent par .conf seront inclus. Par défaut, c'est le premier trouvé parmi : ./pcp2openmetrics.conf, $HOME/.pcp2openmetrics.conf, $HOME/pcp/pcp2o

-a archive, --archive=archive
Get performance metrics from a set of PCP archives. The archive parameter is a comma-separated list of filenames, and pcp2openmetrics will try to reconstruct the original request from the archives. See also -S and -T.
-A access, --access=access
Set the access control list access for the exported metrics. Possible values are all or none. The default is all.
-b value, --backlog=value
Set the backlog size of the listening socket for the HTTP/JSON server to value. The default is 64.
-B, --no-header
Do not print a header line.
-c config, --config=config
Specify the configuration file. The configuration file can specify multiple metric names and parameters, and can also be used to specify command line options. By default, pcp2openmetrics looks for configuration in $PCP_RC_DIR/pcp2openmetrics.conf, $PCP_SYSCONF_DIR/pcp2openmetrics.conf. For details, see the above section and pmrep.conf(5).
--container=container
Fetch performance metrics from the specified container, either local or remote (see -h).
-C, --check
Exit before reporting any values, but after parsing the configuration and metrics and printing possible headers.
--daemonize
Daemonize on startup.
-e derived, --derived=derived
Specify derived performance metrics. If derived starts with a slash (``/'') or with a dot (``.'') it will be interpreted as a PCP derived metrics configuration file, otherwise it will be interpreted as comma- or semicolon-separated derived metric expressions. For complete description of derived metrics and PCP derived metrics configuration files see pmLoadDerivedConfig(3) and pmRegisterDerived(3). Alternatively, using pmrep.conf(5) configuration syntax allows defining derived metrics as part of metricsets.

In case of issues with derived metrics, review the aforementioned manual pages in detail and ensure all the required metrics are available, especially when using archives. Use -Dderive to see additional debug information about parsing derived metrics.

-E, --exact-types
Write numbers as number data types, not as strings, potentially losing some precision.
-f format, --timestamp-format=format
Use the format string for formatting the timestamp. The format will be used with Python's datetime.strftime method which is mostly the same as that described in strftime(3). The default is %Y-%m-%d %H:%M:%S.
-F outfile, --output-file=outfile
Specify the output file outfile.
-G, --no-globals
Do not include global metrics in reporting (see pmrep.conf(5)).
-h host, --host=host
Fetch performance metrics from pmcd(1) on host, rather than from the default localhost.
-i instances, --instances=instances
Retrieve and report only the specified metric instances. By default all instances, present and future, are reported.

Refer to pmrep(1) for complete description of this option.

-I, --ignore-incompat
Ignore incompatible metrics. By default incompatible metrics (that is, their type is unsupported or they cannot be scaled as requested) will cause pcp2openmetrics to terminate with an error message. With this option all incompatible metrics are silently omitted from reporting. This may be especially useful when requesting non-leaf nodes of the PMNS tree for reporting.
-j, --live-filter
Perform instance live filtering. This allows capturing all named instances even if processes are restarted at some point (unlike without live filtering). Performing live filtering over a huge number of instances will add some internal overhead so a bit of user caution is advised. See also -n.
-J rank, --rank=rank
Limit results to highest/lowest ranked instances of set-valued metrics. A positive integer will include highest valued instances in reporting. A negative integer will include lowest valued instances in reporting. A value of zero performs no ranking. Ranking does not imply sorting, see -6. See also -8.
-K spec, --spec-local=spec
When fetching metrics from a local context (see -L), the -K option may be used to control the DSO PMDAs that should be made accessible. The spec argument conforms to the syntax described in pmSpecLocalPMDA(3). More than one -K option may be used.
-L, --local-PMDA
Use a local context to collect metrics from DSO PMDAs on the local host without PMCD. See also -K.
-n, --invert-filter
Perform ranking before live filtering. By default instance live filtering (when requested, see -j) happens before instance ranking (when requested, see -J). With this option the logic is inverted and ranking happens before live filtering.
-m, --include-labels
Include PCP metric labels in the output.
-N predicate, --predicate=predicate
Specify a comma-separated list of predicate filter reference metrics. By default ranking (see -J) happens for each metric individually. With predicates, ranking is done only for the specified predicate metrics. When reporting, rest of the metrics sharing the same instance domain (see PCPIntro(1)) as the predicate will include only the highest/lowest ranking instances of the corresponding predicate. Ranking does not imply sorting, see -6.

So for example, using proc.memory.rss (resident memory size of process) as the predicate metric together with proc.io.total_bytes and mem.util.used as metrics to be reported, only the processes using most/least (as per -J) memory will be included when reporting total bytes written by processes. Since mem.util.used is a single-valued metric (thus not sharing the same instance domain as the process related metrics), it will be reported as usual.

-o, --http-timeout
Timeout (in seconds) when sending a HTTP POST with the -u option. Default value is 2.5 seconds.
-O origin, --origin=origin
When reporting archived metrics, start reporting at origin within the time window (see -S and -T). Refer to PCPIntro(1) for a complete description of the syntax for origin.
-p, --http-pass
Password when using HTTP basic authentication with the -u option.
-P precision, --precision=precision
Use precision for numeric non-integer output values. The default is to use 3 decimal places (when applicable). This option will not override possible per-metric specifications.
-q scale, --count-scale=scale
Unit/scale for count metrics, possible values include count x 10^-1, count, count x 10, count x 10^2, and so forth from 10^-8 to 10^7. (These values are currently space-sensitive.) This option will not override possible per-metric specifications. See also pmParseUnitsStr(3).
-Q scale, --count-scale-force=scale
Like -q but this option will override per-metric specifications.
-r, --raw
Output raw metric values, do not convert cumulative counters to rates. This option will override possible per-metric specifications.
-R, --raw-prefer
Like -r but this option will not override per-metric specifications.
-s samples, --samples=samples
The samples argument defines the number of samples to be retrieved and reported. If samples is 0 or -s is not specified, pcp2openmetrics will sample and report continuously (in real time mode) or until the end of the set of PCP archives (in archive mode). See also -T.
-S starttime, --start=starttime
When reporting archived metrics, the report will be restricted to those records logged at or after starttime. Refer to PCPIntro(1) for a complete description of the syntax for starttime.
-t interval, --interval=interval
Set the reporting interval to something other than the default 1 second. The interval argument follows the syntax described in PCPIntro(1), and in the simplest form may be an unsigned integer (the implied units in this case are seconds). See also the -T option.
-T endtime, --finish=endtime
When reporting archived metrics, the report will be restricted to those records logged before or at endtime. Refer to PCPIntro(1) for a complete description of the syntax for endtime.

When used to define the runtime before pcp2openmetrics will exit, if no samples is given (see -s) then the number of reported samples depends on interval (see -t). If samples is given then interval will be adjusted to allow reporting of samples during runtime. In case all of -T, -s, and -t are given, endtime determines the actual time pcp2openmetrics will run.

URL for sending an HTTP POST (instead of default standard output).
-U user, --user=user
Username when using HTTP basic authentication with the -u option.
-v, --verbose
Increase verbosity of output.
-V, --version
Display version information and exit.
-w, --write-once
Only report once. This is useful for non-periodic metrics.

-V, --version

-y scale, --time-scale=scale
Unité/échelle pour les métriques temporelles, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option *ne* remplacera *pas* les spécifications par métrique possibles. Voir aussi pmParseUnitsStr(3).

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, tel que décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

Il convient de noter en particulier que PCP_DISCRETE_ONCE peut être défini pour garantir que les valeurs de métriques discrètes ne sont signalées qu'une seule fois, sauf si elles changent à un moment donné.

OPTIONS DE BOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
