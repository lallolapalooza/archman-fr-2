PCP2XLSX(1) Manuel des commandes générales PCP2XLSX(1)

NOM

pcp2xlsx - exportateur de métriques pcp vers xlsx

SYNTAXE

pcp2xlsx [-5CGHILmrRvVz?] [-4 action] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c config] [--container conteneur] [--daemonize] [-e dérivé] [-f format] [-F fichier-sortie] [-h hôte] [-i instances] [-K spécification] [-O origine] [-P|-0 précision] [-q|-Q échelle-nombre] [-s échantillons] [-S heure-début] [-t intervalle] [-T heure-fin] [-y|-Y échelle-temps] [-Z fuseau-horaire] spécification-métrique [...]

DESCRIPTION

pcp2xlsx est un outil personnalisable d'exportation de métriques de performance de PCP vers XLSX. Toute métrique de performance disponible, en temps réel ou archivée, système et/ou application, peut être sélectionnée pour l'exportation en utilisant soit des arguments de ligne de commande, soit un fichier de configuration.

pcp2xlsx est un proche parent de pmrep(1). Référez-vous à pmrep(1) pour la description de spécification-métrique acceptée sur la ligne de commande de pcp2xlsx. Voir pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2xlsx.conf. Cette page décrit les options spécifiques à pcp2xlsx et les différences de fichier de configuration avec pmrep.conf(5). pmrep(1) liste également quelques exemples d'utilisation dont la plupart sont applicables à pcp2xlsx également.

Seules les options de ligne de commande listées sur cette page sont prises en charge, les autres options disponibles pour pmrep(1) ne sont pas prises en charge.

Les options via les variables d'environnement (voir pmGetOptions(3)) remplacent les valeurs par défaut intégrées correspondantes (le cas échéant). Les options du fichier de configuration remplacent les variables d'environnement correspondantes (le cas échéant). Les options de ligne de commande remplacent les options du fichier de configuration correspondantes (le cas échéant).

FICHIER DE CONFIGURATION

pcp2xlsx utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf : version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. Le reste des options de pmrep.conf est reconnu mais ignoré pour des raisons de compatibilité.

options spécifiques à pcp2xlsx

Aucune.

OPTIONS

Les options de ligne de commande disponibles sont :

-0 précision, --precision-force=précision
Comme -P mais cette option remplacera les spécifications par métrique.
-4 action, --names-change=action
Spécifie quelle action entreprendre en recevant un événement de changement de nom de métrique pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques peu après son démarrage et informe les outils clients en cours d'exécution comme pcp2xlsx. Les valeurs valides pour action sont update (actualiser les métriques en cours d'échantillonnage), ignore (ne rien faire - le comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignore-unknown
Ignore silencieusement tout nom de métrique qui ne peut pas être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archive Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Force le premier échantillon à être aligné sur la limite d'une unité de temps naturelle alignement. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe pour alignement.
--archive-folio=folio
Lit les archives sources de métriques à partir du folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b échelle, --space-scale=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, et ainsi de suite. Cette option ne remplacera pas les spécifications par métrique. Voir aussi pmParseUnitsStr(3).
-B échelle, --space-scale-force=échelle
Comme -b mais cette option remplacera les spécifications par métrique.
-c config, --config=config
Spécifie le fichier ou le répertoire de config à utiliser. Si config est un répertoire, tous les fichiers se terminant par .conf seront inclus. Par défaut, c'est le premier trouvé parmi : ./pcp2xlsx.conf, $HOME/.pcp2xlsx.conf, $HOME/pcp/pcp2xlsx.conf, et $PCP_SYSCONF_DIR/pcp2xlsx.conf. Pour plus de détails, voir la section ci-dessus et pmrep.conf(5).
--container=conteneur
Récupère les métriques de performance à partir du conteneur spécifié, local ou distant (voir -h).
-C, --check
Quitte avant de rapporter des valeurs, mais après avoir analysé la configuration et les métriques et imprimé les éventuels en-têtes.
--daemonize
Se lance en arrière-plan au démarrage.
-e dérivé, --derived=dérivé
Spécifie les métriques de performance dérivées. Si dérivé commence par une barre oblique (``/'') ou par un point (``.'') il sera interprété comme un fichier de configuration de métriques dérivées PCP, sinon il sera interprété comme des expressions de métriques dérivées séparées par des virgules ou des points-virgules. Pour une description complète des métriques dérivées et des fichiers de configuration de métriques dérivées PCP, voir pmLoadDerivedConfig(3) et pmRegisterDerived(3). Alternativement, l'utilisation de la syntaxe de configuration de pmrep.conf(5) permet de définir des métriques dérivées dans le cadre des jeux de métriques.

En cas de problèmes avec les métriques dérivées, revoyez en détail les pages man susmentionnées et assurez-vous que toutes les métriques requises sont disponibles, surtout lors de l'utilisation d'archives. Utilisez -Dderive pour voir des informations de débogage supplémentaires sur l'analyse des métriques dérivées.

-G, --no-globals
N'inclut pas les métriques globales dans le rapport (voir pmrep.conf(5)).
-f format, --timestamp-format=format
Utilise la chaîne de format pour formater l'horodatage. Le format sera utilisé avec la méthode datetime.strftime de Python, qui est principalement la même que celle décrite dans strftime(3). Le format par défaut est %Y-%m-%d %H:%M:%S.
-F fichier-sortie, --output-file=fichier-sortie
Spécifie le fichier de sortie fichier-sortie.
-h hôte, --host=hôte
Récupère les métriques de performance à partir de pmcd(1) sur l'hôte spécifié.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

>host, plutôt que de localhost par défaut.
-H, --no-header
Ne pas imprimer d'en-têtes.
-i instances, --instances=instances
Récupérer et rapporter uniquement les instances de métrique spécifiées parmi les instances de métrique actuellement présentes. Par défaut, toutes les instances actuelles sont rapportées.

Se référer à pmrep(1) pour une description complète de cette option.

-I, --ignore-incompat
Ignorer les métriques incompatibles. Par défaut, les métriques incompatibles (c'est-à-dire, dont le type n'est pas supporté ou qui ne peuvent pas être mises à l'échelle comme demandé) provoqueront la terminaison de pcp2xlsx avec un message d'erreur. Avec cette option, toutes les métriques incompatibles sont silencieusement omises du rapport. Ceci peut être particulièrement utile lors de la demande de nœuds non feuilles de l'arbre PMNS pour le rapport.
-K spec, --spec-local=spec
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spec est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peut être utilisée.
-L, --local-PMDA
Utiliser un contexte local pour collecter les métriques des PMDA DSO sur l'hôte local sans PMCD. Voir également -K.
-m, --include-labels
Inclure les étiquettes de métriques PCP dans la sortie.
-O origin, --origin=origin
Lors du rapport de métriques archivées, commencer le rapport à origin dans la fenêtre temporelle (voir -S et -T). Se référer à PCPIntro(1) pour une description complète de la syntaxe de origin.
-P precision, --precision=precision
Utiliser precision pour les valeurs de sortie numériques non entières. La valeur par défaut est de 3 décimales (lorsque applicable). Cette option ne remplacera pas les spécifications possibles par métrique.
-q scale, --count-scale=scale
Unité/échelle pour les métriques de comptage, les valeurs possibles incluent count x 10^-1, count, count x 10, count x 10^2, et ainsi de suite de 10^-8 à 10^7. (Ces valeurs sont actuellement sensibles aux espaces.) Cette option ne remplacera pas les spécifications possibles par métrique. Voir également pmParseUnitsStr(3).
-Q scale, --count-scale-force=scale
Comme -q mais cette option remplacera les spécifications par métrique.
-r, --raw
Sortir les valeurs brutes des métriques, ne pas convertir les compteurs cumulatifs en taux. Cette option remplacera les spécifications possibles par métrique.
-R, --raw-prefer
Comme -r mais cette option ne remplacera pas les spécifications par métrique.
-s samples, --samples=samples
L'argument samples définit le nombre d'échantillons à récupérer et à rapporter. Si samples est 0 ou si -s n'est pas spécifié, pcp2xlsx échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive). Voir également -T.
-S starttime, --start=starttime
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements enregistrés à partir de starttime. Se référer à PCPIntro(1) pour une description complète de la syntaxe de starttime.
-t interval, --interval=interval
Définir l'intervalle de rapport à autre chose que la seconde par défaut. L'argument interval suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes). Voir également l'option -T.
-T endtime, --finish=endtime
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements enregistrés avant ou à endtime. Se référer à PCPIntro(1) pour une description complète de la syntaxe de endtime.

Lorsqu'elle est utilisée pour définir le temps d'exécution avant que pcp2xlsx ne se termine, si aucun samples n'est donné (voir -s), le nombre d'échantillons rapportés dépend de l'interval (voir -t). Si samples est donné, l'interval sera ajusté pour permettre le rapport de samples pendant le temps d'exécution. Dans le cas où -T, -s, et -t sont tous donnés, endtime détermine le moment exact où pcp2xlsx s'exécutera.

-v, --omit-flat
Rapporter uniquement les métriques de type ensemble avec des instances (par exemple, disk.dev.read) et omettre les métriques « plates » à valeur unique sans instances (par exemple, kernel.all.sysfork). Voir -i et -I.
-V, --version
Afficher le numéro de version et quitter.
-y scale, --time-scale=scale
Unité/échelle pour les métriques de temps, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option ne remplacera pas les spécifications possibles par métrique. Voir également pmParseUnitsStr(3).
-Y scale, --time-scale-force=scale
Comme -y mais cette option remplacera les spécifications par métrique.
-z, --hostzone
Utiliser le fuseau horaire local de l'hôte source des métriques de performance, tel qu'identifié par les options -h ou -a. Le fuseau horaire par défaut est celui de l'hôte local.
-Z timezone, --timezone=timezone
Utiliser timezone pour la date et l'heure. Timezone est au format de la variable d'environnement TZ tel que décrit dans environ(7). Notez que lors de l'inclusion d'une chaîne de fuseau horaire dans la sortie, des décalages UTC de style ISO 8601 sont utilisés (donc quelque chose comme -Z EST+5 deviendra UTC-5).
-?, --help
Afficher le message d'utilisation et quitter.

FICHIERS

Fichiers de configuration pmrep par défaut fournis par le système

ENVIRONNEMENT PCP

Les variables d'environnement préfixées par PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, tel que décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).
