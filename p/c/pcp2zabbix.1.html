PCP2ZABBIX(1) Manuel des commandes générales PCP2ZABBIX(1)

NOM

pcp2zabbix - exportateur de métriques pcp vers zabbix

SYNTAXE

pcp2zabbix [-5CGHIjlLnrRvV?] [-4 action] [-8|-9 limite] [-a archives] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c configuration] [--container conteneur] [-D débogage] [--daemonize] [-e dérivé] [-E intervalle-envoi] [-g serveur] [-h hôte] [-i instances] [-J rang] [-K spécification] [-N prédicat] [-O origine] [-p port] [-P|-0 précision] [-q|-Q échelle-compte] [-s échantillons] [-S heure-début] [-t intervalle] [-T heure-fin] [-x préfixe] [-X nom-hôte] [-y|-Y échelle-temps] spécification-métrique [...]

DESCRIPTION

pcp2zabbix est un outil personnalisable d'exportation de métriques de performance de PCP vers Zabbix. Toute métrique de performance disponible, en direct ou archivée, système et/ou application, peut être sélectionnée pour l'exportation en utilisant soit des arguments en ligne de commande, soit un fichier de configuration.

pcp2zabbix est un parent proche de pmrep(1). Référez-vous à pmrep(1) pour la description de spécification-métrique acceptée sur la ligne de commande de pcp2zabbix. Voir pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2zabbix.conf. Cette page décrit les options spécifiques de pcp2zabbix et les différences du fichier de configuration avec pmrep.conf(5). pmrep(1) liste également quelques exemples d'utilisation dont la plupart sont applicables à pcp2zabbix également.

Seules les options en ligne de commande listées sur cette page sont supportées, les autres options disponibles pour pmrep(1) ne sont pas supportées.

Les options via les valeurs d'environnement (voir pmGetOptions(3)) écrasent les valeurs par défaut intégrées correspondantes (le cas échéant). Les options du fichier de configuration écrasent les variables d'environnement correspondantes (le cas échéant). Les options en ligne de commande écrasent les options du fichier de configuration correspondantes (le cas échéant).

FICHIER DE CONFIGURATION

pcp2zabbix utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf : version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. Le reste des options de pmrep.conf est reconnu mais ignoré pour des raisons de compatibilité.

options spécifiques à pcp2zabbix

zabbix_server (chaîne)

Spécifiez le nom d'hôte ou l'adresse IP du serveur Zabbix de destination. Si un hôte est surveillé par un proxy, le nom d'hôte ou l'adresse IP du proxy doit être utilisé à la place. L'option de ligne de commande correspondante est -g. La valeur par défaut est localhost.

zabbix_port (entier)

Spécifiez le numéro de port du trapper du serveur exécuté sur le serveur. L'option de ligne de commande correspondante est -p. La valeur par défaut est 10051.

zabbix_host (chaîne)

Spécifiez le nom d'hôte de l'agent tel qu'enregistré dans l'interface Zabbix. L'adresse IP de l'hôte et le nom DNS ne fonctionneront pas. L'option de ligne de commande correspondante est -X. La valeur par défaut est l'hôte source des métriques.

zabbix_interval (chaîne)

Indique l'intervalle pour envoyer les métriques au serveur Zabbix. Cela peut être plus long que l'intervalle de reporting pour minimiser la surcharge lors de la communication avec le serveur (car chaque envoi crée une nouvelle connexion). Suit la syntaxe temporelle décrite dans PCPIntro(1). L'option de ligne de commande correspondante est -E. La valeur par défaut est l'intervalle de reporting. Les outils Zabbix envoient au maximum 250 métriques à la fois. Ignoré lors de la lecture des métriques à partir des archives PCP, auquel cas les métriques seront envoyées environ par lots de 250 métriques.

zabbix_prefix (chaîne)

Spécifiez le préfixe pour les métriques envoyées au serveur Zabbix. L'option de ligne de commande correspondante est -x. La valeur par défaut est pcp..

zabbix_lld (booléen)

Spécifiez si la découverte de bas niveau Zabbix doit être activée. L'option de ligne de commande correspondante est -l. La valeur par défaut est non.

OPTIONS

Les options en ligne de commande disponibles sont :

-0 précision, --precision-force=précision
Comme -P mais cette option écrasera les spécifications par métrique.
-4 action, --names-change=action
Spécifiez quelle action entreprendre à la réception d'un événement de changement de noms de métriques pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques peu après son démarrage, et informe les outils clients en cours d'exécution comme pcp2zabbix. Les valeurs valides pour action sont update (rafraîchir les métriques échantillonnées), ignore (ne rien faire - le comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignore-unknown
Ignorer silencieusement tout nom de métrique qui ne peut pas être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-8 limite, --limit-filter=limite
Limiter les résultats aux instances dont les valeurs sont supérieures/inférieures à limite. Un entier positif inclura les instances avec des valeurs égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances avec des valeurs égales ou inférieures à la limite dans le rapport. Une valeur de zéro n'effectue aucun filtrage par limite. Cette option n'écrasera pas les spécifications possibles par métrique. Voir aussi -J et -N.
-9 limite, --limit-filter-force=limite
Comme -8 mais cette option écrasera les spécifications par métrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, dont chacun peut être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Forcer le premier échantillon à être aligné sur la frontière d'une unité de temps naturelle alignement. Se référer à PCPIntro(1) pour une description complète de la syntaxe de alignement.
--archive-folio=folio
Lire les archives sources de métriques à partir du folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b échelle, --space-scale=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, etc. Cette option n'écrasera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-B échelle, --space-scale-force=échelle
Comme -b mais cette option écrasera les spécifications par métrique.
-c configuration, --config=configuration
Spécifiez le fichier ou répertoire de configuration à utiliser. Dans le cas où configuration est un répertoire, tous les fichiers qui s'y trouvent se terminant par .conf seront inclus. La valeur par défaut est le premier trouvé parmi : ./pcp2zabbix.conf, $HOME/.pcp2zabbix.conf, $HOME/pcp/pcp2zabbix.conf, et $PCP_SYSCONF_DIR/pcp2zabbi

x.conf. Pour plus de détails, voir la section ci-dessus et pmrep.conf(5).
--container=container
Récupérer les métriques de performance du container spécifié, local ou distant (voir -h).
-C, --check
Quitter avant de rapporter des valeurs, mais après avoir analysé la configuration et les métriques, et après avoir imprimé les en-têtes possibles.
--daemonize
Démoniser au démarrage.
-e derived, --derived=derived
Spécifier les métriques de performance derived. Si derived commence par une barre oblique (``/'') ou par un point (``.''), il sera interprété comme un fichier de configuration de métriques dérivées PCP, sinon il sera interprété comme des expressions de métriques dérivées séparées par des virgules ou des points-virgules. Pour une description complète des métriques dérivées et des fichiers de configuration de métriques dérivées PCP, voir pmLoadDerivedConfig(3) et pmRegisterDerived(3). Alternativement, l'utilisation de la syntaxe de configuration de pmrep.conf(5) permet de définir des métriques dérivées dans le cadre de jeux de métriques.

En cas de problèmes avec les métriques dérivées, examinez les pages de manuel susmentionnées en détail et assurez-vous que toutes les métriques requises sont disponibles, en particulier lors de l'utilisation d'archives. Utilisez -Dderive pour voir des informations de débogage supplémentaires sur l'analyse des métriques dérivées.

-E interval, --zabbix-interval=interval
Spécifier l'intervalle pour envoyer les métriques au serveur. Voir la description de zabbix_interval ci-dessus pour plus de détails.
-g server, --zabbix-server=server
Serveur Zabbix de destination server.
-G, --no-globals
Ne pas inclure les métriques globales dans le rapport (voir pmrep.conf(5)).
-h host, --host=host
Récupérer les métriques de performance depuis pmcd(1) sur host, plutôt que depuis localhost par défaut.
-H, --no-header
Ne pas imprimer d'en-têtes.
-i instances, --instances=instances
Récupérer et rapporter uniquement les instances de métriques spécifiées. Par défaut, toutes les instances, présentes et futures, sont rapportées.

Se référer à pmrep(1) pour une description complète de cette option.

-I, --ignore-incompat
Ignorer les métriques incompatibles. Par défaut, les métriques incompatibles (c'est-à-dire, dont le type n'est pas supporté ou qui ne peuvent pas être mises à l'échelle comme demandé) entraîneront la terminaison de pcp2zabbix avec un message d'erreur. Avec cette option, toutes les métriques incompatibles sont omises silencieusement du rapport. Cela peut être particulièrement utile lors de la demande de nœuds non feuilles de l'arbre PMNS pour le rapport.
-l, --zabbix-lld
Ajouter des métriques de découverte de bas niveau (LLD). Cela permet d'envoyer les domaines d'instances de métriques PCP à Zabbix, de sorte que des éléments/déclencheurs/graphiques prototypes puissent être construits automatiquement par Zabbix. Pour chaque métrique PCP avec un domaine d'instance, la clé pcp.discovery[pcp.met.ric] est envoyée périodiquement. Ce symbole doit être ajouté à une règle de découverte, et définira la macro LLD {#PCP.MET.RIC}. Cette macro peut à son tour être utilisée pour définir des éléments/déclencheurs/graphiques prototypes. Les noms sont ajustés si -x a été donné pour remplacer le préfixe pcp..
-j, --live-filter
Effectuer un filtrage dynamique des instances. Cela permet de capturer toutes les instances nommées même si les processus sont redémarrés à un moment donné (contrairement à l'absence de filtrage dynamique). Effectuer un filtrage dynamique sur un grand nombre d'instances entraînera une certaine surcharge interne, donc une certaine prudence de la part de l'utilisateur est conseillée. Voir aussi -n.
-J rank, --rank=rank
Limiter les résultats aux instances les plus élevées/basses classées des métriques à valeur d'ensemble. Un entier positif inclura les instances de plus grande valeur dans le rapport. Un entier négatif inclura les instances de plus faible valeur dans le rapport. Une valeur de zéro n'effectue aucun classement. Le classement n'implique pas le tri, voir -6. Voir aussi -8.
-K spec, --spec-local=spec
Lors de la récupération de métriques d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spec est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peut être utilisée.
-L, --local-PMDA
Utiliser un contexte local pour collecter des métriques à partir des PMDA DSO sur l'hôte local sans PMCD. Voir aussi -K.
-n, --invert-filter
Effectuer le classement avant le filtrage dynamique. Par défaut, le filtrage dynamique des instances (lorsqu'il est demandé, voir -j) se produit avant le classement des instances (lorsqu'il est demandé, voir -J). Avec cette option, la logique est inversée et le classement se produit avant le filtrage dynamique.
-N predicate, --predicate=predicate
Spécifier une liste séparée par des virgules de métriques de référence prédicat pour le filtrage. Par défaut, le classement (voir -J) s'effectue pour chaque métrique individuellement. Avec des prédicats, le classement ne s'effectue que pour les métriques prédicat spécifiées. Lors du rapport, le reste des métriques partageant le même domaine d'instance (voir PCPIntro(1)) que le prédicat inclura uniquement les instances les plus élevées/basses classées du prédicat correspondant. Le classement n'implique pas le tri, voir -6.

Ainsi, par exemple, en utilisant proc.memory.rss (taille de la mémoire résidente d'un processus) comme métrique prédicat avec proc.io.total_bytes et mem.util.used comme métriques à rapporter, seuls les processus utilisant le plus/le moins de mémoire (selon -J) seront inclus lors du rapport des octets totaux écrits par les processus. Comme mem.util.used est une métrique à valeur unique (ne partageant donc pas le même domaine d'instance que les métriques liées aux processus), elle sera rapportée comme d'habitude.

-O origin, --origin=origin
Lors du rapport de métriques archivées, le rapport commencera à origin dans la fenêtre temporelle (voir -S et -T). Se référer à PCPIntro(1) pour une description complète de la syntaxe de origin.
-p port, --zabbix-port=port
Port du serveur Zabbix port.
-P precision, --precision=precision
Utiliser la précision pour les valeurs de sortie numériques non entières. Par défaut, 3 décimales sont utilisées (lorsque cela est applicable). Cette option ne remplacera pas les spécifications possibles par métrique.
-q scale, --count-scale=scale
Unité/échelle pour les métriques de comptage, les valeurs possibles incluent count x 10^-1, count, count x 10, count x 10^2, et ainsi de suite de 10^-8 à 10^7. (Ces valeurs sont actuellement sensibles aux espaces.) Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-Q scale, --count-scale-force=scale
Similaire à -q, mais cette option remplacera les spécifications par métrique.
-r, --raw
Afficher les valeurs brutes des métriques, ne pas convertir les compteurs cumulatifs en taux. Cette option remplacera les spécifications possibles par métrique.
-R, --raw-prefer
Similaire à -r, mais cette option ne remplacera pas les spécifications par métrique.
-s samples, --samples=samples
L'argument samples définit le nombre d'échantillons à récupérer et à rapporter. Si samples est 0 ou si -s n'est pas spécifié, pcp2zabbix échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive). Voir aussi -T.
-S starttime, --start=starttime
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements efféctués à partir de starttime. Se référer à PCPIntro(1) pour une description complète de la syntaxe de starttime.
-t interval, --interval=interval
Définir l'intervalle de rapport à autre chose que la seconde par défaut. L'argument interval suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes). Voir aussi l'option -T.
-T endtime, --finish=endtime
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements efféctués avant ou à endtime. Se référer à PCPIntro(1) pour une description complète de la syntaxe de endtime.

Lorsqu'utilisé pour définir le temps d'exécution avant que pcp2zabbix ne se termine, si aucun samples n'est donné (voir -s), le nombre d'échantillons rapportés dépendra de l'intervalle (voir -t). Si des samples sont donnés, l'intervalle sera ajusté pour permettre le rapport de ces samples pendant le temps d'exécution. Dans le cas où -T, -s, et -t sont tous donnés, endtime déterminera le moment exact où pcp2zabbix s'exécutera.

-v, --omit-flat
Rapporter uniquement les métriques à valeur d'ensemble avec des instances (par exemple, disk.dev.read) et omettre les métriques "plates" à valeur unique sans instances.
(par exemple, kernel.all.sysfork). Voir -i et -I.
-V, --version
Affiche le numéro de version et quitte.
-x prefix, --zabbix-prefix=prefix
Préfixe prefix pour les mesures envoyées au serveur.
-X hostname, --zabbix-host=hostname
Nom d'hôte hostname de l'agent tel qu'enregistré dans l'interface Zabbix.
-y scale, --time-scale=scale
Unité/échelle scale pour les métriques temporelles, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option *ne* remplacera *pas* les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-Y scale, --time-scale-force=scale
Identique à -y, mais cette option remplacera les spécifications par métrique.
-?, --help
Affiche le message d'utilisation et quitte.

ENVIRONNEMENT PCP

Les variables d'environnement préfixées par PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, tel que décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

À noter en particulier, PCP_DISCRETE_ONCE peut être défini pour garantir que les valeurs de métriques discrètes ne soient rapportées qu'une seule fois, à moins qu'elles ne changent à un moment donné.

OPTIONS DE BOURRAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider au dépannage, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
