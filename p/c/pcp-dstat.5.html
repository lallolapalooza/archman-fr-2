NOM

pcp-dstat - fichier de configuration pcp-dstat

DESCRIPTION

pcp-dstat est un outil personnalisable de rapports de métriques de performance. Il possède une architecture de « plugins », où un ensemble de plugins prédéfinis proposent de petits ensembles de rapports de métriques en colonnes, et les options de ligne de commande de pcp-dstat sélectionnent quels plugins sont utilisés dans le rapport généré.

Chaque plugin est défini dans une section d'un fichier de configuration. Une installation typique fournira de nombreux fichiers de configuration, et souvent plusieurs sections (plugins) dans chaque fichier.

Les fichiers de configuration sont lus à la fois depuis un répertoire système et depuis le répertoire personnel de l'utilisateur ($PCP_SYSCONF_DIR/dstat et $HOME/.pcp/dstat).

FORMAT DU FICHIER

Les fichiers de configuration ont une syntaxe de style ini composée de sections (plugins) et d'options à l'intérieur des sections. Une section commence par le nom du plugin entre crochets et continue jusqu'à ce qu'une nouvelle section commence. Un exemple de section avec deux options suit :

[plugin]
option = valeur
metric.option = valeur2

Un commentaire de ligne commence par un signe dièse (« # ») ou un point-virgule (« ; »). Les commentaires en ligne ne sont pas supportés.

Il existe quelques options qui s'appliquent au plugin dans son ensemble, et tout le reste est considéré comme une définition de colonne. Les définitions de colonnes correspondent directement aux métriques PCP individuelles.

Les options [plugin]

label (chaîne)

Le titre général à utiliser pour ce plugin. Dans le cas spécial de métriques avec des instances rapportées en groupe (voir grouptype ci-dessous), cette chaîne peut contenir le motif %I, qui sera substitué par le nom de l'instance - référez-vous aux plugins cpu, disk, net et int(errupts) pour des exemples de cette syntaxe spéciale. Indéfini par défaut, défini automatiquement au nom de la section (plugin).

width (entier)

La largeur de colonne utilisée pour les métriques de ce plugin. La valeur par défaut est 5.

precision (entier)

La précision maximale à utiliser lors du rapport des colonnes en virgule flottante pour ce plugin. Indéfini par défaut, défini automatiquement en fonction de width.

printtype (caractère)

Indique le style de rapport pour les valeurs de métriques de ce plugin. Les réglages possibles sont d(écimal), f(loat), p(ourcentage), s(tring), b(its), t(emps). Par défaut, un réglage sera utilisé en fonction du type de métrique et de sa sémantique - référez-vous à PMAPI(3) pour plus de détails sur les métadonnées des métriques PCP.

colorstep (entier)

Indique un « pas » auquel la prochaine couleur sera transmutée, lors du rapport des valeurs de métriques. Comme les valeurs de métriques changent à chaque échantillon, colorstep est utilisé pour déterminer les incréments au-delà desquels une nouvelle couleur doit être sélectionnée. La valeur par défaut est 1000.

grouptype (entier)

Pour les plugins avec des métriques partageant le même domaine d'instances, il est possible de demander un comportement de groupement plus complexe. Le comportement par défaut est de ne pas utiliser le groupement d'instances, et de rapporter chaque instance de la métrique dans une colonne séparée (le plugin load en est un exemple, utilisant la métrique kernel.all.load).

Le groupement peut être défini à trois niveaux distincts - 1, 2, 3 ou 4. Le niveau 1 affiche uniquement les instances des métriques (pas de totaux) - c'est l'équivalent de l'utilisation du plugin --cpu sur la ligne de commande pcp-dstat avec les processeurs spécifiques dont l'utilisation est affichée, par exemple, l'affichage des CPU 4, 5 et 12 (-C 4,5,12). Le niveau 2 affiche la colonne totale - la somme de toutes les instances pour la ou les métriques spécifiées dans ce plugin. Le niveau 3 est une combinaison des deux modes, par exemple en utilisant le plugin pcp-dstat --cpu avec les options -C 4,5,12,total. Le niveau 4 est un mode de type « top », où une expression spéciale « top » est utilisée pour classer toutes les instances - la valeur la plus haute (la plus grande) sera affichée.

instances (chaîne de valeurs séparées par des virgules)

Définit les instances à rapporter pour la métrique. Par défaut, toutes les instances sont rapportées pour les métriques de type « set-values ».

cullinsts (modèle regex)

Une expression régulière optionnelle qui peut être utilisée pour supprimer des instances de métriques de l'agrégation (« total ») dans les rapports générés. Par exemple, il est courant d'exclure les périphériques de bouclage des rapports d'interfaces réseau, ce qui est réalisé en utilisant cette option. Par défaut, tous les instances sont rapportées (pas de suppression).

filtertype (chaîne)

Utilisé pour les métriques de plugin qui permettent des options de filtrage d'instances en ligne de commande. La valeur de l'entrée filtertype doit être appropriée pour l'option de sélection d'instance utilisée, comme indiqué dans le tableau ci-dessous.
filtertype option de sélection d'instance
cpu -C
disk -D
dm -L
md -M
part -P
int -I
net -N
net-packets -N
swap -S

Les métriques [plugin]

Chaque plugin doit avoir au moins une métrique associée. Toute clé qui n'est pas une des options globales du plugin ci-dessus est considérée comme une spécification de métrique ou une option de métrique. Ces clés définissent les métriques et leur formatage de rapport.

Avant tout, chaque colonne est généralement représentée par une métrique individuelle (si la métrique est de type set-valued - c'est-à-dire qu'elle a des instances - cela entraînera plusieurs colonnes). Ceci est spécifié par une nouvelle clé (colonne) définie avec une spécification de métrique. Le nom de la colonne (clé) est un mot arbitraire composé de caractères alphabétiques. La spécification de métrique est un nom de métrique PCP quelconque ou une spécification de métrique dérivée, permettant d'utiliser des calculs arithmétiques de base pour former cette colonne individuelle. La syntaxe des métriques dérivées est décrite dans la page de manuel pmRegisterDerived(3).

Quelques exemples des deux formes de spécification de métrique sont donnés ci-dessous dans la section « EXEMPLES ».

Une fois qu'une colonne a été associée à une métrique, d'autres options spécifiques à cette colonne peuvent être définies en utilisant une syntaxe séparée par des points.

Options de métrique

metric.label

Le sous-titre à utiliser pour les valeurs rapportées de cette métrique. Le label par défaut est le nom de la colonne du fichier de configuration.

Lorsque des métriques PCP de type set-valued (c'est-à-dire avec des instances) sont utilisées, il est souvent pratique de spécifier soit le numéro d'instance, soit le nom de l'instance dans l'en-tête. Ceci est réalisé en utilisant des spécificateurs de format - « %d » ou « %i » pour les numéros d'instance (par exemple, remplacé par « 6 » pour le sixième processeur), et « %s » ou « %I » pour les noms d'instance (par exemple, remplacé par « eth0 » pour l'interface Ethernet). Les noms d'instances disponibles pour une métrique quelconque peuvent être découverts via les commandes pminfo(1) ou pmprobe(1).

metric.width

La largeur de colonne à utiliser lors du rapport des valeurs pour cette métrique.

metric.unit (chaîne)

Définit l'unité/la conversion d'échelle pour la métrique. Doit être compatible dimensionnellement et est utilisé avec des métriques non-chaînes. Pour les valeurs autorisées, voir pmrep(1).

metric.type (chaîne)

Si défini sur raw, la conversion du taux pour la métrique sera désactivée.

metric.precision (entier)

Définit la précision pour les valeurs à virgule flottante.

metric.limit (chaîne)

Définit le filtre de limite de valeur pour les valeurs de métriques numériques.

EXEMPLES

L'exemple suivant définit un plugin de système de fichiers virtuel, avec deux colonnes, définies à l'aide de trois métriques PCP - vfs.files.count, vfs.inodes.count et vfs.inodes.free. Les métriques d'inodes sont combinées à l'aide de la notation de métrique dérivée.

[vfs]
width = 6
label = filesystem
files = vfs.files.count
inode = vfs.inodes.count - vfs.inodes.free
inode.label = inodes

Les fichiers de plugin pcp-dstat par défaut du système contiennent de nombreux autres exemples.

ENVIRONNEMENT PCP

Les variables d'environnement préfixées par PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).
