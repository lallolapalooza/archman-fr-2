PCP2XML(1) Manuel des commandes générales PCP2XML(1)

NOM

pcp2xml - exportateur de métriques pcp vers xml

SYNTAXE

pcp2xml [-5CGHIjLmnrRvVxXz?] [-4 action] [-8|-9 limite] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c config] [--container conteneur] [-D débogage] [--daemonize] [-e dérivé] [-f format] [-F fichier-sortie] [-h hôte] [-i instances] [-J rang] [-K spécification] [-N prédicat] [-O origine] [-P|-0 précision] [-q|-Q échelle-compteur] [-s échantillons] [-S heure-début] [-t intervalle] [-T heure-fin] [-y|-Y échelle-temps] [-Z fuseau-horaire] spécification-métrique [...]

DESCRIPTION

pcp2xml est un outil personnalisable d'exportation de métriques de performance de PCP vers XML. Toute métrique de performance disponible, en direct ou archivée, système et/ou application, peut être sélectionnée pour l'exportation en utilisant soit des arguments en ligne de commande, soit un fichier de configuration.

pcp2xml est un proche parent de pmrep(1). Référez-vous à pmrep(1) pour la description de spécification-métrique acceptée en ligne de commande par pcp2xml. Consultez pmrep.conf(5) pour la description de la syntaxe du fichier de configuration pcp2xml.conf. Cette page décrit les options spécifiques à pcp2xml et les différences de fichier de configuration avec pmrep.conf(5). pmrep(1) liste également des exemples d'utilisation dont la plupart sont applicables avec pcp2xml.

Seules les options de ligne de commande listées sur cette page sont supportées, les autres options disponibles pour pmrep(1) ne le sont pas.

Les options via des variables d'environnement (voir pmGetOptions(3)) remplacent les valeurs par défaut intégrées correspondantes (le cas échéant). Les options du fichier de configuration remplacent les variables d'environnement correspondantes (le cas échéant). Les options de ligne de commande remplacent les options correspondantes du fichier de configuration (le cas échéant).

FICHIER DE CONFIGURATION

pcp2xml utilise un fichier de configuration dont la syntaxe est décrite dans pmrep.conf(5). Les options suivantes sont communes avec pmrep.conf : version, source, speclocal, derived, header, globals, samples, interval, type, type_prefer, ignore_incompat, names_change, instances, live_filter, rank, limit_filter, limit_filter_force, invert_filter, predicate, omit_flat, include_labels, precision, precision_force, count_scale, count_scale_force, space_scale, space_scale_force, time_scale, time_scale_force. Le reste des options de pmrep.conf est reconnu mais ignoré pour des raisons de compatibilité.

options spécifiques à pcp2xml

extended (booléen)

Écrit des informations étendues sur les métriques. L'option de ligne de commande correspondante est -x. Par défaut à no.

everything (booléen)

Écrit tout ce qui est connu des métriques, y compris les identifiants internes de PCP. Cependant, les étiquettes sont omises pour des raisons de compatibilité descendante. Activez include_labels pour les inclure également. L'option de ligne de commande correspondante est -X. Par défaut à no.

OPTIONS

Les options de ligne de commande disponibles sont :

-0 précision, --precision-force=précision
Comme -P mais cette option remplacera les spécifications par m étrique.
-4 action, --names-change=action
Spécifie quelle action entreprendre lors de la réception d'un événement de changement de nom de métrique pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques peu après son démarrage, et informe les outils clients en cours d'exécution comme pcp2xml. Les valeurs valides pour action sont update (rafraîchir les métriques échantillonnées), ignore (ne rien faire - comportement par défaut) et abort (quitter le programme si un tel événement se produit).
-5, --ignore-unknown
Ignore silencieusement tout nom de métrique qui ne peut pas être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-8 limite, --limit-filter=limite
Limite les résultats aux instances ayant des valeurs supérieures/inférieures à la limite. Un entier positif inclura les instances avec des valeurs égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances avec des valeurs égales ou inférieures à la limite dans le rapport. Une valeur de zéro n'effectue aucun filtrage par limite. Cette option ne remplacera pas les spécifications possibles par m étrique. Voir aussi -J et -N.
-9 limite, --limit-filter-force=limite
Comme -8 mais cette option remplacera les spécifications par m étrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives PCP (Performance Co-Pilot) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Force le premier échantillon à être aligné sur la frontière d'une unité de temps naturelle alignement. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe de alignement.
--archive-folio=folio
Lit les archives sources de métriques du folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b échelle, --space-scale=échelle
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent bytes, Kbytes, KB, Mbytes, MB, etc. Cette option ne remplacera pas les spécifications possibles par m étrique. Voir aussi pmParseUnitsStr(3).
-B échelle, --space-scale-force=échelle
Comme -b mais cette option remplacera les spécifications par m étrique.
-c config, --config=config
Spécifie le fichier ou répertoire config à utiliser. Dans le cas où config est un répertoire, tous les fichiers se terminant par .conf seront inclus. Par défaut, c'est le premier trouvé parmi : ./pcp2xml.conf, $HOME/.pcp2xml.conf, $HOME/pcp/pcp2xml.conf, et $PCP_SYSCONF_DIR/pcp2xml.conf. Pour plus de détails, voir la section ci-dessus et pmrep.conf(5).
--container=conteneur
Récupère les métriques de performance du conteneur spécifié, local ou distant (voir -h).
-C, --check
Sort avant de rapporter des valeurs, mais après avoir analysé la configuration et les métriques et imprimé les en-têtes possibles.
--daemonize
Se daemonise au démarrage.
-e dérivé, --derived=dérivé
Spécifie les métriques de performance dérivées. Si dérivé commence par une barre oblique (``/'') ou par un point (``.''), il sera interprété comme un fichier de configuration de métriques dérivées PCP, sinon il sera interprété comme des expressions de métriques dérivées séparées par des virgules ou des points-virgules. Pour une description complète des métriques dérivées et des fichiers de configuration de métriques dérivées PCP, voir pmLoadDerivedConfig(3) et pmRegisterDerived(3). Alternativement, en utilisant la syntaxe de configuration de pmrep.conf(5)

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

autorise la définition de métriques dérivées dans le cadre des jeux de métriques.

En cas de problèmes avec les métriques dérivées, consultez les pages de manuel susmentionnées en détail et assurez-vous que toutes les métriques requises sont disponibles, en particulier lors de l'utilisation d'archives. Utilisez -Dderive pour voir des informations de débogage supplémentaires sur l'analyse des métriques dérivées.

-G, --no-globals
N'inclut pas les métriques globales dans le rapport (voir pmrep.conf(5)).
-f format, --timestamp-format=format
Utilise la chaîne de caractères format pour formater l'horodatage. Le format sera utilisé avec la méthode datetime.strftime de Python, qui est largement identique à celle décrite dans strftime(3). La valeur par défaut est %Y-%m-%d %H:%M:%S.
-F outfile, --output-file=outfile
Spécifie le fichier de sortie outfile.
-h host, --host=host
Récupère les métriques de performance depuis pmcd(1) sur host, plutôt que depuis localhost par défaut.
-H, --no-header
N'affiche aucun en-tête.
-i instances, --instances=instances
Récupère et rapporte uniquement les instances de métriques spécifiées. Par défaut, toutes les instances, présentes et futures, sont rapportées.

Se référer à pmrep(1) pour une description complète de cette option.

-I, --ignore-incompat
Ignore les métriques incompatibles. Par défaut, les métriques incompatibles (c'est-à-dire, dont le type n'est pas supporté ou qui ne peuvent pas être mises à l'échelle comme demandé) entraîneront la terminaison de pcp2xml avec un message d'erreur. Avec cette option, toutes les métriques incompatibles sont silencieusement omises du rapport. Ceci peut être particulièrement utile lors de la demande de nœuds non feuilles de l'arbre PMNS pour le rapport.
-j, --live-filter
Effectue le filtrage dynamique des instances. Cela permet de capturer toutes les instances nommées même si les processus redémarrent à un moment donné (contrairement à l'absence de filtrage dynamique). Effectuer un filtrage dynamique sur un nombre énorme d'instances entraînera une surcharge interne, donc un peu de prudence de la part de l'utilisateur est conseillée. Voir aussi -n.
-J rank, --rank=rank
Limite les résultats aux instances les plus élevées/basses dans le classement des métriques à valeurs d'ensemble. Un entier positif inclura les instances à plus haute valeur dans le rapport. Un entier négatif inclura les instances à plus basse valeur dans le rapport. Une valeur de zéro n'effectue aucun classement. Le classement n'implique pas le tri, voir -6. Voir aussi -8.
-K spec, --spec-local=spec
Lors de la récupération de métriques depuis un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spec respecte la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peut être utilisée.
-L, --local-PMDA
Utilise un contexte local pour collecter les métriques des PMDA DSO sur l'hôte local sans PMCD. Voir aussi -K.
-m, --include-labels
Inclut les étiquettes de métriques PCP dans la sortie.
-n, --invert-filter
Effectue le classement avant le filtrage dynamique. Par défaut, le filtrage dynamique des instances (lorsqu'il est demandé, voir -j) se produit avant le classement des instances (lorsqu'il est demandé, voir -J). Avec cette option, la logique est inversée et le classement se produit avant le filtrage dynamique.
-N predicate, --predicate=predicate
Spécifie une liste de métriques de référence de filtre predicate séparées par des virgules. Par défaut, le classement (voir -J) se fait individuellement pour chaque métrique. Avec des prédicats, le classement ne se fait que pour les métriques de prédicat spécifiées. Lors du rapport, les autres métriques partageant le même domaine d'instance (voir PCPIntro(1)) que le prédicat n'incluront que les instances les plus élevées/basses du prédicat correspondant. Le classement n'implique pas le tri, voir -6.

Par exemple, en utilisant proc.memory.rss (taille mémoire résidente d'un processus) comme métrique de prédicat avec proc.io.total_bytes et mem.util.used comme métriques à rapporter, seuls les processus utilisant le plus/le moins de mémoire (selon -J) seront inclus lors du rapport des octets totaux écrits par les processus. Comme mem.util.used est une métrique à valeur unique (et ne partage donc pas le même domaine d'instance que les métriques liées aux processus), elle sera rapportée comme d'habitude.

-O origin, --origin=origin
Lors du rapport de métriques archivées, le rapport commence à origin dans la fenêtre temporelle (voir -S et -T). Se référer à PCPIntro(1) pour une description complète de la syntaxe de origin.
-P precision, --precision=precision
Utilise la precision pour les valeurs numériques de sortie non entières. La valeur par défaut est de 3 décimales (le cas échéant). Cette option ne remplacera pas les spécifications possibles par métrique.
-q scale, --count-scale=scale
Unité/échelle pour les métriques de comptage, les valeurs possibles incluent count x 10^-1, count, count x 10, count x 10^2, et ainsi de suite de 10^-8 à 10^7. (Ces valeurs sont actuellement sensibles aux espaces.) Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-Q scale, --count-scale-force=scale
Identique à -q, mais cette option remplacera les spécifications par métrique.
-r, --raw
Affiche les valeurs brutes des métriques, ne convertit pas les compteurs cumulatifs en taux. Cette option remplacera les spécifications possibles par métrique.
-R, --raw-prefer
Identique à -r, mais cette option ne remplacera pas les spécifications par métrique.
-s samples, --samples=samples
L'argument samples définit le nombre d'échantillons à récupérer et à rapporter. Si samples est 0 ou si -s n'est pas spécifié, pcp2xml échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive). Voir aussi -T.
-S starttime, --start=starttime
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements enregistrés à partir de starttime. Se référer à PCPIntro(1) pour une description complète de la syntaxe de starttime.
-t interval, --interval=interval
Définit l'intervalle de rapport à une valeur autre que la seconde par défaut. L'argument interval suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes). Voir aussi l'option -T.
-T endtime, --finish=endtime
Lors du rapport de métriques archivées, le rapport sera limité aux enregistrements enregistrés avant ou à endtime. Se référer à PCPIntro(1) pour une description complète de la syntaxe de endtime.

Lorsqu'il est utilisé pour définir la durée de vie avant que pcp2xml ne se termine, si aucun samples n'est donné (voir -s), le nombre d'échantillons rapportés dépend de l'intervalle (voir -t). Si samples est donné, l'intervalle sera ajusté pour permettre le rapport de samples pendant la durée de vie. Si -T, -s et -t sont tous donnés, endtime déterminera le moment exact où pcp2xml s'exécutera.

-v, --omit-flat
Rapporte uniquement les métriques à valeurs d'ensemble avec instances (par exemple, disk.dev.read) et omet les métriques "plates" à valeur unique sans instances (par exemple, kernel.all.sysfork). Voir -i et -I.
-V, --version
Affiche le numéro de version et quitte.
-x, --with-extended
Écrit des informations étendues.
-X, --with-everything
Écrit tout ce qui est connu des métriques, y compris les identifiants internes PCP. Les étiquettes sont cependant omises pour des raisons de compatibilité ascendante, utilisez -m pour les inclure également.
-y scale, --time-scale=scale
Unité/échelle pour les métriques temporelles, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-Y scale, --time-scale-force=scale
Identique à -y, mais cette option remplacera les spécifications par métrique.
-z, --hostzone
Utilise le fuseau horaire local de l'hôte qui est la source des métriques de performance, tel qu'identifié par les options -h ou -a. Par défaut, utilise le fuseau horaire de l'hôte local.
-Z timezone, --timezone=timezone
Utilise le fuseau horaire timezone pour la date et l'heure. Timezone est au format de la variable d'environnement TZ tel que décrit dans environ(7). Notez que lors de l'inclusion d'une chaîne de fuseau horaire dans la sortie
ut, les décalages UTC de style ISO 8601 sont utilisés (ainsi, quelque chose comme -Z EST+5 deviendra UTC-5).
-?, --help
Affiche le message d'utilisation et quitte.

Fichier de configuration pcp2xml (voir -c)

Fichiers de configuration pmrep par défaut fournis par le système

ENVIRONNEMENT PCP

Les variables d'environnement dont le préfixe est PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

Il est particulièrement important de noter que PCP_DISCRETE_ONCE peut être défini pour s'assurer que les valeurs métriques discrètes ne sont signalées qu'une seule fois, sauf si elles changent à un moment donné.

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à dépanner les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
