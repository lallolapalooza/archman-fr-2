LA BIBLIOTHÈQUE PCRE 32-BITS

À partir de la version 8.32, il est possible de compiler une bibliothèque PCRE qui prend en charge les chaînes de caractères de 32 bits, y compris les chaînes UTF-32, en plus ou à la place de la bibliothèque 8 bits d'origine. Ce travail a été réalisé par Christian Persch, basé sur le travail effectué par Zoltan Herczeg pour la bibliothèque 16 bits. Les trois bibliothèques contiennent des ensembles de fonctions identiques, utilisés exactement de la même manière. Seuls les noms des fonctions et les types de données de leurs arguments et résultats diffèrent. Pour éviter une sur-complication et réduire la charge de maintenance de la documentation, la plupart de la documentation PCRE décrit la bibliothèque 8 bits, avec seulement des références occasionnelles aux bibliothèques 16 bits et 32 bits. Cette page décrit ce qui est différent lorsque vous utilisez la bibliothèque 32 bits.

ATTENTION : Une seule application peut être liée avec toutes ou n'importe laquelle des trois bibliothèques, mais vous devez faire attention lors du traitement d'un motif particulier pour utiliser les fonctions d'une seule bibliothèque. Par exemple, si vous souhaitez étudier un motif compilé avec pcre32_compile(), vous devez le faire avec pcre32_study(), pas avec pcre_study(), et vous devez libérer les données d'étude avec pcre32_free_study().

LE FICHIER D'EN-TÊTE

Il n'y a qu'un seul fichier d'en-tête, pcre.h. Il contient les prototypes de toutes les fonctions de toutes les bibliothèques, ainsi que les définitions des drapeaux, structures, codes d'erreur, etc.

LE NOM DE LA BIBLIOTHÈQUE

Dans les systèmes de type Unix, la bibliothèque 32 bits s'appelle libpcre32, et peut normalement être accédée en ajoutant -lpcre32 à la commande de liaison d'une application utilisant PCRE.

TYPES DE CHAÎNES

Dans la bibliothèque 8 bits, les chaînes sont passées aux fonctions de la bibliothèque PCRE sous forme de vecteurs d'octets avec le type C "char *". Dans la bibliothèque 32 bits, les chaînes sont passées sous forme de vecteurs de quantités non signées de 32 bits. La macro PCRE_UCHAR32 spécifie un type de données approprié, et PCRE_SPTR32 est défini comme "const PCRE_UCHAR32 *". Dans de nombreux environnements, "unsigned int" est un type de données de 32 bits. Lorsque PCRE est compilé, il définit PCRE_UCHAR32 comme "unsigned int", mais vérifie qu'il s'agit bien d'un type de données de 32 bits. Sinon, la compilation échoue avec un message d'erreur indiquant au mainteneur de modifier la définition de manière appropriée.

TYPES DE STRUCTURES

Les types des structures opaques utilisées pour les motifs 32 bits compilés et les piles JIT sont respectivement pcre32 et pcre32_jit_stack. Le type de la structure accessible par l'utilisateur renvoyée par pcre32_study() est pcre32_extra, et le type de la structure utilisée pour passer des données à une fonction d'appel est pcre32_callout_block. Ces structures contiennent les mêmes champs, avec les mêmes noms, que leurs homologues 8 bits. La seule différence est que les pointeurs vers les chaînes de caractères sont des types 32 bits au lieu de 8 bits.

FONCTIONS 32-BITS

Pour chaque fonction de la bibliothèque 8 bits, il existe une fonction correspondante dans la bibliothèque 32 bits dont le nom commence par pcre32_ au lieu de pcre_. Les prototypes sont listés ci-dessus. De plus, il existe une fonction supplémentaire, pcre32_utf32_to_host_byte_order(). Il s'agit d'une fonction utilitaire qui convertit une chaîne de caractères UTF-32 en ordre d'octets hôte si nécessaire. Les autres fonctions 32 bits attendent que les chaînes qui leur sont passées soient en ordre d'octets hôte.

Les arguments input et output de pcre32_utf32_to_host_byte_order() peuvent pointer vers la même adresse, c'est-à-dire que la conversion sur place est prise en charge. Le tampon de sortie doit être au moins aussi long que l'entrée.

L'argument length spécifie le nombre d'unités de données de 32 bits dans la chaîne d'entrée ; une valeur négative spécifie une chaîne terminée par un zéro.

pcre32 - PCRE 32 bits API

NAME

pcre32 - PCRE 32 bits API

PCRE 32-BIT API BASIC FUNCTIONS

The basic functions for the PCRE 32-bit API are identical in interface to those for the 8-bit API, but operate on UTF-32 strings instead of UTF-8 strings. These functions are:


pcre32_compile, pcre32_compile2
pcre32_dfa_compile, pcre32_dfa_compile2
pcre32_exec
pcre32_free_study, pcre32_free_substring, pcre32_free_substring_list
pcre32_get_substring, pcre32_get_substring_list
pcre32_study
pcre32_version

PCRE 32-BIT API STRING EXTRACTION FUNCTIONS

There are some new functions for extracting substrings from 32-bit strings:


pcre32_copy_named_substring
pcre32_copy_regex_substring
pcre32_get_named_substring
pcre32_get_regex_substring

There are some auxiliary functions that are specific to the 32-bit API:


pcre32_utf32_to_host_byte_order
pcre32_get_stringtable_entries

There are also some functions that are duplicated from the 8-bit API, but which operate on 32-bit strings:

There is one function that is unique to the 32-bit API:

THE PCRE 32-BIT LIBRARY

The PCRE library can be compiled in three modes: 8-bit (UTF-8), 16-bit (UTF-16), and 32-bit (UTF-32). This document is about the 32-bit mode.

The interfaces to the 8-bit and 16-bit libraries are stable. The interfaces to the 32-bit library are the same as for the 8-bit library, except where noted below.

THE HEADER FILE

The header file for the 32-bit library is pcre32.h. It is identical to pcre.h, except that it defines PCRE32 as its API version number, instead of PCRE. The 32-bit library can be built as a shared library that is distinct from the 8-bit library, in which case its name is usually libpcre32.so or similar.

THE LIBRARY NAME

When linking, you should link with the library named libpcre32.a or libpcre32.so. If you are using GCC, you can use the option -lpcre32.

STRING TYPES

In the 8-bit library, strings are sequences of 8-bit characters. In the 16-bit library, strings are sequences of 16-bit characters. In the 32-bit library, strings are sequences of 32-bit characters.

In the 32-bit library, these characters are stored as unsigned 32-bit integers. The character set is Unicode, and the string is implicitly UTF-32.

STRUCTURE TYPES

The structure types that are used by the 32-bit library are identical to those used by the 8-bit library, except that the fields that hold substrings are 32-bit pointers instead of 8-bit pointers.

The exception is the pcre_calloutinfo structure, which has a field subject which is a pointer to the subject string. This also points to a 32-bit string.

32-BIT FUNCTIONS

The functions in the 32-bit library have names that are prefixed with pcre32_ instead of pcre_. For example, the function to compile a pattern is pcre32_compile(). The functions for extracting substrings are also prefixed with pcre32_. These are described in the following paragraphs.

The function pcre32_utf32_to_host_byte_order() is provided to convert a UTF-32 string from network byte order to host byte order. It is intended to be used to process strings that may be changed by byte-order marks (BOMs) anywhere in the string (commonly as the first character).

If byte_order is not NULL, a non-zero value of the integer to which it points means that the input starts off in host byte order, otherwise the opposite order is assumed. Again, BOMs in the string can change this. The final byte order is passed back at the end of processing.

If keep_boms is not zero, byte-order mark characters (0xfeff) are copied into the output string. Otherwise they are discarded.

The result of the function is the number of 32-bit units placed into the output buffer, including the zero terminator if the string was zero-terminated.

SUBJECT STRING OFFSETS

The lengths and starting offsets of subject strings must be specified in 32-bit data units, and the offsets within subject strings that are returned by the matching functions are in also 32-bit units rather than bytes.

NAMED SUBPATTERNS

The name-to-number translation table that is maintained for named subpatterns uses 32-bit characters. The pcre32_get_stringtable_entries() function returns the length of each entry in the table as the number of 32-bit data units.

OPTION NAMES

There are two new general option names, PCRE_UTF32 and PCRE_NO_UTF32_CHECK, which correspond to PCRE_UTF8 and PCRE_NO_UTF8_CHECK in the 8-bit library. In fact, these new options define the same bits in the options word. There is a discussion about the validity of UTF-32 strings in the pcreunicode page.

For the pcre32_config() function there is an option PCRE_CONFIG_UTF32 that returns 1 if UTF-32 support is configured, otherwise 0. If this option is given to pcre_config() or pcre16_config(), or if the PCRE_CONFIG_UTF8 or PCRE_CONFIG_UTF16 option is given to pcre32_config(), the result is the PCRE_ERROR_BADOPTION error.

CHARACTER CODES

In 32-bit mode, when PCRE_UTF32 is not set, character values are treated in the same way as in 8-bit, non UTF-8 mode, except, of course, that they can range from 0 to 0x7fffffff instead of 0 to 0xff. Character types for characters less than 0xff can therefore be influenced by the locale in the same way as before. Characters greater than 0xff have only one case, and no "type" (such as letter or digit).

In UTF-32 mode, the character code is Unicode, in the range 0 to 0x10ffff, with the exception of values in the range 0xd800 to 0xdfff because those are "surrogate" values that are ill-formed in UTF-32.

A UTF-32 string can indicate its endianness by special code knows as a byte-order mark (BOM). The PCRE functions do not handle this, expecting strings to be in host byte order. A utility function called pcre32_utf32_to_host_byte_order() is provided to help with this (see above).

ERROR NAMES

The error PCRE_ERROR_BADUTF32 corresponds to its 8-bit counterpart. The error PCRE_ERROR_BADMODE is given when a compiled pattern is passed to a function that processes patterns in the other mode, for example, if a pattern compiled with pcre_compile() is passed to pcre32_exec().

There are new error codes whose names begin with PCRE_UTF32_ERR for invalid UTF-32 strings, corresponding to the PCRE_UTF8_ERR codes for UTF-8 strings that are described in the section entitled "Reason codes for invalid UTF-8 strings" in the main pcreapi page. The UTF-32 errors are:


PCRE_UTF32_ERR1 Surrogate character (range from 0xd800 to 0xdfff)
PCRE_UTF32_ERR2 Non-character
PCRE_UTF32_ERR3 Character > 0x10ffff

ERROR TEXTS

If there is an error while compiling a pattern, the error text that is passed back by pcre32_compile() or pcre32_compile2() is still an 8-bit character string, zero-terminated.

CALLOUTS

The subject and mark fields in the callout block that is passed to a callout function point to 32-bit vectors.

TESTING

The pcretest program continues to operate with 8-bit input and output files, but it can be used for testing the 32-bit library. If it is run with the command line option -32, patterns and subject strings are converted from 8-bit to 32-bit before being passed to PCRE, and the 32-bit library functions are used instead of the 8-bit ones. Returned 32-bit strings are converted to 8-bit for output. If both the 8-bit and the 16-bit libraries were not compiled, pcretest defaults to 32-bit and the -32 option is ignored.

When PCRE is being built, the RunTest script that is called by "make check" uses the pcretest -C option to discover which of the 8-bit, 16-bit and 32-bit libraries has been built, and runs the tests appropriately.

NOT SUPPORTED IN 32-BIT MODE

Not all the features of the 8-bit library are available with the 32-bit library. The C++ and POSIX wrapper functions support only the 8-bit library, and the pcregrep program is at present 8-bit only.
