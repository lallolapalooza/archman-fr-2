NOM

pcre_table - format des tables PCRE de Postfix

SYNTAXE

postmap -q "chaîne" pcre:/etc/postfix/nom_de_fichier
postmap -q - pcre:/etc/postfix/nom_de_fichier <fichier_entrée
postmap -hmq - pcre:/etc/postfix/nom_de_fichier <fichier_entrée
postmap -bmq - pcre:/etc/postfix/nom_de_fichier <fichier_entrée

DESCRIPTION


Le système de messagerie Postfix utilise des tables optionnelles pour la réécriture d'adresses, le routage de courrier ou le contrôle d'accès. Ces tables sont généralement au format dbm ou db.

Alternativement, les tables de consultation peuvent être spécifiées sous forme d'expressions régulières compatibles Perl. Dans ce cas, chaque entrée est comparée à une liste de motifs. Lorsqu'une correspondance est trouvée, le résultat correspondant est renvoyé et la recherche est terminée.

Pour savoir quels types de tables de consultation votre système Postfix supporte, utilisez la commande "postconf -m".

Pour tester les tables de consultation, utilisez la commande "postmap -q" comme décrit dans la SYNTAXE ci-dessus. Utilisez "postmap -hmq - <fichier" pour les motifs header_checks(5), et "postmap -bmq - <fichier" pour les motifs body_checks(5) (Postfix 2.6 et versions ultérieures).

Ce pilote peut être compilé avec la bibliothèque pcre2 (Postfix 3.7 et versions ultérieures), ou avec la bibliothèque pcre héritée (toutes les versions de Postfix).

COMPATIBILITÉ

Avec Postfix version 2.2 et antérieures, spécifiez "postmap -fq" pour interroger une table contenant des motifs sensibles à la casse. Les motifs ne sont pas sensibles à la casse par défaut.

FORMAT DE TABLE

La forme générale d'une table PCRE est :

/motif/indicateurs résultat
Lorsque motif correspond à la chaîne d'entrée, utilisez la valeur résultat correspondante.
!/motif/indicateurs résultat
Lorsque motif ne correspond pas à la chaîne d'entrée, utilisez la valeur résultat correspondante.
if /motif/indicateurs
endif
Si la chaîne d'entrée correspond à /motif/, alors faites correspondre cette chaîne d'entrée avec les motifs situés entre if et endif. Les blocs if..endif peuvent être imbriqués.

Note : ne préfixez pas d'espaces aux motifs à l'intérieur de if..endif.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

if !/motif/indicateurs
endif
Si la chaîne d'entrée ne correspond pas à /motif/, alors faites correspondre cette chaîne d'entrée avec les motifs situés entre if et endif. Les blocs if..endif peuvent être imbriqués.

Note : ne préfixez pas d'espaces aux motifs à l'intérieur de if..endif.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

lignes vides et commentaires
Les lignes vides et les lignes contenant uniquement des espaces sont ignorées, tout comme les lignes dont le premier caractère non-espace est un `#'.
texte multiligne
Une ligne logique commence par un caractère non-espace. Une ligne commençant par un espace continue la ligne logique.

Chaque motif est une expression régulière de type Perl. Le délimiteur d'expression peut être n'importe quel caractère non alphanumérique, à l'exception des espaces ou des caractères ayant une signification spéciale (traditionnellement, la barre oblique est utilisée). L'expression régulière peut contenir des espaces.

Par défaut, la correspondance n'est pas sensible à la casse et les sauts de ligne ne sont pas traités comme des caractères spéciaux. Le comportement est contrôlé par des indicateurs, qui sont activés ou désactivés en ajoutant un ou plusieurs des caractères suivants après le motif :

i (par défaut : activé)
Active ou désactive l'indicateur de sensibilité à la casse. Par défaut, la correspondance n'est pas sensible à la casse.
m (par défaut : désactivé)
Active ou désactive l'indicateur MULTILIGNE de pcre. Lorsque cet indicateur est activé, les métacaractères ^ et $ correspondent immédiatement après et immédiatement avant un caractère de saut de ligne, respectivement, en plus de correspondre au début et à la fin de la chaîne sujet.
s (par défaut : activé)
Active ou désactive l'indicateur DOTALL de pcre. Lorsque cet indicateur est activé, le métacaractère . correspond au caractère de saut de ligne. Avec les versions de Postfix antérieures à 2.0, l'indicateur est désactivé par défaut, ce qui est peu pratique pour la correspondance d'en-têtes de messages multilignes.
x (par défaut : désactivé)
Active ou désactive l'indicateur étendu de pcre. Lorsque cet indicateur est activé, les espaces blancs dans le motif (autres que dans une classe de caractères) sont ignorés. Pour inclure un espace blanc comme partie du motif, échappez-le avec une barre oblique inverse.

Note : n'utilisez pas #commentaire après les motifs.

A (par défaut : désactivé)
Active ou désactive l'indicateur ANCHORED de pcre. Lorsque cet indicateur est activé, le motif est forcé d'être "ancré", c'est-à-dire qu'il est contraint de ne correspondre qu'au début de la chaîne recherchée (la "chaîne sujet"). Cet effet peut également être obtenu par des constructions appropriées dans le motif lui-même.
E (par défaut : désactivé)
Active ou désactive l'indicateur DOLLAR_ENDONLY de pcre. Lorsque cet indicateur est activé, un métacaractère $ dans le motif correspond uniquement à la fin de la chaîne sujet. Sans cet indicateur, un dollar correspond également juste avant le dernier caractère s'il s'agit d'un caractère de saut de ligne (mais pas avant d'autres caractères de saut de ligne). Cet indicateur est ignoré si l'indicateur MULTILIGNE de pcre est défini.
U (par défaut : désactivé)
Active ou désactive l'indicateur UNGREEDY de pcre. Lorsque cet indicateur est activé, le moteur de correspondance de motifs inverse l'"avidité" des quantificateurs afin qu'ils ne soient pas avides par défaut, mais deviennent avides s'ils sont suivis de "?". Cet indicateur peut également être défini par un modificateur (?U) dans le motif.
X (par défaut : désactivé)
Active ou désactive l'indicateur EXTRA de pcre. Lorsque cet indicateur est activé, toute barre oblique inverse dans un motif suivie d'une lettre qui n'a pas de signification spéciale provoque une erreur, réservant ainsi ces combinaisons pour une expansion future.

Cette fonctionnalité n'est pas supportée avec PCRE2.

ORDRE DE RECHERCHE

Les motifs sont appliqués dans l'ordre spécifié dans la table, jusqu'à ce qu'un motif correspondant à la chaîne d'entrée soit trouvé.

Chaque motif est appliqué à la chaîne d'entrée entière. Selon l'application, cette chaîne est un nom d'hôte client complet, une adresse IP client complète, ou une adresse e-mail complète. Ainsi, aucune recherche de domaine parent ou de réseau parent n'est effectuée, et les adresses e-mail utilisateur@domaine ne sont pas décomposées en leurs parties constitutives utilisateur et domaine, ni utilisateur+foo décomposé en utilisateur et foo.

SUBSTITUTION DE TEXTE

La substitution de sous-chaînes (texte correspondant aux motifs entre parenthèses "()") de l'expression correspondante dans la chaîne de résultat est demandée avec $1, $2, etc. ; spécifiez $$ pour produire un caractère $ en sortie. Les macros dans la chaîne de résultat peuvent devoir être écrites comme ${n} ou $(n) si elles ne sont pas suivies d'un espace. Cette fonctionnalité ne prend pas en charge les noms de sous-chaînes pcre2.

Note : puisque les motifs niés (ceux précédés de !) renvoient un résultat lorsque l'expression ne correspond pas, les substitutions ne sont pas disponibles pour les motifs niés.

SPECIFICATION EN LIGNE

Le contenu d'une table peut être spécifié dans le nom de la table (Postfix 3.7 et versions ultérieures). La syntaxe de base est :

main.cf:
    paramètre = .. pcre:{ { règle-1 }, { règle-2 } .. } ..
master.cf:
    .. -o { paramètre = .. pcre:{ { règle-1 }, { règle-2 } .. } .. } ..

fichier en mémoire :
    règle-1
    règle-2
    ..

Postfix analyse le résultat comme s'il s'agissait d'un fichier dans /etc/postfix.

CAVEATS DE SPÉCIFICATION EN LIGNE

  • Lorsque vous utilisez $nom_paramètre dans un motif en ligne, utilisez \Q$nom_paramètre\E pour désactiver les métacaractères tels que '.' dans l'expansion de $nom_paramètre. Sinon, le motif peut avoir des correspondances inattendues.
  • Lorsqu'une règle en ligne doit contenir $, spécifiez $$ pour empêcher Postfix d'essayer d'effectuer l'expansion $nom lors de l'évaluation d'une valeur de paramètre. Pour vérifier une configuration en ligne, utilisez l'option "postconf -x" comme indiqué ci-dessous :
  • Lorsqu'un paramètre de main.cf "nom_paramètre = valeur" contient une table pcre: en ligne, utilisez la commande "postconf -x nom_paramètre". Vérifiez qu'il n'y a pas d'avertissements de "paramètre indéfini", et que la sortie a la syntaxe que l'on utiliserait dans un fichier Postfix pcre: non en ligne.
  • Lorsqu'une substitution de master.cf "-o { nom_paramètre = valeur }" contient une table pcre: en ligne, utilisez la commande "postconf -Px '*/*/nom_paramètre' ". Vérifiez qu'il n'y a pas d'avertissements de "paramètre indéfini", et que la sortie a la syntaxe que l'on utiliserait dans un fichier Postfix pcre: non en ligne.

EXEMPLE DE MAP ACCES SMTPD

# Protégez vos exploders majordomo sortants
/^(?!owner-)(.*)-outgoing@(.*)/ 550 Utilisez ${1}@${2} à la place
# Renvoie friend@whatever, sauf lorsque whatever est notre domaine (vous seriez
# mieux de simplement renvoyer tous les e-mails friend@ - ce n'est qu'un exemple).
/^(friend@(?!my\.domain$).*)$/  550 Mettez ceci dans votre tuyau $1
# Une entrée multiligne. Le texte est envoyé sur une seule ligne.
#
/^noddy@my\.domain$/
 550 Cet utilisateur est étrange. Vous ne voulez vraiment pas lui envoyer d'e-mail car cela ne fait que lui faire tourner la tête.

EXEMPLE DE MAP FILTRE D'ENTÊTE

/^Subject: make money fast/     REJECT
/^To: friend@public\.com/       REJECT

EXEMPLE DE MAP FILTRE DE CORPS

# Ignorez d'abord le texte encodé en base 64 pour économiser des cycles CPU.
# Nécessite la version 3 de PCRE.
~^[[:alnum:]+/]{60,}$~          OK
# Mettez vos propres motifs de corps ici.
