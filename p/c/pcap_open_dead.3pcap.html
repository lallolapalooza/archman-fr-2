PCAP_OPEN_DEAD(3PCAP) PCAP_OPEN_DEAD(3PCAP)

NOM

pcap_open_dead, pcap_open_dead_with_tstamp_precision - ouvrir un pcap_t factice pour compiler des filtres ou ouvrir une capture pour la sortie

SYNTAXE

#include <pcap/pcap.h>
pcap_t *pcap_open_dead(int linktype, int snaplen);
pcap_t *pcap_open_dead_with_tstamp_precision(int linktype, int snaplen,
    u_int precision);

DESCRIPTION

pcap_open_dead() et pcap_open_dead_with_tstamp_precision() sont utilisées pour créer une structure pcap_t à utiliser lors de l'appel aux autres fonctions de libpcap. Elle est typiquement utilisée lorsqu'on utilise libpcap uniquement pour compiler du code BPF ; elle peut également être utilisée si l'on utilise pcap_dump_open(3PCAP), pcap_dump(3PCAP), et pcap_dump_close(3PCAP) pour écrire un fichier de sauvegarde s'il n'y a pas de pcap_t qui fournit les paquets à écrire.

linktype spécifie le type de couche de liaison pour le pcap_t.

snaplen spécifie la longueur du snapshot pour le pcap_t.

Lorsque pcap_open_dead_with_tstamp_precision() est utilisée pour créer un pcap_t à utiliser avec pcap_dump_open(), precision spécifie la précision de l'horodatage des paquets ; PCAP_TSTAMP_PRECISION_MICRO doit être spécifié si les paquets à écrire ont des horodatages en secondes et microsecondes, et PCAP_TSTAMP_PRECISION_NANO doit être spécifié si les paquets à écrire ont des horodatages en secondes et nanosecondes. Sa valeur n'affecte pas pcap_compile(3PCAP).

COMPATIBILITÉ ASCENDANTE

La fonction pcap_open_dead_with_tstamp_precision() est devenue disponible dans la version 1.5.1 de libpcap. Dans les versions précédentes, il n'existait aucun mécanisme pour ouvrir un fichier de sauvegarde en écriture avec des horodatages donnés en secondes et nanosecondes.
