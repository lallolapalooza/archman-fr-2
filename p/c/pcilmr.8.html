NOM

pcilmr - Marge les liens PCIe

SYNTAXE

pcilmr [--margin] [options communes] port de lien [options de lien] [port de lien] [options de lien] ...
pcilmr --full [options communes]
pcilmr --scan

CONFIGURATION

Liste des exigences pour les liens et les paramètres système afin d'exécuter le test de marging.

Paramètres du BIOS (dépend du système, pertinent pour les cartes mères serveur avec processeurs Xeon) :

•
Désactiver la fonctionnalité Leaky Bucket PCIe, la ré-égalisation et la dégradation du lien ;
•
Définir les seuils d'erreur à 0 ;
•
Intel VMD pour les SSD NVMe - en cas de comportement étrange de pcilmr, essayez de l'exécuter avec le VMD désactivé.

Exigences du périphérique (lien) :

Configuré par l'utilisateur avant d'exécuter l'utilitaire, l'utilitaire ne les modifie pas :
•
Le débit de données actuel du lien doit être de 16,0 GT/s ou plus (actuellement, l'utilitaire prend en charge les liens à 16 GT/s et 32 GT/s) ;
•
Le composant en aval du lien doit être dans l'état de gestion d'alimentation D0.
Configuré par l'utilitaire pendant le fonctionnement, l'utilitaire les rétablit à leur état original après réception des résultats :
•
L'ASPM doit être désactivé dans le port aval et le port amont ;
•
Le bit de désactivation autonome de la vitesse matérielle du registre de contrôle du lien 2 doit être défini dans le port aval et le port amont ;
•
Le bit de désactivation autonome de la largeur matérielle du registre de contrôle du lien doit être défini dans le port aval et le port amont.

DESCRIPTION

L'utilitaire pcilmr vous permet de tirer parti de la capacité de marging des lignes PCIe au niveau du récepteur, qui est obligatoire pour tous les ports prenant en charge un débit de données de 16,0 GT/s ou plus, y compris les pseudo-ports (Retimers). Le marging de ligne au niveau du récepteur permet au logiciel système d'obtenir des informations sur la marge d'un récepteur donné pendant que le lien est à l'état L0. Les informations de marge incluent la tension et le temps, dans les deux directions par rapport à la position actuelle du récepteur. La prise en charge du marging pour le temps est requise, tandis que la prise en charge de la tension est facultative à 16,0 GT/s et requise à 32,0 GT/s et plus. De plus, le marging de temps indépendant et le marging de tension indépendant sont facultatifs.

L'utilitaire permet d'obtenir une approximation du diagramme d'œil de marge sous la forme d'un losange (par quatre points). La capacité de marging de ligne au niveau du récepteur permet aux utilisateurs de marger les liens PCIe sans débogueur matériel et sans avoir à arrêter le système cible. L'utilitaire peut être utile pour déboguer des problèmes de lien dus aux marges du récepteur.

pcilmr nécessite des privilèges root (pour accéder à l'espace de configuration étendu), mais lors de nos tests, il n'y a eu aucun problème avec les périphériques et ils sont revenus avec succès à leur état initial normal après la fin des tests.

GRADING DES RÉSULTATS

La spécification PCIe fournit des valeurs de référence pour le diagramme d'œil, qui sont également utilisées par pcilmr pour évaluer les résultats, mais il semble logique de contacter le fabricant de chaque périphérique pour obtenir des références.

L'utilitaire utilise les valeurs définies dans la norme PCIe de base Rev. 5.0 Section 8.4.2 comme références minimales par défaut pour la largeur et la hauteur de l'œil. Les valeurs recommandées ont été tirées de la spécification de test électrique de l'émetteur PCIe Architecture PHY Test Spec Rev 5.0.

Les valeurs de référence actuellement utilisées par l'utilitaire sont présentées dans le tableau ci-dessous :

16 GT/s (Gen 4) 32 GT/s (Gen 5)
LW LH LW LH
Min 18.75 ps 30% UI 15 mV 9.375 ps 30% UI 15 mV
Rec 23.75 ps 38% UI 21 mV 10.157 ps 33% UI 19.75 mV

pcilmr utilise les valeurs complètes de largeur et de hauteur de l'œil pour classer les lignes. Cependant, il est possible que le périphérique ne prenne en charge qu'un seul côté du marging. Dans de tels cas, par défaut, l'utilitaire calculera la LW ou la LH comme le double du résultat d'un seul côté.

Si des informations pour un périphérique spécifique sont disponibles, vous pouvez configurer les critères de classement et ajuster le comportement de l'utilitaire dans les cas unilatéraux pour votre périphérique en utilisant l'option de lien spécifique -g (voir ci-dessous).

PRISE EN CHARGE DES QUIRKS MATÉRIELS

Grâce aux tests ou directement à la documentation du fabricant, nous savons que certains périphériques nécessitent un traitement spécial pendant le marging. L'utilitaire détecte ces périphériques en fonction de leur paire ID du fournisseur - ID du périphérique. Actuellement, la liste des périphériques spéciaux est codée en dur dans le fichier margin_hw. Pour de tels périphériques, l'utilitaire peut ajuster automatiquement les paramètres de marging du port ou les options de classement.

Par exemple, pour les ports RC des CPU Ice Lake, pcilmr modifiera la valeur MaxVoltageOffset du périphérique et forcera l'utilisation du mode de classement 'un côté est le tout'.

OPTIONS

Spécificateur de périphérique

Vous pouvez spécifier le port aval ou amont du lien.

<périphérique/composant>
[<domaine>:]<bus>:<dev>.<func> (voir lspci(8))

Modes de l'utilitaire

--margin <composant aval> ...
Marger les liens sélectionnés.
--full
Marger tous les liens prêts pour les tests (dans un sens similaire à l'option --scan) dans le système (un par un).
--scan
Analyser les liens avec une vitesse négociée de 16 GT/s ou plus. Marquer "Prêt" ceux d'entre eux sur lesquels au moins un des côtés du lien a le bit Margining Ready défini, signifiant que ces liens sont prêts pour les tests et que vous pouvez exécuter l'utilitaire dessus.

Options communes de marging (pour tous les liens spécifiés)

-c Afficher uniquement les capacités de marging de ligne du périphérique. Ne pas exécuter le marging.

-e <erreurs>
Spécifier la limite du nombre d'erreurs pour le marging.
Défaut : 4.
-o <répertoire>
Sauvegarder les résultats du marging au format csv dans le répertoire spécifié. L'utilitaire générera un fichier dont le nom sera de la forme "lmr_<port>_Rx#_<horodatage>.csv" pour chaque récepteur testé avec succès.
-d <temps>

NOM

pcilmr

PCI Express Lane Margining Tool

SYNOPIS

pcilmr [ options ] [ pci_address ... ]

DESCRIPTION

The pcilmr utility allows you to perform lane margining tests on PCI Express links. Lane margining is a technique used to measure the signal integrity of a link by varying the signal parameters (like voltage and timing) and observing the link's error rate. This helps in identifying the operational limits of the link and ensuring stable operation.

The tool interacts with the hardware to perform these measurements. It requires appropriate hardware support and privileges to access PCI Express registers.

CONFIGURATION

The tool can be configured using various command-line options to specify the devices, lanes, receivers, and margining parameters.

A pci_address can be specified as a PCI bus, device, and function tuple (e.g., 0a:00.0) or as a device name (e.g., eth0).

GRADING DES RÉSULTATS

The utility provides options to define criteria for passing or failing the margining tests based on eye width (timing) and eye height (voltage).

-g <recvn>t=<criteria>{%|ps}[,f]
<recvn>t=f[,<criteria>{%|ps}]
<recvn>v=<criteria>[,f]
<recvn>v=f[,<criteria>]
Specify pass/fail grading criteria for eye width (timing - t) or height (voltage - v) for one of the link receivers. For EW you must choose one of the units (% UI or ps), for EH mV is used.
Additional flag f is for situations when port doesn't support two side independent margining. In such cases by default utility will calculate EW or EH as a double one side result. You can add f flag for -g option to tell the utility that the result in one direction is actually the measurement of the full eye and it does not need to be multiplied. This is so called 'one side is the whole' grading mode.

PRISE EN CHARGE DES PARTICULARITÉS MATÉRIELLES

The utility includes support for specific hardware quirks to ensure correct operation on different systems.

-m <quirk>
Enable specific hardware quirk. Supported quirks depend on the device and `pcilmr` version. Examples might include options to work around specific controller behaviors or reporting inconsistencies.

OPTIONS

General options for the pcilmr utility.

-o <output_format>
Specify the output format for the results. Common formats include:
  • csv: Comma Separated Values.
  • json: JavaScript Object Notation.
  • plain: Plain text.
Default: plain.
-D
Dump margining settings. This option displays the current configuration and parameters used for margining without performing the actual test.
-C
Clear margining state. Use this to reset any lingering margining state on the device before starting a new test.

Options spécifiques au lien de margining

-s <seconds>
Spécifiez le temps de séjour en secondes pour l'étape de margining.
Défaut : 1 s

Options spécifiques au lien de margining

-l <lane>[,<lane>...]
Spécifiez les voies pour le margining.
N'oubliez pas que le périphérique peut utiliser l'inversion de voie pour la numérotation des voies. Cependant, l'utilitaire utilise les numéros de voie logiques dans les arguments et pour la journalisation. L'utilitaire déterminera automatiquement l'inversion de voie et ajustera ses appels.
Défaut : toutes les voies du lien.
-r <recvn>[,<recvn>...]
Spécifiez les récepteurs pour sélectionner les cibles de margining.
Défaut : tous les récepteurs disponibles (y compris les Retimers).
-p <parallel_lanes>
Spécifiez le nombre de voies à marginer simultanément.
Selon la spécification, il est possible pour un récepteur de marginer jusqu'à MaxLanes + 1 voies simultanément, mais pendant les tests, effectuer le margining sur plusieurs voies simultanément a conduit à des résultats différents du margining séquentiel, de sorte que cette fonctionnalité nécessite une vérification supplémentaire et que l'option -p est principalement expérimentale pour le moment.
Défaut : 1.

Utilisez uniquement l'une des options -T/-t en même temps (idem pour -V/-v).
Sans ces options, l'utilitaire utilisera MaxSteps des capacités du périphérique comme limite de test.

-T
Le margining temporel se poursuivra jusqu'à ce que le nombre d'erreurs ne dépasse pas une limite de nombre d'erreurs. Utilisez cette option pour trouver la limite du lien.
-t <steps>
Spécifiez le nombre maximum d'étapes pour le margining temporel.
-V
Identique à l'option -T, mais pour la tension.
-v <steps>
Spécifiez le nombre maximum d'étapes pour le margining de tension.

EXEMPLES

Exemple de syntaxe de l'utilitaire :

pcilmr -o csv ab:0.0 -r 1,6 -g 1t=20% -g 1v=f,30 52:0.0 -l 0,1,2 -TV

Exemples de résultats collectés sur différents systèmes.
