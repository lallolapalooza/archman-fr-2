pam(5) — Spécification du format PAM Manuel des formats de fichiers pam(5) — Spécification du format PAM

NOM

pam — Format commun de bitmaps bidimensionnels Netpbm

GÉNÉRALITÉS

Le format d'image PAM est un format de carte bidimensionnelle de dénominateur commun le plus bas.

Il est conçu pour être utilisé pour une myriade de types de graphiques, mais peut théoriquement être utilisé pour tout type de données organisées sous forme de tableau rectangulaire bidimensionnel. En fait, d'un autre point de vue, il peut être considéré comme un format de données organisées sous forme de tableau tridimensionnel.

Le nom 'PAM' est un acronyme dérivé de 'Portable Arbitrary Map' (Carte Arbitraire Portable). Cette dérivation a plus de sens si l'on considère le contexte des autres noms de formats Netpbm : PBM, PGM et PPM.

Ce format ne définit pas la signification des données à un point particulier du tableau. Il peut s'agir d'intensités lumineuses rouge, verte et bleue telles que le tableau représente une image visuelle, ou il peut s'agir des mêmes composantes rouge, verte et bleue plus une composante de transparence, ou il peut contenir les précipitations annuelles de lieux à la surface de la Terre. Tout processus utilisant le format PAM doit définir davantage le format pour spécifier la signification des données.

Une image PAM décrit une grille bidimensionnelle de tuples. Les tuples sont arrangés en lignes et colonnes. La largeur de l'image est le nombre de colonnes. La hauteur de l'image est le nombre de lignes. Toutes les lignes ont la même largeur et toutes les colonnes ont la même hauteur. Les tuples peuvent avoir n'importe quel degré, mais tous les tuples ont le même degré. Le degré des tuples est appelé la profondeur de l'image. Chaque membre d'un tuple est appelé un échantillon. Un échantillon est un entier non signé représentant un point le long d'une échelle commençant à zéro et se terminant par une certaine valeur maximale appelée maxval. Le maxval est le même pour chaque échantillon de l'image. Le tableau bidimensionnel de tous les Nèmes échantillons de chaque tuple est appelé le Nème plan ou Nème canal de l'image.

Bien que le format de base n'attribue aucune signification aux valeurs des tuples, il inclut une chaîne facultative qui décrit cette signification. Le contenu de cette chaîne, appelé type de tuple, est arbitraire du point de vue du format PAM de base, mais les utilisateurs du format peuvent lui attribuer une signification par convention afin d'identifier leurs implémentations particulières du format PAM. Certains types de tuples sont définis comme des sous-formats officiels de PAM. Voir Types de Tuples Définis.

L'Univers Confus des Formats Netpbm

Il est facile de se confondre sur la relation entre le format PAM et PBM, PGM, PPM et PNM. Voici quelques éclaircissements :

"PNM" n'est pas vraiment un format. C'est un raccourci pour les formats PBM, PGM et PPM collectivement. C'est aussi le nom d'un groupe de fonctions de bibliothèque qui peuvent chacune gérer ces trois formats.

'PAM' est en fait un quatrième format. Mais il est si général que vous pouvez représenter les mêmes informations dans une image PAM que dans une image PBM, PGM ou PPM. Et en fait, un programme conçu pour lire PBM, PGM ou PPM et qui le fait avec une version récente de la bibliothèque Netpbm, lira une image PAM équivalente sans problème et le programme ne verra aucune différence.

Pour compliquer les choses, il existe une collection de routines de bibliothèque appelées fonctions 'pam' qui lisent et écrivent le format PAM, mais lisent et écrivent également les formats PBM, PGM et PPM. Elles le font parce que ces derniers formats sont beaucoup plus anciens et plus populaires, de sorte même un nouveau programme doit travailler avec eux. Le fait que la bibliothèque gère tous les formats rend pratique l'écriture de programmes qui utilisent également le nouveau format PAM.

LA MISE EN PAGE

Un moyen pratique de lire et d'écrire le format PAM avec précision est d'utiliser la bibliothèque de sous-routines C libnetpbm(3).

Un fichier PAM consiste en une séquence d'une ou plusieurs images PAM. Il n'y a pas de données, de délimiteurs ou de remplissage avant, après ou entre les images.

Chaque image PAM consiste en un en-tête suivi immédiatement d'un raster.

Voici un exemple d'en-tête :


P7
WIDTH 227
HEIGHT 149
DEPTH 3
MAXVAL 255
TUPLTYPE RGB
ENDHDR

L'en-tête commence par les caractères ASCII 'P7' suivis d'un retour à la ligne. C'est le nombre magique.

Note : Les miniatures d'images xv commencent également par le nombre magique "P7". (Ceci et PAM étaient des extensions indépendantes des formats Netpbm). Le reste du format permet cependant de distinguer facilement PAM de ce format.

L'en-tête continue avec un nombre arbitraire de lignes de texte ASCII. Chaque ligne se termine et est délimitée par un caractère de retour à la ligne.

Chaque ligne d'en-tête consiste en zéro ou plusieurs jetons délimités par des espaces blancs ou commence par '#'. Si elle commence par '#', c'est un commentaire et le reste de cette spécification ne s'y applique pas.

Une ligne d'en-tête qui a zéro jeton est valide mais n'a aucune signification.

Le type de ligne d'en-tête est identifié par son premier jeton, qui fait 8 caractères ou moins :

ENDHDR
C'est la dernière ligne de l'en-tête. L'en-tête doit contenir exactement une de ces lignes d'en-tête.
HEIGHT
Le deuxième jeton est un nombre décimal représentant la hauteur de l'image (nombre de lignes). L'en-tête doit contenir exactement une de ces lignes d'en-tête.
WIDTH
Le deuxième jeton est un nombre décimal représentant la largeur de l'image (nombre de colonnes). L'en-tête doit contenir exactement une de ces lignes d'en-tête.
DEPTH
Le deuxième jeton est un nombre décimal représentant la profondeur de l'image (nombre de plans ou de canaux). L'en-tête doit contenir exactement une de ces lignes d'en-tête.
MAXVAL
Le deuxième jeton est un nombre décimal représentant le maxval de l'image. L'en-tête doit contenir exactement une de ces lignes d'en-tête.
TUPLTYPE
L'en-tête peut contenir un nombre quelconque de ces lignes d'en-tête, y compris zéro. Le reste de la ligne fait partie du type de tuple. Le reste de la ligne n'est pas tokenisé, mais le type de tuple n'inclut pas d'espaces blancs immédiatement après TUPLTYPE ou à la toute fin de la ligne. Il n'inclut pas de retour à la ligne. Il doit y avoir quelque chose d'autre que des espaces blancs après le jeton TUPLTYPE.

S'il y a plusieurs lignes d'en-tête TUPLTYPE, le type de tuple est la concaténation des valeurs de chacune d'elles, séparées par un seul espace, dans l'ordre où elles apparaissent dans l'en-tête. S'il n'y a pas de lignes d'en-tête TUPLTYPE, le type de tuple est la chaîne nulle.

Le raster consiste en chaque ligne de l'image, dans l'ordre de haut en bas, consécutives sans délimiteur d'aucune sorte entre, avant ou après, les lignes.

Chaque ligne consiste en chaque tuple de la ligne, dans l'ordre de gauche à droite, consécutives sans délimiteur d'aucune sorte entre, avant ou après, les tuples.

Chaque tuple consiste en chaque échantillon du tuple, dans l'ordre, consécutives sans délimiteur d'aucune sorte entre, avant ou après, les échantillons.

Chaque échantillon consiste en un entier non signé au format binaire pur, avec l'octet le plus significatif en premier. Le nombre d'octets est le nombre minimum d'octets nécessaires pour représenter le maxval de l'image.

Le caractère désigné ici par 'retour à la ligne' est le caractère connu en ASCII sous le nom de Line Feed ou LF.

LIMITATIONS

La hauteur, la largeur, la profondeur et le maxval sont d'au moins 1.

La hauteur, la largeur et la profondeur n'ont pas de maximum défini, mais les processeurs et générateurs d'images ont généralement leurs propres limitations.

Le maxval d'une image n'est jamais supérieur à 65535. (La raison pour laquelle il est limité est de faciliter la construction d'un processeur d'images, dans lequel les valeurs arithmétiques intermédiaires doivent souvent tenir dans 31 ou 32 bits). Il n'y avait pas de limitation spécifiée avant octobre 2005, mais pratiquement toutes les implémentations l'ont toujours respectée.

"Pp">Certains types de tuples sont définis dans cette spécification pour spécifier des sous-formats officiels de PAM pour des applications particulièrement populaires du format. Les utilisateurs du format peuvent également définir leurs propres types de tuples, et ainsi leurs propres sous-formats.

PAM Utilisé pour les images visuelles

Une utilisation courante des images PAM est de représenter des images visuelles telles que celles typiquement représentées par les anciens formats plus concrets PBM, PGM et PPM.

Noir Et Blanc (PBM)

Une image en noir et blanc, telle qu'elle serait représentée par une image PBM, a un type de tuple de "BLACKANDWHITE". Une telle image PAM a une profondeur de 1 et maxval 1 où l'unique échantillon dans chaque tuple est 0 pour représenter un pixel noir et 1 pour représenter un pixel blanc. La hauteur, la largeur et le raster ont une relation évidente avec ceux de l'image PBM équivalente.

Notez qu'en format PBM, une valeur zéro signifie blanc, mais en PAM, zéro signifie noir.

Niveaux de gris (PGM)

Une image en niveaux de gris, telle qu'elle serait représentée par une image PGM, a un type de tuple de "GRAYSCALE". Une telle image PAM a une profondeur de 1. Le maxval, la hauteur, la largeur et le raster ont une relation évidente avec ceux de l'image PGM équivalente.

Couleur (PPM)

Une image couleur, telle qu'elle serait représentée par une image PPM, a un type de tuple de "RGB". Une telle image PAM a une profondeur de 3. Le maxval, la hauteur, la largeur et le raster ont une relation évidente avec ceux de l'image PPM. Le premier plan représente le rouge, le second le vert et le troisième le bleu.

Transparent

Chacun des formats d'images visuelles mentionnés ci-dessus a une variation qui contient des informations de transparence. Dans cette variation, le type de tuple a '_ALPHA' ajouté (par exemple 'RGB_ALPHA') et un plan supplémentaire. Le plan le plus haut numéroté est le plan d'opacité (parfois appelé plan alpha ou plan de transparence).

Dans ce type d'image, la couleur représentée par un pixel est en réalité une combinaison d'une couleur de premier plan explicitement spécifiée et d'une couleur d'arrière-plan à identifier ultérieurement.

Les plans autres que le plan d'opacité décrivent la couleur de premier plan. Un échantillon dans le plan d'opacité indique à quel point le pixel est opaque, en indiquant quelle fraction de la lumière du pixel provient de la couleur de premier plan. Le reste de la lumière du pixel provient de la couleur d'arrière-plan (non spécifiée).

Par exemple, dans une image GRAYSCALE_ALPHA, supposons que le Plan 0 indique une tonalité de gris à 60% du blanc et que le Plan 1 indique une opacité de 25%. La couleur de premier plan est le gris à 60%, et 25% de celle-ci contribue à la couleur finale du pixel. Les 75% restants proviennent d'une couleur d'arrière-plan. Supposons donc en outre que la couleur d'arrière-plan du pixel est le blanc pur. Alors la couleur du pixel est 90% du blanc : 25% des 60% du premier plan, plus 75% des 100% de l'arrière-plan.

La valeur de l'échantillon est la fraction d'opacité décrite, en fraction du maxval. Notez qu'elle n'est *pas* ajustée gamma comme les échantillons de couleur de premier plan.

TYPE MÉDIA INTERNET

Aucun type média Internet (également appelé type MIME, type de contenu) pour PBM n'a été enregistré auprès de l'IANA, mais la valeur non officielle image/x-portable-arbitrarymap est attribuée par cette spécification, pour être cohérente avec les valeurs conventionnelles des anciens formats Netpbm.

NOM DE FICHIER

Le suffixe conventionnel pour le nom d'un fichier PAM est '.pam'. Mais ce n'est pas obligatoire.
