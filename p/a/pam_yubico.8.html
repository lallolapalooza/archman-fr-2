PAM_YUBICO(8) Manuel du module PAM Yubico PAM_YUBICO(8)

NOM

pam_yubico - Module d'authentification pour YubiKey

SYNTAXE

pam_yubico [...]

DESCRIPTION

Le module permet l'authentification des YubiKeys, soit par validation en ligne d'un OTP (One-Time Password), soit par validation hors ligne avec réponse au défi HMAC-SHA1.

OPTIONS

debug

Active le débogage.

debug_file=fichier

Nom du fichier où écrire les messages de débogage. Le fichier doit exister et être un fichier régulier. Par défaut, il s'agit de la sortie standard (stdout).

mode=[client|challenge-response]

Mode de fonctionnement : client pour la validation OTP et challenge-response pour la validation par réponse au défi. Par défaut, c'est client.

authfile=fichier

Emplacement du fichier qui contient les correspondances entre les identifiants publics des YubiKeys et les noms d'utilisateurs. Le format est : nom_utilisateur:premier_id_public:deuxieme_id_public:... L'emplacement par défaut du fichier est $HOME/.yubico/authorized_yubikeys.

id=id

Votre identifiant client API pour le serveur de validation.

key=clé

Votre clé client au format base64. La clé client est aussi connue sous le nom de clé API et assure l'intégrité de la communication entre le client (vous) et le serveur de validation. Si vous souhaitez en obtenir une pour l'utiliser avec le service YubiCloud par défaut, veuillez vous rendre sur https://upgrade.yubico.com/getapikey/.

alwaysok

Accepte toutes les tentatives d'authentification (dangereux, mode de présentation).

try_first_pass

Avant de demander le mot de passe de l'utilisateur, le module tente d'utiliser le mot de passe du module précédent de la pile, au cas où celui-ci suffirait à satisfaire ce module.

use_first_pass

Force le module à utiliser le mot de passe d'un module précédent de la pile et ne demandera jamais à l'utilisateur ; si aucun mot de passe n'est disponible ou si le mot de passe est inapproprié, l'accès sera refusé.

always_prompt

Si activé, ne tente pas de vérifier si l'utilisateur a une YubiKey configurée, mais en demande une quoi qu'il arrive. Ceci est utile dans le cas où ldap_bind_as_user est activé mais que ce module est utilisé pour lire le mot de passe de l'utilisateur (dans un scénario d'authentification YubiKey+OTP).

nullok

Ne pas échouer lorsque aucun token n'est déclaré pour l'utilisateur dans les fichiers d'autorisation ou dans LDAP. Ceci peut être utilisé pour rendre l'authentification YubiKey optionnelle, sauf si l'utilisateur a associé des tokens.

ldap_starttls

Si activé, émet une commande STARTTLS sur la connexion LDAP avant de tenter de s'y connecter. C'est une configuration courante pour les serveurs qui n'écoutent que sur le port 389 mais nécessitent néanmoins TLS.

ldap_bind_as_user

Utilise l'utilisateur qui se connecte pour se lier à LDAP. Ceci utilisera le mot de passe fourni par l'utilisateur via PAM. Si ceci est activé, ldapdn et uid_attr doivent également être définis. L'activation de cette option ignorera ldap_bind_user et ldap_bind_password.

urllist=liste

Liste des modèles d'URL à utiliser. Ceci est défini en appelant ykclient_set_url_bases. La liste doit être au format : https://api1.example.com/wsapi/2.0/verify;https://api2.example.com/wsapi/2.0/verify.

url=url

Cette option ne doit pas être utilisée, veuillez utiliser l'option urllist à la place. Définit le modèle d'URL à utiliser, défini en appelant ykclient_set_url_template. L'URL doit être définie au format https://api.example.com/wsapi/2.0/verify?id=%d&otp=%s.

capath=chemin

Le chemin où sont stockés les certificats X509. Ceci est requis si https ou ldaps sont utilisés dans url et ldap_uri, respectivement.

cainfo=fichier

Option permettant d'utiliser un bundle de CA au lieu d'un chemin.

proxy=proxy

Le proxy pour se connecter au serveur de validation. Les schémas valides sont http://, https://, socks4://, socks4a://, socks5:// ou socks5h://. Socks5h demande au proxy de résoudre le nom DNS. Si aucun schéma ou port n'est spécifié, le port 1080 du proxy HTTP sera utilisé. Exemple : socks5h://utilisateur:motdepasse@10.10.0.1:1080.

verbose_otp

Affiche le mot de passe à usage unique lorsqu'il est saisi, c'est-à-dire active l'écho des caractères saisis sur le terminal. Il est conseillé de ne pas l'utiliser si vous utilisez l'authentification à deux facteurs, car cela affichera votre mot de passe à l'écran. Cela nécessite que le service utilisant le module PAM affiche des champs personnalisés. Cette option ne peut pas être utilisée avec OpenSSH.

ldap_uri=uri

L'URI du serveur LDAP (par exemple, ldap://localhost).

ldap_server=serveur

L'hôte du serveur LDAP (le port LDAP par défaut est utilisé). Obsolète. Utilisez ldap_uri à la place.

ldapdn=dn

Le nom unique distinctif (DN) où les utilisateurs sont stockés (par exemple : ou=users,dc=domain,dc=com). Si ldap_filter est utilisé, c'est la base à partir de laquelle la recherche dans l'arborescence sera effectuée.

ldap_clientcertfile=cert_client

Le chemin vers un fichier de certificat client à utiliser lors de la communication avec le serveur LDAP. Notez que cela nécessite que ldap_clientkeyfile soit également défini.

ldap_clientkeyfile=cle_client

Le chemin vers une clé à utiliser avec le certificat client lors de la communication avec le serveur LDAP. Notez que cela nécessite que ldap_clientcertfile soit également défini.

user_attr=attr

L'attribut LDAP utilisé pour stocker les noms d'utilisateurs (par exemple : cn).

yubi_attr=attr

L'attribut LDAP utilisé pour stocker l'identifiant YubiKey.

yubi_attr_prefix=prefix

Le préfixe de la valeur de l'attribut LDAP, dans le cas d'un attribut générique, utilisé pour stocker plusieurs types d'identifiants.

token_id_length=longueur

Longueur de l'identifiant qui préfixe l'OTP (c'est 12 si on utilise YubiCloud).

ldap_bind_user=utilisateur

L'utilisateur avec lequel tenter une liaison LDAP.

ldap_bind_password=motdepasse

Le mot de passe à utiliser pour la liaison LDAP.

ldap_filter=filtre

Un filtre LDAP à utiliser pour tenter de trouver l'objet correct dans LDAP. Dans cette chaîne, %u sera remplacé par le nom d'utilisateur.

ldap_cacertfile=cert_ca

Fichier du certificat de l'autorité de certification pour la connexion LDAP.

chalresp_path=chemin

Chemin d'un répertoire système où les fichiers de défi-réponse peuvent être trouvés pour les utilisateurs. L'emplacement par défaut est $HOME/.yubico/.

mysql_server=serveur_mysql

Nom d'hôte/Adresse du serveur MySQL. Exemple : 10.0.0.1.

mysql_port=port_mysql

Port réseau du serveur MySQL.

mysql_user=utilisateur_mysql

Utilisateur pour accéder à la base de données. Il est fortement recommandé d'utiliser un utilisateur spécifique avec un accès en lecture seule.

mysql_password=motdepasse_mysql

Mot de passe MySQL associé à l'utilisateur.

mysql_database=base_de_donnees_mysql

Le nom de la base de données. Exemple : otp.

EXEMPLES

auth sufficient pam_yubico.so id=16 debug
auth required pam_yubico.so mode=challenge-response
auth required pam_yubico.so id=16 ldap_uri=ldaps://ldap.example.com ldap_filter=(uid=%u) yubi_attr=yubiKeyId

FICHIERS

$HOME/.yubico/authorized_yubikeys

Si authfile n'est pas défini, ce fichier est utilisé pour la correspondance entre l'identifiant public YubiKey et en mode client.

$HOME/.yubico/challenge, $HOME/.yubico/challenge-numero_serie

Si chalresp_path n'est pas défini, ces fichiers sont utilisés
