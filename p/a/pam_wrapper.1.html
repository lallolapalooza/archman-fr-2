NOM

pam_wrapper - Un wrapper préchargeable pour tester des applications PAM et des modules PAM

SYNTAXE

LD_PRELOAD=libpam_wrapper.so PAM_WRAPPER=1 PAM_WRAPPER_SERVICE_DIR=/chemin/vers/config ./monapplication

DESCRIPTION

Cet outil vous permet de tester votre application PAM ou module PAM. Pour tester les applications PAM, nous avons écrit un simple module PAM appelé pam_matrix (voir ci-dessous). Si vous prévoyez de tester un module PAM, vous pouvez utiliser la bibliothèque pamtest que nous avons implémentée. Elle simplifie le test des modules. Vous pouvez la combiner avec le framework de tests unitaires cmocka ou utiliser les liaisons Python fournies pour écrire des tests pour votre module en Python.

VARIABLES D'ENVIRONNEMENT

pam_wrapper est activé et contrôlé par des variables d'environnement. Vous pouvez définir les variables suivantes :

PAM_WRAPPER

Si vous chargez pam_wrapper et l'activez en définissant PAM_WRAPPER=1, tous les appels PAM seront encapsulés afin que vous puissiez spécifier un répertoire contenant les fichiers de service que pam_wrapper doit utiliser.

PAM_WRAPPER_SERVICE_DIR

Le répertoire où lire les fichiers de service PAM.

Si vous souhaitez utiliser pam_matrix (voir ci-dessous) ou tester votre propre module PAM, vous devez spécifier le chemin absolu vers votre module dans les fichiers de service.

PAM_WRAPPER_DEBUGLEVEL

Si vous avez besoin de voir ce qui se passe dans pam_wrapper lui-même ou si vous essayez de trouver un bug, vous pouvez activer le support de journalisation dans pam_wrapper si vous l'avez compilé avec des symboles de débogage.
•0 = ERREUR
•1 = AVERTISSEMENT
•2 = DÉBOGAGE
•3 = TRACE

PAM_WRAPPER_USE_SYSLOG

Par défaut, les journaux PAM iront au niveau de journalisation DEBUG de pam_wrapper et ne seront pas envoyés au syslog. Si vous souhaitez également journaliser vers syslog, vous pouvez définir cette variable sur 1.

PAM_WRAPPER_KEEP_DIR

Si cette option est définie sur 1, pam_wrapper ne supprimera pas ses répertoires temporaires. Principalement utile pour le développement de pam_wrapper.

PAM_WRAPPER_DISABLE_DEEPBIND

Cela vous permet de désactiver le deep binding dans pam_wrapper. Ceci est utile pour exécuter des outils comme valgrind ou des sanitizers tels que (address, undefined, thread).

EXEMPLE

Un fichier de service pour pam_wrapper devrait ressembler à ceci :

auth            required        /usr/lib/pam_wrapper/pam_matrix.so passdb=/path/to/pdb
account         required        /usr/lib/pam_wrapper/pam_matrix.so passdb=/path/to/pdb
password        required        /usr/lib/pam_wrapper/pam_matrix.so passdb=/path/to/pdb
session         required        /usr/lib/pam_wrapper/pam_matrix.so passdb=/path/to/pdb

Le nom du fichier doit représenter le nom du service utilisé par votre application PAM.

LD_PRELOAD=./libpam_wrapper.so PAM_WRAPPER=1 PAM_WRAPPER_SERVICE_DIR=./pam_services ./mon_app_pam

PAM_MATRIX

Nous proposons un module pour faciliter les tests d'applications PAM. Vous trouverez plus d'informations dans la page de manuel pam_matrix(8).
