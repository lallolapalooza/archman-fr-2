FBB::Pattern(3bobcat) Correspondance de motifs FBB::Pattern(3bobcat)

NOM

FBB::Pattern - Effectue la correspondance de motifs RE

SYNTAXE

#include <bobcat/pattern>
Option de liaison : -lbobcat

DESCRIPTION

Les objets Pattern peuvent être utilisés pour la correspondance de motifs d'expressions régulières (RE). La classe est un wrapper autour de la famille de fonctions regcomp(3). Par défaut, elle utilise les « expressions régulières étendues », vous obligeant à échapper les multiplicateurs et les caractères délimitant lorsqu'ils doivent être interprétés comme des caractères ordinaires (c'est-à-dire, *, +, ?, ^, $, |, (, ), [, ], {, } doivent être échappés lorsqu'ils sont utilisés comme caractères littéraux).

La classe Pattern prend en charge l'utilisation des séquences d'échappement spéciales (similaires à Perl) suivantes :
\b - indique une limite de mot
\d - indique un chiffre ([[:digit:]]) caractère
\s - indique un espace blanc ([:space:]) caractère
\w - indique un mot ([:alnum:]) caractère

Les capitales correspondantes (par exemple, \W) définissent les ensembles de caractères complémentaires. Les raccourcis d'ensembles de caractères capitalisés ne sont pas développés à l'intérieur de classes de caractères explicites (c'est-à-dire, les constructions [ ... ]). Ainsi, [\W] représente un ensemble de deux caractères : \ et W.

Comme la barre oblique inverse (\) est traitée comme un caractère spécial, elle doit être manipulée avec soin. Pattern convertit les séquences d'échappement \d \s \w (et en dehors des classes de caractères explicites, les séquences \D \S \W) en leurs classes de caractères respectives. Toutes les autres séquences d'échappement sont conservées telles quelles, et l'expression régulière résultante est proposée à la fonction de compilation de correspondance de motifs regcomp(3). Cette fonction interprète les séquences d'échappement. Par conséquent, une certaine prudence doit être exercée lors de la définition de motifs contenant des séquences d'échappement. Voici les règles :

o
Les séquences d'échappement spéciales (comme \d) sont converties en classes de caractères. Par exemple, 
    ---------------------------------------------------------
    Spécifier : Convertit en : regcomp utilise : Correspond à :
    ---------------------------------------------------------
    \d          [[:digit:]]     [[:digit:]]        3
    ---------------------------------------------------------
o
Les séquences d'échappement ordinaires (comme \x) sont conservées telles quelles. Par exemple, 
    ---------------------------------------------------------
    Spécifier : Convertit en : regcomp utilise : Correspond à :
    ---------------------------------------------------------
    \x          \x              x                  x
    ---------------------------------------------------------
o
Pour spécifier des séquences d'échappement littérales, les chaînes brutes sont recommandées, car elles ne nécessitent pas le doublement des séquences d'échappement. Par exemple, l'expression régulière suivante correspond à un mot (alphanumérique), suivi d'espaces optionnels, deux points, plus d'espaces optionnels et un nombre (décimal) : 
    R"((\w+)\s*:\s*\d+)"

TYPEDEF

o
Pattern::Position :
Un type imbriqué représentant les décalages du premier caractère et du décalage après le dernier caractère du texte correspondant ou de la sous-expression indexée, défini comme std::pair<std::string::size_type, std::string::size_type>.

CONSTRUCTEURS

o
Pattern() :
Le constructeur par défaut ne définit aucun motif, mais est disponible comme espace réservé pour, par exemple, des conteneurs nécessitant des constructeurs par défaut. Un objet Pattern ainsi construit ne peut pas être utilisé pour faire correspondre des motifs, mais peut être le lvalue dans des affectations où un autre objet Pattern est le rvalue. Cependant, il peut recevoir un motif en utilisant le membre setPattern() (voir ci-dessous). Un objet FBB::Exception est lancé si l'objet n'a pas pu être construit.
o
Pattern(std::string const &motif, bool caseSensitive = true, size_t nSub = 10, int options = REG_EXTENDED | REG_NEWLINE) :
Ce constructeur compile motif, préparant l'objet Pattern pour les correspondances de motifs. Le deuxième paramètre détermine si la correspondance sensible à la casse sera utilisée (par défaut) ou non. Les sous-expressions sont définies par des paires de parenthèses. Chaque paire correspondante définit une sous-expression, où le numéro d'ordre de ses parenthèses ouvrantes détermine l'index de la sous-expression. Par défaut, au plus 10 sous-expressions sont reconnues. Les indicateurs options peuvent être :
REG_EXTENDED :
Utilise la syntaxe des expressions régulières étendues POSIX lors de l'interprétation des regex. Si non défini, la syntaxe des expressions régulières basiques POSIX est utilisée.
REG_NOSUB :
La prise en charge de l'adressage de sous-chaînes des correspondances n'est pas requise. Les paramètres nmatch et pmatch de regexec sont ignorés si le tampon de motif fourni a été compilé avec cet indicateur défini.
REG_NEWLINE :
Les opérateurs de correspondance de n'importe quel caractère ne correspondent pas à un saut de ligne.
Une liste de non-correspondance ([^...]) ne contenant pas de saut de ligne ne correspond pas à un saut de ligne.
L'opérateur de début de ligne de correspondance (^) correspond à la chaîne vide immédiatement après un saut de ligne, que les eflags, les indicateurs d'exécution de regexec, contiennent REG_NOTBOL ou non.
L'opérateur de fin de ligne de correspondance ($) correspond à la chaîne vide immédiatement avant un saut de ligne, que les eflags contiennent REG_NOTEOL ou non.

Les constructeurs de copie et de déplacement (ainsi que les opérateurs d'affectation) sont disponibles.

FONCTIONS MEMBRES

Tous les membres de std::ostringstream et std::exception sont disponibles, car Pattern hérite de ces classes.

o
std::string avant() const :
Suite à une correspondance réussie, avant() retourne le texte avant le texte correspondant.
o
std::string au_dela() const :
Suite à une correspondance réussie, au_dela() retourne le texte après le texte correspondant.
o
size_t fin() const :
Retourne le nombre d'éléments correspondants (texte et sous-expressions). fin() est la plus petite valeur d'index pour laquelle position() retourne deux valeurs std::string::npos (voir la fonction membre position(), ci-dessous).
o
void match(std::string const &texte, int options = 0) :
Correspond un texte avec un motif. Si le texte n'a pas pu être mis en correspondance, une exception Exception est lancée, utilisant Pattern::match() comme texte de préfixe.
Les options peuvent être :
REG_NOTBOL :
L'opérateur de début de ligne de correspondance échoue toujours à correspondre (mais voir l'indicateur de compilation REG_NEWLINE ci-dessus). Cet indicateur peut être utilisé lorsque différentes portions d'une chaîne sont passées à regexec et que le début de la chaîne ne doit pas être interprété comme le début de la ligne.
REG_NOTEOL :
L'opérateur de fin de ligne de correspondance échoue toujours à correspondre (mais voir l'indicateur de compilation REG_NEWLINE)
o
std::string correspondant() const :
Suite à une correspondance réussie, cette fonction retourne le texte correspondant.
o
std::string const &motif() const :
Cette fonction membre retourne le motif qui est proposé à regcomp(3). Elle retourne le contenu d'une chaîne statique qui est écrasé à chaque construction d'un objet Pattern et à chaque appel de la fonction

o
Pattern::Position position(size_t index) const:
Avec index == 0, le texte entièrement correspondant est retourné (identique à matched()). D'autres valeurs d'index retournent les sous-expressions correspondantes. std::string::npos, std::string::npos est retourné si l'index est supérieur ou égal à end() (ce qui peut arriver pour l'index 0).
o
void setPattern(std::string const &pattern, bool caseSensitive = true, size_t nSub = 10, int options = REG_EXTENDED | REG_NEWLINE):
Cette fonction membre installe un nouveau pattern compilé dans son objet Pattern. Les paramètres de cette fonction sont identiques à ceux du second constructeur. Référez-vous à ce constructeur pour plus de détails sur les paramètres. Comme pour le constructeur, une exception FBB::Exception est levée si le nouveau pattern ne peut pas être compilé.
o
void swap(Pattern &other):
Le contenu de l'objet courant et de l'objet other sont échangés.

OPÉRATEURS SURCHARGÉS

o
std::string operator[](size_t index) const:
Retourne le texte correspondant (pour l'index 0) ou le texte d'une sous-expression. Une chaîne vide est retournée pour les indices supérieurs ou égaux à end().
o
Pattern &operator<<(int matchOptions):
Définit les options de correspondance à utiliser avec l'opérateur surchargé suivant.
o
bool operator<<(std::string const &text):
Effectue un appel match(text, matchOptions), capturant toute exception qui pourrait être levée. Si aucune matchOptions n'a été définie à l'aide de l'opérateur surchargé ci-dessus, aucune n'est utilisée. Les options définies de cette manière ne sont pas "collantes" : si nécessaire, elles doivent être réinsérées avant chaque nouvelle correspondance de pattern. La fonction retourne true si la correspondance a réussi, false sinon.

EXEMPLE

#include "driver.h"
#include <bobcat/pattern>
using namespace std;
using namespace FBB;
#include <algorithm>
#include <cstring>
void showSubstr(string const &str)
{
    static int count = 0;
    cout << "String " << ++count << " est ’" << str << "’\n";
}
void match(Pattern const &patt, string const &text)
try
{
     Pattern pattern{ patt };
    pattern.match(text);
    Pattern p3(pattern);
    cout << "avant:  " << p3.before() << "\n"
            "correspondant: " << p3.matched() << "\n"
            "apres:  " << pattern.beyond() << "\n"
            "fin() = " << pattern.end() << ’\n’;
    for (size_t idx = 0; idx != pattern.end(); ++idx)
    {
        string str = pattern[idx];
        if (str.empty())
            cout << "partie " << idx << " non présente\n";
        else
        {
            Pattern::Position pos = pattern.position(idx);
            cout << "partie " << idx << ": ’" << str << "’ (" <<
                        pos.first << "-" << pos.second << ")\n";
        }
    }
}
catch (exception const &exc)
{
    cout << exc.what() << ’\n’;
}
int main(int argc, char **argv)
{
    string patStr = R"(\d+)";
    do
    {
        cout << "Pattern: ’" << patStr << "’\n";
        try
        {
                // par défaut: sensible à la casse
                // utiliser n'importe quel argument pour ignorer la casse
            Pattern patt(patStr, argc == 1);
            cout << "Pattern compilé : " << patt.pattern() << ’\n’;
            while (true)
            {
                cout << "chaîne à faire correspondre : ";
                string text;
                getline(cin, text);
                if (text.empty())
                    break;
                cout << "Chaîne : ’" << text << "’\n";
                match(patt, text);
            }
        }
        catch (exception const &exc)
        {
            cout << exc.what() << ": compilation échouée\n";
        }
        cout << "Nouveau pattern : ";
    }
    while (getline(cin, patStr) and not patStr.empty());
}

BOGUES

L'utilisation d'objets Pattern comme membres de données statiques de classes (ou comme objets globaux) est potentiellement dangereuse. Si les fichiers objets définissant ces membres de données statiques sont stockés dans une bibliothèque dynamique, ils peuvent ne pas être initialisés correctement ou en temps voulu, et leur destruction éventuelle peut entraîner un échec de segmentation. C'est un problème bien connu avec les données statiques, voir, par exemple, http://www.parashift.com/c++-faq-lite/ctors.html#faq-10.15. Dans de telles situations, préférez l'utilisation d'un pointeur (partagé, unique) vers un Pattern, en initialisant le pointeur lorsque, par exemple, il est utilisé pour la première fois.
