NOM

paxtar — archiveur de bande

SYNOPSIS

paxtar {crtux}[014578abefHhJjLmOoPpqsvwXZz] [facteur-de-blocage | archive | chaine-remplacement] [-C repertoire] [-I fichier] [fichier ...]

paxtar {-crtux} [-014578aeHhJjLmOoPpqvwXZz] [-b facteur-de-blocage] [-C repertoire] [-D options-format] [-f archive] [-I fichier] [-M indicateur] [-s chaine-remplacement] [fichier ...]

DESCRIPTION

La commande paxtar crée, ajoute des fichiers à, ou extrait des fichiers d'un fichier archive au format “tar” (strictement parlant, ustar). Une archive tar est souvent stockée sur une bande magnétique, mais peut être stockée aussi bien sur une disquette, un CD-ROM, ou dans un fichier disque régulier.

Dans la première forme (héritée), tous les indicateurs d'options sauf -C et -I doivent être contenus dans le premier argument de paxtar et ne doivent pas être préfixés par un tiret (‘-’). Les arguments d'options, s'il y en a, sont traités comme des arguments suivants de paxtar et sont traités dans l'ordre dans lequel leurs indicateurs d'options correspondants ont été présentés sur la ligne de commande.

Dans la deuxième forme, préférée, les indicateurs d'options peuvent être donnés dans n'importe quel ordre et sont immédiatement suivis par leurs valeurs d'arguments d'options correspondantes.

Un des indicateurs suivants doit être présent :

-c
Créer une nouvelle archive, ou écraser une archive existante, en y ajoutant les fichiers spécifiés.
-r
Ajouter les nouveaux fichiers nommés à l'archive existante. Notez que cela ne fonctionnera que sur des médias sur lesquels un marqueur de fin de fichier peut être écrasé.
-t
Lister le contenu de l'archive. Si des fichiers sont nommés sur la ligne de commande, seuls ces fichiers seront listés. Les arguments fichier peuvent être spécifiés comme des modèles globaux (voir glob(7) pour plus d'informations), auquel cas paxtar listera tous les membres de l'archive qui correspondent à chaque modèle.
-u
Alias pour -r.
-x
Extraire des fichiers de l'archive. Si des fichiers sont nommés sur la ligne de commande, seuls ces fichiers seront extraits de l'archive. Les arguments fichier peuvent être spécifiés comme des modèles globaux (voir glob(7) pour plus d'informations), auquel cas paxtar extraira tous les membres de l'archive qui correspondent à chaque modèle.

Si plus d'une copie d'un fichier existe dans l'archive, les copies ultérieures écraseront les copies antérieures lors de l'extraction. Le mode de fichier et l'heure de modification sont préservés si possible. Le mode de fichier est sujet à modification par le umask(2).

En plus des indicateurs mentionnés ci-dessus, n'importe lequel des indicateurs suivants peut être utilisé :

-a
Deviner l'utilitaire de compression en fonction du nom du fichier archive. L'incapacité à deviner entraînera l'absence silencieuse de compression. Cette option n'existe que pour une compatibilité partielle avec GNU tar ; il est fortement recommandé d'archiver sur stdout et de canaliser vers un utilitaire de compression externe avec les arguments appropriés à la place :
tar -cf - foo | xz -2e >foo.txz
-b facteur-de-blocage
Définir le facteur de blocage à utiliser pour l'archive. paxtar utilise des blocs de 512 octets. La valeur par défaut est 20, le maximum est 126. Les archives avec un facteur de blocage supérieur à 63 violent la norme POSIX et ne seront pas portables sur tous les systèmes.
-C repertoire
Il s'agit d'un argument positionnel qui définit le répertoire de travail pour les fichiers suivants. Lors de l'extraction, les fichiers seront extraits dans le répertoire spécifié ; lors de la création, les fichiers spécifiés seront recherchés à partir du répertoire.
-D options-format
Spécifier le format de l'archive et les options de format, séparés par une virgule. paxtar prend actuellement en charge les formats et options suivants :
ar
Le format de bibliothèque d'archive Unix. Ce format correspond aux dépôts APT et à la spécification BSD de ar(1), pas à GNU binutils (qui peuvent cependant les lire) ni aux systèmes SYSV. Voir ar(5) sur certains systèmes d'exploitation pour plus d'informations.
bcpio
Le format cpio binaire ancien. La taille de bloc par défaut pour ce format est de 5120 octets. Ce format n'est pas très portable et ne doit pas être utilisé lorsque d'autres formats sont disponibles. Les informations d'inode et de périphérique d'un fichier (utilisées pour détecter les liens physiques par ce format), qui peuvent être tronquées par ce format, sont détectées par paxtar et réparées.
cpio
Le format d'échange cpio étendu spécifié dans la norme IEEE Std 1003.2 (“POSIX.2”). La taille de bloc par défaut pour ce format est de 5120 octets. Les informations d'inode et de périphérique d'un fichier (utilisées pour détecter les liens physiques par ce format), qui peuvent être tronquées par ce format, sont détectées par paxtar et réparées.
sv4cpio
Le format cpio System V release 4. La taille de bloc par défaut pour ce format est de 5120 octets. Les informations d'inode et de périphérique d'un fichier (utilisées pour détecter les liens physiques par ce format), qui peuvent être tronquées par ce format, sont détectées par paxtar et réparées.
sv4crc
Le format cpio System V release 4 avec sommes de contrôle CRC des fichiers. La taille de bloc par défaut pour ce format est de 5120 octets. Les informations d'inode et de périphérique d'un fichier (utilisées pour détecter les liens physiques par ce format), qui peuvent être tronquées par ce format, sont détectées par paxtar et réparées.
tar
Le format tar ancien de BSD tel qu'on le trouve dans 4.3BSD. La taille de bloc par défaut pour ce format est de 10240 octets. Les noms de chemin stockés par ce format doivent avoir une longueur de 100 caractères ou moins. Seuls les fichiers réguliers, les liens physiques, les liens symboliques et les répertoires seront archivés (les autres types de systèmes de fichiers ne sont pas pris en charge).

Pour la compatibilité descendante avec des formats tar encore plus anciens, l'option write_opt=nodir peut être utilisée lors de l'écriture d'une archive pour omettre le stockage des répertoires.

ustar
Le format tar étendu spécifié dans la norme IEEE Std 1003.2 (“POSIX.2”). La taille de bloc par défaut pour ce format est de 10
-e
Écrire toutes les métadonnées de fichier, y compris les listes de contrôle d'accès (ACL), les étendues étendues (xattrs) et les listes de contrôle d'accès POSIX (POSIX ACLs). Ceci est une extension non standard de tar(1).
-f archive
Utiliser le fichier archive comme source ou destination de l'archive. Si archive est un tiret (‘-’), paxtar utilisera l'entrée standard ou la sortie standard.
-h
Ne pas suivre les liens symboliques ; archiver les liens symboliques eux-mêmes. Ceci est l'inverse du comportement par défaut de paxtar lors de la création d'une archive, mais identique au comportement par défaut lors de l'extraction.
-I fichier
Spécifier le fichier à lire pour les noms de fichiers à traiter. Utile pour les fichiers qui ne peuvent pas être nommés sur la ligne de commande. Voir aussi find.
-J
Compresser l'archive avec lzma. Nécessite xz(1).
-j
Compresser l'archive avec bzip2. Nécessite bzip2(1).
-L fichier
Enregistrer les fichiers d'archive en utilisant le format de liste de fichiers de la bibliothèque de fichiers. Cela peut être utilisé pour créer des archives très volumineuses qui dépassent les limites de taille de fichier. Voir aussi tar(1).
-l
Lister les noms de fichiers au fur et à mesure qu'ils sont traités. Utile pour les archives volumineuses et/ou les médias lents.
-m
Ne pas enregistrer les temps de modification des fichiers. Utile pour les systèmes de fichiers qui ne stockent pas les temps de modification ou pour les archives où le temps de modification n'est pas important.
-O
Extraire les fichiers dans le répertoire courant, sans créer de sous-répertoires. Ceci est l'inverse du comportement par défaut de paxtar lors de l'extraction.
-o
Écrire des fichiers avec leurs permissions d'origine. Utile pour les archives créées sur des systèmes de fichiers différents ou pour les systèmes de fichiers où les permissions ne peuvent pas être définies.
-P
Ne pas supprimer les préfixes de chemin des noms de fichiers absolus. Ceci est l'inverse du comportement par défaut de paxtar lors de l'extraction.
-p
Conserver les permissions des fichiers. Utile pour les archives créées sur des systèmes de fichiers différents ou pour les systèmes de fichiers où les permissions ne peuvent pas être définies.
-q
Continuer à ajouter des fichiers à l'archive, même si cela écrase des fichiers existants. Ceci est l'inverse du comportement par défaut de paxtar lors de l'ajout de fichiers.
-s chaine-remplacement
Remplacer chaine-remplacement dans les noms de fichiers. La chaîne de remplacement est de la forme anchien:nouveau, où anchien est la chaîne à rechercher et nouveau est la chaîne par laquelle la remplacer. Si anchien est omis, nouveau sera préfixé à tous les noms de fichiers. Si nouveau est omis, anchien sera supprimé de tous les noms de fichiers. Plusieurs options -s peuvent être spécifiées.
-v
Verbeux. Lister les fichiers au fur et à mesure qu'ils sont traités. Utile pour les archives volumineuses et/ou les médias lents.
-w
Demander une confirmation avant chaque opération. Utile pour éviter les erreurs accidentelles.
-X fichier
Exclure les fichiers nommés dans fichier de l'archive. Voir aussi find.
-Z
Compresser l'archive avec compress. Nécessite compress(1).
-z
Compresser l'archive avec gzip. Nécessite gzip(1).

Les options suivantes ne sont disponibles que dans la forme syntaxique préférée :

-0
Utiliser le format NUL-delimited archive (GNU tar). Nécessite une liste de fichiers terminée par des NUL.
-1
Utiliser le format de compression zstd. Nécessite zstd(1).
-4
Utiliser le format de compression lz4. Nécessite lz4(1).
-5
Utiliser le format de compression lzop. Nécessite lzop(1).
-7
Utiliser le format de compression bz2. Nécessite bzip2(1).
-8
Utiliser le format de compression xz. Nécessite xz(1).
-9
Utiliser le format de compression gzip. Nécessite gzip(1).
-M indicateur
Indicateur pour les archives multi-volumes. Les indicateurs pris en charge sont :
addfile
Ajouter un fichier d'archive à une archive multi-volumes existante. Ceci est l'inverse du comportement par défaut de paxtar lors de l'ajout de fichiers.
overwrite
Écraser un fichier d'archive existant lors de la création d'une archive multi-volumes. Ceci est l'inverse du comportement par défaut de paxtar lors de la création d'une archive.

La commande paxtar est un programme d'archive universel qui peut lire et écrire des archives dans une variété de formats, y compris le format tar traditionnel, le format ustar POSIX, le format cpio et le format ar. La commande peut également être utilisée pour compresser et décompresser des archives à l'aide de divers utilitaires de compression.

Lorsque vous utilisez l'option -C, le répertoire spécifié devient le répertoire de travail actuel pour toutes les opérations de fichier qui suivent. Par exemple, si vous utilisez -C /tmp, tous les fichiers créés ou extraits seront placés dans le répertoire /tmp.

L'option -I permet de lire une liste de fichiers à partir d'un fichier spécifié. Ceci est utile pour traiter un grand nombre de fichiers ou pour des fichiers dont les noms contiennent des caractères spéciaux qui pourraient interférer avec l'analyse de la ligne de commande.

L'option -s permet de remplacer des chaînes dans les noms de fichiers. Ceci est utile pour renommer des fichiers dans une archive ou pour corriger des erreurs de nommage. Par exemple, -s a:b remplacera toutes les occurrences de la chaîne a par la chaîne b dans les noms de fichiers.

L'option -D permet de spécifier le format de l'archive et les options de format. Ceci est utile pour créer des archives compatibles avec d'autres programmes ou pour utiliser des fonctionnalités spécifiques à un format. Les formats pris en charge incluent ar, bcpio, cpio, sv4cpio, sv4crc, tar et ustar.

La commande paxtar est un outil puissant et flexible pour la gestion des archives. Elle peut être utilisée pour une variété de tâches, de la simple création d'archives à des opérations plus complexes comme la compression, la décompression et le remplacement de chaînes.

EXEMPLES

Créer une archive nommée backup.tar contenant les fichiers file1, file2 et dir1:

paxtar -c -f backup.tar file1 file2 dir1

Extraire tous les fichiers de backup.tar dans le répertoire courant:

paxtar -x -f backup.tar

Lister le contenu de backup.tar sans l'extraire:

paxtar -t -f backup.tar

Créer une archive compressée avec gzip:

paxtar -czf backup.tar.gz file1 file2 dir1

Extraire une archive compressée avec gzip:

paxtar -xzf backup.tar.gz

-m
Ne pas préserver l'heure de modification.
-O
En lecture, extraire les fichiers vers la sortie standard.
En écriture, écrire des archives de style ancien (non-POSIX).
-o
En écriture, écrire des archives de style ancien (non-POSIX).
Ne pas écrire les informations de répertoire que l'ancien style (tar V7) est incapable de décoder. Identique à -D tar,write_opt=nodir.
-P
Pour des raisons de sécurité, paxtar ignore les noms de chemin contenant des composants dotdot (“..”) et supprime les barres obliques de tête (‘/’) des noms de chemin par défaut ; cette option désactive ce comportement.
-p
Préserver l'ID utilisateur et groupe ainsi que le mode de fichier, quelle que soit l'actuelle umask(2). Les bits setuid et setgid ne sont préservés que si l'ID utilisateur et groupe pouvait être préservé. Uniquement significatif en conjonction avec le flag -x.
-q
Sélectionner le premier membre d'archive qui correspond à chaque opérande fichier. Pas plus d'un membre d'archive n'est correspondant pour chaque fichier. Lorsque des membres de type répertoire sont correspondants, la hiérarchie de fichiers racinée à ce répertoire est également correspondante.
-s replstr
Modifier les noms des membres d'archive selon l'expression de substitution replstr, en utilisant la syntaxe des expressions régulières de l'utilitaire ed(1). Des arguments fichier peuvent être donnés pour restreindre la liste des membres d'archive à ceux spécifiés.

Le format de ces expressions régulières est

/ancien/nouveau/[gp]

Comme dans ed(1), ancien est une expression régulière de base (voir re_format(7)) et nouveau peut contenir une esperluette (‘&’), des références arrière ‘\n’ (où n est un chiffre), ou la correspondance de sous-expression. La chaîne ancien peut également contenir des caractères de nouvelle ligne. N'importe quel caractère non nul peut être utilisé comme délimiteur (‘/’ est montré ici). Plusieurs expressions -s peuvent être spécifiées. Les expressions sont appliquées dans l'ordre où elles sont spécifiées sur la ligne de commande, se terminant à la première substitution réussie.

Le g final optionnel continue d'appliquer l'expression de substitution à la sous-chaîne du chemin, qui commence par le premier caractère suivant la fin de la dernière substitution réussie. La première substitution infructueuse arrête le fonctionnement de l'option g. Le p final optionnel provoquera l'écriture du résultat final d'une substitution réussie sur la sortie standard d'erreur dans le format suivant :

nom-chemin-original >> nouveau-nom-chemin

Les fichiers ou les noms de membres d'archive qui se substituent à une chaîne vide ne sont pas sélectionnés et seront ignorés.

-v
Mode de fonctionnement verbeux. Si -v est spécifié plusieurs fois ou si l'option -t est également spécifiée, paxtar utilisera un format long pour lister les fichiers, similaire à ls(1) -l.
-w
Renommer les fichiers interactivement. Cette option amène paxtar à demander à l'utilisateur le nom de fichier à utiliser lors du stockage ou de l'extraction de fichiers dans une archive.
-X
Ne pas traverser les points de montage dans le système de fichiers.
-Z
Utiliser l'utilitaire compress(1) pour compresser l'archive.
-z
Utiliser l'utilitaire gzip(1) pour compresser l'archive.

Les options [-014578] peuvent être utilisées pour sélectionner l'un des périphériques de sauvegarde intégrés, /dev/rstN.

NAME

paxtar — create and extract tape archives

SYNOPSIS

paxtar [ tar(1) options ] [ pax(1) options ] [ file ... ]

DESCRIPTION

paxtar is a utility program that is able to write a number of files and directories into a single archive file, and to extract files and directories from an archive file, back to the file system. It is a combination of the functions of tar(1) and pax(1).

The archive format is the old tar(1) format.

The paxtar utility is compatible with tar(1) command line options and most of pax(1) command line options.

ENVIRONMENT

paxtar uses the following environment variables:

TMPDIR
If set, paxtar uses this directory for temporary files.
TZ
Used to convert times stored in the archive to local time.

FILES

/tmp/tar-*, /tmp/pax-*

Temporary files.

EXIT STATUS

The exit status is zero upon successful completion. Non-zero values indicate that an error occurred.

EXAMPLES

Create an archive named foriru.tar.gz from the file bonvole:

$ paxtar zcf foriru.tar.gz bonvole sekve

Verbosely create an archive, called backup.tar.gz, of all files matching the shell glob(7) function *.c:

$ paxtar zcvf backup.tar.gz *.c

Verbosely list, but do not extract, all files ending in .jpeg from a compressed archive named backup.tar.gz. Note that the glob pattern has been quoted to avoid expansion by the shell:

$ paxtar tvzf backup.tar.gz '*.jpeg'

For more detailed examples, see pax(1).

DIAGNOSTICS

Whenever paxtar cannot create a file or a link when extracting an archive or cannot find a file while writing an archive, or cannot preserve the user ID, group ID, file mode, or access and modification times when the -p option is specified, a diagnostic message is written to standard error and a non-zero exit value will be returned, but processing will continue. In the case where paxtar cannot create a link to a file, unless -M lncp is given, paxtar will not create a second copy of the file.

If the extraction of a file from an archive is prematurely terminated by a signal or error, paxtar may have only partially extracted the file the user wanted. Additionally, the file modes of extracted files and directories may have incorrect file bits, and the modification and access times may be wrong.

If the creation of an archive is prematurely terminated by a signal or error, paxtar may have only partially created the archive, which may violate the specific archive format specification.
