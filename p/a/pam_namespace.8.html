NOM

pam_namespace - Module PAM pour configurer l'espace de noms d'une session

SYNTAXE

pam_namespace.so [debug] [unmnt_remnt] [unmnt_only] [require_selinux] [gen_hash] [ignore_config_error] [ignore_instance_parent_mode] [unmount_on_close] [use_current_context] [use_default_context] [mount_private]

DESCRIPTION

Le module PAM pam_namespace configure un espace de noms privé pour une session avec des répertoires polyinstanciés. Un répertoire polyinstancié fournit une instance différente de lui-même basée sur le nom d'utilisateur, ou en utilisant SELinux, le nom d'utilisateur, le contexte de sécurité ou les deux. Si un script exécutable /etc/security/namespace.init existe, il est utilisé pour initialiser le répertoire d'instance après sa configuration et son montage sur le répertoire polyinstancié. Le script reçoit le chemin du répertoire polyinstancié, le chemin du répertoire d'instance, un indicateur indiquant si le répertoire d'instance a été nouvellement créé (0 pour non, 1 pour oui) et le nom d'utilisateur comme arguments. Le script est appelé avec des privilèges root complets et l'accès au répertoire d'instance dans ce contexte doit être effectué avec prudence, car il est contrôlé par l'utilisateur non privilégié pour lequel il a été créé.

Le module pam_namespace dissocie l'espace de noms de la session de l'espace de noms parent. Tous les montages/démontages effectués dans l'espace de noms parent, tels que le montage de périphériques, ne sont pas reflétés dans l'espace de noms de la session. Pour propager des événements de montage/démontage sélectionnés de l'espace de noms parent vers l'espace de noms de session dissocié, un administrateur peut utiliser la fonctionnalité spéciale de sous-arbre partagé. Pour plus d'informations sur la fonctionnalité de sous-arbre partagé, veuillez vous référer à la page de manuel mount(8) et à la description de sous-arbre partagé à http://lwn.net/Articles/159077 et http://lwn.net/Articles/159092.

OPTIONS

debug

Beaucoup d'informations de débogage sont enregistrées via syslog

unmnt_remnt

Pour des programmes comme su et newrole, la session de connexion a déjà configuré un espace de noms polyinstancié. Pour ces programmes, la polyinstanciation est effectuée en fonction du nouvel identifiant d'utilisateur ou du contexte de sécurité, cependant la commande doit d'abord annuler la polyinstanciation effectuée par login. Cet argument instruit la commande d'annuler d'abord la polyinstanciation précédente avant de continuer avec la nouvelle polyinstanciation basée sur le nouvel id/contexte.

unmnt_only

Pour les programmes de confiance qui souhaitent annuler tous les montages bind existants et traiter les répertoires d'instance par eux-mêmes, cet argument leur permet de démonter les répertoires d'instance actuellement montés.

require_selinux

Si SELinux n'est pas activé, retourner un échec

gen_hash

Au lieu d'utiliser la chaîne de contexte de sécurité pour le nom d'instance, générer et utiliser son hash md5.

ignore_config_error

Si une ligne dans le fichier de configuration correspondant à un répertoire polyinstancié contient une erreur de format, ignorer cette ligne et traiter la suivante. Sans cette option, pam retournera une erreur au programme appelant, ce qui entraînera la fin de la session.

ignore_instance_parent_mode

Les répertoires parents d'instance sont censés avoir par défaut le mode restrictif de 000. En utilisant cette option, un administrateur peut choisir d'ignorer le mode du parent d'instance. Cette option doit être utilisée avec prudence car elle réduira les objectifs de sécurité et d'isolation du mécanisme de polyinstanciation.

unmount_on_close

Démonter explicitement les répertoires polyinstanciés au lieu de s'appuyer sur la destruction automatique de l'espace de noms une fois que le dernier processus d'un espace de noms est terminé. Cette option ne doit être utilisée que s'il est garanti par d'autres moyens qu'aucun processus ne peut rester en cours d'exécution dans l'espace de noms privé après la fermeture de la session. Elle est également utile uniquement s'il y a plusieurs appels de session pam consécutifs à partir du même processus.

use_current_context

Utile pour les services qui ne modifient pas le contexte SELinux avec l'appel setexeccon. Le module utilisera le contexte SELinux actuel du processus appelant pour la polyinstanciation de niveau et de contexte.

use_default_context

Utile pour les services qui n'utilisent pas pam_selinux pour modifier le contexte SELinux avec l'appel setexeccon. Le module utilisera le contexte SELinux par défaut de l'utilisateur pour la polyinstanciation de niveau et de contexte.

mount_private

Cette option peut être utilisée sur les systèmes où le point de montage / ou ses sous-montages sont rendus partagés (par exemple, avec une commande mount --make-rshared /). Le module marquera l'arborescence entière afin que toutes les opérations de montage et de démontage dans l'espace de noms de polyinstanciation soient privées. Normalement, pam_namespace tentera de détecter le point de montage / partagé et de rendre automatiquement les répertoires polyinstanciés privés. Cette option doit uniquement être utilisée lorsqu'un sous-arbre est partagé et que / ne l'est pas.

Notez que les montages et démontages effectués dans l'espace de noms privé n'affecteront pas l'espace de noms parent si cette option est utilisée ou lorsque le point de montage / partagé est détecté automatiquement.

TYPES DE MODULES FOURNIS

Seul le type de module session est fourni. Le module ne doit pas être appelé à partir de processus multithreadés.

VALEURS DE RETOUR

PAM_SUCCESS

La configuration de l'espace de noms a réussi.

PAM_SERVICE_ERR

Une erreur système inattendue s'est produite lors de la configuration de l'espace de noms.

PAM_SESSION_ERR

Une erreur de configuration de l'espace de noms inattendue s'est produite.

FICHIERS

/etc/security/namespace.conf

Fichier de configuration principal

/etc/security/namespace.d

Répertoire pour les fichiers de configuration supplémentaires

/etc/security/namespace.init

Script d'initialisation pour les répertoires d'instance

EXEMPLES

Pour les <services> qui nécessitent une polyinstanciation (login par exemple), mettez la ligne suivante dans /etc/pam.d/<service> en tant que dernière ligne pour le groupe session :

session required pam_namespace.so [arguments]

Pour utiliser la polyinstanciation avec le gestionnaire d'affichage graphique gdm, veuillez vous référer à la documentation de gdm.

VOIR AUSSI

namespace.conf(5), pam.d(5), mount(8), pam(8).

NAME

pam_namespace - PAM module for namespace handling

SYNOPSIS

pam_namespace.so [debug] [verbose] [quiet] [use_system_config] [map_dir=/path/to/dir]

OPTIONS

debug
Enables debugging messages.
verbose
Enables verbose output.
quiet
Suppresses most error messages.
use_system_config
Uses the system-wide configuration file (usually found in /etc/security/namespace.conf) for namespace mappings.
map_dir=/path/to/dir
Specifies a directory where user-specific namespace configuration files can be found. If this option is used, the module will look for a file named .namespace within the specified directory. This allows for per-user namespace configurations.

MODULE TYPES PROVIDED

The following module types are provided:

session
The primary module type used for setting up and tearing down namespaces.

RETURN VALUES

PAM_SUCCESS
The namespace operations were successful.
PAM_SESSION_ERR
An error occurred during session setup or teardown.
PAM_BUF_ERR
Memory buffer related error.
PAM_SYSTEM_ERR
System error.

FILES

/etc/security/namespace.conf
System-wide configuration file for pam_namespace.
~/.namespace
User-specific configuration file, typically located in the user's home directory. This is used when the map_dir option is specified.

EXAMPLES

To configure pam_namespace to create a network namespace and mount specific directories for a user upon login, you might add the following line to your /etc/pam.d/system-login file:

session    required     pam_namespace.so use_system_config map_dir=/etc/namespace.d

And in /etc/security/namespace.conf, you could specify namespace creations:

# Namespace configuration for all users
# Create a network namespace
netns mount
# Mount /data to /srv/data in the new network namespace
mount /data /srv/data
# Mount /var/log to /mnt/logs in the new network namespace
mount /var/log /mnt/logs
# Unmount on session exit (implicitly handled by PAM teardown)

For user-specific configurations, create a directory like /etc/namespace.d/username and place a .namespace file within it, containing the same directives as namespace.conf.

SEE ALSO

pam.d(5), namespaces(7), mount(8)

NOM

pam_namespace - Module PAM pour la gestion des espaces de noms

SYNTAXE

pam_namespace.so [debug] [verbose] [quiet] [use_system_config] [map_dir=/chemin/vers/repertoire]

DESCRIPTION

Le module pam_namespace fournit un mécanisme pour gérer les espaces de noms pour les sessions utilisateur. Il permet la création et le montage d'espaces de noms spécifiques (comme les espaces de noms réseau, UTS ou PID) lors de l'initialisation de la session et leur démontage lors de la fin de la session.

Ceci est particulièrement utile pour les technologies de conteneurisation ou pour isoler des services spécifiques dans leurs propres espaces de noms.

La configuration de pam_namespace se fait généralement via les fichiers de configuration PAM, tels que /etc/pam.d/system-login ou similaire.

OPTIONS

debug
Active les messages de débogage.
verbose
Active la sortie détaillée.
quiet
Supprime la plupart des messages d'erreur.
use_system_config
Utilise le fichier de configuration global du système (généralement trouvé dans /etc/security/namespace.conf) pour les mappages d'espaces de noms.
map_dir=/chemin/vers/repertoire
Spécifie un répertoire où les fichiers de configuration d'espaces de noms spécifiques à l'utilisateur peuvent être trouvés. Si cette option est utilisée, le module recherchera un fichier nommé .namespace dans le répertoire spécifié. Cela permet des configurations d'espaces de noms par utilisateur.

TYPES DE MODULES FOURNIS

Les types de modules suivants sont fournis :

session
Le type de module principal utilisé pour configurer et finaliser les espaces de noms.

VALEURS DE RETOUR

PAM_SUCCESS
Les opérations sur les espaces de noms ont réussi.
PAM_SESSION_ERR
Une erreur s'est produite lors de l'initialisation ou de la finalisation de la session.
PAM_BUF_ERR
Erreur liée à un tampon mémoire.
PAM_SYSTEM_ERR
Erreur système.

FICHIERS

/etc/security/namespace.conf
Fichier de configuration global du système pour pam_namespace.
~/.namespace
Fichier de configuration spécifique à l'utilisateur, généralement situé dans le répertoire personnel de l'utilisateur. Il est utilisé lorsque l'option map_dir est spécifiée.

EXEMPLES

Pour configurer pam_namespace pour créer un espace de noms réseau et monter des répertoires spécifiques pour un utilisateur lors de sa connexion, vous pourriez ajouter la ligne suivante à votre fichier /etc/pam.d/system-login :

session    required     pam_namespace.so use_system_config map_dir=/etc/namespace.d

Et dans /etc/security/namespace.conf, vous pourriez spécifier les créations d'espaces de noms :

# Configuration des espaces de noms pour tous les utilisateurs
# Créer un espace de noms réseau
netns mount
# Monter /data sur /srv/data dans le nouvel espace de noms réseau
mount /data /srv/data
# Monter /var/log sur /mnt/logs dans le nouvel espace de noms réseau
mount /var/log /mnt/logs
# Démontage à la sortie de session (géré implicitement par la finalisation PAM)

Pour les configurations spécifiques à l'utilisateur, créez un répertoire tel que /etc/namespace.d/nom_utilisateur et placez-y un fichier .namespace contenant les mêmes directives que namespace.conf.

VOIR AUSSI

pam.d(5), namespaces(7), mount(8)
