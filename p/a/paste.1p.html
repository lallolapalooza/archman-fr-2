PASTE(1P) Manuel du programmeur POSIX PASTE(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

paste — fusionne les lignes correspondantes ou suivantes de fichiers

SYNOPSIS

paste [-s] [-d liste] fichier...

DESCRIPTION

L'utilitaire paste concatène les lignes correspondantes des fichiers d'entrée donnés et écrit les lignes résultantes sur la sortie standard.

L'opération par défaut de paste concatène les lignes correspondantes des fichiers d'entrée. Le <nouvelle ligne> de chaque ligne sauf la dernière ligne du fichier d'entrée est remplacé par une <tabulation>.

Si une condition de fin de fichier est détectée sur un ou plusieurs fichiers d'entrée, mais pas sur tous les fichiers d'entrée, paste se comportera comme si des lignes vides étaient lues à partir des fichiers pour lesquels la fin de fichier a été détectée, sauf si l'option -s est spécifiée.

OPTIONS

L'utilitaire paste est conforme aux Définitions de base du volume POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

Les options suivantes doivent être supportées :

-d liste
Sauf si un caractère <backslash> apparaît dans liste, chaque caractère de liste est un élément spécifiant un caractère délimiteur. Si un caractère <backslash> apparaît dans liste, le caractère <backslash> et un ou plusieurs caractères qui le suivent constituent un élément spécifiant un caractère délimiteur tel que décrit ci-dessous. Ces éléments spécifient un ou plusieurs délimiteurs à utiliser, au lieu de la <tabulation> par défaut, pour remplacer la <nouvelle ligne> des lignes d'entrée. Les éléments de liste sont utilisés de manière cyclique ; c'est-à-dire que lorsque la liste est épuisée, le premier élément de la liste est réutilisé. Lorsque l'option -s est spécifiée :
*
La dernière <nouvelle ligne> d'un fichier ne doit pas être modifiée.
*
Le délimiteur doit être réinitialisé au premier élément de liste après le traitement de chaque opérande fichier.

Lorsque l'option -s n'est pas spécifiée :

*
Les caractères <nouvelle ligne> du fichier spécifié par le dernier opérande fichier ne doivent pas être modifiés.
*
Le délimiteur doit être réinitialisé au premier élément de liste chaque fois qu'une ligne est traitée à partir de chaque fichier.

Si un caractère <backslash> apparaît dans liste, lui et le caractère qui le suit doivent être utilisés pour représenter les caractères délimiteurs suivants :

\n
<nouvelle ligne>.
\t
<tabulation>.
\\
Caractère <backslash>.
\0
Chaîne vide (pas un caractère nul). Si '\0' est immédiatement suivi du caractère 'x', du caractère 'X', ou de tout caractère défini par le mot-clé LC_CTYPE digit (voir le volume Définitions de base de POSIX.1‐2017, Chapitre 7, Locale), les résultats ne sont pas spécifiés.

Si d'autres caractères suivent le <backslash>, les résultats ne sont pas spécifiés.

-s
Concatène toutes les lignes de chaque fichier d'entrée en une seule ligne de sortie par fichier, dans l'ordre de la commande. La <nouvelle ligne> de chaque ligne sauf la dernière ligne de chaque fichier d'entrée est remplacée par une <tabulation>, sauf indication contraire de l'option -d. Si un fichier d'entrée est vide, la ligne de sortie correspondante pour ce fichier consiste uniquement en un caractère <nouvelle ligne>.

OPÉRANDES

L'opérande suivant doit être supporté :

fichier
Un nom de chemin d'un fichier d'entrée. Si '-' est spécifié pour un ou plusieurs des fichiers, l'entrée standard est utilisée ; l'entrée standard est lue une ligne à la fois, circulairement, pour chaque instance de '-'. Les implémentations doivent supporter la fusion d'au moins 12 opérandes fichier.

STDIN

L'entrée standard est utilisée uniquement si un ou plusieurs opérandes fichier sont '-'. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Les fichiers d'entrée doivent être des fichiers texte, à l'exception du fait que les longueurs de ligne sont illimitées.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de paste :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS SYNCHRONES

Défaut.

STDOUT

Les lignes concaténées des fichiers d'entrée sont séparées par la <tabulation> (ou d'autres caractères sous le contrôle de l'option -d) et terminées par une <nouvelle ligne>.

STDERR

La sortie standard d'erreur est utilisée uniquement pour les messages diagnostiques.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes doivent être retournées :

 0
Achèvement réussi.
>0
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Si un ou plusieurs fichiers d'entrée ne peuvent pas être ouverts lorsque l'option -s n'est pas spécifiée, un message diagnostique est écrit sur la sortie standard d'erreur, mais aucune sortie n'est écrite sur la sortie standard. Si l'option -s est spécifiée, l'utilitaire paste fournit le comportement par défaut décrit dans la Section 1.4, Comportements par défaut des utilitaires.

Les sections suivantes sont informatives.

USAGE APPLICATIF

Lorsque les séquences d'échappement de l'argument d'option liste sont utilisées dans un script shell, elles doivent être mises entre guillemets ; sinon, le shell traite le <backslash> comme un caractère spécial.

Les implémentations historiques traitent '\x', où 'x' n'est pas dans cette liste, comme 'x', mais les futures implémentations sont libres d'étendre cette liste pour reconnaître d'autres échappements courants similaires à ceux acceptés par printf et d'autres utilitaires standard.

La plupart des utilitaires standard fonctionnent sur des fichiers texte. L'utilitaire cut peut être utilisé pour transformer des fichiers avec des longueurs de lignes arbitraires en un ensemble de fichiers texte contenant les mêmes données. L'utilitaire paste peut être utilisé pour créer (ou recréer) des fichiers avec des longueurs de lignes arbitraires. Par exemple, si file contient de longues lignes :

cut -b 1-500 -n file > file1
cut -b 501- -n file > file2

crée file1 (un fichier texte) avec des lignes ne dépassant pas 500 octets (plus le <newline>) et file2 qui contient le reste des données de file. Notez que file2 n'est pas un fichier texte s'il y a des lignes dans file qui dépassent 500 + {LINE_MAX} octets. Le fichier d'origine peut être recréé à partir de file1 et file2 en utilisant la commande :

paste -d "\0" file1 file2 > file

Les commandes :

paste -d "\0" ...
paste -d "" ...

ne sont pas nécessairement équivalentes ; la seconde n'est pas spécifiée par ce volume de POSIX.1-2017 et peut entraîner une erreur. Le construct '\0' est utilisé pour signifier "aucun séparateur" car les versions historiques de paste ne suivaient pas les directives de syntaxe, et la commande :

paste -d"" ...

ne pouvait pas être gérée correctement par getopt().

EXEMPLES

1.
Afficher un répertoire en quatre colonnes :
ls | paste - - - -
2.
Combiner des paires de lignes d'un fichier en lignes uniques :
paste -s -d "\t\n" file
