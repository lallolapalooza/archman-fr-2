PACMAN.CONF(5) Manuel Pacman PACMAN.CONF(5)

NOM

pacman.conf - fichier de configuration du gestionnaire de paquets pacman

SYNTAXE

/etc/pacman.conf

DESCRIPTION

Pacman, en utilisant libalpm(3), tentera de lire pacman.conf à chaque fois qu'il est invoqué. Ce fichier de configuration est divisé en sections ou dépôts. Chaque section définit un dépôt de paquets que pacman peut utiliser lors de la recherche de paquets en mode --sync. L'exception est la section options, qui définit les options globales.

Les commentaires ne sont supportés qu'en commençant une ligne par le symbole dièse (#). Les commentaires ne peuvent pas commencer au milieu d'une ligne.

EXEMPLE

#
# pacman.conf
#
[options]
NoUpgrade = etc/passwd etc/group etc/shadow
NoUpgrade = etc/fstab
[core]
Include = /etc/pacman.d/core
[custom]
Server = file:///home/pkgs

Note

Chaque directive doit être en CamelCase. Si la casse n'est pas respectée, la directive ne sera pas reconnue. Par exemple, noupgrade ou NOUPGRADE ne fonctionneront pas.

OPTIONS

RootDir = /chemin/vers/repertoire/racine

Définit le répertoire racine par défaut dans lequel pacman installera les paquets. Cette option est utilisée si vous souhaitez installer un paquet sur une partition montée temporairement qui est "possédée" par un autre système, ou pour une installation chroot. NOTE : Si le chemin de la base de données ou le fichier journal ne sont pas spécifiés soit sur la ligne de commande, soit dans pacman.conf(5), leur emplacement par défaut sera à l'intérieur de ce chemin racine.

DBPath = /chemin/vers/repertoire/db

Remplace l'emplacement par défaut du répertoire de base de données de premier niveau. Le chemin par défaut est /var/lib/pacman/. La plupart des utilisateurs n'auront pas besoin de définir cette option. NOTE : si elle est spécifiée, il s'agit d'un chemin absolu et le chemin racine n'est pas automatiquement ajouté.

CacheDir = /chemin/vers/repertoire/cache

Remplace l'emplacement par défaut du répertoire de cache des paquets. Le chemin par défaut est /var/cache/pacman/pkg/. Plusieurs répertoires de cache peuvent être spécifiés, et ils sont essayés dans l'ordre où ils sont listés dans le fichier de configuration. Si un fichier n'est pas trouvé dans un répertoire de cache, il sera téléchargé dans le premier répertoire de cache accessible en écriture. NOTE : il s'agit d'un chemin absolu, le chemin racine n'est pas automatiquement ajouté.

HookDir = /chemin/vers/repertoire/hooks

Ajoute des répertoires à rechercher pour les hooks alpm en plus du répertoire de hooks système (/usr/share/libalpm/hooks/). Le chemin par défaut est /etc/pacman.d/hooks. Plusieurs répertoires peuvent être spécifiés, les hooks dans les répertoires ultérieurs ayant priorité sur les hooks dans les répertoires précédents. NOTE : il s'agit d'un chemin absolu, le chemin racine n'est pas automatiquement ajouté. Pour plus d'informations sur les hooks alpm, voir alpm-hooks(5).

GPGDir = /chemin/vers/repertoire/gpg

Remplace l'emplacement par défaut du répertoire contenant les fichiers de configuration pour GnuPG. Le chemin par défaut est /etc/pacman.d/gnupg/. Ce répertoire doit contenir deux fichiers : pubring.gpg et trustdb.gpg. pubring.gpg contient les clés publiques de tous les packagers. trustdb.gpg contient une base de données de confiance, qui spécifie que les clés sont authentiques et fiables. NOTE : il s'agit d'un chemin absolu, le chemin racine n'est pas automatiquement ajouté.

LogFile = /chemin/vers/fichier/journal

Remplace l'emplacement par défaut du fichier journal de pacman. Le chemin par défaut est /var/log/pacman.log. Il s'agit d'un chemin absolu et le répertoire racine n'est pas ajouté.

HoldPkg = paquet ...

Si un utilisateur tente de --remove un paquet listé dans HoldPkg, pacman demandera une confirmation avant de continuer. Les motifs de style shell (glob) sont autorisés.

IgnorePkg = paquet ...

Indique à pacman d'ignorer les mises à jour de ce paquet lors d'une opération --sysupgrade. Les motifs de style shell (glob) sont autorisés.

IgnoreGroup = groupe ...

Indique à pacman d'ignorer les mises à jour de tous les paquets de ce groupe lors d'une opération --sysupgrade. Les motifs de style shell (glob) sont autorisés.

Include = /chemin/vers/fichier/config

Inclut un autre fichier de configuration. Ce fichier peut inclure des dépôts ou des options de configuration générales. Les caractères génériques dans les chemins spécifiés seront développés selon les règles de glob(7).

Architecture = auto &| i686 &| x86_64 | ...

Si définie, pacman n'autorisera l'installation que des paquets ayant les architectures données (par ex. i686, x86_64, etc.). La valeur spéciale auto utilisera l'architecture du système, obtenue via "uname -m". Si non définie, aucune vérification d'architecture n'est effectuée. NOTE : les paquets avec l'architecture spéciale any peuvent toujours être installés, car ils sont conçus pour être indépendants de l'architecture.

XferCommand = /chemin/vers/commande %u [%o]

Si elle est définie, un programme externe sera utilisé pour télécharger tous les fichiers distants. Toutes les occurrences de %u seront remplacées par l'URL de téléchargement. S'il est présent, les occurrences de %o seront remplacées par le nom du fichier local, plus une extension ".part", ce qui permet à des programmes comme wget de reprendre correctement les téléchargements de fichiers.

Cette option est utile pour les utilisateurs qui rencontrent des problèmes avec le support HTTP/FTP intégré, ou qui ont besoin du support proxy plus avancé fourni par des utilitaires comme wget.

NoUpgrade = fichier ...

Tous les fichiers listés avec une directive NoUpgrade ne seront jamais touchés lors d'une installation/mise à niveau de paquet, et les nouveaux fichiers seront installés avec une extension .pacnew. Ces fichiers font référence aux fichiers de l'archive du paquet, donc n'incluez pas la barre oblique initiale (le RootDir) lors de leur spécification. Les motifs de style shell (glob) sont autorisés. Il est possible d'inverser les correspondances en préfixant un fichier avec un point d'exclamation. Les fichiers inversés entraîneront la réintégration dans la liste blanche des fichiers précédemment exclus. Les correspondances ultérieures remplaceront les précédentes. Un point d'exclamation ou une barre oblique littérale initiale doit être échappé.

NoExtract = fichier ...

Tous les fichiers listés avec une directive NoExtract ne seront jamais extraits d'un paquet vers le système de fichiers. Cela peut être utile lorsque vous ne souhaitez pas qu'une partie d'un paquet soit installée. Par exemple, si votre répertoire racine httpd utilise un index.php, vous ne voudriez pas que le fichier index.html soit extrait du paquet apache. Ces fichiers font référence aux fichiers de l'archive du paquet, donc n'incluez pas la barre oblique initiale (le RootDir) lors de leur spécification. Les motifs de style shell (glob) sont autorisés. Il est possible d'inverser les correspondances en préfixant un fichier avec un point d'exclamation. Les fichiers inversés entraîneront la réintégration dans la liste blanche des fichiers précédemment exclus. Les correspondances ultérieures remplaceront les précédentes. Un point d'exclamation ou une barre oblique littérale initiale doit être échappé.

CleanMethod = KeepInstalled &| KeepCurrent

Si défini sur KeepInstalled (par défaut), l'opération -Sc nettoiera les paquets qui ne sont plus installés (non présents dans la base de données locale). Si défini sur KeepCurrent, -Sc nettoiera les paquets obsolètes (non présents dans une base de données de synchronisation). Le second comportement est utile lorsque le cache des paquets est partagé entre plusieurs machines, où les bases de données locales sont généralement différentes, mais les bases de données de synchronisation utilisées peuvent être les mêmes. Si les deux valeurs sont spécifiées, les paquets ne sont nettoyés que s'ils ne sont pas installés localement et ne sont pas présents dans une base de données de synchronisation connue.

SigLevel = ...

Définit le niveau de vérification de signature par défaut. Pour plus d'informations, voir Vérification des signatures de paquets et de bases de données ci-dessous.

LocalFileSigLevel = ...

Définit le niveau de vérification de signature pour l'installation de paquets à l'aide de l'opération "-U" sur un fichier local. Utilise la valeur de SigLevel par défaut.

RemoteFileSigLevel = ...

Définit le niveau de vérification de signature pour l'installation de paquets à l'aide de l'opération "-U" sur une URL de fichier distante. Utilise la valeur de SigLevel par défaut.

UseSyslog

Journalise les messages d'action via syslog(). Cela insérera des entrées de journal dans /var/log/messages ou l'équivalent.

Color

Active automatiquement les couleurs uniquement lorsque pacman est exécuté...

NoProgressBar

Désactive les barres de progression. Ceci est utile pour les terminaux qui ne prennent pas en charge les caractères d'échappement.

CheckSpace

Effectue une vérification approximative de l'espace disque disponible avant d'installer des paquets.

VerbosePkgLists

Affiche le nom, la version et la taille des paquets cibles formatés en tableau pour les opérations de mise à niveau, de synchronisation et de suppression.

DisableDownloadTimeout

Désactive les valeurs par défaut pour la limite de faible vitesse et le délai d'attente des téléchargements. Utilisez ceci si vous rencontrez des problèmes pour télécharger des fichiers avec un proxy et/ou une passerelle de sécurité.

ParallelDownloads = ...

Spécifie le nombre de flux de téléchargement simultanés. La valeur doit être un entier positif. Si cette option de configuration n'est pas définie, un seul flux de téléchargement est utilisé (c'est-à-dire que les téléchargements s'effectuent séquentiellement).

DownloadUser = nom d'utilisateur

Spécifie l'utilisateur vers lequel basculer pour télécharger des fichiers. Si cette option de configuration n'est pas définie, les téléchargements sont effectués en tant qu'utilisateur exécutant pacman.

DisableSandbox

Désactive le bac à sable par défaut appliqué au processus de téléchargement de fichiers sur les systèmes Linux. Utile si vous rencontrez des échecs liés à landlock lors du téléchargement de fichiers lorsque vous utilisez un noyau Linux qui ne prend pas en charge cette fonctionnalité.

SECTIONS RÉPERTOIRE

Chaque section de répertoire définit un nom de section et au moins un emplacement où les paquets peuvent être trouvés. Le nom de la section est défini par la chaîne entre crochets (les deux ci-dessus sont core et custom). Les noms de répertoires doivent être uniques et le nom local est réservé à la base de données des paquets installés. Les emplacements sont définis avec la directive Server et suivent une structure de nommage d'URL. Si vous souhaitez utiliser un répertoire local, vous pouvez spécifier le chemin complet avec le préfixe “file://”, comme indiqué ci-dessus.

Une façon courante de définir les emplacements de base de données utilise la directive Include. Pour chaque répertoire défini dans le fichier de configuration, une seule directive Include peut contenir un fichier qui liste les serveurs de ce répertoire.

[core]
# utiliser ce serveur en premier
Server = ftp://ftp.archlinux.org/$repo/os/$arch
# ensuite utiliser les serveurs tels que définis dans la mirrorlist ci-dessous
Include = {sysconfdir}/pacman.d/mirrorlist

L'ordre des répertoires dans les fichiers de configuration est important ; les répertoires listés en premier auront la priorité sur ceux listés plus tard dans le fichier lorsque les paquets de deux répertoires auront des noms identiques, quelle que soit la version.

Include = chemin

Inclut un autre fichier de configuration. Ce fichier peut inclure des répertoires ou des options de configuration générales. Les caractères génériques dans les chemins spécifiés seront développés selon les règles de glob(7).

CacheServer = url

Une URL complète vers un emplacement où les paquets et les signatures (si disponibles) pour ce répertoire peuvent être trouvés. Les serveurs cache seront essayés avant tout serveur non cache, ne seront pas supprimés du pool de serveurs en cas d'erreurs de téléchargement 404, et ne seront pas utilisés pour les fichiers de base de données.

Server = url

Une URL complète vers un emplacement où la base de données, les paquets et les signatures (si disponibles) pour ce répertoire peuvent être trouvés.

Lors de l'analyse, pacman définira la variable $repo au nom de la section courante. Ceci est souvent utilisé dans les fichiers spécifiés à l'aide de la directive Include afin que tous les répertoires puissent utiliser le même mirrorfile. pacman définit également la variable $arch sur la première (ou seule) valeur de l'option Architecture, de sorte que le même mirrorfile puisse même être utilisé pour différentes architectures.

SigLevel = ...

Définit le niveau de vérification de signature pour ce répertoire. Pour plus d'informations, voir Vérification des signatures de paquets et de bases de données ci-dessous.

Usage = ...

Définit le niveau d'utilisation pour ce répertoire. Cette option prend une liste de jetons qui doivent être au moins l'un des suivants :

Sync

Active les actualisations pour ce répertoire.

Search

Active la recherche pour ce répertoire.

Install

Active l'installation de paquets à partir de ce répertoire lors d'une opération --sync.

Upgrade

Permet à ce répertoire d'être une source valide de paquets lors de l'exécution d'un --sysupgrade.

All

Active toutes les fonctionnalités ci-dessus pour le répertoire. C'est la valeur par défaut si rien n'est spécifié.

Notez qu'un répertoire activé peut être opéré explicitement, quel que soit le niveau d'utilisation défini.

VÉRIFICATION DES SIGNATURES DE PAQUETS ET DE BASES DE DONNÉES

La directive SigLevel est valide dans les sections [options] et de répertoire. Si elle est utilisée dans [options], elle définit une valeur par défaut pour tout répertoire qui ne fournit pas le réglage.

•Si défini sur Never, aucune vérification de signature n'aura lieu.
•Si défini sur Optional, les signatures seront vérifiées lorsqu'elles sont présentes, mais les bases de données et paquets non signés seront également acceptés.
•Si défini sur Required, des signatures seront requises sur tous les paquets et bases de données.

Alternativement, vous pouvez obtenir un contrôle plus granulaire en combinant certaines des options et préfixes décrits ci-dessous. Toutes les options dans un fichier de configuration sont traitées de haut en bas, de gauche à droite, où les options ultérieures remplacent et/ou complètent les précédentes. Si SigLevel est spécifié dans une section de répertoire, la valeur de départ est celle de la section [options], ou la valeur par défaut système intégrée comme indiqué ci-dessous si elle n'est pas spécifiée.

Les options sont divisées en deux groupes principaux, décrits ci-dessous. Les termes utilisés tels que « confiance marginale » sont des termes utilisés par GnuPG, pour plus d'informations veuillez consulter gpg(1).

Quand vérifier

Ces options contrôlent si et quand les vérifications de signature doivent avoir lieu.

Never

Toute vérification de signature est supprimée, même si des signatures sont présentes.

Optional (par défaut)

Les signatures sont vérifiées si elles sont présentes ; l'absence de signature n'est pas une erreur. Une signature invalide est une erreur fatale, tout comme une signature provenant d'une clé non présente dans le trousseau.

Required

Les signatures sont requises ; l'absence de signature ou une signature invalide est une erreur fatale, tout comme une signature provenant d'une clé non présente dans le trousseau.

Ce qui est autorisé

Ces options contrôlent quelles signatures sont considérées comme admissibles. Notez qu'aucune de ces options ne permet l'acceptation de signatures invalides ou expirées, ou celles provenant de clés révoquées.

TrustedOnly (par défaut)

Si une signature est vérifiée, elle doit être dans le trousseau et entièrement fiable ; une confiance marginale ne répond pas à ce critère.

TrustAll

Si une signature est vérifiée, elle doit être dans le trousseau, mais il n'est pas nécessaire qu'un niveau de confiance lui soit attribué (par exemple, confiance inconnue ou marginale).

Les options des deux groupes peuvent en outre être préfixées par Package ou Database, ce qui fera qu'elles ne prendront effet que sur le type d'objet spécifié. Par exemple, PackageTrustAll autoriserait les signatures de niveau de confiance marginal ou inconnu pour les paquets.

La valeur par défaut intégrée est la suivante :

SigLevel = Optional TrustedOnly

UTILISER VOTRE PROPRE RÉPERTOIRE

Si vous avez de nombreux paquets personnalisés, il est souvent plus facile de générer votre propre répertoire local personnalisé que de les installer tous avec l'option --upgrade. Tout ce dont vous avez besoin est de générer une base de données de paquets compressée dans le répertoire contenant ces paquets afin que pacman puisse la trouver lorsqu'il est exécuté avec --refresh.

repo-add /home/pkgs/custom.db.tar.gz /home/pkgs/*.pkg.tar.gz

La commande ci-dessus générera une base de données compressée nommée /home/pkgs/custom.db.tar.gz. Notez que la base de données doit être du formulaire défini dans le fichier de configuration et {ext} est un type de compression valide tel que documenté dans repo-add(8). C'est tout ! Configurez maintenant votre section personnalisée dans le fichier de configuration comme indiqué dans l'exemple de configuration ci-dessus. Pacman utilisera désormais votre répertoire de paquets. Si vous ajoutez de nouveaux paquets au répertoire, n'oubliez pas de régénérer la base de données et d'utiliser l'option --refresh de pacman.

Pour plus d'informations sur la commande repo-add, consultez « repo-add --help » ou repo-add(8).

NAME

pacman.conf(5) - Pacman package manager configuration file

SYNOPSIS

/etc/pacman.conf

DESCRIPTION

The pacman.conf file contains configuration options for pacman(8). Options are grouped into sections, identified by square brackets. The main sections are GLOBAL OPTIONS, REPOSITORY SECTIONS, and PACKAGE AND DATABASE SIGNATURE CHECKING.

The configuration file is parsed from top to bottom. Later definitions override earlier ones.

Comments start with a hash character (#) and extend to the end of the line. Blank lines are ignored.

GLOBAL OPTIONS

These options are defined in the main section of the configuration file.

CacheDir
Specifies the directory where packages are stored after they are downloaded. The default is /var/cache/pacman/pkg/.
Color
Enables or disables colorized output. This is a boolean option. If enabled, output is colorized. Disabled by default.
Confirm
Enables or disables confirmation prompts for all operations. This is a boolean option. If enabled, pacman will prompt before performing any action. Disabled by default.
DBPath
Specifies the directory containing the package database. The default is /var/lib/pacman/.
Gzip
Sets the compression level for gzip compression. This is an integer option. The default is 9.
HoldPkg
Specifies packages that should not be upgraded. This is a list of package names. Use pacman -Syu to upgrade all packages except those listed here.
IgnorePkg
Specifies packages that should be ignored during upgrades. This is a list of package names. Use pacman -Su to upgrade all packages except those listed here.
LogFile
Specifies the log file for pacman operations. The default is /var/log/pacman.log.
NoProgressBar
Disables the progress bar shown during downloads and installations. This is a boolean option. Disabled by default.
Overwrite
Specifies files that pacman is allowed to overwrite. This is a list of file paths. Use with caution.
ParallelDownloads
Specifies the number of packages to download in parallel. Defaults to 5.
SigLevel
Sets the package signature checking level. This is a string option. See PACKAGE AND DATABASE SIGNATURE CHECKING for details.
SkipHash
Specifies files for which pacman should not check the integrity. This is a list of file paths. Use with caution.
SyncFirst
Specifies packages that should be synchronized before any other package. This is a list of package names.
TotalDownload
Enables or disables the display of the total download size. This is a boolean option. Disabled by default.
UseSyslog
Specifies whether to log pacman operations to syslog. This is a boolean option. Disabled by default.
XferCommand
Specifies a command to use for downloading packages. This is a string option. The command must accept the URL and the output filename as arguments. See pacman man page for more details.

REPOSITORY SECTIONS

Each repository is defined in its own section. The section name is the repository name, enclosed in square brackets.

Include
Specifies a list of additional configuration files to include. This is a list of file paths.
Include
Specifies a list of package names to include from this repository. This is a list of package names.
Map
Specifies a URL or a local path to the repository database file. This is a string option.
NoExtract
Specifies a list of package names that should not be extracted. This is a list of package names.
NoSign
Specifies a list of packages that should not be signed. This is a list of package names.
Server
Specifies a URL or a local path to the repository. This is a string option. Multiple Server lines can be specified for a single repository.

The following example defines a repository named \"core\" with a server located at http://mirror.example.com/archlinux/$arch:

[core] SigLevel = Optional TrustAll Server = http://mirror.example.com/archlinux/$arch

PACKAGE AND DATABASE SIGNATURE CHECKING

The SigLevel option controls package signature checking. It can be set globally or per repository. The available options are:

Optional
Signature checking is optional.
Required
Signature checking is required.
Never
Signature checking is never performed.
DatabaseOptional
Database signature checking is optional.
DatabaseRequired
Database signature checking is required.
PackageOptional
Package signature checking is optional.
PackageRequired
Package signature checking is required.
TrustAll
Trust all signatures. Use with extreme caution.

The default SigLevel is Required DatabaseOptional.

To enable signature checking, you need to import the public keys of the repository maintainers using:

pacman-key --recv-keys <key_id>
pacman-key --lsign-key <key_id>

USING YOUR OWN REPOSITORY

To create and use your own repository, you need to:

  1. Create a directory for your repository.
  2. Place your compiled packages in that directory.
  3. Generate a repository database file using repo-add:

    repo-add /path/to/your/repo/yourrepo.db.tar.gz /path/to/your/repo/*.pkg.tar.zst

  4. Add a repository section to your pacman.conf:

    [yourrepo] SigLevel = Optional TrustAll Server = file:///path/to/your/repo/

  5. Run pacman -Sy to refresh the package database.

EXAMPLE

A typical pacman.conf file might look like this:

# # /etc/pacman.conf # # # Global options # [options] # The following paths will be uncommented if you want to use # the standard locations for databases and logs. #DBPath = /var/lib/pacman/ #LogFile = /var/log/pacman.log #MaxParallelDownloads = 5 #Color #ParallelDownloads = 5 # # Repositories # [core] Include = /etc/pacman.d/mirrorlist [extra] Include = /etc/pacman.d/mirrorlist [community] Include = /etc/pacman.d/mirrorlist # For the multilib repository, see the wiki: # https://wiki.archlinux.org/index.php/Multilib #[multilib] #Include = /etc/pacman.d/mirrorlist
