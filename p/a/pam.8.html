NOM

PAM, pam - Modules d'authentification enfichables pour Linux

DESCRIPTION

Ce manuel est destiné à offrir une introduction rapide à Linux-PAM. Pour plus d'informations, le lecteur est dirigé vers le guide d'administration du système Linux-PAM.

Linux-PAM est un système de bibliothèques qui gèrent les tâches d'authentification des applications (services) sur le système. La bibliothèque fournit une interface stable et générale (Application Programming Interface - API) à laquelle les programmes d'octroi de privilèges (tels que login(1) et su(1)) font appel pour effectuer les tâches d'authentification standard.

La caractéristique principale de l'approche PAM est que la nature de l'authentification est configurable dynamiquement. En d'autres termes, l'administrateur système est libre de choisir comment les applications individuelles fournissant des services authentifieront les utilisateurs. Cette configuration dynamique est définie par le contenu du fichier de configuration unique de Linux-PAM, /etc/pam.conf. Alternativement et de préférence, la configuration peut être définie par des fichiers de configuration individuels situés dans un répertoire pam.d. La présence de ce répertoire provoquera l'ignorance de /etc/pam.conf par Linux-PAM.

Les fichiers de configuration PAM fournis par le fournisseur peuvent être installés dans le répertoire système /usr/lib/pam.d/ ou dans un répertoire spécifique au fournisseur configurable au lieu du répertoire de configuration de la machine /etc/pam.d/. Si aucun fichier de configuration de la machine n'est trouvé, le fichier fourni par le fournisseur est utilisé. Tous les fichiers dans /etc/pam.d/ remplacent les fichiers portant le même nom dans d'autres répertoires.

Du point de vue de l'administrateur système, pour qui ce manuel est fourni, il n'est pas d'une importance primordiale de comprendre le comportement interne de la bibliothèque Linux-PAM. Le point important à reconnaître est que le ou les fichiers de configuration définissent la connexion entre les applications (services) et les modules d'authentification enfichables (PAMs) qui effectuent les tâches d'authentification réelles.

Linux-PAM sépare les tâches d'authentification en quatre groupes de gestion indépendants : gestion des comptes ; gestion de l'authentification ; gestion des mot de passe ; et gestion de la session. (Nous mettons en évidence les abréviations utilisées pour ces groupes dans le fichier de configuration.)

En termes simples, ces groupes traitent différents aspects de la demande typique d'un utilisateur pour un service restreint :

compte - fournissent des services de vérification de compte : le mot de passe de l'utilisateur a-t-il expiré ?; cet utilisateur est-il autorisé à accéder au service demandé ?

authentification - authentifie un utilisateur et configure les identifiants de l'utilisateur. Généralement, cela se fait via une demande de défi-réponse à laquelle l'utilisateur doit satisfaire : si vous êtes qui vous prétendez être, veuillez entrer votre mot de passe. Toutes les authentifications ne sont pas de ce type, il existe des schémas d'authentification basés sur le matériel (comme l'utilisation de cartes à puce et de dispositifs biométriques), avec des modules appropriés, ceux-ci peuvent être substitués sans problème aux approches d'authentification plus standard - telle est la flexibilité de Linux-PAM.

mot de passe - ce groupe est responsable de la mise à jour des mécanismes d'authentification. Généralement, ces services sont fortement couplés à ceux du groupe auth. Certains mécanismes d'authentification se prêtent bien à être mis à jour avec une telle fonction. L'accès standard basé sur le mot de passe UN*X est l'exemple évident : veuillez entrer un mot de passe de remplacement.

session - ce groupe de tâches couvre les choses qui devraient être faites avant qu'un service ne soit accordé et après qu'il soit retiré. Ces tâches comprennent la maintenance des pistes d'audit et le montage du répertoire personnel de l'utilisateur. Le groupe de gestion de session est important car il fournit des crochets d'ouverture et de fermeture pour que les modules affectent les services disponibles pour un utilisateur.

FICHIERS

/etc/pam.conf

le fichier de configuration

/etc/pam.d

le répertoire de configuration de Linux-PAM. Généralement, si ce répertoire est présent, le fichier /etc/pam.conf est ignoré.

/usr/lib/pam.d

le répertoire de configuration du fournisseur de Linux-PAM. Les fichiers dans /etc/pam.d remplacent les fichiers portant le même nom dans ce répertoire.

ERREURS

Généralement, les erreurs générées par le système de bibliothèques Linux-PAM seront écrites dans syslog(3).

CONFORMITE

DCE-RFC 86.0, octobre 1995. Contient des fonctionnalités supplémentaires, mais reste rétrocompatible avec cette RFC.
