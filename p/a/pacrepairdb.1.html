PACREPAIRDB(1) pacrepairdb PACREPAIRDB(1)

NOM

pacrepairdb - réparer les entrées corrompues de la base de données

SYNTAXE

pacrepairdb [options] <paquet>...
pacrepairdb (--help|--version)

DESCRIPTION

Tente de réparer les entrées de paquets brisées dans la base de données de libalpm. Tous les fichiers essentiels manquants seront créés et les paquets seront réinstallés depuis le cache.

Si stdin n'est pas connecté à un terminal, les noms des paquets seront lus depuis stdin.

OPTIONS

--cachedir=chemin
Définit un chemin de répertoire de cache alternatif.
--config=chemin
Définit un chemin de fichier de configuration alternatif.
--dbonly
Applique les modifications à la base de données sans extraire ni supprimer réellement de paquets.
--dbpath=chemin
Définit un chemin de base de données alternatif.
--debug
Affiche des informations de débogage supplémentaires.
--hookdir
Ajoute des répertoires de hooks utilisateurs supplémentaires.
--logfile=chemin
Définit un chemin de fichier journal alternatif.
--no-confirm
Accepte les réponses par défaut à toutes les invites.
--no-scriptlet
N'exécute pas les scripts d'installation des paquets.
--no-hooks
N'exécute pas les hooks de transaction.
--no-timeout
Désactive les timeouts de faible vitesse pour les téléchargements.
--print-only
Affiche les paquets à réparer et les paquets du cache à utiliser, puis quitte.
--root=chemin
Définit une racine d'installation alternative.
--sysroot=chemin
Définit une racine système alternative. Voir pacutils-sysroot(7).
--verbose
Affiche des informations de progression supplémentaires.
--help
Affiche les informations d'utilisation et quitte.
--version
Affiche les informations de version et quitte.

EXEMPLES

Trouver et réinstaller les paquets brisés :

paccheck --list-broken --files --file-properties --db-files --require-mtree | pacrepairdb

MISE EN GARDE

pacrepairdb s'attend à ce que tous les paquets en cours de réparation soient mis en cache. Les paquets mis en cache qui correspondent au nom et à la version d'un paquet installé sont supposés être le même paquet. Aucune tentative n'est faite pour valider les paquets mis en cache. Si un cache contient un paquet qui ne correspond pas au paquet installé, mais qui a néanmoins le même nom et la même version, pacrepairdb l'installera aveuglément, aggravant ainsi les problèmes de base de données.

pacrepairdb ne recherche pas les fichiers orphelins restants. Il est de la responsabilité de l'utilisateur de localiser et de gérer les fichiers orphelins.

pacrepairdb détermine s'il faut lire les noms des paquets depuis stdin en utilisant une vérification naïve avec isatty(3). Si pacrepairdb est appelé dans un environnement, tel qu'une fonction shell ou un script utilisé dans un pipeline, où stdin n'est pas connecté à un terminal mais ne contient pas de noms de paquets à réparer, pacrepairdb devrait être appelé avec stdin fermé. Pour les shells compatibles POSIX, cela peut être fait avec "<&-".
