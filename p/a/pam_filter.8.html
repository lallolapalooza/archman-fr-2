NOM

pam_filter - module de filtrage PAM

SYNTAXE

pam_filter.so [debug] [new_term] [non_term] run1|run2 filtre [...]

DESCRIPTION

Ce module est destiné à servir de plateforme pour fournir l'accès à toutes les entrées/sorties qui transitent entre l'utilisateur et l'application. Il ne convient qu'aux applications basées sur tty et (stdin/stdout).

Pour fonctionner, ce module nécessite que des filtres soient installés sur le système. Le filtre unique fourni avec le module transpose simplement les lettres majuscules et minuscules dans les flux d'entrée et de sortie. (Cela peut être très agaçant et n'est pas idéal pour les éditeurs basés sur termcap).

Chaque composant du module a le potentiel d'invoquer le filtre désiré. Le filtre est toujours appelé avec execv(2) avec les privilèges de l'application appelante et non ceux de l'utilisateur. Pour cette raison, il ne peut généralement pas être arrêté par l'utilisateur sans fermer sa session.

OPTIONS

debug

Imprime des informations de débogage.

new_term

L'action par défaut du filtre est de définir l'élément PAM_TTY pour indiquer le terminal que l'utilisateur utilise pour se connecter à l'application. Cet argument indique que le filtre doit définir PAM_TTY sur le pseudo-terminal filtré.

non_term

n'essaie pas de définir l'élément PAM_TTY.

runX

Afin que le module puisse invoquer un filtre, il doit savoir quand l'invoquer. Cet argument est nécessaire pour indiquer au filtre quand cela doit se produire.

Les valeurs permises pour X sont 1 et 2. Celles-ci indiquent le moment précis où le filtre doit être exécuté. Pour comprendre ce concept, il sera utile d'avoir lu la page de manuel de pam(3). Essentiellement, pour chaque groupe de gestion, il existe jusqu'à deux manières d'appeler les fonctions du module. Dans le cas des composants authentication et session, il existe en fait deux fonctions distinctes. Pour le cas de l'authentification, ces fonctions sont pam_authenticate(3) et pam_setcred(3), ici run1 signifie exécuter le filtre depuis la fonction pam_authenticate et run2 signifie exécuter le filtre depuis pam_setcred. Dans le cas des modules de session, run1 implique que le filtre est invoqué à l'étape de pam_open_session(3), et run2 pour pam_close_session(3).

Pour le cas du composant de compte. Soit run1, soit run2 peuvent être utilisés.

Pour le cas du composant mot de passe, run1 est utilisé pour indiquer que le filtre est exécuté lors de la première occurrence de pam_chauthtok(3) (la phase PAM_PRELIM_CHECK) et run2 est utilisé pour indiquer que le filtre est exécuté lors de la seconde occurrence (la phase PAM_UPDATE_AUTHTOK).

filtre

Le chemin complet du filtre à exécuter et les arguments de ligne de commande que le filtre pourrait attendre.

TYPES DE MODULES FOURNIS

Tous les types de modules (auth, account, password et session) sont fournis.

VALEURS DE RETOUR

PAM_SUCCESS

Le nouveau filtre a été défini avec succès.

PAM_ABORT

Erreur critique, abandon immédiat.

EXEMPLES

Ajoutez la ligne suivante à /etc/pam.d/login pour voir comment configurer login pour transposer les lettres majuscules et minuscules une fois que l'utilisateur s'est connecté :

        session required pam_filter.so run1 /lib/security/pam_filter/upperLOWER

VOIR AUSSI

pam.conf(5), pam.d(5), pam(8)
