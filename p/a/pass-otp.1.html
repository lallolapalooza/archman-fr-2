PASS-OTP(1) Manuel des commandes générales PASS-OTP(1)

NOM

pass-otp - Une extension de pass(1) pour gérer les jetons à mot de passe à usage unique (OTP).

SYNTAXE

pass otp [ COMMANDE ] [ OPTIONS ]... [ ARGUMENTS ]...

DESCRIPTION

pass-otp étend l'utilitaire pass(1) avec la commande otp pour ajouter des secrets OTP, générer des codes OTP et afficher les URI de clé secrète en utilisant le schéma standard otpauth://.

Si aucune COMMANDE n'est spécifiée, la COMMANDE par défaut est code.

COMMANDES

otp code [ --clip, -c ] nom-pass

Génère et affiche un code OTP à partir de la clé secrète stockée dans nom-pass en utilisant oathtool(1). Si --clip ou -c est spécifié, n'affiche pas le code mais le copie dans le presse-papiers en utilisant xclip(1), puis restaure le presse-papiers après 45 secondes (ou PASSWORD_STORE_CLIP_TIME). Cette commande est alternativement nommée show.

otp insert [ --force, -f ] [ --echo, -e ] [ [ --secret, -s ] [ --issuer, -i émetteur ] [ --account, -a compte ] ] [ nom-pass ]

Demande et insère un nouveau secret OTP dans le magasin de mots de passe à nom-pass.

Si --secret est spécifié, demande la valeur du secret, en supposant l'algorithme SHA1, une période de 30 secondes et 6 chiffres OTP. L'un ou les deux de émetteur et compte doivent également être spécifiés.

Si --secret n'est pas spécifié, demande une URI de clé ; voir la documentation à https://github.com/google/google-authenticator/wiki/Key-Uri-Format pour la spécification de l'URI de clé.

Le secret est consommé depuis l'entrée standard ; spécifiez --echo ou -e pour afficher l'entrée lors de l'exécution de cette commande de manière interactive. Si nom-pass n'est pas spécifié, convertit le libellé d'URI émetteur:nom-compte en un chemin sous la forme émetteur/nom-compte. Demande avant d'écraser un secret existant, sauf si --force ou -f est spécifié. Cette commande est alternativement nommée add.

otp append [ --force, -f ] [ --echo, -e ] [ [ --secret, -s ] [ --issuer, -i émetteur ] [ --account, -a compte ] ] nom-pass

Ajoute un secret OTP à la fin du mot de passe stocké dans nom-pass, en conservant les lignes existantes.

Si --secret est spécifié, demande la valeur du secret, en supposant l'algorithme SHA1, une période de 30 secondes et 6 chiffres OTP. L'un ou les deux de émetteur et compte doivent également être spécifiés.

Si --secret n'est pas spécifié, demande une URI de clé ; voir la documentation à https://github.com/google/google-authenticator/wiki/Key-Uri-Format pour la spécification de l'URI de clé.

L'URI est consommée depuis l'entrée standard ; spécifiez --echo ou -e pour afficher l'entrée lors de l'exécution de cette commande de manière interactive. Demande avant d'écraser un secret existant, sauf si --force ou -f est spécifié.

otp uri [ --clip, -c | --qrcode, -q ] nom-pass

Affiche l'URI de clé stockée dans nom-pass sur la sortie standard. Si --clip ou -c est spécifié, n'affiche pas l'URI mais la copie dans le presse-papiers en utilisant xclip(1), puis restaure le presse-papiers après 45 secondes (ou PASSWORD_STORE_CLIP_TIME). Si --qrcode ou -q est spécifié, n'affiche pas l'URI mais affiche un code QR en utilisant qrencode(1) soit dans le terminal, soit graphiquement si supporté.

otp validate uri

Teste la validité d'une chaîne URI selon le format d'URI de clé. Pour plus d'informations sur ce format, voir la documentation à https://github.com/google/google-authenticator/wiki/Key-Uri-Format.

OPTIONS

help, -h, --help
Affiche le message d'utilisation.

VOIR AUSSI

pass(1), qrencode(1), zbarimg(1)
