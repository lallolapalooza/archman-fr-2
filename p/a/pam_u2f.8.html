PAM_U2F(8) Manuel du module PAM U2F PAM_U2F(8)

NOM

pam_u2f - Module pour l'authentification U2F

SYNTAXE

pam_u2f [...]

DESCRIPTION

Le module fournit l'authentification U2F contre les Yubikeys et autres authentificateurs compatibles.

OPTIONS

debug

Active la sortie de débogage

debug_file

Nom du fichier où écrire les messages de débogage. Si ce fichier est manquant, rien ne sera consigné. Ce fichier régulier doit être créé par l'utilisateur ou doit exister et être un fichier régulier pour que quelque chose y soit consigné. Il n'est pas créé par pam-u2f intentionnellement (pour des raisons de sécurité). Ce nom de fichier peut alternativement être défini sur "stderr" (par défaut), "stdout", ou "syslog".

origin=origine

Définit l'ID de la partie prenante pour la procédure d'authentification FIDO. Si aucune valeur n'est spécifiée, l'identifiant "pam://$HOSTNAME" est utilisé.

appid=appid

Définit l'ID de l'application pour la procédure d'authentification FIDO. Si aucune valeur n'est spécifiée, la même valeur que celle utilisée pour l'origine est prise ("pam://$HOSTNAME" si l'origine n'est pas non plus spécifiée). Ce réglage n'est applicable qu'aux identifiants FIDO créés avec pamu2fcfg versions v1.0.8 ou antérieures. Notez que sur les versions v1.1.0 et v1.1.1 de pam-u2f, la gestion de ce réglage était temporairement défectueuse si la valeur n'était pas la même que la valeur de l'origine.

authfile=fichier

Définit l'emplacement du fichier qui contient les associations entre les noms d'utilisateur, les cléHandles et les clés utilisateur. Un fichier individuel (par utilisateur) peut être configuré par rapport au répertoire personnel de l'utilisateur, par ex. ".ssh/u2f_keys". Si non spécifié, l'emplacement par défaut est $XDG_CONFIG_HOME/Yubico/u2f_keys. Si $XDG_CONFIG_HOME n'est pas défini, $HOME/.config/Yubico/u2f_keys est utilisé. Le format du fichier d'authentification est <nom_utilisateur>:<KeyHandle1>,<UserKey1>,<CoseType1>,<Options1>:<KeyHandle2>,<UserKey2>,<CoseType2>,<Options2>:...

expand

Active l'expansion des variables dans le chemin du fichier d'authentification : %u est développé en nom d'utilisateur local (PAM_USER) et %% est développé en %. Les séquences d'expansion inconnues entraînent une erreur d'authentification. Voir aussi openasuser.

authpending_file=fichier

Définit l'emplacement du fichier utilisé pour les notifications de demande de toucher. Ce fichier sera ouvert lorsque pam-u2f commencera à attendre qu'un utilisateur touche l'authentificateur FIDO, et sera fermé lorsqu'il cessera d'attendre un toucher. Utilisez inotify pour écouter ces événements, ou un outil de plus haut niveau comme yubikey-touch-detector. Valeur par défaut : /var/run/user/$UID/pam-u2f-authpending. Définissez une valeur vide pour désactiver cette fonctionnalité, comme ceci : "authpending_file=".

nouserok

Défini pour permettre aux tentatives d'authentification de réussir même si l'utilisateur qui tente d'authentifier n'est pas trouvé dans le fichier d'authentification ou si le fichier d'authentification est manquant/malformé.

openasuser

Effectue un setuid sur l'utilisateur authentifiant lors de l'ouverture du fichier d'authentification. Utile lorsque la maison de l'utilisateur est stockée sur un volume NFS monté avec l'option root_squash (qui mappe root à nobody, incapable de lire le fichier). Notez qu'après la version 1.0.8, cela est fait par défaut lorsqu'aucun fichier d'authentification global (chemin absolu) ou variable d'environnement XDG_CONFIG_HOME n'a été défini.

alwaysok

Défini pour permettre à toutes les tentatives d'authentification de réussir (mode présentation).

max_devices=n_devices

Nombre maximum d'authentificateurs FIDO autorisés par utilisateur (défaut est 24). Les authentificateurs FIDO spécifiés dans le fichier de mappage d'autorisation qui dépassent cette valeur seront ignorés.

interactive

Défini pour afficher un message et attendre avant de tester la présence d'un authentificateur FIDO. Recommandé si votre authentificateur n'a pas de déclencheur tactile.

[prompt=votre message ici]

Définit un message de demande individuel pour le mode interactif. Faites attention aux crochets autour de ce paramètre pour que les espaces soient correctement reconnus par PAM.

manual

Défini pour passer à une console manuelle où les défis sont affichés à l'écran et la réponse lue depuis l'entrée standard. Utile pour le débogage et les sessions SSH sans support FIDO du client/serveur SSH. Si activé, le mode interactif devient redondant et n'a aucun effet.

cue

Défini pour afficher un message rappelant de toucher l'authentificateur FIDO.

[cue_prompt=votre message ici]

Définit un message de demande individuel pour l'option cue. Faites attention aux crochets autour de ce paramètre pour que les espaces soient correctement reconnus par PAM.

nodetect

Ignore la détection si un authentificateur FIDO approprié est inséré avant d'effectuer une authentification complète. Voir les NOTES ci-dessous.

userpresence=int

Si 1, exige la présence de l'utilisateur pendant l'authentification. Si 0, ne demande pas la présence de l'utilisateur pendant l'authentification. Si omis, revient au comportement par défaut de l'authentificateur.

userverification=int

Si 1, exige la vérification de l'utilisateur pendant l'authentification (par exemple, biométrie). Si 0, ne demande pas la vérification de l'utilisateur pendant l'authentification. Si omis, revient au comportement par défaut de l'authentificateur. Si activé, un authentificateur supportant la vérification utilisateur FIDO2 est requis.

pinverification=int

Si 1, exige la vérification du code PIN pendant l'authentification. Si 0, ne demande pas la vérification du code PIN pendant l'authentification. Si omis, revient au comportement par défaut de l'authentificateur. Si activé, un authentificateur supportant un code PIN FIDO2 est requis.

sshformat

Utilise les identifiants produits par les versions d'OpenSSH qui supportent l'authentificateur FIDO. Il n'est pas possible de mélanger les identifiants natifs et les identifiants SSH. Une fois cette option activée, tous les identifiants seront analysés comme SSH.

conf=chemin/vers/pam_u2f.conf

Définit un emplacement alternatif pour le fichier de configuration. Le chemin fourni doit être absolu et correspondre à un fichier régulier existant. Voir FICHIER DE CONFIGURATION.

EXEMPLES

Authentification du second facteur déferrant la configuration de la vérification utilisateur au fichier de mappage d'autorisation.

auth required pam_u2f.so authfile=/etc/u2f_mappings cue

Authentification sans mot de passe exigeant la vérification du code PIN.

auth sufficient pam_u2f.so authfile=/etc/u2f_mappings cue pinverification=1 userverification=0

Authentification sans mot de passe utilisant la vérification utilisateur intégrée (par exemple, biométrie) avec une solution de secours au code PIN.

auth sufficient pam_u2f.so authfile=/etc/u2f_mappings cue pinverification=0 userverification=1
auth sufficient pam_u2f.so authfile=/etc/u2f_mappings cue pinverification=1 userverification=0

LIMITATIONS

Par défaut, les chemins relatifs vers le fichier d'authentification seront ouverts en tant qu'utilisateur cible, tandis que les chemins absolus seront ouverts en tant que "root". Si la variable "XDG_CONFIG_HOME" est définie, les privilèges ne seront pas diminués sauf si le paramètre de configuration "openasuser" est défini.

Utiliser pam-u2f pour sécuriser la connexion à un ordinateur tout en stockant le fichier de mappage dans un répertoire personnel chiffré, rendra impossible la connexion au système. La partition est déchiffrée après la connexion et le fichier de mappage ne peut pas être accédé.

FICHIER DE CONFIGURATION

Un fichier de configuration peut être utilisé pour définir les arguments par défaut du module.

•Le fichier a un format nom = valeur, avec des commentaires commençant par le caractère #.
•Les espaces blancs en début de ligne, fin de ligne, et autour du signe = sont ignorés.
•Tous les arguments conf du fichier de configuration sont ignorés.
•La taille maximale du fichier de configuration est de 4 Kio.
•Le chemin par défaut pour le fichier de configuration est /etc/security/pam_u2f.conf. Le fichier par défaut est autorisé à ne pas exister. Un chemin alternatif peut être défini dans la ligne de commande du module o

pam_u2f(8) — Arch Linux

NAME

pam_u2f

pluggable authentication module for U2F devices

SYNOPSIS

pam_u2f.so [option ...]

DESCRIPTION

The PAM module pam_u2f handles authentication using U2F (Universal 2nd Factor) devices. U2F devices are hardware authenticators that provide a second factor of authentication, typically used to protect against phishing and man-in-the-middle attacks.

The module allows users to register one or more U2F devices and use them to authenticate to systems that use PAM. The module supports both registration and authentication phases.

OPTIONS

The following options can be passed to the module:

cue
Prompts the user to insert their U2F device. This is the default behavior.
nodetect
Disables the detection of U2F devices. The module will not prompt the user to insert their device, and will proceed directly to authentication. This can be useful in environments where U2F devices are not always present, or where automatic detection is not desired.
nouserok
Do not permit authentication if the user is not found in the configured authentication file. This is the default behavior.
userok
Permit authentication even if the user is not found in the configured authentication file. This can be useful in environments where users may not have a corresponding entry in the authentication file.
authfile=path
Specifies the path to the authentication file. This file contains the registered U2F devices for each user. If not specified, the default location is ~/.config/ u2fhosts.
keydir=path
Specifies the directory containing the user's U2F keys. This is used when the authentication file is not in the default location. If not specified, the default location is ~/.config/ u2fkeys.
debug
Enables debug logging. This can be useful for troubleshooting issues.
trace
Enables trace logging. This provides more detailed information than debug logging.

EXAMPLES

To use pam_u2f with the default options, add the following line to your PAM configuration file (e.g., /etc/pam.d/system-login):

auth       required     pam_u2f.so

To use pam_u2f without prompting the user to insert their device, use the nodetect option:

auth       required     pam_u2f.so nodetect

To specify a custom authentication file, use the authfile option:

auth       required     pam_u2f.so authfile=/etc/u2f.conf

CAVEATS

The nodetect option should be used with caution. It disables the detection of U2F devices, which can lead to a less secure authentication process. If the user does not have a U2F device inserted, authentication will fail without any prompt or indication.

The default authentication file location is ~/.config/ u2fhosts. Ensure that this file exists and is correctly populated with the user's registered U2F devices.

The default key directory is ~/.config/ u2fkeys. Ensure that this directory exists and contains the user's U2F keys.

CONFIGURATION FILE

The configuration file used by pam_u2f specifies the U2F devices registered for each user. The format is as follows:

username: <base64 encoded key handle>[,<base64 encoded key handle>...]

The key handle is a unique identifier for the registered U2F device. It can be obtained using the pamu2fcfg utility.

Each line in the configuration file represents a single user. The username is followed by a colon and a comma-separated list of key handles. Multiple key handles can be specified for a single user, allowing them to use multiple U2F devices for authentication.

Options specified on the module command line override the values from the configuration file.

NOTES

Nodetect

The "nodetect" option should be used with caution. pam_u2f checks that a key configured for the user is inserted before performing the full tactile authentication. This detection is done by sending a "check-only" authentication request to all inserted tokens to so see if at least one of them responds affirmatively to one or more of the keyhandles configured for the user. By doing this, pam_u2f can avoid emitting the "cue" prompt (if configured), which can cause some confusing UI issues if the cue is emitted followed by the underlying library immediately failing the tactile authentication. This option is also useful to avoid an unintended 1-second delay prior to the tactile authentication caused by versions of libu2f-host <= 1.1.5.

If pam_u2f is configured to "cue" and "nodetect", an attacker can determine that pam_u2f is part of the authentication stack by inserting any random U2F token and performing an authentication attempt. In this scenario, the attacker would see the cue message followed by an immediate failure, whereas with detection enabled, the authentication will fail silently. Understand that an attacker could choose an authenticator that alerts him or her in some way to the "check-only" authentication attempt, so this precaution only pushes the issue back a step.

In summary, the detection feature was added to avoid confusing UI issues and to prevent leaking information about the authentication stack in very specific scenario when "cue" is configured. The "nodetect" option was added to avoid buggy sleep behavior in older versions of libu2f-host and for hypothetical tokens that do not tolerate the double authentication. Detection is performed, and likewise "nodetect" honored, regardless of whether "cue" is also specified.

SELinux

Due to an issue with Fedora Linux, and possibly with other distributions that use SELinux, a system configured with pam-u2f may end up in a situation where access to the credentials file is denied. If the nouserok option is also set, this will result in a successful authentication within the module, without using the FIDO authenticator.

In order to correctly update the security context the command fixfiles onboot should be used on existing installations

Moreover, to allow read access to an authfile or directory placed in a non-standard location, the command

# chcon -R -t auth_home_t /path/to/authfile

should be used.

For more information see https://access.redhat.com/security/cve/CVE-2020-24612.
