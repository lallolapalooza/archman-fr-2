pamfixtrunc a été remplacé dans Netpbm 10.66 (mars 2014) par pamfix(1)

pamfix avec une option -truncate est la même chose que pamfixtrunc. Mais pamfix a d'autres options pour réparer d'autres types de corruption.

Un autre changement arrivé avec Netpbm 10.66 est qu'une valeur d'échantillon invalide (une valeur supérieure au maxval que l'image déclare dans son en-tête) est considérée par le mécanisme commun de lecture d'images Netpbm (dans libnetpbm) comme illisible, ce qui signifie que le fichier est essentiellement tronqué. Dans les anciennes versions de Netpbm, la valeur d'échantillon invalide se propage dans la sortie d'un programme tel que pamfixtrunc. Ainsi, dans les anciennes versions de Netpbm, un fichier avec 100 lignes et une valeur d'échantillon invalide dans la 3ème ligne serait passé inchangé par pamfixtrunc. Mais dans Netpbm 10.66, pamfix -truncate avec la même entrée produirait une image de sortie avec seulement 2 lignes. Bien qu'il ne soit pas possible en 10.66 de faire générer par pamfix une image Netpbm invalide, vous pouvez utiliser les options -clip et -changemaxval pour éviter de tronquer le fichier dans un cas comme celui-ci.

Vous ne devriez pas faire de nouvelle utilisation de pamfixtrunc et si vous modifiez une utilisation existante, vous devriez passer à pamfix. Mais notez que si vous écrivez un programme qui pourrait devoir être utilisé avec de très anciennes versions de Netpbm, pamfixtrunc est le seul moyen de le faire.
