par2(1) Outils d'archivage Parity par2(1)

NOM

par2 - Outil de vérification et de réparation de fichiers compatible PAR 2.0.

SYNTAXE

par2 c|v|r [options] <fichier_PAR2> [fichiers]

par2 c(reate) [options] <fichier_PAR2> [fichiers]
par2 v(erify) [options] <fichier_PAR2> [fichiers]
par2 r(epair) [options] <fichier_PAR2> [fichiers]

Aussi :
par2create [options] <fichier_PAR2> [fichiers]
par2verify [options] <fichier_PAR2> [fichiers]
par2repair [options] <fichier_PAR2> [fichiers]

DESCRIPTION

par2cmdline est un programme de création et d'utilisation de fichiers PAR2 pour détecter les dommages dans les fichiers de données et les réparer si nécessaire. Il peut être utilisé avec tout type de fichier.

OPTIONS

-h
Afficher cette aide
-V
Afficher la version
-VV
Afficher la version et le copyright
-a <fichier>
Définir le nom de l'archive PAR2 principale ; obligatoire lors de la création, optionnel pour vérifier et réparer
-b<n>
Définir le nombre de blocs
-s<n>
Définir la taille des blocs (ne pas utiliser à la fois -b et -s)
-r<n>
Niveau de redondance (pourcentage)
-r<c><n>
Taille cible de redondance, <c>=g(iga),m(ega),k(ilo) octets
-c<n>
Nombre de blocs de récupération (ne pas utiliser à la fois -r et -c)
-f<n>
Numéro du premier bloc de récupération
-u
Tailles de fichiers de récupération uniformes
-l
Limiter la taille des fichiers de récupération (ne pas utiliser à la fois -u et -l)
-n<n>
Nombre de fichiers de récupération (max 31) (ne pas utiliser à la fois -n et -l)
-m<n>
Mémoire (en Mo) à utiliser
-t<n>
Nombre de threads utilisés pour le traitement principal (détecté automatiquement)
-T<n>
Nombre de fichiers hachés en parallèle (pendant les phases de vérification et de création de fichiers, 2 par défaut)
-v [-v]
Être plus verbeux
-q [-q]
Être plus silencieux (-qq donne le silence)
-p
Supprimer les fichiers de sauvegarde et les fichiers par en cas de récupération réussie ou lorsqu'aucune récupération n'est nécessaire
-R
Parcourir récursivement les sous-répertoires (uniquement utile lors de la création)
-N
Saut de données (trouver des blocs de données mal positionnés)
-S<n>
Marge de saut (distance +/- de la position attendue du bloc)
-B<chemin>
Définir le chemin de base à utiliser comme référence pour les fichiers de données
--
Traiter tous les arguments suivants comme des noms de fichiers

CODES DE SORTIE

0
Le processus s'est terminé avec succès
1
La réparation est possible, il y a suffisamment de blocs de récupération
2
La réparation n'est *PAS* possible, il y a un nombre insuffisant de blocs de récupération
3
La combinaison des options de ligne de commande donnée est invalide
4
Données critiques insuffisantes, probablement vos fichiers par sont corrompus
5
La réparation a été complétée, mais les fichiers de données sont toujours corrompus
6
Une erreur d'entrée/sortie lors de l'accès à un fichier
7
Une erreur de logique interne s'est produite
8
Mémoire insuffisante ou autre erreur de mémoire

EXEMPLES

Avec PAR 2.0, vous pouvez créer des fichiers de récupération PAR2 pour aussi peu que 1 ou jusqu'à 32768 fichiers. Si vous vouliez créer des fichiers de récupération PAR1 pour un seul fichier, vous étiez obligé de diviser le fichier en plusieurs parties et RAR était fréquemment utilisé à cette fin. Vous n'avez PAS besoin de diviser les fichiers avec PAR 2.0.

Pour créer des fichiers de récupération PAR 2 pour un seul fichier de données (par exemple, un fichier nommé test.mpg), vous pouvez utiliser la commande suivante :


par2 create test.mpg

Si test.mpg est un fichier de 800 Mo, cela créera un total de 8 fichiers PAR2 avec les noms de fichiers suivants (prenant environ 6 minutes sur un PC avec un CPU de 1500 MHz) :


test.mpg.par2 - Ceci est un fichier d'index uniquement pour la vérification
test.mpg.vol00+01.par2 - Fichier de récupération avec 1 bloc de récupération
test.mpg.vol01+02.par2 - Fichier de récupération avec 2 blocs de récupération
test.mpg.vol03+04.par2 - Fichier de récupération avec 4 blocs de récupération
test.mpg.vol07+08.par2 - Fichier de récupération avec 8 blocs de récupération
test.mpg.vol15+16.par2 - Fichier de récupération avec 16 blocs de récupération
test.mpg.vol31+32.par2 - Fichier de récupération avec 32 blocs de récupération
test.mpg.vol63+37.par2 - Fichier de récupération avec 37 blocs de récupération

Le fichier test.mpg.par2 a une taille de 39 Ko et les autres fichiers varient en taille de 443 Ko à 15 Mo. Ces fichiers par2 permettront de récupérer jusqu'à 100 erreurs totalisant 40 Mo de données perdues ou endommagées du fichier test.mpg original lorsque celui-ci et les fichiers par2 seront postés sur UseNet. Lors de la publication sur UseNet, il est recommandé d'utiliser l'option "-s" pour définir une taille de bloc égale à la taille de l'article que vous utiliserez pour poster le fichier de données. Si vous vouliez poster le fichier test.mpg en utilisant une taille d'article de 300 Ko, la commande que vous taperiez serait :


par2 create -s307200 test.mpg

Cela créera 9 fichiers PAR2 au lieu de 8, et ils seront capables de corriger jusqu'à 134 erreurs totalisant 40 Mo. La création des fichiers de récupération prendra environ 8 minutes cette fois. Dans ces deux exemples, la quantité totale de données de récupération créées était de 40 Mo (ce qui représente 5% de 800 Mo). Si vous souhaitez créer une quantité de données de récupération plus grande ou plus petite, vous pouvez utiliser l'option "-r". Pour créer 10% de données de récupération au lieu des 5% par défaut et également utiliser une taille de bloc de 300 Ko, vous utiliseriez la commande suivante :


par2 create -s307200 -r10 test.mpg

Cela créerait également 9 fichiers PAR2, mais ils seraient capables de corriger jusqu'à 269 erreurs totalisant 80 Mo. Comme deux fois plus de données de récupération sont créées, cela prendra environ 16 minutes avec un CPU de 1500 MHz. Les options "-u" et "-n" peuvent être utilisées pour contrôler exactement combien de fichiers de récupération sont créés et comment les blocs de récupération sont distribués entre eux. Elles n'affectent pas la quantité totale de données de récupération créées. L'option "-f" est utilisée lorsque vous créez des données de récupération supplémentaires. Par exemple, si vous avez déjà créé 10% et que vous en voulez encore 5%, vous pourriez utiliser la commande suivante :


par2 create -s307200 -r5 -f300 test.mpg

Cela spécifie la même taille de bloc (qui est une exigence pour les fichiers de récupération supplémentaires), 5% de données de récupération et un numéro de premier bloc de 300.

L'option "-m" contrôle la quantité de mémoire utilisée par par2. Elle est de 16 Mo par défaut sauf si vous la remplacez.

CRÉATION DE FICHIERS PAR2 POUR PLUSIEURS FICHIERS DE DONNÉES

Lors de la création de fichiers de récupération PAR2 à partir de plusieurs fichiers de données, vous devez spécifier le nom de base du fichier à utiliser pour les fichiers par2 et les noms de tous les fichiers de données. Si test.mpg avait été divisé en plusieurs fichiers RAR, vous pourriez alors utiliser :


par2 create test.mpg.rar.par2 test.mpg.part*.rar

Le nom de fichier "test.mpg.rar.par2" indique comment vous voulez que les fichiers par2 soient nommés et "test.mpg.part*.rar" devrait sélectionner tous les fichiers RAR.

Avec "-R", vous pouvez également créer des fichiers de récupération pour une structure arborescente multi-niveaux.

par2(1) - Arch Linux man pages

par2 - redundancy, protection and recovery generation

par2
par2
par2 c [Options] file...
par2 v [Options] file...
par2 r [Options] file...
par2 c [Options] fileset
par2 v [Options] fileset
par2 r [Options] fileset

The par2 program is used to generate recovery data for use with the par2 program and to verify and repair data files using par2 recovery files.

The par2 program is used to generate recovery data. Par2 creates redundancy files which may be used to reconstruct the original data files if they become corrupted or are lost. These redundancy files contain sufficient information to check the integrity of the original files and to repair them if damage is found. Par2 supports creating multiple sets of recovery files for a given set of data files.

The par2 program is used to verify and repair data files. Given the name of one of the par2 recovery files, par2 will automatically search for the other par2 recovery files that were created and use the information they contain to check the integrity of the data files. If the data files are found to be damaged or missing, par2 will attempt to repair them using the recovery data.

The following options are available:

c
Create recovery data.
-r percentage
Set the recovery volume redundancy percentage. The default is 5% and is used to calculate the number of recovery blocks to create. The number of recovery blocks to create is calculated as follows:

num_blocks = ceil(num_data_files * num_blocks_per_file * (percentage / 100))

where num_blocks_per_file is the number of blocks per file (default is 1).
-b size
Set the maximum recovery volume size in bytes. If the specified size is less than the size of the source files, then multiple recovery volumes will be created. The default is 1MB. The size can be suffixed with K, M, or G for Kilobytes, Megabytes, or Gigabytes respectively.
-n number
Set the number of recovery volumes to create. If the number of recovery volumes is greater than the number of source files, then the number of recovery volumes will be reduced to the number of source files. If the number of recovery volumes is set to 0, then a single recovery volume will be created containing sufficient recovery blocks to ensure that the data files can be recovered.
-q level
Set the recovery level. Higher levels generate more recovery blocks and provide greater protection. Valid levels are 0 to 40. The default is 0. Higher levels increase the amount of time required to create the recovery files and the size of the recovery files.
-m level
Set the recovery block size. Smaller block sizes allow for finer granularity in recovery, but may increase the overhead. Larger block sizes may improve performance but can lead to less efficient recovery if only small amounts of data are damaged. The default is 1MB. The size can be suffixed with K, M, or G for Kilobytes, Megabytes, or Gigabytes respectively.
-s size
Set the size of the input files in bytes. This option is only used when creating recovery files for files that have been split into multiple parts. The size can be suffixed with K, M, or G for Kilobytes, Megabytes, or Gigabytes respectively.
-l file
Write a file containing a list of all recovery files that were created. The default is to not create such a file.
-p file
Write a file containing a list of all the original data files. The default is to not create such a file.
-f
Overwrite existing recovery files without prompting.
-V
Display program version and exit.
--help
Display help message and exit.
v
Verify data files.
r
Repair data files.
-x
Extract original data files from recovery files.
-t size
Set the time limit for searching for recovery files in seconds. The default is 60 seconds. The time limit can be suffixed with M, H, or D for minutes, hours, or days respectively.
-!
Do not prompt before overwriting existing files.

The following exit codes are returned:

0
Success.
1
General error.
2
Insufficient recovery data.
3
A file could not be verified.
4
A file could not be repaired.
5
A file could not be found.
6
Invalid arguments.

VERIFYING AND REPAIRING

When using par2 recovery files to verify or repair the data files from which they were created, you only need to specify the filename of one of the par2 files to par2. For example:


par2 verify test.mpg.par2

This tells par2 to use the information in test.mpg.par2 to verify the data files. Par2 will automatically search for the other par2 files that were created and use the information they contain to determine the filenames of the original data files and then to verify them. If all of the data files are ok, then par2 will report that repair will not be required. If any of the data files are missing or damaged, par2 will report the details of what it has found. If the recovery files contain enough recovery blocks to repair the damage, you will be told that repair is possible. Otherwise you will be told exactly how many recovery blocks will be required in order to repair. To carry out a repair use the following command:


par2 repair test.mpg.par2

This tells par2 to verify and if possible repair any damaged or missing files. If a repair is carried out, then each file which is repaired will be re-verified to confirm that the repair was successful.

MISSNAMED AND INCOMPLETE DATA FILES

If any of the recovery files or data files have the wrong filename, then par2 will not automatically find and scan them. To have par2 scan such files, you must include them on the command line when attempting to verify or repair; e.g.:


par2 r test.mpg.par2 other.mpg

This tells par2 to scan the file called other.mpg to see if it contains any data belonging to the original data files. If one of the extra files specified in this way is an exact match for a data file, then the repair process will rename the file so that it has the correct filename. Because par2 is designed to be able to find good data within a damaged file, it can do the same with incomplete files downloaded from UseNet. If some of the articles for a file are missing, you should still download the file and save it to disk for par2 to scan. If you do this then you may find that you can carry out a repair in a situation where you would not otherwise have sufficient recovery data. You can have par2 scan all files that are in the current directory using a command such as:


par2 r test.mpg.par2 *

WHAT TO DO WHEN YOU ARE TOLD YOU NEED MORE RECOVERY BLOCKS

If par2 determines that any of the data files are damaged or missing and finds that there is insufficient recovery data to effect a repair, you will be told that you need a certain number of recovery blocks. You can obtain these by downloading additional recovery files. In order to make things easy, par2 files have filenames that tell you exactly how many recovery blocks each one contains. Assuming that the following command was used to create recovery data:


par2 c -b1000 -r5 test.mpg

Then the recovery files that are created would be called:


test.mpg.par2
test.mpg.vol00+01.par2
test.mpg.vol01+02.par2
test.mpg.vol03+04.par2
test.mpg.vol07+08.par2
test.mpg.vol15+16.par2
test.mpg.vol31+19.par2

The first file in this list does not contain any recovery data, it only contains information sufficient to verify the data files. Each of the other files contains a different number of recovery blocks. The number after the '+' sign is the number of recovery blocks and the number preceding the '+' sign is the block number of the first recovery block in that file. If par2 told you that you needed 10 recovery blocks, then you would need "test.mpg.vol01+02.par2" and "test.mpg.vol07+08.par". You might of course choose to fetch "test.mpg.vol15+16.par2" instead (in which case you would have an extra 6 recovery blocks which would not be used for the repair).

HASHING

Hashing portion (file verification and creation stages) of the code can't be parallelized without processing multiple files simultaneously. The 2 file/thread default is a good choice for HDDs, using more threads can result in worse performance. Four or more threads can be used for better performance with SSDs.
