PACMAN(8) Manuel Pacman PACMAN(8)

NOM

pacman - utilitaire de gestion de paquets

SYNTAXE

pacman <opération> [options] [cibles]

DESCRIPTION

Pacman est un utilitaire de gestion de paquets qui suit les paquets installés sur un système Linux. Il prend en charge les dépendances, les groupes de paquets, les scripts d'installation et de désinstallation, ainsi que la capacité de synchroniser votre machine locale avec un dépôt distant pour mettre à jour automatiquement les paquets. Les paquets Pacman sont au format tar compressé.

Depuis la version 3.0.0, pacman est le frontal de libalpm(3), la bibliothèque « Arch Linux Package Management ». Cette bibliothèque permet l'écriture de frontaux alternatifs (par exemple, un frontal graphique).

L'invocation de pacman implique la spécification d'une opération avec des options potentielles et des cibles sur lesquelles opérer. Une cible est généralement un nom de paquet, un nom de fichier, une URL ou une chaîne de recherche. Les cibles peuvent être fournies comme arguments de ligne de commande. De plus, si stdin ne provient pas d'un terminal et qu'un simple trait d'union (-) est passé comme argument, les cibles seront lues depuis stdin.

OPÉRATIONS

-D, --database

Opère sur la base de données des paquets. Cette opération vous permet de modifier certains attributs des paquets installés dans la base de données de pacman. Elle vous permet également de vérifier la cohérence interne des bases de données. Voir Options de base de données ci-dessous.

-Q, --query

Interroge la base de données des paquets. Cette opération vous permet de visualiser les paquets installés et leurs fichiers, ainsi que des méta-informations sur les paquets individuels (dépendances, conflits, date d'installation, date de construction, taille). Ceci peut être exécuté sur la base de données locale des paquets ou sur des fichiers de paquets individuels. Dans le premier cas, si aucun nom de paquet n'est fourni dans la ligne de commande, tous les paquets installés seront interrogés. De plus, divers filtres peuvent être appliqués à la liste des paquets. Voir Options de requête ci-dessous.

-R, --remove

Supprime des paquets du système. Les groupes peuvent aussi être spécifiés pour être supprimés, auquel cas chaque paquet de ce groupe sera supprimé. Les fichiers appartenant au paquet spécifié seront supprimés et la base de données sera mise à jour. La plupart des fichiers de configuration seront sauvegardés avec l'extension .pacsave sauf si l'option --nosave est utilisée. Voir Options de suppression ci-dessous.

-S, --sync

Synchronise les paquets. Les paquets sont installés directement depuis les dépôts distants, y compris toutes les dépendances requises pour exécuter les paquets. Par exemple, pacman -S qt téléchargera et installera qt ainsi que tous les paquets dont il dépend. Si un nom de paquet existe dans plusieurs dépôts, le dépôt peut être explicitement spécifié pour clarifier le paquet à installer : pacman -S testing/qt. Vous pouvez aussi spécifier des exigences de version : pacman -S "bash>=3.2". Des guillemets sont nécessaires, sinon le shell interprétera ">" comme une redirection vers un fichier.

En plus des paquets, des groupes peuvent aussi être spécifiés. Par exemple, si gnome est un groupe de paquets défini, alors pacman -S gnome affichera une invite permettant de sélectionner les paquets à installer à partir d'une liste numérotée. La sélection des paquets est spécifiée à l'aide d'une liste de numéros de paquets séparés par des espaces et/ou des virgules. Les paquets séquentiels peuvent être sélectionnés en spécifiant le premier et le dernier numéro de paquet séparés par un trait d'union (-). L'exclusion de paquets est réalisée en préfixant un numéro ou une plage de numéros par un caret (^).

Les paquets qui fournissent d'autres paquets sont également gérés. Par exemple, pacman -S foo cherchera d'abord un paquet foo. Si foo n'est pas trouvé, les paquets qui fournissent la même fonctionnalité que foo seront recherchés. Si un paquet est trouvé, il sera installé. Une invite de sélection est fournie si plusieurs paquets fournissant foo sont trouvés.

Vous pouvez aussi utiliser pacman -Su pour mettre à jour tous les paquets obsolètes. Voir Options de synchronisation ci-dessous. Lors de la mise à jour, pacman effectue une comparaison de versions pour déterminer quels paquets doivent être mis à jour. Ce comportement fonctionne comme suit :

Alphanumérique :
  1.0a < 1.0b < 1.0beta < 1.0p < 1.0pre < 1.0rc < 1.0 < 1.0.a < 1.0.1
Numérique :
  1 < 1.0 < 1.1 < 1.1.1 < 1.2 < 2.0 < 3.0.0

De plus, les chaînes de version peuvent avoir une valeur d'epoch définie qui annulera toute comparaison de version, sauf si les valeurs d'epoch sont égales. Ceci est spécifié dans un format epoch:version-rel. Par exemple, 2:1.0-1 est toujours supérieur à 1:3.6-1.

-T, --deptest

Vérifie les dépendances ; ceci est utile dans des scripts comme makepkg pour vérifier les paquets installés. Cette opération vérifiera chaque dépendance spécifiée et retournera une liste des dépendances qui ne sont pas actuellement satisfaites sur le système. Cette opération n'accepte aucune autre option. Exemple d'utilisation : pacman -T qt "bash>=3.2".

-U, --upgrade

Met à jour ou ajoute des paquets au système et installe les dépendances requises depuis les dépôts de synchronisation. Une URL ou un chemin d'accès à un fichier peuvent être spécifiés. Ceci est un processus de « supprimer puis ajouter ». Voir Options de mise à niveau ci-dessous ; voir également Gestion des fichiers de configuration pour une explication sur la façon dont pacman prend en charge les fichiers de configuration.

-F, --files

Interroge la base de données des fichiers. Cette opération vous permet de rechercher les paquets qui possèdent certains fichiers ou d'afficher les fichiers possédés par certains paquets. Seuls les paquets qui font partie de vos bases de données de synchronisation sont recherchés. Voir Options de fichiers ci-dessous.

-V, --version

Affiche la version et quitte.

-h, --help

Affiche la syntaxe pour l'opération donnée. Si aucune opération n'a été fournie, alors la syntaxe générale est affichée.

OPTIONS

-b, --dbpath <chemin>

Spécifie un emplacement de base de données alternatif (le défaut est /var/lib/pacman). Ceci ne doit pas être utilisé sauf si vous savez ce que vous faites. NOTE : Si spécifié, ceci est un chemin absolu, et le chemin racine n'est pas automatiquement ajouté.

-r, --root <chemin>

Spécifie une racine d'installation alternative (par défaut /). Ceci ne doit pas être utilisé comme moyen d'installer des logiciels dans /usr/local au lieu de /usr. NOTE : Si le chemin de la base de données ou le fichier journal ne sont pas spécifiés sur la ligne de commande ou dans pacman.conf(5), leur emplacement par défaut sera à l'intérieur de ce chemin racine. NOTE : Cette option n'est pas adaptée pour effectuer des opérations sur un système invité monté. Utilisez plutôt --sysroot.

-v, --verbose

Affiche les chemins tels que Root, Fichier de configuration, Chemin de la base de données, Répertoires de cache, etc.

--arch <arch>

Spécifie une architecture alternative.

--cachedir <répertoire>

Spécifie un emplacement de cache de paquets alternatif (le défaut est /var/cache/pacman/pkg). Plusieurs répertoires de cache peuvent être spécifiés, et ils sont essayés dans l'ordre où ils sont passés à pacman. NOTE : Ceci est un chemin absolu, et le chemin racine n'est pas automatiquement ajouté.

--color <quand>

Spécifie quand activer la coloration. Les options valides sont always, never, ou auto. always force l'activation des couleurs ; never désactive les couleurs ; et auto active automatiquement les couleurs uniquement lors de la sortie sur un tty.

--config <fichier>

Spécifie un fichier de configuration alternatif.

--debug

Affiche les messages de débogage. Lors du signalement de bugs, l'utilisation de cette option est recommandée.

--gpgdir <répertoire>

Spécifie un répertoire de fichiers utilisés par GnuPG pour vérifier les signatures de paquets (le défaut est /etc/pacman.d/gnupg). Ce répertoire doit contenir deux fichiers : pubring.gpg et trustdb.gpg. pubring.gpg contient les clés publiques de tous les empaqueteurs. trustdb.gpg contient une base de données de confiance, qui spécifie que les clés sont authentiques et fiables. NOTE : Ceci est un chemin absolu, et le chemin racine n'est pas automatiquement ajouté.

--hookdir <répertoire>

Spécifie un répertoire alternatif contenant les fichiers hook (le défaut est /etc/pacman.d/hooks). Plusieurs répertoires hook peuvent être spécifiés, les hooks dans les répertoires ultérieurs prenant la priorité sur les hooks
dans des répertoires précédents. NOTE : Il s'agit d'un chemin absolu, et le chemin racine n'est pas automatiquement préfixé.

--logfile <fichier>

Spécifiez un fichier journal alternatif. Il s'agit d'un chemin absolu, indépendamment du réglage de la racine d'installation.

--noconfirm

Ignore tous les messages « Êtes-vous sûr ? ». Il est déconseillé d'utiliser cette option, sauf si vous souhaitez exécuter pacman à partir d'un script.

--confirm

Annule les effets d'un --noconfirm précédent.

--disable-download-timeout

Désactive les valeurs par défaut pour la limite de débit faible et le délai d'attente pour les téléchargements. Utilisez cette option si vous rencontrez des problèmes lors du téléchargement de fichiers via un proxy et/ou une passerelle de sécurité.

--sysroot <répertoire>

Spécifiez une racine système alternative. Ce chemin sera préfixé à tous les autres répertoires de configuration et à tous les serveurs de dépôt commençant par file://. Tous les chemins ou URL passés en tant que cibles ne seront pas modifiés. Cela permet de manipuler correctement les systèmes invités montés.

--disable-sandbox

Désactive le bac à sable par défaut appliqué au processus de téléchargement de fichiers sur les systèmes Linux. Utile en cas d'échecs liés à landlock lors du téléchargement de fichiers lorsque vous exécutez un noyau Linux qui ne prend pas en charge cette fonctionnalité.

OPTIONS DE TRANSACTION (APPLICABLES À -S, -R ET -U)

-d, --nodeps

Ignore les vérifications de version des dépendances. Les noms de paquets sont toujours vérifiés. Normalement, pacman vérifie toujours les champs de dépendance d'un paquet pour s'assurer que toutes les dépendances sont installées et qu'il n'y a pas de conflits de paquets dans le système. Spécifiez cette option deux fois pour ignorer toutes les vérifications de dépendances.

--assume-installed <paquet=version>

Ajoute un paquet virtuel « paquet » avec la version « version » à la transaction pour satisfaire les dépendances. Cela permet de désactiver les vérifications de dépendances spécifiques sans affecter toutes les vérifications de dépendances. Pour désactiver toutes les vérifications de dépendances, voir l'option --nodeps.

--dbonly

Ajoute/supprime uniquement l'entrée de la base de données, en laissant tous les fichiers en place.

--noprogressbar

N'affiche pas de barre de progression lors du téléchargement de fichiers. Ceci peut être utile pour les scripts qui appellent pacman et capturent la sortie.

--noscriptlet

Si un scriptlet d'installation existe, ne l'exécutez pas. N'utilisez pas cette option à moins de savoir ce que vous faites.

-p, --print

Affiche uniquement les cibles au lieu d'effectuer l'opération réelle (synchronisation, suppression ou mise à niveau). Utilisez --print-format pour spécifier comment les cibles sont affichées. La chaîne de format par défaut est « %l », qui affiche les URL avec -S, les noms de fichiers avec -U, et pkgname-pkgver avec -R.

--print-format <format>

Spécifiez un format de type printf pour contrôler la sortie de l'opération --print. Les attributs possibles sont : « %a » pour l'architecture, « %b » pour la date de construction, « %d » pour la description, « %e » pour la base du paquet, « %f » pour le nom du fichier, « %g » pour la signature PGP encodée en base64, « %h » pour le sha256sum, « %m » pour le md5sum, « %n » pour le nom du paquet, « %p » pour le packager, « %v » pour la version du paquet, « %l » pour la localisation, « %r » pour le dépôt, « %s » pour la taille, « %C » pour les dépendances de vérification, « %D » pour les dépendances, « %G » pour les groupes, « %H » pour les conflits, « %L » pour les licences, « %M » pour les dépendances de construction, « %O » pour les dépendances optionnelles, « %P » pour les fournitures et « %R » pour les remplacements. Implique --print.

OPTIONS DE MISE À NIVEAU (APPLICABLES À -S ET -U)

-w, --downloadonly

Récupère tous les paquets du serveur, mais n'installe/met à niveau rien.

--asdeps

Installe les paquets de manière non explicite ; en d'autres termes, simule leur raison d'installation comme étant une dépendance. Ceci est utile pour makepkg et d'autres outils de compilation à partir des sources qui doivent installer des dépendances avant de compiler le paquet.

--asexplicit

Installe les paquets de manière explicite ; en d'autres termes, simule leur raison d'installation comme étant explicitement installés. Ceci est utile si vous souhaitez marquer une dépendance comme étant explicitement installée afin qu'elle ne soit pas supprimée par l'opération de suppression --recursive.

--ignore <paquet>

Indique à pacman d'ignorer les mises à niveau du paquet, même s'il y en a une de disponible. Plusieurs paquets peuvent être spécifiés en les séparant par une virgule.

--ignoregroup <groupe>

Indique à pacman d'ignorer les mises à niveau de tous les paquets du groupe, même s'il y en a une de disponible. Plusieurs groupes peuvent être spécifiés en les séparant par une virgule.

--needed

Ne réinstalle pas les cibles qui sont déjà à jour.

--overwrite <glob>

Ignore les vérifications de conflit de fichiers et écrase les fichiers conflictuels. Si le paquet sur le point d'être installé contient des fichiers déjà installés et correspondant à glob, cette option provoquera l'écrasement de tous ces fichiers. L'utilisation de --overwrite n'autorisera pas l'écrasement d'un répertoire par un fichier ni l'installation de paquets avec des fichiers et des répertoires conflictuels. Plusieurs motifs peuvent être spécifiés en les séparant par une virgule. Peut être spécifié plusieurs fois. Les motifs peuvent être niés, de sorte que les fichiers qui y correspondent ne soient pas écrasés, en les préfixant d'un point d'exclamation. Les correspondances ultérieures remplaceront les précédentes. Un point d'exclamation ou une barre oblique inverse littérale en début de motif doit être échappé.

OPTIONS DE RECHERCHE (APPLICABLES À -Q)

-c, --changelog

Affiche le ChangeLog d'un paquet s'il existe.

-d, --deps

Restreint ou filtre la sortie aux paquets installés en tant que dépendances. Cette option peut être combinée avec -t pour lister les orphelins réels - les paquets qui ont été installés en tant que dépendances mais qui ne sont plus requis par aucun paquet installé.

-e, --explicit

Restreint ou filtre la sortie aux paquets explicitement installés. Cette option peut être combinée avec -t pour lister les paquets explicitement installés qui ne sont requis par aucun autre paquet.

-g, --groups

Affiche tous les paquets qui font partie d'un groupe nommé. Si aucun nom n'est spécifié, liste tous les paquets groupés.

-i, --info

Affiche des informations sur un paquet donné. L'option -p peut être utilisée si vous interrogez un fichier de paquet au lieu de la base de données locale. Passer deux indicateurs --info ou -i affichera également la liste des fichiers de sauvegarde et leur état de modification.

-k, --check

Vérifie que tous les fichiers appartenant aux paquets donnés sont présents sur le système. Si des paquets ne sont pas spécifiés ou si des indicateurs de filtre ne sont pas fournis, vérifie tous les paquets installés. Spécifier cette option deux fois effectuera une vérification de fichiers plus détaillée (y compris les permissions, les tailles de fichiers et les heures de modification) pour les paquets contenant le fichier mtree nécessaire.

-l, --list

Liste tous les fichiers appartenant à un paquet donné. Plusieurs paquets peuvent être spécifiés sur la ligne de commande.

-m, --foreign

Restreint ou filtre la sortie aux paquets qui n'ont pas été trouvés dans les bases de données de synchronisation. Il s'agit généralement de paquets téléchargés manuellement et installés avec --upgrade.

-n, --native

Restreint ou filtre la sortie aux paquets qui sont trouvés dans les bases de données de synchronisation. C'est le filtre inverse de --foreign.

-o, --owns <fichier>

Recherche les paquets qui possèdent le ou les fichiers spécifiés. Le chemin peut être relatif ou absolu, et un ou plusieurs fichiers peuvent être spécifiés.

-p, --file

Indique que le paquet fourni sur la ligne de commande est un fichier et non une entrée dans la base de données. Le fichier sera décompressé et interrogé. Ceci est utile en combinaison avec --info et --list.

-q, --quiet

Affiche moins d'informations pour certaines opérations de recherche. Ceci est utile lorsque la sortie de pacman est traitée dans un script. La recherche n'affichera que les noms de paquets et non les informations de version, de groupe et de description ; owns n'affichera que les noms de paquets au lieu des messages « fichier appartenant à pkg » ; group n'affichera que les noms de paquets et omettra les noms de groupes ; list n'affichera que les fichiers et omettra les noms de paquets ; check n'affichera que des paires de noms de paquets et de fichiers manquants ; une recherche nue n'affichera que les noms de paquets au lieu des noms et des versions.

-s, --search <regexp>

Recherche dans chaque paquet installé localement des noms ou descriptions correspondant à regexp. Lors de l'inclusion de plusieurs termes de recherche, seuls les paquets dont les descriptions correspondent à TOUS ces termes sont renvoyés.

-t, --unrequired

Restreint ou filtre la sortie pour n'afficher que les paquets non requis et non optionnellement requis par aucun paquet actuellement installé. Spécifiez cette option deux fois pour inclure les paquets qui sont optionnellement, mais pas directement, requis par un autre paquet.

-u, --upgrades

Restreint ou filtre la sortie aux paquets obsolètes sur le système local. Seules les versions des paquets sont utilisées pour trouver les paquets obsolètes ; les remplacements ne sont pas vérifiés ici. Cette option fonctionne mieux si la base de données de synchronisation est actualisée à l'aide de -Sy.

OPTIONS DE SUPPRESSION (APPLICABLES À -R)

-c, --cascade

Supprime tous les paquets cibles, ainsi que tous les paquets qui dépendent d'un ou plusieurs paquets cibles. Cette opération est récursive et doit être utilisée avec prudence, car elle peut supprimer de nombreux paquets potentiellement nécessaires.

-n, --nosave

Indique à pacman d'ignorer les désignations de sauvegarde de fichiers. Normalement, lorsqu'un fichier est supprimé du système, la base de données est vérifiée pour voir si le fichier doit être renommé avec l'extension .pacsave.

-s, --recursive

Supprime chaque cible spécifiée, y compris toutes ses dépendances, à condition que (A) elles ne soient pas requises par d'autres paquets ; et (B) elles n'aient pas été explicitement installées par l'utilisateur.

ACTIONS

-c, --clean

This operation is recursive and analogous to a backwards --sync operation, and it helps keep a clean system without orphans. If you want to omit condition (B), pass this option twice.

-u, --unneeded

Supprime les cibles qui ne sont requises par aucun autre paquet. Ceci est surtout utile lors de la suppression d'un groupe sans utiliser l'option -c, afin d'éviter de casser des dépendances.

OPTIONS DE SYNCHRONISATION (APPLICABLES À -S)

-c, --clean

Supprime les paquets qui ne sont plus installés du cache ainsi que les bases de données de synchronisation non utilisées actuellement pour libérer de l'espace disque. Lorsque pacman télécharge des paquets, il les sauvegarde dans un répertoire de cache. De plus, les bases de données sont sauvegardées pour chaque DB de synchronisation que vous téléchargez et ne sont pas supprimées même si elles sont retirées du fichier de configuration pacman.conf(5). Utilisez une option --clean pour ne supprimer que les paquets qui ne sont plus installés ; utilisez deux options pour supprimer tous les fichiers du cache. Dans les deux cas, vous aurez une option oui ou non pour supprimer les paquets et/ou les bases de données téléchargées inutilisées.

Si vous utilisez un cache partagé en réseau, consultez l'option CleanMethod dans pacman.conf(5).

-g, --groups

Affiche tous les membres pour chaque groupe de paquets spécifié. Si aucun nom de groupe n'est fourni, tous les groupes seront listés ; passez le drapeau deux fois pour voir tous les groupes et leurs membres.

-i, --info

Affiche des informations sur un paquet de la base de données de synchronisation donné. Passer deux options --info ou -i affichera également les paquets dans tous les dépôts qui dépendent de ce paquet.

-l, --list

Liste tous les paquets dans les dépôts spécifiés. Plusieurs dépôts peuvent être spécifiés sur la ligne de commande.

-q, --quiet

Affiche moins d'informations pour certaines opérations de synchronisation. Ceci est utile lorsque la sortie de pacman est traitée dans un script. La recherche n'affichera que les noms de paquets et non le dépôt, la version, le groupe et les informations de description ; la liste n'affichera que les noms de paquets et omettra les bases de données et les versions ; le groupe n'affichera que les noms de paquets et omettra les noms de groupes.

-s, --search <regexp>

Ceci recherchera dans chaque paquet des bases de données de synchronisation les noms ou descriptions qui correspondent à regexp. Lorsque vous incluez plusieurs termes de recherche, seuls les paquets dont les descriptions correspondent à TOUS ces termes seront renvoyés.

-u, --sysupgrade

Met à niveau tous les paquets qui sont obsolètes. Chaque paquet installé actuellement sera examiné et mis à niveau si un paquet plus récent existe. Un rapport de tous les paquets à mettre à niveau sera présenté, et l'opération ne se poursuivra pas sans confirmation de l'utilisateur. Les dépendances sont résolues automatiquement à ce niveau et seront installées/mises à niveau si nécessaire.

Passez cette option deux fois pour activer la rétrogradation des paquets ; dans ce cas, pacman sélectionnera les paquets de synchronisation dont les versions ne correspondent pas aux versions locales. Ceci peut être utile lorsque l'utilisateur passe d'un dépôt de test à un dépôt stable.

Des cibles supplémentaires peuvent également être spécifiées manuellement, de sorte que -Su foo effectuera une mise à niveau du système et installera/mettra à niveau le paquet "foo" dans la même opération.

-y, --refresh

Télécharge une nouvelle copie des bases de données maîtres des paquets (repo.db) depuis le(s) serveur(s) défini(s) dans pacman.conf(5). Ceci devrait généralement être utilisé à chaque fois que vous utilisez --sysupgrade ou -u. Passer deux options --refresh ou -y forcera une actualisation de toutes les bases de données de paquets, même si elles semblent être à jour.

OPTIONS DE BASE DE DONNÉES (APPLICABLES À -D)

--asdeps <package>

Marque un paquet comme non installé explicitement ; en d'autres termes, définit sa raison d'installation comme étant installé en tant que dépendance.

--asexplicit <package>

Marque un paquet comme installé explicitement ; en d'autres termes, définit sa raison d'installation comme étant installée explicitement. Ceci est utile si vous voulez garder un paquet installé même s'il a été initialement installé comme dépendance d'un autre paquet.

-k, --check

Vérifie la cohérence interne de la base de données locale des paquets. Ceci vérifiera que tous les fichiers requis sont présents et que les paquets installés ont les dépendances requises, n'entrent pas en conflit et que plusieurs paquets ne possèdent pas le même fichier. Spécifier cette option deux fois effectuera une vérification sur les bases de données de synchronisation pour s'assurer que toutes les dépendances spécifiées sont disponibles.

-q, --quiet

Supprime les messages en cas de succès des opérations de base de données.

OPTIONS DE FICHIER (APPLICABLES À -F)

-y, --refresh

Télécharge les bases de données de fichiers de paquets (repo.files) fraîches depuis le serveur. Utilisez deux fois pour forcer une actualisation même si les bases de données sont à jour.

-l, --list

Liste les fichiers appartenant au paquet interrogé.

-x, --regex

Interprète chaque requête comme une expression régulière.

-q, --quiet

Affiche moins d'informations pour certaines opérations sur les fichiers. Ceci est utile lorsque la sortie de pacman est traitée dans un script, cependant, vous pourriez vouloir utiliser --machinereadable à la place.

--machinereadable

Affiche chaque correspondance dans un format de sortie lisible par machine. Le format est repository\0pkgname\0pkgver\0path\n où \0 est le caractère NULL et \n un saut de ligne.

GESTION DES FICHIERS DE CONFIGURATION

Pacman utilise la même logique que rpm pour déterminer l'action à entreprendre sur les fichiers désignés pour être sauvegardés. Lors d'une mise à niveau, trois hachages MD5 sont utilisés pour chaque fichier de sauvegarde afin de déterminer l'action requise : un pour le fichier original installé, un pour le nouveau fichier qui est sur le point d'être installé, et un pour le fichier réel existant sur le système de fichiers. Après comparaison de ces trois hachages, les scénarios suivants peuvent en résulter :

original=X, current=X, new=X

Les trois fichiers sont identiques, donc les écrasements ne sont pas un problème. Installez le nouveau fichier.

original=X, current=X, new=Y

Le fichier actuel est identique à l'original, mais le nouveau est différent. Comme l'utilisateur n'a jamais modifié le fichier, et que le nouveau peut contenir des améliorations ou des corrections de bugs, installez le nouveau fichier.

original=X, current=Y, new=X

Les deux versions du paquet contiennent exactement le même fichier, mais celui du système de fichiers a été modifié. Laissez le fichier actuel en place.

original=X, current=Y, new=Y

Le nouveau fichier est identique au fichier actuel. Installez le nouveau fichier.

original=X, current=Y, new=Z

Les trois fichiers sont différents, donc installez le nouveau fichier avec une extension .pacnew et avertissez l'utilisateur. L'utilisateur doit alors fusionner manuellement les changements nécessaires dans le fichier original.

original=NULL, current=Y, new=Z

Le paquet n'était pas précédemment installé, et le fichier existe déjà sur le système de fichiers. Installez le nouveau fichier avec une extension .pacnew et avertissez l'utilisateur. L'utilisateur doit alors fusionner manuellement les changements nécessaires dans le fichier original.

EXEMPLES

pacman -Ss ne.hack

Recherche l'expression régulière "ne.hack" dans la base de données des paquets.

pacman -S gpm

Télécharge et installe gpm ainsi que ses dépendances.

pacman -U /home/user/ceofhack-0.6-1-x86_64.pkg.tar.gz

Installe le paquet ceofhack-0.6-1 à partir d'un fichier local.

pacman -Syu

Met à jour la liste des paquets et met à niveau tous les paquets ensuite.

pacman -Syu gpm

Met à jour la liste des paquets, met à niveau tous les paquets, puis installe gpm s'il n'était pas déjà installé.

BOGUES

Bogues ? Vous plaisantez ; il n'y a pas de bogues dans ce logiciel. Mais si nous nous trompons, veuillez les signaler au traqueur de problèmes à https://gitlab.archlinux.org/pacman/pacman/-/issues avec des informations spécifiques telles que votre ligne de commande, la nature du bogue, et même la base de données des paquets si cela peut aider.
