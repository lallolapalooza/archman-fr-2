INTRODUCTION

Tcl inclut une bibliothèque de procédures Tcl pour les fonctions couramment nécessaires. Les procédures définies dans la bibliothèque Tcl sont génériques et conviennent à de nombreuses applications différentes. L'emplacement de la bibliothèque Tcl est retourné par la commande info library. En plus de la bibliothèque Tcl, chaque application possède normalement sa propre bibliothèque de procédures de support ; l'emplacement de cette bibliothèque est normalement indiqué par la valeur de la variable globale $app_library, où app est le nom de l'application. Par exemple, l'emplacement de la bibliothèque Tk est conservé dans la variable tk_library.

Pour accéder aux procédures de la bibliothèque Tcl, une application doit sourcer le fichier init.tcl dans la bibliothèque, par exemple avec la commande Tcl

source [file join [info library] init.tcl]

Si la procédure de bibliothèque Tcl_Init est invoquée depuis la procédure Tcl_AppInit d'une application, cela se produit automatiquement. Le code dans init.tcl définira la procédure unknown et organisera le chargement des autres procédures à la demande en utilisant le mécanisme de chargement automatique défini ci-dessous.

PROCÉDURES DE COMMANDES

Les procédures suivantes sont fournies dans la bibliothèque Tcl :

auto_execok cmd
Détermine s'il existe un fichier exécutable ou une commande intégrée au shell du nom cmd. Si c'est le cas, elle renvoie une liste d'arguments à passer à exec pour exécuter le fichier exécutable ou la commande intégrée nommée par cmd. Sinon, elle renvoie une chaîne vide. Cette commande examine les répertoires dans le chemin de recherche actuel (donné par la variable d'environnement PATH) dans sa recherche d'un fichier exécutable nommé cmd. Sur les plateformes Windows, la recherche est étendue avec les mêmes répertoires et extensions de fichiers que ceux utilisés par exec. Auto_execok mémorise les informations sur les recherches précédentes dans un tableau nommé auto_execs ; cela évite la recherche dans le chemin lors des appels ultérieurs pour le même cmd. La commande auto_reset peut être utilisée pour forcer auto_execok à oublier ses informations mises en cache.
auto_import pattern
Auto_import est invoquée lors de namespace import pour voir si les commandes importées spécifiées par pattern résident dans une bibliothèque préchargée. Si c'est le cas, les commandes sont chargées afin qu'elles soient disponibles pour l'interpréteur pour créer les liens d'importation. Si les commandes ne résident pas dans une bibliothèque préchargée, auto_import ne fait rien. La correspondance des motifs est effectuée selon les règles de correspondance de namespace import.
auto_load cmd
Cette commande tente de charger la définition d'une commande Tcl nommée cmd. Pour ce faire, elle recherche un *chemin de chargement automatique* (auto-load path), qui est une liste d'un ou plusieurs répertoires. Le chemin de chargement automatique est donné par la variable globale auto_path s'il existe. S'il n'y a pas de variable auto_path, alors la variable d'environnement TCLLIBPATH est utilisée, si elle existe. Sinon, le chemin de chargement automatique se compose uniquement du répertoire de la bibliothèque Tcl. Dans chaque répertoire du chemin de chargement automatique, il doit y avoir un fichier tclIndex qui décrit une ou plusieurs commandes définies dans ce répertoire et un script à évaluer pour charger chacune des commandes. Le fichier tclIndex doit être généré avec la commande auto_mkindex. Si cmd est trouvé dans un fichier d'index, alors le script approprié est évalué pour créer la commande. La commande auto_load renvoie 1 si cmd a été créé avec succès. La commande renvoie 0 s'il n'y avait pas d'entrée d'index pour cmd ou si le script n'a pas réellement défini cmd (par exemple, parce que les informations d'index sont obsolètes). Si une erreur se produit lors du traitement du script, cette erreur est renvoyée. Auto_load ne lit les informations d'index qu'une seule fois et les enregistre dans le tableau auto_index ; les appels ultérieurs à auto_load vérifient cmd dans le tableau plutôt que de relire les fichiers d'index. Les informations d'index mises en cache peuvent être supprimées avec la commande auto_reset. Cela forcera la prochaine commande auto_load à recharger la base de données d'index depuis le disque.
auto_mkindex dir pattern pattern ...
Génère un index adapté à l'utilisation par auto_load. La commande recherche dans dir tous les fichiers dont les noms correspondent à l'un des arguments pattern (la correspondance est effectuée avec la commande glob), génère un index de toutes les procédures de commande Tcl définies dans tous les fichiers correspondants, et stocke les informations d'index dans un fichier nommé tclIndex dans dir. Si aucun modèle n'est donné, un modèle de *.tcl sera supposé. Par exemple, la commande
auto_mkindex foo *.tcl

lira tous les fichiers .tcl dans le sous-répertoire foo et générera un nouveau fichier d'index foo/tclIndex.

Auto_mkindex analyse les scripts Tcl en les sourçant dans un interpréteur enfant et en surveillant les commandes proc et namespace qui sont exécutées. Les extensions peuvent utiliser le paquet (non documenté) auto_mkindex_parser pour enregistrer d'autres commandes qui peuvent contribuer à l'index de chargement automatique. Vous devrez lire auto.tcl pour voir comment cela fonctionne.

Auto_mkindex_old (qui a la même syntaxe que auto_mkindex) analyse les scripts Tcl d'une manière relativement peu sophistiquée : si une ligne contient le mot « proc » comme premiers caractères, elle est supposée être une définition de procédure et le mot suivant de la ligne est pris comme nom de la procédure. Les définitions de procédure qui n'apparaissent pas de cette manière (par exemple, elles ont des espaces avant proc) ne seront pas indexées. Si votre script contient du code « dangereux », tel que du code d'initialisation global ou des noms de procédure avec des caractères spéciaux comme $, *, [ ou ], vous serez plus en sécurité en utilisant auto_mkindex_old.

auto_reset
Détruit toutes les informations mises en cache par auto_execok et auto_load. Ces informations seront relues depuis le disque la prochaine fois qu'elles seront nécessaires. Auto_reset supprime également toutes les procédures listées dans l'index de chargement automatique, de sorte que de nouvelles copies d'entre elles seront chargées la prochaine fois qu'elles seront utilisées.
auto_qualify command namespace
Calcule une liste de noms complètement qualifiés pour command. Cette liste reflète le chemin suivi par un interpréteur Tcl standard pour la recherche de commandes : il cherche d'abord la commande dans l'espace de noms actuel, puis dans l'espace de noms global. Par conséquent, si command est relatif et que namespace n'est pas ::, la liste retournée a deux éléments : command qualifié par namespace, comme s'il s'agissait d'une commande dans l'espace de noms namespace ; et command comme s'il s'agissait d'une commande dans l'espace de noms global. Sinon, si command est absolu (il commence par ::), ou si namespace est ::, la liste ne contient que command comme s'il s'agissait d'une commande dans l'espace de noms global.

Auto_qualify est utilisé par les installations de chargement automatique dans Tcl, à la fois pour produire des index de chargement automatique tels que pkgIndex.tcl, et pour effectuer le chargement automatique réel des fonctions au moment de l'exécution.

tcl_findLibrary basename version patch initScript enVarName varName
Ceci

… est une procédure Tcl qui recherche une bibliothèque de scripts Tcl. Elle recherche des scripts dans une hiérarchie de répertoires qui correspondent à un nom de base donné, basename, et une version donnée, version. La recherche des bibliothèques est effectuée en recherchant un chemin de la forme basename/version dans les répertoires spécifiés par la variable globale auto_path. La variable d'environnement TCLLIBPATH est également prise en compte, et s'il n'y a rien d'autre, le répertoire de la bibliothèque Tcl est utilisé. Si plusieurs correspondances sont trouvées, la procédure retourne la plus récente. Une fois la bibliothèque trouvée, la procédure source le fichier initScript (s'il est spécifié), le résultat est stocké dans varName, et le nom du répertoire racine de la bibliothèque est stocké dans enVarName. L'argument patch est une version de correctif qui est comparée à celle du répertoire trouvé pour un certain degré de compatibilité. Si aucune bibliothèque ne correspond, une erreur est générée. Cette procédure est une version Tcl de la fonction C `Tcl_FindLibrary`.

parray arrayName ?pattern?
Imprime toutes les valeurs des éléments du tableau arrayName. Si pattern est spécifié, seules les valeurs dont les noms d'index correspondent à pattern (selon les règles de glob) sont imprimées. La sortie est formatée sous forme d'une liste de paires nom-valeur.
tcl_endOfWord str start
Retourne l'index du dernier caractère d'un mot dans la chaîne str commençant à l'index start. Le début d'un mot est défini comme le premier caractère non vide après une séquence de caractères vides ou le début de la chaîne. La fin d'un mot est définie comme le dernier caractère non vide avant une séquence de caractères vides ou la fin de la chaîne.
tcl_startOfNextWord str start
Retourne l'index du premier caractère d'un mot dans la chaîne str après l'index start. Le mot est défini comme le premier caractère non vide après une séquence de caractères vides ou la fin de la chaîne.
tcl_startOfPreviousWord str start
Retourne l'index du premier caractère d'un mot dans la chaîne str avant l'index start. Le mot est défini comme le dernier caractère non vide avant une séquence de caractères vides ou le début de la chaîne.
tcl_wordBreakAfter str start
Retourne l'index du premier caractère vide après le caractère à l'index start dans la chaîne str. Si le caractère à l'index start n'est pas vide, cette procédure retourne l'index du premier caractère vide après le mot contenant le caractère à l'index start. Si le caractère à l'index start est vide, cette procédure retourne l'index du caractère vide suivant.
tcl_wordBreakBefore str start
Retourne l'index du dernier caractère vide avant le caractère à l'index start dans la chaîne str. Si le caractère à l'index start n'est pas vide, cette procédure retourne l'index du caractère vide avant le mot contenant le caractère à l'index start. Si le caractère à l'index start est vide, cette procédure retourne l'index du caractère vide précédent.

s est une procédure de recherche standard destinée à être utilisée par les extensions lors de leur initialisation. Elles appellent cette procédure pour rechercher leur bibliothèque de scripts dans plusieurs répertoires standard. Le dernier composant du nom du répertoire de la bibliothèque est normalement basenameversion (par exemple, tk8.0), mais il peut être « library » dans les hiérarchies de build. Le fichier initScript sera sourcé dans l'interpréteur une fois qu'il sera trouvé. Le répertoire dans lequel ce fichier est trouvé est stocké dans la variable globale varName. Si cette variable est déjà définie (par exemple, par du code C lors de l'initialisation de l'application) alors aucune recherche n'est effectuée. Sinon, la recherche s'effectue dans les répertoires suivants : le répertoire nommé par la variable d'environnement enVarName ; par rapport au répertoire de la bibliothèque Tcl ; par rapport au fichier exécutable dans le répertoire standard d'installation bin ou bin/arch ; par rapport au fichier exécutable dans l'arbre de build actuel ; par rapport au fichier exécutable dans un arbre de build parallèle.
parray nomTableau ?motif?
Affiche sur la sortie standard les noms et les valeurs de tous les éléments du tableau nomTableau, ou seulement les noms qui correspondent au motif (en utilisant les règles de correspondance de string match) et leurs valeurs si le motif est donné. nomTableau doit être un tableau accessible par l'appelant de parray. Il peut être local ou global.

AIDE LIMITE DES MOTS

Ces procédures sont principalement utilisées en interne par Tk.

tcl_endOfWord str debut
Retourne l'index du premier emplacement de fin de mot qui se produit après un index de départ debut dans la chaîne str. Un emplacement de fin de mot est défini comme le premier caractère non-mot suivant le premier caractère mot après le point de départ. Retourne -1 s'il n'y a plus d'emplacements de fin de mot après le point de départ. Voir la description de tcl_wordchars et tcl_nonwordchars ci-dessous pour plus de détails sur la façon dont Tcl détermine quels caractères sont des caractères mots.
tcl_startOfNextWord str debut
Retourne l'index du premier emplacement de début de mot qui se produit après un index de départ debut dans la chaîne str. Un emplacement de début de mot est défini comme le premier caractère mot suivant un caractère non-mot. Retourne -1 s'il n'y a plus d'emplacements de début de mot après le point de départ.
tcl_startOfPreviousWord str debut
Retourne l'index du premier emplacement de début de mot qui se produit avant un index de départ debut dans la chaîne str. Retourne -1 s'il n'y a plus d'emplacements de début de mot avant le point de départ.
tcl_wordBreakAfter str debut
Retourne l'index de la première limite de mot après l'index de départ debut dans la chaîne str. Retourne -1 s'il n'y a plus de limites après le point de départ dans la chaîne donnée. L'index retourné fait référence au second caractère de la paire qui constitue une limite.
tcl_wordBreakBefore str debut
Retourne l'index de la première limite de mot avant l'index de départ debut dans la chaîne str. Retourne -1 s'il n'y a plus de limites avant le point de départ dans la chaîne donnée. L'index retourné fait référence au second caractère de la paire qui constitue une limite.

VARIABLES

Les variables globales suivantes sont définies ou utilisées par les procédures de la bibliothèque Tcl. Elles appartiennent à deux grandes catégories : la gestion des commandes inconnues et des paquets, et la détermination de ce qui constitue un mot.

VARIABLES DE CHARGEMENT AUTOMATIQUE ET DE GESTION DES PAQUETS

auto_execs
Utilisé par auto_execok pour enregistrer des informations sur l'existence ou non de commandes particulières en tant que fichiers exécutables.
auto_index
Utilisé par auto_load pour sauvegarder les informations d'index lues depuis le disque.
auto_noexec
Si définie à une quelconque valeur, alors unknown n'essaiera pas d'exécuter automatiquement des commandes.
auto_noload
Si définie à une quelconque valeur, alors unknown n'essaiera pas de charger automatiquement des commandes.
auto_path
Si définie, alors elle doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations de chargement automatique (y compris pour les fichiers d'index de paquets lors de l'utilisation du gestionnaire par défaut package unknown). Cette variable est initialisée lors du démarrage pour contenir, dans l'ordre : les répertoires listés dans la variable d'environnement TCLLIBPATH, le répertoire nommé par la variable globale tcl_library, le répertoire parent de tcl_library, les répertoires listés dans la variable tcl_pkgPath. Des emplacements supplémentaires pour rechercher des fichiers et des index de paquets devraient normalement être ajoutés à cette variable en utilisant lappend.
env(TCL_LIBRARY)
Si définie, alors elle spécifie l'emplacement du répertoire contenant les scripts de bibliothèque (la valeur de cette variable sera assignée à la variable tcl_library et retournée par conséquent par la commande info library). Si cette variable n'est pas définie, une valeur par défaut est utilisée.
env(TCLLIBPATH)
Si définie, alors elle doit contenir une liste Tcl valide donnant les répertoires à rechercher lors des opérations de chargement automatique. Les répertoires doivent être spécifiés au format Tcl, en utilisant « / » comme séparateur de chemin, quelle que soit la plateforme. Cette variable n'est utilisée que lors de l'initialisation de la variable auto_path.

VARIABLES DE DETERMINATION DES LIMITES DE MOTS

Ces variables ne sont utilisées que dans les commandes tcl_endOfWord, tcl_startOfNextWord, tcl_startOfPreviousWord, tcl_wordBreakAfter et tcl_wordBreakBefore.

tcl_nonwordchars
Cette variable contient une expression régulière qui est utilisée par des routines comme tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non. Si le motif correspond à un caractère, le caractère est considéré comme un caractère non-mot. Sur les plateformes Windows, les espaces, les tabulations et les nouvelles lignes sont considérés comme des caractères non-mots. Sous Unix, tout ce qui n'est pas un chiffre, une lettre ou un underscore est considéré comme un caractère non-mot.
tcl_wordchars
Cette variable contient une expression régulière qui est utilisée par des routines comme tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non. Si le motif correspond à un caractère, le caractère est considéré comme un caractère mot. Sur les plateformes Windows, les mots sont composés de tout caractère qui n'est pas un espace, une tabulation ou une nouvelle ligne. Sous Unix, les mots sont composés de chiffres, de lettres ou d'underscores.
