NOM

pam_winbind - Module PAM pour Winbind

DESCRIPTION

Cet outil fait partie de la suite samba(7).

pam_winbind est un module PAM qui peut authentifier les utilisateurs par rapport au domaine local en communiquant avec le démon Winbind.

SYNTAXE

Modifiez le fichier de configuration système PAM /etc/pam.d/service et modifiez-le comme le montre l'exemple suivant :

    ...
    auth      required        pam_env.so
    auth      sufficient      pam_unix2.so
+++ auth      required        pam_winbind.so  use_first_pass
    account   requisite       pam_unix2.so
+++ account   required        pam_winbind.so  use_first_pass
+++ password  sufficient      pam_winbind.so
    password  requisite       pam_pwcheck.so  cracklib
    password  required        pam_unix2.so    use_authtok
    session   required        pam_unix2.so
+++ session   required        pam_winbind.so
    ...

Assurez-vous que pam_winbind est l'un des premiers modules dans la partie session. Il peut récupérer des tickets kerberos qui sont nécessaires à d'autres modules.

OPTIONS

pam_winbind prend en charge plusieurs options qui peuvent être définies soit dans les fichiers de configuration PAM, soit dans le fichier de configuration pam_winbind situé à /etc/security/pam_winbind.conf. Les options du fichier de configuration PAM ont la priorité sur celles du fichier de configuration. Voir pam_winbind.conf(5) pour plus de détails.

debug

Fournit une sortie de débogage à syslog.

debug_state

Fournit une sortie de débogage détaillée de l'état PAM à syslog.

require_membership_of=[SID ou NOM]

Si cette option est définie, pam_winbind ne réussira que si l'utilisateur est membre du SID ou du NOM donné. Un SID peut être un SID de groupe, un SID d'alias ou même un SID d'utilisateur. Il est également possible de donner un NOM au lieu du SID. Ce nom doit avoir la forme : MONDOMAINE\mongroupe ou MONDOMAINE\monutilisateur (où le caractère '\' correspond à la valeur du paramètre winbind separator). Il est également possible d'utiliser un UPN sous la forme utilisateur@REALM ou groupe@REALM. pam_winbind recherchera alors le SID en interne. Notez que NOM ne peut contenir d'espaces. Il est donc recommandé d'utiliser uniquement des SIDs. Vous pouvez vérifier la liste des SIDs dont un utilisateur est membre avec wbinfo --user-sids=SID.

Cette option ne doit être spécifiée que sur une déclaration de module d'authentification, car elle n'opère qu'en conjonction avec l'authentification par mot de passe.

use_first_pass

Par défaut, pam_winbind essaie d'obtenir le jeton d'authentification d'un module précédent. Si aucun jeton n'est disponible, il demande à l'utilisateur l'ancien mot de passe. Avec cette option, pam_winbind s'arrête avec une erreur si aucun jeton d'authentification d'un module précédent n'est disponible.

try_first_pass

Identique à l'option use_first_pass (élément précédent), sauf que si le mot de passe principal n'est pas valide, PAM demandera un mot de passe.

use_authtok

Définit le nouveau mot de passe sur celui fourni par le module de mot de passe précédemment empilé. Si cette option n'est pas définie, pam_winbind demandera le nouveau mot de passe à l'utilisateur.

try_authtok

Identique à l'option use_authtok (élément précédent), sauf que si le nouveau mot de passe n'est pas valide, PAM demandera un mot de passe.

krb5_auth

pam_winbind peut s'authentifier en utilisant Kerberos lorsque winbindd communique avec un contrôleur de domaine Active Directory. L'authentification Kerberos doit être activée avec ce paramètre. Lorsque l'authentification Kerberos ne peut pas réussir (par exemple, en raison d'un décalage d'horloge), winbindd utilisera l'authentification samlogon sur MSRPC en dernier recours. Lorsque ce paramètre est utilisé conjointement avec winbind refresh tickets, winbind maintiendra votre Ticket Granting Ticket (TGT) à jour en le rafraîchissant si nécessaire.

krb5_ccache_type=[type]

Lorsque pam_winbind est configuré pour essayer l'authentification kerberos en activant l'option krb5_auth, il peut stocker le Ticket Granting Ticket (TGT) récupéré dans un cache de crédentialité. Le type de cache de crédentialité peut être contrôlé avec cette option. Les valeurs prises en charge sont : KCM ou KEYRING (lorsque pris en charge par la bibliothèque Kerberos du système et le système d'exploitation), FILE et DIR (lorsque le type DIR est pris en charge par la bibliothèque Kerberos du système). Dans le cas de FILE, un cache de crédentialité sous la forme /tmp/krb5cc_UID sera créé - dans le cas de DIR, vous DEVEZ spécifier un répertoire qui doit exister, le répertoire UID sera créé dans le répertoire spécifié. Dans tous les cas, UID est remplacé par l'identifiant utilisateur numérique. Vérifiez les détails de l'implémentation Kerberos.

En utilisant le type KEYRING, le mécanisme pris en charge est « KEYRING:persistent:UID », qui utilise le keyring du noyau Linux pour stocker les crédentialités par UID. KEYRING a des limitations. Par exemple, il s'agit de mémoire sécurisée du noyau, donc le stockage en bloc des crédentialités n'est pas possible.

En utilisant le type KCM, le mécanisme pris en charge est « KCM:UID », qui utilise un gestionnaire de crédentialités Kerberos pour stocker les crédentialités par UID, similaire à KEYRING. C'est le choix recommandé sur les dernières distributions Linux qui proposent un Gestionnaire de Crédentialités Kerberos. Sinon, nous suggérons d'utiliser KEYRING, car ce sont les méthodes les plus sûres et les plus prévisibles.

Il est également possible de définir des chemins de fichiers personnalisés et d'utiliser le modèle « %u » afin de substituer l'identifiant utilisateur numérique. Exemples :

krb5_ccache_type = DIR:/run/user/%u/krb5cc

Ceci créera un fichier de cache de crédentialité dans le répertoire spécifié.

krb5_ccache_type = FILE:/tmp/krb5cc_%u

Ceci créera un fichier de cache de crédentialité.

Laissez vide pour simplement effectuer l'authentification kerberos sans avoir de cache de ticket après que la connexion ait réussi. Ce paramètre est vide par défaut.

cached_login

Winbind permet de se connecter en utilisant des crédentialités mises en cache lorsque winbind offline logon est activé. Pour utiliser cette fonctionnalité à partir du module PAM, cette option doit être définie.

silent

Ne pas émettre de messages.

mkhomedir

Crée le répertoire personnel d'un utilisateur à la volée, l'option est valide dans le bloc de session PAM.

warn_pwd_expire

Définit le nombre de jours avant que pam_winbind ne commence à avertir des mots de passe qui vont expirer. Par défaut, 14 jours.

EXPORTATIONS DE DONNÉES PAM

Cette section décrit les données exportées dans la pile PAM qui pourraient être utilisées dans d'autres modules PAM.

PAM_WINBIND_HOMEDIR

Ceci est le répertoire personnel Windows défini dans l'onglet profil des paramètres utilisateur sur le serveur Active Directory. Il peut s'agir d'un chemin local ou d'un répertoire sur un partage mappé à un lecteur.

PAM_WINBIND_LOGONSCRIPT

Le chemin du script de connexion qui doit être exécuté si un utilisateur se connecte. Il s'agit normalement d'un chemin relatif au script stocké sur le serveur.

PAM_WINBIND_LOGONSERVER

Ceci exporte le serveur Active Directory auquel nous nous authentifions. Cela peut être utilisé comme variable ultérieurement.

PAM_WINBIND_PROFILEPATH

C'est le chemin du profil défini dans l'onglet profil des paramètres utilisateur. Normalement, le répertoire personnel est synchronisé avec ce répertoire sur un partage.
