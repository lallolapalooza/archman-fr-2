NOM

pam_cap - Module PAM pour les capacités

SYNTAXE

[nom-du-service] auth indicateur-contrôle pam_cap [options]

DESCRIPTION

Le module pam_so peut être utilisé pour spécifier des capacités héritables pour les arbres de processus racine dans l'application PAM. Le module prend également en charge le blocage des capacités du vecteur Bounding et l'ajout de capacités du vecteur Ambient.

Pour que les applications PAM générales fonctionnent correctement, l'application doit être exécutée avec au moins CAP_SETPCAP activé dans son vecteur de capacités Permitted. De nombreuses applications PAM s'exécutent en tant que root, qui possède tous les bits du vecteur Bounding activés, donc cette exigence est généralement satisfaite. Pour accorder une capacité de vecteur Ambient, le bit Permitted correspondant doit également être disponible pour l'application.

Le module pam_so est un module auth de Linux-PAM. Il fournit des fonctionnalités pour prendre en charge pam_sm_authenticate() et pam_sm_setcred(). C'est ce dernier qui modifie réellement le triplet IAB héritable des vecteurs de capacités. Dans une configuration d'application typique, vous pourriez avoir une ligne comme celle-ci :

auth    optional    pam_cap.so

Les arguments du module sont :

○
debug : Bien que pris en charge, il s'agit d'une opération nulle pour le moment.
○
config=/chemin/vers/fichier : Remplace la configuration par défaut du module. La valeur par défaut non spécifiée pour ce fichier est /etc/security/capability.conf. Notez que config=/dev/null est une valeur valide. Voir default= ci-dessous pour les situations où cela pourrait être approprié.
○
keepcaps : C'est tout ce que le module pam_cap.so peut faire pour aider une application à prendre en charge l'utilisation du vecteur de capacités Ambient. La prise en charge des applications pour l'ensemble Ambient est médiocre à l'heure actuelle.
○
autoauth : Cet argument fait que le module pam_cap.so renvoie PAM_SUCCESS si l'utilisateur PAM_USER authentifié existe. L'absence de cet argument fera que pam_cap.so ne renverra PAM_SUCCESS que si l'utilisateur PAM_USER est couvert par une règle spécifique dans le fichier de configuration prédominant.
○
default=IAB : Cet argument est ignoré si le fichier de configuration prédominant contient une règle "*". S'il n'y a pas de telle règle, le triplet IAB est inséré à la fin du fichier de configuration et s'applique à tous les PAM_USER non couverts par une règle antérieure. Notez que si vous voulez que tous les PAM_USER soient couverts par cette règle par défaut, vous pouvez fournir l'argument de module config=/dev/null.
○
defer : Cet argument organise l'ajout des capacités IAB accordées à un utilisateur suffisamment tard dans la pile d'authentification Linux-PAM pour qu'elles persistent. C'est-à-dire, après que l'application ait effectué son appel setuid(UID). Ainsi, en conjonction avec l'argument de module keepcaps, de telles applications conformes peuvent prendre en charge l'octroi de capacités de vecteur Ambient avec pam_cap.so.

VOIR AUSSI

pam.conf(5), capability.conf(5), cap_text_formats(7), pam(8).
