package(n) Commandes intégrées Tcl package(n)

NOM

package - Mécanismes pour le chargement et le contrôle de version des paquets

SYNOPIS

package forget ?paquet paquet ...?
package ifneeded paquet version ?script?
package names
package present paquet ?exigence...?
package present -exact paquet version
package provide paquet ?version?
package require paquet ?exigence...?
package require -exact paquet version
package unknown ?commande?
package vcompare version1 version2
package versions paquet
package vsatisfies version exigence...
package prefer ?latest|stable?

DESCRIPTION

Cette commande maintient une base de données simple des paquets disponibles pour utilisation par l'interpréteur courant et comment les charger dans cet interpréteur. Elle supporte plusieurs versions de chaque paquet et organise le chargement de la bonne version d'un paquet en fonction de ce qui est requis par l'application. Cette commande détecte et signale aussi les conflits de version. Typiquement, seules les commandes package require et package provide sont appelées dans les scripts Tcl normaux ; les autres commandes sont principalement utilisées par les scripts système qui maintiennent la base de données des paquets.

Le comportement de la commande package est déterminé par son premier argument. Les formes suivantes sont permises :

package forget ?paquet paquet ...?
Supprime toutes les informations relatives à chaque paquet spécifié de cet interpréteur, y compris les informations fournies par package ifneeded et package provide.
package ifneeded paquet version ?script?
Cette commande n'apparaît typiquement que dans les scripts de configuration système pour mettre en place la base de données des paquets. Elle indique qu'une version particulière d'un paquet particulier est disponible si nécessaire, et que le paquet peut être ajouté à l'interpréteur en exécutant script. Le script est sauvegardé dans une base de données pour utilisation par les commandes package require ultérieures ; typiquement, script configure l'auto-chargement des commandes du paquet (ou appelle directement load et/ou source), puis appelle package provide pour indiquer que le paquet est présent. Il peut y avoir des informations dans la base de données pour plusieurs versions différentes d'un même paquet. Si la base de données contient déjà des informations pour paquet et version, le nouveau script remplace celui qui existe. Si l'argument script est omis, le script courant pour la version version du paquet paquet est retourné, ou une chaîne vide si aucune commande package ifneeded n'a été appelée pour ce paquet et cette version.
package names
Retourne une liste des noms de tous les paquets dans l'interpréteur pour lesquels une version a été fournie (via package provide) ou pour lesquels un script package ifneeded est disponible. L'ordre des éléments dans la liste est arbitraire.
package present ?-exact? paquet ?exigence...?
Cette commande est équivalente à package require sauf qu'elle n'essaie pas de charger le paquet s'il n'est pas déjà chargé.
package provide paquet ?version?
Cette commande est appelée pour indiquer que la version version du paquet paquet est maintenant présente dans l'interpréteur. Elle est typiquement appelée une fois dans le cadre d'un script ifneeded, et à nouveau par le paquet lui-même lorsqu'il est finalement chargé. Une erreur se produit si une version différente de paquet a été fournie par une commande package provide précédente. Si l'argument version est omis, alors la commande retourne le numéro de version qui est actuellement fourni, ou une chaîne vide si aucune commande package provide n'a été appelée pour paquet dans cet interpréteur.
package require paquet ?exigence...?
Cette commande est typiquement appelée par le code Tcl qui souhaite utiliser une version particulière d'un paquet particulier. Les arguments indiquent quel paquet est souhaité, et la commande assure qu'une version appropriée du paquet est chargée dans l'interpréteur. Si la commande réussit, elle retourne le numéro de version qui est chargé ; sinon, elle génère une erreur.

Une version appropriée du paquet est toute version qui satisfait au moins une des exigences, selon les règles de package vsatisfies. Si plusieurs versions sont appropriées, l'implémentation avec la version la plus élevée est choisie. Ceci est en outre influencé par le mode de sélection défini avec package prefer.

En mode de sélection “stable”, la commande sélectionnera la version stable la plus élevée satisfaisant aux exigences, s'il y en a. Si aucune version stable ne satisfait aux exigences, la version instable la plus élevée satisfaisant aux exigences sera sélectionnée. En mode de sélection “latest” (la plus récente), la commande acceptera la version la plus élevée satisfaisant à toutes les exigences, indépendamment de sa stabilité.

Si une version de paquet a déjà été fournie (en appelant la commande package provide), alors son numéro de version doit satisfaire aux exigences et la commande retourne immédiatement. Sinon, la commande recherche dans la base de données des informations fournies par les commandes package ifneeded précédentes pour voir si une version acceptable du paquet est disponible. Si c'est le cas, le script de la version acceptable la plus élevée est évalué dans l'espace de noms global ; il doit faire tout ce qui est nécessaire pour charger le paquet, y compris appeler package provide pour le paquet. Si la base de données package ifneeded ne contient pas de version acceptable du paquet et qu'une commande package unknown a été spécifiée pour l'interpréteur, alors cette commande est évaluée dans l'espace de noms global ; lorsqu'elle est terminée, Tcl vérifie à nouveau si le paquet est maintenant fourni ou s'il existe un script package ifneeded pour lui. Si toutes ces étapes échouent à fournir une version acceptable du paquet, alors la commande retourne une erreur.

package require -exact paquet version
Cette forme de la commande est utilisée lorsque seule la version donnée de paquet est acceptable par l'appelant. Cette commande est équivalente à package require paquet version-version.
package unknown ?commande?
Cette commande fournit une commande de “dernier recours” à invoquer lors d'un package require si aucune version appropriée d'un paquet ne peut être trouvée dans la base de données package ifneeded. Si l'argument commande est fourni, il contient la première partie d'une commande ; lorsque la commande est invoquée lors d'une commande package require, Tcl ajoute un ou plusieurs arguments supplémentaires donnant le nom du paquet et les exigences souhaitées. Par exemple, si commande est foo bar et plus tard la commande package require test 2.4 est invoquée, alors Tcl exécutera la commande foo bar test 2.4 pour charger le paquet. Si aucune exigence n'est fournie à la commande package require, alors seul le nom sera ajouté à la commande invoquée. Si la commande package unknown est invoquée sans argument commande, alors le script package unknown courant est retourné, ou une chaîne vide s'il n'y en a pas. Si commande est spécifié comme une chaîne vide, alors le script package unknown courant est supprimé, s'il y en a un.
package vcompare version1 version2
Compare les deux numéros de version donnés par version1 et version2. Retourne -1 si version1 est une version antérieure à version2, 0 s'ils sont égaux, et 1 si version1 est une version ultérieure à version2.
package versions paquet
Retourne une liste de tous les numéros de version du paquet pour lesquels des informations ont été fournies par les commandes package ifneeded.
package vsatisfies version exigence...
Retourne 1 si la version satisfait à au moins une des exigences données, et 0 sinon.

package prefer ?latest|stable?
Sans arguments, la commande renvoie soit « latest » soit « stable », selon le mode actuel de la logique de sélection utilisé par package require.

Lorsqu'elle reçoit l'argument « latest », elle définit le mode de logique de sélection sur « latest ».

Lorsqu'elle reçoit l'argument « stable », si le mode est déjà « stable », cette valeur est conservée. Si le mode est déjà « latest », alors la tentative de le ramener à « stable » est inefficace et la valeur du mode reste « latest ».

Lorsqu'elle reçoit une autre valeur comme argument, elle génère une erreur d'argument invalide.

Lorsqu'un interpréteur est créé, sa valeur de mode de sélection initiale est définie sur « stable », à moins que la variable d'environnement TCL_PKG_PREFER_LATEST ne soit définie. Si cette variable d'environnement est définie (quelle que soit sa valeur), la valeur initiale (et permanente) du mode de sélection est définie sur « latest ».

NUMÉROS DE VERSION

Les numéros de version sont constitués d'un ou plusieurs nombres décimaux séparés par des points, tels que 2, 1.162 ou 3.1.13.1. Le premier nombre est appelé le numéro de version majeure. Des nombres plus grands correspondent à des versions ultérieures d'un paquet, les nombres les plus à gauche ayant plus de signification. Par exemple, la version 2.1 est ultérieure à 1.3 et la version 3.4.6 est ultérieure à 3.3.5. Les champs manquants équivalent à des zéros : la version 1.3 est identique à la version 1.3.0 et 1.3.0.0, elle est donc antérieure à 1.3.1 ou 1.3.0.2. De plus, les lettres « a » (alpha) et/ou « b » (beta) peuvent apparaître exactement une fois pour remplacer un point de séparation. Ces lettres ajoutent sémantiquement un spécificateur négatif à la version, où « a » vaut -2 et « b » vaut -1. Chacun ne peut être spécifié qu'une fois, et « a » ou « b » sont mutuellement exclusifs dans un spécificateur. Ainsi, 1.3a1 devient (sémantiquement) 1.3.-2.1, 1.3b1 est 1.3.-1.1. Les nombres négatifs ne sont pas directement autorisés dans les spécificateurs de version. Un numéro de version ne contenant pas les lettres « a » ou « b » comme spécifié ci-dessus est appelé une version stable, tandis que la présence des lettres rend la version instable. Une version ultérieure est supposée être compatible ascendante avec une version antérieure tant que les deux versions ont le même numéro de version majeure. Par exemple, les scripts Tcl écrits pour la version 2.3 d'un paquet devraient fonctionner sans modification avec les versions 2.3.2, 2.4 et 2.5.1. Les changements dans le numéro de version majeure signifient des changements incompatibles : si du code est écrit pour utiliser la version 2.1 d'un paquet, il n'est pas garanti qu'il fonctionne sans modification avec la version 1.7.3 ou la version 3.1.

INDEX DE PAQUETS

La manière recommandée d'utiliser les paquets en Tcl est d'invoquer les commandes package require et package provide dans les scripts, et d'utiliser la procédure pkg_mkIndex pour créer des fichiers d'index de paquets. Une fois que vous avez fait cela, les paquets seront chargés automatiquement en réponse aux commandes package require. Voir la documentation de pkg_mkIndex pour les détails.

EXEMPLES

Pour indiquer qu'un script Tcl nécessite les paquets Tk et http, mettez ceci en haut du script :

package require Tk
package require http

Pour tester si le paquet Snack est disponible et le charger s'il l'est (souvent utile pour des améliorations optionnelles aux programmes où la perte de fonctionnalité n'est pas critique), faites ceci :

if {[catch {package require Snack}]} {
    # Erreur levée - paquet introuvable.
    # Mettre en place une interface factice pour contourner l'absence
} else {
    # Nous avons le paquet, configurer l'application pour l'utiliser
}
