PAM_START(3) Manuel Linux-PAM PAM_START(3)

NOM

pam_start, pam_start_confdir - initialisation de la transaction PAM

SYNTAXE

#include <security/pam_appl.h>

int pam_start(const char *nom_service, const char *utilisateur, const struct pam_conv *conversation_pam, pam_handle_t **pamh);

int pam_start_confdir(const char *nom_service, const char *utilisateur, const struct pam_conv *conversation_pam, const char *rep_conf, pam_handle_t **pamh);

DESCRIPTION

La fonction pam_start crée le contexte PAM et initialise la transaction PAM. C'est la première des fonctions PAM qui doit être appelée par une application. L'état de la transaction est contenu entièrement dans la structure identifiée par ce handle, il est donc possible d'avoir plusieurs transactions en parallèle. Mais il n'est pas possible d'utiliser le même handle pour différentes transactions, un nouveau est nécessaire pour chaque nouveau contexte.

L'argument nom_service spécifie le nom du service à appliquer et sera stocké en tant qu'élément PAM_SERVICE dans le nouveau contexte. La politique pour le service sera lue dans le fichier /etc/pam.d/nom_service ou, si ce fichier n'existe pas, dans /etc/pam.conf.

L'argument utilisateur peut spécifier le nom de l'utilisateur cible et sera stocké en tant qu'élément PAM_USER. Si l'argument est NULL, le module doit demander cet élément si nécessaire.

L'argument conversation_pam pointe vers une struct pam_conv décrivant la fonction de conversation à utiliser. Une application doit fournir ceci pour une communication directe entre un module chargé et l'application.

Suite à un retour réussi (PAM_SUCCESS), le contenu de pamh est un handle qui contient le contexte PAM pour les appels successifs aux fonctions PAM. En cas d'erreur, le contenu de pamh est indéfini.

Le pam_handle_t est une structure opaque et l'application ne doit pas essayer d'y accéder directement pour obtenir des informations. Au lieu de cela, la bibliothèque PAM fournit les fonctions pam_set_item(3) et pam_get_item(3). Le handle PAM ne peut pas être utilisé pour plusieurs authentifications en même temps tant que pam_end n'a pas été appelé sur celui-ci auparavant.

La fonction pam_start_confdir se comporte comme la fonction pam_start mais elle permet également de définir l'argument rep_conf avec un chemin vers un répertoire pour remplacer le chemin par défaut (/etc/pam.d) pour les fichiers de politique de service. Si rep_conf est NULL, la fonction fonctionne exactement comme pam_start.

VALEURS DE RETOUR

PAM_ABORT

Échec général.

PAM_BUF_ERR

Erreur de tampon mémoire.

PAM_SUCCESS

La transaction a été démarrée avec succès.

PAM_SYSTEM_ERR

Erreur système, par exemple un pointeur NULL a été soumis au lieu d'un pointeur vers des données.

VOIR AUSSI

pam_get_data(3), pam_set_data(3), pam_end(3), pam_strerror(3)
