NOM

pam_unix - Module pour l'authentification traditionnelle par mot de passe

SYNTAXE

pam_unix.so [...]

DESCRIPTION

C'est le module d'authentification Unix standard. Il utilise les appels standard des bibliothèques système pour récupérer et définir les informations de compte ainsi que l'authentification. Habituellement, cela est obtenu à partir des fichiers /etc/passwd et /etc/shadow, si le shadow est activé.

Le composant de compte effectue la tâche d'établissement du statut du compte et du mot de passe de l'utilisateur en fonction des éléments shadow suivants : expire, last_change, max_change, min_change, warn_change. Dans le cas de ce dernier, il peut offrir des conseils à l'utilisateur sur la modification de son mot de passe ou, via le retour PAM_AUTHTOKEN_REQD, retarder l'octroi du service à l'utilisateur jusqu'à ce qu'il ait défini un nouveau mot de passe. Les entrées listées ci-dessus sont documentées dans la page de manuel shadow(5). Si l'enregistrement de l'utilisateur ne contient pas une ou plusieurs de ces entrées, la vérification shadow correspondante n'est pas effectuée.

Le composant d'authentification effectue la tâche de vérification des identifiants de l'utilisateur (mot de passe). L'action par défaut de ce module est de ne pas autoriser l'accès de l'utilisateur à un service si son mot de passe officiel est vide.

Un binaire auxiliaire, unix_chkpwd(8), est fourni pour vérifier le mot de passe de l'utilisateur lorsqu'il est stocké dans une base de données protégée en lecture. Ce binaire est très simple et ne vérifiera que le mot de passe de l'utilisateur qui l'invoque. Il est appelé de manière transparente au nom de l'utilisateur par le composant d'authentification de ce module. De cette façon, il est possible pour des applications comme xlock(1) de fonctionner sans être setuid-root. Le module, par défaut, désactive temporairement la gestion de SIGCHLD pendant l'exécution du binaire auxiliaire. C'est généralement la bonne chose à faire, car de nombreuses applications ne sont pas préparées à gérer ce signal d'un enfant dont elles ne savaient pas qu'il avait été fork()é. L'argument de module noreap peut être utilisé pour supprimer ce bouclier temporaire et peut être nécessaire pour une utilisation avec certaines applications.

La longueur maximale d'un mot de passe supportée par le module pam_unix via le binaire auxiliaire est de PAM_MAX_RESP_SIZE - actuellement 512 octets. Le reste du mot de passe fourni par la fonction de conversation au module sera ignoré.

Le composant mot de passe de ce module effectue la tâche de mise à jour du mot de passe de l'utilisateur. Le hachage de chiffrement par défaut est pris de la variable ENCRYPT_METHOD de /etc/login.defs

Le composant de session de ce module enregistre quand un utilisateur se connecte ou quitte le système.

Les arguments restants, pris en charge par d'autres fonctions de ce module, sont ignorés silencieusement. D'autres arguments sont enregistrés comme erreurs via syslog(3).

OPTIONS

debug

Active le débogage via syslog(3).

audit

Un peu plus extrême que debug.

quiet

Désactive les messages d'information, notamment les messages concernant l'ouverture et la fermeture de session via syslog(3).

nullok

L'action par défaut de ce module est de ne pas autoriser l'accès de l'utilisateur à un service si son mot de passe officiel est vide. L'argument nullok remplace ce comportement par défaut.

nullresetok

Permet aux utilisateurs de s'authentifier avec un mot de passe vide si la réinitialisation du mot de passe est imposée, même si nullok n'est pas défini. Si la réinitialisation du mot de passe n'est pas requise et que nullok n'est pas défini, l'authentification avec un mot de passe vide sera refusée.

try_first_pass

Avant de demander le mot de passe à l'utilisateur, le module essaie d'abord le mot de passe du module empilé précédent au cas où celui-ci satisferait également ce module.

use_first_pass

L'argument use_first_pass force le module à utiliser le mot de passe d'un module empilé précédent et ne demandera jamais à l'utilisateur - si aucun mot de passe n'est disponible ou si le mot de passe n'est pas approprié, l'utilisateur se verra refuser l'accès.

nodelay

Cet argument peut être utilisé pour dissuader le composant d'authentification de demander un délai en cas d'échec de l'authentification dans son ensemble. L'action par défaut est que le module demande un délai en cas d'échec de l'ordre de deux secondes.

use_authtok

Lors du changement de mot de passe, force le module à définir le nouveau mot de passe sur celui fourni par un module password empilé précédemment (c'est utilisé dans l'exemple d'empilement du module pam_passwdqc documenté ci-dessous).

authtok_type=type

Cet argument peut être utilisé pour modifier l'invite du mot de passe lors du changement de mot de passe afin d'inclure le type de mot de passe. Vide par défaut.

nis

Le RPC NIS est utilisé pour définir de nouveaux mots de passe.

remember=n

Les n derniers mots de passe de chaque utilisateur sont sauvegardés dans /etc/security/opasswd afin de forcer l'historique des changements de mot de passe et d'empêcher l'utilisateur d'alterner trop fréquemment entre les mêmes mots de passe. L'algorithme de hachage de mot de passe MD5 est utilisé pour stocker les anciens mots de passe. Au lieu de cette option, le module pam_pwhistory devrait être utilisé.

shadow

Essayer de maintenir un système basé sur shadow.

md5

Lorsque l'utilisateur changera son mot de passe, il sera chiffré avec l'algorithme MD5.

bigcrypt

Lorsque l'utilisateur changera son mot de passe, il sera chiffré avec l'algorithme DEC C2.

sha256

Lorsque l'utilisateur changera son mot de passe, il sera chiffré avec l'algorithme SHA256. L'algorithme SHA256 doit être supporté par la fonction crypt(3).

sha512

Lorsque l'utilisateur changera son mot de passe, il sera chiffré avec l'algorithme SHA512. L'algorithme SHA512 doit être supporté par la fonction crypt(3).

blowfish

Lorsque l'utilisateur changera son mot de passe, il sera chiffré avec l'algorithme blowfish. L'algorithme blowfish doit être supporté par la fonction crypt(3).

gost_yescrypt

Lorsque l'utilisateur changera son mot de passe, il sera chiffré avec l'algorithme gost-yescrypt. L'algorithme gost-yescrypt doit être supporté par la fonction crypt(3).

yescrypt

Lorsque l'utilisateur changera son mot de passe, il sera chiffré avec l'algorithme yescrypt. L'algorithme yescrypt doit être supporté par la fonction crypt(3).

rounds=n

Définit le nombre optionnel de tours des algorithmes de hachage de mot de passe SHA256, SHA512, blowfish, gost-yescrypt et yescrypt à n.

broken_shadow

Ignore les erreurs de lecture des informations shadow pour les utilisateurs dans le module de gestion de compte.

minlen=n

Définit une longueur minimale de mot de passe de n caractères. Le maximum pour les mots de passe basés sur le chiffrement DES est de 8 caractères.

no_pass_expiry

Lorsqu'il est défini, ignore l'expiration du mot de passe telle que définie par l'entrée shadow de l'utilisateur. L'option n'a d'effet que si pam_unix n'a pas été utilisé pour l'authentification ou s'il a retourné un échec d'authentification, signifiant que d'autres sources ou méthodes d'authentification ont réussi. L'exemple peut être l'authentification par clé publique dans sshd. Le module retournera PAM_SUCCESS au lieu de l'éventuel PAM_NEW_AUTHTOK_REQD ou PAM_AUTHTOK_EXPIRED.

Les arguments invalides sont enregistrés avec syslog(3).

MODULE TYPES FOURNIS

Tous les types de modules (account, auth, password et session) sont fournis.

VALEURS DE RETOUR

PAM_IGNORE

Ignorer ce module.

EXEMPLES

Un exemple d'utilisation pour /etc/pam.d/login serait :

# Authentifier l'utilisateur
auth       required   pam_unix.so
# S'assurer que le compte et le mot de passe de l'utilisateur sont toujours actifs
account    required   pam_unix.so
# Changer le mot de passe de l'utilisateur, mais vérifier d'abord sa robustesse
# avec pam_passwdqc(8)
password   required   pam_passwdqc.so config=/etc/pass
