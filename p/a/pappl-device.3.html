DESCRIPTION

Les fonctions de périphérique PAPPL fournissent un accès aux connexions de périphériques de sortie et pour lister les périphériques de sortie disponibles. Les périphériques de sortie sont accessibles en utilisant des chaînes d'identifiant de ressource uniforme (URI) telles que "file:///chemin/vers/fichier-ou-répertoire", "socket://11.22.33.44", et "usb://fabricant/modèle?serial=numéro".

La fonction papplDeviceList liste les périphériques de sortie disponibles, en fournissant chaque périphérique de sortie disponible à la fonction de rappel fournie. La liste ne contient que les périphériques dont le schéma d'URI prend en charge la découverte, actuellement les imprimantes USB et les imprimantes réseau qui s'annoncent via DNS-SD/mDNS et/ou SNMPv1.

La fonction papplDeviceOpen ouvre une connexion à un périphérique de sortie en utilisant son URI. La fonction papplDeviceClose ferme la connexion.

Les fonctions papplDevicePrintf, papplDevicePuts, et papplDeviceWrite envoient des données au périphérique, tandis que la fonction papplDeviceRead lit des données depuis le périphérique.

La fonction papplDeviceGetMetrics obtient des informations statistiques sur toutes les communications avec le périphérique pendant qu'il a été ouvert, tandis que la fonction papplDeviceGetStatus obtient l'état matériel d'un périphérique et le mappe au champ de bits pappl_preason_t.

papplDeviceAddScheme

Ajoute un schéma d'URI de périphérique.

void papplDeviceAddScheme (
    const char *scheme,
    pappl_devtype_t dtype,
    pappl_devlist_cb_t list_cb,
    pappl_devopen_cb_t open_cb,
    pappl_devclose_cb_t close_cb,
    pappl_devread_cb_t read_cb,
    pappl_devwrite_cb_t write_cb,
    pappl_devstatus_cb_t status_cb
);

Cette fonction enregistre un schéma d'URI de périphérique avec PAPPL, de sorte que les périphériques utilisant le schéma nommé puissent recevoir des données d'impression, signaler des informations d'état, etc. PAPPL inclut la prise en charge des schémas d'URI suivants :

  • dnssd : Imprimantes réseau découvertes via DNS-SD.
  • file : Fichiers de périphériques caractère, fichiers simples et répertoires.
  • snmp : Imprimantes réseau découvertes via SNMPv1.
  • socket : Imprimantes réseau utilisant un nom d'hôte ou une adresse IP numérique.
  • usb : Imprimantes USB de classe 1 (unidirectionnelles) ou 2 (bidirectionnelles).

Le paramètre "scheme" spécifie le schéma d'URI et doit consister en lettres minuscules, chiffres, "-", "_", et/ou ".", par exemple "x-foo" ou "com.example.bar".

Le paramètre "dtype" spécifie le type de périphérique et doit être PAPPL_DTYPE_CUSTOM_LOCAL pour les imprimantes connectées localement et PAPPL_DTYPE_CUSTOM_NETWORK pour les imprimantes réseau.

Chacune des fonctions de rappel correspond à l'une des fonctions papplDevice :

  • "list_cb" : Implémente la découverte des périphériques (optionnel)
  • "open_cb" : Ouvre la communication avec un périphérique et alloue les données spécifiques au
    périphérique si nécessaire
  • "close_cb" : Ferme la communication avec un périphérique et libère les données spécifiques au
    périphérique si nécessaire
  • "read_cb" : Lit des données depuis un périphérique
  • "write_cb" : Écrit des données vers un périphérique
  • "status_cb" : Obtient des informations de base sur l'état de l'imprimante depuis un périphérique (optionnel)

La fonction de rappel "open_cb" appelle généralement papplDeviceSetData pour stocker un pointeur vers des informations contextuelles pour la connexion, tandis que les fonctions de rappel "close_cb", "read_cb", "write_cb", et "status_cb" appellent généralement papplDeviceGetData pour la récupérer.

PAPPL_DEVICE FUNCTIONS

These functions provide low-level access to printers and other devices supported by PAPPL.

When PAPPL needs to communicate with a device, it uses a URI (Uniform Resource Identifier) to identify the connection type and location. For example, usb:/dev/usb/lp0 identifies a USB printer connected to the specified device file, while socket://192.168.1.100:9100 identifies a network printer at the given IP address and port.

The "scheme" part of the URI determines how PAPPL communicates with the device. PAPPL includes support for several standard schemes, but it also allows you to define your own custom schemes.

When using a custom device URI scheme, you need to provide a set of callback functions that PAPPL will use to interact with the device. These callbacks are passed to the papplDeviceAddUDC function when you register your custom scheme.

The following table lists the supported URI schemes:

  • dnssd: Printers discovered using DNS-SD.
  • file: Character device files, plain files, and directories.
  • ipp: IPP printers discovered using mDNS/DNS-SD or Bonjour.
  • ipps: IPP printers over TLS discovered using mDNS/DNS-SD or Bonjour.
  • snmp: Printers discovered using SNMPv1.
  • socket: Printers using a hostname or numeric IP address.
  • usb: Class 1 (unidirectional) or 2 (bidirectional) USB printers.

The "scheme" parameter specifies the URI scheme and must consist of lowercase letters, digits, "-", "_", and/or ".", for example "x-foo" or "com.example.bar".

The "dtype" parameter specifies the device type and should be PAPPL_DTYPE_CUSTOM_LOCAL for locally connected printers and PAPPL_DTYPE_CUSTOM_NETWORK for network printers.

Each of the callbacks corresponds to one of the papplDevice functions:

  • "list_cb": Implements discovery of devices (optional)
  • "open_cb": Opens communication with a device and allocates any device-
    specific data as needed
  • "close_cb": Closes communication with a device and frees any device-
    specific data as needed
  • "read_cb": Reads data from a device
  • "write_cb": Write data to a device
  • "status_cb": Gets basic printer state information from a device (optional)
  • "supplies_cb": Gets supply level information from a device (optional)
  • "id_cb": Gets the current IEEE-1284 device ID from a device (optional)

The "open_cb" callback typically calls papplDeviceSetData to store a pointer to contextual information for the connection while the "close_cb", "id_cb", "read_cb", "write_cb", "status_cb", and "supplies_cb" callbacks typically call papplDeviceGetData to retrieve it.

papplDeviceGetStatus

Get the printer status bits.

pappl_preason_t  papplDeviceGetStatus (
    pappl_device_t *device
);

This function returns the current printer status bits, as applicable to the current device.

The status bits for USB devices come from the original Centronics parallel printer "standard" which was later formally standardized in IEEE 1284-1984 and the USB Device Class Definition for Printing Devices. Some vendor extensions are also supported.

The status bits for network devices come from the hrPrinterDetectedErrorState property that is defined in the SNMP Printer MIB v2 (RFC 3805).

This function returns a pappl_preason_t bitfield which can be passed to the papplPrinterSetReasons function. Use the PAPPL_PREASON_DEVICE_STATUS value as the value of the "remove" argument.

5
Note: This function can block for several seconds while getting the status
5
information.

This function returns the number, type, and level of current printer supply levels, as applicable to the current device.

The supply levels for network devices come from the prtSupplyTable and prtMarkerColorantTable properties that are defined in the SNMP Printer MIB v2 (RFC 3805).

The supply levels for other devices are not standardized and must be queried using other methods.

papplDeviceList

List available devices.

bool  papplDeviceList (
    pappl_devtype_t types,
    pappl_device_cb_t cb,
    void *data,
    pappl_deverror_cb_t err_cb,
    void *err_data
);

This function lists the available devices, calling the "cb" function once per device that is discovered/listed. The callback function receives the device URI, IEEE-1284 device ID (if any), and "data" pointer, and returns true to stop listing devices and false to continue.

The "types" argument determines which devices are listed, for example PAPPL_DEVTYPE_ALL will list all types of devices while PAPPL_DEVTYPE_USB only lists USB printers.

Any errors are reported using the supplied "err_cb" function. If you specify NULL for this argument, errors are sent to stderr.

Cette fonction lit des données depuis le périphérique. Selon le périphérique, cette fonction peut bloquer indéfiniment.

papplDeviceRemoveScheme

Supprimer le schéma d'URI de périphérique nommé.

void papplDeviceRemoveScheme (
    const char *scheme
);

Cette fonction supprime la prise en charge du schéma d'URI de périphérique nommé. À utiliser uniquement lorsque vous souhaitez désactiver un schéma d'URI pour des raisons de sécurité ou fonctionnelles, par exemple pour désactiver le schéma d'URI "file".

papplDeviceRemoveTypes

Supprimer les schémas d'URI de périphérique des types spécifiés.

void papplDeviceRemoveTypes (
    pappl_devtype_t types
);

Cette fonction supprime les schémas d'URI de périphérique des types spécifiés. À utiliser uniquement lorsque vous souhaitez désactiver les schémas d'URI pour des raisons de sécurité ou fonctionnelles, par exemple pour désactiver tous les schémas d'URI réseau.

papplDeviceSetData

Définir les données spécifiques au périphérique.

void papplDeviceSetData (
    pappl_device_t *device,
    void *data
);

Cette fonction définit toutes les données spécifiques au périphérique nécessaires pour communiquer avec le périphérique. Elle n'est normalement appelée qu'à partir du rappel d'ouverture qui a été enregistré pour le schéma d'URI du périphérique.

papplDeviceWrite

Écrire sur un périphérique.

ssize_t  papplDeviceWrite (
    pappl_device_t *device,
    const void *buffer,
    size_t bytes
);

Cette fonction met en mémoire tampon les données qui seront envoyées au périphérique. Appelez la fonction papplDeviceFlush pour vous assurer que les données sont immédiatement envoyées au périphérique.
