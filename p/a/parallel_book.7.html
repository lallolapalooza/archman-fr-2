Pourquoi devriez-vous lire ce livre ?

Si vous écrivez des scripts shell pour effectuer le même traitement pour différentes entrées, alors GNU parallel vous facilitera la vie et accélérera vos scripts.

Le livre est écrit de manière à vous présenter d'abord les parties les plus intéressantes : L'objectif est que vous lisiez juste assez pour vous lancer. GNU parallel possède une quantité impressionnante de fonctionnalités spéciales pour aider dans différentes situations, et pour ne pas vous submerger d'informations, les fonctionnalités les plus utilisées sont présentées en premier.

Tous les exemples sont testés sous Bash, et la plupart fonctionneront également dans d'autres shells, mais il y a quelques exceptions. Il est donc recommandé d'utiliser Bash lors des tests des exemples.

Apprendre GNU Parallel en 5 minutes

Vous avez juste besoin d'exécuter des commandes en parallèle. Vous ne vous souciez pas du réglage fin.

Pour commencer, exécutez ceci pour créer quelques fichiers d'exemple :

# Si votre système n'a pas 'seq', remplacez 'seq' par 'jot'
seq 5 | parallel seq {} '>' example.{}

Sources d'entrée

GNU parallel lit les valeurs à partir de sources d'entrée. Une source d'entrée est la ligne de commande. Les valeurs sont placées après ::: :

parallel echo ::: 1 2 3 4 5

Cela permet d'exécuter facilement le même programme sur certains fichiers :

parallel wc ::: example.*

Si vous fournissez plusieurs :::, GNU parallel générera toutes les combinaisons :

parallel wc ::: -l -c ::: example.*

GNU parallel peut également lire les valeurs depuis stdin (entrée standard) :

seq 5 | parallel echo

Construction de la ligne de commande

La ligne de commande est placée avant le :::. Elle peut contenir une commande et des options pour la commande :

parallel wc -l ::: example.*

La commande peut contenir plusieurs programmes. N'oubliez pas de mettre entre guillemets les caractères interprétés par le shell (comme ;) :

parallel echo counting lines';' wc -l ::: example.*

La valeur sera normalement ajoutée à la commande, mais peut être placée n'importe où en utilisant la chaîne de remplacement {} :

parallel echo counting {}';' wc -l {} ::: example.*

Lorsque vous utilisez plusieurs sources d'entrée, utilisez les chaînes de remplacement positionnelles {1} et {2} :

parallel echo count {1} in {2}';' wc {1} {2} ::: -l -c ::: example.*

Vous pouvez vérifier ce qui sera exécuté avec --dry-run :

parallel --dry-run echo count {1} in {2}';' wc {1} {2} ::: -l -c ::: example.*

C'est une bonne idée de le faire pour chaque commande jusqu'à ce que vous soyez à l'aise avec GNU parallel.

Contrôle de la sortie

La sortie sera imprimée dès que la commande sera terminée. Cela signifie que la sortie peut apparaître dans un ordre différent de celui de l'entrée :

parallel sleep {}';' echo {} done ::: 5 4 3 2 1

Vous pouvez forcer GNU parallel à imprimer dans l'ordre des valeurs avec --keep-order/-k. Cela exécutera toujours les commandes en parallèle. La sortie des travaux ultérieurs sera retardée jusqu'à ce que les travaux précédents soient imprimés :

parallel -k sleep {}';' echo {} done ::: 5 4 3 2 1

Contrôle de l'exécution

Si vos tâches sont intensives en calcul, vous exécuterez très probablement une tâche par cœur du système. C'est le comportement par défaut de GNU parallel.

Mais parfois, vous voulez exécuter plus de tâches. Vous contrôlez le nombre d'emplacements de tâches avec -j. Donnez à -j le nombre de tâches à exécuter en parallèle :

parallel -j50 \
  wget https://ftpmirror.gnu.org/parallel/parallel-{1}{2}22.tar.bz2 \
  ::: 2012 2013 2014 2015 2016 \
  ::: 01 02 03 04 05 06 07 08 09 10 11 12

Mode Pipe

GNU parallel peut également passer des blocs de données à des commandes sur stdin (entrée standard) :

seq 1000000 | parallel --pipe wc

Cela peut être utilisé pour traiter de gros fichiers texte. Par défaut, GNU parallel divise par \n (saut de ligne) et passe un bloc d'environ 1 Mo à chaque tâche.

Voilà

Vous avez maintenant appris l'utilisation de base de GNU parallel. Cela couvrira probablement la plupart de vos cas d'utilisation de GNU parallel.

Le reste de ce document entrera plus en détail dans chaque section et couvrira des cas d'utilisation spécifiques.

Apprendre GNU Parallel en une heure

Dans cette partie, nous allons approfondir ce que vous avez appris dans les 5 premières minutes.

Pour commencer, exécutez ceci pour créer quelques fichiers d'exemple :

seq 6 > seq6
seq 6 -1 1 > seq-6

Sources d'entrée

En plus de la ligne de commande, les sources d'entrée peuvent également être stdin (entrée standard ou '-'), des fichiers et des fifos, et elles peuvent être mélangées. Les fichiers sont donnés après -a ou ::::. Donc, tout cela fait la même chose :

parallel echo Dice1={1} Dice2={2} ::: 1 2 3 4 5 6 ::: 6 5 4 3 2 1
parallel echo Dice1={1} Dice2={2} :::: <(seq 6) :::: <(seq 6 -1 1)
parallel echo Dice1={1} Dice2={2} :::: seq6 seq-6
parallel echo Dice1={1} Dice2={2} :::: seq6 :::: seq-6
parallel -a seq6 -a seq-6 echo Dice1={1} Dice2={2}
parallel -a seq6 echo Dice1={1} Dice2={2} :::: seq-6
parallel echo Dice1={1} Dice2={2} ::: 1 2 3 4 5 6 :::: seq-6
cat seq-6 | parallel echo Dice1={1} Dice2={2} :::: seq6 -

Si stdin (entrée standard) est la seule source d'entrée, vous n'avez pas besoin du '-' :

cat seq6 | parallel echo Dice1={1}

Liaison des sources d'entrée

Vous pouvez lier plusieurs sources d'entrée avec :::+ et ::::+ :

parallel echo {1}={2} ::: I II III IV V VI :::+ 1 2 3 4 5 6
parallel echo {1}={2} ::: I II III IV V VI ::::+ seq6

Le :::+ (et ::::+) liera chaque valeur à la valeur correspondante dans la source d'entrée précédente, de sorte que la valeur numéro 3 de la première source d'entrée sera liée à la valeur numéro 3 de la deuxième source d'entrée.

Vous pouvez combiner :::+ et :::, de sorte que vous liez 2 sources d'entrée, mais générez toutes les combinaisons avec d'autres sources d'entrée :

parallel echo Dice1={1}={2} Dice2={3}={4} ::: I II III IV V VI ::::+ seq6 \
  ::: VI V IV III II I ::::+ seq-6

Construction de la ligne de commande

La commande

La commande peut être un script, un binaire ou une fonction Bash si la fonction est exportée à l'aide de export -f :

# Fonctionne uniquement sous Bash
my_func() {
  echo in my_func "$1"
}
export -f my_func
parallel my_func ::: 1 2 3

Si la commande est complexe, il est souvent préférable de la transformer en fonction.

Les chaînes de remplacement

GNU parallel dispose de quelques chaînes de remplacement pour faciliter la référence à l'entrée lue depuis les sources d'entrée.

Si l'entrée est mydir/mysubdir/myfile.myext alors :

{} = mydir/mysubdir/myfile.myext
{.} = mydir/mysubdir/myfile
{/} = myfile.myext
{//} = mydir/mysubdir
{/.} = myfile
{#} = le numéro de séquence de la tâche
{%} = le numéro de slot de la tâche

Lorsqu'une tâche est démarrée, elle reçoit un numéro de séquence qui commence à 1 et augmente de 1 pour chaque nouvelle tâche. La tâche reçoit également un numéro de slot. Ce numéro va de 1 au nombre de tâches en cours d'exécution en parallèle. Il est unique entre les tâches en cours, mais est réutilisé dès qu'une tâche se termine.

Les chaînes de remplacement positionnelles

Les chaînes de remplacement ont des chaînes de remplacement positionnelles correspondantes. Si la valeur de la 3ème source d'entrée est mydir/mysubdir/myfile.myext :

{3} = mydir/mysubdir/myfile.myext
{3.} = mydir/mysubdir/myfile
{3/} = myfile.myext
{3//} = mydir/mysubdir
{3/.} = myfile

Donc, le numéro de la source d'entrée est simplement ajouté en préfixe à l'intérieur des {} .

Manuel de GNU Parallel - parset

parset

parset

parset est une fonction shell pour récupérer la sortie de GNU parallel dans des variables shell.

parset est entièrement pris en charge pour Bash/Zsh/Ksh et partiellement pour ash/dash. Je supposerai que vous exécutez Bash.

Pour activer parset, vous devez exécuter :

. `which env_parallel.bash`

(remplacez bash par le nom de votre shell).

Ensuite, vous pouvez exécuter :

parset a,b,c seq ::: 4 5 6
echo "$c"

ou :

parset 'a b c' seq ::: 4 5 6
echo "$c"

Si vous donnez une seule variable, elle deviendra un tableau :

parset arr seq ::: 4 5 6
echo "${arr[1]}"

parset a une limitation : s'il lit depuis un pipe, la sortie sera perdue.

echo This will not work | parset myarr echo
echo Nothing: "${myarr[*]}"

Au lieu de cela, vous pouvez faire ceci :

echo This will work > tempfile
parset myarr echo < tempfile
echo ${myarr[*]}

Exécution à distance

Pour cette section, vous devez avoir un accès ssh sans mot de passe à 2 serveurs : $server1 et $server2.

server1=server.example.com
server2=server2.example.net

Vous devez donc pouvoir faire ceci :

ssh $server1 echo works
ssh $server2 echo works

Cela peut être configuré en exécutant 'ssh-keygen -t dsa; ssh-copy-id $server1' et en utilisant une passphrase vide. Ou vous pouvez utiliser ssh-agent.

Workers

--transferfile

--transferfile filename transférera filename vers le worker. filename peut contenir une chaîne de remplacement :

parallel -S $server1,$server2 --transferfile {} wc ::: example.*
parallel -S $server1,$server2 --transferfile {2} \
   echo count {1} in {2}';' wc {1} {2} ::: -l -c ::: example.*

Un raccourci pour --transferfile {} est --transfer.
