PAPERKEY(1) Manuel des commandes générales PAPERKEY(1)

NOM

paperkey - extraire des informations secrètes des clés secrètes OpenPGP

SYNTAXE

paperkey [--secret-key=FICHIER] [--output=FICHIER] [--output-type=base16|raw] [--output-width=LARGEUR]

paperkey --pubring=FICHIER [--secrets=FICHIER] [--input-type=auto|base16|raw] [--output=FICHIER] [--ignore-crc-error] [--comment=CHAÎNE] [--file-format]

paperkey --version

MOTIVATION

Comme pour toutes les données, les clés secrètes doivent être sauvegardées. En fait, les clés secrètes devraient être sauvegardées encore mieux que les autres données, car elles sont impossibles à recréer si elles sont perdues. Tous les fichiers chiffrés avec des clés perdues sont indéchiffrables à jamais (ou du moins pendant longtemps). En plus de conserver des sauvegardes d'informations de clé secrète sur des supports numériques tels que des clés USB ou des CD, il est raisonnable de conserver une copie de secours « en cas de défaillance de tout le reste » sur du simple papier, à utiliser si vos supports numériques devaient devenir illisibles pour une raison quelconque. Stocké correctement, le papier peut conserver des informations pendant plusieurs décennies ou plus.

Avec GnuPG, PGP ou d'autres implémentations OpenPGP, la clé secrète contient généralement beaucoup plus que les simples nombres secrets qui sont importants. Elles contiennent également toutes les valeurs publiques des paires de clés, les identifiants d'utilisateur, les dates d'expiration et plus encore. Afin de minimiser les informations qui doivent être saisies manuellement ou à l'aide d'un logiciel OCR, QR code ou similaire, paperkey extrait uniquement les informations secrètes des clés secrètes OpenPGP. Pour récupérer une clé secrète, on suppose que la clé publique est toujours disponible, par exemple à partir des serveurs de clés publics sur Internet.

DESCRIPTION

paperkey a deux modes de fonctionnement :

Le premier mode crée des « paperkeys » en extrayant uniquement les informations secrètes d'une clé secrète, en formatant les données d'une manière adaptée à l'impression ou en mode brut pour un traitement ultérieur.

L'autre mode reconstruit les clés secrètes à partir d'une paperkey et d'une copie de la clé publique, tout en vérifiant les sommes de contrôle intégrées dans la paperkey. Ce mode est sélectionné lorsque l'option --pubring est utilisée, ce qui est requis dans ce cas. Si une phrase secrète a été définie sur la clé secrète d'origine, la même phrase secrète est définie sur la clé reconstruite.

L'entrée est lue depuis l'entrée standard, sauf si l'option --secret-key ou --secrets est utilisée ; la sortie est imprimée sur la sortie standard, sauf indication contraire avec l'option --output.

CONSIDÉRATIONS DE SÉCURITÉ

Veuillez noter que paperkey ne modifie pas le statut de protection et de chiffrement ni les exigences de sécurité pour le stockage de votre clé secrète. Si la clé secrète était protégée par une phrase secrète, la paperkey le sera également. Si la clé secrète n'était pas protégée, la paperkey ne le sera pas non plus.

OPTIONS

--help, -h Afficher un bref message d'aide et quitter avec succès.

--version, -V
Afficher les informations de version et les informations de copyright et quitter avec succès.
--verbose, -v
Afficher les informations de statut et de progression sur la sortie d'erreur standard pendant le traitement de l'entrée. Répéter pour encore plus de sortie.
--output=FICHIER, -o
Rediriger la sortie vers le fichier donné au lieu de l'imprimer sur la sortie standard.
--comment=CHAÎNE
Inclure le commentaire spécifié dans la sortie base16.
--file-format
Paperkey inclut automatiquement le format de fichier qu'il utilise sous forme de commentaires en haut de la sortie base16. Cette commande imprime simplement le format de fichier et quitte avec succès.

OPTIONS POUR EXTRAIRE LES INFORMATIONS SECRÈTES

--output-type=base16, --output-type=raw
Sélectionner le type de sortie. Le style base16 encode les informations dans le style d'un classic hex-dump, incluant des numéros de ligne et des sommes de contrôle CRC par ligne pour faciliter la localisation des erreurs dans le fichier d'entrée pendant la phase de récupération. Le mode brut, ou binaire, est juste un dump brut des informations secrètes, destiné à être fourni à des générateurs de codes-barres ou similaires.
--output-width=LARGEUR
Choisir la largeur de ligne en mode de sortie base16. La valeur par défaut est de 78 caractères.
--secret-key=FICHIER
Fichier à partir duquel lire la clé secrète. Si cette option n'est pas fournie, paperkey lit depuis l'entrée standard.

OPTIONS POUR RECÉRER LES CLÉS PRIVÉES

--input-type=auto, --input-type=base16, --input-type=raw
Spécifier que l'entrée donnée est soit au format base16, comme produit par paperkey, soit au format brut. Le défaut, auto, essaie de détecter automatiquement le format utilisé.
--pubring=FICHIER
Fichier à partir duquel lire les informations de clé publique. On suppose que l'utilisateur peut obtenir la clé publique à partir de sources telles que les serveurs de clés publics sur Internet.
--secrets=FICHIER
Fichier à partir duquel lire les secrets extraits, la paperkey. Si ce n'est pas spécifié, l'information est lue depuis l'entrée standard.
--ignore-crc-error
Ne pas rejeter l'entrée corrompue et continuer malgré les erreurs CRC.

EXEMPLES

Prendre la clé secrète dans key.gpg et générer un fichier texte to-be-printed.txt qui contient les données secrètes :

$ paperkey --secret-key my-secret-key.gpg --output to-be-printed.txt

Prendre les données de clé secrète dans my-key-text-file.txt et les combiner avec my-public-key.gpg pour reconstruire my-secret-key.gpg :

$ paperkey --pubring my-public-key.gpg --secrets my-key-text-file.txt --output my-secret-key.gpg

Si --output n'est pas spécifié, la sortie va vers stdout. Si --secret-key n'est pas spécifié, les données sont lues depuis stdin, vous pouvez donc faire des choses comme :

$ gpg --export-secret-key my-key | paperkey | lpr

    paperkey(1)

    NOM

    paperkey - extrait la clé privée d'un fichier de clé privée sans la clé publique

    SYNOPIS

    paperkey [-help] [-commit] [-verbose] [-in infile] [-out outfile] [-p passfile] [-md5|-sha1|-sha256|-sha384|-sha512] [-a keytype] [-d] [-e]

    MOTIVATION

    La raison d'être de cet utilitaire est de permettre aux utilisateurs de sauvegarder leur clé privée sur un support non sécurisé (comme du papier !) et de la récupérer plus tard. En fait, cela ne fait que réduire le nombre d'éléments que l'on doit saisir pour réimporter une clé. Elle ne constitue donc pas une méthode de sauvegarde vraiment sûre pour votre clé privée.

    DESCRIPTION

    L'utilitaire paperkey prend une clé privée, la "salée" et la crypte à l'aide d'une nouvelle phrase secrète, puis l'écrit dans un fichier. Il imprime ensuite la phrase secrète sur la sortie standard. Cela permet de stocker la clé privée dans un fichier sûr et la phrase secrète sur un support peu sûr (par exemple, le papier).

    Pour récupérer la clé, on utilise l'option -d ou -e, en fonction de la manière dont la clé a été générée.

    Le processus de salage/chiffrement utilise une nouvelle phrase secrète pour crypter la clé privée. Le mot de passe est ensuite haché avec SHA-256 (ou une autre méthode spécifiée par l'option -md5, -sha1, etc.) et cette valeur est combinée avec un nombre aléatoire (généré en utilisant les fonctions PRNG internes d'OpenSSL) pour produire une clé de chiffrement et un vecteur d'initialisation (IV). Le chiffrement est effectué à l'aide de DES-EDE3-CBC.

    Le fichier de sortie contient le nombre aléatoire, l'IV, le sel utilisé, la clé privée cryptée et un résumé du hachage du mot de passe.

    Le processus de décryptage utilise les informations du fichier pour dériver la clé de chiffrement et l'IV, puis déchiffre la clé privée.

    CONSIDÉRATIONS DE SÉCURITÉ

    Comme mentionné précédemment, cette méthode n'est pas une méthode de sauvegarde sûre pour votre clé privée. Un attaquant qui obtiendrait le fichier de clé privée et le fichier de phrase secrète pourrait potentiellement reconstituer votre clé privée.

    Le fichier de clé privée doit être traité comme vous traiteriez normalement votre clé privée : elle doit être stockée dans un endroit sûr et protégé par des autorisations restrictives. La phrase secrète doit également être protégée de manière appropriée.

    OPTIONS

    -help : Affiche un message d'aide et quitte.

    -commit : Indique que la clé privée n'est pas encore stockée et qu'elle doit être générée. Si cette option est spécifiée, paperkey générera une nouvelle clé privée et la stockera dans le fichier spécifié par -out.

    -verbose : Affiche des informations supplémentaires sur le processus.

    -in infile : Spécifie le fichier d'entrée contenant la clé privée. S'il n'est pas spécifié, stdin sera utilisé.

    -out outfile : Spécifie le fichier de sortie où la clé privée traitée sera stockée. S'il n'est pas spécifié, stdout sera utilisé.

    -p passfile : Spécifie un fichier contenant la phrase secrète à utiliser pour crypter/décrypter la clé privée. S'il n'est pas spécifié, la phrase secrète sera demandée à l'utilisateur.

    -md5, -sha1, -sha256, -sha384, -sha512 : Spécifie l'algorithme de hachage à utiliser pour générer la clé de chiffrement à partir de la phrase secrète. La valeur par défaut est -sha256.

    OPTIONS POUR EXTRAIRE DES INFORMATIONS SECRÈTES

    -d : Indique que le fichier d'entrée contient une clé privée "papérisée" et qu'elle doit être décryptée. La phrase secrète sera imprimée sur la sortie standard.

    -e : Similaire à -d, mais suppose que la clé privée a été cryptée avec une clé générée par le schéma de chiffrement de openssl genrsa - paperkey. La phrase secrète sera imprimée sur la sortie standard.

    OPTIONS POUR RECRÉER DES CLÉS PRIVÉES

    -a keytype : Spécifie le type de clé privée à générer. Les valeurs possibles sont rsa, dsa, et ec. Cette option n'est pertinente qu'avec l'option -commit.

    -d : Indique que le fichier d'entrée est une clé privée "papérisée" et qu'elle doit être décryptée. La phrase secrète sera imprimée sur la sortie standard. Cette option peut être utilisée pour reconstruire la clé privée originale.

    -e : Semblable à -d, mais suppose que la clé privée a été cryptée en utilisant le schéma de chiffrement de openssl genrsa - paperkey. La phrase secrète sera imprimée sur la sortie standard. Cette option peut également être utilisée pour reconstruire la clé privée originale.

    EXEMPLES

    Pour crypter une clé privée nommée mykey.pem et imprimer la phrase secrète sur la sortie standard :

    openssl paperkey -in mykey.pem -out mykey.paper

    Pour décrypter la clé privée du fichier mykey.paper et imprimer la clé privée sur la sortie standard :

    openssl paperkey -in mykey.paper -d

    Pour décrypter la clé privée du fichier mykey.paper et la sauvegarder dans un nouveau fichier nommé mykey_decrypted.pem :

    openssl paperkey -in mykey.paper -d -out mykey_decrypted.pem

    Pour crypter une clé privée en utilisant un fichier de phrase secrète nommé mypass.txt :

    openssl paperkey -in mykey.pem -out mykey.paper -p mypass.txt
