NOM

parallel - construire et exécuter des lignes de commande shell à partir de l'entrée standard en parallèle

SYNTAXE

parallel [options] [commande [arguments]] < liste_arguments

parallel [options] [commande [arguments]] ( ::: arguments | :::+ arguments | :::: fichier(s)_arguments | ::::+ fichier(s)_arguments ) ...

parallel --semaphore [options] commande

#!/usr/bin/parallel --shebang [options] [commande [arguments]]

#!/usr/bin/parallel --shebang-wrap [options] [commande [arguments]]

DESCRIPTION

STOP!

Lisez le Guide du lecteur ci-dessous si vous débutez avec GNU parallel.

GNU parallel est un outil shell pour exécuter des tâches en parallèle en utilisant un ou plusieurs ordinateurs. Une tâche peut être une seule commande ou un petit script qui doit être exécuté pour chaque ligne de l'entrée. L'entrée typique est une liste de fichiers, une liste d'hôtes, une liste d'utilisateurs, une liste d'URL, ou une liste de tables. Une tâche peut également être une commande qui lit depuis un pipe. GNU parallel peut alors diviser l'entrée en blocs et envoyer un bloc à chaque commande en parallèle.

Si vous utilisez xargs et tee aujourd'hui, vous trouverez GNU parallel très facile à utiliser car GNU parallel est écrit pour avoir les mêmes options que xargs. Si vous écrivez des boucles en shell, vous trouverez que GNU parallel peut remplacer la plupart des boucles et les faire s'exécuter plus rapidement en exécutant plusieurs tâches en parallèle.

GNU parallel garantit que la sortie des commandes est la même que celle que vous obtiendriez si vous aviez exécuté les commandes séquentiellement. Cela permet d'utiliser la sortie de GNU parallel comme entrée pour d'autres programmes.

Pour chaque ligne d'entrée, GNU parallel exécutera commande avec la ligne comme arguments. Si aucune commande n'est donnée, la ligne d'entrée est exécutée. Plusieurs lignes seront exécutées en parallèle. GNU parallel peut souvent être utilisé comme substitut pour xargs ou cat | bash.

OPTIONS

commande
Commande à exécuter.

Si commande ou les arguments suivants contiennent des chaînes de remplacement (telles que {}), chaque instance sera substituée par l'entrée.

Si commande est donnée, GNU parallel résout les mêmes tâches que xargs. Si commande n'est pas donnée, GNU parallel se comportera de manière similaire à cat | sh.

La commande doit être un exécutable, un script, une commande composée, un alias ou une fonction.

Fonctions Bash : Exportez la fonction en utilisant export -f d'abord ou utilisez env_parallel.

Alias Bash, Csh ou Tcsh : Utilisez env_parallel.

Fonctions et alias Zsh, Fish, Ksh et Pdksh : Utilisez env_parallel.

{}
Ligne d'entrée.

Cette chaîne de remplacement sera remplacée par une ligne complète lue à partir de la source d'entrée. La source d'entrée est normalement stdin (entrée standard), mais peut également être fournie avec --arg-file, :::, ou ::::.

La chaîne de remplacement {} peut être modifiée avec -I.

Si la ligne de commande ne contient pas de chaînes de remplacement, alors {} sera ajouté à la ligne de commande.

Les chaînes de remplacement sont normalement entre guillemets, de sorte que les caractères spéciaux ne soient pas analysés par le shell. L'exception est si la commande commence par une chaîne de remplacement ; alors la chaîne n'est pas mise entre guillemets.

Voir aussi : --plus {.} {/} {//} {/.} {#} {%} {n} {=expression perl=}

{.}
Ligne d'entrée sans extension.

Cette chaîne de remplacement sera remplacée par l'entrée avec l'extension supprimée. Si la ligne d'entrée contient . après le dernier /, le dernier . jusqu'à la fin de la chaîne sera supprimé et {.} sera remplacé par ce qui reste. Par exemple, foo.jpg devient foo, subdir/foo.jpg devient subdir/foo, sub.dir/foo.jpg devient sub.dir/foo, sub.dir/bar reste sub.dir/bar. Si la ligne d'entrée ne contient pas de ., elle restera inchangée.

La chaîne de remplacement {.} peut être modifiée avec --extensionreplace

Voir aussi : {} --extensionreplace

{/}
Nom de base de la ligne d'entrée.

Cette chaîne de remplacement sera remplacée par l'entrée avec la partie répertoire supprimée.

Voir aussi : {} --basenamereplace

{//}
Nom de répertoire de la ligne d'entrée.

Cette chaîne de remplacement sera remplacée par le répertoire de la ligne d'entrée. Voir dirname(1).

Voir aussi : {} --dirnamereplace

{/.}
Nom de base de la ligne d'entrée sans extension.

Cette chaîne de remplacement sera remplacée par l'entrée avec la partie répertoire et extension supprimées. {/.} est une combinaison de {/} et {.}.

Voir aussi : {} --basenameextensionreplace

{#}
Numéro de séquence de la tâche à exécuter.

Cette chaîne de remplacement sera remplacée par le numéro de séquence de la tâche en cours d'exécution. Elle contient le même numéro que $PARALLEL_SEQ.

Voir aussi : {} --seqreplace

{%}
Numéro de slot de la tâche.

Cette chaîne de remplacement sera remplacée par le numéro de slot de la tâche, compris entre 1 et le nombre de tâches à exécuter en parallèle. Il n'y aura jamais 2 tâches exécutées en même temps avec le même numéro de slot de tâche.

Si la tâche doit être retentée (par exemple, en utilisant --retries ou --retry-failed), le slot de tâche n'est pas automatiquement mis à jour. Vous devriez alors utiliser $PARALLEL_JOBSLOT :

$ do_test() {
    id="$3 {%}=$1 PARALLEL_JOBSLOT=$2"
    echo run "$id";
    sleep 1
    # échoue si {%} est impair
    return `echo $1%2 | bc`
  }
$ export -f do_test
$ parallel -j3 --jl mylog do_test {%} \$PARALLEL_JOBSLOT {} ::: A B C D
run A {%}=1 PARALLEL_JOBSLOT=1
run B {%}=2 PARALLEL_JOBSL

{n}
Argument provenant de la source d'entrée n ou du n-ième argument.

Cette chaîne de remplacement positionnelle sera remplacée par l'entrée de la source d'entrée n (lorsqu'elle est utilisée avec --arg-file ou ::::) ou par le n-ième argument (lorsqu'elle est utilisée avec -N ou --colsep).

Si n est négatif, il fait référence au n-ième dernier argument.

Voir aussi : {} {n.} {n/} {n//} {n/.} --colsep

{n.}
Argument provenant de la source d'entrée n ou du n-ième argument sans extension.

{n.} est une combinaison de {n} et {.}.

Cette chaîne de remplacement positionnelle sera remplacée par l'entrée de la source d'entrée n (lorsqu'elle est utilisée avec --arg-file ou ::::) ou par le n-ième argument (lorsqu'elle est utilisée avec -N). L'entrée aura son extension supprimée.

Voir aussi : {n} {.}

{n/}
Nom de base de l'argument provenant de la source d'entrée n ou du n-ième argument.

{n/} est une combinaison de {n} et {/}.

Cette chaîne de remplacement positionnelle sera remplacée par l'entrée de la source d'entrée n (lorsqu'elle est utilisée avec --arg-file ou ::::) ou par le n-ième argument (lorsqu'elle est utilisée avec -N). L'entrée aura son répertoire (le cas échéant) supprimé.

Voir aussi : {n} {/}

{n//}
Nom de répertoire de l'argument provenant de la source d'entrée n ou du n-ième argument.

{n//} est une combinaison de {n} et {//}.

Cette chaîne de remplacement positionnelle sera remplacée par le répertoire de l'entrée provenant de la source d'entrée n (lorsqu'elle est utilisée avec --arg-file ou ::::) ou par le n-ième argument (lorsqu'il est utilisé avec -N). Voir dirname(1).

Voir aussi : {n} {//}

{n/.}
Nom de base de l'argument provenant de la source d'entrée n ou du n-ième argument sans extension.

{n/.} est une combinaison de {n}, {/}, et {.}.

Cette chaîne de remplacement positionnelle sera remplacée par l'entrée de la source d'entrée n (lorsqu'elle est utilisée avec --arg-file ou ::::) ou par le n-ième argument (lorsqu'il est utilisé avec -N). L'entrée aura son répertoire (le cas échéant) et son extension supprimés.

Voir aussi : {n} {/.}

{=expression perl=}
Remplacer par une expression perl calculée.

$_** contiendra la même chose que {}. Après évaluation de l'expression perl $_** sera utilisée comme valeur. Il est recommandé de ne modifier que $_, mais vous avez un accès complet à toutes les fonctions internes et structures de données de GNU parallel.

L'expression doit donner le même résultat si évaluée deux fois ; sinon, le comportement est indéfini. Par exemple, dans certaines versions de GNU parallel, cela ne fonctionnera pas comme prévu :

parallel echo '{= $_= ++$wrong_counter =}' ::: a b c

Quelques fonctions et structures de données de commodité ont été créées :

Q(chaîne)
Échapper une chaîne pour le shell. Exemple : 
parallel echo {} est échappé comme '{= $_=Q($_) =}' ::: \$PWD
pQ(chaîne)
Échapper une chaîne pour Perl. Exemple : 
parallel echo {} est échappé comme '{= $_=pQ($_) =}' ::: \$PWD
uq() (ou uq)
Ne pas échapper la chaîne de remplacement actuelle. Exemple : 
parallel echo {} a la valeur '{= uq =}' ::: \$PWD
hash(val)
Calculer B::hash(val). Exemple : 
parallel echo Le hash de {} est '{= $_=hash($_) =}' ::: a b c
total_jobs()
Nombre total de jobs. Exemple : 
parallel echo Nombre de jobs : '{= $_=total_jobs() =}' ::: a b c
slot()
Numéro de slot du job. Exemple : 
parallel echo Le slot du job {} est '{= $_=slot() =}' ::: a b c
seq()
Numéro de séquence du job. Exemple : 
parallel echo Le numéro de séquence de {} est '{= $_=seq() =}' ::: a b c
@arg
Les arguments en comptant à partir de 1 ($arg[1] = {1} = premier argument). Exemple : 
parallel echo {1}+{2}='{=1 $_=$arg[1]+$arg[2] =}' \
  ::: 1 2 3 ::: 2 3 4

('{=1' force que ce soit une chaîne de remplacement positionnelle, et par conséquent ne répétera pas la valeur pour chaque argument.)

skip()
Ignorer ce job (voir aussi --filter). Exemple : 
parallel echo '{= $arg[1] >= $arg[2] and skip =}' \
  ::: 1 2 3 ::: 2 3 4

yyyy_mm_dd_hh_mm(sec)
yyyy_mm_dd(sec)
hh_mm_ss(sec)
hh_mm(sec)
yyyymmddhhmmss(sec)
yyyymmddhhmm(sec)
yyyymmdd(sec)
hhmmss(sec)
hhmm(sec)
Fonctions temporelles. sec est le nombre de secondes depuis l'époque. S'il est omis, il utilisera l'heure locale actuelle. Exemple : 
parallel echo 'Maintenant : {= $_=yyyy_mm_dd_hh_mm_ss() =}' ::: Dummy
parallel echo 'La fin : {= $_=yyyy_mm_dd_hh_mm_ss($_) =}' \
  ::: 2147483648

Exemple :

Voir aussi : --rpl --parens {} {=n expression perl=} --filter

{=n expression perl=}
Équivalent positionnel de {=expression perl=}.

Pour comprendre les chaînes de remplacement positionnelles, voir {n}.

Voir aussi : {=expression perl=} {n}

{rpl:format}
Chaîne de remplacement formatée.

Utilise format pour formater rpl. format est une chaîne de format utilisée dans printf. rpl est une chaîne de remplacement.

Exemples :

{#:%04d} - Numéro de job ({#}) avec 4 chiffres préfixés par 0
{%:%02d} - Slot de job ({%}) avec 2 chiffres préfixés par 0
{:%6s} - Ligne d'entrée ({}) alignée à droite sur 6 caractères de large
{/:%12s} - Nom de base ({/}) aligné à droite sur 12 caractères de large
{2:%8.2f} - Deuxième source d'entrée ({2}) large de 8 caractères, 2 décimales

Les chaînes de format fonctionnent également sur les chaînes de remplacement définies via --rpl qui commencent par '{'.

Voir aussi : {} {n} --rpl

::: arguments
Utiliser les arguments sur la ligne de commande comme source d'entrée.

Contrairement aux autres options de GNU parallel, ::: est placé après la commande et avant les arguments.

Les lignes suivantes sont équivalentes :

(echo file1; echo file2) | parallel gzip
parallel gzip ::: file1 file2
parallel gzip {} ::: file1 file2
parallel --arg-sep ,, gzip {} ,, file1 file2
parallel --arg-sep ,, gzip ,, file1 file2
parallel ::: "gzip file1" "gzip file2"

Pour éviter que ::: ne soit traité comme spécial, utilisez --arg-sep pour définir le séparateur d'arguments à autre chose.

Si plusieurs ::: sont donnés, chaque groupe sera traité comme une source d'entrée, et toutes les combinaisons de sources d'entrée seront générées. Par exemple, ::: 1 2 ::: a b c produira les combinaisons (1,a) (1,b) (1,c) (2,a) (2,b) (2,c). Ceci est utile pour remplacer des boucles for imbriquées.

:::, ::::, et --arg-file peuvent être mélangés. Donc, ces lignes sont équivalentes :

parallel echo {1} {2} {3} ::: 6 7 ::: 4 5 ::: 1 2 3
parallel echo {1} {2} {3} :::: <(seq 6 7) <(seq 4 5) \
  :::: <(seq 1 3)
parallel -a <(seq 6 7) echo {1} {2} {3} :::: <(seq 4 5) \
  :::: <(seq 1 3)
parallel -a <(seq 6 7) -a <(seq 4 5) echo {1} {2} {3} \
  ::: 1 2 3
seq 6 7 | parallel -a - -a <(seq 4 5) echo {1} {2} {3} \
  ::: 1 2 3
seq 4 5 | parallel echo {1} {2} {3} :::: <(seq 6 7) - \
  ::: 1 2 3

Voir aussi : --arg-sep --arg-file :::: :::+ ::::+ --link

:::+ arguments
Comme ::: mais lié comme --link à la source d'entrée précédente.

Contrairement à --link, les valeurs ne s'enroulent pas : La source d'entrée la plus courte détermine la longueur.

Exemple :

parallel echo ::: a b c :::+ 1 2 3 ::: X Y :::+ 11 22

Voir aussi : ::::+ --link

:::: fichiers d'arguments
Une autre façon de écrire --arg-file argfile1 --arg-file argfile2 ...

::: et :::: peuvent être mélangés.

Voir aussi : --arg-file ::: ::::+ --link

::::+ argfiles
Comme :::: mais lié comme --link à la source d'entrée précédente.

Contrairement à --link, les valeurs ne se répètent pas : la source d'entrée la plus courte détermine la longueur.

Voir aussi : --arg-file :::+ --link

--null
-0
Utiliser NUL comme délimiteur.

Normalement, les lignes d'entrée se terminent par \n (nouvelle ligne). Si elles se terminent par \0 (NUL), utilisez cette option. Elle est utile pour traiter des arguments qui peuvent contenir \n (nouvelle ligne).

Raccourci pour --delimiter '\0'.

Voir aussi : --delimiter

--arg-file input-file
-a input-file
Utiliser input-file comme source d'entrée.

Si plusieurs --arg-file sont donnés, chaque input-file sera traité comme une source d'entrée, et toutes les combinaisons de sources d'entrée seront générées. Par exemple, le fichier foo contient 1 2, le fichier bar contient a b c. -a foo -a bar résultera en les combinaisons (1,a) (1,b) (1,c) (2,a) (2,b) (2,c). Ceci est utile pour remplacer des boucles for imbriquées.

Si input-file commence par +, le fichier sera lié au --arg-file précédent. Par exemple, le fichier foo contient 1 2, le fichier bar contient a b. -a foo -a +bar résultera en les combinaisons (1,a) (2,b) comme --link au lieu de générer toutes les combinaisons.

Voir aussi : --link {n} :::: ::::+ :::

--arg-file-sep sep-str
Utiliser sep-str au lieu de :::: comme chaîne de séparation entre la commande et les fichiers d'arguments.

Utile si :::: est utilisé pour autre chose par la commande.

Voir aussi : ::::

--arg-sep sep-str
Utiliser sep-str au lieu de ::: comme chaîne de séparation.

Utile si ::: est utilisé pour autre chose par la commande.

--bar
Afficher la progression sous forme de barre de progression.

--bf file

--basenamereplace replace-str
--bnr replace-str

--basenameextensionreplace replace-str

--bin binexpr
Utiliser binexpr comme clé de regroupement et regrouper les entrées pour les tâches.

binexpr est [numéro de colonne|nom de colonne] [expression perl] par exemple :

3
Address
3 $_%=100
Address s/\D//g

Chaque ligne d'entrée est divisée en utilisant --colsep. La valeur de la colonne est mise dans $_, l'expression perl est exécutée, la valeur résultante est l'emplacement de tâche qui recevra la ligne. Si la valeur est supérieure au nombre d'emplacements de tâche, la valeur sera modulo le nombre d'emplacements de tâche.

Ceci est similaire à --shard mais l'algorithme de hachage est un simple modulo, ce qui rend prédictible quel emplacement de tâche recevra quelle valeur.

Les performances sont de l'ordre de 100K lignes par seconde. Plus rapide si le bincol est petit (<10), plus lent s'il est grand (>100).

--bin nécessite --pipe et une valeur numérique fixe pour --jobs.

Voir aussi : SPREADING BLOCKS OF DATA --group-by --round-robin --shard

--bg
Exécuter la commande en arrière-plan.

GNU parallel attendra normalement l'achèvement d'une tâche. Avec --bg, GNU parallel n'attendra pas l'achèvement de la commande avant de se terminer.

C'est le comportement par défaut si --semaphore est défini.

Implique --semaphore.

Voir aussi : --fg man sem

--bibtex
--citation
Imprimer l'avis de citation et l'entrée BibTeX pour GNU parallel, supprimer l'avis de citation pour toutes les exécutions futures et quitter. Il n'exécutera aucune commande.

S'il vous est impossible d'exécuter --citation, vous pouvez utiliser à la place --will-cite, qui exécutera des commandes, mais qui ne supprimera l'avis de citation que pour cette seule exécution.

Si vous utilisez --will-cite dans des scripts à exécuter par d'autres, vous rendez plus difficile pour les autres de voir l'avis de citation. Le développement de GNU parallel est indirectement financé par les citations, donc si vos utilisateurs ne savent pas qu'ils doivent citer, vous rendez plus difficile le financement du développement. Cependant, si vous payez 10000 EUR, vous avez fait votre part pour financer le développement futur et devriez vous sentir libre d'utiliser --will-cite dans les scripts.

Si vous ne voulez pas aider à financer le développement futur en laissant d'autres utilisateurs voir l'avis de citation ou en payant, veuillez envisager d'utiliser un autre outil que GNU parallel. Vous pouvez trouver certaines des alternatives dans man parallel_alternatives.

--block size
--block-size size
Taille du bloc en octets à lire à la fois.

Le size peut être suffixé par K, M, G, T, P, k, m, g, t, ou p.

GNU parallel essaie de respecter la taille du bloc, mais peut être inexact de la longueur d'un enregistrement. Pour des raisons de performance, size devrait être supérieur à deux enregistrements. GNU parallel vous avertira et augmentera automatiquement la taille si vous choisissez un size trop petit.

size vaut par défaut 1M.

Une taille de bloc négative n'est pas interprétée comme une taille de bloc mais comme le nombre de blocs que chaque emplacement de tâche doit avoir. Ainsi, --block -3 créera 3 tâches pour chaque emplacement de tâche. En d'autres termes : cela exécutera 3*5 = 15 tâches au total :

parallel --pipe-part -a myfile --block -3 -j5 wc
cat myfile | parallel --pipe --block -3 -j5 wc

--pipe-part --block est une alternative efficace à --round-robin car les données ne sont jamais lues par GNU parallel, mais vous pouvez toujours avoir très peu d'emplacements de tâche traitant d'énormes quantités de données.

D'autre part, --pipe --block est assez inefficace : Il lit tout le fichier en mémoire avant de le diviser. L'entrée doit donc pouvoir tenir en mémoire.

Si vous utilisez --block -size, l'entrée doit être supérieure à size+1 enregistrements.

Voir aussi : UNIT PREFIX -N --pipe --pipe-part --round-robin --block-timeout

--block-timeout duration
--bt duration
Délai d'attente pour la lecture d'un bloc lors de l'utilisation de --pipe.

S'il faut plus de duration pour lire un bloc complet, utiliser le bloc partiel lu jusqu'à présent.

duration est en secondes, mais peut être suffixé par s, m, h, ou d.

Voir aussi : TIME POSTFIXES --pipe --block

--cat
Créer un fichier temporaire avec le contenu.

Normalement, --pipe/--pipe-part transmettra les données au programme sur stdin (entrée standard). Avec --cat, GNU parallel créera un fichier temporaire avec le nom dans {}, vous pouvez donc faire : parallel --pipe --cat wc {}.

Implique --pipe sauf si --pipe-part est utilisé.

Voir aussi : --pipe --pipe-part --fifo

--cleanup

Dans certaines situations, il est inutile d'exécuter tous les jobs. GNU parallel devrait simplement s'arrêter dès qu'une condition est remplie.

n_sleeps() {

  [ $nsleeps -lt $1 ]

parallel --jobs 20auto 'sleep 2.${RANDOM}{}12345; n_sleeps 5' ::: {1..100}

--line-buffer
--lb
Tamponne la sortie ligne par ligne.

--group regroupera la sortie pour une tâche entière. --ungroup permet aux sorties de se mélanger, une moitié de ligne provenant d'une tâche et l'autre moitié d'une autre tâche. --line-buffer se situe entre les deux : GNU parallel affichera une ligne complète, mais permettra le mélange des lignes de différentes tâches.

--line-buffer consomme plus de puissance CPU que --group et --ungroup, mais peut être beaucoup plus rapide que --group si la CPU n'est pas le facteur limitant.

Normalement, --line-buffer ne tamponne pas sur disque, et peut donc traiter une quantité infinie de données, mais il tamponnera sur disque lorsqu'il est combiné avec : --keep-order, --results, --compress et --files. Cela le rendra aussi lent que --group et limitera la sortie à l'espace disque disponible.

Avec --keep-order, --line-buffer affichera les lignes de la première tâche en continu pendant son exécution, puis les lignes de la deuxième tâche pendant son exécution. Il tamponnera les lignes complètes, mais les tâches ne se mélangeront pas. Comparer :

parallel -j0 'echo [{};sleep {};echo {}]' ::: 1 3 2 4
parallel -j0 --lb 'echo [{};sleep {};echo {}]' ::: 1 3 2 4
parallel -j0 -k --lb 'echo [{};sleep {};echo {}]' ::: 1 3 2 4

--match regexp
Fait correspondre la source d'entrée avec une expression régulière pour définir les champs de remplacement.

Avec --match, vous pouvez souvent éviter le prétraitement de votre entrée avec awk ou un outil similaire pour extraire les champs pertinents.

Vous pouvez accéder à chaque groupe de capture, c'est-à-dire les parenthèses dans l'expression régulière '(...)' avec un champ de remplacement. Les champs de remplacement sont nommés {m.n} où m est la source d'entrée et n est le numéro du groupe de capture :

parallel --match +2 --match '([A-Za-z]+)' echo {1.1} {2.1} \
  ::: /Improbability/ ::: 10drive

Pour définir uniquement --match pour la source d'entrée 2, créez un --match fictif pour la source d'entrée 1 :

parallel --match '' --match '([a-z]+)' echo {1} {2.1} \
  ::: Telephone ::: 10sanitizer

--memfree size
Mémoire libre minimale au démarrage d'une autre tâche.

La taille peut être suffixée par K, M, G, T, P, k, m, g, t, ou p.

Si les tâches consomment des quantités de RAM très différentes, GNU parallel ne démarrera que celles pour lesquelles il y a suffisamment de mémoire. Si moins de taille octets sont libres, aucune autre tâche ne sera démarrée. --memsuspend size
Suspend les tâches lorsqu'il y a moins de mémoire disponible.

Si la mémoire disponible tombe en dessous de 2 \* taille, GNU parallel suspendra certaines des tâches en cours. Si la mémoire disponible tombe en dessous de taille, une seule tâche sera en cours d'exécution.

Si une seule tâche tient dans la taille donnée, toutes les tâches se termineront sans manquer de mémoire. Si vous avez de l'espace d'échange disponible, vous pouvez généralement réduire taille à environ la moitié de la taille d'une seule tâche, avec le léger risque de swapper un peu.

Les tâches seront reprises lorsque plus de RAM sera disponible - typiquement lorsque la tâche la plus ancienne se termine.

--memsuspend ne fonctionne que pour les tâches locales car il n'y a pas de moyen évident de suspendre les tâches distantes.

--milestone str
Définit des points de repère où toutes les tâches précédentes doivent être terminées.

Exemple :

doit() {
    start=$(date +%H:%M:%S)
    # Pause jusqu'à 5 secondes
    sleep $((RANDOM % 5000))e-3
    end=$(date +%H:%M:%S)
    echo Start: $start End: $end
}

Cela exécutera (a, b, c), (1, 2), (A, B), (I, II, III). Les tâches d'un lot seront exécutées en parallèle, mais les lots seront exécutés en série.

Remarquez comment l'heure de début de chaque lot est ultérieure à l'heure de fin du lot précédent.

Exemple de produit cartésien :

parallel --tag --milestone // doit ::: Frist_run // Second_run ::: file{1..10}

Cela terminera First_run avec tous les fichiers avant de commencer Second_run sur tous les fichiers.

Exemple de produit cartésien avancé (buggé) :

parallel --tag --milestone // doit ::: a b // 1 2 3 ::: A B C // I II

Les tâches d'un lot seront exécutées en parallèle, mais les lots seront exécutés en série.

Lorsque le bug sera corrigé, il exécutera : [a b] x [A B C], [a b] x [I II], [1 2 3] x [A B C], [1 2 3] x [I II] = (a A, a B, a C, b A, b B, b C), (a I, a II, b I, b II), (1 A, 1 B, 1 C, 2 A, 2 B, 2 C, 3 A, 3 B, 3 C), (1 I, 1 II, 2 I, 2 II, 3 I, 3 II).

--pipe
--spreadstdin
Répartit l'entrée vers les tâches sur stdin (entrée standard).

Lit un bloc de données depuis stdin (entrée standard) et donne un bloc de données en entrée à une tâche.

La taille du bloc est déterminée par --block (par défaut : 1M).

Sauf pour le premier et le dernier enregistrement, GNU parallel ne passe que des enregistrements complets à la tâche. Les chaînes --recstart et --recend déterminent où un enregistrement commence et se termine : la frontière entre deux enregistrements est définie comme --recend immédiatement suivi par --recstart. --resume
Resumes from the last unfinished job.

By reading --joblog or the --results dir GNU parallel will figure out the last unfinished job and continue from there. As GNU parallel only looks at the sequence numbers in --joblog then the input, the command, and --joblog all have to remain unchanged; otherwise GNU parallel may run wrong commands.

See also: --joblog --results --resume-failed --retries

--resume-failed
Retry all failed and resume from the last unfinished job.

By reading --joblog GNU parallel will figure out the failed jobs and run those again. After that it will resume last unfinished job and continue from there. As GNU parallel only looks at the sequence numbers in --joblog then the input, the command, and --joblog all have to remain unchanged; otherwise GNU parallel may run wrong commands.

See also: --joblog --resume --retry-failed --retries

--retry-failed
Retry all failed jobs in joblog.

By reading --joblog GNU parallel will figure out the failed jobs and run those again.

--retry-failed ignores the command and arguments on the command line: It only looks at the joblog.

Differences between --resume, --resume-failed, --retry-failed

In this example exit {= $_%=2 =} will cause every other job to fail.

timeout -k 1 4 parallel --joblog log -j10 \
  'sleep {}; exit {= $_%=2 =}' ::: {10..1}

4 jobs completed. 2 failed:

Seq   [...]   Exitval Signal  Command
10    [...]   1       0       sleep 1; exit 1
9     [...]   0       0       sleep 2; exit 0
8     [...]   1       0       sleep 3; exit 1
7     [...]   0       0       sleep 4; exit 0

--resume does not care about the Exitval, but only looks at Seq. If the Seq is run, it will not be run again. So if needed, you can change the command for the seqs not run yet:

parallel --resume --joblog log -j10 \
  'sleep .{}; exit {= $_%=2 =}' ::: {10..1}
Seq   [...]   Exitval Signal  Command
[... as above ...]
1     [...]   0       0       sleep .10; exit 0
6     [...]   1       0       sleep .5; exit 1
5     [...]   0       0       sleep .6; exit 0
4     [...]   1       0       sleep .7; exit 1
3     [...]   0       0       sleep .8; exit 0
2     [...]   1       0       sleep .9; exit 1

--resume-failed cares about the Exitval, but also only looks at Seq to figure out which commands to run. Again this means you can change the command, but not the arguments. It will run the failed seqs and the seqs not yet run:

parallel --resume-failed --joblog log -j10 \
  'echo {};sleep .{}; exit {= $_%=3 =}' ::: {10..1}
Seq   [...]   Exitval Signal  Command
[... as above ...]
10    [...]   1       0       echo 1;sleep .1; exit 1
8     [...]   0       0       echo 3;sleep .3; exit 0
6     [...]   2       0       echo 5;sleep .5; exit 2
4     [...]   1       0       echo 7;sleep .7; exit 1
2     [...]   0       0       echo 9;sleep .9; exit 0

--retry-failed cares about the Exitval, but takes the command from the joblog. It ignores any arguments or commands given on the command line:

parallel --retry-failed --joblog log -j10 this part is ignored
Seq   [...]   Exitval Signal  Command
[... as above ...]
10    [...]   1       0       echo 1;sleep .1; exit 1
6     [...]   2       0       echo 5;sleep .5; exit 2
4     [...]   1       0       echo 7;sleep .7; exit 1

See also: --joblog --resume --resume-failed --retries

--retries n
Try failing jobs n times.

If a job fails, retry it on another computer on which it has not failed. Do this n times. If there are fewer than n computers in --sshlogin GNU parallel will re-use all the computers. This is useful if some jobs fail for no apparent reason (such as network failure).

n=0 means infinite.

See also: --term-seq --sshlogin

--return filename
Transfer files from remote computers.

--return is used with --sshlogin when the arguments are files on the remote computers. When processing is done the file filename will be transferred from the remote computer using rsync and will be put relative to the default login dir. E.g.

echo foo/bar.txt | parallel --return {.}.out \
  --sshlogin server.example.com touch {.}.out

This will transfer the file $HOME/foo/bar.out from the computer server.example.com to the file foo/bar.out after running touch foo/bar.out on server.example.com.

parallel -S server --trc out/./{}.out touch {}.out ::: in/file

This will transfer the file in/file.out from the computer server.example.com to the files out/in/file.out after running touch in/file.out on server.

echo /tmp/foo/bar.txt | parallel --return {.}.out \
  --sshlogin server.example.com touch {.}.out

This will transfer the file /tmp/foo/bar.out from the computer server.example.com to the file /tmp/foo/bar.out after running touch /tmp/foo/bar.out on server.example.com.

Multiple files can be transferred by repeating the option multiple times:

echo /tmp/foo/bar.txt | parallel \
  --sshlogin server.example.com \
  --return {.}.out --return {.}.out2 touch {.}.out {.}.out2

--return is ignored when used with --sshlogin : or when not used with --sshlogin.

For details on transferring see --transferfile.

See also: --transfer --transferfile --sshlogin --cleanup --workdir

--rpl 'tag perl expression'
Define replacement string.

Use tag as a replacement string for perl expression. This makes it possible to define your own replacement strings. GNU parallel's 7 replacement strings are implemented as:

--rpl '{} '
--rpl '{#} 1 $_=$job->seq()'
--rpl '{%} 1 $_=$job->slot()'
--rpl '{/} s:.*/::'
--rpl '{//} $Global::use{"File::Basename"} ||=
            eval "use File::Basename; 1;"; $_ = dirname($_);'
--rpl '{/.} s:.*/::; s:\.[^/.]+$::;'
--rpl '{.} s:\.[^/.]+$::'

The --plus replacement strings are implemented as:

--rpl '{+/} s:/[^/]*$:: || s:.*$::'
--rpl '{+.} s:.*\.:: || s:.*$::'
--rpl '{+..} s:.*\.([^/.]+\.[^/.]+)$:$1: || s:.*$::'
--rpl '{+...} s:.*\.([^/.]+\.[^/.]+\.[^/.]+)$:$1: || s:.*$::'
--rpl '{..} s:\.[^/.]+\.[^/.]+$::'
--rpl '{...} s:\.[^/.]+\.[^/.]+\.[^/.]+$::'
--rpl '{/..} s:.*/::; s:\.[^/.]+\.[^/.]+$::'
--rpl '{/...} s:.*/::; s:\.[^/.]+\.[^/.]+\.[^/.]+$::'
--rpl '{choose_k}
       for $t (2..$#arg){ if($arg[$t-1] ge $arg[$t]) { skip() } }'
--rpl '{##} 1 $_=total_jobs()'
--rpl '{0%} 1 $f=1+int((log($Global::max_jobs_running||1)/
                        log(10))); $_=sprintf("%0${f}d",slot())'
--rpl '{0#} 1 $f=1+int((log(total_jobs())/log(10)));
            $_=sprintf("%0${f}d",seq())'
--rpl '{seq(.*?)} $_=eval q{$job->seq()}.qq{$$1}'
--rpl '{slot(.*?)} $_=eval q{$job->slot()}.qq{$$1}'
--rpl '{:-([^}]+?)} $_ ||= $$1'
--rpl '{:(\d+?)} substr($_,0,$$1) = ""'
--rpl '{:(\d+?):(\d+?)} $_ = substr($_,$$1,$$2);'
--rpl '{#([^#}][^}]*?)} $nongreedy=::make_regexp_ungreedy($$1);
                        s/^$nongreedy(.*)/$1/;'
--rpl '{##([^#}][^}]*?)} s/^$$1//;'
--rpl '{%([^}]+?)} $nongreedy=::make_regexp_ungreedy($$1);
                   s/(.*)$nongreedy$/$1/;'
--rpl '{%%([^}]+?)} s/$$1$//;'
--rpl '{/([^}]+?)/([^}]*?)} s/$$1/$$2/;'
--rpl '{^([^}]+?)} s/^($$1)/uc($1)/e;'
--rpl '{^^([^}]+?)} s/($$1)/uc($1)/eg;'
--rpl '{,([^}]+?)} s/^($$1)/lc($1)/e;'
--rpl '{,,([^}]+?)} s/($$1)/lc($1)/eg;'
--rpl '{slot} 1 $_="\${PARALLEL_JOBSLOT}";uq()'
--rpl '{host} 1 $_="\${PARALLEL_SSHHOST}";uq()'
--rpl '{sshlogin} 1 $_="\${PARALLEL_SSHLOGIN}";uq()'
--rpl '{hgrp} 1 $_="\${PARALLEL_HOSTGROUPS}";uq()'
--rpl '{agrp} 1 $_="\${PARALLEL_ARGHOSTGROUPS}";uq()'

If the user defined replacement string starts with '{' it can also be used as a positional replacement string (like {2.}).

It is recommended to only change $_ but you have full access to all of GNU parallel's internal functions and data structures.

Voici quelques exemples :

La séquence des tâches est-elle paire ou impaire ?
--rpl '{impair} $_ = seq() % 2 ? "impair" : "pair"'
Remplit la séquence des tâches avec des zéros en tête pour obtenir une largeur égale
--rpl '{0#} $f=1+int("".(log(total_jobs())/log(10)));
  $_=sprintf("%0${f}d",seq())'
Séquence des tâches comptant à partir de 0
--rpl '{#0} $_ = seq() - 1'
Comptage des slots de tâches à partir de 2
--rpl '{%1} $_ = slot() + 1'
Supprime toutes les extensions
--rpl '{:} s:(\.[^/]+)*$::'

Vous pouvez avoir des chaînes de remplacement dynamiques en incluant des parenthèses dans la chaîne de remplacement et en ajoutant une expression régulière entre les parenthèses. La chaîne correspondante sera insérée comme $$1 :

parallel --rpl '{%(.*?)} s/$$1//' echo {%.tar.gz} ::: my.tar.gz
parallel --rpl '{:+(.+?)} s:$$1(\.[^/]+)*$::' \
  echo {:+_file} ::: my_file.tar.gz
parallel -n3 --rpl '{/:+(.*?)} s:.*/(.*)$$1(\.[^/]+)*$:$1:' \
  echo job {#}: {2} {2.} {3/:+_1} ::: a/b.c c/d.e f/g_1.h.i

Vous pouvez même utiliser plusieurs correspondances :

parallel --rpl '{/(.+?)/(.*?)} s/$$1/$$2/;'
  echo {/remplacemoi/parcela} {/b/C} ::: a_remplacemoi_b
parallel --rpl '{(.*?)/(.*?)} $_="$$2$_$$1"' \
  echo {inverser/ces} ::: -milieu-

--sql-master DBURL
Soumettez les jobs via un serveur SQL. DBURL doit pointer vers une table, qui conterra les mêmes informations que --joblog, les valeurs des sources d'entrée (stockées dans les colonnes V1 .. Vn) et la sortie (stockée dans les colonnes Stdout et Stderr).

postgresql://scott:tiger@pg.example.com/pgdb/parjob
pg:///parjob
sqlite3:///%2Ftmp%2Fpardb.sqlite/parjob
sqlite:///file_in_current_dir.sqlite/my_table
csv:///%2Ftmp%2Fpardb/parjob
csv:///./file_in_current_dir
pg:////

Notez comment / dans le chemin de sqlite et CSV doit être encodé en %2F. Sauf le dernier / dans CSV qui doit être un /.

db et table ont par défaut $USER: pg://// = pg:///$USER/$USER

--term-seq séquence
Séquence de terminaison.

Lorsqu'un travail est tué en raison de --timeout, --memfree, --halt ou d'une terminaison anormale de GNU parallel, séquence détermine comment le travail est tué. Le comportement par défaut est :

Transfère nom-fichier vers des ordinateurs distants.

--transferfile est utilisé avec --sshlogin pour transférer des fichiers vers les ordinateurs distants. Les fichiers seront transférés à l'aide de rsync et seront placés par rapport au répertoire de travail.

Le nom-fichier contiendra normalement une chaîne de remplacement.

/tmp/foo/bar   => /tmp/foo/bar

tmp/./foo/bar  => /home/user/foo/bar

SPREADING BLOCKS OF DATA

--round-robin, --pipe-part, --shard, --bin and --group-by are all specialized versions of --pipe.

In the following n is the number of jobslots given by --jobs. A record starts with --recstart and ends with --recend. It is typically a full line. A chunk is a number of full records that is approximately the size of a block. A block can contain half records, a chunk cannot.

--pipe starts one job per chunk. It reads blocks from stdin (standard input). It finds a record end near a block border and passes a chunk to the program.

--pipe-part starts one job per chunk - just like normal --pipe. It first finds record endings near all block borders in the file and then starts the jobs. By using --block -1 it will set the block size to size-of-file/n. Used this way it will start n jobs in total.

--round-robin starts n jobs in total. It reads a block and passes a chunk to whichever job is ready to read. It does not parse the content except for identifying where a record ends to make sure it only passes full records.

--shard starts n jobs in total. It parses each line to read the string in the given column. Based on this string the line is passed to one of the n jobs. All lines having this string will be given to the same jobslot.

--bin works like --shard but the value of the column must be numeric and is the jobslot number it will be passed to. If the value is bigger than n, then n will be subtracted from the value until the value is smaller than or equal to n.

--group-by starts one job per chunk. Record borders are not given by --recend/--recstart. Instead a record is defined by a group of lines having the same string in a given column. So the string of a given column changes at a chunk border. With --pipe every line is parsed, with --pipe-part only a few lines are parsed to find the chunk border.

--group-by can be combined with --round-robin or --pipe-part.

TIME POSTFIXES

Arguments that give a duration are given in seconds, but can be expressed as floats postfixed with s, m, h, or d which would multiply the float by 1, 60, 60*60, or 60*60*24. Thus these are equivalent: 100000 and 1d3.5h16.6m4s.

UNIT PREFIX

Many numerical arguments in GNU parallel can be postfixed with K, M, G, T, P, k, m, g, t, or p which would multiply the number with 1024, 1048576, 1073741824, 1099511627776, 1125899906842624, 1000, 1000000, 1000000000, 1000000000000, or 1000000000000000, respectively.

You can even give it as a math expression. E.g. 1000000 can be written as 1M-12*2.024*2k.

QUOTING

GNU parallel is very liberal in quoting. You only need to quote characters that have special meaning in shell:

( ) $ ` ' " < > ; | \

and depending on context these needs to be quoted, too:

~ & ! ? space * { #

Therefore most people will never need more quoting than putting '\' in front of the special characters.

Often you can simply put \' around every ': 

perl -ne '/^\S+\s+\S+$/ and print $ARGV,"\n"' file

peut être cité :

parallel perl -ne \''/^\S+\s+\S+$/ and print $ARGV,"\n"'\' ::: file

Cependant, lorsque vous souhaitez utiliser une variable shell, vous devez échapper le signe $. Voici un exemple utilisant $PARALLEL_SEQ. Cette variable est définie par GNU parallel lui-même, donc l'évaluation du $ doit être effectuée par le sous-shell démarré par GNU parallel :

seq 10 | parallel -N2 echo seq:\$PARALLEL_SEQ arg1:{1} arg2:{2}

Si la variable est définie avant le démarrage de GNU parallel, vous pouvez faire ceci :

VAR=this_is_set_before_starting
echo test | parallel echo {} $VAR

Affiche : test this_is_set_before_starting

C'est un peu plus délicat si la variable contient plus d'un espace de suite :

VAR="two  spaces  between  each  word"
echo test | parallel echo {} \'"$VAR"\'

Affiche : test two spaces between each word

Si la variable ne doit pas être évaluée par le shell qui démarre GNU parallel mais par le sous-shell démarré par GNU parallel, alors vous devez la citer :

echo test | parallel VAR=this_is_set_after_starting \; echo {} \$VAR

Affiche : test this_is_set_after_starting

C'est un peu plus délicat si la variable contient un espace :

echo test |
  parallel VAR='"two  spaces  between  each  word"' echo {} \'"$VAR"\'

Affiche : test two spaces between each word

$$ est la variable shell contenant l'identifiant du processus du shell. Ceci affichera l'identifiant du processus du shell exécutant GNU parallel :

seq 10 | parallel echo $$

Et ceci affichera les identifiants des processus des sous-shells démarrés par GNU parallel.

seq 10 | parallel echo \$\$

Si les caractères spéciaux ne doivent pas être évalués par le sous-shell, vous devez les protéger contre l'évaluation par le shell qui démarre GNU parallel et par le sous-shell :

echo test | parallel echo {} \\\$VAR

Affiche : test $VAR

GNU parallel peut protéger contre l'évaluation par le sous-shell en utilisant -q :

echo test | parallel -q echo {} \$VAR

Affiche : test $VAR

Ceci est particulièrement utile si vous avez beaucoup de citations. Si vous voulez exécuter un script Perl comme ceci :

perl -ne '/^\S+\s+\S+$/ and print $ARGV,"\n"' file

Il doit être cité comme ceci :

ls | parallel perl -ne '/^\\S+\\s+\\S+\$/\ and\ print\ \$ARGV,\"\\n\"'
ls | parallel perl -ne \''/^\S+\s+\S+$/ and print $ARGV,"\n"'\'

Notez comment les espaces, les ', les ", et les $ doivent être cités. GNU parallel peut effectuer la citation en utilisant l'option -q :

ls | parallel -q  perl -ne '/^\S+\s+\S+$/ and print $ARGV,"\n"'

Cependant, cela signifie que vous ne pouvez pas faire interpréter les caractères spéciaux par le sous-shell. Par exemple, à cause de -q, ceci NE FONCTIONNERA PAS :

ls *.gz | parallel -q "zcat {} >{.}"
ls *.gz | parallel -q "zcat {} | bzip2 >{.}.bz2"

car > et | doivent être interprétés par le sous-shell.

Si vous obtenez des erreurs comme :

sh: -c: line 0: syntax error near unexpected token
sh: Syntax error: Unterminated quoted string
sh: -c: line 0: unexpected EOF while looking for matching `''
sh: -c: line 1: syntax error: unexpected end of file
zsh:1: no matches found:

alors vous pouvez essayer d'utiliser -q.

Si vous utilisez la substitution de processus bash comme <(cat foo), vous pouvez essayer -q et préfixer command avec bash -c :

ls | parallel -q bash -c 'wc -c <(echo {})'

Ou pour la substitution de sortie :

ls | parallel -q bash -c \
  'tar c {} | tee >(gzip >{}.tar.gz) | bzip2 >{}.tar.bz2'

Conclusion : Si cela vous embrouille, essayez d'éviter de devoir gérer les citations en écrivant un petit script ou une fonction (n'oubliez pas de export -f la fonction) et laissez GNU parallel l'appeler.

LISTE DES TRAVAUX EN COURS

Si vous souhaitez une liste des travaux en cours, vous pouvez exécuter :

killall -USR1 parallel

GNU parallel affichera alors les travaux en cours sur stderr (erreur standard).

COMPLÉTER LES TRAVAUX EN COURS MAIS NE PAS EN DÉMARRER DE NOUVEAUX

Si vous regrettez d'avoir lancé beaucoup de travaux, vous pouvez simplement interrompre GNU parallel, mais si vous voulez vous assurer de ne pas avoir de travaux à moitié terminés, vous devriez envoyer le signal SIGHUP à GNU parallel :

killall -HUP parallel

Cela indiquera à GNU parallel de ne pas démarrer de nouveaux travaux, mais d'attendre que les travaux en cours soient terminés avant de quitter.

FICHIERS DE PROFIL

Si --profile est défini, GNU parallel lira le profil depuis ce fichier plutôt que depuis les fichiers de configuration globaux ou utilisateur. Vous pouvez avoir plusieurs --profiles.

Les profils sont recherchés dans ~/.parallel. Si le nom commence par /, il est considéré comme un chemin absolu. Si le nom commence par ./, il est considéré comme un chemin relatif par rapport au répertoire courant.

Exemple : Profil pour exécuter une commande sur chaque sshlogin dans ~/.ssh/sshlogins et préfixer la sortie avec le sshlogin :

echo --tag -S .. --nonall > ~/.parallel/nonall_profile
parallel -J nonall_profile uptime

Exemple : Profil pour exécuter chaque commande avec -j-1 et nice

echo -j-1 nice > ~/.parallel/nice_profile
parallel -J nice_profile bzip2 -9 ::: *

Exemple : Profil pour exécuter un script perl avant chaque commande :

echo "perl -e '\$a=\$\$; print \$a,\" \",\$PARALLEL_SEQ,\" \"';" \
  > ~/.parallel/pre_perl
parallel -J pre_perl echo ::: *

Notez comment les $ et \" doivent être échappés avec \.

Exemple : Profil pour exécuter des tâches distribuées avec nice sur les ordinateurs distants :

echo -S .. nice > ~/.parallel/dist
parallel -J dist --trc {.}.bz2 bzip2 -9 ::: *

DIFFÉRENCES ENTRE GNU Parallel ET LES ALTERNATIVES

Voir : man parallel_alternatives

BOGUES

Mise en guillemets du saut de ligne

En raison de la façon dont le saut de ligne est mis en guillemets, ceci ne fonctionnera pas :

echo 1,2,3 | parallel -vkd, "echo 'a{}b'"

Cependant, ceci fonctionnera :

echo 1,2,3 | parallel -vkd, echo a{}b
echo 1,2,3 | parallel -vkd, "echo 'a'{}'b'"
echo 1,2,3 | parallel -vkd, "echo 'a'"{}"'b'"

Vitesse

Démarrage

GNU parallel est lent au démarrage - environ 250 ms la première fois et 150 ms ensuite.

Démarrage de tâche

Le démarrage d'une tâche sur la machine locale prend environ 3 à 10 ms. Cela peut représenter une surcharge importante si la tâche s'exécute très rapidement. Vous pouvez souvent regrouper de petites tâches ensemble en utilisant -X, ce qui rendra la surcharge moins significative. Ou vous pouvez exécuter plusieurs GNU parallel comme décrit dans EXEMPLE : Accélérer les tâches rapides.

SSH

Lors de l'utilisation de plusieurs ordinateurs, GNU parallel établit des connexions ssh avec eux pour déterminer combien de connexions peuvent être utilisées de manière fiable simultanément (notamment les MaxStartups de SSHD). Ce test est effectué pour chaque hôte en série, donc si votre --sshloginfile contient de nombreux hôtes, cela peut être lent.

Si vos tâches sont courtes, vous pourriez constater qu'il y a moins de tâches en cours d'exécution sur les systèmes distants que prévu. Ceci est dû au temps passé à se connecter et à se déconnecter. -M peut aider ici.

Accès disque

Un seul disque peut normalement lire les données plus rapidement s'il lit un fichier à la fois au lieu de lire de nombreux fichiers en parallèle, car cela évite les déplacements du disque. Cependant, les nouveaux systèmes de disques avec plusieurs lecteurs peuvent lire plus rapidement en lisant parallèlement plusieurs fichiers.

Si les tâches sont du type lire-tout-calculer-tout-écrire-tout, donc tout est lu avant que quoi que ce soit ne soit écrit, il peut être plus rapide de forcer un seul accès disque à la fois :

sem --id diskio cat file | compute | sem --id diskio cat > file

Si les tâches sont du type lire-calculer-écrire, donc l'écriture commence avant que toute la lecture ne soit terminée, il peut être plus rapide de forcer un seul lecteur et un seul écrivain à la fois :

sem --id read cat file | compute | sem --id write cat > file

Si les tâches sont du type lire-calculer-lire-calculer, il peut être plus rapide d'exécuter plus de tâches en parallèle que le système n'a de CPU, car certaines tâches seront bloquées en attendant l'accès disque.

--nice limite la longueur des commandes

L'implémentation actuelle de --nice est trop pessimiste quant à la longueur maximale de commande autorisée. Elle n'utilise qu'un peu plus de la moitié de ce qu'elle pourrait. Cela affecte -X et -m. Si cela devient un problème réel pour vous, signalez un bug.

Les alias et les fonctions ne fonctionnent pas

Si vous obtenez :

Can't exec "command": No such file or directory

ou :

open3: exec of by command failed

ou :

/bin/bash: command: command not found

cela peut être parce que command n'est pas connu, mais cela peut aussi être parce que command est un alias ou une fonction. S'il s'agit d'une fonction, vous devez d'abord exporter -f la fonction ou utiliser env_parallel. Un alias ne fonctionnera que si vous utilisez env_parallel.

La base de données avec MySQL échoue aléatoirement

Les options --sql* peuvent échouer aléatoirement avec MySQL. Ce problème n'existe pas avec PostgreSQL.

  • La sortie complète de parallel --version. Si vous n'utilisez pas la dernière version publiée (voir https://ftp.gnu.org/gnu/parallel/), vous devez spécifier pourquoi vous pensez que le problème n'est pas corrigé dans cette version.
  • Un exemple minimal, complet et vérifiable (Voir la description sur https://stackoverflow.com/help/mcve).

    Il devrait s'agir d'un exemple complet que d'autres peuvent exécuter et qui montre le problème, y compris tous les fichiers nécessaires pour exécuter l'exemple. Il devrait de préférence être petit et simple, alors essayez de supprimer autant d'options que possible.

    Une combinaison de yes, seq, cat, echo, wc et sleep peut reproduire la plupart des erreurs.

    Si votre exemple nécessite de gros fichiers, voyez si vous pouvez les créer avec quelque chose comme seq 100000000 > bigfile ou yes | head -n 1000000000 > file. Si vous avez besoin de plusieurs colonnes : paste <(seq 1000) <(seq 1000 1999)

    Si votre exemple nécessite une exécution à distance, voyez si vous pouvez utiliser localhost - peut-être en utilisant une autre connexion.

    Si vous avez accès à un autre système (peut-être une VirtualBox sur votre propre machine), vérifiez si votre MCVE montre le problème sur ce système. Sinon, lisez ci-dessous.

  • La sortie de votre exemple et ce que vous attendiez à la place. Si votre problème n'est pas facilement reproductible par d'autres, la sortie pourrait les aider à comprendre le problème.
  • Si vous avez regardé les vidéos d'introduction (https://www.youtube.com/playlist?list=PL284C9FF2488BC6D1), parcouru le tutoriel (man parallel_tutorial) et lu les exemples (man parallel_examples).

En général, le problème sera résolu plus rapidement et avec beaucoup moins de travail pour vous si vous pouvez reproduire l'erreur sur une VirtualBox - même si vous devez en créer une.
