NOM

paclog - filtre les entrées du journal de pacman

SYNTAXE

paclog [options] [filtres]...
paclog [options] --pkglist
paclog (--help|--version)

DESCRIPTION

Si une entrée est fournie via stdin, elle sera analysée à la place de --logfile. Les entrées du journal seront affichées si elles correspondent à l'un ou l'autre des filtres fournis. Pour afficher l'intersection de plusieurs filtres, ceux-ci peuvent être connectés par un pipe :

paclog --after=2015-01-01 | paclog --warnings

OPTIONS

--config=chemin
Définit un chemin de fichier de configuration alternatif.
--logfile=chemin
Définit un chemin de fichier journal alternatif.
--root=chemin
Définit une racine d'installation alternative.
--sysroot=chemin
Définit une racine système alternative. Voir pacutils-sysroot(7).
--[no-]color
Colorise la sortie. Par défaut, la sortie sera colorisée si stdout est un terminal.
--pkglist
Affiche la liste des paquets installés selon le journal.
--help
Affiche les informations d'utilisation et quitte.
--version
Affiche les informations de version et quitte.

Filtres

--action=action
Affiche les opérations sur les paquets. action doit être l'une des valeurs suivantes : "install", "reinstall", "upgrade", "downgrade", "remove", ou "all".
--after=date, --before=date
Affiche les entrées après/avant la date. Si des secondes ou des informations de fuseau horaire sont incluses, elles seront ignorées silencieusement, permettant l'utilisation de la sortie de "date -I" : 
paclog --after "$(date -Iminutes --date '3 days ago')"
--caller=nom
Affiche les entrées du journal provenant de nom. Peut être spécifié plusieurs fois. Sensible à la casse.
--commandline
Affiche les entrées de ligne de commande enregistrées de style pacman.
--grep=regex
Affiche les entrées du journal dont le message correspond à la regex.
--package=nom_paquet
Affiche les actions enregistrées affectant nom_paquet. Peut être spécifié plusieurs fois.
--warnings
Affiche les erreurs, avertissements et notes.

AVERTISSEMENTS

paclog détermine s'il faut lire le fichier journal depuis stdin en se basant sur une vérification naïve utilisant isatty(3). Si paclog est appelé dans un environnement, tel qu'une fonction shell ou un script utilisé dans un pipe, où stdin n'est pas connecté à un terminal mais ne contient pas de fichier journal à analyser, paclog devrait être appelé avec stdin fermé. Pour les shells compatibles POSIX, cela peut être fait avec "<&-".
