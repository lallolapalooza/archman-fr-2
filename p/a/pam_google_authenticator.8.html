NOM

pam_google_authenticator - Module PAM pour l'authentification à deux facteurs de Google

SYNTAXE

pam_google_authenticator.so [secret=fichier] [authtok_prompt=invite] [user=nomutilisateur] [no_strict_owner] [allowed_perm=0nnn] [debug] [try_first_pass|use_first_pass|forward_pass] [noskewadj] [no_increment_hotp] [nullok] [echo_verification_code]

DESCRIPTION

Le module pam_google_authenticator est conçu pour protéger l'authentification des utilisateurs avec un second facteur, basé sur le temps (TOTP) ou sur un compteur (HOTP). Avant de se connecter, l'utilisateur sera invité à saisir son mot de passe et un code à usage unique. Ces codes à usage unique peuvent être générés avec l'application Google Authenticator, installée sur l'appareil Android de l'utilisateur. Pour générer et vérifier respectivement ces codes à usage unique, une clé secrète (générée aléatoirement) doit être partagée entre l'appareil sur lequel les codes à usage unique sont générés et le système sur lequel ce module PAM est activé.

Selon sa configuration (voir la section options), ce module exige qu'un fichier secret soit manuellement configuré pour chaque compte sur le système. Ce fichier secret contient la clé secrète et les options spécifiques à l'utilisateur (voir google-authenticator(1)). À moins que l'option nullok ne soit utilisée, les tentatives d'authentification seront rejetées si un tel fichier secret n'existe pas. Alternativement, un administrateur système peut créer ces fichiers secrets au nom des utilisateurs, puis leur communiquer les clés secrètes.

OPTIONS

secret=fichier
Spécifie un emplacement non standard pour le fichier secret.

Par défaut, le module PAM recherche le fichier secret dans le fichier .google_authenticator dans le répertoire personnel de l'utilisateur qui se connecte. Cette option remplace cet emplacement.

L'emplacement fourni peut inclure les raccourcis suivants :

•
${USER} qui sera interprété comme le nom d'utilisateur.
•
${HOME} et ~ qui seront interprétés comme le répertoire personnel de l'utilisateur.
authtok_prompt=invite
Remplace l'invite par défaut pour le token.

Notez que si des espaces sont présents dans l'invite fournie, l'argument entier doit être entouré de crochets.

user=nomutilisateur
Commute vers un utilisateur codé en dur avant d'effectuer toute opération de fichier.
no_strict_owner
Désactive la vérification du propriétaire du fichier secret.

Par défaut, le fichier secret doit appartenir à l'utilisateur qui se connecte. Cette option désactive cette vérification.

allowed_perm=0nnn
Remplace les permissions vérifiées du fichier secret.

Par défaut, le fichier secret ne doit être lisible que par son propriétaire (c'est-à-dire le mode 0600). Cette option permet de spécifier un mode différent pour ce fichier.

debug
Active des messages de journalisation plus détaillés dans syslog.
try_first_pass|use_first_pass|forward_pass
Options d'empilement pour ce module PAM.

Étant donné que certains clients PAM ne peuvent pas demander à l'utilisateur plus qu'un simple mot de passe, les options d'empilement suivantes peuvent être utilisées :

•
try_first_pass : avant de demander à l'utilisateur le code à usage unique, ce module essaie d'abord le mot de passe du module empilé précédent, au cas où celui-ci satisferait également ce module.
•
use_first_pass : force ce module à utiliser un mot de passe d'un module empilé précédent. Avec cette option, ce module ne demandera jamais à l'utilisateur le code à usage unique. Ainsi, si aucun code à usage unique valide n'est disponible, l'utilisateur se verra refuser l'accès.
•
forward_pass : interroge l'utilisateur pour le mot de passe système et le code de vérification dans une seule invite. Le mot de passe système est ensuite transmis au module PAM suivant, qui devra être configuré avec soit l'option use_first_pass, soit l'option try_first_pass.
noskewadj
Ne pas ajuster le décalage temporel automatiquement.

Par défaut, le module PAM tente de compenser le décalage temporel entre le serveur et l'appareil sur lequel les codes à usage unique sont générés. Cette option désactive ce comportement.

Notez que cette option n'est pertinente que pour le mode basé sur le temps (TOTP).

no_increment_hotp
Ne pas incrémenter le compteur pour les tentatives échouées.

Dans certaines circonstances, les mots de passe échoués entraînent toujours une invite OTP. Cette option désactive l'incrémentation du compteur dans de telles situations.

Notez que cette option n'est pertinente que pour le mode basé sur un compteur (HOTP).

nullok
Permettre aux utilisateurs de se connecter sans OTP s'ils n'ont pas encore configuré d'OTP.

Lors du processus de déploiement initial, tous les utilisateurs n'ont peut-être pas encore créé de clé secrète. Cette option leur permet de se connecter, même si le fichier secret n'existe pas.

echo_verification_code
Affiche le code de vérification lorsqu'il est saisi par l'utilisateur.

TYPE MODULE FOURNI

Seul le type de module auth est fourni.

VALEURS DE RETOUR

PAM_SUCCESS
Soit le code à usage unique fourni est correct, soit il s'agit d'un code d'urgence valide.
PAM_IGNORE
Ce module est ignoré.
PAM_AUTH_ERR
Le code à usage unique fourni n'est pas correct et n'est pas un code d'urgence valide, ou une erreur s'est produite.

EXEMPLES

Les lignes suivantes peuvent être utilisées pour activer ce module PAM :

•
auth required pam_google_authenticator.so no_increment_hotp # Assure que le compteur (pour le mode HOTP) n'est pas incrémenté pour les tentatives échouées.
•
auth required pam_google_authenticator.so nullok # Permet aux utilisateurs de se connecter si leurs fichiers secrets n'existent pas
•
auth required pam_google_authenticator.so secret=/var/unencrypted-home/${USER}/.google_authenticator # Stocke les fichiers secrets dans un emplacement spécifique
•
auth required pam_google_authenticator.so [authtok_prompt=Votre token secret : ] # Utilise une invite spécifique
•
auth required pam_google_authenticator.so noskewadj # Ne compense pas automatiquement le décalage temporel

NOTES DE SÉCURITÉ

Pour une sécurité maximale, assurez-vous que le mot de passe et le code à usage unique sont demandés, même si le mot de passe et/ou le code à usage unique sont incorrects. Cela signifie qu'au moins le premier de pam_unix.so (ou tout autre module utilisé pour vérifier les mots de passe) et pam_google_authenticator.so doit être défini comme required, et non comme requisite.
