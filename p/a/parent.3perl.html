NOM

parent - Établir une relation d'héritage avec les classes de base au moment de la compilation

SYNOPSIS

package Baz;
use parent qw(Foo Bar);

DESCRIPTION

Permet à la fois de charger un ou plusieurs modules et de configurer l'héritage de ces modules en même temps. L'effet est principalement similaire à

package Baz;
BEGIN {
    require Foo;
    require Bar;
    push @ISA, qw(Foo Bar);
}

Par défaut, chaque classe de base doit résider dans son propre fichier. Si vous souhaitez avoir une sous-classe et sa classe parente dans le même fichier, vous pouvez indiquer à "parent" de ne pas charger de modules en utilisant le commutateur "-norequire" :

package Foo;
sub exclaim { "J'AI BESOIN DE PERL" }
package DoesNotLoadFooBar;
use parent -norequire, 'Foo', 'Bar';
# ne cherchera pas Foo.pm ou Bar.pm

Ceci est équivalent au code suivant :

package Foo;
sub exclaim { "J'AI BESOIN DE PERL" }
package DoesNotLoadFooBar;
push @DoesNotLoadFooBar::ISA, 'Foo', 'Bar';

Ceci est également utile dans le cas où un paquet réside dans un fichier portant un nom différent :

package MyHash;
use Tie::Hash;
use parent -norequire, 'Tie::StdHash';

Ceci est équivalent au code suivant :

package MyHash;
require Tie::Hash;
push @ISA, 'Tie::StdHash';

Si vous souhaitez charger une sous-classe à partir d'un fichier que "require" ne considérerait pas comme un nom de fichier éligible (c'est-à-dire qu'il ne se termine ni par ".pm" ni par ".pmc"), utilisez le code suivant :

package MySecondPlugin;
require './plugins/custom.plugin'; # contient Plugin::Custom
use parent -norequire, 'Plugin::Custom';
