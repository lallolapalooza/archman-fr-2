NOM

pam_fail_delay - demander un délai en cas d'échec

SYNTAXE

#include <security/pam_appl.h>

int pam_fail_delay(pam_handle_t *pamh, unsigned int usec);

DESCRIPTION

La fonction pam_fail_delay fournit un mécanisme par lequel une application ou un module peut suggérer un délai minimum de usec micro-secondes. La fonction conserve un enregistrement du temps le plus long demandé avec cette fonction. Si pam_authenticate(3) échoue, le retour d'échec à l'application est retardé d'une durée aléatoirement distribuée (jusqu'à 50%) autour de cette valeur la plus longue.

Indépendamment du succès, le délai est réinitialisé à sa valeur nulle par défaut lorsque le module de service PAM renvoie le contrôle à l'application. Le délai survient après l'appel de tous les modules d'authentification, mais avant le retour du contrôle à l'application de service.

Lors de l'utilisation de cette fonction, le programmeur doit vérifier si elle est disponible avec :

#ifdef HAVE_PAM_FAIL_DELAY
    ....
#endif /* HAVE_PAM_FAIL_DELAY */

Pour les applications écrites avec un seul thread et qui sont axées sur les événements, la génération de ce délai peut être indésirable. Au lieu de cela, l'application peut vouloir enregistrer le délai d'une autre manière. Par exemple, dans un serveur monothread qui traite plusieurs requêtes d'authentification à partir d'une seule boucle d'événements, l'application pourrait vouloir simplement marquer une connexion donnée comme bloquée jusqu'à l'expiration d'une minuterie d'application. Pour cette raison, la fonction de délai peut être modifiée avec l'élément PAM_FAIL_DELAY. Il peut être interrogé et défini avec pam_get_item(3) et pam_set_item(3) respectivement. La valeur utilisée pour le définir doit être un pointeur de fonction du prototype suivant :

void (*delay_fn)(int retval, unsigned usec_delay, void *appdata_ptr);

Les arguments étant le code de retour retval de la pile de modules, le délai en micro-secondes usec_delay que libpam demande et le appdata_ptr que l'application a associé à pamh actuel. Cette dernière valeur a été définie par l'application lorsqu'elle a appelé pam_start(3) ou explicitement avec pam_set_item(3).

Notez que l'élément PAM_FAIL_DELAY est défini à NULL par défaut. Cela indique que PAM doit effectuer un délai aléatoire comme décrit ci-dessus en cas d'échec d'authentification et qu'un délai a été suggéré. Si une application ne souhaite pas que la bibliothèque PAM effectue de délai en cas d'échec d'authentification, l'application doit définir une fonction de délai personnalisée qui n'exécute aucune instruction et définir l'élément PAM_FAIL_DELAY pour qu'il pointe vers cette fonction.

RATIONALE

Il est souvent possible d'attaquer un système d'authentification en exploitant le temps qu'il faut au système pour refuser l'accès à un utilisateur demandeur. Dans les cas de timeouts courts, il peut être possible de tenter une attaque par force brute par dictionnaire -- avec un processus automatisé, l'attaquant essaie tous les mots de passe possibles pour accéder au système. Dans d'autres cas, où les échecs individuels peuvent prendre des quantités de temps mesurables (indiquant la nature de l'échec), un attaquant peut obtenir des informations utiles sur le processus d'authentification. Ces dernières attaques utilisent des délais procéduraux qui constituent un canal clandestin d'informations utiles.

Pour minimiser l'efficacité de telles attaques, il est souhaitable d'introduire un délai aléatoire dans un processus d'authentification échoué. De préférence, cette valeur devrait être définie par l'application ou un module PAM spécial. Les modules PAM standard ne devraient pas modifier le délai sans condition.

EXEMPLE

Par exemple, une application de connexion peut nécessiter un délai en cas d'échec d'environ 3 secondes. Elle contiendra le code suivant :

    pam_fail_delay (pamh, 3000000 /* micro-secondes */ );
    pam_authenticate (pamh, 0);

si les modules ne demandent pas de délai, le délai en cas d'échec sera compris entre 1,5 et 4,5 secondes.

Cependant, les modules, appelés dans le processus d'authentification, peuvent également demander des délais :

module #1:    pam_fail_delay (pamh, 2000000);
module #2:    pam_fail_delay (pamh, 4000000);

dans ce cas, c'est la plus grande valeur demandée qui est utilisée pour calculer le délai réel en cas d'échec : ici, entre 2 et 6 secondes.

VALEURS DE RETOUR

PAM_SUCCESS

Le délai a été ajusté avec succès.

PAM_SYSTEM_ERR

Un pointeur NULL a été soumis comme handle PAM.

VOIR AUSSI

pam_start(3), pam_get_item(3), pam_strerror(3)

NORMES

La fonction pam_fail_delay est une extension de Linux-PAM.
