NOM

pam_sss - Module PAM pour SSSD

SYNTAXE

pam_sss.so [quiet] [forward_pass] [use_first_pass] [use_authtok] [retry=N] [ignore_unknown_user] [ignore_authinfo_unavail] [domains=X] [allow_missing_name] [prompt_always] [try_cert_auth] [require_cert_auth] [allow_chauthtok_by_root]

DESCRIPTION

pam_sss.so est l'interface PAM du démon System Security Services (SSSD). Les erreurs et les résultats sont enregistrés via syslog(3) avec le LOG_AUTHPRIV facility.

OPTIONS

quiet

Supprime les messages de journalisation pour les utilisateurs inconnus.

forward_pass

Si forward_pass est défini, le mot de passe saisi est placé sur la pile pour que d'autres modules PAM puissent l'utiliser.

use_first_pass

L'argument use_first_pass force le module à utiliser le mot de passe du module précédent empilé et ne demandera jamais à l'utilisateur; si aucun mot de passe n'est disponible ou si le mot de passe n'est pas approprié, l'utilisateur se verra refuser l'accès.

use_authtok

Lors du changement de mot de passe, force le module à définir le nouveau mot de passe sur celui fourni par un module de mot de passe précédemment empilé.

retry=N

Si spécifié, l'utilisateur est invité N fois supplémentaires pour un mot de passe si l'authentification échoue. La valeur par défaut est 0.

Veuillez noter que cette option peut ne pas fonctionner comme prévu si l'application appelant PAM gère le dialogue utilisateur de manière autonome. Un exemple typique est sshd avec PasswordAuthentication.

ignore_unknown_user

Si cette option est spécifiée et que l'utilisateur n'existe pas, le module PAM retournera PAM_IGNORE. Cela amène le framework PAM à ignorer ce module.

ignore_authinfo_unavail

Spécifie que le module PAM doit retourner PAM_IGNORE s'il ne parvient pas à contacter le démon SSSD. Cela amène le framework PAM à ignorer ce module.

domains

Permet à l'administrateur de restreindre les domaines contre lesquels un service PAM particulier est autorisé à authentifier. Le format est une liste de noms de domaines SSSD séparés par des virgules, comme spécifié dans le fichier sssd.conf.

NOTE : Si cela est utilisé pour un service qui ne s'exécute pas en tant qu'utilisateur root, par exemple un serveur web, il doit être utilisé conjointement avec les options “pam_trusted_users” et “pam_public_domains”. Veuillez consulter la page de manuel sssd.conf(5) pour plus d'informations sur ces deux options de réponse PAM.

allow_missing_name

Le but principal de cette option est de permettre à SSSD de déterminer le nom d'utilisateur en fonction d'informations supplémentaires, par exemple le certificat d'une carte à puce.

Le cas d'utilisation actuel concerne les gestionnaires de connexion qui peuvent surveiller un lecteur de carte à puce pour les événements de carte. Dans le cas où une carte à puce est insérée, le gestionnaire de connexion appellera une pile PAM qui inclut une ligne telle que

auth sufficient pam_sss.so allow_missing_name

Dans ce cas, SSSD essaiera de déterminer le nom d'utilisateur en fonction du contenu de la carte à puce, le renverra à pam_sss qui le placera finalement sur la pile PAM.

prompt_always

Demande toujours à l'utilisateur ses identifiants. Avec cette option, les identifiants demandés par d'autres modules PAM, typiquement un mot de passe, seront ignorés et pam_sss demandera à nouveau les identifiants. Sur la base de la réponse pré-authentification de SSSD, pam_sss pourrait demander un mot de passe, un code PIN de carte à puce ou d'autres identifiants.

try_cert_auth

Essaye d'utiliser l'authentification par certificat, c'est-à-dire l'authentification avec une carte à puce ou des périphériques similaires. Si une carte à puce est disponible et que le service est autorisé pour l'authentification par carte à puce, l'utilisateur sera invité à saisir un code PIN et l'authentification par certificat se poursuivra.

Si aucune carte à puce n'est disponible ou si l'authentification par certificat n'est pas autorisée pour le service actuel, PAM_AUTHINFO_UNAVAIL est retourné.

require_cert_auth

Effectue l'authentification par certificat, c'est-à-dire l'authentification avec une carte à puce ou des périphériques similaires. Si une carte à puce n'est pas disponible, l'utilisateur sera invité à en insérer une. SSSD attendra une carte à puce jusqu'à ce que le délai défini par p11_wait_for_card_timeout soit dépassé, veuillez consulter sssd.conf(5) pour plus de détails.

Si aucune carte à puce n'est disponible après le délai ou si l'authentification par certificat n'est pas autorisée pour le service actuel, PAM_AUTHINFO_UNAVAIL est retourné.

allow_chauthtok_by_root

Par défaut, l'action chauthtok de PAM renverra PAM_SUCCESS lorsque pam_sss.so est appelé par l'utilisateur root.

Cette option désactive ce comportement, permettant de modifier les jetons d'authentification lors de l'exécution en tant que root.

TYPES DE MODULES FOURNIS

Tous les types de modules (account, auth, password et session) sont fournis.

Si le répondeur PAM de SSSD n'est pas en cours d'exécution, par exemple si le socket du répondeur PAM n'est pas disponible, pam_sss retournera PAM_USER_UNKNOWN lorsqu'il est appelé comme module account pour éviter les problèmes avec les utilisateurs d'autres sources pendant le contrôle d'accès.

VALEURS DE RETOUR

PAM_SUCCESS

L'opération PAM s'est terminée avec succès.

PAM_USER_UNKNOWN

L'utilisateur n'est pas connu du service d'authentification ou le répondeur PAM de SSSD n'est pas en cours d'exécution.

PAM_AUTH_ERR

Échec de l'authentification. Peut également être retourné en cas de problème lors de l'obtention du certificat.

PAM_PERM_DENIED

Permission refusée. Les fichiers journaux de SSSD peuvent contenir des informations supplémentaires sur l'erreur.

PAM_IGNORE

Voir les options ignore_unknown_user et ignore_authinfo_unavail.

PAM_AUTHTOK_ERR

Impossible d'obtenir le nouveau jeton d'authentification. Peut également être retourné lorsque les options use_first_pass ou use_authtok étaient définies, mais aucun mot de passe n'a été trouvé à partir du module PAM précédemment empilé.

PAM_AUTHINFO_UNAVAIL

Impossible d'accéder aux informations d'authentification. Cela peut être dû à une défaillance réseau ou matérielle.

PAM_BUF_ERR

Une erreur de mémoire s'est produite. Peut également être retourné lorsque les options use_first_pass ou use_authtok étaient définies, mais aucun mot de passe n'a été trouvé à partir du module PAM précédemment empilé.

PAM_SYSTEM_ERR

Une erreur système s'est produite. Les fichiers journaux de SSSD peuvent contenir des informations supplémentaires sur l'erreur.

PAM_CRED_ERR

Impossible de définir les identifiants de l'utilisateur.

PAM_CRED_INSUFFICIENT

L'application ne dispose pas des identifiants suffisants pour authentifier l'utilisateur. Par exemple, code PIN manquant lors de l'authentification par carte à puce ou facteur manquant lors de l'authentification à deux facteurs.

PAM_SERVICE_ERR

Erreur dans le module de service.

PAM_NEW_AUTHTOK_REQD

Le jeton d'authentification de l'utilisateur a expiré.

PAM_ACCT_EXPIRED

Le compte utilisateur a expiré.

PAM_SESSION_ERR

Impossible de récupérer les règles de profil de bureau IPA ou les informations utilisateur.

PAM_CRED_UNAVAIL

Impossible de récupérer les identifiants utilisateur Kerberos.

PAM_NO_MODULE_DATA

Aucune méthode d'authentification n'a été trouvée par Kerberos. Cela peut se produire si l'utilisateur a une carte à puce attribuée mais que le plugin pkint n'est pas disponible sur le client.

PAM_CONV_ERR

Échec de la conversation.

PAM_AUTHTOK_LOCK_BUSY

Aucun KDC approprié pour le changement de mot de passe n'est disponible.

PAM_ABORT

Appel PAM inconnu.

PAM_MODULE_UNKNOWN

Tâche ou commande PAM non prise en charge.

PAM_BAD_ITEM

Le module d'authentification ne peut pas gérer les identifiants de carte à puce.

FICHIERS

Si une réinitialisation de mot de passe par root échoue, parce que le fournisseur SSSD correspondant ne prend pas en charge la réinitialisation de mot de passe, un message individuel peut être affiché. Ce message peut par exemple contenir des instructions sur la façon de réinitialiser un mot de passe.

Le message est lu à partir du fichier pam_sss_pw_reset_message.LOC où LOC représente une chaîne de locale renvoyée par setlocale(3). S'il n'y a pas de fichier correspondant, le contenu de pam_sss_pw_reset_message.txt est affiché. Root doit être le propriétaire des fichiers et seul root peut avoir les permissions de lecture et d'écriture, tandis que tous les autres utilisateurs ne doivent avoir que des permissions de lecture.

Ces fichiers sont recherchés dans le répertoire /etc/sssd/customize/DOMAIN_NAME/. S'il n'y a pas de fichier correspondant, un message générique est affiché.
