NOM

passwd.nntp - Mots de passe pour la connexion aux serveurs NNTP distants

DESCRIPTION

Le fichier pathetc/passwd.nntp contient des triplets hôte / nom / mot de passe à utiliser lors de l'authentification des programmes clients auprès des serveurs NNTP. Ce fichier est normalement interprété par "NNTPsendpassword()" dans libinn(3). Les lignes vides et les lignes commençant par un signe dièse ("#") sont ignorées. Toutes les autres lignes doivent se composer de trois ou quatre champs séparés par des deux-points :

hôte:nom:motdepasse
hôte:nom:motdepasse:style

Le premier champ est le nom d'un hôte et est comparé sans tenir compte de la casse. (Aucune comparaison détaillée, telle que la comparaison d'adresses IP, n'est effectuée.)

Le deuxième champ est un nom d'utilisateur, et le troisième est un mot de passe. Si le nom d'utilisateur ou le mot de passe est vide, alors cette partie de l'authentification n'aura pas lieu. (Par exemple, un serveur peut nécessiter uniquement un nom d'utilisateur, auquel cas le mot de passe n'est pas nécessaire. Notez qu'un nom d'utilisateur est obligatoire avec AUTHINFO USER/PASS.)

Le quatrième champ optionnel spécifie le type d'authentification à utiliser. Actuellement, le seul « style d'authentification » reconnu est "authinfo" ; c'est aussi le défaut. Cela signifie que les commandes AUTHINFO USER/PASS sont utilisées pour s'authentifier auprès de l'hôte distant. (Ces commandes NNTP sont décrites dans la RFC 4643.)

Par exemple :

mit.edu:bbn:monmotdepasse
uunet.uu.net:bbn:yoyoma:authinfo

Ce fichier ne doit pas être lisible par tous.

actsync, getlist, inews, innxbatch, innxmit, nnrpd, nntpget et rnews utilisent passd.nntp lorsqu'ils ont besoin de se connecter à un serveur distant.
