NOM

pam_winbind.conf - Fichier de configuration du module PAM pour Winbind

DESCRIPTION

Ce fichier de configuration fait partie de la suite samba(7).

pam_winbind.conf est le fichier de configuration du module PAM pam_winbind. Voir pam_winbind(8) pour plus de détails.

SYNTAXE

Le fichier de configuration pam_winbind.conf est un fichier de configuration classique de style ini. Il n'y a qu'une seule section (globale) où diverses options sont définies.

OPTIONS

pam_winbind prend en charge plusieurs options qui peuvent être définies soit dans les fichiers de configuration PAM, soit dans le fichier de configuration pam_winbind situé à /etc/security/pam_winbind.conf. Les options du fichier de configuration PAM ont la priorité sur celles du fichier de configuration pam_winbind.conf.

debug = yes|no

Fournit une sortie de débogage à syslog. La valeur par défaut est "no".

debug_state = yes|no

Fournit une sortie de débogage détaillée de l'état PAM à syslog. La valeur par défaut est "no".

require_membership_of = [SID ou NOM]

Si cette option est définie, pam_winbind réussira uniquement si l'utilisateur est membre du SID ou du NOM donné. Un SID peut être un SID de groupe, un SID d'alias ou même un SID d'utilisateur. Il est également possible de donner un NOM au lieu du SID. Ce nom doit avoir la forme : MYDOMAIN\mygroup ou MYDOMAIN\myuser (où le caractère '\' correspond à la valeur du paramètre winbind separator). Il est également possible d'utiliser un UPN sous la forme user@REALM ou group@REALM. pam_winbind recherchera alors le SID en interne. Notez que le NOM ne peut contenir aucun espace. Il est donc recommandé de n'utiliser que les SIDs. Vous pouvez vérifier la liste des SIDs dont un utilisateur est membre avec wbinfo --user-sids=SID. Ce paramètre est vide par défaut.

Cette option ne fonctionne que lors de l'authentification par mot de passe, et ne restreindra pas l'accès si un mot de passe n'est pas requis pour une raison quelconque (comme une connexion basée sur une clé SSH).

try_first_pass = yes|no

Par défaut, pam_winbind essaie d'obtenir le jeton d'authentification d'un module précédent. Si aucun jeton n'est disponible, il demande à l'utilisateur l'ancien mot de passe. Avec cette option, pam_winbind échoue avec une erreur si aucun jeton d'authentification d'un module précédent n'est disponible. Si un mot de passe principal n'est pas valide, PAM demandera un mot de passe. La valeur par défaut est "no".

krb5_auth = yes|no

pam_winbind peut authentifier en utilisant Kerberos lorsque winbindd communique avec un contrôleur de domaine Active Directory. L'authentification Kerberos doit être activée avec ce paramètre. Lorsque l'authentification Kerberos ne peut pas réussir (par exemple, en raison d'un décalage d'horloge), winbindd se rabattra sur l'authentification samlogon sur MSRPC. Lorsque ce paramètre est utilisé conjointement avec winbind refresh tickets, winbind maintiendra à jour votre Ticket Granting Ticket (TGT) en le rafraîchissant chaque fois que nécessaire. La valeur par défaut est "no".

krb5_ccache_type = [type]

Lorsque pam_winbind est configuré pour tenter l'authentification Kerberos en activant l'option krb5_auth, il peut stocker le Ticket Granting Ticket (TGT) récupéré dans un cache de credentials. Le type de cache de credentials peut être contrôlé avec cette option. Les valeurs supportées sont : KCM ou KEYRING (lorsqu'ils sont supportés par la bibliothèque Kerberos du système et le système d'exploitation), FILE et DIR (lorsque le type DIR est supporté par la bibliothèque Kerberos du système). Dans le cas de FILE, un cache de credentials sous la forme /tmp/krb5cc_UID sera créé - dans le cas de DIR, vous DEVEZ spécifier un répertoire. UID est remplacé par l'identifiant numérique de l'utilisateur. Le répertoire UID est créé. Le chemin jusqu'au répertoire doit déjà exister. Vérifiez les détails de l'implémentation Kerberos.

Lors de l'utilisation du type KEYRING, le mécanisme supporté est « KEYRING:persistent:UID », qui utilise le keyring du noyau Linux pour stocker les credentials par UID. Le KEYRING a ses limitations. Comme il s'agit de mémoire sécurisée du noyau, le stockage en bloc de credentials n'est par exemple pas possible.

Lors de l'utilisation du type KCM, le mécanisme supporté est « KCM:UID », qui utilise un gestionnaire de credentials Kerberos pour stocker les credentials par UID, similaire à KEYRING. C'est le choix recommandé sur les distributions Linux récentes, offrant un gestionnaire de credentials Kerberos. Sinon, nous suggérons d'utiliser KEYRING car c'est la méthode la plus sûre et la plus prévisible.

Il est également possible de définir des chemins de fichiers personnalisés et d'utiliser le modèle "%u" afin de substituer l'identifiant numérique de l'utilisateur. Exemples :

krb5_ccache_type = DIR:/run/user/%u/krb5cc

Ceci créera un fichier de cache de credentials dans le répertoire spécifié.

krb5_ccache_type = FILE:/tmp/krb5cc_%u

Ceci créera un fichier de cache de credentials.

Laissez vide pour simplement effectuer l'authentification Kerberos sans avoir de cache de tickets après la réussite de la connexion. Ce paramètre est vide par défaut.

cached_login = yes|no

Winbind permet de se connecter en utilisant des credentials mis en cache lorsque winbind offline logon est activé. Pour utiliser cette fonctionnalité depuis le module PAM, cette option doit être définie. La valeur par défaut est "no".

silent = yes|no

Ne pas émettre de messages. La valeur par défaut est "no".

mkhomedir = yes|no

Crée le répertoire personnel de l'utilisateur à la volée, cette option est valide dans le bloc de session PAM. La valeur par défaut est "no".

warn_pwd_expire = days

Définit le nombre de jours avant que pam_winbind ne commence à avertir des mots de passe expirant bientôt. La valeur par défaut est 14 jours.

pwd_change_prompt = yes|no

Génère une invite pour changer un mot de passe expiré. La valeur par défaut est "no".
