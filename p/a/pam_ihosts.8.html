pam_ihosts(8) Manuel de l'administrateur système pam_ihosts(8)

NOM

pam_ihosts - Autoriser ou bloquer les connexions sur la base de l'adresse MAC, de l'adresse IP ou de l'enregistreur/région IP.

SYNTAXE

pam_ihosts.so [user=<nom d'utilisateur>] [syslog] [allow-device=<périphérique>] [allow-mac=<adresse mac>] [allow-ip=<adresse ip>] [allow-region=<région>] [region-files=<chemins>] [script=<chemin>]

DESCRIPTION

pam_ihosts examine l'IP distante d'un utilisateur pour empêcher/autoriser la connexion des utilisateurs ayant déjà fourni leurs identifiants corrects.

pam_ihosts.so peut utiliser les fichiers de « stats » que les enregistreurs régionaux d'Internet fournissent afin de rechercher l'enregistreur et le pays auxquels une adresse IP est enregistrée, permettant ainsi une forme de géolocalisation rudimentaire.

pam_ihosts.so définit les variables d'environnement suivantes lors de la connexion. L'adresse IP source de la connexion est stockée dans « IHOSTS_ADDRESS », l'adresse MAC source dans « IHOSTS_MAC » et les informations de région sont stockées dans la variable d'environnement « IHOSTS_REGION » pour être utilisées par les programmes après la connexion.

Attention. pam_ihosts.so refuse la connexion par défaut pour tout utilisateur pour lequel il est spécifié de le gérer. Des options doivent être fournies pour indiquer l'adresse MAC, l'adresse IP, le code pays ou la région des hôtes autorisés à se connecter.

OPTIONS

Les options PAM qui peuvent être appliquées aux fichiers de configuration dans /etc/pam.d sont les suivantes.

user=[modèles d'utilisateur]
Liste séparée par des virgules de modèles fnmatch (style shell) qui identifient les utilisateurs auxquels cette règle s'applique. Pour correspondre à tous les utilisateurs, laissez cette option vide, laissez-la en blanc ou définissez-la explicitement sur « user=* ». Un caractère « ! » au début du modèle permet l'inversion, donc pour correspondre à tous les utilisateurs sauf root, utilisez : « user=!root »
conf-file=[chemin]
Spécifie un chemin vers un fichier de configuration qui peut contenir n'importe quelles options pam_ihosts. Le fichier de configuration ne s'applique qu'à la ligne actuelle de la configuration PAM, vous pouvez donc avoir, par exemple, plusieurs entrées dans la configuration PAM avec différentes correspondances « user= » et différents fichiers de configuration.
syslog
Enregistrer les événements via des messages syslog
script=[chemin]
Exécuter un script lorsqu'une connexion est refusée ou autorisée. Les arguments passés au script seront « ALLOW/DENY » « User », « IP », « Mac Address », « Device » et « Region ». « Region » sera au format « <enregistreur>:<code pays> », donc par exemple, « ripencc:GB ».
allow-ip=[ip]
Une liste séparée par des virgules de modèles fnmatch qui correspondent aux adresses IP autorisées à se connecter.
allow-hosts=[hôte]
Une liste séparée par des virgules de modèles qui correspondent aux noms d'hôtes (recherchés à partir de l'adresse IP) autorisés à se connecter.
allow-dyndns=[hôte]
Une liste séparée par des virgules de noms d'hôtes (pas de modèles) autorisés à se connecter (voir 'DYNDNS' ci-dessous).
allow-mac=[mac]
Une liste séparée par des virgules de modèles fnmatch qui correspondent aux adresses MAC autorisées à se connecter.
allow-dev=[dev]
Une liste séparée par des virgules de modèles fnmatch qui correspondent aux noms de périphériques réseau auxquels la connexion arrive. Il s'agit de la carte réseau de votre machine qui reçoit la connexion de l'hôte distant.
allow-region=[région]
Une liste séparée par des virgules de modèles fnmatch qui correspondent aux chaînes de région recherchées dans les fichiers des enregistreurs IP. Les chaînes de région sont au format « <enregistreur>:<code pays> ». Cette option nécessite que vous fournissiez les chemins des fichiers de région avec l'option « region-files ». Pour plus de détails, voir « REGIONS » ci-dessous.
region-files=[chemins]
Une liste séparée par des virgules de chemins vers des fichiers contenant les affectations d'enregistreurs IP. Chaque chemin peut être précédé de « mmap: » auquel cas le programme utilisera une mmap partagée du fichier (voir FICHIERS MEMORISÉS EN CACHE ci-dessous). Pour plus de détails, voir « REGIONS » ci-dessous.
blacklist=[chemins]
Une liste séparée par des virgules de chemins vers des fichiers contenant des adresses IP, des adresses MAC ou des noms d'hôtes qui sont listés en noir (connexion refusée). Les fichiers doivent contenir un élément (adresse IP) par ligne. Chaque chemin peut être précédé de « mmap: » auquel cas le programme utilisera une mmap partagée du fichier (voir FICHIERS MEMORISÉS EN CACHE ci-dessous).
whitelist=[chemins]
Une liste séparée par des virgules de chemins vers des fichiers contenant des adresses IP, des adresses MAC ou des noms d'hôtes qui sont listés en blanc (connexion autorisée). Les fichiers doivent contenir un élément (adresse IP) par ligne. Chaque chemin peut être précédé de « mmap: » auquel cas le programme utilisera une mmap partagée du fichier (voir FICHIERS MEMORISÉS EN CACHE ci-dessous).
dnsblacklist=[domaines]
Une liste séparée par des virgules de domaines à utiliser pour les recherches de listes noires DNS. Ainsi, par exemple, « dnsblacklist=zen.spamhaus.org,bots.abuse.net » vérifierait si l'hôte est présent dans les listes noires DNS zen.spamhaus.org ou bots.abuse.net. Les éléments pour lesquels une entrée correspondante est retournée se voient refuser la connexion. Les recherches DNS ne sont pas exécutées en parallèle mais les unes après les autres, donc malheureusement la connexion peut devenir lente si de nombreuses listes sont interrogées.
dnswhitelist=[domaines]
Une liste séparée par des virgules de domaines à utiliser pour les recherches de listes blanches DNS. Ainsi, par exemple, « dnswhitelist=whitelist.spamhaus.org,mylist.local » vérifierait si l'hôte est présent dans whitelist.spamhaus.org ou mylist.local. Les éléments pour lesquels une entrée correspondante est retournée sont autorisés à se connecter. Les recherches DNS ne sont pas exécutées en parallèle mais les unes après les autres, donc malheureusement la connexion peut devenir lente si de nombreuses listes sont interrogées.

DYNDNS

Les noms d'hôtes utilisés dans le type de règle « allow-host » sont recherchés à partir de l'adresse IP à partir de laquelle la tentative de connexion provient. Cependant, pour le type de règle « allow-dyndns », les recherches vont dans l'autre sens. Chaque nom d'hôte répertorié dans la règle est recherché, et vérifié s'il a la même adresse IP que l'adresse à laquelle la connexion est effectuée. Ceci est destiné à permettre l'utilisation de services DNS dynamiques qui autorisent les hôtes qui changent leur adresse IP (soit parce que l'hôte est mobile, soit parce que son IP est attribuée par son FAI et change fréquemment) contre un nom d'hôte. Normalement, ces hôtes auront un nom d'hôte « réel » contrôlé par le FAI, et le nom DNS dynamique est un nom secondaire. Ainsi, rechercher le nom d'hôte pour l'IP retournera le nom d'hôte principal « réel », donc la vérification doit être effectuée en recherchant l'IP pour le nom d'hôte dynamique, et en vérifiant si cela correspond à l'IP à partir de laquelle la connexion est effectuée.

FICHIERS DE REGION

Les informations de région sont recherchées dans les fichiers fournis par les Registres Régionaux d'Internet. Ces fichiers sont téléchargeables aux adresses suivantes :

http://ftp.lacnic.net/pub/stats/lacnic/delegated-lacnic-latest # Amérique Latine
http://ftp.ripe.net/ripe/stats/delegated-ripencc-latest # Europe, Russie, Moyen-Orient
http://ftp.arin.net/pub/stats/arin/delegated-arin-extended-latest # Amérique du Nord
http://ftp.afrinic.net/pub/stats/afrinic/de

pam_ihosts(8) — Arch Linux man pages

NAME

pam_ihosts

PAM module for host and MAC address checking

SYNOPSIS

/etc/pam.d/pam_ihosts

account    required  pam_ihosts.so ...

DESCRIPTION

pam_ihosts.so is a PAM module that allows to control access based on IP address, hostname, and MAC address. It can also restrict access based on geographic regions, using data obtained from the regional internet registries (RIRs).

OPTIONS

The module takes the following options:

user=
Specify a user or a list of users. If the current user is not in the list, the rule is ignored. A user can be specified as * (wildcard), or a comma-separated list. Use ! to negate the list (e.g. user=!root means all users except root).
allow-ip=
Allow access from the specified IP address or network. Supports CIDR notation (e.g. 192.168.1.0/24) and wildcards (e.g. 192.168.1.*). If no other allow-* option is specified, access is denied by default.
allow-host=
Allow access from the specified hostname or domain. Supports wildcards (e.g. *.example.com).
allow-mac=
Allow access from the specified MAC address. MAC addresses are specified in colon-separated hexadecimal notation (e.g. ff:c0:a8:e4:99:31).
allow-region=
Allow access from the specified geographic region. The format is RIR:COUNTRY_CODE, where RIR is one of afrinic, apnic, arin, lacnic, or ripencc. * can be used as a wildcard for the country code. Examples: apnic:* (any country in Asia Pacific), ripencc:GB (Great Britain).
region-files=
Specify a comma-separated list of files containing delegated IP addresses from regional internet registries. These files are used by the allow-region option. See the REGION FILES section below.
syslog
Log denied attempts to syslog.
debug
Enable debugging messages.

DYNDNS

If the hostname resolves to a dynamic IP address, it will be checked against the list of allowed IPs. If the IP address is not found, the hostname will be re-checked.

REGION FILES

These files contain IP address assignments from the Regional Internet Registries (RIRs). The format is:

YYYY|AA|ALLOCATED PA |START_IP|CIDR_BLOCK|COUNTRY
YYYY|AA|ALLOCATED PA |START_IP|END_IP|COUNTRY

The files can be downloaded from the following URLs:

http://ftp.afrinic.net/pub/stats/afrinic/delegated-afrinic-latest # Africa
http://ftp.apnic.net/stats/apnic/delegated-apnic-latest # Asia Pacific

BLACKLISTS/WHITELISTS

Blacklist/whitelist files contain IP addresses, hostnames, or MAC addresses that are either denied or allowed login. One item per line. All three types of item can be present in the same file. Blacklist files are checked first, and then can be overridden with whitelist files. As pam_ihosts denies login by default, so a whitelist file can be used on its own. To use only a blacklist file, one would have to specify "allow-ip=*" and then specify a blacklist file, which would have the effect of allowing everything except those things in the blacklist file.

MMAPPED FILES

Blacklist, whitelist and region file paths can be prefixed with "mmap:" In this case pam_ihosts uses a shared memory mapping of the file. Provided that some other program currently has the file mapped, pam_ihosts will not have to load the file from disk, as it will already be available as shared memory. This can significantly improve performance for large files, at the cost of some memory. If no other program has the file mmapped, then pam_ihosts loads it into shared memory, but has to pay the performance cost of loading it from disk. Therefore, for this system to deliver a benefit, some long-lived program has to keep the files mapped.

EXAMPLES

Allow root login only from 192.168.0.x

account    required  pam_ihosts.so user=root syslog allow-ip=192.168.0.*

For all users allow login only from two mac-addresses

account    required  pam_ihosts.so user=* allow-mac=ff:c0:a8:e4:99:31,ff:c0:a8:f9:cc:01

For all users other than root, allow login only from ip-addresses in Great Britain.

account    required  pam_ihosts.so user=!root region-files=/etc/ip-lists/delegated-afrinic-latest,/etc/ip-lists/delegated-lacnic-latest,/etc/ip-lists/delegated-apnic-latest,/etc/ip-lists/delegated-ripencc-latest allow-region=ripencc:GB

For all users, allow login only from Asia Pacific IPs.

account    required  pam_ihosts.so user=* region-files=/etc/ip-lists/delegated-afrinic-latest,/etc/ip-lists/delegated-lacnic-latest,/etc/ip-lists/delegated-apnic-latest,/etc/ip-lists/delegated-ripencc-latest allow-region=apnic:*

Same as above, but perhaps more efficient, only look up regions in the apnic file.

account    required  pam_ihosts.so user=* region-files=/etc/ip-lists/delegated-apnic-latest allow-region=apnic:*

For all users, allow login only from Asia Pacific IPs. Use mmap shared memory for the afrinic and lacnic files.

account    required  pam_ihosts.so user=* region-files=mmap:/etc/ip-lists/delegated-afrinic-latest,mmap:/etc/ip-lists/delegated-lacnic-latest,/etc/ip-lists/delegated-apnic-latest,/etc/ip-lists/delegated-ripencc-latest allow-region=apnic:*
