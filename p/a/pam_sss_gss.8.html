NOM

pam_sss_gss - Module PAM pour l'authentification GSSAPI de SSSD

SYNTAXE

pam_sss_gss.so [debug]

DESCRIPTION

pam_sss_gss.so authentifie l'utilisateur via GSSAPI en collaboration avec SSSD.

Ce module tentera d'authentifier l'utilisateur en utilisant le nom de service GSSAPI basé sur l'hôte host@hostname qui se traduit par un principal Kerberos host/hostname@REALM. La partie REALM du nom du principal Kerberos est dérivée par les mécanismes internes de Kerberos et peut être définie explicitement dans la configuration de la section [domain_realm] de /etc/krb5.conf.

SSSD est utilisé pour fournir le nom de service souhaité et pour valider les identifiants de l'utilisateur en utilisant les appels GSSAPI. Si le ticket de service est déjà présent dans le cache des identifiants Kerberos ou si le ticket d'octroi de ticket de l'utilisateur peut être utilisé pour obtenir le ticket de service correct, alors l'utilisateur sera authentifié.

Si pam_gssapi_check_upn est Vrai (par défaut), alors SSSD exige que les identifiants utilisés pour obtenir les tickets de service puissent être associés à l'utilisateur. Cela signifie que le principal propriétaire des identifiants Kerberos doit correspondre au nom principal de l'utilisateur tel que défini dans LDAP.

Pour activer l'authentification GSSAPI dans SSSD, définissez l'option pam_gssapi_services dans la section [pam] ou de domaine de sssd.conf. Les identifiants de service doivent être stockés dans la keytab de SSSD (elle est déjà présente si vous utilisez le fournisseur ipa ou ad). L'emplacement de la keytab peut être défini avec l'option krb5_keytab. Voir sssd.conf(5) et sssd-krb5(5) pour plus de détails sur ces options.

Certains déploiements Kerberos permettent d'associer des indicateurs d'authentification à une méthode de pré-authentification particulière utilisée pour obtenir le ticket d'octroi de ticket par l'utilisateur. pam_sss_gss.so permet d'imposer la présence d'indicateurs d'authentification dans les tickets de service avant que certains services PAM ne puissent être accédés.

Si pam_gssapi_indicators_map est défini dans la section [pam] ou de domaine de sssd.conf, alors SSSD effectuera une vérification de la présence de tout indicateur configuré dans le ticket de service.

OPTIONS

debug

Affiche des informations de débogage.

TYPES DE MODULE FOURNIS

Seul le type de module auth est fourni.

VALEURS DE RETOUR

PAM_SUCCESS

L'opération PAM s'est terminée avec succès.

PAM_USER_UNKNOWN

L'utilisateur n'est pas connu du service d'authentification ou l'authentification GSSAPI n'est pas prise en charge.

PAM_AUTH_ERR

Échec de l'authentification.

PAM_AUTHINFO_UNAVAIL

Impossible d'accéder aux informations d'authentification. Cela pourrait être dû à un échec réseau ou matériel.

PAM_SYSTEM_ERR

Une erreur système s'est produite. Les fichiers journaux SSSD peuvent contenir des informations supplémentaires sur l'erreur.

EXEMPLES

Le cas d'utilisation principal est de fournir une authentification sans mot de passe dans sudo mais sans avoir besoin de désactiver complètement l'authentification. Pour y parvenir, activez d'abord l'authentification GSSAPI pour sudo dans sssd.conf :

[domain/MYDOMAIN]
pam_gssapi_services = sudo, sudo-i

Et activez ensuite le module dans la pile PAM souhaitée (par exemple, /etc/pam.d/sudo et /etc/pam.d/sudo-i).

...
auth sufficient pam_sss_gss.so
...

DÉPANNAGE

Les journaux SSSD, la sortie de débogage de pam_sss_gss et syslog peuvent contenir des informations utiles sur l'erreur. Voici quelques problèmes courants :

1. La variable d'environnement KRB5CCNAME est définie et l'authentification ne fonctionne pas : Selon votre version de sudo, il est possible que sudo ne passe pas cette variable à l'environnement PAM. Essayez d'ajouter KRB5CCNAME à env_keep dans /etc/sudoers ou dans vos règles sudo LDAP options par défaut.

2. L'authentification ne fonctionne pas et syslog contient "Server not found in Kerberos database" : Kerberos est probablement incapable de résoudre le bon royaume pour le ticket de service basé sur le nom d'hôte. Essayez d'ajouter le nom d'hôte directement à [domain_realm] dans /etc/krb5.conf comme ceci :

3. L'authentification ne fonctionne pas et syslog contient "No Kerberos credentials available" : Vous n'avez pas d'identifiants pouvant être utilisés pour obtenir le ticket de service requis. Utilisez kinit ou authentifiez-vous via SSSD pour acquérir ces identifiants.

4. L'authentification ne fonctionne pas et le journal SSSD sssd-pam contient "User with UPN [$UPN] was not found." ou "UPN [$UPN] does not match target user [$username]." : Vous utilisez des identifiants qui ne peuvent pas être mappés à l'utilisateur en cours d'authentification. Essayez d'utiliser kswitch pour sélectionner un autre principal, assurez-vous de vous être authentifié auprès de SSSD ou envisagez de désactiver pam_gssapi_check_upn.

.myhostname = MYREALM
