Nom

pam_mount.conf - Description du fichier de configuration de pam_mount

Vue d'ensemble

Le fichier de configuration pam_mount définit les valeurs par défaut pour les commandes que pam_mount exécutera, les messages qu'il affichera et les volumes à monter lors de la connexion. Depuis pam_mount 0.18, le fichier de configuration est écrit en XML afin de simplifier la base de code de pam_mount tout en offrant une liberté de formatage à l'utilisateur final. Les caractères spéciaux comme <, > et & utilisés par XML lui-même doivent être encodés en &lt;, &gt; et &amp;, respectivement ; de plus, " doit être encodé en &quot; dans une zone quot;...", mais ces trois/quatre symboles sont peu susceptibles d'être v Multiple.

N'utilisez pas de commentaires à l'intérieur des éléments prenant du texte littéral, comme <fusermount></fusermount> - ceci n'est pas géré par l'analyseur d'arborescence XML de pam_mount.

Définitions de volumes

Les volumes sont définis avec l'élément <volume>, qui prend principalement les paramètres sous forme d'attributs, tels que

<volume user="joe" fstype="nfs" server="fsbox" path="/home/%(USER)" mountpoint="/bigdisk/%(USER)" />

et définissent quoi monter pour qui et comment. Il existe de nombreux paramètres ajustables, décrits dans cette section.

Contrôle utilisateur simple

Les attributs suivants contrôlent si le volume sera monté une fois que l'utilisateur se sera connecté. Par défaut, les volumes s'appliquent à tous les utilisateurs, et la spécification d'attributs les limite aux conditions données, c'est-à-dire qu'ils sont logiquement combinés par un ET. Il existe un mécanisme plus puissant et verbeux pour spécifier des conditions complexes, décrit plus loin dans la section « Contrôle utilisateur étendu ».

user="nom_utilisateur"
Limite le volume à l'utilisateur spécifié, identifié par son nom
uid="nombre" ou uid="nombre-nombre"
Limite le volume à l'utilisateur (ou aux utilisateurs) spécifié(s), identifié(s) par son (leur) UID ou une plage d'UID.
pgrp="nom_groupe"
Limite le volume aux utilisateurs dont le groupe principal est celui identifié par le nom.
gid="nombre" ou gid="nombre-nombre"
Limite le volume aux utilisateurs dont le (les) groupe(s) principal(aux) est (sont) donné(s) par le GID ou une plage de GIDs.
sgrp="nom_groupe"
Limite le volume aux utilisateurs membres du groupe identifié par son nom (en tant que groupe principal ou secondaire).

Configuration du volume

Les attributs suivants sélectionnent la source du volume, la destination, les options, etc.

fstype="type"
Le type de système de fichiers, qui peut être tout ce que votre noyau, l'espace utilisateur et pam_mount comprennent. Si fstype spécifie un type spécial à pam_mount, pam_mount le gérera. Sinon, fstype est passé à mount(8) qui recherche ensuite un utilitaire d'espace utilisateur /sbin/mount.fstype et l'exécute s'il existe, et dans tous les autres cas, mount(8) appellera mount(2) pour que le noyau le monte directement. mount(8) connaît un type de fstype auto, qui peut être utile dans certains cas. Ne pas spécifier l'attribut fstype implique fstype="auto". Notez que le montage avec auto peut échouer si le module noyau du système de fichiers n'est pas encore chargé, car mount(8) vérifiera /proc/partitions.
Les types de fstype cifs, smbfs, ncpfs, fuse, nfs et nfs4 sont remplacés par pam_mount et nous exécutons les programmes d'aide respectifs directement au lieu d'invoquer mount(8) avec l'ensemble d'arguments par défaut qui sont souvent insuffisants pour les systèmes de fichiers réseau. Voir la section « Exemples » de cette page de manuel ci-dessous pour plus de détails.
noroot="1"
Appelle le programme mount sans privilèges root. Il est défini par défaut sur oui pour le type de fstype fuse, car les volumes FUSE doivent être montés en tant qu'utilisateur qui se connecte pour obtenir l'accès aux fichiers par défaut.
server="nom"
Définit le serveur auquel se connecter dans le cas des types de fstype cifs, smbfs et ncpfs et nfs. Pour tous les autres types de fs, cet attribut est ignoré. Vous pouvez également spécifier le serveur dans l'attribut path, mais vous devez respecter la syntaxe spécifique qu'un fstype particulier requiert. (Par exemple, CIFS utilise "//server/path", tandis que NFS utilise "server:path", etc.)
path="chemin"
Cet attribut obligatoire spécifie l'emplacement du volume, relatif au serveur (s'il est spécifié).
mountpoint="répertoire"
Ceci spécifie le répertoire de destination sur lequel le volume est monté. "~" s'étend au répertoire personnel de l'utilisateur tel qu'il est présent dans la base de données passwd, selon la sémantique de sh. "~nom" n'est pas pris en charge. Si cet attribut est omis, l'emplacement est lu depuis /etc/fstab, ce qui requiert également que path soit un périphérique ou un répertoire source d'une entrée fstab.
header="chemin"
Ceci spécifie un fichier de métadonnées détaché (séparé) où l'en-tête LUKS est stocké. Ceci correspond à l'option `cryptsetup --header`. Si cet attribut est omis, la fonctionnalité d'en-tête LUKS détaché n'est pas utilisée.
options="..."
Spécifie les options de montage. Si omises et que /etc/fstab est utilisé (voir mountpoint), les options seront également sources de fstab.
ssh="0" ou ssh="1"
L'option ssh active un wrapper de piratage d'entrée (zerossh, voir fd0ssh(1)) pour ce volume afin de passer le mot de passe à ssh via un mécanisme spécifique à ssh. Activez cette option pour tout montage impliquant le binaire SSH, par exemple ccgfs ou sshfs. Ne l'activez pas pour autre chose, sinon la connexion risque de se bloquer.
empty_pass="0" ou empty_pass="1"
L'option empty_pass contrôle le comportement lorsqu'un mot de passe vide est fourni ou qu'un mot de passe n'est pas disponible. La valeur par défaut, true, essaiera de déverrouiller un volume avec une clé de chaîne vide si aucun mot de passe n'est disponible. Lorsque empty_pass est false, pam_mount ne tentera pas de monter le volume à moins qu'un mot de passe non vide ne soit disponible.
cipher="chiffrement"
Nom du chiffrement cryptsetup pour le volume. À utiliser avec le type fstype crypt.
fskeycipher="type_chiffrement"
Nom du chiffrement OpenSSL pour la clé de fichier (fskey). À utiliser avec le type fstype crypt (dm-crypt et LUKS). Le mot-clé spécial "none" peut être utilisé pour passer directement le contenu du fichier à cryptsetup sans déchiffrement par OpenSSL.
fskeyhash="hash"
Nom du hachage OpenSSL pour la clé de fichier (fskey).
fskeypath="chemin"
Chemin vers la clé du système de fichiers. ignoresource="1" Ignore le chemin source lors de la vérification si le volume était déjà monté. Ceci est utile dans le cas où le chemin source spécifié dans path est différent du chemin stocké dans le noyau. Cela pourrait

Variables

Dans les attributs et les commandes (voir la section ultérieure), des espace réservés ou variables spécifiques, identifiés par %(nom), peuvent être utilisés. Ceux-ci sont substitués au moment de l'invocation de la commande.

%(USER)
Se développe en le nom d'utilisateur de l'utilisateur qui se connecte.
%(DOMAIN_NAME), %(DOMAIN_USER)
Winbind a des noms d'utilisateur UNIX spéciaux sous la forme « domaine\nom d'utilisateur », et %(DOMAIN_NAME) et %(DOMAIN_USER) fournissent les parties distinctes de celui-ci. Ceci est utile lorsqu'un nom de partage sur un serveur MSAD est identique au nom d'utilisateur, par exemple <volume fstype="cifs" server="fsbox" path="%(DOMAIN_USER)" />.
%(USERUID), %(USERGID)
L'UID et le GID numériques du groupe principal de l'utilisateur qui se connecte. Ceci est obtenu via getpw*(), pas getuid(). Il est utile en conjonction avec les options de montage uid= ou gid=, par exemple <volume options="uid=%(USERUID)" />. Notez que vous n'avez pas besoin de spécifier uid=%(USERUID) pour les montages smbfs ou cifs car cela est déjà fait automatiquement par pam_mount.
%(GROUP)
Le nom du groupe pour %(USERGID).

Toutes les autres variables que vous pourriez trouver dans le code source sont internes à pam_mount, et sont susceptibles de ne pas être développées lorsque vous vous y attendriez.

paramètres pam_mount

Outre les volumes, d'autres éléments sont autorisés dans pam_mount.conf.xml qui contrôlent le comportement de pam_mount lui-même.

Réglages généraux

<debug enable="1" />
Active une sortie détaillée pendant la connexion vers stderr et syslog. Certains programmes ne gèrent pas la sortie envoyée sur stderr, voir doc/bugs.txt pour une liste. 0 désactive le débogage, 1 active le traçage de pam_mount, et 2 active en plus le traçage dans mount.crypt. La valeur par défaut est 0. Comme le fichier de configuration est analysé linéairement, la directive <debug> prend effet une fois qu'elle est vue - il est donc conseillé de la placer près du début du fichier, avant toute définition de <volume>.
<logout wait="microsecondes" hup="oui/non" term="oui/non" kill="oui/non" />
Il existe des programmes qui ne se terminent pas lorsque la session est fermée. (Ceci s'applique à la fermeture « finale », c'est-à-dire lorsque la dernière session utilisateur se termine.) Exemples : des processus tournant encore en arrière-plan ; ou un gestionnaire de session X défectueux qui n'a pas nettoyé ses enfants, ou d'autres programmes X qui n'ont pas réagi à la notification de terminaison du serveur X. pam_mount peut être configuré pour tuer ces processus et éventuellement attendre avant d'envoyer des signaux.
<luserconf name=".pam_mount.conf.xml" />
Les utilisateurs individuels peuvent définir des volumes supplémentaires dans un fichier portant le nom spécifié nom par rapport à leur répertoire personnel. La présence de <luserconf> dans le fichier de configuration maître active cette fonctionnalité. Si elle est activée, les utilisateurs peuvent monter et démonter tous les volumes qu'ils spécifient et dont ils sont propriétaires (dans le cas des montages locaux). Le processus de montage est exécuté en tant que superutilisateur. Cela peut avoir des implications en matière de sécurité, donc cette fonctionnalité est désactivée par défaut. Les configurations utilisateur sont analysées après que tous les volumes du fichier de configuration global aient été montés, de sorte qu'il est possible de monter d'abord les répertoires personnels avec une configuration globale, puis de monter d'autres volumes à partir des configurations utilisateur.
<mntoptions allow="options,..." />
Les éléments <mntoptions> déterminent quelles options peuvent être spécifiées dans <volumes> dans les fichiers de configuration par utilisateur (voir <luserconf>). Cela ne s'applique pas au fichier maître. La spécification de <mntoptions> est interdite et ignorée dans les configurations par utilisateur. La liste autorisée par défaut se compose de "nosuid,nodev", et ce défaut est effacé lorsque le premier attribut allow="..." est rencontré par l'analyseur de configuration. Toutes les autres allow="..." sont additives, cependant.
<mntoptions deny="options,..." />
Toutes les options listées dans deny ne peuvent pas apparaître dans la liste d'options des montages par utilisateur. La liste deny par défaut est vide.
<mntoptions require="options,..." />
Toutes les options listées dans require doivent apparaître dans la liste d'options des montages par utilisateur. La liste require par défaut se compose de "nosuid,nodev", et comme allow="", elle est effacée lorsqu'elle est rencontrée pour la première fois par l'analyseur, et est sinon additive.
<path>répertoires...</path>
La valeur par défaut pour la variable d'environnement PATH n'est pas cohérente entre les distributions, et par conséquent, pam_mount fournit son propre ensemble de valeurs par défaut raisonnables que vous pouvez modifier à volonté.

Lié au volume

<mkmountpoint enable="1" remove="true" />
Contrôle la création et la suppression automatiques des points de montage. Si un point de montage n'existe pas lorsque le volume est sur le point d'être monté, pam_mount peut être instruit d'en créer un en utilisant l'attribut enable. Normalement, les répertoires créés de cette manière sont conservés après la déconnexion, mais remove peut être défini sur true pour supprimer à nouveau le point de montage, mais seulement s'il a été créé automatiquement par pam_mount dans la même session auparavant.

Programmes auxiliaires

Certains programmes de montage nécessitent des paramètres par défaut spéciaux pour fonctionner correctement. Il est de bonne pratique de spécifier uid= pour CIFS par exemple, car il est monté en tant que root et afficherait autrement des fichiers appartenant à root au lieu de l'utilisateur qui se connecte.

<fd0ssh>programme...</fd0ssh>
fd0ssh est une astuce autour d'OpenSSH qui le fait essentiellement lire les mots de passe depuis stdin alors qu'OpenSSH ne le fait normalement pas.
<fsck>fsck -p %(FSCKTARGET)</fsck>
Les volumes locaux seront vérifiés avant le montage si ce programme est défini.
<ofl>ofl -k%(SIGNAL) %(MNTPT)</ofl>
L'Open File Lister est utilisé pour identifier les processus utilisant des fichiers dans le sous-répertoire donné, et éventuellement envoyer un signal à ces processus.
<pmvarrun>pmvarrun ...</pmvarrun>
pmvarrun(8) est un programme séparé pour gérer le compteur de référence suivant les sessions utilisateur.

Programmes de montage

Commandes pour monter/démonter des volumes. Elles peuvent prendre des paramètres, comme montré. Vous pouvez spécifier des chemins absolus ou relatifs, auquel cas $PATH sera recherché. Comme les programmes de connexion ont des chemins par défaut différents, pam_mount a sa propre définition de chemin (voir ci-dessus).

<lclmount>mount -t %(FSTYPE) ...</lclmount>
Le programme de montage régulier.
<umount>umount %(MNTPT)</umount>
Sauf s'il existe un programme de démontage dédié pour un type de système de fichiers donné, le programme de démontage régulier sera utilisé.
Linux supporte le démontage paresseux en utilisant `/sbin/umount -l`. Cela peut être dangereux pour les volumes chiffrés car le périphérique sous-jacent n'est pas désactivé. Les périphériques en boucle sont également affectés par cela (ne sont pas désactivés lorsque des fichiers sont encore ouverts). De plus, le démontage sur les volumes SMB doit être appelé sur %(MNTPT) et non sur %(VOLUME).

Commandes pour divers programmes de montage. Tous n'ont pas d'aide de démontage dédiée car certains n'en ont pas besoin.

<cifsmount>mount.cifs ...</cifsmount>
<cryptmount>mount.crypt ...</cryptmount>
<cryptumount>umount.crypt %(MNTPT)</cryptumount>
Aides au montage pour les volumes dm-crypt et LUKS.
<fusemount>mount.fuse ...</fusemount>
<fuseumount>fuserumount ...</fuseumount>
<ncpmount>ncpmount ...</ncpmount>
<ncpumount>ncpumount ...</ncpumount>
<nfsmount>mount %(SERVER):%(VOLUME) ...</nfsmount>
<smbmount>smbmount ...</smbmount>
<smbumount>smbumount ...</smbumount>

Messages

<msg-authpw>pam_mount mot de passe:</msg-authpw>
Lorsque pam_mount ne peut pas obtenir de mot de passe via PAM, ou est configuré pour ne pas le faire en premier lieu, et est configuré pour demander un mot de passe interactivement en remplacement, cette invite sera affichée.
<msg-sessionpw>réentrer...:</msg-sessionpw>
Si le bloc PAM 'session' n'a pas le mot de passe (par exemple lors d'un su de root à utilisateur), il demandera à nouveau. Cette invite peut également être personnalisée.

Contrôle étendu de l'utilisateur

Parfois, les attributs de contrôle utilisateur simples pour l'élément <volume> ne sont pas suffisants lorsque l'on souhaite construire des expressions plus complexes concernant à qui un volume s'applique. Au lieu d'attributs, le contrôle utilisateur étendu est configuré à l'aide d'éléments supplémentaires dans <volume>, par exemple

<volume path="/dev/shm" mountpoint="~"> <and> <sgrp>students</sgrp> <not> <sgrp>profs</sgrp> </not> </and> </volume>

Ce qui se traduit par (étudiants && !professeurs).

Opérateurs logiques

<and><elements>*</and>
Tous les éléments à l'intérieur de celui-ci sont logiquement combinés par un ET. N'importe quel nombre d'éléments peut apparaître.
<or><elements>*</or>
Tous les éléments contenus ici sont logiquement OUés. Un nombre quelconque d'éléments peut apparaître.
<xor><elements>{2}</xor>
Les deux éléments à l'intérieur de <xor> sont logiquement XORés.
<not><element></not>
Le seul élément à l'intérieur de <not> est logiquement nié.

Sélection utilisateur

<user>nom_utilisateur</user>
Correspondance avec le nom d'utilisateur donné.
<uid>nombre</uid> ou <uid>nombre-nombre</uid>
Correspondance avec l'UID de l'utilisateur qui se connecte contre un UID ou une plage d'UID.
<gid>nombre</gid> ou <gid>nombre-nombre</gid>
Correspondance avec le groupe principal de l'utilisateur qui se connecte contre un GID ou une plage de GID.
<pgrp>nom_groupe</pgrp>
Vérifie si l'utilisateur qui se connecte a nom_groupe comme groupe principal.
<sgrp>nom_groupe</sgrp>
Vérifie si l'utilisateur qui se connecte est membre du groupe donné par nom (c'est-à-dire qu'il s'agit d'un groupe principal ou secondaire).

Attributs

icase="yes" ou icase="no"
L'attribut icase peut être utilisé sur <user>, <pgrp> et <sgrp> pour activer la correspondance insensible à la casse (ou non). Il est par défaut à "no".
regex="yes" (ou no)
L'attribut regex peut être utilisé sur <user>, <pgrp> et <sgrp> pour activer l'interprétation du contenu textuel de la balise comme un motif d'expression régulière compatible Perl. Cet attribut peut être combiné avec "icase" (voir ci-dessus). Exemple : <user regex="yes">joe</user> correspond à tout utilisateur qui contient la séquence de lettres "joe" quelque part dans son nom d'utilisateur. Par conséquent, utilisez la fonctionnalité regex avec prudence et envisagez d'ajouter des ancres ^ et $ pour limiter les surprises de sécurité. Exemple : <user regex="yes">^.*joe.*$</user> si vous vouliez vraiment faire correspondre la séquence à n'importe quelle position.

Exemples

N'oubliez pas que ~ peut être utilisé dans l'attribut mountpoint pour désigner le répertoire personnel tel que récupérable via getpwent(3).

sshfs et ccgfs

Ne pas spécifier de chemin après le deux-points (:) utilise le chemin où ssh vous mènera, généralement le répertoire personnel. Avec fd0ssh (package hxtools) installé :

<volume fstype="fuse" path="sshfs#%(USER)@fileserver:" mountpoint="~" ssh="1" />

Sans fd0ssh :

<volume fstype="fuse" path="sshfs#%(USER)@fileserver:" mountpoint="~" options="nosuid,nodev,noatime,reconnect,nonempty,allow_other,default_permissions,password_stdin" ssh="0" noroot="0" />

<volume fstype="fuse" path="ccgfs-ssh-pull#%(USER)@host:directory" mountpoint="~" />

Notez que l'option "password_stdin" de sshfs essaie de localiser une chaîne "assword" dans la sortie de ssh, tandis que fd0ssh utilise plutôt l'API "askpass", qui pourrait également fonctionner avec des clés SSH protégées par phrase secrète dont l'invite est assez différente.

encfs 1.4.x et supérieur

<volume fstype="fuse" path="encfs#/crypto/%(USER)" mountpoint="~" options="nonempty" />

(encfs 1.3 n'est plus supporté.)

Montages NFS

<volume fstype="nfs" server="fileserver" path="/home/%(USER)" mountpoint="~" />

Montages CIFS

<volume user="user" fstype="cifs" server="krueger" path="public" mountpoint="/home/user/krueger" />

Montages Bind

Cela peut être utile en conjonction avec pam_chroot :

<volume path="/bin" mountpoint="~/bin" options="bind" />

Montages tmpfs

Montage tmpfs volatil avec taille limitée (merci à Mike Hommey pour cet exemple) :

<volume user="test" fstype="tmpfs" mountpoint="/home/test" options="size=10M,uid=%(USER),mode=0700" />

Volumes dm-crypt

Les montages cryptés nécessitent un noyau avec CONFIG_BLK_DEV_DM et CONFIG_DM_CRYPT activés, ainsi que tous les chiffrements qui vont être utilisés, par exemple CONFIG_CRYPTO_AES, CONFIG_CRYPTO_BLOWFISH, CONFIG_CRYPTO_TWOFISH.

<volume path="/home/%(USER).img" mountpoint="~" cipher="aes-cbc-essiv:sha256" fskeycipher="aes-256-cbc" fskeyhash="sha1" fskeypath="/home/%(USER).key" />

Volumes LUKS

<volume path="/home/%(USER).img" mountpoint="~" cipher="aes-cbc-essiv:sha256" />

volume path="/home/%(USER).img" mountpoint="~" header="/home/%(USER)-header.img" />

Volumes cryptoloop

cryptoloop n'est pas explicitement supporté par pam_mount. Citant le texte d'aide de configuration du noyau Linux : "ATTENTION : Ce périphérique [cryptoloop] n'est pas sûr pour les systèmes de fichiers journalisés [...]. Veuillez utiliser le module Device Mapper [dm-crypt] à la place."

Maison cryptée OpenBSD

Exemple de répertoire personnel crypté OpenBSD :

<volume path="/home/user.img" mountpoint="/home/user" options="svnd0" />
