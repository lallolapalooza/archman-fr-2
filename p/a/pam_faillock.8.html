NOM

pam_faillock - Module comptant les échecs d'authentification pendant un intervalle spécifié

SYNOPIS

auth ... pam_faillock.so {preauth|authfail|authsucc} [conf=/chemin/vers/fichier-config] [dir=/chemin/vers/repertoire-comptage] [even_deny_root] [deny=n] [fail_interval=n] [unlock_time=n] [root_unlock_time=n] [admin_group=nom] [audit] [silent] [no_log_info]

account ... pam_faillock.so [dir=/chemin/vers/repertoire-comptage] [no_log_info]

DESCRIPTION

Ce module maintient une liste des échecs d'authentification par utilisateur pendant un intervalle spécifié et bloque le compte si le nombre d'échecs consécutifs d'authentification dépasse deny.

Normalement, les tentatives échouées d'authentification de root ne bloquent **pas** le compte root, afin d'éviter un déni de service : si vos utilisateurs ne disposent pas de comptes shell et que root ne peut se connecter que via su ou à la console de la machine (pas par telnet/rsh, etc.), cela est sûr.

OPTIONS

{preauth|authfail|authsucc}

Cet argument doit être défini en fonction de la position de cette instance de module dans la pile PAM.

L'argument preauth doit être utilisé lorsque le module est appelé avant les modules qui demandent les identifiants de l'utilisateur, comme le mot de passe. Le module examine simplement si l'utilisateur doit être bloqué de l'accès au service en cas d'un nombre anormal d'échecs d'authentification consécutifs récents. Cet appel est facultatif si authsucc est utilisé.

L'argument authfail doit être utilisé lorsque le module est appelé après les modules qui déterminent le résultat de l'authentification, en cas d'échec. À moins que l'utilisateur ne soit déjà bloqué en raison d'échecs d'authentification précédents, le module enregistrera l'échec dans le fichier de comptage approprié de l'utilisateur.

L'argument authsucc doit être utilisé lorsque le module est appelé après les modules qui déterminent le résultat de l'authentification, en cas de succès. À moins que l'utilisateur ne soit déjà bloqué en raison d'échecs d'authentification précédents, le module effacera alors l'enregistrement des échecs dans le fichier de comptage respectif de l'utilisateur. Sinon, il renverra une erreur d'authentification. Si cet appel n'est pas effectué, pam_faillock ne distinguera pas les échecs d'authentification consécutifs des échecs non consécutifs. L'appel preauth doit être utilisé dans ce cas. En raison des complications de la configuration de la pile PAM, il est également possible d'appeler pam_faillock comme module de compte. Dans une telle configuration, le module doit également être appelé à l'étape preauth.

conf=/chemin/vers/fichier-config

Utilise un autre fichier de configuration au lieu du fichier par défaut /etc/security/faillock.conf.

Les options de configuration du comportement du module sont décrites dans la page de manuel faillock.conf(5). Les options spécifiées sur la ligne de commande du module remplacent les valeurs du fichier de configuration.

TYPES DE MODULES FOURNIS

Les types de modules auth et account sont fournis.

VALEURS DE RETOUR

PAM_AUTH_ERR

Une option invalide a été donnée, le module n'a pas pu récupérer le nom d'utilisateur, aucun fichier de compteur valide n'a été trouvé, ou trop de connexions ont échoué.

PAM_BUF_ERR

Erreur de tampon mémoire.

PAM_CONV_ERR

La méthode de conversation fournie par l'application n'a pas réussi à obtenir le nom d'utilisateur.

PAM_INCOMPLETE

La méthode de conversation fournie par l'application a renvoyé PAM_CONV_AGAIN.

PAM_SUCCESS

Tout s'est déroulé avec succès.

PAM_IGNORE

Utilisateur non présent dans la base de données passwd.

NOTES

La configuration des options sur la ligne de commande du module n'est pas recommandée. Le fichier /etc/security/faillock.conf doit être utilisé à la place.

La configuration de pam_faillock dans la pile PAM est différente de la configuration du module pam_tally2.

Les fichiers individuels avec les enregistrements d'échecs sont créés en tant que fichiers appartenant à l'utilisateur. Cela permet au module pam_faillock.so de fonctionner correctement lorsqu'il est appelé depuis un économiseur d'écran.

Notez que l'utilisation du module en preauth sans l'option silent spécifiée dans /etc/security/faillock.conf ou avec le champ de contrôle requisite divulgue des informations sur l'existence ou la non-existence d'un compte utilisateur dans le système, car les échecs ne sont pas enregistrés pour les utilisateurs inconnus. Le message indiquant que le compte utilisateur est bloqué n'est jamais affiché pour les comptes d'utilisateurs inexistants, ce qui permet à un attaquant d'en déduire qu'un compte particulier n'existe pas sur un système.

EXEMPLES

Voici deux exemples de configuration possibles pour /etc/pam.d/login. Ils font en sorte que pam_faillock bloque le compte après 4 échecs de connexion consécutifs pendant l'intervalle par défaut de 15 minutes. Le compte root sera également bloqué. Les comptes seront automatiquement débloqués après 20 minutes.

Dans le premier exemple, le module n'est appelé que dans la phase auth et le module n'imprime aucune information sur le blocage du compte par pam_faillock. L'appel preauth peut être ajouté pour informer les utilisateurs que leurs connexions sont bloquées par le module et pour interrompre l'authentification sans même demander le mot de passe dans ce cas.

Exemple de fichier /etc/security/faillock.conf :

deny=4
unlock_time=1200
silent

Exemple de fichier /etc/pam.d/config :

auth     required       pam_securetty.so
auth     required       pam_env.so
auth     required       pam_nologin.so
# facultativement, appelez : auth requisite pam_faillock.so preauth
# pour afficher le message indiquant que le compte est bloqué
auth     [success=1 default=bad] pam_unix.so
auth     [default=die]  pam_faillock.so authfail
auth     sufficient     pam_faillock.so authsucc
auth     required       pam_deny.so
account  required       pam_unix.so
password required       pam_unix.so shadow
session  required       pam_selinux.so close
session  required       pam_loginuid.so
session  required       pam_unix.so
session  required       pam_selinux.so open

Dans le second exemple, le module est appelé dans les phases auth et account et le module informe l'utilisateur qui s'authentifie lorsque le compte est bloqué si l'option silent n'est pas spécifiée dans faillock.conf.

auth     required       pam_securetty.so
auth     required       pam_env.so
auth     required       pam_nologin.so
auth     required       pam_faillock.so preauth
# utilisez facultativement 'requisite' ci-dessus si vous ne voulez pas demander le mot de passe
# pour les comptes bloqués
auth     sufficient     pam_unix.so
auth     [default=die]  pam_faillock.so authfail
auth     required       pam_deny.so
account  required       pam_faillock.so
# si vous supprimez l'appel ci-dessus à pam_faillock.so, le blocage se fera également
# sur les échecs d'authentification non consécutifs
account  required       pam_unix.so
password required       pam_unix.so shadow
session  required       pam_selinux.so close
session  required       pam_loginuid.so
session  required       pam_unix.so
session  required       pam_selinux.so open

FICHIERS

/var/run/faillock/*

les fichiers enregistrant les échecs d'authentification des utilisateurs

Remarque : Ces fichiers disparaîtront après le redémarrage sur les systèmes configurés avec le répertoire /var/run/faillock monté sur la mémoire virtuelle. Pour un stockage persistant, utilisez l'option dir= dans le fichier /etc/security/faillock.conf.

/etc/security/faillock.conf

le fichier de configuration des options pam_faillock
