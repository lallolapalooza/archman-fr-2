NOM

pam_listfile - refuser ou autoriser des services basés sur un fichier arbitraire

SYNOPIS

pam_listfile.so item=[tty|user|rhost|ruser|group|shell] sense=[allow|deny] file=/chemin/nom_fichier onerr=[succeed|fail] [apply=[user|@group]] [quiet]

DESCRIPTION

pam_listfile est un module PAM qui fournit un moyen de refuser ou d'autoriser des services basés sur un fichier arbitraire.

Le module récupère l'item du type spécifié -- user spécifie le nom d'utilisateur, PAM_USER ; tty spécifie le nom du terminal (s'il y en a un) via lequel la requête a été faite, PAM_TTY ; rhost spécifie le nom de l'hôte distant (s'il y en a un) depuis lequel la requête a été faite, PAM_RHOST ; et ruser spécifie le nom de l'utilisateur distant (si disponible) qui a fait la requête, PAM_RUSER -- et recherche une instance de cet item dans le file=nom_fichier. nom_fichier contient une ligne par item listé. Si l'item est trouvé, alors si sense=allow, PAM_SUCCESS est retourné, provoquant la réussite de la demande d'autorisation ; sinon si sense=deny, PAM_AUTH_ERR est retourné, provoquant l'échec de la demande d'autorisation.

Si une erreur survient (par exemple, si nom_fichier n'existe pas, ou si un argument mal construit est rencontré), alors si onerr=succeed, PAM_SUCCESS est retourné, sinon si onerr=fail, PAM_AUTH_ERR ou PAM_SERVICE_ERR (selon le cas) sera retourné.

Un argument supplémentaire, apply=, peut être utilisé pour restreindre l'application de ce qui précède à un utilisateur spécifique (apply=nom_utilisateur) ou à un groupe donné (apply=@nom_groupe). Cette restriction ajoutée n'est pertinente que lorsqu'elle est utilisée avec les items tty, rhost et shell.

Outre cette dernière, tous les arguments doivent être spécifiés ; ne comptez sur aucun comportement par défaut.

Aucun identifiant n'est attribué par ce module.

OPTIONS

item=[tty|user|rhost|ruser|group|shell]

Ce qui est listé dans le fichier et doit être vérifié.

sense=[allow|deny]

Action à entreprendre si l'item est trouvé dans le fichier. Si l'item N'EST PAS trouvé dans le fichier, alors l'action opposée est demandée.

file=/chemin/nom_fichier

Fichier contenant un item par ligne. Le fichier doit être un fichier normal et ne doit pas être accessible en écriture par tous.

onerr=[succeed|fail]

Que faire si quelque chose d'inhabituel se produit, comme l'impossibilité d'ouvrir le fichier.

apply=[user|@group]

Restreindre la classe d'utilisateurs pour laquelle la restriction s'applique. Notez qu'avec item=[user|ruser|group], cela n'a pas de sens, mais pour item=[tty|rhost|shell], cela a une signification.

quiet

Ne pas considérer les refus de service ou les fichiers de liste manquants comme des erreurs nécessitant une journalisation.

TYPES DE MODULE FOURNIS

Tous les types de module (auth, account, password et session) sont fournis.

VALEURS DE RETOUR

PAM_AUTH_ERR

Échec de l'authentification.

PAM_BUF_ERR

Erreur de tampon mémoire.

PAM_IGNORE

La règle ne s'applique pas à l'option apply.

PAM_SERVICE_ERR

Erreur dans le module de service.

PAM_SUCCESS

Succès.

EXEMPLES

L'authentification classique de type 'ftpusers' peut être implémentée avec cette entrée dans /etc/pam.d/ftpd :

#
# refuser l'accès ftp aux utilisateurs listés dans le fichier /etc/ftpusers
#
auth    required       pam_listfile.so \
        onerr=succeed item=user sense=deny file=/etc/ftpusers

Notez que les utilisateurs listés dans le fichier /etc/ftpusers ne sont pas autorisés (contre-intuitivement) à accéder au service ftp.

Pour autoriser l'accès à la connexion uniquement pour certains utilisateurs, vous pouvez utiliser une entrée /etc/pam.d/login comme celle-ci :

#
# autoriser la connexion aux utilisateurs listés dans /etc/loginusers
#
auth    required       pam_listfile.so \
        onerr=fail item=user sense=allow file=/etc/loginusers

Pour que cet exemple fonctionne, tous les utilisateurs autorisés à utiliser le service de connexion doivent être listés dans le fichier /etc/loginusers. À moins que vous n'essayiez explicitement de bloquer root, assurez-vous que lorsque vous faites cela, vous laissez un moyen de se connecter pour root, soit en listant root dans /etc/loginusers, soit en listant un utilisateur capable de faire un su vers le compte root.
