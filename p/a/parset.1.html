NOM

parset - définir des variables shell en parallèle

SYNTAXE

parset nomvariable [options pour GNU Parallel]

env_parset nomvariable [options pour GNU Parallel]

DESCRIPTION

parset est une fonction shell qui place la sortie de GNU parallel dans des variables shell.

env_parset est une fonction shell qui place la sortie de env_parallel dans des variables shell.

Les fonctions parset et env_parset sont définies dans le cadre de env_parallel.

Si nomvariable est un nom de variable unique, il sera traité comme la variable de destination. Si la variable est définie comme un tableau associatif (en utilisant typeset -A monassoc), celle-ci sera utilisée. Sinon, la variable sera transformée en un tableau normal.

Si nomvariable contient plusieurs noms séparés par ',' ou par un espace, les noms seront les variables de destination. Le nombre de noms doit être au moins égal au nombre de tâches.

OPTIONS

Identiques à GNU parallel, mais elles sont placées *après* la variable de destination.

SHELLS SUPPORTES

Bash/Zsh/Ksh/Mksh

Exemples

Placer la sortie dans montable :

parset montable seq 3 ::: 4 5 6
echo "${montable[1]}"

Placer la sortie dans les variables $seq, $pwd, $ls :

parset "seq pwd ls" ::: "seq 10" pwd ls
echo "$ls"

Placer la sortie dans les variables $seq, $pwd, $ls :

into_vars=(seq pwd ls)
parset "${into_vars[*]}" ::: "seq 10" pwd ls
echo "$ls"

Placer la sortie dans le tableau associatif monassoc (non pris en charge pour mksh) :

typeset -A monassoc
parset monassoc seq ::: 4 5 ::: 6 7
echo "${monassoc[4 7]}"

Les commandes à exécuter peuvent être un tableau :

cmd=("echo first" "echo '<<joe  \"double  space\"  cartoon>>'" "pwd")
parset data ::: "${cmd[@]}"
echo "${data[1]}"
echo "${data[2]}"

parset peut lire depuis stdin (entrée standard) si c'est un fichier :

parset res echo < fichier_entree_parallel

mais parset ne peut *pas* faire partie d'un pipe. En particulier, cela signifie qu'il ne peut ni lire depuis un pipe, ni écrire vers un pipe :

seq 10 | parset res echo Ne fonctionne pas

mais doit plutôt utiliser un fichier temporaire :

seq 10 > entree_parallel
parset res echo :::: entree_parallel
echo "${res[1]}"
echo "${res[9]}"

ou un FIFO :

mkfifo fifo_entree
seq 30 > fifo_entree &
parset res echo :::: fifo_entree
echo "${res[1]}"
echo "${res[29]}"

ou la substitution de processus Bash/Zsh/Ksh :

parset res echo :::: <(seq 100)
echo "${res[1]}"
echo "${res[99]}"

Installation

Placez ceci dans le fichier approprié $HOME/.bashrc ou $HOME/.zshenv ou $HOME/.kshrc :

. env_parallel.bash
. env_parallel.zsh
source `which env_parallel.ksh`

Par exemple, en faisant :

echo '. env_parallel.bash' >> $HOME/.bashrc
echo '. env_parallel.zsh' >> $HOME/.zshenv
echo 'source `which env_parallel.ksh`' >> $HOME/.kshrc

ou en faisant :

env_parallel --install

ash/dash (le /bin/sh de FreeBSD)

Exemples

ash ne prend pas en charge les tableaux.

Placer la sortie dans les variables $seq, $pwd, $ls :

parset "seq pwd ls" ::: "seq 10" pwd ls
echo "$ls"

parset peut lire depuis stdin (entrée standard) si c'est un fichier :

parset res1,res2,res3 echo < fichier_entree_parallel

mais parset ne peut pas faire partie d'un pipe. En particulier, cela signifie qu'il ne peut ni lire depuis un pipe, ni écrire vers un pipe :

seq 3 | parset res1,res2,res3 echo Ne fonctionne pas

mais doit plutôt utiliser un fichier temporaire :

seq 3 > entree_parallel
parset res1,res2,res3 echo :::: entree_parallel
echo "$res1"
echo "$res2"
echo "$res3"

ou un FIFO :

mkfifo fifo_entree
seq 3 > fifo_entree &
parset res1,res2,res3 echo :::: fifo_entree
echo "$res1"
echo "$res2"
echo "$res3"

Installation

Placez l'un des éléments suivants dans $HOME/.profile :

. env_parallel.sh
. env_parallel.ash
. env_parallel.dash

Par exemple, en faisant :

echo '. env_parallel.ash' >> $HOME/.bashrc

ou en faisant :

env_parallel --install
