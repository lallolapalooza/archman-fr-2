NOM

pamtogif - convertir une image Netpbm en image GIF

SYNTAXE

pamtogif

[-interlace]

[-sort]

[-mapfile=fichiercarte] [-transparent=[=]couleur]

[-alphacolor=couleur]

[-comment=texte]

[-nolzw]

[-aspect=fraction]

[-verbose] [fichierNetpbm]

Toutes les options peuvent être abrégées à leur plus court préfixe unique. Vous pouvez utiliser deux traits d'union au lieu d'un pour désigner une option. Vous pouvez utiliser soit un espace blanc, soit un signe égal entre un nom d'option et sa valeur.

DESCRIPTION

Ce programme fait partie de Netpbm(1)

pamtogif lit une image Netpbm en entrée et produit un fichier GIF en sortie.

Ce programme crée uniquement des images GIF individuelles. Pour combiner plusieurs images GIF en un GIF animé, utilisez gifsicle (non inclus dans le paquet Netpbm).

pamtogif crée soit un fichier GIF au format GIF87 original, soit le format plus récent GIF89. Il crée GIF89 lorsque vous demandez des fonctionnalités nouvelles avec GIF89, à savoir les options -transparent ou -comment. Sinon, il crée GIF87. Les anciens lecteurs GIF pourraient éventuellement ne pas reconnaître GIF89.

Le format GIF n'est pas capable de représenter une image avec plus de 256 couleurs (il contient une table de couleurs d'une taille maximale de 256). Si l'image que vous souhaitez convertir a plus de couleurs que cela (ppmhist peut vous le dire), vous pouvez utiliser pnmquant pour la réduire à 256.

Si votre image d'entrée est une PAM avec des informations de transparence, ppmtogif utilise une entrée dans la table de couleurs GIF spécifiquement pour les pixels transparents, vous pouvez donc avoir au maximum 255 couleurs opaques. En revanche, si vous utilisez l'option -transparent, l'une des couleurs de l'entrée devient transparente, la limite est donc toujours de 256.

pamtogif est apparu dans Netpbm 10.37 (décembre 2006). Dans les versions antérieures de Netpbm, utilisez ppmtogif.

OPTIONS

-interlace
Produit un fichier GIF entrelacé.
-sort
Produit un fichier GIF avec une table de couleurs triée dans un ordre prévisible.

Cela ne produit pas la table de couleurs triée qui fait partie du format GIF. Ce type de table de couleurs triée est une où les couleurs sont triées selon leur importance, et l'en-tête GIF indique au visualiseur qu'elle est triée de cette manière. Son objectif est de permettre au visualiseur d'utiliser moins de couleurs que celles présentes dans la table de couleurs s'il n'est pas capable d'afficher toutes les couleurs.

Ce que cette option produit est une table de couleurs triée par valeur rouge, puis verte, puis bleue. Cela peut être utile pour analyser les images GIF, en particulier celles créées avec deux versions du programme, car cela élimine une partie de la variabilité.

-mapfile=fichiercarte

Utilise les couleurs trouvées dans le fichier fichiercarte pour créer la table de couleurs dans le fichier GIF, au lieu des couleurs de fichierNetpbm. fichiercarte peut être n'importe quel fichier PPM ; tout ce qui importe, ce sont les couleurs qu'il contient. Si les couleurs dans fichierNetpbm ne correspondent pas à celles de fichiercarte, pamtogif trouve une 'meilleure correspondance'. Vous pouvez obtenir un bien meilleur résultat en utilisant pnmremap pour changer les couleurs de l'entrée à celles du fichier carte.

Le fichier fichiercarte n'est pas un fichier de palette, juste une image dont vous voulez utiliser les couleurs. L'ordre des couleurs dans la palette GIF n'a rien à voir avec leur apparition dans l'image fichiercarte, et la duplication des couleurs dans l'image est sans importance.

La profondeur du fichier carte doit correspondre au nombre de composantes de couleur de l'entrée (ce qui n'est pas nécessairement la même chose que la profondeur de l'entrée - l'entrée peut avoir un plan alpha en plus). Si votre fichier carte ne le fait pas, ou s'il pouvait ne pas le faire, exécutez votre entrée via pnmremap en utilisant le même fichier carte afin qu'il le fasse.

-transparent=couleur
pamtogif marque la couleur spécifiée comme transparente dans l'image GIF.

Si vous ne spécifiez pas -transparent, pamtogif ne marque aucune couleur comme transparente (sauf indication contraire par les informations de transparence dans le fichier d'entrée).

Spécifiez la couleur (couleur) comme décrit pour l'argument de la routine de la bibliothèque ppm_parsecolor().

Si la couleur que vous spécifiez n'est pas présente dans l'image, pamtogif sélectionne à la place la couleur de l'image la plus proche de celle que vous spécifiez. La proximité est mesurée comme une distance euclidienne entre les couleurs dans l'espace RVB. Si plusieurs couleurs sont équidistantes, pamtogif en choisit une arbitrairement.

Cependant, si vous préfixez votre spécification de couleur avec '=', par exemple -transparent==red, seule la couleur exacte que vous spécifiez sera transparente. Si cette couleur n'apparaît pas dans l'image, il n'y aura pas de transparence. pamtogif émet un message d'information lorsque c'est le cas.

Lorsque vous spécifiez -transparent, pamtogif ignore les informations de transparence explicites (le 'canal alpha') dans l'image d'entrée.

-alphacolor=couleur
Il n'y a pas d'option -alpha. Le prédécesseur de pamtogif avait une telle option car il n'était pas capable d'accepter une entrée PAM contenant un plan de transparence (alpha), donc on utilisait cette option pour fournir un plan de transparence sous forme de fichier PGM séparé.


Cette option nomme un fichier PGM qui contient un masque alpha pour l'image. pamtogif crée des pixels entièrement transparents partout où le masque alpha indique une transparence supérieure à 50%. La couleur de ces pixels est celle spécifiée par l'option -alphacolor, ou noir par défaut.

Pour ce faire, pamtogif crée une entrée dans la table de couleurs GIF en plus des entrées pour les couleurs qui sont effectivement présentes dans l'image. Il marque cette entrée de table de couleurs comme transparente et utilise cet index de table de couleurs dans l'image de sortie pour créer un pixel transparent.


L'image alpha doit avoir les mêmes dimensions que l'image d'entrée, mais peut avoir n'importe quel maxval. Le blanc signifie opaque et le noir signifie transparent.


Vous ne pouvez pas spécifier à la fois -transparent et -alpha.

-alphacolor=couleur
Ceci spécifie la couleur de premier plan pour les pixels transparents. Un visualiseur peut utiliser la couleur de premier plan pour un pixel transparent s'il choisit de ne pas avoir une autre couleur qui 'transparaît'. La valeur par défaut est le noir.

Cela ne s'applique qu'aux pixels qui sont transparents dans le GIF parce qu'ils sont transparents dans l'entrée Netpbm. Si un pixel GIF est transparent en raison de l'option -transparent, la couleur de premier plan est la couleur indiquée par cette option.

Notez que dans GIF, tous les pixels transparents ont la même couleur de premier plan. (Il n'y a qu'une seule entrée dans la table de couleurs GIF pour les pixels transparents).

Spécifiez la couleur (couleur) comme décrit pour l'argument de la routine de la bibliothèque ppm_parsecolor().

-comment=texte
Inclut un commentaire dans la sortie GIF avec le texte du commentaire texte.

Sans cette option, il n'y a pas de commentaires dans la sortie.

Notez que dans un shell de commande, vous devrez utiliser des guillemets autour de texte s'il contient des caractères (par exemple, un espace) qui feraient croire au shell qu'il s'agit de plusieurs arguments :

$ pamtogif -comment "c'est un commentaire" <xxx.ppm >xxx.gif
-nolzw

Cette option est principalement d'intérêt historique - elle implique l'utilisation d'un brevet maintenant expiré.

Cette option garantit que la sortie GIF, et donc pamtogif, n'utilise pas la compression LZW (Lempel-Ziv). En conséquence, le fichier image est plus volumineux et, avant l'expiration du brevet, rendait son utilisation illégale dans certains pays.

-aspect=fraction
Définit le rapport d'aspect de l'image. La valeur est une fraction, telle que 100/91.

Le rapport d'aspect est le rapport de la largeur d'un pixel à sa hauteur. Une valeur de 1 indique que les pixels sont carrés. La plupart des images ont un rapport d'aspect de 1.

La spécification du rapport d'aspect dans un fichier GIF est une fonctionnalité expérimentale.

-verbose
Produit des informations supplémentaires sur l'opération, y compris le nom du fichier d'entrée et les nombres de couleurs.

EXEMPLES

Convertir une image ppm en gif, avec une couleur rouge comme transparente :

pamtogif -transparent red input.ppm > output.gif

Convertir une image pam avec transparence alpha en gif, en utilisant la couleur bleue comme couleur de premier plan des pixels transparents :

pamtogif -alphacolor blue input.pam > output.gif

VOIR AUSSI

pam(5), pnmquant(1), pnmremap(1), ppmhist(1), gifsicle(1)

pamtogif(1)

OPTIONS

-nolzw
Par défaut, pamtogif utilise la compression LZW. Le brevet sur le LZW a expiré (en 2003 aux États-Unis et en 2004 ailleurs), donc il n'y a plus de redevances à payer au détenteur du brevet sur LZW. Voir la section LICENSE ci-dessous.

LZW est une méthode permettant de combiner les informations de plusieurs pixels en un seul code GIF. Avec l'option -nolzw, pamtogif crée un code GIF par pixel, il n'effectue donc aucune compression et n'utilise pas LZW. Cependant, tout décodeur GIF, qu'il utilise ou non un décompresseur LZW, décodera correctement ce format non compressé. Un décompresseur LZW verrait cela comme un cas particulier de compression LZW.

Notez que si quelqu'un utilise un décompresseur LZW tel que celui de giftopnm ou pratiquement n'importe quel programme d'affichage graphique pour traiter la sortie de pamtogif -nolzw, il utilise alors le brevet LZW. Mais le détenteur du brevet a montré beaucoup moins d'intérêt pour l'application du brevet sur le décodage que sur l'encodage.

-aspect=fraction
Ceci est le rapport d'aspect des pixels de l'image. Son seul effet est d'enregistrer cette information dans le GIF pour être utilisée par tout ce qui interprète le GIF. Notez que cette fonctionnalité de GIF est rarement utilisée et la plupart des décodeurs GIF ignorent cette information et supposent que les pixels sont carrés.

Les pixels dans une image Netpbm n'ont pas de rapport d'aspect ; il y a toujours une correspondance un-à-un entre les pixels GIF et les pixels Netpbm.

Le rapport d'aspect est le quotient de la largeur divisée par la hauteur. GIF autorise des rapports d'aspect de 0.25 (1:4) à 4 (4:1) par incréments de 1/64. pamtogif implémente une extension naturelle de GIF qui autorise un rapport d'aspect allant jusqu'à 4 14/64. Si vous spécifiez quelque chose en dehors de cette plage, pamtogif échoue. pamtogif arrondit fraction au 1/64 le plus proche.

La valeur par défaut est carrée (1.0).

Cette option a été ajoutée dans Netpbm 10.38 (mars 2007). Avant cela, les pixels étaient toujours carrés.

-verbose
Cette option fait en sorte que pamtogif affiche des informations sur le processus de conversion et l'image qu'il produit.

HISTORIQUE

pamtogif a été introduit dans Netpbm 10.37 (décembre 2006). Il a remplacé ppmtogif, qui créait des images GIF pour les utilisateurs de Pbmplus/Netpbm depuis 1989.

Le principal changement visible lors de la conversion de ppmtogif à pamtogif a été que pamtogif a pu utiliser les informations de transparence ('canal alpha') dans les entrées PAM, alors qu'avec ppmtogif, il fallait fournir le masque de transparence dans une image pseudo-PGM séparée (via l'option -alpha).

Jef Poskanzer a écrit ppmtogif en 1989, et il a toujours été un pilier de Pbmplus/Netpbm car GIF est un format d'image très populaire. Jef a basé l'encodage LZW sur GIFENCOD de David Rowley <mgardi@watdcsu.waterloo.edu>. Jef a inclus le fichier GIFCOMPR.C de GIFENCOD pratiquement tel quel. Rowley, à son tour, a adapté le code de compression LZW de compress de Unix classique, qui utilisait des techniques décrites dans IEEE Computer, juin 1984.

Le ppmtogif de Jef manquait notamment de la capacité à utiliser un masque de transparence avec lui. Vous pouviez créer des pixels transparents dans un GIF, mais seulement avec l'option -transparent, qui permettait de spécifier que tous les pixels d'une certaine couleur dans l'entrée devaient être transparents. Bryan Henderson a ajouté l'option -alpha en juillet 2001 afin que vous puissiez fournir une image de masque indiquant exactement quels pixels devaient être transparents, et ces pixels pouvaient avoir la même couleur que d'autres pixels opaques.

Bryan Henderson a ajouté une autre pièce de code et une fonctionnalité significative en octobre 2001 : la capacité de générer un GIF sans utiliser le brevet LZW - un GIF non compressé. C'était très important pour beaucoup de gens à l'époque car le brevet GIF était toujours en vigueur, et cela leur permettait de créer une image que n'importe quel visualiseur GIF pouvait afficher, sans redevance. Bryan a adapté du code de djpeg de l'Independent JPEG Group pour cela.

Il n'y a pas de code dans pamtogif de l'original de Jef, mais Jef peut encore détenir les droits d'auteur dessus en raison de la façon dont il a évolué. Pratiquement tout le code de pamtogif a été écrit par Bryan Henderson et contribué au domaine public.

LICENCE

Si vous utilisez pamtogif sans l'option -nolzw, vous utilisez un brevet sur la méthode de compression LZW qui appartient à Unisys. Le brevet a expiré (en 2003 aux États-Unis et en 2004 ailleurs), donc cela n'a plus d'importance. Tant que le brevet était en vigueur, la plupart des personnes qui utilisaient pamtogif et des programmes similaires le faisaient sans licence d'Unisys pour ce faire. Unisys demandait généralement 5000 $ pour une licence pour une utilisation triviale du brevet. Unisys n'a jamais appliqué le brevet contre les utilisateurs triviaux.

La rumeur veut qu'IBM possède ou possédait également un brevet couvrant pamtogif.

Un remplacement pour le format GIF qui n'a jamais nécessité de brevet pour être utilisé est le format PNG.
