PARTCLONE(8) Manuel utilisateur Partclone PARTCLONE(8)

NOM

partclone - L'utilitaire pour cloner et restaurer une partition.

SYNTAXE

partclone.[type_fs] {[-c | --clone] [-r | --restore] [-b | --dev-to-dev]} {[-s | --source] source} {[[-o | --output] [-O | --overwrite]] cible} [[-dX | --debug=X] [--restore_raw_file] [-z | --buffer_size] [-N | --ncurses] [-q | --quiet] [-f | --UI-fresh] [-F | --force] [-I | --ignore_fschk] [-i | --ignore_crc] [-C | --nocheck] [-R | --rescue] [-L | --logfile] fichier_journal [-R | --rescue] [-L | --logfile] fichier_journal [-X | --compresscmd] [-D | --domain] [--offset_domain] [-aX | --checksum-mode=X] [-kX | --blocks-per-checksum=X] [-K | --no-reseed] [-w | --skip_write_error] [-E | --offset=X] [-T | --btfiles] [-t | --btfiles_torrent] [-n | --note] [-B | --no_block_detail] [--binary-prefix] [--prog-second] [--write-direct-io] [--read-direct-io]]

DESCRIPTION

partclone.[type_fs] fait partie du projet Partclone. Partclone fournit des utilitaires pour sauvegarder les blocs utilisés et est conçu pour une meilleure compatibilité du système de fichiers en utilisant des bibliothèques existantes, par exemple e2fslibs est utilisé pour lire les blocs utilisés d'une partition ext2.

Les systèmes de fichiers pris en charge par Partclone incluent btrfs, ext2, ext3, ext4, reiserfs, reiser4, xfs et jfs pour LINUX. Il prend également en charge certains systèmes d'exploitation non-Linux, par exemple NTFS, FAT et EXFAT (pour Windows), HFS plus (MAC OS APPLE), UFS2 (FreeBSD), VMFS (VMWare Vsphere) et MINIX (MINIX3).

Tous les utilitaires partclone peuvent être exécutés comme partclone.[type_fs], ce qui est très similaire à fsck ou mkfs. Par exemple, pour sauvegarder/restaurer hfsplus, il suffit d'exécuter partclone.hfsp

       Système de fichiers                 partclone.[type_fs]
       btrfs                       partclone.btrfs
       ext2, ext3, ext4            partclone.[ext2 | ext3 | ext4]
       reiserfs 3.5                partclone.reiserfs
       reiser 4                    partclone.reiser4
       xfs                         partclone.xfs
       ufs | ufs2                  partclone.ufs
       jfs                         partclone.jfs
       hfs plusfs                  partclone.[hfs+ | hfsplus]
       vmfs                        partclone.[vmfs | vmfs5]
       ntfs                        partclone.ntfs
       fat12, fat16, fat32         partclone.[fat12 | fat16 | fat32]
       exfat                       partclone.exfat
       minix                       partclone.minix
       f2fs                        partclone.f2fs
       nilfs2                      partclone.nilfs2
       apfs                        partclone.apfs
       autres (FS non supportés)   partclone.imager

OPTIONS

Le programme suit la syntaxe habituelle des lignes de commande GNU, avec les options longues commençant par deux tirets (`-'). Un résumé des options est inclus ci-dessous.

-s FICHIER, --source FICHIER

FICHIER source. Le FICHIER peut être un fichier image (créé par partclone) ou un périphérique, selon votre action. Normalement, la source de sauvegarde est un périphérique, la source de restauration est un fichier image.

La réception de données depuis un pipeline n'est prise en charge QUE pour la restauration, ignorez simplement l'option -s ou utilisez '-' pour recevoir des données depuis stdin.

-o FICHIER, --output FICHIER

FICHIER de sortie. Le FICHIER peut être un fichier image (partclone générera) ou un périphérique, selon votre action. Normalement, la sortie de sauvegarde vers un fichier image et la sortie de restauration vers un périphérique.

L'envoi de données vers un pipeline est également pris en charge UNIQUEMENT pour la sauvegarde, ignorez simplement l'option -o ou utilisez '-' pour envoyer des données vers stdout.

-O FICHIER, --overwrite FICHIER

Écrase FICHIER, en écrasant s'il existe.

-W FICHIER, --restore_raw_file FICHIER

Crée un fichier brut spécial pour le périphérique de boucle.

-c, --clone

Sauvegarde la partition dans le format d'image spécial.

-r, --restore

Restaure la partition à partir du format d'image spécial.

-b, --dev-to-dev

Copie locale de périphérique à périphérique à la volée, la source et la sortie sont toutes deux des périphériques.

-D, --domain

Crée un fichier journal de domaine GNU Ddrescue à partir du périphérique source. C'est un fichier lisible par l'homme dans lequel + marque les zones de blocs utilisées et ? marque les zones libres.

--offset_domain=X

Ajoute X (en octets) à toutes les positions signalées dans le fichier journal de domaine.

--restore_raw_file

Création d'un fichier brut spécial pour le périphérique de boucle.

-L FICHIER, --logfile FICHIER

Indique un chemin spécial pour enregistrer les informations du journal partclone. (par défaut /var/log/partclone.log)

-R, --rescue

Continue après les erreurs de lecture disque.

-C, --no_check

Ne vérifie pas la taille du périphérique et l'espace libre.

-N, --ncurses

Utilise l'interface utilisateur textuelle Ncurses.

-I, --ignore_fschk

Ignore la vérification du système de fichiers.

-i, --ignore_crc

Ignore l'erreur de vérification crc.

-F, --force

Force la progression.

-f sec, --UI-fresh sec

Définit un intervalle en secondes pour l'actualisation de l'interface utilisateur.

-z taille, --buffer_size taille

Taille du tampon de lecture/écriture (par défaut : 1048576)

-q, --quiet

Désactive le message de progression.

-dniveau, --debug niveau

Définit le niveau de débogage [1|2|3].

-x, --compresscmd CMD

Lance CMD comme un pipeline de sortie pour compresser l'image clonée.

-aX, --checksum-mode=X

Formule de somme de contrôle à utiliser pour ajouter la détection d'erreurs.

où X :

0 : Aucune somme de contrôle (pas de ralentissement, image la plus petite)

1 : CRC32 (Calcul rapide, détection basique)

2 : xxHash, algorithme de hachage non cryptographique extrêmement rapide.

-kX, --blocks-per-checksum=X

Écrit une somme de contrôle tous les X blocs.

-w, --skip_write_error

Continue la restauration en cas d'erreurs d'écriture.

--write-direct-io

Écrit les données dans la partition CIBLE sans cache.

--read-direct-io

Lit les données de la partition SOURCE sans cache.

-B, --no_block_detail

Affiche le message de progression sans détails sur les blocs.

--binary-prefix

Affiche la progression avec la taille en bits (par défaut, c'est en Mo, Go...).

--prog-second

Affiche la progression en secondes (par défaut, c'est en minutes).

-E, --offset=X

Ajoute un décalage X (en octets) à la sortie.

-T, --btfiles

Restaure le bloc sous forme de fichier pour ClonezillaBT.

-t, --btfiles_torrent

Restaure le bloc sous forme de fichier pour ClonezillaBT, mais génère uniquement le torrent.

-n, --note NOTE

Affiche une note de message (128 mots maximum).

-h, --help

Affiche le résumé des options.

-v, --version

Affiche la vé

partclone.ext4dev(8) — man pages

NOM

partclone.ext4dev - Sauvegarde ou restauration de systèmes de fichiers ext4dev.

SYNOPSIS

partclone.ext4dev -c | -r [-s source] [-o destination] [-b block_size] [-N number_of_threads] [-q] [-d]

DESCRIPTION

partclone.ext4dev est un programme qui est utilisé pour cloner ou restaurer des systèmes de fichiers ext4dev. Il permet de copier les données des blocs utilisés d'un système de fichiers et de les enregistrer dans un fichier image. Lors de la restauration, il ne copie que les blocs utilisés à partir du fichier image.

Pour utiliser ce programme, vous devez spécifier soit l'option -c pour cloner ou l'option -r pour restaurer.

-c: Cloner (sauvegarder) le système de fichiers.

-r: Restaurer le système de fichiers.

-s source: Spécifie la source du clonage ou de la restauration. Il peut s'agir d'un périphérique (par exemple, /dev/sda1) ou d'un fichier image.

-o destination: Spécifie la destination du clonage ou de la restauration. Il peut s'agir d'un périphérique ou d'un fichier image.

-b block_size: Spécifie la taille des blocs à utiliser pour le clonage/la restauration. La valeur par défaut est 1024.

-N number_of_threads: Spécifie le nombre de threads à utiliser pour le clonage/la restauration. La valeur par défaut est 1.

-q: Mode silencieux, supprime la plupart des messages.

-d: Activer le débogage.

OPTIONS

Les options courantes de partclone sont les suivantes :

-c
Cloner le système de fichiers.
-r
Restaurer le système de fichiers.
-s source
Spécifie la source (périphérique ou fichier image).
-o destination
Spécifie la destination (périphérique ou fichier image).
-b block_size
Taille des blocs (par défaut : 1024).
-N number_of_threads
Nombre de threads (par défaut : 1).
-q
Mode silencieux.
-d
Activer le débogage.
-h
Afficher l'aide et quitter.
-v
Afficher les informations de version et quitter.

FICHIERS

/var/log/partclone.log

Le fichier journal de partclone

EXEMPLES

 Cloner /dev/hda1 vers hda1.img et afficher les informations de débogage.
   partclone.ext4dev -c -d -s /dev/hda1 -o hda1.img
 Restaurer /dev/hda1 à partir de hda1.img et afficher les informations de débogage.
   partclone.ext4dev -r -d -s hda1.img -o /dev/hda1
 Restaurer une image de clonezilla (divisée, gzipée, etc.) avec une source stdin
   cat sda1.ext4dev-ptcl-img.gz.a* | gunzip -c | partclone.ext4dev -d -r -s - -o /dev/sda1

DIAGNOSTICS

Les diagnostics suivants peuvent être émis sur stderr :

partclone fournit des codes de retour qui peuvent être utilisés dans les scripts :

Code Diagnostic
0 Le programme s'est terminé avec succès.
1 Le clonage ou la restauration semblent avoir échoué.

BOGUES

Signaler les bogues à thomas@clonezilla.org ou http://partclone.org.

Vous pouvez obtenir de l'aide sur http://partclone.org
