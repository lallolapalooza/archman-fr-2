NOM

pam_pwquality - Module PAM pour effectuer des vérifications de qualité des mots de passe

SYNTAXE

pam_pwquality.so [...]

DESCRIPTION

Ce module peut être intégré dans la pile password d'un service donné pour fournir une vérification de la robustesse des mots de passe. Le code était initialement basé sur le module pam_cracklib et le module est rétrocompatible avec ses options.

L'action de ce module est de demander à l'utilisateur un mot de passe et de vérifier sa robustesse par rapport à un dictionnaire système et à un ensemble de règles pour identifier les mauvais choix.

La première action consiste à demander un premier mot de passe, à en vérifier la robustesse, puis, s'il est considéré comme robuste, à demander le mot de passe une seconde fois (pour vérifier qu'il a été correctement tapé la première fois). Si tout va bien, le mot de passe est transmis aux modules suivants pour être installé en tant que nouveau jeton d'authentification.

Les vérifications de robustesse sont les suivantes :

Palindrome
Le nouveau mot de passe est-il un palindrome ?
Changement de casse uniquement
Le nouveau mot de passe est-il identique à l'ancien avec seulement un changement de casse ?
Similaire
Le nouveau mot de passe ressemble-t-il trop à l'ancien ? Ceci est principalement contrôlé par un argument, difok, qui est le nombre de changements de caractères (insertions, suppressions ou remplacements) entre l'ancien et le nouveau mot de passe qui suffisent à accepter le nouveau mot de passe.
Simple
Le nouveau mot de passe est-il trop court ? Ceci est contrôlé par 6 arguments : minlen, maxclassrepeat, dcredit, ucredit, lcredit et ocredit. Voir la section sur les arguments pour les détails sur leur fonctionnement et leurs valeurs par défaut.
Rotation
Le nouveau mot de passe est-il une version permutée de l'ancien mot de passe ?
Mêmes caractères consécutifs
Vérification optionnelle des mêmes caractères consécutifs.
Séquence de caractères monotones trop longue
Vérification optionnelle d'une séquence de caractères monotones trop longue.
Contient le nom de l'utilisateur
Vérifie si le mot de passe contient le nom de l'utilisateur sous une forme quelconque.
Vérification par dictionnaire
La routine Cracklib est appelée pour vérifier si le mot de passe fait partie d'un dictionnaire.

Ces vérifications sont configurables soit par l'utilisation des arguments du module, soit par la modification du fichier de configuration /etc/security/pwquality.conf. Les arguments du module remplacent les paramètres du fichier de configuration.

OPTIONS

debug
Cette option fait en sorte que le module écrive des informations dans syslog(3) indiquant le comportement du module (cette option n'écrit pas d'informations de mot de passe dans le fichier journal).
authtok_type=XXX
L'action par défaut est que le module utilise les invites suivantes lors de la demande de mots de passe : "Nouveau mot de passe UNIX : " et "Retype mot de passe UNIX : ". Le mot exemple UNIX peut être remplacé par cette option, par défaut il est vide.
retry=N
Demander à l'utilisateur au plus N fois avant de retourner une erreur. La valeur par défaut est 1.
difok=N
Cet argument modifie la valeur par défaut de 1 pour le nombre de changements dans le nouveau mot de passe par rapport à l'ancien.

La valeur spéciale de 0 désactive toutes les vérifications de similitude entre le nouveau mot de passe et l'ancien, sauf si le nouveau mot de passe est exactement le même que l'ancien.

minlen=N
La taille minimale acceptable pour le nouveau mot de passe (plus un si les crédits ne sont pas désactivés, ce qui est le cas par défaut). En plus du nombre de caractères dans le nouveau mot de passe, un crédit (de +1 en longueur) est accordé pour chaque type de caractère différent (autre, majuscule, minuscule et chiffre). La valeur par défaut pour ce paramètre est 8. Notez qu'il existe également une paire de limites de longueur dans Cracklib, utilisée pour la vérification par dictionnaire, une limite "beaucoup trop court" de 4 qui est codée en dur et une limite définie à la compilation (6) qui sera vérifiée sans référence à minlen.
dcredit=N
(N >= 0) C'est le crédit maximum pour avoir des chiffres dans le nouveau mot de passe. Si vous avez moins de N chiffres, chaque chiffre comptera +1 pour atteindre la valeur actuelle de minlen. La valeur par défaut pour dcredit est 0, ce qui signifie qu'il n'y a pas de bonus pour les chiffres dans le mot de passe.

(N < 0) C'est le nombre minimum de chiffres qui doivent être présents pour un nouveau mot de passe.

ucredit=N
(N >= 0) C'est le crédit maximum pour avoir des lettres majuscules dans le nouveau mot de passe. Si vous avez moins de N lettres majuscules, chaque lettre majuscule comptera +1 pour atteindre la valeur actuelle de minlen. La valeur par défaut pour ucredit est 0, ce qui signifie qu'il n'y a pas de bonus pour les lettres majuscules dans le mot de passe.

(N < 0) C'est le nombre minimum de lettres majuscules qui doivent être présents pour un nouveau mot de passe.

lcredit=N
(N >= 0) C'est le crédit maximum pour avoir des lettres minuscules dans le nouveau mot de passe. Si vous avez moins de N lettres minuscules, chaque lettre minuscule comptera +1 pour atteindre la valeur actuelle de minlen. La valeur par défaut pour lcredit est 0, ce qui signifie qu'il n'y a pas de bonus pour les lettres minuscules dans le mot de passe.

(N < 0) C'est le nombre minimum de lettres minuscules qui doivent être présents pour un nouveau mot de passe.

ocredit=N
(N >= 0) C'est le crédit maximum pour avoir des caractères autres dans le nouveau mot de passe. Si vous avez moins de N autres caractères, chaque autre caractère comptera +1 pour atteindre la valeur actuelle de minlen. La valeur par défaut pour ocredit est 0, ce qui signifie qu'il n'y a pas de bonus pour les autres caractères dans le mot de passe.

(N < 0) C'est le nombre minimum d'autres caractères qui doivent être présents pour un nouveau mot de passe.

minclass=N
Le nombre minimum de classes de caractères requises pour le nouveau mot de passe. Les quatre classes sont les chiffres, les lettres majuscules et minuscules, et les autres caractères. La différence avec la vérification credit est qu'une classe spécifique de caractères n'est pas requise. Au lieu de cela, N classes sur les 4 sont requises. Par défaut, cette vérification est désactivée.
maxrepeat=N
Rejeter les mots de passe qui contiennent plus de N caractères identiques consécutifs. La valeur par défaut est 0, ce qui signifie que cette vérification est désactivée.
maxsequence=N
Rejeter les mots de passe qui contiennent des séquences de caractères monotones plus longues que N. La valeur par défaut est 0, ce qui signifie que cette vérification est désactivée. Des exemples de telles séquences sont '12345' ou 'fedcb'. Notez que la plupart de ces mots de passe ne passeront pas la vérification de simplicité à moins que la séquence ne soit qu'une petite partie du mot de passe.
maxclassrepeat=N
Rejeter les mots de passe qui contiennent plus de N caractères consécutifs de la même classe. La valeur par défaut est 0, ce qui signifie que cette vérification est désactivée.
gecoscheck=N
Si non nul, vérifie si les mots individuels de plus de 3 caractères du champ GECOS de passwd(5) de l'utilisateur sont contenus dans le nouveau mot de passe. La valeur par défaut est 0, ce qui signifie que cette vérification est désactivée.

pam_pwquality(8)

NOM

pam_pwquality - vérification de la qualité des mots de passe

SYNTAXIS

pam_pwquality.

DESCRIPTION

Le module pam_pwquality est utilisé pour vérifier si les nouveaux mots de passe respectent certaines règles de qualité.

OPTIONS

dictcheck=N
Si différent de zéro, vérifie si le mot de passe (avec d'éventuelles modifications) correspond à un mot d'un dictionnaire. Actuellement, la vérification du dictionnaire est effectuée à l'aide de la bibliothèque cracklib. La valeur par défaut est 1, ce qui signifie que cette vérification est activée.
usercheck=N
Si différent de zéro, vérifie si le mot de passe (avec d'éventuelles modifications) contient le nom d'utilisateur sous une forme ou une autre. La valeur par défaut est 1, ce qui signifie que cette vérification est activée. Elle n'est pas effectuée pour les noms d'utilisateur de moins de 3 caractères.
usersubstr=N
Si supérieur à 3 (en raison de la longueur minimale dans usercheck), vérifie si le mot de passe contient une sous-chaîne du nom d'utilisateur d'au moins N caractères sous une forme ou une autre. La valeur par défaut est 0, ce qui signifie que cette vérification est désactivée.
enforcing=N
Si différent de zéro, rejette le mot de passe s'il échoue aux vérifications, sinon affiche uniquement un avertissement. La valeur par défaut est 1, ce qui signifie que le mot de passe faible est rejeté (pour les utilisateurs non root).
badwords=<liste de mots>
Les mots de plus de 3 caractères de cette liste séparée par des espaces sont individuellement recherchés et interdits dans le nouveau mot de passe. Par défaut, la liste est vide, ce qui signifie que cette vérification est désactivée.
dictpath=/chemin/vers/dict
Cette option permet de spécifier un chemin non par défaut vers les dictionnaires cracklib.
enforce_for_root
Le module renverra une erreur en cas d'échec de la vérification, même si l'utilisateur qui modifie le mot de passe est root. Cette option est désactivée par défaut, ce qui signifie que seul le message concernant l'échec de la vérification est affiché, mais root peut changer le mot de passe de toute façon. Notez que root n'est pas invité à saisir son ancien mot de passe, donc les vérifications qui comparent l'ancien et le nouveau mot de passe ne sont pas effectuées.
local_users_only
Le module ne testera pas la qualité du mot de passe pour les utilisateurs qui ne sont pas présents dans le fichier /etc/passwd. Le module demande toujours le mot de passe, de sorte que les modules suivants dans la pile puissent utiliser l'option use_authtok. Cette option est désactivée par défaut.
use_authtok
Cet argument est utilisé pour forcer le module à ne pas demander à l'utilisateur un nouveau mot de passe, mais à utiliser celui fourni par le module password précédemment empilé.

TYPES DE MODULES FOURNIS

Seul le type de module password est fourni.

VALEURS DE RETOUR

PAM_SUCCESS
Le nouveau mot de passe passe toutes les vérifications.
PAM_AUTHTOK_ERR
Aucun nouveau mot de passe n'a été saisi, le nom d'utilisateur n'a pas pu être déterminé ou le nouveau mot de passe échoue aux vérifications de robustesse.
PAM_AUTHTOK_RECOVERY_ERR
L'ancien mot de passe n'a pas été fourni par un module empilé précédent ou n'a pas été demandé à l'utilisateur. La première erreur peut se produire si use_authtok est spécifié.
PAM_SERVICE_ERR
Une erreur interne s'est produite.

EXEMPLES

Pour un exemple d'utilisation de ce module, nous montrons comment il peut être empilé avec le composant mot de passe de pam_unix(8).

#
# Ces lignes empilent deux modules de type mot de passe. Dans cet exemple,
# l'utilisateur a 3 tentatives pour saisir un mot de passe fort.
# L'argument "use_authtok" garantit que le module pam_unix ne demande pas
# de mot de passe, mais utilise celui fourni par pam_pwquality.
#
password required pam_pwquality.so retry=3
password required pam_unix.so use_authtok

Un autre exemple est le cas où vous souhaitez utiliser le chiffrement de mots de passe sha256 :

#
# Ces lignes permettent aux systèmes modernes de supporter des mots de
# passe d'au moins 14 octets avec un crédit supplémentaire de 2 pour les
# chiffres et 2 pour les autres. Le nouveau mot de passe doit avoir au moins
# trois octets qui ne sont pas présents dans l'ancien mot de passe.
#
password required pam_pwquality.so \
              difok=3 minlen=15 dcredit=2 ocredit=2
password required pam_unix.so use_authtok nullok sha256

Et voici un autre exemple si vous ne souhaitez pas utiliser de crédits :

#
# Ces lignes exigent que l'utilisateur choisisse un mot de passe avec une
# longueur minimale de 8 et avec au moins 1 chiffre, 1 lettre majuscule
# et 1 autre caractère.
#
password required pam_pwquality.so \
              dcredit=-1 ucredit=-1 ocredit=-1 lcredit=0 minlen=8
password required pam_unix.so use_authtok nullok sha256
