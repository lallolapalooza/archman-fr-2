PAM_SYSTEMD_LOADKEY(8) pam_systemd_loadkey PAM_SYSTEMD_LOADKEY(8)

NOM

pam_systemd_loadkey - Lire le mot de passe depuis le keyring du noyau et le définir comme authtok PAM

SYNTAXE

pam_systemd_loadkey.so

DESCRIPTION

pam_systemd_loadkey lit une liste de mots de passe séparés par NUL depuis le keyring du noyau, et définit le dernier mot de passe de la liste comme authtok PAM, qui peut être utilisé par, par exemple, pam_get_authtok(3).

La liste de mots de passe est censée être stockée dans le keyring "user" de l'utilisateur root, par un appel antérieur à systemd-ask-password(1) avec --keyname=. Vous pouvez passer le nom de la clé à pam_systemd_loadkey via l'option keyname=.

OPTIONS

Les options suivantes sont comprises :

keyname=

Prend un argument de chaîne qui définit le nom de la clé à lire. La valeur par défaut est "cryptsetup". Pendant le démarrage, systemd-cryptsetup@.service(8) stocke un mot de passe ou un code PIN dans le keyring. La clé de volume LUKS2 peut également être utilisée, via l'option link-volume-key dans crypttab(5).

Tableau 1.  Valeurs possibles pour keyname.

Valeur Description
cryptsetup Mot de passe ou clé de récupération
fido2-pin Code PIN du jeton de sécurité
luks2-pin Code PIN du jeton LUKS2
tpm2-pin Code PIN TPM2

Ajouté dans la version 255.

debug

Le module enregistrera des informations de débogage lors de son fonctionnement.

Ajouté dans la version 255.

EXEMPLE

Ce module est destiné à être utilisé lorsque vous utilisez LUKS avec un mot de passe, que vous activez l'autologin dans le gestionnaire d'affichage, et que vous souhaitez déverrouiller Gnome Keyring / KDE KWallet automatiquement. Ainsi, au total, vous ne saisissez qu'un seul mot de passe pendant le démarrage.

Vous devez définir le mot de passe de votre Gnome Keyring/KWallet au même que votre mot de passe LUKS. Ensuite, ajoutez les lignes suivantes à la configuration PAM de votre gestionnaire d'affichage sous /etc/pam.d/ (par exemple, sddm-autologin) :

-auth       optional    pam_systemd_loadkey.so
-auth       optional    pam_gnome_keyring.so
-session    optional    pam_gnome_keyring.so auto_start
-session    optional    pam_kwallet5.so auto_start

Et ajoutez les lignes suivantes au fichier de service systemd de votre gestionnaire d'affichage, afin qu'il puisse accéder au keyring de root :

[Service]
KeyringMode=inherit

Dans cette configuration, très tôt pendant le processus de démarrage, systemd-cryptsetup@.service(8) demandera le mot de passe et le stockera dans le keyring du noyau avec le nom de clé "cryptsetup". Ensuite, lorsque le gestionnaire d'affichage effectuera l'autologin, pam_systemd_loadkey lira le mot de passe depuis le keyring du noyau, le définira comme authtok PAM, et ensuite pam_gnome_keyring et pam_kwallet5 se déverrouilleront avec le même mot de passe.
