fpathconf(3) Manuel des fonctions de bibliothèque fpathconf(3)

NOM

fpathconf, pathconf - obtenir les valeurs de configuration pour les fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
long fpathconf(int fd, int name);
long pathconf(const char *path, int name);

DESCRIPTION

fpathconf() obtient une valeur pour l'option de configuration name pour le descripteur de fichier ouvert fd.

pathconf() obtient une valeur pour l'option de configuration name pour le nom de fichier path.

Les macros correspondantes définies dans <unistd.h> sont des valeurs minimales ; si une application souhaite tirer parti de valeurs susceptibles de changer, un appel à fpathconf() ou pathconf() peut être effectué, ce qui peut donner des résultats plus libéraux.

En attribuant à name l'une des constantes suivantes, on obtient les options de configuration suivantes :

_PC_LINK_MAX
Le nombre maximum de liens vers le fichier. Si fd ou path fait référence à un répertoire, la valeur s'applique à l'ensemble du répertoire. La macro correspondante est _POSIX_LINK_MAX.
_PC_MAX_CANON
La longueur maximale d'une ligne d'entrée formatée, où fd ou path doit faire référence à un terminal. La macro correspondante est _POSIX_MAX_CANON.
_PC_MAX_INPUT
La longueur maximale d'une ligne d'entrée, où fd ou path doit faire référence à un terminal. La macro correspondante est _POSIX_MAX_INPUT.
_PC_NAME_MAX
La longueur maximale d'un nom de fichier dans le répertoire path ou fd que le processus est autorisé à créer. La macro correspondante est _POSIX_NAME_MAX.
_PC_PATH_MAX
La longueur maximale d'un chemin relatif lorsque path ou fd est le répertoire de travail courant. La macro correspondante est _POSIX_PATH_MAX.
_PC_PIPE_BUF
Le nombre maximum d'octets qui peuvent être écrits de manière atomique dans un tube ou un FIFO. Pour fpathconf(), fd doit faire référence à un tube ou un FIFO. Pour pathconf(), path doit faire référence à un FIFO ou à un répertoire ; dans ce dernier cas, la valeur retournée correspond aux FIFOs créés dans ce répertoire. La macro correspondante est _POSIX_PIPE_BUF.
_PC_CHOWN_RESTRICTED
Ceci retourne une valeur positive si l'utilisation de chown(2) et fchown(2) pour changer l'ID utilisateur d'un fichier est restreinte à un processus disposant des privilèges appropriés, et si le changement de l'ID de groupe d'un fichier vers une valeur autre que l'ID de groupe effectif du processus ou l'un de ses ID de groupe supplémentaires est restreint à un processus disposant des privilèges appropriés. Selon POSIX.1, cette variable doit toujours être définie avec une valeur autre que -1. La macro correspondante est _POSIX_CHOWN_RESTRICTED.
Si fd ou path fait référence à un répertoire, la valeur de retour s'applique à tous les fichiers de ce répertoire.
_PC_NO_TRUNC
Ceci retourne une valeur non nulle si l'accès à des noms de fichiers plus longs que _POSIX_NAME_MAX génère une erreur. La macro correspondante est _POSIX_NO_TRUNC.
_PC_VDISABLE
Ceci retourne une valeur non nulle si le traitement des caractères spéciaux peut être désactivé, où fd ou path doit faire référence à un terminal.

VALEUR DE RETOUR

La valeur de retour de ces fonctions est l'une des suivantes :

•
En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur (par exemple, EINVAL, indiquant que name est invalide).
•
Si name correspond à une limite maximale ou minimale, et que cette limite est indéterminée, -1 est retourné et errno n'est pas modifié. (Pour distinguer une limite indéterminée d'une erreur, initialisez errno à zéro avant l'appel, puis vérifiez si errno est non nul lorsque -1 est retourné.)
•
Si name correspond à une option, une valeur positive est retournée si l'option est prise en charge, et -1 est retourné si l'option n'est pas prise en charge.
•
Sinon, la valeur actuelle de l'option ou de la limite est retournée. Cette valeur ne sera pas plus restrictive que la valeur correspondante qui a été décrite à l'application dans <unistd.h> ou <limits.h> lors de la compilation de l'application.

ERREURS

EACCES
(pathconf()) La permission de recherche est refusée pour l'un des répertoires dans le préfixe du chemin de path.
EBADF
(fpathconf()) fd n'est pas un descripteur de fichier valide.
EINVAL
name est invalide.
EINVAL
L'implémentation ne prend pas en charge une association de name avec le fichier spécifié.
ELOOP
(pathconf()) Trop de liens symboliques ont été rencontrés lors de la résolution de path.
ENAMETOOLONG
(pathconf()) path est trop long.
ENOENT
(pathconf()) Un composant de path n'existe pas, ou path est une chaîne vide.
ENOTDIR
(pathconf()) Un composant utilisé comme répertoire dans path n'est pas en fait un répertoire.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
fpathconf (), pathconf () Sécurité des threads MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001.

NOTES

Des fichiers dont les noms sont plus longs que la valeur retournée pour name égal à _PC_NAME_MAX peuvent exister dans le répertoire donné.

Certaines valeurs retournées peuvent être énormes ; elles ne conviennent pas à l'allocation de mémoire.

VOIR AUSSI

getconf(1), open(2), statfs(2), confstr(3), sysconf(3)

pathconf(3)

Une section du manuel.

NOM

pathconf, fpathconf - obtenir les informations de configuration d'un fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <unistd.h>

long pathconf(const char *path, int name);
long fpathconf(int fd, int name);

DESCRIPTION

Les fonctions pathconf() et fpathconf() renvoient des informations de configuration permanentes sur le système de fichiers associé au chemin spécifié par path ou au descripteur de fichier fd, respectivement.

Les valeurs retournées par pathconf() et fpathconf() sont le résultat de l'évaluation du paramètre name.

Les valeurs de name possibles sont les suivantes :

_PC_CHOWN_RESTRICTED
Vérifie si le changement de propriétaire est restreint. Si c'est le cas, seul root peut changer la propriété d'un fichier. Si ce n'est pas le cas, un processus sans privilèges peut changer la propriété d'un fichier s'il en est le propriétaire et si le nouveau propriétaire est le propriétaire initial. La valeur renvoyée est positive si la restriction est activée, zéro sinon, et -1 en cas d'erreur.
_PC_LINK_MAX
Le nombre maximal de liens qu'un fichier peut avoir.
_PC_MAX_CANON
La longueur maximale d'une ligne canonique (en octets) pour les terminaux dans le mode canonique.
_PC_MAX_INPUT
La longueur maximale des données d'entrée (en octets) qui peuvent être attentent sur un périphérique d'entrée.
_PC_NAME_MAX
La longueur maximale d'un nom de fichier (à l'exclusion du terminateur nul en C).
_PC_NO_TRUNC
Vérifie si le troncage des noms de fichiers est activé. Si c'est le cas, les noms de fichiers plus longs que _PC_NAME_MAX sont tronqués. Si ce n'est pas le cas, une erreur ENAMETOOLONG est générée si un nom de fichier trop long est rencontré. La valeur renvoyée est positive si le troncage est activé, zéro sinon, et -1 en cas d'erreur.
_PC_PATH_MAX
La longueur maximale d'un nom de chemin (y compris le terminateur nul).
_PC_PIPE_BUF
La taille minimale garantie en octets pour les opérations d'écriture atomiques sur un tuyau. Si PIPE_BUF est supérieur à la taille physique du tuyau, les opérations d'écriture atomiques ne sont pas garanties.
_PC_VDISABLE
La valeur qui désactive une fonction de contrôle de terminal du champ c_cc dans la structure termios. La valeur renvoyée est la valeur de désactivation.

Pour plus d'informations sur ces constantes, consultez pathconf(3p).

VALEUR DE RETOUR

En cas de succès, pathconf() et fpathconf() renvoient la valeur configurée du paramètre demandé. Si la valeur demandée est indéterminée, -1 est renvoyé et errno est défini pour indiquer l'erreur.

Si pathconf() échoue, -1 est renvoyé et errno est défini pour indiquer l'erreur. Si fpathconf() échoue, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
fd n'est pas un descripteur de fichier valide.
EINVAL
name n'est pas une valeur valide.
ENAMETOOLONG
path est trop long.
ENOENT
Le fichier spécifié par path n'existe pas.
ENOTSUP
Le système de fichiers ne prend pas en charge la requête demandée.

ATTRIBUTS

Voir attributes(7) pour les définitions des attributs.

Interface Attribut
pathconf(), fpathconf() Threads, non (voir notes)

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001.

NOTES

Les deux fonctions renvoient des informations sur le système de fichiers sous-jacent. En d'autres termes, elles renvoient des informations spécifiques au système de fichiers et non des informations spécifiques au fichier.

Pour _PC_CHOWN_RESTRICTED, si pathconf() est appelé sur un chemin qui pointe vers un lien symbolique, le test est effectué sur le lien symbolique lui-même, et non sur le fichier vers lequel il pointe.

Pour _PC_NAME_MAX, pathconf() vérifie les limites de nom de fichier pour le répertoire spécifié par path. Si path n'est pas un répertoire, les limites du système de fichiers sont renvoyées.

La valeur renvoyée pour _PC_VDISABLE est spécifique à l'implémentation.

Les fonctions pathconf() et fpathconf() sont des fonctions au niveau du système, ce qui signifie qu'elles peuvent être appelées à partir de threads, mais que leur utilisation est déconseillée pour les raisons suivantes :

  • Elles peuvent être lentes à exécuter, car elles peuvent nécessiter des appels système pour interroger le noyau.
  • Elles ne sont pas conçues pour être utilisées dans des environnements multithreads concurrents.
