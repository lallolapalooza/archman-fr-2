pack200(1) Outils de déploiement Java pack200(1)

NOM

pack200 - Package un fichier JAR dans un fichier pack200 compressé pour le déploiement web.

SYNTAXE

pack200 [options] fichier-sortie fichier-JAR

Les options peuvent être dans n'importe quel ordre. La dernière option sur la ligne de commande ou dans un fichier de propriétés remplace toutes les options précédemment spécifiées.

options
Les options de la ligne de commande. Voir Options.
fichier-sortie
Nom du fichier de sortie.
fichier-JAR
Nom du fichier d'entrée.

DESCRIPTION

La commande pack200 est une application Java qui transforme un fichier JAR en un fichier pack200 compressé avec le compresseur Java gzip. Les fichiers pack200 sont des fichiers hautement compressés qui peuvent être déployés directement pour économiser de la bande passante et réduire le temps de téléchargement.

La commande pack200 dispose de plusieurs options pour affiner et configurer le moteur de compression. L'utilisation typique est montrée dans l'exemple suivant, où myarchive.pack.gz est produit avec les paramètres par défaut de la commande pack200 :

pack200 myarchive.pack.gz myarchive.jar

OPTIONS

-r, --repack

Produit un fichier JAR en packant et décompressant un fichier JAR. Le fichier résultant peut être utilisé comme entrée pour l'outil jarsigner(1). L'exemple suivant packe et décompresse le fichier myarchive.jar : 
pack200 --repack myarchive-packer.jar myarchive.jar
pack200 --repack myarchive.jar

L'exemple suivant préserve l'ordre des fichiers dans le fichier d'entrée.

-g, --no-gzip

Produit un fichier pack200. Avec cette option, un compresseur approprié doit être utilisé, et le système cible doit utiliser un décompresseur correspondant. 
pack200 --no-gzip myarchive.pack myarchive.jar
-G, --strip-debug

Supprime les attributs de débogage de la sortie. Ceux-ci incluent SourceFile, LineNumberTable, LocalVariableTable et LocalVariableTypeTable. La suppression de ces attributs réduit la taille des téléchargements et des installations, mais diminue l'utilité des débogueurs.
--keep-file-order

Préserve l'ordre des fichiers dans le fichier d'entrée. C'est le comportement par défaut.
-O, --no-keep-file-order

Le packeur réorganise et transmet tous les éléments. Le packeur peut également supprimer les noms de répertoire JAR pour réduire la taille de téléchargement. Cependant, certaines optimisations de fichiers JAR, telles que l'indexation, peuvent ne pas fonctionner correctement.
-Svaleur , --segment-limit=valeur

La valeur est la taille cible estimée N (en octets) de chaque segment d'archive. Si un seul fichier d'entrée nécessite plus de N octets, alors son propre segment d'archive est fourni. À titre de cas spécial, une valeur de -1 produit un seul grand segment avec tous les fichiers d'entrée, tandis qu'une valeur de 0 produit un segment pour chaque classe. Des segments d'archive plus grands entraînent moins de fragmentation et une meilleure compression, mais leur traitement nécessite plus de mémoire.

La taille de chaque segment est estimée en comptant la taille de chaque fichier d'entrée à transmettre dans le segment avec la taille de son nom et d'autres propriétés transmises.

La valeur par défaut est -1, ce qui signifie que le packeur crée un fichier de sortie à segment unique. Dans les cas où des fichiers de sortie extrêmement volumineux sont générés, il est fortement recommandé aux utilisateurs d'utiliser la segmentation ou de diviser le fichier d'entrée en JARs plus petits.

Un JAR de 10 Mo packé sans cette limite est généralement packé environ 10 % plus petit, mais le packeur peut nécessiter un tas Java plus grand (environ 10 fois la limite de segment).

-Evaleur , --effort=valeur

Si la valeur est définie sur un seul chiffre décimal, le packeur utilise la quantité d'effort indiquée pour compresser l'archive. Le niveau 1 peut produire une taille légèrement plus grande et une vitesse de compression plus rapide, tandis que le niveau 9 prend beaucoup plus de temps, mais peut produire une meilleure compression. La valeur spéciale 0 indique à la commande pack200 de copier directement le fichier JAR original sans aucune compression. La norme JSR 200 exige que tout décompresseur comprenne ce cas spécial comme un passage direct de l'intégralité de l'archive.

La valeur par défaut est 5, pour investir un temps modeste afin de produire une compression raisonnable.

-Hvaleur , --deflate-hint=valeur

Remplace le comportement par défaut, qui préserve les informations d'entrée, mais peut rendre l'archive transmise plus volumineuse. Les valeurs possibles sont : true, false, ou keep.

Si la valeur est true ou false, la commande packer200 définit l'indice de déflation en conséquence dans l'archive de sortie et ne transmet pas les indices de déflation individuels des éléments de l'archive.

La valeur keep préserve les indices de déflation observés dans le JAR d'entrée. C'est le comportement par défaut.

-mvaleur , --modification-time=valeur

Les valeurs possibles sont latest et keep.

Si la valeur est latest, le packeur tente de déterminer la dernière heure de modification, parmi toutes les entrées disponibles dans l'archive originale, ou la dernière heure de modification de toutes les entrées disponibles dans ce segment. Cette valeur unique est transmise dans le cadre du segment et appliquée à toutes les entrées de chaque segment. Cela peut réduire marginalement la taille transmise de l'archive au détriment de la définition de tous les fichiers installés à une seule date.

Si la valeur est keep, les heures de modification observées dans le JAR d'entrée sont préservées. C'est le comportement par défaut.

-Pfichier , --pass-file=fichier

Indique qu'un fichier doit être transmis octet par octet sans compression. En répétant l'option, plusieurs fichiers peuvent être spécifiés. Il n'y a pas de transformation de chemin, sauf que le séparateur de système de fichiers est remplacé par le séparateur de fichier JAR slash (/).. Les noms de fichiers résultants doivent correspondre exactement aux chaînes de caractères de leurs occurrences dans le fichier JAR. Si fichier est un nom de répertoire, alors tous les fichiers sous ce répertoire sont passés.
-Uaction , --unknown-attribute=action

Remplace le comportement par défaut, ce qui signifie que le fichier de classe contenant l'attribut inconnu est transmis avec l'action spécifiée. Les valeurs possibles pour les actions sont error, strip, ou pass.

Si la valeur est error, toute l'opération de commande pack200 échoue avec une explication appropriée.

Si la valeur est strip, l'attribut est supprimé. La suppression des attributs requis par la Machine Virtuelle Java (JVM) peut entraîner des erreurs de chargeur de classe.

Si la valeur est pass, la classe entière est transmise comme si c'était une ressource.

-f pack.properties ,
    --config-file=pack.properties

  

    

    Un fichier de configuration, contenant des propriétés Java pour initialiser l'emballeur,
      peut être spécifié sur la ligne de commande.
        
pack200 -f pack.properties monarchive.pack.gz monarchive.jar

-v, --verbose

  

    

    Affiche des messages minimaux. La spécification multiple de cette option créera
      des messages plus verbeux.

  
-q, --quiet

  

    

    Spécifie une opération silencieuse sans messages.

  
-lnom_fichier ,
    --log-file=nom_fichier

  

    

    Spécifie un fichier journal pour afficher les messages.

  
-?, -h, --help

  

    

    Affiche des informations d'aide sur cette commande.

  
-V, --version

  

    

    Affiche les informations de version sur cette commande.

  
-Joption

  

    

    Transmet l'option spécifiée à la machine virtuelle Java. Pour plus d'informations,
      voir la page de référence de la commande java(1). Par exemple,
      -J-Xms48m définit la mémoire de démarrage à 48 Mo.






STATUS&#x00A0;DE&#x00A0;SORTIE


Les valeurs de sortie suivantes sont retournées : 0 pour une exécution
    réussie et un nombre supérieur à 0 en cas d'erreur.






NOTES


Cette commande ne doit pas être confondue avec pack(1). Les
    commandes pack et pack200 sont des produits distincts.


La spécification de l'API Java SE fournie avec le JDK fait autorité
    en cas de divergences.
