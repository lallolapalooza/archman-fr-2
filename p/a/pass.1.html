PASS(1) Password Store PASS(1)

NOM

pass - stocke, récupère, génère et synchronise les mots de passe de manière sécurisée

SYNTAXE

pass [ COMMANDE ] [ OPTIONS ]... [ ARGUMENTS ]...

DESCRIPTION

pass est un gestionnaire de mots de passe très simple qui stocke les mots de passe dans des fichiers chiffrés gpg2(1) à l'intérieur d'une arborescence de répertoires simple résidant dans ~/.password-store. L'utilitaire pass fournit une série de commandes pour manipuler le magasin de mots de passe, permettant à l'utilisateur d'ajouter, supprimer, modifier, synchroniser, générer et manipuler les mots de passe.

Si aucune COMMANDE n'est spécifiée, la COMMANDE par défaut est soit show, soit ls, en fonction du type de spécificateur dans ARGUMENTS. Alternativement, si PASSWORD_STORE_ENABLE_EXTENSIONS est défini sur "true", et que le fichier .extensions/COMMANDE.bash existe dans le magasin de mots de passe et est exécutable, alors il est sourcé dans l'environnement, passant tous les arguments et variables d'environnement. Les extensions existant dans un répertoire système, uniquement installables par l'administrateur, sont toujours activées.

Sinon, la COMMANDE doit être l'une des commandes valides listées ci-dessous.

Plusieurs des commandes ci-dessous s'appuient sur, ou fournissent, des fonctionnalités supplémentaires si le répertoire du magasin de mots de passe est également un dépôt git. Si le répertoire du magasin de mots de passe est un dépôt git, toutes les commandes de modification du magasin de mots de passe provoqueront un commit git correspondant. Les sous-répertoires peuvent être des dépôts git imbriqués distincts, et pass utilisera le répertoire le plus interne par rapport au mot de passe actuel. Voir la section EXEMPLE GIT ÉTENDU pour une description détaillée utilisant init et git(1).

La commande init doit être exécutée avant les autres commandes afin d'initialiser le magasin de mots de passe avec l'identifiant de clé gpg correct. Les mots de passe sont chiffrés en utilisant la clé gpg définie avec init.

Il existe un script de complétion bash correspondant pour l'utilisation avec la complétion par tabulation des noms de mots de passe dans bash(1).

COMMANDES

init [ --path=sous-dossier, -p sous-dossier ] id-gpg...
Initialise un nouveau stockage de mots de passe et utilise id-gpg pour le chiffrement. Plusieurs ids gpg peuvent être spécifiés, afin de chiffrer chaque mot de passe avec plusieurs ids. Cette commande doit être exécutée en premier avant qu'un magasin de mots de passe puisse être utilisé. Si l'id-gpg spécifié est différent de la clé utilisée dans les fichiers existants, ces fichiers seront ré-chiffrés pour utiliser le nouvel id. Notez que l'utilisation de gpg-agent(1) est recommandée afin que le déchiffrement par lots ne nécessite pas autant d'intervention utilisateur. Si --path ou -p est spécifié, ainsi qu'un argument, un identifiant gpg spécifique ou un ensemble d'identifiants gpg est attribué à ce sous-dossier spécifique du magasin de mots de passe. Si un seul id-gpg est donné, et qu'il s'agit d'une chaîne vide, alors le fichier .gpg-id courant pour le sous-dossier spécifié (ou la racine s'il n'est pas spécifié) est supprimé.
ls sous-dossier
Liste les noms des mots de passe dans l'arborescence à sous-dossier en utilisant le programme tree(1). Cette commande est alternativement nommée list.
grep [OPTIONS-GREP] chaine-recherche
Recherche dans chaque fichier de mot de passe déchiffré la chaine-recherche, et affiche la ligne contenant la chaîne correspondante avec le nom de fichier. Utilise grep(1) pour la correspondance. OPTIONS-GREP sont passées à grep(1) telles quelles. (Note : la variable d'environnement GREP_OPTIONS fonctionne également.)
find noms-de-mot-de-passe...
Liste les noms des mots de passe dans l'arborescence qui correspondent à noms-de-mot-de-passe en utilisant le programme tree(1). Cette commande est alternativement nommée search.
show [ --clip[=numéro-de-ligne], -c[numéro-de-ligne] ] [ --qrcode[=numéro-de-ligne], -q[numéro-de-ligne] ] nom-de-mot-de-passe
Déchiffre et affiche un mot de passe nommé nom-de-mot-de-passe. Si --clip ou -c est spécifié, n'affiche pas le mot de passe mais copie la première ligne (ou celle spécifiée) dans le presse-papiers en utilisant xclip(1) ou wl-clipboard(1) puis restaure le presse-papiers après 45 (ou PASSWORD_STORE_CLIP_TIME) secondes. Si --qrcode ou -q est spécifié, n'affiche pas le mot de passe mais affiche un code QR en utilisant qrencode(1) soit dans le terminal, soit graphiquement si supporté.
insert [ --echo, -e | --multiline, -m ] [ --force, -f ] nom-de-mot-de-passe
Insère un nouveau mot de passe dans le magasin de mots de passe appelé nom-de-mot-de-passe. Ceci lira le nouveau mot de passe depuis l'entrée standard. Si --echo ou -e n'est *pas* spécifié, désactive l'écho du clavier lorsque le mot de passe est entré et confirme le mot de passe en le demandant deux fois. Si --multiline ou -m est spécifié, les lignes seront lues jusqu'à EOF ou Ctrl+D. Sinon, seule une seule ligne de l'entrée standard est lue. Demande confirmation avant d'écraser un mot de passe existant, sauf si --force ou -f est spécifié. Cette commande est alternativement nommée add.
edit nom-de-mot-de-passe
Insère un nouveau mot de passe ou édite un mot de passe existant en utilisant l'éditeur de texte par défaut spécifié par la variable d'environnement EDITOR ou en utilisant vi(1) en dernier recours. Ce mode utilise des fichiers temporaires pour l'édition, mais des précautions sont prises pour s'assurer que les fichiers temporaires sont créés dans /dev/shm afin d'éviter d'écrire sur des secteurs de disque difficiles à effacer. Si /dev/shm n'est pas accessible, il se rabat sur l'emplacement ordinaire TMPDIR et affiche un avertissement.
generate [ --no-symbols, -n ] [ --clip, -c ] [ --in-place, -i | --force, -f ] nom-de-mot-de-passe [longueur-mot-de-passe]
Génère un nouveau mot de passe en utilisant /dev/urandom d'une longueur de longueur-mot-de-passe (ou PASSWORD_STORE_GENERATED_LENGTH si non spécifiée) et l'insère dans nom-de-mot-de-passe. Si --no-symbols ou -n est spécifié, n'utilise aucun caractère non alphanumérique dans le mot de passe généré. Les ensembles de caractères utilisés pour générer les mots de passe peuvent être modifiés avec les variables d'environnement PASSWORD_STORE_CHARACTER_SET et PASSWORD_STORE_CHARACTER_SET_NO_SYMBOLS, décrites ci-dessous. Si --clip ou -c est spécifié, n'affiche pas le mot de passe mais le copie dans le presse-papiers en utilisant xclip(1) ou wl-clipboard(1) puis restaure le presse-papiers après 45 (ou PASSWORD_STORE_CLIP_TIME) secondes. Si --qrcode ou -q est spécifié, n'affiche pas le mot de passe mais affiche un code QR en utilisant qrencode(1) soit dans le terminal, soit graphiquement si supporté. Demande confirmation avant d'écraser un mot de passe existant, sauf si --force ou -f est spécifié. Si --in-place ou -i est spécifié, ne demande pas interactivement, et remplace uniquement la première ligne du fichier de mot de passe par le nouveau mot de passe généré, en gardant le reste du fichier intact.
rm [ --recursive, -r ] [ --force, -f ] nom-de-mot-de-passe
Supprime le mot de passe nommé nom-de-mot-de-passe du magasin de mots de passe. Cette commande est alternativement nommée remove ou delete. Si --recursive ou -r est spécifié, supprime récursivement nom-de-mot-de-passe s'il s'agit d'un répertoire. Si --force ou -f est spécifié, ne demande pas interactivement avant la suppression.
mv [ --force, -f ] ancien-chemin nouveau-chemin
Renomme le mot de passe ou le répertoire nommé ancien-chemin en nouveau-chemin. Cette commande est alternativement nommée rename. Si --force est spécifié, écrase silencieusement nouveau-chemin s'il existe. Si nouveau-chemin se termine par un /, il est toujours traité comme un répertoire. Les mots de passe sont sélectivement re-chiffrés avec les clés correspondantes de leur nouvelle destination.

i> ] ancien-chemin nouveau-chemin
Copie le mot de passe ou le répertoire nommé ancien-chemin vers nouveau-chemin. Cette commande est alternativement nommée copy. Si --force est spécifié, écrase silencieusement nouveau-chemin s'il existe. Si nouveau-chemin se termine par un /, il est toujours traité comme un répertoire. Les mots de passe sont sélectivement ré-chiffrés aux clés correspondantes de leur nouvelle destination.
git arguments-de-commande-git...
Si le magasin de mots de passe est un dépôt git, passe arguments-de-commande-git en tant qu'arguments à git(1) en utilisant le magasin de mots de passe comme dépôt git. Si arguments-de-commande-git est init, en plus d'initialiser le dépôt git, ajoute le contenu actuel du magasin de mots de passe au dépôt dans un commit initial. Si la clé de configuration git pass.signcommits est définie sur true, alors tous les commits seront signés en utilisant user.signingkey ou la clé de signature git par défaut. Cette clé de configuration peut être activée en utilisant : `pass git config --bool --add pass.signcommits true`
help
Affiche le message d'utilisation.
version
Affiche les informations de version.

EXEMPLES SIMPLES

Initialiser le magasin de mots de passe
zx2c4@laptop ~ $ pass init Jason@zx2c4.com
mkdir: created directory ‘/home/zx2c4/.password-store’
Password store initialized for Jason@zx2c4.com.
Lister les mots de passe existants dans le magasin
zx2c4@laptop ~ $ pass
Password Store
├── Business
│ ├── some-silly-business-site.com
│ └── another-business-site.net
├── Email
│ ├── donenfeld.com
│ └── zx2c4.com
└── France
├── bank
├── freebox
└── mobilephone

Alternativement, "pass ls".

Trouver les mots de passe existants dans le magasin qui correspondent à .com
zx2c4@laptop ~ $ pass find .com
Search Terms: .com
├── Business
│ ├── some-silly-business-site.com
└── Email
├── donenfeld.com
└── zx2c4.com

Alternativement, "pass search .com".

Afficher le mot de passe existant
zx2c4@laptop ~ $ pass Email/zx2c4.com
sup3rh4x3rizmynam3
Copier le mot de passe existant dans le presse-papiers
zx2c4@laptop ~ $ pass -c Email/zx2c4.com
Copied Email/jason@zx2c4.com to clipboard. Will clear in 45 seconds.
Ajouter un mot de passe au magasin
zx2c4@laptop ~ $ pass insert Business/cheese-whiz-factory
Enter password for Business/cheese-whiz-factory: omg so much cheese what am i gonna do
Ajouter un mot de passe multiligne au magasin
zx2c4@laptop ~ $ pass insert -m Business/cheese-whiz-factory
Enter contents of Business/cheese-whiz-factory and press Ctrl+D when finished:

Hey this is my
awesome
multi
line
passworrrrrrrrd.
^D

Générer un nouveau mot de passe
zx2c4@laptop ~ $ pass generate Email/jasondonenfeld.com 15
The generated password to Email/jasondonenfeld.com is:
$(-QF&Q=IN2nFBx
Générer un nouveau mot de passe alphanumérique
zx2c4@laptop ~ $ pass generate -n Email/jasondonenfeld.com 12
The generated password to Email/jasondonenfeld.com is:
YqFsMkBeO6di
Générer un nouveau mot de passe et le copier dans le presse-papiers
zx2c4@laptop ~ $ pass generate -c Email/jasondonenfeld.com 19
Copied Email/jasondonenfeld.com to clipboard. Will clear in 45 seconds.
Supprimer un mot de passe du magasin
zx2c4@laptop ~ $ pass remove Business/cheese-whiz-factory
rm: remove regular file ‘/home/zx2c4/.password-store/Business/cheese-whiz-factory.gpg’? y
removed ‘/home/zx2c4/.password-store/Business/cheese-whiz-factory.gpg’

FICHIERS

~/.password-store
Le répertoire de stockage de mots de passe par défaut.
~/.password-store/.gpg-id
Contient l'identification de la clé gpg par défaut utilisée pour le chiffrement et le déchiffrement. Plusieurs clés gpg peuvent être spécifiées dans ce fichier, une par ligne. Si ce fichier existe dans des sous-répertoires, les mots de passe à l'intérieur de ces sous-répertoires sont chiffrés en utilisant ces clés. Ceci doit être configuré en utilisant la commande init.
~/.password-store/.extensions
Le répertoire contenant les fichiers d'extension.

VARIABLES ENVIRONNEMENT

PASSWORD_STORE_DIR
Remplace le répertoire de stockage de mots de passe par défaut.
PASSWORD_STORE_KEY
Remplace l'identification de la clé gpg par défaut définie par init. Les clés ne doivent pas contenir d'espaces et donc l'utilisation de la signature hexadécimale de la clé est recommandée. Plusieurs clés peuvent être spécifiées séparées par des espaces.
PASSWORD_STORE_GPG_OPTS
Options supplémentaires à passer à toutes les invocations de GPG.
PASSWORD_STORE_X_SELECTION
Remplace la sélection passée à xclip, par défaut clipboard. Voir xclip(1) pour plus d'informations.
PASSWORD_STORE_CLIP_TIME
Spécifie le nombre de secondes à attendre avant de restaurer le presse-papiers, par défaut 45 secondes.
PASSWORD_STORE_UMASK
Définit le umask de tous les fichiers modifiés par pass, par défaut 077.
PASSWORD_STORE_GENERATED_LENGTH
La longueur de mot de passe par défaut si le paramètre pass-length de generate n'est pas spécifié.
PASSWORD_STORE_CHARACTER_SET
L'ensemble de caractères à utiliser dans la génération de mots de passe pour generate. Cette valeur doit être interprétée par tr. Voir tr(1) pour plus d'informations.
PASSWORD_STORE_CHARACTER_SET_NO_SYMBOLS
L'ensemble de caractères à utiliser pour la génération de mots de passe sans symboles pour generate, lorsque --no-symbols, -n est spécifié. Cette valeur doit être interprétée par tr. Voir tr(1) pour plus d'informations.
PASSWORD_STORE_ENABLE_EXTENSIONS
Cette variable d'environnement doit être définie à « true » pour que les extensions soient activées.
PASSWORD_STORE_EXTENSIONS_DIR
L'emplacement où rechercher les fichiers exécutables d'extensions, par défaut PASSWORD_STORE_DIR/.extensions.
PASSWORD_STORE_SIGNING_KEY
Si cette variable d'environnement est définie, alors tous les fichiers .gpg-id et les fichiers d'extensions non système doivent être signés à l'aide d'une signature détachée utilisant la clé GPG spécifiée par l'empreinte complète de 40 caractères en majuscules dans cette variable. Si plusieurs empreintes sont spécifiées, séparées par un espace blanc, la signature doit correspondre à au moins une d'entre elles. La commande init mettra à jour les signatures des fichiers .gpg-id.
EDITOR
L'emplacement de l'éditeur de texte utilisé par edit.

VOIR AUSSI

gpg2(1), tr(1), git(1), xclip(1), wl-clipboard(1), qrencode(1).
