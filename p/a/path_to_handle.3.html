path_to_handle(3)

HANDLE(3) Manuel des fonctions de bibliothèque HANDLE(3)

NOM

path_to_handle, path_to_fshandle, fd_to_handle, handle_to_fshandle, open_by_handle, readlink_by_handle, attr_multi_by_handle, attr_list_by_handle, fssetdm_by_handle, free_handle, getparents_by_handle, getparentpaths_by_handle - opérations sur les descripteurs de fichiers

int open_by_handle(void *hanp, size_t hlen, int oflag);

int readlink_by_handle(void *hanp, size_t hlen, void *buf, size_t bs);

int attr_multi_by_handle(void *hanp, size_t hlen, void *buf, int rtrvcnt, int flags);

int attr_list_by_handle(void *hanp, size_t hlen, char *buf, size_t bufsiz, int flags, struct attrlist_cursor *cursor);

DESCRIPTION

Ces fonctions fournissent un moyen d'effectuer certaines opérations sur le système de fichiers sans utiliser de descripteur de fichier pour accéder aux objets du système de fichiers. Elles sont destinées à être utilisées par un ensemble limité d'utilitaires système tels que les programmes de sauvegarde. Elles ne sont prises en charge que par le système de fichiers XFS. Liez avec la bibliothèque libhandle pour accéder à ces fonctions.

Un descripteur, hanp, identifie de manière unique un objet du système de fichiers ou un système de fichiers entier. Il existe un et un seul descripteur par système de fichiers ou objet du système de fichiers. Les descripteurs consistent en un certain nombre d'octets. La taille d'un descripteur (c'est-à-dire le nombre d'octets le composant) varie selon le type de descripteur et peut varier pour différents objets du même type. Le contenu d'un descripteur est opaque pour les applications. Étant donné que les tailles des descripteurs varient et que leur contenu est opaque, les descripteurs sont décrits par deux quantités, un pointeur (hanp) et une taille (hlen). La taille, hlen, indique le nombre d'octets dans le descripteur auquel le pointeur pointe.

La fonction path_to_handle() renvoie le descripteur de l'objet spécifié par l'argument path. Si le dernier composant du nom de chemin est un lien symbolique, le descripteur renvoyé est celui du lien lui-même.

La fonction path_to_fshandle() renvoie le descripteur du système de fichiers dans lequel réside l'objet spécifié par l'argument path.

La fonction fd_to_handle() renvoie le descripteur de l'objet référencé par l'argument fd, qui doit être un descripteur de fichier valide.

La fonction handle_to_fshandle() renvoie le descripteur du système de fichiers dans lequel réside l'objet référencé par le descripteur fourni par les arguments hanp et hlen.

La fonction open_by_handle() ouvre un descripteur de fichier pour l'objet référencé par un descripteur. Elle est analogue et identique à open(2), à la différence près qu'elle accepte des descripteurs au lieu de noms de chemin.

La fonction readlink_by_handle() renvoie le contenu d'un lien symbolique référencé par un descripteur.

La fonction attr_multi_by_handle() manipule plusieurs attributs utilisateur sur un objet du système de fichiers. Elle est analogue et identique à attr_multif(3) à cela près qu'un descripteur est spécifié au lieu d'un descripteur de fichier.

La fonction attr_list_by_handle() renvoie les noms des attributs utilisateur d'un objet du système de fichiers. Elle est analogue et identique à attr_listf(3) à cela près qu'un descripteur est spécifié au lieu d'un descripteur de fichier.

La fonction fssetdm_by_handle() définit les champs di_dmevmask et di_dmstate dans un inode XFS sur disque. Elle est analogue à la commande XFS_IOC_FSSETDM xfsctl(3), à la différence près qu'un descripteur est spécifié au lieu d'un fichier. Cette fonction n'est pas prise en charge sous Linux.

La fonction free_handle() libère la mémoire allouée pour les descripteurs renvoyés par les fonctions suivantes : path_to_handle(), path_to_fshandle(), fd_to_handle() et handle_to_fshandle().

La fonction getparents_by_handle() renvoie un tableau de structures parent_t pour chaque lien physique vers l'inode représenté par le descripteur donné. La structure parent encode le numéro de l'inode parent, le numéro de génération et le nom de base du lien. Cette fonction n'est pas opérationnelle sous Linux.

La fonction getparentpaths_by_handle() est identique à la fonction getparents_by_handle() à cela près qu'au lieu de renvoyer le nom de base, elle renvoie le chemin du lien jusqu'au point de montage. Cette fonction n'est pas non plus opérationnelle sous Linux.

VALEUR RENVOYÉE

La fonction free_handle() n'a pas d'indication d'échec. Les autres fonctions renvoient la valeur 0 au processus appelant si elles réussissent ; sinon, elles renvoient la valeur -1 et définissent errno pour indiquer l'erreur.

ERREURS

EACCES
La permission de recherche a été refusée pour un composant de path.
EBADF
fd n'est pas un descripteur de fichier valide et ouvert.
EFAULT
Un argument pointait vers une adresse invalide.
EINVAL
path est dans un système de fichiers qui ne prend pas en charge ces fonctions.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la traduction du nom de chemin.
ENAMETOOLONG
Un composant de path ou la longueur entière de path dépasse les limites du système de fichiers.
ENOENT
Un composant de path n'existe pas.
EPERM
L'appelant n'a pas les privilèges suffisants.

VOIR AUSSI
