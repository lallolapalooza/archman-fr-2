Nom

pam_mount - Un module PAM capable de monter des volumes pour une session utilisateur

Présentation

Ce module est destiné aux environnements avec des serveurs de fichiers centraux qu'un utilisateur peut souhaiter monter à la connexion et démonter à la déconnexion, comme les stations (semi-)sans disque où de nombreux utilisateurs peuvent se connecter et où le montage statique de tout le répertoire /home depuis un serveur représente un risque de sécurité, ou où lister tous les volumes possibles dans /etc/fstab n'est pas réalisable.

  • Les utilisateurs peuvent définir leur propre liste de volumes sans avoir à modifier des fichiers de configuration globaux (potentiellement non inscriptibles).
  • Fonctionnalité d'authentification unique – l'utilisateur n'a besoin de taper son mot de passe qu'une seule fois (à la connexion).
  • Processus de montage transparent.
  • Aucun mot de passe stocké.
  • Les volumes sont démontés à la déconnexion, libérant ainsi les ressources système et évitant de laisser des données exposées.

Le module prend également en charge le montage de systèmes de fichiers locaux de tout type que l'utilitaire de montage normal prend en charge, avec du code supplémentaire pour s'assurer que certains volumes sont correctement configurés car ils nécessitent souvent plus qu'un simple appel de montage, tels que les volumes chiffrés. Cela inclut SMB/CIFS, FUSE, dm-crypt et LUKS.

Si vous avez l'intention d'utiliser pam_mount pour protéger des volumes sur votre ordinateur à l'aide d'un système de fichiers chiffré, sachez qu'il existe de nombreux autres problèmes que vous devez considérer afin de protéger vos données. Par exemple, vous voudrez probablement désactiver ou chiffrer votre partition swap (cryptoswap peut vous aider à le faire). Ne supposez pas qu'un système est sécurisé sans examiner attentivement les menaces potentielles.

Configuration

Le fichier de configuration principal du module pam_mount est pam_mount.conf.xml. Sur la plupart des plateformes, ce fichier est lu depuis /etc/security/pam_mount.conf.xml. Sur OpenBSD, pam_mount lit son fichier de configuration depuis /etc/pam_mount.conf.xml. Consultez pam_mount.conf(5) pour sa documentation.

Les utilisateurs individuels peuvent définir des volumes supplémentaires à monter si cela est autorisé par pam_mount.conf.xml (généralement ~/.pam_mount.conf.xml). Le mot-clé volume est le seul mot-clé valide dans ces fichiers de configuration par utilisateur. Si le paramètre luserconf est défini dans pam_mount.conf.xml, autorisant le montage de volumes définis par l'utilisateur, alors les utilisateurs peuvent monter et démonter tout volume leur appartenant, à tout point de montage leur appartenant. Sur certaines configurations de systèmes de fichiers, cela peut constituer une faille de sécurité, c'est pourquoi les volumes définis par l'utilisateur ne sont pas autorisés par l'exemple pam_mount.conf.xml distribué avec pam_mount.

Configuration PAM

De plus, vous devez ajouter deux entrées dans les fichiers de configuration /etc/pam.d/service applicables du système, comme le montre l'exemple suivant :

    auth     required  pam_securetty.so
    auth     required  pam_pwdb.so shadow nullok
    auth     required  pam_nologin.so
+++ auth     optional  pam_mount.so
    account  required  pam_pwdb.so
    password required  pam_cracklib.so
    password required  pam_pwdb.so shadow nullok use_authtok
    session  required  pam_pwdb.so
    session  optional  pam_console.so
+++ session  optional  pam_mount.so

Lorsque "sufficient" est utilisé dans la deuxième colonne, vous devez vous assurer que pam_mount est ajouté avant cette entrée. Sinon, pam_mount ne sera pas exécuté si un module PAM précédent réussit. Soyez également attentif aux instructions "include". Celles-ci amènent PAM à examiner le fichier spécifié. S'il y a une instruction "sufficient", l'entrée pam_mount doit soit se trouver dans le fichier inclus avant l'instruction "sufficient", soit avant l'instruction "include".

Si vous utilisez pam_ldap, pam_winbind, ou tout autre service d'authentification qui utilise le mot-clé sufficient de PAM, modèlez votre configuration sur l'ordre suivant :

•••
account sufficient  pam_ldap.so
auth    required    pam_mount.so
auth    sufficient  pam_ldap.so use_first_pass
auth    required    pam_unix.so use_first_pass
session optional    pam_mount.so
•••

Ceci permet :

1.
pam_mount, en tant que premier module "auth", demandera un mot de passe et l'exportera dans le système PAM.
2.
pam_ldap utilisera le mot de passe du système PAM pour tenter d'authentifier l'utilisateur. Si cela réussit, l'utilisateur sera authentifié. Sinon, pam_unix tentera l'authentification.
3.
pam_unix tentera d'authentifier l'utilisateur si pam_ldap a échoué. Si pam_unix échoue, l'authentification sera refusée (en raison de "required").

Alternativement, ce qui suit est possible (merci à Andrew Morgan pour le tuyau !) :

auth [success=2 default=ignore] pam_unix2.so
auth [success=1 default=ignore] pam_ldap.so use_first_pass
auth requisite pam_deny.so
auth optional pam_mount.so

Cela peut sembler étrange, mais les trois premières lignes garantiront qu'au moins l'un des pam_unix2 ou pam_ldap réussisse. Comme vous pouvez le voir, pam_mount sera exécuté **après** une authentification réussie avec ces sous-systèmes.

Disques chiffrés

pam_mount prend en charge quelques types de chiffrement. Les plus courants sont encfs, dm-crypt et dm-crypt+LUKS.

Le premier utilise la couche FUSE ; les fichiers du conteneur encfs sont stockés en tant que fichiers chiffrés uniques sur l'hôte dans un répertoire préalablement existant. Si vous stockez de nombreux fichiers, il est recommandé d'avoir un système de fichiers sous-jacent robuste dans ce domaine, comme xfs, mais certains logiciels et/ou vos choix de partitionnement peuvent vous obliger à utiliser un autre système de fichiers. Le mappage 1:1 des fichiers permet également aux fichiers chiffrés d'être raisonnablement efficacement synchronisés (par exemple, avec rsync) sans avoir à ouvrir le conteneur chiffré. La création se fait via l'outil encfs(1).

dm-crypt assure le chiffrement du système de fichiers complet/de la partition entière. Vous pouvez également créer un fichier conteneur, mais l'idée est qu'il est représenté comme un périphérique bloc sur lequel vous devez toujours créer un système de fichiers. En fait, de cette façon, vous pouvez choisir un système de fichiers de votre choix. Le revers est que le rétrécissement n'est souvent pas possible (il n'y a pas de tel problème avec encfs car il utilise le système de fichiers sous-jacent). Des conteneurs dm-crypt appropriés (et des fichiers auxiliaires), utilisant des périphériques bloc ou des fichiers simples, peuvent être créés à l'aide de l'outil pmt-ehd(8).

pmt-ehd crée du matériel de clé de système de fichiers qui est un ensemble d'octets aléatoires qui seront utilisés pour chiffrer/déchiffrer le volume. Ce matériel lui-même est chiffré avec votre propre mot de passe - ceci est fait afin que vous puissiez changer le mot de passe sans avoir à ré-chiffrer toutes vos données.

LUKS est une extension de dm-crypt pour prendre en charge les conteneurs multi-mots de passe. Sauf si vous en avez spécifiquement besoin, les deux solutions ci-dessus sont recommandées.

NOTE : Le fichier clé que pmt-ehd(8) créera représente le matériel de clé du système de fichiers tel que chiffré avec votre mot de passe. Il est donc sûr de le stocker sur un système de fichiers non sécurisé.

Dépannage

Pour vous assurer que votre système et, éventuellement, le serveur distant sont correctement configurés, vous devriez essayer de monter tout ou partie des volumes manuellement, en utilisant les mêmes commandes et points de montage que ceux fournis dans pam_mount.conf.xml. Cela vous évitera bien des tracas, car il est plus difficile de déboguer le processus de montage via pam_mount.

Si vous parvenez à monter les volumes manuellement mais que cela ne se produit pas via pam_mount, vous pourriez vouloir activer l'option "debug" dans pam_mount.conf.xml pour voir ce qui se passe.

Vérifiez si l'utilisateur possède le point de montage et dispose des autorisations suffisantes sur celui-ci. pam_mount vérifiera cela et refusera de monter le volume distant si l'utilisateur ne possède pas ce répertoire.

Si pam_mount rencontre des problèmes pour démonter les volumes lors de la déconnexion, activez la variable debug. Cela fait que pam_mount s'exécute à la déconnexion et écrit sa sortie dans le journal du système.

Name

pam_mount - mount user-defined volumes according to PAM rules

Overview

pam_mount is a PAM module that allows users to mount volumes automatically upon login. This can be used for various purposes, such as mounting home directories from a network server, or mounting encrypted volumes when the user logs in.

Configuration

The configuration for pam_mount is done in two files:

  • /etc/security/pam_mount.conf: This file defines the mount points and the rules for mounting them.
  • PAM configuration files: These files (e.g., in /etc/pam.d/) tell the system to use the pam_mount module.
The pam_mount.conf file uses a simple format where each line defines a volume to be mounted. The basic syntax is:

  VOLUME TYPE DEVICE MOUNTPOINT OPTIONS
For example, to mount a user's home directory from an NFS server: 
  Volume    /home    nfsv3    server:/exports/home    /home    auto,user,rw,bg,hard,nointr,rsize=8192,wsize=8192,tcp,vers=3
Or to mount an encrypted LUKS volume: 
  Volume    enc    luks    /dev/sda2    /home/user/encrypted    luks,allow_discards
Refer to the pam_mount.conf(5) man page for a detailed description of all options.

PAM configuration

To enable pam_mount, you need to add it to your PAM stack. For example, in /etc/pam.d/system-login, you might add the following lines:

  auth       optional     pam_mount.so
  session    optional     pam_mount.so
The optional keyword means that the module is not required for authentication or session setup. If it fails, the login process can still continue.

Encrypted disks

pam_mount can be used to automatically unlock and mount encrypted disks upon login. This is typically done using the LUKS (Linux Unified Key Setup) mechanism. The user's passphrase is used to unlock the LUKS container.

Example configuration in /etc/security/pam_mount.conf:

  Volume    enc    luks    /dev/sdb1    /home/user/secrets    luks,allow_discards
This will prompt the user for their LUKS passphrase during login and mount the specified device at /home/user/secrets.

Troubleshooting

If you encounter issues with pam_mount, check the following:

  • Ensure the configuration files are correctly formatted.
  • Check system logs (e.g., /var/log/auth.log or using journalctl) for error messages related to pam_mount.
  • Verify that the necessary tools (e.g., mount.cifs for CIFS, nfsstat for NFS) are installed.
  • Test the mount command manually to ensure it works outside of pam_mount.
