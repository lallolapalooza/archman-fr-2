NOM

paclock - verrouiller/déverrouiller la base de données alpm

SYNTAXE

paclock [options]
paclock (--help|--version)

DESCRIPTION

Verrouillage et déverrouillage sécurisés de la base de données ALPM à l'aide de clés d'identité pour les scripts.

OPTIONS

--config=chemin
Définir un chemin de fichier de configuration alternatif.
--lockfile=chemin
Définir un chemin de fichier de verrouillage alternatif.
--root=chemin
Définir une racine d'installation alternative.
--sysroot=chemin
Définir une racine système alternative. Voir pacutils-sysroot(7).
--lock
Verrouiller la base de données (par défaut).
--unlock
Déverrouiller la base de données.
--run
Traiter "argv" comme une commande à exécuter avec la base de données verrouillée. Si la commande retourne une valeur non nulle, le fichier de verrouillage sera laissé en place pour indiquer une erreur, sauf si --fail-ok est utilisé.
--fail-ok
Déverrouiller la base de données après avoir exécuté une commande avec --run, même si la commande retourne une valeur non nulle. Généralement, la base de données doit rester verrouillée si elle risque d'être dans un état incohérent, afin d'indiquer qu'elle pourrait nécessiter une réparation. Cet indicateur est principalement destiné aux opérations en lecture seule.
--print
Écrire le chemin du fichier de verrouillage dans stdout et quitter sans modifier le fichier de verrouillage.
--no-check-keys
Ignorer la vérification de la correspondance de la clé d'identité avant de déverrouiller.
--enoent-ok
Ne pas traiter un fichier de verrouillage inexistant comme une erreur lors du déverrouillage.
--key=identifiant
Un identifiant à écrire dans le fichier de verrouillage. Par défaut, --unlock ne fonctionnera que si le fichier de verrouillage a été précédemment verrouillé avec la même clé. Par défaut, le nom d'hôte suivi d'un deux-points et de l'ID de processus de l'appelant (par exemple : "localhost:123").
--help
Afficher les informations d'utilisation et quitter.
--version
Afficher les informations de version et quitter.

EXEMPLE

La configuration système dont paclock dépend pour construire le chemin du fichier de verrouillage par défaut et la clé d'identité peut changer entre les invocations. Pour garantir la cohérence, les scripts doivent explicitement fournir le chemin et la clé à utiliser à chaque appel de paclock.

#!/bin/bash
lock_file="$(paclock --print)"
lock_key="myapp:$(hostname):$$"
paclock --lockfile="$lock_file" --key="$lock_key" || exit 1
echo "faire des choses ici"
paclock --lockfile="$lock_file" --key="$lock_key" --unlock || exit 1

Exécuter une commande dépourvue de support de verrouillage natif :

paclock --run -- paccache --dryrun --verbose
