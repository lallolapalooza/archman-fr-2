NOM

pam_set_data - définir des données internes au module

SYNOPSIS

#include <security/pam_modules.h>

int pam_set_data(pam_handle_t *pamh, const char *module_data_name, void *data, void (*cleanup)(pam_handle_t *pamh, void *data, int error_status));

DESCRIPTION

La fonction pam_set_data associe un pointeur vers un objet au nom de chaîne (probablement) unique module_data_name dans le contexte PAM spécifié par l'argument pamh.

Les modules PAM peuvent être des objets chargeables dynamiquement. En général, de tels fichiers ne devraient pas contenir de variables statiques. Cette fonction et son homologue pam_get_data(3) fournissent un mécanisme permettant à un module d'associer des données au descripteur pamh. Typiquement, un module appellera la fonction pam_set_data pour enregistrer des données sous un module_data_name (probablement) unique. Les données sont également disponibles pour d'autres modules, mais *pas* pour une application. Comme cette fonction ne stocke qu'un pointeur vers les data, le module ne doit pas modifier ou libérer leur contenu.

La fonction cleanup() est associée aux data et, si elle n'est pas NULL, elle est appelée lorsque ces données sont écrasées ou après un appel à pam_end(3).

L'argument error_status est utilisé pour indiquer au module le type d'action qu'il doit effectuer pour nettoyer cet élément de données. Par exemple, Kerberos crée un fichier de ticket pendant la phase d'authentification ; ce fichier pourrait être associé à un élément de données. Lorsque pam_end(3) est appelé par le module, error_status contient la valeur de retour de pam_authenticate(3) ou d'une autre fonction libpam appropriée. En fonction de cette valeur, le module Kerberos peut choisir de supprimer le fichier de ticket ( *échec d'authentification* ) ou de le laisser en place.

L'argument error_status peut avoir été combiné logiquement avec l'une des deux valeurs suivantes :

PAM_DATA_REPLACE

Lorsqu'un élément de données est remplacé (par un deuxième appel à pam_set_data), ce masque est utilisé. Sinon, l'appel est supposé provenir de pam_end(3).

PAM_DATA_SILENT

Indique que le processus préférerait effectuer le cleanup() silencieusement. C'est-à-dire, cela décourage la journalisation ou l'envoi de messages à l'utilisateur. Il est généralement utilisé pour indiquer que la fermeture actuelle de la bibliothèque se fait dans un processus fork(2)é, et que le processus parent se chargera de nettoyer les éléments qui existent en dehors de l'espace du processus actuel (fichiers, etc.).

VALEURS DE RETOUR

PAM_BUF_ERR

Erreur de tampon mémoire.

PAM_SUCCESS

Les données ont été stockées avec succès.

PAM_SYSTEM_ERR

Un pointeur NULL a été soumis comme descripteur PAM ou la fonction a été appelée par une application.

VOIR AUSSI

pam_end(3), pam_get_data(3), pam_strerror(3)
