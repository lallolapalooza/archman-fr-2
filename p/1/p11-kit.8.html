NOM

p11-kit - Outil pour opérer sur les modules PKCS#11 configurés

SYNTAXE

p11-kit list-modules

p11-kit list-tokens ...

p11-kit list-objects ...

p11-kit import-object ...

p11-kit export-object ...

p11-kit delete-object ...

p11-kit generate-keypair ...

p11-kit list-profiles ...

p11-kit add-profile ...

p11-kit delete-profile ...

p11-kit list-mechanisms ...

p11-kit print-config

p11-kit extract ...

p11-kit server ...

DESCRIPTION

p11-kit est un outil en ligne de commande qui peut être utilisé pour effectuer des opérations sur les modules PKCS#11 configurés sur le système.

Voir les différentes sous-commandes ci-dessous. Les options globales suivantes peuvent être utilisées :

-v, --verbose

Exécuter en mode verbeux avec sortie de débogage.

-q, --quiet

Exécuter en mode silencieux sans messages d'avertissement ou d'échec.

LIST MODULES

Liste les modules PKCS#11 configurés sur le système.

$ p11-kit list-modules

Les modules, les informations à leur sujet et les tokens présents dans les modules PKCS#11 seront affichés.

LIST TOKENS

Liste tous les tokens disponibles dans les modules PKCS#11 configurés sur le système.

$ p11-kit list-tokens pkcs11:token

Ceci récupère tous les tokens et affiche certains de leurs attributs communs.

Cette sous-commande prend les options suivantes :

--only-uris

N'afficher que les URIs des tokens correspondants.

--provider=<chemin_module>

Charger uniquement le module PKCS#11 donné au lieu d'énumérer les modules installés sur le système. Si chemin_module est un chemin relatif, le module est chargé depuis le chemin de module par défaut. Ce chemin peut être déterminé en exécutant : 
$ pkg-config p11-kit-1 --variable p11_module_path
/usr/lib64/pkcs11

LIST OBJECTS

Liste les objets correspondant à l'URI PKCS#11 donnée.

$ p11-kit list-objects pkcs11:object_on_token

Ceci récupère tous les objets qui correspondent à l'URI PKCS#11 donnée et affiche certains de leurs attributs communs. Les objets de stockage affichent également leur URI PKCS#11.

Cette sous-commande prend les options suivantes :

--login

S'authentifier auprès du token avant d'énumérer les objets. La valeur du PIN est lue soit à partir de l'attribut pin-value dans l'URI, soit depuis le terminal.

--provider=<chemin_module>

Charger uniquement le module PKCS#11 donné au lieu d'énumérer les modules installés sur le système. Si chemin_module est un chemin relatif, le module est chargé depuis le chemin de module par défaut. Ce chemin peut être déterminé en exécutant : 
$ pkg-config p11-kit-1 --variable p11_module_path
/usr/lib64/pkcs11

IMPORT OBJECT

Importer un objet dans un token PKCS#11.

$ p11-kit import-object --file=fichier.pem [--label=libellé] [--id=id_objet] pkcs11:token

Prend soit un certificat X.509, soit une clé publique sous forme de fichier PEM et l'importe dans le premier token correspondant à l'URI PKCS#11 donnée.

Les options suivantes sont requises :

--file=<fichier.pem>

Fichier contenant soit un certificat X.509, soit une clé publique au format PEM.

Cette sous-commande accepte également les options suivantes :

--label=<libellé>

Attribue un libellé à l'objet importé.

--id=<id_objet>

Attribue un ID à l'objet importé. L'ID doit être spécifié en format hexadécimal sans le préfixe '0x'.

--login

S'authentifier auprès du token avant d'énumérer les objets. La valeur du PIN est lue soit à partir de l'attribut pin-value dans l'URI, soit depuis le terminal.

--provider=<chemin_module>

Charger uniquement le module PKCS#11 donné au lieu d'énumérer les modules installés sur le système. Si chemin_module est un chemin relatif, le module est chargé depuis le chemin de module par défaut. Ce chemin peut être déterminé en exécutant : 
$ pkg-config p11-kit-1 --variable p11_module_path
/usr/lib64/pkcs11

EXPORT OBJECT

Exporter l'objet correspondant à l'URI PKCS#11.

$ p11-kit export-object pkcs11:object_on_token

Affiche le contenu formaté en PEM du premier objet correspondant à l'URI PKCS#11 donnée. L'objet correspondant doit être soit un certificat X.509, soit une clé publique.

Cette sous-commande prend les options suivantes :

--login

S'authentifier auprès du token avant d'énumérer les objets. La valeur du PIN est lue soit à partir de l'attribut pin-value dans l'URI, soit depuis le terminal.

--provider=<chemin_module>

Charger uniquement le module PKCS#11 donné au lieu d'énumérer les modules installés sur le système. Si chemin_module est un chemin relatif, le module est chargé depuis le chemin de module par défaut. Ce chemin peut être déterminé en exécutant : 
$ pkg-config p11-kit-1 --variable p11_module_path
/usr/lib64/pkcs11

DELETE OBJECT

Supprimer l'objet correspondant à l'URI PKCS#11.

$ p11-kit delete-object pkcs11:object_on_token

Détruit le premier objet correspondant à l'URI PKCS#11 donnée.

Cette sous-commande prend les options suivantes :

--login

S'authentifier auprès du token avant d'énumérer les objets. La valeur du PIN est lue soit à partir de l'attribut pin-value dans l'URI, soit depuis le terminal.

--provider=<chemin_module>

Charger uniquement le module PKCS#11 donné au lieu d'énumérer les modules installés sur le système. Si chemin_module est un chemin relatif, le module est chargé depuis le chemin de module par défaut. Ce chemin peut être déterminé en exécutant : 
$ pkg-config p11-kit-1 --variable p11_module_path
/usr/lib64/pkcs11

GENERATE KEY-PAIR

Générer une paire de clés sur un token PKCS#11.

$ p11-kit generate-keypair --type=algorithme {--bits=n|--curve=nom} [--label=libellé] [--id=id_objet] pkcs11:token

Génère une paire de clés privée-publique du type donné sur le premier token correspondant à l'URI PKCS#11 donnée. Cette commande doit être utilisée en conjonction avec l'option --type et l'une des options --bits ou --curve.

Les options suivantes sont requises :

--type=<algorithme>

Spécifier le type de clés à générer. Les valeurs supportées sont rsa, ecdsa et eddsa.

--bits=<n>

Spécifier le nombre de bits pour la génération de la paire de clés. Ne peut pas être utilisé avec l'option --curve.

--curve=<nom>

Spécifier une courbe elliptique pour la génération de la paire de clés. Les valeurs supportées sont secp256r1, secp384r1, secp521r1, ed25519 et ed448. Ne peut pas être utilisé avec l'option --bits.

Cette sous-commande accepte également les options suivantes :

--label=<libellé>

Attribue un libellé aux objets de la paire de clés générée.

--id=<id_objet>

Attribue un ID aux objets de la paire de clés générée. L'ID doit être spécifié en format hexadécimal sans le préfixe '0x'.

--login

S'authentifier auprès du token avant d'énumérer les objets. La valeur du PIN est lue soit à partir de l'attribut pin-value dans l'URI, soit depuis le terminal.

--provider=<chemin_module>

Charger uniquement le module PKCS#11 donné au lieu d'énumérer les modules installés sur le système. Si chemin_module est un chemin relatif, le module est chargé depuis le chemin de module par défaut. Ce chemin peut être déterminé en exécutant : 
$ pkg-config p11-kit-1 --variable p11_module_path
/usr/lib64/pkcs11

LIST PROFILES

Liste les profils de configuration PKCS#11.

$ p11-kit list-profiles

Les profils sont des fichiers de configuration qui définissent quels modules PKCS#11 doivent être chargés par les applications.

ADD PROFILE

Ajoute un nouveau profil de configuration PKCS#11.

$ p11-kit add-profile /path/to/my/profile.config

Le fichier de configuration spécifié sera ajouté à la liste des profils disponibles.

DELETE PROFILE

Supprime un profil de configuration PKCS#11.

$ p11-kit delete-profile my-profile

Le profil nommé 'my-profile' sera supprimé.

LIST MECHANISMS

Liste les mécanismes supportés par les tokens.

$ p11-kit list-mechanisms pkcs11:token

Affiche les algorithmes cryptographiques supportés par le token spécifié.

Cette sous-commande prend les options suivantes :

--login

S'authentifier auprès du token avant d'énumérer les mécanismes. La valeur du PIN est lue soit à partir de l'attribut pin-value dans l'URI, soit depuis le terminal.

--provider=<chemin_module>

Charger uniquement le module PKCS#11 donné au lieu d'énumérer les modules installés sur le système. Si chemin_module est un chemin relatif, le module est chargé depuis le chemin de module par défaut. Ce chemin peut être déterminé en exécutant : 
$ pkg-config p11-kit-1 --variable p11_module_path
/usr/lib64/pkcs11

PRINT CONFIG

Affiche la configuration actuelle de p11-kit.

$ p11-kit print-config

Ceci inclut la liste des modules chargés et leurs configurations.

EXTRACT

Extrait des informations des modules PKCS#11.

$ p11-kit extract --output=file.txt pkcs11:token

Cette commande peut être utilisée pour extraire des informations détaillées sur les objets et les capacités d'un token.

Les options suivantes sont requises :

--output=<fichier.txt>

Spécifie le fichier de sortie pour les informations extraites.

Cette sous-commande prend les options suivantes :

--login

S'authentifier auprès du token avant d'extraire les informations. La valeur du PIN est lue soit à partir de l'attribut pin-value dans l'URI, soit depuis le terminal.

--provider=<chemin_module>

Charger uniquement le module PKCS#11 donné au lieu d'énumérer les modules installés sur le système. Si chemin_module est un chemin relatif, le module est chargé depuis le chemin de module par défaut. Ce chemin peut être déterminé en exécutant : 
$ pkg-config p11-kit-1 --variable p11_module_path
/usr/lib64/pkcs11

SERVER

Démarre un serveur p11-kit.

$ p11-kit server --config=/etc/p11-kit/server.conf

Le serveur p11-kit permet aux applications distantes d'accéder aux modules PKCS#11 configurés sur le système.

Les options suivantes sont requises :

--config=<fichier.conf>

Spécifie le fichier de configuration du serveur.

ADD PROFILE

Ajouter un profil PKCS#11 à un token.

$ p11-kit add-profile --profile=profil pkcs11:token

Crée un nouvel objet de profil avec l'identifiant de profil donné sur le premier token correspondant à l'URI PKCS#11 donnée. Cette commande échoue si l'identifiant de profil existe déjà sur le token.

Les options suivantes sont requises :

--profile=<profil>

Identifiant du profil à ajouter. La valeur peut être numérique ou textuelle.

Cette sous-commande accepte également les options suivantes :

Les options suivantes sont requises :

Identifiant du profil à supprimer. La valeur peut être numérique ou textuelle.

LIST MECHANISMS

Lister les mécanismes PKCS#11 pris en charge par le token.

$ p11-kit list-mechanisms pkcs11:token

Ceci liste tous les mécanismes disponibles pour un token PKCS#11

PRINT CONFIG

Afficher la configuration fusionnée.

$ p11-kit print-config

P11-kit fournit 3 niveaux de configuration : système, par module et par utilisateur. À l'exécution, les 3 niveaux sont fusionnés en une seule configuration. Cette commande affiche la configuration fusionnée.

EXTRACT

Extraire les certificats des modules PKCS#11 configurés.

Cette opération a été déplacée vers une commande séparée trust extract. Voir

trust(1)
pour plus d'informations

SERVER

Exécuter un processus serveur qui expose le module PKCS#11 à distance.

$ p11-kit server pkcs11:token1 pkcs11:token2 ...
$ p11-kit server --provider /chemin/vers/pkcs11-module.so pkcs11:token1 pkcs11:token2 ...

Ceci lance un serveur qui expose les tokens PKCS#11 donnés sur un socket local. Les tokens doivent appartenir au même module. Pour accéder au socket, utilisez le module p11-kit-client.so. L'adresse du serveur et le PID sont affichés sous forme d'un extrait de script shell qui définit la variable d'environnement appropriée : P11_KIT_SERVER_ADDRESS et P11_KIT_SERVER_PID.

EXTRACT TRUST

Extraire les fichiers d'informations de confiance standard.

Cette opération a été déplacée vers une commande séparée trust extract-compat. Voir trust(1) pour plus d'informations

REMOTE

Exécuter un module PKCS#11 à distance.

$ p11-kit remote /chemin/vers/pkcs11-module.so
$ p11-kit remote pkcs11:token1 pkcs11:token2 ...

Ceci n'est pas destiné à être exécuté directement à partir d'un terminal, mais plutôt dans une option remote d'un fichier pkcs11.conf(5).

Ceci expose le module PKCS#11 ou les tokens donnés sur l'entrée et la sortie standard. Ces deux formes, qu'il s'agisse d'exposer un module ou des tokens, sont mutuellement exclusives et si la seconde forme est utilisée, les tokens doivent appartenir au même module.
