NOM

pflogsumm - Produire un résumé du fichier journal de Postfix MTA

Copyright (C) 1998-2025 par James S. Seymour, Version 1.1.6

SYNTAXE

pflogsumm -[eq] [-d <aujourdhui|hier>] [--detail <nb>]
    [--bounce-detail <nb>] [--deferral-detail <nb>]
    [-h <nb>] [-i|--ignore-case] [--iso-date-time] [--mailq]
    [-m|--uucp-mung] [--no-no-msg-size] [--problems-first]
    [--rej-add-from] [--reject-detail <nb>] [--smtp-detail <nb>]
    [--smtpd-stats] [--smtpd-warning-detail <nb>]
    [--syslog-name=chaine] [-u <nb>] [--verbose-msg-detail]
    [--verp-mung[=<n>]] [--zero-fill] [fichier1 [filen]]
pflogsumm -[help|version]
Si aucun fichier n'est spécifié, lit depuis l'entrée standard. La sortie va vers la sortie standard.

DESCRIPTION

Pflogsumm est un analyseur/résumateur de journaux pour Postfix MTA. Il est
conçu pour fournir une vue d'ensemble de l'activité de Postfix, avec juste
assez de détails pour donner à l'administrateur un "coup d'œil" sur les
points potentiels de problèmes.

Pflogsumm génère des résumés et, dans certains cas, des rapports détaillés sur
les volumes de trafic du serveur de messagerie, les e-mails rejetés et renvoyés,
ainsi que les avertissements, erreurs et pannes du serveur.

OPTIONS

--bounce-detail <nb>
               Limite les rapports détaillés de rebond aux <nb> principaux.
               0 pour supprimer entièrement.
-d aujourdhui   générer le rapport uniquement pour aujourd'hui
-d hier        générer le rapport uniquement pour "hier"
--deferral-detail <nb>
               Limite les rapports détaillés de report aux <nb> principaux.
               0 pour supprimer entièrement.
--detail <nb>

               Définit tous les paramètres --*-detail, -h et -u à <nb>. Est
               écrasé par les paramètres individuels. --detail 0
               supprime TOUS les détails.
-e             détail étendu (extrême ? excessif ?)
               Émet des rapports détaillés. À l'heure actuelle, cela inclut
               seulement un rapport par message, trié par domaine d'expéditeur,
               puis par utilisateur dans le domaine, puis par identifiant de file d'attente.
               ATTENTION : les données construites pour générer ce rapport peuvent
               consommer rapidement de grandes quantités de mémoire si un
               grand nombre d'entrées de journal sont traitées !
-h <nb>       top <nb> à afficher dans les rapports d'hôtes/domaines.

               0 = aucun.
               Voir aussi : options "-u" et "--*-detail" pour d'autres
                         options de limitation de rapport.
--help         Émet un court message d'utilisation et quitte.

               (Par heureuse coïncidence, "-h" seul fait à peu près la même chose,
               car il nécessite un argument numérique :-). Oui, je sais : c'est nul.)
-i
--ignore-case  Traite l'adresse e-mail complète de manière insensible à la casse.

               Normalement, pflogsumm met en minuscules uniquement les parties hôte et
               domaine, laissant la partie utilisateur intacte. Cette option
               force la mise en minuscules de l'adresse e-mail entière.
--iso-date-time
               Pour les résumés contenant des informations de date ou d'heure,
               utilise les formats standards ISO 8601 (AAAA-MM-JJ et HH:MM),
               plutôt que "Lun JJ AAAA" et "HHMM".
-m             modifier (altérer ?) les chemins UUCP (bang-paths)
--uucp-mung
               Ceci est destiné à être utilisé lorsque vous avez un mélange d'adresses de style domaine
               Internet et de chemins UUCP (bang-paths) dans le journal.
               Les flux UUCP en amont modifient parfois les adresses de style domaine Internet
               en chemins (bang-paths). Cette option peut
               parfois annuler les "dommages". Par exemple :
               "somehost.dom!username@foo" (où "foo" est l'hôte amont suivant et
               "somehost.dom" était l'origine de l'e-mail) sera converti en
               "foo!username@somehost.dom". Cela affecte également le
               rapport de détail étendu (-e), pour aider à garantir que le tri
               par domaine et par nom est plus précis.
--mailq        Exécute la commande "mailq" à la fin du rapport.

               Simplement une fonctionnalité pratique. (Suppose que "mailq"
               est dans $PATH. Voir la variable "$mailqCmd" pour définir ce chemin
               si désiré.)
--no_bounce_detail
--no_deferral_detail
--no_reject_detail
               Ces commutateurs sont dépréciés au profit de
               --bounce-detail, --deferral-detail et
               --reject-detail, respectivement.
               Supprime l'impression des rapports détaillés suivants, respectivement :
                    détail des rebonds de messages (par relais)
                    détail des reports de messages
                    détail des rejets de messages
               Voir aussi : options "-u" et "-h" pour d'autres
                         options de limitation de rapport.
--no-no-msg-size
                Ne pas émettre de rapport sur les "Messages sans données de taille".
                La taille du message n'est signalée que par le gestionnaire de file d'attente.
                Le message peut être livré suffisamment longtemps après la
                (dernière) entrée de journal qmgr que l'information ne figure pas
                dans le(s) journal(aux) traité(s) par une exécution particulière de
                pflogsumm. Cela fausse le rapport "Destinataires par taille de message"
                et le total de "octets livrés". Ceux-ci sont normalement signalés
                par pflogsumm sous le nom de "Messages sans données de taille".
--no-smtpd-warnings
               Ce commutateur est déprécié au profit de
               smtpd-warning-detail
                Sur un serveur de messagerie très actif, par exemple chez un FAI, les avertissements
                SMTPD peuvent générer un rapport assez volumineux. Cette option
                désactive leur signalement.
--problems-first
               Émet les rapports de "problèmes" (rebonds, reports, avertissements,
               etc.) avant les statistiques "normales".
--rej-add-from
               Pour les rapports de rejet qui listent des adresses IP ou des noms d'hôtes/domaines :
               ajoute l'adresse e-mail de l'expéditeur à chaque liste. (Ne s'applique pas
               au rapport "Utilisation inappropriée du pipelining de commande SMTP".)
-q             silencieux - n'imprime pas d'en-têtes pour les rapports vides

               note : les en-têtes pour les messages d'avertissement, fatals et "master"
               seront toujours imprimés.
--reject-detail <nb>
               Limite les rapports détaillés de rejet, d'avertissement, de mise en attente et de rejet
               de smtpd aux <nb> principaux. 0 pour supprimer entièrement.
--smtp-detail <nb>
               Limite les rapports détaillés de livraison SMTP aux <nb> principaux.
               0 pour supprimer entièrement.
--smtpd-stats
               Génère des statistiques de connexion smtpd.
               Le rapport "par jour" n'est pas généré pour les rapports d'un seul jour.
               Pour les rapports sur plusieurs jours : les chiffres "par heure" sont des moyennes journalières
               (reflétées dans l'en-tête du rapport).
--smtpd-warning-detail <nb>
               Limite les rapports détaillés d'avertissements smtpd aux <nb> principaux.
               0 pour supprimer entièrement.
--syslog-name=nom
               Définit le nom syslog à rechercher pour les entrées de journal Postfix.
               Par défaut, pflogsumm recherche des entrées dans les fichiers journaux
               avec un nom syslog de "postfix", le défaut.
               Si vous avez défini un paramètre "syslog_name" non par défaut
               dans votre configuration Postfix, utilisez cette option pour
               indiquer à pflogsumm quel est ce nom.
               Voir la discussion sur l'utilisation de cette option sous
               "NOTES", ci-dessous.
-u <nb>       top <nb> à afficher dans les rapports d'utilisateurs. 0 == aucun.
               Voir aussi : options "-h" et "--*-detail" pour d'autres
                         options de limitation de rapport.
--verbose-msg-detail
               Pour les résumés de report, de rebond et de rejet de messages :
               affiche la "raison" complète, plutôt qu'une raison tronquée.
               Note : cela peut entraîner des lignes très longues dans le rapport.
--verp-mung    effectue le traitement spécial des adresses générées par "VERP" (?)
--verp-mung=2  adresses de l'expéditeur de la forme
               "list-return-NN-someuser=some.dom@host.sender.dom"
                à
                  "list-return-ID-someuser=some.dom@host.sender.dom"
                En d'autres termes : remplace la valeur numérique par "ID".
               En spécifiant le "=2" optionnel (deuxième forme), le
               traitement est plus "agressif", convertissant l'adresse
               en quelque chose comme :
                    "list-return@host.sender.dom"
               En fait : spécifier quoi que ce soit de moins que 2 effectue le
               traitement "simple" et spécifier quoi que ce soit de plus que 1 applique
               le hack plus "agressif".
               Voir "NOTES" concernant cette option.
--version      Imprime le nom du programme et la version et quitte.
--zero-fill    "Remplit de zéros" certains tableaux afin que les rapports s'affichent avec
               des données dans des colonnes qui pourraient autrement être vides.

VALEUR DE RETOUR

Pflogsumm ne retourne rien d'intéressant au shell.

ERREURS

Les messages d'erreur sont émis sur stderr.

EXEMPLES

Produire un rapport des activités de la veille :
    pflogsumm -d yesterday /var/log/maillog
Un rapport des activités de la semaine précédente (après rotation des logs) :
    pflogsumm /var/log/maillog.0
Ce qui s'est passé aujourd'hui :
    pflogsumm -d today /var/log/maillog
Entrée Crontab pour générer un rapport de l'activité de la veille
à 10 minutes après minuit.
    10 0 * * * /usr/local/sbin/pflogsumm -d yesterday /var/log/maillog
    2>&1 |/usr/bin/mailx -s ""`uname -n` stats mail journalières"" postmaster
Entrée Crontab pour générer un rapport de l'activité de la semaine précédente.
(Cet exemple suppose une rotation des logs mail hebdomadaire, un peu avant
4h10 du dimanche matin.)
    10 4 * * 0   /usr/local/sbin/pflogsumm /var/log/maillog.0
    2>&1 |/usr/bin/mailx -s ""`uname -n` stats mail hebdomadaires"" postmaster
Les deux exemples de crontab, ci-dessus, doivent en réalité être une seule ligne
chacun. Ils sont divisés en deux lignes ou plus en raison de problèmes de
formatage de page.

NOTES

Pflogsumm ne tente pas de capturer/analyser les entrées de log non-Postfix.
À moins qu'il n'y ait "postfix/" dans l'entrée de log, elle sera ignorée.
Il est important que les logs soient présentés à pflogsumm dans un ordre
chronologique afin que les tailles de messages soient disponibles quand nécessaire.
À des fins d'affichage : les valeurs entières sont converties en notation "kilo"
et "méga" lorsqu'elles dépassent certaines valeurs. J'ai choisi les limites
certes arbitraires de 512k et 512m comme points de bascule - pensant que 512x
était le plus grand nombre (de chiffres) que la plupart des gens peuvent
comprendre confortablement d'un coup d'œil.
Ce sont des "k" et "m" d'"ordinateur", pas 1000 et 1 000 000. Vous pouvez
facilement changer tout cela avec quelques constantes près du début du programme.
Les rapports "Éléments-par-jour" ne sont pas générés pour les rapports d'une seule
journée. Pour les rapports de plusieurs jours : les nombres "Éléments-par-heure"
sont des moyennes journalières (reflétées dans les titres des rapports).
Les rejets de messages, les avertissements de rejet, les mises en attente et les
rejets sont tous rapportés sous la colonne "rejets" pour les résumés de trafic
Par-Heure et Par-Jour.
Le traitement VERP peut ne pas toujours aboutir à une adresse correcte et à une
réduction du nombre d'adresses.
Le traitement VERP est toujours en état d'expérimentation. L'utilisation de cette
option peut entraîner des statistiques inexactes concernant le décompte des
"expéditeurs".
La gestion des chemins "bang" de style UUCP nécessite plus de travail. Particulièrement
si Postfix n'est pas exécuté avec "swap_bangpath = yes" et/ou *est* exécuté avec
"append_dot_mydomain = yes", le rapport détaillé par message peut ne pas être trié
correctement par domaine par utilisateur. (Cela dépend aussi du MTA amont, je pense.)
Les chiffres "pourcentage rejeté" et "pourcentage rejeté" ne sont que des
approximations. Ils sont calculés comme suit (exemple pour "pourcentage rejeté") :
    pourcentage rejeté =

        (rejeté / (livré + rejeté + abandonné)) * 100
Il y a quelques problèmes avec l'utilisation de --syslog-name. Le problème est
que, même avec $syslog_name de Postfix défini, il enregistrera parfois toujours
des choses avec "postfix" comme syslog_name. Ceci est noté dans
/etc/postfix/sample-misc.cf :
    # Attention : un réglage non par défaut de syslog_name prend effet seulement
    # après l'initialisation du processus. Certaines erreurs d'initialisation seront
    # enregistrées avec le nom par défaut, en particulier les erreurs lors de l'analyse
    # de la ligne de commande et les erreurs lors de l'accès au fichier de configuration
    # principal de Postfix (main.cf).
Par conséquent, pflogsumm doit toujours rechercher "postfix," dans les logs,
ainsi que tout ce qui est fourni pour syslog_name.
Là où cela devient un problème, c'est lorsque les gens exécutent deux instances
ou plus de Postfix, enregistrant dans le même fichier. Dans un tel cas :
    . Aucune des instances ne peut utiliser le nom syslog par défaut "postfix"
      et...
    . Les entrées de log qui tombent victimes de ce qui est décrit dans
      sample-misc.cf seront rapportées sous "postfix", donc si
      vous exécutez pflogsumm deux fois, une fois pour chaque syslog_name, ces
      entrées de log apparaîtront dans chaque rapport.
La page d'accueil de PflogSum est disponible à l'adresse :
    http://jimsun.LinxNet.com/postfix_contrib.html

EXIGENCES

Pour certaines options (par ex. : --smtpd-stats), Pflogsumm nécessite le
module Date::Calc, qui peut être obtenu depuis CPAN à l'adresse
http://www.perl.com.
Pflogsumm est actuellement écrit et testé sous Perl 5.8.3.
Depuis la version 19990413-02, pflogsumm fonctionnait avec Perl 5.003, mais
la compatibilité future n'est pas garantie.
