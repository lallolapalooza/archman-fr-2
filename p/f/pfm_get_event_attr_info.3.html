pfm_get_event_attr_info(3)

Paquet: libpfm

Licences: MIT

LIBPFM(3) Manuel du programmeur Linux LIBPFM(3)

NOM

pfm_get_event_attr_info - obtenir des informations sur les attributs d'événement

SYNTAXE

#include <perfmon/pfmlib.h>

int pfm_get_event_attr_info(int idx, int attr, pfm_os_t os, pfm_event_attr_info_t *info);

DESCRIPTION

Cette fonction renvoie dans info des informations sur l'attribut désigné par attr pour l'événement spécifié par idx et la couche système d'exploitation os.

L'énumération pfm_os_t offre les choix suivants :

PFM_OS_NONE
Les informations renvoyées concernent uniquement ce que le matériel PMU exporte. Aucun attribut du système d'exploitation n'est pris en compte.
PFM_OS_PERF_EVENT
Les informations renvoyées incluent le matériel PMU réel et les attributs supplémentaires exportés par l'interface noyau perf_events. Les attributs perf_events concernent uniquement le matériel PMU. Si perf_events n'est pas détecté, une erreur est renvoyée.
PFM_OS_PERF_EVENT_EXT
Les informations renvoyées incluent tout ce qui est déjà fourni par PFM_OS_PERF_EVENT, plus tous les attributs logiciels contrôlés par perf_events, tels que la période d'échantillonnage, l'échantillonnage précis.

La structure pfm_event_attr_info_t est définie comme suit :

typedef struct {
        const char              *name;
        const char              *desc;
        const char              *equiv;
        size_t			size;
        uint64_t                code;
        pfm_attr_t              type;
        int                     idx;
        pfm_attr_ctrl_t         ctrl;
        int                     reserved1;
        struct {
                int             is_dfl:1;
                int             is_precise:1;
                int             is_speculative:2;
		int		support_hw_smpl:1;
		int		support_no_mods:1;
                int             reserved:26;
        };
        union {
                uint64_t        dfl_val64;
                const char      *dfl_str;
                int             dfl_bool;
                int             dfl_int;
        };
} pfm_event_attr_info_t;

Les champs de cette structure sont définis comme suit :

name
C'est le nom de l'attribut. Il s'agit d'une chaîne en lecture seule.
desc
C'est la description de l'attribut. Il s'agit d'une chaîne en lecture seule. Elle peut contenir plusieurs phrases.
equiv
Certains attributs peuvent être simplement des variations d'autres attributs pour le même événement. Ils peuvent être fournis comme raccourcis pratiques pour éviter de fournir une longue liste d'attributs. Pour ces attributs, ce champ n'est pas NULL et contient la chaîne d'attribut équivalente complète. Cette chaîne, une fois ajoutée au nom de l'événement, peut être utilisée dans les appels de bibliothèque nécessitant une chaîne d'événement.
code
C'est le code brut de l'attribut. Pour PFM_ATTR_UMASK, il s'agit du code du masque d'unité. Pour tous les autres attributs, il s'agit d'un index opaque.
type
C'est le type de l'attribut. Les attributs représentent soit des sous-événements, soit des filtres supplémentaires qui peuvent être appliqués à l'événement. Les filtres (également appelés modificateurs) peuvent être liés à l'événement ou au registre PMU dans lequel l'événement est programmé. Le type d'un attribut détermine comment il doit être spécifié. Les types suivants sont définis :
PFM_ATTR_UMASK
C'est un masque d'unité, c'est-à-dire un sous-événement. Il est spécifié en utilisant son nom. Selon l'événement, il peut être possible de spécifier plusieurs masques d'unité.
PFM_ATTR_MOD_BOOL
C'est un attribut booléen. Il a une valeur de 0, 1, y ou n. La valeur est spécifiée après le signe égal, par exemple, foo=1. Par commodité, le signe égal et la valeur peuvent être omis, auquel cas cela équivaut à =1.
PFM_ATTR_MOD_INTEGER
C'est un attribut entier. Il a une valeur qui doit être passée après le signe égal. La plage des valeurs valides dépend de l'attribut et est généralement spécifiée dans sa description.
idx
C'est l'index de l'attribut. Il est identique à la valeur de attr passée à l'appel et est fourni pour plus de complétude.
size
Ce champ contient la taille de la structure passée. Ce champ est utilisé pour permettre l'extensibilité de la structure sans compromettre la compatibilité ascendante. La valeur doit être définie à sizeof(pfm_event_attr_info_t). Si, au lieu de cela, une valeur de 0 est spécifiée, la bibliothèque suppose que la structure passée est identique à la première version de l'ABI dont la taille est PFM_ATTR_INFO_ABI0. Ainsi, si des champs ont été ajoutés après la première ABI, ils ne seront pas définis par la bibliothèque. La bibliothèque vérifie que les octets au-delà de ce qui est implémenté sont des zéros.
is_dfl
Ce champ indique si cet attribut est défini par défaut. Ceci s'applique principalement à PFM_ATTR_UMASK. Si un masque d'unité est marqué comme par défaut, et qu'aucun masque d'unité n'est spécifié dans la chaîne de l'événement, alors la bibliothèque l'utilise par défaut. Notez qu'il peut y avoir plusieurs valeurs par défaut par événement en fonction de la façon dont les masques d'unité sont regroupés.
is_precise
Ce champ indique si ce masque d'unité prend en charge l'échantillonnage précis. L'échantillonnage précis est un mécanisme matériel qui évite le glissement d'adresse d'instruction lors de l'utilisation de l'échantillonnage basé sur interruption. Sur les processeurs Intel X86, ce champ indique que le masque d'unité prend en charge l'échantillonnage basé sur événement précis (PEBS).
is_speculative
Ce champ de bits indique si l'attribut inclut ou non les occurrences se produisant pendant l'exécution spéculative, à la fois pour les chemins corrects et incorrects. Étant donné que ce type d'information d'événement n'est pas toujours disponible auprès des fournisseurs, ce champ utilise plusieurs bits. Une valeur de PFM_EVENT_INFO_SPEC_NA indique que les informations de spéculation ne sont pas disponibles. Une valeur de PFM_EVENT_INFO_SPEC_TRUE indique que l'attribut compte pendant l'exécution spéculative. Une valeur de PFM_EVENT_INFO_SPEC_FALSE indique que l'attribut ne compte pas pendant l'exécution spéculative.
support_hw_smpl
Ce champ booléen indique que l'attribut (dans ce cas, un masque d'unité) prend en charge l'échantillonnage matériel. Cela signifie que le matériel peut échantillonner cet événement+masques d'unité sans impliquer le noyau à chaque échantillon.
support_no_mods
Ce champ booléen indique que l'attribut (dans ce cas, un masque d'unité) ne prend en charge aucun modificateur matériel ou logiciel, tels que les filtres de niveau de privilège, l'échantillonnage, l'échantillonnage précis, etc. Ceci est nécessaire lorsque certains masques d'unité d'un événement ont plus de restrictions que d'autres, par exemple, l'événement et la plupart des masques d'unité prennent en charge les modificateurs, à l'exception de quelques masques d'unité.
dfl_val64, dfl_str, dfl_bool, dfl_int
Cette union contient la valeur d'un attribut. Pour PFM_ATTR_UMASK, il s'agit du code du masque d'unité, pour tous les autres types, il s'agit de la valeur réelle de l'attribut.
ctrl
Ce champ indique quelle couche ou quelle source contrôle l'attribut. Les sources suivantes sont définies :
PFM_ATTR_CTRL_UNKNOWN
La source contrôlant l'attribut n'est pas connue.
PFM_ATTR_CTRL_PMU
L'attribut est contrôlé par le matériel PMU.
PFM_ATTR_CTRL_PERF_EVENT
L'attribut est contrôlé par l'interface noyau perf_events.
réservé
Ces champs doivent être mis à zéro.

RETOUR

En cas de succès, la fonction renvoie PFM_SUCCESS et les informations sur les attributs dans info, sinon elle renvoie un code d'erreur.

ERREURS

PFMLIB_ERR_NOINIT
La bibliothèque n'a pas été initialisée correctement.
PFMLIB_ERR_INVAL
Les arguments idx ou attr sont invalides, ou info est NULL, ou size n'est pas zéro.
PFM_ERR_NOTSUPP
La couche système d'exploitation demandée n'a pas été détectée sur le système hôte.
