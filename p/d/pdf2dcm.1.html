NOM

pdf2dcm - Encapsuler un fichier PDF dans un fichier DICOM

SYNTAXE

pdf2dcm [options] fichier-pdf-entree fichier-dicom-sortie

DESCRIPTION

L'utilitaire pdf2dcm lit un fichier PDF (fichier-pdf-entree), le convertit en une instance SOP DICOM Encapsulated PDF Storage et stocke les données converties dans un fichier de sortie (fichier-dicom-sortie).

PARAMETRES

fichier-pdf-entree   Nom du fichier PDF d'entrée à encapsuler
fichier-dicom-sortie Nom du fichier DICOM de sortie ("-" pour stdout)

OPTIONS

options générales

  -h   --help
         afficher ce texte d'aide et quitter
       --version
         afficher les informations de version et quitter
       --arguments
         afficher les arguments de la ligne de commande développés
  -q   --quiet
         mode silencieux, n'afficher aucun avertissement ni erreur
  -v   --verbose
         mode verbeux, afficher les détails du traitement
  -d   --debug
         mode débogage, afficher les informations de débogage
  -ll  --log-level  [n]iveau: chaîne constante
         (fatal, error, warn, info, debug, trace)
         utiliser le niveau n pour le logger
  -lc  --log-config  [f]ichier: chaîne
         utiliser le fichier de configuration f pour le logger

options document DICOM

titre du document :
  +t   --title  [t]itre: chaîne (par défaut : vide)
         titre du document
  +cn  --concept-name  [CSD] [CV] [CM]: chaîne (par défaut : vide)
         représentation codée du titre du document définie par le
         sélecteur de schéma de codage CSD, la valeur de code CV et le sens de code CM
données du patient :
  +pn  --patient-name  [n]om: chaîne
         nom du patient au format syntaxique PN DICOM
  +pi  --patient-id  [i]d: chaîne
         identifiant du patient
  +pb  --patient-birthdate  [d]ate: chaîne (YYYYMMDD)
         date de naissance du patient
  +ps  --patient-sex  [s]exe: chaîne (M, F ou O)
         sexe du patient
étude et série :
  +sg  --generate
         générer de nouveaux UID d'étude et de série (par défaut)
  +st  --study-from  [f]ichier: chaîne
         lire les données du patient/étude depuis un fichier DICOM
  +se  --series-from  [f]ichier: chaîne
         lire les données du patient/étude/série depuis un fichier DICOM
numéro d'instance :
  +i1  --instance-one
         utiliser le numéro d'instance 1 (par défaut, pas avec +se)
  +ii  --instance-inc
         incrémenter le numéro d'instance (uniquement avec +se)
  +is  --instance-set [i]d'instance: entier
         utiliser le numéro d'instance i
annotation intégrée :
  +an  --annotation-yes
         le document contient des données d'identification du patient (par défaut)
  -an  --annotation-no
         le document ne contient pas de données d'identification du patient

options de traitement

autres options de traitement :
  -k   --key  [c]lé: gggg,eeee="str", chemin ou nom_dictionnaire="str"
         ajouter un attribut supplémentaire

options de sortie

format du fichier de sortie :
  +F   --write-file
         format de fichier d'écriture (par défaut)
  -F   --write-dataset
         écrire le jeu de données sans méta-informations de fichier
 encodage de la longueur de groupe :
  +g=  --group-length-recalc
         recalculer les longueurs de groupe si présentes (par défaut)
  +g   --group-length-create
         écrire toujours avec des éléments de longueur de groupe
  -g   --group-length-remove
         écrire toujours sans éléments de longueur de groupe
 encodage de la longueur dans les séquences et les éléments :
  +e   --length-explicit
         écrire avec des longueurs explicites (par défaut)
  -e   --length-undefined
         écrire avec des longueurs indéfinies
 remplissage des données de jeu de données (pas avec --write-dataset) :
  -p   --padding-off
         pas de remplissage (implicite avec --write-dataset)
  +p   --padding-create  [p]ad-fichier [p]ad-élément: entier
         aligner le fichier sur un multiple de f octets
         et les éléments sur un multiple de i octets

NOTES

Sources des attributs

L'application peut être alimentée avec des entrées supplémentaires pour remplir les attributs obligatoires (et optionnels) dans le nouveau fichier DICOM, comme les informations du patient, de l'étude et de la série :

  • L'option --key peut être utilisée pour ajouter des attributs supplémentaires au fichier DICOM de sortie.
  • Il est également possible de spécifier des séquences, des éléments et des attributs imbriqués en utilisant l'option --key. Dans ces cas, une notation spéciale de "chemin" doit être utilisée. Les détails sur cette notation de chemin se trouvent dans la documentation de dcmodify.
  • L'option --key peut être présente plusieurs fois.
  • La partie valeur (après le '=') peut être absente, ce qui entraîne la définition de l'attribut avec une longueur nulle.
  • Veuillez noter que l'option --key est appliquée à la toute fin, juste avant d'enregistrer le fichier DICOM, il n'y a donc aucune vérification de valeur.

JOURNALISATION

Le niveau de sortie de journalisation des différents outils en ligne de commande et des bibliothèques sous-jacentes peut être spécifié par l'utilisateur. Par défaut, seules les erreurs et les avertissements sont écrits dans le flux d'erreur standard. En utilisant l'option --verbose, des messages informationnels comme les détails du traitement sont également signalés. L'option --debug peut être utilisée pour obtenir plus de détails sur l'activité interne, par exemple à des fins de débogage. D'autres niveaux de journalisation peuvent être sélectionnés à l'aide de l'option --log-level. En mode --quiet, seuls les erreurs fatales sont signalées. En cas d'événements d'erreur très graves, l'application se terminera généralement. Pour plus de détails sur les différents niveaux de journalisation, voir la documentation du module "oflog".

Si la sortie de journalisation doit être écrite dans un fichier (éventuellement avec rotation de fichier journal), vers syslog (Unix) ou le journal des événements (Windows), l'option --log-config peut être utilisée. Ce fichier de configuration permet également de diriger uniquement certains messages vers un flux de sortie particulier et de filtrer certains messages en fonction du module ou de l'application où ils sont générés. Un exemple de fichier de configuration est fourni dans <etcdir>/logger.cfg.

LIGNE DE COMMANDE

Tous les outils en ligne de commande utilisent la notation suivante pour les paramètres : les crochets indiquent les valeurs optionnelles (0-1), trois points de suspension indiquent que plusieurs valeurs sont autorisées (1-n), une combinaison des deux signifie 0 à n valeurs.

Les options de ligne de commande se distinguent des paramètres par un signe '+' ou '-' respectivement. Habituellement, l'ordre et la position des options de ligne de commande sont arbitraires (c'est-à-dire qu'elles peuvent apparaître n'importe où). Cependant, si des options sont mutuellement exclusives, l'apparence la plus à droite est utilisée. Ce comportement est conforme aux règles d'évaluation standard des shells Unix courants.

De plus, un ou plusieurs fichiers de commande peuvent être spécifiés en utilisant le signe '@' comme préfixe du nom de fichier (par exemple, @commande.txt). Un tel argument de commande est remplacé par le contenu du fichier texte correspondant (plusieurs espaces blancs sont traités comme un seul séparateur sauf s'ils apparaissent entre deux guillemets) avant toute autre évaluation. Veuillez noter qu'un fichier de commande ne peut pas contenir un autre fichier de commande. Cette approche simple mais efficace permet de résumer des combinaisons courantes d'options/paramètres et évite des lignes de commande longues et confuses (un exemple est fourni dans le fichier <datadir>/dumppat.txt).

CODES DE SORTIE

L'utilitaire pdf2dcm utilise les codes de sortie suivants lors de sa terminaison. Cela permet à l'utilisateur de vérifier la raison pour laquelle l'application s'est terminée.

général

EXITCODE_NO_ERROR                 0
EXITCODE_COMMANDLINE_SYNTAX_ERROR 1
EXITCODE_MEMORY_EXHAUSTED         4

erreurs fichiers entrée

EXITCODE_CANNOT_READ_INPUT_FILE   20
EXITCODE_NO_INPUT_FILES           21
EXITCODE_INVALID_INPUT_FILE       22

erreurs fichiers sortie

EXITCODE_CANNOT_WRITE_OUTPUT_FILE 40

ENVIRONNEMENT

L'utilitaire pdf2dcm tentera de charger les dictionnaires de données DICOM spécifiés dans la variable d'environnement DCMDICTPATH

riable. Par défaut, c'est-à-dire si la variable d'environnement DCMDICTPATH n'est pas définie, le fichier <datadir>/dicom.dic sera chargé à moins que le dictionnaire ne soit intégré à l'application (par défaut pour Windows).

Le comportement par défaut doit être préféré et la variable d'environnement DCMDICTPATH ne doit être utilisée que lorsque des dictionnaires de données alternatifs sont requis. La variable d'environnement DCMDICTPATH a le même format que la variable PATH de la shell Unix, en ce sens qu'un deux-points (":") sépare les entrées. Sur les systèmes Windows, un point-virgule (";") est utilisé comme séparateur. Le code du dictionnaire de données tentera de charger chaque fichier spécifié dans la variable d'environnement DCMDICTPATH. Une erreur se produit si aucun dictionnaire de données ne peut être chargé.
