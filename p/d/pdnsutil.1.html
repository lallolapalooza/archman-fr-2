NOM

pdnsutil - Contrôle et gestion des enregistrements et DNSSEC de PowerDNS

SYNTAXE

pdnsutil [OPTION]... COMMANDE

DESCRIPTION

pdnsutil (anciennement pdnssec) est une commande puissante qui sert de passerelle conviviale pour le gestionnaire vers DNSSEC et la gestion des zones pour PowerDNS. En arrière-plan, pdnsutil manipule une base de données backend PowerDNS, ce qui signifie également que pour de nombreuses bases de données, pdnsutil peut être exécuté à distance et peut configurer du matériel de clé sur différents serveurs.

OPTIONS

-h, --help
Afficher le résumé des options
-v, --verbose
Être plus verbeux
-f, --force
Forcer une action
-q, --quiet
Être silencieux
--config-name <NOM>
Nom de configuration virtuel
--config-dir <RÉPERTOIRE>
Emplacement de pdns.conf. Le défaut est /etc/powerdns.

COMMANDES

Il existe de nombreuses commandes disponibles. La plupart des commandes suivent le modèle pdnsutil <objet> <action> [arguments...], où <objet> est un nom et <action> est un verbe ; quelques commandes qui ne s'appliquent à aucun type d'objet particulier n'utilisent que le verbe.

COMMANDES AUTOPRIMARY

autoprimary add IP NOMSERVEUR [COMPTE]

Ajoute une entrée autoprimary dans le backend. Ceci permet de recevoir les mises à jour de zone d'autres serveurs.

autoprimary list

Liste toutes les autoprimary.

autoprimary remove IP NOMSERVEUR

Supprime une autoprimary du backend. Non pris en charge par le backend BIND.

COMMANDES ZONE CATALOGUE

catalog list-members CATALOGUE

Liste tous les membres de la zone catalogue CATALOGUE.

catalog set ZONE [CATALOGUE]

Change le catalogue de ZONE à CATALOGUE. Si CATALOGUE est omis, supprime ZONE du catalogue dans lequel elle se trouve.

COMMANDES METADONNEES ZONE

metadata add ZONE TYPE VALEUR [VALEUR]...

Ajoute VALEUR aux métadonnées existantes de TYPE pour ZONE. Renverra une erreur si TYPE ne supporte pas plusieurs valeurs, utilisez metadata set pour ces valeurs.

metadata get ZONE [TYPE]...

Obtient les métadonnées de la zone. Si aucun TYPE n'est donné, liste tous les types connus.

metadata set ZONE TYPE [VALEUR]...

Définit le TYPE de métadonnées de zone pour ZONE à VALEUR, remplaçant toutes les valeurs existantes de TYPE. Une valeur omise la supprime.

COMMANDES RESEAU

network list

Liste tous les réseaux définis avec leurs vues choisies.

network set RESEAU [VUE]

Définit la VUE pour le réseau RESEAU, ou la supprime s'il n'y a pas d'argument VUE.

COMMANDES ENREGISTREMENTS ZONE

Dans ces commandes, le nom de l'objet rrset peut aussi être écrit record.

rrset add ZONE NOM TYPE [TTL] CONTENU

Ajoute un ou plusieurs enregistrements de NOM et TYPE à ZONE avec CONTENU et TTL optionnel. Si TTL n'est pas défini, le default-ttl configuré sera utilisé. NOM doit être absolu.

rrset delete ZONE NOM TYPE

Supprime un RRSET nommé de la zone. NOM doit être absolu.

rrset hash ZONE RNAME

Cette commande de commodité hache le nom RNAME conformément aux paramètres NSEC3 de la ZONE. Refuse de hacher pour les zones sans paramètres NSEC3.

rrset replace ZONE NOM TYPE [TTL] CONTENU [CONTENU...]

Remplace un NOM existant dans la zone ZONE par un nouvel ensemble.

COMMANDES LIEES A TSIG

Ces commandes manipulent les informations de clé TSIG dans la base de données. Certaines commandes nécessitent un ALGORITHME, qui peut être l'un des suivants :

  • hmac-md5
  • hmac-sha1
  • hmac-sha224
  • hmac-sha256
  • hmac-sha384
  • hmac-sha512

tsigkey activate ZONE NOM {primary,secondary,producer,consumer}

Active AXFR authentifié par TSIG en utilisant la clé NOM pour la zone ZONE. Ceci définit les métadonnées de zone TSIG-ALLOW-AXFR (primaire/producteur) ou AXFR-MASTER-TSIG (secondaire/consommateur).

tsigkey deactivate ZONE NOM {primary,secondary,producer,consumer}

Désactive AXFR authentifié par TSIG en utilisant la clé NOM pour la zone ZONE.

tsigkey delete NOM

Supprime la clé TSIG NOM. Attention : cela ne désactive pas la clé concernée.

tsigkey generate NOM ALGORITHME

Génère une nouvelle clé TSIG avec le nom NOM et l'algorithme spécifié.

tsigkey import NOM ALGORITHME CLE

Importe la CLE de l'algorithme spécifié en tant que NOM.

tsigkey list

Affiche une liste de toutes les clés TSIG configurées.

COMMANDES VUES

views add-zone VUE ZONE..VARIANT

Ajoute la ZONE VARIANT donnée à une VUE.

views del-zone VUE ZONE..VARIANT

Supprime une ZONE VARIANT d'une VUE.

views list VUE

Liste toutes les zones au sein de la VUE.

views list-all

Liste tous les noms de vues.

COMMANDES MANIPULATION ZONE

zone check ZONE

Vérifie la zone ZONE pour l'exactitude.

zone check-all [exit-on-error]

Vérifie toutes les zones pour l'exactitude, s'arrêtant en cas de première erreur trouvée dans une zone si "exit-on-error" est spécifié.

zone clear ZONE

Efface les enregistrements dans la zone ZONE, mais laisse la zone réelle et ses paramètres inchangés.

zone create ZONE

Crée
ate une zone vide nommée ZONE.

zone delete ZONE

Supprime la zone nommée ZONE.

zone edit ZONE

Ouvre ZONE au format zonefile (quel que soit le backend à partir duquel elle a été chargée) dans l'éditeur défini dans la variable d'environnement EDITOR. Si EDITOR est vide, pdnsutil utilise par défaut editor.

zone increase-serial ZONE

Incrémente le SOA-serial de 1. Utilise SOA-EDIT.

zone list ZONE

Affiche tous les enregistrements pour ZONE.

zone list-all KIND

Liste tous les noms de zones actives du type KIND donné (primaire, secondaire, natif, producteur, consommateur), ou toutes si aucune n'est spécifiée. L'option --verbose ou -v affichera également les zones désactivées ou vides.

zone load ZONE FILE

Charge les enregistrements pour ZONE depuis FILE. Si ZONE existe déjà, tous les enregistrements sont écrasés, cette opération est atomique. Si ZONE n'existe pas, elle est créée.

zone set-account ZONE ACCOUNT

Change le compte (propriétaire) de ZONE à ACCOUNT.

zone set-kind ZONE KIND

Change le type de ZONE à KIND (primaire, secondaire, natif, producteur, consommateur).

zone set-option ZONE [producer | consumer] [coo | unique | group] VALUE [VALUE ...]

Définit ou supprime une option pour ZONE. Fournir une valeur vide supprime une option.

zone set-options-json ZONE JSONFILE

Change les options de ZONE au contenu de JSONFILE.

zone zonemd-verify-file ZONE FILE

Valide le ZONEMD pour ZONE lu depuis FILE.

COMMANDES DE ZONE SECONDAIRE

zone change-primary ZONE PRIMARY [PRIMARY]...

Change les serveurs primaires de la zone secondaire ZONE aux nouveaux serveurs primaires PRIMARY. Tous les PRIMARY doivent être des adresses IP séparées par des espaces avec un port optionnel.

zone create-secondary ZONE PRIMARY [PRIMARY]...

Crée une nouvelle zone secondaire ZONE avec les serveurs primaires PRIMARY. Tous les PRIMARY doivent être des adresses IP séparées par des espaces avec un port optionnel.

COMMANDES LIÉES À DNSSEC

Plusieurs commandes manipulent les clés et les options DNSSEC pour les zones. Certaines de ces commandes nécessitent qu'un ALGORITHM soit défini. Les algorithmes suivants sont supportés :

  • rsasha1
  • rsasha1-nsec3-sha1
  • rsasha256
  • rsasha512
  • ecdsa256
  • ecdsa384
  • ed25519
  • ed448

NOTE :

Les algorithmes ed25519 et ed448 ne seront disponibles que si des bibliothèques cryptographiques adéquates étaient disponibles lors de la compilation de PowerDNS sur votre système particulier.

En plus de l'algorithme, certaines commandes ci-dessous peuvent demander une taille de clé en bits. La taille de clé peut être omise pour les algorithmes ECC, qui ne supportent qu'une seule taille valide par algorithme ; pour ECDSA256 et ED25519, elle est de 256 ; pour ECDSA384, elle est de 384 ; et pour ED448, elle est de... 456.

zone dnssec-disable ZONE

Désactive toutes les clés et efface PRESIGNED dans ZONE.

zone export-dnskey ZONE KEY_ID

Exporte la DNSKEY et la DS de la clé avec l'ID de clé KEY_ID dans la zone ZONE vers la sortie standard.

zone export-ds ZONE

Exporte tous les enregistrements DS KSK pour ZONE vers la sortie standard.

zone list-keys [ZONE]

Liste les informations DNSSEC pour toutes les clés ou uniquement pour ZONE. L'option --verbose ou -v affichera également les clés des zones désactivées ou vides.

zone rectify ZONE

Calcule les champs 'ordername' et 'auth' pour une zone appelée ZONE afin qu'ils soient conformes aux paramètres DNSSEC. Peut être utilisé pour corriger des données migrées.

zone rectify-all

Calcule les champs 'ordername' et 'auth' pour toutes les zones afin qu'ils soient conformes aux paramètres DNSSEC. Peut être utilisé pour corriger des données migrées.

zone secure ZONE

Configure une zone appelée ZONE avec des paramètres DNSSEC raisonnables. Vous devriez exécuter manuellement 'pdnsutil zone rectify' après coup.

zone secure-all [increase-serial]

Configure toutes les zones qui ne sont pas actuellement signées avec des paramètres DNSSEC raisonnables. L'option increase-serial incrémentera également le serial de ces zones. Vous devriez exécuter manuellement 'pdnsutil zone rectify-all' après coup.

zone set-nsec3 ZONE ['HASH-ALGORITHM FLAGS ITERATIONS SALT'] [narrow]

Définit les paramètres NSEC3 pour cette zone. Les paramètres entre guillemets sont 4 valeurs utilisées pour l'enregistrement NSEC3PARAM et déterminent comment les enregistrements NSEC3 sont créés. Les paramètres NSEC3 doivent être mis entre guillemets sur la ligne de commande. HASH-ALGORITHM doit être 1 (SHA-1). Définir FLAGS à 1 active l'opération NSEC3 opt-out. Ne faites cela que si vous savez que vous en avez besoin. Pour ITERATIONS, veuillez consulter la RFC 5155.

Et soyez conscient qu'un nombre élevé peut surcharger les résolveurs validants et qu'une limite peut être définie avec max-nsec3-iterations dans pdns.conf. Le SALT est une chaîne hexadécimale encodant les bits pour le sel, ou - pour utiliser aucun sel.

Définir narrow fera que PowerDNS enverra des "mensonges blancs" (RFC 7129) concernant le prochain enregistrement sécurisé pour empêcher l'énumération de zone. Au lieu de le rechercher dans la base de données, il enverra le hash + 1 comme prochain enregistrement sécurisé. Le mode étroit nécessite des capacités de signature en ligne de la part du serveur de noms et, par conséquent, les transferts de zone sont refusés.

Si seule la zone est fournie comme argument, la chaîne entre guillemets à 4 paramètres sera par défaut '1 0 0 -', comme recommandé par la RFC 9276.

Une ligne de commande d'exemple serait :

pdnsutil zone set-nsec3 powerdnssec.org '1 1 1 ab' narrow

ATTENTION : Si vous êtes en mode RSASHA1 (algorithme 5 ou 7), le passage de NSEC à NSEC3 nécessitera une mise à jour DS dans la zone parente.

zone set-presigned ZONE

Passe ZONE en mode presigned, utilisant des RRSIGs internes à la zone.

zone set-publish-cdnskey ZONE [delete]

Configure ZONE pour publier des enregistrements CDNSKEY. Ajoutez 'delete' pour publier un CDNSKEY avec un algorithme de suppression DNSSEC.

zone set-publish-cds ZONE [DIGESTALGOS]

Configure ZONE pour répondre aux requêtes concernant ses enregistrements CDS. L'argument optionnel DIGESTALGOS doit être une liste d'algorithmes DS séparés par des virgules à utiliser. Par défaut, il s'agit de 2 (SHA-256). 0 publiera un CDS avec un algorithme de suppression DNSSEC.

zone show ZONE

Affiche divers détails de la zone appelée ZONE, y compris ses paramètres liés à DNSSEC.

zone unset-nsec3 ZONE

Convertit ZONE en opérations NSEC. ATTENTION : Si vous êtes en mode RSASHA1 (algorithme 5 ou 7), le passage de NSEC à NSEC3 nécessitera une mise à jour DS dans la zone parente !

zone unset-presigned ZONE

Désactive l'opération presigned pour ZONE.

zone unset-publish-cdnskey ZONE

Configure ZONE pour arrêter de publier des enregistrements CDNSKEY.

zone unset-publish-cds ZONE

Configure ZONE pour arrêter de répondre aux requêtes concernant ses enregistrements CDS.

COMMANDES DE CLÉS DE ZONE

zone activate-key ZONE KEY_ID

Active une clé avec l'ID KEY_ID dans une zone appelée ZONE.

zone add-key ZONE [KSK,ZSK] [active,inactive] [published,unpublished] ALGORITHM [KEYBITS]

Crée une nouvelle clé pour la zone ZONE, et en fait une KSK (par défaut) ou une ZSK, avec l'ALGORITHM et la KEYBITS spécifiés. Si KEYBITS est omis, la valeur de setting-default-ksk-size ou setting-default-zsk-size est utilisée.

La clé est inactive par défaut, définissez-la à active pour l'utiliser immédiatement pour signer ZONE. La clé est publiée dans la zone par défaut, définissez-la à unpublished pour l'empêcher d'être retournée dans une requête DNSKEY, ce qui est utile pour les rotations d'algorithmes.

Affiche l'ID de la clé ajoutée.

zone deactivate-key ZONE KEY_ID

Désactive une clé avec l'ID KEY_ID dans une zone appelée ZONE.

zone export-key ZONE KEY_ID

Exporte la clé complète (privée) avec l'ID de clé KEY_ID dans la zone ZONE vers la sortie standard. Le format utilisé est compatible avec BIND et NSD/LDNS.

zone export-key-pem ZONE KEY_ID

Exporte la clé complète (privée) avec l'ID de clé KEY_ID dans la zone ZONE vers la sortie standard au format de fichier PEM. Le format est compatible avec de nombreux produits logiciels non-DNS.

zone generate-key {KSK,ZSK} [ALGORITHM] [KEYBITS]

Génère une ZSK ou KSK avec l'algorithme et les bits spécifiés et l'affiche sur la sortie standard.
. Si ALGORITHM n'est pas défini, ECDSA256 est utilisé. Si KEYBITS n'est pas défini, une taille de clé appropriée est sélectionnée pour ALGORITHM : pour les clés RSA, 2048 bits pour KSK et 1024 bits pour ZSK ; pour les clés ECC, la taille requise par l'algorithme comme mentionné ci-dessus.

zone import-key ZONE FILE [KSK,ZSK] [active,inactive] [published,unpublished]

Importe depuis FILE une clé complète (privée) pour la zone ZONE. Le format utilisé est compatible avec BIND et NSD/LDNS. KSK ou ZSK spécifie les drapeaux que cette clé doit avoir à l'importation. Par défaut, KSK, active et publiée. Affiche l'identifiant de la clé ajoutée.

zone import-key-pem ZONE FILE ALGORITHM {KSK,ZSK}

Importe depuis le fichier PEM FILE une clé complète (privée) pour la zone ZONE avec un algorithme ALGORITHM spécifié. Le format utilisé est compatible avec de nombreux produits non-DNS. KSK ou ZSK spécifie les drapeaux que cette clé doit avoir à l'importation. Affiche l'identifiant de la clé ajoutée.

zone publish-key ZONE KEY_ID

Publie la clé avec l'identifiant KEY_ID dans la zone ZONE.

zone remove-key ZONE KEY_ID

Supprime une clé avec l'identifiant KEY_ID de la zone ZONE.

zone unpublish-key ZONE KEY_ID

Annule la publication de la clé avec l'identifiant KEY_ID dans la zone ZONE.

AUTRES COMMANDES DIVERSES

b2b-migrate OLD NEW

Migre les données d'un backend à un autre. Nécessite launch=OLD,NEW dans la configuration.

backend-cmd BACKEND CMD [CMD...]

Envoie une commande texte à un backend pour exécution. Les backends GSQL accepteront des commandes SQL, d'autres backends peuvent accepter d'autres choses. Soyez prudent !

backend-lookup BACKEND NAME [TYPE [CLIENT_IP_SUBNET]]

Effectue une recherche d'enregistrement dans le backend.

bench-db [FILE]

Effectue une optimisation de la base de données backend. FILE peut être un fichier avec une liste, une par ligne, de noms de zones à utiliser. Si FILE n'est pas spécifié, powerdns.com est utilisé.

create-bind-db FILENAME

Crée une base de données DNSSEC (sqlite3) à l'emplacement FILENAME pour le backend BIND. N'oubliez pas de définir bind-dnssec-db=*FILE* dans votre pdns.conf.

hash-password [WORK_FACTOR]

Cette commande pratique lit un mot de passe (non affiché) depuis l'entrée standard et renvoie une version hachée et salée, pour être utilisée comme mot de passe du serveur web ou comme clé API. Un facteur de travail scrypt optionnel peut être spécifié, en puissances de deux, sinon il est par défaut à 1024.

ipdecrypt IP_ADDRESS PASSPHRASE_OR_KEY [key]

Déchiffre une adresse IP selon la norme 'ipcipher'. Si la phrase secrète est une clé base64, ajoutez le mot "key" après elle.

ipencrypt IP_ADDRESS PASSPHRASE_OR_KEY [key]

Chiffre une adresse IP selon la norme 'ipcipher'. Si la phrase secrète est une clé base64, ajoutez le mot "key" après elle.

list-algorithms [with-backend]

Liste tous les algorithmes DNSSEC pris en charge, en indiquant éventuellement également la bibliothèque cryptographique utilisée si "with-backend" est spécifié.

test-schema ZONE

Teste le schéma de la base de données, cela crée la zone ZONE

raw-lua-from-content TYPE CONTENT

Affiche le contenu d'un enregistrement dans un format adapté à l'action SpoofRawAction de dnsdist.
