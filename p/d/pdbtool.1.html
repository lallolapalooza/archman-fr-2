NOM

pdbtool --- Une application pour tester et convertir les règles de base de données de modèles (pattern database) {{ site.product.short_name }}

SYNTAXE

pdbtool [commande] [options]

DESCRIPTION

Cette page de manuel est seulement un résumé.

L'application syslog-ng OSE peut faire correspondre le contenu des messages de log à une base de données de modèles de messages prédéfinis (également appelés patterndb). En comparant les messages aux modèles connus, syslog-ng OSE est capable d'identifier le type exact des messages, d'étiqueter les messages et de les trier en classes de messages. Les classes de messages peuvent être utilisées pour classifier le type de l'événement décrit dans le message de log. La fonctionnalité de la base de données de modèles est similaire à celle du projet logcheck, mais l'approche d'syslog-ng OSE est plus rapide, plus évolutive et beaucoup plus facile à maintenir par rapport aux expressions régulières de logcheck.

L'application pdbtool est un utilitaire qui peut être utilisé pour :

  • tester des messages, ou des règles spécifiques
  • convertir une ancienne base de données de modèles au dernier format de base de données
  • fusionner des bases de données de modèles en un seul fichier
  • créer automatiquement des bases de données de modèles à partir d'une grande quantité de messages de log
  • extraire l'arbre RADIX construit à partir de la base de données de modèles (ou d'une partie de celle-ci) pour explorer comment fonctionne la correspondance des modèles.

La commande dictionary

dictionary [options]

Liste chaque paire nom-valeur qui peut être définie par les règles de la base de données de modèles.

•
--dump-tag ou -T

Liste les balises (tags) au lieu des noms des paires nom-valeur.

•
--pdb <chemin-vers-fichier> ou -p <chemin-vers-fichier>

Nom du fichier de base de données de modèles à utiliser.

•
--program <nom-de-programme> ou -P <nom-de-programme>

Liste uniquement les paires nom-valeur qui peuvent être définies pour les messages de l'application ${PROGRAM} spécifiée.

La commande dump

dump [options]

Affiche l'arbre RADIX construit à partir des modèles. Cela montre comment les modèles sont représentés dans syslog-ng OSE et peut également aider à dépister les problèmes de correspondance des modèles. L'utilitaire dump peut extraire l'arbre utilisé pour faire correspondre les parties PROGRAM ou MSG.

•
--debug ou -d

Active les messages de débogage/diagnostic sur stderr.

•
--pdb ou -p

Nom du fichier de base de données de modèles à utiliser.

•
--program ou -P

Affiche l'arbre RADIX construit à partir des modèles appartenant à l'application ${PROGRAM}.

•
--program-tree ou -T

Affiche l'arbre ${PROGRAM}.

•
--verbose ou -v

Active les messages verbeux sur stderr.

Exemple et sortie d'exemple

pdbtool dump -p patterndb.xml  -P 'sshd'
'p'
    'assword for'
    @QSTRING:@
        'from'
        @QSTRING:@
            'port '
            @NUMBER:@ rule_id='fc49054e-75fd-11dd-9bba-001e6806451b'
                ' ssh' rule_id='fc55cf86-75fd-11dd-9bba-001e6806451b'
                    '2' rule_id='fc4b7982-75fd-11dd-9bba-001e6806451b'
    'ublickey for'
    @QSTRING:@
        'from'
        @QSTRING:@
            'port '
            @NUMBER:@ rule_id='fc4d377c-75fd-11dd-9bba-001e6806451b'
                ' ssh' rule_id='fc5441ac-75fd-11dd-9bba-001e6806451b'
                    '2' rule_id='fc44a9fe-75fd-11dd-9bba-001e6806451b'

La commande match

match [options]

Utilisez la commande match pour tester les règles d'une base de données de modèles. La commande essaie de faire correspondre le message spécifié aux modèles de la base de données, évalue les analyseurs (parsers) du modèle et affiche également quelle partie du message a été analysée avec succès. La commande renvoie un code de retour de 0 (succès) ou 1 (aucune correspondance) et affiche les informations suivantes :

  • la classe attribuée au message (c'est-à-dire system, violation, etc.),
  • l'ID de la règle qui correspondait au message, et
  • les valeurs des analyseurs (s'il y avait des analyseurs dans le modèle correspondant).

La commande match a les options suivantes :

•
--color-out ou -c

Colore la sortie du terminal pour mettre en évidence la partie du message qui a été analysée avec succès.

•
--debug ou -d

Active les messages de débogage/diagnostic sur stderr.

•
--debug-csv ou -C

Affiche les informations de débogage renvoyées par l'option --debug-pattern sous forme de valeurs séparées par des virgules.

•
--debug-pattern ou -D

Affiche des informations de débogage sur la correspondance des modèles. Voir également l'option --debug-csv.

•
--file=<nom-de-fichier-avec-chemin> ou -f

Traite les messages du fichier de log spécifié avec la base de données de modèles. Cette option permet de classifier les messages hors ligne et d'appliquer la base de données de modèles à des fichiers journaux déjà existants. Pour lire les messages depuis l'entrée standard (stdin), spécifiez un tiret (-) à la place d'un nom de fichier.

•
--filter=<expression-de-filtrage> ou -F

Affiche uniquement les messages correspondant à l'expression de filtrage syslog-ng OSE spécifiée.

•
--message ou -M

Le texte du message de log à faire correspondre (seulement la partie MESSAGE sans les en-têtes syslog).

•
--pdb ou -p

Nom du fichier de base de données de modèles à utiliser.

•
--program ou -P

Nom du programme à utiliser, tel qu'il est contenu dans la partie PROGRAM du message syslog.

•
--template=<expression-de-modèle> ou -T

Une expression de modèle syslog-ng OSE qui est utilisée pour formater les messages de sortie.

•
--verbose ou -v

Active les messages verbeux sur stderr.

Exemple - vérification

La commande suivante vérifie si le fichier patterndb.xml reconnaît le message Accepted publickey for myuser from 127.0.0.1 port 59357 ssh6 :

pdbtool match -p patterndb.xml -P sshd -M "Accepted publickey for myuser from 127.0.0.1 port 59357 ssh6"

Exemple - application

L'exemple suivant applique le fichier de base de données de modèles sshd.pdb aux messages de log stockés dans le fichier /var/log/messages et affiche uniquement les messages qui ont reçu une balise useracct.

pdbtool match -p sshd.pdb \
    –file /var/log/messages \
    –filter ‘tags(“usracct”);’

La commande merge

merge [options]

Utilisez la commande merge pour combiner des fichiers de base de données de modèles séparés en un seul fichier (les bases de données de modèles sont généralement stockées dans des fichiers séparés par application pour simplifier la maintenance). Si un fichier utilise un ancien format de base de données, il est automatiquement mis à jour vers le dernier format (V3). Voir le Guide d'administration de syslog-ng OSE pour plus de détails sur les différentes versions de bases de données de modèles.

•
--debug ou -d

Active les messages de débogage/diagnostic sur stderr.

•
--directory ou -D

Le répertoire qui contient les fichiers XML de base de données de modèles à fusionner.

•

The merge command

merge [options]

Merge multiple pattern database files into one. This command is useful if you have pattern database files stored in different locations, or if you want to split a large pattern database file into smaller files and then merge them back together.

•
--debug or -d

Enable debug/diagnostic messages on stderr.

•
--directory=<path> or -D

Directory containing the pattern database files to be merged. The glob(7) pattern is applied to the filenames in this directory.

•
--filter=<pattern> or -f

Specifies the filenames that should be merged using a glob pattern, for example, using wildcards. For details on glob patterns, see man glob. This pattern is applied only to the filenames, and not on directory names.

•
--pdb or -p

Name of the output pattern database file.

•
--recursive or -r

Merge files from subdirectories as well.

•
--sort or -s

Sort files into alphabetic order during the merge (first sort by filename, then by directory name).

•
--verbose or -v

Enable verbose messages on stderr.

Example - merge

pdbtool merge --recursive --directory /home/me/mypatterns/  --pdb /var/lib/syslog-ng/patterndb.xml

Currently it is not possible to convert a file without merging, so if you only want to convert an older pattern database file to the latest format, you have to copy it into an empty directory.

The patternize command

patternize [options]

Automatically create a pattern database from a log file containing a large number of log messages. The resulting pattern database is printed to the standard output (stdout). The pdbtool patternize command uses a data clustering technique to find similar log messages and replacing the differing parts with @ESTRING:: @ parsers. For details on pattern databases and message parsers, see the The syslog-ng OSE Administrator Guide ⟨https://www.syslog-ng.com/⟩. The patternize command is available only in version 3.2 and later.

•
--debug or -d

Enable debug/diagnostic messages on stderr.

•
--file=<path> or -f

The logfile containing the log messages to create patterns from. To receive the log messages from the standard input (stdin), use -.

•
--iterate-outliers or -o

Recursively iterate on the log lines to cover as many log messages with patterns as possible.

•
--named-parsers or -n

The number of example log messages to include in the pattern database for every pattern. Default value: 1

•
--no-parse or -p

Do not parse the input file, treat every line as the message part of a log message.

•
--samples=<number-of-samples>

Include a generated name in the parsers, for example, .dict.string1, .dict.string2, and so on.

•
--support=<number> or -S

A pattern is added to the output pattern database if at least the specified percentage of log messages from the input logfile match the pattern. For example, if the input logfile contains 1000 log messages and the --support=3.0 option is used, a pattern is created only if the pattern matches at least 3 percent of the log messages (that is, 30 log messages). If patternize does not create enough patterns, try to decrease the support value.

Default value: 4.0

•
--verbose or -v

Enable verbose messages on stderr.

Example - patternize

pdbtool patternize --support=2.5 --file=/var/log/messages

The test command

test [options]

Use the test command to validate a pattern database XML file. Note that you must have the xmllint application installed. The test command is available only in syslog-ng OSE version 3.2 and later.

•
--color-out or -c

Enable coloring in terminal output.

•
--debug or -d

Enable debug/diagnostic messages on stderr.

•
--debug or -D

Print debugging information on non-matching patterns.

•
--rule-id or -r

Test only the patterndb rule (specified by its rule id) against its example.

•
--validate

Validate a pattern database XML file.

•
--verbose or -v

Enable verbose messages on stderr.

Example - test

pdbtool test --validate /home/me/mypatterndb.pdb
