NOM

pdbedit - gérer la base de données SAM (Base de données des utilisateurs Samba)

SYNTAXE

pdbedit [-L|--list] [-v|--verbose] [-w|--smbpasswd-style] [-u|--user=UTILISATEUR] [-N|--account-desc=CHAINE] [-f|--fullname=CHAINE] [-h|--homedir=CHAINE] [-D|--drive=CHAINE] [-S|--script=CHAINE] [-p|--profile=CHAINE] [-I|--domain=CHAINE] [-U|--user SID=CHAINE] [-M|--machine SID=CHAINE] [-a|--create] [-r|--modify] [-m|--machine] [-x|--delete] [-b|--backend=CHAINE] [-i|--import=CHAINE] [-e|--export=CHAINE] [-g|--group] [-y|--policies] [--policies-reset] [-P|--account-policy=CHAINE] [-C|--value=LONG] [-c|--account-control=CHAINE] [--force-initialized-passwords] [-z|--bad-password-count-reset] [-Z|--logon-hours-reset] [--time-format=CHAINE] [-t|--password-from-stdin] [-K|--kickoff-time=CHAINE] [--set-nt-hash=CHAINE] [-?|--help] [--usage] [-d|--debuglevel=NIVEAU_DEBOGAGE] [--debug-stdout] [--configfile=FICHIER_CONFIG] [--option=nom=valeur] [-l|--log-basename=BASE_FICHIER_LOG] [--leak-report] [--leak-report-full]

DESCRIPTION

Cet outil fait partie de la suite samba(7).

Le programme pdbedit est utilisé pour gérer les comptes utilisateurs stockés dans la base de données sam et ne peut être exécuté que par root.

L'outil pdbedit utilise l'interface modulaire passdb et est indépendant du type de base de données d'utilisateurs utilisée (actuellement, il existe des bases smbpasswd, ldap, nis+ et tdb, et d'autres peuvent être ajoutées sans modifier l'outil).

Il y a cinq façons principales d'utiliser pdbedit : ajouter un compte utilisateur, supprimer un compte utilisateur, modifier un compte utilisateur, lister les comptes utilisateurs, importer des comptes utilisateurs.

OPTIONS

-L|--list

Cette option liste tous les comptes utilisateurs présents dans la base de données d'utilisateurs. Cette option affiche une liste de paires utilisateur/uid séparées par le caractère ':'.

Exemple : pdbedit -L

sorce:500:Simo Sorce
samba:45:Test User

-v|--verbose

Cette option active le format de liste verbeux. Elle demande à pdbedit de lister les utilisateurs dans la base de données, en affichant les champs du compte dans un format descriptif. Utilisée avec -w, elle montre également les hachages de mots de passe.

Exemple : pdbedit -L -v

---------------
username:       sorce
user ID/Group:  500/500
user RID/GRID:  2000/2001
Full Name:      Simo Sorce
Home Directory: \\BERSERKER\sorce
HomeDir Drive:  H:
Logon Script:   \\BERSERKER\netlogon\sorce.bat
Profile Path:   \\BERSERKER\profile
---------------
username:       samba
user ID/Group:  45/45
user RID/GRID:  1090/1091
Full Name:      Test User
Home Directory: \\BERSERKER\samba
HomeDir Drive:  
Logon Script:   
Profile Path:   \\BERSERKER\profile

-w|--smbpasswd-style

Cette option définit le format de liste "smbpasswd". Elle demandera à pdbedit de lister les utilisateurs dans la base de données, en affichant les champs du compte dans un format compatible avec le format du fichier smbpasswd. (voir le smbpasswd(5) pour les détails). Utilisée avec (-v) affiche les hachages de mots de passe en sortie verbeuse.

Exemple : pdbedit -L -w

sorce:500:508818B733CE64BEAAD3B435B51404EE:
          D2A2418EFC466A8A0F6B1DBB5C3DB80C:
          [UX         ]:LCT-00000000:
samba:45:0F2B255F7B67A7A9AAD3B435B51404EE:
          BC281CE3F53B6A5146629CD4751D3490:
          [UX         ]:LCT-3BFA1E8D:

-u|--user utilisateur

Cette option spécifie le nom d'utilisateur à utiliser pour l'opération demandée (liste, ajout, suppression). Il est *requis* pour les opérations d'ajout, de suppression et de modification, et *optionnel* pour les opérations de liste.

-f|--fullname nomcomplet

Cette option peut être utilisée lors de l'ajout ou de la modification d'un compte utilisateur. Elle spécifie le nom complet de l'utilisateur.

Exemple : -f "Simo Sorce"

-h|--homedir rep_accueil

Cette option peut être utilisée lors de l'ajout ou de la modification d'un compte utilisateur. Elle spécifie le chemin réseau du répertoire personnel de l'utilisateur.

Exemple : -h "\\BERSERKER\sorce"

-D|--drive lecteur

Cette option peut être utilisée lors de l'ajout ou de la modification d'un compte utilisateur. Elle spécifie la lettre de lecteur Windows à utiliser pour mapper le répertoire personnel.

Exemple : -D "H:"

-S|--script script

Cette option peut être utilisée lors de l'ajout ou de la modification d'un compte utilisateur. Elle spécifie le chemin du script de connexion de l'utilisateur.

Exemple : -S "\\BERSERKER\netlogon\sorce.bat"

--set-nt-hash

Cette option peut être utilisée lors de la modification d'un compte utilisateur. Elle définira le mot de passe de l'utilisateur en utilisant la valeur nt-hash donnée sous forme de chaîne hexadécimale. Utile pour synchroniser les mots de passe.

Exemple : --set-nt-hash 8846F7EAEE8FB117AD06BDD830B7586C

-p|--profile profil

Cette option peut être utilisée lors de l'ajout ou de la modification d'un compte utilisateur. Elle spécifie le répertoire de profil de l'utilisateur.

Exemple : -p "\\BERSERKER\netlogon"

-M|'--machine SID' SID|rid

Cette option peut être utilisée lors de l'ajout ou de la modification d'un compte machine. Elle spécifiera le nouveau SID (Security Identifier) ou le nouveau RID (Relative Identifier) du groupe principal de la machine.

Exemple : -M S-1-5-21-2447931902-1787058256-3961074038-1201

-U|'--user SID' SID|rid

Cette option peut être utilisée lors de l'ajout ou de la modification d'un compte utilisateur. Elle spécifiera le nouveau SID (Security Identifier) ou le nouveau RID (Relative Identifier) de l'utilisateur.

Exemple : -U S-1-5-21-2447931902-1787058256-3961074038-5004

Exemple : '--user SID' S-1-5-21-2447931902-1787058256-3961074038-5004

Exemple : -U 5004

Exemple : '--user SID' 5004

-c|--account-control compte-controle

Cette option peut être utilisée lors de l'ajout ou de la modification d'un compte utilisateur. Elle spécifiera la propriété de contrôle du compte de l'utilisateur. Les drapeaux possibles sont listés ci-dessous.
— Pas de mot de passe requis (No password required)
— Compte désactivé (Account disabled)
— Répertoire personnel requis (Home directory required)
— Compte temporaire duplicata d'un autre compte (Temporary duplicate of other account)
— Compte utilisateur régulier (Regular user account)
— Compte utilisateur MNS (MNS logon user account)
— Compte de confiance de station de travail (Workstation Trust Account)
— Compte de confiance de serveur (Server Trust Account)
— Verrouillage automatique (Automatic Locking)
— Le mot de passe n'expire pas (Password does not expire)
— Compte de confiance de domaine (Domain Trust Account)

Exemple : -c "[X ]"

-K|--kickoff-time

Cette option est utilisée pour modifier l'heure de fin d'activité d'un utilisateur. Utilisez "never" comme argument pour définir l'heure de fin d'activité à illimitée.

Exemple : pdbedit -K never utilisateur

-a|--create

Cette option est utilisée pour ajouter un utilisateur dans la base de données. Cette commande nécessite un nom d'utilisateur spécifié avec l'option -u. Lors de l'ajout d'un nouvel utilisateur, pdbedit demandera également le mot de passe à utiliser.

Exemple : pdbedit -a -u sorce

nouveau mot de passe :
retaper le nouveau mot de passe

Note
pdbedit n'appelle pas le script de synchronisation des mots de passe Unix si unix password sync a été défini. Il met uniquement à jour les données dans la base de données des utilisateurs Samba.

Si vous souhaitez ajouter un utilisateur et synchroniser immédiatement le mot de passe, utilisez l'option -a de smbpasswd.

-t|--password-from-stdin

Cette option demande à pdbedit de lire le mot de passe depuis l'entrée standard, plutôt que depuis /dev/tty (comme le fait le programme passwd(1)). Le mot de passe doit être soumis deux fois et terminé par un retour à la ligne à chaque fois.

-r|--modify

Cette option est utilisée pour modifier un utilisateur existant dans la base de données. Cette commande nécessite un nom d'utilisateur spécifié avec l'option -u. D'autres options peuvent être spécifiées pour modifier les propriétés de l'utilisateur spécifié. Cet indicateur est conservé pour des raisons de compatibilité descendante, mais il n'est plus nécessaire de le spécifier.

-m|--machine

Cette option ne peut être utilisée qu'en conjonction avec l'option -a. Elle demandera à pdbedit d'ajouter un compte de confiance de machine au lieu d'un compte utilisateur (l'option -u username fournira le nom de la machine).

Exemple : pdbedit -a -m -u w2k-wks

-x|--delete

Cette option demande à pdbedit de supprimer un compte de la base de données. Elle nécessite un nom d'utilisateur spécifié avec l'option -u.

Exemple : pdbedit -x -u bob

GROUP

-g|--group

This option is used to modify the group database instead of the user database. All the other options apply to groups instead of users.

POLICIES

-y|--policies

This option is used to edit the password policies. Only one policy can be edited at a time. You must use the -P option to specify the policy name and the -C option to specify the value.

--policies-reset

This option resets all password policies to their default values.

-P|--account-policy policy

This option specifies the name of the policy to be edited. The possible policies are listed below.
• min pwd length: Minimum password length
• max pwd age: Maximum password age
• min pwd age: Minimum password age
• pwd complexity: Password complexity
• pwd history: Password history
• lockout threshold: Lockout threshold
• lockout duration: Lockout duration
• lockout observation window: Lockout observation window

-C|--value value

This option specifies the value for the policy to be set. The value must be a long integer.

Example: pdbedit -y -P "min pwd length" -C 8

Example: pdbedit -y -P "pwd complexity"

Example: pdbedit --policies-reset

OTHER OPTIONS

-b|--backend backend

This option specifies the database backend to use. The default is usually tdb. Possible values include: tdbsam(8), smbpasswd(5), ldap.conf(5), nis+.

-i|--import filename

Import user accounts from the specified file. The file format must be compatible with the smbpasswd file format.

-e|--export filename

Export user accounts to the specified file. The file format is compatible with the smbpasswd file format.

-Z|--logon-hours-reset

Reset the logon hours for all users.

--time-format STRING

Sets the time format for logon hours. The default is HH:MM-HH:MM.

-d|--debuglevel DEBUGLEVEL

debuglevel is an integer from 0 to 10. Level 0 means no debugging, while level 10 means maximum debugging.

--debug-stdout

Send debug information to stdout instead of stderr.

--configfile CONFIGFILE

Use the specified configuration file instead of the default smb.conf.

--option=name=value

Set a specific Samba option directly.

-l|--log-basename LOGFILEBASE

Base name for log files.

--leak-report

Generate a leak report on exit.

--leak-report-full

Generate a full leak report on exit.

EXAMPLES

To add a new user called "bob":

pdbedit -a -u bob

To delete the user "alice":

pdbedit -x -u alice

To list all users in a verbose format:

pdbedit -L -v

To change the home directory of user "charlie" to "\\\\SERVER\\charlie" and the logon script to "\\\\SERVER\\netlogon\\charlie.bat":

pdbedit -r -u charlie -h "\\\\SERVER\\charlie" -S "\\\\SERVER\\netlogon\\charlie.bat"

To disable the account for user "david":

pdbedit -r -u david -c "[D ]"

To set the minimum password length to 8 characters:

pdbedit -y -P "min pwd length" -C 8

NAME

pdbedit - gestione del database degli utenti Samba

SYNOPSIS

pdbedit [-i passdb-backend] [-e passdb-backend] [-g] [-b passdb-backend] [-P account-policy] [-C account-policy-value] [-y] [--force-initialized-passwords] [-N description] [-Z] [-z] [--policies-reset] [-I domain] [--time-format] [-?] [--usage] [-d debuglevel] [--debug-stdout] [--configfile=configuration file] [--option=name=value] [-llogdirectory] [--leak-report] [--leak-report-full] [-V]

DESCRIPTION

La utility pdbedit è uno strumento per la gestione del database degli utenti Samba.

Può essere usata per creare, eliminare, modificare e visualizzare gli utenti e i relativi attributi memorizzati nel database degli utenti di Samba.

Il database degli utenti di Samba (passdb) può essere implementato in vari modi. Le implementazioni più comuni includono:

  • smbpasswd: il formato legacy basato su file.
  • tdbsam: un database TDB veloce (utilizzato da default).
  • ldap: un database basato su LDAP.
  • mysql: un database basato su MySQL/MariaDB.
  • pgsql: un database basato su PostgreSQL.
  • xml: un database basato su XML.

Questi sono solo alcuni esempi e l'elenco completo delle implementazioni disponibili può essere trovato nella documentazione di Samba.

Di default, pdbedit userà il backend specificato nel file smb.conf. Se il backend non è specificato in smb.conf, userà il backend tdbsam.

Per la gestione degli utenti, è possibile usare le opzioni -L, -a, -x, e -v.

pdbedit è uno strumento molto potente ma potenzialmente pericoloso. Assicurarsi di comprendere appieno le implicazioni di ogni comando prima di eseguirlo.

OPTIONS

-i|--import passdb-backend

Usa un backend passdb diverso per recuperare gli utenti rispetto a quello specificato in smb.conf. Può essere utilizzato per importare dati nel database locale degli utenti.

Questa opzione faciliterà la migrazione da un backend passdb a un altro.

Esempio: pdbedit -i smbpasswd:/etc/smbpasswd.old

-e|--export passdb-backend

Esporta tutti gli utenti attualmente disponibili nel backend del database delle password specificato.

Questa opzione faciliterà la migrazione da un backend passdb a un altro e ne semplificherà il backup.

Esempio: pdbedit -e smbpasswd:/root/samba-users.backup

-g|--group

Se specifichi -g, allora -i in-backend -e out-backend si applica alla mappatura dei gruppi invece che al database degli utenti.

Questa opzione faciliterà la migrazione da un backend passdb a un altro e ne semplificherà il backup.

-b|--backend passdb-backend

Usa un backend passdb predefinito diverso.

Esempio: pdbedit -b xml:/root/pdb-backup.xml -l

-P|--account-policy account-policy

Visualizza una politica dell'account.

Le politiche valide sono: età minima della password, minuti per il reset del conteggio, tempo di disconnessione, l'utente deve effettuare il login per cambiare password, cronologia delle password, durata del blocco, lunghezza minima della password, età massima della password e numero di tentativi di blocco errati.

Esempio: pdbedit -P "tentativi di blocco errati"

valore della politica dell'account per i tentativi di blocco errati è 0

-C|--value account-policy-value

Imposta una politica dell'account a un valore specificato. Questa opzione può essere utilizzata solo in combinazione con l'opzione -P.

Esempio: pdbedit -P "tentativi di blocco errati" -C 3

il valore della politica dell'account per i tentativi di blocco errati era 0
il valore della politica dell'account per i tentativi di blocco errati è ora 3

-y|--policies

Se specifichi -y, allora -i in-backend -e out-backend si applica alle politiche degli account invece che al database degli utenti.

Questa opzione permetterà di migrare le politiche degli account dal loro archivio tdb predefinito a un backend passdb, ad esempio un server di directory LDAP.

Esempio: pdbedit -y -i tdbsam: -e ldapsam:ldap://my.ldap.host

--force-initialized-passwords

Questa opzione forza tutti gli utenti a cambiare la loro password al prossimo login.

-N|--account-desc description

Questa opzione può essere utilizzata durante l'aggiunta o la modifica di un account utente. Specificherà il campo descrizione dell'utente.

Esempio: -N "descrizione di prova"

-Z|--logon-hours-reset

Questa opzione può essere utilizzata durante l'aggiunta o la modifica di un account utente. Reimposterà le ore di accesso consentite per l'utente. L'utente potrà accedere in qualsiasi momento in seguito.

Esempio: -Z

-z|--bad-password-count-reset

Questa opzione può essere utilizzata durante l'aggiunta o la modifica di un account utente. Reimposterà il contatore dei login errati memorizzato per un utente specificato.

Esempio: -z

--policies-reset

Questa opzione può essere utilizzata per reimpostare le politiche generali delle password memorizzate per un dominio ai loro valori predefiniti.

Esempio: --policies-reset

-I|--domain

Questa opzione può essere utilizzata durante l'aggiunta o la modifica di un account utente. Specificherà il campo dominio dell'utente.

Esempio: -I "MIO DOMINIO"

--time-format

Questa opzione non viene attualmente utilizzata.

-?|--help

Stampa un riepilogo delle opzioni della riga di comando.

--usage

Visualizza un breve messaggio di utilizzo.

-d|--debuglevel=level

level è un intero da 0 a 10. Il valore predefinito se questo parametro non è specificato è 1 per le applicazioni client.

Più alto è questo valore, maggiore sarà il dettaglio registrato nei file di log sulle attività del server. Al livello 0, verranno registrati solo errori critici e avvisi seri. Il livello 1 è un livello ragionevole per l'uso quotidiano: genera una piccola quantità di informazioni sulle operazioni eseguite.

I livelli superiori a 1 genereranno una notevole quantità di dati di log e dovrebbero essere utilizzati solo durante l'indagine di un problema. I livelli superiori a 3 sono progettati per essere utilizzati solo dagli sviluppatori e generano ENORMI quantità di dati di log, la maggior parte dei quali è estremamente criptica.

Si noti che la specifica di questo parametro qui sovrascriverà il parametro log level nel file /etc/samba/smb.conf.

--debug-stdout

Reindirizzerà l'output di debug a STDOUT. Per impostazione predefinita, tutti i client registrano su STDERR.

--configfile=<file di configurazione>

Il file specificato contiene i dettagli di configurazione richiesti dal client. Le informazioni in questo file possono essere generali per client e server o fornire solo opzioni specifiche per il client come client smb encrypt. Vedere /etc/samba/smb.conf per maggiori informazioni. Il nome del file di configurazione predefinito è determinato al momento della compilazione.

--option=<nome>=<valore>

Imposta l'opzione smb.conf(5) "<nome>" al valore "<valore>" dalla riga di comando. Ciò sovrascrive i valori predefiniti compilati e le opzioni lette dal file di configurazione. Se un nome o un valore include uno spazio, racchiudere l'intera opzione --option=nome=valore tra virgolette.

-l|--log-basename=logdirectory

Nome della directory di base per i file di log/debug. Verrà aggiunto l'estensione ".progname" (ad esempio, log.smbclient, log.smbd, ecc...). Il file di log non viene mai rimosso dal client.

--leak-report

Abilita il reporting delle perdite di memoria talloc all'uscita.

--leak-report-full

Abilita il reporting completo delle perdite di memoria talloc all'uscita.

-V|--version

Stampa il numero di versione del programma.

NOTES

Questo comando può essere utilizzato solo da root.
