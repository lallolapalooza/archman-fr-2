PDFOPEN(1) PDFOPEN(1)

NOM

pdfopen, pdfclose - ouvrir ou fermer une visionneuse de fichier PDF

SYNTAXE

pdfopen [ options ]  [ --file ]  fichier.pdf
pdfclose [ --file ]  fichier.pdf

OPTIONS

-h, --help, -?
afficher l'aide et quitter.
-v, --version, -V
afficher le numéro de version et quitter.
-p <n>, --page <n>
lors du lancement de la visionneuse, afficher la page <n> du document (remarques : toutes les visionneuses ne supportent pas cette fonctionnalité, et même dans ces cas, cette option n'a d'effet que lorsque le document est chargé initialement). Cette option est remplacée par -g.
-g <destination nommée>, --goto <destination nommée>
lors du lancement de la visionneuse, afficher la page du document contenant la destination nommée (remarques : toutes les visionneuses ne supportent pas cette fonctionnalité, et même dans ces cas, cette option n'a d'effet que lorsque le document est chargé initialement).
-r, --reset_focus
après avoir envoyé des commandes à la visionneuse PDF, tenter de réinitialiser le focus d'entrée vers la fenêtre qui avait le focus avant l'envoi des commandes.
-viewer, --viewer <ar9|ar9-tab|ar8|ar7|ar5|xpdf|evince>
utiliser (respectivement) Adobe Reader 9 (dans une nouvelle fenêtre), Adobe Reader 9 (dans un nouvel onglet d'un AR9 en cours d'exécution, le cas échéant), Adobe Reader 8, Adobe Reader 7, Adobe Reader 5, xpdf ou evince comme programme de visualisation PDF. Adobe Reader 9 (dans une nouvelle fenêtre) est la valeur par défaut.

RATIONNEL

À certains stades de la préparation des documents TeX, de nombreuses personnes répètent un cycle « édition-compilation-visualisation ». Comme les visionneuses PDF telles qu'Adobe Acrobat Reader («acroread») ne rafraîchissent pas automatiquement l'affichage lorsque le fichier PDF change, ce cycle peut être plus fastidieux que désiré. Le programme pdfopen permet d'automatiser le rechargement du document PDF lorsqu'il est modifié.

Remarque : il semble y avoir peu d'utilité à pdfclose sous GNU/Linux, car (contrairement à la situation sous MS Windows) acroread ne verrouille pas le fichier PDF, ce qui empêcherait pdftex (ou un convertisseur DVI vers PDF) de créer une nouvelle version du fichier de sortie PDF. Cependant, pdfclose est fourni au cas où quelqu'un le trouverait utile.

DESCRIPTION

pdfopen recherche une instance de la visionneuse PDF spécifiée (ou par défaut) affichant le fichier PDF spécifié. S'il existe déjà une instance de la visionneuse donnée affichant le fichier donné, la visionneuse est instruite de recharger le fichier. Si aucune instance de ce type n'est trouvée, pdfopen tente de lancer la visionneuse spécifiée sur le document spécifié.

La visionneuse par défaut est «acroread», qui peut lancer une des nombreuses versions d'Acrobat Reader, en fonction de ce qui est installé sur votre système. Cependant, les commandes pour recharger le document actuel varient d'une version d'acroread à l'autre ; par conséquent, si vous utilisez une version d'acroread autre que AR9, vous devriez spécifier explicitement le programme de visualisation.

Cette version de pdfopen accepte les options de visionneuse suivantes :
ar9, ar9-tab, ar8, ar7, ar5, xpdf, et evince.
La différence entre ar9 et ar9-tab est significative lorsqu'il n'y a pas d'instance d'AR9 affichant déjà le document demandé. Dans cette situation, tandis qu'ar9 demandera à acroread de créer une nouvelle instance d'acroread (et donc d'ouvrir une nouvelle fenêtre) en utilisant l'argument -openInNewInstance, ar9-tab lance acroread sans cet argument ; s'il y a déjà une instance d'acroread en cours d'exécution, un nouvel onglet sera ouvert dans une fenêtre existante.

pdfclose recherche une des visionneuses PDF ci-dessus affichant le fichier donné et demande à la visionneuse de « fermer » la fenêtre. Dans la plupart des cas, la visionneuse PDF continue de s'exécuter, affichant éventuellement juste une fenêtre vide. (Ce comportement varie quelque peu d'une visionneuse PDF à l'autre.)

PORTABILITE ET DISPONIBILITE

Ces programmes ont été testés sur Slackware64 Version 14.1 et quelques autres versions / distributions de GNU/Linux. Le code est raisonnablement générique et devrait fonctionner sans modification sur la plupart des implémentations X11 récentes. (Les rapports contraires sont les bienvenus, surtout s'ils sont accompagnés de corrections robustes.)

Ces programmes sont conçus pour les systèmes basés sur X11. Si vous trouvez par hasard des versions compilées de ces programmes sur un système utilisant un autre système de fenêtrage, il est très peu probable qu'ils vous soient utiles.

Les sources et les binaires des programmes peuvent être téléchargés depuis CTAN://support/xpdfopen/ (par exemple, http://mirror.ctan.org/support/xpdfopen).

AVERTISSEMENTS

Si vous utilisez ar9-tab pour recharger le document PDF et que l'instance d'acroread avec le document donné affiche actuellement un autre document, la commande provoque l'affichage de votre document, mais pas son rechargement.

pdfopen fonctionne en recherchant une fenêtre dont le nom (titre de la fenêtre) correspond à celui attendu pour la visionneuse et le document donnés. Si, pour une raison quelconque, le nom de la fenêtre de votre visionneuse n'est pas celui attendu, pdfopen peut ne pas fonctionner pour vous.

Avec au moins AR9 et certains gestionnaires de fenêtres, l'utilisation de pdfopen pour recharger le document donne le focus à la fenêtre d'acroread, même si le curseur de la souris ne se trouve pas nécessairement dans cette fenêtre. Cela peut être agaçant. L'option -reset_focus peut être utilisée pour résoudre ce problème.
