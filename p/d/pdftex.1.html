PDFTEX(1) Manuel des commandes générales PDFTEX(1)

NOM

pdftex - sortie PDF depuis TeX

SYNTAXE

pdftex [options] [&format] [fichier|\commandes]

DESCRIPTION

Exécute le compositeur pdfTeX sur fichier, créant généralement fichier.pdf. Si l'argument fichier n'a pas d'extension, ".tex" lui sera ajouté. Au lieu d'un nom de fichier, un ensemble de commandes pdfTeX peut être donné, dont la première doit commencer par une barre oblique inverse. Avec un argument &format, pdfTeX utilise un ensemble différent de commandes précompilées, contenues dans format.fmt ; il est généralement préférable d'utiliser l'option -fmt format à la place.

pdfTeX est une version de TeX, avec les extensions e-TeX, qui peut créer des fichiers PDF ainsi que des fichiers DVI.

En mode DVI, pdfTeX peut être utilisé comme un remplacement complet du moteur TeX.

L'utilisation typique de pdfTeX se fait avec des formats pré-générés pour lesquels la sortie PDF a été activée. La commande pdftex utilise l'équivalent du format plain TeX, et la commande pdflatex utilise l'équivalent du format LaTeX. Pour générer des formats, utilisez l'option -ini.

Les commandes pdfinitex et pdfvirtex sont les analogues de pdfTeX aux commandes initex et virtex. Dans cette installation, si les liens existent, ce sont des liens symboliques vers l'exécutable pdftex.

En mode PDF, pdfTeX peut gérer nativement les formats graphiques PDF, JPG, JBIG2 et PNG. pdfTeX ne peut pas inclure des fichiers graphiques PostScript ou Encapsulated PostScript (EPS) ; convertissez-les d'abord en PDF en utilisant epstopdf(1). La gestion des arguments de ligne de commande par pdfTeX est similaire à celle des autres programmes TeX de l'implémentation web2c.

Depuis la version 1.40, pdfTeX intègre les extensions e-TeX, et pdfeTeX n'est qu'une copie de pdfTeX. Voir etex(1).

OPTIONS

Cette version de pdfTeX comprend les options de ligne de commande suivantes.

-cnf-line chaîne
Analyse chaîne comme une ligne de configuration texmf.cnf. Voir le manuel Kpathsea.
-draftmode
Définit \pdfdraftmode afin que pdfTeX n'écrive pas de PDF et ne lise aucune image incluse, accélérant ainsi l'exécution.
-enc
Active les extensions encTeX. Cette option n'est effective qu'en combinaison avec -ini. Pour la documentation des extensions encTeX, voir http://www.olsak.net/enctex.html.
-etex
Active les extensions e-TeX. Cette option n'est effective qu'en combinaison avec -ini. Voir etex(1).
-file-line-error
Affiche les messages d'erreur sous la forme fichier:ligne:erreur, ce qui est similaire à la façon dont de nombreux compilateurs les formatent.
-no-file-line-error
Désactive l'affichage des messages d'erreur au format fichier:ligne:erreur.
-file-line-error-style
C'est l'ancien nom de l'option -file-line-error.
-fmt format
Utilise format comme nom du format à utiliser, au lieu du nom sous lequel pdfTeX a été appelé ou d'une ligne %&.
-halt-on-error
Sort avec un code d'erreur lorsqu'une erreur est rencontrée pendant le traitement.
-help
Affiche le message d'aide et quitte.
-ini
Démarre en mode INI, utilisé pour sauvegarder des formats. Le mode INI peut être utilisé pour la composition, mais aucun format n'est préchargé, et des initialisations de base comme la définition des codes de catégories peuvent être nécessaires.
-interaction mode
Définit le mode d'interaction. Le mode peut être batchmode, nonstopmode, scrollmode, et errorstopmode. La signification de ces modes est la même que celle des \commandes correspondantes.
-ipc
Envoie la sortie DVI ou PDF vers une socket ainsi que vers le fichier de sortie habituel. La disponibilité de cette option dépend de l'installateur.
-ipc-start
Comme -ipc, et démarre également le serveur à l'autre extrémité. La disponibilité de cette option dépend de l'installateur.
-jobname nom
Utilise nom pour le nom du job, au lieu de le dériver du nom du fichier d'entrée.
-kpathsea-debug masque_binaire
Définit les indicateurs de débogage de la recherche de chemins selon le masque binaire. Voir le manuel de Kpathsea pour plus de détails.
-mktex fmt
Active mktexfmt, où fmt doit être soit tex, soit tfm.
-mltex
Active les extensions MLTeX. Uniquement effectif en combinaison avec -ini.
-no-mktex fmt
Désactive mktexfmt, où fmt doit être soit tex, soit tfm.
-output-comment chaîne
En mode DVI, utilise chaîne pour le commentaire du fichier DVI au lieu de la date. Cette option est ignorée en mode PDF.
-output-directory répertoire
Écrit les fichiers de sortie dans répertoire au lieu du répertoire courant. Recherche les fichiers d'entrée dans répertoire d'abord, puis le long du chemin de recherche normal.
-output-format format
Définit le mode du format de sortie, où format doit être soit pdf, soit dvi. Ceci influence également l'ensemble des formats graphiques compris par pdfTeX.
-parse-first-line
Si la première ligne du fichier d'entrée principal commence par %&, elle est analysée pour rechercher un nom de dump ou une option -translate-file.
-no-parse-first-line
Désactive l'analyse de la première ligne du fichier d'entrée principal.
-progname nom
Prétend être le programme nom. Ceci affecte à la fois le format utilisé et les chemins de recherche.
-recorder
Active l'enregistreur de noms de fichiers. Ceci laisse une trace des fichiers ouverts pour l'entrée et la sortie dans un fichier avec l'extension .fls.
-shell-escape
Active la construction \write18{commande}. La commande peut être n'importe quelle commande shell. Cette construction est normalement interdite pour des raisons de sécurité.
-no-shell-escape
Désactive la construction \write18{commande}, même si elle est activée dans le fichier texmf.cnf.
-shell-restricted
Active \write18{} restreint, comme expliqué dans la section ``Shell escapes'' du manuel Texinfo Web2c.
-src-specials
En mode DVI, insère des spéciaux de source dans le fichier DVI. Cette option est ignorée en mode PDF.
-src-specials où
En mode DVI, insère des spéciaux de source à certains endroits du fichier DVI. L'argument où est une liste de valeurs séparées par des virgules : cr, display, hbox, math, par, parent, ou vbox.
>. Cette option est ignorée en mode PDF.
-synctex NOMBRE
génère des données SyncTeX pour les aperçus selon les bits de NOMBRE. Voir la page de manuel synctex pour les détails.
-translate-file tcxname
Utilise la table de traduction tcxname pour définir le mappage des caractères d'entrée et le remappage des caractères de sortie.
-default-translate-file tcxname
Comme -translate-file, sauf qu'une ligne %& peut outrepasser ce réglage.
-version
Affiche les informations de version et quitte.
-8bit
rend tous les caractères imprimables par défaut.

ENVIRONNEMENT

Voir la documentation de la bibliothèque Kpathsea (par exemple, le nœud `Path specifications') pour les détails précis sur l'utilisation des variables d'environnement. L'utilitaire kpsewhich peut être utilisé pour interroger les valeurs des variables.

Une mise en garde : Dans la plupart des formats pdfTeX, vous ne pouvez pas utiliser ~ dans un nom de fichier que vous donnez directement à pdfTeX, car ~ est un caractère actif dans TeX, et est donc développé, pas pris comme partie du nom de fichier. D'autres programmes, comme Metafont, n'ont pas ce problème.

TEXMFOUTPUT
Normalement, pdfTeX place ses fichiers de sortie dans le répertoire courant. Si un fichier de sortie ne peut pas y être ouvert, il essaie de l'ouvrir dans le répertoire spécifié dans la variable d'environnement TEXMFOUTPUT. Il n'y a pas de valeur par défaut pour cette variable. Par exemple, si vous tapez pdftex paper et que le répertoire courant n'est pas inscriptible et que TEXMFOUTPUT a la valeur /tmp, pdfTeX tente de créer /tmp/paper.log (et /tmp/paper.pdf, si une sortie est produite.) TEXMFOUTPUT est également consulté pour les fichiers d'entrée, car TeX génère souvent des fichiers qui doivent ensuite être lus ; pour l'entrée, aucun suffixe (comme ``.tex'') n'est ajouté par défaut, le nom d'entrée est simplement vérifié tel quel.
TEXINPUTS
Chemin de recherche pour les fichiers \input et \openin. Ceci commence normalement par ``.'', de sorte que les fichiers utilisateur soient trouvés avant les fichiers système. Un composant de chemin vide sera remplacé par les chemins définis dans le fichier texmf.cnf. Par exemple, réglez TEXINPUTS sur ".:/home/user/tex:" pour ajouter le répertoire courant et ``/home/user/tex'' au chemin de recherche standard.
TEXFORMATS
Chemin de recherche pour les fichiers de format.
TEXEDIT
Modèle de commande pour passer à l'éditeur. La valeur par défaut, généralement vi, est définie lors de la compilation de pdfTeX.
TFMFONTS
Chemin de recherche pour les fichiers de métriques de polices (.tfm).
SOURCE_DATE_EPOCH
Si elle est définie, sa valeur, prise en secondes depuis l'époque, sera utilisée pour les horodatages dans la sortie PDF, tels que les clés CreationDate et ModDate. Ceci est utile pour rendre les builds reproductibles.
FORCE_SOURCE_DATE
Si définie à la valeur "1", les primitives TeX liées au temps (\year, \month, \day, \time) sont également initialisées à partir de la valeur de SOURCE_DATE_EPOCH. Ce n'est pas recommandé s'il existe une alternative viable.
pdfTeX dispose également de plusieurs primitives pour prendre en charge les builds reproductibles, qui sont préférables à la définition de ces variables d'environnement ; voir le manuel principal.

De nombreuses autres variables d'environnement peuvent être consultées concernant la recherche de chemins. Voir le manuel Kpathsea.

FICHIERS

L'emplacement des fichiers mentionnés ci-dessous varie d'un système à l'autre. Utilisez l'utilitaire kpsewhich pour trouver leurs emplacements.

pdftex.map
Définitions de mappage des noms de polices.
*.tfm
Fichiers de métriques pour les polices de pdfTeX.
*.fmt
Fichiers de format pdfTeX prédigérés (.fmt).

NOTES

BOGUES

Cette version de pdfTeX ne parvient pas à intercepter les dépassements arithmétiques lors de l'ajout ou de la soustraction de dimensions. Les cas où cela se produit sont rares, mais lorsqu'ils se produisent, le fichier DVI ou PDF généré sera invalide.

DISPONIBILITÉ

pdfTeX est disponible pour une grande variété d'architectures de machines et de systèmes d'exploitation. pdfTeX fait partie de toutes les principales distributions TeX.
