NOM

pdfgrep - recherche dans les fichiers PDF une expression régulière

SYNTAXE

pdfgrep [OPTION...] MOTIF FICHIER...
pdfgrep [OPTION...] {-e MOTIF|-f FICHIER}... FICHIER...
pdfgrep [OPTION...] -r|-R MOTIF [FICHIER|RÉPERTOIRE...]
pdfgrep [OPTION...] -r|-R {-e MOTIF|-f FICHIER}... [FICHIER|RÉPERTOIRE...]

DESCRIPTION

Recherche MOTIF dans chaque FICHIER PDF et imprime les lignes correspondantes. Par défaut, MOTIF est une expression régulière étendue.

pdfgrep essaie d'être largement compatible avec GNU grep avec quelques distinctions spécifiques aux PDF et des options supplémentaires. Notamment, -n imprime les numéros de page au lieu des numéros de ligne.

OPTIONS

Informations Générales

--help

Affiche un bref résumé des options.

-V, --version

Affiche les informations sur la version.

Interprétation du Motif

-F, --fixed-strings

Interprète MOTIF comme une liste de chaînes de caractères fixes séparées par des sauts de ligne, dont l'une quelconque doit correspondre.

-P, --perl-regexp

Interprète MOTIF comme une expression régulière compatible Perl (PCRE2). Voir pcre2syntax(3) pour un aperçu rapide.

Contrôle de la Correspondance

-e MOTIF, --regexp=MOTIF

Utilise MOTIF comme motif de recherche. Si cette option est spécifiée plusieurs fois ou combinée avec --file, tous les motifs sont essayés tour à tour jusqu'à ce que l'un d'eux corresponde.

-f FICHIER, --file=FICHIER

Lit les motifs à partir de FICHIER, un par ligne. Si FICHIER contient plusieurs motifs ou si cette option est appliquée plusieurs fois ou combinée avec -e, tous les motifs sont essayés tour à tour jusqu'à ce que l'un d'eux corresponde. Une liste de motifs vide ne correspond à rien.

-i, --ignore-case

Ignore les distinctions de casse dans le MOTIF et dans les fichiers d'entrée.

Contrôle Général de la Sortie

-c, --count

Supprime la sortie normale. À la place, imprime le nombre de correspondances pour chaque fichier d'entrée. Notez que contrairement à grep, plusieurs correspondances sur la même page seront comptées individuellement.

-p, --page-count

Similaire à -c, mais imprime le nombre de correspondances par page. Implique -n.

--color QUAND

Entoure les noms de fichiers, les numéros de page et le texte correspondant avec des séquences d'échappement pour les afficher en couleur dans le terminal. QUAND peut être :
always Utilise toujours les couleurs, même lorsque la sortie standard n'est pas un terminal.
never N'utilise pas de couleurs.
auto Utilise les couleurs uniquement lorsque la sortie standard est un terminal (c'est le comportement par défaut).

-L, --files-without-match

Supprime la sortie normale. À la place, imprime le nom de chaque fichier d'entrée qui ne contient pas de correspondance. Cela fonctionne bien avec -Z, mais de nombreuses autres options de sortie comme -n ou -c sont ignorées lorsque -L est spécifié.

-l, --files-with-matches

Supprime la sortie normale. À la place, imprime le nom de chaque fichier d'entrée qui contient une correspondance. Cela fonctionne bien avec -Z, mais de nombreuses autres options de sortie comme -n ou -c sont ignorées lorsque -l est spécifié.

-m, --max-count NUM

Arrête de lire un fichier après NUM correspondances. Lorsque l'option -c ou --count est également utilisée, pdfgrep ne génère pas de compte supérieur à NUM.

-o, --only-matching

Imprime uniquement la partie correspondante d'une ligne sans aucun contexte environnant.

-q, --quiet

Supprime toute sortie normale vers la sortie standard. Quitte immédiatement avec un code de sortie de 0 si une correspondance est trouvée, même en cas d'erreurs. Utilisez cette option si vous ne vous souciez que de la présence de correspondances, pas de leur nombre ou de leur contenu.

Contrôle du Préfixe de Ligne

-H, --with-filename

Imprime le nom du fichier pour chaque correspondance. C'est le réglage par défaut lorsqu'il y a plusieurs fichiers à rechercher.

-h, --no-filename

Supprime le préfixe du nom de fichier dans la sortie. C'est le réglage par défaut lorsqu'il n'y a qu'un seul fichier à rechercher.

-n, --page-number[=TYPE]

Précède chaque correspondance du numéro de la page où elle a été trouvée.

L'argument optionnel TYPE contrôle comment les numéros de page sont déterminés. S'il est présent, il peut être l'un des suivants :

index L'index de la page dans le PDF, commençant à 1 pour la première page. C'est le comportement par défaut.
label L'étiquette de la page PDF. Il peut s'agir d'une chaîne de caractères arbitraire par page, définie par le créateur du PDF (par exemple, des chiffres romains pour les premières pages).

-Z, --null

Émet un octet nul (appelé NUL en ASCII et '\0' en C) au lieu du deux-points qui sépare habituellement un nom de fichier du reste de la ligne. Cette option rend la sortie non ambiguë en présence de deux-points, d'espaces ou de sauts de ligne dans le nom de fichier. Elle peut être utilisée conjointement avec des commandes telles que xargs -0 ou perl -0.

--match-prefix-separator SEP

Remplace le deux-points utilisé pour séparer le nom de fichier, le numéro de page et le texte dans la sortie par SEP, qui peut être une chaîne de caractères arbitraire. C'est utile lorsque les noms de fichiers contiennent des deux-points, mais uniquement pour une utilisation interactive. Pour les scripts, --null doit être utilisé.

Contrôle du Contexte

-A NUM, --after-context=NUM

Imprime NUM lignes de contexte après les lignes correspondantes. Les groupes contigus de correspondances sont séparés par une ligne contenant --. Avec -o, cette option n'a aucun effet.

-B NUM, --before-context=NUM

Imprime NUM lignes de contexte avant les lignes correspondantes. Les groupes contigus de correspondances sont séparés par une ligne contenant --. Avec -o, cette option n'a aucun effet.

-C NUM, --context=NUM

Imprime NUM lignes de contexte avant et après les lignes correspondantes. Les groupes contigus de correspondances sont séparés par une ligne contenant --. Avec -o, cette option n'a aucun effet.

Sélection des Fichiers

-r, --recursive

Recherche récursivement tous les fichiers (restreints par --include et --exclude) sous chaque répertoire, en suivant les liens symboliques uniquement s'ils sont sur la ligne de commande.

-R, --dereference-recursive

Identique à -r, mais suit tous les liens symboliques.

--exclude=GLOB

Ignore les fichiers dont le nom de base correspond à GLOB. Voir glob(7) pour les caractères génériques que vous pouvez utiliser. Vous pouvez utiliser cette option plusieurs fois pour exclure plus de motifs. Elle a la priorité sur --include. Notez que les inclusions et exclusions ne s'appliquent qu'aux fichiers trouvés via --recursive et non à la liste des arguments.

--include=GLOB

Ne recherche que les fichiers dont le nom de base correspond à
i>GLOB. Voir --exclude pour les détails. La valeur par défaut est *.[Pp][Dd][Ff].

Autres options

--cache

Utilise un cache pour le texte rendu afin d'accélérer l'opération sur les fichiers volumineux.

--password=MOTDEPASSE

Utilise MOTDEPASSE pour décrypter les fichiers PDF. Peut être spécifié plusieurs fois ; tous les mots de passe seront essayés sur tous les PDF. **Notez** que ce mot de passe apparaîtra dans votre historique de commandes et dans la sortie de ps(1). Veuillez donc ne pas l'utiliser si la sécurité de MOTDEPASSE est importante.

--page-range=PLAGE

Limite la recherche à un ensemble de pages spécifié. PLAGE est une liste séparée par des virgules soit d'un numéro de page unique, soit d'une expression de plage de la forme PAGE1-PAGE2. Exemple : 2-3,5,7-10.

--debug

Active la sortie de débogage. **Notez** : En raison des limitations de poppler avant la version 0.30.0, certaines sorties de débogage sont également imprimées sans --debug lors de l'utilisation d'une telle version de poppler.

--warn-empty

Affiche un avertissement sur stderr si un PDF ne contient aucun texte consultable. C'est le cas pour les PDF qui ne contiennent que des images, par exemple les documents numérisés.

--unac

Supprime les accents et les ligatures du modèle de recherche et des documents PDF. Ceci est utile si vous souhaitez rechercher un mot contenant « ae », mais que le PDF utilise le caractère unique « æ » à la place. Voir unac(3) et unaccent(1) pour les détails.

**Cette option est expérimentale et n'est disponible que si pdfgrep est compilé avec le support d'unac.**

Statut de sortie

Normalement, le statut de sortie est 0 si au moins une correspondance est trouvée, 1 si aucune correspondance n'est trouvée et 2 si une erreur s'est produite. Mais si l'option --quiet ou -q est utilisée et qu'une correspondance a été trouvée, pdfgrep retournera 0 indépendamment des erreurs.

Variables d'environnement

Le comportement de pdfgrep est affecté par la variable d'environnement suivante.

GREP_COLORS

Spécifie les couleurs et autres attributs utilisés pour mettre en évidence différentes parties de la sortie. La syntaxe et les valeurs sont similaires à celles de GREP_COLORS de grep. Voir grep(1) pour plus de détails. Actuellement, seules les capacités mt, ms, mc, fn, ln et se sont utilisées par pdfgrep, où mt, ms et mc ont le même effet.

Fichiers

${XDG_CACHE_HOME}/pdfgrep/*

Fichiers cache écrits et utilisés lorsque --cache est activé. Au plus 200 entrées de cache plus anciennes qu'un jour sont conservées.

Exemples

Imprimer les dix premières lignes correspondant à motif et imprimer leur numéro de page :

pdfgrep -n --max-count 10 motif foo.pdf

Rechercher récursivement dans le répertoire courant tous les fichiers .pdf dont les noms commencent par foo :

pdfgrep -r --include "foo*.pdf" motif

Rechercher tous les PDF dans le répertoire courant pour foo qui contiennent également bar :

pdfgrep -Z --files-with-matches "bar" *.pdf | xargs -0 pdfgrep -H foo

Rechercher récursivement dans le répertoire courant tous les fichiers .pdf dont la taille est inférieure à 12 Mo :

find . -name "*.pdf" -size -12M -print0 | xargs -0 pdfgrep motif

Notez que contrairement aux exemples précédents, cette tâche n'a pas pu être résolue avec pdfgrep seul, mais les outils Unix find(1) et xargs(1) ont dû être utilisés. C'est parce que pdfgrep lui-même n'inclut pas d'options pour exclure des fichiers en fonction de leur taille. Mais comme vous pouvez le voir, il n'a pas à le faire !

Rechercher tous les fichiers .pdf dans le répertoire courant en parallèle sur un CPU multicœur

find . -name "*.pdf" -print0 | parallel -q0 pdfgrep -H foobar

Ceci utilise GNU parallel(1) en plus de find(1) pour rechercher plusieurs fichiers en parallèle sur des processeurs multicœurs. Cela peut entraîner une bonne accélération si vous avez plusieurs fichiers à rechercher et un CPU sous-utilisé.

Rapporter des bogues

Les bogues peuvent être signalés à la liste de diffusion (pdfgrep-users@pdfgrep.org) ou au système de suivi des bogues sur gitlab (https://gitlab.com/pdfgrep/pdfgrep/issues).
