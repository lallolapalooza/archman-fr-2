NOM

pdnsd-ctl - contrôle pdnsd

SYNTAXE

pdnsd-ctl [-c repertoire_cache] [-q] commande [arguments]

DESCRIPTION

pdnsd-ctl contrôle pdnsd, un serveur DNS proxy avec mise en cache permanente. Notez que le socket de contrôle d'état doit être activé (en spécifiant une option sur la ligne de commande de pdnsd ou dans le fichier de configuration) avant de pouvoir utiliser pdnsd-ctl.

-c repertoire_cache
Définit le répertoire de cache à repertoire_cache (doit correspondre au réglage de pdnsd). Ceci n'est nécessaire que si le répertoire diffère de celui par défaut spécifié à la compilation.
-q
Soyez silencieux sauf si une sortie est spécifiée par la commande ou si quelque chose se passe mal.

COMMANDES

help   [aucun argument]

Affiche un résumé des commandes.

version [aucun argument]

Affiche la version et les informations de licence.

status [aucun argument]

Affiche une description de l'état du cache de pdnsd, de l'état des threads et de la configuration. Indique également quels serveurs de noms distants sont supposés être disponibles.

server (index|libelle) (up|down|retest) [dns1[,dns2[,...]]]

Définit l'état des serveurs avec l'index ou le libellé donné à actif ou inactif, ou force un re-test. L'index est attribué dans l'ordre de définition dans pdnsd.conf en commençant par 0. Utilisez la commande status pour voir les index. Vous pouvez spécifier all au lieu d'un index pour effectuer l'action pour tous les serveurs enregistrés avec pdnsd.

Un troisième argument optionnel peut être donné, consistant en une liste d'adresses IP séparées par des virgules ou des espaces blancs. Cette liste remplacera les adresses des serveurs de noms utilisés par pdnsd pour la section serveur donnée. Cette fonctionnalité est utile pour la configuration à chaud de pdnsd avec des données DNS dynamiques dans des scripts appelés par des clients ppp ou DHCP. Le dernier argument peut également être une chaîne vide, ce qui provoque la suppression des adresses IP existantes et rend la section serveur correspondante inactive.
record nom (delete|invalidate)

Supprime ou invalide les enregistrements du nom de domaine donné s'il est dans le cache. L'invalidation signifie que les enregistrements sont marqués comme expirés, et seront rechargés si possible. Pour les enregistrements locaux (c'est-à-dire, les enregistrements qui ont été donnés dans le fichier de configuration en utilisant une section rr, les enregistrements lus depuis un fichier de style hosts et les enregistrements ajoutés via pdnsd-ctl), l'invalidation n'a aucun effet. La suppression fonctionnera, cependant.

source fn proprietaire [ttl] [(on|off)] [noauth]

Charge un fichier de style hosts. Fonctionne comme l'utilisation de la section de configuration source de pdnsd. Propriétaire et ttl sont utilisés comme dans la section source. ttl a une valeur par défaut de 900 (il n'a pas besoin d'être spécifié). L'avant-dernier argument correspond à l'option serve_aliases, et est inactif par défaut. noauth est utilisé pour rendre les domaines non-autoritaires (ceci est similaire à la définition de authrec=off dans le fichier de configuration, veuillez consulter la page man de pdnsd.conf(5) pour savoir ce que cela signifie). fn est le nom du fichier, qui doit être lisible par pdnsd.

add    a addr nom [ttl] [noauth]
add    aaaa addr nom [ttl] [noauth]
add    ptr host nom [ttl] [noauth]
add    cname host nom [ttl] [noauth]
add    mx host nom pref [ttl] [noauth]

Ajoute un enregistrement du type donné au cache pdnsd, en remplaçant les enregistrements existants pour le même nom et type. Le 2ème argument correspond à la valeur de l'option dans la section rr qui est nommée comme le premier argument. L'argument addr peut être une liste d'adresses IP, séparées par des virgules ou des espaces blancs. Le ttl est optionnel, la valeur par défaut est 900 secondes. noauth est utilisé pour rendre les domaines non-autoritaires (ceci est similaire à la définition de authrec=off dans le fichier de configuration, veuillez consulter la page man de pdnsd.conf(5) pour savoir ce que cela signifie). Si vous ne voulez aucun autre enregistrement que celui nouvellement ajouté dans le cache, exécutez pdnsd-ctl record nom delete avant d'ajouter des enregistrements.

neg    nom [type] [ttl]

Ajoute un enregistrement mis en cache négativement dans le cache de pdnsd, en remplaçant les enregistrements existants pour le même nom et type. Si aucun type n'est donné, le domaine entier est mis en cache négativement. Pour les enregistrements mis en cache négativement, les erreurs sont immédiatement retournées lors d'une requête, sans interroger d'autres serveurs au préalable. Le ttl est optionnel, la valeur par défaut est 900 secondes.

config nom_fichier

Recharge le fichier de configuration de pdnsd.
Le fichier de configuration doit appartenir à l'uid que pdnsd avait lors de son démarrage, et être lisible par l'uid d'exécution de pdnsd. Si aucun nom de fichier n'est spécifié, le fichier de configuration utilisé au démarrage est rechargé. Notez que certains changements de configuration, comme le port ou l'adresse IP sur lesquels pdnsd écoute, ne peuvent pas être effectués ainsi et vous recevrez un message d'erreur. Dans ces cas, vous devrez redémarrer pdnsd à la place.

include nom_fichier

Analyse un fichier inclus.
Le fichier inclus peut contenir le même type de sections qu'un fichier de configuration, à l'exception des sections global et server, qui ne sont pas autorisées. Cette commande peut être utilisée pour ajouter des données au cache sans reconfigurer pdnsd.

eval   chaîne

Analyse une chaîne comme si elle faisait partie d'un fichier inclus.
La chaîne doit contenir une ou plusieurs sections de configuration complètes, mais aucune section global et server, qui ne sont pas autorisées. Si plusieurs chaînes sont données, elles seront jointes en utilisant des caractères de nouvelle ligne et analysées ensemble.

empty-cache [[+|-]nom ...]

Supprime toutes les entrées du cache correspondant aux règles d'inclusion/exclusion.
Si aucun argument n'est fourni, le cache est complètement vidé, libérant toutes les entrées existantes. Notez que cela supprime également les enregistrements locaux, tels que définis par le fichier de configuration. Pour restaurer les enregistrements locaux, exécutez "pdnsd-ctl config" immédiatement après.
Si un ou plusieurs arguments sont fournis, ceux-ci sont interprétés comme des noms d'inclusion/exclusion. Si un argument commence par un '+', le nom est à inclure. Si un argument commence par un '-', il est à exclure. Si un argument ne commence ni par '+' ni par '-', un '+' est supposé. Si le nom de domaine d'une entrée de cache se termine par l'un des noms de la liste, la première correspondance déterminera ce qui se passe. Si le nom correspondant doit être inclus, l'entrée du cache est supprimée, sinon elle reste. S'il n'y a pas de correspondance, l'action par défaut est de ne pas supprimer.

dump   [nom]

Affiche les informations stockées dans le cache concernant nom. Si nom commence par un point et n'est pas le domaine racine, des informations sur les noms dans le cache se terminant par nom (

(y compris nom sans le point de départ) sera imprimé. Si nom n'est pas spécifié, des informations sur tous les noms du cache seront imprimées.

list-rrtypes [aucun argument]

Liste les types de RR disponibles pour la commande neg. Notez que ceux-ci ne sont utilisés que pour la commande neg, pas pour add !

BOGUES

Si vous redirigez la sortie de la commande dump via une application qui ne lit qu'une partie de la sortie puis se bloque (comme more ou less), les threads de pdnsd qui essaient d'ajouter de nouvelles entrées au cache seront suspendus jusqu'à ce que le pipe soit fermé. Il est préférable de capturer la sortie dans un fichier dans un tel cas.
Signalez tout bogue restant aux auteurs.
