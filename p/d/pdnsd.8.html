PDNSD(8) Commandes d'administration système PDNSD(8)

NOM

pdnsd - serveur DNS proxy

SYNTAXE

pdnsd [-h] [-V] [-s] [-d] [-g] [-t] [-p fichier] [-vn] [-mxx] [-c fichier] [-4] [-6] [-a]

Cette page de manuel est un extrait de la documentation de pdnsd. Pour une documentation complète et actuelle, veuillez vous référer à la documentation HTML (ou texte brut) (que vous pouvez trouver dans le sous-répertoire doc/ des sources ou dans un répertoire de documentation standard, typiquement /usr/share/doc/pdnsd/ si vous utilisez un paquet binaire).

DESCRIPTION

pdnsd est un serveur DNS (Domain Name Server) proxy compatible IPv6 qui sauvegarde le contenu de son cache DNS sur le disque à la sortie.

OPTIONS

-4
active le support IPv4. Le support IPv6 est automatiquement désactivé (s'il est disponible). Activé par défaut.
-6
active le support IPv6. Le support IPv4 est automatiquement désactivé (s'il est disponible). Désactivé par défaut.
-a
Avec cette option, pdnsd essaiera de détecter automatiquement si le système supporte l'IPv6, et se rabattra sur l'IPv4 sinon.
-V ou --version
Affiche les informations de version et quitte.
-c FICHIER ou --config-file=FICHIER
spécifie que la configuration doit être lue depuis FICHIER. Par défaut, c'est /etc/pdnsd.conf.
-d ou --daemon
Démarre pdnsd en mode démon (en tant que processus d'arrière-plan).
-g ou --debug
Affiche des messages de débogage sur la console ou dans le fichier pdnsd.debug dans votre répertoire de cache (en mode démon).
-h ou --help
Affiche un résumé des options et quitte.
-i PREFIXE ou --ipv4_6_prefix=PREFIXE
spécifie le préfixe que pdnsd utilise (lorsqu'il fonctionne en mode IPv6) pour mapper les adresses IPv4 du fichier de configuration en adresses IPv6. Doit être une adresse IPv6 valide. Par défaut, c'est ::ffff:0.0.0.0
-p FICHIER
écrit le pid du serveur en cours d'exécution dans le nom de fichier spécifié. Ne fonctionne qu'en mode démon.
--pdnsd-user
Affiche l'utilisateur sous lequel pdnsd s'exécutera et quitte.
-s ou --status
active le socket de contrôle d'état. Soit cette option doit être passée en ligne de commande, soit status_ctl=on; doit être spécifié dans le fichier de configuration si vous souhaitez utiliser pdnsd-ctl(8) pour contrôler pdnsd en temps réel.
-t ou --tcp
active le thread serveur TCP. pdnsd servira alors les requêtes TCP et UDP.
-vn
définit la verbosité de pdnsd. n est un argument numérique entre 0 (fonctionnement normal) et 3 (beaucoup de messages pour le débogage).
-mxx
définit la méthode de requête que pdnsd utilise. Les valeurs possibles pour xx sont :
uo - pdnsd utilisera uniquement UDP. C'est la méthode la plus rapide, et elle devrait être prise en charge par tous les serveurs de noms sur Internet.
to - pdnsd utilisera uniquement TCP. Les requêtes TCP prennent généralement plus de temps que les requêtes UDP, mais sont plus sûres contre certaines attaques où un attaquant essaie de deviner votre ID de requête et d'envoyer des réponses falsifiées. Les requêtes TCP ne sont pas prises en charge par tous les serveurs de noms.
tu - pdnsd essaiera d'utiliser TCP et se rabattra sur UDP si sa connexion est refusée ou expire.
ut - pdnsd essaiera d'utiliser UDP et répétera la requête en utilisant TCP si la réponse UDP était tronquée (c'est-à-dire si le bit tc est activé). C'est le comportement recommandé par les standards DNS.

De plus, « no » peut être préfixé aux options --status, --daemon, --debug et --tcp (par exemple --notcp) pour inverser leur effet.

UTILISATION

pdnsd est généralement lancé depuis un script de démarrage. Pour que pdnsd fonctionne, vous devez :

1. Indiquer à votre système d'utiliser pdnsd comme serveur DNS principal en modifiant /etc/resolv.conf.
2. Indiquer à pdnsd d'utiliser une source authentique pour les enregistrements DNS, en incluant les adresses IP d'un ou plusieurs serveurs DNS, généralement les serveurs DNS de votre FAI, dans /etc/pdnsd.conf.

Pour cela, placez la ligne suivante dans votre /etc/resolv.conf

nameserver 127.0.0.X

où X peut être n'importe quel nombre. (J'utilise 3). Commentez toutes les autres entrées. Vous devriez mettre la même valeur sur la ligne server_ip= dans la section global de /etc/pdnsd.conf.
Si vous souhaitez utiliser pdnsd comme serveur DNS pour un petit réseau local, vous devriez utiliser l'adresse IP ou le nom de l'interface connectée à ce réseau à la place de 127.0.0.X.

Pour indiquer à pdnsd où obtenir les informations DNS, ajoutez les lignes suivantes dans /etc/pdnsd.conf :

server {
label= "myisp";
ip=123.456.789.001,123.456.789.002;
proxy_only=on;
timeout=10;
}

Notez les accolades ouvrantes et fermantes. Ajoutez d'autres sections server similaires pour chaque ensemble de serveurs DNS que vous souhaitez que pdnsd interroge. Bien sûr, les options de configuration présentées ici ne sont que des exemples. D'autres exemples se trouvent dans /etc/pdnsd.conf.sample ou dans le pdnsd.conf du répertoire de documentation. Voir la page de manuel pdnsd.conf(5) pour toutes les options possibles et leur signification exacte.

Si vous utilisez une connexion dial-up, n'oubliez pas que les scripts ppp remplacent généralement /etc/resolv.conf lors de l'établissement de la connexion avec le FAI. Vous devez configurer ppp (ou tout autre outil que vous utilisez pour établir une connexion) de manière à ce que /etc/resolv.conf ne soit pas remplacé à chaque établissement de connexion. Lisez la documentation des scripts exécutés lorsque votre réseau devient opérationnel.

Si vous utilisez pppconfig, spécifiez `none' dans l'option `nameservers' dans l'onglet `advanced'. Si vous utilisez plusieurs FAI, vous devriez faire cela pour chaque connexion/compte.

Si vous utilisez plusieurs FAI, vous devriez indiquer à pdnsd quels serveurs DNS sont devenus disponibles en appelant pdnsd-ctl, l'utilitaire de contrôle de pdnsd, dans un script (par exemple, /etc/ppp/ip-up lorsque vous utilisez pppd) qui est exécuté lorsque la connexion est établie. Si les adresses des serveurs DNS sont obtenues via un protocole de configuration dynamique (par exemple, pppd avec l'option usepeerdns ou un client DHCP), vous pouvez passer les adresses des serveurs DNS comme argument supplémentaire à pdnsd-ctl pour configurer pdnsd en temps réel. Voir la page de manuel pdnsd-ctl(8) pour plus de détails.

FICHIERS

/etc/pdnsd.conf est le fichier de configuration de pdnsd. Le format du fichier et les options de configuration sont décrits dans la page de manuel pdnsd.conf(5). Vous pouvez trouver des exemples de presque toutes les options dans /etc/pdnsd.conf.sample.

/var/cache/pdnsd/pdnsd.cache

/var/cache/pdnsd/pdnsd.status est le socket de contrôle d'état, qui doit être activé avant que vous puissiez utiliser pdnsd-ctl.

/etc/init.d/pdnsd (le nom et l'emplacement du script de démarrage peuvent différer selon votre distribution.)

/etc/resolv.conf

/etc/defaults/pdnsd contient des paramètres ou options supplémentaires qui peuvent être passés à pdnsd au démarrage. Cela évite d'avoir à modifier les scripts d'initialisation (non disponible sur toutes les distributions).

BOGUES

L'option de verbosité -vn ne semble pas avoir beaucoup d'effet sur la quantité de sortie de débogage.
Signalez tout bogue restant aux auteurs.

CONFORMITE

pdnsd devrait être conforme aux RFC 1034 et 1035. À partir de la version 1.0.0, la conformité aux RFC

amélioré et pdnsd est maintenant considéré (ou espéré ?) comme entièrement compatible avec les RFC. Il suit entièrement la RFC 2181 (sauf pour un problème mineur dans le port FreeBSD, voir la documentation). Il ne prend PAS en charge les fonctionnalités suivantes, dont la plupart sont marquées comme optionnelles, expérimentales ou obsolètes dans ces RFC : * Requêtes inverses * Requêtes de statut * Requêtes de complétion * Espaces de noms autres que IN (Internet) * Requêtes AXFR et IXFR (transferts de zones entières) ; comme pdnsd ne maintient pas de zones, cela ne devrait pas enfreindre la norme. Les types d'enregistrements suivants, qui sont des extensions à la norme DNS d'origine, sont pris en charge s'ils sont spécifiés comme options lors de la compilation. (si vous n'en avez pas besoin, vous n'avez pas besoin de compiler le support pour ceux-ci dans pdnsd et vous économiserez de l'espace de cache et d'exécutable) : * RP (personne responsable, RFC 1183) * AFSDB (emplacement de la base de données AFS, RFC 1183) * X25 (adresse X25, RFC 1183) * ISDN (numéro/adresse ISDN, RFC 1183) * RT (route via, RFC 1183) * NSAP (adresse Network Service Access Protocol, RFC 1348) * PX (informations de mappage X.400/RFC822, RFC 1995) * GPOS (position géographique, obsolète) * AAAA (adresse IPv6, RFC 1886) * LOC (emplacement, RFC 1876) * EID (EID Nimrod) * NIMLOC (localisateur Nimrod) * SRV (enregistrement de service, RFC 2782) * ATMA (adresse ATM) * NAPTR (mappage URI, RFC 2168) * KX (échange de clés, RFC 2230)
