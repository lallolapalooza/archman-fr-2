PDFTK(1) Manuel des commandes générales PDFTK(1)

NOM

pdftk - Un outil pratique pour manipuler les PDF

SYNTAXE

pdftk <fichiers PDF d'entrée | - | INVITE>
[ input_pw <mots de passe propriétaire PDF d'entrée | INVITE> ]
[ <opération> <arguments de l'opération> ]
[ output <nom de fichier de sortie | - | INVITE> ]
[ encrypt_40bit | encrypt_128bit | encrypt_aes128 ]
[ allow <permissions> ]
[ owner_pw <mot de passe propriétaire | INVITE> ]
[ user_pw <mot de passe utilisateur | INVITE> ]
[ flatten ] [ need_appearances ]
[ compress | uncompress ]
[ keep_first_id | keep_final_id ] [ drop_xfa ] [ drop_xmp ]
[ replacement_font <nom de police> ]
[ verbose ] [ dont_ask | do_ask ]
Où:
<opération> peut être vide, ou:
[ cat | shuffle | burst | rotate |
generate_fdf | fill_form |
background | multibackground |
stamp | multistamp |
dump_data | dump_data_utf8 |
dump_data_fields | dump_data_fields_utf8 |
dump_data_annots |
update_info | update_info_utf8 |
attach_files | unpack_files ]

Pour une aide complète : pdftk --help

DESCRIPTION

Si le PDF est du papier électronique, alors pdftk est une agrafeuse-dégrafeuse, une perforeuse, une relieuse, un anneau de décodage secret et des lunettes a rayons X électroniques. Pdftk est un outil simple pour effectuer des tâches quotidiennes avec des documents PDF. Utilisez-le pour :

* Fusionner des documents PDF ou Coller des numérisations de pages PDF
* Séparer des pages PDF dans un nouveau document
* Faire pivoter des documents ou des pages PDF
* Déchiffrer l'entrée au besoin (Mot de passe requis)
* Chiffrer la sortie au besoin
* Remplir des formulaires PDF avec des données X/FDF et/ou aplatir les formulaires
* Générer des gabarits de données FDF à partir de formulaires PDF
* Appliquer un filigrane d'arrière-plan ou un tampon de premier plan
* Rapporter les métriques, signets et métadonnées PDF
* Ajouter/Mettre à jour les métriques, signets ou métadonnées PDF
* Joindre des fichiers à des pages PDF ou au document PDF
* Décompresser des pièces jointes PDF
* Décompresser un document PDF en pages individuelles
* Décompresser et Re-compresser les flux de pages
* Réparer des PDF corrompus (lorsque possible)

OPTIONS

Un résumé des options est inclus ci-dessous.

--help, -h
Afficher ce résumé des options.
<fichiers PDF d'entrée | - | INVITE>
Une liste des fichiers PDF d'entrée. Si vous prévoyez de combiner ces PDF (sans utiliser de poignées), listez les fichiers dans l'ordre où vous souhaitez qu'ils soient combinés. Utilisez - pour passer un seul PDF dans pdftk via stdin. Les fichiers d'entrée peuvent être associés à des poignées, où une poignée est une ou plusieurs lettres majuscules :

<poignée PDF d'entrée>=<nom de fichier PDF d'entrée>

Les poignées sont souvent omises. Elles sont utiles lorsque vous spécifiez des mots de passe PDF ou des plages de pages, plus tard.

Par exemple : A=input1.pdf QT=input2.pdf M=input3.pdf

[input_pw <mots de passe propriétaire PDF d'entrée | INVITE>]
Les mots de passe propriétaire des PDF d'entrée, si nécessaire, sont associés aux fichiers en utilisant leurs poignées :

<poignée PDF d'entrée>=<mot de passe propriétaire du fichier PDF d'entrée>

Si les poignées ne sont pas fournies, les mots de passe sont associés aux fichiers d'entrée par ordre.

La plupart des fonctionnalités de pdftk nécessitent que les PDF d'entrée chiffrés soient accompagnés du mot de passe du ~propriétaire~. Si le PDF d'entrée n'a pas de mot de passe propriétaire, le mot de passe utilisateur doit être donné à la place. Si le PDF d'entrée n'a pas de mot de passe, aucun mot de passe ne doit être donné.

Lors de l'exécution en mode do_ask, pdftk vous demandera un mot de passe si le mot de passe fourni est incorrect ou si aucun n'a été donné.

[<opération> <arguments de l'opération>]
Les opérations disponibles sont : cat, shuffle, burst, rotate, generate_fdf, fill_form, background, multibackground, stamp, multistamp, dump_data, dump_data_utf8, dump_data_fields, dump_data_fields_utf8, dump_data_annots, update_info, update_info_utf8, attach_files, unpack_files. Certaines opérations prennent des arguments supplémentaires, décrits ci-dessous.

Si cet argument facultatif est omis, pdftk s'exécute en mode 'filtre'. Le mode filtre ne prend qu'une seule entrée PDF et crée un nouveau PDF après avoir appliqué toutes les options de sortie, comme le chiffrement et la compression.

cat [<plages de pages>]
Assemble (concaténe) les pages des PDF d'entrée pour créer un nouveau PDF. Utilisez cat pour fusionner des pages PDF ou pour extraire des pages PDF de documents. Vous pouvez également l'utiliser pour faire pivoter des pages PDF. L'ordre des pages dans le nouveau PDF est spécifié par l'ordre des plages de pages données. Les plages de pages sont décrites comme suit :

<poignée PDF d'entrée>[<numéro de page de début>[-<numéro de page de fin>[<qualificatif>]]][<rotation de page>]

Où la poignée identifie l'un des fichiers PDF d'entrée, et les numéros de page de début et de fin sont des références basées sur un pour les pages du fichier PDF. Le qualificatif peut être even, odd, ou ~, et la rotation de page peut être north, south, east, west, left, right, ou down.

Si une poignée PDF est donnée mais aucune page n'est spécifiée, alors le PDF entier est utilisé. Si aucune page n'est spécifiée pour aucun des PDF d'entrée, alors les signets des PDF d'entrée sont également fusionnés et inclus dans la sortie.

Si la poignée est omise de la plage de pages, alors les pages sont prises du premier fichier PDF d'entrée.

Le qualificatif even fait que pdftk utilise uniquement les pages PDF numérotées paires, donc 1-6even produit les pages 2, 4 et 6 dans cet ordre. 6-1even produit les pages 6, 4 et 2 dans cet ordre.

Le qualificatif odd fonctionne de manière similaire à even.

Les pages peuvent être soustraites d'une plage de pages en utilisant le qualificatif ~ suivi d'une plage de pages. Par exemple, 1-20~5-6 et 1-20~5~6 sont équivalents à 1-4 7-20, et ~5 produit toutes les pages sauf la page 5. Selon votre shell, vous devrez peut-être mettre cet argument entre guillemets à cause du ~ au début.

Le paramètre de rotation de page peut amener pdftk à faire pivoter les pages et les documents. Chaque option définit la rotation de page comme suit (en degrés) : north : 0, east : 90, south : 180, west : 270, left : -90, right : +90, down : +180. left, right, et down font des ajustements relatifs à la rotation d'une page.

Si aucun argument n'est passé à cat, pdftk combine tous les PDF d'entrée dans l'ordre où ils ont été donnés pour créer la sortie.

NOTES :
* <numéro de page de fin> peut être inférieur à <numéro de page de début>.
* Le mot-clé end peut être utilisé pour faire référence à la dernière page d'un document au lieu d'un numéro de page.
* Référencez une seule page en omettant le numéro de page de fin.
* La poignée peut être utilisée seule pour représenter le document PDF entièr, par exemple, B1-end est la même chose que B.
* Vous pouvez référencer les numéros de page dans l'ordre inverse en les préfixant avec la lettre r. Par exemple, la page r1 est la dernière page du document, r2 est l'avant-dernière page du document, et rend est la première page du document. Vous pouvez utiliser ce préfixe dans les plages également, par exemple r3-r1 sont les trois dernières pages d'un PDF.

Exemples de plages de pages sans poignées :
1\-endeast – faire pivoter l'ensemble du document de 90 degrés
5 11 20 – prendre des pages individuelles du PDF d'entrée
5-25oddwest – prendre les pages impaires de la plage, faire pivoter de 90 degrés
6-1 – inverser les pages dans la plage du fichier PDF d'entrée

Exemples de plages de pages avec poignées :
Disons A=in1.pdf B=in2.pdf, alors :
A1-21 – prendre la plage de in1.pdf
Bend-1odd –

; prendre toutes les pages impaires de in2.pdf dans l'ordre inverse
A72 – prendre une seule page de in1.pdf
A1-21 Beven A72 – assembler des pages de in1.pdf et de in2.pdf
Awest – faire pivoter le document in1.pdf entier de 90 degrés
B – utiliser tout in2.pdf
A2-30evenleft – prendre les pages paires de la plage, retirer 90 degrés de la rotation de chaque page
A A – concaténer in1.pdf avec in1.pdf
Aevenwest Aoddeast – appliquer des rotations aux pages paires, pages impaires de in1.pdf
Awest Bwest Bdown – concaténer les documents pivotés

shuffle [<page ranges>]
Collationne les pages des PDF d'entrée pour créer un nouveau PDF. Fonctionne comme l'opération cat, sauf qu'elle prend une page à la fois de chaque plage de pages pour assembler le PDF de sortie. Si une plage est épuisée, elle continue avec les plages restantes. Les plages peuvent utiliser toutes les fonctionnalités décrites ci-dessus pour cat, comme les plages de pages inversées, les plages multiples d'un seul PDF et la rotation des pages. Cette fonctionnalité a été conçue pour aider à collationner les pages PDF après la numérisation de documents papier.
burst
Divise un seul document PDF d'entrée en pages individuelles. Crée également un rapport nommé doc_data.txt qui est identique à la sortie de dump_data. La section output peut contenir une chaîne de format de type printf pour nommer ces pages. Par exemple, si vous souhaitez des pages nommées page_01.pdf, page_02.pdf, etc., passez output page_%02d.pdf à pdftk. Si le modèle est omis, alors un modèle par défaut g_%04d.pdf est ajouté et produit des pages nommées pg_0001.pdf, pg_0002.pdf, etc. Le chiffrement peut être appliqué à la sortie en ajoutant des options de sortie telles que owner_pw, par exemple :

pdftk in.pdf burst owner_pw foopass

rotate [<page ranges>]
Prend un seul PDF d'entrée et fait pivoter uniquement les pages spécifiées. Toutes les autres pages restent inchangées. L'ordre des pages reste inchangé. Spécifiez les pages à faire pivoter en utilisant la même notation que celle que vous utiliseriez avec cat, sauf que vous omettez les pages que vous ne faites pas pivoter :

[<numéro de page de début>[-<numéro de page de fin>[<qualificatif>]]][<rotation de page>]

Le qualificatif peut être even ou odd, et la rotation de page peut être north, south, east, west, left, right, ou down.

Chaque option définit la rotation de la page comme suit (en degrés) : north : 0, east : 90, south : 180, west : 270, left : -90, right : +90, down : +180. left, right et down effectuent des ajustements relatifs à la rotation d'une page.

L'ordre donné des pages ne modifie pas l'ordre des pages dans la sortie.

generate_fdf
Lit un seul fichier PDF d'entrée et génère un fichier FDF adapté pour fill_form à partir de celui-ci vers le nom de fichier de sortie donné ou (si aucune sortie n'est donnée) vers stdout. Ne crée pas de nouveau PDF.
fill_form <FDF nom de fichier de données | nom de fichier de données XFDF | - | PROMPT>
Remplit les champs de formulaire du PDF d'entrée unique avec les données d'un fichier FDF, fichier XFDF ou stdin. Entrez le nom du fichier de données après fill_form, ou utilisez - pour passer les données via stdin, comme suit :

pdftk form.pdf fill_form data.fdf output form.filled.pdf

Si le fichier FDF d'entrée inclut des données au format Rich Text en plus du texte brut, alors les données Rich Text sont empaquetées dans les champs du formulaire *ainsi que* le texte brut. Pdftk définit également un indicateur qui invite Reader/Acrobat à générer de nouvelles apparences de champ basées sur les données Rich Text. Ainsi, lorsque l'utilisateur ouvre le PDF, la visionneuse crée l'apparence Rich Text sur place. Si la visionneuse PDF de l'utilisateur ne prend pas en charge Rich Text, alors l'utilisateur verra les données en texte brut à la place. Si vous aplatissez ce formulaire avant qu'Acrobat n'ait la chance de créer (et d'enregistrer) de nouvelles apparences de champ, alors ce sont les données de champ en texte brut que vous verrez.

Voir également les options flatten, need_appearances et replacement_font.

background <nom de fichier PDF de fond | - | PROMPT>
Applique un filigrane PDF en arrière-plan d'un seul PDF d'entrée. Passez le nom du fichier PDF de fond après background comme suit :

pdftk in.pdf background back.pdf output out.pdf

Pdftk utilise uniquement la première page du PDF de fond et l'applique à chaque page du PDF d'entrée. Cette page est mise à l'échelle et pivotée si nécessaire pour s'adapter à la page d'entrée. Vous pouvez utiliser - pour passer un PDF de fond via stdin.

Si le PDF d'entrée n'a pas d'arrière-plan transparent (comme un PDF créé à partir de scans de pages), alors l'arrière-plan résultant ne sera pas visible – utilisez plutôt l'opération stamp.

multibackground <nom de fichier PDF de fond | - | PROMPT>
Identique à l'opération background, mais applique chaque page du PDF de fond à la page correspondante du PDF d'entrée. Si le PDF d'entrée a plus de pages que le PDF de tampon, alors la dernière page de tampon est répétée sur ces pages restantes du PDF d'entrée.
stamp <nom de fichier PDF de tampon | - | PROMPT>
Cela se comporte exactement comme l'opération background, sauf qu'il superpose la page PDF de tampon *au-dessus* des pages du document PDF d'entrée. Cela fonctionne mieux si la page PDF de tampon a un arrière-plan transparent.
multistamp <nom de fichier PDF de tampon | - | PROMPT>
Identique à l'opération stamp, mais applique chaque page du PDF de fond à la page correspondante du PDF d'entrée. Si le PDF d'entrée a plus de pages que le PDF de tampon, alors la dernière page de tampon est répétée sur ces pages restantes du PDF d'entrée.
dump_data
Lit un seul fichier PDF d'entrée et rapporte ses métadonnées, signets (alias outlines), métriques de page (media, rotation et étiquettes), données intégrées par STAMPtk (voir l'option embed de STAMPtk) et d'autres données vers le nom de fichier de sortie donné ou (si aucune sortie n'est donnée) vers stdout. Les caractères non ASCII sont encodés sous forme d'entités numériques XML. Ne crée pas de nouveau PDF.
dump_data_utf8
Identique à dump_data sauf que la sortie est encodée en UTF-8.
dump_data_fields
Lit un seul fichier PDF d'entrée et rapporte les statistiques des champs de formulaire vers le nom de fichier de sortie donné ou (si aucune sortie n'est donnée) vers stdout. Les caractères non ASCII sont encodés sous forme d'entités numériques XML. Ne crée pas de nouveau PDF.
dump_data_fields_utf8
Identique à dump_data_fields sauf que la sortie est encodée en UTF-8.
dump_data_annots
Cette opération ne rapporte actuellement que les annotations de lien. Lit un seul fichier PDF d'entrée et rapporte les informations d'annotation vers le nom de fichier de sortie donné ou (si aucune sortie n'est donnée) vers stdout. Les caractères non ASCII sont encodés sous forme d'entités numériques XML. Ne crée pas de nouveau PDF.
update_info <nom de fichier de données d'info | - | PROMPT>
Modifie les signets, les étiquettes de page, les tailles de page, les rotations de page et les métadonnées dans le dictionnaire Info d'un seul PDF pour correspondre au fichier de données d'entrée. Le fichier de données d'entrée utilise la même syntaxe que la sortie de dump_data. Les caractères non ASCII doivent être encodés sous forme d'entités numériques XML.

Cette opération ne modifie pas les métadonnées stockées dans le flux XMP du PDF, s'il en a un. (Pour cette raison, vous devriez inclure une entrée ModDate dans vos informations mises à jour avec une date/heure actuelle, format : D:AAAAJJHHmmSS, par exemple D:201307241346 – les données omises après AAAA reviennent aux valeurs par défaut.)

Par exemple :

pdftk in.pdf update_info in.info output out.pdf

update_info_utf8 <nom de fichier de données d'info | - | PROMPT>
Identique à update_info sauf que l'entrée est encodée en UTF-8.
attach_files <noms de fichiers de pièces jointes | PROMPT> [to_page <numéro de page | PROMPT> | relation <relation>]
Intègre des fichiers arbitraires dans un PDF en utilisant les fonctionnalités de pièces jointes de fichiers du PDF. Plus d'une pièce jointe peut être listée après attach_files. Les pièces jointes sont ajoutées au niveau du document sauf si l'option optionnelle to_page est donnée, auquel cas les fichiers sont joints à la page spécifiée (la première page est 1, la dernière page est end). Les pièces jointes au niveau du document peuvent être taguées avec une relation parmi Source, Data, Alternative, Supplement et Unspecified (par défaut).

Par exemple :

pdftk in.pdf attach_files table1.html table2.html to_page 6 output out.pdf

pdftk in.pdf attach_files in.tex relation Source output out.pdf

unpack_files
Copie toutes les pièces jointes du PDF d'entrée dans le dossier courant ou vers un répertoire de sortie spécifié après output. Par exemple :

pdftk report.pdf unpack_files output ~/atts/

ou, interactivement :

pdftk report.pdf unpack_files output PROMPT

[output <nom de fichier de sortie | - | PROMPT>]
Le nom du fichier PDF de sortie ne peut pas être le nom d'un fichier d'entrée. Utilisez - pour sortir vers stdout. Lors de l'utilisation de l'opération dump_data, utilisez output pour définir le nom du fichier de données de sortie. Lors de l'utilisation de l'opération unpack_files, utilisez output pour définir le nom d'un répertoire de sortie. Lors de l'utilisation de l'opération burst, vous pouvez utiliser output pour contrôler les noms des fichiers de page PDF résultants (décrit ci-dessus).
[encrypt_40bit | encrypt_128bit | encrypt_aes128]
Si un mot de passe utilisateur ou propriétaire pour le PDF de sortie est donné, le PDF de sortie chiffre

OPTIONS

[encrypt_40bit | encrypt_128bit | encrypt_aes ]
Le chiffrement par défaut est AES-128. Les algorithmes RC4 40 bits et RC4 128 bits, moins sûrs, peuvent être choisis en spécifiant encrypt_40bit ou encrypt_128bit (déconseillé).

L'algorithme de chiffrement par défaut est AES-128. Les algorithmes RC4 40 bits et RC4 128 bits, moins sûrs, peuvent être choisis en spécifiant encrypt_40bit ou encrypt_128bit (déconseillé).

[allow <permissions>]
Les autorisations sont appliquées au PDF de sortie uniquement si une force de chiffrement est spécifiée ou si un mot de passe propriétaire ou utilisateur est donné. Si les autorisations ne sont pas spécifiées, elles sont par défaut à 'none', ce qui signifie que toutes les fonctionnalités suivantes sont désactivées.

La section permissions peut inclure une ou plusieurs des fonctionnalités suivantes :

Printing
Impression de haute qualité
DegradedPrinting
Impression de basse qualité
ModifyContents
Permet également l'assemblage
Assembly
CopyContents
Permet également les lecteurs d'écran
ScreenReaders
ModifyAnnotations
Permet également le remplissage
FillIn
AllFeatures
Permet à l'utilisateur d'effectuer toutes les actions ci-dessus, et l'impression de haute qualité.
[owner_pw <mot de passe propriétaire | PROMPT>]
[user_pw <mot de passe utilisateur | PROMPT>]
Si une force de chiffrement est donnée mais qu'aucun mot de passe n'est fourni, alors les mots de passe propriétaire et utilisateur restent vides, ce qui signifie que le PDF résultant peut être ouvert et ses paramètres de sécurité modifiés par n'importe qui.
[compress | uncompress]
Ceci n'est utile que lorsque vous souhaitez modifier le code PDF dans un éditeur de texte comme vim ou emacs. Supprimez la compression du flux de pages PDF en appliquant le filtre uncompress. Utilisez le filtre compress pour rétablir la compression.
[flatten]
Utilisez cette option pour fusionner les champs de formulaire interactifs (et leurs données) d'un PDF d'entrée avec les pages du PDF. Un seul PDF d'entrée peut être donné. Parfois utilisé avec l'opération fill_form.
[need_appearances]
Définit un indicateur qui signale à Reader/Acrobat de générer de nouvelles apparences de champ basées sur les valeurs des champs de formulaire. Utilisez ceci lors du remplissage d'un formulaire avec du texte non ASCII pour assurer la meilleure présentation dans Adobe Reader ou Acrobat. Cela ne fonctionnera pas en combinaison avec l'option flatten.
[replacement_font <nom de police>]
Utilise la police spécifiée pour afficher le texte dans les champs de formulaire. Cette option est utile lors du remplissage d'un formulaire avec du texte non ASCII qui n'est pas pris en charge par les polices incluses dans le PDF d'entrée. nom de police peut être le nom de fichier ou le nom de famille d'une police, mais l'utilisation d'un nom de fichier est plus fiable. Actuellement, seules les polices TrueType avec du texte Unicode sont prises en charge.
[keep_first_id | keep_final_id]
Lors de la combinaison de pages provenant de plusieurs PDF, utilisez l'une de ces options pour copier l'identifiant du document du premier ou du dernier document d'entrée dans le nouveau PDF de sortie. Sinon, pdftk crée un nouvel identifiant de document pour le PDF de sortie. Lorsqu'aucune opération n'est donnée, pdftk utilise toujours l'identifiant du PDF d'entrée (unique).
[drop_xfa]
Si votre PDF d'entrée est un formulaire créé à l'aide d'Acrobat 7 ou d'Adobe Designer, il contient probablement des données XFA. Le remplissage d'un tel formulaire à l'aide de pdftk produit un PDF avec des données qui ne s'affichent pas correctement dans Acrobat 7 (et 6 ?). La solution de contournement consiste à supprimer les données XFA du formulaire, soit avant de remplir le formulaire à l'aide de pdftk, soit au moment de le remplir. L'utilisation de cette option amène pdftk à omettre les données XFA du formulaire PDF de sortie.

Cette option n'est utile que lors de l'exécution de pdftk sur un seul PDF d'entrée. Lors de l'assemblage d'un PDF à partir de plusieurs entrées à l'aide de pdftk, toutes les données XFA dans l'entrée sont automatiquement omises.

[drop_xmp]
De nombreux PDF stockent les métadonnées du document à l'aide d'un dictionnaire d'informations (ancien style) et d'un flux XMP (nouveau style). L'opération update_info de Pdftk peut mettre à jour le dictionnaire d'informations, mais pas le flux XMP. Le remède approprié à cela est d'inclure une entrée ModDate dans vos informations mises à jour avec une date/horodatage actuel. Le format de la date/horodatage est : D:YYYYMMDDHHmmSS, par exemple D:201307241346 – les données omises après YYYY reviennent aux valeurs par défaut. Ce ModDate plus récent devrait inciter les visionneurs de PDF à considérer que les métadonnées d'information sont plus récentes que les données XMP.

Alternativement, vous pourriez préférer supprimer complètement le flux XMP du PDF – c'est ce que fait cette option. Notez que les objets à l'intérieur du PDF peuvent avoir leurs propres flux de métadonnées XMP distincts, et que drop_xmp ne les supprime pas. Il ne supprime que le flux XMP au niveau du document du PDF.

[verbose]
Par défaut, pdftk s'exécute silencieusement. Ajoutez verbose à la fin et il se fera entendre.
[dont_ask | do_ask]
Selon les paramètres de compilation (voir ASK_ABOUT_WARNINGS), pdftk pourrait vous demander des informations supplémentaires lorsqu'il rencontre un problème, tel qu'un mot de passe incorrect. Remplacez ce comportement par défaut en ajoutant dont_ask (pour que pdftk ne vous demande pas quoi faire) ou do_ask (pour que pdftk vous demande quoi faire).

Lorsque vous exécutez en mode dont_ask, pdftk écrasera les fichiers avec sa sortie sans préavis.

EXEMPLES

Coller des pages numérisées
pdftk A=even.pdf B=odd.pdf shuffle A B output collated.pdf
ou si odd.pdf est en ordre inverse :
pdftk A=even.pdf B=odd.pdf shuffle A Bend-1 output collated.pdf

Les exemples suivants utilisent de vrais mots de passe comme paramètres de ligne de commande, ce qui est déconseillé (voir la section CONSIDÉRATIONS DE SÉCURITÉ).

Déchiffrer un PDF
pdftk secured.pdf input_pw foopass output unsecured.pdf
Chiffrer un PDF en utilisant AES-128 (par défaut), retenir toutes les permissions (par défaut)
pdftk 1.pdf output 1.128.pdf owner_pw foopass
Identique à ci-dessus, sauf que le mot de passe 'baz' doit également être utilisé pour ouvrir le PDF de sortie
pdftk 1.pdf output 1.128.pdf owner_pw foo user_pw baz
Identique à ci-dessus, sauf que l'impression est autorisée (une fois le PDF ouvert)
pdftk 1.pdf output 1.128.pdf owner_pw foo user_pw baz allow printing
Appliquer le chiffrement RCA 40 bits à la sortie, en révoquant toutes les permissions (par défaut). Définir le mot de passe propriétaire sur 'foopass'.
pdftk 1.pdf 2.pdf cat output 3.pdf encrypt_40bit owner_pw foopass
Joindre deux fichiers, dont l'un nécessite le mot de passe 'foopass'. La sortie n'est pas chiffrée.
pdftk A=secured.pdf 2.pdf input_pw A=foopass cat output 3.pdf
Joindre in1.pdf et in2.pdf en un nouveau PDF, out1.pdf
pdftk in1.pdf in2.pdf cat output out1.pdf
ou (en utilisant des identifiants) :
pdftk A=in1.pdf B=in2.pdf cat A B output out1.pdf
ou (en utilisant des jokers) :
pdftk *.pdf cat output combined.pdf
Supprimer la page 13 de in1.pdf pour créer out1.pdf
pdftk in.pdf cat 1-12 14-end output out1.pdf
ou :
pdftk A=in1.pdf cat A1-12 A14-end output out1.pdf
Décompresser les flux de pages PDF pour éditer le PDF dans un éditeur de texte (par exemple, vim, emacs)
pdftk doc.pdf output doc.unc.pdf uncompress
Réparer la table XREF et les longueurs de flux corrompues d'un PDF, si possible
pdftk broken.pdf output fixed.pdf
Décomposer un seul document PDF en pages et exporter ses données dans doc_data.txt
pdftk in.pdf burst
Décomposer un seul document PDF en pages chiffrées. Autoriser l'impression de basse qualité
pdftk in.pdf burst owner_pw foopass allow DegradedPrinting
Écrire un rapport sur les métadonnées et les signets du document PDF dans report.txt
pdftk in.pdf dump_data output report.txt
Faire pivoter la première page du PDF de 90 degrés dans le sens des aiguilles d'une montre
pdftk in.pdf cat 1east 2-end output out.pdf
Faire pivoter un document PDF entier de 180 degrés
pdftk in.pdf cat 1-endsouth output out.pdf

CONSIDÉRATIONS DE SÉCURITÉ

Passer un mot de passe comme paramètre de ligne de commande est peu sûr car il peut être enregistré dans l'historique du shell et être accessible par d'autres utilisateurs via /proc. Utilisez plutôt le mot-clé PROMPT et saisissez les mots de passe via l'entrée standard.
