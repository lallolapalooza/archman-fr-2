PMDALOGGER(1) Manuel des commandes générales PMDALOGGER(1)

NOM

pmdalogger - agent de domaine de métriques de fichiers journaux (PMDA)

SYNTAXE

$PCP_PMDAS_DIR/logger/pmdalogger [-D debug] [-d domaine] [-l logfile] [-m mémoire] [-s intervalle] [-U nomutilisateur] [fichierconfig]

DESCRIPTION

pmdalogger est un agent de domaine de métriques de performance (PMDA) configurable pour la surveillance de fichiers journaux. Il peut être considéré comme analogue à l'option -f de tail(1) et convertit chaque nouvelle ligne de log en un événement de performance. Ce fut le premier PMDA à faire une utilisation extensive des métriques d'événements, qui peuvent être consommées par des outils clients comme pmevent(1).

Le PMDA logger exporte à la fois des métriques de type événement reflétant des enregistrements d'événements horodatés pour le texte enregistré dans un fichier (ou un ensemble de fichiers ou la sortie d'un processus), ainsi que des métriques de type échantillon plus orthodoxes telles que les décomptes d'événements et les valeurs de taille de débit.

Le PMDA est configuré via un fichierconfig qui contient une ligne pour chaque source d'événements (fichier ou processus). Ce fichier est mis en place par le script d'installation décrit dans la section « INSTALLATION » du PMDA.

Une brève description des options de ligne de commande de pmdalogger suit :

-d
Il est absolument crucial que le numéro de domaine des métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire que domaine doit être différent pour chaque PMDA sur le même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé logger.log est écrit dans le répertoire courant de pmcd(1) lorsque pmdalogger est démarré, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est redirigée vers la sortie d'erreur standard.
-m
Limite la mémoire physique utilisée par le PMDA pour mettre en tampon les enregistrements d'événements à taille max octets. Lorsque les événements de log arrivent au PMDA, ils doivent être mis en tampon jusqu'à ce que les outils clients individuels demandent le lot suivant depuis leur lot d'événements précédent. La limite maximale par défaut est de 2 mégaoctets.
-s
Définit l'intervalle d'interrogation pour détecter les nouvelles lignes de log arrivées. Reflète la même option de la commande tail(1).
-U
Compte utilisateur sous lequel exécuter l'agent. Par défaut, c'est le compte non privilégié « pcp » dans les versions récentes de PCP, mais dans les anciennes versions, le compte superutilisateur (« root ») était utilisé par défaut.

INSTALLATION

Si vous souhaitez accéder aux noms, textes d'aide et valeurs des métriques de performance du logger, faites ce qui suit en tant que root :

# cd $PCP_PMDAS_DIR/logger
# ./Install

Il s'agit d'un processus d'installation interactif qui demande le chemin de chaque fichier journal à surveiller (ou la commande à exécuter), un nom d'instance de métrique pour l'identifier, et si l'accès doit être restreint (se référer à l'option -x de pmevent(1) pour plus de détails).

Si vous souhaitez annuler l'installation, faites ce qui suit en tant que root :

# cd $PCP_PMDAS_DIR/logger
# ./Remove

pmdalogger est lancé par pmcd(1) et ne devrait jamais être exécuté directement. Les scripts Install et Remove notifient pmcd(1) lorsque l'agent est installé ou supprimé.

FICHIERS

$PCP_PMCDCONF_PATH
options de ligne de commande utilisées pour lancer pmdalogger
$PCP_PMDAS_DIR/logger/logger.conf
fichier de configuration par défaut pour les métriques du logger
$PCP_PMDAS_DIR/logger/help
fichier d'aide par défaut pour les métriques du logger
$PCP_PMDAS_DIR/logger/Install
script d'installation pour l'agent pmdalogger
$PCP_PMDAS_DIR/logger/Remove
script d'annulation d'installation pour l'agent pmdalogger
$PCP_LOG_DIR/pmcd/logger.log
fichier journal par défaut pour les messages d'erreur et autres informations de pmdalogger

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBUTAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur la sortie standard stderr pour aider à résoudre les problèmes, bien que les informations soient parfois cryptiques et visent principalement à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdalogger sont les suivantes :

Option Description
appl0 Traitement du fichierconfig et configuration PMNS
appl1 Chargement des données d'événements depuis les fichiers journaux
appl2 Interaction avec pmcd(1).

VOIR AUSSI

PCPIntro(1), pmevent(1), pmcd(1), tail(1), pcp.conf(5) et pcp.env(5).
