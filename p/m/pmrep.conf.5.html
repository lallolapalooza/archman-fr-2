PMREP.CONF(5) Manuel des formats de fichiers PMREP.CONF(5)

NOM

pmrep.conf - Fichier de configuration de pmrep

DESCRIPTION

pmrep est un outil personnalisable de reporting de métriques de performance. Toute métrique de performance disponible, en direct ou archivée, système et/ou application, peut être sélectionnée pour le reporting en utilisant une des alternatives de sortie disponibles avec les options de formatage applicables.

Les métriques d'intérêt sont nommées dans l'argument metricspec sur la ligne de commande pmrep. Ces metricspecs définissent des métriques individuelles ou des ensembles de métriques de performance pré-définis à lire depuis les fichiers de configuration décrits ci-dessous. Pour les détails des arguments de la ligne de commande, voir pmrep(1).

Le fichier de configuration pmrep.conf permet de définir les valeurs par défaut d'exécution et de définir un nombre quelconque de metricsets personnalisés pour pmrep. Un metricset est un ensemble défini par l'utilisateur de métriques de performance arbitraires. Cela permet aux utilisateurs de créer des metricsets spécifiquement conçus, particulièrement pertinents pour leur application ou leur environnement. Au lieu d'être dépendant de ce que les outils existants fournissent ou de collecter les données nécessaires avec plusieurs utilitaires disjoints, les utilisateurs peuvent définir des metricsets personnalisés en modifiant simplement pmrep.conf. Voir ci-dessous pour la spécification metricset.

Dans le cas où les fichiers de configuration pmrep sont lus à partir d'un répertoire, les valeurs des sections [options] et [global] seront combinées à partir de chaque fichier où elles sont définies. La dernière définition d'une directive l'emporte, signifiant que la dernière définition sera utilisée si elle est définie plusieurs fois. Cependant, les sections metricset personnalisées ne seront pas combinées, seule la dernière définition trouvée sera utilisée pour le reporting.

Les options via les variables d'environnement (voir pmGetOptions(3)) remplacent les valeurs par défaut intégrées correspondantes (le cas échéant). Les options du fichier de configuration remplacent les variables d'environnement correspondantes (le cas échéant). Les options de la ligne de commande remplacent les options du fichier de configuration correspondantes (le cas échéant).

FORMAT DE FICHIER

Le fichier a une syntaxe de style ini et se compose de sections et de paramètres. Une section commence par le nom de la section entre crochets et continue jusqu'à ce que la section suivante commence. Un exemple de section avec deux paramètres suit :

[section]
clé = valeur
clé2 = valeur2

Les types de données pris en charge pour les valeurs sont chaîne de caractères, entier et booléen. Les valeurs ne doivent pas être mises entre guillemets, sauf lorsque la valeur consiste uniquement en des espaces blancs (c'est-à-dire un séparateur de colonne uniquement composé d'espaces blancs).

Un commentaire de ligne commence par un signe dièse (``#'') ou un point-virgule (``;''). Les commentaires en ligne ne sont pas pris en charge.

pmrep.conf doit être lisible par l'utilisateur qui invoque pmrep.

Toute option décrite ci-dessous avec une option de ligne de commande correspondante contient une description fonctionnelle supplémentaire dans pmrep(1).

SECTIONS SPÉCIALES

La section [options]

La section [options] est lue à chaque fois que pmrep est exécuté et elle définit les options d'exécution par défaut. Ces options peuvent être remplacées par des options spécifiques au metricspec ou par des options de ligne de commande. Les métriques ne sont pas autorisées dans cette section.

Paramètres autorisés

version (entier)

Indique la version du fichier de configuration. Par défaut à 1. La seule valeur actuellement prise en charge est 1.

source (chaîne)

Indique la source des métriques. Interprétée comme une archive PCP si la valeur contient une barre oblique (``/''). Si définie au caractère spécial ``@'', le contexte DSO PMDA local est utilisé. Sinon, interprétée comme un nom d'hôte. Les paramètres de ligne de commande correspondants sont -a, -h et -L. Par défaut local: (voir PCPIntro(1)).

output (chaîne)

Indique la cible de sortie. Paramètre de ligne de commande correspondant : -o. Pour les cibles de sortie prises en charge, voir pmrep(1). Par défaut stdout.

speclocal (chaîne)

Indique les DSO PMDA locaux à rendre disponibles lors de l'utilisation du contexte DSO PMDA local. Paramètre de ligne de commande correspondant : -K. Pour la description de la syntaxe, voir pmSpecLocalPMDA(3). Utiliser un point-virgule (``;'') pour séparer plus d'un spec. Indéfini par défaut.

derived (chaîne)

Spécifications de métriques dérivées. Paramètre de ligne de commande correspondant : -e. Pour la description de la syntaxe, voir pmrep(1). Indéfini par défaut.

daemonize (booléen)

Indique s'il faut se détacher du terminal au démarrage. Paramètre de ligne de commande correspondant : --daemonize. Par défaut no.

header (booléen)

Indique s'il faut afficher les en-têtes. Paramètre de ligne de commande correspondant : -H. Par défaut yes.

instinfo (booléen)

Indique s'il faut inclure les informations d'instance dans les en-têtes. Paramètre de ligne de commande correspondant : --no-inst-info. Par défaut yes.

unitinfo (booléen)

Indique s'il faut inclure les informations d'unité dans les en-têtes. Paramètre de ligne de commande correspondant : -U. Par défaut yes.

globals (booléen)

Indique s'il faut inclure les métriques de la section [global] (voir ci-dessous) pour le reporting. Paramètre de ligne de commande correspondant : -G. Par défaut yes.

timestamp (booléen)

Indique s'il faut afficher l'horodatage. Paramètre de ligne de commande correspondant : -p. Par défaut no.

samples (entier)

Indique le nombre d'échantillons à imprimer. Paramètre de ligne de commande correspondant : -s. Indéfini par défaut (signifie un nombre illimité d'échantillons si non limité par d'autres options).

interval (chaîne)

Indique l'intervalle entre les échantillons. Paramètre de ligne de commande correspondant : -o. Suit la syntaxe temporelle décrite dans PCPIntro(1). Par défaut 1s.

delay (booléen)

Indique s'il faut faire une pause entre les échantillons lors de la relecture à partir d'une archive plutôt que de la relecture à pleine vitesse. Paramètre de ligne de commande correspondant : -d. Par défaut no.

type (chaîne)

Indique s'il faut sortir les valeurs brutes des métriques en désactivant toutes les conversions de taux ou convertir les compteurs cumulatifs en taux (par défaut). Paramètre de ligne de commande correspondant : -r. Valeurs autorisées : default ou raw.

type_prefer (chaîne)

Comme type mais ne remplace pas les spécifications de type possibles par métrique. Paramètre de ligne de commande correspondant : -R. Valeurs autorisées : default ou raw.

ignore_incompat (booléen)

Indique que les métriques incompatibles doivent être ignorées. Paramètre de ligne de commande correspondant : -I. Par défaut no.

ignore_unknown (booléen)

Indique que les métriques inconnues doivent être ignorées. Paramètre de ligne de commande correspondant : -5. Par défaut no.

names_change (chaîne)

Indique l'action à entreprendre en cas de changement du PMNS pendant l'échantillonnage. Paramètre de ligne de commande correspondant : -4. Par défaut ignore.

instances (chaîne)

Indique les instances à rapporter. Paramètre de ligne de commande correspondant : -i. Indéfini (toutes les instances sont rapportées) par défaut.

live_filter (booléen)

Indique que le filtrage en direct doit être activé. Paramètre de ligne de commande correspondant : -j. Par défaut no.

rank (entier)

Indique la valeur à utiliser pour classer les instances. Paramètre de ligne de commande correspondant : -J. Indéfini (toutes les instances sont rapportées) par défaut.

overall_rank (booléen)

Indique que le classement global doit être effectué. Paramètre de ligne de commande correspondant : -2. Par défaut no.

overall_rank_alt (booléen)

Indique que le classement global avec un format de sortie alternatif doit être effectué. Paramètre de ligne de commande correspondant : -3. Par défaut no.

limit_filter (entier)

Indique la valeur à utiliser avec le filtrage par limite. Paramètre de ligne de commande line option est -8. Indéfini (toutes les instances sont signalées) par défaut.

limit_filter_force (entier)

Comme limit_filter mais remplace les spécifications possibles par métrique. Option de ligne de commande correspondante est -9. Indéfini (toutes les instances sont signalées) par défaut.

invert_filter (booléen)

Indique que le filtrage inverse doit être effectué. Option de ligne de commande correspondante est -n. Par défaut no.

predicate (chaîne)

Indique les métriques à utiliser comme métriques prédicats. Option de ligne de commande correspondante est -N. Indéfini par défaut.

sort_metric (chaîne)

Indique les métriques à utiliser comme métriques de référence de tri. Option de ligne de commande correspondante est -6. Indéfini par défaut.

omit_flat (booléen)

Indique que les métriques « plates » à valeur unique doivent être omises du rapport. Option de ligne de commande correspondante est -v. Par défaut no.

include_labels (booléen)

Indique que les étiquettes de métriques PCP doivent être incluses dans la sortie. Option de ligne de commande correspondante est -m. Par défaut no.

include_texts (booléen)

Indique que lors de l'écriture d'une archive PCP, les textes d'aide PCP doivent être inclus dans l'archive créée. Option de ligne de commande correspondante est --include-texts. Par défaut no.

colxrow (chaîne)

Indique d'échanger les colonnes et les lignes dans la sortie stdout en utilisant la valeur comme étiquette de texte de métrique. Option de ligne de commande correspondante est -X. Indéfini (pas d'échange) par défaut.

width (entier)

Indique la largeur des colonnes de sortie stdout. Option de ligne de commande correspondante est -w. La minimum forcé est 3. Par défaut la largeur la plus courte qui peut contenir l'étiquette de texte de la métrique.

width_force (entier)

Comme width mais remplace les spécifications possibles par métrique. Option de ligne de commande correspondante est -W. La minimum forcé est 3.

precision (entier)

Indique le nombre de décimales à utiliser pour les valeurs de sortie numériques non entières. Option de ligne de commande correspondante est -P. Par défaut 3.

precision_force (entier)

Comme precision mais remplace les spécifications possibles par métrique. Option de ligne de commande correspondante est -0. Indéfini par défaut.

delimiter (chaîne)

Indique le séparateur de colonnes. Option de ligne de commande correspondante est -l. Le défaut dépend de la cible de sortie, voir pmrep(1).

extcsv (booléen)

Indique si une sortie CSV étendue similaire à sadf(1) doit être écrite. Option de ligne de commande correspondante est -k. Par défaut no.

extheader (booléen)

Indique si un en-tête étendu doit être imprimé. Option de ligne de commande correspondante est -x. Par défaut no.

fixed_header (booléen)

Indique qu'un en-tête fixe doit être utilisé. Option de ligne de commande correspondante est -7. Par défaut no.

repeat_header (entier)

Indique à quelle fréquence l'en-tête doit être répété. Option de ligne de commande correspondante est -E. auto utilise la hauteur du terminal. Par défaut 0 (l'en-tête n'est pas répété).

dynamic_header (booléen)

Indique qu'un en-tête dynamique doit être utilisé. Option de ligne de commande correspondante est -1. Par défaut no.

separate_header (booléen)

Indique si un en-tête séparé doit être imprimé. Option de ligne de commande correspondante est -g. Par défaut no.

timefmt (chaîne)

Indique la chaîne de format pour le formatage de l'horodatage. Option de ligne de commande correspondante est -f. Par défaut %H:%M:%S.

interpol (booléen)

Indique si les valeurs d'archive signalées doivent être interpolées. Option de ligne de commande correspondante est -u. Voir pmrep(1) pour une description complète. Par défaut yes.

count_scale (chaîne)

Indique l'unité/l'échelle pour les métriques de compteur. Option de ligne de commande correspondante est -q. Pour la syntaxe prise en charge, voir pmrep(1). Indéfini (pas de mise à l'échelle) par défaut.

count_scale_force (chaîne)

Comme count_scale mais remplace les spécifications possibles par métrique. Option de ligne de commande correspondante est -Q. Indéfini par défaut.

space_scale (chaîne)

Indique l'unité/l'échelle pour les métriques d'espace. Option de ligne de commande correspondante est -b. Pour la syntaxe prise en charge, voir pmrep(1). Indéfini (pas de mise à l'échelle) par défaut.

space_scale_force (chaîne)

Comme space_scale mais remplace les spécifications possibles par métrique. Option de ligne de commande correspondante est -B. Indéfini par défaut.

time_scale (chaîne)

Indique l'unité/l'échelle pour les métriques de temps. Option de ligne de commande correspondante est -y. Pour la syntaxe prise en charge, voir pmrep(1). Indéfini (pas de mise à l'échelle) par défaut.

time_scale_force (chaîne)

Comme time_scale mais remplace les spécifications possibles par métrique. Option de ligne de commande correspondante est -Y. Indéfini par défaut.

La section [global]

La section [global] est utilisée pour définir les métriques qui seront signalées en plus de toute autre métrique ou jeu de métriques défini séparément. Les options de configuration ne sont pas autorisées dans cette section. Les métriques globales sont signalées par défaut, l'option de ligne de commande -G ou l'option de fichier de configuration globals peuvent être utilisées pour désactiver les métriques globales.

Paramètres autorisés

Seuls les metric specs sont autorisés dans cette section. Voir ci-dessous pour la spécification des metric specs.

SECTIONS PERSONNALISÉES

Toute section autre que [options] ou [global] sera interprétée comme une nouvelle spécification de metric set. Le nom de la section est arbitraire, faisant généralement référence à sa couverture ou à son objectif. Une section personnalisée peut contenir des options, des metric specs, ou les deux.

Toutes les métriques spécifiées dans une section personnalisée (metric set) seront signalées lorsque pmrep signalera ce metric set particulier. Plus d'un metric set (section personnalisée) peut être défini sur la ligne de commande, auquel cas pmrep signalera la combinaison de toutes les métriques spécifiées dans les metric sets sélectionnés.

Paramètres autorisés

Toute option valide dans la section [options] est également valide dans une section personnalisée. Toute option ou métrique définie dans une section personnalisée remplacera la même option ou métrique éventuellement définie précédemment. Voir ci-dessous pour la spécification des metric specs.

SPECIFICATION DE_METRIC_SET

Il existe trois formes de metric spec. Premièrement, sur la ligne de commande, un metric spec peut commencer par deux-points (« : ») pour indiquer une référence à un metric set (section personnalisée) à lire à partir d'un fichier de configuration pmrep. Deuxièmement, la forme compacte d'un metric spec est une spécification de métrique sur une seule ligne qui peut être utilisée à la fois sur la ligne de commande et dans les sections [global] et personnalisées du fichier de configuration. La seule différence de son utilisation dans le fichier de configuration est que le nom de la métrique est utilisé comme clé et les spécificateurs optionnels comme valeurs. La forme compacte du metric spec est spécifiée en détail dans pmrep(1). La troisième, la forme verbeuse d'un metric spec, n'est valide que dans le fichier de configuration (voir ci-dessous).

Dans une section personnalisée, une clé contenant un point (« . ») est interprétée comme un nom de métrique et une clé non optionnelle ne contenant pas de point est interprétée comme un identifiant (handle) pour lier les déclarations connexes. L'identifiant est arbitraire et n'est pas utilisé autrement que pour lier les spécificateurs et la métrique ci-dessous ensemble.

La forme verbeuse d'un metric spec commence par une déclaration composée d'un identifiant obligatoire comme clé et d'un nom de métrique de performance (un nœud PMNS) comme valeur. Cela équivaut à la forme compacte du metric spec définissant la même métrique de performance sans aucun des spécificateurs optionnels définis.

Les spécificateurs suivants sont facultatifs dans la forme verbeuse et peuvent être utilisés comme clés dans n'importe quel ordre avec un identifiant déclaré précédemment suivi d'un point et du spécificateur (comme dans identifiant.spécificateur). Voir également l'exemple ci-dessous.

étiquette
Définit l'étiquette texte pour la métrique utilisée par les cibles de sortie prises en charge.
formule
Définit l'expression arithmétique nécessaire pour la métrique. Pour plus de détails, voir pmRegisterDerived(3).
instances
Définit les instances à signaler pour la métrique. Pour plus de détails, voir pmrep(1).
unité
Définit la conversion d'unité/échelle pour la métrique. Doit être compatible avec les dimensions et est utilisée avec des métriques non textuelles. Pour les valeurs autorisées, voir pmrep(1).
type
Si défini sur raw, la conversion de taux pour la métrique sera désactivée.
largeur
Définit la largeur de la colonne de sortie pour la métrique.
precision
Définit la précision pour les valeurs de sortie numériques non entières.
limite
Définit un filtre de limite de valeur pour les valeurs de métriques numériques.

EXEMPLE

L'exemple suivant contient une courte section [options] définissant certaines valeurs par défaut souhaitées localement. Il passe ensuite à la définition des métriques globales kernel.all.sysfork en utilisant la forme compacte et mem.util.allcache en utilisant la forme verbeuse d'un metric spec. Cette dernière est une métrique dérivée utilisant la formule spécifiée. Ces deux métriques seront incluses dans le rapport, sauf si elles sont désactivées avec -G ou

Trois metricsets différents sont également spécifiés : db1, db2 et sar-w.

Les jeux DB définissent un hôte à utiliser comme source pour les métriques. Les deux utilisent la forme verbeuse d'un metricspec (car la clé non-optionnelle set ne contient pas le point) pour inclure toutes les métriques relatives à postgresql.

Le jeu sar-w est un exemple de la façon d'imiter un outil existant avec pmrep.

Les fichiers de configuration pmrep par défaut du système contiennent de nombreux autres exemples. La touche tabulation sur la ligne de commande après un deux-points complète les metricsets disponibles (avec bash et zsh).

[options]
timestamp = yes
interval = 2s
extheader = yes
repeat_header = auto
space_scale = MB
[global]
kernel.all.sysfork = forks,,,,8
cacheall = mem.util.allcache
cacheall.formula = mem.util.bufmem + mem.util.cached + mem.util.slab
cacheall.width = 12
[db1]
source = db-host1.example.com
set = postgresql
[db2]
source = db-host2.example.com
set = postgresql
[sar-w]
header = yes
unitinfo = no
globals = no
timestamp = yes
precision = 2
delimiter = " "
kernel.all.sysfork = proc/s,,,,12
kernel.all.pswitch = cswch/s,,,,9

FICHIERS

$PCP_SYSCONF_DIR/pmrep/*.conf
fichiers de configuration pmrep par défaut fournis par le système

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).
