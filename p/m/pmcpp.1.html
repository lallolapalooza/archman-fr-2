PMCPP(1) Manuel des commandes générales PMCPP(1)

NOM

pmcpp - préprocesseur simple pour Performance Co-Pilot

SYNTAXE

pmcpp [-Prs?] [-D nom[=valeur] ...] [-I rep ...] [[fichier_entree] [fichier_sortie]]

DESCRIPTION

pmcpp fournit un préprocesseur très simple conçu à l'origine pour manipuler les fichiers de l'espace de noms de métriques de performance (PMNS) pour Performance Co-Pilot (PCP), mais généralisé plus tard pour fournir des blocs conditionnels, le traitement de fichiers d'inclusion, l'exécution de commandes shell en ligne et la substitution de macros pour des fichiers arbitraires. Il est le plus souvent utilisé en interne pour traiter le(s) fichier(s) PMNS après l'appel de pmLoadNameSpace(3) ou pmLoadASCIINameSpace(3) et pour prétraiter les fichiers de configuration de pmlogger(1).

Les lignes d'entrée sont lues à partir de fichier_entree (ou de l'entrée standard si fichier_entree n'est pas spécifié), traitées et écrites dans fichier_sortie (sortie standard si fichier_sortie n'est pas spécifié).

Tous les commentaires de style C de la forme /* ... */ sont supprimés du flux d'entrée.

Il n'y a pas de macros prédéfinies pour pmcpp bien que les macros puissent être définies sur la ligne de commande à l'aide de l'option -D, où nom et valeur doivent suivre les mêmes règles que celles décrites ci-dessous pour la directive #define.

pmcpp accepte les directives suivantes dans le flux d'entrée (comme cpp(1)) :

  • #include "nom_fichier"
    ou
    #include <nom_fichier>
    Dans les deux cas, le chemin de recherche des répertoires pour nom_fichier essaie d'abord nom_fichier, puis le répertoire du fichier_entree de la ligne de commande (le cas échéant), suivi des répertoires nommés dans les arguments de ligne de commande -I, et enfin le répertoire $PCP_VAR_DIR/pmns (ce dernier est pour la compatibilité descendante avec les versions antérieures de pmcpp et l'utilisation implicite depuis pmLoadASCIINameSpace(3)). Les directives #include peuvent être imbriquées, jusqu'à une profondeur maximale de 5.
  • #shell "commande"
    ou
    #shell 'commande'
    La commande shell sera exécutée et la sortie standard est insérée dans le flux de données à traiter par pmcpp. Fonctionnellement, cela est similaire à une directive #include, sauf que les lignes d'entrée sont lues à partir d'une commande plutôt que d'un fichier. La directive #shell est la plus utile pour inclure ou exclure les directives #define ou #undef en fonction de la logique d'exécution dans la commande.
  • #define nom valeur
    ou
    #define nom "valeur"
    ou
    #define nom 'valeur'
    Définit une valeur pour la macro nom qui doit être un nom valide de style C, donc un caractère alphabétique ou un underscore suivi de zéro ou plusieurs caractères alphanumériques ou underscores. valeur est optionnelle (et par défaut une chaîne vide). Il n'y a pas de mécanisme d'échappement de caractère, mais des apostrophes ou des guillemets peuvent être utilisés pour définir une valeur avec des caractères spéciaux ou des espaces blancs horizontaux incorporés (pas de sauts de ligne).
  • #undef nom
    Supprime la définition de macro, le cas échéant, pour nom.
  • #ifdef nom
    ...
    #endif
    ou
    #ifndef nom
    ...
    #endif
    Les lignes environnantes seront supprimées ou incluses, selon que la macro nom est définie ou non.
  • #else
    Dans un bloc #ifdef ou #ifndef, #else peut être utilisé pour délimiter les lignes à inclure si la condition ``if'' précédente est fausse.

La substitution de macro est obtenue en divisant le flux d'entrée en mots séparés par des espaces blancs ou des caractères non valides dans un nom de macro, c'est-à-dire ni alphanumériques ni underscore. Chaque mot est vérifié et s'il correspond à un nom de macro, le mot est remplacé par la valeur de la macro, sinon le mot reste inchangé.

Il y a généralement une ligne de sortie pour chaque ligne d'entrée, bien que la ligne puisse être vide si le texte a été supprimé en raison du traitement des commentaires ou des directives conditionnelles. Lorsqu'il y a un changement dans le flux d'entrée, une ligne de sortie supplémentaire est générée de la forme :

# numero_ligne "nom_fichier"

pour indiquer que la ligne de sortie suivante correspond au numéro de ligne numero_ligne du fichier d'entrée nom_fichier.

OPTIONS

Les options de ligne de commande disponibles sont :

-D nom[=valeur], --define=nom[=valeur]
Définit une macro avec une valeur optionnelle, comme décrit précédemment.
-I rep, --include=rep
Un répertoire supplémentaire à rechercher pour les fichiers d'inclusion.
-P
Supprime la génération des lignes de marqueurs de ligne, décrites précédemment.
-s, --shell
Change le style d'entrée attendu de type C à type shell (où # est un préfixe de commentaire). Cela force les changements suivants dans le comportement de pmcpp :
  • Le caractère de préfixe de contrôle passe de # à %, donc par exemple %include au lieu de #include, et %ifdef au lieu de #ifdef.
  • Aucun nettoyage de commentaire de style C n'est effectué.
-r, --restrict
Fournit un contrôle plus fin de l'expansion des macros - cette option restreint la substitution de macros aux mots qui correspondent aux motifs #nom ou #{nom} ou si -s est spécifié, alors %nom ou %{nom}. Dans ce mode, le nom de macro seul dans le flux d'entrée ne sera jamais développé, mais dans les lignes de contrôle (comme #ifdef) le nom de macro doit apparaître seul sans le caractère de préfixe ou les accolades (voir les EXEMPLES ci-dessous).
-?, --help
Affiche le message d'utilisation et quitte.

Les fonctionnalités importantes de cpp(1) qui ne sont **pas** prises en charge par pmcpp incluent :

  • Macros avec paramètres - les macros pmcpp ne prennent en charge que la substitution de chaînes sans paramètre.
  • #if expr
    ...
    #endif
  • Utilisation imbriquée de #ifdef ou #ifndef.
  • Suppression des commentaires de style C++, comme avec //.
  • Récupération d'erreur - la première erreur rencontrée par pmcpp sera fatale.
  • Options de ligne de commande de cpp(1) comme -o, -W, -U, et -x.

pmcpp(1) - Performance Co-Pilot

NAME

pmcpp - Performance Co-Pilot (PCP) C preprocessor

SYNOPSIS

pmcpp [-D macro ...]
pmcpp [-I dir ...]
pmcpp [-U macro ...]
pmcpp [-V]

DESCRIPTION

The pmcpp command is a C preprocessor that is tailored for PCP configuration files. It supports the standard C preprocessor directives (#include, #define, #ifdef, #ifndef, #else, #elif, #endif, #undef, #line, and #error). In addition, it supports two PCP-specific directives:

  • %include: similar to #include, but is used to include PCP specific files, especially name space definitions.
  • %define: similar to #define, but is used to define PCP specific macros.

pmcpp processes the standard input, and writes the result to the standard output.

OPTIONS

-D macro
Define macro, with the optional value value. This is equivalent to the C preprocessor directive #define.
-I dir
Add the directory dir to the list of directories to be searched for header files. This is equivalent to the C preprocessor directive #include.
-U macro
Cancel any previous definition of macro. This is equivalent to the C preprocessor directive #undef.
-V
Print version number and exit.

EXAMPLES

This section shows examples of using pmcpp with PCP configuration files. The example uses the %include directive to include a file named "frequencies" which defines macros for logging frequencies.

# e.g. dk_freq macro

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).
