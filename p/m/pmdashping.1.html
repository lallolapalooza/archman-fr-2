PMDASHPING(1) Manuel des commandes générales PMDASHPING(1)

NOM

pmdashping - agent de domaine de métriques de performance "shell-ping"

SYNTAXE

$PCP_PMDAS_DIR/shping/pmdashping [-C] [-D debug] [-d domaine] [-l logfile] [-I intervalle] [-t timeout] [-U nomutilisateur] fichierconfig

DESCRIPTION

pmdashping est un agent de domaine de métriques de performance (PMDA) qui exporte des mesures de qualité de service et de temps de réponse pour des commandes arbitraires telles que celles qui pourraient être exécutées depuis un shell tel que sh(1).

Ces mesures sont destinées à quantifier la qualité de service et la disponibilité des services qui sont soit critiques pour la mission, soit qui agissent comme indicateurs précoces de performances système défavorables.

La configuration d'exemple surveille des commandes shell simples (exit et date(1)), une tâche courte et intensive en calcul utilisant sum(1), une compilation C courte, une recherche DNS via nslookup(1), une recherche YP via ypcat(1), un service bind/portmapper utilisant rpcbind(1), SMTP en se connectant au port telnet 25 et en envoyant une requête ``expn root'', et NNTP en se connectant au port telnet 119 et en exécutant une commande ``listgroup''.

On s'attend à ce que d'autres commandes suivent les exemples du fichier de configuration d'exemple, et la plupart des déploiements du PMDA pmdashping devraient utiliser un fichier de configuration personnalisé.

Une brève description des options de ligne de commande de pmdashping suit :

-C
Analyse fichierconfig, signale toute erreur et quitte avec un statut non nul si le fichier contient des erreurs syntaxiques.
-d
Il est absolument crucial que le numéro de domaine des métriques de performance domaine spécifié ici soit unique et cohérent. C'est-à-dire que domaine doit être différent pour chaque PMDA sur le même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé shping.log est écrit dans le répertoire courant de pmcd(1) lors du démarrage de pmdashping, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est écrite sur la sortie d'erreur standard.
-I
Temps (en secondes) entre les exécutions successives de la liste de commandes fournies via le fichier de configuration fichierconfig. La valeur par défaut est de 2 minutes.
-t
Temps (en secondes) à attendre avant de signaler un délai d'attente lors de l'attente d'une réponse pour une commande de fichierconfig. La valeur par défaut est de 20 secondes.
-U
Compte utilisateur sous lequel exécuter l'agent et toutes les commandes. Par défaut, il s'agit du compte non privilégié "pcp" dans les versions courantes de PCP, mais dans les versions plus anciennes, le compte superutilisateur ("root") était utilisé par défaut.

Le fichierconfig requis spécifie des paires "tag" et "commande", chacune sur une ligne séparée. Toutes les commandes sont exécutées les unes après les autres, et le groupe entier est rescheduled pour être exécuté une fois par intervalle. Pour chaque commande exécutée, pmdashping enregistre des informations relatives au succès (ou au timeout), au statut de sortie, au temps écoulé et au temps CPU (système et utilisateur), et ces informations sont exportées par le PMDA. Les tags sont utilisés pour identifier les commandes individuelles parmi les valeurs exportées par le PMDA, et forment les identifiants externes du domaine d'instance pour les métriques de pmdashping qui se rapportent à chaque commande.

INSTALLATION

Pour qu'un hôte puisse exporter les noms, les textes d'aide et les valeurs des métriques de performance shping, effectuez les opérations suivantes en tant que root :

# cd $PCP_PMDAS_DIR/shping
# ./Install

L'ensemble des paires "tag" et "commande" peut être spécifié à partir d'un fichier de configuration par défaut (exemple), d'un fichier personnalisé ou entré interactivement dans le cadre du script Install.

Si vous souhaitez annuler l'installation, effectuez les opérations suivantes en tant que root :

# cd $PCP_PMDAS_DIR/shping
# ./Remove

pmdashping est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove notifient pmcd(1) lorsque l'agent est installé ou supprimé.

FICHIERS

$PCP_PMCDCONF_PATH
options de ligne de commande utilisées pour lancer pmdashping
$PCP_PMDAS_DIR/shping/help
fichier d'aide par défaut pour les métriques shping
$PCP_PMDAS_DIR/shping/sample.conf
fichier de configuration d'exemple avec un certain nombre de commandes courantes
$PCP_PMDAS_DIR/shping/Install
script d'installation pour l'agent pmdashping
$PCP_PMDAS_DIR/shping/Remove
script d'annulation d'installation pour pmdashping
$PCP_LOG_DIR/pmcd/shping.log
fichier journal par défaut pour les messages d'erreur et autres informations de pmdashping

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DEBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdashping sont les suivantes :

Option Description
appl0 gestion de sortie
appl1 analyse de fichierconfig, timeouts, cycle de rafraîchissement
appl2 ajoute les commandes et leurs arguments à shping.out au fur et à mesure de leur exécution

VOIR AUSSI

PCPIntro(1), pmcd(1) et pcp-shping(1).
