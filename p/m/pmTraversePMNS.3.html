PMTRAVERSEPMNS(3) Manuel des fonctions de bibliothèque PMTRAVERSEPMNS(3)

NOM

pmTraversePMNS, pmTraversePMNS_r - parcourir l'espace de noms des métriques de performance

SYNTAXE C

#include <pcp/pmapi.h>

int pmTraversePMNS(const char *name,
void (*dometric)(const char *));
int pmTraversePMNS_r(const char *name,
void (*dometric_r)(const char *, void *), void *closure);

cc ... -lpcp

DESCRIPTION

La routine pmTraversePMNS peut être utilisée pour effectuer un parcours en profondeur de l'espace de noms des métriques de performance (PMNS).

Le parcours commence au nœud identifié par name ; si name est une chaîne vide (c'est-à-dire ""), le parcours commence à la racine du PMNS. Habituellement, name serait le chemin d'accès d'un nœud non terminal dans le PMNS.

Pour chaque nœud terminal (c'est-à-dire métrique de performance) trouvé dans le parcours, la routine fournie par l'utilisateur dometric est appelée avec le chemin d'accès complet de cette métrique dans le PMNS comme seul argument. Cet argument est terminé par un octet nul et est construit à partir d'un tampon géré en interne par pmTraversePMNS. Par conséquent, la valeur n'est valide que pendant l'appel à dometric ; si le chemin d'accès doit être conservé, il doit être copié à l'aide de strdup(3) avant de retourner de dometric.

La routine pmTraversePMNS_r effectue la même fonction, sauf que la méthode de rappel func_r possède un paramètre supplémentaire qui sera closure de l'appel initial à pmTraversePMNS_r. Le paramètre supplémentaire à pmTraversePMNS_r et la méthode de rappel permettent à l'appelant de passer un contexte via pmTraversePMNS_r et dans la méthode de rappel func_r, rendant le service plus utile pour les applications multithread où les données privées aux threads peuvent être accédées dans la méthode de rappel via l'argument closure.

En cas de succès, pmTraversePMNS et pmTraversePMNS_r retournent le nombre de nœuds terminaux trouvés dans le parcours, qui sera un (1) si name est soit un nœud terminal, soit une métrique dérivée, soit un nœud non terminal avec un seul enfant. Si name est un nœud non terminal, la valeur retournée sera zéro ou plus (zéro est retourné dans le cas spécial où name est un nœud racine dynamique qui n'a actuellement aucun enfant). Dans tous les cas, les métriques dérivées présentes dans le sous-arbre PMNS sous name sont comptées comme des nœuds terminaux. Si une erreur se produit, pmTraversePMNS et pmTraversePMNS_r retourneront un code d'erreur négatif, comme décrit dans la section DIAGNOSTICS ci-dessous.

DIAGNOSTICS

PM_ERR_NOPMNS
Impossible d'accéder à un PMNS pour l'opération. Notez que si l'application n'a pas appelé pmLoadNameSpace(3) au préalable et souhaite utiliser le PMNS distribué, un appel à pmTraversePMNS doit être effectué dans un contexte actuel.
PM_ERR_NAME
Le chemin d'accès initial name n'est pas valide dans le PMNS actuel.
PM_ERR_*
D'autres diagnostics concernent les échecs de protocole lors de l'accès au PMNS distribué.

VOIR AUSSI

PMAPI(3) et pmGetChildren(3).
