pmiStart(3)

Paquet: pcp

Licences: GPL-2.0-or-later, LGPL-2.1-or-later, CC-BY-3.0

PMISTART(3) Manuel des fonctions de bibliothèque PMISTART(3)

NOM

pmiStart - établit un nouveau contexte LOGIMPORT

C SYNTAXE

#include <pcp/pmapi.h>
#include <pcp/import.h>

int pmiStart(const char *archive, int inherit);

cc ... -lpcp_import -lpcp

Perl SYNTAXE

use PCP::LogImport;

pmiStart($archive, $inherit);

DESCRIPTION

Dans le cadre de l'API d'importation de journaux de Performance Co-Pilot (voir LOGIMPORT(3)), pmiStart crée un nouveau contexte. Chaque contexte maintient l'état et les métadonnées suivants :

  • Le nom de base (archive) des fichiers physiques qui constituent l'archive PCP de sortie.
  • Le nom d'hôte source pour les données qui seront écrites dans l'archive PCP. Par défaut, c'est le nom d'hôte de la machine locale, mais il peut être défini à l'aide de pmiSetHostname(3).
  • Le fuseau horaire source pour l'archive PCP. Par défaut, c'est le fuseau horaire de la machine locale, mais il peut être défini à l'aide de pmiSetTimezone(3).
  • Le numéro de version de l'archive de sortie pour l'archive PCP. Par défaut, c'est le format traditionnel version 2, mais il peut être défini à l'aide de pmiSetVersion(3).
  • Les métriques et les domaines d'instances, tels que définis par pmiAddMetric(3).
  • Les instances pour chaque domaine d'instances, tels que définis par pmiAddInstance(3).
  • Les descripteurs, tels que définis par pmiGetHandle(3). Chaque descripteur est une paire métrique-instance, et chaque paire métrique-instance peut avoir une valeur associée dans chaque enregistrement écrit dans l'archive PCP de sortie.
  • Un ensemble optionnel de valeurs de données pour une ou plusieurs paires métrique-instance (prêtes pour le prochain enregistrement à écrire dans l'archive PCP de sortie), tel que défini par les appels à pmiPutValue(3) ou pmiPutValueHandle(3).

Si inherit est vrai, le nouveau contexte héritera de toutes les métadonnées (métriques, domaines d'instances, instances et descripteurs) du contexte actuel, sinon le nouveau contexte est créé sans métadonnées. Le nom de base de l'archive PCP de sortie, le nom d'hôte source, le fuseau horaire source et les valeurs de données du contexte actuel ne sont **pas** hérités. Si c'est le premier appel à pmiStart, les métadonnées seront vides, indépendamment de la valeur de inherit.

Étant donné qu'aucun fichier physique pour l'archive PCP de sortie ne sera créé avant le premier appel à pmiWrite(3) ou pmiPutResult(3), archive peut être NULL pour créer un contexte de commodité qui est rempli de métadonnées à hériter par les contextes ultérieurs.

La valeur de retour est un identifiant de contexte qui peut être utilisé dans un appel ultérieur à pmUseContext(3) et le nouveau contexte devient le contexte actuel, qui persiste pour tous les appels ultérieurs jusqu'à un autre appel à pmiStart, un appel à pmUseContext(3), ou un appel à pmiEnd(3).

DIAGNOSTICS

C'est une erreur si les fichiers physiques archive.0 et/ou archive.index et/ou archive.meta existent déjà, mais cela n'est découvert que lors de la première tentative de sortie de données en appelant pmiWrite(3) ou pmiPutResult(3), donc pmiStart retourne toujours un identifiant de contexte positif.
