PMLOOKUPDESC(3) Manuel des fonctions de bibliothèque PMLOOKUPDESC(3)

NOM

pmLookupDesc, pmLookupDescs - obtenir des descriptions pour les métriques de performance

C SYNTAXE

#include <pcp/pmapi.h>

int pmLookupDesc(pmID pmid, pmDesc *desc);
int pmLookupDescs(int numpmid, pmID *pmids, pmDesc *descs);

cc ... -lpcp

DESCRIPTION

Étant donné un identifiant de métrique de performance (PMID) sous forme de pmid, la routine pmLookupDesc remplit la structure pmDesc donnée, pointée par le paramètre desc, à partir du contexte actuel de l'interface de programmation d'application des métriques de performance (PMAPI).

La variante pmLookupDescs fournit une fonctionnalité équivalente pour numpmid métriques à la fois, avec le tableau pmids fournissant les identifiants de métriques à rechercher. Elle est plus efficace à mesure que le nombre de métriques augmente, car elle évite la latence des allers-retours de plusieurs requêtes individuelles. Notez que le protocole d'erreur garantit une relation 1:1 entre les éléments de descs et pmids, donc les deux listes contiennent exactement numpmid éléments. Pour cette raison, l'appelant est censé avoir pré-alloué un tableau de taille appropriée pour descs.

La structure pmDesc fournit toutes les informations requises pour décrire et manipuler une métrique de performance via la PMAPI, et a la déclaration suivante.

/* Descripteur de métrique de performance */
typedef struct {
    pmID    pmid;   /* identifiant unique */
    int     type;   /* type de données de base (voir ci-dessous) */
    pmInDom indom;  /* domaine d'instance */
    int     sem;    /* sémantique de la valeur (voir ci-dessous) *
    pmUnits units;  /* dimension et unités (voir ci-dessous) */
} pmDesc;
/* pmDesc.type -- type de données des valeurs de métrique */
#define PM_TYPE_NOSUPPORT        -1    /* non impl. dans cette version */
#define PM_TYPE_32               0    /* entier signé 32 bits */
#define PM_TYPE_U32              1    /* entier non signé 32 bits */
#define PM_TYPE_64               2    /* entier signé 64 bits */
#define PM_TYPE_U64              3    /* entier non signé 64 bits */
#define PM_TYPE_FLOAT            4    /* virgule flottante 32 bits */
#define PM_TYPE_DOUBLE           5    /* virgule flottante 64 bits */
#define PM_TYPE_STRING           6    /* tableau de char */
#define PM_TYPE_AGGREGATE        7    /* données binaires arbitraires */
#define PM_TYPE_AGGREGATE_STATIC 8    /* pointeur statique vers l'agrégat */
#define PM_TYPE_EVENT            9    /* pmEventArray packed */
#define PM_TYPE_UNKNOWN          255  /* utilisé dans pmValueBlock, pas pmDesc */
/* pmDesc.sem -- sémantique/interprétation des valeurs de métrique */
#define PM_SEM_COUNTER  1  /* compteur cumulatif (incrément monotone) */
#define PM_SEM_INSTANT  3  /* valeur instantanée domaine continu */
#define PM_SEM_DISCRETE 4  /* valeur instantanée domaine discret */

Le champ type dans pmDesc décrit divers encodages (ou formats) pour la valeur d'une métrique.

Si une valeur est comptée dans l'instrumentation de base sous-jacente avec moins de 32 bits de précision entière, il incombe à l'agent de domaine des métriques de performance (PMDA) de promouvoir la valeur à un entier 32 bits avant son exportation dans le sous-système de collecte des métriques de performance (PMCS) ; c'est-à-dire que les applications au-dessus de la PMAPI n'ont jamais à traiter des compteurs de 8 bits et 16 bits.

Si la valeur d'une métrique de performance est de type PM_TYPE_AGGREGATE, PM_TYPE_AGGREGATE_STATIC, PM_TYPE_EVENT ou PM_TYPE_STRING, l'interprétation de la valeur est inconnue du PMCS. Dans ces cas, l'application utilisant la valeur, et le PMDA fournissant la valeur doivent avoir une compréhension commune de la manière dont la valeur est structurée et interprétée.

Chaque valeur d'une métrique de performance est supposée provenir d'un ensemble de valeurs qui peuvent être décrites en termes de leur dimensionnalité et de leur échelle par un encodage compact comme suit. La dimensionnalité est définie par une puissance, ou un indice, dans chacune des 3 dimensions orthogonales, à savoir Espace, Temps et Comptage (ou Événements, qui sont sans dimension). Par exemple, le débit d'E/S peut être représenté comme           -1 Espace.Temps
tandis que le total cumulé des appels système est Comptage, l'allocation de mémoire est Espace et le temps de service moyen est           -1 Temps.Comptage
Dans chaque dimension, il existe un certain nombre de valeurs d'échelle communes qui peuvent être utilisées pour mieux encoder des plages qui autrement épuiseraient la précision d'une valeur 32 bits. Ces informations sont encodées dans la structure pmUnits qui est intégrée dans la structure pmDesc.

/*
 * Encodage des unités (dimensions Temps et Espace) et de l'échelle
 * pour les valeurs de métriques de performance
 *
 * Par exemple, une structure pmUnits de
 *      { 1, -1, 0, PM_SPACE_MBYTE, PM_TIME_SEC, 0 }
 * représente Mbytes/sec, tandis que
 *      { 0, 1, -1, 0, PM_TIME_HOUR, 6 }
 * représente heures/million-événements
 */
typedef struct {
    int dimSpace:4;             /* dimension espace */
    int dimTime:4;              /* dimension temps */
    int dimCount:4;             /* dimension événement */
    unsigned int scaleSpace:4;  /* une des PM_SPACE_* ci-dessous */
    unsigned int scaleTime:4;   /* une des PM_TIME_* ci-dessous */
    int scaleCount:4;           /* une des PM_COUNT_* ci-dessous */
} pmUnits;                      /* unités dimensionnelles et échelle de la valeur */
/* pmUnits.scaleSpace */
#define PM_SPACE_BYTE   0       /* octets */
#define PM_SPACE_KBYTE  1       /* Kilooctets (1024) */
#define PM_SPACE_MBYTE  2       /* Mégaoctets (1024^2) */
#define PM_SPACE_GBYTE  3       /* Gigaoctets (1024^3) */
#define PM_SPACE_TBYTE  4       /* Téraoctets (1024^4) */
#define PM_SPACE_PBYTE	5	/* Pétaoctets (1024^5) */
#define PM_SPACE_EBYTE	6	/* Exaoctets (1024^6) */
#define PM_SPACE_ZBYTE	7	/* Zettaoctets (1024^7) */
#define PM_SPACE_YBYTE	8	/* Yottaoctets (1024^8) */
/* pmUnits.scaleTime */
#define PM_TIME_NSEC    0       /* nanosecondes */
#define PM_TIME_USEC    1       /* microsecondes */
#define PM_TIME_MSEC    2       /* millisecondes */
#define PM_TIME_SEC     3       /* secondes */
#define PM_TIME_MIN     4       /* minutes */
#define PM_TIME_HOUR    5       /* heures */
/*
 * pmUnits.scaleCount (par exemple, comptage d'événements, appels système,
 * interruptions, etc.) ce sont simplement des puissances de 10, et ne sont pas
 * énumérées ici, par exemple 6 pour 10^6, ou -3 pour 10^-3
 */
#define PM_COUNT_ONE    0       /* 1 */

Des routines spéciales (par exemple, pmExtractValue(3), pmConvScale(3)) sont fournies pour manipuler les valeurs en conjonction avec la structure pmUnits qui définit la dimension et l'échelle des valeurs pour une métrique de performance particulière.

En dessous de la PMAPI, les informations nécessaires pour compléter la structure pmDesc sont récupérées auprès des PMDA, et de cette manière, le format et l'échelle des métriques de performance peuvent changer dynamiquement, à mesure que les PMDA et leur instrumentation sous-jacente évoluent avec le temps. En particulier, lorsque certaines métriques deviennent soudainement de 64 bits de long, ou changent leurs unités de Mo en Go, les applications bien écrites utilisant les services fournis par la PMAPI continueront de fonctionner correctement.

DIAGNOSTIQUES

Ces routines renvoient un code d'erreur négatif pour indiquer un échec.

PM_ERR_PMID
Le PMID demandé n'est pas connu du PMCS
PM_ERR_NOAGENT
Le PMDA responsable de la fourniture de la métrique n'est actuellement pas disponible

pmLookupDesc renvoie zéro pour indiquer le succès.

Le résultat de pmLookupDescs dépend de la présence de tout échec de recherche, de sa gravité et du nombre de métriques recherchées.

1.
En l'absence d'échec de recherche, la valeur de retour sera numpmid.
2.
Si une erreur fatale est rencontrée, la valeur de retour sera inférieure à 0. Par exemple PM_ERR_IPC.
3.
Si numpmid est supérieur à un et que des erreurs non fatales sont rencontrées, la valeur de retour est le nombre de descripteurs de métriques qui ont été recherchés avec succès (supérieur ou égal à zéro et inférieur ou égal à numpmid).
4.
Si numpmid est un et qu'une erreur non fatale est rencontrée, la valeur de retour est le code d'erreur (inférieur à zéro).

Lorsque des erreurs sont rencontrées, toutes les métriques qui ne peuvent pas être recherchées entraînent la définition du champ pmid de l'élément de descripteur correspondant de descs à PM_ID_NULL. Le protocole d'erreur légèrement alambiqué permet des recherches groupées, puis une exploration pour plus de détails d'erreur en cas d'échec spécifique.
