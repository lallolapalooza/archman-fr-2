NOM

pmdaproc - agent de domaine de métriques de performance des processus (PMDA)

SYNTAXE

$PCP_PMDAS_DIR/proc/pmdaproc [-AL] [-D debug] [-d domaine] [-l logfile] [-r cgroup] [-U username]

DESCRIPTION

pmdaproc est un agent de domaine de métriques de performance (PMDA) qui extrait des métriques de performance décrivant l'état des processus individuels exécutés sur un système Linux.

Le PMDA proc exporte des métriques qui mesurent l'utilisation de la mémoire, du processeur et d'autres ressources de chaque processus, ainsi que des informations récapitulatives collectées sur l'ensemble des processus en cours d'exécution. Le PMDA utilise les identifiants transmis par l'outil de surveillance PMAPI(3) identifiant l'utilisateur demandant l'information, pour s'assurer que seules les valeurs auxquelles l'utilisateur est autorisé à accéder sont retournées par le PMDA. Cela implique que le PMDA change temporairement ses identifiants effectifs d'utilisateur et de groupe pendant la durée des requêtes pour les instances et les valeurs. En d'autres termes, les appels système pour extraire des informations sont effectués en tant qu'utilisateur à l'origine de la demande et non en tant qu'utilisateur privilégié. Les mécanismes disponibles pour le transfert des identifiants d'utilisateur sont décrits plus en détail dans la page PCPIntro(1).

Une brève description des options de ligne de commande de pmdaproc suit :

-A
Désactive l'utilisation des identifiants fournis par les outils clients PMAPI et exécute simplement tout sous le compte "root". Reportez-vous à la section CONFIGURATION DE L'ACCÈS ci-dessous pour un contrôle plus fin lors de l'utilisation de pmcd(1) avec authentification client à distance. N'activez cette option que si vous comprenez les risques encourus et si vous êtes sûr que tous les accès à distance proviendront d'utilisateurs bienveillants. Si activé, les clients PMAPI distants non authentifiés pourront accéder à des valeurs de métriques de performance potentiellement sensibles auxquelles un client PMAPI non authentifié ne pourrait normalement pas accéder. Reportez-vous aux CVE-2011-2495 et CVE-2012-3419 pour plus de détails.
-L
Modifie le domaine d'instance par processus utilisé par la plupart des métriques pmdaproc pour inclure également les threads.
-d
Il est absolument crucial que le numéro de domaine des métriques de performance domain spécifié ici soit unique et cohérent. C'est-à-dire que domain doit être différent pour chaque PMDA sur un même hôte, et le même numéro de domain doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé proc.log est écrit dans le répertoire courant de pmcd(1) lors du démarrage de pmdaproc, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou s'il n'est pas accessible en écriture, la sortie est redirigée vers l'erreur standard.
-r
Restreint l'ensemble des processus exportés dans le domaine d'instance par processus à uniquement ceux qui sont contenus dans le conteneur de ressources cgroup spécifié. Cette option fournit une granularité facultative plus fine à la surveillance, et peut également être utilisée pour réduire les ressources consommées par pmdaproc lors des requêtes d'instances et de valeurs.
-U
Compte utilisateur sous lequel exécuter l'agent. La valeur par défaut est le compte privilégié "root", avec commutation seteuid(2) et setegid(2) pour accéder à la plupart des informations.

APERÇU HOTPROC

L'agent de domaine de métriques de performance (PMDA) pmdaproc inclut un ensemble supplémentaire de métriques par processus avec un domaine d'instance de processus restreint à un ensemble "intéressant" ou "chaud". Contrairement aux métriques standard exportées par le PMDA proc, qui ont un domaine d'instance égal aux processus en cours, les métriques hot ont un domaine d'instance qui en est un sous-ensemble. Ce domaine d'instance hotproc est déterminé par un prédicat configurable évalué sur un intervalle de rafraîchissement donné.

En plus des métriques proc équivalentes par processus, hotproc fournit une métrique cpuburn qui spécifie l'utilisation du CPU du processus sur l'intervalle de rafraîchissement, des métriques total qui indiquent quelle part du temps CPU disponible est utilisée par les processus "intéressants", des métriques predicate qui affichent les valeurs des variables réservées (voir ci-dessous) utilisées dans le prédicat hotproc, et des métriques control pour le contrôle de l'agent.

CONFIGURATION HOTPROC

Le fichier de configuration consiste en un seul prédicat utilisé pour déterminer si un processus doit faire partie de l'ensemble intéressant ou non.

Un exemple de fichier de configuration peut être trouvé à $PCP_PMDAS_DIR/proc/samplehotproc.conf

Ce fichier, avec les modifications éventuelles, peut être copié vers $PCP_PMDAS_DIR/proc/hotproc.conf afin de configurer les métriques hot. Les interfaces pmstore(1) et pmStore(3) peuvent également être utilisées (décrites ci-dessous).

Le prédicat est décrit en utilisant le langage spécifié ci-dessous. Les symboles sont basés sur ceux utilisés par les langages C(1) et awk(1).

Connectifs Booléens
&& (et), || (ou), ! (non), () (priorité)
Comparateurs Numériques
< , <= , > , >= , == , !=
Comparateurs de Chaînes
== , !=
Comparateurs Chaîne/Modèle
~ (la chaîne correspond au modèle) , !~ (la chaîne ne correspond pas au modèle)
Variables Réservées
uid (id utilisateur ; type entier) uname (nom d'utilisateur ; type chaîne), gid (id groupe ; type entier) gname (nom de groupe ; type chaîne), fname (nom de fichier du processus ; type chaîne), psargs (nom de fichier du processus avec arguments ; type chaîne), cpuburn (utilisation CPU ; type float), iodemand (demande d'E/S - Kbytes lus/écrits par seconde ; type float), ctxswitch (nombre de changements de contexte par seconde ; type float), syscalls (nombre d'appels système par seconde ; type float), virtualsize (taille virtuelle en Kbytes ; type float), residentsize (taille résidente en Kbytes ; type float), iowait (attente E/S bloquée et brute en sec/sec ; type float), schedwait (temps d'attente dans la file d'exécution en sec/sec ; type float).
Valeurs Littérales
1234 (entier positif), 0.35 (flottant positif), "foobar" (chaîne ; délimitée par "), /[fF](o)+bar/ (modèle ; délimité par /), true (booléen), false (booléen)
Commentaires
# ceci est un commentaire (de # à la fin de la ligne).
Exemples

cpuburn > 0.2 # utilisation CPU supérieure à 20%
cpuburn > 0.2 && uname == "root"
cpuburn > 0.2 && (uname == "root" || uname == "hot")
psargs ~ /pmda/ && cpuburn > 0.4

Les métriques hotproc.predicate peuvent être utilisées pour voir quelles étaient les valeurs des variables réservées utilisées par le prédicat lors du dernier rafraîchissement. Elles ne couvrent pas les variables réservées qui sont déjà exportées ailleurs. Une métrique hotproc.predicate pourrait ne pas avoir de valeur si elle n'est pas référencée dans le prédicat de configuration.

CONFIGURATION DYNAMIQUE

Les métriques de processus hot peuvent également être configurées à l'exécution via l'interface pmstore(1) (et, implicitement, l'API pmStore(3))

Exemples
Voir la section CONFIGURATION DYNAMIQUE de pmdastat(1).

NAME

pmdaproc, pmiproc — process performance metrics domain agent

SYNOPSIS


$PCP_PMDAPIDIR/pmdaproc [options]

DESCRIPTION

The pmdaproc is an optional Performance Metrics Domain Agent (PMDA) that can be used to provide performance metrics for individual processes.

The process accounting metrics are accessed via the PCP proc PMDA. This PMDA can track metrics for all visible processes on the system, or it can be configured to track only a subset of processes. The configuration for this PMDA is specified using the hotproc.conf configuration file.

The pmdaproc agent can be configured to only track processes matching specified criteria, and can be set to track a limited number of processes. This is useful for reducing the overhead of monitoring a large number of processes, or for focusing on a specific set of processes.

HOTPROC OVERVIEW

The hotproc configuration file allows you to specify criteria for selecting processes to monitor. This is done using a set of rules that are applied to each process on the system. The rules can be based on various attributes of the process, such as its name, user ID, or group ID.

The hotproc.conf file is located in $PCP_PMDAS_DIR/proc/hotproc.conf. It consists of a series of rules, one per line. Each rule is a boolean expression that evaluates to true if the process should be monitored.

The following is an example of a simple hotproc.conf file:

# Monitor all processes named "apache" or "nginx"
fname in ("apache", "nginx")

# Monitor all processes run by user "www-data"
uid == "www-data"

# Monitor all processes with PID greater than 1000
pid > 1000

The hotproc configuration can also specify a maximum number of processes to monitor. This is done using the limit keyword. For example:

# Monitor up to 100 processes
limit 100

HOTPROC CONFIGURATION

The pmdaproc agent uses a configuration file named hotproc.conf to specify which processes to monitor. This file can be overridden by the PCP_PMDAS_DIR/proc/hotproc.conf file.

The configuration file consists of a series of rules. Each rule is a boolean expression that is evaluated for each process on the system. If a rule evaluates to true for a process, then that process is monitored.

The following attributes can be used in the rules:

fname
The name of the executable file for the process.
uid
The user ID of the process owner.
gid
The group ID of the process owner.
pid
The process ID.
cmd
The command line arguments for the process.

The rules can be combined using logical operators such as and, or, and not. Parentheses can be used to control the order of evaluation.

The following is an example of a configuration file that monitors all processes named "nginx" or "apache" that are run by the user "www-data":

(fname == "nginx" or fname == "apache") and uid == "www-data"

A limit can be specified using the limit keyword:

limit 100

This limits the number of monitored processes to 100. The specific processes chosen will depend on the order in which they are encountered and the rules defined.

DYNAMIC CONFIGURATION

The configuration for the proc PMDA can be dynamically updated without restarting the PMDA or PMCD. This is achieved using the pmstore(1) command.

To update the set of rules used to select processes, use the hotproc.control.config parameter.

For example, to select only processes named 'mingetty' and processes run by the root user (UID 0):


pmstore hotproc.control.config 'fname == "mingetty"'
pmstore hotproc.control.config 'uid == 0'

The new configuration will be loaded and applied immediately. Existing monitored processes that no longer match the new rules will be unmonitored, and new processes that match the new rules will be monitored.

To force the config file to be reloaded:


pmstore hotproc.control.reload_config "1"

ACCESS CONFIGURATION

Access to per-process metrics is controlled by several factors.

When using automatically authenticating local connections, such as through the "unix:" or "local:" style context, then client tools will have full access to these metrics as if sampling the metrics directly as the user running the client tool.

When using pmcd with remote, authenticated clients it is possible to specify a set of user names that are allowed access to the process metrics.

A configuration file $PCP_SYSCONF_DIR/proc/access.conf can be used to fine-tune this behaviour, and it supports two keywords:

allowed
A comma-separated list of authenticated user names that will be allowed access to per-process metrics. Sampling is performed as the root user.
mapped
A boolean value, when true indicating that authenticated user names will be mapped to local system user account names (this requires a one-to-one user name mapping between the account and the SASL-based authenticated user name enforced by pmcd(1)). Sampling is performed as that local user.

INSTALLATION

The proc PMDA is installed and available by default. If you want to undo the installation, do the following as root:

# cd $PCP_PMDAS_DIR/proc
# ./Remove

If you want to establish access to the names, help text and values for the proc performance metrics once more, after removal, do the following as root:

# cd $PCP_PMDAS_DIR/proc
# ./Install

pmdaproc is launched by pmcd(1) and should never be executed directly. The Install and Remove scripts notify pmcd(1) when the agent is installed or removed.

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.

Debugging options specific to pmdaproc are as follows:

Option Description
appl0 cgroup handling
appl1 refresh processing, including hotproc metrics
appl2 PMNS operations
appl3 process accounting metrics
