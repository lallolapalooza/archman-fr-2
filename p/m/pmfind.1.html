PMFIND(1) Manuel des commandes générales PMFIND(1)

NOM

pmfind - trouver des services PCP sur le réseau

SYNTAXE

pmfind [-CqrSV?] [-D debug] [-m mécanisme] [-s service] [-t timeout]

DESCRIPTION

pmfind recherche des instances du service PCP spécifié annoncées sur le réseau et affiche une liste d'URL correspondant aux services découverts. Il peut être utilisé conjointement avec pmfind_check(1) pour automatiser la surveillance des systèmes collecteurs PCP distants.

OPTIONS

Les options de ligne de commande disponibles sont :

-C, --containers
Effectue également la découverte des conteneurs, pour chaque service pmcd(1) découvert.
-m mécanisme, --mechanism=mécanisme
Cette option définit le mécanisme utilisé par pmfind lors de la découverte de services. Par défaut, ou si le mot-clé all est spécifié, chaque mécanisme disponible sera utilisé (itérativement). Voir la section « MÉCANISMES » pour une description de chaque mécanisme de découverte disponible.
-q, --quiet
Cette option supprime toute sortie sur le flux de sortie standard.
-r, --resolve
Demande que la résolution de noms DNS soit tentée pour les adresses des services découverts. Par défaut, les adresses réseau des services découverts sont affichées.
-s service, --service=service
Par défaut, pmfind recherche tous les services PCP pris en charge, mais un service PCP spécifique à découvrir peut être spécifié à l'aide de l'option -s. Les services pris en charge sont pmcd(1) et pmproxy(1).
-S, --sources
Rapporte les identifiants de source pour chaque service pmcd(1) découvert. Ces identifiants sont uniques pour chaque hôte et sont formés à partir des étiquettes de contexte (non optionnelles) disponibles pour chaque collecteur PCP. Étant donné que le processus de découverte identifie souvent plusieurs chemins vers un hôte collecteur individuel, cette option est une partie importante du processus d'utilisation de pmfind conjointement avec pmfind_check(1), pour s'assurer qu'un seul processus pmie(1) et/ou pmlogger(1) est démarré pour chaque hôte collecteur découvert. Les identifiants de source rapportés par pmfind sont les mêmes que ceux rapportés par les commandes pminfo(1) et pmseries(1).
-t secondes, --timeout=secondes
Définit le temps maximum en secondes que pmfind mettra avant d'interrompre la découverte du service. L'argument temps est un nombre flottant représentant le nombre de secondes avant l'expiration du délai. Par défaut, le temps nécessaire pour terminer le processus est utilisé.
-V, --version
Affiche le numéro de version et quitte.
-?, --help
Affiche le message d'utilisation et quitte.

MÉCANISMES

Les mécanismes pris en charge pour la découverte de services sont :

avahi
Recherche les services diffusés via mDNS en utilisant avahi-daemon(8). Un suffixe optionnel ",timeout=N" peut être ajouté pour limiter le temps d'attente pour avahi-daemon. N est un nombre flottant spécifiant le nombre de secondes d'attente. La valeur par défaut est de 0.5 secondes. Ce délai d'attente peut également être défini en configurant la variable d'environnement AVAHI_DISCOVERY_TIMEOUT avec le nombre de secondes souhaité. Si les deux sont spécifiés, la valeur définie dans la variable d'environnement a la priorité.
probe=<adresse-réseau>/<bits-de-masque>
Sonde activement le sous-réseau donné pour les services PCP demandés. <adresse-réseau> est une adresse réseau Inet ou IPv6 et <bits-de-masque> est le nombre de bits utilisés pour définir le sous-réseau. Par exemple, 192.168.1.0/24 définit un sous-réseau de 8 bits composé des adresses 192.168.1.0 à 192.168.1.255. Un suffixe optionnel ",maxThreads=N" peut être ajouté pour limiter le nombre de threads utilisés lors de la sonde. La valeur par défaut est la valeur de FD_SETSIZE (généralement 1024) ou le nombre d'adresses dans le sous-réseau, le moindre des deux. Un suffixe optionnel ",timeout=N" peut être ajouté pour limiter le temps passé à attendre chaque tentative de connexion. N est un nombre flottant spécifiant le nombre de secondes d'attente. La valeur par défaut est de 0.02 secondes (20 millisecondes).
shell
Sonde la liste d'adresses fournie par des scripts pour les services PCP demandés. Plusieurs paramètres optionnels séparés par des virgules peuvent également être fournis. L'option "path=DIR" spécifie le répertoire où se trouvent les commandes comme pcp-kube-pods(1) (par défaut, $PCP_BINADM_DIR/discover/). Ce paramètre peut être restreint à une commande individuelle en utilisant l'option command=CMD, mais par défaut, toutes les commandes disponibles du path sont utilisées. L'option "maxThreads=N" limite le nombre de threads utilisés lors de la sonde. La valeur par défaut est la valeur de FD_SETSIZE (généralement 1024) ou le nombre d'adresses retournées par les scripts, le moindre des deux. L'option "timeout=N" peut être ajoutée pour limiter le temps passé à attendre chaque tentative de connexion. N est un nombre flottant spécifiant le nombre de secondes d'attente. La valeur par défaut est de 0.02 secondes (20 millisecondes).

SIGNaux

pmfind interrompra le processus de découverte de services lors de la réception de l'un des signaux suivants : SIGHUP, SIGPIPE, SIGINT, SIGTERM, SIGXFSZ, SIGXCPU. pmfind rapportera tous les résultats découverts jusqu'au moment de l'interruption.

DIAGNOSTIC

La valeur du code de sortie de la commande est zéro si des services ont été trouvés avec succès, un si aucun service n'a été trouvé, et deux si une erreur s'est produite.

En cas d'erreur, un message sera généré sur la sortie d'erreur standard, qui est censé être auto-explicatif.

FICHIERS

$PCP_BINADM_DIR/discover
chemin par défaut vers les scripts de découverte d'adresses

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à trier les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
