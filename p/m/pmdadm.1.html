NOM

pmdadm - PMDA de Device Mapper

SYNTAXE

$PCP_PMDAS_DIR/dm/pmdadm [-D debug]

DESCRIPTION

pmdadm est un Agent de Domaine de Métriques de Performance (PMDA) qui exporte les valeurs de métriques pour le Device Mapper sur le système local.

Ce PMDA collecte ses données via l'utilitaire dmsetup(8) et l'API dmstats, et nécessite que le programme soit installé pour fonctionner. De plus, au moins une région de statistiques doit être créée à l'aide de l'utilitaire dmstats(8) afin d'obtenir des valeurs de compteurs de base. Voir ci-dessous pour des exemples.

Notez que la collecte de statistiques de device-mapper n'est pas activée par défaut et n'est pas persistante après les redémarrages (à moins qu'un administrateur système n'ait configuré quelque chose pour s'exécuter dans rc.local ou équivalent). Ceci est dû aux surcoûts associés à la collecte de statistiques. De plus, le PMDA pmdadm n'active pas automatiquement la collecte de statistiques car il pourrait ne pas être le seul consommateur des données.

INSTALLATION

Installez le PMDA DM en utilisant le script d'installation en tant que root :

# cd $PCP_PMDAS_DIR/dm
# ./Install

Pour désinstaller, les commandes suivantes doivent être exécutées en tant que root :

# cd $PCP_PMDAS_DIR/dm
# ./Remove

pmdadm est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove informent pmcd lorsque l'agent est installé ou retiré.

CONFIGURATION

Ce PMDA utilise l'API dmstats (la bibliothèque de support de device-mapper en espace utilisateur) pour capturer les données de performance de device-mapper.
En utilisant ce PMDA, les utilisateurs ont besoin de la bibliothèque de support de device-mapper en espace utilisateur (libdevmapper) et de l'outil en ligne de commande en espace utilisateur dmstats(8). Avant que les métriques de device-mapper ne soient disponibles pour PCP, des régions de statistiques doivent être créées. Par exemple, pour activer les statistiques de base pour tous les périphériques logiques de device-mapper locaux, utilisez la commande suivante :

# dmstats create --alldevices

Pour créer des régions de statistiques avec des limites d'histogramme spécifiées, utilisez ce qui suit :

# dmstats create --alldevices --bounds limites_histogramme

Spécifiez les limites d'un histogramme de latence à suivre pour la région sous forme de liste de valeurs de latence séparées par des virgules. Les valeurs de latence sont données en nanosecondes. Un suffixe d'unité facultatif ns, us, ms ou s peut être ajouté après chaque valeur pour spécifier des unités de nanosecondes, microsecondes, millisecondes ou secondes respectivement. Par exemple,

# dmstats create --alldevices --bounds 10us,30us,50us,70us,90us

Plus de détails et d'exemples plus complexes se trouvent dans dmstats(8).

MÉTRIQUES

Compteurs de base
Les compteurs de base fournissent un accès aux données brutes des compteurs du noyau, permettant un traitement ultérieur par un autre programme.
Le noyau fournit treize compteurs distincts pour chaque zone de statistiques. Les onze premiers correspondent aux compteurs fournis dans /proc/diskstats ou /sys/block/*/*/stat. La paire finale fournit des compteurs distincts pour le temps de lecture et d'écriture.
dmstats.read
Nombre de lectures terminées pendant cet intervalle par périphérique device-mapper.
dmstats.reads_merged
Nombre de lectures fusionnées pendant cet intervalle par périphérique device-mapper.
dmstats.read_bytes
Nombre de kbytes lus pendant cet intervalle par périphérique device-mapper.
dmstats.reads_time
Durée accumulée de toutes les requêtes de lecture par périphérique device-mapper.
dmstats.write
Nombre d'écritures terminées pendant cet intervalle par périphérique device-mapper.
dmstats.writes_merged
Nombre d'écritures terminées pendant cet intervalle par périphérique device-mapper.
dmstats.write_bytes
Nombre de kbytes écrits pendant cet intervalle par périphérique device-mapper.
dmstats.writes_time
Durée accumulée de toutes les requêtes d'écriture par périphérique device-mapper.
dmstats.in_progress
Nombre de requêtes en cours par périphérique device-mapper.
dmstats.io_ticks
Nanosecondes passées à traiter les requêtes par périphérique device-mapper.
dmstats.queue_ticks
Ce champ est incrémenté à chaque début d'E/S, fin d'E/S, fusion d'E/S, ou lecture de ces statistiques par le nombre d'E/S en cours multiplié par le nombre de nanosecondes passées à effectuer des E/S depuis la dernière mise à jour de ce champ. Cela peut fournir une mesure facile du temps de fin d'E/S et du backlog qui peut s'accumuler.
dmstats.read_ticks
Nanosecondes passées à traiter les lectures par périphérique device-mapper.
dmstats.write_ticks
Nanosecondes passées à traiter les écritures par périphérique device-mapper.
Champs d'histogramme
Les histogrammes mesurent la distribution de fréquence des intervalles de latence d'E/S spécifiés par l'utilisateur. Les limites des classes d'histogramme sont spécifiées lors de la création d'une région.
Le nom d'instance représente le nom de l'appareil, l'identifiant de la région et les limites des classes.
dmstats.histogram.hist_count
Une liste des comptes d'histogramme pour la zone de statistiques actuelle, dans l'ordre croissant de latence. Chaque valeur représente le nombre d'E/S dont les temps de latence tombent dans la plage de temps de cette classe pendant la période d'échantillonnage.
dmstats.histogram.hist.bins
Le nombre de classes d'histogramme de latence configurées pour la zone.

EXEMPLES

# dmstats create looptest0 --bounds 10us,30us,50us
looptest0: Created new region with 1 area(s) as region ID 0


# pminfo -f dmstats.read dmstats.histogram.hist_count

dmstats.read
inst [0 or "looptest0"] value 4099

dmstats.histogram.hist_count
inst [0 or "looptest0:0:0s"] value 1
inst [1 or "looptest0:0:10us"] value 3752
inst [2 or "looptest0:0:30us"] value 250
inst [3 or "looptest0:0:50us"] value 96

CONFIGURATION

Le fichier de configuration $PCPCFG/pmcd.conf (voir pcp.conf(5)) contient les options de configuration pour le démon de collection de métriques.

METRICS

La commande pmdadm est utilisée pour installer, désinstaller, démarrer et arrêter les pilotes de métriques (PMDAs).

EXAMPLES

Pour installer le pilote de métriques du noyau Linux :

pmdadm install linux

Pour désinstaller le pilote de métriques du noyau Linux :

pmdadm remove linux

Pour démarrer le pilote de métriques du noyau Linux :

pmdadm start linux

Pour arrêter le pilote de métriques du noyau Linux :

pmdadm stop linux

Pour répertorier tous les pilotes de métriques installés :

pmdadm list

FILES

/etc/pcp/pmcd.conf
Fichier de configuration principal pour le démon de collection de métriques.

PCP ENVIRONMENT

La commande pmdadm est influencée par les variables d'environnement suivantes :

PCPCFG
Spécifie le répertoire de configuration de Performance Co-Pilot. Par défaut, il s'agit de /etc/pcp.
PCP_PMCD_SOCKET
Spécifie le chemin d'accès au socket du démon de collection de métriques (PMCD). Par défaut, il s'agit de /var/run/pcp/pmcd.socket.

OPTIONS DE DÉBOGAGE

L'option -D ou --debug permet d'afficher des diagnostics supplémentaires sur stderr pour aider au dépannage, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
