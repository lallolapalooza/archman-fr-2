PMSNAP(1) Manuel des commandes générales PMSNAP(1)

NOM

pmsnap - génère des images de résumé des performances

SYNTAXE

$PCP_BINADM_DIR/pmsnap [-NV?] [-c configs] [-C rép] [-f format] [-n noms] [-o rép]

DESCRIPTION

pmsnap est un script shell normalement exécuté périodiquement à partir de crontab(1) pour générer des images graphiques des graphiques de performances pmchart(1). Ces images peuvent être dans n'importe lequel des formats pris en charge par pmchart, y compris png, bmp et jpeg, et peuvent être incorporées dans le contenu offert par le serveur web local. Par défaut, pmsnap ne génère aucune sortie textuelle sauf si une condition d'erreur ou d'avertissement est rencontrée.

pmsnap génère des images selon son fichier de contrôle, $PCP_PMSNAPCONTROL_PATH (ou dir/control si l'option -C est spécifiée), et utilise des archives créées par pmlogger(1) ou des folios d'archives PCP créés par pmafm(1) et pmlogger_check(1). Avant de tenter de configurer pmsnap, il est fortement recommandé de configurer pmlogger conformément aux descriptions de pmlogger_daily(1), pmlogger_check(1) et pmlogger(1).

Une fois pmlogger configuré, il est nécessaire de configurer pmsnap comme suit ;

1.
Modifiez le fichier de contrôle $PCP_PMSNAPCONTROL_PATH. La syntaxe de ce fichier est décrite dans le commentaire en tête de fichier et un exemple est fourni pour des graphiques de performances "Résumé" d'une heure et de douze heures pour l'hôte local. Les arguments appropriés pour pmchart sont également décrits dans le commentaire. L'utilisateur doit consulter pmchart pour plus de détails. Notez que lorsque pmsnap est exécuté, il substitue globalement la chaîne LOCALHOSTNAME par le nom de l'hôte local dans le fichier de contrôle.
2.
Testez la configuration en exécutant
$PCP_BINADM_DIR/pmsnap. Sans arguments, pmsnap traitera chaque ligne non commentée dans $PCP_PMSNAPCONTROL_PATH. Les images de sortie seront placées dans les fichiers nommés dans le premier champ de chaque ligne du fichier de contrôle, avec l'extension du format de fichier ajoutée si nécessaire. Si ces noms de fichiers ne commencent pas par / ou ., ils sont supposés relatifs à rép, comme spécifié avec l'option -o. Le rép par défaut est le répertoire courant. Notez que si pmlogger n'a démarré que récemment (environ dans les 15 dernières minutes), des images instantanées peuvent ne pas être produites et aucun message d'erreur ne sera émis - la raison est que pmchart ne peut pas utiliser des archives très courtes et donc, ni pmsnap. À des fins de débogage, l'indicateur -V doit être utilisé.
3.
Ajoutez une entrée appropriée pour pmsnap dans le crontab de l'utilisateur root. Un exemple est fourni dans $PCP_VAR_DIR/config/pmlogger/crontab.
4.
Incorporez les images pmsnap dans le contenu WWW local. Habituellement, les pages WWW utilisent des images relatives à une racine de document particulière, il est donc souvent pratique d'utiliser l'option de ligne de commande -o pour spécifier un sous-répertoire du contenu WWW local, puis de créer une page web dans ce répertoire qui affiche les images instantanées avec du texte et d'autres contenus appropriés à l'environnement local.

Une page HTML d'exemple, appropriée pour l'instantané "Summary", se trouve dans $PCP_VAR_DIR/config/pmsnap/Summary.html.

Bien que pmsnap tente de vider les tampons de sortie stdio(3) dans les processus pmlogger pertinents avant de générer des images instantanées, cela peut échouer pour diverses raisons et aucun message d'erreur ne sera donné.

pmsnap ne doit pas être invoqué immédiatement après que pmlogger_daily a fait rouler les journaux car les nouvelles archives seront trop courtes pour obtenir des résultats significatifs. Notez cependant que pmsnap ne rapportera pas les erreurs de pmchart concernant l'impossibilité de se conformer à l'option -A sur des archives très courtes. Dans ces cas, aucune erreur ne sera signalée et aucune image de sortie ne sera produite.

OPTIONS

Les options de ligne de commande disponibles sont :

-c modèle-config
Traiter uniquement les lignes du fichier de contrôle qui correspondent à l'expression régulière modèle-config dans la colonne Config.
-C rép
Le fichier control se trouve dans le répertoire rép plutôt qu'à l'emplacement par défaut $PCP_PMSNAPCONTROL_PATH.
-f format
Définir le format de l'image de sortie. Le format par défaut est png.
-n modèle-nom
Traiter uniquement les lignes du fichier de contrôle qui correspondent à l'expression régulière modèle-nom (voir egrep(1)) dans la colonne Name.
-N
Activer un mode "montre-moi", où les actions sont échoées, mais pas exécutées, dans le style de "make -n". Utiliser -N conjointement avec -V maximise les capacités de diagnostic pour le débogage.
-o rép
Les images de sortie dont les noms de fichiers ne commencent pas par / ou . seront placées dans un répertoire relatif à rép, sinon le répertoire de sortie est relatif au répertoire courant (c'est-à-dire que la valeur par défaut pour rép est ./). Notez que rép doit être un chemin de répertoire inscriptible et peut se trouver sur un système de fichiers NFS ou CIFS.
-V
Activer le mode verbeux.
-?
Afficher le message d'utilisation et quitter.

Lorsque -n ou -c sont utilisés, pmsnap ne traitera que les lignes du fichier de contrôle qui correspondent à tous les modèles fournis. Si aucun modèle n'est donné, toutes les lignes seront traitées. Ces arguments permettent des entrées multiples pour pmsnap dans crontab afin que différentes images de résumé des performances puissent être générées à des moments différents ou avec des fréquences différentes.

pmsnap(1)

PMSNAP(1) User Commands PMSNAP(1)

DESCRIPTION

The pmsnap utility is used to take snapshots of the Pango markup language. This is useful for debugging Pango markup and for creating portable Pango markup files.

OPTIONS

The pmsnap utility accepts the following options:

-o output_file
Write the Pango markup snapshot to output_file. If this option is not specified, the snapshot will be written to standard output.
-h
Display a help message and exit.

FILES

None.
