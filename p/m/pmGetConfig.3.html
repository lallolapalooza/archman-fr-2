PMGETCONFIG(3) Manuel des fonctions de bibliothèque PMGETCONFIG(3)

NOM

pmGetConfig, pmGetOptionalConfig, pmGetAPIConfig - valeurs de retour pour les variables de configuration de Performance Co-Pilot

SYNTAXE C

#include <pcp/pmapi.h>

char *pmGetConfig(const char *variable);
char *pmGetOptionalConfig(const char *variable);
char *pmGetAPIConfig(const char *feature);

cc ... -lpcp

DESCRIPTION

Les fonctions pmGetConfig et pmGetOptionalConfig recherchent variable d'abord dans l'environnement, puis, si elle n'y est pas trouvée, dans le fichier de configuration de Performance Co-Pilot (PCP) et retournent le résultat sous forme de chaîne de caractères. Si variable n'est pas déjà dans l'environnement, elle y est ajoutée avec un appel à setenv(3) avant de retourner.

La fonction pmGetOptionalConfig tolère les échecs - que ce soit parce que variable n'est pas définie du tout, ou parce que le fichier de configuration est manquant. pmGetConfig est moins tolérante à un fichier de configuration manquant, qu'elle traite comme un échec critique de l'installation PCP - voir la section « VALEUR DE RETOUR » ci-dessous pour plus de détails.

L'emplacement par défaut du fichier de configuration PCP est /etc/pcp.conf, mais cela peut être modifié en définissant PCP_CONF dans l'environnement avec un nouvel emplacement, comme décrit dans pcp.conf(5).

La fonction pmGetAPIConfig rapporte les fonctionnalités de la bibliothèque PCP. Elle peut être utilisée pour interroger le support du multithreading, des extensions de sécurité, et d'autres fonctionnalités.

L'utilitaire pmconfig(1) fournit un accès en ligne de commande à ces deux interfaces, et offre également un mécanisme pour lister toutes les variables et fonctionnalités valides pour ces routines.

VALEUR DE RETOUR

Si variable n'est trouvée ni dans l'environnement ni dans le fichier de configuration PCP, ou si le fichier de configuration est inaccessible, alors pmGetOptionalConfig retourne NULL.

Si variable n'est trouvée ni dans l'environnement ni dans le fichier de configuration PCP, alors pmGetConfig retourne une chaîne vide. Si le fichier de configuration PCP n'est pas trouvé, un message d'erreur fatal est imprimé et le processus exit(2)era - bien que cela semble drastique, c'est la seule action possible car la configuration/installation PCP est jugée fatalement défectueuse.

La routine pmGetAPIConfig retourne NULL en cas d'échec de recherche de la fonctionnalité demandée. Elle ne modifie pas l'environnement et retourne un pointeur vers une chaîne statique en lecture seule.

La valeur retournée par chacune de ces routines est soit un pointeur statique, soit un pointeur vers l'environnement, et donc le modifier est une mauvaise idée.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5). Les valeurs de ces variables peuvent être obtenues par programme en utilisant la fonction pmGetConfig(3).
