PMSTORE(1) Manuel des commandes générales PMSTORE(1)

NOM

pmstore - modifier les valeurs des métriques de performance

SYNTAXE

pmstore [-fFLV?] [-D debug] [-h host] [-i instances] [-K spécification] [-n fichier pmns] nom_métrique valeur

DESCRIPTION

Dans certaines circonstances, il est utile de pouvoir modifier les valeurs des métriques de performance, par exemple pour réinitialiser des compteurs ou pour assigner de nouvelles valeurs à des métriques qui servent de variables de contrôle.

pmstore modifie les valeurs actuelles pour les instances nommées d'une métrique de performance unique, identifiée par nom_métrique et la liste des identifiants d'instance suivant l'argument -i. instances doit être un seul argument, avec les éléments de la liste séparés par des virgules et/ou des espaces blancs. Par défaut, toutes les instances de nom_métrique seront mises à jour.

Normalement, pmstore opère sur l'espace de noms des métriques de performance (PMNS) par défaut, voir PMNS(5), cependant, si l'option -n est spécifiée, un espace de noms alternatif est chargé depuis le fichier fichier pmns.

Sauf indication contraire sur un autre hôte par l'option -h, pmstore interagira avec le démon collecteur de métriques de performance (PMCD) sur l'hôte local.

L'option -L amène pmstore à utiliser un contexte local pour enregistrer des métriques à partir des PMDA locaux sans passer par PMCD. Seules certaines métriques sont disponibles dans ce mode. Les options -h et -L sont mutuellement exclusives.

L'option -f force la valeur donnée à être enregistrée, même s'il n'y a pas de valeur actuelle définie.

L'interprétation de valeur dépend de la syntaxe utilisée dans sa spécification et du type de données sous-jacent de nom_métrique, comme suit :

1.
Si la métrique a un type entier, alors valeur doit être un signe moins optionnel, suivi soit de chiffres décimaux, soit de « 0x » et de quelques chiffres hexadécimaux. « 0X » est également acceptable à la place de « 0x ». Voir strtol(3) et les routines associées.
2.
Si la métrique a un type à virgule flottante, alors valeur doit être soit sous la forme d'un entier décrit ci-dessus, soit d'un nombre à virgule fixe, soit d'un nombre en notation scientifique. Voir strtod(3).
3.
Si la métrique a un type chaîne, alors valeur est interprétée comme une chaîne littérale de caractères ASCII.
4.
Si la métrique a un autre type (c'est-à-dire PM_TYPE_EVENT ou PM_TYPE_AGGREGATE), alors aucun encodage de valeur depuis la ligne de commande n'a de sens, et les valeurs de ces métriques ne peuvent pas être modifiées avec pmstore.

La sortie rapporte l'ancienne valeur et la nouvelle valeur pour chaque instance mise à jour de la métrique demandée.

Lors de l'utilisation de l'option -L pour récupérer des métriques d'un contexte local, l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spécification respecte la syntaxe décrite dans pmSpecLocalPMDA(3). Plusieurs options -K peuvent être utilisées.

Normalement, pmstore rapporte l'ancienne valeur (telle que initialement récupérée à l'aide de pmFetch(3)) et la nouvelle valeur provenant de la ligne de commande. L'option -F force un autre appel à pmFetch(3) après le l'appel à pmStore(3) et la valeur renvoyée est rapportée comme nouvelle valeur. Ceci est utile dans les cas où nom_métrique est une métrique qui fournit des sémantiques différentes pour l'opération de stockage, par exemple pour incrémenter la valeur actuelle ou réinitialiser un compteur (indépendamment de la valeur de la ligne de commande).

OPTIONS

Les options disponibles en ligne de commande sont :

-f, --force
Enregistre la valeur même si aucune valeur actuelle n'est définie.
-F, --fetch
Rapporte la valeur de la métrique après l'avoir définie.
-i insts, --insts=insts
Restreint l'enregistrement à la liste d'instances séparées par des virgules.
-h hôte, --host=hôte
Se connecte à pmcd(1) sur hôte, plutôt que sur l'hôte local par défaut.
-K spécification, --spec-local=spécification
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spécification respecte la syntaxe décrite dans pmSpecLocalPMDA(3). Plusieurs options -K peuvent être utilisées.
-L, --local-PMDA
Utilise un contexte local pour collecter des métriques à partir des PMDA DSO sur l'hôte local sans passer par PMCD. Voir aussi -K.
-n fichier pmns, --namespace=fichier pmns
Normalement, pmcd charge l'espace de noms des métriques de performance (PMNS) par défaut depuis $PCP_VAR_DIR/pmns/root, cependant, si l'option -n est spécifiée, un espace de noms alternatif est chargé depuis le fichier fichier pmns.
-V, --version
Affiche le numéro de version et quitte.
-?, --help
Affiche le message d'utilisation et quitte.

DIAGNOSTICS

Deux messages indiquent une incompatibilité entre le type de données interne pour nom_métrique et la valeur fournie.

La valeur "???" est hors limites pour le type de données (PM_TYPE_...)

La valeur "???" est incompatible avec le type de données (PM_TYPE_...)

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active l'affichage de diagnostics supplémentaires sur stderr pour aider à résoudre les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

VOIR AUSSI
