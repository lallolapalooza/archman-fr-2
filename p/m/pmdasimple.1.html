PMDASIMPLE(1) Manuel des commandes générales PMDASIMPLE(1)

NOM

pmdasimple - agent de domaine de métriques de performance simple (PMDA)

SYNOPIS

$PCP_PMDAS_DIR/simple/pmdasimple [-D débogage] [-d domaine] [-i port] [-l fichier_log] [-p] [-U nom_utilisateur] [-u socket]

DESCRIPTION

pmdasimple est un agent de domaine de métriques de performance (PMDA) simple qui exporte un petit nombre de métriques de performance synthétiques.

Le PMDA simple est fourni sous forme de code source et est conçu pour aider les développeurs de PMDA. En termes de taille de code et de fonctionnalités, il est plus complexe que le PMDA trivial, à peu près aussi complexe que le PMDA txmon et moins complexe que le PMDA sample. Le code source du PMDA simple constitue un bon modèle à partir duquel des PMDA personnalisés et de production peuvent être développés.

Une brève description des options de ligne de commande de pmdasimple suit :

-d
-d
-d
Il est absolument crucial que le numéro de domaine domaine spécifié ici soit unique et cohérent. C'est-à-dire, domaine doit être différent pour chaque PMDA sur le même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-i
-i
-i
Attend que PMCD se connecte à pmdasimple sur le port TCP/IP spécifié. port peut être un numéro de port ou un nom de port.
-l
-l
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé simple.log est écrit dans le répertoire courant de pmcd(1) lors du démarrage de pmdasimple, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou s'il n'est pas inscriptible, la sortie est envoyée sur la sortie standard d'erreur.
-p
-p
-p
Attend que PMCD crée un pipe et que la connexion à pmdasimple se fasse via l'entrée standard et la sortie standard. C'est le mode de connexion par défaut.
-u
-u
-u
Attend que PMCD se connecte à pmdasimple sur le socket de domaine Unix nommé socket.
-U
-U
-U
Compte utilisateur sous lequel exécuter l'agent. Par défaut, il s'agit du compte non privilégié « pcp » dans les versions récentes de PCP, mais dans les versions plus anciennes, le compte superutilisateur (« root ») était utilisé par défaut.

Au plus une des options -i, -p et -u peut être spécifiée.

INSTALLATION

Si vous souhaitez accéder aux noms, textes d'aide et valeurs des métriques de performance simples, faites ce qui suit en tant que root :

# cd $PCP_PMDAS_DIR/simple
# ./Install

Si vous souhaitez annuler l'installation, faites ce qui suit en tant que root :

# cd $PCP_PMDAS_DIR/simple
# ./Remove

pmdasimple est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove notifient pmcd(1) lorsque l'agent est installé ou supprimé.

FICHIERS

$PCP_PMCDCONF_PATH
options de ligne de commande utilisées pour lancer pmdasimple
$PCP_PMDAS_DIR/simple/help
fichier texte d'aide par défaut pour les métriques simples
$PCP_PMDAS_DIR/simple/Install
script d'installation pour l'agent pmdasimple
$PCP_PMDAS_DIR/simple/Remove
script d'annulation d'installation pour l'agent pmdasimple
$PCP_PMDAS_DIR/simple/simple.conf
fichier de configuration pour le domaine d'instance dynamique qui sous-tend la métrique de performance simple.now. Pour une description, référez-vous au fichier texte d'aide, ou exécutez la commande

$ pminfo -T simple.now

$PCP_PMDAS_DIR/simple/*.pmda_simple.so
La version DSO du PMDA. Le même code source est utilisé pour créer la version DSO et la version démon du PMDA simple, et l'un ou l'autre peut être installé dans le cadre du dialogue dans le script Install.
$PCP_LOG_DIR/pmcd/simple.log
fichier journal par défaut pour les messages d'erreur et autres informations provenant de pmdasimple

ENVIRONNEMENT PCP

Les variables d'environnement dont le préfixe est PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à résoudre les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à fournir des conseils aux développeurs plutôt qu'aux utilisateurs finaux. débogage est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et de leur signification.
