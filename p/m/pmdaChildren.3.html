NOM

pmdaChildren - traduire un PMID en un ensemble de noms de métriques de performance dynamiques

SYNTAXE EN C

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaChildren(char *name,
int traverse, char ***offspring, int **status, pmdaExt *pmda);

cc ... -lpcp_pmda -lpcp

DESCRIPTION

Dans le cadre de l'API PMDA (Performance Metrics Domain Agent) (voir PMDA(3)), pmdaChildren est le rappel générique pour retourner les noms de métriques dynamiques (et leur statut) qui sont des descendants de name.

Étant donné que l'implémentation des métriques de performance dynamiques nécessite un support PMDA spécifique, et que la fonctionnalité est une composante optionnelle d'un PMDA (la plupart des PMDA ne supportent **pas** les métriques de performance dynamiques), pmdaChildren est une implémentation squelette qui retourne PM_ERR_NAME.

Un PMDA qui supporte les métriques de performance dynamiques fournira un rappel privé qui remplace pmdaChildren (par affectation à version.four.children de la structure pmdaInterface) et prend le nom initial de la métrique name et retourne les noms via offspring[] et le statut feuille ou non-feuille de chacun via status[].

Si traverse est 0, alors le comportement est similaire à pmGetChildren(3) et offspring[] contient le composant de nom relatif pour les descendants immédiats de name.

Si traverse est 1, alors le comportement est similaire à pmTraversePMNS(3) et offspring[] contient les noms absolus de toutes les métriques dynamiques qui sont des descendants de name.

La liste résultante de pointeurs offspring **et** les valeurs des chaînes (les noms) auxquelles les pointeurs font référence auront été allouées par pmdaChildren avec un seul appel à malloc(3), et l'appelant de pmdaChildren appellera free(offspring) pour libérer l'espace lorsqu'il ne sera plus requis. Il en va de même pour le tableau status, à savoir que l'appelant de pmdaChildren appellera free(status) pour libérer l'espace lorsqu'il ne sera plus requis.

AVERTISSEMENT

Le PMDA doit utiliser PMDA_INTERFACE_4 ou une version ultérieure, comme spécifié dans l'appel à pmdaDSO(3) ou pmdaDaemon(3).

DIAGNOSTICS

pmdaChildren retourne PM_ERR_NAME si le nom n'est pas reconnu ou ne peut pas être traduit, sinon le nombre de noms de métriques descendants trouvés.

VOIR AUSSI

PMAPI(3), PMDA(3), pmdaDaemon(3), pmdaDSO(3), pmdaMain(3), pmGetChildren(3) et pmTraversePMNS(3).
