PMIADDMETRIC(3) Manuel des fonctions de bibliothèque PMIADDMETRIC(3)

NOM

pmiAddMetric - ajouter une nouvelle définition de métrique à un contexte LOGIMPORT

SYNTAXE C

#include <pcp/pmapi.h>
#include <pcp/import.h>

int pmiAddMetric(const char *name,
pmID pmid, int type, pmInDom indom, int sem, pmUnits units);

cc ... -lpcp_import -lpcp

SYNTAXE Perl

use PCP::LogImport;

pmiAddMetric($name,
$pmid, $type, $indom, $sem, $units);

DESCRIPTION

Dans le cadre de l'API d'importation de journaux de Performance Co-Pilot (voir LOGIMPORT(3)), pmiAddMetric est utilisée pour définir une nouvelle métrique. Le name de la métrique doit suivre les conventions de nommage décrites dans PCPIntro(1) et doit être unique pour chaque contexte LOGIMPORT.

Les autres arguments sont en effet les champs d'une structure pmDesc. Reportez-vous à pmLookupDesc(3) pour une description complète des valeurs et des sémantiques des composants de cette structure, et donc des valeurs d'arguments valides pour pmiAddMetric.

L'identifiant interne de la métrique peut être fourni à l'aide de l'argument pmid et doit être unique pour chaque contexte LOGIMPORT. La valeur de pmid serait typiquement construite en utilisant la macro pmID_build, par exemple pmID_build(PMI_DOMAIN, 0, 3) pour la quatrième métrique du premier « cluster » de métriques dans le domaine des métriques de performance PMI_DOMAIN (qui est la valeur par défaut pour toutes les métadonnées créées par la bibliothèque LOGIMPORT). Alternativement, pmid peut être PM_IN_NULL et pmiAddMetric attribuera un pmid unique (bien que cela signifie que le pmid reste opaque et que l'application doit utiliser pmiPutValue(3) ou pmiPutValueHandle(3) et ne peut pas utiliser pmiPutResult(3) pour ajouter des valeurs de données à l'archive PCP).

type définit le type de données de la métrique et doit être une des valeurs PM_TYPE_... définies dans <pcp/import.h>.

Le domaine d'instances pour la métrique est défini par indom et peut être PM_INDOM_NULL pour une métrique avec une valeur singulière, sinon la valeur de indom serait normalement construite en utilisant la macro pmInDom_build, par exemple pmInDom_build(LOGIMPORT,0) pour le premier domaine d'instances dans le domaine des métriques de performance LOGIMPORT (qui est la valeur par défaut pour toutes les métadonnées créées par la bibliothèque LOGIMPORT). Plusieurs métriques peuvent partager le même domaine d'instances si elles ont des valeurs pour un ensemble d'instances similaire (ou plus généralement identique).

La sémantique de la métrique (compteur, valeur instantanée, etc.) est spécifiée par l'argument sem qui serait normalement le résultat d'un appel à la méthode de construction pratique pmiUnits(3).

DIAGNOSTICS

pmiAddMetric renvoie zéro en cas de succès, sinon une valeur négative qui peut être transformée en message d'erreur en appelant pmiErrStr(3).

VOIR AUSSI
