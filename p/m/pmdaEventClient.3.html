PMDAEVENTCLIENT(3) Manuel des fonctions de bibliothèque PMDAEVENTCLIENT(3)

NOM

pmdaEventNewClient, pmdaEventEndClient, pmdaEventClients - interfaces de suivi de contexte client pour les files d'attente d'événements

C SYNTAXE

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaEventNewClient(int context);
int pmdaEventEndClient(int context);
int pmdaEventClients(pmAtomValue *avp);

cc ... -lpcp_pmda -lpcp

DESCRIPTION

Un agent de domaine de métriques de performance (PMDA) qui exporte des enregistrements d'événements doit suivre quels clients y sont connectés, afin de pouvoir suivre quels événements ont été envoyés à quels clients jusqu'à présent. Ce n'est qu'une fois qu'un événement a été envoyé à tous les outils de surveillance qui ont enregistré un intérêt que l'événement peut être écarté et toute mémoire récupérée.

La bibliothèque PMDA(3) fournit des routines de rappel pour les développeurs PMDA afin de fournir une gestion personnalisée des connexions et déconnexions de clients. Si le PMDA utilise le mécanisme de mise en file d'attente d'événements fourni par pmdaEventNewQueue(3) et les fonctions associées, les connexions et déconnexions de clients doivent être suivies via des appels à pmdaEventNewClient et pmdaEventEndClient respectivement. Cela permet à la bibliothèque de suivre quand les événements peuvent être écartés d'une file d'attente, par exemple, pour le context spécifié. Ce paramètre est passé directement dans la fonction de rappel e_endCallBack, et pour d'autres fonctions de rappel, il est disponible via le champ e_context de la structure pmdaExt. De plus, il peut être interrogé à tout moment en utilisant pmdaGetContext(3).

Il est parfois utile pour le PMDA d'exporter une métrique indiquant le nombre actuel de clients attachés - ceci est disponible en utilisant la routine pmdaEventClients, qui remplira la structure pmAtomValue avp pour le compte d'une routine de rappel de récupération PMDA.

VOIR AUSSI

pmdaEventNewArray(3), pmdaEventNewQueue(3), PMAPI(3), PMDA(3) et pmEventFlagsStr(3).
