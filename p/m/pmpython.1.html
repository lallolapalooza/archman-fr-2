PMPYTHON(1) Manuel des commandes générales PMPYTHON(1)

NOM

pmpython - exécute un script python en utilisant une variante python préférée

SYNTAXE

pmpython [arguments-python-et-script]

DESCRIPTION

pmpython fournit un moyen d'exécuter des scripts python en utilisant un interpréteur python personnalisable, plutôt que d'intégrer le nom d'une version particulière de python dans chaque script.

Cela peut être utile car cela permet d'exécuter du code python indépendant de la version n'importe où. Tous les modules python livrés avec PCP supportent les versions 2.6 et ultérieures (dans la série python2), et 3.3 et ultérieures (dans la série de versions python3).

Étant donné que les scripts de surveillance et de collecte python sont relativement simples dans PCP (ne nécessitant pas de nouveaux modules, fonctionnalités linguistiques, etc.), il a été possible de s'assurer qu'ils fonctionnent pour toutes les versions de python ci-dessus.

Cependant, le nom de l'interpréteur python n'est pas toujours le même. Ainsi, il est courant que les scripts python PCP utilisent une ligne « shebang » qui lance l'interpréteur python indirectement comme suit :


#!/usr/bin/env pmpython

env(1) est utilisé pour trouver le chemin correct pour l'exécutable pmpython depuis le $PATH de l'utilisateur.

Par défaut, le nom de l'interpréteur python est trouvé à partir de la valeur de $PCP_PYTHON_PROG de l'environnement (si défini) sinon de /etc/pcp.conf. Ce dernier est le cas le plus typique où cette valeur est basée sur quelques heuristiques concernant la plateforme au moment de la construction des paquets PCP et favorise l'utilisation de python3 dans toutes les versions récentes de PCP (pour les plateformes qui le supportent).

Cela permet d'utiliser un nom approprié pour l'interpréteur python au lieu d'un nom de version python codé en dur, tout en permettant à l'utilisateur de remplacer l'interpréteur python comme suit :


$ PCP_PYTHON_PROG=python3 pmpython --version
Python 3.4.2
$ PCP_PYTHON_PROG=python2 pmpython --version
Python 2.7.9

C'est pratique pour distribuer des scripts identiques sur plusieurs plateformes, et pour tester différentes versions de python avec le même script (par exemple, dans le cas où plusieurs versions de python sont installées, PCP_PYTHON_PROG peut être défini dans l'environnement local pour remplacer le réglage global).

pmpython remplace un outil antérieur de fonction similaire, à savoir pcp-python(1).

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

VOIR AUSSI

env(1), pcp(1), pcp-python(1) et PCPIntro(1).
