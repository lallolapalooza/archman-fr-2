NOM

pmdapostgresql - PMDA de base de données PostgreSQL

DESCRIPTION

pmdapostgresql est un Agent de domaine de métriques de performance (PMDA) de Performance Co-Pilot (PCP) qui extrait des données de performance en temps réel d'un serveur de base de données PostgreSQL en cours d'exécution.

Beaucoup de statistiques disponibles à partir d'un serveur PostgreSQL peuvent ne pas être activées par défaut. Référez-vous à la documentation en ligne https://www.postgresql.org/docs/current/static/monitoring-stats.html qui décrit chacun des paramètres disponibles liés à la collecte de statistiques et comment les activer.

CONFIGURATION

pmdapostgresql lit un fichier de configuration obligatoire de type ini :

$PCP_PMDAS_DIR/postgresql/postgresql.conf

Ce fichier contient actuellement une seule section [authentication] qui spécifie les valeurs pour les paramètres suivants (leurs valeurs par défaut sont indiquées entre parenthèses) :

host (local)
Nom d'hôte auquel se connecter.
port (5432)
Numéro de port à utiliser.
dbname (postgres)
Nom de la base de données.
username (postgres)
Nom d'utilisateur pour exécuter et se connecter à la base de données.
password (password)
Mot de passe pour se connecter à la base de données.
osuser (non défini)
Utilisateur du système d'exploitation sous lequel le PMDA s'exécute.

Les valeurs par défaut (comme ci-dessus) entraîneront l'exécution du PMDA en tant qu'utilisateur actuel, en utilisant une connexion de socket de domaine UNIX au serveur PostgreSQL sur le localhost.

Si osuser n'est pas spécifié dans le fichier de configuration, le PMDA s'exécutera en tant qu'utilisateur actuel. Une spécification d'hôte de local utilisera un socket de domaine UNIX, qui utilise l'authentification par pairs, voir les commentaires dans le fichier pg_hba.conf. Dans ce cas, le paramètre osuser devrait probablement être défini sur postgres.

Il n'est généralement pas nécessaire de modifier le fichier de configuration par défaut pour surveiller l'instance locale du serveur PostgreSQL avec une configuration serveur par défaut. Notez que le numéro de port est requis même pour une connexion par socket UNIX car il est utilisé comme nom de fichier de socket par le serveur.

INSTALLATION

Pour installer, les actions suivantes doivent être effectuées en tant que root :

# cd $PCP_PMDAS_DIR/postgresql
# ./Install

Pour désinstaller, les actions suivantes doivent être effectuées en tant que root :

# cd $PCP_PMDAS_DIR/postgresql
# ./Remove

pmdapostgresql est lancé par pmcd(1) et ne devrait jamais être exécuté directement. Les scripts Install et Remove informent pmcd(1) lorsque l'agent est installé ou supprimé.

pmdapostgresql tentera automatiquement de se reconnecter au serveur PostgreSQL si sa connexion est perdue - par exemple, si le service PostgreSQL est redémarré.

VERSIONS SUPPORTÉES

Cette version de pmdapostgresql a été testée et vérifiée avec la version du serveur PostgreSQL 10.2 et les versions antérieures. Les versions ultérieures fonctionneront probablement aussi correctement car le PMDA interroge les différentes tables de performance au démarrage pour déterminer l'ordre des colonnes. Il tolère également les tables et/ou colonnes manquantes ou renommées.

FICHIERS

$PCP_PMDAS_DIR/postgresql/pmdapostgresql.conf
fichier de configuration de l'agent pmdapostgresql
$PCP_PMDAS_DIR/postgresql/Install
script d'installation de l'agent pmdapostgresql
$PCP_PMDAS_DIR/postgresql/Remove
script d'annulation d'installation de l'agent pmdapostgresql
$PCP_LOG_DIR/pmcd/postgresql.log
fichier journal par défaut pour les messages de l'agent pmdapostgresql

Notez que la valeur habituelle/par défaut pour $PCP_PMDAS_DIR est /var/lib/pcp/pmdas et la valeur par défaut pour $PCP_LOG_DIR est /var/log/pcp, mais ces paramètres dépendent de la plateforme.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

VOIR AUSSI

PCPIntro(1), pmcd(1) et https://www.postgresql.org/docs/current/static/monitoring-stats.html.
