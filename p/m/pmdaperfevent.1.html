NOM

pmdaperfevent - agent de domaine de métriques de performance (PMDA) pour les compteurs de performance matériels

SYNOPIS

$PCP_PMDAS_DIR/perfevent/pmdaperfevent [-d domaine] [-l fichier-journal] [-U nom-utilisateur] [-i port] [-p] [-u socket] [-6]

DESCRIPTION

pmdaperfevent est un agent de domaine de métriques de performance (PMDA) qui configure et lit les compteurs de performance matériels en utilisant l'API perf_event du noyau Linux.

Le PMDA perfevent exporte les métriques pour les compteurs de performance matériels qui sont configurables à partir de l'API perf_event du noyau Linux. Le PMDA utilise la bibliothèque libpfm4 pour accéder aux compteurs de performance matériels, donc tous les compteurs pris en charge par libpfm4 devraient être disponibles. Il inclut également la capacité de lire les compteurs Intel RAPL via un accès MSR direct. Le PMDA prend en charge le chargement automatique de différents compteurs pour chaque architecture matérielle. Un seul fichier de configuration est utilisé pour spécifier les compteurs souhaités pour chaque unité de surveillance de performance matérielle (PMU). Le fichier de configuration permet de programmer différents compteurs sur différents processeurs et prend en charge l'affectation circulaire des compteurs non-uncore nécessaires pour certaines puces AMD.

Le PMDA compte également les événements exposés dans le noyau via le répertoire /sys/bus/event_source/devices. Le nom de l'appareil PMU et le nom de l'événement doivent être mentionnés dans le fichier de configuration. Sinon, la métrique ne sera pas disponible pour être surveillée via ce PMDA.

Le PMDA configure les compteurs pour compter les événements en mode utilisateur et en mode noyau. Cela signifie que les compteurs matériels ne sont pas disponibles pour les applications utilisateur normales non privilégiées lorsqu'ils sont utilisés par le PMDA. Le PMDA fournit un mécanisme pour désactiver temporairement les compteurs système afin de permettre aux utilisateurs normaux d'utiliser les compteurs s'ils le souhaitent. Voir perfalloc(1) pour plus de détails.

Notez que pmdaperfevent est affecté par la valeur du paramètre kernel.perf_event_paranoid, qui peut être ajustée par sysctl(8).

Une brève description des options de ligne de commande de pmdaperfevent suit :

-d
Il est absolument crucial que le numéro de domaine des métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire que domaine doit être différent pour chaque PMDA sur le même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé perfevent.log est écrit dans le répertoire courant de pmcd(1) lorsque pmdaperfevent est démarré, c'est-à-dire **$PCP_LOG_DIR/pmcd**. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est redirigée vers la sortie d'erreur standard.
-U
Compte utilisateur sous lequel exécuter l'agent. Le défaut est le compte privilégié « root ».
-i
écouter sur le port spécifié pour la connexion de pmcd(1)
-p
communiquer avec pmcd(1) via stdin/stdout
-u
s'attendre à ce que pmcd(1) se connecte sur le socket de domaine Unix spécifié
-6
s'attendre à ce que pmcd(1) se connecte sur le port IPv6 spécifié (numéro ou nom)

INSTALLATION

Le PMDA perfevent n'est pas activé par défaut. Pour installer le PMDA, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/perfevent
# ./Install

Si vous souhaitez annuler l'installation, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/perfevent
# ./Remove

pmdaperfevent est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove informent pmcd(1) lorsque l'agent est installé ou supprimé.

MISE À NIVEAU

Certains noms de métriques ont changé à partir de la version 3.10.8 pour mieux se conformer aux conventions PMNS. pmlogrewrite(1) peut être utilisé pour mettre à jour les anciennes archives. Un utilitaire d'aide, $PCP_PMDAS_DIR/perfevent/perfevent-makerewrite.pl générera un fichier de configuration adapté à l'utilisation avec pmlogrewrite(1) pour mettre à jour les noms de métriques dans les archives existantes.

BOGUES

Chaque événement est placé dans son propre groupe et il n'y a aucun moyen de regrouper des événements liés afin qu'ils soient garantis d'être actifs simultanément. Une solution de contournement consiste à s'assurer que le nombre d'événements configurés est inférieur ou égal au nombre de compteurs matériels disponibles. Cela signifie que les événements ne seront pas multiplexés dans le temps par le noyau et seront actifs simultanément.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).
