PMCLIENT(1) Manuel des commandes générales PMCLIENT(1)

NOM

pmclient, pmclient_fg - un client simple de métriques de performance

SYNTAXE

pmclient [-PVz?] [-a archive] [-A align] [-D debug] [-h hôte] [-n fichier_pmns] [-O origine] [-s échantillons] [-S heure_début] [-t intervalle] [-T heure_fin] [-Z fuseau_horaire]

pmclient_fg ...

DESCRIPTION

pmclient et pmclient_fg sont des clients simples qui utilisent l'interface de programmation d'application de métriques de performance (PMAPI) pour rapporter certaines métriques de performance système de haut niveau.

La vraie valeur de ces outils réside dans leur utilisation comme exemples de clients utilisant les interfaces de PMAPI(3). À cet effet, le code source est inclus dans le paquet Performance Co-Pilot (PCP) (voir PCPIntro(1)), et est typiquement installé dans /usr/share/pcp/demos/pmclient.

Le programme pmclient_fg diffère de pmclient en ce qu'il utilise l'extension d'API fetchgroup à la PMAPI, voir pmFetchGroup(3).

Normalement, pmclient opère sur l'Espace Nom de Métriques de Performance (PMNS) distribué, cependant si l'option -n est spécifiée, un PMNS local alternatif est chargé à partir du fichier fichier_pmns.

Sauf indication contraire vers un autre hôte par l'option -h, ou vers une archive par l'option -a, pmclient contactera le démon collecteur de métriques de performance (PMCD) sur l'hôte local pour obtenir les informations requises. L'argument de -a est une liste d'origines séparées par des virgules, chacune pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives. Les options -a et -h sont mutuellement exclusives.

Par défaut, pmclient rapporte l'heure locale selon le fuseau horaire du système où pmclient est exécuté. L'option -Z change le fuseau horaire en fuseau_horaire dans le format de la variable d'environnement TZ tel que décrit dans environ(7). L'option -z change le fuseau horaire en celui de l'hôte source des métriques de performance, tel qu'identifié via les options -h ou -a.

La sortie de pmclient est dirigée vers la sortie standard, et liste

+
L'utilisation CPU agrégée, dans la plage de 0 à 1.
+
Si le système a plus d'un CPU, le numéro ordinal du CPU le plus sollicité, dans la plage de 0 à ...
+
Si le système a plus d'un CPU, l'utilisation CPU du CPU le plus sollicité.
+
Mémoire libre réelle en Mo.
+
Opérations d'entrée/sortie disque physique agrégées par seconde (IOPS).
+
Charge moyenne sur la dernière minute et sur les 15 dernières minutes.

OPTIONS

Les options de ligne de commande disponibles sont :

-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-A alignement, --align=alignement
Forcer le premier échantillon à être aligné sur la limite d'une unité de temps naturelle alignement. Se référer à PCPIntro(1) pour une description complète de la syntaxe de alignement.
-h hôte, --host=hôte
Récupérer les métriques de performance depuis pmcd(1) sur hôte, plutôt que depuis localhost par défaut.
-n fichier_pmns, --namespace=fichier_pmns
Charger un Espace Nom de Métriques de Performance (PMNS) alternatif (PMNS(5)) à partir du fichier fichier_pmns.
-O origine, --origin=origine
Lors du rapport de métriques archivées, commencer le rapport à origine dans la fenêtre temporelle (voir -S et -T). Se référer à PCPIntro(1) pour une description complète de la syntaxe de origine.
-P, --pause
Le comportement par défaut pour la relecture d'un ensemble d'archives est de rejouer à pleine vitesse. L'option -P peut être utilisée en conjonction avec un ensemble d'archives, pour demander que le délai temps réel prévalent soit appliqué entre les échantillons (voir -t) pour effectuer une pause.
-s échantillons, --samples=échantillons
L'argument échantillons définit le nombre d'échantillons à récupérer et à rapporter. Si échantillons est 0 ou si -s n'est pas spécifié, pmclient échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive).
-S heure_début, --start=heure_début
L'option -S peut être utilisée en conjonction avec un ensemble d'archives pour demander que l'affichage commence à heure_début à partir du début de l'archive(s). Se référer à PCPIntro(1) pour une description complète de la syntaxe de heure_début.
-t intervalle, --interval=intervalle
Définir l'intervalle de rapport à quelque chose d'autre que les 5 secondes par défaut. L'argument intervalle suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes).
-T heure_fin, --finish=heure_fin
Lors du rapport de métriques archivées, le rapport sera restreint aux enregistrements enregistrés avant ou à heure_fin. Se référer à PCPIntro(1) pour une description complète de la syntaxe de heure_fin.
-V, --version
Afficher le numéro de version et quitter.
-z, --hostzone
Utiliser le fuseau horaire local de l'hôte source des métriques de performance, tel qu'identifié par les options -h ou -a. Par défaut, le fuseau horaire de l'hôte local est utilisé.
-Z fuseau_horaire, --timezone=fuseau_horaire
Utiliser fuseau_horaire pour la date et l'heure. Fuseau_horaire est dans le format de la variable d'environnement TZ tel que décrit dans environ(7).
-?, --help
Afficher le message d'utilisation et quitter.

FICHIERS

$PCP_DEMOS_DIR/pmclient
Code source, documentation, fichiers de configuration et Makefile lorsque le paquet de développement PCP est installé

ENVIRONNEMENT PCP

Les variables d'environnement préfixées par PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, tel que décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider au dépannage, bien que les informations soient parfois cryptiques et principalement destinées à fournir des indications aux développeurs plutôt qu'aux utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
