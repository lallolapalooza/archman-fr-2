PMGETINDOM(3) Manuel des fonctions de bibliothèque PMGETINDOM(3)

NOM

pmGetInDom - obtenir les identifiants d'instance pour un domaine d'instances de métriques de performance

SYNTAXE C

#include <pcp/pmapi.h>

int pmGetInDom(pmInDom indom,
int **instlist, char ***namelist);

cc ... -lpcp

DESCRIPTION

Dans le contexte actuel de l'interface de programmation d'applications de métriques de performance (PMAPI), localise la description du domaine d'instances indom, et renvoie via instlist les identifiants d'instance internes de toutes les instances, et via namelist les identifiants externes complets de toutes les instances. Le nombre d'instances trouvées est renvoyé comme valeur de retour de la fonction (sinon moins de zéro pour indiquer une erreur).

La valeur du domaine d'instances indom est typiquement extraite d'une structure pmDesc, suite à un appel à pmLookupDesc(3) pour une métrique de performance particulière.

Les listes résultantes d'identifiants d'instance (instlist et namelist), et les noms auxquels les éléments de namelist pointent, auront été alloués par pmGetInDom avec deux appels à malloc(3), et il est de la responsabilité de l'appelant de free(instlist) et free(namelist) pour libérer l'espace lorsqu'il n'est plus nécessaire.

Lorsque le résultat de pmGetInDom est inférieur à un, instlist et namelist sont indéfinis (aucun espace n'aura été alloué, et donc l'appel à free(3) est une très mauvaise idée).

DIAGNOSTICS

PM_ERR_INDOM
indom n'est pas un identifiant de domaine d'instance valide

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5). Les valeurs de ces variables peuvent être obtenues par programmation en utilisant la fonction pmGetConfig(3).

VOIR AUSSI
