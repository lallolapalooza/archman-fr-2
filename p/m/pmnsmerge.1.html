NOM

pmnsmerge - fusionne plusieurs versions d'un PMNS Performance Co-Pilot

SYNOPSIS

$PCP_BINADM_DIR/pmnsmerge [-adfxv] [-D debug] infile [...] outfile

DESCRIPTION

pmnsmerge fusionne plusieurs instances d'un espace de noms de métriques de performance (PMNS), tel qu'utilisé par les composants du Performance Co-Pilot (PCP).

Chaque argument infile nomme un fichier qui inclut la racine d'un PMNS, de la forme


root {
    /* arbitraire */
}

L'ordre dans lequel les fichiers infile sont traités est déterminé par la présence ou l'absence de lignes de contrôle incorporées de la forme

#define _DATESTAMP YYYYMMDD

Les fichiers sans ligne de contrôle sont traités en premier et dans l'ordre où ils apparaissent sur la ligne de commande. Les autres fichiers sont ensuite traités par ordre croissant de _DATESTAMP.

L'option -a supprime le réordonnancement des arguments et traite tous les fichiers dans l'ordre où ils apparaissent sur la ligne de commande.

La fusion progresse en faisant correspondre les noms dans le PMNS, seuls les noms nouveaux dans chaque PMNS sont pris en compte, et ils sont ajoutés après les métriques existantes avec le plus long préfixe correspondant possible dans leurs noms. Par exemple, la fusion de ces deux PMNS d'entrée


root {                    root {
                              surprise  1:1:3
    mine       1:1:1          mine      1:1:1
    foo                       foo
                              yawn
    yours      1:1:2
}                         }
foo {                     foo {
    fumble     1:2:1
                              mumble    1:2:3
    stumble    1:2:2          stumble   1:2:2
}                         }
                          yawn {
                              sleepy    1:3:1
                          }

Produit le PMNS résultant dans out.


root {
    mine      1:1:1
    foo
    yours     1:1:2
    surprise  1:1:3
    yawn
}
foo {
    fumble    1:2:1
    stumble   1:2:2
    mumble    1:2:3
}
yawn {
    sleepy    1:3:1
}

Pour éviter l'écrasement accidentel des fichiers PMNS, outfile est censé ne pas exister lorsque pmnsmerge démarre. L'option -f permet de supprimer (si possible) et de tronquer un outfile existant avant que l'écriture ne commence.

Normalement, les noms dupliqués pour le même identifiant de métrique de performance (PMID) dans un PMNS sont autorisés. L'option -d est l'option par défaut et est incluse pour des raisons de compatibilité ascendante. L'option -x inverse le comportement par défaut et pmnsmerge signalera une erreur et se terminera avec un statut non nul si un nom dupliqué est trouvé pour un PMID dans l'un des fichiers PMNS d'entrée ou dans le PMNS de sortie fusionné.

L'option -v produit une ligne de sortie diagnostique à chaque traitement d'un infile.

Une fois que toutes les fusions ont été effectuées, pmnsmerge tentera de charger l'espace de noms résultant à l'aide de pmLoadASCIINameSpace(3) - si cela échoue pour une raison quelconque, outfile sera toujours créé, mais pmnsmerge signalera le problème et se terminera avec un statut non nul.

Utiliser pmnsmerge avec un seul argument d'entrée permet de vérifier ce fichier PMNS. En plus de la vérification syntaxique, spécifier -x activera également une vérification des noms dupliqués pour tous les PMID.

OPTIONS

Les options de ligne de commande disponibles sont :

-a
Traiter les fichiers dans l'ordre de la ligne de commande.
-d, --dupok
Autoriser les noms de métriques dupliqués par PMID. C'est le comportement par défaut.
-f, --force
Écraser le fichier de sortie s'il existe déjà.
-v, --verbose
Traitement d'entrée détaillé.
-x, --nodups
Ne pas autoriser les noms de métriques dupliqués par PMID.
-?, --help
Afficher le message d'utilisation et quitter.

CAVEATS

Une fois que l'écriture du nouveau fichier outfile a commencé, les signaux SIGINT, SIGHUP et SIGTERM seront ignorés pour protéger l'intégrité du nouveau fichier.

ENVIRONNEMENT PCP

Les variables d'environnement commençant par le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉPANNAGE

L'option -D ou --debug active l'affichage de diagnostics supplémentaires sur stderr pour aider à résoudre les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparée par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

VOIR AUSSI

pmnsadd(1), pmnsdel(1), pmLoadASCIINameSpace(3), pcp.conf(5), pcp.env(5) et PMNS(5).
