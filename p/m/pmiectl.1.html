PMIECTL(1) Manuel des commandes générales PMIECTL(1)

NOM

pmiectl - gérer et contrôler les moteurs d'inférence Performance Co-Pilot

SYNTAXE

pmiectl [-afmNV?] [-C args_verification] [-c classe] [-i identifiant] [-p politique] commande [hôte ...]

DESCRIPTION

pmiectl peut être utilisé pour gérer les instances non primaires du moteur d'inférence Performance Co-Pilot (PCP) pmie(1). Ceci serait le plus pertinent dans une « ferme » de moteurs d'inférence PCP où de nombreuses instances de pmie(1) évalueraient des règles par rapport aux données de performance collectées depuis pmcd(1) sur de nombreux hôtes distants.

L'instance primaire de pmie(1) est étroitement liée au processus pmcd(1) local et, par conséquent, partage la même infrastructure de contrôle, à savoir systemd(1) ou les « scripts rc » de init(1) de PCP. C'est pourquoi l'instance primaire de pmie(1) ne peut pas être gérée avec pmiectl.

Par souci de brièveté dans la description ci-dessous, le terme « instance » désigne une instance de pmie(1).

Toutes les instances gérées par pmiectl, pmie_check(1) et pmie_daily(1) respectent les règles suivantes :

1.
Chaque instance récupère des données de performance à partir d'un seul pmcd(1) (c'est-à-dire un hôte), mais chaque pmcd(1) peut fournir des données de performance à zéro, une ou plusieurs instances de pmie(1) s'exécutant sur un ou plusieurs hôtes.
2.
Sur l'hôte local, chaque instance de pmie(1) doit être spécifiée une fois dans un fichier de contrôle pmie_check(1) et pmie(1) crée un fichier journal unique, nommé dans le 4ème paramètre de l'entrée associée du fichier de contrôle (voir la section CONFIGURATION de pmie_check(1)).
3.
Chaque instance appartient à exactement une classe, nommée facultativement à l'aide d'une affectation $class=... dans le fichier de contrôle associé. La classe spéciale default est réservée à toutes les instances qui n'ont pas d'affectation $class=... associée. À des fins de rapport (voir la commande summary ci-dessous), l'instance primaire de pmie(1) est automatiquement affectée à la classe spéciale primary.

Chaque exécution de pmiectl gère une ou plusieurs instances en mettant à jour les fichiers de contrôle associés, puis en exécutant pmie_check(1) pour effectuer le changement souhaité.

Les arguments hôte sont généralement des noms d'hôtes valides. Pour toutes les commandes sauf create et cond-create (décrites ci-dessous), les arguments hôte peuvent également être des expressions régulières egrep(1) qui correspondent à la totalité d'un nom d'hôte valide, donc le modèle utilisé est en fait ^hôte$. Par exemple foo.* (correspond à tous les noms d'hôtes commençant par « foo ») ou .*foo (correspond à tous les noms d'hôtes se terminant par « foo ») ou .*[fF][oO][oO].* (correspond à tous les noms d'hôtes contenant « foo » en majuscules, minuscules ou mixte).

La combinaison d'une classe de l'option facultative -c (ou default) et des arguments hôte de chaque commande identifie un ensemble cible d'instances auquel l'opération commande doit être appliquée.

L'option -i peut être utilisée avec les commandes create ou cond-create pour remplacer l'identité de l'instance spécifiée dans la section identifiant du fichier de politique de classe (voir la section FICHIER DE POLITIQUE DE CLASSE ci-dessous). Étant donné que l'identifiant doit être unique pour toutes les instances et toutes les classes, cette option n'a de sens que lorsqu'il y a un seul argument hôte.

Compte tenu des tâches qu'entreprend pmiectl, il doit généralement être exécuté en tant que « root », les exceptions étant la commande status ou lorsque l'option -N est spécifiée.

COMMANDES

commande est l'une des commandes suivantes :

check
Vérifie l'état de toutes les instances pmie actuellement configurées et redémarre celles qui ont échoué. Si le drapeau -m est donné sur les plateformes systemd(1), migre également les processus correspondants (et nouveaux) vers le service pmie_farm.
create
Crée de nouvelles instances dans la classe nom_classe (default par défaut) pour les hôtes hôte. Le nom de la classe est utilisé pour identifier un fichier de politique de classe (voir la section FICHIER DE POLITIQUE DE CLASSE ci-dessous) qui fournit un modèle pour chaque nouveau fichier de contrôle avec %h remplacé par hôte et %i remplacé par l'identifiant (unique) de l'instance de la section identifiant du fichier de politique de classe ou identifiant de l'option -i.

L'option -p peut être utilisée pour identifier un fichier de politique de classe autre que celui trouvé à l'emplacement standard, c'est-à-dire $PCP_SYSCONF_DIR/pmie/class.d/nom_classe.

Au moins un hôte doit être spécifié pour la commande create.

cond-create
Similaire à create, mais l'instance ne sera créée que si l'une des conditions dans la section create des fichiers de politique de classe associés est évaluée comme vraie.

Si une option -c est spécifiée, alors seule la classe nom_classe sera considérée, sinon toutes les classes seront considérées. Dans ce dernier cas, si aucune des conditions dans l'une des classes n'est évaluée comme vraie, la classe spéciale pmfind est utilisée (c'est la classe « par défaut » pour la commande cond-create quand tout le reste échoue).

Si plus d'une classe est évaluée comme vraie, un fichier de configuration pmie(1) composite est créé et l'instance est également affectée à la classe spéciale pmfind. Le fichier de configuration composite peut contenir un mélange de clauses de configuration explicites et de clauses de configuration plus générales conditionnelles telles qu'interprétées par l'outil pmieconf(1).

start
Démarre l'ensemble cible d'instances.

Si l'ensemble cible contient intentionnellement plus d'une instance, l'option -a doit être utilisée (conçue pour réduire le risque de démarrer accidentellement un nombre potentiellement important de processus pmie(1)).

Si une instance de l'ensemble cible est déjà démarrée, aucun changement n'est effectué (voir la commande restart pour forcer le lancement de nouvelles instances).

stop
Arrête l'ensemble cible d'instances.

Si l'ensemble cible contient intentionnellement plus d'une instance, l'option -a doit être utilisée (conçue pour réduire le risque d'arrêter accidentellement un nombre potentiellement important de processus pmie(1)).

Si une instance de l'ensemble cible est déjà arrêtée, aucun changement n'est effectué mais un avertissement est émis.

restart
Arrête puis démarre l'ensemble cible d'instances.

Si l'ensemble cible contient intentionnellement plus d'une instance, l'option -a doit être utilisée (conçue pour réduire le risque d'arrêter et de démarrer accidentellement un nombre potentiellement important de processus pmie(1)).

Si une instance de l'ensemble cible est déjà arrêtée, un avertissement est émis avant que l'instance ne soit démarrée.

status
Rapporte l'état de l'ensemble cible d'instances. S'il n'y a pas d'option -c spécifiée et aucun argument hôte, c'est-à-dire si l'ensemble cible est vide, alors toutes les instances seront rapportées.
destroy
Détruit l'ensemble cible d'instances. À la fin de cette opération, les processus pmie(1) associés seront terminés

et leurs fichiers de configuration respectifs seront supprimés.

summary
Produit un résumé de toutes les instances pmie gérées, y compris l'instance primaire. L'option -c peut être utilisée pour limiter le résumé à une classe particulière.

OPTIONS

-a
Utilisée avec les commandes start, stop et restart pour indiquer que l'ensemble cible peut contenir plus d'une instance. Ceci est une mesure de sécurité pour éviter de manipuler accidentellement un grand nombre d'instances.
-f
Forcer l'opération. Par exemple, si destroy est utilisé avec l'option -f, alors les instances qui ne sont pas en cours d'exécution seront également supprimées.
-m
Utilisé avec la commande check pour migrer les instances pmie vers le service pmie_farm (si elles sont en cours d'exécution et correspondent à la sélection).
-N
Ne pas exécuter. L'opération est simulée, c'est-à-dire que toutes les actions qui seraient normalement effectuées sont affichées à la place.
-V
Afficher la version et quitter.
-c classe
Spécifie la classe d'instances à cibler. La valeur par défaut est l'ensemble de toutes les classes. Voir aussi la section DESCRIPTION.
-C args_verification
Les arguments de vérification passés à pmie_check(1). Ceci est utile pour le débogage.
-i identifiant
Identifiant de l'instance pour les commandes create et cond-create. Ceci remplace l'identifiant trouvé dans le fichier de politique de classe.
-p politique
Chemin d'accès au fichier de politique de classe pour les commandes create et cond-create.
-?
Afficher un message d'aide et quitter.

FICHIER DE POLITIQUE DE CLASSE

Les fichiers de politique de classe sont stockés dans le répertoire $PCP_SYSCONF_DIR/pmie/class.d/. Chaque fichier est nommé d'après la classe qu'il définit. Par exemple, le fichier pour la classe « def perf » serait nommé def.perf.

Les fichiers de politique de classe sont des fichiers de configuration qui définissent comment une instance de pmie doit être configurée. Ils contiennent généralement les sections suivantes :

ident
Définit l'identité de l'instance, généralement sous la forme d'une chaîne contenant des espaces réservés tels que %h (pour l'hôte) et %i (pour un identifiant unique).
create
Contient une ou plusieurs conditions qui doivent être vraies pour que l'instance soit créée. Utilisé par la commande cond-create.
rules
Spécifie les règles que l'instance pmie doit exécuter. Ces règles sont généralement formatées pour être utilisées par pmie.
fetch
Spécifie les métriques que l'instance pmie doit récupérer du pmcd.
interval
Définit l'intervalle de temps entre les récupérations de métriques.
logfile
Spécifie le chemin d'accès au fichier journal pour les messages de l'instance pmie.

Les fichiers de politique de classe peuvent également inclure des affectations de variables et des directives d'inclusion pour importer des configurations à partir d'autres fichiers.

EXEMPLES

Pour vérifier l'état de toutes les instances pmie sur tous les hôtes :

pmiectl check

Pour créer une nouvelle instance pmie sur l'hôte « server1 » dans la classe « webserver », en utilisant le fichier de politique par défaut :

pmiectl -c webserver create server1

Pour démarrer toutes les instances pmie sur les hôtes dont le nom commence par « app » :

pmiectl -a start app.*

Pour détruire toutes les instances pmie dans la classe « database » sur l'hôte « dbhost1 » :

pmiectl -c database destroy dbhost1

Pour afficher le statut de toutes les instances pmie sur l'hôte « monitor » :

pmiectl status monitor

FICHIER DE POLITIQUE DE CLASSE

Un fichier de politique de classe contient un certain nombre de sections, chaque section commence par une ligne qui commence simplement par le nom de la section entouré de ``['' et ``]''.

Les lignes commençant par un dièse (#) sont traitées comme des commentaires et ignorées. Les lignes blanches ou vides sont également ignorées.

L'emplacement typique du fichier de politique pour la classe foo est $PCP_SYSCONF_DIR/pmie/class.d/foo.

[class]
La section facultative du nom de classe nomme la classe. Si elle est absente, le nom du fichier de politique (sans le préfixe de répertoire) est utilisé comme nom de la classe.
[ident]
La section ident spécifie le modèle à utiliser pour l'identifiant de l'instance qui sera donné à chaque membre de la classe. Cet identifiant doit être unique pour toutes les instances et toutes les classes, et il doit être un nom de fichier valide dans le système de fichiers local, il conviendra donc normalement du nom de la classe et de la macro %h, par exemple foo-%h. La macro est remplacée par l'hôte lors de la création de chaque instance.
[control]
La section control se compose d'une ou plusieurs lignes de texte modèle qui seront utilisées pour créer le fichier de contrôle de chaque instance. Cela doit au moins inclure la ligne de contrôle pmie_check(1) pour spécifier comment démarrer le processus pmie(1) associé ; cette ligne contient des champs séparés par des espaces blancs comme suit :
1.
le nom d'hôte, généralement la macro %h
2.
n pour indiquer qu'il s'agit d'une instance non primaire
3.
l'indicateur ``socks'', typiquement n
4.
le chemin d'accès utilisé par pmie(1) pour le fichier journal ; celui-ci doit être unique et est généralement spécifié en utilisant la macro pmie_check(1) PCP_LOG_DIR comme début du chemin, suivi de pmie, puis du répertoire unique de l'instance %i, par exemple PCP_LOG_DIR/pmie/%i/pmie.log
5.
des paramètres supplémentaires pour pmie(1) qui incluent probablement au moins une option -c pour fournir un fichier de configuration décrivant quelles règles doivent être évaluées pour les instances de cette classe, ce qui peut être identique pour toutes les instances de cette classe, ou cela peut inclure la macro %i pour utiliser un fichier de configuration différent pour chaque instance. Notez que si ce fichier de configuration n'existe pas, il sera créé en utilisant pmieconf(1) la première fois que pmie_check(1) est exécuté.

Avant la ligne de contrôle, il devrait y avoir une ligne qui définit la version de la ligne de contrôle qui suit, c'est-à-dire
$version=1.1
Si cela est manquant, pmiectl supposera que la version est 1.1 et insérera la ligne lors de la création de l'instance.

pmiectl ajoutera également le nom de la classe lors de la création. Par exemple
$class=foo

Dans un modèle de ligne de contrôle, une forme simple de substitution paramétrique est prise en charge. La macro ENV(spec) est remplacée par du texte utilisant des variables d'environnement comme suit :

  • Si spec est de la forme var, alors la valeur de $var de l'environnement est utilisée. Si $var n'est pas défini ou a la valeur d'une chaîne vide, c'est une erreur.
  • Si spec est de la forme var:default, alors si $var de l'environnement est défini et n'est pas une chaîne vide, la valeur de $var est utilisée, sinon la valeur default est utilisée. La substitution est simple, donc tout espace blanc entre le : et le ) est inclus dans default, et default ne peut pas contenir de ).

À titre d'exemple
# unset PMPROXY_PORT; PMPROXY_HOST=foobar.com pmiectl create ...
avec une ligne de modèle de contrôle de classe de politique qui inclut http://ENV(PMPROXY_HOST):ENV(PMPROXY_PORT:44322)
générera une ligne de contrôle qui inclut
http://foobar.com:44322

[create]
La section create définit les conditions qui doivent être remplies avant qu'une instance ne soit créée avec la commande cond-create. L'intention est de permettre des décisions différentes lorsqu'un nouvel hôte exécutant pmcd(1) est découvert, par exemple par pmfind(1).

Chaque ligne non vide dans la section create est une condition de la forme function(arg), où function est l'une des suivantes :

exists
arg est le nom d'une métrique de performance et exits est évalué à vrai si cette métrique existe dans l'Espace Nom de Métriques de Performance (PMNS) sur l'hôte distant
values
arg est le nom d'une métrique de performance dans le PMNS distant et values est évalué à vrai si une instance de cette métrique a une valeur sur l'hôte distant
condition
arg est une expression de métrique dérivée au format supporté par pmRegisterDerived(3), et condition est évalué à vrai si la valeur de cette expression sur l'hôte distant est supérieure à zéro
hostname
arg est une expression régulière dans le style de egrep(1) et hostname est évalué à vrai si le nom de l'hôte distant correspond à arg
[destroy]
La section destroy définit la politique à appliquer lorsqu'une instance est détruite.

L'intention est de permettre des décisions différentes lorsque le service de découverte, par exemple pmfind(1), remarque qu'un hôte associé à une instance n'est plus présent. Mais dans la version actuelle, ce n'est pas implémenté et la syntaxe et la sémantique de la section destroy ne sont pas encore définies.

Un exemple de fichier de politique de classe est le suivant :

# fichier de politique pour la classe foo
[class]
foo
[ident]
foo-%h
[control]
$version=1.1
%h n n PCP_LOG_DIR/pmie/%i/pmie.log -c foo-metrics.config
[create]
# correspond à tous les hôtes
hostname(.*)
[destroy]
# à définir

OPTIONS

Les options de ligne de commande disponibles sont :

-a, --all
Appliquer l'action à toutes les instances correspondantes. Par défaut, seule une définition d'instance est attendue et traitée.
-c class, --class=class
Définir le nom de la classe à laquelle appartiennent les instances de pmie(1) comme class.
-C check_args, --checkargs=check_args
check_args sont des arguments de ligne de commande supplémentaires pour pmie_check(1) lorsqu'il est appelé. C'est très utile pour des options comme -V. Plusieurs options -C peuvent être utilisées et les différents arguments check_args seront accumulés et tous passés à pmie_check(1).
-f, --force
Forcer l'action si possible.
-i ident, --ident=ident
Substituer l'identifiant d'instance par ident. Cette option s'applique uniquement aux commandes create et cond-create.
-N, --showme
Exécute pmiectl en mode ``montre-moi'' ou ``simulation'' où l'intention de la commande est affichée, mais aucune modification n'est apportée.
-m, --migrate
Lorsqu'il est utilisé avec les commandes create ou check sur les plateformes systemd(1), migrer également les processus pmie nouveaux ou existants non primaires vers le service pmie_farm. Ceci est normalement fait automatiquement par le service pmie_farm_check, qui est piloté par une minuterie (donc il peut y avoir un délai de quelques minutes avant que la migration automatique ne soit initiée).
-p policy, --policy=policy
Utiliser policy comme fichier de politique de classe. Par défaut $PCP_SYSCONF_DIR/pmie/class.d/<class>.
-V, --verbose
Activer le mode verbeux. L'utilisation de cette option deux fois augmente la verbosité. La sortie verbeuse est écrite dans stderr.
-?, --help
Afficher le message d'utilisation et quitter.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).
