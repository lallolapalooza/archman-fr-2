PMATOMSTR(3) Manuel des fonctions de bibliothèque PMATOMSTR(3)

NOM

pmAtomStr, pmAtomStr_r - convertir une valeur de métrique de performance en chaîne de caractères

SYNTAXE C

#include <pcp/pmapi.h>

const char *pmAtomStr(const pmAtomValue *avp, int type);
char *pmAtomStr_r(const pmAtomValue *avp,
int type, char *buf, int buflen);

cc ... -lpcp

DESCRIPTION

Toutes les valeurs de métriques de performance peuvent être encodées dans une union pmAtomValue, définie comme suit ;

typedef union {
    __int32_t    l;     /* 32 bits signé */
    __uint32_t   ul;    /* 32 bits non signé */
    __int64_t    ll;    /* 64 bits signé */
    __uint64_t   ull;   /* 64 bits non signé */
    float        f;     /* Virgule flottante 32 bits */
    double       d;     /* Virgule flottante 64 bits */
    char         *cp;   /* Pointeur char */
    pmValueBlock *vbp;  /* Pointeur pmValueBlock */
} pmAtomValue;

Étant donné la valeur de métrique de performance pointée par avp, et un type de métrique de performance défini par type, pmAtomStr générera la valeur de métrique correspondante sous forme de chaîne de caractères, adaptée pour un diagnostic ou une sortie de rapport. La fonction pmAtomStr_r fait de même, mais stocke le résultat dans un tampon fourni par l'utilisateur buf d'une longueur buflen, qui devrait avoir une capacité d'au moins 80 octets.

La valeur pour type est généralement extraite d'une structure pmDesc, suite à un appel à pmLookupDesc(3) pour une métrique de performance particulière.

Si le type est PM_TYPE_STRING, les valeurs plus longues que 38 caractères seront tronquées après 34 caractères, et la troncature sera indiquée par des points de suspension « ... » à la fin de la valeur.

Si le type est PM_TYPE_AGGREGATE, les trois premiers mots de 32 bits sont affichés sous forme de valeurs hexadécimales.

Si le type est PM_TYPE_EVENT, un résumé du nombre d'enregistrements d'événements trouvés dans la valeur est généré.

La valeur de retour de pmAtomStr est conservée dans un unique tampon statique, ainsi la valeur retournée n'est valide que jusqu'au prochain appel à pmAtomStr.

NOTES

pmAtomStr retourne un pointeur vers un tampon statique et n'est donc pas thread-safe. Les applications multithread devraient utiliser pmAtomStr_r à la place.

VOIR AUSSI

PMAPI(3), pmConvScale(3), pmExtractValue(3), pmLookupDesc(3), pmPrintValue(3), pmTypeStr(3) et pmUnitsStr(3).
