PMGETOPT(1) Manuel des commandes générales PMGETOPT(1)

NOM

pmgetopt - Analyseur d'options pour scripts shell Performance Co-Pilot

SYNTAXE

$PCP_BINADM_DIR/pmgetopt [-u?] [-c fichier] [-D debug] [-p nom] [--] [paramètres]

DESCRIPTION

pmgetopt est utilisé pour analyser les options de ligne de commande des scripts shell utilisés dans la boîte à outils Performance Co-Pilot (PCP). Il est également utilisé pour générer les messages d'utilisation pour ces scripts.

Les paramètres donnés à pmgetopt prennent deux formes : initialement, les options spécifiques à pmgetopt lui-même sont passées, et terminées en utilisant le mécanisme --. Par la suite, tous les paramètres passés au script shell doivent être passés (généralement, il s'agit simplement de la variable "$@").

OPTIONS

Les options de ligne de commande disponibles sont :

-c=fichier, --config=fichier
Un fichier de configuration fichier dans le format décrit ci-dessous est passé à pmconfig en utilisant cette option. Si cette option est omise, pmconfig lira sa configuration depuis le flux d'entrée standard.
-p=nom, --progname=nom
Lors de l'analyse des paramètres du script shell appelant, les messages d'erreur et d'utilisation contiendront le nom de programme donné plutôt que de faire référence à pmgetopt lui-même comme source de l'erreur.
-u, --usage
Un message d'utilisation approprié pour que le script shell appelant puisse se présenter peut être généré en utilisant cette option.
-?, --help
Affiche le message d'utilisation pour pmgetopt lui-même et quitte.

pmgetopt analyse les paramètres donnés et produit une sortie dans un format adapté pour être sourcé dans le script shell appelant. Lorsque des formes courtes et longues d'un argument sont autorisées par la spécification, pmgetopt indiquera toujours la forme courte pour un traitement shell plus simple. Si des arguments sont présentés qui ne correspondent pas à la configuration, une demande de message d'utilisation (-?) sera générée pour que le script appelant y réponde. Tous les paramètres non-options seront renvoyés au script appelant, précédés du délimiteur double-tirets. Ainsi, un script doit arrêter de gérer les options lorsque ce délimiteur est détecté, et commencer la gestion des arguments non-options.

Contrairement à la commande intégrée getopt du shell, des variables comme $OPTARG ne sont pas définies et le script appelant utilisera typiquement la commande intégrée eval, set et les commandes positionnelles shift pour garantir que le traitement des options se déroule correctement.

CONFIGURATION

Le format de configuration utilisé par pmgetopt est destiné à refléter fidèlement le message d'utilisation qui serait généré en présence d'arguments invalides (ou de l'option -?, --help).

Il existe principalement deux types de lignes de configuration : les commandes et les options. Les commandes permettent de passer des métadonnées au processus de traitement des options, et les options sont les options de ligne de commande autorisées que le script shell acceptera. Les lignes de commande sont précédées du caractère dièse (#), tandis que les lignes d'options commenceront toujours par un trait d'union (simple ou double). Toute autre ligne dans la configuration, qui peut inclure des en-têtes d'utilisation ou du texte descriptif, n'a aucun impact sur l'analyse des options et sera copiée telle quelle dans le message d'utilisation.

L'ensemble des commandes est : getopt (fournit la spécification manuelle de l'option d'argument court, si elle n'est pas présente, elle sera générée à partir des options présentées), usage (fournit un résumé d'une ligne utilisé en tête du message d'utilisation, qui sera préfixé par le progname avant d'être rapporté), et end qui indique à pmgetopt d'arrêter de traiter les commandes et options supplémentaires - tout texte rencontré par la suite sera simplement ajouté au message d'utilisation.

Une notation abrégée existe pour chacune des options PCP standard, telle que décrite dans PCPIntro(1). Si l'une de ces options (par ex. --host) apparaît comme un seul mot sur une ligne, elle sera transformée en l'option appropriée pour le script shell, y compris toutes les métadonnées de cette option (si elle accepte un argument, les formes d'options courtes et longues, etc.).

L'utilisation du symbole égal ("=") indique la présence d'un argument requis pour toute option, tant pour les formes courtes que longues. Toute option non standard doit être accompagnée d'une description non vide de cet argument.

EXEMPLES

À titre d'exemple, la configuration suivante est valide : 

# Usage: [options] noeud...
Options:
    --archive
    -d, --delay            pause entre les mises à jour pour la relecture d'archive
    --host
    --interval
    -i=INST, --insts=INST  liste des instances de métriques séparées par des virgules
    -r                     compteurs bruts en sortie (pas de conversion de taux)
    --width=N              définit la largeur de chaque colonne de sortie
    --timezone


Cette configuration produira le message d'utilisation suivant, lorsqu'elle est exécutée comme indiqué. 

$ pmgetopt --usage --progname=clusterstat -- "$@"
Usage: clusterstat [options] noeud...
Options:
  -a FICHIER, --archive=FICHIER
                        source des métriques est une archive PCP
  -d, --delay           pause entre les mises à jour pour la relecture d'archive
  -h HOTE, --host=HOTE  source des métriques est PMCD sur l'hôte
  -t DELTA, --interval=DELTA
                        intervalle d'échantillonnage
  -i INST, --insts=INST liste des instances de métriques séparées par des virgules
  -r                    compteurs bruts en sortie (pas de conversion de taux)
  --width=N             définit la largeur de chaque colonne de sortie
  -Z TZ, --timezone=TZ  définit le fuseau horaire de rapport
  -?, --help            affiche ce message d'utilisation et quitte


Plusieurs exemples d'utilisation de pmgetopt font partie de la boîte à outils PCP, en particulier les scripts pcp(1) et pmlogmv(1) fournissent de bons exemples de référence.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, tel que décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

VOIR AUSSI

pcp(1), pmlogmv(1), pmgetopt_r(3), pcp.conf(5) et pcp.env(5).
