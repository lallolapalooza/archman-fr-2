PMPROXY(1) Manuel des commandes générales PMPROXY(1)

NOM

pmproxy - proxy pour le collecteur et la requête de métriques de performance

SYNTAXE

pmproxy [-AdfFt?] [-c fichier_config] [-D debug] [-h hote[,hote ...] [-i adresse_ip] [-l fichier_log] [-L octets] [-p port[,port ...] [-r port[,port ...] [-s nom_sock] [-U nom_utilisateur] [-x fichier_sortie]

DESCRIPTION

pmproxy agit comme un proxy de protocole, permettant aux clients de surveillance Performance Co-Pilot (PCP) de se connecter indirectement à un ou plusieurs serveurs pmcd(1) et/ou serveurs clé-valeur (tels que https://valkey.io/).

Dans son mode de fonctionnement par défaut, pmproxy fournit l'API REST pour les services PCP (voir PMWEBAPI(3) pour les détails). Cela inclut la fourniture d'une interface texte Open Metrics - https://openmetrics.io - pour les métriques PCP sur /metrics, un accès en temps réel aux métriques PCP via les interfaces /pmapi, et un accès aux capacités rapides et évolutives de requête de séries temporelles PCP offertes en conjonction avec un serveur clé-valeur (voir pmseries(1) pour les détails) via les interfaces REST /query.

pmproxy peut être déployé dans un domaine de pare-feu, ou sur un nœud "head" de cluster où l'adresse IP (Protocole Internet) des hôtes sur lesquels pmcd et/ou un serveur clé-valeur (tel que https://valkey.io/) sont en cours d'exécution peut être inconnue des clients de surveillance PCP, mais où l'adresse IP de l'hôte exécutant pmproxy est connue de ces clients. De même, les clients peuvent n'avoir une connectivité réseau qu'à l'hôte sur lequel pmproxy s'exécute, tandis qu'il existe une connectivité réseau depuis cet hôte vers les hôtes d'intérêt sur lesquels pmcd et/ou un serveur clé-valeur s'exécutent.

Le comportement des clients de surveillance PCP est contrôlé soit par la variable d'environnement PMPROXY_HOST, soit par la spécification étendue du nom d'hôte (voir PCPIntro(1) pour les détails). Si aucun de ces mécanismes n'est utilisé, les clients établissent leurs connexions PMAPI(3) directement à pmcd. Si la syntaxe du nom d'hôte proxy est utilisée ou si PMPROXY_HOST est défini, alors il doit s'agir du nom d'hôte ou de l'adresse IP du système où pmproxy s'exécute, et les clients se connecteront à pmcd ou à un serveur clé-valeur indirectement via les services de proxy de protocole de pmproxy.

OPTIONS

Les options de ligne de commande disponibles sont :

-A
Désactive la publicité de service. Par défaut, pmproxy annonce sa présence sur le réseau en utilisant tous les mécanismes disponibles (tels que Avahi/DNS-SD), aidant les outils de surveillance à distance à le trouver. Ces mécanismes sont désactivés avec cette option.
-c fichier_config, --config=fichier_config
Spécifie le chemin vers un fichier de configuration optionnel fichier_config, dont le format est décrit dans la section ``CONFIGURATION''. Cette option implique que pmproxy s'exécute en mode timeseries.
-d, --deprecated
Par défaut, pmproxy préfère s'exécuter dans le nouveau mode timeseries, fournissant des API REST, une I/O réseau asynchrone, des séries temporelles évolutives et des connexions sécurisées utilisant OpenSSL. Cependant, les déploiements hérités peuvent souhaiter utiliser l'implémentation synchrone originale de pmproxy utilisant le réseau libpcp ; cela peut être réalisé en utilisant cette option. Notez que les options -d et -t sont mutuellement exclusives.
-f, --foreground
Par défaut, pmproxy est démarré comme un daemon. L'option -f indique qu'il doit s'exécuter au premier plan. Ceci est surtout utile lors de la tentative de diagnostic des problèmes de connexion.
-F, --systemd
Comme -f, l'option -F exécute pmproxy au premier plan, mais effectue également un certain entretien (comme créer un fichier "pid" et changer l'ID utilisateur). Ceci est destiné à être utilisé lorsque pmproxy est lancé depuis systemd(1) et que la démonsation a déjà été effectuée par systemd(1) et n'a plus besoin d'être effectuée par pmproxy, ce qui est le cas lorsque ni -f ni -F ne sont spécifiés.

Au plus une des options -f et -F peut être spécifiée.

-h hote, --keyhost=hote
Spécifie un hôte de serveur clé-valeur alternatif auquel se connecter pour l'interrogation de séries temporelles, remplaçant tout paramètre du fichier de configuration. Cette option implique que pmproxy s'exécute en mode timeseries.
-i adresse_ip, --interface=adresse_ip
Cette option est généralement utilisée uniquement sur les hôtes ayant plus d'une interface réseau (très courant pour les hôtes de pare-feu et "head" où pmproxy est susceptible d'être déployé pour arbitrer l'accès à un réseau interne). Si aucune option -i n'est spécifiée, pmproxy accepte les connexions client PCP sur n'importe laquelle des adresses IP de son hôte. L'option -i est utilisée pour spécifier explicitement une adresse IP sur laquelle les connexions client PCP doivent être acceptées. adresse_ip doit être sous la forme décimale standard (par exemple, 100.23.45.6). L'option -i peut être utilisée plusieurs fois pour définir une liste d'adresses IP. Lorsque une ou plusieurs options -i sont spécifiées, les tentatives de connexion effectuées sur d'autres adresses IP seront refusées.
-l fichier_log, --log=fichier_log
Par défaut, un fichier journal nommé pmproxy.log est écrit dans le répertoire courant. L'option -l fait écrire le fichier journal dans un fichier_log donné au lieu du fichier par défaut. Si ce fichier_log ne peut pas être créé ou n'est pas accessible en écriture, la sortie est redirigée vers l'erreur standard.
-L octets
Les PDU reçus par pmproxy des clients de surveillance PCP sont limités par défaut à une taille maximale de 65536 octets pour se défendre contre les attaques par déni de service. L'option -L peut être utilisée pour modifier la taille maximale des PDU entrants.
-p port, --port=port
Spécifie un numéro de port alternatif sur lequel écouter les connexions client. La valeur par défaut est 44322.
-r port, --keyport=port
Spécifie un numéro de port de serveur clé-valeur alternatif auquel se connecter pour l'interrogation de séries temporelles, remplaçant tout paramètre du fichier de configuration. Cette option implique que pmproxy s'exécute en mode timeseries.
-s nom_sock, --socket=nom_sock
Spécifie le chemin vers un socket de domaine Unix local (pour les plateformes supportant cette famille de sockets uniquement). La valeur par défaut est $PCP_RUN_DIR/pmproxy.socket. Cette option implique que pmproxy s'exécute en mode timeseries.
-t, --timeseries
Fonctionne en mode de découverte automatique des archives de séries temporelles. Ce mode de fonctionnement activera les API REST PMWEBAPI(3), détectera dynamiquement et automatiquement les archives système actives écrites par pmlogger(1) et les importera dans un serveur clé-valeur (tel que https://valkey.io/), pour une interrogation rapide et évolutive des séries temporelles décrite dans pmseries(1). Notez que dans ce mode de fonctionnement, pmproxy ne fait que "suivre la fin" (log-tails) et ingérer les archives en croissance active, par exemple celles écrites par une ou plusieurs instances de pmlogger(1). Lorsqu'une archive est découverte (généralement mais pas exclusivement au démarrage de pmproxy), toutes les métadonnées sont chargées et envoyées au serveur clé-valeur configuré, cependant notez que seules les **nouvelles** données de valeurs métriques d'archive provenant de la fin de chaque archive sont ingérées. Les archives compressées ne grossissent jamais et sont donc ignorées. Voir l'option --load de pmseries(1) pour un mécanisme supporté pour le chargement manuel de toutes les métriques d'archive.

CONFIGURATION

Le fichier de configuration (spécifié par l'option -c) est un fichier texte qui contient une directive host= par ligne, pour chaque serveur de métriques de performance (pmcd) ou serveur clé-valeur auquel pmproxy doit se connecter. Les directives peuvent également être spécifiées avec un port, par exemple host=serveur.domaine:port.

Toutes les lignes vides ou commençant par un caractère dièse (#) sont ignorées. Le mode timeseries est activé par défaut s'il y a une option -c, -h, ou -r spécifiée.

Par exemple, un fichier de configuration pourrait ressembler à ceci :

host=server1.example.com
host=server2.example.com:12345

Ceci configure pmproxy pour se connecter à server1.example.com sur le port par défaut de 44321 et à server2.example.com sur le port 12345.

Si le mode timeseries est activé (soit par les options de ligne de commande, soit par la présence d'un fichier de configuration), pmproxy s'attend à trouver un serveur clé-valeur, configuré implicitement via l'option -h et/ou -r, ou via le fichier de configuration.

Un fichier de configuration pour le mode timeseries peut également inclure une directive keyhost= et keyport= pour spécifier le serveur clé-valeur.

Par exemple, un fichier de configuration pour le mode timeseries pourrait ressembler à ceci :

host=server1.example.com
keyhost=kvstore.example.com
keyport=6379

Ceci configure pmproxy pour se connecter à server1.example.com pour les métriques PCP et à kvstore.example.com sur le port 6379 pour les requêtes de séries temporelles.

EXEMPLES

Pour démarrer pmproxy en arrière-plan, écoutant sur le port par défaut (44322), et consignant dans pmproxy.log :

$ pmproxy

Pour démarrer pmproxy au premier plan, écoutant sur le port 5000 et consignant sur la sortie d'erreur standard :

$ pmproxy -f -p 5000 -l /dev/stderr

Pour démarrer pmproxy en mode timeseries, en utilisant le fichier de configuration pmproxy.conf, et en écoutant sur l'interface 192.168.1.100 uniquement :

$ pmproxy -c pmproxy.conf -i 192.168.1.100

Pour démarrer pmproxy en mode timeseries, en se connectant à un serveur clé-valeur sur 10.0.0.5:6379, et en servant les métriques PCP de 10.0.0.1:44321 :

$ pmproxy -h 10.0.0.1 -r 44321 -k 10.0.0.5 -K 6379

ENVIRONNEMENT

La variable d'environnement PMPROXY_HOST peut être définie pour spécifier un nom d'hôte proxy par défaut. Les clients PCP qui utilisent cette variable se connecteront à pmproxy au lieu de pmcd directement.

$PCP_LOGDIR/pmproxy.log

CONFIGURATION

Lorsqu'il fonctionne en mode d'opération timeseries, la configuration d'exécution est relativement complexe et généralement gérée via le fichier $PCP_SYSCONF_DIR/pmproxy/pmproxy.conf. Ce fichier est au format courant « ini », avec des en-têtes de section et des variables et valeurs individuelles pour chaque section. Le fichier de configuration installé dans le cadre de PCP documente chaque section et option disponible.

À un niveau élevé, la section [pmproxy] peut être utilisée pour activer ou désactiver explicitement chacun des différents protocoles.

La section [http] permet un réglage fin des paramètres du serveur HTTP utilisés par pmproxy. chunksize définit la taille du tampon d'encodage de transfert par morceaux, et par défaut, la taille de page du système. Les paramètres du protocole HTTP de contrôle d'accès peuvent être ajustés en utilisant les options Access-Control-Allow-Headers et Access-Control-Max-Age. La discussion de ces en-têtes de protocole HTTP dépasse le cadre de ce document, mais des valeurs par défaut appropriées sont décrites dans le fichier de configuration pmproxy.conf.

La section [keys] permet de configurer les informations de connexion pour un ou plusieurs processus serveur clé-valeur en arrière-plan (noms d'hôtes et ports). Notez que pour accéder à plusieurs serveurs clé-valeur (scalables), la variable servers de cette section peut être une liste séparée par des virgules de paires nom d'hôte:port. Alternativement, il peut s'agir d'un seul hôte serveur clé-valeur qui sera interrogé en utilisant la commande "CLUSTER INFO" pour configurer automatiquement plusieurs hôtes en arrière-plan.

Dans les versions antérieures de PCP (avant la version 6), une section de configuration alternative était utilisée à cette fin : les serveurs clé-valeur étaient spécifiés dans la section [pmseries] et ceci est toujours accepté comme solution de repli pour des raisons de compatibilité ascendante.

DEMARRAGE ET ARRET DE PMPROXY

Normalement, pmproxy est démarré automatiquement au démarrage de la machine et arrêté lorsque le système s'arrête. Dans certaines circonstances, il est nécessaire de démarrer ou d'arrêter pmproxy manuellement. Pour ce faire, il faut devenir superutilisateur et taper

# $PCP_RC_DIR/pmproxy start

pour démarrer pmproxy, ou

# $PCP_RC_DIR/pmproxy stop

pour arrêter pmproxy. Démarrer pmproxy alors qu'il est déjà en cours d'exécution équivaut à l'arrêter puis à le redémarrer.

Normalement, pmproxy écoute les connexions des clients PCP sur le port TCP/IP numéro 44322 (ainsi que 44323 avec timeseries activé) enregistré auprès de https://www.iana.org/. La variable d'environnement PMPROXY_PORT ou l'option de ligne de commande -p peuvent être utilisées pour spécifier des numéros de port alternatifs lors du démarrage de pmproxy ; dans chaque cas, la spécification est une liste séparée par des virgules d'un ou plusieurs numéros de port numériques. Si les deux méthodes sont utilisées ou si plusieurs options -p apparaissent sur la ligne de commande, pmproxy écoutera sur l'union de l'ensemble des ports spécifiés via toutes les options -p et la variable d'environnement PMPROXY_PORT. Si des ports non par défaut sont utilisés avec pmproxy, il faut veiller à ce que PMPROXY_PORT soit également défini dans l'environnement de toute application cliente qui se connectera à pmproxy, ou que la syntaxe étendue de spécification d'hôte soit utilisée (voir PCPIntro(1) pour plus de détails).

DIAGNOSTICS

Si pmproxy est déjà en cours d'exécution, le message « Error: OpenRequestSocket bind: Address already in use » apparaîtra. Ce message peut également apparaître si pmproxy a été arrêté avec une requête en attente d'un client. Dans ce cas, un socket de requête a été laissé dans l'état TIME_WAIT et jusqu'à ce que le système le ferme (après une période de délai d'attente), il ne sera pas possible d'exécuter pmproxy.

En plus des options de débogage standard de PCP, voir pmdbg(1), pmproxy prend actuellement en charge l'option de débogage context pour le suivi des connexions et déconnexions des clients.

Variables d'environnement qui seront définies lors de l'exécution de pmproxy. Seuls les paramètres de la forme « PMPROXY_VARIABLE=valeur » seront respectés.
./pmproxy.log

ENVIRONNEMENT

En plus des variables d'environnement PCP décrites dans la section ENVIRONNEMENT PCP ci-dessous, plusieurs variables d'environnement influencent les interactions entre un client de surveillance PCP, pmproxy et pmcd.

PMCD_PORT
Pour le client de surveillance PCP, ceci (ou le numéro de port par défaut) est passé à pmproxy et utilisé pour se connecter à pmcd. Dans l'environnement de pmproxy, PMCD_PORT n'est pas utilisé.
PMPROXY_HOST
Pour le client de surveillance PCP, c'est le nom d'hôte ou l'adresse IP de la machine où pmproxy est en cours d'exécution. Dans les versions récentes de PCP (depuis la version 3), ceci a été remplacé par la syntaxe étendue de nom d'hôte (voir PCPIntro(1) pour plus de détails).
PMPROXY_PORT
Pour le client de surveillance PCP, c'est le port sur lequel pmproxy acceptera les connexions. La valeur par défaut est 44322, ainsi que 44323 avec timeseries activé.
PMCD_CONNECT_TIMEOUT, PMCD_RECONNECT_TIMEOUT et PMCD_REQUEST_TIMEOUT
(voir PCPIntro(1)) Pour le client de surveillance PCP, la définition de ces variables d'environnement modifiera les délais d'attente utilisés pour les interactions entre le client et pmproxy (indépendamment du pmcd utilisé). Pour pmproxy, ces mêmes variables d'environnement contrôlent les délais d'attente entre pmproxy et toutes les instances de pmcd(1) (indépendamment du client de surveillance impliqué).

Si elle est définie sur la valeur 1, la variable d'environnement PMPROXY_LOCAL fera fonctionner pmproxy en mode d'opération localhost uniquement, où il se lie uniquement à l'interface de bouclage.

La variable PMPROXY_MAXPENDING peut être définie pour indiquer la longueur maximale que la file d'attente des connexions client en attente peut atteindre.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

OPTIONS DE DEBOGAGE

L'option -D ou --debug active l'affichage de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmproxy sont les suivantes :

Option Description
appl0 connexions et déconnexions de clients
appl1 mode de journalisation désespéré, où un point suivi du PID de pmproxy est inséré dans le nom de Rlogfile avant le dernier point, ainsi par exemple pmproxy.log devient pmproxy.<pid>.log
appl2 journalise les URL HTTP entrantes (ceci est également activé par l'option de débogage http, mais cette dernière a une portée plus large car elle active le débogage dans les bibliothèques utilisées par pmproxy)
