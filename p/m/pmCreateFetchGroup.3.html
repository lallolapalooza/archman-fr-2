DESCRIPTION

Les fonctions fetchgroup implémentent un mécanisme basé sur l'enregistrement pour récupérer des groupes de métriques de performance, incluant l'automatisation des conversions générales d'unités, de taux et de types, ainsi que des encodages pratiques d'instances et de valeurs. Elles constituent une alternative puissante et compacte à la séquence classique de l'interface de programmation des métriques de performance (PMAPI(3)) composée de fonctions séparées de recherche, de vérification, de récupération, d'itération, d'extraction et de conversion.

L'idée générale consiste en deux étapes. Dans l'étape de configuration, l'application identifie les métriques d'intérêt par leur nom et avec les conversions souhaitées, et enregistre un emplacement unique de sortie pmAtomValue où le système fetchgroup devra déposer ultérieurement le résultat. Il est également possible d'identifier une métrique avec un domaine d'instance, et d'enregistrer un vecteur unique d'objets pmAtomValue pour celles-ci. Dans l'étape d'opération, une simple fonction pmFetchGroup récupère, décode, convertit et stocke toutes les métriques vers leurs destinations, où l'application peut les lire directement. Cette fonction peut être appelée de manière répétée, et à chaque fois de nouvelles valeurs pmAtomValue seront stockées dans les mêmes destinations. Des conversions de taux entre des échantillons consécutifs peuvent être demandées.

Chaque fetchgroup est associé à un contexte PMAPI privé, afin qu'il puisse manipuler les profils d'instances et d'autres états sans perturber d'autres contextes. Le profil d'instance est manipulé pour optimiser la récupération des éléments individuels, même si certains sont des métriques dérivées. Ce contexte PMAPI privé appartient au fetchgroup, est utilisé pour toutes ses opérations internes, et sera détruit.

Plusieurs fetchgroups peuvent être utilisés simultanément, indépendamment. Un type opaque pmFG est utilisé pour identifier un fetchgroup, qui est passé à tous les appels de fonction associés.

Création d'un fetchgroup

int pmCreateFetchGroup(pmFG *ptr,
int type, const char *name);

Cette fonction crée un nouveau fetchgroup, associé à un nouveau contexte PMAPI. Les paramètres type et name sont transmis à pmNewContext(3) pour la création du contexte. L'identifiant du fetchgroup est retourné en cas de succès via le pointeur ptr. Cet objet est ensuite utilisé comme paramètre pour toutes les autres fonctions de fetchgroup. Le contexte PMAPI privé peut être accédé avec pmGetFetchGroupContext, si nécessaire.

Le code de retour normal de la fonction est zéro, et ptr est défini. Cette fonction peut échouer en cas d'erreurs pmNewContext ou d'allocation mémoire. Celles-ci sont indiquées par un code de retour négatif et une valeur ptr effacée.

Obtention du contexte PMAPI privé

int pmGetFetchGroupContext(pmFG pmfg);

Cette fonction retourne le contexte PMAPI privé utilisé par le fetchgroup donné. Il peut être utilisé en toute sécurité pour ajuster certains paramètres de configuration du contexte, tels que via pmSetMode(3), avant que l'extension du fetchgroup et la récupération ne commencent.

Cependant, la mutation de ce contexte par des fonctions PMAPI après cette date peut perturber la fonctionnalité du fetchgroup. Par exemple, un appel pmSetMode pourrait invalider un pas de temps de conversion de taux.

Le code de retour normal de la fonction est le numéro du contexte.

Extension d'un fetchgroup avec une métrique instance d'intérêt

int pmExtendFetchGroup_item(pmFG pmfg,
const char *metric, const char *instance, const char *scale, pmAtomValue *out_value, int out_type, int *out_sts);

Cette fonction enregistre l'intérêt pour une seule métrique et une instance optionnelle. Le nom de la métrique est donné dans le paramètre obligatoire metric, qui est immédiatement vérifié via pmLookupName(3) et d'autres appels. Si et seulement si la métrique a un domaine d'instance, l'instance spécifique d'intérêt peut être nommée par le paramètre instance, qui est immédiatement vérifié via pmNameInDom(3) ; sinon, passez NULL. Si le contexte fetchgroup est un ensemble d'archives, il est possible que la paire métrique / instance ne soit pas encore définie à l'origine temporelle actuelle. Par conséquent, cette fonction peut tenter de se positionner à la fin de l'ensemble actuel d'archives temporairement pour retenter la recherche de la métrique / instance.

Le paramètre optionnel scale spécifie les conversions d'unité/échelle/taux souhaitées pour la valeur de la métrique. Il peut prendre les valeurs suivantes :

NULL
Pas de conversion d'unité/échelle. Si la métrique a des sémantiques PM_SEM_COUNTER, effectuer une conversion de taux.
taux
Effectuer une conversion de taux quelle que soit la sémantique, et aucune conversion d'unité/échelle.
instantané
Ne pas effectuer de conversion de taux quelle que soit la sémantique, et aucune conversion d'unité/échelle.
EXPRESSION
Effectuer une conversion d'unité/échelle/taux comme spécifié par l'EXPRESSION, qui est analysée par pmParseUnitsStr(3). Ceci peut être utile pour affirmer une mise à l'échelle canonique pour la valeur de métrique résultante, indépendamment de la version ou de la configuration de PCP. La dimensionnalité doit correspondre à la métrique, sauf si une conversion de taux est demandée, auquel cas la dimension temporelle doit être une de moins que la dimension temporelle de la métrique. Notez que le type de conversion de taux effectué ici correspond à la fonction rate(x) dans les expressions de métriques dérivées, en ce sens qu'elle est calculée comme la différence naïve entre les valeurs précédentes et actuelles d'une métrique, divisée par le temps écoulé. Par exemple, si un compteur déborde, ou si une valeur non-compteur diminue, un taux de sortie négatif peut être calculé.

Le paramètre optionnel mais habituel out_value spécifie le pmAtomValue où le résultat converti doit être stocké ultérieurement.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Si la valeur est NULL, la récupération et les conversions seront tentées, les erreurs possibles signalées, mais le résultat sera jeté. Le paramètre obligatoire out_type spécifie le PM_TYPE_* demandé pour la valeur de sortie. Il n'est pas nécessaire qu'il corresponde au type natif de la métrique, car la facilité de groupe de récupération est capable de convertir entre tous les types pris en charge (y compris depuis et vers les chaînes de caractères).

Toute erreur rencontrée ultérieurement lors de la récupération, de la conversion d'unité/échelle/taux, ou de la conversion, entraînera l'attribution d'une valeur sentinelle à pmAtomValue de sortie (voir la section « SITUATIONS INHABITUELLES » ci-dessous). De plus, si le paramètre optionnel out_sts est spécifié, un code d'erreur PMAPI approprié y sera stocké.

Pour récapituler, seuls les paramètres pmfg, metric et out_type sont obligatoires. D'autres peuvent être NULL pour indiquer le désintérêt de l'application.

Le code de retour normal de la fonction est zéro. Cette fonction peut échouer en cas d'erreurs diverses de recherche, de type et de conversion. Celles-ci sont indiquées par un code de retour négatif.

Extension d'un groupe de récupération avec un domaine d'instance de métrique d'intérêt

int pmExtendFetchGroup_indom(pmFG pmfg,
const char* metric, const char *scale, int out_inst_codes[], char *out_inst_names[], pmAtomValue out_values[], int out_type, int out_stss[], unsigned int out_maxnum, unsigned int *out_num, int *out_sts);

Cette fonction généralise la fonction pmExtendFetchGroup_item en enregistrant l'intérêt pour un domaine d'instance entier. Par conséquent, la fonction enregistre des vecteurs pré-alloués pour les variables de sortie (au lieu d'un singleton). Les instances seront stockées dans l'ordre trié dans les éléments de ces vecteurs. Les concepts sont par ailleurs identiques.

Le nom de la métrique est spécifié par le paramètre obligatoire metric. Notez qu'il *peut* faire référence à une métrique sans domaine d'instance, auquel cas la seule valeur de sortie apparaîtra comme une instance sans nom.

Le paramètre optionnel scale spécifie les conversions d'unité/échelle/taux souhaitées pour la valeur de la métrique, comme ci-dessus.

Le paramètre optionnel out_inst_codes spécifie un vecteur d'entiers, où le numéro d'instance brut des métriques récupérées doit être stocké ultérieurement.

Le paramètre optionnel out_inst_names spécifie un vecteur de chaînes de caractères, où les noms des instances des métriques récupérées doivent être stockés ultérieurement. Si une instance n'a pas de nom correspondant, un pointeur NULL y est stocké à la place. L'application ne doit pas modifier ni free(3) les chaînes de ce vecteur.

Le paramètre optionnel out_values spécifie un vecteur d'objets pmAtomValue où le résultat converti doit être stocké ultérieurement. Le paramètre obligatoire out_type spécifie le PM_TYPE_* demandé pour toutes les valeurs de sortie, comme ci-dessus.

Le paramètre optionnel out_stss spécifie un vecteur d'entiers où les codes d'erreur par instance doivent être stockés.

Le paramètre obligatoire out_maxnum spécifie le nombre d'éléments des vecteurs ci-dessus. En d'autres termes, il indique au groupe de récupération le nombre maximum d'instances attendues. Le paramètre optionnel out_num spécifie un entier où le nombre réel d'instances doit être stocké ultérieurement. Il variera entre 0 et out_maxnum. Il est initialisé à 0 par cette fonction.

Enfin, le paramètre optionnel out_sts spécifie un emplacement unique où un code d'état entier pour la récupération globale de cette métrique doit être stocké. Normalement, ce sera zéro. Outre une erreur de récupération grave, on peut y trouver un PM_ERR_TOOBIG si le nombre d'instances effectivement rencontrées était supérieur à out_maxnum.

Toute erreur rencontrée ultérieurement lors de la récupération, de la conversion d'unité/échelle/taux, ou de la conversion, entraînera l'attribution d'une valeur sentinelle à pmAtomValue de sortie approprié (voir la section « SITUATIONS INHABITUELLES » ci-dessous). De plus, si le paramètre optionnel out_stss était spécifié, un code d'erreur PMAPI sera stocké à la position appropriée.

Pour récapituler, seuls les paramètres pmfg, metric, out_type et out_maxnum sont obligatoires. D'autres peuvent être NULL pour indiquer le désintérêt de l'application.

Le code de retour normal de la fonction est zéro. Cette fonction peut échouer en cas d'erreurs diverses de recherche, de type et de conversion. Celles-ci sont indiquées par un code de retour négatif.

Extension d'un groupe de récupération avec un champ d'événement

int pmExtendFetchGroup_event(pmFG pmfg,
const char *metric, const char *instance, const char *field, const char *scale, struct timespec out_times[], pmAtomValue out_values[], int out_type, int out_stss[], unsigned int out_maxnum, unsigned int *out_num, int *out_sts);

Cette fonction enregistre l'intérêt pour toutes les instances d'un champ de tous les enregistrements d'une métrique d'événement. Étant donné que les métriques d'événement peuvent retourner plusieurs enregistrements par récupération, et que chaque enregistrement peut avoir plusieurs champs d'un type de métrique de champ donné, cette fonction enregistre des vecteurs pré-alloués pour les variables de sortie, de manière similaire à pmExtendFetchGroup_indom. Ils sont remplis dans l'ordre temporel/séquentiel.

Le nom de la métrique est spécifié par le paramètre obligatoire metric. Il doit être de type PM_TYPE_EVENT. Si la métrique a un domaine d'instance, le paramètre instance est obligatoire pour identifier l'instance d'intérêt.

Le champ à extraire des enregistrements d'événement est spécifié par le paramètre obligatoire field, qui est un nom de métrique de type scalaire normal. Comme c'est typique pour les métriques de champ d'événement, il ne devrait pas avoir de domaine d'instance. Le paramètre optionnel scale spécifie les conversions d'unité/échelle souhaitées sur cette valeur de métrique. Les conversions de taux ne sont **pas disponibles**, en raison de l'ambiguïté quant à la valeur précédente à utiliser pour calculer les taux.

Le paramètre optionnel out_times spécifie un vecteur de structures timespec, qui recevra une copie de l'horodatage de l'enregistrement d'événement où chaque champ particulier a été trouvé.

Le paramètre optionnel out_values spécifie un vecteur d'objets pmAtomValue où le résultat converti doit être stocké ultérieurement. Le paramètre obligatoire out_type spécifie le PM_TYPE_* demandé pour les valeurs de sortie.

Le paramètre optionnel out_stss spécifie un vecteur d'entiers où les codes d'erreur par champ doivent être stockés.

Le paramètre obligatoire out_maxnum spécifie le nombre d'éléments des vecteurs ci-dessus. En d'autres termes, il indique au groupe de récupération le nombre maximum d'instances attendues. Le paramètre optionnel out_num spécifie un entier où le nombre réel d'instances doit être stocké ultérieurement. Il variera entre zéro et out_maxnum. Il est initialisé à zéro par cette fonction.

Enfin, le paramètre optionnel out_sts spécifie un emplacement unique où un code d'état entier pour la récupération globale de cette métrique doit être stocké. Normalement, ce sera zéro, même si aucune valeur de champ d'événement n'a été trouvée (out_num serait alors zéro). Outre une erreur de récupération grave, on peut y trouver un PM_ERR_TOOBIG si le nombre de champs effectivement rencontrés était supérieur à out_maxnum.

Toute erreur rencontrée ultérieurement lors de la récupération, de la conversion d'unité/échelle, ou de la conversion, entraînera l'attribution d'une valeur sentinelle à pmAtomValue de sortie approprié (voir la section « SITUATIONS INHABITUELLES » ci-dessous). De plus, si le paramètre optionnel out_stss était spécifié, un code d'erreur PMAPI sera stocké à la position appropriée.

Pour récapituler, seuls les paramètres pmfg, metric, field, out_type et out_maxnum sont obligatoires. D'autres peuvent être NULL pour indiquer le désintérêt de l'application.

Le code de retour normal de la fonction est zéro. Cette fonction peut échouer en cas d'erreurs diverses de recherche, de type et de conversion. Celles-ci sont indiquées par un code de retour négatif.

Extension d'un groupe de récupération avec l'horodatage de récupération

int pmExtendFetchGroup_timespec(pmFG pmfg,
struct timespec *out_value);

int pmExtendFetchGroup_timeval(pmFG pmfg,
struct timeval *out_value);

Ces fonctions enregistrent l'intérêt pour l'horodatage pmHighResResult. Si le pointeur out_value est non NULL, à chaque appel futur de pmFetchGroup, l'horodatage de résultat correspondant y sera copié.

Récupération de toutes les métriques dans un groupe de récupération

int pmFetchGroup(pmFG pmfg);

Cette fonction effectue une pmFetch sur son contexte PMAPI privé, incluant toutes les métriques qui ont été enregistrées via les appels précédents de pmExtendFetchGroup_*. Elle exécute toutes les opérations d'extraction et de conversion de données nécessaires pour remplir toutes les variables de sortie demandées.

Le code de retour normal de la fonction est zéro ou positif, conformément à la fonction sous-jacente pmFetch. Cette fonction peut échouer en cas d'erreurs de récupération graves, qui sont indiquées par un code de retour négatif.

En cas d'erreurs de disponibilité ou de conversion par métrique, ou d'erreurs de récupération graves, les variables de sortie sont réinitialisées à des valeurs sentinelles et des codes d'erreur individuels sont définis. PM_ERR_AGAIN signale un échec de conversion de taux dû à l'absence d'une valeur précédente.

Cependant, les métriques temporairement absentes avec une sémantique discrète sont exemptées de certains traitements de sentinelle/erreur : si un pmFetchGroup ne parvient pas à collecter un résultat pour une métrique discrète (pmHighResResult pmValueSet.numval==0), alors la dernière valeur valide observée (le cas échéant) est conservée. Ceci est destiné à faciliter le traitement d'ensembles d'archives avec un mélange de métriques échantillonnées une seule fois et répétées. La variable d'environnement PCP_DISCRETE_ONCE peut être définie pour désactiver cette fonctionnalité.

Effacement d'un groupe de récupération

PMAPI(3) — Performance Co-Pilot — Arch Linux

NAME

pmCreateFetchGroup, pmDestroyFetchGroup - créer, étendre et détruire un groupe de récupération

C SYNOPSIS

#include <pcp/pmapi.h>

int pmCreateFetchGroup(pmFG *pmfg_ptr, pmContext pmcid, const char *host);
int pmDestroyFetchGroup(pmFG pmfg);

DESCRIPTION

Un groupe de récupération (fetchgroup) est une collection de métriques, d'instances et de paramètres d'unités, qui sont tous associés à un contexte d'API PM spécifique (par exemple, un contexte d'hôte, d'archive, d'encours, etc.). Les groupes de récupération sont généralement créés pour regrouper plusieurs demandes de métriques en une seule opération de récupération afin d'améliorer l'efficacité. Le groupe de récupération gère les identifiants de métriques, les identifiants d'instances, les unités et le contexte PM sous-jacent. Les métriques sont récupérées et converties dans les types de données spécifiés par le client. L'API du groupe de récupération maintient également un décalage de récupération interne qui avance au fur et à mesure que les données sont récupérées.

Création d'un groupe de récupération

int pmCreateFetchGroup(pmFG *pmfg_ptr, pmContext pmcid, const char *host);

Cette fonction crée un nouveau groupe de récupération et renvoie un handle dans pmfg_ptr. Le paramètre pmcid spécifie le type de contexte PM à utiliser, qui peut être PM_CONTEXT_HOST, PM_CONTEXT_ARCHIVE, PM_CONTEXT_TRACE, PM_CONTEXT_SYSTEM ou PM_CONTEXT_USER. Si le contexte est PM_CONTEXT_HOST, le paramètre host spécifie l'hôte cible (par exemple, "localhost" ou "my.remote.host"). Pour tous les autres types de contextes, le paramètre host doit être NULL.

Nettoyage d'un groupe de récupération

int pmClearFetchGroup(pmFG pmfg);

Lorsque l'état de récupération actuel d'un groupe de récupération n'est plus nécessaire, il peut être explicitement réinitialisé avec cette fonction. Elle libère tout état stocké dynamiquement, mais conserve le contexte PMAPI privé intact pour une utilisation ultérieure (c'est-à-dire qu'aucun changement n'est apporté au contexte et celui-ci reste au décalage de récupération actuel). Elle libère tous les pointeurs tels que les noms d'instance indom ou les chaînes qui ont pu être stockés dans des variables de sortie.

Destruction d'un groupe de récupération

int pmDestroyFetchGroup(pmFG pmfg);

Lorsque le groupe de récupération n'est plus nécessaire, il peut être explicitement libéré avec cette fonction. Elle libère tout état stocké dynamiquement, ainsi que le contexte PMAPI privé. Elle efface et libère tous les pointeurs tels que les noms d'instance indom ou les chaînes qui ont pu être stockés dans des variables de sortie.

EXAMPLE

Le programme suivant démontre l'utilisation de fetchgroup. Exécutez-le avec différentes variables d'environnement $PCP_DISK_UNITS pour voir différentes conversions d'unités/taux en vigueur.

#include <pcp/pmapi.h>
#include <stdio.h>
#define pcpassert(sts) \
    while (sts<0) { fprintf(stderr, "%s\n", pmErrStr(sts)); exit(42); }
int main()
{
    pmFG fg;
    pmAtomValue v, v2;
    enum { v3_maxnum = 100 };
    pmAtomValue v3_values[v3_maxnum];
    char *v3_names[v3_maxnum];
    int v3_stss[v3_maxnum];
    unsigned int v3_num;
    int sts, i;
    char *diskunits = getenv("PCP_DISK_UNITS");
    struct timeval t;
    sts = pmCreateFetchGroup(&fg, PM_CONTEXT_HOST, "local:");
    pcpassert(sts);
    sts = pmExtendFetchGroup_item(fg, "kernel.all.load", "1 minute",
                                  NULL, &v, PM_TYPE_FLOAT, NULL);
    pcpassert(sts);
    sts = pmExtendFetchGroup_item(fg, "kernel.all.idletime", NULL,
                                  "hour", &v2, PM_TYPE_DOUBLE, NULL);
    pcpassert(sts);
    sts = pmExtendFetchGroup_indom(fg, "disk.dev.total", diskunits,
                                   NULL, v3_names,
                                   v3_values, PM_TYPE_STRING,
                                   v3_stss, v3_maxnum, &v3_num, NULL);
    pcpassert(sts);
    sts = pmExtendFetchGroup_timeval(fg, &t);
    pcpassert(sts);
    for (i=0; i < 10; i++) {
        unsigned int j;
        char stamp[28];
        sts = pmFetchGroup(fg);
        pcpassert(sts);
        printf("%s", pmCtime(&t.tv_sec, stamp));
        printf("1-minute load: %f; idletime: %f h\n", v.f, v2.d);
        for (j=0; j < v3_num; j++) {
            if (v3_stss[j] == 0)
                 printf("disk %s i/o operations (%s): %s\n",
                        v3_names[j] ? v3_names[j] : "?",
                        diskunits ? diskunits : "-",
                        v3_values[j].cp);
        }
        sleep(1);
    }
    sts = pmDestroyFetchGroup(fg);
    pcpassert(sts);
    return 0;
}

UNUSUAL SITUATIONS

L'API fetchgroup ne prend en charge que les types de métriques numériques, de chaînes et d'événements. Les agrégats sont rejetés pendant pmExtendFetchGroup_*.

Toutes les chaînes fournies par l'API fetchgroup à l'application sont "possédées" par l'API. L'application doit les considérer comme en lecture seule, elle ne doit donc ni les modifier ni les free.

Les codes d'erreur sont toujours des entiers négatifs, qu'ils soient renvoyés par les fonctions du groupe de récupération en tant que valeur de retour ou stockés dans des variables de type out_sts. Les codes de résultat normaux sont toujours zéro.

En raison des manières uniques dont les données extraites sont partagées entre l'application et un groupe de récupération, les fonctions de cette API ne sont *pas* protégées par les mutex de multi-threading conventionnels dans d'autres parties de PMAPI. Plus précisément, pour un pmFG donné, il n'est *pas* sûr d'appeler simultanément deux fonctions ou plus de l'API du groupe de récupération, ni de parcourir les variables de sortie enregistrées tout en appelant l'une des fonctions. Au lieu de cela, l'application appelante doit s'assurer qu'un seul thread à la fois utilise ces appels *et* les variables de sortie enregistrées. D'autre part, la concurrence entre différentes instances de pmFG n'est pas restreinte, car elles ne partagent aucune donnée globale.

Tous les pointeurs passés à un appel réussi de pmFetchGroupExtent_* doivent rester valides pendant toute la durée de vie du groupe de récupération, car les futurs appels de pmFetchGroup peuvent écrire dedans.

DIAGNOSTICS

L'API fetchgroup offre plusieurs options pour la collecte de diagnostics. Des codes d'erreur entiers négatifs peuvent être renvoyés par chaque fonction pour des conditions graves.

De plus, chaque pmAtomValue de sortie peut avoir une variable entière correspondante, où pmFetchGroup peut stocker des codes d'erreur par métrique et par instance.

En alternative, les conditions d'erreur par métrique et par instance sont également signalées en définissant le pmAtomValue correspondant à une valeur sentinelle. Si une détection d'erreur sans ambiguïté et précise n'est pas requise, cela peut suffire. La valeur sentinelle est moins un pour tous les entiers (y compris les entiers non signés - c'est-à-dire tous les bits sont définis), NaN pour les types à virgule flottante, un pointeur NULL pour les chaînes et 0.0 pour l'horodatage. L'API fetchgroup garantit qu'une fois qu'un pmAtomValue de sortie est enregistré (lors d'un appel réussi à pmExtendFetchGroup_*), il sera effacé à la valeur sentinelle ou à une valeur métrique convertie valide, depuis le moment de l'enregistrement jusqu'à l'appel à pmDestroyFetchGroup.

COMPATIBILITY

Avant PCP 7.0, pmExtendFetchGroup_timestamp était un alias pour pmExtendFetchGroup_timeval. Pour prendre en charge la transition PMAPI, l'ancienne interface et la sémantique peuvent être utilisées si les applications sont recompilées avec -DPMAPI_VERSION=2.

pmExtendFetchGroup_timestamp bien que cela soit maintenant obsolète et que le support au moment de la compilation sera supprimé dans une future version.
