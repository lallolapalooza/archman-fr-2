rpc(3) Manuel des fonctions de bibliothèque rpc(3)

NOM

rpc - routines de bibliothèque pour les appels de procédure distante

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPIS ET DESCRIPTION

Ces routines permettent aux programmes C d'effectuer des appels de procédure sur d'autres machines via le réseau. D'abord, le client appelle une procédure pour envoyer un paquet de données au serveur. À la réception du paquet, le serveur appelle une routine de dispatch pour effectuer le service demandé, puis renvoie une réponse. Enfin, l'appel de procédure retourne au client.

Pour utiliser ces routines, incluez le fichier d'en-tête <rpc/rpc.h>.

Les prototypes ci-dessous utilisent les types suivants :

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Consultez les fichiers d'en-tête pour les déclarations des types AUTH, CLIENT, SVCXPRT et XDR.

void auth_destroy(AUTH *auth);
Une macro qui détruit les informations d'authentification associées à auth. La destruction implique généralement la désallocation des structures de données privées. L'utilisation de auth est indéfinie après avoir appelé auth_destroy().
AUTH *authnone_create(void);
Crée et retourne un handle d'authentification RPC qui transmet des informations d'authentification non utilisables avec chaque appel de procédure distante. C'est l'authentification par défaut utilisée par RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crée et retourne un handle d'authentification RPC contenant des informations d'authentification. Le paramètre host est le nom de la machine où les informations ont été créées ; uid est l'identifiant utilisateur de l'utilisateur ; gid est l'identifiant du groupe actuel de l'utilisateur ; n et aup_gids se réfèrent à un tableau compté des groupes auxquels l'utilisateur appartient. Il est facile d'usurper l'identité d'un utilisateur.
AUTH *authunix_create_default(void);
Appelle authunix_create() avec les paramètres appropriés.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Appelle la procédure distante associée à prognum, versnum et procnum sur la machine host. Le paramètre in est l'adresse de(s) argument(s) de la procédure, et out est l'adresse où placer le(s) résultat(s) ; inproc est utilisé pour encoder les paramètres de la procédure, et outproc est utilisé pour décoder les résultats de la procédure. Cette routine retourne zéro si elle réussit, ou la valeur de enum clnt_stat convertie en entier si elle échoue. La routine clnt_perrno() est utile pour traduire les statuts d'échec en messages.
Avertissement : appeler des procédures distantes avec cette routine utilise UDP/IP comme transport ; voir clntudp_create() pour les restrictions. Vous n'avez pas de contrôle sur les délais d'attente ou l'authentification avec cette routine.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similaire à callrpc(), sauf que le message d'appel est diffusé à tous les réseaux de diffusion locaux connectés. Chaque fois qu'il reçoit une réponse, cette routine appelle eachresult(), dont la forme est :

eachresult(char *out, struct sockaddr_in *addr);

où out est le même que out passé à clnt_broadcast(), sauf que la sortie de la procédure distante y est décodée ; addr pointe vers l'adresse de la machine qui a envoyé les résultats. Si eachresult() retourne zéro, clnt_broadcast() attend d'autres réponses ; sinon, il retourne avec le statut approprié.
Avertissement : les sockets de diffusion sont limités en taille à l'unité de transfert maximale de la liaison de données. Pour Ethernet, cette valeur est de 1500 octets.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Une macro qui appelle la procédure distante procnum associée au handle client clnt, obtenu avec une routine de création client RPC telle que clnt_create(). Le paramètre in est l'adresse de(s) argument(s) de la procédure, et out est l'adresse où placer le(s) résultat(s) ; inproc est utilisé pour encoder les paramètres de la procédure, et outproc est utilisé pour décoder les résultats de la procédure ; tout est le temps autorisé pour que les résultats reviennent.
clnt_destroy(CLIENT *clnt);
Une macro qui détruit le handle RPC du client. La destruction implique généralement la désallocation des structures de données privées, y compris clnt lui-même. L'utilisation de clnt est indéfinie après avoir appelé clnt_destroy(). Si la bibliothèque RPC a ouvert le socket associé, elle le fermera également. Sinon, le socket reste ouvert.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Routine générique de création de client. host identifie le nom de l'hôte distant où se trouve le serveur. proto indique quel type de protocole de transport utiliser. Les valeurs actuellement supportées pour ce champ sont “udp” et “tcp”. Des délais d'attente par défaut sont définis, mais peuvent être modifiés en utilisant clnt_control().
Avertissement : l'utilisation de UDP présente des inconvénients. Comme les messages RPC basés sur UDP ne peuvent contenir que jusqu'à 8 Ko de données encodées, ce transport ne peut pas être utilisé pour les procédures qui prennent de grands arguments ou retournent d'énormes résultats.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Une macro utilisée pour modifier ou récupérer diverses informations concernant un objet client. req indique le type d'opération, et info est un pointeur vers les informations. Pour UDP et TCP, les valeurs supportées de req et leurs types d'arguments ainsi que leur fonction sont :

CLSET_TIMEOUT  struct timeval // définir le délai d'attente total
CLGET_TIMEOUT  struct timeval // obtenir le délai d'attente total

Note : si vous définissez le délai d'attente en utilisant clnt_control(), le paramètre de délai d'attente passé à clnt_call() sera ignoré pour tous les appels futurs.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtenir l'adresse du serveur

Les opérations suivantes sont valides pour UDP uniquement :

CLSET_RETRY_TIMEOUT  struct timeval // définir le délai de nouvelle tentative
CLGET_RETRY_TIMEOUT  struct timeval // obtenir le délai de nouvelle tentative

Le délai de nouvelle tentative est le temps pendant lequel "UDP RPC" attend la réponse du serveur avant de retransmettre la requête.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Une macro qui libère toutes les données allouées par le système RPC/XDR lors du décodage des résultats d'un appel RPC. Le paramètre out est l'adresse des résultats, et outproc est la routine XDR décrivant les résultats. Cette routine retourne un si les résultats ont été libérés avec succès, et zéro sinon.
void clnt_geterr(CLIENT *clnt, struct rpc_err *errp);
Une macro qui récupère la structure d'erreur RPC associée au handle client clnt. Elle copie la structure d'erreur dans la zone mémoire pointée par errp. Cette routine est généralement appelée après qu'une routine RPC a retourné un statut d'échec.
char *clnt_perror(CLIENT *clnt, char *s);
Une macro qui imprime un message d'erreur sur le flux d'erreurs standard. Le paramètre s est une chaîne de caractères à imprimer avant le message d'erreur système. Elle renvoie la chaîne de message d'erreur.
void clnt_spcreateerror(char *s);
Une macro qui imprime un message d'erreur sur le flux d'erreurs standard, précédé de la chaîne s. Elle est utilisée pour afficher les erreurs lors de la création d'un handle client.
char *clnt_sperrno(int num);
Une macro qui renvoie une chaîne de caractères décrivant l'erreur RPC associée au numéro d'erreur num. Elle est généralement utilisée pour traduire les valeurs de enum clnt_stat en chaînes lisibles.
char *clnt_sperror(CLIENT *clnt);
Une macro qui renvoie une chaîne de caractères décrivant l'erreur RPC associée au handle client clnt. Elle est généralement utilisée pour obtenir une description textuelle d'une erreur RPC.
CLIENT *clnttcp_create(struct sockaddr_in *addr, unsigned long prog,
                     unsigned long vers, struct timeval *timeout,
                     int *sockp, unsigned int send_buf_size,
                     unsigned int recv_buf_size);
Crée un handle client RPC utilisant le transport TCP. addr est l'adresse du serveur, prog est le numéro de programme, vers est le numéro de version, timeout est le délai d'attente pour les opérations RPC. Si sockp n'est pas nul, il pointe vers un entier qui contiendra le descripteur de fichier du socket créé. send_buf_size et recv_buf_size spécifient les tailles des tampons d'envoi et de réception TCP. Si ces derniers sont 0, les tailles par défaut sont utilisées.
CLIENT *clntudp_create(struct sockaddr_in *addr, unsigned long prog,
                     unsigned long vers, struct timeval *timeout,
                     int *sockp);
Crée un handle client RPC utilisant le transport UDP. addr est l'adresse du serveur, prog est le numéro de programme, vers est le numéro de version, timeout est le délai d'attente pour les opérations RPC. Si sockp n'est pas nul, il pointe vers un entier qui contiendra le descripteur de fichier du socket créé.
Avertissement : les messages RPC UDP sont limités à 8 Ko. Si vous avez besoin de transférer des données plus volumineuses, utilisez TCP.
CLIENT *clntudp_bufcreate(struct sockaddr_in *addr, unsigned long prog,
                        unsigned long vers, struct timeval *timeout,
                        int *sockp, unsigned int send_buf_size,
                        unsigned int recv_buf_size);
Crée un handle client RPC utilisant le transport UDP avec des tampons de taille spécifiée. Les paramètres sont les mêmes que pour clntudp_create(), avec en plus send_buf_size et recv_buf_size pour définir les tailles des tampons d'envoi et de réception UDP. Si ces derniers sont 0, les tailles par défaut sont utilisées.
AUTH *get_auth_sys(void);
Retourne un handle d'authentification de type Unix standard.
void registerrpc(unsigned long prognum, unsigned long versnum,
                 unsigned long procnum, char *procname,
                 xdrproc_t argproc, char *args,
                 xdrproc_t resultproc, char *results);
Enregistre une procédure RPC. prognum est le numéro de programme, versnum le numéro de version, procnum le numéro de procédure. procname est le nom de la procédure (pas utilisé dans l'implémentation actuelle). argproc est la routine XDR pour encoder les arguments, args est un pointeur vers les arguments. resultproc est la routine XDR pour encoder les résultats, results est un pointeur vers les résultats. Cette routine est généralement appelée par le code généré par rpcgen.
void rpc_control(CLIENT *cl, unsigned int request, char *info);
Similaire à clnt_control(), mais pour des requêtes RPC génériques.
void svc_destroy(SVCXPRT *xprt);
Détruit un handle de transport de service RPC. Cela libère les ressources associées au handle de transport.
bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                  unsigned long versnum, void (dispatch)(struct svc_req *, SVCXPRT *),
                  int timeout);
Enregistre un programme RPC auprès du système de diffusion de services (pmap). xprt est le handle de transport de service, prognum est le numéro de programme, versnum est le numéro de version. dispatch est un pointeur vers une fonction de dispatch qui sera appelée lorsqu'une requête RPC est reçue pour ce programme et cette version. timeout est le délai d'attente avant de considérer la requête comme perdue (utilisé pour les transports non fiables comme UDP).
void svc_run(void);
Entre dans une boucle infinie qui attend les requêtes RPC entrantes et les distribue aux routines de dispatch appropriées. Cette fonction ne retourne jamais, sauf en cas d'erreur fatale.
void svc_unregister(unsigned long prognum, unsigned long versnum);
Désenregistre un programme RPC du système de diffusion de services.
SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                     unsigned int recv_buf_size);
Crée un handle de transport de service RPC utilisant le transport TCP. sock est le descripteur de fichier du socket TCP déjà connecté. send_buf_size et recv_buf_size spécifient les tailles des tampons d'envoi et de réception TCP.
SVCXPRT *svcfd_create(int fd);
Crée un handle de transport de service RPC à partir d'un descripteur de fichier existant (par exemple, un socket).

SVCXPRT *svcudp_create(int sock);

bool_t xdrrec_endofrec(XDR *xdrs, bool_t sendnow);
Indique la fin d'un enregistrement XDR sérialisé. Si sendnow est vrai, les données en attente sont envoyées immédiatement.

Routine XDR pour encoder ou décoder une chaîne de caractères terminée par un caractère nul. Similaire à xdr_string, mais utilise une approche différente pour la gestion de la mémoire.
bool_t xdr_wrap_opaque(XDR *xdrs, char *addr, u_int len);

Routine XDR pour encoder ou décoder une structure rejected_reply. Cette structure représente une réponse de rejet d'un serveur RPC.
int xdr_sizeof(xdrproc_t proc, void *data);

void xdr_union_field_decl(XDR *xdrs, int *discr, void *addr,

Une macro qui copie la structure d'erreur du descripteur client vers la structure à l'adresse errp.
void clnt_pcreateerror(const char *s);
Imprime un message sur la sortie d'erreur standard indiquant pourquoi un descripteur RPC client n'a pas pu être créé. Le message est précédé de la chaîne s et de deux-points. Utilisé lorsqu'un appel à clnt_create(), clntraw_create(), clnttcp_create(), ou clntudp_create() échoue.
void clnt_perrno(enum clnt_stat stat);
Imprime un message sur la sortie d'erreur standard correspondant à la condition indiquée par stat. Utilisé après callrpc().
clnt_perror(CLIENT *clnt, const char *s);
Imprime un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué ; clnt est le descripteur utilisé pour effectuer l'appel. Le message est précédé de la chaîne s et de deux-points. Utilisé après clnt_call().
char *clnt_spcreateerror(const char *s);
Semblable à clnt_pcreateerror(), sauf qu'il renvoie une chaîne au lieu d'imprimer sur la sortie d'erreur standard.
Bugs : renvoie un pointeur vers des données statiques qui sont écrasées à chaque appel.
char *clnt_sperrno(enum clnt_stat stat);
Prend les mêmes arguments que clnt_perrno(), mais au lieu d'envoyer un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué, renvoie un pointeur vers une chaîne contenant le message. La chaîne se termine par un NOUVELLE LIGNE.
clnt_sperrno() est utilisé à la place de clnt_perrno() si le programme n'a pas de sortie d'erreur standard (comme un programme exécuté en tant que serveur n'en a probablement pas), ou si le programmeur ne veut pas que le message soit affiché avec printf(3), ou si un format de message différent de celui pris en charge par clnt_perrno() doit être utilisé. Note : contrairement à clnt_sperror() et clnt_spcreateerror(), clnt_sperrno() renvoie un pointeur vers des données statiques, mais le résultat ne sera pas écrasé à chaque appel.
char *clnt_sperror(CLIENT *rpch, const char *s);
Semblable à clnt_perror(), sauf que (comme clnt_sperrno()) il renvoie une chaîne au lieu d'imprimer sur la sortie d'erreur standard.
Bugs : renvoie un pointeur vers des données statiques qui sont écrasées à chaque appel.
CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);
Cette routine crée un client RPC factice pour le programme distant prognum, version versnum. Le transport utilisé pour passer les messages au service est en fait un tampon dans l'espace d'adressage du processus, donc le serveur RPC correspondant doit résider dans le même espace d'adressage ; voir svcraw_create(). Cela permet de simuler RPC et d'acquérir les surcoûts RPC, tels que les temps d'aller-retour, sans aucune interférence du noyau. Cette routine renvoie NULL si elle échoue.
CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise TCP/IP comme transport. Le programme distant est situé à l'adresse Internet *addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est une socket ; si c'est RPC_ANYSOCK, alors cette routine en ouvre une nouvelle et définit sockp. Comme RPC basé sur TCP utilise des E/S mises en tampon, l'utilisateur peut spécifier la taille des tampons d'envoi et de réception avec les paramètres sendsz et recvsz ; des valeurs de zéro choisissent des valeurs par défaut appropriées. Cette routine renvoie NULL si elle échoue.
CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est une socket ; si c'est RPC_ANYSOCK, alors cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou que l'appel expire. Le temps total pour que l'appel expire est spécifié par clnt_call().
Avertissement : comme les messages RPC basés sur UDP ne peuvent contenir que jusqu'à 8 Kbytes de données encodées, ce transport ne peut pas être utilisé pour des procédures qui prennent de grands arguments ou retournent d'énormes résultats.
CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);
Cette routine crée un client RPC pour le programme distant prognum, sur versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est une socket ; si c'est RPC_ANYSOCK, alors cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou que l'appel expire. Le temps total pour que l'appel expire est spécifié par clnt_call().
Cela permet à l'utilisateur de spécifier la taille maximale des paquets pour l'envoi et la réception de messages RPC basés sur UDP.
void get_myaddress(struct sockaddr_in *addr);
Insère l'adresse IP de la machine dans *addr, sans consulter les routines de bibliothèque qui traitent /etc/hosts. Le numéro de port est toujours défini sur htons(PMAPPORT).
struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);
Une interface utilisateur pour le service portmap, qui renvoie une liste des mappages actuels programme RPC-vers-port sur l'hôte situé à l'adresse IP *addr. Cette routine peut renvoyer NULL. La commande rpcinfo -p utilise cette routine.
unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);
Une interface utilisateur pour le service portmap, qui renvoie le numéro de port sur lequel attend un service qui prend en charge le numéro de programme prognum, la version versnum et parle le protocole de transport associé à protocol. La valeur de protocol est très probablement IPPROTO_UDP ou IPPROTO_TCP. Une valeur de retour de zéro signifie que le mappage n'existe pas ou que le système RPC n'a pas réussi à contacter le service portmap distant. Dans ce dernier cas, la variable globale rpc_createerr contient le statut RPC.
enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);
Une interface utilisateur pour le service portmap, qui demande à portmap sur l'hôte à l'adresse IP *addr de faire un appel RPC en votre nom à une procédure sur cet hôte. Le paramètre *portp sera modifié au numéro de port du programme si la procédure réussit. Les définitions des autres paramètres sont discutées dans callrpc() et clnt_call(). Cette procédure doit être utilisée pour un « ping » et rien d'autre. Voir aussi clnt_broadcast().
bool_t pmap_set(unsigned long prognum, unsigned long versnum,

Une interface utilisateur pour le service portmap, qui établit un mappage entre le triplet [prognum,versnum,protocol] et port sur le service portmap de la machine. La valeur de protocol est très probablement IPPROTO_UDP ou IPPROTO_TCP. Cette routine renvoie un si elle réussit, zéro sinon. Automatiquement fait par svc_register().
bool_t pmap_unset(unsigned long prognum, unsigned long versnum);
Une interface utilisateur pour le service portmap, qui détruit tous les mappages entre le triplet [prognum,versnum,*] et les ports sur le service portmap de la machine. Cette routine renvoie un si elle réussit, zéro sinon.
int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);
Enregistre la procédure procname auprès du package de services RPC. Si une requête arrive pour le programme prognum, la version versnum et la procédure procnum, procname est appelée avec un pointeur vers ses paramètres ; procname doit renvoyer un pointeur vers ses résultats statiques ; inproc est utilisé pour décoder les paramètres tandis que outproc est utilisé pour encoder les résultats. Cette routine renvoie zéro si l'enregistrement a réussi, -1 sinon.
Avertissement : les procédures distantes enregistrées sous cette forme sont accédées en utilisant le transp UDP/IP
ort ; voir svcudp_create() pour les restrictions. 
struct rpc_createerr rpc_createerr;
Une variable globale dont la valeur est définie par toute routine de création de client RPC qui échoue. Utilisez la routine clnt_pcreateerror() pour imprimer la raison. 
void svc_destroy(SVCXPRT *xprt);
Une macro qui détruit le descripteur de transport du service RPC, xprt. La destruction implique généralement la désallocation des structures de données privées, y compris xprt lui-même. L'utilisation de xprt est indéfinie après l'appel de cette routine. 
fd_set svc_fdset;
Une variable globale reflétant le masque de bits du descripteur de fichier de lecture du côté du service RPC ; elle est appropriée en tant que paramètre pour l'appel système select(2). Ceci n'intéresse que si un implémenteur de service effectue son propre traitement d'événements asynchrones, au lieu d'appeler svc_run(). Cette variable est en lecture seule (ne pas passer son adresse à select(2) !), pourtant elle peut changer après des appels à svc_getreqset() ou à toute routine de création. 
int svc_fds;
Similaire à svc_fdset, mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_fdset. 
svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Une macro qui libère toutes les données allouées par le système RPC/XDR lorsqu'il a décodé les arguments d'une procédure de service en utilisant svc_getargs(). Cette routine renvoie 1 si les résultats ont été libérés avec succès, et zéro sinon. 
svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Une macro qui décode les arguments d'une requête RPC associée au descripteur de transport du service RPC, xprt. Le paramètre in est l'adresse où les arguments seront placés ; inproc est la routine XDR utilisée pour décoder les arguments. Cette routine renvoie un si le décodage réussit, et zéro sinon. 
struct sockaddr_in *svc_getcaller(SVCXPRT *xprt);
La manière approuvée d'obtenir l'adresse réseau de l'appelant d'une procédure associée au descripteur de transport du service RPC, xprt. 
void svc_getreqset(fd_set *rdfds);
Cette routine n'intéresse que si un implémenteur de service n'appelle pas svc_run(), mais implémente à la place un traitement d'événements asynchrones personnalisé. Elle est appelée lorsque l'appel système select(2) a déterminé qu'une requête RPC est arrivée sur un ou plusieurs sockets RPC ; rdfds est le masque de bits de descripteurs de fichiers en lecture résultant. La routine retourne lorsque tous les sockets associés à la valeur de rdfds ont été servis. 
void svc_getreq(int rdfds);
Similaire à svc_getreqset(), mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_getreqset(). 
bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol);
Associe prognum et versnum à la procédure de dispatch du service, dispatch. Si protocol est zéro, le service n'est pas enregistré auprès du service portmap. Si protocol est non nul, alors un mappage du triplet [prognum,versnum,protocol] vers xprt->xp_port est établi avec le service portmap local (généralement protocol est zéro, IPPROTO_UDP ou IPPROTO_TCP). La procédure dispatch a la forme suivante : 

dispatch(struct svc_req *request, SVCXPRT *xprt);

La routine svc_register() renvoie un si elle réussit, et zéro sinon. 
void svc_run(void);
Cette routine ne retourne jamais. Elle attend l'arrivée de requêtes RPC et appelle la procédure de service appropriée en utilisant svc_getreq() lorsqu'une arrive. Cette procédure attend généralement qu'un appel système select(2) retourne. 
bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);
Appelée par la routine de dispatch d'un service RPC pour envoyer les résultats d'un appel de procédure distante. Le paramètre xprt est le descripteur de transport associé à la requête ; outproc est la routine XDR utilisée pour encoder les résultats ; et out est l'adresse des résultats. Cette routine renvoie un si elle réussit, zéro sinon. 
void svc_unregister(unsigned long prognum, unsigned long versnum);
Supprime tous les mappages du double [prognum,versnum] vers les routines de dispatch, et du triple [prognum,versnum,*] vers le numéro de port. 
void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);
Appelée par une routine de dispatch de service qui refuse d'effectuer un appel de procédure distante en raison d'une erreur d'authentification. 
void svcerr_decode(SVCXPRT *xprt);
Appelée par une routine de dispatch de service qui ne peut pas décoder ses paramètres avec succès. Voir aussi svc_getargs(). 
void svcerr_noproc(SVCXPRT *xprt);
Appelée par une routine de dispatch de service qui n'implémente pas le numéro de procédure demandé par l'appelant. 
void svcerr_noprog(SVCXPRT *xprt);
Appelée lorsque le programme désiré n'est pas enregistré auprès du package RPC. Les implémenteurs de service n'ont généralement pas besoin de cette routine. 
void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers,
                     unsigned long high_vers);
Appelée lorsque la version désirée d'un programme n'est pas enregistrée auprès du package RPC. Les implémenteurs de service n'ont généralement pas besoin de cette routine. 
void svcerr_systemerr(SVCXPRT *xprt);
Appelée par une routine de dispatch de service lorsqu'elle détecte une erreur système non couverte par un protocole particulier. Par exemple, si un service ne peut plus allouer de stockage, il peut appeler cette routine. 
void svcerr_weakauth(SVCXPRT *xprt);
Appelée par une routine de dispatch de service qui refuse d'effectuer un appel de procédure distante en raison de paramètres d'authentification insuffisants. La routine appelle svcerr_auth(xprt, AUTH_TOOWEAK). 
SVCXPRT *svcfd_create(int fd, unsigned int sendsize,
                      unsigned int recvsize);
Crée un service au-dessus de tout descripteur de fichier ouvert. Typiquement, ce descripteur de fichier est un socket connecté pour un protocole de flux tel que TCP. sendsize et recvsize indiquent les tailles des tampons d'envoi et de réception. S'ils sont nuls, une valeur par défaut raisonnable est choisie. 
SVCXPRT *svcraw_create(void);
Cette routine crée un transport de service RPC jouet, auquel elle renvoie un pointeur. Le transport est en réalité un tampon dans l'espace d'adressage du processus, donc le client RPC correspondant devrait résider dans le même espace d'adressage ; voir clntraw_create(). Cette routine permet la simulation de RPC et l'acquisition de surcoûts RPC (tels que les temps d'aller-retour), sans aucune interférence du noyau. Cette routine renvoie NULL si elle échoue. 
SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);
Cette routine crée un transport de service RPC basé sur TCP/IP, auquel elle renvoie un pointeur. Le transport est associé au socket sock, qui peut être RPC_ANYSOCK, auquel cas un nouveau socket est créé. Si le socket n'est pas lié à un port TCP local, cette routine le lie à un port arbitraire. À la fin, xprt->xp_sock est le descripteur de socket du transport, et xprt->xp_port est le numéro de port du transport. Cette routine renvoie NULL si elle échoue. Comme le RPC basé sur TCP utilise des E/S mises en tampon, les utilisateurs peuvent spécifier la taille des tampons ; des valeurs nulles choisissent des valeurs par défaut appropriées. 
SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize,
                          unsigned int recosize);
Cette routine crée un transport de service RPC basé sur UDP/IP, auquel elle renvoie un pointeur. Le transport est associé au socket sock, qui peut être RPC_ANYSOCK, auquel cas un nouveau socket est créé. Si le socket n'est pas lié à un port UDP local, cette routine le lie à un port arbitraire. À la fin, xprt->xp_sock est le descripteur de socket du transport, et xprt->xp_port est le numéro de port du transport. Cette routine renvoie NULL si elle échoue.
Ceci permet à l'utilisateur de spécifier la taille maximale du paquet pour l'envoi et la réception des messages RPC basés sur UDP. 
SVCXPRT *svcudp_create(int sock);
Cet appel est équivalent à svcudp_bufcreate(sock,SZ,SZ) pour une taille par défaut SZ. 
bool_t xdr_accepted_reply(XDR *xdrs, struct accepted_reply *ar);

bool_t xdr_authunix_parms(XDR *xdrs, struct authunix_parms *aupp);
Utilisé pour décrire les informations d'identification UNIX. Cette routine est utile pour les utilisateurs qui souhaitent générer ces informations d'identification sans utiliser le package d'authentification RPC. 
void xdr_callhdr(XDR *xdrs, struct rpc_msg *chdr);
Utilisé pour décrire les messages d'en-tête d'appel RPC. Cette routine est utile pour les utilisateurs qui souhaitent générer des messages de style RPC sans utiliser le package RPC. 
bool_t xdr_callmsg(XDR *xdrs
, struct rpc_msg *cmsg);
Utilisé pour décrire les messages d'appel RPC. Cette routine est utile pour les utilisateurs qui souhaitent générer des messages de style RPC sans utiliser le package RPC.

Utilisé pour décrire les paramètres de diverses procédures portmap, en externe. Cette routine est utile pour les utilisateurs qui souhaitent générer ces paramètres sans utiliser l'interface pmap.

bool_t xdr_replymsg(XDR *xdrs, struct rpc_msg *rmsg);
Utilisé pour décrire les messages de réponse RPC. Cette routine est utile pour les utilisateurs qui souhaitent générer des messages de style RPC sans utiliser le package RPC.
