PMINFO(1) Manuel général des commandes PMINFO(1)

NOM

pminfo - affiche des informations sur les métriques de performance

SYNTAXE

pminfo [-dfFIlLmMstTvVxz?] [-a archive] [-b taille_lot] [-c fichier_md] [--container nom] [-D debug] [-h hote] [-K spec] [-[n|N] fichier_pmns] [-O temps] [-r nom_md=expr] [-Z fuseau_horaire] [nom_metrique | id_pm | indom]...

DESCRIPTION

pminfo affiche divers types d'informations sur les métriques de performance disponibles via les facilités du Performance Co-Pilot (PCP).

Les métriques d'intérêt sont nommées dans les arguments nom_metrique. Si nom_metrique est un nœud non-feuille dans le PMNS, alors pminfo descendra récursivement le PMNS et rapportera tous les nœuds feuilles. Si aucun argument nom_metrique n'est donné, la racine du PMNS est utilisée.

Si l'argument nom_metrique est en notation décimale numérique, il est interprété comme un id_pm à 3 décimales (identifiant de métrique - numéros de domaine, cluster, élément) ou un indom à 2 décimales (identifiant de domaine d'instance - domaine, numéro de série). Dans le cas du id_pm, une recherche inversée PMID-vers-nom est effectuée, et dans le cas de l'indom, le domaine d'instance est rapporté directement. Ce dernier mode peut être utilisé pour rapporter le résumé du texte d'aide "une ligne" et le texte long du domaine d'instance.

Sauf indication contraire vers un autre hôte via l'option -h, pminfo contactera par défaut le démon collecteur de métriques de performance (PMCD) sur l'hôte local. La connexion à un PMCD n'est requise que si pminfo nécessite des informations PMNS distribuées, et/ou des métadonnées décrivant les métriques, et/ou des valeurs de métriques, et/ou du texte d'aide.

L'option -a amène pminfo à utiliser l'ensemble spécifié d'archives plutôt que de se connecter à un PMCD.

L'option -L amène pminfo à utiliser un contexte local pour collecter les métriques des PMDA locaux sans PMCD. Seules certaines métriques sont disponibles dans ce mode.

Les options -a, -h et -L sont mutuellement exclusives.

OPTIONS

Les options de ligne de commande disponibles sont :

-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées de l'ensemble des fichiers d'archives du Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste d'archives séparées par des virgules, chacune pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-b, --batch
Cette option peut être utilisée pour définir le nombre maximum de métriques à récupérer dans une seule requête pour les options -f et -v. La valeur par défaut pour taille_lot est 128.
-c fichier_md, --derived=fichier_md
L'argument fichier_md spécifie un fichier contenant des définitions de métriques dérivées dans le format décrit pour pmLoadDerivedConfig(3). L'option -c fournit un moyen de charger des définitions globales de métriques dérivées qui est une alternative à l'utilisation plus générique de la variable d'environnement PCP_DERIVED_CONFIG décrite dans PCPIntro(1). Utiliser l'option -c et la variable d'environnement PCP_DERIVED_CONFIG pour spécifier la **même** configuration est une mauvaise idée, choisissez donc une méthode ou l'autre. Voir aussi l'option -r ci-dessous.
--container=conteneur
Spécifie un conteneur individuel à interroger.
-d, --desc
Descriptions des métriques détaillant le PMID, le type de données, la sémantique des données, les unités, l'échelle et le domaine d'instance associé.
-f, --fetch
Récupère et imprime les valeurs pour toutes les instances. Lors de la récupération à partir d'un ensemble d'archives, seules les instances présentes dans le premier enregistrement d'archive pour une métrique seront affichées ; voir aussi l'option -O, sinon utilisez pmlogdump(1) qui peut être un meilleur outil pour examiner les archives.
-F, --fetchall
Identique à -f mais essaie plus fort de récupérer les instances pour les métriques qui ont des domaines d'instance non énumérables (par exemple, les métriques dans le sous-arbre ``proc'' du PMNS par défaut sur certaines plateformes).
-h hote, --host=hote
Récupère les métriques de performance de pmcd(1) sur hote, plutôt que de localhost par défaut.
-I, --fullindom
Imprime l'InDom en mode verbeux.
-K spec, --spec-local=spec
Lorsque vous utilisez l'option -L pour récupérer des métriques d'un contexte local, cette option contrôle les PMDA DSO qui devraient être rendus accessibles. L'argument spec est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peut être utilisée.
-l, --labels
Imprime les ensembles d'étiquettes associés aux métriques et aux instances. Les étiquettes sont des métadonnées de métriques optionnelles décrites en détail dans pmLookupLabels(3).
-L, --local-PMDA
Utilise un contexte local pour collecter des métriques à partir des PMDA DSO sur l'hôte local sans PMCD. Voir aussi -K.
-m, --pmid
Imprime le PMID en mode concis.
-M, --fullpmid
Imprime le PMID en mode verbeux.
-n fichier_pmns, --namespace=fichier_pmns
Normalement, pminfo opère sur l'espace de noms de métriques de performance (PMNS) distribué, cependant si l'option -n est spécifiée, un PMNS local alternatif est chargé depuis le fichier fichier_pmns.
-N fichier_pmns, --uniqnames=fichier_pmns
L'option -N supporte la même fonction que -n, sauf pour la gestion des noms dupliqués pour le même identifiant de métrique de performance (PMID) dans fichier_pmns - les noms dupliqués sont autorisés avec -n mais ils ne sont pas autorisés avec -N.
-O temps, --origin=temps
Lorsqu'il est utilisé en conjonction avec une source d'archives de métriques et les options -f, l'argument temps définit une origine temporelle à laquelle les métriques doivent être récupérées de l'ensemble des archives. Se référer à PCPIntro(1) pour une description complète de cette option, et la syntaxe de l'argument temps.
-r nom_md=expr, --register=nom_md=expr
Enregistre une métrique dérivée par contexte en utilisant pmAddDerivedMetric(3). nom_md est le nom de la nouvelle métrique dérivée, et expr est l'expression pour la métrique dérivée, suivant la syntaxe décrite dans pmRegisterDerived(3). Plusieurs options -r sont autorisées. Voir aussi l'option -c ci-dessus.
-s, --series
Imprime les identifiants de séries temporelles associés aux métriques, instances et sources. Ces identifiants uniques sont calculés à partir des étiquettes intrinsèques (non optionnelles) et d'autres métadonnées de métriques associées à chaque contexte PMAPI (sources), métriques et instances. Les archives, le contexte local ou les connexions pmcd(1) pour le même hôte produisent le même identifiant de source. Voir aussi pmLookupLabels(3) et l'option -l.
-t, --oneline
Imprime le résumé d'aide ``une ligne'', si disponible.
-T, --helptext
Imprime le texte d'aide, si disponible.
-v, --verify
Mode de vérification dans lequel les descriptions et les valeurs sont récupérées, mais seuls les messages d'erreur sont imprimés. Utile pour vérifier la disponibilité des métriques et des instances sans avoir à gérer les sorties.
-V, --version
Affiche les informations de version et quitte.
-x, --xml
Ce mode génère une sortie XML, utile pour la programmation. Les options standard de pminfo peuvent être utilisées pour restreindre la sortie. Les balises de métrique seront utilisées si elles sont disponibles.
-z, --zero
Définit l'offset du fuseau horaire pour les archives au début de la période d'enregistrement.
-Z fuseau_horaire, --timezone=fuseau_horaire
Utilise le fuseau horaire fuseau_horaire pour la conversion des dates et heures lors de la manipulation d'archives de métriques. Voir aussi PCPIntro(1) pour une description plus complète des options de fuseau horaire.
-?, --help
Affiche un message d'aide et quitte.

EXEMPLES

Pour voir tous les métriques disponibles sur l'hôte local et leur description :

    pminfo -d

Pour voir les descriptions de toutes les métriques sous le domaine ``kernel'' :

    pminfo -d kernel

Pour voir les valeurs de toutes les instances de la métrique ``kernel.cpu.total'' :

    pminfo -f kernel.cpu.total

Pour voir les valeurs de toutes les instances de la métrique ``kernel.cpu.total'' à l'aide des archives nommées ``MyArchive.1.0'' :

    pminfo -f -a MyArchive.1.0 kernel.cpu.total

Pour voir le texte d'aide complet de la métrique ``kernel.cpu.total'' :

    pminfo -T kernel.cpu.total

Pour voir le texte d'aide "une ligne" de la métrique ``kernel.cpu.total'' :

    pminfo -t kernel.cpu.total

Pour voir les identifiants de métriques (PMID) pour la métrique ``kernel.cpu.total'' :

    pminfo -m kernel.cpu.total

Pour voir les descriptions et les valeurs de la métrique ``kernel.cpu.total'' en utilisant le démon PMCD sur l'hôte ``server.example.com'' :

    pminfo -dh server.example.com kernel.cpu.total

Pour voir les descriptions et les valeurs de la métrique ``kernel.cpu.total'' en utilisant un contexte local (sans PMCD) :

    pminfo -L kernel.cpu.total

pminfo(1) — Performance Co-Pilot

NAME

pminfo — report performance metrics

SYNOPSIS

pminfo [-CF] [-D debuglist] [-f | -l | -t | -T] [-h host] [-i domain] [-n nfs] [-p port] [-S source] [-U username] [-V] [-x] [-z] [-Z timezone] [metricname... | ->file]

DESCRIPTION

pminfo retrieves and reports performance metrics from Performance Co-Pilot (PCP) data sources. The default data source is the local system. It can also retrieve metrics from archives or remote hosts.

The optional arguments metricname specify the metrics to be reported. If no metrics are specified, pminfo will print a list of all available metrics.

If the input is specified as ->file, then pminfo will attempt to read metric names from the specified file, one per line. This is useful for reporting on a large number of metrics.

OPTIONS

-C, --constrained
Print only the metric names that are constrained to a single instance.
-D debuglist, --debug=debuglist
Enable debugging output. See the DEBUGGING OPTIONS section below.
-f, --fetch
Fetch and print metric values. This is the default behavior if metrics are specified on the command line.
-F, --filter
Filter the output to include only the metric names that are defined in the local PMNS. Without other options, this will print a list of all available metrics that are defined in the local PMNS.
-h host, --host=host
Retrieve performance metrics from remote host host instead of the default local system.
-i domain, --domain=domain
Retrieve performance metrics from Performance Metrics Domain (PMD) domain instead of the default local system.
-l, --labels
Print available performance metric labels.
-m, --pmid
Print available performance metric identifiers (PMIDs).
-M, --fullpmid
Print available performance metric identifiers (PMIDs) with full domain and item information.
-n nfs, --nfs=nfs
Retrieve performance metrics from the specified Network File System (NFS) export nfs.
-p port, --port=port
Retrieve performance metrics from the Performance Co-Pilot collector (pmcd) listening on port on the specified host.
-S source, --source=source
Retrieve performance metrics from the specified data source. The source can be a hostname, an archive name, or a PMNS specification file.
-t, --oneline
Print metric values on a single line, with metric names and values separated by spaces. This option implies -f.
-T, --helptext
Print help text for available metrics.
-U username, --username=username
Connect to the remote host as username.
-V, --version
Display version number and exit.
-x, --events
Like the -f/--fetch option, but with the additional functionality that if a value is processed that is of type PM_TYPE_EVENT or PM_TYPE_HIGHRES_EVENT, then the event records will be unpacked and the details of each event record reported.
-z, --hostzone
Change the reporting timezone to the local timezone at the host that is the source of the performance metrics, as identified via either the -h or -a options.
-Z timezone, --timezone=timezone
By default, pminfo reports the time of day according to the local timezone on the system where pminfo is run. The -Z option changes the timezone to timezone in the format of the environment variable TZ as described in environ(7).
-?, --help
Display usage message and exit.

FILES

$PCP_VAR_DIR/pmns/*
default local PMNS specification files

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.

Debugging options specific to pminfo are as follows:

Option Description
appl4 report batch downsizing if batchsize would exceed maximum PDU size
appl5 dump PDU stats at end if context is a host
