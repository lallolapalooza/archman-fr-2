NOM

pmGetChildren - retourne les nœuds descendants d'un nœud PMNS

SYNTAXE C

#include <pcp/pmapi.h>

int pmGetChildren(const char *name, char ***offspring);

cc ... -lpcp

DESCRIPTION

Étant donné un chemin d'accès qualifié complet à un nœud dans l'espace de noms des métriques de performance (PMNS) actuel, identifié par name, pmGetChildren renvoie via offspring une liste des noms relatifs de tous les nœuds descendants immédiats de name dans le PMNS actuel.

À titre de cas spécial, si name est une chaîne vide (c'est-à-dire ""), les descendants immédiats du nœud racine dans le PMNS seront renvoyés.

Normalement, pmGetChildren renvoie le nombre de noms descendants découverts, sinon une valeur inférieure à zéro en cas d'erreur. La valeur zéro indique que name est un nom de métrique valide, c'est-à-dire associé à un nœud feuille dans le PMNS.

La liste résultante de pointeurs offspring et les valeurs (les noms relatifs) auxquelles les pointeurs font référence auront été alloués par pmGetChildren avec un seul appel à malloc(3), et il incombe à l'appelant de pmGetChildren d'appeler free(offspring) pour libérer l'espace lorsqu'il n'est plus nécessaire.

Lorsqu'une erreur se produit, ou que name est un nœud feuille (c'est-à-dire que le résultat de pmGetChildren est inférieur à un), offspring n'est pas défini (aucun espace n'aura été alloué, et donc appeler free(3) est une très mauvaise idée).

DIAGNOSTICS

PM_ERR_NOPMNS
Échec de l'accès à un PMNS pour l'opération. Notez que si l'application n'a pas préalablement appelé pmLoadNameSpace(3) et souhaite utiliser le PMNS distribué, alors un appel à pmGetChildren doit être effectué dans un contexte actuel.
PM_ERR_NAME
Le chemin d'accès name n'est pas valide dans le PMNS actuel.
PM_ERR_*
D'autres diagnostics concernent les échecs de protocole lors de l'accès au PMNS distribué.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5). Les valeurs de ces variables peuvent être obtenues par programme en utilisant la fonction pmGetConfig(3).
