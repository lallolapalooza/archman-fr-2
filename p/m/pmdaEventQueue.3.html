DESCRIPTION

Un Agent de Domaine de Métriques de Performance (PMDA) qui exporte des enregistrements d'événements doit agir efficacement comme un multiplexeur d'événements. Les événements consommés par le PMDA peuvent devoir être transmis à un certain nombre d'outils de surveillance (ou de "contextes clients"). Ces outils peuvent demander des événements à des intervalles d'échantillonnage différents, et il est très peu probable qu'ils demandent un événement au moment exact où il arrive au PMDA, rendant une forme de mise en mémoire tampon et de gestion de files d'attente d'événements nécessaire. Les événements doivent être conservés par le PMDA jusqu'à ce que tous les clients enregistrés les aient reçus, ou jusqu'à ce qu'une limite de mémoire soit atteinte par le PMDA, auquel cas il doit rejeter les événements plus anciens à mesure que de nouveaux arrivent.

Les routines décrites ici sont conçues pour aider le développeur de PMDA à gérer les contextes clients et les files d'attente d'événements à un haut niveau. Celles-ci s'intègrent logiquement au-dessus des primitives de plus bas niveau, telles que celles décrites dans pmdaEventNewArray(3), et protègent le PMDA moyen des détails de construction directe de tableaux d'enregistrements d'événements pour des contextes clients individuels.

Le PMDA enregistre une nouvelle file d'attente d'événements en utilisant soit pmdaEventNewQueue, soit pmdaEventNewActiveQueue. Ceux-ci reçoivent un nom identificateur (à des fins de diagnostic et pour une recherche ultérieure par pmdaEventQueueHandle) et maxmem, une limite supérieure de la mémoire (en octets) pouvant être consommée par les événements dans cette file, avant de commencer à les rejeter ("événements manqués" pour tout client qui n'a pas suivi). Si une file est allouée dynamiquement (de sorte que le PMDA puisse déjà avoir des clients connectés), l'interface pmdaEventNewActiveQueue doit être utilisée, avec le paramètre supplémentaire nclients indiquant le nombre de connexions clients actives. La valeur de retour est un code d'erreur négatif en cas d'échec, pouvant être décodé par la routine pmErrStr(3). Toute valeur non négative indique un succès et fournit un handle pouvant être passé aux autres routines de l'API.

Pour chaque nouvel événement reçu par le PMDA, la routine pmdaEventQueueAppend doit être appelée, plaçant cet événement dans la file d'attente identifiée par handle. L'événement lui-même doit être contenu dans le buffer passé, ayant une longueur de bytes. L'horodatage associé à l'événement (heure à laquelle l'événement s'est produit) est passé via le dernier paramètre tv.

Dans l'implémentation spécifique du rappel de récupération du PMDA, lorsque les valeurs d'une métrique d'événement ont été demandées, la routine pmdaEventQueueRecords doit être utilisée. Elle reçoit le handle de la file d'attente et la structure pmAtomValue avp à remplir avec les enregistrements d'événements, pour le client faisant cette demande de récupération (identifié par le paramètre context). Enfin, le PMDA doit également passer une routine de décodage d'événements, responsable du décodage des champs d'un seul événement dans les paramètres individuels de cet événement. Le paramètre data est un cookie opaque qui peut être utilisé pour passer des informations spécifiques à la situation à chaque invocation de decoder.

Dans certaines situations, il est utile pour le PMDA d'exporter l'état des files d'attente sous son contrôle. Les routines d'accès - pmdaEventQueueClients, pmdaEventQueueCounter, pmdaEventQueueBytes et pmdaEventQueueMemory fournissent un mécanisme pour interroger une file par son handle et remplir une structure pmAtomValue que la méthode pmdaFetchCallBack doit retourner.
