Paquet: pcp

PMLOADDERIVEDCONFIG(3) Manuel des fonctions de bibliothèque PMLOADDERIVEDCONFIG(3)

NOM

pmLoadDerivedConfig - charge les définitions de métriques dérivées depuis des fichiers

SYNTAXE

#include <pcp/pmapi.h>

int pmLoadDerivedConfig(char *path);

cc ... -lpcp

DESCRIPTION

Les métriques dérivées peuvent être utilisées pour étendre les métriques disponibles avec de nouvelles métriques (dérivées) en utilisant des expressions arithmétiques simples. Les définitions de ces métriques peuvent être persistantes et chargées par programme par les outils de surveillance à l'aide de pmLoadDerivedConfig.

Le paramètre path définit une liste de fichiers et/ou de répertoires séparés par des deux-points (la syntaxe est la même que pour la variable $PATH de sh(1)), à partir desquels les spécifications de métriques dérivées doivent être sourcées. Les composants de path sont développés en une liste de fichiers comme suit : si un composant est un fichier, alors ce fichier est ajouté à la liste, sinon si un composant est un répertoire alors une descente récursive est utilisée pour énumérer tous les fichiers sous ce répertoire et ceux-ci sont ajoutés à la liste. Chaque fichier de la liste résultante est analysé dans l'ordre, et selon la syntaxe des métriques dérivées décrite ci-dessous.

Chaque ligne des fichiers identifiés par path est soit une ligne de commentaire (avec un « # » en première position de la ligne) soit la déclaration d'une métrique de performance dérivée, spécifiée comme suit :

  • le nom de la métrique dérivée, en utilisant la même syntaxe de « notation par points » que celle utilisée pour les métriques de performance PCP, voir PCPIntro(1) et PMNS(5).
  • un signe égal (« = »)
  • une expression valide pour une métrique dérivée, telle que décrite dans pmRegisterDerived(3).

Pour chaque ligne contenant une définition de métrique dérivée, pmRegisterDerived(3) est appelée pour enregistrer la nouvelle métrique dérivée.

Une fois qu'une métrique dérivée a été déclarée, elle peut se voir attribuer des attributs supplémentaires avec une ligne de la forme :

  • le nom de la métrique dérivée,
  • une parenthèse ouvrante, un type d'attribut et une parenthèse fermante,
  • un signe égal (« = »),
  • une valeur d'attribut.

Actuellement, le type d'attribut peut être soit oneline soit helptext pour désigner le texte d'aide « en une ligne » ou le texte d'aide développé à associer à la métrique dérivée, voir pmLookupText(3).

La valeur d'attribut peut être soit du texte arbitraire suivant le « = » et se terminant à la fin de la ligne, soit une chaîne de caractères entre guillemets simples (') ou doubles ("). Dans ce dernier cas, la valeur d'attribut peut s'étendre sur plusieurs lignes, et un mécanisme d'échappement simple est supporté, à savoir que pour tout caractère « x », « \x » est remplacé par « x » (cela permet d'échapper les guillemets dans une chaîne, par exemple), et il existe un cas spécial où le « \ » est à la fin de la ligne, auquel cas le saut de ligne suivant n'est pas inclus dans la valeur d'attribut.

En dehors des valeurs d'attribut, les espaces blancs sont ignorés dans les lignes, et les lignes vides sont complètement ignorées.

Étant donné que pmLoadDerivedConfig peut traiter de nombreux fichiers, chacun pouvant contenir de nombreuses spécifications de métriques dérivées, il n'est pas possible de fournir un statut d'erreur spécifique en retour. Par conséquent, le résultat de pmLoadDerivedConfig sera le nombre de métriques dérivées chargées avec succès à partir des fichiers du path donné. Les erreurs catastrophiques, telles que l'impossibilité d'ouvrir l'un des fichiers du path donné, entraîneront un retour immédiat avec une valeur négative qui peut être passée à pmErrStr(3) pour obtenir le message d'erreur associé.

Lorsque des erreurs sont rencontrées dans les spécifications des métriques dérivées, des messages de diagnostic sont générés par pmRegisterDerived(3) et affichés via pmprintf(3).

pmUnregisterDerived(3) peut être utilisé pour désenregistrer une métrique dérivée par son nom, ce qui supprime toutes les instances de la métrique dérivée dans tous les contextes, quelle que soit la manière dont la métrique dérivée a été définie.

EXEMPLE

# exemples de définitions de métriques dérivées
bad_in_pkts = network.interface.in.errors + network.interface.in.drops
# notez que ce qui suit devrait être sur une seule ligne ...
disk.dev.read_pct = 100 * delta(disk.dev.read) /
            (delta(disk.dev.read) + delta(disk.dev.write))
disk.dev.read_pct(oneline) = pourcentage de lectures disque
disk.dev.read_pct(helptext) = '\
Pourcentage de lectures disque par rapport au nombre total de
lectures et écritures disque.'

VOIR AUSSI

PCPIntro(1), sh(1), PMAPI(3), pmLookupText(3), pmRegisterDerived(3), pmUnregisterDerived(3), pmprintf(3) et PMNS(5).
