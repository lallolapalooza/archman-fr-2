PMTIME(3) Manuel des fonctions de bibliothèque PMTIME(3)

NOM

pmTimeConnect, pmTimeDisconnect, pmTimeRecv, pmTimeSendAck, pmTimeShowDialog - fonctions de contrôle temporel pour la synchronisation de la position d'archive et de l'intervalle de mise à jour entre une ou plusieurs applications

C SYNTAXE

#include <pcp/pmtime.h>

int pmTimeConnect(int port, pmTime *state);
int pmTimeDisconnect(int fd);
int pmTimeSendAck(int fd, struct timeval *fetchTime);
int pmTimeShowDialog(int fd, int show);
int pmTimeRecv(int fd, pmTime *state);

cc ... -lpcp_gui

DESCRIPTION

Ces fonctions font partie de l'interface de programmation des applications de métriques de performance (PMAPI) et sont destinées à fournir un mécanisme uniforme permettant aux applications de lire des données d'archive et de rapporter des données en direct de manière synchronisée dans le temps.

La structure pmTime contient les champs suivants :

typedef struct {
    unsigned int        magic;
    unsigned int        length;
    pm_tctl_command     command;
    pm_tctl_source      source;
    pm_tctl_state       state;
    pm_tctl_mode        mode;
    struct timeval      delta;
    struct timeval      position;
    struct timeval      start;     /* archive uniquement */
    struct timeval      end;       /* archive uniquement */
    char                data[0];   /* informations de longueur arbitraire (TZ) */
} pmTime;

Dans le cas le plus simple, l'application doit appeler pmTimeConnect pour se connecter au serveur de contrôle temporel, pmtime(1), puis appeler répétitivement pmTimeRecv dans la boucle principale de l'application. En cas de succès, pmTimeConnect retourne un descripteur de fichier non négatif. Dans les applications qui ont plusieurs threads de contrôle, au lieu de bloquer dans pmTimeRecv, le descripteur de fichier peut être utilisé dans des appels à select(2). Dans les applications graphiques, le descripteur de fichier peut être utilisé pour interfacer avec la boucle d'événements.

Le paramètre port de pmTimeConnect est le numéro de port de la socket sur laquelle le serveur de contrôle temporel écoute (ou écoutera) les nouvelles connexions.

Le paramètre d'état à pmTimeConnect est utilisé pour initialiser un nouveau serveur de contrôle temporel ou pour passer des informations supplémentaires à un serveur de contrôle temporel existant. Les champs start et finish indiquent les limites chronologiques intéressantes pour l'application. Le champ showgui indique si le serveur de contrôle temporel doit afficher ou masquer la boîte de dialogue initialement. Les champs position, delta et data indiquent la position d'archive initiale, l'intervalle de mise à jour, la chaîne de fuseau horaire et la chaîne de label de fuseau horaire.

pmTimeRecv bloque jusqu'à ce que le serveur de contrôle temporel envoie un message de commande. Il met ensuite à jour le paramètre d'état et retourne l'un des identifiants de commande PM_TCTL_*.

La commande PM_TCTL_SET indique que l'application doit se positionner à la position d'archive (voir pmSetMode(3)) retournée dans le champ position du paramètre d'état.

La commande PM_TCTL_STEP indique que l'application doit effectuer une mise à jour, c'est-à-dire avancer (ou reculer, si delta est négatif) jusqu'à l'heure indiquée par la position, puis récupérer de nouvelles valeurs de métriques, mettre à jour l'affichage ou autre. Afin que plusieurs applications restent synchronisées, le serveur de contrôle temporel attendra que toutes les applications aient accusé réception de l'exécution de la commande step. Les applications doivent appeler pmTimeSendAck une fois la commande step traitée. Notez que PM_TCTL_STEP est la seule commande qui nécessite un accusé de réception explicite.

La commande PM_TCTL_VCRMODE est utilisée par le serveur de contrôle temporel pour indiquer le mode magnétoscope actuel.

La valeur est retournée dans le champ mode du paramètre d'état passé à pmTimeRecv, et reste valide jusqu'à ce qu'une nouvelle commande PM_TCTL_VCRMODE soit reçue.

La commande PM_TCTL_TZ indique que l'application doit utiliser un nouveau fuseau horaire, tel qu'indiqué dans le champ newzone du paramètre d'état.

La commande PM_TCTL_BOUNDS est envoyée à toutes les applications lorsque le serveur de contrôle temporel modifie ses limites chronologiques. Cela peut se produire lorsqu'une nouvelle application se connecte au serveur de contrôle temporel ou lorsque l'utilisateur modifie manuellement les limites. La plupart des applications ignoreront cette commande.

Les commandes PM_TCTL_GUIHIDE ou PM_TCTL_GUISHOW seront envoyées à toutes les applications lorsque la visibilité du serveur de contrôle temporel change. Cela permet aux applications de modifier le texte dans les menus ou les boutons pour refléter ce changement. Les applications peuvent modifier la visibilité de la boîte de dialogue de contrôle temporel à l'aide de la fonction pmTimeShowDialog. La visibilité initiale est déterminée lors de la première création de la boîte de dialogue de contrôle temporel par une application appelant pmTimeConnect avec le champ showgui du paramètre d'état défini sur la valeur souhaitée.

La fonction pmTimeDisconnect peut être utilisée pour fermer la socket de commande vers le serveur de contrôle temporel. Ceci est utile lorsque les applications ont besoin de changer le mode de connexion, par exemple pour dissocier le serveur de contrôle temporel actuel et se connecter à un nouveau.

VOIR AUSSI
