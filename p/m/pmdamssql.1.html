NOM

pmdamssql - PMDA de base de données Microsoft SQL Server

DESCRIPTION

pmdamssql est un Agent de domaine de métriques de performance (PMDA) de Performance Co-Pilot (PCP) qui extrait les données de performance en temps réel d'un serveur de base de données Microsoft SQL Server en cours d'exécution.

CONFIGURATION

Premièrement, pmdamssql nécessite l'installation des paquets de support suivants :

mssql-server
Le paquet principal de la base de données Microsoft SQL Server.
msodbcsql18, msodbcsql17 ou msodbcsql
Liaisons ODBC de Microsoft SQL Server.
pyodbc
Module ODBC général pour Python avec le support de Microsoft SQL Server activé.

Ensuite, pmdamssql lit un fichier de configuration facultatif de style ini :

$PCP_PMDAS_DIR/mssql/mssql.conf

Ce fichier permet actuellement deux sections, l'une pour configurer la bibliothèque qui se connecte au serveur SQL, l'autre pour s'authentifier auprès du serveur SQL.

La section [connection] spécifie les valeurs pour les paramètres suivants (leurs valeurs par défaut sont indiquées entre parenthèses) :

driver ({ODBC Driver 17 for SQL Server})
Chaîne de pilote ODBC.
server (tcp:localhost)
Chaîne de connexion socket SQL Server.
timeout (2)
Délai de connexion, en secondes.

La section [authentication] spécifie les valeurs pour les deux modes d'authentification pris en charge avec SQL Server.

Par défaut, l'authentification SQL Server est utilisée, ce qui nécessite un nom d'utilisateur et un mot de passe. Ce sont les paramètres de configuration suivants (leurs valeurs par défaut sont indiquées entre parenthèses) :

username (pcp)
Nom d'utilisateur pour se connecter à la base de données.
password (vide)
Mot de passe pour se connecter à la base de données.

Notez que si un fichier de configuration de l'API d'évaluations SQL Server est trouvé dans /var/opt/mssql/secrets/assessment, alors pmdamssql lit le nom d'utilisateur et le mot de passe à partir de ce fichier de manière préférentielle. Le format est simplement un fichier texte de deux lignes, la première contenant le nom d'utilisateur et la seconde le mot de passe.

La deuxième option est le mode d'authentification Windows, où des connexions sont créées dans SQL Server qui ne sont pas basées sur les comptes utilisateurs du système d'exploitation.

trusted (false)
Défini sur true pour utiliser l'authentification Windows lors de la connexion à la base de données.

Il s'agit d'une connexion de type Kerberos et les informations d'identification doivent être disponibles avant le démarrage du PMDA (voir kinit(1) pour plus de détails).

INSTALLATION

Pour installer, les opérations suivantes doivent être effectuées en tant que root :

# cd $PCP_PMDAS_DIR/mssql
# ./Install

Pour désinstaller, les opérations suivantes doivent être effectuées en tant que root :

# cd $PCP_PMDAS_DIR/mssql
# ./Remove

pmdamssql est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove informent pmcd(1) lorsque l'agent est installé ou supprimé.

pmdamssql tentera automatiquement de se reconnecter au serveur SQL si sa connexion est perdue - par exemple, si le service SQL Server est redémarré.

FICHIERS

$PCP_PMDAS_DIR/mssql/mssql.conf
fichier de configuration pour l'agent pmdamssql
$PCP_PMDAS_DIR/mssql/Install
script d'installation pour l'agent pmdamssql
$PCP_PMDAS_DIR/mssql/Remove
script d'annulation d'installation pour l'agent pmdamssql
$PCP_LOG_DIR/pmcd/mssql.log
fichier journal par défaut pour les messages de l'agent pmdamssql

Notez que la valeur habituelle/par défaut pour $PCP_PMDAS_DIR est /var/lib/pcp/pmdas et la valeur par défaut pour $PCP_LOG_DIR est /var/log/pcp, mais ces paramètres dépendent de la plateforme.

ENVIRONNEMENT PCP

Les variables d'environnement portant le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).
