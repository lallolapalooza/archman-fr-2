PMGENMAP(1) Manuel des commandes générales PMGENMAP(1)

NOM

pmgenmap - génère du code C pour simplifier la gestion des métriques de performance

SYNOPIS

pmgenmap [fichier_entree]

DESCRIPTION

À partir d'une ou plusieurs listes de noms de métriques dans fichier_entree ou sur l'entrée standard, pmgenmap génère des déclarations C et des macros cpp(1) adaptées à une utilisation dans toute l'interface de programmation des métriques de performance (PMAPI) sur la sortie standard.

Les déclarations produites par pmgenmap simplifient le codage des applications clientes utilisant la PMAPI.

L'entrée doit consister en une ou plusieurs listes de noms de métriques de la forme

nomliste {
    nommetrique1 nomsymbole1
    nommetrique2 nomsymbole2
    ...
}

qui généreront des déclarations C et cpp(1) de la forme

char *nomliste[] = {
#define nomsymbole1 0
    "nommetrique1",
#define nomsymbole2 1
    "nommetrique2",
    ...
};

Les déclarations de tableaux produites sont adaptées comme paramètres pour pmLookupName(3) et les constantes définies par #define peuvent être utilisées pour indexer les vsets dans la structure pmResult retournée par un appel à pmFetch(3).

Évidemment, nomliste doit respecter les règles de nommage des identificateurs C, chaque nomsymbole doit respecter les règles de nommage des macros cpp(1), et chaque nommetrique est censé être un nom de métrique de performance valide (voir PMNS(5) pour plus de détails).

L'entrée peut inclure des lignes de commentaires de style sh, c'est-à-dire avec un caractère `#' comme premier caractère non blanc de la ligne, et celles-ci sont traduites en sortie en commentaires C sur une ou plusieurs lignes de style K&R. Par exemple, l'entrée :

# bloc de commentaires multi-lignes en tête
# groupe d'initialisation
foo {
        a.b.c   ONE
        d.e.f.g TWO
        # bloc embarqué de commentaires multi-lignes
        # et texte de remplissage ennuyeux
        xx.yy.zz        THREE
}
# commentaire de fin sur une seule ligne

Produit la sortie suivante :

/*
 * bloc de commentaires multi-lignes en tête
 * groupe d'initialisation
 */
char *foo[] = {
#define ONE 0
        "a.b.c",
#define TWO 1
        "d.e.f.g",
/*
 * bloc embarqué de commentaires multi-lignes
 * et texte de remplissage ennuyeux
 */
#define THREE 2
        "xx.yy.zz",
};
/* commentaire de fin sur une seule ligne */

EXEMPLES

Pour plus de concision, nous avons supprimé le code de gestion d'erreurs et supposé que les métriques choisies n'avaient pas de valeurs multiples.

Le fichier d'entrée

mystats {
    kernel.percpu.cpu.idle     IDLE
    kernel.percpu.cpu.sys      SYS
    kernel.percpu.cpu.user     USER
    hinv.ncpu                       NCPU
}

produit le code C suivant, adapté pour être #include-d

/*
 * Espace de noms des métriques de performance
 * Construit par pmgenmap à partir du fichier
 * mystats.metrics
 * le Mer 28 Déc 19:44:17 EST 1994
 *
 * Ne modifiez pas ce fichier !
 */
char *mystats[] = {
#define IDLE    0
        "kernel.percpu.cpu.idle",
#define SYS     1
        "kernel.percpu.cpu.sys",
#define USER    2
        "kernel.percpu.cpu.user",
#define NCPU    3
        "hinv.ncpu",
};

En utilisant le code généré par pmgenmap, nous sommes maintenant en mesure d'obtenir facilement les métriques du sous-système de collecte des métriques de performance (PMCS) comme suit :

#define MAX_PMID 4
    int         trip = 0;
    int         numpmid = sizeof(mystats)/sizeof(mystats[0]);
    double      duration;
    pmResult    *resp;
    pmResult    *prev;
    pmID        pmidlist[MAX_PMID];
    pmNewContext(PM_CONTEXT_HOST, "localhost");
    pmLookupName(numpmid, mystats, pmidlist);
    pmFetch(numpmid, pmidlist, &resp);
    printf("%d CPUs: %d usr   %d sys   %d   idle0,
           resp->vset[NCPU]->vlist[0].value.lval,
           resp->vset[USER]->vlist[0].value.lval,
           resp->vset[SYS]->vlist[0].value.lval,
           resp->vset[IDLE]->vlist[0].value.lval);

Certains appels pour assurer la portabilité ont été supprimés du code ci-dessus pour plus de clarté - l'exemple ci-dessus ne devrait pas être utilisé comme modèle de programmation. En particulier, les valeurs brutes des métriques ont été utilisées alors que pmLookupDesc(3) aurait dû être appelé pour déterminer la sémantique de chaque métrique.

Des exemples plus complets démontrant l'utilisation de pmgenmap et qui peuvent servir de base au développement de programmes sont inclus dans les démos PCP, par exemple $PCP_DEMOS_DIR/pmclient.

ENVIRONNEMENT PCP

Les variables d'environnement commençant par PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).
