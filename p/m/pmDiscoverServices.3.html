PMDISCOVERSERVICES(3) Manuel des fonctions de bibliothèque PMDISCOVERSERVICES(3)

NOM

pmDiscoverServices, __pmDiscoverServicesWithOptions - découvrir les services PCP sur le réseau

C SYNTAXE

#include <pcp/pmapi.h>

int pmDiscoverServices(const char *service,
const char *mechanism, char ***urls);

#include <pcp/libpcp.h>

int __pmDiscoverServicesWithOptions(const char *service,
const char *mechanism, const char *optionsString, const volatile unsigned *flags, char ***urls);

cc ... -lpcp

AVERTISSEMENT

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API PCP garanties de rester stables entre les versions, et elles pourraient ne pas fonctionner, ou fournir une sémantique différente à l'avenir.

DESCRIPTION

Étant donné un nom de service PCP, tel qu'identifié par service, et en utilisant le type de découverte optionnellement spécifié dans mechanism, pmDiscoverServices retourne, via urls, une liste d'URL représentant les services découverts sur le réseau.

La fonction interne __pmDiscoverServicesWithOptions effectue la même fonction et ajoute des arguments pour les options globales et un mécanisme pour interrompre le processus de découverte.

L'utilitaire pmfind(1) fournit un accès en ligne de commande à ces deux interfaces.

Appeler

pmDiscoverServices(service, mechanism, urls)

est équivalent à appeler

__pmDiscoverServicesWithOptions(service, mechanism, NULL, NULL, urls);

service spécifie le service PCP à découvrir. Les services actuellement supportés sont PM_SERVER_SERVICE_SPEC et PM_SERVER_PROXY_SPEC qui recherchent respectivement les serveurs pmcd(1) et pmproxy(1).

mechanism spécifie le style de découverte à utiliser.

Les mécanismes actuellement supportés sont :

avahi
Ceci recherche les services qui diffusent en utilisant mDNS via avahi-daemon(8). Un suffixe optionnel ",timeout=N" peut être ajouté pour spécifier le délai de découverte en multiples décimaux d'une seconde. Le délai par défaut est de 0.5 seconde, qui peut être outrepassé par la variable d'environnement AVAHI_DISCOVERY_TIMEOUT, également spécifiée en multiples décimaux d'une seconde. Si les deux sont spécifiés, alors la valeur spécifiée dans la variable d'environnement a la priorité.
probe=<adresse-réseau>/<bits-masque>
Sonde activement le sous-réseau donné pour le(s) service(s) PCP demandé(s). <adresse-réseau> est une adresse réseau inet ou ipv6 et <bits-masque> est le nombre de bits utilisés pour définir le sous-réseau. Par exemple, 192.168.1.0/24 définit un sous-réseau de 8 bits composé des adresses 192.168.1.0 à 192.168.1.255. Un suffixe optionnel ",maxThreads=N" peut être ajouté pour limiter le nombre de threads utilisés lors de la sonde. La valeur par défaut est la valeur de __FD_SETSIZE (qui est typiquement 1024) ou le nombre d'adresses dans le sous-réseau, le moindre des deux. Un suffixe optionnel ",timeout=N" peut être ajouté pour spécifier le délai de chaque tentative de connexion en multiples décimaux d'une seconde. La valeur par défaut est de 0.02 seconde (20 millisecondes).
shell
Sonde la liste d'adresses fournies par des scripts pour le(s) service(s) PCP demandé(s). Plusieurs paramètres optionnels, séparés par des virgules, peuvent également être fournis. Premièrement, l'option "path=DIR" spécifie le répertoire où se trouvent les commandes comme pcp-kube-pods(1) (par défaut $PCP_BINADM_DIR/discover/). Ce réglage peut être restreint à une commande individuelle à l'aide de l'option command=CMD, mais par défaut, toutes les commandes disponibles du path sont utilisées. L'option "maxThreads=N" limite le nombre de threads utilisés lors de la sonde. La valeur par défaut est la valeur de __FD_SETSIZE (qui est typiquement 1024) ou le nombre d'adresses retournées par les scripts, le moindre des deux. L'option "timeout=N" peut être ajoutée pour limiter la durée d'attente pour chaque tentative de connexion. N est un nombre décimal spécifiant le nombre de secondes d'attente. La valeur par défaut est de 0.02 seconde (20 millisecondes).

mechanism peut également être NULL, ce qui signifie d'utiliser tous les mécanismes de découverte disponibles.

Pour __pmDiscoverServicesWithOptions, optionsString spécifie les options globales à appliquer au processus de découverte. Les options sont séparées par des virgules et peuvent être une ou plusieurs des suivantes :

resolve
Ceci demande que la résolution DNS soit tentée pour les adresses de tous les services découverts.
timeout=N
Ceci spécifie une période de temps après laquelle le processus de découverte sera interrompu. N est un nombre décimal représentant le nombre de secondes avant l'expiration du délai.

optionsString peut également être NULL, ce qui signifie qu'aucune option globale n'est spécifiée.

Pour __pmDiscoverServicesWithOptions, flags spécifie un pointeur vers un objet de type unsigned qui est un masque de bits d'options/indicateurs de statut pour le processus de découverte. Les indicateurs supportés sont :

PM_SERVICE_DISCOVERY_RESOLVE
Spécifier cet indicateur est équivalent à spécifier resolve dans optionsString
PM_SERVICE_DISCOVERY_INTERRUPTED
Cet indicateur doit être désactivé lors de l'appel à __pmDiscoverServicesWithOptions mais peut être activé de manière asynchrone (par un gestionnaire d'interruption, par exemple) afin d'interrompre le processus de découverte de services.

flags peut également être NULL, ce qui indique qu'aucun indicateur n'est défini.

pmDiscoverServices et __pmDiscoverServicesWithOptions retourneront le nombre de services découverts, sinon une valeur inférieure à zéro en cas d'erreur. La valeur zéro indique qu'aucun service n'a été découvert.

La liste résultante de pointeurs, urls, et les valeurs (les URL) auxquelles les pointeurs font référence auront été alloués par pmDiscoverServices ou __pmDiscoverServicesWithOptions avec un unique appel à malloc(3), et il est de la responsabilité de l'appelant de pmDiscoverServices ou __pmDiscoverServicesWithOptions de libérer (free(urls)) l'espace lorsqu'il n'est plus requis.

Lorsqu'une erreur se produit, ou qu'aucun service n'est découvert, urls est indéfini (aucun espace n'aura été alloué, et par conséquent appeler free(3) est une très mauvaise idée).

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, tel que décrit dans pcp.conf(5). Les valeurs de ces variables peuvent être obtenues par programme en utilisant la fonction pmGetConfig(3).
