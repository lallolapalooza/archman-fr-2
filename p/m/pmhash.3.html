PMHASH(3) Manuel des fonctions de bibliothèque PMHASH(3)

NOM

__pmHashInit, __pmHashPreAlloc, __pmHashAdd, __pmHashDel, __pmHashSearch, __pmHashWalk, __pmHashWalkCB, __pmHashFree, __pmHashClear - routines de hachage à usage général

SYNOPSIS EN C

#include <pcp/pmapi.h>
#include <pcp/libpcp.h>

void __pmHashInit(__pmHashCtl *hcp);
int __pmHashPreAlloc(int hsize, __pmHashCtl *hcp);
int __pmHashAdd(unsigned int key,
void *data, __pmHashCtl *hcp);
int __pmHashDel(unsigned int key,
void *data, __pmHashCtl *hcp);
__pmHashNode *__pmHashSearch(unsigned int key,
__pmHashCtl *hcp);
__pmHashNode *__pmHashWalk(__pmHashCtl *hcp,
__pmHashWalkState state);
void __pmHashWalkCB(__pmHashWalkCallback cb,
void *cdata, const __pmHashCtl *hcp);
void __pmHashFree(__pmHashCtl *hcp);
void __pmHashClear(__pmHashCtl *hcp);

cc ... -lpcp

CAVEAT

Cette documentation est destinée à l'usage interne des développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API de PCP dont la stabilité est garantie d'une version à l'autre, et il se peut qu'à l'avenir elles ne fonctionnent plus ou qu'elles aient une sémantique différente.

DESCRIPTION

Le groupe de routines __pmHash implémente une suite généralisée de services de hachage linéaire basés sur une clé de type unsigned int et des données qui sont un pointeur opaque vers les informations que l'appelant souhaite associer à la clé.

Le type de données de la clé la rend adaptée à l'accès par hachage basé sur l'identifiant de métrique (pmID), le numéro de domaine d'instance (pmInDom) ou les identifiants d'instance internes au sein d'un domaine d'instance.

Plusieurs tables de hachage peuvent exister, chacune identifiée par une structure de contrôle de hachage (__pmHashCtl) hcp déclarée par l'appelant et initialisée en appelant __pmHashInit. Référez-vous aux sections HASH CONTROL et HASH NODE ci-dessous pour plus d'informations sur les structures de données internes de la table de hachage.

La table de hachage est initialement vide mais grandit dynamiquement par doublement approximatif de sa taille à mesure que des entrées sont ajoutées, ce qui peut entraîner une certaine surcharge organisationnelle lors de la re-liaison des chaînes de hachage lorsque la table de hachage grandit. Cette surcharge peut être évitée en appelant optionnellement __pmHashPreAlloc avec une taille initiale de table de hachage de hsize entrées, mais cela doit être fait après avoir appelé __pmHashInit et avant que toute entrée ne soit ajoutée.

Les entrées sont ajoutées à une table de hachage en appelant __pmHashAdd. Les données opaques sont typiquement un pointeur vers un bloc d'informations supplémentaires à associer à la clé, bien qu'il puisse être NULL s'il n'y a pas d'informations supplémentaires requises ou disponibles actuellement.

Bien que généralement non requis, des valeurs de clé dupliquées peuvent être stockées dans une table de hachage et __pmHashAdd les ajoutera silencieusement (probablement avec un pointeur data différent). Si l'unicité des clés est requise, il est nécessaire d'appeler __pmHashSearch d'abord pour déterminer qu'il n'y a pas d'entrée pour la clé, avant d'appeler __pmHashAdd.

Les entrées peuvent être supprimées d'une table de hachage en utilisant __pmHashDel où l'entrée à supprimer est la première avec une clé et un pointeur data correspondants. Voir la note ci-dessus sur les clés dupliquées pour comprendre pourquoi le paramètre data est nécessaire.

__pmHashSearch trouve la première entrée avec une clé correspondante. Si des clés dupliquées sont stockées, l'appelant devra suivre la chaîne hp->next à la recherche d'entrées supplémentaires avec la même clé. Référez-vous aux sections HASH CONTROL et HASH NODE ci-dessous pour plus d'informations sur les structures de données internes de la table de hachage.

__pmHashWalk fournit une interface avec état pour parcourir chaque nœud de la table de hachage. Elle est d'abord appelée avec state défini à PM_HASH_WALK_START pour récupérer la première entrée, puis appelée de manière répétée avec state défini à PM_HASH_WALK_NEXT pour récupérer les entrées suivantes.

__pmHashWalkCB fournit une méthode alternative pour parcourir la table de hachage. La fonction de rappel cb est appelée avec deux arguments, un pointeur vers l'entrée de hachage actuelle et cdata (ce dernier permet à l'appelant de passer des informations auxiliaires à la fonction de rappel, mais peut être NULL si ce n'est pas nécessaire). La fonction de rappel doit retourner l'une des valeurs __pmHashWalkState suivantes :

PM_HASH_WALK_NEXT
continuer le parcours
PM_HASH_WALK_STOP
terminer le parcours
PM_HASH_DELETE_NEXT
supprimer le nœud actuel de la table de hachage et continuer le parcours
PM_HASH_DELETE_STOP
supprimer le nœud actuel de la table de hachage et terminer le parcours

__pmHashFree libérera tout espace de stockage associé à la table de hachage et la remettra dans l'état vide, comme après l'appel à __pmHashInit. Mais __pmHashFree ne peut pas libérer le stockage attaché via l'argument data aux appels __pmHashAdd. La manière la plus appropriée de nettoyer la table de hachage est donc de parcourir d'abord la table en libérant toutes les données, puis d'appeler __pmHashFree comme le montre l'exemple ci-dessous.


__pmHashCtl	hash;
__pmHashWalkState
mycallback(const __pmHashNode *hp, void *cp)
{
    (void)cp;
    if (hp->data) {
	/*
	 * free() si alloué avec malloc() ou une méthode spécifique
	 * aux données, par ex. __pmFreeProfile()
	 */
        free(hp->data);
    }
    return PM_HASH_WALK_NEXT;
}
...
    __pmHashWalkCB(mycallback, NULL, &hash);
    __pmHashFree(&hash);
}

__pmHashClear remet la table de hachage dans l'état vide, comme après l'appel à __pmHashInit. Attention, __pmHashClear ne libère aucun espace de stockage associé aux entrées de hachage, et risque donc de fuir de la mémoire. Cependant, l'exemple suivant montre comment libérer toute la mémoire en un seul parcours de la table de hachage avec __pmHashWalkCB avant d'appeler __pmHashClear.


__pmHashCtl	hash;
__pmHashWalkState
mycallback(const __pmHashNode *hp, void *cp)
{
    (void)cp;
    if (hp->data) {
	/*
	 * free() si alloué avec malloc() ou une méthode spécifique
	 * aux données, par ex. __pmFreeProfile()
	 */
        free(hp->data);
    }
    /*
     * par rapport à l'exemple précédent, cette différence
     * est importante et libère chaque nœud de hachage
     */
    return PM_HASH_DELETE_NEXT;
}
...
    __pmHashWalkCB(mycallback, NULL, &hash);
    __pmHashClear(&hash);
}

CONTROLE DE HASHAGE

La structure __pmHashCtl est définie comme suit :


typedef struct __pmHashCtl {
    int                 nodes;
    int                 hsize;
    __pmHashNode        **hash;
    __pmHashNode        *next;
    unsigned int        index;
} __pmHashCtl;

La table de hachage hash contient hsize entrées, chacune pouvant pointer vers une liste chaînée de nœuds de hachage. Le nombre total de nœuds de hachage est conservé dans nodes. Les champs index et next sont utilisés pour maintenir l'état pendant les opérations de parcours de la table de hachage.

NOEUD DE HASHAGE

La structure __pmHashNode est définie comme suit :


typedef struct __pmHashNode {
    struct __pmHashNode *next;
    unsigned int        key;
    void                *data;
} __pmHashNode;

Chaque nœud contient la clé, le pointeur opaque (data) et next implémente la liste chaînée des nœuds de hachage à partir de chaque entrée dans la table de hachage.

pmhash, __pmHashAdd, __pmHashDel, __pmHashSearch, __pmHashWalk - manipulate hash tables.

CAVEAT

The hash table implementation is not thread-safe.

DESCRIPTION

The hash table functions provide a generic mechanism for storing and retrieving arbitrary key-value pairs. A hash table is created implicitly when pmhash(3) is first called to search or add an entry.

The table is implemented as a doubly linked list of hash buckets, where each bucket contains a list of key-value pairs. The key must be a non-null pointer, and the value can be any pointer, including NULL.

The key is hashed using the standard C hash(3) function. If a key already exists, the associated value is updated.

The initial size of the hash table is determined dynamically. Resizing occurs automatically when the load factor is exceeded.

The pmhash(3) function is used to retrieve the hash table handle. It takes a pointer to the hash table as input and returns a pointer to the hash table structure. This handle should be passed to other hash table functions.

HASH CONTROL

The hash table is controlled by a struct pmHash. This structure contains information about the hash table, such as the number of entries, the current size, and pointers to the first and last buckets.

HASH NODE

Each entry in the hash table is represented by a struct pmHashNode. This structure contains the key, the value, and pointers to the next and previous nodes in the bucket's linked list.

DIAGNOSTICS AND RETURN VALUES

The pmhash(3) function returns a pointer to the hash table structure. If the hash table is not found, it is created and a pointer to the new hash table is returned.

The return value of pmhash(3) can be turned into an error message by calling pmErrStr(3).

__pmHashAdd returns 1 for success, else a value < 0 to indicate an error, probably from calloc(3).

Return values from __pmHashDel are 0 if no matching entry is found, else 1 if a matching entry was deleted.

__pmHashSearch returns with a pointer to the entry if found, else NULL.

__pmHashWalk returns with a pointer to the next entry if found, else NULL when all entries have been traversed.

SEE ALSO

PMAPI(3), calloc(3), free(3) and pmErrStr(3).

L'implémentation de la table de hachage n'est pas thread-safe.

DESCRIPTION

Les fonctions de table de hachage fournissent un mécanisme générique pour stocker et récupérer des paires clé-valeur arbitraires. Une table de hachage est créée implicitement lorsque pmhash(3) est appelée pour la première fois pour rechercher ou ajouter une entrée.

La table est implémentée comme une liste doublement chaînée de compartiments de hachage, où chaque compartiment contient une liste de paires clé-valeur. La clé doit être un pointeur non nul, et la valeur peut être n'importe quel pointeur, y compris NULL.

La clé est hachée en utilisant la fonction C standard hash(3). Si une clé existe déjà, la valeur associée est mise à jour.

La taille initiale de la table de hachage est déterminée dynamiquement. Le redimensionnement se produit automatiquement lorsque le facteur de charge est dépassé.

La fonction pmhash(3) est utilisée pour récupérer le handle de la table de hachage. Elle prend un pointeur vers la table de hachage en entrée et retourne un pointeur vers la structure de la table de hachage. Ce handle doit être passé aux autres fonctions de table de hachage.

CONTRÔLE DU HACHAGE

La table de hachage est contrôlée par une struct pmHash. Cette structure contient des informations sur la table de hachage, telles que le nombre d'entrées, la taille actuelle et les pointeurs vers les premiers et derniers compartiments.

NOEUD DE HACHAGE

Chaque entrée de la table de hachage est représentée par une struct pmHashNode. Cette structure contient la clé, la valeur et les pointeurs vers les nœuds suivant et précédent dans la liste chaînée du compartiment.

DIAGNOSTICS ET VALEURS DE RETOUR

La fonction pmhash(3) retourne un pointeur vers la structure de la table de hachage. Si la table de hachage n'est pas trouvée, elle est créée et un pointeur vers la nouvelle table de hachage est retourné.

La valeur de retour de pmhash(3) peut être transformée en un message d'erreur en appelant pmErrStr(3).

__pmHashAdd retourne 1 en cas de succès, sinon une valeur < 0 pour indiquer une erreur, probablement de la part de calloc(3).

Les valeurs de retour de __pmHashDel sont 0 si aucune entrée correspondante n'est trouvée, sinon 1 si une entrée correspondante a été supprimée.

__pmHashSearch retourne avec un pointeur vers l'entrée si elle est trouvée, sinon NULL.

__pmHashWalk retourne avec un pointeur vers l'entrée suivante si elle est trouvée, sinon NULL lorsque toutes les entrées ont été parcourues.

VOIR AUSSI

PMAPI(3), calloc(3), free(3) et pmErrStr(3).
