PMVAL(1) Manuel des commandes générales PMVAL(1)

NOM

pmval, pmevent - Vidage de valeurs arbitraires de métriques de performance

SYNTAXE

pmval [-dgLrvVXz?] [-a archive] [-A align] [--container=nom] [-D debug] [--derived=fichier] [-f N] [-h hote] [-i instances] [-K spec] [-n fichier-pmns] [-O decalage] [-p port] [-s echantillons] [-S heure-debut] [-t intervalle] [-T heure-fin] [-U archive] [-w largeur] [-x motif] [-Z fuseau-horaire] nom-metrique

pmevent ...

DESCRIPTION

pmval affiche les valeurs actuelles ou archivées de la métrique de performance sélectionnée. La métrique d'intérêt est nommée dans l'argument nom-metrique, sous réserve de qualification d'instance avec le drapeau -i comme décrit ci-dessous.

Sauf indication contraire sur un autre hôte par l'option -h, ou sur un ensemble d'archives par les options -a ou -U, pmval contactera le démon collecteur de métriques de performance (PMCD) sur l'hôte local pour obtenir les informations requises.

L'argument nom-metrique peut également être donné dans la syntaxe de spécification de métrique, comme décrit dans PCPIntro(1), où la source, la métrique et l'instance peuvent toutes être incluses dans nom-metrique, par exemple, thathost:kernel.all.load["1 minute"]. Lorsque ce format est utilisé, aucune des options -h, -a ou -U ne peut être spécifiée.

Lors de l'utilisation de la syntaxe de spécification de métrique, le nom d'hôte @ est traité spécialement et amène pmval à utiliser un contexte local pour collecter les métriques à partir des PMDA locaux sans PMCD. Seules certaines métriques sont disponibles dans ce mode.

Lors du traitement d'un ensemble d'archives, pmval peut renoncer à son propre contrôle temporel et fonctionner sous le contrôle d'un processus pmtime(1) qui utilise une boîte de dialogue graphique pour fournir le contrôle temporel. Dans ce cas, soit l'option -g doit être utilisée pour démarrer pmval en tant que client unique d'une nouvelle instance de pmtime(1), soit -p doit être utilisé pour connecter pmval à une instance existante de pmtime(1) via le canal IPC identifié par l'argument port.

Les options -S, -T, -O et -A peuvent être utilisées pour définir une fenêtre temporelle afin de restreindre les échantillons récupérés, définir une origine initiale dans la fenêtre temporelle, ou spécifier un alignement « naturel » des temps d'échantillon ; référez-vous à PCPIntro(1) pour une description complète de ces options.

La sortie de pmval est dirigée vers la sortie standard. Les symboles suivants peuvent occasionnellement apparaître, à la place d'une valeur de métrique, dans la sortie de pmval : Un point d'interrogation (?) indique qu'une valeur n'est plus disponible pour cette instance de métrique. Un point d'exclamation (!) indique qu'un compteur 64 bits a dépassé sa capacité pendant l'échantillon.

pmevent est un alias pour pmval.

OPTIONS

Les options de ligne de commande disponibles sont :

-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives. Voir aussi -U.
-A align, --align=align
Force le premier échantillon à être aligné sur la limite d'une unité de temps naturelle align. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe de align.
--container=conteneur
Spécifie un conteneur individuel à interroger.
-d, --delay
Lors de la relecture à partir d'une archive, cette option demande que le délai temps réel prévalant soit appliqué entre les échantillons (voir -t) pour effectuer une pause, plutôt que le comportement par défaut de relecture à pleine vitesse.
--derived=fichier
Charge les définitions de métriques dérivées du fichier.
-f précision, --precision=précision
Les nombres sont rapportés en notation « virgule fixe », plutôt qu'en notation scientifique par défaut, en utilisant précision chiffres pour la précision. Chaque nombre sera jusqu'à la largeur de colonne déterminée par les heuristiques par défaut, sinon par l'option -w si spécifiée, et inclura précision chiffres après le point décimal. Ainsi, les options -f 3 -w 8 produiraient des nombres de la forme 9999.999. Une valeur de zéro pour précision omet le point décimal et tout chiffre fractionnaire.
-g, --guimode
Démarre pmval en tant que client unique d'un nouveau processus serveur pmtime(1) pour la relecture des données de performance archivées en utilisant l'interface graphique de pmtime(1).
-h hote, --host=hote
Récupère les métriques de performance de pmcd(1) sur l'hôte hote, plutôt que depuis localhost par défaut.
-i instances, --instances=instances
Spécifie une liste d'un ou plusieurs noms d'instances pour la métrique de performance sélectionnée - seules ces instances seront récupérées et rapportées (par défaut, toutes les instances sont rapportées). La liste doit être un seul argument, avec les éléments de la liste séparés par des virgules et/ou des espaces blancs.

Le nom d'instance peut être entouré de guillemets simples (') ou doubles (") pour les cas où le nom d'instance contient des espaces blancs ou des virgules.

Plusieurs options -i sont autorisées comme moyen alternatif de spécifier plus d'une instance d'intérêt.

Par exemple, les commandes suivantes sont équivalentes : 

$ pmval -i "'1 minute','5 minute'" kernel.all.load
$ pmval -i '"1 minute","5 minute"' kernel.all.load
$ pmval -i "'1 minute' '5 minute'" kernel.all.load
$ pmval -i "'1 minute'" -i "'5 minute'" kernel.all.load
$ pmval 'localhost:kernel.all.load["1 minute","5 minute"]'


-K spec, --spec-local=spec
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui devraient être rendus accessibles. L'argument spec est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plusieurs options -K peuvent être utilisées.
-L, --local-PMDA
Utilise un contexte local pour collecter les métriques à partir des PMDA DSO sur l'hôte local sans PMCD. Voir aussi -K.
-n fichier-pmns, --namespace=fichier-pmns
Charge un espace de noms de métriques de performance (PMNS) alternatif (PMNS(5)) depuis le fichier fichier-pmns.
-O origine, --origin=origine
Lors du rapport des métriques archivées, commence le rapport à origine dans la fenêtre temporelle (voir -S et -T). Référez-vous à PCPIntro(1) pour une description complète de la syntaxe de origine.
-p port, --guiport=port
Connecte pmval à une instance de processus de contrôle temporel pmtime(1) existante via le canal IPC identifié par l'argument port. Cette option est normalement utilisée uniquement par d'autres outils, par exemple pmchart(1), lorsqu'ils lancent pmval avec un contrôle temporel synchronisé.
-r, --raw
Affiche les valeurs brutes pour les métriques de compteurs cumulatifs. Normalement, les métriques de compteurs cumulatifs sont converties en taux. Par exemple, les transferts de disque sont rapportés comme nombre de transferts de disque par secon

-s echantillons, --samples=echantillons
L'argument echantillons définit le nombre d'échantillons à récupérer et à rapporter. Si echantillons est 0 ou si -s n'est pas spécifié, pmval échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive).
-S heuredebut, --start=heuredebut
Lors du rapport des métriques archivées, le rapport sera limité aux enregistrements journalisés à partir de ou après heuredebut. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe de heuredebut.
-t intervalle, --interval=intervalle
Définir l'intervalle de rapport à autre chose que la seconde par défaut. L'argument intervalle suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes).
-T heurefin, --finish=heurefin
Lors du rapport des métriques archivées, le rapport sera limité aux enregistrements journalisés avant ou à heurefin. Référez-vous à PCPIntro(1) pour une description complète de la syntaxe de heurefin.
-U archive, --nointerp=archive
Les valeurs des métriques de performance sont récupérées de l'archive de Performance Co-Pilot (PCP) archive. L'argument est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives. Cependant, contrairement à -a, chaque valeur enregistrée dans l'archive pour la métrique et les instances sélectionnées est rapportée (donc aucun mode d'interpolation, et l'intervalle d'échantillonnage (option -t) est ignoré). Voir aussi -a.

Au plus une des options -a et -U peut être spécifiée.

-v, --verbose
Activer le mode verbeux.
-V, --version
Afficher le numéro de version et quitter.
-w largeur, --width=largeur
Définir la largeur de chaque colonne de sortie à largeur colonnes. Si non spécifié, les colonnes sont suffisamment larges pour accueillir la plus grande valeur du type imprimé.
-x motif, --filter=motif
Le motif donné est envoyé à l'agent du domaine de métriques de performance pour le nomdemetrique demandé avant que toute valeur ne soit demandée. Ceci sert deux objectifs. Premièrement, il fournit un mécanisme de filtrage d'événements côté serveur qui est personnalisable pour des flux d'événements individuels. De plus, certains agents du domaine de métriques de performance utilisent également le mécanisme de stockage PMCD pour fournir un modèle de sécurité de base (par exemple, pour des fichiers journaux sensibles, seul un hôte client ayant un accès pmStore(3) pourrait accéder au flux d'événements).

Comme motif peut être traité par regcomp(3), ce doit être une chaîne non vide. Utilisez . (point) pour un motif "tout correspondre".

-X, --timestamp
Lors de la relecture à partir d'une archive, cette option demande que l'horodatage soit rapporté avec des informations de date supplémentaires et une précision accrue (microsecondes avec un seul -X, nanosecondes avec un -X supplémentaire), par exemple Sam Mai 22 20:32:20.971633 2021 au lieu du format par défaut, par exemple 20:32:20.971.
-z, --hostzone
Utiliser le fuseau horaire local de l'hôte source des métriques de performance, tel qu'identifié par les options -h, -a ou -U. Par défaut, on utilise le fuseau horaire de l'hôte local.
-Z fuseauhoraire, --timezone=fuseauhoraire
Utiliser le fuseauhoraire pour la date et l'heure. Fuseauhoraire est au format de la variable d'environnement TZ telle que décrite dans environ(7).
-?, --help
Afficher le message d'utilisation et quitter.

MISES EN GARDE

Par défaut, pmval tente d'afficher les valeurs numériques non entières d'une manière qui ne déforme pas la précision inhérente (rarement plus de 4 chiffres significatifs), et essaie de maintenir un format tabulaire dans la sortie. Ces objectifs sont parfois en conflit.

En l'absence de l'option -f (décrite ci-dessus), le tableau suivant décrit les formats utilisés pour différentes plages de valeurs numériques pour toute métrique de type PM_TYPE_FLOAT ou PM_TYPE_DOUBLE, ou toute métrique ayant la sémantique d'un compteur (pour laquelle pmval rapporte la valeur convertie du taux) :

Format Plage de valeurs
! Aucune valeur disponible
9.999E-99 < 0.1
0.0    0
9.9999 > 0 et <= 0.9999
9.999  > 0.9999 et < 9.999
99.99   > 9.999 et < 99.99
999.9    > 99.99 et < 999.9
9999.     > 999.9 et < 9999
9.999E+99 > 9999

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, tel que décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à fournir des indications aux développeurs plutôt qu'aux utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmval sont les suivantes :

Option Description
appl0 positionnement initial de la chronologie lors de l'utilisation de -a
