NOM

pmdapipe - agent de domaine de métriques de performance (PMDA) pour la capture de sortie de commande

SYNOPIS

$PCP_PMDAS_DIR/pipe/pmdapipe [-c fichier_config] [-D debug] [-d domaine] [-l fichier_log] [-m mémoire]

DESCRIPTION

pmdapipe est un agent de domaine de métriques de performance (PMDA) configurable pour la surveillance de la sortie de commande. Il peut être considéré comme analogue à un shell restreint, où des options peuvent être passées à des commandes prédéfinies, et chaque ligne de leur sortie est convertie en un événement de performance. Ces événements peuvent être consommés par des outils clients comme pmval(1).

Le PMDA pipe exporte à la fois des métriques de type événement reflétant des enregistrements d'événements horodatés pour la sortie de commande orientée texte, ainsi que des métriques de type échantillon plus orthodoxes telles que les comptes d'événements et les valeurs de débit.

Le PMDA est configuré via un fichier_config qui contient une ligne pour chaque processus dont la sortie peut être capturée, comme décrit dans la section « CONFIGURATION » ci-dessous.

Une brève description des options de ligne de commande de pmdapipe suit :

-c
spécifie un fichier de configuration alternatif pour le PMDA. Par défaut, un fichier nommé $PCP_PMDAS_DIR/pipe/pipe.conf et tous les fichiers situés sous le répertoire $PCP_SYSCONF_DIR/pipe.conf.d/ sont utilisés.
-d
Il est absolument crucial que le numéro de domaine des métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire que le domaine doit être différent pour chaque PMDA sur le même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé pipe.log est écrit dans le répertoire courant de pmcd(1) lorsque pmdapipe est lancé, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est écrite sur la sortie d'erreur standard.
-m
Limite la mémoire physique utilisée par le PMDA pour mettre en mémoire tampon les enregistrements d'événements à maxsize octets. Lorsque les événements de journal arrivent au PMDA, ils doivent être mis en mémoire tampon jusqu'à ce que les outils clients individuels demandent le lot suivant depuis leur lot précédent d'événements. La limite maximale par défaut est de 2 mégaoctets.

CONFIGURATION

L'ensemble des commandes de pipe autorisées est configuré par des fichiers texte simples. Le format est une seule ligne pour chaque commande suivie d'une section de contrôle d'accès optionnelle.

Les lignes vides et les commentaires sont autorisés (voire encouragés) dans le fichier de configuration. Un commentaire commence par un caractère « # » et se termine à la fin de la ligne.

Chaque ligne de configuration de commande est de la forme :

instance nom_utilisateur commande options

Où,

instance
est une chaîne identifiant la commande pipe, également exportée comme identifiant d'instance de métrique.
nom_utilisateur
est le nom du compte utilisateur sous lequel la commande doit être exécutée (par exemple, « root »)
commande
est le chemin vers le binaire qui sera exécuté pour générer la sortie pipée
options
est une liste facultative de paramètres séparés par des espaces à passer à la commande
Cette liste d'options peut contenir des paramètres numériques préfixés par le signe dollar, et ceux-ci seront substitués par des valeurs fournies par l'utilisateur au moment où la commande est exécutée (similaire à la substitution de paramètres shell).

Les paramètres sont passés sous forme d'une seule chaîne séparée par des espaces ou des virgules à la métrique pipe.firehose, en utilisant l'interface pmStore (3). La commande pmval fournit un accès de stockage via son option -x. Les paramètres fournis par l'utilisateur sont limités aux caractères alphanumériques.

La section de contrôle d'accès du fichier doit commencer par une ligne de la forme :

[access]

Les espaces blancs en tête et en fin de ligne peuvent apparaître autour et à l'intérieur des crochets, et la casse du mot-clé access est ignorée. Aucun autre texte ne doit apparaître sur la ligne, sauf un commentaire final.

Après cette ligne, le reste du fichier de configuration doit contenir des lignes qui autorisent ou interdisent l'utilisation des commandes par des utilisateurs ou groupes particuliers.

Les noms d'utilisateurs et de groupes seront vérifiés à l'aide des fichiers locaux /etc/passwd et /etc/groups (ou d'un service d'annuaire alternatif), en utilisant les routines getpwent(3) et getgrent(3).

L'accès pour les utilisateurs ou les groupes est autorisé ou refusé en spécifiant des instructions de la forme :

allow user nom_utilisateur : instance
disallow user nom_utilisateur : instance
allow group nom_groupe : instance
disallow group nom_groupe : instance

Les noms d'utilisateur et de groupe seront vérifiés à l'aide des fichiers locaux /etc/passwd et /etc/groups (ou d'un service d'annuaire alternatif), en utilisant les routines getpwent(3) et getgrent(3).

Le caractère générique « * » peut être utilisé pour faire référence à tous les noms d'instance.

INSTALLATION

Si vous souhaitez accéder aux noms, au texte d'aide et aux valeurs des métriques de performance de pipe, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/pipe
# ./Install

Ceci est un processus d'installation interactif qui demande chaque chemin de fichier journal à surveiller (ou commande à exécuter), un nom d'instance de métrique pour l'identifier, et si l'accès doit être restreint (voir l'option -x de pmval(1) pour plus de détails).

Si vous souhaitez annuler l'installation, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/pipe
# ./Remove

pmdapipe est lancé par pmcd et ne doit jamais être exécuté directement. Les scripts Install et Remove informent pmcd lorsque l'agent est installé ou supprimé.

EXEMPLES

Voici un exemple simple de configuration de pmdapipe et d'utilisation des métriques de pipe pour exécuter la commande btrace, par l'utilisateur bob :


bob> cat $PCP_PMDAS_DIR/pipe/pipe.conf
# instance      user      command
rw_syscalls     root      perf script rw-by-file $1
bdev_trace      root      btrace -w $1 /dev/$2
[access]
allow user bob : *;
allow user jane : bdev_trace;
allow group perf : rw_syscalls;
bob> pmval -i bdev_trace -x '5 sda' pipe.firehose
 8,2  5  1  0.000000000 25227  A  WS 734332384 + 24 <- (253,2) 734330336
 8,0  5  2  0.000000414 25227  A  WS 735358432 + 24 <- (8,2) 734332384
 8,0  5  3  0.000000756 25227  Q  WS 735358432 + 24 [qemu-kvm]
 [...5 secondes]
bob>

$PCP_PMDAS_DIR/pipe/help
fichier d'aide par défaut pour les métriques de pipe
$PCP_PMDAS_DIR/pipe/Install
script d'installation pour l'agent pmdapipe
$PCP_PMDAS_DIR/pipe/Remove
script d'annulation d'installation pour l'agent pmdapipe
$PCP_LOG_DIR/pmcd/pipe.log
fichier journal par défaut pour les messages d'erreur et autres informations de pmdapipe
$PCP_SYSCONF_DIR/pipe.conf.d
répertoire contenant des fichiers de configuration supplémentaires pour les métriques de pipe

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active l'affichage de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir la liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdapipe sont les suivantes :

Option Description
appl0 traitement et génération d'événements, interactions avec pmcd(1), gestion du contexte client, exécution de commandes
appl1 contrôles d'accès, diagnostics utilisateurs et groupes
appl2 gestion de configfile, diagnostics d'arguments de commande erronés, gestion de select(2)
