PMDAOVERHEAD(1) Manuel des commandes générales PMDAOVERHEAD(1)

NOM

pmdaoverhead - agent de domaine de métriques de performance (PMDA) exportant les métriques de consommation de ressources pour des groupes de processus

SYNOPHIS

$PCP_PMDAS_DIR/overhead/pmdaoverhead [-C] [-c config] [-D debug] [-d domain] [-l logfile] [-R interval]

DESCRIPTION

pmdaoverhead est un agent de domaine de métriques de performance (PMDA) configurable pour exporter la consommation de ressources pour des groupes de processus apparentés.

Les options de ligne de commande de pmdaoverhead sont :

-C
analyse le(s) fichier(s) de configuration et quitte après avoir signalé toute erreur.
-c
fichier(s) de configuration, config peut être un fichier ou un répertoire ; dans ce dernier cas, tous les fichiers contenus dans config sont supposés être des fichiers de configuration pour pmdaoverhead et ils seront tous traités.

Chaque fichier de configuration définit un ou plusieurs "groupes" de processus d'intérêt, en utilisant la syntaxe décrite dans la section "CONFIGURATION" ci-dessous.

Par défaut, tous les fichiers de configuration du répertoire $PCP_SYSCONF_DIR/overhead/conf.d/ sont utilisés.

-d
Il est absolument crucial que le numéro de domaine des métriques de performance domain spécifié ici soit unique et cohérent. C'est-à-dire, domain doit être différent pour chaque PMDA sur un même hôte, et le même numéro domain doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé overhead.log est écrit dans le répertoire courant de pmcd(1) lorsque pmdaoverhead est démarré, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est redirigée vers la sortie standard d'erreur.
-R
Le PMDA utilise un thread séparé pour scanner périodiquement tous les processus afin de déterminer quels processus sont considérés comme "intéressants" dans chaque groupe, et pour extraire la consommation de ressources de ces processus. L'intervalle (en secondes) détermine la fréquence de ce scan et de ce calcul de ressources, la valeur par défaut est de 60 (secondes).

CONFIGURATION

Chaque fichier de configuration définit un ou plusieurs "groupes" de processus. Le format du fichier est simple et suit les règles suivantes.

1.
Les lignes commençant par un dièse '#' sont traitées comme des commentaires. Plus généralement, sauf pour la clause pattern: décrite ci-dessous, tout texte entre un dièse et la fin de la ligne est traité comme un commentaire.
2.
Les espaces blancs (espaces ou tabulations ou sauts de ligne) sont nécessaires pour séparer les composants lexicaux. Les espaces et tabulations sont sinon ignorés. À part pour terminer les commentaires et le regex dans une clause pattern:, les sauts de ligne sont également ignorés.
3.
Chaque groupe est introduit par une clause group qui a la forme
group name { paramètres }
où name est un nom unique pour le groupe parmi tous les groupes dans les fichiers de configuration de pmdaoverhead. Comme name est intégré dans l'espace de noms des métriques de performance (PMNS), il doit suivre les règles pour les composants de noms de métriques comme décrit dans PMNS(5), c'est-à-dire commencer par un caractère alphabétique, suivi de zéro ou plusieurs caractères tirés des alphabets, des chiffres et du caractère de soulignement "_".
4.
Les paramètres doivent inclure une clause id: et une clause pattern:.
5.
Une clause id: a la forme
id: ident
où ident est un identifiant unique pour le groupe parmi tous les groupes dans les fichiers de configuration de pmdaoverhead. Les valeurs valides pour ident sont dans la plage de 0 à 4094 (inclus).
6.
Une clause pattern: a la forme
pattern: regex
où regex est une notation d'expression régulière étendue dans le style de egrep(1). Le regex commence au premier caractère non espace après pattern: et s'étend jusqu'au prochain saut de ligne.

Les processus considérés comme membres du groupe sont ceux pour lesquels le nom de la commande, tel que rapporté par
$ pminfo -f proc.psinfo.cmd
correspond au regex PLUS tous les descendants de ces processus. Ainsi, par exemple, le regex ^pmcd$ correspondra à pmcd(1) et à tous les processus PMDA lancés par pmcd(1) et à tous leurs enfants, etc.

INSTALLATION

Si vous souhaitez accéder aux noms, aux textes d'aide et aux valeurs des métriques de performance de surcharge, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/overhead
# ./Install

Si vous souhaitez annuler l'installation, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/overhead
# ./Remove

pmdaoverhead est lancé par pmcd et ne doit jamais être exécuté directement. Les scripts Install et Remove notifient pmcd lorsque l'agent est installé ou supprimé.

FICHIERS

$PCP_PMCDCONF_PATH
options de ligne de commande utilisées pour lancer pmdaoverhead
$PCP_PMDAS_DIR/overhead/Install
script d'installation de l'agent pmdaoverhead
$PCP_PMDAS_DIR/overhead/Remove
script d'annulation de l'installation pour l'agent pmdaoverhead
$PCP_LOG_DIR/pmcd/overhead.log
fichier journal par défaut pour les messages d'erreur et autres informations de pmdaoverhead
$PCP_SYSCONF_DIR/overhead/conf.d
répertoire contenant les fichiers de configuration pour les métriques de surcharge

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DEBOGAGE

L'option -D ou --debug active l'affichage de diagnostics supplémentaires sur stderr pour aider à résoudre les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdaoverhead sont les suivantes :

Option Description
appl0 Analyse du fichier de configuration
appl1 Horodatages de début et de fin de refresh()
appl2 Sélection /proc dans refresh()

VOIR AUSSI

PCPIntro(1), pmcd(1), pmdaproc(1), pcp.conf(5), pcp.env(5) et PMNS(5).

NAME

pmdaoverhead - Performance Co-Pilot (PCP) data structure overhead detector PMDA

SYNOPSIS

pmdaoverhead [-d] [-h host] [-m metric_spec] [-t timeout]

DESCRIPTION

The pmdaoverhead is a Performance Co-Pilot (PCP) Performance Data Metric Domain Agent (PMDA) that monitors the memory overhead of PCP data structures. It is useful for tuning the PCP instrumentation and for identifying potential memory leaks or excessive memory usage within PCP applications or agents.

This PMDA works by instrumenting the memory allocation routines used by PCP. It then tracks the amount of memory allocated for various PCP data structures and reports this information as performance metrics.

The primary use case is to identify which parts of the PCP system are consuming the most memory, allowing developers and administrators to optimize memory usage.

CONFIGURATION

The pmdaoverhead PMDA can be configured via its command-line options:

  • -d: Enables debug logging.

  • -h host: Specifies the host from which to collect PCP metrics. Defaults to the local host.

  • -m metric_spec: A comma-separated list of metric specifications to enable. If not specified, all available metrics are enabled.

  • -t timeout: Sets the timeout for collecting metrics in seconds. Defaults to 10 seconds.

Configuration can also be done by creating a configuration file for the PMDA, typically located in /etc/pcp/pmdaoverhead.conf. The format of this file is a simple key-value pair.

INSTALLATION

The pmdaoverhead PMDA is typically installed as part of the pcp package. After installation, it can be started and enabled using the standard PCP service management tools, such as:

# systemctl enable pmdaoverhead
# systemctl start pmdaoverhead

FILES

  • /etc/pcp/pmdaoverhead.conf: PMDA configuration file.

  • /var/log/pcp/pmdaoverhead.log: PMDA log file (if enabled).

PCP ENVIRONMENT

The pmdaoverhead PMDA uses the standard PCP environment variables. These include:

  • PCP_PMCD_PORT: The port number for the PCP metrics collector daemon (pmcd).

  • PCP_ARCH: The architecture of the system.

  • PCP_CONF: The directory containing PCP configuration files.

DEBUGGING OPTIONS

To enable debugging, use the -d command-line option when starting the PMDA. Debug messages will be logged to the PMDA's log file (typically /var/log/pcp/pmdaoverhead.log).

The specific metrics available can be queried using the pminfo command:

$ pminfo -f pmdaoverhead

NOM

pmdaoverhead - Agent de domaine de métriques Performance Co-Pilot (PCP) pour la détection de la surcharge des structures de données

SYNTAXE

pmdaoverhead [-d] [-h hôte] [-m spécification_métrique] [-t délai]

DESCRIPTION

Le pmdaoverhead est un Agent de domaine de métriques Performance Co-Pilot (PCP) qui surveille la surcharge mémoire des structures de données PCP. Il est utile pour optimiser l'instrumentation PCP et pour identifier des fuites de mémoire potentielles ou une utilisation excessive de la mémoire au sein des applications ou agents PCP.

Ce PMDA fonctionne en instrumentant les routines d'allocation mémoire utilisées par PCP. Il suit ensuite la quantité de mémoire allouée pour diverses structures de données PCP et rapporte ces informations sous forme de métriques de performance.

Son utilisation principale est d'identifier quelles parties du système PCP consomment le plus de mémoire, permettant aux développeurs et administrateurs d'optimiser l'utilisation de la mémoire.

CONFIGURATION

Le PMDA pmdaoverhead peut être configuré via ses options en ligne de commande :

  • -d : Active la journalisation de débogage.

  • -h hôte : Spécifie l'hôte à partir duquel collecter les métriques PCP. Par défaut, il s'agit de l'hôte local.

  • -m spécification_métrique : Une liste séparée par des virgules de spécifications de métriques à activer. Si non spécifié, toutes les métriques disponibles sont activées.

  • -t délai : Définit le délai de collecte des métriques en secondes. Par défaut, il est de 10 secondes.

La configuration peut également être effectuée en créant un fichier de configuration pour le PMDA, généralement situé dans /etc/pcp/pmdaoverhead.conf. Le format de ce fichier est une simple paire clé-valeur.

INSTALLATION

Le PMDA pmdaoverhead est généralement installé dans le cadre du paquet pcp. Après l'installation, il peut être démarré et activé à l'aide des outils de gestion de services PCP standards, tels que :

# systemctl enable pmdaoverhead
# systemctl start pmdaoverhead

FICHIERS

  • /etc/pcp/pmdaoverhead.conf : Fichier de configuration du PMDA.

  • /var/log/pcp/pmdaoverhead.log : Fichier journal du PMDA (si activé).

ENVIRONNEMENT PCP

Le PMDA pmdaoverhead utilise les variables d'environnement PCP standards. Celles-ci incluent :

  • PCP_PMCD_PORT : Le numéro de port du démon collecteur de métriques PCP (pmcd).

  • PCP_ARCH : L'architecture du système.

  • PCP_CONF : Le répertoire contenant les fichiers de configuration PCP.

OPTIONS DE DÉBOGAGE

Pour activer le débogage, utilisez l'option en ligne de commande -d lors du démarrage du PMDA. Les messages de débogage seront enregistrés dans le fichier journal du PMDA (généralement /var/log/pcp/pmdaoverhead.log).

Les métriques spécifiques disponibles peuvent être interrogées à l'aide de la commande pminfo :

$ pminfo -f pmdaoverhead
