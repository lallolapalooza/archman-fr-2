PMSERIESDESCS(3) Manuel des fonctions de bibliothèque PMSERIESDESCS(3)

NOM

pmSeriesDescs, pmSeriesLabels, pmSeriesLabelValues, pmSeriesInstances, pmSeriesMetrics, pmSeriesSources - métadonnées de séries chronologiques rapides et évolutives

SYNOPSIS EN C

#include <pcp/pmwebapi.h>

int pmSeriesDescs(pmSeriesSettings *sp,
int count, sds *series, void *arg);

int pmSeriesLabels(pmSeriesSettings *sp,
int count, sds *series, void *arg);

int pmSeriesLabelValues(pmSeriesSettings *sp,
int count, sds *labels, void *arg);

int pmSeriesInstances(pmSeriesSettings *sp,
int count, sds *series, void *arg);

int pmSeriesMetrics(pmSeriesSettings *sp,
int count, sds *series, void *arg);

int pmSeriesSources(pmSeriesSettings *sp,
int count, sds *series, void *arg);

cc ... -lpcp_web

DESCRIPTION

Chaque métrique de performance et source de données faisant partie du service de séries chronologiques rapide et évolutif du Performance Co-Pilot (PCP) possède certaines propriétés (métadonnées) associées. Ces propriétés peuvent être interrogées à l'aide des interfaces décrites ici.

Cette fonctionnalité est fournie par des API asynchrones, qui fonctionnent dans un mode événementiel où des fonctions de rappel sont invoquées pour chaque structure de métadonnées retournée.

Dans l'ensemble, toutes les interfaces de ces API qui doivent invoquer des fonctions de rappel fournies par le programme appelant (voir pmSeriesSetup(3)) prendront un paramètre opaque (pointeur void *), arg. Ce pointeur sera passé tel quel et est généralement utilisé pour accéder à une structure de données maintenant l'état dans le programme appelant.

À quelques exceptions près, ces interfaces ont tendance à fonctionner dans l'un des deux modes suivants. Premièrement, une invocation est disponible pour interroger les métadonnées pour un nombre (non nul) spécifié de series chronologiques. Un second mode, avec un nombre (nul), retourne toutes les métadonnées disponibles de ce type, à travers toutes les séries chronologiques.

Afin de récupérer les informations descriptives des métriques pour une ou plusieurs séries chronologiques, l'interface pmSeriesDescs est utilisée. Pour chaque identifiant de series valide fourni, une fonction de rappel sera invoquée fournissant les unités de la métrique, la sémantique et le type, ainsi que d'autres identifiants associés (pmID, InDom et identifiant de source). Lorsque cet appel est émis avec une valeur nulle pour count, il est erroné de passer une valeur nulle ou négative de count à cette interface.

Pour extraire les noms et valeurs des étiquettes, l'interface pmSeriesLabels est utilisée. Avec un nombre (non nul) d'identifiants de series valides, cette routine invoquera une fonction de rappel une fois pour chaque nom d'étiquette et une fois pour chaque paire nom d'étiquette:valeur, pour les étiquettes associées à ces séries chronologiques. Si appelée avec un count nul, cette interface retournera (via la fonction de rappel du nom d'étiquette) tous les noms d'étiquettes observés à ce jour - non associés à des séries chronologiques spécifiques. L'interface pmSeriesLabelValues est comparable à ce dernier mode, sauf qu'elle retournera toutes les valeurs d'étiquettes observées à ce jour pour le tableau donné de noms d'étiquettes (non associées à des identifiants de séries chronologiques spécifiques).

pmSeriesInstances peut être utilisé pour trouver les métadonnées concernant les domaines d'instances et les identifiants d'instances associés à un (non nul) count donné d'identifiants de séries chronologiques. Si une valeur nulle est passée pour count, tous les noms d'instances observés à ce jour seront retournés.

pmSeriesMetrics peut être utilisé pour trouver les noms de métriques associés à un (non nul) count donné d'identifiants de séries chronologiques. Si une valeur nulle est passée pour count, tous les noms de métriques observés à ce jour seront retournés.

pmSeriesSources peut être utilisé pour trouver des métadonnées sur la source des métriques - c'est-à-dire les noms d'hôtes et les chemins d'accès aux fichiers d'archives. Si une valeur nulle est passée pour count, toutes les sources de métriques observées à ce jour seront retournées.

DIAGNOSTICS

Là où ces fonctions retournent un code d'état, il s'agit toujours de zéro en cas de succès. En cas d'échec, un code d'erreur PMAPI négatif est retourné.
