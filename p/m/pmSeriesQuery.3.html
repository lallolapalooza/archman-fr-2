PMSERIESQUERY(3) Manuel des fonctions de bibliothèque PMSERIESQUERY(3)

NOM

pmSeriesQuery, pmSeriesWindow, pmSeriesValues, pmSeriesLoad - interroger rapidement et à l'échelle des séries temporelles

C SYNTAXE

#include <pcp/pmwebapi.h>

int pmSeriesQuery(pmSeriesSettings *sp,
sds *query, pmSeriesFlags flags, void *arg);

int pmSeriesWindow(pmSeriesSettings *sp,
sds *window, pmSeriesTimeWindow *window, void *arg);

int pmSeriesValues(pmSeriesSettings *sp,
pmSeriesTimeWindow *window, int count, sds *series, void *arg);

int pmSeriesLoad(pmSeriesSettings *sp,
sds *query, pmSeriesFlags flags, void *arg);

cc ... -lpcp_web

DESCRIPTION

La recherche d'identificateurs et de valeurs de séries temporelles à l'aide des services d'interrogation rapide et évolutive de séries temporelles de Performance Co-Pilot (PCP) est réalisée à l'aide de l'utilitaire pmseries(1) et du service d'API REST associé pmproxy(1).

L'implémentation de ces installations est partagée et disponible pour que d'autres programmes l'utilisent également. La fonctionnalité est fournie par des API asynchrones, qui fonctionnent de manière événementielle où des rappels sont invoqués pour chaque ensemble d'identificateurs de séries ou structure de valeurs retournée. Ces rappels doivent être enregistrés à l'aide de pmSeriesSetup(3) avant que tout appel d'API de requête ne soit effectué.

En tant que modèle général, ces interfaces prennent un paramètre opaque (pointeur void *), arg. Ce pointeur sera transmis inchangé et est généralement utilisé pour accéder à une structure de données maintenant l'état dans le programme appelant.

Selon la chaîne de query de pmseries fournie, pmSeriesQuery fonctionne dans l'un des deux modes.

Premièrement, si aucune spécification de fenêtre temporelle n'est fournie (entre crochets), l'interface ne retournera que les identificateurs de séries correspondants et aucune valeur. Ces identificateurs sont retournés via le rappel on_match enregistré avec pmSeriesSetup. Si l'expression query inclut des appels de fonction ou des opérateurs arithmétiques (plutôt que de simples noms de métriques), l'identificateur retourné est créé dynamiquement et associé de manière persistante à l'expression. L'expression query peut être récupérée avec l'appel d'API pmSeriesExprs(3). Voir aussi PMWEBAPI(3) et l'option -e de pmseries(1).

Le second mode est celui où une spécification de fenêtre temporelle est utilisée dans la chaîne query, ou lorsque l'interface pmSeriesValues est utilisée. Ce mode fournit des valeurs et des horodatages pour tous les identificateurs de séries temporelles correspondants ayant des points de données dans la window temporelle fournie. Dans ce cas, les résultats sont retournés via le rappel on_value enregistré avec pmSeriesSetup. Une routine d'aide pour créer une structure de window temporelle à partir d'une spécification temporelle entre crochets est fournie sous la forme de pmSeriesWindow.

D'autres métadonnées (noms de métriques, étiquettes, unités, sémantique, type, etc.) sur les séries temporelles correspondantes et leurs valeurs peuvent être obtenues à l'aide des interfaces décrites sur la page du manuel pmSeriesDescs(3).

Typiquement, le chargement des séries temporelles est géré automatiquement par le démon pmproxy, qui utilise la série d'interfaces pmDiscoverSetup(3) pour détecter et charger automatiquement les séries temporelles enregistrées à partir de pmlogger(1). Cependant, il est également possible de charger manuellement des séries temporelles à partir d'une archive PCP à l'aide de l'interface pmSeriesLoad. La chaîne query fournie doit fournir une archive ou un répertoire à partir duquel charger les données à l'aide du mot-clé source.path.

DIAGNOSTICS

Lorsque ces fonctions retournent un code de statut, celui-ci est toujours zéro en cas de succès. En cas d'échec, un code d'erreur PMAPI négatif est retourné.

VOIR AUSSI

pmproxy(1), pmlogger(1), pmSeriesSetup(3), pmSeriesDescs(3), pmDiscoverSetup(3), PMAPI(3) et PMWEBAPI(3).
