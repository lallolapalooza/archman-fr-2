PMEXTRACTVALUE(3) Manuel des fonctions de bibliothèque PMEXTRACTVALUE(3)

NOM

pmExtractValue - extraire une valeur de métrique de performance d'une structure pmResult

SYNTAXE C

#include <pcp/pmapi.h>

int pmExtractValue(int valfmt,
const pmValue *ival, int itype, pmAtomValue *oval, int otype);

cc ... -lpcp

DESCRIPTION

La structure pmValue est intégrée dans la structure pmResult qui est utilisée pour retourner une ou plusieurs métriques de performance ; voir pmFetch(3).

Toutes les valeurs de métriques de performance peuvent être codées dans une union pmAtomValue, définie comme suit :

typedef union {
    __int32_t    l;     /* 32-bit signé */
    __uint32_t   ul;    /* 32-bit non signé */
    __int64_t    ll;    /* 64-bit signé */
    __uint64_t   ull;   /* 64-bit non signé */
    float        f;     /* virgule flottante 32 bits */
    double       d;     /* virgule flottante 64 bits */
    char         *cp;   /* pointeur char */
    pmValueBlock *vbp;  /* pointeur pmValueBlock */
} pmAtomValue;

La routine pmExtractValue fournit un mécanisme pratique pour extraire des valeurs de la partie pmValue d'une structure pmResult, en convertissant éventuellement le type de données, et en rendant le résultat disponible au programmeur de l'application.

itype définit le type de données de la valeur d'entrée contenue dans ival selon le format de stockage défini par valfmt (voir pmFetch(3)). otype définit le type de données du résultat à placer dans oval.

La valeur pour itype est généralement extraite d'une structure pmDesc, suite à un appel à pmLookupDesc(3) pour une métrique de performance particulière.

La valeur otype doit être l'une des valeurs PM_TYPE_... définies, qui ont une correspondance 1:1 avec les champs de l'union pmAtomValue.

Normalement, le paramètre valfmt serait extrait de la même structure pmResult qui fournit le paramètre ival, et si valfmt spécifie PM_VAL_INSITU, alors les types d'entrée suivants ne sont pas autorisés, car ils ne peuvent pas être codés en 32 bits ; __int64_t, __uint64_t, double, char * et void * et les valeurs itype correspondantes sont PM_TYPE_64, PM_TYPE_U64, PM_TYPE_DOUBLE, PM_TYPE_STRING, PM_TYPE_AGGREGATE et PM_TYPE_EVENT (ou PM_TYPE_HIGHRES_EVENT) respectivement. Si valfmt spécifie PM_VAL_SPTR ou PM_VAL_DPTR, alors la valeur sera extraite de la structure pmValueBlock associée, et les options __int32_t, __uint32_t et float (itype étant respectivement PM_TYPE_32, PM_TYPE_U32 et PM_TYPE_FLOAT) ne sont pas autorisées, car PM_VAL_INSITU est le codage approprié pour ceux-ci.

Le tableau suivant définit les différentes possibilités de conversion de type -- le type d'entrée (itype) est indiqué verticalement, et le type de sortie (otype) est indiqué horizontalement. Y signifie que la conversion est toujours acceptable, N signifie que la conversion ne peut jamais être effectuée (la fonction renvoie PM_ERR_CONV), P signifie que la conversion peut perdre en précision (mais aucun statut d'erreur n'est retourné), T signifie que le résultat peut être sujet à une troncature de haut niveau (auquel cas la fonction renvoie PM_ERR_TRUNC) et S signifie que la conversion peut être impossible en raison du signe de la valeur d'entrée (auquel cas la fonction renvoie PM_ERR_SIGN). En cas d'erreur, la valeur représentée par oval sera zéro (ou NULL).

Aucune conversion impliquant les types PM_TYPE_EVENT, PM_TYPE_HIGHRES_EVENT ou PM_TYPE_AGGR n'est prise en charge, et l'étiquette « BLOB » dans le tableau ci-dessous couvre ces trois types.

      | 32  |  U32  | 64  |  U64  | FLOAT | DBLE | STRNG | BLOB
======|=====|=======|=====|=======|=======|======|=======|======
32    |  Y  |   S   |  Y  |   S   |   P   |  P   |   Y   |  N
U32   |  T  |   Y   |  Y  |   Y   |   P   |  P   |   Y   |  N
64    |  T  |  T,S  |  Y  |   S   |   P   |  P   |   Y   |  N
U64   |  T  |   T   |  T  |   Y   |   P   |  P   |   Y   |  N
FLOAT | P,T | P,T,S | P,T | P,T,S |   Y   |  Y   |   P   |  N
DBLE  | P,T | P,T,S | P,T | P,T,S |   P   |  Y   |   P   |  N
STRNG |  N  |   N   |  N  |   N   |   N   |  N   |   Y   |  N
BLOB  |  N  |   N   |  N  |   N   |   N   |  N   |   N   |  N

Dans les cas où plusieurs erreurs de conversion pourraient se produire, la première erreur rencontrée sera signalée, et l'ordre de vérification n'est pas défini.

Si la conversion de sortie est vers l'un des types pointeurs, c'est-à-dire si otype est PM_TYPE_STRING ou PM_TYPE_AGGREGATE, alors le tampon de valeur aura été alloué par pmExtractValue(3) en utilisant malloc(3), et il est de la responsabilité de l'appelant de libérer l'espace lorsqu'il n'est plus nécessaire.

Bien que cette fonction semble assez complexe, elle a été conçue pour aider au développement d'outils de performance qui souhaitent convertir des valeurs, dont le type n'est connu que via le champ type d'une structure pmDesc, en un type canonique pour le traitement local. Voir les fonctions pmFetchGroup pour une alternative plus simple.

DIAGNOSTICS

PM_ERR_CONV

Conversion impossible, marquée par N dans le tableau ci-dessus

PM_ERR_TRUNC

Troncature de haut niveau s'est produite

PM_ERR_SIGN

Tentative de conversion d'une valeur négative vers un type non signé
