PMSERIES(1) Manuel des commandes générales PMSERIES(1)

NOM

pmseries - affiche des informations sur les séries temporelles de métriques de performance

SYNTAXE

pmseries [-adFiIlLmMnqsStvV?] [-c config] [-D debug] [-g pattern] [-h host] [-p port] [-w window] [-Z timezone] [requête | labels ... | séries ... | source ... ]

DESCRIPTION

pmseries affiche divers types d'informations sur les métriques de performance disponibles via les installations de séries temporelles évolutives de Performance Co-Pilot (PCP) et un magasin de données clé-valeur distribué tel que https://valkey/io/.

Par défaut, pmseries communique avec un serveur clé-valeur local, cependant les options -h et -p peuvent être utilisées pour spécifier un serveur clé-valeur alternatif. Si cette instance fait partie d'un cluster, toutes les autres instances du cluster seront découvertes et utilisées automatiquement.

pmseries s'exécute dans plusieurs modes différents - soit en interrogeant des identifiants de séries temporelles, des métadonnées ou des valeurs (déjà stockées dans le magasin clé-valeur), soit en chargeant manuellement des séries temporelles. Ce dernier mode est généralement utilisé uniquement pour charger des archives précédemment collectées (inactives), car pmproxy(1) effectue automatiquement cette fonction pour les instances pmlogger(1) locales "en direct" (en croissance active), lorsqu'il est exécuté dans son mode de série temporelle par défaut. Voir la section CHARGEMENT DES SÉRIES TEMPORELLES ci-dessous et l'option -L pour plus de détails.

Sans options de ligne de commande spécifiant le contraire, pmseries émettra une requête de série temporelle pour trouver des séries temporelles et des valeurs correspondantes. Toutes les séries temporelles sont identifiées à l'aide d'un hachage SHA-1 unique qui est toujours affiché sous une forme lisible par l'homme en 40 chiffres hexadécimaux. Ces hachages sont formés en utilisant les métadonnées associées à chaque métrique.

Notamment, cela inclut toutes les métadonnées de métrique (labels, noms, descripteurs). Les labels de métrique en particulier sont (dans la mesure du possible) uniques pour chaque machine - sous Linux par exemple, les labels associés à chaque métrique incluent le /etc/machine-id unique, le nom d'hôte, le nom de domaine, et d'autres labels de machine générés automatiquement, ainsi que tous les labels définis par l'administrateur depuis /etc/pcp/labels. Ces labels peuvent être rapportés avec pminfo(1) et la métrique pmcd.labels.

Voir pmLookupLabels(3), pmLookupInDom(3), pmLookupName(3) et pmLookupDesc(3) pour des informations détaillées sur les labels de métriques et d'autres métadonnées de métriques utilisées dans le calcul du hachage de l'identifiant de chaque série temporelle.

Les identifiants de séries temporelles fournissent un identifiant de niveau supérieur (et indépendant de la machine) par rapport aux identifiants de métriques de performance (pmID), identifiants de domaine d'instance (pmInDom) et noms de métriques traditionnels de PCP. Voir PCPIntro(1) pour plus de détails sur ces identifiants traditionnels. Cependant, pmseries utilise les identifiants de séries temporelles de manière très similaire à la façon dont pminfo(1) utilise les indom de bas niveau, les identifiants de métriques et les noms de métriques.

Le mode de fonctionnement par défaut de pmseries (c'est-à-dire sans options de ligne de commande) dépend des arguments qui lui sont présentés. Si tous les arguments autres que les options semblent être des identifiants de séries temporelles (en forme hexadécimale sur 40 chiffres), pmseries rapportera les métadonnées de ces séries temporelles - se référer à l'option -a pour les détails. Sinon, les paramètres seront traités comme une requête de série temporelle.

REQUETES DE SERIES TEMPORELLES

Les expressions de requête sont formées en utilisant le langage de requête pmseries décrit ci-dessous, mais peuvent être aussi simples qu'un nom de métrique.

Voici un exemple de requête de séries temporelles à partir de tous les hôtes qui correspondent à un motif de nom de métrique (globbed) :

$ pmseries kernel.all.cpu*
1d7b0bb3f6aec0f49c54f5210885464a53629b60
379db729afd63fb9eff436625bd6c55a7adc5cfd
3dd3b45bb05f96636043e5d58b52b441ce542285
[...]
ed2bf325ff6dc7589ec966698e5404b67252306a
dcb2a032a308b5717bf605ba8f8737e9c6e1ed19

Pour identifier les opérandes d'expression de série temporelle, le langage de requête utilise la syntaxe générale :

[nom.métrique] '{qualificatifs de métadonnées}' '[spécification de temps]'

Le composant nom.métrique restreint la requête de série temporelle à tout nom de métrique PCP correspondant (la liste des noms de métriques pour une archive PCP ou un hôte en direct est rapportée par pminfo(1) sans arguments autres que --host ou --archive). La syntaxe pmseries étend celle de pminfo et permet la mise en correspondance de motifs basée sur glob(7) dans le nom de la métrique. Le ci-dessus décrit les opérandes disponibles aux feuilles des expressions pmseries, qui peuvent inclure des fonctions, des opérateurs arithmétiques et d'autres fonctionnalités. Voir la section EXPRESSIONS ci-dessous pour plus de détails.

QUALIFICATIFS DE METADONNEES ET OPERATEURS DE METADONNEES

Les qualificatifs de métadonnées sont entourés d'accolades ({}), et restreignent davantage les résultats de la requête aux opérandes de séries temporelles avec diverses propriétés de métadonnées. Ces qualificatifs sont basés sur les noms de métriques ou d'instances, et les valeurs des labels de métriques, et prennent la forme générale nom.métadonnée OPERATEUR valeur, comme :

instance.name == "cpu0"
metric.name != "kernel.all.pswitch"

Lors de l'utilisation de noms de labels, le qualificatif de métadonnée est optionnel et peut être omis, comme :

label.hostname == "www.acme.com"
hostname == "www.acme.com"

Pour les noms de métriques et d'instances, seuls les opérateurs de chaînes s'appliquent, mais pour les valeurs de labels de métriques, tous les opérateurs sont disponibles. L'ensemble des opérateurs disponibles est :

Opérateurs booléens

Toutes les chaînes (labels, métriques et instances) et valeurs numériques (labels) peuvent être testées pour l'égalité ("==") ou l'inégalité ("!=").

Opérateurs de chaîne

Les chaînes peuvent être sujettes à une mise en correspondance de motif sous la forme de correspondance glob ("~~"), de correspondance d'expression régulière ("=~"), et de non-correspondance d'expression régulière ("!~"). L'opérateur ":" est équivalent à "~~" - c'est-à-dire, correspondance glob.

Opérateurs relationnels (valeurs numériques de labels seulement)

Les valeurs numériques de labels peuvent être sujettes aux opérateurs inférieur à ("<"), supérieur à (">"), inférieur ou égal ("<="), supérieur ou égal (">="), égal ("==") et différent ("!=").

Opérateurs logiques

Plusieurs qualificatifs de métadonnées peuvent être combinés avec les opérateurs logiques AND ("&&") et OR ("||") comme dans de nombreux langages de programmation. Le caractère virgule (",") est équivalent à l'opérateur logique AND ("&&").

SPECIFICATION DE TEMPS

La dernière composante (optionnelle) d'une requête permet à l'utilisateur de spécifier une fenêtre temporelle spécifique d'intérêt. Toute spécification de temps entraînera le retour des valeurs pour toutes les séries temporelles correspondantes uniquement pour la fenêtre temporelle spécifiée.

La spécification est entourée de crochets ([]), et consiste en un ou plusieurs composants séparés par des virgules. Chaque composant spécifie un aspect lié au temps, prenant la forme générale : mot-clé : valeur, comme :

samples:10

Nombre d'échantillons

Le nombre d'échantillons à retourner, spécifié via le mot-clé samples ou (équivalent) count. La valeur fournie doit être un entier positif. Si aucune heure de fin n'est explicitement définie (voir "Fenêtre temporelle" plus loin), alors le plus récent

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

cent échantillons seront retournés.

Intervalle d'échantillonnage

Un intervalle entre des échantillons successifs peut être demandé en utilisant le mot-clé interval ou (équivalent) delta. La valeur fournie doit être une valeur numérique ou textuelle qui sera analysée par pmParseInterval(3), comme 5 (secondes) ou 2min (minutes).

Fenêtre temporelle

Les heures de début et de fin, ainsi que les alignements, affectant les valeurs retournées. Les mots-clés correspondent aux paramètres de la fonction pmParseTimeWindow(3) qui sera utilisée pour les analyser, et sont : start ou (équivalent) begin, finish ou (équivalent) end, align et offset.

Fuseaux horaires

Les horodatages résultants peuvent être retournés après avoir été évalués pour un fuseau horaire spécifique, en utilisant les mots-clés timezone ou hostzone. La valeur associée à timezone sera interprétée par pmNewZone(3). Une valeur true ou false doit être associée à hostzone, et lorsqu'elle est définie à true, cela a le même effet que décrit par pmNewContextZone(3).

EXPRESSIONS

Comme décrit ci-dessus, les opérandes sont les feuilles d'un arbre d'expression de requête.

[nom.de.la.métrique] '{qualificateurs de métadonnées}' '[spécification temporelle]'
Notez que dans la plupart des exemples d'expressions de requête ci-dessous, les qualificateurs de métadonnées ont été omis pour plus de concision. Dans tous les cas, plusieurs séries temporelles peuvent être qualifiées, en particulier pour le libellé hostname.

Dans le cas simple, une expression de requête consiste en un seul opérande et peut être simplement un nom de métrique. Dans le cas plus général, une expression de requête est soit un opérande, soit l'argument d'une fonction, soit deux opérandes dans une expression arithmétique ou logique binaire. La plupart des fonctions prennent un seul argument (une expression), bien que certaines en nécessitent d'autres, par exemple rescale.

opérande | expr opérateur expr | func(expr[, arg])

Cette grammaire montre que les expressions peuvent être imbriquées, par exemple, en utilisant l'opérateur d'addition (+) comme exemple,

func1(func2(expr))
func1(expr) + func2(expr)
expr + func(expr)
func(expr) + expr
expr + expr

Les règles régissant la compatibilité des opérandes dans une expression dépendent généralement de la fonction et/ou des opérateurs et sont décrites ci-dessous individuellement. Une règle importante est que si des fenêtres temporelles sont spécifiées, tous les opérandes doivent couvrir le même nombre d'échantillons, bien que les fenêtres temporelles puissent différer individuellement. Si aucun intervalle temporel ou nombre d'échantillons n'est donné, pmseries retournera un identifiant de série (SID) au lieu d'une série d'horodatages et de valeurs. Ce SID peut être utilisé dans les appels RESTAPI ultérieurs /series/values?series=SID, ainsi qu'une fenêtre temporelle spécifique.

Opérateurs arithmétiques

pmseries supporte l'addition, la soustraction, la division et la multiplication sur chaque valeur dans la série temporelle d'une paire binaire d'opérandes. Aucun opérateur unaire ou ternaire n'est supporté (pour l'instant). Dans tous les cas, le domaine d'instance et le nombre d'échantillons des opérandes de séries temporelles doivent être les mêmes. Les métadonnées (unités et dimensions) doivent également être compatibles. Selon la fonction, le résultat aura généralement le même domaine d'instance et (sauf indication contraire) les mêmes unités que les opérandes. Les dimensions des métadonnées (espace, temps, comptage) du résultat peuvent différer (voir ci-dessous).

Les opérandes d'expression peuvent avoir des qualificateurs différents, par exemple, vous pouvez effectuer une arithmétique binaire sur des métriques qualifiées par différents libellés (comme hostname), ou des noms de métriques. Par exemple, pour ajouter les deux échantillons les plus récents du compteur de changements de contexte (pswitch) pour les hôtes node88 et node89, puis effectuer une conversion de taux :

$ pmseries 'rate(kernel.all.pswitch{hostname:node88}[count:2] +
                 kernel.all.pswitch{hostname:node89}[count:2])'
1cf1a85d5978640ef94c68264d3ae8866cc11f7c
    [Tue Nov 10 14:39:48.771868000 2020] 71.257509 8e0a59304eb99237b89593a3e839b5bb8b9a9924

Notez que la série temporelle de valeurs résultante a un échantillon de moins que l'opérande d'expression passé à la fonction rate.

Autres règles pour les expressions arithmétiques :

1. Si les deux opérandes ont la sémantique d'un compteur, seuls l'addition et la soustraction sont autorisées
2. Si l'opérande de gauche est un compteur et l'opérande de droite ne l'est pas, seules la multiplication ou la division sont autorisées
3. Si l'opérande de gauche n'est pas un compteur et l'opérande de droite en est un, seule la multiplication est autorisée.
4. Addition et soustraction - les dimensions du résultat sont les mêmes que les dimensions des opérandes.
5. Multiplication - les dimensions du résultat sont la somme des dimensions des opérandes.
6. Division - les dimensions du résultat sont la différence des dimensions des opérandes.

Fonctions

Les fonctions d'expression opèrent sur des vecteurs de valeurs de séries temporelles, et peuvent être imbriquées avec d'autres fonctions ou expressions comme décrit ci-dessus. Lorsqu'un opérande a plusieurs instances, il y aura généralement un résultat pour chaque série d'instances. Par exemple, le résultat pour

$ pmseries 'min_sample(kernel.all.load[count:100])'

sera la plus petite valeur des 100 échantillons les plus récents, en traitant chaque instance de moyenne de charge comme une série temporelle distincte. Par exemple, pour les deux échantillons les plus récents de chacune des trois instances de la métrique de moyenne de charge :

Certaines fonctions de pmseries fournissent des opérations sur les domaines temporel et d'instance. Par exemple, max_inst(expr) trouve la valeur maximale parmi les instances tandis que max_sample(expr) trouve la valeur maximale dans le temps.

Les futures versions de pmseries pourront fournir des fonctions qui effectueront des agrégations, des interpolations, des filtrages ou des transformations d'autres manières.

Référence des fonctions

max_inst(expr) la valeur maximale dans la série temporelle pour chaque instance de expr. Pour des raisons de compatibilité ascendante, le synonyme max est équivalent à max_inst.

max_sample(expr) la valeur maximale dans la série temporelle pour chaque échantillon de expr dans le temps.

min_inst(expr) la valeur minimale dans la série temporelle pour chaque instance de expr. Pour des raisons de compatibilité ascendante, le synonyme min est équivalent à min_inst.

min_sample(expr) la valeur minimale dans la série temporelle pour chaque échantillon de expr dans le temps.

sum_inst(expr) somme des valeurs dans la série temporelle pour chaque instance de expr. Pour des raisons de compatibilité ascendante, le synonyme sum est équivalent à sum_inst.

sum_sample(expr) somme des valeurs dans la série temporelle pour chaque échantillon de expr dans le temps.

avg_inst(expr) moyenne des valeurs dans la série temporelle pour chaque instance de expr. Pour des raisons de compatibilité ascendante, le synonyme avg est équivalent à avg_inst.

avg_sample(expr) moyenne des valeurs dans la série temporelle pour chaque échantillon de expr dans le temps.

rate(expr) le taux par rapport au temps de chaque échantillon. L'expression expr donnée doit avoir la sémantique de counter et le résultat aura la sémantique d'instant (la dimension temporelle réduite de un). De plus, le résultat aura un échantillon de moins que l'opérande - ceci est dû au fait que le premier échantillon ne peut pas être converti en taux (deux échantillons sont requis).

rescale(expr,scale) remet à l'échelle les valeurs dans la série temporelle pour chaque instance de expr à scale (unités). Notez que expr doit avoir la sémantique instant ou discrete (pas counter - la conversion de taux doit être effectuée au préalable si nécessaire). Les dimensions temporelles, spatiales et de comptage entre expr et scale doivent être compatibles. Exemple : convertir le compteur de débit de lecture pour chaque instance de disque et ensuite remettre à l'échelle en Mo/sec. Notez que les unités natives de disk.dev.read_by

tes est un compteur de ko lus sur chaque instance de périphérique depuis le démarrage.

$ pmseries 'rescale(rate(disk.dev.read_bytes[count:4]), "mbytes/s")'

abs(expr) la valeur absolue de chaque valeur dans la série temporelle pour chaque instance de expr. Ceci n'a aucun effet si le type de expr est non signé.

floor(expr) arrondi à l'entier inférieur le plus proche de la série temporelle pour chaque instance de expr.

round(expr) arrondi à l'entier le plus proche, supérieur ou inférieur, pour chaque valeur dans la série temporelle pour chaque instance de expr.

log(expr) logarithme des valeurs dans la série temporelle pour chaque instance de expr

sqrt(expr) racine carrée des valeurs dans la série temporelle pour chaque instance de expr

stdev_inst(expr) écart-type des valeurs dans la série temporelle pour chaque instance de expr.

stdev_sample(expr) écart-type des valeurs dans la série temporelle pour chaque échantillon de expr au fil du temps.

topk_inst(expr,k) les k plus grandes valeurs dans la série temporelle pour chaque instance de expr.

topk_sample(expr,k) les k plus grandes valeurs dans la série temporelle pour chaque échantillon de expr au fil du temps.

nth_percentile_inst(expr,percentile_value) le nième percentile des valeurs dans la série temporelle pour chaque instance de expr. Notez que percentile_value a une valeur comprise entre 0 et 100.

nth_percentile_sample(expr,percentile_value) le nième percentile des valeurs dans la série temporelle pour chaque échantillon de expr au fil du temps. Notez que percentile_value a une valeur comprise entre 0 et 100.

Compatibilité

Tous les opérandes d'une expression doivent avoir le même nombre d'échantillons, mais pas nécessairement la même fenêtre temporelle. Par exemple, vous pourriez soustraire une série temporelle de métrique d'aujourd'hui de celle d'hier en donnant des fenêtres temporelles et des métriques ou des qualificateurs différents, en vous assurant que le même nombre d'échantillons sont donnés comme opérandes.

Les opérandes d'une expression doivent soit tous avoir une fenêtre temporelle, soit aucun. Si aucun opérande n'a de fenêtre temporelle, alors au lieu d'une série d'horodatages et de valeurs, le résultat sera un identifiant de série temporelle (SID) qui peut être passé à la fonction d'API REST /series/values?series=SID, avec une fenêtre temporelle. Pour plus de détails, voir PMWEBAPI(3).

Si la sémantique des deux opérandes d'une expression arithmétique n'est pas un compteur (c'est-à-dire PM_SEM_INSTANT ou PM_SEM_DISCRETE) alors le résultat aura la sémantique PM_SEM_INSTANT à moins que les deux opérandes ne soient PM_SEM_DISCRETE, auquel cas le résultat est également PM_SEM_DISCRETE.

MÉTABLES DES SÉRIES TEMPORELLES

En utilisant des options de ligne de commande, pmseries peut être invité à fournir des métadonnées (noms de métriques, noms d'instances, étiquettes, descripteurs) associées à des séries temporelles individuelles ou à un groupe de séries temporelles, par exemple :

    Metric: kernel.all.cpu.nice

            "latitude":-25.28496,"longitude":152.87886,\
            "machineid":"295b16e3b6074cc8bdbda8bf96f6930a",\

L'ensemble complet des options de rapport de métadonnées pmseries est :

-a, --all
Option pratique pour afficher toutes les métadonnées pour la série temporelle donnée, équivalent à -deilms.
-d, --desc
Descriptions des métriques détaillant le PMID, le type de données, la sémantique des données, les unités, l'échelle et le domaine d'instance associé. Cette option a un équivalent direct dans pminfo(1).
-F, --fast
Interroger ou charger uniquement les métadonnées des séries, pas les valeurs.
-g motif, --glob=motif
Fournit un motif glob(7) pour restreindre le rapport fourni par les options -i, -l, -m et -S.
-i, --instances
Descriptions des métriques détaillant le PMID, le type de données, la sémantique des données, les unités, l'échelle et le domaine d'instance associé.
-I, --fullindom
Affiche l'InDom en mode verbeux. Cette option a un équivalent direct dans pminfo(1).
-l, --labels
Affiche les ensembles d'étiquettes associés aux métriques et aux instances. Les étiquettes sont des métadonnées optionnelles décrites en détail dans pmLookupLabels(3). Cette option a un équivalent direct dans pminfo(1).
-m, --metrics
Affiche les noms des métriques.
-M, --fullpmid
Affiche le PMID en mode verbeux. Cette option a un équivalent direct dans pminfo(1).
-n, --names
Affiche uniquement les noms des étiquettes séparés par des virgules (pas les valeurs) pour les étiquettes associées aux métriques et aux instances.
-s, --series
Affiche les identifiants de séries temporelles associés aux métriques, instances et sources. Ces identifiants uniques sont calculés à partir des étiquettes intrinsèques (non optionnelles) et d'autres métadonnées associées à chaque contexte PMAPI (sources), métriques et instances. Les archives, les contextes locaux ou les connexions pmcd(1) pour le même hôte produisent tous le même identifiant de source. Cette option a un équivalent direct dans pminfo(1). Voir aussi pmLookupLabels(3) et l'option -l/--labels.

SOURCES DES SÉRIES TEMPORELLES

Une source est un identifiant unique (représenté extérieurement sous forme de hash SHA-1 hexadécimal de 40 octets) qui représente à la fois l'hôte en direct et/ou les archives d'où provient chaque série temporelle. Le contexte d'un identifiant de source (obtenu avec -s) peut être rapporté avec :

-S, --sources
Affiche les noms des sources de séries temporelles. Ces noms sont soit des noms d'hôtes, soit des chemins d'archives entièrement qualifiés.

Il est important de noter que les sources en direct et d'archives peuvent générer et généreront le même hash d'identifiant de source SHA-1, à condition que les étiquettes de contexte restent les mêmes pour cet hôte (les étiquettes sont stockées dans les archives PCP et peuvent également être récupérées en direct depuis pmcd(1)).

CHARGEMENT DES SÉRIES TEMPORELLES

Les métadonnées et les données des séries temporelles sont chargées soit automatiquement par un pmproxy(1) local, soit manuellement à l'aide d'une requête pmseries spécialement conçue et de l'option -L/--load :

$ pmseries --load "{source.path: \"$PCP_LOG_DIR/pmlogger/acme\"}"
pmseries: [Info] processed 2275 archive records from [...]

Cette requête doit spécifier un chemin d'archive source, mais peut également restreindre l'importation à des séries temporelles spécifiques (en utilisant des noms de métriques, des étiquettes, etc.) et à une fenêtre temporelle spécifique en utilisant le composant de spécification temporelle du langage de requête.

Par souci de commodité, si l'argument de chargement est un chemin de fichier valide tel que déterminé par access(2), alors une forme abrégée peut être utilisée :

$ pmseries --load $PCP_LOG_DIR/pmlogger/acme.0

NOTE : Le chargement des séries temporelles est en mode ajout uniquement (par horodatage) et si plus de stream.maxlen entrées (défini dans $PCP_SYSCONF_DIR/pmseries/pmseries.conf) sont chargées pour une métrique donnée, les entrées les plus anciennes sont supprimées.

OPTIONS

-a [ArchFile]
Indicate that metric values should be retrieved from an archive rather than from a Performance Co-Pilot (PCP) data source. ArchFile identifies the archive, or collection of archives, to be used. If ArchFile is not specified, then the default is the current directory. See pmarchiverc(5) for a description of how archives may be searched. When archives are used, the query is always executed relative to the archive's time zone, and any environ(7) variable TZ is ignored.
-c config
Use the Performance Co-Pilot (PCP) configuration file specified by config. This overrides the default location specified by $PCP_CONF.
-D debug
Enable debug mode. The debug argument is a comma-separated list of optional debugging keywords. Use pmdbg(1) with the -l option for a list of available debugging keywords and their meanings.
-h host
Retrieve performance metrics from the Performance Co-Pilot (PCP) data source on the specified host. The default is localhost.
-i indent
Specify the instance(s) to be selected for metrics which have an instance domain. indent is a comma-separated list of instance names or instance identifiers. If an instance identifier is used it must be prefixed with the character ‘#’.
-n PCP_SHARE
Specify the location of the Performance Co-Pilot (PCP) PCP_SHARE directory, which contains subdirectories for fonts and PMNS (Performance Metric Namespace). This option may be used to control which PMNS is used by overriding the default location specified by $PCP_SHARE.
-p port
Use the Performance Co-Pilot (PCP) data source communication port specified by port. This overrides the default port specified in $PCP_CONF.
-q query
Use the specified query string. This is useful for interactive queries where the query string may contain spaces or other characters that would be misinterpreted by the shell. The query string must be a valid pmseries query.
-r remote_store
Use the specified remote_store to access the Performance Metrics Name Space (PMNS). remote_store is of the form host:port. This option may be used to access a remote PMNS instead of the local one defined by $PCP_PMNS_SOURCE.
-T timezone
Use the specified timezone when interpreting time specifications. This overrides the default time zone, which is determined by the format of the environment variable TZ as described in environ(7).
-?, --help
Display usage message and exit.

The following sample query shows several fundamental aspects of the pmseries query language:

$ pmseries 'kernel.all.load{hostname:"toium"}[count:2]'
eb713a9cf472f775aa59ae90c43cd7f960f7870f
    [Thu Nov 14 05:57:06.082861000 2019] 1.0e-01 b84040ffccd54f839b65140cf139bab51cbbcf62
    [Thu Nov 14 05:57:06.082861000 2019] 6.8e-01 a60b5b3bf25e71071c41934fa4d7d251f765f30c
    [Thu Nov 14 05:57:06.082861000 2019] 6.4e-01 e1974a062375e6e62370ffadf5b0650dad739480
    [Thu Nov 14 05:57:16.091546000 2019] 1.6e-01 b84040ffccd54f839b65140cf139bab51cbbcf62
    [Thu Nov 14 05:57:16.091546000 2019] 6.7e-01 a60b5b3bf25e71071c41934fa4d7d251f765f30c
    [Thu Nov 14 05:57:16.091546000 2019] 6.4e-01 e1974a062375e6e62370ffadf5b0650dad739480

This query returns the two most recent values for all instances of the kernel.all.load metric with a label.hostname matching the regular expression "toium". This is a set-valued metric (i.e., a metric with an ``instance domain'' which in this case consists of three instances: 1, 5 and 15 minute averages). The first column returned is a timestamp, then a floating point value, and finally an instance identifier timeseries hash (two values returned for three instances, so six rows are returned).     Source: 0e89c1192db79326900d82131c31399524f0b3ee

    inst [1 or "1 minute"] series b84040ffccd54f839b65140cf139bab51cbbcf62
    inst [5 or "5 minute"] series a60b5b3bf25e71071c41934fa4d7d251f765f30c
    inst [15 or "15 minute"] series e1974a062375e6e62370ffadf5b0650dad739480
    inst [1 or "1 minute"] labels {"agent":"linux","hostname":"toium"}
    inst [5 or "5 minute"] labels {"agent":"linux","hostname":"toium"}
    inst [15 or "15 minute"] labels {"agent":"linux","hostname":"toium"}

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.
