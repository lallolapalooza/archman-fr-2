PMLOGPUSH(1) Manuel des commandes générales PMLOGPUSH(1)

NOM

pmlogpush - pousser une archive vers un serveur pmproxy distant

SYNTAXE

pmlogpush [-vV?] [-D debug] [-h hôte] [-p port] [-s unix] [-Z fuseau_horaire] archive

DESCRIPTION

pmlogpush envoie le contenu d'une archive Performance Co-Pilot (PCP) à un serveur HTTP (typiquement un démon pmproxy(1) distant) en utilisant le sous-ensemble de l'API logger de PMWEBAPI(5). L'archive doit avoir été créée précédemment à l'aide de pmlogger(1).

Cette archive doit être complète et terminée (pas en cours d'écriture). Une fonctionnalité comparable est disponible directement depuis pmlogger en utilisant l'option -R, pour pousser des archives à distance pendant qu'elles sont en cours d'écriture.

OPTIONS

Les options de ligne de commande disponibles sont :

-h nom_hote, --host=nom_hote
Le nom_hote du serveur pmproxy distant pour recevoir l'archive PCP donnée.
-p port, --port=port
Le numéro de port du socket Internet où le serveur pmproxy distant écoute, attendant de recevoir l'archive PCP donnée. Le port par défaut est 44322.
-s chemin, --unix=chemin
Le chemin du socket de domaine Unix où un serveur pmproxy local écoute (localement), attendant de recevoir l'archive PCP donnée.
-v, --verbose
Augmente les informations de diagnostic rapportées lorsque pmlogpush s'exécute.
-?, --help
Affiche le message d'utilisation et quitte.
-V, --version
Affiche le numéro de version et quitte.

FICHIERS

$PCP_LOG_DIR/pmproxy/<nom_hote>
Répertoire par défaut pour les archives PCP poussées créées (à distance) par le serveur pmproxy receveur. Le nom_hote est extrait de l'*archive* donnée, tout comme l'heure de début de l'enregistrement - ensemble, ces propriétés sont utilisées pour nommer l'archive poussée à l'extrémité receveuse (c'est-à-dire par le serveur pmproxy).

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active l'affichage de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à fournir des indications aux développeurs plutôt qu'aux utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification. L'option de débogage http est particulièrement intéressante pour cet utilitaire.

VOIR AUSSI

PCPIntro(1), pmlogger(1), pmproxy(1), PMWEBAPI(3), pcp.conf(5) et pcp.env(5).
