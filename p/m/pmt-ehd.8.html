Nom

pmt-ehd - créer une image disque chiffrée

Syntaxe

pmt-ehd [-DFx] [-c chiffrementfs] [-h hash] [-k bitsclésfschiffrement] [-t typessf] [-H chemin_en_tête] -f chemin_conteneur -s taille_en_Mo

Options

Les options obligatoires absentes sont demandées interactivement, et pmt-ehd se terminera si l'entrée standard n'est pas un terminal.

-D
Activer les chaînes de débogage.
-F
Forcer une opération qui demanderait normalement une confirmation interactive. Plusieurs -F peuvent être spécifiés pour plus de force.
-c chiffrement
Le chiffrement à utiliser pour le système de fichiers. Ceci peut prendre n'importe quelle valeur reconnue par cryptsetup(8), généralement sous la forme "chiffrement-mode[-suppléments]". Il est recommandé d'utiliser aes-cbc-essiv:sha256 (c'est la valeur par défaut) ou aes-xts-essiv:sha256.
-f chemin
Stocker la nouvelle image disque à l'emplacement chemin. Si le fichier existe déjà, pmt-ehd demandera avant d'écraser, sauf si -F est donné. Si chemin fait référence à un lien symbolique, pmt-ehd agira avec encore plus de prudence.
-H chemin
Stocker un fichier de métadonnées détaché (séparé) avec un nouvel en-tête LUKS à l'emplacement chemin. Si le fichier existe déjà, pmt-ehd demandera avant d'écraser, sauf si -F est donné. Si chemin fait référence à un lien symbolique, pmt-ehd agira avec encore plus de prudence. Par défaut, aucun en-tête détaché n'est utilisé. Correspond à l'option `cryptsetup --header`.
-h hash
Message digest/hash utilisé pour la dérivation de clé dans l'étape PBKDF2. La valeur par défaut est sha512.
-i chiffrement
(Cette option a été supprimée dans pam_mount/pmt_ehd 2.11.)
-k bitsclés
La taille de la clé pour le chiffrement spécifié avec -c. Certains chiffrements supportent plusieurs tailles de clés, AES par exemple est disponible avec au moins les tailles de clés 192 et 256. La valeur par défaut est 256 (pour correspondre à aes-cbc-essiv). Notez que XTS utilise deux clés, mais dérivées du même matériel de clé, donc aes-cbc-256 est équivalent à aes-xts-512, et aes-cbc-128 à aes-xts-256.
-p chemin
(Cette option a été supprimée dans pam_mount/pmt_ehd 2.11.)
-s taille
La taille initiale du système de fichiers chiffré, en mégaoctets. Cette option est ignorée lorsque le système de fichiers est créé sur un périphérique bloc.
-t typessf
Système de fichiers à utiliser pour le système de fichiers chiffré. La valeur par défaut est xfs.
-u utilisateur
Donner les fichiers conteneur et cléfs à utilisateur (car le programme s'exécute généralement en tant que root, et les fichiers conserveraient sinon la propriété root).
-x
Ne pas initialiser le conteneur avec des octets aléatoires. Cela peut avoir un impact sur la confidentialité.

Description

pmt-ehd peut être utilisé pour créer un nouveau conteneur chiffré, et remplace le script mkehd précédent ainsi que toutes les HOWTOs expliquant comment le faire manuellement. Sans aucun argument, pmt-ehd demandera interactivement tous les paramètres manquants. Pour créer un conteneur d'une taille de 256 Mo, utilisez :

pmt-ehd -f /home/user.cont -s 256
