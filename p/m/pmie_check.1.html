PMIE_CHECK(1) Manuel des commandes générales PMIE_CHECK(1)

NOM

pmie_check, pmie_daily - administration du moteur d'inférence Performance Co-Pilot

SYNTAXE

$PCP_BINADM_DIR/pmie_check [-CNPpsTV?] [-c contrôle] [-l journal]
$PCP_BINADM_DIR/pmie_daily [-NV?] [-c contrôle] [-k suppression] [-l journal] [-m adresses] [-x compression] [-X programme] [-Y regex]

DESCRIPTION

Cette série de scripts shell et de fichiers de contrôle associés peut être utilisée pour créer un régime personnalisé d'administration et de gestion pour le moteur d'inférence Performance Co-Pilot (voir PCPIntro(1)), pmie(1).

pmie_check peut être exécuté à tout moment de la journée et vérifie qu'un ensemble souhaité de processus pmie est en cours d'exécution. Sinon, il (re)démarre tout processus d'inférence manquant.

pmie_daily est destiné à être exécuté une fois par jour, de préférence tôt le matin, dès que possible après minuit. Sa tâche est de faire tourner les fichiers journal des processus pmie en cours d'exécution - ces fichiers peuvent croître sans limite si l'action ``print'' est utilisée, ou si toute autre action pmie écrit dans ses flux stdout/stderr. Après une certaine période, les anciens fichiers journaux pmie sont supprimés.

OPTIONS

Les options de ligne de commande disponibles sont :

-c contrôle, --control=contrôle
pmie_check et pmie_daily sont contrôlés par un ou plusieurs fichiers de contrôle du moteur d'inférence PCP qui spécifient les instances pmie à gérer. Le fichier de contrôle par défaut est $PCP_PMIECONTROL_PATH mais un autre peut être spécifié en utilisant l'option -c. Si le répertoire $PCP_PMLOGGERCONTROL_PATH.d (ou contrôle.d de l'option -c) existe, alors le contenu de tout fichier de contrôle supplémentaire qu'il contient sera ajouté au fichier de contrôle principal (qui doit exister).
-C
Cette option amène pmie_check à interroger les informations du niveau de service système pour pmie, et à les utiliser pour déterminer s'il faut démarrer des processus ou non.
-k période, --discard=période
La période de rétention des journaux est de 14 jours par défaut, mais cela peut être modifié en utilisant cette option. Deux valeurs spéciales sont reconnues pour la période de suppression, à savoir 0 pour ne conserver aucun fichier journal au-delà du courant, et forever pour empêcher la suppression de tout fichier journal.
-l fichier, --logfile=fichier
Afin de garantir qu'aucun courrier ne soit envoyé involontairement lorsque ces scripts sont exécutés depuis cron(8), les diagnostics sont toujours envoyés à des fichiers journaux. Par défaut, ces fichiers sont $PCP_LOG_DIR/pmie/pmie_daily.log et $PCP_LOG_DIR/pmie/pmie_check.log mais cela peut être modifié en utilisant l'option -l. Si ce fichier journal existe déjà lorsque le script démarre, il sera renommé avec un suffixe .prev (écrasant tout fichier journal sauvegardé précédemment) avant que les diagnostics ne soient générés dans le nouveau fichier journal.
-m adresses, --mail=adresses
L'utilisation de cette option amène pmie_daily à construire un résumé des fichiers journaux générés pour tous les hôtes surveillés au cours des dernières 24 heures (les lignes correspondant à `` OK '' sont supprimées), et à envoyer ce résumé par e-mail à l'ensemble des adresses séparées par des espaces.
-N, --showme
Cette option active un mode ``montre-moi'', où les actions des programmes sont affichées, mais pas exécutées, dans le style de ``make -n''. Utiliser -N conjointement avec -V maximise les capacités de diagnostic pour le débogage.
-s, --stop
L'utilisation de cette option fournit la fonctionnalité inverse de pmie_check, permettant de fermer proprement l'ensemble des processus pmie.
-p, --skip-primary
Si cette option est spécifiée pour pmie_check, alors toute ligne provenant des fichiers de contrôle pour le pmie primaire sera ignorée. Cette option est prévue pour les environnements où un démon système, comme systemd(1), est responsable du contrôle (démarrage, arrêt, redémarrage, etc.) du pmie primaire.
-P, --only-primary
Si cette option est spécifiée pour pmie_check, alors seule l'entrée pmie primaire dans les fichiers de contrôle sera traitée. Ceci est l'opposé logique de l'option -p décrite ci-dessus et est destiné à être utilisé par des scripts RC qui démarrent uniquement le pmie primaire, comme l'unité pmie.service. Les options -p et -P de pmie_check sont mutuellement exclusives.
-T, --terse
Cette option de pmie_check produit une sortie moins verbeuse que la sortie par défaut. Ceci est plus approprié pour une ``ferme'' pmie où de nombreuses instances de pmie sont censées être en cours d'exécution.
-V, --verbose
La sortie de l'exécution des scripts par cron peut être étendue en utilisant l'option -V aux scripts, ce qui activera le traçage détaillé de leur activité. Par défaut, les scripts ne génèrent aucune sortie sauf en cas d'erreur ou d'avertissement. Utiliser -N conjointement avec -V maximise les capacités de diagnostic pour le débogage.
-x période, --compress-after=période
Les fichiers journaux peuvent éventuellement être compressés après une certaine période pour économiser de l'espace disque. Ceci est particulièrement utile pour un grand nombre de processus pmie sous le contrôle de pmie_check. L'option -x spécifie le nombre de jours après lesquels compresser les fichiers d'archives de données.
-X programme, --compressor=programme
Cette option spécifie le programme à utiliser pour la compression - par défaut, il s'agit de xz(1).
-Y regex, --regex=regex
Cette option permet de spécifier une expression régulière pour exclure certains fichiers de l'ensemble des fichiers sélectionnés pour la compression - ceci permet de ne compresser que le fichier de données, et empêche également le programme de tenter de le compresser plusieurs fois. La regex par défaut est
"\.(meta|index|Z|gz|bz2|zip|xz|lzma|lzo|lz4|zst)$"
- de tels fichiers sont filtrés en utilisant l'option -v de egrep(1).
-?, --help
Affiche le message d'utilisation et quitte.

CONFIGURATION

Avertissement : Les fichiers $PCP_PMIECONTROL_PATH et $PCP_PMIECONTROL_PATH.d ne doivent pas être accessibles en écriture par un utilisateur autre que root.

Les fichiers de contrôle doivent être personnalisés selon les règles suivantes qui définissent le format actuel (version 1.1) du fichier de contrôle.

1.
Les lignes commençant par un ``#'' sont des commentaires.
2.
Les lignes commençant par un ``$'' sont supposées être des affectations de variables d'environnement dans le style de sh(1), et tout le texte suivant le ``$'' sera traité par eval par le script lisant le fichier de contrôle, et la variable correspondante exportée dans l'environnement. Ceci est particulièrement utile pour définir et exporter des variables dans l'environnement du script administratif, par exemple : 

$ PMCD_CONNECT_TIMEOUT=20

3.
Il doit y avoir une ligne de version dans le fichier de contrôle initial de la forme : 

$ version=1.1

4.
Il devrait y avoir une ligne dans les fichiers de contrôle pour chaque instance pmie de la forme : 


hote o|n o|n journal args

5.
Les champs dans une ligne des fichiers de contrôle sont séparés par un ou plusieurs espaces ou tabulations.
6.
Le premier champ est le nom de t

l'hôte qui est la source par défaut des métriques de performance pour cette instance pmie.
7.
Le deuxième champ indique s'il s'agit d'une instance pmie principale (y) ou non (n). Étant donné que le moteur d'inférence principal doit s'exécuter sur l'hôte local, et qu'il ne peut y avoir qu'un seul moteur principal pour un hôte donné, ce champ ne peut être y que pour une seule instance pmie à la fois, auquel cas le nom de l'hôte doit être le nom de l'hôte local. Lors de la génération des fichiers de configuration pmie, la clause principale indique que pmieconf(1) doit activer toutes les règles du groupe principal, en plus de toutes les autres règles par défaut.
8.
Le troisième champ indique si cette instance pmie doit être démarrée sous le contrôle de pmsocks(1) pour se connecter à un pmcd à travers un pare-feu (y ou n).
9.
Le quatrième champ est le nom du fichier journal d'activité de pmie. Une convention utile est que les instances pmie qui surveillent l'hôte local (nom d'hôte myhost) sont maintenues dans le répertoire $PCP_LOG_DIR/pmie/myhost, tandis que les journaux d'activité pour l'hôte distant mumble sont maintenus dans $PCP_LOG_DIR/pmie/mumble. Ceci est cohérent avec la manière dont pmlogger(1) maintient ses journaux d'activité et ses fichiers d'archives.
10.
Tous les autres champs sont interprétés comme des arguments à passer à pmie(1). Le plus souvent, il s'agirait de l'option -c.

Les lignes de contrôle d'exemple suivantes spécifient une instance pmie surveillant l'hôte local (wobbly) et une autre surveillant les métriques de performance de l'hôte splat.

wobbly  n  PCP_LOG_DIR/pmie/wobbly  -c config.default
splat   n  PCP_LOG_DIR/pmie/splat   -c splat/cpu.conf

Les entrées typiques de crontab(5) pour l'exécution périodique de pmie_daily et pmie_check se trouvent dans $PCP_SYSCONF_DIR/pmie/crontab (sauf si elles sont installées par défaut dans /etc/cron.d) et sont présentées ci-dessous.

# traitement quotidien des journaux pmie
08      0       *       *       *       $PCP_BINADM_DIR/pmie_daily
# toutes les 30 minutes, vérifier que les instances pmie sont en cours d'exécution
28,58   *       *       *       *       $PCP_BINADM_DIR/pmie_check
Lors de l'utilisation de systemd(1) sous Linux, aucune entrée crontab n'est nécessaire car le mécanisme de minuterie fourni par systemd est utilisé à la place.

L'utilitaire pmiectl(1) peut invoquer pmie_check en utilisant la commande sudo(1) pour l'exécuter sous le compte utilisateur ``pcp'' de $PCP_USER. Si sudo est configuré avec l'option non-défaut requiretty (voir ci-dessous), pmie_check peut échouer à s'exécuter car il manque un tty configuré. Ce problème peut être résolu en ajoutant une deuxième ligne (développez $PCP_BINADM_DIR selon votre plateforme) au fichier de configuration /etc/sudoers comme suit :

Defaults requiretty
Defaults!$PCP_BINADM_DIR/pmie_check !requiretty

Notez que le compte PCP non privilégié sous lequel ces commandes s'exécutent utilise /sbin/nologin comme shell, donc l'option requiretty est inefficace ici et peut être désactivée en toute sécurité de cette manière.

FICHIERS

$PCP_PMIECONTROL_PATH
le fichier de contrôle par défaut du moteur d'inférence PCP
Attention : ce fichier ne doit pas être accessible en écriture par un utilisateur autre que root.
$PCP_PMIECONTROL_PATH.d
répertoire optionnel contenant des fichiers de contrôle supplémentaires du moteur d'inférence PCP, typiquement un par hôte
Attention : ces fichiers ne doivent pas être accessibles en écriture par un utilisateur autre que root.
$PCP_SYSCONF_DIR/pmie/crontab
exemple de crontab pour l'exécution automatisée de scripts par $PCP_USER (ou root) - n'existe que si la plateforme ne prend pas en charge le mécanisme /etc/cron.d.
$PCP_VAR_DIR/config/pmie/config.default
emplacement par défaut du fichier de configuration pmie pour un moteur d'inférence localhost, généralement généré automatiquement par pmieconf(1).
$PCP_LOG_DIR/pmie/pmie_check.log
emplacement par défaut pour le fichier journal de pmie_check. Lorsqu'il est exécuté en tant que service démon, si le processus pmie n'a pas pu démarrer ou s'est terminé prématurément, des messages d'erreur peuvent se trouver dans ce fichier, en particulier si le démon n'a pas pu ouvrir son propre fichier journal.
$PCP_LOG_DIR/pmie/pmie_daily.log
emplacement par défaut pour les messages d'erreur générés lors des opérations de maintenance quotidiennes du service pmie.
$PCP_LOG_DIR/pmie/<hostname>
emplacement du répertoire par défaut pour le fichier journal pmie de l'hôte hostname
$PCP_LOG_DIR/pmie/<hostname>/lock
fichier de verrouillage transitoire pour garantir l'exclusion mutuelle lors de l'administration de pmie pour l'hôte hostname - s'il est présent, il peut être supprimé en toute sécurité si ni pmie_daily ni pmie_check ne sont en cours d'exécution
$PCP_LOG_DIR/NOTICES
fichier "notices" de PCP utilisé par pmie(1) et ses associés

ENVIRONNEMENT PCP

Les variables d'environnement préfixées par PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

VOIR AUSSI

egrep(1), PCPIntro(1), pmie(1), pmieconf(1), systemd(1), xz(1) et cron(8).
