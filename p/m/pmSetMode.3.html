PMSETMODE(3) Manuel des fonctions de bibliothèque PMSETMODE(3)

NOM

pmSetMode - définir l'heure de collecte et les paramètres de mode pour le contexte PMAPI actuel

SYNTHSE C

#include <pcp/pmapi.h>

int pmSetMode(int mode,
const struct timespec *when, const struct timespec *delta);

cc ... -lpcp

DESCRIPTION

pmSetMode est utilisé pour définir l'heure de collecte et/ou le mode d'accès aux métriques de performance et aux métadonnées dans le contexte actuel de l'interface de programmation d'applications de performance (PMAPI). Ce mode affecte la sémantique des appels ultérieurs aux routines PMAPI suivantes : pmFetch(3), pmFetchArchive(3), pmLookupDesc(3), pmGetInDom(3), pmLookupInDom(3), pmLookupLabels(3) et pmNameInDom(3).

Principalement destiné à l'analyse rétrospective des métriques de performance à partir d'une archive PCP, les options décrites ci-dessous permettent à une application d'implémenter la recherche d'une heure arbitraire dans l'archive, la lecture, l'avance rapide, le retour arrière, etc. en alternant les appels à pmSetMode et pmFetch(3).

Si mode est PM_MODE_LIVE, toutes les informations sont renvoyées à partir du pool actif de métriques de performance au moment où l'appel PMAPI est effectué, et les deux autres paramètres de pmSetMode (when et delta) sont ignorés. PM_MODE_LIVE est le mode par défaut lorsqu'un nouveau contexte PMAPI est créé avec le type PM_CONTEXT_HOST (c'est-à-dire en récupérant les métriques depuis pmcd (1)) ou PM_CONTEXT_LOCAL, et ce mode est rarement utilisé dans les appels à pmSetMode

Les autres valeurs de mode sont utilisées avec les archives PCP où le contexte PMAPI associé doit être de type PM_CONTEXT_ARCHIVE (lorsqu'il a été créé avec pmNewContext(3)) et le paramètre when définit l'heure actuelle dans l'archive. Toutes les requêtes de valeurs de métriques et de métadonnées (descriptions de métriques et identifiants d'instances des domaines d'instances) seront traitées pour refléter l'état dans l'archive à l'heure actuelle.

Lors de la sélection d'une valeur pour when, l'heure de début de l'archive peut être obtenue à partir du champ ll_start dans la structure renvoyée par un appel à pmGetArchiveLabel(3) ou le champ start dans la structure renvoyée par un appel à pmGetArchiveLabel(3), et l'heure de fin de l'archive peut être obtenue en appelant pmGetArchiveEnd(3)

Comme cas spécial, si when est NULL, alors les arguments mode et delta sont utilisés comme décrit ci-dessous, mais l'heure actuelle dans l'archive n'est pas modifiée.

MODE ARCHIVE PILOTE PAR TEMPS

Si mode est PM_MODE_INTERP, alors lorsque les valeurs de métriques sont récupérées de l'archive avec pmFetch(3), l'heure actuelle est renvoyée comme horodatage dans la structure pmResult et l'heure actuelle progresse ; si delta est positif, l'heure actuelle progresse, sinon l'heure actuelle recule. L'ajustement de l'heure actuelle est appliqué même si pmFetch(3) ne parvient pas à renvoyer de valeurs pour certaines métriques ou renvoie une erreur, par exemple PM_ERR_EOL parce que l'heure actuelle est en dehors de la plage définie par les enregistrements de l'archive.

Lorsque des valeurs de métriques sont demandées via pmFetch(3), l'heure actuelle peut ne pas correspondre exactement aux heures auxquelles les valeurs ont été enregistrées dans l'archive, de sorte que les valeurs de métriques renvoyées sont calculées à partir des valeurs de métriques observées dans l'archive (généralement à des heures proches de l'heure actuelle).

Pour les métriques dont la sémantique est PM_SEM_COUNTER, la valeur calculée est basée sur une interpolation linéaire entre la dernière observation avant l'heure actuelle et la première observation après l'heure actuelle.

Pour les métriques dont la sémantique est PM_SEM_INSTANT ou PM_SEM_DISCRETE, la valeur calculée est basée sur les valeurs dans le voisinage de l'heure actuelle.

Les algorithmes utilisés dans ces calculs dépendent de la sémantique des métriques et des séries temporelles des valeurs observées dans l'archive ; une explication plus complète peut être trouvée dans le livre blanc Explaining Value Interpolation with PCP Archives disponible à l'adresse https://pcp.io/papers/archive-interpolation.pdf.

MODES ARCHIVE PILOTES PAR ENREGISTREMENT

Si mode est PM_MODE_FORW ou PM_MODE_BACK, alors lorsque les valeurs de métriques sont demandées via pmFetch(3), l'archive sera parcourue dans un sens (PM_MODE_FORW) ou dans l'autre (PM_MODE_BACK) temporellement, jusqu'à ce qu'un enregistrement d'archive contenant des valeurs pour au moins une des métriques demandées soit rencontré. Cet enregistrement d'archive est utilisé pour fournir autant de métriques demandées que possible, et celles-ci sont renvoyées avec l'horodatage de l'enregistrement dans l'archive, qui devient la nouvelle heure actuelle.

Notez que toutes les métriques demandées via pmFetch(3) qui n'ont pas de valeur dans l'enregistrement d'archive à la nouvelle heure actuelle ne renverront aucune valeur, et ce mode est donc plus utile pour les archives où toutes les métriques d'intérêt ont été enregistrées régulièrement à la même heure dans l'archive. Sinon, chaque pmFetch(3) contiendra uniquement le sous-ensemble des métriques demandées et les instances associées trouvées dans l'enregistrement d'archive qualifiant.

Le paramètre delta est ignoré, car l'heure actuelle est déterminée par l'horodatage de l'enregistrement d'archive correspondant. Il n'y a donc aucun concept de progression à travers l'archive à intervalles de temps réguliers avec ce mode, bien que si les métriques demandées apparaissent à intervalles réguliers dans l'archive, l'heure actuelle puisse avancer par intervalles réguliers, mais cela est fortuit.

Si aucune métrique qualifiante ne peut être trouvée dans la direction de recherche demandée avant la fin ou le début de l'archive, alors pmFetch(3) renvoie l'indicateur d'erreur spécial, PM_ERR_EOL.

RECOMMANDATIONS

Lors du traitement des archives PCP, PM_MODE_INTERP est préférable car :

  • Cela maximise les informations qui seront renvoyées dans chaque pmFetch(3)
  • Cela renvoie des valeurs à intervalles de temps réguliers, indépendamment de la fréquence d'enregistrement des métriques demandées dans l'archive.
  • Cela fonctionne avec n'importe quelle archive PCP, contrairement aux modes pilotés par enregistrement qui peuvent fonctionner de manière acceptable pour les archives avec un enregistrement régulier de toutes les métriques demandées, mais peuvent ne pas renvoyer de résultats complets ou utiles pour d'autres archives.
  • Ce mode fournit la correspondance sémantique la plus proche de PM_MODE_LIVE et entraîne le moins de surprises pour l'utilisateur lors du passage de la surveillance en temps réel à l'analyse rétrospective.

EXEMPLES

Pour rejouer des métriques interpolées à partir d'une archive à intervalles de 10 secondes, le fragment de code suivant peut être utilisé :

struct timeval mytime;
int mydelta = 10 * 1000;      /* msec */
pmLogLabel label;
pmResult result;
pmNewContext(PM_CONTEXT_ARCHIVE, "myarchive");
pmGetArchiveLabel(&label);
mytime = label.ll_start;
pmSetMode(PM_MODE_INTERP, &mytime, mydelta)
while (pmFetch(numpmid, pmidlist, &result) != PM_ERR_EOL) {
    /*
     * traiter les valeurs de métriques interpolées à
     * result->timestamp
     */
    . . .
    pmFreeResult(result);
}

Le fragment de code suivant peut être utilisé pour extraire les valeurs de métriques sélectionnées dans une archive dans l'ordre temporel inverse.

struct timespec mytime;
pmResult result;
pmNewContext(PM_CONTEXT_ARCHIVE, "myarchive");
pmGetArchiveEnd(&mytime);
pmSetMode(PM_MODE_BACK, &mytime, NULL);
while (pmFetch(npmid, pmidlist, &result) != PM_ERR_EOL) {
    /*
     * traiter les valeurs de métriques enregistrées à
     * result->timestamp
     */
    . . .
    pmFreeResult(result);
}

Y'>COMPATIBILITÉ

Avant PCP 7.0, l'argument when était une struct timeval et l'argument delta était un int (en unités de millisecondes). Pour prendre en charge la transition PMAPI, l'ancienne interface et la sémantique peuvent être utilisées si les applications sont recompilées avec -DPMAPI_VERSION=2.

Pendant un temps dans PCP 6.x, il y avait une routine avec la même sémantique que pmSetMode actuelle, appelée pmSetModeHighRes, bien que celle-ci soit maintenant dépréciée et que le support au moment de la compilation pour pmSetModeHighRes sera supprimé dans une future version.
