PMDAGETOPTIONS(3) Manuel des fonctions de bibliothèque PMDAGETOPTIONS(3)

NOM

pmdaGetOptions, pmdaGetOpt - obtenir des options à partir des arguments, en analysant les options génériques PMDA

C SYNTAXE

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaGetOptions(int argc,
char *const *argv, pmdaOptions *opts, pmdaInterface *dispatch);

int pmdaGetOpt(int argc,
char *const *argv, const char *optstring, pmdaInterface *dispatch, int *err);

cc ... -lpcp_pmda -lpcp

DESCRIPTION

Ces fonctions sont des enveloppes pour pmgetopt_r(3). Le comportement de chaque fonction est tel que certaines options sont supposées avoir un comportement prédéfini qui initialise plusieurs champs de la structure pmdaInterface. L'interface pmdaGetOptions permet de donner des options courtes et longues, tandis que pmdaGetOpt ne permet que des options courtes.

Les options que pmdaGetOptions et pmdaGetOpt piégeront sont :

-Ddebugspec
Définit les options de débogage PMAPI(3) à debugspec, comme décrit dans PCPIntro(1). Utilisé pour contrôler les niveaux de sortie de trace pendant le débogage.
-ddomaine
Définit le numéro de domaine de cet agent.
-hfichieraide
Obtient le texte d'aide (voir pmdaText(3)) pour les métriques à partir de ce fichier plutôt qu'à partir du chemin spécifié avec pmdaDSO(3) ou pmdaDaemon(3).
-iport
Attend que PMCD se connecte sur le port inet port (numéro ou nom).
-6port
Attend que PMCD se connecte sur le port ipv6 port (numéro ou nom).
-lfichierjournal
Redirige la sortie des diagnostics et de la trace vers fichierjournal.
-p
Attend que PMCD fournisse un tuyau stdin/stdout.
-usocket
Attend que PMCD se connecte sur le socket de domaine unix socket.

L'interface pmdaGetOptions capturera également les options suivantes et les stockera dans le paramètre opts :

-Unomutilisateur
Définit le nom du compte utilisateur sous lequel le PMDA doit s'exécuter.

Une seule des options -i, -6, -p et -u peut être spécifiée. Si aucune de ces trois options n'est donnée, un tuyau (-p) est supposé. Lorsque ces options sont rencontrées par pmdaGetOpt, l'option est traitée et l'option suivante est examinée. Par conséquent, pmdaGetOpt ne retournera que lorsqu'une option autre que celles listées ci-dessus est trouvée, ou que la fin de la liste est atteinte. La valeur retournée sera l'argument ou EOF, respectivement.

Un PMDA peut contrôler quelles options le programme acceptera avec soit l'argument opts, soit optstring. Pour accepter toutes les options, le PMDA doit appeler pmdaGetOptions avec le champ short_options de la structure opts défini sur la macro PMDA_OPTIONS, ou pmdaGetOpt avec la chaîne d'options « D:d:h:i:l:pu:". Toutes les options spécifiques au PMDA doivent être ajoutées à ces chaînes dans le style de getopt(3), et seront retournées par pmdaGetOptions et pmdaGetOpt si elles sont rencontrées.

Lorsqu'une erreur d'utilisation d'option en ligne de commande est détectée dans l'interface pmdaGetOptions, le champ d'erreur de la structure opts contiendra un nombre d'erreurs non nul.

pmdaGetOpt prend un pointeur vers un entier, err, qui est utilisé comme compteur d'erreurs. Cette variable doit être initialisée à zéro avant le premier appel à pmdaGetOpt, et testée lorsque pmdaGetOpt retourne EOF.

Ni pmdaGetOptions ni pmdaGetOpt ne modifient leurs paramètres argc ou argv.

Les variables globales utilisées par l'interface getopt (3) du système peuvent également être utilisées par l'appelant de pmdaGetOpt dans la boucle d'analyse des arguments.

En revanche, l'interface pmdaGetOptions n'utilise aucune variable globale (ni ne les lit, ni ne les modifie). Au lieu de cela, ces variables sont accessibles via les champs opts du même nom.

AVERTISSEMENT

Les options -D, -d, -i, -l, -p et -u ne peuvent pas être réutilisées à d'autres fins par le PMDA, sauf en utilisant la méthode override fournie par l'interface pmdaGetOptions, qui fonctionne de la même manière que décrit pour l'interface pmGetOptions(3) utilisée par les outils clients PMAPI.

Le PMDA doit utiliser PMDA_INTERFACE_2 ou une version ultérieure, comme spécifié dans l'appel à pmdaDSO(3) ou pmdaDaemon(3).

DIAGNOSTICS

pmdaGetOptions et pmdaGetOpt afficheront les mêmes messages d'erreur que getopt.

VOIR AUSSI
