PMREP(1) Manuel des commandes générales PMREP(1)

NOM

pmrep, pcp2csv - rapporteur de métriques de performance

SYNTAXE

pmrep [-12357CdgGHIjkLmnprRuUvVxz?] [-4 action] [-6 métrique-de-tri] [-8|-9 limite] [-a archive] [-A alignement] [--archive-folio folio] [-b|-B échelle-espace] [-c config] [--container conteneur] [-D débogage] [--daemonize] [-e dérivé] [-E lignes] [-f format] [-F fichier-sortie] [-h hôte] [-i instances] [--include-texts] [-J classement] [-K spéc] [-l délimiteur] [-N prédicat] [--no-inst-info] [-o sortie] [-O origine] [-P|-0 précision] [-q|-Q échelle-compte] [-s échantillons] [-S heure-début] [-t intervalle] [-T heure-fin] [-w|-W largeur] [-X label] [-y|-Y échelle-temps] [-Z fuseau-horaire] spéc-métrique [...]

DESCRIPTION

pmrep est un outil personnalisable de reporting de métriques de performance. N'importe quelle métrique de performance disponible, en temps réel ou archivée, système et/ou application, peut être sélectionnée pour le reporting en utilisant une des alternatives de sortie listées ci-dessous avec les options de formatage applicables.

pmrep collecte les valeurs des métriques sélectionnées via les mécanismes de Performance Co-Pilot (PCP), voir PCPIntro(1). Les métriques à rapporter sont spécifiées sur la ligne de commande, dans des fichiers de configuration, ou les deux. Les métriques peuvent être converties et mises à l'échelle automatiquement en utilisant les mécanismes de PCP, soit par défaut, soit par des spécifications de mise à l'échelle par métrique. En plus des métriques existantes, les métriques dérivées peuvent être définies en utilisant les expressions arithmétiques décrites dans pmRegisterDerived(3).

Une large gamme de jeux de métriques (voir ci-dessous) est incluse par défaut, fournissant des rapports sur les détails par processus, la performance NUMA, imitant d'autres outils comme sar(1) et plus, voir les fichiers de configuration pmrep dans $PCP_SYSCONF_DIR/pmrep (typiquement /etc/pcp/pmrep) pour plus de détails. La complétion par tabulation pour les options, métriques et jeux de métriques est disponible pour bash et zsh.

Sauf indication contraire vers un autre hôte par l'option -h, pmrep contactera le démon collecteur de métriques de performance (PMCD, voir pmcd(1)) sur l'hôte local.

L'option -a fait en sorte que pmrep utilise l'ensemble d'archives spécifié au lieu de se connecter à un PMCD. Les options -a et -h sont mutuellement exclusives.

L'option -L fait en sorte que pmrep utilise un contexte local pour collecter les métriques depuis les PMDA DSO (Performance Metrics Domain Agents, « plugins ») sur l'hôte local sans PMCD. Seules certaines métriques sont disponibles dans ce mode. Les options -a, -h et -L sont mutuellement exclusives.

Les métriques d'intérêt sont nommées dans les arguments spéc-métrique. Si un spéc-métrique spécifie un nœud non-feuille dans l'espace de noms des métriques de performance (PMNS), alors pmrep descendra récursivement le PMNS et rapportera tous les nœuds feuilles (c'est-à-dire les métriques) pour ce spéc-métrique. Utilisez pminfo(1) pour lister toutes les métriques (nœuds principaux du PMNS) et leurs descriptions.

Un spéc-métrique a trois formes différentes. Premièrement, sur la ligne de commande, il peut commencer par un deux-points (« : ») pour indiquer un jeu de métriques à lire à partir des fichiers de configuration pmrep (voir -c et pmrep.conf(5)), qui peut alors être composé de n'importe quel nombre de métriques. Deuxièmement, un spéc-métrique commençant par autre chose qu'un deux-points spécifie un nœud PMNS comme décrit ci-dessus, optionnellement suivi de définitions de formatage de sortie des métriques. Cette forme dite compacte d'un spéc-métrique est définie comme suit :


métrique[,libellé[,instances[,unité/échelle[,type[,largeur[,précision[,limite]]]]]]]

Un nœud PMNS valide (métrique) est obligatoire. Il peut être suivi d'un libellé texte utilisé avec la sortie stdout. La définition optionnelle d'instances restreint le reporting csv et stdout aux instances spécifiées de la métrique, ainsi les instances non correspondantes seront filtrées (voir -i). Une unité/échelle optionnelle est applicable aux métriques non-chaînes compatibles en dimensions. Voir ci-dessous pour les spécifications unité/échelle supportées. Par défaut, les métriques de compteurs cumulatifs sont converties en taux, un type optionnel peut être défini sur raw pour désactiver cette conversion en taux. Pour la sortie stdout, une largeur numérique peut être utilisée pour définir la largeur de la colonne de sortie pour cette métrique. Les chaînes trop larges dans la sortie seront tronquées pour tenir dans la colonne. Une précision spécifique à la métrique peut être fournie pour les valeurs de sortie numériques non entières. Enfin, une limite spécifique à la métrique peut être définie pour filtrer les valeurs numériques selon la limite.

En tant que cas spécial pour les métriques qui sont des compteurs avec des unités de temps (nanosecondes à heures), l'unité/échelle peut être utilisée pour changer le reporting par défaut (par exemple, millisecondes / seconde) afin de normaliser dans la plage de zéro à un en la définissant sur sec (voir aussi -y et -Y).

Le spéc-métrique suivant demande que la métrique kernel.all.sysfork soit rapportée sous le libellé texte forks, en la convertissant au taux par défaut de la métrique (compte/s) dans une colonne de largeur 8. Bien que les définitions dans cette forme compacte soient optionnelles, elles doivent toujours être fournies dans l'ordre spécifié ci-dessus, d'où les virgules.


kernel.all.sysfork,forks,,,,8

La troisième forme d'un spéc-métrique, la forme détaillée, est décrite et valide uniquement dans pmrep.conf(5).

Les métriques dérivées sont spécifiées comme les métriques feuilles régulières du PMNS.

Les options via les valeurs d'environnement (voir pmGetOptions(3)) remplacent les valeurs par défaut intégrées correspondantes (s'il y en a). Les options du fichier de configuration remplacent les variables d'environnement correspondantes (s'il y en a). Les options de la ligne de commande remplacent les options du fichier de configuration correspondantes (s'il y en a).

pcp2csv est un alias pour pmrep.

OPTIONS

Les options de ligne de commande disponibles sont :

-0 précision, --precision-force=précision
Comme -P, mais cette option remplacera les spécifications par métrique.
-1, --dynamic-header
Imprime un nouvel en-tête dynamiquement ajusté chaque fois que des changements surviennent dans la disponibilité des métriques et des valeurs d'instances. Par défaut, un en-tête statique qui ne change jamais est imprimé une seule fois. Voir aussi -4, -7 et -E.
-2, --overall-rank
Effectue un classement global des instances dans l'archive. Par défaut, le classement (voir -J) et le reporting se font à chaque intervalle. Avec cette option, toutes les instances et valeurs sont classées avant qu'un résumé ne soit rapporté. Voir pmlogsummary(1) pour d'autres alternatives de reporting de résumé d'archive, incluant les moyennes et les heures de pic pour les valeurs.
-3, --overall-rank-alt
Comme -2, mais imprime les instances de métriques au format spéc-métrique de pmrep, afin de permettre de sélectionner facilement les instances pour une investigation plus poussée.
-4 action, --names-change=action
Spécifie quelle action entreprendre lors de la réception d'un événement de changement de nom de métrique pendant l'échantillonnage. Ces événements se produisent lorsqu'un PMDA découvre de nouvelles métriques quelque temps après son démarrage, et en informe les outils clients en cours d'exécution comme pmrep. Les valeurs valides pour action sont update (mettre à jour les métriques échantillonnées), ignore (ne rien faire - comportement par défaut) et abort (quitter le programme si un tel événement se produit). update implique --dynamic-header.
-5, --ignore-unknown
Ignore silencieusement tout nom de métrique qui ne peut pas être résolu. Au moins une métrique doit être trouvée pour que l'outil démarre.
-6, --sort-metric=métrique-de-tri
Spécifie une métrique de référence pour trier la sortie par valeurs avec -X. Par défaut, l'ordre de tri est décroissant, préfixer le nom de la métrique avec un signe moins (« - ») changera l'ordre pour être ascendant. Voir aussi -J et -N.
-7, --fixed-header
Avec -X, imprime un en-tête fixe une fois (sauf si on utilise -E) incluant toutes les métriques rapportées. Contrairement à l'en-tête statique par défaut,

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Les instances dont les valeurs sont disponibles sont uniquement signalées. Contrairement à l'en-tête dynamique, l'en-tête n'est pas mis à jour même si les valeurs de certaines métriques deviennent (in)disponibles plus tard. Voir aussi **-1** et **-E**.
-8 limit, --limit-filter=limit
Limiter les résultats aux instances dont les valeurs sont supérieures/inférieures à limit. Un entier positif inclura les instances dont les valeurs sont égales ou supérieures à la limite dans le rapport. Un entier négatif inclura les instances dont les valeurs sont égales ou inférieures à la limite dans le rapport. Une valeur nulle n'effectue aucun filtrage par limite. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi **-J** et **-N**.
-9 limit, --limit-filter-force=limit
Comme **-8** mais cette option remplacera les spécifications par métrique.
-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives. Voir aussi **-u**.
-A align, --align=align
Forcer l'échantillon initial à être aligné sur la frontière d'une unité de temps naturelle align. Se référer à PCPIntro(1) pour une description complète de la syntaxe de align.
--archive-folio=folio
Lire les archives source de métriques du folio d'archives PCP créé par des outils comme pmchart(1) ou, moins souvent, manuellement avec mkaf(1).
-b scale, --space-scale=scale
Unité/échelle pour les métriques d'espace (octets), les valeurs possibles incluent **bytes**, **Kbytes**, **KB**, **Mbytes**, **MB**, et ainsi de suite. Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-B scale, --space-scale-force=scale
Comme **-b** mais cette option remplacera les spécifications par métrique.
-c config, --config=config
Spécifier le fichier ou le répertoire config à utiliser. Si config est un répertoire, tous les fichiers qu'il contient se terminant par **.conf** seront inclus. La valeur par défaut est la première trouvée parmi : ./pmrep.conf, $HOME/.pmrep.conf, $HOME/pcp/pmrep.conf, $PCP_SYSCONF_DIR/pmrep.conf, et $PCP_SYSCONF_DIR/pmrep. Voir pmrep.conf(5).
--container=container
Récupérer les métriques de performance du conteneur spécifié, local ou distant (voir **-h**).
-C, --check
Quitter avant de rapporter toute valeur, mais après avoir analysé la configuration et les métriques et imprimé les éventuels en-têtes.
-d, --delay
Lors de la relecture à partir d'une archive, cette option demande que le délai temps réel prédominant soit appliqué entre les échantillons (voir **-t**) pour effectuer une pause, plutôt que le comportement par défaut de relecture à pleine vitesse.
--daemonize
Démoniser au démarrage.
-e derived, --derived=derived
Spécifier les métriques de performance dérivées. Si derived commence par une barre oblique ('/') ou par un point ('.') il sera interprété comme un fichier de configuration des métriques dérivées PCP, sinon il sera interprété comme des expressions de métriques dérivées séparées par des virgules ou des points-virgules. Pour une description complète des métriques dérivées et des fichiers de configuration des métriques dérivées PCP, voir pmLoadDerivedConfig(3) et pmRegisterDerived(3). Alternativement, l'utilisation de la syntaxe de configuration pmrep.conf(5) permet de définir des métriques dérivées dans le cadre des jeux de métriques.

En cas de problèmes avec les métriques dérivées, examinez en détail les pages de manuel susmentionnées et assurez-vous que toutes les métriques requises sont disponibles, en particulier lors de l'utilisation d'archives. Utilisez **-Dderive** pour voir des informations de débogage supplémentaires sur l'analyse des métriques dérivées.

-E lines, --repeat-header=lines
Répéter l'en-tête toutes les lines lignes de sortie. Lorsque vous n'utilisez pas **-1** ou **-7**, utilisez **auto** pour répéter l'en-tête en fonction de la hauteur du terminal. Voir aussi **-1** et **-7**.
-f format, --timestamp-format=format
Utiliser la chaîne de format pour formater l'horodatage. Le format sera utilisé avec la méthode datetime.strftime de Python, qui est très similaire à celle décrite dans strftime(3). Une chaîne de format vide (c'est-à-dire "") supprimera les horodatages de la sortie. La valeur par défaut est **%H:%M:%S** lors de l'utilisation de la cible de sortie stdout. La valeur par défaut est **%Y-%m-%d %H:%M:%S** lors de l'utilisation de la cible de sortie csv.
-F outfile, --output-file=outfile
Spécifier le fichier de sortie outfile. Voir **-o**.
-g, --separate-header
Afficher le numéro de colonne et les informations complètes sur la métrique, une par ligne, avant d'afficher les valeurs des métriques.
-G, --no-globals
Ne pas inclure les métriques globales dans le rapport (voir pmrep.conf(5)).
-h host, --host=host
Récupérer les métriques de performance depuis pmcd(1) sur host, plutôt que depuis localhost par défaut.
-H, --no-header
Ne pas imprimer d'en-têtes.
-i instances, --instances=instances
Récupérer et rapporter uniquement les instances de métriques spécifiées. Par défaut, toutes les instances initialement présentes sont rapportées, sauf lors de l'écriture d'une archive (voir **-o**), où toutes les instances futures seront également rapportées.

Les instances spécifiées sont filtrées à partir des instances initialement présentes lorsque l'outil démarre. Ainsi, les instances qui correspondraient au filtre apparaissant après le démarrage de l'outil ne seront pas rapportées ; utilisez **-j** pour changer cela.

Ceci est une option globale utilisée pour toutes les métriques à valeurs multiples, sauf si un filtre d'instance spécifique à la métrique est fourni dans le cadre d'un metricspec. Par défaut, les métriques "plates" à valeur unique sans instances sont toujours rapportées comme d'habitude ; utilisez **-v** pour changer cela.

instances est une liste séparée par des virgules d'une ou plusieurs spécifications de filtre d'instance. Les filtres contenant des virgules ou des espaces doivent être entourés de guillemets simples (') ou doubles ("). Notez que dans le cadre d'un metricspec sur la ligne de commande, une liste avec plus d'un filtre, et chaque filtre, doit être mise entre guillemets comme montré ci-dessous. Il est également possible de définir un filtre unique avec des barres (|) comme séparateur d'instance dans une expression régulière afin de faciliter la mise entre guillemets, voir ci-dessous.

Plusieurs options **-i** sont autorisées comme moyen alternatif de spécifier plus d'un filtre d'instance non spécifique à la métrique.

Un filtre d'instance individuel peut être l'une des options suivantes :

name
Nom d'instance complet. Par exemple, **sda** pour les instances disk.dev ou **eth0** pour les instances network.interface.
PID
Identifiant de processus pour les instances proc.
command
Nom de base d'un processus pour les instances proc. Par exemple, **pmcd** correspondrait à tous les processus pmcd(1), indépendamment de leur chemin ou de leur PID.
regex
Expression régulière. Par exemple, **.*python.*** correspondrait à toutes les instances dont le nom contient la chaîne **python**, ce qui signifie que cela correspondrait à tous les processus Python, indépendamment de leur chemin, PID ou version.

Par exemple, les commandes suivantes rapporteraient les mêmes instances : 

$ pmrep -i '. minute' kernel.all.load
$ pmrep -i '1 minute','5 minute' kernel.all.load
$ pmrep -i "'1 minute','5 minute'" kernel.all.load
$ pmrep -i '1 minute' -i '5 minute' kernel.all.load
$ pmrep kernel.all.load,,"'1 minute','5 minute'"
$ pmrep kernel.all.load,,'1 minute|5 minute'


Cependant, ceci ne rapporterait que l'instance de 1 minute : 

$ pmrep -i '1 minute','5 minute' kernel.all.load,,'1 minute'


Et ceci rapporterait toutes les instances (en raison de l'expression régulière par métrique) : 

$ pmrep -i '1 minute','5 minute' 'kernel.all.load,,.*'


-I, --ignore-incompat
Ignorer les métriques incompatibles. Par défaut, les métriques incompatibles (c'est-à-dire dont le type n'est pas pris en charge ou qui ne peuvent pas être mises à l'échelle comme demandé) entraîneront l'arrêt de **pmrep** avec un message d'erreur. Avec cette option, toutes les métriques incompatibles sont silencieusement omises du rapport. Cela peut être particulièrement utile lors de la demande de nœuds non terminaux de l'arbre PMNS pour le rapport.
--include-texts
Lors de l'écriture d'une archive PCP, inclure les textes d'aide des métriques PCP dans l'archive créée.
-j, --live-filter
Effectuer un filtrage d'instance en direct. Cela permet de capturer toutes les instances nommées même si des processus sont redémarrés à un moment donné (contrairement à l'absence de filtrage en direct). L'exécution d'un filtrage en direct sur un grand nombre d'instances entraînera une surcharge interne, il est donc conseillé d'être prudent. Voir aussi **-1** et **-n**.
-J rank, --rank=rank
Limiter les résultats aux rank instances les plus élevées/les plus basses des métriques à valeurs multiples. Un entier positif inclura les instances les plus valorisées dans le rapport. Un entier négatif inclura les instances les moins valorisées dans le rapport.
reporting. Une valeur de zéro n'effectue aucun classement. Le classement n'implique pas le tri, voir -6. Voir aussi -2 et -8.
-k, --extended-csv
Écrit la sortie CSV étendue, similaire à sadf(1).
-K spec, --spec-local=spec
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spec est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peuvent être utilisées.
-l delimiter, --delimiter=delimiter
Spécifie le delimiter qui sépare chaque colonne de la sortie csv ou stdout. Le défaut pour stdout est deux espaces (`` '') et une virgule (``,'') pour csv. Lors de l'utilisation d'un délimiteur autre qu'un espace blanc, toutes les occurrences du délimiteur dans les valeurs de chaîne seront remplacées par le caractère underscore (``_''). Notez que de nombreux jeux de métriques par défaut spécifient un délimiteur (qui peut ne pas être une virgule), il peut donc être nécessaire d'utiliser cette option avec les jeux de métriques pour définir explicitement le délimiteur comme une virgule pour la sortie CSV, c'est-à-dire . --delimiter=,
-L, --local-PMDA
Utilise un contexte local pour collecter les métriques des PMDA DSO sur l'hôte local sans PMCD. Voir aussi -K.
-m, --include-labels
Inclut les étiquettes de métriques PCP dans la sortie.
-n, --invert-filter
Effectue le classement avant le filtrage en direct. Par défaut, le filtrage en direct des instances (lorsqu'il est demandé, voir -j) se produit avant le classement des instances (lorsqu'il est demandé, voir -J). Avec cette option, la logique est inversée et le classement se produit avant le filtrage en direct.
-N predicate, --predicate=predicate
Spécifie une liste séparée par des virgules de métriques de référence de filtre predicate. Par défaut, le classement (voir -J) se produit individuellement pour chaque métrique. Avec les prédicats, le classement ne se fait que pour les métriques prédicat spécifiées. Lors de la génération de rapports, le reste des métriques partageant le même domaine d'instance (voir PCPIntro(1)) que le prédicat n'inclura que les instances les plus/moins classées du prédicat correspondant. Le classement n'implique pas le tri, voir -6.

Ainsi, par exemple, en utilisant proc.memory.rss (taille de la mémoire résidente d'un processus) comme métrique predicate avec proc.io.total_bytes et mem.util.used comme métriques à rapporter, seuls les processus utilisant le plus/le moins de mémoire (conformément à -J) seront inclus lors du rapport des octets totaux écrits par les processus. Comme mem.util.used est une métrique à valeur unique (ne partageant donc pas le même domaine d'instance que les métriques liées aux processus), elle sera rapportée comme d'habitude.

--no-inst-info
Omet les informations d'instance des en-têtes. Non applicable avec un en-tête séparé (voir -g).
-o output, --output=output
Utilise la cible output pour la génération de rapports. La cible par défaut est stdout. Les alternatives de cible de sortie disponibles sont :
archive
Enregistre les métriques dans une archive PCP qui peut plus tard être rejouée avec les outils PCP, y compris pmrep lui-même. Voir LOGARCHIVE(5) et PCPIntro(1) pour les détails sur les fichiers d'archives PCP. Nécessite -F.
csv
Imprime les métriques au format CSV (soumis aux options de formatage).
stdout
Imprime les métriques sur stdout (format soumis aux options de formatage).
-O origin, --origin=origin
Lors de la génération de rapports sur les métriques archivées, commence la génération de rapports à origin dans la fenêtre temporelle (voir -S et -T). Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de origin.
-p, --timestamps
Imprime les horodatages. Par défaut, aucun horodatage n'est imprimé.
-P precision, --precision=precision
Utilise la precision pour les valeurs numériques de sortie non entières. Si la valeur est trop large pour sa largeur de colonne, la precision est réduite un par un jusqu'à ce que la valeur tienne, ou pas imprimée du tout si elle ne tient pas. Le défaut est d'utiliser 3 décimales (lorsque applicable). Cette option ne remplacera pas les spécifications possibles par métrique.
-q scale, --count-scale=scale
Unité/échelle pour les métriques de comptage, les valeurs possibles incluent count x 10^-1, count, count x 10, count x 10^2, et ainsi de suite de 10^-8 à 10^7. (Ces valeurs sont actuellement sensibles aux espaces.) Cette option ne remplacera pas les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).
-Q scale, --count-scale-force=scale
Comme -q mais cette option remplacera les spécifications par métrique.
-r, --raw
Sortie des valeurs brutes des métriques, ne convertit pas les compteurs cumulatifs en taux. Lors de l'écriture dans des archives, les valeurs brutes sont toujours utilisées. Cette option remplacera les spécifications possibles par métrique.
-R, --raw-prefer
Comme -r mais cette option ne remplacera pas les spécifications par métrique.
-s samples, --samples=samples
L'argument samples définit le nombre d'échantillons à récupérer et à rapporter. Si samples est 0 ou si -s n'est pas spécifié, pmrep échantillonnera et rapportera en continu (en mode temps réel) ou jusqu'à la fin de l'ensemble des archives PCP (en mode archive). Voir aussi -T.
-S starttime, --start=starttime
Lors de la génération de rapports sur les métriques archivées, le rapport sera limité aux enregistrements enregistrés à partir de starttime. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de starttime.
-t interval, --interval=interval
Définit l'intervalle de génération de rapports à autre chose que la seconde par défaut. L'argument interval suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes). Voir aussi les options -T et -u.
-T endtime, --finish=endtime
Lors de la génération de rapports sur les métriques archivées, le rapport sera limité aux enregistrements enregistrés avant ou à endtime. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de endtime.

Lorsqu'il est utilisé pour définir le temps d'exécution avant que pmrep ne se termine, si aucun samples n'est donné (voir -s), alors le nombre d'échantillons rapportés dépend de l'intervalle (voir -t). Si samples est donné, alors l'intervalle sera ajusté pour permettre le rapport de samples pendant le temps d'exécution. Dans le cas où -T, -s et -t sont tous donnés, endtime détermine le moment réel où pmrep s'exécutera.

-u, --no-interpol
Lors de la génération de rapports sur les métriques archivées, par défaut, les valeurs sont rapportées selon l'intervalle d'échantillonnage sélectionné (option -t), et non selon l'intervalle d'enregistrement réel dans une archive. À cet effet, PCP interpole les valeurs à rapporter sur la base des enregistrements dans l'archive. Avec l'option -u, le rapport non interpolé est activé, chaque valeur enregistrée pour les métriques sélectionnées est rapportée et l'intervalle d'échantillonnage demandé (-t) est ignoré.

Ainsi, par exemple, si une archive PCP contient des valeurs enregistrées toutes les 10 secondes et que l'intervalle d'échantillonnage demandé est de 1 heure, par défaut, pmrep utilisera un schéma d'interpolation pour calculer les valeurs des métriques demandées à partir des valeurs enregistrées à proximité de ces métriques demandées et les valeurs pour chaque heure sont rapportées. Avec -u, chaque enregistrement toutes les 10 secondes est rapporté tel quel (les valeurs rapportées sont toujours soumises à la conversion en taux, utilisez -r ou -R pour désactiver).

-U, --no-unit-info
Omet les informations d'unité des en-têtes.
-v, --omit-flat
Rapporte uniquement les métriques à valeurs définies avec des instances (par exemple, disk.dev.read) et omet les métriques "plates" à valeur unique sans instances (par exemple, kernel.all.sysfork). Voir -i et -I.
-V, --version
Affiche le numéro de version et quitte.
-w width, --width=width
Définit la largeur des colonnes de sortie stdout. Les chaînes seront tronquées à cette largeur. La largeur par défaut est la plus courte qui puisse contenir l'étiquette de texte de la métrique, le minimum forcé est 3. Cette option ne remplacera pas les spécifications possibles par métrique.
-W width, --width-force=width
Comme -w mais cette option remplacera les spécifications par métrique.
-x, --extended-header
Imprime l'en-tête étendu.
-X label, --colxrow=label
Inverse les colonnes et les lignes dans la sortie stdout, rapportant une instance par ligne, en utilisant label comme étiquette textuelle pour la colonne d'instance. Utiliser une chaîne vide ("") pour activer l'inversion sans étiquette de colonne spécifique. Ce changement de sortie permet d'utiliser grep(1) pour filtrer les résultats ou pour plus de précision.
ly mimicker d'autres outils. Voir aussi -i et -6.
-y échelle, --time-scale=échelle
Unité/échelle pour les métriques de temps, les valeurs possibles incluent nanosec, ns, microsec, us, millisec, ms, et ainsi de suite jusqu'à hour, hr. Cette option *ne* remplacera *pas* les spécifications possibles par métrique. Voir aussi pmParseUnitsStr(3).

Similaire à -y, mais cette option remplacera les spécifications par métrique.

EXEMPLES

Les exemples suivants utilisent les installations PCP standard pour collecter les valeurs de métriques, aucun utilitaire externe n'est nécessaire. Les ensembles de métriques commençant par un deux-points référencés font partie de la configuration par défaut de pmrep. Avec bash et zsh, la touche tabulation permet de compléter les options, les métriques et, après un deux-points, les ensembles de métriques.

Afficher les métriques de l'interface réseau sur l'hôte local :

$ pmrep network.interface.total.bytes

Afficher toutes les métriques réseau sortantes pour l'interface wlan0 :

$ pmrep -i wlan0 -v network.interface.out

Afficher l'utilisation totale du slab (en Mo) de deux instances de slab spécifiques :

$ pmrep mem.slabinfo.slabs.total_size,,'kmalloc-4k|xfs_inode',MB

Afficher des informations de type vmstat(8) horodatées en utilisant des mégaoctets au lieu des kilo-octets et inclure également le nombre d'inodes utilisés :

$ pmrep -p -B MB :vmstat vfs.inodes.count

Afficher les lectures et écritures de disque par appareil de l'hôte server1 en utilisant un intervalle de deux secondes et le format de sortie CSV de type sadf(1) :

$ pmrep -h server1 -t 2s -o csv -k disk.dev.read disk.dev.write

Afficher les processus utilisant au moins 100 Mo de mémoire avec des en-têtes dynamiques, utiliser également -g pour afficher les noms d'instance (processus) en entier :

$ pmrep -b MB --limit-filter 100 --dynamic-header proc.memory.rss

Afficher l'ensemble prédéfini de métriques du fichier de configuration par défaut pmrep.conf(5) contenant les détails des requêtes d'E/S par les processus pmlogger actuels :

$ pmrep -gp -i pmlogger :proc-io

Afficher les trois processus consommant le plus de CPU :

$ pmrep -1gUJ 3 proc.hog.cpu

Afficher simultanément des informations de type sar -w et sar -W à partir de l'archive PCP ./20150921.09.13, montrant les valeurs enregistrées entre 15h00 et 17h00 :

$ pmrep -a ./20150921.09.13 -S @15:00 -T @17:00 :sar-w :sar-W

Enregistrer les informations les plus pertinentes relatives au CPU, à la mémoire et aux E/S pour chaque processus Java du système, présent et futur, dans une archive ./a avec un intervalle d'une minute à chaque minute complète, dans un processus d'arrière-plan :

$ pmrep --daemonize -A 1m -t 1m -i '.*java.*' -j -o archive -F ./a \
    :proc-info :proc-cpu :proc-mem :proc-io

Enregistrer les métriques relatives au serveur d'annuaire 389, au système de fichiers XFS, et au CPU/mémoire/disque toutes les cinq secondes pendant cinq minutes dans une archive PCP ./a :

$ pmrep -t 5s -T 5m -o archive -F ./a ds389 xfs kernel.all.cpu mem disk

Enregistrer les informations de mémoire et d'E/S des processus qui sont les trois processus consommant le plus de mémoire :

$ pmrep -o archive -F ./a -J 3 -N proc.memory.rss proc.memory proc.io

ENVIRONNEMENT PCP

Les variables d'environnement commençant par PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

Il convient de noter que PCP_DISCRETE_ONCE peut être défini pour garantir que les valeurs de métriques discrètes ne soient rapportées qu'une seule fois, sauf si elles changent à un moment donné.

OPTIONS DE BOGAGEAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et destinées principalement aux développeurs plutôt qu'aux utilisateurs finaux. debug est une liste d'options de bogageage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir la liste des options de bogageage disponibles et leur signification.

Les options de bogageage spécifiques à pmrep sont les suivantes :

Option Description
