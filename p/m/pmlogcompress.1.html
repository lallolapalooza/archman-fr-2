NOM

pmlogcompress, pmlogdecompress - compresser et décompresser des fichiers d'archive PCP

SYNTAXE

pmlogcompress [-NV?] [-A arg] [-c proglist] [-f prog] [-l limit] [-o type] [-Z min] archive ...
pmlogdecompress [-NV?] [-t dir] archive ...

DESCRIPTION

pmlogcompress et pmlogdecompress supportent la compression et la décompression des fichiers qui constituent une archive Performance Co-Pilot (PCP) ; référez-vous à LOGARCHIVE(5) pour une explication des divers fichiers composants d'une archive PCP.

Les arguments archive peuvent être soit le nom d'un fichier unique dans une archive PCP, soit le nom de base d'une archive PCP, comme ceux générés par pmlogbasename(1). Dans le premier cas, pmlogcompress compressera (ou pmlogdecompress décompressera) uniquement ce fichier, mais dans le second cas, pmlogcompress tentera de compresser (ou pour pmlogdecompress de décompresser) tous les fichiers faisant partie de l'archive PCP associée.

Pour la décompression, le suffixe du nom de chaque fichier associé à archive détermine l'outil de décompression à utiliser.

OPTIONS

Les options de ligne de commande disponibles sont :

-A arg, --arg=arg
arg est utilisé comme argument pour le programme de compression ; probablement utile avec l'option -f afin que le choix du programme de compression soit déterministe.

Le traitement de arg n'est pas sophistiqué, donc les variables d'environnement incorporées, les caractères d'échappement, les caractères "glob" du shell et les espaces blancs doivent être évités.

Plusieurs options -A sont permises et tous les arguments arg seront utilisés.

-c proglist, --command=proglist
Selon d'autres options de ligne de commande, et la disponibilité des programmes de compression installés, le choix du programme lors de la compression peut varier. L'option -c permet de fournir une liste de programmes de compression, soit avec plusieurs options -c et/ou en séparant les noms de programme dans proglist par deux-points, dans le style de la notation $PATH du shell.

La valeur par défaut pour proglist est zstd:xz:bzip2:gzip.

-f prog, --use=prog
Si un seul programme doit être considéré pour la compression, il peut être spécifié via l'option -f. L'effet est le même que si seule une option -c était utilisée, et proglist contenait exactement un nom de programme, à savoir prog.
-l limit, --lower-limit=limit
Lors de la compression, ne pas considérer les fichiers plus petits que limit (en octets).

La valeur par défaut pour limit est 4096.

-N, --show-me
Ne rien faire, mais afficher les commandes qui auraient été exécutées.
-o type, --optimize=type
Lors de la compression, l'option -o tentera de choisir le programme de compression parmi proglist (voir l'option -c ci-dessus) qui fait le « meilleur » travail, où type peut être space pour choisir le programme de compression qui produit le fichier de sortie le plus petit, ou time pour choisir le programme de compression qui utilise le moins de temps CPU.

Si archive est un nom de base d'archive, alors le plus grand des fichiers faisant partie de l'archive PCP associée est sélectionné pour le test, sinon archive sera utilisé pour le test.

L'utilisation de cette option signifie que chacun des fichiers archive sélectionnés sera compressé plusieurs fois, il est donc probable que -o soit utilisé dans des expériences avec -N (et éventuellement -V) pour déterminer le meilleur outil de compression pour l'environnement local et les archives PCP.

-t dir, --dir=dir
Lors de la décompression, tous les fichiers compressés seront (par défaut) remplacés par leur équivalent décompressé. L'option -t modifie ce comportement pour créer un doublon, décompressé, de l'*archive* dans le répertoire dir.

Si archive est un fichier unique, alors seul ce fichier est décompressé dans dir, mais si archive est un nom de base d'archive, alors tous les fichiers de archive seront copiés, et éventuellement décompressés, dans dir.

Si un fichier n'est pas compressé, alors une tentative sera d'abord faite pour créer un lien physique dans dir avec ln(1) et si cela échoue, alors une copie est faite avec cp(1).

dir doit exister avant que pmlogdecompress ne soit exécuté.

-V, --verbose
Augmenter la verbosité.
-Z min, --min-zstd-size=min
xz(1) produit des fichiers compressés plus petits pour les petits fichiers d'entrée, mais à partir d'une certaine taille, le fichier d'entrée devient suffisamment grand pour que zstd(1) produise des fichiers compressés plus petits et zstd est généralement beaucoup plus rapide.

Lorsque xz et zstd sont tous deux pris en compte (voir l'option -c ci-dessus), l'option -Z permet à l'utilisateur de régler le seuil de passage de xz à zstd ; les fichiers d'entrée plus petits que min (en octets) seront compressés avec xz, sinon zstd sera utilisé.

La valeur par défaut pour min est 52428800 (50 Mio).

-?, --help
Afficher le message d'utilisation et quitter.

NOTE

Pour la plupart des utilisateurs, ces outils ne seront pas utilisés directement car la compression et la décompression explicites des archives PCP ne sont pas nécessaires.

Plutôt, si la compression d'archive est activée, elle sera effectuée indirectement par les scripts de gestion d'archive PCP pmlogger_check(1), pmlogger_daily(1) et pmlogger_rewrite(1).

La décompression est gérée de manière transparente lors de la relecture d'archive par les routines qui implémentent l'Interface de Programmation des Métriques de Performance (PMAPI).
