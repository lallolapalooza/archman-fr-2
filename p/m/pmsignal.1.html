PMSIGNAL(1) Manuel des commandes générales PMSIGNAL(1)

NOM

pmsignal - envoyer un signal à un ou plusieurs processus

SYNTAXE

$PCP_BINADM_DIR/pmsignal [-alnp] [-s signal] [PID ...|nom ...]

DESCRIPTION

pmsignal fournit un mécanisme de signalisation d'événements multiplateforme pour être utilisé avec les outils de la suite Performance Co-Pilot. Il peut être utilisé pour envoyer un signal nommé (seuls HUP, USR1, TERM et KILL sont acceptés) à un ou plusieurs processus.

Les processus sont spécifiés directement à l'aide de PID ou en tant que noms de programme (avec les options -a ou -p). Dans le cas all, l'ensemble de tous les processus en cours d'exécution est recherché pour une correspondance de basename(1) avec nom. Dans le cas program, les identifiants de processus sont extraits des fichiers du répertoire $PCP_RUN_DIR où les noms de fichiers correspondent à nom.pid.

L'option -n signale la liste des identifiants de processus qui auraient été signalés, mais aucun signal n'est réellement envoyé.

Si un signal n'est pas spécifié, alors le signal TERM sera envoyé. La liste des signaux pris en charge est signalée lors de l'utilisation de l'option -l.

Sur les plateformes Linux et UNIX, pmsignal est un simple wrapper autour de la commande kill(1). Sous Windows, il n'y a pas d'équivalent direct à ce mécanisme, et donc un mécanisme alternatif a été implémenté - cela n'est honoré que par les outils PCP, cependant, pas par toutes les utilitaires Windows.

OPTIONS

Les options de ligne de commande disponibles sont :

-a, --all
Envoyer le signal à tous les processus nommés.
-l, --list
Lister les signaux pris en charge.
-n, --dry-run
Lister les processus qui seraient affectés.
-p, --program
Extraire les programmes des fichiers PID d'exécution de PCP.
-s signal, --signal=signal
Spécifier le signal à envoyer, l'un des suivants : HUP, USR1, TERM, KILL.
-?, --help
Afficher le message d'utilisation et quitter.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

VOIR AUSSI

basename(1), kill(1), killall(1), pcp.conf(5) et pcp.env(5).
