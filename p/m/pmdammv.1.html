NOM

pmdammv - agent de domaine de métriques de performance pour les valeurs mappées en mémoire (PMDA)

SYNTAXE

$PCP_PMDAS_DIR/mmv/pmdammv [-D debug] [-d domaine] [-l logfile] [-U username]

DESCRIPTION

pmdammv est un agent de domaine de métriques de performance (PMDA) qui expose des métriques de performance au niveau applicatif via des fichiers mappés en mémoire. Il offre un mécanisme d'instrumentation à très faible surcharge, bien adapté aux applications critiques de longue durée pour lesquelles il est souhaitable d'avoir des métriques de performance et des informations de disponibilité activées en permanence.

Le PMDA mmv expose l'instrumentation ajoutée à une application en utilisant les API MMV (voir mmv_stats_init(3) et mmv(5) pour plus de détails). Ces API peuvent être appelées depuis plusieurs langages, y compris C, C++, Perl, Python, Java (via la bibliothèque de classe séparée « Parfait ») et GoLang (via la bibliothèque séparée « Speed »).

Une brève description des options de ligne de commande de pmdammv suit :

-d
Il est absolument crucial que le numéro de domaine de métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire que domaine doit être différent pour chaque PMDA sur un même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé mmv.log est écrit dans le répertoire courant de pmcd(1) au moment du démarrage de pmdammv, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est envoyée sur la sortie d'erreur standard.
-U
Compte utilisateur sous lequel exécuter l'agent. Par défaut, il s'agit du compte non privilégié « pcp » dans les versions actuelles de PCP, mais dans les versions plus anciennes, le compte superutilisateur (« root ») était utilisé par défaut.

INSTALLATION

Premièrement, un modèle de sécurité pour la communication inter-processus entre les applications instrumentées et pmdammv (exécuté en tant que bibliothèque partagée à l'intérieur de pmcd) doit être choisi et mis en place.

Cette communication s'effectue via des fichiers mappés en mémoire, dans un emplacement connu à la fois de pmdammv et des applications instrumentées. Cet emplacement est $PCP_TMP_DIR/mmv, bien que cela soit souvent caché derrière des API applicatives telles que « Parfait » et mmv_stats_init(3). Les permissions définies sur ce répertoire indiquent le modèle de sécurité utilisé.

La méthode la plus sécurisée consiste à utiliser un groupe non privilégié existant, partagé par les applications instrumentées, pmcd et pmdammv, tel que le groupe « pcp ».

# . /etc/pcp.env
# mkdir -m 775 $PCP_TMP_DIR/mmv
# chgrp pcp $PCP_TMP_DIR/mmv

Puisque cette méthode exige que les applications instrumentées utilisent ce groupe non par défaut (voir newgrp(1) et setgid(2)), une alternative courante implique l'utilisation d'un répertoire $PCP_TMP_DIR/mmv accessible en écriture par tous et avec le bit sticky activé (similaire à /tmp et /var/tmp, par exemple).

Cela permet à toute application, exécutée sous n'importe quel compte utilisateur, de communiquer avec le PMDA (qui s'exécute par défaut sous le compte « pcp »). Cela peut ne pas être souhaitable pour tous les environnements et il faut considérer les implications de sécurité de toute configuration de répertoire de ce type (des problèmes de classes similaires existent à ceux qui affectent les répertoires de fichiers temporaires du système).

pmdammv est activé par défaut sur toutes les installations modernes de PCP, et par conséquent les noms, textes d'aide et valeurs des métriques de performance mmv sont disponibles sans le processus habituel d'installation du PMDA (./Install).

Si le répertoire $PCP_TMP_DIR/mmv n'existe pas, le script ./Install peut être utilisé pour créer un répertoire accessible en écriture par tous avec le bit sticky activé pour la communication. Ceci est pour la compatibilité descendante, ainsi que pour la facilité d'utilisation - pour utiliser ce mécanisme, faites ceci en tant que root :

# rmdir $PCP_TMP_DIR/mmv
# cd $PCP_PMDAS_DIR/mmv
# ./Install

Ce processus d'installation ne supprimera pas un répertoire $PCP_TMP_DIR/mmv existant.

Si vous souhaitez annuler l'installation, faites ceci en tant que root :

# cd $PCP_PMDAS_DIR/mmv
# ./Remove

pmdammv est lancé par pmcd et ne doit jamais être exécuté directement. Les scripts Install et Remove informent pmcd de l'installation ou de la suppression de l'agent.

FICHIERS

$PCP_PMCDCONF_PATH
options de ligne de commande utilisées pour lancer pmdammv
$PCP_TMP_DIR/mmv
répertoire contenant les fichiers de valeurs mappées en mémoire
$PCP_PMDAS_DIR/mmv/help
fichier d'aide par défaut pour les métriques mmv
$PCP_PMDAS_DIR/mmv/Install
script d'installation pour l'agent pmdammv
$PCP_PMDAS_DIR/mmv/Remove
script d'annulation d'installation pour l'agent pmdammv
$PCP_LOG_DIR/pmcd/mmv.log
fichier journal par défaut pour les messages d'erreur et autres informations de pmdammv

ENVIRONNEMENT PCP

Les variables d'environnement préfixées par PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DEBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdammv sont les suivantes :

Option Description
appl0 diagnostics verbeux
