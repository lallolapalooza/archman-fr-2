PMIADDINSTANCE(3) Manuel des fonctions de bibliothèque PMIADDINSTANCE(3)

NOM

pmiAddInstance - ajouter un élément à un domaine d'instance dans un contexte LOGIMPORT

C SYNTAXE

#include <pcp/pmapi.h>
#include <pcp/import.h>

int pmiAddInstance(pmInDom indom,
const char *instance, int inst);

cc ... -lpcp_import -lpcp

SYNTAXE PERL

use PCP::LogImport;

pmiAddInstance($indom, $instance, $inst);

DESCRIPTION

Dans le cadre de l'API d'importation de journaux de Performance Co-Pilot (voir LOGIMPORT(3)), pmiAddInstance ajoute un nouvel élément au domaine d'instance identifié par indom.

indom serait normalement construit en utilisant la macro pmInDom_build, par exemple pmInDom_build(PMI_DOMAIN,0) pour le premier domaine d'instance dans le domaine de métriques Performance PMI_DOMAIN (qui est le domaine par défaut pour toutes les métadonnées créées par la bibliothèque LOGIMPORT).

La nouvelle instance doit avoir à la fois un nom externe (instance) et un identifiant d'instance interne (inst) qui est unique parmi toutes les instances dans le domaine d'instance indom. Il existe une « règle d'unicité » spéciale pour instance qui est imposée par pmLookupInDom(3), à savoir que le nom d'instance externe doit être unique dans les caractères non-espaces de début, par exemple les noms d'instance « foo » et « foo bar » sont considérés comme identiques par cette règle et ne sont pas autorisés dans le même domaine d'instance, mais « foo » et « foobar » seraient autorisés.

Une fois défini, le nom d'instance externe peut être utilisé dans les appels à pmiGetHandle(3) et/ou pmiPutValue(3) avec le nom d'une métrique définie sur le même domaine d'instance.

DIAGNOSTICS

pmiAddInstance retourne zéro en cas de succès, sinon une valeur négative qui peut être transformée en message d'erreur en appelant pmiErrStr(3).

VOIR AUSSI

LOGIMPORT(3), pmiAddMetric(3), pmiErrStr(3), pmiGetHandle(3), pmiPutValue(3), pmiPutText(3), pmiPutLabel(3) et pmLookupInDom(3).
