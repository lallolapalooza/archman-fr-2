NOM

pmfind_check - administration de la découverte des collecteurs Performance Co-Pilot

SYNOPIS

$PCP_BINADM_DIR/pmfind_check [-CNV?] [-l fichierjournal]

DESCRIPTION

Ce script shell est utilisé pour intégrer les mécanismes de découverte de service du collecteur Performance Co-Pilot (voir PCPIntro(1)) avec l'administration des services pmie(1) et pmlogger(1), de telle sorte que plusieurs hôtes collecteurs puissent être surveillés depuis un seul hôte centralisé. Il est important de noter que le service pmfind est étroitement intégré aux services pmie et pmlogger, et que ces derniers doivent également être activés si les services doivent être démarrés pour chaque système collecteur que pmfind découvre.

pmfind_check est conçu pour être activé via un démon de gestion de service tel que systemd(1) sous Linux. Il est exécuté à partir d'un minuteur système (soit par systemd, soit par cron sur d'autres systèmes). Une fois par intervalle de minuteur, pmfind tente de découvrir les systèmes collecteurs PCP. Pour chaque système unique trouvé, pmfind_check crée des entrées de fichier de contrôle pmie_check et pmlogger_check, de telle sorte que ces derniers processus puissent gérer un service pmie et pmlogger pour chaque système collecteur découvert.

Lorsqu'il est exécuté via systemd, ces processus seront lancés immédiatement car systemd surveille les fichiers de contrôle des services pour détecter les modifications. Avec systemd, vous pouvez également lancer une découverte de service immédiate avec pmfind et pmfind_check en modifiant le répertoire $PCP_SYSCONF_DIR/pmfind de quelque manière que ce soit.

Lorsqu'il est exécuté depuis cron, la prochaine invocation (également basée sur un minuteur) de pmie_check ou pmlogger_check démarrera et gérera les processus pmie et pmlogger associés.

Les entrées de fichier de contrôle créées par pmfind_check suivent la convention de fichiers individuels pour chaque hôte collecteur. Les fichiers sont nommés en utilisant l'identifiant source (unique) que pmfind calcule. Cet identifiant est un hachage calculé sur la base des étiquettes de contexte (non optionnelles) disponibles sur chaque hôte collecteur, et c'est le même identifiant source rapporté et utilisé par pminfo(1) et pmseries(1).

OPTIONS

Les options de ligne de commande disponibles sont :

-C, --containers
Cette option demande à pmfind_check d'interroger chaque système collecteur découvert pour les conteneurs en cours d'exécution également, qui seront alors surveillés individuellement.
-l fichier, --logfile=fichier
Afin d'éviter l'envoi involontaire d'e-mails lorsque ces scripts sont exécutés depuis cron(8), les diagnostics sont toujours envoyés aux fichiers journaux. Par défaut, ce fichier est $PCP_LOG_DIR/pmfind/pmfind_check.log, mais cela peut être modifié en utilisant l'option -l. Si ce fichier journal existe déjà lorsque le script démarre, il sera renommé avec un suffixe .prev (écrasant tout fichier journal sauvegardé précédemment) avant que les diagnostics ne soient générés dans le nouveau fichier journal.
-N, --showme
Cette option active un mode « montre-moi », où les actions du programme sont affichées, mais non exécutées, dans le style de « make -n ». L'utilisation de -N conjointement avec -V maximise les capacités de diagnostic pour le débogage.
-V, --verbose
La sortie de l'exécution des scripts par cron peut être étendue en utilisant l'option -V des scripts, ce qui activera un traçage détaillé de leur activité. Par défaut, les scripts ne génèrent aucune sortie à moins qu'une condition d'erreur ou d'avertissement ne soit rencontrée. L'utilisation de -N conjointement avec -V maximise les capacités de diagnostic pour le débogage.
-?, --help
Affiche le message d'utilisation et quitte.

CONFIGURATION

Les options de ligne de commande passées à pmie et pmlogger peuvent être personnalisées via le fichier de configuration $PCP_SYSCONFIG_DIR/pmfind.

Consultez les pages de manuel de pmie_check et pmlogger_check pour les détails du format de fichier de contrôle généré par pmfind_check.

Par défaut, le fichier journal pmie de chaque système collecteur sera créé dans $PCP_LOG_DIR/pmie/source et les archives pmlogger seront créées sous $PCP_ARCHIVE_DIR/source. Ceci est cohérent avec la manière dont pmie(1) et pmlogger(1) maintiennent leurs journaux d'activité et leurs fichiers d'archives.

Les entrées typiques de crontab(5) pour l'exécution périodique de pmfind_check sont données dans $PCP_SYSCONF_DIR/pmfind/crontab (sauf si elles sont installées par défaut dans /etc/cron.d) et sont présentées ci-dessous.

# chaque minute, découvrir les services PCP distants
*       *       *       *       *       $PCP_BINADM_DIR/pmfind_check
Lors de l'utilisation de systemd(1) sous Linux, aucune entrée crontab n'est nécessaire car les mécanismes de minuteur et de chemin fournis par systemd sont utilisés à la place.

FICHIERS

$PCP_PMIECONTROL_PATH.d
Fichiers de contrôle du moteur d'inférence PCP pour chaque source de métriques découverte, généralement un par hôte ou conteneur.
Attention : les fichiers ici ne doivent pas être accessibles en écriture par un utilisateur autre que root.
$PCP_PMLOGGERCONTROL_PATH.d
Fichiers de contrôle du journaliseur PCP pour chaque source de métriques découverte, généralement un par hôte ou conteneur.
Attention : les fichiers ici ne doivent pas être accessibles en écriture par un utilisateur autre que root.
$PCP_SYSCONFIG_DIR/pmfind
Arguments par défaut de la ligne de commande pmie et pmlogger, et autres paramètres passés à pmfind.
$PCP_SYSCONF_DIR/pmfind/crontab
Exemple de crontab pour l'exécution automatisée du script par root - existe uniquement si la plateforme ne prend pas en charge le mécanisme /etc/cron.d.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

VOIR AUSSI

PCPIntro(1), pmcd(1), pmfind(1), pmie(1), pmie_check(1), pminfo(1), pmlogger(1), pmlogger_check(1), pmseries(1), systemd(1), crontab(5), et cron(8).

SYNOPIS

pmfind_check [-?] [-h] [-t] [-u] [spec ...]

DESCRIPTION

pmfind_check lit des spécifications de métriques à partir d'un ou plusieurs fichiers (voir pmfind(1)), et vérifie que les métriques spécifiées sont disponibles sur le système. Si une métrique n'est pas disponible, un message d'erreur est imprimé sur la sortie d'erreur standard.

Si aucune spécification n'est donnée, l'entrée standard est lue.

OPTIONS

Les options suivantes sont prises en charge :

-?
Affiche un message d'aide et quitte.
-h
Affiche un message d'aide et quitte.
-t
Imprime la valeur des métriques trouvées sur la sortie standard. Cela peut être utile pour tester que les métriques sont disponibles et que leur récupération ne génère pas d'erreurs.
-u
Force la recherche d'une valeur pour chaque métrique trouvée, même si celle-ci n'est pas instanciée. Ceci est utile pour vérifier que des métriques sont disponibles et peuvent être référencées, mais que leur valeur n'est pas forcément définie.

CONFIGURATION

Aucune configuration n'est nécessaire pour pmfind_check. Il utilise les mêmes mécanismes de configuration que les autres outils du Performance Co-Pilot (PCP).

FICHIERS

$PCP_PMCONFIG_PATH/pmfindspec
Chemin par défaut pour les fichiers de spécification de métriques utilisés par pmfind et pmfind_check.

ENVIRONNEMENT PCP

L'exécution de pmfind_check peut être affectée par les variables d'environnement suivantes :

PCP_DIR
Spécifie le répertoire de base pour les données PCP. La valeur par défaut est /var/lib/pcp.
PCP_LOGCONF_PATH
Chemin de recherche pour les fichiers de configuration des compteurs PCP. La valeur par défaut est /var/lib/pcp/config/pcp.conf.
PCP_PMCONFIG_PATH
Chemin de recherche pour les fichiers de spécification de métriques. La valeur par défaut est /etc/pcp.

pmfind(1), pmprobe(1), pminfo(1).
