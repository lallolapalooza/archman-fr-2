PMGETARCHIVELABEL(3) Manuel des fonctions de bibliothèque PMGETARCHIVELABEL(3)

NOM

pmGetArchiveLabel - récupérer l'enregistrement d'étiquette à partir d'un ensemble d'archives de métriques de performance

SYNTAXE C

#include <pcp/pmapi.h>

int pmGetArchiveLabel(pmLogLabel *lp);

cc ... -lpcp

DESCRIPTION

Dans le cadre du Performance Co-Pilot (PCP), les archives de valeurs de métriques de performance peuvent être accumulées et enregistrées en utilisant le programme pmlogger(1) et l'interface de programmation LOGIMPORT(3).

Les routines pmGetArchiveLabel peuvent être utilisées pour récupérer l'enregistrement d'étiquette à partir d'un ensemble d'archives qui a déjà été ouvert en utilisant pmNewContext(3), ou pmDupContext(3), et ainsi associé au contexte actuel de l'API des métriques de performance (PMAPI).

Le résultat retourné via le pointeur lp est une structure qui doit être pré-allouée par l'appelant et a le format suivant (défini dans pmapi.h).


typedef struct {
  int        magic;       /* PM_LOG_MAGIC | numéro de version du format d'archive */
  pid_t      pid;         /* PID du logger */
  struct timespec start;  /* début de cette archive */
  char       hostname[PM_MAX_HOSTNAMELEN];   /* nom complet de l'hôte de collecte */
  char       timezone[PM_MAX_TIMEZONELEN];   /* générique, fuseau horaire $TZ "écrasé" */
  char       zoneinfo[PM_MAX_ZONEINFOLEN];   /* fuseau horaire $TZ de la plateforme locale */
} pmLogLabel;

pmGetArchiveLabel peut être utilisé avec les archives de version 2 ou 3, cependant un mappage peut être nécessaire avec les archives plus anciennes de version 2, par exemple le temps start n'a qu'une résolution à la microseconde et le champ zoneinfo n'est pas présent. Pour des informations détaillées sur le format des archives sur disque, référez-vous à LOGARCHIVE(5).

Pour une application utilisant pmGetArchiveLabel, les informations les plus utiles de l'étiquette d'archive se trouvent probablement dans les champs start, hostname, timezone et zoneinfo.

Le champ zoneinfo contient les informations les plus détaillées sur le fuseau horaire disponibles, et devrait être utilisé s'il est présent (chaîne de longueur non nulle). Il ne sera présent que dans le cas des archives de version 2 - c'est un nouveau champ ajouté dans le cadre du format de version 3. Le champ timezone sera toujours présent, cependant c'est la valeur de fuseau horaire "écrasée" et dans certaines situations, ce n'est pas le fuseau horaire le plus précis.

Pour les anciennes applications utilisant pmGetArchiveLabel, les informations les plus utiles de l'étiquette d'archive se trouvent probablement dans les champs ll_start, ll_hostname ou ll_tz. Notez que la taille du champ ll_hostname est PM_LOG_MAXHOSTLEN (64 octets) ce qui est inférieur à MAXHOSTNAMELEN (voir gethostbyname(3)) sur certaines plateformes. Ces sémantiques sont nécessaires pour conserver la compatibilité ascendante avec le format de fichier d'archive PCP.

pmGetArchiveLabel retourne zéro en cas de succès.

COMPATIBILITÉ

Avant PCP 7.0 et libpcp.so.4, la structure pmLogLabel était quelque peu différente. Pour supporter la transition PMAPI, l'ancienne interface et les anciennes sémantiques peuvent être utilisées si les applications sont liées avec libpcp.so.3 ou recompilées avec -DPMAPI_VERSION=2.

Pendant un certain temps dans PCP 6.x, il y avait une routine avec la même sémantique que pmGetArchiveLabel actuelle, appelée pmGetHighResArchiveLabel et une structure avec la même définition que pmLogLabel appelée pmHighResLogLabel, bien que celles-ci soient maintenant dépréciées et que le support à la compilation pour pmGetHighResArchiveLabel et pmHighResLogLabel sera supprimé dans une future version.

DIAGNOSTICS

PM_ERR_NOCONTEXT
le contexte PMAPI actuel est soit invalide, soit non associé à un ensemble d'archives

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5). Les valeurs pour ces variables peuvent être obtenues programmatiquement en utilisant la fonction pmGetConfig(3).

VOIR AUSSI

pmlogger(1), LOGIMPORT(3), PMAPI(3), pmDupContext(3), pmGetConfig(3), pmNewContext(3), LOGARCHIVE(5), pcp.conf(5) et pcp.env(5).
