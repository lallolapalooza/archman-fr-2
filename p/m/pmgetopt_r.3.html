PMGETOPTIONS(3) Manuel des fonctions de bibliothèque PMGETOPTIONS(3)

NOM

pmgetopt_r, pmGetOptions, pmGetContextOptions, pmFreeOptions, pmUsageMessage - gestion des lignes de commande pour les outils PMAPI

SYNCHOPSIS

#include <pcp/pmapi.h>

int pmgetopt_r(int argc, char *const *argv, pmOptions *opts);
int pmGetOptions(int argc,
char *const *argv, pmOptions *opts);

int pmGetContextOptions(int ctx, pmOptions *opts);
void pmUsageMessage(pmOptions *opts);
void pmFreeOptions(pmOptions *opts);

cc ... -lpcp

DESCRIPTION

La fonction pmGetOptions fournit des services de traitement des options de ligne de commande pour les outils du moniteur et du collecteur PMAPI(3). Elle est basée sur les variantes thread-safe de l'API GNU getopt_long(3), et diffère principalement par son orientation vers le traitement généralisé des options de ligne de commande standard (de facto) de PCP décrites dans PCPIntro(1). Ces options courantes incluent la spécification de l'hôte et des archives, les fenêtres temporelles, les fuseaux horaires, les comptes d'échantillons, les intervalles de temps, etc.

L'interface principale est pmGetOptions, à laquelle il faut passer le nombre d'arguments argc et le tableau argv, tels que transmis à la fonction main() lors de l'invocation du programme. L'argument final opts décrit l'ensemble des options longues et courtes que l'outil est prêt à traiter, ainsi que d'autres métadonnées concernant la manière dont ces options doivent être traitées.

L'interface pmgetopt_r, utilisée en interne par pmGetOptions, se comporte de manière similaire, mais elle n'effectue aucun traitement d'option commun. Elle est plus adaptée aux processus collecteurs PCP, tandis que les outils moniteurs PCP ont tendance à utiliser pmGetOptions.

L'argument opts consiste en un tableau d'entrées pmLongOpts décrivant les arguments, ainsi que la structure englobante pmOptions, qui sont définies comme suit (les champs internes ne sont pas présentés, par souci de brièveté) :

typedef struct {
    const char *        long_opt;
    int                 has_arg;
    int                 short_opt;
    const char *        argname;
    const char *        message;
} pmLongOptions;
typedef struct {
    int                 version;
    int                 flags;
    const char *        short_options;
    pmLongOptions *     long_options;
    const char *        short_usage;
    pmOptionOverride    override;
    int                 index;
    int                 optind;
    int                 opterr;
    int                 optopt;
    char                *optarg;
    /* [champs internes, non documentés] */
    int                 errors;
    int                 context; /* PM_CONTEXT_{HOST,ARCHIVE,LOCAL} */
    int                 nhosts;
    int                 narchives;
    char **             hosts;
    char **             archives;
    struct timespec     start;
    struct timespec     finish;
    struct timespec     origin;
    struct timespec     interval;
    char *              align_optarg;
    char *              start_optarg;
    char *              finish_optarg;
    char *              origin_optarg;
    char *              guiport_optarg;
    char *              timezone;
    int                 samples;
    int                 guiport;
    int                 padding;
    unsigned int        guiflag : 1;
    unsigned int        tzflag  : 1;
    unsigned int        nsflag  : 1;
    unsigned int        Lflag   : 1;
    unsigned int        zeroes  : 28;
} pmOptions;

Les champs initiaux flags et version décrivent comment le reste de la structure pmOptions doit être interprété. Ces champs peuvent être mis à zéro, spécifiant une interprétation par défaut. Alternativement, la macro PMAPI_VERSION peut être utilisée pour spécifier le niveau d'API à utiliser (actuellement, les valeurs de 3 ou moins sont autorisées). La version 2 est par défaut, la version 3 introduit des champs de fenêtre temporelle et d'intervalle à haute résolution (c'est-à-dire en utilisant struct timespec au lieu de struct timeval). Lors de l'utilisation de cette dernière forme, avant d'inclure <pcp/pmapi.h>, la macro PMAPI_VERSION doit être définie à 3 pour garantir la disposition correcte de la structure pmOptions par l'application. Le champ flags peut être utilisé pour modifier le comportement du traitement des options tel que décrit dans la section ``VALEURS DES FLAGS'' ci-dessous.

Le tableau de structures long_options pmLongOpts doit être terminé par un sentinelle et la macro PMAPI_OPTIONS_END peut être utilisée pour cela. Les entrées individuelles dans le tableau long_options peuvent être de deux types : des en-têtes d'options ou des options réelles. Un en-tête d'option est construit à l'aide de la macro PMAPI_OPTIONS_HEADER, et sert au regroupement des options dans le message d'utilisation. Du texte libre peut être inséré dans le message d'utilisation à tout moment à l'aide de la macro PMAPI_OPTIONS_TEXT - ceci est destiné à du texte explicatif supplémentaire couvrant l'utilisation détaillée qui dépasse la portée des en-têtes ou options individuels. Sinon, l'entrée du tableau spécifie une option. Celles-ci doivent être nommées (long_opt) si une forme d'option longue est autorisée, spécifier si elles prennent ou non un argument (has_arg), spécifier le caractère variant de l'argument (short_opt) si une forme d'option courte est autorisée, et enfin spécifier comment présenter l'option dans le message d'utilisation. Cette dernière composante consiste en une description courte, en un seul mot, de l'argument optionnel (argname) et une description sur une ligne de ce que fait l'option de ligne de commande (message).

La chaîne short_usage est également utilisée uniquement lors de la construction du message d'utilisation. Elle forme la composante du message d'utilisation qui suit le nom du programme (c'est-à-dire argv[0]).

La chaîne optionnelle short_options est la chaîne de spécification d'option normale de getopt, utilisant des caractères individuels (ceux avec arguments sont désignés ainsi à l'aide du caractère ':') - telle qu'utilisée par toutes les implémentations getopt.

Une facilité est fournie pour étendre l'ensemble existant d'options communes avec des options supplémentaires, ainsi que pour réassigner les options standard à des rôles non standard pour des outils individuels. Ce dernier est réalisé en utilisant la méthode override, qui permet de fournir une fonction de rappel qui sera appelée à la réception de chaque argument, avant le traitement commun. Si cette fonction de rappel renvoie une valeur non nulle, le traitement commun sera court-circuité pour cette option, sinon le traitement continue. Ainsi, chaque outil client est libre de choisir exactement quelles options standard il souhaite supporter - cela peut être toutes, certaines, ou aucune, et quoi qu'il choisisse, chaque outil a toujours accès à la capacité d'analyse des options longues et à la facilité de génération des messages d'utilisation.

Les champs restants de la structure pmOptions sont remplis à la suite du traitement des arguments, et sont largement auto-explicatifs. Des discussions supplémentaires à leur sujet sont reportées à la section ``VALEURS DES FLAGS'' ci-dessous. Le champ error contient un compte des erreurs détectées lors du traitement des options. Celles-ci peuvent être des erreurs d'utilisation ou d'exécution, comme indiqué par le champ flags (mis à jour et transmis à l'appelant). Typiquement, un outil en ligne de commande échouera à démarrer avec succès et produira un message d'erreur (par exemple, via pmUsageMessage) si le champ error n'est pas nul à la fin de pmGetOptions ou pmGetContextOptions.

Certains post-traitements des options de ligne de commande ne peuvent être effectués qu'une fois que l'outil a établi un contexte PMAPI via pmNewContext(3). Ce traitement inclut l'utilisation des fuseaux horaires sensibles au contexte (-z), et le traitement des fenêtres temporelles (-A, -O, -S, -T) qui peuvent être affectées par le fuseau horaire, par exemple. La fonction pmGetContextOptions est disponible pour de telles situations, et elle complète tout traitement restant de opts par rapport à l'identifiant de contexte ctx donné.

La fonction pmUsageMessage génère un message d'utilisation pour l'outil, et inclut à la fois les options standard PCP et les options personnalisées pour chaque outil, comme spécifié par le tableau pmLongOptions. Elle prend en charge le regroupement des options (via PMAPI_OPTIONS_HEADER) ainsi que le formatage soigné de toutes les options - courtes et longues - de leurs arguments et des messages explicatifs individuels. Elle construira ce message d'utilisation en utilisant pmprintf(3) sur lequel elle émettra un seul pmflush(3) avant de retourner à l'appelant, à condition que le flag PM_OPTFLAG_USAGE_ERR soit défini dans flags, ce qui se produira automatiquement lors de l'analyse des options, lorsque des erreurs d'utilisation sont détectées.

Dans certaines situations, comme l'enregistrement de listes de spécifications d'hôtes ou de chemins d'archives PCP, la routine pmGetOptions peut allouer de la mémoire et stocker des pointeurs vers celle-ci dans opts. Si un programme souhaite libérer cette mé

VALEURS DES INDICATEURS

PM_OPTFLAG_INIT
Utilisé en interne dans la bibliothèque pour indiquer que l'initialisation a été effectuée, de sorte que lors des appels ultérieurs, elle ne sera pas répétée.
PM_OPTFLAG_DONE
Utilisé principalement en interne dans la bibliothèque pour indiquer que le traitement final des options est terminé. Ce traitement implique la mise en correspondance d'un certain nombre d'options, pour vérifier l'absence d'exclusion mutuelle, par exemple. Il peut y avoir d'autres post-traitements à ce stade, à condition qu'ils ne nécessitent pas de contexte PMAPI.
PM_OPTFLAG_MULTI
Permet de spécifier plus d'un hôte ou d'un ensemble d'archives. Par défaut, un seul a source de métriques est autorisée. Cependant, certains des outils les plus sophistiqués permettent plusieurs sources de métriques, chacune étant gérée dans un contexte séparé. Voir aussi PM_OPTFLAG_MIXED.
PM_OPTFLAG_USAGE_ERR
Indique que la bibliothèque a détecté une erreur d'utilisation de la ligne de commande. Il s'agit d'une erreur telle qu'une option requiert un argument mais qu'aucun n'est fourni, ou que des options conflictuelles sont spécifiées (comme -s et -T).
PM_OPTFLAG_RUNTIME_ERR
Indique que la bibliothèque a détecté une erreur d'exécution. Il s'agit d'une erreur telle que l'échec de la récupération des informations de fuseau horaire auprès de pmcd(1) ou l'échec du chargement d'un espace de noms de métriques alternatif à partir d'un fichier local (via l'option -n).
PM_OPTFLAG_EXIT
Indique une suggestion de la bibliothèque pour que l'outil se termine proprement. Ceci est utilisé lorsque le numéro de version est demandé, par exemple (l'option -V et la macro PMOPT_VERSION).
PM_OPTFLAG_POSIX
Utilise la gestion stricte des arguments de ligne de commande POSIX. Cela signifie que les options et les arguments qui les suivent ne seront pas réordonnés, de sorte que des options supplémentaires ne pourront pas suivre les arguments de la ligne de commande. Cela peut être important pour les outils où les arguments peuvent être des nombres négatifs, par exemple, car ceux-ci ne doivent pas être traités comme des options de ligne de commande dans ce cas.
PM_OPTFLAG_MIXED
Permet de spécifier des sources de métriques à la fois en direct et archivées. Par défaut, un seul type de contexte de métriques est autorisé. Cependant, certains des outils les plus sophistiqués autorisent plusieurs types de contextes. Voir aussi PM_OPTFLAG_MULTI.
PM_OPTFLAG_ENV_ONLY
De nombreuses options peuvent être spécifiées soit via la ligne de commande, soit via des variables d'environnement de noms similaires. Cet indicateur désactive tout analyse des arguments, et modifie uniquement opts en fonction des variables d'environnement. Ceci peut être utile pour les outils qui souhaitent s'assurer qu'aucun conflit d'option de ligne de commande ne se produise entre leur propre ensemble et l'ensemble standard d'options PCP (comme un outil existant, réimplémenté à l'aide des services PMAPI).
PM_OPTFLAG_LONG_ONLY
Traiter uniquement les options longues, pas les options courtes.
PM_OPTFLAG_BOUNDARIES
Le comportement par défaut de pmGetOptions consiste à analyser les options de fenêtre temporelle (à savoir, -A, -O, -S et -T), uniquement si l'une de ces options a été spécifiée sur la ligne de commande. Cependant, cet indicateur peut être utilisé (en particulier avec des contextes d'archive) pour trouver les heures de début et de fin associées au(x) contexte(s), même si aucune option de fenêtre temporelle n'a été spécifiée. Dans le cas d'archives multiples, la fenêtre temporelle est définie comme la fenêtre temporelle englobant toutes les archives.
PM_OPTFLAG_STDOUT_TZ
Le fuseau horaire utilisé sera rapporté sur le flux de sortie standard pendant l'analyse des options. Le comportement par défaut est de ne pas rapporter, mais simplement de retourner les informations de fuseau horaire via les champs timezone (-Z) et tzflag (-z) dans la structure opts.
PM_OPTFLAG_NOFLUSH
Le dernier appel pmflush émis par pmUsageMessage sera ignoré si cet indicateur est défini. Ceci est utile dans les situations où l'appelant souhaite ajouter du texte supplémentaire au message d'utilisation généré avant de vider le tampon.
PM_OPTFLAG_QUIET
Supprime les messages de pmgetopt_r concernant les options de ligne de commande non reconnues. Ceci équivaut à définir le champ opterr dans le paramètre opt (qui imite la variable getopt du même nom).

OPTIONS VIA LES VARIABLES D'ENVIRONNEMENT

Certaines variables d'environnement peuvent être utilisées comme alternative aux options de la ligne de commande. L'utilisation de ces mécanismes est principalement destinée à un usage interne par les outils PCP. Les utilisateurs généraux devraient choisir les options de la ligne de commande car cela indique plus clairement l'intention, rend le débogage des problèmes plus facile et évite la confusion sur les conflits possibles entre les options de la ligne de commande et les variables d'environnement (où les options de la ligne de commande l'emportent généralement).

Le tableau suivant décrit les variables d'environnement qui peuvent être utilisées pour définir des valeurs en remplacement des options de la ligne de commande.

$PCP_ARCHIVE -a --archive source des métriques est une archive PCP
$PCP_ARCHIVE_LIST --archive list une liste d'archives sources de métriques séparées par des virgules
$PCP_FOLIO --archive-folio la source de métriques est un folio d'archives mkaf(1)
$PCP_DEBUG -D --debug une liste d'options de débogage pmSetDebug(3) séparées par des virgules
$PCP_GUIMODE -g --guimode démarrer en mode GUI avec le nouveau contrôle temporel pmtime(1)

COMPATIBILITÉ

Avant PCP 7.0 et libpcp.so.4, les membres start, finish, origin et interval de la structure pmOptions étaient des struct timeval. Pour prendre en charge la transition de PMAPI, les anciennes interfaces et sémantiques peuvent être utilisées si les applications sont liées avec libpcp.so.3 ou recompilées avec -DPMAPI_VERSION=2.

VALEUR DE RETOUR

La fonction pmGetOptions retourne soit lorsqu'elle détecte une option de ligne de commande qui ne fait pas partie de l'ensemble standard de PCP, soit lorsque la fin des options de la ligne de commande a été atteinte (auquel cas -1 est retourné). Les routines pmgetopt_r et pmGetOptions retournent le contrôle à l'appelant de la même manière qu'un appel getopt régulier, la valeur de retour indiquant soit la fin de tout traitement (-1), soit la forme de caractère unique de l'option en cours de traitement, soit zéro pour le cas spécial des options longues uniquement. Pour tous les cas de traitement d'options, la structure opts est retournée contenant les champs optarg, opterr, optopt, optind et index remplis comme d'habitude (n'utilisez **pas** les optarg ou optind globaux de votre bibliothèque C de plateforme, ceux-ci **ne seront pas** modifiés).

pmGetOptions ne retourne pas à l'appelant lorsque des options PCP standard sont en cours de traitement (bien que le mécanisme de remplacement puisse être utilisé pour détecter de telles options si nécessaire).

La fonction pmGetContextOptions retourne zéro en cas de succès, ou un code d'erreur PCP négatif en cas d'échec. Le champ error dans le paramètre opts sera également non nul dans ce dernier cas.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5). Les valeurs pour ces variables peuvent être obtenues par programme en utilisant la fonction pmGetOptions(3).
