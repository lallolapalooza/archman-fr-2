NOM

pmlogcheck - vérifie les données invalides dans une archive PCP

SYNTAXE

pmlogcheck [-lmvwz?] [-D debug] [-n pmnsfile] [-S start] [-T finish] [-Z timezone] archive ...

DESCRIPTION

pmlogcheck affiche des informations sur la nature de toutes les données invalides qu'il détecte dans les fichiers des archives PCP.

Chaque archive a pour nom de base archive et doit avoir été précédemment créée à l'aide de pmlogger(1). Alternativement, archive peut être le nom d'un fichier physique qui fait partie d'une archive PCP.

Lorsque plusieurs options archive sont présentes, toutes les archives PCP correspondantes seront vérifiées, cependant si les options archive sont des noms de fichiers, alors chaque archive PCP associée sera vérifiée au plus une fois.

OPTIONS

Les options de ligne de commande disponibles sont :

-l, --label
Affiche l'étiquette de l'archive, montrant la version du format de l'archive, l'heure et la date de début et de fin (actuelle) de l'archive, et l'hôte à partir duquel les valeurs des métriques de performance ont été collectées.
-m, --metadataonly
Ignore la Pass 3 (voir ci-dessous) et vérifie uniquement les métadonnées de l'archive. Cela peut être substantiellement plus rapide dans les cas où les données de volume n'ont pas besoin d'être vérifiées, en particulier sur les archives avec des volumes de données compressés.
-n pmnsfile, --namespace=pmnsfile
Charge un Espace de Noms de Métriques de Performance (PMNS(5)) alternatif à partir du fichier pmnsfile.
-S starttime, --start=starttime
Spécifie le starttime de la fenêtre temporelle sur laquelle les métriques doivent être vérifiées dans la Pass 3 (voir ci-dessous). Se référer à PCPIntro(1) pour une description complète de la syntaxe pour starttime.
-T endtime, --finish=endtime
Spécifie le endtime de la fenêtre temporelle sur laquelle les métriques doivent être vérifiées dans la Pass 3 (voir ci-dessous). Se référer à PCPIntro(1) pour une description complète de la syntaxe pour endtime.
-v, --verbose
Active le mode verbeux.
-w, --nowrap
Supprime le rapport des dépassements de compteur.
-z, --hostzone
Utilise le fuseau horaire local de l'hôte qui est la source de l'archive des métriques de performance. Par défaut, utilise le fuseau horaire de l'hôte local.
-Z timezone, --timezone=timezone
Utilise timezone pour la date et l'heure. Timezone est au format de la variable d'environnement TZ comme décrit dans environ(7). Par défaut, utilise le fuseau horaire de l'hôte local.
-?, --help
Affiche le message d'utilisation et quitte.

FONCTIONNEMENT

La vérification procède en plusieurs passes, chacune conçue pour valider des relations sémantiques de plus en plus complexes entre les informations d'une archive PCP.

Passe 0

Chaque fichier physique de l'archive PCP est traité pour s'assurer que les enregistrements d'étiquette sont valides et cohérents, et que chaque fichier contient un nombre intégral d'enregistrements physiques avec des champs d'en-tête et de pied de page corrects.

Toute erreur à ce stade est généralement fatale. L'archive PCP est probablement endommagée irrémédiablement, et aucune autre passe de pmlogcheck n'est tentée.

Passe 1

Valide l'intégrité de l'index temporel, généralement archive.index.

L'index temporel étant (à proprement parler) optionnel, les erreurs à ce stade sont gérées en marquant l'index comme corrompu et en l'ignorant pour le reste des passes de pmlogcheck.

Une réparation permanente peut être effectuée en supprimant le fichier d'index temporel, puis en copiant l'archive PCP à l'aide de pmlogrewrite(1) ou pmlogextract(1). Cela créera un nouvel index temporel pour l'archive copiée en tant qu'effet secondaire.

Passe 2

Valide l'intégrité du fichier de métadonnées, généralement archive.meta.

Passe 3

Valide l'intégrité de chaque volume de l'archive PCP, généralement archive.0, archive.1, etc.

Il existe quelques vérifications d'intégrité de base pour s'assurer que le codage des valeurs pour chaque métrique reste cohérent et que les valeurs sont bien formées dans toutes les observations de l'archive.

De plus, les horodatages des observations sont censés être monotoniquement croissants lors du parcours de l'archive.

Une attention particulière est accordée aux métriques de compteur (type de pmLookupDesc(3) est PM_SEM_COUNTER) dont les valeurs sont censées être monotones croissantes. Si les valeurs ne sont pas monotones croissantes, cela peut suggérer qu'un dépassement de compteur s'est produit ou qu'il y a eu une interruption ou une réinitialisation de la source sous-jacente des données de performance qui n'est pas capturée dans l'archive.

Pour chaque métrique de compteur détectée comme ayant dépassé sa valeur maximale à un moment donné dans l'archive, pmlogcheck produit une sortie décrivant le nom de la métrique (avec les identifiants d'instance le cas échéant), le type de stockage interne pour la métrique, la valeur de la métrique avant le dépassement de compteur (avec son horodatage associé), et la valeur de la métrique après le dépassement (également avec un horodatage).

L'option -w peut être utilisée pour supprimer le rapport des dépassements de compteur.

pmlogcheck produit deux formats d'horodatage différents, selon l'intervalle sur lequel il est exécuté. Pour un intervalle supérieur à 24 heures, la date est affichée en plus de l'heure à laquelle le dépassement de compteur s'est produit. Si l'étendue des données vérifiées est inférieure à 24 heures, un format plus précis est utilisé (l'heure est affichée avec une précision milliseconde, mais sans la date).

EXEMPLES

Les exemples suivants sont tous équivalents : 

$ pmlogcheck myarchive
$ pmlogcheck myarchive.0
$ pmlogcheck myarchive.meta
$ pmlogcheck myarchive.0 myarchive.meta


Si le répertoire courant contient plusieurs archives PCP, alors la commande 

$ pmlogcheck *.meta*


les vérifiera toutes, car il y a un fichier .meta pour chaque archive PCP, mais ce fichier peut être compressé (d'où le * final).

FICHIERS

$PCP_VAR_DIR/pmns/*
fichiers de spécification PMNS par défaut
$PCP_LOG_DIR/pmlogger/<hostname>
répertoire par défaut pour les archives PCP contenant les données de performance collectées depuis l'hôte hostname.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active l'affichage de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et destinées principalement à guider les développeurs plutôt que les utilisateurs finaux. debug i
