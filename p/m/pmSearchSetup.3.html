PMSEARCHSETUP(3) Manuel des fonctions de bibliothèque PMSEARCHSETUP(3)

NOM

pmSearchSetup, pmSearchSetSlots, pmSearchSetEventLoop, pmSearchSetConfiguration, pmSearchSetMetricRegistry, pmSearchClose - services de recherche rapides, évolutifs et capables de recherche plein texte

C SYNTAXE

#include <pcp/pmwebapi.h>

int pmSearchSetup(pmSearchModule *module, void *arg);

int pmSearchSetSlots(pmSearchModule *module, void *slots);
int pmSearchSetEventLoop(pmSearchModule *module, void *events);
int pmSearchSetConfiguration(pmSearchModule *module,
struct dict *config);

int pmSearchSetMetricRegistry(pmSearchModule *module,
struct mmv_registry *registry);

int pmSearchClose(pmSearchModule *module);

cc ... -lpcp_web

DESCRIPTION

Les fonctions pmSearchSetup et API associées préparent une application à accéder aux fonctionnalités de recherche rapides et évolutives de métriques, d'instances et de domaines d'instances, capables de recherche plein texte, du Performance Co-Pilot (PCP).

Cette fonctionnalité est fournie par le biais d'API asynchrones, qui fonctionnent de manière pilotée par événements. L'interface décrite ici prépare un module de recherche donné qui associe des routines de rappel à certains événements asynchrones qui surviennent lors du traitement des requêtes de recherche.

En tant que modèle général, toutes les interfaces de ces API qui doivent invoquer des rappels fournis par le programme appelant prendront un paramètre arg opaque (pointeur void *). Ce pointeur sera transmis tel quel et est généralement utilisé pour accéder à une structure de données maintenant l'état dans le programme appelant.

Lorsque la configuration asynchrone est requise par pmSearchSetup, son achèvement sera indiqué par l'utilisation du rappel on_setup, qui fait partie de la structure pmSearchModule passée en argument. Cette structure fournit également la gestion des diagnostics personnalisés, via le rappel on_info. Ceux-ci s'expliquent d'eux-mêmes, voir <pcp/pmwebapi.h> pour les conventions d'appel exactes.

Les rappels enregistrés par pmSearchSetup pour gérer les événements sont les suivants :

pmSearchTextResultCallBack on_text_result
Le rappel est appelé une fois pour chaque élément du résultat de recherche qui correspond à une requête donnée passée par pmSearchTextInDom(3), pmSearchTextQuery(3), pmSearchTextSuggest(3).
pmSearchMetricsCallBack on_metrics
Le rappel est appelé pour les résultats d'un appel à pmSearchInfo(3).
pmSearchDoneCallBack on_done
À l'achèvement de toutes les interfaces asynchrones qui renvoient un succès (code de retour zéro), ce rappel sera appelé. Il fournit un code de statut indiquant le succès global (zéro) ou l'échec (code d'erreur PMAPI négatif) de l'opération.

Les fonctions d'assistance pmSearchSetSlots (serveur clé-valeur), pmSearchSetEventLoop (libuv), pmSearchSetConfiguration (fichier de configuration) et pmSearchSetMetricRegistry (instrumentation MMV) fournissent un mécanisme pour passer l'état de chacun des sous-systèmes associés.

Enfin, un appel à pmSearchClose est utilisé pour terminer les services disponibles à partir d'un module de recherche précédemment établi par pmSearchSetup.

Dans PCP, les utilitaires pmproxy(1) et pmsearch(1) sont les principaux utilisateurs des interfaces, fournissant respectivement des services de recherche REST API et en ligne de commande.

DIAGNOSTICS

Lorsque ces fonctions renvoient un code de statut, il s'agit toujours de zéro en cas de succès. En cas d'échec, un code d'erreur PMAPI négatif est renvoyé.
