PMDAAPACHE(1) Manuel des commandes générales PMDAAPACHE(1)

NOM

pmdaapache - agent de domaine de métriques de performance Apache2 (PMDA)

SYNOPIS

$PCP_PMDAS_DIR/apache/pmdaapache [-D debug] [-d domaine] [-l logfile] [-U username] [-S server] [-P port] [-L location]

DESCRIPTION

pmdaapache est un Agent de Domaine de Métriques de Performance (PMDA) qui extrait les métriques de performance décrivant l'état d'un serveur web Apache.

Le PMDA apache exporte des métriques qui mesurent le taux de requêtes, les tailles cumulées des requêtes, le temps de fonctionnement et divers états de connexion pour les clients actifs.

Ces informations sont obtenues en effectuant une requête HTTP vers l'URL d'état du serveur, qui doit être activée dans le fichier de configuration httpd.conf.

ExtendedStatus on
<Location /server-status>
SetHandler server-status
Order deny,allow
Deny from all
Allow from localhost
</Location>

Une brève description des options de ligne de commande de pmdaapache suit :

-d
Il est absolument crucial que le numéro de domaine des métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire que domaine doit être différent pour chaque PMDA sur un même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé apache.log est écrit dans le répertoire courant de pmcd(1) lorsque pmdaapache est démarré, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est dirigée vers l'erreur standard à la place.
-S
Interroger les informations d'état Apache depuis le serveur nommé plutôt que depuis l'hôte local.
-P
Interroger les informations d'état Apache depuis le port donné plutôt que depuis le port par défaut (80).
-L
Spécifier un emplacement alternatif pour trouver la page server-status.
-U
Compte utilisateur sous lequel exécuter l'agent. Par défaut, c'est le compte non privilégié « pcp » dans les versions actuelles de PCP, mais dans les versions plus anciennes, le compte superutilisateur (« root ») était utilisé par défaut.

INSTALLATION

Si vous souhaitez accéder aux noms, aux textes d'aide et aux valeurs des métriques de performance Apache, faites ce qui suit en tant que root :

# cd $PCP_PMDAS_DIR/apache
# ./Install

Si vous souhaitez annuler l'installation, faites ce qui suit en tant que root :

# cd $PCP_PMDAS_DIR/apache
# ./Remove

pmdaapache est lancé par pmcd(1) et ne devrait jamais être exécuté directement. Les scripts Install et Remove informent pmcd(1) lorsque l'agent est installé ou supprimé.

FICHIERS

$PCP_PMCDCONF_PATH
options de ligne de commande utilisées pour lancer pmdaapache
$PCP_PMDAS_DIR/apache/help
fichier texte d'aide par défaut pour les métriques Apache
$PCP_PMDAS_DIR/apache/Install
script d'installation pour l'agent pmdaapache
$PCP_PMDAS_DIR/apache/Remove
script d'annulation d'installation pour l'agent pmdaapache
$PCP_LOG_DIR/pmcd/apache.log
fichier journal par défaut pour les messages d'erreur et autres informations de pmdaapache

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et destinées principalement aux développeurs plutôt qu'aux utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdaapache sont les suivantes :

Option Description
appl0 trace chaque appel à refreshData()
appl1 signale les erreurs détectées dans refreshData()
appl2 dump les données internes après chaque appel à refreshData()
