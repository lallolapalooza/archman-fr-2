PMDASAMPLE(1) Manuel des commandes générales PMDASAMPLE(1)

NOM

pmdasample - agent de domaine de métriques de performance d'échantillon (PMDA)

SYNTAXE

$PCP_PMDAS_DIR/pmdasample [-D debug] [-d domaine] [-i port] [-l logfile] [-p] [-u socket] [-U username]

DESCRIPTION

pmdasample est un agent de domaine de métriques de performance (PMDA) d'échantillon qui exporte une variété de métriques de performance synthétiques.

Ce PMDA a été développé dans le cadre des tests d'assurance qualité du produit PCP, mais il a d'autres usages, notamment dans le développement de nouveaux clients PCP.

Les métriques exportées par le PMDA d'échantillon couvrent la gamme complète des types de données, des sémantiques de données, de la cardinalité des valeurs, de la stabilité du domaine d'instance et des conditions d'erreur trouvées dans les PMDA réels.

Une brève description des options de ligne de commande de pmdasample suit :

-d
Il est absolument crucial que le numéro de domaine des métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire que domaine doit être différent pour chaque PMDA sur un hôte donné, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-i
Attendre que PMCD se connecte à pmdasample sur le port TCP/IP spécifié. port peut être un numéro de port ou un nom de port.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé sample.log est écrit dans le répertoire courant de pmcd(1) lorsque pmdasample est démarré, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est envoyée sur la sortie d'erreur standard à la place.
-p
Attendre que PMCD crée un tube et que la connexion à pmdasample se fasse via l'entrée standard et la sortie standard. C'est le mode de connexion par défaut.
-u
Attendre que PMCD se connecte à pmdasample sur le socket de domaine Unix nommé socket.
-U
Compte utilisateur sous lequel exécuter l'agent. Par défaut, il s'agit du compte non privilégié "pcp" dans les versions récentes de PCP, mais dans les versions plus anciennes, le compte superutilisateur ("root") était utilisé par défaut.

Au plus l'une des options -i, -p et -u peut être spécifiée.

INSTALLATION

Si vous souhaitez accéder aux noms, aux textes d'aide et aux valeurs des métriques de performance d'échantillon, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/sample
# ./Install

Notez que le script d'installation installe également la version DSO du PMDA d'échantillon, donc il y a en fait deux PMDA installés, et deux ensembles de métriques de performance, à savoir sample.* et sampledso.*.

Si vous souhaitez annuler l'installation (et supprimer les deux PMDA), procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/sample
# ./Remove

pmdasample est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove notifient pmcd(1) lorsque l'agent est installé ou supprimé.

FICHIERS

$PCP_PMCDCONF_PATH
options de ligne de commande utilisées pour lancer pmdasample
$PCP_PMDAS_DIR/sample/help
fichier d'aide par défaut pour les métriques d'échantillon
$PCP_PMDAS_DIR/sample/Install
script d'installation pour l'agent pmdasample
$PCP_PMDAS_DIR/sample/Remove
script d'annulation d'installation pour l'agent pmdasample
$PCP_LOG_DIR/pmcd/sample.log
fichier journal par défaut pour les messages d'erreur et autres informations de pmdasample

ENVIRONNEMENT PCP

Les variables d'environnement dont le préfixe est PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DEBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider au diagnostic des problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdasample sont les suivantes :

Option Description
appl0 diagnostics verbeux pour les domaines d'instances dynamiques et le mappage des métriques
