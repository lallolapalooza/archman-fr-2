PMDAROOTCONNECT(3) Manuel des fonctions de bibliothèque PMDAROOTCONNECT(3)

NOM

pmdaRootConnect, pmdaRootShutdown, pmdaRootContainerHostName, pmdaRootContainerProcessID, pmdaRootContainerCGroupName, pmdaRootProcessStart, pmdaRootProcessWait, pmdaRootProcessTerminate - services de collecteur PCP privilégiés

C SYNTAXE

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaRootConnect(void);
void pmdaRootShutdown(int fd);
int pmdaRootContainerHostName(int fd,
char *name, int namelen, char *buffer, int buflen);

int pmdaRootContainerProcessID(int fd,
char *name, int namelen);

int pmdaRootContainerCGroupName(int fd,
char *name, int namelen, char *buffer, int buflen);

int pmdaRootProcessStart(int fd,
int ipctype, char *label, int labellen, const char *args, int argslen, int *pid, int *infd, int *outfd);

int pmdaRootProcessWait(int fd, int pid, int *status);
int pmdaRootProcessTerminate(int fd, int pid);

cc ... -lpcp_pmda -lpcp

DESCRIPTION

pmdaRootConnect initialise un canal IPC entre un processus collecteur PCP - soit un PMDA(3), soit pmcd(1) lui-même - et le serveur pmdaroot(1).

En cas de succès, la valeur de retour de pmdaRootConnect est un descripteur de fichier de socket de domaine unix(7), qui peut ensuite être passé à chacune des autres API décrites ici. Ce canal peut être utilisé pour effectuer une escalade limitée des privilèges pour des scénarios spécifiques requis par les services collecteurs PCP. Le canal peut être désactivé à l'aide de l'interface pmdaRootShutdown.

CONTENEURS

Plusieurs interfaces sont fournies pour accéder aux facilités de conteneur des distributions Linux modernes, comme requis par divers agents accédant aux fonctionnalités du noyau relatives aux conteneurs.

pmdaRootContainerHostName permet de rechercher le nom d'hôte actuel pour un conteneur nommé au nom d'un processus non privilégié, via l'appel système setns(3) sous Linux. En cas de succès, le nom d'hôte est renvoyé dans le buffer fourni, de taille buflen et la valeur de retour indique la longueur du nom d'hôte.

pmdaRootContainerProcessID effectue une traduction de nom en identifiant de processus - en cas de succès, la valeur de retour est l'identifiant du premier processus démarré (processus 1) dans le conteneur nommé.

pmdaRootContainerCGroupName remplit le buffer fourni avec les noms spécifiques au moteur des groupes de contrôle du noyau qui ont été utilisés pour construire le conteneur identifié par name. En cas de succès, la valeur de retour indique la longueur du nom du cgroup résolu pour le conteneur.

Le nom du conteneur est interprété par pmdaroot(1), qui tente de faire correspondre le nom spécifié avec une des implémentations de conteneurs dont il a connaissance. Par conséquent, l'argument name est potentiellement interprété différemment, en fonction du moteur de conteneur installé, tel que déterminé en interne par pmdaroot).

Dans le cas du moteur de conteneur Docker, par exemple, un nom de conteneur valide peut être l'identifiant de hachage unique, le nom lisible par l'homme, ou toute sous-chaîne d'identifiant unique. C'est l'algorithme utilisé par les outils clients Docker eux-mêmes.

PROCESSUS

Un deuxième ensemble d'interfaces est fourni, permettant au système collecteur de démarrer des processus enfants privilégiés. En particulier, ceux-ci sont utilisés par pmcd(1) afin qu'il puisse démarrer des PMDA privilégiés même lorsqu'il s'exécute sous un compte non privilégié.

Ces interfaces permettent de démarrer des processus (pmdaRootProcessStart), de les récupérer à leur achèvement (pmdaRootProcessWait), et de les terminer de force en utilisant des signaux (pmdaRootProcessTerminate). À ce stade, elles sont uniquement destinées à être utilisées par pmcd lui-même et sont donc décrites ici uniquement pour des raisons d'exhaustivité.

DIAGNOSTICS

Toutes les interfaces pmdaRoot renverront des codes de statut négatifs appropriés pour être passés à pmErrStr_r(3).

VOIR AUSSI

pmcd(1), pmdaroot(1), pmErrStr_r(3), PMDA(3), setns(3) et unix(7).
