PMAREWRITEDATA(3) Manuel des fonctions de bibliothèque PMAREWRITEDATA(3)

NOM

pmaRewriteData - essayer de modifier la version d'un enregistrement de données d'archive

C SYNOPSIS

#include <pcp/pmapi.h>
#include <pcp/libpcp.h>
#include <pcp/archive.h>

int pmaRewriteData(int invers,
int outvers __int32_t *rbuf);

cc ... -lpcp_archive -lpcp

CAVEAT

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API de PCP garanties pour rester fixes entre les versions, et elles peuvent ne pas fonctionner, ou fournir des sémantiques différentes à un moment donné dans le futur.

DESCRIPTION

Un enregistrement de données physique d'une archive de version invers est passé via rbuf et est reformaté si nécessaire pour produire l'enregistrement de données équivalent pour une archive de version outvers.

Les enregistrements de données d'archive fournissent le codage d'un pmResult pour un volume de données d'archive.

Le seul choix sensé pour invers et outvers aujourd'hui est PM_LOG_VERS02 et PM_LOG_VERS03 respectivement, ce qui demanderait une réécriture du format d'archive version 2 vers le format d'archive version 3 (car seules les versions 2 et 3 sont actuellement prises en charge).

Si une réécriture a lieu, l'ancien rbuf sera libéré et un nouveau rbuf sera alloué avec malloc(3). Il est de la responsabilité de l'appelant de s'assurer que cette libération et cette allocation potentielles seront sûres, par exemple, sans références pendantes vers le contenu de rbuf, ou de passer une copie de l'enregistrement s'il est précieux.

DIAGNOSTICS ET VALEURS DE RETOUR

À plusieurs endroits, des erreurs fatales déclencheront un message d'erreur et forceront l'application à se terminer.

S'il n'y a pas de traduction définie de invers à outvers, alors pmaRewriteData renvoie PM_ERR_APPVERSION (une légère perversion de ce code d'erreur).

Si aucune réécriture n'est effectuée, la valeur de retour est 0, sinon une valeur de retour de 1 indique qu'une réécriture a eu lieu et que rbuf a été réalloué.

VOIR AUSSI

free(3), malloc(3), PMAPI(3), et pmaRewriteMeta(3).
