PMWEBTIMERREGISTER(3) Manuel des fonctions de bibliothèque PMWEBTIMERREGISTER(3)

NOM

pmWebTimerRegister, pmWebTimerRelease, pmWebTimerSetMetricRegistry - gestion de liste de minuteurs thread-safe

C SYNTAXE

#include <pcp/pmwebapi.h>

typedef void (*pmWebTimerCallBack)(void *data);
int pmWebTimerRegister(pmWebTimerCallBack callback, void *data);

int pmWebTimerRelease(int seq);
int pmWebTimerSetMetricRegistry(struct mmv_registry *registry);

cc ... -lpcp_web

DESCRIPTION

Les fonctions API pmWebTimerRegister et associées fournissent une API thread-safe pratique pour que les applications gèrent une liste de callbacks pilotés par minuteur. Lors du premier appel à pmWebTimerRegister ou pmWebTimerSetMetricRegistry, un minuteur interne est configuré et initialisé pour se déclencher toutes les 1,0 secondes. Chaque fois que le minuteur se déclenche, toutes les fonctions callback actuellement enregistrées seront appelées en série avec le pointeur opaque data qui a été fourni lors de l'enregistrement de chaque fonction. Le typedef pmWebTimerCallBack fournit un prototype de fonction de rappel approprié.

Toutes les fonctions callback enregistrées doivent être non bloquantes et s'exécuter rapidement et de manière synchrone. Les fonctions callback typiques incluent le rafraîchissement de l'instrumentation, le calcul et la mise à jour des valeurs de métriques de performance, la collecte périodique des déchets et toute autre fonction locale qui nécessite une exécution régulière.

La fonction pmWebTimerSetMetricRegistry offre un moyen pratique à une application de passer un pointeur vers un registry de libpcp_mmv(3) qui a été correctement initialisé par l'application appelante. Ce registry sera utilisé pour créer dynamiquement six métriques de ressources serveur nommées NAME.mem.datasz, NAME.mem.maxrss, NAME.cpu.total, NAME.cpu.sys, NAME.cpu.user et NAME.pid, où NAME est le nom racine PCP PMNS(5) configuré par l'application appelante. Ces métriques devraient être raisonnablement auto-explicatives ; elles fournissent des métriques d'utilisation des ressources provenant de l'application / serveur appelant et utilisent getrusage(2), times(2) et getpid(2).

VALEUR DE RETOUR

La fonction pmWebTimerRegister renvoie un identifiant entier positif qui peut ensuite être utilisé dans un appel à pmWebTimerRelease pour supprimer un minuteur de la liste de minuteurs interne. Lorsqu'un minuteur est supprimé avec un appel à pmWebTimerRelease, les structures de données internes sont libérées. Cependant, l'appelant est responsable de libérer le data associé (car il peut ou non être alloué dynamiquement).

DIAGNOSTICS

En cas d'échec, un code d'erreur PMAPI négatif est retourné dans tous les cas.

VOIR AUSSI

pmproxy(1), mmv_stats_registry(3), PMAPI(3) et PMWEBAPI(3).
