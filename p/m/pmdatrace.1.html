PMDATRACE(1) Manuel des commandes générales PMDATRACE(1)

NOM

pmdatrace - agent de domaine de métriques de performance au niveau de l'application

SYNTAXE

$PCP_PMDAS_DIR/trace/pmdatrace [-D debug] [-d domaine] [-l logfile] [-A access] [-I port] [-M username] [-N buckets] [-T period] [-U units]

DESCRIPTION

pmdatrace est un agent de domaine de métriques de performance (PMDA) qui exporte les métriques de performance des transactions à partir des processus d'application qui utilisent la bibliothèque pcp_trace décrite dans pmdatrace(3).

Une brève description des options de ligne de commande de pmdatrace suit :

-d
Il est absolument crucial que le numéro de domaine des métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire que domaine doit être différent pour chaque PMDA sur le même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé trace.log est écrit dans le répertoire courant de pmcd(1) lorsque pmdatrace est démarré, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est redirigée vers la sortie d'erreur standard.
-A
Contrôle d'accès basé sur l'hôte pour pmdatrace. access doit être une spécification d'autorisation ou de refus, utilisant soit allow:hostspec:maxconns soit disallow:hostspec, où `allow' et `disallow' sont des mots-clés, `hostspec' est une spécification d'hôte conforme au format utilisé par pmcd(1) et pmlogger(1), et `maxconns' est le nombre maximum de connexions autorisées depuis un `hostspec' donné. Utiliser un nombre maximum de connexions de zéro spécifie un nombre illimité de connexions pour le `hostspec' correspondant.
-I
Communiquer avec les clients pcp_trace via le port Internet port spécifié. Ceci peut être alternativement spécifié en définissant $PCP_TRACE_PORT dans l'environnement à un numéro de port valide (l'utilisation de l'option -I remplace ceci). Le numéro de port par défaut est 4323.
-T
period définit la période d'agrégation utilisée pour calculer les moyennes récentes et les extrema. Spécifié comme un intervalle de temps en utilisant la syntaxe décrite dans PCPIntro(1) pour l'argument commun -t de PCP, par exemple 30 seconds ou 1 min. La valeur par défaut est de 60 secondes.
-M
Compte utilisateur sous lequel exécuter l'agent. La valeur par défaut est le compte non privilégié "pcp" dans les versions courantes de PCP, mais dans les versions plus anciennes, le compte superutilisateur ("root") était utilisé par défaut.
-N
En interne, la période d'agrégation est divisée en bucket divisions, et la moyenne mobile est recalculée toutes les période/bucket secondes. Par exemple, les valeurs par défaut correspondent à -T 60 et -N 12, ce qui signifie que la moyenne est recalculée toutes les cinq secondes pour une période couvrant les 60 secondes précédentes.
-U
Cette option permet de configurer la dimension et l'échelle associées à la métrique de valeur d'observation. units est une chaîne de caractères séparée par des virgules de six valeurs entières, qui sont respectivement la dimension spatiale, la dimension temporelle, la dimension de comptage, l'échelle spatiale, l'échelle temporelle et l'échelle de comptage. La dimension et l'échelle par défaut sont "none", ce qui équivaut à présenter "0,0,0,0,0,0" comme argument à -U. Les unités associées à une métrique sont plus facilement consultées à l'aide de l'option -d (description de métrique) de pminfo(1). Le script d'installation décrit ci-dessous parcourt cette option de manière assez explicite, il est donc recommandé d'utiliser le script d'installation pour construire la spécification units.

Essentiellement, les métriques exportées fournissent des statistiques sur le temps d'achèvement de chaque transaction, et un nombre moyen de transactions terminées et de points de surveillance franchis sur une période de temps donnée période.

INSTALLATION

Pour qu'un hôte puisse exporter les noms, le texte d'aide et les valeurs des métriques de performance Trace, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/trace
# ./Install

Si vous souhaitez annuler l'installation, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/trace
# ./Remove

pmdatrace est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove notifient pmcd(1) lorsque l'agent est installé ou supprimé.

fichier journal par défaut pour les messages d'erreur et autres informations de pmdatrace

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider au dépannage, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdatrace sont les suivantes :

Option Description
appl0 analyse d'authentification, changements de client, IPC, actualisations de données et de métadonnées
appl1 données brutes pour les métriques de taux

VOIR AUSSI

PCPIntro(1), pmcd(1), pmtrace(1), PMAPI(3) et pmdatrace(3).
