PMLOGGER_DAILY_REPORT(1) Manuel des commandes générales PMLOGGER_DAILY_REPORT(1)

NOM

pmlogger_daily_report - écrit les rapports de résumé quotidiens de Performance Co-Pilot

SYNTAXE

$PCP_BINADM_DIR/pmlogger_daily_report [-ApV?] [-a fichier_archive] [-f fichier_sortie] [-h nom_hote] [-l fichier_log] [-o repertoire] [-t intervalle]

DESCRIPTION

pmlogger_daily_report écrit des rapports de résumé des performances quotidiens, similaires à ceux produits par sadc(1) et l'utilitaire sa2(8).

Tous les arguments de la ligne de commande sont optionnels et sont destinés à être explicites.

Par défaut, les rapports ne sont pas générés, mais si le paquet pcp-zeroconf a été installé (il y aura des fichiers dans $PCP_VAR_DIR/config/pmlogconf/zeroconf) alors les métriques nécessaires auront été incluses dans le fichier de configuration pmlogger(1) par défaut et les rapports seront générés.

Les rapports sont générés (par défaut) peu après minuit, une fois que pmlogger_daily(1) a terminé la fusion des archives partielles pour générer une archive de l'activité d'hier.

Chaque rapport de résumé des performances est nommé sarXX (où XX est le jour du mois d'hier). Le fichier_sortie peut être modifié avec l'option -f. Le rapport sera écrit dans le répertoire $PCP_LOG_DIR/sa par défaut, mais cela peut être modifié avec l'option -o vers un autre répertoire.

Notez qu'il existe des options de ligne de commande suffisamment flexibles pour que pmlogger_daily_report puisse être utilisé pour lire n'importe quel fichier_archive et écrire le rapport dans n'importe quel répertoire de sortie.

Si l'option -a n'est pas donnée, le fichier_archive d'entrée par défaut est $PCP_ARCHIVE_DIR/NOM_HOTE/YYYYMMDD, où NOM_HOTE est le nom d'hôte local par défaut (sauf s'il est modifié avec l'option -h) et YYYYMMDD est le nom de base de l'archive fusionnée d'hier, telle que produite par pmlogger(1) et pmlogger_daily(1). Si fichier_archive est un répertoire, alors pmlogger_daily_report utilisera toutes les archives PCP trouvées dans ce répertoire pour écrire le rapport (ceci est connu sous le nom de mode multi-archive, et peut être considérablement plus lent que de spécifier une seule archive en entrée).

Les rapports eux-mêmes sont créés par l'utilitaire pmrep(1) en utilisant son fichier de configuration par défaut, voir pmrep.conf(5). Les entrées de configuration de pmrep(1) utilisées pour écrire les rapports sont actuellement codées en dur dans le script pmlogger_daily_report.

Enfin, les archives d'entrée doivent contenir suffisamment de métriques selon les besoins de pmrep(1) pour écrire le rapport. Sur les plateformes qui le supportent, le paquet pcp-zeroconf configure la journalisation PCP comme requis pour cela - d'où l'utilisation de pmlogger_daily_report avec la configuration de pmlogger(1) qui est configurée par pcp-zeroconf. Comme son nom l'indique, pcp-zeroconf ne nécessite aucune configuration supplémentaire après l'installation pour capturer les archives nécessaires à pmlogger_daily_report.

OPTIONS

Les options de ligne de commande disponibles sont :

-a archive
Spécifie un fichier archive d'entrée alternatif ou un chemin de répertoire.
-A
Utilise les heures de début et de fin de l'archive d'entrée pour le rapport, par opposition au comportement par défaut de 24 heures à partir de minuit hier.
-f nom_fichier
Spécifie un nom_fichier de sortie alternatif. -h nom_hote Spécifie un nom_hote alternatif à utiliser dans le chemin du fichier archive d'entrée par défaut.
-l fichier, --logfile=fichier
Afin de s'assurer que le courrier ne soit pas envoyé involontairement lorsque ce script est exécuté depuis pmlogger_daily(1), les diagnostics sont toujours envoyés à un fichier journal. Par défaut, ce fichier est $PCP_LOG_DIR/pmlogger/pmlogger_daily_report.log mais cela peut être modifié à l'aide de l'option -l. Si ce fichier journal existe déjà lorsque le script démarre, il sera renommé avec un suffixe .prev (écrasant tout fichier journal sauvegardé précédemment) avant que les diagnostics ne soient générés dans le fichier journal.
-p
Si cette option est spécifiée, l'état du traitement quotidien est interrogé et s'il n'a pas été effectué au cours des dernières 24 heures, il est effectué maintenant. Avec cette option, pmlogger_daily_report se termine simplement si le traitement du jour précédent a déjà été effectué.

Cette option n'est plus requise car l'interrogation de pmlogger_daily(1) garantira que le rapport sera généré, cependant l'option est conservée pour des raisons de compatibilité ascendante.

-t intervalle
Spécifie l'intervalle d'échantillonnage utilisé lors de la génération du rapport, dans le format décrit dans PCPIntro(1). La valeur par défaut est toutes les 10 minutes.
-V, --verbose
La sortie de l'exécution du script peut être étendue en utilisant cette option qui active un suivi verbeux de l'activité. Par défaut, le script ne génère aucune sortie de journal à moins qu'une condition d'erreur ou d'avertissement ne soit rencontrée.
-?, --help
Affiche le message d'utilisation et quitte.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

VOIR AUSSI
