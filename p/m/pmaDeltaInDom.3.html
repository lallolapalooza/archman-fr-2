PMADELTAINDOM(3) Manuel des fonctions de bibliothèque PMADELTAINDOM(3)

NOM

pmaDeltaInDom - générer un « delta indom » si deux observations d'un domaine d'instance sont différentes

SYNTAXE C

#include <pcp/pmapi.h>
#include <pcp/libpcp.h>
#include <pcp/archive.h>

int pmaDeltaInDom(__pmLogInDom *old,
__pmLogInDom *new, __pmLogInDom *new_delta);

cc ... -lpcp_archive -lpcp

AVERTISSEMENT

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API PCP garanties comme étant fixes entre les versions, et elles peuvent ne pas fonctionner, ou fournir des sémantiques différentes à l'avenir.

DESCRIPTION

Vérifie si deux observations du même domaine d'instance sont identiques et, si elles ne le sont **pas**, tente de générer un « delta indom » pour décrire les différences.

Le code suppose (a) que old->indom == new->indom et (b) que les deux domaines d'instance sont triés selon une séquence croissante d'identifiants d'instance internes ; voir pmaSortInDom(3) pour savoir comment rendre la deuxième condition vraie.

Le format « delta indom » n'est pris en charge que pour les archives de version 3, et il incombe à l'appelant de déterminer si l'appel de pmaDeltaInDom est approprié, plutôt que d'appeler pmaSameInDom(3), qui est la méthode préférée pour les archives V2.

pmaDeltaInDom retourne 0 si les domaines d'instance old et new sont identiques.

Une valeur de retour de 1 indique que les domaines d'instance sont différents et que le format « delta indom » n'est **pas** plus efficace ; dans ce cas, new_delta n'est pas modifié.

Une valeur de retour de 2 indique que les domaines d'instance sont différents et que new_delta a été configuré pour décrire l'encodage « delta indom » des différences ; dans ce cas, il incombe à l'appelant de libérer new_delta->instlist et new_delta->namelist.

Les domaines d'instance sont considérés comme différents si l'une des conditions suivantes est remplie :

1.
old->numinst != new->numinst
2.
Pour un certain i, old->instlist[i] != new->instlist[i]
3.
Pour un certain i, les chaînes pointées par old->namelist[i] et new->instlist[i] ne sont pas identiques

FORMAT DELTA INDOM

Comme pour un domaine d'instance régulier, new_delta->numinst définit le nombre de spécifications d'instance.

Si new_delta->namelist[i] == NULL, alors l'instance identifiée par new_delta->instlist[i] a été **supprimée** du domaine d'instance.

Si new_delta->namelist[i] != NULL, alors l'instance identifiée par new_delta->instlist[i] a été **ajoutée** au domaine d'instance.

Étant donné que le « delta indom » n'est susceptible d'avoir qu'une pertinence à court terme pour l'appelant, les entrées new_delta->namelist[i] qui ne sont pas NULL pointeront vers old->namelist[j] ou new->namelist[k], et donc old et new ne doivent pas être libérés tant que l'appelant n'a pas fini d'utiliser new_delta.

VOIR AUSSI

PMAPI(3), pmaSortInDom(3) et pmaSameInDom(3).
