pmdanetcheck(1)

Paquet: pcp

PMDANETCHECK(1) Manuel des commandes générales PMDANETCHECK(1)

NOM

pmdanetcheck - PMDA netcheck

DESCRIPTION

pmdanetcheck est un Agent de domaine de métriques de performance (PMDA) de Performance Co-Pilot (PCP) qui effectue des vérifications réseau de base sur l'hôte local en utilisant de simples modules Python et, dans certains cas, des utilitaires externes tels que ping(1).

pmdanetcheck charge et agit comme un pont pour un nombre quelconque de modules Python de PMDA netcheck PCP configurés et séparés exécutant du code Python ou des programmes externes. Il devrait être possible d'utiliser les modules et programmes Python existants avec les modules PMDA netcheck PCP avec un minimum d'effort.

Notez que sur les systèmes activés pour SELinux, pour que pmdanetcheck puisse utiliser la commande ping(1), le groupe pcp doit être capable de créer des sockets ICMP Echo ; assurez-vous que l'identifiant du groupe pour pcp est inclus dans la plage de /proc/sys/net/ipv4/ping_group_range et consultez icmp(7) pour plus de détails à ce sujet.

CONFIGURATION

pmdanetcheck lit un fichier de configuration obligatoire de style ini :

$PCP_PMDAS_DIR/netcheck/netcheck.conf

Ce fichier doit contenir une section [pmda]. Les options PMDA suivantes sont disponibles (leurs valeurs par défaut sont indiquées entre parenthèses), les options marquées d'un astérisque (*) peuvent être remplacées dans les sections de configuration spécifiques au module :

modules (non défini)
Le PMDA pmdanetcheck lit la configuration spécifique au module pour chaque module listé dans la liste séparée par des virgules de modules (obligatoire).
hosts (DGW,DNS) *
Une liste séparée par des virgules d'hosts (facultatif) spécifie les hôtes pour lesquels effectuer les vérifications. Les valeurs spéciales DGW, DNS, NTP seront traduites respectivement en passerelle par défaut, serveurs de noms listés dans /etc/resolv.conf, et serveurs de temps listés dans /etc/chrony.conf, au démarrage du PMDA.
background_check (True) *
Une valeur booléenne pour background_check (facultatif) contrôle si les vérifications doivent être exécutées en permanence en arrière-plan ou seulement sur demande. Consultez le fichier de configuration par défaut pour plus de discussion à ce sujet.
check_hosts_parallel (True) *
check_hosts_parallel (facultatif) contrôle si les modules doivent vérifier les hôtes un par un ou en parallèle.
check_interval (1m) *
check_interval (facultatif) spécifie l'intervalle de temps entre deux vérifications consécutives d'hôtes lorsque les vérifications sont effectuées en arrière-plan. Consultez PCPIntro(1) pour une description complète de la syntaxe de l'intervalle de temps.
align_interval (True) *
align_interval (facultatif) spécifie s'il faut tenir compte de la durée de la vérification précédente lors de la pause entre les vérifications.
module_failure_fatal (True)
Une valeur booléenne pour module_failure_fatal (facultatif) contrôle si un module qui ne parvient pas à s'initialiser doit provoquer l'abandon de l'ensemble du PMDA (ce qui est le comportement par défaut) ou s'il faut démarrer avec des modules potentiellement encore fonctionnels. Les erreurs de configuration de module et les erreurs internes (telles que l'échec de l'enregistrement des métriques fournies par le PMNS, voir pmns(5)) empêcheront toujours le PMDA de démarrer.

Pour chaque module listé dans modules, une section [module] correspondante doit être définie. Chaque section [module] peut contenir au moins les options suivantes (leurs valeurs par défaut sont indiquées entre parenthèses) :

timeout (1)
Forcer un timeout dur (facultatif) pour chaque opération de vérification réseau individuelle.
debug (False)
Activer l'enregistrement des messages de debug internes (rarement utilisé).

Les options spécifiques au module que les modules acceptent sont décrites dans le fichier de configuration par défaut.

Les modules s'attendent à ce que des fonctionnalités réseau de base soient présentes sur le système, par exemple, que l'adresse du localhost soit accessible.

INSTALLATION

Pour installer, les étapes suivantes doivent être effectuées en tant que root :

# cd $PCP_PMDAS_DIR/netcheck
# ./Install

Pour désinstaller, les étapes suivantes doivent être effectuées en tant que root :

# cd $PCP_PMDAS_DIR/netcheck
# ./Remove

pmdanetcheck est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove notifient pmcd(1) lorsque l'agent est installé ou supprimé.

Si module_failure_fatal est défini sur False, l'installation du PMDA sera considérée comme réussie si certains modules configurés (mais pas tous) échouent à se charger ; dans ce cas, les métriques fournies par les modules défaillants ne seront pas disponibles. Le fichier journal de l'agent pmdanetcheck (voir ci-dessous) contiendra des informations détaillées sur l'activation de chaque module.

Les modules fourniront des valeurs réelles uniquement après avoir collecté des données. Par exemple, pour le module ping, la valeur métrique est la valeur de retour de la commande ping(1) et pour ping_latency, la latence moyenne des paquets telle que rapportée par ping(1). Pour les métriques indiquant un statut, 0 signifie succès. Si une vérification n'est pas encore terminée, sa valeur métrique est -1. Si une vérification a été interrompue pendant son exécution en raison d'un délai d'attente, la valeur est -2.

FICHIERS

$PCP_PMDAS_DIR/netcheck/netcheck.conf
fichier de configuration de l'agent pmdanetcheck
$PCP_PMDAS_DIR/netcheck/netcheck/*.{py,python}
modules Python PMDA netcheck pour l'agent pmdanetcheck
$PCP_PMDAS_DIR/netcheck/Install
script d'installation de l'agent pmdanetcheck
$PCP_PMDAS_DIR/netcheck/Remove
script d'annulation de l'installation de l'agent pmdanetcheck
$PCP_LOG_DIR/pmcd/netcheck.log
fichier journal par défaut pour les messages de l'agent pmdanetcheck

Notez que la valeur habituelle/par défaut de $PCP_PMDAS_DIR est /var/lib/pcp/pmdas et celle de $PCP_LOG_DIR est /var/log/pcp, mais ces paramètres dépendent de la plateforme.

ENVIRONNEMENT PCP

Les variables d'environnement dont le préfixe est PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).
