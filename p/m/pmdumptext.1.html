NAME

pmdumptext - décharger les métriques de performance dans un tableau ASCII

SYNOPSIS

pmdumptext [-CFGHilmMNoruVXz?] [-a archive] [-A align] [-c config] [-d delimiter] [-D debug] [-f format] [-h host] [-n pmnsfile] [-O offset] [-P precision] [-R lines] [-s sample] [-S starttime] [-t interval] [-T endtime] [-U string] [-w width] [-Z timezone] [metric ...]

DESCRIPTION

pmdumptext affiche les valeurs des métriques de performance collectées en direct ou à partir d'un ensemble d'archives Performance Co-Pilot (PCP). Par défaut, les valeurs des métriques sont affichées dans des colonnes séparées par des tabulations, précédées d'un horodatage.

Sauf indication contraire vers un autre hôte par l'option -h, ou vers un ou plusieurs ensembles d'archives par l'option -a, ou un préfixe explicite host: ou archive/ dans le metric (voir ci-dessous pour plus d'informations), pmdumptext contactera le démon collecteur de métriques de performance (PMCD) sur l'hôte local pour obtenir les informations requises.

pmdumptext peut être exécuté en mode interactif avec l'option -i qui affiche les valeurs dans des colonnes de largeur égale. Sans cette option, aucune tentative n'est faite pour aligner les valeurs, ce qui permet à la sortie d'être facilement analysée par d'autres applications.

Le format de la sortie peut être davantage contrôlé en modifiant la précision des valeurs avec -P, la largeur des colonnes avec -w, et le format des valeurs avec les options -G et -F pour les plus courtes des chiffres scientifiques ou à virgule fixe, et un format à largeur fixe, respectivement.

Par défaut, pmdumptext mettra à l'échelle les valeurs des métriques en unités « canoniques » d'octets, de secondes et de comptes. La seule exception est avec l'option -r où les valeurs ne sont pas mises à l'échelle. L'option -u indique les unités de chaque métrique.

Les metrics à décharger peuvent être listées sur la ligne de commande, dans un fichier de config, ou transmises à pmdumptext sur stdin. Une métrique consiste en une source optionnelle (hôte ou archive), le nom de la métrique, et une liste d'instances optionnelle immédiatement après le nom. Deux points (:) sont utilisés pour séparer un nom d'hôte de la métrique, et une barre oblique (``/'') pour séparer un nom d'archive de la métrique. Les instances sont entourées de crochets et une virgule est utilisée entre chaque instance s'il y en a plus d'une. Par exemple, certaines métriques légales sont :


kernel.all.cpu.idle
myhost:kernel.all.cpu.idle[cpu0,cpu3]
/path/to/myarchive/kernel.all.cpu.idle[cpu1]

Lorsqu'une metric ne contient pas de préfixe host: ou archive/, par exemple kernel.all.cpu.idle ci-dessus, alors la source de la métrique est déterminée par les règles suivantes :

(a)
PMCD sur host de l'option -h s'il y en a une, sinon
(b)
l'archive de la première option -a s'il y en a une, sinon
(c)
l'hôte de la première metric avant celle-ci avec un préfixe host: s'il y en a un, sinon
(d)
l'archive de la première metric avant celle-ci avec un préfixe archive/ s'il y en a un, sinon
(e)
PMCD sur l'hôte local, ce qui est équivalent à local::metric.

Le format d'une metric est décrit plus en détail dans PCPIntro(1) dans la section PERFORMANCE METRIC SPECIFICATIONS. Une valeur de normalisation peut éventuellement suivre un nom de métrique dans un fichier de config ou sur stdin. La valeur de la métrique sera mise à l'échelle par cette valeur. Par exemple, si le système de fichiers ``/dev/root'' a une capacité de 1965437 octets, alors le pourcentage du système de fichiers utilisé pourrait être déchargé avec cette config :


filesys.used[/dev/root] 19654.37

Une valeur de normalisation ne peut pas être utilisée avec les metrics spécifiées comme arguments de ligne de commande.

Un nom de métrique n'est pas obligé d'être un nœud feuille dans l'espace de noms des métriques de performance (PMNS), sauf lorsque une ou plusieurs instances sont spécifiées. Par exemple, pour décharger toutes les métriques du système de fichiers, il suffit de filesys pour décharger filesys.capacity, filesys.used, filesys.free etc.

OPTIONS

Les options de ligne de commande -A (ou --align), -O (ou --origin), -S (ou --start) et -T (ou --finish) contrôlent l'alignement, le décalage, le début et la fin du temps lors de la visualisation des métriques à partir d'archives. Ces options sont communes à la plupart des outils Performance Co-Pilot et sont entièrement décrites dans PCPIntro(1).

Les autres options disponibles sont :

-a archive, --archive=archive
Spécifie l'archive historique archive à partir de laquelle les métriques peuvent être obtenues pour un hôte particulier. archive est le chemin complet vers un fichier d'archive individuel, ou le nom d'un répertoire contenant des archives, ou le nom de base d'une archive - toutes créées précédemment par pmlogger(1). Plusieurs ensembles d'archives (séparés par des virgules ou dans différentes options -a) provenant de différents hôtes peuvent être donnés, mais un seul ensemble d'archives par hôte est autorisé. Toutes les métriques qui ne sont pas associées à un hôte ou une archive spécifique utiliseront la première archive comme source.
-c config, --config=config
Si aucune metrics n'est listée sur la ligne de commande, un fichier de config peut être utilisé pour spécifier les metrics à décharger. Contrairement aux metrics de ligne de commande, chaque métrique peut être suivie d'une valeur de normalisation. Les lignes vides et les lignes commençant par '#' sont ignorées.
-C, --check
Sortir avant de décharger toute valeur, mais après avoir analysé les métriques. Les métriques, instances, normales et unités sont listées si -m, -l, -N et/ou -u sont spécifiés.
-d delimiter, --delimiter=delimiter
Spécifie le délimiteur delimiter qui sépare chaque colonne de sortie. Le delimiter ne peut être qu'un seul caractère.
-f format, --time-format=format
Utilise la chaîne de format pour formater l'horodatage avec chaque ensemble de valeurs. La syntaxe de cette chaîne est la même que celle décrite dans strftime(3). Une chaîne de format vide (par exemple '') supprimera les horodatages de la sortie.
-F, --fixed
Affiche les valeurs dans un format à largeur fixe de 6 caractères. Les nombres positifs sont représentés comme dd.ddu et les nombres négatifs comme [-]d.ddu. Le multiplicateur de postfixe peut avoir les valeurs K(10^3), M(10^6), G(10^9) et T(10^12). Par exemple, 4567 s'affichera comme 4.57K, même si les unités de la métrique sont des octets.
-G, --scientific
Affiche les valeurs en utilisant le format le plus court entre un format scientifique ou une notation décimale.
-h host, --host=host
Récupère les métriques de performance depuis pmcd(1) sur host, plutôt que l'hôte local par défaut.
-H, --headers
Affiche tous les en-têtes avant de décharger toute valeur de métrique. Ceci est équivalent à -lmNu.
-i, --interactive
Affiche les données dans des colonnes à largeur fixe avec des valeurs à largeur fixe (voir -F) afin qu'elles soient lisibles par l'homme. Cette option ne peut pas être utilisée avec -P car les valeurs à virgule fixe ne sont pas à largeur fixe. Cette option affectera également la sortie des options -m et -u car les noms de métrique, d'instance et d'unité seront tronqués.
-l, --source
Affiche la source des métriques. En mode interactif, l'hôte des métriques est affiché. En mode non interactif, cette option affiche la source des métriques avec le nom de la métrique même si -m n'est pas spécifié.
-m, --metrics
Affiche les noms des métriques avant les valeurs des métriques. La source et les unités des métriques peuvent être

OPTIONS

-a archive,..., --archive=archive,...
Extract performance metrics from a set of Performance Co-Pilot (PCP) archives. Multiple archives may be specified, separated by commas. If the archive name contains a comma or an equals sign, it must be quoted. Each archive should have been created by the same instance of pmlogger(1), and the archives must be in the same directory, and from the same host. The tool automatically determines the time interval and the other properties of the archive and the values are read in the order of the archives supplied. Up to two archives may be used to interpolate between samples taken using different sample rates or at different times. See pcarchive(5) for more details.
-C config, --config=config
Specify the name of the configuration file to be used to control the output format. The default configuration file is $PCP_PMDUMPTEXTCFG. If no configuration file is specified, then the default options are used. See pmdumptext.cfg(5) for more details.
-d, --domain
Output the PMNS (Performance Metrics Name Space) domain of the metrics before the first values.
-D [misc,...] , --debug=[misc,...]
Set the PMDUMPTEXT debugging facility. See the DEBUGGING OPTIONS section below.
-e pmtime, --end=pmtime
Stop processing after pmtime. See pmtime(7) for details.
-F, --fullwidth
Full output, do not truncate any output. Column headers are not repeated when output is to a terminal.
-f format, --format=format
Specify the strftime(3) format string that controls the format of the timestamp that precedes each line of output. If the format string is empty, then no timestamp is printed.
-h host, --host=host
Extract performance metrics from the specified host. The default is to use the local host.
-i, --interactive
Interactive mode. This is the default mode when output is to a terminal. Metric names may be truncated and instance names are truncated on the following line. The header is repeated every 20 lines. Use -R to change the number of lines.
-I instance,..., --instances=instance,...
Extract only the specified instances for each metric. The default behaviour is to extract all instances. The instance names may be fully qualified, e.g. ``cpu0'', or they may be abbreviated, e.g. ``cpu''. If abbreviated, then all instances starting with that prefix are selected. Use pmprobe(1) for a list of instance names for a metric.
-l, --labels
Output the metric labels before the metric values. The metric labels are also dumped with the -u options respectively. If in interactive mode, the metrics names may be truncated, and the instance names, where relevant, are also truncated on the follow line.
-M
Output the column number and complete metric names before dumping any values. If the -l flag is also specified, the source of the metrics is also shown.
-n pmnsfile, --namespace=pmnsfile
Load an alternative local PMNS from the file pmnsfile.
-o, --offset
When a timestamp is being reported (i.e. unless an empty format string is given with the -f option), the timestamp is prefixed with the offset in seconds from the start of the set of archives or the beginning of the execution of pmdumptext.
-N
Output the normalization factors before the metric values.
-p precision, --precision=precision
Set the precision of the values. This option may not be used with -F as the precision is constant. The default precision is 3.
-r, --raw
Output the raw metric values, do not convert counters to rates and do not scale values to ``canonical'' units. This option also causes pmdumptext to ignore the normalization values for each metric.
-R lines, --repeat=lines
Repeat the header every lines of output. This option is useful in interactive mode when using a graphical window to avoid the header scrolling beyond the window's buffer, and to realign the header if the window is resized.
-s samples, --samples=samples
pmdumptext will terminate after this many samples.
-t interval, --interval=interval
The interval option follows the syntax described in PCPIntro(1), and in the simplest form may be an unsigned integer (the implied units in this case are seconds). The default interval is 1 second.
-u, --units
Output the units of the metrics before the first values, but after the metric names if -m is also specified.
-U string, --unavailable=string
Change the output when values are unavailable to string. The default string is ``?''.
-V, --version
Display version number and exit.
-w width, --widthfR=width
Set the column width of the output. Strings will be truncated to this width, and maybe postfixed by ``...'' if the width is greater than 5.
-X, --extended
Output the column number and complete metric names, one-per-line, both before dumping the first set of values and again each time the header is repeated.
-z, --hostzone
Use the local timezone of the host that is the source of the performance metrics, as identified by either the -h or the first -a options. The default is to use the timezone of the local host.
-Z timezone, --timezone=timezone
Use timezone for the date and time. Timezone is in the format of the environment variable TZ as described in environ(7).
-?, --help
Display usage message and exit.

MULTIPLE SOURCES

pmdumptext supports the dumping of metrics from multiple hosts or set of archives. The metrics listed on the command line or in the config file may have no specific source or come from different sources.

However, restrictions apply when archives are specified on the command line (-a) and/or in the configuration file. Firstly, there may be only one set of archives for any one host. Secondly, the hosts of any metrics with host sources must correspond to the host of a set of archives, either on the command line or previously as the source of another metric.

The options -a and -h may not be used together.

UNIT CONVERSION

All metrics that have the semantics of counters are automatically converted to rates over the sample time interval. In interactive mode, pmdumptext will also change the units of some metrics so that they are easier to comprehend:

o
All metrics with space units (bytes to terabytes) are scaled to bytes. Note that 1024 bytes will be represented as 1.02K, not 1.00K.
o
Metrics that are counters with time units (nanoseconds to hours) represent time utilization over the sample interval. The unit strings of such metrics is changed to ``Time Utilization'' or abbreviated to ``util'' and the values are normalized to the range zero to one.

EXAMPLES

o To examine the load on two hosts foo and bar, simultaneously:


$ pmdumptext -il 'foo:kernel.all.load[1]' 'bar:kernel.all.load[1]'
             Source        foo     bar
Wed Jul 30 11:37:53      0.309   0.409
Wed Jul 30 11:37:54      0.309   0.409
Wed Jul 30 11:37:55      0.309   0.409

o To output the memory utilization on a remote host called bong with a simpler timestamp:


$ pmdumptext -imu -h bong -f '%H:%M:%S' mem.util
  Metric        kernel  fs_ctl  _dirty  _clean    free    user
   Units             b       b       b       b       b       b
09:32:28         8.98M   0.97M   0.00    3.90M   7.13M  46.13M
09:32:29         8.99M   0.98M   0.00    5.71M   5.39M  46.03M
09:32:30         8.99M   1.07M   0.00    5.81M   4.55M  46.69M
09:32:31         9.03M   1.16M   0.00    6.45M   3.48M  47.00M
09:32:32         9.09M   1.18M  20.48K   6.23M   3.29M  47.30M

o To dump all metrics collected in an archive at a 30 second interval to a file for processing by another tool:


$ pminfo -a archive | pmdumptext -t 30s -m -a archive > outfile

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.

Debugging options specific to pmdumptext are as follows:

Option Description
appl0 detailed diagnostics for metrics, their source and timezone, metadata, units normalization, output format, etc.
