PMLOGCONF(1) Manuel des commandes générales PMLOGCONF(1)

NOM

pmlogconf - créer/éditer un fichier de configuration pmlogger

SYNTAXE

pmlogconf [-cqrvV?] [-d repertoire_groupes] [-D debug] [-g tag_groupe] [-h hôte] [-s fichier_groupe] fichier_config

DESCRIPTION

pmlogconf peut être utilisé pour créer et modifier un fichier de configuration générique pour l'archiveur PCP, pmlogger(1).

Si fichier_config n'existe pas, pmlogconf créera un fichier de configuration générique avec un ensemble par défaut de métriques activées et d'intervalles d'enregistrement.

Une fois créé, fichier_config peut être utilisé avec l'option -c de pmlogger(1) pour sélectionner les métriques de performance et spécifier les intervalles d'enregistrement pour une archive PCP.

Si fichier_config existe déjà, pmlogconf demandera à l'utilisateur d'activer ou de désactiver des groupes de métriques de performance liées et de contrôler l'intervalle d'enregistrement pour chaque groupe activé.

La sélection de groupe nécessite une simple réponse o (oui) ou n (non) à la demande Enregistrer ce groupe ?.

D'autres réponses à ce stade peuvent être utilisées pour sélectionner des fonctions de contrôle supplémentaires comme suit :

m
Afficher les noms des métriques du groupe actuel.
q
Terminer la sélection des groupes (quitter) et ne faire aucune autre modification à ce groupe ou aux groupes suivants.
/motif
Ne pas modifier ce groupe mais rechercher un groupe contenant motif dans la description du groupe ou les noms des métriques associées.

Un intervalle d'enregistrement est spécifié en répondant à la demande Intervalle d'enregistrement ? avec les mots-clés once ou default ou une spécification d'intervalle pmlogger(1) valide de la forme ``every N unitestemps'' ou simplement ``N unitestemps'' (le every est facultatif) où N est un entier non signé et unitestemps est l'un des mots-clés msec, millisecond, sec, second, min, minute, hour ou la forme plurielle de l'un des mots-clés.

Lorsqu'il est exécuté par des processus d'enregistrement automatisés, l'option -c est utilisée pour indiquer que pmlogconf est en mode de création automatique et qu'aucun dialogue interactif n'a lieu. Le fichier de configuration de sortie contient un message de commentaire supplémentaire et un horodatage indiquant ce fait, de sorte qu'il puisse être identifié et mis à jour ultérieurement en utilisant à nouveau -c. Cette option n'est pas appropriée pour une utilisation interactive de l'outil.

L'option -q supprime le dialogue sur l'intervalle d'enregistrement et conserve l'intervalle actuel du fichier_config.

Une sortie plus verbeuse peut être activée avec l'option -v.

FICHIERS DE CONFIGURATION DE GROUPES

Lorsqu'un fichier_config initial est créé, les spécifications par défaut proviennent d'un ensemble de fichiers de groupes sous le repertoire_groupes spécifié avec l'option -d (le repertoire_groupes par défaut est $PCP_VAR_DIR/config/pmlogconf, ce qui est le plus souvent correct, donc l'option -d est rarement utilisée en pratique).

La structure des répertoires sous repertoire_groupes est arbitraire car tous les fichiers réguliers seront trouvés par descente récursive et pris en compte. Ainsi, les produits supplémentaires et les développeurs PMDA peuvent facilement étendre les défauts disponibles pour pmlogconf en ajoutant de nouveaux répertoires et/ou fichiers de groupes sous repertoire_groupes.

Ces fichiers de groupes sont traités de la manière suivante :

  • Lorsqu'un nouveau fichier_config est créé, tous les fichiers de groupes sont traités.
  • Chaque fois que pmlogconf est exécuté avec un fichier_config existant, repertoire_groupes est parcouru pour voir si de nouveaux groupes ont été définis et doivent être pris en compte pour leur inclusion dans fichier_config.
  • Lorsque pmlogconf traite un groupe dans fichier_config qui est activé, la liste des métriques associées au groupe est extraite du fichier de groupe (et remplace toute liste précédente de métriques associées à ce groupe dans fichier_config).
  • Lorsque l'option de ligne de commande -r (re-sonder) ou -c (création automatique) est spécifiée, chaque groupe (pas seulement ceux découverts récemment) est retraité pour voir s'il doit être pris en compte pour son inclusion dans fichier_config.
  • Si un groupe est trouvé dans fichier_config mais que le groupe correspondant n'existe pas sous repertoire_groupes (ce qui serait le cas lorsqu'un groupe devient obsolète suite à une mise à niveau de PCP), la gestion du groupe dépend du mode dans lequel pmlogconf est exécuté. Avec -c, le groupe correspondant est supprimé de fichier_config, sinon le groupe correspondant reste inchangé dans fichier_config. Dans les deux cas, un avertissement est émis.

Chaque fichier de groupe est structuré comme suit :

  • La première ligne doit contenir #pmlogconf-setup 2.0
  • Les autres lignes commençant par # sont traitées comme des commentaires.
  • Les lignes vides sont ignorées.
  • Une ou plusieurs lignes commençant par le mot-clé ident sont utilisées pour fournir la description lisible par l'homme du groupe.
  • Les lignes non vides commençant par un espace blanc définissent les métriques à associer à ce groupe, une par ligne. Chaque spécification de métrique suit les règles d'une configuration pmlogger(1), à savoir soit le nom d'un nœud non-feuille dans le PMNS (impliquant tous les noms descendants dans le PMNS), soit le nom d'un nœud-feuille dans le PMNS suivi éventuellement d'un ou plusieurs noms d'instance délimités par ``['' et ``]''.
  • Une ligne de contrôle commençant par l'un des mots-clés probe ou force doit être présente.
  • Une ligne de contrôle d'intervalle d'enregistrement facultative commence par le mot-clé delta suivi de l'une des spécifications d'intervalle de pmlogger(1) décrite ci-dessus.
  • Des lignes de contrôle de métriques dérivées facultatives commencent par le mot-clé define et ont le format :

define nom expression
où nom est le nom d'une métrique dérivée et expression est une expression de métrique dérivée. Reportez-vous à pmRegisterDerived(3) pour les descriptions syntaxiques et sémantiques de nom et expression. Une fois définie, nom peut être utilisé comme métrique dans une ligne de contrôle probe ultérieure, permettant l'expression de gardes plus complexes pour l'inclusion conditionnelle de métriques dans fichier_config.

Notez que nom doit être unique parmi tous les fichiers de groupes et ne pas entrer en collision avec un nom existant dans le PMNS. Une convention de nommage appropriée peut donc devoir être adoptée lors de la création des fichiers de groupes.

•
Les lignes de contrôle probe ont le format :

probe métrique [condition [règle_état] ]
où métrique est le nom d'une métrique PCP (doit être un nœud-feuille dans le PMNS, aucune spécification d'instance n'est autorisée, et ce ne doit pas être une métrique dérivée, autre que celle mentionnée dans une ligne define précédente) et la condition facultative est le mot-clé exists (vrai si métrique existe, c'est-à-dire est définie dans le PMNS) ou le mot-clé values (vrai si métrique existe dans le PMNS et a une ou plusieurs valeurs actuelles) ou une expression de la forme
op val où op est l'un des opérateurs de awk(1) (==, !=, >, >=, <, <=, ~ (correspondance d'expression régulière) ou !~ (correspondance d'expression régulière niée)) et val est une valeur (séquence arbitraire de caractères, excluant un espace) et la condition est vraie s'il existe une instance de métrique qui rend l'expression vraie.

Si la condition est manquante, la valeur par défaut est exists.

Lorsqu'une condition explicite est fournie, il peut également y avoir une règle_état facultative de la forme
? état_vrai : état_faux où état_vrai (s'applique si la condition est vraie) et état_faux (s'applique si la condition est fausse) sont tous deux tirés des mots-clés include (inclure et activer le groupe et les métriques associées dans fichier_config), available (inclure et désactiver le groupe dans fichier_config - une action utilisateur de o comme décrit ci-dessus est nécessaire pour activer le groupe et ajouter les métriques associées dans fichier_config) ou exclude (le groupe n'est pas pris en compte pour l'inclusion dans fichier_config).

Si la règle_état est omise, la valeur par défaut est include.

Les lignes de contrôle force ne sont utilisées que lorsque le mode de création automatique de pmlogconf est utilisé (option -c), et elles sont utilisées pour spécifier un ensemble de métriques à toujours inclure dans le fichier de configuration, quels que soient les résultats des tests de sonde. Ces métriques sont ajoutées à la fin de la liste des métriques déjà existantes pour le groupe.

Les lignes de contrôle delta sont utilisées pour spécifier l'intervalle d'enregistrement des métriques d'un groupe. Si un groupe contient des métriques déjà enregistrées avec des intervalles différents, le dernier intervalle spécifié pour le groupe sera utilisé pour toutes les métriques du groupe.

•
Une ligne de contrôle default facultative spécifie la valeur par défaut de l'intervalle d'enregistrement pour un groupe s'il n'est pas spécifié explicitement.

Exemple de fichier de groupe :

#pmlogconf-setup 2.0
ident: Swap Memory Statistics
ident: Statistiques de la mémoire swap
delta: every 1 minute
force: swapin
force: swapout
probe: swap_alloc available ? include : exclude
probe: swap_free available ? include : exclude

Ce fichier de groupe enregistrera les statistiques de la mémoire swap. Il enregistrera les métriques swapin et swapout toutes les minutes. Il inclura également les métriques swap_alloc et swap_free si elles sont disponibles, sinon elles seront exclues.

OPTIONS

Les options de ligne de commande suivantes sont disponibles :

-c
Mode de création automatique. Supprime le dialogue interactif et écrit le résultat dans fichier_config. La sortie fichier_config comprendra un message de commentaire et un horodatage indiquant qu'elle a été créée en mode automatique.
-q
Supprime le dialogue sur l'intervalle d'enregistrement et conserve l'intervalle actuel de fichier_config.
-r
Re-sonde tous les groupes définis dans groupsdir pour les inclure dans fichier_config, même s'ils étaient déjà présents.
-v
Sortie verbeuse. Affiche plus d'informations sur le processus de configuration.
-V
Version. Affiche les informations de version et quitte.
?
Aide. Affiche un message d'aide et quitte.
-d groupsdir
Spécifie le répertoire où rechercher les fichiers de groupes. Le défaut est $PCP_VAR_DIR/config/pmlogconf.
-D debug
Niveau de débogage. Les valeurs valides sont des entiers de 0 à 9.
-g grouptag
Spécifie le groupe à configurer. Par défaut, tous les groupes sont configurés.
-h host
Spécifie l'hôte distant dont les métriques doivent être configurées. Par défaut, l'hôte local est utilisé.
-s groupfile
Spécifie un fichier de groupe unique à utiliser pour la configuration. Par défaut, tous les fichiers de groupes dans groupsdir sont utilisés.

EXEMPLES

Pour créer un fichier de configuration nommé myconfig pour l'enregistrement des métriques système de base :

$ pmlogconf myconfig

Vous serez invité à activer ou désactiver des groupes de métriques et à définir leurs intervalles d'enregistrement.

Pour créer un fichier de configuration autocfg en mode automatique, en utilisant les fichiers de groupes de /etc/pcp/pmlogconf/groups :

$ pmlogconf -c -d /etc/pcp/pmlogconf/groups autocfg

Pour modifier un fichier de configuration existant myconfig et supprimer le dialogue d'intervalle d'enregistrement :

$ pmlogconf -q myconfig

•
Les lignes de contrôle force commencent par le mot-clé force suivi de l'un des états définis ci-dessus, de sorte que l'une des actions include, exclude ou available est appliquée inconditionnellement au groupe.

La sonde n'est effectuée que lorsqu'un nouveau groupe est ajouté à configfile ou lorsque l'option de ligne de commande -r est spécifiée. L'évaluation des conditions de sonde est effectuée en contactant pmcd(1) sur hostname (par défaut : local).

OPTIONS

Les options de ligne de commande disponibles sont :

-c
Active le mode non interactif et de création automatique.
-d groupsdir, --groups=groupsdir
Spécifie le chemin d'accès au répertoire groupsdir.
-g grouptag, --group=grouptag
Interroge l'état de journalisation pour le groupe de journalisation spécifique nommé grouptag.
-h host, --host=host
La source des métriques de performance est pmcd(1) sur host, plutôt que sur le localhost par défaut.
-q, --quiet
Mode silencieux, supprime la boîte de dialogue d'intervalle de journalisation.
-r, --reprobe
Réévalue chaque groupe pour son inclusion dans configfile.
-s groupfile, --setup=groupfile
Rapporte l'état de journalisation par défaut pour le groupe de journalisation unique dans groupfile. Ceci est un rendu équivalent à celui produit par le script shell retiré pmlogconf-setup des versions antérieures de PCP.
-v, --verbose
Active le mode verbeux.
-V, --version
Affiche le numéro de version et quitte.
-?, --help
Affiche le message d'utilisation et quitte.

EXEMPLES

Le fichier de groupe suivant démontre la plupart des éléments syntaxiques pris en charge.

#pmlogconf-setup 2.0
ident   Exemple de fichier de groupe
ident   ... description supplémentaire
delta   1 minute
probe   sample.secret.foo.one values ? include : exclude
        sample.secret.foo.one
        sample.secret.foo.bar   # feuille non-feuille dans le PMNS
        sample.colour [ red green ]

Dans l'exemple suivant (les barres obliques inverses ont été ajoutées pour la lisibilité, la clause define est sur une seule ligne), les métriques mumble seront incluses dans configfile si la métrique mumble.foo est connue et a au moins une instance (et une valeur) ou si la métrique mumble.bar est connue et a au moins une instance (et une valeur) :

#pmlogconf-setup 2.0
ident   Exemple de métrique dérivée avec alternance
define  mumble.check = \
            (defined(mumble.foo) ? count(mumble.foo) : 0) + \
            (defined(mumble.bar) ? count(mumble.bar) : 0)
probe   mumble.check > 0 ? include : exclude
        mumble

L'exemple suivant utilise une métrique dérivée pour accéder à une instance de métrique particulière dans une ligne de contrôle probe.

#pmlogconf-setup 2.0
ident   Exemple de métrique dérivée utilisant une seule instance de métrique
define  fumble_log = fumble.control[verbose_log]
probe   fumble_log > 0 ? include : exclude
        fumble.detailed

MIGRATION

La version actuelle de pmlogconf (2.0) prend en charge un format légèrement différent pour configfile par rapport aux versions antérieures. Si un ancien fichier configfile est présenté à pmlogconf, il sera converti au nouveau format.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

pmlogconf ignore toute variable d'environnement $PCP_DERIVED_CONFIG et la remplace par une chaîne vide, pour des raisons de performance et pour empêcher l'inclusion de métriques dérivées dans configfile.

pmlogconf respecte la variable d'environnement $PMCD_WAIT_TIMEOUT lors de la sonde et de la création de nouveaux fichiers de configuration pmlogger. Il utilise une valeur de délai d'attente par défaut de 10 secondes pour cela, en l'absence d'un paramètre d'environnement.

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.
