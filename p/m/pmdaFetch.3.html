PMDAFETCH(3) Manuel des fonctions de bibliothèque PMDAFETCH(3)

NOM

pmdaFetch, pmdaSetFetchCallBack - remplir une structure pmResult avec les valeurs de métriques demandées

C SYNTAXE

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaFetch(int numpmid,
pmID *pmidlist, pmResult **resp, pmdaExt *pmda);

void pmdaSetFetchCallBack(pmdaInterface *dispatch,
pmdaFetchCallBack callback);

cc ... -lpcp_pmda -lpcp

DESCRIPTION

pmdaFetch est un rappel générique utilisé par un PMDA(3) pour traiter une requête de récupération de pmcd(1). La requête de pmcd est initiée par un client appelant pmFetch(3).

C'est l'un des rares rappels génériques dans libpcp_pmda (voir PMDA(3)) qui est incomplet, nécessitant une méthode pmdaFetchCallBack supplémentaire propre. Le rappel supplémentaire doit être enregistré en utilisant pmdaSetFetchCallBack et la méthode pmdaFetchCallBack a le prototype suivant :

int func(pmdaMetric *mdesc, unsigned int inst, pmAtomValue *avp)

pmdaFetch allouera et redimensionnera la structure de résultat resp, pour stocker les valeurs des numpmid métriques listées dans pmidlist.

Pour chaque instance listée dans le profil (voir pmdaProfile(3)) de chaque métrique listée dans pmidlist, la méthode pmdaFetchCallBack est appelée pour remplir la structure pmAtomValue identifiée par avp avec une valeur pour une paire métrique-instance spécifique identifiée par le descripteur de métrique mdesc et l'instance inst. Cette valeur est ensuite copiée dans la structure pmResult.

La méthode pmdaFetchCallBack doit retourner une valeur inférieure à zéro en cas d'erreur, les cas les plus probables étant PM_ERR_PMID si la métrique identifiée par mdesc n'est pas connue de la méthode, ou PM_ERR_INST si la méthode estime que l'instance inst n'est pas connue pour la métrique identifiée par mdesc.

Les codes d'erreur de succès dépendent de la version de PMDA_INTERFACE utilisée par le PMDA.

Si le PMDA utilise PMDA_INTERFACE_2, alors en cas de succès, la méthode pmdaFetchCallBack doit retourner 0.

Si le PMDA utilise PMDA_INTERFACE_3 ou PMDA_INTERFACE_4, alors en cas de succès, la méthode pmdaFetchCallBack doit retourner 1 si une valeur est retournée via avp, sinon 0 si aucune valeur n'est actuellement disponible pour la paire métrique-instance demandée, bien que mdesc et inst semblent raisonnables.

Si le PMDA utilise PMDA_INTERFACE_5 ou une version ultérieure, alors en cas de succès, la méthode pmdaFetchCallBack doit retourner PMDA_FETCH_STATIC (1) si la valeur retournée via avp peut être ignorée par pmdaFetch une fois qu'elle a été copiée dans la structure pmResult, sinon PMDA_FETCH_DYNAMIC (2) si la valeur retournée via avp utilise les champs vp ou cp de pmAtomValue et que la valeur associée (tampon) a été allouée en utilisant l'une des fonctions malloc(3), calloc(3), realloc(3), strdup (3), etc. et que pmdaFetch doit libérer la mémoire en appelant free(3) une fois qu'un nouveau tampon a été alloué et la valeur copiée, sinon PMDA_FETCH_NOVALUES (0) si aucune valeur n'est actuellement disponible pour la paire métrique-instance demandée, bien que mdesc et inst semblent raisonnables.

Si la méthode pmdaFetchCallBack retourne une valeur pour une instance d'une métrique de type PM_TYPE_STRING ou PM_TYPE_AGGREGATE, un soin particulier est nécessaire – la méthode doit soit utiliser un tampon statique, définir avp->cp ou avp->vp à l'adresse du tampon et retourner PMDA_FETCH_STATIC, soit utiliser un tampon alloué dynamiquement, conserver une référence statique à l'adresse du tampon, retourner PMDA_FETCH_STATIC et free (3) ou realloc (3) ou réutiliser le tampon la prochaine fois que la méthode pmdaFetchCallBack est appelée, sinon utiliser un tampon alloué dynamiquement et retourner PMDA_FETCH_DYNAMIC.

EXEMPLE

Les fragments de code suivants proviennent d'un PMDA hypothétique ayant les métriques (A, B, C et D) et un domaine d'instance (X) avec deux instances (X1 et X2). Le domaine d'instance et les tables de description des métriques (voir pmdaInit(3)) pourraient être définis comme suit :

static pmdaInstid _X[] = {
    { 0, "X1" }, { 1, "X2" }
};

static pmdaIndom indomtab[] = {
#define X_INDOM 0
    { 0, 2, _X },
};

static pmdaMetric metrictab[] = {
/* A */
    { (void *)0,
      { PMDA_PMID(0,0), PM_TYPE_32, PM_INDOM_NULL,
        PM_SEM_INSTANT, {0,0,0,0,0,0} }, },
/* B */
    { (void *)0,
      { PMDA_PMID(0,1), PM_TYPE_DOUBLE, X_INDOM,
        PM_SEM_INSTANT, {0,1,0,0,PM_TIME_SEC,0} }, },
/* C */
    { (void *)0,
      { PMDA_PMID(0,2), PM_TYPE_STRING, PM_INDOM_NULL,
        PM_SEM_INSTANT, {0,0,0,0,0,0} }, },
/* D */
    { (void *)0,
      { PMDA_PMID(0,3), PM_TYPE_STRING, PM_INDOM_NULL,
        PM_SEM_INSTANT, {0,0,0,0,0,0} }, },
};

Une méthode pmdaFetchCallBack à appeler depuis pmdaFetch pourrait être définie comme suit :

int
myFetchCallBack(pmdaMetric *mdesc, unsigned int inst, pmAtomValue *avp)
{
  static char sbuf[20]; // réutiliser ce tampon
  char        *dbuf;    // alloué avec malloc
  switch (pmID_item(mdesc->m_desc.pmid)) {
    case 0:
      /* assigner une valeur pour la métrique A */;
      avp->l = ...
      break;
    case 1:
      switch (inst) {
          case 0:
	      /* assigner une valeur pour la métrique B, instance X1 */;
              avp->d = ...
              break;
          case 1:
	      /* assigner une valeur pour la métrique B, instance X2 */;
              avp->d = ...
              break;
          default:
              return PM_ERR_INST;
      }
    case 2:
      /* placer la valeur pour la métrique C dans dbuf[] */
      memcpy(dbuf, ...);
      avp->cp = dbuf;
      break;
    case 3:
      avp->cp = (char *)malloc(somesize);
      /* placer la valeur dans avp->cp */
      pmsprintf(avp->cp, somesize, ...);
      return PMDA_FETCH_DYNAMIC;
    default:
      return PM_ERR_PMID;
  }
  return PMDA_FETCH_STATIC;
}

MISE EN GARDE

Le PMDA doit utiliser PMDA_INTERFACE_2 ou une version ultérieure, comme spécifié dans l'appel à pmdaDSO(3) ou pmdaDaemon(3).

DIAGNOSTICS

Les messages d'erreur suivants indiquent un décalage entre le nom de l'espace, les tables pmdaMetric et pmdaIndom passées à pmdaInit(3), et le rappel de récupération enregistré :

pmdaFetch: La métrique demandée metric n'est pas définie
Une métrique demandée metric n'est pas listée dans la table pmdaMetric. L'espace de noms de ce PMDA(3) peut contenir des métriques supplémentaires.
pmdaFetch: PMID pmid non géré par le rappel de récupération
La méthode pmdaFetchCallBack a retourné PM_ERR_PMID. Ceci indique qu'une métrique peut être listée dans la table pmdaMetric, mais n'est pas prise en charge par la méthode de rappel.
pmdaFetch: Instance inst de PMID pmid non gérée par le rappel de récupération
La méthode pmdaFetchCallBack a retourné PM_ERR_INST. Ceci indique qu'une instance de métrique est listée dans la table pmdaIndom, mais n'est pas prise en charge par la méthode de rappel.
pmdaFetch: Erreur du rappel de récupération :
La méthode pmdaFetchCallBack a retourné un résultat autre que PMDA_FETCH_NOVALUES, PMDA_FETCH_STATIC, PMDA_FETCH_DYNAMIC, PM_ERR_PMID ou PM_ERR_INST.
pmdaFetch: Type de descripteur (type) pour la métrique pmid est incorrect
Le type de données type spécifié pour la métrique pmid dans la table pmdaMetric est illégal.

pmdaFetch retournera -errno si une erreur s'est produite.
