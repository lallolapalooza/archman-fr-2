PMPROBE(1) Manuel des commandes générales PMPROBE(1)

NOM

pmprobe - sonde légère pour les métriques de performance

SYNTAXE

pmprobe [-dfFiILvVz?] [-a archive] [-b taille_lot] [--container=nom] [-D debug] [--derived=fichier] [-h hote] [-K spec] [-n fichier_pmns] [-O temps] [-Z fuseau_horaire] [nom_metrique ...]

DESCRIPTION

pmprobe détermine la disponibilité des métriques de performance exportées par les installations de Performance Co-Pilot (PCP).

Les métriques d'intérêt sont nommées dans les arguments nom_metrique. Si nom_metrique est un nœud non terminal dans l'espace de noms des métriques de performance (PMNS(5)), alors pmprobe descendra récursivement le PMNS et signalera tous les nœuds terminaux. Si aucun argument nom_metrique n'est donné, la racine de l'espace de noms est utilisée.

Cette expansion récursive du PMNS peut être inhibée par l'option -F (aller plus vite), qui réduit le nombre d'allers-retours vers pmcd(1) lorsque les arguments nom_metrique sont connus comme étant des nœuds terminaux à l'avance.

Le format de sortie est spartiate et destiné à être utilisé dans des scripts wrapper créant des fichiers de configuration pour d'autres outils PCP. Par défaut, il y a une ligne de sortie par métrique, avec le nom de la métrique suivi d'un compte du nombre de valeurs disponibles. Les conditions d'erreur sont codées sous forme de nombre négatif de comptes (conformément aux protocoles de PMAPI(3), mais peuvent être décodées à l'aide de pmerr(1)) et suivies d'une description textuelle de l'erreur.

Sauf indication contraire à un autre hôte par l'option -h, pmprobe contactera le démon collecteur de métriques de performance (PMCD) sur l'hôte local.

L'option -a fait en sorte que pmprobe utilise l'ensemble spécifié d'archives plutôt que de se connecter à un PMCD.

L'option -L fait en sorte que pmprobe utilise un contexte local pour collecter les métriques des PMDA sans PMCD. Seules certaines métriques sont disponibles dans ce mode.

Les options -a, -h et -L sont mutuellement exclusives.

OPTIONS

Les options de ligne de commande disponibles sont :

-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des fichiers d'archives de Performance Co-Pilot (PCP) identifiés par l'argument archive, qui est une liste séparée par des virgules de noms, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives.
-b, --batch
Cette option peut être utilisée pour définir le nombre maximum de métriques à récupérer en une seule requête pour l'option -v et toute demande de pmLookupName(3) que pmprobe appelle avec une liste de noms de métriques terminales. La valeur par défaut de taille_lot est 128. Cette option est utile pour éviter les limitations sur les tailles de requêtes PDU et aussi pour étaler les récupérations, qui sinon pourraient expirer si pmcd(1) ou un PMDA répond lentement, en particulier si un grand nombre de métriques sont sondées.
--container=conteneur
Spécifier un conteneur individuel à interroger.
-d, --version
Affiche le numéro de version et quitte.
--derived=fichier_dm
L'argument fichier_dm spécifie un fichier contenant des définitions de métriques dérivées dans le format décrit pour pmLoadDerivedConfig(3). Cette option fournit un moyen de charger des définitions de métriques dérivées qui est une alternative à l'utilisation plus générique de la variable d'environnement PCP_DERIVED_CONFIG décrite dans PCPIntro(1). Utiliser l'option --derived et la variable d'environnement PCP_DERIVED_CONFIG pour spécifier la **même** configuration est une mauvaise idée, alors choisissez l'une ou l'autre méthode.
-f, --force
Lorsqu'elle est utilisée avec -i ou -I, l'ensemble des instances signalées sera toutes celles connues à la source des données de performance. Par défaut, l'ensemble des instances signalées sont celles pour lesquelles des valeurs sont actuellement disponibles, ce qui peut être plus petit que l'ensemble signalé avec -f.
-F, --faster
Supposer que les noms de métriques donnés sont des nœuds terminaux PMNS.
-h hote, --host=hote
Se connecter à pmcd(1) sur hote, plutôt que sur localhost par défaut.
-i, --internal
Signaler les identificateurs internes pour chaque instance. Les valeurs sont en décimal et préfixées par ``?''. Comme cas spécial, la chaîne littérale PM_IN_NULL est signalée pour les métriques singulières.
-I, --external
Signaler les identificateurs externes pour chaque instance. La chaîne littérale PM_IN_NULL est signalée pour les métriques singulières.
-K spec, --spec-local=spec
Lors de l'utilisation de l'option -L/ pour récupérer des métriques depuis un contexte local, cette option contrôle les PMDA DSO qui devraient être rendus accessibles. L'argument spec est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plus d'une option -K peuvent être utilisées.
-L, --local-PMDA
Utiliser un contexte local pour collecter les métriques des PMDA DSO sur l'hôte local sans PMCD. Voir aussi -K.
-n fichier_pmns, --namespace=fichier_pmns
Normalement, pmprobe opère sur l'espace de noms distribué des métriques de performance (PMNS), cependant, si l'option -n est spécifiée, un fichier PMNS local alternatif est chargé depuis le fichier fichier_pmns.
-O temps, --origin=temps
Lorsqu'elle est utilisée conjointement avec une source d'archives de métriques et les options -f/, l'argument temps définit une origine de temps à laquelle les métriques doivent être récupérées à partir de l'ensemble des archives. Reportez-vous à PCPIntro(1) pour une description complète de cette option, et la syntaxe de l'argument temps.
-v, --values
Signaler la valeur pour chaque instance, conformément aux règles de formatage de pmPrintValue(3). Lors de la récupération à partir d'un ensemble d'archives, seules les instances présentes dans le premier enregistrement d'archive pour une métrique seront affichées ; voir aussi l'option -O. L'option -v est mutuellement exclusive avec les options -I ou -i.
-V, --verbose
Cette option fournit un résumé cryptique du nombre de messages envoyés et reçus via l'interface PMAPI.
-z, --hostzone
Changer le fuseau horaire de reporting au fuseau horaire local de l'hôte qui est la source des métriques de performance, tel qu'identifié via les options -h ou -a.
-Z fuseau_horaire, --timezone=fuseau_horaire
Par défaut, pmprobe signale l'heure de la journée selon le fuseau horaire local sur le système où pmprobe est exécuté. L'option -Z change le fuseau horaire à fuseau_horaire dans le format de la variable d'environnement TZ décrite dans environ(7).
-?, --help
Affiche le message d'utilisation et quitte.

EXEMPLES

$ pmprobe disk.dev
disk.dev.read 2
disk.dev.write 2
disk.dev.total 2
disk.dev.blkread 2
disk.dev.blkwrite 2
disk.dev.blktotal 2
disk.dev.active 2
disk.dev.response 2

$ pmprobe -I disk.dev.read disk.dev.write disk.

pmprobe(1) — Performance Co-Pilot

NAME

pmprobe

probe Performance Co-Pilot metrics

SYNOPSIS

pmprobe [-?] [-c config] [-D debuglist] [-h host] [-i instance] [-l] [-n name] [-p port] [-q] [-t seconds] [-V] [metricspec ...]

DESCRIPTION

The pmprobe utility is a client-side tool that allows you to query Performance Co-Pilot (PCP) metrics from a PCP collection system. It can be used to query individual metrics, groups of metrics, or to check the availability and basic properties of metrics and their PMDA (Performance Metrics Domain Agent) sources.

By default, pmprobe connects to the PCP collector (pmcd) on the local host. The -h option can be used to specify a remote host.

The metricspec arguments specify the metrics to be queried. A metricspec can be a metric name or a metric name with instance selectors.

OPTIONS

The options available for the pmprobe command are:

-?
Print a help message and exit.
-c config
Use the specified configuration file instead of the default $PCP_CONF.
-D debuglist
Enable debugging output. debuglist is a comma-separated list of debugging options. See the DEBUGGING OPTIONS section below for details.
-h host
Connect to the PCP collector host instead of the local host.
-i instance
Specify an instance selector for the metric. This can be a single instance name or a comma-separated list of instance names.
-l
List all available metrics and their descriptions. This option is useful for exploring the available metrics in the system.
-n name
Probe only metrics whose names start with the specified name.
-p port
Connect to the PCP collector on the specified port. The default port is 44321.
-q
Query metrics with a timeout. The timeout is specified using the -t option.
-t seconds
Set the timeout in seconds for queries when the -q option is used.
-V
Print version information and exit.

EXAMPLES

$ pmprobe -l
kernel.all.cpu 0-15 Average CPU utilization
kernel.all.load 0-1 Load average
disk.dev.read 2 "sda" "sdb" Read operations for sda and sdb
disk.dev.write 2 "sda" "sdb" Write operations for sda and sdb
disk.all.total 1 PM_IN_NULL Total disk I/O

$ pmprobe -v pmcd.numagents pmcd.version pmcd.control.timeout
pmcd.numagents 1 9
pmcd.version 1 "5.0.0"
pmcd.control.timeout 1 5

$ pmprobe -v disk.dev.total disk.all.total
disk.dev.total -1012 Unknown metric name
disk.all.total 1 4992466

FILES

$PCP_VAR_DIR/pmns/*
default PMNS specification files

PCP ENVIRONMENT

Environment variables with the prefix PCP_ are used to parameterize the file and directory names used by PCP. On each installation, the file /etc/pcp.conf contains the local values for these variables. The $PCP_CONF variable may be used to specify an alternative configuration file, as described in pcp.conf(5).

For environment variables affecting PCP tools, see pmGetOptions(3).

DEBUGGING OPTIONS

The -D or --debug option enables the output of additional diagnostics on stderr to help triage problems, although the information is sometimes cryptic and primarily intended to provide guidance for developers rather end-users. debug is a comma separated list of debugging options; use pmdbg(1) with the -l option to obtain a list of the available debugging options and their meaning.

Debugging options specific to pmprobe are as follows:

Option Description
appl0 batch information when -b used
