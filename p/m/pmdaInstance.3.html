PMDAINSTANCE(3) Manuel des fonctions de bibliothèque PMDAINSTANCE(3)

NOM

pmdaInstance - retourner les descriptions d'instance pour un PMDA

SYNTAXE C

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaInstance(pmInDom indom,
int inst, char *name, pmInResult **result, pmdaExt *pmda);

cc ... -lpcp_pmda -lpcp

DESCRIPTION

pmdaInstance utilise les structures de données standard du PMDA(3) pour retourner des informations concernant le domaine d'instance indom.

La structure result est construite par pmdaInstance et contiendra un ou plusieurs noms et/ou identifiants d'instance comme spécifié par les arguments inst et name.

Si inst a la valeur PM_IN_NULL et name est une chaîne vide, result contiendra tous les noms et identifiants d'instance dans le domaine d'instance.

Si inst est PM_IN_NULL mais que name est le nom d'une instance dans le domaine d'instance indom, alors result contiendra l'identifiant d'instance pour l'instance name. Notez que si name ne contient pas d'espaces, une correspondance partielle jusqu'au premier espace dans le nom d'instance est effectuée, c'est-à-dire que « 1 » correspondra au nom d'instance « 1 minute ». Si name contient un espace intégré, aucune correspondance partielle n'est effectuée et name doit correspondre exactement à l'un des noms d'instance.

Si name est une chaîne vide mais que inst est un identifiant d'instance dans le domaine d'instance indom, alors result contiendra le nom de l'instance inst. La structure result est allouée avec malloc(3) et doit être libérée par l'appelant avec free(3).

NOMMAGE D'INSTANCE MULTI-DIMENSIONNEL

En plus de la description ci-dessus de name, l'ensemble des règles décrivant les noms d'instance externes est fourni dans la page de manuel pmdaCacheStore(3).

Les domaines d'instance ajoutent une autre dimension (ensemble de valeurs) aux métriques. Cependant, cela peut ne pas suffire pour décrire des situations complexes de domaines d'instance multidimensionnels. Dans ce cas, l'approche utilisée par un certain nombre de PMDA est de structurer les noms d'instance externes à l'aide d'un délimiteur (« / » ou « :: » sont les plus couramment utilisés) pour permettre la séparation des autres dimensions. Dans ce cas, les étiquettes de domaine d'instance doivent être utilisées pour définir les noms de chaque composant du nom d'instance. Cela permet aux outils clients de PMAPI(3) d'identifier et d'affiner les récupérations de valeurs aux dimensions spécifiques d'intérêt.

Par exemple, certains domaines d'instance de métriques cgroup (control group) du noyau Linux sont multidimensionnels. Le domaine d'instance représente des valeurs individuelles à travers les groupes de contrôle et les CPU, ce qui en fait un domaine d'instance bidimensionnel. Les noms d'instance associés à ces indom de métriques cgroup ont été structurés à l'aide du délimiteur « :: » pour séparer les deux dimensions. Le domaine d'instance lui-même a été étiqueté en conséquence, comme suit.

$ pminfo --desc --fetch --labels cgroup.cpuacct.usage_percpu
cgroup.cpuacct.usage_percpu
Type de données : entier non signé 64 bits  InDom: 3.22 0xc00016
Sémantique : compteur  Unités : nanosec
inst [0 ou "/::cpu0"] valeur 713787
inst [1 ou "/::cpu1"] valeur 353969
inst [2 ou "/app::cpu0"] valeur 407816
inst [3 ou "/app::cpu1"] valeur 202747
inst [0 ou "/::cpu0"] étiquettes {"device_type":"cpu","cgroup":"/","cpu":0}
inst [1 ou "/::cpu1"] étiquettes {"device_type":"cpu","cgroup":"/","cpu":1}
inst [2 ou "/app::cpu0"] étiquettes {"device_type":"cpu","cgroup":"/app","cpu":0}
inst [3 ou "/app::cpu1"] étiquettes {"device_type":"cpu","cgroup":"/app","cpu":1}

$ pminfo --labels 3.22
InDom: 3.22 0xc00016
étiquettes {"device_type":"cpu"}

Comme montré ci-dessus, les instances individuelles héritent des étiquettes du domaine d'instance, et le PMDA applique également des étiquettes supplémentaires par instance décrivant les noms individuels de cgroup et de CPU. Lorsque ce modèle a été utilisé par le PMDA, les clients PMAPI peuvent restreindre leurs requêtes aux instances de métriques cgroup - dans l'exemple, en restreignant au processeur « cpu0 » en utilisant l'étiquette « cpu », par exemple, ou aux métriques du cgroup « /app » en utilisant l'étiquette « cgroup ».

De plus, en utilisant ce schéma d'étiquetage, les outils clients peuvent également corréler les instances associées entre différents domaines d'instance.

$ pminfo --desc --fetch --labels kernel.percpu.cpu.irq.soft
kernel.percpu.cpu.irq.soft
Type de données : entier non signé 64 bits  InDom: 60.0 0xf000000
Sémantique : compteur  Unités : millisec
inst [0 ou "cpu0"] valeur 6770
inst [1 ou "cpu1"] valeur 100
inst [0 ou "cpu0"] étiquettes {"device_type":"cpu"}
inst [1 ou "cpu1"] étiquettes {"device_type":"cpu"}

$ pminfo --labels 60.0
InDom: 60.0 0xf000000
étiquettes {"device_type":"cpu"}

Bien que ces deux métriques aient des domaines d'instance différents (respectivement 60.0 et 3.22) et proviennent de différents PMDA, l'étiquette « device_type » identifie le périphérique commun auquel ces valeurs se rapportent.

AVERTISSEMENT

Le PMDA doit utiliser PMDA_INTERFACE_2 ou une version ultérieure, comme spécifié dans l'appel à pmdaDSO(3) ou pmdaDaemon(3). Si l'étiquetage des noms d'instance multidimensionnels est effectué, le PMDA doit utiliser PMDA_INTERFACE_7 ou une version ultérieure.

En raison de la correspondance partielle optionnelle jusqu'au premier espace dans le nom d'instance, le développeur PMDA doit s'assurer que si les noms d'instance sont autorisés à contenir des espaces, les noms sont uniques jusqu'au premier espace.

DIAGNOSTICS

Si des erreurs se produisent pendant l'exécution de pmdaInstance, la structure result est désallouée. Si le domaine d'instance indom n'est pas pris en charge par le PMDA, pmdaInstance retournera PM_ERR_INDOM.

Si inst ou name ne correspondent à aucune instance dans le domaine indom, pmdaInstance retournera PM_ERR_INST.

VOIR AUSSI

malloc(3), PMAPI(3), PMDA(3), pmdaCacheStore(3), pmdaLabel(3) et pmGetInDom(3).
