PMRECORD(3) Manuel des fonctions de bibliothèque PMRECORD(3)

NOM

pmRecordSetup, pmRecordAddHost, pmRecordControl - support du mode enregistrement pour les clients PMAPI

SYNTAXE C

#include <pcp/pmafm.h>

FILE *pmRecordSetup(const char *folio,
const char *creator, int replay);

int pmRecordAddHost(const char *host,
int isdefault, pmRecordHost **rhp);

int pmRecordControl(pmRecordHost *rhp,
int request, const char *options);

cc ... -lpcp_gui

DESCRIPTION

Ces routines peuvent être utilisées pour créer une archive PCP (Performance Co-Pilot) « à la volée » afin de prendre en charge les services en mode « enregistrement » pour les applications clientes PMAPI.

Chaque « session » en mode enregistrement implique une ou plusieurs archives PCP, chacune créée à l'aide d'un processus dédié pmlogger(1), avec un format général d'Archive Folio tel qu'entendu par pmafm(1), pour nommer et collecter toutes les archives associées à une seule session d'enregistrement.

La structure pmRecordHost est utilisée pour maintenir l'état entre le créateur de la session d'enregistrement et le ou les processus pmlogger associés. La structure est définie comme suit :

typedef struct {
    FILE   *f_config;    /* l'appelant écrit la configuration pmlogger ici */
    int    fd_ipc;       /* canal IPC vers pmlogger */
    char   *logfile;     /* chemin d'accès complet au fichier journal des erreurs de pmlogger */
    pid_t  pid;          /* identifiant du processus pour pmlogger */
    int    status;       /* statut de sortie, -1 si inconnu */
} pmRecordHost;

Les routines sont utilisées en combinaison pour créer une session d'enregistrement comme suit :

1.
Appelez pmRecordSetup pour établir une nouvelle session d'enregistrement. Un nouveau Folio d'Archive sera créé en utilisant le nom folio ; si le fichier ou le répertoire folio existe déjà, ou si le fichier folio ne peut pas être créé, c'est une erreur. L'application qui crée la session est identifiée par creator (le plus souvent, ce serait le même que le nom global de l'application PMAPI, tel que renvoyé par pmGetProgname(3)). Si l'application sait comment créer son propre fichier de configuration pour rejouer la session enregistrée, alors replay doit être différent de zéro.

pmRecordSetup renvoie un flux stdio sur lequel l'application doit écrire le texte du fichier de configuration de rejeu requis, le cas échéant.

2.
Pour chaque host qui doit être inclus dans la session d'enregistrement, appelez pmRecordAddHost. Une nouvelle structure pmRecordHost est renvoyée via rhp. Il est supposé que pmcd(1) est en cours d'exécution sur host, car c'est ainsi que pmlogger(1) récupérera les métriques de performance requises.

Si ce host est l'hôte par défaut pour cette session d'enregistrement, alors isdefault doit être différent de zéro. Cela garantira que l'archive correspondante apparaîtra en premier dans le folio d'archives PCP, et par conséquent les outils utilisés pour rejouer le folio d'archives feront la bonne détermination de l'archive associée à l'hôte par défaut. Au plus un host par session d'enregistrement peut être désigné comme hôte par défaut.

L'application appelante doit écrire la configuration désirée de pmlogger sur le flux stdio renvoyé via le champ f_config dans la structure pmRecordHost.

3.
Optionnellement, ajoutez des arguments à la ligne de commande qui sera utilisée pour lancer pmlogger(1) en appelant pmRecordControl avec une request de PM_REC_SETARG. L'argument est passé via options et un appel à pmRecordControl est requis pour chaque argument distinct.

Un argument peut être ajouté pour une instance particulière de pmlogger identifiée par rhp, ou si l'argument rhp est NULL, l'argument est ajouté pour toutes les instances de pmlogger qui seront lancées dans la session d'enregistrement actuelle.

Indépendamment de tout appel à pmRecordControl avec une request de PM_REC_SETARG, chaque instance de pmlogger sera automatiquement lancée avec les arguments suivants : -c, -h, -l, -x et le nom de base de l'archive PCP.

4.
Pour démarrer la session d'enregistrement, appelez pmRecordControl avec une request de PM_REC_ON, et rhp doit être NULL. Cela lancera un processus pmlogger(1) pour chaque hôte de la session d'enregistrement, et initialisera les champs fd_ipc, logfile, pid et status dans la ou les structures pmRecordHost associées.
5.
Pour terminer une instance de pmlogger identifiée par rhp, appelez pmRecordControl avec une request de PM_REC_OFF. Si l'argument rhp de pmRecordControl est NULL, la demande de terminaison est diffusée à tous les processus pmlogger de la session d'enregistrement actuelle.

Un dialogue informatif est généré directement par chaque processus pmlogger et par conséquent, notez les commentaires sur la disposition de la sortie de pmlogger ci-dessous.

Alternativement, pmlogger peut être démarré avec des options pour limiter la durée de l'enregistrement, par exemple les arguments -T ou -s, auquel cas il n'est pas nécessaire d'appeler pmRecordControl avec une request de PM_REC_OFF et aucun dialogue n'est généré.

6.
Pour afficher l'état actuel de l'instance de pmlogger identifiée par rhp, appelez pmRecordControl avec une request de PM_REC_STATUS. Si l'argument rhp de pmRecordControl est NULL, la demande de statut est diffusée à tous les processus pmlogger de la session d'enregistrement actuelle.

L'affichage est généré directement par chaque processus pmlogger et par conséquent, notez les commentaires sur la disposition de la sortie de pmlogger ci-dessous.

7.
Pour détacher une instance de pmlogger identifiée par rhp et lui permettre de continuer indépendamment de l'application qui a lancé la session d'enregistrement, appelez pmRecordControl avec une request de PM_REC_DETACH. Si l'argument rhp de pmRecordControl est NULL, la demande de détachement est diffusée à tous les processus pmlogger de la session d'enregistrement actuelle.

Un dialogue informatif est généré directement par chaque processus pmlogger et par conséquent, notez les commentaires sur la disposition de la sortie de pmlogger ci-dessous.

L'application appelante ne doit pas fermer les flux stdio renvoyés ; cela sera fait par pmRecordControl lorsque l'enregistrement sera commencé.

Une fois que pmlogger a été démarré pour une session d'enregistrement, pmlogger assumera la responsabilité de tout dialogue avec l'utilisateur au cas où l'application qui a lancé la session d'enregistrement devrait se terminer, en particulier sans terminer la session d'enregistrement.

Par défaut, les informations et dialogues de pmlogger seront affichés à l'aide de pmquery(1), en supposant que la plupart des applications souhaitant lancer une session d'enregistrement sont basées sur une interface graphique. Dans le cas où pmquery ne parvient pas à afficher les informations (par exemple, parce que la variable d'environnement DISPLAY n'est pas définie), pmlogger écrira sur son propre flux stderr (pas le flux stderr du processus lanceur) ; la sortie sera assignée au fichier XXXXXX.host.log décrit dans la section FICHIERS ci-dessous. Pour plus de commodité, le chemin d'accès complet à ce fichier est fourni via le champ logfile dans la structure pmRecordHost.

Si l'argument options de pmRecordControl n'est pas NULL, cette chaîne peut être utilisée pour passer des arguments supplémentaires à pmquery(1) dans les cas où un dialogue doit être affiché. Une utilisation de cette capacité serait de fournir une chaîne -geometry pour contrôler le placement du dialogue.

La terminaison prématurée d'un processus pmlogger lancé peut être déterminée en utilisant la structure pmRecordHost, en appelant select(2) sur le champ fd_ipc ou en interrogeant le champ status qui contiendra le statut de terminaison de waitpid(2) s'il est connu, sinon -1.

PM_REC_SETARG
PM_REC_ON
PM_REC_OFF
PM_REC_STATUS
PM_REC_DETACH
sont des valeurs prédéfinies pour le paramètre request.

DIAGNOSTIQUES

Les routines de la bibliothèque retournent des codes d'erreur pour indiquer l'échec. Une description textuelle de l'erreur peut être obtenue en appelant la fonction pmErrStr(3).

Lorsque les routines de la bibliothèque génèrent des erreurs, les codes d'erreur sont les suivants :

PM_ERR_EINVAL
Un argument invalide a été fourni.
PM_ERR_EPERM
Une opération a été tentée qui n'est pas autorisée dans l'état actuel de la session.
PM_ERR_FAULT
Un pointeur invalide a été fourni.
PM_ERR_NOMEM
Il n'y avait pas assez de mémoire disponible.
PM_ERR_POST
Impossible d'envoyer un message au processus
PM_ERR_RECV
Impossible de recevoir un message du processus
PM_ERR_TRACE
Le traçage ne peut pas être démarré pour un des hôtes.
PM_ERR_LOGIN
Impossible de se connecter au démon d'agent de performance.
PM_ERR_SLOGIN
Impossible de se connecter à un démon d'agent de performance distant.
PM_ERR_FINDHOST
Impossible de localiser le démon d'agent de performance.
PM_ERR_PCPOPTS
Impossible de dériver les options PCP pour l'exécution de
PM_ERR_IPC
Un problème de communication IPC s'est produit.

Lorsque pmlogger génère une erreur, celle-ci est renvoyée en texte brut (par exemple, comme s'il s'agissait d'une commande en ligne). Les messages d'erreur sont affichés via la procédure de dialogue standard (voir la section DESCRIPTION ci-dessus).

DIAGNOSTICS

pmRecordSetup peut retourner NULL en cas d'erreur. Vérifiez errno pour connaître la cause réelle, mais la valeur EINVAL indique généralement que l'ordre des appels à ces routines n'est pas correct (il existe un état évident associé à la session d'enregistrement actuelle qui est maintenu lors des appels à ces routines). Par exemple, les appels suivants produiraient cette erreur EINVAL : appeler pmRecordControl avant d'avoir appelé pmRecordAddHost au moins une fois, ou appeler pmRecordAddHost avant d'avoir appelé pmRecordSetup.

pmRecordControl et pmRecordAddHost retournent tous deux 0 en cas de succès, sinon une valeur inférieure à 0 pouvant être décodée avec pmErrStr(3) en cas d'échec. La valeur -EINVAL a la même interprétation que si errno était défini à EINVAL comme décrit ci-dessus.

pmRecordControl retournera PM_ERR_IPC si le processus pmlogger associé a déjà quitté.

FILES

Ces routines créent un certain nombre de fichiers dans le même répertoire que le fichier folio nommé dans l'appel à pmRecordSetup. Dans tous les cas, le composant « XXXXXX » est le résultat de l'appel à mktemp(3).

XXXXXX
Si replay est non nul, il s'agit du fichier de configuration de relecture du créateur, sinon d'un fichier de contrôle vide, utilisé pour garantir l'unicité.
folio
Le folio d'archives PCP, utilisable avec pmafm(1).
XXXXXX.host.config
La configuration de pmlogger(1) pour chaque host - si le même host est utilisé dans différents appels à pmRecordAddHost au sein de la même session d'enregistrement, alors une des lettres « a » à « z » sera ajoutée à la partie « XXXXXX » de tous les noms de fichiers associés pour garantir l'unicité.
XXXXXX.host.log
stdout et stderr pour l'instance de pmlogger(1) pour chaque host.
XXXXXX.host.{0,meta,index}
Les fichiers composant une archive PCP unique pour chaque host.

VOIR AUSSI

pmafm(1), pmlogger(1), pmquery(1) et PMAPI(3).
