PMDATXMON(1) Manuel des commandes générales PMDATXMON(1)

NOM

pmdatxmon, txrecord, genload - agent du domaine de métriques de performance txmon (PMDA)

SYNTAXE

$PCP_PMDAS_DIR/txmon/pmdatxmon [-D debug] [-d domaine] [-l logfile] [-U username] tx_type ...
$PCP_PMDAS_DIR/txmon/txrecord [-l]
$PCP_PMDAS_DIR/txmon/txrecord tx_type servtime [tx_type servtime ... ]
$PCP_PMDAS_DIR/txmon/genload

DESCRIPTION

pmdatxmon est un exemple d'agent de domaine de métriques de performance (PMDA) qui exporte un petit nombre de métriques de performance à partir d'un moniteur de transaction simulé.

Le PMDA txmon est fourni sous forme binaire et de code source et est conçu pour aider les développeurs de PMDA ; le PMDA txmon démontre comment les données de performance peuvent être exportées d'une application (dans ce cas txrecord) vers l'infrastructure PCP via un segment de mémoire partagée. Par souci de commodité, pmdatxmon crée (et détruit à la sortie) le segment de mémoire partagée.

Les arguments tx_type sont des balises arbitraires uniques utilisées pour identifier différents types de transactions.

L'application txrecord simule le traitement d'une ou plusieurs transactions identifiées par tx_type et avec un temps de service observé de servtime.

Avec l'option -l, txrecord affiche le résumé actuel de l'activité de transaction à partir du segment de mémoire partagée.

genload est un script shell et awk(1) qui agit comme une interface pour txrecord afin de générer une charge constante d'activité de transaction simulée.

Une brève description des options de ligne de commande de pmdatxmon suit :

-d
Il est absolument crucial que le numéro de domaine des métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire, domaine devrait être différent pour chaque PMDA sur un hôte, et le même numéro de domaine devrait être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé txmon.log est écrit dans le répertoire courant de pmcd(1) lorsque pmdatxmon est démarré, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est écrite sur l'erreur standard à la place.
-U
Compte utilisateur sous lequel exécuter l'agent. Par défaut, c'est le compte non privilégié "pcp" dans les versions récentes de PCP, mais dans les versions plus anciennes, le compte superutilisateur ("root") était utilisé par défaut.

INSTALLATION

Si vous souhaitez accéder aux noms, textes d'aide et valeurs des métriques de performance txmon, faites ce qui suit en tant que root :

# cd $PCP_PMDAS_DIR/txmon
# ./Install

Vous serez invité à saisir les balises tx_type.

Si vous souhaitez annuler l'installation, faites ce qui suit en tant que root :

# cd $PCP_PMDAS_DIR/txmon
# ./Remove

pmdatxmon est lancé par pmcd(1) et ne devrait jamais être exécuté directement. Les scripts Install et Remove notifient pmcd(1) lorsque l'agent est installé ou supprimé.

FICHIERS

$PCP_PMCDCONF_PATH
options de ligne de commande utilisées pour lancer pmdatxmon
$PCP_PMDAS_DIR/txmon/help
fichier de texte d'aide par défaut pour les métriques txmon
$PCP_PMDAS_DIR/txmon/Install
script d'installation pour l'agent pmdatxmon
$PCP_PMDAS_DIR/txmon/Remove
script d'annulation d'installation pour l'agent pmdatxmon
$PCP_LOG_DIR/pmcd/txmon.log
fichier journal par défaut pour les messages d'erreur et autres informations de pmdatxmon

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider au dépannage, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdatxmon sont les suivantes :

Option Description
appl0 opérations de mémoire partagée
