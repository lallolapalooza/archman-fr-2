PMNSADD(1) Manuel des commandes générales PMNSADD(1)

NOM

pmnsadd - ajouter de nouveaux noms à l'espace de noms de métriques de performance (PMNS) de PCP

SYNTAXE

$PCP_BINADM_DIR/pmnsadd [-?] [-n namespace] fichier

DESCRIPTION

pmnsmerge(1) effectue la même fonction que pmnsadd et est plus rapide, plus robuste et plus flexible. Il est donc recommandé d'utiliser pmnsmerge(1) à la place.

pmnsadd ajoute un ou plusieurs sous-arbres de nouveaux noms à un espace de noms de métriques de performance (PMNS), tel qu'utilisé par les composants de Performance Co-Pilot (PCP).

Normalement, pmnsadd opère sur l'espace de noms de métriques de performance (PMNS) par défaut, cependant si l'option -n est spécifiée, un espace de noms alternatif est utilisé à partir du fichier namespace.

Le PMNS par défaut se trouve dans le fichier $PCP_VAR_DIR/pmns/root à moins que la variable d'environnement PMNS_DEFAULT ne soit définie, auquel cas la valeur est supposée être le chemin d'accès au fichier contenant le PMNS par défaut.

Les nouveaux noms sont spécifiés dans le fichier, les arguments et sont conformes à la syntaxe des spécifications PMNS, voir PMNS(5). Il y a un sous-arbre PMNS dans chaque fichier, et le chemin d'accès de base du PMNS du sous-arbre inséré est identifié par le premier groupe nommé dans chaque fichier, par exemple si les spécifications commencent


myagent.foo.stuff {
    mumble	123:45:1
    fumble	123:45:2
}

alors les nouveaux noms seront ajoutés au PMNS à la position non-feuille identifiée par myagent.foo.stuff, et suivant tous les autres noms avec le préfixe myagent.foo.

Les nouveaux noms doivent être contenus dans un seul sous-arbre de l'espace de noms. Si des sous-arbres disjoints doivent être ajoutés, ceux-ci doivent être regroupés dans des fichiers séparés et pmnsadd utilisé sur chacun, un par un.

Tous les fichiers définissant le PMNS doivent être situés dans le répertoire contenant la racine du PMNS, ce serait typiquement $PCP_VAR_DIR/pmns pour le PMNS par défaut, et cela impliquerait typiquement d'exécuter pmnsadd en tant que root.

À titre de cas spécial, si fichier contient une ligne commençant par root { alors il est supposé être un PMNS complet qui doit être fusionné, donc aucune extraction et réécriture de sous-arbre n'est effectuée et fichier est transmis directement à pmnsmerge(1).

Sous réserve que certaines vérifications d'intégrité initiales soient satisfaites, pmnsadd mettra à jour le PMNS en utilisant pmnsmerge(1) - si cela échoue pour une raison quelconque, l'espace de noms d'origine reste inchangé.

OPTIONS

Les options de ligne de commande disponibles sont :

-n pmnsfile
Charge un Espace de Noms de Métriques de Performance (PMNS) alternatif (PMNS(5)) depuis le fichier pmnsfile.
-?
Affiche le message d'utilisation et quitte.

ATTENTION

Une fois que l'écriture du nouveau fichier namespace a commencé, les signaux SIGINT, SIGHUP et SIGTERM seront ignorés pour protéger l'intégrité des nouveaux fichiers.

FICHIERS

$PCP_VAR_DIR/pmns/root
le PMNS par défaut, lorsque la variable d'environnement PMNS_DEFAULT est non définie

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

VOIR AUSSI

pmnsdel(1), pmnsmerge(1), pcp.conf(5), pcp.env(5) et PMNS(5).
