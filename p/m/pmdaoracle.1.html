PMDAORACLE(1) Manuel des commandes générales PMDAORACLE(1)

NOM

pmdaoracle - PMDA de base de données Oracle

DESCRIPTION

pmdaoracle est un PMDA Performance Co-Pilot qui extrait des données de performance en direct d'une base de données Oracle en cours d'exécution.

INSTALLATION

pmdaoracle utilise un fichier de configuration à partir de (dans cet ordre) :

  • /etc/pcpdbi.conf
  • $PCP_PMDAS_DIR/oracle/oracle.conf
  • ./oracle.conf

Ce fichier peut contenir des valeurs remplacées (code Perl) pour les paramètres listés au début de pmdaoracle.pl, par exemple :

  • $username - nom d'utilisateur pour se connecter à la base de données [défaut : 'SYSTEM']
  • $password - mot de passe pour se connecter à la base de données [défaut : 'manager']
  • $host - hôte sur lequel la base de données s'exécute [défaut : 'localhost']
  • $port - port sur lequel la base de données écoute [défaut : '1521']
  • $os_user - nom d'utilisateur du système d'exploitation (le PMDA s'exécutera avec l'identifiant utilisateur correspondant) [défaut : oracle]
  • @sids - un tableau d'identifiants de base de données $ORACLE_SID [défaut : ('master')]

Pour tester vos paramètres locaux, un script simple est fourni qui se connectera et se déconnectera de la base de données - vérifiant que la configuration fondamentale est en place avant de poursuivre. Si le script $PCP_PMDAS_DIR/oracle/connect.pl ne parvient pas à se connecter, ne procédez pas à l'installation du PMDA car elle échouera. Corrigez d'abord vos paramètres locaux.

Une fois cela configuré, vous pouvez accéder aux noms et valeurs des métriques de performance d'oracle en faisant ce qui suit en tant que root :

# cd $PCP_PMDAS_DIR/oracle
# ./Install

Pour désinstaller, les actions suivantes doivent être effectuées en tant que root :

# cd $PCP_PMDAS_DIR/oracle
# ./Remove

pmdaoracle est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove notifient pmcd(1) lorsque l'agent est installé ou supprimé.

ETAT DE LA CONNEXION

Par défaut, pmdaoracle tentera de manière agressive de maintenir des connexions persistantes à Oracle pour garantir des réponses rapides à ses requêtes, et se reconnectera automatiquement si une connexion est perdue.

Cependant, dans certaines circonstances, cela peut être indésirable, de sorte qu'un mécanisme manuel pmStore(3) est fourni pour contrôler explicitement la déconnexion et la reconnexion à une instance Oracle. Ceci peut être utilisé, par exemple, pour s'assurer que pmdaoracle n'est pas connecté lors de l'arrêt, afin de garantir un processus d'arrêt propre d'Oracle.

La commande pmstore (1) peut être utilisée pour se déconnecter et se reconnecter. En utilisant les instances individuelles de la métrique oracle.control.connected, on peut régler l'état de la connexion sur activé (1) ou désactivé (0). De plus, pminfo(1) peut rapporter l'état actuel des connexions Oracle.

# pminfo ‐f oracle.control.connected
oracle.control.connected
    inst [0 or "master"] value 1
# pmstore oracle.control.connected 0
oracle.control.connected inst [0 or "master"] old value=1 new value=0

FICHIERS

/etc/pcpdbi.conf
fichier de configuration pour tous les moniteurs de base de données PCP
$PCP_PMDAS_DIR/oracle/oracle.conf
fichier de configuration pour pmdaoracle
$PCP_PMDAS_DIR/oracle/sample.conf
fichier de configuration d'exemple pour pmdaoracle utilisant $LD_LIBRARY_PATH
$PCP_PMDAS_DIR/oracle/connect.pl
script de test de configuration pour la connectivité de la base de données Oracle
$PCP_PMDAS_DIR/oracle/Install
script d'installation de l'agent pmdaoracle
$PCP_PMDAS_DIR/oracle/Remove
script d'annulation d'installation de l'agent pmdaoracle
$PCP_LOG_DIR/pmcd/oracle.log
fichier journal par défaut pour les messages d'erreur de pmdaoracle

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. À chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).
