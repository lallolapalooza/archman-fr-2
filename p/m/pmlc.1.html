PMLC(1) Manuel des commandes générales PMLC(1)

NOM

pmlc - configurer interactivement les pmlogger actifs de Performance Co-Pilot

SYNTAXE

pmlc [-eiPz?] [-D debug] [-h hote] [-n fichier_pmns] [-p port] [-Z fuseau_horaire] [pid]

DESCRIPTION

pmlc peut être utilisé pour modifier les métriques et les instances que pmlogger(1) écrit dans une archive Performance Co-Pilot (voir PCPIntro(1)), la fréquence à laquelle les métriques sont collectées et si la journalisation est obligatoire, conseillée, activée ou désactivée. Il rapporte également l'état actuel de journalisation des métriques et des instances. pmlc peut être utilisé pour contrôler les instances pmlogger sur des hôtes distants ainsi que ceux sur l'hôte local.

Normalement, pmlc opère sur l'espace de noms des métriques de performance (PMNS) distribué, cependant si l'option -n est spécifiée, un PMNS local alternatif est chargé depuis le fichier fichier_pmns.

Si l'option -P est spécifiée, pmlc tentera de démarrer avec une connexion au pmlogger primaire sur l'hôte local. Si l'option -p est spécifiée, alors pmlc tentera de démarrer avec une connexion au pmlogger sur ce port TCP/IP. Alternativement, si pid est spécifié, une connexion à l'instance pmlogger avec cet identifiant de processus sera tentée au démarrage. L'option -h ne peut être utilisée que si -P, -p port ou un pid sont également spécifiés. Dans ce cas, pmlc se connectera initialement à l'instance pmlogger spécifiée (distante) sur hôte plutôt qu'à l'hôte local. Si la connexion à l'instance pmlogger spécifiée ne peut être établie, pmlc démarrera sans connexion. Ces options permettent typiquement de diriger le même fichier de commandes pmlc vers plusieurs instances pmlogger en variant les arguments de la ligne de commande. Notez que -P, -p port, pid et -h sont utilisés uniquement lors d'une connexion initiale à une instance pmlogger. Ils ne sont pas utilisés par défaut si des connexions ultérieures sont établies interactivement (voir la commande connect ci-dessous).

Par défaut, pmlc affiche l'heure selon le fuseau horaire local sur le système où pmlc est exécuté. L'option -Z change le fuseau horaire en fuseau_horaire dans le format de la variable d'environnement TZ comme décrit dans environ(7). L'option -z change le fuseau horaire à celui de l'instance pmlogger dont les informations sont obtenues. Une seule des options -z ou -Z peut être spécifiée.

Si l'entrée standard provient d'un tty, pmlc est interactif, avec des invites. Le drapeau -i peut être utilisé pour forcer le comportement interactif, et est typiquement utilisé conjointement avec -e pour afficher toutes les entrées de commande sur la sortie standard.

COMMANDES

Les commandes suivantes peuvent être utilisées :

show [ loggers ] [ @hote ]
Affiche les identifiants de processus de toutes les instances pmlogger exécutées sur l'hôte local (ou hote, si spécifié). Le pid du pmlogger primaire est entre parenthèses car il peut être référencé en tant que « primary » ainsi que par son pid.
connect pid [ @hote ]


connect primary [ @hote ]
Connecte pmlc au processus pmlogger spécifié. Toute connexion existante à une instance pmlogger est d'abord fermée. Chaque instance pmlogger acceptera une seule connexion à la fois, donc si la connexion est établie avec succès, votre pmlc sera le seul à contrôler l'instance pmlogger à laquelle il est connecté.
new volume
Cette commande fonctionne uniquement lorsqu'une connexion à une instance pmlogger est établie. Elle indique au pmlogger de fermer le volume courant de l'archive et d'en ouvrir un nouveau. Les volumes fermés peuvent être compressés et/ou déplacés vers un système distant, un stockage distant ou un stockage hors ligne, par exemple dans le cadre d'une procédure de gestion régulière d'archives pour contrôler la taille des fichiers d'archives physiques sur le système où pmlogger est exécuté.
status
Cette commande fonctionne uniquement lorsqu'une connexion à une instance pmlogger est établie. Elle affiche des informations sur l'état du pmlogger et de son archive associée.
timezone local | logger | "fuseau_horaire"
Cette commande définit le fuseau horaire utilisé lors de l'affichage des heures. local signifie utiliser le fuseau horaire de la machine sur laquelle pmlc est exécuté. logger signifie utiliser le fuseau horaire de la machine où l'instance pmlogger est exécutée. Alternativement, un fuseau_horaire explicite entre guillemets peut être fourni (voir TZ dans environ(7) pour les détails). Le fuseau horaire par défaut est local à moins que l'une des options -z ou -Z n'ait été fournie en ligne de commande.
flush
Cette commande fonctionne uniquement lorsqu'une connexion à une instance pmlogger est établie, et demande à l'instance pmlogger de vider sur disque tous les tampons associés à l'archive courante. Pour les anciens, sync est un synonyme de flush. Dans les versions actuelles de pmlogger(1), toutes les écritures sont non tamponnées et alignées sur les enregistrements logiques dans les fichiers externes, donc cette commande n'a aucun effet, mais est conservée pour des raisons de compatibilité ascendante.
disconnect
Déconnecte pmlc de l'instance pmlogger courante, le cas échéant.
sleep delai
Met pmlc en pause pendant delai millisecondes. Ceci peut être utile dans des utilisations scriptées de pmlc pour permettre à l'instance pmlogger courante de progresser sur les requêtes récentes avant d'interroger l'état.
help
Affiche un résumé des commandes disponibles.

h et ? sont des synonymes de help.

quit
Quitte pmlc.

Les commandes restantes interrogent et modifient l'état de journalisation des métriques et des instances. Elles ne fonctionneront que si pmlc a une connexion à une instance pmlogger. Les métriques peuvent être spécifiées sous forme de noms complets (par ex. hinv.ncpu) ou de sous-arbres du PMNS (par ex. hinv) qui sont développés pour inclure toutes les métriques du sous-arbre (par ex. hinv.ncpu, hinv.cpuclock, etc.). Les listes de métriques peuvent être spécifiées en les entourant d'accolades avec des espaces ou une virgule entre les métriques (par ex. {hinv.ncpu hinv.ndisk}). Les sous-arbres de métriques peuvent être inclus dans de telles listes.

Chaque spécification individuelle de métrique peut être qualifiée par une liste d'instances séparées par des espaces ou des virgules entre crochets (par ex. kernel.all.load["1 minute", "5 minute"]). Les noms d'instance externes ou les identifiants d'instance internes numériques ou les deux peuvent être utilisés dans la même liste (par ex. sample.colour.[red,1,"blue"]). Si une qualification d'instance est appliquée à un sous-arbre du PMNS, toutes les métriques du sous-arbre doivent avoir le même domaine d'instance. Les qualifications d'instance ne peuvent pas être appliquées à des listes complètes de métriques mais peuvent apparaître à l'intérieur de telles listes.

Si aucune instance n'est spécifiée pour une métrique, toutes les instances sont utilisées. Toutes les instances signifie toutes les instances disponibles au moment où l'instance pmlogger concernée récupère les métriques pour la journalisation. Si un domaine d'instance change avec le temps, ce n'est pas toujours la même chose que l'ensemble des instances affichées par pmlc, qui ne peut afficher que les instances actuellement disponibles. Pour éviter les erreurs involontaires, seules les instances actuellement disponibles pour pmlc peuvent apparaître dans les spécifications d'instance.

query listemétriques
L'état de journalisation actuel de chaque métrique (et instances, le cas échéant) dans listemétriques est affiché. Cela inclut l'état de journalisation (par ex. activé, peut-être, désactivé) et l'intervalle de journalisation pour chaque métrique (et instance) demandée. Les abréviations suivantes concernant les métriques (et instances) peuvent apparaître dans la sortie : adv, conseillé ; mand, obligatoire ; nl, non journalisé (pas dans l'archive) ; na, dans l'archive mais pas actuellement

SYNTAXE DE LA COMMANDE

La commande pmlc(1) est utilisée pour contrôler l'archiveur de métriques PCP.

L'archiveur de métriques PCP est disponible depuis son domaine PMNS.

Les commandes sont divisées en catégories :

[ log ] mandatory on interval metriclist
Cette forme de la commande log active la journalisation pour les métriques (et leurs instances) dans metriclist. interval spécifie la fréquence à laquelle les métriques/instances spécifiées doivent être journalisées. once indique que les métriques/instances doivent apparaître au plus une fois dans l'archive. Plus souvent, on utilise le mot-clé optionnel every suivi d'un nombre positif et de l'un des mots millisecond (ou msec), second (ou sec), minute (ou min), hour ou de leurs pluriels.

Notez que le mot-clé default, qui peut être utilisé pour l'intervalle par défaut dans un fichier de configuration de pmlogger(1), ne peut pas être utilisé dans pmlc.

Les limitations internes exigent que l'intervalle soit inférieur à (environ) 74 heures. Une valeur d'intervalle de zéro est synonyme de once.

[ log ] mandatory off metriclist
Indique à l'instance pmlogger de ne pas archiver les métriques/instances dans metriclist.
[ log ] mandatory maybe metriclist
Indique à l'instance pmlogger d'honorer toute demande ultérieure de journalisation consultative pour les métriques/instances dans metriclist. Si l'état de journalisation actuel des métriques/instances est obligatoire (activé ou désactivé), le nouvel état sera défini sur maybe (effectivement, désactivé de manière consultative). Si l'état actuel des métriques/instances est déjà consultatif (activé ou désactivé), les états des métriques/instances resteront inchangés.
[ log ] advisory on interval metriclist


[ log ] advisory off metriclist
La journalisation consultative n'est applicable que si le dernier état de journalisation spécifié pour une métrique/instance était "mandatory maybe" (ce qui permet un contrôle de journalisation consultative ultérieur) ou si l'état de journalisation est déjà consultatif. Ces deux instructions activent ou désactivent (respectivement) la journalisation consultative pour les métriques/instances spécifiées.

L'interprétation de l'intervalle est la même que pour le cas mandatory.

Aucun caractère de continuation n'est requis pour les commandes qui s'étendent sur plusieurs lignes.

Le mot at peut être utilisé indifféremment avec @.

Une demande d'archivage de toutes les instances d'une métrique remplacera toute demande antérieure de journalisation de toutes les instances ou d'instances spécifiques d'une métrique (si la demande spécifie une transition permise dans l'état de journalisation). Une demande d'archivage d'instances spécifiques d'une métrique alors que toutes les instances d'une métrique sont déjà journalisées est refusée par pmlogger.

OPTIONS

Les options de ligne de commande disponibles sont :

-e, --echo
Affiche toutes les entrées de commande sur la sortie standard.
-h host, --host=host
Connecte pmlogger sur host, plutôt que sur localhost par défaut.
-i, --interactive
Force le comportement interactif.
-n pmnsfile, --namespace=pmnsfile
Charge un espace de noms de métriques de performance (PMNS) alternatif depuis le fichier pmnsfile.
-p port, --port=port
Se connecte à l'archiveur pmlogger principal sur le port TCP/IP port.
-P, --primary
Se connecte à l'archiveur pmlogger principal.
-z, --logzone
Utilise l'heure locale de pmlogger comme fuseau horaire de reporting.
-Z timezone, --timezone=timezone
Utilise timezone pour la date et l'heure. Timezone est dans le format de la variable d'environnement TZ tel que décrit dans environ(7).
-?, --help
Affiche le message d'utilisation et quitte.

CONTRÔLE D'ACCÈS

pmlc peut avoir un accès et un contrôle restreints sur les processus pmlogger(1).

Si un pmlogger(1) est incapable d'exporter ses informations de contrôle vers le pmcd(1) local, alors cet pmlogger(1) ne peut pas être connecté ni contrôlé par pmlc. En pratique, cela signifie que le processus pmlogger(1) doit appartenir à l'utilisateur ``pcp'' et/ou au groupe ``pcp''. Si pmlogger(1) s'exécute sur l'hôte ``foo'', alors utilisez ``pminfo -f -h foo pmcd.pmlogger'' pour vérifier que le pmlogger(1) d'intérêt est connu de pmcd(1), sinon les instances pmlogger(1) qui ne sont pas rapportées par la commande pmlc show loggers @foo ne sont pas connues de pmcd(1) sur l'hôte ``foo''.

Si pmlogger(1) est lancé avec un fichier de configuration qui contient une section [access], alors pmlc ne pourra pas se connecter à cet pmlogger(1) à moins que les contrôles d'accès ne permettent un certain accès depuis l'hôte où pmlc est exécuté. Au minimum, cela nécessite que l'accès enquire soit autorisé dans la section de contrôle d'accès de pmlogger(1).

Si pmlc peut se connecter à l'pmlogger(1) d'intérêt, alors le tableau suivant résume les permissions nécessaires pour effectuer les différentes commandes pmlc :

Commande pmlc Accès pmlogger requis
show loggers Any
connect Any of enquire, advisory or mandatory
status Any of enquire, advisory or mandatory
query ... Any of enquire, advisory or mandatory
disconnect Any
log advisory ... advisory
log mandatory ... mandatory
new volume mandatory

ATTENTION

Si toutes les instances d'une métrique sont journalisées et qu'une demande est faite pour journaliser des instances spécifiques de la métrique avec le même état et la même fréquence, la demande peut sembler réussir, même si pmlogger a refusé la demande. Ce n'est normalement pas un problème, car les informations requises seront toujours placées dans l'archive par pmlogger.

Cependant, dans le cas où la métrique doit être journalisée une fois, le résultat n'est pas celui attendu. Lorsque pmlogger reçoit une demande d'archivage d'une métrique une fois, il place les valeurs actuelles de la métrique dans l'archive dès que possible, indépendamment du fait que la métrique soit déjà dans l'archive. Ceci peut être utilisé pour forcer des valeurs dans l'archive. Lorsqu'une demande d'archivage d'instances spécifiques d'une métrique arrive et est refusée parce que toutes les instances de la métrique sont déjà journalisées, pmlogger ne place pas les valeurs des instances demandées dans l'archive. Il renvoie l'état de journalisation actuel pour chaque instance demandée à pmlc. Les états demandés et renvoyés sont identiques, donc pmlc ne génère pas d'erreur comme il le devrait.

Pour s'assurer que seules certaines instances d'une métrique sont journalisées, il faut toujours désactiver la journalisation de toutes les instances de la métrique avant d'activer la journalisation pour les instances spécifiques requises.

DIAGNOSTICS

La plupart des messages d'erreur ou d'avertissement sont auto-explicatifs. Un message de la forme



Warning: unable to change logging state for...
suivi d'une liste de métriques (et éventuellement d'instances) indique que pmlogger a refusé la demande pour les métriques (et instances) qui apparaissent. Toutes les métriques (et instances) qui ont été spécifiées mais n'apparaissent pas dans le message ont vu leur état de journalisation mis à jour avec succès (pas de nouvelles est une bonne nouvelle). Habituellement, cet avertissement résulte d'une demande de journalisation consultative alors qu'un contrôle obligatoire est déjà en place, ou d'une demande de journalisation pour des instances spécifiques alors que toutes les instances sont déjà journalisées.

ENVIRONNEMENT

Si la variable d'environnement PMLOGGER_REQUEST_TIMEOUT n'est pas définie ou est définie à 0 (zéro), alors pmlc bloquera jusqu'à ce qu'une connexion soit établie avec pmlogger(1) sur le port demandé. Si PMLOGGER_REQUEST_TIMEOUT est définie à une valeur supérieure à zéro, alors pmlc échouera avec une erreur après ce nombre de secondes si une connexion n'est pas établie. Ceci peut être utilisé par des scripts administratifs tels que pmlogger_daily(1) pour interroger pmlogger lorsqu'il démarre jusqu'à ce qu'il soit prêt et écoute sur son port de contrôle.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes.

ms, bien que les informations soient parfois cryptiques et principalement destinées à fournir des directives aux développeurs plutôt qu'aux utilisateurs finaux. debug est une liste séparée par des virgules d'options de débogage ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmlc sont les suivantes :

Option Description
appl0 dump des métriques et des instances reçues
appl1 dump de l'état après l'analyse de chaque commande
