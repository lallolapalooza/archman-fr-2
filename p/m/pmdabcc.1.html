PMDABCC(1) Manuel des commandes générales PMDABCC(1)

NOM

pmdabcc - PMDA BCC

DESCRIPTION

pmdabcc est un Agent de Domaine de Métriques de Performance (PMDA) de Performance Co-Pilot (PCP) qui extrait les données de performance en direct des programmes étendus BPF (Berkeley Packet Filter) dans le noyau, en utilisant le frontend Python BCC (BPF Compiler Collection).

pmdabcc charge et agit comme un pont pour un nombre quelconque de modules Python PMDA BCC PCP configurés et séparés, exécutant des programmes BPF. Il devrait être possible d'utiliser les outils et programmes Python BCC existants avec les modules PMDA BCC PCP avec un effort raisonnable.

Voir la documentation BPF et BCC pour une description détaillée de chacun.

CONFIGURATION

pmdabcc lit un fichier de configuration obligatoire de style ini :

$PCP_PMDAS_DIR/bcc/bcc.conf

Ce fichier doit contenir une section [pmda]. Les options PMDA suivantes sont disponibles (leurs valeurs par défaut sont indiquées entre parenthèses), les options marquées d'un astérisque (*) peuvent être remplacées dans les sections de configuration spécifiques aux modules :

modules (non défini)
Le PMDA pmdabcc lit la configuration spécifique au module pour chaque module listé dans la liste de modules séparée par des virgules (obligatoire).
prefix (bcc.) *
Par défaut, toutes les métriques des modules apparaîtront sous l'arbre de l'espace de noms des métriques de performance (PMNS) bcc. Le prefix (facultatif) peut être utilisé pour modifier ce préfixe générique.
process_refresh (0)
Voir ci-dessous.
module_failure_fatal (True)
Une valeur booléenne pour module_failure_fatal (facultative) contrôle si un module échouant à la compilation doit entraîner l'arrêt complet du PMDA (ce qui est le défaut) ou s'il doit démarrer avec des modules potentiellement encore fonctionnels. Les erreurs de configuration de module et les erreurs internes (comme l'échec d'enregistrement des métriques PMNS fournies, voir PMNS(5)) entraîneront toujours l'échec du PMDA.

Notamment, l'option process acceptée par certains modules évalue les PID et noms de processus donnés au moment de l'initialisation du PMDA/module et applique un filtrage pour les processus trouvés à ce stade. Ceci est dû au fait que le programme BPF dans le noyau est compilé au moment de l'initialisation du module et, plus important encore, ils s'exécutent souvent dans des zones critiques de performance où il n'est pas acceptable d'effectuer des recherches de noms de processus à chaque fois qu'une requête est traitée par le programme BPF. Pour permettre aux modules de surveiller des processus nommés (par exemple, process = java) même s'ils redémarrent, process_refresh doit être défini sur un entier non négatif N pour actualiser dynamiquement les processus surveillés toutes les N secondes. Dans le cas où de nouveaux processus correspondant au filtre de processus sont apparus, le programme BPF en cours d'exécution est détaché et un nouveau programme BPF avec des informations PID mises à jour est installé (et s'il n'y a plus de PID correspondant au filtre, le programme BPF sera détaché pour éviter toute surcharge inutile).

Pour chaque module listé dans modules, une section [module] correspondante doit être définie, contenant au moins les options suivantes :

module
Définit le nom du fichier module Python réel à charger pendant le démarrage du PMDA sous le sous-répertoire modules de l'installation du PMDA BCC PCP.
cluster
Spécifie l'identifiant de cluster unique (voir PMNS(5)) pour les métriques fournies par le module sous le chemin PMNS.

Tous les modules acceptent, mais n'utilisent pas nécessairement, l'option booléenne debug.

Les modules peuvent également prendre en charge des options de configuration supplémentaires spécifiques aux modules, consultez le fichier de configuration par défaut pour leurs options prises en charge.

INSTALLATION

Pour installer, les opérations suivantes doivent être effectuées en tant que root :

# cd $PCP_PMDAS_DIR/bcc
# ./Install

Pour désinstaller, les opérations suivantes doivent être effectuées en tant que root :

# cd $PCP_PMDAS_DIR/bcc
# ./Remove

pmdabcc est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove notifient pmcd(1) lors de l'installation ou de la suppression de l'agent.

Dans le cas où module_failure_fatal est défini sur False, l'installation du PMDA sera considérée comme réussie même si certains ou même tous les modules configurés échouent au chargement. Dans ce cas, les valeurs des métriques fournies par les modules défaillants ne seront pas disponibles. Le fichier journal de l'agent pmdabcc (voir ci-dessous) contiendra des informations détaillées sur l'activation de chaque module.

Certains modules commenceront à fournir des valeurs uniquement après avoir collecté des données d'activités système associées. Par exemple, le module tcpperpid ne fournira aucune valeur à moins qu'il n'y ait des processus générant du trafic TCP sur le système.

FICHIERS

$PCP_PMDAS_DIR/bcc/bcc.conf
fichier de configuration pour l'agent pmdabcc
$PCP_PMDAS_DIR/bcc/modules/*.{py,python}
modules Python PMDA BCC disponibles pour l'agent pmdabcc
$PCP_PMDAS_DIR/bcc/Install
script d'installation pour l'agent pmdabcc
$PCP_PMDAS_DIR/bcc/Remove
script d'annulation d'installation pour l'agent pmdabcc
$PCP_LOG_DIR/pmcd/bcc.log
fichier journal par défaut pour les messages de l'agent pmdabcc

Notez que la valeur habituelle/par défaut pour $PCP_PMDAS_DIR est /var/lib/pcp/pmdas et la valeur par défaut pour $PCP_LOG_DIR est /var/log/pcp, mais ces paramètres dépendent de la plateforme.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).
