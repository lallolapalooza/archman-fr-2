PMIECONF(5) Manuel des formats de fichiers PMIECONF(5)

NOM

pmieconf - règles et personnalisations généralisées de pmie

DESCRIPTION

Les formats de fichiers pmieconf sont utilisés par l'outil pmieconf(1) comme moyen de généraliser les ensembles de règles pmie(1) afin qu'ils puissent être facilement configurés pour différents systèmes et différents environnements. Il existe deux formats de fichiers complètement différents (bien que étroitement liés) abordés ici, à savoir « pmieconf-rules » et « pmieconf-pmie ».

Le répertoire $PCP_VAR_DIR/config/pmieconf contient des informations sur toutes les règles et variables généralisées par défaut du système pmie, y compris les valeurs par défaut pour toutes les variables. Ces fichiers sont au format pmieconf-rules. Bien que de nouveaux fichiers pmieconf-rules puissent être ajoutés, les fichiers de ce répertoire ne doivent jamais être modifiés. Utilisez plutôt l'utilitaire pmieconf pour modifier les valeurs des variables dans le fichier de configuration pmie.

Le format pmieconf-pmie permet des personnalisations spécifiques au site des règles contenues dans les fichiers pmieconf-rules et de leurs variables associées. Le format pmieconf-pmie est généré par pmieconf et ne doit pas être modifié à la main. Ce fichier généré est au format pmie, avec des informations supplémentaires contenues en tête du fichier - ainsi, le format pmieconf-pmie est un sur-ensemble du format de fichier pmie (étendu pour contenir des personnalisations des règles généralisées, mais contenant également les règles de performance réelles à évaluer par pmie) qui peut également être analysé par pmie (toutes les extensions sont cachées dans des commentaires, et sont donc sans signification pour pmie lui-même).

Le fichier $PCP_VAR_DIR/config/pmieconf/config.pmie contient les paramètres locaux du système pour les variables configurables par pmieconf. Les paramètres de variables dans ce fichier remplacent les valeurs par défaut spécifiées dans $PCP_VAR_DIR/config/pmieconf/*/*.

SYNTAXE PMIECONF-PMIE

Toutes les lignes de personnalisation de règles dans une spécification pmieconf-pmie valide sont précédées de « // » et sont situées en tête du fichier - cela permet aux fichiers contenant une spécification pmieconf-pmie d'être analysés avec succès par pmie. Un fichier pmieconf-pmie doit toujours avoir la première ligne sous la forme :

    // pmieconf-pmie version chemin_pmieconf

La version spécifie quelle version de la syntaxe pmieconf-pmie doit être utilisée pour analyser ce fichier. Actuellement, la seule version prise en charge est 1. Le chemin_pmieconf spécifie le chemin d'accès aux fichiers pmieconf-rules qui ont été utilisés, par pmieconf, pour générer ce fichier. Ceci est discuté dans la page de manuel pmieconf(1) (voir l'option -r).

Le reste de la spécification se compose d'entrées sur une seule ligne pour chacune des variables modifiées. La syntaxe de chaque ligne est :

    // version_regle nom_regle variable_regle = valeur

La version_regle et le nom_regle sont utilisés pour identifier la règle à laquelle associer la personnalisation. Ils sont suivis du nom de la variable_regle (c'est-à-dire la variable de la règle nom_regle qui a été modifiée) pour laquelle la nouvelle valeur doit être utilisée.

Une spécification pmieconf-pmie doit être terminée par le mot-clé « end ». Ceci est utilisé par pmieconf pour distinguer où se terminent les personnalisations et où commence le composant de règle pmie réel.

EXEMPLE PMIECONF-PMIE

L'exemple suivant est un fichier au format pmieconf-pmie valide, tel que généré par pmieconf. Afin d'apporter des modifications à la main qui sont conservées par pmieconf, voir les commentaires contenus dans le fichier généré (ci-dessous) quant à l'endroit où de telles modifications doivent être apportées.

    // pmieconf-pmie 1 $PCP_VAR_DIR/config/pmieconf
    // 1 memory.exhausted delta = "4 minutes"
    // 1 memory.exhausted enabled = yes
    // 1 memory.exhausted pcplog_action = yes
    // end
    //
    // --- DEBUT SECTION GENEREE (ne pas modifier cette section) ---
    //     généré par pmieconf le :  [DATESTAMP]
    //
    // 1 memory.exhausted
    delta = 4 minutes;
    some_host (
        ( avg_sample (swap.pagesout @0..9 ) ) > 0 &&
        30 %_sample swap.pagesout >= 5
    ) -> shell 10 min "$PCP_BINADM_DIR/pmpost Severe demand for real memory" \
            " %vpgsout/s@%h";
    // --- FIN SECTION GENEREE (les modifications ci-dessous seront préservées) ---

Pour voir comment tout cela fonctionne, vous pouvez générer ce fichier comme suit :

    # cat - | pmieconf -f /tmp/pmieconf.out \
        -r $PCP_VAR_DIR/config/pmieconf/memory:$PCP_VAR_DIR/config/pmieconf/global
    modify memory.exhausted delta "4 minutes"
    modify memory.exhausted enabled yes
    modify memory.exhausted pcplog_action yes
    ^D
    #

Ensuite, vérifiez que le fichier généré est un fichier de configuration pmie valide en utilisant :

    # pmie -C /tmp/pmieconf.out

Ceci analyse le fichier, puis se termine après avoir signalé toute erreur de syntaxe. Remplacez maintenant -C par -v (ci-dessus), et regardez pmie faire son travail !

SYNTAXE PMIECONF-RULES

Une spécification pmieconf-rules se compose d'un certain nombre d'objets de données distincts qui forment ensemble une spécification de règle complète (notez qu'une spécification peut s'étendre sur plusieurs fichiers et même plusieurs sous-répertoires). Chaque objet doit avoir une chaîne d'identifiant et un type de données, suivis d'une liste (facultative) d'attributs.

La spécification générique d'un objet pmieconf-rules est donc :

    type identifiant [ attribut = valeur ]* ;

L'ensemble des types valides est : « rule » (définition de règle), « string » (chaîne de caractères arbitraire, entre guillemets doubles), « double », « integer », « unsigned », « percent » (nombre réel entre 0 et 100), « hostlist » (liste d'hôtes séparés par des espaces), « instlist » (liste d'instances de métrique séparées par des espaces), et les quatre types d'actions pmie, à savoir « print », « shell », « alarm » et « syslog ».

Les noms de règles utilisent le caractère « . » pour introduire le concept de groupe de règles, par exemple « memory.exhausted » associe cette règle au groupe « memory ». pmieconf peut fonctionner au niveau des groupes de règles ou des règles individuelles. Le nom de groupe « global » est réservé et ne peut pas être utilisé avec une règle.

Habituellement, lorsqu'un objet est créé, il est associé à la règle en cours. Cependant, si le nom d'un objet est précédé du nom de groupe réservé « global », cet objet est alors visible par toutes les règles.

L'ensemble des attributs valides est : « help » (texte descriptif sur cet objet), « modify » (la valeur est oui/non, indique si pmieconf doit autoriser les modifications), « enabled » (la valeur est oui/non, indique si c'est activé ou désactivé - ne signifie que pour les règles et les actions), « display » (oui/non - indique si pmieconf doit afficher cet objet), « default » (la valeur est déterminée par le type, et est la valeur par défaut pour cet objet), et spécifiquement pour les objets de type règle, les attributs « version », « predicate » et « enumerate ». « version » et « predicate » s'expliquent d'eux-mêmes (« predicate » doit équivaloir à une règle pmie valide une fois développée), mais « enumerate » nécessite une discussion plus approfondie.

La clause « enumerate » est utile lorsque vous souhaitez générer plusieurs règles pmie similaires à partir d'un seul prédicat. Ceci est particulièrement utile pour les définitions de règles souhaitant utiliser la clause « some_inst » dans le langage pmie sur plusieurs hôtes. Pour qu'une règle utilise ces éléments ensemble, elle doit être certaine que la liste d'instances est la même sur tous les hôtes surveillés. Ceci est rarement le cas, donc l'attribut « enumerate » nous permet de générer plusieurs règles, développées sur des variables de type « instlist » ou « hostlist ». Ces variables composent la valeur de l'attribut « enumerate » - qui est une liste séparée par des espaces de noms de variables « instlist » ou « hostlist ».

Les objets peuvent être incorporés dans les définitions d'autres objets en utilisant la syntaxe $identifiant$. Voir l'exemple plus loin pour un aperçu de l'utilité de ceci.

Lorsque pmieconf génère le fichier de configuration pmie, il examine chaque règle activée avec N actions activées (où N > 0) et développe la chaîne :

    // "version" identifiant
    delta = $delta$;
    "predicate" -> $threshold$ $action1$ & ... &a

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

mp; $actionN$ ;

Les variables delta, threshold et action sont définies globalement (en utilisant le mot-clé "global") pour toutes les règles, mais peuvent, bien sûr, être modifiées au niveau d'une règle individuelle ou d'un groupe de règles.

PMIECONF-RULES EXEMPLE

L'exemple suivant est une spécification unique de pmieconf-rules, montrant plusieurs aspects du langage discutés ci-dessus. L'exemple définit une règle ("memory.exhausted") et une chaîne ("rule").

    rule    memory.exhausted
            default = "$rule$"
            predicate =
    "some_host (
        ( avg_sample (swap.pagesout $hosts$ @0..9 ) ) > 0 &&
        $pct$ %_sample swap.pagesout $hosts$ @0..9 >= $threshold$
    )"
            enabled = yes
            version = 1
            help    =
    "Le système utilise la partition de swap pour la mémoire principale, et ce,
    sur au moins pct des 10 dernières évaluations de cette règle.
    Il semble y avoir une insuffisance de mémoire principale pour satisfaire
    les demandes résiduelles de la charge de travail actuelle.";
    string  rule
            default = "Demande sévère de mémoire vive"
            modify  = no
            display = no;

Notez que pour que la règle ci-dessus soit complète, "threshold" et "pct" devraient également être définis - pour l'expression complète de cette règle, référez-vous à $PCP_VAR_DIR/config/pmieconf/memory/exhausted.
