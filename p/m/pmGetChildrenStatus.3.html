NOM

pmGetChildrenStatus - renvoie les nœuds descendants d'un nœud PMNS et leur statut respectif

SYNTAXE C

#include <pcp/pmapi.h>

int pmGetChildrenStatus(const char *name,
char ***offspring, int **status);

cc ... -lpcp

DESCRIPTION

Étant donné un chemin d'accès pleinement qualifié à un nœud dans l'espace de noms des métriques de performance (PMNS) actuel, identifié par name, pmGetChildrenStatus renvoie via offspring une liste des noms relatifs de tous les nœuds descendants immédiats de name dans le PMNS actuel.

Dans un cas spécial, si name est une chaîne vide (c'est-à-dire ""), les descendants immédiats du nœud racine dans le PMNS seront retournés.

Si status n'est pas NULL, alors pmGetChildrenStatus renverra également le statut de chaque enfant via status. Le statut se référera soit à un nœud feuille (avec la valeur PMNS_LEAF_STATUS), soit à un nœud non-feuille (avec la valeur PMNS_NONLEAF_STATUS).

Normalement, pmGetChildrenStatus renvoie le nombre de noms descendants découverts, sinon une valeur inférieure à zéro en cas d'erreur. La valeur zéro indique que name est un nom de métrique valide, c'est-à-dire associé à un nœud feuille dans le PMNS.

La liste résultante de pointeurs offspring et les valeurs (les noms relatifs) auxquelles les pointeurs font référence auront été alloués par pmGetChildrenStatus avec un unique appel à malloc(3), et il incombe à l'appelant de pmGetChildrenStatus de libérer l'espace en appelant free(offspring) lorsque celui-ci n'est plus requis. Il en va de même pour le tableau status.

Lorsqu'une erreur survient, ou si name est un nœud feuille (c'est-à-dire si le résultat de pmGetChildrenStatus est inférieur à un), offspring et status sont indéfinis (aucun espace n'aura été alloué et par conséquent appeler free(3) est une très mauvaise idée).

DIAGNOSTICS

PM_ERR_NOPMNS
Échec d'accès à un PMNS pour l'opération. Notez que si l'application n'a pas appelé a priori pmLoadNameSpace(3) et souhaite utiliser le PMNS distribué, alors un appel à pmGetChildrenStatus doit être fait dans un contexte actuel.
PM_ERR_NAME
Le chemin d'accès name n'est pas valide dans le PMNS actuel.
PM_ERR_*
Les autres diagnostics concernent des échecs de protocole lors de l'accès au PMNS distribué.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5). Les valeurs de ces variables peuvent être obtenues par programme en utilisant la fonction pmGetConfig(3).
