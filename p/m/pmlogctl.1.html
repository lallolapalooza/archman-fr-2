PMLOGCTL(1) Manuel des commandes générales PMLOGCTL(1)

NOM

pmlogctl - gérer et contrôler les archiveurs Performance Co-Pilot

SYNTAXE

pmlogctl [-afmNV?] [-C args_verification] [-c classe] [-i identifiant] [-p politique] commande [hôte ...]

DESCRIPTION

pmlogctl peut être utilisé pour gérer les instances non-primaires de l'archiveur Performance Co-Pilot (PCP) pmlogger(1). Ce serait le plus pertinent dans une « ferme » d'archiveurs PCP où de nombreuses instances de pmlogger(1) créeraient des archives de données de performance collectées depuis pmcd(1) sur de nombreux hôtes distants.

L'instance primaire de pmlogger(1) est étroitement liée au processus local pmcd(1) et, par conséquent, partage la même infrastructure de contrôle, à savoir systemd(1) ou les scripts « rc » de init(1) de PCP. C'est pourquoi l'instance primaire de pmlogger(1) *ne peut pas* être gérée avec pmlogctl.

Pour plus de brièveté dans la description ci-dessous, le terme « instance » signifie une instance de pmlogger(1).

Toutes les instances gérées par pmlogctl, pmlogger_check(1) et pmlogger_daily(1) respectent les règles suivantes :

1.
Chaque instance récupère des données de performance d'un seul pmcd(1) (c'est-à-dire un hôte), mais chaque pmcd(1) peut fournir des données de performance à zéro, une ou plusieurs instances de pmlogger(1) s'exécutant sur un ou plusieurs hôtes.
2.
Sur l'hôte local, chaque instance de pmlogger(1) doit être spécifiée une fois dans un fichier de contrôle pmlogger_check(1) et pmlogger(1) crée des archives dans un répertoire unique, nommé dans le 4ème paramètre de l'entrée du fichier de contrôle associée (voir la section CONFIGURATION de pmlogger_check(1)).
3.
Chaque instance appartient à exactement une classe, nommée optionnellement à l'aide d'une affectation $class=... dans le fichier de contrôle associé. La classe spéciale default est réservée à toutes les instances qui n'ont pas d'affectation $class=... associée. À des fins de rapport (voir la commande summary ci-dessous), l'instance primaire de pmlogger(1) est automatiquement assignée à la classe spéciale primary.

Chaque exécution de pmlogctl gère une ou plusieurs instances en mettant à jour les fichiers de contrôle associés, puis en exécutant pmlogger_check(1) pour effectuer le changement souhaité.

Les arguments hôte sont généralement des noms d'hôtes valides. Pour toutes les commandes *sauf* create et cond-create (décrites ci-dessous), les arguments hôte peuvent également être des expressions régulières egrep(1) qui correspondent à la *totalité* d'un nom d'hôte valide, donc le motif utilisé est en fait ^hôte$. Par exemple, foo.* (correspond à tous les noms d'hôtes commençant par « foo ») ou .*foo (correspond à tous les noms d'hôtes se terminant par « foo ») ou .*[fF][oO][oO].* (correspond à tous les noms d'hôtes contenant « foo » en majuscules, minuscules ou mixte).

La combinaison d'une classe de l'option facultative -c (ou default) et des arguments hôte de chaque commande identifie un *ensemble cible* d'instances auxquelles l'opération de la commande doit être appliquée.

L'option -i peut être utilisée avec les commandes create ou cond-create pour remplacer l'identité de l'instance spécifiée dans la section ident du fichier de politique de classe (voir la section FICHIER DE POLITIQUE DE CLASSE ci-dessous). L'identifiant devant être unique parmi toutes les instances et toutes les classes, il n'est logique d'utiliser cette option que lorsqu'il y a un seul argument hôte.

Étant donné les tâches que pmlogctl entreprend, il doit généralement être exécuté en tant que « root », les exceptions étant la commande status ou lorsque l'option -N est spécifiée.

COMMANDES

commande est l'une des suivantes :

check
Vérifie l'état de toutes les instances pmlogger actuellement configurées et redémarre celles qui ont échoué. Si l'indicateur -m est donné sur les plateformes systemd(1), migre également les processus correspondants (et nouveaux) vers le service pmlogger_farm.
create
Crée de nouvelles instances dans la classe nom_classe (default par défaut) pour les hôtes hôte. Le nom de la classe est utilisé pour identifier un fichier de politique de classe (voir la section FICHIER DE POLITIQUE DE CLASSE ci-dessous) qui fournit un modèle pour chaque nouveau fichier de contrôle avec %h remplacé par hôte et %i remplacé par l'identifiant (unique) de l'instance à partir de la section ident du fichier de politique de classe ou identifiant de l'option -i.

L'option -p peut être utilisée pour identifier un fichier de politique de classe autre que celui trouvé à l'emplacement standard, c'est-à-dire $PCP_SYSCONF_DIR/pmlogger/class.d/nom_classe.

Au moins un hôte doit être spécifié pour la commande create.

cond-create
Similaire à create mais l'instance ne sera créée que si l'une des conditions dans la section de création du(des) fichier(s) de politique associé(s) est évaluée comme vraie.

Si une option -c est spécifiée, alors seule la classe nom_classe sera considérée, sinon toutes les classes seront considérées. Dans ce dernier cas, si aucune des conditions dans l'une des classes n'est évaluée comme vraie, la classe spéciale pmfind est utilisée (c'est la classe « default » pour la commande cond-create quand tout le reste échoue).

Si plus d'une classe est évaluée comme vraie, un fichier de configuration pmlogger(1) composite est créé et l'instance est également assignée à la classe spéciale pmfind. Le fichier de configuration composite peut contenir un mélange de clauses de configuration explicites et de clauses de configuration conditionnelles plus générales telles qu'interprétées par l'outil pmlogconf(1).

start
Démarre l'ensemble cible d'instances.

Si l'ensemble cible contient intentionnellement plus d'une instance, alors l'option -a doit être utilisée (ceci est conçu pour réduire le risque de démarrer accidentellement un nombre potentiellement élevé de processus pmlogger(1)).

Si une instance de l'ensemble cible est déjà démarrée, aucun changement n'est effectué (voir la commande restart pour forcer le lancement de nouvelles instances).

stop
Arrête l'ensemble cible d'instances.

Si l'ensemble cible contient intentionnellement plus d'une instance, alors l'option -a doit être utilisée (ceci est conçu pour réduire le risque d'arrêter accidentellement un nombre potentiellement élevé de processus pmlogger(1)).

Si une instance de l'ensemble cible est déjà arrêtée, aucun changement n'est effectué mais un avertissement est émis.

restart
Arrête puis démarre l'ensemble cible d'instances.

Si l'ensemble cible contient intentionnellement plus d'une instance, alors l'option -a doit être utilisée (ceci est conçu pour réduire le risque d'arrêter et de démarrer accidentellement un nombre potentiellement élevé de processus pmlogger(1)).

Si une instance de l'ensemble cible est déjà arrêtée, un avertissement est émis avant que l'instance ne soit démarrée.

status
Rapporte l'état de l'ensemble cible d'instances. S'il n'y a pas d'option -c spécifiée et pas d'arguments hôte, c'est-à-dire si l'ensemble cible est vide, alors *toutes* les instances seront rapportées.
destroy

Supprime l'ensemble cible d'instances.

Si l'ensemble cible contient intentionnellement plus d'une instance, alors l'option -a doit être utilisée (ceci est conçu pour réduire le risque de supprimer accidentellement un nombre potentiellement élevé de processus pmlogger(1)).

summary
Imprime un résumé des instances PCP non-primaires qui sont configurées pour être gérées par pmlogctl.

Le résumé inclut le nom de l'instance, l'identifiant de l'instance, le nom de l'hôte source, la classe de l'instance, la politique de l'instance et l'état de l'instance.

Si l'option -f est donnée, le nom de fichier de configuration est aussi imprimé.

reload
Force toutes les instances de l'ensemble cible à recharger leur configuration à partir de leurs fichiers de contrôle respectifs.

Cette commande est généralement utilisée après avoir modifié manuellement le fichier de contrôle d'une instance de pmlogger(1).

modify
Modifie la configuration de l'ensemble cible d'instances, en utilisant les informations fournies dans les fichiers de politique de classe.

Par exemple, cela peut être utilisé pour changer la fréquence d'échantillonnage ou les métriques collectées pour un ensemble d'instances.

rotate
Fait tourner les archives de l'ensemble cible d'instances.

Ceci est utile pour la gestion de l'espace disque, en s'assurant que les anciennes archives sont supprimées ou archivées.

OPTIONS

-a
Demande de confirmation avant d'appliquer une action à un ensemble cible d'instances qui contient plus d'une instance. Utile pour éviter de déclencher accidentellement des actions sur un grand nombre d'instances.
-f
Utilisé avec la commande summary pour imprimer le nom du fichier de configuration pour chaque instance.
-m
Sur les plateformes utilisant systemd(1), migre les processus pmlogger vers le service pmlogger_farm.
-N
Ne pas faire de vérifications d'identification de l'utilisateur. Ceci permet à un utilisateur non-root d'exécuter la commande status, et peut être utilisé avec d'autres commandes si l'infrastructure de contrôle sous-jacente le permet (par exemple, si des configurations spécifiques de sudo sont en place).
-V
Imprime la version de pmlogctl et quitte.
-?
Imprime un message d'aide et quitte.
-C args_verification
Spécifie des arguments de vérification pour la commande check. Ces arguments sont transmis à pmlogger_check(1) et peuvent être utilisés pour filtrer les instances qui sont vérifiées.
-c classe
Spécifie la classe d'instances à gérer. Si cette option n'est pas spécifiée, la classe default est utilisée par défaut, sauf pour les commandes cond-create et summary où cela peut avoir un comportement différent.
-i identifiant
Spécifie un identifiant d'instance personnalisé. Principalement utilisé avec les commandes create et cond-create pour remplacer l'identifiant défini dans le fichier de politique de classe. Doit être utilisé avec un seul argument hôte.
-p politique
Spécifie le chemin vers un fichier de politique de classe personnalisé. Utilisé avec les commandes create et cond-create.

FICHIER DE POLITIQUE DE CLASSE

Les fichiers de politique de classe sont stockés dans le répertoire $PCP_SYSCONF_DIR/pmlogger/class.d/. Chaque fichier de politique de classe définit comment une instance de pmlogger(1) doit être configurée. La structure d'un fichier de politique de classe est la suivante :

identifiant
Une section qui définit comment générer l'identifiant unique de l'instance. Typiquement, il utilise des variables comme %h pour l'hôte et %i pour un identifiant interne.
creation
Une section qui définit les conditions sous lesquelles une instance de cette classe doit être créée. Utilisée par la commande cond-create.
configuration
Une section qui contient les paramètres de configuration pour l'instance de pmlogger(1), tels que le répertoire d'archives, les métriques à collecter, la fréquence d'échantillonnage, etc. Ces valeurs peuvent inclure des substitutions de variables comme %h.

Pour plus de détails sur le format des fichiers de politique de classe, veuillez consulter la documentation de pmlogconf(1).

EXEMPLES

Pour démarrer toutes les instances non-primaires sur l'hôte mon_serveur :

    $ pmlogctl start mon_serveur

Pour arrêter toutes les instances dans la classe serveurs_web sur tous les hôtes dont le nom commence par www :

    $ pmlogctl -c serveurs_web stop www.*

Pour détruire toutes les instances configurées qui ne sont pas en cours d'exécution :

    $ pmlogctl destroy -c default

Pour vérifier l'état de toutes les instances et redémarrer celles qui ont échoué :

    $ pmlogctl check

Pour créer une nouvelle instance sur l'hôte db1 dans la classe bases_de_donnees, en utilisant le fichier de politique par défaut pour cette classe :

    $ pmlogctl -c bases_de_donnees create db1

>
Détruit l'ensemble cible d'instances. À la fin de cette opération, les processus pmlogger(1) associés auront été arrêtés et les informations du fichier de contrôle pertinentes auront été supprimées.

Si l'ensemble cible contient intentionnellement plus d'une instance, l'option -a doit être utilisée (cela est conçu pour réduire le risque de terminer accidentellement un nombre potentiellement important de processus pmlogger(1) et de supprimer leurs configurations pmlogger_check(1)).

Le fichier de politique lié à la classe d'une instance à détruire peut contenir une section destroy qui peut influencer si et comment l'opération de destruction doit être effectuée. Cela peut nécessiter une option -p pour trouver le fichier de politique de classe associé.

La vérification de la politique de classe peut être contournée à l'aide de l'option de ligne de commande -f (force).

FICHIER POLITIQUE CLASSE

Un fichier de politique de classe contient un certain nombre de sections, chaque section commence par une ligne qui commence simplement par le nom de la section entouré de ``['' et ``]''.

Les lignes commençant par un dièse (#) sont traitées comme des commentaires et ignorées. Les lignes vides ou vides sont également ignorées.

L'emplacement typique du fichier de politique pour la classe foo est $PCP_SYSCONF_DIR/pmlogger/class.d/foo.

[class]
La section optionnelle du nom de classe nomme la classe. Si elle est manquante, le nom du fichier de politique (en supprimant tout préfixe de répertoire) est utilisé comme nom de la classe.
[ident]
La section ident spécifie le modèle à utiliser pour l'identifiant de l'instance qui sera attribué à chaque membre de la classe. Cet identifiant doit être unique parmi toutes les instances et toutes les classes, et il doit s'agir d'un nom de fichier valide dans le système de fichiers local, il contiendra donc normalement le nom de la classe et la macro %h, par exemple foo-%h. La macro est remplacée par l'hôte lors de la création de chaque instance.
[control]
La section de contrôle se compose d'une ou plusieurs lignes de texte modèle qui seront utilisées pour créer le fichier de contrôle de chaque instance. Cela doit au moins inclure la ligne de contrôle pmlogger_check(1) pour spécifier comment démarrer le processus pmlogger(1) associé ; cette ligne contient des champs séparés par des espaces blancs comme suit :
1.
le nom d'hôte, généralement la macro %h
2.
n pour indiquer qu'il s'agit d'une instance non primaire
3.
le drapeau ``socks'', généralement n
4.
le répertoire dans lequel les archives pmlogger(1) seront créées ; il doit être unique et est généralement spécifié en utilisant la macro pmlogger_check(1) PCP_ARCHIVE_DIR comme début du chemin, suivi de l'identifiant de l'instance, généralement la macro %i, par exemple PCP_ARCHIVE_DIR/%i
5.
des paramètres supplémentaires pour pmlogger(1) qui incluent probablement au moins une option -c pour fournir un fichier de configuration qui décrit quelles métriques doivent être enregistrées pour les instances de cette classe, qui peut être la même pour toutes les instances de cette classe, ou elle peut inclure la macro %i pour utiliser un fichier de configuration différent pour chaque instance. Notez que si ce fichier de configuration n'existe pas, il sera créé à l'aide de pmlogconf(1) la première fois que pmlogger_check(1) est exécuté.

Avant la ligne de contrôle, il devrait y avoir une ligne qui définit la version de la ligne de contrôle qui suit, c'est-à-dire
$version=1.1
Si cela est manquant, pmlogctl supposera que la version est 1.1 et insérera la ligne lors de la création de l'instance.

pmlogctl ajoutera également le nom de la classe lors de la création. Par exemple
$class=foo

Dans un modèle de ligne de contrôle, une forme simple de substitution paramétrique est prise en charge. La macro ENV(spéc) est remplacée par du texte à l'aide de variables d'environnement comme suit :

  • Si spéc est de la forme var, alors la valeur de $var de l'environnement est utilisée. Si $var n'est pas définie ou a la valeur d'une chaîne vide, il s'agit d'une erreur.
  • Si spéc est de la forme var:défaut, alors si $var de l'environnement est définie et n'est pas une chaîne vide, la valeur de $var est utilisée, sinon la valeur défaut est utilisée. La substitution est simple, donc tout espace blanc entre le : et le ) est inclus dans défaut, et défaut ne peut pas contenir de ).

Par exemple
# unset PMPROXY_PORT; PMPROXY_HOST=foobar.com pmlogctl create ...
avec une ligne de modèle de contrôle de classe de politique qui inclut http://ENV(PMPROXY_HOST):ENV(PMPROXY_PORT:44322)
générera une ligne de contrôle qui inclut
http://foobar.com:44322

[create]
La section create définit les conditions qui doivent être remplies avant qu'une instance ne soit créée avec la commande cond-create. L'intention est de permettre de prendre différentes décisions lorsqu'un nouvel hôte exécutant pmcd(1) est découvert, par exemple par pmfind(1).

Chaque ligne non vide dans la section create est une condition de la forme fonction(arg), où fonction est l'une des suivantes :

existe
arg est le nom d'une métrique de performance et existes évalue à vrai si cette métrique existe dans l'espace des noms de métriques de performance (PMNS) sur l'hôte distant
valeurs
arg est le nom d'une métrique de performance dans le PMNS distant et valeurs évalue à vrai si une instance de cette métrique a une valeur sur l'hôte distant
condition
arg est une expression de métrique dérivée dans le format pris en charge par pmRegisterDerived(3), et condition évalue à vrai si la valeur de cette expression sur l'hôte distant est supérieure à zéro
hote
arg est une expression régulière dans le style de egrep(1) et hote évalue à vrai si le nom de l'hôte distant correspond à arg
[destroy]
La section destroy définit la politique à appliquer lors de la destruction d'une instance.

L'intention est de permettre de prendre différentes décisions lorsque le service de découverte, par exemple pmfind(1), constate qu'un hôte associé à une instance n'est plus présent. Mais dans la version actuelle, cela n'est pas implémenté et la syntaxe et la sémantique de la section destroy ne sont pas encore définies.

Un exemple de fichier de politique de classe est le suivant :

# fichier de politique pour la classe foo
[class]
foo
[ident]
foo-%h
[control]
$version=1.1
%h n n PCP_ARCHIVE_DIR/%i -c foo-metrics.config
[create]
# correspond à tous les hôtes
hostname(.*)
[destroy]
# reste à définir

OPTIONS

Les options de ligne de commande disponibles sont :

-a, --all
Applique l'action à toutes les instances correspondantes. Par défaut, une seule définition d'instance est attendue et traitée.
-c classe, --class=classe
Définit le nom de la classe à laquelle appartiennent les instances pmlogger(1) comme classe.
-C args_verif, --checkargs=args_verif
args_verif sont des arguments de ligne de commande supplémentaires pour pmlogger_check(1) lorsqu'il est appelé. Ceci est très utile pour des options telles que -V. Plusieurs options -C peuvent être utilisées et les différents arguments args_verif seront accumulés et tous passés à pmlogger_check(1).
-f, --force
Force l'action si possible.
-i ident, --ident=ident
Remplace l'identifiant de l'instance par ident. Cette option s'applique uniquement aux commandes create et cond-create.
-N, --showme
Exécute pmlogctl en mode « montre-moi » ou « essai » où l'intention de la commande est affichée, mais aucune modification n'est apportée.
-m, --migrate
Lorsqu'il est utilisé avec les commandes create ou check sur les plateformes systemd(1), migre également les processus pmlogger nouveaux ou existants non primaires vers le service pmlogger_farm. Ceci est normalement effectué automatiquement par le service pmlogger_farm_check, qui est piloté par une minuterie (il peut donc y avoir quelques minutes de délai avant que la migration automatique ne soit initiée).
-p politique, --policy=politique
Utilise politique comme fichier de politique de classe. Par défaut, $PCP_SYSCONF_DIR/pmlogger/class.d/<classe>.
-V, --verbose
Active le mode verbeux. Utiliser cette option deux fois augmente la verbosité. La sortie verbeuse est écrite sur stderr.
-?, --help
Affiche le message d'utilisation et quitte.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).
