PMCHART(1) Manuel des commandes générales PMCHART(1)

NOM

pmchart - outil de graphique en bande pour Performance Co-Pilot

SYNTAXE

pmchart [-CLVWz?] [-a archive] [-A align] [--archive-folio folio] [-c fichier_config] [-D debug] [-f famille_police] [-F taille_police] [-g geometrie] [-h hote] [-n fichier_pmns] [-o fichier_sortie] [-O decalage] [-p port] [-s echantillons] [-S heure_debut] [-t intervalle] [-T heure_fin] [-v visible] [-Z fuseau_horaire] [--geometry geometrie] [sources...]

DESCRIPTION

pmchart est un utilitaire graphique qui trace les valeurs des métriques de performance disponibles via les installations de Performance Co-Pilot (PCP). Plusieurs graphiques peuvent être affichés simultanément, soit alignés sur l'axe temporel unifié (axe X), soit grâce à l'utilisation de plusieurs onglets d'interface.

Les valeurs des métriques peuvent provenir d'un ou plusieurs hôtes en direct (simultanément). Alternativement, un ou plusieurs ensembles d'archives PCP peuvent être utilisés comme source de données historiques. Voir PCPIntro(1) pour une discussion approfondie des capacités du framework PCP, dont beaucoup sont utilisées par pmchart.

De nombreux aspects du comportement de pmchart peuvent être personnalisés via l'interface. En particulier, l'utilisation de "vues" (voir la section décrivant les VUES plus loin dans ce document) permet de stocker des ensembles prédéfinis de métriques et de paramètres de graphique comme les couleurs, l'échelle, les titres, les légendes, etc., pour une utilisation ultérieure, ou pour une utilisation avec différents hôtes et ensembles d'archives. De plus, la boîte de dialogue Préférences permet d'enregistrer et de restaurer les personnalisations du reste de l'interface utilisateur de pmchart entre différentes invocations de l'outil. Cela permet de configurer la couleur de fond par défaut, la couleur de surbrillance, le contenu et l'emplacement de la barre d'outils, et de nombreux autres aspects.

pmchart utilise intensivement l'utilitaire pmtime(1) pour le contrôle temporel, référez-vous à la page de manuel pmtime pour plus de détails sur son fonctionnement.

OPTIONS

Les options de ligne de commande disponibles sont :

-a archive, --archive=archive
Les valeurs des métriques de performance sont récupérées à partir de l'ensemble des archives Performance Co-Pilot (PCP) identifiées par cette option, par défaut. L'argument est une liste de noms séparés par des virgules, chacun pouvant être le nom de base d'une archive ou le nom d'un répertoire contenant une ou plusieurs archives. L'ensemble résultant d'archives sera la source des métriques de performance. L'onglet initial créé sera un onglet en mode archive. Plusieurs options -a peuvent être présentées, et la liste résultante d'ensembles d'archives est utilisée pour sourcer les valeurs des métriques. Tous les sources listés sur la ligne de commande sont supposés être des ensembles d'archives si cette option est utilisée.
-A align, --align=align
Force le premier échantillon à être aligné sur la limite d'une unité de temps naturelle align. Voir PCPIntro(1) pour une description complète de la syntaxe de align.
--archive-folio=folio
Lit les archives sources de métriques à partir du folio d'archives PCP folio.
-c fichier_config, --view=fichier_config
fichier_config spécifie une vue initiale à charger, en utilisant la source de métriques par défaut. Plusieurs vues -c peuvent être spécifiées, et elles seront toutes ouvertes dans l'onglet par défaut avec la source de métriques par défaut.
-c, --check
Utilisé avec -c, les vues sont analysées, toutes les erreurs sont rapportées, et l'outil se quitte. Ceci est principalement destiné à des fins de test. Si une deuxième option -C est présentée, pmchart se connecte également à pmcd(1) pour vérifier la sémantique des métriques.
-f famille, --font-family=famille
Spécifie la famille de polices par défaut à utiliser dans plusieurs composants du graphique, tels que le titre du graphique, la légende et l'étiquette de l'axe Y. La valeur par défaut est "Sans Serif". Ce paramètre n'affecte pas le reste de l'interface utilisateur, où la valeur est héritée de l'environnement dans lequel pmchart opère, et diffère selon l'apparence de chaque plateforme.
-F point, --font-size=point
Spécifie la taille en points de la police par défaut à utiliser dans plusieurs composants du graphique, tels que le titre du graphique, la légende et l'étiquette de l'axe Y. La valeur par défaut dépend de la plateforme, mais est soit 7, 8 ou 9. Ce paramètre n'affecte pas le reste de l'interface utilisateur.
-g geometrie, --geometry=geometrie
Génère une image avec la géométrie spécifiée (largeur et hauteur). Cette option est utile uniquement lorsqu'elle est utilisée conjointement avec l'option -o pour générer une image de sortie. L'argument géométrie prend la forme "LxH" (par exemple, 240x120). Lorsque vous n'utilisez PAS l'indicateur -o, pour spécifier la géométrie de la fenêtre d'affichage, utilisez -geometry geometrie où geometrie spécifie la largeur, la hauteur et éventuellement le placement souhaités de la fenêtre.
-h hote, --host=hote
Les valeurs actuelles des métriques de performance sont récupérées par défaut à partir de la machine hôte hote désignée. Plusieurs options -h peuvent être présentées, et la liste des hôtes est utilisée pour sourcer les valeurs des métriques. Tous les sources listés sur la ligne de commande sont supposés être des hôtes si cette option est utilisée.
-H chemin, --hostsfile=chemin
Spécifie le chemin vers un fichier contenant un ensemble de noms d'hôtes où pmcd(1) est en cours d'exécution, plutôt que d'utiliser localhost par défaut.
-K spec, --spec-local=spec
Lors de la récupération de métriques à partir d'un contexte local (voir -L), l'option -K peut être utilisée pour contrôler les PMDA DSO qui doivent être rendus accessibles. L'argument spec est conforme à la syntaxe décrite dans pmSpecLocalPMDA(3). Plusieurs options -K peuvent être utilisées.
-L, --local-PMDA
Utilise un contexte local pour collecter des métriques à partir de PMDA DSO sur l'hôte local sans PMCD. Voir également -K.
-n fichier_pmns, --namespace=fichier_pmns
Charge un espace de noms de métriques de performance (PMNS) alternatif (PMNS(5)) depuis le fichier fichier_pmns.
-o fichier_sortie, --output=fichier_sortie
Génère un fichier image nommé fichier_sortie, puis se quitte. Ceci est surtout utile lorsqu'il est exécuté avec un ensemble d'archives et une ou plusieurs vues. L'image générée sera dans le format spécifié par l'extension du fichier (déterminé automatiquement à partir de fichier_sortie). Si aucune extension ne peut être déterminée, alors le format GIF est utilisé et le fichier généré est nommé avec cette extension. Les formats de fichiers image pris en charge incluent : bmp, jpeg, jpg, png, ppm, tif, tiff, xbm et xpm.
-O origine, --origin=origine
Lors de la création de rapports sur les métriques archivées, commencez les rapports à origine dans la fenêtre temporelle (voir -S et -T). Voir PCPIntro(1) pour une description complète de la syntaxe de origine.
-p port, --guiport=port
Numéro de port pour la connexion à un processus de contrôle temporel pmtime existant.
-s echantillons, --samples=echantillons
Spécifie le nombre d'échantillons qui seront conservés avant de supprimer les anciennes données (remplacées par de nouvelles valeurs à la position temporelle actuelle). Cette valeur peut être modifiée ultérieurement via la boîte de dialogue d'édition d'onglet.
-S heure_debut, --start=heure_debut
Lors de la création de rapports archivés, démarrez à heure_debut. Voir PCPIntro(1) pour une description complète de la syntaxe pour heure_debut.
-t intervalle, --interval=intervalle
Spécifie le taux d'interrogation des métriques, en secondes, intervalle. L'intervalle par défaut est de 1 seconde. Si l'option -t est spécifiée, l'outil essaie de se connecter à un processus pmtime existant pour contrôler le temps.
-T heure_fin, --end=heure_fin
Lorsque vous créez des rapports archivés, terminez à heure_fin. Voir PCPIntro(1) pour une description complète de la syntaxe pour heure_fin.
-V, --version
Affiche la version de pmchart et se quitte.
-v visible, --visible=visible
Spécifie le nombre d'échantillons visibles dans le graphique. Les valeurs sont de 1 à 1024 échantillons. La valeur par défaut est de 60 échantillons.
-W, --window-style
Tente d'obtenir un style de fenêtre amélioré pour l'application.
-z, --host-config
Charge des métriques à partir de la configuration de l'hôte par défaut. Voir pmcd(1) pour plus de détails.
-Z fuseau_horaire, --timezone=fuseau_horaire
Utilise fuseau_horaire comme fuseau horaire par défaut pour toutes les opérations temporelles.
-D debug, --debug=debug
Active la journalisation de débogage pour les niveaux spécifiés dans debug. Voir pmDebug(3) pour une description de la syntaxe de debug.
--geometry geometrie
Spécifie la géométrie de la fenêtre d'application, y compris la taille et le placement optionnel. Par exemple : 800x600+100+50.
--permute
Réorganise les métriques dans les vues et/ou les graphiques en fonction de la séquence spécifiée dans les options -I ou -D. S'il n'y a pas d'option -I ou -D, les métriques sont organisées par nom.
-?, --help
Affiche un message d'utilisation et quitte.

SOURCES

La syntaxe des sources est la même que celle utilisée par les outils de la suite PCP comme pmdatop(1), pminfo(1) et pmrep(1). Il s'agit d'une liste de spécifications de métriques qui peuvent inclure des noms d'hôtes, des noms de fichiers d'archives et des noms de métriques. Par exemple :

host1:disk,host2:/path/to/archives:/proc/diskstats,disk

Les spécifications de métriques peuvent être préfixées par un nom d'hôte suivi d'un deux-points, par exemple : kernel:cpu. Si aucun nom d'hôte n'est spécifié, alors l'hôte actuellement défini par les options -h ou -H, ou le contexte par défaut (généralement localhost) est utilisé.

Les spécifications de métriques peuvent également être préfixées par un nom d'archive suivi d'un deux-points, par exemple : /path/to/archives/archive.0:disk. Si aucun nom d'archive n'est spécifié, alors l'archive actuellement définie par l'option -a, ou le contexte par défaut (généralement les archives en direct) est utilisée.

Si aucune source de métrique n'est spécifiée, alors pmchart tente de se connecter à l'hôte local.

VUES

Une "vue" est un ensemble de paramètres qui spécifie quelles métriques doivent être tracées, ainsi que leurs propriétés de traçage associées (couleur, étiquette, échelle, etc.). Les vues sont généralement stockées dans des fichiers texte utilisant un format spécifié par l'outil pmchart.conf(5). Les vues peuvent être chargées via l'option -c ou via le menu Fichier de l'interface graphique.

Lorsque plusieurs vues sont chargées, elles sont affichées dans des onglets distincts. Chaque onglet peut contenir plusieurs graphiques, et chaque graphique peut tracer plusieurs métriques.

DIAGNOSTICS

Les diagnostics de base sont générés en permanence et écrits sur la sortie d'erreur standard.

EXEMPLES

Pour afficher le graphique des métriques CPU et mémoire de l'hôte local, en utilisant l'intervalle de 5 secondes et en conservant 100 échantillons :

pmchart -t 5 -s 100 cpu memory

Pour afficher le graphique des métriques réseau et disque de l'hôte `plato`, en utilisant un fichier de vue prédéfini :

pmchart -h plato -c network.view net.if₁

Pour générer un fichier GIF de la métrique d'utilisation du disque à partir d'archives PCP :

pmchart -a /path/to/archives -o disk_usage.gif disk

Pour charger et afficher deux vues différentes à partir de fichiers de configuration :

pmchart -c cpu.conf -c memory.conf

CONTEXTE TEMPOREL

pmchart utilise le mécanisme de contrôle temporel de PCP. Cela signifie que le temps peut être contrôlé en temps réel ou à partir d'archives. La commande pmtime est généralement utilisée pour cela. Si pmchart est lancé avec l'option -t, il tentera de se connecter à un processus pmtime existant pour contrôler le temps.

VOIR AUSSI

PCPIntro(1), pmtime(1), pminfo(1), pmrep(1), pmdatop(1), pmcd(1), pmSpecLocalPMDA(3), pmDebug(3), PMNS(5), pmchart.conf(5).

orting archived metrics, the report will be restricted to those records logged at or after starttime. Refer to PCPIntro(1) for a complete description of the syntax for starttime.
-t interval, --interval=interval
Définit l'intervalle de mise à jour initial à autre chose que la seconde par défaut. L'argument interval suit la syntaxe décrite dans PCPIntro(1), et sous sa forme la plus simple peut être un entier non signé (les unités implicites dans ce cas sont les secondes).
-T endtime, --finish=endtime
Lors de la génération de rapports sur les métriques archivées, le rapport sera limité aux enregistrements consignés avant ou à endtime. Reportez-vous à PCPIntro(1) pour une description complète de la syntaxe de endtime.
-v samples, --visible=samples
Définit le nombre initial d'échantillons visibles qui seront affichés dans tous les graphiques de l'onglet par défaut. Cette valeur doit être inférieure ou égale au nombre total d'échantillons conservés (la valeur de -s).
-V, --version
Affiche le numéro de version de pmchart et quitte
-W, --white
Exportation des images avec un fond opaque (blanc)
-z, --hostzone
Change le fuseau horaire de reporting au fuseau horaire local de l'hôte qui est la source des métriques de performance, tel qu'identifié par les options -h ou -a.
-Z timezone, --timezone=timezone
Par défaut, pmtime rapporte l'heure de la journée selon le fuseau horaire local sur le système où pmchart est exécuté. L'option -Z change le fuseau horaire en timezone dans le format de la variable d'environnement TZ tel que décrit dans environ(7).
-?, --help
Affiche le message d'utilisation et quitte.

VUES

Le fichier de configuration principal de pmchart est la "vue", qui permet de sauvegarder les métadonnées associées à un ou plusieurs graphiques dans le système de fichiers. Ces métadonnées décrivent tous les aspects des graphiques, y compris les métriques et instances PCP à utiliser, les hôtes, les couleurs, les titres des graphiques, l'utilisation des légendes des graphiques, et bien plus encore.

D'un point de vue conceptuel, il existe deux classes de vues. Ces vues partagent le même format de fichier de configuration - reportez-vous à une section ultérieure pour une description complète de ce format. Les différences résident dans leur emplacement et la manière dont elles sont manipulées.

La première classe, la vue "système", est simplement toute vue qui est installée dans le cadre du paquet pmchart. Celles-ci sont stockées dans $PCP_VAR_DIR/config/pmchart. Lorsque la boîte de dialogue Fichier→Ouvrir la vue est affichée, ce sont ces vues qui sont initialement listées. Les vues système ne peuvent pas être modifiées par un utilisateur normal, et ne doivent pas être modifiées même par un utilisateur ayant les privilèges appropriés, car elles seront écrasées lors d'une mise à niveau.

La deuxième classe de vues est la vue "utilisateur". Ces vues sont créées à la volée à l'aide de la boîte de dialogue Fichier→Enregistrer la vue. C'est un mécanisme permettant aux utilisateurs individuels de sauvegarder leurs vues couramment utilisées. L'accès à ces vues se fait par la boîte de dialogue Fichier→Ouvrir la vue, comme pour les vues système. Une fois la boîte de dialogue ouverte, la liste des vues peut être basculée entre les vues utilisateur et système en cliquant sur les deux boutons de bascule dans le coin supérieur droit. Les vues utilisateur sont stockées dans $HOME/.pcp/pmchart.

ONGLETS

pmchart fournit le concept courant d'interface utilisateur d'onglet, qui est le plus répandu dans les navigateurs web modernes. Les onglets permettent à pmchart de mettre à jour beaucoup plus de graphiques que l'espace d'écran disponible ne le permet, en fournissant un mécanisme d'interface utilisateur pour empiler (et basculer entre) différents ensembles verticaux de graphiques. Le passage d'un onglet à l'autre se fait en cliquant sur les étiquettes des onglets, qui sont situées en haut de l'affichage sous les barres de menu et d'outils).

Chaque onglet a un mode de fonctionnement (en direct ou archive - pmchart peut prendre en charge les deux modes simultanément), le nombre total d'échantillons et de points actuellement visibles, et une étiquette décrivant l'onglet qui s'affiche en haut de la fenêtre pmchart. De nouveaux onglets peuvent être créés à l'aide de la boîte de dialogue Fichier→Ajouter un onglet.

Afin de gagner de l'espace d'écran vertical, notez que l'élément d'interface utilisateur permettant de changer d'onglet (et son étiquette) n'est affiché que lorsqu'il existe plus d'un onglet. Un onglet peut être fermé à l'aide du menu Fichier→Fermer l'onglet, qui supprime l'onglet actuel et tous les graphiques qu'il contenait.

IMAGES et IMPRESSION

Une copie statique de la série d'images actuellement affichées peut être capturée de deux manières.

Lorsque le périphérique d'affichage prévu est l'écran, l'option de menu Fichier→Exporter doit être utilisée. Cela permet d'exporter les graphiques dans divers formats d'image, y compris PNG, JPEG, GIF et BMP. La taille de l'image peut être mise à l'échelle vers le haut ou vers le bas dans n'importe quelle dimension.

Alternativement, lorsque le périphérique d'affichage prévu est le papier, l'option de menu Fichier→Imprimer peut être utilisée. Ceci prend en charge l'ensemble habituel d'options d'impression (choix de l'imprimante, niveaux de gris/couleur, paysage/portrait, mise à l'échelle sur différentes tailles de papier, etc.), et en outre permet d'imprimer vers les formats d'imprimante intermédiaires PostScript et Portable Document Format (PDF).

ENREGISTREMENT

Il est possible de faire un enregistrement d'un ensemble de graphiques affichés, pour une lecture ultérieure via pmchart ou tout autre outil du Performance Co-Pilot. La fonctionnalité Enregistrement→Démarrer est simple à configurer via l'interface utilisateur, et permet un réglage fin du processus d'enregistrement (y compris des fréquences d'enregistrement différentes de l'intervalle de mise à jour de pmchart, des emplacements de fichiers alternatifs, etc.).

pmchart produit des enregistrements compatibles avec le mécanisme de relecture de pmafm du PCP pmafm(1), pour une lecture ultérieure via une nouvelle instance de pmchart. De plus, lors de l'enregistrement via pmchart, on peut également rejouer l'enregistrement immédiatement, car à la fin de l'enregistrement (via l'élément de menu Enregistrement→Arrêter), un onglet en mode archive sera créé avec la vue capturée.

Une fois l'enregistrement actif dans un onglet en direct, le bouton d'état de contrôle du temps dans le coin inférieur gauche de la fenêtre pmchart est affiché avec un point rouge distinctif. À tout moment pendant une session d'enregistrement pmchart, l'espace disque utilisé par cet enregistrement peut être affiché en utilisant l'élément de menu Enregistrement→Interroger.

Enfin, l'option de menu Enregistrement→Détacher fournit un mécanisme par lequel le processus d'enregistrement peut être complètement dissocié du processus pmchart en cours, et être autorisé à continuer lorsque pmchart se termine. Une boîte de dialogue affichant la taille actuelle et le taux de croissance estimé de l'enregistrement est présentée. D'un autre côté, si pmchart est arrêté alors que l'enregistrement est en cours, le processus d'enregistrement invitera l'utilisateur à choisir l'arrêt immédiat de l'enregistrement ou à ce qu'il continue indépendamment.

Tous les services en mode enregistrement disponibles depuis pmchart sont implémentés avec l'aide des services de journalisation de base du Performance Co-Pilot - reportez-vous à pmlogger(1) et pmafm(1) pour une description détaillée des capacités de ces outils.

SYNTAXE DU FICHIER DE CONFIGURATION

pmchart charge les configurations de graphiques prédéfinies (ou "vues") à partir de fichiers externes qui respectent les règles suivantes. Dans les descriptions ci-dessous, les mots-clés (affichés en gras) peuvent apparaître en majuscules, minuscules ou en casse mixte, les éléments affichés entre [parenthèses carrées] sont optionnels, et les éléments fournis par l'utilisateur sont indiqués comme <autre chose>. Une barre verticale (|) est utilisée lorsque les éléments syntaxiques sont des alternatives. Les guillemets ("") peuvent être utilisés pour délimiter des éléments lexicaux qui peuvent contenir des espaces blancs, tels que les titres, les étiquettes et les noms d'instances.

1.
La première ligne définit le type de fichier de configuration et doit être 
#kmchart
bien que pmchart offre une compatibilité descendante pour les anciens formats de vues pmchart avec une ligne initiale de 
#pmchart
2.
Après la première ligne, les lignes commençant par "#" comme premier caractère ne correspondant pas à un espace blanc sont traitées comme des commentaires et ignorées. De même, les lignes vides sont ignorées.
3.
La ligne suivante doit être 
version <n> <clause-hote>
où <n> dépend du type de fichier de configuration, et est 1 pour pmchart sinon 1.1, 1.2 ou 2.0 pour pmchart.
La partie <clause-hote> est optionnelle (et ignorée) pour les fichiers de configuration pmchart, mais requise pour les fichiers de configuration pmchart, et est de la forme 
host literal
ou 
host dynamic
4.
Une configuration contient un ou plusieurs graphiques définis comme suit : 
chart [title <titre>] style <style> <options>
Si spécifié, le titre apparaîtra centré et au-dessus de la zone de graphique du graphique. Le <titre> est généralement entouré de guillemets ("") et s'il contient la séquence "%h", elle sera remplacée par la forme courte du nom d'hôte pour la source par défaut des métriques au moment où ce graphique a été chargé. Alternativement, "%H" peut être utilisé pour insérer le nom d'hôte complet. Si le nom d'hôte semble être une adresse inet ou IPv6, aucun raccourcissement ne sera tenté ; il sera utilisé
as-is dans les deux cas de remplacement. Une fois la vue chargée, la visibilité et la configuration du titre peuvent être manipulées à l'aide de la zone de texte Titre du graphique dans la boîte de dialogue Modifier→Graphique.

La balise <style> contrôle le style de traçage initial du graphique, et doit être l'un des mots-clés plot (graphique linéaire), bar, stacking (barres empilées), area ou utilization. Une fois la vue chargée, le style de traçage peut être modifié à l'aide de la liste déroulante Style dans Modifier→Graphique.

Les <options> sont zéro ou plusieurs des éléments optionnels :

[scale [from] <ymin> [to] <ymax>] [legend <onoff>]
Si scale est spécifié, la mise à l'échelle verticale est définie pour tous les tracés du graphique sur une plage y définie par <ymin> et <ymax>. Sinon, l'axe vertical sera ajusté automatiquement en fonction des valeurs actuellement tracées.

<onoff> est l'un des mots-clés on ou off et la clause legend contrôle la présence ou l'absence de la légende du tracé sous la zone graphique. Par défaut, la légende est affichée. Une fois la vue chargée, la visibilité de la légende peut être basculée à l'aide du bouton Afficher la légende dans la boîte de dialogue Modifier→Graphique.

5.
pmchart prend en charge une clause global pour spécifier les dimensions de la fenêtre de premier niveau (en utilisant les mots-clés width et height), le nombre de points visibles (mot-clé points) et les positions de départ des axes X et Y à l'écran (mots-clés xpos et ypos). Chacun de ces attributs global prend une valeur entière comme seul qualificateur.
6.
Chaque chart a un ou plusieurs tracés associés, tels que définis par l'une des spécifications suivantes : 
plot
    [legend <title>] [color <colorspec>] [host <hostspec>]
    metric <metricname>
    [ instance <inst> | matching <pat> | not-matching <pat> ]

Le mot-clé plot peut être remplacé par le mot-clé optional-plot, auquel cas si la source des données de performance n'inclut pas la métrique de performance et/ou l'instance spécifiée, ce tracé sera silencieusement supprimé du graphique.

Si spécifié, le titre apparaîtra dans la légende du graphique. Le <title> est généralement entouré de guillemets (") et peut contenir un ou plusieurs caractères génériques qui seront développés en utilisant le nom de la métrique, le nom de l'instance et le nom de l'hôte pour le tracé. Les caractères génériques sont "%i" (nom d'instance court et unique, jusqu'au premier espace blanc), "%I" (nom d'instance complet), "%h" (nom d'hôte court, jusqu'au premier point), %H (nom d'hôte complet), "%m" (nom de métrique raccourci aux deux derniers composants PMNS) et "%M" (nom de métrique complet).

Pour les anciens fichiers de configuration pmchart, le mot-clé title doit être utilisé à la place de legend. Désormais, pmchart prend en charge les deux mots-clés.

La clause color est facultative pour les nouveaux fichiers de configuration pmchart, mais elle était obligatoire dans le format original des fichiers de configuration pmchart. <colorspec> peut être l'une des suivantes :

#-cycle
rgbi:rr:gg:bb
#rgb
#rrggbb
#rrrgggbbb
#rrrrggggbbbb
<Xcolor>
où chacun de r, g et b sont des chiffres hexadécimaux (0-9 et A-F) représentant respectivement les composantes de couleur rouge, verte et bleue. <Xcolor> est l'un des noms de couleur de la base de données de couleurs X, par exemple red ou steelblue, voir également la sortie de showrgb(1).

La spécification de couleur #-cycle indique que pmchart doit utiliser la couleur suivante d'une palette de couleurs qu'il utilise de manière cyclique pour chaque graphique. C'est le comportement par défaut si la clause color est omise.

Le <hostspec> dans la clause host peut être un nom d'hôte, une adresse IP ou un astérisque (*); ce dernier est utilisé pour signifier la source par défaut des métriques de performance. Pour les anciens fichiers de configuration pmchart, la clause host doit être présente, pour les nouveaux fichiers de configuration pmchart elle est facultative, et si elle est manquante, la source par défaut des métriques de performance sera utilisée.

La spécification d'instance facultative,

(a)
est omise, auquel cas un tracé sera créé pour chaque instance de la métrique <metricname>
(b)
commence par instance, auquel cas seule l'instance nommée <inst> sera tracée
(c)
commence par matching, auquel cas toutes les instances dont les noms correspondent au motif <pat> seront tracées; le motif utilise la notation d'expression régulière étendue dans le style de egrep(1) (se référer à la vue PMCD pour un exemple)
(d)
commence par not-matching, auquel cas toutes les instances dont les noms ne correspondent pas au motif <pat> seront tracées; le motif utilise la notation d'expression régulière étendue dans le style de egrep(1) (se référer à la vue Netbytes pour un exemple)

pmchart utilise une notation syntaxique bizarre où <inst> et <pat> s'étendent du premier caractère non blanc jusqu'à la fin de la ligne d'entrée. Pour les fichiers de configuration pmchart, ces éléments sont soit délimités par des espaces blancs, soit entourés de guillemets (").

7.
La directive facultative tab peut être utilisée pour créer des vues avec plusieurs graphiques qui s'étendent sur plusieurs onglets. La syntaxe est la suivante : 
tab <label> [host <host>] [points <points> [samples <samples>]]


Toutes les spécifications de graphique suivant ce mot-clé seront créées
sur le nouvel onglet, jusqu'à la fin du fichier de configuration ou jusqu'à
ce qu'un autre mot-clé tab soit rencontré.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

À noter en particulier, le paramètre $PCP_XCONFIRM_PROG est explicitement et inconditionnellement remplacé par pmchart. Il est défini sur l'utilitaire pmconfirm(1), afin que certaines boîtes de dialogue (en particulier dans le domaine de l'enregistrement) conservent une apparence cohérente avec le reste de l'application pmchart.

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmchart sont les suivantes :

Option Description
appl2 analyse et chargement de la vue
appl3 analyseur lexical de l'analyse de la vue
