PMDAATTRIBUTE(3) Manuel des fonctions de bibliothèque PMDAATTRIBUTE(3)

NOM

pmdaAttribute - informe un PMDA des attributs de connexion client

SYNTAXE C

#include <pcp/pmapi.h>
#include <pcp/pmda.h>

int pmdaAttribute(int context,
int key, char *value, int length, pmdaExt *pmda);

cc ... -lpcp_pmda -lpcp

DESCRIPTION

Dans le cadre de l'API du domaine d'agents de métriques de performance (PMDA) (voir PMDA(3)), pmdaAttribute est le rappel générique pour répondre aux attributs de connexion client. Ces attributs incluent les informations d'identification du client, telles que l'ID utilisateur et l'ID de groupe.

Un PMDA qui prend en charge les attributs de connexion fournira un rappel pmdaAttribute privé en l'assignant à version.six.attribute de la structure pmdaInterface, et implémentera une logique personnalisée pour toute paire d'attributs clé-valeur qui l'intéresse.

Tous les attributs sont associés à un contexte client spécifique, et ceux-ci peuvent être identifiés de manière unique en utilisant l'argument ctx comme premier argument. Le PMDA doit suivre les connexions et les déconnexions des clients en utilisant l'interface pmdaSetEndContextCallBack(3), en conséquence. L'interface pmdaGetContext(3) peut également être particulièrement utile.

Tous les attributs sont passés sous forme de paires clé-valeur et la valeur est toujours passée sous forme de chaîne de caractères terminée par un caractère nul de la longueur donnée. Cela inclut les attributs numériques tels que l'ID utilisateur.

Les attributs les plus couramment utilisés seraient PCP_ATTR_USERID et PCP_ATTR_GROUPID, mais d'autres peuvent également être transmis facultativement (tels que PCP_ATTR_USERNAME) s'ils sont disponibles. Certains attributs seront consommés par pmcd et jamais transmis aux PMDA, tels que PCP_ATTR_PASSWORD. Une liste complète de tous les attributs possibles se trouve dans les en-têtes listés ci-dessus, tous sont préfixés par PCP_ATTR.

ATTENTION

Le PMDA doit utiliser PMDA_INTERFACE_6 ou une version ultérieure, comme spécifié dans l'appel à pmdaDSO(3) ou pmdaDaemon(3).

DIAGNOSTICS

pmdaAttribute doit renvoyer soit zéro en cas de succès, soit un code de retour négatif pour indiquer une erreur dans le traitement de l'attribut. Ce code de retour ne peut pas être utilisé pour indiquer qu'un client doit se voir refuser l'accès - une telle fonctionnalité doit être effectuée par l'agent en réponse aux rappels pour le client en question (en utilisant PM_ERR_PERMISSION pour ces rappels spécifiques, pour ce client spécifique. Autrement dit, les erreurs seront transmises à PMCD, mais aucune garantie n'est faite que l'erreur sera renvoyée au client et entraînera sa terminaison, par exemple.

VOIR AUSSI

PMAPI(3), PMDA(3), pmdaDaemon(3), pmdaDSO(3), pmdaMain(3) et pmdaGetContext(3).
