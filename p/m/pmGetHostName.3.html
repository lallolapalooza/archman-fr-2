pmGetHostName(3)

Paquet: pcp

PMGETCONTEXTHOSTNAME(3) Manuel des fonctions de bibliothèque PMGETCONTEXTHOSTNAME(3)

NOM

pmGetHostName, pmGetContextHostName, pmGetContextHostName_r - retourner le nom d'hôte associé à un contexte Performance Co-Pilot

C SYNTAXE

#include <pcp/pmapi.h>

int pmGetHostName(int id, char *buf, int buflen);
const char *pmGetContextHostName(int id);
char *pmGetContextHostName_r(int id, char *buf, int buflen);

cc ... -lpcp

DESCRIPTION

Étant donné un identifiant de contexte PCP valide précédemment créé avec pmNewContext(3) ou pmDupContext(3), la fonction pmGetContextHostName retourne le nom d'hôte associé à id. La fonction pmGetContextHostName_r fait de même, mais stocke le résultat dans un tampon fourni par l'utilisateur buf d'une longueur buflen, qui devrait avoir de la place pour au moins MAXHOSTNAMELEN octets. La fonction pmGetHostName se comporte de manière similaire, mais retourne un code d'état pour indiquer le succès ou l'échec.

Si le contexte id est associé à une source de données d'archive, le nom d'hôte retourné est extrait de l'étiquette d'archive en utilisant pmGetArchiveLabel(3).

Pour les contextes en direct, une tentative sera d'abord faite pour récupérer le nom d'hôte du système collecteur PCP en utilisant pmFetch(3) avec la métrique pmcd.hostname. Cela permet aux outils clients utilisant cette interface de récupérer un identifiant d'hôte précis, même en présence de transfert de ports et de connexions tunnelisées.

Si cela échoue, une méthode de repli est utilisée. Pour les contextes locaux - locaux signifiant tout de DSO, ``localhost'' ou une connexion par socket de domaine Unix - un nom d'hôte sera recherché via gethostname(3). Pour d'autres contextes, le nom d'hôte extrait de la spécification d'hôte du contexte initial sera utilisé.

VALEUR DE RETOUR

Si id n'est pas un identifiant de contexte PCP valide, le nom d'hôte retourné est une chaîne de longueur zéro.

En cas d'échec, le code de retour de pmGetHostName est un code d'erreur PMAPI négatif qui peut être traité par pmErrStr_r(3) pour le diagnostic de l'échec d'obtention du nom d'hôte du contexte.

NOTES

pmGetContextHostName retourne un pointeur vers un tampon statique, donc la valeur retournée n'est valide que jusqu'au prochain appel à pmGetContextHostName et n'est donc pas thread-safe. Les applications multithread devraient plutôt utiliser pmGetHostName ou pmGetContextHostName_r.

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5). Les valeurs de ces variables peuvent être obtenues par programme en utilisant la fonction pmGetConfig(3).
