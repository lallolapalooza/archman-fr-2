NOM

pmGetArchiveEnd - localiser la fin logique du fichier pour un ensemble d'archives

SYNTAXE C

#include <pcp/pmapi.h>

int pmGetArchiveEnd(struct timespec *tp);

cc ... -lpcp

DESCRIPTION

En supposant que le contexte PMAPI actuel est associé à un ensemble d'archives, pmGetArchiveEnd tentera de trouver la fin logique du fichier (après le dernier enregistrement complet dans l'ensemble d'archives) et retournera le dernier horodatage enregistré via tp. Cet horodatage peut être passé à pmSetMode(3) pour positionner de manière fiable le contexte sur le dernier enregistrement d'archive valide, par exemple, en préparation d'une lecture ultérieure en ordre chronologique inverse.

Pour les archives qui ne sont pas écrites simultanément, la fin physique du fichier et la fin logique du fichier coïncident. Cependant, si une archive est en cours d'écriture par pmlogger(1) en même temps qu'une application essaie de lire l'archive, la fin logique du fichier peut être antérieure à la fin physique du fichier en raison de la mise en mémoire tampon d'écriture qui n'est pas alignée sur les limites logiques des enregistrements.

pmGetArchiveEnd retourne une erreur inférieure à zéro si le contexte n'est ni valide, ni associé à un ensemble d'archives, ou si l'ensemble d'archives est gravement corrompu. Sinon, la valeur de retour est 0 s'il n'y a pas eu de changement d'état depuis le dernier appel, ou 1 si la fin logique du fichier a progressé depuis le dernier appel.

En l'absence d'erreur, le résultat retourné via tp est bien défini.

Les deux pmGetArchiveEnd préservent l'état de positionnement du fichier d'archive avant cet appel de fonction.

COMPATIBILITÉ

Avant PCP 7.0 et libpcp.so.4, l'argument tp était une struct timeval. Pour prendre en charge la transition de PMAPI, l'ancienne interface et sémantique peuvent être utilisées si les applications sont liées avec libpcp.so.3 ou recompilées avec -DPMAPI_VERSION=2.

Pendant un temps, dans PCP 6.x, il existait une routine avec la même sémantique que pmGetArchiveEnd actuelle, appelée pmGetHighResArchiveEnd, bien que celle-ci soit maintenant dépréciée et que le support de compilation pour pmGetHighResArchiveEnd sera supprimé dans une future version.

DIAGNOSTICS

PM_ERR_NOCONTEXT
le contexte PMAPI actuel est invalide, ou n'est pas associé à un ensemble d'archives
PM_ERR_LOGREC
l'ensemble d'archives est suffisamment endommagé pour qu'aucun enregistrement valide ne puisse être trouvé

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5). Les valeurs pour ces variables peuvent être obtenues par programme en utilisant la fonction pmGetConfig(3).
