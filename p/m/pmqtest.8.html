NOM

pmqtest - Lance une paire de threads et mesure la latence de la communication inter-processus avec les files d'attente de messages POSIX

SYNTAXE

pmqtest [-a|-a PROC] [-b USEC] [-d DIST] [-D TIME] [-f TO] [-h] [-i INTV] [--json FILENAME] [-l LOOPS] [-p PRIO] [-q] [-S] [-t|-t NUM]

DESCRIPTION

Le programme pmqtest démarre des paires de threads synchronisées via mq_send/mw_receive() et mesure la latence entre l'envoi et la réception du message.

OPTIONS

-a, --affinity[=PROC]
Exécuter sur le processeur numéro PROC. Si PROC n'est pas spécifié, exécuter sur le processeur actuel.
-b, --breaktrace=USEC
Envoyer une commande de traçage d'interruption lorsque la latence est > USEC. Ceci est une option de débogage pour contrôler le traceur de latence dans le patch de préemption temps réel. Il est utile pour identifier des latences système inattendues importantes.
-d, --distance=DIST
Définir la distance des intervalles des threads en microsecondes (par défaut 500 µs). Lorsque pmqtest est appelé avec l'option -t et que plus d'un thread est créé, cette valeur de distance est ajoutée à l'intervalle des threads : Intervalle(thread N) = Intervalle(thread N-1) + DIST
-D, --duration=TIME
Spécifier une durée pour l'exécution du test.
Ajouter 'm', 'h', ou 'd' pour spécifier les minutes, heures ou jours.
-h, --help
Afficher le message d'aide
-f, --forcetimeout=TO
Définir un délai artificiel de la fonction d'envoi pour forcer le timeout du récepteur, nécessite l'option -T
-i, --interval=INTV
Définir l'intervalle de base du ou des threads en microsecondes (par défaut 1000 µs). Ceci définit l'intervalle du premier thread. Voir aussi -d.
--json=FILENAME
Écrire les résultats finaux dans FILENAME, au format JSON.
-l, --loops=LOOPS
Définir le nombre de boucles. La valeur par défaut est 0 (sans fin). Cette option est utile pour les tests automatisés avec un nombre donné de cycles de test. pmqtest s'arrête une fois que le nombre d'intervalles de temps a été atteint.
-p, --prio=PRIO
Définir la priorité du processus.
-q, --quiet
Afficher un résumé uniquement à la sortie. Utile pour les tests automatisés, où seul le résumé de sortie doit être capturé.
-S, --smp
Mode de test pour le multi-traitement symétrique, implique -a et -t et utilise la même priorité sur tous les threads.
-t, --threads[=NUM]
Définir le nombre de threads de test (par défaut 1, si cette option n'est pas donnée). Si NUM est spécifié, créer NUM threads de test. Si NUM n'est pas spécifié, NUM est défini sur le nombre de CPU disponibles.
-T, --timeout=TO
Utiliser mq_timedreceive() au lieu de mq_receive() et spécifier le délai TO en secondes.
