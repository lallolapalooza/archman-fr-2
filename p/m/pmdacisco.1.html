PMDACISCO(1) Manuel des commandes générales PMDACISCO(1)

NOM

pmdacisco - agent de domaine de métriques de performance pour routeurs Cisco (PMDA)

SYNTAXE

$PCP_PMDAS_DIR/cisco/pmdacisco [-D debug] [-d domaine] [-l fichier_journal] [-U nom_utilisateur] [-P mot_de_passe] [-r rafraichissement] [-s invite] [-M nom_utilisateur] [-x port] hote:spec_interface [...]
$PCP_PMDAS_DIR/cisco/parse [options] hote:spec_interface [...]
$PCP_PMDAS_DIR/cisco/probe [-D debug] [-P mot_de_passe] [-s invite] [-U nom_utilisateur] [-x port] hote

DESCRIPTION

pmdacisco est un agent de domaine de métriques de performance (PMDA) qui extrait les métriques de performance d'un ou plusieurs routeurs Cisco.

Une brève description des options de ligne de commande de pmdacisco suit :

-d
Il est absolument crucial que le numéro de domaine des métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire que le domaine doit être différent pour chaque PMDA sur un même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé cisco.log est écrit dans le répertoire courant de pmcd(1) lors du démarrage de pmdacisco, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est envoyée à l'erreur standard à la place.
-P
Par défaut, il est supposé qu'aucun mot de passe au niveau utilisateur n'est requis pour accéder au port telnet de Cisco. Si des mots de passe au niveau utilisateur ont été activés sur les Cisco, ces mots de passe doivent être spécifiés à pmdacisco. Si spécifié avec l'option -P, mot_de_passe sera utilisé comme mot de passe utilisateur par défaut pour tous les Cisco. Voir également la section IDENTIFICATION DE L'INTERFACE ci-dessous.
-r
pmdacisco rafraîchira les valeurs courantes pour toutes les métriques de performance en contactant chaque routeur Cisco une fois toutes les rafraichissement secondes. Le rafraichissement par défaut est de 120 secondes.
-s
L'invite de commande Cisco se termine par la chaîne invite. La valeur par défaut est « > ». La seule façon pour pmdacisco de synchroniser l'envoi des commandes et l'analyse de la sortie est de reconnaître invite comme une chaîne unique qui se trouve à la fin de toute sortie, c'est-à-dire comme l'invite de commande lorsqu'elle attend la commande suivante.
-U
Par défaut, il est supposé qu'aucun nom d'utilisateur de connexion n'est requis pour accéder au port telnet de Cisco. Si une connexion par nom d'utilisateur a été activée sur les Cisco, les noms d'utilisateurs correspondants doivent être spécifiés à pmdacisco. Si spécifié avec l'option -U, nom_utilisateur sera utilisé comme nom d'utilisateur de connexion par défaut pour tous les Cisco. Voir également la section IDENTIFICATION DE L'INTERFACE ci-dessous.
-M
Compte utilisateur sous lequel exécuter l'agent. Par défaut, il s'agit du compte non privilégié « pcp » dans les versions actuelles de PCP, mais dans les versions plus anciennes, le compte superutilisateur (« root ») était utilisé par défaut.
-x
Se connecter au Cisco via le port TCP numéro port plutôt que le port par défaut 23 pour une connexion telnet.

Pour chaque interface, une fois la connexion telnet établie, pmdacisco est disposé à attendre jusqu'à 5 secondes pour que le Cisco fournisse un nouvel instantané des informations demandées. Si cela ne se produit pas, la connexion telnet est rompue et aucune valeur n'est retournée. Cela empêche pmdacisco d'occuper les ports telnet du Cisco en attendant indéfiniment lorsque la réponse du routeur n'est pas celle attendue, par exemple si le format de la sortie de « show int » change, ou si la commande est erronée parce qu'une interface n'est plus configurée sur le routeur.

IDENTIFICATION DE L'INTERFACE

Étant donné que chaque routeur Cisco peut prendre en charge plusieurs interfaces réseau et/ou plusieurs protocoles de communication, il est nécessaire d'indiquer à pmdacisco quelles interfaces doivent être surveillées.

Les arguments hote:spec_interface sur la ligne de commande définissent une interface particulière sur un routeur Cisco particulier. hote doit être un nom d'hôte ou une adresse IP en « notation décimale » qui identifie le port telnet d'un routeur Cisco particulier. Il existe plusieurs composants à l'interface-spec comme suit.

protocole
Une des abréviations a, B, E, e, f, G, h, s ou Vl respectivement pour ATM, BRI (ISDN), FastEthernet, Ethernet, FDDI, GigabitEthernet, HSSI, série ou Vlan.
interface
Selon le modèle du Cisco, il s'agira soit d'un entier, par exemple s0, soit d'un entier suivi d'une barre oblique (« / ») suivie d'un identifiant de sous-interface sous différentes formes syntaxiques, par exemple e1/0, G0/0/1 ou s4/2.1.

Pour découvrir les interfaces valides sur un Cisco particulier, connectez-vous au port telnet (en utilisant telnet(1)) et entrez la commande « show int » et recherchez les identifiants d'interface suivant les mots-clés « Ethernet », « Fddi », « Serial », etc.

Alternativement, exécutez la commande probe.

nom_utilisateur
S'il y a une connexion par nom d'utilisateur, et qu'elle est différente de la valeur par défaut (voir ci-dessus -U), elle peut être spécifiée facultativement ici en ajoutant « @ » et le nom d'utilisateur à la fin de spec_interface.
mot_de_passe
S'il y a un mot de passe au niveau utilisateur, et qu'il est différent de la valeur par défaut (voir ci-dessus -P), il peut être spécifié facultativement ici en ajoutant un point d'interrogation (« ? ») et le mot de passe à la fin de spec_interface.
invite
Si l'invite de commande Cisco est différente de la valeur par défaut (voir ci-dessus -s), elle peut être spécifiée facultativement ici en ajoutant un point d'exclamation (« ! ») et l'invite à la fin de spec_interface.

Voici des exemples d'arguments spec_interface valides : 

mon-routeur:e1/2
123.456.789.0:s0
wan-cisco:f2/3?motdepasse_secret
cisco-wifi:G1/0!mon_invite
cisco34.foo.bar.com:e2?trop_cool
mon-cisco:s2/2.1@mon_login
ton-cisco:E0/0@ton_login?ton_motdepasse
mon-cisco:E0/0@mon_login?mon_motdepasse!mon_invite

UTILITAIRES D'AIDE

La commande probe peut être utilisée pour découvrir les noms de toutes les interfaces d'un routeur Cisco particulier identifié par hote. L'argument -P est le même que pour pmdacisco.

La commande parse prend exactement les mêmes arguments que pmdacisco, mais s'exécute en dehors du contrôle de tout pmcd(1) et peut donc être utilisée pour diagnostiquer les problèmes de traitement d'un routeur Cisco particulier et/ou de l'une de ses interfaces.

Une verbosité diagnostique supplémentaire peut être produite en utilisant l'option de ligne de commande -D appl0,appl1,appl2. appl0 enregistre les événements de connexion et de déconnexion, le processus de connexion, le flux de contrôle de haut niveau et les statistiques extraites. appl1 trace toutes les commandes envoyées au périphérique Cisco. appl2 enregistre la tokenisation et l'analyse de la sortie du périphérique Cisco. Les diagnostics sont générés sur la sortie standard lors de la récupération et de l'analyse de chaque échantillon.

INSTALLATION

Si vous souhaitez accéder aux noms, au texte d'aide et aux valeurs des métriques de performance Cisco, effectuez les opérations suivantes en tant que root :

# cd $PCP_PMDAS_DIR/cisco
# ./Install

Si vous souhaitez annuler l'installation, effectuez les opérations suivantes en tant que root :

# cd $PCP_PMDAS_DIR/cisco
# ./Remove

pmdacisco est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove informent pmcd(1) lorsque l'agent est installé ou supprimé.

ENVIRONNEMENT PCP

Les variables d'environnement dont le préfixe est PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DEBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider au dépannage, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdacisco sont les suivantes :

Option Description
appl0 initialisation, détails du processus travailleur, actualisation des données, délais d'attente
appl1 requêtes envoyées à l'appareil Cisco
appl2 analyseur lexical et syntaxique pour la sortie de l'appareil Cisco
