NOM

pmaUndeltaInDom - trouver le domaine d'instance « complet » correspondant à un domaine d'instance « delta »

C SYNTAXE

#include <pcp/pmapi.h>
#include <pcp/libpcp.h>
#include <pcp/archive.h>

__pmLogInDom *pmaUndeltaInDom(__pmLogCtl *lcp,
__int32_t *buf);

cc ... -lpcp_archive -lpcp

AVERTISSEMENT

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API PCP garanties de rester stables entre les versions, et elles peuvent ne pas fonctionner, ou présenter des sémantiques différentes à un moment donné dans le futur.

DESCRIPTION

Trouve le domaine d'instance « complet » chargé qui correspond à un domaine d'instance « delta ».

L'appelant s'assure que l'enregistrement des métadonnées physiques du domaine d'instance « delta » a été lu dans buf. La structure de contrôle d'archive associée est identifiée par lcp, ce qui implique que l'archive d'entrée a également été ouverte avec pmNewContext(3).

pmaUndeltaInDom commence par extraire l'horodatage et le numéro du domaine d'instance pour le domaine d'instance « delta » à partir de buf. Avec ces informations, __pmLogSearchInDom(3) est appelé pour trouver le domaine d'instance chargé correspondant, qui aura été converti d'un domaine d'instance « delta » en un domaine d'instance « complet » dans le processus.

pmaUndeltaInDom est particulièrement utile pour les applications qui lisent des enregistrements de métadonnées physiques et qui doivent fonctionner sur des domaines d'instance « complets », plutôt que sur les domaines d'instance « delta » qui apparaissent dans les archives de Version 3.

DIAGNOSTICS ET VALEURS DE RETOUR

Beaucoup de bavardages d'avertissement si le domaine d'instance chargé correspondant ne peut pas être trouvé, et la valeur de retour est NULL dans ce cas.
