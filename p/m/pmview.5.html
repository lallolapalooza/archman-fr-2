PMVIEW(5) Manuel des formats de fichiers PMVIEW(5)

NOM

pmview - format de fichier de configuration pour les vues de performance

DESCRIPTION

Cette page de manuel décrit la version 2.1 du format de fichier de configuration de pmview (1).

Le format de configuration supporte les métriques de plusieurs hôtes ou archives. Un fichier de configuration peut spécifier des métriques sans source, avec des hôtes différents et des archives différentes. Cependant, un fichier de configuration contenant des archives ne peut avoir qu'une seule archive pour un hôte donné. En mode "replay", toute métrique avec une source spécifique à un hôte nécessite qu'une archive soit spécifiée pour cet hôte sur la ligne de commande ou comme source d'une métrique précédente. L'archive doit être la même archive (basée sur une comparaison de chaînes des noms d'archives) que toute archive spécifiée dans le fichier de configuration pour le même hôte.

Les contrôles de temps listeront tous les hôtes spécifiés sur la ligne de commande et dans le fichier de configuration dans la liste des fuseaux horaires (voir pmtime(1)).

Le format de fichier de configuration est basé sur une grille bidimensionnelle qui peut contenir une variété de barres, piles, liens, tuyaux, étiquettes et autres grilles. Les grilles redimensionnent chaque colonne et ligne pour correspondre à la taille de l'élément le plus grand de cette colonne ou ligne. Un fichier de configuration contenant un seul objet ne nécessite pas de grille. Le fichier de configuration pmview commence par un en-tête d'identification sur la première ligne qui n'est pas un commentaire :


pmview Version 2.1 [ligne_de_commande]

La ligne_de_commande optionnelle doit être la ligne de commande avec laquelle l'outil a été lancé, si le fichier de configuration a été généré par un autre outil. Ceci est utile pour les applications qui doivent être redémarrées automatiquement lors de la prochaine connexion, après que l'utilisateur se soit déconnecté alors que pmview était encore en cours d'exécution. Il faut veiller à ce que la commande spécifiée soit un chemin d'accès complet ou qu'elle soit trouvée dans le PATH disponible à la connexion.

Toutes les lignes commençant par "#" sont traitées comme des commentaires et ignorées. Sinon, tous les espaces, tabulations et sauts de ligne sont traités comme des espaces blancs, de sorte que plusieurs commandes peuvent être sur la même ligne.

La syntaxe pour spécifier les valeurs dans le fichier de configuration est cohérente pour toutes les commandes, à savoir :

couleur
Une couleur doit être soit l'un des ~20 noms de couleur Qt (voir la classe QColor sur https://doc.qt.io/qt-5/qcolor.html#predefined-colors), soit une valeur hexadécimale de couleur HTML (entre guillemets, par exemple ""#ff6347""), soit trois valeurs réelles normalisées représentant la saturation du rouge, du vert et du bleu. Par exemple, les couleurs suivantes sont identiques :


red
"#ff0000"
1.0 0.0 0.0
entier
Un nombre entier.
métrique
Une métrique consiste en une source optionnelle (hôte ou archive), le nom de la métrique, une liste d'instances optionnelle immédiatement après le nom, suivie de la valeur maximale (ou de normalisation). Un double point (" : ") est utilisé pour séparer un nom d'hôte de la métrique, et une barre oblique (" / ") pour séparer un nom d'archive de la métrique. Les instances sont entre crochets et séparées par des virgules. Chaque instance peut être entre guillemets.
Par exemple, voici quelques métriques valides : 


kernel.all.cpu.idle 4000
myhost:kernel.all.cpu.idle[cpu0,"cpu3"] 1000.0
/path/to/myarchive/kernel.all.cpu.idle[cpu1] 1000

Pour faciliter la correspondance des noms d'instances, deux comparaisons supplémentaires sont effectuées au-delà d'une simple comparaison de chaînes. Si le nom de l'instance contient des espaces, seul le premier mot du nom de l'instance doit correspondre à l'instance, en supposant que le premier mot est unique. Si le premier mot n'est pas unique, seule la première instance correspondante sera sélectionnée. La deuxième comparaison a lieu si le premier mot est un nombre avec des zéros initiaux. Tous les zéros initiaux seront ignorés avant de comparer à nouveau le premier mot. Cela permet de faire correspondre facilement les identifiants de processus utilisés dans les métriques proc, sans spécifier le nom d'instance complet. Par exemple, pour visualiser le temps utilisateur et système de init, utilisez la spécification de métrique


proc.psusage.utime[1]	1000
proc.psusage.stime[1]	1000

nom
Un nom pour un objet qui pourra être référencé ultérieurement dans le fichier de configuration. Les noms doivent être un seul mot composé de caractères alphanumériques, ainsi que de tirets bas, tirets et deux-points. Il est recommandé de ne pas commencer les noms par un tiret bas car cela pourrait être interprété comme un mot-clé.
pos
Ceci est la position de l'objet dans la grille. La syntaxe d'une position est :

[ [x z] [ [largeur profondeur] [alignement] ] ]
x
La coordonnée horizontale (de gauche à droite) de l'objet, commençant à 0. La valeur x par défaut est 0.
z
La coordonnée verticale (de haut en bas) de l'objet, commençant à 0. La valeur z par défaut est 0.
largeur
Le nombre de colonnes occupées par l'objet. La valeur largeur par défaut est 1.
profondeur
Le nombre de lignes occupées par l'objet. La valeur profondeur par défaut est 1.
alignement
Le bord ou le coin auquel l'objet est aligné. Les alignements possibles incluent : north, south, east, west, northeast, northwest, southeast, southwest et center. Des abréviations comme se et SE sont également acceptées. L'alignement par défaut est center.
La taille d'un objet peut ne pas être connue car le nombre d'instances pour certaines métriques varie entre les hôtes et les configurations PMDA. Par conséquent, la position de l'objet peut être utilisée pour spécifier la taille probable de l'objet, afin que la position des objets environnants soit ajustée en conséquence.
Les positions suivantes sont valides :

0 5
L'objet est centré à la position de grille 0,5 et occupe 1 case de grille.

1 2 north
L'objet est aligné sur le bord nord de la position 1,2 et occupe 1 case de grille.

2 2 2 1 east
L'objet est aligné sur le bord est de la position 3,2 et occupe 2 cases de grille (2,2 et 3,2).
chaîne
Une chaîne est une série de caractères entre guillemets doubles. Une chaîne ne peut pas contenir de sauts de ligne ni de guillemets doubles échappés.

Il existe plusieurs paramètres qui peuvent affecter la taille, la forme et la couleur des objets lors de leur affichage. Ces paramètres sont délimités de manière à ne modifier que les objets définis plus loin dans le même périmètre. Par conséquent, les réglages de paramètres en haut d'un fichier de configuration affectent l'ensemble de la scène, sauf s'ils sont modifiés ultérieurement dans le fichier. La plupart de ces paramètres sont également des ressources.

_barLength entier
La longueur du côté des blocs _bar et _stack. La valeur par défaut est 28.
_barHeight entier
La hauteur maximale d'un bloc _bar et _stack. La valeur par défaut est 80.
_baseColor couleur
La couleur des plans de base _bar, _grid et _stack. La valeur par défaut est ""#262626"" (c'est-à-dire gris15).
_baseHeight entier
La hauteur des plans de base _bar, _grid et _stack. La valeur par défaut est 2.
_gapWidth entier
L'espace entre les blocs dans un objet _bar sur l'axe X. La valeur par défaut est 8.
_gapDepth entier
L'espace entre les blocs dans un objet _bar sur l'axe Z. La valeur par défaut est 8.
_gapLabel entier
L'espace entre la base d'un objet _bar et les étiquettes de métrique ou d'instance. La valeur par défaut est 6.
_gridWidth entier
La largeur minimale d'une colonne _grid. La valeur par défaut est 20.
_gridDepth entier
La profondeur minimale d'une ligne
f a _grid ligne. La valeur par défaut est 20.
_labelMargin int
La marge autour d'un objet _label. La valeur par défaut est 5.
_labelColor color
La couleur des étiquettes _label et _bar. La valeur par défaut est le blanc.
_marginWidth int
La largeur supplémentaire d'un plan de base _bar, _grid et _stack au-delà des objets sur le plan. La valeur par défaut est 8.
_marginDepth int
La profondeur supplémentaire d'un plan de base _bar, _grid et _stack au-delà des objets sur le plan. La valeur par défaut est 8.
_pipeLength int
La longueur totale d'un _pipe. La valeur par défaut est la valeur de _barHeight.
_scale real
L'échelle appliquée à l'ensemble de la scène. Ce paramètre peut ne pas être utilisé dans les objets, mais uniquement en haut du fichier de configuration. La valeur par défaut est 1.0.

Pour simplifier la spécification des couleurs, une _colorList et une _colorScale peuvent être utilisées pour définir les couleurs d'un objet qui possède des métriques associées, c'est-à-dire _bar, _stack ou _pipe. Une liste de couleurs peut être définie dans un objet, ou nommée et définie en haut d'un fichier de configuration. Une liste de couleurs nommée peut ensuite être référencée dans plusieurs objets :

_colorList name ( color [color...] )
Associe les couleurs à la liste de couleurs name. L'assignation des couleurs aux blocs dépend du type d'un objet. Par exemple, la liste de couleurs appelée foo a la même couleur trois fois :
_colorList foo ( red "#ff0000" 1.0 0.0 0.0 )
_colorScale name color ( color real [color real...] )
Associe les couleurs et les reals à la liste de couleurs name. La couleur initiale est la couleur par défaut de l'objet. L'objet changera de couleur pour les autres couleurs lorsque la valeur normalisée de l'objet sera égale ou supérieure à chaque real. Par conséquent, chaque real doit être supérieur au real précédent, et doit être dans la plage de 0.0 à 1.0. Cette échelle change graduellement du bleu au rouge :
_colorScale coldToHot blue ( "#7f00ff" 0.3
                             purple 0.6
                             "#ff007f" 0.8
                             red 0.95)

Il existe plusieurs types d'objets différents que l'on peut trouver dans une scène pmview : _bar, _stack, _pipe, _grid, _link et _label. Il y a aussi _xing qui est un type spécial de _link. Les objets _bar, _stack et _pipe sont modulés par des valeurs métriques, un _label est un texte fixe, _link et _xing sont des interconnexions et un _grid est un conteneur d'objets, y compris d'autres objets _grid, qui contrôle la disposition de la scène. Un objet _grid n'est requis que s'il y a deux objets ou plus dans la scène.

Les objets _bar, _grid et _stack peuvent avoir des plans de base qui fournissent un point de référence pour les blocs lorsqu'ils changent de hauteur. Une étiquette peut être appliquée au plan de base de l'objet _grid s'il est _shown avec :


_baseLabel name|string

_baseLabel doit être utilisé dans le champ d'application de l'objet _bar, _grid ou _stack pertinent. Les premiers caractères ``\n'' dans la chaîne seront remplacés par une nouvelle ligne. Les caractères ``\n'' suivants seront ignorés.

Pour qu'une scène soit valide, elle doit contenir au moins un objet modulé.

Les objets sont définis comme suit :

_bar [options] ( [metric-list] [color-list] [label-list] )
Un objet _bar représente une collection de blocs. Le nombre de blocs dépend du nombre de métriques et d'instances de métriques assignées à l'objet. Par défaut, les blocs sont modulés en changeant la hauteur de chaque bloc. Alternativement, les blocs peuvent être modulés en changeant de couleur, ou les deux, hauteur et couleur. Chaque couleur de la color-list est assignée à chaque métrique. Par conséquent, plusieurs instances d'une même métrique auront la même couleur. Les options qui peuvent être passées à un objet _bar sont :
pos
La position de l'objet _bar dans l'objet _grid actuel.
_col|_row
Positionne les blocs de manière à ce que chaque instance soit dans une colonne (_col) ou une ligne (_row). Cela implique que chaque métrique différente se trouve dans une ligne ou une colonne séparée, respectivement. La valeur par défaut est _col.
_show|_hide
Le plan de base est-il visible ? La valeur par défaut est _show.
_ymod|_colormod|_colorymod
Modulation des blocs en ajustant leur hauteur (_ymod), leur couleur (_colormod) ou les deux, hauteur et couleur (_colorymod).
_cube|_cylinder
Définit la forme des blocs. La valeur par défaut est _cube.
_groupbymetric|_groupbyinst|_groupbyrow||groupbycol
Définit le regroupement des blocs lors du lancement d'autres outils. Pour des outils comme pmchart(1), certaines vues peuvent générer de nombreux petits graphiques qui ne peuvent pas être entièrement dessinés à l'écran. Un autre problème est qu'il peut être plus approprié de générer des graphiques avec la même instance dans chaque graphique, plutôt que la même métrique. Les spécificateurs de groupe contrôlent l'algorithme utilisé de manière à ce qu'un graphique séparé soit dessiné pour chaque spécification _metrics (_groupbymetric), pour la première, la deuxième, etc. instance de chaque _metric (_groupbyinst), ou par les lignes et les colonnes de l'objet _bar en fonction de _row ou _col. La valeur par défaut est _groupbymetric.

Les options doivent être spécifiées dans cet ordre, bien que les options précédentes ne soient pas obligatoires. Par conséquent, ceci est légal :


_bar _hide _cylinder ( ... )

Les métriques, les couleurs et les étiquettes sont spécifiées entre les crochets dans n'importe quel ordre. Seule la metric-list est obligatoire.

metric-list
Une liste de métriques _bar contient une liste de noms de métriques, de valeurs de normalisation et une étiquette optionnelle pour la métrique :
_metrics ( metric real [string] [metric real [string]...] )
color-list
Une liste de couleurs _bar peut être une liste de couleurs nommée qui a été définie précédemment, ou une liste de couleurs non nommée. Une liste _colorScale doit être utilisée lors de l'utilisation de la modulation _colormod ou _colorymod. Par conséquent, la syntaxe des listes de couleurs dans un objet _bar est l'une des suivantes :
_colorList name
_colorList ( color [color...] )
_colorScale name
_colorScale color ( color real [color real...] )
label-list
En plus des étiquettes pour chaque métrique dans la metric-list, les étiquettes de métrique et d'instance peuvent être définies à l'aide des instructions _metriclabels et _instlabels. La position des étiquettes autour de l'objet _bar dépend de l'orientation _row ou _col des métriques et des instances, et si l'étiquette est lue _towards l'objet _bar, ou _away. La valeur par défaut est _towards.
_metriclabels [_away|_towards] ( name|string [name|string...] )
_instlabels [_away|_towards] ( name|string
[name|string...] )
_grid [pos] [_show|_hide] ( objects )
Un objet _grid est un conteneur pour des objets, y compris d'autres objets _grid. Les lignes et les colonnes d'un objet _grid sont redimensionnées à la taille du plus grand objet de la ligne ou de la colonne. Si un objet s'étend sur plusieurs lignes et/ou colonnes, ces lignes et colonnes peuvent être partiellement redimensionnées pour contenir l'objet. Cependant, le redimensionnement des lignes et des colonnes pour les objets occupant plusieurs lignes et colonnes se produit après le redimensionnement pour les objets n'occupant qu'une seule case de grille.

Une collision entre des objets occupant les mêmes cases sera signalée comme un message d'erreur et l'objet ultérieur sera ignoré.

Les options d'un objet _grid contrôlent la position (pos) de l'objet _grid dans le _grid parent, et indiquent s'il faut _show ou _hide le plan de base du _grid. Par défaut, le plan de base est masqué.

Les paramètres décrits ci-dessus peuvent être spécifiés entre les crochets d'un objet _grid, mais ils ne s'appliquent qu'aux objets contenus dans le _grid, pas au _grid lui-même. Pour qu'un paramètre s'applique à un objet _grid, il doit être spécifié avant la déclaration de l'objet _grid.

_label [options] string
Un objet _label dessine le contenu de string à la position, orientation et taille spécifiées dans les options :
pos
La position de l'objet _label dans l'objet _grid actuel.
_left|_right|_up|_down
L'orientation de la string. La direction indique la direction dans laquelle l'étiquette est lue. Par conséquent, _right est la valeur par défaut car la chaîne est lue de gauche à droite.
_small|_medium|_large
La taille de la police. La valeur par défaut est _medium.
_link pos [string]
Un objet _link dessine un "tuyau" rond, droit ou en forme de L, horizontal, dont le diamètre est égal à 80% de la _baseHeight d'un _grid englobant. Les propriétés de l'objet sont définies par les options :
pos
définit la position du _link sur la grille et sa forme. Le _link commence dans la colonne et la ligne sur le _grid spécifiées par les deux premiers nombres de la pos et s'étend sur le nombre de colonnes et

DESCRIPTION

Les valeurs de col et row définissent la position de l'objet dans la grille englobante. La valeur columns définit le nombre de colonnes occupé par l'objet et rows le nombre de lignes. Ces valeurs sont utilisées pour la mise en page de l'objet.

La valeur alignment est utilisée pour décider de l'orientation du lien (les liens sont toujours alignés au centre) : les liens east et west sont droits et vont de gauche à droite, les liens north et south sont droits et vont de l'extrémité éloignée de la grille à l'extrémité proche, les liens northeast, northwest, southeast et southwest sont en forme de L et relient les points correspondants de la boussole, c'est-à-dire qu'un lien northeast prend la forme générale de la lettre latine « L ».

string
définit le « tag » du _link qui sera affiché dans la fenêtre de texte lorsque le pointeur se trouve sur le lien.
_pipe pos ( [metric-list] [color-list] [tag] )
Un objet _pipe représente un ensemble de cylindres, placés les uns sur les autres et orientés parallèlement au plan de base. Le diamètre d'un _pipe est égal à 80% de _baseHeight. Le nombre de blocs dépend du nombre d'instances métriques dans la metric-list. Les couleurs de la color-list sont attribuées tour à tour à chaque cylindre du _pipe. La longueur du _pipe est définie par _pipeLength.
pos
définit la position du _pipe sur le _grid englobant et son orientation, le champ alignment étant utilisé pour définir à quelle extrémité du tuyau empiler les cylindres colorés. Les cylindres sont empilés au point de la boussole correspondant et la direction du tuyau va du point de la boussole vers le centre de la boussole. Seules les valeurs east, west, north et south sont valides pour l'alignement du tuyau.
Les métriques, couleurs et libellés peuvent être spécifiés entre crochets dans n'importe quel ordre. Seule la metric-list est obligatoire.
metric-list
Une liste métrique de _pipe contient une liste de noms de métriques et de valeurs de normalisation : 
_metrics ( metric real [metric real...] )
color-list
Une liste de couleurs de _pipe peut être une liste de couleurs nommée définie précédemment, ou une liste de couleurs non nommée : 
_colorList name
_colorList ( color [color...] )
tag
Un _pipe peut avoir un « tag » pour le bloc de remplissage (bloc non animé à l'autre extrémité du tuyau) qui sera affiché dans la fenêtre de texte lorsque le pointeur se trouvera sur cette extrémité du tuyau. 
_pipeTag name|string
_stack [options] ( [metric-list] [color-list] [label] )
Un objet _stack représente un ensemble de blocs placés verticalement les uns sur les autres. Le nombre de blocs dépend du nombre d'instances métriques dans la metric-list. Les couleurs de la color-list sont attribuées à chaque bloc du _stack. Par défaut, la hauteur du _stack sera la somme des hauteurs de chaque bloc. Les options qui peuvent être passées à un objet _stack sont :
pos
La position de l'objet _stack dans l'objet _grid actuel.
_show|_hide
Le plan de base est-il visible ? Par défaut, c'est _show.
_utilmod|_fillmod
Forcer la hauteur de la pile à être toujours la hauteur maximale. Ceci est réalisé en normalisant la hauteur de chaque bloc (_utilmod), ou en ajoutant un bloc gris au sommet de la pile (_fillmod).
_cube|_cylinder
Définir la forme des blocs. Par défaut, c'est _cube.

Les options doivent être spécifiées dans cet ordre, bien que les options précédentes ne soient pas obligatoires. Par conséquent, ceci est légal :


_stack 1 1 _north _utilmod ( ... )

Les métriques, couleurs et libellés peuvent être spécifiés entre crochets dans n'importe quel ordre. Seule la metric-list est obligatoire.

metric-list
Une liste métrique de _stack contient une liste de noms de métriques et de valeurs de normalisation : 
_metrics ( metric real [metric real...] )
color-list
Une liste de couleurs de _stack peut être une liste de couleurs nommée définie précédemment, ou une liste de couleurs non nommée : 
_colorList name
_colorList ( color [color...] )
label
Un _stack de type _fillmod peut avoir un libellé pour le bloc de remplissage : 
_stackLabel name|string
_xing col row columns rows dir1 ... dir4
Un _xing est un type spécial de lien utilisé pour dessiner une paire de liens qui se croisent. Pour donner l'impression visuelle que les liens ne se rejoignent pas, l'un des liens est dessiné comme un cylindre « cassé ». col et row définissent la position sur la grille englobante. columns et rows définissent la taille de la boîte englobante. Les points d'extrémité des cylindres croisés sont placés exactement au centre des cellules d'angle de la boîte englobante et quatre petits cylindres ou moignons sont utilisés pour relier le périmètre de la boîte englobante aux points d'extrémité des cylindres croisés. Quatre valeurs dir définissent l'orientation des moignons, en commençant par le coin supérieur gauche du _xing et en procédant dans le sens des aiguilles d'une montre, de sorte que les moignons respectifs soient utilisés pour relier le point de la boussole au centre de la cellule (voir l'exemple).

EXEMPLE

Cet exemple simple illustre l'utilisation des paramètres et des différents types d'objets :


pmview Version 2.1
# Utiliser un gris plus clair pour les plans de base
_baseColor "#7f7f7f"
# Définir les couleurs pour l'objet CPU
_colorList cpu ( blue2 red2 yellow2 cyan2 green2 )
# L'objet grille supérieur, mais le cacher de la vue
_grid _hide (
# Afficher la charge actuelle dans un objet barre
   _bar 0 0 (
       _baseLabel "Moyennes de charge sur\n1, 5 et 15 minutes"
       _metrics (
		kernel.all.load[1] 1 "1"
		kernel.all.load[5] 1 "5"
		kernel.all.load[15] 1 "15"
	)
	_colorList ( blue blue blue )
    )
# Ajouter un libellé sous les barres de charge
    _label 0 1 "Charge"
# Changer la couleur du plan de base pour les objets ultérieurs
    _baseColor "#fba2f5" # rose
# Afficher l'utilisation du CPU sur tous les CPU dans une pile d'utilisation
    _stack 2 0 _south _utilmod (
	_baseLabel "Utilisation du CPU sur tous les CPU"
	_metrics (
		kernel.all.cpu.user 1000
		kernel.all.cpu.sys 1000
		kernel.all.cpu.intr 1000
		kernel.all.cpu.wait.total 1000
		kernel.all.cpu.idle 1000
	)
	_colorList cpu
    )
# Ajouter un libellé sous la pile CPU
    _label 2 1 "CPU"
# Créer une grille séparée pour les liens et les tuyaux
    _marginWidth 1
    _marginDepth 1
    _gridSpace  12
    _grid 0 3 5 4 _hide (
	_pipeLength 12
	_baseHeight 12
	# Ajouter un tuyau et un lien avec orientation ouest
	_pipe 0 0 west (
	    _pipeTag "Tuyau Ouest"
	    _metrics (
		kernel.all.cpu.user 1000
		kernel.all.cpu.sys 1000
		kernel.all.cpu.idle 1000
	    )
	    _colorList cpu
	)
	_link 0 2 west "Lien Ouest"
	# Ajouter un croisement
	_xing 1 0 3 3 west east east west
	# Ajouter un lien et un tuyau avec orientation est
	_pipe 4 0 east (
	    _pipeTag "Tuyau Est"
	    _metrics (
		kernel.all.cpu.user 1000
		kernel.all.cpu.sys 1000
		kernel.all.cpu.idle 1000
	    )
	    _colorList cpu
	)
	_link 4 2 east "Lien Est"
    )
)
