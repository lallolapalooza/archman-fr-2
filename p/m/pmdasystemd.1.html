NOM

pmdasystemd - agent de domaine de métriques de performance systemd (PMDA)

SYNTAXE

$PCP_PMDAS_DIR/systemd/pmdasystemd [-f] [-D debug] [-d domaine] [-l logfile] [-m mémoire] [-s intervalle] [-U nomutilisateur]

DESCRIPTION

pmdasystemd est un agent de domaine de métriques de performance (PMDA) pour la surveillance des fichiers journaux de systemd. Il peut être considéré comme analogue à l'option -f de journalctl(1) et convertit chaque nouvelle ligne de journal en un événement de performance, adapté à la consommation par les outils clients de PMAPI(3) comme pmevent(1).

Le PMDA systemd exporte à la fois des métriques de style événement, reflétant des enregistrements d'événements horodatés pour les messages consignés dans les journaux système, ainsi que des métriques de style échantillon plus orthodoxes, telles que les comptages de messages et les valeurs de taille de débit.

Une brève description des options de ligne de commande de pmdasystemd suit :

-d
Il est absolument crucial que le numéro de domaine des métriques de performance spécifié ici soit unique et cohérent. C'est-à-dire que domaine doit être différent pour chaque PMDA sur le même hôte, et le même numéro de domaine doit être utilisé pour le même PMDA sur tous les hôtes.
-f
Désactive le filtrage des enregistrements par uid/gid. Par défaut, les identifiants utilisateur et groupe seront utilisés pour filtrer les enregistrements de journal renvoyés à l'outil client, empêchant ainsi l'exposition d'informations à des utilisateurs arbitraires. Cette option désactive cela, alors utilisez-la avec une extrême prudence.
-l
Emplacement du fichier journal. Par défaut, un fichier journal nommé systemd.log est écrit dans le répertoire courant de pmcd(1) lorsque pmdasystemd est démarré, c'est-à-dire $PCP_LOG_DIR/pmcd. Si le fichier journal ne peut pas être créé ou n'est pas accessible en écriture, la sortie est écrite sur la sortie d'erreur standard à la place.
-m
Limite la mémoire physique utilisée par le PMDA pour mettre en mémoire tampon les enregistrements d'événements à maxsize octets. Au fur et à mesure que les événements de journal arrivent au PMDA, ils doivent être mis en mémoire tampon jusqu'à ce que les outils clients individuels demandent le lot suivant depuis leur lot précédent d'événements. La limite maximale par défaut est de 2 mégaoctets.
-s
Définit l'intervalle d'interrogation pour la détection des nouvelles lignes de journal arrivantes. Reproduit la même option de la commande tail(1).
-U
Compte utilisateur sous lequel exécuter l'agent. Par défaut, c'est le compte utilisateur "adm".

INSTALLATION

Si vous souhaitez accéder aux noms, aux textes d'aide et aux valeurs des métriques de performance systemd, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/systemd
# ./Install

Si vous souhaitez annuler l'installation, procédez comme suit en tant que root :

# cd $PCP_PMDAS_DIR/systemd
# ./Remove

pmdasystemd est lancé par pmcd(1) et ne doit jamais être exécuté directement. Les scripts Install et Remove informent pmcd(1) lorsque l'agent est installé ou supprimé.

FICHIERS

$PCP_PMCDCONF_PATH
options de ligne de commande utilisées pour lancer pmdasystemd
$PCP_PMDAS_DIR/systemd/help
fichier texte d'aide par défaut pour les métriques systemd
$PCP_PMDAS_DIR/systemd/Install
script d'installation pour l'agent pmdasystemd
$PCP_PMDAS_DIR/systemd/Remove
script d'annulation d'installation pour l'agent pmdasystemd
$PCP_LOG_DIR/pmcd/systemd.log
fichier journal par défaut pour les messages d'erreur et autres informations de pmdasystemd

ENVIRONNEMENT PCP

Les variables d'environnement avec le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Lors de chaque installation, le fichier /etc/pcp.conf contient les valeurs locales pour ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à diagnostiquer les problèmes, bien que les informations soient parfois cryptiques et principalement destinées à guider les développeurs plutôt que les utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

Les options de débogage spécifiques à pmdasystemd sont les suivantes :

Option Description
appl0 filtrage des enregistrements de journal, contrôle d'accès, interactions avec pmcd(1)
appl2 trace des appels select(2)

VOIR AUSSI

PCPIntro(1), pmcd(1), pmevent(1), journalctl(1), tail(1), PMAPI(3), pcp.conf(5) et pcp.env(5).
