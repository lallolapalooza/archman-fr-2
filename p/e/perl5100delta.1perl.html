PERL5100DELTA(1perl) Guide du programmeur Perl PERL5100DELTA(1perl)

NOM

perl5100delta - ce qui est nouveau pour la version 5.10.0 de Perl

DESCRIPTION

Ce document décrit les différences entre la version 5.8.8 et la version 5.10.0.

Beaucoup des corrections de bugs dans la version 5.10.0 étaient déjà présentes dans les versions de maintenance 5.8.X ; elles ne sont pas reproduites ici et sont documentées dans l'ensemble des pages de manuel nommées perl58[1-8]?.delta.

Améliorations du cœur de Perl

Le pragma "feature"

Le pragma "feature" est utilisé pour activer de nouvelles syntaxes qui casseraient la compatibilité ascendante de Perl avec les anciennes versions du langage. C'est un pragma lexical, comme "strict" ou "warnings".

Actuellement, les nouvelles fonctionnalités suivantes sont disponibles : "switch" (ajoute une instruction switch), "say" (ajoute une fonction intégrée "say"), et "state" (ajoute un mot-clé "state" pour déclarer des variables "statiques"). Ces fonctionnalités sont décrites dans leurs sections respectives de ce document.

Le pragma "feature" est également chargé implicitement lorsque vous exigez une version minimale de Perl (avec la construction "use VERSION") supérieure ou égale à 5.9.5. Voir feature pour plus de détails.

Nouveau commutateur de ligne de commande -E

-E est équivalent à -e, mais il active implicitement toutes les fonctionnalités optionnelles (comme "use feature ":5.10"").

Opérateur défini-ou logique

Un nouvel opérateur "//" (défini-ou logique) a été implémenté. L'expression suivante :

$a // $b

est simplement équivalente à

defined $a ? $a : $b

et l'instruction

$c //= $d;

peut maintenant être utilisée à la place de

$c = $d unless defined $c;

L'opérateur "//" a la même priorité et la même associativité que "||". Des soins particuliers ont été apportés pour garantir que cet opérateur fasse ce que vous voulez tout en ne cassant pas le code existant, mais certains cas limites impliquant l'expression régulière vide peuvent maintenant être analysés différemment. Voir perlop pour plus de détails.

Opérateurs Switch et Smart Match

Perl 5 dispose maintenant d'une instruction switch. Elle est disponible lorsque use feature 'switch' est activé. Cette fonctionnalité introduit trois nouveaux mots-clés : "given", "when", et "default" :

given ($foo) {
    when (/^abc/) { $abc = 1; }
    when (/^def/) { $def = 1; }
    when (/^xyz/) { $xyz = 1; }
    default { $nothing = 1; }
}

Une description plus complète de la manière dont Perl compare la variable du switch aux conditions "when" est donnée dans "Switch statements" dans perlsyn.

Ce type de correspondance est appelé smart match, et il est également possible de l'utiliser en dehors des instructions switch, via le nouvel opérateur "~~". Voir "Smart matching in detail" dans perlsyn.

Cette fonctionnalité a été contribuée par Robin Houston.

Expressions régulières

Motifs récursifs
Il est maintenant possible d'écrire des motifs récursifs sans utiliser la construction "(??{})". Cette nouvelle manière est plus efficace et, dans de nombreux cas, plus facile à lire.

Chaque parenthèse de capture peut maintenant être traitée comme un motif indépendant auquel on peut accéder en utilisant la syntaxe "(?PARNO)" ("PARNO" signifiant "numéro de parenthèse"). Par exemple, le motif suivant correspondra à des crochets d'angle imbriqués et équilibrés :

/
 ^                      # début de ligne
 (                      # début du buffer de capture 1
    <                   #   correspond à un crochet d'angle ouvrant
    (?:                 #   correspond à l'un des éléments suivants :
        (?>             #     ne pas revenir en arrière sur l'intérieur de ce groupe
            [^<>]+      #       un ou plusieurs caractères qui ne sont pas des crochets
        )               #     fin du groupe sans retour arrière
    |                   #     ... ou ...
        (?1)            #     récursion vers la parenthèse 1 et essai à nouveau
    )*                  #   0 ou plusieurs fois.
    >                   #   correspond à un crochet d'angle fermant
 )                      # fin du buffer de capture un
 $                      # fin de ligne
/x

Les utilisateurs de PCRE noteront que la fonctionnalité de regex récursives de Perl permet le retour arrière dans un motif récursé, tandis que dans PCRE, la récursion est atomique ou de nature "possessif". Comme dans l'exemple ci-dessus, vous pouvez ajouter (?>) pour contrôler cela sélectivement. (Yves Orton)

Buffers de capture nommés
Il est maintenant possible de nommer les parenthèses de capture dans un motif et de faire référence au contenu capturé par son nom. La syntaxe de nommage est "(?<NOM>....)". Il est possible de faire des références arrière à un buffer nommé avec la syntaxe "\k<NOM>". En code, les nouvelles hachages magiques "%+" et "%-" peuvent être utilisées pour accéder au contenu des buffers de capture.

Ainsi, pour remplacer tous les caractères doublés par une seule copie, on pourrait écrire :

s/(?<lettre>.)\k<lettre>/$+{lettre}/g

Seuls les buffers dont le contenu est défini seront "visibles" dans la hachage "%+", il est donc possible de faire quelque chose comme :

foreach my $nom (keys %+) {
    print "le contenu du buffer '$nom' est $+{$nom}\n";
}

La hachage "%-" est un peu plus complète, car elle contiendra des références de tableaux contenant les valeurs de tous les buffers de capture nommés de manière similaire, s'il devrait y en avoir plusieurs.

"%+" et "%-" sont implémentés en tant que hachages liés via le nouveau module "Tie::Hash::NamedCapture".

Les utilisateurs familiers avec le moteur regex de .NET remarqueront que l'implémentation de Perl diffère en ce que l'ordre numérique des buffers est séquentiel, et non "non nommés d'abord, puis nommés". Ainsi dans le motif

/(A)(?<B>B)(C)(?<D>D)/

$1 sera 'A', $2 sera 'B', $3 sera 'C' et $4 sera 'D' et non $1 est 'A', $2 est 'C' et $3 est 'B' et $4 est 'D' ce à quoi un programmeur .NET s'attendrait. Ceci est considéré comme une fonctionnalité. :-) (Yves Orton)

Quantificateurs possessifs
Perl supporte maintenant la syntaxe de quantificateur possessif du motif de correspondance atomique. Essentiellement, un quantificateur possessif correspond autant que possible et ne revient jamais en arrière. Il peut donc être utilisé pour contrôler le retour arrière. La syntaxe est similaire à la correspondance non gourmande, sauf qu'au lieu d'utiliser un '?' comme modificateur, on utilise un '+'. Ainsi "?+", "*+", "++", "{min,max}+" sont maintenant des quantificateurs légaux. (Yves Orton)
Verbes de contrôle de retour arrière
Le moteur regex prend maintenant en charge un certain nombre de verbes de contrôle de retour arrière spécialisés : (*THEN), (*PRUNE), (*MARK), (*SKIP), (*COMMIT), (*FAIL) et (*ACCEPT). Voir perlre pour plus d'informations.

VUES D'ENSEMBLE

Parmi les nombreuses améliorations apportées à Perl 5.10.0, on peut noter :

  • Nouvel opérateur définie-ou logique "//"
  • Nouvelle instruction "switch" qui permet des correspondances intelligentes (smart matching)
  • Nouveau pragma "feature" pour activer de nouvelles syntaxes de manière contrôlée
  • Améliorations de la syntaxe des expressions régulières, y compris des motifs récursifs, des buffers de capture nommés et des quantificateurs possessifs
  • Nouvelles fonctions intégrées "say", "state" et "__DIR__"
  • Opérateur "~~" pour le smart matching
  • Nouvelle option de ligne de commande "-E", qui est comme "-e" mais active toutes les fonctionnalités optionnelles

FONCTIONS INTÉGRÉES

say

La fonction "say" est similaire à "print", sauf qu'elle ajoute automatiquement un caractère de nouvelle ligne à la fin de son argument. Elle est activée via use feature 'say'.

Le caractère de nouvelle ligne utilisé est celui défini par $/. Si $/ est undef, alors "say" ne l'ajoute pas. Si $/ est une chaîne vide, alors "say" n'ajoute rien et utilise seulement le caractère de nouvelle ligne par défaut.

Si l'auto-vivification est activée, "say" insère des nouvelles lignes appropriées.

Dans ce qui suit :

print $fh, $_, $/;

est maintenant devenu une forme abrégée disponible dans le code

say $fh, $_;

Notez que la documentation sur le comportement exact de "say" avec les champs $/ n'est pas finalisée et pourrait changer dans de futures versions.

state

Le mot-clé "state" permet de déclarer des variables qui ont une durée de vie à l'échelle du programme, mais dont la portée est lexicale. C'est-à-dire qu'elles se comportent comme des variables locales, mais leur valeur est conservée entre les appels à la sous-routine qui les contient. C'est donc un moyen de créer des variables statiques.

sub counter {
    state $count = 0;
    $count++;
    return $count;
}
print counter(), "\n"; # imprime 1
print counter(), "\n"; # imprime 2

Pour plus de détails, voir "state" in perlsub.

__DIR__

La constante magique "__DIR__" est maintenant disponible. Elle renvoie le nom du répertoire contenant le fichier source courant, sous forme absolue. C'est l'équivalent de File::Spec->catfile(File::Basename::dirname(__FILE__)), mais plus court et plus rapide.

Cette fonctionnalité est activée via use feature 'dir'.

Descriptions

Références arrière relatives
Une nouvelle syntaxe "\g{N}" ou "\gN" où "N" est un entier décimal permet une forme plus sûre de notation de référence arrière ainsi que des références arrière relatives. Cela devrait faciliter la génération et l'incorporation de motifs contenant des références arrière. Voir "Capture buffers" dans perlre. (Yves Orton)
"\K" escape
La fonctionnalité du module de Jeff Pinyan Regexp::Keep a été ajoutée au noyau. Dans les expressions régulières, vous pouvez maintenant utiliser l'échappement spécial "\K" pour faire quelque chose comme une recherche arrière positive de longueur flottante. C'est également utile dans les substitutions comme: 
s/(foo)bar/$1/g
qui peut maintenant être converti en: 
s/foo\Kbar//g
ce qui est beaucoup plus efficace. (Yves Orton)
Espaces blancs verticaux et horizontaux, et sauts de ligne
Les expressions régulières reconnaissent maintenant les échappements "\v" et "\h" qui correspondent respectivement aux espaces blancs verticaux et horizontaux. "\V" et "\H" correspondent logiquement à leurs compléments.

"\R" correspond à un saut de ligne générique, c'est-à-dire un espace blanc vertical, plus la séquence multi-caractères "\x0D\x0A".

Captures optionnelles avant et après la correspondance avec le drapeau /p
Il existe un nouveau drapeau "/p" pour les expressions régulières. Son utilisation permet au moteur de conserver une copie de la partie de la chaîne correspondante avant la sous-chaîne correspondante dans la nouvelle variable spéciale "${^PREMATCH}", la partie après la sous-chaîne correspondante dans "${^POSTMATCH}", et la sous-chaîne correspondante elle-même dans "${^MATCH}".

Perl est toujours capable de stocker ces sous-chaînes dans les variables spéciales "$`", "$'", $&, mais l'utilisation de ces variables n'importe où dans le programme ajoute une pénalité à toutes les correspondances d'expressions régulières, alors que si vous utilisez le drapeau "/p" et les nouvelles variables spéciales à la place, vous ne payez que pour les expressions régulières où le drapeau est utilisé.

Pour plus de détails sur les nouvelles variables, voir perlvar ; pour l'utilisation du drapeau d'expression régulière, voir perlop et perlre.

say()

say() est une nouvelle fonction intégrée, uniquement disponible lorsque "use feature 'say'" est activé, qui est similaire à print(), mais qui ajoute implicitement un saut de ligne à la chaîne imprimée. Voir "say" dans perlfunc. (Robin Houston)

Lexical $_

La variable par défaut $_ peut maintenant être lexicalisée, en la déclarant comme n'importe quelle autre variable lexicale, avec un simple

my $_;

Les opérations qui utilisent $_ par défaut utiliseront la version lexicale de $_ lorsqu'elle existe, au lieu de la globale $_.

Dans un bloc "map" ou "grep", si $_ a été déclaré my auparavant, alors le $_ à l'intérieur du bloc est également lexical (et limité au bloc).

Dans une portée où $_ a été lexicalisé, vous pouvez toujours accéder à la version globale de $_ en utilisant $::_, ou, plus simplement, en remplaçant la déclaration lexicale par "our $_". (Rafael Garcia-Suarez)

Prototype "_"

Un nouveau caractère de prototype a été ajouté. "_" est équivalent à "$" mais utilise par défaut $_ si l'argument correspondant n'est pas fourni (à la fois "$" et "_" désignent un scalaire). En raison de la nature optionnelle de l'argument, vous ne pouvez l'utiliser qu'à la fin d'un prototype, ou avant un point-virgule.

Cela a une petite conséquence incompatible : la fonction prototype() a été ajustée pour renvoyer "_" pour certains éléments intégrés dans des cas appropriés (par exemple, prototype('CORE::rmdir')). (Rafael Garcia-Suarez)

Blocs UNITCHECK

"UNITCHECK", un nouveau bloc de code spécial a été introduit, en plus de "BEGIN", "CHECK", "INIT" et "END".

"CHECK" et "INIT", bien qu'utiles à certaines fins spécialisées, sont toujours exécutés lors de la transition entre la compilation et l'exécution du programme principal, et sont donc inutiles lorsque du code est chargé à l'exécution. D'autre part, les blocs "UNITCHECK" sont exécutés juste après que l'unité qui les a définis ait été compilée. Voir perlmod pour plus d'informations. (Alex Gough)

Nouveau Pragma, "mro"

Un nouveau pragma, "mro" (pour Method Resolution Order - Ordre de Résolution des Méthodes), a été ajouté. Il permet de changer, par classe, l'algorithme que perl utilise pour trouver les méthodes héritées en cas d'héritage multiple. L'MRO par défaut n'a pas changé (DFS, pour Depth First Search - Recherche en Profondeur). Un autre MRO est disponible : l'algorithme C3. Voir mro pour plus d'informations. (Brandon Black)

Notez qu'en raison des changements dans l'implémentation de la recherche de hiérarchie de classes, le code qui utilisait auparavant `undef` sur le glob *ISA va très probablement échouer. Quoi qu'il en soit, `undef` sur *ISA avait l'effet secondaire de supprimer la magie sur le tableau @ISA et n'aurait pas dû être fait en premier lieu. De plus, le cache *::ISA::CACHE:: n'existe plus ; pour forcer la réinitialisation du cache de @ISA, vous devez maintenant utiliser l'API "mro", ou plus simplement affecter à @ISA (par exemple avec "@ISA = @ISA").

readdir() peut renvoyer un "nom de fichier court" sous Windows

La fonction readdir() peut renvoyer un "nom de fichier court" lorsque le nom de fichier long contient des caractères en dehors de la codepage ANSI. De même, Cwd::cwd() peut renvoyer un nom de répertoire court, et glob() peut également renvoyer des noms courts. Sur le système de fichiers NTFS, ces noms courts peuvent toujours être représentés dans la codepage ANSI. Ce ne sera pas le cas pour tous les autres pilotes de système de fichiers ; par exemple, le système de fichiers FAT stocke les noms de fichiers courts dans la codepage OEM, de sorte que certains fichiers sur des volumes FAT restent inaccessibles via les API ANSI.

De même, $^X, @INC, et $ENV{PATH} sont prétraités au démarrage pour s'assurer que tous les chemins sont valides dans la codepage ANSI (si possible).

La fonction Win32::GetLongPathName() renvoie maintenant le nom de fichier long correct encodé en UTF-8 au lieu d'utiliser des caractères de remplacement pour forcer le nom dans la codepage ANSI. La nouvelle fonction Win32::GetANSIPathName() peut être utilisée pour transformer un nom de chemin long en un nom court uniquement si le nom long ne peut pas être représenté dans la codepage ANSI.

De nombreuses autres fonctions du module "Win32" ont été améliorées pour accepter des arguments encodés en UTF-8. Veuillez consulter Win32 pour plus de détails.

readpipe() est maintenant redéfinissable

La fonction intégrée readpipe() est maintenant redéfinissable. La redéfinir permet également de redéfinir son opérateur correspondant, "qx//" (aussi connu sous le nom de ``). De plus, elle utilise maintenant par défaut $_ si aucun argument n'est fourni. (Rafael Garcia-Suarez)

Argument par défaut pour readline()

readline() utilise maintenant par défaut *ARGV si aucun argument n'est fourni. (Rafael Garcia-Suarez)

Variables state()

Une nouvelle classe de variables a été introduite. Les variables d'état sont similaires aux variables "my", mais sont déclarées avec le mot-clé "state" au lieu de "my". Elles ne sont visibles que dans leur portée lexicale, mais leur valeur est persistante : contrairement aux variables "my", elles ne sont pas indéfinies lors de l'entrée dans la portée, mais conservent leur valeur précédente. (Rafael Garcia-Suarez, Nicholas Clark)

Pour utiliser les variables d'état, il faut les activer en utilisant

use feature 'state';

ou en utilisant le commutateur de ligne de commande "-E" dans les one-liners. Voir "Persistent Private Variables" dans perlsub.

Opérateurs filetest empilés

Comme une nouvelle forme de sucre syntaxique, il est maintenant possible d'empiler les opérateurs filetest. Vous pouvez maintenant écrire "-f -w -x $file" à la suite pour signifier "-x $file && -w _ && -f _". Voir "-X" dans perlfunc.

UNIVERSAL::DOES()

La classe "UNIVERSAL" a une nouvelle méthode, DOES(). Elle a été ajoutée pour résoudre les problèmes sémantiques avec la méthode isa(). isa() vérifie l'héritage, tandis que DOES() a été conçu pour être redéfini lorsque le module

authors utilisent d'autres types de relations entre les classes (en plus de l'héritage). (chromatique)

Voir "$obj->DOES( ROLE )" dans UNIVERSAL.

Formats

Les formats ont été améliorés de plusieurs manières. Un nouveau champ, "^*", peut être utilisé pour le texte de largeur variable, une ligne à la fois. Les caractères nuls sont maintenant gérés correctement dans les lignes de format. L'utilisation de "@#" et "~~" ensemble produira maintenant une erreur de compilation, car ces champs de format sont incompatibles. perlform a été amélioré, et divers bogues ont été corrigés.

Modificateurs d'ordre des octets pour pack() et unpack()

Il existe deux nouveaux modificateurs d'ordre des octets, ">" (big-endian) et "<" (little-endian), qui peuvent être ajoutés à la plupart des caractères et groupes de modèles pack() et unpack() pour forcer un certain ordre d'octets pour ce type ou groupe. Voir "pack" dans perlfunc et perlpacktut pour plus de détails.

"no VERSION"

Vous pouvez maintenant utiliser "no" suivi d'un numéro de version pour spécifier que vous souhaitez utiliser une version de perl antérieure à celle spécifiée.

"chdir", "chmod" et "chown" sur les filehandles

"chdir", "chmod" et "chown" peuvent maintenant fonctionner sur les filehandles ainsi que sur les noms de fichiers, si le système prend en charge respectivement "fchdir", "fchmod" et "fchown", grâce à un correctif fourni par Gisle Aas.

Groupes OS

$( et $) retournent maintenant les groupes dans l'ordre où l'OS les retourne, grâce à Gisle Aas. Ce n'était pas le cas auparavant.

Subs de tri récursives

Vous pouvez maintenant utiliser des sous-routines récursives avec sort(), grâce à Robin Houston.

Exceptions dans la réduction de constantes

La routine de réduction de constantes est maintenant enveloppée dans un gestionnaire d'exceptions, et si la réduction déclenche une exception (comme la tentative d'évaluer 0/0), perl conserve maintenant l'arbre d'opérations actuel, au lieu d'arrêter tout le programme. Sans ce changement, les programmes ne compileraient pas s'ils avaient des expressions qui généraient des exceptions, même si ces expressions se trouvaient dans du code qui ne pouvait jamais être atteint à l'exécution. (Nicholas Clark, Dave Mitchell)

Filtres source dans @INC

Il est possible d'améliorer le mécanisme des hooks de sous-routines dans @INC en ajoutant un filtre source par-dessus le filehandle ouvert et retourné par le hook. Cette fonctionnalité était prévue depuis longtemps, mais ne fonctionnait pas tout à fait jusqu'à maintenant. Voir "require" dans perlfunc pour plus de détails. (Nicholas Clark)

Nouvelles variables internes

"${^RE_DEBUG_FLAGS}"
Cette variable contrôle les indicateurs de débogage actifs pour le moteur d'expressions régulières lors de l'exécution sous "use re "debug"". Voir re pour plus de détails.
"${^CHILD_ERROR_NATIVE}"
Cette variable donne le statut natif retourné par la dernière fermeture de pipe, commande backtick, appel réussi à wait() ou waitpid(), ou de l'opérateur system(). Voir perlvar pour plus de détails. (Contribué par Gisle Aas.)
"${^RE_TRIE_MAXBUF}"
Voir "Optimisation par trie des alternances de chaînes littérales".
"${^WIN32_SLOPPY_STAT}"
Voir "Statistique imprécise sous Windows".

Divers

unpack() déballe maintenant par défaut la variable $_.

mkdir() sans arguments utilise maintenant par défaut $_.

La sortie de vidage interne a été améliorée, de sorte que les caractères non imprimables tels que la nouvelle ligne et le retour arrière sont affichés en notation "\x", plutôt qu'en octal.

L'option -C ne peut plus être utilisée sur la ligne "#!". Elle ne fonctionnait de toute façon pas là, car les flux standards sont déjà configurés à ce stade de l'exécution de l'interpréteur perl. Vous pouvez utiliser binmode() à la place pour obtenir le comportement souhaité.

UCD 5.0.0

La copie de la base de données des caractères Unicode incluse dans Perl 5 a été mise à jour à la version 5.0.0.

MAD

MAD, qui signifie Miscellaneous Attribute Decoration (Décoration d'attributs divers), est un travail encore en développement menant à un convertisseur de Perl 5 vers Perl 6. Pour l'activer, il est nécessaire de passer l'argument "-Dmad" à Configure. Le perl obtenu n'est pas binaire compatible avec un perl 5.10 régulier, et présente des pénalités d'espace et de vitesse ; de plus, tous les tests de régression ne passent pas encore avec. (Larry Wall, Nicholas Clark)

kill() sous Windows

Sur les plateformes Windows, "kill(-9, $pid)" tue maintenant un arbre de processus. (Sous Unix, cela délivre le signal à tous les processus du même groupe de processus.)

Changements incompatibles

Emballage et chaînes UTF-8

La sémantique de pack() et unpack() concernant les données encodées en UTF-8 a été modifiée. Le traitement se fait maintenant par défaut caractère par caractère au lieu d'octet par octet sur l'encodage sous-jacent. Notamment, le code qui utilisait des choses comme "pack("a*", $string)" pour voir à travers l'encodage de la chaîne obtiendra simplement la $string d'origine. Les chaînes emballées peuvent également être mises à niveau pendant le traitement lorsque vous stockez des caractères mis à niveau. Vous pouvez obtenir l'ancien comportement en utilisant "use bytes".

Pour être cohérent avec pack(), le modèle "C0" dans les modèles unpack() indique que les données doivent être traitées en mode caractère, c'est-à-dire caractère par caractère ; au contraire, "U0" dans unpack() indique le mode UTF-8, où la chaîne emballée est traitée dans sa forme Unicode encodée en UTF-8, octet par octet. Ceci est inversé par rapport à perl 5.8.X, mais est maintenant cohérent entre pack() et unpack().

De plus, "C0" et "U0" peuvent également être utilisés dans les modèles pack() pour spécifier respectivement les modes caractère et octet.

"C0" et "U0" au milieu d'un format d'emballage ou de déballage passent maintenant au mode d'encodage spécifié, en respectant le regroupement par parenthèses. Auparavant, les parenthèses étaient ignorées.

De plus, il existe un nouveau format de caractère pack(), "W", qui est destiné à remplacer l'ancien "C". "C" est conservé pour les caractères non signés codés en octets dans la représentation interne des chaînes. "W" représente les valeurs de caractères non signés (logiques), qui peuvent être supérieures à 255. Il est donc plus robuste lors du traitement de données potentiellement encodées en UTF-8 (car "C" enveloppera les valeurs en dehors de la plage 0..255, et ne respectera pas l'encodage de la chaîne).

En pratique, cela signifie que les formats d'emballage sont maintenant neutres vis-à-vis de l'encodage, à l'exception de "C".

Par souci de cohérence, "A" dans le format unpack() supprime maintenant tous les espaces blancs Unicode de la fin de la chaîne. Avant perl 5.9.2, il ne supprimait que les espaces classiques ASCII.

Fonctionnalité de compte d'octets/caractères dans unpack()

Un nouveau caractère de modèle unpack(), ".", retourne le nombre d'octets ou de caractères (selon le mode d'encodage sélectionné, voir ci-dessus) lus jusqu'à présent.

Les variables $* et $# ont été supprimées

$*, qui était dépréciée en faveur des modificateurs d'expressions régulières "/s" et "/m", a été supprimée.

La variable dépréciée $# (format de sortie des nombres) a été supprimée.

Deux nouveaux avertissements sévères, "$#/$* n'est plus pris en charge", ont été ajoutés.

Les lvalues de substr() ne sont plus de longueur fixe

Les lvalues retournées par la forme à trois arguments de substr() étaient auparavant une "fenêtre de longueur fixe" sur la chaîne d'origine. Dans certains cas, cela pouvait entraîner des actions surprenantes à distance ou d'autres comportements indéfinis. Désormais, la longueur de la fenêtre s'ajuste à la longueur de la chaîne qui lui est assignée.

Analyse de &

Changements dans la version 5.10.0

L'identificateur "_" est maintenant forcé d'être un bareword après un opérateur de test de fichier. Cela résout un certain nombre de problèmes de mauvaise analyse lorsqu'une sous-routine globale "_" est définie.

L'attribut ":unique" a été rendu inopérant, car son implémentation actuelle était fondamentalement défectueuse et non thread-safe.

Effet des pragmata dans eval

La valeur de compilation de la variable d'indice "%^H" peut maintenant se propager dans le code évalué par eval(""). Cela rend plus utile l'implémentation des pragmata lexicaux.

En conséquence, la surcharge des constantes se propage maintenant dans eval("").

chdir FOO

Un argument bareword à chdir() est maintenant reconnu comme une poignée de fichier. Les versions antérieures interprétaient le bareword comme un nom de répertoire. (Gisle Aas)

Gestion des fichiers .pmc

Une ancienne fonctionnalité de perl était qu'avant que "require" ou "use" ne recherchent un fichier avec une extension * .pm*, ils rechercheraient d'abord un nom de fichier similaire avec une extension * .pmc*. Si ce fichier est trouvé, il serait chargé à la place de tout fichier potentiellement existant se terminant par une extension * .pm*.

Auparavant, les fichiers *.pmc* n'étaient chargés que s'ils étaient plus récents que le fichier *.pm* correspondant. À partir de la version 5.9.4, ils seront toujours chargés s'ils existent.

$^V est maintenant un objet "version" au lieu d'une chaîne v

$^V peut toujours être utilisé avec le format %vd dans printf, mais toute opération au niveau du caractère accédera maintenant à la représentation de chaîne de l'objet "version" et non aux ordinaux d'une chaîne v. Les expressions telles que "substr($^V, 0, 2)" ou "split //, $^V" ne fonctionnent plus et doivent être réécrites.

@- et @+ dans les modèles

Les tableaux spéciaux "@-" et "@+" ne sont plus interpolés dans les expressions régulières. (Sadahiro Tomoyuki)

$AUTOLOAD peut maintenant être tainé

Si vous appelez une sous-routine par un nom tainé, et si elle reporte à une fonction AUTOLOAD, alors $AUTOLOAD sera (correctement) tainé. (Rick Delaney)

Tainting et printf

Lorsque perl est exécuté en mode taint, printf() et sprintf() rejetteront désormais tout argument de format tainé. (Rafael Garcia-Suarez)

undef et les gestionnaires de signaux

L'undefinir ou supprimer un gestionnaire de signaux via "undef $SIG{FOO}" est maintenant équivalent à le définir sur 'DEFAULT'. (Rafael Garcia-Suarez)

strictures et déréférencement dans defined()

"use strict 'refs'" ignorait la prise d'une référence forte dans un argument de defined(), comme dans :

use strict 'refs';
my $x = 'foo';
if (defined $$x) {...}

Cela produit maintenant correctement l'erreur d'exécution "Can't use string as a SCALAR ref while "strict refs" in use".

"defined @$foo" et "defined %$bar" sont maintenant également soumis à strict 'refs' (c'est-à-dire que $foo et $bar doivent être de vraies références). ( defined(@foo) et defined(%bar) sont de toute façon des constructions découragées.) (Nicholas Clark)

"(?p{})" a été supprimé

La construction d'expression régulière "(?p{})", qui a été dépréciée dans perl 5.8, a été supprimée. Utilisez plutôt "(??{})". (Rafael Garcia-Suarez)

Les pseudo-hashes ont été supprimés

La prise en charge des pseudo-hashes a été supprimée de Perl 5.9. (Le pragma "fields" reste ici, mais utilise une implémentation alternative.)

Suppression du compilateur bytecode et de perlcc

"perlcc", le byteloader et les modules de support (B::C, B::CC, B::Bytecode, etc.) ne sont plus distribués avec les sources de perl. Ces outils expérimentaux n'ont jamais fonctionné de manière fiable et, en raison du manque de volontaires pour les maintenir à jour avec les développements de l'interpréteur perl, il a été décidé de les supprimer plutôt que de distribuer une version défectueuse de ceux-ci. La dernière version de ces modules peut être trouvée avec perl 5.9.4.

Cependant, le framework du compilateur B reste pris en charge dans le noyau de perl, comme avec les modules plus utiles qu'il a permis (entre autres, B::Deparse et B::Concise).

Suppression du JPL

Le JPL (Java-Perl Lingo) a été supprimé de l'archive source de perl.

Héritage récursif détecté plus tôt

Perl lèvera maintenant immédiatement une exception si vous modifiez @ISA d'un package d'une manière qui entraînerait un héritage récursif.

Auparavant, l'exception ne se produisait que lorsque Perl tentait d'utiliser l'héritage récursif lors de la résolution d'une méthode ou lors d'une recherche "$foo->isa($bar)".

warnings::enabled et warnings::warnif modifiés pour favoriser les utilisateurs de modules

Le comportement en 5.10.x favorise la personne qui utilise le module ; le comportement en 5.8.x favorise l'auteur du module ;

Supposons le code suivant :

  main appelle Foo::Bar::baz()
  Foo::Bar hérite de Foo::Base
  Foo::Bar::baz() appelle Foo::Base::_bazbaz()
  Foo::Base::_bazbaz() appelle : warnings::warnif('substr', 'some warning
message');

Sur 5.8.x, le code génère un avertissement lorsque Foo::Bar contient "use warnings;". Il n'a pas d'importance si Foo::Base ou main ont les avertissements activés pour désactiver l'avertissement, il faut modifier Foo::Bar.

Sur 5.10.0 et versions ultérieures, le code génère un avertissement lorsque main contient "use warnings;". Il n'a pas d'importance si Foo::Base ou Foo::Bar ont les avertissements activés pour désactiver l'avertissement, il faut modifier main.

Suppression de "package;" ("package" sans arguments)

La syntaxe "package;" qui permettait au code de sortir de n'importe quel package (et donc d'exiger l'utilisation de noms lexicaux ou entièrement qualifiés) a été supprimée. Sa sémantique n'a jamais été très claire et son implémentation encore moins. (Elle a été précédemment dépréciée dans perl 5.8.0.)

Mise à jour des modules cœur individuels

Encore plus de modules cœur sont maintenant également disponibles séparément via CPAN. Si vous souhaitez mettre à jour l'un de ces modules, vous n'avez pas besoin d'attendre une nouvelle version de perl. Depuis l'interpréteur cpan, l'exécution de la commande 'r' signalera les modules dont des mises à jour sont disponibles. Voir "perldoc CPAN" pour plus d'informations.

Modifications des pragmas

base
Le pragma "base" émet désormais un avertissement si une classe tente d'hériter d'elle-même. (Curtis "Ovid" Poe)
strict et warnings
"strict" et "warnings" signaleront désormais bruyamment s'ils sont chargés avec une casse incorrecte (comme dans "use Strict;"). (Johan Vromans)

Le module "version" fournit un support pour les objets de version.
warnings
Le pragma "warnings" ne charge plus "Carp". Cela signifie que le code qui utilisait les routines "Carp" sans l'avoir chargé au moment de la compilation pourrait nécessiter des ajustements ; typiquement, le code (erroné) suivant ne fonctionnera plus et nécessitera l'ajout de parenthèses après le nom de la fonction : 
use warnings;
require Carp;
Carp::confess 'argh';
less
"less" fait maintenant quelque chose d'utile (ou du moins essaie). En fait, il a été transformé en pragma lexical. Ainsi, dans vos modules, vous pouvez maintenant tester si vos utilisateurs ont demandé à utiliser moins de CPU, ou moins de mémoire, moins de magie, ou même moins de gras. Voir less pour plus d'informations. (Joshua ben Jore)

Nouveaux modules

  • "encoding::warnings", par Audrey Tang, est un module qui émet des avertissements chaque fois qu'une chaîne de caractères ASCII contenant des octets de haute bit est implicitement convertie en UTF-8. C'est un pragma lexical depuis Perl 5.9.4 ; sur les perls plus anciens, son effet est global.
  • "Module::CoreList", par Richard Clamp, est un petit module pratique qui indique quelles versions de modules de base sont livrées avec n'importe quelle version de Perl 5. Il est livré avec une interface en ligne de commande, "corelist".
  • "Math::BigInt::FastCalc" est une version optimisée en XS, et donc plus rapide, de "Math::BigInt::Calc".
  • "Compress::Zlib" est une interface pour la bibliothèque de compression zlib. Il est livré avec une version groupée de zlib, donc avoir une zlib fonctionnelle n'est pas un prérequis pour l'installer. Il est utilisé par "Archive::Tar" (voir ci-dessous).
  • "IO::Zlib" est une interface de style "IO::" pour "Compress::Zlib".
  • "Archive::Tar" est un module pour manipuler des archives "tar".
  • "Digest::SHA" est un module utilisé pour calculer de nombreux types de digests SHA, il a été inclus pour le support SHA dans le module CPAN.
  • "ExtUtils::CBuilder" et "ExtUtils::ParseXS" ont été ajoutés.
  • "Hash::Util::FieldHash", par Anno Siegel, a été ajouté. Ce module fournit un support pour les *hashes de champs* : des hashes qui maintiennent une association d'une référence avec une valeur, de manière thread-safe et collectée par le garbage collector. Ces hashes sont utiles pour implémenter des objets de l'intérieur.
  • "Module::Build", par Ken Williams, a été ajouté. C'est une alternative à "ExtUtils::MakeMaker" pour construire et installer des modules Perl.
  • "Module::Load", par Jos Boumans, a été ajouté. Il fournit une interface unique pour charger les modules Perl et les fichiers de type ".pl".
  • "Module::Loaded", par Jos Boumans, a été ajouté. Il est utilisé pour marquer les modules comme chargés ou déchargés.
  • "Package::Constants", par Jos Boumans, a été ajouté. C'est une aide simple pour lister toutes les constantes déclarées dans un paquet donné.
  • "Win32API::File", par Tye McQueen, a été ajouté (pour les compilations Windows). Ce module fournit un accès de bas niveau aux appels système Win32 pour les fichiers/répertoires.
  • "Locale::Maketext::Simple", requis par CPANPLUS, est un simple wrapper autour de "Locale::Maketext::Lexicon". Notez que "Locale::Maketext::Lexicon" n'est pas inclus dans le noyau de Perl ; le comportement de "Locale::Maketext::Simple" se dégrade gracieusement lorsque ce dernier n'est pas présent.
  • "Params::Check" implémente un mécanisme générique d'analyse/vérification des entrées. Il est utilisé par CPANPLUS.
  • "Term::UI" simplifie la tâche de poser des questions à une invite de terminal.
  • "Object::Accessor" fournit une interface pour créer des accesseurs par objet.
  • "Module::Pluggable" est un framework simple pour créer des modules qui acceptent des sous-modules enfichables.
  • "Module::Load::Conditional" fournit des moyens simples de consulter et éventuellement de charger les modules installés.
  • "Time::Piece" fournit une interface orientée objet aux fonctions temporelles, remplaçant les fonctions natives localtime() et gmtime().
  • "IPC::Cmd" aide à trouver et exécuter des commandes externes, potentiellement de manière interactive.
  • "File::Fetch" fournit un mécanisme générique simple de récupération de fichiers.
  • "Log::Message" et "Log::Message::Simple" sont utilisés par la facility de journalisation de "CPANPLUS".
  • "Archive::Extract" est un mécanisme générique d'extraction d'archives pour les fichiers .tar (plains, gzippés ou bzip2) ou .zip.
  • "CPANPLUS" fournit une API et un outil en ligne de commande pour accéder aux miroirs CPAN.
  • "Pod::Escapes" fournit des utilitaires utiles pour décoder les séquences E<...> de Pod.
  • "Pod::Simple" est désormais le backend pour plusieurs des modules liés aux Pod inclus avec Perl.

Aide à la configuration
"Configure -h" a été étendu avec les options les plus couramment utilisées.

Améliorations de la compilation

Compilation en parallèle
Les compilations parallèles devraient maintenant fonctionner correctement, bien qu'il puisse encore y avoir des problèmes si "make test" est instruit pour s'exécuter en parallèle.
Support des compilateurs Borland
La compilation avec les compilateurs Borland sur Win32 devrait être plus fluide. Notamment, Steve Hay a travaillé pour contourner de nombreux avertissements émis par leurs compilateurs et au moins une erreur interne du compilateur C.
Compilation statique sous Windows
Les extensions Perl sous Windows peuvent désormais être compilées statiquement dans la DLL Perl.

De plus, il est maintenant possible de compiler un "perl-static.exe" qui ne dépend pas de la DLL Perl sous Win32. Voir les makefiles Win32 pour plus de détails. (Vadim Konovalov)

Fichiers ppport.h
Tous les fichiers ppport.h dans les modules XS groupés avec perl sont maintenant auto-générés au moment de la compilation. (Marcus Holland-Moritz)
Compatibilité C++
Des efforts ont été faits pour rendre perl et les modules XS centraux compilables avec divers compilateurs C++ (bien que la situation ne soit pas parfaite avec certains compilateurs sur certaines des plateformes testées.)
Support du compilateur 64 bits Microsoft
Le support de la compilation de perl avec le compilateur 64 bits de Microsoft a été amélioré. (ActiveState)
Visual C++
Perl peut maintenant être compilé avec Microsoft Visual C++ 2005 (et 2008 Beta 2).
Compilations Win32
Toutes les compilations win32 (MS-Win, WinCE) ont été fusionnées et nettoyées.

Améliorations de l'installation

Fichiers auxiliaires des modules
Les fichiers README et les journaux de modifications pour les modules CPAN groupés avec perl ne sont plus installés.

Plateformes nouvelles ou améliorées

Perl a été signalé comme fonctionnant sous Symbian OS. Voir perlsymbian pour plus d'informations.

De nombreuses améliorations ont été apportées pour que Perl fonctionne correctement sur z/OS.

Perl a été signalé comme fonctionnant sous DragonFlyBSD et MidnightBSD.

Perl a également été signalé comme fonctionnant sous NexentaOS ( http://www.gnusolaris.org/ ).

Le port VMS a été amélioré. Voir perlvms.

Le support de Cray XT4 Catamount/Qk a été ajouté. Voir hints/catamount.sh dans la distribution du code source pour plus d'informations.

Des correctifs de fournisseurs ont été fusionnés pour RedHat et Gentoo.

DynaLoader::dl_unload_file() fonctionne maintenant sous Windows.

Corrections de bugs sélectionnées

strictures dans les blocs d'évaluation d'expressions régulières
"strict" n'était pas pris en compte dans les blocs d'évaluation d'expressions régulières ("/(?{...})/").
Appel à CORE::require()
CORE::require() et CORE::do() étaient toujours analysés comme require() et do() lorsqu'ils étaient remplacés. Ceci est maintenant corrigé.
Sous-index de tranches
Vous pouvez maintenant utiliser une forme sans flèche pour les sous-index chaînés après une tranche de liste, comme dans : 
({foo => "bar"})[0]{foo}

C'était auparavant une erreur de syntaxe ; un "->" était requis.

"no warnings 'category'" fonctionne correctement avec -w
Précédemment, lors de l'exécution avec les avertissements activés globalement via "-w", la désactivation sélective de catégories d'avertissement spécifiques désactivait en fait tous les avertissements. Ceci est maintenant corrigé ; maintenant "no warnings 'io';" ne désactivera que les avertissements de la classe "io". Auparavant, cela désactivait par erreur tous les avertissements.
Améliorations des threads
Plusieurs fuites de mémoire dans les ithreads ont été corrigées. De plus, les ithreads ont été rendus moins gourmands en mémoire.

"threads" est maintenant un module à double vie, également disponible sur CPAN. Il a été étendu de nombreuses manières. Une méthode kill() est disponible pour la signalisation de threads. On peut obtenir le statut d'un thread, ou la liste des threads en cours d'exécution ou joignables.

Une nouvelle méthode "threads->exit()" est utilisée pour quitter l'application (c'est le comportement par défaut pour le thread principal) ou uniquement le thread actuel (c'est le comportement par défaut pour tous les autres threads). En revanche, la fonction intégrée exit() provoque maintenant toujours la terminaison de l'application entière. (Jerry D. Hedden)

chr() et les valeurs négatives
chr() sur une valeur négative donne maintenant "\x{FFFD}", le caractère de remplacement Unicode, sauf lorsque le pragma "bytes" est activé, où les huit bits de poids faible de la valeur sont utilisés.
PERL5SHELL et tainting
Sous Windows, la variable d'environnement PERL5SHELL est maintenant vérifiée pour le taintedness. (Rafael Garcia-Suarez)
Utilisation de *FILE{IO}
stat() et les tests de fichiers "-X" traitent maintenant les poignées de fichier *FILE{IO} comme des poignées de fichier *FILE. (Steve Peters)
Surcharge et reblessing
La surcharge fonctionne maintenant lorsque des références sont reblessées dans une autre classe. En interne, cela a été implémenté en déplaçant le drapeau de "surcharge" de la référence vers ce qui est référencé, ce qui logiquement était où il aurait toujours dû être. (Nicholas Clark)
Surcharge et UTF-8
Quelques bogues liés à la gestion d'UTF-8 avec des objets ayant une chaîne de caractères surchargée ont été corrigés. (Nicholas Clark)
Fuites de mémoire eval corrigées
Traditionnellement, "eval 'syntax error'" fuyait considérablement. Beaucoup (mais pas toutes) de ces fuites ont maintenant été éliminées ou réduites. (Dave Mitchell)
Périphérique aléatoire sous Windows
Dans les versions précédentes, perl lisait le fichier /dev/urandom s'il existait lors de l'initialisation de son générateur de nombres aléatoires. Ce fichier est peu susceptible d'exister sous Windows, et s'il existait, il ne contiendrait probablement pas de données appropriées, donc perl n'essaie plus de le lire sous Windows. (Alex Davies)
PERLIO_DEBUG
La variable d'environnement "PERLIO_DEBUG" n'a plus aucun effet pour les scripts setuid et pour les scripts exécutés avec -T.

De plus, avec un perl activé pour les threads, l'utilisation de "PERLIO_DEBUG" pouvait entraîner un débordement de tampon interne. Ceci a été corrigé.

PerlIO::scalar et scalaires en lecture seule
PerlIO::scalar empêchera désormais l'écriture sur des scalaires en lecture seule. De plus, seek() est maintenant supporté avec les poignées de fichier basées sur PerlIO::scalar, la chaîne sous-jacente étant remplie de zéros si nécessaire. (Rafael, Jarkko Hietaniemi)
study() et UTF-8
study() n'a jamais fonctionné pour les chaînes UTF-8, mais pouvait conduire à de faux résultats. C'est maintenant une opération nulle sur les données UTF-8. (Yves Orton)
Signaux critiques
Les signaux SIGILL, SIGBUS et SIGSEGV sont maintenant toujours délivrés de manière "non sûre" (contrairement aux autres signaux, qui sont différés jusqu'à ce que l'interpréteur perl atteigne un état raisonnablement stable ; voir "Deferred Signals (Safe Signals)" dans perlipc). (Rafael)
Correction @INC-hook
Lorsqu'un module ou un fichier est chargé via un @INC-hook, et lorsque ce hook a défini une entrée de nom de fichier dans %INC, __FILE__ est maintenant défini pour ce module en conséquence du contenu de cette entrée %INC. (Rafael)
"-t" switch fix
Les commutateurs "-w" et "-t" peuvent maintenant être utilisés ensemble sans perturber quelles catégories d'avertissements sont activées. (Rafael)
Duplication de poignées de fichier UTF-8
La duplication d'une poignée de fichier qui a la couche PerlIO ":utf8" définie transportera maintenant correctement cette couche sur la poignée de fichier dupliquée. (Rafael)
Localisation des éléments de hachage
La localisation d'un élément de hachage dont la clé était donnée comme une variable ne fonctionnait pas correctement si la variable était modifiée pendant que le local() était actif (comme dans "local $h{$x}; ++$x"). (Bo Lindbergh)

Diagnostics nouveaux ou modifiés

Utilisation d'une valeur non initialisée
Perl tentera maintenant de vous indiquer le nom de la variable (le cas échéant) qui était indéfinie.
Utilisation dépréciée de my() dans une condition fausse
Un nouvel avertissement de dépréciation, Utilisation dépréciée de my() dans une condition fausse, a été ajouté, pour avertir contre l'utilisation de la construction discutable et dépréciée 
my $x if 0;

Nouveaux avertissements et erreurs

?
Voir perldiag. Utiliser des variables "state" à la place.
!=~ doit être !~
Un nouvel avertissement, "!=~ doit être !~", est émis pour empêcher cette faute d'orthographe de l'opérateur de non-correspondance.
Nouvelle ligne dans une chaîne justifiée à gauche
L'avertissement *Nouvelle ligne dans une chaîne justifiée à gauche* a été supprimé.
Trop tard pour l'option « -T »
L'erreur *Trop tard pour l'option « -T »* a été reformulée pour être plus descriptive.
La variable « %s » %s masque une déclaration antérieure
Cet avertissement est maintenant émis dans des cas plus cohérents ; en bref, lorsque l'une des déclarations impliquées est une variable "my" : 
my $x;   my $x;     # avertit
my $x;  our $x;     # avertit
our $x;  my $x;     # avertit

En revanche, ce qui suit :

our $x; our $x;

donne maintenant un avertissement *La variable « our » %s est redéclarée*.

readdir()/closedir()/etc. tenté sur un descripteur de répertoire invalide
Ces nouveaux avertissements sont maintenant émis lorsqu'un descripteur de répertoire est utilisé mais qu'il est soit fermé, soit pas vraiment un descripteur de répertoire.
Ouverture du descripteur de répertoire/fichier %s également comme fichier/répertoire
Deux avertissements de dépréciation ont été ajoutés : (Rafael)

Ouverture du descripteur de fichier %s également comme répertoire
L'utilisation de -P est dépréciée
Le commutateur en ligne de commande de Perl "-P" est maintenant déprécié.
La chaîne v en cours d'utilisation/nécessaire n'est pas portable
Perl vous avertira des problèmes potentiels de compatibilité ascendante avec la syntaxe "use VERSION".
perl -V
"perl -V" présente plusieurs améliorations, le rendant plus utilisable depuis les scripts shell pour obtenir la valeur des variables de configuration. Voir perlrun pour les détails.

Internes modifiés

En général, le code source de Perl a été refactorisé, nettoyé et optimisé à de nombreux endroits. De plus, la gestion et l'allocation de la mémoire ont été améliorées à plusieurs points.

Lors de la compilation du cœur de Perl avec gcc, autant de drapeaux d'avertissement gcc que possible sont activés sur la plateforme. (Cette quête de propreté ne s'étend pas au code XS car nous ne pouvons garantir la propreté du code que nous n'avons pas écrit.) Des drapeaux d'avertissement similaires ont été ajoutés ou resserrés pour divers autres compilateurs C.

Réorganisation des constantes SVt_*

L'ordre relatif des constantes qui définissent les différents types de "SV" a changé ; en particulier, "SVt_PVGV" a été déplacé avant "SVt_PVLV", "SVt_PVAV", "SVt_PVHV" et "SVt_PVCV". Cela ne devrait faire aucune différence, sauf si vous avez du code qui fait explicitement des hypothèses sur cet ordre. (La hiérarchie d'héritage des objets "B::*" a été modifiée pour refléter cela.)

Élimination de SVt_PVBM

Dans ce contexte, le type interne "SVt_PVBM" a été supprimé. Ce type dédié de "SV" était utilisé par l'opérateur "index" et certaines parties du moteur d'expressions régulières pour faciliter les correspondances rapides de Boyer-Moore. Son utilisation interne a été remplacée par des "SV" de type "SVt_PVGV".

Nouveau type SVt_BIND

Un nouveau type "SVt_BIND" a été ajouté, en préparation du projet visant à implémenter Perl 6 sur 5. Il n'y a délibérément pas encore d'implémentation, et ils ne peuvent pas encore être créés ou détruits.

Suppression des symboles CPP

Les symboles du préprocesseur C "PERL_PM_APIVERSION" et "PERL_XS_APIVERSION", qui étaient censés donner le numéro de version du plus ancien binaire Perl compatible (resp. compatible source) avec le présent, n'étaient pas utilisés et avaient parfois des valeurs trompeuses. Ils ont été supprimés.

Moins d'espace utilisé par les ops

La structure "BASEOP" utilise maintenant moins d'espace. Le champ "op_seq" a été supprimé et remplacé par un champ de bits unique "op_opt". "op_type" fait maintenant 9 bits de long. (Par conséquent, la classe "B::OP" ne fournit plus de méthode "seq".)

Nouveau parseur

Le parseur de Perl est maintenant généré par bison (il était auparavant généré par byacc.) En conséquence, il semble être un peu plus robuste.

De plus, Dave Mitchell a amélioré la sortie de débogage du lexer sous "-DT".

Utilisation de "const"

Andy Lester a apporté de nombreuses améliorations pour déterminer quels paramètres de fonction et variables locales pouvaient réellement être déclarés "const" au compilateur C. Steve Peters a fourni de nouvelles macros *_set et a retravaillé le cœur pour les utiliser plutôt que d'assigner à des macros dans un contexte LVALUE.

Mathoms

Un nouveau fichier, mathoms.c, a été ajouté. Il contient des fonctions qui ne sont plus utilisées dans le cœur de Perl, mais qui restent disponibles pour des raisons de compatibilité binaire ou source. Cependant, ces fonctions ne seront pas compilées si vous ajoutez "-DNO_MATHOMS" dans les drapeaux du compilateur.

« AvFLAGS » a été supprimé

La macro "AvFLAGS" a été supprimée.

Changements « av_* »

Les fonctions "av_*()", utilisées pour manipuler les tableaux, n'acceptent plus de paramètres "AV*" nuls.

$^H et %^H

L'implémentation des variables spéciales $^H et %^H a changé, pour permettre l'implémentation des pragmas lexicaux en Perl pur.

L'héritage des modules B:: a changé

La hiérarchie d'héritage des modules "B::" a changé ; "B::NV" hérite maintenant de "B::SV" (il héritait auparavant de "B::IV").

Constructeurs de hashs et tableaux anonymes

Les constructeurs de hashs et tableaux anonymes prennent maintenant 1 op dans l'arbre d'opérations au lieu de 3, maintenant que pp_anonhash et pp_anonlist retournent une référence vers un hash/tableau lorsque l'op est marqué avec OPf_SPECIAL. (Nicholas Clark)

Problèmes connus

Il reste un problème dans l'implémentation du lexique $_ : il ne fonctionne pas à l'intérieur des blocs "/(?{...}) /". (Voir le test TODO dans t/op/mydef.t.)

Les opérateurs de test de fichier empilés ne fonctionneront pas lorsque le pragma "filetest" est actif, car ils dépendent du tampon "_" de stat() étant rempli, et filetest contourne stat().

Problèmes UTF-8

La gestion de l'Unicode est encore peu soignée à plusieurs endroits, où elle dépend du fait qu'une chaîne soit interne marquée comme UTF-8. Cela sera rendu plus cohérent dans Perl 5.12, mais cela ne sera pas possible sans une certaine incompatibilité ascendante.

Problèmes spécifiques à la plateforme

Lorsqu'il est compilé avec g++ et le support des threads sous Linux, il est signalé que $! cesse de fonctionner correctement. Cela est lié au fait que glibc fournit deux implémentations de strerror_r(3), et Perl sélectionne la mauvaise.
