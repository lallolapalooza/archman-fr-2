NOM

perlref - Références Perl et structures de données imbriquées

NOTE

Ceci est la documentation complète sur tous les aspects des références. Pour une introduction plus courte et tutorielle sur les fonctionnalités essentielles, voir perlreftut.

DESCRIPTION

Avant la version 5 de Perl, il était difficile de représenter des structures de données complexes, car toutes les références devaient être symboliques -- et même alors, il était difficile de faire référence à une variable plutôt qu'à une entrée de table de symboles. Perl rend maintenant non seulement plus facile l'utilisation de références symboliques aux variables, mais vous permet également d'avoir des références « dures » à n'importe quel morceau de données ou de code. N'importe quel scalaire peut contenir une référence dure. Comme les tableaux et les hashes contiennent des scalaires, vous pouvez maintenant facilement construire des tableaux de tableaux, des tableaux de hashes, des hashes de tableaux, des tableaux de hashes de fonctions, et ainsi de suite.

Les références dures sont intelligentes -- elles suivent les comptes de références pour vous, libérant automatiquement la chose référencée lorsque son compte de références atteint zéro. (Les comptes de références pour les valeurs dans des structures de données autoréférentielles ou cycliques peuvent ne pas atteindre zéro sans un peu d'aide ; voir « Références circulaires » pour une explication détaillée.) Si cette chose se trouve être un objet, l'objet est détruit. Voir perlobj pour en savoir plus sur les objets. (Dans un sens, tout dans Perl est un objet, mais nous réservons généralement le terme pour les références à des objets qui ont été officiellement « bénis » dans un package de classe.)

Les références symboliques sont des noms de variables ou d'autres objets, tout comme un lien symbolique dans un système de fichiers Unix ne contient que le nom d'un fichier. La notation *glob est une sorte de référence symbolique. (Les références symboliques sont parfois appelées « références douces », mais s'il vous plaît, ne les appelez pas ainsi ; les références sont déjà assez confuses sans synonymes inutiles.)

En revanche, les références dures ressemblent davantage aux liens durs dans un système de fichiers Unix : elles sont utilisées pour accéder à un objet sous-jacent sans se soucier de son autre nom. Lorsque le mot « référence » est utilisé sans adjectif, comme dans le paragraphe suivant, il s'agit généralement d'une référence dure.

Les références sont faciles à utiliser en Perl. Il n'y a qu'un seul principe directeur : en général, Perl n'effectue pas de référencement ou de déréférencement implicite. Lorsqu'un scalaire contient une référence, il se comporte toujours comme un simple scalaire. Il ne commence pas magiquement à être un tableau, un hash ou une sous-routine ; vous devez le lui dire explicitement, en le déréférençant.

Créer des Références

Les références peuvent être créées de plusieurs manières.

Opérateur Backslash

En utilisant l'opérateur backslash sur une variable, une sous-routine ou une valeur. (Cela fonctionne un peu comme l'opérateur & (adresse de) en C.) Cela crée généralement une autre référence à une variable, car il existe déjà une référence à la variable dans la table des symboles. Mais la référence de la table des symboles peut disparaître, et vous aurez toujours la référence que le backslash a renvoyée. Voici quelques exemples :

$scalarref = \$foo;
$arrayref  = \@ARGV;
$hashref   = \%ENV;
$coderef   = \&handler;
$globref   = \*foo;

Il n'est pas possible de créer une véritable référence à une poignée d'E/S (poignée de fichier ou de répertoire) en utilisant l'opérateur backslash. Le maximum que vous puissiez obtenir est une référence à un typeglob, qui est en fait une entrée complète de table de symboles. Mais voir l'explication de la syntaxe *foo{THING} ci-dessous. Cependant, vous pouvez toujours utiliser des typeglobs et des globrefs comme s'il s'agissait de poignées d'E/S.

Crochets

Une référence à un tableau anonyme peut être créée en utilisant des crochets :

$arrayref = [1, 2, ['a', 'b', 'c']];

Ici, nous avons créé une référence à un tableau anonyme de trois éléments dont le dernier élément est lui-même une référence à un autre tableau anonyme de trois éléments. (La syntaxe multidimensionnelle décrite plus tard peut être utilisée pour y accéder. Par exemple, après ce qui précède, "$arrayref->[2][1]" aurait la valeur "b".)

Prendre une référence à une liste énumérée n'est pas la même chose que d'utiliser des crochets -- c'est plutôt la même chose que de créer une liste de références !

@list = (\$x, \@y, \%z);
@list = \($x, @y, %z);      # même chose !

Comme cas spécial, "\(@foo)" renvoie une liste de références aux contenus de @foo, pas une référence à @foo lui-même. Idem pour %foo, sauf que les références aux clés sont à des copies (puisque les clés ne sont que des chaînes plutôt que des scalaires à part entière).

Accolades

Une référence à un hash anonyme peut être créée en utilisant des accolades :

$hashref = {
    'Adam'  => 'Eve',
    'Clyde' => 'Bonnie',
};

Les compositeurs de hashes et tableaux anonymes comme ceux-ci peuvent être mélangés librement pour produire une structure aussi compliquée que vous le souhaitez. La syntaxe multidimensionnelle décrite ci-dessous fonctionne également pour ceux-ci. Les valeurs ci-dessus sont des littéraux, mais les variables et les expressions fonctionneraient tout aussi bien, car les opérateurs d'affectation en Perl (même dans local() ou my()) sont des instructions exécutables, pas des déclarations au moment de la compilation.

Parce que les accolades sont utilisées pour plusieurs autres choses, y compris les BLOCs, vous devrez peut-être occasionnellement désambiguïser les accolades au début d'une instruction en mettant un "+" ou un "return" devant afin que Perl réalise que l'accolade d'ouverture ne commence pas un BLOC. L'économie et la valeur mnémotechnique de l'utilisation des accolades sont jugées dignes de cet inconvénient occasionnel.

Par exemple, si vous vouliez une fonction pour créer un nouveau hash et renvoyer une référence à celui-ci, vous avez ces options :

sub hashem {        { @_ } }   # silencieusement faux
sub hashem {       +{ @_ } }   # ok
sub hashem { return { @_ } }   # ok

D'un autre côté, si vous voulez l'autre signification, vous pouvez faire ceci :

sub showem {        { @_ } }   # ambigu (actuellement ok,
                               # mais pourrait changer)
sub showem {       {; @_ } }   # ok
sub showem { { return @_ } }   # ok

Le "+{" et le "{;" en tête servent toujours à désambiguïser l'expression pour signifier soit la référence de HASH, soit le BLOC.

Sous-routines Anonymes

Une référence à une sous-routine anonyme peut être créée en utilisant "sub" sans nom de sous-routine :

$coderef = sub { print "Boink!\n" };

Notez le point-virgule. Sauf pour le code à l'intérieur qui n'est pas immédiatement exécuté, un "sub {}" n'est pas tant une déclaration qu'un opérateur, comme "do{}" ou "eval{}". (Cependant, peu importe combien de fois vous exécutez cette ligne particulière (sauf si vous êtes dans un eval("...")), $coderef contiendra toujours une référence à la même sous-routine anonyme.)

Les sous-routines anonymes agissent comme des fermetures (closures) par rapport aux variables my(), c'est-à-dire aux variables lexicalement visibles dans le contexte actuel. La fermeture est une notion du monde Lisp qui dit que si vous définissez une fonction anonyme dans un contexte lexical particulier, elle fait semblant de s'exécuter dans ce contexte même lorsqu'elle est appelée en dehors du contexte.

En termes simples, c'est une façon amusante de passer des arguments à une sous-routine lors de sa définition ainsi que lors de son appel. C'est utile pour configurer de petits bouts de code à exécuter plus tard, comme des rappels (callbacks). Vous pouvez même faire des choses orientées objet avec cela, bien que Perl fournisse déjà un mécanisme différent pour le faire -- voir perlobj.

Vous pourriez également considérer la fermeture comme un moyen d'écrire un modèle de sous-routine sans utiliser eval(). Voici un petit exemple sur le fonctionnement des fermetures :

sub newprint {
    my $x = shift;
    return sub { my $y = shift; print "$x, $y!\n"; };
}
$h = newprint("Howdy");
$g = newprint("Greetings");
# Le temps passe...
&$h("world");
&$g("earthlings");

Ceci affiche

Howdy, world!
Greetings, earthlings!

Notez en particulier que $x continue de faire référence à la valeur passée à newprint() malgré que « my $x » soit sorti de portée au moment où la sous-routine anonyme s'exécute. C'est ce qu'est une fermeture.

Cela ne s'applique d'ailleurs qu'aux variables lexicales. Les variables dynamiques continuent de fonctionner comme elles l'ont toujours fait. La fermeture n'est pas quelque chose dont la plupart des programmeurs Perl ont besoin de se soucier pour commencer

Création de Références

Les références sont souvent retournées par des sous-routines spéciales appelées constructeurs. Les objets Perl ne sont que des références à un type spécial d'objet qui sait à quel paquet il est associé. Les constructeurs sont simplement des sous-routines spéciales qui savent comment créer cette association. Ils le font en commençant par une référence ordinaire, et elle reste une référence ordinaire même si elle est aussi un objet. Les constructeurs sont souvent nommés new(). Vous *pouvez* les appeler indirectement :

$objref = new Doggie( Tail => 'short', Ears => 'long' );

Mais cela peut produire une syntaxe ambiguë dans certains cas, il est donc souvent préférable d'utiliser l'approche d'invocation de méthode directe :

$objref   = Doggie->new(Tail => 'short', Ears => 'long');
use Term::Cap;
$terminal = Term::Cap->Tgetent( { OSPEED => 9600 });
use Tk;
$main    = MainWindow->new();
$menubar = $main->Frame(-relief              => "raised",
                        -borderwidth         => 2)

Cette syntaxe d'objet indirecte n'est disponible que lorsque "use feature "indirect"" est activé, ce qui n'est pas le cas lorsque "use v5.36" (ou une version supérieure) est demandé. Il est préférable d'éviter complètement la syntaxe d'objet indirect.

Autovivification

Les références du type approprié peuvent apparaître si vous les déréférencez dans un contexte qui suppose qu'elles existent. Comme nous n'avons pas encore parlé de déréférencement, nous ne pouvons pas vous montrer d'exemples pour le moment.

Slots de Typeglob

Une référence peut être créée en utilisant une syntaxe spéciale, affectueusement connue sous le nom de syntaxe *foo{THING}. *foo{THING} retourne une référence au slot THING dans *foo (qui est l'entrée de la table des symboles qui contient tout ce qui est connu sous le nom de foo).

$scalarref = *foo{SCALAR};
$arrayref  = *ARGV{ARRAY};
$hashref   = *ENV{HASH};
$coderef   = *handler{CODE};
$ioref     = *STDIN{IO};
$globref   = *foo{GLOB};
$formatref = *foo{FORMAT};
$globname  = *foo{NAME};    # "foo"
$pkgname   = *foo{PACKAGE}; # "main"

La plupart de ces éléments s'expliquent d'eux-mêmes, mais *foo{IO} mérite une attention particulière. Il retourne le handle IO, utilisé pour les handles de fichiers ("open" dans perlfunc), les sockets ("socket" dans perlfunc et "socketpair" dans perlfunc), et les handles de répertoires ("opendir" dans perlfunc). Pour la compatibilité avec les versions précédentes de Perl, *foo{FILEHANDLE} est un synonyme de *foo{IO}, bien que cela soit déconseillé, afin d'encourager une utilisation cohérente d'un seul nom : IO. Sur les Perl entre v5.8 et v5.22, cela émettra un avertissement de dépréciation, mais cette dépréciation a depuis été annulée.

*foo{THING} retourne undef si ce THING particulier n'a pas encore été utilisé, sauf dans le cas des scalaires. *foo{SCALAR} retourne une référence à un scalaire anonyme si $foo n'a pas encore été utilisé. Cela pourrait changer dans une future version.

*foo{NAME} et *foo{PACKAGE} sont les exceptions, en ce sens qu'ils retournent des chaînes de caractères, plutôt que des références. Ceux-ci retournent le paquet et le nom du typeglob lui-même, plutôt que celui qui lui a été attribué. Ainsi, après "*foo=*Foo::bar", *foo deviendra "*Foo::bar" lorsqu'il est utilisé comme une chaîne de caractères, mais *foo{PACKAGE} et *foo{NAME} produiront respectivement "main" et "foo".

*foo{IO} est une alternative au mécanisme *HANDLE donné dans "Typeglobs and Filehandles" dans perldata pour passer des handles de fichiers dans ou hors des sous-routines, ou pour stocker dans des structures de données plus grandes. Son inconvénient est qu'il ne crée pas de nouveau handle de fichier pour vous. Son avantage est que vous avez moins de risque d'écraser plus que vous ne le souhaitez avec une affectation de typeglob. (Il confond toujours les handles de fichiers et de répertoires, cependant.) Cependant, si vous attribuez la valeur entrante à un scalaire au lieu d'un typeglob, comme nous le faisons dans les exemples ci-dessous, il n'y a aucun risque que cela se produise.

splutter(*STDOUT);          # passe le glob entier
splutter(*STDOUT{IO});      # passe les handles de fichiers et de répertoires
sub splutter {
    my $fh = shift;
    print $fh "her um well a hmmm\n";
}
$rec = get_rec(*STDIN);     # passe le glob entier
$rec = get_rec(*STDIN{IO}); # passe les handles de fichiers et de répertoires
sub get_rec {
    my $fh = shift;
    return scalar <$fh>;
}

Utilisation des Références

Voilà pour la création de références. À l'heure actuelle, vous mourez probablement d'envie de savoir comment utiliser les références pour retrouver vos données perdues depuis longtemps. Il existe plusieurs méthodes de base.

Scalaire Simple

Partout où vous mettriez un identifiant (ou une chaîne d'identifiants) dans le cadre d'un nom de variable ou de sous-routine, vous pouvez remplacer l'identifiant par une variable scalaire simple contenant une référence du type correct :

$bar = $$scalarref;
push(@$arrayref, $filename);
$$arrayref[0] = "January";
$$hashref{"KEY"} = "VALUE";
&$coderef(1,2,3);
print $globref "output\n";

Il est important de comprendre que nous ne déréférençons *pas* spécifiquement $arrayref[0] ou $hashref{"KEY"} ici. Le déréférencement de la variable scalaire se produit *avant* qu'il ne fasse aucune recherche de clé. Tout ce qui est plus complexe qu'une simple variable scalaire doit utiliser les méthodes 2 ou 3 ci-dessous. Cependant, un "scalaire simple" inclut un identifiant qui utilise lui-même la méthode 1 récursivement. Par conséquent, ce qui suit affiche "howdy".

$refrefref = \\\"howdy";
print $$$$refrefref;

Bloc

Partout où vous mettriez un identifiant (ou une chaîne d'identifiants) dans le cadre d'un nom de variable ou de sous-routine, vous pouvez remplacer l'identifiant par un BLOC retournant une référence du type correct. Autrement dit, les exemples précédents pourraient être écrits comme suit :

$bar = ${$scalarref};
push(@{$arrayref}, $filename);
${$arrayref}[0] = "January";
${$hashref}{"KEY"} = "VALUE";
&{$coderef}(1,2,3);
$globref->print("output\n");  # si IO::Handle est chargé

Certes, il est un peu inutile d'utiliser les accolades dans ce cas, mais le BLOC peut contenir n'importe quelle expression arbitraire, en particulier des expressions indexées :

&{ $dispatch{$index} }(1,2,3);      # appelle la routine correcte

En raison de la possibilité d'omettre les accolades pour le cas simple de $$x, les gens font souvent l'erreur de considérer les symboles de déréférencement comme des opérateurs à part entière et s'interrogent sur leur précédence. S'ils l'étaient, vous pourriez utiliser des parenthèses au lieu des accolades. Ce n'est pas le cas. Considérez la différence ci-dessous ; le cas 0 est une version abrégée du cas 1, *pas* du cas 2 :

$$hashref{"KEY"}   = "VALUE";       # CAS 0
${$hashref}{"KEY"} = "VALUE";       # CAS 1
${$hashref{"KEY"}} = "VALUE";       # CAS 2
${$hashref->{"KEY"}} = "VALUE";     # CAS 3

Le cas 2 est également trompeur en ce sens que vous accédez à une variable appelée %hashref, et non que vous déréférencez via $hashref vers le hash auquel elle fait vraisemblablement référence. Ce serait le cas 3.

Notation Flèche

Les appels de sous-routines et les recherches d'éléments individuels de tableaux surviennent assez souvent pour que l'utilisation de la méthode 2 devienne fastidieuse. En tant que forme de sucre syntaxique, les exemples de la méthode 2 peuvent être écrits :

$arrayref->[0] = "January";   # Élément de tableau
$hashref->{"KEY"} = "VALUE";  # Élément de hash
$coderef->(1,2,3);            # Appel de sous-routine

La partie gauche de la flèche peut être n'importe quelle expression retournant une référence, y compris un déréférencement précédent. Notez que $array[$x] n'est *pas* la même chose que "$array->[$x]" ici :

$array[$x]->{"foo"}->[0] = "January";

C'est l'un des cas que nous avons mentionnés précédemment où les références peuvent apparaître dans un contexte lvalue. Avant cette instruction, $array[$x] pouvait être indéfini. Si c'est le cas, il est automatiquement défini avec une référence de hash afin que nous puissions y rechercher "{"foo"}". De même, "$array[$x]->{"foo"}" sera automatiquement défini avec une référence de tableau afin que nous puissions y rechercher "[0]". Ce processus est appelé *autovivification*.

Encore une chose ici. La flèche est facultative *entre* les indices de crochets, vous pouvez donc réduire ce qui précède à

$array[$x]{"foo"}[0] = "January";

Ce qui, dans le cas dégénéré d'utilisation de tableaux ordinaires uniquement, vous donne des tableaux multidimensionnels tout comme en C :

$score[$x][$y][$z] += 42;

Bon, d'accord, pas tout à fait comme les tableaux de C, en fait. C ne sait pas comment faire grandir ses tableaux sur demande. Perl le fait.

Objets

Si une référence est une référence à un objet, alors il y a probablement des méthodes pour accéder aux choses auxquelles elle fait référence, et vous devriez probablement vous en tenir à ces méthodes, sauf si vous êtes dans le paquet de classe qui définit les méthodes de l'objet. Autrement dit, soyez gentil et ne violez pas l'encapsulation de l'objet sans une très bonne raison. Perl n'applique pas l'encapsulation. Nous ne sommes pas des totalitaires ici. Nous attendons cependant une civilité de base.

Utilisation Diverses

Utiliser une chaîne de caractères ou un nombre comme référence produit une référence symbolique, comme expliqué ci-dessus. Utiliser une référence comme un nombre produit un entier représentant son emplacement de stockage en mémoire. La seule chose utile à faire avec cela est de comparer deux références numériquement pour voir si elles font référence au même emplacement.

if ($ref1 == $ref2) {  # comparaison numérique bon marché des références
    print "les références 1 et 2 font référence à la même chose\n";
}

Utiliser une référence comme une chaîne de caractères produit le type de sa référence, y compris toute bénédiction de paquet comme décrit dans perlobj, ainsi que l'adresse numérique exprimée en hexadécimal. L'opérateur ref() retourne uniquement le type de chose vers lequel la référence pointe, sans l'adresse. Voir "ref" dans perlfunc pour les détails et les exemples de son utilisation.

L'opérateur bless() peut être utilisé pour associer l'objet auquel une référence pointe avec un paquet fonctionnant comme une classe d'objet. Voir perlobj.

Un typeglob peut être déréférencé de la même manière qu'une référence, car la syntaxe de déréférencement indique toujours le type de référence souhaité. Donc "${*foo}" et "${\$foo}" indiquent tous deux la même variable scalaire.

Voici une astuce pour interpoler un appel de sous-routine dans une chaîne de caractères :

print "Mon sous-programme a retourné @{[mysub(1,2,3)]} cette fois-ci.\n";

La façon dont cela fonctionne est que lorsque la "@{...}" est vue dans la chaîne entre guillemets doubles, elle est évaluée comme un bloc. Le bloc crée une référence vers un tableau anonyme contenant les résultats de l'appel à "mysub(1,2,3)". Ainsi, l'ensemble du bloc renvoie une référence vers un tableau, qui est ensuite déréférencée par "@{...}" et insérée dans la chaîne entre guillemets doubles. Cette astuce est également utile pour les expressions arbitraires :

print "Cela donne @{[$n + 5]} articles\n";

De même, une expression qui renvoie une référence vers un scalaire peut être déréférencée via "${...}". Ainsi, l'expression ci-dessus peut être écrite comme suit :

print "Cela donne ${\($n + 5)} articles\n";

Références circulaires

Il est possible de créer une "référence circulaire" en Perl, ce qui peut entraîner des fuites de mémoire. Une référence circulaire se produit lorsque deux références se référencent mutuellement, comme ceci :

my $foo = {};
my $bar = { foo => $foo };
$foo->{bar} = $bar;

Vous pouvez également créer une référence circulaire avec une seule variable :

my $foo;
$foo = \$foo;

Dans ce cas, le nombre de références pour les variables n'atteindra jamais 0, et les références ne seront jamais collectées par le garbage collector. Cela peut entraîner des fuites de mémoire.

Étant donné que les objets en Perl sont implémentés sous forme de références, il est possible d'avoir des références circulaires avec des objets également. Imaginez une classe TreeNode où chaque nœud référence son parent et ses enfants. Tout nœud ayant un parent fera partie d'une référence circulaire.

Vous pouvez briser les références circulaires en créant une "référence faible". Une référence faible n'incrémente pas le compteur de références d'une variable, ce qui signifie que l'objet peut sortir de portée et être détruit. Vous pouvez affaiblir une référence avec la fonction "weaken" exportée par le module Scalar::Util, ou disponible en tant que "builtin::weaken" directement dans Perl version 5.35.7 ou ultérieure.

Voici comment nous pouvons rendre le premier exemple plus sûr :

use Scalar::Util 'weaken';
my $foo = {};
my $bar = { foo => $foo };
$foo->{bar} = $bar;
weaken $foo->{bar};

La référence de $foo vers $bar a été affaiblie. Lorsque la variable $bar sortira de portée, elle sera collectée par le garbage collector. La prochaine fois que vous regarderez la valeur de la clé "$foo->{bar}", ce sera "undef".

Cette action à distance peut être déroutante, vous devez donc faire attention à votre utilisation de `weaken`. Vous devriez affaiblir la référence dans la variable qui sortira de portée *en premier*. De cette façon, la variable qui vivra plus longtemps contiendra la référence attendue jusqu'à ce qu'elle sorte de portée.

Références symboliques

Nous avons dit que les références surgissent lorsque nécessaire si elles sont indéfinies, mais nous n'avons pas dit ce qui se passe si une valeur utilisée comme référence est déjà définie, mais n'en est *pas* une référence matérielle. Si vous l'utilisez comme une référence, elle sera traitée comme une référence symbolique. C'est-à-dire que la valeur du scalaire est considérée comme le *nom* d'une variable, plutôt qu'un lien direct vers une valeur (éventuellement) anonyme.

Beaucoup de gens s'attendent à ce que cela fonctionne ainsi. Donc, cela fonctionne.

$name = "foo";
$$name = 1;                 # Définit $foo
${$name} = 2;               # Définit $foo
${$name x 2} = 3;           # Définit $foofoo
$name->[0] = 4;             # Définit $foo[0]
@$name = ();                # Vide @foo
&$name();                   # Appelle &foo()
$pack = "THAT";
${"${pack}::$name"} = 5;    # Définit $THAT::foo sans eval

C'est puissant, et légèrement dangereux, car il est possible d'avoir l'intention (avec la plus grande sincérité) d'utiliser une référence matérielle, et d'en utiliser accidentellement une symbolique à la place. Pour vous en protéger, vous pouvez dire

use strict 'refs';

et alors seules les références matérielles seront autorisées pour le reste du bloc englobant. Un bloc intérieur peut infirmer cela avec

no strict 'refs';

Seules les variables de package (globales, même si elles sont localisées) sont visibles par les références symboliques. Les variables lexicales (déclarées avec my()) ne sont pas dans une table de symboles, et sont donc invisibles pour ce mécanisme. Par exemple :

local $value = 10;
$ref = "value";
{
    my $value = 20;
    print $$ref;
}

Cela affichera toujours 10, pas 20. Rappelez-vous que local() affecte les variables de package, qui sont toutes "globales" au package.

Références pas si symboliques

Les crochets autour d'une référence symbolique peuvent simplement servir à isoler un identifiant ou un nom de variable du reste d'une expression, comme ils l'ont toujours fait dans une chaîne de caractères. Par exemple,

$push = "pop on ";
print "${push}over";

a toujours signifié d'imprimer "pop on over", même si `push` est un mot réservé. Ceci est généralisé pour fonctionner de la même manière sans les guillemets doubles englobants, de sorte que

print ${push} . "over";

et même

print ${ push } . "over";

auront le même effet. Cette construction n'est *pas* considérée comme une référence symbolique lorsque vous utilisez `strict refs`: 

use strict 'refs';
${ bareword };      # OK, signifie $bareword.
${ "bareword" };    # Erreur, référence symbolique.

De même, en raison de l'indexation effectuée à l'aide de mots uniques, la même règle s'applique à tout mot nu utilisé pour indexer une table de hachage. Ainsi, au lieu d'écrire

$hash{ "aaa" }{ "bbb" }{ "ccc" }

vous pouvez simplement écrire

$hash{ aaa }{ bbb }{ ccc }

et ne pas vous soucier de savoir si les indices sont des mots réservés. Dans le rare cas où vous souhaitez faire quelque chose comme

$hash{ shift }

vous pouvez forcer l'interprétation comme un mot réservé en ajoutant quelque chose qui en fait plus qu'un mot nu :

$hash{ shift() }
$hash{ +shift }
$hash{ shift @_ }

Le pragma "use warnings" ou le commutateur -w vous avertira s'il interprète un mot réservé comme une chaîne. Mais il ne vous avertira plus de l'utilisation de mots en minuscules, car la chaîne est effectivement mise entre guillemets.

Pseudo-tables de hachage : Utilisation d'un tableau comme une table de hachage

Les pseudo-tables de hachage ont été supprimées de Perl. Le pragma `fields` reste disponible.

Modèles de fonctions

Comme expliqué ci-dessus, une fonction anonyme ayant accès aux variables lexicales visibles lors de la compilation de cette fonction crée une fermeture (closure). Elle conserve l'accès à ces variables même si elle n'est exécutée que plus tard, par exemple dans un gestionnaire de signaux ou un rappel Tk.

Utiliser une fermeture comme modèle de fonction permet de générer de nombreuses fonctions qui agissent de manière similaire. Supposons que vous souhaitiez des fonctions nommées d'après les couleurs qui génèrent des changements de police HTML pour les différentes couleurs :

print "Soyez ", red("prudent"), " avec ce ", green("feu");

Les fonctions red() et green() seraient similaires. Pour les créer, nous allons assigner une fermeture à un typeglob du nom de la fonction que nous essayons de construire.

@colors = qw(red blue green yellow orange purple violet);
for my $name (@colors) {
    no strict 'refs';       # autorise la manipulation de la table de symboles
    *$name = *{uc $name} = sub { "<FONT COLOR='$name'>@_</FONT>" };
}

Maintenant, toutes ces fonctions différentes semblent exister indépendamment. Vous pouvez appeler red(), RED(), blue(), BLUE(), green(), etc. Cette technique permet d'économiser à la fois le temps de compilation et l'utilisation de la mémoire, et est également moins sujette aux erreurs, car les vérifications de syntaxe se font au moment de la compilation. Il est essentiel que toutes les variables de la sous-routine anonyme soient lexicales pour créer une fermeture appropriée. C'est la raison du "my" sur la variable d'itération de la boucle.

C'est l'un des rares endroits où donner un prototype à une fermeture a beaucoup de sens. Si vous vouliez imposer un contexte scalaire aux arguments de ces fonctions (probablement pas une bonne idée pour cet exemple particulier), vous auriez pu l'écrire ainsi à la place :

*$name = sub ($) { "<FONT COLOR='$name'>$_[0]</FONT>" };

Cependant, comme la vérification des prototypes se produit au moment de la compilation, l'affectation ci-dessus se produit trop tard pour être très utile. Vous pourriez résoudre ce problème en plaçant toute la boucle d'affectations dans un bloc BEGIN, forçant ainsi son exécution pendant la compilation.

L'accès aux variables lexicales qui changent avec le temps - comme celles de la boucle "for" ci-dessus, essentiellement des alias vers des éléments des portées lexicales environnantes - ne fonctionne qu'avec les sous-routines anonymes, pas avec les sous-routines nommées. En général, les sous-routines nommées ne s'imbriquent pas correctement et ne devraient être déclarées que dans la portée principale du package.

C'est parce que les sous-routines nommées sont créées au moment de la compilation, de sorte que leurs variables lexicales sont assignées aux variables lexicales parentes de la première exécution du bloc parent. Si une portée parente est entrée une seconde fois, ses variables lexicales sont recréées, tandis que les sous-routines imbriquées référencent toujours les anciennes.

Les sous-routines anonymes capturent à chaque fois que vous exécutez l'opérateur "sub", car elles sont créées à la volée. Si vous êtes habitué à utiliser des sous-routines imbriquées dans d'autres langages de programmation avec leurs propres variables privées, vous devrez y travailler un peu en Perl. Le codage intuitif de ce type de choses entraîne des avertissements mystérieux sur "ne restera pas partagé" en raison des raisons expliquées ci-dessus. Par exemple, ceci ne fonctionnera pas :

sub outer {
    my $x = $_[0] + 35;
    sub inner { return $x * 19 }   # FAUX
    return $x + inner();
}

Une solution de contournement est la suivante :

sub outer {
    my $x = $_[0] + 35;
    local *inner = sub { return $x * 19 };
    return $x + inner();
}

Maintenant, inner() ne peut être appelé que depuis l'intérieur de outer(), en raison des affectations temporaires de la sous-routine anonyme. Mais lorsqu'elle le fait, elle a un accès normal à la variable lexicale $x de la portée de outer() au moment où outer

NAME

perlref - Perl references and symbolic references

NOTE

This document refers to Perl version 5.42.0.

DESCRIPTION

A reference is a scalar value that points to some other data (or subroutine). A reference can be thought of as an address or a pointer to the data. You can't directly manipulate the data through the reference; you have to dereference the reference first.

References are created using the backslash operator:

\$foo
\@array
\%hash
\&subroutine
\sub { print "hello" }
\my $scalar
\my @array
\my %hash
\state $scalar
\state @array
\state %hash
\our $scalar
\our @array
\our %hash
\local $scalar
\local @array
\local %hash

The optional "my", "state", "our", or "local" specifies that the reference should be to a lexical variable, a state variable, an our variable, or a special variable, respectively.

If the sigil is followed by parentheses, it refers to the whole structure, not to an individual element:

\(@array)
\(%hash)

Dereferencing is done using the same sigils, but prefixed to the reference variable:

$aref = \@a;
@b = @$aref;  # same as @b = @a

$href = \%h;
%g = %$href;  # same as %g = %h

$sref = \$x;
$y = $$sref;  # same as $y = $x

You can also dereference directly:

push @{$aref}, 5;         # same as push @a, 5
$href->{key} = $value;   # same as $href->{key} = $value
print $$sref;            # same as print $x

The syntax "$href->{key}" is the same as "$href->{key}" (and so on for arrays, subroutines, etc.) is preferred when the reference is not the only thing on the left-hand side of the arrow.

For example, a reference to an array element:

$aref = \$a[3];
print $$aref;            # prints $a[3]

Or a reference to a hash element:

$href = \$h{key};
$$href = 'value';      # same as $h{key} = 'value'

A reference to a subroutine:

$subref = \&time;
@timer = $subref->(1, 2, 3); # same as @timer = time(1, 2, 3)

You can also create an anonymous subroutine reference:

$anon_sub = sub {
    my ($arg1, $arg2) = @_;
    return $arg1 + $arg2;
};
print $anon_sub->(5, 6); # prints 11

And an anonymous array reference:

$anon_aref = [ 1, 2, [ 3, 4 ] ];
print $anon_aref->[1];      # prints 2
print $anon_aref->[2]->[0]; # prints 3

And an anonymous hash reference:

$anon_href = {
    name => "fred",
    age  => 42,
};
print $anon_href->{age}; # prints 42


Note that array and hash constructors ([]
    and {}) create anonymous arrays and hashes, and the
    reference operator \ creates a reference to them.




Autoderef


In Perl, if you try to use a method call on something that
    looks like a plain scalar variable, but is actually a reference to an
    object, Perl will automatically dereference it for you.


package MyClass;
sub new { bless {}, shift }
sub foo { "bar" }

package main;
my $obj = MyClass->new;
print $obj->foo; # Autodereferencing happens here


This behaviour is not affected by whether the variable is lexically
    scoped or not. However, it does not work for plain references to arrays,
    hashes, or scalars.






Symbolic References


A symbolic reference is a scalar variable containing the name of
    another variable (or a reference to it). When Perl encounters a symbolic
    reference, it treats it as if you had used the name directly. This is generally
    considered poor practice, as it makes code harder to read and debug.


$name = "x";
$$name = 10;        # same as $x = 10
$aref = \@a;
$name = "aref";
@b = $$name;       # same as @b = @aref


Symbolic references are often used with "eval",
    though this is generally discouraged.


$varname = 'my_variable';
eval "\$$varname = 5;"; # same as $my_variable = 5;


Symbolic references are deprecated in favour of actual references.
    The main reason for this is that symbolic references prevent Perl from doing
    many of its optimizations, and they can be confusing to read.


If you need to refer to a lexical variable symbolically, you must
    use "eval", because the symbol table is
    not directly accessible for lexicals.


my $var = 10;
my $varname = 'var';
eval "\$$varname = 20;"; # works
print $var;              # prints 20


But this has the interesting effect of creating a function local to
    another function, something not normally supported in Perl.






Postfix   Dereference Syntax


Beginning in v5.20.0, a postfix syntax for using references is
    available. It behaves as described in "Using References", but
    instead of a prefixed sigil, a postfixed sigil-and-star is used.


For example:


$r = \@a;
@b = $r->@*; # equivalent to @$r or @{ $r }
$r = [ 1, [ 2, 3 ], 4 ];
$r->[1]->@*;  # equivalent to @{ $r->[1] }
$aref->@* = (1, 2, 3);  # same as @{ $aref } = (1, 2, 3)


In Perl 5.20 and 5.22, this syntax must be enabled with
    use feature 'postderef'. As
    of Perl 5.24, no feature declarations are required to make it available.


Postfix dereference should work in all circumstances where block
    (circumfix) dereference worked, and should be entirely equivalent. This
    syntax allows dereferencing to be written and read entirely left-to-right.
    The following equivalencies are defined:


$sref->$*;  # same as  ${ $sref }
$aref->@*;  # same as  @{ $aref }
$aref->$#*; # same as $#{ $aref }
$href->%*;  # same as  %{ $href }
$cref->&*;  # same as  &{ $cref }
$gref->**;  # same as  *{ $gref }


Note especially that
    "$cref->&*" is not
    equivalent to $cref->(), and can serve different
    purposes.


Glob elements can be extracted through the postfix dereferencing
    feature:


$gref->*{SCALAR}; # same as *{ $gref }{SCALAR}


Postfix array and scalar dereferencing can be used in
    interpolating strings (double quotes or the
    "qq" operator), but only if the
    "postderef_qq" feature is enabled.
    Interpolation of postfix array highest index access
    ("->$#*") is also supported when the
    "postderef_qq" feature is enabled.






Postfix   Reference Slicing


Value slices of arrays and hashes may also be taken with postfix
    dereferencing notation, with the following equivalencies:


$aref->@[ ... ];  # same as @$aref[ ... ]
$href->@{ ... };  # same as @$href{ ... }


Postfix key/value pair slicing, added in 5.20.0 and documented in
    the Key/Value Hash Slices section of perldata, also behaves as expected:


$aref->%[ ... ];  # same as %$aref[ ... ]
$href->%{ ... };  # same as %$href{ ... }


As with postfix array, postfix value slice dereferencing
    can be used in interpolating strings (double quotes or the
    "qq" operator), but only if the
    "postderef_qq" feature is enabled.






Assigning   to References


Beginning in v5.22.0, the referencing operator can be assigned to.
    It performs an aliasing operation, so that the variable name referenced on
    the left-hand side becomes an alias for the thing referenced on the
    right-hand side:


\$x = \$y; # $x and $y now point to the same scalar
\&foo = \&bar; # foo() now means bar()


This syntax must be enabled with "use
    feature 'refaliasing'". It is experimental, and will warn by
    default unless no warnings
    'experimental::refaliasing' is in effect.


These forms may be assigned to, and cause the right-hand side to
    be evaluated in scalar context:


\$scalar
\@array
\%hash
\&sub
\my $scalar
\my @array
\my %hash
\state $scalar # or @array, etc.
\our $scalar   # etc.
\local $scalar # etc.
\local our $scalar # etc.
\$some_array[$index]
\$some_hash{$key}
\local $some_array[$index]
\local $some_hash{$key}
condition ? \$this : \$that[0] # etc.


Slicing operations and parentheses cause the right-hand side to be
    evaluated in list context:


\@array[5..7]
(\@array[5..7])
\(@array[5..7])
\@hash{'foo','bar'}
(\@hash{'foo','bar'})
\(@hash{'foo','bar'})
(\$scalar)
\($scalar)
\(my $scalar)
\my($scalar)
(\@array)
(\%hash)
(\&sub)
\(&sub)
\($foo, @bar, %baz)
(\$foo, \@bar, \%baz)


Each element on the right-hand side must be a reference to a datum
    of the right type. Parentheses immediately surrounding an array (and
    possibly also
    "my"/"state"/"our"/"local")
    will make each element of the array an alias to the corresponding scalar
    referenced on the right-hand side:


\(@x) = \(@y); # @x and @y now have the same elements
\my(@x) = \(@y); # likewise
\(my @x) = \(@y); # likewise
push @x, 3; # but now @x has an extra element that @y lacks
\(@x) = (\$x, \$y, \$z); # @x now contains $x, $y, and $z


Combining that form with "local"
    and putting parentheses immediately around a hash are forbidden (because it
    is not clear what they should do):


\local(@array) = foo(); # WRONG
\(%hash)       = bar(); # WRONG


Assignment to references and non-references may be combined in
    lists and conditional ternary expressions, as long as the values on the
    right-hand side are the right type for each element on the left, though this
    may make for obfuscated code:


(my $tom, \my $dick, \my @harry) = (\1, \2, [1..3]);
# $tom is now \1
# $dick is now 2 (read-only)
# @harry is (1,2,3)
my $type = ref $thingy;
($type ? $type eq 'ARRAY' ? \@foo : \$bar : $baz) = $thingy;


A reference assignment in list context returns a list of
    references to each left-hand value. So for example


@b = ((\$l1, \$l2, \(@a)) = (\$r1, \$r2, $\r3, \$4));


is equivalent to


(\$l1, \$l2, \(@a)) = (\$r1, \$r2, $\r3, \$4);
@b = (\$l1, \$l2, \$a[0], \$a[1]);


The "foreach" loop can also take
    a reference constructor for its loop variable, though the syntax is limited
    to one of the following, with an optional
    "my",
    "state", or
    "our" after the backslash:


\$s
\@a
\%h
\&c


No parentheses are permitted. This feature is particularly useful
    for arrays-of-arrays, or arrays-of-hashes:


foreach \my @a (@array_of_arrays) {
    frobnicate($a[0], $a[-1]);
}
foreach \my %h (@array_of_hashes) {
    $h{gelastic}++ if $h{type} eq 'funny';
}


CAVEAT: Aliasing does not work correctly with closures. If
    you try to alias lexical variables from an inner subroutine or
    "eval", the aliasing will only be visible
    within that inner sub, and will not affect the outer subroutine where the
    variables are declared. This bizarre behavior is subject to change.






Declaring   a Reference to a Variable


Beginning in v5.26.0, the referencing operator can come after
    "my",
    "state",
    "our", or
    "local". This syntax must be enabled with
    "use feature
    'declared_refs'". It is experimental, and will warn by default
    unless "no warnings
    'experimental::refaliasing'" is in effect.


This feature makes these:


my \$x;
our \$y;


equivalent to:


\my $x;
\our $x;


It is intended mainly for use in assignments to references (see
    "Assigning to References", above). It also allows the backslash to
    be used on just some items in a list of declared variables:


my ($foo, \@bar, \%baz); # equivalent to:  my $foo, \my(@bar, %baz);

WARNING: Don't use references as hash keys

You may not (usefully) use a reference as the key to a hash. It will be converted into a string:

$x{ \$x } = $x;

If you try to dereference the key, it won't do a hard dereference, and you won't accomplish what you're attempting. You might want to do something more like

$r = \@a;
$x{ $r } = $r;

And then at least you can use the values(), which will be real refs, instead of the keys(), which won't.

The standard Tie::RefHash module provides a convenient workaround to this.
