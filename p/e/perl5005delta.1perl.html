PERL5005DELTA(1perl) Guide du programmeur Perl PERL5005DELTA(1perl)

NOM

perl5005delta - nouveautés pour perl5.005

DESCRIPTION

Ce document décrit les différences entre la version 5.004 et celle-ci.

À propos du nouveau système de versionnement

Perl est maintenant développé sur deux pistes : une piste de maintenance qui apporte de petites mises à jour sécurisées aux versions de production publiées, en mettant l'accent sur la compatibilité ; et une piste de développement qui poursuit une évolution plus agressive. Les versions de maintenance (qui devraient être considérées comme de qualité production) ont des numéros de sous-version allant de 1 à 49, et les versions de développement (qui devraient être considérées comme de qualité "alpha") vont de 50 à 99.

Perl 5.005 est le produit combiné du nouveau schéma de développement à double piste.

Changements incompatibles

AVERTISSEMENT : Cette version n’est pas compatible binairement avec Perl 5.004

À partir de Perl 5.004_50, de nombreux changements profonds et de grande portée ont été apportés aux internes du langage. Si vous avez des extensions chargées dynamiquement que vous avez compilées sous perl 5.003 ou 5.004, vous pouvez continuer à les utiliser avec 5.004, mais vous devrez reconstruire et réinstaller ces extensions pour les utiliser avec 5.005. Voir INSTALL pour des instructions détaillées sur la manière de mettre à niveau.

La structure d’installation par défaut a changé

Les nouveaux paramètres par défaut de Configure sont conçus pour permettre une mise à niveau en douceur de 5.004 à 5.005, mais vous devriez lire INSTALL pour une discussion détaillée des changements afin de les adapter à votre système.

Compatibilité source Perl

Lorsque aucune des fonctionnalités expérimentales n'est activée, il devrait y avoir très peu de problèmes de compatibilité source Perl visibles par l'utilisateur.

Si les threads sont activés, certaines mises en garde s'appliquent. @_ et $_ deviennent des variables lexicales. L'effet de cela devrait être largement transparent pour l'utilisateur, mais il existe certaines conditions limites pour lesquelles l'utilisateur devra être conscient des problèmes. Par exemple, local(@_) entraîne un message "Can't localize lexical variable @_ ...". Cela pourrait être activé dans une future version.

Certains nouveaux mots-clés ont été introduits. On s'attend généralement à ce qu'ils aient très peu d'impact sur la compatibilité. Voir "Nouveau mot-clé "INIT"", "Nouveau mot-clé "lock"" et "Nouvel opérateur "qr//"".

Certains barewords sont maintenant réservés. Leur utilisation provoquera un avertissement si vous les avez demandés avec le commutateur "-w". Voir ""our" est maintenant un mot réservé".

Compatibilité source C

Un grand nombre de changements ont été apportés aux internes pour prendre en charge les nouvelles fonctionnalités de cette version.

  • Les sources du cœur exigent maintenant un compilateur C ANSI

    Un compilateur C ANSI est maintenant requis pour compiler perl. Voir INSTALL.

  • Toutes les variables globales Perl doivent maintenant être référencées avec un préfixe explicite

    Toutes les variables globales Perl qui sont visibles pour une utilisation par les extensions ont maintenant un préfixe "PL_". Les nouvelles extensions "ne" devraient "pas" référencer les variables globales Perl par leurs noms sans préfixe. Pour préserver la cohérence, nous fournissons une compatibilité descendante limitée pour les globales largement utilisées comme "sv_undef" et "na" (qui devraient maintenant s'écrire "PL_sv_undef", "PL_na", etc.)

    Si vous constatez que votre extension XS ne compile plus car une variable globale Perl n'est pas visible, essayez d'ajouter un préfixe "PL_" à la variable globale et reconstruisez.

    Il est fortement recommandé que toutes les fonctions de l'API Perl qui ne commencent pas par "perl" soient référencées avec un préfixe "Perl_". Les noms de fonctions bruts sans le préfixe "Perl_" sont pris en charge par des macros, mais cette prise en charge pourrait cesser dans une future version.

    Voir perlapi.

  • L'activation des threads présente des problèmes de compatibilité source

    Perl compilé avec le threading activé nécessite que les extensions utilisent la nouvelle macro "dTHR" pour initialiser le descripteur d'accès aux données par thread. Si vous voyez une erreur de compilation parlant de la variable "thr" non déclarée (lors de la compilation d'un module ayant du code XS), vous devez ajouter "dTHR;" au début du bloc qui a suscité l'erreur.

    La fonction d'API "perl_get_sv("@",GV_ADD)" doit être utilisée à la place de l'accès direct aux variables globales Perl comme GvSV(errgv). L'appel d'API est rétrocompatible avec les Perl existants et assure la compatibilité source lorsque le threading est activé.

    Voir "Compatibilité source C" pour plus d'informations.

Compatibilité binaire

Cette version N'EST PAS compatible binairement avec les versions antérieures. Toutes les extensions devront être recompilées. De plus, les binaires construits avec le support des threads activé sont incompatibles avec ceux construits sans. Cela devrait être largement transparent pour l'utilisateur, car toutes les configurations binaires incompatibles ont leur propre nom d'architecture unique, et les binaires d'extensions sont installés à des emplacements uniques. Cela permet la coexistence de plusieurs configurations dans la même hiérarchie de répertoires. Voir INSTALL.

Les corrections de sécurité peuvent affecter la compatibilité

Quelques fuites et omissions de taint ont été corrigées. Cela peut entraîner l'"échec" de scripts qui fonctionnaient auparavant avec des versions plus anciennes. La compilation avec -DINCOMPLETE_TAINTS fournit un perl avec un minimum de changements au comportement du taint. Mais notez que le perl résultant aura des insécurités connues.

Les oneliners avec le commutateur "-e" ne créent plus de fichiers temporaires.

Les nouvelles avertissements obligatoires introduits en 5.004 ont été assouplis

De nombreux nouveaux avertissements introduits en 5.004 ont été rendus optionnels. Certains de ces avertissements sont toujours présents, mais les nouvelles fonctionnalités de perl les rendent moins problématiques. Voir "Nouveaux diagnostics".

Licence

Perl a un nouveau Contrat Social pour les contributeurs. Voir Porting/Contract.

La licence incluse dans une grande partie de la documentation Perl a changé. La plupart de la documentation Perl était auparavant sous la licence GNU General Public License implicite ou sous la Licence Artistique (au choix de l'utilisateur). Désormais, une grande partie de la documentation indique sans ambiguïté les conditions selon lesquelles elle peut être distribuée. Ces conditions sont en général beaucoup moins restrictives que la GNU GPL. Voir perl et les manpages perl individuelles qui y sont listées.

Compilateur

ATTENTION : Le compilateur et les outils associés sont considérés comme expérimentaux. Les fonctionnalités peuvent changer sans préavis, et il existe des limitations et des bugs connus. Comme le compilateur est entièrement externe à perl, la configuration par défaut le compilera et l'installera.

Le compilateur produit trois types de transformations d'un programme perl. Le backend C génère du code C qui capture l'état de perl juste avant le début de l'exécution. Il élimine les surcoûts de compilation de l'interpréteur perl régulier, mais les performances d'exécution restent relativement les mêmes. Le backend CC génère du code C optimisé équivalent au chemin de code au moment de l'exécution. Le backend CC a un plus grand potentiel pour de grosses optimisations, mais seules quelques optimisations sont actuellement implémentées. Le backend Bytecode génère une représentation bytecode indépendante de la plateforme de l'état de l'interpréteur juste avant l'exécution. Ainsi, le backend Bytecode élimine également une grande partie des surcoûts de compilation de l'interpréteur.

Le compilateur est livré avec plusieurs utilitaires précieux.

"B::Lint" est un module expérimental pour détecter et signaler le code suspect, en particulier les cas que le commutateur "-w" ne détecte pas.

"B::Deparse" peut être utilisé pour démystifier le code perl, et comprendre comment perl optimise certaines constructions.

"B::Xref" génère des rapports de références croisées de toutes les définitions et utilisations de variables, sous-routines et formats dans un programme.

"B::Showlex" affiche en un coup d'œil les variables lexicales utilisées par une sous-routine ou un fichier.

"perlcc" est un simple frontend pour compiler perl.

Voir "ext/B/README", B, et les modules de compilateur respectifs.

Amélioration de malloc()

Voir la bannière au début de "malloc.c" pour les détails.

Quicksort est implémenté en interne

Perl contient maintenant sa propre routine qsort() hautement optimisée. Le nouveau qsort() est résistant aux fonctions de comparaison incohérentes, de sorte que sort() de Perl ne provoquera plus de coredumps lorsqu'il recevra des sous-routines de tri mal écrites. (Certains qsort() de bibliothèques C qui étaient utilisés auparavant avaient ce problème.) Dans nos tests, le nouveau qsort() a nécessité le nombre minimal de comparaisons par paires en moyenne, parmi toutes les implémentations connues de qsort().

Voir "perlfunc/sort".

Signaux fiables

La gestion des signaux de Perl est susceptible de provoquer des plantages aléatoires, car les signaux arrivent de manière asynchrone et le runtime Perl n'est pas réentrant à des moments arbitraires.

Cependant, une implémentation expérimentale de signaux fiables est disponible lorsque les threads sont activés. Voir "Thread::Signal". Voir également INSTALL pour savoir comment compiler un Perl capable de threads.

Pointeurs de pile fiables

Les internes réallouent maintenant la pile perl uniquement à des moments prévisibles. En particulier, les appels magiques ne déclenchent jamais de réallocations de la pile, car toute la réentrance du runtime est gérée à l'aide d'une "pile de piles". Cela devrait améliorer la fiabilité des pointeurs de pile mis en cache dans les internes et dans les XSUBs.

Traitement plus généreux des retours chariot

Perl se plaignait auparavant s'il rencontrait des retours chariot littéraux dans les scripts. Maintenant, ils sont principalement traités comme des espaces blancs dans le texte du programme. À l'intérieur des littéraux de chaînes et des here documents, les retours chariot littéraux sont ignorés s'ils sont associés à des sauts de ligne, ou interprétés comme des espaces blancs s'ils apparaissent seuls. Ce comportement signifie que les retours chariot littéraux dans les fichiers doivent être évités. Vous pouvez obtenir le comportement plus ancien, plus compatible (mais moins généreux) en définissant le symbole préprocesseur "PERL_STRICT_CR" lors de la compilation de perl. Bien sûr, tout cela n'a rien à voir avec la manière dont les échappements comme "\r" sont gérés dans les chaînes.

Notez que cela ne vous permet pas magiquement de conserver tous les fichiers texte au format DOS. Le traitement généreux ne s'applique qu'aux fichiers que perl lui-même analyse. Si votre compilateur C n'autorise pas les retours chariot dans les fichiers, vous pourriez toujours ne pas être en mesure de compiler des modules qui nécessitent un compilateur C.

Fuites de mémoire

"substr", "pos" et "vec" ne fuient plus de mémoire lorsqu'ils sont utilisés dans un contexte lvalue. De nombreuses petites fuites qui affectaient les applications intégrant plusieurs interpréteurs ont été corrigées.

Meilleur support pour les interprètes multiples

L'option de compilation "-DMULTIPLICITY" a fait l'objet de nombreux ajustements. Certaines variables précédemment globales qui auraient dû être par interpréteur le sont maintenant. Avec précaution, cela permet aux interpréteurs de s'appeler mutuellement. Voir l'extension "PerlInterp" sur CPAN.

Le comportement de local() sur les éléments de tableaux et de hashes est maintenant bien défini

Voir "Valeurs temporaires via local()" dans perlsub.

"%!_" est transparentement lié au module Errno

Voir perlvar, et Errno.

Les pseudo-hashes sont supportés

Voir perlref.

"EXPR foreach EXPR" est supporté

Voir perlsyn.

Les mots clés peuvent être globalement remplacés

Voir perlsub.

$^E est significatif sur Win32

Voir perlvar.

"foreach (1..1000000)" optimisé

"foreach (1..1000000)" est maintenant optimisé en une boucle de comptage. Il n'essaie plus d'allouer une liste de 1000000 éléments.

"Foo::" peut être utilisé pour référencer des sous-programmes

Voir perlfunc.

"Foo::" peut être utilisé comme nom de paquet entre guillemets implicites

Les mots nus provoquaient un comportement imprévisible lorsqu'une sous-routine portant le même nom qu'un paquet était définie. Ainsi, "new Foo @args" utilise le résultat de l'appel à Foo() au lieu de traiter "Foo" comme une chaîne littérale. La façon recommandée d'écrire des mots nus dans la position de l'objet indirect est "new Foo:: @args". Notez que la méthode new() est appelée avec un premier argument de "Foo", et non de "Foo::" lorsque vous faites cela.

"exists $Foo::{Bar::}" teste l'existence d'un paquet

Il était impossible de tester l'existence d'un paquet sans le créer réellement au préalable. Désormais, "exists $Foo::{Bar::}" peut être utilisé pour vérifier si l'espace de noms "Foo::Bar" a été créé.

Meilleur support des locales

Voir perllocale.

Support expérimental pour les plateformes 64 bits

Perl5 a toujours eu un support 64 bits sur les systèmes disposant de `long` 64 bits. À partir de la version 5.005, les débuts d'un support expérimental pour les systèmes avec des entiers `long` 32 bits et `long long` 64 bits ont été ajoutés. Si vous ajoutez -DUSE_LONG_LONG à vos `ccflags` dans `config.sh` (ou le définissez manuellement dans `perl.h`), Perl sera compilé avec le support `long long`. Il y aura de nombreux avertissements du compilateur, et le Perl résultant pourrait ne pas fonctionner sur tous les systèmes. Il existe de nombreux autres problèmes liés aux extensions et bibliothèques tierces. Cette option existe pour permettre aux utilisateurs de travailler sur ces problèmes.

prototype() renvoie des résultats utiles sur les fonctions intégrées

Voir "prototype" dans perlfunc.

Support étendu pour la gestion des exceptions

die() accepte désormais une valeur de référence, et $@ est défini sur cette valeur dans les pièges d'exception. Cela permet de propager des objets d'exception. Il s'agit d'une fonctionnalité **expérimentale** non documentée.

Le ré-enrobage dans DESTROY() est supporté pour l'enchaînement des méthodes DESTROY()

Voir "Destructors" dans perlobj.

Toutes les conversions de format "printf" sont gérées en interne

Voir "printf" dans perlfunc.

Nouveau mot clé "INIT"

Les sous-routines "INIT" sont similaires à "BEGIN" et "END", mais elles sont exécutées juste avant le début de l'exécution du runtime Perl. Par exemple, le compilateur Perl utilise les blocs "INIT" pour initialiser et résoudre les pointeurs vers les XSUBs.

Nouveau mot clé "lock"

Le mot clé "lock" est le primitive de synchronisation fondamentale dans le Perl multi-threadé. Lorsque les threads ne sont pas activés, il est actuellement inopérant (no-op).

Pour minimiser l'impact sur la compatibilité des sources, ce mot clé est "faible", c'est-à-dire que toute sous-routine définie par l'utilisateur portant le même nom le remplace, à moins qu'un "use Thread" n'ait été rencontré.

Nouvel opérateur "qr//"

L'opérateur "qr//", dont la syntaxe est similaire aux autres opérateurs de guillemets, est utilisé pour créer des expressions régulières précompilées. Cette forme compilée peut maintenant être explicitement transmise dans des variables et interpolée dans d'autres expressions régulières. Voir perlop.

"our" est maintenant un mot réservé

Appeler une sous-routine nommée "our" provoquera désormais un avertissement lorsque le commutateur "-w" est utilisé.

Les tableaux liés sont maintenant entièrement supportés

Voir Tie::Array.

Le support des poignées liées est amélioré

Plusieurs crochets manquants ont été ajoutés. Il existe également une nouvelle classe de base pour les implémentations TIEARRAY. Voir Tie::Array.

4ème argument pour substr

substr() peut maintenant à la fois renvoyer et remplacer en une seule opération. Le 4ème argument optionnel est la chaîne de remplacement. Voir "substr" dans perlfunc.

Argument LENGTH négatif pour splice

splice() avec un argument LENGTH négatif fonctionne maintenant de manière similaire à ce que faisait LENGTH pour substr(). Auparavant, un LENGTH négatif était traité comme 0. Voir "splice" dans perlfunc.

Les lvalues magiques sont maintenant plus magiques

Lorsque vous écrivez quelque chose comme "substr($x, 5) = "hi"", le scalaire renvoyé par substr() est spécial, en ce sens que toute modification qui lui est apportée affecte $x. (Ceci est appelé une 'lvalue magique' car une 'lvalue' est quelque chose qui se trouve du côté gauche d'une assignation.) Normalement, c'est exactement ce à quoi vous vous attendriez, mais Perl utilise la même magie si vous utilisez substr(), pos(), ou vec() dans un contexte où ils pourraient être modifiés, comme prendre une référence avec "\" ou en tant qu'argument d'une sous-routine qui modifie @_. Dans les versions précédentes, cette 'magie' n'allait que dans un sens, mais maintenant les changements apportés au scalaire auquel la magie fait référence ( $x dans l'exemple ci-dessus) affectent également la lvalue magique. Par exemple, le code suivant agit maintenant différemment :

$x = "hello";
sub printit {
    $x = "g'bye";
    print $_[0], "\n";
}
printit(substr($x, 0, 5));

Dans les versions précédentes, cela imprimerait "hello", mais cela imprime maintenant "g'bye".

<> lit maintenant en enregistrements

Si $/ est une référence à un entier, ou un scalaire contenant un entier, <> lira des enregistrements au lieu de lignes. Pour plus d'informations, voir "$/" dans perlvar.

"h2ph" et les utilitaires associés ont été considérablement remaniés.

L'émulateur de script "configure" brut de GNU s'appelle maintenant "configure.gnu" pour éviter d'écraser "Configure" sur les systèmes de fichiers insensibles à la casse.

"perldoc" était autrefois plutôt lent. Les fonctionnalités les plus lentes sont maintenant optionnelles. En particulier, les recherches insensibles à la casse nécessitent le commutateur "-i", et les recherches récursives nécessitent "-r". Vous pouvez définir ces commutateurs dans la variable d'environnement "PERLDOC" pour retrouver le comportement précédent.

Modifications de la documentation

Config.pm a maintenant un glossaire de variables.

Porting/patching.pod contient des instructions détaillées sur la façon de créer et de soumettre des patchs pour perl.

perlport spécifie les directives sur la façon d'écrire de manière portable.

perlmodinstall décrit comment récupérer et installer des modules depuis les sites "CPAN".

Quelques pièges Perl supplémentaires sont maintenant documentés. Voir perltrap.

perlopentut donne un tutoriel sur l'utilisation de open().

perlreftut donne un tutoriel sur les références.

perlthrtut donne un tutoriel sur les threads.

Nouveaux diagnostics

Appel ambigu résolu comme CORE::%s(), qualifiez-le ainsi ou utilisez &
(W) Une sous-routine que vous avez déclarée a le même nom qu'un mot-clé Perl, et vous avez utilisé le nom sans qualification pour appeler l'un ou l'autre. Perl a décidé d'appeler la fonction intégrée car la sous-routine n'est pas importée.

Pour forcer l'interprétation comme un appel de sous-routine, ajoutez une esperluette avant le nom de la sous-routine, ou qualifiez le nom avec son paquet. Alternativement, vous pouvez importer la sous-routine (ou prétendre qu'elle est importée avec le pragma "use subs").

Pour l'interpréter silencieusement comme l'opérateur Perl, utilisez le préfixe "CORE::" sur l'opérateur (par exemple, CORE::log($x)) ou en déclarant la sous-routine comme une méthode d'objet (voir "attrs").

Indice invalide lors de la coercition d'un tableau en hash
(F) L'indice recherché dans le hash trouvé à l'élément 0 d'un pseudo-hash n'est pas valide. Les valeurs d'indice doivent être à partir de 1. Voir perlref.
Mot nu "%s" fait référence à un paquet inexistant
(W) Vous avez utilisé un mot nu qualifié de la forme "Foo::", mais le compilateur n'a vu aucune autre utilisation de cet espace de noms avant ce point. Peut-être devez-vous prédéclarer un paquet ?
Impossible d'appeler la méthode "%s" sur une valeur indéfinie
(F) Vous avez utilisé la syntaxe d'un appel de méthode, mais l'emplacement occupé par la référence d'objet ou le nom du paquet contient une valeur indéfinie. Quelque chose comme ceci reproduira l'erreur : 
$MAUVAISE_REF = 42;
process $MAUVAISE_REF 1,2,3;
$MAUVAISE_REF->process(1,2,3);
Impossible de vérifier le système de fichiers du script "%s" pour nosuid
(P) Pour une raison quelconque, vous ne pouvez pas vérifier le système de fichiers du script pour nosuid.
Impossible de convertir un tableau en hash
(F) Vous avez utilisé un tableau là où un hash était attendu, mais le tableau n'a aucune information sur la façon de mapper des clés aux indices du tableau. Vous ne pouvez le faire qu'avec des tableaux qui ont une référence de hash à l'indice 0.
Impossible d'aller à la sous-routine depuis une chaîne eval
(F) L'appel "goto subroutine" ne peut pas être utilisé pour sortir d'une chaîne eval. (Vous pouvez l'utiliser pour sortir d'un bloc eval {}, mais vous ne voudrez probablement pas le faire.)
Impossible de localiser un élément de pseudo-hash
(F) Vous avez dit quelque chose comme "local $ar->{'key'}", où $ar est une référence à un pseudo-hash. Cela n'a pas encore été implémenté, mais vous pouvez obtenir un effet similaire en localisant directement l'élément de tableau correspondant : "local $ar->[$ar->[0]{'key'}]".
Impossible d'utiliser %%! car Errno.pm n'est pas disponible
(F) La première fois que le hash %! est utilisé, perl charge automatiquement le module Errno.pm. Le module Errno est censé "lier" le hash %! pour fournir des noms symboliques pour les valeurs d'errno $!.
Impossible de trouver un numéro d'opération pour "%s"
(F) Une chaîne de la forme "CORE::mot" a été donnée à prototype(), mais il n'y a pas de fonction intégrée portant le nom "mot".
Syntaxe de classe de caractères [. .] réservée pour extensions futures
(W) Dans les classes de caractères d'expressions régulières ([]), la syntaxe commençant par "[." et se terminant par ".]" est réservée pour les extensions futures. Si vous devez représenter ces séquences de caractères à l'intérieur d'une classe de caractères d'expression régulière, citez simplement les crochets avec une barre oblique inverse : "\[." et ".\]".
Syntaxe de classe de caractères [: :] réservée pour extensions futures
(W) Dans les classes de caractères d'expressions régulières ([]), la syntaxe commençant par "[:" et se terminant par ":]" est réservée pour les extensions futures. Si vous devez représenter ces séquences de caractères à l'intérieur d'une classe de caractères d'expression régulière, citez simplement les crochets avec une barre oblique inverse : "\[:" et ":\]".
Syntaxe de classe de caractères [= =] réservée pour extensions futures
(W) Dans les classes de caractères d'expressions régulières ([]), la syntaxe commençant par "[=" et se terminant par "=]" est réservée pour les extensions futures. Si vous devez représenter ces séquences de caractères à l'intérieur d'une classe de caractères d'expression régulière, citez simplement les crochets avec une barre oblique inverse : "\[=" et "=\]".
%s: Groupe Eval dans une expression régulière non sécurisée
(F) Perl a détecté des données "tainted" lors de la compilation d'une expression régulière contenant l'assertion de largeur nulle "(?{ ... })", qui est dangereuse. Voir "(?{ code })" dans perlre, et perlsec.

Nouveaux diagnostics

%s: groupe Eval non autorisé, utilisez le pragma "use re 'eval'"
(F) Une expression régulière contenait l'assertion de largeur nulle "&%s;(?{ ... })&%s;", mais cette construction n'est autorisée que lorsque le pragma "use re 'eval'" est actif. Voir "(?{ code })" dans perlre.
%s: groupe Eval non autorisé à l'exécution
(F) Perl a tenté de compiler une expression régulière contenant l'assertion de largeur nulle "&%s;(?{ ... })&%s;" à l'exécution, comme ce serait le cas lorsque le motif contient des valeurs interpolées. Comme il s'agit d'un risque de sécurité, cela n'est pas autorisé. Si vous insistez, vous pouvez toujours le faire en construisant explicitement le motif à partir d'une chaîne interpolée à l'exécution et en l'utilisant dans un eval(). Voir "(?{ code })" dans perlre.
Bénédiction explicite vers '' (en supposant le package principal)
(W) Vous bénissez une référence à une chaîne de longueur nulle. Cela a pour effet de bénir la référence dans le package principal. Ce n'est généralement pas ce que vous voulez. Envisagez de fournir une cible de package par défaut, par exemple, bless($ref, $p || 'MonPackage');
Chiffre hexadécimal illégal ignoré
(W) Vous avez peut-être essayé d'utiliser un caractère autre que 0 à 9 ou A à F dans un nombre hexadécimal. L'interprétation du nombre hexadécimal s'est arrêtée avant le caractère illégal.
Pas de tel champ de tableau
(F) Vous avez essayé d'accéder à un tableau comme à une table de correspondance, mais le nom de champ utilisé n'est pas défini. La table de correspondance à l'indice 0 doit mapper tous les noms de champs valides à des indices de tableau pour que cela fonctionne.
Pas de tel champ "%s" dans la variable %s de type %s
(F) Vous avez essayé d'accéder à un champ d'une variable typée dont le type ne connaît pas le nom du champ. Les noms de champs sont recherchés dans la table de correspondance %FIELDS dans le package de type au moment de la compilation. La table de correspondance %FIELDS est généralement configurée avec le pragma 'fields'.
Mémoire épuisée lors d'une requête ridiculement grande
(F) Vous ne pouvez pas allouer plus de 2^31 + "une petite quantité" d'octets. Cette erreur est très probablement causée par une faute de frappe dans le programme Perl. par exemple, $arr[time] au lieu de $arr[$time].
Itérateur de plage en dehors de la plage entière
(F) L'un (ou les deux) des arguments numériques de l'opérateur de plage ".." est en dehors de la plage qui peut être représentée par des entiers en interne. Une solution possible consiste à forcer Perl à utiliser l'incrémentation magique de chaîne en ajoutant "0" devant vos nombres.
Héritage récursif détecté lors de la recherche de la méthode '%s' %s
(F) Plus de 100 niveaux d'héritage ont été rencontrés lors de l'invocation d'une méthode. Indique probablement une boucle involontaire dans votre hiérarchie d'héritage.
Référence trouvée là où une liste de taille paire était attendue
(W) Vous avez fourni une seule référence là où Perl attendait une liste avec un nombre pair d'éléments (pour l'affectation à une table de correspondance). Cela signifie généralement que vous avez utilisé le constructeur de table de correspondance anonyme alors que vous vouliez utiliser des parenthèses. Quoi qu'il en soit, une table de correspondance nécessite des paires clé/valeur. 
%hash = { one => 1, two => 2, };   # INCORRECT
%hash = [ qw/ un tableau anonyme / ];   # INCORRECT
%hash = ( one => 1, two => 2, );   # CORRECT
%hash = qw( one 1 two 2 );                 # également correct
Valeur indéfinie affectée à un glob de type
(W) Une valeur indéfinie a été affectée à un glob de type, comme "&%s;*foo = undef&%s;". Cela ne fait rien. Il est possible que vous vouliez vraiment dire "&%s;undef *foo&%s;".
Utilisation du mot réservé "%s" dépréciée
(D) Le bareword indiqué est un mot réservé. Les futures versions de perl pourraient l'utiliser comme mot-clé, il est donc préférable soit de citer explicitement le mot d'une manière appropriée à son contexte d'utilisation, soit d'utiliser un nom différent. L'avertissement peut être supprimé pour les noms de sous-programmes en ajoutant un préfixe "&", ou en utilisant un qualificateur de package, par exemple &%s;our()&%s;, ou Foo::our().
perl: avertissement : échec de la définition de la locale.
(S) L'ensemble du message d'avertissement ressemblera à quelque chose comme : 
perl: warning: Setting locale failed.
perl: warning: Please check that your locale settings:
        LC_ALL = "En_US",
        LANG = (unset)
    are supported and installed on your system.
perl: warning: Falling back to the standard locale ("C").

Exactement quels étaient les paramètres de locale échoués varie. Dans ce qui précède, les paramètres étaient que LC_ALL était "En_US" et que LANG n'avait pas de valeur. Cette erreur signifie que Perl a détecté que vous et/ou votre administrateur système avez configuré le système dit de variables, mais que Perl n'a pas pu utiliser ces paramètres. Ce n'était heureusement pas très grave : il existe une "locale par défaut" appelée "C" que Perl peut et utilisera, le script sera exécuté. Avant de résoudre réellement le problème, cependant, vous obtiendrez le même message d'avertissement chaque fois que vous exécuterez Perl. Comment résoudre réellement le problème se trouve dans "LOCALE PROBLEMS" dans perllocale.

Diagnostics obsolètes

Impossible de mktemp()
(F) La routine mktemp() a échoué pour une raison quelconque lors du traitement d'un commutateur -e. Peut-être que votre partition /tmp est pleine, ou corrompue.

Supprimé car -e n'utilise plus de fichiers temporaires.

Impossible d'écrire dans le fichier temporaire pour -e : %s
(F) La routine d'écriture a échoué pour une raison quelconque lors du traitement d'un commutateur -e. Peut-être que votre partition /tmp est pleine, ou corrompue.

Supprimé car -e n'utilise plus de fichiers temporaires.

Impossible d'ouvrir le fichier temporaire
(F) La routine de création a échoué pour une raison quelconque lors du traitement d'un commutateur -e. Peut-être que votre partition /tmp est pleine, ou corrompue.

Supprimé car -e n'utilise plus de fichiers temporaires.

regexp trop grand
(F) L'implémentation actuelle des expressions régulières utilise des entiers courts comme décalages d'adresse au sein d'une chaîne. Malheureusement, cela signifie que si l'expression régulière compile à plus de 32767, elle échouera. Généralement, lorsque vous voulez une expression régulière aussi grande, il existe une meilleure façon de le faire avec plusieurs instructions. Voir perlre.

Modifications de configuration

Vous pouvez utiliser "Configure -Uinstallusrbinperl" qui demande à installperl de ne pas installer perl également sous /usr/bin/perl. Ceci est utile si vous préférez ne pas modifier /usr/bin pour une raison ou une autre, mais nuisible car de nombreux scripts supposent de trouver Perl sous /usr/bin/perl.

NOM

perl5005delta - Notes de publication de Perl 5.005

DESCRIPTION

Ce document décrit les changements apportés entre Perl 5.004 et Perl 5.005.

Nouveautés dans Perl 5.005

Ceci est la première version majeure de Perl depuis le 5.004_01. Il y a eu de nombreux changements, tant au niveau interne qu'au niveau de l'interface de programmation.

Changements importants

  • Modules : Les modules sont maintenant une partie intégrante du système de distribution de Perl. Le `make install` d'un module le place dans un endroit où Perl peut le trouver.

    Les modules sont maintenant installés dans des sous-répertoires de @INC, par exemple /usr/lib/perl5/site_perl/. Ceci est censé prévenir les conflits de noms entre les modules qui font partie de la distribution de Perl et ceux installés par l'utilisateur.

  • use Module version : Vous pouvez maintenant demander une version minimale d'un module lorsque vous l'utilisez. Par exemple, use CGI 2.4 échouera si la version installée de CGI n'est pas au moins 2.4. Le module doit explicitement définir sa version via $VERSION.

  • use base qw(...) : Ceci est le nouveau moyen préféré de spécifier l'héritage de package. Il remplace l'ancien @ISA et est plus sûr pour les environnements de taint.

  • use parent qw(...) : Similaire à use base, mais il ne fait que définir @ISA et ne charge pas les parents. Utile lorsque vous vous souciez moins de la sécurité de taint ou lorsque les parents ne sont pas censés être des modules.

  • BEGIN blocks : Les blocs BEGIN sont maintenant exécutés avant que le reste du fichier ne soit compilé. Utile pour les pragma comme use strict.

  • FILTER : Il est maintenant possible d'intercepter l'exécution d'un script Perl et de le modifier avant qu'il ne soit compilé. Ceci est utilisé par le module Filter::Simple et Filter::cpp.

  • tie et untie : Fonctionnalité ajoutée pour lier des variables à des objets afin de surcharger les opérateurs d'accès aux tableaux et aux hachages.

  • $^X : Contient le nom du fichier exécutable de l'interpréteur Perl.

  • $^V : Contient la version de Perl sous forme de tuple (par exemple, (5, 0, 0, 5)).

  • Expressions régulières : Support amélioré des expressions régulières, y compris de nouvelles fonctionnalités comme les looks-behind positifs et négatifs.

  • Opérateur defined : Peut maintenant être utilisé sur des éléments de tableau et de hachage. Par exemple, defined($array[0]).

  • localtime et gmtime : Retournent maintenant une chaîne de caractères lorsqu'ils sont appelés sans arguments.

  • select : Peut maintenant être appelé avec un argument pour définir le fichier par défaut pour la sortie standard.

  • IPC::Open2 et IPC::Open3 : Nouveaux modules pour gérer la communication bidirectionnelle et tridirectionnelle avec les sous-processus.

  • Symbol : Nouveau module pour manipuler les symboles de package.

  • ExtUtils::MakeMaker : La version a été mise à jour pour supporter la création de modules et d'extensions.

Changements mineurs

  • Les messages d'erreur ont été améliorés.
  • Les performances générales ont été améliorées.
  • Le débogueur Perl a été mis à jour.
  • De nombreux bugs ont été corrigés.

INSTALLATION

Pour installer Perl 5.005, décompressez le fichier tar et exécutez les commandes suivantes :

sh configure
make
make install
