NOM

percona-toolkit - Outils en ligne de commande avancés pour MySQL

DESCRIPTION

Percona Toolkit est une collection d'outils en ligne de commande avancés utilisés par le personnel de support de Percona (http://www.percona.com/) pour effectuer une variété de tâches système et MySQL trop difficiles ou complexes à effectuer manuellement.

Ces outils sont des alternatives idéales aux scripts privés ou "ponctuels" car ils sont développés professionnellement, testés formellement et entièrement documentés. Ils sont également entièrement autonomes, donc l'installation est rapide et facile et aucune bibliothèque n'est installée.

Percona Toolkit est dérivé de Maatkit et Aspersa, deux des boîtes à outils les plus connues pour l'administration de serveurs MySQL. Il est développé et supporté par Percona. Pour plus d'informations et d'autres logiciels libres et open source développés par Percona, visitez http://www.percona.com/software/.

TYPES D'OPTIONS SPÉCIALES

Les options des outils utilisent des types standard ("int", "string", etc.) ainsi que ces types spéciaux :

temps
Les valeurs de temps sont exprimées en secondes par défaut. Par exemple, "--run-time 60" signifie 60 secondes. Les valeurs de temps prennent en charge un suffixe optionnel : s (secondes), m (minutes), h (heures), d (jours). "--run-time 1m" signifie 1 minute (la même chose que 60 secondes).
taille
Les valeurs de taille sont exprimées en octets par défaut. Par exemple, "--disk-space-free 1024" signifie 1 Kibioctet. Les valeurs de taille prennent en charge un suffixe optionnel : k (Kibioctet), M (Mébioctet), G (Gibioctet).
DSN
Voir "SPÉCIFICATIONS DSN (DATA SOURCE NAME)".
Hash, hash, Tableau, tableau
Les valeurs Hash, hash, Tableau et tableau sont des listes de valeurs séparées par des virgules. Par exemple, "--ignore-tables foo,bar" ignore les tables "foo" et "bar".

FICHIERS DE CONFIGURATION

Les outils Percona Toolkit peuvent lire les options à partir de fichiers de configuration. La syntaxe des fichiers de configuration est simple et directe, et présente certaines similitudes avec les outils clients en ligne de commande de MySQL. Tous les fichiers de configuration suivent les mêmes conventions.

">En interne, ce qui se passe réellement est que les lignes sont lues à partir du fichier et ensuite ajoutées en tant qu'options et arguments de ligne de commande à l'outil. Pensez donc simplement aux fichiers de configuration comme un moyen d'écrire vos lignes de commande.

SYNTAXE

La syntaxe des fichiers de configuration est la suivante :

  • Les espaces suivis d'un signe dièse (#) indiquent que le reste de la ligne est un commentaire. Ceci est supprimé. Par exemple :
  • Les espaces sont supprimés du début et de la fin de toutes les lignes.
  • Les lignes vides sont ignorées.
  • Chaque ligne peut être dans l'un des formats suivants : 
    option
option=valeur

    Ne préfixez pas l'option avec "--". Ne mettez pas les valeurs entre guillemets, même si elles contiennent des espaces ; les valeurs sont littérales. Les espaces autour du signe égal sont supprimés pendant le traitement.

  • Seules les options longues sont reconnues.
  • Une ligne contenant uniquement deux traits d'union signale la fin de l'analyse des options. Toute ligne ultérieure est interprétée comme des arguments supplémentaires (pas des options) pour le programme.

EXEMPLE

Ce fichier de configuration pour pt-stalk,

# Config pour pt-stalk
variable=Threads_connected
cycles=2  # déclenche si le problème est vu deux fois de suite
--
--user daniel

est équivalent à cette ligne de commande :

pt-stalk --variable Threads_connected --cycles 2 -- --user daniel

Les options après "--" sont transmises littéralement à mysql et mysqladmin.

ORDRE LECTURE

Les outils lisent plusieurs fichiers de configuration dans l'ordre :

1.
Le fichier de configuration global de Percona Toolkit, /etc/percona-toolkit/percona-toolkit.conf. Tous les outils lisent ce fichier, vous ne devriez donc y ajouter que les options que vous souhaitez appliquer à tous les outils.
2.
Le fichier de configuration global spécifique à l'outil, /etc/percona-toolkit/TOOL.conf, où "TOOL" est un nom d'outil tel que "pt-query-digest". Ce fichier est nommé d'après l'outil spécifique que vous utilisez, vous pouvez donc y ajouter des options qui s'appliquent uniquement à cet outil.
3.
Le fichier de configuration personnel de l'utilisateur pour Percona Toolkit, $HOME/.percona-toolkit.conf. Tous les outils lisent ce fichier, vous ne devriez donc y ajouter que les options que vous souhaitez appliquer à tous les outils.
4.
Le fichier spécifique à l'outil de l'utilisateur, $HOME/.TOOL.conf, où "TOOL" est un nom d'outil tel que "pt-query-digest". Ce fichier est nommé d'après l'outil spécifique que vous utilisez, vous pouvez donc y ajouter des options qui s'appliquent uniquement à cet outil.

SPECIFICATION

Il existe une option spéciale "--config", qui vous permet de spécifier quels fichiers de configuration Percona Toolkit doit lire. Vous spécifiez une liste de fichiers séparés par des virgules. Cependant, son comportement n'est pas comme les autres options de ligne de commande. Elle doit être donnée en premier sur la ligne de commande, avant toute autre option. Si vous essayez de la spécifier ailleurs, cela provoquera une erreur. De plus, vous ne pouvez pas spécifier "--config=/chemin/vers/fichier" ; vous devez spécifier l'option et le chemin d'accès au fichier séparés par des espaces sans signe égal entre eux, comme suit :

--config /chemin/vers/fichier

Si vous ne voulez aucun fichier de configuration, spécifiez "--config ''" pour fournir une liste vide de fichiers.

SPECIFICATIONS DSN (NOM SOURCE DE DONNÉES)

Les outils Percona Toolkit utilisent des DSN pour spécifier comment créer une connexion DBD à un serveur MySQL. Un DSN est une chaîne séparée par des virgules de parties "clé=valeur", comme suit :

h=hôte1,P=3306,u=bob

Les parties clés standard sont présentées ci-dessous, mais certains outils ajoutent des parties clés supplémentaires. Consultez la documentation de chaque outil pour plus de détails.

Certains outils n'utilisent pas de DSN mais se connectent toujours à MySQL en utilisant des options telles que "--host", "--user" et "--password". Ces outils utilisent ces options pour créer un DSN automatiquement, en coulisses.

D'autres outils utilisent à la fois des DSN et des options comme celles ci-dessus. Les options fournissent des valeurs par défaut pour toutes les parties clés des DSN qui ne spécifient pas la partie clé correspondante de l'option. Par exemple, si le DSN "h=hôte1" et l'option "--port=12345" sont spécifiés, alors l'outil ajoute automatiquement "P=12345" au DSN.

ÉCHAPPEMENT VALEURS

Les DSN sont généralement spécifiés sur la ligne de commande, il faut donc tenir compte des guillemets et de l'échappement du shell. Les caractères spéciaux, tels que l'astérisque ("*"), doivent être mis entre guillemets et/ou échappés correctement pour être transmis comme caractères littéraux dans les valeurs DSN.

Comme les parties DSN sont séparées par des virgules, les virgules littérales dans les valeurs DSN doivent être échappées avec une seule barre oblique inverse ("\"). Et comme la barre oblique inverse est le caractère d'échappement pour la plupart des shells, deux barres obliques inverses sont nécessaires pour transmettre une barre oblique inverse littérale. Par exemple, si le nom d'utilisateur est littéralement "mon,nom", il doit être spécifié comme "mon\\,nom" sur la plupart des shells. Ceci s'applique aux DSN et aux options liées aux DSN telles que "--user".

PARTIES CLÉS

Beaucoup d'outils ajoutent des parties supplémentaires aux DSN pour des usages spéciaux, et parfois remplacent des parties pour leur faire faire quelque chose de légèrement différent. Cependant, tous les outils prennent en charge au moins les éléments suivants :

A
Jeu de caractères par défaut pour la connexion ("SET NAMES").

Active les paramètres de jeu de caractères dans Perl et MySQL. Si la valeur est "utf8", définit le mode binaire de Perl sur STDOUT en utf8, passe l'option "mysql_enable_utf8" à DBD::mysql, et exécute "SET NAMES 'utf8'" après la connexion à MySQL. D'autres valeurs définissent le mode binaire sur STDOUT sans la couche utf8 et exécutent "SET NAMES" après la connexion à MySQL.

Malheureusement, il n'y a aucun moyen depuis Perl lui-même de spécifier le jeu de caractères de la bibliothèque client. "SET NAMES" n'affecte que le serveur ; si les paramètres de la bibliothèque client ne correspondent pas, il pourrait y avoir des problèmes. Vous pouvez utiliser le fichier de configuration par défaut pour spécifier le jeu de caractères de la bibliothèque client, cependant. Voir la description de la partie F ci-dessous.

D
Base de données par défaut à utiliser lors de la connexion. Les outils peuvent "USE" une base de données différente pendant l'exécution.
F
Fichier de configuration par défaut pour la bibliothèque cliente MySQL (la bibliothèque cliente C utilisée par DBD::mysql, pas Percona Toolkit lui-même). Tous les outils lisent la section "[client]" dans le fichier de configuration par défaut. Si vous omettez ceci, les fichiers de configuration par défaut standard seront lus dans l'ordre habituel. "Standard" varie d'un système à l'autre, car les noms de fichiers à lire sont compilés dans la bibliothèque cliente. Sur les systèmes Debian, par exemple, il s'agit généralement de "/etc/mysql/my.cnf" puis "~/.my.cnf". Si vous placez ce qui suit dans "~/.my.cnf", vous n'aurez pas à spécifier votre nom d'utilisateur et mot de passe MySQL sur la ligne de commande : 
[client]
user=votre_nom_utilisateur
pass=secret

Omettre la partie F est généralement la bonne chose à faire. Tant que vous avez configuré correctement votre "~/.my.cnf", cela permettra aux outils de se connecter automatiquement sans avoir besoin d'un nom d'utilisateur ou d'un mot de passe.

Vous pouvez également spécifier un jeu de caractères par défaut dans le fichier de configuration par défaut. Contrairement à la partie "A" décrite ci-dessus, cela indiquera en fait à la bibliothèque cliente (DBD::mysql) de changer le jeu de caractères qu'elle utilise en interne, ce qui ne peut être accompli par aucun autre moyen.

h
Nom d'hôte ou adresse IP MySQL à connecter.
L
Active explicitement LOAD DATA LOCAL INFILE.

Pour une raison quelconque, certains vendeurs compilent libmysql sans l'option --enable-local-infile, ce qui désactive l'instruction. Cela peut entraîner des situations étranges, comme le serveur autorisant LOCAL INFILE, mais le client générant des exceptions s'il est utilisé.

Cependant, tant que le serveur autorise LOAD DATA, les clients peuvent facilement le réactiver ; voir https://dev.mysql.com/doc/refman/en/load-data-local-security.html et http://search.cpan.org/~capttofu/DBD-mysql/lib/DBD/mysql.pm. Cette option fait exactement cela.

p
Mot de passe MySQL à utiliser lors de la connexion.
P
Numéro de port à utiliser pour la connexion. Notez que les comportements spéciaux habituels s'appliquent : si vous spécifiez "localhost" comme nom d'hôte sur les systèmes Unix, la connexion utilise en fait un fichier socket, pas une connexion TCP/IP, et ignore donc le port.
S
Fichier de socket MySQL à utiliser pour la connexion (sur les systèmes Unix).
u
Nom d'utilisateur MySQL à utiliser lors de la connexion, si ce n'est pas l'utilisateur système actuel.
s
Crée une connexion SSL

MOT_VIDE

Beaucoup d'outils vous permettent de spécifier un DSN comme un seul mot, sans aucune syntaxe "clé=valeur". Ceci est appelé un 'mot vide'. La façon dont cela est géré est spécifique à l'outil, mais il est généralement interprété comme la partie "h". percona-toolkit(1p) — Outils Percona

NOM

percona-toolkit — Collection d'outils avancés pour la gestion de MySQL et MongoDB.

DESCRIPTION

Percona Toolkit est une collection de plus de 25 outils avancés, principalement développés par les principaux contributeurs de MySQL. Les outils sont conçus pour effectuer un large éventail de tâches, notamment la sauvegarde, l'analyse, la vérification, le réglage, le dépannage et la gestion de la réplication. Ce manuel couvre tous les outils de Percona Toolkit.

TYPES D'OPTIONS SPÉCIALES

Certains outils acceptent des options spéciales qui affectent la façon dont ils interagissent avec les bases de données. Les types d'options spéciales les plus courants sont :

DSN
Une chaîne DSN (Data Source Name) spécifie les informations de connexion à une base de données. La syntaxe générale est : chemin/vers/base/de/données[:type_de_base_de_données]://utilisateur:mot_de_passe@hôte:port/base_de_données. Les outils qui utilisent des DSN incluent : pt-archiver, pt-backup, pt-deadlock-logger, pt-online-schema-change, pt-query-digest, pt-table-checksum, pt-table-copy, pt-table-lock, pt-table-move.
SQL
Les options SQL permettent de spécifier des requêtes SQL personnalisées ou des fragments de code SQL. Par exemple, pt-online-schema-change utilise l'option --alter pour spécifier la modification de schéma à appliquer.

La sortie d'aide de l'outil ("--help") vous indiquera le comportement de cet outil.

PROPAGATION

De nombreux outils vous permettent de propager des valeurs d'un DSN au suivant, de sorte que vous n'ayez pas à spécifier toutes les parties pour chaque DSN. Par exemple, si vous souhaitez spécifier un nom d'utilisateur et un mot de passe pour chaque DSN, vous pouvez vous connecter à trois hôtes comme suit :

h=host1,u=fred,p=wilma host2 host3

Ceci est spécifique à l'outil.

ENVIRONNEMENT

La variable d'environnement "PTDEBUG" active une sortie de débogage détaillée vers STDERR. Pour activer le débogage et capturer toute la sortie dans un fichier, exécutez l'outil comme suit :

PTDEBUG=1 pt-table-checksum ... > FICHIER 2>&1

Soyez prudent : la sortie de débogage est volumineuse et peut générer plusieurs mégaoctets de sortie.

EXIGENCES SYSTÈME

La plupart des outils nécessitent :

  • Perl v5.8 ou plus récent
  • Bash v3 ou plus récent
  • Modules Perl de base comme Time::HiRes

Les outils qui se connectent à MySQL nécessitent :

  • Modules Perl DBI et DBD::mysql
  • MySQL 5.0 ou plus récent

Percona Toolkit supporte officiellement et est testé sur de nombreuses distributions Linux populaires et MySQL 5.0 à 5.6 ; voir http://goo.gl/srHm7 pour la liste des plateformes et versions prises en charge.

Support IPv6

Afin de prendre en charge les adresses IPv6 pour se connecter à MySQL, le pilote Perl DBD::MySQL v4.033_01 est requis. De plus, comme indiqué dans la RFC 3986 https://www.ietf.org/rfc/rfc3986.txt section 3.2.2, les crochets doivent être utilisés pour distinguer l'hôte et le port. Exemples : https://metacpan.org/pod/DBD::mysql#port

BOGUES

Veuillez signaler les bogues à https://jira.percona.com. Incluez les informations suivantes dans votre rapport de bogue :

  • Commande complète utilisée pour exécuter l'outil
  • Outil "--version"
  • Version MySQL, MongoDB ou PostgreSQL de tous les serveurs impliqués
  • Sortie de l'outil, y compris STDERR
  • Fichiers d'entrée (journaux/dumps/fichiers de configuration, etc.)

Si possible, incluez la sortie de débogage en exécutant l'outil avec "PTDEBUG" ; voir "ENVIRONNEMENT".
