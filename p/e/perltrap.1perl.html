PERLTRAP(1perl) Guide de référence du programmeur Perl PERLTRAP(1perl)

NOM

perltrap - Pièges Perl pour les imprudents

DESCRIPTION

Le plus grand piège de tous est d'oublier d'"use warnings" ou d'utiliser le commutateur -w ; voir warnings et "-w" dans perlrun. Le deuxième plus grand piège est de ne pas rendre tout votre programme exécutable sous "use strict". Le troisième plus grand piège est de ne pas lire la liste des changements de cette version de Perl ; voir perldelta.

Pièges Awk

Les utilisateurs habitués à awk devraient noter spécialement ce qui suit :

  • Un programme Perl s'exécute une seule fois, pas une fois par ligne d'entrée. Vous pouvez faire une boucle implicite avec "-n" ou "-p".
  • Le module English, chargé via 
    use English;

    vous permet de faire référence à des variables spéciales (comme $/) avec des noms (comme $RS), comme s'ils étaient dans awk ; voir perlvar pour les détails.

  • Les points-virgules sont requis après toutes les instructions simples en Perl (sauf à la fin d'un bloc). Le saut de ligne n'est pas un délimiteur d'instruction.
  • Les accolades sont requises sur les "if" et "while".
  • Les variables commencent par "$", "@" ou "%" en Perl.
  • Les tableaux sont indexés à partir de 0. De même pour les positions des chaînes dans substr() et index().
  • Vous devez décider si votre tableau a des indices numériques ou des indices de chaînes.
  • Les valeurs de hachage ne surgissent pas lors d'une simple référence.
  • Vous devez décider si vous souhaitez utiliser des comparaisons de chaînes ou numériques.
  • La lecture d'une ligne d'entrée ne la divise pas pour vous. Vous devez la diviser vous-même dans un tableau. Et l'opérateur split() a des arguments différents de ceux d'awk.
  • La ligne d'entrée actuelle se trouve normalement dans $_, pas dans $0. Elle n'a généralement pas le saut de ligne supprimé. ($0 est le nom du programme exécuté.) Voir perlvar.
  • $<chiffre> ne fait pas référence aux champs, mais aux sous-chaînes correspondant au dernier motif de correspondance.
  • L'instruction print() n'ajoute pas de séparateurs de champs et d'enregistrements, sauf si vous définissez $, et "$\". Vous pouvez définir $OFS et $ORS si vous utilisez le module English.
  • Vous devez ouvrir vos fichiers avant d'y imprimer.
  • L'opérateur de plage est "..", pas la virgule. L'opérateur de virgule fonctionne comme en C.
  • L'opérateur de correspondance est "=~", pas "~". ("~" est l'opérateur de complément à un, comme en C.)
  • L'opérateur d'exponentiation est "**", pas "^". "^" est l'opérateur XOR, comme en C. (Vous savez, on pourrait avoir l'impression qu'awk est fondamentalement incompatible avec C.)
  • L'opérateur de concaténation est ".", pas la chaîne vide. (Utiliser la chaîne vide rendrait "/pat/ /pat/" impossible à analyser, car le troisième slash serait interprété comme un opérateur de division - le tokenizer est en fait légèrement sensible au contexte pour les opérateurs comme "/", "?" et ">". Et en fait, "." lui-même peut être le début d'un nombre.)
  • Les mots-clés "next", "exit" et "continue" fonctionnent différemment.
  • Les variables suivantes fonctionnent différemment : 
    Awk       Perl
ARGC      scalaire @ARGV (comparer avec $#ARGV)
ARGV[0]   $0
FILENAME  $ARGV
FNR       $. - quelque chose
FS        (ce que vous voulez)
NF        $#Fld, ou quelque chose comme ça
NR        $.
OFMT      $#
OFS       $,
ORS       $\
RLENGTH   length($&)
RS        $/
RSTART    length($`)
SUBSEP    $;
  • Vous ne pouvez pas définir $RS avec un motif, seulement une chaîne.
  • En cas de doute, exécutez la construction awk à travers a2p et voyez ce qu'il vous donne.

Pièges C/C++

Les programmeurs C et C++ cérébraux devraient noter ce qui suit :

  • Les accolades sont requises sur les "if" et "while".
  • Vous devez utiliser "elsif" plutôt que "else if".
  • Les mots-clés "break" et "continue" de C deviennent en Perl "last" et "next", respectivement. Contrairement à C, ceux-ci ne fonctionnent pas dans une construction "do { } while". Voir "Loop Control" dans perlsyn.
  • L'instruction switch s'appelle "given"/"when" et n'est disponible qu'à partir de perl 5.10. Voir "Switch Statements" dans perlsyn.
  • Les variables commencent par "$", "@" ou "%" en Perl.
  • Les commentaires commencent par "#", pas par "/*" ou "//". Perl peut interpréter les commentaires C/C++ comme des opérateurs de division, des expressions régulières non terminées ou l'opérateur défini-ou.
  • Vous ne pouvez pas prendre l'adresse de quoi que ce soit, bien qu'un opérateur similaire en Perl soit la barre oblique inverse, qui crée une référence.
  • "ARGV" doit être en majuscules. $ARGV[0] est "argv[1]" de C, et "argv[0]" se retrouve dans $0.
  • Les appels système tels que link(), unlink(), rename(), etc., renvoient non nul pour le succès, pas 0. (system(), cependant, renvoie zéro pour le succès.)
  • Les gestionnaires de signaux traitent les noms de signaux, pas les numéros. Utilisez "kill -l" pour trouver leurs noms sur votre système.

Pièges JavaScript

Les programmeurs JavaScript judicieux devraient noter ce qui suit :

  • En Perl, le "+" binaire est toujours une addition. "$string1 + $string2" convertit les deux chaînes en nombres puis les ajoute. Pour concaténer deux chaînes, utilisez l'opérateur ".".
  • L'opérateur unaire "+" ne fait rien en Perl. Il existe pour éviter les ambiguïtés syntaxiques.
  • Contrairement à "for...in", le "for" de Perl (également orthographié "foreach") ne permet pas que le côté gauche soit une expression arbitraire. Il doit s'agir d'une variable : 
    for my $variable (keys %hash) {
     ...
}

    De plus, n'oubliez pas "keys" là-dedans, car "foreach my $kv (%hash) {}" itère sur les clés et les valeurs, et n'est généralement pas utile ($kv serait une clé, puis une valeur, et ainsi de suite).

  • Pour itérer sur les indices d'un tableau, utilisez "foreach my $i (0 .. $#array) {}". "foreach my $v (@array) {}" itère sur les valeurs.
  • Perl requiert des accolades après "if", "while", "foreach", etc.
  • En Perl, "else if" s'écrit "elsif".
  • "? :" a une priorité plus élevée que l'affectation. En JavaScript, on peut écrire : 
    condition ? do_something() : variable = 3

    et la variable n'est affectée que si la condition est fausse. En Perl, vous avez besoin de parenthèses :

    $condition ? do_something() : ($variable = 3);

    Ou utilisez simplement "if".

  • Perl requiert des points-virgules pour séparer les instructions.
  • Les variables déclarées avec "my" n'affectent que le code après la déclaration. Vous ne pouvez pas écrire "$x = 1; my $x;" et vous attendre à ce que la première affectation affecte la même variable. Elle affectera plutôt un $x déclaré précédemment dans une portée externe, ou une variable globale.

    Notez également que la variable n'est pas visible avant

Pièges Perl

Les programmeurs Perl expérimentés devraient prendre note de ce qui suit:

  • Rappelez-vous que de nombreuses opérations se comportent différemment dans un contexte de liste que dans un contexte scalaire. Voir perldata pour les détails.
  • Évitez les mots nus si vous le pouvez, en particulier ceux qui sont entièrement en minuscules. Vous ne pouvez pas dire en regardant simplement si un mot nu est une fonction ou une chaîne de caractères. En utilisant des guillemets sur les chaînes de caractères et des parenthèses sur les appels de fonction, vous ne les confondrez jamais.
  • Vous ne pouvez pas discerner par simple inspection quels sont les éléments intégrés qui sont des opérateurs unaires (comme chop() et chdir()) et lesquels sont des opérateurs de liste (comme print() et unlink()). (Sauf s'ils sont prototypés, les sous-routines définies par l'utilisateur ne peuvent être que des opérateurs de liste, jamais des opérateurs unaires.) Voir perlop et perlsub.
  • Les gens ont du mal à se souvenir que certaines fonctions utilisent par défaut $_, ou @ARGV, ou quoi que ce soit, mais que d'autres qui pourraient s'attendre à le faire ne le font pas.
  • La construction <FH> n'est pas le nom du handle de fichier, c'est une opération de lecture sur ce handle. Les données lues sont assignées à $_ uniquement si la lecture du fichier est la seule condition dans une boucle while: 
    while (<FH>)      { }
while (defined($_ = <FH>)) { }..
<FH>;  # données ignorées !
  • N'oubliez pas de ne pas utiliser "=" quand vous avez besoin de "=~" ; ces deux constructions sont assez différentes: 
    $x =  /foo/;
$x =~ /foo/;
  • La construction "do {}" n'est pas une vraie boucle sur laquelle vous pouvez utiliser le contrôle de boucle.
  • Utilisez my() pour les variables locales chaque fois que vous pouvez vous en sortir (mais voir perlform pour les cas où vous ne pouvez pas). Utiliser local() donne en fait une valeur locale à une variable globale, ce qui vous expose à des effets secondaires imprévus de la portée dynamique.
  • Si vous localisez une variable exportée dans un module, sa valeur exportée ne changera pas. Le nom local devient un alias pour une nouvelle valeur mais le nom externe est toujours un alias pour l'original.

Comme toujours, si l'un de ces éléments est déclaré officiellement comme un bogue, il sera corrigé et supprimé.

Pièges Shell

Les programmeurs Shell aguerris devraient prendre note de ce qui suit:

  • L'opérateur de backtick effectue une interpolation de variable sans tenir compte de la présence de guillemets simples dans la commande.
  • L'opérateur de backtick n'effectue aucune traduction de la valeur de retour, contrairement à csh.
  • Les shells (en particulier csh) effectuent plusieurs niveaux de substitution sur chaque ligne de commande. Perl n'effectue de substitution que dans certaines constructions comme les guillemets doubles, les backticks, les chevrons et les motifs de recherche.
  • Les shells interprètent les scripts un peu à la fois. Perl compile le programme entier avant de l'exécuter (sauf pour les blocs "BEGIN", qui s'exécutent au moment de la compilation).
  • Les arguments sont disponibles via @ARGV, pas $1, $2, etc.
  • L'environnement n'est pas automatiquement mis à disposition sous forme de variables scalaires distinctes.
  • Le "test" du shell utilise "=", "!=", "<", etc. pour les comparaisons de chaînes et "-eq", "-ne", "-lt", etc. pour les comparaisons numériques. C'est l'inverse de Perl, qui utilise "eq", "ne", "lt" pour les comparaisons de chaînes, et "==", "!=", "<", etc. pour les comparaisons numériques.

Pièges Sed

Les programmeurs Sed expérimentés devraient prendre note de ce qui suit:

  • Un programme Perl s'exécute une seule fois, pas une fois pour chaque ligne d'entrée. Vous pouvez faire une boucle implicite avec "-n" ou "-p".
  • Les références arrière dans les substitutions utilisent "$" au lieu de "\".
  • Les métacaractères de correspondance de motif "(", ")", et "|" n'ont pas d'antislash devant.
  • L'opérateur de plage est "...", plutôt que une virgule.

Pièges Divers

Cette section couvre des pièges qui ne sont pas spécifiques à Perl, sed ou au shell, mais qui peuvent être sources de confusion pour les programmeurs venant d'autres langages.

  • Les variables déclarées avec "my" sont visibles uniquement dans le bloc courant (et les sous-blocs qui en découlent). Les variables déclarées avec "our" sont visibles dans tout le paquetage. Les variables déclarées avec "state" conservent leur valeur entre les appels. Voir perllexical pour plus de détails.
  • Les variables déclarées avec "my" sont visibles uniquement dans le bloc courant, pas dans la fonction courante. Si vous écrivez "{my $x;} $x;", le second $x ne fait pas référence à celui déclaré dans le bloc.
  • Les membres d'un objet ne peuvent pas être rendus accessibles en tant que variables. L'équivalent le plus proche en Perl de "with(object) { method() }" est "for", qui peut aliasser $_ à l'objet : 
    for ($object) {
    $_->method;
}
  • L'objet ou la classe sur laquelle une méthode est appelée est passé comme l'un des arguments de la méthode, pas comme une valeur "this" distincte.
