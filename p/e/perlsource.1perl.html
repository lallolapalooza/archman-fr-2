PERLSOURCE(1perl) Guide du programmeur Perl PERLSOURCE(1perl)

NOM

perlsource - Guide de l'arborescence source de Perl

DESCRIPTION

Ce document décrit l'organisation de l'arborescence source de Perl. Si vous contribuez au noyau de Perl, cela vous aidera à trouver ce que vous cherchez.

S'ORIENTER DANS L'ARBORESCENCE

L'arborescence source de Perl est vaste. Voici quelques-unes des choses que vous y trouverez :

Code C

Le code source et les fichiers d'en-tête C se trouvent principalement à la racine de l'arborescence source. Il existe quelques répertoires spécifiques à la plateforme qui contiennent du code C. De plus, certains des modules livrés avec Perl incluent du code C ou XS.

Voir perlinterp pour plus de détails sur les fichiers qui composent l'interpréteur Perl, ainsi que sur son fonctionnement.

Modules de base

Les modules livrés dans le noyau de Perl résident dans quatre sous-répertoires. Deux de ces répertoires contiennent des modules qui font partie du noyau, et deux contiennent des modules qui peuvent également être publiés séparément sur CPAN. Les modules qui peuvent être publiés sur CPAN sont appelés modules à « double vie ».

  • lib/

    Ce répertoire contient des modules purs Perl qui ne sont publiés que dans le cadre du noyau. Ce répertoire contient tous les modules et leurs tests, contrairement aux autres modules du noyau.

  • ext/

    Comme lib/, ce répertoire contient des modules qui ne sont publiés que dans le cadre du noyau. Contrairement à lib/, cependant, un module sous ext/ a généralement une disposition de répertoire et de fichiers de style CPAN et son propre Makefile.PL. Il n'est pas attendu qu'un module sous ext/ fonctionne avec les versions antérieures de Perl 5. Par conséquent, un tel module peut tirer pleinement parti des améliorations syntaxiques et autres de la version de développement de Perl 5 (blead).

  • dist/

    Ce répertoire est destiné aux modules à double vie où la source de développement (blead) est canonique. Notez que certains modules de ce répertoire peuvent ne pas avoir encore été publiés séparément sur CPAN. Les modules sous dist/ devraient s'efforcer de fonctionner avec les versions antérieures de Perl 5.

  • cpan/

    Ce répertoire contient des modules à double vie où le module CPAN est canonique. Ne modifiez pas ces modules directement ! Les modifications apportées à ces modules doivent être soumises au mainteneur du module CPAN. Une fois ces modifications appliquées et publiées, la nouvelle version du module sera intégrée au noyau.

Pour certains modules à double vie, il n'a pas encore été déterminé si la version CPAN ou la source de développement (blead) est canonique. Jusqu'à ce qu'une décision soit prise, ces modules doivent se trouver dans cpan/.

Tests

Le noyau de Perl dispose d'une suite de tests étendue. Si vous ajoutez de nouveaux tests (ou de nouveaux modules avec des tests), vous devrez peut-être mettre à jour le fichier t/TEST afin que les tests soient exécutés.

  • Tests de modules

    Les tests pour les modules du noyau dans le répertoire lib/ se trouvent juste à côté du module lui-même. Par exemple, nous avons lib/strict.pm et lib/strict.t.

    Les tests pour les modules dans ext/ et les modules à double vie se trouvent dans des sous-répertoires de t/ pour chaque module, comme dans une distribution CPAN standard.

  • t/base/

    Tests pour les fonctionnalités absolument basiques de Perl. Cela inclut "if", les lectures et écritures de fichiers de base, les expressions régulières simples, etc. Ces tests sont exécutés en premier dans la suite de tests et si l'un d'eux échoue, quelque chose est vraiment cassé.

  • t/cmd/

    Tests pour les structures de contrôle de base, "if"/"else", "while", les sous-programmes, etc.

  • t/comp/

    Tests pour les problèmes de base liés à la manière dont Perl analyse et compile lui-même.

  • t/io/

    Tests pour les fonctions d'E/S intégrées, y compris les arguments de la ligne de commande.

  • t/mro/

    Tests pour les implémentations de l'ordre de résolution de méthodes de Perl (voir mro).

  • t/op/

    Tests pour les fonctions intégrées de Perl qui ne correspondent à aucun des autres répertoires.

  • t/opbasic/

    Tests pour les fonctions intégrées de Perl qui, comme celles dans t/op/, ne correspondent à aucun des autres répertoires, mais qui, en outre, ne peuvent pas utiliser t/test.pl, car ce programme dépend de fonctionnalités que le fichier de test lui-même teste.

  • t/re/

    Tests pour les fonctions ou le comportement liés aux expressions régulières. (Ces tests étaient auparavant dans t/op).

  • t/run/

    Tests pour les fonctionnalités de la manière dont Perl s'exécute réellement, y compris les codes de sortie et la gestion des variables d'environnement PERL*.

  • t/uni/

    Tests pour le support du noyau Unicode.

  • t/win32/

    Tests spécifiques à Windows.

  • t/porting/

    Teste l'état de l'arborescence source pour diverses erreurs courantes. Par exemple, il vérifie que toutes les personnes listées dans le journal git ont une entrée correspondante dans le fichier AUTHORS.

  • t/lib/

    L'ancien emplacement pour les tests de modules, vous ne devriez rien mettre de nouveau ici. Il y a encore quelques éléments qui traînent ici et qui doivent être déplacés. Peut-être pourriez-vous les déplacer ? Merci !

Documentation

Toute la documentation du noyau destinée aux utilisateurs finaux se trouve dans pod/. Les modules individuels dans lib/, ext/, dist/ et cpan/ ont généralement leur propre documentation, soit dans le fichier Module.pm, soit dans un fichier Module.pod associé.

Enfin, la documentation destinée aux développeurs du noyau Perl se trouve dans le répertoire Porting/.

Outils et documentation de hacking

Le répertoire Porting contient un assortiment de code et de documentation destinés à aider les contributeurs à travailler sur Perl. Voici quelques points saillants :

  • check*

    Ce sont des scripts qui vérifient le code source pour des éléments tels que les violations de C ANSI, les problèmes d'encodage POD, etc.

  • Maintainers, Maintainers.pl et Maintainers.pm

    Ces fichiers contiennent des informations sur qui maintient quels modules. Exécutez "perl Porting/Maintainers -M Module::Name" pour obtenir plus d'informations sur un module à double vie.

  • podtidy

    Nettoie un fichier pod. Il est conseillé d'exécuter ce script sur un fichier pod que vous avez modifié.

Système de construction

Le système de construction de Perl sur les systèmes de type *nix commence par le script Configure dans le répertoire racine.

Des parties spécifiques à la plateforme du système de construction résident également dans des répertoires spécifiques à la plateforme comme win32/, vms/, etc. Windows et VMS ont leurs propres scripts similaires à Configure, dans leurs répertoires respectifs.

Le script Configure (ou un script similaire spécifique à la plateforme) est finalement responsable de la génération d'un Makefile à partir de Makefile.SH.

Le système de construction utilisé par Perl s'appelle metaconfig. Ce système est maintenu séparément du noyau de Perl et connaît les scripts similaires à Configure spécifiques à la plateforme, ainsi que Configure lui-même.

Le système metaconfig possède son propre dépôt git. Veuillez consulter son fichier README dans https://github.com/Perl/metaconfig pour plus de détails.

Le répertoire Cross contient divers fichiers liés à la compilation croisée de Perl. Voir Cross/README pour plus de détails.

AUTHORS

Ce fichier liste toutes les personnes ayant contribué à Perl. Si vous soumettez un correctif, vous devriez ajouter votre nom à ce fichier dans le cadre du correctif.

MANIFEST

Le fichier MANIFEST à la racine de l'arborescence source contient une liste de tous les fichiers du noyau de Perl, ainsi qu'une brève description de chaque fichier.
