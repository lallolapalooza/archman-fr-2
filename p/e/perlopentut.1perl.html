NAME

perlopentut - recettes simples pour ouvrir des fichiers et des pipes en Perl

DESCRIPTION

Chaque fois que vous effectuez des E/S sur un fichier en Perl, vous le faites via ce qu'on appelle en Perl un filehandle. Un filehandle est un nom interne pour un fichier externe. Il appartient à la fonction "open" de faire l'association entre le nom interne et le nom externe, et il appartient à la fonction "close" de rompre cette association.

Pour votre commodité, Perl configure quelques filehandles spéciaux qui sont déjà ouverts lorsque vous l'exécutez. Ceux-ci incluent "STDIN", "STDOUT", "STDERR", et "ARGV". Comme ils sont pré-ouverts, vous pouvez les utiliser immédiatement sans avoir à vous donner la peine de les ouvrir vous-même :

print STDERR "Ceci est un message de débogage.\n";
print STDOUT "Veuillez entrer quelque chose : ";
$response = <STDIN> // die "comment se fait-il qu'il n'y ait pas d'entrée ?";
print STDOUT "Merci !\n";
while (<ARGV>) { ... }

Comme vous pouvez le voir dans ces exemples, "STDOUT" et "STDERR" sont des handles de sortie, et "STDIN" et "ARGV" sont des handles d'entrée. Ils sont en lettres capitales car ils sont réservés à Perl, tout comme le tableau @ARGV et le hash %ENV. Leurs associations externes ont été définies par votre shell.

Vous devrez ouvrir tous les autres filehandles par vous-même. Bien qu'il existe de nombreuses variantes, la façon la plus courante d'appeler la fonction open() de Perl est avec trois arguments et une valeur de retour :

" OK = open(HANDLE, MODE, PATHNAME)"

Où :

OK
sera une valeur définie si l'ouverture réussit, mais "undef" si elle échoue ;
HANDLE
devrait être une variable scalaire indéfinie qui sera remplie par la fonction "open" si elle réussit ;
MODE
est le mode d'accès et le format d'encodage avec lesquels ouvrir le fichier ;
PATHNAME
est le nom externe du fichier que vous souhaitez ouvrir.

La majeure partie de la complexité de la fonction "open" réside dans les nombreuses valeurs possibles que le paramètre MODE peut prendre.

Une dernière chose avant de vous montrer comment ouvrir des fichiers : l'ouverture de fichiers ne les verrouille pas (généralement) automatiquement en Perl. Voir perlfaq5 pour savoir comment verrouiller.

Ouverture de fichiers texte

Ouverture de fichiers texte en lecture

Si vous souhaitez lire à partir d'un fichier texte, ouvrez-le d'abord en mode lecture seule comme ceci :

my $filename = "/quel/chemin/vers/un/fichier/texte/ici";
my $encoding = ":encoding(UTF-8)";
my $handle   = undef;     # ceci sera rempli en cas de succès
open($handle, "< $encoding", $filename)
    || die "$0: impossible d'ouvrir $filename en lecture : $!";

Comme avec le shell, en Perl, le symbole "<" est utilisé pour ouvrir le fichier en mode lecture seule. S'il réussit, Perl alloue un tout nouveau filehandle pour vous et remplit votre argument $handle précédemment indéfini avec une référence à ce handle.

Vous pouvez maintenant utiliser des fonctions comme "readline", "read", "getc", et "sysread" sur ce handle. La fonction d'entrée probablement la plus courante est celle qui ressemble à un opérateur :

$line = readline($handle);
$line = <$handle>;          # identique

Étant donné que la fonction "readline" renvoie "undef" à la fin du fichier ou en cas d'erreur, vous la verrez parfois utilisée ainsi :

$line = <$handle>;
if (defined $line) {
    # faire quelque chose avec $line
}
else {
    # $line n'est pas valide, donc le sauter
}

Vous pouvez également simplement sortir en cas de valeur indéfinie de cette manière :

$line = <$handle> // die "aucune entrée trouvée";

Cependant, si atteindre la fin du fichier (EOF) est un événement attendu et normal, vous ne voudrez pas quitter simplement parce que vous avez manqué d'entrées. Au lieu de cela, vous voudrez probablement simplement quitter une boucle d'entrée. Vous pouvez alors tester si une erreur réelle a provoqué la fin de la boucle et agir en conséquence :

while (<$handle>) {
    # faire quelque chose avec les données dans $_
}
if ($!) {
    die "erreur inattendue lors de la lecture depuis $filename : $!";
}

Une note sur les encodages : devoir spécifier l'encodage texte à chaque fois peut sembler un peu gênant. Pour configurer un encodage par défaut pour "open" afin de ne pas avoir à le fournir à chaque fois, vous pouvez utiliser le pragma "open" :

use open qw< :encoding(UTF-8) >;

Une fois que vous avez fait cela, vous pouvez omettre en toute sécurité la partie encodage du mode open :

open($handle, "<", $filename)
    || die "$0: impossible d'ouvrir $filename en lecture : $!";

Mais n'utilisez jamais le simple "<" sans avoir préalablement configuré un encodage par défaut. Sinon, Perl ne saura pas quelle saveur parmi les nombreuses, nombreuses, nombreuses de fichiers texte vous avez, et Perl n'aura aucune idée de la manière de mapper correctement les données de votre fichier en caractères réels avec lesquels il peut travailler. D'autres formats d'encodage courants incluent "ASCII", "ISO-8859-1", "ISO-8859-15", "Windows-1252", "MacRoman", et même "UTF-16LE". Voir perlunitut pour plus d'informations sur les encodages.

Ouverture de fichiers texte en écriture

Lorsque vous souhaitez écrire dans un fichier, vous devez d'abord décider quoi faire du contenu existant de ce fichier. Vous avez ici deux choix de base : préserver ou écraser.

Si vous souhaitez préserver le contenu existant, vous devez ouvrir le fichier en mode ajout. Comme dans le shell, en Perl, vous utilisez ">>" pour ouvrir un fichier existant en mode ajout. ">>" crée le fichier s'il n'existe pas encore.

my $handle   = undef;
my $filename = "/quel/chemin/vers/un/fichier/texte/ici";
my $encoding = ":encoding(UTF-8)";
open($handle, ">> $encoding", $filename)
    || die "$0: impossible d'ouvrir $filename en ajout : $!";

Vous pouvez maintenant écrire dans ce filehandle en utilisant n'importe laquelle des fonctions "print", "printf", "say", "write", ou "syswrite".

Comme mentionné ci-dessus, si le fichier n'existe pas encore, alors l'ouverture en mode ajout le créera pour vous. Mais si le fichier existe déjà, son contenu est en sécurité car vous ajouterez votre nouveau texte après le texte ancien.

D'un autre côté, parfois vous voulez écraser tout ce qui pourrait déjà s'y trouver. Pour vider un fichier avant de commencer à y écrire, vous pouvez l'ouvrir en mode écriture seule :

my $handle   = undef;
my $filename = "/quel/chemin/vers/un/fichier/texte/ici";
my $encoding = ":encoding(UTF-8)";
open($handle, "> $encoding", $filename)
    || die "$0: impossible d'ouvrir $filename en mode écriture seule : $!";

Ici encore, Perl fonctionne comme le shell en ce sens que le symbole ">" écrase un fichier existant.

Comme en mode ajout, lorsque vous ouvrez un fichier en mode écriture seule, vous pouvez maintenant écrire dans ce filehandle en utilisant n'importe laquelle des fonctions "print", "printf",

Qu'en est-il du mode lecture-écriture ? Vous devriez probablement prétendre qu'il n'existe pas, car l'ouverture de fichiers texte en mode lecture-écriture ne fera probablement pas ce que vous attendez. Voir perlfaq5 pour plus de détails.

Ouverture de fichiers binaires

Si le fichier à ouvrir contient des données binaires au lieu de caractères texte, alors l'argument "MODE" de la fonction "open" est un peu différent. Au lieu de spécifier l'encodage, vous dites à Perl que vos données sont en octets bruts.

my $filename = "/quelque/chemin/vers/un/fichier/binaire/ici";
my $encoding = ":raw :bytes"
my $handle   = undef;     # sera rempli en cas de succès

Et ensuite, ouvrez comme d'habitude, en choisissant "<", ">>", ou ">" selon les besoins :

open($handle, "< $encoding", $filename)
    || die "$0: impossible d'ouvrir $filename en lecture : $!";
open($handle, ">> $encoding", $filename)
    || die "$0: impossible d'ouvrir $filename en ajout : $!";
open($handle, "> $encoding", $filename)
    || die "$0: impossible d'ouvrir $filename en mode écriture : $!";

Alternativement, vous pouvez passer en mode binaire sur une poignée existante de cette manière :

binmode($handle)    || die "impossible de faire binmode sur la poignée";

C'est particulièrement utile pour les poignées que Perl a déjà ouvertes pour vous.

binmode(STDIN)      || die "impossible de faire binmode sur STDIN";
binmode(STDOUT)     || die "impossible de faire binmode sur STDOUT";

Vous pouvez également passer un encodage explicite à "binmode" pour le modifier à la volée. Ce n'est pas exactement le mode « binaire », mais nous utilisons toujours "binmode" pour ce faire :

binmode(STDIN,  ":encoding(MacRoman)") || die "impossible de faire binmode sur STDIN";
binmode(STDOUT, ":encoding(UTF-8)")    || die "impossible de faire binmode sur STDOUT";

Une fois que vous avez correctement ouvert votre fichier binaire dans le bon mode, vous pouvez utiliser toutes les mêmes fonctions d'E/S Perl que celles que vous avez utilisées sur les fichiers texte. Cependant, vous pourriez préférer utiliser la fonction "read" de taille fixe au lieu de "readline" de taille variable pour votre entrée.

Voici un exemple de copie d'un fichier binaire :

my $BUFSIZ   = 64 * (2 ** 10);
my $name_in  = "/quelque/fichier/entree";
my $name_out = "/quelque/fichier/sortie";
my($in_fh, $out_fh, $buffer);
open($in_fh,  "<", $name_in)
    || die "$0: impossible d'ouvrir $name_in en lecture : $!";
open($out_fh, ">", $name_out)
    || die "$0: impossible d'ouvrir $name_out en écriture : $!";
for my $fh ($in_fh, $out_fh)  {
    binmode($fh)               || die "binmode a échoué";
}
while (read($in_fh, $buffer, $BUFSIZ)) {
    unless (print $out_fh $buffer) {
        die "impossible d'écrire sur $name_out : $!";
    }
}
close($in_fh)       || die "impossible de fermer $name_in : $!";
close($out_fh)      || die "impossible de fermer $name_out : $!";

Ouverture de pipes

Perl vous permet également d'ouvrir une poignée de fichier vers un programme externe ou une commande shell plutôt que vers un fichier. Vous pouvez le faire afin de transmettre des données de votre programme Perl à une commande externe pour un traitement ultérieur, ou pour recevoir des données d'un autre programme pour que votre propre programme Perl les traite.

Les poignées de fichier vers les commandes sont également connues sous le nom de pipes, car elles fonctionnent sur des principes de communication inter-processus similaires à ceux des pipelines Unix. Une telle poignée de fichier a un programme actif au lieu d'un fichier statique à son extrémité externe, mais à tous autres égards, elle fonctionne comme une poignée de fichier plus typique, avec toutes les techniques discutées plus tôt dans cet article tout aussi applicables.

Ainsi, vous ouvrez un pipe en utilisant le même appel "open" que celui que vous utilisez pour ouvrir des fichiers, en définissant le deuxième argument ("MODE") sur des caractères spéciaux qui indiquent soit un pipe d'entrée, soit un pipe de sortie. Utilisez "-|" pour une poignée de fichier qui permettra à votre programme Perl de lire des données à partir d'un programme externe, et "|-" pour une poignée de fichier qui lui enverra des données.

Ouverture d'un pipe pour la lecture

Disons que vous souhaitez que votre programme Perl traite les données stockées dans un répertoire voisin appelé "unsorted", qui contient un certain nombre de fichiers texte. Vous souhaiteriez également que votre programme trie tout le contenu de ces fichiers en une seule liste de lignes uniques triées par ordre alphabétique avant de commencer à les traiter.

Vous pourriez le faire en ouvrant une poignée de fichier ordinaire dans chacun de ces fichiers, en construisant progressivement un tableau en mémoire de tout le contenu des fichiers que vous chargez de cette manière, puis en triant et filtrant ce tableau lorsque vous avez fini de charger les fichiers. *Ou*, vous pourriez décharger tout ce travail de fusion et de tri sur la commande "sort" de votre système d'exploitation en ouvrant un pipe directement vers sa sortie, et commencer à travailler beaucoup plus rapidement.

Voici à quoi cela pourrait ressembler :

open(my $sort_fh, '-|', 'sort -u unsorted/*.txt')
    or die "Impossible d'ouvrir un pipe vers sort : $!";
# Et immédiatement, nous pouvons commencer à lire les lignes triées :
while (my $line = <$sort_fh>) {
    #
    # ... Faites quelque chose d'intéressant avec chaque $line ici ...
    #
}

Le deuxième argument de la fonction "open", "-|", en fait un pipe de lecture vers un programme séparé, plutôt qu'une poignée de fichier ordinaire vers un fichier.

Notez que le troisième argument de la fonction "open" est une chaîne contenant le nom du programme ("sort") plus tous ses arguments : dans ce cas, "-u" pour spécifier le tri unique, puis un glob de fichiers spécifiant les fichiers à trier. La poignée de fichier résultante $sort_fh fonctionne comme une poignée de fichier en lecture seule ("<"), et votre programme peut ensuite lire des données à partir de celle-ci comme s'il était ouvert sur un seul fichier ordinaire.

Ouverture d'un pipe pour l'écriture

Pour continuer l'exemple précédent, disons que votre programme a terminé son traitement et que les résultats se trouvent dans un tableau appelé @processed. Vous souhaitez imprimer ces lignes dans un fichier appelé "numbered.txt" avec une colonne bien formatée de numéros de ligne.

Certes, vous pourriez écrire votre propre code pour faire cela — ou, une fois de plus, vous pourriez déléguer ce travail à un autre programme. Dans ce cas, "cat", exécuté avec son option "-n" pour activer la numérotation des lignes, devrait faire l'affaire :

open(my $cat_fh, '|-', 'cat -n > numbered.txt')
    or die "Impossible d'ouvrir un pipe vers cat : $!";
for my $line (@processed) {
    print $cat_fh $line;
}

Ici, nous utilisons un deuxième argument "open", "|-", signifiant que la poignée de fichier attribuée à $cat_fh doit être un pipe d'écriture. Nous pouvons ensuite l'utiliser comme nous le ferions pour une poignée de fichier ordinaire en écriture seule, y compris la fonction de base d'"imprimer" des données.

Notez que le troisième argument, spécifiant la commande à laquelle nous souhaitons envoyer un pipe, configure "cat" pour rediriger sa sortie via ce symbole ">" vers le fichier "numbered.txt". Cela peut commencer à paraître un peu délicat, car le même symbole aurait signifié quelque chose d'entièrement différent s'il était apparu dans le deuxième argument de la fonction "open" ! Mais ici, dans le troisième argument, il fait simplement partie de la commande shell dans laquelle Perl ouvrira le pipe, et Perl lui-même ne lui attribue aucune signification particulière.

Expression de la commande sous forme de liste

Pour ouvrir des pipes, Perl offre la possibilité d'appeler "open" avec une liste comprenant la commande souhaitée et tous ses propres arguments comme éléments distincts, plutôt que de les combiner en une seule chaîne comme dans les exemples ci-dessus. Par exemple, nous aurions pu formuler l'appel "open" dans le premier exemple comme suit :

open(my $sort_fh, '-|', 'sort', '-u', glob('unsorted/*.txt'))
    or die "Impossible d'ouvrir un pipe vers sort : $!";

Lorsque vous appelez "open" de cette manière, Perl invoque la commande donnée directement, contournant le shell. Ainsi, le shell n'essaiera pas d'interpréter les caractères spéciaux dans la liste des arguments de la commande, ce qui pourrait sinon avoir des effets indésirables. Cela peut conduire à des appels "open" plus sûrs et moins sujets aux erreurs, utiles dans des cas tels que le passage de variables en tant qu'arguments, ou même simplement la référence à des noms de fichiers contenant des espaces.

Cependant, lorsque vous *voulez* passer un métacaractère significatif au shell, comme avec le symbole "*" dans cet dernier argument "unsorted/*.txt", vous ne pouvez pas utiliser cette syntaxe alternative. Dans ce cas, nous avons contourné le problème grâce à la fonction intégrée pratique "glob" de Perl, qui évalue son argument en une liste de noms de fichiers ; et nous pouvons passer en toute sécurité cette liste résultante à "open", comme indiqué ci-dessus.

Notez également que la représentation des arguments de commande piped sous forme de liste de cette manière ne fonctionne pas sur toutes les plateformes. Cela fonctionnera sur tout système d'exploitation basé sur Unix qui fournit une vraie fonction "fork" (par exemple, macOS ou Linux), ainsi que sur Windows lors de l'exécution de Perl 5.22 ou version ultérieure.
