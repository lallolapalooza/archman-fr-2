PERL585DELTA(1perl) Guide de référence du programmeur Perl PERL585DELTA(1perl)

NOM

perl585delta - ce qui est nouveau pour perl v5.8.5

DESCRIPTION

Ce document décrit les différences entre la version 5.8.4 et la version 5.8.5.

Changements incompatibles

Il n'y a aucun changement incompatible avec la version 5.8.4.

Améliorations du noyau

Le moteur d'expressions régulières de Perl prend désormais en charge la correspondance sur l'intersection de deux classes de caractères Unicode. Vous pouvez également désormais faire référence à des classes de caractères définies par l'utilisateur à l'intérieur d'autres classes de caractères définies par l'utilisateur.

Modules et pragmata

  • Carp a été amélioré pour fonctionner correctement avec Safe. Le rapport de messages de Carp devrait maintenant être exempt d'anomalies - il affichera toujours les informations de numéro de ligne.
  • CGI mis à jour vers la version 3.05
  • charnames évite maintenant d'écraser $_
  • Digest mis à jour vers la version 1.08
  • Encode mis à jour vers la version 2.01
  • FileCache mis à jour vers la version 1.04
  • libnet mis à jour vers la version 1.19
  • Pod::Parser mis à jour vers la version 1.28
  • Pod::Perldoc mis à jour vers la version 3.13
  • Pod::LaTeX mis à jour vers la version 0.57
  • Safe fonctionne maintenant correctement avec Carp
  • Scalar-List-Utils mis à jour vers la version 1.14
  • La documentation de Shell a été réécrite, et son comportement historique de mise entre guillemets partielles automatiques des arguments de commande peut maintenant être désactivé.
  • Test mis à jour vers la version 1.25
  • Test::Harness mis à jour vers la version 2.42
  • Time::Local mis à jour vers la version 1.10
  • Unicode::Collate mis à jour vers la version 0.40
  • Unicode::Normalize mis à jour vers la version 0.30

Changements utilitaires

Le débogueur de Perl

Le débogueur peut maintenant simuler un pas en arrière, en redémarrant et en réexécutant toutes les commandes sauf la dernière à partir d'un historique de commandes sauvegardé.

h2ph

h2ph est maintenant capable de comprendre un ensemble très limité de fonctions C inline - essentiellement, les fonctions inline qui ressemblent à des macros CPP. Cela a été introduit pour traiter certains en-têtes des dernières versions de glibc. L'avertissement standard s'applique toujours ; pour citer la documentation de h2ph, vous devrez peut-être bricoler avec les fichiers produits.

Améliorations d'installation et de configuration

Perl 5.8.5 devrait pouvoir être compilé proprement à partir des sources sur LynxOS.

Corrections de bugs sélectionnées

  • L'optimisation du tri sur place introduite en 5.8.4 contenait un bug. Par exemple, dans un code tel que 
    @a = sort ($b, @a)

    le résultat omettait la valeur $b. Ceci est maintenant corrigé.

  • L'optimisation pour les affectations inutiles introduite en 5.8.4 pouvait générer des avertissements erronés. Ceci est maintenant corrigé.
  • Perl devrait maintenant correctement détecter et lire les scripts UTF-16 marqués par BOM et (sans BOM) de n'importe quel endianness.
  • La création d'un nouveau thread en présence de références faibles était boguée, et provoquait souvent des avertissements lors de la destruction de l'interpréteur. Le bug connu est maintenant corrigé.
  • Plusieurs bugs obscurs impliquant la manipulation de chaînes Unicode avec "substr" ont été corrigés.
  • Précédemment, si la fonction de glob de fichiers de Perl rencontrait un répertoire qu'elle n'avait pas la permission d'ouvrir, elle retournait immédiatement, entraînant une troncature inattendue de la liste des résultats. Ceci a été corrigé, pour être cohérent avec le comportement de glob des shells Unix.
  • Le temps de création des threads pouvait varier considérablement entre des exécutions identiques. Ceci était causé par un algorithme de hachage médiocre dans les routines de clonage de threads, qui est maintenant corrigé.
  • Les internes de l'implémentation des ithreads ne vérifiaient pas si la création de threads au niveau du système d'exploitation avait échoué. threads->create() renvoie maintenant "undef" si la création du thread échoue au lieu de faire planter perl.

Diagnostics nouveaux ou modifiés

•
Perl -V présente plusieurs améliorations
  • affiche correctement les noms de patchs locaux qui contiennent des extraits de code intégrés ou d'autres caractères qui le confondaient auparavant.
  • les arguments de -V qui ressemblent à des expressions régulières donnent plusieurs lignes de sortie.
  • un deux-points final supprime la fin de ligne et le terminateur ';', permettant l'intégration de requêtes dans des commandes shell.
  • un deux-points initial supprime la partie 'name=' de la réponse, permettant le mappage sur n'importe quel nom.
•
Lorsque perl ne trouve pas le script spécifié, il affiche maintenant une deuxième ligne suggérant à l'utilisateur d'utiliser l'indicateur "-S" : 
$ perl5.8.5 missing.pl
Can't open perl script "missing.pl": No such file or directory.
Use -S to search $PATH for it.

Internes modifiés

Les fichiers de classes de caractères Unicode utilisés par le moteur d'expressions régulières sont maintenant construits au moment de la compilation à partir des fichiers de données fournis par le consortium Unicode, au lieu d'être livrés pré-compilés. Cela réduit le fichier tarball source Perl compressé d'environ 200 Ko. Un effet secondaire est que la disposition des fichiers à l'intérieur de lib/unicore a changé.

Problèmes connus

Le test de régression t/uni/class.t effectue maintenant considérablement plus de tests, et peut prendre plusieurs minutes à s'exécuter même sur une machine rapide.

Problèmes spécifiques à la plateforme

Cette version n'est pas connue pour pouvoir être compilée sous Windows 95.

Rapports de bugs

Si vous trouvez ce qui vous semble être un bug, vous pourriez consulter les articles récemment postés dans le groupe de discussion comp.lang.perl.misc et la base de données des bugs de Perl à http://bugs.perl.org. Il peut également y avoir des informations sur http://www.perl.org, la page d'accueil de Perl.

Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bug à un cas de test minimal mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", sera envoyé à perlbug@perl.org pour être analysé par l'équipe de portage Perl. Vous pouvez parcourir et rechercher les bugs Perl 5 à http://bugs.perl.org/
