PERF-ANNOTATE(1) Manuel perf PERF-ANNOTATE(1)

NOM

perf-annotate - Lire perf.data (créé par perf record) et afficher le code annoté

SYNTAXE

perf annotate [-i <fichier> | --input=fichier] [nom_symbole]

DESCRIPTION

Cette commande lit le fichier d'entrée et affiche une version annotée du code. Si le fichier objet contient des symboles de débogage, le code source sera affiché à côté du code assembleur.

S'il n'y a pas d'informations de débogage dans l'objet, l'assembleur annoté est affiché.

OPTIONS

-i, --input=<fichier>

Nom du fichier d'entrée. (par défaut : perf.data sauf si stdin est un fifo)

-d, --dsos=<dso[,dso...]>

Ne considérer que les symboles dans ces dsos.

-s, --symbol=<symbole>

Symbole à annoter.

-f, --force

Ne pas effectuer la validation de propriété.

-v, --verbose

Être plus verbeux. (Afficher l'adresse du symbole, etc.)

-q, --quiet

Ne pas afficher d'avertissements ou de messages. (Supprime -v)

-n, --show-nr-samples

Afficher le nombre d'échantillons pour chaque symbole.

-D, --dump-raw-trace

Exporter la trace brute en ASCII.

-k, --vmlinux=<fichier>

Chemin d'accès au fichier vmlinux.

--ignore-vmlinux

Ignorer les fichiers vmlinux.

--itrace

Options pour le décodage des données de traçage d'instructions. Les options sont : 
i       synthétiser les événements d'instructions
y       synthétiser les événements de cycles
b       synthétiser les événements de branchements
c       synthétiser les événements de branchements (appels uniquement)
r       synthétiser les événements de branchements (retours uniquement)
x       synthétiser les événements de transactions
w       synthétiser les événements ptwrite
p       synthétiser les événements de puissance (incluant les événements PSB pour Intel PT)
o       synthétiser d'autres événements enregistrés en raison de l'utilisation
        de la sortie auxiliaire (voir perf record)
I       synthétiser les événements d'interruption ou similaires (asynchrones)
        (ex: Intel PT Event Trace)
e       synthétiser les événements d'erreur
d       créer un journal de débogage
f       synthétiser les événements du cache de premier niveau
m       synthétiser les événements du cache de dernier niveau
M       synthétiser les événements de mémoire
t       synthétiser les événements TLB
a       synthétiser les événements d'accès distant
g       synthétiser une chaîne d'appels (à utiliser avec i ou x)
G       synthétiser une chaîne d'appels sur les enregistrements d'événements existants
l       synthétiser les entrées de dernière branche (à utiliser avec i ou x)
L       synthétiser les entrées de dernière branche sur les enregistrements d'événements existants
s       ignorer le nombre initial d'événements
q       décodage plus rapide (moins détaillé)
A       IPC approximatif
Z       préférer ignorer les horodatages (décodage dit "sans temps")
T       utiliser la trace d'horodatage comme temps noyau
Par défaut, tous les événements sont activés, c'est-à-dire l'équivalent de --itrace=iybxwpe,
sauf pour perf script où c'est --itrace=ce
De plus, la période (par défaut 100000, sauf pour perf script où c'est 1)
pour les événements d'instructions peut être spécifiée en unités de :
i       instructions
t       ticks
ms      millisecondes
us      microsecondes
ns      nanosecondes (par défaut)
La taille de la chaîne d'appels (par défaut 16, max 1024) pour les événements
d'instructions ou de transactions peut également être spécifiée.
Le nombre d'entrées de dernière branche (par défaut 64, max 1024) pour
les événements d'instructions ou de transactions peut également être spécifié.
Similaire aux options g et l, la taille peut également être spécifiée pour les options G et L.
Sur x86, notez que G et L fonctionnent mal lorsque les données ont été enregistrées avec
un PEBS volumineux. Voir la page de manuel linkperf:perf-intel-pt[1] pour les détails.
Il est également possible d'ignorer les événements générés (instructions, branchements, transactions,
ptwrite, puissance) au début. Ceci est utile pour ignorer le code d'initialisation.
--itrace=i0nss1000000
ignore la première million d'instructions.
L'option 'e' peut être suivie de drapeaux qui affectent quels erreurs seront ou ne seront pas rapportées. Chaque drapeau doit être précédé de '+' ou '-'.
Les drapeaux sont :
        o       dépassement
        l       données de trace perdues
Si supporté, l'option 'd' peut être suivie de drapeaux qui affectent quels
messages de débogage seront ou ne seront pas enregistrés. Chaque drapeau doit être précédé
de '+' ou '-'. Les drapeaux sont :
        a       tous les événements perf
        e       sortie uniquement en cas d'erreurs (taille configurable - voir linkperf:perf-config[1])
        o       sortie vers stdout
Si supporté, l'option 'q' peut être répétée pour augmenter l'effet.
Pour désactiver complètement le décodage, utilisez --no-itrace.

-m, --modules

Charger les symboles des modules. ATTENTION : utiliser uniquement avec -k et le noyau LIVE.

-l, --print-line

Afficher les lignes sources correspondantes (peut être lent).

-P, --full-paths

Ne pas raccourcir les noms de chemins affichés.

--stdio

Utiliser l'interface stdio.

--stdio2

Utiliser l'interface stdio2, non interactive, utilise le formatage TUI.

--stdio-color=<mode>

always, never ou auto, permettant de configurer la sortie couleur via la ligne de commande, en plus de via "color.ui" .perfconfig. Utiliser --stdio-color always pour générer des couleurs même lors de la redirection vers un pipe ou un fichier. Utiliser simplement --stdio-color équivaut à utiliser always.

--tui

Utiliser l'interface TUI. L'utilisation de --tui nécessite un tty, s'il n'est pas présent, comme lors du pipage vers d'autres commandes, l'interface stdio est utilisée. Cette interface commence par se centrer sur la ligne avec le plus d'échantillons, TAB/UNTAB parcourt les lignes avec le plus d'échantillons.

--gtk

Utiliser l'interface GTK.

-C, --cpu=<cpu>

Ne signaler que les échantillons pour la liste des CPUs fournis. Plusieurs CPUs peuvent être fournis sous forme de liste séparée par des virgules sans espace : 0,1. Les plages de CPUs sont spécifiées avec - : 0-2. Par défaut, tous les échantillons sont signalés sur tous les CPUs.

--asm-raw

Afficher le codage brut des instructions d'assemblage.

--show-total-period

Afficher une colonne avec la somme des périodes.

--source

Entrelacer le code source avec le code assembleur. Activé par défaut, désactiver avec --no-source.

--symfs=<répertoire>

Rechercher les fichiers avec des symboles relatifs à ce répertoire.

-M, --disassembler-style=

Définir le style du désassembleur pour objdump.

--addr2line=<chemin>

Chemin d'accès vers l'exécutable addr2line.

--objdump=<chemin>

Chemin d'accès vers l'exécutable objdump.

--prefix=PRÉFIXE, --prefix-strip=N

Supprimer les N premières entrées des noms de fichiers sources dans les exécutables et ajouter PRÉFIXE. Cela permet d'afficher le code source compilé sur des systèmes avec une structure de fichiers différente.

--skip-missing

Ignorer les symboles qui ne peuvent pas être annotés.

--group

Afficher les informations de groupe d'événements ensemble.

--demangle

Démangler les noms de symboles en forme lisible par l'homme. C'est activé par défaut, désactiver avec --no-demangle.

--demangle-kernel

Démangler les noms de symboles du noyau en forme lisible par l'homme (pour les noyaux C++).

--percent-type

Définir le type de pourcentage d'annotation à partir des choix suivants : global-period, local-period, global-hits, local-hits 
Les mots clés local/global définissent si le pourcentage est calculé
dans la portée de la fonction (local) ou de l'ensemble des données (global).
Les mots clés period/hits définissent la base sur laquelle le pourcentage est calculé
- la période des échantillons ou le nombre d'échantillons (hits).

--percent-limit

Ne pas afficher les fonctions dont le surcoût est inférieur à ce pourcentage en stdio ou stdio2 (Par défaut : 0). Notez qu'il s'agit de la sélection des fonctions à afficher, pas des lignes à l'intérieur de la fonction.

--data-type[=NOM_TYPE]

Afficher l'annotation du type de données au lieu du code. Il infère le type de données des échantillons (s'il s'agit d'instructions d'accès à la mémoire) à l'aide des informations de débogage DWARF. Il peut prendre un argument optionnel de nom de type de données. Dans ce cas, il affichera l'annotation pour le type.

perf-annotate(1) — perf — The Linux profiler

NAME

perf-annotate

Read perf data and display annotated code

SYNOPSIS

perf annotate [OPTIONS]

DESCRIPTION

This command reads perf data and displays annotated code.

OPTIONS

--objdump <objdump_path>

Specify the path to the objdump utility.

--callgraph <callgraph_type>

Specify the callgraph type. Valid options are: "none", "local", "graph".

--demangle <demangle_type>

Specify the demangle type. Valid options are: "none", "auto", "gnu", "llvm".

--symbol <symbol_name>

Annotate only the specified symbol.

--source

Show source code annotations.

--line

Show source code line annotations.

--show-types

Show data type annotations.

--type-stat

Show stats for the data type annotation.

--skip-empty

Do not display empty (or dummy) events.

--code-with-type

Show data type info in code annotation (for memory instructions only). Currently it only works with --stdio option.

SEE ALSO

perf-record(1), perf-report(1)
