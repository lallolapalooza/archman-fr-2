PERL5320DELTA(1perl) Guide de référence du programmeur Perl PERL5320DELTA(1perl)

NOM

perl5320delta - ce qui est nouveau pour la version perl v5.32.0

DESCRIPTION

Ce document décrit les différences entre la sortie 5.30.0 et la sortie 5.32.0.

Si vous mettez à jour depuis une version antérieure comme la 5.28.0, lisez d'abord perl5300delta, qui décrit les différences entre les versions 5.28.0 et 5.30.0.

Améliorations du noyau

L'opérateur isa

Un nouvel opérateur infixe expérimental appelé "isa" teste si un objet donné est une instance d'une classe donnée ou d'une classe qui en dérive :

if( $obj isa Package::Name ) { ... }

Pour plus de détails, voir "Class Instance Operator" dans perlop.

Unicode 13.0 est pris en charge

Voir https://www.unicode.org/versions/Unicode13.0.0/ pour les détails.

Capacité de comparaisons enchaînées

Certains opérateurs de comparaison, en raison de leur associativité, s'enchaînent avec certains opérateurs de même priorité (mais jamais avec des opérateurs de priorité différente).

if ( $x < $y <= $z ) {...}

se comporte exactement comme :

if ( $x < $y && $y <= $z ) {...}

(en supposant que "$y" est un scalaire aussi simple qu'il y paraît.)

Vous pouvez en lire plus à ce sujet dans perlop sous "Operator Precedence and Associativity" dans perlop.

Nouvelles propriétés Unicode "Identifier_Status" et "Identifier_Type" prises en charge

Unicode a révisé ses exigences pour les expressions régulières : https://www.unicode.org/reports/tr18/tr18-21.html. Dans ce cadre, ils souhaitent que davantage de propriétés soient exposées, celles qui ne font pas partie du UCD strict (base de données de caractères Unicode). Ces deux propriétés sont utilisées pour examiner les entrées à des fins de sécurité. Les détails de leur utilisation se trouvent à l'adresse https://www.unicode.org/reports/tr39/.

Il est maintenant possible d'écrire "qr/\p{Name=...}/", ou "qr!\p{na=/(SMILING|GRINNING) FACE/}!"

La propriété de nom Unicode est maintenant accessible dans les motifs d'expressions régulières, en alternative à "\N{...}". Une comparaison des deux méthodes est donnée dans "Comparison of \N{...} and \p{name=...}" dans perlunicode.

Le second exemple ci-dessus montre que les sous-motifs génériques peuvent également être utilisés dans cette propriété. Voir "Wildcards in Property Values" dans perlunicode.

Amélioration de POSIX::mblen(), "mbtowc", et "wctomb"

Les fonctions POSIX::mblen(), "mbtowc", et "wctomb" fonctionnent maintenant sur les locales avec état de décalage et sont thread-safe sur les compilateurs C99 et supérieurs lorsqu'elles sont exécutées sur une plateforme disposant de la thread-safety des locales ; les paramètres de longueur sont désormais facultatifs.

Ces fonctions sont toujours exécutées sous la locale C courante. (Voir perllocale.) La plupart des locales sont sans état, mais quelques-unes, notamment le très rarement rencontré ISO 2022, maintiennent un état entre les appels à ces fonctions. Auparavant, l'état était effacé à chaque appel, mais maintenant l'état n'est pas réinitialisé à moins que le paramètre approprié ne soit "undef".

Sur les perls threadés, les fonctions C99 mbrlen(3), mbrtowc(3), et wcrtomb(3), lorsqu'elles sont disponibles, sont substituées aux fonctions simples. Cela rend ces fonctions thread-safe lorsqu'elles s'exécutent sur une plateforme de locale thread-safe.

Les paramètres de longueur de chaîne dans "mblen" et "mbtowc" sont maintenant facultatifs ; utiles uniquement si vous souhaitez limiter la longueur analysée dans la chaîne source à moins que la longueur réelle.

Les assertions alpha ne sont plus expérimentales

Voir "(*pla:pattern)" dans perlre, "(*plb:pattern)" dans perlre, "(*nla:pattern)" dans perlre, et "(*nlb:pattern)" dans perlre. Leur utilisation ne génère plus d'avertissement ; le code existant qui désactive la catégorie d'avertissement "experimental::alpha_assertions" continuera de fonctionner sans aucune modification. L'activation de la catégorie n'a aucun effet.

Les exécutions de scripts ne sont plus expérimentales

Voir "Script Runs" dans perlre. Leur utilisation ne génère plus d'avertissement ; le code existant qui désactive la catégorie d'avertissement "experimental::script_run" continuera de fonctionner sans aucune modification. L'activation de la catégorie n'a aucun effet.

Les vérifications de fonctionnalités sont maintenant plus rapides

Précédemment, les vérifications de fonctionnalités dans le parseur nécessitaient une recherche dans une table de hachage lorsque les fonctionnalités étaient définies en dehors d'un bundle de fonctionnalités ; cela a été optimisé pour une vérification par masque de bits. [GH #17229 https://github.com/Perl/perl5/issues/17229]

Perl est maintenant développé sur GitHub

Perl est maintenant développé sur GitHub. Vous pouvez nous trouver à l'adresse https://github.com/Perl/perl5.

Les bugs non liés à la sécurité devraient maintenant être signalés via GitHub. Les problèmes de sécurité doivent continuer à être signalés comme documenté dans perlsec.

Les motifs compilés peuvent maintenant être déchargés avant l'optimisation

Ceci est principalement utile pour traquer les bugs dans le compilateur d'expressions régulières. Ce déchargement se produit sur les perls "-DDEBUGGING", si vous spécifiez "-Drv" sur la ligne de commande ; ou sur n'importe quel perl si le motif est compilé dans la portée de "use re qw(Debug DUMP_PRE_OPTIMIZE)" ou "use re qw(Debug COMPILE EXTRA)". (Tous sauf le second cas affichent également d'autres informations.)

Sécurité

[CVE-2020-10543] Dépassement de tampon causé par une expression régulière spécialement conçue

Un dépassement d'entier signé "size_t" dans les calculs d'espace de stockage pour les quantificateurs d'expressions régulières imbriqués pourrait provoquer un dépassement de tampon de tas dans le compilateur d'expressions régulières de Perl, écrasant la mémoire allouée après l'espace de stockage de l'expression régulière avec des données fournies par l'attaquant.

Le système cible doit disposer d'une quantité de mémoire suffisante pour allouer des expansions partielles des quantificateurs imbriqués avant que le dépassement ne se produise. Cette exigence est peu susceptible d'être satisfaite sur les systèmes 64 bits.

Découvert par : ManhND de The Tarantula Team, VinCSS (un membre de Vingroup).

[CVE-2020-10878] Dépassement d'entier

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

rflow via un octet de code malformé produit par une expression régulière conçue ad hoc

Les dépassements d'entiers dans le calcul des décalages entre les instructions pour le moteur d'expressions régulières pouvaient entraîner la corruption de l'état du langage intermédiaire d'une expression régulière compilée. Un attaquant pourrait abuser de ce comportement pour insérer des instructions dans la forme compilée d'une expression régulière Perl.

Découvert par : Hugo van der Sanden et Slaven Rezic.

[CVE-2020-12723] Dépassement de tampon causé par une expression régulière conçue ad hoc

Les appels récursifs à S_study_chunk() par le compilateur d'expressions régulières de Perl pour optimiser la représentation du langage intermédiaire d'une expression régulière pouvaient entraîner la corruption de l'état du langage intermédiaire d'une expression régulière compilée.

Découvert par : Sergey Aleynikov.

Note Additionnelle

Une application écrite en Perl ne serait vulnérable à aucune des failles ci-dessus que si elle évalue des expressions régulières fournies par l'attaquant. L'évaluation des expressions régulières de cette manière est connue pour être dangereuse, car le moteur d'expressions régulières ne protège pas contre les attaques par déni de service dans ce scénario d'utilisation.

Changements Incompatibles

Certaines fonctionnalités de correspondance de motifs sont désormais interdites lors de la compilation de sous-motifs de caractère générique de valeur de propriété Unicode

Ces quelques fonctionnalités sont soit inappropriées, soit interfèrent avec l'algorithme utilisé pour accomplir cette tâche. La liste complète se trouve dans "Wildcards in Property Values" dans perlunicode.

Les fonctions inutilisées "POSIX::mbstowcs" et "POSIX::wcstombs" sont supprimées

Ces fonctions n'auraient jamais pu fonctionner en raison d'une spécification d'interface défectueuse. Il n'y a manifestement aucune demande pour elles, étant donné que personne ne s\'est jamais plaint pendant les nombreuses années où les fonctions ont été prétendument disponibles, par conséquent le soi-disant "support" pour elles est maintenant abandonné.

Une correction de bug pour "(?[...])" peut avoir entraîné la non-compilation de certains motifs

Voir "Corrections de bugs sélectionnées". Les heuristiques précédemment utilisées peuvent avoir permis la compilation de certains construits (peut-être pas avec l'effet voulu par le programmeur) qui auraient dû être des erreurs. Aucune n'est connue, mais il est possible que certains construits erronés ne compilent plus.

"\p{défini-par-l_utilisateur}" les propriétés remplacent désormais toujours celles officielles Unicode

Précédemment, si et seulement si une propriété définie par l'utilisateur était déclarée avant la compilation du motif d'expression régulière qu'elle contenait, sa définition était utilisée à la place de toute propriété Unicode officielle portant le même nom. Désormais, elle remplace toujours la propriété officielle. Ce changement pourrait casser du code existant qui reposait (probablement à l'insu) sur le comportement précédent. Sans cette correction, si Unicode publiait une nouvelle version avec une nouvelle propriété portant le même nom que celle que vous utilisiez depuis longtemps, votre programme planterait lorsque vous passeriez à une version de Perl utilisant cette nouvelle version Unicode. Voir "Propriétés de caractères définies par l'utilisateur" dans perlunicode. [GH #17205 https://github.com/Perl/perl5/issues/17205]

Les variables modifiables ne sont plus autorisées dans les constantes

Du code comme :

my $var;
$sub = sub () { $var };

où $var est référencé ailleurs dans une sorte de contexte modifiable, produit désormais une exception lors de la définition du sous.

Cette erreur peut être évitée en ajoutant un `return` à la définition du sous :

$sub = sub () { return $var };

Ceci était déprécié depuis Perl 5.22. [GH #17020] https://github.com/Perl/perl5/issues/17020

L'utilisation de "vec" sur des chaînes avec des points de code supérieurs à 0xFF est interdite

Ces chaînes sont représentées en interne en UTF-8, et "vec" est une opération orientée bits qui donnera probablement des résultats inattendus sur ces chaînes. Ceci a été déprécié dans perl 5.28.0.

Utilisation de points de code supérieurs à 0xFF dans les opérateurs bit-à-bit de chaîne

Certaines utilisations de ceux-ci étaient déjà illégales après un cycle de dépréciation précédent. Les utilisations restantes sont désormais interdites, ayant été dépréciées dans perl 5.28.0. Voir perldeprecation.

Sys::Hostname::hostname() n'accepte pas d'arguments

Cette utilisation a été dépréciée dans perl 5.28.0 et est maintenant fatale.

La chaîne "0" simple est désormais traitée comme un nombre pour l'opérateur de plage

Précédemment, une plage "0" .. "-1" produisait une plage de chaînes numériques de "0" à "99" ; ceci produit maintenant une liste vide, tout comme "0 .. -1". Cela signifie également que "0" .. "9" produit maintenant une liste d'entiers, alors qu'auparavant cela produisait une liste de chaînes.

Cela était dû à un cas particulier qui traitait les chaînes commençant par "0" comme des chaînes, de sorte que les plages comme "00" .. "03" produisaient "00", "01", "02", "03", mais ne gérait pas spécialement la chaîne "0". [GH #16770] https://github.com/Perl/perl5/issues/16770

"\K" est désormais interdit dans les assertions de recherche anticipée et de recherche arrière

Ceci a été interdit car cela provoque un comportement inattendu, et personne n'a pu définir quel devrait être le comportement souhaité. [GH #14638] https://github.com/Perl/perl5/issues/14638

Améliorations de Performance

  • "my_strnlen" a été accéléré pour les systèmes qui n'ont pas leur propre implémentation "strnlen".
  • "grok_bin_oct_hex" (et donc, "grok_bin", "grok_oct", et "grok_hex") ont été accélérés.
  • "grok_number_flags" a été accéléré.
  • "sort" est maintenant sensiblement plus rapide dans des cas tels que "sort {$a <=> $b}" ou "sort {$b <=> $a}". [GH #17608 https://github.com/Perl/perl5/pull/17608]

Modifications apportées à la documentation existante

Nous avons tenté de mettre à jour la documentation pour refléter les changements listés dans ce document. Si vous en trouvez que nous avons manqués, ouvrez un ticket sur https://github.com/Perl/perl5/issues.

De plus, les changements sélectionnés suivants ont été apportés :

perldebguts

  • Simplification de quelques définitions de regnode.

    Mise à jour des définitions de "BOUND" et "NBOUND".

  • Ajout de la regnode ANYOFHs.

    Ce nœud est similaire à "ANYOFHb", mais est utilisé lorsqu'un seul octet de départ est identique dans tous les points de code correspondants.

    "ANYOFHb" est utilisé pour éviter d'avoir à convertir de UTF-8 en point de code pour quelque chose qui ne correspondra pas. Il vérifie que le premier octet dans la cible encodée en UTF-8 est celui désiré, écartant ainsi la plupart des points de code possibles.

  • "sv_setpvn" mis à jour pour mentionner que le drapeau UTF-8 ne sera pas modifié par cette fonction, et qu'un octet NUL de terminaison est garanti.
  • Ajout de la documentation pour "PL_phase".
  • La documentation pour "grok_bin", "grok_oct", et "grok_hex" a été mise à jour et clarifiée.

    Diagnostics

    Les ajouts ou modifications suivants ont été apportés aux sorties diagnostiques, y compris les avertissements et les messages d'erreur fatals. Pour la liste complète des messages diagnostiques, voir perldiag.

    Nouveaux Diagnostics

    Nouvelles Erreurs

    • Expecting interpolated extended charclass in regex; marked by <-- HERE in m/%s/

      Ceci est un remplacement pour plusieurs messages d'erreur listés sous "Modifications des diagnostics existants".

    • "No digits found for %s literal"

      (F) Aucun chiffre hexadécimal n'a été trouvé après "0x" ou aucun chiffre binaire n'a été trouvé après "0b".

    Nouveaux Avertissements

    • Code point 0x%X n'est pas Unicode et n'est pas portable

      Ce n'est en fait pas un nouveau message, mais il est maintenant émis lorsque la catégorie d'avertissement "portable" est activée.

      Lorsqu'il est levé lors de la compilation d'une expression régulière, l'avertissement a du texte supplémentaire ajouté à la fin, indiquant précisément où dans le motif il s'est produit.

    • Non-hex character '%c' terminates \x early. Resolved as "%s"

      Ceci remplace un avertissement qui était beaucoup moins spécifique et qui donnait des informations erronées. Ce nouvel avertissement fait écho à celui, similaire et déjà existant, levé pour "\o{}".

    Modifications des Diagnostics Existants

    • Character following "\c" must be printable ASCII

      ...a maintenant du texte supplémentaire ajouté à la fin, lorsqu'il est levé lors de la compilation d'une expression régulière, indiquant précisément où dans le motif il s'est produit.

    • Use "%s" instead of "%s"

      ...a maintenant du texte supplémentaire ajouté à la fin, lorsqu'il est levé lors de la compilation d'une expression régulière, indiquant précisément où dans le motif il s'est produit.

    • Sequence "\c{" invalid

      ...a maintenant du texte supplémentaire ajouté à la fin, lorsqu'il est levé lors de la compilation d'une expression régulière, indiquant précisément où dans le motif il s'est produit.

    • "\c%c" is more clearly written simply as "%s"

      ...a maintenant du texte supplémentaire ajouté à la fin, lorsqu'il est levé lors de la compilation d'une expression régulière, indiquant précisément où dans le motif il s'est produit.

    • Non-octal character '%c' terminates \o early. Resolved as "%s"

      ...inclut maintenant la phrase "terminates \o early", et a du texte supplémentaire ajouté à la fin, lorsqu'il est levé lors de la compilation d'une expression régulière, indiquant précisément où dans le motif il s'est produit. Dans certains cas, le texte de la résolution a été clarifié.

    • '%s' resolved to '\o{%s}%d'

      Depuis Perl 5.32, ce message n'est plus généré. À la place, "Non-octal character '%c' terminates \o early. Resolved as "%s"" dans perldiag est utilisé.

    • Use of code point 0x%s is not allowed; the permissible max is 0x%X

      Certaines instances de ce message affichaient auparavant les chiffres hexadécimaux "A", "B", "C", "D", "E" et "F" en minuscules. Maintenant, ils sont tous uniformément en majuscules.

    • Les trois diagnostics suivants ont été supprimés et remplacés par "Expecting interpolated extended charclass in regex; marked by <-- HERE in m/%s/" : "Expecting close paren for nested extended charclass in regex; marked by <-- HERE in m/%s/", "Expecting close paren for wrapper for nested extended charclass in regex; marked by <-- HERE in m/%s/", et "Expecting '(?flags:(?[...' in regex; marked by <-- HERE in m/%s/".
    • L'avertissement "Code point 0x%X is not Unicode, and not portable" a supprimé la ligne "Code points above 0xFFFF_FFFF require larger than a 32 bit word." car les points de code aussi grands ne sont plus légaux sur les plateformes 32 bits.
    • Can't use global %s in %s

      Ce message d'erreur a été légèrement reformaté par rapport à l'original "Can't use global %s in "%s"", et en particulier les messages d'erreur trompeurs comme "Can't use global $_ in "my"" sont maintenant affichés comme "Can't use global $_ in subroutine signature".

    • Constants from lexical variables potentially modified elsewhere are no longer permitted

      Ce message d'erreur remplace l'ancien Constants from lexical variables potentially modified elsewhere are deprecated. This will not be allowed in Perl 5.32 pour refléter le fait que cette utilisation précédemment dépréciée est maintenant transformée en une exception. La classification du message a également été mise à jour de D (déprécié) à F (fatal).

      Voir également "Incompatible Changes".

    • "\N{} here is restricted to one character" est maintenant émis dans les mêmes circonstances où auparavant "\N{} in inverted character class or as a range end-point is restricted to one character" l'était.

      Ceci est dû à de nouvelles circonstances ajoutées dans Perl 5.30 qui n'étaient pas couvertes par la formulation précédente.

    • Pour clang++, ajoutez "#include <stdlib.h>" aux sondes de Configure pour "futimes", "strtoll", "strtoul", "strtoull", "strtouq", sinon les sondes échoueraient à la compilation.

  • Vérifiez l'alignement des données de caractères.

  • Perl ne recherche plus "d_u32align", par défaut "define" sur toutes les plateformes. Cette vérification était sujette aux erreurs lorsqu'elle était effectuée, ce qui n'était le cas que sur les plateformes 32 bits. [GH #16680] https://github.com/Perl/perl5/issues/16680

  • autodoc.pl

    Cet outil qui régénère perlintern et perlapi a été considérablement remanié, restaurant la cohérence des drapeaux utilisés dans embed.fnc et Devel::PPPort et permettant la suppression de nombreuses entrées redondantes "=for apidoc" dans le code.

  • La macro "ECHO" est maintenant définie. Elle est utilisée dans une règle "dtrace" qui a été initialement modifiée pour FreeBSD, et le make de FreeBSD la prédéfinit apparemment.   • Les versions de Bison 3.1 à 3.4 sont désormais prises en charge.

    Changements internes

    • Le paramètre len de "savepvn" est maintenant un "Size_t" au lieu d'un "I32" car nous pouvons gérer des chaînes plus longues que 31 bits.
    • Le lexer (Perl_yylex() dans toke.c) était auparavant une seule fonction de 4100 lignes, s'appuyant fortement sur "goto" et un grand nombre de variables locales à large portée pour effectuer son travail. Il a maintenant été divisé en quelques dizaines de fonctions statiques plus petites ; le plus grand bloc restant (yyl_word_or_keyword()) fait un peu plus de 900 lignes, et consiste en une seule instruction "switch", tous les groupes de "case" étant indépendants. Cela devrait être beaucoup plus facile à comprendre et à maintenir.
    • Les gestionnaires de signaux au niveau du système d'exploitation et le type (Sighandler_t) utilisés par le cœur de perl étaient déclarés comme ayant trois paramètres, mais le système d'exploitation était toujours informé de les appeler avec un seul argument. Cela a été corrigé en les déclarant comme ayant un seul paramètre. Voir le commit de fusion "v5.31.5-346-g116e19abbf" pour les détails complets.
    • Le code qui gère "tr///" a été extérieurement révisé, corrigeant divers bugs, notamment lorsque les chaînes source et/ou de remplacement contiennent des caractères dont les points de code sont supérieurs à 255. Certains des bugs étaient non documentés, l'un étant que dans certaines circonstances (mais pas toutes) avec "/s", l'écrasement était effectué en fonction de la source, plutôt que du remplacement. Un bug documenté qui a été corrigé est [GH #14777] https://github.com/Perl/perl5/issues/14777.
    • Une nouvelle macro pour les auteurs XS traitant des chaînes Unicode encodées en UTF-8 a été créée : "UTF8_CHK_SKIP" dans perlapi, qui est plus sûre face à une entrée UTF-8 malformée que "UTF8_SKIP" dans perlapi (mais pas aussi sûre que "UTF8_SAFE_SKIP" dans perlapi). Elle ne lira pas au-delà d'un caractère NUL. Elle a été rétroportée dans Devel::PPPort 3.55 et versions ultérieures.
    • Ajout du champ "PL_curstackinfo->si_cxsubix". Cela enregistre l'index de pile du plus
    récemment poussé sub/format/eval contexte. Il est défini et restauré automatiquement par cx_pushsub(), cx_popsub() etc., mais devrait être géré manuellement si vous effectuez une manipulation inhabituelle de la pile de contexte.
  • Divers macros traitant de la classification des types de caractères et du changement de casse où l'entrée est encodée en UTF-8 nécessitent maintenant un paramètre supplémentaire pour éviter les lectures potentielles au-delà de la fin du tampon. L'utilisation de ceux-ci a généré un avertissement de dépréciation depuis Perl 5.26. Les détails se trouvent dans "Dans le code XS, utilisation de diverses macros traitant de l'UTF-8." dans perldeprecation
  • Une nouvelle fonction d'analyseur parse_subsignature() permet à un plugin de mot-clé d'analyser une signature de sous-routine pendant que use feature 'signatures' est actif. Cela permet aux mots-clés personnalisés d'implémenter une sémantique similaire aux déclarations sub régulières qui incluent des signatures. [GH #16261] https://github.com/Perl/perl5/issues/16261
  • Comme sur certaines plateformes, nous devons détenir un mutex lors du changement temporaire de locale, de nouvelles macros ("STORE_LC_NUMERIC_SET_TO_NEEDED_IN", "WITH_LC_NUMERIC_SET_TO_NEEDED" et "WITH_LC_NUMERIC_SET_TO_NEEDED_IN") ont été ajoutées pour faciliter cela de manière sûre et efficace dans le cadre de [GH #17034] https://github.com/Perl/perl5/issues/17034.
  • La surcharge de la gestion de la mémoire pour l'allocation d'une structure OP a été réduite de 8 octets par OP sur les systèmes 64 bits.
  • eval_pv() ne convertit plus l'exception en chaîne lors de "[GH #17035]|https://github.com/Perl/perl5/issues/17035"]
  • La variable d'environnement PERL_DESTRUCT_LEVEL était auparavant uniquement respectée sur les binaires perl compilés avec le support DEBUGGING. Elle est maintenant vérifiée sur toutes les compilations perl. Son utilisation normale consiste à forcer perl à libérer individuellement chaque bloc de mémoire qu'il a alloué avant de se terminer, ce qui est utile lors de l'utilisation d'outils de détection de fuites de mémoire automatisés comme valgrind.
  • L'API eval_sv() accepte maintenant un drapeau "G_RETHROW". Si ce drapeau est défini et qu'une exception est levée lors de la compilation ou de l'exécution du code fourni, elle sera relancée, et eval_sv() ne retournera pas. [GH #17036] https://github.com/Perl/perl5/issues/17036
  • Dans le cadre de la correction de [GH #1537] https://github.com/Perl/perl5/issues/1537, perl_parse() retourne maintenant une valeur non nulle si exit(0) est appelé dans un bloc "BEGIN", "UNITCHECK" ou "CHECK".

    • Un code tel que "s/.../ ${time} /e" génère désormais correctement un avertissement "Ambiguous use of ${time} resolved to $time at ..." lorsque les avertissements sont activés.
    • "@x {"a"}" (avec l'espace) dans une sous-analyse génère désormais correctement un avertissement "better written as" lorsque les avertissements sont activés.
    • Les attributs peuvent maintenant être utilisés dans une sous-analyse. [GH #16847] https://github.com/Perl/perl5/issues/16847
    • Les littéraux hexadécimaux et binaires incomplets tels que "0x" et "0b" sont maintenant traités comme si le "x" ou le "b" faisait partie du token suivant. [#17010 https://github.com/Perl/perl5/issues/17010]
    • Une ")" superflue dans une sous-analyse, comme dans "s/.../code here/e" ou "...${code here}", ne perturbe plus l'analyseur.

      Auparavant, une sous-analyse était délimitée par des tokens générés "(" et ")", de sorte qu'un ")" superflu fermait la construction sans effectuer le nettoyage normal de la sous-analyse, ce qui perturbait l'analyseur et pouvait potentiellement entraîner un échec d'assertion.

      De telles constructions sont maintenant entourées de tokens artificiels qui ne peuvent pas être inclus dans le code source. [GH #15814] https://github.com/Perl/perl5/issues/15814

    • L'assignation de référence d'une sous-routine, telle que "\&foo = \&bar;", ne faisait silencieusement rien dans la construction [GH #16987] https://github.com/Perl/perl5/issues/16987]
    • sv_gets() récupère maintenant mieux si la SV cible est modifiée par un gestionnaire de signal. [GH #16960] https://github.com/Perl/perl5/issues/16960
    • L'instruction "readline @foo" évalue maintenant @foo dans un contexte scalaire. Auparavant, elle était évaluée dans un contexte de liste, et comme readline() ne retire qu'un seul argument de la pile, la pile pouvait sous-fluer, ou contenir des valeurs inattendues sur la pile. [GH #16929] https://github.com/Perl/perl5/issues/16929
    • L'analyse des littéraux hexadécimaux ou binaires incomplets a été modifiée dans la version 5.31.1 pour traiter un tel littéral comme étant seulement le 0, laissant le "x" ou le "b" suivant être analysé comme faisant partie du token suivant. Cela pouvait entraîner certains changements comportementaux silencieux, donc maintenant les littéraux hexadécimaux ou binaires incomplets provoquent une erreur fatale. [GH #17010] https://github.com/Perl/perl5/issues/17010
    • Le drapeau croak_on_error de eval_pv() va maintenant lancer même si l'exception est une valeur surchargée fausse. [GH #17036] https://github.com/Perl/perl5/issues/17036
    • Les blocs "INIT" et le programme lui-même ne sont plus exécutés si exit(0) est appelé dans un bloc "BEGIN", "UNITCHECK" ou "CHECK". [GH #1537] https://github.com/Perl/perl5/issues/1537
    • L'instruction "open my $fh, ">>+", undef" ouvre maintenant le fichier temporaire en mode ajout : les écritures chercheront à la fin du fichier avant d'écrire. [GH #17058] https://github.com/Perl/perl5/issues/17058
    • Correction d'un SEGV lors de la recherche de la source d'un avertissement de valeur non initialisée sur un op dont le sous-arbre inclut un OP_MULTIDEREF. [GH #17088] https://github.com/Perl/perl5/issues/17088

    Signalement de bugs

    Si vous trouvez ce que vous pensez être un bug, vous pouvez consulter la base de données des bugs de Perl à l'adresse https://github.com/Perl/perl5/issues. Il peut également y avoir des informations sur http://www.perl.org/, la page d'accueil de Perl.

    Si vous pensez avoir un bug non signalé, veuillez ouvrir un problème sur https://github.com/Perl/perl5/issues. Assurez-vous de réduire votre bug à un cas de test minuscule mais suffisant.

    Si le bug que vous signalez a des implications de sécurité qui le rendent inapproprié pour un rapport public, consultez "SECURITY VULNERABILITY CONTACT INFORMATION" dans perlsec pour savoir comment signaler le problème.
