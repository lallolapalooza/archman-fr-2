NOM

perldata - Types de données Perl

DESCRIPTION

Noms de variables

Perl possède trois types de données intégrés : les scalaires, les tableaux de scalaires, et les tableaux associatifs de scalaires, connus sous le nom de "hashes". Un scalaire est une chaîne de caractères unique (de n'importe quelle taille, limitée uniquement par la mémoire disponible), un nombre, ou une référence vers quelque chose (ce qui sera discuté dans perlref). Les tableaux normaux sont des listes ordonnées de scalaires indexées par un nombre, commençant à 0. Les hashes sont des collections non ordonnées de valeurs scalaires indexées par leur clé de chaîne de caractères associée.

Les valeurs sont généralement désignées par leur nom, ou via une référence nommée. Le premier caractère du nom indique à quel type de structure de données il se réfère. Ce caractère est appelé un "sigil". Le reste du nom indique la valeur particulière à laquelle il se réfère. Habituellement, ce nom est un identificateur unique, c'est-à-dire une chaîne de caractères commençant par une lettre ou un underscore, et contenant des lettres, des underscores et des chiffres. Dans certains cas, il peut s'agir d'une chaîne d'identificateurs, séparés par "::" (ou par le déprécié "'") ; tous sauf le dernier sont interprétés comme des noms de paquets, pour localiser l'espace de noms dans lequel rechercher l'identificateur final (voir "Packages" dans perlmod pour plus de détails). Pour une discussion plus approfondie sur les identificateurs, voir "Analyse des identificateurs". Il est possible de substituer à un identificateur simple, une expression qui produit une référence à la valeur au moment de l'exécution. Ceci est décrit plus en détail ci-dessous et dans perlref. Il est légal, mais non recommandé, de séparer le sigil d'une variable de son nom par des espaces et/ou des tabulations.

Perl a également ses propres variables intégrées dont les noms ne suivent pas ces règles. Elles ont des noms étranges afin de ne pas entrer en conflit accidentellement avec vos variables normales. Les chaînes de caractères qui correspondent aux parties entre parenthèses d'une expression régulière sont enregistrées sous des noms ne contenant que des chiffres après le "$" (voir perlop et perlre). De plus, plusieurs variables spéciales qui fournissent des fenêtres sur le fonctionnement interne de Perl ont des noms contenant des caractères de ponctuation. Celles-ci sont documentées dans perlvar.

Les valeurs scalaires sont toujours nommées avec le sigil '$', même lorsqu'elles font référence à un scalaire qui fait partie d'un tableau ou d'un hash. Le symbole '$' fonctionne sémantiquement comme le mot anglais "le" en ce sens qu'il indique qu'une valeur unique est attendue.

$jours               # la valeur scalaire simple "jours"
$jours[28]           # le 29ème élément du tableau @jours
$jours{'Fev'}        # la valeur 'Fev' du hash %jours
$#jours              # le dernier index du tableau @jours

Les tableaux entiers (et les tranches de tableaux et de hashes) sont désignés par le sigil '@', qui fonctionne à peu près comme les mots "ces" ou "celles-ci" en français, en ce sens qu'il indique que plusieurs valeurs sont attendues.

@jours               # ($jours[0], $jours[1],... $jours[n])
@jours[3,4,5]        # identique à ($jours[3],$jours[4],$jours[5])
@jours{'a','c'}      # identique à ($jours{'a'},$jours{'c'})

Les hashes entiers sont désignés par le sigil '%':

%jours               # (clef1, valeur1, clef2, valeur2 ...)

De plus, les sous-routines sont nommées avec un sigil initial '&', bien que cela soit optionnel lorsqu'il n'y a pas d'ambiguïté, tout comme le mot "faire" est souvent redondant en français. Les entrées de table symbolique peuvent être nommées avec un '*' initial, mais cela ne vous concerne pas vraiment pour l'instant (voire jamais :-).

Chaque type de variable a son propre espace de noms, tout comme plusieurs identificateurs non variables. Cela signifie que vous pouvez, sans crainte de conflit, utiliser le même nom pour une variable scalaire, un tableau, ou un hash - ou, d'ailleurs, pour un handle de fichier, un handle de répertoire, un nom de sous-routine, un nom de format, ou une étiquette. Cela signifie que $foo et @foo sont deux variables différentes. Cela signifie également que $foo[1] fait partie de @foo, et non de $foo. Cela peut sembler un peu étrange, mais ce n'est pas grave, car c'est étrange.

Parce que les références de variables commencent toujours par les sigils '$', '@', ou '%', les mots "réservés" ne sont en fait pas réservés par rapport aux noms de variables. Ils sont réservés par rapport aux étiquettes et aux handles de fichiers, cependant, qui n'ont pas de caractère spécial initial. Vous ne pouvez pas avoir un handle de fichier nommé "log", par exemple. Indice : vous pourriez dire "open(LOG,'fichierlog')" plutôt que "open(log,'fichierlog')". L'utilisation de handles de fichiers en majuscules améliore également la lisibilité et vous protège des conflits avec de futurs mots réservés. La casse est significative - "FOO", "Foo", et "foo" sont tous des noms différents. Les noms commençant par une lettre ou un underscore peuvent également contenir des chiffres et des underscores.

Il est possible de remplacer un tel nom alphanumérique par une expression qui renvoie une référence du type approprié. Pour une description de ceci, voir perlref.

Les noms commençant par un chiffre ne peuvent contenir que d'autres chiffres. Les noms qui ne commencent pas par une lettre, un underscore, un chiffre ou un caret sont limités à un seul caractère, par ex. $% ou $$. (La plupart de ces noms d'un seul caractère ont une signification prédéfinie pour Perl. Par exemple, $$ est l'ID du processus courant. Et tous ces noms sont réservés pour une utilisation potentielle par Perl.)

Analyse des identificateurs

Jusqu'à Perl 5.18, les règles réelles de ce qu'était un identificateur valide étaient un peu floues. Cependant, en général, tout ce qui est défini ici devrait fonctionner sur les versions précédentes de Perl, tandis que l'inverse - des cas limites qui fonctionnent dans les versions précédentes, mais qui ne sont pas définis ici - ne fonctionneront probablement pas sur les versions plus récentes. Comme note importante, veuillez noter que ce qui suit ne s'applique qu'aux identificateurs en clair tels qu'ils apparaissent dans le code source de Perl, et non aux identificateurs introduits par des références symboliques, qui ont beaucoup moins de restrictions. Si vous travaillez sous l'effet du pragma "use utf8;", les règles suivantes s'appliquent :

/ (?[ ( \p{Word} & \p{XID_Start} ) + [_] ])
  (?[ ( \p{Word} & \p{XID_Continue} ) ]) *    /x

C'est-à-dire, un caractère de "début" suivi d'un nombre quelconque de caractères de "continuation". Perl exige que chaque caractère d'un identificateur corresponde également à "\w" (ce qui empêche certains cas problématiques) ; et Perl accepte en outre les noms d'identificateurs commençant par un underscore.

Si vous n'êtes pas sous "use utf8", la source est traitée comme de l'ASCII + 128 caractères génériques supplémentaires, et les identificateurs doivent correspondre à

/ (?aa) (?!\d) \w+ /x

C'est-à-dire, tout caractère de mot dans la plage ASCII, tant que le premier caractère n'est pas un chiffre.

Il y a un séparateur de paquet dans Perl : un double deux-points ("::"). Les identificateurs normaux peuvent commencer ou se terminer par un double deux-points, et peuvent contenir plusieurs parties délimitées par des doubles deux-points.

Auparavant, vous pouviez utiliser "'" comme séparateur de paquet, ceci a été supprimé dans Perl 5.42.

De plus, si l'identificateur est précédé d'un sigil - c'est-à-dire, si l'identificateur fait partie d'un nom de variable - il peut éventuellement être entouré d'accolades. Par exemple, "${nom}", "@{grands_chats}", "%{garnitures_pizza}".

Mis ensemble, une grammaire pour correspondre à un identificateur de base devient

/
 (?(DEFINE)
     (?<variable>
         (?&sigil)
         (?:
                 (?&identificateur_normal)
             |   \{ \s* (?&identificateur_normal) \s* \}
         )
     )
     (?<identificateur_normal>
         (?: :: )*
          (?&identificateur_base)
          (?: (?= :: ) (?&identificateur_normal) )?
         (?: :: )*
     )
     (?<identificateur_base>
       # is use utf8 on?
         (?(?{ (caller(0))[8] & $utf8::hint_bits })
             (?&Perl_XIDS) (?&Perl_XIDC)*
           | (?aa) (?!\d) \w+
         )
     )
     (?<sigil> \$\# | [&*\$\@%])
     (?<Perl_XIDS> (?[ ( \p{Word} & \p{XID_Start} ) + [_] ]) )
     (?<Perl_XIDC> (?[ \p{Word} & \p{XID_Continue} ]) )
 )
/x

Pendant ce temps, les identificateurs spéciaux ne suivent pas les règles ci-dessus ; Pour la plupart, tous les identificateurs de cette catégorie ont une signification spéciale donnée par Perl. Parce qu'ils ont des règles d'analyse spéciales, ceux-ci ne peuvent généralement pas être entièrement qualifiés.

Variables spéciales

Ils se présentent sous six formes (mais n'utilisez pas les formes 5 et 6) :

1.
Un sigil, suivi uniquement de chiffres correspondant à "\p{POSIX_Digit}", comme $0, $1, ou $10000.
2.
Un sigil suivi d'un seul caractère correspondant à la propriété "\p{POSIX_Punct}", comme $! ou "%+", à l'exception du caractère "{" qui ne fonctionne pas.
3.
Un sigil, suivi d'un accent circonflexe et de l'un des caractères "[][A-Z^_?\]", comme $^V ou $^].
4.
Similaire à ce qui précède, un sigil, suivi d'un texte sans guillemets entre accolades, où le premier caractère est un accent circonflexe. Le caractère suivant est l'un des caractères "[][A-Z^_?\]", suivi de caractères de mot ASCII. Un exemple est "${^GLOBAL_PHASE}".
5.
Un sigil, suivi de n'importe quel caractère unique dans la plage "[\xA1-\xAC\xAE-\xFF]" lorsqu'il n'est pas sous "use utf8". (Sous "use utf8", les règles d'identifiant normales données précédemment dans cette section s'appliquent.) L'utilisation de caractères non graphiques (les contrôles C1, l'espace insécable et le trait d'union insécable) est interdite depuis la v5.26.0. L'utilisation des autres caractères est déconseillée, car ils sont tous réservés pour avoir une signification spéciale pour Perl, et aucun d'entre eux n'a actuellement de signification spéciale, bien que cela puisse changer sans préavis.

Notez qu'une implication de cette forme est qu'il existe des identifiants uniquement légaux sous "use utf8", et vice-versa, par exemple l'identifiant $état est légal sous "use utf8", mais est sinon considéré comme la variable à caractère unique $é suivi du texte sans guillemets "tat", dont la combinaison est une erreur de syntaxe.

6.
Ceci est une combinaison des deux formes précédentes. Elle n'est valide que lorsqu'elle n'est pas sous "use utf8" (les règles d'identifiant normales s'appliquent sous "use utf8"). La forme est un sigil, suivi de texte entre accolades, où le premier caractère est l'un des caractères de la plage "[\x80-\xFF]" suivi de caractères de mot ASCII jusqu'à l'accolade fermante.

Les mêmes mises en garde que pour la forme précédente s'appliquent : les caractères non graphiques ne sont plus autorisés avec "use utf8", il est déconseillé d'utiliser cette forme du tout, et l'encodage utf8 fait une grande différence.

Avant Perl v5.24, les caractères de contrôle ASCII non graphiques étaient également autorisés dans certaines situations ; cela était déconseillé depuis la v5.20.

Contexte

L'interprétation des opérations et des valeurs en Perl dépend parfois des exigences du contexte entourant l'opération ou la valeur. Il existe deux contextes principaux : liste et scalaire. Certaines opérations retournent des valeurs de liste dans les contextes qui attendent une liste, et des valeurs scalaires sinon. Si cela est vrai d'une opération, cela sera mentionné dans la documentation de cette opération. En d'autres termes, Perl surcharge certaines opérations en fonction de si la valeur de retour attendue est singulière ou plurielle. Certains mots en français fonctionnent de cette manière, comme « poisson » et « mouton ».

De manière réciproque, une opération fournit un contexte scalaire ou de liste à chacun de ses arguments. Par exemple, si vous dites

int( <STDIN> )

l'opération d'entier fournit un contexte scalaire à l'opérateur <>, qui répond en lisant une ligne de STDIN et en la renvoyant à l'opération d'entier, qui trouvera alors la valeur entière de cette ligne et la retournera. Si, au contraire, vous dites

sort( <STDIN> )

alors l'opération de tri fournit un contexte de liste à <>, qui procédera à la lecture de toutes les lignes disponibles jusqu'à la fin du fichier, et passera cette liste de lignes à la routine de tri, qui triera alors ces lignes et les retournera sous forme de liste au contexte du tri.

L'affectation est un peu spéciale en ce sens qu'elle utilise son argument de gauche pour déterminer le contexte de l'argument de droite. L'affectation à un scalaire évalue le côté droit dans un contexte scalaire, tandis que l'affectation à un tableau ou à un hachage évalue le côté droit dans un contexte de liste. L'affectation à une liste (ou à une tranche, qui n'est de toute façon qu'une liste) évalue également le côté droit dans un contexte de liste.

Lorsque vous utilisez le pragma "use warnings" ou l'option de ligne de commande -w de Perl, vous pouvez voir des avertissements concernant des utilisations inutiles de constantes ou de fonctions dans un "contexte vide". Le contexte vide signifie simplement que la valeur a été rejetée, comme une instruction contenant uniquement ""fred";" ou "getpwuid(0);". Cela compte toujours comme un contexte scalaire pour les fonctions qui se soucient de savoir si elles sont appelées dans un contexte de liste.

Les sous-routines définies par l'utilisateur peuvent choisir de se soucier de savoir si elles sont appelées dans un contexte vide, scalaire ou de liste. La plupart des sous-routines n'ont pas besoin de s'en soucier, cependant. C'est parce que les scalaires et les listes sont automatiquement interpolés dans les listes. Voir "wantarray" dans perlfunc pour savoir comment discerner dynamiquement le contexte d'appel de votre fonction.

Valeurs scalaires

Toutes les données en Perl sont soit un scalaire, soit un tableau de scalaires, soit un hachage de scalaires. Un scalaire peut contenir une seule valeur dans l'une des trois saveurs : un nombre, une chaîne de caractères ou une référence. En général, la conversion d'une forme à une autre est transparente. Bien qu'un scalaire ne puisse pas contenir directement plusieurs valeurs, il peut contenir une référence à un tableau ou à un hachage qui contient à son tour plusieurs valeurs.

Les scalaires ne sont pas nécessairement une chose ou une autre. Il n'y a aucun endroit pour déclarer une variable scalaire comme étant de type « chaîne », de type « nombre », de type « référence », ou quoi que ce soit d'autre. En raison de la conversion automatique des scalaires, les opérations qui retournent des scalaires n'ont pas besoin de se soucier (et en fait, ne peuvent pas se soucier) si leur appelant recherche une chaîne, un nombre ou une référence. Perl est un langage contextuellement polymorphe dont les scalaires peuvent être des chaînes, des nombres ou des références (qui incluent des objets). Bien que les chaînes et les nombres soient considérés comme pratiquement la même chose pour presque toutes les fins, les références sont des pointeurs fortement typés, incastables avec comptage de références intégré et invocation de destructeurs.

Une valeur scalaire est interprétée comme FAUX au sens booléen si elle est indéfinie, la chaîne nulle ou le nombre 0 (ou son équivalent en chaîne, "0"), et VRAI si elle est autre chose. Le contexte booléen n'est qu'un type spécial de contexte scalaire où aucune conversion en chaîne ou en nombre n'est jamais effectuée. La négation d'une valeur vraie par "!" ou "not" renvoie une valeur fausse spéciale. Lorsqu'elle est évaluée comme une chaîne, elle est traitée comme "", mais comme un nombre, elle est traitée comme 0. La plupart des opérateurs Perl qui retournent vrai ou faux se comportent de cette manière.

Il existe en fait deux variétés de chaînes nulles (parfois appelées chaînes « vides »), une définie et une indéfinie. La version définie est juste une chaîne de longueur zéro, comme "". La version indéfinie est la valeur qui indique qu'il n'y a pas de valeur réelle pour quelque chose, comme lorsqu'il y a eu une erreur, ou en fin de fichier, ou lorsque vous faites référence à une variable non initialisée ou à un élément d'un tableau ou d'un hachage. Bien que dans les premières versions de Perl, un scalaire indéfini puisse devenir défini lorsqu'il était utilisé pour la première fois dans un endroit attendant une valeur définie, cela ne se produit plus, sauf dans de rares cas d'autovivification comme expliqué dans perlref. Vous pouvez utiliser l'opérateur defined() pour déterminer si une valeur scalaire est définie (cela n'a aucun sens sur les tableaux ou les hachages), et l'opérateur undef() pour produire une valeur indéfinie.

Pour savoir si une chaîne donnée est un nombre valide non nul, il suffit parfois de la tester par rapport au nombre 0 et aussi à la chaîne lexicale « 0 » (bien que cela génère des bruits si les avertissements sont activés). C'est parce que les chaînes qui ne sont pas des nombres comptent comme 0, tout comme en awk :

if ($str == 0 && $str ne "0")  {
    warn "Cela ne ressemble pas à un nombre";
}

Cette méthode est peut-être la meilleure car sinon vous ne traiterez pas correctement les notations IEEE comme "NaN" ou "Infinity". D'autres fois, vous pourriez préférer déterminer si des données textuelles peuvent être utilisées numériquement en appelant la fonction POSIX::strtod() ou en inspectant votre chaîne avec une expression régulière (comme documenté dans perlre).

warn "contient des non-chiffres"        if     /\D/;
warn "pas un nombre naturel" unless /^\d+$/;             # rejette -3
warn "pas un entier"       unless /^-?\d+$/;           # rejette +3
warn "pas un entier"       unless /^[+-]?\d+$/;
warn "pas un nombre décimal" unless /^-?\d+\.?\d*$/;     # rejette .2
warn "pas un nombre décimal" unless /^-?(?:\d+(?:\.\d*)?|\.\d+)$/;
warn "pas un flottant C"
    unless /^([+-]?)(?=\d|\.\d)\d*(\.\d*)?([Ee]([+-]?\d+))?$/;

La longueur d'un tableau est une valeur scalaire. Vous pouvez trouver la longueur du tableau @days en évaluant $#days, comme en csh. Cependant, ce n'est pas la longueur du tableau ; c'est l'indice du dernier élément, ce qui est une valeur différente puisqu'il y a normalement un élément 0. L'affectation à $#days modifie en fait la longueur du tableau. Raccourcir un tableau de cette manière détruit les valeurs intermédiaires. Allonger un tableau qui avait été précédemment raccourci ne récupère pas les valeurs qui se trouvaient dans ces éléments.

Vous pouvez également obtenir une minuscule mesure d'efficacité en pré-étendant un tableau qui va devenir grand. Vous pouvez également étendre un tableau en affectant une valeur à un élément qui se trouve en dehors du tableau. Vous pouvez tronquer un tableau à néant en lui affectant la liste nulle (). Ce qui suit est équivalent :

@whatever = ();
$#whatever = -1;

Si vous évaluez un tableau dans un contexte scalaire, il retourne la longueur du tableau. (Notez que ce n'est pas vrai des listes, qui retournent la dernière valeur, comme l'opérateur virgule de C, ni des fonctions intégrées, qui retournent ce qu'elles ont envie de retourner.) Ce qui suit est toujours vrai :

scalar(@whatever) == $#whatever + 1;

Quelques programme

SCALAR CONTEXT

rs choisissent d'utiliser une conversion explicite afin de ne laisser place à aucun doute :

$element_count = scalar(@whatever);

Si vous évaluez une table de hachage dans un contexte scalaire, elle retourne une valeur fausse si la table de hachage est vide. S'il y a des paires clé/valeur, elle retourne une valeur vraie. Une définition plus précise dépend de la version.

Avant Perl 5.25, la valeur retournée était une chaîne de caractères composée du nombre de compartiments utilisés et du nombre de compartiments alloués, séparés par un slash. Ceci est surtout utile pour savoir si l'algorithme de hachage interne de Perl fonctionne mal sur votre jeu de données. Par exemple, vous stockez 10 000 éléments dans une table de hachage, mais évaluer %HASH dans un contexte scalaire révèle "1/16", ce qui signifie qu'un seul compartiment sur seize a été utilisé, et contient probablement vos 10 000 éléments. Ce n'est pas ce qui est censé se produire.

À partir de Perl 5.25, la valeur retournée a été modifiée pour être le nombre de clés dans la table de hachage. Si vous avez besoin d'accéder à l'ancien comportement, vous pouvez utiliser Hash::Util::bucket_ratio() à la place.

Si une table de hachage liée est évaluée dans un contexte scalaire, la méthode "SCALAR" est appelée (avec un fallback vers "FIRSTKEY").

Vous pouvez pré-allouer de l'espace pour une table de hachage en assignant à la fonction keys(). Ceci arrondit les compartiments alloués à la puissance de deux supérieure :

keys(%users) = 1000;                # alloue 1024 compartiments

Constructeurs de valeurs scalaires

Les littéraux numériques sont spécifiés dans l'un des formats suivants à virgule flottante ou entier :

12345
12345.67
.23E-10             # un très petit nombre
3.14_15_92          # un très important nombre
4_294_967_296       # underscore pour la lisibilité
0xff                # hexadécimal
0xdead_beef         # plus d'hexadécimal
0377                # octal (uniquement des chiffres, commence par 0)
0o12_345            # octal alternatif (introduit dans Perl 5.33.5)
0b011011            # binaire
0x1.999ap-4         # virgule flottante hexadécimale (le 'p' est obligatoire)
07.65p2             # virgule flottante octale (le 'p' est obligatoire)
0o7.65p2            # virgule flottante octale alternative
0b101.01p-1         # virgule flottante binaire (le 'p' est obligatoire)

Vous êtes autorisé à utiliser des underscores (tirets bas) dans les littéraux numériques entre les chiffres pour la lisibilité (mais pas plusieurs underscores d'affilée : "23__500" n'est pas légal ; "23_500" l'est). Vous pouvez, par exemple, regrouper les chiffres binaires par trois (comme pour un argument de mode style Unix tel que 0b110_100_100) ou par quatre (pour représenter des nibbles, comme dans 0b1010_0110) ou dans d'autres groupes.

Les littéraux de chaînes de caractères sont généralement délimités par des apostrophes ou des guillemets. Ils fonctionnent de manière très similaire aux guillemets dans les shells Unix standard : les littéraux de chaînes entre guillemets doubles sont soumis à la substitution d'échappement et de variables ; les chaînes entre apostrophes ne le sont pas (sauf pour "\'" et "\\"). Les règles d'échappement classiques de style C s'appliquent pour représenter des caractères tels que le saut de ligne, la tabulation, etc., ainsi que des formes plus exotiques. Voir "Quote and Quote-like Operators" dans perlop pour une liste.

Les représentations hexadécimales, octales ou binaires dans les littéraux de chaînes (par ex. '0xff') ne sont pas automatiquement converties en leur représentation entière. Les fonctions hex() et oct() effectuent ces conversions pour vous. Voir "hex" dans perlfunc et "oct" dans perlfunc pour plus de détails.

Les nombres à virgule flottante hexadécimaux peuvent commencer comme un littéral hexadécimal, et peuvent être suivis d'une partie fractionnaire hexadécimale optionnelle, mais doivent être suivis de "p", d'un signe optionnel, et d'une puissance de deux. Le format est utile pour présenter avec précision les valeurs à virgule flottante, en évitant les conversions vers ou depuis des nombres à virgule flottante décimaux, et donc en évitant une éventuelle perte de précision. Notez que bien que la plupart des plateformes actuelles utilisent la virgule flottante IEEE 754 sur 64 bits, ce n'est pas le cas de toutes. Une autre source potentielle de différences (de bas ordre) concerne les modes d'arrondi de la virgule flottante, qui peuvent différer entre les processeurs, les systèmes d'exploitation et les compilateurs, et que Perl ne contrôle pas.

Les nombres à virgule flottante octaux et binaires utilisent le même format que les nombres à virgule flottante hexadécimaux, mais limités respectivement aux chiffres binaires et octaux.

Vous pouvez également intégrer des sauts de ligne directement dans vos chaînes, c'est-à-dire qu'elles peuvent se terminer sur une ligne différente de celle où elles commencent. C'est pratique, mais si vous oubliez votre guillemet de fin, l'erreur ne sera signalée que lorsque Perl trouvera une autre ligne contenant le caractère guillemet, ce qui peut être bien plus loin dans le script. La substitution de variables à l'intérieur des chaînes est limitée aux variables scalaires, aux tableaux et aux tranches de tableaux ou de tables de hachage. (En d'autres termes, les noms commençant par $ ou @, suivis d'une expression optionnelle entre crochets comme indice.) Le segment de code suivant affiche "Le prix est $100."

$Price = '$100';    # non interpolé
print "Le prix est $Price.\n";     # interpolé

Il n'y a pas de double interpolation en Perl, donc le $100 est laissé tel quel.

Par défaut, les nombres à virgule flottante substitués dans les chaînes utilisent le point (".") comme séparateur décimal. Si "use locale" est effectif et que POSIX::setlocale() a été appelé, le caractère utilisé pour le séparateur décimal est affecté par la locale LC_NUMERIC. Voir perllocale et POSIX.

Noms de variables délimités par des accolades

Comme dans certains shells, vous pouvez entourer le nom de la variable d'accolades comme délimiteur pour le distinguer des alphanumériques et des underscores suivants ou d'autres textes. Vous devez également le faire lorsque vous interpollez une variable dans une chaîne pour séparer le nom de la variable d'un double-point ou d'une apostrophe suivant, car ceux-ci seraient sinon traités comme un séparateur de package :

$who = "Larry";
print PASSWD "${who}::0:0:Superuser:/:/bin/perl\n";
print "Nous utilisons ${who}speak quand ${who}'s est là.\n";

Sans les accolades, Perl aurait cherché une variable $whospeak, un $who::0, et une variable "$who's". Les deux derniers seraient le $0 et la variable $s dans le package (vraisemblablement) inexistant "who".

En fait, un identifiant simple entre ces accolades est forcé d'être une chaîne, et de même dans un indice de table de hachage. Ni l'un ni l'autre n'a besoin de guillemets. Notre exemple précédent, $days{'Feb'} peut être écrit comme $days{Feb} et les guillemets seront automatiquement supposés. Mais toute chose plus complexe dans l'indice sera interprétée comme une expression. Cela signifie par exemple que "$version{2.0}++" est équivalent à "$version{2}++", et non à "$version{'2.0'}++".

Il existe un problème similaire avec l'interpolation de texte qui ressemble à une notation d'accès à un tableau ou à une table de hachage. Placer une variable simple comme $who immédiatement devant un texte comme "[1]" ou "{foo}" amènerait la variable à être interpolée comme accédant à un élément de @who ou à une valeur stockée dans %who :

$who = "Larry Wall";
print "$who[1] est le père de Perl.\n";

tentera d'accéder à l'indice 1 d'un tableau nommé @who. Encore une fois, l'utilisation d'accolades empêchera cela :

$who = "Larry Wall";
print "${who}[1] est le père de Perl.\n";

sera traité de la même manière que

$who = "Larry Wall";
print $who . "[1] est le père de Perl.\n";

Cette notation s'applique également à des descriptions de variables plus complexes, telles que des accès à des tableaux ou des tables de hachage avec des indices. Par exemple

@name = qw(Larry Curly Moe);
print "Aussi ${name[0]}[1] était membre\n";

Sans les accolades, l'exemple ci-dessus serait analysé comme un indice de tableau à deux niveaux dans le tableau @name, et sous "use strict" produirait probablement une exception fatale, car il serait analysé comme suit :

print "Aussi " . $name[0][1] . " était membre\n";

et non comme l'intention :

print "Aussi " . $name[0] . "[1] était membre\n";

Un résultat similaire peut être obtenu en utilisant un antislash sur le premier caractère de l'indice ou de la notation de package qui ne fait pas partie de la variable à laquelle vous voulez accéder. Ainsi, l'exemple ci-dessus pourrait également être écrit :

@name = qw(Larry Curly Moe);
print "Aussi $name[0]\[1] était membre\n";

cependant pour certaines variables spéciales (variables caret multi-caractères), la forme délimitée par des accolades est la **seule** façon de référencer la variable, et la seule façon d'accéder à un indice de la variable via l'interpolation.

Considérez le tableau magique "@{^CAPTURE}" qui est peuplé par le moteur d'expressions régulières avec le contenu de tous les buffers de capture d'un motif (voir perlvar et perlre). La **seule** façon d'accéder à l'un de ces membres à l'intérieur d'une chaîne est via la forme entre accolades (délimitée) :

"abc"=~/(.)(.)(.)/
    et print "Second buffer est ${^CAPTURE[1]}";

est équivalent à

"abc"=~/(.)(.)(.)/
    et print "Second buffer est " . ${^CAPTURE}[1];

Dire "@^CAPTURE" est une erreur de syntaxe, donc il **doit** être référencé comme "@{^CAPTURE}", et pour accéder à l'un de ses éléments dans du code normal, vous écririez " ${^CAPTURE}[1] ". Cependant, lors de l'interpolation dans une chaîne, "${^CAPTURE}[1]" serait équivalent à "${^CAPTURE} . "[1]"", ce qui ne fait même pas référence à la même variable ! Ainsi, les indices doivent **également** être placés **à l'intérieur** des accolades : "${^CAPTURE[1]}".

La forme délimitée utilisant des accolades peut être utilisée avec tous les types d'accès aux variables, y compris les tranches de tableaux et de tables de hachage. Par exemple, un code comme le suivant :

@name = qw(Larry Curly Moe);
local $" = " et ";
print "Mes préférés étaient @{name[1,2]}.\n";

afficherait

Mes préférés étaient Curly et Moe.

Virgule flottante spéciale : infini (Inf) et non-un-nombre (NaN)

Les valeurs à virgule flottante incluent les valeurs spéciales "Inf" et "NaN", pour infini et non-un-nombre. L'infini peut aussi être négatif.

Th

e infinity est le résultat de certaines opérations mathématiques qui dépassent la plage des nombres à virgule flottante, comme 9**9**9. Le « not-a-number » (NaN) est le résultat lorsque le résultat est indéfini ou irreprésentable. Il est toutefois à noter que vous ne pouvez pas obtenir "NaN" à partir de certaines opérations courantes « indéfinies » ou « hors limites » comme la division par zéro, ou la racine carrée d’un nombre négatif, car Perl génère des erreurs fatales pour celles-ci.

L’infini et le NaN ont leurs propres règles d’arithmétique spéciales. La règle générale est qu’ils sont « contagieux » : "Inf" plus un est "Inf", et "NaN" plus un est "NaN". Là où les choses deviennent intéressantes, c’est lorsque vous combinez des infinis et des NaN : "Inf" moins "Inf" et "Inf" divisé par "Inf" donnent "NaN" (alors que "Inf" plus "Inf" est "Inf" et "Inf" multiplié par "Inf" est "Inf"). Le "NaN" est également curieux en ce sens qu’il n’est égal à aucun nombre, *y compris* lui-même : "NaN" != "NaN".

Perl ne comprend pas "Inf" et "NaN" comme des littéraux numériques, mais vous pouvez les avoir sous forme de chaînes, et Perl les convertira au besoin : "Inf" + 1. (Vous pouvez cependant les importer depuis l’extension POSIX ; "use POSIX qw(Inf NaN);" puis les utiliser comme des littéraux.)

Notez que lors de l’entrée (chaîne vers nombre), Perl accepte "Inf" et "NaN" sous de nombreuses formes. La casse est ignorée, et les formes spécifiques à Win32 comme "1.#INF" sont comprises, mais en sortie les valeurs sont normalisées en "Inf" et "NaN".

Version Strings

Un littéral de la forme "v1.20.300.4000" est analysé comme une chaîne composée de caractères ayant les ordonnées spécifiées. Cette forme, connue sous le nom de chaînes v, fournit un moyen alternatif et plus lisible de construire des chaînes, plutôt que d’utiliser la forme d’interpolation quelque peu moins lisible "\x{1}\x{14}\x{12c}\x{fa0}". Ceci est utile pour représenter des chaînes Unicode et pour comparer des « nombres » de version en utilisant les opérateurs de comparaison de chaînes, "cmp", "gt", "lt" etc. S’il y a deux points ou plus dans le littéral, le "v" initial peut être omis.

print v9786;              # imprime SMILEY, "\x{263a}"
print v102.111.111;       # imprime "foo"
print 102.111.111;        # identique

De tels littéraux sont acceptés par "require" et "use" pour effectuer une vérification de version. Notez que l’utilisation des chaînes v pour les adresses IPv4 n’est pas portable sauf si vous utilisez également les routines inet_aton()/inet_ntoa() du package Socket.

Notez que depuis Perl 5.8.1, les chaînes v à nombre unique (comme "v65") ne sont pas des chaînes v avant l’opérateur "=>" (qui est généralement utilisé pour séparer une clé de hachage de sa valeur) ; elles sont plutôt interprétées comme des chaînes littérales ('v65'). Elles étaient des chaînes v de Perl 5.6.0 à Perl 5.8.0, mais cela a causé plus de confusion et de ruptures que de bonnes choses. Les chaînes v à plusieurs nombres comme "v65.66" et 65.66.67 continuent d’être des chaînes v en permanence.

Littéraux spéciaux

Les littéraux spéciaux __FILE__, __LINE__, et __PACKAGE__ représentent le nom du fichier courant, le numéro de ligne et le nom du package à cet endroit dans votre programme. __SUB__ donne une référence à la sous-routine courante. Ils ne peuvent être utilisés que comme jetons distincts ; ils ne seront pas interpolés dans les chaînes. S’il n’y a pas de package courant (en raison d’une directive "package;" vide), __PACKAGE__ est la valeur indéfinie. (Mais le "package;" vide n’est plus pris en charge depuis la version 5.10.) En dehors d’une sous-routine, __SUB__ est la valeur indéfinie. __SUB__ n’est disponible qu’à partir de 5.16 et uniquement avec une déclaration "use v5.16" ou "use feature "current_sub"".

Les deux caractères de contrôle ^D et ^Z, et les jetons __END__ et __DATA__ peuvent être utilisés pour indiquer la fin logique du script avant la fin réelle du fichier. Tout texte suivant est ignoré par l’interpréteur, sauf s’il est lu par le programme comme décrit ci-dessous.

Le texte après __DATA__ peut être lu via le handle de fichier "PACKNAME::DATA", où "PACKNAME" est le package qui était courant lorsque le jeton __DATA__ a été rencontré. Le handle de fichier reste ouvert et pointe vers la ligne après __DATA__. Le programme doit "close DATA" lorsqu’il a fini de le lire. (Le laisser ouvert fuit des handles de fichier si le module est rechargé pour une raison quelconque, donc c’est une pratique plus sûre de le fermer.) Pour la compatibilité avec les scripts plus anciens écrits avant l’introduction de __DATA__, __END__ se comporte comme __DATA__ dans le script de niveau supérieur (mais pas dans les fichiers chargés avec "require" ou "do") et laisse le contenu restant du fichier accessible via "main::DATA".

while (my $line = <DATA>) { print $line; }
close DATA;
__DATA__
Hello world.

Le handle de fichier "DATA" a par défaut les couches PerlIO qui étaient en place lorsque Perl a lu le fichier pour analyser la source. Normalement, cela signifie que le fichier est lu octet par octet, comme s’il était encodé en Latin-1, mais il existe deux manières principales pour qu’il en soit autrement. Premièrement, si le jeton "__END__"/"__DATA__" se trouve dans la portée d’un pragma "use utf8", alors le handle "DATA" sera en mode UTF-8. Deuxièmement, si la source est lue depuis l’entrée standard de Perl, alors le handle de fichier "DATA" est en fait un alias du handle de fichier "STDIN", et peut être en mode UTF-8 en raison de la variable d’environnement "PERL_UNICODE" ou des options de ligne de commande de Perl.

Voir SelfLoader pour plus de détails sur __DATA__ et un exemple de son utilisation. Notez que vous ne pouvez pas lire depuis le handle de fichier DATA dans un bloc BEGIN : le bloc BEGIN est exécuté dès qu’il est vu (pendant la compilation), moment où le jeton __DATA__ (ou __END__) correspondant n’a pas encore été vu.

Barewords

Un mot qui n’a aucune autre interprétation dans la grammaire sera traité comme s’il s’agissait d’une chaîne entre guillemets. Ce sont les « barewords ». Comme pour les handles de fichier et les étiquettes, un bareword entièrement composé de lettres minuscules risque un conflit avec les mots réservés futurs, et si vous utilisez le pragma "use warnings" ou le commutateur -w, Perl vous avertira de tout mot de ce type. Perl limite les barewords (comme les identificateurs) à environ 250 caractères. Les futures versions de Perl élimineront probablement ces limitations arbitraires.

Certaines personnes peuvent souhaiter interdire complètement les barewords. Si vous dites

use strict 'subs';

alors tout bareword qui ne serait PAS interprété comme un appel de sous-routine produira une erreur de compilation. La restriction dure jusqu’à la fin du bloc englobant. Un bloc interne peut contrer cela en disant "no strict 'subs'".

Interpolation de tableaux

Les tableaux et les tranches sont interpolés dans les chaînes entre guillemets doubles en joignant les éléments avec le délimiteur spécifié dans la variable $" ($LIST_SEPARATOR si « use English;" est spécifié), espace par défaut. Les éléments suivants sont équivalents :

$temp = join($", @ARGV);
system "echo $temp";
system "echo @ARGV";

Dans les modèles de recherche (qui subissent également une substitution à la manière des chaînes entre guillemets) il y a une ambiguïté malheureuse : "/$foo[bar]/" doit-il être interprété comme "/${foo}[bar]/" (où "[bar]" est une classe de caractères pour l’expression régulière) ou comme "/${foo[bar]}/" (où "[bar]" est l’indice du tableau @foo) ? Si @foo n’existe pas autrement, c’est évidemment une classe de caractères. Si @foo existe, Perl fait une bonne supposition à propos de "[bar]", et il a presque toujours raison. S’il se trompe, ou si vous êtes simplement paranoïaque, vous pouvez forcer l’interprétation correcte avec des accolades comme ci-dessus.

Si vous cherchez des informations sur l’utilisation des here-documents, qui étaient auparavant ici, cela a été déplacé vers « Quote and Quote-like Operators » dans perlop.

Constructeurs de valeurs de liste

Les valeurs de liste sont dénotées en séparant les valeurs individuelles par des virgules (et en encadrant la liste de parenthèses lorsque la précédence l’exige) :

(LIST)

Dans un contexte qui ne nécessite pas une valeur de liste, la valeur de ce qui ressemble à un littéral de liste est simplement la valeur du dernier élément, comme avec l’opérateur virgule de C. Par exemple,

@foo = ('cc', '-E', $bar);

affecte la valeur de liste entière à la variable tableau @foo, mais

$foo = ('cc', '-E', $bar);

affecte la valeur de la variable $bar à la variable scalaire $foo. Notez que la valeur d’un tableau réel dans un contexte scalaire est la longueur du tableau ; ce qui suit affecte la valeur 3 à $foo :

@foo = ('cc', '-E', $bar);
$foo = @foo;                # $foo obtient 3

Vous pouvez avoir une virgule optionnelle avant la parenthèse fermante d’un littéral de liste, de sorte que vous puissiez dire :

@foo = (
    1,
    2,
    3,
);

Pour utiliser un here-document afin d’affecter un tableau, une ligne par élément, vous pourriez utiliser une approche comme celle-ci :

@sauces = <<End_Lines =~ m/(\S.*\S)/g;
    normal tomato
    spicy tomato
    green chile
pesto vin blanc End_Lines

Les LISTs effectuent une interpolation automatique des sous-listes. C'est-à-dire que lorsqu'une LIST est évaluée, chaque élément de la liste est évalué dans un contexte de liste, et la valeur de liste résultante est interpolée dans la LIST comme si chaque élément individuel était un membre de la LIST. Ainsi, les tableaux et les hachages perdent leur identité dans une LIST -- la liste

(@foo,@bar,&SomeSub,%glarch)

contient tous les éléments de @foo suivis de tous les éléments de @bar, suivis de tous les éléments retournés par la sous-routine nommée SomeSub appelée dans un contexte de liste, suivis des paires clé/valeur de %glarch. Pour créer une référence de liste qui n'interpole PAS, voir perlref.

La liste nulle est représentée par (). L'interpoler dans une liste n'a aucun effet. Ainsi, ((),(),()) équivaut à (). De même, interpoler un tableau sans éléments revient au même que si aucun tableau n'avait été interpolé à ce point.

Cette interpolation se combine avec le fait que les parenthèses ouvrantes et fermantes sont facultatives (sauf lorsqu'elles sont nécessaires pour la précédence) et que les listes peuvent se terminer par une virgule facultative, ce qui signifie que plusieurs virgules dans les listes sont une syntaxe légale. La liste "1,,3" est une concaténation de deux listes, "1," et 3, la première se terminant par cette virgule facultative. "1,,3" est "(1,),(3)" est "1,3" (Et de même pour "1,,,3" est "(1,),(,),3" est "1,3" et ainsi de suite.) Bien que nous ne vous conseillions pas d'utiliser cette obfuscation.

Une valeur de liste peut également être indexée comme un tableau normal. Vous devez placer la liste entre parenthèses pour éviter toute ambiguïté. Par exemple :

# stat retourne une valeur de liste.
$time = (stat($file))[8];
# ERREUR DE SYNTAXE ICI.
$time = stat($file)[8];  # OUPS, J'AI OUBLIÉ LES PARENTHÈSES
# Trouver un chiffre hexadécimal.
$hexdigit = ('a','b','c','d','e','f')[$digit-10];
# Un "opérateur virgule inversé".
return (pop(@foo),pop(@foo))[0];

Les listes ne peuvent être assignées que lorsque chaque élément de la liste est lui-même assignable :

($x, $y, $z) = (1, 2, 3);
($map{'red'}, $map{'blue'}, $map{'green'}) = (0x00f, 0x0f0, 0xf00);

Une exception à cette règle est que vous pouvez assigner à "undef" dans une liste. Ceci est utile pour jeter certaines des valeurs de retour d'une fonction :

($dev, $ino, undef, undef, $uid, $gid) = stat($file);

Depuis Perl 5.22, vous pouvez également utiliser "(undef)x2" au lieu de "undef, undef". (Vous pouvez aussi faire "($x) x 2", ce qui est moins utile, car cela assigne à la même variable deux fois, écrasant la première valeur assignée.)

Lorsque vous assignez une liste de scalaires à un tableau, toutes les valeurs précédentes de ce tableau sont effacées et le nombre d'éléments dans le tableau sera désormais égal au nombre d'éléments dans la liste de droite -- la liste à partir de laquelle l'assignation a été faite. Le tableau se redimensionnera automatiquement pour accueillir précisément chaque élément de la liste de droite.

use warnings;
my (@xyz, $x, $y, $z);
@xyz = (1, 2, 3);
print "@xyz\n";                             # 1 2 3
@xyz = ('al', 'be', 'ga', 'de');
print "@xyz\n";                             # al be ga de
@xyz = (101, 102);
print "@xyz\n";                             # 101 102

Lorsque, cependant, vous assignez une liste de scalaires à une autre liste de scalaires, les résultats diffèrent selon que la liste de gauche -- la liste à laquelle on assigne -- a le même nombre d'éléments, plus ou moins d'éléments que la liste de droite.

($x, $y, $z) = (1, 2, 3);
print "$x $y $z\n";                         # 1 2 3
($x, $y, $z) = ('al', 'be', 'ga', 'de');
print "$x $y $z\n";                         # al be ga
($x, $y, $z) = (101, 102);
print "$x $y $z\n";                         # 101 102
# Utilisation de valeur non initialisée $z dans la concaténation (.)
# ou la chaîne à la ligne [numéro de programme] ligne [numéro de ligne].

Si le nombre de scalaires dans la liste de gauche est inférieur à celui de la liste de droite, les scalaires "supplémentaires" de la liste de droite ne seront tout simplement pas assignés.

Si le nombre de scalaires dans la liste de gauche est supérieur à celui de la liste de gauche, les scalaires "manquants" deviendront indéfinis.

($x, $y, $z) = (101, 102);
for my $el ($x, $y, $z) {
    (defined $el) ? print "$el " : print "<undef>";
}
print "\n";
                                            # 101 102 <undef>

L'affectation de liste dans un contexte scalaire retourne le nombre d'éléments produits par l'expression du côté droit de l'affectation :

$x = (($foo,$bar) = (3,2,1));       # définit $x à 3, pas à 2
$x = (($foo,$bar) = f());           # définit $x au nombre de retours de f()

Ceci est utile lorsque vous souhaitez effectuer une affectation de liste dans un contexte booléen, car la plupart des fonctions de liste retournent une liste nulle lorsqu'elles sont terminées, ce qui, lorsqu'il est assigné, produit un 0, interprété comme FAUX.

C'est aussi la source d'un idiome utile pour exécuter une fonction ou effectuer une opération dans un contexte de liste, puis compter le nombre de valeurs de retour, en assignant à une liste vide puis en utilisant cette affectation dans un contexte scalaire. Par exemple, ce code :

$count = () = $string =~ /\d+/g;

placer dans $count le nombre de groupes de chiffres trouvés dans $string. Cela se produit parce que la correspondance de motif est dans un contexte de liste (puisqu'elle est assignée à la liste vide), et retournera donc une liste de toutes les parties correspondantes de la chaîne. L'affectation de liste dans un contexte scalaire la traduira en le nombre d'éléments (ici, le nombre de fois que le motif a correspondu) et assignera cela à $count. Notez que simplement utiliser

$count = $string =~ /\d+/g;

n'aurait pas fonctionné, car une correspondance de motif dans un contexte scalaire ne retournera que vrai ou faux, plutôt qu'un décompte des correspondances.

Le dernier élément d'une affectation de liste peut être un tableau ou un hachage :

($x, $y, @rest) = split;
my($x, $y, %rest) = @_;

Vous pouvez en fait placer un tableau ou un hachage n'importe où dans la liste, mais le premier dans la liste absorbera toutes les valeurs, et tout ce qui le suit deviendra indéfini. Cela peut être utile dans un my() ou un local().

Un hachage peut être initialisé en utilisant une liste littérale contenant des paires d'éléments à interpréter comme une clé et une valeur :

# équivaut à l'affectation de carte ci-dessus
%map = ('red',0x00f,'blue',0x0f0,'green',0xf00);

Bien que les listes littérales et les tableaux nommés soient souvent interchangeables, ce n'est pas le cas pour les hachages. Ce n'est pas parce que vous pouvez indexer une valeur de liste comme un tableau normal que vous pouvez indexer une valeur de liste comme un hachage. De même, les hachages inclus comme parties d'autres listes (y compris les listes de paramètres et les listes de retour de fonctions) sont toujours aplatis en paires clé/valeur. C'est pourquoi il est parfois bon d'utiliser des références.

Il est souvent plus lisible d'utiliser l'opérateur "=>" entre les paires clé/valeur. L'opérateur "=>" est surtout un synonyme plus distinctif visuellement d'une virgule, mais il fait également en sorte que son opérande de gauche soit interprété comme une chaîne si c'est un bareword qui serait un identifiant simple légal. "=>" ne met pas de guillemets aux identifiants composés, qui contiennent des doubles deux-points. Cela le rend agréable pour initialiser des hachages :

 %map = (
              red   => 0x00f,
              blue  => 0x0f0,
              green => 0xf00,
);

ou pour initialiser des références de hachage à utiliser comme enregistrements :

$rec = {
            witch => 'Mable the Merciless',
            cat   => 'Fluffy the Ferocious',
            date  => '10/31/1776',
};

ou pour utiliser le passage de paramètres nommés à des fonctions compliquées :

$field = $query->radio_group(
            name      => 'group_name',
            values    => ['eenie','meenie','minie'],
            default   => 'meenie',
            linebreak => 'true',
            labels    => \%labels
);

Notez que le fait qu'un hachage soit initialisé dans cet ordre ne signifie pas qu'il en sortira dans cet ordre. Voir "sort" dans perlfunc pour des exemples sur la façon d'organiser un ordre de sortie.

Si une clé apparaît plus d'une fois dans la liste d'initialisation d'un hachage, la dernière occurrence l'emporte :

%circle = (
              center => [5, 10],
              center => [27, 9],
              radius => 100,
              color => [0xDF, 0xFF, 0x00],
              radius => 54,
);
# équivaut à
%circle = (
              center => [27, 9],
              color => [0xDF, 0xFF, 0x00],
              radius => 54,
);

Cela peut être utilisé pour fournir des valeurs par défaut de configuration qui peuvent être remplacées :

# les valeurs dans %args ont la priorité sur %config_defaults
%config = (%config_defaults, %args);

Sous-scripts

Un tableau peut être accédé un scalaire à la fois en spécifiant un signe dollar ("$"), puis le nom du tableau (sans le signe "@"), puis le sous-script entre crochets. Par exemple :

@myarray = (5, 50, 500, 5000);
print "The Third Element is", $myarray[2], "\n";

Les indices du tableau commencent à 0. Un sous-script négatif récupère sa valeur depuis la fin. Dans notre exemple, $myarray[-1] aurait été 5000, et $myarray[-2] aurait été 500.

Les sous-scripts de hachage sont similaires, sauf qu'au lieu de crochets, des accolades sont utilisées. Par exemple :

%scientists = 
(
    "Newton" => "Isaac",
    "Einstein" => "Albert",
    "Darwin" => "Charles",
    "Feynman" => "Richard",
);
print "Darwin's First Name is ", $scientists{"Darwin"}, "\n";

Vous pouvez également indexer une liste pour obtenir un seul élément :

$dir = (getpwnam("daemon"))[7];

Émulation de tableaux multidimensionnels

Les tableaux multidimensionnels peuvent être émulés en indexant un hachage avec une liste. Les éléments de la liste sont joints avec le séparateur de sous-script (voir "$;" dans perlvar).

$foo{$x,$y,$z}

est équivalent à

$foo{join($;, $x, $y, $z)}

Le séparateur de sous-script par défaut est "\034", le même que SUBSEP dans awk.

Tranches

Une tranche accède à plusieurs éléments d'une liste, d'un tableau ou d'un hachage.

NAME

perldata - Perl Data Structures Manual

DESCRIPTION

This document describes Perl's built-in data structures: scalars, arrays, and hashes.

While Perl has only two built-in data types (scalars and arrays), hashes are built from arrays. Scalars can hold either a string or a number. Arrays are ordered lists of scalars. Hashes are unordered associative arrays of scalars, indexed by strings.

Perl also provides references, which are scalars that refer to other scalars, arrays, or hashes. This allows you to build arbitrary nested data structures, such as arrays of arrays, hashes of arrays, etc.

Arrays

Arrays are ordered lists of scalars. They are denoted by the '@' sigil. For example:

@list = (1, 2, 3);
@names = qw(Ada Betty Carol);
@empty = ();

Array elements are accessed by index, starting from 0. The index is given in square brackets after the array name. For example:

$first = $list[0];       # $first is 1
$second = $names[1];    # $second is 'Betty'

Negative indices count from the end of the array. $-1 is the last element, $-2 is the second-to-last, and so on.

$last = $list[-1];      # $last is 3
$second_last = $names[-2]; # $second_last is 'Betty'

The special array variable \@_ is used to hold the arguments passed to a subroutine.

The number of elements in an array is returned when the array is used in a scalar context.

$count = @list;         # $count is 3

Array slicing allows you to extract a list of elements from an array.

@first_two = @list[0, 1];      # @first_two is (1, 2)
@middle = @names[1 .. 2];    # @middle is ('Betty', 'Carol')

You can assign to array slices:

@list[0, 2] = (10, 30);     # @list is now (10, 2, 30)

The special array variable $& holds the most recently matched regular expression, and @+ and @- hold the offsets of the captured substrings.

Hashes

Hashes are associative arrays, mapping keys (strings) to values (scalars). They are denoted by the '%' sigil.

%ages = (
    'Ada'   => 30,
    'Betty' => 25,
    'Carol' => 35,
);

Hash elements are accessed by key, using curly braces after the hash name.

$ada_age = $ages{'Ada'};    # $ada_age is 30

If a key does not exist, accessing it returns undef in scalar context, or an empty list in list context.

The number of key-value pairs in a hash is returned when the hash is used in a scalar context.

$count = %ages;         # $count is 3

Hash slicing allows you to extract values based on a list of keys.

@betty_carol_ages = @ages{'Betty', 'Carol'}; # @betty_carol_ages is (25, 35)

You can assign to hash slices:

@ages{'Ada', 'David'} = (31, 40); # %ages is now ('Ada' => 31, 'Betty' => 25, 'Carol' => 35, 'David' => 40)

When assigning to a hash slice, if a key doesn't exist, it's created. If it does exist, its value is updated.

The keys and values of a hash can be retrieved as lists:

@keys = keys %ages;         # @keys is ('Ada', 'Betty', 'Carol', 'David') (order unspecified)
@values = values %ages;     # @values is (31, 25, 35, 40) (order unspecified)

The order of keys and values is not guaranteed. However, iterating over keys and then accessing the hash with those keys will yield the values in a consistent order within that iteration.

The special hash variable %ENV holds the environment variables.

Scalars

Scalars are the basic data type in Perl. They can hold either a string or a number. Perl automatically converts between strings and numbers as needed.

$number = 123;
$string = "Hello, world!";
$mixed = $number . $string; # $mixed is "123Hello, world!"
$sum = $number + 5;        # $sum is 128

When a scalar is used in a numeric context, it's interpreted as a number. When used in a string context, it's interpreted as a string.

The undef value represents an uninitialized or undefined scalar. It has no numeric or string value.

$uninitialized; # is undef
if (defined $uninitialized) { ... }

Perl provides several special scalar variables, including:

  • $_: The default variable for many operations.
  • $.: The current input line number.
  • $!: The system error string.
  • $@: The error string for eval.
  • $&: The last matched substring.
  • $`: The string preceding the last match.
  • $': The string following the last match.
  • $1, $2, etc.: Captured substrings from the last regex match.

References

References are scalars that refer to other data structures (arrays, hashes, subroutines, or even other references). They are created using the backslash operator \'.

@array = (1, 2, 3);
$aref = \@array;       # $aref is a reference to @array

%hash = (a => 1, b => 2);
$href = \%hash;        # $href is a reference to %hash

You can dereference a reference to access the original data structure. The sigil used for dereferencing matches the sigil of the data structure being referred to.

print $aref->[0];      # Prints 1 (equivalent to $aref->[0])
print $href->{'a'};     # Prints 1 (equivalent to $href->{'a'})

You can also use the arrow operator -> for dereferencing, which is particularly useful for nested structures.

$nested_array_ref = [ [1, 2], [3, 4] ];
print $nested_array_ref->[0]->[1]; # Prints 2

Anonymous arrays and hashes can be created directly:

$anon_array_ref = [1, 2, 3];
$anon_hash_ref = { a => 1, b => 2 };

References are fundamental for building complex data structures in Perl, such as nested arrays or hashes of arrays.

Lists and Slices

A list is an ordered collection of scalars. It can be created explicitly using parentheses or implicitly in various contexts.

@list1 = (1, 'hello', 3.14);
@list2 = qw(this is a list);

A list slice is a way to extract multiple elements from an array or hash using a list of indices or keys.

my @folks = qw(Alice Bob Charlie David Eve);
my @people = qw(Alice Charlie Eve);

# Array slice
my ($first, $last) = @folks[0, -1];        # $first='Alice', $last='Eve'
my @subset = @folks[1 .. 3];            # @subset is ('Bob', 'Charlie', 'David')

# Hash slice
my %ages = ( Alice => 30, Bob => 25, Charlie => 35 );
my ($alice_age, $charlie_age) = @ages{'Alice', 'Charlie'}; # $alice_age=30, $charlie_age=35

# Using a list of keys/indices directly
my @selected_folks = @folks[@people]; # Selects elements at indices 'Alice', 'Charlie', 'Eve' (not typical usage)
                                      # More commonly: my @selected_folks = @folks[0, 2, 4];

# Using values from another array as indices
my @indices = (1, 3);
my @selected_by_indices = @folks[@indices]; # @selected_by_indices is ('Bob', 'David')

It's important to distinguish between an array slice and a list slice. An array slice operates on an actual array variable.

A list slice, on the other hand, operates on an anonymous list generated on the fly.

my ($him, $her) = @folks[0, -1];           # array slice
my @them = @folks[0 .. 3];                 # array slice
my ($who, $home) = @ENV{'USER', 'HOME'};   # hash slice (environment variables)
my ($uid, $dir) = (getpwnam("daemon"))[2, 7]; # list slice (from function return)

Since you can assign to a list of variables, you can also assign to an array or hash slice.

@days[3..5] = qw/Wed Thu Fri/;
@colors{'red', 'blue', 'green'} = (0xff0000, 0x0000ff, 0x00ff00);
@folks[0, -1] = @folks[-1, 0];

The previous assignments are exactly equivalent to

($days[3], $days[4], $days[5]) = qw/Wed Thu Fri/;
($colors{'red'}, $colors{'blue'}, $colors{'green'}) = (0xff0000, 0x0000ff, 0x00ff00);
($folks[0], $folks[-1]) = ($folks[-1], $folks[0]);

Since changing a slice changes the original array or hash that it's slicing, a "foreach" construct will alter some--or even all--of the values of the array or hash.

foreach (@array[ 4 .. 10 ]) { s/peter/paul/ }
foreach (@hash{qw[key1 key2]}) {
    s/^\s+//;                       # trim leading whitespace
    s/\s+$//;                       # trim trailing whitespace
    s/\b(\w)(\w*)\b/\u$1\L$2/g;     # "titlecase" words
}

As a special exception, when you slice a list (but not an array or a hash), if the list evaluates to empty, then taking a slice of that empty list will always yield the empty list in turn. Thus:

@a = ()[0,1];          # @a has no elements
@b = (@a)[0,1];        # @b has no elements
@c = (sub{return()}->())[0,1]; # @c has no elements
@d = ('a','b')[0,1];   # @d has two elements
@e = (@d)[0,1,8,9];    # @e has four elements
@f = (@d)[8,9];        # @f has two elements

This makes it easy to write loops that terminate when a null list is returned:

while ( ($home, $user) = (getpwent)[7,0] ) {
    printf "%-8s %s\n", $user, $home;
}

As noted earlier in this document, the scalar sense of list assignment is the number of elements on the right-hand side of the assignment. The null list contains no elements, so when the password file is exhausted, the result is 0, not 2.

Slices in scalar context return the last item of the slice.

@a = qw/first second third/;
%h = (first => 'A', second => 'B');
$t = @a[0, 1];                  # $t is now 'second'
$u = @h{'first', 'second'};     # $u is now 'B'

If you're confused about why you use an '@' there on a hash slice instead of a '%', think of it like this. The type of bracket (square or curly) governs whether it's an array or a hash being looked at. On the other hand, the leading symbol ('$' or '@') on the array or hash indicates whether you are getting back a singular value (a scalar) or a plural one (a list).

Key/Value Hash Slices

Starting in Perl 5.20, a hash slice operation with the % symbol is a variant of slice operation returning a list of key/value pairs rather than just values:

%h = (blonk => 2, foo => 3, squink => 5, bar => 8);
%subset = %h{'foo', 'bar'}; # key/value hash slice
# %subset is now (foo => 3, bar => 8)
%removed = delete %h{'foo', 'bar'};
# %removed is now (foo => 3, bar => 8)
# %h is now (blonk => 2, squink => 5)

However, the result of such a slice cannot be localized or assigned to. These are otherwise very much consistent with hash slices using the @ symbol.

Index/Value Array Slices

Similar to key/value hash slices (and also introduced in Perl 5.20), the % array slice syntax returns a list of index/value pairs:

@a = "a".."z";
@list = %a[3,4,6];
# @list is now (3, "d", 4, "e", 6, "g")
@removed = delete %a[3,4,6]
# @removed is now (3, "d", 4, "e", 6, "g")
# @a[3,4,6] are now undef

Note that calling "delete" on array values is strongly discouraged.

Typeglobs and Filehandles

Perl uses an internal type called a typeglob to hold an entire symbol table entry. The type prefix of a typeglob is a "*", because it represents all types. This used to be the preferred way to pass arrays and hashes by reference into a function, but now that we have real references, this is seldom needed.

The main use of typeglobs in modern Perl is to create symbol table aliases. This assignment:

*this = *that;

makes $this an alias for $that, @this an alias for @that, %this an alias for %that, &this an alias for &that, etc. Much safer is to use a reference. This:

local *Here::blue = \$There::green;

temporarily makes $Here::blue an alias for $There::green, but doesn't make @Here::blue an alias for @There::green, or %Here::blue an alias for %There::green, etc. See "Symbol Tables" in perlmod for more examples of this. Strange though this may seem, this is the basis for the whole module import/export system.

Another use for typeglobs is to pass filehandles into a function or to create new filehandles. If you need to use a typeglob to save away a filehandle, do it this way:

$fh = *STDOUT;

or perhaps as a real reference, like this:

$fh = \*STDOUT;

See perlsub for examples of using these as indirect filehandles in functions.

Typeglobs are also a way to create a local filehandle using the local() operator. These last until their block is exited, but may be passed back. For example:

sub newopen {
    my $path = shift;
    local  *FH;  # not my!
    open   (FH, $path)          or  return undef;
    return *FH;
}
$fh = newopen('/etc/passwd');

Now that we have the *foo{THING} notation, typeglobs aren't used as much for filehandle manipulations, although they're still needed to pass brand new file and directory handles into or out of functions. That's because *HANDLE{IO} only works if HANDLE has already been used as a handle. In other words, *FH must be used to create new symbol table entries; *foo{THING} cannot. When in doubt, use *FH.

All functions that are capable of creating filehandles (open(), opendir(), pipe(), socketpair(), sysopen(), socket(), and accept()) automatically create an anonymous filehandle if the handle passed to them is an uninitialized scalar variable. This allows the constructs such as "open(my $fh, ...)" and "open(local $fh,...)" to be used to create filehandles that will conveniently be closed automatically when the scope ends, provided there are no other references to them. This largely eliminates the need for typeglobs when opening filehandles that must be passed around, as in the following example:

sub myopen {
    open my $fh, "@_"
         or die "Can't open '@_': $!";
    return $fh;
}

    result is different: "my $fh='zzz'; open($fh, ...)"
