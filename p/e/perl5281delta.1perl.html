NOM

perl5281delta - Quoi de neuf pour la version perl v5.28.1

DESCRIPTION

Ce document décrit les différences entre la version 5.28.0 et la version 5.28.1.

Si vous mettez à niveau à partir d'une version antérieure comme la 5.26.0, lisez d'abord perl5280delta, qui décrit les différences entre les versions 5.26.0 et 5.28.0.

Sécurité

[CVE-2018-18311] Dépassement d'entier entraînant un dépassement de tampon et un échec de segmentation

L'arithmétique entière dans Perl_my_setenv() pourrait faire un cycle lorsque la longueur combinée du nom de la variable d'environnement et de sa valeur dépassait environ 0x7fffffff. Cela aurait pu entraîner une écriture au-delà de la fin d'un tampon alloué avec des données fournies par l'attaquant.

[GH #16560] https://github.com/Perl/perl5/issues/16560

[CVE-2018-18312] Écriture de dépassement de tampon dans le tas dans S_regatom (regcomp.c)

Une expression régulière conçue sur mesure pourrait provoquer une écriture de dépassement de tampon dans le tas lors de la compilation, permettant potentiellement l'exécution de code arbitraire.

[GH #16649] https://github.com/Perl/perl5/issues/16649

Changements incompatibles

Il n'y a pas de changements intentionnellement incompatibles avec la version 5.28.0. S'il en existe, ce sont des bugs, et nous vous demandons de soumettre un rapport. Voir "Signalement de bugs" ci-dessous.

Modules et Pragmata

Modules et Pragmata mis à jour

•
Module::CoreList a été mis à jour de la version 5.20180622 à 5.20181129_28.

Corrections de bugs sélectionnées

  • Perl 5.28 a introduit une optimisation de index() lors de la comparaison à -1 (ou indirectement, par exemple >= 0). Lorsque cette optimisation était déclenchée dans une clause "when", elle provoquait un avertissement ("Argument %s isn't numeric in smart match"). Ceci est maintenant corrigé. [GH #16626] https://github.com/Perl/perl5/issues/16626
  • La correspondance des chiffres décimaux dans les séquences de scripts, introduite dans Perl 5.28, présentait un bug qui conduisait à ce que "1\N{THAI DIGIT FIVE}" corresponde à "/^(*sr:\d+)$/" alors qu'il ne le devrait pas. Ceci est maintenant corrigé.
  • Le nouveau code de modification sur place ne fuit plus les descripteurs de répertoire. [GH #16602] https://github.com/Perl/perl5/issues/16602

Remerciements

Perl 5.28.1 représente environ 5 mois de développement depuis Perl 5.28.0 et contient environ 6 100 lignes de modifications réparties sur 44 fichiers de 12 auteurs.

En excluant les fichiers générés automatiquement, la documentation et les outils de publication, il y a eu environ 700 lignes de modifications apportées à 12 fichiers .pm, .t, .c et .h.

Perl continue de prospérer pour sa quatrième décennie grâce à une communauté dynamique d'utilisateurs et de développeurs. Les personnes suivantes sont connues pour avoir contribué aux améliorations qui sont devenues Perl 5.28.1 :

Signalement de bugs

Si vous trouvez ce qui vous semble être un bug, vous pourriez consulter la base de données des bugs de Perl à l'adresse https://rt.perl.org/ . Il peut également y avoir des informations sur http://www.perl.org/ , la page d'accueil de Perl.

Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus dans votre version. Assurez-vous de réduire votre bug à un cas de test minuscule mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl.

Si le bug que vous signalez a des implications de sécurité qui le rendent inapproprié à l'envoi sur une liste de diffusion publiquement archivée, alors consultez "INFORMATIONS DE CONTACT POUR LES VULNÉRABILITÉS DE SÉCURITÉ" dans perlsec pour plus de détails sur la manière de signaler le problème.

Remercier

Si vous souhaitez remercier les Perl 5 Porters pour le travail accompli dans Perl 5, vous pouvez le faire en exécutant le programme "perlthanks" :

perlthanks

Cela enverra un e-mail à la liste Perl 5 Porters avec votre message de remerciement.
