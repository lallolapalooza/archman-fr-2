NAME

perlunitut - Tutoriel Perl sur Unicode

DESCRIPTION

L'époque où l'on se contentait de manipuler des chaînes de caractères est révolue. Il est bien établi que les programmes modernes doivent être capables de communiquer des lettres avec des accents bizarres, et des choses comme les symboles euro. Cela signifie que les programmeurs doivent adopter de nouvelles habitudes. Il est facile de programmer des logiciels compatibles avec Unicode, mais cela demande de la discipline pour bien faire les choses.

Il y a beaucoup à savoir sur les jeux de caractères et les encodages de texte. Il est probablement préférable de consacrer une journée entière à l'apprentissage de tout cela, mais les bases peuvent être apprises en quelques minutes.

Ce ne sont pas les bases les plus élémentaires, cependant. Il est supposé que vous connaissez déjà la différence entre les octets et les caractères, et que vous réalisez (et acceptez !) qu'il existe de nombreux jeux de caractères et encodages différents, et que votre programme doit être explicite à leur sujet. La lecture recommandée est "The Absolute Minimum Every Software Developer Absolutely, Positively Must Know About Unicode and Character Sets (No Excuses!)" par Joel Spolsky, à https://joelonsoftware.com/articles/Unicode.html.

Ce tutoriel utilise des termes plutôt absolus et ne présente qu'une vision limitée de la richesse des fonctionnalités liées aux chaînes de caractères que Perl a à offrir. Pour la plupart des projets, ces informations suffiront probablement.

Définitions

Il est important de mettre quelques choses au clair d'abord. C'est la partie la plus importante de ce tutoriel. Cette vision peut entrer en conflit avec d'autres informations que vous auriez pu trouver sur le web, mais c'est surtout parce que de nombreuses sources se trompent.

Vous devrez peut-être relire toute cette section plusieurs fois...

Unicode

Unicode est un jeu de caractères avec de la place pour de nombreux caractères. La valeur ordinale d'un caractère est appelée un point de code. (Mais en pratique, la distinction entre point de code et caractère est floue, donc les termes sont souvent utilisés indistinctement.)

Il existe de nombreux, très nombreux points de code, mais les ordinateurs travaillent avec des octets, et un octet n'a de la place que pour 256 valeurs. Unicode a beaucoup plus de caractères que cela, donc vous avez besoin d'une méthode pour les rendre accessibles.

Unicode est encodé en utilisant plusieurs encodages concurrents, dont UTF-8 est le plus utilisé. Dans un encodage Unicode, plusieurs octets successifs peuvent être utilisés pour stocker un seul point de code, ou plus simplement : un caractère.

UTF-8

UTF-8 est un encodage Unicode. Beaucoup de gens pensent qu'Unicode et UTF-8 sont la même chose, mais ce n'est pas le cas. Il existe d'autres encodages Unicode, mais une grande partie du monde s'est standardisée sur UTF-8.

UTF-8 traite les 128 premiers points de code, 0..127, de la même manière qu'ASCII. Ils ne prennent qu'un seul octet par caractère. Tous les autres caractères sont encodés sur deux à quatre octets en utilisant un schéma complexe. Heureusement, Perl s'en charge pour nous, donc nous n'avons pas à nous en soucier.

Chaînes de texte (chaînes de caractères)

Les chaînes de texte, ou chaînes de caractères, sont composées de caractères. Les octets sont hors de propos ici, tout comme les encodages. Chaque caractère est juste cela : le caractère.

Sur une chaîne de texte, vous feriez des choses comme :

$text =~ s/foo/bar/;
if ($string =~ /^\d+$/) { ... }
$text = ucfirst $text;
my $character_count = length $text;

La valeur d'un caractère ("ord", "chr") est le point de code Unicode correspondant.

Chaînes binaires (chaînes d'octets)

Les chaînes binaires, ou chaînes d'octets, sont composées d'octets. Ici, vous n'avez pas de caractères, juste des octets. Toute communication avec le monde extérieur (tout ce qui est en dehors de votre processus Perl actuel) se fait en binaire.

Sur une chaîne binaire, vous feriez des choses comme :

my (@length_content) = unpack "(V/a)*", $binary;
$binary =~ s/\x00\x0F/\xFF\xF0/;  # pour les courageux :)
print {$fh} $binary;
my $byte_count = length $binary;

Encoder

Encoder (comme verbe) est la conversion de texte en binaire. Pour encoder, vous devez spécifier l'encodage cible, par exemple "iso-8859-1" ou "UTF-8". Certains encodages, comme la gamme "iso-8859" ("latin"), ne prennent pas en charge la norme Unicode complète ; les caractères qui ne peuvent pas être représentés sont perdus lors de la conversion.

Décoder

Décoder est la conversion de binaire en texte. Pour décoder, vous devez savoir comment les données ont été encodées lors de la phase d'encodage. Et surtout, cela doit être quelque chose de décodable. Il n'est pas très logique de décoder une image PNG en une chaîne de texte.

Format interne

Perl a un format interne, un encodage qu'il utilise pour encoder les chaînes de texte afin de les stocker en mémoire. Toutes les chaînes de texte sont dans ce format interne. En fait, les chaînes de texte ne sont jamais dans un autre format !

Vous ne devriez pas vous soucier de ce qu'est ce format, car la conversion est effectuée automatiquement lorsque vous décodez ou encodez.

Votre nouvelle boîte à outils

Ajoutez à votre en-tête standard la ligne suivante :

use Encode qw(encode decode);

Ou, si vous êtes paresseux, simplement :

use Encode;

Flux d'E/S (le vrai tutoriel de 5 minutes)

Le flux typique d'entrée/sortie d'un programme est :

1. Recevoir et décoder
2. Traiter
3. Encoder et sortir

Si votre entrée est binaire et doit rester binaire, vous ne devriez pas la décoder en une chaîne de texte, bien sûr. Mais dans tous les autres cas, vous devriez la décoder.

Le décodage ne peut pas se faire de manière fiable si vous ne savez pas comment les données ont été encodées. Si vous avez le choix, c'est une bonne idée de standardiser sur UTF-8.

my $foo   = decode('UTF-8', get 'http://example.com/');
my $bar   = decode('ISO-8859-1', readline STDIN);
my $xyzzy = decode('Windows-1251', $cgi->param('foo'));

Le traitement se déroule comme vous le saviez auparavant. La seule différence est que vous utilisez maintenant des caractères au lieu d'octets. C'est très utile si vous utilisez des choses comme "substr" ou "length".

Il est important de réaliser qu'il n'y a pas d'octets dans une chaîne de texte. Bien sûr, Perl a son encodage interne pour stocker la chaîne en mémoire, mais ignorez cela. Si vous devez faire quoi que ce soit avec le nombre d'octets, il est probablement préférable de déplacer cette partie à l'étape 3, juste après avoir encodé la chaîne. Vous saurez alors exactement combien d'octets elle contiendra dans la chaîne de destination.

La syntaxe pour encoder des chaînes de texte en chaînes binaires est aussi simple que le décodage :

$body = encode('UTF-8', $body);

Si vous aviez besoin de connaître la longueur de la chaîne en octets, c'est le moment idéal pour le faire. Parce que $body est maintenant une chaîne d'octets, "length" indiquera le nombre d'octets, au lieu du nombre de caractères. Le nombre de caractères n'est plus connu, car les caractères n'existent que dans les chaînes de texte.

my $byte_count = length $body;

Et si le protocole que vous utilisez supporte un moyen de faire savoir au destinataire quel encodage de caractères vous avez utilisé, s'il vous plaît aidez le destinataire en utilisant cette fonctionnalité ! Par exemple, l'e-mail et le HTTP supportent les en-têtes MIME, vous pouvez donc utiliser l'en-tête "Content-Type". Ils peuvent aussi avoir "Content-Length" pour indiquer le nombre d'octets, ce qui est toujours une bonne idée à fournir si le nombre est connu.

"Content-Type: text/plain; charset=UTF-8",
"Content-Length: $byte_count"

RÉSUMÉ

Décodez tout ce que vous recevez, encodez tout ce que vous envoyez. (Si ce sont des données textuelles.)
