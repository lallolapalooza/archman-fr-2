PERLDEBUG(1perl) Guide du programmeur Perl PERLDEBUG(1perl)

NOM

perldebug — Débogage de Perl

DESCRIPTION

Avant tout, avez-vous essayé d'utiliser "use strict;" et "use warnings;"?

Si vous êtes novice en débogage Perl, vous préférerez peut-être lire perldebtut, qui est une introduction tutorielle au débogueur.

Si vous recherchez les détails pointus sur la façon dont le débogueur est implémenté, vous préférerez peut-être lire perldebguts.

Pour des détails techniques approfondis sur l'utilisation, consultez perl5db.pl, la documentation du débogueur lui-même.

Le Débogueur Perl

Si vous invoquez Perl avec l'option -d, votre script s'exécute sous le débogueur source de Perl. Cela fonctionne comme un environnement Perl interactif, demandant des commandes de débogueur qui vous permettent d'examiner le code source, de définir des points d'arrêt, d'obtenir des traces de pile, de modifier les valeurs des variables, etc. C'est tellement pratique que vous lancez souvent le débogueur tout seul juste pour tester des constructions Perl interactivement afin de voir ce qu'elles font. Par exemple :

$ perl -d -e 42

En Perl, le débogueur n'est pas un programme séparé comme il l'est habituellement dans un environnement compilé typique. Au lieu de cela, l'option -d indique au compilateur d'insérer des informations sources dans les arbres d'analyse qu'il s'apprête à transmettre à l'interpréteur. Cela signifie que votre code doit d'abord compiler correctement pour que le débogueur puisse l'utiliser. Ensuite, lorsque l'interpréteur démarre, il préalablement charge un fichier de bibliothèque Perl spécial contenant le débogueur.

Le programme s'arrêtera juste avant la première instruction exécutable d'exécution (mais voir ci-dessous concernant les instructions de compilation) et vous demandera d'entrer une commande de débogueur. Contrairement aux attentes populaires, chaque fois que le débogueur s'arrête et vous affiche une ligne de code, il affiche toujours la ligne qu'il est sur le point d'exécuter, plutôt que celle qu'il vient d'exécuter.

Toute commande non reconnue par le débogueur est directement exécutée ("eval"uée) comme du code Perl dans le paquet courant. (Le débogueur utilise le paquet DB pour conserver ses propres informations d'état.)

Notez que ledit "eval" est lié par une portée implicite. Par conséquent, toute variable lexicale nouvellement introduite ou tout contenu de tampon de capture modifié est perdu après l'eval. Le débogueur est un environnement agréable pour apprendre Perl, mais si vous expérimentez interactivement avec du matériel qui devrait être dans la même portée, mettez-le sur une seule ligne.

Pour tout texte entré à l'invite du débogueur, les espaces de début et de fin sont d'abord supprimés avant tout traitement ultérieur. Si une commande de débogueur coïncide avec une fonction de votre propre programme, précédez simplement la fonction de quelque chose qui ne ressemble pas à une commande de débogueur, comme un ";" initial ou peut-être un "+", ou en l'encapsulant entre parenthèses ou accolades.

Appeler le Débogueur

Il existe plusieurs façons d'appeler le débogueur :

perl -d nom_programme
Sur le programme donné identifié par "nom_programme".
perl -d -e 0
Fournir interactivement une "expression" arbitraire en utilisant "-e".
perl -d:ptkdb nom_programme
Déboguer un programme donné via l'interface graphique Devel::ptkdb.
perl -dt programme_filet_nommé
Déboguer un programme donné en utilisant des threads (expérimental).

Si Perl est appelé avec l'option "-d", la variable $^P aura une valeur vraie. Ceci est utile si vous avez besoin de savoir si votre code s'exécute sous le débogueur :

if ( $^P ) {
    # en cours d'exécution sous le débogueur
}

Voir "$^P" in perlvar pour plus d'informations sur la variable.

Commandes du Débogueur

Le débogueur interactif comprend les commandes suivantes :

h
Affiche un résumé d'aide
h [commande]
Affiche un message d'aide pour la commande de débogueur donnée.
h h
L'argument spécial "h h" produit toute la page d'aide, qui est assez longue.

Si la sortie de la commande "h h" (ou de n'importe quelle commande, d'ailleurs) défile sur votre écran, précédez la commande d'un symbole pipe initial afin qu'elle soit traitée par votre paginateur, comme dans

DB> |h h

Vous pouvez changer le paginateur utilisé via la commande "o pager=...".

p expr
Identique à "print {$DB::OUT} expr" dans le paquet courant. En particulier, parce qu'il s'agit de la propre fonction "print" de Perl, cela signifie que les structures de données imbriquées et les objets ne sont pas déchargés, contrairement à la commande "x".

Le descripteur de fichier "DB::OUT" est ouvert sur /dev/tty, indépendamment de l'endroit où STDOUT peut être redirigé.

x [maxdepth] expr
Évalue son expression dans un contexte de liste et décharge le résultat de manière formatée. Les structures de données imbriquées sont imprimées récursivement, contrairement à la vraie fonction "print" en Perl. Lors du déchargement de hachages, vous préférerez probablement 'x \%h' plutôt que 'x %h'. Voir Dumpvalue si vous souhaitez faire cela vous-même.

Le format de sortie est régi par plusieurs options décrites sous "Options Configurables".

Si "maxdepth" est inclus, il doit s'agir d'un nombre N ; la valeur est déchargée seulement N niveaux de profondeur, comme si l'option "dumpDepth" avait été temporairement définie sur N.

V [pkg [vars]]
Affiche toutes les variables (ou certaines) du paquet (par défaut "main") en utilisant un joli imprimeur de données (les hachages montrent leurs clés et leurs valeurs pour que vous voyiez ce qui est quoi, les caractères de contrôle sont rendus imprimables, etc.). Assurez-vous de ne pas y mettre le spécificateur de type (comme "$"), juste les noms des symboles, comme ceci : 
V DB filename line

Utilisez "~pattern" et "!pattern" pour des expressions régulières positives et négatives.

Ceci est similaire à l'appel de la commande "x" sur chaque variable applicable.

X [vars]
Identique à "V currentpackage [vars]".
y [level [vars]]
Affiche toutes les variables lexicales (ou certaines) (mnémonique : variables "mY") dans la portée actuelle ou level portées plus haut. Vous pouvez limiter les variables que vous voyez avec vars, qui fonctionne exactement comme pour les commandes "V" et "X". Nécessite le module PadWalker version 0.08 ou supérieure ; avertira si celui-ci n'est pas installé. La sortie est jolie, imprimée dans le même style que pour "V" et le format est contrôlé par les mêmes options.
T
Produit une trace de pile. Voir ci-dessous pour les détails sur sa sortie.
s [expr]
Pas à pas. Exécute jusqu'au début d'une autre instruction, en descendant dans les appels de sous-routine. Si une expression est fournie et inclut des appels de fonction, elle sera également exécutée pas à pas.
n [expr]
Suivant. Exécute par-dessus les appels de sous-routine, jusqu'au début de l'instruction suivante. Si une expression est fournie et inclut des appels de fonction, ces fonctions seront exécutées avec des arrêts avant chaque instruction.
r

l "PrintRet"
L'option « PrintRet » est activée (par défaut).
<CR>
Répète la dernière commande « n » ou « s ».
c [ligne|sous]
Continue, en insérant éventuellement un point d'arrêt unique à la ligne ou sous-routine spécifiée.
l
Affiche la fenêtre suivante de lignes.
l min+incr
Affiche "incr+1" lignes à partir de "min".
l min-max
Affiche les lignes de "min" à "max". "l -" est synonyme de "-".
l ligne
Affiche une seule ligne.
l sousnom
Affiche la première fenêtre de lignes de la sous-routine. *sousnom* peut être une variable contenant une référence de code.
-
Affiche la fenêtre précédente de lignes.
v [ligne]
Visualise quelques lignes de code autour de la ligne actuelle.
.
Ramène le pointeur interne du débogueur à la dernière ligne exécutée et affiche cette ligne.
f nomfichier
Commute vers la visualisation d'un autre fichier ou d'une instruction « eval ». Si *nomfichier* n'est pas un chemin complet trouvé dans les valeurs de %INC, il est considéré comme une expression régulière.

Les chaînes « eval » (lorsqu'elles sont accessibles) sont considérées comme des noms de fichiers : « f (eval 7) » et « f eval 7\b » accèdent au contenu de la 7ème chaîne « eval » (dans l'ordre d'exécution). Le contenu de « eval » actuellement exécuté et des chaînes « eval » qui définissent des sous-routines sont sauvegardés et donc accessibles.

/motif/
Recherche vers l'avant le motif (une expression régulière Perl) ; le / final est facultatif. La recherche est insensible à la casse par défaut.
?motif?
Recherche vers l'arrière le motif ; le ? final est facultatif. La recherche est insensible à la casse par défaut.
L [abw]
Liste (par défaut toutes) les actions, points d'arrêt et expressions de surveillance.
S [[!]motif]
Liste les noms de sous-routines qui correspondent [pas] au motif.
t [n]
Commute le mode de traçage (voir aussi l'option « AutoTrace »). L'argument facultatif est le nombre maximum de niveaux à tracer sous le niveau actuel ; tout ce qui est plus profond sera silencieux.
t [n] expr
Trace l'exécution de « expr ». L'argument facultatif est le nombre maximum de niveaux à tracer sous le niveau actuel ; tout ce qui est plus profond sera silencieux. Voir « Exemples de sortie de liste de cadres » dans perldebguts pour des exemples.
b
Définit un point d'arrêt sur la ligne actuelle.
b [ligne] [condition]
Définit un point d'arrêt avant la ligne donnée. Si une condition est spécifiée, elle est évaluée chaque fois que l'instruction est atteinte : un point d'arrêt n'est pris que si la condition est vraie. Les points d'arrêt ne peuvent être définis que sur des lignes qui commencent une instruction exécutable. Les conditions n'utilisent pas « if » : 
b 237 $x > 30
b 237 ++$count237 < 11
b 33 /motif/i

Si le numéro de ligne est ".", définit un point d'arrêt sur la ligne actuelle :

b . $n > 100
b [fichier]:[ligne] [condition]
Définit un point d'arrêt avant la ligne donnée dans un fichier (éventuellement différent). Si une condition est spécifiée, elle est évaluée chaque fois que l'instruction est atteinte : un point d'arrêt n'est pris que si la condition est vraie. Les points d'arrêt ne peuvent être définis que sur des lignes qui commencent une instruction exécutable. Les conditions n'utilisent pas « if » : 
b lib/MonModule.pm:237 $x > 30
b /usr/lib/perl5/site_perl/CGI.pm:100 ++$count100 < 11
b sousnom [condition]
Définit un point d'arrêt avant la première ligne de la sous-routine nommée. *sousnom* peut être une variable contenant une référence de code (dans ce cas, *condition* n'est pas prise en charge).
b postposer sousnom [condition]
Définit un point d'arrêt à la première ligne de la sous-routine après sa compilation.
b charger nomfichier
Définit un point d'arrêt avant la première ligne exécutée du *nomfichier*, qui doit être un chemin complet trouvé parmi les valeurs de %INC.
b compiler sousnom
Définit un point d'arrêt avant la première instruction exécutée après la compilation de la sous-routine spécifiée.
B ligne
Supprime un point d'arrêt de la *ligne* spécifiée.
B *
Supprime tous les points d'arrêt installés.
désactiver [fichier]:[ligne]
Désactive le point d'arrêt afin qu'il n'arrête pas l'exécution du programme. Les points d'arrêt sont activés par défaut et peuvent être réactivés en utilisant la commande « activer ».
désactiver [ligne]
Désactive le point d'arrêt afin qu'il n'arrête pas l'exécution du programme. Les points d'arrêt sont activés par défaut et peuvent être réactivés en utilisant la commande « activer ».

Ceci est fait pour un point d'arrêt dans le fichier actuel.

activer [fichier]:[ligne]
Active le point d'arrêt afin qu'il arrête l'exécution du programme.
activer [ligne]
Active le point d'arrêt afin qu'il arrête l'exécution du programme.

Ceci est fait pour un point d'arrêt dans le fichier actuel.

a [ligne] commande
Définit une action à effectuer avant l'exécution de la ligne. Si *ligne* est omise, une action est définie sur la ligne sur le point d'être exécutée. La séquence des étapes suivies par le débogueur est la suivante : 
1. vérifier s'il y a un point d'arrêt sur cette ligne
2. afficher la ligne si nécessaire (traçage)
3. effectuer les actions associées à cette ligne
4. demander à l'utilisateur s'il est à un point d'arrêt ou en mode pas à pas
5. évaluer la ligne

Par exemple, ceci affichera $foo chaque fois que la ligne 53 sera dépassée :

a 53 print "DB FOUND $foo\n"
A ligne
Supprime une action de la ligne spécifiée.
A *
Supprime toutes les actions installées.
w expr
Ajoute une expression de surveillance globale. Chaque fois qu'une variable globale surveillée change, le débogueur s'arrête et affiche les anciennes et nouvelles valeurs.
W expr
Supprime une expression de surveillance.
W *
Supprime toutes les expressions de surveillance.
o
Affiche toutes les options.
o booloption ...
Définit chaque option booléenne listée à la valeur 1.
o anyoption? ...
Affiche la valeur d'une ou plusieurs options.
o option=valeur ...
Définit la valeur d'une ou plusieurs options. Si la valeur contient des espaces internes, elle doit être mise entre guillemets. Par exemple, vous pouvez définir "o pager="less -MQeicsNfr"" pour appeler less avec ces options spécifiques. Vous pouvez utiliser des guillemets simples ou doubles, mais si vous le faites, vous devez échapper toute instance incorporée du même type de guillemets que vous avez utilisé pour commencer, ainsi que toutes les échappements qui précèdent immédiatement ce guillemet mais qui ne sont pas destinés à l'échapper lui-même. En d'autres termes, vous suivez les règles des guillemets simples quel que soit le guillemet ; par exemple : "o option='ceci n\'est pas mal'" ou "o option="Elle a dit, \"N'est-ce pas" mieux ?\""".

Pour des raisons historiques, le "=valeur" est facultatif, mais il est par défaut à 1 uniquement là où cela est sûr de le faire - c'est-à-dire, principalement pour les options booléennes. Il est toujours préférable d'assigner une valeur spécifique en utilisant "=". L' "option" peut être abrégée, mais pour des raisons de clarté, il ne faudrait probablement pas le faire. Plusieurs options peuvent être définies ensemble. Voir « Options configurables » pour une liste de celles-ci.

< ?
Liste toutes les actions Perl exécutées avant l'invite.
< [ commande ]
Définit une action (commande Perl) à exécuter avant chaque invite du débogueur. Une commande multi-lignes peut être saisie en utilisant un antislash pour les nouvelles lignes.
< *
Supprime toutes les actions Perl exécutées avant l'invite.
<< commande
Ajoute une action (commande Perl) à exécuter avant chaque invite du débogueur. Une commande multi-lignes peut être saisie en utilisant un antislash pour les nouvelles lignes.
> ?
Liste toutes les actions Perl exécutées après l'invite.
> commande
Définit une action (commande Perl) à exécuter après l'invite, lorsque vous venez de donner une commande pour reprendre l'exécution du script. Une commande multi-lignes peut être saisie en utilisant un antislash pour les nouvelles lignes (nous parions que vous n'auriez pas pu deviner cela à ce stade).
> *
Supprime toutes les actions Perl exécutées après l'invite.
>> commande
Ajoute une action (commande Perl) à exécuter après l'invite, lorsque vous venez de donner une commande pour reprendre l'exécution du script. Une commande multi-lignes peut être saisie en utilisant un antislash pour les nouvelles lignes.
{ ?
Liste toutes les commandes du débogueur exécutées avant l'invite.
{ [ commande ]
Définit une action (commande du débogueur) à exécuter avant chaque invite du débogueur. Une commande multi-lignes peut être saisie de la manière habituelle.

Étant donné que cette commande est, à certains égards, nouvelle, un avertissement est émis si vous semblez avoir accidentellement entré un bloc. Si c'est ce que vous vouliez faire, écrivez-le comme avec « ; { ... } » ou même « do { ... } ».

{ *
Supprime toutes les commandes du débogueur exécutées avant l'invite.
{{ commande
Ajoute une action (commande du débogueur) à exécuter avant chaque invite du débogueur. Une commande multi-lignes peut être saisie, si vous parvenez à deviner comment : voir ci-dessus.
! nombre
Refait une commande précédente (par défaut, la commande précédente).
! -nombre
Refait la nième commande précédente.
! motif
Refait la dernière commande qui commençait par le motif. Voir "o&#

COMMAND SUMMARY

Commands are abbreviations of the first characters of the word represented by the command, possibly followed by arguments. Many commands can be abbreviated. (e.g. `t' is equivalent to `trace'.) Some commands are only one character long. The command "o" is described below under Configurable Options.

!! cmd
Exécute cmd dans un sous-processus (lit depuis DB::IN, écrit vers DB::OUT). Voir aussi "o shellBang". Notez que le shell actuel de l'utilisateur (enfin, sa variable $ENV{SHELL}) sera utilisé, ce qui peut interférer avec l'interprétation correcte du statut de sortie ou des informations de vidage de noyau (coredump).
source file
Lit et exécute les commandes du débogueur depuis file. file peut lui-même contenir des commandes "source".
H -number
Affiche les n dernières commandes. Seules les commandes de plus d'un caractère sont listées. Si number est omis, elles sont toutes listées.
q ou ^D
Quitter. ("quit" ne fonctionne pas pour cela, sauf si vous avez créé un alias) C'est la seule façon supportée de quitter le débogueur, bien que taper "exit" deux fois puisse fonctionner.

Définissez l'option "inhibit_exit" à 0 si vous voulez pouvoir dépasser la fin du script. Vous pourriez aussi avoir besoin de définir $finished à 0 si vous voulez passer à travers la destruction globale.

R
Redémarre le débogueur en exécutant (exec()) une nouvelle session. Nous essayons de maintenir votre historique à travers cela, mais les réglages internes et les options de la ligne de commande peuvent être perdus.

Les réglages suivants sont actuellement préservés : historique, points d'arrêt, actions, options du débogueur, et les options de la ligne de commande Perl -w, -I, et -e.

|dbcmd
Exécute la commande du débogueur, en redirigeant DB::OUT vers votre pager actuel.
||dbcmd
Identique à "|dbcmd" mais DB::OUT est aussi temporairement "sélectionné".
= [alias value]
Définit un alias de commande, comme 
= quit q

ou liste les alias actuels.

command
Exécute la commande en tant qu'instruction Perl. Un point-virgule final sera ajouté. Si l'instruction Perl pourrait être confondue avec le débogueur Perl, utilisez également un point-virgule au début.
m expr
Liste les méthodes qui peuvent être appelées sur le résultat de l'expression évaluée. L'expression peut être évaluée comme une référence à un objet béni, ou à un nom de paquetage.
M
Affiche tous les modules chargés et leurs versions.
man [manpage]
Malgré son nom, cela appelle le visionneur de documentation par défaut de votre système sur la page donnée, ou sur le visionneur lui-même si manpage est omis. Si ce visionneur est man, les informations de "Config" actuelles sont utilisées pour invoquer man en utilisant le MANPATH approprié ou l'option -M manpath. Les recherches échouées de la forme "XXX" qui correspondent à des manpages connues de la forme perlXXX seront retentées. Cela vous permet de taper "man debug" ou "man op" depuis le débogueur.

Sur les systèmes traditionnellement dépourvus d'une commande man utilisable, le débogueur invoque perldoc. Parfois, cette détermination est incorrecte en raison de fournisseurs récalcitrants ou, plus heureusement, d'utilisateurs entreprenants. Si vous appartenez à l'une de ces catégories, définissez simplement manuellement la variable $DB::doccmd à l'outil de visualisation que vous souhaitez utiliser pour la documentation Perl sur votre système. Ceci peut être défini dans un fichier rc, ou par assignation directe. Nous attendons toujours un exemple fonctionnel de quelque chose comme :

$DB::doccmd = 'netscape -remote http://something.here/';

Options configurables

Le débogueur possède de nombreuses options configurables via la commande "o", soit interactivement, soit depuis l'environnement, soit depuis un fichier rc. Le fichier est nommé ./.perldb ou ~/.perldb sous Unix avec /dev/tty, perldb.ini sinon.

"recallCommand", "ShellBang"
Les caractères utilisés pour rappeler une commande ou lancer un shell. Par défaut, les deux sont réglés sur "!", ce qui est malheureux.
"pager"
Programme à utiliser pour la sortie des commandes redirigées par pager (celles commençant par un caractère "|".) Par défaut, $ENV{PAGER} sera utilisé. Parce que le débogueur utilise les caractéristiques de votre terminal actuel pour le gras et le soulignement, si le pager choisi ne transmet pas les séquences d'échappement inchangées, la sortie de certaines commandes du débogueur ne sera pas lisible lorsqu'elle sera envoyée via le pager.
"tkRunning"
Exécute Tk tout en demandant (avec ReadLine).
"signalLevel", "warnLevel", "dieLevel"
Niveau de verbosité. Par défaut, le débogueur laisse vos exceptions et avertissements tranquilles, car les modifier peut casser des programmes qui s'exécutent correctement. Il tentera d'afficher un message lors de la réception de signaux INT, BUS ou SEGV non interceptés. (Mais voir la mention des signaux dans "BUGS" ci-dessous.)

Pour désactiver ce mode sûr par défaut, réglez ces valeurs à quelque chose de supérieur à 0. À un niveau de 1, vous obtenez des traces d'appels lors de la réception de tout type d'avertissement (ce qui est souvent agaçant) ou d'exception (ce qui est souvent précieux). Malheureusement, le débogueur ne peut pas distinguer les exceptions fatales des non-fatales. Si "dieLevel" est même de 1, alors vos exceptions non-fatales sont également tracées et modifiées sans ménagement si elles proviennent de chaînes "eval'ed" ou de tout type de "eval" au sein de modules que vous tentez de charger. Si "dieLevel" est de 2, le débogueur ne se soucie pas de leur origine : il usurpe votre gestionnaire d'exceptions, affiche une trace, puis modifie toutes les exceptions avec ses propres embellissements. Cela peut peut-être être utile à des fins de traçage, mais a tendance à détruire irrémédiablement tout programme qui prend au sérieux sa gestion des exceptions.

"AutoTrace"
Mode trace (similaire à la commande "t", mais peut être mis dans "PERLDB_OPTS").
"LineInfo"
Fichier ou pipe vers lequel imprimer les informations de numéro de ligne. S'il s'agit d'un pipe (par exemple, "|visual_perl_db"), un court message est utilisé. C'est le mécanisme utilisé pour interagir avec un éditeur client ou un débogueur visuel, tel que les crochets spéciaux "vi" ou "emacs", ou le débogueur graphique "ddd".
"inhibit_exit"
Si 0, permet de dépasser la fin du script.
"PrintRet"
Affiche la valeur de retour après la commande "r" si réglée (par défaut).
"ornaments"
Affecte l'apparence de l'écran de la ligne de commande (voir Term::ReadLine). Il n'y a actuellement aucun moyen de les désactiver, ce qui peut rendre certaines sorties illisibles sur certains affichages, ou avec certains pagers. Ceci est considéré comme un bug.
"frame"
Affecte l'affichage des messages lors de l'entrée et de la sortie des sous-routines. Si "frame & 2" est faux, les messages sont affichés à l'entrée seulement. (L'affichage à la sortie pourrait être utile s'il est intercalé avec d'autres messages.)

Si "frame & 4", les arguments des fonctions sont affichés, ainsi que le contexte et les informations sur l'appelant. Si "frame & 8", les méthodes "stringify" surchargées et les "FETCH" des objets liés ("tie"d) sont activées sur les arguments affichés. Si "frame & 16", la valeur de retour de la sous-routine est affichée.

La longueur à laquelle la liste des arguments est tronquée est régie par l'option suivante :

"maxTraceLen"
Longueur de troncature de la liste des arguments lorsque le bit 4 de l'option "frame" est activé.
"windowSize"
Change la taille de la fenêtre de liste de code (la valeur par défaut est 10 lignes).

Les options suivantes affectent ce qui se passe avec les commandes "V", "X", et "x" :

"arrayDepth", "hashDepth"
Affiche seulement les N premiers éléments (vide pour tous).
"dumpDepth"
Limite la profondeur de récursion à N niveaux lors du vidage des structures. Les valeurs négatives sont interprétées comme l'infini. Défaut : infini.
"compactDump", "veryCompact"
Change le style de sortie des tableaux et des hachages. Si "compactDump", un tableau court peut être affiché sur une seule ligne.
"globPrint"
Indique s'il faut afficher le contenu des globs.
"DumpDBFiles"
Vide les tableaux contenant les fichiers débogués.
"DumpPackages"
Vide les tables de symboles des paquets.
"DumpReused"
Vide le contenu des adresses "réutilisées".
"quote", "HighBit", "undefPrint"
Change le style de vidage des chaînes. La valeur par défaut pour "quote" est "auto" ; on peut activer le format double-guillemet ou simple-guillemet en le réglant sur """ ou "'", respectivement. Par défaut, les caractères avec leur bit de poids fort activé sont affichés tels quels.
"UsageOnly"
Vidage rudimentaire de l'utilisation de la mémoire par paquetage. Calcule la taille totale des chaînes trouvées dans les variables du paquetage. Cela n'inclut pas les variables locales dans la portée du fichier d'un module, ni celles perdues dans les fermetures.
"HistFile"
Le chemin du fichier à partir duquel l'historique (en supposant un backend Term::ReadLine utilisable) sera lu au démarrage du débogueur, et vers lequel il sera sauvegardé à l'arrêt (pour la persistance entre les sessions). Semblable en concept au fichier ".bash_history" de Bash.
"HistSize"
Le nombre de lignes sauvegardées dans l'historique (en supposant "HistFile" ci-dessus).

Après la lecture du fichier rc, le débogueur lit l'environnement $ENV{PERLDB_OPTS}

OPTIONS DU DÉBOGUEUR

Vous pouvez définir des options de débogage de deux manières:

  • En définissant la variable d'environnement $ENV{PERLDB_OPTS}.
  • En utilisant la fonction parse_options() dans votre fichier rc.

Le débogueur utilise le contenu de la variable $ENV{PERLDB_OPTS} comme une chaîne d'options à analyser, comme si vous les entriez à l'invite du débogueur. Vous pouvez y placer les options d'initialisation "TTY", "noTTY", "ReadLine" et "NonStop".

Si votre fichier rc contient:

parse_options("NonStop=1 LineInfo=db.out AutoTrace");

alors votre script s'exécutera sans intervention humaine, plaçant les informations de traçage dans le fichier db.out. (Si vous l'interrompez, vous devriez réinitialiser "LineInfo" à /dev/tty si vous vous attendez à voir quelque chose.)

"TTY"
Le TTY à utiliser pour les entrées/sorties de débogage.
"noTTY"
Si défini, le débogueur passe en mode "NonStop" et ne se connectera pas à un TTY. S'il est interrompu (ou si le contrôle va au débogueur par réglage explicite de $DB::signal ou $DB::single depuis le script Perl), il se connecte à un TTY spécifié dans l'option "TTY" au démarrage, ou à un tty trouvé à l'exécution en utilisant le module "Term::Rendezvous" de votre choix.

Ce module devrait implémenter une méthode nommée "new" qui retourne un objet avec deux méthodes : "IN" et "OUT". Celles-ci devraient retourner des filehandles à utiliser respectivement pour les entrées et sorties de débogage. La méthode "new" devrait inspecter un argument contenant la valeur de $ENV{PERLDB_NOTTY} au démarrage, ou "$ENV{HOME}/.perldbtty$$" autrement. Ce fichier n'est pas inspecté pour la propriété, donc des problèmes de sécurité sont théoriquement possibles.

"ReadLine"
Si faux, le support readline dans le débogueur est désactivé afin de déboguer des applications qui utilisent elles-mêmes ReadLine.
"NonStop"
Si défini, le débogueur passe en mode non interactif jusqu'à interruption, ou programmatiquement en réglant $DB::signal ou $DB::single.

Voici un exemple d'utilisation de la variable $ENV{PERLDB_OPTS}:

$ PERLDB_OPTS="NonStop frame=2" perl -d myprogram

Cela exécutera le script myprogram sans intervention humaine, imprimant l'arbre d'appels avec les points d'entrée et de sortie. Notez que "NonStop=1 frame=2" équivaut à "N f=2", et qu'à l'origine, les options pouvaient être abrégées de manière unique par la première lettre (modulo les options "Dump*"). Il est néanmoins recommandé de toujours les écrire en toutes lettres pour la lisibilité et la compatibilité future.

D'autres exemples incluent

$ PERLDB_OPTS="NonStop LineInfo=listing frame=2" perl -d myprogram

qui exécute le script de manière non interactive, imprimant des informations sur chaque entrée dans une sous-routine et chaque ligne exécutée dans le fichier nommé listing. (Si vous l'interrompez, vous feriez mieux de réinitialiser "LineInfo" à quelque chose d'"interactif" !)

D'autres exemples incluent (en utilisant la syntaxe shell standard pour montrer les paramètres de variables d'environnement):

$ ( PERLDB_OPTS="NonStop frame=1 AutoTrace LineInfo=tperl.out"
    perl -d myprogram )

ce qui peut être utile pour déboguer un programme qui utilise Term::ReadLine lui-même. N'oubliez pas de détacher votre shell du TTY dans la fenêtre correspondant à /dev/ttyXX, par exemple, en exécutant une commande comme

$ sleep 1000000

Voir "Debugger Internals" dans perldebguts pour plus de détails.

Entrées/Sorties du Débogueur

Invite
L'invite du débogueur ressemble à 
DB<8>

ou même

DB<<17>>

où ce nombre est le numéro de commande, et que vous utiliseriez pour accéder avec le mécanisme d'historique intégré de type csh. Par exemple, "!17" répéterait la commande numéro 17. La profondeur des chevrons indique la profondeur d'imbrication du débogueur. Vous pourriez obtenir plus d'un jeu de chevrons, par exemple, si vous étiez déjà à un point d'arrêt puis que vous affichiez le résultat d'un appel de fonction qui a lui-même un point d'arrêt, ou si vous passez dans une expression via la commande "s/n/t expression".

Commandes multilignes
Si vous souhaitez entrer une commande multiligne, telle qu'une définition de sous-routine avec plusieurs instructions ou un format, échappez le retour à la ligne qui terminerait normalement la commande du débogueur avec une barre oblique inverse. Voici un exemple : 
DB<1> for (1..4) {         \
cont:     print "ok\n";   \
cont: }
ok
ok
ok
ok

Notez que cette affaire d'échappement d'un retour à la ligne est spécifique aux commandes interactives tapées dans le débogueur.

Trace de pile
Voici un exemple de ce à quoi peut ressembler une trace de pile via la commande "T" : 
$ = main::infested called from file 'Ambulation.pm' line 10
@ = Ambulation::legs(1, 2, 3, 4) called from file 'camel_flea'
                                                         line 7
$ = main::pests('bactrian', 4) called from file 'camel_flea'
                                                         line 4

Le caractère de gauche indique le contexte dans lequel la fonction a été appelée, avec "$" et "@" signifiant respectivement contexte scalaire ou liste, et "." signifiant contexte vide (qui est en fait une sorte de contexte scalaire). L'affichage ci-dessus indique que vous étiez dans la fonction "main::infested" lorsque vous avez exécuté la sortie de pile, et qu'elle a été appelée en contexte scalaire depuis la ligne 10 du fichier Ambulation.pm, mais sans aucun argument du tout, signifiant qu'elle a été appelée comme &infested. Le cadre de pile suivant montre que la fonction "Ambulation::legs" a été appelée en contexte liste depuis le fichier camel_flea avec quatre arguments. Le dernier cadre de pile montre que "main::pests" a été appelée en contexte scalaire, également depuis camel_flea, mais depuis la ligne 4.

Si vous exécutez la commande "T" depuis une instruction "use" active, la trace contiendra à la fois un cadre "require" et un cadre "eval".

Format de liste de lignes
Ceci montre les types de sortie que la commande "l" peut produire : 
  DB<<13>> l
101:        @i{@i} = ();
102:b       @isa{@i,$pack} = ()
103             if(exists $i{$prevpack} || exists $isa{$pack});
104     }
105
106     next
107==>      if(exists $isa{$pack});
108
109:a   if ($extra-- > 0) {
110:        %isa = ($pack,1);

Les lignes sur lesquelles on peut s'arrêter sont marquées par ":". Les lignes avec des points d'arrêt sont marquées par "b" et celles avec des actions par "a". La ligne qui est sur le point d'être exécutée est marquée par "==>".

Veuillez noter que le code dans les listages du débogueur peut ne pas ressembler à votre code source d'origine. Les directives de ligne et les filtres de source externes peuvent modifier le code avant que Perl ne le voie, faisant déplacer le code de ses positions d'origine ou lui donnant des formes entièrement différentes.

Liste de cadres
Lorsque l'option "frame" est définie, le débogueur affiche les sous-routines entrées (et éventuellement sorties) dans différents styles. Voir perldebguts pour des exemples incroyablement longs de ces fonctionnalités.

Débogage des instructions de compilation

Si vous avez des instructions exécutables au moment de la compilation (telles que du code dans les blocs BEGIN, UNITCHECK et CHECK ou les instructions "use"), celles-ci ne seront *pas* arrêtées par le débogueur, bien que les "require" et les blocs INIT le soient, et les instructions de compilation peuvent être tracées avec l'option "AutoTrace" définie dans "PERLDB_OPTS"). Depuis votre propre code Perl, cependant, vous pouvez transférer le contrôle au débogueur en utilisant l'instruction suivante, qui est inoffensive si le débogueur n'est pas en cours d'exécution:

$DB::single = 1;

Si vous définissez $DB::single à 2, c'est équivalent à avoir tapé la commande "n", tandis qu'une valeur de 1 signifie la commande "s". La variable $DB::trace doit être définie à 1 pour simuler avoir tapé la commande "t".

Une autre façon de déboguer le code au moment de la compilation est de démarrer le débogueur, de définir un point d'arrêt sur le chargement (load) d'un module :

  DB<7> b load f:/perllib/lib/Carp.pm
Will stop on load of 'f:/perllib/lib/Carp.pm'.

et ensuite de redémarrer le débogueur en utilisant la commande "R" (si possible). On peut utiliser "b compile subname" pour le même objectif.

Personnalisation du Débogueur

Le débogueur contient probablement suffisamment de points d'accroche de configuration pour que vous n'ayez jamais à le modifier vous-même. Vous pouvez modifier le comportement du débogueur depuis l'intérieur du débogueur en utilisant sa commande "o", depuis la ligne de commande via la variable d'environnement "PERLDB_OPTS", et depuis des fichiers de personnalisation.

Vous pouvez effectuer une personnalisation en configurant un fichier .perldb, qui contient du code d'initialisation. Par exemple, vous pourriez créer des alias comme ceux-ci (le dernier est celui que les gens s'attendent à trouver) :

$DB::alias{'len'}  = 's/^len(.*)/p length($1)/';
$DB::alias{'stop'} = 's/^stop (at|in)';
/b/'; $DB::alias{'ps'} = 's/^ps\b/p scalar /'; $DB::alias{'quit'} = 's/^quit(\s*)/exit/';

Vous pouvez modifier les options à partir de .perldb en utilisant des appels comme celui-ci ;

parse_options("NonStop=1 LineInfo=db.out AutoTrace=1 frame=2");

Le code est exécuté dans le package "DB". Notez que .perldb est traité avant le traitement de "PERLDB_OPTS". Si .perldb définit la sous-routine "afterinit", cette fonction est appelée après la fin de l'initialisation du débogueur. .perldb peut se trouver dans le répertoire courant ou dans le répertoire personnel. Comme ce fichier est sourcé par Perl et peut contenir des commandes arbitraires, pour des raisons de sécurité, il doit appartenir au superutilisateur ou à l'utilisateur courant, et ne pouvoir être écrit que par son propriétaire.

Vous pouvez simuler une entrée TTY pour le débogueur en ajoutant des commandes arbitraires à @DB::typeahead. Par exemple, votre fichier .perldb pourrait contenir :

sub afterinit { push @DB::typeahead, "b 4", "b 6"; }

Cela tenterait de définir des points d'arrêt aux lignes 4 et 6 immédiatement après l'initialisation du débogueur. Notez que @DB::typeahead n'est pas une interface supportée et est susceptible de changer dans les futures versions.

Si vous souhaitez modifier le débogueur, copiez perl5db.pl depuis la bibliothèque Perl vers un autre nom et modifiez-le à votre guise. Vous voudrez alors définir votre variable d'environnement "PERL5DB" pour qu'elle ressemble à ceci :

BEGIN { require "myperl5db.pl" }

En dernier recours, vous pourriez également utiliser "PERL5DB" pour personnaliser le débogueur en définissant directement des variables internes ou en appelant des fonctions du débogueur.

Notez que toutes les variables et fonctions qui ne sont pas documentées dans ce document (ou dans perldebguts) sont considérées comme étant à usage interne uniquement, et à ce titre, sont susceptibles de changer sans préavis.

Support Readline / Historique dans le Débogueur

Tel qu'expédié, le seul historique de ligne de commande fourni est un historique simpliste qui vérifie les points d'exclamation en début de ligne. Cependant, si vous installez les modules Term::ReadKey et l'un des modules "Term::ReadLine::*" de CPAN (comme Term::ReadLine::Gnu, Term::ReadLine::Perl, ...), vous aurez des capacités d'édition complètes, similaires à celles que fournit GNU readline(3). Recherchez-les dans le répertoire modules/by-module/Term sur CPAN. Ceux-ci ne supportent cependant pas l'édition de ligne de commande vi normale.

Une complétion rudimentaire de ligne de commande est également disponible, y compris pour les variables lexicales dans la portée courante si le module PadWalker est installé.

Sans le support Readline, vous pourriez voir les symboles "^[[A", "^[[C", "^[[B", "^[[D"", "^H", ... lors de l'utilisation des touches fléchées et/ou de la touche retour arrière.

Support de l'Éditeur pour le Débogage

Si vous avez la version GNU d'
emacs installée sur votre système, elle peut interagir avec le débogueur Perl pour fournir un environnement de développement logiciel intégré, rappelant ses interactions avec les débogueurs C.

Les versions récentes d'Emacs incluent un fichier de démarrage pour faire d'
emacs un éditeur dirigé par la syntaxe qui comprend (certains aspects de) la syntaxe de Perl. Voir perlfaq3.

Les utilisateurs de vi devraient également jeter un œil à vim et gvim, les versions avec souris et fenêtrées, pour la coloration des mots-clés Perl.

Notez que seul Perl peut réellement analyser Perl, donc tous ces outils CASE sont un peu insuffisants, surtout si vous ne programmez pas votre Perl comme le ferait un programmeur C.

Le Profileur Perl

Si vous souhaitez fournir un débogueur alternatif pour que Perl l'exécute, invoquez votre script avec un deux-points et un argument de package donnés à l'option -d. Les débogueurs alternatifs de Perl incluent un profileur Perl, Devel::NYTProf, qui est disponible séparément en tant que distribution CPAN. Pour profiler votre programme Perl dans le fichier mycode.pl, tapez simplement :

$ perl -d:NYTProf mycode.pl

Lorsque le script se termine, le profileur créera une base de données d'informations de profil que vous pourrez transformer en rapports en utilisant les outils du profileur. Voir <perlperf> pour les détails.

Débogage des Expressions Régulières

"use re 'debug'" vous permet de voir les détails techniques de la façon dont le moteur d'expressions régulières de Perl fonctionne. Pour comprendre cette sortie généralement volumineuse, il faut non seulement avoir une idée de la façon dont la correspondance d'expressions régulières fonctionne en général, mais aussi savoir comment les expressions régulières de Perl sont compilées en interne en un automate. Ces questions sont explorées en détail dans "Debugging Regular Expressions" dans perldebguts.

Débogage de l'Utilisation de la Mémoire

Perl contient un support interne pour rapporter sa propre utilisation de la mémoire, mais c'est un concept assez avancé qui nécessite une certaine compréhension du fonctionnement de l'allocation mémoire. Voir "Debugging Perl Memory Usage" dans perldebguts pour les détails.

VOIR AUSSI

Vous avez bien activé "use strict" et "use warnings", n'est-ce pas ?

perldebtut, perldebguts, perl5db.pl, re, DB, Devel::NYTProf, Dumpvalue, et perlrun.

Lors du débogage d'un script qui utilise #! et qui est donc normalement trouvé dans $PATH, l'option -S fait rechercher $PATH par perl, donc vous n'avez pas besoin de taper le chemin ou "which $scriptname".

$ perl -Sd foo.pl

BOGUES

Vous ne pouvez pas obtenir d'informations sur les frames de la pile ou déboguer de quelque manière que ce soit les fonctions qui n'ont pas été compilées par Perl, comme celles provenant d'extensions C ou C++.

Si vous modifiez vos arguments @_ dans une sous-routine (par exemple avec "shift" ou "pop"), la trace de la pile n'affichera pas les valeurs originales.

Le débogueur ne fonctionne actuellement pas en conjonction avec le commutateur de ligne de commande -W, car il n'est pas exempt d'avertissements lui-même.

Si vous êtes dans un appel système lent (comme "wait", "accept" ou "read" depuis votre clavier ou une socket) et que vous n'avez pas configuré votre propre gestionnaire $SIG{INT}, alors vous ne pourrez pas utiliser CTRL-C pour revenir au débogueur, car le propre gestionnaire $SIG{INT} du débogueur ne comprend pas qu'il doit lever une exception pour faire un longjmp(3) hors des appels systèmes lents.
