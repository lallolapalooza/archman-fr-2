PERL5243DELTA(1perl) Guide de référence du programmeur Perl PERL5243DELTA(1perl)

NOM

perl5243delta - nouveautés de la version perl v5.24.3

DESCRIPTION

Ce document décrit les différences entre la version 5.24.2 et la version 5.24.3.

Si vous effectuez une mise à niveau à partir d'une version antérieure comme la 5.24.1, lisez d'abord perl5242delta, qui décrit les différences entre la 5.24.1 et la 5.24.2.

Sécurité

[CVE-2017-12837] Dépassement de tampon dans le tas du compilateur d'expressions régulières

La compilation de certains motifs d'expressions régulières avec le modificateur insensible à la casse pouvait provoquer un dépassement de tampon dans le tas et faire planter perl. Ceci est maintenant corrigé. [GH #16021] https://github.com/Perl/perl5/issues/16021

[CVE-2017-12883] Dépassement de lecture de tampon dans l'analyseur d'expressions régulières

Pour certains types d'erreurs de syntaxe dans un motif d'expression régulière, le message d'erreur pouvait soit contenir le contenu d'une partie aléatoire, potentiellement volumineuse, de la mémoire, soit faire planter perl. Ceci est maintenant corrigé. [GH #16025] https://github.com/Perl/perl5/issues/16025

[CVE-2017-12814] Dépassement de tampon dans la pile pour $ENV{$key} sous Windows

Un possible dépassement de tampon dans la pile dans le code %ENV sous Windows a été corrigé en supprimant complètement le tampon, car il était superflu de toute façon. [GH #16051] https://github.com/Perl/perl5/issues/16051

Changements incompatibles

Il n'y a pas de changements intentionnellement incompatibles avec la version 5.24.2. S'il y en a, il s'agit de bugs, et nous vous prions de soumettre un rapport. Voir "Signalement de bugs" ci-dessous.

Modules et Pragmata

Modules et Pragmata mis à jour

  • Module::CoreList a été mis à jour de la version 5.20170715_24 à la version 5.20170922_24.
  • POSIX a été mis à jour de la version 1.65 à la version 1.65_01.
  • Time::HiRes a été mis à jour de la version 1.9733 à la version 1.9741.

Configuration et compilation

  • Lors de la compilation avec GCC 6 et l'optimisation au moment de l'édition des liens (l'option -flto de gcc), Configure traitait tous les symboles sondés comme présents sur le système, indépendamment de leur existence réelle. Ceci est maintenant corrigé. [GH #15322] https://github.com/Perl/perl5/issues/15322
  • Configure s'arrête maintenant si "-Duselongdouble" et "-Dusequadmath" sont tous deux demandés. [GH #14944] https://github.com/Perl/perl5/issues/14944
  • Correction d'un bug où Configure pouvait ajouter "-quadmath" au nom d'architecture même s'il était déjà présent. [GH #15423] https://github.com/Perl/perl5/issues/15423
  • Les compilations avec Clang et "-DPERL_GLOBAL_STRUCT" ou "-DPERL_GLOBAL_STRUCT_PRIVATE" ont été corrigées (en désactivant l'analyse de sécurité des threads pour ces configurations).

Corrections de bugs sélectionnées

  • "/@0{0*->@*/*0" et des constructions similaires faisaient planter perl, mais ne le font plus, produisant simplement une erreur de syntaxe. [GH #15333] https://github.com/Perl/perl5/issues/15333
  • "do" ou "require" avec un argument qui est une référence ou un typeglob qui, lorsqu'il est converti en chaîne, contient un caractère nul, faisait planter perl à partir de la version 5.20, mais cela est maintenant corrigé. [GH #15337] https://github.com/Perl/perl5/issues/15337
  • Les expressions contenant un opérateur "&&" ou "||" (ou leurs synonymes "and" et "or") étaient compilées de manière incorrecte dans certains cas. Si le côté gauche consistait en une constante de mot nu niée ou un bloc "do {}" nié contenant une expression constante, et que le côté droit consistait en une expression non repliable niée, l'une des négations était effectivement ignorée. Il en était de même pour les modificateurs d'instruction "if" et "unless", bien qu'avec les côtés gauche et droit échangés. Ce bug de longue date est maintenant corrigé. [GH #15285] https://github.com/Perl/perl5/issues/15285
  • "reset" avec un argument ne fait plus planter perl lorsqu'il rencontre des entrées de stash autres que des typeglobs. [GH #15314] https://github.com/Perl/perl5/issues/15314
  • Les affectations de hachages à, et les suppressions de, typeglobs nommés *:::::: ne provoquent plus de plantages. [GH #15307] https://github.com/Perl/perl5/issues/15307
  • Les variantes d'affectation de toutes les opérations binaires sous la fonctionnalité "bitwise" faisaient planter perl si le côté gauche était un tableau ou un hachage. [GH #15346] https://github.com/Perl/perl5/issues/15346
  • "socket" laisse maintenant le code d'erreur renvoyé par le système dans $! en cas d'échec. [GH #15383] https://github.com/Perl/perl5/issues/15383
  • L'analyse des classes de caractères POSIX invalides ne provoque plus de fuite de mémoire. [GH #15382] https://github.com/Perl/perl5/issues/15382
  • Depuis Perl 5.20, les numéros de ligne étaient incorrects (décalés de un) lorsque perl était invoqué avec le commutateur -x. Ceci est maintenant corrigé. [GH #15413] https://github.com/Perl/perl5/issues/15413
  • Certains cas obscurs de libération de sous-routines et de descripteurs de fichiers en même temps pouvaient entraîner des plantages, mais cela est maintenant corrigé. Le plantage a été introduit dans Perl 5.22. [GH #15435] NAME

    perl5243delta - novedades en Perl 5.24.3

DESCRIPTION

Ce document décrit les différences entre Perl 5.24.2 et Perl 5.24.3.

Security

Une vulnérabilité dans l'implémentation sprintf de Perl a été corrigée en évitant un possible dépassement de capacité de la mémoire. [GH #15970] https://github.com/Perl/perl5/issues/15970

Incompatible Changes

En Perl 5.24, fchown a été modifié pour ne pas accepter moins un comme argument car sur certaines plateformes, il s'agit d'une erreur. Cependant, sur d'autres plateformes, c'est un argument acceptable. Ce changement a été annulé. [GH #15523] https://github.com/Perl/perl5/issues/15523.

Modules and Pragmata

Aucun changement significatif.

Configuration and Compilation

Aucun changement significatif.

Platform Support

Aucun changement significatif.

Selected Bug Fixes

  • A bug found by T. J. Lee which caused Perl to crash when attempting to reallocate the stack, has been fixed. [GH #15435] https://github.com/Perl/perl5/issues/15435
  • Certain regular expression parsing glitches could lead to assertion failures with regular expressions such as "/(?<=/" and "/(?<!/". This has now been fixed. [GH #15332] https://github.com/Perl/perl5/issues/15332
  • "gethostent" and similar functions now perform a null check internally, to avoid crashing with the torsocks library. This was a regression from Perl 5.22. [GH #15478] https://github.com/Perl/perl5/issues/15478
  • Mentioning the same constant twice in a row (which is a syntax error) no longer fails an assertion under debugging builds. This was a regression from Perl 5.20. [GH #15017] https://github.com/Perl/perl5/issues/15017
  • In Perl 5.24 "fchown" was changed not to accept negative one as an argument because in some platforms that is an error. However, in some other platforms that is an acceptable argument. This change has been reverted. [GH #15523] https://github.com/Perl/perl5/issues/15523.
  • "@{x" followed by a newline where "x" represents a control or non-ASCII character no longer produces a garbled syntax error message or a crash. [GH #15518] https://github.com/Perl/perl5/issues/15518
  • A regression in Perl 5.24 with "tr/\N{U+...}/foo/" when the code point was between 128 and 255 has been fixed. [GH #15475] https://github.com/Perl/perl5/issues/15475.
  • Many issues relating to "printf "%a"" of hexadecimal floating point were fixed. In addition, the "subnormals" (formerly known as "denormals") floating point numbers are now supported both with the plain IEEE 754 floating point numbers (64-bit or 128-bit) and the x86 80-bit "extended precision". Note that subnormal hexadecimal floating point literals will give a warning about "exponent underflow". [GH #15495] https://github.com/Perl/perl5/issues/15495 [GH #15502] https://github.com/Perl/perl5/issues/15502 [GH #15503] https://github.com/Perl/perl5/issues/15503 [GH #15504] https://github.com/Perl/perl5/issues/15504 [GH #15505] https://github.com/Perl/perl5/issues/15505 [GH #15510] https://github.com/Perl/perl5/issues/15510 [GH #15512] https://github.com/Perl/perl5/issues/15512
  • The parser could sometimes crash if a bareword came after "evalbytes". [GH #15586] https://github.com/Perl/perl5/issues/15586
  • Fixed a place where the regex parser was not setting the syntax error correctly on a syntactically incorrect pattern. [GH #15565] https://github.com/Perl/perl5/issues/15565
  • A vulnerability in Perl's "sprintf" implementation has been fixed by avoiding a possible memory wrap. [GH #15970] https://github.com/Perl/perl5/issues/15970

Reporting Bugs

Si vous trouvez ce qui vous semble être un bug, vous pourriez consulter les articles récemment publiés sur le groupe de discussion comp.lang.perl.misc et la base de données des bugs de Perl à l'adresse https://rt.perl.org/ . Des informations peuvent également être disponibles sur http://www.perl.org/ , la page d'accueil de Perl.

Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bug à un cas de test minuscule mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl.

Si le bug que vous signalez a des implications de sécurité qui le rendent inapproprié à l'envoi à une liste de diffusion archivée publiquement, alors consultez "SECURITY VULNERABILITY CONTACT INFORMATION" dans perlsec pour les détails sur la façon de signaler le problème.
