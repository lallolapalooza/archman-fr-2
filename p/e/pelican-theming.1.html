NOM

pelican-theming - Comment créer des thèmes pour Pelican

Veuillez noter que bien que nous fassions de notre mieux pour examiner et fusionner les contributions de thèmes, elles sont soumises par la communauté Pelican et peuvent donc avoir des niveaux de support et d'interopérabilité variables.

CRÉATION DE THÈMES

Pour générer votre site en utilisant un thème que vous avez créé (ou téléchargé manuellement puis modifié), vous pouvez spécifier ce thème via l'option -t :

pelican content -s pelicanconf.py -t /projects/your-site/themes/your-theme

Si vous préférez ne pas spécifier le thème à chaque invocation, vous pouvez définir THEME dans vos paramètres pour qu'il pointe vers l'emplacement de votre thème préféré.

Structure

Pour créer votre propre thème, vous devez suivre la structure suivante :

├── static
│   ├── css
│   └── images
└── templates
    ├── archives.html         // pour afficher les archives
    ├── article.html          // traité pour chaque article
    ├── author.html           // traité pour chaque auteur
    ├── authors.html          // doit lister tous les auteurs
    ├── categories.html       // doit lister toutes les catégories
    ├── category.html         // traité pour chaque catégorie
    ├── index.html            // l'index (liste tous les articles)
    ├── page.html             // traité pour chaque page
    ├── period_archives.html  // pour afficher les archives par période
    ├── tag.html              // traité pour chaque tag
    └── tags.html             // doit lister tous les tags. Peut être un nuage de tags.
  • static contient tous les actifs statiques, qui seront copiés dans le dossier de sortie theme. La disposition du système de fichiers ci-dessus comprend des dossiers css et images, mais ce ne sont que des exemples. Mettez ce dont vous avez besoin ici.
  • templates contient tous les modèles qui seront utilisés pour générer le contenu. Les fichiers modèles listés ci-dessus sont obligatoires ; vous pouvez ajouter vos propres modèles si cela vous aide à garder les choses organisées lors de la création de votre thème.

Modèles et Variables

L'idée est d'utiliser une syntaxe simple que vous pouvez intégrer à vos pages HTML. Ce document décrit quels modèles doivent exister dans un thème et quelles variables seront passées à chaque modèle lors de la génération.

Tous les modèles recevront les variables définies dans votre fichier de configuration, à condition qu'elles soient en majuscules. Vous pouvez y accéder directement.

Variables Communes

Tous ces paramètres seront disponibles pour tous les modèles.

Variable Description
output_file Le nom du fichier en cours de génération. Par exemple, lorsque Pelican génère la page d'accueil, output_file sera "index.html".
articles La liste des articles, triés par date décroissante. Tous les éléments sont des objets Article, vous pouvez donc accéder à leurs attributs (par exemple, titre, résumé, auteur, etc.). Parfois, ceci est masqué (par exemple, dans la page des tags). Vous y trouverez alors des informations dans la variable all_articles.
dates La même liste d'articles, mais triée par date croissante.
hidden_articles La liste des articles cachés
drafts La liste des brouillons d'articles
period_archives Un dictionnaire contenant les éléments liés aux archives par période (si activé). Voir la section Lister et Lier aux Archives par Période pour plus de détails.
authors Une liste de tuples (auteur, articles), contenant tous les auteurs et les articles correspondants (valeurs)
categories Une liste de tuples (catégorie, articles), contenant toutes les catégories et les articles correspondants (valeurs)
tags Une liste de tuples (tag, articles), contenant tous les tags et les articles correspondants (valeurs)
pages La liste des pages
hidden_pages La liste des pages cachées
draft_pages La liste des brouillons de pages

Vérification des Plugins Chargés

Pelican fournit un test Jinja plugin_enabled pour vérifier si un certain plugin est activé. Ce test accepte un nom de plugin sous forme de chaîne et renvoie un booléen. Les plugins de namespace peuvent être spécifiés par leur nom complet (pelican.plugins.plugin_name) ou par leur nom court (plugin_name). L'exemple suivant utilise le plugin webassets pour minimiser le CSS si le plugin est activé, sinon il utilise le CSS ordinaire :

{% if "webassets" is plugin_enabled %}
    {% assets filters="cssmin", output="css/style.min.css", "css/style.scss" %}
        <link rel="stylesheet" href="{{SITEURL}}/{{ASSET_URL}}">
    {% endassets %}
{% else %}
    <link rel="stylesheet" href="{{SITEURL}}/css/style.css}">
{% endif %}

article.html

Ce modèle sera traité pour chaque article, avec une sortie générée conformément au paramètre ARTICLE_SAVE_AS (Par défaut : {slug}.html). Les variables suivantes sont disponibles lors du rendu.

Variable Description
article L'objet article à afficher
category Le nom de la catégorie pour l'article actuel

Toute métadonnée que vous placez dans l'en-tête du fichier source de l'article sera disponible sous forme de champs sur l'objet article. Le nom du champ sera le même que le nom du champ de métadonnée, sauf en minuscules.

Par exemple, vous pouvez ajouter un champ appelé FacebookImage aux métadonnées de votre article, comme indiqué ci-dessous :

Titre : J'aime le Python plus que la musique
Date : 2013-11-06 10:06
Tags : personnel, python
Catégorie : Tech
Slug : python-je-l-aime-a-mourir
Auteur : Francis Cabrel
FacebookImage : http://franciscabrel.com/images/pythonlove.png

Ces nouvelles métadonnées seront disponibles sous forme de article.facebookimage dans votre modèle article.html. Cela vous permettrait, par exemple, de spécifier une image pour les balises open graph de Facebook qui changera pour chaque article :

<meta property="og:image" content="{{ article.facebookimage }}"/>

page.html

Ce modèle sera traité pour chaque page, avec une sortie générée conformément au paramètre PAGE_SAVE_AS (Par défaut : pages/{slug}.html). Les variables suivantes sont disponibles lors du rendu.

Variable Description
page L'objet page à afficher. Vous pouvez accéder à son titre, son slug et son contenu.

tag.html

Ce modèle sera traité pour chaque tag, avec une sortie générée conformément au paramètre TAG_SAVE_AS (Par défaut : tag/{slug}.html). Si la pagination est active, les pages suivantes résideront par défaut à tag/{slug}{nombre}.html.

Variable Description
tag Le nom du tag en cours de traitement
articles Articles liés à ce tag
dates Articles liés à ce tag, mais triés par date, ascendante
articles_paginator Un objet paginator pour la liste des articles
articles_page La page actuelle des articles
articles_page_precedente La page précédente d'articles (None si la page n'existe pas)
articles_page_suivante La page suivante d'articles (None si la page n'existe pas)
paginateur_dates Un objet paginateur pour la liste d'articles, triés par date, croissant
page_dates La page actuelle d'articles, triés par date, croissant
page_dates_precedente La page précédente d'articles, triés par date, croissant (None si la page n'existe pas)
page_dates_suivante La page suivante d'articles, triés par date, croissant (None si la page n'existe pas)
nom_page TAG_URL où tout ce qui suit {slug} est supprimé -- utile pour les liens de pagination

archives_periodiques.html

Ce modèle sera traité pour chaque année de vos articles si un chemin pour YEAR_ARCHIVE_SAVE_AS est défini, chaque mois si MONTH_ARCHIVE_SAVE_AS est défini, et chaque jour si DAY_ARCHIVE_SAVE_AS est défini.

Variable Description
periode Un tuple de la forme (année, mois, jour) qui indique la période temporelle actuelle. année et jour sont des nombres tandis que mois est une chaîne de caractères. Ce tuple ne contient que année si la période temporelle est une année donnée. Il contient à la fois année et mois si la période temporelle couvre des années et des mois, et ainsi de suite.
numero_periode Un tuple de la forme (année, mois, jour), comme dans periode, sauf que toutes les valeurs sont des nombres.

Vous pouvez voir un exemple de l'utilisation de periode dans le modèle archives_periodiques.html du thème "simple".

Lister et lier aux Archives Périodiques

La variable archives_periodiques peut être utilisée pour générer une liste de liens vers l'ensemble des archives périodiques que Pelican génère. En tant que variable commune, elle est disponible pour être utilisée dans n'importe quel modèle, vous pouvez donc implémenter un tel index dans un modèle personnalisé direct, ou dans une barre latérale visible sur différentes pages du site.

archives_periodiques est un dictionnaire qui peut contenir les clés année, mois et/ou jour, en fonction des paramètres *_ARCHIVE_SAVE_AS activés. La valeur correspondante est une liste de dictionnaires, où chaque dictionnaire représente une période temporelle (triée selon le paramètre NEWEST_FIRST_ARCHIVES) avec les clés et valeurs suivantes :

Clé Valeur
periode Le même tuple que décrit dans archives_periodiques.html, par exemple (2023, 'Juin', 18).
numero_periode Le même tuple que décrit dans archives_periodiques.html, par exemple (2023, 6, 18).
url L'URL de la page d'archive périodique, par exemple posts/2023/06/18/. Ceci est contrôlé par le paramètre correspondant *_ARCHIVE_URL.
sauvegarde_sous L'emplacement de sauvegarde du fichier de la page d'archive périodique, par exemple posts/2023/06/18/index.html. Ceci est utilisé en interne par Pelican et n'est généralement pas pertinent pour les thèmes.
articles Une liste d'objets Article qui appartiennent à la période temporelle.
dates Même liste que articles, mais triée selon le paramètre NEWEST_FIRST_ARCHIVES.

Voici un exemple de l'utilisation de archives_periodiques dans un modèle :

<ul>
{% for archive in period_archives.month %}
    <li>
        <a href="{{ SITEURL }}/{{ archive.url }}">
            {{ archive.period | reverse | join(' ') }} ({{ archive.articles|count }})
        </a>
    </li>
{% endfor %}
</ul>

Vous pouvez remplacer period_archives.month dans l'instruction for par period_archives.year ou period_archives.day selon la granularité de période temporelle souhaitée.

Héritage

Depuis la version 3.0, Pelican prend en charge l'héritage du thème simple, vous pouvez donc réutiliser les modèles du thème simple dans vos propres thèmes.

Si l'un des fichiers obligatoires dans le répertoire templates/ de votre thème est manquant, il sera remplacé par le modèle correspondant du thème simple. Ainsi, si la structure HTML d'un modèle du thème simple vous convient, vous n'avez pas à écrire un nouveau modèle à partir de zéro.

Vous pouvez également étendre les modèles du thème simple dans vos propres thèmes en utilisant la directive {% extends %} comme dans l'exemple suivant :

{% extends "!simple/index.html" %}   <!-- étend le modèle ``index.html`` du thème ``simple`` -->
{% extends "index.html" %}   <!-- étend "régulier" -->

Exemple

Avec ce système, il est possible de créer un thème avec seulement deux fichiers.

base.html

Le premier fichier est le modèle templates/base.html :

{% extends "!simple/base.html" %}
{% block head %}
{{ super() }}
   <link rel="stylesheet" type="text/css" href="{{ SITEURL }}/theme/css/style.css" />
{% endblock %}
1.
Sur la première ligne, nous étendons le modèle base.html du thème simple, nous n'avons donc pas à réécrire tout le fichier.
2.
Sur la troisième ligne, nous ouvrons le bloc head qui a déjà été défini dans le thème simple.
3.
Sur la quatrième ligne, la fonction super() conserve le contenu précédemment inséré dans le bloc head.
4.
Sur la cinquième ligne, nous ajoutons une feuille de style à la page.
5.
Sur la dernière ligne, nous fermons le bloc head.

Ce fichier sera étendu par tous les autres modèles, la feuille de style sera donc liée à toutes les pages.

style.css

Le second fichier est la feuille de style CSS static/css/style.css :

body {
    font-family : monospace ;
    font-size : 100% ;
    background-color : white ;
    color : #111 ;
    width : 80% ;
    min-width : 400px ;
    min-height : 200px ;
    padding : 1em ;
    margin : 5% 10% ;
    border : thin solid gray ;
    border-radius : 5px ;
    display : block ;
}
a:link    { color : blue ; text-decoration : none ;      }
a:hover   { color : blue ; text-decoration : underline ; }
a:visited { color : blue ;                               }
h1 a { color : inherit !important }
h2 a { color : inherit !important }
h3 a { color : inherit !important }
h4 a { color : inherit !important }
h5 a { color : inherit !important }
h6 a { color : inherit !important }
pre {
    margin : 2em 1em 2em 4em ;
}
#menu li {
    display : inline ;
}
#post-list {
    margin-bottom : 1em ;
    margin-top : 1em ;
}
