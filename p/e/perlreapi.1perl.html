PERLREAPI(1perl) Guide du programmeur Perl PERLREAPI(1perl)

NOM

perlreapi - Interface des plugins d'expressions régulières Perl

DESCRIPTION

Depuis Perl 5.9.5, il existe une nouvelle interface pour brancher et utiliser des moteurs d'expressions régulières autres que celui par défaut.

Chaque moteur est censé fournir un accès à une structure constante du format suivant :

typedef struct regexp_engine {
    REGEXP* (*comp) (pTHX_
                     const SV * const pattern, const U32 flags);
    I32     (*exec) (pTHX_
                     REGEXP * const rx,
                     char* stringarg,
                     char* strend, char* strbeg,
                     SSize_t minend, SV* sv,
                     void* data, U32 flags);
    char*   (*intuit) (pTHX_
                       REGEXP * const rx, SV *sv,
                       const char * const strbeg,
                       char *strpos, char *strend, U32 flags,
                       struct re_scream_pos_data_s *data);
    SV*     (*checkstr) (pTHX_ REGEXP * const rx);
    void    (*free) (pTHX_ REGEXP * const rx);
    void    (*numbered_buff_FETCH) (pTHX_
                                    REGEXP * const rx,
                                    const I32 paren,
                                    SV * const sv);
    void    (*numbered_buff_STORE) (pTHX_
                                    REGEXP * const rx,
                                    const I32 paren,
                                    SV const * const value);
    I32     (*numbered_buff_LENGTH) (pTHX_
                                     REGEXP * const rx,
                                     const SV * const sv,
                                     const I32 paren);
    SV*     (*named_buff) (pTHX_
                           REGEXP * const rx,
                           SV * const key,
                           SV * const value,
                           U32 flags);
    SV*     (*named_buff_iter) (pTHX_
                                REGEXP * const rx,
                                const SV * const lastkey,
                                const U32 flags);
    SV*     (*qr_package)(pTHX_ REGEXP * const rx);
#ifdef USE_ITHREADS
    void*   (*dupe) (pTHX_ REGEXP * const rx, CLONE_PARAMS *param);
#endif
    REGEXP* (*op_comp) (...);

Lorsque une expression régulière est compilée, son champ "engine" est ensuite défini pour pointer vers la structure appropriée, afin que lorsque l'expression régulière a besoin d'être utilisée, Perl puisse trouver les routines correctes pour le faire.

Afin d'installer un nouveau gestionnaire d'expressions régulières, $^H{regcomp} est défini comme un entier qui (lorsqu'il est correctement casté) se résout en l'une de ces structures. Lors de la compilation, la méthode "comp" est exécutée, et le champ "engine" de la structure "regexp" résultante est censé pointer à nouveau vers la même structure.

Le symbole pTHX_ dans la définition est une macro utilisée par Perl dans le contexte du multithreading pour fournir un argument supplémentaire à la routine, contenant un pointeur vers l'interpréteur qui exécute l'expression régulière. Ainsi, en multithreading, toutes les routines reçoivent un argument supplémentaire.

Callbacks

comp

REGEXP* comp(pTHX_ const SV * const pattern, const U32 flags);

Compile le motif stocké dans "pattern" en utilisant les "flags" donnés et retourne un pointeur vers une structure "REGEXP" préparée qui peut effectuer la correspondance. Voir "The REGEXP structure" ci-dessous pour une explication des champs individuels de la structure REGEXP.

Le paramètre "pattern" est le scalaire qui a été utilisé comme motif. Les versions antérieures de Perl passaient deux "char*" indiquant le début et la fin du motif chaîné ; le fragment de code suivant peut être utilisé pour obtenir les anciens paramètres :

STRLEN plen;
char*  exp = SvPV(pattern, plen);
char* xend = exp + plen;

Comme tout scalaire peut être passé comme motif, il est possible d'implémenter un moteur qui fait quelque chose avec un tableau (""ook" =~ [ qw/ eek hlagh / ]") ou avec la forme non chaînée d'une expression régulière compilée (""ook" =~ qr/eek/"). Le moteur de Perl chaînera toujours tout en utilisant le fragment de code ci-dessus, mais cela ne signifie pas que les autres moteurs doivent le faire.

Le paramètre "flags" est un champ de bits qui indique avec quels drapeaux "msixpn" l'expression régulière a été compilée. Il contient également des informations supplémentaires, telles que l'activation de "use locale".

Les drapeaux "eogc" sont retirés avant d'être passés à la routine comp. Le moteur d'expressions régulières n'a pas besoin de savoir si l'un d'eux est défini, car ces drapeaux ne devraient affecter que ce que Perl fait avec le motif et ses variables de correspondance, et non comment il est compilé et exécuté.

Au moment où le callback comp est appelé, certains de ces drapeaux ont déjà eu un effet (noté ci-dessous le cas échéant). Cependant, la plupart de leurs effets se produisent après l'exécution du callback comp, dans des routines qui lisent le champ "rx->extflags" qu'il peuple.

En général, les drapeaux doivent être conservés dans "rx->extflags" après la compilation, bien que le moteur d'expressions régulières puisse vouloir en ajouter ou en supprimer pour activer ou désactiver un comportement spécial dans Perl. Les drapeaux ainsi que tout comportement spécial qu'ils provoquent sont documentés ci-dessous :

Les modificateurs de motif :

"/m" - RXf_PMf_MULTILINE
S'il est présent dans "rx->extflags", il sera passé à "Perl_fbm_instr" par "pp_split", qui traitera la chaîne sujet comme une chaîne multiligne.
"/s" - RXf_PMf_SINGLELINE
"/i" - RXf_PMf_FOLD
"/x" - RXf_PMf_EXTENDED
S'il est présent sur une expression régulière, les commentaires "#" seront traités différemment par le tokenizer dans certains cas.

Jeux de caractères
Les règles de jeu de caractères sont déterminées par une énumération contenue dans ce champ. Ceci est encore expérimental et sujet à changement, mais l'interface actuelle retourne les règles en utilisant la fonction en ligne "get_regex_charset(const U32 flags)". La seule valeur actuellement documentée retournée est REGEX_LOCALE_CHARSET, qui est définie si "use locale" est actif. Si présent dans "rx->extflags", "split" utilisera la définition des espaces dépendante de la locale lorsque RXf_SKIPWHITE ou RXf_WHITE est actif. Les espaces ASCII sont définis conformément à isSPACE, et par les macros internes "is_utf8_space" en UTF-8, et "isSPACE_LC" sous "use locale".

Drapeaux supplémentaires :

RXf_SPLIT
Ce drapeau a été supprimé dans perl 5.18.0. "split ' '" est maintenant géré spécialement dans le parseur. RXf_SPLIT est toujours #défini, vous pouvez donc le tester. Voici comment cela fonctionnait :

Si "split" est invoqué comme "split ' '" ou sans arguments (ce qui signifie en fait "split(' ', $_)", voir split), Perl définira ce drapeau. Le moteur d'expressions régulières peut alors le vérifier et définir les drapeaux SKIPWHITE et WHITE. Pour ce faire, le moteur Perl fait :

if (flags & RXf_SPLIT && r->prelen == 1 && r->precomp[0] == ' ')
    r->extflags |= (RXf_SKIPWHITE|RXf_WHITE);

Ces drapeaux peuvent être définis lors de la compilation pour activer des optimisations dans l'opérateur "split".

RXf_SKIPWHITE
Ce drapeau a été supprimé dans perl 5.18.0. Il est toujours #défini, vous pouvez donc le définir, mais le faire n'aura aucun effet. Voici comment cela fonctionnait :

Si le drapeau est présent dans "rx->extflags" "split" supprimera les espaces du début de la chaîne sujet avant qu'elle ne soit opérée

éd. Ce qui est considéré comme un espace blanc dépend du fait que le sujet soit une chaîne UTF-8 et si le drapeau "RXf_PMf_LOCALE" est défini.

Si RXf_WHITE est défini en plus de ce drapeau, "split" se comportera comme "split " "" sous le moteur Perl.

RXf_START_ONLY
Indique à l'opérateur split de diviser la chaîne cible sur les nouvelles lignes ("\n") sans invoquer le moteur regex.

Le moteur de Perl définit ceci si le motif est "/^/" ("plen == 1 && *exp == '^'"), même sous "/^/s" ; voir split. Bien sûr, un moteur regex différent pourrait vouloir utiliser les mêmes optimisations avec une syntaxe différente.

RXf_WHITE
Indique à l'opérateur split de diviser la chaîne cible sur les espaces blancs sans invoquer le moteur regex. La définition de l'espace blanc varie en fonction du fait que la chaîne cible soit une chaîne UTF-8 et si RXf_PMf_LOCALE est défini.

Le moteur de Perl définit ce drapeau si le motif est "\s+".

RXf_NULL
Indique à l'opérateur split de diviser la chaîne cible sur les caractères. La définition du caractère varie en fonction du fait que la chaîne cible soit une chaîne UTF-8.

Le moteur de Perl définit ce drapeau sur les motifs vides, cette optimisation rend "split //" beaucoup plus rapide qu'il ne le serait autrement. C'est même plus rapide que "unpack".

RXf_NO_INPLACE_SUBST
Ajouté dans perl 5.18.0, ce drapeau indique qu'une expression régulière peut effectuer une opération qui interférerait avec la substitution sur place. Par exemple, elle pourrait contenir une assertion arrière (lookbehind) ou affecter des variables non magiques (telles que $REGMARK et $REGERROR) pendant la correspondance. "s///" ignorera certaines optimisations lorsque ce drapeau est défini.

exec

I32 exec(pTHX_ REGEXP * const rx,
         char *stringarg, char* strend, char* strbeg,
         SSize_t minend, SV* sv,
         void* data, U32 flags);

Exécute un regex. Les arguments sont

rx
L'expression régulière à exécuter.
sv
C'est le SV contre lequel la correspondance doit être effectuée. Notez que le tableau de caractères réel à faire correspondre est fourni par les arguments décrits ci-dessous ; le SV est simplement utilisé pour déterminer l'encodage UTF8, pos(), etc.
strbeg
Pointeur vers le début physique de la chaîne.
strend
Pointeur vers le caractère suivant la fin physique de la chaîne (c'est-à-dire le "\0", s'il y en a un).
stringarg
Pointeur vers la position dans la chaîne où la correspondance doit commencer ; il pourrait ne pas être égal à "strbeg" (par exemple dans une itération ultérieure de "/.../g").
minend
Longueur minimale de la chaîne (mesurée en octets à partir de "stringarg") qui doit correspondre ; si le moteur atteint la fin de la correspondance mais n'a pas atteint cette position dans la chaîne, il doit échouer.
data
Données d'optimisation ; sujettes à changement.
flags
Drapeaux d'optimisation ; sujets à changement.

intuit

char* intuit(pTHX_
            REGEXP * const rx,
            SV *sv,
            const char * const strbeg,
            char *strpos,
            char *strend,
            const U32 flags,
            struct re_scream_pos_data_s *data);

Trouve la position de départ où une correspondance regex doit être tentée, ou éventuellement si le moteur regex ne doit pas être exécuté car le motif ne peut pas correspondre. Ceci est appelé, le cas échéant, par le noyau, en fonction des valeurs du membre "extflags" de la structure "regexp".

Arguments :

rx:     le regex à faire correspondre
sv:     le SV correspondant : utilisé uniquement pour le drapeau utf8 ; la chaîne
        elle-même est accessible via les pointeurs ci-dessous. Notez que sur
        quelque chose comme un SV surchargé, SvPOK(sv) peut être faux
        et les pointeurs de chaîne peuvent pointer vers quelque chose sans rapport avec
        le SV lui-même.
strbeg: début réel de la chaîne
strpos: le point dans la chaîne où commencer la correspondance
strend: pointeur vers l'octet suivant le dernier caractère de la chaîne
flags   actuellement inutilisé ; défini à 0
data:   actuellement inutilisé ; défini à NULL

checkstr

SV* checkstr(pTHX_ REGEXP * const rx);

Retourne un SV contenant une chaîne qui doit apparaître dans le motif. Utilisé par "split" pour optimiser les correspondances.

free

void free(pTHX_ REGEXP * const rx);

Appelé par Perl lors de la libération d'un motif regex afin que le moteur puisse libérer toutes les ressources pointées par le membre "pprivate" de la structure "regexp". Ceci est uniquement responsable de la libération des données privées ; Perl s'occupera de libérer tout le reste contenu dans la structure "regexp".

Callbacks de capture numérotée

Appelé pour obtenir/définir la valeur de "$`", "$'", $& et leurs équivalents nommés, ${^PREMATCH}, ${^POSTMATCH} et ${^MATCH}, ainsi que les groupes de capture numérotés ($1, $2, ...).

Le paramètre "paren" sera 1 pour $1, 2 pour $2, etc., et aura ces valeurs symboliques pour les variables spéciales :

${^PREMATCH}  RX_BUFF_IDX_CARET_PREMATCH
${^POSTMATCH} RX_BUFF_IDX_CARET_POSTMATCH
${^MATCH}     RX_BUFF_IDX_CARET_FULLMATCH
$`            RX_BUFF_IDX_PREMATCH
$'            RX_BUFF_IDX_POSTMATCH
$&            RX_BUFF_IDX_FULLMATCH

Notez qu'en Perl 5.17.3 et versions antérieures, les trois dernières constantes étaient également utilisées pour les variantes caret des variables.

Les noms ont été choisis par analogie avec les noms des méthodes de Tie::Scalar, avec une méthode LENGTH supplémentaire pour l'efficacité. Cependant, les variables de capture nommées ne sont actuellement pas liées en interne mais implémentées via la magie.

numbered_buff_FETCH

void numbered_buff_FETCH(pTHX_ REGEXP * const rx, const I32 paren,
                         SV * const sv);

Récupère une capture numérotée spécifiée. "sv" doit être défini comme le scalaire à retourner. Le scalaire est passé comme argument plutôt que d'être retourné par la fonction car lorsque la fonction est appelée, Perl dispose déjà d'un scalaire pour stocker la valeur ; en créer un autre serait redondant. Le scalaire peut être défini avec "sv_setsv", "sv_setpvn" et fonctions similaires, voir perlapi.

Ce callback est l'endroit où Perl désintoxique ses propres variables de capture en mode de désintoxication (voir perlsec). Voir la fonction "Perl_reg_numbered_buff_fetch" dans regcomp.c pour savoir comment désintoxiquer les variables de capture si c'est quelque chose que votre moteur souhaite également faire.

numbered_buff_STORE

void    (*numbered_buff_STORE) (pTHX_
                                REGEXP * const rx,
                                const I32 paren,
                                SV const * const value);

Définit la valeur d'une variable de capture numérotée. "value" est le scalaire qui doit servir de nouvelle valeur. Il appartient au moteur de s'assurer que cette valeur est utilisée comme nouvelle valeur (ou de la rejeter).

Exemple :

if ("ook" =~ /(o*)/) {
    # 'paren' sera '1' et 'value' sera 'ee'
    $1 =~ tr/o/e/;
}

Le propre moteur de Perl générera une erreur sur toute tentative de modification des variables de capture. Pour faire cela dans un autre moteur, utilisez le callback suivant (copié de "Perl_reg_numbered_buff_store") :

void
Example_reg_numbered_buff_store(pTHX_
                                REGEXP * const rx,
                                const I32 paren,
                                SV const * const value)
{
    PERL_UNUSED_ARG(rx);
    PERL_UNUSED_ARG(paren);
    PERL_UNUSED_ARG(value);
    if (!PL_localizing)
        Perl_croak(aTHX_ PL_no_modify);
}

En réalité, Perl ne générera pas *toujours* une erreur dans une instruction qui semble modifier une variable de capture numérotée. Ceci est dû au fait que le callback STORE ne sera pas appelé si Perl peut déterminer qu'il n'a pas à modifier la valeur. C'est exactement le comportement des variables liées dans la même situation :

package CaptureVar;
use parent 'Tie::Scalar';
sub TIESCALAR { bless [] }
sub FETCH { undef }
sub STORE { die "Ceci n'est pas appelé" }
package main;
tie my $sv => "CaptureVar";
$sv =~ y/a/b/;

Parce que $sv est "undef" lorsque l'opérateur "y///" lui est appliqué, la translittération ne s'exécutera pas réellement et le programme ne "mourra" pas. C'est différent de la façon dont les versions 5.8 et antérieures se comportaient car les variables de capture étaient des variables en lecture seule à l'époque ; maintenant elles généreront simplement une erreur lors de l'affectation dans le moteur par défaut.

numbered_buff_LENGTH

I32 numbered_buff_LENGTH (pTHX_
                          REGEXP * const rx,
                          const SV * const sv,
                          const I32 paren);

Obtient la "longueur" d'une capture de variable. Il existe un callback spécial pour cela afin que Perl n'ait pas à effectuer un FETCH et à exécuter "length" sur le résultat, puisque la longueur est (dans le cas de Perl) connue à partir d'un décalage sstocké dans "rx->offs", c'est beaucoup plus efficace :

I32 s1  = rx->offs[paren].start;
I32 s2  = rx->offs[paren].end;
I32 len = t1 - s1;

C'est un peu plus complexe dans le cas de l'UTF-8, regardez ce que "Perl_reg_numbered_buff_length" fait avec is_utf8_string_loclen.

Callbacks de capture nommée

Appelés pour obtenir/définir la valeur de "%+" et "%-", ainsi que par certaines fonctions utilitaires dans re.

Il y a deux callbacks, "named_buff" est appelé dans tous les cas où les callbacks Tie::Hash FETCH, STORE, DELETE, CLEAR, EXISTS et SCALAR seraient utilisés lors de modifications de "%+" et "%-", et "named_buff_iter" dans les mêmes cas que FIRSTKEY et NEXTKEY.

Le paramètre "flags" peut être utilisé pour déterminer quelles opérations les callbacks doivent gérer. Les drapeaux suivants sont actuellement définis :

Quelle opération Tie::Hash est effectuée depuis le niveau Perl sur "%+" ou "%-", le cas échéant :

RXapif_FETCH
RXapif_STORE
RXapif_DELETE
RXapif_CLEAR
RXapif_EXISTS
RXapif_SCALAR
RXapif_FIRSTKEY
RXapif_NEXTKEY

Si "%+" ou "%-" est manipulé, le cas échéant.

RXapif_ONE /* %+ */
RXapif_ALL /* %- */

Si ceci est appelé comme "re::regname", "re::regnames" ou "re::regnames_count", le cas échéant. Les deux premiers seront combinés avec "RXapif_ONE" ou "RXapif_ALL".

RXapif_REGNAME
RXapif_REGNAMES
RXapif_REGNAMES_COUNT

En interne, "%+" et "%-" sont implémentés avec une véritable interface liée via Tie::Hash::NamedCapture. Les méthodes de ce package rappelleront ces fonctions. Cependant, l'utilisation de Tie::Hash::NamedCapture à cette fin pourrait changer dans les futures versions. Par exemple, cela pourrait être implémenté par de la magie à la place (nécessiterait une extension à mgvtbl).

SV*     (*named_buff) (pTHX_ REGEXP * const rx, SV * const key,
                       SV * const value, U32 flags);

SV*     (*named_buff_iter) (pTHX_
                            REGEXP * const rx,

qr_package

SV* qr_package(pTHX_ REGEXP * const rx);

Le paquet auquel l'objet magique qr// est béni (comme vu par "ref qr//"). Il est recommandé que les moteurs changent ceci à leur nom de paquet pour identification, même s'ils implémentent des méthodes sur l'objet.

Le paquet retourné par cette méthode devrait également avoir le paquet interne "Regexp" dans son @ISA. "qr//->isa("Regexp")" devrait toujours être vrai quel que soit le moteur utilisé.

Une implémentation exemple pourrait être :

SV*
Example_qr_package(pTHX_ REGEXP * const rx)
{
    PERL_UNUSED_ARG(rx);
    return newSVpvs("re::engine::Example");
}

Tous les appels de méthode sur un objet créé avec "qr//" seront distribués au paquet comme un objet normal.

use re::engine::Example;
my $re = qr//;
$re->meth; # distribué à re::engine::Example::meth()

Pour récupérer l'objet "REGEXP" depuis le scalaire dans une fonction XS, utilisez la macro "SvRX", voir "REGEXP Functions" dans perlapi.

void meth(SV * rv)
PPCODE:
    REGEXP * re = SvRX(sv);

dupe

void* dupe(pTHX_ REGEXP * const rx, CLONE_PARAMS *param);

Sur les compilations multithreadées, une regexp peut devoir être dupliquée afin que le motif puisse être utilisé par plusieurs threads. Cette routine est censée gérer la duplication de toute donnée privée pointée par le membre "pprivate" de la structure "regexp". Elle sera appelée avec la nouvelle structure "regexp" préconstruite comme argument, le membre "pprivate" pointera vers la **vieille** structure privée, et il incombera à cette routine de construire une copie et d'en retourner un pointeur (que Perl utilisera ensuite pour écraser le champ tel qu'il a été passé à cette routine).

Cela permet au moteur de dupliquer ses données privées, mais aussi, si nécessaire, de modifier la structure finale s'il le doit vraiment.

Sur les compilations non multithreadées, ce champ n'existe pas.

op_comp

Ceci est privé au cœur de Perl et sujet à changement. Il devrait rester nul.

La structure REGEXP

La structure REGEXP est définie dans regexp.h. Tous les moteurs d'expressions régulières doivent pouvoir construire correctement une telle structure dans leur routine "comp".

La structure REGEXP contient toutes les données que Perl doit connaître pour travailler correctement avec l'expression régulière. Elle comprend des données sur les optimisations que Perl peut utiliser pour déterminer si le moteur d'expressions régulières doit réellement être utilisé, et diverses autres informations de contrôle nécessaires pour exécuter correctement les motifs dans divers contextes, comme si le motif était ancré d'une manière ou d'une autre, quels drapeaux ont été utilisés lors de la compilation, ou si le programme contient des constructions spéciales dont Perl doit être conscient.

De plus, elle contient deux champs destinés à l'usage privé du moteur d'expressions régulières qui a compilé le motif. Ce sont les membres "intflags" et "pprivate". "pprivate" est un pointeur void vers une structure arbitraire, dont l'utilisation et la gestion relèvent de la responsabilité du moteur de compilation. Perl ne modifiera jamais aucune de ces valeurs.

/* copié de : regexp.h */
typedef struct regexp {
    /*----------------------------------------------------------------------
     * Champs requis pour la compatibilité avec les types SV
     */
    _XPV_HEAD;
    /*----------------------------------------------------------------------
     * Champs opérationnels
     */
    const struct regexp_engine* engine; /* quel moteur a créé cette regexp ? */
    REGEXP *mother_re; /* de quelle re s'agit-il d'une copie légère ? */
    HV *paren_names;   /* Hash optionnel des noms de parenthèses */
    /*----------------------------------------------------------------------
     * Informations sur la correspondance que le cœur de Perl utilise pour gérer les choses
     */
    /* voir le commentaire dans regcomp_internal.h sur le reset de branche pour comprendre
       la distinction entre les tampons de capture physiques et logiques */
    U32 nparens;                    /* nombre physique de tampons de capture */
    U32 logical_nparens;            /* nombre logique de tampons de capture */
    I32 *logical_to_parno;          /* mapper parno logique au premier physique */
    I32 *parno_to_logical;          /* mapper chaque parno physique au logique */
    I32 *parno_to_logical_next;     /* mapper chaque parno physique au suivant
                                       physique avec le même ID logique */
    SSize_t maxlen;    /* nombre maximum possible de caractères dans la chaîne à faire correspondre */
    SSize_t minlen;    /* nombre minimum possible de caractères dans la chaîne à faire correspondre */
    SSize_t minlenret; /* nombre minimum possible de caractères pour $& */
    STRLEN gofs;       /* caractères à gauche de la position à partir de laquelle nous cherchons */
                       /* données de sous-chaîne concernant les chaînes qui doivent apparaître dans
                        * la correspondance finale, utilisées pour les optimisations */
    struct reg_substr_data *substrs;
    /* données spécifiques au moteur privé */
    void *pprivate;    /* Données privées au moteur d'expressions régulières qui
                        * a créé cet objet. */
    U32 extflags;      /* Drapeaux utilisés à la fois en externe et en interne */
    U32 intflags;      /* Drapeaux internes spécifiques au moteur */
    /*----------------------------------------------------------------------
     * Données sur la dernière/courante correspondance. Elles sont modifiées pendant la correspondance
     */
    U32 lastparen;           /* parenthèse fermante la plus élevée correspondante ($+) */
    U32 lastcloseparen;      /* dernière parenthèse fermante correspondante ($^N) */
    regexp_paren_pair *offs; /* Tableau d'offsets pour (@-) et (@+) */
    char **recurse_locinput; /* utilisé pour détecter la récursion infinie, XXX: déplacer vers l'interne */
    /*---------------------------------------------------------------------- */
    /* décalage depuis le wrapper jusqu'au début du précompilé */
    PERL_BITFIELD32 pre_prefix:4;
    /* drapeaux d'origine utilisés pour compiler le motif, peut différer de
     * extflags de diverses manières */
    PERL_BITFIELD32 compflags:9;
    /*---------------------------------------------------------------------- */
    char *subbeg;       /* chaîne sauvegardée ou d'origine pour que \digit fonctionne toujours. */
    SV_SAVED_COPY       /* Si non NULL, SV qui est COW de l'original */
    SSize_t sublen;     /* Longueur de la chaîne pointée par subbeg */
    SSize_t suboffset;  /* décalage en octets de subbeg par rapport au début logique de la chaîne */
    SSize_t subcoffset; /* équivalent de suboffset, mais en caractères (pour @-/@+) */
    /*----------------------------------------------------------------------
     * Plus de champs opérationnels
     */
    CV *qr_anoncv;      /* le sub anonyme enveloppé autour de qr/(?{..})/ */
} regexp;

La plupart des champs contenus dans cette structure sont accessibles via des macros avec un préfixe de "RX_" ou "RXp_". Les champs sont discutés plus en détail ci-dessous :

"engine"

Ce champ pointe vers une structure "regexp_engine" qui contient des pointeurs vers les sous-routines à utiliser pour effectuer une correspondance. Il incombe à la routine de compilation de remplir ce champ avant de retourner l'objet regexp.

En interne, il est défini à "NULL" sauf si un moteur personnalisé est spécifié dans $^H{regcomp}. Les propres callbacks de Perl sont accessibles dans la structure pointée par "RE_ENGINE_PTR".

"mother_re"

Ceci is un pointeur vers une autre structure regexp dont celle-ci a été dérivée. Les objets "qr//" signifient que le même modèle d'expression régulière peut être utilisé dans différents contextes en même temps, et tant que les informations sur l'état de la correspondance sont stockées dans la structure (il est prévu de changer cela éventuellement), nous devons prendre en charge plusieurs copies de la structure en cours d'utilisation simultanément. Les champs relatifs au programme d'expression régulière lui-même sont copiés de la mère_re, et appartiennent à la mère_re, tandis que les variables d'état de correspondance appartiennent à la structure elle-même.

"extflags"

Ceci sera utilisé par Perl pour voir avec quels drapeaux l'expression régulière a été compilée, ceci sera normalement défini sur la valeur du paramètre flags par le callback comp. Voir la documentation de comp pour les drapeaux valides.

"minlen" "minlenret"

La longueur minimale de la chaîne (en caractères) requise pour que le modèle corresponde. Ceci est utilisé pour élaguer l'espace de recherche en évitant de correspondre plus près de la fin d'une chaîne que ce qui permettrait une correspondance. Par exemple, il est inutile de démarrer le moteur d'expression régulière si le minlen est de 10 mais que la chaîne ne fait que 5 caractères de long. Il n'y a aucun moyen que le modèle puisse correspondre.

"minlenret" est la longueur minimale (en caractères) de la chaîne qui sera trouvée dans $& après une correspondance.

La différence entre "minlen" et "minlenret" peut être vue dans le modèle suivant :

/ns(?=\d)/

où le "minlen" serait de 3 mais le "minlenret" ne serait que de 2 car le \d est requis pour correspondre mais n'est pas réellement inclus dans le contenu correspondant. Cette distinction est particulièrement importante car la logique de substitution utilise le "minlenret" pour savoir si elle peut effectuer des substitutions sur place (celles-ci peuvent entraîner une accélération considérable).

"gofs"

Décalage gauche par rapport à pos() pour commencer la correspondance.

"substrs"

Données de sous-chaîne sur les chaînes qui doivent apparaître dans la correspondance finale. Ceci est actuellement utilisé uniquement en interne par le moteur de Perl, mais pourrait être utilisé à l'avenir pour tous les moteurs pour des optimisations.

"nparens", "logical_nparens"

Ces champs sont utilisés pour suivre le nombre de groupes de capture physiques et logiques dans le modèle, qui peuvent différer si le modèle inclut l'utilisation du constructeur de réinitialisation de branche "(?| ... | ... )". Par exemple, le modèle "/(?|(foo)|(bar))/" contient deux buffers de capture physiques, mais un seul buffer de capture logique. La plupart des logiques internes du moteur d'expression régulière utilisent les identifiants des buffers de capture physiques, mais la logique exposée à l'utilisateur utilise les identifiants des buffers de capture logiques. Voir la section suivante pour les structures de données qui permettent de mapper de l'un à l'autre.

"logical_to_parno", "parno_to_logical", "parno_to_logical_next"

Ces champs facilitent la cartographie entre les numéros de buffers de capture logiques et physiques. "logical_to_parno" est un tableau dont le K-ième élément contient l'identifiant le plus bas du buffer de capture physique pour le K-ième buffer de capture logique. "parno_to_logical" est un tableau dont le K-ième élément contient le buffer de capture logique associé au K-ième buffer de capture physique. "parno_to_logical_next" est un tableau dont le K-ième élément contient le prochain buffer de capture physique avec le même identifiant logique, ou 0 s'il n'y en a pas.

Notez que ces trois tableaux sont UNIQUEMENT remplis lorsque le modèle inclut l'utilisation du concept de réinitialisation de branche. Les modèles qui n'utilisent pas la réinitialisation de branche ont effectivement un mappage 1:1 entre le logique et le physique, il n'y a donc pas besoin de ces méta-données.

Le tableau suivant donne un exemple de fonctionnement.

Pattern /(a) (?| (b) (c) (d) | (e) (f) | (g) ) (h)/
Logical: $1      $2  $3  $4    $2  $3    $2    $5
Physical: 1       2   3   4     5   6     7     8
Next:     0       5   6   0     7   0     0     0

Notez également que le 0-ième élément de n'importe lequel de ces tableaux n'est pas utilisé car il représente le "modèle entier".

"lastparen", et "lastcloseparen"

Ces champs sont utilisés pour suivre : quel était le dernier parenthèse à être fermée (voir "$+" dans perlvar) ; et quelle était la dernière parenthèse à être fermée (voir "$^N" dans perlvar).

"intflags"

La copie privée du moteur des drapeaux avec lesquels le modèle a été compilé. Généralement, c'est la même chose que "extflags" à moins que le moteur n'ait choisi d'en modifier un.

"pprivate"

Un pointeur void* vers une structure de données définie par le moteur. Le moteur Perl utilise la structure "regexp_internal" (voir "Structures de Base" dans perlreguts) mais un moteur personnalisé devrait utiliser autre chose.

"offs"

Une structure "regexp_paren_pair" qui définit les décalages dans la chaîne correspondant aux captures $& et $1, $2 etc. La structure "regexp_paren_pair" est définie comme suit :

typedef struct regexp_paren_pair {
    I32 start;
    I32 end;
} regexp_paren_pair;

Si "->offs[num].start" ou "->offs[num].end" est -1 alors ce groupe de capture n'a pas correspondu. "->offs[0].start/end" représente $& (ou "${^MATCH}" sous "/p") et "->offs[paren].end" correspond à $$paren où $paren = 1>.

"RX_PRECOMP" "RX_PRELEN"

Utilisé pour les optimisations. "RX_PRECOMP" contient une copie du modèle qui a été compilé et "RX_PRELEN" sa longueur. Lorsqu'un nouveau modèle doit être compilé (comme dans une boucle) l'opérateur interne "regcomp" vérifie si les "RX_PRECOMP" et "RX_PRELEN" de la dernière "REGEXP" compilée sont équivalents au nouveau, et si c'est le cas, utilise l'ancien modèle au lieu de compiler un nouveau.

Dans les anciennes versions de perl, ces deux macros étaient en fait des champs de la structure avec les noms "precomp" et "prelen" respectivement.

"paren_names"

C'est une table de hachage utilisée en interne pour suivre les groupes de capture nommés et leurs décalages. Les clés sont les noms des buffers, les valeurs sont des dualvars, avec le slot IV contenant le nombre de buffers portant le nom donné et le pv étant un tableau imbriqué de I32. Les valeurs peuvent également être contenues indépendamment dans le tableau de données dans les cas où des références arrière nommées sont utilisées.

"substrs"

Contient des informations sur la chaîne la plus longue qui doit apparaître à un décalage fixe par rapport au début du modèle, et la chaîne la plus longue qui doit apparaître à un décalage flottant par rapport au début du modèle. Utilisé pour effectuer des recherches Fast-Boyer-Moore sur la chaîne afin de déterminer s'il vaut la peine d'utiliser le moteur d'expression régulière et, le cas échéant, où chercher dans la chaîne.

"subbeg" "sublen" "saved_copy" "suboffset" "subcoffset"

Utilisé pendant la phase d'exécution pour gérer les modèles de recherche et remplacement, et pour fournir le texte pour $&, $1 etc. "subbeg" pointe vers un buffer (soit la chaîne d'origine, soit une copie dans le cas de RX_MATCH_COPIED(rx_sv)), et "sublen" est la longueur du buffer. Les macros "RX_OFFS_START(rx_sv,n)" et "RX_OFFS_END(rx_sv,n)" indexent dans ce buffer. tout comme la structure de données retournée par RX_OFFSp(rx_sv) mais vous ne devriez pas l'utiliser directement.

perlreapi(1) - Perl API for Regular Expression Engines

NAME

perlreapi - API Perl pour les moteurs d'expressions régulières

DESCRIPTION

Ce document décrit l'API qui est fournie par Perl pour les moteurs d'expressions régulières personnalisés.

Callbacks

Le moteur d'expressions régulières est capable de remplir le structure REGEXP avec des informations sur la manière d'utiliser le regexp compilé. L'API est principalement constituée de pointeurs vers des fonctions (callbacks).

La structure REGEXP

La structure REGEXP contient des champs pour les métadonnées et des pointeurs vers les callbacks spécifiques au moteur. L'ordre de ces champs est sujet à modification sans préavis, bien que les noms des champs le soient dans les versions récentes de Perl.

Voici quelques-uns des champs les plus courants et leurs usages:

"RXf_PMf_KEEPCOPY"
Un indicateur qui, s'il est défini, oblige le moteur à copier la chaîne d'entrée au lieu de la traiter comme s'il s'agissait d'un pointeur vers une chaîne copiable. Ceci est souvent utilisé par les opérations qui retournent une chaîne (par exemple, "s///").
Un pointeur vers la chaîne d'entrée à analyser.
Le nombre d'octets du début logique du tampon au début physique. Ceci est utilisé pour les fonctions qui traitent les tableaux et qui pourraient avoir une chaîne d'octets qui ne commence pas au début du tampon alloué.
Le nombre de caractères dans le décalage (vu par RX_SUBOFFSET). Ceci est nécessaire pour supporter "@-" et "@+", qui fonctionnent en caractères et non en octets.
"RXf_PMf_KEEPCOPY"
Il s'agit d'un champ de bits dans RX_FLAGS. S'il est défini, le moteur d'expressions régulières ne doit pas copier le tampon d'entrée dans un tampon interne qu'il utilise.
"PL_sawampersand"
Il s'agit d'un champ de bits dans RX_FLAGS. S'il est défini, le moteur d'expressions régulières ne doit pas copier le tampon d'entrée.

Lorsque ces drapeaux ne sont pas définis, le moteur doit copier le tampon (ou une partie de celui-ci) dans un tampon interne qu'il gère lui-même. Il peut choisir de ne pas copier le tampon entier (bien qu'il doive toujours le faire en présence de "RXf_PMf_KEEPCOPY" ou des bits pertinents définis dans "PL_sawampersand"). Dans ce cas, il peut définir "suboffset" pour indiquer le nombre d'octets du début logique du tampon au début physique (c.-à-d. "subbeg"). Il doit également définir "subcoffset", le nombre de caractères dans le décalage. Ce dernier est nécessaire pour supporter "@-" et "@+" qui fonctionnent en caractères, pas en octets.

"RX_WRAPPED" "RX_WRAPLEN"

Macros qui accèdent à la chaîne résultant de la stringification de "qr//". Le moteur Perl, par exemple, stocke "(?^:eek)" dans le cas de "qr/eek/".

Lorsque vous utilisez un moteur personnalisé qui ne prend pas en charge la construction "(?:)" pour les modificateurs en ligne, il est probablement préférable que "qr//" se stringifie vers le motif fourni. Notez que cela créera des motifs indésirables dans des cas comme:

my $x = qr/a|b/;  # "a|b"
my $y = qr/c/i;   # "c"
my $z = qr/$x$y/; # "a|bc"

Il n'y a pas de solution à ce problème, autre que de faire en sorte que le moteur personnalisé comprenne une construction comme "(?:)".

RX_REFCNT()

Le nombre de fois où la structure est référencée. Lorsque ce nombre tombe à 0, l'expression régulière est automatiquement libérée par un appel à "pregfree". Ceci doit être défini à 1 dans la routine de compilation de chaque moteur. Notez que dans les anciennes versions de Perl, il s'agissait d'un membre de la structure appelé "refcnt", mais dans les versions plus modernes où la structure de l'expression régulière a été unifiée avec la structure SV, il s'agit d'un alias pour SvREFCNT().
