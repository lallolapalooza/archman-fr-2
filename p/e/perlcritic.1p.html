PERLCRITIC(1p) Documentation Perl fournie par l'utilisateur PERLCRITIC(1p)

NOM

"perlcritic" - Interface en ligne de commande pour critiquer le code source Perl.

SYNTAXE

perlcritic [-12345 | --brutal | --cruel | --harsh | --stern | --gentle]
           [--severity nombre | nom] [{-p | --profile} fichier | --noprofile]
           [--top [ nombre ]] [--theme expression] [--include motif]
           [--exclude motif] [{-s | --single-policy} motif]
           [--only | --noonly] [--profile-strictness {warn|fatal|quiet}]
           [--force | --noforce] [--statistics] [--statistics-only]
           [--count | -C] [--verbose {nombre | format}] [--allow-unsafe]
           [--color | --nocolor] [--pager pager] [--quiet]
           [--color-severity-highest couleur_spec]
           [--color-severity-high couleur_spec]
           [--color-severity-medium couleur_spec]
           [--color-severity-low couleur_spec]
           [--color-severity-lowest couleur_spec]
           [--files-with-violations | -l]
           [--files-without-violations | -L]
           [--program-extensions extension_nom_fichier]
           {FICHIER | REPERTOIRE | STDIN}
perlcritic --profile-proto
perlcritic { --list | --list-enabled | --list-themes | --doc motif [...] }
perlcritic { --help | --options | --man | --version }

DESCRIPTION

"perlcritic" est un analyseur de code source Perl. C'est la façade exécutable du moteur Perl::Critic, qui tente d'identifier les constructions maladroites, difficiles à lire, sujettes aux erreurs ou non conventionnelles dans votre code. La plupart des règles sont basées sur le livre de Damian Conway, Perl Best Practices. Cependant, "perlcritic" ne se limite pas à faire respecter PBP, et il prendra même en charge des règles qui contredisent Conway. Toutes les règles peuvent être facilement configurées ou désactivées selon vos préférences.

Cette documentation ne couvre que la manière d'utiliser cette commande. Pour toutes autres informations, telles que la référence de l'API et les interfaces alternatives, veuillez consulter la documentation de Perl::Critic elle-même.

EXEMPLES D'UTILISATION

Avant de plonger dans tous les détails techniques, voici quelques exemples d'utilisation de base pour vous aider à démarrer.

# Rapporter uniquement les violations les plus sévères (gravité = 5)
perlcritic VotreModule.pm
# Identique à ci-dessus, mais lit l'entrée depuis STDIN
perlcritic
# Traiter récursivement tous les fichiers Perl sous le répertoire
perlcritic /quel/repertoire
# Rapporter les violations légèrement moins sévères aussi (gravité >= 4)
perlcritic -4 VotreModule.pm
# Identique à ci-dessus, mais en utilisant un niveau de gravité nommé
perlcritic --stern VotreModule.pm
# Rapporter toutes les violations, quelle que soit leur gravité (gravité >= 1)
perlcritic -1 VotreModule.pm
# Identique à ci-dessus, mais en utilisant un niveau de gravité nommé
perlcritic --brutal VotreModule.pm
# Rapporter uniquement les violations des choses de "Perl Best Practices"
perlcritic --theme pbp VotreModule.pm
# Rapporter les 20 violations les plus sévères (gravité >= 1)
perlcritic --top VotreModule.pm
# Rapporter des violations supplémentaires des Politiques correspondant à m/variables/xms
perlcritic --include variables VotreModule.pm
# Utiliser les configurations par défaut depuis un endroit autre que ~/.perlcriticrc
perlcritic --profile projet/spécifique/perlcriticrc VotreModule.pm

ARGUMENTS

Les arguments sont les chemins vers les fichiers que vous souhaitez analyser. Vous pouvez spécifier plusieurs fichiers. Si un argument est un répertoire, "perlcritic" analysera tous les fichiers Perl situés en dessous de ce répertoire. Si aucun argument n'est spécifié, l'entrée est lue depuis STDIN.

OPTIONS

Les noms d'options peuvent être abrégés jusqu'à l'unicité et peuvent être indiqués avec des tirets simples ou doubles, et les valeurs des options peuvent être séparées du nom de l'option par un espace ou '=' (comme avec Getopt::Long). Les noms d'options sont également sensibles à la casse.

"--profile FICHIER" ou "-p FICHIER"
Indique à "perlcritic" d'utiliser un profil nommé par FICHIER plutôt que de rechercher le fichier par défaut .perlcriticrc dans le répertoire courant ou votre répertoire personnel. Voir "CONFIGURATION" dans Perl::Critic pour plus d'informations.
"--noprofile"
Indique à "perlcritic" de ne charger aucun fichier de configuration, revenant ainsi à la configuration par défaut pour toutes les Politiques.
"--severity N"
Indique à "perlcritic" d'appliquer uniquement les Politiques dont la gravité est supérieure à "N". Les valeurs de gravité sont des entiers allant de 1 (moins sévère) à 5 (plus sévère). La valeur par défaut est 5. Pour un "--profile" donné, diminuer "--severity" produira généralement plus de violations. Vous pouvez définir la valeur par défaut de cette option dans votre fichier .perlcriticrc. Vous pouvez également redéfinir la "gravité" de toute Politique dans votre fichier .perlcriticrc. Voir "CONFIGURATION" pour plus d'informations.
"-5 | -4 | -3 | -2 | -1"
Ce sont des raccourcis numériques pour définir l'option "--severity". Par exemple, "-4" est équivalent à "--severity 4". Si plusieurs raccourcis sont spécifiés, alors le plus restrictif l'emporte. Si une option "--severity" explicite est également donnée, alors tous les raccourcis sont silencieusement ignorés. NOTE : Faites attention à ne pas placer l'une des options de raccourci numérique de gravité immédiatement après l'indicateur "--top" ou "perlcritic" l'interprétera comme le nombre de violations à signaler.
"--severity NOM"
S'il vous est difficile de vous souvenir si la gravité "5" est le niveau le plus ou le moins restrictif, alors vous pouvez utiliser l'une de ces valeurs nommées : 
NOM GRAVITÉ   ...est équivalent à...   NUMÉRO DE GRAVITÉ
--------------------------------------------------------
--severity gentle                           --severity 5
--severity stern                            --severity 4
--severity harsh                            --severity 3
--severity cruel                            --severity 2
--severity brutal                           --severity 1
"--gentle | --stern | --harsh | --cruel | --brutal"
Ce sont des raccourcis nommés pour définir l'option "--severity". Par exemple, "--cruel" est équivalent à "--severity 2". Si plusieurs raccourcis sont spécifiés, alors le plus restrictif l'emporte. Si une option "--severity" explicite est également donnée, alors tous les raccourcis sont silencieusement ignorés.
"--theme REGLE"
Indique à "perlcritic" d'appliquer uniquement les Politiques dont les thèmes satisfont la "REGLE". Les thèmes sont des noms arbitraires pour des groupes de politiques liées. Vous pouvez combiner des noms de thèmes avec des opérateurs booléens pour créer une "REGLE" arbitrairement complexe. Par exemple, ce qui suit appliquerait uniquement les Politiques qui ont un thème 'bugs' ET 'pbp' : 
$> perlcritic --theme='bugs && pbp' MonModule.pm

Sauf si l'option "--severity" est explicitement donnée, la définition de "--theme" provoque silencieusement la définition de "--severity" à 1. Vous pouvez définir la valeur par défaut de cette option dans votre fichier .perlcriticrc. Voir "THÈMES DE POLITIQUES" dans Perl::Critic pour plus d'informations sur les thèmes.

"--include MOTIF"
Indique à "perlcritic" d'appliquer des Politiques supplémentaires qui correspondent à l'expression régulière "/MOTIF/imx". Utilisez cette option pour remplacer temporairement votre profil et/ou les paramètres de gravité en ligne de commande. Par exemple : 
perlcritic --include=layout mon_fichier.pl

Cela amènera "perlcritic" à appliquer toutes les politiques "CodeLayout::*" même si leur niveau de gravité est inférieur au niveau par défaut de 5, ou si elles ont été désactivées dans votre fichier .perlcriticrc. Vous pouvez spécifier plusieurs options "--include" et vous pouvez l'utiliser en conjonction avec l'option "--exclude". Notez que "--exclude" a priorité sur

"--include" lorsqu'une politique correspond aux deux motifs. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc.

"--exclude PATTERN"
Indique à "perlcritic" de ne pas appliquer de politique qui correspond à l'expression régulière "/PATTERN/imx". Utilisez cette option pour remplacer temporairement votre profil et/ou les paramètres de gravité depuis la ligne de commande. Par exemple : 
perlcritic --exclude=strict mon_fichier.pl

Cela amènerait "perlcritic" à ne pas appliquer les politiques "RequireUseStrict" et "ProhibitNoStrict" même si elles ont le niveau de gravité le plus élevé. Vous pouvez spécifier plusieurs options "--exclude" et vous pouvez l'utiliser en conjonction avec l'option "--include". Notez que "--exclude" a la priorité sur "--include" lorsqu'une politique correspond aux deux motifs. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc.

"--single-policy PATTERN" ou "-s PATTERN"
Indique à "perlcritic" d'appliquer un seul module de politique correspondant à l'expression régulière "/PATTERN/ixms", et d'exclure toutes les autres politiques. Cette option a la priorité sur les options "--severity", "--theme", "--include", "--exclude" et "--only". Par exemple : 
perlcritic --single-policy=nowarnings mon_fichier.pl

Cela amènerait "perlcritic" à appliquer uniquement la politique "ProhibitNoWarnings", indépendamment du niveau de gravité défini. Aucune autre politique ne serait appliquée.

Ceci est équivalent à ce que l'on pourrait vouloir dire avec :

perlcritic --exclude=. --include=nowarnings mon_fichier.pl

... mais cela ne fonctionnera pas car l'option "--exclude" remplace l'option "--include".

L'équivalent de cette option peut être réalisé en créant un profil personnalisé ne contenant que la politique souhaitée, puis en exécutant...

perlcritic --profile=profilpersonnalise --only mon_fichier.pl
"--top [ N ]"
Indique à "perlcritic" de ne signaler que les "N" violations de politique les plus importantes dans chaque fichier, classées par leur gravité. Si "N" n'est pas spécifié, la valeur par défaut est 20. Si l'option "--severity" (ou l'un des raccourcis) n'est pas explicitement donnée, l'option "--top" implique que le niveau de gravité minimum est « 1 » (c'est-à-dire « brutal »). Les utilisateurs peuvent redéfinir la gravité de n'importe quelle politique dans leur fichier .perlcriticrc. Voir « CONFIGURATION » pour plus d'informations. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc. REMARQUE : Faites attention à ne pas placer l'une des options de raccourci de gravité immédiatement après l'indicateur "--top" ou "perlcritic" l'interprétera comme le nombre de violations à signaler.
"--force"
Indique à "perlcritic" d'ignorer les annotations magiques "## no critic" dans le code source. Voir « PLIER LES RÈGLES » pour plus d'informations. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc.
"--statistics"
Provoque le rapport de plusieurs statistiques sur le code analysé et les violations trouvées après toute autre sortie.
"--statistics-only"
Comme l'option "--statistics", mais supprime la sortie normale et n'affiche que les statistiques.
"--verbose N | FORMAT"
Définit le niveau de verbosité ou le format pour le rapport des violations. Si un nombre ("N") est donné, "perlcritic" signale les violations en utilisant l'un des formats prédéfinis décrits ci-dessous. Si une chaîne ("FORMAT") est donnée, elle est interprétée comme une spécification de format réelle. Si l'option "--verbose" n'est pas spécifiée, la valeur par défaut est soit 4, soit 5, selon que plusieurs fichiers ont été fournis comme arguments à "perlcritic". Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc. 
Verbosity     Format Specification
-----------   -------------------------------------------------------
 1            "%f:%l:%c:%m\n",
 2            "%f: (%l:%c) %m\n",
 3            "%m at %f line %l\n",
 4            "%m at line %l, column %c.  %e.  (Severity: %s)\n",
 5            "%f: %m at line %l, column %c.  %e.  (Severity: %s)\n",
 6            "%m at line %l, near '%r'.  (Severity: %s)\n",
 7            "%f: %m at line %l near '%r'.  (Severity: %s)\n",
 8            "[%p] %m at line %l, column %c.  (Severity: %s)\n",
 9            "[%p] %m at line %l, near '%r'.  (Severity: %s)\n",
10            "%m at line %l, column %c.\n  %p (Severity: %s)\n%d\n",
11            "%m at line %l, near '%r'.\n  %p (Severity: %s)\n%d\n"

Les formats sont une combinaison de caractères littéraux et d'échappement similaire à la façon dont fonctionne "sprintf". Voir String::Format pour une explication complète des capacités de formatage. Les caractères d'échappement valides sont :

Escape    Meaning
-------   ------------------------------------------------------------
%c        Numéro de la colonne où la violation s'est produite
%d        Discussion diagnostique complète de la violation
%e        Explication de la violation ou numéros de page dans PBP
%F        Juste le nom du fichier où la violation s'est produite.
%f        Chemin d'accès au fichier où la violation s'est produite.
%l        Numéro de la ligne où la violation s'est produite
%m        Brève description de la violation
%P        Nom complet du module de politique qui a créé la violation
%p        Nom de la politique sans le préfixe Perl::Critic::Policy::
%r        La chaîne de code source qui a causé la violation
%C        La classe de l'élément PPI::Element qui a causé la violation
%s        Le niveau de gravité de la violation

Le but de ces formats est de fournir une certaine compatibilité avec les éditeurs de texte qui ont une interface pour analyser certains types d'entrées. Voir « INTÉGRATION AVEC LES ÉDITEURS » pour plus d'informations à ce sujet.

"--list"
Affiche une liste condensée de tous les modules Perl::Critic::Policy trouvés sur cette machine. Cette option liste toutes les politiques, indépendamment de votre fichier .perlcriticrc ou des options de ligne de commande. Pour chaque politique, le nom, la gravité par défaut et les thèmes par défaut sont affichés.
"--list-enabled"
Affiche une liste condensée de tous les modules Perl::Critic::Policy qui seraient appliqués si vous critiquez réellement un fichier avec cette commande. Ceci est utile lorsque vous avez construit une commande compliquée ou modifié votre fichier .perlcriticrc et que vous voulez voir exactement quelles politiques seront appliquées (ou non appliquées, le cas échéant). Pour chaque politique, le nom, la gravité par défaut et les thèmes par défaut sont affichés.
"--list-themes"
Affiche une liste de tous les thèmes des modules Perl::Critic::Policy trouvés sur cette machine.
"--profile-proto"
Affiche une liste étendue de tous les modules Perl::Critic::Policy trouvés sur cette machine. Pour chaque politique, le nom, la gravité par défaut et les thèmes par défaut sont affichés, ainsi que le nom de tout paramètre supplémentaire que la politique prend en charge. Le format convient comme prototype pour votre fichier .perlcriticrc.
"--only"
Indique à perlcritic d'appliquer uniquement les politiques explicitement mentionnées dans votre fichier .perlcriticrc. Ceci est utile si vous souhaitez utiliser seulement un sous-ensemble de politiques sans avoir à désactiver toutes les autres. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc.
"--profile-strictness {warn|fatal|quiet}"
Indique à perlcritic comment traiter certains problèmes récupérables trouvés dans un fichier .perlcriticrc ou spécifié via l'option "--profile". Les valeurs valides sont "warn" (par défaut), "fatal" et "quiet". Par exemple, perlcritic normalement ne fait que prévenir des profils faisant référence à des politiques inexistantes, mais cette option peut rendre cette situation fatale. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc.
"--count"
"-C"
Affiche uniquement le nombre de violations pour chaque fichier. Utilisez cette fonctionnalité pour avoir rapidement une idée de l'endroit où une grande quantité de code pourrait nécessiter le plus d'attention.
"--color"
"--colour"
Cette option est activée lorsque la sortie est dirigée vers un tty. Lorsqu'elle est activée, les gravités 5 et 4 sont colorées en rouge et jaune, respectivement. La coloration ne se produit que si Term::ANSIColor est installé. Pour les environnements Windows, Win32::Console::ANSI doit également être installé. Négatezd cet interrupteur pour désactiver la couleur. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc.
"--pager PAGER_COMMAND_STRING"
Si défini, perlcritic redirigera sa sortie vers la chaîne de commande du pagineur donnée. Vous pouvez définir la valeur par défaut pour cette option dans votre fichier .perlcriticrc.

La définition d'un pagineur désactive la couleur par défaut. Vous devrez activer explicitement la couleur. Si vous souhaitez la couleur, vous voudrez probablement également dire à votre pagineur d'afficher des caractères bruts. Pour "less" et "more", utilisez l'option -R.

"--color-severity-highest COLOR_SPECIFICATION"
Spécifie la couleur à utiliser pour les violations de gravité la plus élevée, sous forme de spécification de couleur Term::ANSIColor. Peut également être spécifié comme "--colour- severity-highest", "--color-severity-5", ou "--colour-severity-5".
"--color-severity-high COLOR_SPECIFICATION"
Spécifie la couleur à utiliser pour les violations de gravité élevée, sous forme de spécification de couleur Term::ANSIColor.

OPTIONS

"--color-severity-high COLOR_SPECIFICATION"
Spécifie la couleur à utiliser pour les violations de haute sévérité, en tant que spécification de couleur Term::ANSIColor. Peut également être spécifié comme "--colour- severity-high", "--color-severity-4", ou "--colour-severity-4".
"--color-severity-medium COLOR_SPECIFICATION"
Spécifie la couleur à utiliser pour les violations de sévérité moyenne, en tant que spécification de couleur Term::ANSIColor. Peut également être spécifié comme "--colour- severity-medium", "--color-severity-3", ou "--colour-severity-3".
"--color-severity-low COLOR_SPECIFICATION"
Spécifie la couleur à utiliser pour les violations de faible sévérité, en tant que spécification de couleur Term::ANSIColor. Peut également être spécifié comme "--colour- severity-low", "--color-severity-2", ou "--colour-severity-2".
"--color-severity-lowest COLOR_SPECIFICATION"
Spécifie la couleur à utiliser pour les violations de la plus faible sévérité, en tant que spécification de couleur Term::ANSIColor. Peut également être spécifié comme "--colour- severity-lowest", "--color-severity-1", ou "--colour-severity-1".
"--files-with-violations"
Affiche uniquement les noms des fichiers contenant des violations. Utilisez cette fonctionnalité avec --single-policy pour trouver les fichiers qui contiennent des violations d'une politique donnée. Peut également être spécifié comme "--l".
"--files-without-violations"
Affiche uniquement les noms des fichiers sans violations. Utilisez cette fonctionnalité avec --single-policy pour trouver les fichiers qui ne contiennent pas de violations d'une politique donnée. Peut également être spécifié comme "--L".
"--program-extensions file_name_extension"
Indique à "perlcritic" de traiter les fichiers dont le nom se termine par l'extension de nom de fichier donnée comme des programmes, et non comme des modules. Si un point initial est souhaité, il doit être explicitement spécifié, par exemple : 
--program-extensions .pl

La correspondance est sensible à la casse, et l'option peut être spécifiée autant de fois que souhaité, par exemple :

--program-extensions .pl --program-extensions .cgi

Ce qui précède peut également être fait en citant les extensions de nom de fichier :

--program-extensions '.pl .cgi'

Les fichiers dont le nom se termine par '.PL' seront toujours considérés comme des programmes.

"--doc PATTERN"
Affiche la documentation perldoc pour tous les modules Perl::Critic::Policy qui correspondent à "m/PATTERN/ixms". Étant donné que les modules de politique ont tendance à avoir des noms plutôt longs, cela fournit simplement un moyen plus pratique de dire quelque chose comme : "perldoc Perl::Critic::Policy::ValuesAndExpressions::RequireUpperCaseHeredocTerminator" à l'invite de commande.
"--allow-unsafe"
Cette option demande à "perlcritic" d'autoriser l'utilisation de politiques qui ont été marquées comme « dangereuses ». Les politiques dangereuses peuvent entraîner des opérations risquées en compilant et en exécutant le code qu'elles analysent. Toutes les politiques fournies dans la distribution principale de Perl::Critic sont sûres. Cependant, les politiques tierces, telles que celles de la distribution Perl::Critic::Dynamic, peuvent ne pas l'être. Notez que « la sécurité » est honorifique – si un auteur de politique marque une politique comme sûre, ce n'est pas une garantie qu'elle ne fera rien de méchant. Si vous ne faites pas confiance à vos politiques et au code que vous analysez, n'utilisez pas ce commutateur.
"--quiet"
Supprime le message « source OK » lorsqu'aucune violation n'est trouvée.
"--help"
"-?"
"-H"
Affiche un bref résumé des options et quitte.
"--options"
Affiche les descriptions des options et quitte. Bien que cette sortie soit longue, elle n'est en aucun cas proche de la longueur de la sortie de "--man".
"--man"
Affiche le manuel complet de "perlcritic" et quitte.
"--version"
Affiche le numéro de version de "perlcritic" et quitte.

CONFIGURATION

La plupart des paramètres de Perl::Critic et de chacun des modules de politique peuvent être contrôlés par un fichier de configuration. Le fichier de configuration par défaut s'appelle .perlcriticrc. "perlcritic" recherchera ce fichier dans le répertoire courant d'abord, puis dans votre répertoire personnel. Alternativement, vous pouvez définir la variable d'environnement "PERLCRITIC" pour pointer explicitement vers un fichier différent dans un autre emplacement. Si aucun de ces fichiers n'existe et que l'option "--profile" n'est pas fournie sur la ligne de commande, alors toutes les politiques seront chargées avec leur configuration par défaut.

Le format du fichier de configuration est une série de blocs de style INI qui contiennent des paires clé-valeur séparées par « = ». Les commentaires doivent commencer par « # » et peuvent être placés sur une ligne séparée ou après les paires nom-valeur si vous le souhaitez.

Les paramètres par défaut pour perlcritic lui-même peuvent être définis avant le premier bloc nommé. Par exemple, mettre n'importe lequel ou tous ceux-ci en haut de votre fichier .perlcriticrc définira la valeur par défaut pour l'argument de ligne de commande correspondant.

severity  = 3                                     #Entier ou niveau nommé
only      = 1                                     #Zéro ou un
force     = 0                                     #Zéro ou un
verbose   = 4                                     #Entier ou spécificateur de format
top       = 50                                    #Un entier positif
theme     = (pbp + security) * bugs               #Une expression thématique
include   = NamingConventions ClassHierarchies    #Liste délimitée par des espaces
exclude   = Variables  Modules::RequirePackage    #Liste délimitée par des espaces

Le reste du fichier de configuration est une série de blocs comme celui-ci :

[Perl::Critic::Policy::Category::PolicyName]
severity = 1
set_themes = foo bar
add_themes = baz
arg1 = value1
arg2 = value2

"Perl::Critic::Policy::Category::PolicyName" est le nom complet d'un module qui implémente la politique. Les modules de politique distribués avec Perl::Critic ont été regroupés en catégories selon la table des matières du livre de Damian Conway, Perl Best Practices. Pour plus de brièveté, vous pouvez omettre la partie 'Perl::Critic::Policy' du nom du module.

"severity" est le niveau d'importance que vous souhaitez attribuer à la politique. Tous les modules de politique sont définis avec une valeur de sévérité par défaut allant de 1 (moins sévère) à 5 (plus sévère). Cependant, vous pouvez ne pas être d'accord avec la sévérité par défaut et choisir de lui attribuer une sévérité plus élevée ou plus basse, en fonction de votre propre philosophie de codage. Vous pouvez définir la "severity" sur un entier de 1 à 5, ou utiliser l'un des noms équivalents :

NOM DE SEVERITE ...est équivalent à... NOMBRE DE SEVERITE
----------------------------------------------------
gentle                                             5
stern                                              4
harsh                                              3
cruel                                              2
brutal                                             1

"set_themes" définit le thème de la politique et remplace son thème par défaut. L'argument est une chaîne d'un ou plusieurs mots alphanumériques délimités par des espaces. Les thèmes ne sont pas sensibles à la casse. Voir "POLICY THEMES" pour plus d'informations.

"add_themes" ajoute des thèmes aux thèmes par défaut pour cette politique. L'argument est une chaîne d'un ou plusieurs mots délimités par des espaces. Les thèmes ne sont pas sensibles à la casse. Voir "POLICY THEMES" pour plus d'informations.

Les paires clé-valeur restantes sont des paramètres de configuration qui seront passés au constructeur de cette politique. Les constructeurs de la plupart des modules de politique ne prennent pas d'arguments, et ceux qui le font devraient avoir des valeurs par défaut raisonnables. Voir la documentation sur le module de politique approprié pour plus de détails.

Au lieu de redéfinir la sévérité pour une politique donnée, vous pouvez désactiver complètement une politique en faisant précéder d'un '-' le nom du module dans votre fichier de configuration. De cette manière, la politique ne sera jamais chargée, quelle que soit la valeur de "--severity" donnée sur la ligne de commande.

Une configuration simple pourrait ressembler à ceci :

#--------------------------------------------------------------
# Je pense que c'est vraiment important, alors chargez toujours
[TestingAndDebugging::RequireUseStrict]
severity = 5
[TestingAndDebugging::RequireUseWarnings]
severity = 5
#--------------------------------------------------------------
# Je pense que c'est moins important, alors chargez uniquement lorsque demandé
[Variables::ProhibitPackageVars]
severity = 2
[ControlStructures::ProhibitPostfixControls]
allow = if unless  # Ma configuration personnalisée
severity = cruel   # Équivalent à « severity = 2 »
#--------------------------------------------------------------
# Donnez à ces politiques un thème personnalisé. Je peux activer uniquement
# ces politiques en disant « perlcritic --theme 'larry || curly' »
[Modules::RequireFilenameMatchesPackage]
add_themes = larry
[TestingAndDebugging::RequireTestLabels]
add_themes = curly moe
#--------------------------------------------------------------
# Je ne suis pas du tout d'accord avec celles-ci, alors ne les chargez jamais
[-NamingConventions::Capitalization]
[-ValuesAndExpressions::ProhibitMagicNumbers]
#--------------------------------------------------------------
# Pour toutes les autres politiques, j'accepte la sévérité par défaut,
# donc aucune configuration supplémentaire n'est requise pour elles.

Notez que toutes les politiques incluses dans la distribution Perl::Critic qui ont des paramètres entiers acceptent les tirets bas (« _ ») dans leurs valeurs, comme pour les littéraux numériques Perl. Par exemple,

[ValuesAndExpressions::RequireNumberSeparators]
min_value = 1_000

Pour des exemples de configuration supplémentaires, voir le fichier perlcriticrc qui est inclus dans ce répertoire examples de cette distribution.

La propre configuration Perl::Critic de Damian Conway est également incluse dans cette distribution sous le nom examples/perlcriticrc-conway.

LES POLITIQUES

Un grand nombre de modules de politique sont distribués avec Perl::Critic. Ils sont décrits brièvement dans le document d'accompagnement Perl::Critic::PolicySummary et plus en détail dans les modules individuels eux-mêmes. Dites

NOMS DE POLITIQUE EXPLICITES

Pour voir la perldoc de toutes les politiques qui correspondent à l'expression régulière "m/PATTERN/ixms", utilisez "perlcritic --doc PATTERN".

Il existe un certain nombre de distributions de politiques supplémentaires sur CPAN. Si Perl::Critic ne contient pas une politique que vous désirez, quelqu'un l'a peut-être déjà écrite. Voir "VOIR AUSSI" dans Perl::Critic pour une liste de ces distributions.

THÈMES DE POLITIQUE

Chaque politique est définie avec un ou plusieurs "thèmes". Les thèmes peuvent être utilisés pour créer des groupes arbitraires de politiques. Ils sont destinés à fournir un mécanisme alternatif pour sélectionner votre ensemble préféré de politiques. Par exemple, vous pourriez vouloir désactiver un certain ensemble de politiques lors de l'analyse de programmes de test. Inversement, vous pourriez vouloir activer seulement un sous-ensemble spécifique de politiques lors de l'analyse de modules.

Les politiques livrées avec Perl::Critic ont été divisées dans les thèmes suivants. Ce n'est que notre tentative de fournir quelques regroupements logiques de base. Vous êtes libre d'inventer de nouveaux thèmes qui conviennent à vos besoins.

THÈME             DESCRIPTION
------------------------------------------------------------------------
core              Toutes les politiques livrées avec Perl::Critic
pbp               Politiques provenant directement de "Perl Best Practices"
bugs              Politiques qui préviennent ou révèlent des bugs
certrec           Politiques recommandées par CERT
certrule          Politiques considérées comme des règles par CERT
maintenance       Politiques qui affectent la santé à long terme du code
cosmetic          Politiques qui n'ont qu'un effet superficiel
complexity        Politiques spécifiquement liées à la complexité du code
security          Politiques liées aux problèmes de sécurité
tests             Politiques spécifiques aux programmes de test

Dites "perlcritic --list" pour obtenir une liste de toutes les politiques disponibles et des thèmes qui leur sont associés. Vous pouvez également changer le thème de n'importe quelle politique dans votre fichier .perlcriticrc. Voir la section "CONFIGURATION" pour plus d'informations à ce sujet.

En utilisant l'option de ligne de commande "--theme", vous pouvez créer une règle arbitrairement complexe qui détermine quelles politiques appliquer. La précedence est la même que dans le code Perl normal, et vous pouvez utiliser des parenthèses pour forcer la précedence également. Les opérateurs supportés sont :

Opérateur    Alternative    Exemple
-----------------------------------------------------------------
&&          and            'pbp && core'
||          or             'pbp || (bugs && security)'
!           not            'pbp && ! (portability || complexity)'

Les noms de thèmes ne sont pas sensibles à la casse. Si "--theme" est réglé sur une chaîne vide, alors toutes les politiques sont évaluées comme vraies.

DOBLER LES RÈGLES

Perl::Critic adopte une approche stricte vis-à-vis de votre code : soit vous vous y conformez, soit vous ne le faites pas. Dans le monde réel, il n'est pas toujours pratique (ni même possible) de se conformer entièrement aux normes de codage. Dans de tels cas, il est sage de montrer que vous enfreignez sciemment les normes et que vous avez une Très Bonne Raison (TBR) pour le faire.

Pour vous aider dans ces situations, vous pouvez demander à Perl::Critic d'ignorer certaines lignes ou blocs de code en utilisant des annotations :

require 'LegacyLibaray1.pl';  ## no critic
require 'LegacyLibrary2.pl';  ## no critic
for my $element (@list) {
    ## no critic
    $foo = "";               # Ne respecte pas 'ProhibitEmptyQuotes'
    $barf = bar() if $foo;   # Ne respecte pas 'ProhibitPostfixControls'
    # Encore du code diabolique...
    ## use critic
    # Du bon code...
    do_something($_);
}

Les annotations "## no critic" demandent à Perl::Critic d'ignorer les lignes de code restantes jusqu'à ce qu'une annotation "## use critic" soit trouvée. Si l'annotation "## no critic" se trouve sur la même ligne qu'une instruction de code, alors seule cette ligne de code est ignorée. Pour demander à perlcritic d'ignorer les annotations "## no critic", utilisez l'option "--force".

Une annotation "## no critic" nue désactive toutes les politiques actives. Si vous souhaitez désactiver uniquement des politiques spécifiques, ajoutez une liste de noms de politiques en tant qu'arguments, comme vous le feriez pour le pragma "no strict" ou "no warnings". Par exemple, ceci désactiverait les politiques "ProhibitEmptyQuotes" et "ProhibitPostfixControls" jusqu'à la fin du bloc ou jusqu'à la prochaine annotation "## use critic" (la première arrivée) :

## no critic (EmptyQuotes, PostfixControls);
# Maintenant exempt de ValuesAndExpressions::ProhibitEmptyQuotes
$foo = "";
# Maintenant exempt de ControlStructures::ProhibitPostfixControls
$barf = bar() if $foo;
# Toujours soumis à ValuesAndExpression::RequireNumberSeparators
$long_int = 10000000000;

Étant donné que les noms de politiques sont comparés aux arguments de "## no critic" en tant qu'expressions régulières, vous pouvez abréger les noms de politiques ou désactiver une famille entière de politiques en une seule fois comme ceci :

## no critic (NamingConventions)
# Maintenant exempt de NamingConventions::Capitalization
my $camelHumpVar = 'foo';
# Maintenant exempt de NamingConventions::Capitalization
sub camelHumpSub {}

La liste des arguments doit être enfermée entre parenthèses et doit contenir un ou plusieurs barewords séparés par des virgules (c'est-à-dire n'utilisez pas de guillemets). Les annotations "## no critic" peuvent être imbriquées, et les politiques nommées par une annotation interne seront désactivées en même temps que celles déjà désactivées par une annotation externe.

Certaines politiques comme "Subroutines::ProhibitExcessComplexity" s'appliquent à un bloc entier de code. Dans ces cas, "## no critic" doit apparaître sur la ligne où la violation est signalée. Par exemple :

sub complicated_function {  ## no critic (ProhibitExcessComplexity)
    # Votre code ici...
}

Certaines politiques comme "Documentation::RequirePodSections" s'appliquent à l'ensemble du document, auquel cas les violations sont signalées à la ligne 1. Mais si le fichier nécessite une ligne shebang, il est impossible de placer "## no critic" sur la première ligne du fichier. C'est une limitation connue et elle sera abordée dans une future version. En guise de solution de contournement, vous pouvez désactiver les politiques affectées en ligne de commande ou dans votre fichier .perlcriticrc. Mais attention, cela affectera l'analyse de **tous** les fichiers.

Utilisez cette fonctionnalité judicieusement. "## no critic" doit être utilisé dans la portée la plus petite possible, ou uniquement sur des lignes de code individuelles. Et vous devez toujours être aussi spécifique que possible quant aux politiques que vous souhaitez désactiver (c'est-à-dire n'utilisez jamais un "## no critic" nu). Si Perl::Critic se plaint de votre code, essayez de trouver une solution conforme avant de recourir à cette fonctionnalité.

EXIT STATUS

If "perlcritic" has any errors itself, exits with status == 1. If there are no errors, but "perlcritic" finds Policy violations in your source code, exits with status == 2. If there were no errors and no violations were found, exits with status == 0.

THE Perl::Critic PHILOSOPHY

Coding standards are deeply personal and highly subjective. The goal of Perl::Critic is to help you write code that conforms with a set of best practices. Our primary goal is not to dictate what those practices are, but rather, to implement the practices discovered by others. Ultimately, you make the rules -- Perl::Critic is merely a tool for encouraging consistency. If there is a policy that you think is important or that we have overlooked, we would be very grateful for contributions, or you can simply load your own private set of policies into Perl::Critic.

EXTENDING THE CRITIC

The modular design of Perl::Critic is intended to facilitate the addition of new Policies. You'll need to have some understanding of PPI, but most Policy modules are pretty straightforward and only require about 20 lines of code. Please see the Perl::Critic::DEVELOPER file included in this distribution for a step-by-step demonstration of how to create new Policy modules.

If you develop any new Policy modules, feel free to send them to "<team@perlcritic.com>" and I'll be happy to consider putting them into the Perl::Critic distribution. Or if you would like to work on the Perl::Critic project directly, you can fork our repository at https://github.com/Perl-Critic/Perl-Critic.git.

The Perl::Critic team is also available for hire. If your organization has its own coding standards, we can create custom Policies to enforce your local guidelines. Or if your code base is prone to a particular defect pattern, we can design Policies that will help you catch those costly defects before they go into production. To discuss your needs with the Perl::Critic team, just contact "<team@perlcritic.com>".

CONTACTING THE DEVELOPMENT TEAM

You are encouraged to subscribe to the mailing list at https://groups.google.com/d/forum/perl-critic. At least one member of the development team is usually hanging around in <irc://irc.perl.org/#perlcritic> and you can follow Perl::Critic on Twitter, at https://twitter.com/perlcritic.
