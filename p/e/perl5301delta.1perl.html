PERL5301DELTA(1perl) Guide de référence pour programmeurs Perl PERL5301DELTA(1perl)

NOM

perl5301delta - ce qui est nouveau pour la version perl v5.30.1

DESCRIPTION

Ce document décrit les différences entre la version 5.30.0 et la version 5.30.1.

Si vous effectuez une mise à niveau à partir d'une version antérieure, telle que la 5.28.0, lisez d'abord perl5300delta, qui décrit les différences entre la 5.28.0 et la 5.30.0.

CHANGEMENTS INCOMPATIBLES

Il n'y a aucun changement intentionnellement incompatible avec la version 5.30.1. S'il en existe, ce sont des bugs, et nous vous prions de bien vouloir soumettre un rapport. Voir "Signalement de bugs" ci-dessous.

MODULES ET PRAGMAS

Modules et pragmas mis à jour

•
Module::CoreList a été mis à jour de la version 5.20190522 à 5.20191110.

DOCUMENTATION

Modifications de la documentation existante

Nous avons tenté de mettre à jour la documentation pour refléter les changements listés dans ce document. Si vous en trouvez que nous avons manqués, envoyez un email à perlbug@perl.org <mailto:perlbug@perl.org>.

De plus, la documentation a été mise à jour pour référencer GitHub comme nouveau dépôt canonique et pour décrire le nouveau workflow de requêtes de tirage (pull requests) sur GitHub.

CONFIGURATION ET COMPILATION

•
La macro "ECHO" est maintenant définie. Elle est utilisée dans une règle "dtrace" qui a été initialement modifiée pour FreeBSD, et le make de FreeBSD la définit apparemment de manière prédéfinie. Le make de Solaris ne définit pas "ECHO" de manière prédéfinie, ce qui cassait cette règle sur Solaris. [perl #17057] https://github.com/perl/perl5/issues/17057

TESTS

Des tests ont été ajoutés et modifiés pour refléter les autres ajouts et changements dans cette version.

SUPPORT PLATEFORMES

Notes spécifiques aux plateformes

Win32
Les tests de locale pouvaient planter sous Win32 en raison d'un bug de Windows, et séparément parce que la CRT lançait une exception si le nom de la locale n'était pas correctement encodé dans la page de code actuelle.

Pour ce dernier point, nous décodons maintenant nous-mêmes le nom de la locale, et le décodons toujours en UTF-8.

[perl #16922] https://github.com/perl/perl5/issues/16922

CORRECTIONS DE BUGS SÉLECTIONNÉES

  • La définition de $) définit maintenant correctement les identifiants de groupe supplémentaires, si vous avez les privilèges nécessaires. [perl #17031] https://github.com/perl/perl5/issues/17031
  • "readline @foo" évalue maintenant @foo en contexte scalaire. Auparavant, il était évalué en contexte de liste, et comme readline() extrait un seul argument de la pile, la pile pouvait déborder, ou se retrouver avec des valeurs inattendues. [perl #16929] https://github.com/perl/perl5/issues/16929
  • sv_gets() récupère mieux maintenant si le SV cible est modifié par un gestionnaire de signaux. [perl #16960] https://github.com/perl/perl5/issues/16960
  • La correspondance d'une chaîne non-"SVf_UTF8" avec une expression régulière contenant des littéraux Unicode pouvait fuir un SV à chaque tentative de correspondance. [perl #17140] https://github.com/perl/perl5/issues/17140
  • "sprintf("%.*a", -10000, $x)" provoquait un débordement de tampon en raison d'une mauvaise gestion de la valeur de précision négative. [perl #16942] https://github.com/perl/perl5/issues/16942
  • scalar() sur une référence pouvait provoquer un échec d'assertion erroné pendant la compilation. [perl #16969] https://github.com/perl/perl5/issues/16969

REMERCIEMENTS

Perl 5.30.1 représente environ 6 mois de développement depuis Perl 5.30.0 et contient environ 4 700 lignes de changements dans 67 fichiers de 14 auteurs.

En excluant les fichiers générés automatiquement, la documentation et les outils de publication, il y a eu environ 910 lignes de changements dans 20 fichiers .pm, .t, .c et .h.

Perl continue de prospérer dans sa quatrième décennie grâce à une communauté dynamique d'utilisateurs et de développeurs. Les personnes suivantes sont connues pour avoir contribué aux améliorations qui sont devenues Perl 5.30.1 :

Pour une liste plus complète de tous les contributeurs historiques de Perl, veuillez consulter le fichier AUTHORS dans la distribution source de Perl.

SIGNALEMENT DE BUGS

Si vous trouvez ce que vous pensez être un bug, vous pouvez consulter la base de données des bugs de Perl à l'adresse https://rt.perl.org/. Il peut également y avoir des informations sur http://www.perl.org/, la page d'accueil de Perl.

Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bug à un cas de test minuscule mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", sera envoyé à perlbug@perl.org pour être analysé par l'équipe de portage Perl.

Si le bug que vous signalez a des implications de sécurité qui le rendent inapproprié à l'envoi à une liste de diffusion archivée publiquement, alors voir "INFORMATIONS DE CONTACT POUR LES VULNÉRABILITÉS DE SÉCURITÉ" dans perlsec pour des détails sur la manière de signaler le problème.

EXPRIMER SA GRATITUDE

Si vous souhaitez remercier les Perl 5 Porters pour le travail qu'ils ont effectué dans Perl 5, vous pouvez le faire en exécutant le programme "perlthanks" :

perlthanks

Cela enverra un e-mail à la liste Perl 5 Porters avec votre témoignage de gratitude.
