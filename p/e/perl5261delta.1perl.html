PERL5261DELTA(1perl) Guide de référence du programmeur Perl PERL5261DELTA(1perl)

NOM

perl5261delta - nouveautés de perl v5.26.1

DESCRIPTION

Ce document décrit les différences entre la version 5.26.0 et la version 5.26.1.

Si vous mettez à jour depuis une version antérieure comme la 5.24.0, lisez d'abord perl5260delta, qui décrit les différences entre 5.24.0 et 5.26.0.

Sécurité

[CVE-2017-12837] Dépassement de tampon du tas dans le compilateur d'expressions régulières

La compilation de certains modèles d'expressions régulières avec le modificateur insensible à la casse pouvait provoquer un dépassement de tampon du tas et faire planter perl. Ceci est maintenant corrigé. [GH #16021] https://github.com/Perl/perl5/issues/16021

[CVE-2017-12883] Lecture hors limites dans l'analyseur d'expressions régulières

Pour certains types d'erreurs de syntaxe dans un modèle d'expression régulière, le message d'erreur pouvait soit contenir le contenu d'un bloc de mémoire aléatoire, potentiellement volumineux, soit faire planter perl. Ceci est maintenant corrigé. [GH #16025] https://github.com/Perl/perl5/issues/16025

[CVE-2017-12814] Dépassement de tampon de pile $ENV{$key} sous Windows

Un possible dépassement de tampon de pile dans le code %ENV sous Windows a été corrigé en supprimant complètement le tampon car il était superflu de toute façon. [GH #16051] https://github.com/Perl/perl5/issues/16051

Changements incompatibles

Il n'y a pas de changements intentionnellement incompatibles avec la version 5.26.0. S'il y en a, ce sont des bugs, et nous vous demandons de soumettre un rapport. Voir "Signalement de bugs" ci-dessous.

Modules et Pragmata

Modules et Pragmata mis à jour

  • base a été mis à jour de la version 2.25 à 2.26.

    Les effets de @INC sans point sur ce module ont été limités par l'introduction d'une solution plus précise et plus juste pour supprimer le '.' de @INC tout en réduisant les faux positifs.

  • charnames a été mis à jour de la version 1.44 à 1.45.
  • Module::CoreList a été mis à jour de la version 5.20170530 à 5.20170922_26.

Support des plateformes

Notes spécifiques à la plateforme

FreeBSD
•
La compilation avec g++ sous FreeBSD-11.0 a été corrigée. [GH #15984] https://github.com/Perl/perl5/issues/15984
Windows
  • Le support de la compilation de perl sous Windows en utilisant Microsoft Visual Studio 2017 (contenant Visual C++ 14.1) a été ajouté.
  • La compilation de modules XS avec GCC 6 dans une compilation 64 bits de Perl échouait en raison d'un mappage incorrect de "strtoll" et "strtoull". Ceci est maintenant corrigé. [GH #16074] https://github.com/Perl/perl5/issues/16074 [cpan #121683] https://rt.cpan.org/Public/Bug/Display.html?id=121683 [cpan #122353] https://rt.cpan.org/Public/Bug/Display.html?id=122353

Corrections de bugs sélectionnées

  • Plusieurs fonctions intégrées présentaient auparavant des bugs qui pouvaient provoquer l'écriture sur la pile interne sans allouer d'espace pour l'élément écrit. Dans des situations rares, cela aurait pu entraîner un crash. Ces bugs sont maintenant corrigés, et si des bugs similaires sont introduits à l'avenir, ils seront détectés automatiquement dans les compilations de débogage. [GH #16076] https://github.com/Perl/perl5/issues/16076
  • L'utilisation d'une référence symbolique avec la syntaxe post-déréférencement en tant que clé dans une recherche de table de hachage produisait un échec d'assertion dans les compilations de débogage. [GH #16029] https://github.com/Perl/perl5/issues/16029
  • L'assignation de liste ("aassign") pouvait dans certains cas rares allouer une entrée sur la pile mortelle et laisser l'entrée non initialisée. [GH #16017] https://github.com/Perl/perl5/issues/16017
  • Tenter d'appliquer un attribut à une variable "our" où une fonction portant ce nom existait déjà pouvait entraîner la fourniture d'un pointeur NULL là où un SV était attendu, faisant planter perl. [perl #131597] https://rt.perl.org/Public/Bug/Display.html?id=131597
  • Le code qui vivifie un typeglob à partir d'une référence de code faisait des hypothèses fausses qui pouvaient conduire à un crash dans des cas tels que "$::{"A"} = sub {}; \&{"A"}". Ceci est maintenant corrigé. [GH #15937] https://github.com/Perl/perl5/issues/15937
  • "my_atof2" ne lit plus au-delà du NUL terminateur, ce qui se produisait auparavant si le point décimal était immédiatement avant le NUL. [GH #16002] https://github.com/Perl/perl5/issues/16002
  • Des crashes occasionnels de type "Caractère UTF-8 mal formé" dans "s//" sur des chaînes utf8 ont été corrigés. [GH #16019] https://github.com/Perl/perl5/issues/16019
  • "perldoc -f s" trouve maintenant "s///". [GH #15989] https://github.com/Perl/perl5/issues/15989
  • Certains avertissements erronés après la conversion utf8 ont été corrigés. [GH #15958] https://github.com/Perl/perl5/issues/15958
  • La trame "jmpenv" pour attraper les exceptions Perl est configurée paresseusement, et cela était un peu trop paresseux. Le capteur est maintenant configuré plus tôt, empêchant certains crashs possibles. [GH #11804] https://github.com/Perl/perl5/issues/11804
  • Les avertissements parasites "Supposition de classe NON POSIX" ont été supprimés. [GH #16001] https://github.com/Perl/perl5/issues/16001

Signalement des bogues

Si vous trouvez ce qui vous semble être un bogue, vous pourriez consulter la base de données des bogues de perl à l'adresse https://rt.perl.org/ . Des informations pourraient également être disponibles sur http://www.perl.org/ , la page d'accueil de Perl.

Si vous pensez avoir un bogue non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bogue à un cas de test minuscule mais suffisant. Votre rapport de bogue, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl.

Si le bogue que vous signalez a des implications de sécurité qui le rendent inapproprié à l'envoi sur une liste de diffusion archivée publiquement, consultez alors le paragraphe "SECURITY VULNERABILITY CONTACT INFORMATION" dans perlsec pour connaître les détails sur la manière de signaler le problème.

perlthanks

Cela enverra un courriel à la liste des Perl 5 Porters avec votre message de remerciement.
