PERLBREW(1p) Documentation Perl Contribuée par l'Utilisateur PERLBREW(1p)

NOM

perlbrew - Gestionnaire d'environnements Perl.

SYNTAXE

Syntaxe de la commande perlbrew :

perlbrew <commande> [options] [arguments]

Commandes :

init           Initialise l'environnement perlbrew.
info           Affiche des informations utiles sur l'installation de perlbrew
install        Installe perl
uninstall      Désinstalle l'installation donnée
available      Liste les perls disponibles à l'installation
lib            Gère les répertoires local::lib.
alias          Donne un nouveau nom aux installations perl
upgrade-perl   Met à jour le perl courant
list           Liste les installations perl
use            Utilise le perl spécifié dans le shell courant
off            Désactive perlbrew dans le shell courant
switch         Utilise de manière permanente le perl spécifié comme défaut
switch-off     Désactive de manière permanente perlbrew (revient au perl système)
exec           Exécute des programmes avec des environnements perl spécifiés.
list-modules   Liste les modules CPAN installés pour la version Perl actuellement utilisée
clone-modules  Réinstalle tous les modules CPAN d'une installation à une autre
self-install       Installe perlbrew lui-même sous PERLBREW_ROOT/bin
self-upgrade       Met à jour perlbrew lui-même.
install-patchperl  Installe patchperl
install-cpanm      Installe cpanm, un compagnon convivial.
install-cpm        Installe cpm, un compagnon plus rapide mais toujours convivial.
install-multiple   Installe plusieurs versions et saveurs de perl
download       Télécharge la distribution perl spécifiée.
clean          Nettoie les tarballs et les répertoires de build
version        Affiche la version
help           Lit des instructions plus détaillées

Options génériques de commande :

-q --quiet     Soyez silencieux sur les messages d'information.
-v --verbose   Dites-m'en plus.

Consultez `perlbrew help` pour la documentation complète de perlbrew, ou

Consultez `perlbrew help <commande>` pour une description détaillée de la commande.

CONFIGURATION

PERLBREW_ROOT
Par défaut, perlbrew construit et installe les perls dans le répertoire "$ENV{HOME}/perl5/perlbrew". Pour utiliser un répertoire différent, définissez cette variable d'environnement dans votre "bashrc" au répertoire de votre RC shell avant de sourcer le RC de perlbrew.

Il est possible de partager une seule racine perlbrew avec plusieurs comptes utilisateurs sur la même machine. Ainsi, les gens n'ont pas à installer la même version de perl encore et encore. Disons que "/opt/perl5" est le répertoire que nous voulons partager. Tous les utilisateurs devraient pouvoir ajouter cet extrait à leur bashrc pour le rendre effectif :

export PERLBREW_ROOT=/opt/perl5
source ${PERLBREW_ROOT}/etc/bashrc

Après cela, le PATH de chacun devrait inclure "/opt/perl5/bin" et "/opt/perl5/perls/${PERLBREW_PERL}/bin". Chaque utilisateur peut invoquer "perlbrew switch" et "perlbrew use" pour passer indépendamment à différents environnements perl de leur choix. Cependant, seul l'utilisateur ayant des permissions d'écriture sur $PERLBREW_ROOT peut installer des modules CPAN. Ceci est à la fois bon et mauvais selon la convention de travail de votre équipe.

Si vous souhaitez installer des modules CPAN uniquement pour vous-même, vous devriez utiliser la commande "lib" pour construire un environnement local::lib personnel. Les environnements local::lib sont personnels et ne sont pas partagés entre différents utilisateurs. Pour plus de détails, lisez "perlbrew help lib" et la documentation de local::lib.

Si vous voulez une isolation encore plus cool des modules et souhaitez installer des modules CPAN utilisés uniquement pour un projet, vous devriez utiliser carton à cette fin.

Il est également possible de définir cette variable avant d'installer perlbrew pour que perlbrew s'installe sous le PERLBREW_ROOT donné :

export PERLBREW_ROOT=/opt/perl5
curl -L https://install.perlbrew.pl | bash

Après cela, l'exécutable perlbrew est installé en tant que "/opt/perl5/bin/perlbrew"

PERLBREW_HOME
Par défaut, perlbrew stocke les paramètres par utilisateur dans le répertoire "$ENV{HOME}/.perlbrew". Pour utiliser un répertoire différent, définissez cette variable d'environnement dans votre RC shell avant de sourcer le RC de perlbrew.

Dans certains cas, par exemple, si votre répertoire personnel est sur NFS et partagé entre plusieurs machines, vous pourriez souhaiter avoir plusieurs paramètres perlbrew différents par machine. Pour ce faire, vous pouvez utiliser la variable d'environnement "PERLBREW_HOME" pour indiquer à perlbrew où chercher le fichier d'initialisation. Voici un bref extrait bash pour le scénario donné.

if [ "$(hostname)" == "machine-a" ]; then
    export PERLBREW_HOME=~/.perlbrew-a
elif [ "$(hostname)" == "machine-b" ]; then
    export PERLBREW_HOME=~/.perlbrew-b
fi
source ~/perl5/perlbrew/etc/bashrc
PERLBREW_CONFIGURE_FLAGS
Cette variable d'environnement spécifie la liste des drapeaux de commande à transmettre à 'sh Configure'. Par défaut, c'est '-de'.
PERLBREW_CPAN_MIRROR
L'URL du miroir CPAN de votre choix. Par défaut, "https://cpan.metacpan.org" est utilisé.

COMMANDE : INIT

Utilisation : perlbrew init

La commande "init" doit être invoquée manuellement chaque fois que vous (l'utilisateur de perlbrew) mettez à niveau ou réinstallez perlbrew.

Si la mise à niveau est effectuée avec la commande "self-upgrade", ou en exécutant manuellement l'installateur en une seule ligne, cette commande est invoquée automatiquement.

COMMANDE : INFO

info [module]
Utilisation : perlbrew info [ <module> ]

Affiche des informations utiles sur l'installation de perlbrew.

Si un module est donné, la version et l'emplacement du module sont affichés.

COMMANDE : INSTALL

Utilisation :

perlbrew install [options] <perl-release>
perlbrew install [options] /chemin/vers/perl-5.14.0.tar.gz
perlbrew install [options] /chemin/vers/le/repertoire/de/checkout/perl5
perlbrew install [options] https://exemple.com/miroir/perl-5.12.3.tar.gz

Construit et installe le perl désiré. Le dernier argument peut être une chaîne courte désignant une version spécifique qui peut être connue à partir de la sortie de "perlbrew available", un chemin vers une archive tar pré-téléchargée, un chemin vers un checkout git du dépôt perl5, ou une URL vers une archive tar.

Le format de <perl-release> ressemble à :

perl-<version>
perl-stable
perl-blead
<version>
stable
blead

Les numéros de version ressemblent généralement à "5.x.xx", ou "perl-5.xx.x-RCx" pour les candidats de publication.

La version "stable" est un jeton spécial qui signifie la dernière version stable du moment.

La version "blead" est également un jeton spécial qui signifie la dernière version du dépôt, téléchargée depuis cette URL spécifique quel que soit le paramètre du miroir :

https://github.com/Perl/perl5/archive/blead.tar.gz

Le perl spécifié est téléchargé depuis le site officiel CPAN ou depuis le site miroir configuré auparavant.

Un numéro de version seul sans le préfixe "perl-" signifie la sortie officielle fournie par les développeurs de perl5.

Options pour la commande "install" :

-f --force     Force l'installation
-j $n          Construction et tests parallèles. ex. C<perlbrew install -j 5 perl-5.14
.2> -n --notest Ignorer le test --switch Basculer automatiquement vers cette version de Perl une fois installée avec succès, comme avec `perlbrew switch <version>` --as Installer la version de perl donnée sous un nom. ex. C<perlbrew install perl-5.6.2 --as legacy-perl> --noman Ignorer l'installation des manpages --thread Compiler perl avec usethreads activé --multi Compiler perl avec usemultiplicity activé --64int Compiler perl avec use64bitint activé --64all Compiler perl avec use64bitall activé --ld Compiler perl avec uselongdouble activé --debug Compiler perl avec DEBUGGING activé --clang Compiler perl en utilisant le compilateur clang --no-patchperl Ignorer l'appel à patchperl -D,-U,-A Options passées au script Configure de perl. ex. C<perlbrew install perl-5.10.1 -D usemymalloc -U versiononly> --destdir $path Installer perl comme avec 'make install DESTDIR=$path' --sitecustomize $filename Spécifier un fichier à installer comme sitecustomize.pl --mirror $URL Spécifier une URL de miroir CPAN. La valeur par défaut est "https://www.cpan.org"

Par défaut, toutes les installations sont configurées selon leur nom comme ceci:

sh Configure -de -Dprefix=$PERLBREW_ROOT/perls/<name>

COMMANDE: INSTALL-MULTIPLE

Utilisation: perlbrew install-multiple [options] <version-perl-1> <version-perl-2> ...

Compiler et installer les versions de perl données.

"install-multiple" accepte le même ensemble d'options que la commande "install" plus les suivantes:

--both $flavor       Où $flavor est l'une de C<thread>, C<multi>, C<ld>,
                     C<64int>, C<64all>, C<debug> et C<clang>.
                     Pour chaque version de perl donnée, installer deux
                     variantes, l'une avec le drapeau C<--$flavor> défini
                     et l'autre sans. C<--both> peut être
                     passé plusieurs fois avec différentes valeurs
                     et dans ce cas, toutes les combinaisons possibles
                     sont générées.
--common-variations  équivalent à C<--both thread --both ld --both 64int>
--all-variations     génère toutes les combinaisons de variantes possibles
--append $string     Ajoute la chaîne donnée aux noms générés

Par exemple:

perlbrew install-multiple 5.18.0 blead --both thread --both debug

Installe les perls suivants:

perl-blead
perl-blead-debug
perl-blead-thread-multi
perl-blead-thread-multi-debug
perl-5.18.0
perl-5.18.0-debug
perl-5.18.0-thread-multi
perl-5.18.0-thread-multi-debug

(notez que la variante "multi" est sélectionnée automatiquement car "thread" la requiert)

Autre exemple utilisant des drapeaux de compilation personnalisés:

perlbrew install-multiple 5.18.0 --both thread -Doptimize='-O3' --append='-O3'

COMMANDE: UNINSTALL

Utilisation:

perlbrew uninstall <nom>

Alternativement:

perlbrew delete <nom>
perlbrew rm <nom>

Désinstalle l'installation de perl donnée. Le nom est le nom de l'installation tel qu'affiché par `perlbrew list`. Cela supprime effectivement l'installation de perl spécifiée et toutes les bibliothèques qui lui sont associées.

COMMANDE: USE

Utilisation: perlbrew use [perl-<version> | <version> | <nom>]

Utilise la version de perl donnée dans le shell actuel. Cela n'affectera pas les shells nouvellement ouverts.

Sans paramètre, affiche la version de perl actuellement utilisée.

COMMANDE: SWITCH

Utilisation: perlbrew switch [ <nom> ]

Bascule vers la version donnée et en fait la valeur par défaut pour cette session et toutes les sessions de terminal futures.

Sans paramètre, affiche la version de perl actuellement sélectionnée.

COMMANDE: LIST

Utilisation: perlbrew list

Liste toutes les installations de perl dans le répertoire racine de perlbrew spécifié par la variable d'environnement $PERLBREW_ROOT. Par défaut, la valeur est "~/perl5/perlbrew".

S'il y a des bibliothèques associées à certaines installations de perl, elles seront incluses dans le nom. Les éléments de cette liste peuvent être utilisés comme arguments dans diverses autres commandes.

COMMANDE: AVAILABLE

Utilisation: perlbrew available [--all]

Liste les versions de perl récemment disponibles sur CPAN.

Par défaut, la sous-version la plus récente de chaque version stable est listée.

Pour obtenir une liste de tous les perls jamais publiés, y compris les versions de développement et les versions candidates (RC), exécutez la commande avec l'option "--all".

COMMANDE: OFF

Utilisation: perlbrew off

Désactive temporairement perlbrew dans le shell actuel. Réactive effectivement le Perl système par défaut, quel qu'il soit.

Cette commande ne fonctionne que si vous ajoutez la déclaration `source $PERLBREW_ROOT/etc/bashrc` dans votre initialisation de shell (bashrc / zshrc).

COMMANDE: SWITCH-OFF

Utilisation: perlbrew switch-off

Désactive définitivement perlbrew. Utilisez la commande "switch" pour le réactiver. Appelez la commande "use" pour l'activer uniquement dans le shell actuel.

Réactive le Perl système par défaut, quel qu'il soit.

COMMANDE: ALIAS

Utilisation: perlbrew alias [-f] create <nom> <alias>

Crée un alias pour l'installation nommée <nom>.

Utilisation: perlbrew alias [-f] rename <ancien_alias> <nouvel_alias>

Renomme l'alias avec un nouveau nom.

Utilisation: perlbrew alias delete <alias>

Supprime l'alias donné.

COMMANDE: EXEC

Utilisation: perlbrew exec [options] <commande> <args...>

Options pour la commande "exec":

--with perl-version,... - utiliser uniquement ces versions
--min n.nnnnn           - version minimale de perl
                            (le format est le même que dans 'use 5.012')
--max n.nnnnn           - version maximale de perl
--halt-on-error         - arrêter à la première sortie non nulle

Exécute la commande pour chaque installation de perl, une par une.

Par exemple, exécuter un programme Bonjour:

perlbrew exec perl -e 'print "Hello from $]\n"'

La sortie ressemble à ceci:

perl-5.12.2
==========
Hello word from perl-5.012002
perl-5.13.10
==========
Hello word from perl-5.013010
perl-5.14.0
==========
Hello word from perl-5.014000

Notez que la commande n'est pas exécutée en parallèle.

Lorsque l'argument "--with" est fourni, la commande ne sera exécutée qu'avec les installations de perl spécifiées. La commande suivante installe le module Moose dans perl-5.12, quel que soit le perl actuel:

perlbrew exec --with perl-5.12 cpanm Moose

Plusieurs noms d'installation peuvent être fournis:

perlbrew exec --with perl-5.12,perl-5.12-debug,perl-5.14.2 cpanm Moo

Ils sont séparés par des espaces ou des virgules. Lorsque des espaces sont utilisés, il est nécessaire de mettre entre guillemets l'ensemble de la spécification comme un seul argument, mais les virgules peuvent alors être utilisées dans les noms d'installation:

perlbrew exec --with '5.12 5.12,debug 5.14.2@nobita @shizuka' cpanm Moo

Comme démontré ci-dessus, le préfixe "perl-" peut être omis, et les noms de bibliothèques peuvent également être spécifiés. Les noms de bibliothèques peuvent apparaître sans nom d'installation de perl, dans ce cas, il est supposé être le "perl actuel".

Actuellement, tous les noms spécifiés qui ne peuvent pas être résolus en noms d'installation réels sont silencieusement ignorés dans la sortie. De plus, les statuts de sortie des commandes ne sont pas renvoyés.

COMMANDE: ENV

Utilisation: perlbrew env [ <nom> ]

Commande de bas niveau. Appelez cette commande pour voir la liste des variables d'environnement qui sont définies par "perlbrew" lui-même pour l'intégration au shell.

La sortie ressemble à ceci (si votre shell est bash/zsh):

export PERLBREW_ROOT=/Users/gugod/perl5/perlbrew
export PERLBREW_VERSION=0.31
export PERLBREW_PATH=/Users/gugod/perl5/perlbrew/bin:/Users/gugod/perl5/perlbrew/perls/current/bin
export PERLBREW_PERL=perl-5.14.1

Les utilisateurs de tcsh / csh devraient voir des instructions 'setenv' au lieu de `export`.

COMMANDE: SYMLINK-EXECUTABLES

Utilisation: perlbrew symlink-executables [ <nom> ]

Commande de bas niveau. Cette commande est utilisée pour créer le lien symbolique de l'exécutable "perl" vers, par exemple, "perl5.13.6". Ceci n'est requis que pour les versions de développement de perl.

Vous n'avez pas besoin de le faire à moins que vous n'ayez utilisé une ancienne version de perlbrew pour installer des perls, et que vous soyez confus car le perl que vous venez d'installer semble manquer après avoir exécuté `use` ou `switch`. perlbrew modifie sa structure d'installation depuis la version 0.11, qui génère des liens symboliques vers les exécutables d'une meilleure manière.

Si vous venez de mettre à jour perlbrew (depuis la version 0.11 ou antérieure) et que "perlbrew switch" n'a pas fonctionné après avoir basculé vers une version de développement de perl, disons perl-5.13.6, exécutez cette commande:

perlbrew symlink-executables perl-5.13.6

Cela crée essentiellement ce lien symbolique:

${PERLBREW_ROOT}/perls/perl-5.13.6/bin/perl
-> ${PERLBREW_ROOT}/perls/perl-5.13.6/bin/perl5.13.6

Les perls nouvellement installés, qu'ils soient des versions de développement ou non, ne nécessitent pas de traitement manuel avec cette commande.

COMMAND : SELF-UPGRADE

Utilisation : perlbrew self-upgrade

Cette commande met à jour Perlbrew vers sa dernière version.

COMMAND : SELF-INSTALL

Utilisation : perlbrew self-install

AVIS : Vous ne devriez pas avoir besoin d'exécuter cette commande dans votre routine quotidienne.

Cette commande installe perlbrew lui-même dans "$PERLBREW_ROOT/bin". Elle est destinée à être utilisée par l'installateur de perlbrew. Cependant, vous pouvez manuellement faire ce qui suit pour réinstaller uniquement l'exécutable "perlbrew" :

curl https://raw.githubusercontent.com/gugod/App-perlbrew/master/perlbrew -o perlbrew
perl ./perlbrew self-install

Elle est légèrement différente de l'exécution de l'installateur perlbrew car "patchperl" n'est pas installé dans ce cas.

COMMAND : CLEAN

Utilisation : perlbrew clean

Supprime toutes les archives Perl téléchargées et tous les répertoires de compilation précédents.

COMMAND : VERSION

Utilisation : perlbrew version

Affiche la version de perlbrew.

COMMAND : LIB

Utilisation : perlbrew lib <action> <nom-lib>

perlbrew lib list
perlbrew lib create <nom-lib>
perlbrew lib delete <nom-lib>

La commande `lib` est utilisée pour manipuler les racines local::lib à l'intérieur des installations Perl. Elle est effectivement similaire à `perl -Mlocal::lib=/chemin/vers/lib-nom`, mais un peu plus que cela.

Un nom de lib peut être un nom court, contenant des caractères alphanumériques, comme 'awesome', ou un nom complet, précédé d'un nom d'installation Perl et d'un signe '@', par exemple, 'perl-5.14.2@awesome'.

Voici quelques exemples succincts pour invoquer la commande `lib` :

# Crée la lib perl-5.12.3@shizuka
perlbrew lib create perl-5.12.3@shizuka
# Crée les libs perl-5.14.2@nobita et perl-5.14.2@shizuka
perlbrew use perl-5.14.2
perlbrew lib create nobita
perlbrew lib create shizuka
# Voir la liste des cibles d'utilisation/changement
perlbrew list
# Active une lib dans le shell courant
perlbrew use perl-5.12.3@shizuka
perlbrew use perl-5.14.2@nobita
perlbrew use perl-5.14.2@shizuka
# Active une lib par défaut
perlbrew switch perl-5.12.3@shizuka
perlbrew switch perl-5.14.2@nobita
perlbrew switch perl-5.14.2@shizuka
# Supprime les libs perl-5.14.2@nobita et perl-5.14.2@shizuka
perlbrew use perl-5.14.2
perlbrew lib delete nobita
perlbrew lib delete shizuka
# Supprime la lib perl-5.12.3@shizuka
perlbrew lib delete perl-5.12.3@shizuka

Les noms de libs courts sont locaux à la Perl courante. Un nom de lib 'nobita' peut faire référence à 'perl-5.12.3@nobita' ou 'perl-5.14.2@nobita', selon celle qui est activée dans le shell courant.

Lors de l'utilisation de `use` ou `switch` pour activer une lib, fournissez toujours le nom complet. Une règle simple : l'argument de la commande `use` ou `switch` doit apparaître dans la sortie de `perlbrew list`.

COMMAND : UPGRADE-PERL

Utilisation : perlbrew upgrade-perl

L'exécution de cette commande met à jour la Perl actuellement activée vers sa dernière version mineure. Si vous avez un shell avec 5.32.0 activé, elle le mettra à jour vers 5.32.1.

Les versions mineures de Perl (par ex. 5.x.*) sont binaires compatibles entre elles, donc cette commande vous offre la possibilité de mettre à jour les anciens environnements perlbrew sur place.

COMMAND : DOWNLOAD

Utilisation :
perlbrew download <version-perl>

Exemples :
perlbrew download perl-5.14.2
perlbrew download perl-5.16.1
perlbrew download perl-5.17.3

Télécharge la version spécifiée de l'archive de distribution Perl sous le répertoire "$PERLBREW_ROOT/dists/".

L'argument "version-perl" doit être l'un des éléments de la commande "perlbrew available".

COMMAND : LIST-MODULES

Utilisation :
perlbrew list-modules

Liste tous les modules cpan installés pour la Perl courante.

Cette commande peut être utilisée en conjonction avec `perlbrew exec` pour migrer votre installation de modules vers une autre Perl. La commande suivante réinstalle tous les modules sous perl-5.16.0 :

perlbrew list-modules | perlbrew exec --with perl-5.16.0 cpanm

Notez que cela installe les versions *les plus récentes* des modules Perl sur la nouvelle Perl, qui ne sont pas nécessairement les *mêmes* versions de modules que vous aviez installées précédemment.

COMMAND : CLONE-MODULES

Utilisation :

perlbrew clone-modules [options] <destination>
perlbrew clone-modules [options] <source> <destination>

Options :

--notest    Ignorer tous les tests de modules

Cette commande réinstalle tous les modules CPAN trouvés d'une installation à une autre. Par exemple, cela liste tous les modules sous '5.26.1' et les réinstalle sous '5.27.7' :

perlbrew clone-modules 5.26.1 5.27.7

L'argument "source" est optionnel et prend par défaut la source actuellement activée. Cependant, si aucune n'est activée (perlbrew est désactivé), c'est une erreur.

Notez que cela ne garantit pas que les versions des modules resteront les mêmes dans la destination.

COMMAND : MAKE-SHIM

Utilisation :

perlbrew make-shim <programme>
perlbrew make-shim -o <nom-shim> <programme>
perlbrew make-shim --output <nom-shim> <programme>

Cette commande produit un fichier exécutable dans le répertoire courant nommé "programme", ou "nom-shim" si spécifié après "--output" (ou "-o" pour faire court). La sortie est un wrapper de shell, un shim, du programme nommé dans l'environnement perlbrew courant.

Lorsque le shim est exécuté, le "programme" d'origine est exécuté avec toutes les variables d'environnement pertinentes définies pour l'environnement perlbrew dans lequel il est installé, quel que soit l'environnement perlbrew actuellement activé. Le shim peut également être déplacé vers différents répertoires et, comme le conventionnel "~/.local/bin", il est ainsi toujours disponible.

Par exemple, vous pourriez trouver "tldr" d'App::tldr un outil pratique et décider de l'installer dans votre environnement de travail quotidien :

perlbrew use perl-5.36.1
cpm install -g App::tldr

Mais lorsque vous êtes occasionnellement amené à passer à un environnement différent, le "PATH" serait modifié et la commande "tldr" disparaîtrait, ce qui est le résultat attendu :

perlbrew use perl-5.18.4
tldr perl  #=> erreur : commande introuvable

Il serait souhaitable que "tldr" soit rendu universellement disponible. Une façon d'atténuer de tels besoins est de préparer et d'installer le programme "tldr" en dehors de "PERLBREW_ROOT", tout en utilisant l'environnement perlbrew pour l'exécuter.

Par exemple, préparez un répertoire conventionnel "~/.local/bin" et ajoutez-le au "PATH", puis :

perlbrew use perl-5.36.1
cd /tmp
perlbrew make-shim tldr
mv /tmp/tldr ~/.local/bin/tldr

Ce "~/.local/bin/tldr" est un wrapper de shell du programme "tldr" réel, et il active en interne l'environnement perlbrew "perl-5.36.1". L'exécution du shim tldr exécutera alors toujours le "tldr" réel, peu importe quel environnement perlbrew est activé, voire même si perlbrew est désactivé. Les seules exigences sont que l'environnement perlbrew "perl-5.36.1" et l'installation de "App::tldr" doivent rester.

COMMAND : MAKE-PP

Utilisation :

perlbrew make-pp -i <chemin> -o <chemin>
perlbrew make-pp --input <chemin> --output <chemin>

Cette commande prend le chemin d'un programme Perl (l'entrée) et produit une version packagée au format PAR de ce programme vers le chemin spécifié (la sortie). Essentiellement, il s'agit d'un wrapper de "pp" de PAR::Packer, d'où le nom.

Cela nécessite que l'environnement perlbrew actuel ait d'abord PAR et PAR::Packer installés. Sinon, "make-pp" échoue. De plus, si la Perl actuelle n'est pas gérée par perlbrew

perlbrew.1p - perlbrew

NAME

make-pp - Créer un exécutable autonome pour un programme Perl

COMMAND: MAKE-PP

Crée un exécutable autonome pour un programme Perl.

La commande make-pp crée un exécutable autonome à partir d'un programme Perl et de toutes ses dépendances, y compris l'interpréteur Perl lui-même, les bibliothèques Perl principales et toutes les bibliothèques installées dans site_perl et local_perl (si perlbrew lib est actif).

Si le chemin de sortie spécifié existe déjà, make-pp s'arrête.

Le fichier produit est un exécutable autonome contenant les éléments suivants :

1. Le programme Perl d'entrée
2. L'interpréteur Perl
3. Toutes les bibliothèques Perl principales de la version Perl courante
4. L'intégralité de la bibliothèque site
5. L'intégralité de la bibliothèque locale (gérée par la commande `perlbrew lib`), si active.

Il est attendu que l'exécutable puisse ensuite être exécuté sur une machine différente du même système d'exploitation et de la même architecture.

Il est à noter que cette approche est une solution excessive pour regrouper un seul programme, car elle inclura certainement beaucoup plus que la liste exacte des dépendances d'exécution du programme nommé. « make-pp » est destiné à être une solution de paresse pour le problème non trivial de déterminer parfaitement les dépendances d'exécution d'un programme arbitraire.
