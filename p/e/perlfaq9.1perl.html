PERLFAQ9(1perl) Guide de référence du programmeur Perl PERLFAQ9(1perl)

NOM

perlfaq9 - Web, Email et Réseaux

VERSION

version 5.20250619

DESCRIPTION

Cette section traite des questions relatives à la gestion de sites web, à l'envoi et à la réception d'e-mails, ainsi qu'aux réseaux en général.

Dois-je utiliser un framework web ?

Oui. Si vous créez un site web avec un quelconque niveau d'interactivité (formulaires / utilisateurs / bases de données), vous voudrez utiliser un framework pour faciliter la gestion des requêtes et des réponses.

S'il n'y a pas d'interactivité, vous pourriez quand même envisager d'utiliser quelque chose comme Template Toolkit https://metacpan.org/module/Template ou Plack::Middleware::TemplateToolkit pour faciliter la maintenance de vos fichiers HTML (et autres ressources).

Quel framework web dois-je utiliser ?

Il n'y a pas de réponse simple à cette question. Les frameworks Perl peuvent tout gérer, des serveurs de fichiers de base et des intranets à petite échelle aux sites web multinationaux et multilingues massifs qui sont au cœur des entreprises internationales.

Vous trouverez ci-dessous une liste de quelques frameworks avec des commentaires qui pourraient vous aider à prendre une décision, en fonction de vos besoins spécifiques. Commencez par lire la documentation, puis posez vos questions sur la liste de diffusion ou le canal IRC concerné.

Catalyst
Fortement orienté objet et complet, avec une longue histoire de développement et une grande communauté ainsi qu'un écosystème de modules complémentaires. Il est excellent pour les applications grandes et complexes, où vous avez un contrôle total sur le serveur.
Dancer2
Libéré du poids de l'héritage, il offre une API légère et facile à apprendre. Il dispose d'un écosystème de modules complémentaires en croissance. Il est préférable de l'utiliser pour les projets plus petits et est très facile à apprendre pour les débutants.
Mojolicious
Autonome et puissant pour les projets petits et plus grands, avec un accent sur HTML5 et les technologies web en temps réel telles que WebSockets.
Web::Simple
Fortement orienté objet et minimaliste, conçu pour la vitesse et destiné à être une boîte à outils pour construire des micro applications web, des frameworks personnalisés ou pour lier des applications web compatibles Plack existantes avec un répartiteur central unique.

Tous ces frameworks interagissent avec ou utilisent Plack, qu'il est utile de comprendre les bases lorsque l'on crée un site web en Perl (il existe de nombreux composants Plack::Middleware https://metacpan.org/search?q=plack%3A%3Amiddleware utiles).

Qu'est-ce que Plack et PSGI ?

PSGI est la spécification Perl Web Server Gateway Interface, c'est une norme que de nombreux frameworks web Perl utilisent. Vous ne devriez pas avoir besoin de la comprendre pour créer un site web, la partie que vous pourriez vouloir utiliser est Plack.

Plack est un ensemble d'outils pour utiliser la pile PSGI. Il contient des composants middleware https://metacpan.org/search?q=plack%3A%3Amiddleware, un serveur de référence et des utilitaires pour les frameworks d'applications web. Plack est similaire au Rack de Ruby ou au Paste de Python pour WSGI.

Vous pourriez construire un site web en utilisant Plack et votre propre code, mais pour tout ce qui dépasse un site web très basique, utiliser un framework web (qui utilise https://plackperl.org) est une meilleure option.

Comment retirer le HTML d'une chaîne ?

Utilisez HTML::Strip, ou HTML::FormatText qui non seulement retire le HTML mais tente également un peu de formatage simple du texte brut résultant.

Comment extraire les URLs ?

HTML::SimpleLinkExtor extraira les URLs du HTML, il gère les ancres, les images, les objets, les cadres et de nombreuses autres balises qui peuvent contenir une URL. Si vous avez besoin de quelque chose de plus complexe, vous pouvez créer votre propre sous-classe de HTML::LinkExtor ou HTML::Parser. Vous pourriez même utiliser HTML::SimpleLinkExtor comme exemple pour quelque chose d'adapté à vos besoins.

Vous pouvez utiliser URI::Find ou URL::Search pour extraire des URLs d'un document texte arbitraire.

Comment récupérer un fichier HTML ?

(contribué par brian d foy)

Le module principal HTTP::Tiny peut récupérer des ressources web et vous renvoyer leur contenu sous forme de chaîne de caractères :

use HTTP::Tiny;
my $ua = HTTP::Tiny->new;
my $html = $ua->get( "http://www.example.com/index.html" )->{content};

Il peut également stocker la ressource directement dans un fichier :

$ua->mirror( "http://www.example.com/index.html", "foo.html" );

Si vous avez besoin de faire quelque chose de plus complexe, l'objet HTTP::Tiny peut être personnalisé en définissant des attributs, ou vous pouvez utiliser LWP::UserAgent de la distribution libwww-perl ou Mojo::UserAgent de la distribution Mojolicious pour faciliter les tâches courantes. Si vous souhaitez simuler un navigateur web interactif, vous pouvez utiliser le module WWW::Mechanize.

Comment automatiser la soumission d'un formulaire HTML ?

Si vous faites quelque chose de complexe, comme naviguer à travers de nombreuses pages et formulaires d'un site web, vous pouvez utiliser WWW::Mechanize. Consultez sa documentation pour tous les détails.

Si vous soumettez des valeurs en utilisant la méthode GET, créez une URL et encodez le formulaire en utilisant la méthode "www_form_urlencode" de HTTP::Tiny :

use HTTP::Tiny;
my $ua = HTTP::Tiny->new;
my $query = $ua->www_form_urlencode([ q => 'DB_File', lucky => 1 ]);
my $url = "https://metacpan.org/search?$query";
my $content = $ua->get($url)->{content};

Si vous utilisez la méthode POST, la méthode "post_form" encodera le contenu appropriément.

use HTTP::Tiny;
my $ua = HTTP::Tiny->new;
my $url = 'https://metacpan.org/search';
my $form = [ q => 'DB_File', lucky => 1 ];
my $content = $ua->post_form($url, $form)->{content};

Comment décoder ou créer ces %-encodages sur le web ?

La plupart du temps, vous ne devriez pas avoir à faire cela car votre framework web, ou si vous faites une requête, LWP ou un autre module s'en chargerait pour vous.

Pour encoder une chaîne vous-même, utilisez le module URI::Escape. La fonction "uri_escape" renvoie la chaîne encodée :

my $original = "Colon : Hash # Percent %";
my $escaped = uri_escape( $original );
print "$escaped\n"; # 'Colon%20%3A%20Hash%20%23%20Percent%20%25'

Pour décoder la chaîne, utilisez la fonction "uri_unescape" :

my $unescaped = uri_unescape( $escaped );
print $unescaped; # de retour à l'original

N'oubliez pas de ne pas encoder une URI complète, vous devez encoder chaque composant séparément, puis les joindre.

Comment rediriger vers une autre page ?

La plupart des frameworks web Perl auront un mécanisme pour cela. En utilisant le framework Catalyst, ce serait :

$c->res->redirect($url);
$c->detach();

Si vous utilisez Plack (ce que la plupart des frameworks font), alors Plack::Middleware::Rewrite vaut la peine d'être examiné si vous migrez depuis Apache ou si vous avez des URLs que vous souhaitez toujours rediriger.

Comment mettre un mot de passe sur mes pages web ?

Vérifiez si le framework web que vous utilisez dispose d'un système d'authentification et s'il répond à vos besoins.

Alternativement, regardez du côté de Plack::Middleware::Auth::Basic, ou l'un des

les autres options d'authentification Plack https://metacpan.org/search?q=plack+auth.

Comment m'assurer que les utilisateurs ne peuvent pas saisir de valeurs dans un formulaire qui provoquent des erreurs dans mon script CGI ?

(contribué par brian d foy)

Vous ne pouvez pas empêcher les gens d'envoyer de mauvaises données à votre script. Même si vous ajoutez des vérifications côté client, les gens peuvent les désactiver ou les contourner complètement. Par exemple, quelqu'un pourrait utiliser un module comme LWP pour soumettre des données à votre site Web. Si vous voulez empêcher les données qui tentent d'utiliser l'injection SQL ou d'autres types d'attaques (et vous devriez le vouloir), vous ne devez faire confiance à aucune donnée qui entre dans votre programme.

La documentation perlsec contient des conseils généraux sur la sécurité des données. Si vous utilisez le module DBI, utilisez des espaces réservés pour insérer les données. Si vous exécutez des programmes externes avec "system" ou "exec", utilisez les formes de liste. Il existe de nombreuses autres précautions que vous devriez prendre, trop nombreuses pour être listées ici, et la plupart d'entre elles entrent dans la catégorie de ne pas utiliser de données que vous n'avez pas l'intention d'utiliser. Ne faites confiance à personne.

Comment analyser un en-tête de courrier ?

Utilisez le module Email::MIME. Il est bien testé et prend en charge toute la folie que vous verrez dans le monde réel (espaces blancs plissés en commentaire, encodages, commentaires, etc.).

use Email::MIME;
my $message = Email::MIME->new($rfc2822);
my $subject = $message->header('Subject');
my $from    = $message->header('From');

Si vous avez déjà un autre type d'objet de courrier électronique, envisagez de le passer à Email::Abstract, puis d'utiliser sa méthode cast pour obtenir un objet Email::MIME :

my $abstract = Email::Abstract->new($mail_message_object);
my $email_mime_object = $abstract->cast('Email::MIME');

Comment vérifier une adresse e-mail valide ?

(partiellement contribué par Aaron Sherman)

Cette question n'est pas aussi simple qu'il y paraît. Il y a deux parties :

a) Comment vérifier si une adresse e-mail est correctement formatée ?

b) Comment vérifier si une adresse e-mail cible un destinataire valide ?

Sans envoyer de courrier à l'adresse et voir s'il y a un humain à l'autre bout pour vous répondre, vous ne pouvez pas répondre complètement à la partie b, mais le module Email::Valid fera les parties a et b autant que possible en temps réel.

Notre meilleur conseil pour vérifier l'adresse e-mail d'une personne est de lui demander de saisir son adresse deux fois, comme vous le faites normalement pour changer un mot de passe. Cela élimine généralement les fautes de frappe. Si les deux versions correspondent, envoyez un e-mail à cette adresse avec un message personnel. Si vous recevez le message en retour et qu'ils ont suivi vos instructions, vous pouvez être raisonnablement assuré qu'il est réel.

Une stratégie connexe, moins sujette à la falsification, consiste à leur donner un PIN (numéro d'identification personnel). Enregistrez l'adresse et le PIN (idéalement aléatoire) pour un traitement ultérieur. Dans le courrier que vous envoyez, incluez un lien vers votre site avec le PIN inclus. Si le courrier est retourné, vous savez qu'il n'est pas valide. S'ils ne cliquent pas sur le lien, soit ils ont falsifié l'adresse, soit (en supposant qu'ils aient reçu le message) le suivi n'était pas important, donc vous n'avez pas à vous en soucier.

Comment décoder une chaîne MIME/BASE64 ?

Le package MIME::Base64 gère cela ainsi que l'encodage MIME/QP. Le décodage base 64 devient aussi simple que :

use MIME::Base64;
my $decoded = decode_base64($encoded);

Le module Email::MIME peut décoder les parties de message encodées en base 64 de manière transparente, de sorte que le développeur n'a pas à s'en soucier.

Comment trouver l'adresse e-mail de l'utilisateur ?

Demandez-la-lui. Il existe tellement de fournisseurs de messagerie disponibles qu'il est peu probable que le système local ait la moindre idée de la façon de déterminer l'adresse e-mail d'un utilisateur.

L'exception concerne les courriels spécifiques à une organisation (par exemple, foo@votreentreprise.com) où la politique peut être codifiée dans votre programme. Dans ce cas, vous pourriez regarder $ENV{USER}, $ENV{LOGNAME}, et getpwuid($<) en contexte scalaire, comme ceci :

my $user_name = getpwuid($<)

Mais vous ne pouvez toujours pas faire d'hypothèses quant à la correction, à moins que votre politique ne dise qu'elle l'est. Il est vraiment préférable de demander à l'utilisateur.

Comment envoyer un e-mail ?

Utilisez le module Email::Stuffer, comme ceci :

# d'abord, créez votre message
my $message = Email::Stuffer->from('vous@example.com')
                            ->to('ami@example.com')
                            ->subject('Joyeux anniversaire!')
                            ->text_body("Joyeux anniversaire à vous!\n");
$message->send_or_die;

Par défaut, Email::Sender::Simple (les méthodes "send" et "send_or_die" utilisent ceci en arrière-plan) essaiera d'abord "sendmail", s'il existe dans votre $PATH. Ce n'est généralement pas le cas. S'il existe un serveur de messagerie distant que vous utilisez pour envoyer des e-mails, envisagez d'explorer l'une des classes Transport. Au moment de la rédaction, les transports disponibles comprennent :

Email::Sender::Transport::Sendmail
C'est la valeur par défaut. Si vous pouvez utiliser le programme mail(1) ou mailx(1) pour envoyer des e-mails depuis la machine où votre code s'exécute, vous devriez pouvoir l'utiliser.
Email::Sender::Transport::SMTP
Ce transport contacte un serveur SMTP distant via TCP. Il utilise éventuellement TLS ou SSL et peut s'authentifier auprès du serveur via SASL.

Indiquer à Email::Stuffer d'utiliser votre transport est simple.

$message->transport($email_sender_transport_object)->send_or_die;

Comment utiliser MIME pour créer une pièce jointe à un message ?

Email::MIME prend directement en charge les messages multipart. Les objets Email::MIME eux-mêmes sont des parties et peuvent être joints à d'autres objets Email::MIME. Consultez la documentation Email::MIME pour plus d'informations, y compris toutes les méthodes prises en charge et des exemples de leur utilisation.

Email::Stuffer utilise Email::MIME en arrière-plan pour construire des messages, et enveloppe les tâches de pièces jointes les plus courantes avec les méthodes simples "attach" et "attach_file".

Email::Stuffer->to('ami@example.com')
              ->subject('Le fichier')
              ->attach_file('stuff.csv')
              ->send_or_die;

Comment lire l'e-mail ?

Utilisez le module Email::Folder, comme ceci :

use Email::Folder;
my $folder = Email::Folder->new('/chemin/vers/dossier/email');
while(my $message = $folder->next_message) {
  # next_message retourne des objets Email::Simple, mais nous voulons
  # des objets Email::MIME car ils sont plus robustes
  my $mime = Email::MIME->new($message->as_string);
}

Il existe différentes classes dans l'espace de noms Email::Folder pour prendre en charge divers types de boîtes aux lettres. Notez que ces modules sont généralement assez limités et ne prennent en charge que la lecture plutôt que l'écriture.

Comment trouver mon nom d'hôte, mon nom de domaine, ou mon adresse IP ?

(contribué par brian d foy)

Le module Net::Domain, qui fait partie de la bibliothèque standard à partir de Perl 5.7.3, peut vous donner le nom de domaine pleinement qualifié (FQDN), le nom d'hôte, ou le nom de domaine.

use Net::Domain qw(hostname hostfqdn hostdomain);
my $host = hostfqdn();

Le module Sys::Hostname, faisant partie de la bibliothèque standard, peut également obtenir le nom d'hôte :

use Sys::Hostname;
$host = hostname();

Le module Sys::Hostname::Long adopte une approche différente et s'efforce davantage de retourner le nom d'hôte pleinement qualifié :

use Sys::Hostname::Long 'hostname_long';
my $hostname = hostname_long();

Pour obtenir l'adresse IP, vous pouvez utiliser la fonction intégrée "gethostbyname" pour convertir le nom en un nombre. Pour convertir ce nombre en forme d'octet en pointillé (a.b.c.d) que la plupart des gens attendent, utilisez la fonction "inet_ntoa" du module Socket, qui est également fourni avec perl.

use Socket;
my $address = inet_ntoa(
    scalar gethostbyname( $host || 'localhost' )
);

Comment récupérer/envoyer un fichier (S)FTP ?

Net::FTP, et Net::SFTP vous permettent d'interagir avec les serveurs FTP et SFTP (Secure FTP).

Comment puis-je faire du RPC en Perl ?

Utilisez l'un des modules RPC ( https://metacpan.org/search?q=RPC ).
