NOM

perf-top - Outil de profilage système.

SYNTAXE

perf top [-e <EVENT> | --event=EVENT] [<options>]

DESCRIPTION

Cette commande génère et affiche un profil de compteur de performance en temps réel.

OPTIONS

-a, --all-cpus

Collecte sur l'ensemble des CPU. (par défaut)

-c <count>, --count=<count>

Période d'événements à échantillonner.

-C <cpu-list>, --cpu=<cpu>

Surveiller uniquement sur la liste des CPU fournie. Plusieurs CPU peuvent être fournies sous forme de liste séparée par des virgules sans espace : 0,1. Les plages de CPU sont spécifiées avec - : 0-2. Par défaut, tous les CPU sont surveillés.

-d <secondes>, --delay=<secondes>

Nombre de secondes à attendre entre chaque actualisation.

-e <event>, --event=<event>

Sélectionne l'événement PMU. La sélection peut être un nom d'événement symbolique (utilisez perf list pour lister tous les événements) ou un événement PMU brut sous la forme rN où N est une valeur hexadécimale représentant l'encodage brut du registre avec la disposition des registres de contrôle d'événements telle que décrite par les entrées dans /sys/bus/event_source/devices/cpu/format/*.

--filter=<filter>

Filtre d'événement. Cette option doit suivre un sélecteur d'événement (-e). Pour la syntaxe, voir perf-record(1).

-E <entrées>, --entries=<entrées>

Affiche ce nombre de fonctions.

-f <count>, --count-filter=<count>

N'affiche que les fonctions ayant plus d'événements que cette valeur.

--group-sort-idx

Trie la sortie par l'événement à l'index n du groupe. Si n est invalide, trie par le premier événement. Peut prendre en charge plusieurs groupes avec un nombre différent d'événements. ATTENTION : Ceci doit être utilisé sur des événements groupés.

-F <freq>, --freq=<freq>

Profile à cette fréquence. Utilisez max pour utiliser la fréquence maximale actuellement autorisée, c'est-à-dire la valeur dans le sysctl kernel.perf_event_max_sample_rate.

-i, --inherit

Les tâches enfants n'héritent pas des compteurs.

-k <path>, --vmlinux=<path>

Chemin vers vmlinux. Requis pour la fonctionnalité d'annotation.

--ignore-vmlinux

Ignore les fichiers vmlinux.

--kallsyms=<file>

Chemin du fichier kallsyms.

-m <pages>, --mmap-pages=<pages>

Nombre de pages de données mmap (doit être une puissance de deux) ou spécification de taille en octets avec un caractère d'unité ajouté - B/K/M/G. La taille est arrondie au nombre de pages de puissance de deux supérieur.

-p <pid>, --pid=<pid>

Profile les événements sur un Process ID existant (liste séparée par des virgules).

-t <tid>, --tid=<tid>

Profile les événements sur un Thread ID existant (liste séparée par des virgules).

-u, --uid=

Enregistre les événements dans les threads appartenant à l'uid. Nom ou numéro.

-r <priorité>, --realtime=<priorité>

Collecte les données avec cette priorité RT SCHED_FIFO.

--sym-annotate=<symbole>

Annote ce symbole.

-K, --hide_kernel_symbols

Masque les symboles du noyau.

-U, --hide_user_symbols

Masque les symboles utilisateur.

--demangle-kernel

Démangle les symboles du noyau.

-D, --dump-symtab

Affiche la table des symboles utilisée pour le profilage.

-v, --verbose

Être plus verbeux (afficher les erreurs d'ouverture de compteur, etc.).

-z, --zero

Zéro l'historique lors des mises à jour d'affichage.

-s, --sort

Trie par clé(s) : pid, comm, dso, symbol, parent, srcline, weight, local_weight, abort, in_tx, transaction, overhead, sample, period. Veuillez consulter la description de --sort dans la page de manuel de perf-report.

--fields=

Spécifie le champ de sortie - plusieurs clés peuvent être spécifiées au format CSV. Les champs suivants sont disponibles : overhead, overhead_sys, overhead_us, overhead_children, sample et period. Il peut également contenir n'importe quelle(s) clé(s) de tri. 
Par défaut, toutes les clés de tri non spécifiées dans --field seront ajoutées
automatiquement.

-n, --show-nr-samples

Affiche une colonne avec le nombre d'échantillons.

--show-total-period

Affiche une colonne avec la somme des périodes.

--dsos

Ne considère que les symboles dans ces dsos. Cette option affectera le pourcentage de la colonne overhead. Voir --percentage pour plus d'informations.

--comms

Ne considère que les symboles dans ces comms. Cette option affectera le pourcentage de la colonne overhead. Voir --percentage pour plus d'informations.

--symbols

Ne considère que ces symboles. Cette option affectera le pourcentage de la colonne overhead. Voir --percentage pour plus d'informations.

-M, --disassembler-style=

Définit le style du désassembleur pour objdump.

--addr2line=<path>

Chemin vers l'exécutable addr2line.

--objdump=<path>

Chemin vers l'exécutable objdump.

--prefix=PREFIX, --prefix-strip=N

Supprime les N premières entrées des noms de fichiers sources dans les exécutables et ajoute PREFIX. Ceci permet d'afficher le code source compilé sur des systèmes avec une disposition de système de fichiers différente.

--source

Entrelace le code source avec le code assembleur. Activé par défaut, désactivé avec --no-source.

--asm-raw

Affiche le codage d'instruction brut des instructions assembleur.

-g

Active l'enregistrement du graphe d'appels (chaîne de piles/backtrace).

--call-graph [mode,type,min[,limit],order[,key][,branch]]

Configure et active l'enregistrement du graphe d'appels (chaîne de piles/backtrace), implique -g. Voir la section --call-graph dans les pages de manuel de perf-record et perf-report pour les détails.

--children

Accumule la chaîne d'appels des enfants dans l'entrée parente afin qu'ils puissent apparaître dans la sortie. La sortie aura une nouvelle colonne "Children" et sera triée sur ces données. Nécessite l'option -g/--call-graph activée. Voir la section ‘calcul de l'overhead’ pour plus de détails. Activé par défaut, désactivé avec --no-children.

--max-stack

Définit la limite de profondeur de la pile lors de l'analyse de la chaîne d'appels, tout ce qui dépasse la profondeur spécifiée sera ignoré. C'est un compromis entre la perte d'informations et un traitement plus rapide, en particulier pour les charges de travail qui peuvent avoir une très longue chaîne d'appels. 
Par défaut : /proc/sys/kernel/perf_event_max_stack lorsque présent, 127 sinon.

--ignore-callees=<regex>

Ignore les appels des fonctions correspondant à l'expression régulière donnée. Cela a pour effet de collecter les appelants de chaque fonction de ce type à un seul endroit dans l'arbre du graphe d'appels.

--percent-limit

N'affiche pas les entrées dont l'overhead est inférieur à ce pourcentage. (Par défaut : 0).

--percentage

Détermine comment afficher le pourcentage d'overhead des entrées filtrées. Des filtres peuvent être appliqués par les options --comms, --dsos et/ou --symbols ainsi que par les opérations de zoom dans l'interface utilisateur (thread, dso, etc.). 
"relative" signifie qu'il est relatif uniquement aux entrées filtrées, de sorte que la somme des entrées affichées sera toujours de 100%. "absolute" signifie qu'il conserve la valeur d'origine avant et après l'application du filtre.

-w, --column-widths=<width[,width...]>

Force la largeur de chaque colonne à la liste fournie, pour une lisibilité sur un terminal large. 0 signifie pas de limite (comportement par défaut).

--proc-map-timeout

Lors du traitement des threads préexistants /proc/XXX/mmap, cela peut prendre beaucoup de temps, car le fichier peut être énorme. Un délai d'attente est nécessaire dans de tels cas. Cette option définit la limite de temps d'attente. La valeur par défaut est de 500 ms.

-b, --branch-any

Active l'échantillonnage de la pile de branchements pris. Tout type de branchement pris peut être échantillonné. C'est un raccourci pour --branch-filter any. Voir --branch-filter pour plus d'informations.

-j, --branch-filter

Active l'échantillonnage de la pile de branchements pris. Chaque échantillon capture une série de branchements pris consécutifs
ranches. Le nombre de branches capturées avec chaque échantillon dépend du matériel sous-jacent, du type de branches d'intérêt et du code exécuté. Il est possible de sélectionner les types de branches capturées en activant des filtres. Pour une liste complète des modificateurs, consultez la page de manuel de perf record. 
L'option nécessite au moins un type de branche parmi any, any_call, any_ret, ind_call, cond.
Les niveaux de privilège peuvent être omis, auquel cas les niveaux de privilège de l'événement associé
sont appliqués au filtre de branche. Les niveaux de privilège du noyau (k) et de l'hyperviseur (hv) sont soumis aux permissions. Lorsque vous échantillonnez sur plusieurs événements, l'échantillonnage de la pile de branches est activé pour tous les événements d'échantillonnage. Le type de branche échantillonné est le même pour tous les événements.
Les différents filtres doivent être spécifiés sous forme de liste séparée par des virgules : --branch-filter any_ret,u,k
Notez que cette fonctionnalité peut ne pas être disponible sur tous les processeurs.

--branch-history

Ajoute les adresses des branches prises échantillonnées à la pile d'appels. Cela permet d'examiner le chemin emprunté par le programme pour atteindre chaque échantillon.

--raw-trace

Lors de l'affichage de la sortie traceevent, n'utilisez pas de format d'impression ou de plugins.

-H, --hierarchy

Active la sortie hiérarchique. En mode hiérarchique, chaque clé de tri regroupe les échantillons en fonction des critères, puis les subdivise à l'aide de la clé de tri de niveau inférieur. 
Par exemple, en sortie normale :
perf report -s dso,sym
#
# Overhead  Shared Object      Symbol
# ........  .................  ...........
    50.00%  [kernel.kallsyms]  [k] kfunc1
    20.00%  perf               [.] foo
    15.00%  [kernel.kallsyms]  [k] kfunc2
    10.00%  perf               [.] bar
     5.00%  libc.so            [.] libcall
En sortie hiérarchique :
perf report -s dso,sym --hierarchy
#
#   Overhead  Shared Object / Symbol
# ..........  ......................
    65.00%    [kernel.kallsyms]
      50.00%    [k] kfunc1
      15.00%    [k] kfunc2
    30.00%    perf
      20.00%    [.] foo
      10.00%    [.] bar
     5.00%    libc.so
       5.00%    [.] libcall

--overwrite

Activez cette option pour utiliser uniquement les enregistrements les plus récents, ce qui est utile sur les machines avec un grand nombre de cœurs comme Knights Landing/Mill, mais est désactivé par défaut car la pause utilisée dans cette technique entraîne une perte d'événements de métadonnées tels que PERF_RECORD_MMAP, ce qui empêche perf top de résoudre les échantillons, entraînant l'apparition de nombreux échantillons inconnus dans l'interface utilisateur. Activez cette option si vous êtes sur de telles machines et que vous profilez une charge de travail qui ne crée pas de threads de courte durée et/ou n'utilise pas de nombreuses opérations mmap exécutables. Des travaux sont prévus pour résoudre cette situation, en attendant, cette option restera désactivée par défaut.

--force

N'effectue pas la validation de propriété.

--num-thread-synthesize

Le nombre de threads à exécuter lors de la synthèse d'événements pour les processus existants. Par défaut, le nombre de threads est égal au nombre de CPU en ligne.

--namespaces

Enregistre les événements de type PERF_RECORD_NAMESPACES et les affiche avec la clé de tri cgroup_id.

-G name, --cgroup name

surveille uniquement dans le conteneur (cgroup) appelé "name". Cette option n'est disponible qu'en mode par CPU. Le système de fichiers cgroup doit être monté. Tous les threads appartenant au conteneur "name" sont surveillés lorsqu'ils s'exécutent sur les CPU surveillés. Plusieurs cgroups peuvent être fournis. Chaque cgroup est appliqué à l'événement correspondant, c'est-à-dire que le premier cgroup correspond au premier événement, le deuxième cgroup au deuxième événement, et ainsi de suite. Il est possible de fournir un cgroup vide (surveiller tout le temps) en utilisant, par exemple, -G foo,,bar. Les cgroups doivent avoir des événements correspondants, c'est-à-dire qu'ils se réfèrent toujours aux événements définis précédemment dans la ligne de commande. Si l'utilisateur souhaite suivre plusieurs événements pour un cgroup spécifique, il peut utiliser -e e1 -e e2 -G foo,foo ou simplement utiliser -e e1 -e e2 -G foo.

--all-cgroups

Enregistre les événements de type PERF_RECORD_CGROUP et les affiche avec la clé de tri cgroup.

--switch-on EVENT_NAME

Ne considère les événements qu'après avoir trouvé cet événement. 
Par exemple :
Trouver où les paquets de diffusion sont gérés
perf probe -L icmp_rcv
Insérer une sonde là :
perf probe icmp_rcv:59
Démarrer perf top et lui demander de ne considérer que les événements de cycles lorsqu'un
paquet de diffusion arrive. Cela affichera un menu avec deux entrées et
commencera à compter lorsqu'un paquet de diffusion arrivera :
perf top -e cycles,probe:icmp_rcv --switch-on=probe:icmp_rcv
Alternativement, on peut demander un groupe, et deux colonnes de surcharge
apparaîtront, la première pour les cycles et la seconde pour l'événement switch-on.
perf top -e '{cycles,probe:icmp_rcv}' --switch-on=probe:icmp_rcv
Cela peut être intéressant pour mesurer une charge de travail uniquement après que certaines phases d'initialisation
soient terminées, c'est-à-dire insérer une sonde perf à ce point et utiliser les exemples ci-dessus
en remplaçant probe:icmp_rcv par la sonde juste après l'initialisation.

--switch-off EVENT_NAME

Arrête de considérer les événements après avoir trouvé cet événement.

--show-on-off-events

Affiche également les événements --switch-on/off. Cela n'a aucun effet dans perf top actuellement, mais nous allons probablement faire en sorte que par défaut, les événements switch-on/off ne soient pas affichés en mode --group et que s'il n'y a qu'un seul événement en dehors des événements off/on, on passe directement au navigateur d'histogrammes, tout comme perf top le fait sans aucun événement spécifié.

--stitch-lbr

Affiche le graphe d'appels avec des LBR cousus, ce qui peut produire un graphe d'appels plus complet. L'option doit être utilisée avec l'enregistrement --call-graph lbr. Désactivée par défaut. Dans les cas courants avec des dépassements de pile d'appels, elle peut recréer de meilleures piles d'appels que la sortie par défaut de la pile d'appels lbr. Mais cette approche n'est pas infaillible. Il peut y avoir des cas où elle crée des piles d'appels incorrectes à partir de correspondances incorrectes. Les limitations connues incluent la gestion des exceptions comme setjmp/longjmp où les appels/retours ne correspondent pas.

--pfm-events events

Sélectionne un événement PMU en utilisant la syntaxe libpfm4 (voir http://perfmon2.sf.net), y compris la prise en charge des filtres d'événements. Par exemple, --pfm-events inst_retired:any_p:u:c=1:i. Plus d'un événement peut être passé à l'option en utilisant le séparateur virgule. Les événements matériels et les événements matériels génériques ne peuvent pas être mélangés. Ces derniers doivent être utilisés avec l'option -e. L'option -e et celle-ci peuvent être mélangées. Les événements peuvent être groupés en utilisant la notation {}.

Événement à afficher lorsque plusieurs compteurs sont actifs.

Filtre d'affichage du profil (>= nombre de succès).

[F]

Filtre d'affichage des annotations (>= % du total).

[s]

Annoter le symbole.

[S]

Arrêter l'annotation, revenir à l'affichage du profil complet.

[K]

Masquer les symboles du noyau.

[U]

Masquer les symboles utilisateur.

[z]

Activez/désactivez la mise à zéro du compte d'événements entre les mises à jour de l'affichage.

[qQ]

Quitter.

Appuyer sur une touche non mappée affiche un menu et invite à saisir une entrée.

CALCUL DE LA CHARGE

La charge CPU peut être affichée en deux colonnes : Enfants et Propre lorsque perf collecte des chaînes d'appels (et les colonnes Temps réel correspondantes pour la charge en temps réel). La charge propre est simplement calculée en additionnant toutes les valeurs de période de l'entrée - généralement une fonction (symbole). C'est la valeur que perf affiche traditionnellement et la somme de toutes les valeurs de charge propre devrait être de 100%.

La charge enfants est calculée en additionnant toutes les valeurs de période des fonctions enfants afin qu'elle puisse afficher la charge totale des fonctions de niveau supérieur, même si elles n'exécutent pas beaucoup de code directement. Enfants ici signifie les fonctions qui sont appelées par une autre fonction (parente).

Il peut être déroutant que la somme de toutes les valeurs de charge enfants dépasse 100%, car chacune d'entre elles est déjà une accumulation de la charge propre de ses fonctions enfants. Mais avec cette option activée, les utilisateurs peuvent trouver quelle fonction a le plus de charge, même si les échantillons sont répartis sur les enfants.

Considérez l'exemple suivant ; il y a trois fonctions comme ci-dessous.

.ft C
void foo(void) {
    /* faire quelque chose */
}
void bar(void) {
    /* faire quelque chose */
    foo();
}
int main(void) {
    bar()
    return 0;
}
.ft

Dans ce cas, foo est un enfant de bar, et bar est un enfant immédiat de main, donc foo est aussi un enfant de main. En d'autres termes, main est un parent de foo et bar, et bar est un parent de foo.

Supposons que tous les échantillons soient enregistrés dans foo et bar uniquement. Lorsqu'ils sont enregistrés avec des chaînes d'appels, la sortie affichera quelque chose comme ci-dessous dans la sortie habituelle (uniquement la charge propre) de perf report :

.ft C
Overhead  Symbol
........  .....................
  60.00%  foo
          |
          --- foo
              bar
              main
              __libc_start_main
  40.00%  bar
          |
          --- bar
              main
              __libc_start_main
.ft

Lorsque l'option --children est activée, la charge propre des fonctions enfants (c'est-à-dire foo et bar) est ajoutée aux parents pour calculer la charge enfants. Dans ce cas, le rapport pourrait être affiché comme suit :

.ft C
Children      Self  Symbol
........  ........  ....................
 100.00%     0.00%  __libc_start_main
          |
          --- __libc_start_main
 100.00%     0.00%  main
          |
          --- main
              __libc_start_main
 100.00%    40.00%  bar
          |
          --- bar
              main
              __libc_start_main
  60.00%    60.00%  foo
          |
          --- foo
              bar
              main
              __libc_start_main
.ft

Dans la sortie ci-dessus, la charge propre de foo (60%) a été ajoutée à la charge enfants overhead de bar, main et __libc_start_main. De même, l'overhead self de bar (40%) a été ajouté à l'overhead children de main et \_\_libc_start_main.

Ainsi, \_\_libc_start_main et main sont affichés en premier car ils ont le même overhead children (100%) (même s'ils ont un overhead self nul) et ce sont les parents de foo et bar.

Depuis la v3.16, l'overhead children est affiché par défaut et la sortie est triée selon ses valeurs. L'overhead children est désactivé en spécifiant l'option --no-children sur la ligne de commande ou en ajoutant report.children = false ou top.children = false dans le fichier de configuration de perf.
