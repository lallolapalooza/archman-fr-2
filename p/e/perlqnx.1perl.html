NOM

perlqnx - Version 5 de Perl sur QNX

DESCRIPTION

Depuis perl5.7.2, tous les tests réussissent sous :

QNX 4.24G
Watcom 10.6 avec Beta/970211.wcc.update.tar.F
socket3r.lib 21 novembre 1996.

Depuis perl5.8.1, au moins un test échoue encore.

Certains tests peuvent se plaindre dans des circonstances connues.

Voir ci-dessous et hints/qnx.sh pour plus d'informations.

Sous QNX 6.2.0, quelques tests échouent encore. Voir ci-dessous et hints/qnx.sh pour plus d'informations.

Logiciels requis pour compiler Perl sur QNX4

Comme pour de nombreux ports Unix, celui-ci dépend de quelques utilitaires Unix "standard" qui ne sont pas nécessairement standard pour QNX4.

/bin/sh
Ceci est fortement utilisé par Configure, puis par Perl lui-même. La version de QNX4 est correcte, mais Configure échouera sur la version 16 bits, donc si vous utilisez QNX 4.22, liez /bin/sh à /bin32/ksh.
ar
C'est le constructeur de bibliothèques Unix standard. Nous utilisons wlib. Avec Watcom 10.6, lorsque wlib est lié comme "ar", il se comporte comme ar et tout va bien. Sous 9.5, une enveloppe est requise. Une est incluse dans ../qnx.
nm
Ceci est utilisé (facultativement) par configure pour lister le contenu des bibliothèques. Je générerai une fonction d'enveloppe à la volée dans le répertoire UU.
cpp
Configure et Perl ont besoin d'un moyen d'invoquer un préprocesseur C. J'ai créé une simple enveloppe pour cc qui fait ce qu'il faut. Sans cela, Configure créera son propre wrapper qui fonctionne, mais il ne gère pas certains des arguments de ligne de commande que perl lui lancera.
make
Vous avez vraiment besoin de GNU make pour compiler ceci. GNU make est livré par défaut avec QNX 4.23, mais vous pouvez l'obtenir auprès de quics pour les versions antérieures.

Problèmes en cours avec Perl sur QNX4

Il n'y a pas de support pour les bibliothèques liées dynamiquement sous QNX4.

Si vous souhaitez compiler avec l'extension Socket, vous devez avoir la boîte à outils TCP/IP, et vous devez vous assurer que -lsocket localise la bonne copie de socket3r.lib. Attention, le compilateur Watcom livre une version stub de socket3r.lib qui a très peu de fonctionnalités. Attention également à l'ordre dans lequel wlink recherche les répertoires pour les bibliothèques. Vous pouvez avoir /usr/lib/socket3r.lib pointant vers la bonne bibliothèque, mais wlink peut récupérer /usr/watcom/10.6/usr/lib/socket3r.lib à la place. Assurez-vous qu'ils pointent tous deux vers la bonne bibliothèque, c'est-à-dire /usr/tcptk/current/usr/lib/socket3r.lib.

Les tests suivants peuvent signaler des erreurs sous QNX4 :

dist/Cwd/Cwd.t se plaindra si `pwd` et cwd ne donnent pas les mêmes résultats. cwd appelle `fullpath -t`, donc si vous faites cd `fullpath -t` avant d'exécuter le test, il réussira.

lib/File/Find/taint.t se plaindra si '.' est dans votre PATH. Le test PATH est déclenché car cwd appelle `fullpath -t`.

ext/IO/lib/IO/t/io_sock.t : Les sous-tests 14 et 22 sont ignorés en raison du fait que la fonctionnalité pour relire l'état de non-blocage d'une socket n'est pas implémentée dans le TCP/IP de QNX. Ceci a été signalé à QNX et cela pourrait fonctionner avec des versions ultérieures de TCP/IP.

t/io/tell.t : Le sous-test 27 échoue. Nous enquêtons encore.

Fichiers auxiliaires QNX

Les fichiers du répertoire "qnx" sont :

qnx/ar
Un script qui émule l'utilitaire d'archive (alias, bibliothèque) Unix standard. Sous Watcom 10.6, ar est lié à wlib et fournit l'interface attendue. Avec Watcom 9.5, une enveloppe est requise. Celle-ci est assez rudimentaire mais s'est avérée adéquate pour compiler perl.
qnx/cpp
Un script qui fournit la fonctionnalité de préprocesseur C. Configure peut générer une enveloppe similaire, mais elle ne gère pas toutes les options de ligne de commande que perl lui lance. Ceci pourrait être raisonnablement placé dans /usr/local/bin.

Problèmes en cours avec perl sous QNX6

Les tests suivants échouent encore pour Perl 5.8.1 sous QNX 6.2.0 :

op/sprintf.........................FAILED at test 91
lib/Benchmark......................FAILED at test 26

Ceci est dû à un bug dans la routine printf de la bibliothèque C. printf("'%e'", 0. ) produit '0.000000e+0', mais ANSI exige '0.000000e+00'. QNX a reconnu le bug.

Compilation croisée

Perl prend en charge la compilation croisée vers QNX NTO via le kit de développement natif (NDK) pour Blackberry 10. Cela signifie que vous pouvez compiler en croisé pour les versions ARM et x86 de la plateforme.

Mise en place d'un environnement de compilation croisée

Vous pouvez télécharger le NDK depuis http://developer.blackberry.com/native/downloads/.

Consultez http://developer.blackberry.com/native/documentation/cascades/getting_started/setting_up.html pour les instructions de mise en place de votre appareil avant de tenter quoi que ce soit d'autre.

Une fois que vous avez installé le NDK et configuré votre appareil, il ne reste plus qu'à configurer l'appareil et l'environnement de compilation croisée. Blackberry fournit un script, "bbndk-env.sh" (parfois nommé quelque chose comme "bbndk-env_10_1_0_4828.sh") qui peut être utilisé pour cela. Cependant, il y a un petit problème à résoudre : le script modifie PATH de sorte que 'gcc' ou 'ar' pointent vers leurs équivalents de compilation croisée, ce qui perturbe le processus de construction.

Vous voudrez donc plutôt faire quelque chose comme ceci :

$ orig_path=$PATH
$ source $location_of_bbndk/bbndk-env*.sh
$ export PATH="$orig_path:$PATH"

En plus de placer le compilateur croisé et le reste de la chaîne d'outils dans votre PATH, cela fournira également la variable QNX_TARGET, que nous passerons à Configure via -Dsysroot.

Préparation du système cible

Il est tout à fait possible que le système cible n'ait pas de /tmp facilement disponible, il est donc généralement plus sûr de faire quelque chose comme ceci :

$ ssh $USER_CIBLE@$HOTE_CIBLE 'rm -rf perl; mkdir perl; mkdir perl/tmp'
$ export REPERTOIRE_CIBLE=`ssh $USER_CIBLE@$HOTE_CIBLE pwd`/perl
$ export ENV_CIBLE="export TMPDIR=$REPERTOIRE_CIBLE/tmp; "

Plus tard, nous passerons ceci à Configure via -Dtargetenv

Appel de Configure

Si vous ciblez un appareil ARM -- qui inclut actuellement la grande majorité des téléphones et tablettes -- vous voudrez passer -Dcc=arm-unknown-nto-qnx8.0.0eabi-gcc à Configure. Alternativement, si vous ciblez un appareil x86, ou si vous utilisez le simulateur fourni avec le NDK, vous devriez spécifier -Dcc=ntox86-gcc à la place.

Une invocation typique de Configure ressemble à ceci :

./Configure -des -Dusecrosscompile \
    -Dsysroot=$QNX_TARGET          \
    -Dtargetdir=$REPERTOIRE_CIBLE         \
    -Dtargetenv="$ENV_CIBLE"       \
    -Dcc=ntox86-gcc                \
    -Dtarghost=... # Options habituelles de compilation croisée
