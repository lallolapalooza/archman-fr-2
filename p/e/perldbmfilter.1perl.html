PERLDBMFILTER(1perl) Guide du programmeur Perl PERLDBMFILTER(1perl)

NOM

perldbmfilter - Filtres DBM Perl

SYNTAXE

$db = tie %hash, 'DBM', ...
$ancien_filtre = $db->filter_store_key  ( sub { ... } );
$ancien_filtre = $db->filter_store_value( sub { ... } );
$ancien_filtre = $db->filter_fetch_key  ( sub { ... } );
$ancien_filtre = $db->filter_fetch_value( sub { ... } );

DESCRIPTION

Les quatre méthodes "filter_*" présentées ci-dessus sont disponibles dans tous les modules DBM fournis avec Perl, à savoir DB_File, GDBM_File, NDBM_File, ODBM_File et SDBM_File.

Chacune des méthodes fonctionne de manière identique et est utilisée pour installer (ou désinstaller) un filtre DBM unique. La seule différence entre elles réside dans l'endroit où le filtre est installé.

Pour résumer :

filter_store_key
Si un filtre a été installé avec cette méthode, il sera appelé à chaque fois que vous écrirez une clé dans une base de données DBM.
filter_store_value
Si un filtre a été installé avec cette méthode, il sera appelé à chaque fois que vous écrirez une valeur dans une base de données DBM.
filter_fetch_key
Si un filtre a été installé avec cette méthode, il sera appelé à chaque fois que vous lirez une clé d'une base de données DBM.
filter_fetch_value
Si un filtre a été installé avec cette méthode, il sera appelé à chaque fois que vous lirez une valeur d'une base de données DBM.

Vous pouvez utiliser n'importe quelle combinaison des méthodes, de aucune à toutes les quatre.

Toutes les méthodes de filtre retournent le filtre existant, s'il est présent, ou "undef" sinon.

Pour supprimer un filtre, passez "undef" à celui-ci.

Le Filtre

Lorsque chaque filtre est appelé par Perl, une copie locale de $_ contiendra la clé ou la valeur à filtrer. Le filtrage est réalisé en modifiant le contenu de $_. Le code de retour du filtre est ignoré.

Un Exemple : le problème de la terminaison NULL

Les filtres DBM sont utiles pour une classe de problèmes où vous voulez toujours appliquer la même transformation à toutes les clés, toutes les valeurs ou les deux.

Par exemple, considérons le scénario suivant. Vous avez une base de données DBM que vous devez partager avec une application C tierce. L'application C suppose que toutes les clés et valeurs sont terminées par un NULL. Malheureusement, lorsque Perl écrit dans des bases de données DBM, il n'utilise pas la terminaison NULL, donc votre application Perl devra gérer la terminaison NULL elle-même. Lorsque vous écrivez dans la base de données, vous devrez utiliser quelque chose comme ceci :

$hash{"$key\0"} = "$value\0";

De même, le NULL doit être pris en compte lorsque vous considérez la longueur des clés/valeurs existantes.

Il serait beaucoup mieux si vous pouviez ignorer le problème de la terminaison NULL dans le code de l'application principale et disposer d'un mécanisme qui ajoute automatiquement le NULL de terminaison à toutes les clés et valeurs lors de l'écriture dans la base de données et les supprime lors de la lecture depuis la base de données. Comme vous l'avez sans doute déjà deviné, c'est un problème que les filtres DBM peuvent résoudre très facilement.

use v5.36;
use SDBM_File;
use Fcntl;
my %hash;
my $filename = "filt";
unlink $filename;
my $db = tie(%hash, 'SDBM_File', $filename, O_RDWR|O_CREAT, 0640)
  or die "Impossible d'ouvrir $filename: $!\n";
# Installer les filtres DBM
$db->filter_fetch_key  ( sub { s/\0$//    } );
$db->filter_store_key  ( sub { $_ .= "\0" } );
$db->filter_fetch_value( 
    sub { no warnings 'uninitialized'; s/\0$// } );
$db->filter_store_value( sub { $_ .= "\0" } );
$hash{"abc"} = "def";
my $x = $hash{"ABC"};
# ...
undef $db;
untie %hash;

Le code ci-dessus utilise SDBM_File, mais il fonctionnera avec n'importe lequel des modules DBM.

On espère que le contenu de chacun des filtres devrait s'expliquer de lui-même. Les deux filtres "fetch" suppriment le NULL de terminaison, et les deux filtres "store" ajoutent un NULL de terminaison.

Un Autre Exemple : La clé est un entier C

Voici un autre exemple concret. Par défaut, chaque fois que Perl écrit dans une base de données DBM, il écrit toujours la clé et la valeur sous forme de chaînes. Donc, lorsque vous utilisez ceci :

$hash{12345} = "quelque chose";

la clé 12345 sera stockée dans la base de données DBM sous forme de chaîne de 5 octets "12345". Si vous souhaitez que la clé soit stockée dans la base de données DBM en tant qu'entier C, vous devrez utiliser "pack" lors de l'écriture et "unpack" lors de la lecture.

Voici un filtre DBM qui le fait :

use v5.36;
use DB_File;
my %hash;
my $filename = "filt";
unlink $filename;
my $db = tie %hash, 'DB_File', $filename, O_CREAT|O_RDWR, 0666,
    $DB_HASH or die "Impossible d'ouvrir $filename: $!\n";
$db->filter_fetch_key  ( sub { $_ = unpack("i", $_) } );
$db->filter_store_key  ( sub { $_ = pack ("i", $_) } );
$hash{123} = "def";
# ...
undef $db;
untie %hash;

Le code ci-dessus utilise DB_File, mais encore une fois, il fonctionnera avec n'importe lequel des modules DBM.

Cette fois, seulement deux filtres ont été utilisés ; nous devons uniquement manipuler le contenu de la clé, il n'était donc pas nécessaire d'installer de filtres de valeur.

VOIR AUSSI

DB_File, GDBM_File, NDBM_File, ODBM_File et SDBM_File.
