NOM

perlos400 - Perl version 5 sur OS/400

Ce document doit être mis à jour, mais nous ne savons pas ce qu'il devrait dire. Veuillez soumettre vos commentaires à https://github.com/Perl/perl5/issues.

DESCRIPTION

Ce document décrit diverses fonctionnalités du système d'exploitation OS/400 d'IBM qui affecteront la manière dont Perl version 5 (ci-après Perl) est compilé et/ou exécuté.

De loin la manière la plus simple de construire Perl pour OS/400 est d'utiliser PASE (Portable Application Solutions Environment). Pour plus d'informations, voir http://www.iseries.ibm.com/developer/factory/pase/index.html. Cet environnement permet d'utiliser les API AIX lors de la programmation et fournit un environnement d'exécution qui permet aux binaires AIX de s'exécuter directement sur l'iSeries PowerPC.

Compilation de Perl pour OS/400 PASE

La manière recommandée de construire Perl pour l'OS/400 PASE est de construire le code source de Perl 5 (version 5.8.1 ou ultérieure) sous AIX.

L'astuce consiste à passer un paramètre spécial au script Configure lors de son exécution sur AIX :

sh Configure -DPASE ...

Le répertoire d'installation par défaut de Perl sous PASE est /QOpenSys/perl. Ceci peut être modifié si nécessaire avec le paramètre Configure -Dprefix=/some/dir.

À partir d'OS/400 V5R2, le compilateur IBM Visual Age est pris en charge sur OS/400 PASE, il est donc possible de construire Perl nativement sur OS/400. La manière la plus simple, cependant, est de compiler sous AIX, comme décrit ci-dessus.

Si vous ne souhaitez pas installer le Perl compilé dans AIX sous /QOpenSys (pour l'empaqueter avant de le copier dans PASE), vous pouvez utiliser un paramètre de Configure : -Dinstallprefix=/tmp/QOpenSys/perl. Cela entraînera l'installation de tout sous ce répertoire lors de la commande « make install », tandis que les fichiers installés penseront toujours qu'ils sont (seront) dans /QOpenSys/perl.

Si vous compilez nativement sous PASE, veuillez effectuer la compilation dans le répertoire /QOpenSys, car Perl fonctionne mieux lorsqu'il est compilé sur un système de fichiers sensible à la casse.

Installation de Perl dans OS/400 PASE

Si vous compilez sous AIX, exécutez simplement « make install » sur la machine AIX. Une fois l'installation terminée, archivez le répertoire /QOpenSys/perl. Transférez l'archive sur l'OS/400 en utilisant FTP avec les commandes suivantes :

> binary
> site namefmt 1
> put perl.tar /QOpenSys

Une fois que vous l'avez sur la machine, lancez simplement un shell PASE et extrayez l'archive.

Si vous compilez sous PASE, alors « make install » est la seule chose dont vous aurez besoin.

Le chemin par défaut pour le binaire perl est /QOpenSys/perl/bin/perl. Vous voudrez créer un lien symbolique /QOpenSys/usr/bin/perl vers ce fichier afin de ne pas avoir à modifier votre chemin.

Utilisation de Perl dans OS/400 PASE

Perl dans PASE peut être utilisé de la même manière que Perl serait utilisé sur AIX.

Les scripts commençant par #!/usr/bin/perl devraient fonctionner si vous avez un lien symbolique vers votre binaire perl à l'emplacement /QOpenSys/usr/bin/perl. Cela ne fonctionnera pas si vous avez fait un setuid/setgid ou si la variable d'environnement PASE_EXEC_QOPENSYS est définie sur « N ». Si vous avez la version V5R1, vous devrez obtenir les derniers PTF pour bénéficier de cette fonctionnalité. Les scripts commençant par #!/QOpenSys/perl/bin/perl devraient toujours fonctionner.

Problèmes connus

Lors de la compilation sous PASE, il n'y a pas de commande « oslevel ». Par conséquent, vous pourriez vouloir créer un script appelé « oslevel » qui affiche le niveau d'AIX pris en charge par votre version d'environnement d'exécution PASE. Si vous n'êtes pas sûr, consultez votre documentation ou utilisez « 4.3.3.0 ».

Si des cas de test échouent, vérifiez l'existence de fichiers spool. Le cas de test peut essayer d'utiliser un appel système qui n'est pas implémenté dans PASE. Pour éviter le SIGILL, essayez de définir la variable d'environnement PASE_SYSCALL_NOSIGILL ou d'avoir un gestionnaire pour SIGILL. Si vous pouvez compiler des programmes pour PASE, exécutez le script de configuration et modifiez config.sh lorsqu'il vous en donne l'option. Si vous souhaitez supprimer fchdir(), qui n'est pas implémenté en V5R1, changez simplement la ligne qui dit :

d_fchdir='define'

en

d_fchdir='undef'

puis compilez Perl. Les endroits où fchdir() est utilisé ont des alternatives pour les systèmes qui n'ont pas fchdir() disponible.

Perl sur ILE

Il existe un port de Perl vers l'environnement ILE. Ce port, cependant, est basé sur une version assez ancienne de Perl, Perl 5.00502 (août 1998). (En juillet 2002, la dernière version de Perl était 5.8.0, et même 5.6.1 est disponible depuis avril 2001.) Si vous avez besoin d'exécuter Perl sur ILE, vous pourriez avoir besoin de ce port plus ancien : http://www.cpan.org/ports/#os400. Notez que toute version de Perl ultérieure à 5.00502 n'a pas été portée sur ILE.

Si vous devez utiliser Perl dans l'environnement ILE, vous pourriez envisager d'utiliser Qp2RunPase() pour appeler la version PASE de Perl.
