PERLTRU64(1perl) Guide de référence du programmeur Perl PERLTRU64(1perl)

NOM

perltru64 - Version 5 de Perl sur les systèmes Tru64 (anciennement connu sous le nom de Digital UNIX, précédemment DEC OSF/1)

DESCRIPTION

Ce document décrit diverses fonctionnalités du système d'exploitation de HP (anciennement Compaq, précédemment Digital) (Tru64) qui affecteront la configuration, la compilation et/ou l'exécution de Perl version 5 (ci-après appelé Perl).

Compilation de Perl 5 sur Tru64

Le compilateur recommandé à utiliser sous Tru64 est le compilateur C natif. Le compilateur natif produit un code beaucoup plus rapide (la différence de vitesse est notable : plusieurs dizaines de pourcentages) et aussi un code plus correct : si vous envisagez d'utiliser le compilateur C de GNU, vous devriez utiliser au minimum la version 2.95.3 car toutes les versions antérieures de gcc sont connues pour produire du code défectueux lors de la compilation de Perl. Une manifestation de cette défaillance est le test lib/sdbm qui plante (core dump) ; une autre est que de nombreux tests op/regexp et op/pat, ou ext/Storable plantent (le schéma exact des échecs dépend de la version de GCC et des indicateurs d'optimisation).

Le compilateur natif cc et gcc semblent consommer beaucoup de mémoire lors de la construction de Perl. toke.c est un point problématique connu lors de l'optimisation : 256 mégaoctets de section de données semblent suffire. Un autre point problématique connu est le script mktables qui construit les tables de support Unicode. Le réglage par défaut de la section de données du processus sous Tru64 devrait être d'un gigaoctet, mais certains sites/configurations pourraient l'avoir abaissé. Le processus de configuration de Perl vérifie les limites de processus trop basses, réduit l'optimisation pour toke.c si nécessaire, et donne également des conseils sur la manière d'augmenter les limites de processus (par exemple : "ulimit -d 262144")

De plus, Configure pourrait avorter avec

Build a threading Perl? [n]
Configure[2437]: Syntax error at line 1 : 'config.sh' is not expected.

Cela indique que Configure est exécuté avec un shell Korn défectueux (même si vous pensez utiliser un shell Bourne en utilisant "sh Configure" ou "./Configure"). Le bug du shell Korn a été signalé à Compaq en février 1999 mais en attendant, la raison pour laquelle ksh est utilisé est que vous avez la variable d'environnement BIN_SH définie à 'xpg4'. Cela amène /bin/sh à déléguer ses fonctions à /bin/posix/sh (un ksh). Supprimez la variable d'environnement et relancez Configure.

Utilisation de grands fichiers avec Perl sur Tru64

Sous Tru64, Perl est automatiquement capable d'utiliser de grands fichiers, c'est-à-dire des fichiers de plus de 2 gigaoctets, il n'est pas nécessaire d'utiliser l'option Configure -Duselargefiles décrite dans INSTALL (bien que l'utilisation de l'option soit inoffensive).

Perl threadé sur Tru64

Si vous souhaitez utiliser des threads, vous devriez principalement utiliser le modèle de threads de Perl 5.8.0 en exécutant Configure avec -Duseithreads.

Le threading de Perl ne fonctionnera que sous Tru64 4.0 et les versions ultérieures ; les versions plus anciennes du système d'exploitation comme la 3.2 ne fonctionneront probablement pas correctement avec les threads.

Sous Tru64 V5 (au moins V5.1A, V5.1B), vous ne pouvez pas compiler de Perl threadé avec gcc car l'en-tête système <pthread.h> vérifie explicitement les compilateurs C pris en charge, gcc (au moins 3.2.2) n'en faisant pas partie. Mais le compilateur C système devrait fonctionner parfaitement.

Long Doubles sur Tru64

Vous ne pouvez pas configurer Perl pour utiliser des long doubles à moins d'avoir au moins Tru64 V5.0 ; le support des long doubles n'était tout simplement pas assez fonctionnel avant cela. Configure de Perl remplacera les tentatives d'utilisation des long doubles (vous pouvez le remarquer en voyant Configure découvrir que la fonction modfl() ne fonctionne pas comme elle le devrait).

Au moment de la rédaction (juin 2002), il existe un bogue connu dans l'impression par libc de Tru64 des long doubles lorsque la notation "e" n'est pas utilisée. Les valeurs sont correctes et utilisables, mais vous n'obtenez qu'un nombre limité de chiffres affichés à moins de forcer la chose en utilisant "printf "%.33e",$num" ou similaire. Pour les versions Tru64 V5.0A à V5.1A, un correctif est attendu peu après la sortie de perl 5.8.0. Si votre libc n'a pas encore été corrigée, vous obtiendrez un avertissement de Configure lors de la sélection des long doubles.

Tests de DB_File échouant sur Tru64

Les tests DB_File (db-btree.t, db-hash.t, db-recno.t) peuvent échouer si vous avez installé une version plus récente de Berkeley DB dans le système et que les indicateurs de compilateur et de lieur -I et -L introduisent des conflits de version avec les en-têtes et bibliothèques DB 1.85 fournis avec Tru64. Par exemple, mélanger une bibliothèque DB v2 avec les en-têtes DB v1 est une mauvaise idée. Faites attention aux options Configure -Dlocincpth et -Dloclibpth, et vérifiez vos /usr/local/include et /usr/local/lib car ils sont inclus par défaut.

La deuxième option consiste à instruire explicitement Configure de détecter la nouvelle installation de Berkeley DB, en fournissant les bons répertoires avec "-Dlocincpth=/some/include" et "-Dloclibpth=/some/lib" et avant d'exécuter "make test" en définissant votre LD_LIBRARY_PATH à /some/lib.

La troisième option consiste à contourner le problème en désactivant complètement DB_File lors de la construction de Perl en spécifiant -Ui_db à Configure, puis en utilisant le module BerkeleyDB de CPAN au lieu de DB_File. BerkeleyDB fonctionne avec les versions 2.* ou supérieures de Berkeley DB.

Berkeley DB 4.1.25 a été testé avec Tru64 V5.1A et s'est avéré fonctionnel. La dernière version de Berkeley DB peut être trouvée sur http://www.sleepycat.com.

Perl 64 bits sur Tru64

Sous Tru64, les entiers de Perl ont automatiquement une largeur de 64 bits, il n'est pas nécessaire d'utiliser l'option Configure -Duse64bitint décrite dans INSTALL. De même, il n'est pas nécessaire d'utiliser -Duse64bitall car les pointeurs ont automatiquement une largeur de 64 bits.

Avertissements concernant le dépassement de capacité en virgule flottante lors de la compilation de Perl sur Tru64

Lors de la compilation de Perl sous Tru64, vous pouvez (selon la version du compilateur) voir deux avertissements comme celui-ci :

cc: Warning: numeric.c, line 104: In this statement, floating-point
overflow occurs in evaluating the expression "1.8e308". (floatoverfl)
    return HUGE_VAL;
-----------^

et lors de la compilation de l'extension POSIX

cc: Warning: const-c.inc, line 2007: In this statement, floating-point
overflow occurs in evaluating the expression "1.8e308". (floatoverfl)
            return HUGE_VAL;
-------------------^

Les numéros de ligne exacts peuvent varier entre les versions de Perl. Les avertissements sont bénins et peuvent être ignorés : dans les versions ultérieures du compilateur C, les avertissements devraient avoir disparu.

Lorsque le fichier pp_sys.c est compilé, vous pouvez (selon la version du système d'exploitation) voir un indicateur de compilateur supplémentaire être utilisé : "-DNO_EFF_ONLY_OK". Ceci est normal et fait référence à une fonctionnalité qui n'est pertinente que si vous utilisez le pragma "filetest". Dans les versions antérieures du système d'exploitation, cette fonctionnalité était défectueuse et NO_EFF_ONLY_OK indique à Perl de ne pas utiliser cette fonctionnalité.

Test de Perl sur Tru64

Pendant "make test", le test "comp"/"cpp" sera ignoré car sous Tru64, il ne peut pas être testé avant que Perl n'ait été installé. Le test fait référence à l'utilisation de l'option "-P" de Perl.

ext/ODBM_File/odbm Test échouant avec les builds statiques

Le module ext/ODBM_File/odbm est connu pour échouer avec les builds statiques (Configure -Uusedl) en raison d'un bogue connu dans la bibliothèque statique libdbm de Tru64. La bonne nouvelle est que vous n'avez très probablement jamais besoin d'utiliser l'extension ODBM_File car NDBM_File, plus avancé, fonctionne bien, sans parler de DB_File, encore plus avancé.

perltru64(1perl) — Documentation Arch Linux

Nom

perltru64 - Spécificités de Perl pour Tru64

Description

Ce document décrit les problèmes courants et les solutions pour l'installation et l'utilisation de Perl sur les systèmes d'exploitation Tru64 (anciennement DEC OSF/1).

Test de Perl sur Tru64

L'exécution des tests standard de Perl peut échouer sur Tru64 pour diverses raisons liées à la plateforme.

ext/ODBM_File/odbm Test Échoue Avec Les Constructions Statiques

Si vous constatez que le test pour ODBM_File échoue lors d'une construction statique, cela peut être dû à une incompatibilité ou à un manque de symboles nécessaires dans la bibliothèque statique. Il est généralement recommandé d'utiliser des bibliothèques partagées si possible sur Tru64.

Perl échoue à cause d'un symbole non résolu sockatmark

Si vous obtenez une erreur telle que

Can't load '.../OSF1/lib/perl5/5.8.0/alpha-dec_osf/auto/IO/IO.so' for module IO: Unresolved symbol in .../lib/perl5/5.8.0/alpha-dec_osf/auto/IO/IO.so: sockatmark at .../lib/perl5/5.8.0/alpha-dec_osf/XSLoader.pm line 75.

vous devez soit recompiler votre Perl dans Tru64 4.0D, soit mettre à niveau votre Tru64 4.0D à au moins 4.0F : l'appel système sockatmark() a été ajouté dans Tru64 4.0F, et l'extension IO fait référence à ce symbole.

read_cur_obj_info: nombre magique de fichier incorrect

Il se peut que vous mélangez les outils Tru64 cc/ar/ld avec les outils GNU gcc/ar/ld. Cela peut fonctionner, mais parfois non (votre gcc ou vos utilitaires GNU peuvent avoir été compilés pour une version du système d'exploitation incompatible).

Essayez 'which ld' et 'which cc' (ou essayez 'ar --version' et 'ld --version', qui ne fonctionnent que pour les outils GNU et s'annonceront comme tels), et ajustez votre PATH de manière à utiliser de manière cohérente soit les outils natifs, soit les outils GNU. Après avoir corrigé votre PATH, vous devriez faire 'make distclean' et recommencer tout le processus à partir de l'exécution de Configure, car la situation peut être assez confuse.
