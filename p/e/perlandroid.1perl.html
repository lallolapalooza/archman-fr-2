PERLANDROID(1perl) Guide de référence des programmeurs Perl PERLANDROID(1perl)

NOM

perlandroid - Perl sous Android

SYNOPSIS

Les premières parties de ce document contiennent des instructions pour compiler croisement Perl pour Android 2.0 et versions ultérieures, en utilisant les binaires fournis par Google. Les parties ultérieures décrivent comment compiler nativement Perl en utilisant l'une des chaînes d'outils disponibles sur le Play Store.

DESCRIPTION

Ce document décrit comment configurer votre environnement hôte lors de la tentative de compilation de Perl pour Android.

Compilation croisée

Ces instructions supposent un environnement de compilation de type Unix sur votre système hôte ; elles ont été testées sous Linux et OS X, et peuvent fonctionner sous Cygwin et MSYS. Bien que Google fournisse également un NDK pour Windows, ces étapes ne fonctionneront pas nativement là-bas, bien qu'il soit possible de compiler croisement par d'autres moyens.

Si l'architecture de votre système hôte est 32 bits, n'oubliez pas de remplacer les "x86_64" ci-dessous par "x86". De même, les exemples ci-dessous utilisent la chaîne d'outils 4.8 ; si vous souhaitez en utiliser une plus ancienne ou plus récente (par exemple, la chaîne d'outils 4.4.3 incluse dans la 8ème révision du NDK), remplacez simplement celles-ci par la version pertinente.

Obtenir le kit de développement natif Android (NDK)

Vous pouvez télécharger le NDK depuis https://developer.android.com/tools/sdk/ndk/index.html. Vous aurez besoin de la version normale, pas de l'ancienne.

Déterminer l'architecture pour laquelle vous allez compiler croisement

Il y a trois options possibles : arm-linux-androideabi pour ARM, mipsel-linux-android pour MIPS, et simplement x86 pour x86. Depuis 2014, la plupart des appareils Android fonctionnent sur ARM, donc c'est généralement un choix sûr.

Avec ces deux éléments en main, vous devriez ajouter

$ANDROID_NDK/toolchains/$TARGETARCH-4.8/prebuilt/`uname | tr '[A-Z]' '[a-z]'`-x86_64/bin

à votre "PATH", où $ANDROID_NDK est l'emplacement où vous avez décompressé le NDK, et $TARGETARCH est l'architecture de votre cible.

Configurer une chaîne d'outils autonome

Ceci crée un sysroot fonctionnel que nous pourrons fournir à Configure plus tard.

$ export ANDROID_TOOLCHAIN=/tmp/my-toolchain-$TARGETARCH
$ export SYSROOT=$ANDROID_TOOLCHAIN/sysroot
$ $ANDROID_NDK/build/tools/make-standalone-toolchain.sh \
        --platform=android-9 \
        --install-dir=$ANDROID_TOOLCHAIN \
        --system=`uname | tr '[A-Z]' '[a-z]'`-x86_64 \
        --toolchain=$TARGETARCH-4.8

adb ou ssh ?

adb est l'Android Debug Bridge. Pour nos besoins, c'est essentiellement un moyen d'établir une connexion ssh à un appareil Android sans avoir à installer quoi que ce soit sur l'appareil lui-même, tant que l'appareil est soit sur le même réseau local que l'hôte, soit connecté à l'hôte via USB.

Perl peut être compilé croisement en utilisant soit adb soit une connexion ssh normale ; en général, si vous pouvez connecter votre appareil à l'hôte à l'aide d'un port USB, ou si vous n'avez pas envie d'installer une application sshd sur votre appareil, vous pourriez vouloir utiliser adb, bien que vous puissiez être obligé de passer à ssh si votre appareil n'est pas racine et que vous n'avez pas de chance -- plus à ce sujet plus tard. Alternativement, si vous compilez croisement vers un émulateur, vous devrez utiliser adb.

adb

Pour utiliser adb, téléchargez le SDK Android depuis https://developer.android.com/sdk/index.html. La version "SDK Tools Only" devrait suffire -- si vous avez téléchargé l'ADT Bundle, vous pouvez trouver le sdk sous $ADT_BUNDLE/sdk/.

Ajoutez $ANDROID_SDK/platform-tools à votre "PATH", ce qui devrait vous donner accès à adb. Vous devrez maintenant trouver le nom de votre appareil en utilisant "adb devices", et le passer plus tard à Configure via "-Dtargethost=$DEVICE".

Cependant, avant d'appeler Configure, vous devez vérifier si l'utilisation d'adb est un choix viable en premier lieu. Parce qu'Android n'a pas de /tmp, et ne permet pas non plus d'exécutables sur la carte sd, nous devons trouver quelque part sur l'appareil où Configure peut placer certains fichiers, ainsi que pour que les tests s'exécutent. Si votre appareil est rooté, alors vous êtes bon. Essayez d'exécuter ceci :

$ export TARGETDIR=/mnt/asec/perl
$ adb -s $DEVICE shell "echo sh -c '\"mkdir $TARGETDIR\"' | su --"

Ce qui créera le répertoire dont nous avons besoin, et vous pourrez passer à l'étape suivante. /mnt/asec est monté en tant que tmpfs sous Android, mais il n'est accessible qu'à root.

Si votre appareil n'est pas rooté, vous pourriez encore avoir de la chance. Essayez d'exécuter ceci :

$ export TARGETDIR=/data/local/tmp/perl
$ adb -s $DEVICE shell "mkdir $TARGETDIR"

Si la commande fonctionne, vous pouvez passer à l'étape suivante, mais attention : Vous devrez supprimer le répertoire de l'appareil une fois que vous aurez terminé ! Contrairement à /mnt/asec, /data/local/tmp peut ne pas être automatiquement nettoyé une fois que vous éteignez le téléphone.

Si aucune de ces solutions ne fonctionne, alors vous ne pouvez pas utiliser adb pour compiler croisement vers votre appareil. Essayez de le rooter, ou optez pour la voie ssh.

ssh

Pour utiliser ssh, vous devrez installer et exécuter une application sshd et la configurer correctement. Il existe plusieurs applications payantes et gratuites qui font cela assez facilement, vous devriez donc pouvoir en trouver une sur le store. N'oubliez pas que Perl nécessite une connexion sans mot de passe, alors configurez une clé publique.

Notez que plusieurs applications crachent des saletés sur stderr à chaque connexion, ce qui peut perturber Configure. Vous devrez peut-être modifier la partie de Configure qui crée "run-ssh" pour qu'elle rejette stderr.

Comme vous utilisez ssh, vous devrez passer des arguments supplémentaires à Configure :

-Dtargetrun=ssh -Dtargethost=$TARGETHOST -Dtargetuser=$TARGETUSER -Dtargetport=$TARGETPORT

Configure et au-delà

Avec tout ce qui précède fait, vous êtes maintenant prêt à appeler Configure.

Si vous utilisez adb, une ligne Configure "de base" ressemblera à ceci :

$ ./Configure -des -Dusedevel -Dusecrosscompile -Dtargetrun=adb \
    -Dcc=$TARGETARCH-gcc   \
    -Dsysroot=$SYSROOT     \
    -Dtargetdir=$TARGETDIR \
    -Dtargethost=$DEVICE

Si vous utilisez ssh, ce n'est pas très différent -- nous changeons juste targetrun en ssh, et passons targetuser et targetport. Cela ressemble à ceci :

$ ./Configure -des -Dusedevel -Dusecrosscompile -Dtargetrun=ssh \
    -Dcc=$TARGETARCH-gcc        \
    -Dsysroot=$SYSROOT          \
    -Dtargetdir=$TARGETDIR      \
    -Dtargethost="$TARGETHOST"  \
    -Dtargetuser=$TARGETUSER    \
    -Dtargetport=$TARGETPORT

Maintenant, vous êtes prêt à exécuter "make" et "make test" !

Pour un dernier avertissement, si vous utilisez adb, "make test" peut sembler bloqué ; c'est parce qu'il ne produit rien jusqu'à ce qu'il ait fini d'exécuter tous les tests. Vous pouvez vérifier sa progression en vous connectant à l'appareil, en vous déplaçant vers $TARGETDIR, et en regardant le fichier output.stdout.

Notes

  • Si vous ciblez Android x86, vous devrez changer "$TARGETARCH-gcc" en "i686-linux-android-gcc".
  • Sur certains appareils plus anciens et moins puissants -- pensez début 2010 -- certains tests, en particulier t/re/uniprops.t, peuvent faire planter le téléphone, le faisant s'éteindre une fois, puis se rallumer.

Compilations natives

Bien que Google ne fournisse pas de chaîne d'outils native pour Android, vous pouvez toujours en obtenir une depuis le Play Store.

CCTools

Vous pourriez peut-être obtenir l'application CCTools, qui est gratuite. Gardez à l'esprit que vous voulez une chaîne d'outils complète ; certaines applications ont tendance à installer par défaut seulement une version rudimentaire sans certaines utilitaires importants, comme ar ou nm.

Une fois que la chaîne d'outils est correctement configurée, le seul obstacle restant est de localiser où elle a été installée sur l'appareil. Par exemple, CCTools installe sa chaîne d'outils dans /data/data/com.pdaxrom.cctools/root/cctools. Avec le chemin en main, compiler perl revient un peu à ceci :

export SYSROOT=<emplacement de la chaîne d'outils native>
export LD_LIBRARY_PATH="$SYSROOT/lib:`pwd`:`pwd`/lib:`pwd`/lib/auto:$LD_LIBRARY_PATH"
sh Configure -des -Dsysroot=$SYSROOT -Alibpth="/system/lib /vendor/lib"

Termux

Termux https://termux.com/ fournit un émulateur de terminal Android et un environnement Linux. Il est livré avec un perl compilé croisé déjà installé.

Compiler nativement perl 5.30 ou plus récent devrait être aussi simple que ceci :

sh Configure -des -Alibpth="/system/lib /vendor/lib"

Cela fonctionne certainement sur Android 8.1 (Oreo) au moins...
