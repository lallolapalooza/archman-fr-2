PERLCYGWIN(1perl) Guide de référence pour programmeurs Perl PERLCYGWIN(1perl)

NOM

perlcygwin - Perl pour Cygwin

SYNTAXE

Ce document vous aidera à configurer, construire, tester et installer Perl sur Cygwin. Ce document décrit également les fonctionnalités de Cygwin qui affecteront le comportement de Perl à l'exécution.

NOTE : Des paquets Perl précompilés sont disponibles pour Cygwin et une version de Perl est fournie dans l'installation normale de Cygwin. Si vous n'avez pas besoin de personnaliser la configuration, envisagez d'utiliser l'un de ces paquets.

PRÉREQUIS POUR COMPILATION DE PERL SUR CYGWIN

Cygwin = GNU+Cygnus+Windows (Ne quittez pas UNIX sans lui)

Les outils Cygwin sont des portages des outils de développement GNU populaires pour les plateformes Win32. Ils fonctionnent grâce à la bibliothèque Cygwin qui fournit les appels système UNIX et l'environnement que ces programmes attendent. Plus d'informations sur ce projet peuvent être trouvées à l'adresse :

https://www.cygwin.com/

Une version récente de Cygwin, en réseau ou commerciale, est requise.

Au moment où ce document a été mis à jour pour la dernière fois, Cygwin 3.0.7 était la version actuelle.

Configuration de Cygwin

Lors de la construction de Perl, des modifications peuvent être nécessaires à votre configuration Cygwin afin que Perl se construise proprement. Ces modifications ne sont pas requises pour une utilisation normale de Perl.

NOTE : Les binaires qui seront construits fonctionneront sur toutes les versions Win32. Ils ne dépendent pas de votre système hôte ou de votre configuration Cygwin (montages binaires/texte, cygserver). Les seules dépendances proviennent des chemins codés en dur comme /usr/local. Cependant, votre système hôte et votre configuration Cygwin affecteront le comportement de Perl à l'exécution (voir "TEST").

  • "PATH"

    Définissez la variable d'environnement "PATH" afin que Configure trouve les versions Cygwin des programmes. Tous les répertoires Windows non nécessaires devraient être supprimés ou déplacés à la fin de votre "PATH".

  • nroff

    Si vous n'avez pas nroff (qui fait partie du paquet groff), Configure ne vous demandera pas d'installer les pages de manuel man.

CONFIGURER PERL SUR CYGWIN

Les options par défaut collectées par Configure avec l'aide de hints/cygwin.sh construiront un Perl qui supporte le chargement dynamique (ce qui nécessite une cygperl5_16.dll partagée).

Ceci lancera Configure et conservera un enregistrement :

./Configure 2>&1 | tee log.configure

Si vous êtes prêt à accepter tous les défauts, lancez Configure avec -de. Cependant, plusieurs personnalisations utiles sont disponibles.

Nettoyage des binaires Perl sur Cygwin

Il est possible de nettoyer les exécutables et DLL créés par le processus de construction. Les binaires résultants seront significativement plus petits. Si vous souhaitez que les binaires soient nettoyés, vous pouvez soit ajouter une option -s lorsque Configure vous la demande,

Any additional ld flags (NOT including libraries)? [none] -s
Any special flags to pass to g++ to create a dynamically loaded
library?
[none] -s
Any special flags to pass to gcc to use dynamic linking? [none] -s

soit modifier hints/cygwin.sh et décommenter les variables pertinentes vers la fin du fichier.

Bibliothèques optionnelles pour Perl sur Cygwin

Plusieurs fonctions et modules Perl dépendent de l'existence de certaines bibliothèques optionnelles. Configure les trouvera si elles sont installées dans l'un des répertoires listés comme utilisés pour la recherche de bibliothèques. Des paquets précompilés pour la plupart d'entre elles sont disponibles auprès de l'installeur Cygwin.

  • "-lcrypt"

    Le paquet crypt distribué avec Cygwin est un port crypt DES 56 bits compatible Linux par Corinna Vinschen.

    Alternativement, les bibliothèques crypt de GNU libc ont été portées sur Cygwin.

    Depuis libcrypt 1.3 (mars 2016), vous devrez installer le paquet libcrypt-devel pour que Configure détecte crypt().

  • "-lgdbm_compat" ("use GDBM_File")

    GDBM est disponible pour Cygwin.

    NOTE : La bibliothèque GDBM ne fonctionne que sur les partitions NTFS.

  • "-ldb" ("use DB_File")

    BerkeleyDB est disponible pour Cygwin.

    NOTE : La bibliothèque BerkeleyDB ne fonctionne complètement que sur les partitions NTFS.

  • "cygserver" ("use IPC::SysV")

    Un portage de SysV IPC est disponible pour Cygwin.

    NOTE : Ceci n'a pas été testé de manière exhaustive. En particulier, "d_semctl_semun" est indéfini car il échoue à un test de Configure. Il crée également une dépendance au moment de la compilation car perl.h inclut <sys/ipc.h> et <sys/sem.h> (qui seront nécessaires à l'avenir lors de la compilation de modules CPAN). ACTUELLEMENT NON SUPPORTÉ !

  • "-lutil"

    Inclus avec le paquet netrelease standard de Cygwin, on trouve le paquet inetutils qui inclut libutil.a.

Options à la compilation pour Perl sur Cygwin

Le document INSTALL décrit plusieurs options à la compilation. Certaines d'entre elles fonctionneront avec Cygwin, d'autres ne sont pas encore possibles. De plus, certaines sont expérimentales. Vous pouvez soit sélectionner une option lorsque Configure vous la demande, soit définir (définir) des symboles sur la ligne de commande.

  • "-Uusedl"

    Définir ce symbole oblige Perl à être compilé statiquement.

  • "-Dusemymalloc"

    Par défaut, Perl n'utilise pas le malloc() inclus avec la source de Perl, car il était plus lent et pas entièrement thread-safe. Si vous voulez forcer Perl à se construire avec l'ancien -Dusemymalloc, définissez ceci.

  • "-Uuseperlio"

    Définir ce symbole désactive l'abstraction PerlIO. PerlIO est maintenant le défaut ; il n'est pas recommandé de désactiver PerlIO.

  • "-Dusemultiplicity"

    La multiplicité est requise lors de l'intégration de Perl dans un programme C et lors de l'utilisation de plusieurs instances d'interpréteur. Ceci n'est requis que lorsque vous construisez un perl non-threadé avec "-Uuseithreads".

  • "-Uuse64bitint"

    Par défaut, Perl utilise des entiers de 64 bits. Si vous voulez utiliser des entiers de 32 bits plus petits, définissez ce symbole.

  • "-Duselongdouble"

    gcc supporte les doubles longs (12 octets). Cependant, plusieurs fonctions mathématiques supplémentaires pour les doubles longs sont nécessaires pour les utiliser au sein de Perl ({atan2, cos, exp, floor, fmod, frexp, isnan, log, modf, pow, sin, sqrt}l, strtold). Celles-ci ne sont pas encore disponibles avec newlib, la libc de Cygwin.

  • "-Uuseithreads"

    Définissez ce symbole si vous voulez un perl non-threadé plus rapide.

  • "-Duselargefiles"

    Cygwin utilise des entiers de 64 bits pour les calculs internes de taille et de position, cela sera correctement détecté et défini par Configure.

  • "-Dmksymlinks"

    Utilisez ceci pour construire perl en dehors de l'arborescence source. Les détails se trouvent dans le document INSTALL. C'est la manière recommandée de construire perl à partir des sources.

TEST SUR CYGWIN

Il y a deux étapes pour exécuter la suite de tests :

make test 2>&1 | tee log.make-test
cd t; ./perl harness 2>&1 | tee ../log.harness

Les mêmes tests sont exécutés les deux fois, mais plus d'informations sont fournies lors de l'exécution en tant que "./perl harness", et vous pouvez exécuter les tests en parallèle en spécifiant plutôt

cd t; TEST_JOBS=n ./perl harness 2>&1 | tee ../log.harness

où n est le nombre maximum de tests à exécuter simultanément.

Les résultats des tests varient en fonction de votre système hôte et de votre configuration Cygwin. Si un test peut passer dans une certaine configuration Cygwin, il est toujours tenté et les échecs de tests explicables sont documentés. Il est possible que Perl réussisse tous les tests, mais il est plus probable que certains tests échouent pour l'une des raisons énumérées ci-dessous.

Permissions des fichiers sur Cygwin

Les permissions de fichiers UNIX sont basées sur des ensembles de bits de mode pour {lecture,écriture,exécution} pour chaque {utilisateur,groupe,autre}. Par défaut, Cygwin suit uniquement l'attribut en lecture seule Win32 représenté comme le bit d'écriture utilisateur UNIX (les fichiers sont toujours lisibles, les fichiers sont exécutables s'ils ont une extension .{com,bat,exe} ou commencent par "#!", les répertoires sont toujours lisibles et exécutables). Sur WinNT avec le paramètre "CYGWIN" ntea, les bits de mode supplémentaires sont stockés sous forme d'attributs de fichier étendus. Sur WinNT avec le paramètre "CYGWIN" ntsec par défaut, les permissions utilisent les descripteurs de sécurité et les listes de contrôle d'accès WinNT standard. Sans l'une de ces options, ces tests échoueront (liste non mise à jour pour le moment) :

Caractéristiques spécifiques du port Cygwin

Portabilité des scripts sur Cygwin

Cygwin fait un travail remarquable pour fournir des sémantiques de type UNIX sur les systèmes Win32. Cependant, en plus des points mentionnés ci-dessus, il existe quelques différences à connaître. Ceci est un guide très bref sur la portabilité, plus d'informations peuvent être trouvées dans la documentation Cygwin.

  • Chemins

    Les chemins Cygwin sont séparés par des barres obliques (/), les codes d'universalité du nommage (//UNC) sont également pris en charge. Depuis cygwin-1.7, les chemins non POSIX ne doivent pas être utilisés. Les noms peuvent contenir tous les caractères imprimables.

    Les noms de fichiers sont insensibles à la casse, mais conservent la casse. Un chemin contenant une barre oblique inverse ou une lettre de lecteur est un chemin Win32, et n'est pas soumis aux traductions appliquées aux chemins de style POSIX, mais cygwin vous avertira, il est donc préférable de les convertir en POSIX.

    Pour la conversion, nous avons Cygwin::win_to_posix_path() et Cygwin::posix_to_win_path().

    Depuis cygwin-1.7, les chemins sont encodés en UTF-8.

  • Texte/Binaire

    Depuis cygwin-1.7, les montages de texte sont dépréciés et fortement déconseillés.

    Lorsqu'un fichier est ouvert, il est en mode texte ou binaire. En mode texte, un fichier est soumis aux traductions CR/LF/Ctrl-Z. Avec Cygwin, le mode par défaut pour un open() est déterminé par le mode du montage qui sous-tend le fichier. Voir "Cygwin::is_binmount"(). Perl fournit une fonction binmode() pour définir le mode binaire sur les fichiers qui seraient autrement traités comme du texte. sysopen() avec le drapeau "O_TEXT" définit le mode texte sur les fichiers qui seraient autrement traités comme binaires :

    sysopen(FOO, "bar", O_WRONLY|O_CREAT|O_TEXT)

    lseek(), tell() et sysseek() ne fonctionnent qu'avec les fichiers ouverts en mode binaire.

    La question du texte/binaire est traitée en détail dans la documentation Cygwin.

  • PerlIO

    PerlIO remplace le comportement par défaut de Cygwin Texte/Binaire. Un fichier sera toujours traité comme binaire, quel que soit le mode du montage sur lequel il se trouve, tout comme sous UNIX. La traduction CR/LF doit donc être demandée soit dans l'appel open() comme ceci :

    open(FH, ">:crlf", "out.txt");

    ce qui fera la conversion de LF en CR/LF sur la sortie, soit dans les paramètres d'environnement (ajoutez ceci à votre .bashrc) :

    export PERLIO=crlf

    ce qui importera la couche PerlIO crlf qui effectue la conversion LF -> CRLF sur chaque sortie générée par perl.

  • .exe

    Les fonctions Cygwin stat(), lstat() et readlink() rendent l'extension .exe transparente en recherchant foo.exe lorsque vous demandez foo (sauf si un foo existe également). Cygwin n'exige pas d'extension .exe, mais gcc l'ajoute automatiquement lors de la compilation d'un programme. Cependant, lors de l'accès à un exécutable en tant que fichier normal (par exemple, cp dans un makefile), le .exe n'est pas transparent. Le programme install inclus avec Cygwin ajoute automatiquement un .exe lorsque nécessaire.

  • PIDs Cygwin vs Windows

    Les processus Cygwin ont leur propre pid, qui est différent du pid Windows sous-jacent. La plupart des fonctions Proc conformes à posix attendent le pid cygwin, mais plusieurs fonctions Win32::Process attendent le winpid. Par exemple $$ est le pid cygwin de /usr/bin/perl, qui n'est pas le winpid. Utilisez Cygwin::pid_to_winpid() et Cygwin::winpid_to_pid() pour traduire entre eux.

  • Erreurs Cygwin vs Windows

    Sous Cygwin, $^E est identique à $!. Lors de l'utilisation des fonctions API Win32, utilisez Win32::GetLastError() pour obtenir la dernière erreur Windows.

  • Erreurs de rebase lors de fork ou de system

    L'utilisation de fork() ou de system() vers un autre perl après le chargement de plusieurs dll peut entraîner un conflit d'adresse de base de DLL. L'erreur interne de cygwin ressemble à ceci :

    0 [main] perl 8916 child_info_fork::abort: data segment start:
parent (0xC1A000) != child(0xA6A000)

    ou :

    183 [main] perl 3588 C:\cygwin\bin\perl.exe: *** fatal error -
unable to remap C:\cygwin\bin\cygsvn_subr-1-0.dll to same address
as parent(0x6FB30000) != 0x6FE60000 46 [main] perl 3488 fork: child
3588 - died waiting for dll loading, errno11

    Voir https://cygwin.com/faq/faq.html#faq.using.fixing-fork-failures Il est utile s'il n'y a pas trop de DLL chargées en mémoire afin que l'espace d'adressage disponible soit plus grand, par exemple, arrêter le navigateur MS Internet Explorer peut aider.

    +Utilisez les utilitaires de rebase pour résoudre les conflits d'adresses de dll. Le package de rebase est inclus dans la configuration Cygwin. Utilisez setup.exe depuis https://cygwin.com/install.html pour l'installer.

    1. Arrêtez tous les processus perl et exécutez
    "</bin/find <dir" -xdev -name \*.dll | /bin/rebase -OT ->> ou

    2. Arrêtez tous les processus et services Cygwin, et exécutez setup.exe.

  • Divers

    Le verrouillage de fichiers à l'aide de la commande "F_GETLK" pour fcntl() est une stub qui renvoie "ENOSYS".

    L'implémentation de chroot() de Cygwin présente des failles (elle ne peut pas restreindre l'accès aux fichiers par les programmes Win32 natifs).

    L'édition sur place "perl -i" des fichiers ne fonctionne pas sans faire de sauvegarde du fichier en cours d'édition "perl -i.bak" en raison des restrictions de type fenêtrage, par conséquent Perl ajoute automatiquement le suffixe ".bak" si vous utilisez "perl -i" sans spécifier d'extension de sauvegarde.

Méthodes préconstruites :

"Cwd::cwd"
Retourne le répertoire de travail actuel.
"Cygwin::pid_to_winpid"
Traduit un PID Cygwin vers le PID Windows correspondant (qui peut ou non être le même).
"Cygwin::winpid_to_pid"
Traduit un PID Windows vers le PID Cygwin correspondant (s'il existe).
"Cygwin::win_to_posix_path"
Traduit un chemin Windows vers le chemin Cygwin correspondant, en respectant les points de montage actuels. Avec un deuxième argument non nul, retourne un chemin absolu. Les caractères double octet ne seront pas traduits.
"Cygwin::posix_to_win_path"
Traduit un chemin Cygwin vers le chemin Cygwin correspondant, en respectant les points de montage actuels. Avec un deuxième argument non nul, retourne un chemin absolu. Les caractères double octet ne seront pas traduits.
Cygwin::mount_table()
Retourne un tableau de [mnt_dir, mnt_fsname, mnt_type, mnt_opts]. 
perl -e 'for $i (Cygwin::mount_table) {print join(" ",@$i),"\n";}'
/bin c:\cygwin\bin system binmode,cygexec
/usr/bin c:\cygwin\bin system binmode
/usr/lib c:\cygwin\lib system binmode
/ c:\cygwin system binmode
/cygdrive/c c: system binmode,noumount
/cygdrive/d d: system binmode,noumount
/cygdrive/e e: system binmode,noumount
"Cygwin::mount_flags"
Retourne le type de montage et les drapeaux pour un point de montage spécifié. Une chaîne de caractères séparés par des virgules de mntent->mnt_type (toujours "system" ou "user"), puis les mntent->mnt_opts, où le premier est toujours "binmode" ou "textmode". 
system|user,binmode|textmode,exec,cygexec,cygdrive,mixed,
notexec,managed,nosuid,devfs,proc,noumount

Si l'argument est "/cygdrive", alors seuls les paramètres de montage de volume et le préfixe de montage cygdrive sont retournés.

Les montages utilisateur remplacent les montages système.

$ perl -e 'print Cygwin::mount_flags "/usr/bin"'
system,binmode,cygexec
$ perl -e 'print Cygwin::mount_flags "/cygdrive"'
binmode,cygdrive,/cygdrive
"Cygwin::is_binmount"
Retourne vrai si le chemin Cygwin donné est monté en mode binaire, faux si le chemin est monté en mode texte.
"Cygwin::sync_winenv"
Cygwin n'initialise pas toutes les variables d'environnement Win32 d'origine. Voir le bas de cette page https://cygwin.com/cygwin-ug-net/setup-env.html pour "Environnement Win32 restreint".

Certains programmes Win32 appelés depuis des programmes Cygwin peuvent nécessiter certaines variables d'environnement, telles que ADODB qui a besoin de %COMMONPROGRAMFILES%. Appelez Cygwin::sync_winenv() pour copier toutes les variables d'environnement Win32 dans votre processus et notez que Cygwin émettra un avertissement à chaque rencontre de chemins non POSIX.

INSTALLER PERL SUR CYGWIN

Ceci installera Perl, y compris les pages de manuel (*man*).

make install 2>&1 | tee log.make-install

NOTE : Si "STDERR" est redirigé, "make install" ne vous demandera **pas** d'installer perl dans /usr/bin.

Vous pourriez avoir besoin d'être Administrateur pour exécuter "make install". Si vous ne l'êtes pas, vous devez avoir les droits d'écriture dans les répertoires concernés.

Des informations sur l'installation de la documentation Perl au format HTML peuvent être trouvées dans le document INSTALL.

BOGUES SUR CYGWIN

La prise en charge de l'échange des identifiants utilisateur et groupe réels et effectifs est incomplète. Sur WinNT, Cygwin fournit setuid(), seteuid(), setgid() et setegid(). Cependant, des appels Cygwin supplémentaires pour manipuler les jetons d'accès et les contextes de sécurité WinNT sont nécessaires.
