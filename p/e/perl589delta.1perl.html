PERL589DELTA(1perl) Guide du programmeur Perl PERL589DELTA(1perl)

NOM

perl589delta - ce qu'il y a de nouveau dans perl v5.8.9

DESCRIPTION

Ce document décrit les différences entre la version 5.8.8 et la version 5.8.9.

Avis

La version 5.8.9 sera la dernière version significative de la série 5.8.x. Les futures versions de 5.8.x ne traiteront probablement que des problèmes de sécurité et des échecs de compilation de plateforme. Par conséquent, vous devriez envisager de migrer vers 5.10.x, si vous ne l'avez pas déjà fait. Voir "Problèmes connus" pour plus d'informations.

Changements incompatibles

Une construction particulière dans le code source des extensions écrites en C++ peut nécessiter une modification. Voir "Internes modifiés" pour plus de détails. Toutes les extensions écrites en C, la plupart de celles écrites en C++, et toutes les extensions compilées existantes ne sont pas affectées. Cela était nécessaire pour améliorer la prise en charge de C++.

À part cela, il n'y a pas de changements intentionnellement incompatibles avec 5.8.8. S'il en existe, ce sont des bugs et les rapports sont les bienvenus.

Améliorations principales

Base de données de caractères Unicode 5.1.0

La copie de la base de données de caractères Unicode incluse dans Perl 5.8 a été mise à jour de 4.1.0 à 5.1.0. Voir http://www.unicode.org/versions/Unicode5.1.0/#NotableChanges pour les changements notables.

stat et -X sur les descripteurs de répertoire

Il est maintenant possible d'appeler "stat" et les opérateurs de fichier "-X" sur les descripteurs de répertoire. Comme les descripteurs de répertoire et de fichier sont tous deux des barewords, il peut y avoir des ambiguïtés quant à celui qui était prévu. Dans ces situations, les sémantiques du descripteur de fichier sont préférées. Les deux traitent également les descripteurs de fichier *FILE{IO} comme les descripteurs de fichier *FILE.

Filtres de source dans @INC

Il est possible d'améliorer le mécanisme des hooks de sous-routines dans @INC en ajoutant un filtre de source par-dessus le descripteur de fichier ouvert et retourné par le hook. Cette fonctionnalité était prévue depuis longtemps, mais n'a été que récemment finalisée. Voir "require" dans perlfunc pour les détails. (Nicholas Clark)

Exceptions dans le pliage de constantes

La routine de pliage de constantes est maintenant encapsulée dans un gestionnaire d'exception, et si le pliage lève une exception (comme tenter d'évaluer 0/0), perl conserve maintenant l'arbre d'opérations actuel, au lieu d'interrompre tout le programme. Sans cette modification, les programmes ne compileraient pas s'ils avaient des expressions qui généraient des exceptions, même si ces expressions se trouvaient dans du code qui ne pouvait jamais être atteint à l'exécution. (Nicholas Clark, Dave Mitchell)

"no VERSION"

Vous pouvez maintenant utiliser "no" suivi d'un numéro de version pour spécifier que vous souhaitez utiliser une version de perl antérieure à celle spécifiée.

Amélioration du code de mise en cache interne UTF-8

Le code qui met en cache les décalages d'octets UTF-8 calculés pour les décalages de caractères d'une chaîne a été réécrit. Plusieurs bugs ont été trouvés et éliminés, et le code utilise maintenant mieux les informations dont il dispose, il devrait donc être plus rapide. En particulier, il ne scanne pas jusqu'à la fin d'une chaîne avant de calculer un décalage dans la chaîne, ce qui devrait accélérer certaines opérations sur les longues chaînes. Il est maintenant possible de désactiver le code de mise en cache à l'exécution, pour vérifier qu'il n'est pas la cause de problèmes suspectés.

Installations déplaçables à l'exécution

Il existe maintenant un support pour Configure afin de créer un arbre perl qui est déplaçable à l'exécution. voir "Installations déplaçables".

Nouvelles variables internes

"${^CHILD_ERROR_NATIVE}"
Cette variable donne le statut natif retourné par la dernière fermeture de pipe, la commande entre backticks, l'appel réussi à "wait" ou "waitpid", ou par l'opérateur "system". Voir perlvar pour les détails. (Contribué par Gisle Aas.)
"${^UTF8CACHE}"
Cette variable contrôle l'état du code interne de mise en cache des décalages UTF-8. 1 pour activé (par défaut), 0 pour désactivé, -1 pour déboguer le code de mise en cache en vérifiant tous ses résultats par rapport à des scans linéaires, et paniquer en cas de divergence.

"readpipe" est maintenant surchargable

La fonction intégrée "readpipe" est maintenant surchargable. La surcharger permet également de surcharger son équivalent opérateur, "qx//" (également connu sous le nom de ``).

macros simples de gestion d'exceptions

Perl 5.8.9 (et les versions ultérieures à partir de 5.10.0) fournit maintenant quelques macros pour effectuer une gestion d'exception très basique dans les modules XS. Vous pouvez utiliser ces macros si vous appelez du code qui peut "croak", mais que vous devez effectuer un nettoyage avant de redonner le contrôle à Perl. Voir "Gestion des exceptions" dans perlguts pour plus de détails.

Améliorations de l’option -D

  • "-Dq" supprime le message EXECUTING... lors de l'exécution sous "-D"
  • "-Dl" enregistre l'entrée et la sortie de la boucle runops, et le désempilement des niveaux de saut.
  • "-Dv" affiche l'identifiant du processus dans la sortie de trace.

SWASHGET assisté par XS

Une partie du code Perl pur utilisé par le moteur d'expressions régulières pour récupérer les propriétés Unicode et les mappings de translittération a été réimplémentée en XS pour une exécution plus rapide. (SADAHIRO Tomoyuki)

Sous-routines constantes

Les internes de l'interpréteur prennent maintenant en charge une forme plus économe en mémoire des constantes inlineables. Stocker une référence à une valeur constante dans une table de symboles équivaut à un typeglob complet référençant une sous-routine constante, mais utilise environ 400 octets de mémoire en moins. Cette sous-routine constante proxy est automatiquement mise à niveau vers un véritable typeglob avec sous-routine si nécessaire. L'approche adoptée est analogue à l'optimisation d'espace existante pour les déclarations de stubs de sous-routines, qui sont stockées comme des scalaires simples à la place du typeglob complet.

Cependant, pour aider à la compatibilité ascendante du code existant, qui (à tort) ne s'attend pas à autre chose que des typeglobs dans les tables de symboles, rien dans le cœur n'utilise cette fonctionnalité, à l'exception des tests de régression.

Les stubs pour les sous-routines prototypées sont stockés dans les tables de symboles comme des chaînes simples, et les stubs pour les sous-routines non prototypées comme le nombre -1, depuis 5.005. Ainsi, le code qui suppose que le cœur ne place que des typeglobs dans les tables de symboles faisait des hypothèses incorrectes depuis plus de 10 ans.

Améliorations des performances

  • Par défaut depuis perl 5.000, perl créait un scalaire vide avec chaque typeglob nouveau. L'utilisation accrue des variables lexicales signifie que la plupart sont maintenant inutilisées. Grâce aux efforts de Nicholas Clark, Perl peut maintenant être compilé avec "-DPERL_DONT_CREATE_GVSV" pour éviter de créer ces scalaires vides. Cela diminuera considérablement le nombre de scalaires alloués pour toutes les configurations, et le nombre de scalaires qui doivent être copiés pour la création d'ithread. Bien que cette option soit compatible avec les installations Perl existantes, elle modifie une hypothèse de longue date sur les internes, elle n'est donc pas activée par défaut, car certains codes tiers peuvent dépendre de l'ancien comportement.

    Nous recommandons de tester avec cette configuration sur de nouveaux déploiements de Perl, en particulier pour les serveurs multi-thread, afin de voir si tous les codes tiers sont compatibles avec elle, car cette configuration peut offrir des améliorations de performance utiles. Pour les installations existantes, nous ne recommandons pas de passer à cette configuration à moins qu'un test approfondi ne soit effectué avant le déploiement.

  • "diagnostics" n'utilise plus $&, ce qui entraîne des accélérations importantes pour la correspondance d'expressions régulières dans tout le code qui l'utilise.
  • Les classes d'expressions régulières d'un seul caractère sont maintenant traitées de la même manière que si le caractère avait été utilisé comme littéral, ce qui signifie que le code qui utilise des classes de caractères comme mécanisme d'échappement verra une accélération. (Yves Orton)
  • La création de références de tableaux et de hachages anonymes (c'est-à-dire "[]" et "{}") n'entraîne plus de surcharge que la création d'une liste ou d'un hachage anonyme. Nicholas Clark a fourni des modifications avec une économie de deux ops et un push de pile, ce qui a été mesuré comme une amélioration légèrement meilleure que 5% pour ces opérations.
  • De nombreux appels à strlen() ont été éliminés, soit parce que la longueur était déjà connue, soit en adoptant ou en améliorant des API qui passent des longueurs. Cela a été facilité par l'adoption d'un wrapper my_sprintf(), qui renvoie la valeur C89 correcte - la longueur de la chaîne formatée. Auparavant, nous ne pouvions pas nous fier à la valeur de retour de sprintf(), car sur certaines plateformes anciennes mais existantes, elle renvoie toujours "char *".
  • "index" est maintenant plus rapide si la chaîne de recherche est stockée en UTF-8 mais ne contient que des caractères de la plage Latin-1.
  • Le cache des échantillons Unicode à l'intérieur du moteur d'expressions régulières est maintenant utilisé. (la recherche avait une clé incorrecte, présente depuis l'implémentation initiale). [RT #42839]

Améliorations de l'installation et de la configuration

Installations déplaçables

Il existe maintenant une prise en charge de Configure pour créer un arbre Perl déplaçable. Si vous Configure avec "-Duserelocatableinc", alors les chemins dans @INC (et tout le reste dans %Config) peuvent être trouvés de manière optionnelle via le chemin de l'exécutable perl.

Au démarrage, si des chemins dans @INC ou "Config" que Configure a marqués comme déplaçables (en les faisant commencer par ".../"), alors ils sont préfixés par le répertoire de $^X. Cela permet de configurer le déplacement sur une base par répertoire, bien que la valeur par défaut avec "-Duserelocatableinc" soit que tout est déplacé. L'installation initiale est effectuée vers le préfixe configuré d'origine.

Améliorations de la configuration

Configure est maintenant meilleur pour supprimer les fichiers temporaires. Tom Callaway (de RedHat) a également contribué à des correctifs qui complètent l'ensemble des drapeaux passés au compilateur et à l'éditeur de liens, en particulier le fait que "-fPIC" est maintenant activé sous Linux. Il se bloquera également lorsque votre /dev/null n'est pas un périphérique.

Une nouvelle variable de configuration "d_pseudofork" a été ajoutée à Configure, et est disponible en tant que $Config{d_pseudofork} dans le module "Config". Cela désactive

distingue le vrai "fork" de l'émulation de pseudofork utilisée sur les plateformes Windows.

Config.pod et config.sh sont maintenant placés correctement pour la compilation croisée.

$Config{useshrplib} vaut maintenant 'true' plutôt que 'yes' lors de l'utilisation d'une bibliothèque perl partagée.

Améliorations de la compilation

Les compilations parallèles devraient maintenant fonctionner correctement, bien qu'il puisse encore y avoir des problèmes si "make test" est instruit pour s'exécuter en parallèle.

De nombreux avertissements de compilation ont été corrigés. Un avertissement de compilateur très tenace dans S_emulate_eaccess() a été supprimé après six tentatives. La prise en charge de g++ a été optimisée, en particulier pour FreeBSD.

mkppport a été intégré, et tous les fichiers ppport.h du noyau seront maintenant auto-générés au moment de la compilation (et supprimés lors du nettoyage).

De très nombreux bogues liés à l'implémentation interne d'Unicode (UTF-8) ont été corrigés. En particulier, les bogues de longue date liés au retour d'Unicode via "tie", au surcharge ou à $@ ont disparu, certains n'ayant jamais été signalés.

"unpack" convertira en interne la chaîne de retour de UTF-8 vers des types numériques. C'est un compromis entre la cohérence totale présente dans la version 5.10 et le comportement actuel, qui est souvent utilisé comme une "fonctionnalité" pour les types de chaînes.

L'utilisation des couches d'entrée/sortie ":crlf" et "UTF-16" ensemble fonctionnera maintenant.

Correction d'un bogue où l'utilisation de certains motifs dans une expression régulière entraînait un panic. [RT #45337]

Plusieurs bogues ont été corrigés dans Magie, le système interne utilisé pour implémenter des fonctionnalités telles que "tie", le "tainting" et le partage de threads.

Pour les détails d'implémentation, voir "Magic Virtual Tables" dans perlguts.

Le reblessiment des objets surchargés fonctionne maintenant

En interne, la nature d'objet de perl réside dans la référence, pas dans la référence elle-même, bien que les méthodes ne puissent être appelées que via une référence. Cependant, l'implémentation originale du surcharge stockait les indicateurs liés au surcharge sur la référence, s'appuyant sur le fait que les indicateurs étaient copiés lorsque la référence était copiée, ou définis lors de la création d'une nouvelle référence. Cela se manifeste par un bogue : si vous reblessiez un objet d'une classe qui a un surcharge, dans une classe qui n'en a pas, alors toutes les autres références existantes pensent qu'elles pointent (toujours) vers un objet surchargé, choisissent ces chemins de code C, puis génèrent des erreurs. De même, blesser dans une classe surchargée alors que d'autres références existent fera qu'elles n'utiliseront pas le surcharge.

L'implémentation a été corrigée pour la version 5.10, mais cette correction modifie la sémantique des bits d'indicateurs, elle n'est donc pas binairement compatible, et ne peut donc pas être appliquée à la version 5.8.9. Cependant, la version 5.8.9 dispose d'une solution de contournement qui implémente la même correction de bogue. Si la référence a plusieurs références, alors toutes les autres références sont localisées et corrigées. Une recherche complète est évitée autant que possible en scannant les léxicaux à partir de la sous-routine actuelle et de la pile d'arguments.

Un certain vendeur Linux bien connu a appliqué des versions incomplètes de cette correction de bogue à son /usr/bin/perl, puis a prématurément fermé les rapports de bogues concernant des problèmes de performance sans consulter en amont. N'étant pas suffisant, ils ont ensuite ignoré les corrections nécessaires à ces changements non publiés pendant 11 mois, jusqu'à ce qu'une pression massive soit exercée par leurs clients payants lassés, catalysée par le fait que les défaillances étaient présentées sur un blog proéminent et sur Slashdot.

"strict" se propage maintenant correctement dans les évaluations de chaînes

Sous les versions 5.8.8 et antérieures :

$ perl5.8.8 -e 'use strict; eval "use foo bar" or die $@'
Can't locate foo.pm in @INC (@INC contains: ... .) at (eval 1) line 2.
BEGIN failed--compilation aborted at (eval 1) line 2.

Sous les versions 5.8.9 et ultérieures :

$ perl5.8.9 -e 'use strict; eval "use foo bar" or die $@'

Cela peut causer des problèmes avec les programmes qui analysent le message d'erreur et s'appuient sur le comportement défectueux.

    Internes modifiées

    Les sources Perl peuvent désormais être compilées avec un compilateur C++ au lieu d'un compilateur C. Une amélioration nécessaire est que sous C++, la macro "XS" utilisée pour définir les XSUBs inclut désormais une définition "extern "C"". Un effet secondaire est que le code C++ qui utilisait la construction

    typedef XS(SwigPerlWrapper);

    doit maintenant être écrit

    typedef XSPROTO(SwigPerlWrapper);

    en utilisant la nouvelle macro "XSPROTO", afin de compiler. Les extensions C ne sont pas affectées, bien que les extensions C soient encouragées à utiliser également "XSPROTO". Cette modification était présente dans la version 5.10.0 de Perl, donc tout code activement maintenu qui utilisait cette construction aurait déjà dû être adapté. Le code nécessitant une modification échouera avec une erreur de compilation.

    "set" magic lors de la localisation/affectation à une variable magique ne se déclenchera désormais que pour les *magies de conteneurs*, c'est-à-dire qu'elle se déclenchera pour %ENV ou %SIG mais pas pour $#array.

    La nouvelle macro d'API newSVpvs() peut être utilisée à la place de constructions telles que "newSVpvn("ISA", 3)". Elle prend une seule constante de chaîne, et au moment de la compilation C détermine sa longueur.

    La nouvelle fonction d'API Perl_newSV_type() peut être utilisée comme un remplacement plus efficace de l'idiome courant

    sv = newSV(0);
sv_upgrade(sv, type);

    De même, Perl_newSVpvn_flags() peut être utilisée pour combiner Perl_newSVpv() avec Perl_sv_2mortal() ou l'équivalent Perl_sv_newmortal() avec Perl_sv_setpvn()

    Deux nouvelles macros mPUSHs() et mXPUSHs() sont ajoutées, pour faciliter le push de SV mortels sur la pile. Elles ont ensuite été utilisées pour corriger plusieurs bugs où les valeurs sur la pile n'avaient pas été rendues mortelles.

    Une fonction Perl_signbit() a été ajoutée pour tester le signe d'un "NV". Elle correspond à la fonction système lorsque disponible.

    Perl_av_reify(), Perl_lex_end(), Perl_mod(), Perl_op_clear(), Perl_pop_return(), Perl_qerror(), Perl_setdefout(), Perl_vivify_defelem() et Perl_yylex() sont désormais visibles par les extensions. Ceci était nécessaire pour permettre à "Data::Alias" de fonctionner sous Windows.

    Perl_find_runcv() est désormais visible par les extensions du noyau Perl. Ceci était nécessaire pour permettre à "Sub::Current" de fonctionner sous Windows.

    Les fonctions "ptr_table*" sont maintenant disponibles dans les Perl non multithreadés. "Storable" en tire parti.

    De nombreux petits nettoyages ont été apportés aux internes. En particulier, Perl_sv_upgrade() a été considérablement simplifiée, avec un chemin de code direct qui utilise memset() et memcpy() pour initialiser le nouveau corps, plutôt que l'affectation via plusieurs variables temporaires. Elle a également bénéficié de la simplification et de la déduplication du code de gestion de l'arène.

    De nombreuses petites améliorations ont été apportées à la base de code grâce aux rapports de l'analyseur de code statique Coverity.

    Utilisation et documentation corrigées de Perl_gv_stashpv(), Perl_gv_stashpvn(), Perl_gv_stashsv() (le dernier paramètre est un masque de bits, pas un booléen).

    Les macros "PERL_SYS_INIT", "PERL_SYS_INIT3" et "PERL_SYS_TERM" ont été remplacées par des fonctions.

    "PERLSYS_TERM" ne nécessite plus de contexte. PerlIO_teardown() est maintenant appelée sans contexte, et la sortie de débogage dans cette fonction a été désactivée car elle nécessitait la présence d'un interpréteur, une hypothèse invalide au moment de la terminaison.

    Toutes les options de compilation qui affectent la compatibilité binaire ont été regroupées dans une variable globale ("PL_bincompat_options").

    Les valeurs de "PERL_REVISION", "PERL_VERSION" et "PERL_SUBVERSION" sont maintenant intégrées dans des variables globales (et donc dans toute bibliothèque Perl partagée). De plus, sous "MULTIPLICITY", l'exécutable Perl enregistre maintenant la taille de la structure de l'interpréteur (totale, et pour cette version). Couplé avec "PL_bincompat_options", cela permettra à 5.8.10 (et versions ultérieures), lorsqu'il est compilé avec une bibliothèque Perl partagée, d'effectuer des vérifications de cohérence dans main() pour s'assurer que la bibliothèque partagée est bien compatible au niveau binaire.

    Les références symboliques peuvent maintenant avoir des NUL intégrés. La nouvelle fonction publique Perl_get_cvn_flags() peut être utilisée dans les extensions si vous devez les gérer.

    Nettoyage des macros

    Le code source, et le code XS dans ext qui n'est pas dual-lived sur CPAN, n'utilisent plus les macros "PL_na", NEWSV(), Null(), "Nullav", "Nullcv", "Nullhv", "Nullhv" *etc*. Leur utilisation est déconseillée dans le nouveau code, en particulier "PL_na", qui représente un léger surcoût de performance.

    Problèmes connus

    Il n'y a pas de nouveaux bugs connus.

    Cependant, les programmes qui dépendent de bugs qui ont été corrigés auront des problèmes. De plus, de nombreuses corrections de bugs présentes dans 5.10.0 ne peuvent pas être rétroportées vers la branche 5.8.x, car elles nécessitent des modifications incompatibles au niveau binaire, ou parce que les changements de code sont trop importants et donc trop risqués à incorporer.

    Nous avons une main-d'œuvre bénévole limitée, et le fardeau de la maintenance devient de plus en plus complexe. Par conséquent, ce sera la dernière version significative de la série 5.8.x. Les futures versions de 5.8.x ne traiteront probablement que les problèmes de sécurité et les échecs de compilation sur plateforme. Par conséquent, vous devriez envisager de migrer vers 5.10.x, si vous ne l'avez pas déjà fait. Alternativement, si les exigences commerciales vous obligent à continuer à utiliser 5.8.x, vous pourriez envisager un support commercial auprès d'entreprises telles qu'ActiveState.

    Rapports de bugs

    Si vous trouvez ce qui vous semble être un bug, vous pouvez consulter les articles récemment publiés sur le groupe de discussion comp.lang.perl.misc et la base de données des bugs Perl à l'adresse http://bugs.perl.org. Vous y trouverez peut-être aussi des informations sur http://www.perl.org, la page d'accueil de Perl.

    Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bug à un cas de test simple mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage Perl. Vous pouvez parcourir et rechercher les bugs Perl 5 à l'adresse http://bugs.perl.org/

    Si le bug que vous signalez a des implications en matière de sécurité, ce qui le rend inapproprié à envoyer sur une liste de diffusion publiquement archivée, veuillez l'envoyer à perl5-security-report@perl.org. Ceci pointe vers une liste de diffusion fermée et non archivée, qui inclut tous les contributeurs principaux, qui pourront aider à évaluer l'impact des problèmes, trouver une solution et aider à coordonner la publication de correctifs pour atténuer ou résoudre le problème sur toutes les plateformes pour lesquelles Perl est supporté. Veuillez n'utiliser cette adresse que pour les problèmes de sécurité dans le noyau Perl, pas pour les modules distribués indépendamment sur CPAN.
