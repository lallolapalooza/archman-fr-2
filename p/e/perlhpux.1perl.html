PERLHPUX(1perl) Guide de référence du programmeur Perl PERLHPUX(1perl)

NOM

perlhpux - Version Perl 5 sur les systèmes Hewlett-Packard Unix (HP-UX)

DESCRIPTION

Ce document décrit diverses caractéristiques du système d'exploitation Unix de HP (HP-UX) qui affecteront la compilation et/ou l'exécution de Perl version 5 (ci-après simplement Perl).

Utilisation de perl fourni avec HP-UX

La version d'application de septembre 2001, HP-UX 11.00, est la première à être fournie avec Perl. Il s'agissait alors de perl-5.6.1 dans /opt/perl. La première occurrence se trouve sur le CD 5012-7954 et peut être installée à l'aide de

swinstall -s /cdrom perl

en supposant que vous ayez monté ce CD sur /cdrom.

Cette compilation était une compilation multithread portable hppa-1.1 prenant en charge les gros fichiers, compilée avec gcc-2.9-hppa-991112.

Si vous effectuez une nouvelle installation, une version (plus récente) de Perl sera installée automatiquement. Les systèmes HP-UX préinstallés disposent désormais de versions plus récentes de Perl et des modules mis à jour.

Les compilations officielles (threadées) de HP, telles qu'elles sont livrées sur les DVD/CD d'application, sont disponibles sur http://www.software.hp.com/portal/swdepot/displayProductInfo.do?productNumber=PERL pour PA-RISC et IPF (Itanium Processor Family). Elles sont compilées avec le compilateur HP ANSI-C. Jusqu'à la version 5.8.8, cela était fait par ActiveState.

Pour voir quelle version est incluse sur le DVD (supposé ici monté sur /cdrom), exécutez cette commande :

# swlist -s /cdrom perl
# perl           D.5.8.8.B  5.8.8 Perl Programming Language
  perl.Perl5-32  D.5.8.8.B  32-bit 5.8.8 Perl Programming Language
                                         with Extensions
  perl.Perl5-64  D.5.8.8.B  64-bit 5.8.8 Perl Programming Language
                                         with Extensions

Pour voir ce qui est installé sur votre système :

# swlist -R perl
# perl                    E.5.8.8.J  Perl Programming Language
# perl.Perl5-32           E.5.8.8.J  32-bit Perl Programming Language
                                     with Extensions
  perl.Perl5-32.PERL-MAN  E.5.8.8.J  32-bit Perl Man Pages for IA
  perl.Perl5-32.PERL-RUN  E.5.8.8.J  32-bit Perl Binaries for IA
# perl.Perl5-64           E.5.8.8.J  64-bit Perl Programming Language
                                     with Extensions
  perl.Perl5-64.PERL-MAN  E.5.8.8.J  64-bit Perl Man Pages for IA
  perl.Perl5-64.PERL-RUN  E.5.8.8.J  64-bit Perl Binaries for IA

Utilisation de perl provenant du centre de portage HP

Le centre de portage HP tente de suivre la demande des clients et de publier des mises à jour de la communauté Open Source. La disponibilité de binaires Perl précompilés est évidente, bien que « à jour » soit relatif. Au moment de la rédaction, perl-5.10.1 et 5.28.0 étaient disponibles.

Les centres de portage HP sont limités quant aux systèmes pour lesquels ils sont autorisés à porter des logiciels et choisissent généralement les deux versions les plus récentes du système d'exploitation disponibles.

HP a demandé au centre de portage de déplacer les binaires Open Source de /opt vers /usr/local. Les binaires produits depuis début juillet 2002 se trouvent donc dans /usr/local.

L'une des URL des centres de portage HP est http://hpux.connect.org.uk/ Le port actuellement disponible est compilé avec GNU gcc. Comme le portage de versions modernes de GNU gcc est extrêmement difficile sur HP-UX, ils sont bloqués à la version gcc-4.2.3.

Autres binaires perl précompilés

Pour obtenir plus de dépôts Perl pour toute la gamme HP-UX, visitez le site de H.Merijn Brand à l'adresse http://mirrors.develooper.com/hpux/#Perl. Lisez attentivement les notes pour voir si les versions disponibles correspondent à vos besoins.

Compilation de Perl 5 sur HP-UX

Lors de la compilation de Perl, vous devez utiliser un compilateur C ANSI. Le compilateur C fourni avec tous les systèmes HP-UX est un compilateur K&R qui ne doit être utilisé que pour construire de nouveaux noyaux.

Perl peut être compilé avec le compilateur C ANSI de HP ou avec gcc. Le premier est recommandé, car il peut non seulement compiler Perl sans difficulté, mais aussi tirer parti des fonctionnalités listées plus loin qui nécessitent l'utilisation d'indicateurs de ligne de commande spécifiques au compilateur HP.

Si vous décidez d'utiliser gcc, assurez-vous que votre installation est récente et complète, et lisez le fichier INSTALL de Perl pour plus de détails spécifiques à gcc.

PA-RISC

La dernière et ultime version de PA-RISC est la 2.0. HP ne vend plus aucun système avec ces processeurs.

Les systèmes Unix HP de HP9000 fonctionnent sur la puce Precision Architecture (PA-RISC) de HP. HP-UX fonctionnait auparavant sur la famille de puces MC68000 de Motorola, mais toute machine dotée de cette puce est assez obsolète et ce document n'essaiera pas de traiter les problèmes de compilation de Perl sur le chipset Motorola. Bien que le matériel PA-RISC ne soit plus vendu, de nombreuses machines fonctionnant encore sur ces processeurs peuvent être trouvées.

La dernière date de commande pour les systèmes HP 9000 était le 31 décembre 2008.

Portabilité Entre Versions PA-RISC

Un exécutable compilé sur une plateforme PA-RISC 2.0 ne s'exécutera pas sur une plateforme PA-RISC 1.1, même s'ils exécutent la même version d'HP-UX. Si vous compilez Perl sur une plateforme PA-RISC 2.0 et que vous souhaitez que ce Perl s'exécute également sur une PA-RISC 1.1, les options du compilateur +DAportable et +DS32 doivent être utilisées.

Il n'est plus possible de compiler des exécutables PA-RISC 1.0 sur les plateformes PA-RISC 1.1 ou 2.0. Les options de ligne de commande sont acceptées, mais l'exécutable résultant ne s'exécutera pas lorsqu'il sera transféré sur un système PA-RISC 1.0.

Famille de processeurs Itanium (IPF) et HP-UX

HP-UX s'exécute également sur le nouveau processeur Itanium. Cela nécessite l'utilisation de la version 11.23 (11i v2) ou 11.31 (11i v3) d'HP-UX, et à l'exception de quelques différences détaillées ci-dessous et dans les sections suivantes, Perl devrait se compiler sans problème.

Bien que les binaires PA-RISC puissent s'exécuter sur des systèmes Itanium, vous ne devez pas tenter d'utiliser une version PA-RISC de Perl sur un système Itanium. En effet, les bibliothèques partagées créées sur un système Itanium ne peuvent pas être chargées lors de l'exécution d'un exécutable PA-RISC.

Les systèmes HP Itanium 2 sont généralement désignés par la description de modèle "HP Integrity".

Compilation d'extensions dynamiques sur HP-UX

HP-UX supporte les bibliothèques chargeables dynamiquement (bibliothèques partagées). Les bibliothèques partagées se terminent par le suffixe .sl. Sur les systèmes Itanium, elles se terminent par le suffixe .so.

Les bibliothèques partagées créées sur une plateforme utilisant une version PA-RISC particulière ne sont pas utilisables par défaut sur des plateformes utilisant une version PA-RISC antérieure. Cependant, cette rétrocompatibilité peut être activée en utilisant la même option de compilateur +DAportable (avec la même mise en garde sur PA-RISC 1.0 mentionnée ci-dessus).

Les bibliothèques partagées créées sur une plateforme Itanium ne peuvent pas être chargées sur une plateforme PA-RISC. Les bibliothèques partagées créées sur une plateforme PA-RISC ne peuvent être chargées sur une plateforme Itanium que s'il s'agit d'un exécutable PA-RISC qui tente de charger la bibliothèque PA-RISC. Une bibliothèque partagée PA-RISC ne peut pas être chargée dans un exécutable Itanium ni vice versa.

Pour créer une bibliothèque partagée, les étapes suivantes doivent être effectuées :

1. Compiler les modules sources avec l'option +z ou +Z pour créer un module .o
   qui contient du code indépendant de la position (PIC). L'éditeur de liens
   vous le dira à l'étape suivante si +Z était nécessaire.
   (Pour gcc, l'option appropriée est -fpic ou -fPIC.)
2. Lier la bibliothèque partagée en utilisant l'option -b. Si le code appelle
   des fonctions dans d'autres bibliothèques système (par exemple, libm), il doit
   être inclus sur cette ligne.

(Notez que ces étapes sont généralement gérées automatiquement par le Makefile de l'extension).

Si ces bibliothèques dépendantes ne sont pas listées au moment de la création de la bibliothèque partagée, vous obtiendrez des erreurs fatales "Symbole non résolu" au moment de l'exécution lorsque la bibliothèque sera chargée.

Vous pouvez créer une bibliothèque partagée qui fait référence à une autre bibliothèque, qui peut être une bibliothèque archive ou une bibliothèque partagée. Si cette deuxième bibliothèque est une bibliothèque partagée, cela s'appelle une "bibliothèque dépendante". Le nom de la bibliothèque dépendante est enregistré dans la bibliothèque partagée principale, mais il n'est pas lié dans la bibliothèque partagée. Au lieu de cela, il est chargé lorsque la bibliothèque partagée principale est chargée. Cela peut causer des problèmes si vous compilez une extension sur un système et la déplacez vers un autre système où les bibliothèques peuvent ne pas être situées au même endroit que sur le premier système.

Si la bibliothèque référencée est une bibliothèque archive, alors elle est traitée comme une simple collection de modules .o (tous doivent contenir du PIC). Ces modules sont ensuite liés dans la bibliothèque partagée.

Notez qu'il est acceptable de créer une bibliothèque qui contient une bibliothèque dépendante déjà liée à Perl.

Certaines extensions, comme DB_File et Compress::Zlib, utilisent/nécessitent des bibliothèques pré-compilées pour que les extensions/modules Perl fonctionnent. Si ces bibliothèques sont compilées en utilisant la configuration par défaut, il peut arriver que vous rencontriez une erreur comme "correction de chargeur invalide" pendant la phase de chargement. HP est conscient de ce problème. Recherchez dans les forums HP-UX cxx-dev des discussions à ce sujet. La réponse courte est que tout (toutes les bibliothèques, tout) doit être compilé avec "+z" ou "+Z" pour être du code indépendant de la position (PIC). (Pour gcc, ce serait "-fpic" ou "-fPIC"). Dans HP-UX 11.00 ou plus récent, le message d'erreur de l'éditeur de liens devrait indiquer le nom du fichier objet en cause.

Une approche plus générale consiste à intervenir manuellement, comme avec un exemple pour le module DB_File, qui nécessite la libdb.sl de SleepyCat :

# cd .../db-3.2.9/build_unix
# vi Makefile
... ajouter +Z à tous les cflags pour créer des objets partagés
CFLAGS=         -c $(CPPFLAGS) +Z -Ae +O2 +Onolimit \
                -I/usr/local/include -I/usr/include/X11R6
CXXFLAGS=       -c $(CPPFLAGS) +Z -Ae +O2 +Onolimit \
                -I/usr/local/include -I/usr/include/X11R6
# make clean
# make
# mkdir tmp
# cd tmp
# ar x ../libdb.a
# ld -b -o libdb-3.2.sl *.o
# mv libdb-3.2.sl /usr/local/lib
# rm *.o
# cd /usr/local/lib
# rm -f libdb.sl
# ln -s libdb-3.2.sl libdb.sl
# cd .../DB_File-1.76
# make distclean
# perl Makefile.PL
# make
# make test
# make install

Depuis db-4.2.x, il n'est plus nécessaire de le faire manuellement. Sleepycat a modifié le processus de configuration pour ajouter +z sur HP-UX automatiquement.

# cd .../db-4.2.25/build_unix
# env CFLAGS=+DD64 LDFLAGS=+DD64 ../dist/configure

devrait fonctionner pour générer des bibliothèques partagées 64 bits pour HP-UX 11.00 et 11i.

Il n'est plus possible de lier des bibliothèques partagées PA-RISC 1.0 (même si les options de ligne de commande sont toujours présentes).

Les fichiers objets PA-RISC et Itanium ne sont pas interchangeables. Bien que vous puissiez utiliser ar pour créer une bibliothèque archive de fichiers objets PA-RISC sur un système Itanium, vous ne pouvez pas la lier en utilisant un éditeur de liens Itanium.

Le compilateur ANSI C de HP

Lorsque vous utilisez ce compilateur pour construire Perl, vous devez vous assurer que l'option -Aa est ajoutée aux variables cpprun et cppstdin dans le fichier config.sh (bien que voir la section sur Perl 64 bits ci-dessous). Si vous utilisez une version récente de la distribution Perl, ces options sont définies automatiquement.

Même si HP-UX 10.20 et 11.00 ne sont plus activement maintenus par HP, des mises à jour pour le compilateur HP ANSI C sont toujours disponibles de temps en temps, et il pourrait être conseillé de voir si des mises à jour sont applicables. Au moment de la rédaction, les dernières mises à jour disponibles pour 11.00 qui devraient être appliquées sont PHSS_35098, PHSS_35175, PHSS_35100, PHSS_33036 et PHSS_33902). Si vous avez un compte SUM, vous pouvez l'utiliser pour rechercher des mises à jour/correctifs. Entrez "ANSI" comme mot-clé.

Le compilateur GNU C

Lorsque vous allez utiliser le compilateur GNU C (gcc), et que vous n'avez pas encore gcc, vous pouvez soit le compiler vous-même (si vous vous sentez assez masochiste) à partir des sources (disponibles par exemple sur http://gcc.gnu.org/mirrors.html) ou télécharger un binaire pré-compilé depuis le centre de portage HP sur <http://hpux.connect.org.uk/hppd/cgi-bin/search?term=gcc&Search=Search> ou depuis le DSPP (vous devez être membre) sur <http://h21007.www2.hp.com/portal/site/dspp/menuitem.863c3e4cbcdc3f3515b49c108973a801?ciid=2a08725cc2f02110725cc2f02110275d6e10RCRD&jumpid=reg_r1002_usen_c-001_title_r0001> (Parcourez la liste, car il existe souvent plusieurs versions du même paquet disponible).

La plupart des distributions mentionnées sont des dépôts. H.Merijn Brand a rendu disponibles des binaires gcc précompilés sur http://mirrors.develooper.com/hpux/ et/ou http://www.cmve.net/~merijn/ pour HP-UX 10.20 (uniquement 32 bits), HP-UX 11.00, HP-UX 11.11 (HP-UX 11i v1) et HP-UX 11.23 (HP-UX 11i v2 PA-RISC) en versions 32 et 64 bits. Pour HP-UX 11.23 IPF et HP-UX 11.31 IPF, des dépôts sont également disponibles. Les versions IPF ne nécessitent pas deux versions de GNU gcc.

Sur PA-RISC, vous avez besoin d'un compilateur différent pour les applications 32 bits et pour les applications 64 bits. Sur PA-RISC, les objets 32 bits et les objets 64 bits ne se mélangent pas. Point final. Il n'y a pas de comportement différent pour HP C-ANSI-C ou GNU gcc. Ainsi, si vous exigez que votre binaire perl utilise des bibliothèques 64 bits, comme Oracle-64 bits, vous DEVEZ compiler un perl 64 bits.

Compiler un gcc 64 bits sur PA-RISC à partir des sources n'est possible que si vous disposez du compilateur HP C-ANSI C ou d'un binaire 64 bits de gcc déjà fonctionnel. Les meilleures performances pour perl sont obtenues avec le compilateur natif de HP.

Utilisation des grands fichiers avec Perl sur HP-UX

À partir de la version HP-UX 10.20, les fichiers de plus de 2 Go (2^31 octets) peuvent être créés et manipulés. Trois méthodes distinctes sont disponibles pour cela. Parmi ces méthodes, la meilleure pour Perl est de compiler en utilisant le drapeau -Duselargefiles avec Configure. Cela amène Perl à être compilé en utilisant des structures et des fonctions où celles-ci sont de 64 bits de large, plutôt que de 32 bits de large. (Notez que cela ne fonctionnera qu'avec le compilateur ANSI C de HP. Si vous souhaitez compiler Perl en utilisant gcc, vous devrez obtenir une version du compilateur qui prend en charge les opérations 64 bits. Voir ci-dessus où la trouver.)

Cette approche présente quelques inconvénients. L'un d'eux est que toute extension qui appelle une fonction de manipulation de fichiers en C devra être recompilée (suivez simplement la procédure habituelle "perl Makefile.PL; make; make test; make install").

La liste des fonctions qui devront être recompilées est la suivante :
creat, fgetpos, fopen,
freopen, fsetpos, fstat,
fstatvfs, fstatvfsdev, ftruncate,
ftw, lockf, lseek,
lstat, mmap, nftw,
open, prealloc, stat,
statvfs, statvfsdev, tmpfile,
truncate, getrlimit, setrlimit

Un autre inconvénient ne concerne que les versions de Perl antérieures à 5.6.0. Cet inconvénient est que les fonctions seek et tell (la version intégrée et la version du module POSIX) ne fonctionneront pas correctement.

Il est fortement recommandé d'utiliser ce drapeau lorsque vous exécutez Configure. Si vous ne le faites pas, mais que vous répondez plus tard aux questions sur les grands fichiers lorsque Configure vous les pose, vous pourriez obtenir une configuration qui ne peut pas être compilée ou qui ne fonctionne pas comme prévu.

Perl threadé sur HP-UX

Il est possible de compiler une version de Perl threadé sur toute version de HP-UX avant 10.30, mais il est fortement suggéré d'utiliser au moins HP-UX 11.00.

Pour compiler Perl avec des threads, ajoutez -Dusethreads aux arguments de Configure. Vérifiez que le drapeau du compilateur -D_POSIX_C_SOURCE=199506L est automatiquement ajouté à la liste des drapeaux. Assurez-vous également que -lpthread est listé avant -lc dans la liste des bibliothèques pour lier Perl. Les indications fournies pour HP-UX pendant Configure essayeront très fort de faire cela correctement pour vous.

Les versions de HP-UX antérieures à 10.30 nécessitent une installation séparée d'un paquet de bibliothèque de threads POSIX. Deux exemples sont le paquet HP DCE, disponible sur "HP-UX Hardware Extensions 3.0, Install and Core OS, Release 10.20, April 1999 (B3920-13941)" ou le paquet PTH, disponible gratuitement sur le site de H.Merijn (http://mirrors.develooper.com/hpux/). L'utilisation de PTH ne sera pas prise en charge dans perl-5.12 et supérieur et est plutôt boguée dans 5.11.x.

Si vous utilisez le paquet HP DCE, la bibliothèque utilisée pour le threading est /usr/lib/libcma.sl, mais il y a eu plusieurs mises à jour de cette bibliothèque au fil du temps. Perl se compilera avec la première version, mais il ne réussira pas la suite de tests. Les anciennes versions d'Oracle pourraient être une raison convaincante de ne pas mettre à jour cette bibliothèque, sinon veuillez trouver une version plus récente dans l'un des correctifs suivants : PHSS_19739, PHSS_20608 ou PHSS_23672

Pour compiler perl afin de prendre en charge Oracle, il doit être lié avec libcl et libpthread. Donc, même si votre perl est une compilation non threadée, ces bibliothèques pourraient être requises. Voir "Oracle sur HP-UX" ci-dessous.

Perl 64 bits sur HP-UX

À partir de HP-UX 11.00, les programmes compilés sous HP-UX peuvent bénéficier de l'environnement de programmation LP64 (LP64 signifie que les Longs et les Pointers font 64 bits de large), dans lequel les variables scalaires pourront contenir des nombres supérieurs à 2^32 avec une précision complète. Perl s'est avéré cohérent et fiable en mode 64 bits depuis 5.8.1 sur tous les HP-UX 11.xx.

À la date de ce document, Perl est entièrement compatible 64 bits sur HP-UX 11.00 et supérieur pour les compilations cc et gcc. Si vous êtes sur le point de compiler un perl 64 bits avec GNU gcc, veuillez lire attentivement la section gcc.

Si un utilisateur a besoin de compiler Perl dans l'environnement LP64, utilisez le drapeau -Duse64bitall avec Configure. Cela forcera Perl à être compilé dans un environnement LP64 pur (avec le drapeau +DD64 pour HP C-ANSI-C, sans options supplémentaires pour GNU gcc 64 bits sur PA-RISC, et avec -mlp64 pour GNU gcc sur Itanium). Si vous souhaitez compiler Perl en utilisant gcc, vous devrez obtenir une version du compilateur qui prend en charge les opérations 64 bits.)

Vous pouvez également utiliser le drapeau -Duse64bitint avec Configure. Bien qu'il y ait quelques différences mineures entre la compilation de Perl avec ce drapeau par rapport au drapeau -Duse64bitall, elles ne devraient pas être perceptibles du point de vue de l'utilisateur Perl. Lors de la configuration avec -Duse64bitint en utilisant un gcc 64 bits sur une architecture pa-risc, -Duse64bitint est silencieusement promu en -Duse64bitall.

Dans les deux cas, il est fortement recommandé d'utiliser ces drapeaux lorsque vous exécutez Configure. Si vous ne le faites pas, mais que vous répondez plus tard aux questions sur les nombres 64 bits lorsque Configure vous les pose, vous pourriez obtenir une configuration qui ne peut pas être compilée ou qui ne fonctionne pas comme prévu.

Oracle sur HP-UX

L'utilisation de perl pour se connecter à des bases de données Oracle via DBI et DBD::Oracle a causé beaucoup de maux de tête à de nombreuses personnes. Lisez README.hpux dans DBD::Oracle pour beaucoup plus d'informations. La raison de le mentionner ici est qu'Oracle nécessite un perl compilé avec libcl et libpthread, ce dernier même lorsque perl est compilé sans threads. Compiler perl en utilisant tous les défauts, mais permettant quand même de compiler DBD::Oracle plus tard peut être réalisé en utilisant

Configure -A prepend:libswanted='cl pthread ' ...

N'oubliez pas l'espace avant la citation finale.

Notez également que cela ne fonctionne pas (encore) avec toutes les configurations, il est connu pour échouer avec les versions 64 bits de GCC.

GDBM et Threads sur HP-UX

Si vous tentez de compiler Perl avec des threads (POSIX) sur un système 11.X et que vous liez également la bibliothèque GDBM, Perl plantera immédiatement au démarrage. La seule solution de contournement à ce stade est de relier la bibliothèque GDBM sous 11.X, puis de la relier dans Perl.

l'erreur pourrait ressembler à quelque chose comme :

Erreur de thread interne : message : __libc_reinit() échoué, fichier : ../pthreads/pthread.c, ligne : 1096 Pointeur de retour est 0xc082bf33 sh : 5345 Quit(coredump)

Systèmes de fichiers NFS et utime(2) sur HP-UX

Si vous compilez Perl sur un système de fichiers NFS monté à distance, le test io/fs.t peut échouer au test #18. Il semble s'agir d'un bug dans HP-UX et aucune correction n'est actuellement disponible.

Paramètres du noyau HP-UX (maxdsiz) pour la compilation de Perl

Par défaut, HP-UX est configuré avec une taille maximale de segment de données de 64 Mo. C'est trop petit pour compiler correctement Perl avec les niveaux d'optimisation maximum. Vous pouvez augmenter la taille du paramètre du noyau maxdsiz en utilisant SAM.

En utilisant la version graphique de SAM, cliquez sur l'icône Kernel Configuration, puis sur l'icône Configurable Parameters. Faites défiler et sélectionnez la ligne maxdsiz. Dans le menu Actions, sélectionnez l'élément Modifier le paramètre configurable. Insérez la nouvelle formule dans la zone Formule/Valeur. Ensuite, suivez les instructions pour reconstruire votre noyau et redémarrer votre système.

En général, une valeur de 256 Mo (ou "256*1024*1024") est suffisante pour que Perl se compile avec une optimisation maximale.

Suppression des core dump nss de op/pwent ou op/grent

Vous pourriez obtenir un bus error core dump des tests op/pwent ou op/grent. Si compilé avec -g, vous verrez une trace de pile ressemblant à ce qui suit :

Erreur : coller ")" et "l" ne produit pas un jeton de prétraitement valide

Il semble y avoir un fichier d'en-tête système défectueux dans HP-UX 11.00 qui empêche la construction de perl en mode 32 bits avec GNU gcc-4.x, provoquant cette erreur. Le même fichier pour HP-UX 11.11 (même si le fichier est plus ancien) ne présente pas cet échec et a la définition correcte, donc la meilleure solution est de patcher l'en-tête pour qu'il corresponde :

--- /usr/include/inttypes.h  2001-04-20 18:42:14 +0200
+++ /usr/include/inttypes.h  2000-11-14 09:00:00 +0200
@@ -72,7 +72,7 @@
 #define UINT32_C(__c)                   __CONCAT_U__(__c)
 #else /* __LP64 */
 #define INT32_C(__c)                    __CONCAT__(__c,l)
-#define UINT32_C(__c)                   __CONCAT__(__CONCAT_U__(__c),l)
+#define UINT32_C(__c)                   __CONCAT__(__c,ul)
 #endif /* __LP64 */
 #define INT64_C(__c)                    __CONCAT_L__(__c,l)

Redéclaration de "sendpath" avec un spécificateur de classe de stockage différent

cc: "/usr/include/sys/socket.h", line 535: warning 562:
   Redeclaration of "sendfile" with a different storage class
   specifier: "sendfile" will have internal linkage.
cc: "/usr/include/sys/socket.h", line 536: warning 562:
   Redeclaration of "sendpath" with a different storage class

Ils semblent être causés par des fichiers d'en-tête système défectueux, et d'autres projets open source les rencontrent également. Les patchs HP-UX suivants devraient faire disparaître les avertissements :

Divers

Le patch Y2K de HP-UX 11 "Y2K-1100 B.11.00.B0125 HP-UX Core OS Year 2000 Patch Bundle" aurait cassé le test io/fs #18 qui vérifie si utime() peut modifier les horodatages.
