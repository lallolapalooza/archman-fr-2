PERL5101DELTA(1perl) Guide du programmeur Perl PERL5101DELTA(1perl)

NOM

perl5101delta - ce qu'il y a de neuf pour la version perl v5.10.1

DESCRIPTION

Ce document décrit les différences entre la version 5.10.0 et la version 5.10.1.

Si vous mettez à niveau depuis une version antérieure comme la 5.8.8, lisez d'abord le fichier perl5100delta, qui décrit les différences entre 5.8.8 et 5.10.0.

CHANGEMENTS INCOMPATIBLES

Changements de l'instruction Switch

La gestion des expressions complexes par l'instruction switch "given"/"when" a été améliorée. Il y a deux nouveaux cas où "when" interprète désormais son argument comme un booléen, au lieu d'une expression à utiliser dans un smart match :

Opérateurs flip-flop
Les opérateurs flip-flop ".." et "..." sont maintenant évalués en contexte booléen, suivant leurs sémantiques habituelles ; voir "Opérateurs de plage" dans perlop.

Notez que, comme dans perl 5.10.0, "when (1..10)" ne fonctionnera pas pour tester si une valeur donnée est un entier compris entre 1 et 10 ; utilisez plutôt "when ([1..10])" (notez la référence au tableau).

Cependant, contrairement à 5.10.0, l'évaluation des opérateurs flip-flop en contexte booléen garantit qu'ils peuvent maintenant être utiles dans un when(), notamment pour implémenter des conditions bistables, comme dans :

when (/^=begin/ .. /^=end/) {
  # faire quelque chose
}
Opérateur défini-ou
Une expression composée impliquant l'opérateur défini-ou, comme "when (expr1 // expr2)", sera traitée comme booléenne si la première expression est booléenne. (Cela étend la règle existante qui s'applique à l'opérateur OU, comme dans "when (expr1 || expr2)".)

La section suivante détaille d'autres changements apportés aux sémantiques de l'opérateur smart match, qui modifient naturellement aussi le comportement des instructions switch où le smart matching est implicitement utilisé.

Changements du Smart match

Changements dans la répartition par type

L'opérateur smart match "~~" n'est plus commutatif. Le comportement d'un smart match dépend maintenant principalement du type de son argument droit. De plus, ses sémantiques ont été ajustées pour plus de cohérence ou d'utilité dans plusieurs cas. Bien que la compatibilité générale ascendante soit maintenue, plusieurs changements doivent être notés :

  • Les références de code avec un prototype vide ne sont plus traitées spécialement. Elles reçoivent un argument comme les autres références de code (même si elles choisissent de l'ignorer).
  • "%hash ~~ sub {}" et "@array ~~ sub {}" testent maintenant que la sous-routine renvoie une valeur vraie pour chaque clé du hash (ou élément du tableau), au lieu de passer tout le hash ou tableau comme référence à la sous-routine.
  • En raison de la rupture de la commutativité, les références de code ne sont plus traitées spécialement lorsqu'elles apparaissent à gauche de l'opérateur "~~", mais comme un scalaire vulgaire.
  • "undef ~~ %hash" est toujours faux (car "undef" ne peut pas être une clé dans un hash). Aucune conversion implicite en "" n'est effectuée (comme c'était le cas dans perl 5.10.0).
  • "$scalaire ~~ @tableau" distribue maintenant toujours le smart match sur les éléments du tableau. Il est vrai si un élément de @tableau vérifie "$scalaire ~~ $element". Ceci est une généralisation de l'ancien comportement qui testait si le tableau contenait le scalaire.

La table de répartition complète pour l'opérateur smart match est donnée dans "Smart matching in detail" dans perlsyn.

Smart match et surcharge

Conformément à la règle de répartition basée sur le type de l'argument le plus à droite, lorsqu'un objet surchargeant "~~" apparaît à droite de l'opérateur, la routine de surcharge sera toujours appelée (avec un 3ème argument défini à une valeur vraie, voir overload.). Cependant, lorsque l'objet apparaîtra à gauche, la routine de surcharge ne sera appelée que lorsque l'argument le plus à droite est un scalaire simple. De cette manière, la distributivité du smart match sur les tableaux n'est pas rompue, ainsi que les autres comportements avec des types complexes (références de code, hashes, regex). Ainsi, les auteurs des routines de surcharge pour le smart match n'ont principalement besoin de se soucier que de la comparaison avec un scalaire, et éventuellement de la surcharge de stringification ; les autres cas courants seront automatiquement gérés de manière cohérente.

"~~" refusera maintenant de fonctionner sur des objets qui ne le surchargent pas (afin d'éviter de s'appuyer sur la structure interne de l'objet). (Cependant, si l'objet surcharge les opérateurs de stringification ou de numification, et si le fallback de surcharge est actif, il sera utilisé à la place, comme d'habitude.)

Autres changements incompatibles

  • Les sémantiques de "use feature :5.10*" ont légèrement changé. Voir "Modules et Pragmata" pour plus d'informations.
  • C'est maintenant une erreur d'exécution d'utiliser l'opérateur smart match "~~" avec un objet qui n'a pas de surcharge définie pour lui. (Ainsi, "~~" ne brisera pas l'encapsulation en correspondant à la représentation interne de l'objet en tant que référence.)
  • Le système de contrôle de version utilisé pour le développement de l'interpréteur perl a été changé de Perforce à git. Il s'agit principalement d'un problème interne qui n'affecte que les personnes travaillant activement sur le noyau de perl ; mais cela peut avoir une visibilité externe mineure, par exemple dans certains détails de la sortie de "perl -V". Voir perlrepository pour plus d'informations.
  • La structure interne du répertoire "ext/" dans la source de perl a été réorganisée. En général, un module "Foo::Bar" dont la source était stockée sous ext/Foo/Bar/ se trouve maintenant sous ext/Foo-Bar/. De plus, certains modules ont été déplacés de lib/ à ext/. Il s'agit purement d'un changement dans l'archive source, et cela ne devrait faire aucune différence à la compilation ou à l'installation de perl, sauf si vous avez un processus de construction très personnalisé qui dépend explicitement de cette structure, ou qui code en dur le paramètre de configuration "nonxs_ext". Spécifiquement, ce changement ne modifie pas par défaut l'emplacement des fichiers dans l'installation finale.
  • Dans le cadre de la mise à niveau de "Test::Harness" de 2.x vers 3.x, le module expérimental "Test::Harness::Straps" a été supprimé. Voir "Modules mis à jour" pour plus de détails.
  • Dans le cadre de la mise à niveau de "ExtUtils::MakeMaker", les modules "ExtUtils::MakeMaker::bytes" et "ExtUtils::MakeMaker::vmsish" ont été supprimés de cette distribution.
  • "Module::CoreList" ne contient plus le hash %:patchlevel.
  • Celui-ci est en fait un changement introduit dans 5.10.0, mais il a été omis de la perldelta de cette version, il est donc mentionné ici à la place.

    Une correction de bug liée à la gestion du modificateur "/m" et de "qr" a entraîné un changement de comportement entre 5.8.x et 5.10.0 :

    # correspond dans 5.8.x, ne correspond pas dans 5.10.0
$re = qr/^bar/; "foo\nbar" =~ /$re/m;

Changements dans Perl 5.10.1

Cette version apporte un certain nombre de changements et d'améliorations par rapport à Perl 5.10.0.

Mises à jour de la base de données Unicode

La copie de la base de données des caractères Unicode incluse dans Perl 5.10.1 a été mise à jour vers la version 5.1.0 à partir de la version 5.0.0. Voir http://www.unicode.org/versions/Unicode5.1.0/#Notable_Changes pour les changements notables.

Une interface propre pour les ordres de résolution de méthodes enfichables

À partir de Perl 5.10.1, il existe une nouvelle interface pour brancher et utiliser des ordres de résolution de méthodes autres que celui par défaut (recherche linéaire en profondeur). L'ordre de résolution de méthodes C3 ajouté dans 5.10.0 a été réimplémenté en tant que plugin, sans modifier son interface en espace Perl. Voir perlmroapi pour plus d'informations.

Le pragma "overloading"

Ce pragma vous permet de désactiver ou d'activer lexicalement le surchargement pour certaines ou toutes les opérations. (Yuval Kogman)

Tests parallèles

La distribution principale peut désormais exécuter ses tests de régression en parallèle sur les plateformes de type Unix. Au lieu d'exécuter "make test", définissez "TEST_JOBS" dans votre environnement au nombre de tests à exécuter en parallèle, et exécutez "make test_harness". Sur un shell de type Bourne, cela peut être fait comme ceci :

TEST_JOBS=3 make test_harness  # Exécute 3 tests en parallèle

Une variable d'environnement est utilisée, plutôt que le make parallèle lui-même, car TAP::Harness doit être capable de planifier lui-même des scripts de test individuels non conflictuels, et il n'existe pas d'interface standard pour les utilitaires "make" afin d'interagir avec leurs planificateurs de tâches.

Notez que certains scripts de test peuvent actuellement échouer lorsqu'ils sont exécutés en parallèle (notamment "ext/IO/t/io_dir.t"). Si nécessaire, réexécutez juste les scripts défaillants séquentiellement et voyez si les échecs disparaissent.

Support DTrace

Un certain support pour DTrace a été ajouté. Voir "DTrace support" dans INSTALL.

Support pour "configure_requires" dans les métadonnées des modules CPAN

Tant "CPAN" que "CPANPLUS" prennent désormais en charge le mot-clé "configure_requires" dans le fichier de métadonnées "META.yml" inclus dans la plupart des distributions CPAN récentes. Cela permet aux auteurs de distributions de spécifier des prérequis de configuration qui doivent être installés avant d'exécuter Makefile.PL ou Build.PL.

Voir la documentation de "ExtUtils::MakeMaker" ou "Module::Build" pour en savoir plus sur la manière de spécifier "configure_requires" lors de la création d'une distribution pour CPAN.

Les divers grands fichiers "Changes*" (qui listaient chaque changement apporté à perl au cours des 18 dernières années) ont été supprimés et remplacés par un petit fichier, également nommé "Changes", qui explique simplement comment ces mêmes informations peuvent être extraites du système de contrôle de version git.

Le fichier Porting/patching.pod a été supprimé, car il décrivait principalement l'interaction avec l'ancien dépôt basé sur Perforce, qui est maintenant obsolète. Les informations toujours pertinentes ont été déplacées vers perlrepository.

perlapi, perlintern, perlmodlib et perltoc sont désormais tous générés au moment de la compilation, plutôt que d'être distribués dans le cadre de la version.

Améliorations des performances

  • Un nouveau cache interne signifie que isa() sera souvent plus rapide.
  • Sous "use locale", les informations relatives à la locale sont désormais mises en cache.
d sur des valeurs en lecture seule, telles que la liste retournée par "keys %hash". Cela rend les opérations telles que "sort keys %hash" dans le cadre de "use locale" beaucoup plus rapides.
  • Les méthodes "DESTROY" vides ne sont plus appelées.

    Réorganisation de ext/

    La disposition des répertoires dans ext a été révisée. Spécifiquement, toutes les extensions sont maintenant plates et au niveau supérieur, avec "/" dans les chemins remplacé par "-", de sorte que ext/Data/Dumper/ devient maintenant ext/Data-Dumper/, etc. Les noms des extensions tels que spécifiés à Configure, et tels que rapportés par %Config::Config sous les clés "dynamic_ext", "known_extensions", "nonxs_ext" et "static_ext" n'ont pas changé, et utilisent toujours "/". Par conséquent, ce changement n'aura aucun effet une fois perl installé. Cependant, "Attribute::Handlers", "Safe" et "mro" sont maintenant devenus des extensions à part entière, donc si vous exécutez Configure avec des options pour spécifier une liste exacte d'extensions à construire, vous devrez la modifier pour en tenir compte.

    Pour la version 5.10.2, il est prévu que de nombreux modules "dual-life" aient été déplacés de lib vers ext ; encore une fois, cela n'aura aucun effet sur un perl installé, mais sera important si vous invoquez Configure avec une liste prédéfinie d'extensions à construire.

    Améliorations de la configuration

    Si "vendorlib" et "vendorarch" sont identiques, alors ils ne sont ajoutés à @INC qu'une seule fois.

    $Config{usedevel} et "PERL_USE_DEVEL" au niveau C sont maintenant définis si perl est construit avec "-Dusedevel".

    Configure activera l'utilisation de "-fstack-protector", pour fournir une protection contre les attaques par dépassement de tampon de pile, si le compilateur le prend en charge.

    Configure déterminera maintenant les prototypes corrects pour les fonctions réentrantes, et pour "gconvert", si vous utilisez un compilateur C++ plutôt qu'un compilateur C.

    Sur Unix, si vous construisez à partir d'un répertoire contenant un dépôt git, le processus de configuration notera le hash de commit que vous avez extrait, pour affichage dans la sortie de "perl -v" et "perl -V". Les commits locaux non poussés sont automatiquement ajoutés à la liste des patches locaux affichés par "perl -V".

    Améliorations de la compilation

    Dans le cadre de la simplification de ext, toutes les extensions sur toutes les plateformes sont construites par make_ext.pl. Cela remplace ext/util/make_ext spécifique à Unix, make_ext.com spécifique à VMS et win32/buildext.pl spécifique à Win32.

    Changements spécifiques à la plateforme

    AIX
    Suppression de libbsd pour AIX 5L et 6.1. Seul flock() était utilisé depuis libbsd.

    Suppression de libgdbm pour AIX 5L et 6.1. libgdbm est livrée comme un paquet optionnel avec la boîte à outils AIX. Malheureusement, la version 64 bits est défectueuse.

    Les modifications des indications (hints) signifient que AIX 4.2 devrait de nouveau fonctionner.

    Cygwin
    Sur Cygwin, nous supprimons maintenant le dernier chiffre de la DLL. C'est le comportement de la construction de cygwin.com depuis des années. Les fichiers d'indications ont été mis à jour.
    FreeBSD
    Les fichiers d'indications identifient maintenant les bonnes bibliothèques de threads sur FreeBSD 7 et versions ultérieures.
    Irix
    Nous contournons maintenant un bug bizarre du préprocesseur dans le compilateur Irix 6.5 : "cc -E -" passe malheureusement en mode K&R, mais "cc -E file.c" ne le fait pas.
    Haiku
    Les patches des mainteneurs de Haiku ont été fusionnés. Perl devrait maintenant se construire sur Haiku.
    MirOS BSD
    Perl devrait maintenant se construire sur MirOS BSD.
    NetBSD
    Les indications prennent maintenant en charge les versions 5.*.
    Stratus VOS
    Divers changements provenant de Stratus ont été fusionnés.
    Symbian
    Il y a maintenant un support pour les SDK Symbian S60 3.2 et S60 5.0.
    Win32
    Une meilleure gestion des fenêtres de messages signifie que les messages d'"alarm" et de "kill" ne seront plus perdus dans des conditions de concurrence.
    VMS
    Les lectures à partir des fichiers temporaires en mémoire de "PerlIO::scalar" échouaient auparavant si $/ était défini à une référence numérique (pour indiquer des lectures par enregistrement). Ceci est maintenant corrigé.

    VMS prend maintenant en charge "getgrgid".

    De nombreuses améliorations et nettoyages ont été apportés au code de gestion et de conversion des noms de fichiers VMS.

    L'activation du nom logique "PERL_VMS_POSIX_EXIT" encode maintenant un statut de sortie POSIX dans une valeur de condition VMS pour une meilleure interaction avec le shell bash de GNV et d'autres utilitaires qui dépendent des valeurs de sortie POSIX. Voir "$?" dans perlvms pour plus de détails.

    Corrections de bugs sélectionnées

    • La version 5.10.0 désactivait par inadvertance une optimisation, ce qui causait une baisse de performance mesurable dans l'assignation de listes, telle qu'utilisée souvent pour assigner les paramètres de fonction depuis @_. L'optimisation a été réactivée et la régression de performance corrigée.
    • Fuite de mémoire corrigée sur "while (1) { map 1, 1 }" [RT #53038].
    • Certains plantages potentiels dans PerlIO corrigés [RT #57322,54828].
    • Le débogueur fonctionne maintenant avec les sous-routines lvalues.
    • La commande "m" du débogueur était défectueuse sur les modules qui définissaient des constantes [RT #61222].
    • crypt() et le complément de chaîne pouvaient retourner des valeurs contaminées (tainted) pour des arguments non contaminés [RT #59998].
    • Le commutateur de ligne de commande "-i.suffix" recrée maintenant le fichier en utilisant des permissions restreintes, avant de changer son mode pour correspondre au fichier d'origine. Cela élimine une condition de concurrence potentielle [RT #60904].
    • Sur certains systèmes Unix, la valeur dans $? n'avait pas le bit supérieur défini ("$? & 128") même si le processus fils avait un core dump.
    • Dans certaines circonstances, $^R pouvait incorrectement devenir indéfini [RT #57042].
    • (XS) Dans diverses fonctions de hachage, passer un hachage pré-calculé à lorsque la clé est UTF-8 pouvait entraîner une recherche incorrecte.
    • (XS) Inclure XSUB.h avant perl.h donnait une erreur de compilation [RT #57176].
    • "$object->isa('Foo')" rapportait faux si le paquet "Foo" n'existait pas, même si @ISA de l'objet contenait "Foo".
    • Divers bugs dans le code mro nouveau dans la version 5.10.0, déclenchés par la manipulation de @ISA, ont été trouvés et corrigés.
    • Les opérations bit à bit sur les références pouvaient planter l'interpréteur, par exemple "$x=\$y; $x |= "foo"" [RT #54956].
    • Les motifs incluant l'alternance pouvaient être sensibles à la représentation UTF-8 interne, par exemple : 
      my $byte = chr(192);
my $utf8 = chr(192); utf8::upgrade($utf8);
$utf8 =~ /$byte|X}/i;       # échouait en 5.10.0
    • Dans les fichiers source Perl encodés en UTF8 (c'est-à-dire où "use utf8" est activé), les chaînes de caractères littérales entre guillemets doubles pouvaient être corrompues là où un "\xNN", "\0NNN" ou "\N{}" est suivi d'un caractère littéral avec une valeur ordinale supérieure à 255 [RT #59908].
    • "B::Deparse" n'a pas réussi à déparser correctement divers constructeurs : "readpipe STRING" [RT #62428], CORE::require(STRING) [RT #62488], "sub foo(_)" [RT #62484].
    • L'utilisation de setpgrp() sans arguments pouvait corrompre la pile perl.
    • La forme bloc de "eval" est maintenant spécifiquement traçable par "Safe" et "ops". Auparavant, elle était traitée par erreur comme un "eval" de chaîne.
    • En 5.10.0, les deux caractères "[~" étaient parfois analysés comme l'opérateur de correspondance intelligente ("~~") [RT #63854].
    • En 5.10.0, le quantificateur "*" dans les motifs était parfois traité comme "{0,32767}" [RT #60034, #60464]. Par exemple, cette correspondance échouerait : 
      ("ab" x 32768) =~ /^(ab)*$/
    • "shmget" était limité à une taille de segment de 32 bits sur un système d'exploitation 64 bits [RT #63924].
    • L'utilisation de "next" ou "last" pour quitter un bloc "given" ne produit plus un avertissement superflu comme le suivant : 
      Exiting given via last at foo.pl line 123
    • Sous Windows, '.\foo' et '..\foo' étaient traités différemment de './foo' et '../foo' par "do" et "require" [RT #63492].
    • L'attribution d'un format à un glob pouvait corrompre le format ; par exemple : 
      *bar=*foo{FORMAT}; # foo format now bad
    • Tenter de convertir un typeglob en chaîne ou en nombre pouvait provoquer un échec d'assertion. Le message d'erreur correct est maintenant généré, "Can't coerce GLOB to $type".
    • Sous "use filetest 'access'", "-x" utilisait le mauvais mode d'accès. Ceci a été corrigé [RT #49003].
    • La "length" sur un scalaire lié qui renvoyait une valeur Unicode n'était pas correcte la première fois. Ceci a été corrigé.
    • L'utilisation d'un tableau "tie" à l'intérieur d'un tableau "tie" pouvait provoquer un SEGV. Ceci a été corrigé. [RT #51636]
    • Une condition de concurrence (race condition) à l'intérieur de PerlIOStdio_close() a été identifiée et corrigée. Ceci provoquait divers problèmes de threading, y compris des SEGVs.
    • Dans "unpack", l'utilisation de groupes "()" en contexte scalaire plaçait en interne une liste sur la pile de l'interpréteur, ce qui se manifestait de diverses manières, y compris des SEGVs. Ceci est maintenant corrigé [RT #50256].
    • La magie était appelée deux fois dans "substr", "\&$x", "tie $x, $m" et "chop". Tous ces problèmes ont été corrigés.
    • Une optimisation de 5.10.0 visant à vider la pile temporaire dans la boucle implicite de "s///ge" a été annulée, car elle s'est avérée être la cause de bugs obscurs dans des parties apparemment sans rapport de l'interpréteur [commit ef0d4e17921ee3de].
    • Les numéros de ligne pour les avertissements dans "elsif" sont maintenant corrects.
    • L'opérateur ".." fonctionne maintenant correctement avec des plages dont les extrémités sont au niveau des valeurs des entiers les plus petits et les plus grands, ou proches de celles-ci.
    • "binmode STDIN, ':raw'" pouvait entraîner des erreurs de segmentation sur certaines plateformes. Ceci a été corrigé [RT #54828].
    • Une erreur d'un caractère (off-by-one) signifiait que "index $str, ..." était effectivement exécuté comme "index "$str\0", ...". Ceci a été corrigé [RT #53746].
    • Diverses fuites de mémoire associées aux captures nommées dans les regex ont été corrigées [RT #57024].
    • Une référence faible à une table de hachage provoquait une fuite de mémoire. Ceci affectait "DBI" [RT #56908].
    • L'utilisation de (?|) dans une regex pouvait provoquer un segfault [RT #59734].
    • L'utilisation d'une "tr//" UTF-8 dans une closure pouvait provoquer un segfault [RT #61520].
    • L'appel de sv_chop() ou la mise à niveau d'un SV pouvait entraîner un accès 64 bits non aligné sur l'architecture SPARC [RT #60574].
    • Dans la version 5.10.0, "inc_version_list" listait incorrectement "5.10.*" après "5.8.*" ; ceci affectait l'ordre de recherche de @INC [RT #67628].
    • En 5.10.0, "pack "a*", $tainted_value" renvoyait une valeur non souillée (non tainted) [RT #52552].
    • En 5.10.0, "printf" et "sprintf" pouvaient produire l'erreur fatale "panic: utf8_mg_pos_cache_update" lors de l'impression de chaînes UTF-8 [RT #62666].
    • Dans la version 5.10.0, une méthode "AUTOLOAD" créée dynamiquement pouvait être manquée (problème de cache de méthode) [RT #60220,60232].
    • Dans la version 5.10.0, une combinaison de "use feature" et "//ee" pouvait provoquer une fuite de mémoire [RT #63110].
    • "-C" sur la ligne shebang ("#!") est à nouveau autorisé s'il est également spécifié sur la ligne de commande. "-C" sur la ligne shebang était auparavant un "no-op" silencieux *si* il n'était pas également sur la ligne de commande, donc perl 5.10.0 le rejetait, ce qui cassait certains scripts. Maintenant, perl vérifie s'il est également sur la ligne de commande et ne plante que si ce n'est pas le cas [RT #67880].
    • En 5.10.0, certains types d'expressions régulières réentrantes pouvaient planter, ou provoquer l'échec d'assertion suivant [RT #60508] : 
      Assertion rx->sublen >= (s - rx->subbeg) + i failed

    Diagnostics nouveaux ou modifiés

    "panic: sv_chop %s"
    Cette nouvelle erreur fatale se produit lorsque la routine C Perl_sv_chop() reçoit une position qui n'est pas dans le tampon de chaîne du scalaire. Ceci pouvait être causé par un code XS défectueux, et à ce stade, la récupération n'est pas possible.
    "Can't locate package %s for the parents of %s"
    Cet avertissement a été supprimé. En général, il n'était produit qu'en conjonction avec d'autres avertissements, et sa suppression a permis d'ajouter une optimisation de la recherche ISA.
    "v-string in use/require is non-portable"
    Cet avertissement a été supprimé.
    "Deep recursion on subroutine "%s""
    Il est maintenant possible de modifier le seuil de profondeur pour cet avertissement, par défaut à 100, en recompilant le binaire de *perl*, en définissant le macro du préprocesseur C "PERL_SUB_DEPTH_WARN" à la valeur souhaitée.

    Internes modifiés

    • Les citations de J.R.R. Tolkien en tête des fichiers sources C ont été vérifiées et des citations appropriées ont été ajoutées, grâce à un patch de Tom Christiansen.
    • vcroak() accepte maintenant un premier argument nul. De plus, un audit complet des annotations de compilateur "not NULL" a été effectué, et celles de plusieurs autres fonctions internes ont été corrigées.
    • De nouveaux macros "dSAVEDERRNO", "dSAVE_ERRNO", "SAVE_ERRNO", "RESTORE_ERRNO" ont été ajoutés pour formaliser la sauvegarde temporaire de la variable "errno".
    • La fonction "Perl_sv_insert_flags" a été ajoutée pour compléter "Perl_sv_insert".
    • La fonction Perl_newSV_type(type) a été ajoutée, équivalente à Perl_newSV() suivi de Perl_sv_upgrade(type).
    • La fonction Perl_newSVpvn_flags() a été ajoutée, équivalente à Perl_newSVpvn() puis effectuant l'action pertinente pour le drapeau.

      Deux bits de drapeau sont actuellement pris en charge.

    "SVf_UTF8"
    Ceci appellera SvUTF8_on() pour vous. (Notez que cela ne convertit pas une séquence de caractères ISO 8859-1 en UTF-8). Un wrapper, newSVpvn_utf8() est disponible pour cela.
    "SVs_TEMP"
    Appelle sv_2mortal() sur le nouveau SV.

    Il existe également un wrapper qui prend des chaînes constantes, newSVpvs_flags().

    • La fonction "Perl_croak_xs_usage" a été ajoutée comme wrapper à "Perl_croak".
    • Les fonctions "PerlIO_find_layer" et "PerlIO_list_alloc" sont maintenant exportées.
    • "PL_na" a été éliminé du code principal, remplacé par des temporaires STRLEN locaux ou des appels *_nolen(). Chaque approche est plus rapide que "PL_na", qui est une déréférencement de pointeur vers la structure de l'interpréteur sous ithreads, et une variable globale sinon.
    • Perl_mg_free() laissait auparavant la mémoire libérée accessible via SvMAGIC() sur le scalaire. Elle met maintenant à jour la liste chaînée pour supprimer chaque élément de magie au fur et à mesure de sa libération.
    • Sous ithreads, la regex dans "PL_reg_curpm" est maintenant comptée par référence. Cela élimine de nombreux contournements "bidouilleurs" pour pallier son absence de comptage par référence.
    • Perl_mg_magical() activait parfois incorrectement SvRMAGICAL(). Ceci a été corrigé.
    • Les drapeaux IV et NV *publics* ne sont plus définis si la valeur de la chaîne contient des "déchets" à la fin. Ce comportement est cohérent avec le fait de ne pas définir les drapeaux IV ou NV publics si la valeur est hors de portée pour le type.
    • Le traçage de l'allocation des SV a été ajouté aux diagnostics activés par "-Dm". Le traçage peut également sortir via le mécanisme "PERL_MEM_LOG", si celui-ci était activé lors de la compilation du binaire de *perl*.
    • Les utilisations de "Nullav", "Nullcv", "Nullhv", "Nullop", "Nullsv" etc. ont été remplacées par "NULL" dans le code principal, et les modules non "dual-life", car "NULL" est plus clair pour ceux qui ne sont pas familiers avec le code principal.
    • Un macro MUTABLE_PTR(p) a été ajouté, qui sur gcc (non pédant) ne retire pas le "const", renvoyant un "void *". Les macros MUTABLE_SV(av), MUTABLE_SV(cv) etc. s'appuient sur cela, en le convertissant en "AV *" etc. sans retirer le "const". Cela permet une vérification du temps de compilation de la correction du "const" dans le code principal, et a permis de détecter certaines erreurs (maintenant corrigées).
    • Les macros mPUSHs() et mXPUSHs() ont été ajoutées, pour pousser des SV sur la pile et les rendre mortels.
    • L'utilisation de la structure privée "mro_meta" a légèrement changé. Rien en dehors du code principal ne devrait accéder directement à cela de toute façon.
    • Un nouvel outil, ">"Porting/expand-macro.pl" a été ajouté, ce qui vous permet de voir comment une macro du préprocesseur C serait développée lors de la compilation. Ceci est utile lorsque vous essayez de déchiffrer l'enfer des macros qui se trouve au cœur de Perl.

    Problèmes connus

    Voici une liste de quelques bugs importants non corrigés, qui constituent des régressions par rapport à 5.10.0 ou 5.8.x.

    • "List::Util::first" se comporte mal en présence d'un $_ lexical (généralement introduit par "my $_" ou implicitement par "given"). La variable qui est définie pour chaque itération est la variable de paquet $_, et non le $_ lexical [RT #67694].

      Un problème similaire peut survenir dans d'autres modules qui fournissent des fonctions prenant un bloc comme premier argument, tel que

      foo { ... $_ ...} list
    • Le pragma "charnames" peut générer une erreur d'exécution lorsqu'une expression régulière est interpolée [RT #56444]: 
      use charnames ':full';
my $r1 = qr/\N{THAI CHARACTER SARA I}/;
"foo" =~ $r1;    # ok
"foo" =~ /$r1+/; # erreur d'exécution

      Une solution de contournement consiste à générer le caractère en dehors de l'expression régulière :

      my $a = "\N{THAI CHARACTER SARA I}";
my $r1 = qr/$a/;
    • Certaines expressions régulières peuvent s'exécuter beaucoup plus lentement lorsqu'elles sont exécutées dans un thread enfant par rapport au thread dans lequel le motif a été compilé [RT #55600].

    Dépréciations

    Les éléments suivants sont maintenant dépréciés.

    • "Switch" est bogué et doit être évité. À partir de la version 5.11.0 de Perl, l'utilisation de la version du cœur de ce module émettra un avertissement, et le module sera éventuellement supprimé du cœur (probablement dans la version 5.14.0 de Perl). Voir "Switch statements" dans perlsyn pour son remplacement.
    • "suidperl" sera supprimé dans la version 5.12.0. Il fournit un mécanisme pour émuler les bits d'autorisation setuid sur les systèmes qui ne le supportent pas correctement.

    Rapport de bugs

    Si vous trouvez ce que vous pensez être un bug, vous pourriez consulter les articles récemment postés sur le groupe de discussion comp.lang.perl.misc et la base de données des bugs de Perl à l'adresse http://rt.perl.org/perlbug/ . Il peut également y avoir des informations sur http://www.perl.org/ , la page d'accueil de Perl.

    Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bug à un cas de test minuscule mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl.

    Si le bug que vous signalez a des implications de sécurité, le rendant inapproprié à l'envoi vers une liste de diffusion publiquement archivée, alors veuillez l'envoyer à perl5-security-report@perl.org. Ceci pointe vers une liste de diffusion à abonnement fermé et non archivée, qui comprend tous les contributeurs principaux, qui pourront aider à évaluer l'impact des problèmes, à trouver une solution et à coordonner la publication de correctifs pour atténuer ou résoudre le problème sur toutes les plateformes prises en charge par Perl. Veuillez n'utiliser cette adresse que pour les problèmes de sécurité dans le cœur de Perl, et non pour les modules distribués indépendamment sur CPAN.
