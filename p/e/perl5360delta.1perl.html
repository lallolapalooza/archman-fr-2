PERL5360DELTA(1perl) Guide de référence du programmeur Perl PERL5360DELTA(1perl)

NOM

perl5360delta - ce qu'il y a de nouveau dans la version perl v5.36.0

DESCRIPTION

Ce document décrit les différences entre la version 5.34.0 et la version 5.36.0.

Améliorations du cœur

"use v5.36"

Comme toujours, "use v5.36" active le lot de fonctionnalités de cette version de Perl.

Le lot v5.36 active la fonctionnalité "signatures". Introduite dans la version Perl 5.20.0, et modifiée plusieurs fois depuis, la fonctionnalité des signatures de sous-routines n'est plus considérée comme expérimentale. Elle est maintenant considérée comme une fonctionnalité stable du langage et n'imprime plus d'avertissement.

use v5.36;
sub add ($x, $y) {
  return $x + $y;
}

Malgré cela, certains éléments des sous-routines signées restent expérimentaux ; voir ci-dessous.

Le lot v5.36 active également la fonctionnalité "isa". Introduit dans la version Perl 5.32.0, cet opérateur est resté inchangé depuis lors. L'opérateur est maintenant considéré comme une fonctionnalité stable du langage. Pour plus de détails, voir "Class Instance Operator" dans perlop.

Le lot v5.36 désactive également les fonctionnalités "indirect" et "multidimensional". Celles-ci interdiront, respectivement : l'utilisation d'appels de méthodes "indirects" (comme "$x = new Class;") ; l'utilisation d'une expression de liste comme clé de hachage pour simuler des tableaux multidimensionnels épars. Les spécificités de ces changements se trouvent dans feature, mais en bref : c'est un peu comme avoir plus de "use strict" activé, désactivant les fonctionnalités qui causent plus de problèmes qu'elles n'en valent la peine.

De plus, "use v5.36" activera également les avertissements comme si vous aviez écrit "use warnings".

Enfin, avec cette version, la fonctionnalité expérimentale "switch", présente dans chaque lot de fonctionnalités depuis leur introduction dans la v5.10, a été retirée du lot v5.36. Si vous souhaitez l'utiliser (contre notre avis), vous devrez l'activer explicitement.

Drapeau de ligne de commande -g

Un nouveau drapeau de ligne de commande, -g, est disponible. C'est un alias plus simple pour -0777.

Pour plus d'informations, voir "-g" dans perlrun.

Unicode 14.0 est pris en charge

Voir https://www.unicode.org/versions/Unicode14.0.0/ pour les détails.

les ensembles regex ne sont plus considérés comme expérimentaux

Avant cette version, la fonctionnalité des ensembles regex (nommée officiellement "Extended Bracketed Character Classes") était considérée comme expérimentale. Introduite dans la version Perl 5.18.0, et modifiée plusieurs fois depuis, elle est maintenant considérée comme une fonctionnalité stable du langage et son utilisation n'imprime plus d'avertissement. Voir "Extended Bracketed Character Classes" dans perlrecharclass.

Le lookbehind de longueur variable n'est plus considéré comme expérimental dans la plupart des cas

Avant cette version, toute forme de lookbehind de longueur variable était considérée comme expérimentale. Avec cette version, le statut expérimental a été réduit pour ne couvrir que le lookbehind contenant des parenthèses de captage. Cela est dû au fait qu'il n'est pas clair si

"aaz"=~/(?=z)(?<=(a|aa))/

devrait correspondre et laisser $1 égal à "a" ou "aa". Actuellement, il correspondra à la plus longue alternative possible, "aa". Bien que nous soyons convaincus que la construction globale correspondra maintenant seulement quand elle le devrait, nous ne sommes pas convaincus de vouloir conserver le comportement actuel de "correspondance la plus longue".

SIGFPE n'est plus différé

Les exceptions à virgule flottante sont maintenant délivrées immédiatement, de la même manière que d'autres signaux de type "faute" comme SIGSEGV. Cela signifie qu'on a au moins une chance de capturer un tel signal avec un gestionnaire $SIG{FPE}, par exemple pour que "die" puisse rapporter la ligne en Perl qui l'a déclenché.

Suivi booléen stable

Les valeurs booléennes "vrai" et "faux", souvent accessibles par des constructions comme "!!0" et "!!1", ainsi que celles renvoyées par de nombreuses fonctions et opérateurs du noyau, se souviennent maintenant de leur nature booléenne même lors d'assignations dans des variables. La nouvelle fonction is_bool() dans builtin peut vérifier si une valeur a une nature booléenne.

Ceci est susceptible d'être utile lors de l'interopérabilité avec d'autres langages ou la sérialisation de types de données, entre autres.

itérer sur plusieurs valeurs à la fois (expérimental)

Vous pouvez maintenant itérer sur plusieurs valeurs à la fois en spécifiant une liste de lexicals entre parenthèses. Par exemple,

for my ($key, $value) (%hash) { ... }
for my ($left, $right, $gripping) (@moties) { ... }

Avant perl v5.36, tenter de spécifier une liste après "for my" entraînait une erreur de syntaxe.

Cette fonctionnalité est actuellement expérimentale et provoquera un avertissement de catégorie "experimental::for_list". Pour plus de détails, voir "Compound Statements" dans perlsyn. Voir aussi "builtin::indexed" dans ce document, qui est un compagnon utile pour le foreach n-à-la-fois.

fonctions builtin (expérimental)

Un nouveau module central, builtin, a été ajouté, qui fournit une documentation pour les nouvelles fonctions toujours présentes qui sont intégrées à l'interpréteur.

say "Reference type of arrays is ", builtin::reftype([]);

Il fournit également un mécanisme d'importation lexical pour fournir des noms courts pour ces fonctions.

use builtin 'reftype';
say "Reference type of arrays is ", reftype([]);

Ce mécanisme de fonction builtin et les fonctions qu'il fournit sont tous actuellement expérimentaux. Nous prévoyons que "builtin" lui-même cessera d'être expérimental dans un avenir proche, mais que les fonctions individuelles qu'il contient pourront devenir stables au fil du temps. D'autres fonctions seront ajoutées à "builtin" au fil du temps.

Pour plus de détails, voir builtin, mais voici un résumé des fonctions builtin dans la v5.36 :

builtin::trim
Cette fonction traite son argument comme une chaîne de caractères, renvoyant le résultat de la suppression de tous les espaces blancs au début et à la fin.
builtin::indexed
Cette fonction renvoie une liste deux fois plus grande que sa liste d'arguments, où chaque élément est précédé de son index dans cette liste. Ceci est principalement utile pour utiliser la nouvelle syntaxe "foreach" avec plusieurs variables d'itérateur pour parcourir un tableau ou une liste, tout en suivant l'index de chaque élément : 
use builtin 'indexed';
foreach my ($index, $val) (indexed @array) {
    ...
}
builtin::true, builtin::false, builtin::is_bool
"true" et "false" renvoient les booléens vrai et faux. Perl reste Perl, et n'a pas de typage strict des booléens, mais ces valeurs sauront qu'elles ont été créées comme des booléens. "is_bool" vous dira si une valeur est

Nouveautés

Builtins

builtin::evalbytes, builtin::evalfile, builtin::evalfilebytes
Ces fonctions sont similaires à eval, mais elles sont garanties d'opérer sur des chaînes d'octets. Voir "evalbytes" dans perlop pour plus de détails. Elles peuvent remplacer certaines routines similaires trouvées dans Scalar::Util.
builtin::isa, builtin::does
Ces fonctions sont maintenant des fonctions natives Perl, et non plus des opérateurs. Elles peuvent remplacer certaines routines similaires trouvées dans Scalar::Util.
builtin::is_utf8, builtin::unicode_defname, builtin::unicode_via_locale
Ces fonctions fournissent des informations supplémentaires sur l'encodage des chaînes et peuvent remplacer certaines routines similaires trouvées dans Scalar::Util.
builtin::null_bits, builtin::undefbits
Ces fonctions permettent d'obtenir des informations sur la représentation interne des valeurs indéfinies et des chaînes vides, et sont connues pour avoir été créées comme booléens.
builtin::weaken, builtin::unweaken, builtin::is_weak
Ces fonctions permettent respectivement d'affaiblir une référence ; de renforcer une référence ; et de retourner si une référence est faible. (Une référence faible n'est pas prise en compte par le garbage collector. Voir perlref.) Elles peuvent remplacer certaines routines similaires dans Scalar::Util.
builtin::blessed, builtin::refaddr, builtin::reftype
Ces fonctions fournissent plus de données sur les références (ou les non-références, en fait !) et peuvent remplacer des routines similaires trouvées dans Scalar::Util.
builtin::ceil, builtin::floor
"ceil" retourne le plus petit entier supérieur ou égal à son argument. "floor" retourne le plus grand entier inférieur ou égal à son argument. Elles peuvent remplacer des routines similaires trouvées dans POSIX.

Blocs "defer" (expérimental)

Cette version ajoute la prise en charge des blocs "defer", qui sont des blocs de code précédés du modificateur "defer". Ils fournissent une section de code qui s'exécute plus tard, lors de la sortie de portée.

En bref, lorsqu'un bloc "defer" est atteint à l'exécution, son corps est mis de côté pour être exécuté lorsque la portée englobante est quittée. Il diffère d'un UNITCHECK (entre autres raisons) en ce que si le bloc *contenant* le bloc "defer" est quitté avant que le bloc ne soit atteint, il ne sera pas exécuté.

"defer" blocks can be used to take the place of "scope guard" objects where an object is passed a code block to be run by its destructor.

Pour plus d'informations, voir "defer blocks" dans perlsyn.

try/catch peut maintenant avoir un bloc "finally" (expérimental)

La syntaxe expérimentale "try"/"catch" a été étendue pour prendre en charge un troisième bloc optionnel introduit par le mot-clé "finally".

try {
    attempt();
    print "Success\n";
}
catch ($e) {
    print "Failure\n";
}
finally {
    print "This happens regardless\n";
}

Ceci fournit du code qui s'exécute à la fin de la construction "try"/"catch", même si elle est interrompue par une exception ou un mot-clé de contrôle de flux. Ils sont similaires aux blocs "defer".

Pour plus d'informations, voir "Try Catch Exception Handling" dans perlsyn.

Délimiteurs non ASCII pour les opérateurs de type quote (expérimental)

Perl a traditionnellement permis seulement quatre paires de délimiteurs de chaînes/motifs : "( )" "{ }" "[ ]" et "< >", tous dans la plage ASCII. Unicode offre des centaines de possibilités supplémentaires, et l'activation de cette fonctionnalité en permet beaucoup. Une fois activée, vous pouvez écrire "qr« »" par exemple, ou "use utf8; q𝄃string𝄂". Voir "The 'extra_paired_delimiters' feature" dans feature pour les détails.

@_ est maintenant expérimental dans les subs avec signature

Même si les signatures de sous-routines sont maintenant stables, l'utilisation du tableau d'arguments hérité (@_) avec une sous-routine qui a une signature reste *expérimentale*, avec sa propre catégorie d'avertissement. Le silence de la catégorie d'avertissement "experimental::signatures" n'est pas suffisant pour écarter cela. Le nouvel avertissement est émis avec le nom de catégorie "experimental::args_array_with_signatures".

Toute sous-routine qui a une signature et tente d'utiliser le tableau d'arguments par défaut ou un de ses éléments (@_ ou $_[INDEX]), explicitement ou implicitement (comme "shift" ou "pop" sans argument) provoquera un avertissement à la compilation :

use v5.36;
sub f ($x, $y = 123) {
  say "The first argument is $_[0]";
}
Use of @_ in array element with signatured subroutine is experimental
at file.pl line 4.

Le comportement du code qui tente de faire cela n'est plus spécifié et pourrait être sujet à modification dans une version future.

Changements Incompatibles

Un tri physiquement vide est maintenant une erreur de compilation

@a = sort @empty; # non affecté
@a = sort;        # maintenant une erreur de compilation
@a = sort ();     # également une erreur de compilation

Un simple sort était auparavant une manière étrange de créer une liste vide ; maintenant il plante à la compilation. Ce changement vise à libérer de l'espace syntaxique pour d'éventuelles améliorations futures de "sort".

Dépréciations

"use VERSION" (où VERSION est inférieur à v5.11) après "use v5.11" est déprécié

Lorsque l'on est dans la portée de "use v5.11" ou une version ultérieure, un "use vX" où *X* est inférieur à v5.11 émettra maintenant un avertissement :

Downgrading a use VERSION declaration to below v5.11 is deprecated

Par exemple :

use v5.14;
say "The say statement is permitted";
use v5.8;                               # Ceci affichera un avertissement
print "We must use print\n";

C'est parce que l'équipe de Perl prévoit de modifier le comportement dans ce cas. Depuis Perl v5.12 (et certaines parties de v5.11), strict est activé *sauf s'il avait été précédemment désactivé*. En d'autres termes :

no strict;
use v5.12;  # n'activera pas strict, car "no strict" le précédait
$x = 1;     # autorisé, malgré l'absence de déclaration "my"

À l'avenir, ce comportement sera supprimé et "use VERSION" activera *toujours* strict pour les versions v5.12 et ultérieures.

Le code qui souhaite mélanger les versions de cette manière devrait utiliser un scoping lexical avec une syntaxe de bloc pour s'assurer que les régions aux versions différentes restent lexicalement isolées.

{
    use v5.14;
    say "The say statement is permitted";
}
{
    use v5.8;                           # Aucun avertissement n'est émis
    print "We must use print\n";
}

Bien sûr, ce n'est probablement pas quelque chose dont vous aurez jamais besoin ! Si le premier bloc compile, cela signifie que vous utilisez perl v5.14.0 ou une version ultérieure.

Améliorations des Performances

  • Nous sondons maintenant le support du compilateur pour le stockage local de threads C11, et là où il est disponible, nous l'utilisons pour le "contexte implicite" pour les extensions XS faisant des appels API pour une construction Perl threadée. Cela nécessite moins d'appels de fonctions au niveau C que le stockage spécifique aux threads POSIX. Nous continuons à utiliser l'approche pthreads si l'approche C11 n'est pas disponible.

    L'exécution de *Configure* avec les valeurs par défaut construira un Perl non threadé (ce qui est légèrement plus rapide), mais la plupart des systèmes d'exploitation fournissent un Perl threadé.

  • Perl peut maintenant être configuré pour ne plus allouer de clés pour les grandes tables de hachage à partir de la table de chaînes partagée.

    Le même type de données interne ("PVHV") est utilisé pour tous les éléments suivants :

  • Tables de symboles
  • Objets (par défaut)
  • Tableaux associatifs

La table de chaînes partagée a été ajoutée à l'origine pour améliorer les performances des hachages bénis utilisés comme objets, car chaque instance d'objet a les mêmes clés, il est donc optimisé de partager la mémoire entre eux. Cela a également du sens pour les tables de symboles, où les classes dérivées auront les mêmes clés (généralement des noms de méthodes), et les arbres OP construits pour les appels de méthodes peuvent également partager la mémoire. La table de chaînes partagée se comporte à peu près comme un cache pour les clés de hachage.

Mais pour les hachages réellement utilisés comme tableaux associatifs - mappant des clés à des valeurs - typiquement les clés ne sont pas réutilisées dans d'autres hachages. Par exemple, les hachages "vu" sont indexés par des identifiants d'objets (ou des adresses), et logiquement ces clés ne se répéteront pas dans d'autres hachages.

Stocker ces clés "utilisées une seule fois" dans la table de chaînes partagée augmente l'utilisation du CPU et de la RAM sans gain. Pour de telles clés, la table de chaînes partagée se comporte comme un cache avec un taux de réussite de 0%. Stocker toutes les clés là augmente la taille totale de la table de chaînes partagée, ainsi que le nombre de fois où elle est redimensionnée au fur et à mesure de sa croissance. *Pire* - dans tout environnement qui a une mémoire "copie sur écriture" pour les processus enfants (comme un serveur à pré-fork), les pages mémoire utilisées pour la table de chaînes partagée doivent rapidement être copiées lorsque le processus enfant manipule des hachages. Ainsi, si la majeure partie de la table de chaînes partagée est telle que les clés ne sont utilisées qu'à un seul endroit, il n'y a aucun avantage à la réutilisation au sein de l'interpréteur Perl, mais un coût élevé dû à plus de pages pour que l'OS les copie.

L'interpréteur Perl peut maintenant être configuré pour désactiver les clés de hachage partagées pour les "grands" hachages (qui ne sont ni des objets ni des tables de symboles). Pour ce faire, ajoutez "-Accflags='-DPERL_USE_UNSHARED_KEYS_IN_LARGE_HASHES'"

Voici le contenu traduit en français, tout en conservant la structure du fichier : pour vos options Configure. « Large » est une heuristique – actuellement, l'heuristique est que le partage est désactivé lors de l'ajout d'une clé à un hash déclenche l'allocation de plus de stockage, et le hash a plus de 42 clés.

Cela pourrait entraîner une légère augmentation de l'utilisation de la mémoire pour les programmes qui créent des structures de données (non bénies) contenant plusieurs grands hashes qui partagent les mêmes clés. Mais en général, nos tests suggèrent que pour les cas spécifiques décrits, c'est un avantage, et les autres codes ne sont pas affectés.

•
Dans certains scénarios, la création de nouveaux scalaires est maintenant nettement plus rapide.

Par exemple, le code suivant s'exécute maintenant environ 30 % plus vite :

$str = "A" x 64;
for (0..1_000_000) {
    @svs = split //, $str
}

(Vous pouvez en lire plus à ce sujet dans [perl #19414] https://github.com/Perl/perl5/pull/19414.)

Diagnostics

Les ajouts ou modifications suivants ont été apportés à la sortie des diagnostics, y compris les avertissements et les messages d'erreur fatals. Pour la liste complète des messages de diagnostic, voir perldiag.

Nouveaux diagnostics

Nouvelles erreurs

  • Impossible de « %s » hors d'un bloc « defer »

    (F) Une tentative a été faite pour sortir de la portée d'un bloc defer en utilisant une instruction de contrôle de flux telle que « return », « goto » ou une commande de boucle. Ceci n'est pas autorisé.

  • Impossible de modifier %s dans %s (pour l'affectation scalaire à « undef »)

    Tenter d'effectuer une affectation scalaire à « undef », par exemple via « undef = $foo; », déclenchait auparavant une erreur d'exécution fatale avec le message « Modification d'une valeur en lecture seule tentée. ». Il est plus utile de détecter de telles affectations tentées avant l'exécution, elles sont donc maintenant des erreurs de compilation, résultant du message « Impossible de modifier l'opérateur undef dans une affectation scalaire ».

panic: newFORLOOP, %s

L'analyseur syntaxique a échoué à une vérification interne de cohérence lors de la tentative d'analyse d'une boucle "foreach".

Nouveaux avertissements

  • La fonction intégrée '%s' est expérimentale

    Un appel est effectué à une fonction dans l'espace de noms "builtin::", qui est actuellement expérimentale.

  • defer est expérimental

    Le modificateur de bloc "defer" est expérimental. Si vous souhaitez utiliser cette fonctionnalité, désactivez l'avertissement avec "no warnings 'experimental::defer'", mais sachez qu'en faisant cela, vous risquez que votre code ne fonctionne plus dans une future version de Perl.

  • La rétrogradation d'une déclaration de use VERSION à une version antérieure à v5.11 est dépréciée

    Cet avertissement est émis lors d'une instruction "use VERSION" qui demande une version inférieure à v5.11 (lorsque les effets de "use strict" seraient désactivés), après une déclaration précédente d'une version avec un nombre plus élevé (qui aurait activé ces effets)

  • for my (...) est expérimental

    Cet avertissement est émis si vous utilisez "for" pour itérer plusieurs valeurs à la fois. Cette syntaxe est actuellement expérimentale et son comportement peut changer dans les futures versions de Perl.

  • L'utilisation implicite de @_ dans %s avec une sous-routine signée est expérimentale

    Une expression qui implique implicitement le tableau d'arguments @_ a été trouvée dans une sous-routine qui utilise une signature.

  • L'utilisation de @_ dans %s avec une sous-routine signée est expérimentale

    Une expression impliquant le tableau d'arguments @_ a été trouvée dans une sous-routine qui utilise une signature.

  • Caractère large dans $0

    Les tentatives d'insertion de caractères larges dans le nom du programme ($0) déclenchent maintenant cet avertissement.

Changements aux diagnostics existants

  • '/' ne prend pas de nombre de répétitions dans %s

    Cet avertissement n'incluait pas auparavant le texte "in %s".

  • Sous-routine %s redéfinie

    Les redéfinitions de sous-routines localisées ne déclenchent plus cet avertissement.

  • constante inattendue lvalue entersub entry via type/targ %d:%d" a maintenant un préfixe panic

    Cela le rend cohérent avec d'autres vérifications de cohérence interne lors de la compilation d'une sous-routine.

  • Utilisation inutile de sort en contexte scalaire est maintenant dans la nouvelle catégorie "scalar".

    Lorsque "sort" est utilisé en contexte scalaire, il provoque un avertissement indiquant que cela est inutile. Cet avertissement était auparavant dans la catégorie "void". Une nouvelle catégorie pour les avertissements concernant le contexte scalaire a maintenant été ajoutée, appelée "scalar".

  • Suppression d'un certain nombre de diagnostics

    De nombreux diagnostics qui ont été supprimés du cœur de Perl au fil des ans ont maintenant *également* été supprimés de la documentation.

Configuration et Compilation

  • Le code source C de Perl utilise maintenant certaines fonctionnalités C99, que nous avons vérifiées comme étant prises en charge par tous les compilateurs que nous ciblons. Cela signifie que les en-têtes de Perl contiennent maintenant du code légal en C99 mais pas en C89.

    Cela peut poser des problèmes pour certains modules XS qui ajoutent inconditionnellement "-Werror=declaration-after-statement" à leurs options de compilateur C lors de la compilation avec gcc ou clang. Les versions antérieures de Perl prenaient en charge des compilateurs longtemps obsolètes qui sont stricts dans le rejet de certaines fonctionnalités C99, en particulier les déclarations et le code mixtes, et il est donc logique que les auteurs de modules XS auditent leur code pour qu'il ne viole pas cela. Cependant, cela n'est maintenant possible que sur ces versions antérieures de Perl, par conséquent ces modules doivent être modifiés pour n'ajouter ce drapeau que pour "$] < 5.035005".

  • L'étape makedepend est maintenant exécutée en parallèle en utilisant make

    Lorsque vous utilisez MAKEFLAGS=-j8, cela réduit considérablement le temps requis pour :

    sh ./makedepend MAKE=make cflags
  • Configure teste maintenant si "#include <xlocale.h>" est requis pour utiliser les fonctions de locale POSIX 1003 thread-safe ou certaines extensions connexes. Cela évite les problèmes où un xlocale.h non public est supprimé lors d'une mise à jour de bibliothèque, ou si xlocale.h n'est pas destiné à un usage public. (github #18936 https://github.com/Perl/perl5/pull/18936)

Support des plateformes

Windows

  • La prise en charge des anciens MSVC++ (avant VC12) a été supprimée

    Ceux-ci ne prenaient pas en charge C99 et ne peuvent donc plus être utilisés pour compiler perl.

  • La prise en charge de la compilation de perl sous Windows à l'aide de Microsoft Visual Studio 2022 (contenant Visual C++ 14.3) a été ajoutée.
  • La couche IO :win32 a été supprimée. Ce remplacement expérimental de la couche :unix n'a jamais atteint sa maturité au cours de ses près de deux décennies d'existence.

VMS

"keys %ENV" sur VMS donne des résultats cohérents
Sur VMS, les entrées dans le hachage %ENV sont chargées depuis l'environnement du système d'exploitation lors du premier accès. Par conséquent, la première itération de %ENV nécessite que tout l'environnement soit analysé pour trouver toutes les clés possibles. Cette initialisation avait toujours été effectuée correctement pour une itération complète, mais elle ne se produisait auparavant pas pour %ENV en contexte scalaire, ce qui signifie que "scalar %ENV" renverrait 0 si appelé avant tout autre accès à %ENV, ou ne renverrait que le compte des clés accédées s'il n'y avait pas eu d'itération.

Ces bogues sont maintenant corrigés - %ENV et "keys %ENV" en contexte scalaire renvoient maintenant le résultat correct - le nombre de toutes les clés de l'environnement.

Plateformes discontinuees

AT&T UWIN
UWIN est une couche de compatibilité UNIX pour Windows. Elle a été publiée pour la dernière fois en 2012 et a depuis été remplacée par Cygwin.
DOS/DJGPP
DJGPP est un portage de la chaîne d'outils GNU vers des systèmes x86 32 bits exécutant DOS. La dernière tentative connue de compilation de Perl sur celui-ci remonte à la version 5.20, qui n'est allée que jusqu'à la compilation de miniperl.
NetWare
Le code de support pour Novell NetWare a été supprimé. NetWare était un système d'exploitation serveur de Novell. Le portage a été mis à jour pour la dernière fois en juillet 2002, et la plateforme elle-même en mai 2009.

Des changements non liés ont accidentellement cassé la compilation pour le port NetWare en septembre 2009, et en 12 ans, personne ne l'a signalé.

z/OS
Cette mise à jour nous permet de construire des Perl statiques/dynamiques EBCDIC et en mode adressage 31 bits/64 bits. Le nombre de tests qui réussissent est cohérent avec la base avant ces mises à jour.

Le code XS qui appelle déjà les API pour obtenir des valeurs ne sera pas affecté par ce changement. Le code XS qui accède directement aux drapeaux au lieu d'utiliser les appels d'API pour exprimer son intention *pourrait* échouer, mais un tel code est probablement déjà erroné s'il reçoit d'autres valeurs, telles que des valeurs flottantes ou des objets avec surcharge de chaîne.

    Ce petit changement permet au code (tel que les sérialiseurs JSON) de déterminer de manière fiable la différence entre

    my $answer = "42";
print "That doesn't look right\n"

Corrections de bugs sélectionnées

  • utime() définit désormais correctement errno/$! lorsqu'il est appelé sur une poignée fermée.
  • Les drapeaux du paramètre OPTVAL pour setsockopt() étaient précédemment vérifiés avant que le magie ne soit appelée, traitant potentiellement une valeur numérique comme un tampon empaqueté ou vice versa. Il ignorait également le drapeau UTF-8, traitant potentiellement la représentation interne d'un SV mis à niveau comme les octets à fournir à l'appel système setsockopt(). (github #18660 https://github.com/Perl/perl5/issues/18660)
  • Définir seulement IOKp, pas IOK sur $) et $(. Il s'agissait du problème #18955 https://github.com/Perl/perl5/issues/18955 : Cela empêchera les sérialiseurs de sérialiser ces variables comme des nombres (ce qui perd les groupes supplémentaires). Cela restaure le comportement de la version 5.16.
  • L'utilisation de la facilité de débogage "mktables" faisait planter Perl depuis la v5.31.10 ; ce problème est désormais résolu.
  • La logique de "makedepend" est désormais compatible avec le make BSD (corrige GH #19046 https://github.com/Perl/perl5/issues/19046).
  • Appeler "untie" sur un hachage lié qui est en cours d'itération libère désormais immédiatement l'état d'itération.

    L'itération d'un hachage lié amène Perl à stocker une copie de la clé de hachage actuelle pour suivre l'état d'itération, cette copie stockée étant passée comme second paramètre à "NEXTKEY". Cet état interne est libéré immédiatement lorsque l'itération du hachage lié se termine, ou si le hachage est détruit, mais en raison d'une omission de mise en œuvre, il n'était pas libéré si le hachage était désolidarisé. Dans ce cas, la copie interne de la clé persistait jusqu'au premier des événements suivants :

1.
"tie" était à nouveau appelé sur le même hachage
2.
Le hachage (maintenant désolidarisé) était itéré (c'est-à-dire passé à "keys", "values" ou "each")
3.
Le hachage était détruit.

Cette incohérence est maintenant corrigée - l'état interne est désormais libéré immédiatement par "untie".

Comme le moment précis de ce comportement peut être observé avec du code Perl pur (le moment de "DESTROY" sur les objets renvoyés par "FIRSTKEY" et "NEXTKEY"), il est possible que certains codes soient sensibles à cela.

  • La fonction Internals::getcwd() ajoutée pour le démarrage de miniperl dans Perl 5.30.0 n'est maintenant disponible que dans miniperl. [github #19122]
  • Définir un point d'arrêt sur une instruction BEGIN ou équivalente un "use" pouvait entraîner une écriture en mémoire dans un op "dbstate" libéré. [GH #19198 https://github.com/Perl/perl5/issues/19198]
  • Lorsque les gestionnaires de fichiers sans guillemets sont désactivés, l'analyseur interprétait n'importe quel mot-clé comme un gestionnaire de fichiers, même lorsqu'il était immédiatement suivi de parenthèses.
