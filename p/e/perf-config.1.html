NOM

perf-config - Obtenir et définir des variables dans un fichier de configuration.

SYNTAXE

perf config [<option-fichier>] [section.nom[=valeur] ...]
ou
perf config [<option-fichier>] -l | --list

DESCRIPTION

Vous pouvez gérer des variables dans un fichier de configuration avec cette commande.

OPTIONS

-l, --list

Affiche les variables de configuration actuelles, le nom et la valeur, pour toutes les sections.

--user

Pour l'écriture et la lecture d'options : écrit dans le fichier utilisateur $HOME/.perfconfig ou le lit.

--system

Pour l'écriture et la lecture d'options : écrit dans le fichier système $(sysconfdir)/perfconfig ou le lit.

FICHIER DE CONFIGURATION

Le fichier de configuration de perf contient de nombreuses variables pour modifier divers aspects de chacun de ses outils, y compris la sortie, l'utilisation du disque, etc. Le fichier $HOME/.perfconfig est utilisé pour stocker une configuration par utilisateur. Le fichier $(sysconfdir)/perfconfig peut être utilisé pour stocker une configuration par défaut à l'échelle du système.

On peut désactiver la lecture des fichiers de configuration en définissant la variable d'environnement PERF_CONFIG à /dev/null, ou fournir un fichier de configuration alternatif en définissant cette variable.

Lors de la lecture ou de l'écriture, les valeurs sont lues à partir des fichiers de configuration système et utilisateur par défaut, et les options --system et --user peuvent être utilisées pour indiquer à la commande de lire ou d'écrire uniquement à cet emplacement.

Syntaxe

Le fichier se compose de sections. Une section commence par son nom entouré de crochets et se poursuit jusqu'à ce que la section suivante commence. Chaque variable doit être dans une section et avoir la forme nom = valeur, par exemple :

[section]
        nom1 = valeur1
        nom2 = valeur2

Les noms de section sont sensibles à la casse et peuvent contenir tous les caractères sauf le saut de ligne (les guillemets doubles " et la barre oblique inverse doivent être échappés respectivement en \" et \\). Les en-têtes de section ne peuvent pas s'étendre sur plusieurs lignes.

Exemple

Compte tenu d'un $HOME/.perfconfig comme celui-ci :

# # Ceci est le fichier de configuration, et # un caractère # et ; indique un commentaire #

[couleurs]
        # Variables de couleur
        top = rouge, defaut
        medium = vert, defaut
        normal = grisclair, defaut
        selectionne = blanc, grisclair
        jump_arrows = bleu, defaut
        addr = magenta, defaut
        root = blanc, bleu
[tui]
        # Valeurs par défaut si lié avec libslang
        report = on
        annotate = on
        top = on
[buildid]
        # Par défaut, désactive l'utilisation de /dev/null
        dir = ~/.debug
[annotate]
        # Valeurs par défaut
        hide_src_code = false
        use_offset = true
        jump_arrows = true
        show_nr_jumps = false
[help]
        # Le format peut être man, info, web ou html
        format = man
        autocorrect = 0
[ui]
        show-headers = true
[call-graph]
        # fp (pointeur de frame), dwarf
        record-mode = fp
        print-type = graph
        order = caller
        sort-key = function
[report]
        # Valeurs par défaut
        sort_order = comm,dso,symbol
        percent-limit = 0
        queue-size = 0
        children = true
        group = true
        skip-empty = true

Vous pouvez masquer le code source de la fonctionnalité d'annotation en définissant la configuration sur false avec

% perf config annotate.hide_src_code=true

Si vous souhaitez ajouter ou modifier plusieurs éléments de configuration, vous pouvez faire comme suit :

% perf config ui.show-headers=false kmem.default=slab

Pour modifier l'ordre de tri de la fonctionnalité de rapport dans le fichier de configuration utilisateur (c'est-à-dire ~/.perfconfig), faites :

% perf config --user report.sort-order=srcline

Pour changer les couleurs de la ligne sélectionnée en d'autres couleurs de premier plan et d'arrière-plan dans le fichier de configuration système (c'est-à-dire $(sysconf)/perfconfig), faites :

% perf config --system colors.selected=yellow,green

Pour interroger le mode d'enregistrement du graphique d'appels, faites :

% perf config call-graph.record-mode

Si vous souhaitez connaître plusieurs paires clé/valeur de configuration, vous pouvez faire comme suit :

% perf config report.queue-size call-graph.order report.children

Pour interroger la valeur de configuration de l'ordre de tri du graphique d'appels dans le fichier de configuration utilisateur (c'est-à-dire ~/.perfconfig), faites :

% perf config --user call-graph.sort-order

Pour interroger la valeur de configuration du répertoire buildid dans le fichier de configuration système (c'est-à-dire $(sysconf)/perfconfig), faites :

% perf config --system buildid.dir

Variables

colors.*

Les variables pour personnaliser les couleurs utilisées dans la sortie pour report, top et annotate dans le TUI. Elles doivent spécifier les couleurs de premier plan et d'arrière-plan, séparées par une virgule, par exemple : 
medium = vert, grisclair
Si vous souhaitez utiliser la couleur configurée pour votre terminal, laissez-la simplement telle quelle : 'defaut', par exemple :
medium = defaut, grisclair
Couleurs disponibles :
rouge, jaune, vert, cyan, gris, noir, bleu,
blanc, defaut, magenta, grisclair

colors.top

top signifie un pourcentage de surcharge supérieur à 5%. Les valeurs de cette variable spécifient les couleurs des pourcentages. Les valeurs clés de base sont la couleur de premier plan rouge et la couleur d'arrière-plan defaut.

colors.medium

medium signifie un pourcentage de surcharge supérieur à 0,5%. Les valeurs par défaut sont vert et defaut.

colors.normal

normal signifie le reste des pourcentages de surcharge sauf top, medium, selectionne. Les valeurs par défaut sont grisclair et defaut.

colors.selected

Ceci sélectionne les couleurs pour l'entrée actuelle dans une liste d'entrées des sous-commandes (top, report, annotate). Les valeurs par défaut sont noir et grisclair.

colors.jump_arrows

Couleurs pour les flèches de saut dans les listes de code d'assemblage telles que jns, jmp, jane, etc. Les valeurs par défaut sont bleu, defaut.

colors.addr

Ceci sélectionne les couleurs pour les adresses de annotate. Les valeurs par défaut sont magenta et defaut.

colors.root

Couleurs pour les en-têtes dans la sortie des sous-commandes (top, report). Les valeurs par défaut sont blanc et bleu.

core.*, core.proc-map-timeout

Définit un délai (en millisecondes) pour l'analyse des fichiers /proc/<pid>/maps. Peut être remplacé par l'option --proc-map-timeout sur les sous-commandes prises en charge. Le délai par défaut est de 500 ms.

tui., gtk.

Les sous-commandes qui peuvent être configurées ici sont top, report et annotate. Ces valeurs sont des booléens, par exemple : 
[tui]
        top = true
rendra le TUI par défaut pour la sous-commande 'top'. Ceux-ci seront
disponibles si les bibliothèques requises ont été détectées lors de la compilation de l'outil.

buildid.*, buildid.dir

Chaque exécutable et bibliothèque partagée dans les distributions modernes est livré avec un identifiant basé sur le contenu qui, s'il est disponible, sera inséré dans un en-tête de fichier perf.data pour, au moment de l'analyse, trouver ce qui est nécessaire pour effectuer la résolution de symboles, l'annotation de code, etc. 
Les outils d'enregistrement stockent également un lien physique ou une copie dans un répertoire par utilisateur, $HOME/.debug/, des binaires, des bibliothèques partagées, des fichiers /proc/kallsyms et /proc/kcore à utiliser au moment de l'analyse.
La variable buildid.dir peut être utilisée pour modifier l'emplacement de ce cache de répertoire, ou pour le désactiver complètement. Si vous souhaitez le désactiver,
définissez buildid.dir sur /dev/null. La valeur par défaut est $HOME/.debug

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

buildid-cache.*

buildid-cache.debuginfod=URLs Spécifiez les URL de debuginfod à utiliser lors de la récupération des binaires perf.data. La syntaxe est la même que celle de la variable DEBUGINFOD_URLS, par exemple : 
buildid-cache.debuginfod=http://192.168.122.174:8002

annotate.*

Ces options contrôlent les adresses, les fonctions de saut, le code source en lignes de code assembleur à partir d'un programme spécifique.

annotate.disassemblers

Choisissez le désassembleur à utiliser : "objdump", "llvm", "capstone". S'il n'est pas spécifié, il essaiera d'abord, si disponible, celui de "llvm", puis, s'il échoue, celui de "capstone", et enfin celui d'origine basé sur "objdump". 
Choisir un désassembleur différent est utile lorsque vous traitez une fonctionnalité dont on sait qu'elle est mieux prise en charge à un moment donné par l'une des options, pour comparer la sortie en cas de doute sur un bug, etc.
Cela peut être une liste, par ordre de préférence, le premier qui fonctionne termine le processus.

annotate.addr2line

Binaire addr2line à utiliser pour les noms de fichiers et les numéros de ligne.

annotate.objdump

Binaire objdump à utiliser pour le désassemblage et les annotations, y compris dans la commande perf test.

annotate.disassembler_style

Utilisez ceci pour changer le style du désassembleur par défaut à une autre valeur prise en charge par binutils, telle que "intel". Voir l'option -M dans la page de manuel de objdump.

annotate.hide_src_code

Si un programme analysé a du code source, cette option permet à annotate d'afficher une liste de code assembleur avec le code source. Par exemple, considérons une partie d'un programme. Il y a quatre lignes. Si cette option est true, elles peuvent être affichées sans code source du programme comme ci-dessous. 
│        push   %rbp
│        mov    %rsp,%rbp
│        sub    $0x10,%rsp
│        mov    (%rdi),%rdx
Mais si cette option est 'false', le code source de la partie peut également être affiché comme ci-dessous. La valeur par défaut est 'false'.
│      struct rb_node *rb_next(const struct rb_node *node)
│      {
│        push   %rbp
│        mov    %rsp,%rbp
│        sub    $0x10,%rsp
│              struct rb_node *parent;
│
│              if (RB_EMPTY_NODE(node))
│        mov    (%rdi),%rdx
│              return n;
Cette option fonctionne avec les navigateurs tui et stdio2.

annotate.use_offset

En se basant sur la première adresse d'une fonction chargée, un décalage peut être utilisé. Au lieu d'utiliser les adresses d'origine du code assembleur, les adresses soustraites d'une adresse de base peuvent être affichées. Illustrons un exemple. Si une adresse de base est 0XFFFFFFFF81624d50 comme ci-dessous, 
ffffffff81624d50 <load0>
une adresse dans le code assembleur a une adresse absolue spécifique comme ci-dessous
ffffffff816250b8:│  mov    0x8(%r14),%rdi
mais si use_offset est 'true', une adresse soustraite d'une adresse de base est affichée. La valeur par défaut est true. Cette option ne s'applique qu'à TUI.
368:│  mov    0x8(%r14),%rdi
Cette option fonctionne avec les navigateurs tui et stdio2.

annotate.jump_arrows

Il peut y avoir des instructions de saut dans le code assembleur. Selon la valeur booléenne de jump_arrows, des flèches peuvent être affichées ou non, représentant où l'instruction saute, comme ci-dessous. 
│     ┌──jmp    1333
│     │  xchg   %ax,%ax
│1330:│  mov    %r15,%r10
│1333:└─→cmp    %r15,%r14
Si jump_arrow est 'false', les flèches ne sont pas affichées comme ci-dessous. La valeur par défaut est 'false'.
│      ↓ jmp    1333
│        xchg   %ax,%ax
│1330:   mov    %r15,%r10
│1333:   cmp    %r15,%r14
Cette option fonctionne avec le navigateur tui.

annotate.show_linenr

Lors de l'affichage du code source, si cette option est true, les numéros de ligne sont affichés comme ci-dessous. 
│1628         if (type & PERF_SAMPLE_IDENTIFIER) {
│     ↓ jne    508
│1628                 data->id = *array;
│1629                 array++;
│1630         }
Cependant, si cette option est 'false', elles ne sont pas affichées comme ci-dessous. La valeur par défaut est 'false'.
│             if (type & PERF_SAMPLE_IDENTIFIER) {
│     ↓ jne    508
│                     data->id = *array;
│                     array++;
│             }
Cette option fonctionne avec les navigateurs tui et stdio2.

annotate.show_nr_jumps

Considérons une partie du code assembleur. 
│1382:   movb   $0x1,-0x270(%rbp)
Si vous utilisez ceci, le nombre de branches pointant vers cette adresse peut être affiché comme ci-dessous. La valeur par défaut est 'false'.
│1 1382:   movb   $0x1,-0x270(%rbp)
Cette option fonctionne avec les navigateurs tui et stdio2.

annotate.show_total_period

Pour comparer deux enregistrements sur une base d'instructions, avec cette option fournie, affichez le nombre total d'échantillons appartenant à une ligne de code assembleur. Si cette option est true, les périodes totales sont affichées au lieu des pourcentages comme ci-dessous. 
302 │      mov    %eax,%eax
Mais si cette option est 'false', les pourcentages de surcharge sont affichés, c'est-à-dire la valeur par défaut est 'false'.
99.93 │      mov    %eax,%eax
Cette option fonctionne avec les navigateurs tui, stdio2 et stdio.

annotate.show_nr_samples

Par défaut, perf annotate affiche le pourcentage d'échantillons. Cette option peut être utilisée pour afficher le nombre absolu d'échantillons. Par exemple, lorsqu'elle est définie sur false : 
Percent│
 74.03 │      mov    %fs:0x28,%rax
Lorsqu'elle est définie sur true :
Samples│
     6 │      mov    %fs:0x28,%rax
Cette option fonctionne avec les navigateurs tui, stdio2 et stdio.

annotate.offset_level

La valeur par défaut est 1, ce qui signifie que seuls les cibles de saut auront des décalages affichés juste à côté de l'instruction. Lorsqu'elle est définie sur 2, les instructions call auront également leurs décalages affichés, 3 ou plus afficheront les décalages pour toutes les instructions. 
Cette option fonctionne avec les navigateurs tui et stdio2.

annotate.demangle

Démangle les noms de symboles pour les rendre lisibles par l'homme. La valeur par défaut est true.

annotate.demangle_kernel

Démangle les noms de symboles du noyau pour les rendre lisibles par l'homme. La valeur par défaut est true.

hist.*, hist.percentage

Cette option contrôle la manière de calculer la surcharge des entrées filtrées - cela signifie que la valeur de cette option n'est effective que s'il existe un filtre (par nom de comm, dso ou symbole). Supposons l'exemple suivant : 
Overhead  Symbols
........  .......
 33.33%     foo
 33.33%     bar
 33.33%     baz
C'est la surcharge d'origine et nous allons filtrer la première entrée 'foo'. La valeur 'relative' augmenterait la surcharge de 'bar' et 'baz' à 50.00% chacun, tandis que 'absolute' afficherait leur surcharge actuelle (33.33%).

ui.*, ui.show-headers

Cette option contrôle l'affichage des en-têtes de colonnes (comme Overhead et Symbol) dans report et top. Si cette option est false, ils sont masqués. Cette option ne s'applique qu'à TUI.

call-graph.*

Les options suivantes contrôlent la gestion des graphes d'appels (obtenus via les options -g/--call-graph).

call-graph.record-mode

Le mode pour l'espace utilisateur peut être fp (pointeur de cadre), dwarf et lbr. La valeur dwarf n'est effective que si libunwind (ou une version récente de libdw) est présente sur le système ; la valeur lbr ne fonctionne que pour certains CPU. La méthode pour l'espace noyau est contrôlée non pas par cette option mais par la configuration du noyau (CONFIG_UNWINDER_*).

call-graph.dump-size

La taille de la pile à vider pour effectuer le post-démêlage. La valeur par défaut est 8192 (octets). Lors de l'utilisation de dwarf en mode enregistrement, la taille par défaut sera utilisée si elle est omise.

call-graph.print-type

Les types d'affichage peuvent être graph (graphe absolu), fractal (graphe relatif), flat (plat) et folded (replié). Cette option contrôle la façon d'afficher la surcharge pour chaque entrée de la chaîne d'appels. Considérons l'exemple suivant. 
Overhead  Symbols
........  .......
  40.00%  foo
          |
          ---foo
             |
             |--50.00%--bar
             |          main
             |
              --50.00%--baz
                        main
Ceci est une sortie au format 'fractal'. Le 'foo' provient de 'bar' et 'baz' exactement à parts égales, donc 'fractal' affiche 50.00% pour chacun (ce qui signifie qu'il suppose une surcharge totale de 100% pour 'foo').
Le mode 'graph' utilise la surcharge absolue de 'foo' comme total, donc chaque chaîne d'appels de 'bar' et 'baz' aura 20.00% de surcharge. Si 'flat' est utilisé, exposition linéaire des chaînes d'appels sur une seule colonne. 'folded' signifie que les chaînes d'appels sont affichées sur une ligne, séparées par des points-virgules.

call-graph.order

Cette option contrôle l'ordre d'affichage des chaînes d'appels. La valeur par défaut est callee (appelé), ce qui signifie que l'appelé est affiché en haut, suivi de son appelant, et ainsi de suite. caller (appelant) l'affiche dans l'ordre inverse. 
Si cette option n'est pas définie et que report.children ou top.children est défini sur true (ou que l'option de ligne de commande équivalente est donnée), la valeur par défaut de cette option est changée en 'caller' pour l'exécution de 'perf report' ou 'perf top'. Les autres commandes continueront à utiliser 'callee' par défaut.

call-graph.sort-key

Les chaînes d'appels sont fusionnées si elles contiennent les mêmes informations. L'option sort-key détermine une manière de comparer les chaînes d'appels. Une valeur de sort-key peut être function ou address. La valeur par défaut est function.

LIGNES

Les options pour configurer le comportement des différents sous-commandes de perf.

OPTIONS

call-graph.threshold
Limite les petites chaînes d'appels sous un certain seuil de surcharge. La valeur par défaut est 0.5 (%). La surcharge est calculée en fonction du type d'affichage du graphe d'appels.
call-graph.print-limit
Nombre maximum de lignes de chaînes d'appels à imprimer pour une seule entrée d'histogramme. La valeur par défaut est 0 (aucune limitation).
report.*, report.sort_order
Permet de modifier l'ordre de tri par défaut de "comm,dso,symbol" à un autre, par exemple "sym,dso" qui pourrait être plus adapté aux développeurs du noyau.
report.percent-limit
Similaire à call-graph.threshold, mais s'applique aux entrées d'histogramme. Les entrées dont la surcharge est inférieure à ce pourcentage ne seront pas imprimées. La valeur par défaut est 0. Si percent-limit est 10, seules les entrées ayant plus de 10% de surcharge seront imprimées.
report.queue-size
Définit la taille maximale d'allocation de la file d'attente interne des événements pour l'ordonnancement. La valeur par défaut est 0 (aucune limite).
report.children
Les "enfants" sont les fonctions appelées par une autre fonction. Si cette option est vraie, perf report cumule les chaînes d'appels des enfants et affiche la surcharge totale (accumulée) ainsi que la surcharge "Self". Se référer au manuel de perf report. La valeur par défaut est true.
report.group
Cette option permet d'afficher ensemble les informations de groupe d'événements. Exemple de sortie avec cette option activée, remarquez qu'il y a une colonne par événement dans le groupe, ref-cycles et cycles : 
# group: {ref-cycles,cycles}
# ========
#
# Samples: 7K of event 'anon group { ref-cycles, cycles }'
# Event count (approx.): 6876107743
#
#         Overhead  Command      Shared Object               Symbol
# ................  .......  .................  ...................
#
    99.84%  99.76%  noploop  noploop            [.] main
     0.07%   0.00%  noploop  ld-2.15.so         [.] strcmp
     0.03%   0.00%  noploop  [kernel.kallsyms]  [k] timerqueue_del
report.skip-empty
Cette option peut modifier le comportement par défaut de stat avec des résultats vides. Si elle est définie à vrai, perf report --stat n'affichera pas les statistiques égales à 0.
top.*, top.children
Identique à report.children. Ainsi, si elle est activée, la sortie de la commande top aura une colonne de surcharge Children ainsi qu'une colonne de surcharge Self par défaut. La valeur par défaut est true.
top.call-graph
Identique à call-graph.record-mode, sauf qu'elle s'applique uniquement à la sous-commande top. Cette option configure UNIQUEMENT la méthode de désempilement. Pour que perf top l'utilise réellement, l'option de ligne de commande -g doit être spécifiée.
man.*, man.viewer
Cette option permet d'assigner un outil pour visualiser les pages de manuel lorsque la sous-commande help est appelée. Les outils supportés sont man, woman (avec le client emacs) et konqueror. La valeur par défaut est man. 
Un nouvel outil de visualisation de manuel peut également être ajouté en utilisant 'man.<tool>.cmd'
ou utiliser un chemin différent en utilisant l'option de configuration 'man.<tool>.path'.
pager.*, pager.<subcommand>
Lorsque la sous-commande est exécutée sur stdio, détermine si un pager est utilisé ou non en fonction de cette valeur. La valeur par défaut est non spécifiée.
kmem.*, kmem.default
Cette option décide quel allocateur doit être analysé si aucune option --slab ou --page n'est utilisée. La valeur par défaut est slab.
record.*, record.build-id
Cette option peut être cache, no-cache, skip ou mmap. cache permet de post-traiter les données et de sauvegarder/mettre à jour les binaires dans le cache build-id (dans ~/.debug). C'est la valeur par défaut. Mais si cette option est no-cache, elle ne mettra pas à jour le cache build-id. skip saute le post-traitement et ne met pas à jour le cache. mmap saute le post-traitement et lit les build-ids à partir des événements MMAP.
record.call-graph
Identique à call-graph.record-mode, sauf qu'elle s'applique uniquement à la sous-commande record. Cette option configure UNIQUEMENT la méthode de désempilement. Pour que perf record l'utilise réellement, l'option de ligne de commande -g doit être spécifiée.
record.aio
Utilise n blocs de contrôle en mode d'écriture de trace asynchrone (Posix AIO) (n par défaut: 1, max: 4).
record.debuginfod
Spécifie l'URL de debuginfod à utiliser lors de la mise en cache des binaires perf.data, elle suit la même syntaxe que la variable DEBUGINFOD_URLS, par exemple :
http://192.168.122.174:8002 
Si l'URL est 'system', la valeur de la variable d'environnement système DEBUGINFOD_URLS
est utilisée.
diff.*, diff.order
Cette option définit le nombre de colonnes pour trier le résultat. La valeur par défaut est 0, ce qui signifie le tri par ligne de base. La définir à 1 triera le résultat par delta (ou par une autre méthode de calcul sélectionnée).
diff.compute
Cette option définit la méthode de calcul du résultat de la différence. Les valeurs possibles sont delta, delta-abs, ratio et wdiff. La valeur par défaut est delta.
trace.*, trace.add_events
Permet d'ajouter un ensemble d'événements à ceux spécifiés par l'utilisateur, ou de les utiliser comme événements par défaut si aucun n'a été spécifié. Le cas d'utilisation initial est d'ajouter augmented_raw_syscalls.o pour activer la logique de perf trace qui recherche le contenu des pointeurs de syscall après la charge utile normale du tracepoint.
trace.args_alignment
Nombre de colonnes pour aligner la liste des arguments, la valeur par défaut est 70. Utiliser 40 pour la valeur par défaut de strace, zéro pour aucun alignement.
trace.no_inherit
Ne pas suivre les threads enfants.
trace.show_arg_names
Les noms des arguments des appels système doivent-ils être imprimés ? Sinon, trace.show_zeros sera défini.
trace.show_duration
Afficher la durée des appels système.
trace.show_prefix
Si défini à yes, affichera les préfixes de chaîne communs dans les tableaux. Par défaut, le préfixe commun est supprimé dans des choses comme "MAP_SHARED", affichant simplement "SHARED".
trace.show_timestamp
Afficher l'horodatage de début de l'appel système.
trace.show_zeros
Ne pas supprimer les arguments des appels système qui sont égaux à zéro.
trace.tracepoint_beautifiers
Utiliser "libtraceevent" pour utiliser cette bibliothèque afin d'augmenter les arguments des tracepoints, "libbeauty", la valeur par défaut, pour utiliser les mêmes beautifieurs d'arguments que ceux utilisés dans les lignes sys_enter+sys_exit de type strace.
ftrace.*, ftrace.tracer
Peut être utilisé pour sélectionner le traceur par défaut lorsque ni l'option -G ni -F ne sont spécifiées. Les valeurs possibles sont function et function_graph.
samples.*, samples.context
Définit combien de ns de temps afficher autour des échantillons dans le navigateur de contexte d'échantillons de perf report.
scripts.*
Toute option définit un script qui est ajouté au menu des scripts dans le navigateur interactif de perf et dont la sortie est affichée. Le nom de l'option est le nom, la valeur est une ligne de commande de script. Le script reçoit les mêmes options que perf script complet, en particulier -i fichier perfdata, --cpu, --tid
convert.*, convert.queue-size
Limite la taille de la file d'attente ordered_events, nous permettant ainsi de contrôler la taille d'allocation des fichiers de données perf sans événements de fin de cycle appropriés.
stat.*, stat.big-num
(booléen) Change la valeur par défaut de "--big-num". Pour faire de "--no-big-num" la valeur par défaut, définissez "stat.big-num=false".
intel-pt.*, intel-pt.cache-divisor, intel-pt.mispred-all
Si défini, le décodeur Intel PT définira le drapeau mispred sur toutes les branches.
intel-pt.max-loops
Si défini et non nul, le nombre maximum de branches inconditionnelles décodées sans consommer de paquets de trace. Si le maximum est dépassé, une erreur "Boucle sans fin" se produira. La valeur par défaut est 100000.
intel-pt.all-switch-events
Si l'utilisateur en a l'autorisation, enregistrer toujours tous les événements de commutation de contexte sur tous les CPU.
auxtrace.*, auxtrace.dumpdir
s390 uniquement. Le répertoire pour sauvegarder le tampon de trace auxiliaire peut être modifié à l'aide de cette option. Par exemple, auxtrace.dumpdir=/tmp. Si le répertoire n'existe pas ou a le mauvais type de fichier, le répertoire courant est utilisé.
itrace.*, debug-log-buffer-size
Taille du journal en octets à afficher lors de l'utilisation de l'option --itrace=d+e Se référer à l'option itrace de perf-script(1) ou perf-report(1). La valeur par défaut est 16384.
daemon.*, daemon.base
Chemin de base pour les données du démon. Toutes les données de session sont stockées sous ce chemin.
session-<NAME>.*, session-<NAME>.run
Définit une nouvelle session d'enregistrement pour le démon. La valeur est la ligne de commande de record sans le mot-clé record.

Name

perf-config - configure performance counters

Synopsis

perf config [-h|--help] [--version]
perf config [-l|--list]
perf config [-e|--event] 
perf config [-p|--path] 
perf config [-m|--mmap_size] 
perf config [-d|--delay] 
perf config [-f|--file] 
perf config [-a|--all]

Description

The perf-config command is used to configure performance counters on the system. It allows users to set various parameters related to performance event monitoring.

Options

-h, --help
Display help information.
--version
Display version information.
-l, --list
List all available performance events.
-e, --event <event>
Set the performance event to monitor.
-p, --path <path>
Set the path to the performance data file.
-m, --mmap_size <size>
Set the size of the memory-mapped buffer for performance data.
-d, --delay <delay>
Set the delay in seconds before starting performance monitoring.
-f, --file <file>
Specify a file to read performance data from.
-a, --all
Configure all performance counters.

Examples

# List all available performance events
perf config -l

# Monitor the 'cpu-cycles' event
perf config -e cpu-cycles

# Set the performance data file path
perf config -p /var/log/perf.data

# Set the memory-mapped buffer size to 1MB
perf config -m 1048576

# Set the delay to 5 seconds
perf config -d 5

# Read performance data from a file
perf config -f my_perf_data.bin

# Configure all performance counters
perf config -a
