PERL5340DELTA(1perl) Guide de référence du programmeur Perl PERL5340DELTA(1perl)

NOM

perl5340delta - ce qu'il y a de nouveau pour la version perl v5.34.0

DESCRIPTION

Ce document décrit les différences entre la version 5.32.0 et la version 5.34.0.

Si vous mettez à jour depuis une version antérieure comme la 5.30.0, lisez d'abord perl5320delta, qui décrit les différences entre 5.30.0 et 5.32.0.

Améliorations du cœur

Syntaxe expérimentale Try/Catch

Une première tentative expérimentale de fournir une notation "try"/"catch" a été ajoutée.

use feature 'try';
try {
    a_function();
}
catch ($e) {
    warn "Une erreur s'est produite : $e";
}

Pour plus d'informations, voir "Gestion des exceptions Try Catch" dans perlsyn.

"qr/{,n}/" est maintenant accepté

Une borne inférieure vide est maintenant acceptée pour les quantificateurs d'expressions régulières, comme "m/x{,3}/" ce qui signifie "m/x{0,3}/"

Les espaces sont librement autorisés à l'intérieur mais adjacents aux accolades

(dans les contextes de chaînes entre guillemets doubles et les motifs d'expressions régulières)

Cela signifie que vous pouvez écrire des choses comme "\x{ FFFC }" si vous le souhaitez. Cela s'applique à toutes ces constructions, à savoir "\b{}", "\g{}", "\k{}", "\N{}", "\o{}", et "\x{}" ; ainsi qu'au quantificateur d'expression régulière "{m,n}". "\p{}" et "\P{}" conservent leurs règles déjà existantes, encore plus souples, dictées par la norme Unicode (voir "Propriétés accessibles via \p{} et \P{}" dans perluniprops).

Cette capacité est en vigueur indépendamment de la présence du modificateur de motif d'expression régulière "/x".

De plus, la virgule dans un quantificateur de groupe d'expression régulière peut avoir des espaces (tabulations ou espaces) avant et/ou après la virgule, comme "qr/a{ 5, 7 }/".

Nouvelle syntaxe octale "0oddddd"

Il est maintenant possible de spécifier des littéraux octaux avec des préfixes "0o", comme dans "0o123_456", parallèlement à la construction existante pour spécifier un littéral hexadécimal "0xddddd" et un littéral binaire "0bddddd". De plus, la fonction intégrée oct() accepte maintenant cette nouvelle syntaxe.

Voir "Constructeurs de valeurs scalaires" dans perldata et "oct EXPR" dans perlfunc.

Caractère large dans la clé setenv (encodage en utf8)

Les tentatives de mise de caractères larges dans les clés de variables d'environnement via %ENV provoquent maintenant cet avertissement.

Modifications apportées aux diagnostics existants

  • Erreur %s dans l'expansion de %s

    Une erreur a été rencontrée dans la gestion

ling d'une propriété définie par l'utilisateur ("Propriétés de caractères définies par l'utilisateur" dans perlunicode). Ce sont des sous-routines écrites par le programmeur, donc sujettes à des erreurs qui peuvent les empêcher de compiler ou de s'exécuter.

  • Récursion infinie dans une propriété définie par l'utilisateur

    Une propriété définie par l'utilisateur ("Propriétés de caractères définies par l'utilisateur" dans perlunicode) peut dépendre des définitions d'autres propriétés définies par l'utilisateur. Si la chaîne de dépendances ramène à cette propriété, une récursion infinie se produirait, n'eût été la vérification qui a levé cette erreur.

  • Expiration du délai d'attente d'un autre thread pour définir \p{%s}

    La première fois qu'une propriété définie par l'utilisateur ("Propriétés de caractères définies par l'utilisateur" dans perlunicode) est utilisée, sa définition est recherchée et convertie dans une forme interne pour une gestion plus efficace lors d'utilisations ultérieures. Il pourrait y avoir une course si deux threads ou plus tentaient de réaliser ce traitement presque simultanément.

  • Nom de propriété définie par l'utilisateur \p{%s} inconnu

    Vous avez spécifié d'utiliser une propriété dans "\p{...}" qui était syntaxiquement valide en tant que propriété définie par l'utilisateur, mais aucune définition n'a été trouvée pour celle-ci.

  • Trop peu d'arguments pour la sous-routine '%s' (reçu %d ; attendu %d)

    Les erreurs d'inadéquation du nombre d'arguments des sous-routines incluent désormais le nombre d'arguments donnés et attendus.

  • Trop d'arguments pour la sous-routine '%s' (reçu %d ; attendu %d)

    Les erreurs d'inadéquation du nombre d'arguments des sous-routines incluent désormais le nombre d'arguments donnés et attendus.

  • Perte de précision lors de %s %f par 1

    Cet avertissement n'était émis que pour les valeurs positives trop grandes lors de l'incrémentation, et uniquement pour les valeurs négatives lors de la décrémentation. Il est désormais émis pour les valeurs trop grandes, positives ou négatives. [GH #18333 https://github.com/Perl/perl5/issues/18333]

  • \K non autorisé dans les lookahead/lookbehind d'une regex ; marqué par <-- ICI dans m/%s/

    Cette erreur était produite incorrectement dans certains cas impliquant des lookarounds imbriqués. Ceci a été corrigé. [GH #18123 https://github.com/Perl/perl5/issues/18123]

  • Utilisation d'une valeur non initialisée%s

    Cet avertissement peut désormais inclure l'indice du tableau ou du hash lorsque la valeur non initialisée est le résultat d'un élément introuvable. Cela ne se produira que si l'indice est une variable simple et non magique.

    Configuration et Compilation

    • Empêché que incpath n'envahisse libpth
    • Utilisé realpath si disponible. (Cela pourrait détecter plus de chemins dupliqués.)
    • Inclus uniquement les chemins réels existants.
    • Filtré les chemins inc de libpth.

      Le support de stadtx a été entièrement supprimé. Auparavant, il pouvait être demandé avec "PERL_HASH_FUNC_STADTX", et était par défaut dans les compilations 64 bits. Il a été remplacé par SipHash. SipHash a été examiné plus rigoureusement que stadtx.

    • Configure

      Une nouvelle sonde vérifie les implémentations défectueuses de libc des fonctions "gcvt"/"qgcvt". [GH #18170 https://github.com/Perl/perl5/issues/18170]

      Perl peut désormais être compilé avec strict activé par défaut (en utilisant l'option de configuration "-Dusedefaultstrict".

      Ces valeurs par défaut strict ne s'appliquent pas lorsque "perl" est exécuté via "-e" ou "-E".

      Ce paramètre fournit un mécanisme de diagnostic destiné uniquement au développement et est donc désactivé par défaut.

    • La version minimale de Bison prise en charge est désormais 2.4, et la version maximale est 3.7.
    • Les versions 64 bits plus récentes du compilateur Intel C/C++ sont désormais reconnues et les bons indicateurs leur sont appliqués.
    • Nous intercepçons désormais SIGBUS lorsque Configure vérifie "va_copy".

      Sur plusieurs systèmes, la tentative de déterminer si nous avons besoin de "va_copy" ou similaire entraîne un SIGBUS au lieu du SIGSEGV attendu, ce qui provoquait auparavant un vidage du cœur.

    stat(), `lstat()`, et les opérateurs de fichier

    Le mode développeur est activé.

    stat(), y compris "stat FILEHANDLE", et lstat() utilisent maintenant notre propre implémentation qui remplit les numéros de périphérique "dev" et d'inode "ino" retournés plutôt que de toujours retourner zéro. Le champ du nombre de liens "nlink" est maintenant toujours rempli.

    "${^WIN32_SLOPPY_STAT}" contrôlait auparavant si le champ "nlink" était rempli, nécessitant un appel API Windows distinct pour le récupérer, puisque "nlink" et les autres informations requises pour stat() sont maintenant récupérées en un seul appel API.

    Les opérateurs "-r" et "-w" retournent maintenant vrai pour les descripteurs "STDIN", "STDOUT" et "STDERR". Malheureusement, cela ne retournera toujours pas vrai pour les doublons de ces descripteurs. [GH #8502 https://github.com/Perl/perl5/issues/8502].

    Les heures retournées par stat() et lstat() ne sont plus incorrectes après les ajustements de l'heure d'été. [GH #6080 https://github.com/Perl/perl5/issues/6080].

    "-x" sur un descripteur de fichier devrait maintenant correspondre à "-x" sur le nom de fichier correspondant sur Vista ou version ultérieure. [GH #4145 https://github.com/Perl/perl5/issues/4145].

    "-e '"'" ne retourne plus incorrectement vrai. [GH #12431 https://github.com/Perl/perl5/issues/12431].

    Le même manifeste est maintenant utilisé pour les builds Visual C++ et gcc.

    Auparavant, les builds MSVC utilisaient l'indicateur /manifestdependency au lieu d'intégrer perlexe.manifest, ce qui causait des problèmes tels que GetVersionEx() retournant le mauvais numéro de version sous Windows 10.

    z/OS
    Les catégories de locale "LC_SYNTAX" et "LC_TOD" sont maintenant reconnues. Perl ne fait rien avec celles-ci, sauf qu'il vous permet maintenant de les spécifier. Elles sont incluses dans "LC_ALL".

    Changements internes

    • Correction de la gestion des paramètres double et double précision pour l'implémentation de Perl de la sortie formatée pour les builds "-Dusequadmath".

      Cela s'applique à PerlIO_printf(), croak(), warn(), sv_catpvf() et leurs variantes.

      Précédemment dans les builds "quadmath", un code comme :

      PerlIO_printf(PerlIO_stderr(), "%g", somedouble);

      ou

      PerlIO_printf(PerlIO_stderr(), "%Lg", somelongdouble);

      lancerait erroneousément une exception "panic: quadmath invalid format ...", car le code ajouté pour les builds quadmath supposait que les "NV" étaient le seul format à virgule flottante passé à ces fonctions.

      Ce code traitait également le spécificateur C standard pour les doubles précision "L" comme s'il attendait un "NV" ("__float128" pour les builds quadmath), entraînant un comportement indéfini.

      Ces fonctions acceptent maintenant correctement les doubles, les doubles précision et les NVs.

    • Précédemment, l'opérande droit des opérateurs de décalage binaire (montant du décalage) était implicitement converti de IV en int, mais cela pouvait conduire à des résultats incorrects si IV ne tenait pas dans un int.

      De plus, le décalage de bits INT_MIN entraînait auparavant le changement du décalé sans modification (traité comme un décalage de 0 bits au lieu d'un décalage négatif).

    • Un ensemble de fonctions "cop_hints_exists_{pv,pvn,pvs,sv}" a été ajouté, pour prendre en charge la vérification de l'existence de clés dans le hachage des indications d'un cop spécifique sans avoir besoin de créer une copie mortelle de ladite valeur.
    • Une aide a été ajoutée pour utiliser les macros "DEBUG" lors du débogage de code XS ou C. Les commentaires dans perl.h décrivent "DEBUG_PRE_STMTS" et "DEBUG_POST_STMTS", que vous pouvez "#define" pour faire des choses comme sauvegarder et restaurer "errno", au cas où les appels "DEBUG" interféreraient avec cela, ou pour afficher des horodatages, ou de quel thread il provient, ou l'emplacement de l'appel, ou quoi que ce soit d'autre. Vous pouvez faire un hack rapide pour vous aider à suivre quelque chose sans avoir à modifier des appels "DEBUG" individuels.
    • Rendre "REFCOUNTED_HE_EXISTS" disponible en dehors du cœur.
    • Toutes les fonctions de type "SvTRUE" évaluent maintenant leurs arguments une seule fois. Dans 5.32, "SvTRUE" tout court dans perlapi a été modifié pour faire cela ; maintenant les autres le font aussi.
    • Unicode est maintenant un citoyen de première classe lorsqu'on considère le motif /A*B/ où A et B sont arbitraires. Le code de correspondance de motif essaie de faire une boucle serrée pour correspondre à la portée des A. La logique de cela a maintenant été réellement mise à jour avec la prise en charge de UTF-8.
    • Le module re a une nouvelle fonction "optimization", qui peut retourner un hashref de données d'optimisation découvertes sur une regexp compilée.
    • L'option de compilation "PERL_GLOBAL_STRUCT" a été supprimée, et avec elle le besoin ou la macro "dVAR". "dVAR" reste défini comme une opération nulle en dehors de "PERL_CORE" pour la compatibilité ascendante avec les modules XS.
    • Un nouveau type de pile de sauvegarde "SAVEt_HINTS_HH" a été ajouté, ce qui rend plus propre le comportement précédent de "SAVEt_HINTS". Sur les versions précédentes, les types et valeurs poussés sur la pile de sauvegarde dépendaient du fait que les indications incluaient le bit "HINT_LOCALIZE_HH", ce qui complique le code externe qui inspecte la pile de sauvegarde. La nouvelle version utilise un type de pile de sauvegarde différent pour indiquer la différence.
    • Une nouvelle fonction API "av_count" dans perlapi a été ajoutée, qui donne un moyen clairement nommé de trouver combien d'éléments se trouvent dans un tableau.

    Corrections de bugs sélectionnées

    • Définir %ENV gère maintenant correctement les chaînes mises à niveau dans la clé. Précédemment, Perl envoyait le PV interne du SV directement à l'OS ; maintenant, il gérera les clés comme il a géré les valeurs depuis 5.18 : tenter de rétrograder la chaîne d'abord ; si cela échoue, alors avertir et utiliser la forme utf8.
    • Correction d'une fuite de mémoire dans regcomp.c [GH #18604 https://github.com/Perl/perl5/issues/18604]
    • Le format d'emballage/déballage 'D' fonctionne maintenant sur tous les systèmes qui pouvaient le supporter.

      Précédemment, si "NV == long double", maintenant c'est supporté sur toutes les plateformes qui ont des doubles précision. En particulier, cela signifie que c'est maintenant aussi supporté sur les plateformes quadmath.

    • Ignorer la tentative de replier les constantes d'un arbre d'opérations incomplet [GH #18380 https://github.com/Perl/perl5/issues/18380]

      Le repliement des constantes des arbres d'opérations de comparaison en chaîne pouvait échouer dans certaines conditions, provoquant le crash de perl. Comme solution rapide, le repliement des constantes est maintenant ignoré pour de tels arbres d'opérations. Cela corrige également [GH #17917 https://github.com/Perl/perl5/issues/17917].

    • Formatage %g cassé sur Ubuntu-18.04, "NVSIZE == 8" [GH #18170 https://github.com/Perl/perl5/issues/18170]

      Des implémentations libc boguées des fonctions "gcvt" et "qgcvt" causaient que "(s)printf" tronquait incorrectement les nombres formatés en %g. Une nouvelle sonde Configure vérifie maintenant cela, avec le résultat que "sprintf" de libc sera utilisé à la place de "gcvt" et "qgcvt".

      Les tests ajoutés dans le cadre de cette correction ont également révélé des problèmes connexes dans certaines builds Windows. Les makefiles pour les builds MINGW sous Windows ont donc été ajustés pour utiliser "USE_MINGW_ANSI_STDIO" par défaut, assurant qu'ils fournissent également un formatage "(s)printf" correct des nombres.

    • op.c : croak sur "my $_" quand "use utf8" est en vigueur [GH #18449 https://github.com/Perl/perl5/issues/18449]

      L'expérience de la fonction thématique lexicale a été supprimée dans Perl v5.24 et déclarer "my $_" est devenu une erreur au moment de la compilation. Cependant, il était précédemment encore possible de faire cette déclaration si "use utf8" était en vigueur.

    • regexec.c : Correction d'un échec d'assertion [GH #18451 https://github.com/Perl/perl5/issues/18451]

      Le fuzzing a déclenché un échec d'assertion dans le moteur regexp lorsque trop de caractères étaient copiés dans un tampon.

    • semctl(), msgctl(), et shmctl() réinitialisent maintenant correctement le drapeau UTF-8 sur le paramètre "ARG" s'il est modifié pour les opérations "IPC_STAT" ou "GETALL".
    • semctl(), msgctl(), et shmctl() tentent maintenant de rétrograder "ARG"

    Selected Bug Fixes

    • A bug in Tie::Hash::Nested where a tied hash could be incorrectly upgraded was fixed.
    • Fixed a bug where a list assignment could leave $_ in an inconsistent state.
    • The "ARG" parameter is now correctly downgraded if its value is being used as input to "IPC_SET" or "SETALL" calls. A failed downgrade will throw an exception.
    • In cases where semctl(), msgctl() or shmctl() would treat the "ARG" parameter as a pointer, an undefined value no longer generates a warning. In most such calls the pointer isn't used anyway and this allows you to supply "undef" for a value not used by the underlying function.
    • semop() now downgrades the "OPSTRING" parameter, msgsnd() now downgrades the "MSG" parameter and shmwrite now downgrades the "STRING" parameter to treat them as bytes. Previously they would be left upgraded, providing a corrupted structure to the underlying function call.
    • msgrcv() now properly resets the UTF-8 flag the "VAR" parameter when it is modified. Previously the UTF-8 flag could be left on, resulting in a possibly corrupt result in "VAR".
    • Magic is now called correctly for stacked file test operators. [GH #18293 https://github.com/Perl/perl5/issues/18293]
    • The "@ary = split(...)" optimization no longer switches in the target array as the value stack. [GH #18232 https://github.com/Perl/perl5/issues/18232] Also see discussion at https://github.com/Perl/perl5/pull/18014#issuecomment-671299506.
    • Fixed a bug in which some regexps with recursive subpatterns matched incorrectly.

      [GH #18096 https://github.com/Perl/perl5/issues/18096]

    • On Win32, "waitpid(-1, WNOHANG)" could sometimes have a very large timeout. [GH #16529 https://github.com/Perl/perl5/issues/16529]
    • "MARK" and hence "items" are now correctly initialized in "BOOT" XSUBs.
    • Some list assignments involving "undef" on the left-hand side were over-optimized and produced incorrect results. [GH #16685 https://github.com/Perl/perl5/issues/16685], [GH #17816 https://github.com/Perl/perl5/issues/17816]
