PERLIOL(1perl) Guide de référence des programmeurs Perl PERLIOL(1perl)

NOM

perliol - API C pour l'implémentation des couches d'E/S de Perl.

SYNOPIS

/* Définition d'une couche ... */
#include <perliol.h>

DESCRIPTION

Ce document décrit le comportement et l'implémentation de l'abstraction PerlIO décrite dans perlapio lorsque "USE_PERLIO" est défini.

Historique et Contexte

L'abstraction PerlIO a été introduite dans perl5.003_02 mais elle est restée une simple abstraction jusqu'à perl5.7.0. Cependant, pendant cette période, un certain nombre d'extensions Perl ont commencé à l'utiliser, donc l'API est principalement figée pour maintenir la compatibilité (source).

L'objectif de l'implémentation est de fournir l'API PerlIO d'une manière flexible et neutre vis-à-vis de la plateforme. C'est également un essai d'approche "C orienté objet, avec vtables" qui pourra être appliquée à Raku.

Structure de Base

PerlIO est une pile de couches.

Les niveaux inférieurs de la pile travaillent avec les appels système de bas niveau (descripteurs de fichiers en C) pour faire entrer et sortir les octets, les niveaux supérieurs de la pile mettent en mémoire tampon, filtrent et manipulent les E/S, et retournent des caractères (ou des octets) à Perl. Les termes *au-dessus* et *en dessous* sont utilisés pour faire référence à la position relative des couches de la pile.

Une couche contient une "vtables" (table virtuelle), la table des opérations d'E/S (en C, une table de pointeurs de fonction), et des drapeaux d'état. Les fonctions de la vtable implémentent des opérations comme "open", "read", et "write".

Lorsqu'une opération d'E/S, par exemple "read", est demandée, la requête descend d'abord dans la pile en utilisant les fonctions "read" de chaque couche, puis en bas, l'entrée est demandée aux services du système d'exploitation, ensuite le résultat est renvoyé vers le haut de la pile, finalement interprété comme des données Perl.

Les requêtes ne descendent pas nécessairement toujours jusqu'au système d'exploitation : c'est là qu'intervient la mise en mémoire tampon de PerlIO.

Lorsque vous faites un open() et spécifiez des couches PerlIO supplémentaires à déployer, les couches que vous spécifiez sont "empilées" sur la pile par défaut déjà existante. Une façon de le voir est que "le système d'exploitation est à gauche" et "Perl est à droite".

Quelles sont les couches exactes dans cette pile par défaut dépend de beaucoup de choses : votre système d'exploitation, la version de Perl, la configuration de compilation de Perl, et la configuration d'exécution de Perl. Voir PerlIO, "PERLIO" dans perlrun, et open pour plus d'informations.

binmode() fonctionne de manière similaire à open() : par défaut, les couches spécifiées sont empilées sur la pile existante.

Cependant, notez que même si les couches spécifiées sont "empilées sur le dessus" pour open() et binmode(), cela ne signifie pas que les effets sont limités au "dessus" : les couches PerlIO peuvent être très 'actives' et inspecter et affecter également les couches plus profondes dans la pile. Par exemple, il existe une couche appelée "raw" qui "dépile" les couches de manière répétée jusqu'à ce qu'elle atteigne la première couche qui s'est déclarée capable de gérer des données binaires. Les couches "empilées" sont traitées dans l'ordre gauche-droite.

sysopen() fonctionne (sans surprise) à un niveau inférieur dans la pile que open(). Par exemple, sur les systèmes Unix ou similaires, sysopen() fonctionne directement au niveau des descripteurs de fichiers : dans les termes des couches PerlIO, il n'utilise que la couche "unix", qui est un wrapper plutôt mince au-dessus des descripteurs de fichiers Unix.

Couches vs Disciplines

La discussion initiale sur la capacité de modifier le comportement des flux d'E/S utilisait le terme "discipline" pour les entités qui étaient ajoutées. Je crois que cela venait de l'utilisation du terme dans "sfio", qui à son tour l'a emprunté aux "disciplines de ligne" des terminaux Unix. Cependant, ce document (et le code C) utilise le terme "couche".

Ceci est, je l'espère, un terme naturel étant donné l'implémentation, et devrait éviter les connotations inhérentes aux utilisations antérieures de "discipline" pour des choses qui sont assez différentes.

Structures de Données

La structure de données de base est une PerlIOl :

typedef struct _PerlIO PerlIOl;
typedef struct _PerlIO_funcs PerlIO_funcs;
typedef PerlIOl *PerlIO;
struct _PerlIO
{
 PerlIOl *      next;       /* Couche inférieure */
 PerlIO_funcs * tab;        /* Fonctions pour cette couche */
 U32            flags;      /* Divers drapeaux pour l'état */
};

Un "PerlIOl *" est un pointeur vers la structure, et le "PerlIO *" au niveau de l'application est un pointeur vers un "PerlIOl *" - c'est-à-dire un pointeur vers un pointeur vers la structure. Cela permet au pointeur "PerlIO *" de niveau application de rester constant pendant que le "PerlIOl *" réel en dessous change. (Comparez avec le "SV *" de Perl qui reste constant pendant que son champ "sv_any" change à mesure que le type du scalaire change.) Un flux IO est alors généralement représenté comme un pointeur vers cette liste chaînée de "couches".

Il convient de noter qu'en raison de la double indirection dans un "PerlIO *", un "&(perlio->next)" "est" un "PerlIO *", et donc dans une certaine mesure, au moins une couche peut utiliser l'API "standard" sur la couche inférieure.

Une "couche" est composée de deux parties :

1.
Les fonctions et attributs de la "classe de couche".
2.
Les données par instance pour un handle particulier.

Fonctions et Attributs

Les fonctions et attributs sont accessibles via le membre "tab" (pour table) de "PerlIOl". Les fonctions (méthodes de la "classe" de couche) sont fixes, et sont définies par le type "PerlIO_funcs". Elles sont globalement les mêmes que les fonctions publiques "PerlIO_xxxxx" :

struct _PerlIO_funcs
{
 Size_t     fsize;
 char *     name;
 Size_t     size;
 IV         kind;
 IV         (*Pushed)(pTHX_ PerlIO *f,
                            const char *mode,
                            SV *arg,
                            PerlIO_funcs *tab);
 IV         (*Popped)(pTHX_ PerlIO *f);
 PerlIO *   (*Open)(pTHX_ PerlIO_funcs *tab,
                          PerlIO_list_t *layers, IV n,
                          const char *mode,
                          int fd, int imode, int perm,
                          PerlIO *old,
                          int narg, SV **args);
 IV         (*Binmode)(pTHX_ PerlIO *f);
 SV *       (*Getarg)(pTHX_ PerlIO *f, CLONE_PARAMS *param, int flags)
 IV         (*Fileno)(pTHX_ PerlIO *f);
 PerlIO *   (*Dup)(pTHX_ PerlIO *f,
                         PerlIO *o,
                         CLONE_PARAMS *param,
                         int flags)
 /* Fonctions de type Unix - cf disciplines de ligne sfio */
 SSize_t    (*Read)(pTHX_ PerlIO *f, void *vbuf, Size_t count);
 SSize_t    (*Unread)(pTHX_ PerlIO *f, const void *vbuf, Size_t count);
 SSize_t    (*Write)(pTHX_ PerlIO *f, const void *vbuf, Size_t count);
 IV         (*Seek)(pTHX_ PerlIO *f, Off_t offset, int whence);
 Off_t      (*Tell)(pTHX_ PerlIO *f);
 IV         (*Close)(pTHX_ PerlIO *f);
 /* Fonctions d'E/S tamponnées de type stdio */
 IV         (*Flush)(pTHX_ PerlIO *f);
 IV         (*Fill)(pTHX_ PerlIO *f);
 IV         (*Eof)(pTHX_ PerlIO *f);
 IV         (*Error)(pTHX_ PerlIO *f);
 void       (*Clearerr)(pTHX_ PerlIO *f);
 void       (*Setlinebuf)(pTHX_ PerlIO *f);
 /* Fonctions d'espionnage de Perl */
 STDCHAR *  (*Get_base)(pTHX_ PerlIO *f);
 Size_t     (*Get_bufsiz)(pTHX_ PerlIO *f);
 STDCHAR *  (*Get_ptr)(pTHX_ PerlIO *f);
 SSize_t    (*Get_cnt)(pTHX_ PerlIO *f);
 void       (*Set_ptrcnt)(pTHX_ PerlIO *f,STDCHAR *ptr,SSize_t cnt);
};

Les premiers membres de la structure donnent la taille de la table de fonctions pour la vérification de compatibilité, "name" pour la couche, la taille pour "malloc" pour les données par instance, et quelques drapeaux qui sont des attributs de la classe dans son ensemble (tels qu'une couche de mise en mémoire tampon ou non), puis suivent les fonctions qui se répartissent en quatre groupes principaux :

Per-instance Data

1.
Fonctions d'ouverture et de configuration
2.
Opérations d'E/S de base
3.
Options de mise en tampon de la classe Stdio.
4.
Fonctions pour supporter l'accès "rapide" traditionnel de Perl au tampon.

Une couche n'a pas besoin d'implémenter toutes les fonctions, mais toute la table doit être présente. Les emplacements non implémentés peuvent être NULL (ce qui entraînera une erreur lors de l'appel) ou peuvent être remplis avec des stubs pour "hériter" du comportement d'une "classe de base". Cet "héritage" est fixe pour toutes les instances de la couche, mais comme la couche choisit quels stubs peupler la table, un "héritage multiple" limité est possible.

Données par instance

Les données par instance sont détenues en mémoire au-delà de la struct PerlIOl de base, en faisant de PerlIOl le premier membre de la struct de la couche comme suit :

typedef struct
{
 struct _PerlIO base;       /* Informations de "classe" de base */
 STDCHAR *      buf;        /* Début du tampon */
 STDCHAR *      end;        /* Fin de la partie valide du tampon */
 STDCHAR *      ptr;        /* Position actuelle dans le tampon */
 Off_t          posn;       /* Décalage de buf dans le fichier */
 Size_t         bufsiz;     /* Taille réelle du tampon */
 IV             oneword;    /* Tampon d'urgence */
} PerlIOBuf;

De cette manière (comme pour les scalaires de Perl) un pointeur vers une PerlIOBuf peut être traité comme un pointeur vers une PerlIOl.

Les couches en action

             table           perlio          unix
         |           |
         +-----------+    +----------+    +--------+
PerlIO ->|           |--->|  next    |--->|  NULL  |
         +-----------+    +----------+    +--------+
         |           |    |  buffer  |    |   fd   |
         +-----------+    |          |    +--------+
         |           |    +----------+

Ce qui précède tente de montrer comment le schéma de couches fonctionne dans un cas simple. Le "PerlIO *" de l'application pointe vers une entrée dans la ou les tables représentant des descripteurs ouverts (alloués). Par exemple, les trois premiers emplacements de la table correspondent à "stdin", "stdout" et "stderr". La table pointe à son tour vers la couche "supérieure" actuelle pour le descripteur - dans ce cas, une instance de la couche de mise en tampon générique "perlio". Cette couche pointe à son tour vers la couche inférieure suivante - dans ce cas, la couche de bas niveau "unix".

Ce qui précède est à peu près équivalent à un flux mis en tampon "stdio", mais avec beaucoup plus de flexibilité :

  • Si les fonctions Unix de niveau "read"/"write"/"lseek" ne conviennent pas pour (par exemple) les sockets, alors la couche "unix" peut être remplacée (au moment de l'ouverture ou même dynamiquement) par une couche "socket".
  • Les différents descripteurs peuvent avoir différents schémas de mise en tampon. La couche "supérieure" pourrait être la couche "mmap" si la lecture de fichiers sur disque était plus rapide en utilisant "mmap" qu'en utilisant "read". Un flux "non tamponné" peut être implémenté simplement en n'ayant pas de couche de tampon.
  • Des couches supplémentaires peuvent être insérées pour traiter les données au fur et à mesure de leur flux. C'était le besoin principal pour inclure le schéma dans perl 5.7.0+ - nous avions besoin d'un mécanisme pour permettre la traduction des données entre l'encodage interne de Perl (conceptuellement au moins Unicode sous forme de UTF-8) et le format "natif" utilisé par le système. Ceci est fourni par la couche ":encoding(xxxx)" qui se place généralement au-dessus de la couche de mise en tampon.
  • Une couche peut être ajoutée qui fait la traduction de "\n" en CRLF. Cette couche peut être utilisée sur n'importe quelle plateforme, pas seulement celles qui font normalement de telles choses.

Bits d'indicateurs par instance

Les bits d'indicateurs génériques sont un hybride des indicateurs de style "O_XXXXX" déduits de la chaîne de mode passée à PerlIO_open() et des bits d'état pour les couches de tampon typiques.

PERLIO_F_EOF
Fin de fichier.
PERLIO_F_CANWRITE
Les écritures sont autorisées, c'est-à-dire ouvertes en tant que "w" ou "r+" ou "a", etc.
PERLIO_F_CANREAD
Les lectures sont autorisées, c'est-à-dire ouvertes en "r" ou "w+" (voire "a+" - beurk).
PERLIO_F_ERROR
Une erreur s'est produite (pour PerlIO_error()).
PERLIO_F_TRUNCATE
Troncature du fichier suggérée par le mode d'ouverture.
PERLIO_F_APPEND
Toutes les écritures doivent être des ajouts.
PERLIO_F_CRLF
La couche effectue une traduction de "\n" en CR, LF pour la sortie et de CR, LF en "\n" pour l'entrée, comme sous Win32. Normalement, la couche "crlf" fournie est la seule qui doit se préoccuper de cela. PerlIO_binmode() modifiera cet indicateur plutôt que d'ajouter/supprimer des couches si le bit "PERLIO_K_CANCRLF" est défini pour la classe de la couche.
PERLIO_F_UTF8
Les données écrites dans cette couche doivent être encodées en UTF-8 ; les données fournies par cette couche doivent être considérées comme encodées en UTF-8. Peut être défini sur n'importe quelle couche par la couche factice ":utf8". Également défini sur la couche ":encoding".
PERLIO_F_UNBUF
La couche n'est pas tamponnée - c'est-à-dire que l'écriture dans la couche inférieure doit se produire pour chaque écriture dans cette couche.
PERLIO_F_WRBUF
Le tampon de cette couche contient actuellement des données écrites mais non envoyées à la couche suivante.
PERLIO_F_RDBUF
Le tampon de cette couche contient actuellement des données non consommées lues de la couche inférieure.
PERLIO_F_LINEBUF
La couche est mise en tampon ligne par ligne. Les données écrites doivent être transmises à la couche inférieure chaque fois qu'un "\n" est rencontré. Les données au-delà du "\n" doivent ensuite être traitées.
PERLIO_F_TEMP
Le fichier a été unlink()é, ou doit être supprimé à la fermeture.
PERLIO_F_OPEN
Le descripteur est ouvert.
PERLIO_F_FASTGETS
Cette instance de cette couche supporte l'interface "fast "gets"". Normalement définie en fonction du "PERLIO_K_FASTGETS" de la classe et par l'existence de la ou des fonctions dans la table. Cependant, une classe qui fournit normalement cette interface peut avoir besoin de l'éviter pour une instance particulière. La couche "pending" doit faire cela lorsqu'elle est placée au-dessus d'une couche qui ne supporte pas l'interface. (Le sv_gets() de Perl ne s'attend pas à ce que le comportement "gets" rapide des flux change pendant un seul "get".)

Méthodes en détail

fsize
Size_t fsize;

Taille de la table des fonctions. Ceci est comparé à la valeur que le code PerlIO "connaît" comme vérification de compatibilité. Les versions futures *peuvent* être capables de tolérer des couches compilées contre une ancienne version des en-têtes.

name
char * name;

Le nom de la couche dont la méthode open() doit être invoquée par Perl lors de l'appel à open(). Par exemple, si la couche s'appelle APR, vous appellerez :

open $fh, ">:APR", ...

et Perl saura qu'il doit invoquer la méthode PerlIOAPR_open() implémentée par la couche APR.

size
Size_t size;

La taille de la structure de données par instance, par exemple :

sizeof(PerlIOAPR)

Si ce champ est zéro, alors "PerlIO_pushed" n'alloue rien en mémoire et suppose que la fonction Pushed de la couche effectuera toute manipulation de pile de couches nécessaire - utilisé pour éviter les surcoûts d'allocation/libération mémoire pour les couches factices. Si le champ est non nul, il doit être au moins de la taille de "PerlIOl". "PerlIO_pushed" allouera de la mémoire pour les structures de données de la couche et liera la nouvelle couche à la pile du flux. (Si la méthode Pushed de la couche retourne une indication d'erreur, la couche est de nouveau retirée.)

kind
IV kind;
  • PERLIO_K_BUFFERED

    La couche est tamponnée.

  • PERLIO_K_RAW

    La couche peut être acceptée dans une pile binmode(FH) - c'est-à-dire qu'elle ne transforme pas (ou se configure pour ne pas transformer) les octets qui la traversent.

  • PERLIO_K_CANCRLF

    La couche peut traduire entre les fins de ligne "\n" et CRLF.

  • PERLIO_K_FASTGETS

    La couche permet l'inspection du tampon.

  • PERLIO_K_MULTIARG

    Utilisé lorsque la méthode open() de la couche accepte plus d'arguments que d'habitude. Les arguments supplémentaires ne doivent pas précéder l'argument "MODE". Lorsque cette option est utilisée, il appartient à la couche de valider les arguments.

Pushed
IV     (*Pushed)(pTHX_ PerlIO *f,const char *mode, SV *arg);

La seule méthode absolument obligatoire. Appelée lorsque la couche est ajoutée à la pile. L'argument "mode" peut être NULL si cela se produit après l'ouverture. L'"arg" ne sera pas "NULL" si une chaîne d'argument a été passée. Dans la plupart des cas, cela devrait appeler PerlIOBase_pushe

d() pour convertir "mode" dans les drapeaux "PERLIO_F_XXXXX" appropriés en plus de toutes les actions que la couche elle-même effectue. Si une couche ne s'attend pas à un argument, elle n'a pas besoin de sauvegarder celui qui lui a été passé, ni de fournir Getarg() (elle pourrait éventuellement "Perl_warn" que l'argument n'était pas attendu).

Retourne 0 en cas de succès. En cas d'échec, retourne -1 et doit définir errno.

Popped
IV      (*Popped)(pTHX_ PerlIO *f);

Appelé lorsque la couche est retirée de la pile. Une couche sera normalement retirée après l'appel de Close(). Mais une couche peut être retirée sans être fermée si le programme gère dynamiquement les couches sur le flux. Dans de tels cas, Popped() doit libérer toutes les ressources (tampons, tables de traduction, ...) qui ne sont pas détenues directement dans la structure de la couche. Elle doit également Unread() toutes les données non consommées qui ont été lues et mises en tampon à partir de la couche inférieure vers cette couche, afin qu'elles puissent être redonnées à ce qui est maintenant au-dessus.

Retourne 0 en cas de succès et d'échec. Si Popped() retourne true, alors perlio.c suppose que soit la couche s'est retirée elle-même, soit la couche est super spéciale et doit être conservée pour d'autres raisons. Dans la plupart des cas, elle devrait retourner false.

Open
PerlIO *        (*Open)(...);

La méthode Open() a beaucoup d'arguments car elle combine les fonctions de "open" de Perl, "PerlIO_open", "sysopen" de Perl, "PerlIO_fdopen" et "PerlIO_reopen". Le prototype complet est le suivant :

PerlIO *       (*Open)(pTHX_ PerlIO_funcs *tab,
                       PerlIO_list_t *layers, IV n,
                       const char *mode,
                       int fd, int imode, int perm,
                       PerlIO *old,
                       int narg, SV **args);

Open devrait (peut-être indirectement) appeler PerlIO_allocate() pour allouer un emplacement dans la table et l'associer aux informations de couches pour le fichier ouvert, en appelant "PerlIO_push". Les layers sont un tableau de toutes les couches destinées au "PerlIO *", et tous les arguments qui leur sont passés, n est l'indice dans ce tableau de la couche appelée. La macro "PerlIOArg" retournera un SV * (potentiellement "NULL") pour l'argument passé à la couche.

Lorsqu'une couche ouvre ou prend possession d'un descripteur de fichier, cette couche est responsable de mettre le drapeau de fermeture à l'exécution du descripteur de fichier dans l'état correct. Le drapeau doit être effacé pour un descripteur de fichier numéroté inférieur ou égal à "PL_maxsysfd", et défini pour tout descripteur de fichier numéroté supérieur. Pour la sécurité des threads, lorsqu'une couche ouvre un nouveau descripteur de fichier, elle devrait, si possible, l'ouvrir avec le drapeau de fermeture à l'exécution initialement défini.

La chaîne mode est une chaîne de type "fopen()" qui correspondrait à l'expression régulière "/^[I#]?[rwa]\+?[bt]?$/".

Le préfixe 'I' est utilisé lors de la création de "stdin".."stderr" via des appels spéciaux "PerlIO_fdopen" ; le préfixe '#' signifie qu'il s'agit de "sysopen" et que imode et perm doivent être passés à "PerlLIO_open3" ; 'r' signifie read (lecture), 'w' signifie write (écriture) et 'a' signifie append (ajout). Le suffixe '+' signifie que la lecture et l'écriture/l'ajout sont autorisés. Le suffixe 'b' signifie que le fichier doit être binaire, et 't' signifie qu'il est textuel. (Presque toutes les couches devraient effectuer les E/S en mode binaire, et ignorer les bits b/t. La couche ":crlf" devrait être poussée pour gérer la distinction.)

Si old n'est pas "NULL" alors il s'agit d'un "PerlIO_reopen". Perl lui-même n'utilise pas cela (pour l'instant ?) et la sémantique est un peu vague.

Si fd n'est pas négatif alors c'est le descripteur de fichier numérique fd, qui sera ouvert d'une manière compatible avec la chaîne de mode fournie, l'appel est donc équivalent à "PerlIO_fdopen". Dans ce cas, nargs sera zéro. Le descripteur de fichier peut avoir le drapeau de fermeture à l'exécution défini ou effacé ; il incombe à la couche qui en prend possession de mettre le drapeau dans l'état correct.

Si nargs est supérieur à zéro alors il donne le nombre d'arguments passés à "open", sinon il sera de 1 si par exemple "PerlIO_open" a été appelé. Dans les cas simples, SvPV_nolen(*args) est le chemin du fichier à ouvrir.

Si une couche fournit Open(), elle devrait normalement appeler la méthode Open() de la couche inférieure suivante (s'il y en a une) puis se pousser par-dessus si cela réussit. "PerlIOBase_open" est fournie pour faire exactement cela, donc dans la plupart des cas, vous n'avez pas à écrire votre propre méthode Open(). Si cette méthode n'est pas définie, les autres couches peuvent avoir des difficultés à se pousser par-dessus lors de l'ouverture.

Si "PerlIO_push" a été effectué et que l'ouverture a échoué, elle doit "PerlIO_pop" elle-même, car si ce n'est pas le cas, la couche ne sera pas supprimée et peut causer de graves problèmes.

Retourne "NULL" en cas d'échec.

Binmode
IV        (*Binmode)(pTHX_ PerlIO *f);

Optionnel. Utilisé lorsque la couche ":raw" est poussée (explicitement ou en résultat de binmode(FH)). Si elle n'est pas présente, la couche sera retirée. Si elle est présente, elle devrait configurer la couche comme binaire (ou se retirer elle-même) et retourner 0. Si elle retourne -1 en cas d'erreur, "binmode" échouera avec la couche toujours sur la pile.

Getarg
SV *      (*Getarg)(pTHX_ PerlIO *f,
                    CLONE_PARAMS *param, int flags);

Optionnel. Si présent, devrait retourner un SV * représentant l'argument chaîne passé à la couche lorsqu'elle a été poussée. Par ex. ":encoding(ascii)" retournerait un SvPV avec la valeur "ascii". (Les arguments param et flags peuvent être ignorés dans la plupart des cas)

"Dup" utilise "Getarg" pour récupérer l'argument initialement passé à "Pushed", vous devez donc implémenter cette fonction si votre couche a un argument supplémentaire à "Pushed" et sera jamais "Dup"ée.

Fileno
IV        (*Fileno)(pTHX_ PerlIO *f);

Retourne le descripteur de fichier numérique Unix/Posix pour la poignée. Normalement, PerlIOBase_fileno() (qui demande simplement à la couche inférieure suivante) sera suffisant pour cela.

Retourne -1 en cas d'erreur, ce qui est considéré comme incluant le cas où la couche ne peut pas fournir un tel descripteur de fichier.

Dup
PerlIO * (*Dup)(pTHX_ PerlIO *f, PerlIO *o,
                CLONE_PARAMS *param, int flags);

XXX : Nécessite plus de documentation.

Utilisé dans le cadre du processus de clonage lors de la création d'un thread (auquel cas param ne sera pas NULL) et lors de la duplication d'un flux via '&' dans "open".

Similaire à "Open", retourne PerlIO* en cas de succès, "NULL" en cas d'échec.

Read
SSize_t (*Read)(pTHX_ PerlIO *f, void *vbuf, Size_t count);

Opération de lecture de base.

Appellera typiquement "Fill" et manipulera des pointeurs (éventuellement via l'API). PerlIOBuf_read() peut être adapté pour les classes dérivées qui fournissent des méthodes de "gets rapides".

Retourne les octets réellement lus, ou -1 en cas d'erreur.

Unread
SSize_t (*Unread)(pTHX_ PerlIO *f,
                  const void *vbuf, Size_t count);

Un sur-ensemble de ungetc() de stdio. Devrait organiser les lectures futures pour qu'elles voient les octets dans "vbuf". S'il n'y a pas d'implémentation évidemment meilleure, PerlIOBase_unread() fournit la fonction en poussant une couche "fausse" "en attente" au-dessus de la couche appelante.

Retourne le nombre de caractères non lus.

Write
SSize_t (*Write)(PerlIO *f, const void *vbuf, Size_t count);

Opération d'écriture de base.

Retourne les octets écrits, ou -1 en cas d'erreur.

Seek
IV      (*Seek)(pTHX_ PerlIO *f, Off_t offset, int whence);

Positionne le pointeur de fichier. Devrait normalement appeler sa propre méthode "Flush" puis la méthode "Seek" de la couche inférieure suivante.

Retourne 0 en cas de succès, -1 en cas d'échec.

Tell
Off_t   (*Tell)(pTHX_ PerlIO *f);

Retourne le pointeur de fichier. Peut être basé sur le concept mis en cache de position de la couche pour éviter les surcoûts.

Retourne -1 en cas d'échec pour obtenir le fichier

PerlIO_sv_ptr

Represents the PerlIO interface to Perl's scalar values.

The PerlIO layer interface is described in perluniperfio.pod. This file describes the PerlIO layer interface specifically for Perl's scalar types.

PerlIO_sv_ptr methods

These are the methods that are part of the PerlIO interface that can be used to access Perl's scalar values:

Open
IV      (*Open)(pTHX_ PerlIO *f, PerlIO_mode_t mode, SV *arg);

Opens a PerlIO stream. The argument arg is typically a scalar reference, or a scalar value.

Returns 0 on success, -1 on failure.

Read
SSize_t (*Read)(pTHX_ PerlIO *f, void *vdest, Size_t len);

Reads up to len bytes from the stream f into the buffer vdest. Returns the number of bytes read, 0 on end-of-file, and -1 on error.

Write
SSize_t (*Write)(pTHX_ PerlIO *f, const void *vsrc, Size_t len);

Writes up to len bytes from the buffer vsrc to the stream f. Returns the number of bytes written, or -1 on error.

Seek
IV      (*Seek)(pTHX_ PerlIO *f, IV offset, int whence);

Seeks within the stream. The offset and whence arguments are the same as for PerlIO_seek(). Returns the new position on success, or -1 on failure.

Tell
IV      (*Tell)(pTHX_ PerlIO *f);

Returns the current position within the stream, or -1 on failure.

Close
IV      (*Close)(pTHX_ PerlIO *f);

Closes the stream. Should normally call PerlIOBase_close() to flush itself and close layers below, and then deallocate any data structures (buffers, translation tables, ...) not held directly in the data structure.

Returns 0 on success, -1 on failure.

Flush
IV      (*Flush)(pTHX_ PerlIO *f);

Should make the stream's state consistent with layers below. That is, any buffered write data should be written, and the file position of lower layers adjusted for data read from below but not actually consumed. (Should perhaps Unread() such data to the lower layer.)

Returns 0 on success, -1 on failure.

Fill
IV      (*Fill)(pTHX_ PerlIO *f);

The buffer for this layer should be filled (for read) from the layer below. When you "subclass" PerlIOBuf layer, you want to use its _read method and to supply your own fill method, which fills the PerlIOBuf's buffer.

Returns 0 on success, -1 on failure.

Eof
IV      (*Eof)(pTHX_ PerlIO *f);

Returns the end-of-file indicator. PerlIOBase_eof() is normally sufficient.

Returns 0 on end-of-file, 1 if not end-of-file, -1 on error.

Error
IV      (*Error)(pTHX_ PerlIO *f);

Returns the error indicator. PerlIOBase_error() is normally sufficient.

Returns 1 if there is an error (usually when "PERLIO_F_ERROR" is set), 0 otherwise.

Clearerr
void    (*Clearerr)(pTHX_ PerlIO *f);

Clears end-of-file and error indicators. Should call PerlIOBase_clearerr() to set the "PERLIO_F_XXXXX" flags, which may suffice.

Setlinebuf
void    (*Setlinebuf)(pTHX_ PerlIO *f);

Marks the stream as line buffered. PerlIOBase_setlinebuf() sets the PERLIO_F_LINEBUF flag and is normally sufficient.

Get_base
STDCHAR *       (*Get_base)(pTHX_ PerlIO *f);

Allocates (if not already done so) the read buffer for this layer and returns a pointer to it. Returns NULL on failure.

Get_bufsiz
Size_t  (*Get_bufsiz)(pTHX_ PerlIO *f);

Returns the number of bytes that the last Fill() put in the buffer.

Get_ptr
STDCHAR *       (*Get_ptr)(pTHX_ PerlIO *f);

Returns the current read pointer relative to this layer's buffer.

Get_cnt
SSize_t (*Get_cnt)(pTHX_ PerlIO *f);

Returns the number of bytes left to be read in the current buffer.

Set_ptrcnt
void    (*Set_ptrcnt)(pTHX_ PerlIO *f,
                      STDCHAR *ptr, SSize_t cnt);

Adjusts the read pointer and count of bytes to match "ptr" and/or "cnt". The application (or layer above) must ensure they are consistent. (Checking is allowed by the paranoid.)

Utilities

To get the next layer down use PerlIONext(PerlIO *f).

To check that a PerlIO* is valid use PerlIOValid(PerlIO *f). (All this does is really just to check that the pointer is non-NULL and that the pointer behind that is non-NULL.)

PerlIOBase(PerlIO *f) returns the "Base" pointer, or in other words, the "PerlIOl*" pointer.

PerlIOSelf(PerlIO* f, type) returns the PerlIOBase cast to a type.

Perl_PerlIO_or_Base(PerlIO* f, callback, base, failure, args) either calls the callback from the functions of the layer f (just by the name of the IO function, like "Read") with the args, or if there is no such callback, calls the base version of the callback with the same args, or if the f is invalid, sets errno to EBADF and returns failure.

Perl_PerlIO_or_fail(PerlIO* f, callback, failure, args) either calls the callback of the functions of the layer f with the args, or if there is no such callback, sets errno to EINVAL. Or if the f is invalid, sets errno to EBADF and returns failure.

Perl_PerlIO_or_Base_void(PerlIO* f, callback, base, args) either calls the callback of the functions of the layer f with the args, or if there is no such callback, calls the base version of the callback with the same args, or if the f is invalid, sets errno to EBADF.

Perl_PerlIO_or_fail_void(PerlIO* f, callback, args) either calls the callback of the functions of the layer f with the args, or if there is no such callback, sets errno to EINVAL. Or if the f is invalid, sets errno to EBADF.

Implementing PerlIO Layers

If you find the implementation document unclear or not sufficient, look at the existing PerlIO layer implementations, which include:

  • C implementations

    The perlio.c and perliol.h in the Perl core implement the "unix", "perlio", "stdio", "crlf", "utf8", "byte", "raw", "pending" layers, and also the "mmap" and "win32" layers if applicable. (The "win32" is currently unfinished and unused, to see what is used instead in Win32, see "Querying the layers of filehandles" in PerlIO .)

    PerlIO::encoding, PerlIO::scalar, PerlIO::via in the Perl core.

    PerlIO::gzip and APR::PerlIO (mod_perl 2.0) on CPAN.

  • Perl implementations

    PerlIO::via::QuotedPrint in the Perl core and PerlIO::via::* on CPAN.

If you are creating a PerlIO layer, you may want to be lazy, in other words, implement only the methods that interest you. The other methods you can either replace with the "blank" methods

PerlIOBase_noop_ok
PerlIOBase_noop_fail

(which do nothing, and return zero and -1, respectively) or for certain methods you may assume a default behavior by using a NULL method. The Open method looks for help in the 'parent' layer. The following table summarizes the behavior:

   method      behaviour with NULL
   Clearerr    PerlIOBase_clearerr
   Close       PerlIOBase_close
   Dup         PerlIOBase_dup
   Eof         PerlIOBase_eof
   Error       PerlIOBase_error
   Fileno      PerlIOBase_fileno
   Fill        FAILURE
   Flush       SUCCESS
   Getarg      SUCCESS
   Get_base    FAILURE
   Get_bufsiz  FAILURE
   Get_cnt     FAILURE
   Get_ptr     FAILURE
   Open        INHERITED
   Popped      SUCCESS
   Pushed      SUCCESS
   Read        PerlIOBase_read
   Seek        FAILURE
   Set_cnt     FAILURE
   Set_ptrcnt  FAILURE
   Setlinebuf  PerlIOBase_setlinebuf
   Tell        FAILURE
   Unread      PerlIOBase_unread
   Write       FAILURE
FAILURE        Set errno (to EINVAL in Unixish, to LIB$_INVARG in VMS)
               and return -1 (for numeric return values) or NULL (for
               pointers)
INHERITED      Inherited from the layer below
SUCCESS        Return 0 (for numeric return values) or a pointer

Core Layers

The file "perlio.c" provides the following layers:

"unix"
A basic non-buffered layer which calls Unix/POSIX read(), write(), lseek(), close(). No buffering. Even on platforms that distinguish between O_TEXT and O_BINARY this layer is always O_BINARY.
"perlio"
A very complete generic buffering layer which provides the whole of PerlIO API. It is also intended to be used as a "base class" for other layers. (For example, its Read() method is implemented in terms of the Get_cnt()/Get_ptr()/Set_ptrcnt() methods).

"perlio" over "unix" provides a complete replacement for stdio as seen via the PerlIO API. This is the default for USE_PERLIO when the system's stdio does not permit Perl's "fast gets" access, and which do not distinguish between "O_TEXT" and "O_BINARY".

"stdio"
A layer which provides the PerlIO API via the layer scheme, but implements it by calling the system's stdio. This is (currently) the default if the system's stdio provides sufficient access to allow Perl's "fast gets" access and which do not distinguish between "O_TEXT" and "O_BINARY".
"crlf"
A layer derived using "perlio" as a base class. It provides Win32-like "\n" to CR,LF translation. Can either be applied above "perlio" or serve as the buffer layer itself. "crlf" over "unix" is the default if the system distinguishes between "O_TEXT" and "O_BINARY" opens. (At some point "unix" will be replaced by a "native" Win32 IO layer on that platform, as Win32's read/write layer has various drawbacks.) The "crlf" layer is a reasonable model for a layer which transforms data in some way.
"mmap"
If Configure detects mmap() functions, this layer is provided (with "perlio" as a "base") which does "read" operations by
y mmap() en utilisant un fichier. L'amélioration des performances est marginale sur les systèmes modernes, elle est donc principalement présente comme une preuve de concept. Elle sera probablement retirée du cœur à un moment donné. La couche "mmap" est un modèle raisonnable pour une couche "dérivée" minimaliste.
"pending"
Un dérivé "interne" de "perlio" qui peut être utilisé pour fournir la fonction Unread() pour les couches qui n'ont pas de tampon ou qui ne veulent pas s'en occuper. (Fondamentalement, la Fill() de cette couche se retire de la pile et reprend donc la lecture de la couche inférieure.)
"raw"
Une couche factice qui n'existe jamais sur la pile de couches. Au lieu de cela, lorsqu'elle est "poussée", elle retire en fait la pile en se retirant elle-même, puis elle appelle l'entrée de la table de fonctions Binmode sur toutes les couches de la pile - normalement, cela (via PerlIOBase_binmode) retire toutes les couches qui n'ont pas le bit "PERLIO_K_RAW" défini. Les couches peuvent modifier ce comportement en définissant leur propre entrée Binmode.
"utf8"
Une autre couche factice. Lorsqu'elle est poussée, elle se retire et définit le drapeau "PERLIO_F_UTF8" sur la couche qui était (et est redevenue) le sommet de la pile.

En outre, perlio.c fournit un certain nombre de fonctions PerlIOBase_xxxx() qui sont destinées à être utilisées dans les emplacements de table des classes qui n'ont pas besoin de faire quoi que ce soit de spécial pour une méthode particulière.

Couches d'extension

Les couches peuvent être rendues disponibles par des modules d'extension. Lorsqu'une couche inconnue est rencontrée, le code PerlIO effectuera l'équivalent de :

use PerlIO 'layer';

où layer est la couche inconnue. PerlIO.pm tentera alors de :

require PerlIO::layer;

Si, après ce processus, la couche n'est toujours pas définie, alors l'"open" échouera.

Les couches d'extension suivantes sont incluses avec perl :

":encoding"
use Encoding;

rend cette couche disponible, bien que PerlIO.pm "sache" où la trouver. C'est un exemple de couche qui prend un argument car elle est appelée ainsi :

open( $fh, "<:encoding(iso-8859-7)", $pathname );
":scalar"
Fournit la prise en charge de la lecture de données à partir d'un scalaire et de l'écriture de données dans celui-ci. 
open( $fh, "+<:scalar", \$scalar );

Lorsqu'un descripteur est ouvert ainsi, les lectures obtiennent des octets à partir de la valeur de chaîne de $scalar, et les écritures modifient la valeur. Dans les deux cas, la position dans $scalar commence à zéro mais peut être modifiée via "seek" et déterminée via "tell".

Veuillez noter que cette couche est implicite lors de l'appel de open() ainsi :

open( $fh, "+<", \$scalar );
":via"
Fourni pour permettre l'implémentation des couches sous forme de code Perl. Par exemple : 
use PerlIO::via::StripHTML;
open( my $fh, "<:via(StripHTML)", "index.html" );

Voir PerlIO::via pour les détails.
