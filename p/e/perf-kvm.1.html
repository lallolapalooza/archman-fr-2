NOM

perf-kvm - Outil pour tracer/mesurer le système d'exploitation invité KVM

SYNTAXE

perf kvm [--host] [--guest] [--guestmount=<chemin>
        [--guestkallsyms=<chemin> --guestmodules=<chemin> | --guestvmlinux=<chemin>]]
        {top|record|report|diff|buildid-list} [<options>]
perf kvm [--host] [--guest] [--guestkallsyms=<chemin> --guestmodules=<chemin>
        | --guestvmlinux=<chemin>] {top|record|report|diff|buildid-list|stat} [<options>]
'perf kvm stat [record|report|live] [<options>]

DESCRIPTION

Il existe plusieurs variantes de perf kvm :

'perf kvm [options] top <commande>' pour générer et afficher un profil de
compteurs de performance du système d'exploitation invité en temps réel
d'une charge de travail arbitraire.
'perf kvm record <commande>' pour enregistrer le profil des compteurs de
performance d'une charge de travail arbitraire et le sauvegarder dans un
fichier de données perf. Nous définissons le comportement par défaut de perf
kvm comme étant --guest, donc si ni --host ni --guest ne sont entrés, le nom
du fichier de données perf est perf.data.guest. Si --host est entré, le nom du
fichier de données perf est perf.data.kvm. Si vous souhaitez enregistrer des
données dans perf.data.host, veuillez entrer --host --no-guest. Les
comportements sont indiqués comme suit :
  Défaut('')         ->  perf.data.guest
  --host              ->  perf.data.kvm
  --guest             ->  perf.data.guest
  --host --guest      ->  perf.data.kvm
  --host --no-guest   ->  perf.data.host
'perf kvm report' pour afficher les informations de profil des compteurs de
performance enregistrées via perf kvm record.
'perf kvm diff' pour afficher la différence de performance entre deux fichiers
perf.data capturés via perf record.
'perf kvm buildid-list' pour afficher les buildids trouvés dans un fichier de
données perf, afin que d'autres outils puissent être utilisés pour récupérer
les paquets avec des tables de symboles correspondantes à utiliser par perf
report. Comme les buildid sont lus depuis /sys/kernel/notes dans le système
d'exploitation, si vous souhaitez lister les buildid pour l'invité, assurez-vous
que votre fichier de données perf a été capturé avec --guestmount dans perf
kvm record.
'perf kvm stat <commande>' pour exécuter une commande et collecter des
statistiques de compteurs de performance.
Plus spécifiquement, perf 'kvm stat record/report' génère une analyse
statistique des événements KVM. Actuellement, les événements vmexit, mmio (x86
seulement) et ioport (x86 seulement) sont pris en charge. 'perf kvm stat
record <commande>' enregistre les événements kvm et les événements entre le
début et la fin de <commande>.
Et cette commande produit un fichier contenant les résultats de traçage des
événements kvm.
'perf kvm stat report' rapporte des données statistiques qui incluent les
échantillons d'événements gérés, le pourcentage d'échantillons, le temps,
le pourcentage de temps, max_t, min_t, mean_t.
'perf kvm stat live' rapporte des données statistiques en mode live (similaire
à record + report mais avec des données statistiques mises à jour en direct
à un rythme d'affichage donné).

OPTIONS

-i, --input=<chemin>

Nom du fichier d'entrée, pour les sous-commandes report, diff et buildid-list.

-o, --output=<chemin>

Nom du fichier de sortie, pour la sous-commande record. Ne fonctionne pas avec report, redirigez simplement la sortie vers un fichier lors de l'utilisation de report.

--host

Collecter le profil de performance côté hôte.

--guest

Collecter le profil de performance côté invité.

--guestmount=<chemin>

Répertoire de montage du système de fichiers racine du SE invité. Les utilisateurs montent les répertoires racine des SE invités sous <chemin> par une méthode d'accès spécifique au système de fichiers, typiquement, sshfs. Par exemple, démarrez 2 SE invités, dont les PID sont 8888 et 9999 : 
$ mkdir ~/guestmount
$ cd ~/guestmount
$ sshfs -o allow_other,direct_io -p 5551 localhost:/ 8888/
$ sshfs -o allow_other,direct_io -p 5552 localhost:/ 9999/
$ perf kvm --host --guest --guestmount=~/guestmount top

--guestkallsyms=<chemin>

Copie du fichier /proc/kallsyms du SE invité. perf le lit pour obtenir les symboles du noyau invité. Les utilisateurs le copient depuis le SE invité.

--guestmodules=<chemin>

Copie du fichier /proc/modules du SE invité. perf le lit pour obtenir les informations des modules du noyau invité. Les utilisateurs le copient depuis le SE invité.

--guestvmlinux=<chemin>

Vmlinux du noyau du SE invité.

--guest-code

Indique que le code invité peut être trouvé dans le processus de l'hyperviseur, ce qui est un cas courant pour les programmes de test KVM.

--stdio

Utiliser l'interface stdio.

-v, --verbose

Être plus verbeux (afficher les erreurs d'ouverture de compteur, etc.).

OPTIONS STAT REPORT

--vcpu=<valeur>

analyser les événements qui se produisent sur ce vcpu. (par défaut : tous les vcpus)

--event=<valeur>

événement à analyser. Valeurs possibles : vmexit, mmio (x86 seulement), ioport (x86 seulement). (par défaut : vmexit)

-k, --key=<valeur>

Clé de tri. Valeurs possibles : sample (par défaut, tri par nombre d'échantillons), percent_sample (tri par pourcentage d'échantillons), time (tri par temps moyen), precent_time (tri par pourcentage de temps), max_t (tri par temps maximum), min_t (tri par temps minimum), mean_t (tri par temps moyen).

-p, --pid=

Analyser les événements uniquement pour l'ID de processus (liste séparée par des virgules) donné.

OPTIONS STAT LIVE

-d, --display

Temps en secondes entre les mises à jour de l'affichage

-m, --mmap-pages=

Nombre de pages de données mmap (doit être une puissance de deux) ou spécification de taille en octets avec une unité ajoutée - B/K/M/G. La taille est arrondie à la puissance de deux pages la plus proche.

-a, --all-cpus

Collecte système à partir de tous les CPU.

-p, --pid=

Analyser les événements uniquement pour l'ID de processus (liste séparée par des virgules) donné.

--vcpu=<valeur>

analyser les événements qui se produisent sur ce vcpu. (par défaut : tous les vcpus)

--event=<valeur>

événement à analyser. Valeurs possibles : vmexit, mmio (x86 seulement), ioport (x86 seulement). (par défaut : vmexit)

-k, --key=<valeur>

Clé de tri. Valeurs possibles : sample (par défaut, tri par échantillons), time (tri par temps moyen).

--duration=<valeur>

Afficher les événements autres que HLT (x86 seulement) ou Wait state (s390 seulement) qui prennent plus de durée microsecondes.

--proc-map-timeout

Lors du traitement des threads préexistants /proc/XXX/mmap, cela peut prendre beaucoup de temps, car le fichier peut être énorme. Un délai d'attente est nécessaire dans de tels cas. Cette option définit la limite de délai d'attente. La valeur par défaut est 500 ms.
