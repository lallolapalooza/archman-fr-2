NOM

perl5160delta - Nouveautés pour la version Perl v5.16.0

DESCRIPTION

Ce document décrit les différences entre la version 5.14.0 et la version 5.16.0.

Si vous mettez à jour depuis une version antérieure comme la 5.12.0, lisez d'abord perl5140delta, qui décrit les différences entre la 5.12.0 et la 5.14.0.

Certaines corrections de bugs dans cette version ont été rétroportées vers des versions ultérieures de la série 5.14.x. Celles-ci sont indiquées par la version 5.14.x entre parenthèses.

Remarque

Avec la sortie de Perl 5.16.0, la série de versions 5.12.x n'est plus supportée. Il pourra y avoir de futures versions 5.12.x, mais uniquement en cas de problème de sécurité critique. Les utilisateurs de Perl 5.12 ou antérieur devraient envisager de passer à une version plus récente de Perl.

Cette politique est décrite plus en détail dans perlpolicy.

Améliorations du cœur

"use VERSION"

À partir de cette version, les déclarations de version telles que "use v5.16" désactivent toutes les fonctionnalités avant d'activer le nouveau paquet de fonctionnalités. Cela signifie que ce qui suit est vrai :

use 5.016;
# seulement les fonctionnalités 5.16 activées ici
use 5.014;
# seulement les fonctionnalités 5.14 activées ici (pas 5.16)

"use v5.12" et supérieur continuent d'activer strict, mais "use strict" et "no strict" explicites outrepassent maintenant la déclaration de version, même lorsqu'ils viennent en premier :

no strict;
use 5.012;
# pas de strict ici

Il existe un nouveau paquet de fonctionnalités ":default" qui représente l'ensemble des fonctionnalités activées avant toute déclaration de version ou "use feature". Les déclarations de version inférieures à 5.10 activent maintenant l'ensemble de fonctionnalités ":default". Cela ne change pas réellement le comportement de "use v5.8", car les fonctionnalités ajoutées à l'ensemble ":default" sont celles qui étaient traditionnellement activées par défaut, avant de pouvoir être désactivées.

"no feature" réinitialise maintenant à l'ensemble de fonctionnalités par défaut. Pour désactiver toutes les fonctionnalités (ce qui sera probablement une demande très spécifique, car cela ne correspondra sans doute à aucun ensemble de sémantiques nommées) vous pouvez maintenant écrire "no feature ':all'".

$[ est maintenant désactivé sous "use v5.16". Il fait partie de l'ensemble de fonctionnalités par défaut et peut être activé ou désactivé explicitement avec use feature 'array_base'.

"__SUB__"

Le nouveau jeton "__SUB__", disponible sous la fonctionnalité "current_sub" (voir feature) ou "use v5.16", renvoie une référence à la sous-routine courante, facilitant l'écriture de fermetures récursives.

Built-ins nouveaux et améliorés

Evaluations "eval" plus cohérentes

L'opérateur "eval" traite parfois un argument de chaîne comme une séquence de caractères et parfois comme une séquence d'octets, en fonction de l'encodage interne. L'encodage interne n'est pas censé faire de différence, mais il existe du code qui repose sur cette incohérence.

Les nouvelles fonctionnalités "unicode_eval" et "evalbytes" (activées sous use 5.16.0) résolvent cela. La fonctionnalité "unicode_eval" fait que eval $string traite la chaîne toujours comme de l'Unicode. La fonctionnalité "evalbytes" fournit une fonction, appelée elle-même "evalbytes", qui évalue son argument toujours comme une chaîne d'octets.

Ces fonctionnalités corrigent également des bizarreries où les filtres source fuyaient vers les portées dynamiques externes.

Voir feature pour plus de détails.

Refonte des lvalues de "substr"

Lorsque "substr" est appelée dans un contexte lvalue ou lvaleur potentielle avec deux ou trois arguments, un scalaire lvalue spécial est retourné qui modifie la chaîne d'origine (le premier argument) lorsqu'il est assigné.

Auparavant, les décalages (le deuxième et le troisième arguments) passés à "substr" étaient immédiatement convertis pour correspondre à la chaîne, les décalages négatifs étant traduits en positifs et les décalages au-delà de la fin de la chaîne étant tronqués.

Désormais, les décalages sont enregistrés sans modification dans le scalaire lvalue spécial qui est retourné, et la chaîne d'origine n'est même pas examinée par "substr" lui-même, mais seulement lorsque l'lvalue retournée est lue ou modifiée.

Ces changements entraînent un changement incompatible :

Si la chaîne d'origine change de longueur après l'appel à "substr" mais avant l'assignation à sa valeur de retour, les décalages négatifs se souviendront de leur position à partir de la fin de la chaîne, affectant le code comme ceci :

my $string = "string";
my $lvalue = \substr $string, -4, 2;
print $$lvalue, "\n"; # affiche "ri"
$string = "bailing twine";
print $$lvalue, "\n"; # affiche "wi"; affichait "il"

La même chose se produit avec un troisième argument omis. L'lvalue retournée s'étendra toujours jusqu'à la fin de la chaîne, même si la chaîne devient plus longue.

Comme ce changement a également permis de corriger de nombreux bugs (voir "L'opérateur "substr""), et comme le comportement des décalages négatifs n'a jamais été spécifié, le changement a été jugé acceptable.

Valeur de retour de "tied"

La valeur retournée par "tied" sur une variable liée est maintenant le scalaire réel qui contient l'objet auquel la variable est liée. Cela permet d'affaiblir les liens avec "Scalar::Util::weaken(tied $tied_variable)".

Support Unicode

Supporte (presque) Unicode 6.1

Outre l'ajout de scripts entièrement nouveaux et de caractères nouveaux dans les scripts existants, cette nouvelle version d'Unicode, comme toujours, apporte quelques changements aux caractères existants. Un changement qui peut poser problème à certaines applications est que la Catégorie Générale de deux caractères dans la plage Latin-1, SYMBOLE PILCROW et SYMBOLE SECTION, a été changée de Other_Symbol à Other_Punctuation. Le même changement a été apporté à un caractère dans chacun des systèmes tibétain, éthiopien et égéen. Les points de code U+3248..U+324F (NOMBRE CERCLE DIX SUR FOND NOIR à NOMBRE CERCLE quatre-vingt SUR FOND NOIR) ont vu leur Catégorie Générale changée de Other_Symbol à Other_Numeric. La propriété de saut de ligne a des changements pour l'hébreu et le japonais ; et en raison d'autres changements dans la version 6.1, la construction d'expression régulière Perl "\X" fonctionne maintenant différemment pour certains caractères en thaï et en lao.

De nouveaux alias (synonymes) ont été définis pour de nombreuses valeurs de propriétés ; ceux-ci, ainsi que ceux qui existaient auparavant, sont tous indexés de manière croisée dans perluniprops.

La valeur de retour de charnames::viacode() est affectée par d'autres changements :

Point de code    Ancien Nom             Nouveau Nom
  U+000A    SAUT DE LIGNE (LF)        SAUT DE LIGNE
  U+000C    SAUT DE PAGE (FF)        SAUT DE PAGE
  U+000D    RETOUR CHARIOT (CR)  RETOUR CHARIOT
  U+0085    SAUT DE LIGNE SUIVANT (NEL) SAUT DE LIGNE SUIVANT
  U+008E    SINGLE-SHIFT 2        SINGLE-SHIFT-2
  U+008F    SINGLE-SHIFT 3        SINGLE-SHIFT-3
  U+0091    PRIVATE USE 1         PRIVATE USE-1
  U+0092    PRIVATE USE 2         PRIVATE USE-2
  U+2118    P CAPITALE SCRIPT     FONCTION ELLIPTIQUE DE WEIERSTRASS

Perl acceptera n'importe lequel de ces noms en entrée, mais charnames::viacode() retourne maintenant le nouveau nom de chaque paire. Le changement pour U+2118

est considéré par Unicode comme une correction, c'est-à-dire que le nom d'origine était une erreur (mais encore une fois, il restera à jamais valide de l'utiliser pour faire référence à U+2118). Mais la plupart de ces changements sont la conséquence de l'erreur commise par Unicode 6.0 en nommant un caractère utilisé dans les téléphones portables japonais "BELL", ce qui entre en conflit avec l'utilisation de longue date dans l'industrie (et la recommandation d'Unicode d'utiliser) ce nom pour désigner le caractère de contrôle ASCII à U+0007. Par conséquent, ce nom est obsolète dans Perl depuis la v5.14, et toute utilisation de celui-ci provoquera un message d'avertissement (sauf s'il est désactivé). Le nom "ALERT" est maintenant le nom préféré pour ce point de code, avec "BEL" comme forme courte acceptable. Le nom du nouveau caractère de téléphone portable, au point de code U+1F514, reste indéfini dans cette version de Perl (nous n'implémentons donc pas entièrement Unicode 6.1), mais à partir de la v5.18, BELL désignera ce caractère, et non U+0007.

Unicode a pris des mesures pour s'assurer que ce genre d'erreur ne se reproduise plus. La norme inclut désormais tous les noms et abréviations généralement acceptés pour les caractères de contrôle, alors qu'auparavant ce n'était pas le cas (bien qu'il y ait eu des noms recommandés pour la plupart d'entre eux, que Perl utilisait). Cela signifie que la plupart de ces noms recommandés font désormais officiellement partie de la norme. Unicode n'avait pas recommandé de noms pour les quatre points de code listés ci-dessus entre U+008E et U+008F, et en les standardisant, Unicode a subtilement modifié les noms que Perl leur avait précédemment donnés, en remplaçant l'espace final dans chaque nom par un tiret. Unicode accepte également officiellement les noms que Perl avait dépréciés, tels que FILE SEPARATOR. Désormais, seul le nom BELL est déprécié. Enfin, Perl utilise désormais les nouveaux noms officiels au lieu des anciens noms (désormais considérés comme obsolètes) pour les quatre premiers points de code de la liste ci-dessus (ceux qui contiennent des parenthèses).

Maintenant que les noms ont été intégrés dans la norme Unicode, ces types de changements ne devraient plus se produire, bien que des corrections, comme pour U+2118, soient toujours possibles.

Unicode a également ajouté quelques abréviations de noms, que Perl accepte désormais : SP pour SPACE ; TAB pour CHARACTER TABULATION ; NEW LINE, END OF LINE, NL, et EOL pour LINE FEED ; LOCKING-SHIFT ONE pour SHIFT OUT ; LOCKING-SHIFT ZERO pour SHIFT IN ; et ZWNBSP pour ZERO WIDTH NO-BREAK SPACE.

Plus de détails sur cette version d'Unicode sont disponibles sur http://www.unicode.org/versions/Unicode6.1.0/.

"use charnames" n'est plus nécessaire pour "\N{name}"

Lorsque "\N{nom}" est rencontré, le module "charnames" est désormais chargé automatiquement lorsque nécessaire, comme si les options ":full" et ":short" avaient été spécifiées. Voir charnames pour plus d'informations.

"\N{...}" peut maintenant utiliser la mise en correspondance souple des noms Unicode

Ceci est décrit dans l'élément "charnames" de la section "Modules et Pragmata mis à jour" ci-dessous.

Noms des symboles Unicode

Perl prend désormais en charge correctement les noms Unicode dans les noms de symboles. Auparavant, "*{$foo}" ignorait le drapeau UTF8 interne et utilisait les octets de la représentation sous-jacente pour rechercher le symbole. Cela signifiait que "*{"\x{100}"}" et "*{"\xc4\x80"}" renvoyaient la même chose. Toutes ces parties de Perl ont été corrigées pour tenir compte de Unicode :

  • Noms de méthodes (y compris ceux passés à "use overload")
  • Noms de globes de type (y compris les noms de variables, de sous-programmes et de descripteurs de fichiers)
  • Noms de paquets
  • "goto"
  • Déréférencement symbolique
  • Deuxième argument de bless() et tie()
  • Valeur de retour de ref()
  • Prototypes de sous-programmes
  • Attributs
  • Divers avertissements et messages d'erreur mentionnant des noms de variables ou des valeurs, des méthodes, etc.

De plus, un bug d'analyse syntaxique a été corrigé qui empêchait "*{é}" de mettre implicitement le nom entre guillemets, mais l'interprétait comme "*{+é}", ce qui provoquait une violation stricte.

"*{"*a::b"}" supprime automatiquement l'astérisque s'il est suivi d'une lettre ASCII. Ceci a été étendu à tous les caractères d'identifiant Unicode.

Les variables à caractère unique non ASCII et non ponctuelles (comme $é) sont désormais soumises aux avertissements "Utilisé une seule fois". Elles étaient auparavant exemptées, car elles étaient traitées comme des variables ponctuelles.

En outre, les variables ponctuelles Unicode à caractère unique (comme $‰) sont désormais prises en charge [perl #69032].

Amélioration de la capacité à mélanger les locales et Unicode, y compris les locales UTF-8

Un paramètre optionnel a été ajouté à "use locale"

use locale ':not_characters';

qui indique à Perl d'utiliser toutes les parties de la locale actuelle, à l'exception de "LC_CTYPE" et "LC_COLLATE". À la place, le jeu de caractères est supposé être Unicode. Cela permet de mélanger de manière transparente les locales et Unicode, y compris les locales UTF-8 de plus en plus fréquentes. Lors de l'utilisation de cette forme hybride de locales, la couche ":locale" de la pragma open peut être utilisée pour interagir avec le système de fichiers, et des modules CPAN sont disponibles pour les conversions d'ARGV et de variables d'environnement.

Tous les détails se trouvent dans perllocale.

Nouvelle fonction "fc" et séquence d'échappement correspondante "\F" pour la mise en casse Unicode

La mise en casse Unicode est une extension de la mise en minuscule qui donne de meilleurs résultats lors de la comparaison de deux chaînes de caractères sans tenir compte de la casse. Elle est utilisée depuis longtemps en interne dans la mise en correspondance des expressions régulières avec le modificateur "/i". Désormais, elle est explicitement disponible via le nouvel appel de fonction "fc" (activé par "use feature 'fc'", ou "use v5.16", ou appelable explicitement via "CORE::fc") ou via la nouvelle séquence "\F" dans les chaînes entre guillemets doubles.

Tous les détails se trouvent dans "fc" dans perlfunc.

La propriété Unicode "Script_Extensions" est désormais prise en charge

Nouvelle dans Unicode 6.0, il s'agit d'une propriété "Script" améliorée. Les détails se trouvent dans "Scripts" dans perlunicode.

Changements XS

Amélioration des typemaps pour certains types intégrés

La plupart des auteurs XS connaissent un bug de longue date dans le typemap OUTPUT pour T_AVREF ("AV*"), T_HVREF ("HV*"), T_CVREF ("CV*"), et T_SVREF ("SVREF" ou "\$foo") qui nécessite de décrémenter manuellement le compteur de références de la valeur de retour au lieu que le typemap s'en occupe. Pour des raisons de compatibilité ascendante, cela ne peut pas être modifié dans les typemaps par défaut. Mais nous fournissons maintenant des typemaps supplémentaires "T_AVREF_REFCOUNT_FIXED", etc. qui n'ont pas ce bug. Leur utilisation dans votre extension est aussi simple que d'avoir une ligne dans votre section "TYPEMAP" :

HV*   T_HVREF_REFCOUNT_FIXED

is_utf8_char()

La fonction appelable en XS is_utf8_char(), lorsqu'elle reçoit une entrée UTF-8 malformée, peut lire jusqu'à 12 octets au-delà de la fin de la chaîne. Cela ne peut pas être corrigé sans modifier son API, et donc son utilisation est désormais dépréciée. Utilisez plutôt is_utf8_char_buf() (décrit juste ci-dessous).

Ajout de is_utf8_char_buf()

Cette fonction est conçue pour remplacer la fonction dépréciée "is_utf8_char()". Elle inclut un paramètre supplémentaire pour s'assurer qu'elle ne lit pas au-delà de la fin du tampon d'entrée.

Autres fonctions is_utf8_foo(), ainsi que utf8_to_foo(), etc.

La plupart des autres fonctions appelables en XS qui acceptent une entrée encodée en UTF-8 supposent implicitement que l'UTF-8 est valide (non malformé) par rapport à la longueur du tampon. Ne faites pas de choses comme changer la casse d'un caractère ou vérifier s'il est alphanumérique sans être d'abord sûr qu'il s'agit d'un UTF-8 valide. Cela peut être fait en toute sécurité pour une chaîne entière en utilisant l'une des fonctions is_utf8_string(), is_utf8_string_loc(), et is_utf8_string_loclen().

Nouvel API de Pad

De nombreuses nouvelles fonctions ont été ajoutées à l'API pour manipuler les pads lexicaux. Voir "Pad Data Structures" dans perlapi pour plus d'informations.

Changements des variables spéciales

$$ peut être assigné

$$ a été rendu en lecture seule dans Perl 5.8.0. Mais seulement parfois : "local $$" le rendait à nouveau inscriptible. Certains modules CPAN utilisaient "local $$" ou du code XS pour contourner la vérification en lecture seule, il n'y a donc aucune raison de garder $$ en lecture seule. (Ce changement a également permis de corriger un bug tout en maintenant la compatibilité ascendante.)

$^X converti en chemin absolu sur FreeBSD, OS X et Solaris

$^X est maintenant converti en chemin absolu sur OS X, FreeBSD (sans nécessiter le montage de /proc) et Solaris 10 et 11. Cela complète l'approche précédente utilisant /proc sur Linux, FreeBSD et NetBSD (dans tous les cas, là où il est monté).

Cela rend les installations Perl déplaçables plus utiles sur ces plateformes. (Voir "Relocatable @INC" dans INSTALL)

Changements du débogueur

Fonctionnalités à l'intérieur du débogueur

Le Perl actuel

Nouvelles Fonctionnalités

Les regroupements de fonctionnalités sont maintenant activés pour les commandes saisies dans le débogueur interactif

Nouvelle option pour la commande t du débogueur

La commande t du débogueur, qui active/désactive le mode de traçage, accepte maintenant un argument numérique qui détermine le nombre de niveaux d'appels de sous-routines à tracer.

"enable" et "disable"

Le débogueur dispose maintenant des commandes "disable" et "enable" pour désactiver les points d'arrêt existants et les réactiver. Voir perldebug.

Points d'arrêt avec noms de fichiers

La commande "b" du débogueur pour définir des points d'arrêt permet maintenant de préfixer un numéro de ligne avec un nom de fichier. Voir "b [file]:[line] [condition]" dans perldebug.

L'espace de noms "CORE"

Le préfixe "CORE::"

Le préfixe "CORE::" peut maintenant être utilisé sur les mots-clés activés par feature.pm, même en dehors de la portée de "use feature".

Sous-routines dans l'espace de noms "CORE"

De nombreux mots-clés Perl sont maintenant disponibles sous forme de sous-routines dans l'espace de noms CORE. Cela permet de les aliaser :

BEGIN { *entangle = \&CORE::tie }
entangle $variable, $package, @args;

Et pour contourner les prototypes :

sub mytie(\[%$*@]$@) {
    my ($ref, $pack, @args) = @_;
    ... faire quelque chose ...
    goto &CORE::tie;
}

Certains de ceux-ci ne peuvent pas être appelés via des références ou via la syntaxe &foo, mais doivent être appelés comme des mots vides (barewords).

Voir CORE pour plus de détails.

Autres Modifications

Descripteurs de fichiers anonymes

Les descripteurs de fichiers générés automatiquement sont maintenant nommés __ANONIO__ lorsque le nom de la variable ne peut pas être déterminé, au lieu de $___ANONIO__.

Sous-routines de tri chargées automatiquement

Les sous-routines de tri personnalisées peuvent maintenant être chargées automatiquement [perl #30661] :

sub AUTOLOAD { ... }
@sorted = sort foo @list; # utilise AUTOLOAD

"continue" ne nécessite plus la fonctionnalité "switch"

Le mot-clé "continue" a deux significations. Il peut introduire un bloc "continue" après une boucle, ou il peut sortir du bloc "when" courant. Jusqu'à présent, cette dernière signification n'était valide qu'avec la fonctionnalité "switch" activée, et était une erreur de syntaxe sinon. Étant donné que le but principal de feature.pm est d'éviter les conflits avec les sous-routines définies par l'utilisateur, il n'y a aucune raison pour que "continue" en dépende.

Sondes DTrace pour le changement de phase de l'interpréteur

Les sondes "phase-change" seront déclenchées lorsque la phase de l'interpréteur changera, ce qui suit la variable "${^GLOBAL_PHASE}". "arg0" est le nouveau nom de phase ; "arg1" est l'ancien. Ceci est utile pour limiter votre instrumentation à une ou plusieurs des phases suivantes : compilation, exécution ou destruction.

Syntaxe "__FILE__()"

Les jetons "__FILE__", "__LINE__" et "__PACKAGE__" peuvent maintenant être écrits avec une paire de parenthèses vides après eux. Cela les fait analyser de la même manière que "time", "fork" et d'autres fonctions intégrées.

Le prototype "\$" accepte n'importe quelle lvalue scalaire

Les prototypes de sous-routines "\$" et "\[$]" acceptent maintenant n'importe quel argument lvaleur scalaire. Auparavant, ils n'acceptaient que les scalaires commençant par "$" ainsi que les éléments de hachage et de tableau. Ce changement les rend cohérents avec la façon dont les fonctions intégrées "read" et "recv" (entre autres) analysent leurs arguments. Cela signifie que l'on peut remplacer les fonctions intégrées par des sous-routines personnalisées qui analysent leurs arguments de la même manière.

Le caractère "_" dans les prototypes de sous-routines

Le caractère "_" dans les prototypes de sous-routines est maintenant autorisé avant "@" ou "%".

Sécurité

Utilisez is_utf8_char_buf() et non is_utf8_char()

Cette dernière fonction est maintenant dépréciée car son API est insuffisante pour garantir qu'elle ne lit pas (jusqu'à 12 octets dans le pire des cas) au-delà de la fin de sa chaîne d'entrée. Voir is_utf8_char_buf().

Une entrée UTF-8 malformée pourrait provoquer des tentatives de lecture au-delà de la fin du tampon

Deux nouvelles fonctions accessibles depuis XS, utf8_to_uvchr_buf() et utf8_to_uvuni_buf() sont maintenant disponibles pour prévenir cela, et le cœur de Perl a été converti pour les utiliser. Voir "Changements Internes".

Erreur de mémoire de File::Glob::bsd_glob() avec GLOB_ALTDIRFUNC (CVE-2011-2728)

Appeler "File::Glob::bsd_glob" avec le drapeau non supporté GLOB_ALTDIRFUNC provoquait une violation d'accès / un segfault. Un programme Perl qui accepte une valeur de drapeaux provenant d'une source externe pourrait s'exposer à des attaques par déni de service ou par exécution de code arbitraire. Il n'y a pas d'exploits connus dans la nature. Le problème a été corrigé en désactivant explicitement tous les drapeaux non supportés et en mettant à null les pointeurs de fonction inutilisés. Bug rapporté par Clément Lecigne. (5.14.2)

Les privilèges sont maintenant définis correctement lors de l'affectation à $(

Un bug hypothétique (probablement non exploitable en pratique) en raison du réglage incorrect de l'ID de groupe effectif lors du réglage de $( a été corrigé. Le bug n'aurait affecté que les systèmes disposant de setresgid() mais pas de setregid(), mais aucun système de ce type n'est connu pour exister.

Dépréciations

Ne lisez pas les fichiers de base de données Unicode dans lib/unicore

Il est maintenant déconseillé de lire directement les fichiers de base de données Unicode. Ceux-ci sont stockés dans le répertoire lib/unicore. Au lieu de cela, vous devriez utiliser les nouvelles fonctions de Unicode::UCD. Celles-ci fournissent une API stable et donnent des informations complètes.

Perl pourrait à un moment donné dans le futur modifier ou supprimer ces fichiers. Le fichier que les applications étaient les plus susceptibles d'utiliser était lib/unicore/ToDigit.pl. "prop_invmap()" dans Unicode::UCD peut être utilisé pour accéder à ses données à la place.

Fonctions XS is_utf8_char(), utf8_to_uvchr() et utf8_to_uvuni()

Cette fonction est dépréciée car elle pouvait lire au-delà de la fin de la chaîne d'entrée. Utilisez plutôt les nouvelles fonctions is_utf8_char_buf(), utf8_to_uvchr_buf() et utf8_to_uvuni_buf().

Changements incompatibles

Blocs spéciaux appelés dans un contexte void

Les blocs spéciaux (BEGIN, CHECK, INIT, UNITCHECK, END) sont maintenant appelés dans un contexte void. Cela évite une copie coûteuse du résultat de la dernière instruction [perl #108794].

Le pragma "overloading" et les objets regexp

Avec no overloading, les objets d'expression régulière retournés par qr// sont maintenant sérialisés en chaîne de caractères comme "Regexp=REGEXP(0xbe600d)" au lieu de l'expression régulière elle-même [perl #108780].

Deux entrées de typemap XS supprimées

Deux entrées de typemap XS vraisemblablement inutilisées ont été supprimées du typemap principal : T_DATAUNIT et T_CALLBACK. Si vous êtes, contre toute attente, un utilisateur de ces entrées, veuillez consulter les instructions sur la façon de les restaurer dans perlxstypemap.

Unicode 6.1 présente des incompatibilités avec Unicode 6.0

Ces incompatibilités sont détaillées dans la section "Supporte (presque) Unicode 6.1" ci-dessus. Vous pouvez compiler cette version de Perl pour utiliser Unicode 6.0. Voir "Hacking Perl to work on earlier Unicode versions (for very serious hackers only)" dans perlunicode.

Compilateur Borland

Tout support pour le compilateur Borland a été abandonné. Le code ne fonctionnait de toute façon plus depuis longtemps.

Certaines propriétés Unicode obsolètes ne sont plus supportées par défaut

Perl n'aurait jamais dû exposer certaines propriétés Unicode qui sont utilisées par Unicode en interne et qui ne sont pas destinées à être accessibles publiquement. L'utilisation de ces propriétés a généré des messages d'avertissement obsolètes depuis Perl 5.12. Les propriétés supprimées sont Other_Alphabetic, Other_Default_Ignorable_Code_Point, Other_Grapheme_Extend, Other_ID_Continue, Other_ID_Start, Other_Lowercase, Other_Math et Other_Uppercase.

Perl peut être recompilé pour inclure une ou toutes ces propriétés ; des instructions sont données dans la section "Unicode character properties that are NOT accepted by Perl" de perluniprops.

Déréférencement des objets IO comme des typeglobs

L'opérateur *{...}, lorsqu'il reçoit une référence à un objet IO (comme dans *{*STDIN{IO}}), crée un nouveau typeglob contenant uniquement cet objet IO. Auparavant, il était sérialisé en chaîne vide, mais certains opérateurs le traitaient comme indéfini, produisant un avertissement "uninitialized". Il est maintenant sérialisé en __ANONIO__ [perl #96326].

Opérations de changement de cas définies par l'utilisateur

Cette fonctionnalité a été dépréciée dans Perl 5.14 et a maintenant été supprimée. Le module CPAN Unicode::Casing fournit des fonctionnalités améliorées sans les inconvénients que cette fonctionnalité présentait, comme détaillé dans la documentation de la version 5.14 : http://perldoc.perl.org/5.14.0/perlunicode.html#User-Defined-Case-Mappings-%28for-serious-hackers-only%29

Les XSUBs sont maintenant 'static'

Les fonctions C XSUB sont maintenant 'static', c'est-à-dire qu'elles ne sont pas visibles de l'extérieur de l'unité de compilation. Les utilisateurs peuvent utiliser les nouvelles macros XS_EXTERNAL(name) et XS_INTERNAL(name) pour choisir le comportement de liaison souhaité. La déclaration ordinaire XS(name) pour les XSUBs continuera de déclarer des XSUBs non-'static' par souci de compatibilité, mais le compilateur XS, ExtUtils::ParseXS (xsubpp) émettra des XSUBs 'static' par défaut. Le comportement d'ExtUtils::ParseXS peut être reconfiguré à partir de XS en utilisant le mot-clé EXPORT_XSUB_SYMBOLS. Voir perlxs pour plus de détails.

Affaiblissement des références en lecture seule

L'affaiblissement des références en lecture seule n'est plus autorisé. Cela n'aurait jamais dû fonctionner de toute façon, et a parfois pu entraîner des plantages.

Liaison des scalaires contenant des typeglobs

Tenter de lier un scalaire après qu'un typeglob lui ait été assigné liait en fait le handle dans le slot IO du typeglob. Cela signifiait qu'il était impossible de lier le scalaire lui-même. Des problèmes similaires affectaient tied et untie : tied $scalar retournait faux sur un scalaire lié si le dernier élément retourné était un typeglob, et untie $scalar sur un tel scalaire lié ne faisait rien.

Nous avons corrigé ce problème avant Perl 5.14.0, mais cela a causé des problèmes avec certains modules CPAN, nous avons donc introduit un cycle de dépréciation à la place.

Maintenant, la dépréciation a été supprimée et ce bug a été corrigé. Ainsi, tie $scalar liera toujours le scalaire, pas le handle qu'il contient. Pour lier le handle, utilisez tie *$scalar (avec un astérisque explicite). Il en va de même pour tied *$scalar et untie *$scalar.

IPC::Open3 ne fournit plus xfork(), xclose_on_exec() et xpipe_anon()

Les trois fonctions étaient privées, non documentées et non exportées. Elles ne semblent pas être utilisées par aucun code sur CPAN. Deux ont été intégrées et une a été supprimée.

$$ ne met plus en cache le PID

Auparavant, si l'on appelait fork(3) depuis C, la notion de $$ par Perl pouvait se désynchroniser avec ce que retourne getpid(). En récupérant toujours la valeur de $$ via getpid(), ce bug potentiel est éliminé. Le code qui dépend du comportement de mise en cache échouera. Comme décrit dans Core Enhancements, $$ est maintenant modifiable, mais il sera réinitialisé lors d'un fork.

$$ et getppid() n'émulent plus les sémantiques POSIX sous LinuxThreads

L'émulation POSIX de $$ et getppid() sous l'implémentation obsolète LinuxThreads a été supprimée. Cela n'affecte que les utilisateurs de Linux 2.4 et les utilisateurs de Debian GNU/kFreeBSD jusqu'à la version 6.0 incluse, pas la grande majorité des installations Linux qui utilisent les threads NPTL.

Cela signifie que getppid(), comme $$, est maintenant toujours garanti de retourner l'idée du système d'exploitation de l'état actuel du processus, et non la version mise en cache par perl.

Voir la documentation de $$ pour plus de détails.

$<, $>, $( et $) ne sont plus mis en cache

Similairement aux changements apportés à $$ et getppid(), la mise en cache interne de $<, $>, $( et $) a été supprimée.

Lorsque nous mettions en cache ces valeurs, notre idée de ce qu'elles représentaient pouvait se désynchroniser avec la réalité si quelqu'un (par exemple, quelqu'un intégrant Perl) appelait sete?[ug]id() sans mettre à jour PL_e?[ug]id. Gérer cette complexité n'en valait pas la peine étant donné le faible coût de gete?[ug]id().

Quoted Metacharacters

Modifications au quotation des caractères non-ASCII

Le changement de comportement dans le traitement des caractères non-ASCII par quotemeta et la séquence d'échappement \Q est le suivant :

  • Le caractère est maintenant inclus dans la métacaractère si et seulement si sa valeur est supérieure à 255 (c'est-à-dire s'il s'agit d'un caractère non-ASCII).

Ceci est peu susceptible de causer des problèmes réels, car Perl n'attache pas de signification spéciale aux caractères non-ASCII, il est donc actuellement sans importance de savoir lesquels sont cités ou non. Ce changement corrige le bug [perl #77654] et aligne le comportement de Perl sur les recommandations de l'Unicode. Voir quotemeta dans perlfunc.

Améliorations des performances

  • Performances améliorées pour les propriétés Unicode dans les expressions régulières.

    La correspondance d'un point de code avec une propriété Unicode se fait maintenant via une recherche binaire au lieu d'une recherche linéaire. Cela signifie, par exemple, que le pire cas pour une propriété de 1000 éléments nécessite 10 sondes au lieu de 1000. Cette inefficacité a été compensée par le passé en stockant en permanence dans une table de hachage les résultats d'une sonde donnée, ainsi que les résultats des 64 points de code adjacents, dans l'hypothèse où les points de code voisins sont susceptibles d'être recherchés. Une table de hachage distincte était utilisée pour chaque mention d'une propriété Unicode dans chaque expression régulière. Ainsi, qr/\p{foo}abc\p{foo}/ générerait deux tables de hachage. Les sondes dans une instance seraient inconnues de l'autre, et les tables de hachage pourraient s'étendre séparément pour devenir assez grandes si l'expression régulière était utilisée sur de nombreux points de code différents et largement séparés. Maintenant, cependant, il n'y a qu'une seule table de hachage partagée par toutes les instances d'une propriété donnée. Cela signifie que si p{foo} correspond à "A" dans une expression régulière dans un thread, le résultat sera immédiatement connu de toutes les expressions régulières, et la progression inexorable de l'utilisation de la mémoire est considérablement ralentie.

  • Les déclarations de version avec le mot-clé use (par exemple, use 5.012) sont maintenant plus rapides, car elles activent les fonctionnalités sans charger feature.pm.
  • local $_ est maintenant plus rapide, car il n'itère plus à travers la magie qu'il ne va pas copier de toute façon.
  • Perl 5.12.0 a accéléré la destruction des objets dont les classes définissent des méthodes DESTROY vides (pour empêcher le chargement automatique), en n'appelant simplement pas de telles méthodes vides. Cette version va plus loin dans cette optimisation, en n'appelant aucune méthode DESTROY qui commence par une instruction return. Cela peut être utile pour les destructeurs utilisés uniquement pour le débogage : 
    use constant DEBUG => 1;
sub DESTROY { return unless DEBUG; ... }

    La réduction des constantes réduira la première instruction à return; si DEBUG est défini sur 0, déclenchant ainsi cette optimisation.

  • L'affectation à une variable contenant un typeglob ou un scalaire en copie sur écriture est maintenant beaucoup plus rapide. Auparavant, le typeglob était converti en chaîne ou le scalaire en copie sur écriture était copié avant d'être écrasé.
  • L'affectation à substr dans un contexte vide est maintenant plus de deux fois plus rapide qu'auparavant. Au lieu de créer et de retourner un scalaire lvalue spécial qui est ensuite affecté, substr modifie la chaîne d'origine elle-même.
  • substr ne calcule plus de valeur à retourner lorsqu'il est appelé dans un contexte vide.
  • En raison de changements dans File::Glob, la fonction glob de Perl et son équivalent <...> sont maintenant beaucoup plus rapides. La division du motif en mots a été réécrite en C, ce qui entraîne des accélérations de 20 % dans certains cas.

    Cela n'affecte pas glob sur VMS, car il n'utilise pas File::Glob.

  • Les opérateurs de court-circuit &&, ||, et //, lorsqu'ils sont chaînés (comme $a || $b || $c), sont maintenant considérablement plus rapides pour le court-circuit, grâce à une réduction de la traversée de l'optree.
  • L'implémentation de s///r effectue une copie de moins de la valeur du scalaire.
  • Les appels récursifs aux sous-routines lvalue dans un contexte scalaire lvalue utilisent moins de mémoire.

    Les ajouts ou modifications suivants ont été apportés à la sortie des diagnostics, y compris les avertissements et les messages d'erreur fatals. Pour la liste complète des messages de diagnostic, voir perldiag.

    Nouveaux Diagnostics

    Nouvelles Erreurs

    • Cannot set tied @DB::args

      Cette erreur se produit lorsque "caller" essaie de définir @DB::args mais la trouve déjà liée (tied). Avant l'ajout de cette erreur, cela provoquait un crash.

    • Cannot tie unreifiable array

      Cette erreur fait partie d'une vérification de sécurité que l'opérateur "tie" effectue avant de lier un tableau spécial comme @_. Vous ne devriez jamais voir ce message.

    • &CORE::%s cannot be called directly

      Ceci se produit lorsqu'une sous-routine de l'espace de noms "CORE::" est appelée avec la syntaxe &foo ou via une référence. Certaines sous-routines de ce paquet ne peuvent pas encore être appelées de cette manière, mais doivent être appelées comme des mots nus (barewords). Voir "Subroutines in the "CORE" namespace", ci-dessus.

    • Source filters apply only to byte streams

      Cette nouvelle erreur se produit lorsque vous essayez d'activer un filtre source (généralement en chargeant un module de filtre source) dans une chaîne passée à "eval" sous la fonctionnalité "unicode_eval".

    Nouveaux Avertissements

    • defined(@array) is deprecated

      L'instruction defined(@array), dépréciée depuis longtemps, génère maintenant également un avertissement pour les variables de package. Auparavant, elle générait un avertissement uniquement pour les variables lexicales.

    • length() used on %s

      Ce nouvel avertissement se produit lorsque "length" est utilisé sur un tableau ou une hash, au lieu de scalar(@array) ou "scalar(keys %hash)".

    • lvalue attribute %s already-defined subroutine

      attributes.pm émet maintenant cet avertissement lorsque l'attribut :lvalue est appliqué à une sous-routine Perl déjà définie, car cela peut avoir des effets secondaires inattendus.

    • overload arg '%s' is invalid

      Cet avertissement, dans la catégorie « overload », est produit lorsque le pragma overload reçoit un argument qu'il ne reconnaît pas, probablement un opérateur mal orthographié.

    • $[ used in %s (did you mean $] ?)

      Ce nouvel avertissement existe pour détecter l'utilisation erronée de $[ dans les vérifications de version. $], et non $[, contient le numéro de version.

    • Useless assignment to a temporary

      L'assignation à un scalaire temporaire retourné par une sous-routine lvalue génère maintenant cet avertissement [perl #31946].

    • Useless use of \E

      "\E" ne fait rien à moins d'être précédé par "\Q", "\L" ou "\U".

    Erreurs Supprimées

    •
    "sort is now a reserved word"

    Cette erreur se produisait lorsque "sort" était appelé sans arguments, suivi de ";" ou ")". (Par exemple, "sort;" plantait, mais "{sort}" était correct.) Ce message d'erreur a été ajouté dans Perl 3 pour attraper du code comme close(sort) qui ne fonctionnerait plus. Plus de deux décennies plus tard, ce message n'est plus approprié. Maintenant, "sort" sans arguments est toujours autorisé et retourne une liste vide, comme c'était déjà le cas dans les cas où il était déjà autorisé [perl #90030].

    • Un bug qui provoquait une erreur "Use of freed value in iteration" si les deux prochains éléments de hash qui seraient itérés étaient supprimés a été corrigé [perl #85026]. (5.14.1)
    • La suppression de l'itérateur de hash actuel (l'élément de hash qui serait retourné par le prochain appel à "each") dans un contexte vide ne le libérait pas [perl #85026].

Il était possible de provoquer des doubles libérations si le destructeur libérait le hash lui-même [perl #100340].
    • Une optimisation de "keys" dans Perl 5.12.0 pour le rendre plus rapide sur les hashes vides faisait que "each" ne réinitialisait pas l'itérateur s'il était appelé après la suppression du dernier élément.

Ils produisent maintenant un message d'erreur "Modification of non-creatable hash value attempted".

    Scalaires Copy-on-write

    Les scalaires copy-on-write ou à clé de hachage partagée ont été introduits dans la version 5.8.0, mais la plupart du code Perl ne les a pas rencontrés (ils étaient principalement utilisés en interne). Perl 5.10.0 les a étendus, de sorte que l'assignation de "__PACKAGE__" ou d'une clé de hachage à un scalaire en faisait un copy-on-write. Plusieurs parties de Perl n'avaient pas été mises à jour pour en tenir compte, mais cela a maintenant été corrigé.

    • "utf8::decode" présentait un bug malveillant qui modifiait les tampons de chaîne des scalaires copy-on-write en place (c'est-à-dire en sautant la copie). Cela pouvait entraîner des hachages ayant deux éléments avec la même clé [perl #91834]. (5.14.2)
    • Les sous-routines lvaleur ne permettaient pas le retour de scalaires COW. Cela a été corrigé pour le contexte scalaire lvaleur dans Perl 5.12.3 et 5.14.0, mais le contexte liste n'a été corrigé que lors de cette version.
    • Les éléments des hachages restreints (voir le pragma fields) contenant des valeurs copy-on-write ne pouvaient pas être supprimés, pas plus que ces hachages ne pouvaient être vidés ("%hash = ()"). (5.14.2)
    • La localisation d'une variable liée rendait celle-ci en lecture seule si elle contenait une chaîne copy-on-write. (5.14.2)
    • L'affectation d'une chaîne copy-on-write à un élément de stash ne provoque plus de double libération. Indépendamment de ce changement, les résultats de telles affectations restent indéfinis.
    • L'affectation d'une chaîne copy-on-write à une variable liée n'empêche plus cette variable d'être liée si elle se trouve être un PVMG ou PVLV en interne.
    • Effectuer une substitution sur une variable liée retournant un scalaire copy-on-write provoquait auparavant un échec d'assertion ou un avertissement "Attempt to free nonexistent shared string".
    • Ceci est une régression par rapport à la version 5.12 : dans la version 5.14.0, les opérateurs d'affectation bit à bit "|=", "^=" et "&=" commençaient à laisser le côté gauche indéfini s'il s'agissait d'une chaîne copy-on-write [perl #108480].
    • Storable, Devel::Peek et PerlIO::scalar présentaient des problèmes similaires. Voir "Modules et Pragmata mis à jour", ci-dessus.

    Le débogueur

    • dumpvar.pl, et donc la commande "x" dans le débogueur, ont été corrigés pour gérer les objets bénis dans des classes dont les noms contiennent "=". Le contenu de tels objets n'était pas affiché [perl #101814].
    • La commande "R" pour redémarrer une session de débogage a été corrigée pour fonctionner sous Windows, ou tout autre système ne disposant pas d'une constante "POSIX::_SC_OPEN_MAX" [perl #87740].
    • La directive "#line 42 foo" ne mettait plus à jour les tableaux de lignes utilisés par le débogueur si elle survenait dans une évaluation de chaîne. Cela a été partiellement corrigé en 5.14, mais cela ne fonctionnait que pour un seul "#line 42 foo" dans chaque eval. Cela fonctionne maintenant pour plusieurs.
    • Lorsque les appels de sous-routines sont interceptés par le débogueur, le nom de la sous-routine ou une référence à celle-ci est stocké dans $DB::sub, pour que le débogueur y accède. Parfois (comme dans le cas de "$foo = *bar; undef *bar; &$foo"), $DB::sub était défini sur un nom qui ne pouvait pas être utilisé pour trouver la sous-routine, et donc la tentative du débogueur de l'appeler échouait. Désormais, la vérification pour déterminer si une référence est nécessaire est plus robuste, de sorte que ces problèmes ne devraient plus se produire [rt.cpan.org #69862].
    • Chaque sous-routine a un nom de fichier associé que le débogueur utilise. Celui associé aux sous-routines constantes était mal alloué lors du clonage sous les threads. Par conséquent, le débogage d'applications multithreadées pouvait entraîner une corruption de mémoire [perl #96126].

    Opérateurs de déréférencement

    • defined(${"..."}), defined(*{"..."}), etc., retournaient auparavant vrai pour la plupart des variables intégrées, mais pas toutes, si elles n'avaient pas encore été utilisées. Ce bug affectait notamment "${^GLOBAL_PHASE}" et "${^UTF8CACHE}". Cela retournait aussi faux si le nom du paquet était donné ("${"::!"}") [perl #97978, #97492].
    • Perl 5.10.0 a introduit un bug similaire : defined(*{"foo"}) où "foo" représente le nom d'une variable globale intégrée, retournait faux si la variable n'avait jamais été utilisée auparavant, mais seulement lors du premier appel. Ceci a également été corrigé.
    • Depuis 5.6.0, "*{ ... }" a été incohérent dans la façon dont il traite les valeurs indéfinies. Il échouait en mode strict ou en contexte lvaleur pour la plupart des valeurs indéfinies, mais était traité comme une chaîne vide (avec un avertissement) pour le scalaire spécifique retourné par undef() (interne &PL_sv_undef). Ceci a été corrigé. undef() est maintenant traité comme les autres scalaires indéfinis, comme dans Perl 5.005.

    Descripteur de fichier, dernier accédé

    Perl a une variable interne qui stocke le dernier descripteur de fichier accédé. Elle est utilisée par $. et par "tell" et "eof" sans arguments.

    • Il était auparavant possible de définir cette variable interne sur une copie de glob, puis de modifier cette copie de glob pour qu'elle devienne autre chose qu'un glob, et d'avoir toujours le dernier descripteur de fichier accédé associé à la variable après lui avoir à nouveau affecté un glob : 
      my $foo = *STDOUT;  # $foo est une copie de glob
<$foo>;             # $foo est maintenant le dernier handle accédé
$foo = 3;           # plus un glob
$foo = *STDERR;     # toujours le dernier handle accédé

      Maintenant, l'affectation "$foo = 3" désinitialise cette variable interne, donc il n'y a pas de dernier descripteur de fichier accédé, tout comme si "<$foo>" n'avait jamais eu lieu.

      Cela empêche également qu'un descripteur de fichier non lié devienne le dernier accédé si $foo sort de la portée et que le même SV interne est utilisé pour un autre descripteur [perl #97988].

    • Une régression en 5.14 a empêché ces instructions de définir cette variable interne : 
      my $fh = *STDOUT;
tell $fh;
eof  $fh;
seek $fh, 0,0;
tell     *$fh;
eof      *$fh;
seek     *$fh, 0,0;
readline *$fh;

      Ceci est maintenant corrigé, mais "tell *{ *$fh }" présente toujours le problème, et il n'est pas clair comment le résoudre [perl #106536].

    Tests de fichiers et "stat"

    Le terme "tests de fichiers" fait référence aux opérateurs qui consistent en un trait d'union suivi d'une seule lettre : "-r", "-x", "-M", etc. Le terme "empilé" appliqué aux tests de fichiers signifie suivi d'un autre opérateur de test de fichier partageant le même opérande, comme dans "-r -x -w $fooo".

    • "stat" produit des avertissements plus cohérents. Il n'émet plus d'avertissement pour "_" [perl #71002] et ne saute plus parfois l'avertissement pour d'autres descripteurs non ouverts. Il n'émet plus d'avertissement pour un descripteur non ouvert lorsque la fonction "fstat" du système d'exploitation échoue.
    • "stat" retournait parfois des nombres négatifs pour de grands numéros d'inode, car il utilisait le mauvais type C interne. [perl #84590]
    • Il est documenté que "lstat" se rabat sur "stat" (avec un avertissement) lorsqu'il reçoit un descripteur de fichier. Lorsqu'il recevait une référence IO, il effectuait en fait l'équivalent de "stat _" et ignorait le descripteur.
    • "-T _" sans "stat" précédent produisait un avertissement confusant "uninitialized", même s'il n'y a pas de valeur non initialisée visible à signaler.
    • "-T", "-B", "-l" et "-t" fonctionnent désormais lorsqu'ils sont empilés avec d'autres opérateurs de test de fichier [perl #77388].
    • En 5.14.0, les opérations de test de fichier ("-r", "-x", etc.) commençaient à appeler FETCH sur un argument lié appartenant à l'argument précédent d'un opérateur liste, s'ils étaient appelés avec un argument bareword ou aucun argument. Ceci a été corrigé, de sorte que "push @foo, $tied, -r" n'appelle plus FETCH sur $tied.
    • En Perl 5.6, "-l" suivi de quelque chose d'autre qu'un bareword traitait son argument comme un nom de fichier. Cela a été modifié en 5.8 pour les références de glob ("\*foo"), mais pas pour les globs eux-mêmes (*foo). "-l" commençait à retourner "undef" pour les références de glob sans définir le dernier tampon de stat que le descripteur "_" utilise, mais seulement si les avertissements étaient activés. Avertissements désactivés, c'était pareil qu'en 5.6. En d'autres termes, c'était simplement bogué et incohérent. Maintenant, le comportement de 5.6 a été restauré.
    • "-l" suivi d'un bareword ne [...]
    "mange" l'argument précédent à l'opérateur de liste dans la liste d'arguments dont il fait partie. Par conséquent, "print "bar", -l foo" affiche maintenant réellement "bar", car "-l" ne le mange plus.
  • Perl conserve plusieurs variables internes pour suivre le dernier tampon stat, de quel fichier (handle) il provient, quel était son type et si le dernier stat a réussi.

    Il y avait divers cas où ceux-ci pouvaient se désynchroniser, entraînant un comportement incohérent ou erratique dans les cas limites (chaque mention de "-T" s'applique également à "-B") :

    • "-T HANDLE", bien qu'il effectue un "stat", ne réinitialisait pas le dernier type de stat, donc un "lstat _" qui le suivait renvoyait joyeusement de mauvais résultats. De plus, il ne définissait pas le statut de succès.
    • La libération du handle utilisé en dernier par "stat" ou un test de fichier pouvait entraîner l'utilisation par "-T _" d'un handle sans rapport.
    • "stat" avec une référence IO ne réinitialisait pas le type de stat ni n'enregistrait le handle de fichier pour que "-T _" l'utilise.
    • Les avertissements fatals pouvaient empêcher la réinitialisation du tampon stat pour un opérateur de test de fichier sur un handle de fichier non ouvert ou pour "-l" sur n'importe quel handle. Les avertissements fatals empêchaient également "-T" de définir $!.
    • Lorsque le dernier stat portait sur un fichier illisible, "-T _" était censé renvoyer "undef", laissant le dernier tampon stat inchangé. Mais il définissait le type de stat, faisant que "lstat _" ne fonctionne plus.
    • "-T FILENAME" ne réinitialisait pas les tampons stat internes pour les fichiers illisibles.

    Tous ces problèmes ont été résolus.

Dans ces deux cas, il était possible que la sortie soit corrompue [perl #91032].

    • Lorsqu'elles étaient appelées dans un contexte potentiellement lvalue (par exemple, arguments de sous-routine ou une liste passée à "for"), les sous-routines lvalue copiaient auparavant toute valeur en lecture seule qui était renvoyée.     • Lorsqu'elles étaient appelées dans un contexte potentiellement lvalue, une sous-routine lvalue renvoyant des tableaux ou des hachages liait auparavant les tableaux ou les hachages à des variables scalaires, entraînant des bugs.     • Les appels de sous lvalue qui ne sont pas déterminés comme tels à la compilation (&$name ou &{"name"}) ne sont plus exemptés de refs strictes s'ils se produisent dans la dernière instruction d'une sous-routine lvalue [perl #102486].
    • Les appels de sous dont les sous ne sont pas visibles à la compilation, s'ils se produisaient dans la dernière instruction d'une sous-routine lvalue, rejetaient les sous-routines non-lvalue et mouraient avec "Can't modify non-lvalue subroutine call" [perl #102486].

    • Les routines "AUTOLOAD" avaient la priorité sur la sous réelle appelée (c'est-à-dire lorsque l'autoloading n'était pas nécessaire), pour les appels de sous dans un contexte lvalue ou potentiellement lvalue, si la sous-routine n'était pas visible à la compilation.
    • L'application de l'attribut ":lvalue" à un XSUB ou à un stub de sous-routine aliassé avec la syntaxe "sub foo :lvalue;" a cessé de fonctionner dans Perl 5.12. Ceci a été corrigé.
    • L'application de l'attribut :lvalue à une sous-routine déjà définie ne fonctionne pas correctement, car l'attribut modifie la manière dont la sous est compilée.       Prise en charge des nulls intégrés

      • Noms de globes de type (y compris les noms de fichiers et de sous-routines)

      • Éléments de globes de type (*foo{"THING\0stuff"})

      • L'opérateur "+=" ne produit généralement pas d'avertissement lorsque le membre de gauche est "undef", mais il le faisait pour les variables liées. Ceci a été corrigé [perl #44895].
      • L'opérateur "~" a maintenant une sémantique plus proche de C, ne transformant plus les entiers non signés en entiers signés [perl #29070].
      • L'affectation d'une vstring à une variable magique (par exemple, liée, $!) puis l'affectation d'autre chose effaçait auparavant toute magie. Cela signifiait que les variables liées étaient défaites, $! arrêtait d'être mis à jour lors des appels système échoués, $| arrêtait de définir le vidage automatique, et d'autres méfaits se produisaient. Ceci a été corrigé.
      • "version->new("version")" et "printf "%vd", "version"" ne plantent plus [perl #102586].
      • Les comparaisons de version, comme celles qui se produisent implicitement avec "use v5.43", ne modifient plus les paramètres locaux [perl #105784].
      • Les objets de version ne provoquent plus de fuites de mémoire en contexte booléen [perl #109762].

      Avertissements, redéfinition

      • Les sous-routines de l'espace de noms "autouse" sont à nouveau exemptées des avertissements de redéfinition. Cela fonctionnait auparavant dans 5.005, mais a été cassé dans 5.6 pour la plupart des sous-routines. Pour les sous créées via XS qui redéfinissent des sous-routines du paquet "autouse", cela a cessé de fonctionner dans 5.10.
      • Les nouveaux XSUB produisent désormais des avertissements de redéfinition s'ils écrasent des sous existantes, comme ils le faisaient dans 5.8.x. (La logique "autouse" a été inversée dans 5.10-14. Seules les sous-routines de l'espace de noms "autouse" avertissaient lorsqu'elles étaient écrasées.)
      • "newCONSTSUB" utilisait auparavant des indices d'avertissement au moment de la compilation, au lieu d'indices au moment de l'exécution. Le code suivant ne devrait jamais produire d'avertissement de redéfinition, mais il le faisait si "newCONSTSUB" redéfinissait une sous-routine existante : 
        use warnings;
BEGIN {
    no warnings;
    some_XS_function_that_calls_new_CONSTSUB();
}
      • Les avertissements de redéfinition pour les sous-routines constantes sont activés par défaut (ce qui est connu sous le nom d'avertissements sévères dans perldiag). Cela ne se produisait que lorsqu'une affectation de glob ou une déclaration de sous-routine Perl entraînait l'avertissement. Si la création de XSUB déclenchant l'avertissement n'était pas un avertissement par défaut. Ceci a été corrigé.
      • La vérification interne pour déterminer si un avertissement de redéfinition devait être émis produisait des avertissements "non initialisé" dans des cas comme celui-ci : 
        use warnings "uninitialized";
use constant {u => undef, v => undef};
sub foo(){u}
sub foo(){v}

      Avertissements, "Non initialisé"

      • Diverses fonctions prenant un argument de fichier en contexte rvalue ("close", "readline", etc.) avertissaient deux fois pour un handle indéfini [perl #97482].
      • "dbmopen" n'avertit désormais qu'une seule fois, au lieu de trois fois, si l'argument de mode est "undef" [perl #90064].
      • L'opérateur "+=" ne produit généralement pas d'avertissement lorsque le membre de gauche est "undef", mais il le faisait pour les variables liées. Ceci a été corrigé [perl #44895].
      • Une correction de bug dans Perl 5.14 a introduite un nouveau bug, faisant que les avertissements "non initialisé" rapportaient la mauvaise variable si l'opérateur en question avait deux opérandes et que l'un d'était "%{...}" ou "@{...}". Ceci a été corrigé [perl #103766].
      • L'opérateur ".." et "..." en contexte de liste mentionnent désormais le nom de la variable dans les avertissements "non initialisé" pour les plages de chaînes (par opposition aux plages numériques).

      Références faibles

      • Affaiblir le premier argument d'une méthode "DESTROY" automatiquement invoquée pouvait entraîner des erreurs erronées de "DESTROY a créé une nouvelle référence" ou des plantages. C'est maintenant une erreur d'affaiblir une référence en lecture seule.
      • Les références faibles aux hachages lexicaux sortant de la portée ne devenaient pas obsolètes (ne devenaient pas indéfinies), mais continuaient de pointer vers le hachage.
      • Les références faibles aux variables lexicaux sortant de la portée sont maintenant rompues avant que des méthodes magiques (par exemple, DESTROY sur un objet lié) ne soient appelées. Cela empêche de telles méthodes de modifier la variable qui sera vue la prochaine fois que la portée sera entrée.
      • La création d'une référence faible vers un tableau @ISA ou l'accès à l'indice du tableau ($#ISA) pouvait entraîner une mauvaise gestion interne des éléments ajoutés ultérieurement au tableau @ISA. Par exemple, la création d'une référence faible vers l'élément lui-même pouvait pousser cette référence faible sur @ISA ; et les éléments ajoutés après l'utilisation de $#ISA seraient ignorés par la recherche de méthodes [perl #85670].

      Autres corrections notables

      • "quotemeta" met désormais en citation de manière cohérente les mêmes caractères non ASCII sous "use feature 'unicode_strings'", que la chaîne soit codée en UTF-8 ou non, corrigeant ainsi les derniers vestiges (nous l'espérons) du célèbre "Bug Unicode" dans perlunicode. [perl #77654].

        Les points de code cités ont changé, basé sur les recommandations d'Unicode. Voir "quotemeta" dans perlfunc pour les détails.

      • "study" est maintenant un no-op, corrigeant vraisemblablement tous les bugs persistants liés au fait que study entraîne un comportement incorrect des correspondances regex !
      • Lorsque l'on écrit "open foo || die", ce qui fonctionnait auparavant dans Perl 4, un avertissement "Problème de précédence" est produit. Cet avertissement s'appliquait par erreur aux noms de handles bareword entièrement qualifiés non suivis de "||". Ceci a été corrigé.
      • Après un alias de paquet ("*foo:: = *bar::"), "select" avec 0 ou 1 argument renvoyait parfois un nom qui ne pouvait pas être utilisé pour faire référence au handle de fichier, ou parfois il renvoyait "undef" même lorsqu'un handle de fichier était sélectionné. Il renvoie maintenant une référence typeglob dans de tels cas.
      • "PerlIO::get_layers" ignore désormais certains arguments qu'il considère comme numériques, tout en traitant d'autres comme des noms de handles de fichier. Il est maintenant cohérent pour les scalaires plats (c'est-à-dire, pas des références).
      • Commutateurs non reconnus sur la ligne "#!"

        Si un commutateur, tel que -x, qui ne peut pas figurer sur la ligne "#!" y est utilisé, perl meurt avec "Impossible d'imiter...".

        Il produisait auparavant le même message pour les commutateurs que perl ne reconnaissait pas du tout, que ce soit sur la ligne de commande ou sur la ligne "#!".

        Il produit maintenant le message d'erreur "Commutateur non reconnu" [perl #104288].

      • "system" bloque désormais temporairement le gestionnaire de signal SIGCHLD, pour empêcher le gestionnaire de signal de voler le statut de sortie [perl #105700].
      • Le code de formatage %n pour "printf" et "sprintf", qui provoque l'affectation du nombre de caractères à l'argument suivant, affecte désormais le nombre de caractères, au lieu du nombre d'octets.

        Il fonctionne également désormais avec des fonctions lvalue spéciales comme "substr" et avec des éléments de hachage et de tableau inexistants [perl #3471, #103492].

      • Perl ignore la copie des valeurs retournées par une sous-routine, par souci de rapidité, si cela n'entraîne aucune différence observable. En raison d'une logique défectueuse, cela se produisait avec le résultat de "delete", "shift" ou "splice", même si le résultat était référencé ailleurs. Cela se produisait également avec les variables liées sur le point d'être libérées [perl #91844, #95548].
      • "utf8::decode" refuse désormais de modifier les scalaires en lecture seule [perl #91850].
      • La libération de $_ dans un bloc "grep" ou "map", un bloc de code intégré dans une expression régulière, ou un filtre @INC (une sous-routine retournée par une sous-routine dans @INC) entraînait auparavant des libérations multiples ou des plantages [perl #91880, #92254, #92256].
      • "eval" retourne "undef" en contexte scalaire ou une liste vide en contexte de liste en cas d'erreur d'exécution. Lorsque "eval" recevait une chaîne en contexte de liste et qu'une erreur de syntaxe se produisait, il retournait auparavant une liste contenant un seul élément indéfini. Il retourne maintenant une liste vide en contexte de liste pour toutes les erreurs [perl #80630].
      • "goto &func" ne plante plus, mais produit un message d'erreur, lorsque le déroulement de la portée de la sous-routine actuelle déclenche un destructeur qui annule la sous-routine "goneto" [perl #99850].
      • Perl conserve désormais un compte de référence supplémentaire sur le paquet dans lequel le code est en cours de compilation. Cela signifie que le code suivant ne plante plus [perl #101486] : 
        package Foo;
BEGIN {*Foo:: = *Bar::}
sub foo;
      • L'appel "require" sur un $_ implicite lorsque *CORE::GLOBAL::require a été dépasse ne provoque plus de segmentation fault, et $_ est maintenant passé à la sous-routine qui le dépasse [perl #78260].
      • "use" et "require" ne sont plus affectés par les couches d'E/S actives dans la portée de l'appelant (activées par open.pm) [perl #96008].
      • "our $::é; $é" (qui est invalide) ne produit plus l'"Erreur de compilation à lib/utf8_heavy.pl...&qu
      ot ; message d'erreur qu'il a commencé à émettre dans 5.10.0 [perl #99984].
    • Sur les systèmes 64 bits, read() comprend désormais les décalages de chaînes de caractères volumineuses au-delà de la plage 32 bits.
    • Les erreurs qui se produisent lors du traitement des attributs de sous-routine ne provoquent plus de fuite dans l'arbre op de la sous-routine.
    • Passer la même sous-routine constante à la fois à "index" et "formline" ne provoque plus l'échec de l'une ou l'autre [perl #89218]. (5.14.1)
    • L'affectation de liste aux variables lexicales déclarées avec des attributs dans la même instruction ("my ($x,@y) : blimp = (72,94)") a cessé de fonctionner dans Perl 5.8.0. Elle a maintenant été corrigée.
    • Perl 5.10.0 a introduit une logique défectueuse qui rendait "U*" au milieu d'un modèle pack équivalent à "U0" si la chaîne d'entrée était vide. Ceci a été corrigé [perl #90160]. (5.14.2)
    • Les destructeurs sur les objets n'étaient pas appelés lors de la destruction globale sur des objets qui n'étaient référencés par aucun scalaire. Cela pouvait se produire si un élément de tableau était béni (par exemple, "bless \$a[0]") ou si une fermeture référençait une variable bénie ("bless \my @a; sub foo { @a }").

      Il existe maintenant un passage supplémentaire lors de la destruction globale pour déclencher les destructeurs sur tous les objets qui pourraient rester après les passages habituels qui vérifient les objets référencés par des scalaires [perl #36347].

    • Correction d'un cas où il était possible qu'un tampon libéré ait été lu lors de l'analyse d'un here document [perl #90128]. (5.14.1)
    • each(ARRAY) est maintenant encapsulé dans defined(...), comme each(HASH), à l'intérieur d'une condition "while" [perl #90888].
    • Un problème de propagation de contexte lorsqu'un bloc "do" est un argument de "return" a été corrigé. Il provoquait auparavant le retour de "undef" dans certains cas d'un "return" à l'intérieur d'un bloc "if" qui est lui-même suivi d'un autre "return".
    • L'appel de "index" avec une constante tachée ne provoque plus la tachée des constantes dans le code compilé ultérieurement [perl #64804].
    • Les boucles infinies comme "1 while 1" arrêtaient auparavant le fonctionnement du mode "strict 'subs'" pour le reste du bloc.
    • Pour les affectations de listes comme "($a,$b) = ($b,$a)", Perl doit faire une copie des éléments du côté droit avant de les affecter au côté gauche. Pour des raisons d'efficacité, il affecte les valeurs de droite directement aux éléments de gauche si aucune variable n'est mentionnée des deux côtés, comme dans "($a,$b) = ($c,$d)". La logique déterminant quand il pouvait tricher était défectueuse, en ce sens que "&&" et "||" du côté droit pouvaient la tromper. Ainsi, "($a,$b) = $some_true_value && ($b,$a)" finissait par affecter la valeur de $b aux deux scalaires.
    • Perl n'essaie plus d'appliquer un contexte lvalue à la chaîne dans "("string", $variable) ||= 1" (ce qui était auparavant une erreur). Comme le côté gauche de "||=" est évalué en contexte scalaire, il s'agit d'un opérateur virgule scalaire, qui donne à tous les éléments sauf le dernier un contexte vide. Il n'existe pas de contexte lvalue vide, il était donc erroné pour Perl d'essayer de le forcer [perl #96942].
    • "caller" ne fuit plus de mémoire lorsqu'il est appelé depuis le paquet DB si @DB::args a été affecté après le premier appel à "caller". Carp déclenchait ce bug [perl #97010]. (5.14.2)
    • "close" et les fonctions similaires de fichier, lorsqu'elles sont appelées sur des variables globales intégrées (comme $+), causaient auparavant un die si la variable contenait la valeur indéfinie, au lieu de produire l'avertissement habituel "Use of uninitialized value".
    • Lorsque les descripteurs de fichiers auto-vivifiés ont été introduits dans Perl 5.6.0, "readline" a été involontairement rendu auto-vivifiant lorsqu'il était appelé comme readline($foo) (mais pas comme "<$foo>"). Il a maintenant été corrigé pour ne jamais auto-vivifier.
    • L'appel d'une sous-routine anonyme indéfinie (par exemple, ce que contient $x après "undef &{$x = sub{}}") causait auparavant une erreur "Not a CODE reference", qui a été corrigée en "Undefined subroutine called" [perl #71154].
    • Libérer @DB::args entre deux utilisations de "caller" ne provoque plus de crash [perl #93320].
    • setpgrp($foo) était auparavant équivalent à "($foo, setpgrp)", car "setpgrp" ignorait son argument s'il n'y en avait qu'un. Maintenant, il est équivalent à "setpgrp($foo,0)".
    • "shmread" ne réglait pas correctement les indicateurs scalaires lors de la lecture depuis la mémoire partagée, provoquant la persistance de la représentation numérique numérique existante dans le scalaire [perl #98480].
    • "++" et "--" fonctionnent désormais sur des copies de globs, au lieu de provoquer un die.
    • splice() n'émet pas d'avertissement lors de la troncature

      Vous pouvez désormais limiter la taille d'un tableau en utilisant "splice(@a,MAX_LEN)" sans vous soucier des avertissements.

    • $$ n'est plus taché. Comme cette valeur provient directement de getpid(), elle est toujours sûre.
    • L'analyseur ne fuit plus de descripteur de fichier si STDIN a été fermé avant le début de l'analyse [perl #37033].
    • "die;" avec une valeur qui n'est ni une référence, ni une chaîne, ni magique (par exemple, tachée) dans $@ propage désormais correctement cette valeur [perl #111654].

    Problèmes Connus

    • Sur Solaris, nous avons deux types d'échec.

      Si make est le make de Sun, nous obtenons une erreur concernant une affectation de macro mal formée dans le Makefile. Cela se produit lorsque ./Configure essaie de faire les dépendances. Configure se termine alors avec 0, mais la suite des make échoue.

      Si make est gmake, Configure se termine, puis nous obtenons des erreurs liées à /usr/include/stdbool.h

    • Sur Win32, un certain nombre de tests se bloquent sauf si STDERR est redirigé. La cause de cela fait toujours l'objet d'une enquête.
    • Lors de la construction en tant que root avec un umask qui empêche les fichiers d'être lisibles par d'autres, t/op/filetest.t échoue. Ceci est un bug de test, pas un bug dans le comportement de perl.
    • La configuration avec un gcc récent et l'optimisation au moment de la liaison, telle que "Configure -Doptimize='-O2 -flto'" échoue car l'optimiseur optimise certains des tests de Configure. Une solution de contournement consiste à omettre le drapeau "-flto" lors de l'exécution de Configure, mais à le rajouter lors de la construction réelle, quelque chose comme 
      sh Configure -Doptimize=-O2
make OPTIMIZE='-O2 -flto'

    Signalement des bogues

    Si vous trouvez ce que vous pensez être un bogue, vous pouvez consulter les articles récemment publiés sur le groupe de discussion comp.lang.perl.misc et la base de données des bogues de Perl à l'adresse http://rt.perl.org/perlbug/. Il peut également y avoir des informations sur http://www.perl.org/, la page d'accueil de Perl.

    Si vous pensez avoir un bogue non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bogue à un cas de test minuscule mais suffisant. Votre rapport de bogue, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl.

    Si le bogue que vous signalez a des implications de sécurité, qui le rendent inapproprié à l'envoi à une liste de diffusion publiquement archivée, veuillez alors l'envoyer à perl5-security-report@perl.org. Ceci pointe vers une liste de diffusion à souscription fermée et non archivée, qui inclut tous les committeurs principaux, qui seront en mesure d'évaluer l'impact des problèmes, de trouver une solution et d'aider à coordonner la publication de correctifs pour atténuer ou résoudre le problème sur toutes les plateformes sur lesquelles Perl est pris en charge. Veuillez utiliser cette adresse uniquement pour les problèmes de sécurité dans le noyau de Perl, et non pour les modules distribués indépendamment sur CPAN.
