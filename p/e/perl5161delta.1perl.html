NOM

perl5161delta - ce qui est nouveau pour la version perl v5.16.1

DESCRIPTION

Ce document décrit les différences entre la version 5.16.0 et la version 5.16.1.

Si vous mettez à niveau depuis une version antérieure telle que 5.14.0, lisez d'abord perl5160delta, qui décrit les différences entre 5.14.0 et 5.16.0.

Sécurité

une erreur de décalage d'une unité dans Scalar-List-Util a été corrigée

La correction de bug se trouvait dans Scalar-List-Util 1.23_04, et perl 5.16.1 inclut Scalar-List-Util 1.25.

Changements incompatibles

Aucun changement intentionnellement incompatible avec 5.16.0 n'a été apporté. S'il en existe, ce sont des bugs, et nous vous prions de bien vouloir soumettre un rapport. Voir "Rapporter des bugs" ci-dessous.

Modules et Pragmata

Modules et Pragmata mis à jour

  • Scalar::Util et List::Util ont été mis à niveau de la version 1.23 à la version 1.25.
  • B::Deparse a été mis à jour de la version 1.14 à la version 1.14_01. Un avertissement "uninitialized" émis par B::Deparse a été supprimé [perl #113464].

Configuration et Compilation

•
La compilation de perl avec certains compilateurs Windows échouait en raison d'un problème avec l'opérateur "glob" de miniperl (qui utilise le programme "perlglob") qui supprimait la variable d'environnement PATH [perl #113798].

Support de Plateforme

Notes spécifiques à la plateforme

VMS
Tous les fichiers d'en-tête C du répertoire de niveau supérieur de la distribution sont maintenant installés sur VMS, assurant la cohérence avec une pratique de longue date sur d'autres plateformes. Auparavant, seul un sous-ensemble était installé, ce qui cassait la compilation des extensions non essentielles qui dépendaient des fichiers d'inclusion manquants.

Corrections de bugs sélectionnées

  • Une régression introduite dans Perl v5.16.0 concernant "tr/LISTE_RECHERCHE/LISTE_REMPLACEMENT/" a été corrigée. Seule la première instance est censée être significative si un caractère apparaît plus d'une fois dans "LISTE_RECHERCHE". Dans certaines circonstances, la dernière instance avait remplacé toutes les précédentes. [perl #113584]
  • "B::COP::stashlen" a été ajouté. Cela fournit un accès à un champ interne ajouté dans perl 5.16 pour les builds multithreads. Il avait été cassé à la dernière minute avant la sortie de 5.16 [perl #113034].
  • Le pragma re ne corrompra plus $_. [perl #113750]
  • Unicode 6.1 a publié un alias incorrect pour l'une des valeurs de la propriété Canonical_CombiningClass (qui varie entre 0 et 254). L'alias "CCC133" aurait dû être "CCC132". Perl remplace maintenant le fichier de données fourni par Unicode pour donner la valeur correcte.
  • La duplication des poignées de fichier scalaires fonctionne à nouveau. [perl #113764]
  • Dans les perls multithreads, un bloc de code d'exécution dans une expression régulière pouvait corrompre le nom du paquet stocké dans l'arbre d'opérations, entraînant des lectures erronées dans "caller", et potentiellement des plantages [perl #113060].
  • Pour des raisons d'efficacité, de nombreux opérateurs et fonctions intégrées renvoient le même scalaire à chaque fois. Les sous-routines lvalue et les sous-routines dans l'espace de noms CORE:: permettaient à ce détail d'implémentation de fuir. "print &CORE::uc("a"), &CORE::uc("b")" affichait autrefois "BB". La même chose se produisait avec une sous-routine lvalue renvoyant la valeur de retour de "uc". La valeur est maintenant copiée dans de tels cas [perl #113044].
  • "__SUB__" fonctionne maintenant dans les blocs spéciaux ("BEGIN", "END", etc.).
  • Les formats qui référencent des variables lexicales externes ne provoquent plus de plantages.

Problèmes connus

Aucun nouveau problème connu n'a été identifié, mais consultez la section "Problèmes connus" de perl5160delta pour connaître ceux qui ont été identifiés dans la version 5.16.0.

Remerciements

Perl 5.16.1 représente environ 2 mois de développement depuis Perl 5.16.0 et contient environ 14 000 lignes de changements réparties sur 96 fichiers par 8 auteurs.

Perl continue de s'épanouir dans sa troisième décennie grâce à une communauté dynamique d'utilisateurs et de développeurs. Les personnes suivantes sont connues pour avoir contribué aux améliorations qui sont devenues Perl 5.16.1 :

Chris 'BinGOs' Williams, Craig A. Berry, Father Chrysostomos, Karl Williamson, Paul Johnson, Reini Urban, Ricardo Signes, Tony Cook.

La liste ci-dessus est presque certainement incomplète car elle est générée automatiquement à partir de l'historique du contrôle de version. En particulier, elle n'inclut pas les noms des contributeurs (très appréciés) qui ont signalé des problèmes dans le tracker de bugs de Perl.

Beaucoup des changements inclus dans cette version proviennent des modules CPAN inclus dans le cœur de Perl. Nous sommes reconnaissants envers toute la communauté CPAN d'aider Perl à prospérer.

Pour une liste plus complète de tous les contributeurs historiques de Perl, veuillez consulter le fichier AUTHORS dans la distribution source de Perl.

Rapporter des bugs

Si vous trouvez ce que vous pensez être un bug, vous pourriez consulter les articles récemment postés sur le groupe de nouvelles comp.lang.perl.misc et la base de données des bugs de Perl à l'adresse http://rt.perl.org/perlbug/ . Il peut également y avoir des informations sur http://www.perl.org/ , la page d'accueil de Perl.

Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bug à un cas de test minuscule mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", sera envoyé à perlbug@perl.org pour être analysé par l'équipe de portage de Perl.

Si le bug que vous signalez a des implications en matière de sécurité, ce qui le rend inapproprié à envoyer sur une liste de diffusion archivée publiquement, alors envoyez-le à perl5-security-report@perl.org. Cela pointe vers une liste de diffusion à souscription fermée et non archivée, qui inclut tous les committers principaux, qui pourront aider à évaluer l'impact des problèmes, à trouver une solution et à co-ordonner la publication de correctifs pour atténuer ou résoudre le problème sur toutes les plateformes où Perl est pris en charge. Veuillez n'utiliser cette adresse que pour les problèmes de sécurité dans le cœur de Perl, pas pour les modules distribués indépendamment sur CPAN.
