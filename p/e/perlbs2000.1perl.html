PERLBS2000(1perl) Guide de référence pour programmeurs Perl PERLBS2000(1perl)

NOM

perlbs2000 - construction et installation de Perl pour BS2000.

Ce document doit être mis à jour, mais nous ne savons pas ce qu'il devrait dire. Veuillez soumettre vos commentaires à https://github.com/Perl/perl5/issues.

SYNOPIS

Ce document vous aidera à configurer, construire, tester et installer Perl sur BS2000 dans le sous-système POSIX.

DESCRIPTION

C'est un port de Perl pour le sous-système POSIX de BS2000 VERSION OSD V3.1A ou ultérieur. Il peut fonctionner sur d'autres versions, mais nous avons commencé le portage et les tests avec la version 3.1A et utilisons actuellement la version V4.0A.

Vous pourriez avoir besoin des programmes GNU suivants pour installer Perl :

gzip sur BS2000

Nous avons utilisé la version 1.2.4, qui a pu être installée sans problème avec un échec lors de la commande « make check ».

bison sur BS2000

Le programme yacc fourni avec BS2000 POSIX n'a pas fonctionné pour nous. Nous avons donc dû utiliser bison. Nous avons apporté quelques modifications à Perl afin d'utiliser l'analyseur pur (réentrant) de bison. Nous avons utilisé la version 1.25, mais nous avons dû ajouter quelques modifications en raison de l'EBCDIC. Voir ci-dessous pour plus de détails concernant yacc.

Décompression de la distribution Perl sur BS2000

Pour extraire une archive tar ASCII sur BS2000 POSIX, vous avez besoin d'un système de fichiers ASCII (nous avons utilisé le point de montage /usr/local/ascii pour cela). Extrayez ensuite l'archive dans le système de fichiers ASCII sans conversion d'E/S :

cd /usr/local/ascii export IO_CONVERSION=NO gunzip < /usr/local/src/perl.tar.gz | pax -r

Vous pouvez ignorer le message d'erreur pour le premier élément de l'archive (ceci ne ressemble pas à une archive tar / passage au fichier suivant...), il s'agit seulement du répertoire qui sera créé automatiquement de toute façon.

Après avoir extrait l'archive, copiez l'arborescence complète de répertoires vers votre système de fichiers EBCDIC. Cette fois, utilisez la conversion d'E/S :

cd /usr/local/src IO_CONVERSION=YES cp -r /usr/local/ascii/perl5.005_02 ./

Compilation de Perl sur BS2000

Il existe un fichier « hints » pour BS2000 appelé hints.posix-bc (car posix-bc est le nom de l'OS donné par `uname`) qui spécifie les valeurs correctes pour la plupart des choses. Le problème majeur est (bien sûr) le jeu de caractères EBCDIC. Nous avons la version EBCDIC allemande.

En raison de nos problèmes avec le yacc natif, nous avons utilisé GNU bison pour générer un analyseur pur (= réentrant) pour perly.y. Donc, notre yacc est en réalité le script suivant :

-----8<-----/usr/local/bin/yacc-----8<----- #! /usr/bin/sh

# Bison comme un yacc réentrant :

# sauvegarde les paramètres : params="" tant que [[ $# -gt 1 ]]; faire
params="$params $1"
shift
fait

# ajoute le drapeau %pure_parser:

tmpfile=/tmp/bison.$$.y echo %pure_parser > $tmpfile cat $1 >> $tmpfile

# appelle bison :

echo "/usr/local/bin/bison --yacc $params $1\t\t\t(Analyseur Pur)" /usr/local/bin/bison --yacc $params $tmpfile

# nettoyage :

rm -f $tmpfile -----8<----------8<-----

Nous utilisons toujours le yacc normal pour a2p.y cependant ! ! Nous avons créé un lien symbolique appelé byacc pour distinguer les deux versions :

ln -s /usr/bin/yacc /usr/local/bin/byacc

Nous construisons Perl en utilisant GNU make. Nous avons essayé la commande make native une fois et elle a également fonctionné.

Tests de Perl sur BS2000

Nous avons encore eu quelques erreurs lors de la commande « make test ». Certaines d'entre elles sont le résultat de l'utilisation de bison. Bison affiche parser error au lieu de syntax error, nous pouvons donc les ignorer. La liste suivante montre nos erreurs, vos résultats peuvent différer :

Installation de Perl sur BS2000

Nous n'avons pas nroff sur BS2000 POSIX (encore), nous avons donc ignoré toutes les erreurs lors de l'installation de la documentation.

Utilisation de Perl dans le shell POSIX de BS2000

BS2000 POSIX ne prend pas en charge la notation shebang (« #!/usr/local/bin/perl »), vous devez donc utiliser les lignes suivantes à la place :

: # utiliser perl
eval 'exec /usr/local/bin/perl -S $0 ${1+"$@"}'
if 0; # ^ Exécuter uniquement sous un shell

Utilisation de Perl en BS2000 « natif »

Nous n'avons pas encore beaucoup d'expérience avec cela, mais essayez ce qui suit :

Copiez votre exécutable Perl vers un LLM BS2000 en utilisant bs2cp :

"bs2cp /usr/local/bin/perl 'bs2:perl(perl,l)'"

Maintenant, vous pouvez le démarrer avec la commande suivante (SDF) :

"/START-PROG FROM-FILE=*MODULE(PERL,PERL),PROG-MODE=*ANY,RUN-MODE=*ADV"

Vous obtenez d'abord l'invite de ligne de commande BS2000 ('*'). Ici, vous pouvez entrer vos paramètres, par exemple "-e 'print "Hello World!\\n";'" (notez le double antislash !) ou "-w" et le nom de votre script Perl. Les noms de fichiers commençant par "/" sont recherchés dans le système de fichiers Posix, les autres sont recherchés dans le système de fichiers BS2000. Vous pouvez même utiliser des caractères génériques si vous placez un "%" devant votre nom de fichier (par exemple "-w checkfiles.pl %*.c"). Lisez votre manuel C/C++ pour des possibilités supplémentaires de l'invite de ligne de commande (recherchez PARAMETER-PROMPTING).

Anomalies en virgule flottante sur BS2000

Il semble y avoir un bug dans l'implémentation en virgule flottante sur les systèmes POSIX BS2000, de sorte que l'appel de int() sur le produit d'un nombre et d'un nombre de faible magnitude n'est pas le même que l'appel de int() sur le quotient de ce nombre et d'un nombre de grande magnitude. Par exemple, dans le code Perl suivant :

my $x = 100000.0;
my $y = int($x * 1e-5) * 1e5; # '0'
my $z = int($x / 1e+5) * 1e5;  # '100000'
print "\$y is $y and \$z is $z\n"; # $y est 0 et $z est 100000

Bien que l'on s'attende à ce que les quantités $y et $z soient identiques et égales à 100000, elles seront différentes et vaudront respectivement 0 et 100000.

Utilisation de PerlIO et d'encodages différents sur les partitions ASCII et EBCDIC

Depuis la version 5.8, Perl utilise le nouveau PerlIO sur BS2000. Cela vous permet d'utiliser différents encodages par canal d'E/S. Par exemple, vous pouvez utiliser

use Encode;
open($f, ">:encoding(ascii)", "test.ascii");
print $f "Hello World!\n";
open($f, ">:encoding(posix-bc)", "test.ebcdic");
print $f "Hello World!\n";
open($f, ">:encoding(latin1)", "test.latin1");
print $f "Hello World!\n";
open($f, ">:encoding(utf8)", "test.utf8"

;); print $f "Bonjour le monde !\n";

pour obtenir deux fichiers contenant "Bonjour le monde !\n" en ASCII, EBCDIC, ISO Latin-1 (dans cet exemple identique à ASCII) et UTF-EBCDIC respectivement (dans cet exemple identique à EBCDIC normal). Voir la documentation d'Encode::PerlIO pour les détails.

Comme la couche PerlIO utilise des IO brutes en interne, tout cela ignore totalement le type de votre système de fichiers (ASCII ou EBCDIC) et la variable d'environnement IO_CONVERSION. Si vous voulez retrouver le comportement ancien, où les fonctions IO de BS2000 déterminent la conversion en fonction du système de fichiers, PerlIO est toujours votre ami. Vous utilisez IO_CONVERSION comme d'habitude et vous dites à Perl qu'il doit utiliser la couche IO native :

export IO_CONVERSION=YES
export PERLIO=stdio

Maintenant, vos IO seraient en ASCII sur les partitions ASCII et en EBCDIC sur les partitions EBCDIC. Voir la documentation de PerlIO (sans "Encode::" !) pour d'autres possibilités.
