PERLMODINSTALL(1perl) Guide du programmeur Perl PERLMODINSTALL(1perl)

NOM

perlmodinstall - Installation de modules CPAN

DESCRIPTION

Vous pouvez considérer un module comme l'unité fondamentale de code Perl réutilisable ; voir perlmod pour plus de détails. Chaque fois que quelqu'un crée un bloc de code Perl qu'il pense être utile au monde, il s'enregistre comme développeur Perl sur https://www.cpan.org/modules/04pause.html afin de pouvoir ensuite télécharger son code sur CPAN. CPAN est le Comprehensive Perl Archive Network et est accessible à https://www.cpan.org/ , et peut être recherché à https://metacpan.org/ .

Cette documentation s'adresse aux personnes qui souhaitent télécharger des modules CPAN et les installer sur leur propre ordinateur.

PRÉAMBULE

Tout d'abord, êtes-vous sûr que le module n'est pas déjà sur votre système ? Essayez "perl -MFoo -e 1". (Remplacez "Foo" par le nom du module ; par exemple, "perl -MCGI::Carp -e 1".)

Si vous ne voyez aucun message d'erreur, vous avez le module. (Si vous voyez un message d'erreur, il est toujours possible que vous ayez le module, mais qu'il ne soit pas dans votre chemin, que vous pouvez afficher avec perl -e "print qq(@INC)".) Pour le reste de ce document, nous supposerons que vous manquez vraiment, honnêtement, d'un module installé, mais que vous l'avez trouvé sur CPAN.

Vous avez donc maintenant un fichier se terminant par .tar.gz (ou, moins souvent, .zip). Vous savez qu'il y a un module savoureux à l'intérieur. Vous devez maintenant suivre quatre étapes :

DÉCOMPRESSER le fichier
DÉPAQUETER le fichier dans un répertoire
COMPILER le module (parfois inutile)
INSTALLER le module.

Voici comment effectuer chaque étape pour chaque système d'exploitation. Ceci n'est **pas** un substitut à la lecture des fichiers README et INSTALL qui pourraient accompagner votre module !

Notez également que ces instructions sont adaptées à l'installation du module dans le dépôt de modules Perl de votre système, mais vous pouvez installer des modules dans n'importe quel répertoire de votre choix. Par exemple, là où je dis "perl Makefile.PL", vous pouvez substituer "perl Makefile.PL PREFIX=/mon/repertoire_perl" pour installer les modules dans /mon/repertoire_perl. Ensuite, vous pouvez utiliser les modules depuis vos programmes Perl avec "use lib "/mon/repertoire_perl/lib/site_perl";" ou parfois juste "use "/mon/repertoire_perl";". Si vous êtes sur un système qui nécessite un accès superutilisateur/root pour installer des modules dans les répertoires que vous voyez lorsque vous tapez "perl -e "print qq(@INC)"", vous voudrez les installer dans un répertoire local (comme votre répertoire personnel) et utiliser cette approche.

  • Si vous êtes sur un système Unix ou similaire à Unix,

    Vous pouvez utiliser le module CPAN d'Andreas Koenig ( https://metacpan.org/release/CPAN ) pour automatiser les étapes suivantes, de DÉCOMPRESSER à INSTALLER.

    A. DÉCOMPRESSER

    Décompressez le fichier avec "gzip -d votremodule.tar.gz"

    Vous pouvez obtenir gzip sur <ftp://prep.ai.mit.edu/pub/gnu/>

    Ou, vous pouvez combiner cette étape avec la suivante pour économiser de l'espace disque :

    gzip -dc votremodule.tar.gz | tar -xof -

    B. DÉPAQUETER

    Dépacquetez le résultat avec "tar -xof votremodule.tar"

    C. COMPILER

    Allez dans le répertoire nouvellement créé et tapez :

    perl Makefile.PL
make test

    ou

    perl Makefile.PL PREFIX=/mon/repertoire_perl

    pour l'installer localement. (N'oubliez pas que si vous faites cela, vous devrez mettre "use lib "/mon/repertoire_perl";" en haut du programme qui doit utiliser ce module.

    D. INSTALLER

    Toujours dans ce répertoire, tapez :

    make install

    Assurez-vous d'avoir les permissions appropriées pour installer le module dans votre répertoire de modules Perl 5. Souvent, vous devrez être root.

    C'est tout ce que vous avez à faire sur les systèmes Unix avec liaison dynamique. La plupart des systèmes Unix ont la liaison dynamique. Si le vôtre n'en a pas, ou si pour une autre raison vous avez un perl lié statiquement, **et** que le module nécessite une compilation, vous devrez compiler un nouveau binaire Perl qui inclut le module. Encore une fois, vous aurez probablement besoin d'être root.

  • Si vous utilisez ActivePerl (Win95/98/2K/NT/XP, Linux, Solaris),

    Tout d'abord, tapez "ppm" depuis un shell et voyez si le dépôt PPM d'ActiveState contient votre module. Si c'est le cas, vous pouvez l'installer avec "ppm" et vous n'aurez pas à vous soucier des autres étapes ici. Vous pourriez également être en mesure d'utiliser les instructions CPAN de la section "Unix ou Linux" ci-dessus ; essayez. Sinon, vous devrez suivre les étapes ci-dessous.

    A. DÉCOMPRESSER

    Vous pouvez utiliser le logiciel libre 7-zip ( https://www.7-zip.org/ ) ou le shareware Winzip ( https://www.winzip.com ) pour décompresser et dépacqueter les modules.

    B. DÉPAQUETER

    Si vous avez utilisé WinZip, cela a déjà été fait pour vous.

    C. COMPILER

    Vous aurez besoin de "nmake" ou "gmake".

    Le module nécessite-t-il une compilation (c'est-à-dire a-t-il des fichiers se terminant par .xs, .c, .h, .y, .cc, .cxx ou .C) ? Si c'est le cas, la vie devient officiellement difficile pour vous, car vous devez compiler le module vous-même (pas une mince affaire sous Windows). Vous aurez besoin d'un compilateur comme Visual C++. Alternativement, vous pouvez télécharger un package PPM précompilé depuis ActiveState. http://aspn.activestate.com/ASPN/Downloads/ActivePerl/PPM/

    Allez dans le répertoire nouvellement créé et tapez :

       perl Makefile.PL
   nmake test
D. INSTALLER

    Toujours dans ce répertoire, tapez :

    nmake install
  • Si vous êtes sur OS/2,

    Obtenez la suite de développement EMX et gzip/tar depuis Hobbes ( http://hobbes.nmsu.edu/h-browse.php?dir=/pub/os2/dev/emx/v0.9d ), puis suivez les instructions pour Unix.

  • Si vous êtes sous VMS,

    Lors du téléchargement depuis CPAN, enregistrez votre fichier avec une extension ".tgz" au lieu de ".tar.gz". Tous les autres points dans le nom de fichier doivent être remplacés par des underscores. Par exemple, "Votre-Module-1.33.tar.gz" doit être téléchargé en tant que "Votre-Module-1_33.tgz".

    A. DÉCOMPRESSER

    Tapez

    gzip -d Votre-Module.tgz

    ou, pour les modules zippés, tapez

    unzip Votre-Module.zip

    Exécutables pour gzip, zip et VMStar :

    http://www.hp.com/go/openvms/freeware/

    et leur code source :

    http://www.fsf.org/order/ftp.html

    Notez que gzip/gunzip de GNU n'est pas la même chose que le package zip/unzip d'Info-ZIP. Le premier est un simple outil de compression ; le second permet la création d'archives multi-fichiers.

    B. DÉPAQUETER

    Si vous utilisez VMStar :

    VMStar xf Votre-Module.tar

    Ou, si vous êtes amateur de la syntaxe des commandes VMS :

    tar/extract/verbose Votre_Module.tar

    C. COMPILER

    Assurez-vous d'avoir MMS (de Digital) ou le freeware MMK ( disponible chez MadGoat à http://www.madgoat.com ). Ensuite, tapez ceci pour créer le DESCRIP.MMS pour le module :

    perl Makefile.PL

    Vous êtes maintenant prêt à compiler :

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

NAME

perlmodinstall — Installing Perl Modules

DESCRIPTION

This document will explain how to install Perl modules.

Here are the steps for installing a Perl module that you've downloaded (or unpacked) from the CPAN:

  • Unpack the module. These usually come as .tar.gz or .zip files. If you've downloaded a .tar.gz file, you can usually unpack it with "gzip -dc yourmodule.tar.gz | tar xf -". If you've downloaded a .zip file, use "unzip yourmodule.zip".
  • Change into the module's directory.
  • Run the Makefile.PL script. This script figures out where to install the module, and creates a Makefile for you. 
    perl Makefile.PL
    If you're using MMK, substitute "mmk" for "perl".
  • Compile the module. This step is only necessary if the module includes C code, which most don't. 
    make
    If you're using MMK, substitute "mmk" for "make".
  • Test the module. This step is optional, but highly recommended. 
    make test
    Substitute "mmk" for "make" above if you're using MMK.
  • Install the module. 
    make install
    Substitute "mmk" for "make" above if you're using MMK.

If you're on MVS,

Introduce the .tar.gz file into an HFS as binary; don't translate from ASCII to EBCDIC.

A. DECOMPRESS

Decompress the file with "gzip -d yourmodule.tar.gz"

You can get gzip from http://www.s390.ibm.com/products/oe/bpxqp1.html

B. UNPACK

Unpack the result with

pax -o to=IBM-1047,from=ISO8859-1 -r < yourmodule.tar

The BUILD and INSTALL steps are identical to those for Unix. Some modules generate Makefiles that work better with GNU make, which is available from http://www.mks.com/s390/gnu/

PORTABILITY

Note that not all modules will work with on all platforms. See perlport for more information on portability issues. Read the documentation to see if the module will work on your system. There are basically three categories of modules that will not work "out of the box" with all platforms (with some possibility of overlap):

  • Those that should, but don't. These need to be fixed; consider contacting the author and possibly writing a patch.
  • Those that need to be compiled, where the target platform doesn't have compilers readily available. (These modules contain .xs or .c files, usually.) You might be able to find existing binaries on the CPAN or elsewhere, or you might want to try getting compilers and building it yourself, and then release the binary for other poor souls to use.
  • Those that are targeted at a specific platform. (Such as the Win32:: modules.) If the module is targeted specifically at a platform other than yours, you're out of luck, most likely.

Check the CPAN Testers if a module should work with your platform but it doesn't behave as you'd expect, or you aren't sure whether or not a module will work under your platform. If the module you want isn't listed there, you can test it yourself and let CPAN Testers know, you can join CPAN Testers, or you can request it be tested.

https://cpantesters.org/

HEY

If you have any suggested changes for this page, let me know. Please don't send me mail asking for help on how to install your modules. There are too many modules, and too few Orwants, for me to be able to answer or even acknowledge all your questions. Contact the module author instead, ask someone familiar with Perl on your operating system, or if all else fails, file a ticket at https://rt.cpan.org/.
