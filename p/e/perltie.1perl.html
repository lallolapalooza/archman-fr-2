PERLTIE(1perl) Guide du programmeur Perl PERLTIE(1perl)

NOM

perltie — comment masquer une classe d'objet dans une variable simple

SYNOPSIS

tie VARIABLE, CLASSE, LISTE
$objet = tied VARIABLE
untie VARIABLE

DESCRIPTION

Avant la sortie 5.0 de Perl, un programmeur pouvait utiliser dbmopen() pour connecter une base de données sur disque au format standard Unix dbm(3x) à une %HASH dans son programme. Cependant, son Perl était soit construit avec une bibliothèque dbm particulière, soit une autre, et vous ne pouviez pas étendre ce mécanisme à d'autres packages ou types de variables.

Maintenant, vous pouvez.

La fonction tie() lie une variable à une classe (package) qui fournira l'implémentation des méthodes d'accès pour cette variable. Une fois cette magie effectuée, l'accès à une variable liée déclenche automatiquement des appels de méthodes dans la classe appropriée. La complexité de la classe est masquée derrière des appels de méthodes magiques. Les noms des méthodes sont en MAJUSCULES, ce qui est une convention utilisée par Perl pour indiquer qu'elles sont appelées implicitement plutôt qu'explicitement — tout comme les fonctions BEGIN() et END().

Dans l'appel tie(), "VARIABLE" est le nom de la variable à enchanter. "CLASSE" est le nom d'une classe implémentant des objets du type correct. Tous les arguments supplémentaires dans la "LISTE" sont passés à la méthode constructeur appropriée pour cette classe — c'est-à-dire TIESCALAR(), TIEARRAY(), TIEHASH(), ou TIEHANDLE(). (Typiquement, ce sont des arguments qui pourraient être passés à la fonction dbminit() en C.) L'objet retourné par la méthode « new » est également retourné par la fonction tie(), ce qui serait utile si vous vouliez accéder à d'autres méthodes dans "CLASSE". (Vous n'avez pas réellement à retourner une référence vers le bon « type » (par exemple, HASH ou "CLASSE") tant que c'est un objet correctement béni.) Vous pouvez également récupérer une référence vers l'objet sous-jacent en utilisant la fonction tied().

Contrairement à dbmopen(), la fonction tie() ne "utilise" ni ne "requiert" un module pour vous — vous devez le faire vous-même explicitement.

Liaison des Scalaires

Une classe implémentant un scalaire lié doit définir les méthodes suivantes : TIESCALAR, FETCH, STORE, et éventuellement UNTIE et/ou DESTROY.

Examinons chacune à tour de rôle, en utilisant comme exemple une classe de liaison pour scalaires qui permet à l'utilisateur de faire quelque chose comme :

tie $his_speed, 'Nice', getppid();
tie $my_speed,  'Nice', $$;

Et maintenant, chaque fois que ces variables sont accédées, leur priorité système actuelle est récupérée et retournée. Si ces variables sont définies, alors la priorité du processus est modifiée !

Nous utiliserons la classe BSD::Resource de Jarkko Hietaniemi <jhi@iki.fi> (non incluse) pour accéder aux constantes PRIO_PROCESS, PRIO_MIN et PRIO_MAX de votre système, ainsi qu'aux appels système getpriority() et setpriority(). Voici le préambule de la classe.

package Nice;
use Carp;
use BSD::Resource;
use strict;
$Nice::DEBUG = 0 unless defined $Nice::DEBUG;
TIESCALAR classe, LISTE
C'est le constructeur de la classe. Cela signifie qu'il est censé retourner une référence bénie vers un nouveau scalaire (probablement anonyme) qu'il crée. Par exemple : 
sub TIESCALAR {
    my $class = shift;
    my $pid = shift || $$; # 0 signifie moi
    if ($pid !~ /^\d+$/) {
        carp "Nice::Tie::Scalar got non-numeric pid $pid" if $^W;
        return undef;
    }
    unless (kill 0, $pid) { # EPERM ou ERSCH, sans doute
        carp "Nice::Tie::Scalar got bad pid $pid: $!" if $^W;
        return undef;
    }
    return bless \$pid, $class;
}

Cette classe de liaison a choisi de retourner une erreur plutôt que de lever une exception si son constructeur échoue. Bien que ce soit ainsi que fonctionne dbmopen(), d'autres classes pourraient ne pas vouloir être aussi indulgentes. Elle vérifie la variable globale $^W pour voir si elle doit émettre un peu de bruit quand même.

FETCH $self
Cette méthode sera déclenchée à chaque fois que la variable liée est accédée (lue). Elle ne prend aucun argument au-delà de sa propre référence, qui est l'objet représentant le scalaire que nous traitons. Comme dans cet exemple, nous utilisons juste une référence SCALAR pour l'objet scalaire lié, un simple $$self permet à la méthode d'accéder à la valeur réelle stockée. Dans notre exemple ci-dessous, cette valeur réelle est l'identifiant du processus auquel nous avons lié notre variable. 
sub FETCH {
    my $self = shift;
    confess "wrong type" unless ref $self;
    croak "usage error" if @_;
    my $nicety;
    local($!) = 0;
    $nicety = getpriority(PRIO_PROCESS, $$self);
    if ($!) { croak "getpriority failed: $!" }
    return $nicety;
}

Cette fois, nous avons décidé d'exploser (lever une exception) si le renice échoue — il n'y a pas d'autre endroit où nous pourrions retourner une erreur, et c'est probablement la bonne chose à faire.

STORE $self, valeur
Cette méthode sera déclenchée chaque fois que la variable liée est définie (affectée). Au-delà de sa propre référence, elle attend également un (et un seul) argument : la nouvelle valeur que l'utilisateur essaie d'affecter. Ne vous souciez pas de retourner une valeur de STORE ; la sémantique d'une affectation retournant la valeur affectée est implémentée avec FETCH. 
sub STORE {
    my $self = shift;
    confess "wrong type" unless ref $self;
    my $new_nicety = shift;
    croak "usage error" if @_;
    if ($new_nicety < PRIO_MIN) {
        carp sprintf
          "WARNING: priority %d less than minimum system priority %d",
              $new_nicety, PRIO_MIN if $^W;
        $new_nicety = PRIO_MIN;
    }
    if ($new_nicety > PRIO_MAX) {
        carp sprintf
          "WARNING: priority %d greater than maximum system priority %d",
              $new_nicety, PRIO_MAX if $^W;
        $new_nicety = PRIO_MAX;
    }
    unless (defined setpriority(PRIO_PROCESS,
                                $$self,
                                $new_nicety))
    {
        confess "setpriority failed: $!";
    }
}
UNTIE $self
Cette méthode sera déclenchée lorsque le "untie" se produira. Cela peut être utile si la classe doit savoir quand plus aucun appel ne sera effectué. (Sauf DESTROY bien sûr.) Voir « Le piège de "untie" » ci-dessous pour plus de détails.
DESTROY $self
Cette méthode sera déclenchée lorsque la variable liée devra être détruite. Comme pour les autres classes d'objets, une telle méthode est rarement nécessaire, car Perl désalloue automatiquement la mémoire de son objet moribond — ce n'est pas C++, vous savez. Nous utiliserons une méthode DESTROY ici à des fins de débogage uniquement. 
sub DESTROY {
    my $self = shift;
    confess "wrong type" unless ref $self;
    carp "[ Nice::DESTROY pid $$self ]" if $Nice::DEBUG;
}

Voilà à peu près tout. En fait, c'est plus que tout, car nous avons fait quelques choses bien pour des raisons de complétude, de robustesse et d'esthétique générale. Des classes TIESCALAR plus simples sont certainement possibles.

Liaison des Tableaux

Une classe implémentant un tableau ordinaire lié doit définir les méthodes suivantes : TIEARRAY, FETCH, STORE, FETCHSIZE, STORESIZE, CLEAR et peut-être UNTIE et/ou DESTROY.

FETCHSIZE et STORESIZE sont utilisés pour fournir un accès $#tableau et un équivalent scalaire scalar(@tableau).

Les méthodes POP, PUSH, SHIFT, UNSHIFT, SPLICE, DELETE, et EXISTS sont requises si l'opérateur perl avec le nom correspondant (mais en minuscules) doit opérer sur le tableau lié. La classe Tie::Array peut être utilisée comme classe de base pour implémenter les cinq premières en termes des méthodes de base ci-dessus. Les implémentations par défaut de DELETE et EXISTS dans Tie::Array font simplement un "croak".

En outre, EXTEND sera appelé lorsque perl aurait pré-étendu l'allocation dans un tableau réel.

t creation. Si vous essayez de créer un élément plus grand que la taille fixe, vous obtiendrez une exception. Par exemple :

use FixedElem_Array;
tie @array, 'FixedElem_Array', 3;
$array[0] = 'chat';  # ok.
$array[1] = 'chiens'; # exception, longueur('chiens') > 3.

Le code de préambule de la classe est le suivant :

package FixedElem_Array;
use Carp;
use strict;
TIEARRAY classname, LIST
C'est le constructeur de la classe. Cela signifie qu'il est censé retourner une référence bénie à travers laquelle le nouveau tableau (probablement une référence de tableau anonyme) sera accédé.

Dans notre exemple, juste pour vous montrer que vous n'avez pas *vraiment* à retourner une référence de tableau, nous choisirons une référence de hachage pour représenter notre objet. Un hachage fonctionne bien comme type d'enregistrement générique : le champ "{ELEMSIZE}" stockera la taille maximale des éléments autorisée, et le champ "{ARRAY}" conservera la vraie référence de tableau. Si quelqu'un en dehors de la classe essaie de déréférencer l'objet retourné (pensant sans doute que c'est une référence de tableau), il explosera. Cela suffit à montrer que vous devriez respecter la vie privée d'un objet.

sub TIEARRAY {
  my $class    = shift;
  my $elemsize = shift;
  if ( @_ || $elemsize =~ /\D/ ) {
    croak "usage: tie ARRAY, '" . __PACKAGE__ . "', elem_size";
  }
  return bless {
    ELEMSIZE => $elemsize,
    ARRAY    => [],
  }, $class;
}
FETCH this, index
Cette méthode sera déclenchée chaque fois qu'un élément individuel du tableau lié est accédé (lu). Elle prend un argument au-delà de sa référence à elle-même : l'index dont nous essayons de récupérer la valeur. 
sub FETCH {
  my $self  = shift;
  my $index = shift;
  return $self->{ARRAY}->[$index];
}

Si un index de tableau négatif est utilisé pour lire depuis un tableau, l'index sera traduit en un index positif en interne en appelant FETCHSIZE avant d'être passé à FETCH. Vous pouvez désactiver cette fonctionnalité en assignant une valeur vraie à la variable $NEGATIVE_INDICES dans la classe de tableau lié.

Comme vous l'avez peut-être remarqué, le nom de la méthode FETCH (et al.) est le même pour tous les accès, même si les constructeurs diffèrent dans leurs noms (TIESCALAR vs TIEARRAY). Bien qu'en théorie, vous puissiez avoir la même classe servant plusieurs types liés, en pratique, cela devient gênant, et il est plus simple de s'en tenir à un seul type de lien par classe.

STORE this, index, value
Cette méthode sera déclenchée chaque fois qu'un élément du tableau lié est défini (écrit). Elle prend deux arguments au-delà de sa référence à elle-même : l'index auquel nous essayons de stocker quelque chose et la valeur que nous essayons d'y mettre.

Dans notre exemple, "undef" est en réalité "$self->{ELEMSIZE}" espaces, nous avons donc un peu plus de travail à faire ici :

sub STORE {
  my $self = shift;
  my( $index, $value ) = @_;
  if ( length $value > $self->{ELEMSIZE} ) {
    croak "length of $value is greater than $self->{ELEMSIZE}";
  }
  # remplir les blancs
  $self->STORESIZE( $index ) if $index > $self->FETCHSIZE();
  # justifier à droite pour conserver la taille de l'élément pour les éléments plus petits
  $self->{ARRAY}->[$index] = sprintf "%$self->{ELEMSIZE}s", $value;
}

Les index négatifs sont traités de la même manière qu'avec FETCH.

FETCHSIZE this
Retourne le nombre total d'éléments dans le tableau lié associé à l'objet *this*. (Équivalent à scalar(@array)). Par exemple : 
sub FETCHSIZE {
  my $self = shift;
  return scalar $self->{ARRAY}->@*;
}
STORESIZE this, count
Définit le nombre total d'éléments dans le tableau lié associé à l'objet *this* à *count*. Si cela rend le tableau plus grand, la représentation de la classe de "undef" doit être retournée pour les nouvelles positions. Si le tableau devient plus petit, les entrées au-delà de count doivent être supprimées.

Dans notre exemple, 'undef' est en réalité un élément contenant "$self->{ELEMSIZE}" espaces. Observez :

sub STORESIZE {
  my $self  = shift;
  my $count = shift;
  if ( $count > $self->FETCHSIZE() ) {
    foreach ( $count - $self->FETCHSIZE() .. $count ) {
      $self->STORE( $_, '' );
    }
  } elsif ( $count < $self->FETCHSIZE() ) {
    foreach ( 0 .. $self->FETCHSIZE() - $count - 2 ) {
      $self->POP();
    }
  }
}
EXTEND this, count
Appel informatif indiquant que le tableau est susceptible de croître pour avoir *count* entrées. Peut être utilisé pour optimiser l'allocation. Cette méthode n'a rien à faire.

Dans notre exemple, il n'y a aucune raison d'implémenter cette méthode, nous la laissons donc comme un no-op. Cette méthode n'est pertinente que pour les implémentations de tableaux liés où il est possible que la taille allouée du tableau soit plus grande que ce qui est visible par un programmeur Perl inspectant la taille du tableau. De nombreuses implémentations de tableaux liés n'auront aucune raison de l'implémenter.

sub EXTEND {   
  my $self  = shift;
  my $count = shift;
  # rien à voir ici, circulez.
}

NOTE : Il est généralement une erreur de rendre cette méthode équivalente à STORESIZE. Perl peut appeler EXTEND de temps en temps sans vouloir réellement modifier la taille du tableau directement. Tout tableau lié devrait fonctionner correctement si cette méthode est un no-op, même s'il pourrait ne pas être aussi efficace que s'il l'implémentait.

EXISTS this, key
Vérifie si l'élément à l'index *key* existe dans le tableau lié *this*.

Dans notre exemple, nous déterminerons que si un élément ne consiste qu'en "$self->{ELEMSIZE}" espaces, il n'existe pas :

sub EXISTS {
  my $self  = shift;
  my $index = shift;
  return 0 if ! defined $self->{ARRAY}->[$index] ||
              $self->{ARRAY}->[$index] eq ' ' x $self->{ELEMSIZE};
  return 1;
}
DELETE this, key
Supprime l'élément à l'index *key* du tableau lié *this*.

Dans notre exemple, un élément supprimé est constitué de "$self->{ELEMSIZE}" espaces :

sub DELETE {
  my $self  = shift;
  my $index = shift;
  return $self->STORE( $index, '' );
}
CLEAR this
Vide (supprime, efface, ...) toutes les valeurs du tableau lié associé à l'objet *this*. Par exemple : 
sub CLEAR {
  my $self = shift;
  return $self->{ARRAY} = [];
}
PUSH this, LIST
Ajoute les éléments de *LIST* à la fin du tableau. Par exemple : 
sub PUSH {  
  my $self = shift;
  my @list = @_;
  my $last = $self->FETCHSIZE();
  $self->STORE( $last + $_, $list[$_] ) foreach 0 .. $#list;
  return $self->FETCHSIZE();
}
POP this
Supprime le dernier élément du tableau et le retourne. Par exemple : 
sub POP {
  my $self = shift;
  return pop $self->{ARRAY}->@*;
}
SHIFT this
Supprime le premier élément du tableau (décalant les autres éléments vers le bas) et le retourne. Par exemple : 
sub SHIFT {
  my $self = shift;
  return shift $self->{ARRAY}->@*;
}
UNSHIFT this, LIST
Insère les éléments de LIST au début du tableau, déplaçant les éléments existants vers le haut pour faire de la place. Par exemple : 
sub UNSHIFT {
  my $self = shift;
  my @list = @_;
  my $size = scalar( @list );
  # faire de la place pour notre liste
  $self->{ARRAY}[ $size .. $self->{ARRAY}->$#* + $size ]->@*
   = $self->{ARRAY}->@*
  $self->STORE( $_, $list[$_] ) foreach 0 .. $#list;
}
SPLICE this, offset, length, LIST
Exécute l'équivalent de "splice" sur le tableau.

offset est optionnel et vaut zéro par défaut, les valeurs négatives comptent à partir de la fin du tableau.

length est optionnel et vaut le reste du tableau par défaut.

LIST peut être vide.

Retourne une liste des éléments d'origine de *length* à *offset*.

Dans notre exemple, nous utiliserons un petit raccourci s'il y a une *LIST* :

sub SPLICE {
  my $self   = shift;
  my $offset = shift || 0;
  my $length = shift || $self->FETCHSIZE() - $offset;
  my @list   = (); 
  if ( @_ ) {
    tie @list, __PACKAGE__, $self->{ELEMSIZE};
    @list   = @_;
  }
  return splice $self->{ARRAY}->@*, $offset, $length, @list;
}
UNTIE this
Sera appelé lorsque "untie" se produit. (Voir "Le piège de "untie"" ci-dessous.)
DESTROY this
Cette méthode sera déclenchée lorsque la variable liée doit être détruite. Comme avec la classe de lien scalaire, cela n'est presque jamais nécessaire dans un langage qui gère lui-même la collecte de mémoire, donc cette fois, nous allons simplement l'omettre.

Liaison de Hachages

Les hachages ont été le premier type de données Perl à être lié (voir dbmopen()). Une classe implémentant un hachage lié doit définir les méthodes suivantes : TIEHASH est le constructeur. FETCH et STORE accèdent aux paires clé et valeur. EXISTS indique si une clé est présente dans le hachage, et DELETE en supprime une. CLEAR vide le hachage en supprimant toutes les paires clé et valeur. FIRSTKEY et NEXTKEY implémentent les fonctions keys() et each() pour itérer sur toutes les clés. SCALAR est déclenché lorsque le hachage lié est évalué dans un contexte scalaire, et à partir de la version 5.28, par "keys" dans un contexte booléen. UNTIE est appelé lorsque "untie" se produit, et DESTROY est appelé lorsque la variable liée est collectée par le ramasse-miettes.

Si cela semble beaucoup, n'hésitez pas à hériter de la simple classe standard Tie::StdHash pour la plupart de vos méthodes, en redéfinissant seulement celles qui vous intéressent. Voir Tie::Hash pour plus de détails.

Rappelez-vous que Perl fait la distinction entre une clé qui n'existe pas dans le hachage, et la

clés présentes dans la table de hachage mais ayant une valeur correspondante de "undef". Les deux possibilités peuvent être testées avec les fonctions exists() et defined().

Voici un exemple d'une classe de table de hachage liée intéressante : elle vous donne une table de hachage représentant les fichiers dot d'un utilisateur particulier. Vous indexez dans la table de hachage avec le nom du fichier (moins le point) et vous obtenez le contenu de ce fichier dot. Par exemple :

use DotFiles;
tie %dot, 'DotFiles';
if ( $dot{profile} =~ /MANPATH/ ||
     $dot{login}   =~ /MANPATH/ ||
     $dot{cshrc}   =~ /MANPATH/    )
{
    print "you seem to set your MANPATH\n";
}

Ou voici un autre exemple d'utilisation de notre classe liée :

tie %him, 'DotFiles', 'daemon';
foreach $f ( keys %him ) {
    printf "daemon dot file %s is size %d\n",
        $f, length $him{$f};
}

Dans notre exemple de table de hachage liée DotFiles, nous utilisons une table de hachage régulière pour l'objet contenant plusieurs champs importants, dont seul le champ "{LIST}" sera ce que l'utilisateur considère comme la vraie table de hachage.

USER
dont les fichiers dot cet objet représente
HOME
où ces fichiers dot résident
CLOBBER
si nous devons essayer de modifier ou de supprimer ces fichiers dot
LIST
la table de hachage des noms de fichiers dot et des mappings de contenu

Voici le début de Dotfiles.pm :

package DotFiles;
use Carp;
sub whowasi { (caller(1))[3] . '()' }
my $DEBUG = 0;
sub debug { $DEBUG = @_ ? shift : 1 }

Pour notre exemple, nous voulons pouvoir émettre des informations de débogage pour aider au traçage pendant le développement. Nous conservons également une fonction utilitaire interne pour aider à afficher des avertissements ; whowasi() renvoie le nom de la fonction qui l'appelle.

Voici les méthodes pour la table de hachage liée DotFiles.

TIEHASH classname, LIST
Ceci est le constructeur de la classe. Cela signifie qu'il est censé renvoyer une référence bénie à travers laquelle le nouvel objet (probablement, mais pas nécessairement, une table de hachage anonyme) sera accédé.

Voici le constructeur :

sub TIEHASH {
    my $class = shift;
    my $user = shift || $>;
    my $dotdir = shift || '';
    croak "usage: @{[&whowasi]} [USER [DOTDIR]]" if @_;
    $user = getpwuid($user) if $user =~ /^\d+$/;
    my $dir = (getpwnam($user))[7]
            || croak "@{[&whowasi]}: no user $user";
    $dir .= "/$dotdir" if $dotdir;
    my $node = {
        USER    => $user,
        HOME    => $dir,
        LIST    => {},
        CLOBBER => 0,
    };
    opendir(DIR, $dir)
            || croak "@{[&whowasi]}: can't opendir $dir: $!";
    foreach $dot ( grep /^\./ && -f "$dir/$_", readdir(DIR)) {
        $dot =~ s/^\.//;
        $node->{LIST}{$dot} = undef;
    }
    closedir DIR;
    return bless $node, $class;
}

Il est probablement utile de mentionner que si vous allez tester les valeurs de retour de readdir avec des tests de fichier, vous feriez mieux de préfixer le répertoire en question. Sinon, parce que nous ne nous sommes pas chdir() là-bas, cela aurait testé le mauvais fichier.

FETCH this, key
Cette méthode sera déclenchée chaque fois qu'un élément de la table de hachage liée est accédé (lu). Elle prend un argument au-delà de sa référence de soi : la clé dont nous essayons de récupérer la valeur.

Voici la récupération pour notre exemple DotFiles.

sub FETCH {
    carp &whowasi if $DEBUG;
    my $self = shift;
    my $dot = shift;
    my $dir = $self->{HOME};
    my $file = "$dir/.$dot";
    unless (exists $self->{LIST}->{$dot} || -f $file) {
        carp "@{[&whowasi]}: no $dot file" if $DEBUG;
        return undef;
    }
    if (defined $self->{LIST}->{$dot}) {
        return $self->{LIST}->{$dot};
    } else {
        return $self->{LIST}->{$dot} = `cat $dir/.$dot`;
    }
}

Il était facile de l'écrire en appelant la commande Unix cat(1), mais il serait probablement plus portable d'ouvrir le fichier manuellement (et un peu plus efficace). Bien sûr, comme les fichiers dot sont un concept Unix, nous ne sommes pas si préoccupés.

STORE this, key, value
Cette méthode sera déclenchée chaque fois qu'un élément de la table de hachage liée est défini (écrit). Elle prend deux arguments au-delà de sa référence de soi : l'index auquel nous essayons de stocker quelque chose et la valeur que nous essayons d'y mettre.

Ici, dans notre exemple DotFiles, nous ferons attention à ne pas les laisser essayer de réécrire le fichier à moins qu'ils n'aient appelé la méthode clobber() sur la référence d'objet d'origine renvoyée par tie().

sub STORE {
    carp &whowasi if $DEBUG;
    my $self = shift;
    my $dot = shift;
    my $value = shift;
    my $file = $self->{HOME} . "/.$dot";
    my $user = $self->{USER};
    croak "@{[&whowasi]}: $file not clobberable"
        unless $self->{CLOBBER};
    open(my $f, '>', $file) || croak "can't open $file: $!";
    print $f $value;
    close($f);
}

S'ils voulaient écraser quelque chose, ils pourraient dire :

$ob = tie %daemon_dots, 'daemon';
$ob->clobber(1);
$daemon_dots{signature} = "A true daemon\n";

Une autre façon de mettre la main sur une référence à l'objet sous-jacent est d'utiliser la fonction tied(), donc ils pourraient alternativement avoir défini clobber en utilisant :

tie %daemon_dots, 'daemon';
tied(%daemon_dots)->clobber(1);

La méthode clobber est simplement :

sub clobber {
    my $self = shift;
    $self->{CLOBBER} = @_ ? shift : 1;
}
DELETE this, key
Cette méthode est déclenchée lorsque nous supprimons un élément de la table de hachage, généralement à l'aide de la fonction delete(). Encore une fois, nous ferons attention à vérifier si elles veulent vraiment écraser des fichiers. 
sub DELETE   {
    carp &whowasi if $DEBUG;
    my $self = shift;
    my $dot = shift;
    my $file = $self->{HOME} . "/.$dot";
    croak "@{[&whowasi]}: won't remove file $file"
        unless $self->{CLOBBER};
    delete $self->{LIST}->{$dot};
    my $success = unlink($file);
    carp "@{[&whowasi]}: can't unlink $file: $!" unless $success;
    $success;
}

La valeur renvoyée par DELETE devient la valeur de retour de l'appel à delete(). Si vous souhaitez émuler le comportement normal de delete(), vous devez renvoyer ce que FETCH aurait renvoyé pour cette clé. Dans cet exemple, nous avons plutôt choisi de renvoyer une valeur qui indique à l'appelant si le fichier a été supprimé avec succès.

CLEAR this
Cette méthode est déclenchée lorsque toute la table de hachage doit être effacée, généralement en lui assignant la liste vide.

Dans notre exemple, cela supprimerait tous les fichiers dot de l'utilisateur ! C'est une chose tellement dangereuse qu'ils devront définir CLOBBER à quelque chose de plus élevé que 1 pour que cela se produise.

sub CLEAR    {
    carp &whowasi if $DEBUG;
    my $self = shift;
    croak "@{[&whowasi]}: won't remove all dot files for $self->{USER}"
        unless $self->{CLOBBER} > 1;
    my $dot;
    foreach $dot ( keys $self->{LIST}->%* ) {
        $self->DELETE($dot);
    }
}
EXISTS this, key
Cette méthode est déclenchée lorsque l'utilisateur utilise la fonction exists() sur une table de hachage particulière. Dans notre exemple, nous examinerons l'élément de table de hachage "{LIST}" pour cela : 
sub EXISTS   {
    carp &whowasi if $DEBUG;
    my $self = shift;
    my $dot = shift;
    return exists $self->{LIST}->{$dot};
}
FIRSTKEY this
Cette méthode sera déclenchée lorsque l'utilisateur va itérer sur la table de hachage, par exemple via un appel keys(), values() ou each(). 
sub FIRSTKEY {
    carp &whowasi if $DEBUG;
    my $self = shift;
    my $x = keys $self->{LIST}->%*;  # reset each() iterator
    each $self->{LIST}->%*
}

FIRSTKEY est toujours appelé dans un contexte scalaire et il doit simplement renvoyer la première clé. values(), et each() dans un contexte de liste, appelleront FETCH pour les clés renvoyées.

NEXTKEY this, lastkey
Cette méthode est déclenchée lors d'une itération keys(), values() ou each(). Elle a un deuxième argument qui est la dernière clé qui a été accédée. Ceci est utile si vous vous souciez de l'ordre ou si vous appelez l'itérateur à partir de plus d'une séquence, ou si vous ne stockez pas vraiment les choses dans une table de hachage quelque part.

NEXTKEY est toujours appelé dans un contexte scalaire et il doit simplement renvoyer la clé suivante. values(), et each() dans un contexte de liste, appelleront FETCH pour les clés renvoyées.

Pour notre exemple, nous utilisons une vraie table de hachage donc nous ferons juste la chose simple, mais nous devrons passer par le champ LIST indirectement.

sub NEXTKEY  {
    carp &whowasi if $DEBUG;
    my $self = shift;
    return each $self->{LIST}->%*
}

Si l'objet sous-jacent de votre table de hachage liée n'est pas une vraie table de hachage et que vous n'avez pas "each" disponible, alors vous devriez renvoyer "undef" ou la liste vide une fois que vous avez atteint la fin de votre liste de clés. Voir "la documentation propre à each" pour plus de détails.

SCALAR this
Ceci est appelé lorsque la table de hachage est évaluée dans un contexte scalaire, et à partir de la version 5.28, par "keys" dans un contexte booléen. Pour imiter le comportement des tables de hachage non liées, cette méthode doit renvoyer une valeur qui, lorsqu'elle est utilisée comme booléen, indique si la table de hachage liée est considérée comme vide. Si cette méthode n'existe pas, perl fera quelques suppositions éclairées et renverra vrai lorsque la table de hachage se trouve dans une itération. Si ce n'est pas le cas, FIRSTKEY est appelé, et le résultat sera une valeur fausse si FIRSTKEY renvoie la liste vide, vrai sinon.

Cependant, vous ne devriez **pas** vous fier aveuglément au fait que perl fasse toujours la bonne chose. En particulier, perl renverra à tort vrai lorsque vous effacez la table de hachage en appelant DELETE de manière répétée jusqu'à ce qu'elle soit vide. Il est donc conseillé de fournir votre propre méthode SCALAR lorsque vous voulez être absolument sûr que votre table de hachage se comporte correctement dans un contexte scalaire.

="Pp">Dans notre exemple, nous pouvons simplement appeler "scalar" sur le hachage sous-jacent référencé par "$self->{LIST}" :

sub SCALAR {
    carp &whowasi if $DEBUG;
    my $self = shift;
    return scalar $self->{LIST}->%*
}

NOTE : Dans perl 5.25, le comportement de scalar %hash sur un hachage non lié a changé pour retourner le nombre de clés. Avant cela, il retournait une chaîne contenant des informations sur la configuration des buckets du hachage. Voir "bucket_ratio" dans Hash::Util pour une voie de compatibilité ascendante.

UNTIE ce
Ceci est appelé lorsque "untie" se produit. Voir "Le piège "untie"" ci-dessous.
DESTROY ce
Cette méthode est déclenchée lorsqu'un hachage lié est sur le point de sortir de portée. Vous n'en avez pas vraiment besoin à moins d'essayer d'ajouter du débogage ou d'avoir un état auxiliaire à nettoyer. Voici une fonction très simple : 
sub DESTROY  {
    carp &whowasi if $DEBUG;
}

Notez que les fonctions telles que keys() et values() peuvent retourner des listes énormes lorsqu'elles sont utilisées sur de grands objets, comme les fichiers DBM. Vous préférerez peut-être utiliser la fonction each() pour itérer dessus. Exemple :

# imprimer les décalages du fichier d'historique
use NDBM_File;
tie(%HIST, 'NDBM_File', '/usr/lib/news/history', 1, 0);
while (($key,$val) = each %HIST) {
    print $key, ' = ', unpack('L',$val), "\n";
}
untie(%HIST);

Lier des handles de fichiers

Ceci est partiellement implémenté maintenant.

Une classe implémentant un handle de fichier lié doit définir les méthodes suivantes : TIEHANDLE, au moins une parmi PRINT, PRINTF, WRITE, READLINE, GETC, READ, et éventuellement CLOSE, UNTIE et DESTROY. La classe peut également fournir : BINMODE, OPEN, EOF, FILENO, SEEK, TELL - si les opérateurs perl correspondants sont utilisés sur le handle.

Lorsque STDERR est lié, sa méthode PRINT sera appelée pour émettre des avertissements et des messages d'erreur. Cette fonctionnalité est temporairement désactivée pendant l'appel, ce qui signifie que vous pouvez utiliser warn() dans PRINT sans démarrer une boucle récursive. Et tout comme les gestionnaires "__WARN__" et "__DIE__", la méthode PRINT de STDERR peut être appelée pour signaler des erreurs de parseur, donc les mises en garde mentionnées sous "%SIG" dans perlvar s'appliquent.

Tout cela est particulièrement utile lorsque perl est intégré dans un autre programme, où la sortie vers STDOUT et STDERR peut devoir être redirigée d'une manière spéciale. Voir nvi et le module Apache pour des exemples.

Lors de la liaison d'un handle, le premier argument de "tie" doit commencer par un astérisque. Ainsi, si vous liez STDOUT, utilisez *STDOUT. Si vous l'avez assigné à une variable scalaire, disons $handle, utilisez *$handle. "tie $handle" lie la variable scalaire $handle, pas le handle qu'elle contient.

Dans notre exemple, nous allons créer un handle qui crie.

package Shout;
TIEHANDLE nom_classe, LISTE
C'est le constructeur de la classe. Cela signifie qu'il est censé retourner une référence bénie d'une sorte. La référence peut être utilisée pour conserver des informations internes. 
sub TIEHANDLE { print "<shout>\n"; my $i; bless \$i, shift }
WRITE ce, LISTE
Cette méthode sera appelée lorsque le handle est écrit via la fonction "syswrite". 
sub WRITE {
    $r = shift;
    my($buf,$len,$offset) = @_;
    print "WRITE appelé, \$buf=$buf, \$len=$len, \$offset=$offset";
}
PRINT ce, LISTE
Cette méthode sera déclenchée à chaque fois que le handle lié est imprimé avec les fonctions print() ou say(). Au-delà de sa référence propre, elle attend également la liste qui a été passée à la fonction print. 
sub PRINT { $r = shift; $$r++; print join($,,map(uc($_),@_)),$\ }

say() fonctionne comme print() sauf que $\ sera localisé à "\n", vous n'avez donc rien de spécial à faire pour gérer say() dans PRINT().

PRINTF ce, LISTE
Cette méthode sera déclenchée à chaque fois que le handle lié est imprimé avec la fonction printf(). Au-delà de sa référence propre, elle attend également le format et la liste qui ont été passés à la fonction printf. 
sub PRINTF {
    shift;
    my $fmt = shift;
    print sprintf($fmt, @_);
}
READ ce, LISTE
Cette méthode sera appelée lorsque le handle est lu via les fonctions "read" ou "sysread". 
sub READ {
  my $self = shift;
  my $bufref = \$_[0];
  my(undef,$len,$offset) = @_;
  print "READ appelé, \$buf=$bufref, \$len=$len, \$offset=$offset";
  # ajouter à $$bufref, définir $len au nombre de caractères lus
  $len;
}
READLINE ce
Cette méthode est appelée lorsque le handle est lu via "<HANDLE>" ou "readline HANDLE".

Conformément à "readline", en contexte scalaire, elle doit retourner la ligne suivante, ou "undef" s'il n'y a plus de données. En contexte de liste, elle doit retourner toutes les lignes restantes, ou une liste vide s'il n'y a plus de données. Les chaînes retournées doivent inclure le séparateur d'enregistrement d'entrée $/ (voir perlvar), sauf s'il est "undef" (ce qui signifie mode "slurp").

sub READLINE {
  my $r = shift;
  if (wantarray) {
    return ("toutes les lignes restantes\n",
            "jusqu'à la fin\n");
  } else {
    return "READLINE appelé " . ++$$r . " fois\n";
  }
}
GETC ce
Cette méthode sera appelée lorsque la fonction "getc" est appelée. 
sub GETC { print "N'utilisez pas GETC, utilisez Perl"; return "a"; }
EOF ce
Cette méthode sera appelée lorsque la fonction "eof" est appelée.

À partir de Perl 5.12, un paramètre entier supplémentaire sera passé. Il sera zéro si "eof" est appelé sans paramètre ; 1 si "eof" reçoit un handle de fichier en paramètre, par exemple eof(FH) ; et 2 dans le cas très spécial où le handle lié est "ARGV" et "eof" est appelé avec une liste de paramètres vide, par exemple eof().

sub EOF { not length $stringbuf }
CLOSE ce
Cette méthode sera appelée lorsque le handle est fermé via la fonction "close". 
sub CLOSE { print "CLOSE appelé.\n" }
UNTIE ce
Comme pour les autres types de liaisons, cette méthode sera appelée lors de l'"untie". Il peut être approprié de "fermer automatiquement" lorsque cela se produit. Voir "Le piège "untie"" ci-dessous.
DESTROY ce
Comme pour les autres types de liaisons, cette méthode sera appelée lorsque le handle lié est sur le point d'être détruit. Ceci est utile pour le débogage et éventuellement le nettoyage. 
sub DESTROY { print "</shout>\n" }

Voici comment utiliser notre petit exemple :

tie(*FOO,'Shout');
print FOO "bonjour\n";
$x = 4; $y = 6;
print FOO $x, " plus ", $y, " égal ", $x + $y, "\n";
print <FOO>;

UNTIE ce

Vous pouvez définir pour tous les types de liaisons une méthode UNTIE qui sera appelée lors de untie(). Voir "Le piège "untie"" ci-dessous.

Le piège "untie"

Si vous avez l'intention d'utiliser l'objet retourné par tie() ou tied(), et si la classe de liaison cible définit un destructeur, il y a un piège subtil que vous *devez* éviter.

Comme configuration, considérons cet exemple (certes assez artificiel) d'une liaison ; tout ce qu'il fait est d'utiliser un fichier pour conserver un journal des valeurs assignées à un scalaire.

package Remember;
use v5.36;
use IO::File;
sub TIESCALAR {
    my $class = shift;
    my $filename = shift;
    my $handle = IO::File->new( "> $filename" )
                     or die "Impossible d'ouvrir $filename : $!\n";
    print $handle "Le début\n";
    bless {FH => $handle, Value => 0}, $class;
}
sub FETCH {
    my $self = shift;
    return $self->{Value};
}
sub STORE {
    my $self = shift;
    my $value = shift;
    my $handle = $self->{FH};
    print $handle "$value\n";
    $self->{Value} = $value;
}
sub DESTROY {
    my $self = shift;
    my $handle = $self->{FH};
    print $handle "La fin\n";
    close $handle;
}
1;

Voici un exemple qui utilise cette liaison :

use strict;
use Remember;
my $fred;
tie $fred, 'Remember', 'myfile.txt';
$fred = 1;
$fred = 4;
$fred = 5;
untie $fred;
system "cat myfile.txt";

Ceci est la sortie lorsqu'il est exécuté :

Le début
1
4
5
La fin

Jusqu'ici tout va bien. Ceux qui ont prêté attention auront remarqué que l'objet lié n'a pas encore été utilisé. Ajoutons donc une méthode supplémentaire à la classe Remember pour permettre l'inclusion de commentaires dans le fichier ; disons, quelque chose comme ceci :

sub comment {
    my $self = shift;
    my $text = shift;
    my $handle = $self->{FH};
    print $handle $text, "\n";
}

Et voici l'exemple précédent modifié

perltie(1) - Perl Tie

NAME

perltie - Perl tie - interface à Perl pour lier des objets à des types de données Perl

SYNOPSIS

use Tie::Hash;
tie %hash, 'MyTieHash', @args;
tie @array, 'MyTieArray', @args;
tie $scalar, 'MyTieScalar', @args;
tie $fh, 'MyTieHandle', @args;
untie %hash;
untie @array;
untie $scalar;
untie $fh;

DESCRIPTION

La fonction tie vous permet de lier un scalaire, un tableau ou une table de hachage existante à un objet de votre propre classe. Cet objet se substitue au comportement normal de Perl pour ce type de données. La classe doit implémenter une ou plusieurs des méthodes TIESCALAR, TIEARRAY, ou TIEHASH, et les méthodes spécifiques au type de données lié (par exemple, FETCH pour TIEHASH, STORE pour TIEHASH, etc.). La fonction untie détache l'objet lié du scalaire, du tableau ou de la table de hachage.

Voici un exemple simple d'un tableau lié à un fichier qui enregistre ses modifications :

package FileArray;
use strict;
use vars qw(@ISA);
@ISA = qw(Exporter);
my %files;
sub TIEARRAY {
    my ($class, $filename) = @_;
    my $self = bless { filename => $filename }, $class;
    files{$filename} = $self;
    open FH, "<$filename" or die "can't open $filename: $!";
    while (<FH>) {
        push @$self, $_;
    }
    close FH;
    return $self;
}
sub STORE {
    my ($self, $index, $value) = @_;
    $self->{'_array'}[$index] = $value;
    $self->write_file;
}
sub PUSH {
    my ($self, $value) = @_;
    push @{$self->{'_array'}}, $value;
    $self->write_file;
}
sub write_file {
    my $self = shift;
    open FH, ">$self->{filename}" or die "can't open $self->{filename}: $!";
    print FH @{$self->{'_array'}};
    close FH;
}
sub DESTROY {
    my $self = shift;
    # A l'aide de DESTROY, on garantit que le fichier est fermé.
    # Si le programme se termine sans appeler untie, le fichier sera toujours fermé.
    unlink $self->{filename};
}
sub CLEAR {
    my $self = shift;
    @{$self->{'_array'}} = ();
    $self->write_file;
}
sub STORE {
    my ($self, $index, $value) = @_;
    $self->{'_array'}[$index] = $value;
    $self->write_file;
}
sub PUSH {
    my ($self, $value) = @_;
    push @{$self->{'_array'}}, $value;
    $self->write_file;
}
# ... et ainsi de suite pour les autres méthodes d'accès aux tableaux ...
1;

Un script d'utilisation typique pourrait ressembler à ceci :

use FileArray;
my @lines;
my $fa = tie @lines, 'FileArray', 'lines.txt';
@lines = ( "première ligne\n", "seconde ligne\n");
push @lines, "troisième ligne\n";
untie @lines;
system "cat lines.txt";

L'utilisation de untie désassocie le tableau lié et appelle la méthode DESTROY de l'objet lié, qui dans ce cas supprime le fichier lines.txt. La sortie de cat lines.txt sera vide.

Il est également possible d'utiliser la méthode "comment" (qui nécessite l'objet lié) :

use strict;
use Remember;
my ($fred, $x);
$x = tie $fred, 'Remember', 'myfile.txt';
$fred = 1;
$fred = 4;
comment $x "changing...";
$fred = 5;
untie $fred;
system "cat myfile.txt";

Lorsque ce code est exécuté, il n'y a pas de sortie. Voici pourquoi :

Lorsqu'une variable est liée, elle est associée à l'objet qui est la valeur de retour de la fonction TIESCALAR, TIEARRAY ou TIEHASH. Cet objet ne possède normalement qu'une seule référence, à savoir la référence implicite de la variable liée. Lorsque untie() est appelée, cette référence est détruite. Ensuite, comme dans le premier exemple ci-dessus, le destructeur de l'objet (DESTROY) est appelé, ce qui est normal pour les objets qui n'ont plus de références valides ; et ainsi le fichier est fermé.

Dans le second exemple, cependant, nous avons stocké une autre référence à l'objet lié dans $x. Cela signifie que lorsque untie() sera appelée, il y aura toujours une référence valide à l'objet en existence, donc le destructeur ne sera pas appelé à ce moment-là, et ainsi le fichier ne sera pas fermé. La raison pour laquelle il n'y a pas de sortie est que les tampons du fichier n'ont pas été vidés sur le disque.

Maintenant que vous connaissez le problème, que pouvez-vous faire pour l'éviter ? Avant l'introduction de la méthode facultative UNTIE, la seule façon était le bon vieux drapeau . Cela repérera toutes les instances où vous appelez untie() et où il existe encore des références valides à l'objet lié. Si le second script ci-dessus avait en haut "use warnings 'untie'" ou était exécuté avec le drapeau , Perl affiche ce message d'avertissement :

untie attempted while 1 inner references still exist

Pour que le script fonctionne correctement et pour faire taire l'avertissement, assurez-vous qu'il n'y a plus de références valides à l'objet lié *avant* que untie() ne soit appelée :

undef $x;
untie $fred;

Maintenant qu'UNTIE existe, le concepteur de classe peut décider quelles parties des fonctionnalités de la classe sont réellement associées à "untie" et quelles parties sont associées à la destruction de l'objet. Ce qui a du sens pour une classe donnée dépend du fait que les références internes soient conservées afin que des méthodes non liées à la liaison puissent être appelées sur l'objet. Mais dans la plupart des cas, il est probablement judicieux de déplacer la fonctionnalité qui aurait été dans DESTROY vers la méthode UNTIE.

Si la méthode UNTIE existe, l'avertissement ci-dessus ne se produit pas. Au lieu de cela, la méthode UNTIE reçoit le nombre de références « supplémentaires » et peut émettre son propre avertissement si nécessaire. Par exemple, pour reproduire le cas sans UNTIE, cette méthode peut être utilisée :

sub UNTIE
{
 my ($obj,$count) = @_;
 carp "untie attempted while $count inner references still exist"
                                                             if $count;
}

Voir DB_File ou Config pour des implémentations intéressantes de tie(). Un bon point de départ pour de nombreuses implémentations de tie() est l'un des modules Tie::Scalar, Tie::Array, Tie::Hash, ou Tie::Handle.

BUGS

Le retour normal fourni par scalar(%hash) n'est pas disponible. Ce que cela signifie, c'est que l'utilisation de La localisation des tableaux ou tables de hachage liés ne fonctionne pas. Après avoir quitté la portée, les tableaux ou les tables de hachage ne sont pas restaurés.

Le comptage du nombre d'entrées dans une table de hachage via "scalar(keys(%hash))" ou scalar(values(%hash)) est inefficace car il doit itérer sur toutes les entrées avec FIRSTKEY/NEXTKEY.

Les tranches de table de hachage/tableau liées provoquent plusieurs paires FETCH/STORE, il n'existe pas de méthodes de liaison pour les opérations de tranche.

Vous ne pouvez pas facilement lier une structure de données multiniveau (comme une table de hachage de tables de hachage) à un fichier dbm. Le premier problème est que tous, sauf GDBM et Berkeley DB, ont des limitations de taille, mais au-delà de cela, vous avez également des problèmes avec la manière dont les références doivent être représentées sur disque. Un module qui tente de répondre à ce besoin est DBM::Deep. Consultez votre site CPAN le plus proche, comme décrit dans perlmodlib, pour le code source. Notez que malgré son nom, DBM::Deep n'utilise pas dbm. Une autre tentative antérieure pour résoudre le problème est MLDBM, qui est également disponible sur CPAN, mais qui a des limitations assez sérieuses.

Les descripteurs de fichiers liés sont toujours incomplets. sysopen(), truncate(), flock(), fcntl(), stat() et -X ne peuvent actuellement pas être interceptés.
