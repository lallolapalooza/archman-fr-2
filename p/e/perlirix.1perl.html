PERLIRIX(1perl) Guide du programmeur Perl PERLIRIX(1perl)

NOM

perlirix - Perl version 5 sur systèmes Irix

DESCRIPTION

Ce document décrit diverses fonctionnalités d'Irix qui affecteront la compilation et/ou l'exécution de Perl version 5 (ci-après dénommé Perl).

Compilation de Perl 32-bit sous Irix

Utilisez

sh Configure -Dcc='cc -n32'

pour compiler Perl en 32 bits. N'utilisez pas -n32 sauf si vous avez des compilateurs version 7.1 ou ultérieure (utilisez cc -version pour vérifier).

(La compilation avec 'cc -n32' est la valeur par défaut.)

Compilation de Perl 64-bit sous Irix

Utilisez

sh Configure -Dcc='cc -64' -Duse64bitint

Ceci nécessite un CPU MIPS 64 bits (R8000, R10000, ...).

Vous pouvez également utiliser

sh Configure -Dcc='cc -64' -Duse64bitall

mais cela ne fait aucune différence par rapport à -Duse64bitint en raison de "cc -64".

Vous pouvez également faire

sh Configure -Dcc='cc -n32' -Duse64bitint

pour utiliser les 'long longs' pour le type entier 64 bits, au cas où vous n'auriez pas de CPU 64 bits.

Si vous utilisez gcc, juste

sh Configure -Dcc=gcc -Duse64bitint

devrait suffire, Configure devrait automatiquement rechercher les réglages 64 bits corrects.

Concernant les versions de compilateurs d'Irix

Certaines versions de cc Irix, par exemple 7.3.1.1m (essayez cc -version) ont été connues pour avoir des problèmes (core dumps) lors de la compilation de perl.c. Si vous avez utilisé -OPT:fast_io=ON et que cela se produit, essayez de le supprimer. Si cela ne fonctionne pas, ou si vous ne l'avez pas utilisé, alors essayez d'ajuster d'autres options d'optimisation (-LNO, -INLINE, -O3 à -O2, etc.). Le bug du compilateur a été signalé à SGI. (Allen Smith <easmith@beatrice.rutgers.edu>)

Problèmes de l'éditeur sous Irix

Si vous recevez des messages concernant les so_locations, recherchez dans le fichier hints/irix_6.sh les "lddflags" et effectuez les ajustements suggérés. (David Billinghurst <David.Billinghurst@riotinto.com.au>)

Malloc sous Irix

N'essayez pas d'utiliser le malloc de Perl, cela entraînera des erreurs très mystérieuses (surtout avec -Duse64bitall).

Compilation avec les threads sous Irix

Exécutez Configure avec -Duseithreads, ce qui configurera Perl avec les "threads d'interpréteur" de Perl 5.8.0, voir threads.

Pour Irix 6.2 avec les threads Perl, vous devez avoir les correctifs suivants installés :

1404 Irix 6.2 Posix 1003.1b man pages
1645 Mises à jour des fichiers d'en-tête POSIX Irix 6.2 & 6.3
2000 Modules de support POSIX 1003.1b Irix 6.2
2254 Correctifs de la bibliothèque Pthread
2401 Package cumulatif du noyau de toutes les plateformes 6.2

IMPORTANT : Sans le correctif 2401, un bug du noyau dans Irix 6.2 provoquera une panique et un crash de votre machine lors de l'exécution de Perl multithreadé. Irix 6.3 et versions ultérieures sont corrects.

Merci à Hannu Napari <Hannu.Napari@hut.fi> pour les informations sur les
correctifs pthreads IRIX.

Irix 5.3

Lors de l'exécution de Configure et lors de la compilation, vous obtiendrez probablement un certain nombre de ces avertissements :

ld:
The shared object /usr/lib/libm.so did not resolve any symbols.
      You may want to remove it from your link line.

Ignorez-les : sous IRIX 5.3, il n'y a aucun moyen de faire taire ld à ce sujet.

Pendant la compilation, vous verrez cet avertissement de toke.c :

uopt: Warning: Perl_yylex: this procedure not optimized because it
      exceeds size threshold; to optimize this procedure, use -Olimit
      option with value >= 4252.

Ignorez l'avertissement.

Sous IRIX 5.3 et avec Perl 5.8.1 (Perl 5.8.0 ne compilait pas sous IRIX 5.3), les échecs suivants sont connus.

Failed Test                  Stat Wstat Total Fail  Failed|Failing List
-----------------------------------------------------------------------
../ext/List/Util/t/shuffle.t    0   139    ??   ??       %  ??
../lib/Math/Trig.t            255 65280    29   12  41.38%  24-29
../lib/sort.t                   0   138   119   72  60.50%  48-119
56 tests and 474 subtests skipped.
Failed 3/811 test scripts, 99.63% okay. 78/75813 subtests failed,
   99.90% okay.

Ils sont suspectés d'être des erreurs de compilateur (au moins l'échec shuffle.t est connu de certaines configurations IRIX 6) et des erreurs de bibliothèque mathématique (l'échec Trig.t), mais comme IRIX 5 est depuis longtemps en fin de vie, d'autres corrections pour IRIX sont peu probables. Si vous pouvez obtenir gcc pour 5.3, vous pourriez également essayer cela, car gcc sous IRIX 6 est une solution de contournement connue pour au moins les échecs shuffle.t et sort.t.
