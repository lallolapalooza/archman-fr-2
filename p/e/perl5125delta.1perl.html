PERL5125DELTA(1perl) Guide de référence du programmeur Perl PERL5125DELTA(1perl)

NOM

perl5125delta - ce qu'il y a de nouveau dans la version perl v5.12.5

DESCRIPTION

Ce document décrit les différences entre la version 5.12.4 et la version 5.12.5.

Si vous mettez à jour depuis une version antérieure comme la 5.12.3, lisez d'abord perl5124delta, qui décrit les différences entre la 5.12.3 et la 5.12.4.

Sécurité

"Encode" decode_xs dépassement de tas sur n-octets (CVE-2011-2939)

Un bug dans "Encode" pouvait, pour certaines entrées, provoquer un débordement de tas. Ce problème a été corrigé. Bug rapporté par Robert Zacek.

File::Glob::bsd_glob() erreur mémoire avec GLOB_ALTDIRFUNC (CVE-2011-2728)

Appeler "File::Glob::bsd_glob" avec le drapeau non supporté GLOB_ALTDIRFUNC provoquait une violation d'accès / un segfault. Un programme Perl acceptant une valeur de drapeau depuis une source externe pouvait s'exposer à des attaques par déni de service ou par exécution de code arbitraire. Il n'y a pas d'exploits connus à l'état sauvage. Le problème a été corrigé en désactivant explicitement tous les drapeaux non supportés et en mettant à null les pointeurs de fonction inutilisés. Bug rapporté par Clément Lecigne.

Dépassement de tampon tas dans l'opérateur de répétition de chaîne 'x' (CVE-2012-5195)

Du code Perl mal écrit, permettant à un attaquant de spécifier le compteur pour l'opérateur de répétition de chaîne 'x' de Perl, peut déjà provoquer une attaque par déni de service par épuisement de la mémoire. Une faille dans les versions de Perl antérieures à 5.15.5 peut escalader cela en un dépassement de tampon de tas ; couplé avec des versions de glibc antérieures à 2.16, cela permet éventuellement l'exécution de code arbitraire.

Ce problème a été corrigé.

Changements incompatibles

Il n'y a pas de changements intentionnellement incompatibles avec la version 5.12.4. S'il en existe, ce sont des bugs et les rapports sont les bienvenus.

Modules et Pragmata

Modules mis à jour

B::Concise

B::Concise ne produit plus de sortie corrompue avec l'option -tree [perl #80632].

charnames

Une régression introduite dans Perl 5.8.8 a été corrigée, qui faisait que charnames::viacode(0) retournait "undef" au lieu de la chaîne "NULL" [perl #72624].

Encode a été mis à jour de la version 2.39 à la version 2.39_01

Voir "Sécurité".

File::Glob a été mis à jour de la version 1.07 à la version 1.07_01

Voir "Sécurité".

Unicode::UCD

La documentation de la fonction "upper" indique maintenant réellement "upper", pas "lower".

Module::CoreList

Module::CoreList a été mis à jour à la version 2.50_02 pour ajouter les données de cette version.

Modifications apportées à la documentation existante

perlebcdic

Le document perlebcdic contient un tableau utile à utiliser dans "tr///" pour convertir entre EBCDIC et Latin1/ASCII. Malheureusement, le tableau était l'inverse de celui qu'il décrit. Ceci a été corrigé.

perlunicode

La section sur les Mappages de Cas Définis par l'Utilisateur avait une mauvaise balisage et des phrases peu claires, rendant certaines parties illisible. Ceci a été rectifié.

perluniprops

Ce document a été corrigé pour prendre en compte les plateformes non-ASCII.

Améliorations d'installation et de configuration

Modifications spécifiques à la plateforme

Mac OS X
Des corrections de configuration et de tests ont été apportées pour que Perl se compile proprement sur Lion et Mountain Lion.
NetBSD
Le fichier d'indices NetBSD a été corrigé pour être compatible avec NetBSD 6.*

Corrections de bugs sélectionnées

  • "chop" gère maintenant correctement les caractères au-delà de "\x{7fffffff}" [perl #73246].
  • "($<,$>) = (...)" ne fonctionnait plus correctement dans 5.12.0. Il est censé effectuer un seul appel setreuid(), plutôt que d'appeler setruid() et seteuid() séparément. Par conséquent, il ne fonctionnait pas correctement. Ceci a été corrigé [perl #75212].
  • Correction d'une régression de kill() lorsqu'une variable de correspondance est utilisée pour l'ID du processus à tuer [perl #75812].
  • "UNIVERSAL::VERSION" ne fuit plus de mémoire. Elle a commencé à fuir dans Perl 5.10.0.
  • Les fonctions C "my_strftime" ne fuient plus de mémoire. Ceci corrige une fuite de mémoire dans "POSIX::strftime" [perl #73520].
  • "caller" ne fuit plus de mémoire lorsqu'il est appelé depuis le paquet DB si @DB::args était assigné après le premier appel à "caller". Carp déclenchait ce bug [perl #97010].
  • Passer à "index" un décalage au-delà de la fin de la chaîne lorsque la chaîne est encodée en interne en UTF8 ne cause plus de plantages [perl #75898].
  • Les erreurs de syntaxe dans les blocs "(?{...})" dans les expressions régulières ne provoquent plus de messages de plantage [perl #2353].
  • Perl 5.10.0 a introduit une logique défectueuse qui faisait que "U*" au milieu d'un modèle de pack était équivalent à "U0" si la chaîne d'entrée était vide. Ceci a été corrigé [perl #90160].

Errata

split() et @_

split() ne modifie plus @_ lorsqu'il est appelé en contexte scalaire ou vide. En contexte vide, il produit maintenant un avertissement "Useless use of split". Ceci est en fait un changement introduit dans perl 5.12.0, mais il a été omis du perl5120delta de cette version.

Rapport des bugs

If you find what you think is a bug, you might check the articles recently posted to the comp.lang.perl.misc newsgroup and the perl bug database at http://rt.perl.org/perlbug/ . There may also be information at http://www.perl.org/ , the Perl Home Page.

If you believe you have an unreported bug, please run the perlbug program included with your release. Be sure to trim your bug down to a tiny but sufficient test case. Your bug report, along with the output of "perl -V", will be sent off to perlbug@perl.org to be analysed by the Perl porting team.

If the bug you are reporting has security implications, which make it inappropriate to send to a publicly archived mailing list, then please send it to perl5-security-report@perl.org. This points to a closed subscription unarchived mailing list, which includes all the core committers, who be able to help assess the impact of issues, figure out a resolution, and help co-ordinate the release of patches to mitigate or fix the problem across all platforms on which Perl is supported. Please only use this address for security issues in the Perl core, not for modules independently distributed on CPAN.
