PERLFORM(1perl) Guide de référence du programmeur Perl PERLFORM(1perl)

NOM

perlform - Formats Perl

DESCRIPTION

Perl dispose d'un mécanisme pour vous aider à générer des rapports et des graphiques simples. Pour faciliter cela, Perl vous aide à coder votre page de sortie au plus près de ce à quoi elle ressemblera lorsqu'elle sera imprimée. Il peut gérer des choses comme le nombre de lignes par page, le numéro de la page, quand imprimer les en-têtes de page, etc. Les mots clés sont empruntés à FORTRAN : format() pour déclarer et write() pour exécuter ; voir leurs entrées dans perlfunc. Heureusement, la mise en page est beaucoup plus lisible, plus proche de l'instruction PRINT USING de BASIC. Considérez-le comme un nroff(1) pour les pauvres.

Les formats, comme les paquets et les sous-routines, sont déclarés plutôt qu'exécutés, ils peuvent donc apparaître n'importe où dans votre programme. (Généralement, il est préférable de les regrouper tous.) Ils ont leur propre espace de noms, distinct de tous les autres « types » de Perl. Cela signifie que si vous avez une fonction nommée « Foo », ce n'est pas la même chose qu'un format nommé « Foo ». Cependant, le nom par défaut du format associé à un descripteur de fichier donné est le même que le nom du descripteur de fichier. Ainsi, le format par défaut pour STDOUT est nommé « STDOUT », et le format par défaut pour le descripteur de fichier TEMP est nommé « TEMP ». Ils se ressemblent juste. Ils ne sont pas identiques.

Les formats d'enregistrement de sortie sont déclarés comme suit :

format NOM =
LISTE_DE_FORMAT
.

Si le nom est omis, le format « STDOUT » est défini. Un seul « . » dans la colonne 1 est utilisé pour terminer un format. LISTE_DE_FORMAT se compose d'une séquence de lignes, chacune pouvant être de l'un des trois types :

1.
Un commentaire, indiqué par un '#' dans la première colonne.
2.
Une ligne « image » donnant le format d'une ligne de sortie.
3.
Une ligne d'arguments fournissant les valeurs à insérer dans la ligne image précédente.

Les lignes d'image contiennent des définitions de champs de sortie, mélangées à du texte littéral. Ces lignes ne subissent aucune interpolation de variable. Les définitions de champs sont composées d'un ensemble de caractères, pour démarrer et étendre un champ à sa largeur désirée. C'est l'ensemble complet de caractères pour les définitions de champs :

@    début de champ régulier
^    début de champ spécial
<    caractère de remplissage pour justification à gauche
|    caractère de remplissage pour centrage
>    caractère de remplissage pour justification à droite
#    caractère de remplissage pour un champ numérique justifié à droite
0    au lieu du premier # : remplit le nombre avec des zéros en tête
.    point décimal dans un champ numérique
...  termine un champ texte, affiche « ... » comme preuve de troncature
@*   champ de largeur variable pour une valeur multi-lignes
^*   champ de largeur variable pour la ligne suivante d'une valeur multi-lignes
~    supprime la ligne lorsque tous les champs sont vides
~~   répète la ligne jusqu'à épuisement de tous les champs

Chaque champ dans une ligne d'image commence par « @ » (arobase) ou « ^ » (accent circonflexe), indiquant ce que nous appellerons, respectivement, un champ « régulier » ou « spécial ». Le choix des caractères de remplissage détermine si un champ est textuel ou numérique. Les opérateurs tilde ne font pas partie d'un champ. Examinons les différentes possibilités en détail.

Champs Texte

La longueur du champ est fournie en complétant le champ avec plusieurs caractères « < », « > », ou « | » pour spécifier un champ non numérique avec, respectivement, une justification à gauche, une justification à droite, ou un centrage. Pour un champ régulier, la valeur (jusqu'au premier retour à la ligne) est prise et imprimée selon la justification sélectionnée, tronquant les caractères excédentaires. Si vous terminez un champ texte par « ... », trois points seront affichés si la valeur est tronquée. Un champ texte spécial peut être utilisé pour effectuer un remplissage rudimentaire de blocs de texte multi-lignes ; voir « Utilisation du mode de remplissage » pour plus de détails.

Exemple :
   format STDOUT =
   @<<<<<<   @||||||   @>>>>>>
   "gauche",   "milieu", "droite"
   .
Sortie :
   gauche      milieu    droite

Champs Numériques

L'utilisation de « # » comme caractère de remplissage spécifie un champ numérique, avec justification à droite. Un « . » optionnel définit la position du point décimal. Avec un « 0 » (zéro) à la place du premier « # », le nombre formaté sera complété avec des zéros en tête si nécessaire. Un champ numérique spécial est effacé si la valeur n'est pas définie. Si la valeur résultante dépasse la largeur spécifiée, le champ est rempli de « # » comme preuve de débordement.

Exemple :
   format STDOUT =
   @###   @.###   @##.###  @###   @###   ^####
    42,   3.1415,  undef,    0, 10000,   undef
   .
Sortie :
     42   3.142     0.000     0   ####

Le Champ @* pour le Texte Multi-Lignes de Largeur Variable

Le champ « @* » peut être utilisé pour imprimer des valeurs multi-lignes non tronquées ; il devrait (mais n'est pas obligé) apparaître seul sur une ligne. Un saut de ligne final est retiré, mais tous les autres caractères sont émis tels quels.

Le Champ ^* pour le Texte Ligne par Ligne de Largeur Variable

Comme « @* », il s'agit d'un champ de largeur variable. La valeur fournie doit être une variable scalaire. Perl insère la première ligne (jusqu'au premier « \n ») du texte dans le champ, puis coupe le début de la chaîne de manière à ce que la prochaine fois que la variable sera référencée, une autre partie du texte puisse être imprimée. La variable *ne sera pas* restaurée.

Exemple :
   $text = "ligne 1\nligne 2\nligne 3";
   format STDOUT =
   Texte : ^*
         $text
   ~~    ^*
         $text
   .
Sortie :
   Texte : ligne 1
         ligne 2
         ligne 3

Spécification des Valeurs

Les valeurs sont spécifiées sur la ligne de format suivante dans le même ordre que les champs d'image. Les expressions fournissant les valeurs doivent être séparées par des virgules. Elles sont toutes évaluées dans un contexte de liste avant que la ligne ne soit traitée, de sorte qu'une seule expression de liste puisse produire plusieurs éléments de liste. Les expressions peuvent être réparties sur plusieurs lignes si elles sont entourées d'accolades. Si tel est le cas, l'accolade ouvrante doit être le premier jeton de la première ligne. Si une expression évalue à un nombre avec une partie décimale, et si l'image correspondante spécifie que la partie décimale doit apparaître dans la sortie (c'est-à-dire toute image sauf des caractères « # » multiples *sans* « . » incorporé), le caractère utilisé pour le point décimal est déterminé par la locale LC_NUMERIC actuelle si « use locale » est activé. Cela signifie que, si, par exemple, l'environnement d'exécution spécifie une locale allemande, « , » sera utilisé à la place du « . » par défaut. Voir perllocale et « AVERTISSEMENTS » pour plus d'informations.

Utilisation du Mode de Remplissage

Sur les champs texte, l'accent circonflexe active une sorte de mode de remplissage. Au lieu d'une expression arbitraire, la valeur fournie doit être une variable scalaire contenant une chaîne de texte. Perl insère la prochaine partie du texte dans le champ, puis coupe le début de la chaîne de sorte que la prochaine fois que la variable sera référencée, une autre partie du texte pourra être imprimée. (Oui, cela signifie que la variable elle-même est modifiée pendant l'exécution de l'appel write(), et n'est pas restaurée.) La prochaine partie du texte est déterminée par un algorithme rudimentaire de coupure de ligne. Vous pouvez utiliser le caractère de retour à la ligne (« \r ») pour forcer une coupure de ligne. Vous pouvez changer les caractères qui sont légaux pour la coupure en changeant la variable $: (c'est $FORMAT_LINE_BREAK_CHARACTERS si vous utilisez le module English) en une liste des caractères désirés.

Normalement, vous utiliseriez une séquence de champs dans une pile verticale associée à la même variable scalaire pour imprimer un bloc de texte. Vous pourriez souhaiter terminer le dernier champ par le texte « ... », qui apparaîtra dans la sortie si le texte était trop long pour être entièrement affiché.

Suppression des Lignes où Tous les Champs sont Vides

L'utilisation de champs accent circonflexe peut produire des lignes où tous les champs sont vides. Vous pouvez supprimer de telles lignes en plaçant un « ~

Lignes de formatage répétées

If you put two contiguous tilde characters "~~" anywhere into a line, then in addition to suppressing the line if all fields are blank, the line will be repeated until all the fields on the line are exhausted, i.e. undefined. For special (caret) text fields this will occur sooner or later, but if you use a text field of the at variety, the expression you supply had better not give the same value every time forever! (shift(@f) is a simple example that would work.) Don't use a regular (at) numeric field in such lines, because it will never go blank.

Traitement du haut de page

Top-of-form processing is by default handled by a format with the same name as the current filehandle with "_TOP" concatenated to it. It's triggered at the top of each page. See "write" in perlfunc.

Examples:

# a report on the /etc/passwd file
format STDOUT_TOP =
                        Passwd File
Name                Login    Office   Uid   Gid Home
------------------------------------------------------------------
.
format STDOUT =
@<<<<<<<<<<<<<<<<<< @||||||| @<<<<<<@>>>> @>>>> @<<<<<<<<<<<<<<<<<
$name,              $login,  $office,$uid,$gid, $home
.
# a report from a bug report form
format STDOUT_TOP =
                        Bug Reports
@<<<<<<<<<<<<<<<<<<<<<<<     @|||         @>>>>>>>>>>>>>>>>>>>>>>>
$system,                      $%,         $date
------------------------------------------------------------------
.
format STDOUT =
Subject: @<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<
         $subject
Index: @<<<<<<<<<<<<<<<<<<<<<<<<<<<< ^<<<<<<<<<<<<<<<<<<<<<<<<<<<<
       $index,                       $description
Priority: @<<<<<<<<<< Date: @<<<<<<< ^<<<<<<<<<<<<<<<<<<<<<<<<<<<<
          $priority,        $date,   $description
From: @<<<<<<<<<<<<<<<<<<<<<<<<<<<<< ^<<<<<<<<<<<<<<<<<<<<<<<<<<<<
      $from,                         $description
Assigned to: @<<<<<<<<<<<<<<<<<<<<<< ^<<<<<<<<<<<<<<<<<<<<<<<<<<<<
             $programmer,            $description
~                                    ^<<<<<<<<<<<<<<<<<<<<<<<<<<<<
                                     $description
~                                    ^<<<<<<<<<<<<<<<<<<<<<<<<<<<<
                                     $description
~                                    ^<<<<<<<<<<<<<<<<<<<<<<<<<<<<
                                     $description
~                                    ^<<<<<<<<<<<<<<<<<<<<<<<<<<<<
                                     $description
~                                    ^<<<<<<<<<<<<<<<<<<<<<<<...
                                     $description
.

It is possible to intermix print()s with write()s on the same output channel, but you'll have to handle "$-" ($FORMAT_LINES_LEFT) yourself.

Variables de formatage

The current format name is stored in the variable $~ ($FORMAT_NAME), and the current top of form format name is in $^ ($FORMAT_TOP_NAME). The current output page number is stored in $% ($FORMAT_PAGE_NUMBER), and the number of lines on the page is in $= ($FORMAT_LINES_PER_PAGE). Whether to autoflush output on this handle is stored in $| ($OUTPUT_AUTOFLUSH). The string output before each top of page (except the first) is stored in $^L ($FORMAT_FORMFEED). These variables are set on a per-filehandle basis, so you'll need to select() into a different one to affect them:

select((select(OUTF),
        $~ = "My_Other_Format",
        $^ = "My_Top_Format"
       )[0]);

Pretty ugly, eh? It's a common idiom though, so don't be too surprised when you see it. You can at least use a temporary variable to hold the previous filehandle: (this is a much better approach in general, because not only does legibility improve, you now have an intermediary stage in the expression to single-step the debugger through):

$ofh = select(OUTF);
$~ = "My_Other_Format";
$^ = "My_Top_Format";
select($ofh);

If you use the English module, you can even read the variable names:

use English;
$ofh = select(OUTF);
$FORMAT_NAME     = "My_Other_Format";
$FORMAT_TOP_NAME = "My_Top_Format";
select($ofh);

But you still have those funny select()s. So just use the FileHandle module. Now, you can access these special variables using lowercase method names instead:

use FileHandle;
format_name     OUTF "My_Other_Format";
format_top_name OUTF "My_Top_Format";

Much better!

NOTES

Because the values line may contain arbitrary expressions (for at fields, not caret fields), you can farm out more sophisticated processing to other functions, like sprintf() or one of your own. For example:

format Ident =
    @<<<<<<<<<<<<<<<
    &commify($n)
.

To get a real at or caret into the field, do this:

format Ident =
I have an @ here.
        "@"
.

To center a whole line of text, do something like this:

format Ident =
@|||||||||||||||||||||||||||||||||||||||||||||||
        "Some text line"
.

There is no builtin way to say "float this to the right hand side of the page, however wide it is." You have to specify where it goes. The truly desperate can generate their own format on the fly, based on the current number of columns, and then eval() it:

$format  = "format STDOUT = \n"
         . '^' . '<' x $cols . "\n"
         . '$entry' . "\n"
         . "\t^" . "<" x ($cols-8) . "~~\n"
         . '$entry' . "\n"
         . ".\n";
print $format if $Debugging;
eval $format;
die $@ if $@;

Which would generate a format looking something like this:

format STDOUT =
^<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<
$entry
        ^<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<~~
$entry
.

Here's a little program that's somewhat like fmt(1):

format =
^<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<< ~~
$_
.
$/ = '';
while (<>) {
    s/\s*\n\s*/ /g;
    write;
}

Pieds de page

While $FORMAT_TOP_NAME contains the name of the current header format, there is no corresponding mechanism to automatically do the same thing for a footer. Not knowing how big a format is going to be until you evaluate it is one of the major problems. It's on the TODO list.

Here's one strategy: If you have a fixed-size footer, you can get footers by checking $FORMAT_LINES_LEFT before each write() and print the footer yourself if necessary.

Here's another strategy: Open a pipe to yourself, using "open(MYSELF, "|-")" (see "open" in perlfunc) and always write() to MYSELF instead of STDOUT. Have your child process massage its STDIN to rearrange headers and footers however you like. Not very convenient, but doable.

Accès aux internes de formatage

For low-level access to the formatting mechanism, you may use formline() and access $^A (the $ACCUMULATOR variable) directly.

For example:

$str = formline <<'END', 1,2,3;
@<<<  @|||  @>>>
END
print "Wow, I just stored '$^A' in the accumulator!\n";

Or to make an swrite() subroutine, which is to write() what sprintf() is to printf(), do this:

   use Carp;
   sub swrite {
       croak "usage: swrite PICTURE ARGS" unless @_;
       my $format = shift;
       $^A = "";
       formline($format,@_);
       return $^A;
   }
   $string = swrite(<<'END', 1, 2, 3);
Check me out
@<<<  @|||  @>>>
END
   print $string;

WARNINGS

Variables declared with "my" are not visible within a format unless the format is declared within the scope of the lexical variable.

If the environment of a program specifies an LC_NUMERIC locale and "use locale" is in effect when the format is declared, the locale is used to specify the decimal point character in formatted output. Formatted output cannot be controlled by "use locale" at the time when write() is called. See perllocale for further discussion of locale handling.

Within strings that are to be displayed in a fixed-length text field, each control character is substituted by a space. (But remember the special meaning of "\r" when using fill mode.) This is done to avoid misalignment when control characters "disappear" on some output media.
