NOM

perl5124delta - nouveautés de la version perl v5.12.4

DESCRIPTION

Ce document décrit les différences entre la version 5.12.3 et la version 5.12.4.

Si vous mettez à jour depuis une version antérieure comme la 5.12.2, lisez d'abord perl5123delta, qui décrit les différences entre 5.12.2 et 5.12.3. Les changements majeurs introduits dans 5.12.0 sont décrits dans perl5120delta.

CHANGEMENTS INCOMPATIBLES

Il n'y a aucun changement intentionnellement incompatible avec la version 5.12.3. S'il en existe, il s'agit de bugs et les rapports sont les bienvenus.

CORRECTIFS DE BUGS SÉLECTIONNÉS

Lorsque le mode strict « refs » est désactivé, "%{...}" en contexte rvalue renvoie "undef" si son argument est indéfini. Une optimisation introduite dans Perl 5.12.0 pour rendre "keys %{...}" plus rapide lorsqu'il est utilisé comme booléen n'en a pas tenu compte, provoquant une erreur pour "keys %{+undef}" (et "keys %$foo" lorsque $foo est indéfini), ce qui devrait uniquement se produire en mode strict [perl #81750].

"lc", "uc", "lcfirst" et "ucfirst" ne renvoient plus de chaînes non tainted lorsque l'argument est tainted. Ceci était buggé depuis perl 5.8.9 [perl #87336].

Correction d'un cas où un tampon libéré aurait pu être lu lors de l'analyse d'un here document.

MODULES ET PRAGMAS

Module::CoreList a été mis à jour de la version 2.43 à la version 2.50.

TESTS

Le script de test cpan/CGI/t/http.t a été corrigé pour fonctionner lorsque l'environnement contient des variables HTTPS_* , comme HTTPS_PROXY.

DOCUMENTATION

La documentation de rand() dans perlfunc a été mise à jour pour noter qu'elle n'est pas cryptographiquement sécurisée.

SIGNALEMENT DE BUGS

Si vous trouvez ce qui vous semble être un bug, vous pourriez consulter les articles récemment postés sur le groupe de discussion comp.lang.perl.misc et la base de données des bugs de Perl à http://rt.perl.org/perlbug/. Vous trouverez peut-être également des informations sur http://www.perl.org/, la page d'accueil de Perl.

Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus dans votre version. Assurez-vous de réduire votre bug à un cas de test simple mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl.

Si le bug que vous signalez a des implications de sécurité qui le rendent inapproprié à l'envoi à une liste de diffusion archivée publiquement, veuillez alors l'envoyer à perl5-security-report@perl.org. Ceci pointe vers une liste de diffusion à abonnement fermé et non archivée, qui inclut tous les committers du noyau, qui pourront aider à évaluer l'impact des problèmes, trouver une solution et aider à coordonner la publication de correctifs pour atténuer ou résoudre le problème sur toutes les plateformes supportées par Perl. Veuillez n'utiliser cette adresse que pour les problèmes de sécurité dans le noyau Perl, pas pour les modules distribués indépendamment sur CPAN.
