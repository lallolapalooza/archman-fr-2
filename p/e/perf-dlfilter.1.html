NOM

perf-dlfilter - Filtre les événements d'échantillonnage à l'aide d'un fichier objet partagé chargé dynamiquement

SYNTAXE

perf script [--dlfilter fichier.so ] [ --dlarg argument ]...

DESCRIPTION

Cette option est utilisée pour traiter les données à travers un filtre personnalisé fourni par un fichier objet partagé chargé dynamiquement. Des arguments peuvent être passés en utilisant --dlarg et récupérés en utilisant perf_dlfilter_fns.args().

Si fichier.so ne contient pas de "/", il sera trouvé soit dans le répertoire courant, soit dans le chemin d'exécution des outils perf qui est ~/libexec/perf-core/dlfilters pour une compilation et une installation locales (voir perf --exec-path), soit dans les chemins du chargeur dynamique.

API

L'API pour le filtrage se compose de ce qui suit :

#include <perf/perf_dlfilter.h>
struct perf_dlfilter_fns perf_dlfilter_fns;
int start(void **data, void *ctx);
int stop(void *data, void *ctx);
int filter_event(void *data, const struct perf_dlfilter_sample *sample, void *ctx);
int filter_event_early(void *data, const struct perf_dlfilter_sample *sample, void *ctx);
const char *filter_description(const char **long_description);

Si implémentée, start sera appelée au début, avant tout appel à filter_event ou filter_event_early. Retourne 0 pour indiquer le succès, ou retourne un code d'erreur négatif. *data peut être assigné pour être utilisé par d'autres fonctions. ctx est nécessaire pour les appels à perf_dlfilter_fns, mais la plupart des perf_dlfilter_fns ne sont pas valides lorsqu'ils sont appelés depuis start.

Si implémentée, stop sera appelée à la fin, après tout appel à filter_event ou filter_event_early. Retourne 0 pour indiquer le succès, ou retourne un code d'erreur négatif. data est défini par start. ctx est nécessaire pour les appels à perf_dlfilter_fns, mais la plupart des perf_dlfilter_fns ne sont pas valides lorsqu'ils sont appelés depuis stop.

Si implémentée, filter_event sera appelée pour chaque événement d'échantillon. Retourne 0 pour conserver l'événement d'échantillon, 1 pour le filtrer, ou retourne un code d'erreur négatif. data est défini par start. ctx est nécessaire pour les appels à perf_dlfilter_fns.

filter_event_early est identique à filter_event sauf qu'elle est appelée avant le filtrage interne.

Si implémentée, filter_description devrait retourner une description en une ligne du filtre, et éventuellement une description plus longue.

Ne supposez pas que l'argument sample est valide (accessible en lecture) après que filter_event et filter_event_early soient retournées.

Ne supposez pas que les données référencées par les pointeurs dans la structure perf_dlfilter_sample sont valides (accessibles en lecture) après que filter_event et filter_event_early soient retournées.

La structure perf_dlfilter_sample

filter_event et filter_event_early reçoivent une structure perf_dlfilter_sample, qui contient les champs suivants :

/*
 * Informations sur l'événement d'échantillonnage perf (selon perf script et <linux/perf_event.h>)
 */
struct perf_dlfilter_sample {
        __u32 size; /* Taille de cette structure (pour vérification de compatibilité) */
        __u16 ins_lat;          /* Voir PERF_SAMPLE_WEIGHT_TYPE dans <linux/perf_event.h> */
        __u16 p_stage_cyc;      /* Voir PERF_SAMPLE_WEIGHT_TYPE dans <linux/perf_event.h> */
        __u64 ip;
        __s32 pid;
        __s32 tid;
        __u64 time;
        __u64 addr;
        __u64 id;
        __u64 stream_id;
        __u64 period;
        __u64 weight;           /* Voir PERF_SAMPLE_WEIGHT_TYPE dans <linux/perf_event.h> */
        __u64 transaction;      /* Voir PERF_SAMPLE_TRANSACTION dans <linux/perf_event.h> */
        __u64 insn_cnt; /* Pour instructions-par-cycle (IPC) */
        __u64 cyc_cnt;          /* Pour instructions-par-cycle (IPC) */
        __s32 cpu;
        __u32 flags;            /* Voir PERF_DLFILTER_FLAG_* ci-dessus */
        __u64 data_src;         /* Voir PERF_SAMPLE_DATA_SRC dans <linux/perf_event.h> */
        __u64 phys_addr;        /* Voir PERF_SAMPLE_PHYS_ADDR dans <linux/perf_event.h> */
        __u64 data_page_size;   /* Voir PERF_SAMPLE_DATA_PAGE_SIZE dans <linux/perf_event.h> */
        __u64 code_page_size;   /* Voir PERF_SAMPLE_CODE_PAGE_SIZE dans <linux/perf_event.h> */
        __u64 cgroup;           /* Voir PERF_SAMPLE_CGROUP dans <linux/perf_event.h> */
        __u8  cpumode;          /* Voir CPUMODE_MASK etc dans <linux/perf_event.h> */
        __u8  addr_correlates_sym; /* Vrai => resolve_addr() peut être appelé */
        __u16 misc;             /* Voir perf_event_header dans <linux/perf_event.h> */
        __u32 raw_size;         /* Voir PERF_SAMPLE_RAW dans <linux/perf_event.h> */
        const void *raw_data;   /* Voir PERF_SAMPLE_RAW dans <linux/perf_event.h> */
        __u64 brstack_nr;       /* Nombre d'entrées brstack */
        const struct perf_branch_entry *brstack; /* Voir <linux/perf_event.h> */
        __u64 raw_callchain_nr; /* Nombre d'entrées raw_callchain */
        const __u64 *raw_callchain; /* Voir <linux/perf_event.h> */
        const char *event;
        __s32 machine_pid;
        __s32 vcpu;
};

Remarque : machine_pid et vcpu ne sont pas des membres originaux, mais ont été ajoutés plus tard. size peut être utilisé pour déterminer leur présence au moment de l'exécution. PERF_DLFILTER_HAS_MACHINE_PID sera défini s'ils sont présents au moment de la compilation. Par exemple :

#include <perf/perf_dlfilter.h>
#include <stddef.h>
#include <stdbool.h>
static inline bool have_machine_pid(const struct perf_dlfilter_sample *sample)
{
#ifdef PERF_DLFILTER_HAS_MACHINE_PID
        return sample->size >= offsetof(struct perf_dlfilter_sample, vcpu) + sizeof(sample->vcpu);
#else
        return false;
#endif
}

La structure perf_dlfilter_fns

La structure perf_dlfilter_fns est remplie de pointeurs de fonction lors du chargement du fichier. Les fonctions peuvent être appelées par filter_event ou filter_event_early.

struct perf_dlfilter_fns {
        const struct perf_dlfilter_al *(*resolve_ip)(void *ctx);
        const struct perf_dlfilter_al *(*resolve_addr)(void *ctx);
        char **(*args)(void *ctx, int *dlargc);
        __s32 (*resolve_address)(void *ctx, __u64 address, struct perf_dlfilter_al *al);
        const __u8 *(*insn)(void *ctx, __u32 *length);
        const char *(*srcline)(void *ctx, __u32 *line_number);
        struct perf_event_attr *(*attr)(void *ctx);
        __s32 (*object_code)(void *ctx, __u64 ip, void *buf, __u32 len);
        void (*al_cleanup)(void *ctx, struct perf_dlfilter_al *al);
        void *(*reserved[119])(void *);
};

resolve_ip retourne des informations sur l'ip.

resolve_addr retourne des informations sur l'addr (si addr_correlates_sym).

args retourne les arguments des options --dlarg.

resolve_address fournit des informations sur address. al→size doit être défini avant l'appel. Retourne 0 en cas de succès, -1 sinon. Appelez al_cleanup() (si présent, voir ci-dessous) lorsque les données al ne sont plus nécessaires.

insn retourne les octets d'instruction et la longueur.

srcline retourne le nom du fichier source et le numéro de ligne.

attr retourne perf_event_attr, voir <linux/perf_event.h>.

object_code lit le code objet et retourne le nombre d'octets lus.

al_cleanup doit être appelée (si présent, vérifiez donc perf_dlfilter_fns.al_cleanup != NULL) après resolve_address() pour libérer toutes les ressources associées.

Ne supposez pas que les pointeurs obtenus via perf_dlfilter_fns sont valides (accessibles en lecture) après que filter_event et filter_event_early soient retournées.

La structure perf_dlfilter_al

La structure perf_dlfilter_al contient des informations sur une adresse.

/*
 * Emplacement de l'adresse (selon perf script)

struct perf_dlfilter_al {
        __u32 size; /* Taille de cette structure (pour vérification de compatibilité) */

        const char *sym;
        __u64 addr; /* Adresse mappée (depuis dso) */
        __u64 sym_start;
        __u64 sym_end;
        const char *dso;

        __u8  is_64_bit; /* Valide uniquement si dso n'est pas NULL */
        __u8  is_kernel_ip; /* Vrai si dans l'espace noyau */
        __u32 buildid_size;
        __u8 *buildid;
        /* Les membres ci-dessous ne sont peuplés que par */
};

perf_dlfilter_sample flags

Le membre flags de perf_dlfilter_sample correspond au champ flags de perf script. Les bits des flags sont les suivants :

/* Définitions pour les flags de perf_dlfilter_sample */
enum {
        PERF_DLFILTER_FLAG_BRANCH       = 1ULL << 0,
        PERF_DLFILTER_FLAG_CALL         = 1ULL << 1,
        PERF_DLFILTER_FLAG_RETURN       = 1ULL << 2,
        PERF_DLFILTER_FLAG_CONDITIONAL  = 1ULL << 3,
        PERF_DLFILTER_FLAG_SYSCALLRET   = 1ULL << 4,
        PERF_DLFILTER_FLAG_ASYNC        = 1ULL << 5,
        PERF_DLFILTER_FLAG_INTERRUPT    = 1ULL << 6,
        PERF_DLFILTER_FLAG_TX_ABORT     = 1ULL << 7,
        PERF_DLFILTER_FLAG_TRACE_BEGIN  = 1ULL << 8,

EXEMPLE

Filtrer tout sauf les branches de "foo" vers "bar" :

#include <perf/perf_dlfilter.h>
#include <string.h>
struct perf_dlfilter_fns perf_dlfilter_fns;
int filter_event(void *data, const struct perf_dlfilter_sample *sample, void *ctx)
{
        const struct perf_dlfilter_al *al;
        const struct perf_dlfilter_al *addr_al;
        if (!sample->ip || !sample->addr_correlates_sym)
                return 1;
        al = perf_dlfilter_fns.resolve_ip(ctx);
        if (!al || !al->sym || strcmp(al->sym, "foo"))
                return 1;
        addr_al = perf_dlfilter_fns.resolve_addr(ctx);
        if (!addr_al || !addr_al->sym || strcmp(addr_al->sym, "bar"))
                return 1;
        return 0;
}

Pour construire l'objet partagé, en supposant que perf est installé pour l'utilisateur local, c'est-à-dire que perf_dlfilter.h se trouve dans ~/include/perf :

gcc -c -I ~/include -fpic dlfilter-example.c
gcc -shared -o dlfilter-example.so dlfilter-example.o

Pour utiliser le filtre avec perf script :

perf script --dlfilter dlfilter-example.so

NOTES

Le fichier .so dlfilter dépendra des bibliothèques partagées. Si celles-ci changent, il peut être nécessaire de reconstruire le .so. Il peut également y avoir des résultats inattendus si le .so utilise des versions différentes des bibliothèques partagées que perf utilise. Les versions peuvent être vérifiées à l'aide de la commande ldd.
