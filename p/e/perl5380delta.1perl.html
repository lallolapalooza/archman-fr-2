PERL5380DELTA(1perl) Guide de référence du programmeur Perl PERL5380DELTA(1perl)

NOM

perl5380delta - nouveautés de la version perl v5.38.0

DESCRIPTION

Ce document décrit les différences entre la version 5.36.0 et la version 5.38.0.

Améliorations du cœur

Nouvelle fonctionnalité "class"

Une nouvelle syntaxe expérimentale est maintenant disponible pour définir des classes d'objets, où les données par instance sont stockées dans des variables "field" qui se comportent comme des lexicals.

use feature 'class';
class Point
{
    field $x;
    field $y;
    method zero { $x = $y = 0; }
}

Ceci est décrit plus en détail dans perlclass. Des notes sur les internes de son implémentation et d'autres détails connexes peuvent être trouvées dans perlclassguts.

Cela reste une fonctionnalité nouvelle et expérimentale, et elle est encore en cours de développement. Elle fera l'objet de nombreuses autres additions, raffinements et modifications dans les futures versions. Étant expérimentale, elle génère des avertissements dans la catégorie "experimental::class". Ceux-ci peuvent être supprimés par une instruction "no warnings".

use feature 'class';
no warnings 'experimental::class';

Unicode 15.0 est pris en charge

Voir https://www.unicode.org/versions/Unicode15.0.0/ pour les détails.

Les avertissements de dépréciation ont maintenant des sous-catégories spécifiques

Tous les avertissements de dépréciation ont maintenant leur propre catégorie de dépréciation spécifique qui peut être désactivée individuellement. Vous pouvez voir une liste de toutes les fonctionnalités dépréciées dans perldeprecation, et dans warnings. La liste suivante provient de warnings :

+- deprecated ----+
|                 |
|                 +- deprecated::apostrophe_as_package_separator
|                 |
|                 +- deprecated::delimiter_will_be_paired
|                 |
|                 +- deprecated::dot_in_inc
|                 |
|                 +- deprecated::goto_construct
|                 |
|                 +- deprecated::smartmatch
|                 |
|                 +- deprecated::unicode_property_name
|                 |

Il est toujours possible de désactiver tous les avertissements de dépréciation en une seule instruction avec

no warnings 'deprecated';

mais il est maintenant possible d'avoir un contrôle plus granulaire. Comme cela a été le cas historiquement, ces avertissements sont automatiquement activés avec

use warnings;

API %{^HOOK} introduite

Pour diverses raisons, il peut être difficile de créer des wrappers de sous-rotines pour certains mots-clés de perl. Tout mot-clé qui a un prototype indéfini ne peut tout simplement pas être encapsulé par une sous-routine, et certains mots-clés que perl permet d'encapsuler sont en pratique très difficiles à encapsuler. Par exemple, "require" est difficile à encapsuler, c'est possible mais le faire change la profondeur de la pile, et les méthodes standard d'exportation supposent qu'elles exporteront vers un paquet à une certaine profondeur de pile, et le wrapper changera ainsi où les fonctions sont exportées, à moins d'être implémenté avec beaucoup de soin. Cela peut être très gênant à gérer.

Par conséquent, nous avons introduit une nouvelle table de hachage appelée "%{^HOOK}" qui est destinée à faciliter de tels cas. Lorsqu'un mot-clé prend en charge un quelconque hook spécial, le hook vivra dans cette nouvelle table. Les hooks dans cette table seront nommés d'après la fonction qui les appelle, suivis de deux underscores, puis de la phase pendant laquelle ils sont exécutés, actuellement soit avant soit après l'exécution du mot-clé.

Dans cette version initiale, nous prenons en charge deux hooks : "require__before" et "require__after". Ceux-ci sont fournis pour faciliter l'exécution de tâches avant et après une instruction require.

Voir perlvar pour plus de détails.

PERL_RAND_SEED

Ajout d'une nouvelle variable d'environnement "PERL_RAND_SEED" qui peut être utilisée pour rendre reproductible un programme perl qui utilise "rand" sans utiliser explicitement srand() ou qui utilise srand() sans arguments. Voir perlrun. Cette fonctionnalité peut être désactivée au moment de la compilation en passant

-Accflags=-DNO_PERL_RAND_SEED

à Configure lors du processus de construction.

Expressions par défaut d'assignation défini-ou et logique-ou dans les signatures

L'expression par défaut pour un paramètre de signature de sous-routine peut maintenant être assignée en utilisant les opérateurs "//=" ou "||=", pour appliquer les valeurs par défaut chaque fois que l'appelant a fourni une valeur indéfinie ou fausse (respectivement), plutôt que simplement lorsque le paramètre est manquant. Pour plus de détails, voir la documentation dans perlsub.

Améliorations du hook @INC et $INC et INCDIR

Les internes des hooks @INC ont été renforcés pour gérer divers cas limites et ne devraient plus provoquer de segfaults ou d'échecs d'assertion lorsque les hooks modifient @INC pendant une opération require. Dans ce cadre, nous nous assurons maintenant que chaque hook donné n'est exécuté qu'une seule fois lors d'un appel require, et que les répertoires dupliqués ne déclenchent pas de sondages de répertoire supplémentaires.

Pour offrir aux développeurs plus de contrôle sur la recherche dynamique de modules, une nouvelle méthode de hook "INCDIR" est maintenant prise en charge. Un objet prenant en charge cette méthode peut être injecté dans le tableau @INC, et lorsqu'il est rencontré dans le processus de recherche de module, il sera exécuté, tout comme les hooks INC sont exécutés, et sa valeur de retour sera utilisée comme une liste de répertoires à rechercher pour le module. Retourner une liste vide agit comme une opération nulle. Notez que comme toute référence retournée par ce hook sera stringifiée et utilisée comme une chaîne, vous ne pouvez pas retourner un hook pour qu'il soit exécuté plus tard via cette API.

Lorsqu'un hook @INC (soit "INC" soit "INCDIR") est appelé pendant un require, la variable $INC sera localisée pour correspondre à la valeur de l'index de @INC d'où provient le hook. Si le hook souhaite remplacer ce que devrait être le "prochain" index dans @INC, il peut mettre à jour $INC pour qu'il soit un de moins que l'index désiré ("undef" équivaut à -1). Cela permet à un hook @INC de réécrire complètement le tableau @INC et de faire redémarrer perl ses sondages de répertoire depuis le début de @INC.

Les références CODE bénies dans @INC qui ne prennent pas en charge les méthodes "INC" ou "INCDIR" ne déclencheront plus d'exception, et seront traitées de la même manière que les coderefs non bénies, et exécutées comme s'il s'agissait d'un hook "INC".

Le flux de contrôle interdit hors de "defer" ou "finally" est maintenant détecté à la compilation

Il est interdit de tenter de quitter un bloc "defer" ou "finally" par un flux de contrôle tel que "return" ou "goto". Les versions précédentes de perl ne pouvaient le détecter qu'au moment de l'exécution.

Cette version de Perl ajoute la détection au moment de la compilation pour de nombreux cas qui peuvent être déterminés statiquement. Évaluation optimiste dans les motifs

L'utilisation de "(?{ ... })" et "(??{ ... })" dans un motif désactive diverses optimisations globalement dans ce motif. Cela peut être souhaitable ou non pour le programmeur. Cette version ajoute l'équivalent "(*{ ... })". La seule différence est qu'il ne désactive aucune optimisation dans le moteur d'expressions régulières et ne le fera jamais. Cela peut le rendre plus instable dans le sens où il peut être appelé plus ou moins de fois à l'avenir, cependant, le nombre de fois où il s'exécute correspondra réellement à la façon dont le moteur d'expressions régulières fonctionne. Par exemple, certains types d'optimisations sont désactivés lorsque "(?{ ... })" est inclus dans un motif, de sorte que les motifs qui sont en O(N) en utilisation normale deviennent O(N*N) avec un motif "(?{ ... })". Passer à "(*{ ... })" signifie que le motif restera O(N).

REG_INF est passé de 65 536 à 2 147 483 647

De nombreux quantificateurs d'expressions régulières étaient auparavant limités à "U16_MAX", mais sont maintenant limités à "I32_MAX", il est donc désormais possible d'écrire par exemple "/(?:word){1000000}/". Notez que cela peut entraîner une durée d'exécution plus longue et une consommation de mémoire plus importante du moteur d'expressions régulières.

Nouvelles fonctions d'API optimize_optree et finalize_optree

Il existe deux nouvelles fonctions d'API pour opérer sur des fragments d'arbres d'options (optree), vous garantissant d'invoquer les parties requises du processus de génération d'arbres d'options qui pourraient autrement ne pas être invoquées (par exemple, lors de la création d'un LOGOP personnalisé). Pour accéder à ces fonctions, vous devez d'abord définir un "#define" pour activer leur utilisation.

#define PERL_USE_VOLATILE_API

Ces fonctions sont étroitement liées aux internes du fonctionnement de l'interpréteur et pourraient être modifiées ou supprimées à tout moment si d'autres changements internes le rendent nécessaire.

Certains "goto" sont maintenant autorisés dans les blocs "defer" et "finally"

La version 5.36.0 de Perl a ajouté les blocs "defer" et a permis au mot-clé "finally" d'ajouter un comportement similaire à la syntaxe "try"/"catch". Ceux-ci ne permettaient aucune expression "goto" à l'intérieur du corps, car cela aurait pu entraîner un saut du flux de contrôle hors du bloc. Désormais, certaines expressions "goto" sont autorisées, si elles ont une étiquette cible constante et que cette étiquette se trouve dans le bloc.

use feature 'defer';
defer {
  goto LABEL;
  print "Cela ne s'exécute pas\n";
  LABEL: print "Cela s'exécute\n";
}

Nouvelle variable d'expression régulière ${^LAST_SUCCESSFUL_PATTERN}

Ceci permet d'accéder au dernier motif qui a réussi une correspondance dans la portée actuelle. De nombreux aspects du moteur d'expressions régulières font référence au "dernier motif réussi". Le motif vide le réutilise, et toutes les variables magiques des expressions régulières s'y rapportent. Ceci permet d'accéder à son motif. Le code suivant

if (m/foo/ || m/bar/) {
    s//PQR/;
}

peut être réécrit comme suit

if (m/foo/ || m/bar/) {
    s/${^LAST_SUCCESSFUL_PATTERN}/PQR/;
}

et cela fera exactement la même chose.

La catégorie de locale LC_NAME est maintenant prise en charge sur les plateformes participantes

Sur les plateformes qui ont l'extension GNU pour la catégorie "LC_NAME", vous pouvez maintenant l'utiliser comme paramètre de catégorie pour "setlocale" dans POSIX afin de définir et de interroger sa locale.

Changements incompatibles

readline() ne réinitialise plus les drapeaux d'erreur et de fin de fichier du flux

readline(), également orthographié "<>", effaçait les drapeaux d'erreur et de fin de fichier du descripteur après une erreur survenue sur le flux.

Dans presque tous les cas, cette réinitialisation n'est plus effectuée, de sorte que les drapeaux d'erreur et de fin de fichier reflètent désormais correctement l'état du flux après readline().

Étant donné que le drapeau d'erreur n'est plus effacé, l'appel de close() sur le flux peut échouer et si le flux n'a pas été explicitement fermé, la fermeture implicite du flux peut produire un avertissement.

Cela a entraîné deux types principaux de problèmes dans les modules CPAN en aval, et ceux-ci peuvent également survenir dans votre code :

  • Si votre code lit jusqu'à la fin du fichier, puis re-lie le descripteur à un nouveau descripteur de fichier, précédemment, comme le drapeau de fin de fichier n'était pas défini, vous pouviez continuer à lire depuis le flux. Vous devez maintenant effacer vous-même le drapeau de fin de fichier avec "$handle->clearerr()" pour continuer à lire.
  • Si votre code rencontre une erreur sur le flux lors de la lecture avec readline(), vous devrez appeler "$handle->clearerr" pour continuer à lire. Le seul cas où cela s'est produit, le descripteur de fichier sous-jacent était marqué comme non bloquant, de sorte que l'appel système read() échouait avec "EAGAIN", ce qui entraînait la définition du drapeau d'erreur sur le flux.

Le seul cas où les drapeaux d'erreur et de fin de fichier continuent d'être effacés en cas d'erreur est lors de la lecture depuis le processus enfant pour glob() dans miniperl. Cela lui permet de signaler correctement les erreurs du processus enfant sur close(). Cela ne devrait probablement pas être un problème lors du développement normal de Perl.

[GH #20060 https://github.com/Perl/perl5/issues/20060]

Les blocs "INIT" ne s'exécutent plus après un exit() dans "BEGIN"

Les blocs "INIT" ne s'exécuteront plus après un exit() effectué à l'intérieur d'un "BEGIN". Cela signifie que la combinaison de l'option "-v" et de l'option "-c" n'effectue plus une vérification de compilation tout en affichant la version de Perl. L'option "-v" exécute un exit(0) après avoir affiché les informations de version à l'intérieur d'un bloc "BEGIN", et la vérification "-c" est implémentée en utilisant des hooks "INIT", ce qui fait que l'option "-v" prend la priorité.

[GH #1537 https://github.com/Perl/perl5/issues/1537] [GH #20181 https://github.com/Perl/perl5/issues/20181]

Les erreurs de syntaxe ne produisent plus de "messages d'erreur fantômes"

En général, Perl continue d'analyser le code source même après avoir rencontré une erreur de compilation. Dans de nombreux cas, cela est utile, par exemple, pour les noms de variables mal orthographiés, il est utile d'afficher autant d'exemples d'erreurs que possible. Mais dans le cas d'erreurs de syntaxe, la poursuite produit souvent des messages d'erreur bizarres et peut même provoquer des erreurs de segmentation pendant le processus de compilation. Dans cette version, le compilateur s'arrêtera à la première erreur de syntaxe rencontrée. Cela signifie que tout code attendant de voir les messages d'erreur spécifiques que nous avions l'habitude de produire sera cassé. L'erreur qui sera émise sera l'un des diagnostics qui étaient produits auparavant, mais dans certains cas, certains messages qui étaient produits auparavant ne seront plus affichés.

Voir "Modifications des diagnostics existants" pour plus de détails.

utf8::upgrade()

À partir de cette version, si la chaîne d'entrée est "undef", elle reste "undef". Auparavant, elle était convertie en une chaîne définie de longueur nulle.

Modifications des locales "thread-safe"

Perl 5.28 a introduit des locales "thread-safe" sur les systèmes qui les prenaient en charge, à savoir les systèmes Windows modernes et les systèmes prenant en charge les opérations de locale POSIX 2008. Ces systèmes y parviennent en ayant des locales par thread, tout en continuant à prendre en charge les anciennes opérations de locale globales pour le code qui ne prend pas les mesures nécessaires pour utiliser les nouvelles par thread.

Il s'avère que certaines plateformes POSIX 2008 ont ou ont eu des implémentations boguées, ce qui a obligé Perl à ne pas les utiliser. La variable scalaire "${^SAFE_LOCALES}" contient 0 ou 1 pour indiquer si la plateforme actuelle est considérée ou non par Perl comme ayant une implémentation thread-safe fonctionnelle. Certaines implémentations ont déjà été corrigées, mais FreeBSD et Cygwin ont été nouvellement découvertes comme étant suffisamment boguées que le thread-s

Safe Operations

afe operations are no longer used by perl, starting in this release. Hence, "${^SAFE_LOCALES}" is now 0 for them. Older versions of perl can be configured to avoid these buggy implementations by adding the Configure option "-DNO_POSIX_2008_LOCALE".

And v5.38 fixes a bug in all previous perls that led to locales not being fully thread-safe. The first thread that finishes caused the main thread (named "thread0") to revert to the global locale in effect at startup, discarding whatever the thread's locale had been previously set to. If any other thread had switched to the global locale by calling switch_to_global_locale() in XS code, those threads would all share the global locale, and "thread0" would not be thread-safe.

Dépréciations

L'utilisation de « ' » comme séparateur de noms de paquet est dépréciée

Using "'" as package separator in a variable named in a double-quoted string has warned since 5.28. It is now deprecated in both string interpolation and non-interpolated contexts, and will be removed in Perl 5.42.

Opérateurs Switch et Smart Match

The "switch" feature and the smartmatch operator, "~~", were introduced in v5.10. Their behavior was significantly changed in v5.10.1. When the "experiment" system was added in v5.18.0, switch and smartmatch were retroactively declared experimental. Over the years, proposals to fix or supplement the features have come and gone.

In v5.38.0, we are declaring the experiment a failure. Some future system may take the conceptual place of smartmatch, but it has not yet been designed or built.

These features will be entirely removed from perl in v5.42.0.

    Changements aux diagnostics existants

    • Le compilateur s'arrêtera maintenant à la première erreur de syntaxe rencontrée. Historiquement, le compilateur tentait de « passer outre » l'erreur et de continuer l'analyse afin de pouvoir signaler plusieurs erreurs. Pour des choses comme les variables non déclarées sous strict, cela a du sens. Pour les erreurs de syntaxe, cependant, il a été constaté que la poursuite entraînait une avalanche d'erreurs non pertinentes ou bizarres qui masquaient principalement la véritable erreur. Dans les cas extrêmes, cela peut même entraîner des segfaults et d'autres comportements incorrects.

      Par conséquent, nous avons réformé la logique de continuation afin que l'analyse s'arrête après la première erreur de syntaxe rencontrée. Les erreurs sémantiques comme les variables non déclarées n'arrêteront pas l'analyse, vous pourriez donc toujours voir plusieurs erreurs lors de la compilation du code. Cependant, s'il y a une erreur de syntaxe, ce sera le dernier message d'erreur signalé par Perl et toutes les erreurs que vous verrez seront quelque chose qui doit réellement être corrigé.

    • Les messages d'erreur qui affichent des noms de classes ou de paquets ont été modifiés pour afficher des chaînes entre guillemets doubles avec divers caractères échappés afin de rendre la valeur exacte claire pour le lecteur. Les règles exactes sur les caractères à échapper peuvent changer avec le temps, mais actuellement, les points de code ASCII imprimables, à l'exception de """ et "\", et les caractères de mot Unicode dont le point de code est supérieur à 255 sont affichés bruts, et tous les autres symboles sont échappés, tout comme Data::Dumper pourrait les échapper, en utilisant "\n" pour les nouvelles lignes et "\"" pour les guillemets doubles, etc. Les points de code dans la plage 128-255 sont toujours échappés car ils peuvent causer des problèmes sur les terminaux Unicode lorsqu'ils sont affichés bruts.

      Dans les anciennes versions de Perl, la ligne de commande unique

      $ perl -le'"thing\n"->foo()'

      affichait le message d'erreur suivant exactement comme indiqué ici, avec le texte réparti sur plusieurs lignes car le « \n » serait émis comme un caractère de nouvelle ligne brut :

      Can't locate object method "foo" via package "thing
" (perhaps you forgot to load "thing
"?) at -e line 1.

      À partir de cette version, nous afficherions ceci à la place (en une seule ligne) :

      Can't locate object method "foo" via package "thing\n"
  (perhaps you forgot to load "thing\n"?) at -e line 1.

      Notez que la nouvelle ligne dans le nom du paquet a été mise entre guillemets et échappée, et donc le message d'erreur est sur une seule ligne. Le texte est affiché ici avec un retour à la ligne sur deux lignes uniquement pour la lisibilité.

    • Lorsque les noms de paquets ou de classes dans les erreurs sont très longs, la partie excédentaire du milieu sera élidée du message. À partir de cette version, les messages d'erreur afficheront uniquement les 128 premiers caractères et les 128 derniers caractères d'un nom de paquet ou de classe dans les messages d'erreur. Par exemple : 
      $ perl -le'("Foo" x 1000)->new()'

      affichera ceci sur une seule ligne :

      Can't locate object method "new" via package "FooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFo"..."oFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFoo" (perhaps you forgot to load
"FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFo"...
"oFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo
FooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFooFoo"?)
at -e line 1.

      Notez la forme "préfixe"..."suffixe" du nom du paquet dans ce cas. Dans les versions précédentes de Perl, la chaîne complète aurait été affichée, rendant le message d'erreur de plus de 6 Ko et il n'y avait aucune limite supérieure à la longueur du message d'erreur. Si vous utilisiez accidentellement une chaîne de 1 Mo comme nom de classe, le message d'erreur dépasserait 2 Mo. Dans ce Perl, la limite supérieure devrait être d'environ 2 Ko lorsque l'élision et l'échappement sont pris en compte.
