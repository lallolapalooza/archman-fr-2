NOM

perf-buildid-cache - Gérer la cache des id de compilation.

SYNTAXE

perf buildid-cache <options>

DESCRIPTION

Cette commande gère la cache des id de compilation (build-id). Elle peut ajouter, supprimer, mettre à jour et purger des fichiers vers/depuis la cache. À l'avenir, elle devrait également définir des limites supérieures pour l'espace utilisé par la cache, etc. Elle analyse également le binaire cible pour les SDT (Statically Defined Tracing) et les enregistre avec la cache des id de compilation, qui sera utilisée par perf-probe. Pour plus de détails, voir perf-probe(1).

OPTIONS

-a, --add=

Ajoute le fichier spécifié à la cache.

-f, --force

Ne pas se plaindre, le faire.

-k, --kcore

Ajoute le fichier kcore spécifié à la cache. Pour l'hôte actuel, il s'agit de /proc/kcore, ce qui nécessite des droits root pour la lecture. Soyez conscient que l'exécution de perf buildid-cache en tant que root peut mettre à jour la cache des id de compilation de root et non celle de l'utilisateur. Utilisez l'option -v pour voir où le fichier est créé. Notez que le fichier copié ne contient que les sections de code, pas l'image complète du noyau. Notez également que les fichiers "kallsyms" et "modules" doivent également se trouver dans le même répertoire et sont également copiés. Les 3 fichiers sont créés avec des permissions de lecture uniquement pour root. kcore ne sera pas ajouté s'il existe déjà un kcore dans la cache (avec le même id de compilation) qui a les mêmes modules aux mêmes adresses. Utilisez l'option -v pour voir si une copie de kcore est effectivement effectuée.

-r, --remove=

Supprime un binaire mis en cache qui a le même id de compilation que le fichier spécifié de la cache.

-p, --purge=

Purger tous les binaires mis en cache, y compris les anciennes caches qui ont le chemin spécifié, de la cache.

-P, --purge-all

Purger tous les binaires mis en cache. Cela videra entièrement la cache.

-M, --missing=

Lister les id de compilation manquants dans la cache pour le fichier spécifié.

-u, --update=

Mettre à jour le fichier spécifié de la cache. Notez que cela ne supprime pas les anciennes entrées car elles peuvent toujours être nécessaires pour annoter d'anciennes (ou distantes) perf.data. Seule une cache existante ayant exactement le même id de compilation est remplacée par la nouvelle. Elle peut être utilisée pour mettre à jour kallsyms et le dso du noyau vers vmlinux afin de supporter l'annotation.

-l, --list

Lister tous les binaires valides de la cache.

-v, --verbose

Être plus verbeux.

--target-ns=PID : Obtenir les informations de l'espace de noms de montage du pid cible. Ceci est utilisé lors de la création d'une uprobe pour un processus qui réside dans un espace de noms de montage différent de celui de l'utilitaire perf(1).

--debuginfod[=URLS]

Spécifier l'URL debuginfod à utiliser lors de la récupération des binaires perf.data, il suit la même syntaxe que la variable DEBUGINFOD_URLS, comme : 
buildid-cache.debuginfod=http://192.168.122.174:8002
Si les URL ne sont pas spécifiés, la valeur de la variable d'environnement système DEBUGINFOD_URLS
est utilisée.
