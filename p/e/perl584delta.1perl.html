NOM

perl584delta - ce qu'il y a de nouveau dans la version perl v5.8.4

DESCRIPTION

Ce document décrit les différences entre la version 5.8.3 et la version 5.8.4.

Changements incompatibles

De nombreux bugs mineurs ont été corrigés. Les scripts qui s'appuient par hasard sur un comportement erroné précédent considéreront ces corrections comme des changements incompatibles :-). Il est conseillé de procéder à des tests d'acceptation suffisants sur cette version pour vous assurer que cela ne vous affecte pas, avant de mettre cette version en production.

La sortie diagnostique de Carp a été légèrement modifiée pour ajouter un espace après la virgule entre les arguments. Cela rend beaucoup plus facile l'enveloppement pour des outils tels que les navigateurs web, mais peut confondre les outils automatiques qui effectuent une analyse détaillée de la sortie de Carp.

La sortie de vidage interne a été améliorée, de sorte que les caractères non imprimables tels que le saut de ligne et le retour arrière sont affichés sous la notation "\x", plutôt qu'octale. Cela pourrait juste dérouter les outils non robustes qui analysent la sortie de modules tels que Devel::Peek.

Améliorations du cœur

Enveloppement Malloc

Perl peut maintenant être compilé pour détecter les tentatives d'attribution de blocs de mémoire pathologiquement grands. Auparavant, de telles attributions subissaient un débordement d'entiers lors des calculs de taille, provoquant une mauvaise allocation, ce qui plantait perl et pouvait théoriquement être utilisé pour des attaques de type "dépassement de tampon". L'enveloppement est activé par défaut sur les plateformes où nous savons qu'il fonctionne (la plupart des configurations AIX, BSDi, Darwin, DEC OSF/1, FreeBSD, HP/UX, GNU Linux, OpenBSD, Solaris, VMS et la plupart des compilateurs Win32) et désactivé par défaut sur les autres plateformes.

Base de données de caractères Unicode 4.0.1

La copie de la base de données de caractères Unicode incluse dans Perl 5.8 a été mise à jour de 4.0.0 à 4.0.1.

suidperl moins insécurisé

Paul Szabo a analysé et patché "suidperl" pour supprimer les insécurités connues. Actuellement, il n'y a pas de failles connues dans "suidperl", mais l'expérience précédente montre que nous ne pouvons pas être sûrs qu'il n'y en ait plus. Vous ne pouvez plus invoquer perl setuid directement, donc pour maintenir la compatibilité descendante avec les scripts qui invoquent #!/usr/bin/suidperl, le seul binaire setuid est maintenant "sperl5.8."n ("sperl5.8.4" pour cette version). "suidperl" est installé comme un lien physique vers "perl"; "suidperl" et "perl" invoqueront automatiquement le binaire setuid "sperl5.8.4", donc ce changement devrait être complètement transparent.

Pour les nouveaux projets, l'équipe centrale de perl recommande fortement d'utiliser des outils de sécurité dédiés et mono-fonctionnels tels que "sudo" de préférence à "suidperl".

format

En plus des corrections de bugs, les fonctionnalités de "format" ont été améliorées. Voir perlform

Modules et Pragmata

L'utilisation (erronée) de "/tmp" dans les modules de base et la documentation a été corrigée. Certains modules disponibles à la fois dans le cœur de perl et indépendamment de CPAN ("modules à double durée de vie") n'ont pas encore reçu ces changements ; les changements seront intégrés dans les futures versions stables de perl au fur et à mesure que les modules seront mis à jour sur CPAN.

Améliorations de performance

  • Mappages de casse Unicode accélérés ( "/i", "lc", "uc", etc.).
  • Tri sur place optimisé (par ex. "@a = sort @a")
  • Affectation inutile optimisée et supprimée dans 
    my $s = undef;
my @a = ();
my %h = ();
  • Optimisation de "map" en contexte scalaire

Changements utilitaires

Le débogueur Perl (lib/perl5db.pl) peut maintenant sauvegarder toutes les commandes du débogueur pour les sourcer plus tard, et peut afficher l'arbre d'héritage parent d'une classe donnée.

Améliorations d'installation et de configuration

Le processus de compilation sous VMS et Windows a fait l'objet de plusieurs améliorations mineures. Sous Windows, le compilateur C de Borland peut maintenant compiler perl avec PerlIO et/ou USE_LARGE_FILES activés.

perl584delta - Perl documentation

NAME

perl584delta - cambiamenti in Perl 5.8.4

DESCRIPTION

Ce document décrit les différences entre Perl 5.8.0 et Perl 5.8.4.

Changements Incompatibles

Aucun changement incompatible connu.

Améliorations du Cœur

Aucune amélioration du cœur significative connue.

Modules et Pragmata

Il n'y a pas eu de changement dans les modules fournis.

Améliorations des Performances

La vérification des variables de hachage dans les routines de substitution de chaînes est maintenant beaucoup plus rapide.

Changements Utilitaires

Aucun changement utilitaire significatif connu.

Améliorations de l'Installation et de la Configuration

Le support de la compilation sur les systèmes VOS a été restauré.

La compilation sur le système VOS d'IBM ne devrait plus poser de problème.

L'utilisation de l'icône de chameau fournie uniquement comme icône d'exécutable Perl n'est pas couverte. Toute personne souhaitant redistribuer des binaires Perl *avec* l'icône devrait vérifier directement avec O'Reilly au préalable.

Perl devrait à nouveau compiler proprement sur Stratus VOS.

Corrections de Bugs Sélectionnées

Plus de bugs liés à l'UTF-8 corrigés, notamment dans la manière dont "chomp", "chop", "send" et "syswrite" interagissent avec les données UTF-8. La concaténation fonctionne maintenant correctement lorsque "use bytes;" est dans le scope.

Les pragmata sont maintenant correctement propagées dans les constructions (?{...}) dans les regex. Un code tel que

my $x = qr{ ... (??{ $x }) ... };

échouera maintenant (correctement) sous use strict. (Comme le $x intérieur fait et a toujours fait référence à $::x)

L'avertissement « const in void context » a été supprimé pour une constante dans une expression booléenne optimisée hors contexte telle que "5 || print;"

"perl -i" pouvait accidentellement appeler fchmod(stdin). Ceci est grave si stdin est connecté à un terminal et que Perl s'exécute en tant que root. Désormais corrigé.

Diagnostics Nouveaux ou Modifiés

"Carp" et les routines de diagnostic internes utilisées par "Devel::Peek" ont été clarifiées, comme décrit dans "Changements Incompatibles"

Internes Modifiés

Quelques bugs ont été corrigés dans les internes de hachage. Les hachages restreints et leurs espaces réservés sont maintenant alloués et supprimés à des moments légèrement différents, mais cela ne devrait pas être visible par le code utilisateur.

Directions Futures

Le gel du code pour la prochaine version de maintenance (5.8.5) sera le 30 juin 2004, avec une sortie d'ici mi-juillet.

Problèmes Spécifiques à la Plateforme

Il est connu que cette version ne compile pas sous Windows 95.

Signalement de Bugs

Si vous trouvez ce que vous pensez être un bug, vous pourriez consulter les articles récemment postés sur le groupe de discussion comp.lang.perl.misc et la base de données de bugs Perl à l'adresse http://bugs.perl.org. Il peut également y avoir des informations sur http://www.perl.org, la page d'accueil de Perl.

Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus dans votre version. Assurez-vous de réduire votre bug à un cas de test minuscule mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage Perl. Vous pouvez parcourir et rechercher les bugs de Perl 5 à l'adresse http://bugs.perl.org/
