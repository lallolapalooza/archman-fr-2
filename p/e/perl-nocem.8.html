NOM

perl-nocem - Implémentation de NoCeM sur le spool pour INN 2.x

SYNTAXE

perl-nocem [-hlu] [-b répertoire] [-c nom_de_fichier] [-g commande] [-G commande] [-i nom_de_fichier] [-k porte-clés] [-v niveau]

DESCRIPTION

NoCeM, qui se prononce No See 'Em (ne les voyez pas), est un protocole permettant à des tiers authentifiés d'émettre des avis qui peuvent être utilisés pour annuler des articles indésirables (comme le spam et les articles dans des groupes de discussion modérés qui n'ont pas été approuvés par leurs modérateurs). Il peut également être utilisé par les lecteurs comme un killfile tiers. Il est destiné à remplacer à terme le protocole des messages d'annulation tiers qui peuvent être forgés trop facilement car les messages d'annulation ne sont pas authentifiés, contrairement aux avis NoCeM.

perl-nocem traite les avis d'annulation d'articles tiers signés par PGP. Il est possible d'honorer un ensemble sélectif d'avis NoCeM, et pas tous. Vous pouvez configurer dans nocem.ctl dans pathetc la liste des émetteurs NoCeM dont vous vous fiez et ajouter les clés PGP publiques correspondantes à votre porte-clés NoCeM (par défaut, aucune clé PGP n'est installée, donc personne n'est digne de confiance). Il vous appartient de décider si vous souhaitez honorer leurs avis, en fonction des critères qu'ils utilisent. Vous êtes encouragé à consulter régulièrement le registre officiel NoCeM https://rosalind.home.xs4all.nl/nocemreg/nocemreg.html pour vérifier d'éventuels nouveaux émetteurs NoCeM à ajouter et avoir un aperçu de leur politique. Le résumé quotidien des messages NoCeM envoyés https://www.novabbs.com/SEARCH/search_nocem.php?stats=daily peut également être utile.

perl-nocem attend soit des jetons de stockage, soit des noms de fichiers sur son entrée standard. Il lira et traitera ensuite l'article correspondant. Il ajoute tous les messages de statut à perl-nocem.log dans pathlog si le système syslog n'est pas disponible ou si l'indicateur -l est explicitement utilisé ; sinon, le système syslog est utilisé, auquel cas les messages de statut sont ajoutés à un fichier généralement nommé news.notice dans pathlog. (Certains journaux ne seront écrits que si le niveau de débogage est configuré pour être enregistré via syslog.)

CONFIGURATION

Le traitement des avis NoCeM est facile à mettre en place :

1.
Si ce n'est pas déjà fait, installez GnuPG, ou une implémentation équivalente de la norme OpenPGP, pour pouvoir vérifier la signature des messages NoCeM. Il fournira les programmes gpg et gpgv. Si GnuPG a déjà été installé lors de la configuration d'INN, les chemins vers ces programmes ont été pris en compte. Sinon, vous pouvez utiliser les indicateurs -g et -G pour définir (voire remplacer) les commandes que perl-nocem utilisera pour exécuter ces programmes.

Tous les émetteurs NoCeM encore actifs utilisent des clés PGP plutôt modernes acceptées par les versions GnuPG 1.x et 2.x. Il n'est plus nécessaire d'utiliser explicitement gpg1 pour traiter les avis NoCeM.

2.
Importez les clés publiques des émetteurs NoCeM dont vous vous fiez afin de vérifier l'authenticité de leurs avis. Vous pouvez exécuter la commande suivante : 
gpg --no-default-keyring --allow-non-selfsigned-uid \
    --primary-keyring <pathetc>/pgp/ncmring.gpg --no-options \
    --no-permission-warning --batch --import <fichier-clé>
chmod 644 <pathetc>/pgp/ncmring.gpg

où <pathetc> est la valeur du paramètre pathetc défini dans inn.conf et <fichier-clé> est le fichier contenant la ou les clés publiques à importer. Le porte-clés se trouve par défaut dans <pathetc>/pgp/ncmring.gpg ; vous n'avez qu'à créer le répertoire <pathetc>/pgp avant d'utiliser gpg (il générera automatiquement le fichier ncmring.gpg) et vous assurer que l'utilisateur news peut lire ce fichier, une fois généré. Vous pouvez utiliser un autre emplacement et nom de fichier pour le porte-clés, puis exécuter perl-nocem avec l'indicateur -k.

Les clés publiques des émetteurs NoCeM peuvent être trouvées sur le site web de The NoCeM Registry https://rosalind.home.xs4all.nl/nocemreg/nocemreg.html où vous pouvez même télécharger un fichier unique contenant toutes les clés publiques.

3.
Créez ou mettez à jour le fichier de configuration nocem.ctl dans pathetc pour indiquer les émetteurs NoCeM et les types d'avis que vous souhaitez suivre. Ce fichier de permissions contient des lignes comme : 
bleachbot@httrack.com:spam,site
pgpmoose@killfile.org:pgpmoose-forged-moderation

Ceci supprimera tous les articles pour lesquels l'émetteur (première partie de la ligne, avant le signe deux-points ":") a émis des avis NoCeM d'un type présent dans la liste de types séparés par des virgules spécifiée après le signe deux-points (l'utilisation de "*" est possible, et signifie que tous les types sont acceptés).

Les lignes vides et les lignes commençant par un signe dièse ("#") sont ignorées. La casse est insensible. Toute entrée sans clé PGP publique correspondante dans le porte-clés sera ignorée.

Vous trouverez également des informations sur les émetteurs sur le site web de The NoCeM Registry. Notez qu'INN est livré avec un fichier nocem.ctl à jour déjà configuré avec les émetteurs NoCeM actuels. (Seules les clés PGP publiques installées à l'étape précédente ne sont pas incluses, afin de vous laisser le choix de qui faire confiance, et de télécharger les plus récentes, au cas où elles auraient changé.)

4.
Ajoutez au fichier newsfeeds dans pathetc une entrée comme celle-ci afin d'alimenter perl-nocem avec les messages NoCeM (cross)postés sur news.lists.filters, le groupe de discussion global où les avis doivent être envoyés : 
nocem!\
    :!*,news.lists.filters\
    :Tc,Wf,Ap:<pathbin>/perl-nocem

avec le chemin correct vers perl-nocem, situé dans <pathbin>, et tout indicateur optionnel que vous souhaitez utiliser. Ensuite, exécutez "inncheck" pour vous assurer que la syntaxe du fichier newsfeeds modifié est correcte, et rechargez-le (via "ctlinnd reload newsfeeds 'Flux de canal NoCeM'").

Notez que vous devez au moins recevoir news.lists.filters sur votre serveur de news (ou d'autres groupes de discussion où les avis NoCeM sont envoyés) si vous souhaitez les traiter.

5.
Tout devrait maintenant fonctionner. Cependant, n'hésitez pas à tester manuellement perl-nocem avec un message NoCeM, en utilisant l'une des méthodes suivantes : 
grephistory '<Message-ID>' | perl-nocem -l -v 2
echo '/chemin/vers/un/message/nocem' | perl-nocem -l -v 2

perl-nocem attend soit des jetons de stockage, soit des noms de fichiers sur son entrée standard (grephistory renvoie le jeton de stockage d'un article identifié par son Message-ID).

Vérifiez les journaux de ce test dans perl-nocem.log dans pathlog.

Vous pouvez également vérifier la liste des clés publiques PGP installées avec la commande suivante, adaptée à l'emplacement du porte-clés NoCeM :

gpg --no-default-keyring --list-keys \
    --primary-keyring <pathetc>/pgp/ncmring.gpg

OPTIONS

-b répertoire
Sauvegarde les articles annulés dans des fichiers dans répertoire. Le répertoire doit exister et être accessible en écriture par l'utilisateur news. Les fichiers sont nommés émetteur%type, et contiennent les articles effectivement supprimés de votre spool de news par l'émetteur NoCeM donné pour le type d'avis NoCeM donné. Les articles annulés qui ne sont pas stockés dans votre spool de news lors du traitement de l'avis ne peuvent pas être sauvegardés.

Cet indicateur est principalement destiné à auditer d'éventuels faux positifs. Comme les sauvegardes ne sont pas purgées automatiquement, vous devriez les nettoyer de temps en temps après avoir inspecté leur contenu.

-c nom_de_fichier
Par défaut, perl-nocem lit un fichier de configuration nommé nocem.ctl dans pathetc. Cet indicateur permet de lire un autre fichier de configuration, spécifié par un chemin absolu.

Installé à ce moment-là, ou si vous voulez utiliser un autre programme, ce drapeau sera utile. Assurez-vous qu'au moins l'équivalent des options par défaut données à gpg est présent dans command ; sinon, perl-nocem peut mal fonctionner.

En supposant que "/bin/gpg" correspond à l'exécutable gpg, la valeur par défaut est :

-g "/bin/gpg --status-fd=1 --verify --allow-weak-digest-algos"
-G command
Par défaut, perl-nocem exécute l'exécutable gpgv(1) dont le chemin a été déterminé lors de la configuration de INN. Si GnuPG n'était pas installé à ce moment-là, ou si vous voulez utiliser un autre programme, ce drapeau sera utile. Assurez-vous qu'au moins l'équivalent de l'option par défaut donnée à gpgv est présent dans command ; sinon, perl-nocem peut mal fonctionner.

En supposant que "/bin/gpgv" correspond à l'exécutable gpgv, la valeur par défaut est :

-G "/bin/gpgv --status-fd=1"

Notez que gpg sera utilisé préférentiellement à gpgv lorsque les deux sont disponibles, à moins que -g ne reçoive une chaîne vide.

-h
Affiche un message d'utilisation sur la sortie standard et quitte.
-i filename
Lorsque ce drapeau est utilisé, perl-nocem inclut un script Perl externe nommé filename, spécifié par un chemin absolu. Il permet de charger une fonction "local_want_cancel_id" avec des règles locales pour affiner, au sein d'une notice NoCeM, quels articles doivent être annulés. Tous les articles présents dans une notice NoCeM sont sinon annulés par défaut.

Cette fonction est appelée pour chaque article de la notice et a accès à plusieurs variables : le Message-ID $msgid du message NoCeM, le Message-ID $artid de l'article à annuler, la liste séparée par des virgules des newsgroups $groups auxquels l'article à annuler a été posté, la référence de hachage $hdrs vers les champs d'en-tête pseudo de la notice NoCeM, en minuscules. L'article est conservé si la fonction renvoie 0, et annulé sinon.

Voici une illustration de ce que cette fonction peut faire, lorsqu'elle est définie dans filename et que le drapeau -i est utilisé :

sub local_want_cancel_id {
    my ($msgid, $artid, $groups, $hdrs) = @_;
    my $carried = 0;
    # Parcourt les newsgroups auxquels l'article a été posté.
    foreach my $group (split(/,/, $groups)) {
        # Le conserve s'il est posté sur news.software.nntp.
        return 0 if $group eq "news.software.nntp";
        # Le conserve s'il est posté sur fr.* et que l'émetteur est "john".
        return 0
          if $group =~ /^fr\./ and $hdrs->{issuer} eq "john";
        # L'article a été posté sur au moins un newsgroup
        # dans la hiérarchie fr.* ou news.*. Vous pouvez utiliser ici
        # une expression régulière correspondant au motif de newsgroups
        # que vous demandez à vos flux de vous envoyer.
        $carried = 1 if $group =~ /^(fr|news)\./;
    }
    # Dans le cas où le serveur ne transporte que fr.* et news.*, cette
    # règle permet de rejeter les notices NoCeM relatives aux
    # newsgroups non transportés par le serveur, et donc
    # de ne pas traiter ni mémoriser dans le fichier d'historique
    # les Message-IDs des articles qui n'atteindront pas le serveur.
    return 0 if not $carried;
    # Le conserve s'il est uniquement posté sur news.admin.net-abuse.usenet
    # et que le type de la notice est "spam".
    return 0
      if $groups eq "news.admin.net-abuse.usenet"
      and $hdrs->{type} eq "spam";
    # Annule-le !
    return 1;
}

Si un problème de syntaxe survient lors du chargement de la fonction par Perl, perl-nocem s'arrêtera et signalera la raison dans les logs. Vous devrez alors corriger la fonction.

-k keyring
Par défaut, perl-nocem vérifie les signatures des messages NoCeM avec les clés publiques PGP présentes dans un keyring nommé ncmring.gpg dans le répertoire pathetc/pgp. Ce drapeau permet d'utiliser un autre keyring, spécifié par un chemin absolu.

Un drapeau --keyring= avec la valeur keyring est alors passé aux commandes gpg(1) et gpgv(1) à moins que keyring ne soit une chaîne vide.

-l
Par défaut, perl-nocem envoie les logs à syslog(3). Si le facility syslog n'est pas disponible ou si ce drapeau est utilisé, les logs sont envoyés à perl-nocem.log dans pathlog. Le niveau de log d'erreur sera toujours envoyé en plus à syslog si disponible.
-u
Par défaut, innreport affichera les notices NoCeM non traitées dans les rapports quotidiens qu'il génère. Lorsque ce drapeau est utilisé, les émetteurs ou les types de notices non configurés dans nocem.ctl seront toujours mentionnés dans les logs, mais les lignes de log correspondantes ne seront pas analysées par innreport.
-v level
Augmente la verbosité des logs à ce level, de 1 à 3. La valeur par défaut est 1.

FICHIERS

pathbin/perl-nocem
Le script Perl lui-même utilisé pour traiter les messages NoCeM.
pathetc/nocem.ctl
Le fichier de configuration qui spécifie les notices NoCeM à traiter. Un autre fichier peut être spécifié avec le drapeau -c.
pathetc/pgp/ncmring.gpg
Le keyring qui contient les clés publiques des émetteurs NoCeM de confiance. Un autre fichier peut être spécifié avec le drapeau -k.
pathlog/perl-nocem.log
Le fichier de log utilisé lorsque le facility syslog n'est pas disponible ou que le drapeau -l est utilisé.

NOTES

L'exactitude des newsgroups suivant les Message-IDs à annuler dans le corps du NoCeM n'est pas vérifiée, pas plus que le champ d'en-tête pseudo Newsgroups s'il est présent. Eh bien, étant donné que nous faisons déjà confiance à l'émetteur de la notice concernant les Message-IDs qu'il marque comme spam, ayons également confiance concernant les newsgroups listés.
