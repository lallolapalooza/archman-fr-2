OBTENIR DE L'AIDE

Le programme perldoc vous donne accès à toute la documentation fournie avec Perl. Vous pouvez obtenir plus de documentation, de tutoriels et de support communautaire en ligne sur https://www.perl.org/.

Si vous êtes nouveau dans Perl, vous devriez commencer par exécuter "perldoc perlintro", qui est une introduction générale pour les débutants et fournit un contexte pour vous aider à naviguer dans le reste de la documentation étendue de Perl. Exécutez "perldoc perldoc" pour en savoir plus sur ce que vous pouvez faire avec perldoc.

Pour faciliter l'accès, le manuel Perl a été divisé en plusieurs sections.

DESCRIPTION

Perl signifie officiellement Practical Extraction and Report Language, sauf quand ce n'est pas le cas.

Perl était à l'origine un langage optimisé pour l'analyse de fichiers texte arbitraires, l'extraction d'informations de ces fichiers texte et l'impression de rapports basés sur ces informations. Il est rapidement devenu un bon langage pour de nombreuses tâches d'administration système. Au fil des ans, Perl est devenu un langage de programmation à usage général. Il est largement utilisé pour tout, des "one-liners" rapides au développement d'applications à grande échelle.

Le langage est destiné à être pratique (facile à utiliser, efficace, complet) plutôt que beau (minuscule, élégant, minimal). Il combine (selon l'auteur, en tout cas) certaines des meilleures fonctionnalités de sed, awk et sh, ce qui le rend familier et facile à utiliser pour les utilisateurs Unix afin de créer rapidement des solutions à des problèmes agaçants. Ses facilités de programmation à usage général prennent en charge les paradigmes de programmation procédurale, fonctionnelle et orientée objet, faisant de Perl un langage confortable pour le long terme sur des projets majeurs, quelle que soit votre orientation.

Les racines de Perl dans le traitement de texte n'ont pas été oubliées au fil des ans. Il dispose toujours de certaines des expressions régulières les plus puissantes que l'on puisse trouver, et son support du texte Unicode est de classe mondiale. Il traite également toutes sortes de textes structurés, grâce à une collection étendue d'extensions. Ces bibliothèques, collectées dans le CPAN, fournissent des solutions prêtes à l'emploi pour un éventail étonnant de problèmes. Quand elles n'ont pas défini la norme elles-mêmes, elles volent les meilleures -- tout comme Perl lui-même.

DIAGNOSTICS

L'utilisation du pragma "use strict" garantit que toutes les variables sont correctement déclarées et empêche d'autres utilisations abusives de fonctionnalités Perl héritées. Celles-ci sont activées par défaut dans la portée de "use v5.12" (ou supérieur).

Le pragma "use warnings" produit de diagnostics utiles. Il est activé par défaut lorsque vous dites "use v5.35" (ou supérieur). On peut aussi utiliser le drapeau -w, mais son utilisation est normalement déconseillée, car il s'applique à tout le code Perl exécuté, y compris celui qui n'est pas sous votre contrôle.

Voir perldiag pour des explications de tous les diagnostics de Perl. Le pragma "use diagnostics" transforme automatiquement les avertissements et erreurs normalement concis de Perl en ces formes plus longues.

Les erreurs de compilation indiqueront le numéro de ligne de l'erreur, avec une indication du prochain jeton ou type de jeton qui devait être examiné. (Dans un script passé à Perl via les commutateurs -e, chaque -e est compté comme une ligne.)

Les scripts Setuid ont des contraintes supplémentaires qui peuvent produire des messages d'erreur tels que "Insecure dependency". Voir perlsec.

Avons-nous mentionné que vous devriez absolument envisager d'utiliser le pragma use warnings ?

BOGUES

Le comportement implicite par le pragma use warnings n'est pas obligatoire.

Perl est à la merci des définitions de votre machine pour diverses opérations telles que le transtypage, atof() et la sortie en nombre à virgule flottante avec sprintf().

Si votre stdio nécessite un seek ou un eof entre les lectures et les écritures sur un flux particulier, Perl le nécessite également. (Cela ne s'applique pas à sysread() et syswrite().)

Bien qu'aucun des types de données intégrés n'ait de limites de taille arbitraires (à part la taille de la mémoire), il existe encore quelques limites arbitraires : un nom de variable donné ne peut pas dépasser 251 caractères. Les numéros de ligne affichés par les diagnostics sont stockés en interne sous forme de short

BUGS

The maximum number of items in a list is limited by the maximum value of a C long. This is generally 2^31-1 on 32-bit systems and 2^63-1 on 64-bit systems. The number of elements in an array is limited by the maximum size of a C unsigned long. This is generally 2^32-1 on 32-bit systems and 2^64-1 on 64-bit systems.

Some functions will have different behavior on 16-bit systems. Perl is not supported on 16-bit systems.

On systems that don't define _POSIX_SOURCE or _XOPEN_SOURCE, Perl may not correctly handle certain characters in filenames (e.g. characters with the high bit set). This can be fixed by defining _POSIX_SOURCE or _XOPEN_SOURCE before including Perl's headers.

Floating-point numbers are usually IEEE 754. The accuracy of floating point numbers is the same as that of the C compiler's double type. Some operations might produce incorrect results, such as sqrt(-1), which should yield NaN but might yield 0 or something else entirely.

Some string functions are implemented using floating-point numbers internally, so they may be subject to the same limitations as floating-point arithmetic.

Most Perl integer operations are performed using unsigned integers, so they are limited to a maximum of 65535 (higher numbers usually being affected by wraparound).

You may submit your bug reports (be sure to include full configuration information as output by the myconfig program in the perl source tree, or by "perl -V") to https://github.com/Perl/perl5/issues.

BOGUES

Le nombre maximum d'éléments dans une liste est limité par la valeur maximale d'un long C. Ceci est généralement 2^31-1 sur les systèmes 32 bits et 2^63-1 sur les systèmes 64 bits. Le nombre d'éléments dans un tableau est limité par la taille maximale d'un unsigned long C. Ceci est généralement 2^32-1 sur les systèmes 32 bits et 2^64-1 sur les systèmes 64 bits.

Certaines fonctions auront un comportement différent sur les systèmes 16 bits. Perl n'est pas supporté sur les systèmes 16 bits.

Sur les systèmes qui ne définissent pas _POSIX_SOURCE ou _XOPEN_SOURCE, Perl peut ne pas gérer correctement certains caractères dans les noms de fichiers (par exemple, les caractères ayant le bit de poids fort défini). Ceci peut être corrigé en définissant _POSIX_SOURCE ou _XOPEN_SOURCE avant d'inclure les en-têtes de Perl.

Les nombres à virgule flottante sont généralement IEEE 754. La précision des nombres à virgule flottante est la même que celle du type double du compilateur C. Certaines opérations peuvent produire des résultats incorrects, comme sqrt(-1), qui devrait renvoyer NaN mais peut renvoyer 0 ou quelque chose d'autre.

Certaines fonctions de chaîne sont implémentées en utilisant des nombres à virgule flottante en interne, elles peuvent donc être soumises aux mêmes limitations que l'arithmétique à virgule flottante.

La plupart des opérations sur les entiers Perl sont effectuées en utilisant des entiers non signés, elles sont donc limitées à un maximum de 65535 (les nombres plus élevés étant généralement affectés par le débordement).
