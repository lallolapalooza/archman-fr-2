NOM

perl583delta - ce qu'il y a de nouveau pour la version perl v5.8.3

DESCRIPTION

Ce document décrit les différences entre la version 5.8.2 et la version 5.8.3.

Si vous mettez à niveau depuis une version antérieure comme la 5.6.1, lisez d'abord perl58delta, qui décrit les différences entre 5.6.0 et 5.8.0, ainsi que perl581delta et perl582delta, qui décrivent les différences entre 5.8.0, 5.8.1 et 5.8.2.

CHANGEMENTS INCOMPATIBLES

Il n'y a aucun changement incompatible avec la version 5.8.2.

AMÉLIORATIONS DU CŒUR

Une méthode "SCALAR" est maintenant disponible pour les hachages liés (tied hashes). Elle est appelée lorsqu'un hachage lié est utilisé dans un contexte scalaire, par exemple :

if (%tied_hash) {
    ...
}

Le comportement précédent était que %tied_hash renvoyait ce qui aurait été renvoyé pour cet hachage avant que le hachage ne soit lié (donc généralement 0). Le nouveau comportement, en l'absence de méthode SCALAR, est de renvoyer VRAI si l'on est au milieu d'une itération "each", et sinon d'appeler FIRSTKEY pour vérifier si le hachage est vide (en s'assurant qu'un "each" subséquent appellera également FIRSTKEY au début). Veuillez consulter "SCALAR" dans perltie pour les détails complets et les mises en garde.

CHANGEMENTS DES UTILITAIRES

"find2perl" suppose maintenant "-print" comme action par défaut. Auparavant, il fallait le spécifier explicitement.

Un nouvel utilitaire, "prove", permet de lancer facilement un test de régression individuel en ligne de commande. "prove" fait partie de Test::Harness, que les utilisateurs de versions antérieures de Perl peuvent installer depuis CPAN.

NOUVELLE DOCUMENTATION

La documentation a été révisée par endroits pour produire des manpages plus standard.

La documentation des blocs de code spéciaux (BEGIN, CHECK, INIT, END) a été améliorée.

AMÉLIORATIONS D'INSTALLATION ET DE CONFIGURATION

Perl se compile maintenant sur OpenVMS I64.

CORRECTIONS DE BOGUES SÉLECTIONNÉES

L'utilisation de substr() sur une chaîne UTF8 pouvait provoquer des accès ultérieurs à cette chaîne renvoyant des données inutilisables. Cela était dû à la mise en cache d'offsets UTF8 incorrects, et est maintenant corrigé.

join() pouvait renvoyer des données inutilisables lorsque la même instruction join() était utilisée pour traiter des données 8 bits après avoir traité des données UTF8, en raison du fait que les drapeaux de l'espace de travail temporaire de cette instruction n'étaient pas réinitialisés correctement. Ceci est maintenant corrigé.

"$a .. $b" fonctionnera maintenant comme prévu lorsque $a ou $b est "undef".

L'utilisation de clés Unicode avec des hachages liés devrait maintenant fonctionner correctement.

La lecture de $^E préserve maintenant $!. Précédemment, le code C implémentant $^E ne préservait pas "errno", donc la lecture de $^E pouvait provoquer un changement inattendu de "errno" et donc de $!.

Les fonctions réentrantes fonctionneront (une fois de plus) avec C++. La version 5.8.2 avait introduit une correction de bogue qui avait accidentellement cassé la compilation d'extensions Perl écrites en C++.

DIAGNOSTICS NOUVEAUX OU MODIFIÉS

L'erreur fatale "DESTROY created new reference to dead object" est maintenant documentée dans perldiag.

INTERNES MODIFIÉS

Le code des hachages a été refactorisé pour réduire la duplication de code source. L'interface externe reste inchangée, et à part les corrections de bogues décrites ci-dessus, il ne devrait y avoir aucun changement de comportement.

"hv_clear_placeholders" fait maintenant partie de l'API perl.

Certaines macros C ont été tidied. En particulier, les macros qui créent des variables locales temporaires nomment maintenant ces variables de manière plus défensive, ce qui devrait éviter les bogues où les noms se chevauchent.

<signal.h> est maintenant toujours inclus.

CONFIGURATION ET COMPILATION

"Configure" invoque maintenant des callbacks quelle que soit la valeur de la variable pour laquelle ils sont appelés. Auparavant, les callbacks n'étaient invoqués que dans la branche "case $variable $define)". Ce changement ne devrait affecter que les mainteneurs de plateforme écrivant des fichiers d'indices de configuration.

PROBLÈMES SPÉCIFIQUES AUX PLATEFORMES

Le test de régression ext/threads/shared/t/wait.t échoue sur les premières versions de RedHat 9 et HP-UX 10.20 en raison de bogues dans leurs implémentations de threading. Les utilisateurs RedHat devraient consulter https://rhn.redhat.com/errata/RHBA-2003-136.html et envisager de mettre à jour leur glibc.

PROBLÈMES CONNUS

Les threads détachés ne sont pas encore pris en charge sous Windows, car ils peuvent entraîner des problèmes d'accès mémoire non valide.

Il existe une condition de concurrence connue lors de l'ouverture de scripts dans "suidperl". "suidperl" n'est ni construit ni installé par défaut, et il a été déprécié depuis perl 5.8.0. Il est conseillé de remplacer l'utilisation de suidperl par des outils tels que sudo ( http://www.courtesan.com/sudo/ ).

Nous avons un arriéré de bogues non résolus. Traiter les bogues et les rapports de bogues est un travail peu glamour; pas quelque chose qui convient idéalement au travail bénévole, mais c'est tout ce que nous avons.

L'équipe de développement de perl5 met en œuvre des changements pour aider à résoudre ce problème, qui devraient être mis en ligne début 2004.

Signalement de bogues

Si vous trouvez ce que vous pensez être un bogue, vous pouvez consulter les articles récemment publiés sur le groupe de discussion comp.lang.perl.misc et la base de données des bogues de Perl à http://bugs.perl.org. Vous pourriez également trouver des informations sur http://www.perl.org, la page d'accueil de Perl.

Si vous pensez avoir un bogue non signalé, veuillez exécuter le programme perlbug inclus dans votre version. Assurez-vous de réduire votre bogue à un cas de test simple mais suffisant. Votre rapport de bogue, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl. Vous pouvez parcourir et rechercher les bogues de Perl 5 à http://bugs.perl.org/
