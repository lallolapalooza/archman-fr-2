PERL5223DELTA(1perl) Guide de référence du programmeur Perl PERL5223DELTA(1perl)

NOM

perl5223delta - ce qu'il y a de nouveau pour la version perl v5.22.3

DESCRIPTION

Ce document décrit les différences entre la version 5.22.2 et la version 5.22.3.

Si vous mettez à niveau depuis une version antérieure comme la 5.22.1, lisez d'abord perl5222delta, qui décrit les différences entre la 5.22.1 et la 5.22.2.

Sécurité

Le commutateur -Di est maintenant requis pour la sortie de débogage PerlIO

Auparavant, la sortie de débogage PerlIO était envoyée au fichier spécifié par la variable d'environnement "PERLIO_DEBUG" si perl ne fonctionnait pas en mode setuid et que les commutateurs -T ou -t n'avaient pas encore été analysés.

Si perl produisait une sortie à un moment où il n'avait pas encore analysé ses commutateurs, cela pouvait entraîner la création ou l'écrasement par perl du fichier nommé par "PERLIO_DEBUG" même lorsque le commutateur -T avait été fourni.

Perl requiert maintenant le commutateur -Di pour produire une sortie de débogage PerlIO. Par défaut, celle-ci est écrite sur "stderr", mais peut éventuellement être redirigée vers un fichier en définissant la variable d'environnement "PERLIO_DEBUG".

Si perl fonctionne en mode setuid ou si le commutateur -T a été fourni, "PERLIO_DEBUG" est ignoré et la sortie de débogage est envoyée à "stderr" comme pour tout autre commutateur -D.

Les modules et outils de base ne recherchent plus "." pour les modules optionnels

Les outils et de nombreux modules fournis dans le cœur (core) ne recherchent plus le répertoire du répertoire courant par défaut dans @INC pour les modules optionnels. Par exemple, Storable supprimera le "." final de @INC avant d'essayer de charger Log::Agent.

Cela empêche un attaquant d'injecter un module optionnel dans un processus exécuté par un autre utilisateur, où le répertoire courant est modifiable par l'attaquant, par exemple le répertoire /tmp.

Dans la plupart des cas, cette suppression ne devrait pas causer de problèmes, mais des difficultés ont été rencontrées avec base, qui traite chaque nom de module fourni comme optionnel. Ces difficultés n'ont pas encore été résolues, donc pour cette version, il n'y a pas de changements à base. Nous espérons avoir un correctif pour base dans Perl 5.22.4.

Pour protéger votre propre code contre cette attaque, supprimez l'entrée "." par défaut de @INC au début de votre script, donc :

#!/usr/bin/perl
use strict;
...

devient :

#!/usr/bin/perl
BEGIN { pop @INC if $INC[-1] eq '.' }
use strict;
...

ou pour les modules, supprimez "." d'un @INC localisé, donc :

my $can_foo = eval { require Foo; }

devient :

my $can_foo = eval {
    local @INC = @INC;
    pop @INC if $INC[-1] eq '.';
    require Foo;
};

Changements Incompatibles

Outre les changements de sécurité ci-dessus, il n'y a aucun changement intentionnellement incompatible avec Perl 5.22.2. S'il en existe, ce sont des bogues, et nous vous prions de soumettre un rapport. Voir "Signalement des bogues" ci-dessous.

Remerciements

Perl 5.22.3 représente environ 9 mois de développement depuis Perl 5.22.2 et contient environ 4 400 lignes de changements réparties sur 240 fichiers provenant de 20 auteurs.

En excluant les fichiers générés automatiquement, la documentation et les outils de distribution, il y a eu environ 2 200 lignes de changements dans 170 fichiers .pm, .t, .c et .h.

Perl continue de prospérer dans sa troisième décennie grâce à une communauté dynamique d'utilisateurs et de développeurs. Les personnes suivantes sont connues pour avoir contribué aux améliorations qui sont devenues Perl 5.22.3 :

Signaler des bogues

Si vous trouvez ce que vous pensez être un bogue, vous pouvez consulter les articles récemment publiés sur le groupe de discussion comp.lang.perl.misc et la base de données des bogues de Perl à l'adresse https://rt.perl.org/ . Il peut également y avoir des informations sur http://www.perl.org/ , la page d'accueil de Perl.

Si vous croyez avoir un bogue non signalé, veuillez exécuter le programme perlbug inclus dans votre version. Assurez-vous de réduire votre bogue à un cas de test minuscule mais suffisant. Votre rapport de bogue, ainsi que la sortie de "perl -V", sera envoyé à perlbug@perl.org pour être analysé par l'équipe de portage de Perl.

Si le bogue que vous signalez a des implications en matière de sécurité, qui le rendent inapproprié à l'envoi à une liste de diffusion publiquement archivée, veuillez l'envoyer à perl5-security-report@perl.org. Ceci pointe vers une liste de diffusion fermée et non archivée, qui comprend tous les committeurs principaux, qui seront en mesure d'aider à évaluer l'impact des problèmes, de trouver une solution et d'aider à coordonner la publication de correctifs pour atténuer ou résoudre le problème sur toutes les plateformes sur lesquelles Perl est pris en charge. Veuillez n'utiliser cette adresse que pour les problèmes de sécurité dans le cœur de Perl, et non pour les modules distribués indépendamment sur CPAN.
