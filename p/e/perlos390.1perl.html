PERLOS390(1perl) Guide du programmeur Perl PERLOS390(1perl)

NOM

perlos390 - compilation et installation de Perl pour z/OS (anciennement appelé OS/390)

SYNOPIS

Ce document vous aidera à configurer, compiler, tester et installer Perl sous z/OS Unix System Services.

DESCRIPTION

Ceci est une version portée de Perl pour z/OS. Elle a été testée sur z/OS 2.4 et devrait fonctionner correctement avec z/OS 2.5. Elle pourrait fonctionner sur d'autres versions ou éditions, mais ce sont celles sur lesquelles elle a été testée.

Le jeu de caractères natif de z/OS est l'EBCDIC, mais il peut aussi fonctionner en mode ASCII. Perl peut supporter l'un ou l'autre, mais vous devez le compiler explicitement pour l'un ou l'autre. Vous pourriez avoir à la fois un perl ASCII et un perl EBCDIC sur la même machine. Si vous utilisez le mode ASCII et un perl ASCII, le module Encode fourni avec Perl peut être utilisé pour traduire des fichiers de divers jeux de caractères EBCDIC pour le traitement par Perl, puis pour les reconvertir en sortie.

Ce document décrit comment compiler un Perl dynamique 64 bits, ASCII ou EBCDIC. Vous pouvez choisir interactivement d'autres configurations, ainsi que de nombreuses autres options dans le script Configure qui est exécuté dans le cadre du processus de compilation. Vous devrez peut-être effectuer certaines tâches de configuration système avant d'exécuter Configure, comme détaillé ci-dessous.

Outils

Vous voudrez vous procurer GNU make 4.1 ou une version ultérieure. GNU make peut être téléchargé à partir d'un port fourni par Rocket Software. Vous aurez besoin du compilateur c99 de z/OS d'IBM (bien que xlc en mode c99 sans optimisation activée fonctionne en EBCDIC).

Si vous souhaitez la dernière version de développement de Perl, vous aurez besoin de git. Vous pouvez utiliser git sur une autre plateforme et transférer le résultat via sftp ou ftp vers z/OS. Mais il existe un port client git natif pour z/OS disponible via Rocket Software.

Vous pourriez également avoir besoin du port client gunzip fourni par Rocket Software pour décompresser tout tarball zippé que vous téléchargez sur z/OS.

Compilation d'un Perl dynamique 64 bits en ASCII

Pour compiler à partir d'une version stable officielle de Perl, allez sur https://www.perl.org/get.html et choisissez l'un des boutons « Download latest stable source ». Cela vous donnera un tarball. Le nom de ce tarball sera quelque chose comme 'perl-V.R.M.tar.gz', où V.R.M est la version/édition/modification du perl que vous téléchargez. Faites

gunzip perl-V.R.M.tar.gz

Puis l'une des commandes suivantes :

tar -xvf perl-V.R.M.tar
pax -r -f perl-V.R.M.tar

L'une ou l'autre de ces commandes créera le répertoire source. Vous pouvez le renommer comme vous le souhaitez ; pour ces instructions, on suppose que le nom est 'perl'.

Si, au lieu de cela, vous souhaitez la dernière version de développement instable, en utilisant le client git natif sur z/OS, clonez Perl :

git clone https://github.com/Perl/perl5.git perl

Dans tous les cas, une fois que vous avez un répertoire 'perl' contenant la source, placez-vous dedans et marquez tout le code comme ASCII :

cd perl
chtag -R -h -t -cISO8859-1 *

Configurez l'environnement de compilation comme 64 bits, dynamique, ASCII, développement, en le déployant dans /usr/local/perl/ascii :

export PATH=$PWD:$PATH
export LIBPATH=$PWD:$PATH
./Configure -Dprefix=/usr/local/perl/ascii -des -Dusedevel \
      -Duse64bitall -Dusedl

Si vous compilez à partir d'une source stable, vous n'avez pas besoin de « -Dusedevel ». (Si vous exécutez Configure sans options, il vous demandera interactivement toutes les options possibles en fonction de son analyse de ce qui est disponible sur votre machine particulière, vous pouvez donc choisir au fur et à mesure.)

Exécutez GNU make pour compiler Perl

make

Exécutez les tests pour vous assurer que Perl fonctionne correctement. Actuellement, il y a une douzaine de tests échoués sur près de 2500.

make test_harness

Installez Perl dans /usr/local/perl/ascii :

make install

Compilation d'un Perl dynamique 64 bits en EBCDIC

Vous aurez besoin d'un perl fonctionnel sur une machine connectée à la machine de destination. Sur z/OS, il pourrait s'agir d'un perl ASCII, ou d'un perl EBCDIC précédent. De nombreuses machines auront déjà un perl pré-compilé en cours d'exécution, ou l'une d'entre elles peut facilement être téléchargée depuis https://www.perl.org/get.html.

Suivez les instructions ci-dessus dans « Compilation d'un Perl dynamique 64 bits en ASCII » jusqu'à obtenir un répertoire 'perl' rempli. Revenez ensuite ici pour continuer.

Le perl téléchargé devra être converti en EBCDIC 1047. Pour ce faire :

cd perl
Porting/makerel -e

Si l'étape Porting/makerel échoue avec une erreur indiquant qu'il ne peut pas exécuter la commande tar, procédez en exécutant la commande interactivement, où V.R.M est la version/édition/modification de Perl que vous téléchargez :

cd ../
tar cf -  --format=ustar perl-V.R.M | gzip --best > perl-V.R.M.tar.gz

Utilisez sftp pour télécharger le fichier tar zippé sur z/OS :

sftp <votre système>
cd /tmp
put perl-V.R.M.tar.gz

Décompressez et extrayez le fichier tar zippé sur z/OS :

cd /tmp
gunzip perl-V.R.M.tar.gz

Puis l'une des commandes suivantes :

tar -xvf perl-V.R.M.tar
pax -r -f perl-V.R.M.tar

Vous avez maintenant le code source du Perl EBCDIC sur z/OS et vous pouvez procéder à sa compilation. C'est analogue à la façon dont vous compileriez le code pour l'ASCII, mais attention : vous ne **devriez pas** taguer le code mais le laisser non tagué.

Configurez l'environnement de compilation comme 64 bits, dynamique, natif, développement, en le déployant dans /usr/local/perl/ebcdic :

export PATH=$PWD:$PATH
export LIBPATH=$PWD:$PATH
./Configure -Dprefix=/usr/local/perl/ebcdic -des -Dusedevel \
      -Duse64bitall -Dusedl

Si vous compilez à partir d'une source stable, vous n'avez pas besoin de « -Dusedevel ». (Si vous exécutez Configure sans options, il vous demandera interactivement toutes les options possibles en fonction de son analyse de ce qui est disponible sur votre machine particulière, vous pouvez donc choisir au fur et à mesure.)

Exécutez GNU make pour compiler Perl

make

Exécutez les tests pour vous assurer que Perl fonctionne correctement.

make test_harness

Vous pourriez également vouloir que GNU groff pour OS/390 soit installé avant d'exécuter l'étape « make install » pour Perl.

Installez Perl dans /usr/local/perl/ebcdic :

make install

Perl EBCDIC est toujours en cours de développement. Tout le code de base fonctionne à notre connaissance, mais divers modules que vous pourriez vouloir télécharger depuis CPAN ne le font pas. Les échecs vont de très mineurs à catastrophiques. Beaucoup d'entre eux sont simplement des bugs dans les tests, le module fonctionnant réellement correctement. Cela se produit parce que, par exemple, le test est codé pour attendre un certain point de code caractère ASCII ; lorsqu'il reçoit la valeur EBCDIC à la place, il se plaint. Mais le code a réellement fonctionné. D'autres échecs potentiels qui ne sont pas vraiment des échecs proviennent de sommes de contrôle différentes, car « A », par exemple, a une représentation binaire différente entre les jeux de caractères. Un test qui attend la valeur ASCII montrera un échec, même si le module fonctionne parfaitement. Aussi dans le tri, les lettres majuscules viennent avant les lettres minuscules sur les systèmes ASCII ; l'inverse sur les systèmes EBCDIC.

Certains modules CPAN sont livrés avec le perl téléchargé. Et quelques-uns d'entre eux n'ont pas encore été corrigés pour fonctionner sur les plateformes EBCDIC. Par conséquent, ils sont ignorés lorsque vous exécutez 'make test'. La liste actuelle est :

Archive::Tar
Config::Perl::V
CPAN::Meta
CPAN::Meta::YAML
Digest::MD5
Digest::SHA
Encode
ExtUtils::MakeMaker
ExtUtils::Manifest
HTTP::Tiny
IO::Compress
IPC::Cmd
JSON::PP
libnet
MIME::Base64
Module::Metadata
PerlIO::via-QuotedPrint
Pod::Checker
podlators
Pod::Simple
Socket
Test::Harness

Voir aussi hints/os390.sh pour d'autres pièges potentiels.

Configuration et utilitaires pour Perl sur OS/390

Ce pourrait également être le bon moment pour vous assurer que votre fichier /etc/protocol et soit votre fichier /etc/resolv.conf, soit votre fichier /etc/hosts sont en place. Le document IBM qui décrit de tels problèmes de configuration système USS est « z/OS UNIX System Services Planning ».

Pour une réussite des tests, vous devrez peut-être activer le sticky bit pour votre répertoire /tmp lisible par tous si vous ne l'avez pas déjà fait (voir man chmod).

Fichiers utiles pour le dépannage

Si votre configuration échoue, lisez hints/os390.sh Ce fichier fournit des options spécifiques à z/OS pour diriger le processus de compilation.

Shell

Un message de la forme :

(Je vois que vous utilisez le Kor
n shell. Certaines versions de ksh peuvent échouer lors de la configuration, principalement sur des systèmes plus anciens et exotiques. Si le vôtre échoue, essayez le shell Bourne à la place.)

n'est rien à craindre du tout.

Chargement dynamique

Le chargement dynamique est nécessaire si vous souhaitez utiliser des modules XS de CPAN (tels que DBI (et ses DBD), JSON::XS, et Text::CSV_XS) ou mettre à jour les modules CORE de CPAN avec des versions plus récentes (telles qu'Encode) sans avoir à recompiler toute la binaire de perl.

Les instructions ci-dessus créeront une Perl dynamique. Si vous ne souhaitez pas utiliser le chargement dynamique, supprimez l'option -Dusedl. Consultez les commentaires dans hints/os390.sh pour plus d'informations sur le chargement dynamique.

Optimisation

L'optimisation n'a pas encore été activée. Il peut y avoir des problèmes si Perl est optimisé.

Anomalies de construction avec Perl sur OS/390

"Out of memory!" (Mémoire insuffisante !) les messages pendant la construction de Perl sont le plus souvent corrigés en reconstruisant l'utilitaire GNU make pour OS/390 à partir d'un kit de code source.

Dans USS, votre fichier /etc/profile ou $HOME/.profile peut limiter vos paramètres ulimit. Vérifiez que la commande suivante renvoie des valeurs raisonnables :

ulimit -a

Pour économiser de la mémoire, vos modules compilateur devraient être chargés dans la zone de liaison (LPA/ELPA) plutôt que dans une liste de liaison ou une bibliothèque d'étape.

Si le compilateur se plaint d'erreurs de syntaxe pendant la construction de l'extension Socket, assurez-vous de corriger l'erreur de syntaxe dans l'en-tête système /usr/include/sys/socket.h.

Anomalies de test avec Perl sur OS/390

L'étape "make test" exécute une procédure de vérification de Perl, généralement avant l'installation. Vous pourriez rencontrer des messages STDERR même lors d'une exécution réussie de "make test". Voici un guide pour certaines des anomalies les plus courantes :

Mémoire insuffisante (31 bits uniquement)

Les problèmes de mémoire insuffisante ne devraient pas être un problème, sauf si vous tentez de construire une Perl 31 bits.

Si vous _êtes_ en train de construire une Perl 31 bits, l'environnement contraint peut signifier que vous devez modifier les options de mémoire pour Perl. En plus des commentaires ci-dessus sur les limitations de mémoire, il est également utile de vérifier la variable d'environnement _CEE_RUNOPTS. Perl possède maintenant (dans miniperlmain.c) un #pragma C spécifique pour le 31 bits afin de définir les options d'exécution CEE, mais la variable d'environnement l'emporte.

Le code C 31 bits demande :

#pragma runopts(HEAP(2M,500K,ANYWHERE,KEEP,8K,4K) STACK(,,ANY,) ALL31(ON))

Les parties importantes de cela sont le deuxième argument (l'incrément) à HEAP, et l'autorisation de la pile à être "Au-dessus de la ligne (16M)". Si l'incrément du tas est trop petit, lorsque perl (par exemple en chargeant unicode/Name.pl) essaie de créer une chaîne "grande" (400K+) elle ne peut pas tenir dans un seul segment et vous obtenez "Out of Memory!" - même s'il reste encore beaucoup de mémoire disponible.

Un problème connexe est l'utilisation du malloc de perl. Le malloc de Perl utilise sbrk() pour obtenir de la mémoire, et sbrk() est limité à la première allocation, donc dans ce cas, quelque chose comme :

HEAP(8M,500K,ANYWHERE,KEEP,8K,4K)

est nécessaire pour passer la suite de tests.

Conseils d'utilisation de Perl sur z/OS

Lorsque vous utilisez Perl sur z/OS, gardez à l'esprit que les jeux de caractères EBCDIC et ASCII sont différents. Voir perlebcdic pour plus d'informations sur ces problèmes de jeux de caractères. Les fonctions intégrées de Perl qui peuvent se comporter différemment sous EBCDIC sont également mentionnées dans le document perlport.pod.

Si vous rencontrez des problèmes avec les crochets, envisagez de changer de client rlogin ou telnet. Essayez d'éviter les anciens émulateurs 3270 et ISHELL pour travailler avec Perl sur USS.

Modules et extensions pour Perl sur z/OS (statique uniquement)

Les modules Pure Perl (c'est-à-dire non XS) peuvent être installés via la méthode habituelle :

perl Makefile.PL
make
make test
make install

Si vous avez construit perl avec la capacité de chargement dynamique, ce serait également la façon de construire des extensions basées sur XS. Cependant, si vous avez construit perl avec une liaison statique, vous pouvez toujours construire des extensions basées sur XS pour z/OS, mais vous devrez suivre les instructions de ExtUtils::MakeMaker pour construire des binaires perl liés statiquement. Dans les configurations les plus simples, la construction d'une perl statique + extension XS se résume à :

perl Makefile.PL
make
make perl
make test
make install
make -f Makefile.aperl inst_perl MAP_TARGET=perl

Exécution de Perl sur z/OS

Pour exécuter l'environnement Perl dynamique 64 bits, mettez à jour votre PATH et LIBPATH pour inclure l'emplacement où vous avez installé Perl, puis exécutez la perl que vous avez installée sous le nom perlV.R.M où V/R/M est le niveau Version/Release/Modification du niveau de développement actuel. Si vous exécutez l'environnement Perl Bi-Modal ASCII/EBCDIC, vous devez également configurer vos variables d'environnement Bi-Modales ASCII/EBCDIC, et vous assurer que tout code source Perl que vous exécutez est correctement étiqueté comme ASCII ou EBCDIC en utilisant "chtag -t -c<CCSID>" :

Pour ASCII uniquement :
export _BPXK_AUTOCVT=ON
export _CEE_RUNOPTS="FILETAG(AUTOCVT,AUTOTAG),POSIX(ON)"
export _TAG_REDIR_ERR="txt"
export _TAG_REDIR_IN="txt"
export _TAG_REDIR_OUT="txt"
Pour ASCII ou EBCDIC :
export PATH=/usr/local/perl/ascii:$PATH
export LIBPATH=/usr/local/perl/ascii/lib:$LIBPATH
perlV.R.M arguments

Si tcsh est votre shell de connexion, utilisez la commande setenv.
