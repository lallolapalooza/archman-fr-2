NOM

perf-inject - Filtre pour enrichir le flux d'événements avec des informations supplémentaires

SYNOPSIS

perf inject <options>

DESCRIPTION

perf-inject lit un flux d'événements de perf-record et le redirige vers la sortie standard. À tout moment, le code de traitement peut injecter d'autres événements dans le flux d'événements - dans ce cas, les build-ids (option -b) sont lus et injectés si nécessaire dans le flux d'événements.

Les build-ids ne sont que la première utilisation de perf-inject - potentiellement, tout ce qui nécessite un traitement en espace utilisateur pour enrichir le flux d'événements avec des informations supplémentaires pourrait utiliser cette installation.

OPTIONS

-b, --build-ids

Injecte les build-ids des DSO touchés par les échantillons dans le flux de sortie. Cela signifie qu'il doit traiter tous les enregistrements SAMPLE pour trouver les DSO.

--buildid-all

Injecte les build-ids de tous les DSO dans le flux de sortie, quels que soient les hits, et ignore le traitement des SAMPLE.

--known-build-ids=

Remplace les build-ids à injecter en utilisant ces paires build-id et chemin séparées par des virgules. Comprend file://filename pour lire ces paires à partir d'un fichier, qui peut être généré avec perf buildid-list.

-v, --verbose

Être plus verbeux.

-i, --input=

Nom du fichier d'entrée. (par défaut : stdin)

-o, --output=

Nom du fichier de sortie. (par défaut : stdout)

-s, --sched-stat

Fusionne sched_stat et sched_switch pour obtenir les événements où et combien de temps les tâches ont dormi. sched_switch contient une chaîne d'appel où une tâche a dormi et sched_stat contient une tranche de temps sur la durée pendant laquelle une tâche a dormi.

-k, --vmlinux=<fichier>

Chemin du vmlinux

--ignore-vmlinux

Ignore les fichiers vmlinux.

--kallsyms=<fichier>

Chemin du kallsyms

--itrace

Décode les données de traçage d'instructions, en les remplaçant par des événements synthétisés. Les options sont : 
i       synthétise les événements d'instructions
y       synthétise les événements de cycles
b       synthétise les événements de branchements
c       synthétise les événements de branchements (appels uniquement)
r       synthétise les événements de branchements (retours uniquement)
x       synthétise les événements de transactions
w       synthétise les événements ptwrite
p       synthétise les événements d'alimentation (y compris les événements PSB pour Intel PT)
o       synthétise d'autres événements enregistrés en raison de l'utilisation
        de la sortie AUX (voir perf record)
I       synthétise les événements d'interruption ou similaires (asynchrones)
        (par exemple, Intel PT Event Trace)
e       synthétise les événements d'erreur
d       crée un journal de débogage
f       synthétise les événements de cache de premier niveau
m       synthétise les événements de cache de dernier niveau
M       synthétise les événements de mémoire
t       synthétise les événements TLB
a       synthétise les événements d'accès distant
g       synthétise une chaîne d'appels (à utiliser avec i ou x)
G       synthétise une chaîne d'appels sur les enregistrements d'événements existants
l       synthétise les dernières entrées de branchement (à utiliser avec i ou x)
L       synthétise les dernières entrées de branchement sur les enregistrements d'événements existants
s       saute le nombre initial d'événements
q       décodage plus rapide (moins détaillé)
A       IPC approximatif
Z       préfère ignorer les horodatages (décodage dit "sans horodatage")
T       utilise le tracé d'horodatage comme temps noyau
La valeur par défaut est tous les événements, c'est-à-dire la même chose que --itrace=iybxwpe,
sauf pour perf script où c'est --itrace=ce
De plus, la période (par défaut 100000, sauf pour perf script où c'est 1)
pour les événements d'instructions peut être spécifiée en unités de :
i       instructions
t       ticks
ms      millisecondes
us      microsecondes
ns      nanosecondes (par défaut)
De même, la taille de la chaîne d'appels (par défaut 16, max. 1024) pour les événements
d'instructions ou de transactions peut être spécifiée.
De même, le nombre de dernières entrées de branchement (par défaut 64, max. 1024) pour
les événements d'instructions ou de transactions peut être spécifié.
Similairement aux options g et l, la taille peut aussi être spécifiée pour les options G et L.
Sur x86, notez que G et L fonctionnent mal lorsque les données ont été enregistrées avec
PEBS volumineux. Voir la page man linkperf:perf-intel-pt[1] pour plus de détails.
Il est également possible de sauter les événements générés (instructions, branchements, transactions,
ptwrite, alimentation) au début. Ceci est utile pour ignorer le code d'initialisation.
--itrace=i0nss1000000
saute les un million premières instructions.
L'option 'e' peut être suivie de drapeaux qui affectent quels erreurs seront ou ne seront pas signalés. Chaque drapeau doit être précédé de '+' ou '-'.
Les drapeaux sont :
        o       dépassement
        l       perte de données tracées
Si supporté, l'option 'd' peut être suivie de drapeaux qui affectent quels
messages de débogage seront ou ne seront pas enregistrés. Chaque drapeau doit être précédé
de '+' ou '-'. Les drapeaux sont :
        a       tous les événements perf
        e       sortie uniquement en cas d'erreurs (taille configurable - voir linkperf:perf-config[1])
        o       sortie vers stdout
Si supporté, l'option 'q' peut être répétée pour augmenter l'effet.

--strip

À utiliser avec --itrace pour supprimer les événements non synthétisés.

-j, --jit

Traite les fichiers jitdump en injectant les enregistrements mmap correspondant aux fonctions jitted. Cette option génère également les images ELF pour chaque fonction jitted trouvée dans les fichiers jitdumps capturés dans le fichier perf.data d'entrée. Utilisez cette option si vous surveillez un environnement utilisant des runtimes JIT, tels que Java, DART ou V8.

-f, --force

Ne pas se plaindre, le faire.

--vm-time-correlation[=OPTIONS]

Certaines architectures peuvent capturer des données de zone AUX qui contiennent des horodatages affectés par la virtualisation. Cette option mettra à jour ces horodatages sur place, pour les corréler avec les horodatages de l'hôte. La mise à jour sur place signifie qu'aucun fichier de sortie n'est spécifié, et que le fichier d'entrée est modifié. Les options sont spécifiques à l'architecture, sauf qu'elles peuvent commencer par "dry-run", ce qui entraînera le traitement du fichier sans le mettre à jour. Actuellement, cette option n'est prise en charge que par Intel PT, voir perf-intel-pt(1)

--guest-data=<chemin>,<pid>[,<décalage temporel>[,<échelle temporelle>]]

Insère des événements à partir d'un fichier perf.data enregistré dans une machine virtuelle au même moment où le fichier perf.data d'entrée a été enregistré sur l'hôte. Le PID (Process ID) du processus hyperviseur QEMU doit être fourni, et le décalage temporel et l'échelle temporelle (multiplicateur) seront probablement nécessaires pour convertir les horodatages invités en horodatages hôtes. Par exemple, pour x86, le décalage et le multiplicateur TSC peuvent être fournis pour une machine virtuelle utilisant l'option de ligne de commande noyau no-kvmclock. Actuellement, seuls les événements mmap, mmap2, comm, task, context_switch, ksymbol et text_poke sont insérés, ainsi que les informations de build ID. L'option QEMU -name debug-threads=on est nécessaire pour que les noms de threads puissent être utilisés pour déterminer quel thread exécute quel VCPU. Notez que libvirt semble l'utiliser par défaut. Lors de l'utilisation de perf record dans l'invité, l'option --sample-identifier doit être utilisée, et les options --buildid-all et --switch-events peuvent également être utiles.

--guestmount=<chemin>

Répertoire de montage du système de fichiers racine du système d'exploitation invité. Les utilisateurs montent les répertoires racine des systèmes d'exploitation invités sous <chemin> par une méthode d'accès spécifique au système de fichiers, typiquement sshfs. Par exemple, lancez 2 invités, dont le pid est 8888 et l'autre 9999 : 
$ mkdir ~/guestmount
$ cd ~/guestmount
$ sshfs -o allow_other,direct_io -p 5551 localhost:/ 8888/
$ sshfs -o allow_other,direct_io -p 5552 localhost:/ 9999/
$ perf inject --guestmount=~/guestmount
