NOM

perl5184delta - Nouveautés pour la version perl v5.18.4

DESCRIPTION

Ce document décrit les différences entre la version 5.18.4 et la version 5.18.2. Note : ce document ignore perl 5.18.3, une version corrompue qui n'a existé que quelques heures.

Si vous mettez à jour depuis une version antérieure comme la 5.18.1, lisez d'abord perl5182delta, qui décrit les différences entre 5.18.1 et 5.18.2.

Modules et Pragmata

Modules et Pragmata mis à jour

  • Digest::SHA a été mis à jour de la version 5.84_01 à la version 5.84_02.
  • perl5db.pl a été mis à jour de la version 1.39_10 à la version 1.39_11.

    Cela corrige un crash dans la complétion par tabulation, là où elle est disponible. [perl #120827] De plus, les descripteurs de fichier sont correctement réinitialisés après l'exécution d'un pager. [perl #121456]

Support des plateformes

Notes spécifiques à la plateforme

Win32
•
Introduit par [GH #12161] https://github.com/Perl/perl5/issues/12161, une fuite de mémoire à chaque appel de "system" et des backticks ( `` ), sur la plupart des Perl Win32 à partir de la version 5.18.0, a été corrigée. La fuite de mémoire ne se produisait que si vous activiez le pseudo-fork dans votre compilation de Perl Win32, et exécutiez cette compilation sur Server 2003 R2 ou un OS plus récent. La fuite n'apparaît pas sur WinXP SP3. [GH #13741] https://github.com/Perl/perl5/issues/13741

Corrections de bugs sélectionnées

  • Le débogueur réinitialise maintenant correctement les descripteurs de fichier si nécessaire. [perl #121456]
  • Un segfault dans Digest::SHA a été corrigé. [perl #121421]
  • Il est à nouveau possible de compiler Perl avec USE_64_BIT_INT, avec Visual C 2003, 32 bits. [perl #120925]
  • Un { (accolade) en tête dans les formats est à nouveau correctement analysé. [perl #119973]
  • Copie des valeurs utilisées pour perturber l'itération du hachage lors du clonage d'un interpréteur. C'était relativement inoffensif mais provoquait des plaintes de "valgrind". [perl #121336]
  • Dans Perl v5.18, "undef *_; goto &sub" et "local *_; goto &sub" commençaient à planter. Ceci a été corrigé. [perl #119949]

Remerciements

Perl 5.18.4 représente environ 9 mois de développement depuis Perl 5.18.2 et contient environ 2 000 lignes de changements sur 53 fichiers de 13 auteurs.

Perl continue de prospérer dans sa troisième décennie grâce à une communauté dynamique d'utilisateurs et de développeurs. Les personnes suivantes sont connues pour avoir contribué aux améliorations de Perl 5.18.4 :

Beaucoup des changements inclus dans cette version proviennent des modules CPAN inclus dans le cœur de Perl. Nous sommes reconnaissants envers l'ensemble de la communauté CPAN pour avoir aidé Perl à prospérer.

Pour une liste plus complète de tous les contributeurs historiques de Perl, veuillez consulter le fichier AUTHORS dans la distribution source de Perl.

Signalement de bugs

Si vous trouvez ce qui vous semble être un bug, vous pourriez consulter les articles récemment postés sur le groupe de nouvelles comp.lang.perl.misc et la base de données des bugs de Perl sur http://rt.perl.org/perlbug/. Vous pourriez également trouver des informations sur http://www.perl.org/, la page d'accueil de Perl.

Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bug à un cas de test minimal mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl.

Si le bug que vous signalez a des implications de sécurité, le rendant inapproprié pour être envoyé à une liste de diffusion archivée publiquement, veuillez l'envoyer à perl5-security-report@perl.org. Ceci pointe vers une liste de diffusion à abonnement fermé et non archivée, qui inclut tous les committers du cœur, capables d'évaluer l'impact des problèmes, de trouver une solution et d'aider à coordonner la publication de correctifs pour atténuer ou corriger le problème sur toutes les plateformes supportées par Perl. N'utilisez cette adresse que pour les problèmes de sécurité dans le cœur de Perl, pas pour les modules distribués indépendamment sur CPAN.
