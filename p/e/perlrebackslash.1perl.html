PERLREBACKSLASH(1perl) Guide de référence du programmeur Perl PERLREBACKSLASH(1perl)

NOM

perlrebackslash - Séquences d'échappement et de contre-obliques des expressions régulières Perl

DESCRIPTION

La documentation de niveau supérieur sur les expressions régulières Perl se trouve dans perlre.

Ce document décrit toutes les séquences de contre-oblique et d'échappement. Après avoir expliqué le rôle de la contre-oblique, il liste toutes les séquences qui ont une signification spéciale dans les expressions régulières Perl (par ordre alphabétique), puis décrit chacune d'entre elles.

La plupart des séquences sont décrites en détail dans différents documents ; l'objectif principal de ce document est d'avoir un guide de référence rapide décrivant toutes les séquences de contre-oblique et d'échappement.

La contre-oblique

Dans une expression régulière, la contre-oblique peut accomplir l'une des deux tâches : soit elle retire la signification spéciale du caractère qui la suit (par exemple, "\|" correspond à une barre verticale, ce n'est pas une alternance), soit elle est le début d'une séquence de contre-oblique ou d'échappement.

Les règles déterminant ce qu'il en est sont assez simples : si le caractère suivant la contre-oblique est un caractère de ponctuation ASCII (caractère non-mot) (c'est-à-dire tout ce qui n'est pas une lettre, un chiffre ou un underscore), alors la contre-oblique retire simplement toute signification spéciale au caractère qui la suit.

Si le caractère suivant la contre-oblique est une lettre ou un chiffre ASCII, alors la séquence peut être spéciale ; si c'est le cas, elle est listée ci-dessous. Quelques lettres n'ont pas encore été utilisées, donc les échapper avec une contre-oblique ne les rend pas spéciales. Une future version de Perl pourrait leur assigner une signification spéciale, donc si vous avez les avertissements activés, Perl émet un avertissement si vous utilisez une telle séquence. [1].

Il est cependant garanti que les séquences de contre-oblique ou d'échappement n'ont jamais de caractère de ponctuation suivant la contre-oblique, ni maintenant, ni dans une future version de Perl 5. Il est donc sûr de mettre une contre-oblique devant un caractère non-mot.

Notez que la contre-oblique elle-même est spéciale ; si vous voulez faire correspondre une contre-oblique, vous devez échapper la contre-oblique avec une contre-oblique : "/\\/" correspond à une seule contre-oblique.

[1]
Il y a une exception. Si vous utilisez un caractère alphanumérique comme délimiteur de votre motif (ce que vous ne devriez probablement pas faire pour des raisons de lisibilité), vous devez échapper le délimiteur si vous voulez qu'il corresponde. Perl ne vous avertira pas alors. Voir aussi "Détails macabres de l'analyse des constructions entre guillemets" dans perlop.

Échappements de caractères

Caractères fixes

Une poignée de caractères ont un échappement de caractère dédié. Le tableau suivant les montre, ainsi que leurs points de code ASCII (en décimal et hexadécimal), leur nom ASCII, l'échappement de contrôle sur les plateformes ASCII et une courte description. (Pour les plateformes EBCDIC, voir "DIFFÉRENCES OPÉRATEUR" dans perlebcdic.)

Seq.  Point de Code  ASCII   Cntrl   Description.
      Déc    Hex
 \a     7     07    BEL    \cG    alarme ou sonnerie
 \b     8     08     BS    \cH    retour arrière [1]
 \e    27     1B    ESC    \c[    caractère d'échappement
 \f    12     0C     FF    \cL    saut de page
 \n    10     0A     LF    \cJ    saut de ligne [2]
 \r    13     0D     CR    \cM    retour chariot
 \t     9     09    TAB    \cI    tabulation
[1]
"\b" est le caractère de retour arrière uniquement à l'intérieur d'une classe de caractères. En dehors d'une classe de caractères, "\b" seul est une frontière caractère-mot/non-mot, et "\b{}" est un autre type de frontière.
[2]
"\n" correspond à une nouvelle ligne logique. Perl convertit entre "\n" et le caractère de nouvelle ligne natif de votre système d'exploitation lors de la lecture ou de l'écriture de fichiers texte.

Exemple

$str =~ /\t/;   # Correspond si $str contient une tabulation (horizontale).

Caractères de contrôle

"\c" est utilisé pour désigner un caractère de contrôle ; le caractère suivant "\c" détermine la valeur de la construction. Par exemple, la valeur de "\cA" est chr(1), et la valeur de "\cb" est chr(2), etc. Les détails macabres se trouvent dans "Opérateurs de type Quote pour expressions régulières" dans perlop. Une liste complète de ce que chr(1), etc. signifie pour les plateformes ASCII et EBCDIC se trouve dans "DIFFÉRENCES OPÉRATEUR" dans perlebcdic.

Notez que "\c\" seul à la fin d'une expression régulière (ou d'une chaîne entre guillemets doubles) n'est pas valide. La contre-oblique doit être suivie d'un autre caractère. C'est-à-dire que "\c\X" signifie "chr(28) . 'X'" pour tous les caractères X.

Pour écrire du code indépendant de la plateforme, vous devez utiliser "\N{NOM}" à la place, comme "\N{ESCAPE}" ou "\N{U+001B}", voir charnames.

Mnémonique : caractère de contrôle.

Exemple

$str =~ /\cK/;  # Correspond si $str contient une tabulation verticale (contrôle-K).

Caractères et séquences de caractères nommés ou numérotés

Les caractères Unicode ont un nom Unicode et une valeur de point de code (ordinale) numérique. Utilisez la construction "\N{}" pour spécifier un caractère par l'une de ces valeurs. Certaines séquences de caractères ont également des noms.

Pour spécifier par nom, le nom du caractère ou de la séquence de caractères va entre les accolades.

Pour spécifier un caractère par son point de code Unicode, utilisez la forme "\N{U+code point}", où code point est un nombre hexadécimal qui donne le point de code que Unicode a attribué au caractère souhaité.

r. Il est d'usage, mais pas obligatoire, d'utiliser des zéros initiaux pour compléter le nombre à 4 chiffres. Ainsi, "\N{U+0041}" signifie "LATIN CAPITAL LETTER A", et vous le verrez rarement écrit sans les deux zéros initiaux. "\N{U+0041}" signifie "A" même sur les machines EBCDIC (où la valeur ordinale de "A" n'est pas 0x41).

Les espaces peuvent être librement insérés adjacents aux accolades mais à l'intérieur de celles-ci qui entourent le nom ou le point de code. Ainsi, "\N{ U+0041 }" est parfaitement légal.

Il est même possible de donner vos propres noms à des caractères et des séquences de caractères en utilisant le module charnames. Ces noms personnalisés sont délimités lexicalement, et ainsi un point de code donné peut avoir des noms différents dans des portées différentes. Le nom utilisé est celui qui est en vigueur au moment où le "\N{}" est développé. Pour les motifs dans un contexte à guillemets doubles, cela signifie au moment où le motif est analysé. Mais pour les motifs délimités par des apostrophes, le développement est différé jusqu'au moment de la compilation du motif, qui peut très bien avoir un traducteur "charnames" différent en vigueur.

(Il existe une forme interne développée que vous pourriez voir dans la sortie de débogage : "\N{U+point de code.point de code...}". Le "..." signifie n'importe quel nombre de ces points de code séparés par des points. Ceci représente la séquence formée par les caractères. Ceci est une forme interne uniquement, sujette à modification, et vous ne devriez pas essayer de l'utiliser vous-même.)

Mnémonique : caractère Nommé.

Notez qu'un caractère ou une séquence de caractères exprimée comme un caractère nommé ou numéroté est considérée comme un caractère sans signification spéciale par le moteur regex, et correspondra "tel quel".

Exemple

$str =~ /\N{THAI CHARACTER SO SO}/;  # Correspond au caractère thaïlandais SO SO
use charnames 'Cyrillic';            # Charge les noms cyrilliques.
$str =~ /\N{ZHE}\N{KA}/;             # Correspond à "ZHE" suivi de "KA".

Échappements octaux

Il existe deux formes d'échappements octaux. Chacune est utilisée pour spécifier un caractère par son point de code spécifié en base 8.

Une forme, disponible à partir de Perl 5.14, ressemble à "\o{...}", où les points représentent un ou plusieurs chiffres octaux. Elle peut être utilisée pour n'importe quel caractère Unicode.

Elle a été introduite pour éviter les problèmes potentiels avec l'autre forme, disponible dans tous les Perls. Cette forme consiste en une barre oblique inverse suivie de trois chiffres octaux. Un problème avec cette forme est qu'elle peut ressembler exactement à une référence arrière de style ancien (voir "Règles de désambiguïsation entre les échappements octaux de style ancien et les références arrière" ci-dessous.) Vous pouvez l'éviter en faisant en sorte que le premier des trois chiffres soit toujours un zéro, mais cela limite le plus grand point de code spécifiable à \077.

Dans certains contextes, une barre oblique inverse suivie de deux ou même un chiffre octal peut être interprétée comme un échappement octal, parfois avec un avertissement, et en raison de certains bugs, parfois avec des résultats surprenants. De plus, si vous créez une regex à partir de petits extraits concaténés, et que vous utilisez moins de trois chiffres, le début d'un extrait peut être interprété comme l'ajout de chiffres à la fin de l'extrait qui le précède. Voir "Référencement absolu" pour plus de discussions et d'exemples du problème des extraits.

Notez qu'un caractère exprimé comme un échappement octal est considéré comme un caractère sans signification spéciale par le moteur regex, et correspondra "tel quel".

Pour résumer, la forme "\o{}" est toujours sûre à utiliser, et l'autre forme est sûre à utiliser pour les points de code jusqu'à \077 (c'est-à-dire 63 en décimal) lorsque vous utilisez exactement trois chiffres pour les spécifier.

Mnémonique : 0ctale ou octale.

Exemples (en supposant une plateforme ASCII)

$str = "Perl";
$str =~ /\o{120}/;  # Correspond, "\120" est "P".
$str =~ /\120/;     # Idem.
$str =~ /\o{120}+/; # Correspond, "\120" est "P",
                    # il est répété au moins une fois.
$str =~ /\120+/;    # Idem.
$str =~ /P\053/;    # Pas de correspondance, "\053" est "+" et est pris littéralement.
/\o{23073}/         # Visage souriant noir sur fond blanc.
/\o{4801234567}/    # Génère un avertissement, et renvoie chr(4).
/\o{ 400}/          # LETTRE CAPITALE LATINE A AVEC MACRON
/\o{ 400 }/         # Idem. Ceci montre que les espaces sont autorisés à proximité
                    # des accolades

Règles de désambiguïsation entre les échappements octaux de style ancien et les références arrière

Les échappements octaux de la forme "\000" en dehors des classes de caractères entre crochets peuvent entrer en conflit avec les références arrière de style ancien (voir "Référencement absolu" ci-dessous). Les deux consistent en une barre oblique inverse suivie de chiffres. Ainsi, Perl doit utiliser des heuristiques pour déterminer s'il s'agit d'une référence arrière ou d'un échappement octal. Perl utilise les règles suivantes pour désambiguïser :

1.
Si la barre oblique inverse est suivie d'un seul chiffre, il s'agit d'une référence arrière.
2.
Si le premier chiffre suivant la barre oblique inverse est un 0, il s'agit d'un échappement octal.
3.
Si le nombre suivant la barre oblique inverse est N (en décimal), et que Perl a déjà vu N groupes de capture, Perl considère cela comme une référence arrière. Sinon, il le considère comme un échappement octal. Si N a plus de trois chiffres, Perl ne prend que les trois premiers pour l'échappement octal ; le reste est mis en correspondance tel quel. 
my $pat  = "(" x 999;
   $pat .= "a";
   $pat .= ")" x 999;
/^($pat)\1000$/;   # Correspond à 'aa' ; il y a 1000 groupes de capture.
/^$pat\1000$/;     # Correspond à 'a@0' ; il y a 999 groupes de capture
                   # et \1000 est vu comme \100 (un '@') et un '0'.

Vous pouvez forcer une interprétation de référence arrière à tout moment en utilisant la forme "\g{...}". Vous pouvez forcer une interprétation octale à tout moment en utilisant la forme "\o{...}", ou pour les nombres jusqu'à \077 (= 63 décimal), en utilisant trois chiffres, commençant par un "0".

Échappements hexadécimaux

Comme les échappements octaux, il existe deux formes d'échappements hexadécimaux, mais les deux commencent par la séquence "\x". Celle-ci est suivie soit de exactement deux chiffres hexadécimaux formant un nombre, soit d'un nombre hexadécimal de longueur arbitraire entouré d'accolades. Le nombre hexadécimal est le point de code du caractère que vous voulez exprimer.

Notez qu'un caractère exprimé comme l'une de ces échappements est considéré comme un caractère sans signification spéciale par le moteur regex, et correspondra "tel quel".

Mnémonique : hexadécimal.

Exemples (en supposant une plateforme ASCII)

$str = "Perl";
$str =~ /\x50/;    # Correspond, "\x50" est "P".
$str =~ /\x50+/;   # Correspond, "\x50" est "P", il est répété au moins une fois
$str =~ /P\x2B/;   # Pas de correspondance, "\x2B" est "+" et est pris littéralement.
/\x{2603}\x{2602}/ # Bonhomme de neige avec parapluie.
                   # Le caractère Unicode 2603 est un bonhomme de neige,
                   # le caractère Unicode 2602 est un parapluie.
/\x{263B}/         # Visage souriant noir.
/\x{263b}/         # Idem, les chiffres hexadécimaux A à F sont insensible à la casse.
/\x{ 263b }/       # Idem, montrant des espaces optionnels adjacents aux
                   # accolades

Modificateurs

Un certain nombre de séquences de barres obliques inverses ont trait à la modification du ou des caractères qui les suivent. "\l" mettra en minuscule le caractère qui suit, tandis que "\u" le mettra en majuscule (ou, plus précisément, en casse de titre) le caractère qui suit. Ils fournissent des fonctionnalités similaires aux fonctions "lcfirst" et "ucfirst".

Pour mettre en majuscule ou en minuscule plusieurs caractères, on peut vouloir utiliser "\L" ou "\U", qui mettront en minuscule/majuscule tous les caractères qui les suivent, jusqu'à la fin du motif ou la prochaine occurrence de "\E", selon ce qui vient en premier. Ils fournissent des fonctionnalités similaires à ce que fournissent les fonctions "lc" et "uc".

"\Q" est utilisé pour échapper ou mettre en citation (désactiver) les métacaractères de motif, jusqu'à la prochaine occurrence de "\E" ou la fin du motif. "\Q" ajoute une barre oblique inverse à tout caractère qui pourrait avoir une signification spéciale pour Perl. Dans la plage ASCII, il échappe tous les caractères qui ne sont pas des lettres, des chiffres ou des underscores. Voir "quotemeta" dans perlfunc pour plus de détails sur ce qui est échappé pour les points de code non-ASCII. L'utilisation de cela garantit que tout caractère entre "\Q" et "\E" sera mis en correspondance littéralement, et non interprété comme un métacaractère par le moteur regex.

"\F" peut être utilisé pour normaliser la casse de tous les caractères suivants, jusqu'à la prochaine occurrence de "\E" ou la fin du motif. Il fournit une fonctionnalité similaire à celle de la fonction "fc".

Mnémonique : Lowercase (minuscule), Uppercase (majuscule), Fold-case (normalisation de casse), Quotemeta (échappement), End (fin).

Exemples

$sid     = "sid";
$greg    = "GrEg";
$miranda = "(Miranda)";
$str     =~ /\u$sid/;        # Correspond à 'Sid'
$str     =~ /\L$greg/;       # Correspond à 'greg'
$str     =~ /\Q$miranda\E/;  # Correspond à '(Miranda)', comme si le motif
                             #   avait été écrit comme /\(Miranda\)/

Classes de caractères

Les expressions régulières Perl ont une large gamme de classes de caractères. Certaines des classes de caractères sont écrites comme une séquence de barre oblique inverse. Nous en discuterons brièvement ici ; les détails complets des classes de caractères se trouvent dans perlrecharclass.

"\w" est une classe de caractères qui correspond à n'importe quel caractère de mot simple (lettres, chiffres, marques Unicode et ponctuation de connexion (comme le trait de soulignement)). "\d" est une classe de caractères qui correspond à n'importe quel chiffre décimal, tandis que la classe de caractères "\s" correspond à n'importe quel caractère d'espacement. Introduits dans perl 5.10.0 sont les classes "\h" et "\v" qui correspondent aux caractères d'espacement horizontaux et verticaux.

L'ensemble exact de caractères correspondant à "\d", "\s", et "\w"

Classes de caractères

La correspondance de certaines séquences d'échappement de classe de caractères dépend de divers pragma et modificateurs d'expressions régulières. Il est possible de restreindre la correspondance à la plage ASCII en utilisant le modificateur d'expression régulière "/a". Voir perlrecharclass.

Les variantes majuscules ("\W", "\D", "\S", "\H", et "\V") sont des classes de caractères qui correspondent respectivement à tout caractère qui n'est pas un caractère de mot, un chiffre, un espace blanc, un espace blanc horizontal ou un espace blanc vertical.

Mnémoniques : *w*ord (mot), *d*igit (chiffre), *s*pace (espace), *h*orizontal (horizontal), *v*ertical (vertical).

Classes Unicode

"\pP" (où "P" est une seule lettre) et "\p{Propriété}" sont utilisés pour faire correspondre un caractère qui correspond à la propriété Unicode donnée ; les propriétés incluent des choses comme « lettre » ou « caractère thaï ». Mettre la séquence en majuscule, "\PP" et "\P{Propriété}", permet à la séquence de faire correspondre un caractère qui ne correspond pas à la propriété Unicode donnée. Pour plus de détails, voir « Séquences d'échappement » dans perlrecharclass et « Propriétés des caractères Unicode » dans perlunicode.

Mnémonique : *p*ropriété.

Référencement

Si des parenthèses capturantes sont utilisées dans une expression régulière, nous pouvons faire référence à la partie de la chaîne source qui a été mise en correspondance, et faire correspondre exactement la même chose. Il existe trois façons de faire référence à une telle *backreference* : absolument, relativement et par nom.

Référencement absolu

Soit "\gN" (à partir de Perl 5.10.0), soit "\N" (ancien style), où *N* est un nombre décimal positif (non signé) de n'importe quelle longueur, est une référence absolue à un groupe capturant.

*N* fait référence au Nième jeu de parenthèses, donc "\gN" fait référence à tout ce qui a été mis en correspondance par ce jeu de parenthèses. Ainsi, "\g1" fait référence au premier groupe de capture de l'expression régulière.

La forme "\gN" peut être écrite de manière équivalente comme "\g{N}", ce qui évite l'ambiguïté lors de la construction d'une expression régulière par concaténation de chaînes plus courtes. Sinon, si vous aviez une expression régulière "qr/$x$y/", et que $x contenait "\g1" et $y contenait "37", vous obtiendriez "/\g137/", ce qui n'est probablement pas ce que vous aviez l'intention.

Dans la forme "\N", *N* ne doit pas commencer par un « 0 », et il doit y avoir au moins *N* groupes capturants, sinon *N* est considéré comme une séquence d'échappement octale (mais quelque chose comme "\18" est identique à "\0018" ; c'est-à-dire la séquence d'échappement octale "\001" suivie d'un chiffre littéral "8").

Mnémonique : *g*roupe.

Exemples

/(\w+) \g1/;    # Trouve un mot dupliqué (par exemple, "chat chat").
/(\w+) \1/;     # La même chose ; écrit à l'ancienne.
/(\w+) \g{1}/;  # La même chose, en utilisant la notation entre accolades plus sûre.
/(\w+) \g{ 1 }/;# La même chose, montrant les blancs optionnels adjacents aux accolades.
/(.)(.)\g2\g1/; # Met en correspondance un palindrome de quatre lettres (par exemple, "ABBA").

Référencement relatif

"\g-N" (à partir de Perl 5.10.0) est utilisé pour l'adressage relatif. (Il peut être écrit comme "\g{-N}".) Il fait référence au Nième groupe avant le "\g{-N}".

Le grand avantage de cette forme est qu'elle facilite grandement l'écriture de motifs avec des références qui peuvent être interpolées dans des motifs plus grands, même si le motif plus grand contient également des groupes de capture.

Exemples

/(A)        # Groupe 1
 (          # Groupe 2
   (B)      # Groupe 3
   \g{-1}   # Fait référence au groupe 3 (B)
   \g{-3}   # Fait référence au groupe 1 (A)
   \g{ -3 } # La même chose, montrant les blancs optionnels adjacents aux accolades
 )
/x;         # Correspond à "ABBA".
my $qr = qr /(.)(.)\g{-2}\g{-1}/;  # Correspond à 'abab', 'cdcd', etc.
/$qr$qr/                           # Correspond à 'ababcdcd'.

Référencement par nom

"\g{nom}" (à partir de Perl 5.10.0) peut être utilisé pour faire référence à un groupe de capture nommé, se dispensant complètement d'avoir à penser aux positions des tampons de capture.

Pour être compatible avec les expressions régulières .Net, "\g{nom}" peut également être écrit comme "\k{nom}", "\k<nom>" ou "\k'nom'".

Pour éviter toute ambiguïté, *nom* ne doit pas commencer par un chiffre ni contenir de trait d'union.

Exemples

/(?<mot>\w+) \g{mot}/   # Trouve un mot dupliqué (par exemple, "chat chat")
/(?<mot>\w+) \k{mot}/   # La même chose.
/(?<mot>\w+) \g{ mot }/ # La même chose, montrant les blancs optionnels adjacents
                          # aux accolades.
/(?<mot>\w+) \k{ mot }/ # La même chose.
/(?<mot>\w+) \k<mot>/   # La même chose. Il n'y a pas d'accolades, donc aucun blanc
                          # n'est autorisé.
/(?<lettre1>.)(?<lettre2>.)\g{lettre2}\g{lettre1}/
                          # Met en correspondance un palindrome de quatre lettres (par exemple,
                          # "ABBA").

Assertions

Les assertions sont des conditions qui doivent être vraies ; elles ne correspondent pas réellement à des parties de la sous-chaîne. Il existe six assertions qui sont écrites comme des séquences d'échappement.

\A
"\A" ne correspond qu'au début de la chaîne. Si le modificateur "/m" n'est pas utilisé, alors "/\A/" est équivalent à "/^/". Cependant, si le modificateur "/m" est utilisé, alors "/^/" correspond aux sauts de ligne internes, mais le sens de "/\A/" n'est pas modifié par le modificateur "/m". "\A" correspond au début de la chaîne, que le modificateur "/m" soit utilisé ou non.
\z, \Z
"\z" et "\Z" correspondent à la fin de la chaîne. Si le modificateur "/m" n'est pas utilisé, alors "/\Z/" est équivalent à "/$/" ; c'est-à-dire qu'il correspond à la fin de la chaîne, ou un caractère avant le saut de ligne à la fin de la chaîne. Si le modificateur "/m" est utilisé, alors "/$/" correspond aux sauts de ligne internes, mais le sens de "/\Z/" n'est pas modifié par le modificateur "/m". "\Z" correspond à la fin de la chaîne (ou juste avant un saut de ligne final) que le modificateur "/m" soit utilisé ou non.

"\z" est identique à "\Z", sauf qu'il ne correspond pas avant un saut de ligne final. "\z" correspond uniquement à la fin de la chaîne, quels que soient les modificateurs utilisés, et pas seulement avant un saut de ligne. C'est ainsi que l'on ancre la correspondance à la véritable fin de la chaîne dans toutes les conditions.

\G
"\G" est généralement utilisé uniquement en combinaison avec le modificateur "/g". Si le modificateur "/g" est utilisé et que la correspondance est effectuée en contexte scalaire, Perl se souvient où la dernière correspondance s'est terminée dans la chaîne source, et la prochaine fois, il commencera la correspondance à partir de là où il s'est terminé la fois précédente.

"\G" correspond au point où la correspondance précédente sur cette chaîne s'est terminée, ou au début de cette chaîne s'il n'y a pas eu de correspondance précédente.

Mnémonique : *G*lobal.

\b{}, \b, \B{}, \B
"\b{...}", disponible depuis la v5.22, correspond à une limite (entre deux caractères, ou avant le premier caractère de la chaîne, ou après le dernier caractère de la chaîne) basée sur les règles Unicode pour le type de limite spécifié entre les accolades. Les types de limites sont donnés quelques paragraphes plus bas. "\B{...}" correspond à tout endroit entre des caractères où "\b{...}" du même type ne correspond pas.

"\b" lorsqu'il n'est pas immédiatement suivi d'une "{" est disponible dans tous les Perls. Il correspond à tout endroit entre un mot (quelque chose correspondant à "\w") et un caractère non mot ("\W") ; "\B" lorsqu'il n'est pas immédiatement suivi d'une "{" correspond à tout endroit entre des caractères où "\b" ne correspond pas. Pour obtenir une meilleure correspondance de mots dans le texte en langage naturel, voir « \b{wb} » ci-dessous.

"\b" et "\B" supposent qu'il y a un caractère non mot avant le début et après la fin de la chaîne source ; ainsi, "\b" correspondra au début (ou à la fin) de la chaîne source si la chaîne source commence (ou se termine) par un caractère mot. Sinon, "\B" correspondra.

N'utilisez pas quelque chose comme "\b=h

BACKSLASH SENSITIVE METASEQUENCES

The backslash-escaped sequences starting with a backslash have special meaning:

\A
Matches only at the beginning of the string. This is similar to "^", but doesn't match at the beginning of a line if the string is not starting at the beginning of a line.
\Z
Matches only at the end of the string. This is similar to "$", but doesn't match at the end of a line if the string is not ending at the end of a line.
\z
Matches only at the end of the string. This is similar to "\Z", but it does not allow a trailing newline.
\b
Matches the position between a word character and a non-word character, or at the beginning of the string if the first character is a word character, or at the end of the string if the last character is a word character. "\b" is a zero-width assertion.

The definition of a "word character" is implementation-defined, but usually consists of "[a-zA-Z0-9_]". This may be different in different locales.

A common mistake is to try and match the beginning of a word like this:

\bword\b

This works fine if the word is preceded by whitespace or punctuation (since they are non-word characters). But if the text is, say, 

read\b"
and you expect it to match the beginning of a line. It can't, because for there to be a boundary before the non-word "="", there must be a word character immediately previous. All plain "\b" and "\B" boundary determinations look for word characters alone, not for non-word characters nor for string ends. It may help to understand how "\b" and "\B" work by equating them as follows:

\b  really means    (?:(?<=\w)(?!\w)|(?<!\w)(?=\w))
\B  really means    (?:(?<=\w)(?=\w)|(?<!\w)(?!\w))

In contrast, "\b{...}" and "\B{...}" may or may not match at the beginning and end of the line, depending on the boundary type. These implement the Unicode default boundaries, specified in https://www.unicode.org/reports/tr14/ and https://www.unicode.org/reports/tr29/. The boundary types are:

"\b{gcb}" or "\b{g}"
This matches a Unicode "Grapheme Cluster Boundary". (Actually Perl always uses the improved "extended" grapheme cluster"). These are explained below under "\X". In fact, "\X" is another way to get the same functionality. It is equivalent to "/.+?\b{gcb}/". Use whichever is most convenient for your situation.
"\b{lb}"
This matches according to the default Unicode Line Breaking Algorithm (https://www.unicode.org/reports/tr14/), as customized in that document (Example 7 of revision 35 https://www.unicode.org/reports/tr14/tr14-35.html#Example7) for better handling of numeric expressions.

This is suitable for many purposes, but the Unicode::LineBreak module is available on CPAN that provides many more features, including customization.

"\b{sb}"
This matches a Unicode "Sentence Boundary". This is an aid to parsing natural language sentences. It gives good, but imperfect results. For example, it thinks that "Mr. Smith" is two sentences. More details are at https://www.unicode.org/reports/tr29/. Note also that it thinks that anything matching "\R" (except form feed and vertical tab) is a sentence boundary. "\b{sb}" works with text designed for word-processors which wrap lines automatically for display, but hard-coded line boundaries are considered to be essentially the ends of text blocks (paragraphs really), and hence the ends of sentences. "\b{sb}" doesn't do well with text containing embedded newlines, like the source text of the document you are reading. Such text needs to be preprocessed to get rid of the line separators before looking for sentence boundaries. Some people view this as a bug in the Unicode standard, and this behavior is quite subject to change in future Perl versions.
"\b{wb}"
This matches a Unicode "Word Boundary", but tailored to Perl expectations. This gives better (though not perfect) results for natural language processing than plain "\b" (without braces) does. For example, it understands that apostrophes can be in the middle of words and that parentheses aren't (see the examples below). More details are at https://www.unicode.org/reports/tr29/.

The current Unicode definition of a Word Boundary matches between every white space character. Perl tailors this, starting in version 5.24, to generally not break up spans of white space, just as plain "\b" has always functioned. This allows "\b{wb}" to be a drop-in replacement for "\b", but with generally better results for natural language processing. (The exception to this tailoring is when a span of white space is immediately followed by something like U+0303, COMBINING TILDE. If the final space character in the span is a horizontal white space, it is broken out so that it attaches instead to the combining character. To be precise, if a span of white space that ends in a horizontal space has the character immediately following it have any of the Word Boundary property values "Extend", "Format" or "ZWJ", the boundary between the final horizontal space character and the rest of the span matches "\b{wb}". In all other cases the boundary between two white space characters matches "\B{wb}".)

It is important to realize when you use these Unicode boundaries, that you are taking a risk that a future version of Perl which contains a later version of the Unicode Standard will not work precisely the same way as it did when your code was written. These rules are not considered stable and have been somewhat more subject to change than the rest of the Standard. Unicode reserves the right to change them at will, and Perl reserves the right to update its implementation to Unicode's new rules. In the past, some changes have been because new characters have been added to the Standard which have different characteristics than all previous characters, so new rules are formulated for handling them. These should not cause any backward compatibility issues. But some changes have changed the treatment of existing characters because the Unicode Technical Committee has decided that the change is warranted for whatever reason. This could be to fix a bug, or because they think better results are obtained with the new rule.

It is also important to realize that these are default boundary definitions, and that implementations may wish to tailor the results for particular purposes and locales. For example, some languages, such as Japanese and Thai, require dictionary lookup to accurately determine word boundaries.

Mnemonic: boundary.

Examples

 "cat"   =~ /\Acat/;     # Match.
 "cat"   =~ /cat\Z/;     # Match.
 "cat\n" =~ /cat\Z/;     # Match.
 "cat\n" =~ /cat\z/;     # No match.
 "cat"   =~ /\bcat\b/;   # Matches.
 "cats"  =~ /\bcat\b/;   # No match.
 "cat"   =~ /\bcat\B/;   # No match.
 "cats"  =~ /\bcat\B/;   # Match.
 while ("cat dog" =~ /(\w+)/g) {
     print $1;           # Prints 'catdog'
 }
 while ("cat dog" =~ /\G(\w+)/g) {
     print $1;           # Prints 'cat'
 }
 my $s = "He said, \"Is pi 3.14? (I'm not sure).\"";
 print join("|", $s =~ m/ ( .+? \b     ) /xg), "\n";

Misc

Here we document the backslash sequences that don't fall in one of the categories above. These are:

\K
This appeared in perl 5.10.0. Anything matched left of "\K" is not included in $&, and will not be replaced if the pattern is used in a substitution. This lets you write "s/PAT1 \K PAT2/REPL/x" instead of "s/(PAT1) PAT2/${1}REPL/x" or "s/(?<=PAT1) PAT2/REPL/x".

Mnemonic: Keep.

\N
This feature, available starting in v5.12, matches any character that is not a newline. It is a short-hand for writing "[^\n]", and is identical to the "." metasymbol, except under the "/s" flag, which changes the meaning of ".", but not "\N".

Note that "\N{...}" can mean a named or numbered character .

Mnemonic: Complement of \n.

\R
"\R" matches a generic newline; that is, anything considered a linebreak sequence by Unicode. This includes all characters matched by "\v" (vertical whitespace), and the multi character sequence "\x0D\x0A" (carriage return followed by a line feed, sometimes called the network newline; it's the end of line sequence used in Microsoft text files opened in binary mode). "\R" is equivalent to "(?>\x0D\x0A|\v)". (The reason it doesn't backtrack is that the sequence is considered inseparable. That means that 
"\x0D\x0A" =~ /^\R\x0A$/   # No match

fails, because the "\R" matches the entire string, and won't backtrack to match just the "\x0D".) Since "\R" can match a sequence of more than one character, it cannot be put inside a bracketed character class; "/[\R]/" is an error; use "\v" instead. "\R" was introduced in perl 5.10.0.

Note that this does not respect any locale that might be in effect; it matches according to the platform's native character set.

Mnemonic: none really. "\R" was picked because PCRE already uses "\R", and more importantly because Unicode recommends such a regular expression metacharacter, and suggests "\R" as its notation.

\X
This matches a Unicode extended grapheme cluster.

"\X" matches quite well what normal (non-Unicode-programmer) usage would consider a single character. As an example, consider a G with some sort of diacritic mark, such as an arrow. There is no such single character in Unicode, but one can be created by combining a base character with one or more combining characters. "\X" matches the base character and all of its combining characters, as a unit. "\X" is the same thing as "\b{gcb}".

Mnemonic: none really. "\X" was chosen because it is not currently used by PCRE and Unicode recommends it.
