NOM

perlapio - interface d'abstraction des E/S de Perl.

DESCRIPTION

Le code source de Perl, et les extensions qui souhaitent une portabilité maximale, devraient utiliser les fonctions ci-dessus plutôt que celles définies dans le stdio.h de l'ANSI C. Les en-têtes de Perl (en particulier "perlio.h") les "#define" ront au mécanisme d'E/S sélectionné lors de la configuration.

Les fonctions sont calquées sur celles de stdio.h, mais l'ordre des paramètres a été "légèrement réorganisé".

"PerlIO *" prend la place de FILE *. Comme FILE *, il doit être traité comme opaque (il est probablement sûr de supposer que c'est un pointeur vers quelque chose).

Il existe actuellement deux implémentations :

1. USE_STDIO
Toutes les fonctions ci-dessus sont #define'd aux fonctions stdio ou sont des fonctions wrapper triviales qui appellent stdio. Dans ce cas, SEULEMENT PerlIO * est un FILE *. C'est l'implémentation par défaut depuis que l'abstraction a été introduite dans perl5.003_02.
2. USE_PERLIO
Introduite juste après perl5.7.0, il s'agit d'une réimplémentation de l'abstraction ci-dessus qui donne à Perl plus de contrôle sur la manière dont les E/S sont effectuées, car elle découple les E/S de la manière dont le système d'exploitation et la bibliothèque C choisissent de les faire. Pour USE_PERLIO, PerlIO * a une couche d'indirection supplémentaire - c'est un pointeur vers un pointeur. Cela permet à PerlIO * de conserver une valeur connue tout en changeant l'implémentation en dessous * au moment de l'exécution *. Dans ce cas, toutes les fonctions ci-dessus sont de véritables fonctions (mais très simples) qui appellent l'implémentation sous-jacente.

C'est la seule implémentation pour laquelle PerlIO_apply_layers() fait quelque chose d'"intéressant".

L'implémentation USE_PERLIO est décrite dans perliol.

Parce que "perlio.h" est une couche mince (pour l'efficacité), les sémantiques de ces fonctions dépendent quelque peu de l'implémentation sous-jacente. Lorsque ces variations sont comprises, elles sont notées ci-dessous.

Sauf indication contraire, les fonctions retournent 0 en cas de succès, ou une valeur négative (généralement "EOF" qui est généralement -1) et définissent "errno" en cas d'erreur.

PerlIO_stdin(), PerlIO_stdout(), PerlIO_stderr()
Utilisez-les plutôt que "stdin", "stdout", "stderr". Elles sont écrites pour ressembler à des "appels de fonction" plutôt qu'à des variables car cela rend plus facile de *les faire* des appels de fonction si la plateforme ne peut pas exporter de données vers les modules chargés, ou si (par exemple) différents "threads" peuvent avoir des valeurs différentes.
PerlIO_open(path, mode), PerlIO_fdopen(fd,mode)
Elles correspondent à fopen()/fdopen() et les arguments sont les mêmes. Retournent "NULL" et définissent "errno" en cas d'erreur. Il peut y avoir une limite d'implémentation sur le nombre de descripteurs ouverts, qui peut être inférieure à la limite sur le nombre de fichiers ouverts - "errno" peut ne pas être défini lorsque "NULL" est retourné si cette limite est dépassée.
PerlIO_reopen(path,mode,f)
Bien que cela existe actuellement dans les deux implémentations, Perl lui-même ne l'utilise pas. *Comme Perl ne l'utilise pas, il n'est pas bien testé.*

Perl préfère "dup" le nouveau descripteur de bas niveau vers le descripteur utilisé par le PerlIO existant. Cela pourrait devenir le comportement de cette fonction à l'avenir.

PerlIO_printf(f,fmt,...), PerlIO_vprintf(f,fmt,a)
Ce sont les équivalents de fprintf()/vfprintf().
PerlIO_stdoutf(fmt,...)
C'est l'équivalent de printf(). printf est #defined à cette fonction, donc il est (actuellement) légal d'utiliser "printf(fmt,...)" dans les sources de Perl.
PerlIO_read(f,buf,count), PerlIO_write(f,buf,count)
Ils correspondent fonctionnellement à fread() et fwrite() mais les arguments et les valeurs de retour sont différents. Les signatures PerlIO_read() et PerlIO_write() ont été calquées sur les fonctions read() et write() de plus bas niveau, plus sensées : l'argument "fichier" est passé en premier, il n'y a qu'un seul "compte", et la valeur de retour peut distinguer entre erreur et "EOF".

Retourne un compte d'octets en cas de succès (qui peut être nul ou positif), retourne une valeur négative et définit "errno" en cas d'erreur. Selon l'implémentation, "errno" peut être "EINTR" si l'opération a été interrompue par un signal.

PerlIO_fill(f)
Remplit le tampon associé à "f" avec des données de la couche inférieure. "PerlIO_read" appelle ceci dans le cadre de son opération normale. Retourne 0 en cas de succès ; -1 en cas d'échec.
PerlIO_close(f)
Selon l'implémentation, "errno" peut être "EINTR" si l'opération a été interrompue par un signal.
PerlIO_puts(f,s), PerlIO_putc(f,c)
Ils correspondent à fputs() et fputc(). Notez que les arguments ont été modifiés pour avoir le "fichier" en premier.
PerlIO_ungetc(f,c)
Cela correspond à ungetc(). Notez que les arguments ont été modifiés pour avoir le "fichier" f
irst. Configure que la prochaine opération de lecture renverra l'octet c. Malgré l'implicite « caractère » dans le nom, seules les valeurs dans la plage 0..0xFF sont définies. Renvoie l'octet c en cas de succès ou -1 ("EOF") en cas d'erreur. Le nombre d'octets qui peuvent être « remis » peut varier, un seul caractère est garanti, et seulement s'il s'agit du dernier caractère qui a été lu à partir du descripteur.
PerlIO_unread(f,buf,count)
Ceci permet de remettre plus d'un octet. Il décale efficacement "count" octets au début du tampon "buf", de sorte que la ou les prochaines opérations de lecture les renvoient avant tout le reste qui se trouvait dans le tampon.

Renvoie le nombre d'octets non lus.

PerlIO_getc(f)
Ceci correspond à getc(). Malgré le c dans le nom, seule la plage d'octets 0..0xFF est prise en charge. Renvoie le caractère lu ou -1 ("EOF") en cas d'erreur.
PerlIO_eof(f)
Ceci correspond à feof(). Renvoie une indication vraie/fausse si le descripteur est en fin de fichier. Pour les terminaux, cela peut être « collant » ou non selon l'implémentation. Le drapeau est effacé par PerlIO_seek() ou PerlIO_rewind().
PerlIO_error(f)
Ceci correspond à ferror(). Renvoie une indication vraie/fausse s'il y a eu une erreur d'E/S sur le descripteur.
PerlIO_fileno(f)
Ceci correspond à fileno(). Notez que sur certaines plateformes, la signification de « fileno » peut ne pas correspondre à Unix. Renvoie -1 si le descripteur n'a pas de descripteur ouvert associé.
PerlIO_clearerr(f)
Ceci correspond à clearerr(), c'est-à-dire qu'il efface les indicateurs « erreur » et (généralement) « eof » pour le « flux ». Ne renvoie pas de valeur.
PerlIO_flush(f)
Ceci correspond à fflush(). Envoie toutes les données d'écriture mises en mémoire tampon au fichier sous-jacent. Si appelé avec "NULL", cela peut vider tous les flux ou provoquer un vidage de noyau avec certaines implémentations USE_STDIO. L'appel sur un descripteur ouvert en lecture seule, ou sur lequel la dernière opération était une lecture, peut entraîner un comportement indéfini sur certaines implémentations USE_STDIO. L'implémentation USE_PERLIO (couches) essaie de mieux se comporter : elle vide tous les flux ouverts lorsqu'on lui passe "NULL", et tente de conserver les données sur les flux de lecture soit dans le tampon, soit en déplaçant le descripteur à la position logique actuelle.
PerlIO_seek(f,offset,whence)
Ceci correspond à fseek(). Envoie les données d'écriture mises en mémoire tampon au fichier sous-jacent, ou ignore toutes les données de lecture mises en mémoire tampon, puis positionne le descripteur de fichier comme spécifié par offset et whence (sic). C'est la bonne chose à faire lors du passage entre la lecture et l'écriture sur le même descripteur (voir les problèmes avec PerlIO_flush() ci-dessus). L'offset est de type "Off_t" qui est une valeur de configuration perl qui peut ne pas être la même que l'"off_t" de stdio.
PerlIO_tell(f)
Ceci correspond à ftell(). Renvoie la position actuelle du fichier, ou (Off_t) -1 en cas d'erreur. Peut simplement renvoyer la valeur que le système « connaît » sans effectuer d'appel système ou vérifier le descripteur de fichier sous-jacent (donc son utilisation sur des descripteurs de fichiers partagés n'est pas sûre sans un PerlIO_seek()). La valeur de retour est de type "Off_t" qui est une valeur de configuration perl qui peut ne pas être la même que l'"off_t" de stdio.
PerlIO_getpos(f,p), PerlIO_setpos(f,p)
Ceci correspond (grossièrement) à fgetpos() et fsetpos(). Au lieu de Fpos_t de stdio, ils attendent une « valeur scalaire Perl » à passer. Ce qui y est stocké doit être considéré comme opaque. La disposition des données peut varier d'un descripteur à l'autre. Lorsqu'on n'utilise pas stdio ou si la plateforme n'a pas les appels stdio, ils sont implémentés en termes de PerlIO_tell() et PerlIO_seek().
PerlIO_rewind(f)
Ceci correspond à rewind(). Il est généralement défini comme étant 
PerlIO_seek(f,(Off_t)0L, SEEK_SET);
PerlIO_clearerr(f);
PerlIO_tmpfile()
Ceci correspond à tmpfile(), c'est-à-dire qu'il renvoie un PerlIO anonyme ou NULL en cas d'erreur. Le système tentera de supprimer automatiquement le fichier lorsqu'il sera fermé. Sur Unix, le fichier est généralement "unlink"é juste après sa création, donc peu importe comment il est fermé. Sur d'autres systèmes, le fichier peut être supprimé uniquement s'il est fermé via PerlIO_close() et/ou si le programme se termine via "exit". Selon l'implémentation, il peut y avoir des « conditions de concurrence » qui permettent à d'autres processus d'accéder au fichier, bien qu'en général, il sera plus sûr à cet égard que les schémas ad hoc.
PerlIO_setlinebuf(f)
Ceci correspond à setlinebuf(). Ne renvoie pas de valeur. Ce qui constitue une « ligne » dépend de l'implémentation, mais signifie généralement que l'écriture de « \n » vide le tampon. Ce qui se passe avec des choses comme « this\nthat » est incertain. (Le noyau Perl l'utilise *seulement* lors du « vidage » ; il n'a rien à voir avec la mise en mémoire tampon automatique de $| ).

Coexistence avec stdio

Il existe un support de base pour la coexistence de PerlIO avec stdio. Évidemment, si PerlIO est implémenté en termes de stdio, il n'y a pas de problème. Cependant, dans d'autres cas, des mécanismes doivent exister pour créer un FILE * qui peut être passé à du code de bibliothèque qui utilisera des appels stdio.

La première étape consiste à ajouter cette ligne :

#define PERLIO_NOT_STDIO 0

*avant* d'inclure tous les fichiers d'en-tête perl. (Cela deviendra probablement la valeur par défaut à un moment donné). Cela empêchera "perlio.h" de tenter de #définir les fonctions stdio sur les fonctions PerlIO.

Le code XS utilise probablement mieux un « typemap » s'il attend des arguments FILE *. Le typemap standard sera ajusté pour comprendre tous les changements dans ce domaine.

PerlIO_importFILE(f,mode)
Utilisé pour obtenir un PerlIO * à partir d'un FILE *.

L'argument mode doit être une chaîne telle qu'elle serait passée à fopen/PerlIO_open. S'il est NULL, alors - pour la prise en charge de la compatibilité descendante - le code tentera (selon la plateforme et l'implémentation) de déterminer empiriquement le mode dans lequel f est ouvert, ou utilisera « r+ » pour indiquer un flux lecture/écriture.

Une fois appelé, le FILE * ne doit *UNIQUEMENT* être fermé qu'en appelant PerlIO_close() sur le PerlIO * retourné.

Le PerlIO est défini en mode texte. Utilisez PerlIO_binmode si ce n'est pas le mode désiré.

Ce n'est *pas* l'inverse de PerlIO_exportFILE().

PerlIO_exportFILE(f,mode)
À partir d'un PerlIO *, crée un FILE * « natif » adapté pour être passé à du code qui attend d'être compilé et lié avec stdio.h C ANSI. L'argument mode doit être une chaîne telle qu'elle serait passée à fopen/PerlIO_open. S'il est NULL, alors - pour la prise en charge de la compatibilité descendante - le FILE * est ouvert dans le même mode que le PerlIO *.

Le fait qu'un tel FILE * ait été « exporté » est enregistré (normalement en ajoutant une couche :stdio « » au PerlIO *), ce qui peut affecter les futures opérations PerlIO sur le PerlIO * d'origine. Vous ne devez pas appeler fclose() sur le fichier à moins d'appeler PerlIO_releaseFILE() pour le dissocier du PerlIO *. (N'utilisez pas PerlIO_importFILE() pour effectuer la dissociation.)

Appeler cette fonction de manière répétée créera un FILE * à chaque appel (et ajoutera une couche :stdio à chaque fois également).

PerlIO_releaseFILE(p,f)
Appeler PerlIO_releaseFILE informe PerlIO que toute utilisation de FILE * est terminée. Il est retiré de la liste des FILE * « exportés », et le PerlIO * associé devrait retrouver son comportement d'origine.

Utilisez ceci pour dissocier un fichier d'un PerlIO * qui a été associé à l'aide de PerlIO_exportFILE().

PerlIO_findFILE(f)
Renvoie un FILE * natif utilisé par une couche stdio. S'il n'y en a pas, il en créera un avec PerlIO_exportFILE. Dans les deux cas, le FILE * doit être considéré comme appartenant au sous-système PerlIO et ne doit être fermé qu'en appelant PerlIO_close().

Fonctions « Fast gets »

En plus de l'API standard décrite ci-dessus, il existe une interface « d'implémentation » qui permet à perl d'accéder aux internes de PerlIO. Les appels suivants correspondent aux différentes macros FILE_xxx déterminées par Configure ou à leur équivalent dans d'autres implémentations. Cette section intéresse réellement uniquement ceux qui se préoccupent du comportement détaillé du noyau perl, de l'implémentation d'un mappage PerlIO ou de l'écriture de code qui peut utiliser « l'anticipation » qui a été effectuée par le système IO de la même manière que perl le fait. Notez que tout code qui utilise ces interfaces doit être prêt à faire les choses de manière traditionnelle si un descripteur ne les prend pas en charge.

PerlIO_fast_gets(f)
Renvoie vrai si l'implémentation dispose de toutes les interfaces requises pour permettre à "sv_gets" de perl de « contourner » le mécanisme d'E/S normal. Cela peut varier d'un descripteur à l'autre
handle. 
PerlIO_fast_gets(f) = PerlIO_has_cntptr(f) && \
                      PerlIO_canset_cnt(f) && \
                      'Peut définir le pointeur dans le tampon'
PerlIO_has_cntptr(f)
L'implémentation peut retourner un pointeur vers la position actuelle dans le "tampon" et un nombre d'octets disponibles dans le tampon. N'utilisez pas cela - utilisez PerlIO_fast_gets.
PerlIO_get_cnt(f)
Retourne le nombre d'octets lisibles dans le tampon. Un retour zéro ou négatif signifie qu'il n'y a plus d'octets disponibles.
PerlIO_get_ptr(f)
Retourne un pointeur vers le prochain octet lisible dans le tampon. L'accès via le pointeur (déréférencement) n'est sûr que si PerlIO_get_cnt() a retourné une valeur positive. Seuls des décalages positifs jusqu'à la valeur retournée par PerlIO_get_cnt() sont autorisés.
PerlIO_set_ptrcnt(f,p,c)
Définit le pointeur dans le tampon, et un nombre d'octets restants dans le tampon. Devrait être utilisé uniquement pour définir le pointeur dans la plage impliquée par les appels précédents à "PerlIO_get_ptr" et "PerlIO_get_cnt". Les deux valeurs doivent être cohérentes l'une avec l'autre (l'implémentation peut n'en utiliser qu'une ou l'autre, ou en exiger les deux).
PerlIO_canset_cnt(f)
L'implémentation peut ajuster son idée du nombre d'octets dans le tampon. N'utilisez pas cela - utilisez PerlIO_fast_gets.
PerlIO_set_cnt(f,c)
Obscur - définit le nombre d'octets dans le tampon. Obsolète. Utilisable uniquement si PerlIO_canset_cnt() retourne vrai. Actuellement utilisé seulement dans doio.c pour forcer un compte inférieur à -1 à -1. Peut-être devrait-il s'appeler PerlIO_set_empty ou similaire. Cet appel peut en fait ne rien faire si le "compte" est déduit du pointeur et d'une "limite". N'utilisez pas cela - utilisez PerlIO_set_ptrcnt().
PerlIO_has_base(f)
Retourne vrai si l'implémentation a un tampon, et peut retourner un pointeur vers l'ensemble du tampon et sa taille. Utilisé par perl pour les tests -T / -B. D'autres utilisations seraient très obscures...
PerlIO_get_base(f)
Retourne le début du tampon. L'accès n'est autorisé qu'aux décalages positifs dans le tampon jusqu'à la valeur retournée par PerlIO_get_bufsiz().
PerlIO_get_bufsiz(f)
Retourne le nombre total d'octets dans le tampon. Ce n'est ni le nombre qui peut être lu, ni la quantité de mémoire allouée au tampon. C'est plutôt ce que le système d'exploitation et/ou l'implémentation ont read() (ou autre) lors de la dernière demande d'IO.

Autres Fonctions

PerlIO_apply_layers(aTHX_ f,mode,layers)
La nouvelle interface pour l'implémentation USE_PERLIO. Les couches ":crlf" et ":raw" sont les seules autorisées pour les autres implémentations et celles-ci sont silencieusement ignorées. (Depuis perl5.8 ":raw" est obsolète.) Utilisez PerlIO_binmode() ci-dessous pour le cas portable.
PerlIO_binmode(aTHX_ f,ptype,imode,layers)
Le hook utilisé par l'opérateur "binmode" de perl. ptype est le caractère de perl pour le type d'IO :
'<' lecture
'>' écriture
'+' lecture/écriture

imode est "O_BINARY" ou "O_TEXT".

layers est une chaîne de couches à appliquer ; seul ":crlf" a du sens dans le cas non-USE_PERLIO. (Depuis perl5.8 ":raw" est obsolète au profit du passage de NULL.)

Les cas portables sont :

    PerlIO_binmode(aTHX_ f,ptype,O_BINARY,NULL);
et
    PerlIO_binmode(aTHX_ f,ptype,O_TEXT,":crlf");

Sur Unix, ces appels n'ont probablement aucun effet. Ailleurs, ils modifient la traduction de "\n" en CR, LF et provoquent éventuellement l'écriture ou la prise en compte d'un indicateur spécial de fin de fichier "texte" à la lecture. L'effet de l'appel après avoir effectué des IO sur le handle dépend de l'implémentation. (Il peut être ignoré, affecter les données déjà mises en tampon, ou s'appliquer uniquement aux données ultérieures.)

PerlIO_debug(fmt,...)
PerlIO_debug est une fonction de type printf() qui peut être utilisée pour le débogage. Pas de valeur de retour. Son utilisation principale est à l'intérieur de PerlIO où l'utilisation de printf réel, warn() etc. entraînerait un appel récursif à PerlIO et poserait problème.

PerlIO_debug écrit dans le fichier nommé par $ENV{'PERLIO_DEBUG'} ou utilise stderr par défaut si la variable d'environnement n'est pas définie. L'utilisation typique pourrait être

Bourne shells (sh, ksh, bash, zsh, ash, ...):
 PERLIO_DEBUG=/tmp/perliodebug.log ./perl -Di somescript some args
Csh/Tcsh:
 setenv PERLIO_DEBUG /tmp/perliodebug.log
 ./perl -Di somescript some args
Si vous avez l'utilitaire "env" :
 env PERLIO_DEBUG=/tmp/perliodebug.log ./perl -Di somescript args
Win32:
 set PERLIO_DEBUG=perliodebug.log
 perl -Di somescript some args

Sur un Perl compilé sans "-DDEBUGGING", ou lorsque le commutateur de ligne de commande "-Di" n'est pas spécifié, ou sous taint, PerlIO_debug() est une opération nulle (no-op).
