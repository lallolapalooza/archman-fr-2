PERL5420DELTA(1perl) Guide de référence du programmeur Perl PERL5420DELTA(1perl)

NOM

perldelta - ce qui est nouveau pour la version perl v5.42.0

DESCRIPTION

Ce document décrit les différences entre la version 5.42.0 et la version 5.40.0.

Améliorations du Cœur

Plus de subs CORE::

"chdir" a été ajouté en tant que sous-routine dans l'espace de noms "CORE::".

Auparavant, un code comme &CORE::chdir($dir) ou my $ref = \&CORE::chdir; $ref->($dir) générait une erreur indiquant "&CORE::chdir ne peut pas être appelé" directement". Ces cas sont maintenant entièrement pris en charge.

Nouveaupragma "source::encoding"

Cela vous permet de déclarer que la partie d'un programme pour le reste de la portée lexicale de ce pragma est encodée entièrement en ASCII (pour "use source::encoding 'ascii'") ou si l'UTF-8 est également autorisé (pour "use source::encoding 'utf8'"). Aucun autre encodage n'est accepté. La deuxième forme est entièrement équivalente à "use utf8" et peut être utilisée de manière interchangeable avec celle-ci.

Le but de ce pragma est de détecter tôt les cas où vous avez oublié de spécifier "use utf8".

"use source::encoding 'ascii'" est automatiquement activé dans la portée lexicale de "use v5.41.0" ou supérieur.

"no source::encoding" désactive toutes ces vérifications pour le reste de sa portée lexicale. Le sens des caractères non-ASCII est alors indéfini.

Nouveau attribut ":writer" sur les variables de champ

Les classes définies en utilisant "use feature 'class'" peuvent maintenant créer automatiquement des accesseurs d'écriture pour les champs scalaires, en utilisant l'attribut ":writer", de manière similaire à la façon dont ":reader" crée déjà des accesseurs de lecture.

class Point {
    field $x :reader :writer :param;
    field $y :reader :writer :param;
}
my $p = Point->new( x => 20, y => 40 );
$p->set_x(60);

Nouveaux opérateurs "any" et "all"

Deux nouvelles fonctionnalités expérimentales ont été ajoutées, qui introduisent les opérateurs de traitement de liste "any" et "all".

use v5.42;
use feature 'keyword_all';
no warnings 'experimental::keyword_all';
my @numbers = ...
if ( all { $_ % 2 == 0 } @numbers ) {
    say "All the numbers are even";
}

Ces mots-clés fonctionnent de manière similaire à "grep" sauf qu'ils ne retournent jamais vrai ou faux, testant si un (ou tous) des éléments de la liste font que le bloc de test retourne vrai. De ce fait, ils peuvent court-circuiter, évitant le besoin de tester d'autres éléments si un élément donné détermine le résultat final.

Ils sont inspirés par les fonctions du même nom du module List::Util, sauf qu'ils sont implémentés en tant qu'opérateurs de cœur directs, et donc performent plus rapidement, et ne produisent pas de cadre de pile d'appels de sous-routine supplémentaire pour l'invocation du bloc de code.

Les indicateurs de fonctionnalité activant ces mots-clés ont été nommés "keyword_any" et "keyword_all" pour éviter la confusion avec la capacité du module "feature" à se référer à toutes ses fonctionnalités en utilisant la balise d'export ":all". [GH #23104 https://github.com/Perl/perl5/issues/23104]

Les indicateurs d'avertissement expérimentaux associés sont par conséquent nommés "experimental::keyword_any" et "experimental::keyword_all".

L'apostrophe comme séparateur de noms globaux peut être désactivé

Ceci a été déprécié dans Perl 5.38 et supprimé comme prévu dans perl 5.41.3, mais après discussion a été rétabli par défaut.

Ceci peut être contrôlé avec la fonctionnalité "apostrophe_as_package_separator" qui est activée par défaut, mais désactivée à partir du bundle de fonctionnalités 5.41 et au-delà.

Si vous souhaitez désactiver son utilisation dans votre propre code, vous pouvez désactiver explicitement la fonctionnalité :

no feature "apostrophe_as_package_separator";

Notez que la désactivation de cette fonctionnalité empêche uniquement l'utilisation de l'apostrophe comme séparateur de paquet dans le code ; les références symboliques continuent de traiter "'" comme "::" lorsque la fonctionnalité est désactivée :

my $symref = "My'Module'Var";
# fonctionnalités par défaut
my $x = $My'Module'Var; # OK
no feature "apostrophe_as_package_separator";
no strict "refs";
my $y = $$symref;       # équivaut à $My::Module::Var
my $z = $My'Module'Var; # erreur de syntaxe

[GH #22644 https://github.com/Perl/perl5/issues/22644]

Déclaration lexicale de méthode utilisant "my method"

Comme "sub" depuis la version Perl 5.18, "method" peut maintenant être préfixé par le mot-clé "my". Cela déclare une sous-routine qui a une visibilité lexicale, plutôt que de paquet. Voir perlclass pour plus de détails.

Opérateur d'invocation lexicale de méthode "->&"

Outre la capacité de déclarer des méthodes lexicalement, cette release permet également d'invoquer une sous-routine lexicale comme si c'était une méthode, contournant ainsi la résolution de méthode habituelle basée sur le nom.

Combinées avec la déclaration lexicale de méthode, ces deux nouvelles capacités créent l'effet de méthodes privées.

Opérateurs Switch et Smart Match conservés, derrière une fonctionnalité

La fonctionnalité « switch » et l'opérateur smartmatch, "~~", ont été introduits dans la version v5.10. Leur comportement a été significativement modifié dans la version v5.10.1. Lorsque le système « experiment » a été ajouté dans la version v5.18.0, switch et smartmatch ont été déclarés expérimentalement rétroactivement. Au fil des ans, des propositions pour corriger ou compléter les fonctionnalités ont vu le jour et ont disparu.

Ils ont été dépréciés dans Perl v5.38.0 et leur suppression était prévue pour Perl v5.42.0. Après une discussion approfondie, leur suppression a été reportée indéfiniment. Leur utilisation ne produit plus d'avertissement de dépréciation.

Switch nécessite toujours la fonctionnalité "switch", qui est activée par défaut pour les bundles de fonctionnalités de v5.9.5 à v5.34. Switch reste désactivé dans les bundles de fonctionnalités 5.35 et ultérieurs, mais peut être activé séparément :

# pas de switch ici
use v5.10;
# switch ici
use v5.36;
# pas de switch ici
use feature "switch";
# switch ici

Smart match nécessite maintenant la fonctionnalité "smartmatch", qui est activée par défaut et incluse dans tous les bundles de fonctionnalités jusqu'à la version 5.40. Elle est désactivée pour le bundle de fonctionnalités 5.41 et ultérieurs, mais peut être activée séparément :

# smartmatch ici
use v5.41;
# pas de smartmatch ici
use feature "smartmatch";
# smartmatch i

Changements Incompatibles




Suppression des références de fonction parente pour les fonctions sans eval


Perl 5.40 avait réintroduit des références inconditionnelles des fonctions vers leurs fonctions parentes pour corriger un bug introduit dans Perl 5.18 qui cassait le comportement spécial de "eval EXPR" dans le package "DB", utilisé par le débogueur.


Dans certains cas, ce changement entraînait des chaînes de références circulaires entre les fermetures (closures) et d'autres références existantes, entraînant des fuites de mémoire.


Ce changement a été annulé, corrigeant [GH #22547
    https://github.com/Perl/perl5/issues/22547] mais re-cassant [GH
    #19370 https://github.com/Perl/perl5/issues/19370].


Cela signifie que les boucles de référence ne se produiront pas, et que les variables lexicales et les fonctions des fonctions englobantes peuvent ne pas être visibles dans le débogueur.


Notez que l'appel de "eval EXPR" dans une fonction provoque inconditionnellement une référence de la fonction à ses fonctions parentes, comme cela a toujours été le cas.








Améliorations de Performance


    
  
  • Les chaînes constant-foldées sont désormais partageables via le mécanisme Copy-on-Write.
      [GH #22163 https://github.com/Perl/perl5/pull/22163]
    
    Le code suivant aurait précédemment alloué onze tampons de
        chaînes, chacun contenant un million de « A » :
    
        
    my @scalars; push @scalars, ("A" x 1_000_000) for 0..9;

    
    
    Maintenant, un seul tampon est alloué et partagé entre un OP
        CONST et les dix éléments scalaires de @scalars.
    
    
    Notez que tout code utilisant ce type de constante pour simuler
        des fuites de mémoire (peut-être dans des fichiers de test) doit maintenant
        permuter la chaîne afin de déclencher une copie de chaîne et l'allocation
        de tampons distincts. Par exemple, "("A" x
        1_000_000).time" pourrait être un petit changement approprié.
    
  
    • 
  
  • "tr///" s'exécute désormais à la même
      vitesse, quelle que soit la représentation interne de son opérande, tant que les
      seuls caractères traduits sont de la plage ASCII, par exemple
      "tr/A-Z/a-z/". Auparavant, si le codage interne
      était UTF-8, une implémentation plus lente et plus générale était utilisée.
    • 
  
  • Le code qui utilise la fonction "indexed"
      du module intégré pour générer une liste de paires index/valeur à partir d'un
      tableau ou d'une liste qui est ensuite passée à une boucle "foreach"
      à deux variables pour les décompresser à nouveau est maintenant optimisé pour être
      plus efficace.
        
    my @array = (...);
foreach my ($idx, $val) (builtin::indexed @array) {
    ...
}

    
                
    foreach my ($idx, $val) (builtin::indexed LIST...) {
    ...
}

    
    
    En particulier, une liste temporaire deux fois plus grande que
        l'originale n'est plus générée. Au lieu de cela, la boucle itère sur le
        tableau ou la liste original directement, de la même manière que
        "foreach (@array)" ou
        "foreach (LIST)" le feraient.
    
  
    • 
  
  • L'optimiseur "peephole" reconnaît les motifs "substr"
      avec un décalage nul suivants et les remplace par un nouvel opérateur dédié
      ("OP_SUBSTR_LEFT").
      [GH #22785 https://github.com/Perl/perl5/issues/22785]
        
    substr($x, 0, ...)
substr($x, 0, ..., '')

    
  
    • 
  
  • La stringification des entiers par « print » dans perlfunc et « say »
      dans perlfunc, lorsqu'ils proviennent d'un
      "SVt_IV", est désormais plus efficace. [GH
      #22927 https://github.com/Perl/perl5/issues/22927]
    • 
  
  • L'inversion de chaîne à partir d'un seul argument, lorsque le tampon de
      chaîne n'est pas "balayé", est maintenant effectuée en un seul passage et est
      notablement plus rapide. L'étendue de l'amélioration dépend du compilateur et du
      matériel. [GH #23012 https://github.com/Perl/perl5/issues/23012]
    •

Nouveaux avertissements


    
  
  • __CLASS__ est expérimental
    
    (S experimental::class) Cet avertissement est émis si vous
        utilisez le mot-clé "__CLASS__" de
        "use feature 'class'". Ce mot-clé est
        actuellement expérimental et son comportement peut changer dans les
        futures versions de Perl.
    
  
    • 
  
  • %s() tenté sur le descripteur %s ouvert avec
      open()
    
    (W io) Vous avez appelé readdir(), telldir(),
        seekdir(), rewinddir() ou closedir() sur un descripteur
        qui a été ouvert avec open(). Si vous souhaitez utiliser ces
        fonctions pour parcourir le contenu d'un répertoire, vous devez ouvrir le
        descripteur avec opendir().
    
    
    [GH #22394 https://github.com/Perl/perl5/issues/22394]
    
  
    • 
  
  • Problème de précédence possible entre ! et %s
    
    (W precedence) Vous avez écrit quelque chose comme
    
        
    !$x < $y               # analysé comme : (!$x) < $y
!$x eq $y              # analysé comme : (!$x) eq $y
!$x =~ /regex/         # analysé comme : (!$x) =~ /regex/
!$obj isa Some::Class  # analysé comme : (!$obj) isa Some::Class

    
    
    mais parce que "!" a une
        précédence plus élevée que les opérateurs de comparaison,
        "=~", et "isa",
        cela est interprété comme la comparaison/correspondance de la négation
        logique du premier opérande, au lieu de nier le résultat de la
        comparaison/correspondance.
    
    
    Pour désambiguïser, utilisez soit un opérateur de comparaison/liaison
        négativé :
    
        
    $x >= $y
$x ne $y
$x !~ /regex/

    
    
    ... soit des parenthèses :
    
        
    !($x < $y)
!($x eq $y)
!($x =~ /regex/)
!($obj isa Some::Class)

    
    
    ... soit l'opérateur de basse précédence
        "not" :
    
        
    not $x < $y
not $x eq $y
not $x =~ /regex/
not $obj isa Some::Class

    
    
    (Si vous vouliez effectivement comparer le résultat booléen de
        la négation du premier opérande, utilisez des parenthèses comme
        "(!$x) < $y",
        "(!$x) eq $y", etc.)
    
    
    Remarque : cet avertissement ne se déclenche pas pour un code
        comme "!!$x == $y", c'est-à-dire lorsque
        la double négation ("!!") est utilisée
        comme opérateur de conversion en booléen.

      Corrections
      

        

      • Dans les expressions régulières, le contenu des références arrière "\g{...}" est maintenant correctement validé. Auparavant, "\g{1 FOO}" était silencieusement interprété comme "\g{1}", ignorant tout ce qui suivait le premier nombre. [GH #23050 https://github.com/Perl/perl5/issues/23050]
        • 

      • Les builds avec "-msse" et quadmath sur les systèmes x86 32 bits pouvaient planter avec un accès mal aligné au début du build. [GH #22577 https://github.com/Perl/perl5/issues/22577]
        • 

      • Les gestionnaires $SIG{__DIE__} et $SIG{__WARN__} ne peuvent plus être appelés récursivement, que ce soit délibérément ou accidentellement, comme décrit dans "%SIG" dans perlvar. C'est-à-dire que lorsqu'une exception (ou un avertissement) déclenche un appel à un gestionnaire $SIG{__DIE__} (ou $SIG{__WARN__}), les exceptions (ou avertissements) ultérieures sont traitées directement, ignorant %SIG jusqu'au retour de l'appel du gestionnaire $SIG{__DIE__} (ou $SIG{__WARN__}) d'origine. [GH #14527 https://github.com/Perl/perl5/issues/14527], [GH #22984 https://github.com/Perl/perl5/issues/22984], [GH #22987 https://github.com/Perl/perl5/issues/22987]
        • 

      • Une correspondance d'exécution qui contenait un bloc de code qui récursait vers la même partie du code qui exécutait cette correspondance pouvait provoquer un crash. [GH #22869 https://github.com/Perl/perl5/issues/22869]

        Par exemple :
        

        my $r = qr/... (?{ foo() if ... }) .../;
sub foo { $string =~ $r }
foo()

        

        • 

      • builtin::trim() ne vidait pas correctement "TARG", ce qui pouvait entraîner l'utilisation de versions numériques mises en cache obsolètes de la valeur lors d'une seconde évaluation. Vider correctement toutes les valeurs mises en cache. [GH #22784 https://github.com/Perl/perl5/issues/22784]
        • 

      • Dans certains cas, un "eval" n'ajoutait pas les parties entières aux lignes sources sauvegardées par le débogueur. [GH #23151 https://github.com/Perl/perl5/issues/23151]
        • 

      • Sur les systèmes de type POSIX, les builds multithread, si le gestionnaire de signaux de Perl reçoit un signal, nous renvoyons maintenant le signal au thread Perl principal. Précédemment, cela provoquait un crash. [GH #22487 https://github.com/Perl/perl5/issues/22487]
        • 

      • ObjectFIELDS() pour un objet et "xhv_class_fields" pour le stash de l'objet n'étaient pas toujours NULL ou non-NULL, confondant sv_dump() (et donc Dump() de Devel::Peek) qui plantait sur un objet sans champs définis dans certains cas. [GH #22959 https://github.com/Perl/perl5/issues/22959]
        • 

      • Les initialiseurs de classe et les blocs "ADJUST", selon perlclass, qui appelaient "last" ou d'autres sorties de boucle faisaient planter Perl. Même cause que pour [GH #16608 https://github.com/Perl/perl5/issues/16608].
        • 

      • Dans le mode de débogage, Perl sauvegarde les lignes sources de tous les fichiers (plus une indication pour chaque ligne si elle est breakable) pour être utilisées par le débogueur. Le format de stockage interne a été optimisé pour utiliser moins de mémoire. Cela devrait économiser 24 octets par ligne stockée pour les systèmes 64 bits, plus pour les builds "-Duselongdouble" ou "-Dusequadmath". Discuté dans [GH #23171 https://github.com/Perl/perl5/issues/23171].
        • 

      • Lors de la comparaison de chaînes lors de l'utilisation d'une locale UTF-8, le comportement était auparavant indéfini si l'une ou l'autre contenait un point de code supérieur à Unicode, tel que 0x110000. Désormais, tous ces points de code seront classés de la même manière que le point de code Unicode le plus élevé, U+10FFFF. [GH #22989 https://github.com/Perl/perl5/issues/22989]
        • 

      • Assurer que le clonage de la pile de sauvegarde pour l'émulation de fork ne duplique pas la libération de l'état RExC. [GH #23022 https://github.com/Perl/perl5/issues/23022]
        • 

      • Les exceptions levées et attrapées entièrement dans un bloc "defer {}" ou "finally {}" n'arrêtent plus la boucle d'exécution externe.

        Un code comme celui qui suit cessait d'exécuter le contenu du bloc "defer" une fois que l'exception interne du bloc "try"/"catch" interne était attrapée. Ceci a maintenant été corrigé et s'exécute comme prévu. ([GH #23064 https://github.com/Perl/perl5/issues/23064]).
        

        defer {
    try { die "It breaks\n"; }
    catch ($e) { warn $e }
    say "This line would never run";
}

        

        • 

      • La déclaration d'un tableau ou d'une table de hachage à portée lexicale à l'aide de "state" au sein d'une sous-routine, puis le retour immédiat, ne déclenche plus une erreur de type "Bizarre copy of HASH/ARRAY in subroutine exit". [GH #18630 https://github.com/Perl/perl5/issues/18630]
        • 

      • Sur les systèmes de type POSIX, si un signal est reçu par le gestionnaire de signaux de Perl, nous renvoyons maintenant le signal au thread Perl principal. Précédemment, cela provoquait un crash. [GH #22487 https://github.com/Perl/perl5/issues/22487]
        • 

      • La correspondance intelligente avec une référence de code qui utilise une sortie de boucle telle que "last" faisait planter Perl. [GH #16608 https://github.com/Perl/perl5/issues/16608]
        • 

      • "shmread" dans perlfunc et "shmwrite" dans perlfunc ne sont plus limités aux valeurs de 31 bits et peuvent utiliser tous les bits disponibles sur une plateforme pour leurs arguments POS et SIZE. [GH #22895 https://github.com/Perl/perl5/issues/22895]
        • 

      • "shmread" dans perlfunc se comporte mieux si VAR n'est pas une chaîne simple. Si VAR est une variable liée, elle appelle "STORE" une fois ; précédemment, elle appelait également "FETCH", mais sans utiliser le résultat. Si VAR est une référence, l'entité référencée voit son refcount correctement décrémenté lorsque VAR est converti en chaîne ; précédemment, cela entraînait une fuite de mémoire. [GH #22898 https://github.com/Perl/perl5/issues/22898]
        • 

      • "open" crée automatiquement un fichier temporaire anonyme lorsqu'il reçoit "undef" comme nom de fichier :

        open(my $fh, "+>", undef) or die ...

        

        Ceci est censé fonctionner uniquement lorsque la valeur non définie est celle retournée par la fonction "undef".
        

        Dans les versions de Perl antérieures à 5.41.3, cela posait un problème car la même valeur non définie peut être générée par la recherche de clés de table de hachage ou d'éléments de tableau inexistants, ce qui peut entraîner des bogues dans le code utilisateur (rapporté comme [GH #22385 https://github.com/Perl/perl5/issues/22385]).
        

        Dans la version 5.41.3, des vérifications supplémentaires basées sur l'arbre syntaxique du site d'appel ont été ajoutées, ce qui a corrigé ce problème pour un certain nombre de cas courants, mais pas tous, au détriment de la capacité des API qui encapsulent "open" à exposer son mode fichier anonyme. Un exemple notable d'une telle API est autodie.
        

        Cette version revient au problème précédent de préférence au nouveau pour le moment.
        

        • 

      • Le comportement de Perl lors de la recherche d'identifiants commençant par cut dans des chaînes comme "=cut_grass", et dans les chaînes "eval", où tout identifiant commençant par cut (par exemple "=cute") a été corrigé. [GH #22759 https://github.com/Perl/perl5/issues/22759]
        • 

      • "readline" dans perlfunc efface maintenant le drapeau d'erreur si une erreur se produit lors de la lecture et que cette erreur est "EAGAIN" ou "EWOULDBLOCK". Cela permet au code qui dépendait de "readline" pour effacer toutes les erreurs d'ignorer ces erreurs relativement inoffensives. [GH #22883 https://github.com/Perl/perl5/issues/22883]
