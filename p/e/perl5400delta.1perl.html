PERL5400DELTA(1perl) Guide de référence du programmeur Perl PERL5400DELTA(1perl)

NOM

perl5400delta - ce qu'il y a de nouveau pour la version perl v5.40.0

DESCRIPTION

Ce document décrit les différences entre la version 5.38.0 et la version 5.40.0.

Améliorations du noyau

Nouveau mot-clé "__CLASS__"

Lors de l'utilisation de la nouvelle fonctionnalité "class", le code à l'intérieur d'une méthode, d'un bloc "ADJUST" ou d'une expression d'initialisation de champ est maintenant autorisé à utiliser le nouveau mot-clé "__CLASS__". Celui-ci renvoie un nom de classe, similaire à "__PACKAGE__", mais alors que ce dernier donne le nom du paquet au moment de la compilation où le code apparaît, le mot-clé "__CLASS__" est conscient de la classe réelle au moment de l'exécution dont l'instance de l'objet est membre. Cela le rend utile pour la distribution de méthodes sur cette classe, en particulier pendant les constructeurs, où l'accès à $self n'est pas autorisé.

Pour plus d'informations, voir "__CLASS__" dans perlfunc.

Attribut ":reader" pour les variables de champ

Lors de l'utilisation de la fonctionnalité "class", les variables de champ peuvent maintenant avoir un attribut ":reader". Ceci demande qu'une méthode d'accès soit créée automatiquement qui renvoie simplement la valeur de la variable de champ de l'instance donnée.

field $name :reader;

Est équivalent à

field $name;
method name () { return $name; }

Un nom alternatif peut également être fourni :

field $name :reader(get_name);

Pour plus de détails, voir ":reader" dans perlclass.

Autoriser un espace dans l'option de ligne de commande "-M"

Lors du traitement des options de ligne de commande, perl autorise maintenant un espace entre le commutateur "-M" et le nom du module qui le suit.

$ perl -M Data::Dumper=Dumper -E 'say Dumper [1,2,3]'

Cela correspond au comportement existant de l'option "-I".

Restrictions aux déclarations "use VERSION"

Dans Perl 5.36, un avertissement de dépréciation a été ajouté lors de la rétrogradation d'une déclaration "use VERSION" d'une version supérieure à 5.11, à une version inférieure. Ceci est maintenant une erreur fatale.

De plus, il est maintenant une erreur fatale de lancer une déclaration "use VERSION" ultérieure lorsqu'une autre est en portée, lorsque l'une ou l'autre version est 5.39 ou supérieure. Ceci est pour éviter des complications concernant les fonctions lexicales importées des intégrés. Un avertissement de dépréciation a également été ajouté pour toute autre déclaration "use VERSION" ultérieure inférieure à la version 5.39, pour avertir qu'elle ne sera plus autorisée dans la version Perl 5.44.

Nouvelles fonctions "builtin::inf" et "builtin::nan" (expérimental)

Deux nouvelles fonctions, "inf" et "nan", ont été ajoutées à l'espace de noms "builtin". Elles agissent comme des constantes qui fournissent respectivement la valeur infinie en virgule flottante et la valeur Non-un-Nombre.

Nouvel opérateur logique xor "^^"

Perl a toujours eu trois opérateurs logiques de faible priorité "and", "or" et "xor", ainsi que trois versions binaires de haute priorité "&", "^" et "|". Jusqu'à cette version, alors que les opérateurs logiques de priorité moyenne de "&&" et "||" étaient également présents, il n'y avait pas d'équivalent exclusif ou. Cette version de Perl ajoute l'opérateur final "^^", complétant ainsi l'ensemble.

$x ^^ $y and say "L&#39;un de x ou y est vrai, mais pas les deux";

La fonctionnalité "try"/"catch" n'est plus expérimentale

Avant cette version, la fonctionnalité "try"/"catch" pour gérer les erreurs était considérée comme expérimentale. Introduite dans la version Perl 5.34.0, elle est maintenant considérée comme une fonctionnalité stable du langage et son utilisation n'affiche plus d'avertissement. Elle doit toujours être activée avec la fonctionnalité 'try'.

Voir "Try Catch Exception Handling" dans perlsyn.

L'itération sur plusieurs valeurs à la fois avec "for" n'est plus expérimental

Avant cette version, l'itération sur plusieurs valeurs à la fois avec "for" était considérée comme expérimentale. Introduite dans la version Perl 5.36.0, elle est maintenant considérée comme une fonctionnalité stable du langage et son utilisation n'affiche plus d'avertissement. Voir "Compound Statements" dans perlsyn.

Le module "builtin" n'est plus expérimental

Avant cette version, le module builtin et toutes ses fonctions étaient considérés comme expérimentaux. Introduit dans la version Perl 5.36.0, ce module est maintenant considéré comme stable et son utilisation n'affiche plus d'avertissement. Cependant, plusieurs de ses fonctions sont toujours considérées comme expérimentales.

Le bundle de fonctionnalités ":5.40" ajoute "try"

Le dernier bundle de fonctionnalités de version contient maintenant la fonctionnalité récemment stabilisée "try". Comme ce bundle de fonctionnalités est utilisé par le commutateur de ligne de commande "-E", elles sont immédiatement disponibles dans les scripts "-E".

"use v5.40;" importe les fonctions builtin

En plus d'importer un bundle de fonctionnalités, "use v5.40;" (ou des versions ultérieures) importe le bundle de version builtin correspondant.

Windows privilege escalation

A vulnerability in Perl for Windows, when executed from a directory that is writable by an unprivileged user, allows arbitrary code execution. This issue was discovered by PSIRT and reported to the Perl security team.

The Perl for Windows interpreter relies on the system's PATH environment variable to find the shell executable (cmd.exe). When a Perl script is run, the interpreter attempts to locate and execute cmd.exe from the operating system. However, due to a flaw in the path search order, Perl first looks for cmd.exe in the current working directory.

An attacker with limited privileges can exploit this behavior by placing a malicious executable named cmd.exe in a directory with weak permissions, such as C:\ProgramData. When an administrator subsequently runs a Perl script from this compromised directory, the malicious cmd.exe will be executed, leading to arbitrary code execution.

For more details, see the original vulnerability report at https://github.com/ycdxsb/WindowsPrivilegeEscalation. PSIRT then reported it to the Perl security team.

Incompatible Changes

reset EXPR now calls set-magic on scalars

Previously, reset EXPR did not invoke set magic when clearing scalar variables. This prevented changes from propagating to the underlying internal state when necessary, such as for $^W, and did not result in an exception being thrown when the underlying magic would normally do so, such as for $1.

Consequently, code that previously had no effect might now have an effect, potentially including throwing an exception.

reset EXPR already invoked set magic when modifying arrays and hashes.

This change has no impact on the plain reset command, which is used to reset single-match searches, as in m?pattern?.

[GH #20763 https://github.com/Perl/perl5/issues/20763]

Calling the import method of an unknown package produces a warning

Historically, it was possible to call the import or unimport method of any package, including those that had not been defined, with an argument, without encountering an error. For example, the following code would not raise an error in Perl 5.38:

Class::That::Does::Not::Exist->import("foo");

However, as of Perl 5.39.1, this behavior is deprecated and will now issue a warning. Note that calling these methods with no arguments continues to succeed silently and perform no action. For instance:

Class::That::Does::Not::Exist->import();

will continue to execute without raising an error. This is because every package implicitly inherits from the UNIVERSAL package, which now defines an import method. In earlier versions of Perl, no such method was defined, and instead, calls to import and unimport were specially handled to not raise errors if the method was not found.

This change was introduced to simplify the detection of typos in use statements when running on case-insensitive file systems. For example, on Windows or other platforms with case-insensitive file systems, in older versions of Perl, the following code:

use STRICT 'refs';

would silently do nothing because the module is actually named strict.pm, not STRICT.pm. While it would be loaded, its import method would never be called. This change will now also detect cases where a user provides an argument when using a package that does not define its own import method (e.g., most "pure" class definitions do not define an import method).

"return" no longer allows an indirect object

The return operator syntax now rejects indirect objects. In most situations, this would compile and even execute, but it was undocumented and could lead to confusing results. For example:

# note that sum hasn't been defined
sub sum_positive {
    return sum grep $_ > 0, @_;
    # unexpectedly parsed as:
    #   return *sum, grep $_ > 0, @_;
    # ... with the bareword acting like an extra (typeglob) argument
}
say for sum_positive(-1, 2, 3)

produced the following output:

*main::sum
2
3

[GH #21716 https://github.com/Perl/perl5/issues/21716]

Class barewords no longer resolved as file handles in method calls under "no feature "bareword_filehandles""

Under no feature 'bareword_filehandles', bareword file handles continued to be resolved in method calls:

open FH, "<", $somefile or die;
no feature 'bareword_filehandles';
FH->binmode;

This has been fixed. Now, the:

FH->binmode;

will attempt to resolve "FH" as a class, typically resulting in a runtime error.

Standard file handles, such as STDOUT, continue to be resolved as handles:

no feature 'bareword_filehandles';
STDOUT->flush; # continues to work

Note that once Perl resolves a bareword name as a class, it will continue to do so:

package SomeClass {
    sub somemethod{}
}
open SomeClass, "<", "somefile" or die;
# SomeClass resolved as a handle
SomeClass->binmode;
{
    no feature "bareword_filehandles";
    SomeClass->somemethod;
}
# SomeClass resolved as a class
SomeClass->binmode;

[GH #19426 https://github.com/Perl/perl5/issues/19426]

Diagnostics

Les ajouts ou modifications suivants ont été apportés aux messages de diagnostic, y compris les avertissements et les messages d'erreur fatale. Pour la liste complète des messages de diagnostic, voir perldiag.

Nouveaux diagnostics

Nouvelles erreurs

  • Impossible d'utiliser __CLASS__ en dehors d'une méthode ou d'une expression d'initialisation de champ

    (F) Une expression "__CLASS__" renvoie le nom de la classe de l'instance d'objet exécutant la méthode actuelle, et par conséquent, elle ne peut être placée qu'à l'intérieur d'une méthode réelle (ou d'une expression de type méthode, telle qu'une expression d'initialisation de champ).

  • get_layers : argument inconnu '%s'

    (F) Vous avez appelé PerlIO::get_layers() avec un argument inconnu. Les arguments valides sont fournis sous forme de paires clé/valeur, les clés étant l'une de "input", "output" ou "detail", suivie d'un booléen.

  • UNIVERSAL n'exporte rien

    (F) Vous avez demandé à UNIVERSAL d'exporter quelque chose, mais UNIVERSAL est la classe de base de toutes les classes et ne contient aucun symbole exportable.

  • Le paquet de version intégré "%s" n'est pas pris en charge par Perl

    (F) Vous avez tenté d'"use builtin :ver" pour un numéro de version qui est soit antérieur à 5.39 (quand la fonctionnalité a été ajoutée), soit postérieur à la version actuelle de perl.

  • Paquet de version invalide "%s"

    (F) Un numéro de version utilisé pour spécifier un paquet d'importation lors d'une instruction "use builtin ..." doit être formaté comme ":MAJOR.MINOR" avec un troisième composant optionnel, qui est ignoré. Chaque composant doit être un nombre de 1 à 3 chiffres. Aucun autre caractère n'est autorisé. La valeur spécifiée n'est pas conforme à ces règles.

  • Virgule manquante après le premier argument de return

    (F) Bien que certains opérateurs vous permettent de spécifier un descripteur de fichier ou un « objet indirect » avant la liste des arguments, "return" n'en fait pas partie.

  • Mémoire épuisée lors de l'utilisation de vec dans un contexte lvalue

    (F) Une tentative a été faite pour étendre une chaîne au-delà de la plus grande allocation mémoire possible en assignant à vec() appelé avec un deuxième argument important.

    (Ce cas générait auparavant une erreur générique "Mémoire épuisée !".)

  • Impossible de créer un objet d'une classe incomplète "%s"

    (F) Une tentative a été faite pour créer un objet d'une classe dont le début de la définition a été vu, mais la classe n'a pas été complétée.

    Cela peut se produire en cas d'échec d'un eval, ou si vous tentez de créer un objet au moment de la compilation avant que la classe ne soit complète :

    eval "class Foo {"; Foo->new; # erreur
class Bar { BEGIN { Bar->new } }; # erreur

    Auparavant, perl plantait ou se bloquait. [GH #22159 https://github.com/Perl/perl5/issues/22159]

Nouveaux avertissements

  • Forked open '%s' pas significatif dans <>

    (S inplace) Vous aviez "|-" ou "-|" dans @ARGV et avez essayé d'utiliser "<>" pour lire à partir de celui-ci.

    Auparavant, cela créait un fork et produisait un message d'erreur confus. [GH #21176 https://github.com/Perl/perl5/issues/21176]

  • Tentative d'appel de méthode indéfinie %s avec des arguments ("%s"%s) via le paquet "%s" (Peut-être avez-vous oublié de charger le paquet ?)

    (D deprecated::missing_import_called_with_args) Vous avez appelé la méthode import() ou unimport() d'une classe qui n'a pas de méthode d'importation définie dans son graphe d'héritage, et vous avez passé un argument à la méthode. C'est très souvent le signe d'un nom de paquet mal orthographié dans une instruction use ou require qui a réussi silencieusement en raison d'un système de fichiers insensible à la casse.

    Une autre raison fréquente de cette occurrence est lorsqu'on tente par erreur d'importer ou de désimporter un symbole d'une définition de classe ou d'un paquet qui n'utilise pas "Exporter" ou ne définit pas autrement sa propre méthode "import" ou "unimport".

Changements aux diagnostics existants

  • Nom "%s::%s" utilisé une seule fois : possible faute de frappe

    Cet avertissement respecte désormais le fait d'être marqué comme fatal. [GH #13814 https://github.com/Perl/perl5/issues/13814]

  • Mémoire épuisée dans perl:%s

    Il y avait plusieurs endroits dans le cœur de Perl qui imprimaient un message générique "Mémoire épuisée !" et s'arrêtaient en cas d'échec d'allocation de mémoire, sans indiquer quel programme avait manqué de mémoire. Ceux-ci ont été modifiés pour inclure le mot "perl" et la zone générale de l'échec d'allocation, par exemple "Mémoire épuisée dans perl:util:safesysrealloc". [GH #21672 https://github.com/Perl/perl5/issues/21672]

  • Problème de précédence possible avec un opérateur de flux de contrôle (%s)

    Cet avertissement mentionne désormais le nom de l'opérateur de flux de contrôle qui a déclenché le diagnostic (par exemple, "return", "exit", "die", etc.).

    Il couvre également plus de cas : Auparavant, l'avertissement n'était déclenché que si un opérateur logique de faible précédence (tel que "and", "or", "xor") était impliqué. Désormais, il est également affiché pour du code trompeur comme celui-ci :

    exit $x ? 0 : 1;  # est en fait analysé comme : exit($x) ? 0 : 1;
exit $x == 0;     # est en fait analysé comme : exit($x) == 0;
  • Utilisation de valeur non initialisée%s

    Cet avertissement est désormais légèrement plus précis dans les cas impliquant "length", "pop", "shift", ou "splice" :

    my $x;
length($x) == 0
# Avant :
#  Utilisation de valeur non initialisée $x dans numeric eq (==) à ...
# Maintenant :
#  Utilisation de valeur non initialisée length($x) dans numeric eq (==) à ...

    C'est-à-dire que l'avertissement n'implique plus que $x était utilisé directement comme opérande de "==", ce qui n'était pas le cas.

    De même :

    my @xs;
shift @xs == 0
# Avant :
#  Utilisation de valeur non initialisée dans @xs dans numeric eq (==) à ...
# Maintenant :
#  Utilisation de valeur non initialisée shift(@xs) dans numeric eq (==) à ...

    C'est plus précis car il n'y avait jamais d'"undef" dans @xs comme l'impliquait l'avertissement. (L'avertissement pour "pop" fonctionne de manière analogue.)

    Enfin :

    my @xs = (1, 2, 3);
splice(@xs, 0, 0) == 0
# Avant :
#  Utilisation de valeur non initialisée dans @xs dans numeric eq (==) à ...
# Maintenant :
#  Utilisation de valeur non initialisée dans numeric eq (==) à ...

    C'est-à-dire que dans les cas où "splice" renvoie "undef", il ne blâme plus inconditionnellement son premier argument. C'était trompeur car "splice" peut renvoyer "undef" même si aucun de ses arguments ne contient "undef".

    [GH #21930 https://github.com/Perl/perl5/issues/21930]

  • Ancien séparateur de paquet "'" déprécié

    Empêche cet avertissement d'apparaître de manière erronée lors de la vérification de l'heuristique pour l'avertissement Vous devez citer "%s".

    [GH #22145 https://github.com/Perl/perl5/issues/22145]

Changements internes

  • Option de construction "PERL_RC_STACK" ajoutée.

    Cette nouvelle option de construction est hautement expérimentale et n'est pas activée par défaut. Perl peut être compilé avec elle en utilisant l'option Configure "-Accflags='-DPERL_RC_STACK'".

    Elle fait en sorte que la pile d'arguments incrémente le compteur de références des SV qui y sont poussés. Elle est largement fonctionnelle, mais actuellement lente et incomplète.

    Il est prévu à long terme que cette option de construction devienne l'option par défaut, puis finalement la seule option ; mais cela sera dans de nombreuses versions.

    En particulier, il n'y a actuellement aucun support dans le code XS pour utiliser ces nouvelles fonctionnalités. Ainsi, sous cette option de construction, toutes les fonctions XS sont appelées via un wrapper de rétrocompatibilité qui ralentit ces appels.

    Dans les futures versions, un meilleur support pour le code XS est prévu. Il est attendu que le code XS simple pourra éventuellement utiliser une pile à comptage de références sans modification, les tâches lourdes étant gérées par le compilateur XS ("xsubpp") et les macros qu'il génère. Mais le code qui implémente les fonctions PP() devra finalement être modifié pour utiliser une nouvelle API PP : rpp_foo() plutôt que PUSHs() etc. Mais cette nouvelle API n'est pas encore stable, ni rétroportée via "Devel::PPPort".

    Voir perlguts pour plus de détails.

  • Une nouvelle fonction API a été ajoutée pour simplifier le code C (ou XS) qui crée des fragments d'arbre d'opérations "LISTOP". newLISTOPn() est une fonction variadique qui prend une liste de pointeurs d'opérateurs enfants terminée par "NULL", et construit un nouveau "LISTOP" vérifié pour les contenir tous. C'est plus simple que de créer un simple "OP_LIST", d'ajouter chaque enfant individuellement, puis d'appeler op_convert_list() dans la plupart des fragments de code.
  • L'API eval_sv() accepte désormais le drapeau "G_USEHINTS", qui utilise les indices tels que strict et features de "PL_curcop" au lieu des indices par défaut, c'est-à-dire aucun "use vX.XX;", pas de strict, features par défaut.

    Attention si vous utilisez ce drapeau dans du code XS : votre code évalué devra supporter la stricte obligation ou les fonctionnalités en vigueur au moment où votre fonction XS est appelée.

    [GH #21415 https://github.com/Perl/perl5/issues/21415]

  • "PERL_VERSION_LE" a été corrigé pour vérifier correctement « inférieur ou égal » plutôt que « inférieur ».
  • "dAX", "dITEMS" et donc "dXSARGS" déclarent maintenant "AX" et "items" comme "Stack_off_t" plutôt que "SSize_t". Cela revient à la compatibilité avec le support de pile pré-64 bits pour les compilations par défaut de perl où "Stack_off_t" est "I32". [GH #21782 https://github.com/Perl/perl5/issues/21782]
  • Une nouvelle fonction est maintenant disponible pour le code "XS", « sv_langinfo » dans perlapi. Elle fournit les mêmes informations que la fonction existante « Perl_langinfo8 » dans perlapi, mais retourne un SV au lieu d'un "char *", de sorte que les programmeurs n'ont pas à se soucier de l'encodage UTF-8 du résultat. Cette nouvelle fonction est maintenant l'interface préférée pour le code "XS" à la fonction nl_langinfo(3) de "libc". Depuis l'espace Perl, ces informations continuent d'être fournies par le module I18N::Langinfo.
  • glibc a une fonction équivalente non documentée à querylocale(), qui, d'après notre expérience, est fiable. Lorsque cette fonction est utilisée, elle élimine le besoin pour perl de conserver ses propres enregistrements, est donc plus efficace et garantie d'être exacte. L'utilisation de cette fonction peut être désactivée en définissant l'option de construction "NO_NL_LOCALE_NAME"

    Signalement de bugs

    Si vous trouvez ce qui vous semble être un bug, vous pourriez consulter la base de données des bugs de Perl à l'adresse https://github.com/Perl/perl5/issues. Vous pourriez également trouver des informations sur https://www.perl.org/, la page d'accueil de Perl.

    Si vous pensez avoir découvert un bug non signalé, veuillez ouvrir un ticket sur https://github.com/Perl/perl5/issues. Assurez-vous de réduire votre bug à un cas de test minuscule mais suffisant.

    Si le bug que vous signalez a des implications de sécurité qui rendent inapproprié son envoi à un traqueur de bugs public, alors consultez "SECURITY VULNERABILITY CONTACT INFORMATION" dans perlsec pour les détails sur la façon de signaler le problème.

    Exprimer sa gratitude

    Si vous souhaitez remercier les Perl 5 Porters pour le travail effectué dans Perl 5, vous pouvez le faire en exécutant le programme "perlthanks" :

    perlthanks

    Cela enverra un e-mail à la liste Perl 5 Porters avec votre message de remerciement.
