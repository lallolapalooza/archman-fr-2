personality(2) Manuel des appels système personality(2)

NOM

personality - définir le domaine d'exécution d'un processus

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/personality.h>
int personality(unsigned long persona);

DESCRIPTION

Linux prend en charge différents domaines d'exécution, ou personnalités, pour chaque processus. Entre autres choses, les domaines d'exécution indiquent à Linux comment mapper les numéros de signaux aux actions de signal. Le système de domaines d'exécution permet à Linux de fournir un support limité pour les binaires compilés sous d'autres systèmes d'exploitation de type UNIX.

Si persona n'est pas 0xffffffff, alors personality() définit le domaine d'exécution de l'appelant à la valeur spécifiée par persona. Spécifier persona comme 0xffffffff fournit un moyen de récupérer la personnalité actuelle sans la modifier.

Une liste des domaines d'exécution disponibles se trouve dans <sys/personality.h>. Le domaine d'exécution est une valeur de 32 bits dans laquelle les trois octets supérieurs sont réservés aux drapeaux qui amènent le noyau à modifier le comportement de certains appels système afin d'émuler des particularités historiques ou architecturales. L'octet le moins significatif est une valeur définissant la personnalité que le noyau doit supposer. Les valeurs des drapeaux sont les suivantes :

ADDR_COMPAT_LAYOUT (depuis Linux 2.6.9)
Avec ce drapeau défini, fournir une disposition d'espace d'adressage virtuel héritée.
ADDR_NO_RANDOMIZE (depuis Linux 2.6.12)
Avec ce drapeau défini, désactiver la randomisation de l'espace d'adressage.
ADDR_LIMIT_32BIT (depuis Linux 2.2)
Limiter l'espace d'adressage à 32 bits.
ADDR_LIMIT_3GB (depuis Linux 2.4.0)
Avec ce drapeau défini, utiliser 0xc0000000 comme décalage auquel rechercher un bloc de mémoire virtuelle lors de mmap(2) ; sinon, utiliser 0xffffe000. S'applique uniquement aux processus x86 32 bits.
FDPIC_FUNCPTRS (depuis Linux 2.6.11)
Les pointeurs de fonction en espace utilisateur vers les gestionnaires de signaux pointent vers des descripteurs. S'applique uniquement à ARM si BINFMT_ELF_FDPIC et SuperH.
MMAP_PAGE_ZERO (depuis Linux 2.4.0)
Mapper la page 0 en lecture seule (pour prendre en charge les binaires qui dépendent de ce comportement SVr4).
READ_IMPLIES_EXEC (depuis Linux 2.6.8)
Avec ce drapeau défini, PROT_READ implique PROT_EXEC pour mmap(2).
SHORT_INODE (depuis Linux 2.4.0)
Aucun effet.
STICKY_TIMEOUTS (depuis Linux 1.2.0)
Avec ce drapeau défini, select(2), pselect(2), et ppoll(2) ne modifient pas l'argument de délai d'attente retourné lorsqu'ils sont interrompus par un gestionnaire de signaux.
UNAME26 (depuis Linux 3.1)
Faire en sorte que uname(2) rapporte un numéro de version 2.6.(40+x) au lieu d'un numéro de version MAJOR.x. Ajouté comme mesure temporaire pour prendre en charge les applications défectueuses qui ne pouvaient pas gérer le passage de la numérotation des versions du noyau de Linux 2.6.x à Linux 3.x.
WHOLE_SECONDS (depuis Linux 1.2.0)
Aucun effet.

Les domaines d'exécution disponibles sont :

PER_BSD (depuis Linux 1.2.0)
BSD. (Aucun effet.)
PER_HPUX (depuis Linux 2.4)
Prise en charge de HP/UX 32 bits. Ce support n'a jamais été complet et a été abandonné. Ainsi, depuis Linux 4.0, cette valeur n'a aucun effet.
PER_IRIX32 (depuis Linux 2.2)
IRIX 5 32 bits. Jamais pleinement fonctionnel ; support abandonné dans Linux 2.6.27. Implique STICKY_TIMEOUTS.
PER_IRIX64 (depuis Linux 2.2)
IRIX 6 64 bits. Implique STICKY_TIMEOUTS ; sinon, aucun effet.
PER_IRIXN32 (depuis Linux 2.2)
IRIX 6 nouveau 32 bits. Implique STICKY_TIMEOUTS ; sinon, aucun effet.
PER_ISCR4 (depuis Linux 1.2.0)
Implique STICKY_TIMEOUTS ; sinon, aucun effet.
PER_LINUX (depuis Linux 1.2.0)
Linux.
PER_LINUX32 (depuis Linux 2.2)
uname(2) retourne le nom de l'architecture 32 bits dans le champ machine ("i686" au lieu de "x86_64", etc.).
Sous ia64 (Itanium), les processus ayant cette personnalité n'ont pas le drapeau O_LARGEFILE de open(2) forcé.
Sous ARM 64 bits, la définition de cette personnalité est interdite si l'execve(2) d'un processus 32 bits est également interdit (voir le paramètre de noyau allow_mismatched_32bit_el0 et Documentation/arm64/asymmetric-32bit.rst).
PER_LINUX32_3GB (depuis Linux 2.4)
Identique à PER_LINUX32, mais implique ADDR_LIMIT_3GB.
PER_LINUX_32BIT (depuis Linux 2.0)
Identique à PER_LINUX, mais implique ADDR_LIMIT_32BIT.
PER_LINUX_FDPIC (depuis Linux 2.6.11)
Identique à PER_LINUX, mais implique FDPIC_FUNCPTRS.
PER_OSF4 (depuis Linux 2.4)
OSF/1 v4. Aucun effet depuis Linux 6.1, qui a supprimé le support des binaires a.out. Avant cela, sur alpha, effaçait les 32 bits supérieurs de iov_len dans le tampon utilisateur pour assurer la compatibilité avec les anciennes versions d'OSF/1 où iov_len était défini comme int.
PER_OSR5 (depuis Linux 2.4)
SCO OpenServer 5. Implique STICKY_TIMEOUTS et WHOLE_SECONDS ; sinon, aucun effet.
PER_RISCOS (depuis Linux 2.3.7 ; macro depuis Linux 2.3.13)
Acorn RISC OS/Arthur (MIPS). Aucun effet. Jusqu'à Linux v4.0, définissait l'altroot d'émulation sur /usr/gnemul/riscos (voir PER_SUNOS ci-dessous). Avant cela, jusqu'à Linux 2.6.3, émulation Arthur uniquement.
PER_SCOSVR3 (depuis Linux 1.2.0)
SCO UNIX System V Release 3. Identique à PER_OSR5, mais implique également SHORT_INODE.
PER_SOLARIS (depuis Linux 2.4)
Solaris. Implique STICKY_TIMEOUTS ; sinon, aucun effet.
PER_SUNOS (depuis Linux 2.4.0)
Sun OS. Identique à PER_BSD, mais implique STICKY_TIMEOUTS. Avant Linux 2.6.26, redirigeait les recherches de bibliothèques et de liaisons dynamiques vers /usr/gnemul. Buggy, largement non maintenu et presque entièrement inutilisé.
PER_SVR3 (depuis Linux 1.2.0)
AT&T UNIX System V Release 3. Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon, aucun effet.
PER_SVR4 (depuis Linux 1.2.0)
AT&T UNIX System V Release 4. Implique STICKY_TIMEOUTS et MMAP_PAGE_ZERO ; sinon, aucun effet.
PER_UW7 (depuis Linux 2.4)
UnixWare 7. Implique STICKY_TIMEOUTS et MMAP_PAGE_ZERO ;

personality(2) — Linux manual pages

NAME

personality — set process personality

LIBRARY

Standard C library (libc, libc-so)

SYNOPSIS

#include <sys/personality.h>

int personality(unsigned long persona);

DESCRIPTION

The personality() system call allows a process to change its effective "personality". The personality is a set of flags that control certain kernel behaviors related to system call semantics and other aspects of process execution. These flags are used to emulate the behavior of different Unix-like operating systems.

The persona argument specifies the new personality to be set. If persona is zero, the current personality is returned without changing it.

The following personality flags are recognized:

PER_LINUX
Standard Linux behavior. This is the default personality.
PER_LINUX32
Linux 32-bit emulation personality. This allows 32-bit binaries to run on a 64-bit kernel.
PER_IRIX
IRIX behavior. Implies STICKY_TIMEOUTS; otherwise no effect.
PER_IRIX32
IRIX 32-bit emulation personality.
PER_SOLARIS
Solaris behavior. Implies STICKY_TIMEOUTS and SHORT_INODE; otherwise no effect.
PER_SUNOS
SunOS behavior. Implies STICKY_TIMEOUTS and SHORT_INODE; otherwise no effect.
PER_OSF4
OSF/1 behavior (version 4). Implies STICKY_TIMEOUTS and SHORT_INODE; otherwise no effect.
PER_HPUX
HP-UX behavior. Implies STICKY_TIMEOUTS and SHORT_INODE; otherwise no effect.
PER_AIUX386
AIX behavior on Intel x86. Implies STICKY_TIMEOUTS and SHORT_INODE; otherwise no effect.
PER_IRIX64
IRIX 64-bit behavior.
PER_MIPS
MIPS behavior. Implies STICKY_TIMEOUTS and SHORT_INODE; otherwise no effect.
PER_SCOUNT
System V Release 4 behavior (SCO). Implies STICKY_TIMEOUTS and SHORT_INODE; otherwise no effect.
PER_WYSEV386
(since Linux 1.2.0) WYSE UNIX System V/386. Implies STICKY_TIMEOUTS and SHORT_INODE; otherwise no effect.
PER_XENIX
(since Linux 1.2.0) XENIX. Implies STICKY_TIMEOUTS and SHORT_INODE; otherwise no effect.

RETURN VALUE

On success, the previous persona is returned. On error, -1 is returned, and errno is set to indicate the error.

ERRORS

EINVAL
The kernel was unable to change the personality.

STANDARDS

Linux.

HISTORY

Linux 1.1.20, glibc 2.3.

SEE ALSO

NOM

personality — définit la personnalité d'un processus

BIBLIOTHQUE

Bibliothèque C standard (libc, libc-so)

SYNTAXE

#include <sys/personality.h>

int personality(unsigned long persona);

DESCRIPTION

L'appel système personality() permet à un processus de changer sa « personnalité » effective. La personnalité est un ensemble d'indicateurs qui contrôlent certains comportements du noyau liés à la sémantique des appels système et à d'autres aspects de l'exécution du processus. Ces indicateurs sont utilisés pour émuler le comportement de différents systèmes d'exploitation de type Unix.

L'argument persona spécifie la nouvelle personnalité à définir. Si persona est zéro, la personnalité actuelle est retournée sans être modifiée.

Les indicateurs de personnalité suivants sont reconnus :

PER_LINUX
Comportement Linux standard. C'est la personnalité par défaut.
PER_LINUX32
Personnalité d'émulation Linux 32 bits. Permet d'exécuter des binaires 32 bits sur un noyau 64 bits.
PER_IRIX
Comportement IRIX. Implique STICKY_TIMEOUTS ; sinon aucun effet.
PER_IRIX32
Personnalité d'émulation IRIX 32 bits.
PER_SOLARIS
Comportement Solaris. Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon aucun effet.
PER_SUNOS
Comportement SunOS. Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon aucun effet.
PER_OSF4
Comportement OSF/1 (version 4). Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon aucun effet.
PER_HPUX
Comportement HP-UX. Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon aucun effet.
PER_AIUX386
Comportement AIX sur Intel x86. Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon aucun effet.
PER_IRIX64
Comportement IRIX 64 bits.
PER_MIPS
Comportement MIPS. Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon aucun effet.
PER_SCOUNT
Comportement System V Release 4 (SCO). Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon aucun effet.
PER_WYSEV386
(depuis Linux 1.2.0) WYSE UNIX System V/386. Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon aucun effet.
PER_XENIX
(depuis Linux 1.2.0) XENIX. Implique STICKY_TIMEOUTS et SHORT_INODE ; sinon aucun effet.

VALEUR RE tourNEE

En cas de succès, la persona précédente est retournée. En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL

NORMES

Linux.
