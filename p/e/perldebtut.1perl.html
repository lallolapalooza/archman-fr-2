PERLDEBTUT(1perl) Guide de référence pour programmeurs Perl PERLDEBTUT(1perl)

NOM

perldebtut — Tutoriel de débogage Perl

DESCRIPTION

Une introduction (très) légère à l'utilisation du débogueur Perl, et une indication des sources d'information existantes et plus approfondies sur le sujet du débogage de programmes Perl.

Il y a un nombre extraordinaire de personnes qui semblent ne rien savoir sur l'utilisation du débogueur Perl, bien qu'elles utilisent le langage tous les jours. Ceci est pour elles.

use strict

Tout d'abord, il y a quelques choses que vous pouvez faire pour vous simplifier la vie lorsqu'il s'agit de déboguer des programmes Perl, sans utiliser du tout le débogueur. Pour démontrer, voici un script simple, nommé "hello", avec un problème :

#!/usr/bin/perl
$var1 = 'Hello World'; # always wanted to do that :-)
$var2 = "$varl\n";
print $var2; 
exit;

Bien que cela compile et s'exécute sans problème, cela ne fera probablement pas ce qui est attendu, à savoir qu'il n'imprime pas du tout "Hello World\n"; il fera au contraire exactement ce qui lui a été demandé, les ordinateurs étant un peu enclins à cela. C'est-à-dire qu'il imprimera un caractère de nouvelle ligne, et vous obtiendrez ce qui ressemble à une ligne vierge. Il semble y avoir 2 variables alors qu'il y en a réellement 3 (à cause de la faute de frappe) :

$var1 = 'Hello World';
$varl = undef;
$var2 = "\n";

Pour attraper ce genre de problème, nous pouvons forcer chaque variable à être déclarée avant utilisation en incluant le module strict, en plaçant 'use strict;' après la première ligne du script.

Maintenant, lorsque vous l'exécutez, Perl se plaint des 3 variables non déclarées et nous obtenons quatre messages d'erreur car une variable est référencée deux fois :

Global symbol "$var1" requires explicit package name at ./t1 line 4.
Global symbol "$var2" requires explicit package name at ./t1 line 5.
Global symbol "$varl" requires explicit package name at ./t1 line 5.
Global symbol "$var2" requires explicit package name at ./t1 line 7.
Execution of ./hello aborted due to compilation errors.

Magnifique ! Et pour corriger cela, nous déclarons toutes les variables explicitement et maintenant notre script ressemble à ceci :

#!/usr/bin/perl
use strict;
my $var1 = 'Hello World';
my $varl = undef;
my $var2 = "$varl\n";
print $var2; 
exit;

Nous faisons ensuite (toujours une bonne idée) une vérification de la syntaxe avant d'essayer de l'exécuter à nouveau :

> perl -c hello
hello syntax OK

Et maintenant, lorsque nous l'exécutons, nous obtenons toujours "\n", mais au moins nous savons pourquoi. Le simple fait de faire compiler ce script a révélé la variable '$varl' (avec la lettre 'l'), et simplement changer $varl en $var1 résout le problème.

Regarder les données et -w et v

Ok, mais qu'en est-il lorsque vous voulez vraiment voir vos données, ce qu'il y a dans cette variable dynamique, juste avant de l'utiliser ?

#!/usr/bin/perl 
use strict;
my $key = 'welcome';
my %data = (
        'this' => qw(that), 
        'tom' => qw(and jerry),
        'welcome' => q(Hello World),
        'zip' => q(welcome),
);
my @data = keys %data;
print "$data{$key}\n";
exit;

Cela semble correct, après qu'il ait passé la vérification de la syntaxe (perl -c nom_du_script), nous l'exécutons et tout ce que nous obtenons est une ligne vierge à nouveau ! Hmmmm.

Une approche de débogage courante ici serait d'ajouter libéralement quelques instructions print, pour ajouter une vérification juste avant d'imprimer nos données, et une autre juste après :

print "All OK\n" if grep($key, keys %data);
print "$data{$key}\n";
print "done: '$data{$key}'\n";

Et essayons à nouveau :

> perl data
All OK     
done: ''

Après avoir longuement regardé le même morceau de code et ne pas avoir vu la forêt pour les arbres pendant un certain temps, nous prenons une tasse de café et essayons une autre approche. C'est-à-dire que nous appelons la cavalerie en donnant à Perl le commutateur '-d' sur la ligne de commande :

> perl -d data 
Default die handler restored.
Loading DB routines from perl5db.pl version 1.07
Editor support available.
Enter h or `h h' for help, or `man perldebug' for more help.
main::(./data:4):     my $key = 'welcome';

Maintenant, ce que nous avons fait ici, c'est lancer le débogueur Perl intégré sur notre script. Il s'est arrêté à la première ligne de code exécutable et attend une entrée.

Avant d'aller plus loin, vous voudrez savoir comment quitter le débogueur : utilisez juste la lettre 'q', pas les mots 'quit' ou 'exit' :

DB<1> q
>

C'est tout, vous êtes de retour sur votre terrain.

Il y a quelques options utiles à connaître immédiatement. Vous ne penseriez pas que nous utilisons des bibliothèques du tout en ce moment, mais 'M' affichera les modules actuellement chargés et leur numéro de version, tandis que 'm' affichera les méthodes, et 'S' montre toutes les sous-routines (par motif) comme indiqué ci-dessous. DM<3>X ~err
FileHandle(stderr) => fileno(2)

Exemple de session type

Voici un petit programme, et nous allons le déboguer.

Enter h or `h h' for help, or `man perldebug' for more help.

Nous sommes maintenant sur la ligne 4. La ligne 4 est celle qui vient d'être exécutée juste avant d'entrer dans le débogueur. La ligne 5 est celle qui va être exécutée ensuite.

DB<4>

Dans ce cas, il n'y a pas grand-chose à voir, mais normalement il y a des pages de code à parcourir, et l peut être très utile. Pour réinitialiser votre vue à la ligne que nous sommes sur le point d'exécuter, tapez un point seul .:

DB<5> .
main::(./data_a:4):     my $key = 'welcome';

La ligne affichée est celle qui va être exécutée ensuite, elle n'a pas encore eu lieu. Donc, bien que nous puissions imprimer une variable avec la lettre p, à ce stade nous obtiendrions juste une valeur vide (indéfinie). main::(./data_a:9):             'zip' => q(welcome),

DB<7> p $key
welcome

DB<8> c 13

Nous avons dépassé notre vérification (où 'All OK' a été imprimé) et nous nous sommes arrêtés juste avant le cœur de notre tâche. Nous pourrions essayer d'imprimer quelques variables pour voir ce qui se passe :

DB<9> p $data{$key}

Passage pas à pas dans le code

Voici un programme simple qui convertit entre Celsius et Fahrenheit, il a également un problème :

#!/usr/bin/perl
use v5.36;
my $arg = $ARGV[0] || '-c20';
if ($arg =~ /^\-(c|f)((\-|\+)*\d+(\.\d+)*)$/) {
       my ($deg, $num) = ($1, $2);
       my ($in, $out) = ($num, $num);
       if ($deg eq 'c') {
               $deg = 'f';
               $out = &c2f($num);
       } else {
               $deg = 'c';
               $out = &f2c($num);
       }
       $out = sprintf('%0.2f', $out);
       $out =~ s/^((\-|\+)*\d+)\.0+$/$1/;
       print "$out $deg\n";
} else {
       print "Usage: $0 -[c|f] num\n";
}
exit;
sub f2c {
       my $f = shift;
       my $c = 5 * $f - 32 / 9;
       return $c;
}
sub c2f {
       my $c = shift;
       my $f = 9 * $c / 5 + 32;
       return $f;
}

Pour une raison quelconque, la conversion Fahrenheit vers Celsius ne renvoie pas la sortie attendue. Voici ce qu'elle fait :

> temp -c0.72
33.30 f
> temp -f33.3
162.94 c

Pas très cohérent ! Nous allons définir un point d'arrêt dans le code manuellement et l'exécuter sous le débogueur pour voir ce qui se passe. Un point d'arrêt est un drapeau, auquel le débogueur s'exécutera sans interruption, lorsqu'il atteindra le point d'arrêt, il arrêtera l'exécution et offrira un prompt pour une interaction supplémentaire. En utilisation normale, ces commandes de débogueur sont complètement ignorées, et elles sont sûres - bien qu'un peu désordonnées - à laisser dans le code de production.

my ($in, $out) = ($num, $num);
$DB::single=2; # insérer à la ligne 9 !
if ($deg eq 'c')
        ...

Default die handler restored.
Loading DB routines from perl5db.pl version 1.07
Editor support available.
Enter h or `h h' for help, or `man perldebug' for more help.
main::(temp:4): my $arg = $ARGV[0] || '-c100';

Nous pouvons placer un autre point d'arrêt sur n'importe quelle ligne commençant par un deux-points, nous utiliserons la ligne 17 car c'est juste à la sortie de la sous-routine, et nous aimerions y faire une pause plus tard :

DB<2> b 17

Il n'y a pas de retour de cette commande, mais vous pouvez voir quels points d'arrêt sont définis en utilisant la commande liste L:

ASTUCES DE SORTIE

Pour obtenir toute la sortie de votre fichier journal d'erreurs, et ne manquer aucun message via la mise en mémoire tampon utile du système d'exploitation, insérez une ligne comme celle-ci, au début de votre script :

$|=1;

Pour regarder la fin d'un fichier journal qui grossit dynamiquement, (depuis la ligne de commande) :

tail -f $error_log

Encapsuler tous les appels à die dans une routine de gestion peut être utile pour voir comment et d'où ils sont appelés, perlvar a plus d'informations :

BEGIN { $SIG{__DIE__} = sub { require Carp; Carp::confess(@_) } }

Diverses techniques utiles pour la redirection des descripteurs de fichiers STDOUT et STDERR sont expliquées dans perlopentut et perlfaq8.

CGI

Juste une petite astuce ici pour tous ces programmeurs CGI qui ne comprennent pas comment dépasser cette invite « en attente d'entrée », lorsqu'ils exécutent leur script CGI depuis la ligne de commande, essayez quelque chose comme ceci :

> perl -d my_cgi.pl -nodebug

Bien sûr, CGI et perlfaq9 vous en diront plus.

IG

L'interface en ligne de commande est étroitement intégrée à une extension emacs et il existe également une interface vi.

Vous n'avez pas à tout faire en ligne de commande, cependant, il existe quelques options d'interface graphique. La beauté de celles-ci est que vous pouvez passer la souris sur une variable et une décharge de ses données apparaîtra dans une fenêtre appropriée, ou dans une bulle contextuelle, plus besoin de taper laborieusement 'x $nom_var' :-)

En particulier, recherchez les éléments suivants :

ptkdb wrapper basé sur perlTK pour le débogueur intégré

ddd débogueur d'affichage de données

PerlDevKit et PerlBuilder sont spécifiques à NT

NB. (plus d'informations sur ceux-ci et d'autres seraient appréciées).

RÉSUMÉ

Nous avons vu comment encourager de bonnes pratiques de codage avec use strict et -w. Nous pouvons exécuter le débogueur perl perl -d nom_script pour inspecter vos données depuis le débogueur perl avec les commandes p et x. Vous pouvez parcourir votre code, définir des points d'arrêt avec b et parcourir ce code avec s ou n, continuer avec c et revenir d'une sous-routine avec r. Des choses assez intuitives une fois que vous vous y mettez.

Il y a bien sûr beaucoup plus à découvrir, nous n'avons fait qu'effleurer la surface. La meilleure façon d'en apprendre davantage est d'utiliser perldoc pour en savoir plus sur le langage, de lire l'aide en ligne (perldebug est probablement la prochaine étape), et bien sûr, d'expérimenter.
