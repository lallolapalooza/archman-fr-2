NOM

perl5241delta - ce qui est nouveau pour la version perl v5.24.1

DESCRIPTION

Ce document décrit les différences entre la version 5.24.0 et la version 5.24.1.

Si vous mettez à jour à partir d'une version antérieure telle que la 5.22.0, lisez d'abord perl5240delta, qui décrit les différences entre 5.22.0 et 5.24.0.

Sécurité

Le commutateur -Di est maintenant requis pour la sortie de débogage PerlIO

Auparavant, la sortie de débogage PerlIO était envoyée au fichier spécifié par la variable d'environnement "PERLIO_DEBUG" si perl ne fonctionnait pas en mode setuid et si les commutateurs -T ou -t n'avaient pas encore été analysés.

Si perl effectuait une sortie à un moment où il n'avait pas encore analysé ses commutateurs, cela pouvait entraîner la création ou l'écrasement du fichier nommé par "PERLIO_DEBUG" même si le commutateur -T avait été fourni.

Perl exige maintenant le commutateur -Di pour produire une sortie de débogage PerlIO. Par défaut, celle-ci est écrite sur "stderr", mais peut éventuellement être redirigée vers un fichier en définissant la variable d'environnement "PERLIO_DEBUG".

Si perl s'exécute en mode setuid ou si le commutateur -T a été fourni, "PERLIO_DEBUG" est ignoré et la sortie de débogage est envoyée à "stderr", comme pour tout autre commutateur -D.

Les modules et outils principaux ne recherchent plus "." pour les modules optionnels

Les outils et de nombreux modules fournis dans le noyau ne recherchent plus l'entrée du répertoire courant par défaut dans @INC pour les modules optionnels. Par exemple, Storable supprimera le "." final de @INC avant d'essayer de charger Log::Agent.

Cela empêche un attaquant d'injecter un module optionnel dans un processus exécuté par un autre utilisateur, où le répertoire courant est écrivable par l'attaquant, par exemple le répertoire /tmp.

Dans la plupart des cas, cette suppression ne devrait pas causer de problèmes, mais des difficultés ont été rencontrées avec base, qui traite chaque nom de module fourni comme optionnel. Ces difficultés n'ont pas encore été résolues, donc pour cette version, il n'y a pas de changement à base. Nous espérons avoir une correction pour base dans Perl 5.24.2.

Pour protéger votre propre code contre cette attaque, supprimez l'entrée par défaut "." de @INC au début de votre script, donc :

#!/usr/bin/perl
use strict;
...

devient :

#!/usr/bin/perl
BEGIN { pop @INC if $INC[-1] eq '.' }
use strict;
...

ou pour les modules, supprimez "." d'un @INC localisé, donc :

my $can_foo = eval { require Foo; }

devient :

my $can_foo = eval {
    local @INC = @INC;
    pop @INC if $INC[-1] eq '.';
    require Foo;
};

Changements Incompatibles

Outre les changements de sécurité ci-dessus, aucun changement n'est intentionnellement incompatible avec Perl 5.24.0. S'il en existe, il s'agit de bugs, et nous vous prions de bien vouloir soumettre un rapport. Voir "Signalement des bugs" ci-dessous.

•
Le changement apporté à la redirection des shebangs introduit dans Perl 5.24.0, où perl redirigeait vers un autre interpréteur (Perl 6) s'il trouvait un chemin de shebang contenant "perl" suivi de "6", a été annulé car il causait des problèmes dans des cas tels que "#!/opt/perl64/bin/perl".
