PERLAIX(1perl) Guide de référence du programmeur Perl PERLAIX(1perl)

NOM

perlaix - Perl version 5 sur les systèmes IBM AIX (UNIX)

DESCRIPTION

Ce document décrit diverses caractéristiques du système d'exploitation UNIX d'IBM, AIX, qui affecteront la compilation et/ou l'exécution de Perl version 5 (ci-après appelé Perl).

Compilation de Perl 5 sur AIX

Pour des informations sur les compilateurs des anciennes versions d'AIX, voir "Compilation de Perl 5 sur les anciennes versions d'AIX jusqu'à 4.3.3".

Lors de la compilation de Perl, vous devez utiliser un compilateur C ANSI. AIX ne fournit pas par défaut un compilateur C conforme à la norme ANSI, mais des versions binaires de gcc pour AIX sont largement disponibles. Une version de gcc est également incluse dans la boîte à outils AIX livrée avec AIX.

Compilateurs pris en charge

Actuellement, toutes les versions du compilateur C ANSI/C d'IBM, "xlc", "xlc_r", "cc", "cc_r" ou "vac" fonctionneront pour construire Perl si ce compilateur fonctionne sur votre système.

Si vous prévoyez de lier Perl à un module nécessitant un support de threads, comme DBD::Oracle, il est préférable d'utiliser la version _r du compilateur. Cela ne construira pas un Perl threadé, mais un Perl thread-enabled. Voir également "Perl threadé" plus loin.

Au moment de la rédaction (2010-09), seuls les compilateurs IBM XL C for AIX ou IBM XL C/C++ for AIX sont pris en charge par IBM sur AIX 5L/6.1/7.1.

Les versions de compilateurs suivantes sont actuellement prises en charge par IBM:

IBM XL C et IBM XL C/C++ V8, V9, V10, V11

XL C for AIX est intégré dans le compilateur XL C/C++ for AIX et est donc également pris en charge.

Si vous choisissez XL C/C++ V9, vous avez besoin de l'APAR IZ35785 installé, sinon SDBM_File intégré ne compile pas correctement en raison d'un bug d'optimisation. Vous pouvez contourner ce problème en ajoutant -qipa aux indicateurs d'optimisation (-Doptimize='-O -qipa'). Le PTF pour l'APAR IZ35785 qui résout ce problème est disponible auprès d'IBM (PTF d'avril 2009 pour XL C/C++ Enterprise Edition pour AIX, V9.0).

Si vous choisissez XL C/C++ V11, vous avez besoin du PTF d'avril 2010 (ou plus récent) installé, sinon vous n'obtiendrez pas une version fonctionnelle de Perl.

Perl peut être compilé avec le compilateur C ANSI d'IBM ou avec gcc. Le premier est recommandé, car il peut non seulement compiler Perl sans difficulté, mais aussi tirer parti des fonctionnalités listées plus loin qui nécessitent l'utilisation d'options de ligne de commande spécifiques au compilateur IBM.

Si vous décidez d'utiliser gcc, assurez-vous que votre installation est récente et complète, et lisez le fichier INSTALL de Perl pour plus de détails spécifiques à gcc. Veuillez signaler toute difficulté rencontrée à l'équipe de développement.

Incompatibilité avec lib gdbm de la boîte à outils AIX

Si la version 1.8.3-5 ou antérieure de lib gdbm de la boîte à outils AIX est installée sur votre système, Perl ne fonctionnera pas. Cette bibliothèque contient les fichiers d'en-tête /opt/freeware/include/gdbm/dbm.h|ndbm.h qui entrent en conflit avec les versions système d'AIX. lib gdbm sera automatiquement supprimée des bibliothèques demandées si la présence de l'un de ces deux fichiers d'en-tête est détectée. Si vous souhaitez construire Perl avec le support GDBM, veuillez installer au moins gdbm-devel-1.8.3-5 (ou une version supérieure).

Construction d'extensions dynamiques sur AIX

À partir de Perl 5.7.2 (et par conséquent 5.8.x / 5.10.x / 5.12.x) et AIX 4.3 ou plus récent, Perl utilise l'interface de chargement dynamique native d'AIX en mode de liaison d'exécution (runtime linking) au lieu de l'interface émulée utilisée dans les versions de Perl 5.6.1 et antérieures, ou pour les versions AIX 4.2 et antérieures. Ce changement casse la compatibilité ascendante avec les modules compilés des versions Perl antérieures. Le changement a été effectué pour rendre Perl plus conforme aux autres applications comme Apache/mod_perl qui utilisent l'interface native d'AIX. Ce changement permet également l'utilisation de code C++ avec des constructeurs et destructeurs statiques dans les extensions Perl, ce qui n'était pas possible avec l'interface émulée.

Il est fortement recommandé d'utiliser la nouvelle interface.

Utilisation de grands fichiers avec Perl

Ne devrait poser aucun problème.

Perl threadé

Ne devrait poser aucun problème avec AIX 5.1 / 5.2 / 5.3 / 6.1 / 7.1.

IBM utilise le Perl système AIX (V5.6.0 sur AIX 5.1 et V5.8.2 sur AIX 5.2 / 5.3 et 6.1; V5.8.8 sur AIX 5.3 TL11 et AIX 6.1 TL4; V5.10.1 sur AIX 7.1) pour certains scripts système AIX. Si vous changez les liens dans /usr/bin du Perl système AIX (/usr/opt/perl5) vers le Perl nouvellement construit, vous obtiendrez les mêmes fonctionnalités qu'avec le Perl système IBM AIX si les options threadées sont utilisées.

La construction de Perl threadé fonctionne également sur AIX 5.1, mais la construction Perl IBM (Perl v5.6.0) n'est pas threadée sur AIX 5.1.

Perl 5.12 et versions ultérieures n'est pas compatible avec le fichier d'installation IBM perl.libext.

Perl 64 bits

Si votre système AIX est installé avec le support 64 bits, vous pouvez vous attendre à ce que les configurations 64 bits fonctionnent. Si vous souhaitez utiliser Perl 64 bits sur AIX 6.1, vous avez besoin d'un APAR pour un bug de libc.a qui affecte les fonctions (n)dbm_XXX. Le numéro d'APAR pour ce problème est IZ39077.

Si vous avez besoin de plus de mémoire (segment de données plus grand) pour vos programmes Perl, vous pouvez définir:

/etc/security/limits
default:                    (ou votre utilisateur)
    data = -1               (par défaut 262144 * 512 octets)

Avec le réglage par défaut, la taille est limitée à 128 Mo. Le -1 supprime cette limite. Si "make test" échoue, veuillez modifier votre /etc/security/limits comme indiqué ci-dessus.

Doubles longs

IBM appelle son implémentation des doubles longs 128 bits, mais ce n'est pas la norme IEEE 128 bits ("précision quadruple") qui donnerait 116 bits de mantisse (ni n'est implémentée matériellement), c'est plutôt une implémentation logicielle spéciale appelée "double-double", qui donne 106 bits de mantisse.

Il semble y avoir divers problèmes dans cette implémentation des doubles longs. Si Configure détecte cette défaillance, il désactivera le support des doubles longs. Cela peut être outrepassé avec "-Duselongdouble" (ou "-Dusemorebits", qui active à la fois les doubles longs et les entiers 64 bits). Si vous décidez d'activer les doubles longs, la plupart des dysfonctionnements pour lesquels Perl a implémenté des contournements sont gérés, mais la gestion des valeurs spéciales infini et NaN reste gravement défaillante: par exemple, infini plus zéro donne NaN.

Options recommandées AIX 5.1/5.2/5.3/6.1 et 7.1 (thr

Utilisez les options suivantes avec le script Configure.

Afin de prendre en charge les modules qui nécessitent des threads, il est recommandé d'utiliser les options suivantes:

Configure -Duseshrplib -Dusemallocng -Duseithreads -A extensions=Storable,SDBM_File,Sys::Servent,DB_File

Si vous ne souhaitez pas utiliser les threads, utilisez simplement:

Configure -Duseshrplib -Dusemallocng -A extensions=Storable,SDBM_File,Sys::Servent,DB_File

Les options suivantes sont également recommandées pour la compilation de Perl sur AIX:

  • -Duseshrplib : Construit Perl comme une bibliothèque partagée. Ceci est obligatoire pour que les modules dynamiques s'exécutent.
  • -Dusemallocng : Utilise la nouvelle implémentation d'allocateur mémoire de Perl, qui est généralement plus rapide que l'implémentation par défaut d'AIX.
  • -Duseithreads : Active le support des threads. Requis pour les extensions threadées.
  • -Dprefix=/usr/local : Installe Perl et ses modules dans /usr/local.

Note: si vous utilisez les options -Duseshrplib et -Duseithreads ensemble, vous devrez installer les bibliothèques de développement IBM AIX Threads avant de pouvoir compiler Perl. Ces bibliothèques sont fournies sur CD dans le kit de développement AIX.

Si vous n'avez pas les bibliothèques de développement IBM AIX Threads, vous pouvez toujours construire Perl sans support de threads. Dans ce cas, omettez simplement l'option -Duseithreads.

Pour compiler Perl, suivez ces étapes:

  1. Téléchargez le code source de Perl depuis le site Web de CPAN.
  2. Extrayez le code source: tar xzf perl-X.XX.tar.gz
  3. Accédez au répertoire source: cd perl-X.XX
  4. Configurez la construction: sh Configure -Duseshrplib -Dusemallocng -Duseithreads -A extensions=Storable,SDBM_File,Sys::Servent,DB_File -Dprefix=/usr/local
  5. Compilez Perl: make
  6. Testez la construction: make test
  7. Installez Perl: make install

Ces étapes construiront et installeront Perl dans /usr/local avec le support des threads et des bibliothèques partagées.

Options recommandées AIX 5.1/5.2/5.3/6.1 et 7.1 (threadé/32 bits)

Avec les options suivantes, vous obtenez une version Perl threadée qui réussit tous les tests de compilation en mode threadé 32 bits, ce qui est la configuration par défaut pour les compilations Perl fournies avec AIX.

rm config.sh
./Configure \
-d \
-Dcc=cc_r \
-Duseshrplib \
-Dusethreads \
-Dprefix=/usr/opt/perl5_32

L'option -Dprefix installera Perl dans un répertoire parallèle à l'installation Perl système d'IBM AIX.

Compilation de Perl 5 sur AIX 7.1.0

Une régression dans AIX 7 provoque un échec dans les tests de compilation de Time::Piece pendant l'heure d'été. L'APAR IV16514 fournit le correctif pour cela. Un test rapide pour voir si c'est nécessaire, en supposant qu'il fasse actuellement l'heure d'été dans le fuseau horaire de l'Est, consisterait à exécuter " TZ=EST5 date +%Z ". Cela renverra normalement "EST", mais rien si vous avez le problème.

Niveau du système d'exploitation

Avant d'installer les correctifs du compilateur C d'IBM, vous devez connaître le niveau de correction du système d'exploitation. La commande 'oslevel' d'IBM affichera la base, mais n'est pas toujours complète (dans cet exemple, oslevel affiche 4.3.NULL, alors que le système pourrait exécuter la majeure partie de 4.3.THREE) :

Compilation d'extensions dynamiques sur AIX < 5L

AIX prend en charge les objets chargeables dynamiquement ainsi que les bibliothèques partagées. Les bibliothèques partagées, par convention, se terminent par le suffixe .a, ce qui est un peu trompeur, car une archive peut contenir des membres statiques ainsi que dynamiques. Pour les objets chargés dynamiquement de Perl, nous utilisons le suffixe .so également utilisé sur de nombreuses autres plateformes.

Notez qu'à partir de Perl 5.7.2 (et par conséquent 5.8.0) et d'AIX 4.3 ou plus récent, Perl utilise l'interface de chargement dynamique native d'AIX dans le mode dit de liaison à l'exécution, au lieu de l'interface émulée qui était utilisée dans les versions de Perl 5.6.1 et antérieures, ou, pour les versions d'AIX 4.2 et antérieures. Ce changement rompt la compatibilité ascendante avec les modules compilés des versions antérieures de Perl. Le changement a été effectué pour rendre Perl plus conforme avec d'autres applications comme Apache/mod_perl qui utilisent l'interface native d'AIX. Ce changement permet également l'utilisation de code C++ avec des constructeurs et destructeurs statiques dans les extensions Perl, ce qui n'était pas possible en utilisant l'interface émulée.

L'option usenm

Si la liaison de miniperl

cc -o miniperl ... miniperlmain.o opmini.o perl.o ... -lm -lc ...

provoque une erreur comme celle-ci

vous pouvez réessayer avec

En relation avec cela, vous ne devriez probablement pas utiliser l'option "-r" de Configure sous AIX, car cela affecte la manière dont l'outil "nm" est utilisé.

Utiliser gcc de GNU pour compiler Perl

L'utilisation de gcc-3.x (testé avec 3.0.4, 3.1 et 3.2) fonctionne maintenant sans configuration supplémentaire, tout comme les versions récentes de gcc-2.9 disponibles directement auprès d'IBM dans le cadre de leurs packages de compatibilité Linux, disponibles ici :

http://www.ibm.com/servers/aix/products/aixos/linux/

Utiliser les grands fichiers avec Perl < 5L

Ne devrait poser aucun problème.

Perl threadé < 5L

Les threads semblent fonctionner correctement, bien qu'à l'heure actuelle tous les tests ne passent pas lorsque les threads sont utilisés en combinaison avec des configurations 64 bits.

Vous pouvez recevoir un avertissement lors d'une compilation threadée :

"pp_sys.c", ligne 4640.39 : 1506-280 (W) L'affectation d'arguments de fonction 
entre types "unsigned char*" et "const void*" n'est pas autorisée.

Le numéro de ligne exact peut varier, mais si l'avertissement (W) provient d'une ligne comme celle-ci

hent = PerlSock_gethostbyaddr(addr, (Netdb_hlen_t) addrlen, addrtype);

dans la fonction "pp_ghostent", vous pouvez l'ignorer sans risque. L'avertissement est causé par la variante réentrante de gethostbyaddr() ayant un prototype légèrement différent de sa variante non réentrante, mais la différence n'est pas vraiment significative ici.

Perl 64 bits < 5L

Si votre AIX est installé avec le support 64 bits, vous pouvez vous attendre à ce que les configurations 64 bits fonctionnent. En combinaison avec les threads, certains tests pourraient encore échouer.

AIX 4.2 et extensions utilisant C++ avec des statics

Dans AIX 4.2, les extensions Perl qui utilisent des fonctions C++ utilisant des variables statiques peuvent avoir des problèmes car les statiques ne sont pas initialisées. Dans les versions plus récentes d'AIX, cela a été résolu en liaison Perl avec la bibliothèque libC_r, mais malheureusement dans AIX 4.2, ladite bibliothèque a un bug obscur où les différentes fonctions liées au temps (telles que time() et gettimeofday()) retournent des valeurs erronées, et par conséquent sous AIX 4.2, Perl n'est pas lié à la libC_r.
