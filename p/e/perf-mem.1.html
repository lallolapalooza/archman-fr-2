NOM

perf-mem - Profiler les accès mémoire

SYNTAXE

perf mem [<options>] (record [<commande>] | report)

DESCRIPTION

"perf mem record" exécute une commande et recueille des données d'opérations mémoire à partir de celle-ci, dans perf.data. Les options de perf record sont acceptées et transmises.

"perf mem report" affiche le résultat. Il appelle perf report avec les bonnes options pour afficher un profil d'accès mémoire. Par défaut, les chargements et les stockages sont échantillonnés. Utilisez l'option -t pour limiter aux chargements ou aux stockages.

Notez que sur les systèmes Intel, la latence mémoire rapportée est la latence d'utilisation, et non la latence de chargement (ou de stockage) pure. La latence d'utilisation inclut les retards de file d'attente du pipeline en plus de la latence du sous-système mémoire.

Sur Arm64, ceci utilise SPE pour échantillonner les opérations de chargement et de stockage, par conséquent un support matériel et noyau est requis. Voir perf-arm-spe(1) pour un guide de configuration. En raison de la nature statistique de l'échantillonnage SPE, toutes les opérations mémoire ne seront pas échantillonnées.

Sur AMD, ceci utilise le PMU IBS Op pour échantillonner les opérations de chargement-stockage.

OPTIONS COMMUNES

-f, --force

Ne pas faire de validation de propriété

-t, --type=<type>

Sélectionner le type d'opération mémoire : load ou store (défaut : load,store)

-v, --verbose

Être plus verbeux (afficher les erreurs d'ouverture de compteur, etc.)

-p, --phys-data

Enregistrer/Rapporter les adresses physiques des échantillons

--data-page-size

Enregistrer/Rapporter la taille de page de l'adresse de données de l'échantillon

OPTIONS RECORD

<commande>...

Toute commande que vous pouvez spécifier dans un shell.

-e, --event <event>

Sélecteur d'événement. Utilisez perf mem record -e list pour lister les événements disponibles.

-K, --all-kernel

Configurer tous les événements utilisés pour s'exécuter en espace noyau.

-U, --all-user

Configurer tous les événements utilisés pour s'exécuter en espace utilisateur.

--ldlat <n>

Spécifier la latence désirée pour l'événement de chargement. Supporté sur les processeurs Intel, Arm64 et certains AMD. Ignoré sur d'autres architectures. 
Sur les processeurs AMD supportés :
- Le fichier /sys/bus/event_source/devices/ibs_op/caps/ldlat contient '1'.
- Les valeurs de latence supportées sont de 128 à 2048 (inclus).
- Une valeur de latence multiple de 128 entraîne un peu moins de surcharge de profilage
  par rapport aux autres valeurs.
- Le filtrage de la latence de chargement est désactivé par défaut.

OPTIONS REPORT

-i, --input=<file>

Nom du fichier d'entrée.

-C, --cpu=<cpu>

Surveiller uniquement sur la liste des CPUs fournie. Plusieurs CPUs peuvent être fournis sous forme de liste séparée par des virgules sans espace : 0,1. Les plages de CPUs sont spécifiées avec - comme 0-2. Par défaut, tous les CPUs sont surveillés.

-D, --dump-raw-samples

Afficher les échantillons bruts décodés à l'écran dans un format facile à analyser, avec un échantillon par ligne.

-s, --sort=<key>

Grouper le résultat par clé(s) donnée(s) - plusieurs clés peuvent être spécifiées au format CSV. Les clés spécifiques aux échantillons mémoire sont : symbol_daddr, symbol_iaddr, dso_daddr, locked, tlb, mem, snoop, dcacheline, phys_daddr, data_page_size, blocked.
•symbol_daddr : nom du symbole de données sur lequel l'exécution a lieu au moment de l'échantillon
•symbol_iaddr : nom du symbole de code sur lequel l'exécution a lieu au moment de l'échantillon
•dso_daddr : nom de la bibliothèque ou du module contenant les données sur lesquelles l'exécution a lieu au moment de l'échantillon
•locked : si le bus était verrouillé au moment de l'échantillon
•tlb : type d'accès TLB pour les données au moment de l'échantillon
•mem : type d'accès mémoire pour les données au moment de l'échantillon
•snoop : type de snoop (le cas échéant) pour les données au moment de l'échantillon
•dcacheline : la ligne de cache sur laquelle se trouve l'adresse de données au moment de l'échantillon
•phys_daddr : adresse physique des données sur lesquelles l'exécution a lieu au moment de l'échantillon
•data_page_size : la taille de page des données sur lesquelles l'exécution a lieu au moment de l'échantillon
•blocked : raison du blocage de l'accès en lecture pour les données au moment de l'échantillon 
Et les clés de tri par défaut sont modifiées pour : local_weight, mem, sym, dso,
symbol_daddr, dso_daddr, snoop, tlb, locked, blocked, local_ins_lat.

-F, --fields=

Spécifier le champ de sortie - plusieurs clés peuvent être spécifiées au format CSV. Veuillez consulter perf-report(1) pour les détails. 
En plus des champs par défaut, 'perf mem report' fournira les
champs suivants pour décomposer les périodes d'échantillonnage.
•op : opération dans l'instruction de l'échantillon (load, store, prefetch, ...)
•cache : emplacement dans le cache CPU (L1, L2, ...) où l'échantillon a frappé
•mem : emplacement en mémoire ou autres endroits où l'échantillon a frappé
•dtlb : emplacement dans le TLB de données (L1, L2) où l'échantillon a frappé
•snoop : résultat du snoop pour l'accès aux données échantillonné 
Veuillez jeter un œil à la section OUTPUT FIELD SELECTION pour les mises en garde.

-T, --type-profile

Afficher le résultat du profil de type de données au lieu des symboles de code. Cela nécessite les informations de débogage et modifiera les clés de tri par défaut : mem, snoop, tlb, type.

-U, --hide-unresolved

Afficher uniquement les entrées résolues à un symbole.

-x, --field-separator=<separator>

Spécifier le séparateur de champ utilisé lors du vidage des échantillons bruts (option -D). Par défaut, le séparateur est l'espace.

De plus, pour report, toutes les options de perf report sont valides, et pour record, toutes les options de perf record sont valides.

CALCUL DE LA SURCHARGE

Contrairement à perf-report(1), qui calcule la surcharge à partir de la période d'échantillon réelle, la surcharge de perf-mem est calculée en utilisant le poids de l'échantillon. Par exemple, il y a deux échantillons dans le fichier perf.data, tous deux avec la même période d'échantillon, mais un échantillon avec un poids de 180 et l'autre avec un poids de 20 :

$ perf script -F period,data_src,weight,ip,sym
100000    629080842 |OP LOAD|LVL L3 hit|...     20       7e69b93ca524 strcmp
100000   1a29081042 |OP LOAD|LVL RAM hit|...   180   ffffffff82429168 memcpy
$ perf report -F overhead,symbol
50%   [.] strcmp
50%   [k] memcpy
$ perf mem report -F overhead,symbol
90%   [k] memcpy
10%   [.] strcmp

SELECTION DES CHAMPS DE SORTIE

"perf mem report" ajoute un certain nombre de nouveaux champs de sortie spécifiques aux informations de source de données dans l'échantillon. Certains d'entre eux ont le même nom que les clés de tri existantes ("mem" et "snoop"). Ainsi, contrairement aux autres champs et clés de tri, ils se comporteront différemment lorsqu'ils sont utilisés par -F/--fields ou -s/--sort.

Utiliser ces deux-là comme champs de sortie agrègera tous les échantillons et affichera la répartition.

$ perf mem report -F mem,snoop
...
# ------ Memory -------  --- Snoop ----
#     RAM Uncach  Other     HitM  Other
# .....................  ..............
#
     3.5%   0.0%  96.5%    25.1%  74.9%

Mais l'utilisation du même nom pour les clés de tri agrègera les échantillons pour chaque type séparément.

$ perf mem report -s mem,snoop
# Overhead       Samples  Memory access                            Snoop
# ........  ............  .......................................  ............
#
    47.99%          1509  L2 hit                                   N/A
    25.08%           338  core, same node Any cache hit            HitM
    10.24%         54374  N/A                                      N/A
     6.77%         35938  L1 hit
