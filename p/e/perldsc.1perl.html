PERLDSC(1perl) Guide du programmeur Perl PERLDSC(1perl)

NOM

perldsc - Manuel des structures de données Perl

DESCRIPTION

Perl permet d'avoir des structures de données complexes. Vous pouvez écrire quelque chose comme ceci et tout à coup, vous auriez un tableau à trois dimensions !

for my $x (1 .. 10) {
    for my $y (1 .. 10) {
        for my $z (1 .. 10) {
            $AoA[$x][$y][$z] =
                $x ** $y + $z;
        }
    }
}

Hélas, même si cela peut paraître simple, c'est en réalité une construction beaucoup plus élaborée qu'il n'y paraît !

Comment l'imprimer ? Pourquoi ne pouvez-vous pas simplement dire "print @AoA" ? Comment le trier ? Comment peut-on le passer à une fonction ou en récupérer un de ces tableaux à partir d'une fonction ? Est-ce un objet ? Peut-on l'enregistrer sur disque pour le lire plus tard ? Comment accéder à des lignes ou des colonnes entières de cette matrice ? Toutes les valeurs doivent-elles être numériques ?

Comme vous le voyez, il est facile de se perdre. Bien qu'une petite partie de la responsabilité de cela puisse être attribuée à l'implémentation basée sur les références, c'est surtout dû à un manque de documentation existante avec des exemples conçus pour les débutants.

Ce document se veut un traitement détaillé mais compréhensible des différents types de structures de données que vous pourriez vouloir développer. Il devrait également servir de manuel d'exemples. Ainsi, lorsque vous aurez besoin de créer l'une de ces structures de données complexes, vous pourrez simplement pincer, voler ou détourner un exemple directement d'ici.

Examinons en détail chacune de ces constructions possibles. Il y a des sections séparées sur chacune des suivantes :

  • tableaux de tableaux
  • hash de tableaux
  • tableaux de hash
  • hash de hash
  • constructions plus élaborées

Mais pour l'instant, examinons les problèmes généraux communs à tous ces types de structures de données.

RÉFÉRENCES

La chose la plus importante à comprendre à propos de toutes les structures de données en Perl — y compris les tableaux multidimensionnels — est que, même si elles peuvent paraître autrement, les @ARRAYs et les %HASHes de Perl sont toutes une dimension interne. Elles ne peuvent contenir que des valeurs scalaires (c'est-à-dire une chaîne, un nombre ou une référence). Elles ne peuvent pas contenir directement d'autres tableaux ou hash, mais contiennent plutôt des *références* à d'autres tableaux ou hash.

Vous ne pouvez pas utiliser une référence à un tableau ou un hash de la même manière qu'un vrai tableau ou hash. Pour les programmeurs C ou C++ peu habitués à distinguer entre les tableaux et les pointeurs vers ceux-ci, cela peut être déroutant. Si c'est le cas, considérez cela comme la différence entre une structure et un pointeur vers une structure.

Vous pouvez (et devriez) lire davantage sur les références dans perlref. Brièvement, les références sont un peu comme des pointeurs qui savent à quoi ils pointent. (Les objets sont aussi une sorte de référence, mais nous n'en aurons pas besoin tout de suite — voire jamais.) Cela signifie que lorsque vous avez quelque chose qui vous ressemble à un accès à un tableau et/ou un hash multidimensionnel, ce qui se passe réellement, c'est que le type de base n'est qu'une entité unidimensionnelle qui contient des références au niveau suivant. C'est juste que vous pouvez l'*utiliser* comme s'il s'agissait d'un tableau bidimensionnel. C'est d'ailleurs la façon dont fonctionnent presque tous les tableaux multidimensionnels en C.

$array[7][12]                       # tableau de tableaux
$array[7]{string}                   # tableau de hash
$hash{string}[7]                    # hash de tableaux
$hash{string}{'another string'}     # hash de hash

Maintenant, puisque le niveau supérieur ne contient que des références, si vous essayez d'imprimer votre tableau avec une simple fonction print(), vous obtiendrez quelque chose qui n'est pas très joli, comme ceci :

  my @AoA = ( [2, 3], [4, 5, 7], [0] );
  print $AoA[1][2];
7
  print @AoA;
ARRAY(0x83c38)ARRAY(0x8b194)ARRAY(0x8b1d0)

C'est parce que Perl ne déréférence jamais implicitement vos variables. Si vous voulez accéder à l'élément auquel une référence pointe, vous devez le faire vous-même en utilisant soit des indicateurs de type préfixés, comme "${$blah}", "@{$blah}", "@{$blah[$i]}", soit des flèches de pointeur postfixées, comme "$arr->[3]", "$hash->{fred}", ou même "$obj->method()->[3]".

ERREURS COMMUNES

Les deux erreurs les plus courantes lors de la construction d'un tableau de tableaux sont de compter accidentellement le nombre d'éléments ou de prendre une référence au même emplacement mémoire de manière répétée. Voici le cas où vous obtenez juste le compte au lieu d'un tableau imbriqué :

for my $i (1..10) {
    my @array = somefunc($i);
    $AoA[$i] = @array;      # INCORRECT !
}

C'est juste le cas simple d'assignation d'un tableau à un scalaire et d'obtention de son nombre d'éléments. Si c'est ce que vous voulez vraiment, vous pourriez envisager d'être un peu plus explicite à ce sujet, comme ceci :

for my $i (1..10) {
    my @array = somefunc($i);
    $counts[$i] = scalar @array;
}

Voici le cas de la prise d'une référence au même emplacement mémoire encore et encore :

# Soit sans strict, soit avec une déclaration my @array;
# dans une portée extérieure.
for my $i (1..10) {
    @array = somefunc($i);
    $AoA[$i] = \@array;     # INCORRECT !
}

Alors, quel est le gros problème avec ça ? Ça a l'air correct, n'est-ce pas ? Après tout, je vous ai juste dit que vous aviez besoin d'un tableau de références, donc par tous les diables, vous m'en avez fait un !

Malheureusement, même si c'est vrai, c'est toujours cassé. Toutes les références dans @AoA font référence au *même* endroit, et elles contiendront donc toutes ce qui était en dernier dans @array ! C'est similaire au problème démontré dans le programme C suivant :

#include <pwd.h>
main() {
    struct passwd *getpwnam(), *rp, *dp;
    rp = getpwnam("root");
    dp = getpwnam("daemon");
    printf("daemon name is %s\nroot name is %s\n",
            dp->pw_name, rp->pw_name);
}

Qui affichera

daemon name is daemon
root name is daemon

Le problème est que "rp" et "dp" font tous deux référence au même emplacement mémoire ! En C, vous devriez vous souvenir de faire un malloc() pour vous-même pour obtenir de la nouvelle mémoire. En Perl, vous voudrez utiliser le constructeur de tableau "[]" ou le constructeur de hash "{}" à la place. Voici la bonne façon de faire les fragments de code incorrects précédents :

# Soit sans strict, soit avec une déclaration my @array;
# dans une portée extérieure.
for my $i (1..10) {
    @array = somefunc($i);
    $AoA[$i] = [ @array ];
}

Les crochets créent une référence à un nouveau tableau avec une *copie* de ce qui se trouve dans @array au moment de l'assignation. C'est ce que vous voulez.

Notez que cela produira quelque chose de similaire :

# Soit sans strict, soit avec une déclaration my @array;
# dans une portée extérieure.
for my $i (1..10) {
    @array = 0 .. $i;
    $AoA[$i]->@* = @array;
}

Est-ce pareil ? Eh bien, peut-être — et peut-être pas. La subtile différence est que lorsque vous assignez quelque chose entre crochets, vous savez avec certitude qu'il s'agit toujours d'une nouvelle référence avec une nouvelle *copie* des données. Autre chose pourrait se passer dans ce nouveau cas avec la déréférenciation "$AoA[$i]->@*" du côté gauche de l'assignation. Tout dépend si $AoA[$i] était indéfini au départ, ou s'il contenait déjà une référence. Si vous aviez déjà rempli @AoA avec des références, comme dans

$AoA[3] = \@another_array;

Alors l'assignation avec l'indirection du côté gauche utiliserait la référence existante qui était déjà là :

$AoA[3]->@* = @array;

Bien sûr, cela aurait pour effet "intéressant" d'écraser @another_array. (Avez-vous déjà remarqué que quand un programmeur dit que quelque chose est "intéressant", cela signifie plutôt qu'"intrigant" qu'il veut dire, mais qu'il veut plutôt dire que c'est "agaçant", "difficile", ou les deux ? :-)

Donc, souvenez-vous toujours d'utiliser les constructeurs de tableaux ou de hash avec "[]" ou "{}", et tout ira bien, bien que ce ne soit pas toujours optimal en termes d'efficacité.

Étonnamment, la construction suivante, qui semble dangereuse, fonctionnera en fait correctement :

for my $i (1..10) {
    my @array = somefunc($i);
    $AoA[$i] = \@array;
}

Si le dernier élément qui était dans @array n'a pas été écrasé par quelque chose d'autre par la suite, ce code devrait fonctionner comme prévu. Comme vous pouvez vous y attendre, les inconvénients de ceci sont bien sûr que vous n'avez qu'une seule copie de la mémoire (ce qui peut être une bonne chose pour l'efficacité en mémoire, mais une mauvaise chose pour l'indépendance des données) et que l'utilisation de tableaux et de hashs imbriqués devient plus difficile.

THE « my() » OPERATOR

C'est parce que my() est davantage une instruction d'exécution qu'une déclaration de compilation en soi. Cela signifie que la variable my() est recréée à chaque passage dans la boucle. Donc, même si vous semblez avoir stocké la même référence de variable à chaque fois, ce n'est en fait pas le cas ! C'est une distinction subtile qui peut produire un code plus efficace au risque de tromper tous les programmeurs sauf les plus expérimentés. Je déconseille donc généralement de l'enseigner aux débutants. En fait, à l'exception du passage d'arguments à des fonctions, j'aime rarement voir l'opérateur « donne-moi-une-référence » (antislash) beaucoup utilisé dans le code. À la place, je conseille aux débutants qu'ils (et la plupart des autres) devraient essayer d'utiliser les constructeurs beaucoup plus faciles à comprendre "[]" et "{}" au lieu de s'appuyer sur la portée lexicale (ou dynamique) et le comptage de références caché pour faire la bonne chose en arrière-plan.

Notez également qu'il existe une autre façon d'écrire un déréférencement ! Ces deux lignes sont équivalentes :

$AoA[$i]->@* = @array;
@{ $AoA[$i] } = @array;

La première forme, appelée déréférencement postfixe, est généralement plus facile à lire, car l'expression peut être lue de gauche à droite, et il n'y a pas d'accolades englobantes à équilibrer. D'un autre côté, elle est aussi plus récente. Elle a été ajoutée au langage en 2014, vous rencontrerez donc souvent l'autre forme, déréférencement circumfixe, dans du code plus ancien.

En résumé :

$AoA[$i] = [ @array ];     # généralement le meilleur
$AoA[$i] = \@array;        # périlleux ; comment my() était ce tableau ?
$AoA[$i]->@* = @array;     # bien trop compliqué pour la plupart des programmeurs
@{ $AoA[$i] } = @array;    # tout aussi compliqué, et aussi plus difficile à lire

AVERTISSEMENT SUR LA PRÉCÉDENCE

En parlant de choses comme "@{$AoA[$i]}", les éléments suivants sont en réalité la même chose :

$aref->[2][2]       # clair
$$aref[2][2]        # déroutant

C'est parce que les règles de précédence de Perl sur ses cinq déréférenciateurs préfixes (qui ressemblent à quelqu'un jurant : "$ @ * % &") les font se lier plus fortement que les crochets ou les accolades d'indexation postfixes ! Cela sera sans aucun doute un grand choc pour le programmeur C ou C++, qui est tout à fait habitué à utiliser *a[i] pour désigner ce qui est pointé par le i-ème élément de "a". C'est-à-dire, ils prennent d'abord l'index, puis déréférencent la chose à cet index. C'est bien en C, mais ce n'est pas C.

La construction apparemment équivalente en Perl, $$aref[$i], déréférence d'abord $aref, le faisant apparaître comme une référence à un tableau, puis le déréférence, et enfin vous donne la valeur i-ème du tableau pointé par $AoA. Si vous vouliez la notion C, vous pourriez écrire "$AoA[$i]->$*" pour explicitement déréférencer l'élément i-ème, en lisant de gauche à droite.

POURQUOI VOUS DEVRIEZ TOUJOURS « use VERSION »

Si tout cela commence à sembler plus effrayant qu'utile, détendez-vous. Perl possède des fonctionnalités pour vous aider à éviter ses pièges les plus courants. Une façon d'éviter la confusion est de commencer chaque programme par :

use strict;

De cette façon, vous serez obligé de déclarer toutes vos variables avec my() et cela interdira également le « déréférencement symbolique » accidentel. Par conséquent, si vous aviez fait ceci :

my $aref = [
    [ "fred", "barney", "pebbles", "bambam", "dino", ],
    [ "homer", "bart", "marge", "maggie", ],
    [ "george", "jane", "elroy", "judy", ],
];
print $aref[2][2];

Le compilateur signalerait immédiatement cela comme une erreur au moment de la compilation, car vous accédiez accidentellement à @aref, une variable non déclarée, et il vous rappellerait ainsi d'écrire plutôt :

print $aref->[2][2]

Depuis la version 5.12 de Perl, une déclaration "use VERSION" active également le pragma "strict". De plus, elle active un ensemble de fonctionnalités, offrant des fonctionnalités plus utiles. Depuis la version 5.36, elle active également le pragma "warnings". La meilleure façon d'activer toutes ces choses à la fois est souvent de commencer un fichier par :

use v5.36;

De cette façon, chaque fichier commencera par "strict", "warnings", et de nombreuses fonctionnalités nommées utiles activées, ainsi que plusieurs anciennes fonctionnalités désactivées (comme "indirect"). Pour plus d'informations, voir "use VERSION" dans perlfunc.

EXEMPLES DE CODE

Présentés avec peu de commentaires, voici de courts exemples de code illustrant l'accès à divers types de structures de données.

TABLEAUX DE TABLEAUX

Déclaration d'un TABLEAU DE TABLEAUX

my @AoA = (
       [ "fred", "barney" ],
       [ "george", "jane", "elroy" ],
       [ "homer", "marge", "bart" ],
     );

Génération d'un TABLEAU DE TABLEAUX

# lecture depuis un fichier
while ( <> ) {
    push @AoA, [ split ];
}
# appel d'une fonction
for my $i ( 1 .. 10 ) {
    $AoA[$i] = [ somefunc($i) ];
}
# utilisation de variables temporaires
for my $i ( 1 .. 10 ) {
    my @tmp = somefunc($i);
    $AoA[$i] = [ @tmp ];
}
# ajout à une ligne existante
push $AoA[0]->@*, "wilma", "betty";

Accès et impression d'un TABLEAU DE TABLEAUX

# un élément
$AoA[0][0] = "Fred";
# un autre élément
$AoA[1][1] =~ s/(\w)/\u$1/;
# imprimer le tout avec des références
for my $aref ( @AoA ) {
    print "\t [ @$aref ],\n";
}
# imprimer le tout avec des indices
for my $i ( 0 .. $#AoA ) {
    print "\t [ $AoA[$i]->@* ],\n";
}
# imprimer le tout un par un
for my $i ( 0 .. $#AoA ) {
    for my $j ( 0 .. $AoA[$i]->$#* ) {
        print "elem at ($i, $j) is $AoA[$i][$j]\n";
    }
}

TABLEAUX DE HASHES

Déclaration d'un TABLEAU DE HASHES

my %HoA = (
       flintstones        => [ "fred", "barney" ],
       jetsons            => [ "george", "jane", "elroy" ],
       simpsons           => [ "homer", "marge", "bart" ],
     );

Génération d'un TABLEAU DE HASHES

# lecture depuis un fichier
# flintstones: fred barney wilma dino
while ( <> ) {
    next unless s/^(.*?):\s*//;
    $HoA{$1} = [ split ];
}
# lecture depuis un fichier ; plus de temporaires
# flintstones: fred barney wilma dino
while ( my $line = <> ) {
    my ($who, $rest) = split /:\s*/, $line, 2;
    my @fields = split ' ', $rest;
    $HoA{$who} = [ @fields ];
}
# appel d'une fonction qui renvoie une liste
for my $group ( "simpsons", "jetsons", "flintstones" ) {
    $HoA{$group} = [ get_family($group) ];
}
# de même, mais en utilisant des temporaires
for my $group ( "simpsons", "jetsons", "flintstones" ) {
    my @members = get_family($group);
    $HoA{$group} = [ @members ];
}
# ajouter de nouveaux membres à une famille existante
push $HoA{flintstones}->@*, "wilma", "betty";

Accès et impression d'un TABLEAU DE HASHES

# un élément
$HoA{flintstones}[0] = "Fred";
# un autre élément
$HoA{simpsons}[1] =~ s/(\w)/\u$1/;
# imprimer le tout
foreach my $family ( keys %HoA ) {
    print "$family: $HoA{$family}->@* \n"
}
# imprimer le tout avec des indices
foreach my $family ( keys %HoA ) {
    print "family: ";
    foreach my $i ( 0 .. $HoA{$family}->$#* ) {
        print " $i = $HoA{$family}[$i]";
    }
    print "\n";
}
# imprimer le tout trié par nombre de membres
foreach my $family ( sort { $HoA{$b}->@* <=> $HoA{$a}->@* } keys %HoA ) {
    print "$family: $HoA{$family}->@* \n"
}
# imprimer le tout trié par nombre de membres et par nom
foreach my $family ( sort {
                           $HoA{$b}->@* <=> $HoA{$a}->@*
                                         ||
                                     $a cmp $b
           } keys %HoA )
{
    print "$family: ", join(", ", sort $HoA{$family}->@* ), "\n";
}

Déclaration d'un TABLEAU DE HASHES

my @AoH = (
       {
               lead      => "fred",
               "friend"  => "barney",
               wife      => "wilma",
               daughter  => "pebbles",
       },
       {
               lead      => "george",
               wife      => "jane",
               son       => "elroy",
       },
       {
               lead      => "homer",
               wife      => "marge",
               son       => "bart",
       },
);

Génération d'un TABLEAU DE HASHES

# lecture depuis un fichier
# format: LEAD=fred FRIEND=barney
while ( <> ) {
    my $rec = {};
    for my $field ( split ) {
        my ($key, $value) = split /=/, $field;
        $rec->{$key} = $value;
    }
    push @AoH, $rec;
}
# lecture depuis un fichier
# format: LEAD=fred FRIEND=barney
# pas de variable temporaire
while ( <> ) {
    push @AoH, { split /[\s+=]/ };
}
# appel d'une fonction qui retourne une liste de paires clé/valeur, comme
# "lead","fred","daughter","pebbles"
while ( my %fields = getnextpairset() ) {
    push @AoH, { %fields };
}
# idem, mais sans variables temporaires
while (<>) {
    push @AoH, { parsepairs($_) };
}
# ajout d'une clé/valeur à un élément
$AoH[0]{pet} = "dino";
$AoH[2]{pet} = "santa's little helper";

Accès et impression d'un TABLEAU DE HASHES

# un élément
$AoH[0]{lead} = "fred";
# un autre élément
$AoH[1]{lead} =~ s/(\w)/\u$1/;
# imprimer le tout avec des références
for my $href ( @AoH ) {
    print "{ ";
    for my $role ( keys %$href ) {
        print "$role=$href->{$role} ";
    }
    print "}\n";
}
# imprimer le tout avec des indices
for my $i ( 0 .. $#AoH ) {
    print "$i is { ";
    for my $role ( keys $AoH[$i]->%* ) {
        print "$role=$AoH[$i]{$role} ";
    }
    print "}\n";
}
# imprimer le tout un par un
for my $i ( 0 .. $#AoH ) {
    for my $role ( keys $AoH[$i]->%* ) {
        print "elem at ($i, $role) is $AoH[$i]{$role}\n";
    }
}

HASHES DE HASHES

Déclaration d'un HASH DE HASHES

my %HoH = (
       flintstones => {
               lead      => "fred",
               pal       => "barney",
       },
       jetsons     => {
               lead      => "george",
               wife      => "jane",
               "his boy" => "elroy",
       },
       simpsons    => {
               lead      => "homer",
               wife      => "marge",
               kid       => "bart",
       },
);

Génération d'un HASH DE HASHES

# lecture depuis un fichier
# flintstones: lead=fred pal=barney wife=wilma pet=dino
while ( <> ) {
    next unless s/^(.*?):\s*//;
    my $who = $1;
    for my $field ( split ) {
        my ($key, $value) = split /=/, $field;
        $HoH{$who}{$key} = $value;
    }
}
# lecture depuis un fichier; plus de variables temporaires
while ( <> ) {
    next unless s/^(.*?):\s*//;
    my $who = $1;
    my $rec = {};
    $HoH{$who} = $rec;
    for my $field ( split ) {
        my ($key, $value) = split /=/, $field;
        $rec->{$key} = $value;
    }
}
# appel d'une fonction qui retourne une hash clé,valeur
for my $group ( "simpsons", "jetsons", "flintstones" ) {
    $HoH{$group} = { get_family($group) };
}
# idem, mais en utilisant des variables temporaires
for my $group ( "simpsons", "jetsons", "flintstones" ) {
    my %members = get_family($group);
    $HoH{$group} = { %members };
}
# ajout de nouveaux membres à une famille existante
my %new_folks = (
    wife => "wilma",
    pet  => "dino",
);
for my $what (keys %new_folks) {
    $HoH{flintstones}{$what} = $new_folks{$what};
}
# idem, mais en utilisant une tranche de hash
@{ $HoH{flintstones} }{ keys %new_folks } = values %new_folks;
# idem, mais sans variable %new_folks
@{ $HoH{flintstones} }{ "wife", "pet" } = ( "wilma", "dino" );

Accès et impression d'un HASH DE HASHES

# un élément
$HoH{flintstones}{wife} = "wilma";
# un autre élément
$HoH{simpsons}{lead} =~ s/(\w)/\u$1/;
# imprimer le tout
foreach my $family ( keys %HoH ) {
    print "$family: { ";
    for my $role ( keys $HoH{$family}->%* ) {
        print "$role=$HoH{$family}{$role} ";
    }
    print "}\n";
}
# imprimer le tout de manière légèrement triée
foreach my $family ( sort keys %HoH ) {
    print "$family: { ";
    for my $role ( sort keys $HoH{$family}->%* ) {
        print "$role=$HoH{$family}{$role} ";
    }
    print "}\n";
}
# imprimer le tout trié par nombre de membres
foreach my $family ( sort { $HoH{$b}->%* <=> $HoH{$a}->%* } keys %HoH ) {
    print "$family: { ";
    for my $role ( sort keys $HoH{$family}->%* ) {
        print "$role=$HoH{$family}{$role} ";
    }
    print "}\n";
}
# établir un ordre de tri (rang) pour chaque rôle
my $i = 0;
my %rank;
for ( qw(lead wife son daughter pal pet) ) { $rank{$_} = ++$i }
# maintenant imprimer le tout trié par nombre de membres
foreach my $family ( sort { $HoH{$b}->%* <=> $HoH{$a}->%* } keys %HoH ) {
    print "$family: { ";
    # et imprimer ceux-ci selon l'ordre de rang
    for my $role ( sort { $rank{$a} <=> $rank{$b} }
                                              keys $HoH{$family}->%* )
    {
        print "$role=$HoH{$family}{$role} ";
    }
    print "}\n";
}

# attention aux accolades de bloc supplémentaires sur la référence de fh

Génération d'un HASH DE HASHES COMPLEXES

# lecture depuis un fichier
# ceci est plus facilement fait en ayant le fichier lui-même
# dans le format de données brutes comme montré ci-dessus. perl est heureux
# d'analyser des structures de données complexes si elles sont déclarées comme données, donc
# parfois c'est le plus simple à faire
# voici une construction pièce par pièce
my $rec = {};
$rec->{series} = "flintstones";
$rec->{nights} = [ find_days() ];
my @members = ();
# supposer que ce fichier est en syntaxe champ=valeur
while (<>) {
    my %fields = split /[\s=]+/;
    push @members, { %fields };
}
$rec->{members} = [ @members ];
# maintenant se souvenir de l'ensemble
$TV{ $rec->{series} } = $rec;
###########################################################
# maintenant, vous pourriez vouloir créer des champs supplémentaires intéressants qui
# incluent des pointeurs vers la même structure de données, donc si
# vous changez une pièce, cela change partout, comme par exemple
# si vous vouliez un champ {kids} qui est une référence
# vers un tableau des enregistrements des enfants sans avoir de doublons
# enregistrés et donc des problèmes de mise à jour.
###########################################################
foreach my $family (keys %TV) {
    my $rec = $TV{$family}; # pointeur temporaire
    my @kids = ();
    for my $person ( $rec->{members}->@* ) {
        if ($person->{role} =~ /kid|son|daughter/) {
            push @kids, $person;
        }
    }
    # RETENEZ : $rec et $TV{$family} pointent vers les mêmes données !!
    $rec->{kids} = [ @kids ];
}
# vous avez copié le tableau, mais le tableau lui-même contient des pointeurs
# vers des objets non copiés. cela signifie que si vous faites vieillir bart via
$TV{simpsons}{kids}[0]{age}++;
# cela changerait aussi dans
print $TV{simpsons}{members}[2]{age};
# parce que $TV{simpsons}{kids}[0] et $TV{simpsons}{members}[2]
# pointent tous deux vers la même table de hachage anonyme sous-jacente
# imprimer le tout
foreach my $family ( keys %TV ) {
    print "the $family";
    print " is on during $TV{$family}{nights}->@*\n";
    print "its members are:\n";
    for my $who ( $TV{$family}{members}->@* ) {
        print " $who->{name} ($who->{role}), age $who->{age}\n";
    }
    print "it turns out that $TV{$family}{lead} has ";
    print scalar ( $TV{$family}{kids}->@* ), " kids named ";
    print join (", ", map { $_->{name} } $TV{$family}{kids}->@* );
    print "\n";
}

Liens avec les bases de données

Vous ne pouvez pas facilement lier une structure de données multilivello (comme un hash de hashes) à un fichier dbm. Le premier problème est que tous les formats sauf GDBM et Berkeley DB ont des limitations de taille, mais au-delà de cela, vous avez également des problèmes avec la façon dont les références doivent être représentées sur disque. Un module expérimental qui tente partiellement de répondre à ce besoin est le module MLDBM. Consultez votre site CPAN le plus proche comme décrit

perldsc - Perl data structures

Database Ties

This is a brief mention of database ties in Perl, which allow associative arrays (hashes) and arrays to be tied to external data sources, such as databases. The concept is similar to how MLDBM (More Lightweight Database Manager) provides a Perl interface to various database formats. The `DBM_File` module and other tie modules, described in perlmodlib for source code to MLDBM.
