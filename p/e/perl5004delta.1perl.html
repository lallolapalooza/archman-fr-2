PERL5004DELTA(1perl) Guide de référence du programmeur Perl PERL5004DELTA(1perl)

NOM

perl5004delta - nouveautés pour perl5.004

DESCRIPTION

Ce document décrit les différences entre la version 5.003 (telle que documentée dans Programming Perl, deuxième édition - le Livre du Chameau) et celle-ci.

Environnements supportés

Perl5.004 se compile sans problème sous Unix, Plan 9, LynxOS, VMS, OS/2, QNX, AmigaOS et Windows NT. Perl fonctionne également sous Windows 95, mais ne peut pas y être compilé, faute d'interpréteur de commandes raisonnable.

Changements principaux

Plus important encore, de nombreux bugs ont été corrigés, y compris plusieurs problèmes de sécurité. Voir le fichier Changes dans la distribution pour plus de détails.

L'affectation de liste à %ENV fonctionne

"%ENV = ()" et "%ENV = @list" fonctionnent maintenant comme prévu (sauf sur VMS où cela génère une erreur fatale).

Modification de l'erreur "Can't locate Foo.pm in @INC"

L'erreur "Can't locate Foo.pm in @INC" liste maintenant le contenu de @INC pour faciliter le débogage.

Option de compilation : Compatibilité binaire avec 5.003

Il existe une nouvelle question de configuration qui demande si vous souhaitez maintenir la compatibilité binaire avec Perl 5.003. Si vous choisissez la compatibilité binaire, vous n'avez pas à recompiler vos extensions, mais vous pourriez avoir des conflits de symboles si vous intégrez Perl dans une autre application, tout comme dans la version 5.003. Par défaut, la compatibilité binaire est préservée au détriment de la pollution de la table des symboles.

Variable d'environnement $PERL5OPT

Vous pouvez maintenant placer des options Perl dans la variable d'environnement $PERL5OPT. À moins que Perl ne soit exécuté avec des vérifications de taint, il interprétera cette variable comme si son contenu était apparu sur une ligne "#!perl" au début de votre script, à la seule différence que les tirets sont facultatifs. PERL5OPT ne peut être utilisé que pour définir les commutateurs suivants : -[DIMUdmw].

Limitations des options -M, -m et -T

Les options "-M" et "-m" ne sont plus autorisées sur la ligne "#!" d'un script. Si un script a besoin d'un module, il doit l'invoquer avec le pragma "use".

L'option -T est également interdite sur la ligne "#!" d'un script, à moins qu'elle n'ait été présente sur la ligne de commande de Perl. En raison de la façon dont "#!" fonctionne, cela signifie généralement que -T doit être le premier argument. Ainsi :

#!/usr/bin/perl -T -w

fonctionnera probablement pour un script exécutable appelé comme "nom_script", tandis que :

#!/usr/bin/perl -w -T

échouera probablement dans les mêmes conditions. (Les systèmes non-Unix ne suivront probablement pas cette règle.) Mais il est garanti que "perl nom_script" échouera, car il n'y aura alors aucune chance que -T soit trouvé sur la ligne de commande avant d'être trouvé sur la ligne "#!".

Avertissements plus précis

Si vous avez supprimé l'option -w de vos scripts Perl 5.003 parce qu'elle rendait Perl trop verbeux, nous vous recommandons de la remettre lorsque vous mettrez à niveau vers Perl 5.004. Chaque nouvelle version de perl tend à supprimer certains avertissements indésirables, tout en ajoutant de nouveaux avertissements qui peuvent détecter des bugs dans vos scripts.

Déprécié : AUTOLOAD hérité pour les non-méthodes

Avant Perl 5.004, les fonctions "AUTOLOAD" étaient recherchées comme des méthodes (en utilisant la hiérarchie @ISA), même lorsque la fonction à charger automatiquement était appelée comme une fonction simple (par exemple, Foo::bar()), et non comme une méthode (par exemple, "Foo->bar()" ou "$obj->bar()").

Perl 5.005 n'utilisera la recherche de méthode que pour les "AUTOLOAD" des méthodes. Cependant, il existe une base importante de code existant qui peut utiliser l'ancien comportement. Ainsi, comme étape intermédiaire, Perl 5.004 émet un avertissement optionnel lorsqu'un non-méthode utilise un "AUTOLOAD" hérité.

La règle simple est : l'héritage ne fonctionnera pas lors du chargement automatique de non-méthodes. La solution simple pour le code ancien est : Dans tout module qui dépendait de l'héritage de "AUTOLOAD" pour les non-méthodes d'une classe de base nommée "BaseClass", exécutez "*AUTOLOAD = \&BaseClass::AUTOLOAD" au démarrage.

%OVERLOAD précédemment déprécié n'est plus utilisable

L'utilisation de %OVERLOAD pour définir la surcharge était dépréciée en 5.003. La surcharge est maintenant définie à l'aide du pragma overload. %OVERLOAD est toujours utilisé en interne mais ne devrait pas être utilisé par les scripts Perl. Voir overload pour plus de détails.

Les arguments de sous-routine créés seulement lorsqu'ils sont modifiés

Dans Perl 5.004, les éléments de tableau et de hachage inexistants utilisés comme paramètres de sous-routine sont créés uniquement s'ils sont effectivement affectés (via @_).

Les versions antérieures de Perl variaient dans leur gestion de tels arguments. Les versions de Perl 5.002 et 5.003 les créaient toujours. Les versions de Perl 5.000 et 5.001 les créaient uniquement s'ils n'étaient pas le premier argument (ce qui était presque certainement un bug). Les versions antérieures de Perl ne les créaient jamais.

Par exemple, étant donné ce code :

undef @a; undef %a;
sub show { print $_[0] };
sub change { $_[0]++ };
show($a[2]);
change($a{b});

Après l'exécution de ce code dans Perl 5.004, $a{b} existe mais $a[2] n'existe pas. Dans Perl 5.002 et 5.003, $a{b} et $a[2] auraient existé (mais la valeur de $a[2] aurait été indéfinie).

Le vecteur de groupes est modifiable avec $)

La variable spéciale $) a toujours (enfin, au moins dans Perl 5) reflété non seulement le groupe effectif actuel, mais aussi la liste de groupes telle que renvoyée par la fonction C getgroups() (s'il y en a une). Cependant, jusqu'à cette version, il n'y avait aucun moyen d'appeler la fonction C setgroups() depuis Perl.

Dans Perl 5.004, l'affectation à $) est exactement symétrique à son examen : Le premier nombre dans sa valeur de chaîne est utilisé comme gid effectif ; s'il y a d'autres nombres après le premier, ils sont passés à la fonction C setgroups() (s'il y en a une).

Les versions de Perl antérieures à 5.004 interprétaient mal tout marqueur de type suivi de "&lt;code&gt;" et d'un chiffre. Par exemple, "$$0" était incorrectement interprété comme "${$}0" au lieu de "${$0}". Ce bug est (principalement) corrigé dans Perl 5.004.

Cependant, les développeurs de Perl 5.004 n'ont pas pu corriger complètement ce bug, car au moins deux modules largement utilisés dépendent de l'ancienne signification de "$$0" dans une chaîne de caractères. Ainsi, Perl 5.004 interprète toujours "$<chiffre>" de l'ancienne manière (défectueuse) à l'intérieur des chaînes de caractères ; mais il génère ce message comme un avertissement. Et dans Perl 5.005, ce traitement spécial cessera.

Localization corrigée de $<chiffre>, $&, etc.

Les versions de Perl antérieures à 5.004 ne localisaient pas toujours correctement les variables spéciales liées aux expressions régulières. Perl 5.004 les localise, comme la documentation l'a toujours indiqué. Cela peut avoir pour conséquence que $1, $2, etc. ne soient plus définis là où les programmes existants les utilisent.

Pas de réinitialisation de $. lors de la fermeture implicite

La documentation de Perl 5.0 a toujours indiqué que $. n'est *pas* réinitialisé lorsqu'un descripteur de fichier déjà ouvert est rouvert sans appel intermédiaire à close(). En raison d'un bug, les versions de Perl 5.000 à 5.003 réinitialisaient *bien* $. dans cette circonstance ; Perl 5.004 ne le fait pas.

"wantarray" peut renvoyer undef

L'opérateur "wantarray" renvoie vrai si une sous-routine est censée renvoyer une liste, et faux sinon. Dans Perl 5.004, "wantarray" peut également renvoyer la valeur indéfinie si la valeur de retour d'une sous-routine ne sera pas du tout utilisée, ce qui permet aux sous-routines d'éviter un calcul coûteux d'une valeur de retour si elle ne doit pas être utilisée.

"eval EXPR" détermine la valeur d'EXPR dans un contexte scalaire

Perl (version 5) déterminait auparavant la valeur d'EXPR de manière incohérente, utilisant parfois incorrectement le contexte environnant pour la détermination. Désormais, la valeur d'EXPR (avant d'être analysée par eval) est toujours déterminée dans un contexte scalaire. Une fois analysée, elle est exécutée comme précédemment, en fournissant le contexte que le périmètre entourant l'eval fournissait. Ce changement rend le comportement compatible avec Perl4, en plus de corriger les bugs résultant du comportement incohérent. Ce programme :

@a = qw(time now is time);
print eval @a;
print '|', scalar eval @a;

affichait auparavant quelque chose comme "timenowis881399109|4", mais affiche désormais (et dans perl4) "4|4".

Modifications des vérifications de tainting

Un bug dans les versions précédentes pouvait ne pas détecter certaines conditions non sécurisées lorsque les vérifications de tainting sont activées. (Les vérifications de tainting sont utilisées dans les scripts setuid ou setgid, ou lorsqu'elles sont explicitement activées avec l'option d'invocation "-T".) Bien que peu probable, cela pourrait entraîner l'échec d'un script précédemment fonctionnel, ce qui devrait être interprété comme une bénédiction car cela indique qu'un trou de sécurité potentiellement grave vient d'être colmaté.

Les nouvelles restrictions lors du tainting incluent :

Aucun glob() ou <*>
Ces opérateurs peuvent lancer le shell C (csh), qui ne peut pas être rendu sûr. Cette restriction sera levée dans une future version de Perl lorsque le globbing sera implémenté sans utiliser de programme externe.
Aucun lancement si $CDPATH, $ENV, $BASH_ENV sont taintés
Ces variables d'environnement peuvent altérer le comportement des programmes lancés (en particulier les shells) d'une manière qui compromet la sécurité. Elles sont donc désormais traitées comme dangereuses, à la manière de $IFS et $PATH.
Aucun lancement si $TERM tainté ne ressemble pas à un nom de terminal
Certaines bibliothèques termcap font des choses dangereuses avec $TERM. Cependant, il serait inutilement sévère de traiter toutes les valeurs de $TERM comme dangereuses, car seuls les métacaractères du shell peuvent causer des problèmes dans $TERM. Ainsi, un $TERM tainté est considéré comme sûr s'il ne contient que des caractères alphanumériques, des tirets bas, des tirets et des deux-points, et dangereux s'il contient d'autres caractères (y compris des espaces).

Syntaxe nouvelle et modifiée

Une référence de sous-routine peut désormais être suffixée par une flèche et une liste de paramètres (éventuellement vide). Cette syntaxe désigne un appel à la sous-routine référencée, avec les paramètres donnés (le cas échéant).

New conversions and flags in sprintf()

sprintf() conversions and flags
Perl's sprintf() function has new conversions and flags.

The new conversions in Perl's sprintf() are:

%i   a synonym for %d
%p   a pointer (the address of the Perl value, in hexadecimal)
%n   special: *stores* the number of characters output so far
     into the next variable in the parameter list

The new flags that go between the "%" and the conversion are:

#    prefix octal with "0", hex with "0x"
h    interpret integer as C type "short" or "unsigned short"
V    interpret integer as Perl's standard integer type

Also, where a number would appear in the flags, an asterisk ("*") may be used instead, in which case Perl uses the next item in the parameter list as the given number (that is, as the field width or precision). If a field width obtained through "*" is negative, it has the same effect as the '-' flag: left-justification.

See "sprintf" in perlfunc for a complete list of conversion and flags.

keys as an lvalue
As an lvalue, "keys" allows you to increase the number of hash buckets allocated for the given hash. This can gain you a measure of efficiency if you know the hash is going to get big. (This is similar to pre-extending an array by assigning a larger number to $#array.) If you say 
keys %hash = 200;

then %hash will have at least 200 buckets allocated for it. These buckets will be retained even if you do "%hash = ()"; use undef %hash if you want to free the storage while %hash is still in scope. You can't shrink the number of buckets allocated for the hash using "keys" in this way (but you needn't worry about doing this by accident, as trying has no effect).

my() in Control Structures
You can now use my() (with or without the parentheses) in the control expressions of control structures such as: 
while (defined(my $line = <>)) {
    $line = lc $line;
} continue {
    print $line;
}
if ((my $answer = <STDIN>) =~ /^y(es)?$/i) {
    user_agrees();
} elsif ($answer =~ /^n(o)?$/i) {
    user_disagrees();
} else {
    chomp $answer;
    die "`$answer' is neither `yes' nor `no'";
}

Also, you can declare a foreach loop control variable as lexical by preceding it with the word "my". For example, in:

foreach my $i (1, 2, 3) {
    some_function();
}

$i is a lexical variable, and the scope of $i extends to the end of the loop, but not beyond it.

Note that you still cannot use my() on global punctuation variables such as $_ and the like.

pack() and unpack()
A new format 'w' represents a BER compressed integer (as defined in ASN.1). Its format is a sequence of one or more bytes, each of which provides seven bits of the total value, with the most significant first. Bit eight of each byte is set, except for the last byte, in which bit eight is clear.

If 'p' or 'P' are given undef as values, they now generate a NULL pointer.

Both pack() and unpack() now fail when their templates contain invalid types. (Invalid types used to be ignored.)

sysseek()
The new sysseek() operator is a variant of seek() that sets and gets the file's system read/write position, using the lseek(2) system call. It is the only reliable way to seek before using sysread() or syswrite(). Its return value is the new position, or the undefined value on failure.
use VERSION
If the first argument to "use" is a number, it is treated as a version number instead of a module name. If the version of the Perl interpreter is less than VERSION, then an error message is printed and Perl exits immediately. Because "use" occurs at compile time, this check happens immediately during the compilation process, unlike "require VERSION", which waits until runtime for the check. This is often useful if you need to check the current Perl version before "use"ing library modules which have changed in incompatible ways from older versions of Perl. (We try not to do this more than we have to.)
use Module VERSION LIST
If the VERSION argument is present between Module and LIST, then the "use" will call the VERSION method in class Module with the given version as an argument. The default VERSION method, inherited from the UNIVERSAL class, croaks if the given version is larger than the value of the variable $Module::VERSION. (Note that there is not a comma after VERSION!)

This version-checking mechanism is similar to the one currently used in the Exporter module, but it is faster and can be used with modules that don't use the Exporter. It is the recommended method for new code.

srand
The default seed for "srand", which used to be "time", has been changed. Now it's a heady mix of difficult-to-predict system-dependent values, which should be sufficient for most everyday purposes.

Previous to version 5.004, calling "rand" without first calling "srand" would yield the same sequence of random numbers on most or all machines. Now, when perl sees that you're calling "rand" and haven't yet called "srand", it calls "srand" with the default seed. You should still call "srand" manually if your code might ever be run on a pre-5.004 system, of course, or if you want a seed other than the default.

"m//gc" does not reset search position on failure
The "m//g" match iteration construct has always reset its target string's search position (which is visible through the "pos" operator) when a match fails; as a result, the next "m//g" match after a failure starts again at the beginning of the string. With Perl 5.004, this reset may be disabled by adding the "c" (for "continue") modifier, i.e. "m//gc". This feature, in conjunction with the "\G" zero-width assertion, makes it possible to chain matches together. See perlop and perlre.

New builtin methods

The "UNIVERSAL" package automatically contains the following methods that are inherited by all other classes:

isa(CLASS)
"isa" returns true if its object is blessed into a subclass of "CLASS"

"isa" is also exportable and can be called as a sub with two arguments. This allows the ability to check what a reference points to. Example:

use UNIVERSAL qw(isa);
if(isa($ref, 'ARRAY')) {
   ...
}
can(METHOD)
"can" checks to see if its object has a method called "METHOD", if it does then a reference to the sub is returned; if it does not then undef is returned.
VERSION( [NEED] )
"VERSION" returns the version number of the class (package). If the NEED argument is given then it will check that the current version (as defined by the $VERSION variable in the given package) not less than NEED; it will die if this is not the case. This method is normally called as a class method. This method is called automatically by the "VERSION" form of "use". 
use A 1.2 qw(some imported subs);
# implies:
A->VERSION(1.2);

NOTE: "can" utilise directement le code interne de Perl pour la recherche de méthodes, et "isa" utilise une méthode et une stratégie de mise en cache très similaires. Cela peut causer des effets étranges si le code Perl modifie dynamiquement @ISA dans n'importe quel paquet.

Vous pouvez ajouter d'autres méthodes à la classe UNIVERSAL via du code Perl ou XS. Vous n'avez pas besoin de "use UNIVERSAL" pour rendre ces méthodes disponibles à votre programme. Ceci n'est nécessaire que si vous souhaitez que "isa" soit disponible en tant que simple sous-routine dans le paquet courant.

Malloc améliorations

Si perl est compilé avec le malloc inclus dans la distribution de perl (c'est-à-dire si "perl -V:d_mymalloc" est 'define') alors vous pouvez imprimer les statistiques mémoire à l'exécution en exécutant Perl ainsi :

env PERL_DEBUG_MSTATS=2 perl votre_script_ici

La valeur 2 signifie d'imprimer les statistiques après la compilation et à la sortie ; avec une valeur de 1, les statistiques ne sont imprimées qu'à la sortie. (Si vous souhaitez les statistiques à un moment arbitraire, vous devrez installer le module optionnel Devel::Peek.)

Trois nouveaux indicateurs de compilation sont reconnus par malloc.c. (Ils n'ont aucun effet si perl est compilé avec le malloc() système.)

-DPERL_EMERGENCY_SBRK
Si cette macro est définie, manquer de mémoire n'a pas besoin d'être une erreur fatale : une réserve de mémoire peut être allouée en assignant la variable spéciale $^M. Voir "$^M".
-DPACK_MALLOC
L'allocation mémoire de Perl se fait par paquets avec des tailles proches des puissances de deux. En raison de cela, la surcharge de malloc peut être importante, surtout pour les données de taille exactement égale à une puissance de deux. Si "PACK_MALLOC" est défini, perl utilise un algorithme légèrement différent pour les petites allocations (jusqu'à 64 octets), ce qui permet d'avoir une surcharge allant jusqu'à 1 octet pour les allocations qui sont des puissances de deux (et qui apparaissent assez souvent).

L'économie mémoire attendue (avec un alignement de 8 octets dans "alignbytes") est d'environ 20% pour une utilisation typique de Perl. Le ralentissement attendu dû à la surcharge malloc supplémentaire est de l'ordre de fractions de pour cent (difficile à mesurer, en raison de l'effet de la mémoire économisée sur la vitesse).

-DTWO_POT_OPTIMIZE
Similaire à "PACK_MALLOC", cette macro améliore les allocations de données dont la taille est proche d'une puissance de deux ; mais cela fonctionne pour les grosses allocations (à partir de 16K par défaut). De telles allocations sont typiques pour les grands hachages et les scripts à usage spécial, notamment le traitement d'images.

Sur les systèmes récents, le fait que perl demande 2M au système pour 1M d'allocation n'affectera pas la vitesse d'exécution, car la fin d'un tel bloc ne sera pas touchée (et donc ne nécessitera pas de mémoire réelle). Cependant, cela peut entraîner une erreur de mémoire hors limites prématurée. Donc, si vous manipulez de très grands blocs dont la taille est proche des puissances de deux, il serait judicieux de définir cette macro.

L'économie mémoire attendue est de 0 à 100% (100% dans les applications qui nécessitent le plus de mémoire dans de tels blocs 2**n) ; le ralentissement attendu est négligeable.

Améliorations diverses d'efficacité

Six nouveaux modules pragmatiques existent :

Diffère le "require MODULE" jusqu'à ce que quelqu'un appelle l'une des sous-routines spécifiées (qui doivent être exportées par MODULE). Ce pragmatisme doit être utilisé avec prudence, et seulement lorsque nécessaire.

Destiné à être utilisé en ligne de commande avec l'option -M comme moyen de tester des scripts arbitraires contre une version non installée d'un paquet.

Indique au compilateur d'activer (ou de désactiver) l'utilisation des locales POSIX pour les opérations intégrées.

xsubpp

Les XSUB « void » renvoient maintenant par défaut rien
En raison d'un bug de documentation/implémentation dans les versions précédentes de Perl, les XSUB avec un type de retour de "void" renvoyaient en fait une valeur. Habituellement, cette valeur était le GV pour le XSUB, mais parfois c'était une valeur déjà libérée ou réutilisée, ce qui conduisait parfois à des échecs de programme.

Dans Perl 5.004, si un XSUB est déclaré comme renvoyant "void", il ne renvoie en fait aucune valeur, c'est-à-dire une liste vide (bien qu'il y ait une exception de compatibilité ascendante ; voir ci-dessous). Si votre XSUB renvoie effectivement un SV, vous devriez lui donner un type de retour de "SV *".

Pour des raisons de compatibilité ascendante, xsubpp essaie de deviner si un XSUB "void" est réellement "void" ou s'il veut renvoyer un "SV *". Il le fait en examinant le texte du XSUB : si xsubpp trouve ce qui ressemble à une affectation à ST(0), il suppose que le type de retour du XSUB est en fait "SV *".

(S) Vous avez annulé la définition d'une sous-routine qui était auparavant éligible pour l'inlining. Voir "Constant Functions" dans perlsub pour les commentaires et les solutions de contournement.
Copy method did not return a reference
(F) La méthode qui surcharge "=" est boguée. Voir "Copy Constructor" dans overload.
Died
(F) Vous avez passé une chaîne vide à die() (l'équivalent de "die """) ou vous l'avez appelée sans arguments et $@ et $_ étaient tous deux vides.
Exiting pseudo-block via %s
(W) Vous quittez une construction de bloc plutôt spéciale (comme un bloc de tri ou une sous-routine) par des moyens non conventionnels, tels qu'un goto, ou une instruction de contrôle de boucle. Voir "sort" dans perlfunc.
Identifier too long
(F) Perl limite les identifiants (noms de variables, fonctions, etc.) à 252 caractères pour les noms simples, un peu plus pour les noms composés (comme $A::B). Vous avez dépassé les limites de Perl. Les futures versions de Perl supprimeront probablement ces limitations arbitraires.
Illegal character %s (carriage return)
(F) Un caractère de retour chariot a été trouvé dans l'entrée. Ceci est une erreur, et non un avertissement, car les caractères de retour chariot peuvent interrompre les chaînes multilignes, y compris les here documents (par exemple, "print <<EOF;").
Illegal switch in PERL5OPT: %s
(X) La variable d'environnement PERL5OPT ne peut être utilisée que pour définir les commutateurs suivants : -[DIMUdmw].
Integer overflow in hex number
(S) Le nombre hexadécimal littéral que vous avez spécifié est trop grand pour votre architecture. Sur une architecture 32 bits, le plus grand littéral hexadécimal est 0xFFFFFFFF.
Integer overflow in octal number
(S) Le nombre octal littéral que vous avez spécifié est trop grand pour votre architecture. Sur une architecture 32 bits, le plus grand littéral octal est 037777777777.
internal error: glob failed
(P) Quelque chose s'est mal passé avec les programmes externes utilisés pour "glob" et "<*.c>". Cela peut signifier que votre csh (C shell) est défectueux. Si c'est le cas, vous devriez modifier toutes les variables liées à csh dans config.sh : Si vous avez tcsh, faites en sorte que les variables y fassent référence comme s'il s'agissait de csh (par exemple, "full_csh='/usr/bin/tcsh'") ; sinon, laissez-les toutes vides (sauf que "d_csh" devrait être 'undef') afin que Perl pense que csh est absent. Dans les deux cas, après avoir modifié config.sh, exécutez "./Configure -S" et reconstruisez Perl.
Invalid conversion in %s: "%s"
(W) Perl ne comprend pas la conversion de format donnée. Voir "sprintf" dans perlfunc.
Invalid type in pack: '%s'
(F) Le caractère donné n'est pas un type valide pour pack. Voir "pack" dans perlfunc.
Invalid type in unpack: '%s'
(F) Le caractère donné n'est pas un type valide pour unpack. Voir "unpack" dans perlfunc.
Name "%s::%s" used only once: possible typo
(W) Les erreurs typographiques se manifestent souvent par des noms de variables uniques. Si vous aviez une bonne raison d'avoir un nom unique, mentionnez-le simplement à nouveau d'une manière ou d'une autre pour supprimer le message (le pragma "use vars" est fourni à cet effet).
Null picture in formline
(F) Le premier argument de formline doit être une spécification de format valide. Il s'est avéré vide, ce qui signifie probablement que vous lui avez fourni une valeur non initialisée. Voir perlform.
Offset en dehors de la chaîne
(F) Vous avez essayé d'effectuer une opération de lecture/écriture/envoi/réception avec un décalage pointant en dehors du tampon. C'est difficile à imaginer. La seule exception est que la lecture sysread() au-delà du tampon étendra le tampon et remplira la nouvelle zone avec des zéros.
Mémoire insuffisante !
(X|F) La fonction malloc() a retourné 0, indiquant qu'il n'y avait pas assez de mémoire restante (ou de mémoire virtuelle) pour satisfaire la demande.

La demande a été jugée petite, donc la possibilité de la piéger dépend de la façon dont Perl a été compilé. Par défaut, elle n'est pas traçable. Cependant, si elle a été compilée à cet effet, Perl peut utiliser le contenu de $^M comme pool d'urgence après avoir appelé die() avec ce message. Dans ce cas, l'erreur est traçable *une fois*.

Mémoire insuffisante lors de la demande pour %s
(F) La fonction malloc() a retourné 0, indiquant qu'il n'y avait pas assez de mémoire restante (ou de mémoire virtuelle) pour satisfaire la demande. Cependant, la demande a été jugée suffisamment grande (la valeur par défaut à la compilation est de 64 Ko), donc une possibilité d'arrêt en piégeant cette erreur est accordée.
panic: frexp
(P) La fonction de bibliothèque frexp() a échoué, rendant printf("%f") impossible.
Tentative possible de mettre des commentaires dans une liste qw()
(W) Les listes qw() contiennent des éléments séparés par des espaces blancs ; tout comme les chaînes littérales, les caractères de commentaire ne sont pas ignorés, mais sont traités comme des données littérales. (Vous avez peut-être utilisé des délimiteurs différents de ceux des parenthèses montrés ici ; les accolades sont aussi fréquemment utilisées.)

Vous avez probablement écrit quelque chose comme ceci :

@list = qw(
    a # un commentaire
    b # un autre commentaire
);

alors que vous auriez dû écrire ceci :

@list = qw(
    a
    b
);

Si vous souhaitez réellement des commentaires, construisez votre liste à l'ancienne, avec des guillemets et des virgules :

@list = (
    'a',    # un commentaire
    'b',    # un autre commentaire
);
Tentative possible de séparer les mots par des virgules
(W) Les listes qw() contiennent des éléments séparés par des espaces blancs ; par conséquent, les virgules ne sont pas nécessaires pour séparer les éléments. (Vous avez peut-être utilisé des délimiteurs différents de ceux des parenthèses montrés ici ; les accolades sont aussi fréquemment utilisées.)

Vous avez probablement écrit quelque chose comme ceci :

qw! a, b, c !;

ce qui insère des virgules littérales dans certains des éléments de la liste. Écrivez-le sans virgules si vous ne voulez pas qu'elles apparaissent dans vos données :

qw! a b c !;
La valeur scalaire @%s{%s} est mieux écrite comme $%s{%s}
(W) Vous avez utilisé une tranche de hachage (indiquée par @) pour sélectionner un seul élément d'un hachage. Généralement, il est préférable de demander une valeur scalaire (indiquée par $). La différence est que $foo{&bar} se comporte toujours comme un scalaire, à la fois lors de l'affectation et lors de l'évaluation de son argument, tandis que @foo{&bar} se comporte comme une liste lors de l'affectation et fournit un contexte de liste à son sous-indice, ce qui peut avoir des effets étranges si vous n'attendez qu'un seul sous-indice.
Stub trouvé lors de la résolution de la méthode `%s' surchargeant `%s' dans %s
(P) La résolution de la surcharge sur l'arbre @ISA peut être rompue par l'importation de stubs. Les stubs ne devraient jamais être créés implicitement, mais les appels explicites à "can" peuvent casser cela.
Trop tard pour l'option "-T"
(X) La ligne #! (ou son équivalent local) dans un script Perl contient l'option -T, mais Perl n'a pas été invoqué avec -T dans sa liste d'arguments. C'est une erreur car, au moment où Perl découvre un -T dans un script, il est trop tard pour "tainter" correctement tout depuis l'environnement. Perl abandonne donc.
tentative d'untie alors que %d références internes existent toujours
(W) Une copie de l'objet retourné par "tie" (ou "tied") était encore valide lorsque "untie" a été appelé.
Caractère non reconnu %s
(F) L'analyseur Perl ne sait pas quoi faire du caractère spécifié dans votre script Perl (ou eval). Peut-être avez-vous essayé d'exécuter un script compressé, un programme binaire, ou un répertoire comme programme Perl.
Fonction fork non supportée
(F) Votre version de l'exécutable ne supporte pas le fork.

Notez que sur certains systèmes, comme OS/2, il peut y avoir différentes saveurs d'exécutables Perl, dont certaines peuvent supporter le fork, d'autres non. Essayez de changer le nom sous lequel vous appelez Perl en "perl_", "perl__", et ainsi de suite.

L'utilisation de "$$<digit>" pour signifier "${$}<digit>" est dépréciée
(D) Les versions de Perl antérieures à 5.004 interprétaient mal tout marqueur de type suivi de "$" et d'un chiffre. Par exemple, "$$0" était incorrectement interprété comme "${$}0" au lieu de "${$0}". Ce bug est (en grande partie) corrigé dans Perl 5.004.

Cependant, les développeurs de Perl 5.004 n'ont pas pu corriger complètement ce bug, car au moins deux modules largement utilisés dépendent de l'ancienne signification de "$$0" dans une chaîne. Perl 5.004 interprète donc toujours "$$" de l'ancienne manière (défectueuse) à l'intérieur des chaînes ; mais il génère ce message comme un avertissement. Et dans Perl 5.005, ce traitement spécial cessera.

La valeur de %s peut être "0" ; testez avec defined()
(W) Dans une expression conditionnelle, vous avez utilisé <HANDLE>, <*> (glob), each(), ou readdir() comme valeur booléenne. Chacune de ces constructions peut retourner une valeur de "0" ; cela rendrait l'expression conditionnelle fausse, ce qui n'est probablement pas ce que vous aviez l'intention. Lorsque vous utilisez ces constructions dans des expressions conditionnelles, testez leurs valeurs avec l'opérateur "defined".
La variable "%s" peut être indisponible
(W) Une sous-routine anonyme interne (imbriquée) se trouve à l'intérieur d'une sous-routine nommée, et à l'extérieur de celle-ci se trouve une autre sous-routine ; et la sous-routine anonyme (la plus interne) fait référence à une variable lexicale définie dans la sous-routine la plus externe. Par exemple : 
sub outermost { my $a; sub middle { sub { $a } } }

Si la sous-routine anonyme est appelée ou référencée (directement ou indirectement) depuis la sous-routine la plus externe, elle partagera la variable comme vous vous y attendez. Mais si la sous-routine anonyme est appelée ou référencée alors que la sous-routine la plus externe n'est pas active, elle verra la valeur de la variable partagée telle qu'elle était avant et pendant le *premier* appel à la sous-routine la plus externe, ce qui n'est probablement pas ce que vous voulez.

Dans ces circonstances, il est généralement préférable de rendre la sous-routine intermédiaire anonyme, en utilisant la syntaxe "sub {}". Perl a un support spécifique pour les variables partagées dans les sous-routines anonymes imbriquées ; une sous-routine nommée entre les deux interfère avec cette fonctionnalité.

La variable "%s" ne restera pas partagée
(W) Une sous-routine nommée interne (imbriquée) fait référence à une variable lexicale définie dans une sous-routine externe.

Lorsque la sous-routine interne est appelée, elle verra probablement la valeur de la variable de la sous-routine externe telle qu'elle était avant et pendant le *premier* appel à la sous-routine externe ; dans ce cas, après la fin du premier appel à la sous-routine externe, les sous-routines interne et externe ne partageront plus une valeur commune pour la variable. En d'autres termes, la variable ne sera plus partagée.

De plus, si la sous-routine externe est anonyme et fait référence à une variable lexicale à l'extérieur d'elle-même, alors les sous-routines externe et interne ne partageront *jamais* la variable donnée.

Ce problème peut généralement être résolu en rendant la sous-routine interne anonyme, en utilisant la syntaxe "sub {}". Lorsque les sous-routines anonymes internes qui font référence à des variables dans des sous-routines externes sont appelées ou référencées, elles sont automatiquement liées aux valeurs actuelles de ces variables.

Avertissement : quelque chose ne va pas
(W) Vous avez passé une chaîne vide à warn() (l'équivalent de "warn """) ou vous l'avez appelée sans arguments et $_ était vide.
Nom logique mal formé |%s| dans prime_env_iter
(W) Un avertissement spécifique à VMS. Un nom logique a été rencontré lors de la préparation de l'itération sur %ENV qui viole les règles syntaxiques régissant les noms logiques. Comme il ne peut pas être traduit normalement, il est ignoré et n'apparaîtra pas dans %ENV. Cela peut être un événement bénin, car certains progiciels peuvent modifier directement les tables de noms logiques et introduire des noms non standard, ou cela peut indiquer qu'une table de noms logiques a été corrompue.
Erreur reçue de DosAllocMem
(P) Une erreur spécifique à OS/2. Vous utilisez très probablement une version obsolète de Perl, et cela ne devrait de toute façon pas arriver.
PERLLIB_PREFIX malformé
(F) Une erreur spécifique à OS/2. PERLLIB_PREFIX doit être de la forme 
prefix1;prefix2

ou

prefix1 prefix2

avec prefix1 et prefix2 non vides. Si "prefix1" est effectivement un préfixe d'un chemin de recherche de bibliothèque intégré, prefix2 est substitué. L'erreur peut apparaître si des composants sont introuvables ou trop longs. Voir "PERLLIB_PREFIX" dans README.os2.

PERL_SH_DIR trop long
(F) Une erreur spécifique à OS/2. PERL_SH_DIR est le répertoire pour trouver le
"sh"-shell. Voir "PERL_SH_DIR" dans README.os2.
Processus terminé par SIG%s
(W) Ceci est un message standard émis par les applications OS/2, tandis que les applications *nix meurent en silence. Il est considéré comme une fonctionnalité du port OS/2. On peut facilement désactiver ceci par des sighandlers appropriés, voir "Signals" dans perlipc. Voir aussi "Processus terminé par SIGTERM/SIGINT" dans README.os2.
