NOM

perlmroapi - Interface de plugin pour l'ordre de résolution des méthodes Perl

DESCRIPTION

Depuis Perl 5.10.1, il existe une nouvelle interface pour greffer et utiliser des ordres de résolution de méthodes autres que celui par défaut (recherche en profondeur linéaire). L'ordre de résolution de méthodes C3 ajouté en 5.10.0 a été réimplémenté en tant que plugin, sans modifier son interface en espace Perl.

Chaque plugin doit s'enregistrer en fournissant la structure suivante

struct mro_alg {
    AV *(*resolve)(pTHX_ HV *stash, U32 level);
    const char *name;
    U16 length;
    U16 kflags;
    U32 hash;
};

et en appelant "Perl_mro_register":

Perl_mro_register(aTHX_ &my_mro_alg);
resolve
Pointeur vers la fonction de linéarisation, décrite ci-dessous.
name
Nom du MRO, soit en ISO-8859-1 soit en UTF-8.
length
Longueur du nom.
kflags
Si le nom est fourni en UTF-8, définissez ceci à "HVhek_UTF8". La valeur est passée directement comme paramètre kflags à hv_common().
hash
Une valeur de hachage précalculée pour le nom du MRO, ou 0.

Callbacks

La fonction "resolve" est appelée pour générer une ISA linéarisée pour le stash donné, en utilisant ce MRO. Elle est appelée avec un pointeur vers le stash et un niveau level de 0. Le cœur du système passe toujours level à 0 lorsqu'il appelle votre fonction - le paramètre est fourni pour permettre à votre implémentation de suivre la profondeur si elle doit récursivement.

La fonction doit retourner une référence à un tableau contenant des SV de type chaîne de caractères donnant les noms des classes parentes dans l'ordre. Les noms des classes doivent être le résultat de l'appel à HvENAME() sur le stash. Dans les cas où HvENAME() retourne null, HvNAME() doit être utilisé à la place.

L'appelant est responsable d'incrémenter le compteur de références du tableau retourné s'il souhaite conserver la structure. Par conséquent, si vous avez créé une valeur temporaire pour laquelle vous ne conservez aucun pointeur, utilisez sv_2mortal() pour vous assurer qu'elle est correctement libérée. Si vous avez mis en cache votre valeur de retour, retournez un pointeur vers celle-ci sans modifier le compteur de références.

Mise en cache

Le calcul des MRO peut être coûteux. L'implémentation fournit un cache, dans lequel vous pouvez stocker un unique "SV *", ou tout ce qui peut être casté en "SV *", tel que "AV *". Pour lire votre valeur privée, utilisez la macro MRO_GET_PRIVATE_DATA(), en lui passant la structure "mro_meta" du stash, et un pointeur vers votre structure "mro_alg":

meta = HvMROMETA(stash);
private_sv = MRO_GET_PRIVATE_DATA(meta, &my_mro_alg);

Pour définir votre valeur privée, appelez Perl_mro_set_private_data():

Perl_mro_set_private_data(aTHX_ meta, &c3_alg, private_sv);

Le cache de données privées prendra possession d'une référence vers private_sv, de la même manière que hv_store() prend possession d'une référence vers la valeur que vous lui passez.

Exemples

Pour des exemples d'implémentations de MRO, voir S_mro_get_linear_isa_c3() et la section "BOOT:" de ext/mro/mro.xs, et S_mro_get_linear_isa_dfs() dans mro_core.c
