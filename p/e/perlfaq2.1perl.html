perlfaq2 - Obtention et apprentissage de Perl

VERSION

DESCRIPTION

Cette section de la FAQ répond aux questions sur l'endroit où trouver les sources et la documentation de Perl, le support, et les sujets connexes.

Quelles machines supportent Perl ? Où puis-je l'obtenir ?

La distribution standard de Perl (celle maintenue par l'équipe de développement de Perl) est distribuée uniquement sous forme de code source. Vous pouvez trouver les dernières versions sur http://www.cpan.org/src/.

Perl se compile et s'exécute sur une multitude ahurissante de plateformes. Pratiquement tous les dérivés connus et actuels de Unix sont supportés (la plateforme native de perl), ainsi que d'autres systèmes tels que VMS, DOS, OS/2, Windows, QNX, BeOS, OS X, MPE/iX et l'Amiga.

Les distributions binaires pour certaines plateformes propriétaires peuvent être trouvées dans le répertoire http://www.cpan.org/ports/. Comme celles-ci ne font pas partie de la distribution standard, elles peuvent différer, et en fait elles diffèrent, du portage de base de perl de diverses manières. Vous devrez consulter leurs notes de publication respectives pour voir précisément quelles sont les différences. Ces différences peuvent être positives (par exemple, des extensions pour les fonctionnalités de la plateforme particulière qui ne sont pas supportées dans la version source de perl) ou négatives (par exemple, peuvent être basées sur une version source moins récente de perl).

Comment puis-je obtenir une version binaire de Perl ?

Voir les ports CPAN sur http://www.cpan.org/ports/

Je n'ai pas de compilateur C. Comment puis-je construire mon propre interpréteur Perl ?

Pour Windows, utilisez une version binaire de Perl. Strawberry Perl http://strawberryperl.com/ et ActivePerl http://www.activestate.com/activeperl sont livrés avec un compilateur C intégré.

Sinon, si vous souhaitez vraiment construire Perl, vous devez d'abord obtenir une version binaire de "gcc" pour votre système. Utilisez un moteur de recherche pour savoir comment faire cela pour votre système d'exploitation.

J'ai copié le binaire Perl d'une machine à une autre, mais les scripts ne fonctionnent pas.

C'est probablement parce que vous avez oublié des bibliothèques, ou que les chemins des bibliothèques diffèrent. Vous devriez vraiment compiler toute la distribution sur la machine où elle doit finalement résider, puis taper "make install". La plupart des autres approches sont vouées à l'échec.

Une façon simple de vérifier que les choses sont au bon endroit est d'afficher la liste codée en dur @INC que perl utilise pour rechercher les bibliothèques :

% perl -le 'print for @INC'

Si cette commande liste des chemins qui n'existent pas sur votre système, vous devrez peut-être déplacer les bibliothèques appropriées à ces emplacements, ou créer des liens symboliques, des alias ou des raccourcis appropriés. @INC est également affiché dans la sortie de

% perl -V

Vous pourriez également consulter "Comment puis-je garder mon propre répertoire de modules/bibliothèques ?" dans perlfaq8.

J'ai téléchargé les sources et essayé de compiler mais gdbm/chargement dynamique/malloc/édition de liens/... a échoué. Comment le faire fonctionner ?

Lisez le fichier INSTALL, qui fait partie de la distribution source. Il décrit en détail comment gérer la plupart des idiosyncrasies que le script "Configure" ne peut pas contourner pour un système ou une architecture donnée.

Quels modules et extensions sont disponibles pour Perl ? Qu'est-ce que CPAN ?

CPAN signifie Comprehensive Perl Archive Network, une archive de plusieurs gigaoctets répliquée sur des centaines de machines dans le monde. CPAN contient des dizaines de milliers de modules et extensions, du code source et de la documentation, conçus pour *tout*, des interfaces de bases de données commerciales au contrôle du clavier/écran et à l'exécution de grands sites web.

Vous pouvez rechercher sur CPAN sur http://metacpan.org.

Le site web principal de CPAN est http://www.cpan.org/, http://www.cpan.org/SITES.html liste tous les miroirs.

Consultez la FAQ CPAN sur http://www.cpan.org/misc/cpan-faq.html pour des réponses aux questions les plus fréquemment posées sur CPAN.

Le module Task::Kensho contient une liste de modules recommandés que vous devriez consulter comme un bon point de départ.

Où puis-je obtenir des informations sur Perl ?

  • http://www.perl.org/
  • http://perldoc.perl.org/
  • http://learn.perl.org/

La documentation complète de Perl est disponible avec la distribution Perl. Si vous avez Perl installé localement, vous avez probablement la documentation installée également : tapez "perldoc perl" dans un terminal ou consultez en ligne http://perldoc.perl.org/perl.html.

(Certaines distributions de systèmes d'exploitation peuvent expédier la documentation dans un paquet différent ; par exemple, sous Debian, vous devez installer le paquet "perl-doc".)

De nombreux bons livres ont été écrits sur Perl — voir la section "Livres sur Perl" pour plus de détails.

Qu'est-ce que perl.com ? Perl Mongers ? pm.org ? perl.org ? cpan.org ?

Perl.com http://www.perl.com/ faisait autrefois partie du O'Reilly Network, une filiale d'O'Reilly Media. Bien qu'il conserve la plupart du contenu original de son O'Reilly Network, il est maintenant hébergé par The Perl Foundation http://www.perlfoundation.org/.

The Perl Foundation est une organisation de plaidoyer pour le langage Perl qui maintient le site web http://www.perl.org/ comme site général de plaidoyer pour le langage Perl. Elle utilise le domaine pour fournir des services de support généraux à la communauté Perl, y compris l'hébergement de listes de diffusion, de sites web et d'autres services. Il existe également de nombreux autres sous-domaines pour des sujets spéciaux tels que l'apprentissage de Perl et les emplois dans le domaine de Perl, tels que :

  • http://www.perl.org/
  • http://learn.perl.org/
  • http://jobs.perl.org/
  • http://lists.perl.org/

Perl Mongers http://www.pm.org/ utilise le domaine pm.org pour les services liés aux groupes d'utilisateurs Perl locaux, y compris l'hébergement de listes de diffusion et de sites web. Consultez le site web de Perl Mongers http://www.pm.org/ pour plus d'informations sur la façon de rejoindre, de créer ou de demander des services pour un groupe d'utilisateurs Perl.

CPAN, ou Comprehensive Perl Archive Network http://www.cpan.org/, est un dépôt répliqué à l'échelle mondiale de logiciels Perl. Voir Qu'est-ce que CPAN ?.

Où puis-je poser des questions sur Perl ?

Il existe plusieurs endroits pour poser des questions sur Perl. Une liste complète des listes de diffusion liées à Perl se trouve sur https://lists.perl.org, en particulier la liste des débutants http://lists.perl.org/list/beginners.html pourrait vous être utile.

D'autres endroits pour poser des questions sont le site PerlMonks http://www.perlmonks.org/ ou Stack Overflow http://stackoverflow.com/questions/tagged/perl.

Livres sur Perl

Il existe de nombreux bons livres sur Perl, disponibles à http://www.perl.org/books/library.html.

Quels magazines contiennent du contenu sur Perl ?

Il n'y a actuellement aucun magazine axé sur Perl, bien que vous trouviez parfois du contenu sur Perl dans des titres de programmation plus généraux.

Dans le passé lointain, il y a eu quelques magazines Perl. Le premier était The Perl Journal, publié par Jon Orwant. Après cela, il y a eu The Perl Review, publié par brian d foy, et $foo Magazin, publié par Renée Bäcker (http://www.foo-magazin.de).

Le plus proche que vous puissiez trouver aujourd'hui est Perl Weekly, (https://perlweekly.com), une newsletter en ligne avec un format de type magazine.

Quels blogs Perl devrais-je lire ?

Perl News http://perlnews.org/ couvre certains des événements majeurs du monde Perl, Perl Weekly http://perlweekly.com/ est un e-mail hebdomadaire (et flux RSS) d'articles Perl sélectionnés.

http://blogs.perl.org/ héberge de nombreux blogs Perl, il existe également plusieurs agrégateurs de blogs : Perlsphere http://perlsphere.net/ et Ironman http://ironman.enlightenedperl.org/ en sont deux.

Quelles listes de diffusion existent pour Perl ?

Une liste complète des listes de diffusion liées à Perl se trouve sur http://lists.perl.org/

Où puis-je acheter une version commerciale de Perl ?

Perl est déjà un logiciel commercial : il a une licence que vous pouvez prendre et lire attentivement à votre manager. Il est distribué en versions et se présente sous forme de paquets bien définis. Il existe une communauté d'utilisateurs très large et solidaire, ainsi qu'une vaste littérature.

Si vous avez toujours besoin d'un support commercial, ActiveState http://www.activestate.com/activeperl l'offre.

Où dois-je envoyer les rapports de bugs ?

(contribué par brian d foy)

Premièrement, assurez-vous d'avoir trouvé un véritable bug. Deuxièmement, assurez-vous d'avoir trouvé un véritable bug.

Si vous avez trouvé un bug dans l'interpréteur Perl ou dans l'un des modules de la bibliothèque standard (ceux qui sont livrés avec Perl), soumettez un rapport de bug au traqueur de problèmes GitHub à https://github.com/Perl/perl5/issues.

Pour déterminer si un module est livré avec votre version de Perl, vous pouvez installer et utiliser Module::CoreList. Il connaît les modules (avec leurs versions) inclus dans chaque version de Perl :

$ corelist File::Copy
Data for 2023-07-02
File::Copy was first released with perl 5.002
$ corelist Business::ISBN
Data for 2023-07-02
Business::ISBN was not in CORE (or so I think)

Si le module n'est pas livré avec Perl, signalez ses problèmes en utilisant l'outil que l'auteur du module particulier a décidé d'utiliser, tel qu'un traqueur de problèmes GitHub ou Google Code. Le moyen le plus rapide peut être de vérifier la page MetaCPAN du module (par exemple, https://metacpan.org/pod/Business::ISBN), qui affiche le traqueur de bogues désigné dans la barre latérale gauche sous le lien « Issues ».

Vérifiez également la documentation du module, le fichier README, les fichiers de construction (Makefile.PL ou "Build.PL") ou les fichiers META.{json,yml}. Bien que de nombreux auteurs de modules suivent le même schéma, certains ont leur propre méthode. Utilisez les instructions que vous trouvez.

Parfois, l'auteur du module ne déclare pas de traqueur de bogues. Pendant longtemps, tout le monde a supposé que le traqueur de requêtes CPAN (https://rt.cpan.org) était le traqueur de bogues car chaque distribution avait une file d'attente RT générée automatiquement. Dans certains cas, l'auteur peut utiliser CPAN RT. Ils peuvent également ne pas avoir déclaré un traqueur de bogues différent mais n'utilisent pas CPAN RT.

Soumettez les bogues à RT soit via son interface web, https://rt.cpan.org, soit par e-mail. Envoyez un e-mail à bug-<nom-distribution>@rt.cpan.org. Par exemple, si vous vouliez signaler un bug dans le module d'exemple "Foo::Bar", vous pourriez envoyer un message à bug-Foo-Bar@rt.cpan.org.
