PERL5280DELTA(1perl) Guide de référence du programmeur Perl PERL5280DELTA(1perl)

NOM

perl5280delta - nouveautés de la version perl v5.28.0

DESCRIPTION

Ce document décrit les différences entre la version 5.26.0 et la version 5.28.0.

Si vous mettez à jour depuis une version antérieure telle que la 5.24.0, lisez d'abord perl5260delta, qui décrit les différences entre la 5.24.0 et la 5.26.0.

Améliorations du cœur

Unicode 10.0 est pris en charge

Une liste des modifications est disponible à l'adresse http://www.unicode.org/versions/Unicode10.0.0.

"delete" sur les tranches de hachage clé/valeur

"delete" peut maintenant être utilisé sur les tranches de hachage clé/valeur, retournant les clés en même temps que les valeurs supprimées. [GH #15982] https://github.com/Perl/perl5/issues/15982

Expérimentalement, il y a maintenant des synonymes alphabétiques pour certaines assertions d'expressions régulières

Si vous trouvez difficile de vous souvenir comment écrire certaines des assertions de motifs, il existe maintenant des synonymes alphabétiques.

ACTUEL               NOUVEAUX SYNONYMES
------               ------------
(?=...)        (*pla:...) ou (*positive_lookahead:...)
(?!...)        (*nla:...) ou (*negative_lookahead:...)
(?<=...)       (*plb:...) ou (*positive_lookbehind:...)
(?<!...)       (*nlb:...) ou (*negative_lookbehind:...)
(?>...)        (*atomic:...)

Ceux-ci sont considérés comme expérimentaux, donc leur utilisation déclenchera (sauf si désactivé) un avertissement dans la catégorie "experimental::alpha_assertions".

Les scripts Unicode mixtes sont maintenant détectables

Un mélange de scripts, tels que le cyrillique et le latin, dans une chaîne est souvent le signe d'une attaque par usurpation d'identité. Une nouvelle construction d'expression régulière permet désormais de les détecter facilement. Par exemple, vous pouvez dire

qr/(*script_run: \d+ \b )/x

Et les chiffres correspondants proviendront tous du même ensemble de 10. Vous n'obtiendrez pas un chiffre d'apparence similaire d'un script différent qui a une valeur différente de ce qu'il semble être.

Ou :

qr/(*sr: \b \w+ \b )/x

Assure que tous les caractères proviennent du même script.

Vous pouvez également combiner des séquences de scripts avec "(?>...)" (ou "*atomic:...)").

Au lieu d'écrire :

(*sr:(?<...))

Vous pouvez maintenant exécuter :

(*asr:...)
# ou
(*atomic_script_run:...)

Ceci est considéré comme expérimental, donc son utilisation déclenchera (sauf si désactivé) un avertissement dans la catégorie "experimental::script_run".

Voir "Script Runs" dans perlre.

L'édition sur place avec "perl -i" est maintenant plus sûre

Auparavant, l'édition sur place ("perl -i") supprimait ou renommait le fichier d'entrée dès que vous commenciez à travailler sur un nouveau fichier.

Sans sauvegardes, cela entraînait une perte de données en cas d'erreur, telle qu'un disque plein, lors de l'écriture dans le fichier de sortie.

Cela a changé de sorte que le fichier d'entrée n'est remplacé que lorsque le fichier de sortie a été complètement écrit et fermé avec succès.

Cela fonctionne en créant un fichier de travail dans le même répertoire, qui est renommé sur le fichier d'entrée une fois le fichier de sortie terminé.

Incompatibilités :

  • Comme ce renommage ne doit se produire qu'une seule fois, si vous créez un thread ou un processus enfant, ce renommage ne se produira que dans le thread ou le processus d'origine.
  • Si vous changez de répertoire tout en traitant un fichier, et que votre système d'exploitation ne fournit pas les fonctions unlinkat(), renameat() et fchmodat(), l'étape finale de renommage peut échouer.

[GH #15216] https://github.com/Perl/perl5/issues/15216

Initialisation des variables d'état agrégées

Un tableau ou une table de hachage lexicale persistante peut désormais être initialisé, par une expression telle que "state @a = qw(x y z)". L'initialisation d'une liste de variables lexicales persistantes n'est toujours pas possible.

Numéros d'inode de taille complète

Sur les plateformes où les numéros d'inode sont d'un type plus grand que les types numériques entiers natifs de perl, stat préservera le contenu complet des grands numéros d'inode en les retournant sous forme de chaînes de chiffres décimaux. La comparaison exacte des numéros d'inode peut donc être réalisée en comparant avec "eq" plutôt qu'avec "==". La comparaison avec "==", et d'autres opérations numériques (qui sont généralement dénuées de sens sur les numéros d'inode), fonctionnent aussi bien qu'avant, c'est-à-dire qu'elles reviennent à la virgule flottante, et finalement opèrent sur un numéro d'inode arrondi assez inutile si le vrai numéro d'inode est trop grand pour le format à virgule flottante.

Le modificateur de taille de format %j de "sprintf" est maintenant disponible avec les compilateurs pré-C99

La taille réelle utilisée dépend de la plateforme, donc reste non portable.

Le drapeau fermeture-après-exécution est défini atomiquement

Lors de l'ouverture d'un descripteur de fichier, perl l'ouvre maintenant généralement avec son drapeau fermeture-après-exécution déjà défini, sur les plateformes qui le prennent en charge. Cela améliore la sécurité des threads, car cela signifie qu'un "exec" initié par un thread ne peut plus causer qu'un descripteur de fichier en cours d'ouverture par un autre thread soit accidentellement passé au programme exécuté.

De plus, perl définit le drapeau fermeture-après-exécution de manière plus fiable, qu'il le fasse atomiquement ou non. La plupart des descripteurs de fichiers recevaient le drapeau, mais certains manquaient.

Les opérations bitwise spécifiques aux chaînes et nombres ne sont plus expérimentales

Les nouveaux opérateurs bitwise spécifiques aux chaînes ( "&. |. ^. ~. ") et spécifiques aux nombres ( "& | ^ ~") introduits dans Perl 5.22 qui sont disponibles dans la portée de "use feature 'bitwise'" ne sont plus expérimentaux. Comme les opérateurs spécifiques aux nombres ont la même orthographe que les opérateurs existants qui choisissent leur comportement en fonction de leurs opérandes, ces opérateurs doivent toujours être activés via la fonctionnalité "bitwise", de l'une de ces deux manières :

use feature "bitwise";
use v5.28; # "bitwise" maintenant inclus

Ils sont également maintenant activés par le commutateur de ligne de commande -E.

La fonctionnalité "bitwise" n'émet plus d'avertissement. Le code existant qui désactive la catégorie d'avertissement "experimental::bitwise" que la fonctionnalité utilisait auparavant continuera de fonctionner.

Une mise en garde dont les auteurs de modules devraient être conscients est que les opérateurs numériques passent maintenant un cinquième argument VRAI aux méthodes de surcharge. Toutes les méthodes qui vérifient le nombre d'opérandes peuvent planter si elles ne s'attendent pas à autant. Les auteurs XS en particulier doivent savoir que ceci :

SV *

Synopsis

use feature 'bitwise';

my $int = 0b00110101;
my $mask = 0b00001111;

say $int & $mask;  # 5
say $int | $mask;  # 53
say $int ^ $mask;  # 48
say ~$int;         # -54 (on 64-bit)
say ~$int;         # -54 (on 32-bit)

# Note: The bitwise operators are *not* automatically on with 'use feature "bitwise"'.
# They are for demonstration only.
# The actual bitwise operators can be enabled as described below.

my $a = "abc";
my $b = "def";

say $a & $b;  # 195
say $a | $b;  # 101
say $a ^ $b;  # 170
say ~$a;      # -98 (on 64-bit)
say ~$a;      # -98 (on 32-bit)

# The bitwise operators can be enabled on a global or per-scope basis:
use utf8; # needed for Unicode support, see below
use v5.12;

# Bitwise operators enabled globally
use feature 'bitwise';
my $x = 10;
my $y = 7;
say $x & $y; # 2
say $x | $y; # 15
say $x ^ $y; # 13
say ~$x;     # -11

# Bitwise operators enabled per-scope
{
    use feature 'bitwise';
    my $x = 10;
    my $y = 7;
    say $x & $y; # 2
    say $x | $y; # 15
    say $x ^ $y; # 13
    say ~$x;     # -11
}

# Bitwise operators enabled per-block
{
    no feature 'bitwise';
    my $x = 10;
    my $y = 7;
    # say $x & $y; # This would fail at runtime
}

# Note that the feature 'bitwise' is experimental and may change in future releases.

Description

This module provides bitwise operators for integers and strings. The operators are:

  • & (bitwise AND)
  • | (bitwise OR)
  • ^ (bitwise XOR)
  • ~ (bitwise NOT)
  • << (left shift)
  • >> (right shift)

The bitwise operators are not enabled by default. They must be enabled explicitly using use feature 'bitwise'; or use POSIX 'bitwise';. Once enabled, they operate on both integers and strings.

For integers, the operators work as expected. For strings, the operators work on the underlying byte values of the strings.

For Unicode strings, the behavior is more complex. The bitwise operators operate on the Unicode code points of the characters in the string. This means that a string containing multiple characters may not behave as expected when using bitwise operators, as the operators will be applied to each code point individually. If you need to perform bitwise operations on the raw bytes of a Unicode string, you should first encode the string into a byte sequence (e.g., using Encode::encode) and then perform the bitwise operations on the resulting byte string.

Note that the bitwise NOT operator (~) behaves differently for signed and unsigned integers. For signed integers, the result is the two's complement negation of the integer. For unsigned integers, the result is the one's complement negation.

The bitwise operators are implemented using the same underlying mechanisms as the Perl built-in operators, so they should be efficient.

The feature 'bitwise' is experimental and may change in future releases. It is recommended to use it with caution.

Locales are now thread-safe on systems that support them

These systems include Windows starting with Visual Studio 2005, and in POSIX 2008 systems.

The implication is that you are now free to use locales and change them in a threaded environment. Your changes affect only your thread. See "Multi-threaded operation" in perllocale

New read-only predefined variable "${^SAFE_LOCALES}"

This variable is 1 if the Perl interpreter is operating in an environment where it is safe to use and change locales (see perllocale.) This variable is true when the perl is unthreaded, or compiled in a platform that supports thread-safe locale operation (see previous item).

Security

[CVE-2017-12837] Heap buffer overflow in regular expression compiler

Compiling certain regular expression patterns with the case-insensitive modifier could cause a heap buffer overflow and crash perl. This has now been fixed. [GH #16021] https://github.com/Perl/perl5/issues/16021

[CVE-2017-12883] Buffer over-read in regular expression parser

For certain types of syntax error in a regular expression pattern, the error message could either contain the contents of a random, possibly large, chunk of memory, or could crash perl. This has now been fixed. [GH #16025] https://github.com/Perl/perl5/issues/16025

[CVE-2017-12814] $ENV{$key} stack buffer overflow on Windows

A possible stack buffer overflow in the %ENV code on Windows has been fixed by removing the buffer completely since it was superfluous anyway. [GH #16051] https://github.com/Perl/perl5/issues/16051

Default Hash Function Change

Perl 5.28.0 retires various older hash functions which are not viewed as sufficiently secure for use in Perl. We now support four general purpose hash functions, Siphash (2-4 and 1-3 variants), and Zaphod32, and StadtX hash. In addition we support SBOX32 (a form of tabular hashing) for hashing short strings, in conjunction with any of the other hash functions provided.

By default Perl is configured to support SBOX hashing of strings up to 24 characters, in conjunction with StadtX hashing on 64 bit builds, and Zaphod32 hashing for 32 bit builds.

You may control these settings with the following options to Configure:

-DPERL_HASH_FUNC_SIPHASH
-DPERL_HASH_FUNC_SIPHASH13
-DPERL_HASH_FUNC_STADTX
-DPERL_HASH_FUNC_ZAPHOD32

To disable SBOX hashing you can use

-DPERL_HASH_USE_SBOX32_ALSO=0

And to set the maximum length to use SBOX32 hashing on with:

-DSBOX32_MAX_LEN=16

The maximum length allowed is 256. There probably isn't much point in setting it higher than the default.

Incompatible Changes

Subroutine attribute and signature order

The experimental subroutine signatures feature has been changed so that subroutine attributes must now come before the signature rather than after. This is because attributes like ":lvalue" can affect the compilation of code within the signature, for example:

sub f :lvalue ($a = do { $x = "abc"; return substr($x,0,1)}) { ...}

Note that this the second time they have been flipped:

sub f :lvalue ($a, $b) { ... }; # 5.20; 5.28 onwards
sub f ($a, $b) :lvalue { ... }; # 5.22 - 5.26

Comma-less variable lists in formats are no longer allowed

Omitting the commas between variables passed to formats is no longer allowed. This has been deprecated since Perl 5.000.

The ":locked" and ":unique" attributes have been removed

These have been no-ops and deprecated since Perl 5.12 and 5.10, respectively.

"\N{}" with nothing between the braces is now illegal

This has been deprecated since Perl 5.24.

Opening the same symbol as both a file and directory handle is no longer allowed

Using open() and opendir() to associate both a filehandle and a dirhandle to the same symbol (glob or scalar) has been deprecated since Perl 5.10.

Use of bare "<<" to mean "<<""" is no longer allowed

Use of a bare terminator has been deprecated since Perl 5.000.

Setting $/ to a reference to a non-positive integer no longer allowed

This used to work like setting it to "undef", but has been deprecated since Perl 5.20.

Unicode code points with values exceeding "IV_MAX" are now fatal

This was deprecated since Perl 5.24.

The "B::OP::terse" method has been removed

Use "B::Concise::b_terse" instead.

Use of inherited AUTOLOAD for non-methods is no longer allowed

This was deprecated in Perl 5.004.

Use of strings with code points over 0xFF is not allowed for bitwise string operators

Code points over 0xFF do not make sense for bitwise operators and such an operation will now croak, except for a few remaining cases. See perldeprecation.

This was deprecated in Perl 5.24.

Setting "${^ENCODING}" to a defined value is now illegal

This has been deprecated since Perl 5.22 and a no-op since Perl 5.26.

Backslash no longer escapes colon in PATH for the "-S" switch

Previously the "-S" switch incorrectly treated backslash ("\") as an escape for colon when traversing the "PATH" environment variable. [GH #15584] https://github.com/Perl/perl5/issues/15584

the -DH (DEBUG_H) misfeature has been removed

On a perl built with debugging support, the "H" flag to the "-D" debugging option has been removed. This was supposed to dump hash values, but has been broken for many years.

Yada-yada is now strictly a statement

By the time of its initial stable release in Perl 5.12, the "..." (yada-yada) operator was explicitly intended to serve as a statement, not an expression. However, the original implementation was confused on this point, leading to inconsistent parsing. The operator was accidentally accepted in a few situations where it did not serve as a complete statement, such as

... . "foo";
... if $a < $b;

The parsing has now been made consistent, permitting yada-yada only as a statement. Affected code can use "do{...}" to put a yada-yada into an arbitrary expression context.

L'algorithme de tri ne peut plus être spécifié

Depuis Perl 5.8, le pragma sort comportait des sous-pragmas "_mergesort", "_quicksort" et "_qsort" qui pouvaient être utilisés pour spécifier l'algorithme que perl devait utiliser pour implémenter la fonction intégrée sort. Il s'agissait toujours d'une fonctionnalité douteuse qui pourrait ne pas durer, d'où les orthographes avec un tiret bas, et elles étaient documentées comme n'étant pas portables au-delà de Perl 5.8. Ces sous-pragmas ont maintenant été supprimés, et toute tentative de les utiliser est une erreur. Le pragma sort reste, et le sous-pragma "stable", neutre quant à l'algorithme, peut être utilisé pour contrôler le comportement du tri. [GH #13234] https://github.com/Perl/perl5/issues/13234

Chiffres en sur-base dans les littéraux flottants

Les littéraux flottants octaux et binaires permettaient auparavant à n'importe quel chiffre hexadécimal d'apparaître après le point de base. Les chiffres sont maintenant limités à ceux appropriés pour la base, comme l'étaient toujours les chiffres avant le point de base.

Type de retour de unpackstring()

Les types de retour des fonctions de l'API C unpackstring() et unpack_str() sont passés de "I32" à "SSize_t", afin d'accommoder des jeux de données de plus de deux milliards d'éléments.

Dépréciations

L'utilisation de "vec" sur des chaînes avec des points de code supérieurs à 0xFF est dépréciée

Ces chaînes sont représentées en interne en UTF-8, et "vec" est une opération orientée bit qui donnera probablement des résultats inattendus sur ces chaînes.

Certaines utilisations de "{" non échappé dans les regex ne sont plus fatales

Perl 5.26.0 rendait fatales certaines utilisations d'accolades ouvrantes non échappées, mais une exception a été faite à la dernière minute, spécifiquement conçue pour être un changement minimal afin de permettre à GNU Autoconf de fonctionner. Cet outil est très dépendant, et continue d'utiliser l'usage déprécié. Son utilisation d'une accolade ouvrante non échappée est un cas où nous n'avons aucune intention de réaffecter "{" à autre chose qu'elle-même.

Cette exception est maintenant généralisée pour inclure divers autres cas similaires où "{" ne sera pas réaffecté.

Notez que ces utilisations continuent de déclencher un message de dépréciation.

L'utilisation de "{" non échappé immédiatement après un "(" dans les motifs d'expressions régulières est dépréciée

L'utilisation d'accolades ouvrantes non échappées est officiellement dépréciée partout, mais elle n'est pas appliquée dans les contextes où leur utilisation n'interfère pas avec les extensions attendues du langage. Une dépréciation est ajoutée dans cette version lorsque l'accolade apparaît immédiatement après une parenthèse ouvrante. Avant cela, même si l'accolade faisait partie d'un quantificateur légal, elle n'était pas interprétée comme tel, mais comme les caractères littéraux, contrairement à d'autres quantificateurs qui suivent un "(" et sont considérés comme des erreurs. Désormais, leur utilisation déclenchera un message de dépréciation, sauf s'il est désactivé.

L'affectation à $[ sera fatale dans Perl 5.30

L'affectation d'une valeur non nulle à $[ est dépréciée depuis Perl 5.12, mais n'a jamais eu de date limite de suppression. Ceci est maintenant prévu pour Perl 5.30.

hostname() n'acceptera pas d'arguments dans Perl 5.32

Passer des arguments à Sys::Hostname::hostname() était déjà déprécié, mais n'avait pas de date de suppression. Ceci est maintenant prévu pour Perl 5.32. [GH #14662] https://github.com/Perl/perl5/issues/14662

Suppression de modules

Les modules suivants seront supprimés de la distribution principale dans une future version, et devront alors être installés depuis CPAN. Les distributions sur CPAN qui nécessitent ces modules devront les lister comme prérequis.

Les versions principales de ces modules émettront désormais des avertissements de catégorie "déprécié" pour vous alerter de ce fait. Pour faire taire ces avertissements de dépréciation, installez les modules en question depuis CPAN.

Notez qu'il s'agit (à de rares exceptions près) d'excellents modules dont l'utilisation est encouragée. Leur exclusion du cœur dépend principalement de leur nécessité pour amorcer une installation Perl entièrement fonctionnelle et capable de gérer CPAN, et non pas généralement de préoccupations concernant leur conception.

Améliorations de performance

  • Le surcoût au démarrage pour la création d'expressions régulières avec des propriétés Unicode ("\p{...}") a été considérablement réduit dans la plupart des cas.
  • De nombreuses expressions de concaténation de chaînes sont maintenant considérablement plus rapides, grâce à l'introduction interne d'un opcode "multiconcat" qui combine plusieurs concaténations, et optionnellement un "=" ou ".=", en une seule action. Par exemple, en dehors de la récupération de $s, $a et $b, toute cette expression est maintenant traitée comme un seul op : 
    $s .= "a=$a b=$b\n"

    À titre de cas spécial, si le membre de gauche d'une affectation est une variable lexicale ou "my $s", l'op lui-même s'occupe de récupérer la variable lexicale, ce qui est plus rapide.

    En général, plus l'expression inclut un mélange de chaînes constantes et d'expressions variables, plus l'expression est longue, et plus elle mélange des chaînes non-utf8 et utf8, plus l'amélioration de performance sera marquée. Par exemple, sur un système "x86_64", ce code a été benchmarké pour fonctionner quatre fois plus vite :

    my $s;
my $a = "ab\x{100}cde";
my $b = "fghij";
my $c = "\x{101}klmn";
for my $i (1..10_000_000) {
    $s = "\x{100}wxyz";
    $s .= "foo=$a bar=$b baz=$c";
}

    De plus, les expressions "sprintf" qui ont un format constant ne contenant que des éléments de format %s et "%%", et qui ont un nombre fixe d'arguments, sont maintenant également optimisées en un opcode "multiconcat".

  • Le builtin ref() est maintenant beaucoup plus rapide dans un contexte booléen, car il ne prend plus la peine de construire une chaîne temporaire comme "Foo=ARRAY(0x134af48)".
  • Les keys() dans les contextes vide et scalaire sont maintenant plus efficaces.
  • L'idiome courant consistant à comparer le résultat de index() avec -1 est maintenant spécifiquement optimisé, par exemple 
    if (index(...) != -1) { ... }
  • Les boucles for() et les constructions similaires sont maintenant plus efficaces dans la plupart des cas.
  • File::Glob a été modifié pour supprimer les retours arrière et la récursion inutiles, grâce à Russ Cox. Voir https://research.swtch.com/glob pour plus de détails.
  • La fonction de l'API au niveau XS SvTRUE() est maintenant plus efficace.
  • Divers op retournant des entiers sont maintenant plus efficaces dans un contexte scalaire/booléen.
  • Légère amélioration des performances lors de l'analyse des noms de stash. [GH #15689] https://github.com/Perl/perl5/issues/15689
  • Les appels à "require" pour un module déjà chargé sont maintenant légèrement plus rapides. [GH #16175] https://github.com/Perl/perl5/issues/16175
  • Les performances de la mise en correspondance d'expressions régulières "[[:ascii:]]" et "[[:^ascii:]]" ont été considérablement améliorées sauf sur les plateformes EBCDIC.
  • Diverses optimisations ont été appliquées à la mise en correspondance des expressions régulières, de sorte que dans les bonnes circonstances, des gains de performance significatifs peuvent être observés. Mais dans une application avec de nombreux motifs variés, peu d'amélioration globale est susceptible d'être constatée.
  • D'autres optimisations ont été appliquées à la gestion de l'UTF-8, mais celles-ci ne sont généralement pas un facteur majeur dans la plupart des applications.

Modules et Pragmata

Points forts de cette version dans plusieurs modules :

Suppression de use vars

L'utilisation de "use vars" est découragée depuis l'introduction de "our" dans Perl 5.6.0. Lorsque cela était possible, l'utilisation de ce pragma a maintenant été supprimée du code source de Perl.

Cela a eu un léger effet (pour le mieux) sur la sortie de WARNING_BITS dans B::Deparse.

Utilisation de DynaLoader modifiée t

Dans certains cas, nous avons également apporté des modifications à l'implémentation locale qui pourraient ne pas être reflétées dans la version sur CPAN, en raison d'un désir de maintenir une plus grande compatibilité ascendante.

Changements internes

  • Une nouvelle phase d'optimisation a été ajoutée au compilateur, optimize_optree(), qui effectue un balayage descendant d'un arbre optree complet juste avant l'exécution de l'optimiseur de reeks. Cette phase n'est actuellement pas accrochable.
  • Un op "OP_MULTICONCAT" a été ajouté. Au moment de optimize_optree(), une chaîne d'ops "OP_CONCAT" et "OP_CONST", éventuellement combinée avec un "OP_STRINGIFY" et/ou "OP_SASSIGN", est combinée en un seul op "OP_MULTICONCAT". L'op est de type "UNOP_AUX", et le tableau aux contient le nombre d'arguments, plus un pointeur vers une chaîne constante et un ensemble de longueurs de segment. Par exemple, avec 
    my $x = "foo=$foo, bar=$bar\n";

    la chaîne constante serait "foo=, bar=\n" et les longueurs de segment seraient (4,6,1). Si la chaîne contient des caractères tels que "\x80", dont la représentation change en utf8, deux ensembles de chaînes plus longueurs sont précalculés et stockés.

  • L'accès direct à "PL_keyword_plugin" n'est pas sûr en présence de multithreading. Une nouvelle fonction "wrap_keyword_plugin" a été ajoutée pour permettre aux modules XS de définir en toute sécurité des mots-clés personnalisés, même lorsqu'ils sont chargés à partir d'un thread, de manière analogue à "PL_check" / "wrap_op_checker".
  • La variable d'interpréteur "PL_statbuf" a été supprimée.
  • La fonction obsolète to_utf8_case(), accessible depuis le code XS, a été supprimée.
  • Une nouvelle fonction is_utf8_invariant_string_loc() a été ajoutée. Elle est similaire à is_utf8_invariant_string() mais prend un paramètre de pointeur supplémentaire dans lequel est stocké l'emplacement du premier caractère variant, s'il y en a.
  • Une nouvelle fonction, Perl_langinfo(), a été ajoutée. C'est un remplacement (presque) direct de la fonction système nl_langinfo(3), mais elle fonctionne sur les plateformes qui n'en disposent pas ; elle est également plus thread-safe et masque certains pièges de gestion des locales pour l'appelant. Le code qui l'utilise n'a pas besoin d'utiliser "localeconv(3)" (et d'être affecté par les pièges) pour trouver le séparateur décimal, le séparateur de milliers ou le symbole monétaire. Voir "Perl_langinfo" dans perlapi.
  • Une nouvelle fonction d'API sv_rvunweaken() a été ajoutée pour compléter sv_rvweaken(). L'implémentation a été tirée de "unweaken" dans Scalar::Util.
  • Un nouveau drapeau, "SORTf_UNSTABLE", a été ajouté. Cela permettra à un futur commit de rendre le tri fusion instable lorsque l'utilisateur spécifie ‘pas de tri stable’, car il a été décidé que le tri fusion resterait stable par défaut.
  • Les modules XS peuvent désormais obtenir automatiquement des versions réentrantes des fonctions système sur les perls multithreadés.

    En ajoutant

    #define PERL_REENTRANT

    près du début d'un fichier "XS", il sera compilé de manière à ce que toutes les fonctions réentrantes que Perl connaît sur ce système soient automatiquement et invisiblement utilisées à la place des versions simples et non réentrantes. Par exemple, si vous écrivez getpwnam() dans votre code, sur un système qui possède getpwnam_r(), tous les appels à la première seront invisiblement traduits en la seconde. Cela ne se produit que sur les perls multithreadés, car ils ne sont pas nécessaires autrement. Soyez conscient que les fonctions qui ont des versions réentrantes varient d'un système à l'autre.

  • La définition de compilation "PERL_NO_OP_PARENT" n'est plus prise en charge, ce qui signifie que Perl est désormais toujours compilé avec "PERL_OP_PARENT" activé.
  • Le format et le contenu de la table de translittération non-utf8 attachée au champ "op_pv" des ops "OP_TRANS"/"OP_TRANSR" ont changé. Il s'agit désormais d'une "struct OPtrans_map".
  • Un nouveau "#define" de compilateur, "dTHX_DEBUGGING", a été ajouté. Il est utile pour le code XS ou C qui n'a besoin du contexte de thread que parce que ses instructions de débogage qui sont compilées uniquement sous "-DDEBUGGING" en ont besoin.
  • Une nouvelle fonction d'API "Perl_setlocale" dans perlapi a été ajoutée.
  • "sync_locale" dans perlapi a été révisé pour renvoyer un booléen indiquant si le système utilisait ou non la locale globale.
  • Un nouveau type de scalaire magique, appelé scalaire "nonelem", a été introduit. Il est stocké dans un tableau pour désigner un élément inexistant, chaque fois qu'un tel élément est accédé dans un contexte d'lvalue potentiel. Il remplace le magic "defelem" (élément différé) existant chaque fois que possible, étant significativement plus efficace. Cela signifie que some_sub($sparse_array[$nonelem]) n'a plus besoin de créer un nouveau scalaire defelem magique à chaque fois, tant que l'élément est dans le tableau.

    Il corrige partiellement le rare bug des éléments différés qui se désynchronisent avec leurs tableaux lorsque le tableau est décalé ou décalé. [GH #16364] https://github.com/Perl/perl5/issues/16364

Signalement des bogues

Si vous trouvez ce qui vous semble être un bogue, vous pourriez consulter la base de données des bogues de Perl à l'adresse https://rt.perl.org/. Il peut également y avoir des informations sur http://www.perl.org/, la page d'accueil de Perl.

Si vous pensez avoir un bogue non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bogue à un cas de test minuscule mais suffisant. Votre rapport de bogue, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl.

Si le bogue que vous signalez a des implications de sécurité qui le rendent inapproprié à l'envoi vers une liste de diffusion archivée publiquement, alors consultez la section "SECURITY VULNERABILITY CONTACT INFORMATION" dans perlsec pour plus de détails sur la manière de signaler le problème.
