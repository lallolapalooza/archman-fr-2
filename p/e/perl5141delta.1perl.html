NOM

perl5141delta - Quoi de neuf pour perl v5.14.1

DESCRIPTION

Ce document décrit les différences entre la version 5.14.0 et la version 5.14.1.

Si vous mettez à jour depuis une version antérieure comme 5.12.0, lisez d'abord perl5140delta, qui décrit les différences entre 5.12.0 et 5.14.0.

Améliorations du cœur

Aucun changement depuis 5.14.0.

Sécurité

Aucun changement depuis 5.14.0.

Changements incompatibles

Il n'y a aucun changement intentionnellement incompatible avec 5.14.0. S'il en existe, ce sont des bugs et les rapports sont les bienvenus.

Dépréciations

Aucune dépréciation depuis 5.14.0.

Modules et Pragmata mis à jour

  • B::Deparse a été mis à jour de la version 1.03 à 1.04, pour corriger deux régression dans Perl 5.14.0 :

    Le déparsage de l'opérateur "glob" et de sa forme avec losange ("<>") fonctionne à nouveau. [perl #90898]

    La présence de sous-routines nommées "::::" ou "::::::" ne fait plus planter B::Deparse.

  • Pod::Perldoc a été mis à jour de la version 3.15_03 à 3.15_04.

    Il corrige les chemins de recherche sur VMS. [perl #90640]

Changements dans la documentation existante

perlfunc

  • "given", "when" et "default" sont maintenant listés dans perlfunc.
  • La documentation pour "use" inclut maintenant un pointeur vers if.pm.

perllol

•
perllol a été enrichi avec des exemples utilisant la nouvelle syntaxe "push $scalar" introduite dans Perl 5.14.0.

perlop

  • L'explication des opérateurs binaires a été étendue pour expliquer comment ils fonctionnent sur les chaînes Unicode.
  • La section sur l'opérateur triple-point ou yada-yada a été déplacée plus haut, car elle séparait auparavant deux sections étroitement liées concernant l'opérateur virgule.
  • Plus d'exemples pour "m//g" ont été ajoutés.
  • La syntaxe de "here-doc" "<<\FOO" a été documentée.

perlrun

•
perlrun a subi un nettoyage significatif. Notamment, la forme -0x... de l'indicateur -0 a été clarifiée, et la dernière section sur les variables d'environnement a été corrigée et étendue.

POSIX

•
La documentation d'invocation pour "WIFEXITED", "WEXITSTATUS", "WIFSIGNALED", "WTERMSIG", "WIFSTOPPED", et "WSTOPSIG" a été corrigée.

Configuration et compilation

•
regexp.h a été modifié pour être compatible avec l'option "-Werror" de GCC, telle qu'utilisée par certains projets qui incluent les fichiers d'en-tête de perl.

Tests

  • Certains échecs de tests dans dist/Locale-Maketext/t/09_compile.t qui pouvaient survenir en fonction de l'environnement ont été corrigés. [perl #89896]
  • Un timer de surveillance pour t/re/re.t a été allongé pour tenir compte des systèmes SH-4 qui ne parvenaient pas à terminer les tests avant l'expiration du timer précédent.

Notes spécifiques aux plateformes

Solaris

•
La documentation listant les paquets Solaris requis pour compiler Perl sur Solaris 9 et Solaris 10 a été corrigée.

Mac OS X

  • Le script de test lib/locale.t a été mis à jour pour fonctionner sur la future version Lion.
  • Les instructions de compilation spécifiques à Mac OS X ont été clarifiées.

Ubuntu Linux

•
Le processus d'installation d' ODBM_File a été mis à jour avec les nouveaux chemins de bibliothèque sur Ubuntu natty.

Changements internes

•
La représentation compilée des formats est maintenant stockée via le ptr mg du PERL_MAGIC_fm. Auparavant, elle était stockée dans le buffer de chaîne, au-delà de SvLEN(), la fin normale de la chaîne. SvCOMPILED() et SvCOMPILED_{on,off}() existent maintenant uniquement pour la compatibilité avec le code XS. Le premier est toujours 0, les deux autres sont maintenant des no-ops.

Corrections de bugs

  • Un bug qui provoquait une erreur "Utilisation de valeur libérée en itération" si les deux éléments de hachage suivants qui devaient être itérés étaient supprimés, a été corrigé. [perl #85026]
  • Passer la même sous-routine constante à la fois à "index" et "formline" ne provoque plus l'échec de l'un ou l'autre. [perl #89218]
  • 5.14.0 a introduit des fuites de mémoire dans les classes de caractères d'expressions régulières comme "[\w\s]", qui ont maintenant été corrigées.
  • Un cas limite dans la correspondance d'expressions régulières pouvait potentiellement entrer dans une boucle. Cela se produisait uniquement sous "/i" dans les classes de caractères entre crochets contenant des caractères

Bug Fixes

  • Fixed a bug in the Unicode case-folding logic where multi-character folds were not handled correctly when the target string included a character with a multi-character fold that began with the remaining portion of the fold, plus some more. 
    "s\N{U+DF}" =~ /[\x{DF}foo]/i

    is one such case. "\xDF" folds to "ss".

  • Several Unicode case-folding bugs have been fixed.
  • The new (in 5.14.0) regular expression modifier "/a" when repeated like "/aa" forbids the characters outside the ASCII range that match characters inside that range from matching under "/i". This did not work under some circumstances, all involving alternation, such as: 
    "\N{KELVIN SIGN}" =~ /k|foo/iaa;

    succeeded inappropriately. This is now fixed.

  • Fixed a case where it was possible that a freed buffer may have been read from when parsing a here document.

Reporting Bugs

If you find what you think is a bug, you might check the articles recently posted to the comp.lang.perl.misc newsgroup and the perl bug database at http://rt.perl.org/perlbug/ . There may also be information at http://www.perl.org/ , the Perl Home Page.

If you believe you have an unreported bug, please run the perlbug program included with your release. Be sure to trim your bug down to a tiny but sufficient test case. Your bug report, along with the output of "perl -V", will be sent off to perlbug@perl.org to be analysed by the Perl porting team.

If the bug you are reporting has security implications, which make it inappropriate to send to a publicly archived mailing list, then please send it to perl5-security-report@perl.org. This points to a closed subscription unarchived mailing list, which includes all the core committers, who be able to help assess the impact of issues, figure out a resolution, and help co-ordinate the release of patches to mitigate or fix the problem across all platforms on which Perl is supported. Please only use this address for security issues in the Perl core, not for modules independently distributed on CPAN.
