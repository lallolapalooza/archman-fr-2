PERL5282DELTA(1perl) Guide de référence du programmeur Perl PERL5282DELTA(1perl)

NOM

perl5282delta - ce qu'il y a de nouveau pour la version perl v5.28.2

DESCRIPTION

Ce document décrit les différences entre la version 5.28.1 et la version 5.28.2.

Si vous effectuez une mise à niveau à partir d'une version antérieure, telle que la 5.28.0, lisez d'abord perl5281delta, qui décrit les différences entre la 5.28.0 et la 5.28.1.

CHANGEMENTS INCOMPATIBLES

Tout ensemble de chiffres du script commun est légal dans un script défilant d'un autre script

Il existe plusieurs ensembles de chiffres dans le script commun. "[0-9]" est le plus familier. Mais il y a aussi "[\x{FF10}-\x{FF19}]" (ZERO CHIFFRE PLEINE LARGEUR - NEUF CHIFFRE PLEINE LARGEUR), et plusieurs ensembles pour une utilisation dans la notation mathématique, tels que les chiffres à double traversée mathématique. N'importe lequel de ces ensembles devrait pouvoir apparaître dans des scripts défilants, par exemple, du grec. Mais la conception précédente avait négligé tous les chiffres à l'exception des chiffres ASCII "[0-9]", donc la conception était défectueuse. Cela a été corrigé, il s'agit donc à la fois d'une correction de bogue et d'une incompatibilité.

Tous les chiffres dans une série doivent toujours provenir du même ensemble de dix chiffres.

[GH #16704] https://github.com/Perl/perl5/issues/16704

MODULES ET PRAGMA

Modules et pragma mis à jour

  • Module::CoreList a été mis à niveau de la version 5.20181129_28 à 5.20190419.
  • PerlIO::scalar a été mis à niveau de la version 0.29 à 0.30.
  • Storable a été mis à niveau de la version 3.08 à 3.08_01.

SUPPORT PLATEFORME

Notes spécifiques à la plateforme

Windows
La compilation du SDK de plateforme Windows Server 2003 SP1, avec son compilateur et ses outils x64 précoces, a été accidentellement rompue dans Perl 5.27.9. Cela a maintenant été corrigé.
Mac OS X
Le processus de compilation et de test de Perl sur Mac OS X pour les compilations "-Duseshrplib" est maintenant compatible avec la protection de l'intégrité du système (SIP) de Mac OS X.

Le SIP empêche les binaires dans /bin (et quelques autres endroits) de recevoir la variable d'environnement "DYLD_LIBRARY_PATH". Pour nos besoins, cela empêche "DYLD_LIBRARY_PATH" d'être transmis au shell, ce qui empêche cette variable d'être transmise au processus de test ou de compilation. Ainsi, l'exécution de "perl" ne pouvait pas trouver libperl.dylib.

Pour contourner ce problème, la compilation initiale de l'exécutable perl s'attend à trouver libperl.dylib dans le répertoire de compilation, et le chemin de la bibliothèque est ensuite ajusté lors de l'installation pour pointer vers la bibliothèque installée.

[GH #15057] https://github.com/Perl/perl5/issues/15057

Corrections de bogues sélectionnées

  • Si une modification en place est toujours en cours lors de la destruction globale et que le code de sortie du processus (tel que stocké dans $?) est zéro, perl considérera désormais la modification en place comme réussie, remplaçant le fichier d'entrée par toute sortie produite.

    Cela permet un code comme :

    perl -i -ne 'print "Foo"; last'

    pour remplacer le fichier d'entrée, tandis que du code comme :

    perl -i -ne 'print "Foo"; die'

    ne le fera pas. Résout partiellement [perl #133659].

    [GH #16748] https://github.com/Perl/perl5/issues/16748

  • Une régression dans Perl 5.28 a fait échouer le code suivant : 
    close(STDIN); open(CHILD, "|wc -l")'

    car l'entrée standard de l'enfant serait fermée lors de l'exécution. Cela a maintenant été corrigé.

  • "pack "u", "invalid uuencoding"" termine maintenant correctement par un caractère NUL le SV de longueur nulle produit.

    [GH #16343] https://github.com/Perl/perl5/issues/16343

  • L'échec de compilation d'un format interrompt maintenant la compilation. Comme d'autres erreurs dans les sous-analyses, cela pourrait laisser l'analyseur dans un état étrange, risquant de faire planter Perl si la compilation continuait.

    [GH #16169] https://github.com/Perl/perl5/issues/16169

  • Voir "Tout ensemble de chiffres du script commun est légal dans un script défilant d'un autre script".

Remerciements

Perl 5.28.2 représente environ 4 mois de développement depuis Perl 5.28.1 et contient environ 2 500 lignes de modifications réparties sur 75 fichiers de 13 auteurs.

En excluant les fichiers générés automatiquement, la documentation et les outils de publication, il y a eu environ 1 200 lignes de modifications dans 29 fichiers .pm, .t, .c et .h.

Perl continue de prospérer au-delà de sa quatrième décennie grâce à une communauté dynamique d'utilisateurs et de développeurs. Les personnes suivantes sont connues pour avoir contribué aux améliorations qui sont devenues Perl 5.28.2 :

Aaron Crane, Abigail, Andy Dougherty, David Mitchell, Karen Etheridge, Karl Williamson, Leon Timmermans, Nicolas R., Sawyer X, Steve Hay, Tina Müller, Tony Cook, Zak B. Elep.

La liste ci-dessus est presque certainement incomplète car elle est générée automatiquement à partir de l'historique du contrôle de version. En particulier, elle n'inclut pas les noms des contributeurs (très appréciés) qui ont signalé des problèmes dans le suivi des bogues de Perl.

De nombreux changements inclus dans cette version proviennent des modules CPAN inclus dans le noyau de Perl. Nous sommes reconnaissants envers l'ensemble de la communauté CPAN pour avoir aidé Perl à prospérer.

Pour une liste plus complète de tous les contributeurs historiques de Perl, veuillez consulter le fichier AUTHORS dans la distribution source de Perl.

Signalement de bogues

Si vous trouvez ce que vous pensez être un bogue, vous pourriez consulter la base de données des bogues de perl à https://rt.perl.org/ . Il peut également y avoir des informations sur http://www.perl.org/ , la page d'accueil de Perl.

Si vous croyez avoir un bogue non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bogue à un cas de test minimal mais suffisant. Votre rapport de bogue, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl.

Si le bogue que vous signalez a des implications de sécurité qui le rendent inapproprié pour être envoyé à une liste de diffusion archivée publiquement, consultez "INFORMATIONS DE CONTACT SUR LES VULNÉRABILITÉS DE SÉCURITÉ" dans perlsec pour plus de détails sur la façon de signaler le problème.

Exprimer sa gratitude

Si vous souhaitez remercier les Perl 5 Porters pour le travail que nous avons accompli dans Perl 5, vous pouvez le faire en exécutant le programme "perlthanks" :

perlthanks

Cela enverra un e-mail à la liste Perl 5 Porters avec votre marque de remerciement.
