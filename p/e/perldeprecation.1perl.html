PERLDEPRECATION(1perl) Guide de référence du programmeur Perl PERLDEPRECATION(1perl)

NOM

perldeprecation - liste des dépréciations de Perl

DESCRIPTION

Le but de ce document est de documenter ce qui a été déprécié dans Perl, et par quelle version la fonctionnalité dépréciée disparaîtra, ou, pour les fonctionnalités déjà supprimées, quand elles ont été supprimées.

Ce document tentera de discuter des alternatives disponibles pour les fonctionnalités dépréciées.

Les fonctionnalités dépréciées seront regroupées par la version de Perl dans laquelle elles seront supprimées.

Dépréciations non planifiées

Les délimiteurs Unicode seront appairés

Certains délimiteurs Unicode étaient auparavant autorisés comme caractères uniques, mais deviendront à l'avenir une paire équilibrée. Cette catégorie de dépréciation est utilisée pour marquer ceux qui passeront de non appairés à appairés.

Catégorie : « déprécié::delimiter_will_be_paired »

Point dans Inc

Le répertoire de travail courant « . » était automatiquement inclus dans @INC, mais dans Perl 5.26, cela a été supprimé pour des raisons de sécurité. Depuis lors, nous avons émis un avertissement lorsqu'un utilisateur utilise « do EXPR » et que EXPR ne contient pas de chemin, et que le fichier n'a pas été trouvé dans un répertoire de @INC mais était bien situé dans « . ». Le fichier ne sera pas chargé mais un avertissement de dépréciation sera généré.

Catégorie : « déprécié::dot_in_inc »

Nom de propriété Unicode

Divers types de noms de propriétés Unicode généreront des avertissements de dépréciation lorsqu'ils sont utilisés dans un motif regex. Par exemple, les caractères substituts entraîneront des avertissements de dépréciation.

Catégorie : « déprécié::unicode_property_name »

Perl 5.44

Appel d'une méthode import() ou unimport() manquante avec un argument

Historiquement, l'appel de import() ou unimport() sur une classe qui ne définissait pas une telle méthode était ignoré silencieusement. Effectivement, Perl se comportait comme s'il y avait une méthode vide définie dans le paquet « UNIVERSAL » (même s'il n'y avait pas réellement de méthode définie). À partir de la version 5.39.2 de Perl, l'appel d'une telle méthode *avec* un argument déclenchera un avertissement, et dans la version 5.44 de Perl, cet avertissement sera transformé en erreur. (L'appel d'une telle méthode sans argument sera toujours sûr.)

Catégorie : « déprécié::missing_import_called_with_args »

Changement de « use VERSION » lorsqu'un autre « use VERSION » est dans la portée

Une déclaration « use VERSION » a de nombreux effets implicites sur la portée environnante, tels que les drapeaux strict et feature, ou l'importation de fonctions intégrées. Une fois qu'une instruction « use VERSION » est dans la portée, une autre instruction « use VERSION » avec une version différente est maintenant dépréciée depuis Perl 5.39.8, en raison de la complexité croissante du passage d'une version dominante à une autre.

Catégorie : « déprécié::subsequent_use_version »

Perl 5.42

Construction Goto Bloc

« goto LABEL; » produira un avertissement de dépréciation lorsqu'il sautera dans le corps d'une boucle ou d'une autre construction de bloc depuis l'extérieur. Par exemple,

while (should_loop($x)) {
    LABEL:
        do_stuff();
}
goto LABEL;

produira un avertissement indiquant que ce comportement est déprécié. En général, vous devriez simplement éviter de faire cela ; les personnes qui maintiendront votre code vous seront reconnaissantes de votre retenue.

Catégorie : « déprécié::goto_construct »

Perl 5.40

Rétrogradation d'un « use VERSION » à une version antérieure à v5.11

Une fois que Perl a vu une déclaration « use VERSION » qui demande une version égale ou supérieure à « v5.11 », une seconde déclaration ultérieure qui demande une version antérieure imprimera un avertissement de dépréciation. Par exemple,

use v5.14;
say "Nous pouvons utiliser les fonctionnalités de v5.14 ici";
use v5.10;        # Ceci imprime un avertissement

Ceci a été déprécié dans Perl 5.36 et est maintenant fatal.

Ceci est dû à un changement prévu et lié dans l'interaction entre « use VERSION » et « use strict ». Si vous spécifiez une version >= 5.11, strict est activé implicitement. Si vous demandez une version < 5.11, strict sera désactivé *même si vous aviez précédemment écrit* « use strict ». Ce n'était pas le comportement précédent de « use VERSION », qui à l'heure actuelle suit indépendamment les indicateurs strict explicitement activés.

Catégorie : « déprécié::version_downgrade »

Perl 5.38

Fonctions utilitaires de Pod::Html

La définition et la documentation de trois fonctions utilitaires précédemment importables depuis Pod::Html ont été déplacées vers le nouveau paquet Pod::Html::Util dans Perl 5.36. Bien qu'elles soient restées importables depuis Pod::Html dans Perl 5.36, depuis Perl 5.38, elles ne sont importables, sur demande, que depuis Pod::Html::Util.

Perl 5.34

Il n'y a eu aucune dépréciation ou fatalisation dans Perl 5.34.

Perl 5.32

Constantes issues de variables lexicales potentiellement modifiées ailleurs

Vous avez écrit quelque chose comme

my $var;
$sub = sub () { $var };

mais $var est référencé ailleurs et pourrait être modifié après l'évaluation de l'expression « sub ». Soit il est explicitement modifié ailleurs (« $var = 3 »), soit il est passé à une sous-routine ou à un opérateur comme « printf » ou « map », qui peuvent ou non modifier la variable.

Traditionnellement, Perl capturait la valeur de la variable à ce moment-là et transformait la sous-routine en une constante susceptible d'être inline. Dans les cas où la variable peut être modifiée ailleurs, cela casse le comportement des fermetures, où la sous-routine capture la variable elle-même, plutôt que sa valeur, de sorte que les changements futurs de la variable se reflètent dans la valeur de retour de la sous-routine.

Si vous aviez l'intention que la sous-routine soit susceptible d'être inline, assurez-vous que la variable n'est pas référencée ailleurs, éventuellement en la copiant :

my $var2 = $var;
$sub = sub () { $var2 };

Si vous souhaitez que cette sous-routine soit une fermeture qui reflète les changements futurs de la variable qu'elle encapsule, ajoutez un « return » explicite :

my $var;
$sub = sub () { return $var };

Cette utilisation était dépréciée et depuis Perl 5.32, elle n'est plus autorisée.

Utilisation de chaînes avec des points de code supérieurs à 0xFF comme arguments à « vec »

« vec » considère sa chaîne d'argument comme une séquence de bits. Une chaîne contenant un point de code supérieur à 0xFF est absurde. Cette utilisation est dépréciée dans Perl 5.28, et a été supprimée dans Perl 5.32.

Utilisation de points de code supérieurs à 0xFF dans les opérateurs bitwise sur chaînes

Les opérateurs bitwise sur chaînes, « & », « | », « ^ », et « ~ », traitent leurs opérandes comme des chaînes d'octets. En tant que tels, les valeurs supérieures à 0xFF sont absurdes. Certaines instances de celles-ci étaient dépréciées depuis Perl 5.24, et sont devenues fatales en 5.28, mais il s'avère que dans les cas où les caractères larges n'affectaient pas le résultat final, aucun avis de dépréciation n'était émis, et elles restaient donc légales. Perl 5.32

Wide character in &

The use of a wide character in the "&" operation, when the left operand is shorter than the right, was deprecated in Perl 5.32.

An example of this is

"" & "\x{100}"

The wide character is not used in the "&" operation because the left operand is shorter. This now throws an exception.

hostname() doesn't accept any arguments

The function hostname() in the Sys::Hostname module has always been documented to be called with no arguments. Historically it has not enforced this, and has actually accepted and ignored any arguments. As a result, some users have got the mistaken impression that an argument does something useful. To avoid these bugs, the function is being made strict. Passing arguments was deprecated in Perl 5.28 and became fatal in Perl 5.32.

Unescaped left braces in regular expressions

The simple rule to remember, if you want to match a literal "{" character (U+007B "LEFT CURLY BRACKET") in a regular expression pattern, is to escape each literal instance of it in some way. Generally easiest is to precede it with a backslash, like "\{" or enclose it in square brackets ("[{]"). If the pattern delimiters are also braces, any matching right brace ("}") should also be escaped to avoid confusing the parser, for example,

qr{abc\{def\}ghi}

Forcing literal "{" characters to be escaped will enable the Perl language to be extended in various ways in future releases. To avoid needlessly breaking existing code, the restriction is not enforced in contexts where there are unlikely to ever be extensions that could conflict with the use of "{" as a literal. A non-deprecation warning that the left brace is being taken literally is raised in contexts where there could be confusion about it.

Literal uses of "{" were deprecated in Perl 5.20, and some uses of it started to give deprecation warnings since. These cases were made fatal in Perl 5.26. Due to an oversight, not all cases of a use of a literal "{" got a deprecation warning. Some cases started warning in Perl 5.26, and were made fatal in Perl 5.30. Other cases started in Perl 5.28, and were made fatal in 5.32.

In XS code, use of various macros dealing with UTF-8

The macros below now require an extra parameter compared to versions prior to Perl 5.32. The final parameter in each one is a pointer into the string supplied by the first parameter beyond which the input will not be read. This prevents potential reading beyond the end of the buffer. "isALPHANUMERIC_utf8", "isASCII_utf8", "isBLANK_utf8", "isCNTRL_utf8", "isDIGIT_utf8", "isIDFIRST_utf8", "isPSXSPC_utf8", "isSPACE_utf8", "isVERTWS_utf8", "isWORDCHAR_utf8", "isXDIGIT_utf8", "isALPHANUMERIC_LC_utf8", "isALPHA_LC_utf8", "isASCII_LC_utf8", "isBLANK_LC_utf8", "isCNTRL_LC_utf8", "isDIGIT_LC_utf8", "isGRAPH_LC_utf8", "isIDCONT_LC_utf8", "isIDFIRST_LC_utf8", "isLOWER_LC_utf8", "isPRINT_LC_utf8", "isPSXSPC_LC_utf8", "isPUNCT_LC_utf8", "isSPACE_LC_utf8", "isUPPER_LC_utf8", "isWORDCHAR_LC_utf8", "isXDIGIT_LC_utf8", "toFOLD_utf8", "toLOWER_utf8", "toTITLE_utf8", and "toUPPER_utf8".

Since Perl 5.26, this functionality with the extra parameter has been available by using a corresponding macro to each one of these, and whose name is formed by appending "_safe" to the base name. There is no change to the functionality of those. For example, "isDIGIT_utf8_safe" corresponds to "isDIGIT_utf8", and both now behave identically. All are documented in "Character case changing" in perlapi and "Character classification" in perlapi.

This change was originally scheduled for 5.30, but was delayed until 5.32.

File::Glob::glob() was removed

"File::Glob" had a function called "glob", which just called "bsd_glob".

File::Glob::glob() was deprecated in Perl 5.8. A deprecation message was issued from Perl 5.26 onwards, the function became fatal in Perl 5.30, and was removed entirely in Perl 5.32.

Code using File::Glob::glob() should call File::Glob::bsd_glob() instead.

Perl 5.30

$* is no longer supported

Before Perl 5.10, setting $* to a true value globally enabled multi-line matching within a string. This relic from the past lost its special meaning in 5.10. Use of this variable became a fatal error in Perl 5.30, freeing the variable up for a future special meaning.

To enable multiline matching one should use the "/m" regexp modifier (possibly in combination with "/s"). This can be set on a per match basis, or can be enabled per lexical scope (including a whole file) with "use re '/m'".

$# is no longer supported

This variable used to have a special meaning -- it could be used to control how numbers were formatted when printed. This seldom used functionality was removed in Perl 5.10. In order to free up the variable for a future special meaning, its use became a fatal error in Perl 5.30.

To specify how numbers are formatted when printed, one is advised to use "printf" or "sprintf" instead.

Assigning non-zero to $[ is fatal

This variable (and the corresponding "array_base" feature and arybase module) allowed changing the base for array and string indexing operations.

Setting this to a non-zero value has been deprecated since Perl 5.12 and throws a fatal error as of Perl 5.30.

Unqualified dump()

Use of dump() instead of CORE::dump() was deprecated in Perl 5.8, and an unqualified dump() is no longer available as of Perl 5.30.

See "dump" in perlfunc.

Using my() in false conditional

There has been a long-standing bug in Perl that causes a lexical variable not to be cleared at scope exit when its declaration includes a false conditional. Some people have exploited this bug to achieve a kind of static variable. To allow us to fix this bug, people should not be relying on this behavior.

Instead, it's recommended one uses "state" variables to achieve the same effect:

use 5.10.0;
sub count {state $counter; return ++ $counter}
say count ();    # Prints 1
say count ();    # Prints 2

"state" variables were introduced in Perl 5.10.

Alternatively, you can achieve a similar static effect by declaring the variable in a separate block outside the function, e.g.,

sub f { my $x if 0; return $x++ }

becomes

{ my $x; sub f { return $x++ } }

The use of my() in a false conditional has been deprecated in Perl 5.10, and became a fatal error in Perl 5.30.

Reading/writing bytes from/to :utf8 handles

The sysread(), recv(), syswrite() and send() operators are deprecated on handles that have the ":utf8" layer, either explicitly, or implicitly, eg., with the :encoding(UTF-16LE) layer.

Both sysread() and recv() currently use only the ":utf8" flag for the stream, ignoring the actual layers. Since sysread() and recv() do no UTF-8 validation they can end up creating invalidly encoded scalars.

Similarly, syswrite() and send() use only the ":utf8" flag, otherwise ignoring any layers. If the flag is set, both write the value UTF-8 encoded, even if the layer is some different encoding, such as the UTF-16LE example above.

Ideally, all of these operators would completely ignore the ":utf8" state, working only with bytes, but this would result in silently breaking existing code. To avoid this a future version of perl will throw an exception when any of sysread(), recv(), syswrite() or send() are called on handles with the ":utf8" layer.

As of Perl 5.30, it is no longer possible to use sysread(), recv(), syswrite() or send() to read or send bytes from/to ":utf8" handles.

Use of unassigned code point or non-standalone grapheme for a delimiter

A grapheme is what appears to a native speaker of a language to be a character. In Unicode (and hence Perl) a grapheme may actually be several adjacent characters that together form a complete grapheme. For example, there can be a base character, like "R" and an accent, like a circumflex "^", that appear to be a single character when displayed, with the circumflex hovering over the "R".

Perl 5.30

Les délimiteurs des opérateurs de substitution, de recherche et de remplacement, ainsi que des opérateurs de présentation et de transformation des chaînes de caractères ("tr///"), ont été modifiés pour pouvoir accepter des multi-caractères graphiques comme délimiteurs.

De plus, depuis Perl 5.30, les délimiteurs qui sont des points de code non assignés mais qui pourraient éventuellement être assignés à l'avenir sont interdits. Sinon, un code qui fonctionne aujourd'hui échouerait à la compilation si le délimiteur actuellement non assigné s'avérait être quelque chose qui n'est pas un graphème autonome. Étant donné que Unicode n'assignera jamais de points de code non caractères, ni de points de code supérieurs au maximum légal de Unicode, ceux-ci peuvent être des délimiteurs.

Perl 5.28

Attributs ":locked" et ":unique"

Les attributs ":locked" (sur les références de code) et ":unique" (sur les références de tableaux, de hachages et scalaires) n'ont eu aucun effet depuis Perl 5.005 et Perl 5.8.8 respectivement. Leur utilisation a été dépréciée depuis.

Depuis Perl 5.28, ces attributs sont des erreurs de syntaxe. Comme les attributs ne font rien, leur suppression de votre code corrige l'erreur de syntaxe ; et leur suppression n'influencera pas le comportement de votre code.

Terminaisons de here-document nues

Perl vous a permis d'utiliser une terminaison de here-document nue "<<" pour que le here-document se termine à la première ligne vide. Cette pratique a été dépréciée dans Perl 5.000 ; depuis Perl 5.28, l'utilisation d'une terminaison de here-document nue provoque une erreur fatale.

Il vous est conseillé d'utiliser la forme explicitement citée si vous souhaitez utiliser une ligne vide comme terminaison du here-document :

print <<"";
  Imprime cette ligne.
# La ligne vide précédente termine le here-document.

Définition de $/ par une référence à un entier non positif

Vous avez assigné une référence à un scalaire à $/ où l'élément référencé n'est pas un entier positif. Dans les anciennes versions de Perl, cela semblait fonctionner de la même manière que de le définir à "undef", mais était en fait interne différent, moins efficace et, par malchance, aurait pu entraîner la division de votre fichier par une forme stringifiée de la référence.

Dans Perl 5.20.0, cela a été modifié pour que ce soit exactement la même chose que de définir $/ à "undef", à l'exception du fait que cet avertissement serait émis.

Depuis Perl 5.28, définir $/ par une référence à un entier non positif provoque une erreur fatale.

Il est recommandé de modifier votre code pour définir $/ explicitement à "undef" si vous souhaitez "aspirer" le fichier.

Limite sur la valeur des points de code Unicode

Unicode n'autorise que des points de code jusqu'à 0x10FFFF, mais Perl en autorise de beaucoup plus grands. Jusqu'à Perl 5.28, il était autorisé d'utiliser des points de code dépassant la valeur maximale d'un entier ("IV_MAX"). Cependant, cela cassait l'interpréteur perl dans certaines constructions, le faisant même planter dans quelques cas. Les domaines problématiques connus étaient dans "tr///", la correspondance de motif d'expressions régulières utilisant des quantificateurs, comme délimiteurs de guillemets dans "qX...X" (où X est le chr() d'un grand point de code), et comme limites supérieures dans les boucles.

L'utilisation de points de code hors plage a été dépréciée dans Perl 5.24 ; depuis Perl 5.28, l'utilisation d'un point de code dépassant "IV_MAX" provoque une erreur fatale.

Si votre code doit s'exécuter sur différentes plateformes, gardez à l'esprit que la limite supérieure dépend de la plateforme. Elle est beaucoup plus grande sur les tailles de mots 64 bits que sur les 32 bits. Pour les entiers 32 bits, "IV_MAX" est égal à 0x7FFFFFFF ; pour les entiers 64 bits, "IV_MAX" est égal à 0x7FFFFFFFFFFFFFFF.

Utilisation d'une liste de variables sans virgule dans les formats

Il était autorisé d'utiliser une liste de variables dans un format, sans les séparer par des virgules. Cette utilisation a été dépréciée depuis longtemps, et depuis Perl 5.28, cela provoque une erreur fatale.

Utilisation de "\N{}"

L'utilisation de "\N{}" sans rien entre les accolades a été dépréciée dans Perl 5.24, et provoque une erreur fatale depuis Perl 5.28.

Puisqu'une telle construction est équivalente à l'utilisation d'une chaîne vide, il est recommandé de supprimer de telles constructions "\N{}".

Utilisation du même symbole pour ouvrir un descripteur de fichier et un descripteur de répertoire

Il était auparavant légal d'utiliser open() pour associer à la fois un descripteur de fichier et un descripteur de répertoire au même symbole (glob ou scalaire). Cet idiome est susceptible d'être source de confusion, et a été déprécié dans Perl 5.10.

Utiliser le même symbole pour open() un descripteur de fichier et un descripteur de répertoire provoque une erreur fatale depuis Perl 5.28.

Vous devriez plutôt utiliser deux symboles différents.

${^ENCODING} n'est plus supporté

La variable spéciale "${^ENCODING}" était utilisée pour implémenter le pragma "encoding". Définir cette variable à autre chose que "undef" a été déprécié dans Perl 5.22. La dépréciation complète de la variable a eu lieu dans Perl 5.25.3.

Définir cette variable à autre chose qu'une valeur indéfinie provoque une erreur fatale depuis Perl 5.28.

"B::OP::terse"

Cette méthode, qui appelle simplement "B::Concise::b_terse", a été dépréciée, et a disparu dans Perl 5.28. Veuillez utiliser B::Concise à la place.

L'utilisation de AUTOLOAD héritée pour les fonctions non méthodes %s::%s() n'est plus autorisée

En tant que fonctionnalité accidentelle (ahem), les sous-routines "AUTOLOAD" étaient recherchées comme des méthodes (en utilisant la hiérarchie "@ISA") même lorsque les sous-routines à charger automatiquement étaient appelées comme des fonctions simples (par exemple, Foo::bar()), et non comme des méthodes (par exemple, "Foo->bar()" ou "$obj->bar()").

Ce bug a été déprécié dans Perl 5.004 et a été corrigé dans Perl 5.28 en utilisant la recherche de méthode uniquement pour les "AUTOLOAD" des méthodes.

La règle simple est : l'héritage ne fonctionnera pas lors du chargement automatique de fonctions non méthodes. La solution simple pour l'ancien code est : Dans tout module qui dépendait de l'héritage de "AUTOLOAD" pour des fonctions non méthodes d'une classe de base nommée "BaseClass", exécutez "*AUTOLOAD = \&BaseClass::AUTOLOAD" au démarrage.

Dans un code qui dit actuellement "use AutoLoader; @ISA = qw(AutoLoader);" vous devriez supprimer AutoLoader de @ISA et changer "use AutoLoader;" en "use AutoLoader 'AUTOLOAD';".

En code XS, utilisation de to_utf8_case()

Cette fonction a été supprimée depuis Perl 5.28 ; convertissez plutôt pour appeler la fonction appropriée parmi : "toFOLD_utf8_safe", "toLOWER_utf8_safe", "toTITLE_utf8_safe", ou "toUPPER_utf8_safe".

Perl 5.26

"--libpods" dans "Pod::Html"

Depuis Perl 5.18, l'option "--libpods" a été dépréciée, et son utilisation ne faisait rien d'autre que de produire un avertissement.

L'option "--libpods" n'est plus reconnue depuis Perl 5.26.

Les utilitaires "c2ph" et "pstruct"

Ces anciens utilitaires, datant de l'ère perl3, ont été dépréciés en faveur de "h2xs" pendant longtemps. Depuis Perl 5.26, ils ont été supprimés.

Interception de $SIG{__DIE__} autre que lors de la sortie du programme

Le hook $SIG{__DIE__} est appelé même à l'intérieur d'un eval(). Il n'était jamais prévu que cela se produise ainsi, mais un défaut d'implémentation l'a rendu possible. Cela était déprécié, car cela permettait des actions étranges à distance comme la réécriture d'une exception en attente dans $@. Les plans pour rectifier cela ont été abandonnés, car les utilisateurs ont trouvé que la réécriture d'une exception en attente est en fait une fonctionnalité utile, et non un bug.

Perl n'a jamais émis d'avertissement de dépréciation pour cela ; la dépréciation était uniquement par politique de documentation. Mais cette dépréciation a été levée depuis Perl 5.26.

Chaîne UTF-8 malformée dans "%s"

Ce message indique un bug soit dans le noyau de Perl, soit dans le code XS. Ce code essayait de déterminer si un caractère, prétendument stocké en interne encodé en UTF-8, était d'un type donné, comme être une ponctuation ou un chiffre. Mais le caractère n'était pas encodé en UTF-8 légal. Le %s est remplacé par une chaîne qui peut être utilisée par des personnes compétentes pour déterminer quel était le type vérifié.

La transmission de chaînes malformées a été dépréciée dans Perl 5.18, et est devenue fatale dans Perl 5.26.

Perl 5.24

Utilisation de *glob{FILEHANDLE}

L'utilisation de *glob{FILEHANDLE} a été dépréciée dans Perl 5.8. L'intention était d'utiliser *glob{IO} à la place, pour lequel *glob{FILEHANDLE} est un alias.

Cependant, cette fonctionnalité a été rétablie dans Perl 5.24.

Appel de POSIX::%s() est déprécié

Les fonctions suivantes du module "POSIX" ne sont plus disponibles : "isalnum", "isalpha", "iscntrl", "isdigit", "isgraph", "islower", "isprint", "ispunct".

>, "isspace", "isupper", et "isxdigit". Les fonctions sont boguées et ne fonctionnent pas sur les chaînes encodées en UTF-8. Voir leurs entrées dans POSIX pour plus d'informations.

Les fonctions ont été dépréciées dans Perl 5.20 et supprimées dans Perl 5.24.

Perl 5.16

Utilisation de %s sur un handle sans * est dépréciée

Il était possible d'utiliser "tie", "tied" ou "untie" sur un scalaire alors que le scalaire contenait un typeglob. Cela entraînait le tie du descripteur de fichier. Il n'y avait aucun moyen de faire le tie du scalaire lui-même lorsqu'il contenait un typeglob, et aucun moyen de défaire le tie d'un scalaire auquel un typeglob avait été assigné.

Cela a été déprécié dans Perl 5.14, et le bug a été corrigé dans Perl 5.16.

Ainsi, maintenant "tie $scalar" fera toujours le tie du scalaire, et non du handle qu'il contient. Pour faire le tie du handle, utilisez "tie *$scalar" (avec un astérisque explicite). La même chose s'applique à "tied *$scalar" et "untie *$scalar".
