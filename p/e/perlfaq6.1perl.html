Cette section est étonnamment petite car le reste de la FAQ est légèrement parsemé de réponses impliquant des expressions régulières. Par exemple, décoder une URL et vérifier si quelque chose est un nombre peut être géré avec des expressions régulières, mais ces réponses se trouvent ailleurs dans ce document (dans perlfaq9 : « Comment décoder ou créer ces encodages % sur le web » et perlfaq4 : « Comment déterminer si un scalaire est un nombre/entier/flottant »).

Comment puis-je espérer utiliser des expressions régulières sans créer de code illisible et difficile à maintenir ?

Trois techniques peuvent rendre les expressions régulières maintenables et compréhensibles.

Commentaires Extérieurs à l'Expression Régulière
Décrivez ce que vous faites et comment vous le faites, en utilisant des commentaires Perl normaux. 
# transformer la ligne en premier mot, deux-points, et le
# nombre de caractères dans le reste de la ligne
s/^(\w+)(.*)/ lc($1) . ":" . length($2) /meg;
Commentaires Intérieurs à l'Expression Régulière
Le modificateur "/x" fait que les espaces blancs sont ignorés dans un motif d'expression régulière (sauf dans une classe de caractères et quelques autres endroits), et vous permet aussi d'y utiliser des commentaires normaux. Comme vous pouvez l'imaginer, les espaces blancs et les commentaires aident beaucoup.

"/x" vous permet de transformer ceci :

s{<(?:[^>'"]*|".*?"|'.*?')+>}{}gs;

en ceci :

s{ <                    # crochet ouvrant
    (?:                 # Groupe sans retour arrière
        [^>'"] *        # 0 ou plusieurs caractères qui ne sont ni > ni ' ni "
            |           #    ou
        ".*?"           # une section entre guillemets doubles (appariement non gourmand)
            |           #    ou
        '.*?'           # une section entre apostrophes (appariement non gourmand)
    ) +                 #   le tout se produisant une ou plusieurs fois
    >                   # crochet fermant
}{}gsx;                 # remplacer par rien, c'est-à-dire supprimer

Ce n'est toujours pas aussi clair qu'en prose, mais c'est très utile pour décrire la signification de chaque partie du motif.

Délimiteurs Différents
Bien que nous pensions normalement aux motifs délimités par des caractères "/", ils peuvent être délimités par presque n'importe quel caractère. perlre décrit cela. Par exemple, le "s///" ci-dessus utilise des accolades comme délimiteurs. Choisir un autre délimiteur peut éviter d'échapper le délimiteur au sein du motif : 
s/\/usr\/local/\/usr\/share/g;    # mauvais choix de délimiteur
s#/usr/local#/usr/share#g;        # meilleur

L'utilisation de délimiteurs logiquement appariés peut être encore plus lisible :

s{/usr/local/}{/usr/share}g;      # encore mieux

J'ai du mal à faire des correspondances sur plusieurs lignes. Qu'est-ce qui ne va pas ?

Soit vous n'avez pas plus d'une ligne dans la chaîne que vous regardez (probablement), soit vous n'utilisez pas le ou les modificateurs corrects sur votre motif (possiblement).

Il existe de nombreuses façons d'obtenir des données multilignes dans une chaîne. Si vous voulez que cela se produise automatiquement lors de la lecture de l'entrée, vous voudrez définir $/ (probablement à '' pour des paragraphes ou "undef" pour tout le fichier) pour vous permettre de lire plus d'une ligne à la fois.

Lisez perlre pour vous aider à décider lesquels des modificateurs "/s" et "/m" (ou les deux) vous pourriez vouloir utiliser : "/s" permet au point d'inclure le saut de ligne, et "/m" permet au caret et au dollar de correspondre à côté d'un saut de ligne, pas seulement à la fin de la chaîne. Vous devez vous assurer que vous avez réellement une chaîne multiligne dans votre variable.

Par exemple, ce programme détecte les mots dupliqués, même lorsqu'ils chevauchent des sauts de ligne (mais pas des sauts de paragraphe). Pour cet exemple, nous n'avons pas besoin de "/s" car nous n'utilisons pas le point dans une expression régulière que nous voulons faire traverser des limites de ligne. Nous n'avons pas non plus besoin de "/m" car nous ne voulons pas que le caret ou le dollar correspondent à n'importe quel point à l'intérieur de l'enregistrement à côté des sauts de ligne. Mais il est impératif que $/ soit défini à autre chose que la valeur par défaut, sinon nous n'aurons jamais réellement d'enregistrement multiligne lu.

$/ = '';          # lire tout le paragraphe, pas seulement une ligne
while ( <> ) {
    while ( /\b([\w'-]+)(\s+\g1)+\b/gi ) {     # le mot commence par une lettre
        print "Dupliqué $1 au paragraphe $.\n";
    }
}

Voici un code qui trouve les phrases commençant par « From » (ce qui serait modifié par de nombreux mailers) :

$/ = '';          # lire tout le paragraphe, pas seulement une ligne
while ( <> ) {
    while ( /^From /gm ) { # /m fait correspondre ^ à côté de \n
    print "From en tête du paragraphe $.\n";
    }
}

Voici un code qui trouve tout entre START et END dans un paragraphe :

undef $/;          # lire tout le fichier, pas seulement une ligne ou un paragraphe
while ( <> ) {
    while ( /START(.*?)END/sgm ) { # /s fait traverser . les limites de ligne
        print "$1\n";
    }
}

Comment puis-je extraire les lignes entre deux motifs qui se trouvent eux-mêmes sur des lignes différentes ?

Vous pouvez utiliser l'opérateur quelque peu exotique ".." de Perl (documenté dans perlop) :

perl -ne 'print if /START/ .. /END/' fichier1 fichier2 ...

Si vous vouliez du texte et pas des lignes, vous utiliseriez

perl -0777 -ne 'print "$1\n" while /START(.*?)END/gs' fichier1 fichier2 ...

Mais si vous voulez des occurrences imbriquées de "START" à "END", vous rencontrerez le problème décrit dans la question de cette section sur la correspondance de texte équilibré.

Voici un autre exemple d'utilisation de ".." :

while (<>) {
    my $in_header =   1  .. /^$/;
    my $in_body   = /^$/ .. eof;
# maintenant, choisissez entre eux
} continue {
    $. = 0 if eof;    # corriger $.
}

Comment puis-je faire la correspondance de XML, HTML, ou d'autres choses méchantes et laides avec une expression régulière ?

N'utilisez pas d'expressions régulières. Utilisez un module et oubliez les expressions régulières. Les modules XML::LibXML, HTML::TokeParser et HTML::TreeBuilder sont de bons points de départ, bien que chaque espace de noms ait d'autres modules d'analyse spécialisés pour certaines tâches et différentes manières de le faire. Commencez par la recherche CPAN ( http://metacpan.org/ ) et émerveillez-vous de tout le travail que d'autres ont déjà fait pour vous ! :)

J'ai mis une expression régulière dans $/ mais ça n'a pas marché. Qu'est-ce qui ne va pas ?

$/ doit être une chaîne. Vous pouvez utiliser ces exemples si vous avez vraiment besoin de le faire.

Si vous avez File::Stream, c'est facile.

use File::Stream;
my $stream = File::Stream->new(
    $handle_fichier,
    separator => qr/\s*,\s*/,
    );
print "$_\n" while <$stream>;

Si vous n'avez pas File::Stream, vous devez faire un peu plus de travail.

Vous pouvez utiliser la forme à quatre arguments de sysread pour ajouter continuellement à un tampon. Après avoir ajouté au tampon, vous vérifiez si vous avez une ligne complète (en utilisant votre expression régulière).

local $_ = "";
while( sysread FH, $_, 8192, length ) {
    while( s/^((?s).*?)your_pattern// ) {
        my $record = $1;
        # faire quelque chose ici.
    }
}

Comment traiter un fichier tampon par tampon ?

Si vous avez un fichier trop volumineux pour tenir dans la mémoire, vous pouvez lire jusqu'à 8 Ko à la fois, comme suit.

local $_ = "";
while( sysread FH, $_, 8192, length ) {
    foreach my $record ( m/\G((?s).*?)your_pattern/gc ) {
        # faire quelque chose ici.
    }
    substr( $_, 0, pos ) = "" if pos;
}

Ceci est un exemple de traitement de fichier par morceaux. Il utilise la fonction sysread pour lire des portions de 8 Ko du fichier FH dans la variable $_. La fonction length est utilisée comme troisième argument de sysread pour spécifier la position de départ de la lecture dans la chaîne $_. Cela permet de lire le fichier de manière incrémentale, sans tout charger en mémoire.

L'expression régulière m/\G((?s).*?)your_pattern/gc est utilisée pour trouver des motifs dans le tampon lu. Le modificateur \G assure que la recherche continue à partir de la fin de la correspondance précédente. Le modificateur (?s) permet au point . de correspondre également aux nouvelles lignes, traitant ainsi le tampon comme une seule chaîne. Le modificateur g active la recherche globale pour trouver toutes les correspondances dans le tampon, et le modificateur c permet de continuer la recherche après une correspondance sans réinitialiser la position du motif.

Après avoir trouvé une correspondance, le code dans la boucle foreach est exécuté. Ensuite, la partie du tampon qui a déjà été traitée est supprimée à l'aide de substr( $_, 0, pos ) = "" if pos;. Ceci est essentiel pour que la recherche \G fonctionne correctement lors de la lecture des portions suivantes du fichier.

Notez que cette approche suppose que vous pouvez faire tenir la partie la plus grande de votre enregistrement dans la mémoire. Si vous avez besoin de traiter des enregistrements qui peuvent dépasser 8 Ko, vous devrez peut-être ajuster la taille du tampon ou utiliser une approche différente, par exemple en recherchant des délimiteurs d'enregistrement spécifiques.

Cette méthode est particulièrement utile pour traiter de grands fichiers de journal, des fichiers de données volumineux, ou toute autre situation où vous devez analyser des données qui ne tiennent pas en mémoire vive. Elle permet de maintenir une empreinte mémoire faible tout en traitant efficacement de grandes quantités de données.

La possibilité de charger le fichier entier en mémoire à la fin peut être utile pour certaines opérations, mais doit être utilisée avec prudence, car elle peut consommer beaucoup de mémoire pour les fichiers très volumineux.

Comment substituer de manière insensible à la casse à gauche de l'opérateur tout en préservant la casse à droite ?

Voici une belle solution à la Perle par Larry Rosler. Elle exploite les propriétés du XOR bit à bit sur les chaînes ASCII.

$_= "this is a TEsT case";
$old = 'test';
$new = 'success';
s{(\Q$old\E)}
{ uc $new | (uc $1 ^ $1) .
    (uc(substr $1, -1) ^ substr $1, -1) x
    (length($new) - length $1)
}egi;
print;

Et voici la même chose sous forme de sous-routine, basée sur ce qui précède :

sub preserve_case {
    my ($old, $new) = @_;
    my $mask = uc $old ^ $old;
    uc $new | $mask .
        substr($mask, -1) x (length($new) - length($old))
}
$string = "this is a TEsT case";
$string =~ s/(test)/preserve_case($1, "success")/egi;
print "$string\n";

Ceci affiche :

this is a SUcCESS case

Alternativement, pour conserver la casse du mot de remplacement s'il est plus long que l'original, vous pouvez utiliser ce code, par Jeff Pinyan :

sub preserve_case {
    my ($from, $to) = @_;
    my ($lf, $lt) = map length, @_;
    if ($lt < $lf) { $from = substr $from, 0, $lt }
    else { $from .= substr $to, $lf }
    return uc $to | ($from ^ uc $from);
}

Ceci transforme la phrase en "this is a SUcCess case."

Juste pour montrer que les programmeurs C peuvent écrire du C dans n'importe quel langage de programmation, si vous préférez une solution plus proche du C, le script suivant fait en sorte que la substitution ait la même casse, lettre par lettre, que l'original. (Il s'exécute également environ 240 % plus lentement que la solution à la Perle.) Si la substitution a plus de caractères que la chaîne substituée, la casse du dernier caractère est utilisée pour le reste de la substitution.

# Original par Nathan Torkington, retravaillé par Jeffrey Friedl
#
sub preserve_case
{
    my ($old, $new) = @_;
    my $state = 0; # 0 = pas de changement; 1 = lc; 2 = uc
    my ($i, $oldlen, $newlen, $c) = (0, length($old), length($new));
    my $len = $oldlen < $newlen ? $oldlen : $newlen;
    for ($i = 0; $i < $len; $i++) {
        if ($c = substr($old, $i, 1), $c =~ /[\W\d_]/) {
            $state = 0;
        } elsif (lc $c eq $c) {
            substr($new, $i, 1) = lc(substr($new, $i, 1));
            $state = 1;
        } else {
            substr($new, $i, 1) = uc(substr($new, $i, 1));
            $state = 2;
        }
    }
    # terminer avec les nouveaux caractères restants (pour quand new est plus long que old)
    if ($newlen > $oldlen) {
        if ($state == 1) {
            substr($new, $oldlen) = lc(substr($new, $oldlen));
        } elsif ($state == 2) {
            substr($new, $oldlen) = uc(substr($new, $oldlen));
        }
    }
    return $new;
}

Comment faire en sorte que "\w" corresponde aux jeux de caractères nationaux ?

Placez "use locale;" dans votre script. La classe de caractères \w est tirée de la locale actuelle.

Voir perllocale pour plus de détails.

Comment faire correspondre une version "intelligente pour la locale" de "/[a-zA-Z]/" ?

Vous pouvez utiliser la syntaxe des classes de caractères POSIX "/[[:alpha:]]/" documentée dans perlre.

Quelle que soit la locale, les caractères alphabétiques sont les caractères de \w sans les chiffres et le trait de soulignement. En tant qu'expression régulière, cela ressemble à "/[^\W\d_]/". Son complément, les non-alphabétiques, est alors tout dans \W avec les chiffres et le trait de soulignement, ou "/[\W\d_]/".

Comment échapper une variable pour l'utiliser dans une expression régulière ?

L'analyseur Perl développera les références $variable et @variable dans les expressions régulières, à moins que le délimiteur ne soit une apostrophe. Rappelez-vous également que le côté droit d'une substitution "s///" est considéré comme une chaîne entre guillemets doubles (voir perlop pour plus de détails). N'oubliez pas non plus que tous les caractères spéciaux des expressions régulières seront traités, sauf si vous faites précéder la substitution de \Q. Voici un exemple :

$string = "Placido P. Octopus";
$regex  = "P.";
$string =~ s/$regex/Polyp/;
# $string est maintenant "Polypacido P. Octopus"

Comme "." est spécial dans les expressions régulières, et peut correspondre à n'importe quel caractère unique, l'expression régulière "P." a ici correspondu à <Pl> dans la chaîne originale.

Pour échapper la signification spéciale de ".", nous utilisons "\Q" :

$string = "Placido P. Octopus";
$regex  = "P.";
$string =~ s/\Q$regex/Polyp/;
# $string est maintenant "Placido Polyp Octopus"

L'utilisation de "\Q" fait que le "." dans l'expression régulière est traité comme un caractère ordinaire, de sorte que "P." correspond à un "P" suivi d'un point.

À quoi sert vraiment "/o" ?

(contribué par brian d foy)

L'option "/o" pour les expressions régulières (documentée dans perlop et perlreref) indique à Perl de compiler l'expression régulière une seule fois. Ceci n'est utile que lorsque le motif contient une variable. Perl 5.6 et versions ultérieures gèrent cela automatiquement si le motif ne change pas.

Étant donné que l'opérateur de correspondance "m//", l'opérateur de substitution "s///" et l'opérateur d'échappement d'expression régulière "qr//" sont des constructions de type guillemets doubles, vous pouvez interpoler des variables dans le motif. Voir la réponse à "Comment échapper une variable pour l'utiliser dans une expression régulière ?" pour plus de détails.

Cet exemple prend une expression régulière de la liste d'arguments et affiche les lignes d'entrée qui y correspondent :

my $pattern = shift @ARGV;
while( <> ) {
    print if m/$pattern/;
}

Les versions de Perl antérieures à 5.6 recompilez l'expression régulière pour chaque itération, même si $pattern n'avait pas changé. Le "/o" empêchait cela en indiquant à Perl de compiler le motif lors de la première itération, puis de le réutiliser pour les itérations suivantes :

my $pattern = shift @ARGV;
while( <> ) {
    print if m/$pattern/o; # utile pour Perl < 5.6
}

Dans les versions 5.6 et ultérieures, Perl ne recompilera pas l'expression régulière si la variable n'a pas changé, vous n'avez donc probablement pas besoin de l'option "/o". Elle ne fait pas de mal, mais elle n'aide pas non plus. Si vous voulez que n'importe quelle version de Perl compile l'expression régulière une seule fois, même si la variable change (utilisant ainsi seulement sa valeur initiale), vous avez toujours besoin de l'"/o".

Vous pouvez observer le moteur d'expressions régulières de Perl en action pour vérifier par vous-même si Perl recompilait une expression régulière. Le pragma use re 'debug' (livré avec Perl 5.005 et versions ultérieures) affiche les détails. Avec les versions de Perl antérieures à 5.6, vous devriez voir "re" rapporter qu'il compile l'expression régulière à chaque itération. Avec Perl 5.6 ou version ultérieure, vous ne devriez voir "re" le rapporter que pour la première itération.

use re 'debug';
my $regex = 'Perl';
foreach ( qw(Perl Java Ruby Python) ) {
    print STDERR "-" x 73, "\n";
    print STDERR "Trying $_...\n";
    print STDERR "\t$_ is good!\n" if m/$regex/;
}

Comment utiliser une expression régulière pour supprimer les commentaires de style C d'un fichier ?

Bien que cela puisse effectivement être fait, c'est beaucoup plus difficile que vous ne le pensez. Par exemple, cette ligne de commande unique

perl -0777 -pe 's{/\*.*?\*/}{}gs' foo.c

fonctionnera dans de nombreux cas, mais pas tous. En effet, elle est trop simpliste pour certains types de programmes C, en particulier ceux qui contiennent des commentaires dans des chaînes entre guillemets. Pour cela, il vous faudrait quelque chose comme ceci, créé par Jeffrey Friedl et modifié plus tard par Fred Curtis.

$/ = undef;
$_ = <>;
s#/\*[^*]*\*+([^/*][^*]*\*+)*/|("(\\.|[^"\\])*"|'(\\.|[^'\\])*'|.[^/"'\\]*)#defined $2 ? $2 : ""#gse;
print;

Ceci pourrait, bien sûr, être écrit de manière plus lisible avec le modificateur "/x", en ajoutant des espaces et des commentaires. Le voici développé, avec l'aimable autorisation de Fred Curtis.

s{
   /\*         ##  Début du commentaire /* ... */
   [^*]*\*+    ##  Non-* suivi de 1 ou plusieurs *
   (
     [^/*][^*]*\*+
   )*          ##  0 ou plusieurs choses qui ne commencent pas par /
               ##    mais se terminent par '*'
   /           ##  Fin du commentaire /* ... */
 |         ##     OU  divers éléments qui ne sont pas des commentaires :
   (
     "           ##  Début de la chaîne " ... "
     (
       \\.           ##  Caractère échappé
     |               ##    OU
       [^"\\]        ##  Non " ou \
     )*
     "           ##  Fin de la chaîne " ... "
   |         ##     OU
     '           ##  Début de la chaîne ' ... '
     (
       \\.           ##  Caractère échappé
     |               ##    OU
       [^'\\]        ##  Non ' ou \
     )*
     '           ##  Fin de la chaîne ' ... '
   |         ##     OU
     .           ##  N'importe quel autre caractère
     [^/"'\\]*   ##  Caractères qui ne commencent pas un commentaire, une chaîne ou une échappatoire
   )
 }{defined $2 ? $2 : ""}gxse;

Une légère modification supprime également les commentaires C++, pouvant potentiellement s'étendre sur plusieurs lignes à l'aide d'un caractère de continuation :

s#/\*[^*]*\*+([^/*][^*]*\*+)*/|//([^\\]|[^\n][\n]?)*?\n|("(\\.|[^"\\])*"|'(\\.|[^'\\])*'|.[^/"'\\]*)#defined $3 ? $3 : ""#gse;

Puis-je utiliser les expressions régulières Perl pour faire correspondre du texte équilibré ?

Puis-je utiliser les expressions régulières Perl pour faire correspondre du texte équilibré ?

(contribué par brian d foy)

Votre première tentative devrait probablement être le module Text::Balanced, qui se trouve dans la bibliothèque standard Perl depuis la version Perl 5.8. Il dispose d'une variété de fonctions pour traiter du texte difficile. Le module Regexp::Common peut également aider en fournissant des modèles prédéfinis que vous pouvez utiliser.

Depuis Perl 5.10, vous pouvez faire correspondre du texte équilibré avec des expressions régulières en utilisant des motifs récursifs. Avant Perl 5.10, vous deviez recourir à diverses astuces telles que l'utilisation de code Perl dans des séquences "(??{})".

Voici un exemple utilisant une expression régulière récursive. L'objectif est de capturer tout le texte entre crochets angulaires, y compris le texte dans les crochets angulaires imbriqués. Cet exemple de texte contient deux groupes « majeurs » : un groupe avec un niveau d'imbrication et un groupe avec deux niveaux d'imbrication. Il y a cinq groupes au total entre crochets angulaires :

I have some <brackets in <nested brackets> > and
<another group <nested once <nested twice> > >
and that's it.

L'expression régulière pour faire correspondre le texte équilibré utilise deux nouvelles fonctionnalités (pour Perl 5.10) des expressions régulières. Celles-ci sont couvertes dans perlre et cet exemple est une version modifiée de l'une d'elles dans cette documentation.

Premièrement, ajouter le nouveau quantificateur possessif "+" à n'importe quel quantificateur trouve la correspondance la plus longue et ne revient pas en arrière. C'est important car vous voulez gérer tous les crochets angulaires via la récursion, et non par retour arrière. Le groupe "[^<>]++" trouve un ou plusieurs caractères qui ne sont pas des crochets, sans retour arrière.

Deuxièmement, le nouveau "(?PARNO)" fait référence au sous-motif dans le groupe de capture particulier donné par "PARNO". Dans l'expression régulière suivante, le premier groupe de capture trouve (et mémorise) le texte équilibré, et vous avez besoin de ce même motif dans le premier tampon pour passer le texte imbriqué. C'est la partie récursive. Le "(?1)" utilise le motif du groupe de capture externe comme partie indépendante de l'expression régulière.

En assemblant le tout, vous obtenez :

#!/usr/local/bin/perl5.10.0
my $string =<<"HERE";
I have some <brackets in <nested brackets> > and
<another group <nested once <nested twice> > >
and that's it.
HERE
my @groups = $string =~ m/
        (                   # start of capture group 1
        <                   # match an opening angle bracket
            (?:
                [^<>]++     # one or more non angle brackets, non backtracking
                  |
                (?1)        # found < or >, so recurse to capture group 1
            )*
        >                   # match a closing angle bracket
        )                   # end of capture group 1
        /xg;
$" = "\n\t";
print "Found:\n\t@groups\n";

La sortie montre que Perl a trouvé les deux groupes principaux :

Found:
    <brackets in <nested brackets> >
    <another group <nested once <nested twice> > >

Avec un peu de travail supplémentaire, vous pouvez obtenir tous les groupes entre crochets angulaires, même s'ils sont également dans d'autres crochets angulaires. Chaque fois que vous obtenez une correspondance équilibrée, supprimez son délimiteur externe (celui que vous venez de faire correspondre, donc ne le faites pas correspondre à nouveau) et ajoutez-le à une file d'attente de chaînes à traiter. Continuez ainsi jusqu'à ce que vous n'obteniez plus de correspondances :

#!/usr/local/bin/perl5.10.0
my @queue =<<"HERE";
I have some <brackets in <nested brackets> > and
<another group <nested once <nested twice> > >
and that's it.
HERE
my $regex = qr/
        (                   # start of bracket 1
        <                   # match an opening angle bracket
            (?:
                [^<>]++     # one or more non angle brackets, non backtracking
                  |
                (?1)        # recurse to bracket 1
            )*
        >                   # match a closing angle bracket
        )                   # end of bracket 1
        /x;
$" = "\n\t";
while( @queue ) {
    my $string = shift @queue;
    my @groups = $string =~ m/$regex/g;
    print "Found:\n\t@groups\n\n" if @groups;
    unshift @queue, map { s/^<//; s/>$//; $_ } @groups;
}

La sortie montre tous les groupes. Les correspondances les plus externes apparaissent en premier et les correspondances imbriquées apparaissent plus tard :

Found:
    <brackets in <nested brackets> >
    <another group <nested once <nested twice> > >
Found:
    <nested brackets>
Found:
    <nested once <nested twice> >
Found:
    <nested twice>

Que signifie le fait que les expressions régulières soient avides ? Comment puis-je contourner cela ?

La plupart des gens veulent dire par "expressions régulières avides" qu'elles correspondent au plus de texte possible. Techniquement parlant, ce sont en fait les quantificateurs ("?", "*", "+", "{}") qui sont avides plutôt que le modèle entier ; Perl préfère la gourmandise locale et la gratification immédiate à la gourmandise globale. Pour obtenir des versions non avides des mêmes quantificateurs, utilisez ("??", "*?", "+?", "{}?").

Un exemple :

my $s1 = my $s2 = "I am very very cold";
$s1 =~ s/ve.*y //;      # I am cold
$s2 =~ s/ve.*?y //;     # I am very cold

Remarquez comment la deuxième substitution a arrêté de correspondre dès qu'elle a rencontré "y ". Le quantificateur "*?" indique effectivement au moteur d'expressions régulières de trouver une correspondance aussi rapidement que possible et de passer le contrôle à ce qui suit, comme vous le feriez en jouant à la patate chaude.

Comment traiter chaque mot sur chaque ligne ?

Utilisez la fonction split :

while (<>) {
    foreach my $word ( split ) {
        # do something with $word here
    }
}

Notez qu'il ne s'agit pas vraiment d'un mot au sens anglais ; ce sont juste des morceaux de caractères consécutifs qui ne sont pas des espaces blancs.

Pour travailler uniquement avec des séquences alphanumériques (y compris les traits de soulignement), vous pourriez envisager :

while (<>) {
    foreach $word (m/(\w+)/g) {
        # do something with $word here
    }
}

Comment puis-je imprimer un résumé de fréquence de mots ou de lignes ?

Pour ce faire, vous devez analyser chaque mot dans le flux d'entrée. Nous allons prétendre que par mot vous entendez un morceau de lettres, de traits d'union ou d'apostrophes, plutôt que le morceau de caractères sans espace blanc qui définit un mot dans la question précédente :

my (%seen);
while (<>) {
    while ( /(\b[^\W_\d][\w'-]+\b)/g ) {   # misses "`sheep'"
        $seen{$1}++;
    }
}
while ( my ($word, $count) = each %seen ) {
    print "$count $word\n";
}

Si vous vouliez faire la même chose pour les lignes, vous n'auriez pas besoin d'une expression régulière :

my (%seen);
while (<>) {
    $seen{$_}++;
}
while ( my ($line, $count) = each %seen ) {
    print "$count $line";
}

Si vous souhaitez que ces résultats soient triés, voir perlfaq4 : « How do I sort a hash (optionally by value instead of key)? ».

Comment puis-je faire de la correspondance approximative ?

Voir le module String::Approx disponible sur CPAN.

Comment faire correspondre efficacement plusieurs expressions régulières à la fois ?

(contribué par brian d foy)

Vous voulez éviter de compiler une expression régulière chaque fois que vous souhaitez la faire correspondre. Dans cet exemple, perl doit recompiler l'expression régulière pour chaque itération de la boucle "foreach" car $pattern peut changer :

my @patterns = qw( fo+ ba[rz] );
LINE: while( my $line = <> ) {
    foreach my $pattern ( @patterns ) {
        if( $line =~ m/\b$pattern\b/i ) {
            print $line;
            next LINE;
        }
    }
}

L'opérateur "qr//" compile une expression régulière, mais ne l'applique pas. Lorsque vous utilisez la version pré-compilée de l'expression régulière, perl fait moins de travail. Dans cet exemple, j'ai inséré un "map" pour transformer chaque motif en sa forme pré-compilée. Le reste du script est le même, mais plus rapide :

my @patterns = map { qr/\b$_\b/i } qw( fo+ ba[rz] );
LINE: while( my $line = <> ) {
    foreach my $pattern ( @patterns ) {
        if( $line =~ m/$pattern/ ) {
            print $line;
            next LINE;
        }
    }
}

Dans certains cas, vous pourrez peut-être transformer plusieurs motifs en une seule expression régulière. Méfiez-vous cependant des situations qui nécessitent un retour arrière. Dans cet exemple, l'expression régulière n'est compilée qu'une seule fois car $regex ne change pas entre les itérations :

my $regex = join '|', qw( fo+ ba[rz] );
while( my $line = <> ) {
    print if $line =~ m/\b(?:$regex)\b/i;
}

La fonction « list2re » dans Data::Munge sur CPAN peut également être utilisée pour former une seule expression régulière qui fait correspondre une liste de chaînes littérales (pas des expressions régulières).

Pour plus de détails sur l'efficacité des expressions régulières, voir « Mastering Regular Expressions » par Jeffrey Friedl. Il explique comment fonctionne le moteur d'expressions régulières et pourquoi certains motifs sont étonnamment inefficaces. Une fois que vous comprenez comment perl applique les expressions régulières, vous pouvez les optimiser pour des situations individuelles.

Pourquoi les recherches de limites de mots avec "\b" ne fonctionnent-elles pas pour moi ?

(contribué par brian d foy)

Assurez-vous de savoir ce que fait réellement \b : c'est la limite entre un caractère de mot, \w, et quelque chose qui n'est pas un caractère de mot. Cette chose qui n'est pas un caractère de mot peut être \W, mais elle peut aussi être le début ou la fin de la chaîne.

Ce n'est pas (pas du tout !) la limite entre les espaces blancs et les non-espaces blancs, et ce n'est pas ce qui se trouve entre les mots que nous utilisons pour créer des phrases.

Dans le langage des expressions régulières, une limite de mot (\b) est une « assertion de largeur zéro »

Détails des expressions régulières

This FAQ section is concerned with the nitty-gritty details of regular expressions, the sorts of things that might trip you up if you're not careful.

Que signifient « \b » et « \B » ?

The "\b" asserts a position, not a character. That is, it doesn't represent a character in the string, but a condition at a certain position.

Pour l'expression régulière, /\bPerl\b/, il doit y avoir une limite de mot avant le « P » et après le « l ». Tant que quelque chose d'autre qu'un caractère de mot précède le « P » et suit le « l », le motif correspondra. Ces chaînes correspondent à /\bPerl\b/.

"Perl"    # pas de caractère de mot avant « P » ou après « l »
"Perl "   # identique au précédent (l'espace n'est pas un caractère de mot)
"'Perl'"  # le caractère « ' » n'est pas un caractère de mot
"Perl's"  # pas de caractère de mot avant « P », caractère non-mot après « l »

Ces chaînes ne correspondent pas à /\bPerl\b/.

"Perl_"   # « _ » est un caractère de mot !
"Perler"  # pas de caractère de mot avant « P », mais un après « l »

Vous n'avez pas besoin d'utiliser \b pour faire correspondre des mots. Vous pouvez rechercher des caractères non-mots entourés de caractères de mots. Ces chaînes correspondent au motif /\b'\b/.

"don't"   # le caractère « ' » est entouré par « n » et « t »
"qep'a'"  # le caractère « ' » est entouré par « p » et « a »

Ces chaînes ne correspondent pas à /\b'\b/.

"foo'"    # il n'y a pas de caractère de mot après le caractère non-mot « ' »

Vous pouvez également utiliser le complément de \b, \B, pour spécifier qu'il ne doit pas y avoir de limite de mot.

Dans le motif /\Bam\B/, il doit y avoir un caractère de mot avant le « a » et après le « m ». Ces motifs correspondent à /\Bam\B/ :

"llama"   # « am » entouré de caractères de mots
"Samuel"  # identique

Ces chaînes ne correspondent pas à /\Bam\B/

"Sam"      # pas de limite de mot avant « a », mais une après « m »
"I am Sam" # « am » entouré de caractères non-mots

Pourquoi l'utilisation de $&, $`, ou $' ralentit-elle mon programme ?

(contribué par Anno Siegel)

Une fois que Perl voit que vous avez besoin de l'une de ces variables n'importe où dans le programme, il les fournit à chaque correspondance de motif. Cela signifie qu'à chaque correspondance de motif, la chaîne entière sera copiée, une partie à $`, une partie à $&, et une partie à $'. Ainsi, la pénalité est la plus sévère avec les longues chaînes et les motifs qui correspondent souvent. Évitez $&, $', et $` si vous le pouvez, mais si vous ne le pouvez pas, une fois que vous les avez utilisées, utilisez-les à volonté car vous avez déjà payé le prix. N'oubliez pas que certains algorithmes les apprécient vraiment. Depuis la version 5.005, la variable $& n'est plus « coûteuse » comme les deux autres.

Depuis Perl 5.6.1, les variables spéciales @- et @+ peuvent remplacer fonctionnellement $`, $& et $'. Ces tableaux contiennent des pointeurs vers le début et la fin de chaque correspondance (voir perlvar pour toute l'histoire), ils vous donnent donc essentiellement la même information, mais sans le risque de copies de chaînes excessives.

Perl 5.10 a ajouté trois variables spéciales, "${^MATCH}", "${^PREMATCH}", et "${^POSTMATCH}" pour faire le même travail mais sans la pénalité de performance globale. Perl 5.10 ne définit ces variables que si vous compilez ou exécutez l'expression régulière avec le modificateur "/p".

À quoi sert « \G » dans une expression régulière ?

Vous utilisez l'ancre "\G" pour commencer la correspondance suivante sur la même chaîne là où la dernière correspondance s'est arrêtée. Le moteur d'expressions régulières ne peut pas sauter de caractères pour trouver la correspondance suivante avec cette ancre, donc "\G" est similaire à l'ancre de début de chaîne, "^". L'ancre "\G" est typiquement utilisée avec le modificateur "g". Elle utilise la valeur de pos() comme position pour commencer la correspondance suivante. Au fur et à mesure que l'opérateur de correspondance effectue des correspondances successives, il met à jour pos() avec la position du caractère suivant après la dernière correspondance (ou le premier caractère de la correspondance suivante, selon votre point de vue). Chaque chaîne a sa propre valeur pos().

Supposons que vous vouliez faire correspondre toutes les paires consécutives de chiffres dans une chaîne comme « 1122a44 » et arrêter la correspondance lorsque vous rencontrez des non-chiffres. Vous voulez faire correspondre 11 et 22, mais la lettre « a » apparaît entre 22 et 44 et vous voulez vous arrêter à « a ». Faire simplement correspondre des paires de chiffres ignore le « a » et fait toujours correspondre 44.

$_ = "1122a44";
my @pairs = m/(\d\d)/g;   # qw( 11 22 44 )

Si vous utilisez l'ancre "\G", vous forcez la correspondance après 22 à commencer par le « a ». L'expression régulière ne peut pas correspondre là car elle ne trouve pas de chiffre, donc la correspondance suivante échoue et l'opérateur de correspondance renvoie les paires qu'il a déjà trouvées.

$_ = "1122a44";
my @pairs = m/\G(\d\d)/g; # qw( 11 22 )

Vous pouvez également utiliser l'ancre "\G" en contexte scalaire. Vous avez toujours besoin du modificateur "g".

$_ = "1122a44";
while( m/\G(\d\d)/g ) {
    print "Found $1\n";
}

Après l'échec de la correspondance sur la lettre « a », perl réinitialise pos() et la correspondance suivante sur la même chaîne commence au début.

$_ = "1122a44";
while( m/\G(\d\d)/g ) {
    print "Found $1\n";
}
print "Found $1 after while" if m/(\d\d)/g; # trouve « 11 »

Vous pouvez désactiver les réinitialisations de pos() en cas d'échec avec le modificateur "c", documenté dans perlop et perlreref. Les correspondances ultérieures commencent là où la dernière correspondance réussie s'est terminée (la valeur de pos()) même si une correspondance sur la même chaîne a échoué entre-temps. Dans ce cas, la correspondance après la boucle while() commence au « a » (où la dernière correspondance s'est arrêtée), et comme elle n'utilise aucune ancre, elle peut sauter le « a » pour trouver 44.

$_ = "1122a44";
while( m/\G(\d\d)/gc ) {
    print "Found $1\n";
}
print "Found $1 after while" if m/(\d\d)/g; # trouve « 44 »

Typiquement, vous utilisez l'ancre "\G" avec le modificateur "c" lorsque vous voulez essayer une correspondance différente en cas d'échec, comme dans un analyseur lexical. Jeffrey Friedl propose cet exemple qui fonctionne à partir de la version 5.004.

while (<>) {
    chomp;
    PARSER: {
        m/ \G( \d+\b    )/gcx   && do { print "number: $1\n";  redo; };
        m/ \G( \w+      )/gcx   && do { print "word:   $1\n";  redo; };
        m/ \G( \s+      )/gcx   && do { print "space:  $1\n";  redo; };
        m/ \G( [^\w\d]+ )/gcx   && do { print "other:  $1\n";  redo; };
    }
}

Pour chaque ligne, la boucle "PARSER" essaie d'abord de faire correspondre une série de chiffres suivie d'une limite de mot. Cette correspondance doit commencer à l'endroit où la dernière correspondance s'est arrêtée (ou au début de la chaîne lors de la première correspondance). Comme « m/ \G( \d+\b )/gcx » utilise le modificateur "c", si la chaîne ne correspond pas à cette expression régulière, perl ne réinitialise pas pos() et la correspondance suivante commence à la même position pour essayer un motif différent.

Les regex Perl sont-elles des DFA ou des NFA ? Sont-elles conformes à POSIX ?

Bien qu'il soit vrai que les expressions régulières de Perl ressemblent aux DFA (automates finis déterministes) du programme egrep(1), elles sont en fait implémentées comme des NFA (automates finis non déterministes) pour permettre le retour arrière et les références arrière. Et elles ne sont pas non plus de style POSIX, car celles-ci garantissent un comportement dans le pire des cas pour tous les cas. (Il semble que certaines personnes préfèrent les garanties de cohérence, même lorsque ce qui est garanti est la lenteur.) Consultez le livre « Mastering Regular Expressions » (par O'Reilly) de Jeffrey Friedl pour tous les détails que vous pourriez jamais espérer connaître sur ces questions (une citation complète apparaît dans perlfaq2).

Quel est le problème avec l'utilisation de grep dans un contexte vide ?

Le problème est que grep construit une liste de retour, quel que soit le contexte. Cela signifie que vous demandez à Perl de faire l'effort de construire une liste que vous jetez ensuite. Si la liste est grande, vous perdez à la fois du temps et de l'espace. Si votre intention est d'itérer sur la liste, utilisez une boucle for à cet effet.

Dans les versions de Perl antérieures à 5.8.1, map souffre également de ce problème. Mais depuis la version 5.8.1, cela a été corrigé, et map est sensible au contexte - en contexte vide, aucune liste n'est construite.

Comment faire correspondre des chaînes avec des caractères multibytes ?

À partir de Perl 5.6, Perl a un certain niveau de support des caractères multibytes. Perl 5.8 ou une version ultérieure est recommandé. Les répertoires de caractères multibytes pris en charge incluent Unicode, et les encodages hérités via le module Encode. Voir perluniintro, perlunicode et Encode.

Si vous êtes bloqué avec d'anciennes versions de Perl, vous pouvez gérer Unicode avec le module Unicode::String, et les conversions de caractères en utilisant les modules Unicode::Map8 et Unicode::Map. Si vous utilisez des encodages japonais, vous pourriez essayer d'utiliser jperl 5.005_03.

Enfin, l'ensemble des approches suivantes a été proposé par Jeffrey Friedl, dont l'article dans le numéro 5 de The Perl Journal traite de cette question.

Supposons que vous ayez un encodage martien bizarre où des paires de lettres ASCII majuscules codent une seule lettre martienne (c'est-à-dire que les deux octets « CV » forment une seule lettre martienne, tout comme les deux octets « SG », « VS », « XX », etc.). D'autres octets représentent des caractères uniques, comme ASCII.

Donc

, la chaîne martienne "Je suis CVSGXX !" utilise 12 octets pour encoder les neuf caractères 'J', ' ', 's', 'u', 'i', 's', ' ', 'CV', 'SG', 'XX', '!'.

Maintenant, disons que vous voulez rechercher le caractère unique "/GX/". Perl ne connaît pas le martien, il trouvera donc les deux octets "GX" dans la chaîne "Je suis CVSGXX !", même si ce caractère n'y est pas : il semble juste qu'il y soit parce que "SG" est à côté de "XX", mais il n'y a pas de vrai "GX". C'est un gros problème.

Voici quelques façons, toutes douloureuses, de le gérer :

# Assurez-vous que les octets "martiens" adjacents ne sont plus adjacents.
$martien =~ s/([A-Z][A-Z])/ $1 /g;
print "trouvé GX!\n" if $martian =~ /GX/;

Ou comme ceci :

my @chars = $martian =~ m/([A-Z][A-Z]|[^A-Z])/g;
# ci-dessus est conceptuellement similaire à :     my @chars = $text =~ m/(.)/g;
#
foreach my $char (@chars) {
    print "trouvé GX!\n", last if $char eq 'GX';
}

Ou comme ceci :

while ($martian =~ m/\G([A-Z][A-Z]|.)/gs) {  # \G probablement inutile
    if ($1 eq 'GX') {
        print "trouvé GX!\n";
        last;
    }
}

Voici une autre façon, légèrement moins douloureuse, de faire de Benjamin Goldberg, qui utilise une assertion de lookbehind négative de largeur nulle.

print "trouvé GX!\n" if    $martian =~ m/
    (?<![A-Z])
    (?:[A-Z][A-Z])*?
    GX
    /x;

Cela réussit si le caractère martien GX est dans la chaîne, et échoue sinon. Si vous n'aimez pas utiliser (?<!), une assertion de lookbehind négative de largeur nulle, vous pouvez remplacer (?<![A-Z]) par (?:^|[^A-Z]).

Cela a l'inconvénient de placer la mauvaise chose dans $-[0] et $+[0], mais cela peut généralement être résolu.

Comment puis-je faire correspondre une expression régulière qui se trouve dans une variable ?

(contribué par brian d foy)

Nous n'avons pas à coder en dur les motifs dans l'opérateur de correspondance (ou quoi que ce soit d'autre qui fonctionne avec des expressions régulières). Nous pouvons placer le motif dans une variable pour une utilisation ultérieure.

L'opérateur de correspondance est un contexte de guillemets doubles, vous pouvez donc interpoler votre variable juste comme une chaîne entre guillemets doubles. Dans ce cas, vous lisez l'expression régulière en entrée utilisateur et la stockez dans $regex. Une fois que vous avez le motif dans $regex, vous utilisez cette variable dans l'opérateur de correspondance.

chomp( my $regex = <STDIN> );
if( $string =~ m/$regex/ ) { ... }

Les caractères spéciaux d'expression régulière dans $regex sont toujours spéciaux, et le motif doit toujours être valide, sinon Perl se plaindra. Par exemple, dans ce motif, il y a une parenthèse non appariée.

my $regex = "Parenthèse ( non appariée";
"Deux parenthèses pour toutes les lier" =~ m/$regex/;

Lorsque Perl compile l'expression régulière, il traite la parenthèse comme le début d'une correspondance mémorielle. Lorsqu'il ne trouve pas la parenthèse fermante, il se plaint :

Parenthèse ( non appariée dans regex ; marquée par <-- ICI dans m/Parenthèse ( <-- ICI  non appariée/ au script ligne 3.

Vous pouvez contourner cela de plusieurs manières selon votre situation. Premièrement, si vous ne voulez qu'aucun des caractères de la chaîne ne soit spécial, vous pouvez les échapper avec "quotemeta" avant d'utiliser la chaîne.

chomp( my $regex = <STDIN> );
$regex = quotemeta( $regex );
if( $string =~ m/$regex/ ) { ... }

Vous pouvez également le faire directement dans l'opérateur de correspondance en utilisant les séquences "\Q" et "\E". Le "\Q" indique à Perl où commencer à échapper les caractères spéciaux, et le "\E" lui indique où s'arrêter (voir perlop pour plus de détails).

chomp( my $regex = <STDIN> );
if( $string =~ m/\Q$regex\E/ ) { ... }

Alternativement, vous pouvez utiliser "qr//", l'opérateur de citation d'expression régulière (voir perlop pour plus de détails). Il cite et compile éventuellement le motif, et vous pouvez appliquer des drapeaux d'expression régulière au motif.

chomp( my $input = <STDIN> );
my $regex = qr/$input/is;
$string =~ m/$regex/  # équivalent à m/$input/is;

Vous pourriez également vouloir intercepter toutes les erreurs en plaçant un bloc "eval" autour de l'ensemble.

chomp( my $input = <STDIN> );
eval {
    if( $string =~ m/\Q$input\E/ ) { ... }
};
warn $@ if $@;

Ou...

my $regex = eval { qr/$input/is };
if( defined $regex ) {
    $string =~ m/$regex/;
}
else {
    warn $@;
}
