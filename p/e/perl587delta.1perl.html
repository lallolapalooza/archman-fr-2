PERL587DELTA(1perl) Guide du programmeur Perl PERL587DELTA(1perl)

NOM

perl587delta — ce qui est nouveau pour la version perl v5.8.7

DESCRIPTION

Ce document décrit les différences entre la version 5.8.6 et la version 5.8.7.

Changements incompatibles

Il n'y a aucun changement incompatible avec la version 5.8.6.

Améliorations du cœur

Base de données de caractères Unicode 4.1.0

La copie de la base de données de caractères Unicode incluse dans Perl 5.8 a été mise à jour de la version 4.0.1 à la version 4.1.0. Voir http://www.unicode.org/versions/Unicode4.1.0/#NotableChanges pour les changements notables.

suidperl moins insécurisé

Une paire d'exploits dans "suidperl" impliquant le code de débogage a été corrigée.

Pour les nouveaux projets, l'équipe principale de perl recommande fortement d'utiliser des outils de sécurité dédiés à usage unique comme "sudo" de préférence à "suidperl".

Script de personnalisation de site optionnel

L'interpréteur Perl peut être compilé pour permettre l'utilisation d'un script de personnalisation de site. Par défaut, ce n'est pas activé, afin d'être cohérent avec les versions précédentes de Perl. Pour l'utiliser, ajoutez "-Dusesitecustomize" aux options de la ligne de commande lors de l'exécution du script "Configure". Voir aussi "-f" dans perlrun.

"Config.pm" est maintenant beaucoup plus petit

"Config.pm" pèse maintenant environ 3 Ko au lieu de 32 Ko, avec le code rarement utilisé et les valeurs %Config chargés à la demande. Ceci est transparent pour le programmeur, mais signifie que la plupart du code économisera l'analyse et le chargement de 29 Ko de script (par exemple, le code qui utilise "File::Find").

Changements utilitaires

Améliorations de find2perl

"find2perl" a de nouvelles options "-iname", "-path" et "-ipath".

Améliorations des performances

La table de hachage interne de mappage de pointeurs utilisée lors du clonage ithreads utilise maintenant une arène pour l'allocation de mémoire. Dans les tests, cela a réduit le temps de clonage ithreads d'environ 10%.

Améliorations de l'installation et de la configuration

  • Le fichier "makefile.mk" de dmake pour Win32 a été mis à jour pour être compatible avec les dernières versions de dmake.
  • "PERL_MALLOC", "DEBUG_MSTATS", "PERL_HASH_SEED_EXPLICIT" et "NO_HASH_SEED" devraient maintenant fonctionner dans les fichiers make de Win32.

Corrections de bugs sélectionnées

  • La fonction socket() sous Win32 a été corrigée afin qu'elle puisse à nouveau utiliser les fournisseurs de transport qui spécifient un protocole de 0 (signifiant que tout protocole est autorisé). (Ceci était cassé dans la version 5.8.6, et provoquait généralement l'échec de l'utilisation des sockets ICMP.)
  • Un autre bug obscur impliquant "substr" et UTF-8, causé par une mise en cache incorrecte des offsets internes, a été identifié et corrigé.
  • Un bug impliquant le chargement de tables UTF-8 par le moteur d'expressions régulières a été corrigé — le code tel que ""\x{100}" =~ /[[:print:]]/" ne donnera plus de résultats corrompus.
  • Les opérations de conversion de casse telles que "uc" sur une longue chaîne Unicode pouvaient épuiser la mémoire. Ceci a été corrigé.
  • "index"/"rindex" étaient bogués pour certaines combinaisons de données Unicode et non-Unicode. Ceci a été corrigé.
  • "read" (et probablement "sysread") exposaient les détails internes d'UTF-8 lors de la lecture depuis une poignée de fichier orientée octets vers un scalaire UTF-8. Ceci a été corrigé.
  • Plusieurs corrections de bugs pour "pack"/"unpack" :
  • Les sommes de contrôle avec les formats "b" ou "B" étaient incorrectes.
  • Les sommes de contrôle "unpack" pouvaient déborder avec le format "C".
  • "U0" et "C0" sont maintenant limités aux sous-modèles "pack" de "()".
  • Les préfixes de longueur comptée ne modifient plus le mode "C0"/"U0".
  • "pack" "Z0" détruisait le caractère précédent.
  • Les formats "P"/"p" de "pack" ne reconnaissaient que la valeur littérale "undef"
  • L'utilisation de fermetures avec ithreads pouvait provoquer un crash de perl. Ceci était dû à un échec de verrouillage correct des structures OP internes, et a été corrigé.
  • La valeur de retour de "close" reflète maintenant correctement les erreurs de fichier qui surviennent lors de la vidange des données du descripteur, au lieu de simplement renvoyer un échec si l'opération de fermeture sous-jacente échouait.
  • "not() || 1" causait un segmentation fault. not() se comporte maintenant comme not(0), ce qui était le comportement avant la version 5.6.0.
  • "h2ph" a diverses améliorations pour gérer les constructions dans les fichiers d'en-tête qui produisaient auparavant une sortie incorrecte ou invalide.

Nouveaux ou modifiés diagnostics

Il y a une nouvelle erreur de souillure, « %ENV est alias de %s ». Cette erreur est déclenchée lorsque les vérifications de souillure sont activées et que *ENV a été aliasé, de sorte que %ENV n'a plus de magie d'environnement et que l'environnement ne peut donc pas être vérifié comme étant exempt de souillure.

Les internes de "pack" et "unpack" ont été mis à jour. Tous les modèles légitimes devraient fonctionner comme auparavant, mais il peut y avoir des changements dans l'erreur signalée pour les cas d'échec complexes. Tout comportement modifié pour les cas sans erreur est un bug et doit être signalé.

Internes modifiés

Il y a eu pas mal de refactorisation du code source "C", en partie pour le rendre plus propre et plus facile à maintenir. Le code objet résultant et le binaire "perl" peuvent être plus petits que 5.8.6, et espérons-le, plus rapides dans certains cas, mais à part cela, il ne devrait y avoir aucun changement détectable par l'utilisateur.

"${^UTF8LOCALE}" a été ajouté pour donner à Perl un accès espace à "PL_utf8locale".

La taille des arènes utilisées pour allouer les têtes SV et la plupart des corps SV peut maintenant être modifiée au moment de la compilation. L'ancienne taille était de 1008 octets, la nouvelle taille par défaut est de 4080 octets.

Problèmes connus

Les chaînes Unicode renvoyées par les opérateurs surchargés peuvent être boguées. Il s'agit d'un bug de longue date signalé depuis la sortie de 5.8.6, mais nous n'avons pas encore de solution appropriée.

Problèmes spécifiques à la plateforme

Sur UNICOS, lib/Math/BigInt/t/bigintc.t se bloque en consommant du CPU. ext/B/t/bytecode.t et ext/Socket/t/socketpair.t échouent tous deux aux tests. Il est peu probable qu'ils soient résolus, car le dernier Cray de notre valeureux porteur UNICOS est en cours de désaffectation.

Rapport de bogues

Si vous trouvez ce que vous pensez être un bug, vous pourriez consulter les articles récemment publiés sur le groupe de discussion comp.lang.perl.misc et la base de données des bugs de Perl sur http://bugs.perl.org. Il peut également y avoir des informations sur http://www.perl.org, la page d'accueil de Perl.

Si vous pensez avoir un bug non signalé, veuillez exécuter le programme perlbug inclus dans votre version. Assurez-vous de réduire votre bug à un cas de test simple mais suffisant. Votre rapport de bug, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage de Perl. Vous pouvez parcourir et rechercher les bugs de Perl 5 sur http://bugs.perl.org/
