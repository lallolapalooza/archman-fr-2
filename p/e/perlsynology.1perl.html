PERLSYNOLOGY(1perl) Guide de référence pour programmeurs Perl PERLSYNOLOGY(1perl)

NOM

perlsynology - Perl 5 sur les systèmes Synology DSM

DESCRIPTION

Synology fabrique un grand nombre de périphériques de stockage en réseau (NAS) qui sont très populaires dans les grandes organisations ainsi que dans les petites entreprises et les domiciles.

Les systèmes NAS sont équipés de Synology Disk Storage Manager (DSM), qui est un système Linux allégé amélioré avec plusieurs outils pour la gestion du NAS. Il existe plusieurs types de matériel : Marvell Armada (ARMv5tel, ARMv7l), Intel Atom (i686, x86_64), Freescale QorIQ (PPC), et plus. Pour une liste complète, voir la FAQ Synology https://kb.synology.com/fr-fr/DSM/tutorial/Quel_type_de_CPU_mon_NAS_poss%C3%A8de-t-il.

Étant basé sur Linux, le NAS peut exécuter de nombreux paquets logiciels Linux populaires, y compris Perl. En fait, Synology fournit un paquet prêt à être installé pour Perl, selon la version de DSM, le Perl installé varie de 5.8.6 sur DSM-4.3 à 5.28.1 sur DSM-7.1.

Il existe une communauté d'utilisateurs active qui fournit de nombreux paquets logiciels pour les systèmes Synology DSM ; au moment de la rédaction de ce document, ils fournissent la version 5.28.1 de Perl.

Ce document décrit diverses fonctionnalités du système d'exploitation Synology DSM qui affectent la configuration, la compilation et/ou l'exécution de Perl 5 (ci-après simplement Perl). Il a été compilé et vérifié par Johan Vromans pour le Synology DS413 (QorIQ), avec les commentaires de H.Merijn Brand (DS213 : ARMv5tel, RS815 : Intel Atom x64, et DS218+ : Celeron J3355).

Configuration de l'environnement de construction

DSM 7

Pour un environnement de développement confortable, Entware est actuellement la seule solution viable. Suivez simplement les instructions détaillées sur Installer Entware sur Synology NAS https://github.com/Entware/Entware/wiki/Install-on-Synology-NAS. Les architectures supportées sont armv5, armv7, mipsel, wl500g, x86_32 et x86_64. Vérifiez ici https://pkg.entware.net/binaries/ les plateformes supportées.

Ce lien github montre également quels environnements devraient être supportés.

Il a été testé sur DSM-7.1 par H.Merijn Brand sur un DS218+ et un DS220+ (tous deux Intel x64).

Entware est fourni avec un Perl précompilé 5.26.1 (janvier 2018) qui permet de construire du code XS partagé. Notez que cette installation n'utilise pas de dossier site_perl. Le "cpan" disponible fonctionne. Si tous les paquets de développement requis sont également installés, cela fonctionne aussi pour XS.

Installation de perl depuis le centre de paquets Communautaire :

  • Utilisez votre navigateur préféré pour ouvrir la page de gestion de DSM et lancez le Centre de paquets.
  • Dans Paramètres, ajoutez les Sources de paquets suivantes : 
    Nom :     Communauté
Emplacement : https://synopackage.com/repository/spk/All
  • Toujours dans Paramètres, dans Mise à jour des canaux, sélectionnez le Canal Bêta.

Pour compléter l'environnement de développement, installez make et gcc

ds220# opkg install make gcc

Ensuite, éventuellement, assurez-vous d'utiliser les versions plus récentes de bash et gawk.

ds220# opkg install bash gawk
ds220# cd /usr/bin
ds220# mv bash bash.syno
ds220# ln -s /opt/bin/bash .

Afin que Configure trouve les bibliothèques requises

ds220# cd /opt/lib
ds220# ln -s libcrypt.so.?       libcrypt.so
ds220# ln -s libdl.so.?          libdl.so
ds220# ln -s libgdbm.so.?        libgdbm.so
ds220# ln -s libgdbm_compat.so.? libgdbm_compat.so
ds220# ln -s libm.so.?           libm.so
ds220# ln -s libpthread.so.?     libpthread.so
ds220# ln -s libutil.so.?        libutil.so

DSM 6

L'utilisation d'iPkg a été dépréciée sur DSM 6, mais une alternative est disponible pour DSM 6 : entware/opkg. Pour des instructions sur son utilisation, veuillez lire Installer Entware-ng sur Synology NAS https://github.com/Entware-ng/Entware-ng/wiki/Install-on-Synology-NAS

Cela ne fonctionne malheureusement pas (encore) sur QorIQ. Au moment de la rédaction, les architectures supportées sont armv5, armv7, mipsel, wl500g, x86_32 et x86_64. Vérifiez ici https://pkg.entware.net/binaries/ les plateformes supportées.

Entware-ng est fourni avec un Perl précompilé 5.24.1 (juin 2017) qui permet de construire du code XS partagé. Notez que cette installation n'utilise pas de dossier site_perl. Le "cpan" disponible fonctionne. Si tous les paquets de développement requis sont également installés, cela fonctionne aussi pour XS.

DSM 5

DSM étant un système Linux allégé, il manque de nombreux outils et bibliothèques couramment trouvés sur Linux. Les outils de base comme sh, cp, rm, etc. sont implémentés à l'aide de BusyBox https://fr.wikipedia.org/wiki/BusyBox.

  • Utilisez votre navigateur préféré pour ouvrir la page de gestion de DSM et lancez le Centre de paquets.
  • Si vous voulez tester rapidement Perl, installez "Perl".
  • Dans Paramètres, ajoutez les Sources de paquets suivantes : 
    https://www.cphub.net
http://packages.quadrat4.de

    Comme ces deux-là sont interrompues, il est peu probable que vous puissiez configurer un environnement de construction sur DSM 5.

  • Toujours dans Paramètres, dans Mise à jour des canaux, sélectionnez le Canal Bêta.
  • Appuyez sur Actualiser. Dans le panneau de gauche, l'élément "Communauté" apparaîtra. Cliquez dessus. Sélectionnez "Bootstrap Installer Beta" et installez-le.
  • De même, installez "iPKGui Beta".

    La fenêtre de l'application devrait maintenant afficher une icône pour iPKGui.

  • Lancez iPKGui. Installez les paquets "make", "gcc" et "coreutils".

    Si vous voulez tester rapidement Perl, installez "patch".

L'étape suivante consiste à ajouter quelques liens symboliques aux bibliothèques système. Par exemple, le logiciel de développement attend une bibliothèque "libm.so" qui est normalement un lien symbolique vers "libm.so.6". Synology ne fournit que ce dernier et pas le lien symbolique.

Ici, l'architecture réelle du système Synology est importante. Vous devez trouver où les bibliothèques gcc ont été installées. Regardez dans /opt pour un répertoire similaire à arm-none-linux-gnueab ou powerpc-linux-gnuspe. Dans les instructions ci-dessous, j'utiliserai powerpc-linux-gnuspe comme exemple.

  • Sur la page de gestion de DSM, lancez le Panneau de configuration.
  • Cliquez sur Terminal, et activez le service SSH.
  • Fermez le Terminal et le Panneau de configuration.
  • Ouvrez un shell sur le Synology en utilisant ssh et devenez root.
  • Exécutez les commandes suivantes : 
    cd /lib
ln -s libm.so.6 libm.so
ln -s libcrypt.so.1 libcrypt.so
ln -s libdl.so.2 libdl.so
cd /opt/powerpc-linux-gnuspe/lib  (ou
                                  /opt/arm-none-linux-gnueabi/lib)
ln -s /lib/libdl.so.2 libdl.so

ATTENTION : Lorsque vous effectuez une mise à niveau du logiciel système, ces liens disparaîtront et devront être rétablis.

Compilation de Perl 5

Une fois l'environnement de construction configuré, la compilation et le test de Perl sont simples. La seule chose que vous devez faire est de télécharger les sources comme d'habitude, et d'ajouter un fichier Policy.sh comme suit :

# Administrivia.
perladmin="votre.email@va.ici"
# Installer Perl dans un arbre dans /opt/perl au lieu de /opt/bin.
prefix=/opt/perl
# Sélectionner le compilateur. Notez qu'il n'y a pas d'alias ou de lien 'cc'
# sur les anciennes versions de DSM
cc=gcc
awk=/opt/bin/gawk
# Indicateurs de construction. Facultatif
ccflags="-DDEBUGGING"
# Chemins des bibliothèques et des inclusions.
locincpth="/opt/include"
loclibpth="/opt/lib /usr/local/lib /usr/lib"
libpth="/opt/lib /usr/local/lib /usr/lib"

Vous voudrez peut-être créer le répertoire de destination et lui donner les bonnes permissions avant l'installation, éliminant ainsi le besoin de construire Perl en tant que super-utilisateur.

Dans le répertoire où vous avez décompressé les sources, exécutez les commandes familières :

$ bash ./Configure -Dusedevel -Duseshrplib -Duse64bitall -des
$ make -j2
$ env TEST_JOBS=2 make test_harness
$ make install

Problèmes connus

Configure

Le compilateur GNU C pourrait cracher des choses inattendues sous -v, ce qui fait échouer l'analyse des cppsymbols en raison de guillemets non appariés.

Vous remarquerez si config.sh échoue avec un

syntax error.

Build

Erreur message "No error definitions found".
Cette erreur est générée lorsqu'il est impossible de trouver les définitions locales pour les codes d'erreur, en raison de la structure inhabituelle du système de fichiers Synology.

Cette erreur a été corrigée dans le dépôt git de développement Perl pour la version 5.19, commit 7a8f1212e5482613c8a5b0402528e3105b26ff24.

Tests en échec

ext/DynaLoader/t/DynaLoader.t
Un sous-test échoue en raison de la structure inhabituelle du système de fichiers Synology. Le fichier /lib/glibc.so est manquant.

AVERTISSEMENT : Ne créez pas de lien symbolique de /lib/glibc.so.6 vers /lib/glibc.so, sinon certains composants système commenceront à échouer.

Tests de fumée Perl

Si la compilation se termine avec succès, vous pouvez configurer les tests de fumée comme décrit dans la documentation de Test::Smoke.

Pour les tests de fumée, vous avez besoin d'une Perl en cours d'exécution. Vous pouvez soit installer le paquet fourni par Synology pour Perl 5.8.6, soit compiler et installer votre propre version, beaucoup plus récente.

Notez que je n'ai pas pu exécuter de tests de fumée réussis lorsqu'ils étaient initiés par le Planificateur de tâches Synology. J'ai eu recours à l'initiation des tests de fumée via une tâche cron exécutée sur un autre système, en utilisant ssh :

ssh nas1 wrk/Test-Smoke/smoke/smokecurrent.sh

Patches locaux

Lorsque des patches locaux sont appliqués avec des tests de fumée, le pilote de test demandera automatiquement la régénération de certaines tables après l'application des patches. La version Perl 5.8.6 fournie par Synology (du moins sur le DS413) n'est PAS capable de générer ces tables. Elle générera des opcodes avec des valeurs erronées, ce qui entraînera l'échec de la compilation.

Vous pouvez empêcher la régénération en ajoutant le paramètre

'flags' => 0,

à la configuration de fumée, ou en ajoutant un autre patch qui insère

exit 0 if $] == 5.008006;

au début du programme "regen.pl".

Ajout de bibliothèques

La procédure ci-dessus décrit un environnement de base et résulte donc en une Perl de base. Si vous souhaitez ajouter des bibliothèques supplémentaires à Perl, vous pourriez avoir besoin de quelques réglages supplémentaires.

Par exemple, la Perl de base ne contient aucune des bibliothèques DB (db, dbm, ndbm, gdsm). Vous pouvez les ajouter en utilisant iPKGui, cependant, vous devez définir la variable d'environnement LD_LIBRARY_PATH à la valeur appropriée :

LD_LIBRARY_PATH=/lib:/opt/lib
export LD_LIBRARY_PATH

Ce paramètre doit être pris en compte lors de la compilation de Perl, mais aussi lors de l'exécution des programmes.
