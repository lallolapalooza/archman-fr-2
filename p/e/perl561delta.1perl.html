NOM

perl561delta - Nouveautés de perl v5.6.1

DESCRIPTION

Ce document décrit les différences entre la version 5.005 et la version 5.6.1.

Résumé des changements entre 5.6.0 et 5.6.1

Cette section contient un résumé des changements entre les versions 5.6.0 et 5.6.1. Plus de détails sur les changements mentionnés ici peuvent être trouvés dans les fichiers Changes qui accompagnent la distribution source de Perl. Voir perlhack pour des pointeurs vers des ressources en ligne où vous pouvez inspecter les patches individuels décrits par ces changements.

Problèmes de sécurité

suidperl n'exécutera plus /bin/mail, car certaines plateformes ont un /bin/mail vulnérable aux attaques de débordement de tampon.

Notez que suidperl n'est ni construit ni installé par défaut dans aucune version récente de perl. L'utilisation de suidperl est fortement déconseillée. Si vous pensez en avoir besoin, essayez d'abord des alternatives comme sudo. Voir http://www.courtesan.com/sudo/.

Corrections de bugs du cœur

Ce n'est pas une liste exhaustive. Elle est destinée à couvrir uniquement les changements significatifs visibles par l'utilisateur.

UNIVERSAL::isa()
Un bug dans le mécanisme de mise en cache utilisé par UNIVERSAL::isa() qui affectait base.pm a été corrigé. Le bug existait depuis les versions 5.005, mais n'était pas activé par base.pm dans ces versions.
Fuites de mémoire
Divers cas de fuites de mémoire et de tentatives d'accès à de la mémoire non initialisée ont été corrigés. Voir "Problèmes connus" ci-dessous pour d'autres problèmes.
Conversions numériques
Les conversions numériques ne reconnaissaient pas correctement les changements de valeur de chaîne dans certaines circonstances.

Dans d'autres situations, les grands nombres non signés (ceux supérieurs à 2**31) pouvaient parfois perdre leur caractère non signé, entraînant des résultats erronés dans les opérations arithmétiques.

Le module entier sur les grands nombres non signés renvoyait parfois des valeurs incorrectes.

Perl 5.6.0 générait des avertissements "pas un nombre" pour certaines conversions là où les versions précédentes ne le faisaient pas.

Ces problèmes ont tous été résolus.

L'infini est maintenant reconnu comme un nombre.

qw(a\\b)
Dans Perl 5.6.0, qw(a\\b) produisait une chaîne avec deux antislashs au lieu d'un, s'écartant du comportement des versions précédentes. L'ancien comportement a été rétabli.
caller()
caller() pouvait provoquer des plantages du noyau dans certaines situations. Carp était parfois affecté par ce problème.
Bugs dans les expressions régulières
Les correspondances de motifs sur des valeurs surchargées sont maintenant gérées correctement.

Perl 5.6.0 analysait m/\x{ab}/ incorrectement, entraînant des avertissements parasites. Ceci a été corrigé.

Le moteur RE trouvé dans Perl 5.6.0 a accidentellement pessimisé certains types de correspondances de motifs simples. Ceux-ci sont maintenant mieux gérés.

La sortie de débogage des expressions régulières (que ce soit via "use re 'debug'" ou via "-Dr") est maintenant plus claire.

Les correspondances multilignes comme ""a\nxb\n" =~ /(?!\A)x/m" étaient défectueuses. Le bug a été corrigé.

L'utilisation de $& pouvait déclencher un plantage du noyau dans certaines situations. Ceci est maintenant évité.

Les variables de correspondance $1 et al., n'étaient pas désinitialisées lorsque la correspondance d'un motif revenait en arrière, et l'anomalie apparaissait à l'intérieur de "/...(?{ ... }).../" etc. Ces variables sont maintenant correctement suivies.

pos() ne renvoyait pas la valeur correcte dans s///ge dans les versions antérieures. Ceci est maintenant géré correctement.

"mode" 'slurp'
readline() sur des fichiers ouverts en mode "slurp" pouvait renvoyer un "" supplémentaire à la fin dans certaines situations. Ceci a été corrigé.
Autovivification des références symboliques aux variables spéciales
L'autovivification des références symboliques des variables spéciales décrites dans perlvar (comme dans "${$num}") avait été accidentellement désactivée. Cela fonctionne à nouveau maintenant.
Avertissements lexicaux
Les avertissements lexicaux se propagent maintenant correctement dans "eval "..."".

"use warnings qw(FATAL all)" ne fonctionnait pas comme prévu. Ceci a été corrigé.

Les avertissements lexicaux pouvaient fuir dans d'autres portées dans certaines situations. Ceci est maintenant corrigé.

warnings::enabled() signale maintenant correctement l'état de $^W si l'appelant n'utilise pas les avertissements lexicaux.

Avertissements et erreurs parasites
Perl 5.6.0 pouvait émettre des avertissements parasites sur la redéfinition de dl_error() lors de la compilation statique d'extensions dans perl. Ceci a été corrigé.

Les variables "our" pouvaient entraîner des avertissements parasites "La variable ne restera pas partagée". Ceci est maintenant corrigé.

Les variables "our" du même nom déclarées dans deux blocs frères entraînaient des avertissements parasites sur la "redéclaration" des variables. Le problème a été corrigé.

glob()
La compatibilité de la fonction intégrée glob() avec l'ancien glob basé sur csh a été améliorée avec l'ajout de l'option GLOB_ALPHASORT. Voir "File::Glob".

File::Glob::glob() a été renommé en File::Glob::bsd_glob() car le nom entrait en conflit avec la fonction intégrée glob(). L'ancien nom est toujours disponible par compatibilité, mais est déprécié.

Les erreurs de syntaxe parasites générées dans certaines situations, lorsque glob() provoquait le chargement de File::Glob pour la première fois, ont été corrigées.

Tainting
Certains cas de propagation incohérente du taint (comme dans les valeurs de hachage) ont été corrigés.

Le comportement de tainting de sprintf() a été rationalisé. Il ne teinte plus le résultat des formats à virgule flottante, rendant le comportement cohérent avec celui de l'interpolation de chaînes.

sort()
Les arguments de sort() ne recevaient pas le bon contexte wantarray(). Le bloc de comparaison est maintenant exécuté en contexte scalaire, et les arguments à trier sont toujours fournis en contexte de liste.

sort() est également entièrement réentrant, dans le sens où la fonction de tri peut elle-même appeler sort(). Cela ne fonctionnait pas de manière fiable dans les versions précédentes.

Directives #line
Les directives #line fonctionnent maintenant correctement lorsqu'elles apparaissent tout au début de "eval "..."".
Prototypes de sous-routines
Le prototype (\&) fonctionne maintenant correctement.
map()
map() pouvait devenir pathologiquement lent lorsque la liste de résultats qu'il génère est plus grande que la liste source. La performance a été améliorée pour les scénarios courants.
Débogueur
Le code de sortie du débogueur reflète maintenant le code de sortie du script.

La condition "0" dans les points d'arrêt est maintenant traitée correctement.

La commande "d" vérifie maintenant le numéro de ligne.

$. n'est plus corrompu par le débogueur.

Toute la sortie du débogueur va maintenant correctement vers le socket si RemotePort est défini.

Changes in Perl 5.6.1

This is a minor release. It contains mostly bug fixes and documentation updates. There are no new features in this release.

Core enhancements

chop()
chop(@list) dans le contexte de liste renvoyait les caractères coupés dans l'ordre inverse. Ceci a été inversé pour être dans le bon ordre.
Support Unicode
Le support Unicode a bénéficié d'un grand nombre d'améliorations incrémentielles, mais reste très expérimental. Il n'est pas attendu qu'il soit entièrement pris en charge dans les versions de maintenance 5.6.x.

substr(), join(), repeat(), reverse(), quotemeta() et la concaténation de chaînes manipulaient incorrectement les chaînes Unicode dans Perl 5.6.0. Ceci a été corrigé.

Le support de "tr///CU" et "tr///UC" etc., a été supprimé car nous avons réalisé que l'interface était défectueuse. Pour des fonctionnalités similaires, voir "pack" dans perlfunc.

La base de données de caractères Unicode a été mise à jour à la version 3.0.1 avec des ajouts rendus disponibles au public à partir du 30 août 2000.

Les classes de caractères Unicode \p{Blank} et \p{SpacePerl} ont été ajoutées. "Blank" est similaire à C isblank(), c'est-à-dire qu'il ne contient que les "espaces blancs horizontaux" (le caractère espace est inclus, le saut de ligne ne l'est pas), et "SpacePerl" est l'équivalent Unicode de "\s" (\p{Space} ne l'inclut pas, car il comprend le caractère de tabulation verticale, alors que "\s" ne le fait pas.)

Si vous expérimentez avec le support Unicode dans perl, les versions de développement de Perl peuvent offrir davantage. En particulier, les couches d'E/S sont maintenant disponibles dans la voie de développement, mais pas dans la voie de maintenance, principalement pour des problèmes de compatibilité ascendante. Le support Unicode évolue également rapidement sur une base quotidienne dans la voie de développement - la voie de maintenance ne reflète que les changements les plus conservateurs.

Support 64 bits
Le support des plates-formes 64 bits a été amélioré, mais reste expérimental. Le niveau de support varie considérablement d'une plate-forme à l'autre.
Compilateur
Le compilateur B et ses divers backends ont subi de nombreuses améliorations incrémentielles, mais restent très expérimentaux. Leur utilisation dans des environnements de production est déconseillée.

L'outil perlcc a été réécrit de manière à ce que son interface utilisateur ressemble beaucoup plus à celle d'un compilateur C.

L'outil perlbc a été supprimé. Utilisez "perlcc -B" à la place.

Sous-programmes Lvalue
Divers correctifs de bogues ont été apportés pour mieux supporter les sous-programmes lvalue. Cependant, cette fonctionnalité reste expérimentale.
IO::Socket
IO::Socket::INET ne parvenait pas à ouvrir le port spécifié si le nom du service n'était pas connu. Il utilise maintenant correctement le numéro de port fourni tel quel.
File::Find
File::Find effectue maintenant correctement un chdir() lors du suivi des liens symboliques.
xsubpp
xsubpp tolère maintenant les sections POD intégrées.
"no Module;"
"no Module;" ne produit pas d'erreur même si le Module n'a pas de méthode unimport(). Ceci est parallèle au comportement de "use" par rapport à "import".
Tests
Un grand nombre de tests ont été ajoutés.

Fonctionnalités de base

untie() appellera désormais un hook UNTIE() s'il existe. Voir perltie pour plus de détails.

Le commutateur de ligne de commande "-DT" affiche des informations de tokenisation abondantes. Voir perlrun.

Les tableaux sont désormais toujours interpolés dans les chaînes entre guillemets doubles. Auparavant, "foo@bar.com" était une erreur fatale lors de la compilation, si un tableau @bar n'était pas utilisé ou déclaré. Ce comportement transitoire était destiné à faciliter la migration du code perl4 et est jugé inutile. Voir "Arrays now always interpolate into double-quoted strings".

keys(), each(), pop(), push(), shift(), splice() et unshift() peuvent tous être remplacés maintenant.

"my __PACKAGE__ $obj" fait maintenant ce qui est attendu.

Problèmes de configuration

Sur certains systèmes (IRIX et Solaris entre autres), le malloc système est manifestement meilleur. Bien que les valeurs par défaut n'aient pas été modifiées afin de conserver la compatibilité binaire avec les versions antérieures, vous pourriez avoir intérêt à compiler perl avec "Configure -Uusemymalloc ..." comme discuté dans le fichier INSTALL.

"Configure" a été amélioré de diverses manières :

  • Minimise l'utilisation de fichiers temporaires.
  • Par défaut, ne lie pas perl avec des bibliothèques non utilisées par celui-ci, telles que les diverses bibliothèques dbm. Les indices SunOS 4.x préservent le comportement sur cette plate-forme.
  • Le support des modèles mémoire de type pdp11 a été supprimé en raison de l'obsolescence.
  • La construction en dehors de l'arborescence source est supportée sur les systèmes qui ont des liens symboliques. Ceci est fait en exécutant 
    sh /path/to/source/Configure -Dmksymlinks ...
make all test install

    dans un répertoire autre que le répertoire source de perl. Voir INSTALL.

  • "Configure -S" peut être exécuté de manière non interactive.

Améliorations du noyau

Clonage d'interpréteur, threads et concurrence

Perl 5.6.0 introduit les débuts du support pour l'exécution de plusieurs interpréteurs de manière concurrente dans différents threads. En conjonction avec l'appel API perl_clone(), qui peut être utilisé pour dupliquer sélectivement l'état de n'importe quel interpréteur donné, il est possible de compiler un morceau de code une fois dans un interpréteur, de cloner cet interpréteur une ou plusieurs fois, et d'exécuter tous les interpréteurs résultants dans des threads distincts.

Sur la plateforme Windows, cette fonctionnalité est utilisée pour émuler fork() au niveau de l'interpréteur. Voir perlfork pour plus de détails à ce sujet.

Cette fonctionnalité est encore en évolution. Elle est destinée à être utilisée pour cloner sélectivement une sous-routine et les données qui y sont accessibles dans un interpréteur séparé, et exécuter la sous-routine clonée dans un thread séparé. Puisqu'il n'y a pas de données partagées entre les interpréteurs, peu ou pas de verrouillage sera nécessaire (sauf si des parties de la table des symboles sont explicitement partagées). Ceci est clairement destiné à être un remplacement facile à utiliser du support de threads existant.

Le support pour le clonage d'interpréteurs et la concurrence d'interpréteurs peut être activé en utilisant l'option de configuration -Dusethreads (voir win32/Makefile pour savoir comment l'activer sous Windows). L'exécutable perl résultant sera fonctionnellement identique à celui qui a été compilé avec -Dmultiplicity, mais l'appel API perl_clone() ne sera disponible que dans le premier.

-Dusethreads active la macro cpp USE_ITHREADS par défaut, ce qui active à son tour des modifications du code source de Perl qui fournissent une séparation claire entre l'arbre des opérations (op tree) et les données sur lesquelles il opère. Le premier est immuable et peut donc être partagé entre un interpréteur et tous ses clones, tandis que le second est considéré comme local à chaque interpréteur et est donc copié pour chaque clone.

Notez que la compilation de Perl avec l'option de configuration -Dusemultiplicity est suffisante si vous souhaitez exécuter plusieurs interpréteurs indépendants de manière concurrente dans différents threads. -Dusethreads fournit uniquement la fonctionnalité supplémentaire de l'appel API perl_clone() et d'autres supports pour l'exécution d'interpréteurs clonés de manière concurrente.

sont sujets à modification.

Catégories d'avertissement à portée lexicale

Vous pouvez désormais contrôler la granularité des avertissements émis par perl à un niveau plus fin en utilisant le pragma "use warnings". warnings et perllexwarn contiennent une documentation abondante sur cette fonctionnalité.

Support Unicode et UTF-8

Perl utilise désormais UTF-8 comme représentation interne des chaînes de caractères. Les pragmas "utf8" et "bytes" sont utilisés pour contrôler ce support dans la portée lexicale actuelle. Voir perlunicode, utf8 et bytes pour plus d'informations.

On s'attend à ce que cette fonctionnalité évolue rapidement pour supporter une forme de disciplines d'E/S qui peuvent être utilisées pour spécifier le type de données d'entrée et de sortie (octets ou caractères). Jusqu'à ce que cela se produise, des modules supplémentaires de CPAN seront nécessaires pour compléter la boîte à outils pour la gestion de l'Unicode.

NOTE : Ceci doit être considéré comme une fonctionnalité expérimentale. Les détails
d'implémentation sont sujets à modification.

Support pour l'interpolation de caractères nommés

La nouvelle séquence d'échappement "\N" interpole des caractères nommés dans les chaînes. Par exemple, "Salut ! \N{WHITE SMILING FACE}" est évalué en une chaîne avec un visage souriant Unicode à la fin.

Déclarations "our"

Une déclaration "our" introduit une valeur qui peut être comprise comme un alias symbolique à portée lexicale vers une variable globale dans le package qui était courant là où la variable a été déclarée. Ceci est principalement utile comme alternative au pragma "vars", mais offre également la possibilité d'introduire des typages et d'autres attributs pour de telles variables. Voir "our" dans perlfunc.

Support pour les chaînes représentées comme un vecteur d'ordinaux

Les littéraux de la forme "v1.2.3.4" sont désormais analysés comme une chaîne composée de caractères avec les ordinaux spécifiés. C'est une manière alternative et plus lisible de construire des chaînes (éventuellement Unicode) au lieu d'interpoler des caractères, comme dans "\x{1}\x{2}\x{3}\x{4}". Le "v" initial peut être omis s'il y a plus de deux ordinaux, donc 1.2.3 est analysé de la même manière que "v1.2.3".

Les chaînes écrites sous cette forme sont également utiles pour représenter des numéros de version. Il est facile de comparer de tels numéros de version (qui sont en réalité de simples chaînes) en utilisant l'un des opérateurs de comparaison de chaînes habituels "eq", "ne", "lt", "gt", etc., ou d'effectuer des opérations sur les bits de chaînes dessus en utilisant "|", "&", etc.

En conjonction avec la nouvelle variable magique $^V (qui contient la version de perl sous forme de chaîne), de tels littéraux peuvent être utilisés comme un moyen lisible de vérifier si vous exécutez une version particulière de Perl :

# ceci sera également analysé dans les anciennes versions de Perl
if ($^V and $^V gt v5.6.0) {
    # nouvelles fonctionnalités prises en charge
}

"require" et "use" ont également une magie spéciale pour prendre en charge de tels littéraux. Ils seront interprétés comme une version plutôt que comme un nom de module :

require v5.6.0;             # croak si $^V lt v5.6.0
use v5.6.0;                 # idem, mais croak à la compilation

Alternativement, le "v" peut être omis s'il y a plus d'un point :

require 5.6.0;
use 5.6.0;

De plus, "sprintf" et "printf" prennent en charge le drapeau de format spécifique à Perl %v pour imprimer les ordinaux des caractères dans des chaînes arbitraires :

printf "v%vd", $^V;         # imprime la version actuelle, telle que "v5.5.650"
printf "%*vX", ":", $addr;  # formate une adresse IPv6
printf "%*vb", " ", $bits;  # affiche une chaîne de bits

Voir "Scalar value constructors" dans perldata pour plus d'informations.

À partir de la version 5.6.0 de Perl, la convention de numérotation des versions a été modifiée pour adopter un schéma d'"entier décimal" plus courant dans les projets open source.

Les versions de maintenance de v5.6.0 seront publiées sous les noms v5.6.1, v5.6.2, etc. La prochaine série de développement suivant v5.6.0 sera numérotée v5.7.x, commençant par v5.7.0, et la prochaine version de production majeure suivant v5.6.0 sera v5.8.0.

Le module anglais définit maintenant $PERL_VERSION à $^V (une valeur chaîne) plutôt qu'à $] (une valeur numérique). (Ceci est une incompatibilité potentielle. Envoyez-nous un rapport via perlbug si vous êtes affecté par cela.)

La syntaxe v1.2.3 est également maintenant légale en Perl. Voir "Support des chaînes représentées comme un vecteur d'ordinaux" pour plus de détails.

Pour s'adapter au nouveau système de versionnement qui utilise au moins trois chiffres significatifs pour chaque composant de version, la méthode utilisée pour incrémenter le numéro de sous-version a également légèrement changé. Nous supposons que les versions antérieures à v5.6.0 ont incrémenté le composant de sous-version par multiples de 10. Les versions après v5.6.0 les incrémenteront de 1. Ainsi, en utilisant la nouvelle notation, 5.005_03 est "identique" à v5.5.30, et la première version de maintenance suivant v5.6.0 sera v5.6.1 (qui devrait être interprétée comme équivalente à une valeur flottante de 5.006_001 dans l'ancien format, stockée dans $]).

Nouvelle syntaxe pour déclarer les attributs de sous-programmes

Auparavant, si vous vouliez marquer un sous-programme comme étant un appel de méthode ou nécessitant un lock() automatique à son entrée, vous deviez le déclarer avec une pragmatique "use attrs" dans le corps du sous-programme. Cela peut maintenant être réalisé avec une syntaxe de déclaration, comme ceci :

sub mymethod : locked method;
...
sub mymethod : locked method {
    ...
}
sub othermethod :locked :method;
...
sub othermethod :locked :method {
    ...
}

(Notez que seul le premier ":" est obligatoire, et les espaces autour du ":" sont facultatifs.)

AutoSplit.pm et SelfLoader.pm ont été mis à jour pour conserver les attributs avec les stub qu'ils fournissent. Voir attributes.

Les descripteurs de fichiers et de répertoires peuvent être autovivifiés

Similaire à la façon dont des constructions comme "$x->[0]" autovivifient une référence, les constructeurs de descripteurs (open(), opendir(), pipe(), socketpair(), sysopen(), socket(), et accept()) autovivifient maintenant un descripteur de fichier ou de répertoire si le descripteur passé est une variable scalaire non initialisée. Cela permet d'utiliser des constructions comme "open(my $fh, ...)" et "open(local $fh,...)" pour créer des descripteurs de fichiers qui seront commodément fermés automatiquement lorsque la portée se termine, à condition qu'il n'y ait pas d'autres références à eux. Cela élimine largement le besoin de typeglobs lors de l'ouverture de descripteurs de fichiers qui doivent être passés, comme dans l'exemple suivant :

sub myopen {
    open my $fh, "@_"
         or die "Impossible d'ouvrir '@_': $!";
    return $fh;
}
{
    my $f = myopen("</etc/motd");
    print <$f>;
    # $f implicitement fermé ici
}

open() avec plus de deux arguments

Si open() reçoit trois arguments au lieu de deux, le deuxième argument est utilisé comme mode et le troisième argument est considéré comme le nom du fichier. Ceci est principalement utile pour se protéger contre le comportement magique involontaire de la forme traditionnelle à deux arguments. Voir "open" dans perlfunc.

Support 64 bits

Toute plateforme disposant d'entiers 64 bits, soit

(1) nativement en tant que longs ou ints
(2) via des indicateurs de compilateur spéciaux
(3) en utilisant long long ou int64_t

est capable d'utiliser des "quads" (entiers 64 bits) comme suit :

  • constantes (décimales, hexadécimales, octales, binaires) dans le code
  • arguments pour oct() et hex()
  • arguments pour print(), printf() et sprintf() (préfixes d'indicateur ll, L, q)
  • imprimés tels quels
  • formats "q" et "Q" de pack() et unpack()
  • en arithmétique de base : + - * / % (NOTE : opérer près des limites des valeurs entières peut produire des résultats surprenants)
  • en arithmétique de bits : & | ^ ~ << >> (NOTE : ceux-ci étaient forcés d'avoir 32 bits de large mais opèrent maintenant sur toute la largeur native.)
  • vec()

Notez que sauf si vous avez le cas (a), vous devrez configurer et compiler Perl en utilisant l'indicateur Configure -Duse64bitint.

NOTE : Les indicateurs Configure -Duselonglong et -Duse64bits sont obsolètes.
Utilisez plutôt -Duse64bitint.

Il existe en fait deux modes de 64 bits : le premier est obtenu en utilisant Configure -Duse64bitint et le second en utilisant Configure -Duse64bitall. La différence est que le premier est minimal et le second maximal. Le premier fonctionne dans plus d'endroits que le second.

La directive "use64bitint" fait le minimum requis pour avoir des entiers 64 bits dans Perl (cela peut signifier, par exemple, utiliser des "long longs") tandis que votre mémoire peut toujours être limitée à 2 gigaoctets (car vos pointeurs pourraient encore être 32 bits). Notez que le nom "64bitint" n'implique pas que votre compilateur C utilisera des "int"s 64 bits (il pourrait, mais il n'est pas obligé) : "use64bitint" signifie que vous pourrez avoir des valeurs scalaires de 64 bits de large.

La directive "use64bitall" va jusqu'au bout en tentant de basculer également les entiers (si possible), les longs (et les pointeurs) à 64 bits. Cela peut créer un Perl encore plus incompatible binaire que -Duse64bitint : l'exécutable résultant pourrait ne pas du tout fonctionner sur une machine 32 bits, ou vous pourriez avoir à redémarrer/reconfigurer/reconstruire votre système d'exploitation pour qu'il prenne en charge les 64 bits.

Les systèmes nativement 64 bits comme Alpha et Cray n'ont besoin ni de -Duse64bitint ni de -Duse64bitall.

Enfin, notez qu'en raison de l'habitude de Perl d'utiliser toujours des nombres à virgule flottante, les quads ne sont toujours pas de vrais entiers. Lorsque les quads dépassent leurs limites (0...18 446 744 073 709 551 615 non signés, -9 223 372 036 854 775 808...9 223 372 036 854 775 807 signés), ils sont silencieusement promus en nombres à virgule flottante, après quoi ils commenceront à perdre de la précision (dans leurs chiffres inférieurs).

NOTE : Le support 64 bits est encore expérimental sur la plupart des plateformes.
Le support existant ne couvre que le modèle de données LP64. En particulier, le
modèle de données LLP64 n'est pas encore supporté. Les bibliothèques et les API système 64 bits sur de nombreuses plateformes ne sont pas stabilisées--votre expérience peut varier.

Support des grands fichiers

Si vous avez des systèmes de fichiers qui supportent les "grands fichiers" (fichiers de plus de 2 gigaoctets), vous pouvez maintenant aussi les créer et y accéder depuis Perl.

NOTE : L'action par défaut est d'activer le support des grands fichiers, si
disponible sur la plateforme.

Si le support des grands fichiers est activé, et que vous avez une constante Fcntl O_LARGEFILE, O_LARGEFILE est automatiquement ajouté aux drapeaux de sysopen().

Attention, à moins que votre système de fichiers ne supporte également les "fichiers épars", se déplacer vers des milliards de pétaoctets peut être déconseillé.

Notez qu'en plus de nécessiter un système de fichiers approprié pour gérer les grands fichiers, vous devrez peut-être également ajuster vos limites de taille de fichier par processus (ou par système, par groupe de processus, ou par utilisateur) avant d'exécuter des scripts Perl qui tentent de gérer de grands fichiers, surtout si vous avez l'intention d'écrire de tels fichiers.

Enfin, en plus de vos limites de taille de fichier par processus/groupe de processus, vous pourriez avoir des limites de quota sur vos systèmes de fichiers qui vous empêchent (votre identifiant utilisateur ou votre identifiant de groupe utilisateur) d'utiliser de grands fichiers.

L'ajustement de vos limites par processus/utilisateur/groupe/système de fichiers/système d'exploitation sort du cadre du langage Perl de base. Pour les limites de processus, vous pouvez essayer d'augmenter les limites en utilisant la commande limits/limit/ulimit de votre shell avant d'exécuter Perl. L'extension BSD::Resource (non incluse dans la distribution Perl standard) peut également être utile, elle offre l'interface getrlimit/setrlimit qui peut être utilisée pour ajuster les limites d'utilisation des ressources du processus, y compris la limite de taille de fichier maximale.

Long doubles

Dans certains systèmes, vous pourrez utiliser les long doubles pour améliorer la portée et la précision de vos nombres à virgule flottante double précision (c'est-à-dire, les nombres de Perl). Utilisez Configure -Duselongdouble pour activer ce support (s'il est disponible).

"plus de bits"

Vous pouvez utiliser "Configure -Dusemorebits" pour activer à la fois le support 64 bits et le support long double.

Support amélioré pour les sous-programmes de sort()

Les sous-programmes Perl avec un prototype de "($$)", et les XSUBs en général, peuvent maintenant être utilisés comme sous-programmes de tri. Dans les deux cas, les deux éléments à comparer sont passés comme paramètres normaux dans @_. Voir "sort" dans perlfunc.

Pour les sous-programmes de tri non prototypés, le comportement historique de passage des éléments à comparer comme variables globales $a et $b reste inchangé.

"sort $coderef @foo" autorisé

sort() n'acceptait pas de référence de sous-programme comme fonction de comparaison dans les versions antérieures. Ceci est maintenant autorisé.

Globage de fichiers implémenté en interne

Perl utilise maintenant automatiquement l'implémentation de File::Glob pour l'opérateur glob(). Cela évite d'utiliser un processus csh externe et les problèmes qui y sont associés.

Prise en charge des blocs CHECK

En plus de « BEGIN », « INIT », « END », « DESTROY » et « AUTOLOAD », les sous-routines nommées « CHECK » sont désormais spéciales. Elles sont mises en file d'attente pendant la compilation et se comportent de manière similaire aux blocs END, sauf qu'elles sont appelées à la fin de la compilation plutôt qu'à la fin de l'exécution. Elles ne peuvent pas être appelées directement.

Syntaxe de classe de caractères POSIX [: :] prise en charge

Par exemple, pour faire correspondre les caractères alphabétiques, utilisez /[[:alpha:]]/. Voir perlre pour plus de détails.

Meilleur générateur de nombres pseudo-aléatoires

Dans les versions 5.005_x et antérieures, la fonction rand() de Perl utilisait la fonction rand(3) de la bibliothèque C. À partir de la version 5.005_52, Configure teste les fonctions drand48(), random() et rand() (dans cet ordre) et choisit la première qu'il trouve.

Ces changements devraient aboutir à de meilleurs nombres aléatoires de la part de rand().

Opérateur « qw// » amélioré

L'opérateur « qw// » est désormais évalué au moment de la compilation en une liste réelle au lieu d'être remplacé par un appel à l'exécution à split(). Cela élimine le comportement erroné déroutant de « qw// » en contexte scalaire, qui avait hérité ce comportement de split().

Ainsi :

$foo = ($bar) = qw(a b c); print "$foo|$bar\n";

affiche désormais correctement « 3|a », au lieu de « 2|a ».

Meilleur comportement dans le pire des cas des tables de hachage

De petites modifications dans l'algorithme de hachage ont été mises en œuvre afin d'améliorer la distribution des bits de poids faible dans la valeur hachée. On s'attend à ce que cela entraîne de meilleures performances sur les clés qui sont des séquences répétées.

Format 'Z' de pack() pris en charge

Le nouveau type de format 'Z' est utile pour empaqueter et dépaqueter des chaînes de caractères terminées par un caractère nul. Voir « pack » dans perlfunc.

Modificateur de format '!' de pack() pris en charge

Le nouveau modificateur de type de format '!' est utile pour empaqueter et dépaqueter des entiers courts, entiers et longs natifs. Voir « pack » dans perlfunc.

pack() et unpack() prennent en charge les chaînes de caractères comptées

Le caractère de modèle '/' peut être utilisé pour spécifier un type de chaîne de caractères comptée à empaqueter ou dépaqueter. Voir « pack » dans perlfunc.

Commentaires dans les modèles de pack()

Le caractère '#' dans un modèle introduit un commentaire jusqu'à la fin de la ligne. Cela facilite la documentation des modèles de pack().

Références faibles

Dans les versions précédentes de Perl, vous ne pouviez pas mettre en cache des objets pour permettre leur suppression si la dernière référence externe au cache était supprimée. La référence dans le cache maintiendrait un compteur de références sur l'objet, et les objets ne seraient jamais détruits.

Un autre problème familier concerne les références circulaires. Lorsqu'un objet se référence lui-même, son compteur de références ne descend jamais à zéro, et il n'est pas détruit tant que le programme n'est pas sur le point de se terminer.

Les références faibles résolvent ce problème en vous permettant de « renforcer » (weaken) n'importe quelle référence, c'est-à-dire de faire en sorte qu'elle ne compte pas dans le compteur de références. Lorsque la dernière référence non faible à un objet est supprimée, l'objet est détruit et toutes les références faibles à cet objet sont automatiquement indéfinies.

Pour utiliser cette fonctionnalité, vous avez besoin du package Devel::WeakRef de CPAN, qui contient une documentation supplémentaire.

NOTE : Ceci est une fonctionnalité expérimentale. Les détails sont sujets à modification.

Nombres binaires pris en charge

Les nombres binaires sont désormais pris en charge en tant que littéraux, dans les formats s?printf et dans oct() :

$answer = 0b101010;
printf "The answer is: %b\n", oct("0b101010");

Sous-routines lvalue

Les sous-routines peuvent désormais retourner des lvalues modifiables. Voir « Sous-routines lvalue » dans perlsub.

NOTE : Ceci est une fonctionnalité expérimentale. Les détails sont sujets à modification.

Certaines flèches peuvent être omises dans les appels via des références

Perl permet désormais d'omettre la flèche dans de nombreuses constructions impliquant des appels de sous-routines via des références. Par exemple, « $foo[10]->('foo') » peut maintenant s'écrire « $foo[10]('foo') ». Ceci est très similaire à la façon dont la flèche peut être omise dans « $foo[10]->{'foo'} ». Notez cependant que la flèche est toujours requise pour « foo(10)->('bar') ».

Les opérateurs d'affectation booléens sont des lvalues légales

Les constructions telles que « ($a ||= 2) += 1 » sont désormais autorisées.

exists() est pris en charge sur les noms de sous-routines

La fonction intégrée exists() fonctionne désormais sur les noms de sous-routines. Une sous-routine est considérée comme existante si elle a été déclarée (même implicitement). Voir « exists » dans perlfunc pour des exemples.

exists() et delete() sont pris en charge sur les éléments de tableaux

Les fonctions intégrées exists() et delete() fonctionnent désormais également sur les tableaux simples. Le comportement est similaire à celui sur les éléments de tables de hachage.

exists() peut être utilisé pour vérifier si un élément de tableau a été initialisé. Cela évite l'autovivification des éléments de tableau qui n'existent pas. Si le tableau est lié, la méthode EXISTS() du package lié correspondant sera appelée.

delete() peut être utilisé pour supprimer un élément du tableau et le retourner. L'élément de tableau à cette position revient à son état non initialisé, de sorte que le test du même élément avec exists() renverra false. Si l'élément est celui de la fin, la taille du tableau est également réduite jusqu'au plus haut élément qui renvoie true pour exists(), ou 0 si aucun tel élément n'est trouvé. Si le tableau est lié, la méthode DELETE() du package lié correspondant sera appelée.

Voir « exists » dans perlfunc et « delete » dans perlfunc pour des exemples.

Les pseudo-tables de hachage fonctionnent mieux

Le déréférencement de certains types de valeurs de référence dans une pseudo-table de hachage, tels que « $ph->{foo}[1] », était accidentellement interdit. Ceci a été corrigé.

Appliqué à un élément de pseudo-table de hachage, exists() indique désormais si la valeur spécifiée existe, et pas seulement si la clé est valide.

delete() fonctionne désormais sur les pseudo-tables de hachage. Lorsqu'il reçoit un élément ou une tranche de pseudo-table de hachage, il supprime les valeurs correspondant aux clés (mais pas les clés elles-mêmes). Voir « Pseudo-hashes : Using an array as a hash » dans perlref.

Les tranches de pseudo-tables de hachage avec des clés constantes sont désormais optimisées en recherches de tableaux au moment de la compilation.

Les affectations de listes aux tranches de pseudo-tables de hachage sont désormais prises en charge.

Le pragma « fields » fournit désormais des moyens de créer des pseudo-tables de hachage, via fields::new() et fields::phash(). Voir fields.

NOTE : Le type de données pseudo-hash reste expérimental.
Se limiter aux éléments d'interface fournis par le pragma fields vous protégera contre tout changement futur.

Vidange automatique des tampons de sortie

Les fonctions fork(), exec(), system(), qx//, et les open() avec pipe vident désormais les tampons de tous les fichiers ouverts en écriture lorsque l'opération a été tentée. Cela élimine la plupart des erreurs de mise en mémoire tampon déroutantes subies par les utilisateurs qui ignoraient comment Perl gère les E/S en interne.

Ceci n'est pas pris en charge sur certaines plateformes comme Solaris où une implémentation suffisamment correcte de fflush(NULL) n'est pas disponible.

Lorsque possible, les données tamponnées sont ignorées du descripteur de fichier d'entrée dupliqué

« open(NEW, « tente désormais d'ignorer toutes les données qui ont été précédemment lues et mises en tampon dans « OLD » avant de dupliquer le descripteur. Sur les plateformes où cela est autorisé, la prochaine opération de lecture sur « NEW » renverra les mêmes données que l'opération correspondante sur « OLD ». Auparavant, elle aurait renvoyé les données à partir du début du bloc de données suivant.

eof() a la même magie que <>

eof() renvoyait vrai si aucune tentative de lecture depuis "<>" n'avait encore été faite. eof() a été modifié pour avoir sa propre petite magie : il ouvre maintenant les fichiers "<>".

binmode() peut être utilisé pour définir les modes :crlf et :raw

binmode() accepte maintenant un deuxième argument qui spécifie une discipline pour le handle en question. Les deux pseudo-disciplines ":raw" et ":crlf" sont actuellement prises en charge sur les plateformes dérivées de DOS. Voir "binmode" dans perlfunc et open.

"-T" filetest reconnaît les fichiers encodés en UTF-8 comme "texte"

L'algorithme utilisé pour le test de fichier "-T" a été amélioré pour identifier correctement le contenu UTF-8 comme "texte".

system(), backticks et pipe open reflètent maintenant l'échec de exec()

Sur Unix et plateformes similaires, system(), qx() et open(FOO, "cmd |") etc., sont implémentés via fork() et exec(). Lorsque l' exec() sous-jacent échouait, les versions précédentes ne rapportaient pas l'erreur correctement, car l' exec() se produisait dans un processus différent.

Le processus enfant communique maintenant avec le parent concernant l'erreur lors du lancement de la commande externe, ce qui permet à ces constructions de retourner avec leur valeur d'erreur habituelle et de définir $!.

Diagnostics améliorés

Les numéros de ligne ne sont plus supprimés (dans la plupart des circonstances probables) pendant la phase de destruction globale.

Les diagnostics émis par du code exécuté dans des threads autres que le thread principal sont maintenant accompagnés de l'identifiant du thread.

Les caractères nuls intégrés dans les diagnostics apparaissent maintenant réellement. Ils tronquaient le message dans les versions précédentes.

$foo::a et $foo::b sont maintenant exemptés des avertissements de "typo possible" uniquement si sort() est rencontré dans le package "foo".

Les échappements alphabétiques non reconnus rencontrés lors de l'analyse des constructions de guillemets génèrent maintenant un avertissement, car ils peuvent acquérir de nouvelles sémantiques dans les versions ultérieures de Perl.

De nombreux diagnostics rapportent maintenant l'opération interne qui a provoqué l'avertissement, comme suit :

Use of uninitialized value in concatenation (.) at (eval 1) line 1.
Use of uninitialized value in print at (eval 1) line 1.

Les diagnostics qui se produisent dans eval peuvent également signaler le fichier et le numéro de ligne où se trouve l'eval, en plus du numéro de séquence d'eval et du numéro de ligne dans le texte évalué lui-même. Par exemple :

Not enough arguments for scalar at (eval 4)[newlib/perl5db.pl:1411] line 2, at EOF

Diagnostics suivent STDERR

La sortie des diagnostics va maintenant vers le fichier vers lequel le handle "STDERR" pointe, au lieu d'aller toujours vers le "stderr" de la bibliothèque d'exécution C sous-jacente.

Comportement plus cohérent de close-on-exec

Sur les systèmes qui prennent en charge un drapeau close-on-exec sur les descripteurs de fichiers, ce drapeau est maintenant défini pour tous les handles créés par pipe(), socketpair(), socket() et accept(), si cela est justifié par la valeur de $^F qui peut être en vigueur. Les versions antérieures négligeaient de définir le drapeau pour les handles créés avec ces opérateurs. Voir "pipe" dans perlfunc, "socketpair" dans perlfunc, "socket" dans perlfunc, "accept" dans perlfunc, et "$^F" dans perlvar.

syswrite() plus facile à utiliser

L'argument de longueur de syswrite() est devenu facultatif.

Meilleures vérifications syntaxiques sur les opérateurs unaires entre parenthèses

Des expressions telles que :

print defined(&foo,&bar,&baz);
print uc("foo","bar","baz");
undef($foo,&bar);

étaient auparavant autorisées par accident dans les versions antérieures, et produisaient un comportement imprévisible. Certaines produisaient des avertissements auxiliaires lorsqu'elles étaient utilisées de cette manière ; d'autres faisaient silencieusement la mauvaise chose.

Les formes entre parenthèses de la plupart des opérateurs unaires qui attendent un seul argument garantissent maintenant qu'ils ne sont pas appelés avec plus d'un argument, ce qui rend les cas présentés ci-dessus des erreurs de syntaxe. Le comportement habituel de :

print defined &foo, &bar, &baz;
print uc "foo", "bar", "baz";
undef $foo, &bar;

reste inchangé. Voir perlop.

Les opérateurs bit à bit prennent en charge la largeur entière native complète

Les opérateurs bit à bit (& | ^ ~ << >>) opèrent maintenant sur la largeur entière native complète (dont la taille exacte est disponible dans $Config{ivsize}). Par exemple, si votre plateforme est nativement 64 bits ou si Perl a été configuré pour utiliser des entiers 64 bits, ces opérations s'appliquent à 8 octets (contre 4 octets sur les plateformes 32 bits). Pour la portabilité, assurez-vous de masquer les bits excédentaires dans le résultat du "~" unaire, par exemple "~$x & 0xffffffff".

Fonctionnalités de sécurité améliorées

Plus d'opérations potentiellement dangereuses 'taint' (marquent) leurs résultats pour une sécurité améliorée.

Les champs "passwd" et "shell" retournés par getpwent(), getpwnam(), et getpwuid() sont maintenant 'tainted', car l'utilisateur peut affecter son propre mot de passe crypté et son shell de connexion.

La variable modifiée par shmread(), et les messages retournés par msgrcv() (et son interface orientée objet IPC::SysV::Msg::rcv) sont également 'tainted', car d'autres processus non fiables peuvent modifier des messages et des segments de mémoire partagée à leurs propres fins néfastes.

Prototype de bareword plus fonctionnel (*)

Les prototypes de barewords ont été rationalisés pour leur permettre d'être utilisés pour remplacer les fonctions intégrées qui acceptent les barewords et les interprètent d'une manière spéciale, comme "require" ou "do".

Les arguments prototypés comme "*" sont maintenant visibles dans la sous-routine comme un scalaire simple ou comme une référence à un typeglob. Voir "Prototypes" dans perlsub.

"require" et "do" peuvent être remplacés

"require" et "do 'file'" les opérations peuvent être remplacées localement en important des sous-routines du même nom dans le package courant (ou globalement en les important dans l'espace de noms CORE::GLOBAL::). Remplacer "require" affectera également "use", à condition que le remplacement soit visible au moment de la compilation. Voir "Overriding Built-in Functions" dans perlsub.

$^X les variables peuvent maintenant avoir des noms plus longs qu'un seul caractère

Auparavant, $^X était synonyme de ${"\cX"}, mais $^XY était une erreur de syntaxe. Maintenant, les noms de variables commençant par un caractère de contrôle peuvent être arbitrairement longs. Cependant, pour des raisons de compatibilité, ces variables *doivent* être écrites avec des accolades explicites, comme "${^XY}" par exemple. "${^XYZ}" est synonyme de ${"\cXYZ"}. Les noms de variables avec plus d'un caractère de contrôle, comme "${^XY^Z}", sont illégaux.

L'ancienne syntaxe n'a pas changé. Comme auparavant, `^X' peut être soit un caractère de contrôle littéral X, soit la séquence de deux caractères `caret' plus `X'. Lorsque les accolades sont omises, le nom de la variable s'arrête après le caractère de contrôle. Ainsi "$^XYZ" continue d'être synonyme de "$^X . "YZ"" comme auparavant.

Comme auparavant, les variables lexicales ne peuvent pas avoir de noms commençant par des caractères de contrôle. Comme auparavant, les variables dont les noms commencent par un caractère de contrôle sont toujours forcées d'appartenir au package `main'. Toutes ces variables sont réservées pour des extensions futures, à l'exception de celles qui commencent par "^_", qui peuvent être utilisées par les programmes utilisateurs et sont garanties de ne pas acquérir de signification spéciale dans une version future de Perl.

Nouvelle variable $^C reflète le commutateur "-c"

$^C a une valeur booléenne qui indique si perl est exécuté en mode compilation seule (c'est-à-dire via le commutateur "-c"). Comme les blocs BEGIN sont exécutés dans de telles conditions, cette variable permet au code perl de déterminer si les actions qui n'ont de sens que pendant l'exécution normale sont justifiées. Voir perlvar.

Nouvelle variable $^V contient la version de Perl sous forme de chaîne

$^V contient le numéro de version de Perl sous forme d'une chaîne composée de caractères dont les ordinals correspondent aux numéros de version, c'est-à-dire v5.6.0. Cela peut être utilisé dans les comparaisons de chaînes.

Voir "Support for strings represented as a vector of ordinals" pour un exemple.

Changements dans Perl 5.6.1

Ce document décrit les changements par rapport à Perl 5.6.0.

Améliorations du noyau

La plupart des changements majeurs dans cette version sont liés à l'amélioration de la gestion des chaînes de caractères et de la détection des erreurs.

Avertissements optionnels Y2K

Si Perl est compilé avec la macro cpp "PERL_Y2KWARN" définie, il émet des avertissements optionnels lors de la concaténation du nombre 19 avec un autre nombre.

Ce comportement doit être spécifiquement activé lors de l'exécution de Configure. Voir INSTALL et README.Y2K.

Les tableaux s'interpolent maintenant toujours dans les chaînes entre guillemets doubles

Dans les chaînes entre guillemets doubles, les tableaux s'interpolent maintenant, quoi qu'il arrive. Le comportement dans les versions antérieures de Perl 5 était que les tableaux s'interpolaient dans les chaînes si le tableau avait été mentionné avant que la chaîne ne soit compilée, et sinon Perl levait une erreur fatale lors de la compilation. Dans les versions 5.000 à 5.003, l'erreur était

Literal @example now requires backslash

Dans les versions 5.004_01 à 5.6.0, l'erreur était

In string, @example now must be written as \@example

L'idée était d'habituer les gens à écrire "fred\@example.com" lorsqu'ils voulaient un signe "@" littéral, tout comme ils ont toujours écrit "Give me back my \$5" lorsqu'ils voulaient un signe "$" littéral.

À partir de la version 5.6.1, lorsque Perl rencontre maintenant un signe "@" dans une chaîne entre guillemets doubles, il tente *toujours* d'interpoler un tableau, qu'il ait ou non déjà utilisé ou déclaré le tableau. L'erreur fatale a été rétrogradée en un avertissement optionnel :

Possible unintended interpolation of @example in string

Cela vous avertit que "fred@example.com" sera transformé en "fred.com" si vous n'échappez pas le "@". Voir http://perl.plover.com/at-error.html pour plus de détails sur l'historique.

@- et @+ fournissent les décalages de début/fin des sous-matches d'expression régulière

Les nouvelles variables magiques @- et @+ fournissent respectivement les décalages de début et de fin de $&, $2, etc. Voir perlvar pour les détails.

Améliorations des performances

Les sort() simples utilisant { $a <=> $b } et similaires sont optimisés

De nombreuses opérations courantes de sort() utilisant un bloc en ligne simple sont maintenant optimisées pour des performances plus rapides.

Affectations optimisées aux variables lexicales

Certaines opérations du côté droit des instructions d'affectation ont été optimisées pour définir directement la variable lexicale du côté gauche, éliminant les coûts de copie redondants.

Appels de sous-routines plus rapides

Des modifications mineures dans la manière dont les appels de sous-routines sont gérés en interne fournissent des améliorations marginales des performances.

delete(), each(), values() et l'itération de hachage sont plus rapides

Les valeurs de hachage retournées par delete(), each(), values() et les hachages dans un contexte de liste sont les valeurs réelles dans le hachage, au lieu de copies. Cela entraîne des performances significativement meilleures, car cela élimine les copies inutiles dans la plupart des situations.

Améliorations de l'installation et de la configuration

Améliorations

-Dusethreads signifie quelque chose de différent

Le drapeau -Dusethreads active désormais le support expérimental des threads basé sur l'interpréteur par défaut. Pour obtenir la saveur des threads expérimentaux qui était dans 5.005 au lieu de cela, vous devez exécuter Configure avec ""-Dusethreads -Duse5005threads"".

À partir de v5.6.0, le support des threads d'interpréteur manque toujours d'un moyen de créer de nouveaux threads depuis Perl (c'est-à-dire que "use Thread;" ne fonctionnera pas avec les threads d'interpréteur). "use Thread;" continue d'être disponible lorsque vous spécifiez l'option -Duse5005threads à Configure, avec ses bugs et tout.

NOTE : Le support des threads continue d'être une fonctionnalité expérimentale.
Les interfaces et l'implémentation sont sujettes à des changements soudains et drastiques.

Répertoires d'installation améliorés

La structure d'installation a été enrichie pour améliorer la prise en charge de la maintenance de plusieurs versions de perl, pour fournir des emplacements pour les modules, scripts et pages de manuel fournis par le vendeur, et pour faciliter la maintenance des modules, scripts et pages de manuel ajoutés localement. Voir la section sur les répertoires d'installation dans le fichier INSTALL pour tous les détails. gcc essayé automatiquement si 'cc' ne semble pas fonctionner

Sur de nombreuses plateformes, le 'cc' fourni par le vendeur est trop dépouillé pour construire Perl (en gros, le 'cc' ne fait pas de C ANSI). Si tel semble être le cas et que le 'cc' ne semble pas être le compilateur C GNU 'gcc', une tentative automatique est faite pour trouver et utiliser 'gcc' à la place.

Corrections importantes des bogues

<HANDLE> sur fichiers vides

Avec $/ défini à "undef", le "bourrage" d'un fichier vide renvoie une chaîne de longueur zéro (au lieu de "undef", comme c'était le cas auparavant) la première fois que HANDLE est lu après que $/ est défini à "undef". Les lectures ultérieures renvoient "undef".

Cela signifie que la commande suivante ajoutera "foo" à un fichier vide (au lieu de ne rien faire) :

perl -0777 -pi -e 's/^/foo/' fichier_vide

Le comportement de :

perl -pi -e 's/^/foo/' fichier_vide

reste inchangé (le fichier reste vide).

Améliorations de "eval ' ...' "

Les numéros de ligne (tels que reflétés par caller() et la plupart des diagnostics) dans "eval '...'" étaient souvent incorrects lorsque des here documents étaient impliqués. Ceci a été corrigé.

Les recherches lexicales pour les variables apparaissant dans "eval '...'" au sein de fonctions qui étaient elles-mêmes appelées dans un "eval '...'" cherchaient au mauvais endroit les lexicals. La recherche lexicale se termine maintenant correctement à la limite du bloc de la sous-routine.

L'utilisation de "return" dans "eval {...}" provoquait la non-réinitialisation correcte de $@ lorsqu'aucune exception ne se produisait dans l'évaluation. Ceci a été corrigé.

L'analyse des here documents était erronée lorsqu'ils apparaissaient comme expression de remplacement dans "eval 's/.../.../e'". Ceci a été corrigé.

Toutes les erreurs de compilation sont de vraies erreurs

Certaines "erreurs" rencontrées lors de la compilation étaient, par nécessité, générées sous forme d'avertissements suivis d'une terminaison éventuelle du programme. Cela permettait de signaler plus d'erreurs de ce type en une seule exécution, plutôt que de provoquer un arrêt brutal à la première erreur rencontrée.

Le mécanisme de signalement de ces erreurs a été réimplémenté pour mettre en file d'attente les erreurs de compilation et les signaler à la fin de la compilation comme de vraies erreurs plutôt que comme des avertissements. Cela corrige les cas où les messages d'erreur fuyaient sous forme d'avertissements lorsque le code était compilé à l'exécution en utilisant "eval STRING", et permet également de piéger de manière fiable ces erreurs en utilisant "eval "..."".

Les descripteurs de fichiers fermés implicitement sont plus sûrs

Parfois, les descripteurs de fichiers fermés implicitement (comme lorsqu'ils sont localisés, et que Perl les ferme automatiquement à la sortie de la portée) pouvaient involontairement définir $? ou $!. Ceci a été corrigé.

Le comportement des tranches de liste est plus cohérent

Lors de la prise d'une tranche d'une liste littérale (par opposition à une tranche d'un tableau ou d'une table de hachage), Perl renvoyait auparavant une liste vide si le résultat était composé uniquement de valeurs undef.

Le nouveau comportement consiste à produire une liste vide si (et seulement si) la liste originale était vide. Considérons l'exemple suivant :

@a = (1,undef,undef,2)[2,1,2];

Le comportement précédent aurait eu pour résultat que @a n'ait aucun élément. Le nouveau comportement garantit qu'elle a trois éléments indéfinis.

Notez en particulier que le comportement des tranches des cas suivants reste inchangé :

@a = ()[1,2];
@a = (getpwent)[7,0];
@a = (quelque_chose_renvoyant_liste_vide())[2,1,2];
@a = @b[2,1,2];
@a = @c{'a','b','c'};

Voir perldata.

Prototype "(\$)" et $foo{a}

Une référence scalaire de prototype permet maintenant correctement un élément de table de hachage ou de tableau dans cet emplacement.

"goto &sub" et AUTOLOAD

La construction "goto &sub" fonctionne correctement lorsque &sub est effectivement auto-chargé.

"-bareword" autorisé sous "use integer"

L'auto-quotation des barewords précédés de "-" ne fonctionnait pas dans les versions précédentes lorsque le pragma "integer" était activé. Ceci a été corrigé.

Échecs dans DESTROY()

Lorsque du code dans un destructeur lançait une exception, il passait inaperçu dans les versions antérieures de Perl, à moins que quelqu'un ne regarde $@ juste après le point où le destructeur s'exécutait par hasard. De tels échecs sont maintenant visibles sous forme d'avertissements lorsque les avertissements sont activés.

Bogues de locale corrigés

printf() et sprintf() réinitialisaient auparavant la locale numérique à la locale par défaut "C". Ceci a été corrigé.

Les nombres formatés selon la locale numérique locale (comme l'utilisation d'une virgule décimale au lieu d'un point décimal) provoquaient des avertissements "n'est pas numérique", même si les opérations accédant à ces nombres produisaient des résultats corrects. Ces avertissements ont été supprimés.

Fuites de mémoire

La construction "eval 'return sub {...}'" pouvait parfois fuir de la mémoire. Ceci a été corrigé.

Les opérations qui ne sont pas des constructeurs de descripteurs de fichiers fuyaient auparavant de la mémoire lorsqu'elles étaient utilisées sur des descripteurs de fichiers invalides. Ceci a été corrigé.

Les constructions qui modifiaient @_ pouvaient ne pas désallouer les valeurs dans @_ et donc fuir de la mémoire. Ceci a été corrigé.

Méta-brouillons de sous-routines superflus après des appels de sous-routines échoués

Perl pouvait parfois créer des brouillons de sous-routines vides lorsqu'une sous-routine n'était pas trouvée dans le paquet. Ces cas empêchaient les recherches de méthodes ultérieures de progresser dans les paquets de base. Ceci a été corrigé.

Échecs de taint sous "-U"

Lors de l'exécution en mode non sécurisé, les violations de taint pouvaient parfois provoquer des échecs silencieux. Ceci a été corrigé.

Blocs END et commutateur "-c"

Les versions antérieures exécutaient les blocs BEGIN et END lorsque Perl était exécuté en mode compilation seule. Comme ce n'est généralement pas le comportement attendu, les blocs END ne sont plus exécutés lorsque le commutateur "-c" est utilisé, ou si la compilation échoue.

Voir "Support pour les blocs CHECK" pour savoir comment exécuter des choses à la fin de la phase de compilation.

Potentiel de fuite des descripteurs de fichiers DATA

L'utilisation du jeton "__DATA__" crée un descripteur de fichier implicite vers le fichier qui contient le jeton. Il incombe au programme de le fermer lorsqu'il a fini de le lire.

Cette mise en garde est maintenant mieux expliquée dans la documentation. Voir perldata.

Diagnostics nouveaux ou modifiés

"%s" variable %s masque une déclaration précédente dans le même %s
(W misc) Une variable "my" ou "our" a été redéclarée dans la portée ou l'instruction actuelle, éliminant ainsi tout accès à l'instance précédente. C'est presque toujours une erreur typographique. Notez que la variable précédente existera toujours jusqu'à la fin de la portée ou jusqu'à ce que toutes les références de fermeture à celle-ci soient détruites.
"my sub" non encore implémenté
(F) Les sous-routines à portée lexicale ne sont pas encore implémentées. N'essayez pas cela pour l'instant.
"our" variable %s redéclarée
(W misc) Vous semblez avoir déjà déclaré le même global une fois auparavant dans la portée lexicale actuelle.
'!' autorisé seulement après les types %s
(F) Le '!' est autorisé dans pack() et unpack() seulement après certains types. Voir "pack" dans perlfunc.
/ ne peut pas prendre de compte
(F) Vous aviez un modèle de déballage indiquant une chaîne de longueur comptée, mais vous avez également spécifié une taille explicite pour la chaîne. Voir "pack" dans perlfunc.
/ doit être suivi de a, A ou Z
(F) Vous aviez un modèle de déballage indiquant une chaîne de longueur comptée, qui doit être suivie de l'une des lettres a, A ou Z pour indiquer quel type de chaîne doit être déballé. Voir "pack" dans perlfunc.
/ doit être suivi de a*, A* ou Z*
(F) Vous aviez un modèle d'emballage indiquant une chaîne de longueur comptée. Actuellement, les seules choses dont la longueur peut être comptée sont a*, A* ou Z*. Voir "pack" dans perlfunc.
/ doit suivre un type numérique
(F) Vous aviez un modèle de déballage qui contenait un '#', mais celui-ci ne suivait aucune spécification de déballage numérique. Voir "pack" dans perlfunc.
/%s/: Échappement non reconnu \\%c transmis
(W regexp) Vous avez utilisé une combinaison de barre oblique inverse-caractère non reconnue par Perl. Cette combinaison apparaît dans une variable interpolée ou une expression régulière délimitée par des apostrophes. Le caractère a été compris littéralement.
/%s/: Échappement non reconnu \\%c dans une classe de caractères transmis
(W regexp) Vous avez utilisé une combinaison antislash-caractère non reconnue par Perl à l'intérieur des classes de caractères. Le caractère a été compris littéralement.
/%s/ devrait probablement s'écrire "%s"
(W syntax) Vous avez utilisé un motif là où Perl attendait une chaîne, comme dans le premier argument de "join". Perl traitera le résultat vrai ou faux de la correspondance du motif contre $_ comme la chaîne, ce qui n'est probablement pas ce que vous aviez en tête.
%s() appelé trop tôt pour vérifier le prototype
(W prototype) Vous avez appelé une fonction qui a un prototype avant que l'analyseur n'en voie une définition ou une déclaration, et Perl n'a pas pu vérifier que l'appel est conforme au prototype. Vous devez soit ajouter une déclaration de prototype précoce pour la sous-routine en question, soit déplacer la définition de la sous-routine avant l'appel pour obtenir une vérification correcte du prototype. Alternativement, si vous êtes certain d'appeler la fonction correctement, vous pouvez placer une esperluette avant le nom pour éviter l'avertissement. Voir perlsub.
%s argument n'est pas un élément HASH ou ARRAY
(F) L'argument de exists() doit être un élément de hachage ou de tableau, tel que : 
$foo{$bar}
$ref->{"susie"}[12]
%s argument n'est pas un élément ou une tranche HASH ou ARRAY
(F) L'argument de delete() doit être un élément de hachage ou de tableau, tel que : 
$foo{$bar}
$ref->{"susie"}[12]

ou une tranche de hachage ou de tableau, telle que :

@foo[$bar, $baz, $xyzzy]
@{$ref->[12]}{"susie", "queue"}
%s argument n'est pas un nom de sous-routine
(F) L'argument de exists() pour "exists &sub" doit être un nom de sous-routine, et non un appel de sous-routine. "exists &sub()" générera cette erreur.
l'attribut de paquetage %s peut entrer en conflit avec un futur mot réservé : %s
(W reserved) Un nom d'attribut en minuscules a été utilisé avec un gestionnaire spécifique au paquetage. Ce nom pourrait avoir une signification pour Perl lui-même un jour, même si ce n'est pas encore le cas. Peut-être devriez-vous utiliser un nom d'attribut mixte à la place. Voir attributes.
(en nettoyage) %s
(W misc) Ce préfixe indique généralement qu'une méthode DESTROY() a levé l'exception indiquée. Les destructeurs étant généralement appelés par le système à des moments arbitraires pendant l'exécution, et souvent un grand nombre de fois, l'avertissement n'est émis qu'une seule fois pour un nombre quelconque d'échecs qui autrement résulteraient en la répétition du même message.

L'échec des rappels utilisateur distribués à l'aide de l'indicateur "G_KEEPERR" pourrait également entraîner cet avertissement. Voir "G_KEEPERR" dans perlcall.

<> devrait être des guillemets
(F) Vous avez écrit "require <file>" alors que vous auriez dû écrire "require 'file'".
Tentative de joindre soi-même
(F) Vous avez essayé de joindre un thread depuis l'intérieur de lui-même, ce qui est une tâche impossible. Vous joignez peut-être le mauvais thread, ou vous devrez peut-être déplacer le join() vers un autre thread.
Mauvais motif de substitution évalué (eval)
(F) Vous avez utilisé le commutateur /e pour évaluer le remplacement d'une substitution, mais perl a trouvé une erreur de syntaxe dans le code à évaluer, très probablement une accolade fermante inattendue '}'.
Mauvais realloc() ignoré
(S) Une routine interne a appelé realloc() sur quelque chose qui n'avait jamais été préalablement malloc()é. Obligatoire, mais peut être désactivé en définissant la variable d'environnement "PERL_BADFREE" à 1.
Mot nu trouvé dans une condition
(W bareword) Le compilateur a trouvé un mot nu là où il attendait une condition, ce qui indique souvent qu'un || ou && a été analysé comme faisant partie du dernier argument du construct précédent, par exemple : 
open FOO || die;

Cela peut également indiquer une constante mal orthographiée qui a été interprétée comme un mot nu :

use constant TYPO => 1;
if (TYOP) { print "foo" }

Le pragma "strict" est utile pour éviter de telles erreurs.

Nombre binaire > 0b11111111111111111111111111111111 non portable
(W portable) Le nombre binaire que vous avez spécifié est supérieur à 2**32-1 (4294967295) et donc non portable entre les systèmes. Voir perlport pour plus d'informations sur la portabilité.
Taille de vecteur de bits > 32 non portable
(W portable) L'utilisation de tailles de vecteurs de bits supérieures à 32 n'est pas portable.
Dépassement de tampon dans prime_env_iter : %s
(W internal) Un avertissement spécifique à VMS. Pendant que Perl préparait l'itération sur %ENV, il a rencontré un nom logique ou une définition de symbole trop long, il a donc été tronqué à la chaîne affichée.
Impossible de vérifier le système de fichiers du script "%s"
(P) Pour une raison quelconque, vous ne pouvez pas vérifier le système de fichiers du script pour nosuid.
Impossible de déclarer la classe pour un non-scalaire %s dans "%s"
(S) Actuellement, seules les variables scalaires peuvent être déclarées avec un qualificateur de classe spécifique dans une déclaration "my" ou "our". Les sémantiques peuvent être étendues à d'autres types de variables à l'avenir.
Impossible de déclarer %s dans "%s"
(F) Seules les variables scalaires, tableaux et hachages peuvent être déclarées comme variables "my" ou "our". Elles doivent avoir des identificateurs ordinaires comme noms.
Impossible d'ignorer le signal CHLD, force au défaut
(W signal) Perl a détecté qu'il était exécuté avec le signal SIGCHLD (parfois appelé SIGCLD) désactivé. Changements incompatibles

Incompatibilités de source Perl

Attention, tout nouvel avertissement ajouté ou ancien avertissement amélioré n'est **pas** considéré comme un changement incompatible.

Étant donné que tous les nouveaux avertissements doivent être explicitement demandés via le commutateur "-w" ou le pragma "warnings", il incombe en fin de compte au programmeur de s'assurer que les avertissements sont activés judicieusement.

CHECK est un nouveau mot-clé
Toutes les définitions de sous-routine nommées CHECK sont maintenant spéciales. Voir "/"Support for CHECK blocks"" pour plus d'informations.
Le traitement des tranches de liste de undef a changé
Il existe une incompatibilité potentielle dans le comportement des tranches de liste qui consistent entièrement en des valeurs indéfinies. Voir "Comportement des tranches de liste plus cohérent".
Le format de $English::PERL_VERSION est différent
Le module English définit maintenant $PERL_VERSION sur $^V (une valeur de chaîne) plutôt que sur $] (une valeur numérique). C'est une incompatibilité potentielle. Envoyez-nous un rapport via perlbug si vous êtes concerné.

Voir "Système de numérotation des versions Perl amélioré" pour les raisons de ce changement.

Les littéraux de la forme 1.2.3 sont analysés différemment
Auparavant, les littéraux numériques avec plus d'un point étaient interprétés comme un nombre à virgule flottante concaténé avec un ou plusieurs nombres. Ces "nombres" sont maintenant analysés comme des chaînes composées des ordinals spécifiés.

Par exemple, "print 97.98.99" affichait auparavant 97.9899 dans les versions antérieures, mais affiche maintenant "abc".

Voir "Support pour les chaînes représentées comme un vecteur d'ordinals".

Générateur de nombres pseudo-aléatoires potentiellement modifié
Les programmes Perl qui dépendent de la reproduction d'un ensemble spécifique de nombres pseudo-aléatoires peuvent maintenant produire des résultats différents en raison des améliorations apportées à la fonction intégrée rand(). Vous pouvez utiliser "sh Configure -Drandfunc=rand" pour obtenir le comportement précédent.

Voir "Meilleur générateur de nombres pseudo-aléatoires".

La fonction de hachage pour les clés de hachage a changé
Même si les hachages Perl ne conservent pas l'ordre, l'ordre apparemment aléatoire rencontré lors de l'itération sur le contenu d'un hachage est en fait déterminé par l'algorithme de hachage utilisé. Les améliorations de l'algorithme peuvent produire un ordre aléatoire différent de celui des versions précédentes, surtout lors de l'itération
sur les hachages.

Voir « Meilleur comportement dans le pire des cas des hachages » pour plus d'informations.

« undef » échoue sur les valeurs en lecture seule
Utiliser l'opérateur « undef » sur une valeur en lecture seule (telle que $1) a le même effet que d'affecter « undef » à la valeur en lecture seule : cela déclenche une exception.
Le bit de fermeture à l'exécution peut être défini sur les descripteurs de tube et de socket
Les descripteurs de tube et de socket sont également soumis au comportement de fermeture à l'exécution déterminé par la variable spéciale $^F.

Voir « Comportement plus cohérent de fermeture à l'exécution ».

L'écriture de « $$1 » pour signifier « ${$}1 » n'est pas prise en charge
Perl 5.004 a déprécié l'interprétation de $$1 et similaires dans les chaînes interpolées pour signifier « $$ . « 1 » », mais l'a toujours permis.

Dans Perl 5.6.0 et versions ultérieures, « $$1 » signifie toujours « ${$1} ».

delete(), each(), values() et « \%h »
opèrent sur des alias de valeurs, pas des copies

delete(), each(), values() et les hachages (par exemple, « \%h ») dans un contexte de liste retournent les valeurs réelles du hachage, au lieu de copies (comme c'était le cas dans les versions antérieures). Les idiomes typiques pour utiliser ces constructions copient les valeurs retournées, mais cela peut faire une différence significative lors de la création de références aux valeurs retournées. Les clés du hachage sont toujours retournées comme des copies lors de l'itération sur un hachage.

Voir aussi « delete(), each(), values() et l'itération de hachage sont plus rapides ».

vec(EXPR,OFFSET,BITS) impose des BITS puissances de deux
vec() génère une erreur d'exécution si l'argument BITS n'est pas un entier puissance de deux valide.
Le texte de certains diagnostics a changé
La plupart des références aux opérations internes de Perl dans les diagnostics ont été modifiées pour être plus descriptives. Cela peut poser problème aux programmes qui s'appuient incorrectement sur le texte exact des diagnostics pour leur bon fonctionnement.
« %@ » a été supprimé
La variable spéciale non documentée « %@ » qui accumulait auparavant les erreurs « d'arrière-plan » (comme celles qui se produisent dans DESTROY()) a été supprimée, car elle pouvait potentiellement entraîner des fuites de mémoire.
Le not() entre parenthèses se comporte comme un opérateur de liste
L'opérateur « not » tombe désormais sous la règle « s'il ressemble à une fonction, il se comporte comme une fonction ».

En conséquence, la forme entre parenthèses peut être utilisée avec « grep » et « map ». La construction suivante était auparavant une erreur de syntaxe, mais elle fonctionne maintenant comme prévu :

grep not($_), @things;

D'un autre côté, l'utilisation de « not » avec une tranche de liste littérale peut ne pas fonctionner. La construction précédemment autorisée :

print not (1,2,3)[0];

doit maintenant être écrite avec des parenthèses supplémentaires :

print not((1,2,3)[0]);

Le comportement reste inchangé lorsque « not » n'est pas suivi de parenthèses.

La sémantique du prototype de mot vide « (*) » a changé
La sémantique du prototype de mot vide « * » a changé. Perl 5.005 coercissait toujours les arguments scalaires simples en une globe de type, ce qui n'était pas utile dans les situations où la sous-routine doit distinguer un scalaire simple d'une globe de type. Le nouveau comportement est de ne pas coercer les arguments de mot vide en une globe de type. La valeur sera toujours visible soit comme un scalaire simple, soit comme une référence à une globe de type.

Voir « Prototype de mot vide plus fonctionnel (*) ».

La sémantique des opérateurs bit à bit peut avoir changé sur les plateformes 64 bits
Si votre plateforme est nativement 64 bits ou si Perl a été configuré pour utiliser des entiers 64 bits, c'est-à-dire si $Config{ivsize} vaut 8, il peut y avoir une incompatibilité potentielle dans le comportement des opérateurs numériques bit à bit (& | ^ ~ << >>). Ces opérateurs opéraient auparavant strictement sur les 32 bits inférieurs des entiers dans les versions précédentes, mais opèrent maintenant sur toute la largeur entière native. En particulier, notez que « ~ » unaire produira des résultats différents sur les plateformes qui ont un $Config{ivsize} différent. Pour la portabilité, assurez-vous de masquer les bits excédentaires dans le résultat de « ~ » unaire, par exemple, « ~$x & 0xffffffff ».

Voir « Les opérateurs bit à bit prennent en charge la largeur entière native complète ».

Plus de fonctions intégrées marquent leurs résultats
Comme décrit dans « Amélioration des fonctionnalités de sécurité », il peut y avoir plus de sources de marquage dans un programme Perl.

Pour éviter ces nouveaux comportements de marquage, vous pouvez compiler Perl avec l'option de configuration « -Accflags=-DINCOMPLETE_TAINTS ». Attention, le binaire perl résultant peut être dangereux.

C Incompatibilités de source

« PERL_POLLUTE »
La version 5.005 a rétroactivement autorisé les anciens noms de symboles globaux en fournissant des macros de préprocesseur pour la compatibilité des sources d'extension. Depuis la version 5.6.0, ces définitions de préprocesseur ne sont pas disponibles par défaut. Vous devez compiler explicitement Perl avec « -DPERL_POLLUTE » pour obtenir ces définitions. Pour les extensions utilisant toujours les anciens symboles, cette option peut être spécifiée via MakeMaker : 
perl Makefile.PL POLLUTE=1
« PERL_IMPLICIT_CONTEXT »
Cette nouvelle option de compilation fournit un ensemble de macros pour toutes les fonctions de l'API de sorte qu'un argument de contexte d'interpréteur/thread implicite soit passé à chaque fonction de l'API. En conséquence, quelque chose comme « sv_setsv(foo,bar) » équivaut à un appel de macro qui se traduit en fait par quelque chose comme « Perl_sv_setsv(my_perl,foo,bar) ». Bien que l'on s'attende généralement à ce que cela n'ait pas d'impact significatif sur la compatibilité des sources, la différence entre une macro et un véritable appel de fonction devra être prise en compte.

Cela signifie qu'il **y a** un problème de compatibilité de source en raison de cela si vos extensions tentent d'utiliser des pointeurs vers n'importe laquelle des fonctions de l'API Perl.

Notez que le problème ci-dessus n'est pas pertinent pour la compilation par défaut de Perl, dont les interfaces continuent de correspondre à celles des versions précédentes (mais sous réserve des autres options décrites ici).

Voir « Contexte et PERL_IMPLICIT_CONTEXT » dans perlguts pour des informations détaillées sur les ramifications de la compilation de Perl avec cette option. 

NOTE : PERL_IMPLICIT_CONTEXT est automatiquement activé lorsque Perl est compilé avec l'une des options -Dusethreads, -Dusemultiplicity, ou les deux. Il n'est pas destiné à être activé par les utilisateurs pour le moment.
« PERL_POLLUTE_MALLOC »
L'activation du malloc de Perl dans la version 5.005 et antérieures entraînait l'usurpation de l'espace de noms des fonctions de la famille malloc du système par les versions Perl, car par défaut elles utilisaient les mêmes noms. En plus de causer des problèmes sur les plateformes qui ne permettent pas de remplacer proprement ces fonctions, cela signifiait également que les versions système ne pouvaient pas être appelées dans les programmes qui utilisaient le malloc de Perl. Les versions précédentes de Perl ont permis de supprimer ce comportement avec les définitions de préprocesseur HIDEMYMALLOC et EMBEDMYMALLOC.

Depuis la version 5.6.0, les fonctions de la famille malloc de Perl ont des noms par défaut distincts de ceux des versions système. Vous devez compiler explicitement Perl avec « -DPERL_POLLUTE_MALLOC » pour obtenir le comportement précédent. HIDEMYMALLOC et EMBEDMYMALLOC n'ont aucun effet, car le comportement qu'ils permettaient est maintenant le comportement par défaut.

Notez que ces fonctions ne constituent **pas** l'API d'allocation mémoire de Perl. Voir « Allocation mémoire » dans perlguts pour plus d'informations à ce sujet.

Compatible Changements dans l'API source C

« PATCHLEVEL » est maintenant « PERL_VERSION »
Les macros cpp « PERL_REVISION », « PERL_VERSION », et « PERL_SUBVERSION » sont maintenant disponibles par défaut à partir de perl.h, et reflètent la révision de base, le niveau de correctif et la sous-version respectivement. « PERL_REVISION » n'avait pas d'équivalent préalable, tandis que « PERL_VERSION » et « PERL_SUBVERSION » étaient précédemment disponibles sous les noms « PATCHLEVEL » et « SUBVERSION ».

Les nouveaux noms polluent moins l'espace de noms cpp et reflètent ce que les nombres sont censés représenter dans la pratique courante. Pour la compatibilité, les anciens noms sont toujours pris en charge lorsque patchlevel.h est explicitement inclus (comme requis auparavant), il n'y a donc aucune incompatibilité de source due au changement.

Incompatibilités binaires

En général, la compilation par défaut de cette version devrait être binaire compatible pour les extensions compilées avec la version 5.005 ou ses versions de maintenance. Cependant, des plateformes spécifiques peuvent avoir rompu la compatibilité binaire en raison de changements dans les valeurs par défaut utilisées dans les fichiers d'indices. Par conséquent, assurez-vous de toujours vérifier les fichiers README spécifiques à la plateforme pour toute note contraire.

Les compilations usethreads ou usemultiplicity ne sont **pas** binaires compatibles avec les compilations correspondantes de 5.005.

Sur les plateformes qui nécessitent une liste explicite d'exportations (AIX, OS/2 et Windows, entre autres), les symboles purement internes tels que

FONCTIONS ET OPÉRATEURS

Les fonctions d'analyse et les opcodes d'exécution ne sont pas exportés par défaut. Perl 5.005 exportait toutes les fonctions, qu'elles soient considérées comme faisant partie de l'API publique ou non.

Pour la liste complète des fonctions de l'API publique, voir perlapi.

Problèmes Connus

La localisation d'un élément de hachage lié peut provoquer une fuite de mémoire

Depuis la version 5.6.1, il existe une fuite connue lorsque du code comme celui-ci est exécuté :

use Tie::Hash;
tie my %tie_hash => 'Tie::StdHash';
...
local($tie_hash{Foo}) = 1; # fuite

Échecs de tests connus

  • Constructions 64 bits

    Le sous-test n° 15 de lib/b.t peut échouer dans les constructions 64 bits sur des plates-formes telles que HP-UX PA64 et Linux IA64. Le problème est toujours à l'étude.

    Le test lib/io_multihomed peut se bloquer sous HP-UX si Perl a été configuré en 64 bits. Étant donné que d'autres plates-formes 64 bits ne se bloquent pas dans ce test, HP-UX est suspect. Tous les autres tests réussissent en 64 bits HP-UX. Le test tente de créer et de se connecter à des sockets « multihommed » (sockets ayant plusieurs adresses IP).

    Notez que le support 64 bits est toujours expérimental.

  • Échec des tests de thread

    Les sous-tests 19 et 20 de lib/thr5005.t sont connus pour échouer en raison de problèmes fondamentaux dans l'implémentation des threads 5.005. Ce ne sont pas de nouveaux échecs – Perl 5.005_0x a les mêmes bugs, mais n'avait pas ces tests. (Notez que le support des threads de type 5.005 reste expérimental.)

  • Échec du test POSIX sur NEXTSTEP 3.3

    Dans NEXTSTEP 3.3p2, l'implémentation de strftime(3) dans les bibliothèques du système d'exploitation est buggée : le format %j numérote les jours d'un mois à partir de zéro, ce qui, bien qu'étant logique pour les programmeurs, provoquera l'échec des sous-tests 19 à 27 du test lib/posix.

  • Échec du test lib/sdbm sous Tru64 (anciennement Digital UNIX, anciennement DEC OSF/1) avec gcc

    Si compilé avec gcc 2.95, le test lib/sdbm échouera (dump de cœur). Le remède est d'utiliser le compilateur spécifique au fournisseur, qui est livré avec le système d'exploitation et produit du bon code.

Les plates-formes EBCDIC ne sont pas entièrement prises en charge

Dans les versions antérieures de Perl, les environnements EBCDIC comme OS390 (également connu sous le nom d'Open Edition MVS) et VM-ESA étaient pris en charge. En raison des changements requis pour le support de UTF-8 (Unicode), les plates-formes EBCDIC ne sont pas prises en charge dans Perl 5.6.0.

La version 5.6.1 améliore le support des plates-formes EBCDIC, mais elles ne sont pas encore entièrement prises en charge.

Échecs de CC UNICOS/mk lors de l'exécution de Configure

Dans UNICOS/mk, les erreurs suivantes peuvent apparaître lors de l'exécution de Configure :

Guessing which symbols your C compiler and preprocessor define...
CC-20 cc: ERROR File = try.c, Line = 3
...
  bad switch yylook 79bad switch yylook 79bad switch yylook 79bad switch yylook 79#ifdef A29K
...
4 errors detected in the compilation of "try.c".

Le coupable est l'awk défectueux d'UNICOS/mk. L'effet est heureusement assez léger : Perl lui-même n'est pas affecté négativement par l'erreur, seule l'utilitaire h2ph livré avec Perl l'est, et celui-ci est rarement nécessaire de nos jours.

Opérateur flèche et tableaux

Lorsque l'opérande gauche de l'opérateur flèche "->" est un tableau, ou l'opérateur "scalar" opérant sur un tableau, le résultat de l'opération doit être considéré comme erroné. Par exemple :

@x->[2]
scalar(@x)->[2]

Ces expressions provoqueront des erreurs d'exécution dans une future version de Perl.

Diagnostics Obsolètes

La syntaxe des classes de caractères [: :] est réservée pour les extensions futures
(W) Dans les classes de caractères d'expressions régulières ([]) , la syntaxe commençant par « [: » et se terminant par « :] » est réservée aux extensions futures. Si vous devez représenter ces séquences de caractères à l'intérieur d'une classe de caractères d'expressions régulières, citez simplement les crochets avec une barre oblique inverse : « \[ : » et « :\] ».
Nom logique mal formé |%s| dans prime_env_iter
(W) Un avertissement propre à VMS. Un nom logique a été rencontré lors de la préparation d'une itération sur %ENV qui viole les règles syntaxiques régissant les noms logiques. Comme il ne peut pas être traduit normalement, il est ignoré et n'apparaîtra pas dans %ENV. Cela peut être une occurrence bénigne, car certains progiciels peuvent modifier directement les tables de noms logiques et introduire des noms non standard, ou cela peut indiquer qu'une table de noms logiques a été corrompue.
Dans la chaîne, @%s doit maintenant être écrit comme \@%s
La description de cette erreur disait autrefois : 
(Someday it will simply assume that an unbackslashed @
 interpolates an array.)

Ce jour est arrivé, et cette erreur fatale a été supprimée. Elle a été remplacée par un avertissement non fatal. Voir « Arrays now always interpolate into double-quoted strings » pour plus de détails.

Problème de précédence probable sur %s
(W) Le compilateur a trouvé un bareword là où il attendait une conditionnelle, ce qui indique souvent qu'un || ou && a été analysé comme faisant partie du dernier argument du construct précédent, par exemple : 
open FOO || die;
regexp trop grand
(F) L'implémentation actuelle des expressions régulières utilise des shorts comme décalages d'adresse au sein d'une chaîne. Malheureusement, cela signifie que si l'expression régulière compile à plus de 32767, elle explosera. Habituellement, lorsque vous voulez une expression régulière aussi grande, il existe une meilleure façon de le faire avec plusieurs instructions. Voir perlre.
L'utilisation de « $$<digit> » pour signifier « ${$}<digit> » est dépréciée
(D) Les versions de Perl antérieures à 5.004 interprétaient mal tout marqueur de type suivi de « $& » et d'un chiffre. Par exemple, « $$0 » était incorrectement interprété comme « ${$}0 » au lieu de « ${$0} ». Ce bug est (en grande partie) corrigé dans Perl 5.004.

Cependant, les développeurs de Perl 5.004 n'ont pas pu corriger complètement ce bug, car au moins deux modules largement utilisés dépendent de l'ancienne signification de « $$0 » dans une chaîne. Ainsi, Perl 5.004 interprète toujours « $$<digit> » de l'ancienne manière (défectueuse) dans les chaînes ; mais il génère ce message comme un avertissement. Et dans Perl 5.005, ce traitement spécial cessera.
