PERFEVENT.CONF(5) Manuel des formats de fichiers PERFEVENT.CONF(5)

NOM

perfevent.conf - fichier de configuration du PMDA perfevent de Performance Co-Pilot

SYNTAXE

$PCP_PMDAS_DIR/perfevent/perfevent.conf

DESCRIPTION

Le fichier de configuration perfevent.conf définit quels compteurs de performance matériels sont activés par le PMDA perfevent.

Le fichier de configuration contient une liste d'événements qui doivent être activés pour chaque PMU. Le PMDA perfevent détecte les PMU présentes et programme les événements configurés. Si plusieurs PMU sont disponibles, le PMDA perfevent utilise l'ordre des entrées dans le fichier de configuration pour déterminer les paramètres de PMU à utiliser. Les entrées en haut du fichier de configuration ont une priorité plus élevée. Un seul réglage de configuration de PMU est utilisé. Le fichier de configuration peut également contenir des événements dérivés de perf. Un événement dérivé a une liste d'événements qui doivent être répertoriés comme événements de base. Les valeurs des compteurs dans les événements dérivés sont agrégées et affichées.

FORMAT DU FICHIER

Le fichier se compose d'un ou plusieurs groupes de PMU et des événements qui leur correspondent.

La chaîne d'identification de la PMU est entourée d'accolades et un ou plusieurs événements sont listés ci-dessous, un par ligne.

["Chaîne d'identification de la PMU"]
NOM_EVENEMENT [CPU OPTION]
...

Pour les événements dérivés, un ou plusieurs groupes d'événements peuvent être spécifiés où les compteurs d'un groupe peuvent être spécifiques à une architecture et les compteurs d'un autre groupe peuvent être spécifiques à une autre architecture. Sinon, un seul groupe peut être spécifié. NOM_EVENEMENT_1, NOM_EVENEMENT_2, etc. appartiennent au groupe 1 et NOM_EVENEMENT_3, NOM_EVENEMENT_4 appartiennent au groupe 2, et ainsi de suite. Si l'un des événements du premier groupe n'est pas disponible, le groupe entier sera rejeté. Et le groupe suivant sera vérifié. Le premier groupe dont tous les événements sont disponibles sera activé et surveillé. L'événement perf dérivé est entouré d'accolades avec :derived comme suffixe. Notez que le NOM_EVENEMENT répertorié sous l'événement dérivé doit être présent comme événement de base dans le fichier de configuration. Et tous les événements d'un groupe d'événements perf dérivés particulier doivent avoir la même CPU_OPTION. || agit comme séparateur pour différents groupes à l'intérieur d'un seul événement dérivé. La syntaxe est :

[event:derived]
NOM_EVENEMENT_1 [CPU_OPTION] [scale]
NOM_EVENEMENT_2 [CPU_OPTION] [scale]
...
||
NOM_EVENEMENT_3 [CPU_OPTION] [scale]
NOM_EVENEMENT_4 [CPU_OPTION] [scale]
...

Les options de CPU d'événement disponibles sont les suivantes :

cpu
pour ajouter le compteur à tous les cpus du système
cpu_rr
pour ajouter à l'un des cpus selon une stratégie d'allocation en round-robin
node
pour ajouter le compteur au premier cpu de chaque nœud numa
node_rr
pour ajouter le compteur aux cpus de chaque nœud numa selon une stratégie d'allocation en round-robin
[N]
où N est le chiffre numérique de l'index du CPU

si l'option CPU est absente, l'événement est programmé sur tous les cpus.

scale est applicable aux compteurs dans les événements dérivés. Si scale est donné, les compteurs seront mis à l'échelle à leurs valeurs respectives. Les options sont les suivantes :

une valeur flottante
Peut être une simple valeur flottante ou une valeur en notation scientifique.
perf_scale
L'échelle sera prise à partir du fichier d'échelle sysfs du noyau pour cet événement. Elle est généralement spécifiée dans /sys/bus/event_source/device/events/<event_name>.scale

Si aucune échelle n'est donnée, l'échelle par défaut sera de 1.0.

Les lignes vides sont ignorées. Les lignes commençant par le signe # sont ignorées.

Plusieurs PMU, séparées par des virgules, peuvent être spécifiées dans la définition de la PMU.
