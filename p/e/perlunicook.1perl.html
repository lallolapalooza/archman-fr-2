PERLUNICOOK(1perl) Guide de référence du programmeur Perl PERLUNICOOK(1perl)

NOM

perlunicook — exemples de type « cookbook » pour la manipulation de l'Unicode en Perl

DESCRIPTION

Cette page de manuel contient de courtes recettes démontrant comment gérer les opérations courantes sur l'Unicode en Perl, plus un programme complet à la fin. Toute variable non déclarée dans les recettes individuelles est supposée contenir une valeur appropriée précédente.

EXEMPLES

℞ 0: Préambule standard

Sauf indication contraire, tous les exemples ci-dessous nécessitent ce préambule standard pour fonctionner correctement, avec le "#!" ajusté pour fonctionner sur votre système :

#!/usr/bin/env perl
use v5.36;     # ou plus récent pour obtenir la fonctionnalité "unicode_strings",
               #   plus strict, warnings
use utf8;      # pour que les littéraux et identifiants puissent être en UTF-8
use warnings  qw(FATAL utf8);    # fataliser les erreurs d'encodage
use open      qw(:std :encoding(UTF-8)); # flux non déclarés en UTF-8
use charnames qw(:full :short);  # non requis en v5.16

Cela rend même les programmeurs Unix sur "binmode" vos flux binaires, ou les ouvre avec ":raw", mais c'est de toute façon la seule façon de les atteindre de manière portable.

AVERTISSEMENT : "use autodie" (avant 2.26) et "use open" ne s'entendent pas bien.

℞ 1: Filtre générique sensible à l'Unicode

Toujours décomposer en entrée, puis recomposer en sortie.

use Unicode::Normalize;
while (<>) {
    $_ = NFD($_);   # décomposer + réordonner canoniquement
    ...
} continue {
    print NFC($_);  # recomposer (lorsque possible) + réordonner canoniquement
}

℞ 2: Ajustement fin des avertissements Unicode

À partir de la v5.14, Perl distingue trois sous-classes d'avertissements UTF-8.

use v5.14;                  # sous-avertissements indisponibles avant
no warnings "nonchar";      # les 66 non-caractères interdits
no warnings "surrogate";    # bêtises UTF-16/CESU-8
no warnings "non_unicode";  # pour les points de code supérieurs à 0x10_FFFF

℞ 3: Déclarer la source en utf8 pour les identifiants et les littéraux

Sans la déclaration "use utf8", cruciale, mettre de l'UTF-8 dans vos littéraux et identifiants ne fonctionnera pas correctement. Si vous avez utilisé le préambule standard donné ci-dessus, cela s'est déjà produit. Si c'est le cas, vous pouvez faire des choses comme ceci :

use utf8;
my $measure   = "Ångström";
my @μsoft     = qw( cp852 cp1251 cp1252 );
my @ὑπέρμεγας = qw( ὑπέρ  μεγας );
my @鯉        = qw( koi8-f koi8-u koi8-r );
my $motto     = "👪 💗 🐪"; # FAMILLE, CŒUR GRANDISSANT, CAMEL DROMADAIRE

Si vous oubliez "use utf8", les octets supérieurs seront mal interprétés comme des caractères séparés, et rien ne fonctionnera correctement.

℞ 4: Caractères et leurs nombres

Les fonctions "ord" et "chr" fonctionnent de manière transparente sur tous les points de code, pas seulement sur l'ASCII seul — ni même, en fait, pas seulement sur l'Unicode seul.

# Caractères ASCII
ord("A")
chr(65)
# caractères du plan multilingue de base
ord("Σ")
chr(0x3A3)
# au-delà du BMP
ord("𝑛")               # LETTRE PETITE N MATHÉMATIQUE ITALIQUE
chr(0x1D45B)
# au-delà de l'Unicode ! (jusqu'à MAXINT)
ord("\x{20_0000}")
chr(0x20_0000)

℞ 5: Littéraux Unicode par numéro de caractère

Dans un littéral interpolé, qu'il s'agisse d'une chaîne entre guillemets doubles ou d'une expression régulière, vous pouvez spécifier un caractère par son numéro en utilisant l'échappement "\x{HHHHHH}".

Chaîne : "\x{3a3}"
Regex :  /\x{3a3}/
Chaîne : "\x{1d45b}"
Regex :  /\x{1d45b}/
# même les plages non-BMP dans les regex fonctionnent bien
/[\x{1D434}-\x{1D467}]/

℞ 6: Obtenir le nom du caractère par son numéro

use charnames ();
my $name = charnames::viacode(0x03A3);

℞ 7: Obtenir le numéro du caractère par son nom

use charnames ();
my $number = charnames::vianame("GREEK CAPITAL LETTER SIGMA");

℞ 8: Caractères nommés Unicode

Utilisez la notation "\N{nomcaractère}" pour obtenir le caractère par ce nom pour l'utiliser dans des littéraux interpolés (chaînes entre guillemets doubles et expressions régulières). En v5.16, il y a un implicite

use charnames qw(:full :short);

Mais avant la v5.16, vous devez être explicite quant à l'ensemble des noms de caractères que vous souhaitez. Les noms ":full" sont le nom officiel du caractère Unicode, l'alias ou la séquence, qui partagent tous un espace de noms.

use charnames qw(:full :short latin greek);
"\N{MATHEMATICAL ITALIC SMALL N}"      # :full
"\N{GREEK CAPITAL LETTER SIGMA}"       # :full

Tout le reste est une abréviation de commodité spécifique à Perl. Spécifiez un ou plusieurs scripts par leurs noms si vous voulez des noms courts spécifiques au script.

"\N{Greek:Sigma}"                      # :short
"\N{ae}"                               #  latin
"\N{epsilon}"                          #  greek

La version v5.16 prend également en charge une importation ":loose" pour une correspondance flexible des noms de caractères, qui fonctionne comme la correspondance flexible des noms de propriétés : c'est-à-dire qu'elle ignore la casse, les espaces et les soulignements :

"\N{euro sign}"                        # :loose (depuis v5.16)

À partir de la v5.32, vous pouvez également utiliser

qr/\p{name=euro sign}/

pour obtenir les caractères nommés officiels de l'Unicode dans les expressions régulières. La correspondance flexible est toujours effectuée pour ceux-ci.

℞ 9: Séquences nommées Unicode

Celles-ci ressemblent à des noms de caractères mais renvoient plusieurs points de code. Remarquez la fonctionnalité d'impression vectorielle %vx dans "printf".

use charnames qw(:full);
my $seq = "\N{LATIN CAPITAL LETTER A WITH MACRON AND GRAVE}";
printf "U+%v04X\n", $seq;
U+0100.0300

℞ 10: Caractères nommés personnalisés

Utilisez ":alias" pour donner vos propres surnoms lexicalement délimités à des caractères existants, ou même pour donner des noms utiles à des caractères privés non nommés.

use charnames ":full", ":alias" => {
    ecute => "LATIN SMALL LETTER E WITH ACUTE",
    "APPLE LOGO" => 0xF8FF, # caractère d'usage privé
};
"\N{ecute}"
"\N{APPLE LOGO}"

℞ 11: Noms des points de code CJK

Les sinogrammes comme « 東京 » reviennent avec les noms de caractères "CJK UNIFIED IDEOGRAPH-6771" et "CJK UNIFIED IDEOGRAPH-4EAC", car leurs « noms » varient. Le module CPAN "Unicode::Unihan" contient une grande base de données pour décoder ceux-ci (et bien plus encore), à condition de savoir interpréter sa sortie.

# cpan -i Unicode::Unihan
use Unicode::Unihan;
my $str = "東京";
my $unhan = Unicode::Unihan->new;
for my $lang (qw(Mandarin Cantonese Korean JapaneseOn JapaneseKun)) {
    printf "CJK $str en %-12s est ", $lang;
    say $unhan->$lang($str);
}

imprime :

CJK 東京 en Mandarin     est DONG1JING1
CJK 東京 en Cantonese    est dung1ging1
CJK 東京 en Korean       est TONGKYENG
CJK 東京 en JapaneseOn   est TOUKYOU KEI KIN
CJK 東京 en JapaneseKun  est HIGASHI AZUMAMIYAKO

Si vous avez un schéma de romanisation spécifique en tête, utilisez le module spécifique :

# cpan -i Lingua::JA::Romanize::Japanese
use Lingua::JA::Romanize::Japanese;
my $k2r = Lingua::JA::Romanize::Japanese->new;
my $str = "東京";
say "Japonais pour $str est ", $k2r->chars($str);

imprime

Japonais pour 東京 est toukyou

℞ 12: Encodage/Décodage explicite

Dans de rares occasions, comme lors de la lecture d'une base de données, il se peut que l'on vous fournisse du texte encodé que vous devez décoder.

 use Encode qw(encode decode);
 my $chars = decode("shiftjis&qu
ot;", $octets, 1); # OU my $octets = encode("MIME-Header-ISO_2022_JP", $caracteres, 1);

Pour les flux qui sont tous dans le même encodage, n'utilisez pas encode/decode ; définissez plutôt l'encodage du fichier lorsque vous ouvrez le fichier ou immédiatement après avec "binmode" comme décrit plus loin.

℞ 13: Décoder les arguments du programme en utf8

    $ perl -CA ...
ou
    $ export PERL_UNICODE=A
ou
   use Encode qw(decode);
   @ARGV = map { decode('UTF-8', $_, 1) } @ARGV;

℞ 14: Décoder les arguments du programme en encodage local

# cpan -i Encode::Locale
use Encode qw(locale);
use Encode::Locale;
# utiliser "locale" comme argument pour encode/decode
@ARGV = map { decode(locale => $_, 1) } @ARGV;

℞ 15: Déclarer STD{IN,OUT,ERR} comme utf8

Utilisez une option de ligne de commande, une variable d'environnement, ou sinon appelez "binmode" explicitement :

    $ perl -CS ...
ou
    $ export PERL_UNICODE=S
ou
    use open qw(:std :encoding(UTF-8));
ou
    binmode(STDIN,  ":encoding(UTF-8)");
    binmode(STDOUT, ":utf8");
    binmode(STDERR, ":utf8");

℞ 16: Déclarer STD{IN,OUT,ERR} en encodage local

# cpan -i Encode::Locale
use Encode;
use Encode::Locale;
# ou comme un flux pour binmode ou open
binmode STDIN,  ":encoding(console_in)"  if -t STDIN;
binmode STDOUT, ":encoding(console_out)" if -t STDOUT;
binmode STDERR, ":encoding(console_out)" if -t STDERR;

℞ 17: Faire en sorte que les E/S de fichier soient par défaut en utf8

Les fichiers ouverts sans argument d'encodage seront en UTF-8 :

    $ perl -CD ...
ou
    $ export PERL_UNICODE=D
ou
    use open qw(:encoding(UTF-8));

℞ 18: Faire en sorte que toutes les E/S et arguments soient par défaut en utf8

    $ perl -CSDA ...
ou
    $ export PERL_UNICODE=SDA
ou
    use open qw(:std :encoding(UTF-8));
    use Encode qw(decode);
    @ARGV = map { decode('UTF-8', $_, 1) } @ARGV;

℞ 19: Ouvrir un fichier avec un encodage spécifique

Spécifier l'encodage du flux. C'est la manière normale de traiter du texte encodé, pas en appelant des fonctions de bas niveau.

# fichier d'entrée
    open(my $in_file, "< :encoding(UTF-16)", "wintext");
OU
    open(my $in_file, "<", "wintext");
    binmode($in_file, ":encoding(UTF-16)");
PUIS
    my $line = <$in_file>;
# fichier de sortie
    open($out_file, "> :encoding(cp1252)", "wintext");
OU
    open(my $out_file, ">", "wintext");
    binmode($out_file, ":encoding(cp1252)");
PUIS
    print $out_file "quelque texte\n";

Plusieurs couches que le simple encodage peuvent être spécifiées ici. Par exemple, l'incantation ":raw :encoding(UTF-16LE) :crlf" inclut la gestion implicite de CRLF.

℞ 20: Casse Unicode

La casse Unicode est très différente de la casse ASCII.

uc("henry ⅷ")  # "HENRY Ⅷ"
uc("tschüß")   # "TSCHÜSS"  notez ß => SS
# les deux sont vrais :
"tschüß"  =~ /TSCHÜSS/i   # notez ß => SS
"Σίσυφος" =~ /ΣΊΣΥΦΟΣ/i   # notez la similitude de Σ,σ,ς

℞ 21: Comparaisons Unicode insensibles à la casse

Également disponible dans le module CPAN Unicode::CaseFold, la nouvelle fonction "fc" "foldcase" (pliage de casse) à partir de la v5.16 donne accès au même pliage de casse Unicode que le modificateur de motif "/i" a toujours utilisé :

use feature "fc"; # la fonction fc() est à partir de la v5.16
# trier insensiblement à la casse
my @sorted = sort { fc($a) cmp fc($b) } @list;
# les deux sont vrais :
fc("tschüß")  eq fc("TSCHÜSS")
fc("Σίσυφος") eq fc("ΣΊΣΥΦΟΣ")

℞ 22: Faire correspondre une séquence de fin de ligne Unicode dans une regex

Une fin de ligne Unicode correspond à la séquence CRLF de deux caractères ou à l'un des sept caractères d'espacement vertical. Utile pour traiter des fichiers texte provenant de différents systèmes d'exploitation.

\R
s/\R/\n/g;  # normaliser toutes les fins de ligne en \n

℞ 23: Obtenir la catégorie de caractère

Trouver la catégorie générale d'un point de code numérique.

use Unicode::UCD qw(charinfo);
my $cat = charinfo(0x3A3)->{category};  # "Lu"

℞ 24: Désactiver la prise en compte de Unicode dans les classes de caractères intégrées

Désactiver le bon fonctionnement de "\w", "\b", "\s", "\d", et des classes POSIX sur Unicode soit dans ce scope, soit dans une seule regex.

use v5.14;
use re "/a";
# OU
my($num) = $str =~ /(\d+)/a;

Ou utiliser des propriétés non-Unicode spécifiques, comme "\p{ahex}" et "\p{POSIX_Digit}". Les propriétés fonctionnent toujours normalement, quels que soient les modificateurs de jeu de caractères ("/d /u /l /a /aa") en vigueur.

℞ 25: Faire correspondre les propriétés Unicode dans une regex avec \p, \P

Celles-ci correspondent toutes à un seul point de code avec la propriété donnée. Utilisez "\P" à la place de "\p" pour correspondre à un point de code qui n'a pas cette propriété.

\pL, \pN, \pS, \pP, \pM, \pZ, \pC
\p{Sk}, \p{Ps}, \p{Lt}
\p{alpha}, \p{upper}, \p{lower}
\p{Latin}, \p{Greek}
\p{script_extensions=Latin}, \p{scx=Greek}
\p{East_Asian_Width=Wide}, \p{EA=W}
\p{Line_Break=Hyphen}, \p{LB=HY}
\p{Numeric_Value=4}, \p{NV=4}

℞ 26: Propriétés de caractères personnalisées

Définir à la compilation vos propres propriétés de caractères personnalisées à utiliser dans les regex.

# utiliser des caractères d'usage privé
sub In_Tengwar { "E000\tE07F\n" }
if (/\p{In_Tengwar}/) { ... }
# mélanger des propriétés existantes
sub Is_GraecoRoman_Title {<<'END_OF_SET'}
+utf8::IsLatin
+utf8::IsGreek
&utf8::IsTitle
END_OF_SET
if (/\p{Is_GraecoRoman_Title}/) { ... }

℞ 27: Normalisation Unicode

Généralement, rendre en NFD à l'entrée et en NFC à la sortie. L'utilisation des fonctions NFKC ou NFKD améliore la recherche (rappel), en supposant que vous avez déjà fait la même chose pour le texte à rechercher. Notez que cela concerne bien plus que de simples glyphes pré-combinés ; cela réordonne également les marques selon leurs classes de combinaison canoniques et élimine les singletons.

use Unicode::Normalize;
my $nfd  = NFD($orig);
my $nfc  = NFC($orig);
my $nfkd = NFKD($orig);
my $nfkc = NFKC($orig);

℞ 28: Convertir les nombres Unicode non-ASCII

À moins que vous n'ayez utilisé "/a" ou , "\d" correspond à plus que les chiffres ASCII seulement, mais la conversion implicite chaîne-à-nombre de Perl ne les reconnaît pas actuellement. Voici comment convertir manuellement de telles chaînes.

use utf8;
use v5.14;  # nécessaire pour la fonction num()
use Unicode::UCD qw(num);
my $str = "got Ⅻ and ४५६७ and ⅞ and 兆 here";
my @nums = ();
while ($str =~ /(\d+|\N)/g) {  # pas seulement ASCII !
   push @nums, num($1);
}
say "@nums";   # 12 4567 0.875 1000000000000
use charnames qw(:full);
my $nv = num("\N{VAI DIGIT ONE}\N{VAI DIGIT TWO}");
say $nv;  # 12

℞ 29: Faire correspondre un cluster de graphèmes Unicode dans une regex

Les "caractères" visibles par le programmeur sont des points de code correspondants à "/./s", mais les "caractères" visibles par l'utilisateur sont des graphèmes correspondants à "/\X/".

# Trouver une voyelle *plus* tous les diacritiques de combinaison, soulignement, etc.
my $nfd = NFD($orig);
$nfd =~ / (?=[aeiou]) \X /xi

℞ 30: Extraire par graphème au lieu de par point de code (regex)

# faire correspondre et extraire les cinq premiers graphèmes
my($first_five) = $str =~ /^ ( \X{5} ) /x;

℞ 31: Extraire par graphème au lieu de par point de code (substr)

# cpan -i Unicode::GCString
use Unicode::GCString;
my $gcs = Unicode::GCString->new($str);
my $first_five = $gcs->substr(0, 5);

℞ 32: Inverser une chaîne par graphème

Inverser par point de code perturbe les diacritiques, convertissant par erreur "crème brûlée" en "éel̂urb em̀erc" au lieu de "eélûrb emèrc" ; donc inverser par graphème à la place. Les deux approches fonctionnent correctement quelle que soit la normalisation de la chaîne :

$str = join("", reverse $str =~ /\X/g);
# OU : cpan -i Unicode::GCString
use Unicode::GCString;
$str = reverse Unicode::GCString->new($str);

℞ 33: Longueur de chaîne en graphèmes

La chaîne "brûlée" a six graphèmes mais jusqu'à huit points de code. Ceci compte par graphème, pas par point de code :

my $str = "brûlée";
my $count = 0;
while ($str =~ /\X/g) { $count++ }
 # OU : cpan -i Unicode::GCString
use Unicode::GCString;
my $gcs = Unicode::GCString->new($str);
my $count = $gcs->length;

℞ 34: Largeur de colonne Unicode pour l'impression

Les fonctions "printf", "sprintf" et "format" de Perl pensent que tous les points de code prennent 1 colonne d'impression, mais beaucoup en prennent 0 ou 2. Ici, pour montrer que la normalisation n'a aucune différence, nous imprimons les deux formes :

use Unicode::GCString;
use Unicode::Normalize;
my @words = qw/crème brûlée/;
@words = map { NFC($_), NFD($_) } @words;
for my $str (@words) {
    my $gcs = Unicode::GCString->new($str);
    my $cols = $gcs->columns;
    my $pad = " " x (10 - $cols);
    say $str, $pad, " |";
}

génère ceci pour montrer qu'il remplit correctement quel que soit la normalisation :

crème      |
crème      |
brûlée     |
brûlée     |

℞ 35: Tri Unicode

Le texte trié par point de code numérique ne suit aucune logique raisonnable.

DESCRIPTION

Cette section concerne la manipulation du texte Unicode, notamment le tri alphabétique, la gestion des majuscules et des accents, le découpage en lignes, et le stockage dans des bases de données DBM.

℞ 35: Tri alphabétique Unicode

Utilisez l'algorithme de collation Unicode (UCA) pour trier du texte.

use Unicode::Collate;
my $col = Unicode::Collate->new();
my @list = $col->sort(@old_list);

Consultez le programme ucsort du module CPAN Unicode::Tussle pour une interface en ligne de commande pratique de ce module.

℞ 36: Tri Unicode insensible à la casse et aux accents

Spécifiez une force de collation de niveau 1 pour ignorer la casse et les diacritiques, en ne considérant que le caractère de base.

use Unicode::Collate;
my $col = Unicode::Collate->new(level => 1);
my @list = $col->sort(@old_list);

℞ 37: Collation locale Unicode

Certaines locales ont des règles de tri spéciales.

# utilisez v5.12, OU : cpan -i Unicode::Collate::Locale
use Unicode::Collate::Locale;
my $col = Unicode::Collate::Locale->new(locale => "de__phonebook");
my @list = $col->sort(@old_list);

Le programme ucsort mentionné ci-dessus accepte un paramètre "--locale".

℞ 38: Faire fonctionner "cmp" sur du texte au lieu de points de code

Au lieu de ceci :

@srecs = sort {
    $b->{AGE}   <=>  $a->{AGE}
                ||
    $a->{NAME}  cmp  $b->{NAME}
} @recs;

Utilisez ceci :

my $coll = Unicode::Collate->new();
for my $rec (@recs) {
    $rec->{NAME_key} = $coll->getSortKey( $rec->{NAME} );
}
@srecs = sort {
    $b->{AGE}       <=>  $a->{AGE}
                    ||
    $a->{NAME_key}  cmp  $b->{NAME_key}
} @recs;

℞ 39: Comparaisons insensibles à la casse et aux accents

Utilisez un objet collator pour comparer du texte Unicode par caractère plutôt que par point de code.

use Unicode::Collate;
my $es = Unicode::Collate->new(
    level => 1,
    normalization => undef
);
 # maintenant les deux sont vrais :
$es->eq("García",  "GARCIA" );
$es->eq("Márquez", "MARQUEZ");

℞ 40: Comparaisons locales insensibles à la casse et aux accents

Identique, mais dans une locale spécifique.

my $de = Unicode::Collate::Locale->new(
           locale => "de__phonebook",
         );
# maintenant ceci est vrai :
$de->eq("tschüß", "TSCHUESS");  # remarquez ü => UE, ß => SS

℞ 41: Saut de ligne Unicode

Divisez le texte en lignes selon les règles Unicode.

# cpan -i Unicode::LineBreak
use Unicode::LineBreak;
use charnames qw(:full);
my $para = "This is a super\N{HYPHEN}long string. " x 20;
my $fmt = Unicode::LineBreak->new;
print $fmt->break($para), "\n";

℞ 42: Texte Unicode dans les hachages DBM, de manière laborieuse

L'utilisation d'une chaîne Perl ordinaire comme clé ou valeur pour un hachage DBM déclenchera une exception de caractère large si des points de code ne peuvent pas être convertis en octets. Voici comment gérer manuellement la traduction :

   use DB_File;
   use Encode qw(encode decode);
   tie %dbhash, "DB_File", "pathname";
# STOCKAGE
   # supposons que $uni_key et $uni_value soient des chaînes Unicode abstraites
   my $enc_key   = encode("UTF-8", $uni_key, 1);
   my $enc_value = encode("UTF-8", $uni_value, 1);
   $dbhash{$enc_key} = $enc_value;
# RÉCUPÉRATION
   # supposons que $uni_key contienne une chaîne Perl normale (Unicode abstraite)
   my $enc_key   = encode("UTF-8", $uni_key, 1);
   my $enc_value = $dbhash{$enc_key};
   my $uni_value = decode("UTF-8", $enc_value, 1);

℞ 43: Texte Unicode dans les hachages DBM, facilement

Voici comment gérer implicitement la traduction ; tout l'encodage et le décodage sont effectués automatiquement, comme avec des flux auxquels une encodage particulier est attaché :

   use DB_File;
   use DBM_Filter;
   my $dbobj = tie %dbhash, "DB_File", "pathname";
   $dbobj->Filter_Value("utf8");  # c'est le point magique
# STOCKAGE
   # supposons que $uni_key et $uni_value soient des chaînes Unicode abstraites
   $dbhash{$uni_key} = $uni_value;
 # RÉCUPÉRATION
   # $uni_key contient une chaîne Perl normale (Unicode abstraite)
   my $uni_value = $dbhash{$uni_key};

#!/usr/bin/env perl
# umenu - démo de tri et d'impression de nourriture Unicode
#
# (préambule obligatoire et de plus en plus long)
#
use v5.36;
use utf8;
use warnings  qw(FATAL utf8);    # fataliser les erreurs d'encodage
use open      qw(:std :encoding(UTF-8)); # flux non déclarés en UTF-8
use charnames qw(:full :short);  # non requis en v5.16
# modules standard
use Unicode::Normalize;          # distribution perl standard dès v5.8
use List::Util qw(max);          # distribution perl standard dès v5.10
use Unicode::Collate::Locale;    # distribution perl standard dès v5.14
# modules cpan
use Unicode::GCString;           # de CPAN
my %price = (
    "γύρος"             => 6.50, # gyros
    "pears"             => 2.00, # comme um, poires
    "linguiça"          => 7.00, # saucisse épicée, portugais
    "xoriço"            => 3.00, # saucisse chorizo, catalan
    "hamburger"         => 6.00, # burgermeister meisterburger
    "éclair"            => 1.60, # dessert, français
    "smørbrød"          => 5.75, # sandwichs, norvégien
    "spätzle"           => 5.50, # nouilles bavaroises, petits moineaux
    "包子"              => 7.50, # bao1 zi5, brioches à la vapeur au porc, mandarin
    "jamón serrano"     => 4.45, # jambon de pays, espagnol
    "pêches"            => 2.25, # pêches, français
    "シュークリーム"    => 1.85, # pâtisserie garnie de crème comme un éclair
    "막걸리"            => 4.00, # makgeolli, vin de riz coréen
    "寿司"              => 9.99, # sushi, japonais
    "おもち"            => 2.65, # omochi, gâteaux de riz, japonais
    "crème brûlée"      => 2.00, # crème catalane
    "fideuà"            => 4.20, # plus de nouilles, valencien
                                 # (catalan=fideuada)
    "pâté"              => 4.15, # pâté de foie gras, français
    "お好み焼き"        => 8.00, # okonomiyaki, japonais
);
my $width = 5 + max map { colwidth($_) } keys %price;
# Ainsi les éléments asiatiques sortent dans un ordre qui ne fera pas
# hurler quelqu'un qui lit ces écritures ; les éléments CJK seront en ordre
# JIS X 0208 ainsi.
my $coll  = Unicode::Collate::Locale->new(locale => "ja");
for my $item ($coll->sort(keys %price)) {
    print pad(entitle($item), $width, ".");
    printf " €%.2f\n", $price{$item};
}
sub pad ($str, $width, $padchar) {
    return $str . ($padchar x ($width - colwidth($str)));
}
sub colwidth ($str) {
    return Unicode::GCString->new($str)->columns;
}
sub entitle ($str) {
    $str =~ s{ (?=\pL)(\S)     (\S*) }
             { ucfirst($1) . lc($2)  }xge;
    return $str;
}
