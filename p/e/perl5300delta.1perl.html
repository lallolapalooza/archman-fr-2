PERL5300DELTA(1perl) Guide de référence du programmeur Perl PERL5300DELTA(1perl)

NOM

perl5300delta - nouveautés de la version perl v5.30.0

DESCRIPTION

Ce document décrit les différences entre la version 5.28.0 et la version 5.30.0.

Si vous mettez à jour à partir d'une version antérieure telle que la 5.26.0, lisez d'abord perl5280delta, qui décrit les différences entre les versions 5.26.0 et 5.28.0.

Remarque

sv_utf8_(downgrade|decode) ne sont plus marqués comme expérimentaux. [GH #16822] https://github.com/Perl/perl5/issues/16822.

Améliorations du noyau

La recherche en arrière à longueur variable limitée dans la correspondance de motifs d'expressions régulières est désormais prise en charge expérimentalement

L'utilisation d'une assertion de recherche en arrière (comme "(?<=foo?)" ou "(?<!ba{1,9}r)" générait auparavant une erreur et refusait la compilation. Désormais, elle compile (si la recherche en arrière maximale ne dépasse pas 255 caractères), mais déclenche un avertissement dans la nouvelle catégorie d'avertissements "experimental::vlb". Ceci vise à vous avertir que le comportement précis est susceptible d'être modifié en fonction des retours d'expérience sur le terrain.

Voir "(?<=pattern)" dans perlre et "(?<!pattern)" dans perlre.

La limite supérieure "n" spécifiable dans un quantificateur d'expression régulière de la forme "{m,n}" a été doublée à 65534

Le sens d'un quantificateur supérieur illimité "{m,}" reste inchangé. Il correspond à 231 - 1 fois sur la plupart des plateformes, et plus sur celles où une variable courte du langage C fait plus de 4 octets.

Unicode 12.1 est pris en charge

En raison d'un changement dans les cycles de publication d'Unicode, Perl passe d'Unicode 10.0 dans Perl 5.28 à Unicode 12.1 dans Perl 5.30.

Pour plus de détails sur les changements Unicode, voir https://www.unicode.org/versions/Unicode11.0.0/ pour 11.0 ; https://www.unicode.org/versions/Unicode12.0.0/ pour 12.0 ; et https://www.unicode.org/versions/Unicode12.1.0/ pour 12.1. (Unicode 12.1 diffère de 12.0 uniquement par l'ajout d'un seul caractère, celui du nouveau nom d'ère japonais.)

La propriété Word_Break, comme dans les versions précédentes de Perl, reste adaptée pour se comporter davantage en accord avec les attentes des utilisateurs de Perl. Cela signifie que les séquences de caractères d'espacement horizontal ne sont pas séparées, mais conservées comme une seule séquence. Unicode 11 a changé par rapport aux versions précédentes pour s'aligner davantage sur Perl, mais il a laissé plusieurs caractères d'espacement comme provoquant des sauts : TAB, NO BREAK SPACE et FIGURE SPACE (U+2007). Nous avons décidé de continuer à utiliser l'adaptation Perl précédente à cet égard.

Les caractères de remplacement dans les spécifications de valeurs de propriétés Unicode sont désormais partiellement pris en charge

Vous pouvez désormais faire quelque chose comme ceci dans un motif d'expression régulière

qr! \p{nv= /(?x) \A [0-5] \z / }!

ce qui correspond à tous les points de code Unicode dont la valeur numérique est comprise entre 0 et 5 inclus. Ainsi, cela pourrait correspondre aux chiffres thaïlandais ou bengali dont les valeurs numériques sont 0, 1, 2, 3, 4 ou 5.

Ceci marque une autre étape dans la mise en œuvre des fonctionnalités d'expressions régulières suggérées par le Consortium Unicode.

La plupart des propriétés sont prises en charge, les autres étant prévues pour la version 5.32. Les détails se trouvent dans "Wildcards in Property Values" dans perlunicode.

qr'\N{nom}' est désormais pris en charge

Auparavant, évaluer un caractère nommé "\N{...}" dans un motif d'expression régulière entre apostrophes (dont l'évaluation est différée du lieu normal) était une erreur. Cette restriction est maintenant levée.

Les codes locaux turcs UTF-8 sont désormais parfaitement pris en charge

Les langues turques ont des règles de mise en majuscules différentes des autres langues pour les caractères "i" et "I". La majuscule de "i" est LETTRE MAJUSCULE LATINE I AVEC POINT AU-DESSUS (U+0130) ; et la minuscule de "I" est LETTRE LATINE PETITE I SANS POINT (U+0131). Unicode fournit des règles de mise en majuscules alternatives pour une utilisation avec les langues turques. Auparavant, Perl les ignorait, mais maintenant, il les utilise lorsqu'il détecte qu'il fonctionne sous un code local turc UTF-8.

Il est désormais possible de compiler perl pour utiliser toujours des opérations locales thread-safe

Auparavant, ces appels n'étaient utilisés que lorsque perl était compilé pour être multi-threadé. Pour les activer toujours, ajoutez

-Accflags='-DUSE_THREAD_SAFE_LOCALE'

à vos options Configure.

Suppression de l'utilisation de la macro opASSIGN du noyau

Cette macro est toujours définie mais n'est plus utilisée dans le noyau.

"-Drv" a désormais un sens sur les builds "-DDEBUGGING"

Désormais, ajouter l'option verbeuse ("-Dv") à l'option "-Dr" active toutes les options de débogage d'expressions régulières possibles.

Changements incompatibles

L'affectation d'une valeur non nulle à $[ est fatale

Définir $[ à une valeur non nulle était déprécié depuis Perl 5.12 et lance désormais une erreur fatale. Voir "Assigning non-zero to $[ is fatal" dans perldeprecation.

Les délimiteurs doivent désormais être des graphemes

Voir "Use of unassigned code point or non-standalone grapheme for a delimiter." dans perldeprecation

Certaines utilisations précédemment dépréciées d'une accolade gauche non échappée "{" dans les motifs d'expressions régulières sont désormais illégales

Mais pour éviter de casser inutilement du code, la plupart des instances qui généraient un avertissement de dépréciation restent légales et ont désormais un avertissement non lié à la dépréciation. Voir "Unescaped left braces in regular expressions" dans perldeprecation.

Les appels précédemment dépréciés à sysread()/syswrite() sur les handles :utf8 sont désormais fatals

Voir "I/O on filehandles marked with :utf8 flag" dans perldelta pour plus de détails.

Corrections de bogues

La compilation des caractères Unicode spécifiés par nom, ou par valeur hexadécimale, n'est plus une erreur si le nom n'existe pas ou si la valeur est hors limites.

Auparavant, un motif tel que qr/\N{NonExistent}/ ou qr/\x{110000}/ (ce dernier étant hors de la plage valide de 000000-10FFFF) provoquerait une erreur de compilation. Maintenant, cela génère un avertissement et correspond à la chaîne vide.

Si l'on veut que cela soit une erreur fatale, il faut utiliser le pragme strict.

La communauté Arch Linux

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

ly sysread()/syswrite() sur des descripteurs :utf8 est maintenant fatal

L'appel de sysread(), syswrite(), send() ou recv() sur un descripteur ":utf8", qu'il soit appliqué explicitement ou implicitement, est maintenant fatal. Ceci était déprécié dans perl 5.24.

Il y avait deux problèmes lors de l'appel de ces fonctions sur des descripteurs ":utf8" :

  • Les quatre fonctions ne prêtaient attention qu'au drapeau ":utf8". Les autres couches étaient complètement ignorées, donc un descripteur avec une couche :encoding(UTF-16LE) serait traité comme UTF-8. D'autres couches, comme la compression, étaient complètement ignorées, avec ou sans le drapeau ":utf8".
  • sysread() et recv() liraient depuis le descripteur, en ignorant toute validation par les couches, et ne feraient aucune validation propre. Cela pouvait conduire à des scalaires Perl encodés de manière invalide.

[GH #14839] https://github.com/Perl/perl5/issues/14839.

my() dans un conditionnel faux interdit

Les déclarations telles que "my $x if 0" ne sont plus autorisées.

[GH #16702] https://github.com/Perl/perl5/issues/16702.

Fataliser $* et $#

Ces variables spéciales, longtemps dépréciées, lèvent maintenant des exceptions lorsqu'elles sont utilisées.

[GH #16718] https://github.com/Perl/perl5/issues/16718.

Fataliser l'utilisation non qualifiée de dump()

La fonction dump(), longtemps déconseillée, ne peut plus être utilisée à moins d'être entièrement qualifiée, c'est-à-dire CORE::dump().

[GH #16719] https://github.com/Perl/perl5/issues/16719.

Supprimer File::Glob::glob()

La fonction File::Glob::glob(), longtemps dépréciée, a été supprimée et lève maintenant une exception qui conseille d'utiliser File::Glob::bsd_glob() à la place.

[GH #16721] https://github.com/Perl/perl5/issues/16721.

pack() ne peut plus retourner de UTF-8 malformé

Il plante si cela devait retourner une chaîne UTF-8 contenant du UTF-8 malformé. Ceci protège contre d'éventuelles menaces de sécurité. Ceci est également considéré comme une correction de bug. [GH #16035] https://github.com/Perl/perl5/issues/16035.

Tout ensemble de chiffres dans le script Commun est légal dans une exécution de script d'un autre script

Il existe plusieurs ensembles de chiffres dans le script Commun. "[0-9]" est le plus familier. Mais il y a aussi "[\x{FF10}-\x{FF19}]" (ZERO chiffre pleine chasse - NEUF chiffre pleine chasse), et plusieurs ensembles à utiliser dans la notation mathématique, tels que les chiffres à double trait mathématique. Chacun de ces ensembles devrait pouvoir apparaître dans des exécutions de script, par exemple, du grec. Mais la conception de 5.30 a négligé tous les chiffres sauf les chiffres ASCII "[0-9]", donc la conception était défectueuse. Ceci a été corrigé, il s'agit donc à la fois d'une correction de bug et d'une incompatibilité. [GH #16704] https://github.com/Perl/perl5/issues/16704.

Tous les chiffres d'une exécution doivent toujours provenir du même ensemble de dix chiffres.

JSON::PP active allow_nonref par défaut

Comme JSON::XS 4.0 a changé sa politique et a activé allow_nonref par défaut, JSON::PP a également activé allow_nonref par défaut.

Améliorations des performances

  • La traduction de UTF-8 vers le point de code qu'il représente est maintenant réalisée via un automate fini déterministe, ce qui l'accélère. À titre d'exemple typique, ord("\x7fff") nécessite maintenant 12% d'instructions en moins qu'auparavant. Les performances de vérification qu'une séquence d'octets est un UTF-8 valide sont également améliorées, toujours à l'aide d'un automate fini déterministe.
  • Suppression de la récursion de finalize_op(). [GH #11866] https://github.com/Perl/perl5/issues/11866.
  • Une poignée de petites optimisations liées au pliage de caractères et aux classes de caractères dans les expressions régulières.
  • Optimisation des conversions "IV" vers "UV". [GH #16761] https://github.com/Perl/perl5/issues/16761.
  • Accélération de l'algorithme de stringification d'entiers en traitant deux chiffres à la fois au lieu d'un seul. [GH #16769] https://github.com/Perl/perl5/issues/16769.
  • Améliorations basées sur l'analyse et les recommandations de LGTM. (https://lgtm.com/projects/g/Perl/perl5/alerts/?mode=tree). [GH #16765] https://github.com/Perl/perl5/issues/16765. [GH #16773] https://github.com/Perl/perl5/issues/16773.
  • Optimisations de code dans regcomp.c, regcomp.h, regexec.c.
  • La correspondance de motifs d'expressions régulières de choses comme "qr/[^a]/" est significativement accélérée, où a est un caractère ASCII quelconque. D'autres classes peuvent bénéficier de cette accélération, mais lesquelles est compliqué et dépend des motifs de bits sous-jacents de ces caractères, donc cela diffère entre les plateformes ASCII et EBCDIC, mais toutes les paires de cas, comme "qr/[Gg]/" sont incluses, tout comme "[^01]".

Modules et Pragmata Supprimés

Les modules suivants seront supprimés de la distribution principale dans une prochaine version, et devront alors être installés à partir de CPAN. Les distributions sur CPAN qui nécessitent ces modules devront les répertorier comme prérequis.

Les versions principales de ces modules émettront désormais des avertissements de catégorie "déprécié" pour vous en informer. Pour faire taire ces avertissements de dépréciation, installez les modules en question à partir de CPAN.

Notez qu'il s'agit (sauf rares exceptions) d'excellents modules dont l'utilisation est encouragée. Leur exclusion du cœur dépend principalement de leur nécessité pour l'amorçage d'une installation Perl entièrement fonctionnelle et compatible avec CPAN, et non généralement de préoccupations concernant leur conception.

  • arybase a été supprimé. Il fournissait auparavant l'implémentation de la variable $[ (également connue sous le nom de fonctionnalité "array_base"), permettant aux indices de tableaux et de chaînes de commencer à une valeur non nulle. Comme la fonctionnalité a été supprimée (voir « L'assignation d'une valeur non nulle à $[ est fatale »), ce module interne a également disparu.
  • B::Debug n'est plus distribué avec la distribution principale. Il continue d'être disponible sur CPAN sous le nom "B::Debug https://metacpan.org/pod/B::Debug".
  • Locale::Codes a été supprimé à la demande de son auteur. Il continue d'être disponible sur CPAN sous le nom "Locale::Codes https://metacpan.org/pod/Locale::Codes" [GH #16660] https://github.com/Perl/perl5/issues/16660.

Diagnostics

Les ajouts ou modifications suivants ont été apportés aux sorties diagnostiques, y compris les avertissements et les messages d'erreur fatals. Pour la liste complète des messages diagnostiques, voir perldiag.

Modifications apportées aux Diagnostics Existants

  • Comme noté sous « Changements incompatibles » ci-dessus, l'avertissement de dépréciation « Unescaped left brace in regex is deprecated here (and will be fatal in Perl 5.30), passed through in regex; marked by <-- HERE in m/%s/ » a été modifié en l'avertissement non déprécié « Unescaped left brace in regex is passed through in regex; marked by <-- HERE in m/%s/ ».
  • Spécifier "\o{}" sans rien entre les accolades génère désormais le message d'erreur fatal « Empty \o{} ». Auparavant, c'était « Number with no digits ». Cela signifie que la même formulation est utilisée pour ce type d'erreur que pour des constructions similaires telles que "\p{}".
  • Dans le cadre de la fonctionnalité expérimentale "use re 'strict'", spécifier "\x{}" sans rien entre les accolades génère désormais une erreur fatale « Empty \x{} ».

Changements liés à la régularité

  • Le message d'erreur fatal pour les chaînes vides dans les expressions régulières est maintenant "Vide \x{}". Auparavant, c'était "Nombre sans chiffres". Cela signifie que la même formulation est utilisée pour ce type d'erreur que pour des constructions similaires telles que "\p{}". Il est légal, bien que peu sage, d'avoir un "\x" vide en dehors de "re 'strict'" ; cela génère silencieusement un caractère NUL.
  • Le type de l'argument %d à %s doit être %s (et non %s)

    Les tentatives de pousser, dépiler, etc. sur une table de hachage ou un glob produisent désormais ce message plutôt que de se plaindre qu'ils ne fonctionnent plus sur les scalaires. [GH #15774] https://github.com/Perl/perl5/issues/15774.

  • Prototype non terminé

    Le fichier et le numéro de ligne sont désormais signalés pour cette erreur. [GH #16697] https://github.com/Perl/perl5/issues/16697

  • Sous "-Dr" (ou "use re 'Debug'"), le programme du moteur d'expressions régulières compilé est affiché. Il utilisait auparavant deux orthographes différentes pour l' *infini*, "INFINITY" et "INFTY". Il utilise désormais exclusivement cette dernière, car cette orthographe existe depuis le plus longtemps.

Support de Plateforme

Notes spécifiques à la plateforme

HP-UX 11.11
Un problème obscur dans pack() lors de la compilation avec HP C-ANSI-C a été résolu en désactivant les optimisations dans *pp_pack.c*.
Mac OS X
Le processus de construction et de test de Perl sur Mac OS X pour les builds "-Duseshrplib" est désormais compatible avec la protection de l'intégrité du système (SIP) de Mac OS X.

SIP empêche que les binaires dans */bin* (et quelques autres endroits) ne reçoivent la variable d'environnement "DYLD_LIBRARY_PATH". Pour nos besoins, cela empêche "DYLD_LIBRARY_PATH" d'être transmis au shell, ce qui empêche cette variable d'être transmise au processus de test ou de build, de sorte que l'exécution de "perl" ne pouvait pas trouver *libperl.dylib*.

Pour contourner ce problème, la première construction de l'exécutable *perl* attend de trouver *libperl.dylib* dans le répertoire de construction, et le chemin de la bibliothèque est ensuite ajusté lors de l'installation pour pointer vers la bibliothèque installée.

[GH #15057] https://github.com/Perl/perl5/issues/15057.

Minix3
Un certain support pour Minix3 a été réintégré.
Cygwin
Cygwin ne rend pas "cuserid" visible.
Win32 Mingw
Les fonctions mathématiques C99 sont désormais disponibles.
Windows
  • L'option de build "USE_CPLUSPLUS" qui est disponible depuis longtemps dans *win32/Makefile* (pour nmake) et *win32/makefile.mk* (pour dmake) est désormais également disponible dans *win32/GNUmakefile* (pour gmake).
  • Le makefile nmake ne privilégie plus Visual C++ 6.0 (une version très ancienne qui est peu susceptible d'être largement utilisée aujourd'hui). Par conséquent, il est désormais nécessaire de spécifier "CCTYPE" car il n'y a pas de choix évident de la version moderne à privilégier. Le non-respect de la spécification de "CCTYPE" entraînera l'affichage d'une erreur et l'arrêt de la compilation.

    (Les makefiles dmake et gmake détecteront automatiquement le compilateur utilisé, ils n'ont donc pas besoin que "CCTYPE" soit défini. Cette fonctionnalité n'a pas encore été ajoutée au makefile nmake.)

  • sleep() avec les avertissements activés pour une compilation "USE_IMP_SYS" ne signale plus que le délai d'attente du sommeil est trop long. [GH #16631] https://github.com/Perl/perl5/issues/16631.
  • La prise en charge de la compilation de perl sous Windows à l'aide de Microsoft Visual Studio 2019 (contenant Visual C++ 14.2) a été ajoutée.
  • socket() définit maintenant $! si la combinaison protocole, famille d'adresses et type de socket n'est pas trouvée. [GH #16849] https://github.com/Perl/perl5/issues/16849.
  • La construction du SDK de plateforme Windows Server 2003 SP1, avec son compilateur et ses outils x64 précoces, a été accidentellement cassée dans Perl 5.27.9. Cela a maintenant été corrigé.

Changements internes

  • La passe de dimensionnement a été supprimée du compilateur d'expressions régulières. Une passe supplémentaire peut être nécessaire dans certains cas pour compter le nombre de groupes de capture parenthésés.
  • Une nouvelle fonction ""my_strtod"" dans perlapi ou son synonyme, Strtod(), est maintenant disponible avec la même signature que le strtod() de libc. Elle fournit un comportement équivalent à strotod() sur toutes les plateformes, en utilisant la meilleure précision disponible, en fonction des capacités de la plateforme et des options de *Configure*, tout en gérant les problèmes liés à la locale, comme si le séparateur décimal devait être un point ou une virgule.
  • Ajout de newSVsv_nomg() pour copier un SV sans traiter le magie GET sur la source. [GH #16461] https://github.com/Perl/perl5/issues/16461.
  • Il est désormais interdit d'allouer plus de "PTRDIFF_MAX" octets. De nombreux codes (y compris les optimiseurs C) supposent que toutes les structures de données ne dépasseront pas cette taille, cela permet donc de détecter ces tentatives avant qu'un dépassement ne se produise.
  • Deux nouveaux regnodes ont été introduits : "EXACT_ONLY8" et "EXACTFU_ONLY8". Ils sont équivalents à "EXACT" et "EXACTFU", sauf qu'ils contiennent un point de code qui nécessite l'UTF-8 pour être représenté/correspondre. Par conséquent, si la chaîne cible n'est pas en UTF-8, nous savons qu'elle ne peut pas correspondre, sans avoir à essayer.
  • print_bytes_for_locale() est maintenant défini si "DEBUGGING" est défini. Auparavant, il n'était pas défini à moins que "LC_COLLATE" ne soit défini sur la plateforme.

Corrections de bogues sélectionnées

  • La compilation sous "-DPERL_MEM_LOG" et "-DNO_LOCALE" a été corrigée.
  • Perl 5.28 a introduit une optimisation de index() lors de la comparaison à -1 (ou indirectement, par exemple >= 0). Lorsque cette optimisation était déclenchée à l'intérieur d'une clause "when", elle provoquait un avertissement ("Argument %s n'est pas numérique dans le smart match"). Cela a maintenant été corrigé. [GH #16626] https://github.com/Perl/perl5/issues/16626
  • Le nouveau code d'édition en place ne fuit plus les descripteurs de répertoire. [GH #16602] https://github.com/Perl/perl5/issues/16602.
  • Les avertissements produits par des opérations de pliage de constantes sur des valeurs surchargées ne produisent plus d'avertissements parasites "Utilisation d'une valeur non initialisée". [GH #16349] https://github.com/Perl/perl5/issues/16349.
  • Correction pour « mutator non vu dans (lex = ...) .= ... » [GH #16655] https://github.com/Perl/perl5/issues/16655.
  • "pack "u", "invalid uuencoding"" termine maintenant correctement par NUL le SV de longueur zéro produit. [GH #16343] https://github.com/Perl/perl5/issues/16343.
  • Amélioration de la sortie de débogage pour les appels calloc() avec "-Dm". [GH #16653] https://github.com/Perl/perl5/issues/16653.
  • Les exécutions de scripts d'expressions régulières ne permettaient plus les chiffres ASCII dans certains cas. [GH #16704] https://github.com/Perl/perl5/issues/16704.
  • Sur les systèmes de type Unix prenant en charge une technique spécifique à la plateforme pour déterminer $^X, Perl ne revenait pas à la technique générique lorsque celle spécifique à la plateforme échouait (par exemple, un système Linux avec /proc non monté). Il s'agissait d'une régression dans Perl 5.28.0. [GH #16715] https://github.com/Perl/perl5/issues/16715.
  • SDBM_File est maintenant plus robuste avec les fichiers de base de données corrompus. Les améliorations ne rendent pas les fichiers SDBM adaptés en tant que format d'échange. [GH #16164] https://github.com/Perl/perl5/issues/16164.
  • "binmode($fh);" ou "binmode($fh, ':raw');" suppriment maintenant correctement le drapeau ":utf8" de la couche d'E/S par défaut ":crlf" sous Win32. [GH #16730] https://github.com/Perl/perl5/issues/16730.
  • La fonctionnalité expérimentale d'alias de référence interprétait mal l'assignation de tranches de tableaux et de hachages comme étant localisée, par exemple 
    \(@a[3,5,7]) = \(....);

    était interprété comme :

    local \(@a[3,5,7]) = \(....);

    [GH #16701] https://github.com/Perl/perl5/issues/16701.

  • "sort SUBNAME" dans un "eval EXPR" lorsque "EXPR" était mis à niveau en UTF-8 pouvait faire paniquer si "SUBNAME" n'était pas en ASCII. [GH #16979] https://github.com/Perl/perl5/issues/16979.
  • Gère correctement realloc() modifiant "errno" en cas de succès, de sorte que la modification ne soit pas visible pour l'utilisateur perl, puisque realloc() est appelé implicitement par l'interpréteur. Cette modification est autorisée par la norme C, mais n'a été observée que sur FreeBSD 13.0-CURRENT. [GH #16907] https://github.com/Perl/perl5/issues/16907.
  • Perl expose maintenant "getcwd" POSIX comme Internals::getcwd() si disponible. Ceci est destiné à être utilisé par "Cwd.pm" pendant l'amorçage et peut être supprimé ou modifié sans préavis. Cela corrige certains problèmes d'amorçage lors de la construction de perl dans un répertoire où un répertoire parent n'est pas accessible en lecture. [GH #16903] https://github.com/Perl/perl5/issues/16903.
  • pack() ne peut plus renvoyer de UTF-8 malformé. Il plante s'il devait autrement renvoyer une chaîne UTF-8 contenant du UTF-8 malformé. Cela protège contre d'éventuelles menaces de sécurité. [GH #16035] https://github.com/Perl/perl5/issues/16035.
  • Voir « Tout ensemble de chiffres dans le script Commun est légal dans un script d'un autre script ».
  • La correspondance d'expressions régulières ne laisse plus de magie de longueur UTF-8 obsolète lors de la mise à jour de $^R. Cela pouvait entraîner une valeur incorrecte pour length($^R).
  • Réduction de la récursion sur les ops [GH #11866] https://github.com/Perl/perl5/issues/11866.

    Cela peut éviter un débordement de pile lors du traitement d'arbres d'opérations extrêmement profonds.

  • Éviter les fuites dans la multiconcaténation avec surcharge. [GH #16823] https://github.com/Perl/perl5/issues/16823.
  • La gestion des propriétés "\p{}" définies par l'utilisateur (voir « Propriétés de caractères définies par l'utilisateur » dans perlunicode) a été réécrite en C (au lieu de Perl). Cela accélère les choses, mais au cours de ce processus, plusieurs incohérences et corrections de bugs sont apportées.
1.
Quelques messages d'erreur ont des changements mineurs de formulation. Ceci est essentiellement dû au fait que la nouvelle méthode est intégrée au mécanisme de gestion des erreurs d'expressions régulières qui marque la position dans l'entrée à laquelle l'erreur s'est produite. Cela n'était pas possible auparavant. Les messages contiennent maintenant des informations supplémentaires de type « back-trace » si l'erreur se produit en profondeur dans des appels imbriqués.
2.
Une propriété définie par l'utilisateur est implémentée comme une sous-routine Perl avec certaines conventions de nommage très contraignantes. Il était auparavant documenté que la sous-routine se trouverait dans le paquetage courant si le paquetage n'était pas spécifié. Il s'est avéré que ce n'était pas vrai dans tous les cas, mais c'est maintenant le cas.
3.
Tous les appels récursifs sont traités comme une récursion infinie. Auparavant, ils faisaient paniquer l'interpréteur. Maintenant, ils font échouer la compilation du motif d'expression régulière.
4.
De même, toute autre erreur susceptible d'entraîner une panique ; maintenant juste l'échec de la compilation du motif.
5.
L'ancien mécanisme ne détectait pas les plages illégales dans la définition de la propriété. Maintenant, le maximum de la plage ne doit pas être inférieur au minimum de la plage. Sinon, le motif échoue à la compilation.
6.
L'intention était que chaque sous-routine soit appelée une seule fois pendant la durée de vie du programme, afin que la définition d'une propriété soit immuable. Ceci a été assoupli afin qu'elle puisse être appelée une fois pour toutes les compilations /i, et potentiellement une seconde fois pour les compilations non /i (la sous-routine reçoit un paramètre l'indiquant). Cependant, en pratique, il y a eu des cas où cela était rompu, et des appels multiples étaient possibles. Ceux-ci ont été corrigés. Maintenant (outre les cas /i, non-/i), la seule façon pour qu'une sous-routine puisse être appelée plusieurs fois est si un de ses composants n'a pas encore été défini. Par exemple, supposons que nous ayons la sous-routine IsA() dont la définition est connue au moment de la compilation, et qu'elle appelle à son tour isB() dont la définition n'est pas encore connue. isA() sera appelée à chaque fois qu'un motif dans lequel elle apparaît sera compilé. Si isA() appelle également isC() et que sa définition est connue, isC() ne sera appelée qu'une seule fois.
7.
Il y a eu des problèmes de concurrence et de très longs blocages si un fil d'exécution compilait la même propriété qu'un autre simultanément. Ceux-ci ont maintenant été corrigés.
  • Correction d'un échec de correspondance approprié.

    Un regnode EXACTFish a une longueur finie qu'il peut contenir pour la chaîne en cours de correspondance. Si cette longueur est dépassée, un deuxième nœud est utilisé pour le segment suivant de la chaîne, pour autant de regnodes que nécessaire. Il faut faire attention où casser la chaîne, afin de gérer correctement les plis multi-caractères en Unicode. Si nous voulons casser une chaîne à un endroit qui pourrait potentiellement se trouver au milieu d'un pli multi-caractères, nous reculons d'un (ou plusieurs) caractères, laissant un regnode EXACTFish plus court. Ce mécanisme de recul contenait une erreur d'un caractère. [GH #16806] https://github.com/Perl/perl5/issues/16806.

  • Un appel "eof" nu sans aucun descripteur de fichier précédent renvoie maintenant vrai. [GH #16786] https://github.com/Perl/perl5/issues/16786
  • L'échec de compilation d'un format interrompt maintenant la compilation. Comme d'autres erreurs dans les sous-analyses, cela pouvait laisser l'analyseur dans un état étrange, potentiellement faire planter Perl si la compilation continuait. [GH #16169] https://github.com/Perl/perl5/issues/16169
  • Si une modification sur place est toujours en cours lors de la destruction globale et que le code de sortie du processus (tel qu'enregistré dans $?) est zéro, Perl traitera maintenant la modification sur place comme réussie, remplaçant le fichier d'entrée par toute sortie produite.

    Cela permet à un code comme :

    perl -i -ne 'print "Foo"; last'

    de remplacer le fichier d'entrée, tandis qu'un code comme :

    perl -i -ne 'print "Foo"; die'

    ne le fera pas. Résout partiellement [GH #16748] https://github.com/Perl/perl5/issues/16748.

  • Une régression dans 5.28 faisait échouer le code suivant 
    close(STDIN); open(CHILD, "|wc -l")'

    car le stdin de l'enfant serait fermé lors de l'exécution. Ceci est maintenant corrigé.

  • Correction d'un problème où la compilation d'une expression régulière contenant à la fois des blocs de code à la compilation et à l'exécution pouvait conduire à tenter de compiler quelque chose qui était une syntaxe invalide.
  • Correction des échecs de construction avec "-DNO_LOCALE_NUMERIC" et "-DNO_LOCALE_COLLATE". [GH #16771] https://github.com/Perl/perl5/issues/16771.
  • Empêcher le passage des tests dans ext/B/t/strict.t. [GH #16783] https://github.com/Perl/perl5/issues/16783.
  • Les nœuds "/di" se terminant ou commençant par s sont maintenant "EXACTF". Nous ne voulons pas que deux "EXACTFU" soient joints ensemble lors de l'optimisation, pour former une séquence "ss", "sS", "Ss" ou "SS" ; ce sont les seules séquences multi-caractères qui peuvent correspondre différemment sous "/ui" et "/di".

Reporting Bugs

Si vous trouvez ce que vous pensez être un bogue, vous pouvez consulter la base de données des bogues Perl sur https://rt.perl.org/. Vous pourriez également trouver des informations sur http://www.perl.org/, la page d'accueil de Perl.

Si vous pensez avoir un bogue non signalé, veuillez exécuter le programme perlbug inclus avec votre version. Assurez-vous de réduire votre bogue à un cas de test minuscule mais suffisant. Votre rapport de bogue, ainsi que la sortie de "perl -V", seront envoyés à perlbug@perl.org pour être analysés par l'équipe de portage Perl.

Si le bogue que vous signalez a des implications de sécurité qui le rendent inapproprié à l'envoi à une liste de diffusion publiquement archivée, alors consultez "SECURITY VULNERABILITY CONTACT INFORMATION" dans perlsec pour les détails sur la façon de signaler le problème.

Give Thanks

Si vous souhaitez remercier les Perl 5 Porters pour le travail que nous avons effectué dans Perl 5, vous pouvez le faire en exécutant le programme "perlthanks" :

perlthanks

Cela enverra un e-mail à la liste des Perl 5 Porters avec votre manifestation de gratitude.
