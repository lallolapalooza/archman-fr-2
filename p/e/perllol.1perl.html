NOM

perllol - Manipulation des tableaux de tableaux en Perl

DESCRIPTION

Déclaration et accès aux tableaux de tableaux

La structure de données à deux niveaux la plus simple à construire en Perl est un tableau de tableaux, parfois appelé familièrement une liste de listes. C'est raisonnablement facile à comprendre, et presque tout ce qui s'applique ici sera également applicable plus tard avec des structures de données plus sophistiquées.

Un tableau de tableaux est juste un vieux tableau ordinaire @AoA auquel vous pouvez accéder avec deux indices, comme "$AoA[3][2]". Voici une déclaration du tableau :

  use v5.10;  # pour pouvoir utiliser say()
  # affecter à notre tableau, un tableau de références de tableaux
  @AoA = (
         [ "fred", "barney", "pebbles", "bambam", "dino", ],
         [ "george", "jane", "elroy", "judy", ],
         [ "homer", "bart", "marge", "maggie", ],
  );
  say $AoA[2][1];
bart

Maintenant, vous devriez faire très attention à ce que le type de crochet extérieur soit un crochet rond, c'est-à-dire une parenthèse. C'est parce que vous affectez à un @array, vous avez donc besoin de parenthèses. Si vous vouliez qu'il n'y ait *pas* de @AoA, mais plutôt juste une référence à celui-ci, vous pourriez faire quelque chose de plus comme ceci :

  # affecter une référence à un tableau de références de tableaux
  $ref_to_AoA = [
      [ "fred", "barney", "pebbles", "bambam", "dino", ],
      [ "george", "jane", "elroy", "judy", ],
      [ "homer", "bart", "marge", "maggie", ],
  ];
  say $ref_to_AoA->[2][1];
bart

Notez que le type de crochet extérieur a changé, et donc notre syntaxe d'accès a également changé. C'est parce que, contrairement à C, en Perl, vous ne pouvez pas échanger librement des tableaux et des références à ceux-ci. $ref_to_AoA est une référence à un tableau, tandis que @AoA est un tableau propre. De même, $AoA[2] n'est pas un tableau, mais une référence de tableau. Alors comment se fait-il que vous puissiez écrire ceci :

$AoA[2][2]
$ref_to_AoA->[2][2]

au lieu d'avoir à écrire ceci :

$AoA[2]->[2]
$ref_to_AoA->[2]->[2]

Eh bien, c'est parce que la règle est que sur des crochets adjacents uniquement (qu'ils soient carrés ou ondulés), vous êtes libre d'omettre la flèche de déréférencement du pointeur. Mais vous ne pouvez pas le faire pour le tout premier s'il s'agit d'un scalaire contenant une référence, ce qui signifie que $ref_to_AoA en a toujours besoin.

Créer les siennes

C'est bien joli pour la déclaration d'une structure de données fixe, mais que faire si vous vouliez ajouter de nouveaux éléments à la volée, ou la construire entièrement à partir de zéro ?

Tout d'abord, regardons comment lire à partir d'un fichier. C'est un peu comme ajouter une ligne à la fois. Nous supposerons qu'il existe un fichier plat dans lequel chaque ligne est une ligne et chaque mot un élément. Si vous essayez de développer un tableau @AoA contenant tout cela, voici la bonne façon de procéder :

while (<>) {
    @tmp = split;
    push @AoA, [ @tmp ];
}

Vous pourriez également l'avoir chargé à partir d'une fonction :

for $i ( 1 .. 10 ) {
    $AoA[$i] = [ somefunc($i) ];
}

Ou vous auriez pu avoir une variable temporaire qui contenait le tableau.

for $i ( 1 .. 10 ) {
    @tmp = somefunc($i);
    $AoA[$i] = [ @tmp ];
}

Il est important de s'assurer d'utiliser le constructeur de référence de tableau "[ ]". Parce que ceci ne fonctionnerait pas :

$AoA[$i] = @tmp;   # FAUX !

La raison pour laquelle cela ne fait pas ce que vous voulez est que l'affectation d'un tableau nommé comme celui-ci à un scalaire prend un tableau dans un contexte scalaire, ce qui signifie simplement compter le nombre d'éléments dans @tmp.

Si vous exécutez sous "use strict" (et si vous ne le faites pas, pourquoi diable ne le faites-vous pas ?), vous devrez ajouter quelques déclarations pour qu'il soit satisfait :

use strict;
my(@AoA, @tmp);
while (<>) {
    @tmp = split;
    push @AoA, [ @tmp ];
}

Bien sûr, vous n'avez même pas besoin que le tableau temporaire ait un nom :

while (<>) {
    push @AoA, [ split ];
}

Vous n'avez pas non plus à utiliser push(). Vous pourriez simplement faire une affectation directe si vous saviez où vous vouliez le placer :

my (@AoA, $i, $line);
for $i ( 0 .. 10 ) {
    $line = <>;
    $AoA[$i] = [ split " ", $line ];
}

ou même simplement

my (@AoA, $i);
for $i ( 0 .. 10 ) {
    $AoA[$i] = [ split " ", <> ];
}

Vous devriez en général vous méfier de l'utilisation de fonctions qui pourraient potentiellement retourner des listes dans un contexte scalaire sans le déclarer explicitement. Ce serait plus clair pour le lecteur occasionnel :

my (@AoA, $i);
for $i ( 0 .. 10 ) {
    $AoA[$i] = [ split " ", scalar(<>) ];
}

Si vous vouliez avoir une variable $ref_to_AoA comme référence à un tableau, vous devriez faire quelque chose comme ceci :

while (<>) {
    push @$ref_to_AoA, [ split ];
}

Maintenant, vous pouvez ajouter de nouvelles lignes. Qu'en est-il de l'ajout de nouvelles colonnes ? Si vous ne traitez que des matrices, il est souvent plus facile d'utiliser une affectation simple :

for $x (1 .. 10) {
    for $y (1 .. 10) {
        $AoA[$x][$y] = func($x, $y);
    }
}
for $x ( 3, 7, 9 ) {
    $AoA[$x][20] += func2($x);
}

Peu importe que ces éléments soient déjà présents ou non : cela les créera volontiers pour vous, en définissant les éléments intermédiaires à "undef" si nécessaire.

Si vous vouliez juste ajouter à une ligne, vous devriez faire quelque chose d'un peu plus étrange :

# ajouter de nouvelles colonnes à une ligne existante
push $AoA[0]->@*, "wilma", "betty";   # déréférencement explicite

Accès et impression

Il est maintenant temps d'imprimer votre structure de données. Comment allez-vous faire cela ? Eh bien, si vous ne voulez qu'un seul des éléments, c'est trivial :

print $AoA[0][0];

Si vous voulez imprimer le tout, cependant, vous ne pouvez pas dire

print @AoA;         # FAUX

car vous obtiendrez juste des références listées, et Perl ne déréférencera jamais les choses automatiquement pour vous. Au lieu de cela, vous devez créer vous-même une ou deux boucles. Ceci imprime toute la structure, en utilisant la construction for() de style shell pour boucler sur les indices extérieurs.

for $aref ( @AoA ) {
    say "\t [ @$aref ],";
}

Si vous vouliez garder une trace des indices, vous pourriez faire ceci :

for $i ( 0 .. $#AoA ) {
    say "\t elt $i est [ @{$AoA[$i]} ],";
}

ou même ceci. Notez la boucle interne.

for $i ( 0 .. $#AoA ) {
    for $j ( 0 .. $#{$AoA[$i]} ) {
        say "elt $i $j est $AoA[$i][$j]";
    }
}

Comme vous pouvez le voir, cela devient un peu compliqué. C'est pourquoi il est parfois plus facile de prendre un temporaire sur votre chemin :

for $i ( 0 .. $#AoA ) {
    $aref = $AoA[$i];
    for $j ( 0 .. $#{$aref} ) {
        say "elt $i $j est $AoA[$i][$j]";
    }
}

Hmm... c'est toujours un peu laid. Que diriez-vous de ceci :

for $i ( 0 .. $#AoA ) {
    $aref = $AoA[$i];
    $n = @$aref - 1;
    for $j ( 0 .. $n ) {
        say "elt $i $j est $AoA[$i][$j]";
    }
}

Lorsque vous vous fatiguez d'écrire une "impression" personnalisée pour vos structures de données, vous pourriez jeter un coup d'œil aux modules standard Dumpvalue ou Data::Dumper. Le premier est ce qu'utilise le débogueur Perl, tandis que le second génère du code Perl analysable. Par exemple :

use v5.14;     # utilisation du prototype +, nouveau depuis v5.14
sub show(+) {
       require Dumpvalue;
   state $prettify = Dumpvalue->new(
       tick        => q("),
       compactDump => 1,  # commentez ces deux lignes
       veryCompact => 1,  # si vous voulez une décharge plus grande
   );
       $prettify->dumpValue(@_);
}
# Affecter une liste de références de tableaux à un tableau.
my @AoA = (
          [ "fred", "barney" ],
          [ "george", "jane", "elroy" ],
          [ "homer", "marge", "bart" ],
);
push $AoA[0]->@*, "wilma", "betty";
show @AoA;

imprimera :

0  0..3  "fred" "barney" "wilma" "betty"
1  0..2  "george" "jane" "elroy"
2  0..2  "homer" "marge" "bart"

NAME

perllol - Perl's way of dealing with array-of-arrays

DESCRIPTION

This is probably the most confusing of Perl's data structures. It takes the form of an array of array references. That is, you have an array, and each element of that array is itself a reference to an array.

    $AoA = [
        [ "fred", "barney", "wilma", "betty" ],
        [ "george", "jane", "elroy" ],
        [ "homer", "marge", "bart" ]
    ];

While you can certainly access individual elements using double subscripting, i.e.:

    $name = $AoA[0][0]; # "fred"

you may wish to consider that while the dereferencing arrow is implicitly supplied when you use double-subscripting, it's not explicit.

The explicit dereferencing for a single element looks like this:

    $name = $AoA->[0]->[0]; # "fred"

If you have an array-of-arrays where each inner array is of the same length, you might want to think about using a hash keyed by row number instead.

Also, if you want to get at a slice (part of a row) in a multidimensional array, you're going to have to do some fancy subscripting. That's because while we have a nice synonym for single elements via the pointer arrow for dereferencing, no such convenience exists for slices.

Here's how to do one operation using a loop. We'll assume an @AoA variable as before.

    @part = ();
    $x = 4;
    for ($y = 7; $y < 13; $y++) {
        push @part, $AoA[$x][$y];
    }

That same loop could be replaced with a slice operation:

    @part = $AoA[4]->@[ 7..12 ];

Now, what if you wanted a two-dimensional slice, such as having $x run from 4..8 and $y run from 7 to 12? Hmm... here's the simple way:

    @newAoA = ();
    for ($startx = $x = 4; $x <= 8; $x++) {
        for ($starty = $y = 7; $y <= 12; $y++) {
            $newAoA[$x - $startx][$y - $starty] = $AoA[$x][$y];
        }
    }

We can reduce some of the looping through slices

    for ($x = 4; $x <= 8; $x++) {
        push @newAoA, [ $AoA[$x]->@[ 7..12 ] ];
    }

If you were into Schwartzian Transforms, you would probably have selected map for that

    @newAoA = map { [ $AoA[$_]->@[ 7..12 ] ] } 4 .. 8;

Although if your manager accused you of seeking job security (or rapid insecurity) through inscrutable code, it would be hard to argue. :-) If I were you, I'd put that in a function:

    @newAoA = splice_2D( \@AoA, 4 => 8, 7 => 12 );
    sub splice_2D {
        my $lrr = shift;        # ref to array of array refs!
        my ($x_lo, $x_hi,
            $y_lo, $y_hi) = @_;
        return map {
            [ $lrr->[$_]->@[ $y_lo .. $y_hi ] ]
        } $x_lo .. $x_hi;
    }
