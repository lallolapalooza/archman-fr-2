NOM

perf-trace - outil inspiré de strace

SYNTAXE

perf trace
perf trace record

DESCRIPTION

Cette commande affichera les événements associés à la cible, initialement les appels système, mais aussi d'autres événements système comme les fautes de page, les événements de durée de vie des tâches, les événements d'ordonnancement, etc.

C'est un outil en mode direct en plus de fonctionner avec les fichiers perf.data comme les autres outils perf. Les fichiers peuvent être générés en utilisant la commande perf record mais la session doit inclure les événements raw_syscalls (-e raw_syscalls:*). Alternativement, perf trace record peut être utilisé comme un raccourci pour inclure automatiquement les événements raw_syscalls lors de l'écriture des événements dans un fichier.

Les options suivantes s'appliquent à perf trace ; les options pour perf trace record se trouvent dans la page man de perf record.

OPTIONS

-a, --all-cpus

Collecte à l'échelle du système sur tous les CPU.

-e, --expr, --event

Liste des appels système et autres événements perf (tracepoints, événements de cache matériel, etc.) à afficher. Le globbing est supporté, par exemple : "epoll_*", "msg", etc. Voir perf list pour une liste complète des événements. Préfixer avec ! montre tous les appels système sauf ceux spécifiés. Vous pourriez avoir besoin de les échapper.

--filter=<filtre>

Filtre d'événements. Cette option doit suivre un sélecteur d'événement (-e) qui sélectionne un ou plusieurs événements de tracepoint.

-D msecs, --delay msecs

Après avoir démarré le programme, attendez msecs avant de mesurer. Ceci est utile pour filtrer la phase de démarrage du programme, qui est souvent très différente.

-o, --output=

Nom du fichier de sortie.

-p, --pid=

Enregistrer les événements sur l'ID de processus existant (liste séparée par des virgules).

-t, --tid=

Enregistrer les événements sur l'ID de thread existant (liste séparée par des virgules).

-u, --uid=

Enregistrer les événements dans les threads appartenant à uid. Nom ou numéro.

-G, --cgroup

Enregistrer les événements dans les threads d'un cgroup. 
Recherchez les cgroups à définir dans le répertoire /sys/fs/cgroup/perf_event, puis
supprimez la partie /sys/fs/cgroup/perf_event/ et essayez :
perf trace -G A -e sched:*switch
Définira tous les raw_syscalls:sys_{enter,exit}, pgfault, vfs_getname, etc.
_et_ sched:sched_switch dans le cgroup 'A', tandis que :
perf trace -e sched:*switch -G A
ne définira que l'événement sched:sched_switch dans le cgroup 'A', tous les
autres événements (raw_syscalls:sys_{enter,exit}, etc. resteront "sans"
cgroup (sur le cgroup racine, sys wide, etc.).
Multiples cgroups :
perf trace -G A -e sched:*switch -G B
les appels système iront dans le cgroup 'A', le sched:sched_switch ira
dans le cgroup 'B'.

--filter-pids=

Filtrer les événements pour ces pids et pour trace lui-même (liste séparée par des virgules).

-v, --verbose

Augmenter le niveau de verbosité.

--no-inherit

Les tâches enfants n'héritent pas des compteurs.

-m, --mmap-pages=

Nombre de pages de données mmap (doit être une puissance de deux) ou spécification de taille en octets avec un caractère d'unité ajouté - B/K/M/G. La taille est arrondie à la puissance supérieure la plus proche de pages.

-C, --cpu

Collecter des échantillons uniquement sur la liste des CPU fournis. Plusieurs CPU peuvent être fournis sous forme de liste séparée par des virgules sans espace : 0,1. Les plages de CPU sont spécifiées avec - : 0-2. En mode par thread avec l'héritage activé (par défaut), les événements sont capturés uniquement lorsque le thread s'exécute sur les CPU désignés. Par défaut, tous les CPU sont surveillés.

--duration

Afficher uniquement les événements dont la durée est supérieure à N.M ms.

--sched

Accumuler le temps d'exécution du thread et fournir un résumé à la fin de la session.

--failure

Afficher uniquement les appels système qui ont échoué, c'est-à-dire qui ont renvoyé < 0.

-i, --input

Traiter les événements à partir d'un fichier de données perf donné.

-T, --time

Afficher l'horodatage complet plutôt que le temps relatif au premier échantillon.

--comm

Afficher le COMM du processus juste à côté de son ID, activé par défaut, désactiver avec --no-comm.

-s, --summary

Afficher uniquement un résumé des appels système par thread avec les temps min, max et moyens (en msec) et l'écart-type relatif.

-S, --with-summary

Afficher tous les appels système suivis d'un résumé par thread avec les temps min, max et moyens (en msec) et l'écart-type relatif.

--errno-summary

À utiliser avec -s ou -S, pour afficher les statistiques des errnos rencontrés par les appels système, l'utilisation de cette option seule déclenche --summary.

--summary-mode=mode

À utiliser avec -s ou -S, pour sélectionner la manière d'afficher le résumé. Par défaut, il affichera le résumé des appels système par thread. Les valeurs possibles sont : thread, total, cgroup.

--tool_stats

Afficher les statistiques de l'outil telles que le nombre de fois où fd→pathname a été découvert en accrochant le retour de l'appel système open + vfs_getname ou en lisant /proc/pid/fd, etc.

-f, --force

Ne pas se plaindre, le faire.

-F=[all|min|maj], --pf=[all|min|maj]

Tracer les fautes de page. Optionnellement, vous pouvez spécifier si vous voulez les fautes de page mineures, majeures ou toutes. La valeur par défaut est maj.

--syscalls

Tracer les appels système. Cette option est activée par défaut, désactiver avec --no-syscalls.

--call-graph [mode,type,min[,limit],order[,key][,branch]]

Configurer et activer l'enregistrement du graphe d'appels (chaîne de piles/trace arrière). Voir la section --call-graph des pages man de perf-record et perf-report pour les détails. Les plus utiles dans perf trace sont dwarf et lbr, lorsque disponibles, essayez : perf trace --call-graph dwarf. 
L'utilisation de ceci, pour l'utilisateur root, augmentera la valeur de --mmap-pages à 4 fois le maximum pour les utilisateurs non-root, basé sur le sysctl kernel.perf_event_mlock_kb. Ceci n'est fait que si l'utilisateur ne spécifie pas de valeur --mmap-pages.

--kernel-syscall-graph

Afficher les chaînes d'appels du noyau sur le chemin de sortie des appels système.

--max-events=N

Arrêter après avoir traité N événements. Notez que les événements de type strace ne sont pris en compte qu'à la sortie ou lorsqu'un appel système est interrompu, c'est-à-dire dans ces cas cette option est équivalente au nombre de lignes imprimées.

--switch-on EVENT_NAME

Ne considérer les événements qu'après que cet événement a été trouvé.

--switch-off EVENT_NAME

Arrêter de considérer les événements après que cet événement a été trouvé.

--show-on-off-events

Afficher également les événements --switch-on/off.

--max-stack

Définir la limite de profondeur de la pile lors de l'analyse de la chaîne d'appels, tout ce qui dépasse la profondeur spécifiée sera ignoré. Notez qu'à ce stade, il ne s'agit que de la partie présentation, c'est-à-dire que le noyau ne limite pas encore, la surcharge des chaînes d'appels doit être définie via les boutons dans --call-graph dwarf. 
Implique '--call-graph dwarf' lorsque --call-graph n'est pas présent sur la
ligne de commande, sur les systèmes où le désempilement DWARF a été intégré.
Par défaut : /proc/sys/kernel/perf_event_max_stack lorsqu'il est présent pour
les sessions en direct (sans --input/-i), 127 sinon.

--min-stack

Définir la limite de profondeur de la pile lors de l'analyse de la chaîne d'appels, tout ce qui est inférieur à la profondeur spécifiée sera ignoré. Désactivé par défaut. 
Implique '--call-graph dwarf' lorsque --call-graph n'est pas présent sur la
ligne de commande, sur les systèmes où le désempilement DWARF a été intégré.

--print-sample

Imprimer les informations PERF_RECORD_SAMPLE PERF_SAMPLE_ pour les tracepoints raw_syscalls:sys_{enter,exit}, pour le débogage.

--proc-map-timeout

Lors du traitement des threads préexistants /proc/XXX/mmap, cela peut prendre beaucoup de temps, car le fichier peut être énorme. Un délai d'attente est nécessaire dans de tels cas. Cette option définit la limite de temps d'attente. La valeur par défaut est 500 ms.

--sort-events

Trier par lots d'événements, utiliser lorsque vous remarquez des déconnexions
de l'ordre des événements qui peuvent se produire, par exemple, lorsqu'un thread est migré vers un autre CPU pendant le traitement d'un appel système.

--libtraceevent_print

Utilise libtraceevent pour imprimer les arguments des tracepoints. Par défaut, perf trace utilise les mêmes beautificateurs que ceux utilisés dans les lignes d'entrée+sortie de type strace pour enrichir les arguments des tracepoints.

--force-btf

Utilise btf_dump pour imprimer joliment les données des arguments des appels système, au lieu d'utiliser des imprimeurs joliment faits à la main. Cette option est destinée à tester l'intégration de BTF dans perf trace. L'impression joliment formatée basée sur btf_dump sert de solution de repli aux imprimeurs joliment formatés faits à la main, car ces derniers peuvent mieux imprimer joliment les drapeaux entiers et les pointeurs de structures.

--bpf-summary

Collecte les statistiques des appels système en BPF. Ceci est uniquement pour le mode en direct et fonctionne bien avec l'option -s/--summary où aucune information d'argument n'est requise.

PAGEFAULTS

Lors du traçage des fautes de page, le format du traçage est le suivant :

<min|maj>fault [<ip.symbole>+<ip.décalage>] ⇒ <addr.dso@addr.décalage[1]> (<type de carte><niveau d'adresse >).

•min/maj indique si l'événement de faute est mineure ou majeure ;
•ip.symbole affiche le symbole pour le pointeur d'instruction (le code qui a généré la faute) ; si aucun symbole de débogage n'est disponible, perf trace affichera l'IP brut ;
•addr.dso affiche le DSO pour l'adresse en faute ;
•type de carte est soit d pour les cartes non exécutables, soit x pour les cartes exécutables ;
•niveau d'adresse est soit k pour le DSO du noyau, soit . pour le DSO utilisateur.

Pour la résolution des symboles, vous devrez peut-être installer des symboles de débogage.

Veuillez noter que la durée est actuellement toujours de 0 et ne reflète pas le temps réel qu'il a fallu pour traiter la faute !

Lorsque --verbose est spécifié, perf trace tente d'imprimer toutes les informations disponibles pour l'IP et l'adresse de faute sous la forme dso@symbole[2]+décalage.

EXEMPLES

Tracer uniquement les fautes de page majeures :

$ perf trace --no-syscalls -F

Tracer les appels système, les fautes de page majeures et mineures :

$ perf trace -F all
1416.547 ( 0.000 ms): python/20235 majfault [CRYPTO_push_info_+0x0] => /lib/x86_64-linux-gnu/libcrypto.so.1.0.0@0x61be0 (x.)
Comme vous pouvez le voir, il y a eu une faute de page majeure dans le processus python, provenant de la routine
CRYPTO_push_info_ qui a fauté quelque part dans libcrypto.so.

Tracer les 4 premières ouvertures, openat ou open_by_handle_at (plus d'appels système pourraient correspondre à l'avenir) :

$ perf trace -e open* --max-events 4
