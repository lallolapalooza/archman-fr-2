NOM

perlrun - comment exécuter l'interpréteur Perl

SYNOPSIS

perl [ -gsTtuUWX ] [ -h?v ] [ -V[:variable_config] ] [ -cw ] [ -d[t][:débogueur] ] [ -D[nombre/liste] ] [ -pna ] [ -Fmotif ] [ -l[octal] ] [ -0[octal/hexadécimal] ] [ -Irép ] [ -m[-]module ] [ -M[-]'module...' ] [ -f ] [ -C [nombre/liste] ] [ -S ] [ -x[rép] ] [ -i[extension] ] [ [-e|-E] 'commande' ] [ -- ] [ fichier_programme ] [ argument ]...

DESCRIPTION

La façon normale d'exécuter un programme Perl est de le rendre directement exécutable, ou de passer le nom du fichier source comme argument sur la ligne de commande. (Un environnement Perl interactif est également possible -- voir perldebug pour plus de détails sur comment faire cela.) Au démarrage, Perl recherche votre programme dans l'un des endroits suivants :

1.
Spécifié ligne par ligne via les options -e ou -E sur la ligne de commande.
2.
Contenu dans le fichier spécifié par le premier nom de fichier sur la ligne de commande. (Notez que les systèmes supportant la notation "#!" invoquent les interpréteurs de cette façon. Voir "Emplacement de Perl".)
3.
Passé implicitement via l'entrée standard. Cela ne fonctionne que s'il n'y a pas d'arguments de nom de fichier -- pour passer des arguments à un programme lu depuis STDIN, vous devez explicitement spécifier un "-" pour le nom du programme.

Avec les méthodes 2 et 3, Perl commence à analyser le fichier d'entrée depuis le début, à moins que vous n'ayez spécifié l'option "-x", auquel cas il recherche la première ligne commençant par "#!" et contenant le mot "perl", et commence là à la place. C'est utile pour exécuter un programme intégré dans un message plus grand. (Dans ce cas, vous indiqueriez la fin du programme en utilisant le jeton "__END__".)

La ligne "#!" est toujours examinée pour les options lors de l'analyse de la ligne. Ainsi, si vous êtes sur une machine qui n'autorise qu'un seul argument avec la ligne "#!", ou pire, qui ne reconnaît même pas la ligne "#!", vous pouvez toujours avoir un comportement d'options cohérent quel que soit le mode d'invocation de Perl, même si "-x" a été utilisé pour trouver le début du programme.

Parce qu'historiquement certains systèmes d'exploitation tronquaient silencieusement l'interprétation par le noyau de la ligne "#!" après 32 caractères, certaines options peuvent être passées sur la ligne de commande, et d'autres non ; vous pourriez même obtenir un "-" sans sa lettre, si vous n'êtes pas prudent. Vous voudrez probablement vous assurer que toutes vos options tombent avant ou après cette limite de 32 caractères. La plupart des options ne se soucient pas réellement si elles sont traitées de manière redondante, mais obtenir un "-" au lieu d'une option complète pourrait amener Perl à essayer d'exécuter l'entrée standard au lieu de votre programme. Et une option -I partielle pourrait également entraîner des résultats étranges.

Certaines options se soucient d'être traitées deux fois, par exemple les combinaisons de -l et -0. Soit placez toutes les options après la limite de 32 caractères (si applicable), soit remplacez l'utilisation de -0chiffres par "BEGIN{ $/ = "\0chiffres"; }".

L'analyse des options "#!" commence là où "perl" est mentionné sur la ligne. Les séquences "-*" et "- " sont spécifiquement ignorées afin que vous puissiez, si vous le souhaitiez, dire

#!/bin/sh
#! -*- perl -*- -p
eval 'exec perl -x -wS $0 ${1+"$@"}'
    if 0;

pour laisser Perl voir l'option "-p".

Une astuce similaire implique le programme env, si vous l'avez.

#!/usr/bin/env perl

Les exemples ci-dessus utilisent un chemin relatif vers l'interpréteur Perl, obtenant la version disponible en premier dans le chemin de l'utilisateur. Si vous voulez une version spécifique de Perl, par exemple, perl5.14.1, vous devriez la placer directement dans le chemin de la ligne "#!".

Si la ligne "#!" ne contient ni le mot "perl" ni le mot "indir", le programme nommé après "#!" est exécuté à la place de l'interpréteur Perl. C'est un peu bizarre, mais cela aide les utilisateurs sur des machines qui ne gèrent pas "#!", car ils peuvent indiquer à un programme que leur SHELL est /usr/bin/perl, et Perl se chargera alors de distribuer le programme à l'interpréteur correct pour eux.

Après avoir localisé votre programme, Perl compile l'intégralité du programme sous une forme interne. S'il y a des erreurs de compilation, l'exécution du programme n'est pas tentée. (Ceci est différent d'un script shell typique, qui pourrait s'exécuter partiellement avant de trouver une erreur de syntaxe.)

Si le programme est syntaxiquement correct, il est exécuté. Si le programme se termine sans atteindre un opérateur exit() ou die(), un exit(0) implicite est fourni pour indiquer une exécution réussie.

#! et les guillemets sur les systèmes non-Unix

La technique "#!" de Unix peut être simulée sur d'autres systèmes :

OS/2
Mettez 
extproc perl -S -vos_options

comme première ligne dans le fichier "*.cmd" ("-S" en raison d'un bug dans la gestion de `extproc' de cmd.exe).

MS-DOS
Créez un fichier batch pour exécuter votre programme, et codez-le dans "ALTERNATE_SHEBANG" (voir le fichier dosish.h dans la distribution source pour plus d'informations).
Win95/NT
L'installation Win95/NT, lors de l'utilisation de l'installeur ActiveState pour Perl, modifiera le Registre pour associer l'extension .pl à l'interpréteur Perl. Si vous installez Perl par d'autres moyens (y compris la compilation à partir des sources), vous devrez peut-être modifier vous-même le Registre. Notez que cela signifie que vous ne pourrez plus faire la différence entre un programme Perl exécutable et un fichier de bibliothèque Perl.
VMS
Mettez 
$ perl -mes_options 'f$env("procedure")' 'p1' 'p2' 'p3' 'p4' 'p5' 'p6' 'p7' 'p8' !
$ exit++ + ++$status != 0 and $exit = $status = undef;

en haut de votre programme, où -mes_options sont les options de ligne de commande que vous souhaitez passer à Perl. Vous pouvez maintenant invoquer le programme directement, en disant "perl programme", ou comme procédure DCL, en disant @programme (ou implicitement via DCL$PATH en utilisant simplement le nom du programme).

Cette incantation est un peu compliquée à retenir, mais Perl vous l'affichera si vous dites "perl "-V:startperl"".

Les interpréteurs de commandes sur les systèmes non-Unix ont des idées assez différentes sur la mise entre guillemets que les shells Unix. Vous devrez apprendre les caractères spéciaux de votre interpréteur de commandes ("*", "\" et """ sont courants) et comment protéger les espaces blancs et ces caractères pour exécuter des one-liners (voir -e ci-dessous).

Sur certains systèmes, vous devrez peut-être remplacer les apostrophes par des guillemets doubles, ce que vous ne devez *pas* faire sur les systèmes Unix ou Plan 9. Vous devrez peut-être également remplacer un seul % par un %%.

Par exemple :

# Unix
perl -e 'print "Bonjour le monde\n"'
# MS-DOS, etc.
perl -e "print \"Bonjour le monde\n\""
# VMS
perl -e "print ""Bonjour le monde\n"""

Le problème est qu'aucune de ces méthodes n'est fiable : cela dépend de la commande et il est tout à fait possible qu'aucune ne fonctionne. Si 4DOS était le shell de commande, cela fonctionnerait probablement mieux :

perl -e "print <Ctrl-x>"Bonjour m

NAME

perlrun - how to run Perl perl scripts

SYNOPSIS

    perl [ -sTtv ] [ -dìlnhyz ] [ -- ] [ scriptlet | -e prog ] [ -- ] [ args ... ]
    perl L [ -U isa ] [ -dìlnthy ] [ -- ] [ scriptfile ] [ -- ] [ args ... ]
    perl program.pl [ args ... ]

DESCRIPTION

This document describes how to invoke the Perl interpreter and how to make your Perl scripts executable. It also covers Perl's command-line switches.

Quoting rules are notoriously system-dependent. This document assumes that you know how to quote arguments on your particular system. For example, on Unix you might need to escape shell metacharacters with backslashes or put arguments in quotes:

    perl -e 'print "Hello\n"'
    perl -e "print \"Hello\n\""

CMD.EXE in Windows NT a intégré beaucoup de fonctionnalités Unix standard sans que personne ne s'en aperçoive, mais essayez juste de trouver de la documentation pour ses règles de mise entre guillemets.

Il n'y a pas de solution générale à tout cela. C'est juste un désordre.

Location de Perl

Il peut sembler évident de le dire, mais Perl n'est utile que lorsque les utilisateurs peuvent le trouver facilement. Lorsque cela est possible, il est bon que /usr/bin/perl et /usr/local/bin/perl soient des liens symboliques vers le binaire réel. Si cela ne peut être fait, il est fortement recommandé aux administrateurs système de placer (des liens symboliques vers) perl et ses utilitaires d'accompagnement dans un répertoire typiquement trouvé dans le PATH d'un utilisateur, ou dans un autre endroit évident et pratique.

Dans cette documentation, "#!/usr/bin/perl" sur la première ligne du programme remplacera la méthode qui fonctionne sur votre système. Il est conseillé d'utiliser un chemin spécifique si vous vous souciez d'une version spécifique.

#!/usr/local/bin/perl5.14

ou si vous voulez simplement exécuter au moins une version, placez une instruction comme celle-ci en haut de votre programme :

use v5.14;

Commutateurs de commande

Comme pour toutes les commandes standard, un commutateur d'un seul caractère peut être regroupé avec le commutateur suivant, le cas échéant.

#!/usr/bin/perl -spi.orig   # équivalent à -s -p -i.orig

Un "--" signale la fin des options et désactive le traitement ultérieur des options. Tous les arguments après le "--" sont traités comme des noms de fichiers et des arguments.

Les commutateurs incluent :

-0[octal/hexadécimal]
spécifie le séparateur d'enregistrement d'entrée ($/) sous forme de nombre octal ou hexadécimal. S'il n'y a pas de chiffres, le caractère nul est le séparateur. D'autres commutateurs peuvent précéder ou suivre les chiffres. Par exemple, si vous avez une version de find qui peut imprimer des noms de fichiers terminés par le caractère nul, vous pouvez dire ceci : 
find . -name '*.orig' -print0 | perl -n0e unlink

La valeur spéciale 00 fera en sorte que Perl lise les fichiers en mode paragraphe.

Toute valeur 0400 ou supérieure fera en sorte que Perl lise les fichiers en entier, mais par convention, la valeur 0777 est celle normalement utilisée à cette fin. Le drapeau "-g" en est un alias plus simple.

Vous pouvez également spécifier le caractère séparateur en notation hexadécimale : -0xHHH..., où les "H" sont des chiffres hexadécimaux valides. Contrairement à la forme octale, celle-ci peut être utilisée pour spécifier n'importe quel caractère Unicode, même ceux au-delà de 0xFF. Donc, si vous voulez *vraiment* un séparateur d'enregistrement de 0777, spécifiez-le comme -0x1FF. (Cela signifie que vous ne pouvez pas utiliser l'option "-x" avec un nom de répertoire composé de chiffres hexadécimaux, sinon Perl pensera que vous avez spécifié un nombre hexadécimal pour -0.)

-a
active le mode autosplit lorsqu'il est utilisé avec "-n" ou "-p". Un appel implicite à split sur le tableau @F est effectué comme première chose à l'intérieur de la boucle while implicite produite par "-n" ou "-p". 
perl -ane 'print pop(@F), "\n";'

est équivalent à

while (<>) {
    @F = split(' ');
    print pop(@F), "\n";
}

Un délimiteur alternatif peut être spécifié en utilisant -F.

-a définit implicitement "-n".

-C [nombre/liste]
Le drapeau -C contrôle certaines des fonctionnalités Unicode de Perl.

À partir de 5.8.1, -C peut être suivi d'un nombre ou d'une liste de lettres d'option. Les lettres, leurs valeurs numériques et leurs effets sont les suivants ; lister les lettres équivaut à additionner les nombres.

I     1   STDIN est supposé être en UTF-8
O     2   STDOUT sera en UTF-8
E     4   STDERR sera en UTF-8
S     7   I + O + E
i     8   UTF-8 est la couche PerlIO par défaut pour les flux d'entrée
o    16   UTF-8 est la couche PerlIO par défaut pour les flux de sortie
D    24   i + o
A    32   les éléments de @ARGV sont censés être des chaînes encodées
          en UTF-8
L    64   normalement, les "IOEioA" sont inconditionnels, L les rend
          conditionnels aux variables d'environnement de locale
          (les LC_ALL, LC_CTYPE, et LANG, dans l'ordre de priorité décroissante)
          -- si les variables indiquent UTF-8, alors les "IOEioA"
          sélectionnés sont en vigueur
a   256   Définit ${^UTF8CACHE} à -1, pour exécuter le code de mise en
          cache UTF-8 en mode de débogage.

Par exemple, -COE et -C6 activeront tous deux l'UTF-8 sur STDOUT et STDERR. La répétition des lettres n'est pas cumulative ni ne bascule, elle est juste redondante.

Les options "io" signifient que toute opération open() ultérieure (ou opérations d'E/S similaires) dans la portée du programme principal aura la couche PerlIO ":utf8" appliquée implicitement, en d'autres termes, l'UTF-8 est attendu de tout flux d'entrée, et l'UTF-8 est produit vers tout flux de sortie. C'est juste la valeur par défaut définie via "${^OPEN}", avec des couches explicites dans open() et avec binmode() on peut manipuler les flux comme d'habitude. Cela n'a aucun effet sur le code exécuté dans les modules.

-C seul (non suivi d'un nombre ou d'une liste d'options), ou la chaîne vide "" pour la variable d'environnement "PERL_UNICODE", a le même effet que -CSDL. En d'autres termes, les gestionnaires d'E/S standard et la couche par défaut open() sont passés en UTF-8 *mais* seulement si les variables d'environnement de locale indiquent une locale UTF-8. Ce comportement suit le comportement UTF-8 *implicite* (et problématique) de Perl 5.8.0. (Voir "UTF-8 no longer default under UTF-8 locales" dans perl581delta.)

Vous pouvez utiliser -C0 (ou "0" pour "PERL_UNICODE") pour désactiver explicitement toutes les fonctionnalités Unicode ci-dessus.

La variable magique en lecture seule "${^UNICODE}" reflète la valeur numérique de ce réglage. Cette variable est définie pendant le démarrage de Perl et est ensuite en lecture seule. Si vous voulez des effets d'exécution, utilisez le open() à trois arguments (voir "open" dans perlfunc), le binmode() à deux arguments (voir "binmode" dans perlfunc), et le pragma "open" (voir open).

(Dans les versions de Perl antérieures à 5.8.1, le commutateur -C était un commutateur propre à Win32 qui activait l'utilisation des API Win32 "wide system call" compatibles Unicode. Cette fonctionnalité était pratiquement inutilisée, cependant, et le commutateur de ligne de commande a donc été "recyclé".)

Remarque : Depuis perl 5.10.1, si l'option -C est utilisée sur la ligne "#!", elle doit également être spécifiée sur la ligne de commande, car les flux standard sont déjà configurés à ce stade de l'exécution de l'interpréteur perl. Vous pouvez également utiliser binmode() pour définir l'encodage d'un flux d'E/S.

-c
fait en sorte que Perl vérifie la syntaxe du programme puis se termine sans l'exécuter. En fait, il *exécutera* tous les blocs "BEGIN", "UNITCHECK", ou "CHECK" et toutes les instructions "use" : ceux-ci sont considérés comme se produisant en dehors de l'exécution de votre programme. Les blocs "INIT" et "END", cependant, seront sautés.

Si la vérification de la syntaxe réussit, perl se terminera avec un statut de zéro et rapportera "votreprogramme syntax OK". En cas d'échec, perl imprimera toutes les erreurs détectées et se terminera avec un statut non nul.

-d
-dt
exécute le programme sous le débogueur Perl. Voir perldebug. Si t est spécifié, "PERL5DB_THREADED=1" est défini dans l'environnement pour indiquer au débogueur que des threads seront utilisés dans le code en cours de débogage.
-d:MOD[=bar,baz]
-dt:MOD[=bar,baz]
exécute le programme sous le contrôle d'un module de débogage, de profilage ou de traçage installé comme "Devel::MOD". Par exemple, -d:DProf exécute le programme en utilisant le profileur "Devel::DProf". Comme avec le drapeau -M, les options peuvent être passées au paquet "Devel::MOD" où elles seront reçues et interprétées par la routine "Devel::MOD::import". Encore une fois, comme -M, utilisez --d:-MOD pour appeler "Devel::MOD::unimport" au lieu de import. La liste d'options séparées par des virgules doit suivre un caractère "=". Si t est spécifié, il indique au débogueur que des threads seront utilisés dans le code en cours de débogage. Voir perldebug.
-Dlettres
-Dnombre
définit les indicateurs de débogage. Ce commutateur n'est activé que si votre binaire perl a été construit avec le débogage activé : les perls de production normaux ne l'auront pas été.

Par exemple, pour observer comment perl exécute votre programme, utilisez -Dtls. Une autre valeur agréable est -Dx, qui liste votre arbre syntaxique compilé, et -Dr affiche les expressions régulières compilées ; le format de la sortie est expliqué dans perldebguts.

Alternativement, spécifiez un nombre au lieu d'une liste de lettres (par exemple, -D14 est équivalent à -Dtls) :

        1  p  Tokenisation et analyse (avec v, affiche la pile
              d'analyse)
        2  s  Instantanés de pile (avec v, affiche toutes les piles)
        4  l  Traitement de pile de contexte (boucle)
        8
t Traçage de l'exécution 16 o Résolution de méthodes et de surcharges 32 c Conversions chaîne/numérique 64 P Affichage des informations de profilage, état de l'entrée du fichier source 128 m Allocation mémoire et SV 256 f Traitement du format 512 r Analyse et exécution des expressions régulières 1024 x Vidage de l'arbre syntaxique 2048 u Vérifications de contamination (tainting) 4096 U Non officiel, piratage utilisateur (réservé pour un usage privé, non publié) 8192 h Afficher la sortie de débogage de la randomisation du hachage (changements apportés à PL_hash_rand_bits et leur origine) 16384 X Allocation de scratchpad 32768 D Nettoyage 65536 S Allocation de slab d'opérateurs 131072 T Tokenisation 262144 R Inclure les comptes de référence des variables vidées (par exemple, lors de l'utilisation de -Ds) 524288 J Afficher le débogage s, t, P (ne pas sauter par-dessus) sur les opérandes à l'intérieur du package DB 1048576 v Verbose : à utiliser en conjonction avec d'autres drapeaux pour augmenter la verbosité de la sortie. Ne fait rien sur beaucoup d'autres drapeaux. 2097152 C Copier à la volée (Copy On Write) 4194304 A Vérifications de cohérence sur les structures internes 8388608 q quiet - actuellement, ne supprime que le message "EXECUTING" 16777216 M Traçage de la résolution de la correspondance intelligente (smart match) 33554432 B Vidage des définitions de sous-programmes, y compris les blocs spéciaux comme BEGIN 67108864 L Traçage des informations relatives à la locale ; ce qui est affiché est sujet à changement 134217728 i Traçage du traitement des couches PerlIO. Définir PERLIO_DEBUG au nom du fichier à tracer. 268435456 y Traçage de la compilation et de l'exécution de y///, tr///

Tous ces drapeaux nécessitent -DDEBUGGING lors de la compilation de l'exécutable Perl (mais voir ":opd" dans Devel::Peek ou "'mode debug'" dans re, ce qui pourrait changer cela). Consultez le fichier INSTALL dans la distribution source de Perl pour savoir comment procéder.

Si vous essayez simplement d'obtenir un affichage de chaque ligne de code Perl au fur et à mesure de son exécution, comme le fait "sh -x" pour les scripts shell, vous ne pouvez pas utiliser le commutateur -D de Perl. Faites plutôt ceci :

# Si vous avez l'utilitaire "env"
env PERLDB_OPTS="NonStop=1 AutoTrace=1 frame=2" perl -dS programme
# Syntaxe Bourne shell
$ PERLDB_OPTS="NonStop=1 AutoTrace=1 frame=2" perl -dS programme
# Syntaxe csh
% (setenv PERLDB_OPTS "NonStop=1 AutoTrace=1 frame=2"; perl -dS programme)

Consultez perldebug pour les détails et les variations.

-e ligne_de_commande
peut être utilisé pour entrer une ligne de programme. Si -e est donné, Perl ne cherchera pas de nom de fichier dans la liste des arguments. Plusieurs commandes -e peuvent être données pour construire un script de plusieurs lignes. Assurez-vous d'utiliser des points-virgules là où vous le feriez dans un programme normal.
-E ligne_de_commande
se comporte comme -e, sauf qu'il active implicitement toutes les fonctionnalités optionnelles et fonctions intégrées (dans l'unité de compilation principale). Voir feature et builtin.
-f
Désactive l'exécution de $Config{sitelib}/sitecustomize.pl au démarrage.

Perl peut être compilé de manière à essayer par défaut d'exécuter $Config{sitelib}/sitecustomize.pl au démarrage (dans un bloc BEGIN). Ceci est un crochet qui permet à l'administrateur système de personnaliser le comportement de Perl. Il peut par exemple être utilisé pour ajouter des entrées au tableau @INC afin que Perl trouve des modules dans des emplacements non standard.

Perl insère en fait le code suivant :

BEGIN {
    do { local $!; -f "$Config{sitelib}/sitecustomize.pl"; }
        && do "$Config{sitelib}/sitecustomize.pl";
}

Étant donné qu'il s'agit d'un "do" réel (et non d'un "require"), sitecustomize.pl n'a pas besoin de renvoyer une valeur vraie. Le code est exécuté dans le package "main", dans son propre périmètre lexical. Cependant, si le script échoue, $@ ne sera pas défini.

La valeur de $Config{sitelib} est également déterminée en code C et non lue dans "Config.pm", qui n'est pas chargé.

Le code est exécuté très tôt. Par exemple, toute modification apportée à @INC apparaîtra dans la sortie de `perl -V`. Bien sûr, les blocs "END" seront également exécutés très tard.

Pour déterminer au moment de l'exécution si cette capacité a été compilée dans votre perl, vous pouvez vérifier la valeur de $Config{usesitecustomize}.

-Fmotif
spécifie le motif de séparation pour "-a". Le motif peut être entouré de "//", "", ou '', sinon il sera mis entre guillemets simples. Vous ne pouvez pas utiliser d'espaces blancs littéraux ou de caractères NUL dans le motif.

-F active implicitement "-a" et "-n".

-g
définit le séparateur d'enregistrements d'entrée ($/) à undef et active ainsi le mode "slurp". En d'autres termes, cela fait que Perl lit des fichiers entiers d'un coup, au lieu ligne par ligne.

Ce drapeau est un alias plus simple pour -0777.

Mnémoniques : gobble, grab, gulp (engloutir, saisir, avaler).

-h
affiche un résumé des options.
-?
synonyme de -h : affiche un résumé des options.
-i[extension]
spécifie que les fichiers traités par la construction "<>" doivent être modifiés en place. Pour ce faire, il renomme le fichier d'entrée, ouvre le fichier de sortie avec le nom d'origine et sélectionne ce fichier de sortie comme défaut pour les instructions print(). L'extension, si fournie, est utilisée pour modifier le nom du fichier original afin de créer une copie de sauvegarde, selon les règles suivantes :

Si aucune extension n'est fournie et que votre système le prend en charge, le fichier original reste ouvert sans nom pendant que la sortie est redirigée vers un nouveau fichier portant le nom de fichier original. Lorsque perl se termine, proprement ou non, le fichier original est supprimé.

Si l'extension ne contient pas de "*", elle est ajoutée à la fin du nom de fichier actuel comme suffixe. Si l'extension contient un ou plusieurs caractères "*", chaque "*" est remplacé par le nom de fichier actuel. En termes Perl, on pourrait penser à cela comme :

($backup = $extension) =~ s/\*/$nom_fichier/g;

Cela vous permet d'ajouter un préfixe au fichier de sauvegarde, au lieu de (ou en plus de) un suffixe :

$ perl -pi'orig_*' -e 's/bar/baz/' fileA  # sauvegarde vers
                                          # 'orig_fileA'

Ou même de placer des copies de sauvegarde des fichiers originaux dans un autre répertoire (à condition que le répertoire existe déjà) :

$ perl -pi'old/*.orig' -e 's/bar/baz/' fileA  # sauvegarde vers
                                              # 'old/fileA.orig'

Ces ensembles de one-liners sont équivalents :

$ perl -pi -e 's/bar/baz/' fileA          # écrase le fichier actuel
$ perl -pi'*' -e 's/bar/baz/' fileA       # écrase le fichier actuel
$ perl -pi'.orig' -e 's/bar/baz/' fileA   # sauvegarde vers 'fileA.orig'
$ perl -pi'*.orig' -e 's/bar/baz/' fileA  # sauvegarde vers 'fileA.orig'

Depuis le shell, dire

$ perl -p -i.orig -e "s/foo/bar/; ... "

est identique à l'utilisation du programme :

#!/usr/bin/perl -pi.orig
s/foo/bar/;

qui est équivalent à

#!/usr/bin/perl
$extension = '.orig';
LINE: while (<>) {
    if ($ARGV ne $oldargv) {
        if ($extension !~ /\*/) {
            $backup = $ARGV . $extension;
        }
        else {
            ($backup = $extension) =~ s/\*/$ARGV/g;
        }
        rename($ARGV, $backup);
        open(ARGVOUT, ">$ARGV");
        select(ARGVOUT);
        $oldargv = $ARGV;
    }
    s/foo/bar/;
}
continue {
    print;  # ceci imprime dans le nom de fichier original
}
select(STDOUT);

sauf que la forme -i n'a pas besoin de comparer $ARGV à $oldargv pour savoir quand le nom du fichier a changé. Elle utilise cependant ARGVOUT pour le descripteur de fichier sélectionné. Notez que STDOUT est restauré comme descripteur de fichier de sortie par défaut après la boucle.

Comme montré ci-dessus, Perl crée le fichier de sauvegarde que le contenu soit modifié ou non. C'est donc juste une manière sophistiquée de copier des fichiers :

    $ perl -p -i'/some/file/path/*' -e 1 file1 file2 file3...
ou
    $ perl -p -i'.orig' -e 1 file1 file2 file3...

Vous pouvez utiliser "eof" sans parenthèses pour localiser la fin de chaque fichier d'entrée, au cas où vous voudriez ajouter à chaque fichier, ou réinitialiser la numérotation des lignes (voir l'exemple dans "eof" dans perlfunc).

Si, pour un fichier donné, Perl ne parvient pas à créer le fichier de sauvegarde comme spécifié dans l'extension, il ignorera ce fichier et continuera avec le suivant (s'il existe).

Pour une discussion sur les problèmes liés aux permissions de fichiers et à -i, voir "Pourquoi Perl me permet-il de supprimer des fichiers en lecture seule ? Pourquoi -i écrase-t-il des fichiers protégés ? N'est-ce pas un bug dans Perl ?" dans perlfaq5.

Vous ne pouvez pas utiliser -i pour créer des répertoires ou pour supprimer des extensions de fichiers.

Perl n'étend pas "~" dans les noms de fichiers, ce qui est une bonne chose, car certains l'utilisent pour leurs fichiers de sauvegarde :

$ perl -pi~ -e 's/foo/bar/' file1 file2 file3...

Notez que comme -i renomme ou supprime le fichier original avant de créer un nouveau fichier du même nom, les liens Unix de type symbolique et physique ne seront pas préservés.

Enfin, le commutateur -i n'entrave pas l'exécution lorsqu'aucun fichier n'est donné en ligne de commande. Dans ce cas, aucune sauvegarde n'est effectuée (le fichier original ne pouvant, bien sûr, pas être déterminé) et le traitement se déroule de STDIN vers STDOUT comme on pourrait s'y attendre.

-Irépertoire
Les répertoires spécifiés par -I sont ajoutés en tête du chemin de recherche des modules (@INC).
-l[octnum]
active le traitement automatique des fins de ligne. Il a deux effets distincts. Premièrement, il enlève automatiquement le $/ (le séparateur d'enregistrements d'entrée) lorsqu'il est utilisé avec "-n" ou "-p". Deuxièmement, il assigne « $\" » (le séparateur d'enregistrements de sortie) pour qu'il ait la valeur de octnum afin que toutes les instructions d'impression aient ce séparateur ajouté. Si octnum est omis, cela définit $\" à la valeur courante de $/. Par exemple, pour tronquer les lignes à 80 caractères : 
perl -lpe 'substr($_, 80) = ""'

Notez que l'assignation $\" = $/$ est effectuée lors du traitement du commutateur, de sorte que le séparateur d'enregistrements d'entrée peut être différent du séparateur d'enregistrements de sortie si le commutateur -l est suivi d'un commutateur -0 :

gnufind / -print0 | perl -ln0e 'print "found $_" if -p'

Cela définit $\" à une nouvelle ligne, puis $/, à un caractère nul.

-m[-]module
-M[-]module
-M[-]'module ...'
-[mM][-]module=arg[,arg]...
-mmodule exécute « use » module« (); » avant d'exécuter votre programme. Cela charge le module, mais n'appelle pas sa méthode « import », donc n'importe pas de sous-routines et n'applique pas de pragma.

-Mmodule exécute « use » module« ; » avant d'exécuter votre programme. Cela charge le module et appelle sa méthode « import », ce qui donne au module son effet par défaut, typiquement l'importation de sous-routines ou l'application d'un pragma. Vous pouvez utiliser des guillemets pour ajouter du code supplémentaire après le nom du module, par exemple, '-MMODULE qw(foo bar)'.

Si le premier caractère après -M ou -m est un trait d'union (-), alors « use » est remplacé par « no ». Cela ne fait aucune différence pour -m.

Depuis la version 5.39.8 de Perl, le commutateur « -M » et le nom du module peuvent désormais être passés en arguments de ligne de commande séparés :

perl -M MODULE ...            # comme perl -MMODULE ...
perl -M MODULE=arg1,arg2,...  # comme perl -MMODULE=arg1,arg2,...

Un peu de sucre syntaxique intégré signifie que vous pouvez également dire -mMODULE=foo,bar ou -MMODULE=foo,bar comme raccourci pour « -MMODULE qw(foo bar) ». Cela évite d'avoir à utiliser des guillemets lors de l'importation de symboles. Le code réel généré par -MMODULE=foo,bar est « use module split(/,/,q{foo,bar}) ». Notez que la forme « = » supprime la distinction entre -m et -M ; c'est-à-dire que -mMODULE=foo,bar est identique à -MMODULE=foo,bar.

Une conséquence de la formulation « split » est que -MMODULE=number n'effectue jamais de vérification de version, à moins que « MODULE::import() » ne soit lui-même configuré pour effectuer une vérification de version, ce qui pourrait arriver par exemple si MODULE hérite d'Exporter.

-n
fait en sorte que Perl suppose la boucle suivante autour de votre programme, ce qui le fait itérer sur les arguments de noms de fichiers un peu comme sed -n ou awk : 
LINE:
  while (<>) {
      ...             # votre programme va ici
  }

Notez que les lignes ne sont pas imprimées par défaut. Voir « -p » pour imprimer les lignes. Si un fichier nommé par un argument ne peut pas être ouvert pour une raison quelconque, Perl vous avertit et passe au fichier suivant.

Notez également que « <> » passe des arguments de ligne de commande à « open » dans perlfunc, qui ne les interprète pas nécessairement comme des noms de fichiers. Voir perlop pour les implications de sécurité possibles.

Voici un moyen efficace de supprimer tous les fichiers qui n'ont pas été modifiés depuis au moins une semaine :

find . -mtime +7 -print | perl -nle unlink

C'est plus rapide que d'utiliser le commutateur -exec de find car vous n'avez pas à démarrer un processus sur chaque nom de fichier trouvé (mais ce n'est pas plus rapide que d'utiliser le commutateur -delete disponible dans les versions plus récentes de find. Il souffre du bug de mauvaise gestion des nouvelles lignes dans les noms de chemins, que vous pouvez corriger en suivant l'exemple sous -0.

Les blocs « BEGIN » et « END » peuvent être utilisés pour capturer le contrôle avant ou après la boucle implicite du programme, tout comme dans awk.

-p
fait en sorte que Perl suppose la boucle suivante autour de votre programme, ce qui le fait itérer sur les arguments de noms de fichiers un peu comme sed : 
LINE:
  while (<>) {
      ...             # votre programme va ici
  } continue {
      print or die "-p destination: $!\n";
  }

Si un fichier nommé par un argument ne peut pas être ouvert pour une raison quelconque, Perl vous avertit et passe au fichier suivant. Notez que les lignes sont imprimées automatiquement. Une erreur survenant lors de l'impression est considérée comme fatale. Pour supprimer l'impression, utilisez le commutateur « -n ». Un -p remplace un commutateur -n.

Les blocs « BEGIN » et « END » peuvent être utilisés pour capturer le contrôle avant ou après la boucle implicite, tout comme dans awk.

-s
active l'analyse rudimentaire des commutateurs sur la ligne de commande après le nom du programme mais avant les arguments de nom de fichier (ou avant un argument de --). Tout commutateur trouvé là est retiré de @ARGV et définit la variable correspondante dans le programme Perl, dans le paquet principal. Le programme suivant affiche « 1 » si le programme est invoqué avec un commutateur -xyz, et « abc » s'il est invoqué avec -xyz=abc. 
#!/usr/bin/perl -s
if ($xyz) { print "$xyz\n" }

Notez qu'un commutateur comme --help crée la variable « ${-help} », ce qui n'est pas conforme à « use strict "refs" ». De plus, lors de l'utilisation de cette option sur un script avec les avertissements activés, vous pourriez recevoir de nombreux avertissements fantaisistes « utilisé une seule fois ». Pour ces raisons, l'utilisation de -s est déconseillée. Voir Getopt::Long pour une analyse des commutateurs beaucoup plus flexible.

-S
fait en sorte que Perl utilise la variable d'environnement « PATH » pour rechercher le programme, sauf si le nom du programme contient des séparateurs de chemin.

Sur certaines plateformes, cela fait également en sorte que Perl ajoute des suffixes au nom de fichier lors de sa recherche. Par exemple, sur les plateformes Win32, les suffixes « .bat » et « .cmd » sont ajoutés si une recherche du nom d'origine échoue, et si le nom ne se termine pas déjà par l'un de ces suffixes. Si votre Perl a été compilé avec « DEBUGGING » activé, l'utilisation du commutateur -Dp pour Perl montre comment la recherche progresse.

Ceci est généralement utilisé pour émuler le démarrage « #! » sur les plateformes qui ne prennent pas en charge « #! ». C'est également pratique lors du débogage d'un script qui utilise « #! », et qui est donc normalement trouvé par le mécanisme de recherche de chemin de la coquille. $PATH

Cet exemple fonctionne sur de nombreuses plateformes ayant une coquille compatible avec la coquille Bourne :

#!/usr/bin/perl
eval 'exec /usr/bin/perl -wS $0 ${1+"$@"}'
        if 0; # ^ Exécuter uniquement sous une coquille

Le système ignore la première ligne et transmet le programme à /bin/sh, qui procède à l'exécution du programme Perl comme un script de coquille. La coquille exécute la deuxième ligne comme une commande de coquille normale, et lance ainsi l'interpréteur Perl. Sur certains systèmes, $0 ne contient pas toujours le chemin d'accès complet, donc « -S » indique à Perl de rechercher le programme si nécessaire. Une fois que Perl a localisé le programme, il analyse les lignes et les ignore car la condition 'if 0' n'est jamais vraie. Si le programme sera interprété par csh, vous devrez remplacer « ${1+"$@"} » par $*, même si cela ne gère pas les espaces intégrés (et similaires) dans la liste des arguments. Pour démarrer sh plutôt que csh, certains systèmes peuvent avoir à remplacer la ligne « #! » par une ligne ne contenant qu'un deux-points, qui sera poliment ignorée par Perl. D'autres systèmes ne peuvent pas contrôler cela et nécessitent une construction totalement détournée qui fonctionnera sous n'importe quelle coquille (csh, sh, ou Perl), comme la suivante :

eval '(exit $?0)' && eval 'exec perl -wS $0 ${1+"$@"}'
& eval 'exec /usr/bin/perl -wS $0 $argv:q'
        if 0; # ^ Exécuter uniquement sous une coquille

Si le nom de fichier fourni contient des séparateurs de répertoire (et est donc un chemin absolu ou relatif), et si ce fichier n'est pas trouvé, les plateformes qui ajoutent des extensions de fichier le feront et essaieront de rechercher le fichier avec ces extensions ajoutées, une par une.

Sur les plateformes de type DOS, si le programme ne contient pas de séparateurs de répertoire, il sera d'abord recherché dans le répertoire courant avant d'être recherché dans le PATH. Sur les plateformes Unix, le programme sera recherché strictement dans le PATH.

-t
Comme « -T », mais les vérifications de falsification émettront des avertissements plutôt que des erreurs fatales. Ces avertissements peuvent maintenant être contrôlés normalement avec no warnings qw(taint).

Note : Ceci ne remplace pas « -T » ! Ceci est destiné à être utilisé *uniquement* comme aide temporaire au développement lors de la sécurisation de code hérité : pour le vrai code de production et pour le nouveau code sécurisé écrit à partir de zéro, utilisez toujours le vrai « -T ».

Ceci n'a aucun effet si votre perl a été construit sans support de falsification.

-w
affiche des avertissements sur des constructions douteuses, telles que des noms de variables mentionnés une seule fois et des variables scalaires utilisées avant d'être définies ; des sous-programmes redéfinis ; des références à des descripteurs de fichiers non définis ; des descripteurs de fichiers ouverts en lecture seule sur lesquels vous tentez d'écrire ; des valeurs utilisées comme un nombre qui ne *ressemblent* pas à des nombres ; l'utilisation d'un tableau comme s'il s'agissait d'un scalaire ; si vos sous-programmes récursent plus de 100 niveaux de profondeur ; et d'innombrables autres choses.

Ce commutateur active simplement la variable globale $^W ; normalement, le pragma lexicalement délimité "use warnings" est préférable. Vous pouvez désactiver ou transformer en erreurs fatales des avertissements spécifiques en utilisant des hooks "__WARN__", comme décrit dans perlvar et "warn" dans perlfunc. Voir également perldiag et perltrap. Une facilité d'avertissement à grain fin est également disponible si vous souhaitez manipuler des classes entières d'avertissements ; voir warnings.

-W
Active tous les avertissements, quelle que soit la directive "no warnings" ou la variable $^W. Voir warnings.
-X
Désactive tous les avertissements, quelle que soit la directive "use warnings" ou la variable $^W. Voir warnings.

Interdit dans "PERL5OPT".

-x
-xrépertoire
indique à Perl que le programme est intégré dans un bloc de texte plus grand sans rapport, comme dans un message électronique. Les déchets initiaux seront ignorés jusqu'à la première ligne qui commence par "#!" et contient la chaîne "perl". Les commutateurs significatifs sur cette ligne seront appliqués.

Toutes les références aux numéros de ligne par le programme (avertissements, erreurs, ...) traiteront la ligne "#!" comme la première ligne. Ainsi, un avertissement sur la 2ème ligne du programme, qui est sur la 100ème ligne du fichier, sera signalé comme ligne 2, et non comme ligne 100. Ceci peut être outrepassé en utilisant la directive "#line". (Voir "Plain Old Comments (Not!)" dans perlsyn)

Si un nom de répertoire est spécifié, Perl se déplacera vers ce répertoire avant d'exécuter le programme. Le commutateur -x ne contrôle que l'élimination des déchets initiaux. Le programme doit être terminé par "__END__" s'il y a des déchets finaux à ignorer ; le programme peut traiter tout ou partie des déchets finaux via le descripteur de fichier "DATA" si désiré.

Le répertoire, s'il est spécifié, doit apparaître immédiatement après le -x sans espace blanc intermédiaire.

Utilisé si "chdir" n'a pas d'argument et "HOME" n'est pas défini.

Utilisé pour exécuter des sous-processus et pour trouver le programme si "-S" est utilisé.
PERL5LIB
Une liste de répertoires dans lesquels chercher les fichiers de bibliothèque Perl avant de chercher dans la bibliothèque standard. Tous les répertoires spécifiques à l'architecture et à la version, tels que version/archname/, version/, ou archname/ sous les emplacements spécifiés sont automatiquement inclus s'ils existent, cette recherche étant effectuée au démarrage de l'interpréteur. De plus, tous les répertoires correspondant aux entrées de $Config{inc_version_list} sont ajoutés. (Ceux-ci seraient typiquement pour d'anciennes versions compatibles de perl installées dans le même arbre de répertoires.

Si PERL5LIB n'est pas défini, "PERLLIB" est utilisé. Les répertoires sont séparés (comme dans PATH) par un deux-points sur les plateformes de type Unix et par un point-virgule sur Windows (le séparateur de chemin approprié étant donné par la commande "perl -V:separateur_chemin").

Lors de l'exécution de vérifications de contamination (taint checks), soit parce que le programme s'exécutait en setuid ou setgid, soit parce que le commutateur "-T" ou "-t" a été spécifié, ni PERL5LIB ni "PERLLIB" ne sont consultés. Le programme devrait plutôt dire :

use lib "/mon/repertoire";
PERL5OPT
Options de ligne de commande (commutateurs). Les commutateurs de cette variable sont traités comme s'ils étaient sur chaque ligne de commande Perl. Seuls les commutateurs -[CDIMTUWdmtw] sont autorisés. Lors de l'exécution de vérifications de contamination (soit parce que le programme s'exécutait en setuid ou setgid, soit parce que le commutateur "-T" ou "-t" a été utilisé), cette variable est ignorée. Si PERL5OPT commence par -T, la contamination sera activée et les options suivantes ignorées. Si PERL5OPT commence par -t, la contamination sera activée, un point inscriptible sera supprimé de @INC et les options suivantes seront honorées.
PERLIO
Une liste de couches PerlIO séparées par des espaces (ou des deux-points). Si Perl est compilé pour utiliser le système PerlIO pour les E/S (par défaut), ces couches affectent les E/S de Perl.

Il est d'usage de commencer les noms de couches par un deux-points (par exemple, ":perlio") pour souligner leur similarité avec les attributs de variables. Mais le code qui analyse les chaînes de spécification de couches, qui est également utilisé pour décoder la variable d'environnement PERLIO, traite le deux-points comme un séparateur.

Une PERLIO non définie ou vide équivaut à l'ensemble de couches par défaut pour votre plateforme ; par exemple, ":unix:perlio" sur les systèmes de type Unix et ":unix:crlf" sur Windows et autres systèmes de type DOS.

La liste devient la valeur par défaut pour *toutes* les E/S de Perl. Par conséquent, seules les couches intégrées peuvent apparaître dans cette liste, car les couches externes (comme :encoding()) nécessitent des E/S pour être chargées ! Voir "open pragma" pour savoir comment ajouter des encodages externes par défaut.

Les couches qu'il est judicieux d'inclure dans la variable d'environnement PERLIO sont brièvement résumées ci-dessous. Pour plus de détails, voir PerlIO.

:crlf
Une couche qui effectue la translation CRLF en "\n", distinguant les fichiers "texte" et "binaires" à la manière de MS-DOS et des systèmes d'exploitation similaires, et qui fournit également une mise en mémoire tampon similaire à ":perlio" sur ces architectures.
:perlio
Il s'agit d'une réimplémentation de la mise en mémoire tampon de type stdio écrite sous forme de couche PerlIO. En tant que telle, elle appellera la couche qui se trouve en dessous pour ses opérations, typiquement ":unix".
:stdio
Cette couche fournit
interface PerlIO en encapsulant les appels de la bibliothèque ANSI C système "stdio". La couche fournit à la fois la mise en mémoire tampon et les E/S. Notez que la couche ":stdio" ne fait pas de traduction CRLF même si c'est le comportement normal de la plateforme. Vous aurez besoin d'une couche ":crlf" au-dessus pour cela.
:unix
Couche de bas niveau qui appelle "read", "write", "lseek", etc.

L'ensemble par défaut de couches devrait donner des résultats acceptables sur toutes les plateformes.

Pour les plateformes Unix, ce sera l'équivalent de ":unix:perlio" ou ":stdio". La configuration est établie pour préférer l'implémentation ":stdio" si la bibliothèque du système fournit un accès rapide au tampon (peu courant sur les architectures modernes) ; sinon, elle utilise l'implémentation ":unix:perlio".

Sur Win32, la valeur par défaut dans cette version (5.30) est ":unix:crlf". Le ":stdio" de Win32 présente un certain nombre de bugs/mauvaises fonctionnalités pour les E/S Perl qui dépendent quelque peu de la version et du fournisseur du compilateur C. L'utilisation de notre propre couche ":crlf" comme tampon évite ces problèmes et rend les choses plus uniformes.

Cette version (5.30) utilise ":unix" comme couche de base sur Win32, et utilise donc toujours les routines de descripteur de fichier numérique du compilateur C.

La variable d'environnement PERLIO est complètement ignorée lorsque Perl est exécuté en mode taint.

PERLIO_DEBUG
Si elle est définie avec le nom d'un fichier ou d'un périphérique lorsque Perl est exécuté avec le commutateur de ligne de commande -Di, la journalisation de certaines opérations du sous-système PerlIO sera redirigée vers le fichier spécifié au lieu d'aller sur stderr, qui est la valeur par défaut. Le fichier est ouvert en mode ajout. Les utilisations typiques sont sous Unix : 
% env PERLIO_DEBUG=/tmp/perlio.log perl -Di script ...

et sous Win32, l'équivalent approximatif :

> set PERLIO_DEBUG=CON
perl -Di script ...

Cette fonctionnalité est désactivée pour les scripts setuid, pour les scripts exécutés avec "-T", et pour les scripts exécutés sur un Perl compilé sans le support "-DDEBUGGING".

PERLLIB
Une liste de répertoires dans lesquels rechercher les fichiers de bibliothèque Perl avant de rechercher dans la bibliothèque standard. Si "PERL5LIB" est défini, PERLLIB n'est pas utilisé.

La variable d'environnement PERLLIB est complètement ignorée lorsque Perl est exécuté en mode taint.

PERL5DB
La commande utilisée pour charger le code du débogueur. La valeur par défaut est : 
BEGIN { require "perl5db.pl" }

La variable d'environnement PERL5DB n'est utilisée que lorsque Perl est démarré avec un simple commutateur "-d".

PERL5DB_THREADED
Si elle est définie sur une valeur vraie, indique au débogueur que le code débogué utilise des threads.
PERL5SHELL (spécifique au port Win32)
Sur les ports Win32 uniquement, peut être défini sur un shell alternatif que Perl doit utiliser en interne pour exécuter des commandes entre guillemets inversés (backticks) ou system(). La valeur par défaut est "cmd.exe /x/d/c" sur WindowsNT et "command.com /c" sur Windows95. La valeur est considérée comme séparée par des espaces. Faites précéder tout caractère qui doit être protégé, comme un espace ou une barre oblique inverse, d'une autre barre oblique inverse.

Notez que Perl n'utilise pas COMSPEC à cette fin car COMSPEC présente un degré élevé de variabilité parmi les utilisateurs, ce qui pose des problèmes de portabilité. De plus, Perl peut utiliser un shell qui n'est peut-être pas adapté à une utilisation interactive, et définir COMSPEC sur un tel shell peut interférer avec le bon fonctionnement d'autres programmes (qui regardent généralement dans COMSPEC pour trouver un shell adapté à une utilisation interactive).

Avant Perl 5.10.0 et 5.8.8, PERL5SHELL n'était pas vérifié en mode taint lors de l'exécution de commandes externes. Il est recommandé de définir (ou de supprimer) explicitement $ENV{PERL5SHELL} lors de l'exécution en mode taint sous Windows.

PERL_ALLOW_NON_IFS_LSP (spécifique au port Win32)
Défini sur 1 pour autoriser l'utilisation de LSPs (Layered Service Providers) non compatibles avec IFS. Perl recherche normalement un LSP compatible IFS car cela est requis pour son émulation de sockets Windows en tant que descripteurs de fichiers réels. Cependant, cela peut poser des problèmes si vous avez un pare-feu tel que McAfee Guardian, qui exige que toutes les applications utilisent son LSP mais qui n'est pas compatible IFS, car clairement Perl évitera normalement d'utiliser un tel LSP.

Définir cette variable d'environnement sur 1 signifie que Perl utilisera simplement le premier LSP approprié énuméré dans le catalogue, ce qui satisfait McAfee Guardian - et dans ce cas particulier, Perl fonctionne également car le LSP de McAfee Guardian fait effectivement d'autres choses qui permettent aux applications nécessitant une compatibilité IFS de fonctionner.

PERL_DEBUG_MSTATS
Pertinent uniquement si Perl est compilé avec le "malloc" inclus dans la distribution Perl ; c'est-à-dire si "perl -V:d_mymalloc" est "define".

Si elle est définie, cela déversera des statistiques de mémoire après l'exécution. Si elle est définie sur un entier supérieur à un, cela déversera également des statistiques de mémoire après la compilation.

PERL_DESTRUCT_LEVEL
Contrôle le comportement de la destruction globale des objets et autres références. Voir "PERL_DESTRUCT_LEVEL" dans perlhacktips pour plus d'informations.
PERL_DL_NONLAZY
Défini sur "1" pour que Perl résolve tous les symboles indéfinis lors du chargement d'une bibliothèque dynamique. Le comportement par défaut consiste à résoudre les symboles lorsqu'ils sont utilisés. La définition de cette variable est utile lors des tests d'extensions, car elle garantit que vous obtenez une erreur pour les noms de fonctions mal orthographiés, même si la suite de tests ne les appelle pas.
PERL_ENCODING
Si vous utilisez le pragmatisme "use encoding" sans nom d'encodage explicite, la variable d'environnement PERL_ENCODING est consultée pour obtenir un nom d'encodage.
PERL_HASH_SEED
(Depuis Perl 5.8.1, nouvelles sémantiques dans Perl 5.18.0) Utilisé pour remplacer la randomisation de la fonction de hachage interne de Perl. La valeur est exprimée en hexadécimal, et peut inclure un 0x de préfixe. Les motifs tronqués sont traités comme s'ils étaient suffixés de suffisamment de 0's si nécessaire.

Si l'option est fournie, et que "PERL_PERTURB_KEYS" N'EST PAS définie, alors une valeur de '0' implique "PERL_PERTURB_KEYS=0"/"PERL_PERTURB_KEYS=NO" et toute autre valeur implique "PERL_PERTURB_KEYS=2"/"PERL_PERTURB_KEYS=DETERMINISTIC". Voir la documentation de PERL_PERTURB_KEYS pour des avertissements importants concernant le mode "DETERMINISTIC".

VEUILLEZ NOTER : La graine de hachage est une information sensible. Les hachages sont randomisés pour se protéger contre les attaques locales et distantes contre le code Perl. En définissant manuellement une graine, cette protection peut être partiellement ou totalement perdue.

Voir "Algorithmic Complexity Attacks" dans perlsec, "PERL_PERTURB_KEYS", et "PERL_HASH_SEED_DEBUG" pour plus d'informations.

PERL_PERTURB_KEYS
(Depuis Perl 5.18.0) Défini sur "0" ou "NO", le parcours des clés sera répétable d'une exécution à l'autre pour la même "PERL_HASH_SEED". L'insertion dans un hachage ne changera pas l'ordre, sauf pour fournir plus d'espace dans le hachage. Lorsqu'il est combiné avec la définition de PERL_HASH_SEED, ce mode est aussi proche du comportement pré-5.18 que possible.

Lorsqu'il est défini sur "1" ou "RANDOM", le parcours des clés sera randomisé. Chaque fois qu'un hachage est inséré, l'ordre des clés changera de manière aléatoire. L'ordre peut ne pas être répétable lors d'une exécution ultérieure du programme, même si PERL_HASH_SEED a été spécifié.

Lorsqu'il est défini sur "2" ou "DETERMINISTIC", l'insertion de clés dans un hachage entraînera un changement d'ordre des clés, mais d'une manière qui est répétable d'une exécution de programme à l'autre, à condition que la même graine de hachage soit utilisée, et que le code n'effectue lui-même aucune opération non déterministe et fournisse également exactement le même contexte d'environnement. L'ajout ou la suppression d'une variable d'environnement peut et changera probablement l'ordre des clés. Si une partie du code construit un hachage utilisant des clés non déterministes, par exemple un hachage indexé par la forme chaîne de caractères d'une référence, ou l'adresse des objets qu'il contient, alors cela peut et changera probablement l'ordre des clés de *tous* les hachages du processus. Pour fonctionner correctement, ce paramètre DOIT être couplé avec PERL_HASH_SEED pour produire des résultats déterministes, et en fait, si vous définissez explicitement "PERL_HASH_SEED", vous n'avez pas besoin de définir ceci également, il sera automatiquement défini sur ce mode.

NOTE : L'utilisation de cette option est considérée comme non sécurisée et est destinée uniquement au débogage du comportement non déterministe de la fonction de hachage de Perl. Ne l'utilisez pas en production.

Voir "Algorithmic Complexity Attacks" dans perlsec et "PERL_HASH_SEED" et "PERL_HASH_SEED_DEBUG" pour plus d'informations. Vous pouvez obtenir et définir le masque de parcours de clés pour un hachage spécifique en utilisant la fonction hash_traversal_mask() de Hash::Util.

PERL_HASH_SEED_DEBUG
(Depuis Perl 5.8.1.) Défini sur "1" pour afficher (sur STDERR) des informations sur la fonction de hachage

ENVIRONNEMENT

Perl's behavior can be modified by a number of environment variables. The behavior of some of these is influenced by how Perl was compiled.

PERL_HASH_SEED
Available in Perls 5.8.0 and later. When set to a non-negative integer, this value is used to seed the hash function's random number generator. This allows you to deterministically reproduce the hash seed and hash traversal randomization for a given run. This is intended to aid in debugging nondeterministic behavior caused by hash randomization.

If this variable is not set, Perl attempts to get a good seed from the operating system. If it is set to "0", then randomization is disabled (using a fixed seed).

Note that any information about the hash function, especially the hash seed is sensitive information: by knowing it, one can craft a denial-of-service attack against Perl code, even remotely; see "Algorithmic Complexity Attacks" in perlsec for more information. Do not disclose the hash seed to people who don't need to know it. See also hash_seed() and hash_traversal_mask().

An example output might be:

HASH_FUNCTION = ONE_AT_A_TIME_HARD HASH_SEED = 0x652e9b9349a7a032 PERTURB_KEYS = 1 (RANDOM)
PERL_PERTURB_KEYS
Available in Perls 5.8.0 and later. If set to a non-zero value, Perl will randomize the order in which keys are traversed in hashes. This, combined with the hash function randomization, is intended to aid in debugging nondeterministic behavior caused by hash randomization.

If this variable is not set, Perl uses its default behavior, which is to traverse keys in a pseudo-random order based on the hash function and hash seed. If this variable is set to "0", then key traversal randomization is disabled.

This variable is less sensitive than PERL_HASH_SEED. While it is desirable that hash traversal be randomized, it's not as critical as the seed itself.

An example output might be:

HASH_FUNCTION = ONE_AT_A_TIME_HARD HASH_SEED = 0x652e9b9349a7a032 PERTURB_KEYS = 1 (RANDOM)
PERL_HASH_SPEC
Available in Perls 5.8.0 and later. Use this to specify which hash function to use and what type of key traversal randomization is in effect at the beginning of execution. This, combined with "PERL_HASH_SEED" and "PERL_PERTURB_KEYS" is intended to aid in debugging nondeterministic behaviour caused by hash randomization.

Note that any information about the hash function, especially the hash seed is sensitive information: by knowing it, one can craft a denial-of-service attack against Perl code, even remotely; see "Algorithmic Complexity Attacks" in perlsec for more information. Do not disclose the hash seed to people who don't need to know it. See also hash_seed() and hash_traversal_mask().

An example output might be:

HASH_FUNCTION = ONE_AT_A_TIME_HARD HASH_SEED = 0x652e9b9349a7a032 PERTURB_KEYS = 1 (RANDOM)
PERL_MEM_LOG
If your Perl was configured with -Accflags=-DPERL_MEM_LOG, setting the environment variable "PERL_MEM_LOG" enables logging debug messages. The value has the form "<number>[m][s][t]", where "number" is the file descriptor number you want to write to (2 is default), and the combination of letters specifies that you want information about (m)emory and/or (s)v, optionally with (t)imestamps. For example, "PERL_MEM_LOG=1mst" logs all information to stdout. You can write to other opened file descriptors in a variety of ways: 
$ 3>foo3 PERL_MEM_LOG=3m perl ...
PERL_ROOT (specific to the VMS port)
A translation-concealed rooted logical name that contains Perl and the logical device for the @INC path on VMS only. Other logical names that affect Perl on VMS include PERLSHR, PERL_ENV_TABLES, and SYS$TIMEZONE_DIFFERENTIAL, but are optional and discussed further in perlvms and in README.vms in the Perl source distribution.
PERL_SIGNALS
Available in Perls 5.8.1 and later. If set to "unsafe", the pre-Perl-5.8.0 signal behaviour (which is immediate but unsafe) is restored. If set to "safe", then safe (but deferred) signals are used. See "Deferred Signals (Safe Signals)" in perlipc.
PERL_UNICODE
Equivalent to the -C command-line switch. Note that this is not a boolean variable. Setting this to "1" is not the right way to "enable Unicode" (whatever that would mean). You can use "0" to "disable Unicode", though (or alternatively unset PERL_UNICODE in your shell before starting Perl). See the description of the -C switch for more information.
PERL_USE_UNSAFE_INC
If perl has been configured to not have the current directory in @INC by default, this variable can be set to "1" to reinstate it. It's primarily intended for use while building and testing modules that have not been updated to deal with "." not being in @INC and should not be set in the environment for day-to-day use.
SYS$LOGIN (specific to the VMS port)
Used if chdir has no argument and "HOME" and "LOGDIR" are not set.
PERL_INTERNAL_RAND_SEED
Set to a non-negative integer to seed the random number generator used internally by perl for a variety of purposes.

Ignored if perl is run setuid or setgid. Used only for some limited startup randomization (hash keys) if "-T" or "-t" perl is started with tainting enabled.

Perl may be built to ignore this variable.

PERL_RAND_SEED
When set to an integer value this value will be used to seed the perl internal random number generator used for rand() when it is used without an explicit srand() call or for when an explicit no-argument srand() call is made.

Normally calling rand() prior to calling srand() or calling srand() explicitly with no arguments should result in the random number generator using "best efforts" to seed the generator state with a relatively high quality random seed. When this environment variable is set then the seeds used will be deterministically computed from the value provided in the env var in such a way that the application process and any forks or threads should continue to have their own unique seed but that the program may be run twice with identical results as far as rand() goes (assuming all else is equal).

PERL_RAND_SEED is intended for performance measurements and debugging and is explicitly NOT intended for stable testing. The only guarantee is that a specific perl executable will produce the same results twice in a row, there is no guarantee that the results will be the same between perl releases or on different architectures.

Ignored if perl is run setuid or setgid.

Perl also has environment variables that control how Perl handles data specific to particular natural languages; see perllocale.

Perl and its various modules and components, including its test frameworks, may sometimes make use of certain other environment variables. Some of these are specific to a particular platform. Please consult the appropriate module documentation and any documentation for your platform (like perlsolaris, perllinux, perlmacosx, perlwin32, etc) for variables peculiar to those specific situations.

Perl makes all environment variables available to the program being executed, and passes these along to any child processes it starts. However, programs running setuid would do well to execute the following lines before doing anything else, just to keep people honest:

$ENV{PATH}  = "/bin:/usr/bin";    # or whatever you need
$ENV{SHELL} = "/bin/sh" if exists $ENV{SHELL};
delete @ENV{qw(IFS CDPATH ENV BASH_ENV)};

ORDRE D'APPLICATION

Certaines options, notamment "-I", "-M", "PERL5LIB" et "PERL5OPT" peuvent interagir, et l'ordre dans lequel elles sont appliquées est important.

Notez que cette section ne documente pas ce qui se passe *réellement* à l'intérieur de l'interpréteur Perl, elle documente ce qui se passe *effectivement*.

-I
L'effet de plusieurs options "-I" est de les "unshift" sur @INC de droite à gauche. Donc par exemple : 
perl -I 1 -I 2 -I 3

ajoutera d'abord 3 au début de @INC, puis ajoutera 2, et enfin ajoutera 1. Le résultat est que @INC commence par :

qw(1 2 3)
-M
Plusieurs options "-M" sont traitées de gauche à droite. Donc ceci : 
perl -Mlib=1 -Mlib=2 -Mlib=3

utilisera d'abord le pragma lib pour ajouter 1 à @INC, puis ajoutera 2, puis ajoutera 3, résultant en un @INC qui commence par :

qw(3 2 1)
la variable d'environnement PERL5LIB
Celle-ci contient une liste de répertoires, séparés par des deux-points. Toute la liste est ajoutée au début de @INC en une seule fois. Ceci : 
PERL5LIB=1:2:3 perl

résultera en un @INC qui commence par :

qw(1 2 3)
combinaisons de -I, -M et PERL5LIB
"PERL5LIB" est appliquée en premier, puis tous les arguments "-I", puis tous les arguments "-M". Ceci : 
PERL5LIB=e1:e2 perl -I i1 -Mlib=m1 -I i2 -Mlib=m2

résultera en un @INC qui commence par :

qw(m2 m1 i1 i2 e1 e2)
la variable d'environnement PERL5OPT
Celle-ci contient une liste de commutateurs séparés par des espaces. Nous ne considérons que les effets de "-M" et "-I" dans cette section.

Après le traitement normal des commutateurs "-I" de la ligne de commande, tous les commutateurs "-I" dans "PERL5OPT" sont extraits. Ils sont traités de gauche à droite au lieu de droite à gauche. Notez également que si l'espace est autorisé entre un "-I" et son répertoire sur la ligne de commande, il n'est pas autorisé dans "PERL5OPT".

Après le traitement normal des commutateurs "-M" de la ligne de commande, tous les commutateurs "-M" dans "PERL5OPT" sont extraits. Ils sont traités de gauche à droite, *c'est-à-dire* de la même manière que ceux de la ligne de commande.

Un exemple peut éclaircir cela :

export PERL5OPT="-Mlib=optm1 -Iopti1 -Mlib=optm2 -Iopti2"
export PERL5LIB=e1:e2
perl -I i1 -Mlib=m1 -I i2 -Mlib=m2

résultera en un @INC qui commence par :

qw(
    optm2
    optm1
    m2
    m1
    opti2
    opti1
