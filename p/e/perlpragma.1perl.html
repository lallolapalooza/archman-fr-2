NOM

perlpragma - comment écrire un pragma utilisateur

DESCRIPTION

Un pragma est un module qui influence un aspect du comportement de Perl au moment de la compilation ou de l'exécution, tel que "strict" ou "warnings". Avec Perl 5.10, vous n'êtes plus limité aux pragmas intégrés ; vous pouvez désormais créer des pragmas utilisateurs qui modifient le comportement des fonctions utilisateur dans une portée lexicale.

Un exemple de base

Par exemple, disons que vous devez créer une classe implémentant des opérateurs mathématiques surchargés, et que vous souhaitez fournir votre propre pragma qui fonctionne de manière similaire à "use integer;". Vous aimeriez que ce code

use MyMaths;
my $l = MyMaths->new(1.2);
my $r = MyMaths->new(3.4);
print "A: ", $l + $r, "\n";
use myint;
print "B: ", $l + $r, "\n";
{
    no myint;
    print "C: ", $l + $r, "\n";
}
print "D: ", $l + $r, "\n";
no myint;
print "E: ", $l + $r, "\n";

produise la sortie suivante

A: 4.6
B: 4
C: 4.6
D: 4
E: 4.6

c'est-à-dire, là où "use myint;" est en vigueur, les opérations d'addition sont forcées à l'entier, alors que par défaut elles ne le sont pas, le comportement par défaut étant restauré via "no myint;".

L'implémentation minimale du paquet "MyMaths" serait quelque chose comme ceci :

package MyMaths;
use v5.36;
use myint();
use overload '+' => sub {
    my ($l, $r) = @_;
    # Passe 1 pour vérifier un niveau d'appel à partir d'ici
    if (myint::in_effect(1)) {
        int($$l) + int($$r);
    } else {
        $$l + $$r;
    }
};
sub new {
    my ($class, $value) = @_;
    bless \$value, $class;
}
1;

Notez comment nous chargeons le pragma utilisateur "myint" avec une liste vide "()" pour empêcher l'appel de son "import".

L'interaction avec la compilation de Perl se fait à l'intérieur du paquet "myint" :

package myint;
use v5.36;
sub import {
    $^H{"myint/in_effect"} = 1;
}
sub unimport {
    $^H{"myint/in_effect"} = 0;
}
sub in_effect {
    my $level = shift // 0;
    my $hinthash = (caller($level))[10];
    return $hinthash->{"myint/in_effect"};
}
1;

Comme les pragmas sont implémentés comme des modules, comme tout autre module, "use myint;" devient

BEGIN {
    require myint;
    myint->import();
}

et "no myint;" est

BEGIN {
    require myint;
    myint->unimport();
}

Par conséquent, les routines "import" et "unimport" sont appelées au moment de la compilation pour le code de l'utilisateur.

Les pragmas utilisateurs stockent leur état en écrivant dans la table de hachage magique "%^H", d'où ces deux routines la manipulent. L'information d'état dans "%^H" est stockée dans l'arbre d'options (optree), et peut être récupérée en lecture seule à l'exécution avec caller(), à l'indice 10 de la liste des résultats retournés. Dans le pragma d'exemple, la récupération est encapsulée dans la routine in_effect(), qui prend comme paramètre le nombre de cadres d'appel à remonter pour trouver la valeur du pragma dans le script utilisateur. Cela utilise caller() pour déterminer la valeur de $^H{"myint/in_effect"} lorsque chaque ligne du script utilisateur a été appelée, et donc fournir les sémantiques correctes dans la sous-routine implémentant l'addition surchargée.

Nommage des clés

Il n'y a qu'une seule "%^H", mais un nombre arbitraire de modules qui veulent utiliser sa sémantique de portée. Pour éviter de se marcher sur les pieds, ils doivent s'assurer d'utiliser des clés différentes dans la table de hachage. Il est donc conventionnel qu'un module n'utilise que des clés commençant par le nom du module (le nom de son paquet principal) et un caractère "/". Après ce préfixe identifiant le module, le reste de la clé est entièrement à la discrétion du module : il peut inclure n'importe quels caractères. Par exemple, un module "Foo::Bar" devrait utiliser des clés comme "Foo::Bar/baz" et "Foo::Bar/$%/_!". Les modules suivant cette convention interagissent tous bien entre eux.

Le cœur de Perl utilise une poignée de clés dans "%^H" qui ne suivent pas cette convention, car elles sont antérieures. Les clés qui suivent la convention n'entreront pas en conflit avec les clés historiques du cœur.

Détails d'implémentation

L'arbre d'options (optree) est partagé entre les threads. Cela signifie qu'il est possible que l'optree survive au thread particulier (et donc à l'instance de l'interpréteur) qui l'a créé, de sorte que les vrais scalaires Perl ne peuvent pas être stockés dans l'optree. Au lieu de cela, une forme compacte est utilisée, qui ne peut stocker que des valeurs entières (signées et non signées), des chaînes ou "undef" - les références et les valeurs flottantes sont converties en chaînes. Si vous avez besoin de stocker plusieurs valeurs ou des structures complexes, vous devriez les sérialiser, par exemple avec "pack". La suppression d'une clé de table de hachage de "%^H" est enregistrée, et comme toujours, peut être distinguée de l'existence d'une clé avec la valeur "undef" avec "exists".

Ne tentez pas de stocker des références à des structures de données sous forme d'entiers qui sont récupérées via "caller" et reconverties, car ce ne serait pas thread-safe. Les accès se feraient à la structure sans verrouillage (ce qui n'est pas sûr pour les scalaires de Perl), et soit la structure fuirait, soit elle devrait être libérée lorsque son thread créateur se termine, ce qui peut être avant que l'optree qui y fait référence ne soit supprimé, si d'autres threads lui survivent.
