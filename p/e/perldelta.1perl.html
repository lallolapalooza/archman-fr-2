PERLDELTA(1perl) Guide de référence du programmeur Perl PERLDELTA(1perl)

NOM

perldelta - ce qui est nouveau pour la version Perl v5.42.0

DESCRIPTION

Ce document décrit les différences entre la version 5.42.0 et la version 5.40.0.

Améliorations du noyau

Plus de sous CORE::

"chdir" a été ajouté comme sous-routine dans l'espace de noms "CORE::".

Auparavant, un code comme &CORE::chdir($dir) ou my $ref = \&CORE::chdir; $ref->($dir) provoquait une erreur indiquant que "&CORE::chdir ne peut pas être appelé" "directement". Ces cas sont maintenant entièrement pris en charge.

Nouveau pragma "source::encoding"

Ceci vous permet de déclarer que la partie d'un programme pour le reste de la portée lexicale de ce pragma est encodée entièrement en ASCII (pour "use source::encoding 'ascii'") ou si UTF-8 est également autorisé (pour "use source::encoding 'utf8'"). Aucun autre encodage n'est accepté. La deuxième forme est entièrement équivalente à "use utf8", et peut être utilisée indifféremment avec celle-ci.

Le but de ce pragma est de détecter tôt les cas où vous avez oublié de spécifier "use utf8".

"use source::encoding 'ascii'" est automatiquement activé dans la portée lexicale de "use v5.41.0" ou une version supérieure.

"no source::encoding" désactive toutes ces vérifications pour le reste de sa portée lexicale. Le sens des caractères non-ASCII est alors indéfini.

Nouveau attribut ":writer" sur les variables de champ

Les classes définies en utilisant "use feature 'class'" peuvent maintenant créer automatiquement des accesseurs d'écriture pour les champs scalaires, en utilisant l'attribut ":writer", de manière similaire à la façon dont ":reader" crée déjà des accesseurs de lecture.

class Point {
    field $x :reader :writer :param;
    field $y :reader :writer :param;
}
my $p = Point->new( x => 20, y => 40 );
$p->set_x(60);

Nouveaux opérateurs "any" et "all"

Deux nouvelles fonctionnalités expérimentales ont été ajoutées, introduisant les opérateurs de traitement de liste "any" et "all".

use v5.42;
use feature 'keyword_all';
no warnings 'experimental::keyword_all';
my @numbers = ...
if ( all { $_ % 2 == 0 } @numbers ) {
    say "Tous les nombres sont pairs";
}

Ces mots-clés fonctionnent de manière similaire à "grep", sauf qu'ils ne retournent que vrai ou faux, vérifiant si un (ou tous) des éléments de la liste font que le bloc de test renvoie vrai. De ce fait, ils peuvent court-circuiter, évitant d'avoir à tester d'autres éléments si un élément donné détermine le résultat final.

Ils sont inspirés des fonctions du même nom dans le module List::Util, sauf qu'ils sont implémentés comme des opérateurs de base directs, et donc plus rapides, et ne produisent pas de cadre de pile d'appels de sous-routine supplémentaire pour l'invocation du bloc de code.

Les indicateurs de fonctionnalité activant ces mots-clés ont été nommés "keyword_any" et "keyword_all" pour éviter la confusion avec la capacité du module "feature" à faire référence à toutes ses fonctionnalités en utilisant la balise d'export ":all". [GH #23104 https://github.com/Perl/perl5/issues/23104]

Les indicateurs d'avertissement expérimentaux associés sont par conséquent nommés "experimental::keyword_any" et "experimental::keyword_all".

L'apostrophe comme séparateur de nom global peut être désactivé

Ceci a été déprécié dans Perl 5.38 et supprimé comme prévu dans Perl 5.41.3, mais après discussion a été rétabli par défaut.

Ceci peut être contrôlé avec la fonctionnalité "apostrophe_as_package_separator" qui est activée par défaut, mais désactivée à partir du bundle de fonctionnalités 5.41 et suivantes.

Si vous souhaitez désactiver son utilisation dans votre propre code, vous pouvez explicitement désactiver la fonctionnalité :

no feature "apostrophe_as_package_separator";

Notez que la désactivation de cette fonctionnalité empêche seulement l'utilisation de l'apostrophe comme séparateur de paquet dans le code ; les références symboliques traitent toujours "'" comme "::" lorsque la fonctionnalité est désactivée :

my $symref = "My'Module'Var";
# fonctionnalités par défaut
my $x = $My'Module'Var; # OK
no feature "apostrophe_as_package_separator";
no strict "refs";
my $y = $$symref;       # comme $My::Module::Var
my $z = $My'Module'Var; # erreur de syntaxe

[GH #22644 https://github.com/Perl/perl5/issues/22644]

Declaration lexicale de methode utilisant "my method"

Comme "sub" depuis la version Perl 5.18, "method" peut maintenant être précédé du mot-clé "my". Ceci déclare une sous-routine qui a une visibilité lexicale, plutôt que de paquet. Voir perlclass pour plus de détails.

Operateur d'invocation lexicale de methode "->&"

Parallèlement à la capacité de déclarer des méthodes lexicalement, cette version permet également d'invoquer une sous-routine lexicale comme si c'était une méthode, en contournant la résolution de méthode habituelle basée sur le nom.

Combinées avec la déclaration lexicale de méthode, ces deux nouvelles capacités créent l'effet de méthodes privées.

Opérateurs Switch et Smart Match conservés, derrière une fonctionnalité

La fonctionnalité "switch" et l'opérateur smartmatch, "~~", ont été introduits dans la version v5.10. Leur comportement a été significativement modifié dans la version v5.10.1. Lorsque le système "experiment" a été ajouté dans la version v5.18.0, switch et smartmatch ont été déclarés expérimentalement rétroactivement. Au fil des ans, des propositions pour corriger ou compléter ces fonctionnalités ont vu le jour et disparu.

Ils ont été dépréciés dans Perl v5.38.0 et leur suppression était prévue pour Perl v5.42.0. Après discussion approfondie, leur suppression a été reportée indéfiniment. Leur utilisation ne produit plus d'avertissement de dépréciation.

Switch nécessite toujours la fonctionnalité "switch", qui est activée par défaut pour les bundles de fonctionnalités de v5.9.5 à v5.34. Switch reste désactivé dans les bundles de fonctionnalités 5.35 et suivants, mais peut être activé séparément :

# pas de switch ici
use v5.10;
# switch ici
use v5.36;
# pas de switch ici
use feature "switch";
# switch ici

Smart match nécessite maintenant la fonctionnalité "smartmatch", qui est activée par défaut et incluse dans tous les bundles de fonctionnalités jusqu'à la version 5.40. Elle est désactivée pour le bundle de fonctionnalités 5.41 et suivantes, mais peut être activée séparément :

# smartmatch ici
use v5.41;
# pas de smartmatch ici
use feature "smartmatch";
# smartmatch ici

[GH #22752 https://github.com/Perl/perl5/issues/22752]

Unicode 16.0 supporté

Perl supporte désormais Unicode 16.0 https://www.unicode.org/versions/Unicode16.0.0/ y compris les changements introduits dans la version 15.1 https://www.unicode.org/versions/Unicode15.1.0/.

Opérateur d'affectation d'xor logique "^^="

Perl 5.40.0 a introduit l'opérateur exclusif ou de précédence moyenne logique "^^". Il n'a pas été remarqué à l'époque que la variante d'affectation "^^=" manquait également. Elle est maintenant ajoutée.

Sécurité

[CVE-2024-56406] Vulnérabilité de débordement de tampon dans le tas avec tr//

Une vulnérabilité de débordement de tampon dans le tas a été découverte dans Perl.

Lorsque des octets non ASCII sont présents sur le côté gauche de l'opérateur "tr", S_do_trans_invmap() peut déborder le pointeur de destination "d".

$ perl -e '$_ = "\x{FF}" x 1000000; tr/\xFF/\x{100}/;'
Segmentation fault (core dumped)

On pense que cette vulnérabilité peut permettre des attaques par déni de service ou d'exécution de code arbitraire sur les plateformes qui manquent de défenses suffisantes.

Ce problème a été découvert par Nathan Mills et assigné [CVE-2024-56406 https://lists.security.metacpan.org/cve-announce/msg/28708725/] par le CPAN Security Group https://security.metacpan.org/.

Le correctif pour résoudre ce problème (87f42aa0e0096e9a346c9672aa3a0bd3bef8c1dd https://github.com/Perl/perl5/commit/87f42aa0e0096e9a346c9672aa3a0bd3bef8c1dd) est applicable à tous les Perl vulnérables, y compris ceux qui ne sont plus pris en charge.

[CVE-2025-40909] Les threads Perl ont une condition de concurrence du répertoire de travail où les opérations de fichier peuvent cibler des chemins involontaires

Le clonage de threads Perl présentait une condition de concurrence du répertoire de travail où les opérations de fichier pouvaient cibler des chemins involontaires. Perl 5.42 ne fera plus de `chdir` pour chaque handle.

Ce problème a été découvert par Vincent Lefèvre via [GH #23010 https://github.com/Perl/perl5/issues/23010] et assigné [CVE-2025-40909 https://lists.security.metacpan.org/cve-announce/msg/30017499/] par le CPAN Security Group https://security.metacpan.org/.

Des corrections ont été fournies via [GH #23019 https://github.com/Perl/perl5/pull/23019] et [GH #23361 https://github.com/Perl/perl5/pull/23361].

Changements incompatibles

Suppression des références aux fonctions contenant pour les fonctions sans eval

Perl 5.40 a réintroduit des références inconditionnelles des fonctions à leurs fonctions contenant pour corriger un bug introduit dans Perl 5.18 qui cassait le comportement spécial de "eval EXPR" dans le package "DB" qui est utilisé par le débogueur.

Dans certains cas, ce changement a entraîné des chaînes de références circulaires entre les fermetures et d'autres références existantes, entraînant des fuites de mémoire.

Ce changement a été annulé, corrigeant [GH #22547 https://github.com/Perl/perl5/issues/22547] mais cassant à nouveau [GH #19370 https://github.com/Perl/perl5/issues/19370].

Cela signifie que les boucles de référence ne se produiront pas, et que les variables lexicales et les fonctions des fonctions englobantes peuvent ne pas être visibles dans le débogueur.

Notez que l'appel de "eval EXPR" dans une fonction provoque inconditionnellement une référence d'une fonction à ses fonctions englobantes, comme cela a toujours été le cas.

Améliorations des performances

  • Les chaînes en folded constant sont maintenant partageables via le mécanisme de Copy-on-Write. [GH #22163 https://github.com/Perl/perl5/pull/22163]

    Le code suivant aurait auparavant alloué onze tampons de chaînes, chacun contenant un million de "A" :

    my @scalars; push @scalars, ("A" x 1_000_000) for 0..9;

    Maintenant, un seul tampon est alloué et partagé entre un CONST OP et les dix éléments scalaires de @scalars.

    Notez que tout code utilisant ce type de constante pour simuler des fuites de mémoire (peut-être dans des fichiers de test) doit maintenant permuter la chaîne pour déclencher une copie de chaîne et l'allocation de tampons séparés. Par exemple, "("A" x 1_000_000).time" pourrait être une modification mineure appropriée.

  • "tr///" s'exécute désormais à la même vitesse indépendamment de la représentation interne de son opérande, tant que les seuls caractères traduits sont dans la plage ASCII, par exemple "tr/A-Z/a-z/". Auparavant, si l'encodage interne était UTF-8, une implémentation plus lente et plus générale était utilisée.
  • Le code qui utilise la fonction "indexed" du module intégré pour générer une liste de paires index/valeur à partir d'un tableau ou d'une liste qui est ensuite passée à une "foreach" à deux variables pour les décompresser à nouveau est maintenant optimisé pour être plus efficace. 
    my @array = (...);
foreach my ($idx, $val) (builtin::indexed @array) {
    ...
}

    foreach my ($idx, $val) (builtin::indexed LIST...) {
    ...
}

    En particulier, une liste temporaire deux fois plus grande que l'originale n'est plus générée. Au lieu de cela, la boucle itère directement sur le tableau ou la liste d'origine sur place, de la même manière que "foreach (@array)" ou "foreach (LIST)" le feraient.

  • L'optimiseur "peephole" reconnaît les motifs "substr" à décalage zéro suivants et les remplace par un nouvel opérateur dédié ("OP_SUBSTR_LEFT"). [GH #22785 https://github.com/Perl/perl5/issues/22785] 
    substr($x, 0, ...)
substr($x, 0, ..., '')
  • La conversion en chaîne d'entiers par "print" dans perlfunc et "say" dans perlfunc, lorsqu'elle provient d'un "SVt_IV", est maintenant plus efficace. [GH #22927 https://github.com/Perl/perl5/issues/22927]
  • L'inversion de chaîne à partir d'un seul argument, lorsque le tampon de chaîne n'est pas "balayé", est maintenant effectuée en une seule passe et est sensiblement plus rapide. L'ampleur de l'amélioration dépend du compilateur et du matériel. [GH #23012 https://github.com/Perl/perl5/issues/23012]

Documentation

Modifications apportées à la documentation existante

Nous avons tenté de mettre à jour la documentation pour refléter les modifications énumérées dans ce document. Si vous en trouvez que nous avons omis, veuillez ouvrir un ticket sur https://github.com/Perl/perl5/issues.

De plus, les modifications sélectionnées suivantes ont été apportées :

perlapi

  • La documentation de plusieurs groupes de fonctions connexes a été combinée en entrées uniques.
  • Toutes les formes de gv_fetchmeth() sont maintenant documentées ensemble.
  • "gv_autoload4" est maintenant documenté avec "gv_autoload_pv" et des notes supplémentaires ont été ajoutées. Les formes longues "Perl_" sont maintenant répertoriées lorsqu'elles sont disponibles.

perldata

•
Les constantes flottantes binaires et octales (telles que "012.345p-2" et "0b101.11p-1") sont maintenant documentées. Cette fonctionnalité a été introduite pour la première fois dans perl 5.22.0 avec les constantes flottantes hexadécimales et a connu quelques corrections de bugs dans perl 5.28.0, mais elle n'a jamais été formellement documentée. [GH #18664 https://github.com/Perl/perl5/issues/18664]

perlfunc

  • La description de "ref" et "reftype" a été clarifiée par rapport aux types intégrés et aux noms de classes.
  • Il est maintenant précisé que sort de Perl est stable (et l'est depuis v5.8.0).
  • Les alternatives recommandées à la fonction rand() ont été mises à jour avec des modules modernes recommandés par le CPAN Security Group https://security.metacpan.org/. [GH #22873 https://github.com/Perl/perl5/pull/22873]

perlgov

•
La liste des membres du Conseil de Pilotage et de l'Équipe Principale a été mise à jour, suite à la conclusion des dernières élections le 2024-07-17.

perlguts

  • Quelques descriptions des "vrais" "AV" par rapport aux "faux" "AV" ont été ajoutées.
  • La documentation a été mise à jour pour refléter que le mélange de "Newx", "Renew", et "Safefree" par rapport à "malloc", "realloc", et "free" n'est pas autorisé, et le mélange de pointeurs entre les 2 classes d'API n'est pas autorisé. Mises à jour effectuées dans perlguts et perlclib.
  • Des mises en garde supplémentaires ont été ajoutées à la description de "TARG".

perlop

  • Certaines parties de perlop sont censées être ordonnées de manière à ce que tous les opérateurs de même priorité se trouvent dans une seule section, et les sections sont ordonnées de manière à ce que les opérateurs de plus haute priorité apparaissent en premier. Cet ordre a maintenant été rétabli. D'autres réorganisations ont été effectuées pour améliorer la clarté, avec des opérations plus basiques décrites avant celles qui en dépendent.
  • La documentation des here-docs a été nettoyée et réorganisée. Les here-docs indentés étaient auparavant documentés séparément, maintenant les deux types ont une documentation entrelacée qui est plus compacte et plus facile à comprendre.
  • La documentation de l'opérateur "xor" a été étendue.
  • Les conseils obsolètes sur l'utilisation des opérateurs de chaînes relationnelles dans les locales UTF-8 ont été supprimés. Utilisez Unicode::Collate pour obtenir les meilleurs résultats, mais ces opérateurs donneront des résultats adéquats sur de nombreuses plateformes.
  • Alignement normalisé des sections verbatim, corrigeant leur affichage par certains visualiseurs Pod qui suppriment l'indentation.

perlvar

•
Les entrées pour $# et $* ont été modifiées pour noter que leur utilisation entraîne une erreur de compilation, pas un avertissement.

Diagnostics

Les ajouts ou modifications suivants ont été apportés à la sortie diagnostique, y compris les avertissements et les messages d'erreur fatals. Pour la liste complète des messages diagnostiques, voir perldiag.

Nouveaux diagnostics

Nouvelles erreurs

  • Utilisation d'un caractère non ASCII 0x%X illégale lorsque 'use source::encoding "ascii"' est actif

    (F) Ce pragma interdit les caractères non ASCII dans son portée.

  • Sous-routine non définie &%s appelée, près de l'étiquette '%s'

    (F) La sous-routine indiquée n'a pas été définie, ou si elle l'a été, elle a depuis été indéfinie.

    Cette erreur pourrait également indiquer un séparateur de package mal orthographié, lorsqu'un seul deux-points a été tapé au lieu de deux deux-points. Par exemple, Foo:bar() serait analysé comme l'étiquette "Foo" suivie d'un nom de fonction non qualifié : "foo: bar()". [GH #22860 https://github.com/Perl/perl5/issues/22860]

Nouveaux avertissements

  • __CLASS__ est expérimental

    (S experimental::class) Cet avertissement est émis si vous utilisez le mot-clé "__CLASS__" de "use feature 'class'". Ce mot-clé est actuellement expérimental et son comportement peut changer dans les futures versions de Perl.

  • %s() tenté sur une poignée %s ouverte avec open()

    (W io) Vous avez appelé readdir(), telldir(), seekdir(), rewinddir() ou closedir() sur une poignée qui a été ouverte avec open(). Si vous souhaitez utiliser ces fonctions pour parcourir le contenu d'un répertoire, vous devez ouvrir la poignée avec opendir().

    [GH #22394 https://github.com/Perl/perl5/issues/22394]

  • Problème de priorité possible entre ! et %s

    (W precedence) Vous avez écrit quelque chose comme

    !$x < $y               # analysé comme : (!$x) < $y
!$x eq $y              # analysé comme : (!$x) eq $y
!$x =~ /regex/         # analysé comme : (!$x) =~ /regex/
!$obj isa Some::Class  # analysé comme : (!$obj) isa Some::Class

    mais comme "!" a une priorité plus élevée que les opérateurs de comparaison, "=~", et "isa", ceci est interprété comme comparant/correspondant la négation logique du premier opérande, au lieu de nier le résultat de la comparaison/correspondance.

    Pour désambiguïser, utilisez soit un opérateur de comparaison/liaison négatif :

    $x >= $y
$x ne $y
$x !~ /regex/

    ... soit des parenthèses :

    !($x < $y)
!($x eq $y)
!($x =~ /regex/)
!($obj isa Some::Class)

    ... soit l'opérateur de faible priorité "not" :

    not $x < $y
not $x eq $y
not $x =~ /regex/
not $obj isa Some::Class

    (Si vous vouliez vraiment comparer le résultat booléen de la négation du premier opérande, mettez des parenthèses comme "(!$x) < $y", "(!$x) eq $y", etc.)

    Remarque : cet avertissement ne se déclenche pas pour un code comme "!!$x == $y", c'est-à-dire lorsque la double négation ("!!") est utilisée comme opérateur de conversion en booléen.

Modifications des diagnostics existants

  • %s() tenté sur un descripteur de répertoire invalide %s

    Ceci a été consolidé à partir de messages distincts pour readdir(), telldir(), seekdir(), rewinddir() et closedir() dans le cadre du refactoring pour [GH #22394 https://github.com/Perl/perl5/issues/22394].

  • La macro de configuration (principalement non documentée) "PERL_STRICT_CR" a été supprimée. Changements Internes

  • La fonction « "sv_strftime_ints" » dans perlapi est introduite. Il s'agit d'une version améliorée de « "my_strftime" » dans perlapi, qui est conservée pour des raisons de compatibilité ascendante. Les deux appellent strftime(3) lorsque vous avez l'année, le mois, l'heure, etc. La nouvelle fonction gère l'UTF8 pour vous, et vous permet de spécifier si vous souhaitez que la possibilité d'heure d'été soit prise en compte. "my_strftime" ne prend jamais en compte l'heure d'été.
  • Les fonctions "bytes_to_utf8", "bytes_from_utf8", et "bytes_from_utf8_loc" ne sont plus expérimentales.
  • Les appels à call_argv() avec le drapeau "G_DISCARD" activé garantissent également que les paramètres SV construits à partir du paramètre "argv" sont libérés avant le retour de call_argv(). Auparavant, ils étaient libérés lors du prochain FREETMPS. [GH #22255https://github.com/Perl/perl5/issues/22255]
  • Lorsqu'elles sont compilées avec l'option de compilation "-DDEBUGGING", les fonctions de l'API Perl qui prennent des pointeurs vers des types distincts de SV (AV, HV ou CV) vérifieront le SvTYPE() des valeurs passées pour s'assurer qu'elles sont valides. De plus, le code interne des fonctions principales qui tentent d'extraire des AV, HV ou CV à partir de valeurs de référence passées effectuera également de telles vérifications.

    Bien que cela ait été entièrement testé par les tests CI normaux de Perl, il peut encore y avoir des cas limites où ces contraintes sont violées dans des appels par ailleurs valides. Ceux-ci peuvent nécessiter une enquête plus approfondie s'ils sont découverts, et un code spécifique à ajuster pour en tenir compte.

  • La fonction op_dump() a été étendue pour inclure des informations supplémentaires sur les opérations récentes "OP_METHSTART" et "OP_INITFIELD", ainsi que pour "OP_ARGCHECK" et "OP_ARGELEM" qui n'avaient pas été faites auparavant.
  • op_dump() dispose désormais également de la possibilité d'imprimer des informations de débogage supplémentaires sur les opérateurs personnalisés, si ces opérateurs enregistrent une fonction d'aide via le nouvel élément "xop_dump" de la structure "XOP". Pour plus d'informations, voir les ajouts pertinents à perlguts.
  • De nouvelles fonctions d'API sont introduites pour convertir des chaînes encodées en UTF-8 en leur équivalent de point de code ordinal. Celles-ci sont sûres à utiliser par défaut et généralement plus pratiques à utiliser que celles existantes.

    « "utf8_to_uv" » dans perlapi et « "utf8_to_uv_or_die" » dans perlapi remplacent « "utf8_to_uvchr" » dans perlapi (qui est conservé pour des raisons de compatibilité ascendante), mais vous devriez passer aux nouvelles formes, car vous n'utilisez probablement pas l'ancienne de manière sûre.

    Pour convertir dans l'autre sens, vous pouvez maintenant utiliser « "uv_to_utf8" » dans perlapi. Ce n'est pas une nouvelle fonction, mais un nouveau synonyme pour « "uvchr_to_utf8" » dans perlapi. Il est ajouté afin que vous n'ayez pas à apprendre deux ensembles de noms.

    Il existe également deux nouvelles fonctions, « "strict_utf8_to_uv" » dans perlapi et « "c9strict_utf8_to_uv" » dans perlapi qui font la même chose sauf lorsque la chaîne d'entrée représente un point de code que Unicode n'accepte pas comme légal pour l'échange, en utilisant soit la définition stricte originale ("strict_utf8_to_uv"), soit celle plus souple donnée par le rectificatif Unicode #9 https://www.unicode.org/versions/corrigendum9.html ("c9strict_utf8_to_uv"). Lorsque la chaîne d'entrée représente l'un des points de code restreints, ces fonctions retournent le "CARACTÈRE DE REMPLACEMENT" Unicode à la place.

    Aussi « "extended_utf8_to_uv" » dans perlapi est un synonyme de "utf8_to_uv", pour être utilisé lorsque vous voulez souligner que toute la plage de UTF-8 étendu de Perl est acceptable.

    Il existe également des fonctions de remplacement pour les trois fonctions de conversion plus spécialisées que vous n'aurez probablement pas besoin d'utiliser. Encore une fois, les anciennes formes sont conservées pour des raisons de compatibilité ascendante, mais vous devriez passer aux nouvelles formes.

    « "utf8_to_uv_flags" » dans perlapi remplace « "utf8n_to_uvchr" » dans perlapi.

    « "utf8_to_uv_errors" » dans perlapi remplace « "utf8n_to_uvchr_error" »

Celles-ci sont fournies uniquement pour vous éviter d'avoir à apprendre deux jeux de noms.

  • Trois nouvelles fonctions API sont introduites pour convertir des chaînes encodées en UTF-8 au format d'octets natifs (si possible). Elles sont plus faciles à utiliser que les existantes, et elles évitent des allocations de mémoire inutiles. Les fonctions sont ""utf8_to_bytes_overwrite"" dans perlapi qui est utilisée lorsqu'il est acceptable que la chaîne d'entrée soit écrasée avec le résultat converti ; et ""utf8_to_bytes_new_pv"" dans perlapi et ""utf8_to_bytes_temp_pv"" dans perlapi lorsque la chaîne d'origine doit être conservée intacte. "utf8_to_bytes_temp_pv" retourne le résultat dans un temporaire utilisant perlapi/"SAVEFREEPV" qui sera automatiquement détruit. Avec "utf8_to_bytes_new_pv", vous êtes responsable de libérer la mémoire nouvellement allouée qui est retournée si la conversion réussit.

  • De nouvelles fonctions API valid_identifier_pve(), valid_identifier_pvn() et valid_identifier_sv() ont été ajoutées, qui testent si une chaîne serait considérée par Perl comme un nom d'identifiant valide.

Auparavant, un SVt_IV aurait été promu en SVt_PVNV pour stocker un NV, et un SVt_NV aurait été promu en SVt_PVIV pour stocker un IV. Cette modification évite la nécessité d'allouer - et plus tard de libérer - la structure de corps pertinente.
  • Deux nouvelles fonctions API sont introduites pour convertir des chaînes encodées au format d'octets natifs en UTF-8. Elles retournent la chaîne inchangée si sa représentation UTF-8 est identique à l'originale. Sinon, une nouvelle mémoire est allouée pour contenir la chaîne convertie. Ceci est en contraste avec la fonction existante ""bytes_to_utf8"" dans perlapi qui alloue toujours une nouvelle mémoire. Les nouvelles fonctions sont ""bytes_to_utf8_free_me"" dans perlapi et ""bytes_to_utf8_temp_pv"" dans perlapi. ""bytes_to_utf8_temp_pv"" dans perlapi organise la libération automatique de la nouvelle mémoire. Avec "bytes_to_utf8_free_me", vous êtes responsable de libérer toute mémoire nouvellement allouée.
  • La manière dont les signatures de sous-routines sont analysées par la grammaire du parseur a été modifiée.

    Auparavant, lors de l'analyse des paramètres de signature individuels, le parseur accumulait un fragment d'arbre d'opérations "OP_ARGELEM" pour chaque paramètre sur la pile du parseur, les collectant dans une séquence "OP_LIST", avant de construire finalement l'arbre d'opérations complet de gestion des arguments, dans un grand bloc d'action défini directement dans perly.y.

    Dans la nouvelle approche, toute la génération de l'arbre d'opérations est gérée par de nouvelles fonctions définies dans op.c qui sont appelées par les blocs d'action dans le parseur. Celles-ci ne conservent pas d'état sur la pile du parseur, mais plutôt dans une structure mémoire dédiée référencée par la structure principale "PL_parser". Celle-ci est censée être largement opaque aux autres codes, et accessible uniquement via les nouvelles fonctions.

    Ce nouvel arrangement est destiné à permettre une génération de code plus flexible et le développement de fonctionnalités supplémentaires à l'avenir.

  • Trois nouvelles fonctions API ont été ajoutées pour interagir avec la position globale de correspondance d'expression régulière stockée dans un SV. Ce sont sv_regex_global_pos_get(), sv_regex_global_pos_set() et sv_regex_global_pos_clear(). L'utilisation de ces fonctions API évite aux modules XS d'avoir à connaître ou à interagir directement avec la manière dont cette position est actuellement stockée, ce qui implique le type magique "PERL_MAGIC_regex_global".

      Ceci est censé fonctionner uniquement lorsque la valeur non définie est celle retournée par la fonction "undef".

      Dans les Perl antérieurs à la version 5.41.3, cela posait un problème car la même valeur non définie peut être générée par la recherche de clés de hachage ou d'éléments de tableau inexistants, ce qui peut conduire à des bugs dans le code utilisateur (signalé comme [GH #22385 https://github.com/Perl/perl5/issues/22385]).

      Dans la version 5.41.3, des vérifications supplémentaires basées sur l'arbre syntaxique du site d'appel ont été ajoutées, ce qui a corrigé ce problème pour un certain nombre de cas courants, mais pas tous, au détriment de la capacité des API qui encapsulent "open" à exposer son mode de fichier anonyme. Un exemple notable d'une telle API est autodie.

      Cette version revient au problème précédent de préférence au nouveau pour le moment.

    Rapporter des bugs

    Si vous trouvez ce qui vous semble être un bug, vous pouvez consulter la base de données des bugs de Perl à l'adresse https://github.com/Perl/perl5/issues. Vous trouverez peut-être également des informations sur https://www.perl.org/, la page d'accueil de Perl.
