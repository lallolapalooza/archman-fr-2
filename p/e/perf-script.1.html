PERF-SCRIPT(1) Manuel perf PERF-SCRIPT(1)

NOM

perf-script - Lire perf.data (créé par perf record) et afficher la sortie de trace

SYNTAXE

perf script [<options>]
perf script [<options>] record <script> [<record-options>] <commande>
perf script [<options>] report <script> [script-args]
perf script [<options>] <script> <required-script-args> [<record-options>] <commande>
perf script [<options>] <top-script> [script-args]

DESCRIPTION

Cette commande lit le fichier d'entrée et affiche la trace enregistrée.

Il existe plusieurs variantes de perf script :

'perf script' pour voir une trace détaillée de la charge de travail qui a
été enregistrée.
Vous pouvez également exécuter un ensemble de scripts prédéfinis qui agrègent et
résument les données brutes de trace de diverses manières (la liste des scripts
est disponible via 'perf script -l'). Les variantes suivantes vous permettent
d'enregistrer et d'exécuter ces scripts :
'perf script record <script> <commande>' pour enregistrer les événements requis
pour 'perf script report'. <script> est le nom affiché dans la sortie de
'perf script --list', c'est-à-dire le nom réel du script moins toute extension de
langage. Si <commande> n'est pas spécifié, les événements sont enregistrés en
utilisant l'option -a (système entier) de 'perf record'.
'perf script report <script> [args]' pour exécuter et afficher les résultats de
<script>. <script> est le nom affiché dans la sortie de 'perf script --list',
c'est-à-dire le nom réel du script moins toute extension de langage. La sortie
perf.data d'une exécution précédente de 'perf script record <script>' est
utilisée et doit être présente pour que cette commande réussisse. [args] fait
référence aux arguments (principalement optionnels) attendus par le script.
'perf script <script> <required-script-args> <commande>' pour enregistrer les
événements requis pour <script> et exécuter le <script> en utilisant le
'mode live', c'est-à-dire sans rien écrire sur le disque. <script> est le nom
affiché dans la sortie de 'perf script --list', c'est-à-dire le nom réel du
script moins toute extension de langage. Si <script> a des arguments requis,
ils doivent être spécifiés avant <commande>. Ce mode ne permet pas de spécifier
des arguments de script optionnels ; si des arguments de script optionnels sont
souhaités, ils peuvent être spécifiés en utilisant des commandes séparées
'perf script record' et 'perf script report', avec la sortie standard de
l'étape d'enregistrement redirigée vers l'entrée standard du script de rapport,
en utilisant les options '-o -' et '-i -' des commandes correspondantes.
'perf script <top-script>' pour enregistrer les événements requis pour
<top-script> et exécuter le <top-script> en utilisant le 'mode live',
c'est-à-dire sans rien écrire sur le disque. <top-script> est le nom affiché
dans la sortie de 'perf script --list', c'est-à-dire le nom réel du script moins
toute extension de langage ; un <top-script> est défini comme tout nom de script
se terminant par la chaîne 'top'.
[<record-options>] peut être passé aux étapes d'enregistrement de 'perf script
record' et des variantes en 'mode live' ; cependant, ce n'est pas possible pour
le 'mode live' de <top-script> ou pour les variantes 'perf script report'.
Voir la section 'VOIR AUSSI' pour les liens vers des informations spécifiques
à la langue sur la façon d'écrire et d'exécuter vos propres scripts de trace.

OPTIONS

<commande>...

Toute commande que vous pouvez spécifier dans un shell.

-D, --dump-raw-trace=

Affiche une décharge verbeuse des données de trace.

--dump-unsorted-raw-trace=

Identique à --dump-raw-trace mais non trié par ordre temporel.

-L, --Latency=

Affiche les attributs de latence (interruptions/préemption désactivée, etc.).

-l, --list=

Affiche une liste des scripts de trace disponibles.

-s [lang], --script=

Traite les données de trace avec le script donné ([lang]:script[.ext]). Si la chaîne lang est spécifiée à la place d'un nom de script, une liste des langages pris en charge sera affichée à la place.

-g, --gen-script=

Génère un script de démarrage perf-script.[ext] pour le langage donné, en utilisant le perf.data actuel.

--dlfilter=<fichier>

Filtre les événements d'échantillon en utilisant le fichier d'objet partagé donné. Référez-vous à perf-dlfilter(1)

--dlarg=<arg>

Passe arg comme argument au dlfilter. --dlarg peut être répété pour ajouter plus d'arguments.

--list-dlfilters

Affiche une liste des dlfilters disponibles. Utilisez avec l'option -v (doit précéder l'option --list-dlfilters) pour afficher les descriptions longues.

-a

Force la collecte au niveau du système. Les scripts exécutés sans <commande> utilisent normalement -a par défaut, tandis que les scripts exécutés avec une <commande> ne le font pas normalement ; cette option permet à ces derniers d'être exécutés en mode système entier.

-i, --input=

Nom du fichier d'entrée. (par défaut : perf.data sauf si stdin est un fifo)

-d, --debug-mode

Effectue diverses vérifications comme l'ordre des échantillons et les événements perdus.

-F, --fields

Liste des champs séparés par des virgules à imprimer. Les options sont : comm, tid, pid, time, cpu, event, trace, ip, sym, dso, dsoff, addr, symoff, srccode, srcline, period, iregs, uregs, brstack, brstacksym, flags, bpf-output, brstackinsn, brstackinsnlen, brstackdisasm, brstackoff, callindent, insn, disasm, insnlen, synth, phys_addr, metric, misc, srccode, ipc, data_page_size, code_page_size, ins_lat, machine_pid, vcpu, cgroup, retire_lat, brcntr, 
La liste des champs peut être précédée du type, trace, sw ou hw,
pour indiquer à quel type d'événement la liste de champs s'applique.
par exemple, -F sw:comm,tid,time,ip,sym et -F trace:time,cpu,trace
perf script -F <champs>
est équivalent à :
perf script -F trace:<champs> -F sw:<champs> -F hw:<champs>
c'est-à-dire que les champs spécifiés s'appliquent à tous les types d'événements
si la chaîne de type n'est pas donnée.
En plus de remplacer les champs, il est également possible d'ajouter ou de
supprimer des champs des valeurs par défaut. Par exemple
-F -cpu,+insn
supprime le champ cpu et ajoute le champ insn. L'ajout/la suppression de champs
ne peut pas être mélangé avec un remplacement normal.
Les arguments sont traités dans l'ordre de réception. Une utilisation ultérieure
peut annuler une demande précédente. par exemple :
-F trace: -F comm,tid,time,ip,sym
Le premier -F supprime les événements de trace (la liste des champs est ""),
mais ensuite la deuxième invocation définit les champs sur comm,tid,time,ip,sym.
Dans ce cas, un avertissement est donné à l'utilisateur :
"Remplacement de la demande de champ précédente pour tous les événements."
Alternativement, considérez l'ordre :
-F comm,tid,time,ip,sym -F trace:
Le premier -F définit les champs pour tous les événements et le second -F
supprime les événements de trace. L'utilisateur reçoit un message d'avertissement
concernant le remplacement, et le résultat de ce qui précède est que seuls les
événements S/W et H/W sont affichés avec les champs donnés.
Il est possible d'ajouter/supprimer des champs uniquement pour un type d'événement
spécifique :
-Fsw:-cpu,-period
supprime cpu et period des événements logiciels.
Pour l'option 'wildcard', si un champ sélectionné par l'utilisateur n'est pas
valide pour un type d'événement, un message est affiché à l'utilisateur indiquant
que l'option est ignorée pour ce type. Par exemple :
$ perf script -F comm,tid,trace
'trace' non valide pour les événements matériels. Ignoré.
'trace' non valide pour les événements logiciels. Ignoré.
Alternativement, si le type est donné, un champ invalide est spécifié, c'est
une erreur. Par exemple :
perf script -v -F sw:comm,tid,trace
'trace' non valide pour les événements logiciels.
À ce stade, l'utilisation est affichée et perf-script se termine.
Les drapeaux (flags) sont synthétisés et peuvent avoir une valeur lors du décodage
de la trace d'instructions. Les drapeaux sont "bcrosyiABExghDt" qui
représentent branchement, appel, retour, conditionnel, système

Les combinaisons connues d'indicateurs sont imprimées de manière plus lisible, par exemple : « appel » pour « bc », « retour » pour « br », « jcc » pour « bo », « jmp » pour « b », « int » pour « bci », « iret » pour « bri », « syscall » pour « bcs », « sysret » pour « brs », « async » pour « by », « hw int » pour « bcyi », « tx abrt » pour « bA », « tr strt » pour « bB », « tr end » pour « bE », « vmentry » pour « bcg », « vmexit » pour « bch ». Le champ callindent est synthétisé et peut avoir une valeur lors
du décodage de l'Instruction Trace. Pour les appels et les retours, il affichera le
nom du symbole, indenté avec des espaces pour refléter la profondeur de la pile.
Lors du décodage de l'instruction trace, insn, disasm et insnlen donnent les
octets de l'instruction, les instructions désassemblées (nécessite le support de libcapstone)
et la longueur de l'instruction courante respectivement.
Le champ synth est utilisé par les événements synthétisés qui peuvent être créés lors
du décodage de l'Instruction Trace.
Le champ ipc (instructions par cycle) est synthétisé et peut avoir une valeur lors
du décodage de l'Instruction Trace.
Les champs machine_pid et vcpu sont dérivés des données résultant de l'utilisation
de perf inject pour insérer un fichier perf.data enregistré à l'intérieur d'une machine virtuelle dans
un fichier perf.data enregistré sur l'hôte en même temps.
Les champs cgroup nécessitent que l'échantillon ait l'ID cgroup qui est sauvegardé
lorsque l'option « --all-cgroups » est passée à 'perf record'.
Enfin, un utilisateur ne peut pas définir les champs sur none pour tous les types d'événements.
c'est-à-dire que -F "" n'est pas autorisé.
La sortie brstack inclut des informations relatives aux branches avec des adresses brutes en utilisant la
syntaxe FROM/TO/EVENT/INTX/ABORT/CYCLES/TYPE/SPEC dans l'ordre suivant :
FROM : instruction source de la branche
TO : instruction cible de la branche
EVENT : M=cible de la branche ou direction mal prédite
        P=cible de la branche ou direction prédite
        N=branche non prise
        -=aucun événement ou non pris en charge
INTX : X=branche dans une région transactionnelle
        -=branche non dans une région transactionnelle ou non prise en charge
ABORT : A=entrée d'abandon TSX
        -=région non abandonnée ou non prise en charge
CYCLES : le nombre de cycles écoulés depuis le dernier enregistrement de branche
TYPE : type de branche : COND/UNCOND/IND/CALL/IND_CALL/RET etc.
        -=non pris en charge
SPEC : informations de spéculation de branche : SPEC_WRONG_PATH/NON_SPEC_CORRECT_PATH/SPEC_CORRECT_PATH
        -=non pris en charge
Le champ brstacksym est identique à brstack, à l'exception que les adresses FROM et TO sont imprimées sous une forme symbolique si possible.
Lorsque brstackinsn est spécifié, les séquences d'assembleur complètes des séquences de branche pour chaque échantillon
sont imprimées. C'est le chemin d'exécution complet menant à l'échantillon. Ceci n'est pris en charge que lorsque l'échantillon
a été enregistré avec perf record -b ou -j any.
Utilisez brstackinsnlen pour imprimer la longueur de brstackinsn. Par exemple, vous
ne pouvez pas connaître la prochaine instruction séquentielle après une branche inconditionnelle, sauf si
vous la calculez en fonction de sa longueur.
brstackdisasm agit comme brstackinsn, mais imprimera les instructions désassemblées si
perf est compilé avec la bibliothèque capstone.
Le champ brstackoff imprimera un décalage dans un dso/binaire spécifique.
Avec l'option metric, perf script peut calculer des métriques pour
les périodes d'échantillonnage, similaire à perf stat. Cela nécessite
de spécifier un groupe avec plusieurs événements définissant des métriques avec l'option :S
pour perf record. perf échantillonnera sur le premier événement et
imprimera les métriques calculées pour tous les événements du groupe. Veuillez noter
que la métrique calculée est moyennée sur la période d'échantillonnage entière
(depuis le dernier échantillon), pas seulement pour le point d'échantillon.

-k, --vmlinux=<file>

chemin d'accès vmlinux

--kallsyms=<file>

chemin d'accès kallsyms

--symfs=<directory>

Rechercher les fichiers avec symboles par rapport à ce répertoire.

-G, --hide-call-graph

Lors de l'impression des symboles, n'affichez pas la chaîne d'appels.

--stop-bt

Arrêter l'affichage du graphe d'appels à ces symboles

-C, --cpu

Ne signaler que les échantillons pour la liste des CPU fournis. Plusieurs CPU peuvent être fournis sous forme de liste séparée par des virgules sans espace : 0,1. Les plages de CPU sont spécifiées avec - : 0-2. Par défaut, tous les CPU sont signalés.

-c, --comms=

Afficher uniquement les événements pour ces comms. CSV qui comprend les entrées file://filename.

--pid=

Afficher uniquement les événements pour l'ID de processus donné (liste séparée par des virgules).

--tid=

Afficher uniquement les événements pour l'ID de thread donné (liste séparée par des virgules).

-I, --show-info

Afficher des informations étendues sur le fichier perf.data. Cela ajoute des informations qui peuvent être très volumineuses et donc encombrer l'affichage. Il comprend actuellement : la topologie CPU et NUMA du système hôte. Il ne peut être utilisé qu'avec le mode de rapport perf script.

--show-kernel-path

Essayer de résoudre le chemin de [kernel.kallsyms]

--show-task-events Afficher les événements liés aux tâches (par exemple, FORK, COMM, EXIT).

--show-mmap-events Afficher les événements mmap (par exemple, MMAP, MMAP2).

--show-namespace-events Afficher les événements de namespace, c'est-à-dire les événements de type PERF_RECORD_NAMESPACES.

--show-switch-events Afficher les événements de changement de contexte, c'est-à-dire les événements de type PERF_RECORD_SWITCH ou PERF_RECORD_SWITCH_CPU_WIDE.

--show-lost-events Afficher les événements perdus, c'est-à-dire les événements de type PERF_RECORD_LOST.

--show-round-events Afficher les événements de fin de tour, c'est-à-dire les événements de type PERF_RECORD_FINISHED_ROUND.

--show-bpf-events Afficher les événements bpf, c'est-à-dire les événements de type PERF_RECORD_KSYMBOL et PERF_RECORD_BPF_EVENT.

--show-cgroup-events Afficher les événements cgroup, c'est-à-dire les événements de type PERF_RECORD_CGROUP.

--show-text-poke-events Afficher les événements text poke, c'est-à-dire les événements de type PERF_RECORD_TEXT_POKE et PERF_RECORD_KSYMBOL.

--demangle

Démangle les noms de symboles en forme lisible par l'homme. Il est activé par défaut, désactivez-le avec --no-demangle.

--demangle-kernel

Démangle les noms de symboles du noyau pour une forme lisible par l'homme (pour les noyaux C++).

--addr2line=<path>

Chemin d'accès vers le binaire addr2line.

--header Afficher l'en-tête perf.data.

--header-only Afficher uniquement l'en-tête perf.data.

--itrace

Options pour le décodage du traçage d'instructions. Les options sont : 
i       synthétiser les événements d'instructions
y       synthétiser les événements de cycles
b       synthétiser les événements de branches
c       synthétiser les événements de branches (appels uniquement)
r       synthétiser les événements de branches (retours uniquement)
x       synthétiser les événements de transactions
w       synthétiser les événements ptwrite
p       synthétiser les événements de puissance (y compris les événements PSB pour Intel PT)
o       synthétiser d'autres événements enregistrés en raison de l'utilisation
        de la sortie auxiliaire (voir perf record)
I       synthétiser les événements d'interruption ou similaires (asynchrones)
        (par exemple, Intel PT Event Trace)
e       synthétiser les événements d'erreur
d       créer un journal de débogage
f       synthétiser les événements du premier niveau de cache
m       synthétiser les événements du dernier niveau de cache
M       synthétiser les événements mémoire
t       synthétiser les événements TLB
a       synthétiser les événements d'accès distants
g       synthétiser une chaîne d'appels (à utiliser avec i ou x)
G       synthétiser une chaîne d'appels sur les enregistrements d'événements existants
l       synthétiser les dernières entrées de branche (à utiliser avec i ou x)
L       synthétiser les dernières entrées de branche sur les enregistrements d'événements existants
s       ignorer le nombre initial d'événements
q       décodage plus rapide (moins détaillé)
A       estimation de l'IPC
Z       préférer ignorer les horodatages (décodage dit « sans horodatage »)
T       utiliser la trace d'horodatage comme temps noyau
Par défaut, tous les événements sont traités, c'est-à-dire qu'ils sont identiques à --itrace=iybxwpe,
sauf pour perf script où c'est --itrace=ce
De plus, la période (par défaut 100000, sauf pour perf script où elle est de 1)
pour les événements d'instructions peut être spécifiée en unités de :
i       instructions
t       tiques
ms      millisecondes
us      microsecondes
ns      nanosecondes (par défaut)
De même, la taille de la chaîne d'appels (par défaut 16, max. 1024) pour les événements d'instructions ou
de transactions peut être spécifiée.
De même, le nombre de dernières entrées de branche (par défaut 64, max. 1024) pour
les événements d'instructions ou de transactions peut être spécifié.
Similaire aux options g et l, la taille peut également être spécifiée pour les options G et L.
Sur x86, notez que G et L fonctionnent mal lorsque les données ont été enregistrées avec
PEBS volumineux. Reportez-vous à la page de manuel linkperf:perf-intel-pt[1] pour plus de détails.
Il est également possible d'ignorer les événements générés (instructions, branches, transactions,
ptwrite, power) au début. Ceci est utile pour ignorer le code d'initialisation.
--itrace=i0nss1000000
ignore la première million d'instructions.

OPTIONS


--itrace[=flags]


Options pour l'analyse de trace du flux d'instructions. Les
  drapeaux sont facultatifs. Les drapeaux sont:



a       tous les événements perf
        e       sortie uniquement en cas d'erreurs (taille configurable - voir linkperf:perf-config[1])
        o       sortie vers stdout






Si pris en charge, l'option 'q' peut être répétée pour augmenter l'effet.






Pour désactiver complètement le décodage, utilisez --no-itrace.






--full-source-path


Affiche le chemin complet des fichiers source pour la sortie
  srcline.


--max-stack


Définit la limite de profondeur de la pile lors de
  l'analyse de la chaîne d'appel. Tout ce qui dépasse la profondeur spécifiée
  sera ignoré. Il s'agit d'un compromis entre la perte d'informations et un
  traitement plus rapide, en particulier pour les charges de travail qui peuvent
  avoir une très longue pile d'appels. Notez que lorsque l'option
  --itrace est utilisée, la taille de la chaîne d'appels synthétisée remplacera
  cette valeur si la taille de la chaîne d'appels synthétisée est plus grande.



Par défaut: 127






--ns


Utilise 9 décimales lors de l'affichage du temps (c'est-à-dire
  affiche les nanosecondes).


-f, --force


Ne pas effectuer la validation de propriété.


--time


Analyser uniquement les échantillons dans la fenêtre de temps
  donnée : <début>,<arrêt>. Les temps ont le format secondes.nanosecondes.
  Si le début n'est pas donné (c'est-à-dire que la chaîne de temps est
  ,x.y) alors l'analyse commence au début du fichier. Si le temps
  d'arrêt n'est pas donné (c'est-à-dire que la chaîne de temps est
  x.y,) alors l'analyse va jusqu'à la fin du fichier. Plusieurs plages
  peuvent être séparées par des espaces, ce qui nécessite que l'argument soit
  entre guillemets, par exemple --time
  "1234.567,1234.789 1235,"



Prend également en charge les pourcentages de temps avec plusieurs plages
horaires. La chaîne de temps est 'a%/n,b%/m,...' ou 'a%-b%,c%-%d,...'.






Par exemple :
Sélectionner la deuxième tranche de temps de 10% :
perf script --time 10%/2






Sélectionner de 0% à 10% de tranche de temps :
perf script --time 0%-10%






Sélectionner la première et la deuxième tranche de temps de 10% :
perf script --time 10%/1,10%/2






Sélectionner les tranches de 0% à 10% et de 30% à 40% :
perf script --time 0%-10%,30%-40%






--max-blocks


Définit le nombre maximum de blocs de programme à imprimer
  avec brstackinsn pour chaque échantillon.


--reltime


Affiche les horodatages relatifs au début de la trace.


--deltatime


Affiche les horodatages relatifs à l'événement
  précédent.


--per-event-dump


Crée des fichiers par événement nommés
  "perf.data.EVENT.dump" au lieu de les imprimer sur stdout, utile, par
  exemple, pour générer des flamegraphs.


--inline


Si une adresse de graphe d'appel appartient à une fonction
  inline, la pile inline sera imprimée. Chaque entrée a le nom de la fonction et
  le fichier/ligne. Activé par défaut, désactiver avec --no-inline.


--insn-trace[=<raw|disasm>]


Affiche le flux d'instructions en octets (raw) ou
  désassemblé (disasm) pour les traces intel_pt. La valeur par défaut est
  raw. Pour utiliser xed, combinez raw avec --xed pour afficher le
  désassemblage effectué par xed.


--xed


Exécute le désassembleur xed sur la sortie. Nécessite
  l'installation du désassembleur xed.


-S, --symbols=symbole[,symbole...]


Considérer uniquement les symboles listés. Les symboles sont
  typiquement un nom mais peuvent aussi être une adresse hexadécimale.



L'adresse hexadécimale peut être l'adresse de début d'un symbole ou
toute autre adresse pour filtrer les enregistrements de trace






Par exemple, pour sélectionner le symbole noploop ou l'adresse 0x4007a0 :
perf script --symbols=noploop,0x4007a0






Prend en charge le filtrage des enregistrements de trace par nom de symbole,
adresse de début de symbole, toute adresse hexadécimale et plage d'adresses.






L'ordre de comparaison est :




 1. comparaison de nom de symbole


 2. comparaison d'adresse de début de symbole.


 3. comparaison de toute adresse hexadécimale.


 4. comparaison de plage d'adresses (voir --addr-range).




--addr-range


Utiliser avec -S ou --symbols pour lister les enregistrements
  tracés dans une plage d'adresses.



Par exemple, pour lister les enregistrements tracés dans la plage d'adresses
[0x4007a0, 0x0x4007a9] :
perf script -S 0x4007a0 --addr-range 10






--dsos=


Considérer uniquement les symboles dans ces DSO.


--call-trace


Affiche le flux d'appels pour les traces intel_pt. Les CPU
  sont entrelacés, mais peuvent être filtrés avec -C.


--call-ret-trace


Affiche le flux d'appels et de retours pour les traces
  intel_pt.


--graph-function


Pour itrace, n'affiche que les fonctions spécifiées et leurs
  appelés pour itrace. Plusieurs fonctions peuvent être séparées par une virgule.


--switch-on EVENT_NAME


Ne considérer les événements qu'après que cet événement a été
  trouvé.


--switch-off EVENT_NAME


Arrêter de considérer les événements après que cet événement
  a été trouvé.


--show-on-off-events


Afficher également les événements --switch-on/off.


--stitch-lbr


Affiche le graphe d'appels avec les LBR cousus, ce qui peut
  conduire à un graphe d'appels plus complet. Le fichier perf.data doit avoir été
  obtenu en utilisant perf record --call-graph lbr. Désactivé par défaut. Dans
  les cas courants avec des dépassements de pile d'appels, il peut recréer de
  meilleures piles d'appels que la sortie par défaut de la pile d'appels LBR.
  Mais cette approche n'est pas infaillible. Il peut y avoir des cas où elle crée
  des piles d'appels incorrectes à partir de correspondances incorrectes. Les
  limitations connues incluent la gestion des exceptions comme setjmp/longjmp qui
  auront des appels/retours non correspondants.


--guestmount=<chemin>


Répertoire de montage du système de fichiers racine du
  système d'exploitation invité. Les utilisateurs montent les répertoires racine
  du système d'exploitation invité sous <chemin> par une méthode
  d'accès au système de fichiers spécifique, typiquement sshfs. Par exemple,
  démarrer 2 systèmes d'exploitation invités, dont le pid est 8888 et l'autre
  est 9999 :



$ mkdir ~/guestmount
$ cd ~/guestmount
$ sshfs -o allow_other,direct_io -p 5551 localhost:/ 8888/
$ sshfs -o allow_other,direct_io -p 5552 localhost:/ 9999/
$ perf script --guestmount=~/guestmount 






--guestkallsyms=<chemin>


Copie du fichier /proc/kallsyms du système
  d'exploitation invité. perf le lit pour obtenir les symboles du noyau invité.
  Les utilisateurs le copient depuis le système d'exploitation invité.


--guestmodules=<chemin>


Copie du fichier /proc/modules du système
  d'exploitation invité. perf le lit pour obtenir les informations des modules
  du noyau invité. Les utilisateurs le copient depuis le système d'exploitation
  invité.


--guestvmlinux=<chemin>


Vmlinux du noyau du système d'exploitation invité.


--guest-code


Indique que le code invité peut être trouvé dans le
  processus hyperviseur, ce qui est un cas courant pour les programmes de test KVM.
