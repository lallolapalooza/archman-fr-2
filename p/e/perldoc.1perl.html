PERLDOC(1perl) Guide du programmeur Perl PERLDOC(1perl)

NOM

perldoc - Consulter la documentation Perl au format Pod.

SYNTAXE

perldoc [-h] [-D] [-t] [-u] [-m] [-l] [-U] [-F]
    [-i] [-V] [-T] [-r]
    [-d fichier_destination]
    [-o nom_format]
    [-M NomClasseFormateur]
    [-w option:valeur]
    [-n remplacement_nroff]
    [-X]
    [-L code_langue]
    NomPage|NomModule|NomProgramme|URL

Exemples :

perldoc -f FonctionIntrinsèque
perldoc -L it -f FonctionIntrinsèque
perldoc -q MotCléFAQ
perldoc -L fr -q MotCléFAQ
perldoc -v VariablePerl
perldoc -a APIPerl

Voir ci-dessous pour plus de détails sur les options.

DESCRIPTION

perldoc recherche la documentation au format .pod intégrée dans l'arborescence d'installation de perl ou dans un script perl, et l'affiche en utilisant divers formateurs. Ceci est principalement utilisé pour la documentation des modules de la bibliothèque perl.

Votre système peut également avoir des pages man installées pour ces modules, auquel cas vous pouvez probablement utiliser la commande man(1).

Si vous recherchez une table des matières de la documentation des modules de la bibliothèque perl, consultez la page perltoc.

OPTIONS

-h
Affiche un bref message d'aide (help).
-D
Décrit la recherche de l'élément en détail.
-t
Affiche la documentation en utilisant le convertisseur texte brut (plain text), au lieu de nroff. Cela peut être plus rapide, mais le rendu sera probablement moins agréable.
-u
Ignore le formatage Pod réel et affiche uniquement la source Pod brute (non formattée, Unformatted).
-m module
Affiche le module entier : le code et la documentation Pod non formatée. Cela peut être utile si la documentation n'explique pas une fonction avec le détail dont vous avez besoin, et que vous souhaitez inspecter le code directement ; perldoc trouvera le fichier pour vous et le transmettra simplement pour affichage.
-l
Affiche seulement le nom du fichier du module trouvé.
-U
Lors de l'exécution en tant que superutilisateur, ne tente pas de renoncer aux privilèges pour des raisons de sécurité. Cette option est implicite avec -F.

NOTE : Veuillez consulter la rubrique SÉCURITÉ ci-dessous pour plus d'informations.

-F
Considère les arguments comme des noms de fichiers ; aucune recherche dans les répertoires ne sera effectuée. Implique -U si exécuté en tant que superutilisateur.
-f fonctionperl
L'option -f suivie du nom d'une fonction intégrée de Perl extraira la documentation de cette fonction de perlfunc.

Exemple :

perldoc -f sprintf
-q regexp_recherche_perlfaq
L'option -q prend une expression régulière comme argument. Elle recherchera les titres de questions dans perlfaq[1-9] et affichera les entrées correspondant à l'expression régulière.

Exemple :

perldoc -q shuffle
-a fonctionapiperl
L'option -a suivie du nom d'une fonction de l'API Perl extraira la documentation de cette fonction de perlapi.

Exemple :

perldoc -a newHV
-v variableperl
L'option -v suivie du nom d'une variable prédéfinie Perl extraira la documentation de cette variable de perlvar.

Exemples :

perldoc -v '$"'
perldoc -v @+
perldoc -v DATA
-T
Ceci spécifie que la sortie ne doit pas être envoyée à un paginator, mais directement à STDOUT.
-d nom_fichier_destination
Ceci spécifie que la sortie ne doit être envoyée ni à un paginator ni à STDOUT, mais sauvegardée dans le fichier spécifié. Exemple : "perldoc -oLaTeX -dtextwrapdocs.tex Text::Wrap"
-o nom_format_sortie
Ceci spécifie que vous souhaitez que Perldoc essaie d'utiliser une classe de formatage Pod pour le format de sortie que vous spécifiez. Par exemple : "-oman". Ceci est en fait juste un wrapper autour du commutateur "-M" ; utiliser "-onom_format" recherche simplement une classe chargeable en ajoutant ce nom de format (avec différentes capitalisations) à la fin de différents préfixes de nom de classe.

Par exemple, "-oLaTeX" essaie actuellement toutes les classes suivantes : Pod::Perldoc::ToLaTeX Pod::Perldoc::Tolatex Pod::Perldoc::ToLatex Pod::Perldoc::ToLATEX Pod::Simple::LaTeX Pod::Simple::latex Pod::Simple::Latex Pod::Simple::LATEX Pod::LaTeX Pod::latex Pod::Latex Pod::LATEX.

-M nom_module
Ceci spécifie le module que vous souhaitez essayer d'utiliser pour formater le pod. La classe doit au moins fournir une méthode "parse_from_file". Par exemple : "perldoc -MPod::Perldoc::ToChecker".

Vous pouvez spécifier plusieurs classes à essayer en les joignant avec des virgules ou des points-virgules, comme dans "-MTk::SuperPod;Tk::Pod".

-w option:valeur ou -w option
Ceci spécifie une option pour appeler le formateur avec. Par exemple, "-w textsize:15" appellera "$formateur->textsize(15)" sur l'objet formateur avant qu'il ne soit utilisé pour formater l'objet. Pour que cela soit valide, la classe du formateur doit fournir une telle méthode, et la valeur que vous passez doit être valide. (Donc, si "textsize" attend un entier, et que vous faites "-w textsize:big", attendez-vous à des problèmes.)

Vous pouvez utiliser "-w nom_option" (sans valeur) comme raccourci pour "-w nom_option:VRAI". Ceci est probablement utile dans les cas de fonctionnalités activées/désactivées comme : "-w pagination_numerotation".

Vous pouvez utiliser un "=" au lieu du ":", comme dans : "-w textsize=15". Cela pourrait être plus (ou moins) pratique, selon le shell que vous utilisez.

-X
Utilise un index s'il est présent. L'option -X recherche une entrée dont le nom de base correspond au nom donné sur la ligne de commande dans le fichier "$Config{archlib}/pod.idx". Le fichier pod.idx doit contenir des noms de fichiers qualifiés complets, un par ligne.
-L code_langue
Ceci permet de spécifier le code langue pour la traduction linguistique souhaitée. Si le paquet "POD2::<code_langue>" n'est pas installé sur votre système, l'option est ignorée. Tous les paquets de traduction disponibles se trouvent sous le namespace "POD2::". Consultez POD2::IT (ou POD2::FR) pour voir comment créer de nouveaux paquets de documentation localisés "POD2::*" et les intégrer dans Pod::Perldoc.
NomPage|NomModule|NomProgramme|URL
L'élément que vous souhaitez rechercher. Les modules imbriqués (tels que "File::Basename") sont spécifiés soit comme "File::Basename", soit comme "File/Basename". Vous pouvez également donner un nom descriptif d'une page, tel que "perlfunc". Pour les URL, HTTP et HTTPS sont les seuls types actuellement pris en charge.

Pour les noms simples comme 'foo', lorsque la recherche normale ne trouve pas de page correspondante, une recherche avec le préfixe "perl" est également tentée. Ainsi, "perldoc intro" suffit pour trouver/afficher "perlintro".

TÉLÉCHARGEMENT PODS

perldoc recherche dans les répertoires spécifiés dans le fichier de configuration de Perl (perl -V) pour trouver les Pods.

Pour trouver un Pod, perldoc essaie de le trouver dans les sous-répertoires suivants de chaque répertoire spécifié dans la configuration de Perl :

    # Perl versions prior to 5.14
    $Config{siteprefix}/lib/perl5/$Config{version}/$Config{archname}
    $Config{installarchlib}
    $Config{installscript}/lib/perl5/$Config{version}/$Config{archname}
    $Config{installscript}/lib/perl5/$Config{version}
    $Config{installscript}

    # Perl versions 5.14 and later
    $Config{installarchlib}
    $Config{installscript}

Dans le cas où vous demandez un module spécifique, par exemple "Foo::Bar", perldoc cherchera le fichier "Foo/Bar.pm" (ou "Foo/Bar.pod") dans les répertoires ci-dessus. Pour les fonctions intégrées, il recherche le fichier "perlfunc.pod", pour les variables "perlvar.pod", et pour les FAQs "perlfaq[0-9].pod".

SÉCURITÉ

Si perldoc est exécuté par un utilisateur root, il essaiera de renoncer à ses privilèges root avant d'ouvrir des fichiers Pod. Ceci est fait en appelant la méthode "chown" sur le formatteur (qui, par défaut, est "Pod::Perldoc"). Ceci est fait pour des raisons de sécurité afin d'empêcher un utilisateur root malveillant d'utiliser perldoc pour lire des fichiers privés.

Si vous souhaitez désactiver ce comportement, vous pouvez utiliser l'option -U. Cette option est implicite si l'option -F est utilisée.

FORMATTEURS

L'option -t demandera à perldoc d'utiliser Pod::PlainText pour formater la sortie. Il existe plusieurs autres formateurs disponibles, tels que :

  • Pod::Perldoc::ToChecker : pour vérifier si le Pod est bien formé.
  • Pod::Perldoc::ToHTML : pour formater la sortie en HTML.
  • Pod::Perldoc::ToNroff : pour formater la sortie en utilisant nroff (le comportement par défaut).
  • Pod::Perldoc::ToSwingman : pour formater la sortie en utilisant Swingman.

Vous pouvez également spécifier votre propre formateur avec l'option -M.

EXEMPLES SUPPLÉMENTAIRES

perldoc Pod::Perldoc
perldoc -f open
perldoc -q utf8
perldoc -a TIEHANDLE
perldoc -MPod::Perldoc::ToHTML -o html
perldoc -L fr Pod::Perldoc
perldoc -T Pod::Perldoc
perldoc -d output.txt Pod::Perldoc

SÉCURITÉ

Comme perldoc ne fonctionne pas correctement lorsqu'il est en mode restreint et qu'il est connu pour avoir des problèmes de sécurité, lorsqu'il est exécuté en tant que superutilisateur, il tentera de réduire ses privilèges en définissant les identifiants effectifs et réels sur le compte de nobody ou nouser, ou sur -2 s'il n'est pas disponible. S'il ne peut pas renoncer à ses privilèges, il ne s'exécutera pas.

Voir l'option "-U" si vous ne souhaitez pas ce comportement, mais faites attention car il y a des risques de sécurité importants si vous choisissez d'utiliser "-U".

Depuis la version 3.26, l'utilisation de "-F" en tant que superutilisateur implique également "-U", car l'ouverture de la plupart des fichiers et la traversée des répertoires nécessitent des privilèges supérieurs à ceux de nobody/nogroup.

ENVIRONNEMENT

Tous les commutateurs de la variable d'environnement "PERLDOC" seront utilisés avant les arguments de la ligne de commande.

Les valeurs utiles pour "PERLDOC" incluent "-oterm", "-otext", "-ortf", "-oxml", et ainsi de suite, en fonction des modules dont vous disposez ; ou la classe formatrice peut être spécifiée exactement avec "-MPod::Perldoc::ToTerm" ou similaire.

"perldoc" recherche également les répertoires spécifiés par les variables d'environnement "PERL5LIB" (ou "PERLLIB" si "PERL5LIB" n'est pas défini) et "PATH". (Ce dernier permet de rendre disponibles les pods intégrés aux exécutables, tels que "perldoc" lui-même.)

Dans les répertoires où "Makefile.PL" ou "Build.PL" existent, "perldoc" ajoutera "." et "lib" en premier à son chemin de recherche, et tant que vous n'êtes pas superutilisateur, il ajoutera également "blib". C'est très utile si vous travaillez dans un répertoire de construction et que vous souhaitez lire la documentation même si une version d'un module est déjà installée.

"perldoc" utilisera, par ordre de préférence, le paginator défini dans "PERLDOC_PAGER", "MANPAGER", ou "PAGER" avant d'essayer de trouver un paginator par lui-même. ("MANPAGER" n'est pas utilisé si "perldoc" a été configuré pour afficher du texte brut ou du pod non formaté.)

Lors de l'utilisation de perldoc en mode "-m" (affichage du code source du module), "perldoc" tentera d'utiliser le paginator défini dans "PERLDOC_SRC_PAGER". Un réglage utile pour cette commande est votre éditeur préféré, par exemple "/usr/bin/nano". (Ne me jugez pas.)

Une valeur utile pour "PERLDOC_PAGER" est "less -+C -E".

Avoir PERLDOCDEBUG défini sur un entier positif fera émettre à perldoc une sortie encore plus descriptive que l'option "-D" ; plus le nombre est élevé, plus la sortie est descriptive.

CHANGEMENTS

Jusqu'à la version 3.14_05, l'option -v était utilisée pour produire des messages détaillés sur le fonctionnement de perldoc, qui est maintenant activée par -D.
