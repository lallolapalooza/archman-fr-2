NOM

perf-c2c - Analyseur de données partagées C2C/HITM.

SYNTAXE

perf c2c record [<options>] <commande>
perf c2c record [<options>] -- [<options de commande record>] <commande>
perf c2c report [<options>]

DESCRIPTION

C2C signifie Cache To Cache (Cache à Cache).

L'outil perf c2c fournit des moyens pour l'analyse de données partagées C2C/HITM. Il vous permet de traquer les contentions de lignes de cache.

Sur Intel, l'outil est basé sur la latence de chargement et les événements de préfixe de magasin précis fournis par les processeurs Intel. Sur PowerPC, l'outil utilise l'échantillonnage aléatoire d'instructions avec la fonction de seuil. Sur AMD, l'outil utilise le PMU d'opérations IBS (en raison de limites matérielles, perf c2c n'est pas pris en charge sur les processeurs Zen3). Sur Arm64, il utilise SPE pour échantillonner les opérations de chargement et de magasin, par conséquent, un support matériel et du noyau est requis. Voir perf-arm-spe(1) pour un guide de configuration. En raison de la nature statistique de l'échantillonnage Arm SPE, toutes les opérations mémoire ne seront pas échantillonnées.

Ces événements fournissent : - l'adresse mémoire de l'accès - le type d'accès (détails de chargement et de magasin) - la latence (en cycles) de l'accès en lecture

L'outil c2c fournit des moyens pour enregistrer ces données et afficher les détails d'accès pour les lignes de cache ayant la plus forte contention - le plus grand nombre d'accès HITM.

Le flux de travail de base avec cet outil suit la phase standard d'enregistrement/rapport. L'utilisateur utilise la commande d'enregistrement pour enregistrer les données des événements et la commande de rapport pour les afficher.

OPTIONS RECORD

-e, --event=

Sélectionne l'événement PMU. Utilisez perf c2c record -e list pour lister les événements disponibles.

-v, --verbose

Être plus verbeux (afficher les erreurs d'ouverture de compteur, etc).

-l, --ldlat

Configure la latence des chargements mémoire. Pris en charge sur les processeurs Intel, Arm64 et certains processeurs AMD. Ignoré sur les autres architectures. 
Sur les processeurs AMD pris en charge :
- Le fichier /sys/bus/event_source/devices/ibs_op/caps/ldlat contient '1'.
- Les valeurs de latence prises en charge vont de 128 à 2048 (inclus).
- Une valeur de latence multiple de 128 entraîne une surcharge de profilage
  légèrement inférieure par rapport à d'autres valeurs.
- Le filtrage de la latence de chargement est désactivé par défaut.

-k, --all-kernel

Configure tous les événements utilisés pour s'exécuter dans l'espace noyau.

-u, --all-user

Configure tous les événements utilisés pour s'exécuter dans l'espace utilisateur.

OPTIONS REPORT

-k, --vmlinux=<fichier>

Chemin du fichier vmlinux

-v, --verbose

Être plus verbeux (afficher les erreurs d'ouverture de compteur, etc).

-i, --input

Spécifiez le fichier d'entrée à traiter.

-N, --node-info

Afficher des informations de nœud supplémentaires dans le rapport (voir la section INFORMATIONS DE NŒUD)

-c, --coalesce

Spécifiez les champs de tri pour l'affichage d'une seule ligne de cache. Les champs suivants sont disponibles : tid,pid,iaddr,dso (voir COALESCE)

-g, --call-graph

Configure les paramètres des chaînes d'appel. Veuillez vous référer à la page man de perf-report pour plus de détails.

--stdio

Forcer la sortie stdio (voir SORTIE STDIO)

--stats

Afficher uniquement les tableaux statistiques et forcer le mode stdio.

--full-symbols

Afficher la longueur complète des symboles.

--no-source

Ne pas afficher la colonne Source:Ligne.

--show-all

Afficher toutes les lignes HITM capturées, sans tenir compte de la limite de % HITM de 0,0005.

-f, --force

Ne pas effectuer la validation de propriété.

-d, --display

Basculer vers le type HITM (rmt, lcl) ou le type de snooping pair (peer) pour afficher et trier. Total HITMs (tot) par défaut, sauf sur Arm64 où le mode pair est par défaut.

--stitch-lbr

Afficher le graphe d'appels avec des LBR cousus, ce qui peut donner un graphe d'appels plus complet. Le fichier perf.data doit avoir été obtenu en utilisant perf c2c record --call-graph lbr. Désactivé par défaut. Dans les cas courants avec des dépassements de pile d'appels, il peut recréer de meilleures piles d'appels que la sortie de pile d'appels lbr par défaut. Mais cette approche n'est pas infaillible. Il peut y avoir des cas où elle crée des piles d'appels incorrectes à partir de correspondances incorrectes. Les limitations connues incluent la gestion des exceptions comme setjmp/longjmp, où les appels/retours ne correspondront pas.

--double-cl

Regrouper la détection des événements de cache partagé sur une granularité de double ligne de cache. Certaines architectures disposent d'une fonction de pré-chargement de ligne de cache adjacente, qui fait que le partage de ligne de cache se comporte comme si la taille de la ligne de cache était doublée.

C2C RECORD

La commande perf c2c record configure les options relatives à l'analyse des lignes de cache HITM et appelle la commande perf record standard.

Les options perf record suivantes sont configurées par défaut : (consultez la page man de perf record pour plus de détails)

-W,-d,--phys-data,--sample-cpu

Sauf indication contraire avec l'option -e, les événements suivants sont surveillés par défaut sur Intel :

cpu/mem-loads,ldlat=30/P
cpu/mem-stores/P

sur AMD :

ibs_op//

et sur PowerPC :

cpu/mem-loads/
cpu/mem-stores/

L'utilisateur peut passer n'importe quelle option perf record derrière le marqueur --, comme (pour activer les chaînes d'appels et la surveillance globale du système) :

$ perf c2c record -- -g -a

Veuillez consulter la section OPTIONS RECORD pour les options spécifiques de perf c2c record.

C2C REPORT

La commande perf c2c report affiche l'analyse des données partagées. Elle se présente en deux modes d'affichage : stdio et tui (par défaut).

Le flux de travail de la commande de rapport est le suivant : - trier toutes les données en fonction de l'adresse de la ligne de cache - stocker les détails d'accès pour chaque ligne de cache - trier toutes les lignes de cache en fonction des paramètres de l'utilisateur - afficher les données

En général, la sortie de perf report se compose de 2 vues de base : 1) liste des lignes de cache les plus coûteuses 2) détails des décalages pour chaque ligne de cache

Pour chaque ligne de cache dans la liste 1), nous affichons les données suivantes : (Les modes stdio et TUI suivent les mêmes champs de sortie)

Index
- index basé sur zéro pour identifier la ligne de cache
Ligne de cache
- adresse de la ligne de cache (nombre hexadécimal)
Rmt/Lcl Hitm (Affichage avec types HITM)
- pourcentage de lignes de cache de tous les accès HITM distants/locaux
Peer Snoop (Affichage avec type pair)
- pourcentage de lignes de cache de tous les accès pairs
LLC Load Hitm - Total, LclHitm, RmtHitm (Pour affichage avec types HITM)
- nombre de HITM de chargement Total/Local/Distant
Load Peer - Total, Local, Remote (Pour affichage avec type pair)
- nombre de chargements depuis le cache pair ou la DRAM, Total/Local/Distant
Total enregistrements
- somme de tous les accès aux lignes de cache
Total chargements
- somme de tous les accès en lecture
Total magasins
- somme de tous les accès en écriture
Référence de magasin - L1Hit, L1Miss, N/A
  L1Hit - accès en écriture qui frappent le L1
  L1Miss - accès en écriture qui manquent le L1
  N/A - accès en écriture dont le niveau mémoire n'est pas disponible
Chargement Core - FB, L1, L2
- nombre de succès de chargement dans le FB (Fill Buffer), L1 et L2
LLC Load Hit - LlcHit, LclHitm
- nombre d'accès en lecture LLC, inclut les succès LLC et les HITM LLC
RMT Load Hit - RmtHit, RmtHitm
- nombre d'accès en lecture distants, inclut les succès distants et les HITM distants ;
  sur les cœurs Arm Neoverse, RmtHit est utilisé pour comptabiliser les accès distants,
  incluant la DRAM distante ou tout niveau de cache supérieur dans le nœud distant
DRAM de chargement - Lcl, Rmt
- nombre d'accès locaux et distants à la DRAM

Pour chaque décalage dans la liste 2), nous affichons les données suivantes :

HITM - Rmt, Lcl (Affichage avec types HITM)
- % d'accès HITM distants/locaux pour un décalage donné au sein de la ligne de cache
Peer Snoop - Rmt, Lcl (Affichage avec type pair)
- % d'accès pairs distants/locaux pour un décalage donné au sein de la ligne de cache
Références de stockage - Succès L1, Échec L1, N/A
- % des accès de stockage qui ont réussi L1, ont échoué L1 et N/A (non disponible)
  niveau de mémoire pour un décalage donné dans la ligne de cache
Adresse de données - Décalage
- adresse de décalage
Pid
- pid du processus responsable des accès
Tid
- tid du processus responsable des accès
Adresse de code
- adresse de code responsable des accès
cycles - rmt hitm, lcl hitm, load (Afficher avec les types HITM)
  - somme des cycles pour les accès donnés - HITM distant/local et chargement générique
cycles - rmt peer, lcl peer, load (Afficher avec le type peer)
  - somme des cycles pour les accès donnés - chargement peer distant/local et chargement générique
cpu cnt
  - nombre de CPUs qui ont participé à l'accès
Symbol
  - symbole de code lié à la valeur 'Adresse de code'
Shared Object
  - nom de l'objet partagé lié à la valeur 'Adresse de code'
Source:Ligne
  - informations source liées à la valeur 'Adresse de code'
Node
  - nœuds participant à l'accès (voir la section NODE INFO)

INFOS NŒUD

Le champ Node affiche les nœuds qui accèdent à un décalage de ligne de cache donné. Sa sortie se présente sous 3 formes : - identifiants de nœuds séparés par , - identifiants de nœuds avec des statistiques pour chaque identifiant, au format suivant : Node{cpus %hitms %stores} (Afficher avec les types HITM) Node{cpus %peers %stores} (Afficher avec le type peer) - identifiants de nœuds avec une liste des CPUs affectés sous le format suivant : Node{liste des cpus}

L'utilisateur peut basculer entre les formes ci-dessus avec l'option -N ou utiliser la touche n pour basculer interactivement en mode TUI.

REGROUPEMENT

L'utilisateur peut spécifier comment trier les décalages pour une ligne de cache.

Les champs suivants sont disponibles et régissent l'ensemble des champs de sortie finaux pour la sortie des décalages de lignes de cache :

tid   - regroupé par TID de processus
pid   - regroupé par PID de processus
iaddr - regroupé par adresse de code, les champs suivants sont affichés :
           Adresse de code, Symbole de code, Objet partagé, Ligne source
dso   - regroupé par objet partagé

Par défaut, le regroupement est configuré avec pid,iaddr.

SORTIE STDIO

La sortie stdio affiche les données sur la sortie standard.

Les tableaux suivants sont affichés : Informations sur les événements de trace - statistiques globales des accès mémoire

Informations globales sur les événements de ligne de cache partagée
- statistiques globales sur les lignes de cache partagées
Tableau des lignes de cache de données partagées
- liste des lignes de cache les plus coûteuses
Distribution Pareto des lignes de cache partagées
- liste de tous les décalages accédés pour chaque ligne de cache

SORTIE TUI

La sortie TUI fournit une interface interactive pour naviguer dans la liste des lignes de cache et afficher les détails des décalages.

Pour plus de détails, veuillez consulter la fenêtre d'aide en appuyant sur la touche ?.
