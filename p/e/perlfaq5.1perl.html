Comment vider/débufferiser un fichier de sortie ? Pourquoi faut-il le faire ?

(contribué par brian d foy)

Vous pourriez aimer lire l'article de Mark Jason Dominus, "Suffering From Buffering" sur http://perl.plover.com/FAQs/Buffering.html .

Perl met normalement en tampon la sortie afin de ne pas effectuer un appel système pour chaque bit de sortie. En accumulant la sortie, il effectue moins d'appels système coûteux. Par exemple, dans ce petit extrait de code, vous voulez imprimer un point à l'écran pour chaque ligne traitée afin de suivre la progression de votre programme. Au lieu de voir un point pour chaque ligne, Perl met la sortie en tampon et vous attendez longtemps avant de voir une rangée de 50 points d'un coup :

# Longue attente, puis une rangée de points d'un coup
while( <> ) {
    print ".";
    print "\n" unless ++$count % 50;
    #... opérations coûteuses de traitement de ligne
}

Pour contourner cela, vous devez débufferiser le fichier de sortie, dans ce cas, "STDOUT". Vous pouvez définir la variable spéciale $| à une valeur vraie (moyen mnémotechnique : rendre vos filehandles "bouillants") :

$|++;
# point affiché immédiatement
while( <> ) {
    print ".";
    print "\n" unless ++$count % 50;
    #... opérations coûteuses de traitement de ligne
}

Le $| est l'une des variables spéciales par filehandle, donc chaque filehandle a sa propre copie de sa valeur. Si vous voulez fusionner la sortie standard et l'erreur standard par exemple, vous devez débufferiser chacun (bien que STDERR puisse être débufferisé par défaut) :

{
    my $previous_default = select(STDOUT);  # sauvegarde le défaut précédent
    $|++;                                   # vide automatiquement STDOUT
    select(STDERR);
    $|++;                                   # vide automatiquement STDERR, pour être sûr
    select($previous_default);              # restaure le défaut précédent
}
# maintenant devrait alterner . et +
while( 1 ) {
    sleep 1;
    print STDOUT ".";
    print STDERR "+";
    print STDOUT "\n" unless ++$count % 25;
}

En plus de la variable spéciale $|, vous pouvez utiliser "binmode" pour donner à votre filehandle une couche ":unix", qui n'est pas bufferisée :

binmode( STDOUT, ":unix" );
while( 1 ) {
    sleep 1;
    print ".";
    print "\n" unless ++$count % 50;
}

Pour plus d'informations sur les couches de sortie, voir les entrées pour "binmode" et open dans perlfunc, et la documentation du module PerlIO.

Si vous utilisez IO::Handle ou l'une de ses sous-classes, vous pouvez appeler la méthode "autoflush" pour changer les paramètres du filehandle :

use IO::Handle;
open my( $io_fh ), ">", "output.txt";
$io_fh->autoflush(1);

Les objets IO::Handle ont également une méthode "flush". Vous pouvez vider le tampon à tout moment sans auto-buffering.

$io_fh->flush;

Comment changer, supprimer ou insérer une ligne dans un fichier, ou ajouter au début d'un fichier ?

(contribué par brian d foy)

L'idée de base pour insérer, changer ou supprimer une ligne d'un fichier texte implique de lire et d'imprimer le fichier jusqu'à l'endroit où vous souhaitez apporter la modification, d'effectuer la modification, puis de lire et d'imprimer le reste du fichier. Perl ne fournit pas d'accès aléatoire aux lignes (surtout que le séparateur d'entrée d'enregistrement, $/, est mutable), bien que des modules comme Tie::File puissent le simuler.

Un programme Perl pour effectuer ces tâches prend la forme de base d'ouverture d'un fichier, d'impression de ses lignes, puis de fermeture du fichier :

open my $in,  '<',  $file      or die "Impossible de lire l'ancien fichier : $!";
open my $out, '>', "$file.new" or die "Impossible d'écrire le nouveau fichier : $!";
while( <$in> ) {
        print $out $_;
}
close $out;

Dans cette forme de base, ajoutez les parties dont vous avez besoin pour insérer, changer ou supprimer des lignes.

Pour ajouter des lignes au début, imprimez ces lignes avant d'entrer dans la boucle qui imprime les lignes existantes.

open my $in,  '<',  $file      or die "Impossible de lire l'ancien fichier : $!";
open my $out, '>', "$file.new" or die "Impossible d'écrire le nouveau fichier : $!";
print $out "# Ajouter cette ligne en haut\n"; # <--- VOICI LA MAGIE
while( <$in> ) {
        print $out $_;
}
close $out;

Pour changer des lignes existantes, insérez le code pour modifier les lignes à l'intérieur de la boucle "while". Dans ce cas, le code trouve toutes les versions en minuscules de "perl" et les met en majuscules. Cela se produit pour chaque ligne, alors assurez-vous que c'est ce que vous êtes censé faire sur chaque ligne !

open my $in,  '<',  $file      or die "Impossible de lire l'ancien fichier : $!";
open my $out, '>', "$file.new" or die "Impossible d'écrire le nouveau fichier : $!";
print $out "# Ajouter cette ligne en haut\n";
while( <$in> ) {
    s/\b(perl)\b/Perl/g;
    print $out $_;
}
close $out;

Pour changer seulement une ligne particulière, le numéro de ligne d'entrée, $., est utile. Lisez et imprimez d'abord les lignes jusqu'à celle que vous voulez changer. Ensuite, lisez la seule ligne que vous voulez changer, changez-la et imprimez-la. Après cela, lisez le reste des lignes et imprimez-les :

while( <$in> ) { # imprime les lignes avant le changement
    print $out $_;
    last if $. == 4; # numéro de ligne avant le changement
}
my $line = <$in>;
$line =~ s/\b(perl)\b/Perl/g;
print $out $line;
while( <$in> ) { # imprime le reste des lignes
    print $out $_;
}

Pour sauter des lignes, utilisez les contrôles de boucle. Le "next" dans cet exemple saute les lignes de commentaire, et le "last" arrête tout traitement dès qu'il rencontre soit "__END__", soit "__DATA__".

while( <$in> ) {
    next if /^\s+#/;             # sauter les lignes de commentaire
    last if /^__(END|DATA)__$/;  # s'arrêter au marqueur de fin de code
    print $out $_;
}

Faites la même chose pour supprimer une ligne particulière en utilisant "next" pour sauter les lignes que vous ne voulez pas voir apparaître dans la sortie. Cet exemple saute une ligne sur cinq :

while( <$in> ) {
    next unless $. % 5;
    print $out $_;
}

Si, pour une raison étrange, vous voulez vraiment voir tout le fichier d'un coup plutôt que de le traiter ligne par ligne, vous pouvez le "charger" (tant que vous pouvez tout faire tenir en mémoire !) :

open my $in,  '<',  $file      or die "Impossible de lire l'ancien fichier : $!";
open my $out, '>', "$file.new" or die "Impossible d'écrire le nouveau fichier : $!";
my $content = do { local $/; <$in> }; # charger !
    # faites votre magie ici
print $out $content;

Des modules comme Path::Tiny et Tie::File peuvent aussi aider à cela. Si vous le pouvez, cependant, évitez de lire tout le fichier d'un coup. Perl ne rendra pas cette mémoire au système d'exploitation avant que le processus ne se termine.

Vous pouvez également utiliser des one-liners Perl pour modifier un fichier en place. La commande suivante remplace tous les 'Fred' par 'Barney' dans inFile.txt, écrasant le fichier avec le nouveau contenu. Avec l'option "-p", Perl enveloppe une boucle "while" autour du code que vous spécifiez avec "-e", et "-i" active l'édition en place. La ligne courante est dans $_. Avec "-p", Perl imprime automatiquement la valeur de $_ à la fin de la boucle. Voir perlrun pour plus de détails.

perl -pi -e 's/Fred/Barney/' inFile.txt

Pour faire une sauvegarde de "inFile.txt", donnez à "-i" une extension de fichier à ajouter :

perl -pi.bak -e 's/Fred/Barney/' inFile.txt

Pour changer seulement la cinquième ligne, vous pouvez ajouter un test vérifiant $., le numéro de ligne d'entrée, puis effectuer l'opération seulement lorsque le test passe :

perl -pi -e 's/

Comment modifier un fichier sur place ?

(contributed by brian d foy)

Perl dispose d'une option en ligne de commande, "-i", qui vous permet de modifier un fichier sur place. Pour les utilisateurs de Perl 5.005 et plus récents, ceci inclut la possibilité de créer des sauvegardes.

Pour utiliser l'option "-i", vous fournissez un script Perl à l'option "-e", et vous vous assurez que "<>" est utilisé pour lire le fichier. L'option "-p" est également utile car elle vous permet d'insérer votre code et de vous assurer que le résultat est écrit dans le fichier.

perl -pi -e 's/foo/bar/g' inFile.txt

Si vous utilisez "-i.bak" (ou n'importe quelle extension), vous obtenez une sauvegarde du fichier original.

perl -pi.bak -e 's/foo/bar/g' inFile.txt

Pour ajouter des lignes après une certaine ligne, vous pouvez ajouter une ligne (ou des lignes !) après que Perl ait imprimé $_ :

perl -pi -e 'print "Put after fifth line\n" if $. == 5' inFile.txt

Pour ajouter des lignes avant une certaine ligne, vous pouvez ajouter une ligne (ou des lignes !) avant que Perl n'imprime $_ :

perl -pi -e 'print "Put before third line\n" if $. == 3' inFile.txt

Vous pouvez même ajouter une ligne au début d'un fichier, puisque la ligne actuelle est imprimée à la fin de la boucle :

perl -pi -e 'print "Put before first line\n" if $. == 1' inFile.txt

Pour insérer une ligne après une ligne déjà présente dans le fichier, utilisez le commutateur "-n". C'est comme "-p" sauf qu'il n'imprime pas $_ à la fin de la boucle, vous devez donc le faire vous-même. Dans ce cas, imprimez $_ d'abord, puis imprimez la ligne que vous souhaitez ajouter.

perl -ni -e 'print; print "Put after fifth line\n" if $. == 5' inFile.txt

Pour supprimer des lignes, imprimez uniquement celles que vous souhaitez.

perl -ni -e 'print if /d/' inFile.txt

Comment compter le nombre de lignes dans un fichier ?

(contributed by brian d foy)

Conceptuellement, la manière la plus simple de compter les lignes d'un fichier est simplement de les lire et de les compter :

my $count = 0;
while( <$fh> ) { $count++; }

Vous n'avez cependant pas vraiment à les compter vous-même, car Perl le fait déjà avec la variable $., qui est le numéro de ligne actuel du dernier handle de fichier lu :

1 while( <$fh> );
my $count = $.;

Si vous souhaitez utiliser $., vous pouvez le réduire à une simple ligne de commande, comme l'une des suivantes :

% perl -lne '} print $.; {'    file
% perl -lne 'END { print $. }' file

Celles-ci peuvent cependant être assez inefficaces. Si elles ne sont pas assez rapides pour vous, vous pouvez simplement lire des blocs de données et compter le nombre de nouvelles lignes :

my $lines = 0;
open my($fh), '<:raw', $filename or die "Can't open $filename: $!";
while( sysread $fh, $buffer, 4096 ) {
    $lines += ( $buffer =~ tr/\n// );
}
close $fh;

Cependant, cela ne fonctionne pas si la fin de ligne n'est pas une nouvelle ligne. Vous pouvez changer ce "tr///" en "s///" afin de pouvoir compter le nombre de fois que le séparateur d'enregistrement d'entrée, $/, apparaît :

my $lines = 0;
open my($fh), '<:raw', $filename or die "Can't open $filename: $!";
while( sysread $fh, $buffer, 4096 ) {
    $lines += ( $buffer =~ s|$/||g );
}
close $fh;

Si vous n'avez pas peur de faire appel à un shell externe, la commande "wc" est généralement la plus rapide, même avec la surcharge interprocessus supplémentaire. Assurez-vous d'avoir un nom de fichier non altéré :

#!perl -T
$ENV{PATH} = undef;
my $lines;
if( $filename =~ /^([0-9a-z_.]+)\z/ ) {
    $lines = `/usr/bin/wc -l $1`;
    chomp $lines;
}

Comment supprimer les N dernières lignes d'un fichier ?

(contributed by brian d foy)

La solution conceptuellement la plus simple consiste à compter les lignes du fichier, puis à commencer par le début et à imprimer le nombre de lignes (moins les N dernières) dans un nouveau fichier.

Le plus souvent, la vraie question est de savoir comment supprimer les N dernières lignes sans faire plus d'un passage sur le fichier, ou comment le faire sans beaucoup de copie. Le concept simple est la dure réalité quand vous pourriez avoir des millions de lignes dans votre fichier.

Une astuce consiste à utiliser File::ReadBackwards, qui commence à la fin du fichier. Ce module fournit un objet qui encapsule le handle de fichier réel pour vous permettre de vous déplacer facilement dans le fichier. Une fois que vous arrivez à l'endroit souhaité, vous pouvez obtenir le handle de fichier réel et travailler avec comme d'habitude. Dans ce cas, vous obtenez la position du fichier à la fin de la dernière ligne que vous souhaitez conserver et tronquez le fichier à ce point :

use File::ReadBackwards;
my $filename = 'test.txt';
my $Lines_to_truncate = 2;
my $bw = File::ReadBackwards->new( $filename )
    or die "Could not read backwards in [$filename]: $!";
my $lines_from_end = 0;
until( $bw->eof or $lines_from_end == $Lines_to_truncate ) {
    print "Got: ", $bw->readline;
    $lines_from_end++;
}
truncate( $filename, $bw->tell );

Le module File::ReadBackwards a également l'avantage de définir le séparateur d'enregistrement d'entrée sur une expression régulière.

Vous pouvez également utiliser le module Tie::File, qui vous permet d'accéder aux lignes via un tableau lié. Vous pouvez utiliser des opérations de tableau normales pour modifier votre fichier, y compris définir le dernier index et utiliser "splice".

Comment puis-je utiliser l'option Perl « -i » depuis un programme ?

"-i" définit la valeur de la variable $^I de Perl, ce qui affecte à son tour le comportement de "<>" ; voir perlrun pour plus de détails. En modifiant directement les variables appropriées, vous pouvez obtenir le même comportement au sein d'un programme plus vaste. Par exemple :

# ...
{
    local($^I, @ARGV) = ('.orig', glob("*.c"));
    while (<>) {
        if ($. == 1) {
            print "This line should appear at the top of each file\n";
        }
        s/\b(p)earl\b/${1}erl/i;        # Correct typos, preserving case
        print;
        close ARGV if eof;              # Reset $.
    }
}
# $^I et @ARGV reviennent à leurs anciennes valeurs ici

Ce bloc modifie tous les fichiers ".c" du répertoire courant, en laissant une sauvegarde des données originales de chaque fichier dans un nouveau fichier ".c.orig".

Comment copier un fichier ?

(contributed by brian d foy)

Utilisez le module File::Copy. Il est fourni avec Perl et peut effectuer une véritable copie entre systèmes de fichiers, et il fait sa magie de manière portable.

use File::Copy;
copy( $original, $new_copy ) or die "Copy failed: $!";

Si vous ne pouvez pas utiliser File::Copy, vous devrez faire le travail vous-même : ouvrez le fichier d'origine, ouvrez le fichier de destination, puis écrivez dans le fichier de destination en lisant l'original. Vous devez également vous souvenir de copier les permissions, le propriétaire et le groupe dans le nouveau fichier.

Comment créer un nom de fichier temporaire ?

Si vous n'avez pas besoin de connaître le nom du fichier, vous pouvez utiliser open() avec "undef" à la place du nom de fichier. Dans Perl 5.8 ou plus récent, la fonction open() crée un fichier temporaire anonyme :

open my $tmp, '+>', undef or die $!;

Sinon, vous pouvez utiliser le module File::Temp.

use File::Temp qw/ tempfile tempdir /;
my $dir = tempdir( CLEANUP => 1 );
($fh, $filename) = tempfile( DIR => $dir );
# ou si vous n'avez pas besoin de connaître le nom du fichier
my $fh = tempfile( DIR => $dir );

File::Temp est un module standard depuis Perl 5.6.1. Si vous n'avez pas une version suffisamment moderne de Perl installée, utilisez la méthode de classe "new_tmpfile" du module IO::File pour obtenir un handle de fichier ouvert en lecture et en écriture. Utilisez-le si vous n'avez pas besoin de connaître le nom du fichier :

use IO::File;
my $fh = IO::File->new_tmpfile()
    or die "Unable to make new temporary file: $!";

Si vous êtes déterminé à créer un fichier temporaire manuellement, utilisez l'ID du processus et/ou la valeur de l'heure actuelle. Si vous avez besoin de plusieurs fichiers temporaires dans un seul processus, utilisez un compteur :

BEGIN {
    use Fcntl;
    use File::Spec;
    my $temp_dir  = File::Spec->tmpdir();
    my $file_base = sprintf "%d-%d-0000", $$, time;
    my $base_name = File::Spec->catfile($temp_dir, $file_base);
    sub temp_file {
        my $fh;
        my $count = 0;
        until( defined(fileno($fh)) || $count++ > 100 ) {
            $base_name =~ s/-(\d+)$/"-" . (1 + $1)/e;
            # O_EXCL est requis pour des raisons de sécurité.
            sysopen $fh, $base_name, O_WRONLY|O_EXCL|O_CREAT;
        }
        if( defined fileno($fh) ) {
            return ($fh, $base_name);
        }
        else {
            return ();
        }
    }
}

Comment manipuler des fichiers à enregistrement de longueur fixe ?

La manière la plus efficace est d'utiliser pack() et unpack(). C'est plus rapide que d'utiliser substr() pour de nombreuses chaînes. C'est plus lent pour seulement quelques-unes.

Voici un exemple de code pour diviser et reconstituer des lignes d'entrée de format fixe, dans ce cas, la sortie d'un ps normal, de style Berkeley :

# ligne d'entrée d'exemple :
#   15158 p5  T      0:00 perl /home/tchrist/scripts/now-what
my $PS_T = 'A6 A4 A7 A5 A*';
open my $ps, '-|', 'ps';
print scalar <$ps>;
my @fields = qw( pid tt stat time command );
while (<$ps>) {
    my %process;
    @process{@fields} = unpack($PS_T, $_);
    for my $field ( @fields ) {
        print "$field: <$process{$field}>\n";
    }
    print 'line=', pack($PS_T, @process{@fields} ), "\n";
}

Nous avons utilisé une tranche de hachage afin de gérer facilement les champs de chaque ligne. Stocker les clés dans un tableau facilite leur manipulation en groupe ou leur parcours avec "for". Cela évite également de polluer le programme avec des variables globales et d'utiliser des références symboliques.

Comment puis-je rendre un handle de fichier local à une sous-routine ? Comment puis-je passer des handles de fichier entre sous-routines ? Comment puis-je créer un tableau de handles de fichier ?

Depuis perl5.6, open() autovivifie les handles de fichiers et de répertoires sous forme de références si vous lui passez une variable scalaire non initialisée. Vous pouvez ensuite passer ces références comme n'importe quel autre scalaire, et les utiliser à la place de handles nommés.

open my    $fh, $file_name;
open local $fh, $file_name;
print $fh "Hello World!\n";
process_file( $fh );

Si vous le souhaitez, vous pouvez stocker ces handles de fichier dans un tableau ou un hachage. Si vous y accédez directement, ce ne sont pas de simples scalaires et vous devez donner à "pr

int" une petite aide en plaçant la référence du descripteur de fichier entre accolades. Perl ne peut le comprendre tout seul que lorsque la référence du descripteur de fichier est un scalaire simple.

my @fhs = ( $fh1, $fh2, $fh3 );
for( $i = 0; $i <= $#fhs; $i++ ) {
    print {$fhs[$i]} "just another Perl answer, \n";
}

Avant perl5.6, il fallait gérer divers idiomes de typeglob que vous pourriez rencontrer dans du code plus ancien.

open FILE, "> $filename";
process_typeglob(   *FILE );
process_reference( \*FILE );
sub process_typeglob  { local *FH = shift; print FH  "Typeglob!" }
sub process_reference { local $fh = shift; print $fh "Reference!" }

Si vous souhaitez créer de nombreux descripteurs anonymes, vous devriez jeter un coup d'œil aux modules Symbol ou IO::Handle.

Comment puis-je utiliser un descripteur de fichier indirectement ?

Un descripteur de fichier indirect est l'utilisation de quelque chose d'autre qu'un symbole dans un endroit où un descripteur de fichier est attendu. Voici les moyens d'obtenir des descripteurs de fichier indirects :

$fh =   SOME_FH;       # bareword est hostile aux subs strictes
$fh =  "SOME_FH";      # strict-refs est hostile ; même package uniquement
$fh =  *SOME_FH;       # typeglob
$fh = \*SOME_FH;       # référence à un typeglob (peut être béni)
$fh =  *SOME_FH{IO};   # IO::Handle béni à partir du typeglob *SOME_FH

Ou, vous pouvez utiliser la méthode "new" de l'un des modules IO::* pour créer un descripteur de fichier anonyme et le stocker dans une variable scalaire.

use IO::Handle;                     # 5.004 ou supérieur
my $fh = IO::Handle->new();

Ensuite, utilisez chacun d'eux comme vous le feriez pour un descripteur de fichier normal. Partout où Perl attend un descripteur de fichier, un descripteur de fichier indirect peut être utilisé à la place. Un descripteur de fichier indirect est juste une variable scalaire qui contient un descripteur de fichier. Les fonctions comme "print", "open", "seek", ou l'opérateur de diamant "<FH>" accepteront soit un descripteur de fichier nommé, soit une variable scalaire qui en contient un :

($ifh, $ofh, $efh) = (*STDIN, *STDOUT, *STDERR);
print $ofh "Tapez ceci : ";
my $got = <$ifh>;
print $efh "Qu'est-ce que c'était : $got";

Si vous passez un descripteur de fichier à une fonction, vous pouvez écrire la fonction de deux manières :

sub accept_fh {
    my $fh = shift;
    print $fh "Envoi vers le descripteur de fichier indirect\n";
}

Ou elle peut localiser un typeglob et utiliser directement le descripteur de fichier :

sub accept_fh {
    local *FH = shift;
    print  FH "Envoi vers le descripteur de fichier localisé\n";
}

Les deux styles fonctionnent avec des objets ou des typeglobs de descripteurs de fichier réels. (Ils pourraient également fonctionner avec des chaînes dans certaines circonstances, mais c'est risqué.)

accept_fh(*STDOUT);
accept_fh($handle);

Dans les exemples ci-dessus, nous avons assigné le descripteur de fichier à une variable scalaire avant de l'utiliser. C'est parce que seules les variables scalaires simples, et non les expressions ou les sous-scripts de hachages ou de tableaux, peuvent être utilisées avec des fonctions intégrées comme "print", "printf", ou l'opérateur de diamant. L'utilisation d'autre chose qu'une variable scalaire simple comme descripteur de fichier est illégale et ne compilera même pas :

my @fd = (*STDIN, *STDOUT, *STDERR);
print $fd[1] "Tapez ceci : ";                           # FAUX
my $got = <$fd[0]>                                  # FAUX
print $fd[2] "Qu'est-ce que c'était : $got";                 # FAUX

Avec "print" et "printf", vous contournez cela en utilisant un bloc et une expression là où vous placeriez le descripteur de fichier :

print  { $fd[1] } "drôle de chose\n";
printf { $fd[1] } "Pauvre %x.\n", 3_735_928_559;
# Pauvre deadbeef.

Ce bloc est un bloc proper comme n'importe quel autre, vous pouvez donc y mettre du code plus compliqué. Cela envoie le message à l'un des deux endroits :

my $ok = -x "/bin/cat";
print { $ok ? $fd[1] : $fd[2] } "stat du chat $ok\n";
print { $fd[ 1+ ($ok || 0) ]  } "stat du chat $ok\n";

Cette approche qui consiste à traiter "print" et "printf" comme des appels de méthodes d'objet ne fonctionne pas pour l'opérateur de diamant. C'est parce que c'est un véritable opérateur, pas seulement une fonction avec un argument sans virgule. En supposant que vous avez stocké des typeglobs dans votre structure comme nous l'avons fait ci-dessus, vous pouvez utiliser la fonction intégrée nommée "readline" pour lire un enregistrement tout comme "<>" le fait. Compte tenu de l'initialisation montrée ci-dessus pour @fd, cela fonctionnerait, mais uniquement parce que readline() nécessite un typeglob. Cela ne fonctionne pas avec des objets ou des chaînes, ce qui pourrait être un bug que nous n'avons pas encore corrigé.

$got = readline($fd[0]);

Il convient de noter que l'instabilité des descripteurs de fichier indirects n'est pas liée à savoir s'ils sont des chaînes, des typeglobs, des objets ou autre chose. C'est la syntaxe des opérateurs fondamentaux. Jouer au jeu des objets ne vous aide pas du tout ici.

Comment puis-je ouvrir un descripteur de fichier vers une chaîne ?

(contribué par Peter J. Holzer, hjp-usenet2@hjp.at)

Depuis Perl 5.8.0, un descripteur de fichier faisant référence à une chaîne peut être créé en appelant open avec une référence à cette chaîne au lieu du nom de fichier. Ce descripteur de fichier peut ensuite être utilisé pour lire ou écrire dans la chaîne :

open(my $fh, '>', \$string) or die "Impossible d'ouvrir la chaîne en écriture";
print $fh "foo\n";
print $fh "bar\n";    # $string contient maintenant "foo\nbar\n"
open(my $fh, '<', \$string) or die "Impossible d'ouvrir la chaîne en lecture";
my $x = <$fh>;    # $x contient maintenant "foo\n"

Avec les anciennes versions de Perl, le module IO::String fournit une fonctionnalité similaire.

Comment puis-je écrire() dans une chaîne ?

(contribué par brian d foy)

Si vous souhaitez "écrire" dans une chaîne, il vous suffit d'<open> un descripteur de fichier sur une chaîne, ce que Perl sait faire depuis Perl 5.6 :

open FH, '>', \my $string;
write( FH );

Étant donné que vous voulez être un bon programmeur, vous voudrez probablement utiliser un descripteur de fichier lexical, même si les formats sont conçus pour fonctionner avec des descripteurs de fichier bareword car les noms de format par défaut prennent le nom du descripteur de fichier. Cependant, vous pouvez contrôler cela avec certaines variables spéciales Perl par descripteur de fichier : $^, qui nomme le format du haut de page, et $~ qui affiche le format de ligne. Vous devez changer le descripteur de fichier par défaut pour définir ces variables :

open my($fh), '>', \my $string;
{ # définir les variables par descripteur de fichier
    my $old_fh = select( $fh );
    $~ = 'ANIMAL';
    $^ = 'ANIMAL_TOP';
    select( $old_fh );
}
format ANIMAL_TOP =
 ID  Type    Nom
.
format ANIMAL =
@##   @<<<    @<<<<<<<<<<<<<<
$id,  $type,  $name
.

Bien que write puisse fonctionner avec des variables lexicales ou de package, quelles que soient les variables que vous utilisez, elles doivent être dans la portée du format. Cela signifie très probablement que vous voudrez localiser certaines variables de package :

{
    local( $id, $type, $name ) = qw( 12 chat Buster );
    write( $fh );
}
print $string;

Il existe également quelques astuces que vous pouvez jouer avec "formline" et la variable accumulatrice $^A, mais vous perdez une grande partie de la valeur des formats puisque "formline" ne gérera pas la pagination, etc. Vous finirez par réimplémenter les formats lorsque vous les utiliserez.

Comment puis-je afficher mes nombres avec des virgules ajoutées ?

(contribué par brian d foy et Benjamin Goldberg)

Le module CLDR::Number (Common Locale Data Repository Unicode) sait comment formater les nombres en fonction d'une locale pour utiliser son regroupement et son séparateur de chiffres :

use CLDR::Number;
my $number = 1234567890;
foreach my $locale ( qw(en-US de-DE en-IN) ) {
    my $cldr = CLDR::Number->new( locale => $locale );
    my $decimal = $cldr->decimal_formatter;
    printf "%-5s %s\n", $locale, $decimal->format( $number );
    }

La sortie montre le même nombre formaté selon les règles de chaque locale. Le bare "en" utilise des virgules entre des groupes de trois, le "de" utilise des points et des groupes de trois, et le "en-IN" utilise la règle 3:2:2 avec des virgules :

en-US 1,234,567,890
de-DE 1.234.567.890
en-IN 1,23,45,67,890

CLDR::Number possède de nombreuses fonctionnalités avancées pour gérer à peu près tout ce que vous pourriez souhaiter. L'article d'Olaf Alders "Stop Writing Your Own Commify Functions" contient plus d'exemples (https://www.olafalders.com/2015/09/04/stop-writing-your-own-commify-functions/).

Si vous savez exactement ce que vous voulez, une sous-routine simple peut suffire. Cet exemple ajoutera des séparateurs à votre nombre entre des groupes de trois chiffres (ou n'importe quel regroupement). Il utilise des groupes de trois et une virgule :

sub commify {
    local $_  = shift;
    1 while s/^([-+]?\d+)(\d{3})/$1,$2/;
    return $_;
}

Cette regex de Benjamin Goldberg fait la même chose sans la boucle :

s/(^[-+]?\d+?(?=(?>(?:\d{3})+)(?!\d))|\G\d{3}(?=\d))/$1,/g;

Il est plus facile de la voir avec des commentaires :

s/(
    ^[-+]?             # début du nombre.
    \d+?               # premiers chiffres avant la première virgule
    (?=                # suivi par, (mais non inclus dans la correspondance) :
        (?>(?:\d{3})+) # un multiple positif quelconque de trois chiffres.
        (?!\d)         # un multiple *exact*, pas x * 3 + 1 ou autre.
    )
    |                  # ou :
    \G\d{3}            # après le dernier groupe, prendre trois chiffres
    (?=\d)             # mais ils doivent avoir d'autres chiffres après eux.
)/$1,/xg;

Comment puis-je traduire les tildes (~) dans un nom de fichier ?

Utilisez l'opérateur <> (glob()), documenté dans perlfunc. Les versions de Perl antérieures à 5.6 nécessitent l'installation d'un shell qui comprend les tildes. Les versions ultérieures de Perl ont cette fonctionnalité intégrée. Le module File::KGlob (disponible sur CPAN) offre une fonctionnalité de glob plus portable.

Dans Perl, vous pouvez l'utiliser directement :

$filename =~ s{
  ^ ~             # trouver un tilde en début de chaîne
  (               # sauvegarder ceci dans $1
      [^/]        # un caractère autre qu'une barre oblique
            *     # répété 0 ou plusieurs fois (0 signifie moi)
  )
}{
  $1
      ? (getpwnam($1))[7]
      : ( $ENV{HOME} || $ENV{LOGDIR} )
}ex;

Quand j'ouvre un fichier en lecture-écriture, pourquoi l'efface-t-il ?

Parce que vous utilisez quelque chose comme ceci, qui tronque le fichier puis vous donne un accès en lecture-écriture :

open my $fh, '+>', '/chemin/nom'; # INCORRECT (presque toujours)

Oups. Vous devriez plutôt utiliser ceci, qui échouera si le fichier n'existe pas :

open my $fh, '+<', '/chemin/nom'; # ouvre en mise à jour

L'utilisation de ">" écrase ou crée toujours. L'utilisation de "<" ne fait jamais ni l'un ni l'autre. Le "+" ne change rien à cela.

Voici des exemples de nombreux types d'ouvertures de fichiers. Ceux qui utilisent "sysopen" supposent tous que vous avez importé les constantes de Fcntl :

use Fcntl;

Pour ouvrir un fichier en lecture :

open my $fh, '<', $path                               ou die $!;
sysopen my $fh, $path, O_RDONLY                       ou die $!;

Pour ouvrir un fichier en écriture, créer un nouveau fichier si nécessaire ou sinon tronquer l'ancien fichier :

open my $fh, '>', $path                               ou die $!;
sysopen my $fh, $path, O_WRONLY|O_TRUNC|O_CREAT       ou die $!;
sysopen my $fh, $path, O_WRONLY|O_TRUNC|O_CREAT, 0666 ou die $!;

Pour ouvrir un fichier en écriture, créer un nouveau fichier, le fichier ne doit pas exister :

sysopen my $fh, $path, O_WRONLY|O_EXCL|O_CREAT        ou die $!;
sysopen my $fh, $path, O_WRONLY|O_EXCL|O_CREAT, 0666  ou die $!;

Pour ouvrir un fichier en ajout, créer si nécessaire :

open my $fh, '>>', $path                              ou die $!;
sysopen my $fh, $path, O_WRONLY|O_APPEND|O_CREAT      ou die $!;
sysopen my $fh, $path, O_WRONLY|O_APPEND|O_CREAT, 0666 ou die $!;

Pour ouvrir un fichier en ajout, le fichier doit exister :

sysopen my $fh, $path, O_WRONLY|O_APPEND              ou die $!;

Pour ouvrir un fichier en mise à jour, le fichier doit exister :

open my $fh, '+<', $path                              ou die $!;
sysopen my $fh, $path, O_RDWR                         ou die $!;

Pour ouvrir un fichier en mise à jour, créer le fichier si nécessaire :

sysopen my $fh, $path, O_RDWR|O_CREAT                 ou die $!;
sysopen my $fh, $path, O_RDWR|O_CREAT, 0666           ou die $!;

Pour ouvrir un fichier en mise à jour, le fichier ne doit pas exister :

sysopen my $fh, $path, O_RDWR|O_EXCL|O_CREAT          ou die $!;
sysopen my $fh, $path, O_RDWR|O_EXCL|O_CREAT, 0666    ou die $!;

Pour ouvrir un fichier sans blocage, en créant si nécessaire :

sysopen my $fh, '/foo/somefile', O_WRONLY|O_NDELAY|O_CREAT
    or die "impossible d'ouvrir /foo/somefile : $!";

Attention, la création et la suppression de fichiers ne sont pas garanties d'être des opérations atomiques sur NFS. Autrement dit, deux processus peuvent à la fois créer ou supprimer le même fichier avec succès ! Par conséquent, O_EXCL n'est pas aussi exclusif que vous pourriez le souhaiter.

Voir aussi perlopentut.

Pourquoi ai-je parfois un message "Argument list too long" quand j'utilise <*> ?

L'opérateur "<>" effectue une opération de glob (voir ci-dessus). Dans les versions de Perl antérieures à v5.6.0, l'opérateur interne glob() déclenche csh(1) pour effectuer l'expansion du glob, mais csh ne peut pas gérer plus de 127 éléments et affiche donc le message d'erreur "Argument list too long". Les personnes qui ont installé tcsh en tant que csh n'auront pas ce problème, mais leurs utilisateurs pourraient en être surpris.

Pour contourner cela, mettez à niveau vers Perl v5.6.0 ou une version ultérieure, effectuez le glob vous-même avec readdir() et des motifs, ou utilisez un module comme File::Glob, un module qui n'utilise pas le shell pour effectuer le glob.

Comment puis-je ouvrir un fichier nommé avec un ">" en début ou des blancs en fin de nom ?

(contribué par Brian McCauley)

La forme spéciale à deux arguments de la fonction open() de Perl ignore les blancs de fin dans les noms de fichiers et déduit le mode de certains caractères de début (ou d'un "|" en fin de nom). Dans les anciennes versions de Perl, c'était la seule version de open() et elle est donc prévalente dans le code et les livres anciens.

À moins d'avoir une raison particulière d'utiliser la forme à deux arguments, vous devriez utiliser la forme à trois arguments de open() qui ne traite aucun caractère du nom de fichier comme spécial.

open my $fh, "<", "  file  ";  # le nom du fichier est "  file  "
open my $fh, ">", ">file";     # le nom du fichier est ">file"

Comment puis-je renommer un fichier de manière fiable ?

Si votre système d'exploitation prend en charge un utilitaire mv(1) approprié ou son équivalent fonctionnel, ceci fonctionne :

rename($old, $new) or system("mv", $old, $new);

Il peut être plus portable d'utiliser plutôt le module File::Copy. Vous copiez simplement le fichier vers le nouveau nom (en vérifiant les valeurs de retour), puis vous supprimez l'ancien. Ce n'est pas vraiment la même chose sémantiquement qu'un rename(), qui préserve les métadonnées comme les permissions, les horodatages, les informations d'inode, etc.

Comment puis-je verrouiller un fichier ?

La fonction intégrée flock() de Perl (voir perlfunc pour les détails) appellera flock(2) si celui-ci existe, fcntl(2) s'il n'existe pas (dans les versions de perl 5.004 et ultérieures), et lockf(3) si aucun des deux appels système précédents n'existe. Sur certains systèmes, il peut même utiliser une forme différente de verrouillage natif. Voici quelques points délicats avec flock() de Perl :

1.
Produit une erreur fatale si aucun des trois appels système (ou leur équivalent proche) n'existe.
2.
lockf(3) ne fournit pas de verrouillage partagé et nécessite que le descripteur de fichier soit ouvert en écriture (ou en ajout, ou en lecture/écriture).
3.
Certaines versions de flock() ne peuvent pas verrouiller les fichiers sur un réseau (par exemple, sur les systèmes de fichiers NFS), vous devrez donc forcer l'utilisation de fcntl(2) lors de la compilation de Perl. Mais même cela est discutable au mieux. Voir l'entrée flock de perlfunc et le fichier INSTALL dans la distribution source pour des informations sur la compilation de Perl pour faire cela.

Deux sémantiques de flock potentiellement non évidentes mais traditionnelles sont qu'elle attend indéfiniment jusqu'à ce que le verrou soit accordé, et que ses verrous sont simplement consultatifs. Ces verrous discrétionnaires sont plus flexibles, mais offrent moins de garanties. Cela signifie que les fichiers verrouillés avec flock() peuvent être modifiés par des programmes qui n'utilisent pas non plus flock(). Les voitures qui s'arrêtent aux feux rouges s'entendent bien entre elles, mais pas avec les voitures qui ne s'arrêtent pas aux feux rouges. Voir la page man perlport, la documentation spécifique à votre port, ou vos pages man locales spécifiques au système pour les détails. Il est préférable de supposer le comportement traditionnel si vous écrivez des programmes portables. (Si ce n'est pas le cas, vous devriez, comme toujours, vous sentir parfaitement libre d'écrire pour les idiosyncrasies de votre propre système (parfois appelées "fonctionnalités"). Une adhérence servile aux préoccupations de portabilité ne devrait pas entraver votre travail.)

Pour plus d'informations sur le verrouillage de fichiers, voir aussi "File Locking" dans perlopentut si vous l'avez (nouveau pour 5.6).

Pourquoi ne puis-je pas simplement ouvrir(FH, ">file.lock") ?

Un morceau de code courant à **NE PAS UTILISER** est le suivant :

sleep(3) while -e 'file.lock';    # S'IL VOUS PLAÎT N'UTILISEZ PAS
open my $lock, '>', 'file.lock'; # CE CODE DÉFECTUEUX

C'est une condition de concurrence classique : vous faites deux étapes pour faire quelque chose qui doit être fait en une seule. C'est pourquoi le matériel informatique fournit une instruction atomique de test et d'ensemble. En théorie, cela "devrait" fonctionner :

sysopen my $fh, "file.lock", O_WRONLY|O_EXCL|O_CREAT
    or die "impossible d'ouvrir file.lock : $!";

sauf que malheureusement, la création (et la suppression) de fichiers n'est pas atomique sur NFS, donc cela ne fonctionnera pas (du moins, pas à chaque fois) sur le réseau. Divers schémas impliquant link() ont été suggérés, mais ceux-ci ont tendance à impliquer une attente active, ce qui est également moins souhaitable.

Je ne comprends toujours pas le verrouillage. Je veux juste incrémenter le chiffre dans le fichier. Comment puis-je faire ça ?

Personne ne vous a dit que les compteurs de visites de pages web étaient inutiles ? Ils ne comptent pas le nombre de visites, ils sont une perte de temps et ne servent qu'à flatter la vanité de l'auteur. Il est préférable de choisir un nombre aléatoire ; ils sont plus réalistes.

Quoi qu'il en soit, voici ce que vous pouvez faire si vous ne pouvez pas vous en empêcher.

use Fcntl qw(:DEFAULT :flock);
sysopen my $fh, "numfile", O_RDWR|O_CREAT or die "impossible d'ouvrir numfile : $!";
flock $fh, LOCK_EX                        or die "impossible de verrouiller numfile : $!";
my $num = <$fh> || 0;
seek $fh, 0, 0                            or die "impossible de rembobiner numfile : $!";
truncate $fh, 0                           or die "impossible de tronquer numfile : $!";
(print $fh $num+1, "\n")                  or die "impossible d'écrire dans numfile : $!";
close $fh                                 or die "impossible de fermer numfile : $!";

Voici un bien meilleur compteur de visites de pages web :

$hits = int( (time() - 850_000_000) / rand(1_000) );

Si le compte n'impressionne pas vos amis, alors le code pourrait le faire. :-)

Tout ce que je veux faire, c'est ajouter une petite quantité de texte à la fin d'un fichier. Dois-je encore utiliser le verrouillage ?

Si vous êtes sur un système qui implémente correctement "flock" et que vous utilisez le code d'ajout d'exemple de "perldoc -f flock", tout ira bien, même si le système d'exploitation sur lequel vous vous trouvez n'implémente pas le mode d'ajout correctement (s'il existe un tel système). Donc, si vous êtes satisfait de vous limiter aux systèmes d'exploitation qui implémentent "flock" (et ce n'est pas vraiment une grande restriction), alors c'est ce que vous devriez faire.

Si vous savez que vous n'utiliserez qu'un système qui implémente correctement l'ajout (c'est-à-dire pas Win32), vous pouvez omettre "seek" du code de la réponse précédente.

Si vous savez que vous écrivez du code destiné à s'exécuter sur un système d'exploitation et un système de fichiers qui implémentent correctement le mode d'ajout (un système de fichiers local sur un Unix moderne, par exemple), et que vous conservez le fichier en mode tamponné par blocs et que vous écrivez moins d'un tampon de sortie entre chaque vidage manuel du tampon, alors chaque charge de tampon est quasiment garantie d'être écrite à la fin du fichier en un seul bloc sans être mélangée avec la sortie de quelqu'un d'autre. Vous pouvez également utiliser la fonction "syswrite" qui n'est qu'un wrapper autour de l'appel système write(2) de votre système.

Il existe toujours une petite possibilité théorique qu'un signal interrompe l'opération write() au niveau du système avant son achèvement. Il est également possible que certaines implémentations STDIO effectuent plusieurs appels système write() même si le tampon était vide au départ. Il peut exister des systèmes où cette probabilité est réduite à zéro, et ce n'est pas une préoccupation lors de l'utilisation de ":perlio" au lieu du STDIO de votre système.

Comment mettre à jour aléatoirement un fichier binaire ?

Si vous essayez simplement de patcher un binaire, dans de nombreux cas, quelque chose d'aussi simple que ceci fonctionne :

perl -i -pe 's{window manager}{window mangler}g' /usr/bin/emacs

Cependant, si vous avez des enregistrements de taille fixe, vous pourriez faire quelque chose de plus similaire à ceci :

my $RECSIZE = 220; # taille de l'enregistrement, en octets
my $recno   = 37;  # quel enregistrement mettre à jour
open my $fh, '+<', 'quelque part' or die "impossible de mettre à jour quelque part : $!";
seek $fh, $recno * $RECSIZE, 0;
read $fh, $record, $RECSIZE == $RECSIZE or die "impossible de lire l'enregistrement $recno : $!";
# modifier l'enregistrement
seek $fh, -$RECSIZE, 1;
print $fh $record;
close $fh;

Comment obtenir l'horodatage d'un fichier en Perl ?

Si vous souhaitez récupérer le moment où le fichier a été lu, écrit ou ses métadonnées (propriétaire, etc.) modifiées pour la dernière fois, vous utilisez les opérations de test de fichier -A, -M ou -C telles que documentées dans perlfunc. Celles-ci récupèrent l'âge du fichier (mesuré par rapport au moment de démarrage de votre programme) en jours sous forme de nombre à virgule flottante. Certaines plateformes peuvent ne pas avoir toutes ces informations. Voir perlport pour les détails. Pour récupérer le temps "brut" en secondes depuis l'époque, vous appelleriez la fonction stat, puis utiliseriez localtime(), gmtime(), ou POSIX::strftime() pour le convertir en un format lisible par l'homme.

Voici un exemple :

my $write_secs = (stat($file))[9];
printf "fichier %s mis à jour à %s\n", $file,
    scalar localtime($write_secs);

Si vous préférez quelque chose de plus lisible, utilisez le module File::stat (qui fait partie de la distribution standard dans les versions 5.004 et ultérieures) :

# vérification des erreurs laissée en exercice pour le lecteur.
use File::stat;
use Time::localtime;
my $date_string = ctime(stat($file)->mtime);
print "fichier $file mis à jour à $date_string\n";

L'approche POSIX::strftime() a l'avantage d'être, en théorie, indépendante de la locale actuelle. Voir perllocale pour les détails.

Comment définir l'horodatage d'un fichier en Perl ?

Vous utilisez la fonction utime() documentée dans "utime" dans perlfunc. À titre d'exemple, voici un petit programme qui copie les heures de lecture et d'écriture de son premier argument à tous les autres.

if (@ARGV < 2) {
    die "utilisation : cptimes fichier_horodatage autres_fichiers ...\n";
}
my $timestamp = shift;
my($atime, $mtime) = (stat($timestamp))[8,9];
utime $atime, $mtime, @ARGV;

La vérification des erreurs est, comme d'habitude, laissée en exercice pour le lecteur.

La documentation perldoc pour utime contient également un exemple qui a le même effet que touch(1) sur les fichiers qui existent déjà.

Certains systèmes de fichiers ont une capacité limitée à stocker les heures sur un fichier au niveau de précision attendu. Par exemple, les systèmes de fichiers FAT et HPFS sont incapables de créer des dates sur les fichiers avec une granularité plus fine que deux secondes. C'est une limitation des systèmes de fichiers, pas de utime().

Comment imprimer dans plusieurs fichiers à la fois ?

Pour connecter un descripteur de fichier à plusieurs descripteurs de fichier de sortie, vous pouvez utiliser les modules IO::Tee ou Tie::FileHandle::MultiPlex.

Si vous n'avez à le faire qu'une seule fois, vous pouvez imprimer individuellement dans chaque descripteur de fichier.

for my $fh ($fh1, $fh2, $fh3) { print $fh "quelque chose\n" }

Comment lire un fichier entier d'un coup ?

L'approche Perl habituelle pour traiter toutes les lignes d'un fichier est de le faire ligne par ligne :

open my $input, '<', $file or die "impossible d'ouvrir $file : $!";
while (<$input>) {
    chomp;
    # faire quelque chose avec $_
}
close $input or die "impossible de fermer $file : $!";

C'est beaucoup plus efficace que de lire tout le fichier en mémoire sous forme de tableau de lignes, puis de le traiter élément par élément, ce qui est souvent - sinon presque toujours - la mauvaise approche. Chaque fois que vous voyez quelqu'un faire ceci :

my @lines = <INPUT>;

Vous devriez réfléchir sérieusement à la raison pour laquelle vous avez besoin que tout soit chargé en même temps. Ce n'est tout simplement pas une solution évolutive.

Si vous "mmap" le fichier avec le module File::Map de CPAN, vous pouvez charger virtuellement tout le fichier dans une chaîne sans le stocker réellement en mémoire :

use File::Map qw(map_file);
map_file my $string, $filename;

Une fois mappé, vous pouvez traiter $string comme n'importe quelle autre chaîne. Comme vous n'avez pas nécessairement besoin de charger les données, le mmap-ing peut être très rapide et n'augmente pas nécessairement votre empreinte mémoire.

Vous pourriez également trouver plus amusant d'utiliser le module standard Tie::File, ou les liaisons $DB_RECNO du module DB_File, qui vous permettent d'associer un tableau à un fichier de sorte que l'accès à un élément du tableau accède en fait à la ligne correspondante dans le fichier.

Si vous voulez charger tout le fichier, vous pouvez utiliser le module Path::Tiny pour le faire en une seule étape simple et efficace :

use Path::Tiny;
my $all_of_it = path($filename)->slurp; # tout le fichier en scalaire
my @all_lines = path($filename)->lines; # une ligne par élément

Ou vous pouvez lire tout le contenu du fichier dans un scalaire comme ceci :

my $var;
{
    local $/;
    open my $fh, '<', $file or die "impossible d'ouvrir $file : $!";
    $var = <$fh>;
}

Cela annule temporairement votre séparateur d'enregistrements et fermera automatiquement le fichier à la sortie du bloc. Si le fichier est déjà ouvert, utilisez simplement ceci :

my $var = do { local $/; <$fh> };

Vous pouvez également utiliser un @ARGV localisé pour éliminer l'"open" :

my $var = do { local( @ARGV, $/ ) = $file; <> };

Comment lire un fichier par paragraphes ?

Utilisez la variable $/ (voir perlvar pour les détails). Vous pouvez soit la définir sur "" pour éliminer les paragraphes vides ("abc\n\n\n\ndef", par exemple, est traité comme deux paragraphes et non trois), soit sur "\n\n" pour accepter les paragraphes vides.

Notez qu'une ligne vide ne doit contenir aucun blanc. Ainsi, "fred\n \nstuff\n\n" est un paragraphe, mais "fred\n\nstuff\n\n" en sont deux.

Comment lire un seul caractère d'un fichier ? Du clavier ?

Vous pouvez utiliser la fonction intégrée getc() pour la plupart des descripteurs de fichiers, mais elle ne fonctionnera pas (facilement) sur un terminal. Pour STDIN, utilisez soit le module Term::ReadKey de CPAN, soit le code d'exemple dans "getc" dans perlfunc.

Si votre système prend en charge l'interface de programmation du système d'exploitation portable (POSIX), vous pouvez utiliser le code suivant, qui, vous le remarquerez, désactive également le traitement de l'écho.

#!/usr/bin/perl -w
use strict;
$| = 1;
for (1..4) {
    print "entrez : ";
    my $got = getone();
    print "--> $got\n";
}
exit;
BEGIN {
    use POSIX qw(:termios_h);
    my ($term, $oterm, $echo, $noecho, $fd_stdin);
    my $fd_stdin = fileno(STDIN);
    $term     = POSIX::Termios->new();
    $term->getattr($fd_stdin);
    $oterm     = $term->getlflag();
    $echo     = ECHO | ECHOK | ICANON;
    $noecho   = $oterm & ~$echo;
    sub cbreak {
        $term->setlflag($noecho);
        $term->setcc(VTIME, 1);
        $term->setattr($fd_stdin, TCSANOW);
    }
    sub cooked {
        $term->setlflag($oterm);
        $term->setcc(VTIME, 0);
        $term->setattr($fd_stdin, TCSANOW);
    }
    sub getone {
        my $key = '';
        cbreak();
        sysread(STDIN, $key, 1);
        cooked();
        return $key;
    }
}
END { cooked() }

Le module Term::ReadKey de CPAN peut être plus facile à utiliser. Les versions récentes incluent également la prise en charge

Comment savoir s'il y a un caractère en attente sur un descripteur de fichier ?

La toute première chose à faire est de vous procurer l'extension Term::ReadKey depuis CPAN. Comme nous l'avons mentionné précédemment, elle prend désormais en charge même les systèmes non portables (c'est-à-dire : systèmes fermés, propriétaires, non POSIX, non Unix, etc.).

Vous devriez également consulter la liste des questions fréquemment posées dans comp.unix.* pour ce genre de chose : la réponse est essentiellement la même. C'est très dépendant du système. Voici une solution qui fonctionne sur les systèmes BSD :

sub key_ready {
    my($rin, $nfd);
    vec($rin, fileno(STDIN), 1) = 1;
    return $nfd = select($rin,undef,undef,0);
}

Si vous voulez savoir combien de caractères sont en attente, il y a aussi l'appel ioctl FIONREAD à examiner. L'outil h2ph qui vient avec Perl essaie de convertir les fichiers d'en-tête C en code Perl, qui peut être "require"d. FIONREAD finit par être défini comme une fonction dans le fichier sys/ioctl.ph :

require './sys/ioctl.ph';
$size = pack("L", 0);
ioctl(FH, FIONREAD(), $size)    or die "Impossible d'appeler ioctl: $!\n";
$size = unpack("L", $size);

Si h2ph n'était pas installé ou ne fonctionne pas pour vous, vous pouvez grep les fichiers d'en-tête à la main :

% grep FIONREAD /usr/include/*/*
/usr/include/asm/ioctls.h:#define FIONREAD      0x541B

Ou écrire un petit programme C en utilisant l'éditeur des champions :

% cat > fionread.c
#include <sys/ioctl.h>
main() {
    printf("%#08x\n", FIONREAD);
}
^D
% cc -o fionread fionread.c
% ./fionread
0x4004667f

Et ensuite le coder en dur, laissant le portage comme exercice à votre successeur.

$FIONREAD = 0x4004667f;         # XXX: dépendant de l'OS
$size = pack("L", 0);
ioctl(FH, $FIONREAD, $size)     or die "Impossible d'appeler ioctl: $!\n";
$size = unpack("L", $size);

FIONREAD nécessite un descripteur de fichier connecté à un flux, ce qui signifie que les sockets, les pipes et les périphériques tty fonctionnent, mais pas les fichiers.

Comment faire un "tail -f" en perl ?

Essayez d'abord

seek($gw_fh, 0, 1);

L'instruction "seek($gw_fh, 0, 1)" ne modifie pas la position actuelle, mais elle efface la condition de fin de fichier sur le descripteur, de sorte que le prochain "<$gw_fh>" fait que Perl essaie à nouveau de lire quelque chose.

Si cela ne fonctionne pas (cela repose sur les fonctionnalités de votre implémentation stdio), vous avez besoin de quelque chose de plus similaire à ceci :

for (;;) {
  for ($curpos = tell($gw_fh); <$gw_fh>; $curpos =tell($gw_fh)) {
    # chercher quelque chose et le mettre dans des fichiers
  }
  # dormir un peu
  seek($gw_fh, $curpos, 0);  # se positionner là où nous étions
}

Si cela ne fonctionne toujours pas, examinez la méthode "clearerr" de IO::Handle, qui réinitialise les états d'erreur et de fin de fichier sur le descripteur.

Il existe également un module File::Tail sur CPAN.

Comment faire un dup() d'un descripteur de fichier en Perl ?

Si vous consultez "open" dans perlfunc, vous verrez que plusieurs des façons d'appeler open() devraient faire l'affaire. Par exemple :

open my $log, '>>', '/foo/logfile';
open STDERR, '>&', $log;

Ou même avec un descripteur numérique littéral :

my $fd = $ENV{MHCONTEXTFD};
open $mhcontext, "<&=$fd";  # comme fdopen(3S)

Notez que "<&STDIN" crée une copie, mais "<&=STDIN" crée un alias. Cela signifie que si vous fermez un descripteur aliasé, tous les alias deviennent inaccessibles. Ce n'est pas le cas avec un descripteur copié.

La gestion des erreurs, comme toujours, a été laissée comme exercice au lecteur.

Comment fermer un descripteur de fichier par numéro ?

Si, pour une raison quelconque, vous avez un descripteur de fichier au lieu d'un descripteur de flux (peut-être avez-vous utilisé "POSIX::open"), vous pouvez utiliser la fonction close() du module POSIX :

use POSIX ();
POSIX::close( $fd );

Cela ne devrait être nécessaire que rarement, car la fonction close() de Perl est à utiliser pour les choses que Perl a ouvertes lui-même, même s'il s'agissait d'un dup d'un descripteur numérique comme avec "MHCONTEXT" ci-dessus. Mais si vous devez vraiment le faire, vous pourrez peut-être faire ceci :

require './sys/syscall.ph';
my $rc = syscall(SYS_close(), $fd + 0);  # forcer à être numérique
die "impossible de sysclose $fd: $!" if $rc == -1;

Ou, utilisez simplement la fonctionnalité fdopen(3S) de open() :

{
    open my $fh, "<&=$fd" or die "Impossible de rouvrir fd=$fd: $!";
    close $fh;
}

Pourquoi ne puis-je pas utiliser "C:\temp\foo" dans les chemins DOS ? Pourquoi `C:\temp\foo.exe` ne fonctionne-t-il pas ?

Oups ! Vous venez d'insérer une tabulation et un saut de page dans ce nom de fichier ! N'oubliez pas qu'à l'intérieur des chaînes entre guillemets doubles ("comme\ça"), la barre oblique inverse est un caractère d'échappement. La liste complète de ces caractères se trouve dans "Quote and Quote-like Operators" dans perlop. Sans surprise, vous n'avez pas de fichier nommé "c:(tab)emp(saut de page)oo" ou "c:(tab)emp(saut de page)oo.exe" sur votre système de fichiers DOS hérité.

Soit mettez vos chaînes entre apostrophes, soit (de préférence) utilisez des barres obliques. Comme toutes les versions de DOS et de Windows depuis environ MS-DOS 2.0 ou plus ont traité "/" et "\" de la même manière dans un chemin, vous pourriez aussi bien utiliser celle qui n'entre pas en conflit avec Perl - ou le shell POSIX, ANSI C et C++, awk, Tcl, Java, ou Python, pour n'en mentionner que quelques-uns. Les chemins POSIX sont également plus portables.

Pourquoi glob("*. *") ne récupère-t-il pas tous les fichiers ?

Parce que même sur les ports non Unix, la fonction glob de Perl suit la sémantique standard de globbing Unix. Vous aurez besoin de glob("*") pour obtenir tous les fichiers (non cachés). Cela rend glob() portable même vers les systèmes hérités. Votre port peut également inclure des fonctions de globbing propriétaires. Consultez sa documentation pour plus de détails.

Pourquoi Perl me laisse-t-il supprimer des fichiers en lecture seule ? Pourquoi "-i" écrase-t-il des fichiers protégés ? N'est-ce pas un bug dans Perl ?

Ceci est décrit de manière élaborée et minutieuse dans l'article file-dir-perms de la collection "Far More Than You Ever Wanted To Know" sur http://www.cpan.org/misc/olddoc/FMTEYEWTK.tgz.

Le résumé exécutif : apprenez comment fonctionne votre système de fichiers. Les permissions d'un fichier indiquent ce qui peut être fait avec les données de ce fichier. Les permissions d'un répertoire indiquent ce qui peut être fait avec la liste des fichiers dans ce répertoire. Si vous supprimez un fichier, vous supprimez son nom du répertoire (donc l'opération dépend des permissions du répertoire, pas de celles du fichier). Si vous essayez d'écrire dans le fichier, les permissions du fichier régissent si vous êtes autorisé à le faire.

Comment sélectionner une ligne aléatoire d'un fichier ?

Sans charger le fichier dans une base de données ou pré-indexer les lignes du fichier, il y a quelques choses que vous pouvez faire.

Voici un algorithme d'échantillonnage par réservoir du livre du Chameau :

srand;
rand($.) < 1 && ($line = $_) while <>;

Cela présente un avantage significatif en termes d'espace par rapport à la lecture de l'ensemble du fichier. Vous pouvez trouver une preuve de cette méthode dans The Art of Computer Programming, Volume 2, Section 3.4.2, par Donald E. Knuth.

Vous pouvez utiliser le module File::Random qui fournit une fonction pour cet algorithme :

use File::Random qw/random_line/;
my $line = random_line($filename);

Une autre façon est d'utiliser le module Tie::File, qui traite l'ensemble du fichier comme un tableau. Accédez simplement à un élément aléatoire du tableau.

Pourquoi ai-je des espaces étranges lorsque j'affiche un tableau de lignes ?

(contribué par brian d foy)

Si vous voyez des espaces entre les éléments de votre tableau lorsque vous affichez le tableau, vous êtes probablement en train d'interpoler le tableau dans des guillemets doubles :

my @animals = qw(camel llama alpaca vicuna);
print "animals are: @animals\n";

Ce sont les guillemets doubles, pas la commande "print", qui font cela. Chaque fois que vous interpollez un tableau dans un contexte de guillemets doubles, Perl joint les éléments avec des espaces (ou quoi que ce soit dans $", qui est un espace par défaut) :

animals are: camel llama alpaca vicuna

C'est différent de l'affichage du tableau sans l'interpolation :

my @animals = qw(camel llama alpaca vicuna);
print "animals are: ", @animals, "\n";

Maintenant, la sortie n'a pas d'espaces entre les éléments car les éléments de @animals deviennent simplement partie de la liste à afficher par "print" :

animals are: camelllamaalpacavicuna

Vous pourriez remarquer cela lorsque chaque élément de @array se termine par un saut de ligne. Vous vous attendez à afficher un élément par ligne, mais vous remarquez que chaque ligne après la première est indentée :

this is a line
 this is another line
 this is the third line

Cet espace supplémentaire provient de l'interpolation du tableau. Si vous ne voulez rien mettre entre les éléments de @array

How do I find files with a certain name in a directory tree?

(contributed by brian d foy)

The File::Find module, which comes with Perl, does all of the hard work to traverse a directory structure. You simply call the find() subroutine with a callback subroutine and the directories you want to traverse:

use File::Find;
find( \&wanted, @directories );
sub wanted {
    # full path in $File::Find::name
    # just filename in $_
    ... do whatever you want to do ...
}

The File::Find::Closures, which you can download from CPAN, provides many ready-to-use subroutines that you can use with File::Find.

The File::Finder, which you can download from CPAN, can help you create the callback subroutine using something closer to the syntax of the find command-line utility:

use File::Find;
use File::Finder;
my $deep_dirs = File::Finder->depth->type('d')->ls->exec('rmdir','{}');
find( $deep_dirs->as_options, @places );

The File::Find::Rule module, which you can download from CPAN, has a similar interface, but does the traversal for you too:

use File::Find::Rule;
my @files = File::Find::Rule->file()
                         ->name( '*.pm' )
                         ->in( @INC );

How do I delete a directory tree?

(contributed by brian d foy)

If you have an empty directory, you can use Perl's built-in rmdir(). If the directory is not empty (so, with files or subdirectories), you either have to empty it yourself (a lot of work) or use a module to help you.

The File::Path module, which comes with Perl, has a remove_tree() which can take care of all of the hard work for you:

use File::Path qw(remove_tree);
remove_tree( @directories );

The File::Path module also has a legacy interface to the older rmtree() subroutine.

How do I copy an entire directory?

(contributed by Shlomi Fish)

To do the equivalent of cp -R (i.e. copy an entire directory tree recursively) in portable Perl, you'll either need to write something yourself or find a good CPAN module such as File::Copy::Recursive.
