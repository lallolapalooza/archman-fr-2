NOM

pgrep, pkill, pidwait - rechercher, signaler ou attendre des processus basés sur le nom et d'autres attributs

SYNOPIS

pgrep [option ...] motif

pkill [option ...] motif

pidwait [option ...] motif

DESCRIPTION

pgrep parcourt les processus actuellement en cours d'exécution et liste les identifiants de processus qui correspondent aux critères de sélection sur la sortie standard. Tous les critères doivent correspondre. Par exemple,

$ pgrep -u root sshd

n'affichera que les processus dont le nom inclut sshd ET qui appartiennent à root. D'un autre côté,

$ pgrep -u root,daemon

affichera les processus appartenant à root OU daemon.

pkill enverra le signal spécifié (par défaut SIGTERM) à chaque processus au lieu de les lister sur la sortie standard.

pidwait attendra chaque processus au lieu de les lister sur la sortie standard.

OPTIONS

-signal
--signal signal
Définit le signal à envoyer à chaque processus correspondant. Le signal peut être spécifié par sa valeur numérique ou son nom symbolique. Dans les modes pgrep ou pidwait, seule l'option longue peut être utilisée et elle n'a d'effet que si elle est utilisée conjointement avec --require-handler pour filtrer les processus ayant un gestionnaire de signal en espace utilisateur présent pour un signal particulier.
-c, --count
Supprime la sortie normale ; affiche à la place un décompte des processus correspondants. Lorsque le décompte ne correspond à rien, par exemple renvoie zéro, la commande renverra une valeur non nulle. Notez que pour pkill et pidwait, le décompte est le nombre de processus correspondants, pas les processus qui ont été signalés ou attendus avec succès.
-d, --delimiter delimiteur
Définit la chaîne utilisée pour séparer chaque identifiant de processus dans la sortie (par défaut, une nouvelle ligne). (pgrep uniquement.)
-e, --echo
Affiche le nom et le PID du processus en cours de suppression. (pkill uniquement.)
-f, --full
Le motif est normalement comparé uniquement au nom du processus. Lorsque -f est activé, la ligne de commande complète est utilisée.
-g, --pgroup pgrp,...
Ne faire correspondre que les processus appartenant aux groupes de processus listés. Le groupe de processus 0 est traduit en son propre groupe de processus pour pgrep, pkill, ou pidwait.
-G, --group gid,...
Ne faire correspondre que les processus dont l'identifiant de groupe réel est listé. La valeur numérique ou symbolique peut être utilisée.
-i, --ignore-case
Faire correspondre les processus sans tenir compte de la casse.
-l, --list-name
Lister le nom du processus ainsi que son identifiant. (pgrep uniquement.)
-a, --list-full
Lister la ligne de commande complète ainsi que l'identifiant du processus. (pgrep uniquement.)
-n, --newest
Sélectionner uniquement le plus récent (lancé le plus récemment) des processus correspondants.
-o, --oldest
Sélectionner uniquement le plus ancien (lancé le moins récemment) des processus correspondants.
-O, --older secs
Sélectionner les processus plus anciens que secs.
-P, --parent ppid,...
Ne faire correspondre que les processus dont l'identifiant de processus parent est listé.
-s, --session sid,...
Ne faire correspondre que les processus dont l'identifiant de session est listé. L'identifiant de session 0 est traduit en son propre identifiant de session pour pgrep, pkill, ou pidwait.
-t, --terminal term,...
Ne faire correspondre que les processus dont le terminal de contrôle est listé. Le nom du terminal doit être spécifié sans le préfixe "/dev/".
-u, --euid euid,...
Ne faire correspondre que les processus dont l'identifiant utilisateur effectif est listé. La valeur numérique ou symbolique peut être utilisée.
-U, --uid uid,...
Ne faire correspondre que les processus dont l'identifiant utilisateur réel est listé. La valeur numérique ou symbolique peut être utilisée.
-v, --inverse
Inverse la correspondance. Cette option est généralement utilisée dans le contexte de pgrep ou pidwait. Dans le contexte de pkill, l'option courte est désactivée pour éviter une utilisation accidentelle de l'option.
-w, --lightweight
Affiche tous les identifiants de threads au lieu des identifiants de processus dans le contexte de pgrep ou pidwait. Dans le contexte de pkill, cette option est désactivée.
-x, --exact
Ne faire correspondre que les processus dont les noms (ou les lignes de commande si -f est spécifié) correspondent exactement au motif.
-F, --pidfile fichier
Lit les PID à partir du fichier. Cette option est plus utile pour pkill ou pidwait que pour pgrep. Le nom de fichier "-" peut être utilisé pour lire depuis STDIN.
-L, --logpidfile
Échoue si le fichier de pid (voir -F) n'est pas verrouillé.
-r, --runstates D,R,S,Z,...
Ne faire correspondre que les processus qui correspondent à l'état du processus.
-A, --ignore-ancestors
Ignore tous les ancêtres de pgrep, pkill, ou pidwait. Par exemple, cela peut être utile lors de l'élévation avec sudo ou des outils similaires.
-H, --require-handler
Ne faire correspondre que les processus ayant un gestionnaire de signal en espace utilisateur présent pour le signal à envoyer.
--cgroup nom,...
Faire correspondre le groupe de contrôle (cgroup) v2 fourni. Voir cgroups(8)
--env nom[=valeur],...
Faire correspondre les processus qui ont ces variables d'environnement. Si le paramètre =valeur n'est pas défini, seule la variable est mise en correspondance.
--ns pid
Faire correspondre les processus qui appartiennent aux mêmes espaces de noms. Nécessite d'être exécuté en tant que root pour faire correspondre les processus d'autres utilisateurs. Voir --nslist pour savoir comment limiter les espaces de noms à faire correspondre.
--nslist nom,...
Ne faire correspondre que les espaces de noms fournis. Espaces de noms disponibles : ipc, mnt, net, pid, user, uts.
-q, --queue valeur
Utiliser sigqueue(3) plutôt que kill(2) et l'argument valeur est utilisé pour spécifier un entier à envoyer avec le signal. Si le processus récepteur a installé un gestionnaire pour ce signal en utilisant le drapeau SA_SIGINFO à sigaction(2), alors il peut obtenir ces données via le champ si_value de la structure siginfo_t.
-V, --version
Affiche les informations de version et quitte.
-h, --help
Affiche l'aide et quitte.

OPERANDES

motif
Spécifie une expression régulière étendue pour la mise en correspondance avec les noms de processus ou les lignes de commande.

NOM

pkill, pgrep, pidwait — envoyer des signaux ou rechercher des processus par nom ou par d'autres attributs.

SYNOPIS

pkill [options] [signal] motif
pgrep [options] [motif]
pidwait [options] PID...

DESCRIPTION

Ces utilitaires lisent la liste des processus en cours sur le système, sélectionnent ceux qui correspondent aux critères spécifiés par les options, puis, pour pkill et pidwait, envoient un signal à chaque processus correspondant. pgrep affiche les identifiants de processus (PID) des processus correspondants.

Le motif est une expression régulière qui est appliquée au nom du processus ou à la ligne de commande complète (si l'option -f est utilisée). Si aucun motif n'est spécifié, pkill enverra le signal à tous les processus (ce qui est généralement une mauvaise idée).

OPTIONS

Les options communes à pkill et pgrep incluent :

-a, --list-full
Affiche la ligne de commande complète de chaque processus correspondant.
-c, --count
Affiche uniquement le nombre de processus correspondants.
-d, --delimiter chaîne
Spécifie le délimiteur à utiliser entre les PID lors de l'affichage. La valeur par défaut est le saut de ligne.
-e, --exact
Correspond exactement au nom du processus ou à la ligne de commande complète. Ceci est généralement utilisé avec l'option -x pour une correspondance exacte.
-f, --full
Correspond au motif sur la ligne de commande complète du processus, plutôt que sur le nom du processus uniquement.
-g, --group groupe
Correspond aux processus appartenant au groupe spécifié (par nom ou PID).
-G, --real-group groupe
Correspond aux processus dont le groupe réel spécifié (par nom ou PID).
-i, --ignore-case
Ignore la casse lors de la correspondance des motifs.
-l, --list-name
Affiche le nom de chaque processus correspondant, suivi du PID.
-n, --newest
Correspond au processus le plus récent.
-o, --oldest
Correspond au processus le plus ancien.
-O, --older fichier
Correspond au processus le plus ancien parmi ceux qui sont plus vieux que le fichier spécifié.
-p, --pid pid
Correspond uniquement au PID spécifié.
-P, --parent pid
Correspond uniquement aux processus dont le PID parent est celui spécifié.
-t, --terminal tty
Correspond aux processus associés au terminal spécifié.
-u, --user utilisateur
Correspond aux processus appartenant à l'utilisateur spécifié (par nom ou UID).
-U, --real-user utilisateur
Correspond aux processus dont l'utilisateur réel spécifié (par nom ou UID).
-v, --cumulative
Correspond au processus ayant le plus de temps CPU utilisé cumulativement.
-x, --regex-exact
Correspond au nom du processus ou à la ligne de commande complète exactement au motif.

Options spécifiques à pkill :

signal
Le signal à envoyer. Peut être un nom de signal (par ex. HUP) ou un numéro. Le signal par défaut est TERM.

Options spécifiques à pidwait :

-F, --force
Ne pas afficher les messages d'erreur si un PID n'est pas trouvé.

OPÉRANDES

Les PID sur lesquels agir (pour pidwait) sont une liste d'identifiants de processus.

EXEMPLES

Exemple 1 : Trouver l'identifiant de processus du démon named :

$ pgrep -u root named

Exemple 2 : Faire relire sa configuration à syslog :

$ pkill -HUP syslogd

Exemple 3 : Donner des informations détaillées sur tous les processus xterm :

$ ps -fp $(pgrep -d, -x xterm)

Exemple 4 : Faire tourner tous les processus chrome avec une priorité plus basse :

$ renice +4 $(pgrep chrome)

Exemple 5 : Attendre qu'un processus avec un PID connu se termine :

$ echo ${PID} | pidwait -F -

STATUT DE SORTIE

0
Un ou plusieurs processus ont correspondu aux critères. Pour pkill et pidwait, un ou plusieurs processus doivent également avoir été signalés ou attendus avec succès.
1
Aucun processus n'a correspondu ou aucun d'entre eux n'a pu être signalé.
2
Erreur de syntaxe dans la ligne de commande.
3
Erreur fatale : manque de mémoire, etc.

NOTES

Le nom du processus utilisé pour la correspondance est limité aux 15 caractères présents dans la sortie de /proc/pid/stat. Utilisez l'option -f pour correspondre à la ligne de commande complète, /proc/pid/cmdline. Les threads peuvent ne pas avoir le même nom de processus que le processus parent mais auront la même ligne de commande.

Le processus pgrep, pkill ou pidwait en cours d'exécution ne se signalera jamais lui-même comme correspondant.

L'option -O --older échouera silencieusement si /proc est monté avec l'option subset=pid.

BOGUES

Les options -n et -o et -v ne peuvent pas être combinées. Faites savoir si vous avez besoin de faire cela.

Les processus défunts sont signalés.

pidwait nécessite l'appel système pidfd_open(2) qui est apparu pour la première fois sous Linux 5.3.
