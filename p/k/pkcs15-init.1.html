NOM

pkcs15-init - utilitaire de personnalisation de carte à puce

SYNTAXE

pkcs15-init [OPTIONS]

DESCRIPTION

L'utilitaire pkcs15-init peut être utilisé pour créer une structure PKCS #15 sur une carte à puce, et ajouter des objets clés ou certificats. Les détails de la structure qui sera créée sont contrôlés via des profils.

Le profil utilisé par défaut est pkcs15. D'autres profils peuvent être spécifiés via l'option -p.

UTILISATION DU CODE PIN

pkcs15-init peut être utilisé pour créer une structure PKCS #15 sur votre carte à puce, créer des codes PIN, et installer des clés et certificats sur la carte. Ce processus est également appelé personnalisation.

Une carte OpenSC peut avoir un code PIN d'administrateur système (SO), et zéro ou plusieurs codes PIN utilisateurs. PIN signifie Personal Identification Number (Numéro d'Identification Personnel), et est un code secret que vous devez présenter à la carte avant d'être autorisé à effectuer certaines opérations, telles que l'utilisation d'une des clés RSA stockées pour signer un document, ou modifier la carte elle-même.

Habituellement, les codes PIN sont une séquence de chiffres décimaux, mais certaines cartes acceptent des caractères ASCII arbitraires. Soyez toutefois conscient qu'utiliser des caractères autres que des chiffres rendra la carte inutilisable avec les lecteurs à pavé numérique, car ceux-ci ont généralement uniquement des touches pour entrer des chiffres.

Le code PIN de l'administrateur système (SO) est spécial ; il est utilisé pour protéger les informations de métadonnées sur la carte, telles que la structure PKCS #15 elle-même. Définir le code PIN SO est facultatif, car le pire qui puisse généralement arriver est que quelqu'un trouvant votre carte puisse la perturber. Pour extraire l'une de vos clés secrètes stockées sur la carte, un attaquant aura toujours besoin de votre code PIN utilisateur, du moins pour les profils OpenSC par défaut. Cependant, il est possible de créer des profils de carte qui permettront à l'administrateur système de remplacer les codes PIN utilisateurs.

Pour chaque code PIN, vous pouvez spécifier un PUK (également appelé code de déblocage). Le PUK peut être utilisé pour remplacer ou déverrouiller un code PIN si trop de valeurs incorrectes ont été saisies consécutivement.

Pour certaines cartes qui utilisent l'émulation PKCS#15, les attributs des objets privés sont protégés et ne peuvent pas être analysés sans authentification (généralement avec le PIN utilisateur). Cette authentification doit être effectuée immédiatement après la liaison de la carte. Dans de tels cas, --verify-pin doit être utilisé.

MODES DE FONCTIONNEMENT

Initialisation

C'est la première étape de la personnalisation de la carte, et elle créera les fichiers de base sur la carte. Pour créer la structure PKCS #15 initiale, invoquez l'utilitaire comme suit :

pkcs15-init --create-pkcs15

Il vous sera ensuite demandé le code PIN et le PUK de l'administrateur système. Appuyer simplement sur retour à l'invite du code PIN SO ignorera l'installation d'un code PIN SO.

Si la carte le prend en charge, vous devriez effacer le contenu de la carte avec pkcs15-init --erase-card avant de créer la structure PKCS#15.

Installation du code PIN utilisateur

Avant d'installer des objets utilisateurs tels que des clés privées, vous avez besoin d'au moins un code PIN pour protéger ces objets. vous pouvez le faire en utilisant :

pkcs15-init --store-pin --id " nn

où nn est un ID PKCS #15 en notation hexadécimale. Les valeurs courantes sont 01, 02, etc.

La saisie de la commande ci-dessus vous demandera le code PIN et le PUK de l'utilisateur. Si vous ne souhaitez pas installer de code de déblocage, appuyez simplement sur retour à l'invite du PUK.

Pour définir une étiquette pour cet objet PIN (qui peut être utilisée par les applications pour afficher une invite significative à l'utilisateur), utilisez l'option de ligne de commande --label.

Génération de clé

pkcs15-init vous permet de générer une nouvelle clé et de la stocker sur la carte. Vous pouvez le faire en utilisant :

pkcs15-init --generate-key "spécification_clé" --auth-id "nn"

où spécification_clé décrit l'algorithme et les paramètres de la clé à créer. Par exemple, rsa:2048 génère une clé RSA avec un module de 2048 bits. Si vous générez une clé EC, la désignation de la courbe doit être spécifiée, par exemple ec:prime256v1. Pour les clés symétriques, la longueur de la clé est spécifiée en octets, par exemple AES:32 ou DES3:24.

nn est l'ID d'un code PIN utilisateur installé précédemment, par exemple 01.

En plus de stocker la partie privée de la clé sur la carte, pkcs15-init stockera également la partie publique de la clé sous forme d'objet clé publique PKCS #15.

Téléversement de clé privée

Vous pouvez utiliser une clé privée générée par d'autres moyens et la téléverser sur la carte. Par exemple, pour téléverser une clé privée contenue dans un fichier nommé okir.pem, qui est au format PEM, vous utiliseriez :

pkcs15-init --store-private-key okir.pem --id 45 --auth-id 01

En plus de stocker la partie privée de la clé sur la carte, pkcs15-init stockera également la partie publique de la clé sous forme d'objet clé publique PKCS #15.

Notez que l'utilisation de l'option --id dans les commandes pkcs15-init pour générer ou importer une nouvelle clé est dépréciée. Une meilleure pratique consiste à laisser le middleware dériver l'identifiant du matériel clé. (SHA1(module) pour RSA, ...). Cela permet d'établir facilement une relation entre des objets 'liés' (clés privées/publiques et certificats).

En plus du format de fichier de clé PEM, pkcs15-init prend également en charge les clés codées en DER, et les fichiers PKCS #12. Ce dernier est le format de fichier utilisé par Netscape Navigator (entre autres) lors de l'exportation de certificats vers un fichier. Un fichier PKCS #12 contient généralement le certificat X.509 correspondant à la clé privée. Si tel est le cas, pkcs15-init stockera le certificat au lieu de la partie clé publique.

Téléversement de clé publique

Vous pouvez également téléverser des clés publiques individuelles sur la carte en utilisant l'option --store-public-key, qui prend un nom de fichier comme argument. Ce fichier est censé contenir la clé publique. Si vous ne spécifiez pas de format de fichier clé à l'aide de l'option --format, pkcs15-init supposera le format PEM. Le seul autre format de fichier de clé publique pris en charge est DER.

Comme les clés publiques correspondantes sont toujours téléversées automatiquement lors de la génération d'une nouvelle clé, ou lors du téléversement d'une clé privée, vous utiliserez probablement cette option très rarement.

Téléversement de certificat

Vous pouvez téléverser des certificats sur la carte en utilisant l'option --store-certificate, qui prend un nom de fichier comme argument. Ce fichier est censé contenir le certificat X.509 encodé en PEM.

Téléversement de sacs PKCS #12

La plupart des navigateurs utilisent aujourd'hui le format PKCS #12 lorsque vous leur demandez d'exporter votre clé et votre certificat dans un fichier. pkcs15-init est capable d'analyser ces fichiers et de stocker leur contenu sur la carte en une seule opération. Cela fonctionne comme le stockage d'une clé privée, sauf que vous devez spécifier le format du fichier :

pkcs15-init --store-private-key okir.p12 --format pkcs12 --auth-id 01

Cela installera la clé privée contenue dans le fichier okir.p12, et la protégera avec le code PIN référencé par l'ID d'authentification 01. Il stockera également tous les certificats X.509 contenus dans le fichier, qui est généralement le certificat utilisateur qui va avec la clé, ainsi que le certificat de l'AC.

Téléversement de clé secrète

Vous pouvez utiliser une clé secrète générée par d'autres moyens et la téléverser sur la carte. Par exemple, pour téléverser une clé secrète AES générée par le générateur aléatoire système, vous utiliseriez :

pkcs15-init --store-secret-key /dev/urandom --secret-key-algorithm aes:256 --auth-id 01

Par défaut, un ID aléatoire est généré pour la clé secrète. Vous pouvez spécifier un ID avec --id si nécessaire.

OPTIONS

--version,

Imprimer la version du paquet OpenSC.

--card-profile nom, -c nom

Indique à pkcs15-init de charger l'option de profil de carte spécifiée. Vous aurez rarement besoin de cette option.

--create-pkcs15, -C

Ceci indique à pkcs15-init de créer une structure PKCS #15 sur la carte et d'initialiser toutes les PINs.

--serial NUMÉROSÉRIE

Spécifie le numéro de série de la carte.

--erase-card, -E

Ceci effacera la carte avant de créer la structure PKCS #15, si la carte le supporte. Si la carte ne supporte pas l'effacement, pkcs15-init échouera.

--erase-application AID

Ceci effacera l'application avec l'identifiant d'application AID.

--generate-key spécificationclé, -G spécificationclé

Demande à la carte de générer une nouvelle clé et de la stocker sur la carte. spécificationclé se compose d'un nom d'algorithme, éventuellement suivi d'un deux-points ":", d'un slash "/" ou d'un tiret "-" et des paramètres de la clé à créer. Il est conseillé de spécifier l'ID de la clé avec cette commande, en utilisant l'option id, sinon un ID intrinsèque sera calculé à partir du matériel de la clé. Consultez la description de l'attribut 'pkcs15-id-style' dans 'pkcs15.profile' pour les détails sur l'algorithme utilisé pour calculer l'ID intrinsèque. Pour les cartes multi-applications, l'application PKCS#15 cible peut être spécifiée par la valeur AID hexadécimale de l'option aid.

--pin pin, --puk puk, --so-pin sopin, --so-puk sopuk

Ces options peuvent être utilisées pour spécifier les valeurs de PIN/PUK en ligne de commande. Si la valeur est définie sur env:VARIABLE, la valeur de la variable d'environnement spécifiée est utilisée. Par défaut, le code est invité en ligne de commande si nécessaire.

Notez que sur la plupart des systèmes d'exploitation, n'importe quel utilisateur peut afficher la ligne de commande de n'importe quel processus sur le système en utilisant des utilitaires tels que ps(1). Par conséquent, vous devriez préférer passer les codes via une variable d'environnement sur un système non sécurisé.

--no-so-pin,

Ne pas installer de PIN SO, et ne pas le demander.

--profile nom, -p nom

Indique à pkcs15-init de charger le profil général spécifié. Actuellement, le seul profil d'application défini est pkcs15, mais vous pouvez écrire vos propres profils et les spécifier en utilisant cette option.

Le nom du profil peut être combiné avec une ou plusieurs options de profil, qui modifient légèrement le comportement du profil. Par exemple, le profil OpenSC par défaut prend en charge l'option openpin, qui installe une seule PIN lors de l'initialisation de la carte. Cette PIN est ensuite utilisée à la fois comme PIN SO et comme PIN utilisateur pour toutes les clés stockées sur la carte.

Le nom du profil et les options sont séparés par un caractère +, comme dans pkcs15+onepin.

--secret-key-algorithm spécificationclé,

spécificationclé décrit l'algorithme et la longueur de la clé à créer ou à télécharger, comme aes:256. Ceci créera une clé AES de 256 bits.

--store-certificate nomfichier, -X nomfichier

Indique à pkcs15-init de stocker le certificat donné dans nomfichier sur la carte, en créant un objet certificat avec l'ID spécifié via l'option --id. Sans ID fourni, un ID intrinsèque sera calculé à partir de la clé publique du certificat. Consultez la description de l'attribut 'pkcs15-id-style' dans 'pkcs15.profile' pour les détails sur l'algorithme utilisé pour calculer l'ID intrinsèque. Le fichier est supposé contenir le certificat encodé en PEM. Pour les cartes multi-applications, l'application cible peut être spécifiée par la valeur AID hexadécimale de l'option aid.

--store-pin, -P

Stocker une nouvelle PIN/PUK sur la carte.

--store-public-key nomfichier

Indique à pkcs15-init de télécharger la clé publique spécifiée sur la carte et de créer un objet clé publique avec l'ID de clé spécifié via --id. Par défaut, le fichier est supposé contenir la clé au format PEM. Des formats alternatifs peuvent être spécifiés en utilisant --format.

--store-private-key nomfichier, -S nomfichier

Indique à pkcs15-init de télécharger la clé privée spécifiée sur la carte. Cette commande créera également un objet clé publique contenant la partie clé publique. Par défaut, le fichier est supposé contenir la clé au format PEM. Des formats alternatifs peuvent être spécifiés en utilisant --format. Il est conseillé de spécifier l'ID de la clé avec cette commande, en utilisant l'option --id, sinon un ID intrinsèque sera calculé à partir du matériel de la clé. Consultez la description de l'attribut 'pkcs15-id-style' dans 'pkcs15.profile' pour les détails sur l'algorithme utilisé pour calculer l'ID intrinsèque. Pour les cartes multi-applications, l'application PKCS#15 cible peut être spécifiée par la valeur AID hexadécimale de l'option aid.

--store-secret-key nomfichier,

Indique à pkcs15-init de télécharger la clé secrète spécifiée sur la carte. Le fichier est supposé contenir la clé brute. Le type de clé doit être spécifié avec l'option --secret-key-algorithm.

Vous pouvez en outre spécifier l'ID de la clé avec cette commande, en utilisant l'option --id, sinon un ID aléatoire est généré. Pour les cartes multi-applications, l'application PKCS#15 cible peut être spécifiée par la valeur AID hexadécimale de l'option aid.

--store-data nomfichier, -W nomfichier

Stocker un objet de données.

--update-certificate nomfichier, -U nomfichier

Indique à pkcs15-init de mettre à jour l'objet certificat avec l'ID spécifié via l'option --id avec le certificat dans nomfichier. Le fichier est supposé contenir un certificat encodé en PEM.

Soyez particulièrement attentif lors de la mise à jour des certificats de déchiffrement de courrier, car les certificats manquants peuvent rendre les messages électroniques illisibles !

--delete-objects arg, -D arg

Indique à pkcs15-init de supprimer l'objet spécifié. arg est une liste séparée par des virgules contenant l'un des éléments suivants : privkey, pubkey, secrkey, cert, chain ou data.

Lorsque data est spécifié, un ---application-id doit également être spécifié ; dans les autres cas, un --id doit également être spécifié.

Lorsque chain est spécifié, la chaîne de certificats commençant par le cert avec l'ID spécifié sera supprimée, jusqu'à ce qu'un certificat d'autorité de certification (CA) certifie un autre cert sur la carte.

--change-attributes arg, -A arg

Indique à pkcs15-init de modifier l'attribut spécifié. arg est soit privkey, pubkey, secrkey, cert ou data. Vous devez également spécifier le --id de l'objet. Pour l'instant, vous ne pouvez modifier que le --label, par exemple : 
pkcs15-init -A cert --id 45 -a 1 --label Jim

--use-default-transport-keys, -T

Indique à pkcs15-init de ne pas demander les clés de transport et d'utiliser les clés par défaut, telles que connues par le pilote de la carte.

--sanity-check

Indique à pkcs15-init d'effectuer une vérification de cohérence spécifique à la carte et éventuellement une procédure de mise à jour.

--reader arg, -r arg

Numéro du lecteur à utiliser. Par défaut, le premier lecteur avec une carte présente est utilisé. Si arg est une ATR, le lecteur avec une carte correspondante sera choisi.

--verbose, -v

Rend pkcs15-init plus verbeux. Spécifiez ce drapeau plusieurs fois pour activer la sortie de débogage dans la bibliothèque OpenSC.

--wait, -w

Fait en sorte que pkcs15-init attende l'insertion d'une carte.

--use-pinpad

Ne pas demander à l'utilisateur ; si aucune PIN n'est fournie, le pavé numérique sera utilisé.

--auth-id nomfichier, -a nomfichier

Spécifier l'ID de la PIN à utiliser/créer.

--puk-id ID

Spécifier l'ID du PUK à utiliser/créer.

--label LIBELLÉ

Spécifier le libellé d'une PIN, d'une clé, d'un certificat ou d'un objet de données lors de la création de nouveaux objets. Lors de la suppression d'objets, ceci peut être utilisé pour supprimer un objet par libellé.

--puk-label LIBELLÉ

Spécifier le libellé du PUK.

--public-key-label LIBELLÉ

Spécifier le libellé de la clé publique (à utiliser avec --generate-key).

--cert-label LIBELLÉ

Spécifier le libellé du certificat utilisateur (à utiliser avec --store-private-key).

--application-name arg

Spécifier le nom de l'application de l'objet de données (à utiliser avec --store-data-object).

--aid AID

Spécifier l'AID de l'application PKCS#15 sur carte à lier (en format hexadécimal).

--output-file nomfichier -o nomfichier,

Sortir la partie publique de la clé générée dans un fichier.

--passphrase PHRASE

Spécifier la phrase de passe pour déverrouiller la clé secrète.

--authority

Marquer le certificat comme certificat d'autorité de certification (CA).

--key-usage arg -u arg,

Spécifie l'utilisation de la clé X.509. arg est une liste séparée par des virgules contenant l'un des éléments suivants : digitalSignature, nonRepudiation, keyEncipherment, dataEncipherment, keyAgreement, keyCertSign, cRLSign. Des noms abrégés sont autorisés s'ils sont uniques (par exemple, dataEnc).

L'alias sign est équivalent à digitalSignature,keyCertSign,cRLSign

L'alias decrypt est équivalent à keyEncipherment,dataEncipherment

--finalize -F,

Terminer la phase d'initialisation de la carte à puce.

--update-last-update

Mettre à jour l'attribut 'lastUpdate' de tokenInfo.

--ignore-ca-certificates

Lors du stockage de PKCS#12, ignorer les certificats CA.

--update-existing

Stocker ou mettre à jour un certificat existant.

--extractable

Clé privée stockée comme clé extractible.

--user-consent arg

Spécifier le consentement de l'utilisateur. arg est une valeur entière. Si > 0, la valeur spécifie combien de fois l'objet peut être accédé avant qu'une nouvelle authentification ne soit requise. Si zéro, l'objet ne nécessite pas de ré-authentification.

<

b>--insecure

Mode non sécurisé : ne pas exiger de code PIN pour la clé privée

--md-container-guid GUID

Pour une nouvelle clé, spécifiez le GUID d'un conteneur MD

--help -h,

Afficher le message d'aide
