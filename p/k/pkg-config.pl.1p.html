NOM

PkgConfig - Remplacement pur Perl et uniquement le cœur pour pkg-config

SYNTAXE

Comme remplacement pour "pkg-config"

$ ppkg-config --libs --cflags --static gio-2.0
#sorties (lignes coupées artificiellement pour la lisibilité):
# -I/usr/include/glib-2.0 -I/usr/lib/glib-2.0/include
# -pthread -lgio-2.0 -lz -lresolv -lgobject-2.0
# -lgmodule-2.0 -ldl -lgthread-2.0 -pthread -lrt -lglib-2.0

"pkg-config.pl" peut être utilisé comme un alias pour "ppkg-config" sur les plateformes qui le supportent. Il peut également être installé sous le nom "pkg-config" bien que ce ne soit pas recommandé si votre système dispose d'un "pkg-config" natif.

À comparer avec :
$ pkg-config --libs --cflags --static gio-2.0

#sorties ( "" ):
# -pthread -I/usr/include/glib-2.0 -I/usr/lib/glib-2.0/include
# -pthread -lgio-2.0 -lz -lresolv -lgobject-2.0 -lgmodule-2.0
# -ldl -lgthread-2.0 -lrt -lglib-2.0

Depuis un autre module Perl

use PkgConfig;
my $o = PkgConfig->find('gio');
if($o->errmsg) {
    #gérer l'erreur
} else {
    my $prefix = $o->get_var('prefix');
    my @cflags = $o->get_cflags;
    my @ldflags = $o->get_ldflags;
}

DESCRIPTION

"PkgConfig" fournit un remplacement pur Perl, uniquement cœur, pour l'utilitaire "pkg-config".

Ce n'est pas une description des utilisations de "pkg-config" mais plutôt une description des différences entre la version C et la version Perl.

Alors que "pkg-config" est un binaire compilé lié avec glib, la version pure Perl n'a pas une telle exigence et fonctionnera partout où Perl ( >= 5.6 ) fonctionne.

Les options principales supportées sont les options courantes "--libs", "--cflags", "--static", "--exists" et "--modversion".

OPTIONS DU SCRIPT

UTILISATION

<nom_paquet1 nom_paquet2..> [ --options ]

ARGUMENTS

Par défaut, un nom de bibliothèque doit être fourni, sauf si l'une des options --version ou --real-version est spécifiée.

La sortie devrait normalement être adaptée pour être passée à votre compilateur préféré.

--libs

(Également) afficher les options de l'éditeur de liens. Les dépendances sont parcourues dans l'ordre. Les dépendances de haut niveau apparaîtront plus tôt dans la ligne de commande que les dépendances de bas niveau.

--libs-only-L

Affiche la partie -L/-R de "--libs". Elle définit le chemin de recherche des bibliothèques mais sans les bibliothèques à lier.

--libs-only-l

Affiche la partie -l de "--libs".

--libs-only-other

Affiche la partie de "--libs" qui n'est pas couverte par "--libs-only-L" et "--libs-only-l", comme "--pthread".

--list-all

Lister tous les paquets connus.

--cflags

(Également) afficher les options du compilateur et du préprocesseur C.

--cflags-only-I

Affiche la partie -I de "--cflags"

--cflags-only-other

Affiche les parties de "--cflags" qui ne sont pas couvertes par "--cflags-only-I".

--modversion

Afficher la version d'un paquet donné.

--static

Utiliser des dépendances et des bibliothèques supplémentaires si l'on lie contre une version statique de la bibliothèque demandée.

--exists

Retourner succès (0) si le paquet existe dans le chemin de recherche.

--with-path=CHEMIN

Ajouter "CHEMIN" au début de la liste des chemins de recherche contenant les fichiers ".pc".

Cette option peut être spécifiée plusieurs fois avec différents chemins, et ils seront tous ajoutés.

--env-only

Avec cette option, **seuls** les chemins spécifiés dans "PKG_CONFIG_PATH" sont reconnus et tous les défauts codés en dur sont ignorés.

--guess-paths

Invoquer "gcc" et "ld" pour déterminer les chemins par défaut de l'éditeur de liens et d'inclusion. Les chemins par défaut seront exclus des options explicites -L et -I.

--define-variable=VARIABLE=VALEUR

Définir une variable, remplaçant toute définition de variable dans le fichier .pc, et permettant à votre valeur de s'interpoler avec les utilisations ultérieures.

--variable=VARIABLE

Ceci retourne la valeur d'une variable définie dans le fichier .pc d'un paquet.

--print-variables

Afficher toutes les variables définies trouvées dans les fichiers .pc.

--version

La version cible de "pkg-config" émulée par ce script.

--real-version

La version réelle de ce script.

--debug

Afficher les informations de débogage.

--silence-errors

Désactiver les erreurs. C'est le comportement par défaut pour les arguments autres que --libs, --cflags, --modversion.

--print-errors

Afficher les erreurs sur STDERR et a priorité sur "--silence-errors".

--short-errors

Ignoré, mais reconnu pour des raisons de compatibilité.

--errors-to-stdout

Afficher les erreurs sur STDOUT et a priorité sur "--print-errors".

ENVIRONNEMENT

Les variables "PKG_CONFIG_PATH" et "PKG_CONFIG_LIBDIR" sont prises en compte et utilisées comme une liste de répertoires délimités par des deux-points (ou des points-virgules sous Windows) contenant des fichiers ".pc".

D'autres variables d'environnement reconnues par "pkg-config" et PkgConfig incluent :

PKG_CONFIG_ALLOW_SYSTEM_CFLAGS
PKG_CONFIG_ALLOW_SYSTEM_LIBS

Si Win32API::Registry est installé, sous Windows (mais pas Cygwin), PkgConfig consultera également ces clés de registre. Les noms sont ignorés, mais les valeurs sont des chemins contenant des fichiers ".pc".

HKEY_CURRENT_USER\Software\pkgconfig\PKG_CONFIG_PATH
HKEY_LOCAL_MACHINE\Software\pkgconfig\PKG_CONFIG_PATH

Le support du registre doit être considéré comme quelque peu expérimental, sujet à changement à l'avenir, bien que non sans bonne raison. La justification de cette mise en garde est que cette fonctionnalité est documentée dans plusieurs endroits, mais je n'ai pas encore trouvé de version fonctionnelle qui implémente cette fonctionnalité.

OPTIONS DU MODULE

PkgConfig->find

my $result = PkgConfig->find($bibliotheque, %options);

Trouve une bibliothèque et retourne un objet résultat. $bibliotheque peut être soit le nom unique d'une bibliothèque, soit une référence à un tableau de noms de bibliothèques.

Les options sont sous forme de clés et valeurs de hachage, et les suivantes sont reconnues :

"search_path"
"search_path_override"
Ajoute des chemins de recherche au début, en plus des chemins spécifiés dans $ENV{PKG_CONFIG_PATH}. La valeur est une référence de tableau.

la variante "_override" ignore les valeurs par défaut (comme "PKG_CONFIG_PATH").

"file_path"
Spécifie le chemin complet du fichier .pc que vous souhaitez charger. Il n'a pas besoin d'être dans le chemin de recherche (bien que ses dépendances le doivent). Utile si vous connaissez le chemin complet du fichier .pc exact que vous souhaitez.

NOM

PkgConfig - interface avec pkg-config pour trouver les indicateurs du compilateur et de l'éditeur de liens

SYNOPSIS

    use PkgConfig;

    my $pkg = PkgConfig->new($pkg_name, %options);

    # Ou en utilisant le constructeur par défaut
    my $pkg = PkgConfig->new;
    $pkg->get_cflags($pkg_name, %options);
    $pkg->get_ldflags($pkg_name, %options);

    # Ou en faisant confiance à la détection automatique des chemins
    PkgConfig->Guess;
    my $pkg = PkgConfig->new($pkg_name);

    # Récupération des options
    my $cflags = $pkg->get_cflags;
    my $ldflags = $pkg->get_ldflags;

    # Vérification de l'existence du paquet
    if ( $pkg->pkg_exists ) {
        print "$cflags $ldflags\n";
    } else {
        warn $pkg->errmsg;
    }

    # Obtenir une version spécifique du paquet
    my $pkg_v = PkgConfig->new($pkg_name, version => '1.2.3');
    if ( $pkg_v->pkg_version ) { ... }

    # Ignorer certaines options
    my $pkg_no_i = PkgConfig->new($pkg_name, exclude_cflags => 1);
    my $pkg_no_l = PkgConfig->new($pkg_name, exclude_ldflags => 1);
    my $pkg_no_i_ov = PkgConfig->new($pkg_name, exclude_cflags_override => 1);
    my $pkg_no_l_ov = PkgConfig->new($pkg_name, exclude_ldflags_override => 1);

    # Obtenir les bibliothèques statiques
    my $pkg_static = PkgConfig->new($pkg_name, static => 1);

    # Ne pas parcourir les dépendances
    my $pkg_no_recurse = PkgConfig->new($pkg_name, no_recurse => 1);

    # Définir des variables personnalisées
    my $pkg_vars = PkgConfig->new($pkg_name, VARS => { prefix => '/usr/local' });

    # Obtenir un message d'erreur
    my $errmsg = $pkg->errmsg;

    # Vérifier si le paquet existe
    my $exists = $pkg->pkg_exists;

    # Obtenir la version du paquet
    my $version = $pkg->pkg_version;

    # Obtenir une variable spécifique
    my $prefix = $pkg->get_var('prefix');

DESCRIPTION

Ce module fournit une interface Perl à l'utilitaire pkg-config. Il est utilisé pour récupérer des informations sur les bibliothèques installées, notamment les indicateurs du compilateur et de l'éditeur de liens nécessaires pour les utiliser.

Le constructeur PkgConfig->new prend une liste d'options qui sont traitées de manière similaire aux options de ligne de commande de pkg-config.

Les options acceptées sont les suivantes :

force
Forcer la récupération des options, même si la version spécifiée n'est pas exactement la même.
version
Spécifier la version exacte du paquet requis. S'il est absent, seul le nom du paquet sera utilisé.
min_version
Spécifier la version minimale du paquet requis. S'il est absent, seul le nom du paquet sera utilisé.
max_version
Spécifier la version maximale du paquet requis. S'il est absent, seul le nom du paquet sera utilisé.
modversion
Utiliser le nom du module pour obtenir les options. Ceci est utile pour les paquets qui ont une version incluse dans leur nom (par exemple, "glib-2.0").
exists
Simule l'option "--exists". La méthode pkg_exists sera définie en fonction du résultat.
cflags
Récupérer uniquement les indicateurs du compilateur.
ldflags
Récupérer uniquement les indicateurs de l'éditeur de liens.
libs
Récupérer uniquement les bibliothèques.
prefix
Spécifier le préfixe d'installation. Ceci est équivalent à l'option "--variable=prefix".
exec_prefix
Spécifier le préfixe d'exécution. Ceci est équivalent à l'option "--variable=exec_prefix".
include_prefix
Spécifier le préfixe d'inclusion. Ceci est équivalent à l'option "--variable=includedir".
libdir
Spécifier le répertoire des bibliothèques. Ceci est équivalent à l'option "--variable=libdir".
exclude_cflags
exclude_ldflags
exclude_cflags_override
exclude_ldflags_override
Certains fichiers ".pc" spécifient des chemins de recherche par défaut pour le compilateur et l'éditeur de liens, par exemple "-I/usr/include -L/usr/lib". Les spécifier sur la ligne de commande peut être problématique car cela modifie radicalement l'ordre de recherche.

Les options ci-dessus ajouteront ou remplaceront les options qui sont exclues et filtrées.

Les options par défaut exclues pour l'éditeur de liens et le compilateur peuvent être obtenues via @PkgConfig::DEFAULT_EXCLUDE_LFLAGS et @PkgConfig::DEFAULT_EXCLUDE_CFLAGS, respectivement.

static
Spécifier également les bibliothèques statiques.
no_recurse
Ne pas parcourir les dépendances. Ceci est utile pour effectuer uniquement des vérifications de version.
VARS
Définir un hashref de variables pour remplacer toute définition de variable dans les fichiers .pc. Ceci est équivalent à l'option de ligne de commande "--define-variable".

Un objet "PkgConfig" est retourné et peut être interrogé sur les résultats :

$o->errmsg

Un message d'erreur, le cas échéant. Il s'agit d'une chaîne de caractères indiquant une erreur.

$o->pkg_exists

Valeur booléenne, vraie si le paquet existe.

$o->pkg_version

La version du paquet

$o->get_cflags

$o->get_ldflags

Retourne respectivement les indicateurs du compilateur et de l'éditeur de liens.

En contexte de liste, ces méthodes retournent une liste avec chaque argument divisé par des espaces non échappés.

En contexte de liste retourne une liste d'indicateurs de compilateur et d'éditeur de liens, respectivement.

En contexte scalaire retourne une chaîne d'indicateurs de compilateur et d'éditeur de liens avec les espaces et les guillemets correctement échappés.

$o->get_var($name)

Obtient la variable avec le nom donné.

PkgConfig->Guess

Ceci est une méthode de classe, et elle remplacera les chemins par défaut codés en dur de l'éditeur de liens et d'inclusion par ceux découverts en invoquant ld(1) et cpp(1).

Actuellement, cela ne fonctionne qu'avec "ld" fourni par GCC et le "ld" GNU.

INSTALLATION

Le fichier "Makefile.PL" qui accompagne "PkgConfig" peut prendre une ou plusieurs options "--script" pour modifier le nom du ou des scripts qui sont installés.

--script ppkg-config
C'est le défaut et cela fonctionne sur toutes les plateformes.
--script pkg-config.pl
Ceci est installé par défaut sur toutes les plateformes sauf Windows, où le suffixe .pl peut prêter à confusion pour le shell et entraîner l'ouverture du script dans un éditeur de texte.
--script pkg-config
C'est le nom par défaut du véritable "pkg-config" et vous devez donc l'activer spécifiquement si vous le souhaitez.
--script none
N'installe aucun script.

Exemple, installation de tous les noms de scripts :

% perl Makefile.PL --script ppkg-config --script pkg-config.pl --script pkg-config

Exemple, ne pas installer de scripts :

% perl Makefile.PL --script none

Vous pouvez également définir la variable d'environnement PERL_PKG_CONFIG_SCRIPTS à la valeur --script désirée (en séparant chaque nom de script par une virgule ",") pour garantir que les mises à jour de PkgConfig fassent de même.

CAVEATS

Sur Strawberry Perl, "ppkg-config" agit comme si Strawberry était le système. Cela signifie que :

  • Les fichiers .pc qui sont groupés avec Strawberry sont recherchés par défaut.
  • Les répertoires d'inclusion et de bibliothèque de Strawberry sont utilisés pour calculer les listes d'exclusion.

Depuis Strawberry 5.20.0.1, PkgConfig est groupé avec Strawberry et "pkg-config" est installé par défaut (en plus de "ppkg-config", bien que l'alias "ppkg-config" ne soit PAS groupé avec Strawberry lui-même).

Pour plus de détails sur la façon de patcher les fichiers .pc groupés avec les anciennes versions de Strawberry, voir le fichier "README.win32" qui accompagne cette distribution.

BUGS

L'ordre des indicateurs ne correspond pas exactement à celui de "pkg-config". D'après mes observations, il semble que ce module fasse un meilleur travail, mais je pourrais avoir tort.

Contrairement à "pkg-config", la fonction "--exists" des scripts retournera un nombre non nul si un paquet ou l'une de ses dépendances est manquant. Cela diffère du comportement de "pkg-config" qui vérifie uniquement la définition du paquet lui-même (sans les dépendances).

À propos

À propos

Ce logiciel est un outil utilitaire simple conçu pour interagir avec le système de gestion de paquets Arch Linux. Il vise à fournir une interface conviviale pour certaines opérations courantes, telles que la recherche de paquets, l'installation, la mise à jour et la suppression.

Le développement de cet outil est guidé par les principes de simplicité et d'efficacité, reflétant l'esprit d'Arch Linux lui-même. Il est destiné aux utilisateurs d'Arch Linux qui recherchent un moyen rapide et pratique d'effectuer des tâches de gestion de paquets sans avoir à se souvenir de tous les drapeaux et options de la commande `pacman`.

La fonctionnalité et le comportement de cet outil sont étroitement liés à ceux spécifiés dans le paquet Arch Linux correspondant.
