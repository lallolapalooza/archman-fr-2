NOM

pkcs11-tool - utilitaire pour gérer et utiliser des jetons de sécurité PKCS #11

SYNOPIS

pkcs11-tool [OPTIONS]

DESCRIPTION

L'utilitaire pkcs11-tool est utilisé pour gérer les objets de données sur les cartes à puce et les jetons de sécurité PKCS #11 similaires. Les utilisateurs peuvent lister et lire les codes PIN, les clés et les certificats stockés sur le jeton. L'authentification par code PIN utilisateur est effectuée pour les opérations qui la nécessitent.

OPTIONS

--attr-from nom_fichier

Extrait les informations du fichier nom_fichier (fichier de certificat encodé DER) et crée les attributs correspondants lors de l'écriture d'un objet sur le jeton. Par exemple : le nom du sujet du certificat est utilisé pour créer l'attribut CKA_SUBJECT.

--change-pin, -c

Change le code PIN utilisateur sur le jeton.

--unlock-pin

Déverrouille le code PIN utilisateur (sans --login déverrouiller en session connectée ; sinon, --login-type doit être 'context-specific').

--hash, -h

Hache des données.

--hash-algorithm mécanisme

Spécifie l'algorithme de hachage utilisé avec la signature RSA-PKCS-PSS ou le déchiffrement RSA-OAEP. Les valeurs autorisées sont "SHA-1", "SHA256", "SHA384", "SHA512", et certains jetons peuvent aussi autoriser "SHA224". Par défaut, c'est "SHA-1".

Notez que l'entrée pour RSA-PKCS-PSS doit avoir une taille égale à l'algorithme de hachage spécifié. Par exemple, pour SHA256, l'entrée de la signature doit faire exactement 32 octets de long (pour les mécanismes SHA256-RSA-PKCS-PSS, il n'y a pas une telle restriction). Pour RSA-OAEP, la taille de l'entrée en clair mLen ne doit pas dépasser keyLen - 2 - 2*hashLen. Par exemple, pour une clé RSA de 3072 bits et SHA384, le plus long texte en clair à chiffrer avec RSA-OAEP est (toutes les tailles en octets) : 384 - 2 - 2*48 = 286, soit 286 octets.

--id id, -d id

Spécifie l'identifiant de l'objet sur lequel opérer.

--init-pin

Initialise le code PIN utilisateur. Cette option diffère de --change-pin en ce qu'elle définit le code PIN utilisateur pour la première fois. Une fois défini, le code PIN utilisateur peut être modifié en utilisant --change-pin.

--init-token

Initialise un jeton : définit l'étiquette du jeton ainsi qu'un code PIN d'Officier de Sécurité (l'étiquette doit être spécifiée à l'aide de --label).

--input-file nom_fichier, -i nom_fichier

Spécifie le chemin d'un fichier pour l'entrée.

--keypairgen, -k

Génère une nouvelle paire de clés (paire publique et privée).

--keygen

Génère une nouvelle clé.

--key-type spécification

Spécifie le type et (pas toujours obligatoire) la saveur (longueur de la clé symétrique en octets, longueur de la clé asymétrique en bits, identifiant de courbe elliptique, etc.) de la clé à créer, par exemple RSA:2048, EC:prime256v1, GOSTR3410-2012-256:B, DES:8, DES3:24, AES:16, AES: ou GENERIC:64. Si le type de clé a été spécifié de manière incomplète, les valeurs possibles sont listées.

--usage-sign

Spécifie le drapeau d'utilisation de clé 'sign' (définit SIGN dans la clé privée, définit VERIFY dans la clé publique).

--usage-decrypt

Spécifie le drapeau d'utilisation de clé 'decrypt'.

Pour les clés RSA, définit DECRYPT dans la clé privée et ENCRYPT dans la clé publique. Pour les clés secrètes, définit DECRYPT et ENCRYPT.

--usage-derive

Spécifie le drapeau d'utilisation de clé 'derive' (EC uniquement).

--usage-wrap

Spécifie le drapeau d'utilisation de clé 'wrap'.

--label nom, -a nom

Spécifie le nom de l'objet sur lequel opérer (ou l'étiquette du jeton lorsque --init-token est utilisé).

--list-mechanisms, -M

Affiche une liste des mécanismes pris en charge par le jeton.

--list-objects, -O

Affiche une liste d'objets.

Les options --keytype, --label, --id ou --application-id peuvent être utilisées pour filtrer les objets listés.

--list-slots, -L

Affiche une liste des slots disponibles sur le jeton.

--list-token-slots, -T

Liste les slots avec des jetons.

--list-interfaces

Liste les interfaces de la bibliothèque PKCS #11 3.0.

--session-rw,

Force l'ouverture de la session PKCS#11 avec CKF_RW_SESSION.

--login, -l

S'authentifie auprès du jeton avant d'effectuer d'autres opérations. Cette option n'est pas nécessaire si un code PIN est fourni sur la ligne de commande.

--login-type

Spécifie le type de connexion ('so', 'user', 'context-specific' ; par défaut : 'user').

--mechanism mécanisme, -m mécanisme

Utilise le mécanisme spécifié pour les opérations sur le jeton. Voir -M pour une liste des mécanismes pris en charge par votre jeton. Le mécanisme peut également être spécifié en hexadécimal, par exemple, 0x80001234.

--mgf fonction

Utilise la fonction de génération de message (MGF) fonction spécifiée pour les signatures RSA-PKCS-PSS ou les déchiffrements RSA-OAEP. Les arguments pris en charge vont de MGF1-SHA1 à MGF1-SHA512 s'ils sont pris en charge par le pilote. La valeur par défaut est basée sur la sélection du hachage.

--module mod

Spécifie un module (ou une bibliothèque) PKCS#11 à charger.

--moz-cert nom_fichier, -z nom_fichier

Teste la génération d'une paire de clés de type Mozilla et la requête de certificat. Spécifie le nom_fichier du fichier de certificat.

--output-file nom_fichier, -o nom_fichier

Spécifie le chemin d'un fichier pour la sortie.

--pin pin, -p pin

Utilise le pin donné pour les opérations sur le jeton. S'il est défini sur env:VARIABLE, la valeur de la variable d'environnement VARIABLE est utilisée. ATTENTION : Faites attention en utilisant cette option car d'autres utilisateurs pourraient lire la ligne de commande depuis le système ou si elle est intégrée dans un script. S'il est défini sur env:VARIABLE, la valeur de la variable d'environnement VARIABLE est utilisée.

Cette option définira également l'option --login.

--puk puk

Fournit le PUK utilisateur sur la ligne de commande.

--new-pin pin

Fournit le nouveau PIN utilisateur sur la ligne de commande.

--sensitive

Définit l'attribut CKA_SENSITIVE (l'objet ne peut pas être révélé en clair).

--extractable

Définit l'attribut CKA_EXTRACTABLE (l'objet peut être extrait).

--undestroyable

Définit l'attribut CKA_DESTROYABLE à faux (l'objet ne peut pas être détruit).

--set-id id, -e id

Définit l'attribut CKA_ID de l'objet.

--show-info, -I

Affiche des informations générales sur le jeton.

--sign, -s

Signe des données.

--decrypt,

Déchiffre des données.

--encrypt,

Chiffre des données.

--unwrap,

Déchiffre une clé.

--wrap,

Chiffre une clé.

--derive,

Dérive une clé secrète en utilisant une autre clé et des données.

--derive-pass-der,

Dérive une clé publique ECDHpass au format DER pour la compatibilité avec certaines implémentations PKCS#11.

--salt-len octets

Spécifie combien d'octets de sel doivent être utilisés dans les signatures RSA-PSS. Accepte deux valeurs spéciales : "-1" signifie que la longueur du sel est égale à la longueur du digest, "-2" ou "-3" signifie utiliser la longueur maximale autorisée. Pour l'opération de vérification, "-2" signifie que la longueur du sel est automatiquement récupérée de la signature. La valeur "-2" pour l'opération de vérification est uniquement prise en charge par le module opensc pkcs#11. Par défaut, c'est la longueur du digest (-1).

--slot id

Spécifie l'identifiant du slot à utiliser (accepte le format HEX avec un préfixe 0x.. ou un nombre décimal).

--slot-description descrip

tion

Spécifiez la description du slot à utiliser.

--slot-index index

Spécifiez l'index du slot à utiliser.

--object-index index

Spécifiez l'index de l'objet à utiliser.

--use-locking

Indique au module pkcs11 d'utiliser le verrouillage de thread du système d'exploitation.

--test-threads options

Teste les implications de thread d'un module pkcs11. (Voir le code source).

--token-label label

Spécifiez l'étiquette du token. Le premier slot contenant un token inséré avec cette étiquette sera utilisé.

--so-pin pin

Utilisez le pin donné comme PIN de l'Officier de Sécurité pour certaines opérations de token (initialisation du token, initialisation du PIN utilisateur, etc.). S'il est défini sur env:VARIABLE, la valeur de la variable d'environnement VARIABLE est utilisée. Le même avertissement que pour --pin s'applique également ici.

--test, -t

Effectue quelques tests sur le token. Cette option est plus utile lorsqu'elle est utilisée avec --login ou --pin.

--test-hotplug

Teste les capacités de hotplug (C_GetSlotList + C_WaitForSlotEvent).

--private

Définit l'attribut CKA_PRIVATE (l'objet n'est visible qu'après une connexion).

--always-auth

Définit l'attribut CKA_ALWAYS_AUTHENTICATE pour un objet de clé privée. S'il est défini, l'utilisateur devra fournir le PIN pour chaque utilisation (signature ou déchiffrement) avec la clé.

--allowed-mechanisms mechanisms

Définit l'attribut CKA_ALLOWED_MECHANISMS pour les objets de clé lors de l'importation ou de la génération de clés. L'argument accepte une liste d'algorithmes séparés par des virgules, qui peuvent être utilisés avec la clé donnée.

--test-ec

Teste la courbe elliptique (il est préférable de l'utiliser avec l'option --login ou --pin).

--test-fork

Teste le fork et l'appel à C_Initialize() dans l'enfant.

--type type, -y type

Spécifiez le type d'objet sur lequel opérer. Les valeurs valides sont cert, privkey, pubkey, secrkey et data.

--verbose, -v

Rend pkcs11-tool plus verbeux.

NB ! Cela n'affecte pas le niveau de débogage d'OpenSC ! Pour activer le mode de débogage du module PKCS#11 d'OpenSC, définissez la variable d'environnement OPENSC_DEBUG à un nombre non nul.

--verify,

Vérifie la signature de certaines données.

--read-object, -r

Récupère l'attribut CKA_VALUE de l'objet (à utiliser avec --type).

--delete-object, -b

Supprime un objet.

--application-label label

Spécifiez l'étiquette de l'application de l'objet de données (à utiliser avec --type data).

--application-id id

Spécifiez l'ID de l'application de l'objet de données (à utiliser avec --type data).

--issuer data

Spécifiez l'émetteur au format hexadécimal (à utiliser avec --type cert).

--subject data

Spécifiez le sujet au format hexadécimal (à utiliser avec --type cert/privkey/pubkey).

--signature-file filename

Le chemin vers le fichier de signature pour la vérification de signature.

--signature-format format

Format pour la signature ECDSA : 'rs' (par défaut), 'sequence', 'openssl'.

--write-object filename, -w filename

Écrit une clé ou un certificat sur le token. filename pointe vers le fichier de certificat ou de clé encodé en DER.

--generate-random num

Obtient num octets de données aléatoires.

--allow-sw

Permet d'utiliser des mécanismes logiciels qui n'ont pas le drapeau CKF_HW défini. Peut être nécessaire lors de l'utilisation de tokens logiciels et d'émulateurs.

--iv data

Vecteur d'initialisation pour les chiffrements symétriques. Les données sont un nombre hexadécimal, c'est-à-dire "000013aa7bffa0".

--mac-general-param num

Définit la longueur du MAC pour les mécanismes de MAC de longueur générale à num octets.

--aad data

Données authentifiées supplémentaires pour les chiffrements AEAD. Les données sont un nombre hexadécimal.

--tag-bits-len num

Définit la longueur de la balise pour les chiffrements AEAD à num bits.

--salt-file filename

Spécifie le fichier contenant le sel pour HKDF (facultatif).

--info-file filename

Spécifie le fichier contenant les informations pour HKDF (facultatif).

EXEMPLES

Effectuer un test de fonctionnalité de base de la carte :

pkcs11-tool --test --login

Lister tous les certificats sur la carte à puce :

pkcs11-tool --list-objects --type cert

Lire le certificat avec l'ID CERT_ID au format DER depuis la carte à puce et le convertir en PEM via OpenSSL :

pkcs11-tool --read-object --id $CERT_ID --type cert \
					--output-file cert.der
openssl x509 -inform DER -in cert.der -outform PEM > cert.pem

Écrire un certificat sur le token :

pkcs11-tool --login --write-object certificate.der --type cert

Générer une nouvelle paire de clés RSA :

pkcs11-tool --login --keypairgen --key-type RSA:2048

Générer une nouvelle paire de clés RSA extractible :

pkcs11-tool --login --keypairgen --key-type RSA:2048 --extractable

Générer une paire de clés de courbe elliptique avec OpenSSL et l'importer sur la carte sous le nom $ID :

openssl genpkey -out EC_private.der -outform DER \
	-algorithm EC -pkeyopt ec_paramgen_curve:P-521
pkcs11-tool --write-object EC_private.der --id "$ID" \
	--type privkey --label "EC private key" -p "$PIN"
openssl pkey -in EC_private.der -out EC_public.der \
	-pubout -inform DER -outform DER
pkcs11-tool --write-object EC_public.der --id "$ID" \
	--type pubkey  --label "EC public key" -p $PIN

Lister les clés privées :

pkcs11-tool --login --list-objects --type privkey

Signer des données stockées dans le fichier `data` en utilisant la clé privée avec l'ID ID et le mécanisme RSA-PKCS :

pkcs11-tool --sign --id $ID --mechanism RSA-PKCS \
	--input-file data --output-file data.sig

La même opération est également possible en redirigeant les données depuis stdin plutôt qu'en spécifiant un fichier d'entrée :

dd if=data bs=128 count=1 \
	| pkcs11-tool --sign --id $ID --mechanism RSA-PKCS \
	> data.sig

Vérifier les données signées :

pkcs11-tool --id ID --verify -m RSA-PKCS \
	--input-file data --signature-file data.sig

Pour chiffrer un fichier en utilisant la clé AES avec l'ID 85 et le mécanisme AES-CBC avec padding :

pkcs11-tool --login --encrypt --id 85 -m AES-CBC-PAD \
	--iv "00000000000000000000000000000000" \
	-i file.txt -o encrypted_file.data

Déchiffrer le fichier chiffré :

pkcs11-tool --login --decrypt --id 85 -m AES-CBC-PAD \
	--iv "00000000000000000000000000000000" \
	--i encrypted_file.data -o decrypted.txt

Utiliser la clé avec l'ID 75 et le mécanisme AES-CBC-PAD, avec un vecteur d'initialisation "00000000000000000000000000000000" pour encapsuler la clé avec l'ID 76 dans le fichier de sortie `exported_aes.key`.

pkcs11-tool --login --wrap --id 75 --mechanism AES-CBC-PAD \
	--iv "00000000000000000000000000000000" \
	--application-id 76 \
	--output-file exported_aes.key

Utiliser la clé avec l'ID 22 et le mécanisme RSA-PKCS pour désencapsuler la clé du fichier `aes_wrapped.key`. Après une opération de désencapsulation réussie, une nouvelle clé AES est créée sur le token. L'ID de cette clé est défini à 90 et son étiquette à `unwrapped-key`. Note : pour la carte MyEID, la taille de la clé AES doit être présente dans la spécification de la clé, par exemple AES:16.

pkcs11-tool --login --unwrap --mechanism RSA-PKCS --id 22 \
	-i aes_wrapped.key --key-type AES: \
	--application-id 90 --applicatin-label unwrapped-key

Utiliser le SO-PIN pour initialiser ou réinitialiser le PIN :

pkcs11-tool --login --login-type so --init-pin
