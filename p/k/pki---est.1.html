NOM

pki --est - Enregistrer un certificat X.509 auprès d'un serveur EST

SYNOPIS

pki --est --url url [--label étiquette] [--in fichier] --cacert fichier [--cert fichier|--certid hex --key fichier|--keyid hex] [--userpass nomutilisateur:motdepasse] [--interval temps] [--maxpolltime temps] [--outform encodage] [--debug niveau]
pki --est --options fichier
pki --est -h | --help

DESCRIPTION

Cette sous-commande de pki(1) envoie une requête de certificat PKCS#10 via HTTPS à un serveur utilisant le protocole Enrollment over Secure Transport (EST) (RFC 7030). Après une autorisation réussie qui, avec une authentification manuelle, nécessite un interrogatoire périodique par le client d'enregistrement, le serveur EST renvoie un certificat X.509 signé par l'AC.

Avant l'expiration du certificat actuel, un nouveau certificat client basé sur une nouvelle clé privée peut être demandé, en utilisant l'ancien certificat et l'ancienne clé pour une authentification client TLS automatique auprès du serveur EST.

OPTIONS

-h, --help
Affiche les informations d'utilisation avec un résumé des options disponibles.
-v, --debug niveau
Définit le niveau de débogage, par défaut : 1.
-+, --options fichier
Lit les options de ligne de commande depuis le fichier.
-u, --url url
URL du serveur EST.
-l, --label étiquette
Étiquette dans le chemin du serveur EST.
-i, --in fichier
Requête de certificat PKCS#10. Si non fournie, la requête de certificat est lue depuis STDIN.
-C, --cacert fichier
Certificat de l'AC dans la chaîne de confiance utilisée pour la vérification de la signature du serveur TLS EST ou dans la chaîne de confiance pour vérifier le certificat client émis par l'AC. Peut être utilisé plusieurs fois.
-c, --cert fichier
Certificat client à renouveler.
-X, --certid hex
Identifiant de l'objet certificat client sur carte à puce ou TPM 2.0.
-k, --key fichier
Clé privée client à remplacer.
-x, --keyid hex
Identifiant de l'objet clé privée client sur carte à puce ou TPM 2.0.
-p, --userpass nomutilisateur:motdepasse
Nom d'utilisateur : mot de passe optionnel qui peut être utilisé pour l'authentification HTTP basique.
-t, --interval temps
Intervalle d'interrogation en secondes, par défaut 60s. Cette valeur peut être remplacée par l'en-tête retry-after dans la réponse HTTP 202 du serveur EST.
-m, --maxpolltime temps
Temps d'interrogation maximum en secondes, par défaut 0, ce qui signifie une interrogation illimitée.
-f, --outform encodage
Encodage du fichier certificat créé. Soit der (ASN.1 DER) soit pem (PEM Base64), par défaut der.

EXEMPLES

Pour économiser un peu de saisie, les options de ligne de commande suivantes sont stockées dans un fichier est.opt :

--url https://pki.strongswan.org:8443
--cacert tlsca.crt
--cacert tlsca-1.crt
--cacert myca.crt
--cacert myca-1.crt

NOTE : Pour une connexion HTTPS réussie, la confiance doit être établie dans le certificat du serveur EST. La chaîne de confiance TLS, y compris le certificat de l'AC racine et éventuellement les certificats d'AC intermédiaires, doit être fournie en utilisant plusieurs options --cacert.

L'option --cacert doit également être utilisée pour pouvoir vérifier le certificat client reçu, émis par l'AC. Cette deuxième chaîne de confiance peut être identique à la chaîne de confiance TLS (si le serveur EST utilise un certificat de serveur TLS émis par sa propre AC) ou peut être totalement différente, par exemple, si un certificat de serveur EST Let's Encrypt est utilisé.

Avec la commande suivante, un certificat X.509 signé par l'AC intermédiaire est demandé à un serveur EST basé sur une requête de certificat PKCS#10 :

pki --options est.opt --in moonReqNew.der --certid 0x01800004 --keyid 0x81010004 > moonCertNew.der
