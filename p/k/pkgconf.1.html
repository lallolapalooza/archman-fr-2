PKGCONF(1) Manuel des commandes générales PKGCONF(1)

NOM

pkgconf — un système pour configurer les informations de dépendance de construction

SYNOPIS

pkgconf [options] module ...

DESCRIPTION

Le programme pkgconf récupère les informations de configuration relatives aux arguments de module à partir des fichiers pc(5) installés sur le système et affiche des parties des informations récupérées en fonction des options spécifiées. L'utilisation la plus courante consiste à afficher les indicateurs du compilateur et de l'éditeur de liens nécessaires pour compiler des logiciels qui utilisent les bibliothèques données par les arguments de module.

Les fichiers pc(5) sont recherchés le long d'un chemin construit à partir de l'option --with-path, des variables d'environnement PKG_CONFIG_PATH et PKG_CONFIG_LIBDIR, et de certains répertoires par défaut intégrés à la compilation. Les arguments de module correspondent aux noms de fichiers, mais sans l'extension de nom de fichier .pc.

Plusieurs des options provoquent une sortie immédiate. Si plusieurs de ces options sont données, seule l'option avec la priorité la plus élevée prend effet et celles avec une priorité inférieure sont silencieusement ignorées. Ces options sont, par ordre de priorité décroissante :

  1. Options sans module : --relocate, --dump-personality, --about, --version, --help, --atleast-pkgconfig-version, --list-all, et --list-package-names : Ces options font que tous les arguments sont ignorés.
  2. Options dépendant uniquement des arguments : --atleast-version, --exact-version, et --max-version : Ces options inspectent uniquement les modules explicitement spécifiés sur la ligne de commande et ne recherchent pas les dépendances.
  3. Options de sortie limitée : --validate, --license, --uninstalled, et --env : Ces options effectuent une résolution de dépendances, mais se terminent après avoir affiché les informations demandées par l'option de priorité la plus élevée, ignorant les autres options de sortie qui auraient pu être spécifiées.

Plusieurs autres options nécessitent au moins un argument de module, produisent une sortie, ne provoquent pas de sortie anticipée, peuvent être combinées entre elles, mais remplacent et désactivent toutes les options --cflags et --libs :

  1. Options de sortie à module unique : --path, --print-variables, --variable : Si l'une de ces options est spécifiée, seul le premier argument de module est utilisé, tous les autres arguments sont silencieusement ignorés, et aucune résolution de dépendance n'est tentée.
  2. Options de sortie à profondeur un : --print-provides, --modversion, --print-requires, et --print-requires-private : Si l'une de ces options est spécifiée, seuls les modules explicitement spécifiés sur la ligne de commande sont inspectés et aucune résolution de dépendance n'est tentée.
  3. Options de sortie générales : --simulate, --digraph, --solution, --fragment-tree : Ces options ne limitent pas la résolution des dépendances.

Les options de sortie les plus importantes --cflags et --libs peuvent être combinées entre elles, mais sont remplacées et ignorées si l'une des options listées ci-dessus est spécifiée.

La liste complète des options est la suivante :

--about
Affiche le numéro de version, l'avis de copyright et la licence du programme pkgconf sur la sortie standard et quitte. La plupart des autres options et tous les arguments de la ligne de commande sont ignorés.
--atleast-pkgconfig-version=version
Quitte avec une erreur si le numéro de version demandé est supérieur au numéro de version du programme pkgconf, ou avec succès sinon. La plupart des autres options et tous les arguments de la ligne de commande sont ignorés.
--atleast-version=version
Vérifie les arguments de module dans l'ordre donné. Quitte avec une erreur dès qu'un module n'existe pas, et quitte avec succès dès que le numéro de version d'un module est supérieur ou égal au numéro de version demandé. Quitte avec une erreur si le numéro de version de chaque module est inférieur au numéro de version demandé.
--cflags, --cflags-only-I, --cflags-only-other
Affiche tous les indicateurs du compilateur requis pour compiler contre le module, ou uniquement les indicateurs de chemin d'inclusion (-I), ou uniquement les indicateurs du compilateur qui ne sont pas des indicateurs de chemin d'inclusion, respectivement. Ces options impliquent --print-errors.
--debug
Affiche certains messages d'avertissement non fatals sur la sortie d'erreur standard qui seraient par ailleurs ignorés silencieusement. Cette option implique également --print-errors. Si pkgconf a été compilé sans définir le macro du préprocesseur PKGCONF_LITE, cette option affiche également de nombreux messages de débogage sur la sortie d'erreur standard.
--define-prefix
Tente de déterminer la variable préfixe à utiliser pour les relocalisations d'entrées CFLAGS et LIBS. Ceci est principalement utile pour les plates-formes où les SDK frameworks sont déplaçables, comme Windows.
--define-variable=varname=value
Définit varname comme value. Les variables sont utilisées dans la sortie de requête, et les résultats de certains modules peuvent changer en fonction de la présence d'une définition de variable.
--digraph
Extrait la solution du résolveur de dépendances sous forme de fichier ‘dot’ graphviz. Ceci peut être utilisé avec graphviz pour visualiser les interdépendances des modules. Cette option n'est disponible que si le macro du préprocesseur PKGCONF_LITE n'a pas été défini lors de la compilation.
--dont-define-prefix
Désactive la fonctionnalité ‘define-prefix’.
--dont-relocate-paths
Désactive la fonctionnalité de relocalisation des chemins.
--dump-personality
Affiche certains paramètres par défaut sur la sortie standard, en particulier le chemin de recherche de module par défaut utilisé lorsque PKG_CONFIG_LIBDIR n'est pas défini, la liste par défaut des chemins d'inclusion qui sont filtrés lorsque PKG_CONFIG_SYSTEM_INCLUDE_PATH n'est pas défini, et la liste par défaut des chemins de bibliothèque qui sont filtrés lorsque PKG_CONFIG_SYSTEM_LIBRARY_PATH n'est pas défini, puis quitte. La plupart des autres options et tous les arguments de la ligne de commande sont ignorés. Cette option n'est disponible que si le macro du préprocesseur PKGCONF_LITE n'a pas été défini lors de la compilation.
--env=varname
Affiche les valeurs demandées sous forme de déclarations de variables dans un format similaire à la commande env(1).
--env-only

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Initialise le chemin de recherche des modules à partir de --with-path et PKG_CONFIG_PATH uniquement, en ignorant PKG_CONFIG_LIBDIR et les répertoires par défaut compilés.
--errors-to-stdout
Imprime tous les messages d'erreur, d'avertissement et de débogage sur la sortie standard au lieu de la sortie d'erreur standard.
--exact-version=version
Vérifie les arguments module dans l'ordre donné. Quitte avec une erreur dès qu'un module n'existe pas, et quitte avec succès dès que le numéro de version d'un module est exactement le version demandé. Quitte avec une erreur si le numéro de version de chaque module diffère du version demandé.
--exists
Quitte avec un statut de sortie non nul si le résolveur de dépendances ne parvient pas à trouver tous les modules demandés. Cette option est active par défaut et ne peut pas être désactivée. Cependant, diverses autres options font que pkgconf quitte et rapporte le succès ou l'échec avant que tous les arguments aient été inspectés.
--fragment-filter=types
Filtre les listes de fragments pour les types spécifiés.
--help
Imprime un résumé d'utilisation sur la sortie standard et quitte. La plupart des autres options et tous les arguments de la ligne de commande sont ignorés.
--ignore-conflicts
Ignore les règles ‘Conflicts’ dans les modules.
--keep-system-cflags, --keep-system-libs
Conserve les fragments de CFLAGS ou de flags de linker qui seraient filtrés car inclus par défaut dans le compilateur.
--libs, --libs-only-L, --libs-only-l, --libs-only-other
Imprime tous les flags de linker nécessaires pour lier contre le module, ou uniquement les flags de chemin de bibliothèque (-L), ou uniquement les flags de bibliothèque (-l), ou uniquement les flags de linker qui ne sont ni des chemins de bibliothèque ni des flags de bibliothèque, respectivement. Ces options impliquent --print-errors.
--list-all
Parcourt le chemin de recherche des modules dans l'ordre de priorité décroissante. Pour chaque fichier pc(5) trouvé, imprime une ligne sur la sortie standard, contenant le nom de base du fichier sans l'extension, la propriété Name, un tiret (‘-’), et la propriété Description. Cette option implique --print-errors. Tous les arguments de la ligne de commande sont ignorés.
--list-package-names
Effectue la même recherche que --list-all, mais imprime uniquement le nom de base de chaque fichier pc(5) sans l'extension, pas le nom du module et la description. Cette option implique --print-errors. Tous les arguments de la ligne de commande sont ignorés.
--log-file=file
Définit le nom du fichier de sortie file où les informations sur les modules sélectionnés sont enregistrées, à la fois ceux sélectionnés par arguments et ceux sélectionnés comme dépendances. Pour chaque module sélectionné, une ligne est imprimée, contenant le nom de base du fichier pc(5) sans l'extension, éventuellement un opérateur et un numéro de version décrivant la plage de versions demandée, et soit le numéro de version réel entre crochets, soit la chaîne "NOT-FOUND". Si cette option n'est pas fournie, le nom du fichier de sortie est pris de la variable d'environnement PKG_CONFIG_LOG, et si celle-ci n'est pas non plus fournie, ce type d'enregistrement est désactivé.
--max-version=version
Vérifie les arguments module dans l'ordre donné. Quitte avec une erreur dès qu'un module n'existe pas, et quitte avec succès dès que le numéro de version d'un module est inférieur ou égal au version demandé. Quitte avec une erreur si le numéro de version de chaque module est supérieur au version demandé.
--maximum-traverse-depth=depth
Impose une limite à la profondeur autorisée dans le graphe de dépendances. Par exemple, une depth de 2 restreint le résolveur de traiter les dépendances enfants des modules ajoutés à la solution du résolveur. Cette option est outrepassée par la variable d'environnement PKG_CONFIG_MAXIMUM_TRAVERSE_DEPTH et par les options --modversion, --path, --print-provides, --print-requires, --print-requires-private, --print-variables, et --variable.
--modversion
Pour chaque module spécifié, imprime le numéro de version sur la sortie standard. Si l'option --verbose est également spécifiée, le nom du module respectif et un deux-points sont imprimés avant chaque numéro de version. Cette option implique --print-errors et --maximum-traverse-depth=1 et outrepasse et désactive tous les flags --cflags et --libs.
--msvc-syntax
Utilise la syntaxe MSVC pour la sortie de --cflags, --env, et --libs. Cette option n'est disponible que si le macro préprocesseur PKGCONF_LITE n'a pas été défini lors de la compilation.
--no-cache
Ignore la mise en cache des paquets lorsqu'ils sont chargés dans le résolveur interne. Cela peut entraîner le calcul d'un graphe de dépendances différent.
--no-provides
Ignore les règles ‘Provides’ dans les modules lors de la résolution des dépendances.
--no-uninstalled
Interdit au résolveur de dépendances de considérer les modules 'non installés' comme faisant partie d'une solution.
--path
Pour le premier module donné sur la ligne de commande, laisse le résolveur de dépendances trouver le fichier pc(5) décrivant ce module, imprime le chemin absolu de ce fichier sur la sortie standard, et quitte immédiatement, ignorant la plupart des autres options et tous les autres arguments.
--prefix-variable=variable
Définit la variable ‘prefix’ utilisée par la fonctionnalité ‘define-prefix’.
--print-errors
Imprime quelques messages concernant les erreurs fatales sur la sortie d'erreur standard qui seraient autrement omis. Cette option est implicite pour de nombreuses autres options, mais pas pour toutes. Elle peut être outrepassée avec --silence-errors.
--print-provides
Pour chaque module spécifié, imprime une ligne sur la sortie standard contenant la propriété Name, un signe égal (‘=’), et la propriété Version. Si le module contient une ou plusieurs propriétés Provides, imprime des lignes supplémentaires au format de liste de dépendances, un nom par ligne, chaque nom étant facultativement suivi d'un opérateur et d'une version. Cette option implique --maximum-traverse-depth=1 et outrepasse et désactive tous les flags --cflags et --libs.
--print-requires, --print-requires-private
Pour chaque module spécifié, imprime les propriétés Requires ou Requires.private, respectivement, au format de liste de dépendances sur la sortie standard. Ces deux options impliquent --maximum-traverse-depth=1 et outrepassent et désactivent tous les flags --cflags et --libs.
--print-variables
Pour le premier module donné sur la ligne de commande, imprime les noms de toutes les variables vues sur la sortie standard, une par ligne. Tous les arguments suivants sont ignorés silencieusement. Cette option implique --print-errors et --maximum-traverse-depth=1 et outrepasse et désactive tous les flags --cflags et --libs.
--pure
Traite le graphe de dépendances calculé comme s'il était pur. Ceci est principalement destiné à être utilisé avec le flag --static et n'a aucun effet si --shared est également spécifié.
--relocate=path
Relocalise un chemin en utilisant l'API pkgconf_path_relocate. Ceci est principalement utilisé par la suite de tests pour fournir une interface garantie au backend de relocalisation de chemin du système.
--shared
Calcule un graphe de dépendances simple qui ne convient qu'à la liaison partagée. Cette option remplace --static.
--short-errors
Lors de l'impression des messages d'erreur concernant les modules introuvables ou en conflit les uns avec les autres, évitez d'imprimer des instructions supplémentaires et verbeuses expliquant les méthodes potentielles pour résoudre le problème.
--silence-errors
Ne pas imprimer du tout de messages d'erreur, d'avertissement ou de débogage. Remplace tous les --debug, --errors-to-stdout et --print-errors. Cette option est remplacée et désactivée si la variable d'environnement PKG_CONFIG_DEBUG_SPEW est définie.
--simulate
Simule la résolution d'un graphe de dépendances basé sur les modules demandés sur la ligne de commande. Affiche une série d'arbres dénotant l'état du résolveur de pkgconf. Cette option n'est disponible que si la macro préprocesseur PKGCONF_LITE n'a pas été définie lors de la compilation.
--solution
Affiche les noms des modules demandés avec les arguments module et leurs dépendances sur la sortie standard. Cette option n'est disponible que si la macro préprocesseur PKGCONF_LITE n'a pas été définie lors de la compilation.
--static
Calcule un graphe de dépendances plus profond et utilise des indicateurs de compilateur/éditeur de liens destinés à la liaison statique. Cette option est remplacée par --shared.
--uninstalled
Quitte avec un résultat non nul si le résolveur de dépendances utilise un module « non installé » dans le cadre de sa solution.
--validate package ...
Valide des fichiers ‘.pc’ spécifiques pour leur exactitude. Cette option implique --print-errors et --errors-to-stdout.
--variable=varname
Pour le premier module donné sur la ligne de commande, imprime la valeur de la variable nommée varname sur la sortie standard. Les arguments suivants sont ignorés silencieusement. Cette option implique --maximum-traverse-depth=1 et remplace et désactive tous les indicateurs --cflags et --libs.
--verbose
Cette option n'a d'effet que si --modversion est également spécifié. Elle imprime le nom du module respectif et un deux-points avant chaque numéro de version.
--version
Imprime le numéro de version du programme pkgconf sur la sortie standard et quitte. La plupart des autres options et tous les arguments de la ligne de commande sont ignorés.
--with-path=path
Prépende le répertoire path au chemin de recherche des modules, lui donnant la priorité sur tous les autres répertoires, y compris ceux de PKG_CONFIG_PATH et PKG_CONFIG_LIBDIR.

ENVIRONNEMENT

CPATH
Première liste supplémentaire de chemins d'inclusion séparés par des deux-points, filtrée de la même manière que PKG_CONFIG_SYSTEM_INCLUDE_PATH.
CPLUS_INCLUDE_PATH
Troisième liste supplémentaire de chemins d'inclusion séparés par des deux-points, filtrée de la même manière que PKG_CONFIG_SYSTEM_INCLUDE_PATH.
C_INCLUDE_PATH
Deuxième liste supplémentaire de chemins d'inclusion séparés par des deux-points, filtrée de la même manière que PKG_CONFIG_SYSTEM_INCLUDE_PATH.
DESTDIR
Si défini avec la même valeur que PKG_CONFIG_SYSROOT_DIR, se comporte de la même manière que si PKG_CONFIG_FDO_SYSROOT_RULES est défini. Si PKG_CONFIG_SYSROOT_DIR n'est pas défini ou défini avec une valeur différente, DESTDIR est ignoré.
LIBRARY_PATH
Liste supplémentaire de chemins de bibliothèques séparés par des deux-points, filtrée de la même manière que PKG_CONFIG_SYSTEM_LIBRARY_PATH.
OBJC_INCLUDE_PATH
Quatrième liste supplémentaire de chemins d'inclusion séparés par des deux-points, filtrée de la même manière que PKG_CONFIG_SYSTEM_INCLUDE_PATH.
PKG_CONFIG_ALLOW_SYSTEM_CFLAGS
Si définie, cette variable a le même effet que l'option --keep-system-cflags.
PKG_CONFIG_ALLOW_SYSTEM_LIBS
Si définie, cette variable a le même effet que l'option --keep-system-libs.
PKG_CONFIG_DEBUG_SPEW
Si définie, remplace et désactive l'option --silence-errors.
PKG_CONFIG_DISABLE_UNINSTALLED
Si définie, active le même comportement que l'indicateur --no-uninstalled.
PKG_CONFIG_DONT_DEFINE_PREFIX
Si définie, cette variable a le même effet que l'option --dont-define-prefix.
PKG_CONFIG_DONT_RELOCATE_PATHS
Si définie, désactive la fonctionnalité de relocalisation des chemins.
PKG_CONFIG_FDO_SYSROOT_RULES
Si définie, suit les règles de préfixage du sysroot utilisées par pkg-config de freedesktop.org.
PKG_CONFIG_IGNORE_CONFLICTS
Si définie, ignore les règles Conflicts dans les modules. A le même effet que l'option --ignore-conflicts.
PKG_CONFIG_LIBDIR
Une liste de répertoires de faible priorité, séparés par des deux-points, où les fichiers pc(5) sont recherchés. Le chemin de recherche des modules est construit en ajoutant cette liste à PKG_CONFIG_PATH, qui a une priorité plus élevée. Si PKG_CONFIG_LIBDIR n'est pas définie, la liste par défaut compilée dans le programme pkgconf à partir de la macro préprocesseur PKG_DEFAULT_PATH est ajoutée à la place. Si PKG_CONFIG_LIBDIR est définie mais vide, rien n'est ajouté.
PKG_CONFIG_LOG
Si définie, enregistre des informations sur les modules sélectionnés dans le fichier dont le nom est stocké dans cette variable. Pour plus de détails, voir l'option de ligne de commande --log-file, qui remplace cette variable.
PKG_CONFIG_MAXIMUM_TRAVERSE_DEPTH
Limite la profondeur autorisée dans le graphe de dépendances. Cette variable remplace l'option --maximum-traverse-depth, mais est remplacée par les autres options mentionnées.
PKG_CONFIG_MSVC_SYNTAX
Si définie, utilise la syntaxe MSVC pour la sortie de --cflags, --env et --libs. Cette variable a le même effet que l'option --msvc-syntax. Si la macro préprocesseur PKGCONF_LITE a été définie lors de la compilation, cette variable est ignorée.
PKG_CONFIG_PATH
Une liste de répertoires de haute priorité, séparés par des deux-points, où les fichiers pc(5) sont recherchés. Le chemin de recherche des modules est construit en préfixant le répertoire spécifié avec --with-path, le cas échéant, et sauf si --env-only est spécifié, en ajoutant soit PKG_CONFIG_LIBDIR, soit les répertoires par défaut intégrés avec une priorité plus faible.
PKG_CONFIG_PRELOADED_FILES
Liste de fichiers pc(5) séparés par des deux-points qui sont chargés avant tout autre fichier pkg-config. Ces paquets reçoivent la priorité la plus élevée par rapport à tout autre fichier pc(5) qui fournirait autrement un paquet donné.
PKG_CONFIG_PURE_DEPGRAPH
Si définie, active le même comportement que l'indicateur --pure.
PKG_CONFIG_RELOCATE_PATHS
Si définie, cette variable a le même effet que l'option --define-prefix.

NAME

pkgconf

utility to query installed libraries

SYNOPSIS

pkgconf

-h

-V

--exists PACKAGE...
--version [PACKAGE...]
--atleast-version PACKAGE=VERSION
--exact-version PACKAGE=VERSION
--max-version PACKAGE=VERSION
--variable=VARIABLE [PACKAGE...]
--define-variable=VARIABLE=VALUE
--print-variables [PACKAGE...]
--cflags [PACKAGE...]
--cflags-only-I [PACKAGE...]
--cflags-only-other [PACKAGE...]
--libs [PACKAGE...]
--libs-only-L [PACKAGE...]
--libs-only-l [PACKAGE...]
--libs-only-other [PACKAGE...]
--static [PACKAGE...]
--static-libs [PACKAGE...]
--builtin-variables
--uninstalled
--path [PACKAGE...]
--direct [PACKAGE...]
--search-paths
--modversion [PACKAGE...]
--requires [PACKAGE...]
--data [PACKAGE...]
--make-install-args [PACKAGE...]
--depflags [PACKAGE...]
--compile [PACKAGE...]

DESCRIPTION

pkgconf is a program which helps to make compiling and linking easier for projects using pkg-config compatible modules. It queries installed libraries for their metadata, such as CFLAGS and LIBS, needed to compile and link against them.

This program is a successor to the original pkg-config implementation, aiming to be faster and more robust.

For a list of available options, see pkgconf(1).

The following are a subset of the available flags, detailing common usage.

ENVIRONMENT

FIG_SYSROOT_DIR
If set, this variable defines a ‘sysroot’ directory, which will be prepended to every path variable beginning with the prefix variable in a given pc(5) file. Useful for cross compilation. The value of this environment variable is also copied into the global variable pc_sysrootdir.
PKG_CONFIG_SYSTEM_INCLUDE_PATH
Colon-separated list of include paths that are filtered out and not printed by the --cflags and --cflags-only-I options because they are considered system include paths. If not defined, the default list compiled into the pkgconf program from the SYSTEM_INCLUDEDIR preprocessor macro is used instead. This variable is a pkgconf-specific extension. Any directories listed in the environment variables CPATH, C_INCLUDE_PATH, CPLUS_INCLUDE_PATH, and OBJC_INCLUDE_PATH are also filtered out.
PKG_CONFIG_SYSTEM_LIBRARY_PATH
Colon-separated list of library paths that are filtered out and not printed by the --libs and --libs-only-L options because they are considered system library paths. If not defined, the default list compiled into the pkgconf program from the SYSTEM_LIBDIR preprocessor macro is used instead. This variable is a pkgconf-specific extension.
PKG_CONFIG_TOP_BUILD_DIR
The value of the pc_top_builddir global variable. If this environment variable is not defined, the string "$(top_builddir)" is used as the value of pc_top_builddir.

EXIT STATUS

The pkgconf utility exits 0 on success, and >0 if an error occurs.

EXAMPLES

Displaying the CFLAGS of a package:

$ pkgconf --cflags foo
-fPIC -I/usr/include/foo
