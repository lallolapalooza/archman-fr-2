PKCHECK(1) pkcheck PKCHECK(1)

NOM

pkcheck - Vérifie si un processus est autorisé

SYNTAXE

pkcheck [--version] [--help|-h]

pkcheck [--list-temp]

pkcheck [--revoke-temp]

pkcheck --action-id|-a action {--process|-p { pid | pid-heure_début | pid,heure_début,uid } | --system-bus-name|-s nom_bus} [--allow-user-interaction|-u] [--enable-internal-agent] [--detail|-d clé valeur...]

DESCRIPTION

pkcheck est utilisé pour vérifier si un processus, spécifié par --process (voir ci-dessous) ou --system-bus-name, est autorisé pour une action. L'option --detail peut être utilisée zéro ou plusieurs fois pour passer des détails sur l'action. Si --allow-user-interaction est passé, pkcheck se bloque en attendant l'authentification.

L'invocation pkcheck --list-temp listera toutes les autorisations temporaires pour la session courante et pkcheck --revoke-temp révoquera toutes les autorisations temporaires pour la session courante.

Cette commande est un simple wrapper autour de l'interface D-Bus de polkit ; consultez la documentation de l'interface D-Bus pour plus de détails.

VALEUR DE RETOUR

Si le processus spécifié est autorisé, pkcheck se termine avec une valeur de retour de 0. Si le résultat de l'autorisation contient des détails, ceux-ci sont imprimés sur la sortie standard sous forme de paires clé/valeur utilisant le style de rapport d'environnement, par exemple d'abord la clé suivie d'un signe égal, puis la valeur suivie d'un saut de ligne.

CLE1=VALEUR1
CLE2=VALEUR2
CLE3=VALEUR3
...

Les octets qui ne sont pas dans [a-zA-Z0-9_] sont échappés en utilisant des codes octaux préfixés par \. Par exemple, la chaîne UTF-8 føl,你好 sera imprimée comme f\303\270l\54\344\275\240\345\245\275.

Si le processus spécifié n'est pas autorisé, pkcheck se termine avec une valeur de retour de 1 et un message de diagnostic est imprimé sur la sortie d'erreur standard. Les détails sont imprimés sur la sortie standard.

Si le processus spécifié n'est pas autorisé parce qu'aucun agent d'authentification approprié n'est disponible ou si --allow-user-interaction n'a pas été passé, pkcheck se termine avec une valeur de retour de 2 et un message de diagnostic est imprimé sur la sortie d'erreur standard. Les détails sont imprimés sur la sortie standard.

Si le processus spécifié n'est pas autorisé parce que la boîte de dialogue d'authentification / la requête a été rejetée par l'utilisateur, pkcheck se termine avec une valeur de retour de 3 et un message de diagnostic est imprimé sur la sortie d'erreur standard. Les détails sont imprimés sur la sortie standard.

Si une erreur s'est produite lors de la vérification de l'autorisation, pkcheck se termine avec une valeur de retour de 127 avec un message de diagnostic imprimé sur la sortie d'erreur standard.

Si une ou plusieurs des options passées sont malformées, pkcheck se termine avec une valeur de retour de 126. Si stdin est un tty, alors cette page de manuel est également affichée.

NOTES

N'utilisez ni la forme pid nue ni la forme pid,heure_début pour --process. Il existe des conditions de concurrence dans les deux. Le nouveau code doit toujours utiliser pid,heure_début,uid. La valeur de heure_début peut être déterminée en consultant par exemple le système de fichiers proc(5) en fonction du système d'exploitation. Si moins de 3 arguments sont passés, pkcheck tentera de les rechercher en interne, mais notez que cela peut être sujet à des conditions de concurrence.

Si votre programme est un démon avec, par exemple, un socket Unix personnalisé, vous devriez déterminer le paramètre uid via des mécanismes du système d'exploitation tels que PEERCRED.

AGENT D'AUTHENTIFICATION

pkcheck, comme toute autre application polkit, utilisera l'agent d'authentification enregistré pour le processus en question. Cependant, si aucun agent d'authentification n'est disponible, pkcheck peut enregistrer son propre agent d'authentification textuel si l'option --enable-internal-agent est passée.
