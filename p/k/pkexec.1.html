PKEXEC(1) pkexec PKEXEC(1)

NOM

pkexec - Exécute une commande en tant qu'un autre utilisateur

SYNTAXE

pkexec [--version] [--disable-internal-agent] [--help]

pkexec [--keep-cwd] [--user nomutilisateur] PROGRAMME [ARGUMENTS...]

DESCRIPTION

pkexec permet à un utilisateur autorisé d'exécuter PROGRAMME en tant qu'un autre utilisateur. Si PROGRAMME n'est pas spécifié, le shell par défaut sera exécuté. Si nomutilisateur n'est pas spécifié, le programme sera exécuté en tant que superutilisateur administratif, root.

VALEUR DE RETOUR

En cas de succès, la valeur de retour est la valeur de retour de PROGRAMME. Si le processus appelant n'est pas autorisé ou si une autorisation n'a pas pu être obtenue par authentification ou si une erreur s'est produite, pkexec se termine avec une valeur de retour de 127. Si l'autorisation n'a pas pu être obtenue car l'utilisateur a rejeté la boîte de dialogue d'authentification, pkexec se termine avec une valeur de retour de 126.

AGENT D'AUTHENTIFICATION

pkexec, comme toute autre application polkit, utilisera l'agent d'authentification enregistré pour le processus appelant ou la session. Cependant, si aucun agent d'authentification n'est disponible, pkexec enregistrera son propre agent d'authentification textuel. Ce comportement peut être désactivé en passant l'option --disable-internal-agent.

NOTES DE SÉCURITÉ

Exécuter un programme en tant qu'un autre utilisateur est une opération privilégiée. Par défaut, l'action à vérifier (voir la section « ACTION ET AUTORISATIONS ») nécessite une authentification administrateur. De plus, la boîte de dialogue d'authentification présentée à l'utilisateur affichera le chemin complet du programme à exécuter afin que l'utilisateur soit informé de ce qui va se passer.

L'environnement dans lequel PROGRAMME sera exécuté sera configuré avec un environnement minimal connu et sûr afin d'éviter l'injection de code via LD_LIBRARY_PATH ou des mécanismes similaires. De plus, la variable d'environnement PKEXEC_UID est définie avec l'ID utilisateur du processus qui appelle pkexec. Par conséquent, pkexec ne vous permettra pas par défaut d'exécuter des applications X11 en tant qu'un autre utilisateur car les variables d'environnement $DISPLAY et $XAUTHORITY ne sont pas définies. Ces deux variables seront conservées si l'annotation org.freedesktop.policykit.exec.allow_gui sur une action est définie avec une valeur non vide ; ceci est cependant déconseillé et ne doit être utilisé que pour des programmes hérités.

pkexec exécutera PROGRAMME dans le répertoire personnel de nomutilisateur, sauf si --keep-cwd est utilisé pour outrepasser ce comportement.

Notez que pkexec n'effectue aucune validation des ARGUMENTS transmis à PROGRAMME. Dans le cas normal (où l'authentification administrateur est requise à chaque utilisation de pkexec), ce n'est pas un problème car si l'utilisateur est un administrateur, il peut tout aussi bien exécuter pkexec bash pour obtenir les droits root.

Cependant, si une action est utilisée pour laquelle l'utilisateur peut conserver son autorisation (ou si l'utilisateur est implicitement autorisé), cela pourrait constituer une faille de sécurité. Par conséquent, en règle générale, les programmes pour lesquels l'autorisation par défaut requise est modifiée, ne doivent jamais faire confiance implicitement aux entrées utilisateur (par exemple, comme tout autre programme suid bien écrit).

ACTION ET AUTORISATIONS

Par défaut, l'action org.freedesktop.policykit.exec est utilisée. Pour utiliser une autre action, utilisez l'annotation org.freedesktop.policykit.exec.path sur une action dont la valeur est définie sur le chemin complet du programme. En plus de spécifier le programme, le message d'authentification, la description, l'icône et les options par défaut peuvent être spécifiés. Si l'annotation org.freedesktop.policykit.exec.argv1 est présente, l'action ne sera sélectionnée que si le premier argument du programme correspond à la valeur de l'annotation.

Notez que les messages d'authentification peuvent référencer des variables (voir la section « VARIABLES »), par exemple $(user) sera développé avec la valeur de la variable user.

UTILISATION DE WRAPPER

Afin d'éviter de modifier les logiciels existants pour préfixer leurs invocations en ligne de commande avec pkexec, il est possible d'utiliser pkexec dans un wrapper she-bang[1] comme ceci :

#!/usr/bin/pkexec /usr/bin/python
import os
import sys
print "Hello, I'm running as uid %d"%(os.getuid())
for n in range(len(sys.argv)):
    print "arg[%d]=`%s'"%(n, sys.argv[n])

Si ce script est installé dans /usr/bin/my-pk-test, alors les annotations suivantes

  [...]
  <annotate key="org.freedesktop.policykit.exec.path">/usr/bin/python</annotate>
  <annotate key="org.freedesktop.policykit.exec.argv1">/usr/bin/my-pk-test</annotate>
  [...]

peuvent être utilisées pour sélectionner l'action polkit appropriée. Soyez attentif à bien configurer la dernière annotation, sinon elle correspondra à toute invocation pkexec de scripts /usr/bin/python.

VARIABLES

Les variables suivantes sont définies par pkexec. Elles peuvent être utilisées dans les règles d'autorisation et les messages affichés dans les boîtes de dialogue d'authentification :

programme

Chemin complet du programme à exécuter. Exemple : « /bin/cat »

ligne_commande

La ligne de commande demandée (n'utilisez pas ceci pour des vérifications de sécurité, ce n'est pas sécurisé). Exemple : « cat /srv/xyz/foobar »

utilisateur

Le nom d'utilisateur sous lequel exécuter le programme. Exemple : « davidz »

utilisateur.gecos

Le nom complet de l'utilisateur sous lequel exécuter le programme. Exemple : « David Zeuthen »

utilisateur.display

Une représentation de l'utilisateur à exécuter, adaptée à l'affichage dans une boîte de dialogue d'authentification. Est généralement définie sur une combinaison du nom d'utilisateur et du nom complet. Exemple : « David Zeuthen (davidz) »

pkexec(1)

pkexec - exécute une commande en tant qu'autre utilisateur

NOM

pkexec - exécute une commande en tant qu'autre utilisateur

SYNTAXE

pkexec [--version] [--help] [--disable-internal-agent] [--assume-authenticated] [--] PROGRAM [ARGUMENTS...]

DESCRIPTION

pkexec est un utilitaire qui permet à un utilisateur autorisé d'exécuter une commande en tant qu'un autre utilisateur (par défaut l'utilisateur root).

pkexec fonctionne en examinant les fichiers d'autorisation définis dans /usr/share/polkit-1/actions/. Ces fichiers spécifient quelles actions sont autorisées pour quels utilisateurs et sous quelles conditions. Si une action est autorisée, pkexec lance un agent d'authentification (généralement via un dialogue graphique) pour demander à l'utilisateur de confirmer son identité. Si l'authentification réussit, la commande est exécutée avec les privilèges appropriés.

VALEUR DE RETOUR

pkexec retourne la valeur de sortie du PROGRAM exécuté.

AGENT D'AUTHENTIFICATION

pkexec utilise un agent d'authentification pour demander à l'utilisateur son mot de passe ou une autre forme d'authentification. L'agent d'authentification par défaut est un dialogue graphique fourni par Polkit. Il est possible de désactiver l'agent d'authentification interne avec l'option --disable-internal-agent, mais cela peut avoir des implications de sécurité.

NOTES DE SÉCURITÉ

L'utilisation de pkexec doit être faite avec prudence. Il permet d'exécuter des commandes avec des privilèges élevés, ce qui peut potentiellement compromettre la sécurité du système si elle est mal utilisée. Les fichiers d'autorisation doivent être configurés de manière appropriée pour limiter l'accès aux commandes sensibles.

ACTION ET AUTORISATIONS

pkexec détermine si une commande peut être exécutée en se basant sur les fichiers d'action Polkit. Ces fichiers définissent les actions possibles, leurs descriptions et les autorisations requises. L'administrateur système peut modifier ou ajouter des fichiers d'action pour personnaliser le comportement de pkexec.

UTILISATION DU WRAPPER

pkexec peut être utilisé comme un wrapper pour des commandes qui nécessitent des privilèges élevés. Par exemple, pour exécuter nano en tant que root, on utiliserait pkexec nano.

VARIABLES

Certaines variables d'environnement peuvent affecter le comportement de pkexec, notamment celles liées à l'interface graphique et à l'authentification.

AUTEUR

Ce manuel a été écrit par l'équipe d'Arch Linux.

BOGUES

Signaler les bogues à <https://bugs.archlinux.org/>.

VOIR AUSSI

sudo(1), su(1), polkit(8)

NOTES

pkexec est une alternative plus moderne et plus flexible à su et sudo pour l'exécution de commandes avec des privilèges élevés. Il s'intègre étroitement avec le système Polkit pour une gestion fine des autorisations.
