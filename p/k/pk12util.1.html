PK12UTIL(1) Outils de sécurité NSS PK12UTIL(1)

NOM

pk12util - Exporter et importer des clés et certificats vers ou depuis un fichier PKCS #12 et la base de données NSS

SYNTAXE

pk12util [-i fichierP12|-l fichierP12|-o fichierP12] [-c chiffrementCle] [-C chiffrementCert] [-d repertoire] [-h nomToken] [-m | --longueur-cle longueurCle] [-M algoHachage] [-n nomCert] [-P prefixeBd] [-r] [-v] [--longueur-cle-cert longueurCleCert] [-k fichierMdpSlot|-K mdpSlot] [-w fichierMdpP12|-W mdpP12]

STATUT

Cette documentation est toujours en cours de développement. Veuillez contribuer à la revue initiale dans le bug NSS 836477 de Mozilla[1]

DESCRIPTION

L'utilitaire PKCS #12, pk12util, permet le partage de certificats entre tout serveur prenant en charge PKCS #12. L'outil peut importer des certificats et des clés depuis des fichiers PKCS #12 vers des bases de données de sécurité, exporter des certificats, et lister des certificats et des clés.

OPTIONS ET ARGUMENTS

Options

-i fichierP12

Importe des clés et certificats d'un fichier PKCS #12 dans une base de données de sécurité.

-l fichierP12

Liste les clés et certificats dans un fichier PKCS #12.

-o fichierP12

Exporte des clés et certificats de la base de données de sécurité vers un fichier PKCS #12.

Arguments

-c chiffrementCle

Spécifie l'algorithme de chiffrement de clé.

-C chiffrementCert

Spécifie l'algorithme de chiffrement de certificat.

-d repertoire

Spécifie le répertoire de la base de données vers lequel importer ou depuis lequel exporter des certificats et clés.

pk12util prend en charge deux types de bases de données : les bases de données de sécurité héritées (cert8.db, key3.db et secmod.db) et les nouvelles bases de données SQLite (cert9.db, key4.db et pkcs11.txt). Si le préfixe dbm: n'est pas utilisé, l'outil suppose que les bases de données fournies sont au format SQLite.

-h nomToken

Spécifie le nom du token à importer ou à exporter.

-k fichierMdpSlot

Spécifie le fichier texte contenant le mot de passe du slot.

-K mdpSlot

Spécifie le mot de passe du slot.

-m | --longueur-cle longueurCle

Spécifie la longueur désirée de la clé symétrique à utiliser pour chiffrer la clé privée.

-M algoHachage

Spécifie l'algorithme de hachage utilisé dans le MAC de pkcs #12. Cet algorithme spécifie également le HMAC utilisé dans le PRF lors de l'utilisation de pkcs #5 v2.

--longueur-cle-cert longueurCleCert

Spécifie la longueur désirée de la clé symétrique à utiliser pour chiffrer les certificats et autres métadonnées.

-n nomCert

Spécifie le pseudonyme du certificat et de la clé privée à exporter.

Le pseudonyme peut également être une URI PKCS #11. Par exemple, si vous avez un certificat nommé "certificat-serveur-mon" dans le magasin de certificats interne, il peut être spécifié sans ambiguïté comme "pkcs11:token=NSS%20Certificate%20DB;object=certificat-serveur-mon". Pour plus de détails sur le format, voir RFC 7512.

-P prefixe

Spécifie le préfixe utilisé sur les bases de données de certificats et de clés. Cette option est fournie à titre exceptionnel. Modifier les noms des bases de données de certificats et de clés n'est pas recommandé.

-r

Affiche toutes les données sous forme brute (binaire). Cela doit être enregistré sous forme de fichier DER. Par défaut, les informations sont renvoyées dans un format texte ASCII imprimable, qui affiche les informations sur les certificats et les clés publiques dans le fichier p12.

-v

Active la journalisation de débogage lors de l'importation.

-w fichierMdpP12

Spécifie le fichier texte contenant le mot de passe du fichier pkcs #12.

-W mdpP12

Spécifie le mot de passe du fichier pkcs #12.

CODES DE RETOUR

•0 - Aucune erreur
•1 - Annulé par l'utilisateur
•2 - Erreur d'utilisation
•6 - Erreur d'initialisation NLS
•8 - Erreur d'ouverture de la base de données de certificats
•9 - Erreur d'ouverture de la base de données de clés
•10 - Erreur d'initialisation de fichier
•11 - Erreur de conversion Unicode
•12 - Erreur de création de fichier temporaire
•13 - Erreur d'obtention de slot PKCS11
•14 - Erreur de démarrage du décodeur PKCS12
•15 - Erreur de lecture du fichier d'importation
•16 - Erreur de décodage pkcs12
•17 - Erreur de vérification du décodeur pkcs12
•18 - Erreur de validation des sacs du décodeur pkcs12
•19 - Erreur d'importation des sacs du décodeur pkcs12
•20 - Erreur de conversion de la base de données de clés version 3 vers version 2
•21 - Erreur de conversion de la base de données de certificats version 7 vers version 5
•22 - Erreur de patch des bases de données de certificats et de clés
•23 - Erreur d'obtention de la base de données de certificats par défaut
•24 - Erreur de recherche de certificat par pseudonyme
•25 - Erreur de création du contexte d'exportation
•26 - Erreur d'intégrité du mot de passe d'ajout PKCS12
•27 - Erreur de création des sacs de certificats et de clés PKCS12
•28 - Erreur d'ajout de certificat et de clé PKCS12
•29 - Erreur d'encodage PKCS12

EXEMPLES

Importation de clés et certificats

L'utilisation la plus basique de pk12util pour importer un certificat ou une clé est le fichier d'entrée PKCS #12 (-i) et un moyen de spécifier la base de données de sécurité accédée (soit -d pour un répertoire, soit -h pour un token).

pk12util -i fichierP12 [-h nomToken] [-v] [-d repertoire] [-P prefixeBd] [-k fichierMdpSlot|-K mdpSlot] [-w fichierMdpP12|-W mdpP12]

Par exemple :

# pk12util -i /tmp/cert-files/users.p12 -d /home/my/sharednssdb
Entrez un mot de passe qui sera utilisé pour chiffrer vos clés.
Le mot de passe doit comporter au moins 8 caractères,
et doit contenir au moins un caractère non alphabétique.
Nouveau mot de passe : 
Confirmez le mot de passe : 
Entrez le mot de passe du fichier PKCS12 : 
pk12util: IMPORTATION PKCS12 RÉUSSIE

Exportation de clés et certificats

L'utilisation de la commande pk12util pour exporter des certificats et des clés nécessite à la fois le nom du certificat à extraire de la base de données (-n) et le fichier de sortie au format PKCS #12 à écrire. Il existe des paramètres optionnels qui peuvent être utilisés pour chiffrer le fichier afin de protéger le matériel du certificat.

pk12util -o fichierP12 -n nomCert [-c chiffrementCle] [-C chiffrementCert] [-m|--longueur-cle longueurCle] [-n|--longueur-cle-cert longueurCleCert] [-d repertoire] [-P prefixeBd] [-k fichierMdpSlot|-K mdpSlot] [-w fichierMdpP12|-W mdpP12]

Par exemple :

# pk12util -o certs.p12 -n Certificat-Serveur -d /home/my/sharednssdb
Entrez le mot de passe du fichier PKCS12 : 
Confirmez le mot de passe :

Lister les clés et certificats

Les informations contenues dans un fichier .p12 ne sont pas lisibles par l'homme. Les certificats et clés du fichier peuvent être imprimés (listés) dans un format texte imprimable lisible par l'homme qui affiche des informations pour chaque certificat et toutes les clés publiques dans le fichier .p12.

pk12util -l fichierP12 [-h nomToken] [-r] [-d repertoire] [-P prefixeBd] [-k fichierMdpSlot|-K mdpSlot] [-w fichierMdpP12|-W mdpP12]

Par exemple, ceci affiche la sortie ASCII par défaut :

pk12util(1) - Manuel Linux

NAME

pk12util - Importer et exporter des clés privées et des certificats via des fichiers PKCS #12.

SYNOPSIS

pk12util [options]

STATUS

Ce programme est un utilitaire de ligne de commande pour l'exportation et l'importation de clés privées et de certificats via des fichiers PKCS #12. Il est utilisé par des applications telles que Firefox et Thunderbird.

DESCRIPTION

Le fichier PKCS #12 est un format de fichier qui peut stocker des informations cryptographiques, y compris des certificats et des clés privées. Il est souvent utilisé pour importer ou exporter des certificats et des clés privées dans ou à partir d'un magasin de clés.

L'outil pk12util permet d'effectuer les opérations suivantes:

  • Exporter des clés privées et des certificats dans un fichier PKCS #12.
  • Importer des clés privées et des certificats à partir d'un fichier PKCS #12.
  • Lister le contenu d'un fichier PKCS #12.

OPTIONS AND ARGUMENTS

Les options suivantes sont disponibles:

-i infile
Spécifie le fichier PKCS #12 à importer.
-o outfile
Spécifie le fichier PKCS #12 à exporter.
-l
Liste le contenu du fichier PKCS #12 spécifié par -i ou -o.
-n nickname
Spécifie le surnom d'une clé privée ou d'un certificat.
-d dirpath
Spécifie le répertoire contenant les bases de données de sécurité NSS. Le chemin par défaut est ~/.dogtag/nssdb.
-P password
Spécifie le mot de passe pour le fichier PKCS #12. Si cette option n'est pas spécifiée, il vous sera demandé d'entrer le mot de passe.
-e
Active l'exportation de clé privée. Utilisé avec -o.
-c
Active l'exportation de certificats. Utilisé avec -o.
-r
Exportation de certificats dans des fichiers binaires DER séparés. Utilisé avec -o.
-C cipher
Spécifie l'algorithme de chiffrement à utiliser pour chiffrer les certificats. Les options valides sont "NONE", "RC2", "DES", "DES3", "AES".
-F cipher
Spécifie l'algorithme de chiffrement à utiliser pour chiffrer les clés privées. Les options valides sont "RC2", "DES", "DES3", "AES".
-a
Convertit le fichier PKCS #12 au format texte ASCII.
-v
Active le mode verbeux.
-h
Affiche le message d'aide.

RETURN CODES

L'outil pk12util retourne 0 en cas de succès, et une valeur différente de zéro en cas d'échec.

EXAMPLES

Pour exporter un fichier PKCS #12:

pk12util -o mycert.p12 -n "My Certificate" -e -c

Cela exportera le certificat et la clé privée associés au surnom "My Certificate" dans le fichier mycert.p12.

Pour importer un fichier PKCS #12:

pk12util -i mycert.p12 -n "My Certificate"

Cela importera le certificat et la clé privée du fichier mycert.p12 dans le magasin de clés NSS.

Pour lister le contenu d'un fichier PKCS #12:

pk12util -l mycert.p12

Cela affichera les informations sur les certificats et les clés contenus dans le fichier mycert.p12.

Alternativement, l'option -r imprime les certificats puis les exporte dans des fichiers binaires DER séparés. Cela permet de transmettre les certificats à une autre application qui prend en charge les fichiers .p12. Chaque certificat est écrit dans un fichier numéroté séquentiellement, en commençant par file0001.der et en continuant jusqu'à file000N.der, en incrémentant le nombre pour chaque certificat:

pk12util -l test.p12 -r
Entrez le mot de passe du fichier PKCS12: 
Clé(chiffrée):
    Nom convivial: Thawte Freemail Member's Thawte Consulting (Pty) Ltd. ID
    Algorithme de chiffrement: PKCS #12 V2 PBE With SHA-1 And 3KEY Triple DES-CBC
        Paramètres:
            Sel:
                45:2e:6a:a0:03:4d:7b:a1:63:3c:15:ea:67:37:62:1f
            Compteur d'itérations: 1 (0x1)
Certificat    Nom convivial: Thawte Personal Freemail Issuing CA - Thawte Consulting
Certificat    Nom convivial: Thawte Freemail Member's Thawte Consulting (Pty) Ltd. ID

PASSWORD ENCRYPTION

PKCS #12 permet non seulement la protection des clés privées mais aussi du certificat et des métadonnées associées aux clés. Le chiffrement par mot de passe est utilisé pour protéger les clés privées lors de l'exportation vers un fichier PKCS #12 et, éventuellement, les certificats associés. Si aucun algorithme n'est spécifié, l'outil utilise par défaut PKCS #12 SHA-1 et triple DES à 3 clés pour le chiffrement des clés privées. En mode non FIPS, PKCS #12 SHA-1 et RC4 40 bits sont utilisés pour le chiffrement des certificats. En mode FIPS, il n'y a pas de chiffrement de certificat. Si le chiffrement de certificat n'est pas souhaité, spécifiez "NONE" comme argument de l'option -C.

La clé privée est toujours protégée par un chiffrement fort par défaut.

Plusieurs types de chiffrements sont pris en charge.

Chiffrement par mot de passe PKCS #5

•PBES2 avec AES-CBC-Pad comme schéma de chiffrement sous-jacent ("AES-128-CBC", "AES-192-CBC", et "AES-256-CBC")

Chiffrement par mot de passe PKCS #12

•SHA-1 et RC4 128 bits ("PKCS #12 V2 PBE With SHA-1 And 128 Bit RC4" ou "RC4")
•SHA-1 et RC4 40 bits ("PKCS #12 V2 PBE With SHA-1 And 40 Bit RC4") (utilisé par défaut pour le chiffrement des certificats en mode non FIPS)
•SHA-1 et triple DES 3 clés ("PKCS #12 V2 PBE With SHA-1 And 3KEY Triple DES-CBC" ou "DES-EDE3-CBC")
•SHA-1 et RC2 128 bits ("PKCS #12 V2 PBE With SHA-1 And 128 Bit RC2 CBC" ou "RC2-CBC")
•SHA-1 et RC2 40 bits ("PKCS #12 V2 PBE With SHA-1 And 40 Bit RC2 CBC")

Avec PKCS #12, le fournisseur de cryptographie peut être le module de token logiciel ou un module matériel externe. Si le module cryptographique ne prend pas en charge l'algorithme demandé, le meilleur substitut sera sélectionné (généralement par défaut). Si aucun remplacement approprié pour l'algorithme désiré ne peut être trouvé, l'outil retourne l'erreur no security module can perform the requested operation.

NSS DATABASE TYPES

NSS utilisait à l'origine des bases de données BerkeleyDB pour stocker les informations de sécurité. Les dernières versions de ces bases de données héritées sont:

•cert8.db pour les certificats
•key3.db pour les clés
•secmod.db pour les informations sur les modules PKCS #11

BerkeleyDB a des limitations de performance, cependant, qui l'empêchent d'être facilement utilisé par plusieurs applications simultanément. NSS a une certaine flexibilité qui permet aux applications d'utiliser leur propre moteur de base de données indépendant tout en conservant une base de données partagée et en contournant les problèmes d'accès. Néanmoins, NSS nécessite plus de flexibilité pour fournir une base de données de sécurité véritablement partagée.

En 2009, NSS a introduit un nouvel ensemble de bases de données qui sont des bases de données SQLite plutôt que BerkleyDB. Ces nouvelles bases de données offrent plus d'accessibilité et de performance:

•cert9.db pour les certificats
•key4.db pour les clés
•pkcs11.txt, qui est une liste de tous les modules PKCS #11 contenus dans un nouveau sous-répertoire dans le répertoire des bases de données de sécurité

Comme les bases de données SQLite sont conçues pour être partagées, ce sont des bases de données de type partagé. Le type de base de données partagée est préféré; le format hérité est inclus pour la compatibilité descendante.

Par défaut, les outils (certutil, pk12util, modutil) supposent que les bases de données de sécurité données utilisent le type SQLite. L'utilisation des bases de données héritées doit être spécifiée manuellement en utilisant le préfixe dbm: avec le répertoire de sécurité donné. Par exemple:

# pk12util -i /tmp/cert-files/users.p12 -d dbm:/home/my/sharednssdb

Pour définir le type de base de données hérité comme type par défaut pour les outils, définissez la variable d'environnement NSS_DEFAULT_DB_TYPE à dbm:

export NSS_DEFAULT_DB_TYPE="dbm"

Cette ligne peut être ajoutée au fichier ~/.bashrc pour rendre le changement permanent.

COMPATIBILITY NOTES

Le comportement d'exportation de pk12util a changé au fil du temps, tandis que l'importation de fichiers exportés avec des versions plus anciennes de NSS est toujours prise en charge.

Jusqu'à la version 3.30, pk12util utilisait l'encodage UTF-16 pour les schémas de chiffrement par mot de passe PKCS #5, alors que la recommandation est d'encoder les mots de passe en UTF-8 si le schéma de chiffrement utilisé est défini en dehors de la norme PKCS #12.

Jusqu'à la version 3.31, même lorsque "AES-128-CBC" ou "AES-192-CBC" était spécifié en ligne de commande, pk12util utilisait toujours AES 256 bits comme schéma de chiffrement sous-jacent.

Pour des raisons historiques, pk12util accepte des schémas de chiffrement par mot de passe non listés dans ce document. Cependant, ces schémas ne sont pas officiellement pris en charge et peuvent poser des problèmes d'interopérabilité avec d'autres outils.
