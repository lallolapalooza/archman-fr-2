PKCS15-PROFILE(5) Formats de fichiers OpenSC PKCS15-PROFILE(5)

NOM

pkcs15-profile - format du profil pour pkcs15-init

DESCRIPTION

L'utilitaire pkcs15-init pour la personnalisation de cartes à puce PKCS #15 est contrôlé via des profils. Au démarrage, il lira deux de ces profils à l'heure actuelle, un profil d'application générique et un profil spécifique à la carte. Le profil générique doit être spécifié sur la ligne de commande, tandis que le fichier spécifique à la carte est sélectionné en fonction du type de carte détectée.

Le profil d'application générique définit des informations générales sur la disposition de la carte, telles que le chemin du DF d'application, divers fichiers PKCS #15 dans ce répertoire, et les conditions d'accès à ces fichiers. Il définit également des informations générales sur les objets PIN, clés et certificats. Actuellement, il n'existe qu'un seul profil générique de ce type, pkcs15.profile.

Le profil spécifique à la carte contient des informations supplémentaires requises lors de l'initialisation de la carte, telles que l'emplacement des fichiers PIN, les références de clés, etc. Les profils résident actuellement dans /usr/share/opensc

Terminologie PKCS#15 de base :

1. MF (Master File) est la racine de la hiérarchie du système de fichiers
2. DF (PKCS#15) est le répertoire contenant les fichiers et répertoires PKCS#15
3. EF (ODF) (Object Directory File) est un fichier élémentaire contenant des pointeurs vers d'autres fichiers élémentaires (PrKDF, PuKDF, SKDF, CDF, DODF, AODF)
4. PrKDF (Private Key Directory File) est un fichier élémentaire contenant des pointeurs vers les clés privées et des informations supplémentaires sur les clés privées
5. PubKDF (Public Key Directory File) est un fichier élémentaire contenant des pointeurs vers les clés publiques et des informations supplémentaires sur les clés publiques
6. CDF (Certificate Directory File) est un fichier élémentaire contenant des pointeurs vers les certificats et des informations supplémentaires sur les certificats
7. EF (TokenInfo) est un fichier élémentaire avec des informations génériques sur la carte

SYNTAXE ET SEMANTIQUE

La syntaxe des blocs des fichiers de profil est, en général, similaire à celle du fichier de configuration. Le fichier de profil est composé de blocs, qui, en général, ont le format suivant :

clé [, nom...] {
	contenu_du_bloc
}

contenu_du_bloc est un ou plusieurs item_de_bloc où un item_de_bloc est soit

•# chaîne de commentaire
•clé[, nom...] = valeur;
•bloc

Au niveau racine, le profil contient plusieurs blocs de configuration. Les clés de bloc sont les suivantes :

•cardinfo : Configuration pour les informations générales sur la carte.
•pkcs15 : Contrôle de certains aspects généraux du PKCS#15 placé sur la carte.
•option : Options du profil pour modifier le comportement du profil.
•PIN : Configuration et limites pour un type de PIN particulier.
•filesystem : Spécification du système de fichiers qui doit être créé sur la carte.
•macros

Configuration du fichier de profil

Configuration des informations de la carte

cardinfo { contenu_du_bloc }

Configuration des informations générales sur la carte :

label = nom;

Libellé de la carte (Défaut : OpenSC Card).

manufacturer = nom;

Fabricant de la carte (Défaut : OpenSC Project).

min-pin-length = int;

Longueur minimale du PIN (Défaut : 4).

max-pin-length = int;

Longueur maximale du PIN, devrait être remplacée dans le profil par carte (Défaut : 8).

pin-encoding = valeur;

Type de codage du PIN. Paramètres connus :
•BCD : décimal codé binaire
•ascii-numeric : valeurs numériques ASCII
•utf8
•half-nibble-bcd
•iso9564-1

(Défaut : ascii-numeric).

pin-pad-char = valeur;

Caractère utilisé pour le remplissage du PIN lorsque nécessaire (Défaut : 0x00).

pin-domains = bool;

Certaines cartes nécessitent de conserver tous leurs PIN dans des répertoires séparés. Les clés particulières de ce domaine seront placées sous le DF du PIN spécifié. (Défaut : non)

Configuration de PKCS#15

pkcs15 { contenu_du_bloc }

Contrôle de certains aspects généraux du PKCS#15 placé sur la carte. Les paramètres de ce bloc sont :

direct-certificates = bool;

Le système PKCS#15 doit contenir au moins un CDF, il contient les certificats directement ou des références vers des certificats. Cette option définit si les certificats doivent être placés directement dans le CDF lui-même ou non (Défaut : non).

encode-df-length = bool;

Sauvegarde la longueur du DF dans le fichier ODF. Utile si nous stockons des certificats directement dans le CDF pour une meilleure meilleure performance et robustesse (Défaut : non).

do-last-update = valeur;

Stocke les informations sur la dernière mise à jour dans l'EF(TokenInfo) (Défaut : oui).

pkcs15-id-style = valeur;

Méthode de calcul de l'ID des objets cryptographiques. Paramètres connus :
•native : 'E' + nombre_d_objets_présents_du_même_type
•mozilla : SHA1(module) pour RSA
•rfc2459 SHA1(Séquence ASN1 des composants de clé publique en tant qu'entiers ASN1)
(Défaut : native) .sp

minidriver-support-style = valeur;

Style de support minidriver de pkcs15-init. Paramètres connus :
•none
•gemalto

(Défaut : none)

Configuration des options du profil

option nom { contenu_du_bloc } .PP Le nom spécifie les options du profil pour modifier le comportement du profil, il peut être .PP .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . default: l'option spécifie les paramètres par défaut et ce bloc avec l'option est toujours traité, .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . onepin: option pour utiliser 1 PIN utilisateur, la création/suppression/génération est contrôlée par le PIN utilisateur et donc par l'utilisateur (en conséquence, seulement 1 PIN utilisateur est possible), .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . small option adaptée aux cartes avec une petite mémoire. .RE .sp .PP Les options sont utilisées par l'outil pkcs15-init via --profile name, -p name : .PP .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . pkcs15+default : le défaut (pas besoin de le spécifier) .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . pkcs15+onepin : pour l'option de profil onepin .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . pkcs15+small pour l'option de profil small .RE .sp .PP Le bloc option peut contenir les sous-blocs suivants :

macros { contenu_du_bloc }

Les macros sont spécifiées sous forme de paires nom = valeur ;.

pkcs15 { contenu_du_bloc }

Bloc interne pour la configuration de la structure PKCS#15.

Configuration des PIN

PIN nom { contenu_du_bloc } .PP Le nom spécifie le type de PIN, il peut être .PP .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . pin ou user-pin (pas besoin de définir le chemin du fichier ou la référence car ils sont faits dynamiquement) .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . puk ou user-puk .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . sopin ou so-pin .RE .sp .RS 4 .ie n  • . .el  .sp

NAME

pkcs15-profile — PKCS#15 profile file format

DESCRIPTION

The profile file defines the structure and content of the PKCS#15 filesystem. It is used by pkcs15-init(1) to setup the card.

PIN CONFIGURATION

A PIN object can be defined with the following parameters:

pin label { parameters }

Known parameters are:

attempts = int;

Définit le nombre de tentatives pour le code PIN donné (Défaut : 3).

flags = value...;

Les indicateurs définissent les propriétés du code PIN. Indicateurs possibles :
•case-sensitive
•local
•change-disabled
•unblock-disabled
•initialized
•needs-padding
•unblockingPin
•soPin
•disable-allowed
•integrity-protected
•confidentiality-protected
•exchangeRefData

(Défaut : local,initialized,needs-padding).

auth-id = value;

Valeur utilisée pour l'ID d'authentification (Défaut : 0).

min-length = int;

Longueur minimale du code PIN (Défaut : valeur min-pin-length définie dans le bloc cardinfo).

max-length = int;

Longueur maximale du code PIN (Défaut : valeur max-pin-length définie dans le bloc cardinfo).

reference = int;

Valeur de référence du code PIN (Défaut : défini dans le pilote de carte spécifique).

file = name;

Fichier avec le code PIN, option obsolète (Défaut : Aucun).

offset = int;

Décalage du code PIN dans le fichier PIN, option obsolète (Défaut : 0).

encoding = value;

Type d'encodage du code PIN. Valeurs possibles :
•BCD
•ascii-numeric
•utf8
•half-nibble-bcd
•iso9564-1

(Défaut : valeur pin-encoding définie dans le bloc cardinfo).

stored-length = int;

(Défaut : valeur max-pin-length définie dans le bloc cardinfo).

max-unlocks = int;

(Défaut : 0).

Les valeurs dans ce bloc peuvent être définies par des macros. Cela permet de spécifier les valeurs particulières avec l'utilisation de l'option.

CONFIGURATION OF FILESYSTEM

filesystem { block_contents } .PP Ce bloc contient la spécification du système de fichiers à créer sur la carte. Le système de fichiers se compose de plusieurs blocs imbriqués représentant des fichiers DF et EF. Lorsque les DF ou EF sont spécifiés dans le profil spécifique à la carte, cela est ajouté aux informations du système de fichiers spécifiées dans le profil principal.

EF name { block_contents } .PP Ce bloc définit un fichier élémentaire dans la hiérarchie des fichiers PKCS#15. Le nom peut être l'un des suivants : .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-TokenInfo .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-ODF .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-UnusedSpace .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-PRKDF .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-PUKDF .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-PUKDF-TRUSTED .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-SKDF .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-CDF .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-CDF-TRUSTED .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-CDF-USEFUL .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-DODF .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-AODF .RE .sp .PP Le bloc EF peut contenir :

type = EF;

Le type doit correspondre au type de fichier.

acl = value;

Valeur de l'ACL (Liste de Contrôle d'Accès) (Défaut : AUCUN)

file-id = EF;

ID de fichier, chemin relatif.

structure = value;

La structure du fichier est l'un des suivants :
•TRANSPARENT
•LINEAR-FIXED
•LINEAR-FIXED-TLV
•LINEAR-VARIABLE
•LINEAR-VARIABLE-TLV
•CYCLIC
•CYCLIC-TLV

DF name { block_contents } .PP Ce bloc définit un répertoire dans la hiérarchie des fichiers PKCS#15. Le nom peut être l'un des suivants : .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . MF .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . PKCS15-AppDF .RE .sp .RS 4 .ie n  • . .el  .sp -1 .IP • 2.3 . Cas spéciaux pour ces DF gérés séparément par la logique PKCS15 .RE .sp .PP Le bloc DF peut contenir :

type = DF;

Le type doit correspondre au type de fichier.

path = value;

Spécification du chemin du répertoire.

file-id = value;

ID de fichier, chemin relatif.

aid = value;

Valeur de l'AID, en notation XX:XX:XX:...:XX:XX:XX.

acl = value;

Le type doit correspondre au type de fichier.

size = int;

Taille du fichier en octets.

EF name { block_contents }

Bloc spécifiant un fichier élémentaire imbriqué.

Typiquement, le DF racine est MF.

Il est obligatoire que le fichier de profil contienne une entrée DF pour MF (Master File). Sinon, le fichier de profil est incomplet et ne peut pas être utilisé.

Le DF peut contenir d'autres blocs DF ou MF. Pour des exemples de la structure du système de fichiers, veuillez vous référer à pkcs15.profile ou à tout autre fichier de profil existant.
