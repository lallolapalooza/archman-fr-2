PKI --ESTCA(1) strongSwan PKI --ESTCA(1)

NOM

pki --estca - Récupérer le(s) certificat(s) de l'AC à partir d'un serveur EST

SYNTAXE

pki --estca --url url [--label étiquette] --cacert fichier [--caout fichier] [--outform encodage] [--force] [--debug niveau]
pki --estca --options fichier
pki --estca -h | --help

DESCRIPTION

Cette sous-commande de pki(1) récupère les certificats d'AC via https à partir d'un serveur EST en utilisant l'opération /cacerts du protocole Enrollment over Secure Transport (RFC 7030).

OPTIONS

-h, --help
Affiche les informations d'utilisation avec un résumé des options disponibles.
-v, --debug niveau
Définit le niveau de débogage, par défaut : 1.
-+, --options fichier
Lit les options de la ligne de commande à partir du fichier.
-u, --url url
URL du serveur SCEP.
-l, --label étiquette
Étiquette dans le chemin du serveur EST.
-C, --cacert fichier
Certificat d'AC dans la chaîne de confiance utilisée pour la vérification de la signature du serveur TLS EST. Peut être utilisé plusieurs fois.
-c, --caout fichier
Si présent, chemin où le fichier de certificat d'AC racine récupéré est stocké. Si plusieurs certificats d'AC sont téléchargés, alors la valeur de --caout est utilisée comme modèle pour dériver des noms de fichiers uniques (*-1, *-2, etc.) pour les certificats d'AC intermédiaires ou subordonnés. Si un suffixe de fichier est manquant, alors en fonction de la valeur de --outform, soit .der (par défaut) soit .pem est automatiquement ajouté. Si l'option --caout est manquante et --outform est défini sur pem alors un paquet de certificats d'AC encodé en PEM est écrit sur stdout.
-f, --outform encodage
Encodage du fichier certificat créé. Soit der (ASN.1 DER) ou pem (Base64 PEM), par défaut der.
-F, --force
Force l'écrasement des fichiers existants.

EXEMPLES

Pour économiser du travail de frappe, les options de ligne de commande suivantes sont stockées dans un fichier est.opt :

--url https://pki.strongswan.org:8443
--cacert tlsca.crt
--cacert tlsca-1.crt

NOTE : Pour une connexion HTTPS réussie, la confiance doit être établie dans le certificat du serveur EST. La chaîne de confiance TLS, y compris le certificat de l'AC racine et éventuellement les certificats des AC intermédiaires, doit être fournie en utilisant plusieurs options --cacert.

NOTE : La fiabilité du certificat de l'AC racine est soit vérifiée automatiquement si le certificat de l'AC racine de la chaîne de confiance TLS est le même que celui de l'AC émettrice. Sinon, la confiance doit être établie manuellement en vérifiant l'empreinte SHA256 ou SHA1 du certificat encodé DER qui est, par exemple, listé sur le site web officiel de la PKI ou par un autre moyen.

Les fichiers certificats stockés au format DER peuvent être écrasés par des versions encodées PEM avec :

pki --estca --options est.opt --caout myca.crt --outform pem --force

Un paquet de certificats d'AC au format PEM est écrit sur stdout :

pki --estca --options est.opt --outform pem > cacerts.pem
