NOM

pki --scep - Enregistrer un certificat X.509 auprès d'un serveur SCEP

SYNOPIS

pki --scep --url url [--in fichier] [--dn  nom-distinctif] [--san nomAlternatifSujet] [--profile profil] [--password motdepasse] --ca-cert-enc fichier --ca-cert-sig fichier [--cacert fichier] [--cert fichier --key fichier] [--cipher chiffrement] [--digest hachage] [--rsa-padding rembourrage] [--interval temps] [--maxpolltime temps] [--outform encodage] [--debug niveau]
pki --scep --options fichier
pki --scep -h | --help

DESCRIPTION

Cette sous-commande de pki(1) envoie une requête de certificat PKCS#10 dans un conteneur PKCS#7 chiffré et signé via HTTP à un serveur SCEP en utilisant le protocole SCEP (RFC 8894). Après une autorisation réussie qui, avec une authentification manuelle, nécessite un interogation périodique par le client d'enregistrement, le serveur SCEP renvoie un certificat X.509 signé par l'AC.

Avant l'expiration du certificat actuel, un nouveau certificat client basé sur une nouvelle clé privée RSA peut être demandé, en utilisant l'ancien certificat et l'ancienne clé pour une authentification automatique auprès du serveur SCEP.

OPTIONS

-h, --help
Affiche les informations d'utilisation avec un résumé des options disponibles.
-v, --debug niveau
Définit le niveau de débogage, par défaut : 1.
-+, --options fichier
Lit les options de la ligne de commande depuis le fichier.
-u, --url url
URL du serveur SCEP.
-i, --in fichier
Clé privée RSA. Si elle n'est pas fournie, la clé est lue depuis STDIN.
-d, --dn nom-distinctif
Nom distinctif du sujet (DN). Requis sauf si --cert est fourni.
-a, --san nomAlternatifSujet
Extension subjectAltName à inclure dans la requête. Peut être utilisée plusieurs fois.
-P, --profile profil
Nom du profil de certificat à inclure dans la requête de certificat. Peut être n'importe quelle chaîne UTF8. Supporté par exemple par le serveur SCEP openxpki avec des profils (pc-client, tls-server, etc.) qui sont traduits en drapeaux EKU (Extended Key Usage) correspondants dans le certificat X.509 généré.
-p, --password motdepasse
Le challengePassword à inclure dans la requête de certificat.
-e, --cacert-enc fichier
Certificat d'AC ou d'AR pour le chiffrement.
-s, --cacert-sig fichier
Certificat d'AC pour la vérification de signature.
-C, --cacert fichier
Certificat d'AC supplémentaire dans la chaîne de confiance utilisé pour la vérification de signature. Peut être utilisé plusieurs fois.
-c, --cert fichier
Certificat client à renouveler.
-k, --key fichier
Clé privée RSA du client à remplacer.
-E, --cipher chiffrement
Chiffrement utilisé pour le chiffrement symétrique. Soit aes (par défaut) soit des3.
-g, --digest hachage
Hachage à utiliser pour la création de signature. Un parmi sha256 (par défaut), sha384, sha512, ou sha1.
-R, --rsa-padding rembourrage
Rembourrage à utiliser pour les signatures RSA. Soit pkcs1 (par défaut) soit pss.
-t, --interval temps
Intervalle d'interrogation en secondes, par défaut 60s.
-m, --maxpolltime temps
Temps d'interrogation maximum en secondes, par défaut 0 ce qui signifie une interogation illimitée.
-f, --outform encodage
Encodage du fichier certificat créé. Soit der (ASN.1 DER) soit pem (PEM Base64), par défaut der.

EXEMPLES

Pour économiser du travail de frappe, les options de ligne de commande suivantes sont enregistrées dans un fichier scep.opt :

--url http://pki.strongswan.org:8080/scep
--cacert-enc myra.crt
--cacert-sig myca-1.crt
--cacert myca.crt

Avec la commande suivante, un certificat X.509 signé par l'AC intermédiaire est demandé à un serveur SCEP :
