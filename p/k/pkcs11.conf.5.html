NOM

pkcs11.conf - Fichiers de configuration pour les modules PKCS#11

DESCRIPTION

Les fichiers de configuration pkcs11.conf sont un moyen standard de configurer les modules PKCS#11.

FORMAT DES FICHIERS

Une configuration complète se compose de plusieurs fichiers. Ces fichiers sont des fichiers texte. Comme p11-kit est conçu pour être utilisé dans toutes sortes d'environnements et à des niveaux très bas de la pile logicielle, nous ne pouvons pas utiliser d'API de configuration de haut niveau que vous pourriez trouver sur un bureau moderne.

Chaque réglage dans le fichier de configuration est spécifié par un nom et une valeur. Le nom est une chaîne de caractères simple composée de caractères et de tirets. Le nom se compose de caractères alphanumériques, de points, de tirets et de soulignements.

La valeur est spécifiée après le nom sur la même ligne, séparée de celui-ci par un deux-points (:). Les espaces blancs entre le nom et la valeur sont ignorés.

Les lignes vides sont ignorées. Les espaces blancs au début ou à la fin des lignes sont supprimés. Les lignes commençant par un caractère # sont ignorées en tant que commentaires. Les commentaires ne sont pas reconnus lorsqu'ils apparaissent après une valeur sur une ligne.

Un fichier de configuration de module fictif pourrait ressembler à ceci :

module: module.so
# Ceci est un commentaire
managed: true
setting.2: Une longue valeur avec du texte.
x-custom : texte

CONFIGURATION DU MODULE

Chaque module PKCS#11 configuré a son propre fichier de configuration. Ces fichiers peuvent être placés dans divers emplacements.

Le nom de fichier du fichier de configuration peut être composé de lettres majuscules et minuscules, de soulignements, de virgules, de tirets et de points. Les premiers caractères doivent être alphanumériques, le nom de fichier doit se terminer par une extension .module.

Plus important encore, chaque fichier de configuration spécifie le chemin d'accès du module PKCS#11 à charger. Un fichier de configuration de module a les champs suivants :

module:

Le nom de fichier du module PKCS#11 à charger. Il doit inclure une extension comme .so

Si cette valeur est vide, le module sera ignoré. Ceci peut être utilisé dans les configurations utilisateur pour remplacer le chargement d'un module spécifié dans la configuration système.

Si il s'agit d'un chemin relatif, le module sera chargé à partir du répertoire de modules par défaut.

critical:

Défini sur yes si le module est critique et requis pour le chargement. Si un module critique échoue à charger ou à s'initialiser, le processus de chargement de tous les modules enregistrés s'arrêtera et retournera un code d'erreur.

Cet argument est facultatif et par défaut à no.

enable-in:

Une liste de noms de programmes, séparés par des virgules et/ou des espaces, pour lesquels ce module ne doit être chargé. Le module ne sera pas chargé pour d'autres programmes utilisant p11-kit. Le nom de base de l'exécutable du processus doit être utilisé ici, par exemple seahorse, ssh.

Cette option peut également être utilisée pour contrôler si le module sera chargé par le module proxy. Pour activer le chargement uniquement depuis le module proxy, spécifiez p11-kit-proxy comme valeur.

Ce n'est pas une fonctionnalité de sécurité. L'argument est facultatif. S'il n'est pas présent, n'importe quel processus chargera le module.

disable-in:

Une liste de noms de programmes, séparés par des virgules et/ou des espaces, pour lesquels ce module ne doit pas être chargé. Le module sera chargé pour tous les autres programmes utilisant p11-kit. Le nom de base de l'exécutable du processus doit être utilisé ici, par exemple firefox, thunderbird-bin.

Cette option peut également être utilisée pour contrôler si le module sera chargé par le module proxy. Pour désactiver le chargement depuis le module proxy, spécifiez p11-kit-proxy comme valeur.

Ce n'est pas une fonctionnalité de sécurité. L'argument est facultatif. S'il n'est pas présent, n'importe quel processus chargera le module.

managed:

Défini sur no si le module ne doit pas être géré par p11-kit. La gestion non supervisée d'un module n'est pas recommandée et causera des problèmes si plusieurs appelants dans un seul processus partagent un module PKCS#11.

Cet argument est facultatif et par défaut à yes.

priority:

La valeur doit être un entier. Lorsque des listes de modules sont renvoyées à un appelant de p11-kit, les modules ayant un nombre plus élevé sont triés en premier. Lorsque les applications recherchent des modules pour des certificats, des clés et des informations de politique de confiance, ce réglage affectera ce qui est trouvé en premier.

Cet argument est facultatif et par défaut à zéro. Les modules ayant la même option priority seront triés par ordre alphabétique.

remote:

Au lieu de charger le module PKCS#11 localement, exécutez le module à distance.

Spécifiez une commande à exécuter, préfixée par | un pipe. La commande doit parler le protocole de remotage p11-kit sur son entrée standard et sa sortie standard. Par exemple :

remote: |ssh user@remote p11-kit remote /path/to/module.so

D'autres formes de remotage apparaîtront dans les futures versions de p11-kit.

trust-policy:

Défini sur yes pour utiliser ce module comme source d'informations sur la politique de confiance, telles que les ancres de certificats et les listes de blocage.

log-calls:

Défini sur yes pour écrire un journal sur stderr de tous les appels vers le module. Ceci n'est pris en charge que pour les modules gérés.

Cet argument est facultatif et par défaut à no.

server-address:

Une adresse de socket sur laquelle le serveur p11-kit écoute. Applicable uniquement au module p11-kit-client.

Cette option peut être remplacée par la variable d'environnement P11_KIT_SERVER_ADDRESS.

Ne spécifiez pas à la fois enable-in et disable-in pour le même module.

D'autres champs peuvent être présents, mais il est recommandé que les noms de champs qui ne sont pas spécifiés dans ce document commencent par un préfixe x-.

CONFIGURATION GLOBALE

Une configuration globale peut également être présente. Ce fichier contient des paramètres qui ne sont pas liés à un seul module PKCS#11. L'emplacement des configurations globales est décrit ci-dessous. Le fichier de configuration globale peut contenir les champs suivants :

user-config:

Cette valeur sera l'une des suivantes : none, merge, only.

managed:

Défini sur yes ou no pour forcer tous les modules à être gérés ou non gérés par p11-kit. La définition de ce paramètre dans un fichier de configuration globale remplacera le paramètre managed dans les fichiers de configuration des modules individuels. La gestion non supervisée des modules n'est pas recommandée et causera des problèmes si plusieurs appelants dans un seul processus partagent un module PKCS#11.

Cet argument est facultatif.

log-calls:

Défini sur yes pour écrire un journal sur stderr de tous les appels vers tous les modules configurés. Ceci n'est pris en charge que pour les modules gérés.

Cet argument est facultatif.

D'autres champs peuvent être présents, mais il est recommandé que les noms de champs qui ne sont pas spécifiés dans ce document commencent par un préfixe x-.

FICHIERS DE CONFIGURATION

Chaque module PKCS#11 configuré a son propre fichier de configuration. Ces fichiers sont placés dans un répertoire. De plus, un fichier de configuration globale existe. Il y a une configuration système composée des différents fichiers de configuration de modules et d'un fichier pour la configuration globale. Facultativement, chaque utilisateur peut fournir une configuration supplémentaire ou remplacer la configuration système.

Le fichier de configuration globale système se trouve généralement dans /etc/pkcs11/pkcs11.conf et le fichier de configuration globale utilisateur dans ~/.config/pkcs11/pkcs11.conf dans le répertoire personnel de l'utilisateur.

Les fichiers de configuration des modules se trouvent généralement dans le répertoire /etc/pkcs11/modules, avec un fichier de configuration par module. De plus, le répertoire ~/.config/pkcs11/modules peut être utilisé pour les modules installés par l'utilisateur.

Notez que les fichiers de configuration utilisateur ne sont pas chargés depuis le répertoire personnel si le programme s'exécute dans un programme setuid ou setgid.

Le fichier de configuration système par défaut et le répertoire des modules peuvent être modifiés lors de la compilation de p11-kit. Recherchez toujours ces chemins en utilisant pkg-config.
