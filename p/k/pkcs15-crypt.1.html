NOM

pkcs15-crypt - effectuer des opérations cryptographiques à l'aide de cartes à puce PKCS#15

SYNTAXE

pkcs15-crypt [OPTIONS]

DESCRIPTION

L'utilitaire pkcs15-crypt peut être utilisé depuis la ligne de commande pour effectuer des opérations cryptographiques telles que le calcul de signatures numériques ou le déchiffrement de données, en utilisant des clés stockées sur une carte à puce conforme à PKCS#15.

OPTIONS

--version,

Affiche la version de la distribution du paquet OpenSC.

--aid aid

Spécifie l'AID de l'application PKCS#15 sur carte à laquelle se connecter. L'aid doit être en format hexadécimal.

--decipher, -c

Déchiffre le contenu du fichier spécifié par l'option --input. Le résultat de l'opération de déchiffrement est écrit dans le fichier spécifié par l'option --output. Si cette option n'est pas donnée, les données déchiffrées sont imprimées sur la sortie standard, affichant les caractères non imprimables à l'aide de leur notation hexadécimale xNN (voir aussi --raw).

--input fichier, -i fichier

Spécifie le fichier d'entrée à utiliser. Par défaut, utilise stdin si non spécifié.

--key id, -k id

Sélectionne l'ID de la clé à utiliser.

--output fichier, -o fichier

Toute sortie sera envoyée au fichier spécifié. Par défaut, utilise stdout si non spécifié.

--pin pin, -p pin

Lorsque l'opération cryptographique nécessite un PIN pour accéder à la clé, pkcs15-crypt demandera le PIN à l'utilisateur sur le terminal. Utiliser cette option permet de spécifier le PIN sur la ligne de commande.

Notez que sur la plupart des systèmes d'exploitation, la ligne de commande d'un processus peut être affichée par n'importe quel utilisateur à l'aide de la commande ps(1). Il s'agit donc d'un risque de sécurité de spécifier des informations secrètes telles que les PIN sur la ligne de commande. Si vous spécifiez '-' comme PIN, il sera lu depuis STDIN.

--pkcs1

Par défaut, pkcs15-crypt suppose que les données d'entrée ont été complétées à la bonne longueur (c'est-à-dire lors du calcul d'une signature RSA avec une clé de 1024 bits, l'entrée doit être complétée à 128 octets pour correspondre à la longueur du module). Cependant, en donnant l'option --pkcs1, pkcs15-crypt effectuera le remplissage requis en utilisant l'algorithme décrit dans la norme PKCS #1 version 1.5.

--raw, -R

Sortie de données brutes sur 8 bits.

--reader arg, -r arg

Numéro du lecteur à utiliser. Par défaut, le premier lecteur avec une carte présente est utilisé. Si arg est une ATR, le lecteur avec une carte correspondante sera choisi.

--md5 --sha-1 --sha-224 --sha-256 --sha-384 --sha-512

Ces options indiquent à pkcs15-crypt que le fichier d'entrée est le résultat de l'opération de hachage spécifiée. Par défaut, un hachage MD5 est attendu. Encore une fois, les données doivent être en représentation binaire.

--sign, -s

Effectue une opération de signature numérique sur les données lues à partir d'un fichier spécifié à l'aide de l'option --input. Par défaut, le contenu du fichier est supposé être le résultat d'une opération de hachage MD5. Notez que pkcs15-crypt attend les données en représentation binaire, et non ASCII.

La signature numérique est stockée, en représentation binaire, dans le fichier spécifié par l'option --output. Si cette option n'est pas donnée, la signature est imprimée sur la sortie standard, affichant les caractères non imprimables à l'aide de leur notation hexadécimale xNN (voir aussi --raw).

--signature-format, --f

Lors de la signature avec une clé ECDSA, cette option indique à pkcs15-crypt le format de sortie de la signature. Les valeurs possibles sont 'rs' (par défaut) -- deux entiers concaténés (PKCS#11), 'sequence' ou 'openssl' -- séquence d'entiers encodée en DER (OpenSSL).

--wait, -w

Force pkcs15-crypt à attendre l'insertion d'une carte.

--verbose, -v

Rend pkcs15-crypt plus verbeux. Spécifiez ce drapeau plusieurs fois pour activer la sortie de débogage dans la bibliothèque OpenSC.
