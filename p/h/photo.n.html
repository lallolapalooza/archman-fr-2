photo(n) Commandes intégrées Tk photo(n)

NOM

photo - Images en couleur réelle

SYNOPIS

image create photo ?nom? ?options?
nomImage blank
nomImage cget option
nomImage configure ?option? ?valeur option valeur ...?
nomImage copy imageSource ?option valeur(s) ...?
nomImage data ?option valeur(s) ...?
nomImage get x y
nomImage put données ?option valeur(s) ...?
nomImage read nomFichier ?option valeur(s) ...?
nomImage redither
nomImage transparency sous-commande ?arg arg ...?
nomImage write nomFichier ?option valeur(s) ...?

DESCRIPTION

Une photo est une image dont les pixels peuvent afficher n'importe quelle couleur ou être transparents. Une image photo est stockée en interne en couleur réelle (32 bits par pixel), et est affichée en utilisant le tramage si nécessaire. Les données de l'image pour une image photo peuvent être obtenues à partir d'un fichier ou d'une chaîne de caractères, ou peuvent être fournies par du code C via une interface procédurale. Actuellement, seuls les formats PNG, GIF et PPM/PGM sont pris en charge, mais une interface existe pour permettre l'ajout facile de formats de fichiers d'images supplémentaires. Une image photo est transparente dans les régions où aucune donnée d'image n'a été fournie ou où elle a été définie comme transparente par la sous-commande transparency set.

CRÉATION DES PHOTOS

Comme toutes les images, les photos sont créées à l'aide de la commande image create. Les photos prennent en charge les options suivantes :

-data chaîne
Spécifie le contenu de l'image sous forme de chaîne. La chaîne doit contenir des données binaires ou, pour certains formats, des données encodées en base64 (ceci est actuellement garanti d'être pris en charge pour les images PNG et GIF). Le format de la chaîne doit être l'un de ceux pour lesquels il existe un gestionnaire de format de fichier image qui accepte des données sous forme de chaîne. Si les options -data et -file sont toutes deux spécifiées, l'option -file a la priorité.
-format nom-format
Spécifie le nom du format de fichier pour les données spécifiées avec l'option -data ou -file.
-file nom
nom donne le nom d'un fichier qui doit être lu pour fournir des données pour l'image photo. Le format du fichier doit être l'un de ceux pour lesquels il existe un gestionnaire de format de fichier image capable de lire des données.
-gamma valeur
Spécifie que les couleurs allouées pour afficher cette image dans une fenêtre doivent être corrigées pour un affichage non linéaire avec la valeur d'exposant gamma spécifiée. (L'intensité produite par la plupart des écrans CRT est une fonction puissance de la valeur d'entrée, à une bonne approximation ; gamma est l'exposant et est généralement d'environ 2). La valeur spécifiée doit être supérieure à zéro. La valeur par défaut est un (aucune correction). En général, les valeurs supérieures à un rendront l'image plus claire, et les valeurs inférieures à un la rendront plus sombre.
-height nombre
Spécifie la hauteur de l'image, en pixels. Cette option est principalement utile dans les situations où l'utilisateur souhaite construire le contenu de l'image pièce par pièce. Une valeur de zéro (par défaut) permet à l'image de s'agrandir ou de rétrécir verticalement pour s'adapter aux données qu'elle contient.
-palette spéc-palette
Spécifie la résolution du cube de couleurs à allouer pour afficher cette image, et donc le nombre de couleurs utilisées à partir des palettes de couleurs des fenêtres où elle est affichée. La chaîne spéc-palette peut être soit un seul nombre décimal, spécifiant le nombre de nuances de gris à utiliser, soit trois nombres décimaux séparés par des barres obliques (/), spécifiant le nombre de nuances de rouge, vert et bleu à utiliser, respectivement. Si la première forme (un seul nombre) est utilisée, l'image sera affichée en monochrome (c'est-à-dire en niveaux de gris).
-width nombre
Spécifie la largeur de l'image, en pixels. Cette option est principalement utile dans les situations où l'utilisateur souhaite construire le contenu de l'image pièce par pièce. Une valeur de zéro (par défaut) permet à l'image de s'agrandir ou de rétrécir horizontalement pour s'adapter aux données qu'elle contient.

COMMANDE IMAGE

Lorsqu'une image photo est créée, Tk crée également une nouvelle commande dont le nom est le même que celui de l'image. Cette commande peut être utilisée pour invoquer diverses opérations sur l'image. Elle a la forme générale suivante :

nomImage option ?arg arg ...?
Option et les args déterminent le comportement exact de la commande.

Les options qui écrivent des données dans l'image étendent généralement la taille de l'image, si nécessaire, pour accueillir les données écrites dans l'image, à moins que l'utilisateur n'ait spécifié des valeurs non nulles pour les options de configuration -width et/ou -height, auquel cas la largeur et/ou la hauteur de l'image ne seront pas modifiées.

Les commandes suivantes sont possibles pour les images photo :

nomImage blank
Efface l'image ; c'est-à-dire, définit l'ensemble de l'image pour qu'elle n'ait pas de données, de sorte qu'elle sera affichée comme transparente, et que l'arrière-plan de la fenêtre dans laquelle elle est affichée apparaîtra.
nomImage cget option
Retourne la valeur actuelle de l'option de configuration donnée par option. Option peut avoir n'importe laquelle des valeurs acceptées par la commande image create photo.
nomImage configure ?option? ?valeur option valeur ...?
Interroge ou modifie les options de configuration de l'image. Si aucune option n'est spécifiée, retourne une liste décrivant toutes les options disponibles pour nomImage (voir Tk_ConfigureInfo pour des informations sur le format de cette liste). Si option est spécifiée sans valeur, alors la commande retourne une liste décrivant l'option nommée (cette liste sera identique à la sous-liste correspondante de la valeur retournée si aucune option n'est spécifiée). Si une ou plusieurs paires option-valeur sont spécifiées, alors la commande modifie l'option (les options) donnée(s) pour avoir la ou les valeur(s) donnée(s) ; dans ce cas, la commande retourne une chaîne vide. Option peut avoir n'importe laquelle des valeurs acceptées par la commande image create photo.
nomImage copy imageSource ?option valeur(s) ...?
Copie une région de l'image appelée imageSource (qui doit être une image photo) vers l'image appelée nomImage, potentiellement avec zoom et/ou sous-échantillonnage. Si aucune option n'est spécifiée, cette commande copie l'intégralité de imageSource dans nomImage, en commençant aux coordonnées (0,0) dans nomImage. Les options suivantes peuvent être spécifiées :
-from x1 y1 x2 y2
Spécifie une sous-région rectangulaire de l'image source à copier. (x1,y1) et (x2,y2) spécifient des coins diagonalement opposés du rectangle. Si x2 et y2 ne sont pas spécifiés, la valeur par défaut est le coin inférieur droit de l'image source. Les pixels copiés incluront les bords gauche et supérieur du rectangle spécifié, mais pas les bords inférieur ou droit. Si l'option -from n'est pas donnée, la valeur par défaut est l'image source entière.
-to x1 y1 x2 y2
Spécifie une sous-région rectangulaire de l'image de destination à affecter. (x1,y1) et (x2,y2) spécifient des coins diagonalement opposés du rectangle. Si x2 et y2 ne sont pas spécifiés, la valeur par défaut est (x1,y1) plus la taille de la région source (après sous-échantillonnage et zoom, si spécifié). Si x2 et y2 sont spécifiés, la région source sera répliquée si nécessaire pour remplir la région de destination de manière pavée.
-shrink
Spécifie que la taille de l'image de destination

doit être réduit, si nécessaire, de sorte que la région copiée se trouve dans le coin inférieur droit de l'image. Cette option n'affectera pas la largeur ou la hauteur de l'image si l'utilisateur a spécifié une valeur non nulle pour l'option de configuration -width ou -height, respectivement.
-zoom x y
Spécifie que la région source doit être agrandie d'un facteur de x dans la direction X et de y dans la direction Y. Si y n'est pas donné, la valeur par défaut est la même que x. Avec cette option, chaque pixel de l'image source sera étendu en un bloc de x x y pixels dans l'image de destination, tous de la même couleur. x et y doivent être supérieurs à 0.
-subsample x y
Spécifie que l'image source doit être réduite en taille en utilisant uniquement chaque x-ième pixel dans la direction X et chaque y-ième pixel dans la direction Y. Les valeurs négatives provoqueront un retournement de l'image par rapport aux axes Y ou X, respectivement. Si y n'est pas donné, la valeur par défaut est la même que x.
-compositingrule rule
Spécifie comment les pixels transparents de l'image source sont combinés avec l'image de destination. Lorsqu'une règle de composition overlay est définie, le contenu précédent de l'image de destination est visible, comme si l'image source était imprimée sur un morceau de film transparent et placé par-dessus la destination. Lorsqu'une règle de composition set est définie, le contenu précédent de l'image de destination est ignoré et l'image source est utilisée telle quelle. La règle de composition par défaut est overlay.
imageName data ?option valeur(s) ...?
Retourne les données de l'image sous forme de chaîne de caractères. Les options suivantes peuvent être spécifiées :
-background couleur
Si la couleur est spécifiée, les données ne contiendront aucune information de transparence. Tous les pixels transparents seront remplacés par la couleur spécifiée.
-format nom-format
Spécifie le nom du gestionnaire de format de fichier image à utiliser. Spécifiquement, cette sous-commande recherche le premier gestionnaire dont le nom correspond à une sous-chaîne initiale de nom-format et qui a la capacité d'écrire une chaîne contenant ces données d'image. Si cette option n'est pas donnée, cette sous-commande utilise un format qui consiste en une liste (un élément par ligne) de listes (un élément par pixel/colonne) de couleurs au format «#rrggbb» (où rr est une paire de chiffres hexadécimaux pour le canal rouge, gg pour le vert et bb pour le bleu).
-from x1 y1 x2 y2
Spécifie une région rectangulaire de imageName à retourner. Si seulement x1 et y1 sont spécifiés, la région s'étend de (x1,y1) au coin inférieur droit de imageName. Si les quatre coordonnées sont données, elles spécifient des coins opposés diagonalement de la région rectangulaire, incluant x1,y1 et excluant x2,y2. La valeur par défaut, si cette option n'est pas donnée, est l'image entière.
-grayscale
Si cette option est spécifiée, les données ne contiendront pas d'informations de couleur. Toutes les données de pixels seront transformées en niveaux de gris.
imageName get x y
Retourne la couleur du pixel aux coordonnées (x,y) dans l'image sous forme d'une liste de trois entiers compris entre 0 et 255, représentant respectivement les composantes rouge, verte et bleue.
imageName put data ?option valeur(s) ...?
Définit les pixels de imageName avec les données spécifiées dans data. Cette commande recherche d'abord dans la liste des gestionnaires de formats de fichiers image un gestionnaire capable d'interpréter les données de data, puis lit l'image encodée dans imageName (l'image de destination). Si data ne correspond à aucun format connu, une tentative est faite pour l'interpréter comme une liste de lignes de balayage (de haut en bas), chaque ligne de balayage étant une liste de couleurs de pixels (de gauche à droite) (voir Tk_GetColor pour une description des couleurs valides.) Chaque ligne de balayage doit avoir la même longueur. Notez que lorsque data est un nom de couleur unique, vous demandez à Tk de remplir une région rectangulaire avec cette couleur. Les options suivantes peuvent être spécifiées :
-format nom-format
Spécifie le format des données d'image dans data. Spécifiquement, seuls les gestionnaires de formats de fichiers image dont les noms commencent par nom-format seront utilisés lors de la recherche d'un gestionnaire de formats de données d'image pour lire les données.
-to x1 y1 ?x2 y2?
Spécifie les coordonnées du coin supérieur gauche (x1,y1) de la région de imageName dans laquelle les données de l'image seront copiées. La position par défaut est (0,0). Si x2,y2 est donné et data n'est pas assez grand pour couvrir le rectangle spécifié par cette option, les données d'image extraites seront carrelées pour couvrir tout le rectangle de destination. Notez que si data spécifie une seule valeur de couleur, une région s'étendant jusqu'au coin inférieur droit représenté par (x2,y2) sera remplie avec cette couleur.
imageName read nom-fichier ?option valeur(s) ...?
Lit les données d'image du fichier nommé nom-fichier dans l'image. Cette commande recherche d'abord dans la liste des gestionnaires de formats de fichiers image un gestionnaire capable d'interpréter les données de nom-fichier, puis lit l'image dans nom-fichier dans imageName (l'image de destination). Les options suivantes peuvent être spécifiées :
-format nom-format
Spécifie le format des données d'image dans nom-fichier. Spécifiquement, seuls les gestionnaires de formats de fichiers image dont les noms commencent par nom-format seront utilisés lors de la recherche d'un gestionnaire de formats de données d'image pour lire les données.
-from x1 y1 x2 y2
Spécifie une région rectangulaire de sous-données de l'image à copier dans l'image de destination. Si seulement x1 et y1 sont spécifiés, la région s'étend de (x1,y1) au coin inférieur droit de l'image dans le fichier image. Si les quatre coordonnées sont spécifiées, elles définissent des coins opposés diagonalement de la région. La valeur par défaut, si cette option n'est pas spécifiée, est l'intégralité de l'image dans le fichier image.
-shrink
Si cette option est spécifiée, la taille de imageName sera réduite, si nécessaire, de sorte que la région dans laquelle les données du fichier image sont lues se trouve dans le coin inférieur droit de imageName. Cette option n'affectera pas la largeur ou la hauteur de l'image si l'utilisateur a spécifié une valeur non nulle pour les options de configuration -width ou -height, respectivement.
-to x y
Spécifie les coordonnées du coin supérieur gauche de la région de imageName dans laquelle les données de nom-fichier doivent être lues. La valeur par défaut est (0,0).
imageName redither
L'algorithme de tramage utilisé pour afficher les images photo propage les erreurs de quantification d'un pixel à ses voisins. Si les données de l'image pour imageName sont fournies par morceaux, l'image tramée peut ne pas être tout à fait correcte. Normalement, la différence n'est pas perceptible, mais si elle pose problème, cette commande peut être utilisée pour recalculer l'image tramée dans chaque fenêtre où l'image est affichée.
imageName transparency subcommande ?arg arg ...?
Permet d'examiner et de manipuler les informations de transparence dans l'image photo. Plusieurs sous-commandes sont disponibles :
imageName transparency get x y
Retourne un booléen indiquant si le pixel aux coordonnées (x,y) est transparent.
imageName transparency set x y booléen
Rend le pixel aux coordonnées (x,y) transparent si booléen est vrai, et rend ce pixel opaque sinon.
imageName write nom-fichier ?option valeur(s) ...?
Écrit les données d'image de imageName dans un fichier nommé nom-fichier. Les options suivantes peuvent être spécifiées :
-background couleur
Si la couleur est spécifiée, les données ne contiendront aucune information de transparence. Tous les pixels transparents seront remplacés par la couleur spécifiée.
-format nom-format
Spécifie le nom du gestionnaire de format de fichier image à utiliser pour écrire les données dans le fichier. Spécifiquement, cette sous-commande recherche le premier gestionnaire dont le nom correspond à une sous-chaîne initiale de nom-format et qui a la capacité d'écrire un fichier image. Si cette option n'est pas donnée, le format est deviné à partir de l'extension du fichier. Si cela ne peut pas être déterminé, cette sous-commande utilise le premier gestionnaire qui a la capacité d'écrire un fichier image.
-from x1 y1 x2 y2
Spécifie une région rectangulaire de imageName à écrire dans le fichier image. Si seulement x1 et y1 sont spécifiés, la région s'étend de (x1,y1) au coin inférieur droit de imageName. Si les quatre coordonnées sont données, elles spécifient des coins opposés diagonalement de la région rectangulaire. La valeur par défaut, si cette option n'est pas donnée, est l'image entière.

NAME

photo - image type for storing and displaying photographs

SYNOPSIS

image create photo ?name?
imageName copy sourceImage ?options?
imageName delete
imageName height ?window?
imageName put data ?-channel channel?
imageName show
imageName type
imageName width ?window?
imageName configure ?options?
imageName blank
imageName redimensionner largeur hauteur ?fenetre?
imageName copie imageSource ?-a_la_destination_X ?-a_la_destination_Y ?-a_la_destination_largeur* ?-a_la_destination_hauteur* ?options?
imageName pixel x y ?valeur?
imageName data ?-channel channel?

DESCRIPTION

The photo image type is used to store and display images that have a relatively large number of colors, such as photographs. It supports several standard image file formats, including GIF, PPM/PGM, and PNG.

CREATING PHOTOS

A photo image is created using the image create photo command. A name can be given for the new image, otherwise one is generated automatically. The photo image is initially empty.

The contents of the photo image can be loaded from a file using the -file option to the image create command, or from a memory buffer using the -data option. If the image is loaded from a file or memory buffer, the format of the image data must be specified using the -format option, or it will be determined automatically. The supported formats are GIF, PPM/PGM, and PNG. If the format cannot be determined automatically, an error will occur.

Once created, a photo image can be displayed in a Tk widget, such as a label(n) or canvas(n), using the -image option.

The copy operation can be used to copy pixels from one photo image to another. This can be used to scale, resize, or tile images. The redimensionner operation can be used to copy an image to another image, resizing it to the specified width and height. The copie operation is similar to redimensionner but allows for more control over the destination coordinates and dimensions.

The pixel operation can be used to get or set the color of a single pixel in the image.

The data operation can be used to retrieve the image data in a raw format. This can be useful for passing image data to external libraries or for custom processing.

IMAGE COMMAND

The following operations are supported for photo images:

imageName copy sourceImage ?-to x y? ?-shrink? ?-increase?
Copies the contents of sourceImage to imageName. The -to option specifies the top-left corner in imageName where the copy should begin. If -shrink is specified, the image will be shrunk to fit within the destination area if it is larger. If -increase is specified, the image will be scaled up to fill the destination area if it is smaller. The destination area is defined by the width and height of imageName unless overridden by explicit destination width and height options.
imageName blank
Clears the image, making it empty.
imageName delete
Deletes the image, freeing associated memory.
imageName height ?window?
Returns the height of the image in pixels. If window is specified, the height is adjusted to the screen's resolution.
imageName width ?window?
Returns the width of the image in pixels. If window is specified, the width is adjusted to the screen's resolution.
imageName redimensionner largeur hauteur ?fenetre?
Resizes the image to the specified largeur and hauteur. If fenetre is specified, the dimensions are interpreted in screen units relative to that window.
imageName copie imageSource ?-a_la_destination_X ?-a_la_destination_Y ?-a_la_destination_largeur* ?-a_la_destination_hauteur* ?options?
Copies pixels from imageSource to imageName. The destination area can be specified by -a_la_destination_X, -a_la_destination_Y, -a_la_destination_largeur, and -a_la_destination_hauteur. This allows for more precise control over the copying process, including scaling and cropping.
imageName pixel x y ?valeur?
Gets or sets the color of the pixel at coordinates (x, y). If valeur is specified, it sets the pixel to that color. If not, it returns the current color of the pixel.
imageName data ?-channel channel?
Returns the raw pixel data of the image. The -channel option can be used to specify the channel to retrieve (e.g., RGB, RGBA). If not specified, all channels are returned.
-grayscale
If this option is specified, the data will not contain color information. All pixel data will be transformed into grayscale.

IMAGE FORMATS

The photo image code is structured to allow handlers for additional image file formats to be added easily. The photo image code maintains a list of these handlers. Handlers are added to the list by registering them with a call to Tk_CreatePhotoImageFormat. The standard Tk distribution comes with handlers for PPM/PGM, PNG and GIF formats, which are automatically registered on initialization.

When reading an image file or processing string data specified with the -data configuration option, the photo image code invokes each handler in turn until one is found that claims to be able to read the data in the file or string. Usually this will find the correct handler, but if it does not, the user may give a format name with the -format option to specify which handler to use. In fact the photo image code will try those handlers whose names begin with the string specified for the -format option (the comparison is case-insensitive). For example, if the user specifies -format gif, then a handler named GIF87 or GIF89 may be invoked, but a handler named JPEG may not (assuming that such handlers had been registered).

When writing image data to a file, the processing of the -format option is slightly different: the string value given for the -format option must begin with the complete name of the requested handler, and may contain additional information following that, which the handler can use, for example, to specify which variant to use of the formats supported by the handler. Note that not all image handlers may support writing transparency data to a file, even where the target image format does.

FORMAT SUBOPTIONS

Some image formats support sub-options, which are specified at the time that the image is loaded using additional words in the -format option. At the time of writing, the following are supported:

gif -index indexValue
When parsing a multi-part GIF image, Tk normally only accesses the first image. By giving the -index sub-option, the indexValue'th value may be used instead. The indexValue must be an integer from 0 up to the number of image parts in the GIF data.
png -alpha alphaValue
An additional alpha filtering for the overall image, which allows the background on which the image is displayed to show through. This usually also has the effect of desaturating the image. The alphaValue must be between 0.0 and 1.0.

COLOR ALLOCATION

When a photo image is displayed in a window, the photo image code allocates colors to use to display the image and dithers the image, if necessary, to display a reasonable approximation to the image using the colors that are available. The colors are allocated as a color cube, that is, the number of colors allocated is the product of the number of shades of red, green and blue.

Normally, the number of colors allocated is chosen based on the depth of the window. For example, in an 8-bit PseudoColor window, the photo image code will attempt to allocate seven shades of red, seven shades of green and four shades of blue, for a total of 198 colors. In a 1-bit StaticGray (monochrome) window, it will allocate two colors, black and white. In a 24-bit DirectColor or TrueColor window, it will allocate 256 shades each of red, green and blue. Fortunately, because of the way that pixel values can be combined in DirectColor and TrueColor windows, this only requires 256 colors to be allocated. If not all of the colors can be allocated, the photo image code reduces the number of shades of each primary color and tries again.

The user can exercise some control over the number of colors that a photo image uses with the -palette configuration option. If this option is used, it specifies the maximum number of shades of each primary color to try to allocate. It can also be used to force the image to be displayed in shades of gray, even on a color display, by giving a single number rather than three numbers separated by slashes.

CREDITS

The photo image type was designed and implemented by Paul Mackerras, based on his earlier photo widget and some suggestions from John Ousterhout.

EXAMPLE

Load an image from a file and tile it to the size of a window, which is useful for producing a tiled background:

# These lines should be called once
image create photo untiled -file "theFile.ppm"
image create photo tiled
# These lines should be called whenever .someWidget changes
# size; a <Configure> binding is useful here
set width  [winfo width .someWidget]
set height [winfo height .someWidget]
tiled copy untiled -to 0 0 $width $height -shrink

The PNG image loader allows the application of an additional alpha factor during loading, which is useful for generating images suitable for disabled buttons:

image create photo icon -file "icon.png"
image create photo iconDisabled -file "icon.png" \
        -format "png -alpha 0.5"
button .b -image icon -disabledimage iconDisabled
