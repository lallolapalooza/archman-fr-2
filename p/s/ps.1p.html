PS(1P) Manuel du programmeur POSIX PS(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

ps — rapporter le statut des processus

SYNTAXE

ps [-aA] [-defl] [-g listegroupe] [-G listegroupe]
    [-n listenom] [-o format]... [-p listeProc] [-t listeterm]
    [-u listeUtil] [-U listeUtil]

DESCRIPTION

L'utilitaire ps écrira des informations sur les processus, sous réserve d'avoir les privilèges appropriés pour obtenir des informations sur ces processus.

Par défaut, ps sélectionnera tous les processus ayant le même ID utilisateur effectif que l'utilisateur courant et le même terminal de contrôle que l'invocateur.

OPTIONS

L'utilitaire ps se conformera au volume Base Definitions de POSIX.1‐2017, Section 12.2, Directives de syntaxe des utilitaires.

Les options suivantes seront prises en charge :

-a
Écrit des informations pour tous les processus associés aux terminaux. Les implémentations peuvent omettre les leaders de session de cette liste.
-A
Écrit des informations pour tous les processus.
-d
Écrit des informations pour tous les processus, à l'exception des leaders de session.
-e
Écrit des informations pour tous les processus. (Équivalent à -A.)
-f
Génère une liste complète. (Voir la section STDOUT pour le contenu d'une liste complète.)
-g listegroupe
Écrit des informations pour les processus dont les leaders de session sont donnés dans listegroupe. L'application doit s'assurer que listegroupe est un seul argument sous forme de liste séparée par des espaces ou des virgules.
-G listegroupe
Écrit des informations pour les processus dont les ID de groupe réels sont donnés dans listegroupe. L'application doit s'assurer que listegroupe est un seul argument sous forme de liste séparée par des espaces ou des virgules.
-l
Génère une liste longue. (Voir STDOUT pour le contenu d'une liste longue.)
-n listenom
Spécifie le nom d'un fichier système listenom alternatif à la place du fichier par défaut. Le nom du fichier par défaut et le format d'un fichier listenom ne sont pas spécifiés.
-o format
Écrit des informations selon la spécification de format donnée dans format. Ceci est entièrement décrit dans la section STDOUT. Plusieurs options -o peuvent être spécifiées ; la spécification de format sera interprétée comme la concaténation séparée par des espaces de tous les arguments d'option format.
-p listeProc
Écrit des informations pour les processus dont les numéros d'ID de processus sont donnés dans listeProc. L'application doit s'assurer que listeProc est un seul argument sous forme de liste séparée par des espaces ou des virgules.
-t listeterm
Écrit des informations pour les processus associés aux terminaux donnés dans listeterm. L'application doit s'assurer que listeterm est un seul argument sous forme de liste séparée par des espaces ou des virgules. Les identifiants de terminal seront donnés dans un format spécifié par l'implémentation. Sur les systèmes conformes XSI, ils seront donnés sous l'une des deux formes : le nom de fichier de l'appareil (par exemple, tty04) ou, si le nom de fichier de l'appareil commence par tty, juste l'identifiant suivant les caractères tty (par exemple, "04").
-u listeUtil
Écrit des informations pour les processus dont les ID utilisateur ou les noms de connexion sont donnés dans listeUtil. L'application doit s'assurer que listeUtil est un seul argument sous forme de liste séparée par des espaces ou des virgules. Dans la liste, l'ID utilisateur numérique sera écrit, sauf si l'option -f est utilisée, auquel cas le nom de connexion sera écrit.
-U listeUtil
Écrit des informations pour les processus dont les ID utilisateur réels ou les noms de connexion sont donnés dans listeUtil. L'application doit s'assurer que listeUtil est un seul argument sous forme de liste séparée par des espaces ou des virgules.

À l'exception de -f, -l, -n listenom et -o format, toutes les options montrées sont utilisées pour sélectionner des processus. Si l'une d'elles est spécifiée, la liste par défaut sera ignorée et ps sélectionnera les processus représentés par l'OU inclusif de toutes les options de critère de sélection.

Aucun.

STDIN

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de ps :

COLUMNS
Remplace la taille de ligne d'affichage horizontale sélectionnée par le système, utilisée pour déterminer le nombre de colonnes de texte à afficher. Voir le volume Base Definitions de POSIX.1‐2017, Chapitre 8, Variables d'environnement pour les valeurs valides et les résultats lorsqu'elle est non définie ou nulle.
LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou nulles. (Voir le volume Base Definitions de POSIX.1‐2017, Section 8.2, Variables d'internationalisation la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données texte en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard et des messages informatifs écrits sur la sortie standard.
LC_TIME
Détermine le format et le contenu des chaînes de date et d'heure affichées.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.
TZ
Détermine le fuseau horaire utilisé pour calculer les chaînes de date et d'heure affichées. Si TZ est non défini ou nul, un fuseau horaire par défaut non spécifié sera utilisé.

EVENEMENTS ASYNCHRONES

Par défaut.

STDOUT

Lorsque l'option -o n'est pas spécifiée, le format de sortie standard n'est pas spécifié.

Sur les systèmes conformes XSI, le format de sortie sera le suivant. Les en-têtes de colonne et les descriptions des colonnes dans une liste ps sont donnés ci-dessous. Les significations précises de ces champs sont spécifiées par l'implémentation.

Notez que ces deux options déterminent uniquement quelles informations sont fournies pour un processus ; elles ne déterminent pas quels processus sont listés.

F (l) Indicateurs (octal et additifs) associés au processus.
S (l) L'état du processus.
UID (f,l) Le numéro d'identification utilisateur du propriétaire du processus ; le nom de connexion est imprimé sous l'option -f.
PID (all) L'identifiant du processus ; il est possible de tuer un processus si cette donnée est connue.
PPID (f,l) L'identifiant du processus parent.
C (f,l) Utilisation du processeur pour la planification.
PRI (l) La priorité du processus ; des nombres plus élevés signifient une priorité plus basse.
NI (l) Valeur de nice ; utilisée dans le calcul de la priorité.
ADDR (l) L'adresse du processus.
SZ (l) La taille en blocs de l'image mémoire du processus.
WCHAN (l) L'événement pour lequel le processus attend ou dort ; si vide, le processus est en cours d'exécution.
STIME (f) Heure de démarrage du processus.
TTY (all) Le terminal de contrôle du processus.
TIME (all) Le temps d'exécution cumulé du processus.
CMD (all) Le nom de la commande ; le nom complet de la commande et ses arguments sont écrits sous l'option -f.

Un processus qui s'est terminé et a un parent, mais qui n'a pas encore été attendu par le parent, sera marqué comme defunct.

Sous l'option -f, ps essaie de déterminer le nom de la commande et les arguments donnés lors de la création du processus en examinant la mémoire ou la zone de pagination. En cas d'échec, le nom de la commande, tel qu'il apparaîtrait sans l'option -f, est écrit entre crochets.

L'option -o permet de spécifier le format de sortie sous le contrôle de l'utilisateur.

L'application doit s'assurer que la spécification de format est une liste de noms présentés comme un seul argument, séparés par un <espace> ou une <virgule>. Chaque variable a un en-tête par défaut. L'en-tête par défaut peut être remplacé en ajoutant un <signe égal> et le nouveau texte de l'en-tête. Le reste des caractères de l'argument sera utilisé comme texte d'en-tête. Les champs spécifiés doivent être écrits dans l'ordre spécifié sur la ligne de commande, et doivent être disposés en colonnes dans la sortie. Les largeurs de champ seront sélectionnées par le système pour être au moins aussi larges que le texte de l'en-tête (valeur par défaut ou remplacée). Si le texte de l'en-tête est nul, comme -o user=, la largeur du champ sera au moins aussi large que le texte de l'en-tête par défaut. Si tous les champs de texte d'en-tête sont nuls, aucune ligne d'en-tête ne sera écrite.

Les noms suivants sont reconnus dans la locale POSIX :

ruser
L'identifiant utilisateur réel du processus. Ce sera l'identifiant utilisateur textuel, s'il peut être obtenu et que la largeur du champ le permet, sinon une représentation décimale.
user
L'identifiant utilisateur effectif du processus. Ce sera l'identifiant utilisateur textuel, s'il peut être obtenu et que la largeur du champ le permet, sinon une représentation décimale.
rgroup
L'identifiant de groupe réel du processus. Ce sera l'identifiant de groupe textuel, s'il peut être obtenu et que la largeur du champ le permet, sinon une représentation décimale.
group
L'identifiant de groupe effectif du processus. Ce sera l'identifiant de groupe textuel, s'il peut être obtenu et que la largeur du champ le permet, sinon une représentation décimale.
pid
La valeur décimale de l'identifiant du processus.
ppid
La valeur décimale de l'identifiant du processus parent.
pgid
La valeur décimale de l'identifiant du groupe de processus.
pcpu
Le rapport du temps CPU utilisé récemment sur le temps CPU disponible pendant la même période, exprimé en pourcentage. La signification de « récemment » dans ce contexte n'est pas spécifiée. Le temps CPU disponible est déterminé d'une manière non spécifiée.
vsz
La taille du processus en mémoire (virtuelle) en unités de 1024 octets sous forme d'entier décimal.
nice
La valeur décimale de la valeur de nice du processus ; voir nice.
etime
Dans la locale POSIX, le temps écoulé depuis le démarrage du processus, sous la forme :
[[jj-]hh:]mm:ss

où jj représente le nombre de jours, hh le nombre d'heures, mm le nombre de minutes et ss le nombre de secondes. Le champ jj sera un entier décimal. Les champs hh, mm et ss seront des entiers décimaux à deux chiffres complétés à gauche par des zéros.

time
Dans la locale POSIX, le temps CPU cumulé du processus sous la forme :
[jj-]hh:mm:ss

Les champs jj, hh, mm et ss seront tels que décrits dans le spécificateur etime.

tty
Le nom du terminal de contrôle du processus (le cas échéant) dans le même format utilisé par l'utilitaire who.
comm
Le nom de la commande en cours d'exécution (valeur de argv[0]) sous forme de chaîne.
args
La commande avec tous ses arguments sous forme de chaîne. L'implémentation peut tronquer cette valeur à la largeur du champ ; il est défini par l'implémentation si une troncature supplémentaire se produit. Il n'est pas spécifié si la chaîne représentée est une version de la liste d'arguments telle qu'elle a été passée à la commande lors de son démarrage, ou une version des arguments tels qu'ils ont pu être modifiés par l'application. Les applications ne peuvent pas s'attendre à pouvoir modifier leur liste d'arguments et à ce que cette modification soit reflétée dans la sortie de ps.

Tout champ n'a pas nécessairement à être significatif dans toutes les implémentations. Dans un tel cas, un <trait d'union> ('-') doit être affiché à la place de la valeur du champ.

Seuls comm et args sont autorisés à contenir des caractères <espace> ; tous les autres ne le sont pas. Les variables définies par l'implémentation doivent être spécifiées dans la documentation du système avec l'en-tête par défaut et indiquer si le champ peut contenir des caractères <espace>.

USAGE PAR L'APPLICATION

Les choses peuvent changer pendant que ps s'exécute ; l'instantané qu'il donne n'est vrai qu'à un instant T, et pourrait ne pas être exact au moment où il est affiché.

Le spécificateur de format args est autorisé à produire une version tronquée des arguments de la commande. Dans certaines implémentations, ces informations ne sont plus disponibles lorsque l'utilitaire ps est exécuté.

/p>

Si la largeur du champ est trop étroite pour afficher un identifiant textuel, le système peut utiliser une version numérique. Normalement, on s'attend à ce que le système choisisse des largeurs de champ suffisamment grandes, mais si un grand nombre de champs ont été sélectionnés pour l'écriture, il peut réduire les champs à leurs tailles minimales pour qu'ils tiennent sur une seule ligne. Une façon de garantir une largeur adéquate pour les identifiants textuels est de remplacer l'en-tête par défaut d'un champ pour le rendre plus grand que la plupart ou la totalité des noms d'utilisateurs ou de groupes.

Il n'y a pas de mécanisme de mise entre guillemets spécial pour le texte de l'en-tête. Le texte de l'en-tête est le reste de l'argument. Si plusieurs modifications d'en-tête sont nécessaires, plusieurs options -o peuvent être utilisées, comme suit :

ps -o "user=Nom d'utilisateur" -o pid=ID\ processus

Sur certaines implémentations, en particulier les systèmes sécurisés à plusieurs niveaux, ps peut être sévèrement restreint et ne produire des informations que sur les processus enfants appartenant à l'utilisateur.

EXEMPLES

La commande :

ps -o user,pid,ppid=MOM -o args

écrit au moins ce qui suit dans la locale POSIX :

  USER   PID   MOM   COMMAND
helene    34    12   ps -o uid,pid,ppid=MOM -o args

Le contenu du champ COMMAND n'est pas nécessairement le même dans toutes les implémentations, en raison d'une éventuelle troncature.

RATIONALE

Il y a très peu de points communs entre les implémentations BSD et System V de ps. De nombreuses options entrent en conflit ou ont des utilisations subtilement différentes. Les développeurs du standard ont tenté de sélectionner un ensemble d'options pour le standard de base qui soient utiles sur une large gamme de systèmes et ont choisi des options qui soit peuvent être implémentées sur des systèmes basés sur BSD et System V sans casser les implémentations actuelles, soit dont les options sont suffisamment similaires pour que tout changement ne soit pas inutilement problématique pour les utilisateurs ou les implémenteurs.

Il est reconnu que sur certaines implémentations, en particulier les systèmes sécurisés à plusieurs niveaux, ps peut être presque inutile. La sortie par défaut a donc été choisie de manière à ne pas casser les implémentations historiques et à fournir au moins quelques informations utiles sur la plupart des systèmes.

Le changement majeur est l'ajout de la capacité de spécification de format. La motivation pour cette invention est de fournir un mécanisme permettant aux utilisateurs d'accéder à un éventail plus large d'informations système, si le système le permet, de manière portable. Les champs choisis pour apparaître dans ce volume de POSIX.1‐2017 ont été déterminés après avoir considéré quels concepts étaient susceptibles d'être à la fois raisonnablement utiles à l'utilisateur « moyen » et d'avoir une chance raisonnable d'être implémentés sur une large gamme de systèmes. Encore une fois, il est reconnu que tous les systèmes ne sont pas en mesure de fournir toutes les informations et, inversement, certains peuvent souhaiter en fournir plus. On espère que l'approche adoptée sera suffisamment flexible et extensible pour accueillir la plupart des systèmes. On peut s'attendre à ce que les implémentations introduisent de nouveaux spécificateurs de format.

La sortie par défaut devrait consister en une courte liste contenant l'ID du processus, le nom du terminal, le temps d'exécution cumulé et le nom de la commande de chaque processus.

La préférence des développeurs du standard aurait été de faire de la spécification de format un opérande de la commande ps. Malheureusement, l'utilisation de BSD a empêché cela.

À une époque, un format était inclus pour afficher le tableau d'environnement du processus. Il a été supprimé car il n'y a pas de moyen portable de l'afficher.

L'option -A est équivalente à l'option -g de BSD et à l'option -e de SVID. Parce que les deux systèmes différaient, un compromis mnémotechnique a été sélectionné.

L'option -a est décrite avec un comportement optionnel car SVID omet les chefs de session, mais pas BSD.

Dans une proposition antérieure, des spécificateurs de format apparaissaient pour la priorité et l'heure de démarrage. Le premier n'était pas adéquatement défini dans ce volume de POSIX.1‐2017 et a été supprimé au profit de la valeur de "nice" définie ; le second parce que le temps écoulé était considéré comme plus utile.

Dans une nouvelle version BSD de ps, une option -O peut être utilisée pour écrire toutes les informations par défaut, suivies de spécificateurs de format supplémentaires. Cela n'a pas été adopté car la sortie par défaut est définie par l'implémentation. Néanmoins, c'est une option utile qui devrait être réservée à cet effet. Dans l'option -o pour le ps de POSIX Shell and Utilities, le format est la concaténation de chaque -o. Par conséquent, l'utilisateur peut avoir un alias ou une fonction qui définit le début de son format souhaité et ajouter d'autres champs à la fin de la sortie dans certains cas où cela serait utile.

Le format du nom du terminal n'est pas spécifié, mais les descriptions de ps, talk, who et write exigent qu'ils utilisent tous le même format.

Le champ pcpu indique que le temps CPU disponible est déterminé d'une manière non spécifiée. Ceci est dû au fait qu'il est difficile d'exprimer un algorithme utile sur toutes les architectures machine possibles. Les contreparties historiques de cette valeur ont tenté de montrer le pourcentage d'utilisation dans un passé récent, comme la minute précédente. Fréquemment, ces valeurs pour tous les processus n'additionnaient pas 100%. On encourage les implémentations à fournir des données dans ce champ aux utilisateurs afin de les aider à identifier les processus affectant actuellement les performances du système.
