pscp(1) Suite d'outils PuTTY pscp(1)

NOM

pscp - client en ligne de commande SCP (copie sécurisée) / SFTP (protocole de transfert de fichiers sécurisé)

SYNTAXE

pscp [options] [utilisateur@]hôte:source cible
pscp [options] source [source...] [utilisateur@]hôte:cible
pscp [options] -ls [utilisateur@]hôte:spécification_fichier

DESCRIPTION

pscp est un client en ligne de commande pour les protocoles SCP (copie sécurisée) et SFTP (protocole de transfert de fichiers sécurisé) basés sur SSH.

OPTIONS

Les options en ligne de commande prises en charge par pscp sont :

-V
Affiche les informations de version et quitte.
-pgpfp
Affiche les empreintes digitales des clés maîtres PGP de PuTTY et quitte, pour aider à vérifier les nouveaux fichiers publiés par l'équipe PuTTY.
-ls
Liste le répertoire distant.
-p
Préserve les attributs du fichier.
-q
Silencieux, n'affiche pas de statistiques.
-r
Copie les répertoires de manière récursive.
-unsafe
Autorise les caractères génériques côté serveur (DANGEREUX).
-v
Affiche les messages détaillés.
-load session
Charge les paramètres à partir d'une session enregistrée.
-P port
Se connecte au port port.
-proxycmd commande
Au lieu d'établir une connexion TCP, utilise commande comme proxy ; le trafic réseau sera redirigé vers l'entrée et la sortie standard de commande. commande doit être un seul mot, il est donc probable qu'elle nécessite des guillemets de la part du shell.

Les chaînes spéciales %host et %port dans commande seront remplacées par le nom d'hôte et le numéro de port auxquels vous souhaitez vous connecter ; pour obtenir un signe % littéral, entrez %%.

Les échappements de barre oblique inverse sont également pris en charge, tels que les séquences comme \n étant remplacées par un saut de ligne littéral ; pour obtenir une barre oblique inverse littérale, entrez \\. (Un échappement supplémentaire peut être requis par le shell.)

(Voir le manuel principal de PuTTY pour les détails complets des jetons pris en charge délimités par % et par barre oblique inverse, bien que la plupart d'entre eux ne soient probablement pas très utiles dans ce contexte.)

-l utilisateur
Définit le nom d'utilisateur distant sur utilisateur.
-batch
Désactive les invites interactives.
-no-sanitise-stderr
Par défaut, PSCP filtrera les caractères de contrôle du canal d'erreur standard du serveur, afin d'empêcher les processus distants d'envoyer des séquences d'échappement confuses. Cette option force le canal d'erreur standard à ne pas être filtré.
-pwfile nom_fichier
Ouvre le fichier spécifié et utilise la première ligne de texte lue à partir de celui-ci comme mot de passe distant.
-pw mot_de_passe
Définit le mot de passe distant sur mot_de_passe. ATTENTION : cela rendra probablement le mot de passe visible aux autres utilisateurs de la machine locale (via des commandes telles que `ps' ou `w'). Utilisez plutôt -pwfile.
-1
Force l'utilisation du protocole SSH version 1.
-2
Force l'utilisation du protocole SSH version 2.
-ssh-connection
Force l'utilisation du protocole `SSH brut'. Ceci n'est probablement utile que lors de la connexion à un serveur psusan(1), le plus souvent avec un chemin absolu vers un socket de domaine Unix à la place de hôte.
-ssh
Force l'utilisation du protocole SSH. (Ce n'est généralement pas nécessaire ; cela n'est probablement utile que si vous devez remplacer une autre configuration du protocole `SSH brut'.)
-4, -6
Force l'utilisation d'IPv4 ou IPv6 pour les connexions réseau.
-C
Active la compression SSH.
-i fichier_clé
Fichier de clé privée pour l'authentification de l'utilisateur. Pour les clés SSH-2, ce fichier de clé doit être au format PPK de PuTTY, pas au format OpenSSH ou à tout autre format.

Si vous utilisez un agent d'authentification, vous pouvez également spécifier une clé publique ici (au format RFC 4716 ou OpenSSH), pour identifier quelle clé de l'agent utiliser.

-noagent
N'essaie pas d'utiliser un agent d'authentification.
-agent
Autorise l'utilisation d'un agent d'authentification. (Cette option n'est nécessaire que pour remplacer un paramètre dans une session enregistrée.)
-no-trivial-auth
Se déconnecte de tout serveur SSH qui accepte l'authentification sans jamais avoir demandé de mot de passe, de signature ou de jeton. (Vous pourriez vouloir activer ceci pour un serveur qui vous demande toujours une authentification, par exemple pour vous assurer de ne pas taper accidentellement le mot de passe de votre fichier clé dans un serveur compromis se faisant passer pour l'invite de mot de passe de PSCP.)
-hostkey clé
Spécifie une clé publique d'hôte acceptable. Cette option peut être spécifiée plusieurs fois ; chaque clé peut être soit une empreinte digitale (SHA256:AbCdE..., 99:aa:bb:..., etc.) soit un blob encodé en base64 au format ligne unique d'OpenSSH.

La spécification de cette option remplace la gestion automatisée des clés d'hôte ; seules les clés spécifiées dans la ligne de commande seront acceptées (sauf si une session enregistrée remplace également les clés d'hôte, auquel cas celles-ci seront ajoutées), et le cache des clés d'hôte ne sera pas écrit.

-scp
Force l'utilisation du protocole SCP.
-sftp
Force l'utilisation du protocole SFTP.
-sshlog fichier_journal
-sshrawlog fichier_journal
Ces options permettent à pscp d'enregistrer les détails du protocole dans un fichier. (Certains de ces détails peuvent être sensibles, bien que par défaut un effort soit fait pour supprimer les mots de passe évidents.)

-sshlog enregistre les paquets SSH décodés et d'autres événements (ceux que -v afficherait). -sshrawlog enregistre en plus les données brutes des paquets chiffrés.

-logoverwrite
Si PSCP est configuré pour écrire dans un fichier journal qui existe déjà, supprime le fichier existant.
-logappend
Si PSCP est configuré pour écrire dans un fichier journal qui existe déjà, ajoute les nouvelles données du journal au fichier existant.

pscp(1)

NOM

pscp — transfert de fichiers sécurisé avec PuTTY

SYNTAXE

pscp [options] source destination

DESCRIPTION

pscp est un utilitaire de ligne de commande qui permet de transférer des fichiers de manière sécurisée sur un réseau en utilisant le protocole SSH. Il est basé sur l'outil scp (secure copy) de Unix, mais utilise le protocole réseau de PuTTY.

Il est particulièrement utile pour copier des fichiers entre des machines exécutant un serveur SSH, comme ceux utilisés par OpenSSH.

OPTIONS

pscp prend en charge un certain nombre d'options qui modifient son comportement. Les options courantes incluent :

  • -V : Affiche les informations de version de pscp et quitte.
  • -pgpfp : Affiche l'empreinte du serveur PGP et quitte.
  • -l nom d'utilisateur : Spécifie le nom d'utilisateur à utiliser pour la connexion.
  • -p : Préserve les horodatages des fichiers et les modes d'accès.
  • -q : Mode silencieux. Désactive les messages de progression et d'avertissement.
  • -r : Copie récursivement les répertoires.
  • -v : Mode verbeux. Provoque l'impression d'informations de débogage sur le fonctionnement de pscp.
  • -load session : Charge une session enregistrée depuis PuTTY.
  • -P port : Spécifie le port sur lequel le serveur SSH écoute.
  • -pw mot de passe : Spécifie le mot de passe à utiliser pour l'authentification (déconseillé pour des raisons de sécurité).
  • -unsafe-getenv VAR : Permet à pscp d'obtenir la valeur de la variable d'environnement VAR depuis le serveur distant. À utiliser avec une extrême prudence.
  • -sftp : Force l'utilisation du sous-système SFTP (par défaut).
  • -scp : Force l'utilisation du protocole SCP (plus ancien).

Les arguments source et destination peuvent être des fichiers locaux ou des chemins sur un serveur distant. Le format pour une ressource distante est :

[utilisateur@]hôte:chemin

Par exemple :

  • pscp monfichier.txt utilisateur@distant.com:/chemin/vers/destination
  • pscp -r monrepertoire/ utilisateur@distant.com:
