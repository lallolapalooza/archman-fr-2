PSIGINFO(3P) Manuel du programmeur POSIX PSIGINFO(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

psiginfo, psignal — écrire des informations sur les signaux sur le flux d'erreurs standard

SYNTAXE

#include <signal.h>
void psiginfo(const siginfo_t *pinfo, const char *message);
void psignal(int signum, const char *message);

DESCRIPTION

Les fonctions psiginfo() et psignal() écrivent un message, dépendant de la langue, associé à un numéro de signal sur le flux d'erreurs standard comme suit :

*
Premièrement, si message n'est pas un pointeur nul et n'est pas une chaîne vide, la chaîne pointée par l'argument message sera écrite, suivie d'un <deux-points> et d'un <espace>.
*
Ensuite, la chaîne de description du signal associée à signum ou au signal indiqué par pinfo sera écrite, suivie d'un <saut de ligne>.

Pour psiginfo(), l'application doit s'assurer que l'argument pinfo référence une structure siginfo_t valide. Pour psignal(), si signum n'est pas un numéro de signal valide, le comportement est défini par l'implémentation.

Les fonctions psiginfo() et psignal() ne modifient pas l'orientation du flux d'erreurs standard.

Les fonctions psiginfo() et psignal() marquent pour mise à jour les horodatages de dernière modification des données et de dernier changement d'état du fichier associé au flux d'erreurs standard à un moment donné entre leur achèvement réussi et exit(), abort(), ou l'achèvement de fflush() ou fclose() sur stderr.

Les fonctions psiginfo() et psignal() ne modifient pas la valeur de errno en cas de succès.

En cas d'erreur, les fonctions psiginfo() et psignal() définissent l'indicateur d'erreur pour le flux pointé par stderr, et définissent errno pour indiquer l'erreur.

Comme aucune valeur n'est retournée, une application souhaitant vérifier les situations d'erreur doit définir errno à 0, puis appeler psiginfo() ou psignal(), puis vérifier errno.

VALEUR DE RETOUR

Ces fonctions ne retournent aucune valeur.

ERREURS

Voir fputc().

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION APPLICATIVE

Comme alternative à la définition de errno à zéro avant l'appel et à la vérification de sa non-nullité après, les applications peuvent utiliser ferror() pour détecter si psiginfo() ou psignal() a rencontré une erreur.

Une application souhaitant utiliser cette méthode pour vérifier les situations d'erreur devrait appeler clearerr(stderr) avant d'appeler psiginfo() ou psignal(), puis si ferror(stderr) retourne une valeur non nulle, la valeur de errno indique quelle erreur s'est produite.

RATIONALE

Historiquement, System V avait psignal() et psiginfo() dans <siginfo.h>. Cependant, l'en-tête <siginfo.h> n'est pas spécifié dans le volume des Définitions de base de POSIX.1‐2017, et le type siginfo_t est défini dans <signal.h>.
