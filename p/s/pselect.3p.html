PSELECT(3P) Manuel du programmeur POSIX PSELECT(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pselect, select — multiplexage d'E/S synchrone

SYNTAXE

#include <sys/select.h>
int pselect(int nfds, fd_set *restrict readfds,
    fd_set *restrict writefds, fd_set *restrict errorfds,
    const struct timespec *restrict timeout,
    const sigset_t *restrict sigmask);
int select(int nfds, fd_set *restrict readfds,
    fd_set *restrict writefds, fd_set *restrict errorfds,
    struct timeval *restrict timeout);
void FD_CLR(int fd, fd_set *fdset);
int FD_ISSET(int fd, fd_set *fdset);
void FD_SET(int fd, fd_set *fdset);
void FD_ZERO(fd_set *fdset);

DESCRIPTION

La fonction pselect() examine les ensembles de descripteurs de fichiers dont les adresses sont passées dans les paramètres readfds, writefds et errorfds pour voir si certains de leurs descripteurs sont prêts en lecture, prêts en écriture, ou ont une condition exceptionnelle en attente, respectivement.

La fonction select() est équivalente à la fonction pselect(), sauf pour les points suivants :

*
Pour la fonction select(), la période de temps d'attente est donnée en secondes et en microsecondes dans un argument de type struct timeval, alors que pour la fonction pselect(), la période de temps d'attente est donnée en secondes et en nanosecondes dans un argument de type struct timespec.
*
La fonction select() n'a pas d'argument sigmask ; elle se comporte comme pselect() lorsque sigmask est un pointeur nul.
*
En cas de succès, la fonction select() peut modifier l'objet pointé par l'argument timeout.

Les fonctions pselect() et select() prennent en charge les fichiers réguliers, les périphériques de terminaux et de pseudo-terminaux, les fichiers basés sur STREAMS, les FIFO, les pipes et les sockets. Le comportement de pselect() et select() sur des descripteurs de fichiers se référant à d'autres types de fichiers n'est pas spécifié.

L'argument nfds spécifie la plage de descripteurs à tester. Les nfds premiers descripteurs sont vérifiés dans chaque ensemble ; c'est-à-dire que les descripteurs de zéro à nfds-1 dans les ensembles de descripteurs sont examinés.

Si l'argument readfds n'est pas un pointeur nul, il pointe vers un objet de type fd_set qui, en entrée, spécifie les descripteurs de fichiers à vérifier pour être prêts en lecture, et en sortie, indique quels descripteurs de fichiers sont prêts en lecture.

Si l'argument writefds n'est pas un pointeur nul, il pointe vers un objet de type fd_set qui, en entrée, spécifie les descripteurs de fichiers à vérifier pour être prêts en écriture, et en sortie, indique quels descripteurs de fichiers sont prêts en écriture.

Si l'argument errorfds n'est pas un pointeur nul, il pointe vers un objet de type fd_set qui, en entrée, spécifie les descripteurs de fichiers à vérifier pour des conditions d'erreur en attente, et en sortie, indique quels descripteurs de fichiers ont des conditions d'erreur en attente.

En cas de succès, la fonction pselect() ou select() modifie les objets pointés par les arguments readfds, writefds et errorfds pour indiquer quels descripteurs de fichiers sont prêts en lecture, prêts en écriture, ou ont une condition d'erreur en attente, respectivement, et renvoie le nombre total de descripteurs prêts dans tous les ensembles de sortie. Pour chaque descripteur de fichier inférieur à nfds, le bit correspondant est défini en cas de succès s'il était défini en entrée et que la condition associée est vraie pour ce descripteur de fichier.

Si aucun des descripteurs sélectionnés n'est prêt pour l'opération demandée, la fonction pselect() ou select() se bloque jusqu'à ce qu'au moins une des opérations demandées soit prête, jusqu'à ce que le timeout se produise, ou jusqu'à ce qu'elle soit interrompue par un signal. Le paramètre timeout contrôle la durée pendant laquelle la fonction pselect() ou select() attend avant d'expirer. Si le paramètre timeout n'est pas un pointeur nul, il spécifie un intervalle maximal à attendre pour que la sélection s'achève. Si l'intervalle de temps spécifié expire sans qu'aucune opération demandée ne soit prête, la fonction retourne. Si le paramètre timeout est un pointeur nul, alors l'appel à pselect() ou select() se bloque indéfiniment jusqu'à ce qu'au moins un descripteur réponde aux critères spécifiés. Pour effectuer un sondage, le paramètre timeout ne doit pas être un pointeur nul et doit pointer vers une structure timespec de valeur nulle.

L'utilisation d'un délai d'attente n'affecte pas les temporisateurs en attente mis en place par alarm() ou setitimer().

Les implémentations peuvent imposer des limitations sur l'intervalle de temps d'attente maximal supporté. Toutes les implémentations doivent supporter un intervalle de temps d'attente maximal d'au moins 31 jours. Si l'argument timeout spécifie un intervalle de temps d'attente supérieur à la valeur maximale définie par l'implémentation, la valeur maximale est utilisée comme intervalle de temps d'attente réel. Les implémentations peuvent également imposer des limitations sur la granularité des intervalles de temps d'attente. Si l'intervalle de temps d'attente demandé nécessite une granularité plus fine que celle supportée par l'implémentation, l'intervalle de temps d'attente réel est arrondi à la valeur supportée suivante.

Si sigmask n'est pas un pointeur nul, alors la fonction pselect() remplace le masque de signaux de l'appelant par l'ensemble de signaux pointé par sigmask avant d'examiner les descripteurs, et restaure le masque de signaux du thread appelant avant de retourner.

Un descripteur est considéré comme prêt en lecture lorsqu'un appel à une fonction d'entrée avec O_NONBLOCK effacé ne se bloque pas, que la fonction transfère des données avec succès ou non. (La fonction peut retourner des données, une indication de fin de fichier, ou une erreur autre que celle indiquant qu'elle est bloquée, et dans chacun de ces cas, le descripteur est considéré comme prêt en lecture.)

Un descripteur est considéré comme prêt en écriture lorsqu'un appel à une fonction de sortie avec O_NONBLOCK effacé ne se bloque pas, que la fonction transfère des données avec succès ou non.

Si un socket a une erreur en attente, il est considéré comme ayant une condition exceptionnelle en attente. Sinon, ce qui constitue une condition exceptionnelle est spécifique au type de fichier. Pour un descripteur de fichier à utiliser avec un socket, il est spécifique au protocole sauf indication contraire ci-dessous. Pour d'autres types de fichiers, il est défini par l'implémentation. Si l'opération est dénuée de sens pour un type de fichier particulier, pselect() ou select() indique que le descripteur est prêt pour les opérations de lecture ou d'écriture, et indique que le descripteur n'a aucune condition exceptionnelle en attente.

Si un descripteur se réfère à un socket, la fonction d'entrée implicite est la fonction recvmsg() avec des paramètres demandant des données normales et accessoires, de sorte que la présence de l'un ou l'autre type entraîne la marquage du socket comme lisible. La présence de données hors bande est vérifiée si l'option de socket SO_OOBINLINE a été activée, car les données hors bande sont mises en file d'attente avec les données normales. Si le socket est en cours d'écoute, il est marqué comme lisible si une demande de connexion entrante a été reçue, et un appel à la fonction accept() se termine sans bloquer.

Si un descripteur se réfère à un socket, la fonction de sortie implicite est la fonction sendmsg() fournissant une quantité de données normales égale à la valeur actuelle de l'option SO_SNDLOWAT pour le socket. Si un appel non bloquant à la fonction connect() a été effectué pour un socket, et que la tentative de connexion a réussi ou échoué en laissant une erreur en attente, le socket est marqué comme accessible en écriture.

Un socket est considéré comme ayant une condition exceptionnelle en attente si une opération de réception avec O_NONBLOCK effacé pour la description de fichier ouverte et avec le drapeau MSG_OOB défini renvoie des données hors bande sans bloquer. (Il est spécifique au protocole si le drapeau MSG_OOB serait utilisé pour lire des données hors bande.) Un socket est également considéré comme ayant une condition exceptionnelle en attente si une marque de données hors bande est présente dans la file de réception. D'autres circonstances dans lesquelles un socket peut être considéré comme ayant une condition exceptionnelle en attente sont spécifiques au protocole et définies par l'implémentation.

This page is part of the POSIX Programmer's Manual. The Linux implementation of this system call is described in pselect(2).

NAME

pselect, select - synchronous I/O multiplexing

SYNOPSIS

#include <sys/select.h>
#include <sys/time.h>
#include <signal.h>
#include <unistd.h>

int select(int nfds, fd_set *restrict readfds, fd_set *restrict writefds,
    fd_set *restrict errorfds, const struct timespec *restrict timeout);
int pselect(int nfds, fd_set *restrict readfds, fd_set *restrict writefds,
    fd_set *restrict errorfds, const struct timespec *restrict timeout,
    const sigset_t *restrict sigmask);

DESCRIPTION

The select() and pselect() functions shall monitor file descriptors to determine if they are ready to perform I/O or if they have an exceptional condition pending. The monitoring is done using three sets of file descriptors: readfds, writefds, and errorfds. The caller specifies the maximum file descriptor number to be checked in each set, plus one, in the nfds argument. The system call blocks until one of the following occurs:

  • A file descriptor in one of the sets is ready for I/O or has an exceptional condition pending.
  • The timeout interval expires.
  • A signal is caught and the signal handler returns.

The file descriptor sets are represented by fd_set structures. The macros FD_CLR(), FD_ISSET(), FD_SET(), and FD_ZERO() are used to manipulate these structures.

The nfds argument specifies the range of file descriptors to be tested. It is the number of file descriptors to be checked. It is the maximum file descriptor number to be checked plus one. For example, if the highest file descriptor number is 9, then nfds should be 10.

The readfds argument points to an fd_set structure containing the file descriptors to be checked for their readiness to be read. The writefds argument points to an fd_set structure containing the file descriptors to be checked for their readiness to be written. The errorfds argument points to an fd_set structure containing the file descriptors to be checked for errors. If any of these arguments are a null pointer, the corresponding set is not checked.

The timeout argument points to a struct timespec structure specifying a maximum interval to wait for the selection to complete. If the timeout argument is not a null pointer, the system call blocks for at most the specified amount of time. If the timeout interval expires before any of the specified events occur, the function returns, and the contents of the fd_set structures pointed to by readfds, writefds, and errorfds are not modified. If timeout is a null pointer, the select() function shall block indefinitely until at least one file descriptor becomes ready or is interrupted by a signal.

The pselect() function is similar to select(), but it also takes an additional argument, sigmask. If sigmask is not a null pointer, pselect() replaces the calling thread's signal mask with the one pointed to by sigmask, waits for the selection to complete, and then restores the original signal mask. If sigmask is a null pointer, pselect() behaves like select(). This atomicity prevents race conditions between the signal mask manipulation and the selection process.

If the readfds, writefds, and errorfds arguments are all null pointers and the timeout argument is a null pointer, the pselect() or select() function shall block until interrupted by a signal.

File descriptors associated with regular files shall always select true for ready to read, ready to write, and error conditions.

On failure, the objects pointed to by the readfds, writefds, and errorfds arguments shall not be modified. If the timeout interval expires without the specified condition being true for any of the specified file descriptors, the objects pointed to by the readfds, writefds, and errorfds arguments shall have all bits set to 0.

File descriptor masks of type fd_set can be initialized and tested with FD_CLR(), FD_ISSET(), FD_SET(), and FD_ZERO(). It is unspecified whether each of these is a macro or a function. If a macro definition is suppressed in order to access an actual function, or a program defines an external identifier with any of these names, the behavior is undefined.

FD_CLR(fd, fdsetp) shall remove the file descriptor fd from the set pointed to by fdsetp. If fd is not a member of this set, there shall be no effect on the set, nor will an error be returned.

FD_ISSET(fd, fdsetp) shall evaluate to non-zero if the file descriptor fd is a member of the set pointed to by fdsetp, and shall evaluate to zero otherwise.

FD_SET(fd, fdsetp) shall add the file descriptor fd to the set pointed to by fdsetp. If the file descriptor fd is already in this set, there shall be no effect on the set, nor will an error be returned.

FD_ZERO(fdsetp) shall initialize the descriptor set pointed to by fdsetp to the null set. No error is returned if the set is not empty at the time FD_ZERO() is invoked.

The behavior of these macros is undefined if the fd argument is less than 0 or greater than or equal to FD_SETSIZE, or if fd is not a valid file descriptor, or if any of the arguments are expressions with side-effects.

If a thread gets canceled during a pselect() call, the signal mask in effect when executing the registered cleanup functions is either the original signal mask or the signal mask installed as part of the pselect() call.

RETURN VALUE

Upon successful completion, the pselect() and select() functions shall return the total number of bits set in the bit masks. Otherwise, -1 shall be returned, and errno shall be set to indicate the error.

FD_CLR(), FD_SET(), and FD_ZERO() do not return a value. FD_ISSET() shall return a non-zero value if the bit for the file descriptor fd is set in the file descriptor set pointed to by fdset, and 0 otherwise.

ERRORS

Under the following conditions, pselect() and select() shall fail and set errno to:

EBADF
One or more of the file descriptor sets specified a file descriptor that is not a valid open file descriptor.
EINTR
The function was interrupted while blocked waiting for any of the selected descriptors to become ready and before the timeout interval expired.

If SA_RESTART has been set for the interrupting signal, it is implementation-defined whether the function restarts or returns with [EINTR].

EINVAL
An invalid timeout interval was specified.
EINVAL
The nfds argument is less than 0 or greater than FD_SETSIZE.
EINVAL
One of the specified file descriptors refers to a STREAM or multiplexer that is linked (directly or indirectly) downstream from a multiplexer.

RATIONALE

In earlier versions of the Single UNIX Specification, the select() function was defined in the <sys/time.h> header. This is now changed to <sys/select.h>. The rationale for this change was as follows: the introduction of the pselect() function included the <sys/select.h> header and the <sys/select.h> header defines all the related definitions for the pselect() and select() functions. Backwards-compatibility to existing XSI implementations is handled by allowing <sys/time.h> to include <sys/select.h>.

Code which wants to avoid the ambiguity of the signal mask for thread cancellation handlers can install an additional cancellation handler which resets the signal mask to the expected value.

void cleanup(void *arg)
{
    sigset_t *ss = (sigset_t *) arg;
    pthread_sigmask(SIG_SETMASK, ss, NULL);
}
int call_pselect(int nfds, fd_set *readfds, fd_set *writefds,
    fd_set errorfds, const struct timespec *timeout,
    const sigset_t *sigmask)
{
    sigset_t oldmask;
    int result;
    pthread_sigmask(SIG_SETMASK, NULL, &oldmask);
    pthread_cleanup_push(cleanup, &oldmask);
    result = pselect(nfds, readfds, writefds, errorfds, timeout, sigmask);
    pthread_cleanup_pop(0);
    return result;
}
