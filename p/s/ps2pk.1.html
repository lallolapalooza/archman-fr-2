PS2PK(1) Manuel des commandes générales PS2PK(1)

NOM

ps2pk - crée un pkfont TeX à partir d'une police PostScript de type 1

SYNTAXE

ps2pk [ -v ] [ -eenc ] [ -Xxres ] [ -Eexpansion ] [ -Sinclinaison ] [ -Ptaillepoint ] [ -Rresbase ] [ -rrapportaspect ] [ -Yyres ] [ -afichierAFM ] [ -mmodename ] type1 [pkfont]

DESCRIPTION

Ce programme rend une police PostScript de type 1 donnée à une taille de point (par défaut 10.0 points) et une résolution (par défaut 300 dpi) spécifiées en un pkfont TeX.

Pour générer le pkfont, ps2pk a besoin d'un fichier de police de type 1 valide (par exemple Utopia-Regular, Utopia-Regula.pfb ou Utopia-Regula.pfa) et de son fichier AFM correspondant (Utopia-Regular.afm) avec les métriques de la police. Le programme accepte à la fois le format binaire de type 1 (Utopia-Regula.pfb) et son équivalent ASCII (Utopia-Regular ou Utopia-Regula.pfa). Pour localiser les fichiers, ps2pk utilise la bibliothèque kpathsea (voir la page d'information sur kpathsea). De plus, les fichiers pfb et pfa sont recherchés dans le répertoire spécifié par la variable d'environnement T1INPUTS, et les fichiers afm sont recherchés dans AFMFONTS, s'ils sont définis (l'indicateur -v indiquera quels noms de fichiers sont recherchés).

Le programme créera un pkfont où les codes de caractères sont dérivés de leurs valeurs définies dans AFM (Adobe Font Metrics). Cela peut être remplacé en spécifiant un fichier d'encodage explicite via l'option -e. Le fichier d'encodage enc doit contenir un encodage PostScript valide contenant des noms PostScript comme /hyphen. Voici un exemple incomplet (voir afm2tfm pour la syntaxe complète) :

% C'est l'encodage EC.
/ECEncoding [          % maintenant 256 caractères suivent
% 0x00
  /grave /acute /circumflex /tilde /dieresis /hungarumlaut
  /ring /caron /breve /macron /dotaccent /cedilla
  /ogonek /quotesinglbase /guilsinglleft /guilsinglright
  (Reste des lignes omises.)
% 0xF0
  /eth /ntilde /ograve /oacute /ocircumflex /otilde
  /odieresis /oe /oslash /ugrave /uacute /ucircumflex
  /udieresis /yacute /thorn /germandbls ] def

Options et arguments :

-afichierAFM
Remplace le nom utilisé pour localiser le fichier AFM.
-eenc
Nom d'un fichier contenant un schéma d'encodage (par défaut - l'encodage nommé dans le fichier AFM est utilisé). Le nom PostScript réel du schéma d'encodage est écrit comme un « spécial » à la fin du pkfont.
-Eextension
Le facteur d'extension (valeur réelle, par défaut 1.0).
-mmodename
Un nom de mode tel qu'utilisé par METAFONT (par défaut « Unknown mode »).
-Ptaillepoint
La taille de point souhaitée (valeur réelle, par défaut 10.0 points).
-Rresbase
La résolution de base souhaitée (valeur entière, par défaut 300 dpi). Si elle diffère de la valeur de xres, la magnification appropriée sera affichée dans les « specials » à la fin du pkfont. Si possible, elle sera exprimée comme un magstep, sinon comme un nombre réel. Par exemple, un pkfont avec un xres de 329, utilisant la résolution de base par défaut de 300, inclura le texte « special » « mag=magstep(0.5) » à la fin de la police.
-rrapportaspect
Le rapport d'aspect souhaité (expression, entierY/entierX, par défaut 300/300). Il sera affiché dans les « specials » à la fin du pkfont. La définition du rapport d'aspect crée une valeur pour yres mais une valeur yres explicite aura la priorité. L'argument doit être entre guillemets s'il y a des espaces autour du `/'.
-Sinclinaison
L'inclinaison (valeur réelle, par défaut 0.0).
-Xxres
La résolution dans la direction X (valeur entière, par défaut 300 dpi).
-Yyres
La résolution dans la direction Y (valeur entière, par défaut la valeur de xres). Si yres diffère de xres, un texte « special » donnant le rapport d'aspect sera écrit à la fin du pkfont.
-v
Indicateur de verbosité. (Indique ce que fait le programme.)
type1
Le nom de la police PostScript de type 1. Le nom du fichier AFM sera construit à partir de ce nom en supprimant l'extension (si fournie) et en ajoutant « .afm ». Le « FontName » PostScript est extrait du fichier AFM et écrit dans un « special » à la fin du pkfont.
[pkfont]
Le nom du pkfont résultant peut être remplacé par ce nom. Le nom par défaut du pkfont est dérivé du nom de base de la police type1, de la taille de point et de xres. Par exemple `ps2pk -P17.28 Utopia-Regular' résultera en `Utopia-Regular17.300pk'. Une valeur explicite pour le nom du pkfont est nécessaire lorsque le nom de la police type1 affiche déjà la taille du point, sinon la valeur taillepoint est concaténée au nom de base du pkfont, ce qui n'est généralement pas souhaité.

Les « specials » PK suivants fournissent une vérification interne des caractéristiques du pkfont, conformément aux recommandations du TeX Working Group sur le TeX Directory Standard (TWG-TDS) :
« fontid=NomPolice », « codingscheme=Encodage », « fontfacebyte », « mag », « mode=(ps2pk)nommode », « pixels-per-inch », et « aspect-ratio » s'il est différent de l'unité.

REMERCIEMENT

Ce programme utilise le logiciel de rendu et d'optimisation Type1 qu'IBM a donné à la X Consortium.
