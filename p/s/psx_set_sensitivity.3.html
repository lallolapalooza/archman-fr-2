LIBPSX(3) Manuel du programmeur Linux LIBPSX(3)

NOM

psx_syscall3, psx_syscall6, psx_set_sensitivity - Sémantiques POSIX pour les appels système

SYNTAXE

#include <sys/psx_syscall.h>
long int psx_syscall3(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3);
long int psx_syscall6(long int syscall_nr,
                      long int arg1, long int arg2, long int arg3,
                      long int arg4, long int arg5, long int arg6);
int psx_set_sensitivity(psx_sensitivity_t sensitivity);
void psx_load_syscalls(long int (**syscall_fn)(long int,
                                    long int, long int, long int),
                       long int (**syscall6_fn)(long int,
                                    long int, long int, long int,
                                    long int, long int, long int));

Tout code utilisant l'une des fonctions ci-dessus peut être lié comme suit :

ld ... -lpsx -lpthread

gcc ... -lpsx -lpthread

Notez que des indicateurs spéciaux sont nécessaires pour que -lcap fonctionne avec des capacités au niveau du processus lorsqu'il est lié avec -lpsx. Notamment, utilisez le fichier d'options pkg-config : gcc ... -lcap $(pkg-config --libs --cflags libpsx) Plus de détails sont disponibles dans la page de manuel cap_get_proc(3).

DESCRIPTION

La bibliothèque libpsx tente de combler une lacune laissée par l'implémentation pthreads(7) sous Linux. Pour être conformes aux threads POSIX, via le mécanisme nptl(7) setxid, glibc maintient des identifiants UID et GID cohérents parmi tous les threads associés au processus actuel. Cependant, d'autres états d'identification ne sont pas pris en charge par cette abstraction. Pour prendre en charge ces attributs de sécurité étendus gérés par le noyau, libpsx fournit une paire de fonctions génériques d'encapsulation d'appels système : psx_syscall3() et psx_syscall6(). Comme le mécanisme nptl:setxid, la coordination de l'état des threads est médiatisée par un signal temps réel. Alors que le mécanisme nptl:setxid utilise signo=33 (qui est caché par glibc sous un SIGRTMIN redéfini), libpsx s'insère dans la pile des gestionnaires SIGSYS. Il fait de grands efforts pour être le premier gestionnaire de ce type mais agit comme un passage pour d'autres utilisations de SIGSYS.

Une macrologie inefficace prend en charge la pseudo-fonction psx_syscall() qui prend 1 à 7 arguments, en fonction des besoins de l'appelant. La macrologie (qui invoque finalement __psx_syscall()) complète l'appel pour utiliser effectivement psx_syscall3() ou psx_syscall6() avec des zéros remplissant les arguments manquants. Bien que son utilisation dans le code source le rende propre en apparence, l'empreinte du code réel est plus importante. Il est conseillé d'utiliser les fonctions plus explicites psx_syscall3() et psx_syscall6() selon les besoins.

psx_set_sensitivity() modifie le comportement des appels système miroir : PSX_IGNORE garantit que les différences sont ignorées (comportement par défaut) ; PSX_WARNING imprime une notification stderr sur la façon dont les résultats diffèrent ; et PSX_ERROR imprime les détails de l'erreur et génère un signal SIGSYS.

psx_load_syscalls() peut être utilisée pour définir des pointeurs de fonction définis par l'appelant pour invoquer des appels système à 3 et 6 arguments. Cette fonction peut être utilisée pour configurer une bibliothèque ou un programme afin de modifier le comportement lorsqu'il est lié à libpsx. En effet, libcap utilise cette fonction de libpsx pour remplacer son API par défaut basée sur les appels système au niveau du thread. Lorsqu'il est lié à libpsx, libcap peut opérer sur tous les threads d'un programme multithread pour fonctionner avec les sémantiques POSIX.

VALEUR DE RETOUR

La valeur de retour des fonctions d'appel système est généralement la valeur retournée par le noyau, ou -1 en cas d'erreur. Dans de tels cas, errno(3) est défini à la valeur d'erreur détaillée. Les fonctions psx_syscall3() et psx_syscall6() tentent un appel système à thread unique et retournent immédiatement en cas d'erreur. Si cet appel réussit, les mêmes appels système sont exécutés à partir d'un gestionnaire de signal sur chacun des autres threads du processus.

CONFORMITÉ

Les besoins de libcap(3) pour les sémantiques POSIX de manipulation des capacités. Vous pouvez en lire plus sur pourquoi c'est nécessaire ici :

https://sites.google.com/site/fullycapable/who-ordered-libpsx

Les versions de libpsx antérieures à 2.72 ne supportaient que pthreads. Depuis libpsx-2.72, la bibliothèque fonctionne avec toutes les implémentations de threads Linux car elle opère au plus bas niveau d'abstraction des threads, les LWP.

SIGNALEMENT DES BOGUES

La bibliothèque libpsx est distribuée depuis https://sites.google.com/site/fullycapable/ où les notes de version peuvent déjà couvrir les problèmes récents. Veuillez signaler les bogues nouvellement découverts via :
