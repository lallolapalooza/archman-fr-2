NOM

ps2eps - convertir des fichiers PostScript en fichiers EPS (Encapsulated PostScript)

SYNTAXE

ps2eps [ -f ] [ -q ] [ -N ] [ -O ] [ -X ] [ -n ] [ -P ] [ -c ] [ -C ] [ -m ] [ -B ] [ -E ] [ -s dimpage ] [ -t offset ] [ -r resolution ] [ -R +|-|^ ] [ -l ] [ -g ] [ -H ] [ -d ] [ -h|--help ] [ -a ] [ -W ] [ -L ] [ -V|--version ] [ -- ] [ psfile1 ] [ psfile2 ] [ ... ]

DESCRIPTION

Cette page de manuel documente ps2eps version 1.70.

ps2eps est un outil (écrit en Perl) pour produire des fichiers Encapsulated PostScript (EPS/EPSF) à partir de documents PostScript habituels d'une seule page. Il calcule des Bounding Boxes correctes pour ces fichiers EPS et filtre certaines séquences de commandes PostScript spéciales qui peuvent produire des résultats erronés sur les imprimantes. Les fichiers EPS sont souvent nécessaires pour inclure des graphiques (redimensionnables) de haute qualité dans des documents TeX/LaTeX (ou même Word). Il peut également être utilisé pour calculer des Bounding Boxes correctes pour les fichiers PDF en utilisant l'option --BBonly. Cependant, il ne peut pas produire de fichier PDF, mais il peut être utilisé conjointement avec pdfcrop.

Sans aucun argument, ps2eps lit depuis l'entrée standard et écrit vers la sortie standard. Si des noms de fichiers sont donnés comme arguments, ils sont traités un par un et les fichiers de sortie sont écrits avec des noms de fichiers se terminant par l'extension .eps. Si les noms de fichiers d'entrée ont l'extension .ps ou .prn, cette extension est remplacée par .eps. Dans tous les autres cas, .eps est ajouté au nom du fichier d'entrée. Veuillez noter que les fichiers PostScript en entrée ne doivent contenir qu'une seule page (vous pouvez éventuellement utiliser psselect du paquet psutils pour extraire une seule page d'un document contenant plusieurs pages).

Si la BoundingBox de sortie semble incorrecte, essayez les options --size ou --ignoreBB. Voir également la section DÉPANNAGE.

OPTIONS

ps2eps suit la syntaxe habituelle des lignes de commande GNU, avec des options longues commençant par deux tirets (`-'). Un résumé des options est inclus ci-dessous.

-h, --help
Affiche le résumé des options.
-V, --version
Affiche la version du programme.
-f, --force
Force l'écrasement des fichiers existants. ps2eps n'écrase pas les fichiers par défaut pour éviter de supprimer accidentellement les fichiers EPS originaux.
-q, --quiet
Opération silencieuse (pas de sortie pendant le traitement des fichiers, sauf erreurs).
-N, --noinsert
N'insère aucun code PostScript. Normalement, quelques instructions PostScript sont ajoutées autour du code PostScript original par ps2eps, ce qui peut être désactivé par cette option.
-O, --preserveorientation
Ne filtre pas le commentaire d'en-tête %%Orientation.
-X, --BBonly
Affiche simplement la ou les bounding boxes résultantes sur la sortie d'erreur standard, aucun fichier de sortie n'est écrit. ps2eps effectue une opération en lecture seule. Ceci est très utile pour calculer les bounding boxes des fichiers PDF. Peut être utilisé avec l'option --quiet pour supprimer les autres sorties et également avec --nohires pour supprimer la sortie de la HiResBoundingBox. Peut être utilisé avec pdfcrop comme suit : pdfcrop --gscmd 'gswrap-ps2eps.sh' file.pdf où gswrap-ps2eps.sh contient quelque chose comme ps2eps -l -X -q $BASH_ARGV
-n, --nofix
N'essaie pas de corriger le code PostScript en filtrant certaines instructions.
-P, --removepreview
Supprime l'image d'aperçu (fichier plus petit, mais plus d'aperçu).
-F, --fixps
Corrige le code PostScript sans condition. Sinon, le filtrage est généralement déclenché par la détection de certains pilotes uniquement.
-c, --comments
Préserve les commentaires de structure du document.
-C, --clip
Insère du code PostScript pour le découpage. Sauf si --nohires est spécifié, la HiResBoundingBox (agrandie de 0.1 point) est utilisée pour le découpage.
-m, --mono
Utilise un bitmap noir et blanc comme base pour le calcul (par défaut : désactivé).
-s, --size=dimpage
où dimpage est une taille de page standard prédéfinie (par exemple, a4,a0,b0,letter,...) ou spécifiée explicitement dans un format dimpage:=XxY[cm|in], où X et Y sont des nombres (les nombres à virgule flottante sont acceptés) suivis des unités centimètre (cm) ou pouce (in), (par défaut : cm). Utilisez --size=list pour lister les pages prédéfinies. Voir aussi la variable d'environnement PS2EPS_SIZE.
-t, --translate=x,y
Spécifie un décalage x,y (peut être négatif) en points PostScript (1/72 ppp) pour le dessin. Cette option peut être requise si votre dessin a des coordonnées négatives, ce qui fait généralement que ghostscript coupe la partie négative de votre image, car il commence à rendre à des coordonnées positives. La sortie résultante sera également décalée.
-r, --resolution=dpi
Spécifie une résolution en dpi (points par pouce) pour le dessin sous ghostscript. La résolution par défaut est de 144 dpi, ce qui est le double du typique 72 dpi. Cette option peut aider s'il y a une résolution dépendante du matériel encodée dans le PostScript, par exemple 600 dpi. Exemple : ps2eps -l -r 600 test.ps
-R, --rotate=direction
Cette option fait pivoter la sortie EPS résultante. Le paramètre direction détermine la direction de la rotation : + signifie +90 degrés (sens horaire), - signifie -90 degrés (sens antihoraire), et ^ signifie 180 degrés (renversé).
-l, --loose
Étend la bounding box serrée d'origine d'un point dans chaque direction.
-B, --ignoreBB
N'utilise pas la bounding box existante comme taille de page pour le rendu.
-E, --ignoreEOF
N'utilise pas %%EOF comme indication de fin de fichier. Sinon, ps2eps suppose que le code PostScript se termine après le dernier commentaire %%EOF, car certains pilotes ajoutent du code binaire "parasite" à la fin, qui est supprimé par ps2eps par défaut.
-g, --gsbbox
Utilise le périphérique de bbox interne de ghostscript au lieu du programme externe bbox. Le périphérique bbox interne de ghostscript génère des valeurs différentes (parfois même incorrectes), donc l'utilisation de bbox fourni devrait être plus robuste. Voir aussi la variable d'environnement PS2EPS_GSBBOX.
-H, --nohires
Ne génère pas de commentaire %%HiResBoundingBox pour la sortie.
-a, --accuracy
Augmente la précision en activant l'anti-aliasing par sous-échantillonnage (peut être plus lent)
-L, --license
Affiche les informations de licence.
-d, --debuggs
Affiche l'appel à ghostscript. Ceci peut être utile pour résoudre les problèmes qui surviennent lors d'un appel à ghostscript.
-W, --warnings
Affiche les avertissements sur la validité du fichier EPS généré. Certaines commandes PostScript ne devraient pas être contenues dans un fichier EPS. Avec cette option activée, ps2eps émettra un avertissement s'il en détecte au moins une.

DEPANNAGE

Basé sur le code source PostScript fourni (dans la plupart des cas généré par un pilote d'imprimante PostScript), il existe de nombreux obstacles ou problèmes potentiels qui peuvent survenir lors de la création de fichiers EPS corrects. Veuillez lire attentivement cette section pour être conscient des pièges courants.

pour déterminer la bonne taille pour ghostscript.

Si vous avez des documents plus grands que la taille par défaut de votre ghostscript (généralement A4 ou US letter), vous devez spécifier explicitement les dimensions de la page en utilisant l'option -s. Sinon, votre EPS pourrait être coupé lors de la pixellisation par ghostscript, ce qui entraînerait un calcul incorrect de la boîte englobante. Vous pouvez passer toutes les tailles de page prédéfinies à -s que ghostscript comprend. Il s'agit actuellement de : 11x17, ledger, legal, letter, lettersmall, archA, archB, archC, archD, archE a0, a1, a2, a3, a4, a5, a6, a7, a8, a9, a10, isob0, isob1, isob2, isob3, isob4, isob5, isob6, b0, b1, b2, b3, b4, b5, c0, c1, c2, c3, c4, c5, c6, jisb0, jisb1, jisb2, jisb3, jisb4, jisb5, jisb6, flsa, flse, halfletter. Malheureusement, toutes les tailles ne sont actuellement disponibles qu'en orientation portrait (pas en paysage).

Par défaut, ps2eps utilise un %%BoundingBox déjà présent dans le fichier source, qui correspond souvent à la taille du format de page physique pour lequel le document a été imprimé. Cependant, vous devez savoir que cette boîte englobante déjà spécifiée peut être incorrecte, ce qui entraîne un fichier .eps mal rogné (ou même inutilisable). ps2eps ne peut faire que ce que ghostscript fait pour rendre le fichier postscript d'origine (bien que ps2eps fonctionne même avec des valeurs négatives et fractionnaires contenues dans la boîte englobante d'origine en utilisant une traduction automatique). Par conséquent, si la boîte englobante donnée est trop petite ou incorrecte de toute façon, vous pouvez ignorer la boîte englobante existante avec l'option -B, ce qui amènera ghostscript à utiliser sa taille par défaut interne (ou utiliser -s). Cependant, si la BoundingBox a des coordonnées négatives, ce qui n'est pas autorisé par la spécification, ps2eps décalera la sortie vers des valeurs positives.

Indice : pour éviter de faire pivoter l'image si vous avez le dessin original en format paysage, vous pouvez utiliser l'option ``Encapsulated Postscript'' dans le pilote d'impression qui devrait générer un fichier EPS (mais avec une boîte englobante de la taille de la feuille !). Mais certains pilotes d'impression Windows dessinent l'image avec un décalage par rapport au bas de la page portrait, de sorte qu'une partie de celle-ci est dessinée en dehors de la page orientée paysage. Dans ce cas, vous devrez spécifier une taille carrée de la page en utilisant la longueur maximale, par exemple 29,7 cm x 29,7 cm pour une page A4.

ROGNER

ou pourquoi une partie de mon texte est-elle supprimée au-dessus du fichier .eps inclus ?

Certains pilotes postscript dessinent un rectangle blanc du coin supérieur gauche de la page au coin inférieur droit de l'objet. Cela peut effacer tout texte, voire la totalité, au-dessus de votre fichier EPS importé/inclus, ce qui est très gênant. Afin d'éviter cela, la plupart des programmes ont une option de rognage pour les fichiers .eps importés (dans LaTeX, vous pouvez utiliser \includegraphics*{}) à cet effet. Si ce n'est malheureusement pas le cas, vous pouvez utiliser l'option -C de ps2eps qui le fera (espérons-le) pour vous. Malheureusement, PScript.dll 5.2 (Windows XP) a introduit un nouveau code Postscript très mal comporté (initclip) qui outrepassera même le rognage externe ! Ainsi, un nouveau filtre a dû être installé dans ps2eps pour le corriger.

Cependant, comme la plupart des programmes rognent directement sur la boîte englobante, vous pouvez toujours perdre quelques pixels de votre image, car la boîte englobante est décrite dans la résolution grossière des points postscript, c'est-à-dire 72 dpi. Afin d'éviter cela, vous pouvez utiliser l'option -l ou l'option -C (pour cette dernière, le rognage par le programme d'importation devrait alors être désactivé) pour permettre une boîte englobante plus grande de 1 point. -C rogne autour d'une boîte englobante agrandie de 1 point et -l agrandit les valeurs de la boîte englobante de 1 point (vous pouvez également combiner les deux options).

FILTRES INCLUS

Certaines séquences postscript, par exemple pour utiliser des fonctionnalités spécifiques de l'imprimante (featurebegin ...), ne fonctionnent pas bien dans un fichier .eps, donc ps2eps essaie de les filtrer. Mais veuillez noter que les filtres pour le code postscript peuvent ne pas fonctionner correctement pour votre pilote d'impression (ps2eps a principalement été testé avec les pilotes d'impression HP et Adobe, bien qu'il puisse fonctionner pour toutes les imprimantes utilisant PScript.dll). Dans ce cas, vous pouvez essayer de désactiver le filtrage en utilisant l'option -n, ou essayer de trouver la mauvaise séquence dans le code postscript et adapter la règle de filtrage dans le script ps2eps (variables $linefilter, $rangefilter_begin, $rangefilter_end ; linefilter est une expression pour filtrer des lignes uniques, rangefilter_... sont des expressions qui filtrent toutes les lignes entre un modèle correspondant à $rangefilter_begin et $rangefilter_end ; envoyez-moi un e-mail avec vos modifications). Cependant, les choses peuvent changer à mesure que les pilotes d'impression (par exemple, PScript.dll) ou le langage postscript évoluent.

Certaines applications ou pilotes génèrent du code postscript avec un code binaire en tête ou en queue, ce qui confused souvent les anciens interpréteurs postscript. ps2eps essaie de supprimer ce code, mais il peut parfois faire une mauvaise supposition quant au début et à la fin du code postscript réel (envoyez-moi un e-mail avec une source postscript zippée, voir la section BUGS).

Les lignes de commentaires ou même les lignes vides sont supprimées (ce qui est le défaut pour réduire la taille des fichiers .eps), ce qui peut corrompre votre sortie. Veuillez vérifier la section suivante pour savoir comment corriger cela. ps2eps supprime les lignes vides et aussi le <CR> (retour chariot ``\r'') à la fin des lignes. Cependant, un code postscript bien formaté donne un indice en utilisant les commentaires ``%%BeginBinary'' ``%%EndBinary''. Lorsque ps2eps détecte ces commentaires, il s'abstient de toute action de filtrage dans les sections binaires marquées.

ps2eps filtre également les commentaires %%Orientation: par défaut (vous pouvez utiliser l'option -O pour désactiver le filtrage), car ghostscript peut faire pivoter les images ``automatiquement'' lors de la génération d'images PDF, ce qui n'est souhaité dans la plupart des cas. Indice : vous pouvez désactiver cette fonctionnalité dans ghostscript sans condition en spécifiant -dAutoRotatePages=/None.

SORTIE CORROMPUE

Certains codes postscript peuvent être corrompus lorsque les lignes de commentaires ou même les lignes vides sont supprimées (ce qui est le défaut pour réduire la taille des fichiers .eps), car ces fichiers peuvent contenir des images encodées qui ont également un % comme premier caractère d'une ligne ou utilisent un commentaire spécial comme délimiteur de fin d'image. Si tel est le cas, utilisez l'option -c pour empêcher le filtrage des commentaires.

COULEUR ET MÉMOIRE

ps2eps prend en charge le postscript couleur, ce qui permet à ghostscript de consommer plus de ressources pour dessiner son bitmap (environ 6 Mo pour une page A4). bbox lit le bitmap ligne par ligne, il consomme donc un minimum de mémoire. Si vous rencontrez des problèmes de consommation de mémoire de ghostscript, vous pouvez utiliser l'option -m pour utiliser une image monochrome. Mais cela entraînera probablement des boîtes englobantes déterminées de manière incorrecte avec des images couleur, car ghostscript doit faire du tramage noir et blanc et peut ainsi supprimer des objets dessinés dans des couleurs claires.

Une autre option en cas de problèmes de mémoire et de temps d'exécution trop longs est d'utiliser le périphérique bbox interne de ghostscript, beaucoup plus efficace en mémoire, en utilisant l'option -g.

VARIABLES D'ENVIRONNEMENT

Veuillez noter qu'une option en ligne de commande a toujours la priorité sur la variable d'environnement associée.

La variable d'environnement PS2EPS_SIZE peut être utilisée pour spécifier une taille de page par défaut et accepter n'importe quel argument que --size accepte. Exemples : export PS2EPS_SIZE=a0 (syntaxe de type bash) ou setenv PS2EPS_SIZE letter (syntaxe csh).

Si la variable d'environnement PS2EPS_GSBBOX est définie, le périphérique bbox interne de ghostscript sera utilisé à la place de la commande externe bbox. Exemples : export PS2EPS_GSBBOX=true (syntaxe de type bash) ou setenv PS2EPS_GSBBOX 1 (syntaxe csh).

EXEMPLES

L'appel habituel est simplement : ps2eps -l fichier

Un appel relativement sûr serait (si votre postscript est plus petit que l'iso b0 [100cm x 141.4cm] et que vous avez un ordinateur rapide avec suffisamment de mémoire) : ps2eps -l -B -s b0 -c -n fichier

Si la sortie n'est pas correcte, essayez : ps2eps -l -B -s b0 -F fichier

POURQUOI ?

D'autres programmes comme ps2epsi ne calculent pas toujours correctement la boîte englobante (car les valeurs sont mises sur la pile postscript qui peut être corrompue par un mauvais code postscript) ou les arrondissent de sorte que le rognage de l'EPS coupe une partie de l'image. ps2eps utilise une résolution double précision de 144 dpi et un arrondi approprié pour obtenir une boîte englobante correcte. Le périphérique bbox interne de ghostscript génère des valeurs différentes (parfois même incorrectes), donc l'utilisation du bbox fourni devrait être plus robuste. Cependant, comme le rognage normal n'a qu'une résolution de 1/72 dpi (point postscript), le processus de rognage peut toujours effacer des parties de votre image EPS. Dans ce cas, veuillez utiliser l'option -l pour ajouter un point supplémentaire d'espace blanc autour de la boîte englobante serrée.

ps2eps(1) - Arch Linux

NOM

ps2eps

convertir PostScript en EPS

SYNTAXE

ps2eps [ options ] [ fichier ]

DESCRIPTION

ps2eps est un script qui convertit les fichiers PostScript en fichiers EPS (Encapsulated PostScript). Il est basé sur Ghostscript et sur l'utilitaire bbox(1). Il prend en charge la détection automatique de la boîte englobante et des options pour la personnaliser.

OPTIONS

-
L'option - lit depuis l'entrée standard.
-d density
Définit la densité pour le rendu PostScript. La valeur par défaut est 72.
-n nom
Définit le nom du fichier EPS de sortie. S'il n'est pas spécifié, il est déduit du nom du fichier d'entrée.
-o
Crée un fichier EPS optimisé. Cela inclut la suppression des objets inutilisés et la réduction de la taille du fichier.
-O
Crée un fichier EPS optimisé et le sauvegarde avec une extension .eps.
-p
Utilise le format de page spécifié dans le fichier PostScript. Si cette option n'est pas utilisée, la taille par défaut est A4.
-q
Mode silencieux. Supprime la sortie de Ghostscript.
-r resolution
Définit la résolution du rendu PostScript en ppp (points par pouce). La valeur par défaut est 1000.
-s
Génère un fichier EPS séparé pour chaque page du fichier PostScript.
-t
Convertit le fichier PostScript en un fichier EPS sans boîte englobante.
-x largeur
Définit la largeur de la boîte englobante.
-y hauteur
Définit la hauteur de la boîte englobante.
-h
Affiche l'aide et quitte.
-v
Affiche la version de ps2eps et quitte.

FICHIER

Le fichier d'entrée PostScript. S'il est omis, ps2eps lit depuis l'entrée standard.

EXEMPLES

Convertir un fichier input.ps en output.eps:

    ps2eps -n output.eps input.ps

Convertir un fichier input.ps en utilisant la taille A4 et l'optimisation:

    ps2eps -o -p input.ps

Convertir un fichier PostScript lu depuis l'entrée standard en output.eps:

    cat input.ps | ps2eps -n output.eps
