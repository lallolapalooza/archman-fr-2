NOM

pstore.conf, pstore.conf.d - Fichier de configuration PStore

SYNTAXE

/etc/systemd/pstore.conf
/run/systemd/pstore.conf
/usr/local/lib/systemd/pstore.conf
/usr/lib/systemd/pstore.conf
/etc/systemd/pstore.conf.d/*.conf
/run/systemd/pstore.conf.d/*.conf
/usr/local/lib/systemd/pstore.conf.d/*.conf
/usr/lib/systemd/pstore.conf.d/*.conf

DESCRIPTION

Ce fichier configure le comportement de systemd-pstore(8), un outil pour archiver le contenu du système de fichiers de stockage persistant, pstore[1].

RÉPERTOIRES DE CONFIGURATION ET PRÉCÉDENCE

La configuration par défaut est définie lors de la compilation, donc une configuration n'est nécessaire que lorsqu'il est nécessaire de s'écarter de ces valeurs par défaut. Le fichier de configuration principal est chargé à partir de l'un des répertoires listés par ordre de priorité, seul le premier fichier trouvé est utilisé : /etc/systemd/, /run/systemd/, /usr/local/lib/systemd/ [2], /usr/lib/systemd/. La version du fournisseur du fichier contient des entrées commentées montrant les valeurs par défaut comme guide pour l'administrateur. Des substitutions locales peuvent également être créées en créant des fichiers drop-in, comme décrit ci-dessous. Le fichier de configuration principal peut également être modifié à cette fin (ou une copie dans /etc/ s'il est distribué sous /usr/), cependant l'utilisation de fichiers drop-in pour la configuration locale est recommandée plutôt que les modifications du fichier de configuration principal.

En plus du fichier de configuration principal, des extraits de configuration drop-in sont lus depuis /usr/lib/systemd/*.conf.d/, /usr/local/lib/systemd/*.conf.d/, et /etc/systemd/*.conf.d/. Ces fichiers drop-in ont une priorité plus élevée et remplacent le fichier de configuration principal. Les fichiers dans les sous-répertoires de configuration *.conf.d/ sont triés par leur nom de fichier par ordre lexicographique, indépendamment du sous-répertoire dans lequel ils résident. Lorsque plusieurs fichiers spécifient la même option, pour les options qui n'acceptent qu'une seule valeur, l'entrée dans le fichier trié en dernier prend la prééminence, et pour les options qui acceptent une liste de valeurs, les entrées sont collectées au fur et à mesure de leur apparition dans les fichiers triés.

Lorsque des paquets ont besoin de personnaliser la configuration, ils peuvent installer des fichiers drop-in sous /usr/. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur. Des fichiers drop-in doivent être utilisés pour remplacer les fichiers drop-in des paquets, car le fichier de configuration principal a une priorité plus faible. Il est recommandé de préfixer tous les noms de fichiers dans ces sous-répertoires avec un nombre à deux chiffres et un tiret, pour simplifier l'ordre. Cela définit également un concept de priorités de fichiers drop-in pour permettre aux fournisseurs d'OS de distribuer des fichiers drop-in dans une plage spécifique inférieure à la plage utilisée par les utilisateurs. Cela devrait réduire le risque que les fichiers drop-in des paquets remplacent accidentellement les fichiers drop-in définis par les utilisateurs. Il est recommandé d'utiliser la plage 10-40 pour les fichiers drop-in dans /usr/ et la plage 60-90 pour les fichiers drop-in dans /etc/ et /run/, afin de s'assurer que les fichiers drop-in locaux et transitoires ont la priorité sur les fichiers drop-in distribués par le fournisseur de l'OS.

Pour désactiver un fichier de configuration fourni par le fournisseur, la méthode recommandée consiste à placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du fournisseur.

OPTIONS

Toutes les options sont configurées dans la section [PStore] :

Storage=

Contrôle où archiver (c'est-à-dire copier) les fichiers du système de fichiers pstore. L'une des valeurs : « none », « external », et « journal ». Lorsque « none », l'outil se termine sans traiter les fichiers du système de fichiers pstore. Lorsque « external » (par défaut), les fichiers sont archivés dans /var/lib/systemd/pstore/ et enregistrés dans le journal. Lorsque « journal », le contenu des fichiers pstore est uniquement enregistré dans le journal.

Ajouté dans la version 243.

Unlink=

Contrôle si les fichiers sont supprimés de pstore après traitement. Accepte une valeur booléenne. Lorsque true, un fichier pstore est supprimé de pstore une fois qu'il a été archivé (sur disque ou dans le journal). Lorsque false, le traitement des fichiers pstore se déroule normalement, mais les fichiers restent dans pstore. La valeur par défaut est true afin de maintenir pstore dans un état presque vide, de sorte que pstore dispose d'un espace de stockage disponible pour le prochain événement d'erreur du noyau.

Ajouté dans la version 243.

Utiliser

systemd-analyze cat-config systemd/pstore.conf

pour afficher la configuration complète.
