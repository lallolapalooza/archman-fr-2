NOM

profile-sync-daemon - Lie et synchronise les profils de navigateur en RAM (tmpfs) réduisant ainsi les appels disque et accélérant les navigateurs.

DESCRIPTION

Profile-sync-daemon (psd) est un petit pseudo-démon conçu pour gérer le ou les profils de navigateur dans tmpfs et pour les synchroniser périodiquement vers le disque physique (HDD/SSD). Ceci est accompli par une utilisation innovante de rsync pour maintenir la synchronisation entre une copie tmpfs et la sauvegarde liée au média du ou des profils de navigateur. De plus, psd dispose de plusieurs fonctionnalités de récupération après crash.

Objectifs de conception de psd :

  • Expérience utilisateur complètement transparente.
  • Usure réduite des disques physiques (particulièrement les SSD).
  • Vitesse.

Étant donné que le ou les profils, le cache du navigateur*, etc. sont déplacés dans tmpfs (disque RAM), les E/S correspondantes associées à l'utilisation du navigateur sont également redirigées du disque physique vers la RAM, réduisant ainsi l'usure du disque physique et améliorant la réactivité du navigateur.

*Notez que certains navigateurs comme Chrome/Chromium, Firefox (depuis v21), Midori et Rekonq gardent effectivement leurs répertoires de cache séparés de leur répertoire de profil de navigateur. Il n'appartient pas à profile-sync-daemon de modifier ce comportement ; les utilisateurs souhaitant déplacer ce répertoire peuvent se référer à l'URL suivante pour plusieurs solutions de contournement : https://wiki.archlinux.org/index.php/Chromium_Tips_and_Tweaks#Cache_in_tmpfs

MISE EN PLACE

$XDG_CONFIG_HOME/psd/psd.conf (désigné ci-après comme « le fichier de configuration ») contient tous les paramètres gérés par l'utilisateur.

NOTE : les modifications apportées au fichier de configuration pendant que psd est actif ne seront appliquées qu'après le redémarrage du service.

  • Activez éventuellement l'utilisation d'overlayfs pour améliorer la vitesse de synchronisation et pour utiliser une empreinte mémoire plus petite. Faites-le dans la variable USE_OVERLAYFS. L'utilisateur n'aura pas besoin de droits sudo sans mot de passe pour /usr/bin/psd-overlay-helper pour utiliser cette option et le noyau doit supporter overlayfs version 22 ou supérieure. Voir la FAQ ci-dessous pour des détails supplémentaires.
  • Faites éventuellement resynchroniser psd sur le système de fichiers avant un appel de veille. Cela peut aider dans le cas où le système ne se réveille pas correctement. Faites-le dans la variable USE_SUSPSYNC.
  • Définissez éventuellement quels navigateurs doivent être gérés dans le tableau BROWSERS. S'il n'y en a aucun de défini, la valeur par défaut est tous les navigateurs détectés.
  • Désactivez éventuellement l'utilisation des instantanés de récupération après crash (non recommandé). Faites-le dans la variable USE_BACKUPS.
  • Définissez éventuellement le nombre d'instantanés de récupération après crash à conserver. Faites-le dans la variable BACKUP_LIMIT.

NOTE : occasionnellement, des mises à jour/changements sont apportés au fichier de configuration par défaut (/usr/share/psd/psd.conf) en amont. La copie utilisateur ($XDG_CONFIG_HOME/psd/psd.conf) devra être comparée avec celui-ci.

DÉMARRER ET ARRÊTER PSD

Psd est livré avec un service utilisateur systemd pour le démarrer ou l'arrêter (psd.service). De plus, un timer de resynchronisation fourni exécutera une resynchronisation horaire de tmpfs vers le disque. Le timer de resynchronisation est démarré automatiquement avec psd.service, il n'est donc pas nécessaire de démarrer le timer ; démarrez seulement psd.service.

 $ systemctl --user [option] psd.service
Options disponibles : start stop enable disable

MODE NETTOYAGE

Le mode nettoyage supprimera TOUS les instantanés de récupération qui se sont accumulés. Ne l'exécutez que lorsque vous êtes sûr qu'ils ne sont plus nécessaires.

 $ psd c
 Profile-sync-daemon v6.39
 Suppression de 2 répertoires de récupération après crash pour le profil /home/facade/.config/chromium
  /home/facade/.config/chromium-backup-crashrecovery-20200423_171359
  /home/facade/.config/chromium-backup-crashrecovery-20200424_112204

Faites une entrée correspondante dans le tableau BROWSERS du fichier de configuration. Le support pour ceux-ci n'est pas garanti.

NOTE SUR LES PROFILS LIÉS PAR SYMBOLIQUE

Actuellement, psd ne prend pas en charge les profils liés par symbolique et refusera de synchroniser si l'un est détecté. Par exemple, votre profil firefox est ~/.mozilla/firefox/f8cv8bfu.default mais vous avez déplacé ce répertoire vers /foo/bar/f8cv8bfu.default et l'avez remplacé par un lien symbolique :

 $ ls -l ~/.mozilla/firefox
 lrwxrwxrwx 1 facade users  26 Oct  1 17:02 f8cv8bfu.default -> /foo/bar/f8cv8bfu.default
L'exécution de psd en mode prévisualisation se terminera par une erreur vous en informant : 
 $ psd p
 Attention !
 /home/facade/.mozilla/firefox/f8cv8bfu.default semble être un lien symbolique mais ceux-ci ne sont pas supportés.
 Veuillez faire du profil de navigateur un répertoire actif et réessayer. Sortie.
Une solution appropriée pour firefox est de simplement éditer ~/.mozilla/firefox/profiles.ini en y définissant le chemin canonique. Il faut également ajuster l'indicateur IsRelative comme suit : 
 [Profile0]
 Name=default
 IsRelative=0
 Path=/foo/bar/f8cv8bfu.default
D'autres solutions peuvent exister pour d'autres navigateurs, mais les documenter toutes ici sort du cadre.

DISTRIBUTIONS SUPPORTÉES

Puisque psd n'est qu'un script bash avec un service systemd, il devrait fonctionner sur n'importe quelle saveur de Linux exécutant systemd. Plusieurs distributions fournissent un paquet officiel ou une option maintenue par les utilisateurs pour installer psd. On peut également construire psd à partir des sources. Voir le site web officiel pour les paquets disponibles, les dépendances et les instructions d'installation

FAQ

Q1 : Qu'est-ce que le mode overlayfs ?

R1 : Overlayfs est un système de fichiers union simple intégré dans le noyau Linux version 3.18.0. Lorsqu'il est utilisé avec psd, une empreinte mémoire réduite et des opérations de synchronisation plus rapides peuvent être réalisées. La magie réside dans la façon dont le montage overlay n'écrit que les données sortantes

qu'il a changé plutôt que le profil entier. Les mêmes fonctionnalités de récupération que psd utilise dans son mode par défaut sont également actives lorsqu'il s'exécute en mode overlayfs.

Voir l'exemple dans la section MODE PRÉVISUALISATION ci-dessus qui montre un système utilisant overlayfs pour illustrer les économies de mémoire typiques. Notez le rapport « taille overlayfs » comparé au rapport total « taille profil » pour chaque profil. Sachez que ces chiffres changeront en fonction de la quantité de nouvelles données écrites dans le profil, mais dans les cas d'utilisation courants, la taille overlayfs sera toujours inférieure à la taille du profil.

Q2 : Comment activer le mode overlayfs ?

R2 : Tout d'abord, assurez-vous que psd n'est pas actif, sinon toute modification du fichier de configuration sera ignorée jusqu'à ce qu'il soit redémarré. Le mode overlayfs est activé avec la variable USE_OVERLAYFS= qui doit être définie sur « yes » dans le fichier de configuration. Psd détectera automatiquement la version d'overlayfs disponible pour le noyau s'il est configuré pour en utiliser une. Il est recommandé d'exécuter psd en mode prévisualisation pour vérifier que le système peut effectivement utiliser overlayfs.

Les utilisateurs souhaitant utiliser le mode overlayfs DOIVENT avoir des droits sudo sans invite de mot de passe pour /usr/bin/psd-overlay-helper ou des droits sudo globaux sans invite de mot de passe. Si l'utilisateur n'a pas les droits globaux, ajoutez la ligne suivante à /etc/sudoers après toute autre ligne définissant l'accès sudo. Il est recommandé d'utiliser /usr/bin/visudo en tant que root pour configurer cela :

 foo ALL=(ALL) NOPASSWD: /usr/bin/psd-overlay-helper
Q3 : Pourquoi ai-je un autre répertoire de profil de navigateur « foo-back-ovfs » lorsque j'active overlayfs ?

R3 : La façon dont overlayfs fonctionne est de monter une copie de base en lecture seule (appelée répertoire inférieur) du profil, et de gérer les nouvelles données par-dessus. Afin d'éviter la resynchronisation sur le système de fichiers en lecture seule, une copie est utilisée à la place. Utiliser overlayfs est donc un compromis : des temps de synchronisation initiaux plus rapides et une utilisation de la mémoire réduite contre de l'espace disque dans le répertoire personnel.

Q4 : J'ai besoin de plus de mémoire pour accueillir mon/mes profil(s) dans /run/user/xxxx. Comment puis-je en allouer plus ?

R4 : La manière standard de contrôler la taille de /run/user/ est la directive RuntimeDirectorySize dans logind.conf (voir la page man de logind.conf pour plus de détails). Par défaut, 10 % de la mémoire physique est utilisée, mais on peut l'augmenter sans risque. N'oubliez pas que tmpfs ne consomme que ce qui est réellement utilisé ; le nombre spécifié ici n'est qu'un maximum autorisé.

Q5 : Mon système a planté pour une raison quelconque et psd n'a pas synchronisé en retour. Que dois-je faire ?

R5 : La sauvegarde « dernière bonne » du/des profil(s) du navigateur devrait être le système de fichiers. Au redémarrage de psd (lors d'un redémarrage, par exemple), une vérification est effectuée pour voir si le lien symbolique vers la copie tmpfs du profil est invalide. S'il est invalide, psd sauvegardera la « dernière bonne » sauvegarde avant de la réintégrer. C'est davantage une vérification de cohérence pour s'assurer que psd n'a causé aucun dommage et que toute perte de données était due à autre chose.

Q6 : Où puis-je trouver cette sauvegarde ?

R6 : Cela dépend du navigateur. La sauvegarde sera située dans le même répertoire que le profil du navigateur et contiendra un horodatage correspondant à l'heure à laquelle la récupération a eu lieu. Par exemple, une sauvegarde chromium sera ~/.config/chromium-backup-crashrecovery-20130912_153310 -- bien sûr, le suffixe date_heure sera différent.

Q7 : Comment puis-je restaurer la sauvegarde ?

R7 : Suivez ces étapes :

1.
Arrêter psd.
2.
Déplacer la copie « défectueuse » du profil vers une sauvegarde (ne supprimez rien aveuglément).
3.
Copier le répertoire de sauvegarde vers le nom attendu par le navigateur.

Exemple avec chromium :

1.
systemctl --user stop psd.service
2.
mv ~/.config/chromium ~/.config/chromium-bad
3.
cp -a ~/.config/chromium-backup-crashrecovery-20130912_153310 ~/.config/chromium

À ce stade, lancez chromium qui utilisera la sauvegarde copiée à l'instant. Si tout va bien, il est sûr de supprimer ~/.config/chromium-bad et la sauvegarde. N'oubliez pas que pour démarrer psd, aucun navigateur ne doit être ouvert (sinon psd refusera de démarrer).

Q8 : psd peut-il supprimer les sauvegardes automatiquement ?

R8 : Oui, exécutez psd avec le commutateur « clean » pour supprimer les sauvegardes.
