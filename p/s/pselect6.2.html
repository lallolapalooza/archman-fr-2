select(2) Manuel des appels système select(2)

NOM

select, pselect, FD_CLR, FD_ISSET, FD_SET, FD_ZERO, fd_set - multiplexage d'E/S synchrone

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/select.h>
typedef /* ... */ fd_set;
int select(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           struct timeval *_Nullable restrict timeout);
void FD_CLR(int fd, fd_set *set);
int  FD_ISSET(int fd, const fd_set *set);
void FD_SET(int fd, fd_set *set);
void FD_ZERO(fd_set *set);
int pselect(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           const struct timespec *_Nullable restrict timeout,
           const sigset_t *_Nullable restrict sigmask);

pselect():

    _POSIX_C_SOURCE >= 200112L

DESCRIPTION

AVERTISSEMENT: select() ne peut surveiller que les descripteurs de fichiers dont le numéro est inférieur à FD_SETSIZE (1024) — une limite déraisonnablement basse pour de nombreuses applications modernes — et cette limitation ne changera pas. Toutes les applications modernes devraient plutôt utiliser poll(2) ou epoll(7), qui ne souffrent pas de cette limitation.

select() permet à un programme de surveiller plusieurs descripteurs de fichiers, en attendant qu'un ou plusieurs descripteurs de fichiers deviennent "prêts" pour une classe d'opération d'E/S (par exemple, une entrée possible). Un descripteur de fichier est considéré comme prêt si une opération d'E/S correspondante (par exemple, read(2), ou une write(2) suffisamment courte) peut être effectuée sans bloquer.

fd_set

Un type de structure qui peut représenter un ensemble de descripteurs de fichiers. Selon POSIX, le nombre maximum de descripteurs de fichiers dans une structure fd_set est la valeur de la macro FD_SETSIZE.

Ensembles de descripteurs de fichiers

Les arguments principaux de select() sont trois "ensembles" de descripteurs de fichiers (déclarés avec le type fd_set), qui permettent à l'appelant d'attendre trois classes d'événements sur l'ensemble spécifié de descripteurs de fichiers. Chacun des arguments fd_set peut être spécifié comme NULL si aucun descripteur de fichier ne doit être surveillé pour la classe d'événements correspondante.

Attention : Au retour, chacun des ensembles de descripteurs de fichiers est modifié sur place pour indiquer quels descripteurs de fichiers sont actuellement "prêts". Ainsi, si select() est utilisé dans une boucle, les ensembles doivent être réinitialisés avant chaque appel.

Le contenu d'un ensemble de descripteurs de fichiers peut être manipulé à l'aide des macros suivantes :

FD_ZERO()
Cette macro efface (retire tous les descripteurs de fichiers de) set. Elle devrait être utilisée comme première étape dans l'initialisation d'un ensemble de descripteurs de fichiers.
FD_SET()
Cette macro ajoute le descripteur de fichier fd à set. L'ajout d'un descripteur de fichier déjà présent dans l'ensemble n'a aucun effet et ne génère pas d'erreur.
FD_CLR()
Cette macro retire le descripteur de fichier fd de set. Le retrait d'un descripteur de fichier non présent dans l'ensemble n'a aucun effet et ne génère pas d'erreur.
FD_ISSET()
select() modifie le contenu des ensembles selon les règles décrites ci-dessous. Après avoir appelé select(), la macro FD_ISSET() peut être utilisée pour vérifier si un descripteur de fichier est toujours présent dans un ensemble. FD_ISSET() renvoie une valeur non nulle si le descripteur de fichier fd est présent dans set, et zéro sinon.

Arguments

Les arguments de select() sont les suivants :

readfds
Les descripteurs de fichiers dans cet ensemble sont surveillés pour déterminer s'ils sont prêts pour la lecture. Un descripteur de fichier est prêt pour la lecture si une opération de lecture ne bloquera pas ; en particulier, un descripteur de fichier est également prêt en cas de fin de fichier.
Après le retour de select(), readfds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts pour la lecture.
writefds
Les descripteurs de fichiers dans cet ensemble sont surveillés pour déterminer s'ils sont prêts pour l'écriture. Un descripteur de fichier est prêt pour l'écriture si une opération d'écriture ne bloquera pas. Cependant, même si un descripteur de fichier indique qu'il est accessible en écriture, une écriture importante peut toujours bloquer.
Après le retour de select(), writefds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts pour l'écriture.
exceptfds
Les descripteurs de fichiers dans cet ensemble sont surveillés pour les "conditions exceptionnelles". Pour des exemples de conditions exceptionnelles, voir la discussion sur POLLPRI dans poll(2).
Après le retour de select(), exceptfds sera vidé de tous les descripteurs de fichiers sauf ceux pour lesquels une condition exceptionnelle s'est produite.
nfds
Cet argument doit être défini sur le descripteur de fichier numéroté le plus élevé dans l'un des trois ensembles, plus 1. Les descripteurs de fichiers indiqués dans chaque ensemble sont vérifiés, jusqu'à cette limite (mais voir BUGS).
timeout
L'argument timeout est une structure timeval (affichée ci-dessous) qui spécifie l'intervalle pendant lequel select() doit bloquer en attendant qu'un descripteur de fichier devienne prêt. L'appel bloquera jusqu'à ce que :
•
un descripteur de fichier devienne prêt ;
•
l'appel soit interrompu par un gestionnaire de signaux ; ou
•
le délai d'attente expire.
Notez que l'intervalle timeout sera arrondi à la granularité de l'horloge système, et les délais de planification du noyau signifient que l'intervalle de blocage peut dépasser de manière minime.
Si les deux champs de la structure timeval sont à zéro, alors select() retourne immédiatement. (Ceci est utile pour le sondage.)
Si timeout est spécifié comme NULL, select() bloque indéfiniment en attendant qu'un descripteur de fichier devienne prêt.

pselect()

L'appel système pselect() permet à une application d'attendre en toute sécurité jusqu'à ce qu'un descripteur de fichier devienne prêt ou jusqu'à ce qu'un signal soit capturé.

Le fonctionnement de select() et pselect() est identique, à l'exception de ces trois différences :

•
select() utilise un délai d'attente qui est une struct timeval (avec secondes et microsecondes), tandis que pselect() utilise une struct timespec (avec secondes et nanosecondes).
•
select() peut mettre à jour l'argument timeout pour indiquer le temps restant. pselect() ne modifie pas cet argument.
•
select() n'a pas d'argument sigmask, et se comporte comme pselect() appelé avec un sigmask NULL.

sigmask est un pointeur vers un masque de signaux (voir sigprocmask(2)) ; s'il n'est pas NULL, alors pselect() remplace d'abord le masque de signaux actuel par celui

À l'exception de la différence de précision de l'argument timeout, l'appel pselect() suivant :


ready = pselect(nfds, &readfds, &writefds, &exceptfds,
                timeout, &sigmask);

est équivalent à l'exécution *atomique* des appels suivants :


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = select(nfds, &readfds, &writefds, &exceptfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

La raison pour laquelle pselect() est nécessaire est que si l'on veut attendre soit un signal, soit qu'un descripteur de fichier devienne prêt, un test atomique est nécessaire pour éviter les conditions de concurrence. (Supposons que le gestionnaire de signaux définisse un drapeau global et revienne. Un test de ce drapeau global suivi d'un appel à select() pourrait alors rester bloqué indéfiniment si le signal arrive juste après le test mais juste avant l'appel. Par contraste, pselect() permet de bloquer d'abord les signaux, de traiter les signaux reçus, puis d'appeler pselect() avec le sigmask désiré, évitant ainsi la concurrence.)

Le timeout

L'argument timeout pour select() est une structure du type suivant :


struct timeval {
    time_t      tv_sec;         /* secondes */
    suseconds_t tv_usec;        /* microsecondes */
};

L'argument correspondant pour pselect() est une structure timespec(3).

Sous Linux, select() modifie timeout pour refléter la durée non dormie ; la plupart des autres implémentations ne le font pas. (POSIX.1 autorise l'un ou l'autre comportement.) Cela pose des problèmes à la fois lorsque le code Linux qui lit timeout est porté sur d'autres systèmes d'exploitation, et lorsque du code est porté sur Linux qui réutilise une struct timeval pour plusieurs appels à select() dans une boucle sans la réinitialiser. Considérer timeout comme indéfini après le retour de select().

VALEUR DE RETOUR

En cas de succès, select() et pselect() retournent le nombre de descripteurs de fichiers contenus dans les trois ensembles de descripteurs retournés (c'est-à-dire le nombre total de bits définis dans readfds, writefds, exceptfds). La valeur de retour peut être zéro si le délai d'attente a expiré avant que des descripteurs de fichiers ne soient prêts.

En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur ; les ensembles de descripteurs de fichiers sont inchangés et timeout devient indéfini.

ERREURS

EBADF
Un descripteur de fichier invalide a été donné dans l'un des ensembles. (Peut-être un descripteur de fichier déjà fermé, ou un sur lequel une erreur s'est produite.) Cependant, voir BUGS.
EINTR
Un signal a été capturé ; voir signal(7).
EINVAL
nfds est négatif ou dépasse la limite de ressources RLIMIT_NOFILE (voir getrlimit(2)).
EINVAL
La valeur contenue dans timeout est invalide.
ENOMEM
Impossible d'allouer de la mémoire pour les tables internes.

VERSIONS

Sur certains autres systèmes UNIX, select() peut échouer avec l'erreur EAGAIN si le système ne parvient pas à allouer de ressources internes au noyau, plutôt que ENOMEM comme le fait Linux. POSIX spécifie cette erreur pour poll(2), mais pas pour select(). Les programmes portables peuvent souhaiter vérifier EAGAIN et boucler, tout comme avec EINTR.

NORMES

NOTES

L'en-tête suivant fournit également le type fd_set : <sys/time.h>.

Un fd_set est un tampon de taille fixe. L'exécution de FD_CLR() ou FD_SET() avec une valeur de fd négative ou égale ou supérieure à FD_SETSIZE entraînera un comportement indéfini. De plus, POSIX exige que fd soit un descripteur de fichier valide.

Le fonctionnement de select() et pselect() n'est pas affecté par le drapeau O_NONBLOCK.

L'astuce du pipe interne

Sur les systèmes qui n'ont pas pselect(), un piège de signal fiable (et plus portable) peut être réalisé en utilisant l'astuce du pipe interne. Dans cette technique, un gestionnaire de signal écrit un octet dans un pipe dont l'autre extrémité est surveillée par select() dans le programme principal. (Pour éviter de potentiellement bloquer lors de l'écriture dans un pipe potentiellement plein ou de la lecture d'un pipe potentiellement vide, les E/S non bloquantes sont utilisées lors de la lecture et de l'écriture dans le pipe.)

Émulation de usleep(3)

Avant l'avènement de usleep(3), certains codes utilisaient un appel à select() avec tous les trois ensembles vides, nfds à zéro, et un timeout non NULL comme moyen assez portable de dormir avec une précision inférieure à la seconde.

Correspondance entre les notifications de select() et poll()

Dans le code source du noyau Linux, on trouve les définitions suivantes qui montrent la correspondance entre les notifications de lecture, d'écriture et de condition exceptionnelle de select() et les notifications d'événement fournies par poll(2) et epoll(7) :


#define POLLIN_SET  (EPOLLRDNORM | EPOLLRDBAND | EPOLLIN |
                     EPOLLHUP | EPOLLERR)
                   /* Prêt pour la lecture */
#define POLLOUT_SET (EPOLLWRBAND | EPOLLWRNORM | EPOLLOUT |
                     EPOLLERR)
                   /* Prêt pour l'écriture */
#define POLLEX_SET  (EPOLLPRI)
                   /* Condition exceptionnelle */

Applications multithreads

Si un descripteur de fichier surveillé par select() est fermé dans un autre thread, le résultat est indéfini. Sur certains systèmes UNIX, select() se débloque et revient, avec une indication que le descripteur de fichier est prêt (une opération d'E/S ultérieure échouera probablement avec une erreur, à moins qu'un autre processus ne rouvre le descripteur de fichier entre le moment où select() est revenu et le moment où l'opération d'E/S est effectuée). Sous Linux (et certains autres systèmes), la fermeture du descripteur de fichier dans un autre thread n'a aucun effet sur select(). En résumé, toute application qui repose sur un comportement particulier dans ce scénario doit être considérée comme défectueuse.

Différences bibliothèque C/noyau

Le noyau Linux permet des ensembles de descripteurs de fichiers de taille arbitraire, déterminant la longueur des ensembles à vérifier à partir de la valeur de nfds. Cependant, dans l'implémentation glibc, le type fd_set a une taille fixe. Voir aussi BUGS.

L'interface pselect() décrite dans cette page est implémentée par glibc. L'appel système Linux sous-jacent est nommé pselect6(). Cet appel système a un comportement quelque peu différent de la fonction d'enrobage de glibc.

L'appel système Linux pselect6() modifie son argument timeout. Cependant, la fonction d'enrobage de glibc masque ce comportement en utilisant une variable locale pour l'argument de délai d'attente qui est passé à l'appel système. Ainsi, la fonction pselect() de glibc ne modifie pas son argument timeout ; c'est le comportement requis par POSIX.1-2001.

Le dernier argument de l'appel système pselect6() n'est pas un pointeur sigset_t *, mais plutôt une structure de la forme :


struct {
    const kernel_sigset_t *ss;   /* Pointeur vers l'ensemble de signaux */
    size_t ss_len;               /* Taille (en octets) de l'objet
                                    pointé par 'ss' */
};

Cela permet à l'appel système d'obtenir à la fois un pointeur vers l'ensemble de signaux et sa taille, tout en tenant compte du fait que la plupart des architectures supportent un maximum de 6 arguments pour un appel système. Voir sigprocmask(2) pour une discussion sur la différence entre la notion de noyau et celle de libc de l'ensemble de signaux.

Détails historiques glibc

glibc 2.0 fournissait une version incorrecte de pselect() qui ne prenait pas d'argument sigmask.

De glibc 2.1 à glibc 2.2.1, il fallait définir _GNU_SOURCE pour obtenir la déclaration de pselect() à partir de <sys/select.h>.

NOM

select, pselect, select, pselect — observation des descripteurs de fichiers pour l'attente d'E/S

LIBRARY

librairie C standard (libc, -lc)

SYNOPSIS

#include <sys/select.h>

    /* Les types fd_set, timeval, et les macros FD_ZERO, FD_SET,
       FD_CLR, FD_ISSET sont définis dans <sys/select.h> */

    int select(int nfds, fd_set *restrict readfds,
               fd_set *restrict writefds, fd_set *restrict exceptfds,
               struct timeval *restrict timeout);

    #define _GNU_SOURCE             /* Voir feature_test_macros(7) */
    #include <sys/select.h>

    int pselect(int nfds, fd_set *restrict readfds,
                fd_set *restrict writefds, fd_set *restrict exceptfds,
                const struct timespec *restrict timeout,
                const sigset_t *restrict sigmask);

DESCRIPTION

Les appels système select() et pselect() inspectent un ensemble de descripteurs de fichiers pour vérifier s'ils sont prêts pour la lecture, l'écriture ou une condition exceptionnelle. Ils peuvent être utilisés pour synchroniser un programme avec des opérations d'E/S.

Le paramètre nfds est le nombre de descripteurs de fichiers à tester. L'examen est effectué à partir des nfds premiers descripteurs de fichiers (c'est-à-dire les descripteurs de fichiers de 0 à nfds−1).

Les paramètres readfds, writefds, et exceptfds spécifient les ensembles de descripteurs de fichiers à surveiller pour la lecture, l'écriture ou les conditions exceptionnelles. Si un pointeur est NULL, cet ensemble n'est pas surveillé.

Le type fd_set est une structure opaque utilisée pour représenter un ensemble de descripteurs de fichiers. Les macros suivantes sont fournies pour manipuler ces ensembles :

  • FD_ZERO(fdset):
    Initialise l'ensemble fdset à l'ensemble vide.
  • FD_SET(fd, fdset):
    Ajoute le descripteur de fichier fd à l'ensemble fdset.
  • FD_CLR(fd, fdset):
    Supprime le descripteur de fichier fd de l'ensemble fdset.
  • FD_ISSET(fd, fdset):
    Test si le descripteur de fichier fd est présent dans l'ensemble fdset. Retourne une valeur non nulle si c'est le cas, sinon zéro.

Le paramètre timeout spécifie la durée pendant laquelle select() doit attendre que l'un des descripteurs de fichiers surveillés devienne prêt. Si timeout est NULL, select() attend indéfiniment. Sinon, timeout pointe vers une structure timeval qui spécifie un délai en secondes et en microsecondes.

Si timeout pointe vers une structure timeval dont les champs tv_sec et tv_usec sont tous deux à zéro, alors select() retourne immédiatement sans bloquer. Sinon, select() bloque jusqu'à ce que l'un des descripteurs de fichiers devienne prêt, ou jusqu'à ce que le délai imparti soit écoulé.

Si select() retourne car le temps imparti est écoulé, les structures fd_set sont laissées inchangées. Si select() retourne car un ou plusieurs descripteurs de fichiers sont prêts, les structures fd_set sont modifiées pour indiquer lesquels sont prêts.

L'appel système pselect() est similaire à select(), mais il permet également de spécifier un ensemble de signaux à masquer pendant l'attente. Le paramètre sigmask est un pointeur vers un sigset_t. Si sigmask n'est pas NULL, l'ensemble de signaux spécifié est atomiquement restauré à l'état avant l'appel après le retour de pselect(). Si timeout est NULL, pselect() attend indéfiniment.

VALEUR DES RETOURS

En cas de succès, select() et pselect() retournent le nombre total de descripteurs de fichiers prêts dans tous les ensembles, ou zéro si le temps imparti est écoulé. En cas d'erreur, ils retournent -1 et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
Un descripteur de fichier dans l'un des ensembles n'est pas valide, ou est ouvert sans les autorisations appropriées.
EINTR
Un signal a interrompu l'appel système.
EINVAL
nfds est négatif, ou timeout pointe vers une structure timeval invalide.
ENOMEM
Mémoire insuffisante pour allouer des ressources internes.

VERSIONS

pselect() a été ajouté au noyau Linux dans la version 2.6.10.

STANDARDS

pselect() est conforme à POSIX.1-2008.

HISTORIQUE

pselect() a été ajouté dans le noyau Linux 2.6.10.

NOTES

La taille des ensembles fd_set est limitée par la définition de FD_SETSIZE, qui est généralement de 1024. Pour surveiller un nombre plus important de descripteurs de fichiers, il est recommandé d'utiliser poll(2) ou epoll(7).

L'implémentation de fd_set comme arguments de valeur-résultat est une conception qui est évitée dans poll(2) et epoll(7).

Selon POSIX, select() doit vérifier tous les descripteurs de fichiers spécifiés dans les trois ensembles de descripteurs de fichiers, jusqu'à la limite nfds−1. Cependant, l'implémentation actuelle ignore tout descripteur de fichier dans ces ensembles qui est supérieur au nombre maximum de descripteurs de fichiers actuellement ouverts par le processus. Selon POSIX, tout descripteur de fichier spécifié dans l'un des ensembles qui est supérieur à ceux ouverts doit entraîner l'erreur EBADF.

À partir de glibc 2.1, glibc fournissait une émulation de pselect() implémentée à l'aide de sigprocmask(2) et select(). Cette implémentation restait vulnérable à la condition de concurrence que pselect() était conçu pour prévenir. Les versions modernes de glibc utilisent l'appel système pselect() (sans concurrence) sur les noyaux où il est fourni.

Sous Linux, select() peut signaler un descripteur de fichier de socket comme « prêt pour la lecture », tout en bloquant une lecture ultérieure. Cela pourrait par exemple se produire lorsque des données sont arrivées mais, après examen, ont une somme de contrôle incorrecte et sont rejetées. Il peut y avoir d'autres circonstances dans lesquelles un descripteur de fichier est signalé à tort comme prêt. Il peut donc être plus sûr d'utiliser O_NONBLOCK sur les sockets qui ne devraient pas bloquer.

Sous Linux, select() modifie également timeout si l'appel est interrompu par un gestionnaire de signaux (c'est-à-dire, le retour d'erreur EINTR). Cela n'est pas autorisé par POSIX.1. L'appel système pselect() sous Linux a le même comportement, mais l'enveloppe glibc masque ce comportement en copiant en interne timeout dans une variable locale et en passant cette variable à l'appel système.

EXEMPLES

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Surveiller stdin (fd 0) pour voir s'il y a des entrées.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Attendre jusqu'à cinq secondes.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Ne pas se fier à la valeur de tv maintenant ! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Des données sont disponibles maintenant.\n");
        /* FD_ISSET(0, &rfds) sera vrai.  */
    else
        printf("Aucune donnée dans les cinq secondes.\n");
    exit(EXIT_SUCCESS);
}
