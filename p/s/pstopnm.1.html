NOM

pstopnm - convertir un fichier PostScript en image PNM

SYNOPIS

pstopnm

[-stdout]

[-forceplain]

[-help]

[-dpi=dpi]

[-xsize=pixels] [-ysize=pixels]

[-xborder=frac] [-yborder=frac] [-landscape]

[-portrait]

[-nocrop]

[-pbm

|-pgm

|-ppm]

[-llx=s] [-lly=s] [-urx=s] [-ury=s]

[-verbose]

[-xmax=pixels] [-ymax=pixels]

[-textalphabits={1,2,4}]

fichier_ps[.ps]

UTILISATION DES OPTIONS

L'abréviation unique minimale de l'option est acceptable. Vous pouvez utiliser des doubles tirets au lieu de tirets simples pour désigner les options. Vous pouvez utiliser un espace blanc à la place du signe égal pour séparer un nom d'option de sa valeur.

DESCRIPTION

Ce programme fait partie de Netpbm(1)

pstopnm lit un fichier PostScript en entrée et produit des images PBM, PGM ou PPM en sortie. Ce programme utilise simplement GhostScript pour rendre un fichier PostScript avec ses pilotes de périphériques PNM. Si vous n'avez pas GhostScript installé ou si la version que vous avez installée n'a pas été compilée avec les pilotes de périphériques PNM pertinents, pstopnm échouera. Vous pouvez vérifier si vous avez le bon environnement en lançant la commande gs --help . Si elle répond et liste sous 'Available Devices' pbm, pbmraw, pgm, pgmraw, pnm, pnmraw, ppm, ou ppmraw, vous êtes prêt.

Il est important de comprendre que pstopnm est un convertisseur de format de fichier image Netpbm uniquement au sens le plus large du terme, car PostScript est loin d'être un format de fichier image. Ce que pstopnm est réellement, c'est un moteur de rendu PostScript - un générateur d'images. Un endroit où vous remarquerez la différence est là où vous vous attendez à ce que pstopnm | pnmtops soit idempotent (ce qui n'est pas le cas). Des détails sur ce type de conversion sont fournis ci-dessous.

pstopnm utilise la valeur de la variable d'environnement GHOSTSCRIPT comme nom de fichier pour le programme Ghostscript. Si GHOSTSCRIPT n'est pas définie, pstopnm recherche dans votre variable PATH un fichier régulier nommé gs. S'il n'en trouve pas, il suppose que Ghostscript se trouve dans le fichier /usr/bin/gs.

pstopnm n'utilise pas les bibliothèques Netpbm pour générer les fichiers de sortie, il peut donc ne pas être entièrement cohérent avec la plupart des programmes Netpbm.

fichier_ps[.ps] est le nom du fichier d'entrée. pstopnm ajoutera ps à la fin du nom que vous spécifiez s'il n'existe aucun fichier portant exactement le nom que vous spécifiez, mais un fichier avec l'extension .ps existe. Pour l'entrée standard, utilisez - ou ne fournissez aucun argument.

Si vous utilisez l'option -stdout ou si votre entrée provient de l'entrée standard, pstopnm génère les images de toutes les pages sous forme de fichier multi-images vers la sortie standard. Sinon, pstopnm crée un fichier pour chaque page de l'entrée PostScript. Les fichiers sont nommés comme suit : Si le fichier d'entrée s'appelle fichier_ps.ps, le nom des fichiers sera fichier_ps001.ppm, fichier_ps002.ppm, etc. Le suffixe du type de fichier est .ppm, .pgm, ou .pbm, selon le type de sortie que vous choisissez avec vos options d'invocation. Si le nom du fichier d'entrée ne se termine pas par .ps, le nom de fichier complet est utilisé dans le nom du fichier de sortie. Par exemple, si le fichier d'entrée s'appelle fichier_ps.old, le nom du fichier de sortie sera fichier_ps.old001.ppm, etc.

Notez que la sélection du fichier de sortie est incohérente avec la plupart des programmes Netpbm, car elle ne se fait pas par défaut sur la sortie standard. Ceci est dû à des raisons historiques, basées sur le fait que les formats Netpbm ne prévoyaient pas toujours une séquence d'images dans un seul fichier.

Lorsque votre entrée provient de l'entrée standard, vous pouvez fournir plusieurs documents PostScript encapsulés, l'un après l'autre, et pstopnm convertit chaque document et le place dans le flux de sortie standard sous forme d'image. Mais si votre entrée provient d'un fichier nommé, pstopnm s'attend à ce que le fichier soit un fichier PostScript encapsulé, ce qui signifie qu'il ne contient qu'un seul document PostScript encapsulé. Si le fichier contient plusieurs documents concaténés, pstopnm ignore tous les documents sauf le premier. Cette distinction n'existe pas pour les entrées PostScript non-EPSF — pstopnm génère une image de sortie pour chaque page de l'entrée, que l'entrée provienne de l'entrée standard ou d'un fichier nommé.

Notez que vous pouvez générer les deux types de fichiers — EPSF concaténé et non-EPSF multi-pages — avec pnmtops, en sélectionnant avec l'option -setpage.

Chaque image de sortie contient une zone rectangulaire de la page à laquelle elle se rapporte. Voir la section Dimensions pour plus de détails sur quelle partie de l'image d'entrée va dans l'image de sortie, sa taille en sortie, et les bordures et marges dans l'image de sortie.

Il a été signalé que sur certaines entrées PostScript Version 1, Ghostscript, et donc pstopnm, ne produit aucune sortie. Pour résoudre ce problème, vous pouvez convertir le fichier en PostScript Version 3 avec le programme ps2ps. Il est rapporté que le programme pstops ne fonctionne pas.

Dimensions

Cette section décrit quelle partie de l'image d'entrée est utilisée dans la sortie et les dimensions de la sortie, y compris les bordures et l'arrière-plan.

Notez qu'une image de sortie est associée à une seule page d'entrée.

pstopnm commence par prendre une zone rectangulaire de la page d'entrée. C'est ce qu'on appelle l'image sujet.

pstopnm peut ajouter des bordures à l'image sujet pour former ce qu'on appelle l'image sujet bordée.

pstopnm place l'image sujet bordée au centre de l'image de sortie et rogne les bords si nécessaire pour s'adapter à la taille calculée de l'image de sortie.

L'emplacement de l'image sujet sur la page d'entrée PostScript est défini par quatre nombres, les coordonnées du coin inférieur gauche et du coin supérieur droit en x et y. Ces coordonnées sont généralement spécifiées par l'instruction BoundingBox DSC (un commentaire PostScript) dans le fichier PostScript, mais elles peuvent être remplacées par l'utilisateur en spécifiant une ou plusieurs des options suivantes : -llx, -lly, -urx, et -ury.

La présence et l'épaisseur d'une bordure à ajouter à l'image sujet pour former l'image sujet bordée sont contrôlées par les options -xborder et -yborder. Si pstopnm ne trouve pas d'instruction BoundingBox dans l'entrée, et que vous ne spécifiez pas les coordonnées de la zone d'image sur la ligne de commande, pstopnm utilise les valeurs par défaut. Si votre entrée provient de l'entrée standard, pstopnm n'utilise pas les valeurs BoundingBox (en raison de la difficulté technique d'extraire ces informations tout en alimentant le fichier à Ghostscript), vous devez donc soit spécifier les coordonnées de la zone d'image, soit prendre les valeurs par défaut.

La taille de l'image de sortie est une chose confuse. Dans un fichier PostScript, les choses ont des dimensions spatiales. Par exemple, une ligne particulière peut mesurer 3 centimètres de long. Une imprimante PostScript est censée imprimer la ligne de 3 centimètres de long, en utilisant autant de pixels que nécessaire, sans tenir compte de la taille de la feuille de papier sur laquelle elle imprime. Dans une image PNM, en revanche, il n'y a pas de dimension spatiale ; il n'y a que des pixels. Vous pourriez avoir une ligne de 100 pixels de long, mais l'image PNM ne dit rien sur la longueur que cette ligne devrait avoir sur une page imprimée.

pstopnm remplit le rôle d'une imprimante PostScript. L'image PNM est une page imprimée virtuelle. pstopnm doit déterminer combien de pixels il utilisera dans l'image de sortie pour représenter un pouce de l'image d'entrée, ce qui est la « résolution du périphérique de sortie ». Pensez-y comme le nombre de points par pouce que l'imprimante virtuelle imprime sur la page virtuelle.

La chose la plus simple est que vous disiez à pstopnm exactement quelle résolution de périphérique de sortie utiliser, à l'aide de l'option -dpi. Si vous dites par exemple -dpi=300 et que l'image sujet bordée fait 2 pouces par 3 pouces, la sortie PNM sera de 600 pixels par 900 pixels. En utilisant cette méthode, la résolution du périphérique de sortie doit être la même dans les deux directions.

Dans le cas improbable où vous souhaiteriez des résolutions de sortie différentes dans les deux directions, vous pourriez utiliser -xsize et -ysize pour cela. Dans l'exemple ci-dessus, si vous changez -ysize en 900, un pixel représente toujours 1/600 de pouce horizontalement, mais 1/300 de pouce verticalement.

Si vous spécifiez l'un des paramètres -xsize et -ysize et pas l'autre, pstopnm ajuste l'autre pour que la résolution du périphérique de sortie soit la même dans les deux directions.

Les 'x' et 'y' de -xsize et -ysize font référence à l'image imprimée sur la page, et non à la page elle-même. Ainsi, si pstopnm l'imprime en orientation paysage, 'x' se rapporterait à la direction verticale sur la page, c'est-à-dire la direction verticale de l'image PNM de sortie.

Si vous spécifiez -nocrop, pstopnm utilise les valeurs de -xmax et -ymax pour les dimensions de l'image de sortie. Celles-ci sont par défaut de 612 et 792 pixels, respectivement.

Le cas final, le défaut, est celui où vous ne spécifiez aucune option de taille ou de résolution, ni -nocrop. C'est le cas le plus compliqué. Dans ce cas, pstopnm choisit d'abord une résolution de périphérique de sortie qui générerait le nombre de pixels indiqué par -xmax et -ymax à partir de l'image du sujet bordée. Ensuite, en fonction de cette résolution, il choisit une taille d'image de sortie juste assez grande pour accueillir l'image du sujet (sans bordures). Rappelez-vous (ci-dessus) que pstopnm rogne les bords de l'image du sujet bordée pour qu'elle corresponde à la taille de sortie calculée.

Limitations de Ghostscript

Les tests effectués en 2013 avec Ghostscript 8.71 indiquent que le pilote de sortie pgmraw de Ghostscript présente une erreur d'arrondi qui provoque de légères variations des valeurs de pixels, ce qui fait que pstopnm génère une sortie incorrecte lorsque vous avez une entrée Postscript monochrome. Mais avec une entrée Postscript couleur, pstopnm utilise le pilote de sortie ppmraw de Ghostscript et génère une sortie PPM correcte.

Notes d'utilisation

Il y a de bons conseils sur la conversion vers et depuis Postscript, dans le document Postscript File Conversions (1)
par Andrew T. Young.

Conversion réversible

Si vous essayez de faire l'équivalent de l'opération naïve pnmtops | pstopnm, les étapes suivantes le feront :


    $ pnmtops -nocenter -equalpixels -dpi 72 -noturn testimg.ppm > testimg.ps
    $ pstopnm -xborder=0 -yborder=0 -xsize=XSIZE -ysize=YSIZE \
        -portrait -stdout -quiet testimg.ps >testimg2.ppm

XSIZE et YSIZE ci-dessus sont les dimensions de l'image, que vous pouvez obtenir à partir de testimg.ps comme dans l'exemple suivant (les commandes grep, awk et echo servent uniquement à démontrer comment les autres commandes fonctionnent - vous ne les utiliseriez pas dans un programme).


    $ grep "BoundingBox" testimg.ps
    %%BoundingBox: 0 0 227 149
    $ awk  '/%%BoundingBox/ {print $4,$5}' testimg.ps
     227 149
 
    $ xysize=$(awk  '/%%BoundingBox/ {print "-xsize="$4,"-ysize="$5}' testimg.ps)
    $ echo $xysize
     -xsize=227 -ysize=149
    $ pstopnm -xborder=0 -yborder=0 $xysize -portrait ... testimg.ps

Notez que les bogues de Ghostscript peuvent empêcher une conversion réversible parfaite.

OPTIONS

-forceplain

force le fichier de sortie à être au format brut (texte). Sinon, il est au format brut (binaire). Voir pbm(5) , etc.
-llx=bx
sélectionne bx comme coordonnée x du coin inférieur gauche (en pouces) sur la page d'entrée Postscript de l'image du sujet. Voir la section Dimensions .
-lly=by
sélectionne by comme coordonnée y du coin inférieur gauche (en pouces) sur la page d'entrée Postscript de l'image du sujet. Voir la section Dimensions .
-landscape
rend l'image en orientation paysage.

Si vous ne spécifiez ni -portrait ni -landscape, pstopnm choisit l'orientation qui correspond le mieux à l'image sur la page de sortie.

Paysage signifie imprimé de côté sur la page, pas imprimé dans le sens de la longueur. Ce sont des choses différentes si le bord long de la page est le dessus.

-portrait
rend l'image en orientation portrait.

Voir -landscape.

-nocrop
cette option fait en sorte que pstopnm donne à l'image de sortie exactement les dimensions de l'image du sujet bordée. Par défaut, pstopnm donne à l'image de sortie les dimensions spécifiées par -xmax et -ymax. Voir la section Dimensions .
-pbm
-pgm
-ppm
sélectionne le format du fichier de sortie. Par défaut, tous les fichiers sont rendus en PPM.
-stdout
envoie la sortie vers la sortie standard au lieu de fichiers réguliers, un par page (voir la description des fichiers de sortie ci-dessus). Utilisez pnmsplit pour extraire les pages individuelles de la sortie standard.
-urx=tx
sélectionne tx comme coordonnée x du coin supérieur droit (en pouces) sur la page d'entrée Postscript de l'image du sujet. Voir la section Dimensions .
-ury=ty
sélectionne ty comme coordonnée y du coin supérieur droit (en pouces) sur la page d'entrée Postscript de l'image du sujet. Voir la section Dimensions .
-verbose
affiche les informations de traitement sur stdout.
-xborder=frac
spécifie que les bordures gauche et droite ajoutées à l'image du sujet doivent être frac fois la largeur de l'image du sujet. La valeur par défaut est 0.1. Voir la section Dimensions .
-xmax=xmax
spécifie que l'image de sortie doit faire xmax pixels de large. La valeur par défaut est 612. Voir la section Dimensions .
-xsize=xsize
spécifie que l'image de sortie doit faire xsize pixels de large. Voir la section Dimensions .
-yborder=frac
spécifie que les bordures supérieure et inférieure ajoutées à l'image du sujet doivent être frac fois la hauteur de l'image du sujet. La valeur par défaut est 0.1. Voir la section Dimensions .
-ymax=ymax
spécifie que l'image de sortie doit faire ymax pixels de haut. La valeur par défaut est 792. Voir la section Dimensions .
-ysize=ysize
spécifie que l'image de sortie doit faire ymax pixels de haut. Voir la section Dimensions .
-dpi=dpi
spécifie la résolution du périphérique de sortie, en points par pouce, de l'imprimante Postscript que pstopnm simule. C'est le nombre de pixels PNM que pstopnm génère pour chaque pouce d'image. Voir la section Dimensions .

Cette option a été ajoutée dans Netpbm 10.21 (mars 2004).

-textalphabits={1,2,4}
ceci contrôle l'anti-crénelage par sous-échantillonnage du texte. L'anti-crénelage est une forme de lissage qui élimine les bords dentelés des caractères. L'anti-crénelage par sous-échantillonnage est un type d'anti-crénelage qui utilise des sous-pixels dans une boîte, et la valeur de cette option est la taille de cette boîte. 4 donne le meilleur rendu visuel, tandis que 1 n'applique aucun anti-crénelage. Des nombres plus petits font que pnmtops utilise moins de temps CPU.

Pstopnm utilise le paramètre TextAlphaBits de Ghostscript pour cela.

La valeur par défaut est 4.

Cette option a été ajoutée dans Netpbm 10.53 (décembre 2010). Les versions plus anciennes de pstopnm n'effectuent aucun anti-crénelage.

LIMITATIONS

Le programme produira des résultats incorrects avec les fichiers Postscript qui initialisent la matrice de transformation actuelle. Dans ces cas, la translation et la rotation de page n'auront aucun effet. Pour rendre ces fichiers, les options suivantes sont probablement les meilleures :

    pstopnm -xborder 0 -yborder 0 -portrait -nocrop file.ps

Des options supplémentaires peuvent être nécessaires si le document doit être rendu sur un support différent du papier de format lettre.
