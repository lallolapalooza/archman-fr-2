select(2) Manuel des appels système select(2)

NOM

select, pselect, FD_CLR, FD_ISSET, FD_SET, FD_ZERO, fd_set - multiplexage d'E/S synchrone

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/select.h>
typedef /* ... */ fd_set;
int select(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           struct timeval *_Nullable restrict timeout);
void FD_CLR(int fd, fd_set *set);
int  FD_ISSET(int fd, const fd_set *set);
void FD_SET(int fd, fd_set *set);
void FD_ZERO(fd_set *set);
int pselect(int nfds, fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           const struct timespec *_Nullable restrict timeout,
           const sigset_t *_Nullable restrict sigmask);
Exigences pour les macros de test de fonctionnalité dans glibc (voir feature_test_macros(7)) :

pselect():

    _POSIX_C_SOURCE >= 200112L

DESCRIPTION

ATTENTION : select() ne peut surveiller que les descripteurs de fichiers dont le numéro est inférieur à FD_SETSIZE (1024) — une limite déraisonnablement basse pour de nombreuses applications modernes — et cette limite ne changera pas. Toutes les applications modernes devraient utiliser à la place poll(2) ou epoll(7), qui ne souffrent pas de cette limitation.

select() permet à un programme de surveiller plusieurs descripteurs de fichiers, en attendant qu'un ou plusieurs des descripteurs de fichiers deviennent "prêts" pour une certaine classe d'opération d'E/S (par exemple, une entrée possible). Un descripteur de fichier est considéré comme prêt s'il est possible d'effectuer une opération d'E/S correspondante (par exemple, read(2), ou un write(2) suffisamment petit) sans bloquer.

fd_set

Un type de structure qui peut représenter un ensemble de descripteurs de fichiers. Selon POSIX, le nombre maximum de descripteurs de fichiers dans une structure fd_set est la valeur de la macro FD_SETSIZE.

Ensembles de descripteurs de fichiers

Les arguments principaux de select() sont trois "ensembles" de descripteurs de fichiers (déclarés avec le type fd_set), qui permettent à l'appelant d'attendre trois classes d'événements sur l'ensemble spécifié de descripteurs de fichiers. Chacun des arguments fd_set peut être spécifié comme NULL s'il n'y a pas de descripteurs de fichiers à surveiller pour la classe d'événements correspondante.

Attention : Au retour, chacun des ensembles de descripteurs de fichiers est modifié sur place pour indiquer quels descripteurs de fichiers sont actuellement "prêts". Ainsi, si vous utilisez select() dans une boucle, les ensembles *doivent être réinitialisés* avant chaque appel.

Le contenu d'un ensemble de descripteurs de fichiers peut être manipulé à l'aide des macros suivantes :

FD_ZERO()
Cette macro efface (supprime tous les descripteurs de fichiers de) set. Elle devrait être utilisée comme première étape lors de l'initialisation d'un ensemble de descripteurs de fichiers.
FD_SET()
Cette macro ajoute le descripteur de fichier fd à set. L'ajout d'un descripteur de fichier déjà présent dans l'ensemble est une opération nulle et ne produit pas d'erreur.
FD_CLR()
Cette macro supprime le descripteur de fichier fd de set. La suppression d'un descripteur de fichier qui n'est pas présent dans l'ensemble est une opération nulle et ne produit pas d'erreur.
FD_ISSET()
select() modifie le contenu des ensembles selon les règles décrites ci-dessous. Après avoir appelé select(), la macro FD_ISSET() peut être utilisée pour tester si un descripteur de fichier est toujours présent dans un ensemble. FD_ISSET() retourne une valeur non nulle si le descripteur de fichier fd est présent dans set, et zéro sinon.

Arguments

Les arguments de select() sont les suivants :

readfds
Les descripteurs de fichiers de cet ensemble sont surveillés pour savoir s'ils sont prêts en lecture. Un descripteur de fichier est prêt en lecture si une opération de lecture ne bloque pas ; en particulier, un descripteur de fichier est également prêt en cas de fin de fichier.
Après le retour de select(), readfds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts en lecture.
writefds
Les descripteurs de fichiers de cet ensemble sont surveillés pour savoir s'ils sont prêts en écriture. Un descripteur de fichier est prêt en écriture si une opération d'écriture ne bloque pas. Cependant, même si un descripteur de fichier indique être prêt en écriture, une opération d'écriture importante peut toujours bloquer.
Après le retour de select(), writefds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts en écriture.
exceptfds
Les descripteurs de fichiers de cet ensemble sont surveillés pour les "conditions exceptionnelles". Pour des exemples de conditions exceptionnelles, voir la discussion de POLLPRI dans poll(2).
Après le retour de select(), exceptfds sera vidé de tous les descripteurs de fichiers sauf ceux pour lesquels une condition exceptionnelle s'est produite.
nfds
Cet argument doit être défini sur le descripteur de fichier le plus élevé dans l'un des trois ensembles, plus 1. Les descripteurs de fichiers indiqués dans chaque ensemble sont vérifiés, jusqu'à cette limite (mais voir BUGS).
timeout
L'argument timeout est une structure timeval (illustrée ci-dessous) qui spécifie l'intervalle pendant lequel select() doit bloquer en attendant qu'un descripteur de fichier devienne prêt. L'appel bloquera jusqu'à ce que :
•
un descripteur de fichier devienne prêt ;
•
l'appel soit interrompu par un gestionnaire de signal ; ou
•
le délai d'attente expire.
Notez que l'intervalle timeout sera arrondi à la granularité de l'horloge système, et que les délais de planification du noyau signifient que l'intervalle de blocage peut dépasser légèrement.
Si les deux champs de la structure timeval sont à zéro, alors select() retourne immédiatement. (Ceci est utile pour sonder.)
Si timeout est spécifié comme NULL, select() bloque indéfiniment en attendant qu'un descripteur de fichier devienne prêt.

pselect()

L'appel système pselect() permet à une application d'attendre en toute sécurité jusqu'à ce qu'un descripteur de fichier devienne prêt ou jusqu'à ce qu'un signal soit intercepté.

Le comportement de select() et pselect() est identique, à l'exception de ces trois différences :

•
select() utilise un délai d'attente qui est un struct timeval (avec secondes et microsecondes), tandis que pselect() utilise un struct timespec (avec secondes et nanosecondes).
•
select() peut mettre à jour l'argument timeout pour indiquer combien de temps il restait. pselect() ne modifie pas cet argument.
•
select() n'a pas d'argument sigmask, et se comporte comme pselect() appelé avec NULL sigmask.

sigmask est un pointeur vers un masque de signaux (voir sigprocmask(2)) ; s'il n'est pas NULL, alors pselect() remplace d'abord le masque de signaux courant par celui

NAME

select, pselect, pselect6 - synchronous I/O multiplexing

SYNOPSIS

#include <sys/select.h>

int select(int nfds, fd_set *restrict readfds,
           fd_set *restrict writefds, fd_set *restrict exceptfds,
           struct timeval *restrict timeout);

int pselect(int nfds, fd_set *restrict readfds,
            fd_set *restrict writefds, fd_set *restrict exceptfds,
            const struct timespec *restrict timeout,
            const sigset_t *restrict sigmask);

long pselect6(int nfds, fd_set *restrict readfds,
              fd_set *restrict writefds, fd_set *restrict exceptfds,
              struct timespec *restrict timeout,
              void *restrict sigmask_info);

DESCRIPTION

The select() function monitors a set of file descriptors to see if any of them are ready for reading, writing, or have an exceptional condition pending. The file descriptors to be monitored are specified by the arguments readfds, writefds, and exceptfds. nfds is the highest-numbered file descriptor in any of the three sets, plus one.

The readfds argument points to a set of file descriptors for which we wish to know if data is available for reading. The writefds argument points to a set of file descriptors for which we wish to know if we can write without blocking. The exceptfds argument points to a set of file descriptors for which we wish to know about exceptional conditions.

If any of the sets is NULL, then select() does not monitor that set. Otherwise, each set is a pointer to a fd_set structure. On return from select(), the set points to the subset of the original file descriptors that are ready. If the set is not NULL and no file descriptors in the set are ready for the requested event, the set will be empty upon return.

The timeout argument specifies the amount of time that select() should block waiting for a file descriptor to become ready. If timeout is NULL, select() blocks indefinitely until at least one file descriptor becomes ready. Otherwise, timeout points to a struct timeval structure, which specifies a ceiling for the amount of time that select() will wait. If the time specified by timeout elapses before any file descriptors are ready, select() returns with a return value of 0. The struct timeval is described in The timeout.

The pselect() function is an extension that is useful for multi-threaded applications or applications that handle signals. It allows the calling application to block the delivery of signals during the execution of select(), and it also allows the use of a higher-precision timeout.

The pselect() call works as follows:

  • It first sets the process's signal mask to the value pointed to by sigmask (using `pthread_sigmask(SIG_SETMASK, sigmask, NULL)`).
  • Then it performs the `select(nfds, readfds, writefds, exceptfds, timeout)` call.
  • Finally, it restores the process's signal mask to the original value that was in effect before the `pselect` call.

(If sigmask is NULL, the signal mask is not modified during the pselect() call.)

The timeout argument for pselect() is a pointer to a timespec(3) structure, which allows for higher precision than select().

Other than the difference in the precision of the timeout argument, the following pselect() call:


ready = pselect(nfds, &readfds, &writefds, &exceptfds,
                timeout, &sigmask);

is equivalent to *atomically* executing the following calls:


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = select(nfds, &readfds, &writefds, &exceptfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

The reason that pselect() is needed is that if one wants to wait for either a signal or for a file descriptor to become ready, then an atomic test is needed to prevent race conditions. (Suppose the signal handler sets a global flag and returns. Then a test of this global flag followed by a call of select() could hang indefinitely if the signal arrived just after the test but just before the call. By contrast, pselect() allows one to first block signals, handle the signals that have come in, then call pselect() with the desired sigmask, avoiding the race.)

The timeout

The timeout argument for select() is a structure of the following type:


struct timeval {
    time_t      tv_sec;         /* seconds */
    suseconds_t tv_usec;        /* microseconds */
};

The corresponding argument for pselect() is a timespec(3) structure.

On Linux, select() modifies timeout to reflect the amount of time not slept; most other implementations do not do this. (POSIX.1 permits either behavior.) This causes problems both when Linux code which reads timeout is ported to other operating systems, and when code is ported to Linux that reuses a struct timeval for multiple select()s in a loop without reinitializing it. Consider timeout to be undefined after select() returns.

RETURN VALUE

On success, select() and pselect() return the number of file descriptors contained in the three returned descriptor sets (that is, the total number of bits that are set in readfds, writefds, exceptfds). The return value may be zero if the timeout expired before any file descriptors became ready.

On error, -1 is returned, and errno is set to indicate the error; the file descriptor sets are unmodified, and timeout becomes undefined.

ERRORS

EBADF
An invalid file descriptor was given in one of the sets. (Perhaps a file descriptor that was already closed, or one on which an error has occurred.) However, see BUGS.
EINTR
A signal was caught; see signal(7).
EINVAL
nfds is negative or exceeds the RLIMIT_NOFILE resource limit (see getrlimit(2)).
EINVAL
The value contained within timeout is invalid.
ENOMEM
Unable to allocate memory for internal tables.

VERSIONS

On some other UNIX systems, select() can fail with the error EAGAIN if the system fails to allocate kernel-internal resources, rather than ENOMEM as Linux does. POSIX specifies this error for poll(2), but not for select(). Portable programs may wish to check for EAGAIN and loop, just as with EINTR.

STANDARDS

POSIX.1-2024.

NOTES

The following header also provides the fd_set type: <sys/time.h>.

An fd_set is a fixed size buffer. Executing FD_CLR() or FD_SET() with a value of fd that is negative or is equal to or larger than FD_SETSIZE will result in undefined behavior. Moreover, POSIX requires fd to be a valid file descriptor.

The operation of select() and pselect() is not affected by the O_NONBLOCK flag.

The self-pipe trick

On systems that lack pselect(), reliable (and more portable) signal trapping can be achieved using the self-pipe trick. In this technique, a signal handler writes a byte to a pipe whose other end is monitored by select() in the main program. (To avoid possibly blocking when writing to a pipe that may be full or reading from a pipe that may be empty, nonblocking I/O is used when reading from and writing to the pipe.)

Emulating usleep(3)

Before the advent of usleep(3), some code employed a call to select() with all three sets empty, nfds zero, and a non-NULL timeout as a fairly portable way to sleep with subsecond precision.

Correspondence between select() and poll() notifications

Within the Linux kernel source, we find the following definitions which show the correspondence between the readable, writable, and exceptional condition notifications of select() and the event notifications provided by poll(2) and epoll(7):


#define POLLIN_SET  (EPOLLRDNORM | EPOLLRDBAND | EPOLLIN |
                     EPOLLHUP | EPOLLERR)
                   /* Ready for reading */
#define POLLOUT_SET (EPOLLWRBAND | EPOLLWRNORM | EPOLLOUT |
                     EPOLLERR)
                   /* Ready for writing */
#define POLLEX_SET  (EPOLLPRI)
                   /* Exceptional condition */

Multithreaded applications

If a file descriptor being monitored by select() is closed in another thread, the result is unspecified. On some UNIX systems, select() unblocks and returns, with an indication that the file descriptor is ready (a subsequent I/O operation will likely fail with an error, unless another process reopens the file descriptor between the time select() returned and the I/O operation is performed). On Linux (and some other systems), closing the file descriptor in another thread has no effect on select(). In summary, any application that relies on a particular behavior in this scenario must be considered buggy.

C library/kernel differences

The Linux kernel allows file descriptor sets of arbitrary size, determining the length of the sets to be checked from the value of nfds. However, in the glibc implementation, the fd_set type is fixed in size. See also BUGS.

The pselect() interface described in this page is implemented by glibc. The underlying Linux system call is named pselect6(). This system call has somewhat different behavior from the glibc wrapper function.

The Linux pselect6() system call modifies its timeout argument. However, the glibc wrapper function hides this behavior by using a local variable for the timeout argument that is passed to the system call. Thus, the glibc pselect() function does not modify its timeout argument; this is the behavior required by POSIX.1-2001.

The final argument of the pselect6() system call is not a sigset_t * pointer, but is instead a structure of the form:


struct {
    const kernel_sigset_t *ss;   /* Pointer to signal set */
    size_t ss_len;               /* Size (in bytes) of object
                                    pointed to by 'ss' */
};

This allows the system call to obtain both a pointer to the signal set and its size, while allowing for the fact that most architectures support a maximum of 6 arguments to a system call. See sigprocmask(2) for a discussion of the difference between the kernel and libc notion of the signal set.

Historical glibc details

glibc 2.0 provided an incorrect version of pselect() that did not take a sigmask argument.

From glibc 2.1 to glibc 2.2.1, one must define _GNU_SOURCE in order to obtain the declaration of pselect() from <sys/select.h>.

BUGS

POSIX allows an implementation to define an upper limit, advertised via the constant FD_SETSIZE, on the number of file descriptors that can be held in an fd_set. On Linux, this limit is currently 1024. This limit can be changed by editing <linux/posix_types.h>. If you need to support more file descriptors than this, use poll(2) or epoll(7).

The exceptfds argument is not supported on all systems. (It is supported on Linux and on BSD-derived systems.)

It is not possible to implement a correct pselect() using only the select() and `pthread_sigmask` calls, because there is a race condition between the two calls. This is the reason why pselect() is implemented as a single atomic call.

The value of nfds is only a hint to the kernel. The kernel will check all file descriptors in the sets regardless of the value of nfds. If nfds is larger than the actual highest file descriptor plus one, then the behavior is undefined.

The behavior of select() and pselect() when passed a file descriptor referring to a regular file is implementation-defined. POSIX requires that these functions work on streams, and regular files are not streams. On Linux, select() will always report that a regular file is ready for reading if any data is present, and ready for writing if the file has been opened in write mode. This means that a call to select() on a regular file will return immediately. This behavior is not portable.

The glibc implementation of pselect() (prior to glibc 2.1) had a bug where it would return EINTR if a signal was caught during the internal call to select(), even if the signal mask was changed correctly. The correct behavior is to return the number of ready file descriptors or 0 on timeout.

The behavior of select() when one of the file descriptor sets is modified by another thread is undefined. Specifically, if a file descriptor is closed in another thread while select() is blocked, the behavior is unpredictable.

NOTES

The range of file descriptors that can be specified in a file descriptor set. The Linux kernel imposes no fixed limit, but the glibc implementation makes fd_set a fixed-size type, with FD_SETSIZE defined as 1024, and the FD_*() macros operating according to that limit. To monitor file descriptors greater than 1023, use poll(2) or epoll(7) instead.

The implementation of the fd_set arguments as value-result arguments is a design error that is avoided in poll(2) and epoll(7).

According to POSIX, select() should check all specified file descriptors in the three file descriptor sets, up to the limit nfds-1. However, the current implementation ignores any file descriptor in these sets that is greater than the maximum file descriptor number that the process currently has open. According to POSIX, any such file descriptor that is specified in one of the sets should result in the error EBADF.

Starting with glibc 2.1, glibc provided an emulation of pselect() that was implemented using sigprocmask(2) and select(). This implementation remained vulnerable to the very race condition that pselect() was designed to prevent. Modern versions of glibc use the (race-free) pselect() system call on kernels where it is provided.

On Linux, select() may report a socket file descriptor as "ready for reading", while nevertheless a subsequent read blocks. This could for example happen when data has arrived but upon examination has the wrong checksum and is discarded. There may be other circumstances in which a file descriptor is spuriously reported as ready. Thus it may be safer to use O_NONBLOCK on sockets that should not block.

On Linux, select() also modifies timeout if the call is interrupted by a signal handler (i.e., the EINTR error return). This is not permitted by POSIX.1. The Linux pselect() system call has the same behavior, but the glibc wrapper hides this behavior by internally copying the timeout to a local variable and passing that variable to the system call.

EXEMPLES

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Watch stdin (fd 0) to see when it has input.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Wait up to five seconds.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Don't rely on the value of tv now! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Data is available now.\n");
        /* FD_ISSET(0, &rfds) will be true.  */
    else
        printf("No data within five seconds.\n");
    exit(EXIT_SUCCESS);
}
