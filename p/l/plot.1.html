PLOT(1) Utilitaire de tracé GNU PLOT(1)

NOM

plot - traduire les métacharques GNU vers d'autres formats graphiques

SYNOPSIS

plot [ options ] [ fichiers ]

DESCRIPTION

plot traduit les fichiers au format métacharque GNU vers d'autres formats graphiques, ou les affiche sur un écran X Window System. Le format métacharque GNU est un format indépendant du périphérique pour le stockage de données graphiques. C'est le format de sortie par défaut des programmes graph(1), pic2plot(1), tek2plot(1), et plotfont(1), et il est plus amplement documenté dans plot(5), car il s'agit d'une version améliorée du format traditionnel plot(5) trouvé sur les systèmes non-GNU. Il peut également être produit par la bibliothèque graphique 2D GNU libplot (voir plot(3)).

Le format de sortie est spécifié avec l'option -T. Les formats de sortie et types d'affichage possibles sont les mêmes que ceux pris en charge par graph(1), plotfont(1), pic2plot(1), et tek2plot(1). Si un fichier de sortie est produit, il est écrit sur la sortie standard.

Les options et les noms de fichiers peuvent être mélangés sur la ligne de commande, mais les options sont traitées avant la lecture des noms de fichiers. Si -- est rencontré, il est interprété comme la fin des options. Si aucun nom de fichier n'est spécifié, ou si le nom de fichier - est rencontré, l'entrée standard est lue.

OPTIONS

Options générales

-T type

--format-sortie type
Sélectionne type comme format de sortie. Il peut être « X », « png », « pnm », « gif », « svg », « ai », « ps », « cgm », « fig », « pcl », « hpgl », « regis », « tek », ou « meta » (par défaut). Ceux-ci se réfèrent respectivement au système X Window, au format PNG (Portable Network Graphics), au format portable anymap (PBM/PGM/PPM), un format pseudo-GIF qui n'utilise pas d'encodage LZW, le nouveau format XML Scalable Vector Graphics, le format utilisé par Adobe Illustrator, Postscript ou Encapsulated Postscript (EPS) qui peut être édité avec idraw(1), le format CGM (par défaut, conformément au profil WebCGM), le format utilisé par l'éditeur de dessin xfig(1), le langage d'imprimante Hewlett-Packard PCL 5, le Hewlett-Packard Graphics Language, le format graphique ReGIS (qui peut être affiché par l'émulateur de terminal dxterm(1) ou par un terminal VT330 ou VT340), le format Tektronix (qui peut être affiché par l'émulateur de terminal xterm(1)), et le format métacharque GNU indépendant du périphérique lui-même. Sauf si type est « X », un fichier de sortie est produit et écrit sur la sortie standard.
Omettre l'option -T est équivalent à spécifier -T meta. Traduire du format métacharque vers lui-même est parfois utile, car il existe deux versions du format métacharque (voir l'option -O ci-dessous).
Une liste des polices disponibles dans tout format de sortie spécifié peut être obtenue avec l'option --aide-polices (voir ci-dessous). Si une police demandée est indisponible, une police par défaut sera substituée. La police par défaut est « Helvetica » pour « X », « svg », « ai », « ps », « cgm », et « fig », « Univers » pour « pcl », et « HersheySerif » pour « png », « pnm », « gif », « hpgl », « regis », « tek », et « meta ».
-p n

--numero-page n
Sortir uniquement la page numéro n, dans la métacharque ou la séquence de métacharques qui est en cours de traduction.
Les métacharques peuvent contenir une ou plusieurs pages, numérotées à partir de 1. De plus, chaque page peut contenir plusieurs « images ». plot -T X, plot -T regis, et plot -T tek, qui tracent en temps réel, sépareront les images successives par une effacement de l'écran. plot -T png, plot -T pnm, plot -T gif, plot -T svg, plot -T ai, plot -T ps, plot -T cgm, plot -T fig, plot -T pcl, et plot -T hpgl, qui ne tracent pas en temps réel, sortiront uniquement la dernière image de toute page contenant plusieurs images.
Le comportement par défaut, si -p n'est pas utilisé, est de sortir toutes les pages. Par exemple, plot -T X affiche chaque page dans sa propre fenêtre X. Si l'option -T png, -T pnm, -T gif, -T ai, ou -T fig est utilisée, le comportement par défaut est de sortir uniquement la première page non vide, car les fichiers dans ces formats de sortie ne contiennent qu'une seule page de graphiques.
Les métacharques produites par graph(1) et plotfont(1) ne contiennent qu'une seule page (page n° 1), qui comprend deux images : une image vide pour effacer l'écran, et une seconde image qui contient les graphiques.
-s

--fusionner-pages
Fusionner toutes les pages affichées en une seule page, et également fusionner toutes les « images ».
Cette option est utile lors de la fusion de tracés d'une seule page provenant de différentes sources. Par exemple, elle peut être utilisée pour fusionner des tracés obtenus à partir d'invocations séparées de graph(1).
--taille-bitmap taille_bitmap
Définir la taille de l'affichage graphique dans lequel le tracé sera dessiné, en pixels, à taille_bitmap. La valeur par défaut est « 570x570 ». Ceci n'est pertinent que pour plot -T X, plot -T png, plot -T pnm, et plot -T gif, qui produisent tous des bitmaps. Si vous choisissez une taille de fenêtre rectangulaire (non carrée), les polices du tracé seront mises à l'échelle de manière anisotrope, c'est-à-dire par des facteurs différents dans les directions horizontale et verticale. Pour plot -T X, cela nécessite un affichage X11R6. Toute police qui ne peut pas être mise à l'échelle de cette manière sera remplacée par une police évolutive par défaut, telle que la police vectorielle « HersheySerif ».
La variable d'environnement BITMAPSIZE peut tout aussi bien être utilisée pour spécifier la taille de la fenêtre. Pour des raisons de compatibilité ascendante, la ressource X Xplot.geometry peut être utilisée à la place.
--emuler-couleur option
Si option est oui, remplace chaque couleur de la sortie par une nuance de gris appropriée. C'est rarement utile, sauf lors de l'utilisation de plot -T pcl pour préparer la sortie pour un périphérique PCL 5. (De nombreux périphériques PCL 5 monochromes, comme les LaserJets monochromes, n'émulent pas bien la couleur par eux-mêmes.) Vous pouvez également demander une émulation de couleur en définissant la variable d'environnement EMULATE_COLOR à « yes ».
--longueur-max-ligne longueur_max_ligne
Définit le nombre maximum de points qu'une ligne polygonale peut contenir, avant d'être vidée, à longueur_max_ligne. Si ce vidage se produit, la ligne polygonale sera divisée en deux ou plusieurs sous-lignes, bien que la division ne devrait pas être perceptible. La valeur par défaut de longueur_max_ligne est 500.
La raison de la division des lignes polygonales longues est que certains périphériques d'affichage (par exemple, les anciennes imprimantes Postscript et les traceurs HP-GL à stylet) ont des tailles de tampon limitées. La variable d'environnement MAX_LINE_LENGTH peut également être utilisée pour spécifier la longueur maximale de ligne.
--taille-page taille_page
Définit la taille de la page sur laquelle le tracé sera positionné. Ceci n'est pertinent que pour plot -T svg, plot -T ai, plot -T ps, plot -T cgm

, plot -T fig, plot -T pcl, et plot -T hpgl. La valeur par défaut est "letter", ce qui signifie une page de 8,5 pouces sur 11 pouces. Toute taille de page ISO dans la plage "a0"..."a4" ou toute taille de page ANSI dans la plage "a"..."e" peut être spécifiée ("letter" est un alias pour "a" et "tabloid" est un alias pour "b"). Les tailles de page "legal" et "ledger" sont également reconnues. La variable d'environnement PAGESIZE peut également être utilisée pour spécifier la taille de la page.
L'affichage graphique dans lequel le tracé est dessiné sera, par défaut, une région carrée qui occupe presque toute la largeur de la page spécifiée. Une taille alternative pour l'affichage graphique peut être spécifiée. Par exemple, la taille de la page pourrait être spécifiée comme "letter,xsize=4in,ysize=6in" ou "a4,xsize=5.0cm,ysize=100mm". Pour toutes les options ci-dessus, sauf plot -T hpgl, l'affichage graphique sera, par défaut, centré sur la page. Pour toutes les options ci-dessus, sauf plot -T svg et plot -T cgm, l'affichage graphique peut être repositionné manuellement, en spécifiant l'emplacement de son coin inférieur gauche, par rapport au coin inférieur gauche de la page. Par exemple, la taille de la page pourrait être spécifiée comme "letter,xorigin=2in,yorigin=3in" ou "a4,xorigin=0.5cm,yorigin=0.5cm". Il est également possible de spécifier un vecteur de décalage. Par exemple, la taille de la page pourrait être spécifiée comme "letter,xoffset=1in" ou "letter,xoffset=1in,yoffset=1.2in" ou "a4,yoffset=-1cm". En format SVG et en format WebCGM, il est possible de spécifier la taille de l'affichage graphique, mais pas sa position.
--rotation angle
Faire pivoter l'affichage graphique de angle degrés. Les valeurs reconnues sont "0", "90", "180" et "270". "no" et "yes" sont respectivement équivalents à "0" et "90". La variable d'environnement ROTATION peut également être utilisée pour spécifier un angle de rotation.

Options d'initialisation des paramètres

Les options suivantes définissent les valeurs initiales des paramètres de dessin. Cependant, toutes ces options peuvent être remplacées par des directives dans un métafichier. En fait, ces options sont principalement utiles lors du tracé d'anciens métafichiers au format traditionnel (pré-GNU) de plot(5), qui ne prenait pas en charge de telles directives.

--bg-color nom
Définir la couleur initialement utilisée pour l'arrière-plan à nom. Ceci n'est pertinent que pour plot -T X, plot -T png, plot -T pnm, plot -T gif, plot -T svg, plot -T cgm, et plot -T regis. Un nom non reconnu définit la couleur sur la valeur par défaut, qui est "white". La variable d'environnement BG_COLOR peut également être utilisée pour spécifier la couleur de l'arrière-plan.
Si l'option -T png ou -T gif est utilisée, un fichier PNG transparent ou un pseudo-GIF transparent, respectivement, peut être produit en définissant la variable d'environnement TRANSPARENT_COLOR sur le nom de la couleur de l'arrière-plan. Si l'option -T svg ou -T cgm est utilisée, un fichier de sortie sans arrière-plan peut être produit en définissant la couleur de l'arrière-plan sur "none".
-f taille

--font-size taille
Définir la taille de la police initialement utilisée pour le rendu du texte, comme fraction de la largeur de l'affichage graphique, à taille. La valeur par défaut est 0.0525.
-F nom

--font-name nom
Définir la police initialement utilisée pour le texte à nom. Les noms de police ne sont pas sensibles à la casse. Si la police spécifiée n'est pas disponible, la police par défaut sera utilisée. Les polices disponibles et la police par défaut dépendent de l'option -T spécifiée (voir ci-dessus). Une liste des polices disponibles peut être obtenue avec l'option --help-fonts (voir ci-dessous).
-W largeur_ligne

--line-width largeur_ligne
Définir la largeur initiale des lignes, comme fraction de la largeur de l'affichage, à largeur_ligne. Une valeur négative signifie qu'une valeur par défaut doit être utilisée. Cette valeur dépend du format. L'interprétation d'une largeur de ligne nulle dépend également du format (dans certains formats de sortie, une ligne de largeur nulle est la ligne la plus fine qui puisse être tracée ; dans d'autres, une ligne de largeur nulle est invisible).
--pen-color nom
Définir la couleur initiale du stylo à nom. Un nom non reconnu définit la couleur du stylo sur la valeur par défaut, qui est "black".

Options pour la sortie de métafichier

L'option suivante n'est pertinente que si l'option -T est omise ou si -T meta est utilisée. Dans ce cas, la sortie de plot, comme l'entrée, sera au format métafichier GNU graphics.

-O

--portable-output
Produire la version portable (lisible par l'homme) du format métafichier GNU, plutôt que la version binaire (par défaut). Le format de la version binaire est dépendant de la machine.

Options pour la compatibilité descendante

Par défaut, plot suppose que ses fichiers d'entrée sont soit dans la version binaire, soit dans la version portable du format métafichier GNU. Vous pouvez spécifier que l'entrée est, au lieu de cela, au format métafichier graphique Unix traditionnel (pré-GNU), qui est documenté dans plot(5). Le format métafichier graphique traditionnel était produit par les versions pré-GNU de graph(1).

-h

--high-byte-first-input
Les fichiers d'entrée sont supposés être dans la version binaire, "octet de poids fort en premier", du format métafichier traditionnel. Cette variante est peu courante.
-l

--low-byte-first-input
Les fichiers d'entrée sont supposés être dans la version binaire, "octet de poids faible en premier", du format métafichier traditionnel. Cette variante est la plus courante.
-A

--ascii-input
Les fichiers d'entrée sont supposés être dans la variante ASCII (lisible par l'homme) du format métafichier traditionnel. Sur certains anciens systèmes Unix, cette variante était produite par plottoa(1).

Options d'information

--help
Imprimer une liste des options de ligne de commande et quitter.
--help-fonts
Imprimer un tableau des polices disponibles et quitter. Le tableau dépendra du format de sortie spécifié avec l'option -T. plot -T X, plot -T svg, plot -T ai, plot -T ps, plot -T cgm, et plot -T fig prennent en charge les 35 polices Postscript standard. plot -T svg, plot -T pcl, et plot -T hpgl prennent en charge les 45 polices PCL 5 standard, et ces deux dernières prennent en charge un certain nombre de polices vectorielles Hewlett-Packard. Les sept prennent en charge un ensemble de 22 polices vectorielles Hershey, tout comme plot -T png, plot -T pnm, plot -T gif, plot -T regis, et plot -T tek. plot sans option -T prend en charge en principe toutes ces polices, car sa sortie doit être traduite dans d'autres formats par une invocation ultérieure de plot.
L'utilitaire plotfont(1) peut être utilisé pour obtenir une carte de caractères de n'importe quelle police prise en charge.
--list-fonts
Similaire à --help-fonts, mais liste les polices dans une seule colonne pour faciliter le transfert vers d'autres programmes. Si aucun format de sortie n'est spécifié avec l'option -T, l'ensemble complet des polices prises en charge est listé.
--version
Imprimer le numéro de version de plot et du package d'utilitaires de tracé et quitter.

ENVIRONNEMENT

Les variables d'environnement BITMAPSIZE, PAGESIZE, BG_COLOR, EMULATE_COLOR, MAX_LINE_LENGTH et ROTATION servent de secours pour les options --bitmap-size, --page-size, --bg-color, --emulate-color, --max-line-length, et --rotation, respectivement. Les autres variables d'environnement sont spécifiques aux formats de sortie individuels.

plot -T X, qui affiche une fenêtre sur un écran X Window System et y dessine des graphiques, vérifie la variable d'environnement DISPLAY. Sa valeur détermine l'affichage qui sera utilisé.

plot -T png et plot -T gif, qui produisent une sortie au format PNG et au format pseudo-GIF respectivement, sont affectés par la variable d'environnement INTERLACE. Si sa valeur est "yes", la sortie sera entrelacée. De plus, si la variable d'environnement TRANSPARENT_COLOR est définie sur le nom d'une couleur, cette couleur sera traitée comme transparente dans la sortie.

plot -T pnm, qui produit une sortie au format portable anymap (PBM/PGM/PPM), est affecté par la variable d'environnement PNM_PORTABLE. Si sa valeur est "yes", la sortie sera dans un format lisible par l'homme plutôt qu'en binaire (par défaut).

ENVIRONMENT

The behavior of plot is affected by the following environment variables.

CGM_MAX_VERSION

Controls the maximum version of CGM output. If set to "3" or undefined, then plot will produce a binary-encoded version of CGM version 3 format. For backward compatibility, the version number may be reduced by setting CGM_MAX_VERSION to "2" or "1". Irrespective of version, the output CGM file will use the human-readable clear text encoding if CGM_ENCODING is set to "clear_text". However, only binary-encoded CGM files conform to the WebCGM profile.

PCL_ASSIGN_COLORS

plot -T pcl, which produces PCL 5 output for Hewlett-Packard printers and plotters, is affected by the environment variable PCL_ASSIGN_COLORS. It should be set to "yes" when producing PCL 5 output for a color printer or other color device. This will ensure accurate color reproduction by giving the output device complete freedom in assigning colors, internally, to its "logical pens". If it is "no" then the device will use a fixed set of colored pens, and will emulate other colors by shading. The default is "no" because monochrome PCL 5 devices, which are much more common than colored ones, must use shading to emulate color.

HPGL_VERSION, HPGL_ROTATE, HPGL_PENS, HPGL_ASSIGN_COLORS, HPGL_OPAQUE_MODE

plot -T hpgl, which produces Hewlett-Packard Graphics Language output, is affected by several environment variables. The most important is HPGL_VERSION, which may be set to "1", "1.5", or "2" (the default). "1" means that the output should be generic HP-GL, "1.5" means that the output should be suitable for the HP7550A graphics plotter and the HP758x, HP7595A and HP7596A drafting plotters (HP-GL with some HP-GL/2 extensions), and "2" means that the output should be modern HP-GL/2. If the version is "1" or "1.5" then the only available fonts will be vector fonts, and all lines will be drawn with a default width (the -W option will not work). Additionally, if the version is "1" then the filling of arbitrary curves with solid color will not be supported (circles and rectangles aligned with the coordinate axes may be filled, though).

The position of the plot -T hpgl graphics display on the page can be rotated 90 degrees counterclockwise by setting the HPGL_ROTATE environment variable to "yes". This is not the same as the rotation obtained with the --rotation option, since it both rotates the graphics display and repositions its lower left corner toward another corner of the page. Besides "no" and "yes", recognized values for HPGL_ROTATE are "0", "90", "180", and "270". "no" and "yes" are equivalent to "0" and "90", respectively. "180" and "270" are supported only if HPGL_VERSION is "2" (the default).

By default, plot -T hpgl will draw with a fixed set of pens. Which pens are present may be specified by setting the HPGL_PENS environment variable. If HPGL_VERSION is "1", the default value of HPGL_PENS is "1=black"; if HPGL_VERSION is "1.5" or "2", the default value of HPGL_PENS is "1=black:2=red:3=green:4=yellow:5=blue:6=magenta:7=cyan". The format should be self-explanatory. By setting HPGL_PENS you may specify a color for any pen in the range #1...#31. All color names recognized by the X Window System may be used. Pen #1 must always be present, though it need not be black. Any other pen in the range #1...#31 may be omitted.

If HPGL_VERSION is "2" then plot -T hpgl will also be affected by the environment variable HPGL_ASSIGN_COLORS. If its value is "yes", then plot -T hpgl will not be restricted to the palette specified in HPGL_PENS: it will assign colors to "logical pens" in the range #1...#31, as needed. The default value is "no" because other than color LaserJet printers and DesignJet plotters, not many HP-GL/2 devices allow the assignment of colors to logical pens.

Opaque filling and the drawing of visible white lines are supported only if HPGL_VERSION is "2" and the environment variable HPGL_OPAQUE_MODE is "yes" (the default). If its value is "no" then white lines (if any), which are normally drawn with pen #0, will not be drawn. This feature is to accommodate older HP-GL/2 devices. HP-GL/2 pen plotters, for example, do not support opacity or the use of pen #0 to draw visible white lines. Some older HP-GL/2 devices may, in fact, malfunction if asked to draw opaque objects.

TERM

plot -T tek, which produces output for a Tektronix terminal or emulator, checks the TERM environment variable. If the value of TERM is a string beginning with "xterm", "nxterm", or "kterm", it is taken as a sign that plot is running in an X Window System VT100 terminal emulator: a copy of xterm(1), nxterm(1), or kterm(1). Before drawing graphics, plot -T tek will emit an escape sequence that causes the terminal emulator's auxiliary Tektronix window, which is normally hidden, to pop up. After the graphics are drawn, an escape sequence that returns control to the original VT100 window will be emitted. The Tektronix window will remain on the screen.

If the value of TERM is a string beginning with "kermit", "ansi.sys", or "nansi.sys", it is taken as a sign that plot is running in the VT100 terminal emulator provided by the MS-DOS version of kermit(1). Before drawing graphics, plot -T tek will emit an escape sequence that switches the terminal emulator to Tektronix mode. Also, some of the Tektronix control codes emitted by plot -T tek will be kermit-specific. There will be a limited amount of color support, which is not normally the case (the 16 `ansi.sys' colors will be supported). After drawing graphics, plot -T tek will emit an escape sequence that returns the emulator to VT100 mode. The key sequence `ALT minus' can be employed manually within kermit to switch between the two modes.
