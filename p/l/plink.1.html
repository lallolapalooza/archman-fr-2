plink(1) Suite d'outils PuTTY plink(1)

NOM

plink - outil de connexion réseau en ligne de commande PuTTY link

SYNTAXE

plink [options] [utilisateur@]hote [commande]

DESCRIPTION

plink est un outil de connexion réseau prenant en charge plusieurs protocoles.

OPTIONS

Les options en ligne de commande prises en charge par plink sont :

-V
Affiche les informations de version et quitte.
-pgpfp
Affiche les empreintes des clés maîtres PGP de PuTTY et quitte, pour aider à vérifier les nouveaux fichiers publiés par l'équipe PuTTY.
-v
Affiche des messages verbeux.
-load session
Charge les paramètres à partir d'une session enregistrée.
-ssh
Force l'utilisation du protocole SSH (par défaut).
-telnet
Force l'utilisation du protocole Telnet.
-rlogin
Force l'utilisation du protocole rlogin.
-raw
Force le mode brut.
-serial
Force le mode série.
-ssh-connection
Force l'utilisation du protocole `bare ssh-connection'. Ceci est probablement seulement utile lorsque vous vous connectez à un serveur psusan(1), le plus souvent avec un chemin absolu vers une socket de domaine Unix à la place de hote.
-proxycmd commande
Au lieu d'établir une connexion TCP, utilise commande comme proxy ; le trafic réseau sera redirigé vers l'entrée et la sortie standard de commande. commande doit être un seul mot, donc il est probable qu'il faudra le mettre entre guillemets par le shell.

Les chaînes spéciales %host et %port dans commande seront remplacées par le nom d'hôte et le numéro de port auxquels vous voulez vous connecter ; pour obtenir un signe % littéral, entrez %%.

Les échappements de barre oblique inverse sont également pris en charge, comme les séquences comme \n étant remplacées par un saut de ligne littéral ; pour obtenir une barre oblique inverse littérale, entrez \\. (Un échappement supplémentaire peut être requis par le shell.)

(Voir le manuel principal de PuTTY pour les détails complets des jetons pris en charge délimités par % et par barre oblique inverse, bien que la plupart d'entre eux ne soient probablement pas très utiles dans ce contexte.)

-P port
Se connecte au port port.
-l utilisateur
Définit le nom d'utilisateur distant sur utilisateur.
-m chemin
Lit la ou les commandes distantes à partir du fichier local chemin.
-batch
Désactive les invites interactives.
-sanitise-stderr
-sanitise-stdout
-no-sanitise-stderr
-no-sanitise-stdout
Par défaut, Plink peut choisir de filtrer les caractères de contrôle si cela semble approprié, pour empêcher les processus distants d'envoyer des séquences d'échappement confuses. Ces options remplacent le comportement par défaut de Plink pour activer ou désactiver ce filtrage sur les canaux de sortie d'erreur standard et de sortie standard.
-pwfile nom_fichier
Ouvre le fichier spécifié et utilise la première ligne de texte lue à partir de celui-ci comme mot de passe distant.
-pw mot_de_passe
Définit le mot de passe distant sur mot_de_passe. ATTENTION : cela rendra probablement le mot de passe visible par d'autres utilisateurs de la machine locale (via des commandes telles que `ps' ou `w'). Utilisez plutôt -pwfile.
-L [srcaddr:]srcport:desthost:destport
Configure un transfert de port local : écoute sur srcport (ou srcaddr:srcport si spécifié), et transfère toutes les connexions via la connexion SSH vers l'adresse de destination desthost:destport. Ne fonctionne qu'en SSH.
-R [srcaddr:]srcport:desthost:destport
Configure un transfert de port distant : demande au serveur SSH d'écouter sur srcport (ou srcaddr:srcport si spécifié), et de transférer toutes les connexions en retour via la connexion SSH où le client les transmettra à l'adresse de destination desthost:destport. Ne fonctionne qu'en SSH.
-D [srcaddr:]srcport
Configure un transfert de port dynamique. Le client écoute sur srcport (ou srcaddr:srcport si spécifié), et implémente un serveur SOCKS. Vous pouvez donc pointer les applications compatibles SOCKS vers ce port et elles utiliseront automatiquement la connexion SSH pour tunneliser toutes leurs connexions. Ne fonctionne qu'en SSH.
-X
Active le transfert X11.
-x
Désactive le transfert X11 (par défaut).
-A
Active le transfert d'agent.
-a
Désactive le transfert d'agent (par défaut).
-t
Active l'allocation de pty (par défaut si une commande N'EST PAS spécifiée).
-T
Désactive l'allocation de pty (par défaut si une commande EST spécifiée).
-1
Force l'utilisation du protocole SSH version 1.
-2
Force l'utilisation du protocole SSH version 2.
-4, -6
Force l'utilisation d'IPv4 ou d'IPv6 pour les connexions réseau.
-C
Active la compression SSH.
-i fichier_clé
Fichier de clé privée pour l'authentification de l'utilisateur. Pour les clés SSH-2, ce fichier de clé doit être au format PPK de PuTTY, et non au format OpenSSH ou tout autre format.

Si vous utilisez un agent d'authentification, vous pouvez également spécifier une clé publique ici (au format RFC 4716 ou OpenSSH), pour identifier quelle clé de l'agent utiliser.

-noagent
N'essaie pas d'utiliser un agent d'authentification pour l'authentification locale. (Cela n'affecte pas le transfert d'agent.)
-agent
Autorise l'utilisation d'un agent d'authentification. (Cette option n'est nécessaire que pour remplacer un paramètre dans une session enregistrée.)
-no-trivial-auth
Se déconnecte de tout serveur SSH qui accepte l'authentification sans jamais avoir demandé de mot de passe, de signature ou de jeton. (Vous pourriez vouloir activer ceci pour un serveur qui vous demande toujours une authentification, par exemple pour vous assurer que vous ne tapez pas accidentellement le mot de passe de votre fichier clé dans un serveur compromis qui usurpe l'invite de mot de passe de Plink.)
-noshare
Ne teste pas et n'essaie pas de partager une connexion existante, crée toujours une nouvelle connexion.
-share
Teste et essaie de partager une connexion existante.
-hostkey clé
Spécifie une clé publique hôte acceptable. Cette option peut être spécifiée plusieurs fois ; chaque clé peut être soit une empreinte (SHA256:AbCdE..., 99:aa:bb:..., etc.) soit un bloc encodé en base64 au format d'une ligne d'OpenSSH.

La spécification de cette option remplace la gestion automatisée des clés hôtes ; seulement la ou les clés spécifiées en ligne de commande seront acceptées (sauf si une session enregistrée remplace également les clés hôtes, auquel cas celles-ci seront ajoutées

plink(1) — PuTTY tool suite

NAME

plink — PuTTY link command line connection utility

SYNOPSIS

plink [-V] [-pgpfp] [-batch] [-}{-safehelphostkey] [-}{-noprompt] [-}{-strictrc] [-{-nonpassive] [-{-proxycmd command] [-}{-proxyjump host] [-{-proxyauth username] [-}{-sshlog logfile] [-}{-sshrawlog logfile] [-}{-logoverwrite] [-}{-logappend] [-{-shareexists] [-{-serial port] [-{-sercfg configuration-string] [-{-telnet] [-{-rlogin] [-}{-raw] [-{-l username] [-{-P port] [-{-pw password] [-{-pwfile filename] [-{-key private-key-file] [-{-agent] [-{-load session] [-{-N] [-{-s] [-{-nc host:port] [-{-t] [-{-A] [-{-4|-{-6] [-{-m message-file] [-{-batch] [{-{-proxy proxy-settings]] [{-{-cert certificate-file]] host [
command]

DESCRIPTION

plink is a command-line tool for connecting to remote servers using the SSH, Telnet, Rlogin or raw-socket protocols. It is part of the PuTTY suite of tools.

The primary use of plink is to execute a command on a remote machine. This is done by specifying the remote host you want to connect to, followed by the command you want to execute. If you do not specify a command, plink will run a remote shell.

OPTIONS

-V
Print version information and exit.
-pgpfp
Print PGP fingerprints of PuTTY keys and exit.
-safehelphostkey
When connecting to a server for the first time, plink will prompt you to confirm the server's host key. If you are automating a connection, you might not want to be prompted. If you use this option, and the server's host key is not already known, plink will fail the connection instead of prompting.
-noprompt
If this option is given, plink will try to be non-interactive. It will not prompt the user for any information, such as passwords or passphrases. If it requires information that it cannot obtain non-interactively, it will fail.
-strictrc
Causes plink to treat configuration errors in a saved session as fatal. Normally, plink will try to continue even if it encounters an error in a session configuration.
-nonpassive
Forces plink to use active mode for FTP connections (which is the default for plink's proxying mechanism). In active mode, the server connects back to the client. Some network environments (like those behind strict firewalls) may require passive mode instead.
-proxycmd command
Use the specified command as an external proxy. plink will connect to the proxy, and the proxy is expected to connect to the target host.
-proxyjump host
Use the specified host as a jump host. This is equivalent to using -proxycmd ssh -W %hop:%port.
-proxyauth username
The username to use when authenticating with a proxy server.
-serial port
Connect to the specified serial port (e.g. COM1 on Windows, /dev/ttyS0 on Unix). The host name should be omitted if this option is used. If you use -serial, the connection will be to the local serial port, not a remote host. If you omit the host name, the host key cache will not be written.
-s
Remote command is SSH subsystem (SSH-2 only).
-N
Don't start a remote command or shell at all (SSH-2 only).
-nc host:port
Make a remote network connection from the server instead of starting a shell or command.
-sercfg configuration-string
Specify the configuration parameters for the serial port, in -serial mode. configuration-string should be a comma-separated list of configuration parameters as follows:
•
Any single digit from 5 to 9 sets the number of data bits.
•
`1', `1.5' or `2' sets the number of stop bits.
•
Any other numeric string is interpreted as a baud rate.
•
A single lower-case letter specifies the parity: `n' for none, `o' for odd, `e' for even, `m' for mark and `s' for space.
•
A single upper-case letter specifies the flow control: `N' for none, `X' for XON/XOFF, `R' for RTS/CTS and `D' for DSR/DTR.
-sshlog logfile
-sshrawlog logfile
For SSH connections, these options make plink log protocol details to a file. (Some of these may be sensitive, although by default an effort is made to suppress obvious passwords.)

-sshlog logs decoded SSH packets and other events (those that -v would print). -sshrawlog additionally logs the raw encrypted packet data.

-logoverwrite
If Plink is configured to write to a log file that already exists, discard the existing file.
-logappend
If Plink is configured to write to a log file that already exists, append new log data to the existing file.
-shareexists
Instead of making a new connection, test for the presence of an existing connection that can be shared. The desired session can be specified in any of the usual ways.

Returns immediately with a zero exit status if a suitable `upstream' exists, nonzero otherwise.
