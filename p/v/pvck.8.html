NOM

pvck — Vérifier les métadonnées sur les volumes physiques

SYNOPSIS

pvck option_args position_args
[ option_args ]
    --commandprofile Chaîne
    --config Chaîne
-d|--debug ...
    --devices PV
    --devicesfile Chaîne
    --driverloaded o|n
    --dump headers|metadata|metadata_all|metadata_search
-f|--file Chaîne
-h|--help
    --journal Chaîne
    --labelsector Nombre
    --lockopt Chaîne
    --longhelp
    --nohints
    --nolocking
    --profile Chaîne
    --[pv]metadatacopies 0|1|2
-q|--quiet ...
    --repair
    --repairtype pv_header|metadata|label_header
    --settings Chaîne
-t|--test
-v|--verbose ...
    --version
-y|--yes

DESCRIPTION

pvck vérifie et répare les métadonnées LVM sur les volumes physiques (PV).

Options de vidage (Dump)

headers
Affiche les en-têtes et structures LVM sur disque : label_header, pv_header, en-têtes mda et texte des métadonnées. Des avertissements sont affichés si des valeurs sont incorrectes. Le label_header et le pv_header existent tous deux dans un secteur de 512 octets, généralement le deuxième secteur du périphérique. Un en-tête mda existe dans un secteur de 512 octets à un décalage de 4096 octets. Un second en-tête mda peut exister en option vers la fin du périphérique. Le texte des métadonnées existe dans une zone (environ 1 Mio par défaut) immédiatement après le secteur de l'en-tête mda. Le texte des métadonnées est vérifié mais pas affiché (voir les autres options).

metadata
Affiche le texte des métadonnées du VG LVM actuel (ou l'enregistre dans un fichier), en utilisant les en-têtes pour localiser la dernière copie des métadonnées. Si les en-têtes sont endommagés, les métadonnées peuvent ne pas être trouvées (voir metadata_search). Utilisez --settings "mda_num=2" pour chercher dans mda2 (le deuxième mda à la fin du périphérique, s'il est utilisé). Le texte des métadonnées est affiché sur stdout ou enregistré dans un fichier avec --file.

metadata_all
Liste toutes les versions des métadonnées VG trouvées dans la zone de métadonnées, en utilisant les en-têtes pour localiser les métadonnées. Des copies complètes de toutes les métadonnées sont enregistrées dans un fichier avec l'option --file. Si les en-têtes sont endommagés, les métadonnées peuvent ne pas être trouvées (voir metadata_search). Utilisez --settings "mda_num=2" comme ci-dessus. Utilisez -v pour inclure les descriptions et les dates lors de la liste des versions de métadonnées.

metadata_search
Liste toutes les versions des métadonnées VG trouvées dans la zone de métadonnées, en recherchant des emplacements courants afin que les métadonnées puissent être trouvées si les en-têtes sont endommagés. Des copies complètes de toutes les métadonnées sont enregistrées dans un fichier avec l'option --file. Pour enregistrer une version spécifique de métadonnées, utilisez --settings "metadata_offset=<décalage>", où le décalage est pris dans la liste des versions trouvées. Utilisez -v pour inclure les descriptions et les dates lors de la liste des versions de métadonnées.

metadata_area
Enregistre toute la zone de texte des métadonnées dans un fichier sans traitement.

Options de réparation

--repair
Répare les en-têtes et les métadonnées sur un PV. Utilise un fichier d'entrée de métadonnées extrait par --dump, ou un fichier de sauvegarde (de /etc/lvm/backup). Lorsque cela est possible, utilise les métadonnées sauvegardées par --dump à partir d'un autre PV du même VG (ou à partir d'une seconde zone de métadonnées sur le PV).

Il y a des cas où l'UUID du PV doit être spécifié pour le PV en cours de réparation. Il est spécifié en utilisant --settings "pv_uuid=<UUID>". Notamment, si le nom du périphérique du PV en cours de réparation ne correspond pas au nom précédent du PV, LVM peut ne pas être en mesure de déterminer le bon UUID du PV. Lorsque les en-têtes sont endommagés sur plus d'un PV dans un VG, il est important que l'utilisateur détermine le bon UUID du PV et le spécifie dans --settings. Sinon, le mauvais UUID du PV pourrait être utilisé si les noms des périphériques ont été échangés depuis la dernière écriture des métadonnées.

Si un PV n'a pas de zones de métadonnées et que le pv_header est endommagé, la réparation ne saura pas qu'il ne faut pas créer de zones de métadonnées lors de la réparation. Elle réparera par défaut les métadonnées dans mda1. Pour réparer sans zones de métadonnées, utilisez --settings "mda_offset=0 mda_size=0".

Il y a des cas où la réparation doit être effectuée sur tous les PVs du VG (en utilisant les mêmes métadonnées) : si tous les PVs du VG sont endommagés, si une ancienne version des métadonnées est utilisée, ou si un fichier de sauvegarde est utilisé au lieu des métadonnées brutes (extraites par pvck dump).

Utiliser --repair équivaut à exécuter --repairtype pv_header suivi de --repairtype metadata.

--repairtype pv_header
Répare le secteur d'en-tête, contenant le pv_header et le label_header.

--repairtype metadata
Répare l'en-tête mda et le texte des métadonnées. Nécessite que les en-têtes soient corrects (n'ayant pas été endommagés ou ayant déjà été réparés).

--repairtype label_header
Répare les champs du label_header, laissant le pv_header (dans le même secteur) inchangé. (repairtype pv_header devrait généralement être utilisé à la place.)

Paramètres

L'option --settings contrôle ou remplace certains comportements de vidage ou de réparation. Toutes les valeurs de décalage et de taille dans les paramètres sont en octets (les unités ne sont pas reconnues). Ces paramètres sont susceptibles d'être modifiés.

mda_num=1|2
Sélectionne quelle zone de métadonnées doit être utilisée. Par défaut, la première zone de métadonnées (1) est utilisée. mda1 est toujours située au décalage 4096. mda2, à la fin du périphérique, n'existe souvent pas (elle n'est pas créée par défaut). Si mda1 est effacé, mda2, s'il existe, contiendra souvent encore des métadonnées.

metadata_offset=octets
Sélectionne le texte des métadonnées à ce décalage. À utiliser avec metadata_search pour afficher/enregistrer une instance des métadonnées.

mda_offset=octets mda_size=octets
Se réfère à un emplacement et une taille de zone de métadonnées (mda). Un mda inclut un en-tête mda et un tampon circulaire de texte de métadonnées. Le définir force metadata_search à rechercher les métadonnées dans la zone donnée au lieu des emplacements standards. Lorsqu'il est défini à zéro avec la réparation, il indique qu'aucune zone de métadonnées ne doit exister.

mda2_offset=octets mda2_size=octets
Lors de la réparation d'un pv_header, cela force un décalage et une taille spécifiques pour mda2 qui doivent être enregistrés dans le pv_header.

pv_uuid=uuid
Spécifie l'UUID du PV du périphérique en cours de réparation. Lorsqu'il n'est pas spécifié, la réparation tentera de déterminer le bon UUID du PV en faisant correspondre un nom de périphérique dans les métadonnées.

device_size=octets
data_offset=octets
Lors de la réparation d'un pv_header, le device_size, le data_offset et le pvid peuvent tous être spécifiés directement, auquel cas ces valeurs ne sont pas prises d'un fichier de métadonnées (d'où elles proviennent habituellement), et le fichier de métadonnées peut être omis. data_offset est l'emplacement de départ du premier extent physique (données), qui suit la première zone de métadonnées.

OPTIONS

--commandprofile Chaîne
Le profil de commande à utiliser pour la configuration de la commande. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config Chaîne
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). L'argument Chaîne utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définir le niveau de débogage. Répétez de 1 à 6 fois pour augmenter le détail des messages envoyés au fichier journal et/ou à syslog (si configuré).
--devices PV
Restreint les périphériques qui sont visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Cela remplace le fichier de périphériques.
--devicesfile Chaîne
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Cela remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
Si défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour les tests et le débogage.
--dump headers|metadata|metadata_all|metadata_search
Extraire les en-têtes et les métadonnées d'un PV pour le débogage et la réparation. Les valeurs des options incluent : headers pour imprimer et vérifier les en-têtes LVM, metadata pour imprimer ou enregistrer les métadonnées textuelles actuelles, metadata_all pour lister ou enregistrer toutes les versions des métadonnées, metadata_search pour lister ou enregistrer toutes les versions des métadonnées, en recherchant les emplacements standards en cas d'en-têtes endommagés, metadata_area pour enregistrer une zone entière de métadonnées textuelles dans un fichier.
-f|--file Chaîne
Fichier de métadonnées à lire ou écrire.
-h|--help
Afficher le texte d'aide.
--journal Chaîne
Enregistrer les informations dans le journal systemd. Ces informations s'ajoutent aux informations activées par le paramètre lvm.conf log/journal. command : enregistrer des informations sur la commande. output : enregistrer la sortie par défaut de la commande. debug : enregistrer le débogage complet de la commande.
--labelsector Nombre
Par défaut, le PV est étiqueté avec un identifiant LVM2 dans son deuxième secteur (secteur 1). Cela vous permet d'utiliser un secteur différent près du début du disque (entre 0 et 3 inclus - voir LABEL_SCAN_SECTORS dans le code source). À utiliser avec précaution.
--lockopt Chaîne
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Afficher le texte d'aide détaillé.
--nohints
Ne pas utiliser le fichier d'indices pour localiser les périphériques pour les PV. Une commande peut lire plus de périphériques pour trouver des PV lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices le cas échéant.
--nolocking
Désactiver le verrouillage. Utiliser avec précaution, des commandes concurrentes peuvent produire des résultats incorrects.
--profile Chaîne
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
--[pv]metadatacopies 0|1|2
Le nombre de zones de métadonnées à réserver sur un PV pour stocker les métadonnées de VG. Lorsque 2, une copie des métadonnées de VG est stockée au début du PV et une deuxième copie est stockée à la fin. Lorsque 1, une copie des métadonnées de VG est stockée au début du PV. Lorsque 0, aucune copie des métadonnées de VG n'est stockée sur le PV donné. Ceci peut être utile dans les VG contenant de nombreux PV (cela limite la capacité à utiliser vgsplit ultérieurement).
-q|--quiet ...
Supprimer la sortie et les messages de journal. Remplace --debug et --verbose. Répétez une fois pour également supprimer toute invite avec la réponse 'non'.
--repair
Réparer les en-têtes et les métadonnées sur un PV.
--repairtype pv_header|metadata|label_header
Réparer les en-têtes et les métadonnées sur un PV. Voir la description de la commande.
--settings Chaîne
Spécifie les paramètres spécifiques de la commande sous forme "Clé = Valeur". Combinez plusieurs paramètres entre guillemets, ou répétez l'option settings pour chacun.
-t|--test
Exécuter en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées mais en renvoyant néanmoins un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations en plusieurs étapes si un outil s'appuie sur la lecture de métadonnées qu'il croit avoir changées mais qui n'ont pas été modifiées.
-v|--verbose ...
Définir le niveau de verbosité. Répétez de 1 à 4 fois pour augmenter le détail des messages envoyés à stdout et stderr.
--version
Afficher les informations de version.
-y|--yes
Ne pas demander de confirmation interactivement mais toujours répondre oui. Utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)

VARIABLES

PV
Nom du Volume Physique, un chemin d'accès de périphérique sous /dev. Pour les commandes gérant les extensions physiques, un argument positionnel PV accepte généralement un suffixe indiquant une plage (ou plusieurs plages) d'extensions physiques (PE). Lorsque le premier PE est omis, il est par défaut au début du périphérique, et lorsque le dernier PE est omis, il est par défaut à la fin.
Plage de début et de fin (inclusive) : PV[:PE-PE] ...
Plage de début et de longueur (en comptant à partir de 0) : PV[:PE+PE] ...
Chaîne
Voir la description de l'option pour des informations sur le contenu de la chaîne.
Taille[UNITÉ]
La taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs de base deux, quelle que soit la casse, par exemple 'k' et 'K' font tous deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNITÉ. UNITÉ représente d'autres unités d'entrée possibles : b|B est en octets, s|S est en secteurs de 512 octets, k|K est en KiB, m|M est en MiB, g|G est en GiB, t|T est en TiB, p|P est en PiB, e|E est en EiB. (Ceci ne doit pas être confondu avec le contrôle de sortie --units, où les lettres majuscules signifient un multiple de 1000.)

VARIABLES D'ENVIRONNEMENT

Voir lvm(8) pour des informations sur les variables d'environnement utilisées par lvm. Par exemple, LVM_VG_NAME peut généralement être substitué à un paramètre VG requis.

EXEMPLES

Si la table des partitions est corrompue ou perdue sur /dev/sda, et que vous suspectez qu'il y avait une partition LVM à environ 100 MiB, alors cette zone du disque peut être scannée en utilisant le paramètre --labelsector avec une valeur de 204800 (100 * 1024 * 1024 / 512 = 204800).
pvck --labelsector 204800 /dev/sda

NAME

pvck — check Physical Volume metadata consistency.

SYNOPSIS

pvck [-a|--all] [-c|--check] [-d|--debug] [-h|--help] [-k|--version] [-M|--metadatadump] [-n|--noheadings] [-o|--output <filename>] [-v|--verbose] [PhysicalVolume † PhysicalVolume † …]

DESCRIPTION

The pvck command checks the metadata on one or more Physical Volumes (PVs) for consistency. It uses the metadata dump created by `pvcreate` and checks it against the metadata on disk. If no metadata dump is available, it will try to recreate it from the PV metadata on disk.

This command is useful for diagnosing problems with Physical Volume metadata, such as corruption or inconsistencies.

USAGE

pvck [options] { PhysicalVolume [PhysicalVolume …] | LogicalVolume [LogicalVolume …] }

OPTIONS

See lvm(8) for common options.

-a, --all
Perform the check on all Physical Volumes in the system.
-c, --check
Perform the check. This is the default action.
-d, --debug
Enable debugging output.
-h, --help
Display help information.
-k, --version
Display version information.
-M, --metadatadump
Dump the metadata to standard output.
-n, --noheadings
Suppress the column headings in the output.
-o, --output <filename>
Write the output to the specified file.
-v, --verbose
Enable verbose output.

VARIABLES

No variables are used by this command.

ENVIRONMENT VARIABLES

See lvm(8) for environment variables.

EXAMPLES

To check the consistency of a Physical Volume named /dev/sda1:

pvck /dev/sda1

To check all Physical Volumes in the system and enable verbose output:

pvck -a -v
