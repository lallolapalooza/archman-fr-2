DESCRIPTION

Lorsqu'il est appelé sans l'option --cache, pvscan liste les PV du système, comme pvs(8) ou pvdisplay(8).

Lorsque --cache est utilisé, pvscan met à jour l'état d'exécution de lvm sur le système, ou avec -aay effectue l'auto-activation.

pvscan --cache périphérique

Si le périphérique est présent, lvm enregistre que le PV sur le périphérique est en ligne. Si le périphérique n'est pas présent, lvm supprime l'enregistrement en ligne du PV. pvscan lit uniquement le périphérique nommé.

pvscan --cache

Met à jour l'état d'exécution de tous les périphériques lvm.

pvscan --cache -aay périphérique

Effectue les étapes --cache pour le périphérique, puis vérifie si le VG utilisant le périphérique est complet. Si c'est le cas, les LV du VG sont auto-activés, de la même manière que vgchange -aay nom_vg le ferait. (Un nom de périphérique peut être remplacé par des numéros majeur et mineur.)

pvscan --cache -aay

Effectue les étapes --cache pour tous les périphériques, puis auto-active tous les VG complets.

pvscan --cache --listvg|--listlvs périphérique

Effectue les étapes --cache pour le périphérique, puis affiche le nom du VG utilisant le périphérique, ou les noms des LV utilisant le périphérique. --checkcomplete est généralement inclus pour vérifier si tous les PV du VG ou des LV sont en ligne. Lorsque cette commande est appelée par une règle udev, la sortie doit être conforme aux spécifications des règles udev (voir --udevoutput.) La règle udev utilisera les résultats pour effectuer l'auto-activation.

L'auto-activation des VG ou des LV peut être activée/désactivée en utilisant vgchange ou lvchange avec --setautoactivation y|n, ou en ajoutant des noms à la liste activation/auto_activation_volume_list de lvm.conf(5).

Voir lvmautoactivation(7) pour plus d'informations sur la façon dont pvscan est utilisé pour l'auto-activation.

OPTIONS

-a|--activate y|n|ay
Active automatiquement les LV d'un VG lorsque les PV scannés ont complété le VG. (Seul ay est applicable.)
-A|--allpvs
Affiche des informations sur les PV en dehors du fichier de périphériques. Affiche l'ID du périphérique pour les PV inclus dans le fichier de périphériques.
--autoactivation Chaîne
Spécifie si l'auto-activation est utilisée à partir d'un événement. Cela permet à la commande d'appliquer des paramètres spécifiques à l'activation par événement, tels que les optimisations de scan de périphériques utilisant des fichiers pvs_online créés par des scans de PV basés sur des événements.
--cache
Scanne un ou plusieurs périphériques et enregistre qu'ils sont en ligne.
--checkcomplete
Vérifie si tous les périphériques utilisés par un VG ou un LV sont présents, et affiche "complete" ou "incomplete" pour chaque VG ou LV listé. Cette option est utilisée dans le cadre de l'auto-activation par événement, donc pvscan ne fera rien si cette option est définie et que event_activation=0 dans les paramètres de configuration.
--commandprofile Chaîne

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

-a|--all
Toutes les LVs sont traitées. Pour les LVs de groupe, la commande est appliquée à tous les LVs appartenant au groupe. Pour les LVs, cette option est utilisée pour les LVs qui sont associés à tous les PVs.
--commandprofile String
Le profil de commande à utiliser pour la configuration des commandes. Voir lvm.conf(5) pour plus d'informations sur les profils.
--config String
Paramètres de configuration pour la commande. Ceux-ci remplacent les paramètres de lvm.conf(5). L'argument String utilise le même format que lvm.conf(5), ou peut utiliser la syntaxe section/champ. Voir lvm.conf(5) pour plus d'informations sur la configuration.
-d|--debug ...
Définit le niveau de débogage. Répéter de 1 à 6 fois pour augmenter le niveau de détail des messages envoyés au fichier journal et/ou au syslog (si configuré).
--devices PV
Restreint les périphériques visibles et accessibles à la commande. Les périphériques non listés apparaîtront comme manquants. Cette option peut être répétée, ou accepter une liste de périphériques séparés par des virgules. Ceci remplace le fichier de périphériques.
--devicesfile String
Un fichier listant les périphériques que LVM doit utiliser. Le fichier doit exister dans /etc/lvm/devices/ et est géré avec la commande lvmdevices(8). Ceci remplace les paramètres devices/devicesfile et devices/use_devicesfile de lvm.conf(5).
--driverloaded y|n
S'il est défini sur non, la commande ne tentera pas d'utiliser device-mapper. Pour les tests et le débogage.
-e|--exported
Afficher uniquement les PV appartenant aux VG exportés.
-h|--help
Afficher le texte d'aide.
--ignorelockingfailure
Permet à une commande de continuer avec des opérations de métadonnées en lecture seule après des échecs de verrouillage.
--journal String
Enregistre les informations dans le journal systemd. Ces informations sont en plus des informations activées par le paramètre log/journal de lvm.conf. command: enregistre les informations sur la commande. output: enregistre la sortie par défaut de la commande. debug: enregistre le débogage complet de la commande.
--listlvs
Imprimer une liste des LVs qui utilisent le périphérique.
--listvg
Imprimer le VG qui utilise le périphérique.
--lockopt String
Utilisé pour passer des options pour des cas spéciaux à lvmlockd. Voir lvmlockd(8) pour plus d'informations.
--longhelp
Afficher le texte d'aide détaillé.
-j|--major Number
Le numéro majeur d'un périphérique.
--minor Number
Le numéro mineur d'un périphérique.
--nohints
N'utilise pas le fichier d'indices pour localiser les périphériques pour les PVs. Une commande peut lire plus de périphériques pour trouver des PVs lorsque les indices ne sont pas utilisés. La commande effectuera toujours une invalidation standard du fichier d'indices lorsque cela est approprié.
--nolocking
Désactive le verrouillage. Utiliser avec prudence, des commandes concurrentes peuvent produire des résultats incorrects.
--noudevsync
Désactive la synchronisation udev. Le processus n'attendra pas de notification d'udev. Il continuera indépendamment de tout traitement udev possible en arrière-plan. N'utilisez ceci que si udev n'est pas en cours d'exécution ou a des règles qui ignorent les périphériques créés par LVM.
-n|--novolumegroup
Afficher uniquement les PV n'appartenant à aucun VG.
--profile String
Un alias pour --commandprofile ou --metadataprofile, selon la commande.
-q|--quiet ...
Supprimer la sortie et les messages de journal. Remplace --debug et --verbose. Répéter une fois pour supprimer également toute invite avec la réponse 'non'.
--reportformat basic|json|json_std
Remplace le format de sortie actuel pour les rapports, qui est défini globalement par le paramètre report/output_format dans lvm.conf(5). basic est le format original avec des colonnes et des lignes. S'il y a plus d'un rapport par commande, chaque rapport est préfixé par le nom du rapport pour identification. json produit la sortie du rapport au format JSON. json_std produit la sortie du rapport au format JSON, qui est plus conforme à la norme JSON. Voir lvmreport(7) pour plus d'informations.
-s|--short
Format de liste court.
-t|--test
Exécuter en mode test. Les commandes ne mettront pas à jour les métadonnées. Ceci est implémenté en désactivant toute écriture de métadonnées tout en renvoyant un succès à la fonction appelante. Cela peut entraîner des messages d'erreur inhabituels dans les opérations en plusieurs étapes si un outil repose sur la relecture des métadonnées qu'il pense avoir changées mais qui n'ont pas changé.
--udevoutput
La sortie de la commande est modifiée pour être importée à partir d'une règle udev.
-u|--uuid
Afficher les UUIDs en plus des noms de périphériques.
-v|--verbose ...
Définit le niveau de verbosité. Répéter de 1 à 4 fois pour augmenter le niveau de détail des messages envoyés à stdout et stderr.
--version
Afficher les informations de version.
--vgonline
La première commande à voir un VG complet le rapportera de manière unique. D'autres commandes pour voir le VG complet le rapporteront différemment.
-y|--yes
Ne pas demander de confirmation interactivement mais supposer toujours la réponse oui. Utiliser avec une extrême prudence. (Pour un non automatique, voir -qq.)

VARIABLES

PV
Nom du Volume Physique (Physical Volume), un chemin de périphérique sous /dev. Pour les commandes qui gèrent les extents physiques, un argument positionnel PV accepte généralement un suffixe indiquant une plage (ou plusieurs plages) d'extents physiques (PEs). Lorsque le premier PE est omis, il commence par défaut au début du périphérique, et lorsque le dernier PE est omis, il se termine par défaut à la fin.
Plage de début et de fin (inclusive) : PV[:PE-PE] ...
Plage de début et de longueur (en comptant à partir de 0) : PV[:PE+PE] ...
String
Voir la description de l'option pour des informations sur le contenu de la chaîne.
Size[UNIT]
La taille est un nombre d'entrée qui accepte une unité optionnelle. Les unités d'entrée sont toujours traitées comme des valeurs binaires, quelle que soit la casse, par exemple 'k' et 'K' font tous deux référence à 1024. L'unité d'entrée par défaut est spécifiée par une lettre, suivie de |UNIT. UNIT représente d'autres unités d'entrée possibles : b|B est en octets, s|S est en secteurs de 512 octets, k|K est en KiB, m|M est en MiB, g|G est en GiB, t|T est en TiB, p|P est en PiB, e|E est en EiB. (Cela ne doit pas être confondu avec le contrôle de sortie --units, où les lettres capitales signifient un multiple de 1000.)

VARIABLES D'ENVIRONNEMENT

Voir lvm(8) pour des informations sur les variables d'environnement utilisées par lvm. Par exemple, LVM_VG_NAME peut généralement être substitué à un paramètre VG requis.
