NOM

puts - Écrire sur un canal

SYNTAXE

puts ?-nonewline? ?channelId? string

DESCRIPTION

Écrit les caractères fournis par string sur le canal donné par channelId.

ChannelId doit être un identifiant pour un canal ouvert tel qu'un canal standard Tcl (stdout ou stderr), la valeur de retour d'une invocation de open ou socket, ou le résultat d'une commande de création de canal fournie par une extension Tcl. Le canal doit avoir été ouvert pour la sortie.

Si aucun channelId n'est spécifié, il prend par défaut stdout. Puts écrit normalement un caractère de nouvelle ligne après string, mais cette fonctionnalité peut être supprimée en spécifiant le commutateur -nonewline.

Les caractères de nouvelle ligne dans la sortie sont traduits par puts en séquences de fin de ligne spécifiques à la plateforme selon la valeur actuelle de l'option -translation pour le canal (par exemple, sur les PC, les nouvelles lignes sont normalement remplacées par des séquences de retour chariot-nouvelle ligne. Voir la page de manuel fconfigure pour une discussion sur les manières dont fconfigure modifiera la sortie.

Tcl met en mémoire tampon la sortie en interne, de sorte que les caractères écrits avec puts peuvent ne pas apparaître immédiatement sur le fichier ou le périphérique de sortie ; Tcl retardera normalement la sortie jusqu'à ce que le tampon soit plein ou que le canal soit fermé. Vous pouvez forcer l'apparition immédiate de la sortie avec la commande flush.

Lorsque le tampon de sortie se remplit, la commande puts se bloque normalement jusqu'à ce que toutes les données tamponnées aient été acceptées pour la sortie par le système d'exploitation. Si channelId est en mode non bloquant, la commande puts ne se bloquera pas même si le système d'exploitation ne peut pas accepter les données. Au lieu de cela, Tcl continue de mettre en mémoire tampon les données et les écrit en arrière-plan aussi rapidement que possible que le fichier ou le périphérique sous-jacent peut les accepter. L'application doit utiliser la boucle d'événements Tcl pour que la sortie non bloquante fonctionne ; sinon, Tcl ne sait jamais que le fichier ou le périphérique est prêt pour plus de données de sortie. Il est possible qu'une quantité arbitrairement grande de données soit mise en mémoire tampon pour un canal en mode non bloquant, ce qui pourrait consommer une grande quantité de mémoire. Pour éviter de gaspiller de la mémoire, les E/S non bloquantes doivent normalement être utilisées dans un mode piloté par les événements avec la commande fileevent (n'invoquez pas puts à moins d'avoir été récemment notifié via un événement de fichier que le canal est prêt pour plus de données de sortie).

EXEMPLES

Écrire un court message sur la console (ou là où stdout est dirigé) :

puts "Bonjour, le monde !"

Afficher un message en plusieurs parties :

puts -nonewline "Bonjour, "
puts "le monde !"

Afficher un message sur le canal d'erreur standard :

puts stderr "Bonjour, le monde !"

Ajouter un message de journalisation à un fichier :

set chan [open my.log a]
set timestamp [clock format [clock seconds]]
puts $chan "$timestamp - Bonjour, le monde !"
close $chan
