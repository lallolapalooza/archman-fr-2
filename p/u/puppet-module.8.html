NOM

puppet-module - Crée, installe et recherche des modules sur le Puppet Forge.

SYNOPIS

puppet module action [--environment production ] [--modulepath ]

DESCRIPTION

Cette sous-commande peut trouver, installer et gérer des modules du Puppet Forge, un dépôt de code Puppet contribué par les utilisateurs. Elle peut également générer des modules vides et préparer des modules développés localement pour leur publication sur le Forge.

OPTIONS

Notez que tout paramètre valide dans le fichier de configuration est également un argument long valide, bien qu'il puisse être pertinent ou non pour l'action présente. Par exemple, server et run_mode sont des paramètres valides, vous pouvez donc spécifier --server <nomserveur> ou --run_mode <modedexecution> comme argument.

Consultez la documentation du fichier de configuration à https://puppet.com/docs/puppet/latest/configuration.html pour la liste complète des paramètres acceptables. Une liste commentée de toutes les options de configuration peut également être générée en exécutant puppet avec --genconfig.

--render-as FORMAT
Le format dans lequel rendre la sortie. Les formats les plus courants sont json, s (chaîne), yaml et console, mais d'autres options telles que dot sont parfois disponibles.
--verbose
Indique s'il faut enregistrer de manière détaillée.
--debug
Indique s'il faut enregistrer des informations de débogage.
--environment production
L'environnement dans lequel Puppet s'exécute. Pour les clients, tels que puppet agent, cela détermine l'environnement lui-même, que Puppet utilise pour trouver des modules et bien plus encore. Pour les serveurs, tels que puppet server, cela fournit l'environnement par défaut pour les nœuds que Puppet ne connaît pas.
Lors de la définition d'un environnement dans la section [agent], cela fait référence à l'environnement que l'agent demande au serveur principal. L'environnement n'a pas besoin d'exister sur le système de fichiers local car l'agent le récupère auprès du serveur principal. Cette définition est utilisée lors de l'exécution de puppet agent.
Lors de sa définition dans la section [user], l'environnement fait référence au chemin que Puppet utilise pour rechercher du code et des modules liés à son exécution. Cela nécessite que l'environnement existe localement sur le système de fichiers où puppet est exécuté. Les sous-commandes Puppet, y compris puppet module et puppet apply, utilisent cette définition.
Étant donné que le contexte et les effets varient en fonction de la section de configuration https://puppet.com/docs/puppet/latest/config_file_main.html#config-sections dans laquelle le paramètre environment est défini, ne le définissez pas globalement.
--modulepath
Le chemin de recherche des modules, sous forme d'une liste de répertoires séparés par le caractère séparateur de chemin du système. (Le séparateur de chemin POSIX est ´:´, et le séparateur de chemin Windows est ´;´.)
La définition d'une valeur globale pour modulepath dans puppet.conf n'est pas autorisée (mais elle peut être remplacée en ligne de commande). Utilisez plutôt les environnements par répertoire. Si vous avez besoin d'utiliser autre chose que le chemin de module par défaut de <MODULES DIR DE L'ENVIRONNEMENT ACTIF>:$basemodulepath, vous pouvez définir modulepath dans environment.conf. Pour plus d'informations, voir https://puppet.com/docs/puppet/latest/environments_about.html

ACTIONS

changes - Afficher les fichiers modifiés d'un module installé.
SYNOPIS
puppet module changes chemin
DESCRIPTION
Affiche les fichiers d'un module qui ont été modifiés depuis leur installation. Cette action compare les fichiers sur le disque aux sommes de contrôle md5 incluses dans le fichier checksums.json du module ou, s'il est manquant, dans metadata.json.
RETOURS
Tableau de chaînes représentant les chemins des fichiers modifiés.
install - Installe un module depuis le Puppet Forge ou une archive de distribution.
SYNOPIS
puppet module install [--force | -f] [--target-dir DIR | -i DIR] [--ignore-dependencies] [--version VER | -v VER] nom
DESCRIPTION
Installe un module depuis le Puppet Forge ou depuis un fichier d'archive de distribution. Remarque : L'installation de modules utilise des sommes de contrôle MD5, qui sont interdites sur les systèmes activant le mode FIPS.
Le module spécifié sera installé dans le répertoire spécifié avec l'option --target-dir, qui par défaut est le premier répertoire du modulepath.
OPTIONS --force | -f - Forcer l'écrasement du module existant, le cas échéant. Implique --ignore-dependencies.
--ignore-dependencies - Ne pas tenter d'installer les dépendances. Impliqué par --force.
--target-dir DIR | -i DIR - Le répertoire dans lequel les modules sont installés ; par défaut, le premier répertoire du modulepath.
La spécification de cette option changera le répertoire d'installation et utilisera le modulepath existant lors de la vérification des dépendances. Si vous souhaitez vérifier un ensemble de répertoires différent pour les dépendances, vous devez également utiliser les options --environment ou --modulepath.
--version VER | -v VER - Version du module à installer ; peut être une version exacte ou une chaîne de spécification, par ex. ´>= 1.0.3´. Par défaut, la dernière version.
RETOURS
Objet de type nom de chemin représentant le chemin vers le module installé.
list - Lister les modules installés
SYNOPIS
puppet module list [--tree]
DESCRIPTION
Liste les modules puppet installés. Par défaut, cette action analyse le modulepath du bloc [main] de puppet.conf ; utilisez l'option --modulepath pour changer les répertoires analysés.
La sortie de cette action inclut des informations provenant des métadonnées du module, y compris les numéros de version et les dépendances de modules non satisfaites.
OPTIONS --tree - Indique s'il faut afficher les dépendances sous forme d'arborescence
RETOURS
Tableau associatif des chemins vers les objets modules
uninstall - Désinstalle un module puppet.
SYNOPIS
puppet module uninstall [--force | -f] [--ignore-changes | -c] [--version=] nom
DESCRIPTION
Désinstalle un module puppet du modulepath (ou d'un répertoire cible spécifique). Remarque : La désinstallation de modules utilise des sommes de contrôle MD5, qui sont interdites sur les systèmes activant le mode FIPS.
OPTIONS --force | -f - Forcer la désinstallation d'un module installé même s'il y a des modifications locales ou un risque de causer des dépendances cassées.
--ignore-changes | -c - Désinstaller un module installé même s'il présente des modifications locales. (Impliqué par --force.)
--version= - La version du module à désinstaller. Lors de l'utilisation de cette option, un module correspondant à la version spécifiée doit être installé, sinon une erreur est générée.
RETOURS
Tableau associatif des objets modules représentant les modules désinstallés et les erreurs associées.
upgrade - Met à jour un module puppet.
SYNOPIS
puppet module upgrade [--force | -f] [--ignore-dependencies] [--ignore-changes | -c] [

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

--version=] nom
DESCRIPTION
Met à jour un module puppet. Remarque : La mise à jour de module utilise des sommes de contrôle MD5, qui sont interdites sur les systèmes activés FIPS.
OPTIONS --force | -f - Force la mise à jour d'un module installé, même en présence de modifications locales ou d'un risque de dépendances cassées. Implique --ignore-dependencies.
--ignore-changes | -c - Met à jour un module installé même s'il contient des modifications locales. (Impliqué par --force.)
--ignore-dependencies - N'essaie pas d'installer les dépendances. Impliqué par --force.
--version= - La version du module à laquelle mettre à jour.
RETOURNE
Hash

EXEMPLES

changes

Affiche les fichiers modifiés d'un module installé :

$ puppet module changes /etc/puppetlabs/code/modules/vcsrepo/ warning: 1 files modified lib/puppet/provider/vcsrepo.rb

install

Installe un module :

$ puppet module install puppetlabs-vcsrepo Préparation de l'installation dans /etc/puppetlabs/code/modules ... Téléchargement depuis https://forgeapi.puppet.com ... Installation - n'interrompez pas ... /etc/puppetlabs/code/modules └── puppetlabs-vcsrepo (v0.0.4)

Installe un module dans un environnement spécifique :

$ puppet module install puppetlabs-vcsrepo --environment development Préparation de l'installation dans /etc/puppetlabs/code/environments/development/modules ... Téléchargement depuis https://forgeapi.puppet.com ... Installation - n'interrompez pas ... /etc/puppetlabs/code/environments/development/modules └── puppetlabs-vcsrepo (v0.0.4)

Installe une version spécifique d'un module :

$ puppet module install puppetlabs-vcsrepo -v 0.0.4 Préparation de l'installation dans /etc/puppetlabs/modules ... Téléchargement depuis https://forgeapi.puppet.com ... Installation - n'interrompez pas ... /etc/puppetlabs/code/modules └── puppetlabs-vcsrepo (v0.0.4)

Installe un module dans un répertoire spécifique :

$ puppet module install puppetlabs-vcsrepo --target-dir=/opt/puppetlabs/puppet/modules Préparation de l'installation dans /opt/puppetlabs/puppet/modules ... Téléchargement depuis https://forgeapi.puppet.com ... Installation - n'interrompez pas ... /opt/puppetlabs/puppet/modules └── puppetlabs-vcsrepo (v0.0.4)

Installe un module dans un répertoire spécifique et vérifie les dépendances dans d'autres répertoires :

$ puppet module install puppetlabs-vcsrepo --target-dir=/opt/puppetlabs/puppet/modules --modulepath /etc/puppetlabs/code/modules Préparation de l'installation dans /opt/puppetlabs/puppet/modules ... Téléchargement depuis https://forgeapi.puppet.com ... Installation - n'interrompez pas ... /opt/puppetlabs/puppet/modules └── puppetlabs-vcsrepo (v0.0.4)

Installe un module à partir d'une archive de release :

$ puppet module install puppetlabs-vcsrepo-0.0.4.tar.gz Préparation de l'installation dans /etc/puppetlabs/code/modules ... Téléchargement depuis https://forgeapi.puppet.com ... Installation - n'interrompez pas ... /etc/puppetlabs/code/modules └── puppetlabs-vcsrepo (v0.0.4)

Installe un module à partir d'une archive de release et ignore les dépendances :

$ puppet module install puppetlabs-vcsrepo-0.0.4.tar.gz --ignore-dependencies Préparation de l'installation dans /etc/puppetlabs/code/modules ... Installation - n'interrompez pas ... /etc/puppetlabs/code/modules └── puppetlabs-vcsrepo (v0.0.4)

list

Liste les modules installés :

$ puppet module list /etc/puppetlabs/code/modules ├── bodepd-create_resources (v0.0.1) ├── puppetlabs-bacula (v0.0.2) ├── puppetlabs-mysql (v0.0.1) ├── puppetlabs-sqlite (v0.0.1) └── puppetlabs-stdlib (v2.2.1) /opt/puppetlabs/puppet/modules (aucun module installé)

Liste les modules installés dans une vue arborescente :

$ puppet module list --tree /etc/puppetlabs/code/modules └─┬ puppetlabs-bacula (v0.0.2) ├── puppetlabs-stdlib (v2.2.1) ├─┬ puppetlabs-mysql (v0.0.1) │ └── bodepd-create_resources (v0.0.1) └── puppetlabs-sqlite (v0.0.1) /opt/puppetlabs/puppet/modules (aucun module installé)

Liste les modules installés à partir d'un environnement spécifié :

$ puppet module list --environment production /etc/puppetlabs/code/modules ├── bodepd-create_resources (v0.0.1) ├── puppetlabs-bacula (v0.0.2) ├── puppetlabs-mysql (v0.0.1) ├── puppetlabs-sqlite (v0.0.1) └── puppetlabs-stdlib (v2.2.1) /opt/puppetlabs/puppet/modules (aucun module installé)

Liste les modules installés à partir d'un modulepath spécifié :

$ puppet module list --modulepath /opt/puppetlabs/puppet/modules /opt/puppetlabs/puppet/modules (aucun module installé)

uninstall

Désinstalle un module :

$ puppet module uninstall puppetlabs-ssh Supprimé /etc/puppetlabs/code/modules/ssh (v1.0.0)

Désinstalle un module à partir d'un répertoire spécifique :

$ puppet module uninstall puppetlabs-ssh --modulepath /opt/puppetlabs/puppet/modules Supprimé /opt/puppetlabs/puppet/modules/ssh (v1.0.0)

Désinstalle un module à partir d'un environnement spécifique :

$ puppet module uninstall puppetlabs-ssh --environment development Supprimé /etc/puppetlabs/code/environments/development/modules/ssh (v1.0.0)

Désinstalle une version spécifique d'un module :

$ puppet module uninstall puppetlabs-ssh --version 2.0.0 Supprimé /etc/puppetlabs/code/modules/ssh (v2.0.0)

upgrade

Met à jour un module installé vers la dernière version

$ puppet module upgrade puppetlabs-apache /etc/puppetlabs/puppet/modules └── puppetlabs-apache (v1.0.0 -> v2.4.0)

Met à jour un module installé vers une version spécifique

$ puppet module upgrade puppetlabs-apache --version 2.1.0 /etc/puppetlabs/puppet/modules └── puppetlabs-apache (v1.0.0 -> v2.1.0)

Met à jour un module installé pour un environnement spécifique

$ puppet module upgrade puppetlabs-apache --environment test /etc/puppetlabs/code/environments/test/modules └── puppetlabs-apache (v1.0.0 -> v2.4.0)
