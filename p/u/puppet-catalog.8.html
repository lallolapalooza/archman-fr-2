NOM

puppet-catalog - Compiler, sauvegarder, visualiser et convertir des catalogues.

SYNTAXE

puppet catalog action [--terminus _TERMINUS]

DESCRIPTION

Cette sous-commande traite les catalogues, qui sont des artefacts compilés par nœud générés à partir d'un ensemble de manifests Puppet. Par défaut, elle interagit avec le sous-système de compilation et compile un catalogue en utilisant le manifest et le certname par défaut, mais vous pouvez modifier la source du catalogue avec l'option --terminus. Vous pouvez également choisir d'imprimer n'importe quel catalogue au format ´dot´ (pour une visualisation facile des graphes avec OmniGraffle ou Graphviz) avec ´--render-as dot´.

OPTIONS

Notez que tout paramètre valide dans le fichier de configuration est également un argument long valide, bien qu'il puisse être pertinent ou non pour l'action en cours. Par exemple, server et run_mode sont des paramètres valides, vous pouvez donc spécifier --server <nom_serveur>, ou --run_mode <mode_d_exécution> comme argument.

Consultez la documentation du fichier de configuration à l'adresse https://puppet.com/docs/puppet/latest/configuration.html pour la liste complète des paramètres acceptables. Une liste commentée de toutes les options de configuration peut également être générée en exécutant puppet avec --genconfig.

--render-as FORMAT
Le format dans lequel afficher la sortie. Les formats les plus courants sont json, s (string), yaml, et console, mais d'autres options telles que dot sont parfois disponibles.
--verbose
Afficher les logs de manière verbeuse.
--debug
Afficher les informations de débogage.
--terminus _TERMINUS
Les faces d'indirection exposent les sous-systèmes indirectés de Puppet. Ces sous-systèmes sont chacun capables de récupérer et de modifier un type de données spécifique (avec les actions familières de find, search, save et destroy) à partir d'un nombre arbitraire de backends pluggables. Dans le langage de Puppet, ces backends sont appelés terminaux.
Presque tous les sous-systèmes indirectés ont un terminal rest qui interagit avec les données du maître puppet. La plupart d'entre eux ont des terminaux supplémentaires pour divers modèles de données locaux, qui sont à leur tour utilisés par le sous-système indirecté sur le maître puppet chaque fois qu'il reçoit une requête distante.
Le terminal d'une action est souvent déterminé par le contexte, mais doit parfois être défini explicitement. Voir la section « Notes » de la page man de cette face pour plus de détails.

ACTIONS

apply - Trouver et appliquer un catalogue.
SYNTAXE
puppet catalog apply [--terminus _TERMINUS]
DESCRIPTION
Trouve et applique un catalogue. Cette action ne prend aucun argument, mais la source du catalogue peut être gérée avec l'option --terminus.
RETOURNE
Rien. Lorsqu'il est utilisé depuis l'API Ruby, renvoie un objet Puppet::Transaction::Report.
compile - Compiler un catalogue.
SYNTAXE
puppet catalog compile [--terminus _TERMINUS]
DESCRIPTION
Compile un catalogue localement pour un nœud, nécessitant un accès aux modules, au classificateur de nœuds, etc.
RETOURNE
Un catalogue sérialisé.
download - Télécharger le catalogue de ce nœud à partir du serveur maître puppet.
SYNTAXE
puppet catalog download [--terminus _TERMINUS]
DESCRIPTION
Récupère un catalogue du maître puppet et le sauvegarde dans le cache yaml local. Cette action contacte toujours le maître puppet et ignorera les termini alternatifs.
Le catalogue sauvegardé peut être utilisé dans toute action de catalogue ultérieure en spécifiant ´--terminus yaml´ pour cette action.
RETOURNE
Rien.
NOTES
Lorsqu'elle est utilisée depuis l'API Ruby, cette action a pour effet secondaire de laisser Puppet::Resource::Catalog.indirection.terminus_class défini sur yaml. Le terminal doit être explicitement réinitialisé pour les actions de catalogue ultérieures.
find - Récupérer le catalogue du nœud à partir duquel la commande est exécutée.
SYNTAXE
puppet catalog find [--terminus _TERMINUS] [--facts_for_catalog] certname, facts
DESCRIPTION
Récupère le catalogue du nœud à partir duquel la commande est exécutée.
OPTIONS --facts_for_catalog - Non implémenté pour la ligne de commande ; les facts sont collectés en interne.
RETOURNE
Un catalogue sérialisé. Lorsqu'il est utilisé depuis l'API Ruby, renvoie un objet Puppet::Resource::Catalog.
info - Afficher la classe de terminal par défaut pour cette face.
SYNTAXE
puppet catalog info [--terminus _TERMINUS]
DESCRIPTION
Affiche la classe de terminal par défaut pour cette sous-commande. Notez que différents modes d'exécution peuvent avoir différents terminaux par défaut ; en cas de doute, spécifiez le mode d'exécution avec l'option ´--run_mode´.
save - API uniquement : créer ou écraser un objet.
SYNTAXE
puppet catalog save [--terminus _TERMINUS] clé
DESCRIPTION
API uniquement : créer ou écraser un objet. Comme le framework Faces n'accepte actuellement pas de données depuis STDIN, les actions save ne peuvent actuellement pas être invoquées depuis la ligne de commande.
select - Récupérer un catalogue et le filtrer pour les ressources d'un type donné.
SYNTAXE
puppet catalog select [--terminus _TERMINUS] hôte type_ressource
DESCRIPTION
Récupère un catalogue pour l'hôte spécifié, puis recherche toutes les ressources du type demandé.
RETOURNE
Une liste de références de ressources ("Type[titre]"). Lorsqu'elle est utilisée depuis l'API, renvoie un tableau d'objets Puppet::Resource extraits d'un catalogue.
NOTES
Par défaut, cette action récupérera un catalogue à partir du sous-système de compilation de Puppet ; vous devez appeler l'action avec --terminus rest si vous souhaitez récupérer un catalogue à partir du maître puppet.
PROBLÈMES DE FORMATAGE : Cette action ne peut pas actuellement générer de yaml utile ; elle renvoie à la place un catalogue complet. Utilisez plutôt json.

EXEMPLES

apply

Appliquer le catalogue mis en cache localement :

$ puppet catalog apply --terminus yaml

Récupérer un catalogue du maître et l'appliquer, en une seule étape :

$ puppet catalog apply --terminus rest

Exemple API :

# ...
Puppet::Face[:catalog, ´0.0.1´].download
# (Les termini sont des singletons ; catalog.download a pour effet secondaire
# de définir le terminal du catalogue sur yaml)
report  = Puppet::Face[:catalog, ´0.0.1´].apply
# ...

compile

Compiler le catalogue pour le nœud ´mynode´ :

$ puppet catalog compile mynode --codedir ...

download

Récupérer et stocker un catalogue :

$ puppet catalog download

Exemple API :

NAME

puppet-catalog - Retrieve a compiled node catalog

SYNOPSIS

puppet catalog find [--terminus TERMINUS] NODE

puppet catalog upload NODE

puppet catalog download NODE

puppet catalog select [--terminus TERMINUS] NODE TYPE

DESCRIPTION

The puppet-catalog subcommand is used to interact with Puppet's catalog compilation system. It allows you to retrieve, upload, download, and select resources from a compiled node catalog.

OPTIONS

--terminus TERMINUS
Specifies the terminus to use for the specified action. Common termini include rest, yaml, json, and compiler. See NOTES for a full list.

ACTIONS

find
upload
Upload the current node's catalog to the Puppet master.
download
Download the catalog for the specified node from the Puppet master.
select
Select specific resources from a node's catalog.

EXAMPLES

Retrieve the catalog for a node:

$ puppet catalog find somenode.magpie.lan

Download the catalog for a node using the REST terminus:

$ puppet catalog download --terminus rest somenode.magpie.lan

Upload the current node's catalog:

$ puppet catalog upload

This shows some of the underlying indirector actions that can be invoked through the Puppet faces.

Puppet::Face[:plugin, '0.0.1'].download
Puppet::Face[:facts, '0.0.1'].upload
Puppet::Face[:catalog, '0.0.1'].download
# ...

select

Ask the puppet master for a list of managed file resources for a node:

$ puppet catalog select --terminus rest somenode.magpie.lan file

NOTES

This subcommand is an indirector face, which exposes find, search, save, and destroy actions for an indirected subsystem of Puppet. Valid termini for this face include:

  • compiler
  • json
  • msgpack
  • rest
  • store_configs
  • yaml
