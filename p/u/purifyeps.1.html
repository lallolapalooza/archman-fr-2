NOM

purifyeps - rendre un fichier Encapsulated PostScript compatible avec dvips et pdflatex

SYNTAXE

purifyeps --help

purifyeps --version

purifyeps [--fontmap=fichier .fmp] [fichier d'entrée .eps [fichier de sortie .eps]]

purifyeps --make-man[=nom de fichier] [--section=section]

purifyeps --make-ps-man[=nom de fichier] [--section=section]

DESCRIPTION

Bien que pdflatex possède un certain nombre de fonctionnalités intéressantes, sa principale lacune par rapport à latex+dvips standard est son incapacité à lire les fichiers Encapsulated PostScript (EPS) ordinaires, le format graphique le plus courant dans le monde LaTeX. pdflatex ne peut lire que les types de fichiers graphiques suivants :

PDF
La plupart des utilisateurs de pdflatex convertissent leurs documents en PDF à l'aide d'un utilitaire tel que epstopdf. Cela fonctionne bien et préserve la nature vectorielle de l'EPS d'origine. Malheureusement, dvips ne lit pas le PDF, il faut donc maintenir deux versions du graphique si le document doit être traité à la fois avec latex+dvips et pdflatex.
PNG
PNG est un format bitmap et donc mal mis à l'échelle. De plus, dvips ne lit pas PNG, il faut donc maintenir deux versions du graphique si le document doit être traité à la fois avec latex+dvips et pdflatex.
JPEG
JPEG est un format bitmap et donc mal mis à l'échelle. De plus, dvips ne lit pas JPEG, il faut donc maintenir deux versions du graphique si le document doit être traité à la fois avec latex+dvips et pdflatex.
MPS
C'est probablement le format graphique compatible pdflatex le moins utilisé. MPS est en fait une version stylisée d'EPS que MetaPost produit. Comme le PDF, le MPS est un format vectoriel et le reste lorsqu'il est importé dans un document pdflatex. Comme le PDF, dvips ne lit pas le MPS, il faut donc maintenir deux versions du graphique si le document doit être traité à la fois avec latex+dvips et pdflatex.

L'idée derrière purifyeps est qu'il n'y a que quelques différences mineures entre MPS et EPS et qu'un fichier peut être converti dans un format qui correspond simultanément aux spécifications MPS et EPS. purifyeps prend un fichier EPS en entrée, utilise le filtre "mpost" de pstoedit pour convertir le fichier en MetaPost (.mp), exécute mpost sur le fichier pour le convertir en MPS, et effectue finalement quelques retouches sur le résultat pour reconvertir le fichier en EPS, tout en préservant sa capacité à être analysé par pdflatex.

OPTIONS

--help
Affiche "Usage" et "Options" de la documentation purifyeps.
-V, --version
Affiche le numéro de version de purifyeps, les droits d'auteur et la licence.
--fontmap=fichier .fmp
Spécifie le nom d'un fichier indiquant à purifyeps comment mapper les noms de polices TeX aux noms de polices PostScript. [Défaut : mpost.fmp]
--make-man [=nom de fichier]] [--section=section]
Crée automatiquement une page de manuel Unix pour purifyeps. section spécifie la section [défaut : 1 (Commandes utilisateur)]. nom de fichier prend par défaut purifyeps.1 ou un nom de fichier analogue si section est spécifié.
--make-ps-man [=nom de fichier]] [--section=section]
Crée automatiquement une version PostScript de la documentation de purifyeps. La documentation est formatée comme une page de manuel Unix. section spécifie la section [défaut : 1 (Commandes utilisateur)]. nom de fichier prend par défaut purifyeps.ps.

En fonctionnement normal (c'est-à-dire lorsqu'il n'est pas exécuté avec "--help", "--make-man" ou "--make-ps-man"), purifyeps prend le nom d'un fichier d'entrée et d'un fichier de sortie. Le même nom de fichier peut être utilisé sans risque pour les deux. Si le nom du fichier de sortie est omis, la sortie sera dirigée vers la sortie standard. Si le nom du fichier d'entrée est omis, purifyeps lira depuis l'entrée standard.

EXEMPLES

Créez une version PostScript de la documentation de purifyeps, mais appelez-la happydoc.ps au lieu du nom par défaut, purifyeps.ps :

purifyeps --make-ps-man=happydoc.ps

Crée une page de manuel Unix pour purifyeps (au format roff habituel), mais indique qu'elle appartient à la section "LOCAL" au lieu de la section par défaut 1 :

purifyeps --make-man --section=LOCAL

Nettoie sample.eps (mpost.fmp est dans le répertoire courant) :

purifyeps sample.eps sample.eps

Nettoie sample.eps (mpost.fmp est dans un emplacement différent) :

purifyeps --fontmap=/usr/share/pstoedit/mpost.fmp sample.eps sample.eps

Renomme la version nettoyée tout en la nettoyant :

purifyeps sample.eps sample-pure.eps

Fait la même chose, mais dans un pipeline Unix :

cat sample.eps | purifyeps > sample-pure.eps

Lorsque vous exécutez purifyeps, vous devriez voir la sortie de pstoedit et mpost, suivie d'un message de succès de purifyeps :

% cat sample.eps | purifyeps > sample-pure.eps

Copyright (C) 1993 - 2001 Wolfgang Glunz

This is MetaPost, Version 0.641 (Web2C 7.3.1)
(/tmp/purifyeps-jdeGPkh9.mp [1] )

FICHIERS

mpost.fmp
Fichier contenant les mappages entre les noms de polices TeX et PostScript. Voir "NOTES" pour une description du contenu de ce fichier.

BOGUES

La gestion des erreurs pourrait certainement être améliorée. Les messages d'erreur produits par pstoedit et mpost sont parfois ignorés silencieusement. De plus, les erreurs entraînent parfois purifyeps à laisser traîner des fichiers temporaires (purifyeps-#####).

purifyeps est soumis à toutes les limitations qui affectent pstoedit et en particulier le backend "mpost" de pstoedit. Par conséquent, purifyeps ignore certains constructs PostScript, tels que le texte mis à l'échelle de manière non uniforme.

NOTES

purifyeps a besoin d'un fichier qui lui indique comment mapper les noms de polices TeX aux noms de polices PostScript. Ce fichier doit contenir deux colonnes séparées par des espaces. La première liste un nom de police PostScript et la seconde l'équivalent TeX. Les lignes vides et les lignes commençant par "%" sont ignorées. Voici un exemple de fichier .fmp :

% This is a sample font map for purifyeps.
Times-Bold                           ptmb
Times-Italic                         ptmri
Times-Roman                          ptmr
Helvetica                            phvr
Helvetica-Bold                       phvb
Helvetica-Oblique                    phvro
Courier                              pcrr
Courier-Bold                         pcrb
Courier-Oblique                      pcrro

Notez que c'est exactement le même format que celui utilisé par pstoedit. Par défaut, purifyeps recherche dans le répertoire courant un fichier de mappage de polices appelé mpost.fmp. L'option de ligne de commande "--fontmap" indique à purifyeps d'utiliser un fichier de mappage différent, qui sera généralement le fichier mpost.fmp fourni avec pstoedit.
