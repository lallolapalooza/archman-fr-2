PUTENV(3P) Manuel du programmeur POSIX PUTENV(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

putenv — modifier ou ajouter une valeur à un environnement

SYNOPIS

#include <stdlib.h>
int putenv(char *string);

DESCRIPTION

La fonction putenv() utilise l'argument string pour définir des valeurs de variables d'environnement. L'argument string doit pointer vers une chaîne de la forme "nom=valeur". La fonction putenv() rend la valeur de la variable d'environnement nom égale à valeur en modifiant une variable existante ou en en créant une nouvelle. Dans les deux cas, la chaîne pointée par string devient partie de l'environnement, donc modifier la chaîne modifie l'environnement.

La fonction putenv() n'a pas besoin d'être thread-safe.

VALEUR RENVOYÉE

En cas de succès, putenv() renvoie 0 ; sinon, elle renvoie une valeur non nulle et définit errno pour indiquer l'erreur.

ERREURS

La fonction putenv() peut échouer si :

ENOMEM
Une mémoire insuffisante était disponible.

Les sections suivantes sont informatives.

EXEMPLES

Modification de la valeur d'une variable d'environnement

L'exemple suivant modifie la valeur de la variable d'environnement HOME pour qu'elle soit /usr/home.

#include <stdlib.h>
...
static char *var = "HOME=/usr/home";
int ret;
ret = putenv(var);

UTILISATION PAR L'APPLICATION

La fonction putenv() manipule l'environnement pointé par environ, et peut être utilisée conjointement avec getenv().

Voir exec() pour les restrictions sur la modification de l'environnement dans les applications multi-threadées.

Cette routine peut utiliser malloc() pour agrandir l'environnement.

Une erreur potentielle est d'appeler putenv() avec une variable automatique comme argument, puis de retourner de la fonction appelante alors que string fait toujours partie de l'environnement.

Bien que l'espace utilisé par string ne soit plus utilisé une fois qu'une nouvelle chaîne définissant name est passée à putenv(), si un thread de l'application a utilisé getenv() pour récupérer un pointeur vers cette variable, il ne doit pas être libéré en appelant free(). Si la variable d'environnement modifiée est connue du système (comme les variables d'environnement de locale), l'application ne doit jamais libérer le tampon utilisé par des appels précédents à putenv() pour la même variable.

La fonction setenv() est préférée à cette fonction. Une raison est que putenv() est facultative et donc moins portable. Une autre raison est que l'utilisation de putenv() peut ralentir les recherches dans l'environnement, comme expliqué dans la section RATIONALE de getenv().

RATIONALE

Se référer à la section RATIONALE de setenv().
