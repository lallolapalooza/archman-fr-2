NOM

puppet-apply - Applique les manifestes Puppet localement

SYNOPIS

Applique un manifeste Puppet autonome au système local.

UTILISATION

puppet apply [-h|--help] [-V|--version] [-d|--debug] [-v|--verbose] [-e|--execute] [--detailed-exitcodes] [-L|--loadclasses] [-l|--logdest syslog|eventlog|CHEMIN ABSOLU|console] [--noop] [--catalog catalogue] [--write-catalog-summary] fichier

DESCRIPTION

Ceci est l'outil d'exécution Puppet autonome ; utilisez-le pour appliquer des manifestes individuels.

Lorsqu'il est fourni avec un modulepath, via la ligne de commande ou le fichier de configuration, puppet apply peut imiter efficacement le catalogue qui serait servi par un puppet master ayant accès aux mêmes modules, bien qu'il y ait quelques différences subtiles. Lorsqu'il est combiné avec la planification et un système automatisé pour pousser les manifestes, cela peut être utilisé pour implémenter un site Puppet sans serveur.

La plupart des utilisateurs devraient utiliser ´puppet agent´ et ´puppet master´ pour les manifestes à l'échelle du site.

OPTIONS

Toute configuration valide dans le fichier de configuration est un argument long valide pour puppet apply. Par exemple, ´tags´ est une configuration valide, vous pouvez donc spécifier ´--tags classe,tag´ comme argument.

Voir la documentation du fichier de configuration à https://puppet.com/docs/puppet/latest/configuration.html pour la liste complète des paramètres acceptables. Vous pouvez générer une liste commentée de toutes les options de configuration en exécutant puppet avec ´--genconfig´.

  • --debug : Activer le débogage complet.
  • --detailed-exitcodes : Fournir des informations supplémentaires sur l'exécution via des codes de sortie. S'il est activé, ´puppet apply´ utilisera les codes de sortie suivants :
0 : L'exécution a réussi sans modifications ni échecs ; le système était déjà dans l'état souhaité.
1 : L'exécution a échoué.
2 : L'exécution a réussi, et certaines ressources ont été modifiées.
4 : L'exécution a réussi, et certaines ressources ont échoué.
6 : L'exécution a réussi, et comprenait à la fois des modifications et des échecs.
  • --help : Imprimer ce message d'aide
  • --loadclasses : Charger les classes stockées. ´puppet agent´ met en cache les classes configurées (généralement dans /etc/puppetlabs/puppet/classes.txt), et la définition de cette option provoque la définition de toutes ces classes dans votre manifeste Puppet.
  • --logdest : Où envoyer les messages de log. Choisissez entre ´syslog´ (le service syslog POSIX), ´eventlog´ (le journal des événements Windows), ´console´, ou le chemin vers un fichier de log. Par défaut ´console´. Plusieurs destinations peuvent être définies en utilisant une liste séparée par des virgules (par ex. : /chemin/fichier1,console,/chemin/fichier2)"
Un chemin se terminant par ´.json´ recevra une sortie structurée au format JSON. Le fichier log n'aura pas de ´]´ final écrit automatiquement en raison de la nature d'ajout de la journalisation. Il doit être ajouté manuellement pour que le contenu soit un JSON valide.
Un chemin se terminant par ´.jsonl´ recevra une sortie structurée au format Lignes JSON.
  • --noop : Utiliser le mode ´noop´ où Puppet s'exécute en mode no-op ou simulation (dry-run). Ceci est utile pour voir quelles modifications Puppet apportera sans réellement exécuter les changements.
  • --execute : Exécuter un morceau spécifique de code Puppet
  • --test : Activer les options les plus courantes utilisées pour les tests. Ce sont ´verbose´, ´detailed-exitcodes´ et ´show_diff´.
  • --verbose : Afficher des informations supplémentaires.
  • --catalog : Appliquer un catalogue JSON (tel que généré avec ´puppet master --compile´). Vous pouvez spécifier un fichier JSON ou rediriger du JSON depuis l'entrée standard.
  • --write-catalog-summary Après compilation, enregistre la liste des ressources et des classes dans le nœud dans le répertoire d'état nommé classes.txt et resources.txt

EXEMPLE

$ puppet apply -e ´notify { "salut le monde": }´
$ puppet apply -l /tmp/manifest.log manifest.pp
$ puppet apply --modulepath=/root/dev/modules -e "include ntpd::server"
$ puppet apply --catalog catalog.json
