NOM

puppet-node - Afficher et gérer les définitions de nœuds.

SYNOPSIS

puppet node action [--terminus _TERMINUS]

DESCRIPTION

Cette sous-commande interagit avec les objets nœuds, qui sont utilisés par Puppet pour construire un catalogue. Un objet nœud se compose des facts du nœud, de son environnement, des paramètres du nœud (exposés dans l'analyseur comme des variables de portée supérieure) et de ses classes.

OPTIONS

Notez que tout paramètre valide dans le fichier de configuration est également un argument long valide, bien qu'il puisse être pertinent ou non pour l'action en cours. Par exemple, server et run_mode sont des paramètres valides, vous pouvez donc spécifier --server <servername>, ou --run_mode <runmode> comme argument.

Voir la documentation du fichier de configuration sur https://puppet.com/docs/puppet/latest/configuration.html pour la liste complète des paramètres acceptables. Une liste commentée de toutes les options de configuration peut également être générée en exécutant puppet avec --genconfig.

--render-as FORMAT
Le format dans lequel rendre la sortie. Les formats les plus courants sont json, s (string), yaml et console, mais d'autres options telles que dot sont parfois disponibles.
--verbose
Indique s'il faut enregistrer de manière détaillée.
--debug
Indique s'il faut enregistrer des informations de débogage.
--terminus _TERMINUS
Les faces indirectrices exposent des sous-systèmes indirects de Puppet. Ces sous-systèmes sont chacun capables de récupérer et de modifier un type de données spécifique (avec les actions familières find, search, save et destroy) à partir d'un nombre arbitraire de backends plugables. Dans le jargon de Puppet, ces backends sont appelés terminaux.
Presque tous les sous-systèmes indirects ont un terminal rest qui interagit avec les données du maître Puppet. La plupart d'entre eux ont des terminaux supplémentaires pour divers modèles de données locaux, qui sont à leur tour utilisés par le sous-système indirect lorsqu'il reçoit une requête distante.
Le terminal d'une action est souvent déterminé par le contexte, mais peut parfois nécessiter d'être défini explicitement. Voir la section "Notes" de la page de manuel de cette face pour plus de détails.

ACTIONS

clean - Nettoyer les certificats signés, les faits mis en cache, les objets nœuds et les rapports stockés par le maître Puppet
SYNOPSIS
puppet node clean [--terminus _TERMINUS] hôte1 [hôte2 ...]
DESCRIPTION
Nettoie les informations suivantes qu'un maître Puppet connaît sur un nœud :
Certificats signés - ($vardir/ssl/ca/signed/node.domain.pem)
Faits mis en cache - ($vardir/yaml/facts/node.domain.yaml)
Objets nœuds mis en cache - ($vardir/yaml/node/node.domain.yaml)
Rapports - ($vardir/reports/node.domain)
NOTE : cette action nettoie désormais les certificats via l'API CA du serveur Puppet. Un serveur en cours d'exécution est nécessaire pour que les certificats soient nettoyés.
find - Récupérer un objet nœud.
SYNOPSIS
puppet node find [--terminus _TERMINUS] hôte
DESCRIPTION
Récupère un objet nœud.
RETOURNE
Une table de hachage contenant les classes du nœud, son environnement, son expiration, son nom, ses paramètres (ses faits, combinés avec tous les paramètres définis par ENC) et son heure. Lorsqu'il est utilisé depuis l'API Ruby : un objet Puppet::Node.
PROBLÈMES DE RENDU : Le rendu en chaîne de caractères et en JSON est actuellement cassé ; les objets nœuds ne peuvent être rendus qu'en yaml.
info - Afficher la classe de terminal par défaut pour cette face.
SYNOPSIS
puppet node info [--terminus _TERMINUS]
DESCRIPTION
Affiche la classe de terminal par défaut pour cette sous-commande. Notez que différents modes d'exécution peuvent avoir des terminaux par défaut différents ; en cas de doute, spécifiez le mode d'exécution avec l'option '--run_mode'.

EXEMPLES

find

Récupérer un nœud "vide" (pas de classes, pas de paramètres imposés par ENC, et un environnement "production") :

$ puppet node find somenode.puppetlabs.lan --terminus plain --render-as yaml

Récupérer un nœud en utilisant l'ENC configuré du serveur Puppet :

$ puppet node find somenode.puppetlabs.lan --terminus exec --run_mode server --render-as yaml

Récupérer le même nœud du serveur Puppet :

$ puppet node find somenode.puppetlabs.lan --terminus rest --render-as yaml

NOTES

Cette sous-commande est une face d'indirecteur, qui expose les actions find, search, save et destroy pour un sous-système indirect de Puppet. Les terminaux valides pour cette face incluent :

  • exec
  • json
  • memory
  • msgpack
  • plain
  • rest
  • store_configs
  • yaml
