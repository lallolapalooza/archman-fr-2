NOM

putty - Client GUI SSH, Telnet, Rlogin et SUPDUP pour X

SYNTAXE

putty [ options ] [ hote ]

DESCRIPTION

putty est un client graphique SSH, Telnet, Rlogin et SUPDUP pour X. C'est un portage direct du client SSH de mêmes nom pour Windows.

OPTIONS

Les options de ligne de commande supportées par putty sont :

--display nom-affichage
Spécifie l'affichage X sur lequel ouvrir putty. (Notez que cette option a un double tiret, alors que les autres n'en ont pas. C'est parce que cette option est fournie automatiquement par GTK. Désolé.)
-fn nom-police
Spécifie la police à utiliser pour le texte normal affiché dans le terminal. Par exemple, -fn fixed, -fn "Monospace 12".
-fb nom-police
Spécifie la police à utiliser pour le texte en gras affiché dans le terminal. Si la ressource BoldAsColour est définie à 1 (par défaut), le texte en gras sera affiché dans des couleurs différentes au lieu d'une police différente, donc cette option sera ignorée. Si BoldAsColour est définie à 0 ou 2 et que vous ne spécifiez pas de police pour le gras, putty superposera la police normale pour la rendre plus audacieuse.
-fw nom-police
Spécifie la police à utiliser pour les caractères double largeur (généralement du texte chinois, japonais et coréen) affichés dans le terminal.
-fwb nom-police
Spécifie la police à utiliser pour les caractères double largeur en gras (généralement du texte chinois, japonais et coréen). Comme -fb, cela sera ignoré à moins que la ressource BoldAsColour ne soit définie à 0 ou 2.
-geometry geometrie
Spécifie la taille du terminal, en lignes et colonnes de texte. Voir X(7) pour plus d'informations sur la syntaxe des spécifications de géométrie.
-sl lignes
Spécifie le nombre de lignes de défilement à sauvegarder au-dessus du terminal.
-fg couleur
Spécifie la couleur de premier plan à utiliser pour le texte normal.
-bg couleur
Spécifie la couleur d'arrière-plan à utiliser pour le texte normal.
-bfg couleur
Spécifie la couleur de premier plan à utiliser pour le texte en gras, si la ressource BoldAsColour est définie à 1 (par défaut) ou 2.
-bbg couleur
Spécifie la couleur de premier plan à utiliser pour le texte en gras et en vidéo inversée, si la ressource BoldAsColour est définie à 1 (par défaut) ou 2. (Cette couleur doit être comprise comme la version en gras de la couleur d'arrière-plan ; elle n'apparaît donc que lorsque du texte est affiché *dans* la couleur d'arrière-plan.)
-cfg couleur
Spécifie la couleur de premier plan à utiliser pour le texte couvert par le curseur.
-cbg couleur
Spécifie la couleur d'arrière-plan à utiliser pour le texte couvert par le curseur. En d'autres termes, c'est la couleur principale du curseur.
-title titre
Spécifie le titre initial de la fenêtre du terminal. (Celui-ci peut être modifié sous le contrôle du serveur.)
-sb- ou +sb
Indique à putty de ne pas afficher de barre de défilement.
-sb
Indique à putty d'afficher une barre de défilement : c'est l'opposé de -sb-. C'est l'option par défaut : vous n'aurez probablement besoin de la spécifier explicitement que si vous avez modifié la valeur par défaut à l'aide de la ressource ScrollBar.
-log fichier-journal, -sessionlog fichier-journal
Cette option permet à putty de journaliser toute la sortie du terminal dans un fichier tout en l'affichant dans le terminal.
-sshlog fichier-journal
-sshrawlog fichier-journal
Pour les connexions SSH, ces options permettent à putty de journaliser les détails du protocole dans un fichier. (Certains de ces détails peuvent être sensibles, bien que par défaut un effort soit fait pour supprimer les mots de passe évidents.)

-sshlog journalise les paquets SSH décodés et d'autres événements (ceux que -v imprimerait). -sshrawlog journalise en plus les données brutes des paquets cryptés.

-logoverwrite
Si putty est configuré pour écrire dans un fichier journal existant, supprime le fichier existant.
-logappend
Si putty est configuré pour écrire dans un fichier journal existant, ajoute les nouvelles données du journal à la fin du fichier existant.
-cs jeu-caracteres
Cette option spécifie le jeu de caractères dans lequel putty doit supposer que la session fonctionne. Ce jeu de caractères sera utilisé pour interpréter toutes les données reçues de la session, et toute saisie que vous tapez ou collez dans putty sera convertie dans ce jeu de caractères avant d'être envoyée à la session.

Tout nom de jeu de caractères valide dans un en-tête MIME (et supporté par putty) devrait être valide ici (les exemples sont `ISO-8859-1', `windows-1252' ou `UTF-8'). De plus, tout encodage de caractères valide dans une description de police logique X devrait être valide (`ibm-cp437', par exemple).

Le comportement par défaut de putty est d'utiliser le même encodage de caractères que sa police principale. Si vous fournissez une police Unicode (iso10646-1), il utilisera par défaut le jeu de caractères UTF-8.

Les noms de jeux de caractères ne sont pas sensibles à la casse.

-nethack
Indique à putty d'activer le mode pavé numérique NetHack, dans lequel le pavé numérique génère les touches de direction hjklyubn de NetHack. Cela vous permet de jouer à NetHack avec le pavé numérique sans avoir à utiliser l'option number_pad de NetHack (qui vous oblige à appuyer sur 'n' avant tout compteur de répétition). Ainsi, vous pouvez vous déplacer avec le pavé numérique, et entrer les compteurs de répétition avec les touches numériques normales.
-help, --help
Affiche un message résumant les options disponibles.
-pgpfp
Affiche les empreintes des clés maîtres PGP de PuTTY, pour aider à vérifier les nouveaux fichiers publiés par l'équipe PuTTY.
-load session
Charge une session sauvegardée par son nom. Cela vous permet de lancer une session sauvegardée directement depuis la ligne de commande sans avoir à passer d'abord par la boîte de dialogue de configuration.
-ssh, -telnet, -rlogin, -supdup, -raw, -ssh-connection, -serial
Sélectionne le protocole que putty utilisera pour établir la connexion.
-proxycmd commande
Au lieu d'établir une connexion TCP, utilise commande comme proxy ; le trafic réseau sera redirigé vers l'entrée et la sortie standard de commande. commande doit être un seul mot, il est donc probable qu'elle nécessite des guillemets par le shell.

Les chaînes spéciales %host et %port dans commande seront remplacées par le nom d'hôte et le numéro de port auxquels vous souhaitez vous connecter ; pour obtenir un signe % littéral, entrez %%.

Les échappements par antislash sont également supportés, tels que des séquences comme \n étant remplacées par un saut de ligne littéral ; pour obtenir un antislash littéral, entrez \\. (Un échappement supplémentaire peut être requis par le shell.)

(Voir le manuel principal de PuTTY pour des détails complets sur les tokens supportés délimités par % et antislash, bien que la plupart d'entre eux ne soient probablement pas très utiles dans ce contexte.)

/p>
-l nom d'utilisateur
Spécifie le nom d'utilisateur à utiliser lors de la connexion au serveur.
-L [addr_source:]port_source:hote_destination:port_destination
Configure un transfert de port local : écoute sur port_source (ou addr_source:port_source si spécifié), et transfère toute connexion via la connexion SSH vers l'adresse de destination hote_destination:port_destination. Fonctionne uniquement en SSH.
-R [addr_source:]port_source:hote_destination:port_destination
Configure un transfert de port distant : demande au serveur SSH d'écouter sur port_source (ou addr_source:port_source si spécifié), et de transférer toute connexion en retour via la connexion SSH, où le client les transmettra à l'adresse de destination hote_destination:port_destination. Fonctionne uniquement en SSH.
-D [addr_source:]port_source
Configure un transfert de port dynamique. Le client écoute sur port_source (ou addr_source:port_source si spécifié), et implémente un serveur SOCKS. Vous pouvez donc pointer des applications compatibles SOCKS vers ce port et elles utiliseront automatiquement la connexion SSH pour tunneliser toutes leurs connexions. Fonctionne uniquement en SSH.
-P port
Spécifie le port sur lequel se connecter au serveur.
-A, -a
Active (-A) ou désactive (-a) le transfert de l'agent SSH. Actuellement, cela ne fonctionne qu'avec OpenSSH et SSH-1.
-X, -x
Active (-X) ou désactive (-x) le transfert X11.
-T, -t
Active (-t) ou désactive (-T) l'allocation d'un pseudo-terminal côté serveur.
-C
Active la compression de type zlib sur la connexion.
-1, -2
Sélectionne la version du protocole SSH 1 ou 2.
-4, -6
Force l'utilisation d'IPv4 ou d'IPv6 pour les connexions réseau.
-i fichier_clé
Fichier de clé privée pour l'authentification de l'utilisateur. Pour les clés SSH-2, ce fichier de clé doit être au format PPK de PuTTY, et non au format OpenSSH ou autre.

Si vous utilisez un agent d'authentification, vous pouvez également spécifier une clé publique ici (au format RFC 4716 ou OpenSSH), pour identifier quelle clé de l'agent utiliser.

-noagent
N'essaie pas d'utiliser un agent d'authentification pour l'authentification locale. (Cela n'affecte pas le transfert d'agent.)
-agent
Autorise l'utilisation d'un agent d'authentification. (Cette option n'est nécessaire que pour outrepasser un réglage dans une session enregistrée.)
-no-trivial-auth
Se déconnecte de tout serveur SSH qui accepte l'authentification sans jamais avoir demandé de mot de passe, de signature ou de jeton. (Vous pourriez vouloir activer ceci pour un serveur qui vous mettra toujours au défi, par exemple pour vous assurer de ne pas taper accidentellement la phrase secrète de votre fichier de clé dans un serveur compromis qui usurpe l'invite de phrase secrète de PuTTY.)
-hostkey clé
Spécifie une clé publique d'hôte acceptable. Cette option peut être spécifiée plusieurs fois ; chaque clé peut être soit une empreinte digitale (SHA256:AbCdE..., 99:aa:bb:..., etc.) soit un bloc encodé en base64 au format d'une seule ligne d'OpenSSH.

La spécification de cette option remplace la gestion automatique des clés d'hôte ; seules les clés spécifiées sur la ligne de commande seront acceptées (sauf si une session enregistrée surcharge également les clés d'hôte, auquel cas celles-ci seront ajoutées), et le cache des clés d'hôte ne sera pas écrit.

-sercfg chaîne_configuration
Spécifie les paramètres de configuration pour le port série, en mode -serial. chaîne_configuration doit être une liste de paramètres de configuration séparés par des virgules, comme suit :
•
Un seul chiffre de 5 à 9 définit le nombre de bits de données.
•
`1', `1.5' ou `2' définit le nombre de bits d'arrêt.
•
Toute autre chaîne numérique est interprétée comme un débit en bauds.
•
Une seule lettre minuscule spécifie la parité : `n' pour aucune, `o' pour impair, `e' pour pair, `m' pour marque et `s' pour espace.
•
Une seule lettre majuscule spécifie le contrôle de flux : `N' pour aucun, `X' pour XON/XOFF, `R' pour RTS/CTS et `D' pour DSR/DTR.

SESSIONS ENREGISTRÉES

Les sessions enregistrées sont stockées dans un sous-répertoire .putty/sessions dans votre répertoire personnel.
