NOM

puppet-facts - Récupérer et stocker des faits.

SYNTAXE

puppet facts action [--terminus _TERMINUS]

DESCRIPTION

Cette sous-commande gère les faits, qui sont des collections d'informations système normalisées utilisées par Puppet. Elle peut lire les faits directement depuis le système local (avec le terminus facter par défaut).

OPTIONS

Notez que tout paramètre valide dans le fichier de configuration est également un argument long valide, bien qu'il puisse ou non être pertinent pour l'action en cours. Par exemple, server et run_mode sont des paramètres valides, vous pouvez donc spécifier --server <nom_serveur>, ou --run_mode <mode_d_exécution> comme argument.

Consultez la documentation du fichier de configuration à l'adresse https://puppet.com/docs/puppet/latest/configuration.html pour la liste complète des paramètres acceptables. Une liste commentée de toutes les options de configuration peut également être générée en exécutant puppet avec --genconfig.

--render-as FORMAT
Le format dans lequel afficher la sortie. Les formats les plus courants sont json, s (chaîne), yaml et console, mais d'autres options telles que dot sont parfois disponibles.
--verbose
Afficher la journalisation de manière détaillée.
--debug
Afficher les informations de débogage.
--terminus _TERMINUS
Les faces d'indexation exposent des sous-systèmes indexés de Puppet. Ces sous-systèmes sont chacun capables de récupérer et de modifier un type spécifique de données (avec les actions familières find, search, save et destroy) à partir d'un nombre arbitraire de backends enfichables. Dans le langage de Puppet, ces backends sont appelés des terminaux.
Presque tous les sous-systèmes indexés ont un terminus rest qui interagit avec les données du maître puppet. La plupart d'entre eux ont des terminaux supplémentaires pour divers modèles de données locaux, qui sont à leur tour utilisés par le sous-système indexé sur le maître puppet chaque fois qu'il reçoit une requête à distance.
Le terminus pour une action est souvent déterminé par le contexte, mais il peut parfois devoir être défini explicitement. Voir la section "Notes" de cette page de manuel de face pour plus de détails.

ACTIONS

find - Récupérer les faits d'un nœud.
SYNTAXE
puppet facts find [--terminus _TERMINUS] [nom_certificat_nœud]
DESCRIPTION
Récupérer les faits d'un nœud.
RETOURNE
Une table contenant des métadonnées et (sous la clé "values") l'ensemble des faits pour le nœud demandé. Lorsqu'elle est utilisée depuis l'API Ruby : un objet Puppet::Node::Facts.
PROBLÈMES DE RENDU : Les faits ne peuvent actuellement pas être rendus sous forme de chaîne ; utilisez yaml ou json.
NOTES
Lors de l'utilisation du terminus facter, l'argument hôte est ignoré.
info - Afficher la classe de terminus par défaut pour cette face.
SYNTAXE
puppet facts info [--terminus _TERMINUS]
DESCRIPTION
Affiche la classe de terminus par défaut pour cette sous-commande. Notez que différents modes d'exécution peuvent avoir différents terminaux par défaut ; en cas de doute, spécifiez le mode d'exécution avec l'option ´--run_mode´.
save - API uniquement : créer ou écraser un objet.
SYNTAXE
puppet facts save [--terminus _TERMINUS] clé
DESCRIPTION
API uniquement : créer ou écraser un objet. Comme le framework Faces n'accepte pas actuellement de données depuis STDIN, les actions de sauvegarde ne peuvent actuellement pas être invoquées depuis la ligne de commande.
show - Récupérer les faits du nœud actuel.
SYNTAXE
puppet facts [--terminus _TERMINUS] [--config-file chemin] [--custom-dir chemin] [--external-dir chemin] [--no-block] [--no-cache] [--show-legacy] [--value-only] [--timing] [faits]
DESCRIPTION
Lit les faits du système local en utilisant le terminus facter. Une requête peut être fournie pour récupérer uniquement un fait spécifique ou un ensemble de faits.
OPTIONS --config-file <chemin> - L'emplacement du fichier de configuration pour Facter.
--custom-dir <chemin> - Le chemin vers un répertoire contenant des faits personnalisés.
--external-dir <chemin> - Le chemin vers un répertoire contenant des faits externes.
--no-block - Désactive le mécanisme de blocage des faits.
--no-cache - Désactive le mécanisme de mise en cache des faits.
--show-legacy - Affiche les faits hérités lors de la requête de tous les faits.
--timing - Affiche le temps nécessaire à la résolution de chaque fait.
--value-only - Affiche uniquement la valeur lorsque l'action est appelée avec une seule requête
RETOURNE
La sortie de facter avec les faits spécifiques à puppet ajoutés.
NOTES
upload - Téléverser les faits locaux sur le maître puppet.
SYNTAXE
puppet facts upload [--terminus _TERMINUS]
DESCRIPTION
Lit les faits du système local en utilisant le terminus facter, puis sauvegarde les faits retournés en utilisant le terminus rest.
RETOURNE
Rien.
NOTES
Cette action nécessite que le fichier auth.conf du serveur Puppet autorise l'accès PUT ou save au point de terminaison de l'API /puppet/v3/facts.
Pour plus de détails sur la configuration du auth.conf du serveur Puppet, voir :
https://puppet.com/docs/puppetserver/latest/config_file_auth.html

EXEMPLES

find

Obtenir les faits du système local :

$ puppet facts find

show

récupérer les faits :

$ puppet facts show os

upload

Téléverser les faits :

$ puppet facts upload

NOTES

Cette sous-commande est une face d'indexation, qui expose les actions find, search, save et destroy pour un sous-système indexé de Puppet. Les termini valides pour cette face incluent :

  • facter
  • json
  • memory
  • network_device
  • rest
  • store_configs
  • yaml
