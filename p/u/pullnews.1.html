NOM

pullnews - Récupère des actualités depuis plusieurs serveurs de news et les alimente vers un autre

SYNTAXE

pullnews [-BhnOqRx] [-a hashfeed] [-b fraction] [-c config] [-C largeur] [-d niveau] [-f fraction] [-F fauxsaut] [-g groupes] [-G newsgroups] [-H en-têtes] [-k pointcontrole] [-l fichierjournal] [-L taille] [-m modèles-en-tête] [-M num] [-N délaiattente] [-p port] [-P limite-sauts] [-Q niveau] [-r fichier] [-s serveur-vers[:port][_modetls]] [-S max-exécution] [-t tentatives] [-T pause-connexion] [-w num] [-z pause-article] [-Z pause-groupe] [serveur-depuis ...]

PRÉREQUIS

Le module "Net::NNTP" doit être installé. Ce module est disponible dans le cadre de la distribution libnet et est fourni avec les versions récentes de Perl. Pour les versions plus anciennes de Perl, vous pouvez le télécharger depuis http://www.cpan.org/.

DESCRIPTION

pullnews lit un fichier de configuration nommé pullnews.marks et se connecte aux serveurs en amont listés là comme client lecteur. Ce fichier est recherché dans pathdb lorsque pullnews est exécuté par l'utilisateur défini dans runasuser dans inn.conf (qui est par défaut l'utilisateur "news") ; sinon, ce fichier est recherché dans le répertoire personnel de l'utilisateur en cours d'exécution.

Par défaut, pullnews se connecte à tous les serveurs listés dans le fichier de configuration, mais vous pouvez limiter pullnews à des serveurs spécifiques en les listant sur la ligne de commande : une liste de noms de serveurs séparés par des espaces peut être spécifiée, comme serveur-depuis pour l'un d'eux. Pour chaque serveur auquel il se connecte, il récupère les articles et les alimente vers le serveur de destination via les commandes IHAVE ou POST. Cela signifie que le système sur lequel pullnews est exécuté doit avoir un accès d'alimentation au serveur de news de destination.

pullnews est conçu pour les très petits sites qui ne veulent pas s'encombrer de la mise en place d'un peering traditionnel et n'est pas destiné à gérer des flux importants.

Dans le cas où vous auriez des pairs actifs et ne voudriez pas leur propager les articles que vous récupérez des serveurs en amont, vous devriez ajouter un faux saut avec l'indicateur -F à tous les articles récupérés, et ajouter ce même faux saut dans le sous-champ d'exclusion de tous les sites configurés dans votre fichier newsfeeds qui ne devraient pas recevoir ces articles. Par exemple, en utilisant "pullnews -F myserverimported", changez "nomsite:*:Tm:innfeed!" en "nomsite/myserverimported:*:Tm:innfeed!" pour chaque nomsite dans newsfeeds auquel vous ne voulez pas alimenter les articles récupérés (comme vos pairs sortants et une éventuelle entrée "inpaths!"). Les entrées comme "ME", "controlchan!", "innfeed!" ou "nocem!" n'ont pas besoin de cette exclusion.

OPTIONS

-a hashfeed
Cette option est une manière déterministe de contrôler le flux des articles et de diviser un flux. Le paramètre hashfeed doit être sous la forme "valeur/mod" ou "début-fin/mod". Le Message-ID de chaque article est haché en utilisant MD5, ce qui produit un hachage de 128 bits. Les 32 bits les plus bas sont ensuite utilisés par défaut comme valeur hashfeed (qui est un entier). Si la valeur hashfeed modulo "mod" plus un égale "valeur" ou est comprise entre "début" et "fin", pullnews alimentera l'article. Tous ces nombres doivent être des entiers.

Par exemple :

pullnews -a 1/2      Alimente environ 50% de tous les articles.
pullnews -a 2/2      Alimente l'autre 50% de tous les articles.

Un autre exemple :

pullnews -a 1-3/10   Alimente environ 30% de tous les articles.
pullnews -a 4-5/10   Alimente environ 20% de tous les articles.
pullnews -a 6-10/10  Alimente environ 50% de tous les articles.

Vous pouvez utiliser une syntaxe étendue de la forme "valeur/mod:décalage" ou "début-fin/mod:décalage" (l'utilisation d'un tiret bas "_" à la place des deux points ":" est également reconnue). Comme MD5 génère une valeur de retour de 128 bits, il est possible de spécifier à partir de quel décalage en octets l'entier de 32 bits utilisé par hashfeed commence. La valeur par défaut pour "décalage" est ":0" et treize valeurs chevauchantes de ":0" à ":12" peuvent être utilisées. Jusqu'à quatre valeurs totalement indépendantes existent : ":0", ":4", ":8" et ":12".

Par conséquent, cela permet de générer un deuxième niveau de distribution déterministe. En effet, si pullnews alimente "1/2", il peut continuer à diviser grâce à "1-3/9:4" par exemple. Jusqu'à quatre niveaux de distribution déterministe peuvent être utilisés.

L'algorithme est compatible avec celui utilisé par Diablo 5.1 et supérieur.

-b fraction
Retour en arrière sur réinitialisation de la numérotation du serveur. Spécifie la proportion (de 0.0 à 1.0) des articles d'un groupe à récupérer lorsque le numéro d'article du serveur est inférieur à notre maximum pour ce groupe. Lorsque fraction est 1.0, récupère tous les articles sur un serveur renuméroté. Par défaut, ne fait rien.
-B
Le flux est uniquement en en-têtes, c'est-à-dire que pullnews n'envoie que les en-têtes des articles, plus une ligne vide. Il ajoute le champ d'en-tête Bytes si l'article n'en possède pas déjà un, et ne conserve le corps que si l'article est un article de contrôle.
-c config
Normalement, le fichier de configuration est stocké dans pullnews.marks dans pathdb lorsque pullnews est exécuté en tant qu'utilisateur news, ou sinon dans le répertoire personnel de l'utilisateur en cours d'exécution. Si -c est donné, config sera utilisé comme fichier de configuration à la place. Ceci est utile si vous exécutez pullnews en tant qu'utilisateur système sur une base automatisée hors cron ou en tant qu'utilisateur individuel, plutôt que l'utilisateur news.

Voir "FICHIER DE CONFIGURATION" ci-dessous pour le format de ce fichier.

-C largeur
Utilise largeur caractères par ligne pour le tableau de progression. La valeur par défaut est 50.
-d niveau
Définit le niveau de débogage à l'entier niveau (jusqu'à 4) ; plus la valeur augmente, plus la sortie de débogage sera détaillée. La valeur par défaut est 0.
-f fraction
Change la proportion d'articles à récupérer de chaque groupe à fraction et doit être dans la plage de 0.0 à 1.0 (1.0 étant la valeur par défaut).
-F fauxsaut
Ajoute fauxsaut en tant qu'hôte au début du champ d'en-tête Path des articles alimentés.
-g groupes
Spécifie une collection de groupes à récupérer. groupes est une liste de groupes de news séparés par des virgules (uniquement des virgules, pas d'espaces). Chaque groupe doit être défini dans le fichier de configuration, et seuls les hôtes distants qui diffusent ces groupes seront contactés. Notez qu'il s'agit d'une simple liste de groupes, pas d'une expression wildcard, et les wildcards ne sont pas pris en charge.
-G newsgroups
Ajoute la liste de groupes newsgroups séparés par des virgules à la liste des groupes à récupérer.

Voir l'option -g pour plus de détails.

-h
N'écrit que les en-têtes des articles. Voir l'option -B pour plus de détails.
-H en-têtes
Ajoute un champ d'en-tête en-têtes à tous les articles qui seront alimentés, s'il n'est pas déjà présent. L'en-tête en-têtes doit être une chaîne de caractères au format d'un en-tête standard.
-k pointcontrole
Utilise pointcontrole comme nom de fichier pour les points de contrôle au lieu du nom par défaut "pullnews.marks". Le fichier sera situé dans le répertoire pathdb du système (par exemple, /var/lib/inn/pathdb/) ou dans le répertoire personnel de l'utilisateur si le programme n'est pas exécuté par l'utilisateur news.
-l fichierjournal
Écrit les journaux dans fichierjournal au lieu d'utiliser le fichier journal par défaut défini dans inn.conf.
-L taille
Fixe la taille maximale des articles en octets à taille. Les articles plus volumineux seront ignorés.
-m modèles-en-tête
Ne conserve que les articles dont les en-têtes correspondent à l'un des modèles modèles-en-tête, qui sont des expressions wildmat séparées par des virgules. Par défaut, tous les articles sont conservés.
-M num
Ne récupérer que num articles par groupe. Utile pour le test.
-n
Ne pas construire la table des groupes. Cela évite que pullnews ne se connecte pour la première fois à chaque serveur en utilisant la commande LIST NEWSGROUPS. Cela peut être utile si le serveur distant ne supporte pas cette commande, ou si vous souhaitez simplement alimenter des groupes qui ne sont pas réellement présents sur le serveur distant.
-N délaiattente
Définit le délai d'attente pour les commandes NNTP à délaiattente secondes. La valeur par défaut est 300.
-O
Ne récupère que les articles dont le Message-ID correspond à ceux qui sont déjà présents dans la base de données des articles. Cela peut être utile pour récupérer des articles perdus.
-p port
Utilise le port port pour se connecter aux serveurs distants. La valeur par défaut est 119.
-P limite-sauts
Définit la limite de sauts pour le champ Path à limite-sauts. La valeur par défaut est 10.
-q
Mode silencieux : ne pas afficher le tableau de progression.
-Q niveau
Définit le niveau de qualité de la journalisation à l'entier niveau (jusqu'à 4). La valeur par défaut est 1.
-r fichier
Lit la liste des groupes à récupérer à partir du fichier spécifié, au lieu de les lire à partir du fichier de configuration.
-R
Ne fait pas de rapprochement avec la base de données des articles existants sur le serveur. Cela signifie que tous les articles sont récupérés.
-s serveur-vers[:port][_modetls]
Spécifie le serveur de destination où envoyer les articles. Par défaut, pullnews essaie d'envoyer les articles au serveur défini dans la variable newspost de inn.conf. Le port peut être spécifié après le nom du serveur, séparé par deux-points. Le mode TLS peut être spécifié en ajoutant _starttls ou _ssl après le port ou le nom du serveur. Par exemple : serveur.example.com:119_starttls.
-S max-exécution
Ne pas exécuter pullnews pendant plus de max-exécution secondes. La valeur par défaut est 0 (pas de limite).
-t tentatives
Nombre de tentatives de connexion au serveur avant d'abandonner. La valeur par défaut est 3.
-T pause-connexion
Spécifie le temps en secondes à attendre entre deux tentatives de connexion au serveur. La valeur par défaut est 30.
-w num
Ne récupère que les articles les plus récents (basés sur le numéro d'article) dans chacun des groupes spécifiés. Le nombre d'articles à récupérer est spécifié par num. Ceci est particulièrement utile pour le chargement initial des groupes.
-x
Ne pas écrire la sortie dans le fichier journal. Cela désactive complètement la journalisation, à l'exception des messages d'erreur qui sont toujours affichés sur la sortie d'erreur standard.
-z pause-article
Spécifie le temps en secondes à attendre entre la récupération de deux articles consécutifs. La valeur par défaut est 0.
-Z pause-groupe
Spécifie le temps en secondes à attendre entre le traitement de deux groupes consécutifs. La valeur par défaut est 0.

CONFIG FILE

Le fichier de configuration (par défaut pullnews.marks) contient une liste de groupes de news, avec pour chacun d'eux le nom de l'hôte distant et le nombre d'articles qui ont été lus. Le format est le suivant :

nom-hôte-distant:groupe1,groupe2,...:nombre-lus

Par exemple :

news.example.com:comp.sources.misc,comp.sources.unix:12345
another.example.org:rec.woodworking:5678

Pour chaque ligne, pullnews essaiera de se connecter à nom-hôte-distant et de récupérer tous les articles plus récents que nombre-lus pour les groupes spécifiés.

Si le nom d'hôte distant est préfixé par "!", les articles seront uniquement récupérés et stockés localement, sans être envoyés à un autre serveur. Ce mode est utile pour la mise en cache ou pour la création de serveurs de news locaux sans accès d'alimentation.

Si le nom d'hôte distant est préfixé par "@", cela signifie que la connexion doit être faite en utilisant TLS (SSL). La même option que celle utilisée pour la ligne de commande avec l'indicateur -s s'appliquera.

Si le nom d'hôte distant est préfixé par "@@", cela signifie que la connexion doit être faite en utilisant STARTTLS.

Il est possible de spécifier plusieurs groupes sur une seule ligne, séparés par des virgules. Il est également possible de spécifier des groupes à l'aide de caractères génériques (wildcards) comme dans comp.sources.*.

Si la ligne commence par "#", elle est considérée comme un commentaire.

Le fichier de configuration est automatiquement mis à jour après chaque exécution réussie de pullnews pour refléter le dernier numéro d'article lu pour chaque groupe.

NOTES

pullnews est conçu pour être exécuté périodiquement, par exemple via cron, pour récupérer les nouvelles de serveurs distants.

Il est fortement recommandé d'utiliser l'option -F avec un nom d'hôte factice approprié, et de l'exclure de la distribution à vos pairs sortants dans le fichier newsfeeds. Cela empêche la propagation des articles récupérés à vos pairs, ce qui pourrait autrement entraîner des doublons ou des problèmes de bande passante.

La gestion des erreurs est basique. En cas de problème, le script peut s'arrêter prématurément. Il est conseillé de surveiller la sortie et les journaux de pullnews.

L'utilisation de l'option -b doit être faite avec prudence, car elle peut entraîner la récupération d'un grand nombre d'articles, potentiellement des centaines de milliers, si un groupe a été renuméroté.

Pour les serveurs qui n'acceptent pas de connexion NNTP anonyme, vous devez utiliser la commande ichat pour autoriser la connexion de l'hôte sur lequel pullnews s'exécute.

EXEMPLES

Pour récupérer tous les articles des groupes comp.sources.* et rec.arts.cinema du serveur news.example.com et les envoyer au serveur de news local :

pullnews -g comp.sources.*,rec.arts.cinema news.example.com

Pour récupérer environ 10% des articles de tous les groupes du serveur news.example.com et les alimenter au serveur localhost, en ajoutant un faux saut "myuplink" :

pullnews -a 1/10 -F myuplink news.example.com

OPTIONS

-b num
Set the number of articles to be read from each group to num. This corresponds to the batchsize parameter in inn.conf(5).
-c
Clean up the config file. This will remove any server entry for which no articles are retrieved. It will also remove any entries for groups that are no longer present on the remote server.
-d dir
Change directory to dir before running. This is useful for accessing the config file which is stored in a subdirectory.
-f file
Read the list of newsgroups to process from file instead of the config file. The file format is the same as the config file, except that newsgroup lines may not have a high water mark. This option should be used in conjunction with -M for controlling the number of articles to process per group.
-g group
Add the specified group to the list of newsgroups to process. It is possible to specify the same group several times.
-G wsgroups
Add the specified wsgroups to each server in the configuration file (see also -g and -w).
-h
Print a usage message and exit.
-H headers
Remove these named header fields (colon-separated list) from fed articles.
-k checkpt
Checkpoint (save) the config file every checkpt articles (default is 0, that is to say at the end of the session).
-l logfile
Log progress/stats to logfile (default is "stdout").
-L size
Specify the largest wanted article size in bytes. The default is to download all articles, whatever their size. When this option is used, pullnews will first retrieve overview data (if available) of each newsgroup to process so as to obtain articles sizes, before deciding which articles to actually download.
-m header_pats
Feed an article based on header field body matching. The argument is a number of whitespace-separated tuples (each tuple being a colon-separated header field name and regular expression). For instance: 
-m "Hdr1:regexp1 !Hdr2:regexp2 #Hdr3:regexp3 !#Hdr4:regexp4"

specifies that the article will be passed only if the "Hdr1" header field body matches "regexp1" and the "Hdr2" header field body does not match "regexp2". Besides, if the "Hdr3" header field body matches "regexp3", that header is removed; and if the "Hdr4" header field body does not match "regexp4", that header is removed.

-M num
Specify the maximum number of articles (per group) to process. The default is to process all new articles. See also -f.
-n
Do nothing but read articles -- does not feed articles downstream, writes no rnews file, does not update the config file.
-N timeout
Specify the timeout length, as timeout seconds, when establishing an NNTP connection.
-O
Use an optimized mode: pullnews checks whether the article already exists on the downstream server, before downloading it. It may help for huge articles or a slow link to upstream hosts.
-p port
Connect to the destination news server on a port other than the default of 119. This option does not change the port used to connect to the source news servers.
-P hop_limit
Restrict feeding an article based on the number of hops it has already made. Count the hops in the Path header field body (hop_count), feeding the article only when hop_limit is "+num" and hop_count is more than num; or hop_limit is "-num" and hop_count is less than num.
-q
Print out less status information while running.
-Q level
Set the quietness level ("-Q 2" is equivalent to "-q"). The higher this value, the less gets logged. The default is 0.
-r file
Rather than feeding the downloaded articles to a destination server, instead create a batch file that can later be fed to a server using rnews. See rnews(1) for more information about the batch file format.
-R
Be a reader (use MODE READER and POST commands) to the downstream server. Some posts will then be rejected because of unexpected injection header fields, obsolete or incorrectly formatted header fields, or with a date too far in the past. You may then want to set artcutoff to 0 in inn.conf, and use the -H flag to strip unwanted header fields. Even with that, a few articles may still be rejected.

The default is to behave like a feeder and use the IHAVE command. (You'll have to allow in incoming.conf the connections from pullnews so that it is recognized as a feeder.)

-s to-server[:port][_tlsmode]
Normally, pullnews will feed the articles it retrieves to the news server running on localhost. To connect to a different host, specify a server with the -s flag. You can also specify the port with this same flag or use -p. Default port is 119.

The connection is by default unencrypted. To negotiate a TLS encryption layer, you can set tlsmode to "TLS" for implicit TLS (negotiated immediately upon connection on a dedicated port) or "STARTTLS" for explicit TLS (the appropriate command will be sent before authenticating or feeding messages). Examples of use are:

pullnews -s news.server.com
pullnews -s news.server.com_STARTTLS
pullnews -s news.server.com:433_TLS

Note that not all NNTP servers implement TLS for feeding articles.

-S max-run
Specify the maximum time max-run in seconds for pullnews to run.
-t retries
The maximum number (retries) of attempts to connect to a server or reconnect to a server if the socket is unexpectedly closed (see also -T). The default is 0.
-T connect-pause
Pause connect-pause seconds between connection retries (see also -t). The default is 1.
-w num
Set each group's high water mark (last received article number) to num. If num is negative, calculate Current+num instead (i.e. get the last num articles). Therefore, a num of 0 will re-get all articles on the server; whereas a num of "-0" will get no old articles, setting the water mark to Current (the most recent article on the server).
-x
If the -x flag is used, an Xref header field is added to any article that lacks one. It can be useful for instance if articles are fed to a news server which has xrefslave set in inn.conf.
-z article-pause
Sleep article-pause seconds between articles. The default is 0.
-Z group-pause
Sleep group-pause seconds between groups. The default is 0.

CONFIG FILE

The config file for pullnews is divided into blocks, one block for each remote server to connect to. A block begins with the host line (which must have no leading whitespace) and contains just the hostname of the remote server with optional port and TLS mode (with the same semantics as the -s flag), optionally followed by authentication details (username and password for that server). Note that authentication details can also be provided for the downstream server (a host line for "localhost" or the hostname specified with the -s flag could be added for it in the configuration file, with no newsgroup to fetch).

Following the host line should be one or more newsgroup lines which start with whitespace followed by the name of a newsgroup to retrieve. Only one newsgroup should be listed on each line.

pullnews will update the config file to include the time the group was last checked and the highest numbered article successfully retrieved and transferred to the destination server. It uses this data to avoid doing duplicate work the next time it runs.

The full syntax is:

<host>[:<port>][_<tlsmode>] [<username> <password>]
    <group> [<time> <high>]
    <group> [<time> <high>]

where the <host> line must not have leading whitespace and the <group> lines must.

A typical configuration file would be:

# Format: group date high
data.pa.vix.com
    rec.bicycles.racing 908086612 783
    rec.humor.funny 908086613 18
    comp.programming.threads
nnrp.vix.com pull sekret
    comp.std.lisp
news.server.com:563_TLS joe password
    news.software.nntp

Note that an earlier run of pullnews has filled in details about the last article downloads from the two rec.* groups. The two comp.* groups and the news.* group were just added by the user and have not yet been checked.

The nnrp.vix.com server requires authentication, and pullnews will use the username "pull" and the password "sekret" (without any encryption layer).

The connection to news.server.com will be encrypted with implicit TLS on port 563. Joe's password won't be sent in plaintext.

FILES

pathbin/pullnews
The Perl script itself used to pull news from upstream servers and feed it to another news server.
pathdb/pullnews.marks or ~/pullnews.marks
The default config file. It is stored in pullnews.marks in pathdb when pullnews is run as the news user, or otherwise in the running user's home directory.
