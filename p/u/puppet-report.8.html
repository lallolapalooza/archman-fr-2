NOM

puppet-report - Créer, afficher et soumettre des rapports.

SYNOPSIS

puppet report action [--terminus _TERMINUS]

OPTIONS

Notez que tout paramètre valide dans le fichier de configuration est également un argument long valide, bien qu'il puisse ou non être pertinent pour l'action en cours. Par exemple, server et run_mode sont des paramètres valides, vous pouvez donc spécifier --server <servername> ou --run_mode <runmode> comme argument.

Consultez la documentation du fichier de configuration à l'adresse https://puppet.com/docs/puppet/latest/configuration.html pour la liste complète des paramètres acceptables. Une liste commentée de toutes les options de configuration peut également être générée en exécutant puppet avec --genconfig.

--render-as FORMAT
Le format dans lequel afficher la sortie. Les formats les plus courants sont json, s (string), yaml et console, mais d'autres options comme dot sont parfois disponibles.
--verbose
Indique s'il faut activer la journalisation détaillée.
--debug
Indique s'il faut activer la journalisation des informations de débogage.
--terminus _TERMINUS
Les faces indirectes exposent des sous-systèmes indirects de Puppet. Ces sous-systèmes sont chacun capables de récupérer et de modifier un type de données spécifique (avec les actions familières de find, search, save et destroy) à partir d'un nombre arbitraire de backends pluggables. Dans le jargon de Puppet, ces backends sont appelés terminaux.
Presque tous les sous-systèmes indirects ont un terminal rest qui interagit avec les données du maître puppet. La plupart d'entre eux ont des terminaux supplémentaires pour divers modèles de données locaux, qui sont à leur tour utilisés par le sous-système indirect lorsque le maître puppet reçoit une requête distante.
Le terminal d'une action est souvent déterminé par le contexte, mais peut parfois devoir être défini explicitement. Voir la section "Notes" de la page de manuel de cette face pour plus de détails.

ACTIONS

info - Affiche la classe de terminal par défaut pour cette face.
SYNOPSIS
puppet report info [--terminus _TERMINUS]
DESCRIPTION
Affiche la classe de terminal par défaut pour cette sous-commande. Notez que différents modes d'exécution peuvent avoir différents terminaux par défaut ; en cas de doute, spécifiez le mode d'exécution avec l'option ´--run_mode´.
save - API uniquement : soumettre un rapport.
SYNOPSIS
puppet report save [--terminus _TERMINUS] report
DESCRIPTION
API uniquement : crée ou écrase un objet. Comme le framework Faces n'accepte actuellement pas de données depuis STDIN, les actions de sauvegarde ne peuvent pas être invoquées depuis la ligne de commande.
RETOURS
Rien.
submit - API uniquement : soumettre un rapport avec gestion des erreurs.
SYNOPSIS
puppet report submit [--terminus _TERMINUS] report
DESCRIPTION
API uniquement : soumet un rapport au maître puppet. Cette action est essentiellement un raccourci et un wrapper pour l'action save avec le terminal rest, et fournit des détails supplémentaires en cas d'échec.

EXEMPLES

save

Extrait de l'implémentation de puppet report submit (exemple API) :

begin Puppet::Transaction::Report.indirection.terminus_class = :rest Puppet::Face[:report, "0.0.1"].save(report) Puppet.notice "Uploaded report for #{report.name}" rescue => detail Puppet.log_exception(detail, "Could not send report: #{detail}") end

submit

Exemple API : report = Puppet::Face[:catalog, ´0.0.1´].apply Puppet::Face[:report, ´0.0.1´].submit(report) return report

NOTES

Cette sous-commande est une face indirecte, qui expose les actions find, search, save et destroy pour un sous-système indirect de Puppet. Les terminaux valides pour cette face incluent :

  • json
  • msgpack
  • processor
  • rest
  • yaml
