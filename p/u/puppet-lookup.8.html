NOM

puppet-lookup - Recherche Hiera interactive

SYNOPHIS

Effectue des recherches Hiera depuis la ligne de commande.

Comme cette commande a besoin d'accéder à vos données Hiera, assurez-vous de l'exécuter sur un nœud qui dispose d'une copie de ces données. Cela implique généralement de se connecter à un nœud Puppet Server et d'exécuter ´puppet lookup´ avec sudo.

La version la plus courante de cette commande est :

´puppet lookup CLE --node NOM --environment ENV --explain´

UTILISATION

puppet lookup [--help] [--type TYPECHAINE] [--merge first|unique|hash|deep] [--knock-out-prefix CHAINE-PREFIX] [--sort-merged-arrays] [--merge-hash-arrays] [--explain] [--environment ENV] [--default VALEUR] [--node NOM-NOEUD] [--facts FICHIER] [--compile] [--render-as s|json|yaml|binary|msgpack] clés

DESCRIPTION

La commande lookup est une interface en ligne de commande pour la fonction Puppet ´lookup()´. Elle parcourt vos données Hiera et renvoie une valeur pour la clé de recherche demandée, vous permettant ainsi de tester et d'explorer vos données. C'est un remplacement moderne de la commande ´hiera´. Lookup utilise le paramètre pour le hiera.yaml global de la configuration de puppet, ainsi que l'environnement pour trouver le hiera.yaml au niveau de l'environnement, ainsi que le modulepath résultant pour l'environnement (pour les fichiers hiera.yaml dans les modules). Hiera s'appuie généralement sur les faits d'un nœud pour localiser les sources de données pertinentes. Par défaut, ´puppet lookup´ utilise les faits du nœud sur lequel vous exécutez la commande, mais vous pouvez obtenir des données pour tout autre nœud avec l'option ´--node NOM´. Si possible, la commande lookup utilisera les faits réels stockés du nœud demandé de PuppetDB ; si PuppetDB n'est pas configuré ou si vous souhaitez fournir des valeurs de faits arbitraires, vous pouvez passer des faits alternatifs sous forme de fichier JSON ou YAML avec ´--facts FICHIER´.

Si vous déboguez vos données Hiera et que vous souhaitez voir d'où proviennent les valeurs, utilisez l'option ´--explain´.

Si ´--explain´ n'est pas spécifié, lookup se termine avec 0 si une valeur a été trouvée et 1 sinon. Avec ´--explain´, lookup se termine toujours avec 0 sauf en cas d'erreur majeure.

Vous pouvez fournir plusieurs clés de recherche à cette commande, mais elle ne renvoie une valeur que pour la première clé trouvée, omettant les autres.

Pour plus de détails sur le fonctionnement de Hiera, consultez la documentation Hiera : https://puppet.com/docs/puppet/latest/hiera_intro.html

OPTIONS

  • --help : Imprime ce message d'aide.
  • --explain Explique en détail comment la recherche a été effectuée et d'où provenait la valeur finale (ou la raison pour laquelle aucune valeur n'a été trouvée).
  • --node NOM-NOEUD Spécifie pour quel nœud effectuer la recherche de données ; par défaut, il s'agit du nœud sur lequel la commande est exécutée. Étant donné que le but de Hiera est de fournir différentes valeurs pour différents nœuds (généralement basées sur leurs faits), vous voudrez généralement utiliser les faits d'un nœud spécifique pour explorer vos données. Si le nœud sur lequel vous exécutez cette commande est configuré pour communiquer avec PuppetDB, la commande utilisera les faits les plus récents du nœud demandé. Sinon, vous pouvez remplacer les faits avec l'option ´--facts´.
  • --facts FICHIER Spécifie un fichier .json ou .yaml de correspondances clé => valeur pour remplacer les faits de cette recherche. Tous les faits non spécifiés dans ce fichier conservent leur valeur d'origine.
  • --environment ENV Comme avec la plupart des commandes Puppet, vous pouvez spécifier un environnement sur la ligne de commande. Ceci est important pour la recherche car différents environnements peuvent avoir des données Hiera différentes. Cet environnement sera toujours celui utilisé, quelles que soient les autres facteurs.
  • --merge first|unique|hash|deep : Spécifie le comportement de fusion, remplaçant tout comportement de fusion des lookup_options des données. ´first´ renvoie la première valeur trouvée. ´unique´ ajoute tout à un tableau fusionné et dédupliqué. ´hash´ effectue une fusion de hachage simple en écrasant les clés de priorité de recherche inférieure. ´deep´ effectue une fusion profonde sur les valeurs de type Array et Hash. Il existe des options supplémentaires qui peuvent être utilisées avec ´deep´.
  • --knock-out-prefix CHAINE-PREFIX Peut être utilisé avec la stratégie de fusion ´deep´. Spécifie un préfixe pour indiquer qu'une valeur doit être supprimée du résultat final.
  • --sort-merged-arrays Peut être utilisé avec la stratégie de fusion ´deep´. Lorsque ce drapeau est utilisé, tous les tableaux fusionnés sont triés.
  • --merge-hash-arrays Peut être utilisé avec la stratégie de fusion ´deep´. Lorsque ce drapeau est utilisé, les hachages DANS les tableaux sont fusionnés en profondeur avec leurs homologues par position.
  • --explain-options Explique si un hachage lookup_options affecte cette recherche, et comment ce hachage a été assemblé. (lookup_options est la manière dont Hiera configure le comportement de fusion dans les données.)
  • --default VALEUR Une valeur à renvoyer si Hiera ne parvient pas à trouver de valeur dans les données. Pour émuler les appels à la fonction ´lookup()´ qui incluent une valeur par défaut.
  • --type TYPECHAINE : Asserte que la valeur a le type spécifié. Pour émuler les appels à la fonction ´lookup()´ qui incluent un type de données.
  • --compile Effectue une compilation complète du catalogue avant la recherche. Si votre hiérarchie et vos données n'utilisent que les variables $facts, $trusted et $server_facts, vous n'avez pas besoin de cette option ; cependant, si votre configuration Hiera utilise des variables arbitraires définies par un manifeste Puppet, vous pourriez avoir besoin de cette option pour obtenir des données précises. Aucune compilation de catalogue n'a lieu, sauf si ce drapeau est donné.
  • --render-as s|json|yaml|binary|msgpack Spécifie le format de sortie des résultats ; « s » signifie texte brut. La valeur par défaut lors de la production d'une valeur est yaml et la valeur par défaut lors de la production d'une explication est s.

EXEMPLE

Pour rechercher ´cle_nom´ en utilisant les faits du nœud Puppet Server : $ puppet lookup cle_nom

Pour rechercher ´cle_nom´ en utilisant les variables arbitraires du nœud Puppet Server provenant d'un manifeste, et classifier le nœud si applicable : $ puppet lookup cle_nom --compile

Pour rechercher ´cle_nom´ en utilisant les faits du nœud Puppet Server, remplacés par les faits donnés dans un fichier : $ puppet lookup cle_nom --facts fichier_faits.yaml

Pour rechercher ´cle_nom´ avec les faits de agent.local : $ puppet lookup --node agent.local cle_nom

Pour obtenir la première valeur trouvée pour ´cle_nom_un´ et ´cle_nom_deux´ avec les faits de agent.local tout en fusionnant les valeurs et en supprimant le préfixe ´foo´ lors de la fusion : $ puppet lookup --node agent.local --merge deep --knock-out-prefix foo cle_nom_un cle_nom_deux

Pour rechercher ´cle_nom´ avec les faits de agent.local, et renvoyer une valeur par défaut de ´bar´ si rien n'a été trouvé : $ puppet lookup --node agent.local --default bar cle_nom

Pour obtenir une explication sur la manière dont la valeur de ´cle_nom´ serait trouvée, en utilisant les faits de agent.local : $ puppet lookup --node agent.local --explain cle_nom
