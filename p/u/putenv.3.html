putenv(3) Manuel des fonctions de bibliothèque putenv(3)

NOM

putenv - modifier ou ajouter une variable d'environnement

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <stdlib.h>
int putenv(char *string);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

putenv():

    _XOPEN_SOURCE
        || /* glibc >= 2.19: */ _DEFAULT_SOURCE
        || /* glibc <= 2.19: */ _SVID_SOURCE

DESCRIPTION

La fonction putenv() ajoute ou modifie la valeur des variables d'environnement. L'argument string est de la forme nom=valeur. Si nom n'existe pas déjà dans l'environnement, alors string est ajouté à l'environnement. Si nom existe déjà, alors la valeur de nom dans l'environnement est changée en valeur. La chaîne pointée par string fait partie de l'environnement, donc modifier la chaîne modifie l'environnement.

VALEUR DE RETOUR

La fonction putenv() retourne zéro en cas de succès. En cas d'échec, elle retourne une valeur non nulle et errno est définie pour indiquer l'erreur.

ERREURS

ENOMEM
Espace insuffisant pour allouer le nouvel environnement.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
putenv () Sécurité des threads MT-Unsafe const:env

NORMES

POSIX.1-2008.

HISTORIQUE

POSIX.1-2001, SVr2, 4.3BSD-Reno.

La fonction putenv() n'est pas obligatoirement réentrante, et celle de glibc 2.0 ne l'est pas, mais celle de glibc 2.1 l'est.

Depuis glibc 2.1.2, l'implémentation glibc est conforme à SUSv2 : le pointeur string passé à putenv() est utilisé. En particulier, cette chaîne fait partie de l'environnement ; la modifier plus tard modifiera l'environnement. (Par conséquent, il est erroné d'appeler putenv() avec une variable automatique comme argument, puis de retourner de la fonction appelante alors que string fait toujours partie de l'environnement.) Cependant, de glibc 2.0 à glibc 2.1.1, cela diffère : une copie de la chaîne est utilisée. D'une part, cela provoque une fuite de mémoire, et d'autre part, cela viole SUSv2.

La version 4.3BSD-Reno, comme glibc 2.0, utilise une copie ; ceci est corrigé dans tous les BSD modernes.

SUSv2 retire le const du prototype, tout comme glibc 2.1.3.

L'implémentation de la bibliothèque C GNU fournit une extension non standard. Si string n'inclut pas de signe égal :


putenv("NOM");

alors la variable nommée est retirée de l'environnement de l'appelant.

VOIR AUSSI

clearenv(3), getenv(3), setenv(3), unsetenv(3), environ(7)
