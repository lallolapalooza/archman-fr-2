PUTMSG(3P) Manuel du programmeur POSIX PUTMSG(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

putmsg, putpmsg — envoyer un message sur un flux (STREAMS)

SYNTAXE

#include <stropts.h>
int putmsg(int fildes, const struct strbuf *ctlptr,
    const struct strbuf *dataptr, int flags);
int putpmsg(int fildes, const struct strbuf *ctlptr,
    const struct strbuf *dataptr, int band, int flags);

DESCRIPTION

La fonction putmsg() crée un message à partir d'un ou plusieurs tampons de processus et l'envoie à un fichier STREAMS. Le message peut contenir une partie de données, une partie de contrôle, ou les deux. Les parties de données et de contrôle sont distinguées par leur placement dans des tampons séparés, comme décrit ci-dessous. Les sémantiques de chaque partie sont définies par le module STREAMS qui reçoit le message.

La fonction putpmsg() est équivalente à putmsg(), à l'exception près que le processus peut envoyer des messages dans différentes bandes de priorité. Sauf indication contraire, toutes les exigences applicables à putmsg() s'appliquent également à putpmsg().

L'argument fildes spécifie un descripteur de fichier faisant référence à un flux STREAMS ouvert. Les arguments ctlptr et dataptr pointent chacun vers une structure strbuf.

L'argument ctlptr pointe vers la structure décrivant la partie de contrôle, le cas échéant, à inclure dans le message. Le membre buf de la structure strbuf pointe vers le tampon où résident les informations de contrôle, et le membre len indique le nombre d'octets à envoyer. Le membre maxlen n'est pas utilisé par putmsg(). De même, l'argument dataptr spécifie les données, le cas échéant, à inclure dans le message. L'argument flags indique quel type de message doit être envoyé et est décrit plus en détail ci-dessous.

Pour envoyer la partie données d'un message, l'application doit s'assurer que dataptr n'est pas un pointeur nul et que le membre len de dataptr est égal ou supérieur à 0. Pour envoyer la partie contrôle d'un message, l'application doit s'assurer que les valeurs correspondantes sont définies pour ctlptr. Aucune partie de données (ou de contrôle) ne sera envoyée si dataptr (ou ctlptr) est un pointeur nul ou si le membre len de dataptr (ou ctlptr) est défini à -1.

Pour putmsg(), si une partie de contrôle est spécifiée et que flags est défini à RS_HIPRI, un message de haute priorité sera envoyé. Si aucune partie de contrôle n'est spécifiée et que flags est défini à RS_HIPRI, putmsg() échouera et définira errno à [EINVAL]. Si flags est défini à 0, un message normal (bande de priorité égale à 0) sera envoyé. Si une partie de contrôle et une partie de données ne sont pas spécifiées et que flags est défini à 0, aucun message ne sera envoyé et 0 sera retourné.

Pour putpmsg(), les drapeaux sont différents. L'argument flags est un masque de bits avec les drapeaux mutuellement exclusifs suivants définis : MSG_HIPRI et MSG_BAND. Si flags est défini à 0, putpmsg() échouera et définira errno à [EINVAL]. Si une partie de contrôle est spécifiée et que flags est défini à MSG_HIPRI et que band est défini à 0, un message de haute priorité sera envoyé. Si flags est défini à MSG_HIPRI et qu'aucune partie de contrôle n'est spécifiée ou que band est défini à une valeur non nulle, putpmsg() échouera et définira errno à [EINVAL]. Si flags est défini à MSG_BAND, un message sera envoyé dans la bande de priorité spécifiée par band. Si une partie de contrôle et une partie de données ne sont pas spécifiées et que flags est défini à MSG_BAND, aucun message ne sera envoyé et 0 sera retourné.

La fonction putmsg() se bloquera si la file d'attente d'écriture du flux est pleine en raison de conditions de contrôle de flux internes, à l'exception des cas suivants :

*
Pour les messages de haute priorité, putmsg() ne se bloquera pas sur cette condition et continuera le traitement du message.
*
Pour les autres messages, putmsg() ne se bloquera pas mais échouera lorsque la file d'attente d'écriture sera pleine et que O_NONBLOCK sera défini.

La fonction putmsg() se bloquera également, sauf si elle est empêchée par un manque de ressources internes, en attendant la disponibilité de blocs de messages dans le flux, quelle que soit la priorité ou si O_NONBLOCK a été spécifié. Aucun message partiel ne sera envoyé.

VALEUR DE RETOUR

En cas de succès, putmsg() et putpmsg() retourneront 0 ; sinon, elles retourneront -1 et définiront errno pour indiquer l'erreur.

ERREURS

Les fonctions putmsg() et putpmsg() échoueront si :

EAGAIN
Un message non prioritaire a été spécifié, le drapeau O_NONBLOCK est défini, et la file d'attente d'écriture du flux est pleine en raison de conditions de contrôle de flux internes ; ou des tampons n'ont pas pu être alloués pour le message qui devait être créé.
EBADF
fildes n'est pas un descripteur de fichier valide ouvert en écriture.
EINTR
Un signal a été intercepté pendant putmsg().
EINVAL
Une valeur indéfinie est spécifiée dans flags, ou flags est défini à RS_HIPRI ou MSG_HIPRI et aucune partie de contrôle n'est fournie, ou le flux ou le multiplexeur référencé par fildes est lié (directement ou indirectement) en aval d'un multiplexeur, ou flags est défini à MSG_HIPRI et band est non nul (pour putpmsg() uniquement).
ENOSR
Des tampons n'ont pas pu être alloués pour le message qui devait être créé en raison d'un manque de ressources mémoire STREAMS.
ENOSTR
Aucun flux STREAMS n'est associé à fildes.
ENXIO
Une condition de déconnexion a été générée en aval pour le flux spécifié.
EPIPE ou EIO
L'argument fildes fait référence à un tube basé sur STREAMS et l'autre extrémité du tube est fermée. Un signal SIGPIPE est généré pour le thread appelant.
ERANGE
La taille de la partie données du message ne se situe pas dans la plage spécifiée par les tailles de paquet maximum et minimum du module STREAMS supérieur. Cette valeur est également retournée si la partie de contrôle du message est plus grande que la taille maximale configurée de la partie de contrôle d'un message, ou si la partie de données d'un message est plus grande que la taille maximale configurée de la partie de données d'un message.

De plus, putmsg() et putpmsg() échoueront si la tête du flux a traité une erreur asynchrone avant l'appel. Dans ce cas, la valeur de errno ne reflète pas le résultat de putmsg() ou putpmsg(), mais l'erreur précédente.

Les sections suivantes sont informatives.

EXEMPLES

Envoi d'un message de haute priorité

La valeur de fd est supposée faire référence à un fichier STREAMS ouvert. Cet appel à putmsg() fait les choses suivantes :

1.
Crée un message de haute priorité avec une partie de contrôle et une partie de données, en utilisant les tampons pointés par ctrlbuf et databuf, respectivement.
2.
Envoie le message au fichier STREAMS identifié par fd. 
#include <stropts.h>
#include <string.h>
...
int fd;
char *ctrlbuf = "Ceci est la partie de contrôle";
char *databuf = "Ceci est la partie de données";
struct strbuf ctrl;
struct strbuf data;
int ret;
ctrl.buf = ctrlbuf;
ctrl.len = strlen(ctrlbuf);
data.buf = databuf;
data.len = strlen(databuf);
ret = putmsg(fd, &ctrl, &data, MSG_HIPRI);

Utilisation de putpmsg()<

DESCRIPTION

This example has the same effect as the previous example. In this example, however, the putpmsg() function creates and sends the message to the STREAMS file.

#include <stropts.h>
#include <string.h>
...
int fd;
char *ctrlbuf = "This is the control part";
char *databuf = "This is the data part";
struct strbuf ctrl;
struct strbuf data;
int ret;
ctrl.buf = ctrlbuf;
ctrl.len = strlen(ctrlbuf);
data.buf = databuf;
data.len = strlen(databuf);
ret = putpmsg(fd, &ctrl, &data, 0, MSG_HIPRI);

APPLICATION USAGE

None.

RATIONALE

None.

FUTURE DIRECTIONS

The putmsg() and putpmsg() functions may be removed in a future version.
