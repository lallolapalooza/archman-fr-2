pulseaudio(1) Manuel des commandes générales pulseaudio(1)

NOM

pulseaudio - Le système sonore PulseAudio

SYNTAXE

pulseaudio [options]

pulseaudio --help

pulseaudio --version

pulseaudio --dump-conf

pulseaudio --dump-modules

pulseaudio --dump-resample-methods

pulseaudio --cleanup-shm

pulseaudio --start

pulseaudio --kill

pulseaudio --check

DESCRIPTION

PulseAudio est un serveur sonore réseau à faible latence pour Linux, POSIX et Windows.

OPTIONS

-h | --help
Afficher l'aide.
--version
Afficher les informations de version.
--dump-conf
Charger le fichier de configuration du démon daemon.conf (voir ci-dessous), analyser les options de configuration restantes sur la ligne de commande et afficher la configuration résultante du démon, dans un format compatible avec daemon.conf.
--dump-modules
Lister les modules chargeables disponibles. Combinez avec -v pour une liste plus détaillée.
--dump-resample-methods
Lister les rééchantillonneurs audio disponibles.
--cleanup-shm
Identifier les segments de mémoire partagée POSIX PulseAudio obsolètes dans /dev/shm et les supprimer si possible. Ceci est fait implicitement chaque fois qu'un nouveau démon démarre ou qu'un client essaie de se connecter à un démon. Il ne devrait normalement pas être nécessaire d'émettre cette commande manuellement. Uniquement disponible sur les systèmes ayant des segments de mémoire partagée POSIX implémentés via un système de fichiers virtuel monté sur /dev/shm (par exemple, Linux).
--start
Démarrer PulseAudio s'il n'est pas déjà en cours d'exécution. Ceci est différent de démarrer PulseAudio sans --start, ce qui échouerait si PA est déjà en cours d'exécution. PulseAudio est garanti d'être entièrement initialisé lorsque cet appel retourne. Implique --daemonize.
-k | --kill
Tuer un démon PulseAudio déjà en cours d'exécution de l'utilisateur appelant (Équivalent à envoyer un SIGTERM).
--check
Retourner 0 comme code de retour lorsque le démon PulseAudio est déjà en cours d'exécution pour l'utilisateur appelant, ou non-zéro sinon. Ne produit aucune sortie sur la console, sauf pour les erreurs envoyées sur stderr.

Notez qu'une valeur de retour non nulle ne signifie pas nécessairement que PulseAudio n'est pas utilisable. Même si le serveur ne tourne pas, il peut être démarré automatiquement via le mécanisme d'auto-démarrage de PulseAudio ou l'activation de socket de systemd, ou l'environnement peut être tel que la vérification des processus ne fonctionne pas (par exemple, le serveur en cours d'exécution peut ne pas apparaître dans un conteneur, même si le serveur est accessible via un socket). De plus, désactiver les fichiers PID avec --use-pid-file=no empêche --check de détecter les serveurs en cours d'exécution.

Une vérification plus robuste dans la plupart des situations consisterait à essayer d'établir une connexion client avec le serveur. Malheureusement, il n'existe actuellement pas d'option --check-connection pour remplacer --check, mais exécuter "pactl info" pourrait être un substitut assez bon.

--system[=BOOL]
Exécuter en tant qu'instance système au lieu d'une instance par utilisateur. Veuillez noter que cela désactive certaines fonctionnalités de PulseAudio et n'est généralement pas recommandé, sauf si le système ne connaît aucun utilisateur local (par exemple, est un client léger). Cette fonctionnalité nécessite une configuration spéciale et un utilisateur UNIX dédié. Il est fortement recommandé de combiner cela avec --disallow-module-loading (voir ci-dessous).
-D | --daemonize[=BOOL]
Démoniser après le démarrage, c'est-à-dire se détacher du terminal. Notez que lors de l'exécution en tant que service systemd, vous devriez utiliser --daemonize=no pour que la notification systemd fonctionne.
--fail[=BOOL]
Échouer au démarrage si l'une des commandes spécifiées dans le script de démarrage default.pa (voir ci-dessous) échoue.
--high-priority[=BOOL]
Essayer d'acquérir un niveau de priorité Unix élevé (nice). Cela ne réussira que si l'utilisateur appelant a une limite de ressources RLIMIT_NICE non nulle définie (sur les systèmes qui le prennent en charge), ou si nous sommes configurés pour être exécutés en tant que démon système (voir --system ci-dessus). Il est recommandé d'activer ceci, car ce n'est qu'un risque de sécurité négligeable (voir ci-dessous).
--realtime[=BOOL]
Essayer d'acquérir une planification temps réel pour les threads d'E/S de PulseAudio. Cela ne réussira que si l'utilisateur appelant a une limite de ressources RLIMIT_RTPRIO non nulle définie (sur les systèmes qui le prennent en charge), ou si rtkit est disponible et permet à PulseAudio d'activer la planification temps réel, ou si nous sommes configurés pour être exécutés en tant que démon système (voir --system ci-dessus).
--disallow-module-loading[=BOOL]
Interdire le chargement de modules après le démarrage. C'est une fonctionnalité de sécurité car elle interdit le chargement de modules supplémentaires pendant l'exécution et sur demande de l'utilisateur. C'est fortement recommandé lorsque --system est utilisé (voir ci-dessus). Notez cependant que cela casse certaines fonctionnalités comme le chargement automatique de modules lors de la connexion à chaud.
--disallow-exit[=BOOL]
Interdire la sortie demandée par l'utilisateur
--exit-idle-time=SECS
Terminer le démon après le départ du dernier client et après le passage de ce temps en secondes. Utilisez une valeur négative pour désactiver cette fonctionnalité. Par défaut, la valeur est 20.

Lorsque PulseAudio s'exécute en mode par utilisateur et détecte une session de connexion, toute valeur positive sera réinitialisée à 0 afin que PulseAudio se termine immédiatement à la déconnexion. Une valeur positive n'a donc d'effet que dans les environnements où il n'y a pas de support pour le suivi des sessions de connexion (ou si l'utilisateur est connecté sans session démarrée, aussi appelée "lingering"). Une valeur négative peut toujours être utilisée pour désactiver toute sortie automatique.

Lorsque PulseAudio s'exécute en mode système, la sortie automatique est toujours désactivée, donc cette option ne fait rien.

--scache-idle-time=SECS
Décharger les échantillons auto-chargés du cache lorsqu'ils n'ont pas été utilisés pendant le nombre de secondes spécifié.
--log-level[=NIVEAU]
Si un argument est passé, définir le niveau de journalisation à la valeur spécifiée, sinon augmenter le niveau de verbosité configuré d'une unité. Les niveaux de journalisation sont numériques de 0 à 4, correspondant à error, warn, notice, info, debug. Le niveau de journalisation par défaut est notice, c'est-à-dire que tous les messages de journal avec des niveaux de journalisation inférieurs sont imprimés : error, warn, notice.
-v | --verbose
Augmenter le niveau de verbosité configuré d'une unité (voir --log-level ci-dessus). Spécifiez plusieurs fois pour augmenter le niveau de journalisation plusieurs fois.
--log-target={auto,syslog,journal,stderr,file:CHEMIN,newfile:CHEMIN}
Spécifier la cible de journalisation. Si défini sur auto (ce qui est par défaut), la journalisation est dirigée vers syslog lorsque --daemonize est passé, sinon vers STDERR. Si défini sur journal, la journalisation est dirigée vers le journal systemd. Si défini sur file:CHEMIN, la journalisation est dirigée vers le fichier indiqué par CHEMIN. newfile:CHEMIN est sinon identique à file:CHEMIN, mais les fichiers existants ne sont jamais écrasés. Si le fichier spécifié existe déjà, un suffixe est ajouté au nom du fichier pour éviter l'écrasement.
--log-meta[=BOOL]
Afficher l'emplacement du code source dans les messages de journal.
--log-time[=BOOL]
Afficher les horodatages dans les messages de journal.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

--log-backtrace=FRAMES

Lorsque FRAMES est supérieur à 0, enregistre pour chaque message une trace de pile allant jusqu'au nombre d'images de pile spécifié.
-p | --dl-search-path=PATH
Définit le chemin de recherche pour les objets partagés dynamiques (plugins).
--resample-method=METHOD
Utilise le rééchantillonneur spécifié par défaut (Voir --dump-resample-methods ci-dessus pour les valeurs possibles).
--use-pid-file[=BOOL]
Crée un fichier PID. Si cette option est désactivée, il est possible d'exécuter plusieurs serveurs de son par utilisateur.
--no-cpu-limit[=BOOL]
N'installe pas de limiteur de charge CPU sur les plateformes qui le supportent. Par défaut, PulseAudio s'auto-terminera lorsqu'il constatera qu'il consomme trop de temps CPU. Ceci est utile comme protection contre les blocages système lorsque l'ordonnancement temps réel est utilisé (voir ci-dessous). Désactiver ce mécanisme est utile lors du débogage de PulseAudio avec des outils tels que valgrind(1) qui ralentissent l'exécution.
--disable-shm[=BOOL]
Les clients PulseAudio et le serveur peuvent échanger des données audio via des segments de mémoire partagée POSIX ou memfd (sur les systèmes qui le supportent). Si désactivé, PulseAudio communiquera exclusivement via des sockets. Veuillez noter que le transfert de données via les segments de mémoire partagée est toujours désactivé lorsque PulseAudio s'exécute avec --system activé (voir ci-dessus).
--enable-memfd[=BOOL]
Les clients PulseAudio et le serveur peuvent échanger des données audio via des memfds - le mécanisme de mémoire partagée anonyme du noyau Linux (sur les noyaux qui le supportent). Si désactivé, PulseAudio communiquera via la mémoire partagée POSIX.
-L | --load="MODULE ARGUMENTS"
Charge le module plugin spécifié avec les arguments spécifiés.
-F | --file=FILENAME
Exécute le script spécifié au démarrage. Peut être spécifié plusieurs fois pour spécifier plusieurs scripts à exécuter dans l'ordre. Combinez avec -n pour désactiver le chargement du script par défaut default.pa (voir ci-dessous).
-C
Ouvre un interpréteur de commandes sur STDIN/STDOUT après le démarrage. Ceci peut être utilisé pour configurer PulseAudio dynamiquement pendant l'exécution. Équivalent à --load=module-cli.
-n
Ne charge pas le fichier de script par défaut default.pa (voir ci-dessous) au démarrage. Utile en conjonction avec -C ou --file.

FICHIERS

~/.config/pulse/daemon.conf, /etc/pulse/daemon.conf: paramètres de configuration pour le démon PulseAudio. Si la version dans le répertoire personnel de l'utilisateur n'existe pas, le fichier de configuration global est chargé. Voir pulse-daemon.conf(5) pour plus d'informations.

~/.config/pulse/default.pa, /etc/pulse/default.pa: le script de configuration par défaut à exécuter lorsque le démon PulseAudio est démarré. Si la version dans le répertoire personnel de l'utilisateur n'existe pas, le script de configuration global est chargé. Voir default.pa(5) pour plus d'informations.

~/.config/pulse/client.conf, /etc/pulse/client.conf: paramètres de configuration pour les applications clientes PulseAudio. Si la version dans le répertoire personnel de l'utilisateur n'existe pas, le fichier de configuration global est chargé. Voir pulse-client.conf(5) pour plus d'informations.

SIGNAUX

SIGINT, SIGTERM: le démon PulseAudio s'arrêtera (Identique à --kill).

SIGHUP: affiche un rapport de statut détaillé sur STDOUT ou syslog, selon la configuration.

SIGUSR1: charge module-cli, permettant une reconfiguration à la volée via STDIN/STDOUT.

SIGUSR2: charge module-cli-protocol-unix, permettant une reconfiguration à la volée via un socket AF_UNIX. Voir pacmd(1) pour plus d'informations.

GROUPES ET UTILISATEURS UNIX

Groupe pulse-access: si PulseAudio s'exécute en tant que démon système (voir --system ci-dessus), l'accès est accordé aux membres de ce groupe lorsqu'ils se connectent via des sockets AF_UNIX. Si PulseAudio s'exécute en tant que démon utilisateur, ce groupe n'a aucune signification.

Utilisateur pulse, groupe pulse: si PulseAudio s'exécute en tant que démon système (voir --system ci-dessus) et est démarré en tant que root, le démon abandonnera les privilèges et deviendra un processus utilisateur normal utilisant cet utilisateur et ce groupe. Si PulseAudio s'exécute en tant que démon utilisateur, cet utilisateur et ce groupe n'ont aucune signification.

ORDONNANCEMENT TEMPS RÉEL ET HAUTE PRIORITÉ

Pour minimiser le risque de coupures lors de la lecture, il est recommandé d'exécuter PulseAudio avec l'ordonnancement temps réel si la plateforme sous-jacente le supporte. Cela découple la latence d'ordonnancement du démon PulseAudio de la charge système et constitue donc le meilleur moyen de s'assurer que PulseAudio reçoit toujours du temps CPU lorsqu'il en a besoin pour recharger les tampons matériels de lecture. Malheureusement, cela peut présenter un risque de sécurité sur certains systèmes, car PulseAudio s'exécute en tant que processus utilisateur, et accorder des privilèges d'ordonnancement temps réel à un utilisateur comporte toujours le risque que l'utilisateur en abuse pour bloquer le système -- ce qui est possible car rendre un processus temps réel désactive effectivement la préemption. Pour résoudre ce problème, PulseAudio utilise rtkit pour acquérir en toute sécurité l'ordonnancement temps réel lorsqu'il est disponible.

Si le risque de bloquer la machine est jugé trop élevé pour activer l'ordonnancement temps réel, l'ordonnancement à haute priorité peut être activé à la place (c'est-à-dire un niveau nice négatif). Cela peut être activé en passant --high-priority (voir ci-dessus) lors du démarrage de PulseAudio et peut également être activé avec l'option appropriée dans daemon.conf. Les niveaux nice négatifs ne peuvent être activés que lorsque la limite de ressources appropriée RLIMIT_NICE est définie (voir setrlimit(2) pour plus d'informations), éventuellement configurée dans /etc/security/limits.conf. Une limite de ressources de 31 (correspondant au niveau nice -11) est recommandée.

VARIABLES D'ENVIRONNEMENT

Les bibliothèques clientes PulseAudio vérifient l'existence des variables d'environnement suivantes et modifient leur configuration locale en conséquence :

$PULSE_SERVER: la chaîne de serveur spécifiant le serveur auquel se connecter lorsqu'un client demande une connexion au serveur sonore et ne demande pas explicitement de serveur spécifique. La chaîne de serveur est une liste d'adresses de serveurs séparées par des espaces qui sont essayées tour à tour. Une adresse de serveur se compose d'un spécificateur de type d'adresse optionnel (unix:, tcp:, tcp4:, tcp6:), suivi d'un chemin ou d'une adresse d'hôte. Une adresse d'hôte peut inclure un numéro de port optionnel. Une adresse de serveur peut être préfixée par une chaîne entourée d'accolades {}. Dans ce cas, l'adresse de serveur suivante est ignorée à moins que la chaîne de préfixe ne corresponde au nom d'hôte local ou à l'identifiant de la machine (/etc/machine-id).

$PULSE_SINK: le nom symbolique du sink auquel se connecter lorsqu'un client crée un flux de lecture et ne demande pas explicitement de sink spécifique.

$PULSE_SOURCE: le nom symbolique de la source à laquelle se connecter lorsqu'un client crée un flux d'enregistrement et ne demande pas explicitement de source spécifique.

$PULSE_BINARY: chemin de l'exécutable PulseAudio à lancer lorsque le démarrage automatique du serveur est utilisé.

$PULSE_CLIENTCONFIG: chemin du fichier qui sera lu à la place de client.conf (voir ci-dessus) pour la configuration du client.

$PULSE_COOKIE: chemin du fichier contenant le cookie d'authentification PulseAudio. Par défaut, il s'agit de ~/.config/pulse/cookie.

Ces paramètres d'environnement ont priorité -- s'ils sont définis -- sur les paramètres de configuration de client.conf (voir ci-dessus).

NOM

pulseaudio — serveur de son démoniaque

SYNOPSIS

pulseaudio [OPTIONS...]

DESCRIPTION

PulseAudio est un serveur de son destiné à être une extension générale à l'architecture son des systèmes d'exploitation de type Unix. En particulier, il est conçu pour être un serveur de mixage et de lecture en réseau facile à utiliser.

Les caractéristiques principales incluent :

  • Mixage d'un nombre quelconque de sources et de récepteurs d'un côté ou de l'autre d'une application.
  • La capacité d'arrêter et de démarrer des périphériques sans interrompre les flux audio.
  • La capacité de déplacer des flux audio entre des périphériques sans interruption.
  • La capacité d'utiliser des périphériques audio via le réseau.
  • Architecture de plugins qui permet d'ajouter facilement de nouveaux périphériques, des nouveaux formats audio, et de nouvelles fonctions.

PulseAudio peut être démarré en tant que démon. Lorsque vous démarrez PulseAudio, il s'exécute en arrière-plan et gère le son de tous les utilisateurs qui se connectent à ce serveur. Il est souvent démarré automatiquement par le gestionnaire d'affichage (comme GDM ou KDM) lorsque l'utilisateur se connecte.

OPTIONS

Le démon PulseAudio prend en charge les options suivantes :

--daemonize, -D
Démarrer le démon en arrière-plan.
--exit-idle-time=SECS
Spécifier le temps d'inactivité (en secondes) après lequel le serveur devrait se terminer s'il n'est utilisé par aucune application. Si cette valeur est réglée sur 0, le serveur ne se terminera jamais de lui-même.
--log-target=TARGET
Spécifier la cible de la journalisation. Les valeurs possibles pour TARGET sont : stderr, syslog, journal, null. Si omise, la valeur par défaut est stderr (lorsque le démon est démarré interactivement) ou syslog (lorsqu'il est démarré en tant que démon).
--no-default-environment-save
Ne pas enregistrer la configuration par défaut de l'environnement.
--fail-if-existing
Échouer si un serveur PulseAudio existe déjà. Utile pour les installations où vous ne voulez pas que plusieurs instances de PulseAudio s'exécutent.
--watch-daemon
Surveiller le démon PulseAudio et le redémarrer s'il plante.
--system, -s
Démarrer le serveur en tant que démon système. Cela désactive certaines fonctions de sécurité et est généralement déconseillé sauf si vous savez ce que vous faites.
--disallow-module-loading
Désactiver le chargement de modules. Utile pour les environnements de production où vous voulez un serveur statique et prévisible.
--flat-volumes
Activer le comportement de "volumes plats". Dans ce mode, le volume d'un flux ne peut pas être changé indépendamment de son canal de sortie. Cela permet d'économiser des ressources car le mixage est plus simple.

STATUT DE SORTIE

Si PulseAudio est démarré en tant que démon, il renvoie 0 en cas de succès, et une valeur non nulle en cas d'échec.

EXEMPLES

Pour démarrer le démon PulseAudio en arrière-plan :

pulseaudio -D

Pour démarrer le démon PulseAudio en arrière-plan et le faire se terminer après 60 secondes d'inactivité :

pulseaudio -D --exit-idle-time=60
