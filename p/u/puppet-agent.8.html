NOM

puppet-agent - Le démon puppet agent

SYNOPSSIS

Récupère la configuration client du maître Puppet et l'applique à l'hôte local.

Ce service peut être exécuté comme un démon, exécuté périodiquement à l'aide de cron (ou similaire), ou exécuté interactivement à des fins de test.

UTILISATION

puppet agent [--certname NOM] [-D|--daemonize|--no-daemonize] [-d|--debug] [--detailed-exitcodes] [--digest DIGEST] [--disable [MESSAGE]] [--enable] [--fingerprint] [-h|--help] [-l|--logdest syslog|eventlog|CHEMIN_ABSOLU|console] [--serverport PORT] [--noop] [-o|--onetime] [--sourceaddress ADRESSE_IP] [-t|--test] [-v|--verbose] [-V|--version] [-w|--waitforcert SECONDES]

DESCRIPTION

Ceci est le client puppet principal. Sa tâche consiste à récupérer la configuration de la machine locale à partir d'un serveur distant et à l'appliquer. Pour communiquer avec succès avec le serveur distant, le client doit posséder un certificat signé par une autorité de certification à laquelle le serveur fait confiance ; la méthode recommandée pour cela, à l'heure actuelle, est d'exécuter une autorité de certification dans le cadre du serveur puppet (ce qui est le comportement par défaut). Le client se connectera et demandera un certificat signé, et continuera de se connecter jusqu'à ce qu'il en reçoive un.

Une fois que le client a un certificat signé, il récupérera sa configuration et l'appliquera.

NOTES D'UTILISATION

«puppet agent» fait de son mieux pour trouver un compromis entre l'utilisation interactive et l'utilisation en démon. Si vous l'exécutez sans arguments et sans configuration, il passe en arrière-plan, tente d'obtenir un certificat signé, et récupère et applique sa configuration toutes les 30 minutes.

Certaines options sont spécifiquement destinées à une utilisation interactive --- en particulier, «test», «tags» et «fingerprint» sont utiles.

«--test» s'exécute une fois en premier plan avec une journalisation détaillée, puis se termine. Il se termine également s'il ne parvient pas à obtenir un catalogue valide. --test inclut l'option «--detailed-exitcodes» par défaut et se termine avec l'un des codes de sortie suivants :

  • 0 : L'exécution a réussi sans changements ni échecs ; le système était déjà dans l'état souhaité.
  • 1 : L'exécution a échoué, ou n'a pas été tentée en raison d'une autre exécution déjà en cours.
  • 2 : L'exécution a réussi, et certaines ressources ont été modifiées.
  • 4 : L'exécution a réussi, et certaines ressources ont échoué.
  • 6 : L'exécution a réussi, et comprenait à la fois des changements et des échecs.

«--tags» vous permet de spécifier quelles parties d'une configuration vous souhaitez appliquer. Les éléments Puppet sont tagués avec tous les noms de classe ou de définition qui les contiennent, et vous pouvez utiliser l'option «tags» pour spécifier l'un de ces noms, ce qui ne fera appliquer que les éléments de configuration contenus dans cette classe ou définition. Ceci est très utile lorsque vous testez de nouvelles configurations --- par exemple, si vous commencez à gérer «ntpd», vous mettriez tous les nouveaux éléments dans une classe «ntpd», et appelleriez puppet avec «--tags ntpd», ce qui n'appliquerait que cette petite partie de la configuration pendant vos tests, plutôt que d'appliquer le tout.

«--fingerprint» est une option unique. Dans ce mode, «puppet agent» s'exécute une fois et affiche sur la console (et dans le journal) l'empreinte digitale actuelle du certificat (ou de la demande de signature de certificat). La fourniture de l'option «--digest» permet d'utiliser un algorithme de hachage différent pour générer l'empreinte digitale. L'utilisation principale est de vérifier qu'avant de signer une demande de certificat sur le maître, la demande de certificat que le maître a reçue est la même que celle envoyée par le client (pour se prémunir contre les attaques de l'homme du milieu lors de la signature des certificats).

«--skip_tags» est une option utilisée pour filtrer les ressources. Si elle est définie, seules les ressources non taguées avec les tags spécifiés seront appliquées. Les valeurs doivent être séparées par des virgules.

OPTIONS

Notez que tout paramètre Puppet valide dans le fichier de configuration est également un argument long valide. Par exemple, «server» est un paramètre valide, vous pouvez donc spécifier «--server nom_serveur» comme argument. Les paramètres booléens acceptent un préfixe «--no-» pour désactiver un comportement, se traduisant par des paires «--parametre» et «--no-parametre», comme --daemonize et --no-daemonize.

Consultez la documentation du fichier de configuration à l'adresse https://puppet.com/docs/puppet/latest/configuration.html pour la liste complète des paramètres acceptables. Une liste commentée de tous les paramètres peut également être générée en exécutant puppet agent avec «--genconfig».

  • --certname : Définit le nom de certificat (identifiant unique) du client. Le maître lit cette chaîne d'identification unique, qui est généralement définie sur le nom de domaine complet du nœud, pour déterminer quelles configurations le nœud recevra. Utilisez cette option pour déboguer des problèmes d'installation ou implémenter des schémas d'identification de nœud inhabituels. (Ceci est un paramètre Puppet et peut être placé dans puppet.conf.)
  • --daemonize : Envoie le processus en arrière-plan. C'est le comportement par défaut. (Ceci est un paramètre Puppet et peut être placé dans puppet.conf. Notez le préfixe spécial «no-» pour les paramètres booléens en ligne de commande.)
  • --no-daemonize : N'envoie pas le processus en arrière-plan. (Ceci est un paramètre Puppet et peut être placé dans puppet.conf. Notez le préfixe spécial «no-» pour les paramètres booléens en ligne de commande.)
  • --debug : Active le débogage complet.
  • --detailed-exitcodes : Fournit des informations supplémentaires sur l'exécution via les codes de sortie ; ne fonctionne que si «--test» ou «--onetime» sont également spécifiés. Si activé, «puppet agent» utilise les codes de sortie suivants :
0 : L'exécution a réussi sans changements ni échecs ; le système était déjà dans l'état souhaité.
1 : L'exécution a échoué, ou n'a pas été tentée en raison d'une autre exécution déjà en cours.
2 : L'exécution a réussi, et certaines ressources ont été modifiées.
4 : L'exécution a réussi, et certaines ressources ont échoué.
6 : L'exécution a réussi, et comprenait à la fois des changements et des échecs.
  • --digest : Change l'algorithme de hachage utilisé pour les empreintes digitales des certificats. La valeur par défaut est SHA256. Les valeurs valides dépendent de la version d'OpenSSL installée, mais contiendront probablement MD5, MD2, SHA1 et SHA256.
  • --disable : Désactive le travail sur le système local. Ceci place un fichier de verrouillage en place, empêchant «puppet agent» de travailler sur le système jusqu'à ce que le fichier de verrouillage soit supprimé. Ceci est utile si vous testez une configuration et ne voulez pas que la configuration centrale remplace l'état local jusqu'à ce que tout soit testé et validé.
Disable peut également accepter un message optionnel qui sera rapporté par «puppet agent» lors de la prochaine exécution désactivée.
«puppet agent» utilise le même fichier de verrouillage pendant son exécution, donc pas plus d'un processus «puppet agent» ne fonctionne en même temps.
«puppet agent» se termine après l'exécution de cette commande.
•
--enable : Active le travail sur le système local. Ceci supprime tout fichier de verrouillage, faisant que «puppet agent» recommence à gérer le système local. Cependant, il continue d'utiliser sa planification normale, il pourrait donc ne pas démarrer avant une demi-heure.
«puppet agent» se termine après l'exécution de cette commande.
  • --evaltrace : Journalise chaque ressource au fur et à mesure de son évaluation. Ceci vous permet de voir interactivement exactement ce qui est fait. (Ceci est un paramètre Puppet et peut être placé dans puppet.conf. Notez le préfixe spécial «no-» pour les paramètres booléens en ligne de commande.)
  • --fingerprint : Affiche l'empreinte digitale actuelle du certificat ou de la demande de signature de certificat et quitte. Utilisez l'option «--digest» pour changer l'algorithme de hachage utilisé.
  • --help : Imprime ce message d'aide
  • --job-id : Attache l'identifiant de travail spécifié à la demande de catalogue et au rapport utilisés pour cette exécution de l'agent. Cette option ne fonctionne que lorsque «--onetime» est spécifié.

puppet-agent — Puppet Agent

SYNOPSIS

           [-d | --debug]
           [-v | --verbose]
           [--trace]
           [--summarize]
           [--logdest <logdest>]
           [--no-daemonize]
           [--daemonize]
           [--disable-warnings]
           [--enable-warnings]
           [--rundir <dir>]
           [--statedir <dir>]
           [--rundir <dir>]
           [--confdir <dir>]
           [--vardir <dir>]
           [--libdir <dir>]
           [--debug]
           [--debug-commits]
           [--debug-events]
           [--debug-graph]
           [--debug-locale]
           [--debug-plugins]
           [--debug-providers]
           [--debug-rest]
           [--debug-stdlib]
           [--debug-templates]
           [--debug-transaction-trace]
           [--debug-util]
           [--debug-vardir]
           [--debug-yellow-lines]
           [--debug-routes]
           [--color <color>]
           [--colour <colour>]
           [--no-color]
           [--no-colour]
           [--detail-exitcodes]
           [--detailed-exitcodes]
           [--disable_warnings]
           [--enable_warnings]
           [--evaltrace]
           [--external-facts <file>]
           [--fact-path <path>]
           [--fingerprint]
           [--force-watch-fs]
           [--help]
           [--ignorecache]
           [--ignoreschedules]
           [--no-disable-warnings]
           [--no-enable-warnings]
           [--no-ignorecache]
           [--no-ignoreschedules]
           [--no-usecacheonfailure]
           [--noop]
           [--puppetport <port>]
           [--splay]
           [--splaylimit <seconds>]
           [--usecacheonfailure]
           [--no-splay]
           [--show_diff]
           [--no-show_diff]
           [--server <server>]
           [--serverport <port>]
           [--no-trace]
           [--transaction-trace]
           [--transaction-trace-dir <dir>]
           [--use_cached_catalog]
           [--no_use_cached_catalog]
           [--verbose]
           [--version]
           [--waitforcert <seconds>]
           [--write-catalog-summary]

DESCRIPTION

Le démon puppet agent est le composant côté client de Puppet. Il est responsable de la récupération et de l'application des configurations depuis un serveur Puppet (ou de l'application d'une configuration locale si aucun serveur n'est spécifié).

Le démon puppet agent peut fonctionner de deux manières :

  • Comme un démon qui tourne en permanence et qui récupère les configurations à intervalles réguliers.
  • Comme un utilitaire qui tourne une seule fois, souvent utilisé en conjonction avec le script cron ou l'option --onetime.

Dans la plupart des cas, puppet agent est exécuté en tant que démon qui contacte le serveur Puppet à intervalles réguliers (généralement 30 minutes) pour vérifier les mises à jour et appliquer les configurations.

Si puppet agent ne trouve pas de configuration définie pour le nœud, il n'appliquera aucune configuration et quittera proprement. Cela peut arriver si le nœud n'est pas présent dans le Manifest Master.

USAGE NOTES

L'exécution de puppet agent en tant que démon se fait généralement via le script init ou systemd.

Dans les versions antérieures de Puppet, le démon était connu sous le nom de puppetd. Ce nom est maintenant obsolète, mais l'exécutable puppetd existe toujours pour la compatibilité descendante. Il est recommandé d'utiliser puppet agent à la place.

Le démon puppet agent est configuré via le fichier /etc/puppetlabs/puppet/puppet.conf (sur les systèmes POSIX) ou via des entrées de registre sur les systèmes Windows.

Les options de ligne de commande peuvent remplacer les paramètres du fichier de configuration.

OPTIONS

  • --color color
    --colour colour Active la coloration de la sortie. Les valeurs possibles pour color sont always, auto, et never. auto est la valeur par défaut, qui active la coloration uniquement si la sortie est envoyée à un terminal. Peut être également défini par la directive color dans puppet.conf.
  • --debug Active le mode de débogage pour une journalisation plus détaillée.
  • --detailed-exitcodes --detail-exitcodes Permet de renvoyer des codes de sortie plus spécifiques afin de déterminer si des modifications ont été apportées, si une erreur s'est produite, etc.
  • --disable-warnings --enable-warnings Permet de désactiver ou d'activer des avertissements spécifiques. Les avertissements peuvent être spécifiés par leur nom.
  • --evaltrace Affiche des informations sur le temps d'exécution de chaque ressource.
  • --external-facts file Spécifie un fichier contenant des faits externes.
  • --fact-path path Ajoute un répertoire au chemin de recherche des faits. Peut être spécifié plusieurs fois.
  • --fingerprint Imprime l'empreinte numérique du certificat du nœud avant de quitter.
  • --force-watch-fs Force la réinitialisation du système de fichiers surveillé, même si le système de fichiers n'a pas changé.
  • --help Affiche un message d'aide et quitte.
  • --ignorecache Ne pas utiliser le cache de catalogue.
  • --ignoreschedules Ne pas exécuter les tâches planifiées.
  • --logdest logdest Définit la destination des messages de log. Les valeurs possibles sont syslog (service syslog POSIX), eventlog (journal des événements Windows), console, ou le chemin vers un fichier de log. Si le débogage ou la verbosité est activé, la valeur par défaut est console. Sinon, la valeur par défaut est syslog sur les systèmes POSIX et eventlog sur Windows. Plusieurs destinations peuvent être spécifiées en utilisant une liste séparée par des virgules (par exemple : /chemin/fichier1,console,/chemin/fichier2).
Un chemin se terminant par .json recevra une sortie structurée au format JSON. Le fichier de log n'aura pas de crochet fermant ] écrit automatiquement en raison de la nature d'ajout des logs. Il doit être ajouté manuellement pour que le contenu soit un JSON valide.
Un chemin se terminant par .jsonl recevra une sortie structurée au format JSON Lines.
  • --masterport port Le port sur lequel contacter le serveur Puppet. (Ceci est un paramètre Puppet, et peut être défini dans puppet.conf. Obsolète au profit du paramètre serverport.)
  • --no-daemonize Ne pas daemoniser le processus. Utile pour exécuter une seule fois.
  • --no-show_diff Ne pas afficher les différences entre les anciens et les nouveaux fichiers.
  • --no-splay Désactive le splay (l'étalement des exécutions) de puppet agent.
  • --no-usecacheonfailure Ne pas utiliser le catalogue mis en cache en cas d'échec.
  • --noop Utilise le mode noop où le démon s'exécute en mode simulation ou vérification. Ceci est utile pour voir les modifications que Puppet apporterait sans exécuter réellement les changements. (Ceci est un paramètre Puppet, et peut être défini dans puppet.conf. Notez le préfixe spécial no- pour les paramètres booléens sur la ligne de commande.)
  • --onetime Exécute la configuration une seule fois. Exécute une seule fois une tâche Puppet (normalement exécutée par le démon). Utile pour exécuter interactivement puppet agent lorsqu'il est utilisé avec l'option --no-daemonize. (Ceci est un paramètre Puppet, et peut être défini dans puppet.conf. Notez le préfixe spécial no- pour les paramètres booléens sur la ligne de commande.)
  • --server server Le nom d'hôte du serveur Puppet.
  • --serverport port Le port sur lequel contacter le serveur Puppet. (Ceci est un paramètre Puppet, et peut être défini dans puppet.conf.)
  • --sourceaddress address Définit l'adresse IP source pour les transactions. Par défaut, elle est sélectionnée automatiquement. (Ceci est un paramètre Puppet, et peut être défini dans puppet.conf.)
  • --test Active les options les plus courantes utilisées pour les tests. Il s'agit de onetime, verbose, no-daemonize, no-usecacheonfailure, detailed-exitcodes, no-splay, et show_diff.
  • --trace Affiche les traces de pile sur certaines erreurs. (Ceci est un paramètre Puppet, et peut être défini dans puppet.conf. Notez le préfixe spécial no- pour les paramètres booléens sur la ligne de commande.)
  • --verbose Active le rapport détaillé.
  • --version Affiche le numéro de version de Puppet et quitte.
  • --waitforcert seconds Cette option n'a d'importance que pour les démons qui n'ont pas encore de certificats et elle est activée par défaut, avec une valeur de 120 (secondes). Cela amène puppet agent à se connecter au serveur toutes les 2 minutes et à lui demander de signer une requête de certificat. Ceci est utile pour la configuration initiale d'un client Puppet. Vous pouvez désactiver l'attente de certificats en spécifiant une valeur de 0. (Ceci est un paramètre Puppet, et peut être défini dans puppet.conf.)
  • --write-catalog-summary Après avoir compilé le catalogue, enregistre la liste des ressources et la liste des classes sur le nœud dans le répertoire d'état nommé classes.txt et resources.txt. (Ceci est un paramètre Puppet, et peut être défini dans puppet.conf.)

EXAMPLE

$ puppet agent --server puppet.domain.com

DIAGNOSTICS

Puppet agent accepte les signaux suivants :

SIGHUP
Redémarre le démon puppet agent.
SIGINT and SIGTERM
Arrête le démon puppet agent.
SIGUSR1
Récupère et applique immédiatement les configurations du serveur Puppet.
SIGUSR2
Ferme les descripteurs de fichiers pour les fichiers de log et les rouvre. Utilisé avec logrotate.
