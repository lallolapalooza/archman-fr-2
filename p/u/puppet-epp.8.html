NOM

puppet-epp - Interagir directement avec l'analyseur/rendeur de modèles EPP.

SYNOPIS

puppet epp action

OPTIONS

Notez que tout paramètre valide dans le fichier de configuration est également un argument long valide, bien qu'il puisse être pertinent ou non pour l'action présente. Par exemple, server et run_mode sont des paramètres valides, vous pouvez donc spécifier --server <nom_serveur>, ou --run_mode <mode_exécution> comme argument.

Consultez la documentation du fichier de configuration à https://puppet.com/docs/puppet/latest/configuration.html pour la liste complète des paramètres acceptables. Une liste commentée de toutes les options de configuration peut également être générée en exécutant puppet avec --genconfig.

--render-as FORMAT
Le format dans lequel rendre la sortie. Les formats les plus courants sont json, s (chaîne), yaml, et console, mais d'autres options comme dot sont parfois disponibles.
--verbose
Indique s'il faut enregistrer les messages de manière verbeuse.
--debug
Indique s'il faut enregistrer les informations de débogage.

ACTIONS

•
dump - Affiche une représentation interne de l'arbre d'analyse du modèle pour le débogage : SYNOPIS
puppet epp dump [--e source] [--[no-]validate] [--format old, pn, ou json] [--pretty] [--[no-]header] [--format old|pn|json] [--pretty] { -e source | [modèles ...] }
DESCRIPTION
L'action dump analyse et valide la syntaxe EPP et affiche le modèle AST résultant dans un format lisible par l'homme (mais pas nécessairement facile à comprendre).
Le format de sortie peut être contrôlé à l'aide de --format old|pn|json où :
  • ´old´ est le format par défaut, mais désormais déprécié et non API.
  • ´pn´ est la notation S-expression étendue de Puppet (Puppet Extended S-Expression Notation).
  • ´json´ affiche le même graphe que ´pn´ mais avec une syntaxe JSON.
La sortie sera "jolie" (pretty printed) lorsque l'option --pretty est donnée avec --format ´pn´ ou ´json´. Cette option n'a aucun effet sur le format ´old´.
La commande accepte un ou plusieurs modèles (.epp) fichiers, ou un -e suivi du texte source du modèle. Les modèles donnés peuvent être des chemins vers des fichiers de modèles, ou des références à des modèles dans des modules lorsqu'ils sont donnés sous la forme nom_module/nom_modèle.epp. Si aucun argument n'est donné, l'entrée standard (stdin) est lue (sauf si elle est connectée à un terminal).
Si plusieurs modèles sont donnés, ils sont séparés par un en-tête indiquant le nom du modèle. Cela peut être supprimé avec l'option --no-header. L'option --[no-]header n'a aucun effet lorsqu'un seul modèle est affiché.
Lors du débogage de l'analyseur epp lui-même, il peut être utile de supprimer l'étape de validation avec l'option --no-validate pour observer ce que l'analyseur a produit à partir de la source donnée.
Cette commande ignore le réglage/option --render-as.
OPTIONS --e <source> - Affiche une expression source epp donnée sur la ligne de commande.
--format <old, pn, ou json> - Obtient le résultat dans le format ´old´ (format déprécié), ´pn´ (nouveau format), ou ´json´ (nouveau format en JSON).
--[no-]header - Indique s'il faut afficher un en-tête de nom de fichier entre les fichiers.
--pretty - Affiche la sortie de manière lisible. Applicable uniquement avec --format pn ou json
--[no-]validate - Indique s'il faut valider le résultat analysé ; si no-validate, seules les erreurs de syntaxe sont signalées.
RETOURNE
Une représentation du modèle AST résultant, sauf en cas d'erreurs de syntaxe ou de validation.
•
render - Rend un modèle epp sous forme de texte : SYNOPIS
puppet epp render [--node nom_noeud] [--e source] [--values hash_valeurs] [--values_file fichier_pp_ou_yaml] [--facts fichier_faits] [--[no-]header] -e source | [modèles ...]
DESCRIPTION
Cette action rend un ou plusieurs modèles EPP.
La commande accepte un ou plusieurs modèles (.epp fichiers), donnés de la même manière que les modèles sont donnés à la fonction puppet epp (un chemin complet, ou une référence relative sous la forme ´nom_module/nom_modèle.epp´), ou en tant que chemin relatif. En cas où le chemin donné correspond à la fois à un nom_module/modèle et à un fichier, le modèle du module est utilisé.
Un équivalent d'inline_epp peut également être effectué en donnant le modèle après un -e, ou en redirigeant le texte source EPP vers la commande.
Les valeurs pour le modèle peuvent être définies en utilisant le Langage Puppet sur la ligne de commande avec --values ou dans un fichier .pp ou .yaml référencé avec --values_file. Si les deux sont spécifiés, le résultat est fusionné avec --values ayant la priorité la plus haute.
L'option --values permet de définir une séquence d'expressions en Langage Puppet sur la ligne de commande, de la même manière qu'elle peut être donnée dans un fichier .pp référencé avec --values_file. Elle peut définir des valeurs de variables (qui deviennent disponibles dans le modèle), et doit produire soit undef soit un Hash de valeurs (le hash peut être vide). Produire undef simule que le modèle est appelé sans argument hash et donc ne fait référence qu'à des variables de sa portée externe. Lorsqu'un hash est donné, un modèle est limité à ne voir que la portée globale. Il est ainsi possible de simuler les différents types d'appels aux fonctions epp et inline_epp, avec ou sans hash donné. Notez que si des variables sont données, elles sont toujours disponibles dans cette simulation - pour tester que le modèle ne référence que des variables données en arguments, produire un hash dans --values ou le --values_file, ne pas spécifier de variables qui ne sont pas globales, et activer le paramètre --strict_variables.
Si plusieurs modèles sont donnés, le même ensemble de valeurs est donné à chaque modèle. Si --values et --value_file sont utilisés, les --values sont fusionnés par-dessus ceux donnés dans le fichier.
Lorsque plusieurs modèles sont rendus, un en-tête séparateur est affiché entre les modèles indiquant le nom du modèle avant la sortie. La sortie d'en-tête peut être désactivée avec --no-header. Cela concatène également les résultats des modèles sans ajout de séparateurs de nouvelle ligne.
Les faits du nœud sur lequel la commande est exécutée sont utilisés par défaut. Les faits peuvent être obtenus pour d'autres nœuds s'ils ont appelé et rapporté leurs faits en utilisant l'indicateur --node <nom_noeud>.
Les faits du nœud peuvent être remplacés ainsi que des faits supplémentaires peuvent être donnés dans un fichier .yaml ou .json et référencés avec l'option --facts. (Les valeurs peuvent être obtenues au format yaml directement depuis facter, ou depuis puppet pour un nœud donné). Notez qu'il n'est pas possible de simuler le nom de variable réservé $facts autrement.
Notez qu'il n'est pas possible de définir des variables en utilisant le Langage Puppet qui ont les mêmes noms que les faits car cela résulte en une erreur ; "tentative de redéfinition d'une variable" puisque les faits sont définis en premier.
Se termine avec 0 s'il n'y a pas eu d'erreurs de validation. En cas d'erreurs, aucune sortie rendue n'est produite pour ce fichier de modèle.
Lors de la conception de modèles EPP, il est fortement recommandé de définir tous les arguments du modèle dans le modèle, et de les fournir dans un hash lors de l'appel à epp ou inline_epp et d'utiliser le moins possible de variables globales, de préférence seulement le hash $facts. Cela rend les modèles plus autonomes et plus faciles à réutiliser et à tester.
OPTIONS --e <source> - Rend un modèle epp en ligne donné sur la ligne de commande.
--facts <fichier_faits> - Un fichier .yaml ou .json contenant un hash de faits mis à disposition dans $facts et $trusted
--[no-]header - Indique s'il faut afficher un en-tête de nom de fichier entre

résultats rendus.
--node <nom_du_nœud> - Le nom du nœud pour lequel les faits sont obtenus. Par défaut, les faits du nœud local.
--values <hash_de_valeurs> - Un Hash sous forme de DSL Puppet donné comme arguments au modèle rendu.
--values_file <fichier_pp_ou_yaml> - Un fichier .pp ou .yaml qui est traité pour produire un hash de valeurs pour le modèle.
RETOURS
Un résultat rendu d'un ou plusieurs modèles donnés.

validate - Valide la syntaxe d'un ou plusieurs modèles EPP : SYNOPSIS
puppet epp validate [--[no-]continue_on_error] [modèle] [modèle ...]
DESCRIPTION
Cette action valide la syntaxe EPP sans produire de sortie.
Lors de la validation, plusieurs problèmes par fichier sont signalés jusqu'aux paramètres de max_error et max_warnings. Le traitement s'arrête après avoir signalé les problèmes pour le premier fichier rencontré avec des erreurs, sauf si l'option --continue_on_error est donnée.
Les fichiers peuvent être donnés en utilisant le style nom_module/modele.epp pour rechercher le modèle dans un module, ou être donnés comme référence à un fichier. Si la référence à un fichier peut être résolue par rapport à un modèle dans un module, la version du module l'emporte - dans ce cas, utilisez un chemin absolu pour référencer le fichier modèle si la version du module n'est pas souhaitée.
Se termine avec 0 s'il n'y a pas eu d'erreurs de validation.
OPTIONS --[no-]continue_on_error - Indique s'il faut continuer ou non après le signalement d'erreurs pour un modèle.
RETOURS
Rien, ou les erreurs de syntaxe rencontrées.

EXEMPLES

render

Rend le modèle du module ´mymodule´ appelé ´mytemplate.epp´, et lui donne deux arguments a et b :

$ puppet epp render mymodule/mytemplate.epp --values ´{a => 10, b => 20}´

Rend un modèle en utilisant un chemin absolu :

$ puppet epp render /tmp/testing/mytemplate.epp --values ´{a => 10, b => 20}´

Rend un modèle avec des données provenant d'un fichier .pp :

$ puppet epp render /tmp/testing/mytemplate.epp --values_file mydata.pp

Rend un modèle avec des données provenant d'un fichier .pp et remplace une valeur en ligne de commande :

$ puppet epp render /tmp/testing/mytemplate.epp --values_file mydata.pp --values ´{a=>10}´

Rend à partir de STDIN :

$ cat template.epp | puppet epp render --values ´{a => 10, b => 20}´

Définit des variables dans un fichier .pp et rend un modèle qui utilise des références de variables :

# fichier data.pp
$greeted = ´une variable globale´
undef
$ puppet epp render -e ´hello <%= $greeted %>´ --values_file data.pp

Rend un modèle qui affiche un fait :

$ facter --yaml > data.yaml
$ puppet epp render -e ´<% $facts[osfamily] %>´ --facts data.yaml

validate

Valide le modèle ´template.epp´ dans le module ´mymodule´ :

$ puppet epp validate mymodule/template.epp

Valide deux fichiers modèles arbitraires :

$ puppet epp validate mymodule/template1.epp yourmodule/something.epp

Valide un modèle quelque part dans le système de fichiers :

  $ puppet epp validate /tmp/testing/template1.epp

Valide un modèle par rapport à un fichier relatif au répertoire courant :

 $ puppet epp validate template1.epp
 $ puppet epp validate ./template1.epp

Valide à partir de STDIN :

$ cat template.epp | puppet epp validate

Continue en cas d'erreur pour voir les erreurs de tous les modèles :

$ puppet epp validate mymodule/template1.epp mymodule/template2.epp --continue_on_error
