NOM

puppet-device - Gérer les appareils réseau distants

SYNOPSIS

Récupère les catalogues du maître Puppet et les applique aux appareils distants.

Cette sous-commande peut être exécutée manuellement ; ou périodiquement à l'aide de cron, d'une tâche planifiée ou d'un outil similaire.

UTILISATION

puppet device [-h|--help] [-v|--verbose] [-d|--debug] [-l|--logdest syslog|fichier|console] [--detailed-exitcodes] [--deviceconfig fichier] [-w|--waitforcert secondes] [--libdir répertoire] [-a|--apply fichier] [-f|--facts] [-r|--resource type [nom]] [-t|--target appareil] [--user=utilisateur] [-V|--version]

DESCRIPTION

Les appareils nécessitent un agent Puppet proxy pour demander des certificats, collecter des facts, récupérer et appliquer des catalogues, et stocker des rapports.

NOTES D'UTILISATION

Les appareils gérés par la sous-commande puppet-device sur un agent Puppet sont configurés dans device.conf, qui est situé par défaut dans $confdir/device.conf et est configurable avec le paramètre $deviceconfig.

Le fichier device.conf est un fichier de type INI, avec une section par appareil :

[NOM_CERTIFICAT_APPAREIL] type TYPE url URL debug

Le nom de la section spécifie le nom de certificat de l'appareil.

Les valeurs des propriétés type et url sont spécifiques à chaque type d'appareil.

La propriété optionnelle debug spécifie le débogage au niveau du transport, et est limitée aux transports telnet et ssh.

Voir https://puppet.com/docs/puppet/latest/config_file_device.html pour plus de détails.

OPTIONS

Notez que tout paramètre valide dans le fichier de configuration est également un argument long valide. Par exemple, ´server´ est un paramètre de configuration valide, vous pouvez donc spécifier ´--server nom_serveur´ comme argument.

--help, -h
Imprimer ce message d'aide
--verbose, -v
Activer le reporting détaillé.
--debug, -d
Activer le débogage complet.
--logdest, -l
Où envoyer les messages de journal. Choisissez entre ´syslog´ (le service syslog POSIX), ´console´, ou le chemin vers un fichier de journal. Si le débogage ou la verbosité est activé, la valeur par défaut est ´console´. Sinon, la valeur par défaut est ´syslog´. Plusieurs destinations peuvent être définies en utilisant une liste séparée par des virgules (par ex. : /chemin/fichier1,console,/chemin/fichier2)"
Un chemin se terminant par ´.json´ recevra une sortie structurée au format JSON. Le fichier journal n'aura pas de ´]´ ajouté automatiquement en raison de la nature d'ajout des journaux. Il doit être ajouté manuellement pour rendre le contenu JSON valide.
--detailed-exitcodes
Fournir des informations de transaction via des codes de sortie. Si cela est activé, un code de sortie de ´1´ signifie qu'au moins un appareil a eu un échec de compilation, un code de sortie de ´2´ signifie qu'au moins un appareil a eu des changements de ressources, et un code de sortie de ´4´ signifie qu'au moins un appareil a eu des échecs de ressources. Les codes de sortie de ´3´, ´5´, ´6´, ou ´7´ signifient qu'une combinaison binaire des codes de sortie précédents s'est produite.
--deviceconfig
Chemin vers le fichier de configuration de l'appareil pour puppet device. Par défaut : $confdir/device.conf
--waitforcert, -w
Cette option n'a d'importance que pour les cibles qui n'ont pas encore de certificats et elle est activée par défaut, avec une valeur de 120 (secondes). Cela amène +puppet device+ à interroger le serveur toutes les 2 minutes et à lui demander de signer une demande de certificat. Ceci est utile pour la configuration initiale d'une cible. Vous pouvez désactiver l'attente des certificats en spécifiant un temps de 0.
--libdir
Remplacer le libdir par appareil par un répertoire local. Spécifier un libdir désactive également pluginsync. Ceci est utile pour les tests.
Un chemin se terminant par ´.jsonl´ recevra une sortie structurée au format JSON Lines.
--apply
Appliquer un manifeste contre une cible distante. La cible doit être spécifiée.
--facts
Affiche les facts d'une cible distante. La cible doit être spécifiée.
--resource
Affiche l'état d'une ressource sous forme de code Puppet, équivalent approximatif de puppet resource. Peut être filtré par titre. Nécessite que --target soit spécifié.
--target
Cibler un appareil/certificat spécifique dans device.conf. Cela effectuera une exécution de périphérique uniquement sur cet appareil/certificat.
--to_yaml
Sortie des ressources trouvées au format YAML, adapté à une utilisation avec Hiera et create_resources.
--user
L'utilisateur sous lequel exécuter.

EXEMPLE

  $ puppet device --target remotehost --verbose
