NOM

puppet-parser - Interagir directement avec l'analyseur.

SYNOPIS

puppet parser action

OPTIONS

Notez que tout paramètre valide dans le fichier de configuration est également un argument long valide, bien qu'il puisse être pertinent ou non pour l'action en cours. Par exemple, server et run_mode sont des paramètres valides, vous pouvez donc spécifier --server <nomserveur>, ou --run_mode <modedexecution> comme argument.

Voir la documentation du fichier de configuration sur https://puppet.com/docs/puppet/latest/configuration.html pour la liste complète des paramètres acceptables. Une liste commentée de toutes les options de configuration peut également être générée en exécutant puppet avec --genconfig.

--render-as FORMAT
Le format dans lequel afficher la sortie. Les formats les plus courants sont json, s (string), yaml, et console, mais d'autres options comme dot sont parfois disponibles.
--verbose
Faut-il journaliser de manière verbeuse.
--debug
Faut-il journaliser les informations de débogage.

ACTIONS

•
dump - Affiche une décomposition de l'arbre d'analyse interne pour le débogage : SYNOPIS
puppet parser dump [--e source] [--[no-]validate] [--format old, pn, ou json] [--pretty] [--format old|pn|json] [--pretty] { -e source | [modèles ...] }
DESCRIPTION
Cette action analyse et valide la syntaxe Puppet DSL sans compiler de catalogue ni synchroniser de ressources.
Le format de sortie peut être contrôlé à l'aide de --format old|pn|json où :
  • ´old´ est le format par défaut, mais maintenant déprécié, qui n'est pas une API.
  • ´pn´ est la notation S-Expression étendue de Puppet.
  • ´json´ affiche le même graphe que ´pn´ mais avec la syntaxe JSON.
La sortie sera « jolie » lorsque l'option --pretty sera donnée avec --format ´pn´ ou ´json´. Cette option n'a aucun effet sur le format ´old´.
La commande accepte un ou plusieurs fichiers manifests (.pp), ou un -e suivi du texte source puppet. Si aucun argument n'est donné, l'entrée standard est lue (sauf si elle est connectée à un terminal)
Le format de sortie de l'arbre décomposé est destiné au débogage et n'est pas une API, il peut changer de temps en temps.
OPTIONS --e <source> - décompose une expression source donnée en ligne de commande.
--format <old, pn, ou json> - Obtient le résultat en format ´old´ (déprécié), ´pn´ (nouveau format), ou ´json´ (nouveau format en JSON).
--pretty - Affiche la sortie de manière agréable. Applicable uniquement avec --format pn ou json
--[no-]validate - Indique s'il faut valider le résultat analysé, si no-validate seules les erreurs de syntaxe sont rapportées
RETOURS
Une décomposition du modèle AST résultant sauf en cas d'erreurs de syntaxe ou de validation.
•
validate - Valide la syntaxe d'un ou plusieurs manifests Puppet : SYNOPIS
puppet parser validate [manifest] [manifest ...]
DESCRIPTION
Cette action valide la syntaxe Puppet DSL sans compiler de catalogue ni synchroniser de ressources. Si aucun fichier manifest n'est fourni, elle validera le manifest de site par défaut.
Lors de la validation, plusieurs problèmes par fichier sont signalés jusqu'aux paramètres max_error et max_warnings. Le traitement s'arrête après avoir signalé les problèmes pour le premier fichier rencontré avec des erreurs.
RETOURS
Rien, ou la première erreur de syntaxe rencontrée.

EXEMPLES

validate

Valide le manifest de site par défaut à l'adresse /etc/puppetlabs/puppet/manifests/site.pp :

$ puppet parser validate

Valide deux fichiers manifest arbitraires :

$ puppet parser validate init.pp vhost.pp

Valide depuis STDIN :

$ cat init.pp | puppet parser validate
