podman-kube-apply(1) Manuel des commandes générales podman-kube-apply(1)

NOM

podman-kube-apply - Appliquer un fichier YAML Kubernetes basé sur des conteneurs, des pods ou des volumes à un cluster Kubernetes

SYNTAXE

podman kube apply [options] [conteneur... | pod... | volume...]

DESCRIPTION

podman kube apply déploie un conteneur, un pod ou un volume podman sur un cluster Kubernetes. Utilisez l'option --file pour déployer également un fichier YAML Kubernetes (spécification v1) sur un cluster Kubernetes.

Notez que le fichier YAML Kubernetes peut être utilisé pour exécuter le déploiement dans Podman via podman-play-kube(1).

OPTIONS

--ca-cert-file=fichier certificat CA chemin | insecure

Le chemin vers le fichier de certificat CA pour le cluster Kubernetes. Généralement, le fichier kubeconfig contient les données du fichier de certificat CA et generate kube le sélectionne automatiquement s'il est disponible dans le kubeconfig. Si aucune donnée de fichier de certificat CA n'est disponible, définissez-le sur insecure pour contourner la vérification du certificat.

--file, -f=fichier yaml chemin

Chemin vers le fichier yaml kubernetes à déployer sur le cluster kubernetes. Ce fichier peut être généré en utilisant la commande podman kube generate. L'entrée peut être sous forme de fichier yaml ou de stdin. Pour stdin, utilisez --file=-.

--kubeconfig, -k=chemin fichier

Chemin vers le fichier kubeconfig à utiliser lors du déploiement du yaml kube généré sur le cluster Kubernetes. La variable d'environnement KUBECONFIG peut également être utilisée pour définir le chemin du fichier kubeconfig. Remarque : Un kubeconfig peut contenir plusieurs configurations de cluster, mais kube generate sélectionne toujours la première configuration de cluster dans le kubeconfig donné.

--ns=espace de noms

L'espace de noms ou le projet sur lequel déployer les charges de travail du fichier yaml kube généré dans le cluster Kubernetes.

--service, -s

Utilisé pour créer un service pour le conteneur ou le pod correspondant déployé sur le cluster. En particulier, si le conteneur ou le pod a des liaisons de port, la spécification du service comprend une déclaration NodePort pour exposer le service. Un port aléatoire est attribué par Podman dans la spécification du service qui est déployé sur le cluster.

EXEMPLES

Appliquer un volume et un conteneur podman à l'espace de noms « default » dans un cluster Kubernetes.

$ podman kube apply --kubeconfig /tmp/kubeconfig myvol vol-test-1
Deploying to cluster...
Successfully deployed workloads to cluster!
$ kubectl get pods
NAME             READY   STATUS    RESTARTS   AGE
vol-test-1-pod   1/1     Running   0          9m

Appliquer un fichier YAML Kubernetes à l'espace de noms « default » dans un cluster Kubernetes.

$ podman kube apply --kubeconfig /tmp/kubeconfig -f vol.yaml
Deploying to cluster...
Successfully deployed workloads to cluster!
$ kubectl get pods
NAME             READY   STATUS    RESTARTS   AGE
vol-test-2-pod   1/1     Running   0          9m

Appliquer un fichier YAML Kubernetes à l'espace de noms « test1 » dans un cluster Kubernetes.

$ podman kube apply --kubeconfig /tmp/kubeconfig --ns test1 vol-test-3
Deploying to cluster...
Successfully deployed workloads to cluster!
$ kubectl get pods --namespace test1
NAME             READY   STATUS    RESTARTS   AGE
vol-test-3-pod   1/1     Running   0          9m
