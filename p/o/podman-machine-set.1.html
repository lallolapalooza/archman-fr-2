NOM

podman-machine-set - Définir un paramètre de machine virtuelle

SYNTAXE

podman machine set [options] [nom]

DESCRIPTION

Modifie un paramètre de machine.

Le nom de machine par défaut est podman-machine-default. Si aucun nom de machine n'est spécifié en tant qu'argument, les paramètres seront appliqués à podman-machine-default.

Uniquement sans privilèges root.

Les paramètres par défaut de la machine Podman peuvent être définis via la section [machine] dans le fichier containers.conf(5).

OPTIONS

--cpus=nombre

Nombre de CPU. Uniquement pris en charge pour les machines QEMU.

--disk-size=nombre

Taille du disque pour la VM invitée en Go. Ne peut qu'être augmentée. Uniquement pris en charge pour les machines QEMU.

--help

Affiche le message d'utilisation.

--memory, -m=nombre

Mémoire (en Mo). Uniquement pris en charge pour les machines QEMU.

--rootful

Si cette machine préfère l'exécution de conteneurs avec privilèges root (true) ou sans privilèges root (false). Cette option met à jour la connexion par défaut du podman distant si elle pointe actuellement vers le nom de machine spécifié (ou podman-machine-default si aucun nom n'est spécifié).

Contrairement à [podman system connection default], cette option fait transiter la socket API, si disponible, vers la socket rootful/rootless dans la VM.

Notez que la modification de cette option signifie que tous les conteneurs/images/volumes existants, etc... ne seront plus visibles avec la connexion/socket par défaut. En effet, les utilisateurs root et non-root dans la VM sont complètement séparés et ne partagent aucun stockage. Les données ne sont cependant pas perdues et vous pouvez toujours modifier cette option pour revenir en arrière ou utiliser l'autre connexion pour y accéder.

--usb=bus=nombre,devnum=nombre ou vendor=hexadécimal,product=hexadécimal ou ""

Attribue un périphérique USB de l'hôte à la VM. Uniquement pris en charge pour les machines QEMU.

Le périphérique doit être présent lorsque la VM démarre. Le périphérique doit avoir les permissions appropriées pour être attribué à la machine podman.

Utilisez une chaîne vide pour supprimer tous les périphériques USB précédemment définis.

Notez que l'utilisation du numéro de bus et de périphérique est plus simple mais que les valeurs peuvent changer à chaque démarrage ou lorsque le périphérique est débranché. L'utilisation du vendeur et du produit peut entraîner des collisions dans le cas de plusieurs périphériques ayant la même valeur vendeur/produit, le premier périphérique disponible est attribué.

--user-mode-networking

Cette option ne peut être utilisée que pour le fournisseur WSL sous Windows. Sur toutes les autres plateformes, cette option est ignorée et le réseau en mode utilisateur sera toujours true car ces fournisseurs dépendent toujours de gvproxy (notre outil de réseau en mode utilisateur pour les VM).

En revanche, le backend Windows/WSL est false par défaut et suit la configuration réseau WSL standard. Changer ce paramètre à true sous Windows/WSL informe Podman de remplacer la configuration réseau WSL au démarrage de cette instance de machine par une distribution réseau en mode utilisateur. Comme WSL partage le même noyau entre les distributions, toutes les autres distributions en cours d'exécution réutilisent ce réseau. De même, lorsque la dernière instance de machine avec un réglage true s'arrête, la configuration réseau d'origine est restaurée.

Dans certaines configurations VPN, le VPN peut ignorer le trafic provenant d'interfaces réseau alternatives, y compris les périphériques réseau VM. En activant le réseau en mode utilisateur, les VPN observent tout le trafic de la machine podman comme provenant de l'hôte, contournant le problème.

EXEMPLES

Pour passer la machine Podman par défaut de sans privilèges root à avec privilèges root :

$ podman machine set --rootful

ou plus explicitement en définissant la valeur à true.

$ podman machine set --rootful=true

Pour passer la machine Podman par défaut de avec privilèges root à sans privilèges root.

$ podman machine set --rootful=false

Pour passer la machine Podman spécifiée de sans privilèges root à avec privilèges root.

$ podman machine set --rootful myvm
