NOM

podman-network - Gérer les réseaux Podman

SYNTAXE

podman network sous-commande

DESCRIPTION

La commande network gère les réseaux pour Podman.

Podman prend en charge deux backends réseau : Netavark et CNI. Netavark est le backend réseau par défaut et a été ajouté à Podman version 4.0. CNI est obsolète et sera supprimé dans la prochaine version majeure de Podman, la version 5.0, au profit de Netavark. Pour configurer le backend réseau, utilisez la clé network_backend sous [Network] dans containers.conf(5). Les nouveaux systèmes utilisent netavark par défaut. Pour vérifier quel backend est utilisé, exécutez podman info --format {{.Host.NetworkBackend}}.

Toutes les commandes réseau fonctionnent pour les deux backends, mais CNI et Netavark utilisent des fichiers de configuration différents, les réseaux doivent donc être recréés après un changement de backend.

NOTES SUR LES SOUS-RÉSEAUX

Podman nécessite des adresses IP par défaut spécifiques et, par conséquent, des sous-réseaux réseau. Les valeurs par défaut utilisées par Podman peuvent être modifiées dans le fichier containers.conf(5).

Réseau Podman

Le réseau bridge par défaut (nommé podman) utilise 10.88.0.0/16 comme sous-réseau. Lorsque Podman s'exécute en tant que root, le réseau podman est utilisé par défaut. C'est l'équivalent de l'ajout de l'option --network bridge ou --network podman. Ce sous-réseau peut être modifié dans containers.conf(5) sous la section [network]. Définissez le default_subnet sur tout sous-réseau disponible dans l'environnement. Le nom du réseau par défaut peut également être modifié de podman à un autre nom en utilisant la clé de réseau par défaut. Notez que cela n'est fait que lorsqu'aucun conteneur n'est en cours d'exécution.

Pasta

Pasta n'effectue par défaut aucune traduction d'adresses réseau (NAT) et copie les adresses IP de votre interface principale dans l'espace de noms du conteneur. Si pasta ne trouve pas d'interface avec la route par défaut, il sélectionnera une interface s'il n'y a qu'une seule interface avec une route valide. Si vous n'avez pas de route par défaut et que plusieurs interfaces ont des routes définies, pasta ne pourra pas déterminer la bonne interface et échouera au démarrage. Pour spécifier l'interface, utilisez l'option -i de pasta. Un ensemble d'options pasta par défaut peut être défini dans containers.conf(5) sous la section [network] avec la clé pasta_options.

L'outil réseau rootless par défaut peut être sélectionné dans containers.conf(5) sous la section [network] avec default_rootless_network_cmd, qui peut être défini sur pasta (par défaut) ou slirp4netns.

Slirp4netns

Slirp4netns utilise 10.0.2.0/24 pour son réseau par défaut. Cela peut également être modifié dans containers.conf(5) mais sous la section [engine]. Utilisez la clé network_cmd_options et ajoutez ["cidr=X.X.X.X/24"] comme valeur. Notez que slirp4netns a besoin d'une taille de préfixe réseau comprise entre 1 et 25. Cette option accepte un tableau, donc plus d'options peuvent être ajoutées dans une chaîne séparée par des virgules, comme décrit dans la page de manuel de podman-network-create(1). Pour changer le CIDR pour un seul conteneur, spécifiez-le sur la ligne de commande en utilisant l'option --network comme suit : --network slirp4netns:cidr=192.168.1.0/24.

Création réseau Podman

Lorsqu'un nouveau réseau est créé avec la commande podman network create et qu'aucun sous-réseau n'est fourni avec l'option --subnet, Podman commence à choisir un sous-réseau libre de 10.89.0.0/24 à 10.255.255.0/24. Utilisez l'option default_subnet_pools sous la section [network] dans containers.conf(5) pour modifier la plage et/ou la taille qui est attribuée par défaut.
