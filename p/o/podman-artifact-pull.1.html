NOM

podman-artifact-pull - Récupère un artefact d'un registre et le stocke localement

SYNTAXE

podman artifact pull [options] source

DESCRIPTION

podman artifact pull copie un artefact d'un registre vers la machine locale.

SOURCE

SOURCE est l'emplacement à partir duquel l'image artefact est obtenue.

# Récupérer depuis un registre
$ podman artifact pull quay.io/foobar/artifact:special

OPTIONS

--authfile=chemin

Chemin du fichier d'authentification. Par défaut, ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'y est pas trouvé, $HOME/.docker/config.json est vérifié, qui est défini à l'aide de docker login.

Note : Il est également possible de remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utilise les certificats à l'emplacement chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--creds=[nomdutilisateur[:motdepasse]]

Le [nomdutilisateur[:motdepasse]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou les deux valeurs ne sont pas fournies, une invite de commande apparaît et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les informations d'identification spécifiées sont uniquement utilisées pour l'authentification auprès des registres cibles. Elles ne sont pas utilisées pour les miroirs ni lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour vous authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--decryption-key=clé[:phraseclée]

La [clé[:phraseclée]] à utiliser pour le déchiffrement des images. La clé peut pointer vers des clés et/ou des certificats. Le déchiffrement est essayé avec toutes les clés. Si la clé est protégée par une phrase secrète, elle doit être fournie dans l'argument et omise sinon.

--help, -h

Affiche l'énoncé d'utilisation.

--quiet, -q

Supprime les informations de sortie lors de la récupération des images

--retry=tentatives

Nombre de tentatives de récupération ou d'envoi d'images entre le registre et le stockage local en cas d'échec. Par défaut, 3.

--retry-delay=durée

Durée du délai entre les tentatives de récupération ou d'envoi d'images entre le registre et le stockage local en cas d'échec. Par défaut, le délai commence à deux secondes puis s'accroît exponentiellement. Le délai est utilisé lorsque cette valeur est définie, et aucune exponentielle ne se produit.

--tls-verify

Exige HTTPS et vérifie les certificats lors du contact avec les registres (par défaut : true). S'il est explicitement défini sur true, la vérification TLS est utilisée. S'il est défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée, sauf si le registre cible est listé comme registre non sécurisé dans containers-registries.conf(5)

FICHIERS

EXEMPLES

Récupérer un artefact depuis un registre

podman artifact pull quay.io/baude/artifact:josey
