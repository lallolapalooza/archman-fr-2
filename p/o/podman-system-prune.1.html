NOM

podman-system-prune - Supprime tous les pods, conteneurs, images, réseaux et données de volume inutilisés

SYNOPIS

podman system prune [options]

DESCRIPTION

podman system prune supprime tous les conteneurs inutilisés (à la fois pendants et non référencés), les conteneurs de build, les pods, les réseaux et facultativement les volumes du stockage local.

Utilisez l'option --all pour supprimer toutes les images inutilisées. Les images inutilisées sont les images pendantes ainsi que toute image qui n'a pas de conteneur basé sur elle.

Par défaut, les volumes ne sont pas supprimés pour éviter la suppression de données importantes s'il n'y a actuellement aucun conteneur utilisant le volume. Utilisez le drapeau --volumes lors de l'exécution de la commande pour supprimer également les volumes.

Par défaut, les conteneurs de build ne sont pas supprimés pour éviter d'interférer avec les builds en cours. Utilisez le drapeau --build lors de l'exécution de la commande pour supprimer également les conteneurs de build.

OPTIONS

--all, -a

Supprime récursivement tous les pods, conteneurs, images, réseaux et données de volume inutilisés. (Maximum 50 itérations.)

--build

Supprime tous les conteneurs de build qui ont été créés pendant le build, mais qui n'ont pas été supprimés car le build a été interrompu de manière inattendue.

Note : Ce n'est pas une opération sûre et ne doit être exécutée que lorsqu'aucun build n'est en cours. Cela peut interférer avec les builds en cours.

--external

Tente de nettoyer les restes de conteneurs ou de couches précédents qui ne sont pas référencés dans les fichiers json de stockage. Ceux-ci peuvent survenir en cas d'arrêts imprévus ou de redémarrages réguliers en mode de stockage transitoire.

Cependant, lors de l'utilisation du mode de stockage transitoire, la base de données Podman ne persiste pas. Cela signifie que les conteneurs laissent les couches inscriptibles sur le disque après un redémarrage. Lors de l'utilisation d'un magasin transitoire, il est recommandé d'exécuter la commande podman system prune --external au démarrage.

Cette option est incompatible avec --all et --filter et supprime le comportement par défaut de suppression des ressources inutilisées.

--filter=filtres

Fournit des valeurs de filtre.

Le format de l'argument filtres est clé=valeur. S'il y a plus d'un filtre, passez plusieurs OPTIONS : --filter foo=bar --filter bif=baz.

Filtres pris en charge :

Filtre Description
label Supprime uniquement les conteneurs et les images, avec (ou sans, dans le cas où label!=[...] est utilisé) les labels spécifiés.
until Supprime uniquement les conteneurs et les images créés avant un horodatage donné.

Le filtre label accepte deux formats. L'un est label=clé ou label=clé=valeur, qui supprime les conteneurs et les images avec les labels spécifiés. L'autre format est label!=clé ou label!=clé=valeur, qui supprime les conteneurs et les images sans les labels spécifiés.

Le filtre until peut être des horodatages Unix, des horodatages formatés par date, ou des chaînes de durée Go (par exemple, 10m, 1h30m) calculées par rapport à l'heure de la machine.

--force, -f

Ne pas demander de confirmation

--help, -h

Afficher l'énoncé d'utilisation

--volumes

Supprime les volumes actuellement inutilisés par aucun conteneur
