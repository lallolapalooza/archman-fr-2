podman-pull(1) Manuel des commandes générales podman-pull(1)

NOM

podman-pull - Télécharger une image depuis un registre

SYNTAXE

podman pull [options] source [source...]

podman image pull [options] source [source...]

podman pull [options] [transport]nom[:tag|@digest]

podman image pull [options] [transport]nom[:tag|@digest]

DESCRIPTION

podman pull copie une image depuis un registre vers la machine locale. La commande peut télécharger une ou plusieurs images. Si la référence de l'image dans l'argument de la ligne de commande ne contient pas de registre, elle est considérée comme une référence de nom court. Si l'image est une référence de 'nom court', Podman invite l'utilisateur à spécifier le registre de conteneurs à partir duquel télécharger l'image, si un alias pour le nom court n'a pas été spécifié dans le fichier short-name-aliases.conf. Si un tag d'image n'est pas spécifié, podman pull utilise par défaut l'image avec le tag latest (si elle existe) et la télécharge. Après le téléchargement de l'image, podman affiche l'identifiant complet de l'image. podman pull peut également télécharger des images en utilisant un digest podman pull image@digest et peut également être utilisé pour télécharger des images à partir d'archives et de stockage local en utilisant différents transports. IMPORTANT : Les images sont stockées dans le stockage d'images local.

SOURCE

SOURCE est l'emplacement à partir duquel l'image du conteneur est téléchargée. Il prend en charge tous les transports de containers-transports(5). Si aucun transport n'est spécifié, l'entrée est soumise à la résolution de nom court et le transport docker (c'est-à-dire registre de conteneurs) est utilisé. Pour les clients distants, y compris les machines Mac et Windows (à l'exception de WSL2), docker est le seul transport pris en charge.

# Télécharger depuis un registre de conteneurs
$ podman pull quay.io/username/myimage
# Télécharger depuis un registre de conteneurs avec résolution de nom court
$ podman pull fedora
# Télécharger depuis un registre de conteneurs via le transport docker
$ podman pull docker://quay.io/username/myimage
# Télécharger depuis un répertoire local
$ podman pull dir:/tmp/myimage
# Télécharger depuis une archive au format docker-archive
$ podman pull docker-archive:/tmp/myimage
# Télécharger depuis un démon docker local
$ sudo podman pull docker-daemon:docker.io/library/myimage:33
# Télécharger depuis une archive au format oci-archive
$ podman pull oci-archive:/tmp/myimage

OPTIONS

--all-tags, -a

Toutes les images taguées du dépôt sont téléchargées.

*IMPORTANT : Lors de l'utilisation de l'option all-tags, Podman n'itère pas sur les registres de recherche dans le fichier containers-registries.conf(5) mais utilise toujours docker.io pour les noms d'images non qualifiés.*

--arch=ARCH

Remplace l'architecture, par défaut celle de l'hôte, de l'image à télécharger. Par exemple, arm. Sauf remplacement, les recherches ultérieures de la même image dans le stockage local correspondent à cette architecture, quel que soit l'hôte.

--authfile=chemin

Chemin du fichier d'authentification. Par défaut, ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'y est pas trouvé, $HOME/.docker/config.json est vérifié, ce qui est défini en utilisant docker login.

Note : Il existe également l'option de remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utilise les certificats situés dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Par défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exception de WSL2)).

--creds=[nomutilisateur[:motdepasse]]

[nomutilisateur[:motdepasse]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou les deux valeurs ne sont pas fournies, une invite de commande apparaît et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les informations d'identification spécifiées sont uniquement utilisées pour s'authentifier auprès des registres cibles. Elles ne sont pas utilisées pour les miroirs ou lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour vous authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--decryption-key=clé[:phrase_de_passe]

[clé[:phrase_de_passe]] à utiliser pour le déchiffrement des images. La clé peut pointer vers des clés et/ou des certificats. Le déchiffrement est tenté avec toutes les clés. Si la clé est protégée par une phrase de passe, elle doit être passée dans l'argument et omise sinon.

--disable-content-trust

Il s'agit d'une option spécifique à Docker pour désactiver la vérification des images auprès d'un registre de conteneurs et elle n'est pas prise en charge par Podman. Cette option est une NOOP (rien ne se passe) et est fournie uniquement pour la compatibilité des scripts.

--help, -h

Affiche l'énoncé d'utilisation.

--os=OS

Remplace le système d'exploitation, par défaut celui de l'hôte, de l'image à télécharger. Par exemple, windows. Sauf remplacement, les recherches ultérieures de la même image dans le stockage local correspondent à ce système d'exploitation, quel que soit l'hôte.

--platform=OS/ARCH

Spécifie la plateforme pour sélectionner l'image. (En conflit avec --arch et --os) L'option --platform peut être utilisée pour remplacer l'architecture et le système d'exploitation actuels. Sauf remplacement, les recherches ultérieures de la même image dans le stockage local correspondent à cette plateforme, quel que soit l'hôte.

--policy

Politique de téléchargement de l'image. La valeur par défaut est always.

  • always: Télécharge toujours l'image et génère une erreur si le téléchargement échoue.
  • missing: Ne télécharge l'image que si elle n'a pas pu être trouvée dans le stockage de conteneurs local. Génère une erreur si aucune image n'a pu être trouvée et que le téléchargement échoue.
  • never: Ne télécharge jamais l'image ; utilise uniquement la version locale. Génère une erreur si l'image n'est pas présente localement.
  • newer: Télécharge si l'image dans le registre est plus récente que celle dans le stockage de conteneurs local. Une image est considérée comme plus récente lorsque les digestions sont différentes. La comparaison des horodatages est sujette à erreurs. Les erreurs de téléchargement sont supprimées si une image locale a été trouvée.

--quiet, -q

Supprime les informations de sortie lors du téléchargement des images

--retry=tentatives

Nombre de tentatives de téléchargement ou d'envoi d'images entre le registre et le stockage local en cas d'échec. Par défaut, c'est 3.

--retry-delay=durée

Durée du délai entre les tentatives de téléchargement ou d'envoi d'images entre le registre et le stockage local en cas d'échec. Par défaut, le délai commence à deux secondes puis augmente exponentiellement. Le délai est utilisé lorsque cette valeur est définie, et aucune augmentation exponentielle ne se produit.

--tls-verify

Exige HTTPS et vérifie les certificats lors du contact avec les registres (par défaut : true). Si explicitement défini sur true, la vérification TLS est utilisée. Si défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée à moins que le registre cible ne soit listé comme registre non sécurisé dans containers-registries.conf(5)

--variant=VARIANT

Utilise VARIANT au lieu de la variante d'architecture par défaut de l'image du conteneur. Certaines images peuvent utiliser plusieurs variantes des architectures arm, comme arm/v5 et arm/v7.

FICHIERS

short-name-aliases.conf

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

podman-pull 1

NOM

podman-pull - Télécharge des images depuis un registre.

SYNOPSIS

podman pull [options] [registry host[/namespace]/]imagename[:tag|@digest]

DESCRIPTION

Commande podman pull pour télécharger des images depuis un registre. Quand des images sont spécifiées sans nom de registre, l'image est tirée des registres non qualifiés spécifiés dans le fichier registries.conf. Pour plus d'informations sur les noms courts, voir la page de manuel containers-registries.conf(5).

Lorsque le système essaie de tirer une image en utilisant un nom court (sans nom de registre), l'utilisateur est invité à sélectionner un registre parmi la liste des registres non qualifiés par défaut définis dans le fichier registries.conf. La sélection de l'utilisateur est ensuite stockée dans un fichier cache pour être utilisée dans toutes les futures expansions de noms courts. Les noms courts rootful sont stockés dans /var/cache/containers/short-name-aliases.conf. Les noms courts rootless sont stockés dans le fichier $HOME/.cache/containers/short-name-aliases.conf.

OPTIONS

--add-host[=name:ip]
Ajoute des entrées au fichier /etc/hosts. La valeur par défaut est name:ip.
--all, -a
Télécharge tous les images et tags disponibles du dépôt spécifié.
--authfile string
Chemin d'accès au fichier d'authentification.
--cert-dir string
Chemin d'accès à un répertoire contenant les certificats TLS pour l'authentification au registre.
--creds string
Identifiants du registre (nom d'utilisateur:mot de passe).
--format string
Format du format de sortie.
--get-content
Extraire et transférer le contenu de l'image.
--help
Aide sur la commande.
--history
Afficher l'historique de l'image.
--identity string
Permet de spécifier un fichier d'identité pour l'authentification.
--list-tags
Liste tous les tags disponibles pour une image.
--omit-content
Ne pas télécharger le contenu de l'image.
--os string
OS de l'image (par exemple, linux).
--policy string
Politique pour le tirage d'image (par exemple, always, missing, never).
--quiet, -q
Ne pas afficher d'informations sur le processus de tirage.
--registry string
Registre à utiliser pour la résolution des noms courts.
--repo string
Nom du dépôt.
--retry int
Nombre de tentatives en cas d'échec (par défaut 3).
--retry-delay duration
Délai entre les tentatives (par défaut 2s).
--security-policy string
Politique de sécurité pour le tirage d'image.
--signature-policy string
Chemin d'accès à la politique de signature.
--storage-driver string
Driver de stockage à utiliser.
--storage-opt string
Options du driver de stockage.
--tls-verify
Vérifie le certificat TLS du registre (par défaut true).
--username string
Nom d'utilisateur pour l'authentification au registre.
--version
Informations sur la version.

FICHIERS

/var/cache/containers/short-name-aliases.conf, $HOME/.cache/containers/short-name-aliases.conf

Lorsque les utilisateurs spécifient des images qui n'incluent pas le registre de conteneurs où l'image est stockée, cela est appelé un nom court. L'utilisation de registres de recherche non qualifiés entraîne une ambiguïté car il n'est pas clair à partir de quel registre une image donnée, référencée par un nom court, peut être tirée.

L'utilisation de noms courts présente le risque de rencontrer des espaces de noms de registre squattés. Si les registres de recherche non qualifiés sont définis sur ["public-registry.com", "my-private-registry.com"], un attaquant peut prendre le contrôle d'un espace de noms de public-registry.com de sorte qu'une image puisse être tirée de public-registry.com au lieu de la source prévue my-private-registry.com.

Bien qu'il soit fortement recommandé d'utiliser toujours des références d'images entièrement qualifiées, les déploiements existants utilisant des noms courts peuvent ne pas être facilement modifiables. Pour contourner l'ambiguïté mentionnée ci-dessus, des alias de noms courts peuvent être configurés pour pointer vers une référence d'image entièrement qualifiée. Les distributions fournissent souvent un fichier d'expansion de noms courts par défaut dans le répertoire /etc/containers/registries.conf.d/. Les administrateurs peuvent utiliser ce répertoire pour ajouter leurs propres fichiers d'expansion de noms courts locaux.

Lors du tirage d'une image, si l'utilisateur ne spécifie pas le registre complet, les moteurs de conteneurs tentent d'étendre le nom court en un nom complet. Si la commande est exécutée avec un tty, l'utilisateur est invité à sélectionner un registre dans la liste des registres non qualifiés par défaut définis dans registries.conf. La sélection de l'utilisateur est ensuite stockée dans un fichier cache pour être utilisée dans toutes les futures expansions de noms courts. Les noms courts rootful sont stockés dans /var/cache/containers/short-name-aliases.conf. Les noms courts rootless sont stockés dans le fichier $HOME/.cache/containers/short-name-aliases.conf.

Pour plus d'informations sur les noms courts, voir containers-registries.conf(5)

registries.conf (/etc/containers/registries.conf)

registries.conf est le fichier de configuration qui spécifie quels registres de conteneurs sont consultés lors de la complétion des noms d'images qui n'incluent pas une partie registre ou domaine.

NOTE : Utilisez la variable d'environnement TMPDIR pour changer l'emplacement de stockage temporaire des images de conteneurs téléchargées. Podman utilise par défaut /var/tmp.
