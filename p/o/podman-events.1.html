NOM

podman-events - Surveiller les événements Podman

SYNTAXE

podman events [options]

podman system events [options]

DESCRIPTION

Surveiller et afficher les événements qui se produisent dans Podman. Chaque événement inclut un horodatage, un type, un statut, un nom (si applicable) et une image (si applicable). Le mécanisme de journalisation par défaut est journald. Ceci peut être modifié dans containers.conf en changeant la valeur de events_logger en file. Seuls file et journald sont acceptés. Un logger none est également disponible, mais ce mécanisme de journalisation désactive complètement les événements; rien n'est rapporté par podman events.

Par défaut, le mode de diffusion (streaming) est utilisé, affichant les nouveaux événements au fur et à mesure qu'ils se produisent. Les événements précédents peuvent être listés via --since et --until.

Le type d'événement container rapporte les statuts suivants :
* attach
* checkpoint
* cleanup
* commit
* connect
* create
* died
* disconnect
* exec
* exec_died
* exited
* export
* import
* init
* kill
* mount
* pause
* prune
* remove
* rename
* restart
* restore
* start
* stop
* sync
* unmount
* unpause
* update

Le type d'événement pod rapporte les statuts suivants :
* create
* kill
* pause
* remove
* start
* stop
* unpause

Le type d'événement image rapporte les statuts suivants :
* loadFromArchive,
* mount
* pull
* pull-error
* push
* remove
* save
* tag
* unmount
* untag

Le type system rapporte les statuts suivants :
* refresh
* renumber

Le type volume rapporte les statuts suivants :
* create
* prune
* remove

Le type secret rapporte les statuts suivants :
* create
* remove

Événements de création verbeux

Définir events_container_create_inspect_data=true dans containers.conf(5) demande à Podman de créer des événements de création de conteneur plus verbeux qui incluent une charge utile JSON avec des informations détaillées sur les conteneurs. La charge utile JSON est identique à celle de podman-container-inspect(1). Le champ associé dans journald est nommé PODMAN_CONTAINER_INSPECT_DATA.

OPTIONS

--filter, -f=filtre

Filtre les événements affichés. Ils doivent être au format "filtre=valeur". Les filtres suivants sont supportés :

Filtre Description
container [Nom ou ID] Nom ou ID du conteneur
event event_status (décrit ci-dessus)
image [Nom ou ID] Nom ou ID de l'image
label [clé] ou [clé=valeur] étiquette
pod [Nom ou ID] Nom ou ID du pod
volume [Nom ou ID] Nom ou ID du volume
type Event_type (décrit ci-dessus)

Dans le cas où un ID est utilisé, l'ID peut être sous sa forme complète ou abrégée. L'événement "die" est mappé à "died" pour la compatibilité avec Docker.

--format

Formate la sortie en lignes JSON ou en utilisant le template Go donné.

Espace réservé Description
.Attributes ... created_at, _by, labels, et plus (map[])
.ContainerExitCode Code de sortie (int)
.ContainerInspectData Charge utile de l'inspection du conteneur
.Error Message d'erreur en cas de statut d'événement d'erreur (par exemple, pull-error)
.HealthStatus Statut de santé (string)
.ID ID du conteneur (SHA complète 64 bits)
.Image Nom de l'image en cours d'exécution (string)
.Name Nom du conteneur (string)
.Network Nom du réseau utilisé (string)
.PodID ID du pod associé au conteneur, le cas échéant
.Status Statut de l'événement (par exemple, create, start, died, ...)
.Time Horodatage de l'événement (string)
.TimeNano Horodatage de l'événement avec précision nanoseconde (int64)
.Type Type d'événement (par exemple, image, conteneur, pod, ...)

--help

Affiche le message d'utilisation.

--no-trunc

Ne pas tronquer la sortie (par défaut true).

--since=horodatage

Afficher tous les événements créés depuis l'horodatage donné

--stream

Diffuser les événements et ne pas quitter après avoir lu le dernier événement connu (par défaut true).

--until=horodatage

Afficher tous les événements créés jusqu'à l'horodatage donné

Les valeurs since et until peuvent être des horodatages au format RFC3339Nano ou une chaîne de durée Go telle que 10m, 5h. Si aucune valeur since ou until n'est fournie, seuls les nouveaux événements sont affichés.

IDENTIFIANTS JOURNALD

Le backend d'événements journald de Podman utilise les identifiants journald suivants. Vous pouvez utiliser ces identifiants pour filtrer directement les événements Podman avec journalctl.

Identifiant Description
SYSLOG_IDENTIFIER Toujours défini sur "podman"
PODMAN_EVENT Le statut de l'événement tel que décrit ci-dessus
PODMAN_TYPE Le type d'événement tel que décrit ci-dessus
PODMAN_TIME L'horodatage de l'écriture de l'événement
PODMAN_NAME Nom de l'objet de l'événement (par exemple, conteneur, image)
PODMAN_ID ID de l'objet de l'événement (par exemple, conteneur, image)
PODMAN_EXIT_CODE Code de sortie du conteneur
PODMAN_POD_ID ID du pod du conteneur
PODMAN_LABELS Étiquettes du conteneur
PODMAN_HEALTH_STATUS Statut de santé du conteneur
PODMAN_CONTAINER_INSPECT_DATA La charge utile JSON de podman-inspect telle que décrite ci-dessus
PODMAN_NETWORK_NAME Nom du réseau

EXEMPLES

Afficher les événements Podman :

$ podman events

2019-03-02 10:33:46.958768077 -0600 CST container init 34503c192940 (image=docker.io/library/alpine:latest, name=friendly_allen)
2019-03-02 10:33:46.973661968 -0600 CST container start 34503c192940 (image=docker.io/library/alpine:latest, name=friendly_allen)
2019-03-02 10:33:50.833761479 -0600 CST container stop 34503c192940 (image=docker.io/library/alpine:latest, name=friendly_allen)
2019-03-02 10:33:51.047104966 -0600 CST container cleanup 34503c192940 (image=docker.io/library/alpine:latest, name=friendly_allen)

$ podman events -f event=create

NAME

podman-events - Display an event stream from the container runtime

SYNOPSIS

podman events [options]

DESCRIPTION

The podman events command returns a stream of events that occur on the container runtime. This command can be used to observe events like container creation, termination, and other events that occur during the container lifecycle.

OPTIONS

--all, -a
Display all events. This includes events related to containers, pods, images, volumes, etc. If this option is not specified, only container events are displayed by default.
--cert-dir path
Path to a directory containing PEM-formatted certificates and private keys, for use in establishing a connection. The certs directory can contain multiple certifcates for the same host, but only one for each host is allowed in the CA directory.
--filter, -f condition
Filter output based on conditions. Supported filters are:
event
Filter by event type. For example, use `event=create` to show only creation events.
id
Filter by ID of the container, pod, volume, or image.
image
Filter by image name. For example, use `image=alpine` to show only events related to the alpine image.
name
Filter by name of the container, pod, volume, or image.
type
Filter by type of object. Supported types are: container, pod, volume, image.
--format template
Format the output using Go's text/template syntax. The default format is table.
--since timestamp
Display events generated since a specified timestamp. The timestamp can be provided in RFC3339 format, or as a duration relative to the current time (e.g., 5m for 5 minutes).
--until timestamp
Display events generated until a specified timestamp. The timestamp can be provided in RFC3339 format, or as a duration relative to the current time (e.g., 5m for 5 minutes).

JOURNALD IDENTIFIERS

If Podman is configured to use journald for logging, the events will include the following journald identifiers:

  • container ID
  • container name
  • image name
  • pod ID
  • pod name
