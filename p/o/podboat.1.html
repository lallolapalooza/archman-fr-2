NOM

podboat - un gestionnaire de téléchargement de podcasts pour terminaux texte

SYNOPSIS

podboat [-C fichier_config] [-q fichier_queue] [-a] [-h]

DESCRIPTION

Podboat est un gestionnaire de podcasts pour terminaux texte. C'est un programme auxiliaire pour Newsboat qui met en file d'attente les téléchargements de podcasts dans un fichier. Ces téléchargements mis en file d'attente peuvent ensuite être téléchargés avec Podboat.

OPTIONS

-h, --help

Afficher l'aide

-C fichier_config, --config-file=fichier_config

Utiliser un fichier de configuration alternatif

-q fichier_queue, --queue-file=fichier_queue

Utiliser un fichier de file d'attente alternatif

--lock-file=fichier_verrou

Utiliser un fichier de verrouillage alternatif

-a, --autodownload

Démarrer le téléchargement automatique de tous les fichiers mis en file d'attente au démarrage

-l niveau_log, --log-level=niveau_log

Générer un fichier journal avec un certain niveau_log (valeurs valides : 1 à 6, pour erreur utilisateur, critique, erreur, avertissement, info et débogage respectivement). Le nom de fichier peut être spécifié à l'aide de l'option --log-file. S'il n'est pas spécifié, un nom de fichier est généré sous la forme podboat_<date-heure>.log

-d fichier_log, --log-file=fichier_log

Utiliser ce fichier_log comme sortie lors de l'enregistrement des messages de débogage. Veuillez noter que cela ne fonctionne qu'en fournissant un niveau de journalisation.

SUPPORT DES PODCASTS

Un podcast est un fichier multimédia distribué sur Internet à l'aide de flux de syndication tels que RSS, pour une lecture ultérieure sur des lecteurs portables ou des ordinateurs. Newsboat prend en charge le téléchargement, la sauvegarde et le streaming de podcasts, bien qu'un lecteur multimédia externe soit nécessaire pour la lecture. Ce support diffère un peu des autres agrégateurs de podcasts ou « podcatchers » dans la manière dont il est effectué.

Le contenu des podcasts est transporté dans les flux RSS via des balises spéciales appelées « enclosures ». Newsboat reconnaît ces enclosures et stocke les informations pertinentes pour chaque élément de podcast qu'il trouve dans un flux RSS. Depuis la version 2.0, il reconnaît et gère également les extensions Yahoo Media RSS.

Les API distantes ne listent pas toujours ces « enclosures », de sorte que les podcasts pourraient être absents de Newsboat. Ces API sont marquées dans la section pertinente de notre documentation. Si une note est manquante mais que vous ne voyez toujours pas d'enclosures dans Newsboat, veuillez signaler un problème et nous allons résoudre cela !

GESTION DES FICHIERS AUDIO AVEC PODBOAT

Ce que l'utilisateur peut faire, c'est ajouter l'URL de téléchargement du podcast à une file d'attente de téléchargement. Alternativement, Newsboat peut être configuré pour le faire automatiquement. Cette file d'attente est stockée dans le fichier queue à côté du fichier cache.db.

L'utilisateur peut ensuite utiliser le gestionnaire de téléchargement podboat pour télécharger ces fichiers dans un répertoire du système de fichiers local. Podboat est livré avec le paquet Newsboat et présente un aspect très proche de celui de Newsboat. Il partage également le même fichier de configuration.

Les podcasts qui ont été téléchargés mais qui n'ont pas encore été lus restent dans la file d'attente mais sont marqués comme téléchargés. Vous pouvez les supprimer en les purgant de la file d'attente avec la touche Maj + P. Après avoir lu un fichier et fermé Podboat, il sera supprimé de la file d'attente. Le fichier téléchargé reste sur le système de fichiers à moins que « delete-played-files » ne soit activé.

Un « cas d'utilisation » courant est de configurer Newsboat pour mettre automatiquement en file d'attente les URL de téléchargement de podcasts nouvellement trouvés. Ensuite, l'utilisateur recharge les flux RSS de podcasts dans Newsboat, et après cela, utilise Podboat pour afficher la file d'attente actuelle, et soit télécharge sélectivement certains fichiers, soit les télécharge automatiquement tous ensemble en appuyant sur A dans Podboat.

COMMANDES DE CONFIGURATION

delete-played-files (paramètres : [oui/non] ; valeur par défaut : non)

Si défini sur oui, Podboat supprimera les fichiers lorsque leur entrée de file d'attente correspondante sera supprimée (cela inclut les entrées « terminé » et « supprimé »). (exemple : delete-played-files oui)

download-path (paramètres : <chemin> ; valeur par défaut : ~/)

Spécifie le répertoire où Podboat doit télécharger les fichiers. Optionnellement, des espaces réservés peuvent être utilisés pour placer les téléchargements dans une structure de répertoires. Voir la section « Chaînes de formatage » du manuel de Newsboat pour les détails sur les formats disponibles. Ce paramètre est appliqué au moment de la mise en file d'attente ; le modifier n'affectera pas les chemins de téléchargement des podcasts qui ont déjà été ajoutés à la file d'attente. (exemple : download-path "~/Téléchargements/%h/%n")

download-filename-format (paramètres : <chaîne> ; valeur par défaut : "%?u?%u&%Y-%b-%d-%H%M%S.unknown?")

Spécifie comment Podboat nommera les fichiers qu'il télécharge (voir aussi download-path). Voir la section « Chaînes de formatage » du manuel de Newsboat pour les détails sur les formats disponibles. (exemple : download-filename-format "%F-%t.%e")

max-downloads (paramètres : <nombre> ; valeur par défaut : 1)

Spécifie le nombre maximum de téléchargements parallèles lorsque le téléchargement automatique est activé. (exemple : max-downloads 3)

player (paramètres : <commande_lecteur> ; valeur par défaut : "")

Spécifie le lecteur qui doit être utilisé pour la lecture des fichiers téléchargés. (exemple : player "mp3blaster")

podlist-format (paramètres : <format> ; valeur par défaut : "%4i [%6dMB/%6tMB] [%5p %%] [%12K] %-20S %u → %F")

Cette variable définit le format des entrées dans la liste de téléchargement de Podboat. Voir la section correspondante de la documentation pour plus d'informations sur les chaînes de format. (exemple : podlist-format "%i %u %-20S %F")

FICHIERS

Par défaut, Newsboat stocke tous les fichiers dans un répertoire traditionnel Unix, c'est-à-dire dans un « dotdir » situé à ~/.newsboat. Cependant, il prend également en charge une méthode moderne, la spécification XDG Base Directory https://standards.freedesktop.org/basedir-spec/basedir-spec-latest.html, qui divise les fichiers entre les emplacements suivants :

1.$XDG_CONFIG_HOME/newsboat/ (XDG_CONFIG_HOME vaut par défaut ~/.config)
2.$XDG_DATA_HOME/newsboat/ (XDG_DATA_HOME vaut par défaut ~/.local/share)

Si le répertoire newsboat existe sous XDG_CONFIG_HOME, alors Newsboat utilisera les répertoires XDG (en créant le répertoire de données si nécessaire). Sinon, Newsboat utilisera par défaut ~/.newsboat.

Si vous utilisez actuellement ~/.newsboat/ mais souhaitez migrer vers les répertoires XDG, vous devriez déplacer les fichiers comme suit :

config, urls

vers $XDG_CONFIG_HOME/newsboat/

cache.db, history.search, history.cmdline, queue

vers $XDG_DATA_HOME/newsboat/

Newsboat et Podboat créent également des « fichiers de verrouillage ». Ceux-ci empêchent de lancer deux instances du même programme, et donc de corrompre vos données. Newsboat et Podboat suppriment ces fichiers lorsque vous quittez le programme, il n'est donc pas nécessaire de les copier quelque part — soyez simplement conscient de leur existence si vous écrivez des scripts qui fonctionnent avec cache.db ou queue. Par défaut, les fichiers de verrouillage sont situés comme suit :

dotdir XDG
Newsboat ~/.newsboat/cache.db.lock $XDG_DATA_HOME/newsboat/cache.db.lock
Podboat ~/.newsboat/pb-lock.pid $XDG_DATA_HOME/newsboat/.lock

Newsboat place le fichier de verrouillage à côté du fichier cache, donc si vous spécifiez le réglage cache-file ou passez l'argument de ligne de commande —cache-file, le chemin vers le fichier de verrouillage changera également. Le verrouillage de Podboat peut être placé ailleurs en utilisant l'argument de ligne de commande —lock-file.

dotfiles

~/.newsboat/config

~/.newsboat/queue

XDG

$XDG_CONFIG_HOME/newsboat/config

$XDG_DATA_HOME/newsboat/queue

Note : si la variable d'environnement XDG_CONFIG_HOME n'est pas définie, Podboat se comporte comme si elle était définie à ~/.config. De même, XDG_DATA_HOME est par défaut ~/.local/share.

ENVIRONNEMENT

BROWSER

Indique à Newsboat quel navigateur utiliser s'il n'y a pas de réglage browser dans le fichier de configuration. Si cette variable n'existe pas, la valeur par défaut lynx(1) sera utilisée.

CURL_CA_BUNDLE

Indique à Newsboat d'utiliser le fichier de certificat spécifié pour vérifier le pair. Le fichier peut contenir plusieurs certificats. Le(s) certificat(s) doivent être au format PEM.

Cette option est utile si votre libcurl est compilée sans informations de certificat utiles, et que vous ne pouvez pas recompiler la bibliothèque vous-même.

EDITOR

Indique à Newsboat quel éditeur de repli utiliser lors de la modification du fichier urls via l'opération edit-urls et qu'aucune variable d'environnement VISUAL n'est définie. Si cette variable n'existe pas non plus, la valeur par défaut vi(1) sera utilisée.

NO_PROXY

Indique à Newsboat d'ignorer le réglage proxy pour certains sites.

Cette variable contient une liste de noms d'hôtes, de noms de domaine et d'adresses IP séparés par des virgules.

Les noms de domaine correspondent aux sous-domaines, c'est-à-dire que « example.com » correspond également à « foo.example.com ». Les noms de domaine qui commencent par un point ne correspondent qu'aux sous-domaines, par exemple « .example.com » correspond à « bar.example.com » mais pas à « example.com » lui-même.

Les adresses IPv6 sont écrites sans crochets et sont comparées comme des chaînes. Ainsi « ::1 » ne correspond pas à « ::0:1 » même s'il s'agit de la même adresse.

PAGER

Indique à Newsboat quel pagineur utiliser si le réglage pager dans le fichier de configuration est explicitement défini sur une chaîne vide.

TMPDIR

Indique à Newsboat d'utiliser le répertoire spécifié pour stocker les fichiers temporaires. Si cette variable n'existe pas, la valeur par défaut /tmp sera utilisée.

VISUAL

Indique à Newsboat quel éditeur utiliser lors de la modification du fichier urls via l'opération edit-urls. Si cette variable n'existe pas, la variable d'environnement EDITOR sera utilisée.

XDG_CONFIG_HOME

Indique à Newsboat quel répertoire de base utiliser pour les fichiers de configuration. Voir également la section sur les fichiers pour plus d'informations.

XDG_DATA_HOME

Indique à Newsboat quel répertoire de base utiliser pour les fichiers de données. Voir également la section sur les fichiers pour plus d'informations.
