NOM

postfix-wrapper - API Postfix multi-instance

DESCRIPTION


La prise en charge de la gestion de plusieurs instances Postfix est disponible à partir de la version 2.6. Les instances partagent les fichiers exécutables et la documentation, mais ont leurs propres répertoires pour les fichiers de configuration, de file d'attente et de données.

Ce document décrit comment l'interface utilisateur familière "postfix start", etc., peut être utilisée pour gérer une ou plusieurs instances Postfix, et donne des détails sur une API pour coordonner les activités entre la commande postfix(1) et un programme de gestion multi-instance.

Avec la prise en charge multi-instance, l'instance Postfix par défaut est toujours requise. Cette instance est identifiée par la valeur par défaut du paramètre config_directory.

FONCTIONNEMENT GÉNÉRAL

La prise en charge multi-instance est rétrocompatible : lorsque vous n'utilisez qu'une seule instance Postfix, les commandes telles que "postfix start" ne changeront pas du tout leur comportement.

Même avec plusieurs instances Postfix, vous pouvez continuer à utiliser les mêmes commandes postfix dans les scripts de démarrage, les procédures de mise à niveau et d'autres endroits. Les commandes font plus de travail, mais les humains ne sont pas obligés d'apprendre de nouvelles astuces.

Par exemple, pour démarrer toutes les instances Postfix, utilisez :

# postfix start

Les autres commandes postfix(1) fonctionnent également comme prévu. Par exemple, pour savoir quelles instances Postfix existent dans une configuration multi-instance, utilisez :

# postfix status

Ceci énumère l'état de toutes les instances Postfix dans une configuration multi-instance.

GESTION D'UNE INSTANCE POSTFIX INDIVIDUELLE

Pour gérer une instance Postfix spécifique, spécifiez son répertoire de configuration sur la ligne de commande de postfix(1) :

# postfix -c /chemin/vers/le/repertoire_config commande

Alternativement, la commande postfix(1) accepte le répertoire de configuration de l'instance via la variable d'environnement MAIL_CONFIG (l'option de ligne de commande -c a une priorité plus élevée).

Sinon, la commande postfix(1) agira sur toutes les instances Postfix.

ACTIVATION DU MODE MULTI-INSTANCE DE POSTFIX(1)

Par défaut, la commande postfix(1) fonctionne en mode mono-instance. Dans ce mode, la commande invoque directement le fichier postfix-script (actuellement installé dans le répertoire des démons). Ce fichier contient les commandes qui démarrent ou arrêtent une instance Postfix, qui mettent à niveau la configuration d'une instance Postfix, etc.

Lorsque la commande postfix(1) fonctionne en mode multi-instance comme décrit ci-dessous, la commande doit exécuter des commandes de démarrage, d'arrêt, etc. pour chaque instance Postfix. Cette multiplication de commandes est gérée par un programme de gestion multi-instance.

L'activation du mode multi-instance de postfix(1) se fait comme suit : dans le fichier main.cf de l'instance Postfix par défaut, 1) spécifiez le chemin d'accès d'un programme de gestion multi-instance avec le paramètre multi_instance_wrapper ; 2) peuplez le paramètre multi_instance_directories avec les chemins d'accès des répertoires de configuration des instances Postfix supplémentaires. Par exemple :

/etc/postfix/main.cf:
    multi_instance_wrapper = $daemon_directory/postfix-wrapper
    multi_instance_directories = /etc/postfix-test

Le fichier $daemon_directory/postfix-wrapper implémente un gestionnaire simple et contient des instructions pour créer des instances Postfix à la main. La commande postmulti(1) fournit une implémentation plus complète, y compris la prise en charge de la gestion du cycle de vie.

Les paramètres multi_instance_directories et autres paramètres de main.cf sont listés ci-dessous dans la section PARAMÈTRES DE CONFIGURATION.

En mode multi-instance, la commande postfix(1) invoque la commande $multi_instance_wrapper au lieu du fichier postfix-script. Ce gestionnaire multi-instance exécute à son tour la commande postfix(1) en mode mono-instance pour chaque instance Postfix.

Pour illustrer les idées principales derrière le fonctionnement multi-instance, voici un exemple d'implémentation de gestionnaire multi-instance simple mais utile :

#!/bin/sh
: ${command_directory?"ne pas invoquer cette commande directement"}
POSTCONF=$command_directory/postconf
POSTFIX=$command_directory/postfix
instance_dirs=`$POSTCONF -h multi_instance_directories |
                sed 'y/,/ /'` || exit 1
err=0
for dir in $config_directory $instance_dirs
do
    case "$1" in
    stop|abort|flush|reload|drain)
        test "`$POSTCONF -c $dir -h multi_instance_enable`" \
            = yes || continue;;
    start)
        test "`$POSTCONF -c $dir -h multi_instance_enable`" \
            = yes || {
            $POSTFIX -c $dir check || err=$?
            continue
        };;
    esac
    $POSTFIX -c $dir "$@" || err=$?
done
exit $err

CONTRÔLES DU GESTIONNAIRE MULTI-INSTANCE PAR INSTANCE

Chaque instance Postfix a son propre fichier main.cf avec des paramètres qui contrôlent le fonctionnement du gestionnaire multi-instance sur cette instance. Cette section discute des réglages les plus importants.

Le réglage "multi_instance_enable = yes" permet au gestionnaire multi-instance de démarrer (arrêter, etc.) l'instance Postfix correspondante. Pour des raisons de sécurité, ce réglage n'est pas le défaut.

Le réglage par défaut "multi_instance_enable = no" est utile pour les tests manuels avec "postfix -c /chemin/nom start", etc. Le gestionnaire multi-instance ne démarrera pas une telle instance et ignorera les commandes telles que "stop" ou "flush" qui nécessitent une instance Postfix en cours d'exécution. Le gestionnaire multi-instance exécutera des commandes telles que "check", "set-permissions" ou "upgrade-configuration", et remplacera "start" par "check" afin que les problèmes soient signalés même lorsque l'instance est désactivée.

MAINTENANCE DES FICHIERS PARTAGÉS ET NON-PARTAGÉS

Certains fichiers sont partagés entre les instances Postfix, tels que les exécutables et les pages de manuel, et certains fichiers sont spécifiques à chaque instance, tels que les fichiers de configuration, les fichiers de file d'attente de courrier et les fichiers de données. Voir la section FICHIERS NON PARTAGÉS ci-dessous pour une liste des fichiers spécifiques à chaque instance.

Avant que la prise en charge multi-instance de Postfix ne soit implémentée, les exécutables, les pages de manuel, etc., ont toujours été maintenus dans le cadre de l'instance Postfix par défaut.

Avec la prise en charge multi-instance, nous continuons simplement à faire cela. Plus précisément, une instance Postfix ne vérifiera ni ne mettra à jour les fichiers partagés lorsque la valeur de config_directory de cette instance est listée avec le paramètre multi_instance_directories du fichier main.cf par défaut.

La conséquence de cette approche est que l'instance Postfix par défaut doit être vérifiée et mise à jour avant toute autre instance.

RÉSUMÉ DE L'API MULTI-INSTANCE

Seul le gestionnaire multi-instance implémente la prise en charge du paramètre de configuration multi_instance_enable. Le gestionnaire multi-instance démarrera uniquement les instances Postfix dont le fichier main.cf a "multi_instance_enable = yes". Un réglage de "no" permet de tester une instance Postfix manuellement.

La commande postfix(1) agit sur une seule instance Postfix lorsque l'option -c est spécifiée, ou lorsque MAIL_CONFIG est présent dans l'environnement du processus. Ceci est nécessaire pour terminer la récursion.

Sinon, lorsque la valeur du paramètre multi_instance_directories n'est pas vide, la commande postfix(1) exécute la commande spécifiée avec le paramètre multi_instance_wrapper, au lieu d'exécuter les commandes dans postfix-script.

Le gestionnaire multi-instance ignore les commandes telles que "stop" ou "reload" qui nécessitent une instance Postfix en cours d'exécution, lorsqu'une instance n'a pas "multi_instance_enable = yes". Cela évite les faux messages d'erreur.

Le gestionnaire multi-instance remplace une commande "start" par "check" lorsque le fichier main.cf d'une instance Postfix n'a pas "multi_instance_enable = yes". Cette substitution garantit que les problèmes seront signalés même lorsque l'instance est désactivée.

MAINTENANCE DES FICHIERS PARTAGÉS ET NON PARTAGÉS

Aucune commande ou script Postfix ne mettra à jour ou ne vérifiera les fichiers partagés lorsque sa valeur `config_directory` est répertoriée dans la valeur du paramètre `multi_instance_directories` du `main.cf` par défaut. Par conséquent, l'instance par défaut doit être vérifiée et mise à jour avant toute instance Postfix qui en dépend.

Les commandes set-gid telles que postdrop(1) et postqueue(1) ajoutent effectivement la valeur de `multi_instance_directories` à la valeur de l'ancien paramètre `alternate_config_directories`. Les commandes utilisent ces informations pour déterminer si une option -c ou un paramètre d'environnement MAIL_CONFIG spécifie une valeur légitime.

L'ancien paramètre `alternate_config_directories` reste nécessaire pour les instances Postfix non par défaut qui exécutent différentes versions de Postfix, ou qui ne sont pas gérées avec l'instance Postfix par défaut.

VARIABLES D'ENVIRONNEMENT

MAIL_CONFIG
Lorsqu'elle est présente, cette variable force la commande postfix(1) à opérer uniquement sur l'instance Postfix spécifiée. Cette variable d'environnement est exportée par l'option -c de postfix(1), de sorte que les commandes postfix(1) dans les processus descendants fonctionnent correctement.

PARAMÈTRES DE CONFIGURATION

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails.

multi_instance_directories (vide)
Une liste facultative de répertoires de configuration Postfix non par défaut ; ces répertoires appartiennent à des instances Postfix supplémentaires qui partagent les fichiers exécutables et la documentation Postfix avec l'instance Postfix par défaut, et qui sont démarrées, arrêtées, etc., ensemble avec l'instance Postfix par défaut.
multi_instance_wrapper (vide)
Le chemin d'accès à une commande de gestionnaire multi-instance que la commande postfix(1) invoque lorsque la valeur du paramètre `multi_instance_directories` n'est pas vide.
multi_instance_name (vide)
Le nom d'instance facultatif de cette instance Postfix.
multi_instance_group (vide)
Le nom de groupe d'instances facultatif de cette instance Postfix.
multi_instance_enable (non)
Permet à cette instance Postfix d'être démarrée, arrêtée, etc., par un gestionnaire multi-instance.

FICHIERS NON PARTAGÉS

config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
data_directory (voir la sortie de 'postconf -d')
Le répertoire contenant les fichiers de données inscriptibles par Postfix (par exemple : caches, nombres pseudo-aléatoires).
queue_directory (voir la sortie de 'postconf -d')
L'emplacement du répertoire de file d'attente de niveau supérieur de Postfix.
