POPEN(3P) Manuel du programmeur POSIX POPEN(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation de cette interface sous Linux peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

popen — initier des flux de tuyaux vers ou depuis un processus

SYNTAXE

#include <stdio.h>
FILE *popen(const char *commande, const char *mode);

DESCRIPTION

La fonction popen() exécute la commande spécifiée par la chaîne commande. Elle crée un tuyau entre le programme appelant et la commande exécutée, et retourne un pointeur vers un flux qui peut être utilisé pour lire ou écrire dans le tuyau.

L'environnement de la commande exécutée sera comme si un processus enfant avait été créé dans l'appel popen() en utilisant la fonction fork(), et que l'enfant ait invoqué l'utilitaire sh en utilisant l'appel :

execl(chemin_shell, "sh", "-c", commande, (char *)0);

où chemin_shell est un chemin d'accès non spécifié pour l'utilitaire sh.

La fonction popen() garantira que tous les flux des appels précédents à popen() qui restent ouverts dans le processus parent sont fermés dans le nouveau processus enfant.

L'argument mode de popen() est une chaîne qui spécifie le mode d'E/S :

1.
Si mode est r, lorsque le processus enfant est démarré, son descripteur de fichier STDOUT_FILENO sera l'extrémité accessible en écriture du tuyau, et le descripteur de fichier fileno(flux) dans le processus appelant, où flux est le pointeur de flux retourné par popen(), sera l'extrémité accessible en lecture du tuyau.
2.
Si mode est w, lorsque le processus enfant est démarré, son descripteur de fichier STDIN_FILENO sera l'extrémité accessible en lecture du tuyau, et le descripteur de fichier fileno(flux) dans le processus appelant, où flux est le pointeur de flux retourné par popen(), sera l'extrémité accessible en écriture du tuyau.
3.
Si mode est une autre valeur, le résultat n'est pas spécifié.

Après popen(), le processus parent et le processus enfant sont tous deux capables d'exécuter indépendamment avant que l'un d'eux ne se termine.

Les flux de tuyaux sont orientés octets.

VALEUR DE RETOUR

En cas de succès, popen() retourne un pointeur vers un flux ouvert qui peut être utilisé pour lire ou écrire dans le tuyau. Sinon, il retourne un pointeur nul et peut définir errno pour indiquer l'erreur.

ERREURS

La fonction popen() échoue si :

EMFILE
Les flux {STREAM_MAX} sont actuellement ouverts dans le processus appelant.

La fonction popen() peut échouer si :

EMFILE
Les flux {FOPEN_MAX} sont actuellement ouverts dans le processus appelant.
EINVAL
L'argument mode est invalide.

La fonction popen() peut également définir des valeurs errno comme décrit par fork() ou pipe().

Les sections suivantes sont informatives.

EXEMPLES

Utilisation de popen() pour obtenir une liste de fichiers depuis l'utilitaire ls

L'exemple suivant démontre l'utilisation de popen() et pclose() pour exécuter la commande ls* afin d'obtenir une liste de fichiers dans le répertoire courant :

#include <stdio.h>
...
FILE *fp;
int status;
char path[PATH_MAX];
fp = popen("ls *", "r");
if (fp == NULL)
    /* Gérer l'erreur */;
while (fgets(path, PATH_MAX, fp) != NULL)
    printf("%s", path);
status = pclose(fp);
if (status == -1) {
    /* Erreur signalée par pclose() */
    ...
} else {
    /* Utiliser les macros décrites sous wait() pour inspecter `status' afin
       de déterminer le succès/l'échec de la commande exécutée par popen() */
    ...
}

USAGE APPLICATIF

Étant donné que les fichiers ouverts sont partagés, une commande en mode r peut être utilisée comme filtre d'entrée et une commande en mode w comme filtre de sortie.

La lecture mise en mémoire tampon avant l'ouverture d'un filtre d'entrée peut laisser l'entrée standard de ce filtre mal positionnée. Des problèmes similaires avec un filtre de sortie peuvent être évités par une gestion attentive de la mise en mémoire tampon ; par exemple, avec fflush().

Un flux ouvert par popen() doit être fermé par pclose().

Le comportement de popen() est spécifié pour les valeurs de mode r et w. D'autres modes tels que rb et wb peuvent être pris en charge par des implémentations spécifiques, mais il ne s'agirait pas de fonctionnalités portables. Notez que les implémentations historiques de popen() vérifient uniquement si le premier caractère de mode est r. Ainsi, un mode de robert le robot serait traité comme mode r, et un mode de tout autre chose serait traité comme mode w.

Si l'application appelle waitpid() ou waitid() avec un argument pid supérieur à 0, et qu'elle a toujours un flux ouvert appelé avec popen(), elle doit s'assurer que pid ne fait pas référence au processus démarré par popen().

Pour déterminer si l'environnement spécifié dans le volume Shell et Utilitaires de POSIX.1‐2017 est présent, utilisez l'appel de fonction :

sysconf(_SC_2_VERSION)

(Voir sysconf()).

RATIONALE

La fonction popen() ne doit pas être utilisée par des programmes qui ont des privilèges d'ID utilisateur (ou de groupe) définis. Les fonctions fork() et la famille exec (sauf execlp() et execvp()) doivent être utilisées à la place. Cela empêche toute manipulation imprévue de l'environnement de l'utilisateur qui pourrait entraîner l'exécution de commandes non anticipées par le programme appelant.

Si le processus d'origine et le processus ouvert via popen() ont tous deux l'intention de lire ou d'écrire, ou de lire et d'écrire un fichier commun, et que l'un d'eux utilisera des fonctions de type FILE C (fread(), fwrite(), et ainsi de suite), les règles de partage des descripteurs de fichiers doivent être respectées (voir la Section 2.5.1, Interaction des descripteurs de fichiers et des flux d'E/S standard).
