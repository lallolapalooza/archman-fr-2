NAME

powervar_cx_usb - Driver for Powervar GTS and UPM Series UPS equipment with USB connection

SYNOPSIS

powervar_cx_usb -h

powervar_cx_usb -a UPS_NAME [OPTIONS]


Note

This man page only documents the hardware-specific features of the Powervar driver. For information about the core driver, see nutupsdrv(8).

SUPPORTED HARDWARE

This driver supports two Powervar UPS families with USB connections:

•UPM (either USB or Serial)
•GTS (USB only)

For serial connected UPM Series devices, see also powervar_cx_ser(8).

EXTRA ARGUMENTS

This driver supports the following optional settings in the ups.conf(5) file:

port = string

Required option for all NUT drivers. Some value must be set, typically auto for drivers that handle USB connections.

Note
This could be a device filesystem path like /dev/usb/hiddev0 but current use of libusb API precludes knowing and matching by such identifiers. They may also be inherently unreliable (dependent on re-plugging and enumeration order). At this time the actual value is ignored, but syntactically some port configuration must still be there.

It is possible to control multiple UPS units simultaneously by running several instances of this driver, provided they can be uniquely distinguished by setting some combination of the vendor, product, vendorid, productid, serial, bus and/or device options detailed below. For devices or operating systems that do not provide sufficient information, the allow_duplicates option can be of use (limited and risky!)

vendorid = regex, productid = regex, vendor = regex, product = regex, serial = regex

Select a specific UPS, in case there is more than one connected via USB. Each option specifies an extended regular expression (see regex(7) for more information on regular expressions), which must match the UPS’s entire respective vendor/product/serial string values (minus any surrounding whitespace), or the whole 4-digit hexadecimal code for vendorid and productid.

Try lsusb(8) or running this NUT driver with -DD command-line argument for finding out the strings to match.

Examples:

•-x vendor="Foo.Corporation.*"
•-x vendorid="051d*" (APC)
•-x product=".*(Smart|Back)-?UPS.*"

bus = regex

OPTIONAL, NOT RECOMMENDED.

Select a UPS on a specific USB bus or group of buses. The argument is a regular expression that must match the bus name where the UPS is connected (e.g. bus="002" or bus="00[2-3]") as seen on Linux in /sys/bus/usb/devices or lsusb(8); including leading zeroes.


Note
Bus numbers are not guaranteed by the OS to be stable across re-boots, kernel driver reloads or device re-plugging (e.g. changing visible population of USB hubs).

device = regex

OPTIONAL, NOT RECOMMENDED.

Select a UPS on a specific USB device or group of devices. The argument is a regular expression that must match the device name where the UPS is connected (e.g. device="001" or device="00[1-2]") as seen on Linux in /sys/bus/usb/devices or lsusb(8); including leading zeroes.


Note
Device numbers are not guaranteed by the OS to be stable across re-boots or device re-plugging.

busport = regex

OPTIONAL, NOT RECOMMENDED.

If supported by the hardware, OS and libusb on the particular deployment, this option should allow to specify physical port numbers on an USB hub, rather than logical device enumeration values, and in turn — this should be less volatile across reboots or re-plugging. The value may be seen in the USB topology output of lsusb -tv on systems with that tool, for example.


Note
This option is not practically supported by some NUT builds (it should be ignored with a warning then), and not by all systems that NUT can run on.

allow_duplicates

OPTIONAL, NOT RECOMMENDED.

If you have several UPS devices which may not be uniquely identified by the options above (e.g. only VID:PID can be discovered there), this flag allows each driver instance where it is set to take the first match if available, or proceed to try another.

Normally the driver initialization would abort at this point claiming "Resource busy" or similar error, assuming that the otherwise properly matched device is unique — and some other process already handles it.


Warning
This feature is inherently non-deterministic! The association of driver instance name to actual device may vary between runs!

If you only care to know that at least one of your no-name UPSes is online, this option can help.

If you must really know which one, it will not!

usb_set_altinterface = bAlternateSetting

Force redundant call to usb_set_altinterface(), especially if needed for devices serving multiple USB roles where the UPS is not represented by the interface number 0 (default).

usb_config_index, usb_hid_rep_index, usb_hid_desc_index, usb_hid_ep_in, usb_hid_ep_out

Force use of specific interface, endpoint, descriptor index etc. numbers, rather than defaulting to 0 (rarely other values in certain drivers for some devices known to use non-zero numbers). Specified as a hexadecimal number.

As a rule of thumb for usb_hid_desc_index discovery, you can see larger wDescriptorLength values (roughly 600+ bytes) in reports of lsusb or similar tools.

LIBUSB_DEBUG = INTEGER

Run-time troubleshooting of USB-capable NUT drivers can involve not only raising the common NUT debug verbosity (e.g. using the DEBUG_MIN setting in ups.conf(5) or protocol commands to change the driver.debug value), but may also benefit from LibUSB specific debugging.

For the latter, you can set the LIBUSB_DEBUG driver option; alternatively you can classically export the environment variable LIBUSB_DEBUG before starting a NUT driver program (may be set and "exported" in driver init script or service method, perhaps via nut.conf(5)), to a numeric value such as 4 ("All messages are emitted").

For more details, including the currently supported values for your version of the library, see e.g.:

•https://libusb.sourceforge.io/api-1.0/
•https://libusb.sourceforge.io/api-1.0/group__libusb__lib.html

startdelay=num

Change startup delay time from 1 second default.

offdelay=num

Change shutdown delay time from 0 second default.

disptesttime=num

Change display test time from the 10 second default (UPM only).

INSTANT COMMANDS

This driver supports the following Instant Commands (see upscmd(8)):

All GTS and UPM UPS units

beeper.disable

Disable the UPS beeper.

beeper.enable

Enable the UPS beeper.

beeper.mute

NOM

powervar_cx_usb - Pilote pour les équipements d'onduleurs Powervar séries GTS et UPM avec connexion USB

SYNTAXE

powervar_cx_usb -h

powervar_cx_usb -a NOM_ONDULEUR [OPTIONS]


Note

Cette page de manuel documente uniquement les fonctionnalités spécifiques au matériel du pilote Powervar. Pour des informations sur le pilote principal, consultez nutupsdrv(8).

MATÉRIEL SUPPORTÉ

Ce pilote prend en charge deux familles d'onduleurs Powervar avec connexions USB :

•UPM (USB ou Série)
•GTS (USB uniquement)

Pour les appareils de la série UPM connectés en série, voir également powervar_cx_ser(8).

ARGUMENTS SUPPLÉMENTAIRES

Ce pilote prend en charge les paramètres optionnels suivants dans le fichier ups.conf(5) :

port = chaîne

Option requise pour tous les pilotes NUT. Une valeur doit être définie, typiquement auto pour les pilotes qui gèrent les connexions USB.

Note
Il peut s'agir d'un chemin de système de fichiers de périphérique comme /dev/usb/hiddev0, mais l'utilisation actuelle de l'API libusb empêche de connaître et de faire correspondre ces identificateurs. Ils peuvent également être intrinsèquement peu fiables (dépendants du rebranchement et de l'ordre d'énumération). Actuellement, la valeur réelle est ignorée, mais syntaxiquement une configuration de port doit toujours être présente.

Il est possible de contrôler plusieurs unités d'onduleur simultanément en exécutant plusieurs instances de ce pilote, à condition qu'elles puissent être distinguées de manière unique en définissant une combinaison des options vendor, product, vendorid, productid, serial, bus et/ou device détaillées ci-dessous. Pour les appareils ou systèmes d'exploitation qui ne fournissent pas suffisamment d'informations, l'option allow_duplicates peut être utile (limitée et risquée !)

vendorid = regex, productid = regex, vendor = regex, product = regex, serial = regex

Sélectionne un onduleur spécifique, s'il y en a plus d'un connecté via USB. Chaque option spécifie une expression régulière étendue (voir regex(7) pour plus d'informations sur les expressions régulières), qui doit correspondre aux valeurs complètes de la chaîne vendeur/produit/série respective de l'onduleur (moins les espaces blancs environnants), ou au code hexadécimal complet à 4 chiffres pour vendorid et productid.

Essayez lsusb(8) ou exécutez ce pilote NUT avec l'argument de ligne de commande -DD pour connaître les chaînes à faire correspondre.

Exemples :

•-x vendor="Foo.Corporation.*"
•-x vendorid="051d*" (APC)
•-x product=".*(Smart|Back)-?UPS.*"

bus = regex

OPTIONNEL, NON RECOMMANDÉ.

Sélectionne un onduleur sur un bus USB spécifique ou un groupe de bus. L'argument est une expression régulière qui doit correspondre au nom du bus sur lequel l'onduleur est connecté (par exemple, bus="002" ou bus="00[2-3]") tel qu'il apparaît sous Linux dans /sys/bus/usb/devices ou lsusb(8) ; y compris les zéros non significatifs.


Note
Les numéros de bus ne sont pas garantis par le système d'exploitation pour être stables lors des redémarrages, des rechargements de pilotes de noyau ou des rebranchements de périphériques (par exemple, modification de la population visible des concentrateurs USB).

device = regex

OPTIONNEL, NON RECOMMANDÉ.

Sélectionne un onduleur sur un périphérique USB spécifique ou un groupe de périphériques. L'argument est une expression régulière qui doit correspondre au nom du périphérique sur lequel l'onduleur est connecté (par exemple, device="001" ou device="00[1-2]") tel qu'il apparaît sous Linux dans /sys/bus/usb/devices ou lsusb(8) ; y compris les zéros non significatifs.


Note
Les numéros de périphérique ne sont pas garantis par le système d'exploitation pour être stables lors des redémarrages ou des rebranchements de périphériques.

busport = regex

OPTIONNEL, NON RECOMMANDÉ.

Si le matériel, le système d'exploitation et libusb le prennent en charge dans le déploiement particulier, cette option devrait permettre de spécifier les numéros de port physiques sur un concentrateur USB, plutôt que les valeurs d'énumération logique des périphériques, et en retour — cela devrait être moins volatile lors des redémarrages ou des rebranchements. La valeur peut être vue dans la sortie de topologie USB de lsusb -tv sur les systèmes disposant de cet outil, par exemple.


Note
Cette option n'est pas pratiquement prise en charge par certaines versions de NUT (elle devrait alors être ignorée avec un avertissement), ni par tous les systèmes sur lesquels NUT peut fonctionner.

allow_duplicates

OPTIONNEL, NON RECOMMANDÉ.

Si vous avez plusieurs appareils d'onduleur qui ne peuvent pas être identifiés de manière unique par les options ci-dessus (par exemple, seul le VID:PID peut être découvert), ce drapeau permet à chaque instance de pilote où il est défini de prendre la première correspondance disponible, ou de continuer à en essayer une autre.

Normalement, l'initialisation du pilote s'arrêterait à ce stade en affirmant "Ressource occupée" ou une erreur similaire, en supposant que l'appareil correctement mis en correspondance est unique — et qu'un autre processus s'en occupe déjà.


Attention
Cette fonctionnalité est intrinsèquement non déterministe ! L'association du nom de l'instance du pilote à l'appareil réel peut varier d'une exécution à l'autre !

Si vous voulez seulement savoir qu'au moins l'un de vos onduleurs sans nom est en ligne, cette option peut vous aider.

Si vous devez vraiment savoir lequel, elle ne le fera pas !

usb_set_altinterface = bAlternateSetting

Force un appel redondant à usb_set_altinterface(), surtout si nécessaire pour les appareils servant plusieurs rôles USB où l'onduleur n'est pas représenté par l'interface numéro 0 (par défaut).

usb_config_index, usb_hid_rep_index, usb_hid_desc_index, usb_hid_ep_in, usb_hid_ep_out

Force l'utilisation d'indices d'interface, de point de terminaison, de descripteur, etc., spécifiques, plutôt que de prendre par défaut 0 (rarement d'autres valeurs dans certains pilotes pour certains appareils connus pour utiliser des nombres non nuls). Spécifié comme un nombre hexadécimal.

En règle générale pour la découverte de usb_hid_desc_index, vous pouvez voir des valeurs plus grandes de wDescriptorLength (environ 600 octets ou plus) dans les rapports de lsusb ou d'outils similaires.

LIBUSB_DEBUG = ENTIER

Le dépannage des pilotes NUT capables d'USB à l'exécution peut impliquer non seulement d'augmenter la verbosité de débogage commune de NUT (par exemple, en utilisant le réglage DEBUG_MIN dans ups.conf(5) ou les commandes de protocole pour changer la valeur driver.debug), mais peut également bénéficier du débogage spécifique à LibUSB.

Pour cela, vous pouvez définir l'option de pilote LIBUSB_DEBUG ; alternativement, vous pouvez classiquement exporter la variable d'environnement LIBUSB_DEBUG avant de démarrer un programme de pilote NUT (peut être défini et "exporté" dans le script d'initialisation du pilote ou la méthode de service, peut-être via nut.conf(5)), à une valeur numérique telle que 4 ("Tous les messages sont émis").

Pour plus de détails, y compris les valeurs actuellement prises en charge pour votre version de la bibliothèque, voir par exemple :

•https://libusb.sourceforge.io/api-1.0/
•https://libusb.sourceforge.io/api-1.0/group__libusb__lib.html

startdelay=num

Change le délai de démarrage de 1 seconde par défaut.

offdelay=num

Change le délai d'arrêt de 0 seconde par défaut.

disptesttime=num

Change le temps de test de l'affichage du défaut de 10 secondes (UPM uniquement).

COMMANDES INSTANTANÉES

Ce pilote prend en charge les commandes instantanées suivantes (voir upscmd(8)) :

Tous les onduleurs GTS et UPM

beeper.disable

Désactive le buzzer de l'onduleur.

beeper.enable

Active le buzzer de l'onduleur.

beeper.mute

Powervar CX USB Control Utility

NAME

powervar_cx_usb - Powervar CX USB Control Utility

SYNOPSIS

powervar_cx_usb [-h|--help] [-q|--quiet] [-v|--version] [-d|--debug] [-D|--daemon] [-c file|--conf file] [-i file|--instonly file] [-l logfile|--logfile logfile] [-p pidfile|--pidpath pidfile] [-x port|--port port] [-u upsname|--upsname upsname] [COMMAND]

DESCRIPTION

The powervar_cx_usb utility controls the Powervar CX series UPS units via USB. It implements the UPS protocol defined by the Network UPS Tools (NUT) project. This driver should handle the Powervar CX series of UPS units.

The UPS unit can be controlled by sending instant commands.

See the nutupsdrv(8) man page for more information about the core driver and the NUT configuration files.

SUPPORTED HARDWARE

Powervar CX Series UPS units with USB interface.

EXTRA ARGUMENTS

This driver supports the following extra arguments:

ups.conf
testime (integer)
Sets the time in seconds for the quick battery test. Default is 120 seconds.
ups.conf
serial_num (string)
The serial number of the UPS. This is optional.
ups.conf
ups.realpower.start.delay (integer)
Delay in seconds before starting the real power test. Default is 10 seconds.
ups.conf
ups.realpower.stop.delay (integer)
Delay in seconds before stopping the real power test. Default is 10 seconds.

INSTANT COMMANDS

This driver supports the following instant commands:

Powervar CX Series UPS units:

mute

Mute the UPS beeper.

unmute

Unmute the UPS beeper.

shutdown.return

Turn off the load possibly after a delay and return when power is back.

shutdown.stop

Stop a shutdown in progress.

shutdown.reboot

Shut down the load briefly while rebooting the UPS.

shutdown.stayoff

Turn off the load and remain off.

test.battery.start.deep

Start a "deep" battery test. This test runs the UPS until the low battery point and then returns to the AC line.

test.battery.start.quick

Start a "quick" battery test. The default time is 2 minutes. This time can be set in the ups.conf file. See testime above.

test.battery.stop

Stops a battery test that is in progress.

test.failure.start

Starts a simulation of an input power failure.

test.failure.stop

Stops a simulation of an input power failure.

All UPM UPS units

test.panel.start

Start testing the UPS panel.

reset.input.minmax

Reset minimum and maximum input voltage status.

WRITABLE VARIABLES

See upsrw(8) to see what variables are writable for the UPS.
