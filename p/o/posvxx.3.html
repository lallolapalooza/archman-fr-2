CPOSVXX calcule la solution du système d'équations linéaires A * X = B pour les matrices PO

Objectif:

!>
!>    CPOSVXX utilise la factorisation de Cholesky A = U**T*U ou A = L*L**T
!>    pour calculer la solution d'un système d'équations linéaires complexes
!>    A * X = B, où A est une matrice hermitienne positive définie de taille N
!>    et X et B sont des matrices de taille N par NRHS.
!>
!>    Si demandé, des bornes d'erreur normées et maximales par composante
!>    sont retournées. CPOSVXX retournera une solution avec une erreur garantie
!>    infime (O(eps) où eps est la précision de la machine de travail)
!>    sauf si la matrice est très mal conditionnée, auquel cas un avertissement
!>    est retourné. Les numéros de condition pertinents sont également
!>    calculés et retournés.
!>
!>    CPOSVXX accepte les factorisations et facteurs d'équilibrage fournis par
!>    l'utilisateur ; voir les définitions des options FACT et EQUED.
!>    La résolution avec raffinement et l'utilisation d'une factorisation
!>    issue d'un appel précédent à CPOSVXX produiront également une solution
!>    avec soit des erreurs O(eps), soit des avertissements, mais nous ne
!>    pouvons pas affirmer cela pour les factorisations et facteurs
!>    d'équilibrage généraux fournis par l'utilisateur s'ils diffèrent de
!>    ce que CPOSVXX produirait lui-même.
!>

Description:

!>
!>    Les étapes suivantes sont effectuées :
!>
!>    1. Si FACT = 'E', des facteurs d'échelle réels sont calculés pour
!>    équilibrer le système :
!>
!>      diag(S)*A*diag(S)     *inv(diag(S))*X = diag(S)*B
!>
!>    Que le système soit équilibré ou non dépend de l'échelle de la matrice A,
!>    mais si l'équilibrage est utilisé, A est écrasé par diag(S)*A*diag(S)
!>    et B par diag(S)*B.
!>
!>    2. Si FACT = 'N' ou 'E', la décomposition de Cholesky est utilisée pour
!>    factoriser la matrice A (après équilibrage si FACT = 'E') comme suit :
!>       A = U**T* U,  si UPLO = 'U', ou
!>       A = L * L**T,  si UPLO = 'L',
!>    où U est une matrice triangulaire supérieure et L est une matrice
!>    triangulaire inférieure.
!>
!>    3. Si le mineur principal de tête d'ordre i n'est pas positif,
!>    la routine retourne avec INFO = i. Sinon, la forme factorisée de A
!>    est utilisée pour estimer le numéro de condition de la matrice
!>    A (voir l'argument RCOND). Si l'inverse du numéro de condition
!>    est inférieur à la précision machine, la routine continue à résoudre
!>    pour X et à calculer les bornes d'erreur comme décrit ci-dessous.
!>
!>    4. Le système d'équations est résolu pour X en utilisant la forme
!>    factorisée de A.
!>
!>    5. Par défaut (sauf si PARAMS(LA_LINRX_ITREF_I) est réglé sur zéro),
!>    la routine utilise le raffinement itératif pour tenter d'obtenir une petite
!>    erreur et de petites bornes d'erreur. Le raffinement calcule le résidu
!>    avec une précision au moins double de celle de travail.
!>
!>    6. Si l'équilibrage a été utilisé, la matrice X est pré-multipliée par
!>    diag(S) de sorte qu'elle résolve le système original avant
!>    l'équilibrage.
!> 
!>     Certains paramètres optionnels sont regroupés dans le tableau PARAMS. Ces
!>     réglages déterminent comment le raffinement est effectué, mais souvent les
!>     valeurs par défaut sont acceptables. Si les valeurs par défaut sont acceptables,
!>     les utilisateurs peuvent passer NPARAMS = 0, ce qui empêche le code source
!>     d'accéder à l'argument PARAMS.
!>

!>    maximales sont retournées. DPOSVXX retournera une solution avec une erreur garantie
!>    infime (O(eps) où eps est la précision de la machine de travail) sauf si la matrice est
!>    très mal conditionnée, auquel cas un avertissement est retourné. Les nombres de condition
!>    pertinents sont également calculés et retournés.
!>
!>    DPOSVXX accepte des factorisations et des facteurs d'équilibrage fournis par l'utilisateur ;
!>    voir les définitions des options FACT et EQUED.
!>    La résolution avec raffinement et l'utilisation d'une factorisation provenant d'un appel
!>    DPOSVXX précédent produiront également une solution avec des erreurs O(eps) ou des avertissements,
!>    mais nous ne pouvons pas affirmer cela pour des factorisations et des facteurs d'équilibrage
!>    généraux fournis par l'utilisateur s'ils diffèrent de ce que DPOSVXX produirait lui-même.
!>

Description :

!>
!>    Les étapes suivantes sont effectuées :
!>
!>    1. Si FACT = 'E', des facteurs d'échelle en double précision sont calculés pour équilibrer
!>    le système :
!>
!>      diag(S)*A*diag(S)     *inv(diag(S))*X = diag(S)*B
!>
!>    Que le système soit équilibré ou non dépend de la mise à l'échelle de la matrice A,
!>    mais si l'équilibrage est utilisé, A est remplacée par diag(S)*A*diag(S) et B par diag(S)*B.
!>
!>    2. Si FACT = 'N' ou 'E', la décomposition de Cholesky est utilisée pour
!>    factoriser la matrice A (après équilibrage si FACT = 'E') comme suit :
!>       A = U**T* U,  si UPLO = 'U', ou
!>       A = L * L**T,  si UPLO = 'L',
!>    où U est une matrice triangulaire supérieure et L est une matrice triangulaire inférieure.
!>
!>    3. Si le mineur principal principal d'ordre i n'est pas positif,
!>    alors la routine retourne avec INFO = i. Sinon, la forme factorisée de A est utilisée pour
!>    estimer le nombre de condition de la matrice A (voir l'argument RCOND). Si l'inverse du nombre de condition
!>    est inférieur à la précision de la machine, la routine continue quand même pour résoudre
!>    pour X et calculer les bornes d'erreur comme décrit ci-dessous.
!>
!>    4. Le système d'équations est résolu pour X en utilisant la forme factorisée de
!>    A.
!>
!>    5. Par défaut (sauf si PARAMS(LA_LINRX_ITREF_I) est mis à zéro),
!>    la routine utilisera le raffinement itératif pour tenter d'obtenir une petite
!>    erreur et des bornes d'erreur. Le raffinement calcule le résidu avec une précision au moins double
!>    de la précision de travail.
!>
!>    6. Si l'équilibrage a été utilisé, la matrice X est pré-multipliée par
!>    diag(S) de sorte qu'elle résolve le système original avant
!>    l'équilibrage.
!> 
!>     Certains paramètres optionnels sont regroupés dans le tableau PARAMS. Ces
!>     paramètres déterminent comment le raffinement est effectué, mais les
!>     valeurs par défaut sont souvent acceptables. Si les valeurs par défaut sont acceptables, les utilisateurs
!>     peuvent passer NPARAMS = 0, ce qui empêche le code source d'accéder
!>     à l'argument PARAMS.
!>

Paramètres

FACT 
!>          FACT est de type CHARACTER*1
!>     Spécifie si la forme factorisée de la matrice A est
!>     fournie ou non à l'entrée, et si ce n'est pas le cas, si la matrice A doit être
!>     équilibrée avant d'être factorisée.
!>       = 'F' : À l'entrée, AF contient la forme factorisée de A.
!>               Si EQUED n'est pas 'N', la matrice A a été
!>               équilibrée avec des facteurs d'échelle donnés par S.
!>               A et AF ne sont pas modifiées.
!>       = 'N' : La matrice A sera copiée dans AF et factorisée.
!>       = 'E' : La matrice A sera équilibrée si nécessaire, puis
!>               copiée dans AF et factorisée.
!>

UPLO

!>          UPLO est de type CHARACTER*1
!>       = 'U' : Le triangle supérieur de A est stocké ;
!>       = 'L' : Le triangle inférieur de A est stocké.
!>

N

!>          N est de type INTEGER
!>     Le nombre d'équations linéaires, c'est-à-dire l'ordre de
!>     la matrice A.  N >= 0.
!>

NRHS

!>          NRHS est de type INTEGER
!>     Le nombre de seconds membres, c'est-à-dire le nombre de colonnes
!>     des matrices B et X.  NRHS >= 0.
!>

!>          A est un tableau de type DOUBLE PRECISION, de dimension (LDA,N)
!>     À l'entrée, la matrice symétrique A, sauf si FACT = 'F' et EQUED =
!>     'Y', alors A doit contenir la matrice équilibrée
!>     diag(S)*A*diag(S).  Si UPLO = 'U', la partie supérieure triangulaire N x N de A contient la partie triangulaire supérieure de
!>     la matrice A, et la partie strictement triangulaire inférieure de A n'est pas référencée.  Si UPLO = 'L', la partie inférieure triangulaire N x N de A contient la partie triangulaire inférieure de la matrice A, et
!>     la partie strictement triangulaire supérieure de A n'est pas référencée.  A n'est pas modifié si FACT = 'F' ou 'N', ou si FACT = 'E' et EQUED =
!>     'N' à la sortie.

!>     À la sortie, si FACT = 'E' et EQUED = 'Y', A est remplacée par
!>     diag(S)*A*diag(S).
!>

LDA

!>          LDA est de type INTEGER
!>     La dimension principale du tableau A.  LDA >= max(1,N).
!>

AF

!>          AF est un tableau de type DOUBLE PRECISION, de dimension (LDAF,N)
!>     Si FACT = 'F', alors AF est un argument d'entrée et contient à l'entrée
!>     le facteur triangulaire U ou L de la décomposition de Cholesky
!>     A = U**T*U ou A = L*L**T, dans le même format de stockage que A.  Si EQUED .ne. 'N', alors AF est la forme factorisée
!>     de la matrice équilibrée diag(S)*A*diag(S).
!>
!>     Si FACT = 'N', alors AF est un argument de sortie et retourne à la sortie
!>     le facteur triangulaire U ou L de la décomposition de Cholesky
!>     A = U**T*U ou A = L*L**T de la matrice originale
!>     A.
!>
!>     Si FACT = 'E', alors AF est un argument de sortie et retourne à la sortie
!>     le facteur triangulaire U ou L de la décomposition de Cholesky
!>     A = U**T*U ou A = L*L**T de la matrice équilibrée
!>     A (voir la description de A pour la forme de la
!>     matrice équilibrée).
!>

LDAF

!>          LDAF est de type INTEGER
!>     La dimension principale du tableau AF.  LDAF >= max(1,N).
!>

EQUED

!>          EQUED est de type CHARACTER*1
!>     Spécifie la forme d'équilibrage qui a été effectuée.
!>       = 'N' : Aucun équilibrage (toujours vrai si FACT = 'N').
!>       = 'Y' : Équilibrage des lignes et des colonnes, c'est-à-dire que A a été
!>               remplacée par diag(S) * A * diag(S).
!>     EQUED est un argument d'entrée si FACT = 'F' ; sinon, c'est un
!>     argument de sortie.
!>

S

!>          S est un tableau de type DOUBLE PRECISION, de dimension (N)
!>     Les facteurs d'échelle des lignes de A.  Si EQUED = 'Y', A est multipliée à

!>     élément de S est une puissance de la base de numération. Si S est en entrée, chaque

!>     et des estimations d'erreur. La mise à l'échelle par des puissances de la base de numération ne provoque pas
!>     d'erreurs d'arrondi, sauf si le résultat sousflue ou déborde.
!>     Les erreurs d'arrondi lors de la mise à l'échelle conduisent au raffinement avec une matrice qui
!>     n'est pas équivalente à la matrice d'entrée, produisant des estimations d'erreur
!>     qui pourrait ne pas être fiable.

!>  Further Details
!>  ===============
!>
!>  The solution and error bounds are computed using the algorithm and
!>  techniques described in the following LAPACK Working Notes:
!>
!>  LAPACK Working Note 165:
!>  "An improved]{  "An improved algorithm for solution and error bounding of
!>  a general system of linear equations"
!>  by L. S. Blackford and J. Waśniewski.
!>
!>  The condition number and forward error bounds are computed using the
!>  following algorithm:
!>
!>  Algorithm:
!>
!>  Compute the LU factorization of A: A = P*L*U.
!>  Check if the U matrix is singular (or close to singular). If so,
!>  RCOND is set to 0 and the routine exits.
!>
!>  Compute S such that diag(S)*A or A*diag(S) has approximately unit
!>  row or column sums respectively.
!>
!>  Compute the reciprocal pivot growth factor RPVGRW.
!>
!>  Compute the condition number estimate.
!>
!>  Compute the solution X to A*X = B.
!>
!>  Iterative refinement (optional):
!>
!>  While (the error is not small enough) and (iter < maxiter):
!>      Compute the residual R = B - A*X.
!>      Compute the solution Z to A*Z = R.
!>      Update the solution X = X + Z.
!>      Increment iter.
!>
!>  Compute the componentwise backward error BERR.
!>
!>  Compute the normwise and componentwise forward error bounds.
!>
!>  The condition number is computed using the infinity norm.
!>
!>  The value of PARAM(3) (LA_LINRX_CWISE_I) determines whether the code
!>  attempts to find a solution with small componentwise relative error.
!>
!>  Equilibration:
!>
!>  Equilibration is performed by scaling the matrix A to be approximately
!>  balanced before the LU factorization. The scaling factors are chosen
!>  to make the largest element in each row or column approximately equal
!>  to 1.
!>
!>  EQUED = 'S': Diagonal matrix S scales rows of A such that
!>               diag(S)*A has unit row sums. B is scaled by S.
!>               Solution of diag(S)*A*X = diag(S)*B.
!>
!>  EQUED = 'C': Diagonal matrix S scales columns of A such that
!>               A*diag(S) has unit column sums. B is NOT scaled.
!>               Solution of A*diag(S)*X = B.
!>
!>  EQUED = 'B': Both scaling are performed. The system becomes
!>               diag(S)*A*diag(S)*X = diag(S)*B.
!>
!>  If equilibration is performed, the solution returned is X. The solution
!>  to the original system is diag(inv(S))*X if EQUED = 'S' or 'B', and
!>  X*diag(inv(S)) if EQUED = 'C'. Note that the returned solution X
!>  is the solution to the equilibrated system.
!>
!>  The componentwise backward error BERR is the smallest value such that
!>  || A*X - B ||_inf / (|| A*X - B ||_inf + || B ||_inf) <= BERR(j),
!>  where || . ||_inf is the maximum absolute row sum norm.
!>
!>  The normwise forward error bound is:
!>
!>  || XTRUE - X ||_inf / || X ||_inf
!>
!>  where XTRUE is the true solution.
!>
!>  The componentwise forward error bound is:
!>
!>  max_j (abs(XTRUE(j,i) - X(j,i)) / abs(X(j,i)))
!>
!>  If the matrix is singular or badly scaled, the solution and error
!>  bounds might be unreliable.
!>
!>  The values ERR_BNDS_NORM(:,1) and ERR_BNDS_COMP(:,1) are boolean flags
!>  which indicate whether the computed error bounds are guaranteed to be
>

Nom


ZPOSVXX - calcule la solution du système d'équations linéaires A * X = B pour les matrices PO.






Description



  ZPOSVXX utilise la factorisation de Cholesky A = UTU ou A = L*LT
  pour calculer la solution d'un système d'équations linéaires complex*16 A * X = B,
  où A est une matrice hermitienne définie positive N-par-N et X et B sont des matrices N-par-NRHS.




  Si demandé, des bornes d'erreur normatives et des bornes d'erreur maximales par composante
  sont retournées. ZPOSVXX retournera une solution avec une petite erreur garantie (O(eps) où eps est la précision de travail de la machine)
  sauf si la matrice est très mal conditionnée, auquel cas un avertissement est retourné.
  Les nombres de condition pertinents sont également calculés et retournés.




  ZPOSVXX accepte les factorisations et les facteurs d'équilibrage fournis par l'utilisateur ;
  voir les définitions des options FACT et EQUED.
  La résolution avec raffinement et l'utilisation d'une factorisation approximative
  sont également possibles.




  Dans la plupart des cas, une meilleure précision peut être obtenue en exécutant
  ZPOSVXX avec la valeur de paramètre FACT='F' (facteur) puis en appelant ZPOSVX
  en utilisant la factorisation retournée dans AF.




  Note : La plupart des routines de diagnostic de LAPACK supposent que la matrice
  des coefficients est numériquement normale. Elles retournent des bornes d'erreur
  et des nombres de condition qui ne sont généralement pas garantis d'être exacts
  à moins que la factorisation de la matrice ne soit exacte. Les routines de diagnostic
  qui sont appelées par cette routine le sont avec l'intention d'obtenir une
  solution et des bornes d'erreur qui sont garanties d'être exactes dans
  la limite de la précision de la machine.




  Dans certains cas, il est possible d'obtenir une meilleure précision en calculant
  la solution au moyen de la décomposition LU plutôt que de la décomposition de
  Cholesky. Si le raffinement itératif est effectué (PARAMS(LA_LINRX_ITREF_I) = 1.0),
  la solution X calculée est garantie d'être la solution exacte à des erreurs
  de précision de machine près, en supposant que la matrice A est bien conditionnée.




  La définition des bornes d'erreur et des nombres de condition est la suivante :





  La norme matricielle infinie est utilisée dans toutes les estimations des erreurs.
  Les matrices A, AF, S, B, X, et WORK sont représentées par des tableaux de
  dimensions (LDA, N), (LDAF, N), (N), (LDB, NRHS), (LDX, NRHS), et (4*N)
  respectivement.

!>    ZPOSVXX utilise la factorisation de Cholesky A = U**T*U ou A = L*L**T

!>    A * X = B, où A est une matrice hermitienne positive définie N-par-N

!>    sont retournées. ZPOSVXX retournera une solution avec une petite erreur garantie (O(eps) où eps est la précision de travail de la machine)
!>    sauf si la matrice est très mal conditionnée, auquel cas un avertissement est retourné.
!>    Les nombres de condition pertinents sont également calculés et retournés.

NAME


posvxx - solves a real symmetric positive definite system of linear
equations A*X = B with error bounds and condition number estimates

Detailed Description


This routine calls the routines SPOTRF, SPOTRI, and SPORFS. Use
    POEQU to compute the scaling and pivoting information. To avoid/limit
    overflow and underflow when computing factorizations and inverses, these
    routines are called.


The purpose of POSVXX is to solve the system of linear equations
    A*X = B, where A is a real symmetric positive definite matrix. In addition
    to the solution X, the routine provides an estimate of the condition
    number of the matrix A, and error bounds for the solution X.


The error bounds are computed by forming the matrices that would
    be used if EQUED was set to "Y", and then calling SPORFS.


The routine first calls SPOTRF to compute the Cholesky
    factorization of A. If the factorization fails, the routine returns an
    error code.


If the factorization is successful, the routine calls SPORFS
    to compute the reciprocal of the condition number and error bounds for the
    solution X. The error bounds are computed using iterative refinement.


The routine returns the solution X, the reciprocal of the condition
    number RCOND, and the error bounds in the arrays ERR_BNDS_NORM and
    ERR_BNDS_COMP.


The routine uses the following parameters to control the computation
    of the solution and error bounds:

ERR_BNDS_COMP


!>          ERR_BNDS_COMP is DOUBLE PRECISION array, dimension (NRHS, N_ERR_BNDS)
!>     For each right-hand side, this array contains information about
!>     various error bounds and condition numbers corresponding to the
!>     componentwise relative error, which is defined as follows:
!>
!>     Componentwise relative error in the ith solution vector:
!>                    abs(XTRUE(j,i) - X(j,i))
!>             max_j ----------------------
!>                         abs(X(j,i))
!>
!>     The array is indexed by the right-hand side i (on which the
!>     componentwise relative error depends), and the type of error
!>     information as described below. There currently are up to three
!>     pieces of information returned for each right-hand side. If
!>     componentwise accuracy is not requested (PARAMS(3) = 0.0), then
!>     ERR_BNDS_COMP is not accessed.  If N_ERR_BNDS < 3, then at most
!>     the first (:,N_ERR_BNDS) entries are returned.
!>
!>     The first index in ERR_BNDS_COMP(i,:) corresponds to the ith
!>     right-hand side.
!>
!>     The second index in ERR_BNDS_COMP(:,err) contains the following
!>     three fields:
!>     err = 1  boolean. Trust the answer if the
!>              reciprocal condition number is less than the threshold
!>              sqrt(n) * dlamch('Epsilon').
!>
!>     err = 2  error bound: The estimated forward error,
!>              almost certainly within a factor of 10 of the true error
!>              so long as the next entry is greater than the threshold
!>              sqrt(n) * dlamch('Epsilon'). This error bound should only
!>              be trusted if the previous boolean is true.
!>
!>     err = 3  Reciprocal condition number: Estimated componentwise
!>              reciprocal condition number.  Compared with the threshold
!!>              sqrt(n) * dlamch('Epsilon') to determine if the error
!>              estimate is . These reciprocal condition
!>              numbers are 1 / (norm(Z^{-1},inf) * norm(Z,inf)) for some
!>              appropriately scaled matrix Z.
!>              Let Z = S*(A*diag(x)), where x is the solution for the
!>              current right-hand side and S scales each row of
!>              A*diag(x) by a power of the radix so all absolute row
!>              sums of Z are approximately 1.
!>
!>     See Lapack Working Note 165 for further details and extra
!>     cautions.
!>
