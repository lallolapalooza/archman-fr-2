NOM

po4a-updatepo - mettre à jour la traduction (au format PO) de la documentation

SYNTAXE

po4a-updatepo -f fmt (-m master.doc)+ (-p XX.po)+

(XX.po sont les sorties, tous les autres sont les entrées)

DESCRIPTION

Le projet po4a (PO pour n'importe quoi) a pour objectif de faciliter les traductions (et plus intéressant encore, la maintenance des traductions) en utilisant les outils gettext dans des domaines où ils n'étaient pas attendus, comme la documentation.

Le script po4a-updatepo est chargé de mettre à jour les fichiers PO pour qu'ils reflètent les changements apportés au fichier de documentation original. Pour ce faire, il convertit le fichier de documentation en un fichier POT, puis appelle msgmerge(1) sur ce nouveau POT et sur les fichiers PO fournis.

Il est possible de donner plus d'un fichier PO (si vous voulez mettre à jour plusieurs langues à la fois), et plusieurs fichiers de documentation (si vous voulez stocker les traductions de plusieurs documents dans le même fichier PO).

Si le document maître contient des caractères non-ASCII, ce script convertira les fichiers PO en UTF-8 (s'ils ne l'étaient pas déjà), pour une gestion transparente des caractères non standard.

OPTIONS

-f, --format
Format de la documentation que vous voulez gérer. Utilisez l'option --help-format pour voir la liste des formats disponibles.
-m, --master
Fichier(s) contenant le document maître à traduire.
-M, --master-charset
Encodage des fichiers contenant le document à traduire. Notez que tous les fichiers doivent avoir le même encodage.
-p, --po
Fichier(s) PO à mettre à jour. Si ces fichiers n'existent pas, ils sont créés par po4a-updatepo.
-o, --option
Option(s) supplémentaire(s) à passer au plugin de format. Voir la documentation de chaque plugin pour plus d'informations sur les options valides et leur signification. Par exemple, vous pourriez passer '-o tablecells' à l'analyseur AsciiDoc, tandis que l'analyseur de texte accepterait '-o tabs=split'.
--no-previous
Cette option retire --previous des options passées à msgmerge. Cela aide à supporter les anciennes versions de gettext (avant la v0.16).
--previous
Cette option ajoute --previous aux options passées à msgmerge. Elle nécessite gettext 0.16 ou plus récent, et est activée par défaut.
--msgmerge-opt options
Options supplémentaires pour msgmerge(1).
-h, --help
Afficher un court message d'aide.
--help-format
Lister les formats de documentation compris par po4a.
-V, --version
Afficher la version du script et quitter.
-v, --verbose
Augmenter la verbosité du programme.
-d, --debug
Afficher des informations de débogage.
--porefs type[,wrap|nowrap]
Spécifier le format de référence. L'argument type peut être never pour ne produire aucune référence, file pour spécifier uniquement le fichier sans le numéro de ligne, counter pour remplacer le numéro de ligne par un compteur croissant, et full pour inclure des références complètes (par défaut : full).

L'argument peut être suivi d'une virgule et du mot clé wrap ou nowrap. Les références sont écrites par défaut sur une seule ligne. L'option wrap renvoie les références sur plusieurs lignes, pour imiter les outils gettext (xgettext et msgmerge). Cette option deviendra la valeur par défaut dans une future version, car elle est plus logique. L'option nowrap est disponible afin que les utilisateurs qui souhaitent conserver l'ancien comportement puissent le faire.

--wrap-po no|newlines|number (défaut : 76)
Spécifie comment le fichier po doit être renvoyé. Cela offre le choix entre des fichiers joliment renvoyés mais qui pourraient entraîner des conflits git, ou des fichiers plus faciles à gérer automatiquement, mais plus durs à lire pour les humains.

Historiquement, la suite gettext reformattait les fichiers po à la 77ème colonne par souci cosmétique. Cette option spécifie le comportement de po4a. Si elle est définie sur une valeur numérique, po4a renverra le fichier po après cette colonne et après les sauts de ligne dans le contenu. Si elle est définie sur newlines, po4a ne divisera le msgid et le msgstr qu'après les sauts de ligne dans le contenu. Si elle est définie sur no, po4a ne renverra pas le fichier po du tout. Le renvoi des commentaires de référence est contrôlé par l'option --porefs.

Notez que cette option n'a aucun impact sur la manière dont le msgid et le msgstr sont renvoyés, c'est-à-dire sur la manière dont les sauts de ligne sont ajoutés au contenu de ces chaînes.

--msgid-bugs-address email@address
Définit l'adresse de rapport pour les bugs msgid. Par défaut, les fichiers POT créés n'ont pas de champs Report-Msgid-Bugs-To.
--copyright-holder string
Définit le détenteur du copyright dans l'en-tête POT. La valeur par défaut est "Free Software Foundation, Inc."
--package-name string
Définit le nom du paquet pour l'en-tête POT. Par défaut, c'est "PACKAGE".
--package-version string
Définit la version du paquet pour l'en-tête POT. Par défaut, c'est "VERSION".
