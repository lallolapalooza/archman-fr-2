NOM

podman-image-trust - Gérer la politique de confiance des images de registre de conteneurs

SYNTAXE

podman image trust set|show [options] registre[/répertoire]

DESCRIPTION

Gère les registres à approuver comme source d'images de conteneurs en fonction de leur emplacement. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exception de WSL2)).

L'emplacement est déterminé par le transport et l'hôte du registre de l'image. En utilisant l'image de conteneur docker://docker.io/library/busybox comme exemple, docker est le transport et docker.io est l'hôte du registre.

La confiance est définie dans /etc/containers/policy.json et est appliquée lorsqu'un utilisateur tente de télécharger une image distante depuis un registre. La politique de confiance dans policy.json décrit une portée de registre (registre et/ou répertoire) pour la confiance. Cette confiance peut utiliser des clés publiques pour les images signées.

La portée de la confiance est évaluée du plus spécifique au moins spécifique. Autrement dit, une politique peut être :

  • Définie pour un registre entier.
  • Définie pour un répertoire particulier dans ce registre.
  • Définie pour une image signée spécifique à l'intérieur du registre.

La liste suivante contient des exemples de valeurs de portée valides utilisées dans policy.json, du plus spécifique au moins spécifique :

docker.io/library/busybox:notlatest

docker.io/library/busybox

docker.io/library

docker.io

Si aucune configuration n'est trouvée pour l'une de ces portées, la valeur par défaut (spécifiée en utilisant « default » au lieu de REGISTRY[/REPOSITORY]) est utilisée.

Le type de confiance fournit un moyen de :

Autoriser (« accept ») ou Refuser (« reject ») des registres ou Exiger une signature de signature simple (« signedBy »), Exiger une signature sigstore (« sigstoreSigned »).

La confiance peut être mise à jour en utilisant la commande podman image trust set pour une portée de confiance existante.

OPTIONS

--help, -h

Affiche le message d'utilisation.

set OPTIONS

--pubkeysfile, -f=CLE1

Un chemin vers une clé publique exportée sur le système local. Les chemins des clés
sont référencés dans policy.json. Tout chemin vers un fichier peut être utilisé, mais il est recommandé de placer le fichier dans /etc/pki/containers. Des options peuvent être utilisées plusieurs fois pour
exiger qu'une image soit signée par plusieurs clés. L'option --pubkeysfile est requise pour les types signedBy et sigstoreSigned.

--type, -t=valeur

Le type de confiance pour cette entrée de politique.
Valeurs acceptées :
signedBy (par défaut) : Exige des signatures simples avec la liste correspondante de
clés publiques.
sigstoreSigned : Exige des signatures sigstore avec la liste correspondante de
clés publiques.
accept : n'exige aucune signature pour cette
portée de registre.
reject : n'accepte pas les images pour cette portée de registre.

show OPTIONS

--json, -j

Affiche la confiance au format JSON pour l'analyse par machine.

--noheading, -n

Omet les en-têtes de tableau de la liste.

--raw

Affiche le fichier de politique de confiance sous forme de JSON brut.

EXEMPLES

Accepter toutes les images non signées d'un registre :

sudo podman image trust set --type accept docker.io

Modifier la politique de confiance par défaut :

sudo podman image trust set -t reject default

Afficher la politique de confiance du système :

podman image trust show
TRANSPORT      NAME                        TYPE        ID                   STORE
all            default                     reject
repository     docker.io/library           accept
repository     registry.access.redhat.com  signed      security@redhat.com  https://access.redhat.com/webassets/docker/content/sigstore
repository     registry.redhat.io          signed      security@redhat.com  https://registry.redhat.io/containers/sigstore
repository     docker.io                   reject
docker-daemon                              accept

Afficher le fichier de politique de confiance :
