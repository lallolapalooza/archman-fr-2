POSTFIX(1) Manuel des commandes générales POSTFIX(1)

NOM

postfix - Programme de contrôle de Postfix

SYNTAXE

postfix [-Dv] [-c config_dir] commande

DESCRIPTION


Cette commande est réservée au superutilisateur. Pour soumettre du courrier, utilisez la commande Postfix sendmail(1).

La commande postfix(1) contrôle le fonctionnement du système de messagerie Postfix : démarrage ou arrêt du démon master(8), vérification de l'état, et autres opérations de maintenance.

Par défaut, la commande postfix(1) configure un environnement standardisé et exécute le script shell postfix-script pour effectuer le travail réel.

Cependant, lorsque la prise en charge de plusieurs instances Postfix est configurée, postfix(1) exécute la commande spécifiée avec le paramètre de configuration multi_instance_wrapper. Cette commande exécutera la commande pour chaque instance Postfix applicable.

Les commandes suivantes sont implémentées :

check
Signale les erreurs de propriété ou de permissions des répertoires/fichiers, et crée les répertoires manquants.
start
Démarre le système de messagerie Postfix. Cela exécute également la vérification de la configuration décrite ci-dessus.
start-fg
Comme start, mais maintient le démon master(8) en cours d'exécution au premier plan, et active le mode « init » de master(8) lorsqu'il est exécuté en tant que PID 1. Cette commande nécessite que le support multi-instance soit désactivé (c'est-à-dire que la valeur du paramètre multi_instance_directories doit être vide).

Lors de l'exécution de Postfix dans un conteneur, consultez MAILLOG_README pour l'enregistrement sur stdout. Postfix enregistre sur syslog par défaut, ce qui nécessite a) l'exécution d'un processus syslogd à l'intérieur du conteneur, ou b) le montage du socket /dev/log de l'hôte du conteneur dans le conteneur (exemple : « docker run -v /dev/log:/dev/log ... »), et c) un préfixe distinct « syslog_name » de Postfix qui identifie les enregistrements provenant de l'instance Postfix.

stop
Arrête le système de messagerie Postfix de manière ordonnée. Si possible, les processus en cours d'exécution sont autorisés à se terminer à leur meilleure convenance.

Note : pour actualiser le système de messagerie Postfix après une modification de configuration, n'utilisez pas les commandes start et stop successivement. Utilisez plutôt la commande reload.

abort
Arrête le système de messagerie Postfix de manière abrupte. Les processus en cours d'exécution reçoivent un signal pour s'arrêter immédiatement.
flush
Force la livraison : tente de livrer chaque message dans la file d'attente des messages différés. Normalement, les tentatives de livraison de courrier retardé se produisent à intervalles réguliers, l'intervalle doublant après chaque tentative échouée.

Avertissement : vider fréquemment le courrier non livrable entraînera une mauvaise performance de livraison de tous les autres courriers.

reload
Relit les fichiers de configuration. Les processus en cours d'exécution se terminent à leur meilleure convenance.
status
Indique si le système de messagerie Postfix est actuellement en cours d'exécution (code de sortie zéro) ou arrêté (code de sortie non nul).
set-permissions [nom=valeur ...]
Définit la propriété et les permissions des fichiers et répertoires liés à Postfix, comme spécifié dans le fichier postfix-files.

Spécifiez nom=valeur pour remplacer et mettre à jour des paramètres de configuration spécifiques de main.cf. Utilisez ceci, par exemple, pour changer le réglage mail_owner ou setgid_group pour un système Postfix déjà installé.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures. Avec Postfix 2.0 et versions antérieures, utilisez « $config_directory/post-install set-permissions ».

logrotate
Fait pivoter le fichier journal spécifié par $maillog_file, en ajoutant un suffixe d'horodatage formaté selon $maillog_file_rotate_suffix, et en compressant le fichier avec la commande spécifiée par $maillog_file_compressor. Cela ne fera pas pivoter les fichiers /dev/*.

Cette fonctionnalité est disponible dans Postfix 3.4 et versions ultérieures.

tls sous-commande
Active le TLS opportuniste dans le client ou le serveur SMTP de Postfix, et gère les clés privées et certificats TLS du serveur SMTP de Postfix. Voir postfix-tls(1) pour la documentation.

Cette fonctionnalité est disponible dans Postfix 3.1 et versions ultérieures.

upgrade-configuration [nom=valeur ...]
Met à jour les fichiers main.cf et master.cf avec les informations dont Postfix a besoin pour fonctionner : ajoute ou met à jour des services, et ajoute ou met à jour des paramètres de configuration.

Spécifiez nom=valeur pour remplacer et mettre à jour des paramètres de configuration spécifiques de main.cf.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures. Avec Postfix 2.0 et versions antérieures, utilisez « $config_directory/post-install upgrade-configuration ».

Les options suivantes sont implémentées :

-c config_dir
Lit les fichiers de configuration main.cf et master.cf dans le répertoire nommé au lieu du répertoire de configuration par défaut. Utilisez ceci pour distinguer plusieurs instances Postfix sur le même hôte.

Avec Postfix 2.6 et versions ultérieures, cette option force la commande postfix(1) à opérer uniquement sur l'instance Postfix spécifiée. Ce comportement est hérité par les commandes postfix(1) qui s'exécutent en tant que descendant du processus actuel.

-D (avec postfix start seulement)
Exécute chaque démon Postfix sous le contrôle d'un débogueur tel que spécifié via le paramètre de configuration debugger_command.
-v
Active l'enregistrement verbeux à des fins de débogage. Plusieurs options -v rendent le logiciel de plus en plus verbeux.

ENVIRONNEMENT

La commande postfix(1) exporte les variables d'environnement suivantes avant d'exécuter le fichier postfix-script :

MAIL_CONFIG
Ceci est défini lorsque l'option de ligne de commande -c est présente.

Avec Postfix 2.6 et versions ultérieures, cette variable d'environnement force la commande postfix(1) à opérer uniquement sur l'instance Postfix spécifiée. Ce comportement est hérité par les commandes postfix(1) qui s'exécutent en tant que descendant du processus actuel.

MAIL_VERBOSE
Ceci est défini lorsque l'option de ligne de commande -v est présente.
MAIL_DEBUG
Ceci est défini lorsque l'option de ligne de commande -D est présente.

Lorsque le service d'enregistrement interne est activé (en définissant une valeur non vide pour le paramètre maillog_file), la commande postfix(1) exporte des paramètres qui sont utilisés par les processus enfants avant qu'ils n'aient traité les paramètres main.cf ou les paramètres de ligne de commande.

POSTLOG_SERVICE
Le nom du point d'accès du service public postlog.
POSTLOG_HOSTNAME
Le nom d'hôte à préfixer à l'enregistrement interne.

PARAMÈTRES DE CONFIGURATION

Les paramètres de configuration main.cf suivants sont exportés en tant que variables d'environnement portant les mêmes noms :

config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
command_d
Annuaire (voir la sortie de 'postconf -d')
L'emplacement de toutes les commandes administratives de Postfix.
daemon_directory (voir la sortie de 'postconf -d')
Le répertoire contenant les programmes de support et les démons de Postfix.
html_directory (voir la sortie de 'postconf -d')
L'emplacement des fichiers HTML de Postfix qui décrivent comment construire, configurer ou exploiter un sous-système ou une fonctionnalité spécifique de Postfix.
mail_owner (postfix)
Le compte système UNIX qui possède la file d'attente Postfix et la plupart des processus démons de Postfix.
mailq_path (voir la sortie de 'postconf -d')
Fonctionnalité de compatibilité Sendmail qui spécifie l'emplacement de la commande mailq(1) de Postfix.
manpage_directory (voir la sortie de 'postconf -d')
Où les pages de manuel de Postfix sont installées.
newaliases_path (voir la sortie de 'postconf -d')
Fonctionnalité de compatibilité Sendmail qui spécifie l'emplacement de la commande newaliases(1).
queue_directory (voir la sortie de 'postconf -d')
L'emplacement du répertoire de file d'attente de haut niveau de Postfix.
readme_directory (voir la sortie de 'postconf -d')
L'emplacement des fichiers README de Postfix qui décrivent comment construire, configurer ou exploiter un sous-système ou une fonctionnalité spécifique de Postfix.
sendmail_path (voir la sortie de 'postconf -d')
Une fonctionnalité de compatibilité Sendmail qui spécifie l'emplacement de la commande sendmail(1) de Postfix.
setgid_group (postdrop)
La propriété de groupe des commandes Postfix définies par set-gid et des répertoires Postfix inscriptibles par le groupe.

Disponible dans Postfix version 2.5 et ultérieures :

data_directory (voir la sortie de 'postconf -d')
Le répertoire contenant les fichiers de données inscriptibles par Postfix (par exemple : caches, nombres pseudo-aléatoires).

Disponible dans Postfix version 3.0 et ultérieures :

compatibility_level (0)
Un filet de sécurité qui fait que Postfix s'exécute avec des paramètres par défaut rétrocompatibles après une mise à niveau vers une nouvelle version de Postfix.
meta_directory (voir la sortie de 'postconf -d')
L'emplacement des fichiers non exécutables qui sont partagés entre plusieurs instances Postfix, tels que postfix-files, dynamicmaps.cf, et les fichiers de modèle multi-instances main.cf.proto et master.cf.proto.
shlib_directory (voir la sortie de 'postconf -d')
L'emplacement des bibliothèques liées dynamiquement de Postfix (libpostfix-*.so), et l'emplacement par défaut des plugins de base de données Postfix (postfix-*.so) qui ont un chemin relatif dans le fichier dynamicmaps.cf.

Disponible dans Postfix version 3.1 et ultérieures :

openssl_path (openssl)
L'emplacement du programme en ligne de commande OpenSSL openssl(1).

Autres paramètres de configuration :

import_environment (voir la sortie de 'postconf -d')
La liste des variables d'environnement qu'un processus Postfix privilégié importera d'un processus parent non-Postfix, ou des remplacements d'environnement nom=valeur.
syslog_facility (mail)
La facilité syslog de la journalisation Postfix.
syslog_name (voir la sortie de 'postconf -d')
Un préfixe qui est ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, "smtpd" devienne "prefix/smtpd".

Disponible dans Postfix version 2.6 et ultérieures :

multi_instance_directories (vide)
Une liste facultative de répertoires de configuration Postfix non par défaut ; ces répertoires appartiennent à des instances Postfix supplémentaires qui partagent les fichiers exécutables et la documentation Postfix avec l'instance Postfix par défaut, et qui sont démarrées, arrêtées, etc., conjointement avec l'instance Postfix par défaut.
multi_instance_wrapper (vide)
Le chemin d'accès à une commande de gestion multi-instances que la commande postfix(1) invoque lorsque la valeur du paramètre multi_instance_directories n'est pas vide.
multi_instance_group (vide)
Le nom de groupe d'instance facultatif de cette instance Postfix.
multi_instance_name (vide)
Le nom d'instance facultatif de cette instance Postfix.
multi_instance_enable (no)
Autoriser cette instance Postfix à être démarrée, arrêtée, etc., par un gestionnaire multi-instances.

Disponible dans Postfix version 3.4 et ultérieures :

maillog_file (vide)
Le nom d'un fichier journal facultatif écrit par le service postlogd(8) de Postfix.
maillog_file_compressor (gzip)
Le programme à exécuter après la rotation de $maillog_file avec "postfix logrotate".
maillog_file_prefixes (/var, /dev/stdout)
Une liste de préfixes autorisés pour une valeur de maillog_file.
maillog_file_rotate_suffix (%Y%m%d-%H%M%S)
Le format du suffixe à ajouter à $maillog_file lors de la rotation du fichier avec "postfix logrotate".
postlog_service_name (postlog)
Le nom de l'entrée de service postlogd(8) dans master.cf.

FICHIERS

Avant la version 2.6 de Postfix, tous les fichiers suivants se trouvaient dans $config_directory. Certains fichiers se trouvent maintenant dans $daemon_directory ou $meta_directory afin de pouvoir être partagés entre plusieurs instances exécutant la même version de Postfix.

Utilisez la commande "postconf config_directory" ou "postconf daemon_directory" pour développer les noms en leurs valeurs réelles.

$config_directory/main.cf, Paramètres de configuration de Postfix

$daemon_directory/postfix-script, Commandes administratives
$daemon_directory/post-install, Configuration post-installation
$meta_directory/dynamicmaps.cf, Clients de base de données plug-in
$meta_directory/postfix-files, Permissions de fichiers/répertoires

FICHIERS README

postfix(1) — Manuel d'administration Linux

NAME

postfix — Postfix mail system control program

SYNOPSIS

postfix inline|check|flush|get-value|new-config|pid|ping|release|send-proc|set-value|show-config|signal-process|status|stop|throttle|trace|version

DESCRIPTION

The postfix command is a wrapper around the Postfix low-level control program. It allows you to start, stop, and manage the Postfix mail system. This program is not intended to be used directly by users, but rather by system administration scripts.

ENVIRONMENT

The postfix command respects the following environment variables:

SHELL
The shell to use for controlling Postfix processes. Defaults to /bin/sh.
POSTFIX_BINDIR
The directory containing Postfix binary commands. Defaults to /usr/sbin.
POSTFIX_CONFIG_DIR
The directory containing Postfix configuration files. Defaults to /etc/postfix.

CONFIGURATION PARAMETERS

The behavior of Postfix is controlled by parameters in the main.cf file. Use "postconf" to view these settings.

FILES

Use "postconf readme_directory" or "postconf html_directory" to locate this information.
