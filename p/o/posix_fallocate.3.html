posix_fallocate(3) Manuel des fonctions de bibliothèque posix_fallocate(3)

NOM

posix_fallocate - allouer de l'espace disque à un fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <fcntl.h>
int posix_fallocate(int fd, off_t offset, off_t size);
Exigences relatives aux macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

posix_fallocate() :

    _POSIX_C_SOURCE >= 200112L

DESCRIPTION

La fonction posix_fallocate() garantit que de l'espace disque est alloué pour le fichier référencé par le descripteur de fichier fd pour les octets dans la plage commençant à offset et continuant sur size octets. Après un appel réussi à posix_fallocate(), les écritures ultérieures sur les octets dans la plage spécifiée sont garanties de ne pas échouer en raison d'un manque d'espace disque.

Si la taille du fichier est inférieure à offset+size, alors le fichier est agrandi à cette taille ; sinon, la taille du fichier reste inchangée.

VALEUR DE RETOUR

posix_fallocate() retourne zéro en cas de succès, ou un numéro d'erreur en cas d'échec. Notez qu’errno n’est pas défini.

ERREURS

EBADF
fd n'est pas un descripteur de fichier valide, ou n'est pas ouvert en écriture.
EFBIG
offset+size dépasse la taille maximale du fichier.
EINTR
Un signal a été intercepté pendant l'exécution.
EINVAL
offset était inférieur à 0, ou size était inférieur ou égal à 0, ou le système de fichiers sous-jacent ne prend pas en charge l'opération.
ENODEV
fd ne fait pas référence à un fichier régulier.
ENOSPC
Il n'y a plus assez d'espace sur le périphérique contenant le fichier référencé par fd.
EOPNOTSUPP
Le système de fichiers contenant le fichier référencé par fd ne prend pas en charge cette opération. Ce code d'erreur peut être retourné par les bibliothèques C qui n'effectuent pas l'émulation indiquée dans les MISES EN GARDE, comme musl libc.
ESPIPE
fd fait référence à un tube (pipe).

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
posix_fallocate () Sécurité des threads MT-Safe (mais voir MISES EN GARDE)

NORMES

POSIX.1-2008.

HISTORIQUE

glibc 2.1.94. POSIX.1-2001

POSIX.1-2008 indique qu'une implémentation doit renvoyer l'erreur EINVAL si size était 0, ou offset était inférieur à 0. POSIX.1-2001 indique qu'une implémentation doit renvoyer l'erreur EINVAL si size est inférieur à 0, ou offset était inférieur à 0, et peut renvoyer l'erreur si size est égal à zéro.

MISES EN GARDE

Dans l'implémentation glibc, posix_fallocate() est implémentée en utilisant l'appel système fallocate(2), qui est MT-safe. Si le système de fichiers sous-jacent ne prend pas en charge fallocate(2), l'opération est émulée avec les mises en garde suivantes :

•
L'émulation est inefficace.
•
Il existe une condition de concurrence où des écritures concurrentes provenant d'un autre thread ou processus pourraient être écrasées par des octets nuls.
•
Il existe une condition de concurrence où des augmentations de taille de fichier concurrentes par un autre thread ou processus pourraient résulter en un fichier dont la taille est inférieure à celle attendue.
•
Si fd a été ouvert avec les drapeaux O_APPEND ou O_WRONLY, la fonction échoue avec l'erreur EBADF.

En général, l'émulation n'est pas MT-safe. Sous Linux, les applications peuvent utiliser fallocate(2) si elles ne peuvent pas tolérer les mises en garde de l'émulation. En général, cela n'est recommandé que si l'application prévoit de terminer l'opération si EOPNOTSUPP est renvoyé, sinon l'application elle-même devra implémenter un repli avec tous les mêmes problèmes que l'émulation fournie par glibc.

VOIR AUSSI

fallocate(1), fallocate(2), lseek(2), posix_fadvise(2)
