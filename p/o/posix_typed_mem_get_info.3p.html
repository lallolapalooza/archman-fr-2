POSIX_TYPED_MEM_GET_INFO(3P) Manuel du programmeur POSIX POSIX_TYPED_MEM_GET_INFO(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

posix_typed_mem_get_info — interroger les informations sur la mémoire typée (TEMPS RÉEL AVANCÉ)

SYNOPIS

#include <sys/mman.h>
int posix_typed_mem_get_info(int fildes,
    struct posix_typed_mem_info *info);

DESCRIPTION

La fonction posix_typed_mem_get_info() renvoie, dans le champ posix_tmi_length de la structure posix_typed_mem_info pointée par info, la longueur maximale qui peut être allouée avec succès par l'objet de mémoire typée désigné par fildes. Cette longueur maximale prendra en compte le drapeau POSIX_TYPED_MEM_ALLOCATE ou POSIX_TYPED_MEM_ALLOCATE_CONTIG spécifié lors de l'ouverture de l'objet de mémoire typée représenté par fildes. La longueur maximale est dynamique ; par conséquent, la valeur renvoyée n'est valide que tant que le mappage actuel du pool de mémoire typée correspondant reste inchangé.

Si fildes représente un objet de mémoire typée ouvert sans le drapeau POSIX_TYPED_MEM_ALLOCATE ni le drapeau POSIX_TYPED_MEM_ALLOCATE_CONTIG spécifié, la valeur renvoyée de info->posix_tmi_length est indéterminée.

La fonction posix_typed_mem_get_info() peut renvoyer des informations supplémentaires définies par l'implémentation dans d'autres champs de la structure posix_typed_mem_info pointée par info.

Si l'objet mémoire spécifié par fildes n'est pas un objet de mémoire typée, alors le comportement de cette fonction est indéfini.

VALEUR RENVOYÉE

En cas de succès, la fonction posix_typed_mem_get_info() renvoie zéro ; sinon, la valeur du statut d'erreur correspondante est renvoyée.

ERREURS

La fonction posix_typed_mem_get_info() échouera si :

EBADF
L'argument fildes n'est pas un descripteur de fichier ouvert valide.
ENODEV
L'argument fildes n'est pas connecté à un objet mémoire pris en charge par cette fonction.

Cette fonction ne renverra pas le code d'erreur [EINTR].

RATIONALE

Une application qui a besoin d'allouer un bloc de mémoire typée dont la longueur dépend de la quantité de mémoire actuellement disponible doit soit interroger l'objet de mémoire typée pour obtenir la quantité disponible, soit invoquer répétitivement mmap() en tentant de deviner une longueur appropriée. Bien que cette dernière méthode soit une pratique courante avec malloc(), elle est maladroite et imprécise. La fonction posix_typed_mem_get_info() permet à une application de déterminer immédiatement la mémoire disponible. Ceci est particulièrement important pour les objets de mémoire typée qui peuvent dans certains cas être des ressources rares. Notez que lorsqu'un pool de mémoire typée est une ressource partagée, une forme d'exclusion mutuelle ou de synchronisation peut être nécessaire pendant que la mémoire typée est interrogée et allouée pour éviter les conditions de concurrence.

La fonction existante fstat() n'est pas adaptée à cet effet. Nous réalisons que les implémentations peuvent souhaiter fournir d'autres attributs des objets de mémoire typée (par exemple, exigences d'alignement, taille de page, etc.). La fonction fstat() renvoie une structure qui n'est pas extensible et, de plus, contient des informations substantielles qui sont inappropriées pour les objets de mémoire typée.
