NOM

podman-machine-init - Initialise une nouvelle machine virtuelle

SYNTAXE

podman machine init [options] [nom]

DESCRIPTION

Initialise une nouvelle machine virtuelle pour Podman.

Le nom de machine par défaut est podman-machine-default. Si aucun nom de machine n'est spécifié en argument, la nouvelle machine sera nommée podman-machine-default.

Sans privilèges (Rootless) uniquement.

Podman sur MacOS et Windows nécessite une machine virtuelle. Ceci est dû au fait que les conteneurs sont basés sur Linux ; les conteneurs ne fonctionnent pas sur d'autres systèmes d'exploitation car leurs fonctionnalités principales sont liées au noyau Linux. Podman machine doit être utilisé pour gérer les machines MacOS et Windows, mais peut être utilisé en option sous Linux.

podman machine init initialise une nouvelle machine virtuelle Linux où les conteneurs seront exécutés. Les clés SSH sont automatiquement générées pour accéder à la VM, et les connexions système au compte root et à un compte utilisateur dans la VM sont ajoutées.

Par défaut, la distribution de la VM est une image personnalisée basée sur Fedora CoreOS poussée vers quay.io/podman/machine-os (construite dans https://github.com/containers/podman-machine-os). WSL fait exception et est basé sur une image Fedora personnalisée.

Pour vérifier s'il existe une mise à jour disponible pour le système d'exploitation de votre machine, vous pouvez exécuter la commande suivante :

$ podman machine ssh 'sudo rpm-ostree upgrade --check'

Si une mise à jour est disponible, vous pouvez réexécuter la commande ci-dessus en supprimant --check et votre système d'exploitation sera mis à jour. Après la mise à jour, vous devez arrêter et démarrer votre machine avec podman machine stop && podman machine start pour qu'elle prenne effet.

Le mécanisme ci-dessus est uniquement utilisé pour mettre à jour les versions de correctif (Z) de Podman. Pour les mises à jour vers de nouvelles versions majeures et mineures (X.Y), utilisez la commande podman machine os apply, consultez la documentation associée pour plus d'informations.

Note : Les mises à jour décrites ci-dessus peuvent entraîner des incompatibilités de version entre Podman sur l'hôte et Podman dans la machine. L'exécution de podman info devrait révéler les versions des deux. Une configuration où l'hôte et la machine Podman ne correspondent pas n'est pas prise en charge.

Pour mettre à jour l'image WSL, vous devez exécuter dnf update à l'intérieur, utilisez la commande suivante :

$ podman machine ssh dnf update

Les paramètres par défaut de la machine Podman peuvent être définis via la section [machine] dans le fichier containers.conf(5).

OPTIONS

--cpus=nombre

Nombre de CPU.

--disk-size=nombre

Taille du disque pour la VM invitée en Gio.

--help

Affiche le message d'utilisation.

--ignition-path

Chemin d'accès complet du fichier d'allumage.

Si un fichier d'allumage est fourni, le fichier est copié dans le dossier CONF_DIR de l'utilisateur et renommé. De plus, aucune clé SSH n'est générée, ni aucune connexion système effectuée. Il est supposé que l'utilisateur effectue ces opérations manuellement ou d'une autre manière.

--image

Registre, chemin ou URL complet d'une image de VM. Le registre cible doit être sous la forme docker://registre/depot/image:version.

Note : Seules les images fournies par Podman seront prises en charge.

--memory, -m=nombre

Mémoire (en Mio). Note : 1024 Mio = 1 Gio.

--now

Démarre la machine virtuelle immédiatement après son initialisation.

--playbook

Ajoute le playbook Ansible fourni à la machine et l'exécute après le premier démarrage.

Note : Le playbook sera exécuté avec les mêmes privilèges que ceux accordés à l'utilisateur dans la machine virtuelle. Le playbook fourni ne peut pas inclure d'autres fichiers du système hôte, car ils ne seront pas copiés. L'utilisation de l'indicateur --playbook nécessitera que l'image inclue Ansible. L'image par défaut fournie inclura Ansible.

--rootful

Indique si cette machine préfère l'exécution de conteneurs avec privilèges (true) ou sans privilèges (false). Cette option détermine la configuration par défaut de la connexion distante s'il n'y a pas de configurations de connexion distante existantes.

Le transfert de port API, s'il est disponible, suit ce réglage.

--swap, -s=nombre

Swap (en Mio). Note : 1024 Mio = 1 Gio.

Génère un fichier zram-generator.conf avec zram-size défini à la valeur passée à --swap

--timezone

Définit le fuseau horaire pour la machine et les conteneurs. Les valeurs valides sont local ou un fuseau horaire tel que America/Chicago. La valeur local, qui est la valeur par défaut, signifie utiliser le fuseau horaire de la machine hôte.

Le réglage du fuseau horaire n'est pas utilisé avec WSL. WSL définit automatiquement le fuseau horaire sur celui du système d'exploitation Windows hôte.

--tls-verify

Exige HTTPS et vérifie les certificats lors du contact avec les registres (par défaut : true). S'il est explicitement défini sur true, la vérification TLS est utilisée. S'il est défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée à moins que le registre cible ne soit listé comme registre non sécurisé dans containers-registries.conf(5)

--usb=bus=nombre,devnum=nombre ou vendor=hexadecimal,product=hexadecimal

Attribue un périphérique USB de l'hôte à la VM via le passage USB. Uniquement pris en charge pour les machines QEMU.

Le périphérique doit avoir les permissions appropriées pour être transmis à la machine. Cela signifie que le périphérique doit appartenir à votre groupe utilisateur.

Notez que l'utilisation des numéros de bus et de périphérique est plus simple, mais les valeurs peuvent changer à chaque démarrage ou lorsque le périphérique est débranché.

Lorsqu'un périphérique USB est spécifié par ses identifiants de vendeur et de produit, si plusieurs périphériques ont les mêmes identifiants, le premier périphérique disponible est attribué.

--user-mode-networking

Cette option ne peut être utilisée qu'avec le fournisseur WSL sous Windows. Sur toutes les autres plateformes, cette option est ignorée et la mise en réseau en mode utilisateur sera toujours true car ces fournisseurs dépendent toujours de gvproxy (notre outil de mise en réseau en mode utilisateur pour les VM).

En revanche, le backend Windows/WSL est par défaut à false et suit la configuration réseau WSL standard. Changer ce réglage sur true sur Windows/WSL indique à Podman de remplacer la configuration réseau WSL au démarrage de cette instance de machine par une distribution réseau en mode utilisateur. Comme WSL partage le même noyau entre les distributions, toutes les autres distributions en cours d'exécution réutilisent ce réseau. De même, lorsque la dernière instance de machine avec un réglage true s'arrête, la configuration réseau d'origine est restaurée.

Dans certaines configurations VPN, le VPN peut rejeter le trafic provenant d'interfaces réseau alternatives, y compris les périphériques réseau de VM. En activant la mise en réseau en mode utilisateur, les VPN observent tout le trafic de la machine Podman comme provenant de l'hôte, contournant ainsi le problème.

--username

Nom d'utilisateur à utiliser pour exécuter les commandes dans la VM distante. La valeur par défaut est core pour FCOS et user pour Fedora (par défaut sur les hôtes Windows). Doit correspondre à celui utilisé dans l'image de la VM résultante.

--volume, -v=source:cible[:options]

Monte un volume de la source vers la cible.

Crée un montage. Si /host-dir:/machine-dir est spécifié comme *source:cible*, Podman monte host-dir sur l'hôte vers machine-dir dans la machine Podman.

Des options supplémentaires peuvent être spécifiées sous forme de chaîne de caractères séparée par des virgules. Les options reconnues sont : * ro : monte le volume en lecture seule * rw : monte le volume en lecture/écriture (par défaut) * security_model=[modèle] : spécifie le modèle de sécurité 9p (voir ci-dessous)

Le modèle de sécurité 9p [détermine] https://wiki.qemu.org/Documentation/9psetup#Starting_the_Guest_directly si et comment le système de fichiers 9p traduit certaines opérations de système de fichiers avant le stockage réel sur l'hôte.

Afin d'autoriser le fonctionnement des liens symboliques, sur MacOS, le modèle de sécurité par défaut est
none.

La valeur de mapped-xattr spécifie que 9p stocke les liens symboliques et certains attributs de fichier sous forme d'attributs étendus sur l'hôte. Ceci convient lorsque l'hôte et l'invité n'ont pas besoin d'interopérer sur le système de fichiers partagé, mais présente des inconvénients pour un accès partagé réel ; notamment, les liens symboliques sur l'hôte ne sont pas utilisables sur l'invité et vice versa. Si l'interopérabilité est requise, choisissez plutôt none, mais gardez à l'esprit que l'invité ne peut pas faire des choses que l'utilisateur exécutant la machine virtuelle ne peut pas faire, par exemple, créer des fichiers appartenant à un autre utilisateur. L'utilisation de none est presque certainement le meilleur choix pour les volumes en lecture seule.

Exemple : -v "$HOME/git:$HOME/git:ro,security_model=none"

Les montages de volumes par défaut sont définis dans containers.conf. Sauf modification, la valeur par défaut est $HOME:$HOME.

Note sur le sous-système Windows pour Linux (WSL) Puisque tous les lecteurs sont montés sous /mnt au démarrage par défaut dans WSL, passer --volume est redondant et n'a aucun effet. Le répertoire personnel de l'hôte pour un lecteur C: sera monté sous /mnt/c/Users/<mon nom d'utilisateur>.

EXEMPLES

Initialise la machine Podman par défaut, en téléchargeant le contenu depuis Internet.

$ podman machine init

Initialise une machine Podman pour le nom spécifié en téléchargeant le contenu depuis Internet.

$ podman machine init myvm

Initialise et démarre une nouvelle machine Podman en une seule étape.

podman machine init --now

Initialise la machine Podman par défaut en téléchargeant le contenu depuis Internet et en utilisant le mode rootful par défaut. Le mode par défaut est rootless.

$ podman machine init --rootful

Initialise la machine Podman par défaut en ignorant la taille de disque spécifiée, en téléchargeant le contenu depuis Internet.

$ podman machine init --disk-size 50

Initialise la machine Podman spécifiée en ignorant la taille de la mémoire, en téléchargeant le contenu depuis Internet.

$ podman machine init --memory=1024 myvm

Initialise la machine Podman par défaut avec le répertoire hôte /Users monté dans la VM sous /Users.

$ podman machine init -v /Users:/Users

Initialise la machine Podman par défaut avec un périphérique USB transmis avec des options spécifiées. Uniquement pris en charge pour les machines QEMU.

$ podman machine init --usb vendor=13d3,product=5406

Initialise la machine Podman par défaut avec un périphérique USB transmis avec des options spécifiées. Uniquement pris en charge pour les machines QEMU.

$ podman machine init --usb bus=1,devnum=3
