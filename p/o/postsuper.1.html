POSTSUPER(1) Manuel des commandes générales POSTSUPER(1)

NOM

postsuper - Superviseur Postfix

SYNTAXE

postsuper [-psSv]
[-c config_dir] [-d queue_id]
[-e queue_id] [-f queue_id]
[-h queue_id] [-H queue_id]
[-r queue_id] [répertoire ...]

DESCRIPTION


La commande postsuper(1) effectue des tâches de maintenance sur la file d'attente Postfix. L'utilisation de la commande est réservée au superutilisateur. Voir la commande postqueue(1) pour les opérations sur la file d'attente non privilégiées telles que l'affichage ou la purge de la file d'attente de messagerie.

Par défaut, postsuper(1) effectue les opérations demandées avec les options de ligne de commande -s et -p sur tous les répertoires de file d'attente Postfix - cela inclut les répertoires incoming, active, deferred et hold avec les fichiers de messages et les répertoires bounce, defer, trace et flush avec les fichiers journaux.

Options :

-c config_dir
Le fichier de configuration main.cf se trouve dans le répertoire nommé au lieu du répertoire de configuration par défaut. Voir également le paramètre d'environnement MAIL_CONFIG ci-dessous.
-d queue_id
Supprime un message avec l'identifiant de file d'attente nommé des files d'attente de messagerie nommées (par défaut : hold, incoming, active et deferred).

Pour supprimer plusieurs fichiers, spécifiez l'option -d plusieurs fois, ou spécifiez un queue_id de - pour lire les IDs de file d'attente depuis l'entrée standard. Par exemple, pour supprimer tous les courriels avec exactement un destinataire user@example.com :

postqueue -j | jq -r '
    # Voir la section FORMAT D'OBJET JSON dans la page de manuel de postqueue(1)
    select(.recipients[0].address == "user@example.com")
    | select(.recipients[1].address == null)
    | .queue_id
 ' | postsuper -d -

(notez l'option "jq -r"), ou la forme historique :

mailq | tail -n +2 | grep -v '^ *(' | awk  'BEGIN { RS = "" }
    # $7=expéditeur, $8=destinataire1, $9=destinataire2
    { if ($8 == "user@example.com" && $9 == "")
          print $1 }
 ' | tr -d '*!' | postsuper -d -

Spécifiez "-d ALL" pour supprimer tous les messages ; par exemple, spécifiez "-d ALL deferred" pour supprimer tous les courriels dans la file d'attente deferred. Par mesure de sécurité, le mot ALL doit être spécifié en majuscules.

Avertissement : Les identifiants de file d'attente Postfix sont réutilisés (toujours avec Postfix <= 2.8 ; et avec Postfix >= 2.9 lorsque enable_long_queue_ids=no). Il y a une très faible possibilité que postsuper supprime le mauvais fichier de message lorsqu'il est exécuté pendant que le système de messagerie Postfix est en train de livrer du courrier.

Le scénario est le suivant :

1)
Le gestionnaire de file d'attente Postfix supprime le message que postsuper(1) est invité à supprimer, car Postfix a terminé avec le message (il est livré, ou retourné à l'expéditeur).
2)
Un nouveau message arrive, et le nouveau message reçoit le même identifiant de file d'attente que le message que postsuper(1) est censé supprimer. La probabilité de réutilisation d'un identifiant de file d'attente supprimé est d'environ 1 sur 2**15 (le nombre de valeurs de microsecondes différentes que l'horloge système peut distinguer en une seconde).
3)
postsuper(1) supprime le nouveau message, au lieu de l'ancien message qu'il aurait dû supprimer.
-e queue_id
-f queue_id
Demande l'expiration forcée d'un message avec l'identifiant de file d'attente nommé dans la ou les files d'attente de messagerie nommées (par défaut : hold, incoming, active et deferred).
  • Le message sera retourné à l'expéditeur lorsque le gestionnaire de file d'attente tentera de livrer ce message (notez que Postfix ne livrera jamais les messages de la file d'attente hold).
  • Les options -e et -f demandent toutes deux l'expiration forcée. La différence est que -f libérera également un message s'il se trouve dans la file d'attente hold. Avec -e, un tel message ne serait pas retourné à l'expéditeur avant d'être libéré avec -f ou -H.
  • Lorsqu'un message différé est expiré de force, le message de retour indiquera la raison du délai. Sinon, la raison sera "message expiré administrativement".
Pour expirer plusieurs fichiers, spécifiez l'option -e ou -f plusieurs fois, ou spécifiez un queue_id de - pour lire les IDs de file d'attente depuis l'entrée standard (voir l'option -d ci-dessus pour un exemple, mais assurez-vous de remplacer -d dans l'exemple).

Spécifiez "-e ALL" ou "-f ALL" pour expirer tous les messages ; par exemple, spécifiez "-e ALL deferred" pour expirer tous les courriels dans la file d'attente deferred. Par mesure de sécurité, le mot ALL doit être spécifié en majuscules.

Ces fonctionnalités sont disponibles dans Postfix 3.5 et ultérieur.

-h queue_id
Met le courrier "en attente" de sorte qu'aucune tentative de livraison ne soit effectuée. Déplace un message avec l'identifiant de file d'attente nommé des files d'attente de messagerie nommées (par défaut : incoming, active et deferred) vers la file d'attente hold.

Pour mettre en attente plusieurs fichiers, spécifiez l'option -h plusieurs fois, ou spécifiez un queue_id de - pour lire les IDs de file d'attente depuis l'entrée standard.

Spécifiez "-h ALL" pour mettre en attente tous les messages ; par exemple, spécifiez "-h ALL deferred" pour mettre en attente tous les courriels dans la file d'attente deferred. Par mesure de sécurité, le mot ALL doit être spécifié en majuscules.

Note : tant que le courrier est "en attente", il n'expirera pas lorsque son temps dans la file d'attente dépasse le paramètre maximal_queue_lifetime ou bounce_queue_lifetime. Il devient soumis à l'expiration après avoir été libéré de "l'attente".

Cette fonctionnalité est disponible dans Postfix 2.0 et ultérieur.

-H queue_id
Libère le courrier qui a été mis "en attente". Déplace un message avec l'identifiant de file d'attente nommé des files d'attente de messagerie nommées (par défaut : hold) vers la file d'attente deferred.

Pour libérer plusieurs fichiers, spécifiez l'option -H plusieurs fois, ou spécifiez un queue_id de - pour lire les IDs de file d'attente depuis l'entrée standard.

Note : spécifiez "postsuper -r" pour libérer le courrier qui a été gardé en attente pendant une fraction significative de $maximal_queue_lifetime ou $bounce_queue_lifetime, ou plus longtemps.

Spécifiez "-H ALL" pour libérer tous les courriels qui sont "en attente". Par mesure de sécurité, le mot ALL doit être spécifié en majuscules.

Cette fonctionnalité est disponible dans Postfix 2.0 et ultérieur.

-p
Nettoie les anciens fichiers temporaires qui restent après des pannes système ou logicielles. Les opérations -p, -s et -S sont effectuées avant les autres opérations.
-r queue_id
Remet en file d'attente le message avec l'identifiant de file d'attente nommé des files d'attente de messagerie nommées (par défaut : hold, incoming, active et deferred).

Pour remettre en file d'attente plusieurs fichiers, spécifiez l'option -r plusieurs fois, ou spécifiez un queue_id de - pour lire les IDs de file d'attente depuis l'entrée standard.

Spécifiez "-r ALL" pour remettre en file d'attente tous les messages. Par mesure de sécurité, le mot ALL doit être spécifié en majuscules.

Un message remis en file d'attente est déplacé vers la file d'attente maildrop, d'où il est copié par les démons pickup(8) et cleanup(8) vers un nouveau fichier de file d'attente. À bien des égards, sa gestion diffère de celle d'une nouvelle soumission locale.

  • Le message n'est pas soumis aux paramètres smtpd_milters ou non_smtpd_milters. Lorsque le courrier a transité par un filtre de contenu externe, cela produirait des résultats incorrects

postsuper(1) — Manuel Postfix

NOM

postsuper — maintenance de la file d'attente Postfix

SYNOPSIS

postsuper [options] ...

DESCRIPTION

Le programme postsuper est un utilitaire pour des opérations de maintenance des files d'attente de messagerie Postfix. Il est utilisé pour supprimer, expirer, libérer, mettre en attente, relancer et réparer les messages dans la file d'attente de messagerie.

Les opérations suivantes sont possibles :

-d
Suppression. Les messages spécifiés sont supprimés de la file d'attente. Sans argument, tous les messages sont supprimés. Les messages sont supprimés de la file d'attente de manière permanente.
-e
Expiration. Les messages spécifiés sont supprimés de la file d'attente, et le client d'envoi reçoit un rapport de non-remise.
-f
Forcer la libération. Les messages spécifiés sont libérés de la file d'attente, et l'expéditeur reçoit un rapport de non-remise. Ceci est identique à l'option -e.
-h
Mettre en attente. Les messages spécifiés sont mis en attente (retardés sans délai d'attente). Les messages qui sont déjà en attente sont ignorés.
-H
Libérer. Les messages spécifiés sont libérés de la file d'attente. Les messages qui sont déjà libérés sont ignorés.
-p
Réécrire les en-têtes. Cette opération nécessite l'exécution des opérations par le processus Postfix principal. Elle permet d'éviter des interblocages entre les applications Milter qui dépendent des informations d'état de la connexion SMTP d'origine.

Le message est soumis à nouveau à la réécriture et à la substitution des adresses e-mail. Ceci est utile lorsque les règles de réécriture ou les mappages virtuels ont changé.

Le contexte de réécriture d'adresses (local ou distant) est le même que lors de la réception du message.

  • Le message est soumis aux mêmes paramètres de content_filter (le cas échéant) que ceux utilisés pour les nouvelles soumissions de courrier local. Ceci est utile lorsque les paramètres de content_filter ont changé.
    • Avertissement : les ID de file d'attente Postfix sont réutilisés (toujours avec Postfix <= 2.8 ; et avec Postfix >= 2.9 lorsque enable_long_queue_ids=no). Il y a une très faible possibilité que postsuper(1) remette en file d'attente le mauvais fichier de message lorsqu'il est exécuté pendant que le système de messagerie Postfix est en cours d'exécution, mais aucun dommage ne devrait être causé.

    Cette fonctionnalité est disponible dans Postfix 1.1 et versions ultérieures.

    -s
    Vérification et réparation de la structure. Ceci doit être fait une fois avant le démarrage de Postfix. Les opérations -p, -s et -S sont effectuées avant les autres opérations.
    • Renommer les fichiers dont le nom ne correspond pas au numéro d'inode du fichier message. Cette opération est nécessaire après la restauration d'une file d'attente de messagerie à partir d'une autre machine ou d'une sauvegarde, lorsque les fichiers de file d'attente ont été créés avec Postfix <= 2.8 ou avec « enable_long_queue_ids = no ».
    • Déplacer les fichiers de file d'attente qui sont mal placés dans la hiérarchie du système de fichiers et supprimer les sous-répertoires qui ne sont plus nécessaires. Les réorganisations de position des fichiers sont nécessaires après une modification des paramètres de configuration hash_queue_names et/ou hash_queue_depth.
    • Renommer les fichiers de file d'attente créés avec « enable_long_queue_ids = yes » en noms courts, pour la migration vers Postfix <= 2.8. La procédure est la suivante : 
      # postfix stop
# postconf enable_long_queue_ids=no
# postsuper

      Exécutez postsuper(1) de manière répétée jusqu'à ce qu'il cesse de signaler des changements de noms de fichiers.

    -S
    Une version redondante de -s qui exige que les noms de fichiers longs correspondent également au numéro d'inode du fichier message. Cette option existe à des fins de test et est disponible avec Postfix 2.9 et versions ultérieures. Les opérations -p, -s et -S sont effectuées avant les autres opérations.
    -v
    Activer la journalisation détaillée à des fins de débogage. Plusieurs options -v rendent le logiciel de plus en plus verbeux.

    DIAGNOSTICS


    Les problèmes sont signalés sur le flux d'erreurs standard et sur syslogd(8) ou postlogd(8).

    postsuper(1) signale le nombre de messages supprimés avec -d, le nombre de messages expirés avec -e, le nombre de messages expirés ou libérés avec -f, le nombre de messages mis en attente ou libérés avec -h ou -H, le nombre de messages remis en file d'attente avec -r, et le nombre de messages dont le nom de fichier de file d'attente a été corrigé avec -s. Le rapport est écrit sur le flux d'erreurs standard et sur syslogd(8) ou postlogd(8).

    ENVIRONNEMENT

    MAIL_CONFIG
    Répertoire contenant le fichier main.cf.

    BUGS


    Les courriers qui ne sont pas assainis par Postfix (c'est-à-dire les courriers dans la file d'attente maildrop) ne peuvent pas être mis « en attente ».

    PARAMETRES DE CONFIGURATION

    Les paramètres main.cf suivants sont particulièrement pertinents pour ce programme. Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

    config_directory (voir la sortie de 'postconf -d')
    L'emplacement par défaut des fichiers de configuration Postfix main.cf et master.cf.
    hash_queue_depth (1)
    Le nombre de niveaux de sous-répertoires pour les répertoires de files d'attente listés avec le paramètre hash_queue_names.
    hash_queue_names (deferred, defer)
    Les noms des répertoires de files d'attente qui sont divisés sur plusieurs niveaux de sous-répertoires.
    import_environment (voir la sortie de 'postconf -d')
    La liste des variables d'environnement qu'un processus Postfix privilégié importera d'un processus parent non-Postfix, ou des remplacements d'environnement nom=valeur.
    queue_directory (voir la sortie de 'postconf -d')
    L'emplacement du répertoire de file d'attente de niveau supérieur de Postfix.
    syslog_facility (mail)
    La facilité syslog de la journalisation Postfix.
    syslog_name (voir la sortie de 'postconf -d')
    Un préfixe qui est ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, « smtpd » devienne « prefix/smtpd ».

    Disponible dans la version 2.9 de Postfix et ultérieures :

    enable_long_queue_ids (no)
    Activer les ID de file d'attente longs et non répétitifs (noms de fichiers de file d'attente).
