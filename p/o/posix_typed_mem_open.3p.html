POSIX_TYPED_MEM_OPEN(3P) Manuel du programmeur POSIX POSIX_TYPED_MEM_OPEN(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

posix_typed_mem_open — ouvrir un objet mémoire typé (TEMPS RÉEL AVANCÉ)

SYNOPSIS

#include <sys/mman.h>
int posix_typed_mem_open(const char *name, int oflag, int tflag);

DESCRIPTION

La fonction posix_typed_mem_open() établit une connexion entre l'objet mémoire typé spécifié par la chaîne pointée par name et un descripteur de fichier. Elle crée une description de fichier ouvert qui référence l'objet mémoire typé et un descripteur de fichier qui référence cette description de fichier ouvert. Le descripteur de fichier est alloué comme décrit dans la Section 2.14, Allocation de descripteurs de fichiers et peut être utilisé par d'autres fonctions pour référencer cet objet mémoire typé. Il est non spécifié si le nom apparaît dans le système de fichiers et est visible par d'autres fonctions qui acceptent des chemins d'accès comme arguments. L'argument name est conforme aux règles de construction d'un chemin d'accès, à l'exception du fait que l'interprétation des caractères <slash> autres que le caractère <slash> initial dans name est définie par l'implémentation, et que les limites de longueur pour l'argument name sont définies par l'implémentation et n'ont pas à être les mêmes que les limites de chemin d'accès {PATH_MAX} et {NAME_MAX}. Si name commence par le caractère <slash>, alors les processus appelant posix_typed_mem_open() avec la même valeur de name référenceront le même objet mémoire typé. Si name ne commence pas par le caractère <slash>, l'effet est défini par l'implémentation.

Chaque objet mémoire typé supporté dans un système sera identifié par un nom qui spécifie non seulement son pool de mémoire typée associé, mais aussi le chemin ou le port par lequel il est accédé. C'est-à-dire que le même pool de mémoire typée accédé via plusieurs ports différents aura plusieurs noms correspondants différents. La liaison entre les noms et les objets mémoire typés est établie d'une manière définie par l'implémentation. Contrairement aux objets mémoire partagés, il n'existe aucun moyen dans POSIX.1‐2008 pour qu'un programme crée un objet mémoire typé.

La valeur de tflag déterminera le comportement de l'objet mémoire typé lorsqu'il sera mappé ultérieurement par des appels à mmap(). Au maximum, l'un des indicateurs suivants définis dans <sys/mman.h> peut être spécifié :

POSIX_TYPED_MEM_ALLOCATE

Allouer sur mmap().
POSIX_TYPED_MEM_ALLOCATE_CONTIG

Allouer de manière contiguë sur mmap().
POSIX_TYPED_MEM_MAP_ALLOCATABLE

Mapper sur mmap(), sans affecter l'allocabilité.

Si tflag a l'indicateur POSIX_TYPED_MEM_ALLOCATE spécifié, tout appel ultérieur à mmap() utilisant le descripteur de fichier retourné entraînera l'allocation et le mappage de mémoire typée à partir du pool de mémoire typée spécifié. La mémoire allouée peut être une zone précédemment non allouée et contiguë du pool de mémoire typée, ou plusieurs zones non allouées et non contiguës précédemment (mappées dans une portion contiguë de l'espace d'adressage du processus). Si tflag a l'indicateur POSIX_TYPED_MEM_ALLOCATE_CONTIG spécifié, tout appel ultérieur à mmap() utilisant le descripteur de fichier retourné entraînera l'allocation et le mappage d'une seule zone précédemment non allouée et contiguë du pool de mémoire typée (également mappée dans une portion contiguë de l'espace d'adressage du processus). Si tflag n'a aucun des indicateurs POSIX_TYPED_MEM_ALLOCATE ou POSIX_TYPED_MEM_ALLOCATE_CONTIG spécifiés, tout appel ultérieur à mmap() utilisant le descripteur de fichier retourné mappera une zone choisie par l'application à partir du pool de mémoire typée spécifié, de sorte que cette zone mappée devienne indisponible pour l'allocation jusqu'à ce qu'elle soit démappée par tous les processus. Si tflag a l'indicateur POSIX_TYPED_MEM_MAP_ALLOCATABLE spécifié, tout appel ultérieur à mmap() utilisant le descripteur de fichier retourné mappera une zone choisie par l'application à partir du pool de mémoire typée spécifié sans affecter la disponibilité de cette zone pour l'allocation ; c'est-à-dire que le mappage d'un tel objet laisse chaque octet de la zone mappée non alloué s'il était non alloué avant le mappage, ou alloué s'il était alloué avant le mappage. Les privilèges appropriés pour spécifier l'indicateur POSIX_TYPED_MEM_MAP_ALLOCATABLE sont définis par l'implémentation.

En cas de succès, posix_typed_mem_open() retournera un descripteur de fichier pour l'objet mémoire typé. La description de fichier ouverte est nouvelle, et par conséquent le descripteur de fichier ne la partagera avec aucun autre processus. Il est non spécifié si le décalage de fichier est défini. Le drapeau de descripteur de fichier FD_CLOEXEC associé au nouveau descripteur de fichier sera effacé.

Le comportement de msync(), ftruncate() et de toutes les opérations de fichier autres que mmap(), posix_mem_offset(), posix_typed_mem_get_info(), fstat(), dup(), dup2(), et close(), est non spécifié lorsqu'ils reçoivent un descripteur de fichier connecté à un objet mémoire typé par cette fonction.

Les drapeaux d'état de fichier de la description de fichier ouverte seront définis selon la valeur de oflag. Les applications devront spécifier exactement l'un des trois modes d'accès décrits ci-dessous et définis dans l'en-tête <fcntl.h>, comme valeur de oflag.

O_RDONLY
Ouverture en lecture seule.
O_WRONLY
Ouverture en écriture seule.
O_RDWR
Ouverture en lecture/écriture.

VALEUR RENVOYÉE

En cas de succès, la fonction posix_typed_mem_open() retournera un entier non négatif représentant le descripteur de fichier. Sinon, elle retournera -1 et définira errno pour indiquer l'erreur.

ERREURS

La fonction posix_typed_mem_open() échouera si :

EACCES
L'objet mémoire typé existe et les permissions spécifiées par oflag sont refusées.
EINTR
L'opération posix_typed_mem_open() a été interrompue par un signal.
EINVAL
Les indicateurs spécifiés dans tflag sont invalides (plusieurs parmi POSIX_TYPED_MEM_ALLOCATE, POSIX_TYPED_MEM_ALLOCATE_CONTIG, ou POSIX_TYPED_MEM_MAP_ALLOCATABLE sont spécifiés).
EMFILE
Tous les descripteurs de fichiers disponibles pour le processus sont actuellement ouverts.
ENFILE
Trop de descripteurs de fichiers sont actuellement ouverts dans le système.
ENOENT
L'objet mémoire typé nommé n'existe pas.
EPERM
L'appelant manque des privilèges appropriés pour spécifier l'indicateur POSIX_TYPED_MEM_MAP_ALLOCATABLE dans l'argument tflag.

La fonction posix_typed_mem_open() peut échouer si :

ENAMETOOLONG

La longueur de l'argument name dépasse {_POSIX_PATH_MAX} sur les systèmes qui ne supportent pas l'option XSI ou dépasse {_XOPEN_PATH_MAX} sur les systèmes XSI, ou a une composante de chemin d'accès plus longue que {_POSIX_NAME_MAX} sur les systèmes qui ne supportent pas l'option XSI ou plus longue que {_XOPEN_NAME_MAX} sur les systèmes XSI.
