posix_fadvise(2) Manuel des appels système posix_fadvise(2)

NOM

posix_fadvise - pré-déclarer un modèle d'accès aux données d'un fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <fcntl.h>
int posix_fadvise(int fd, off_t offset, off_t size, int advice);
Conditions de test des fonctionnalités pour glibc (voir feature_test_macros(7)):

posix_fadvise():

    _POSIX_C_SOURCE >= 200112L

DESCRIPTION

Les programmes peuvent utiliser posix_fadvise() pour annoncer l'intention d'accéder aux données d'un fichier selon un modèle spécifique à l'avenir, permettant ainsi au noyau d'effectuer les optimisations appropriées.

L'advice s'applique à une région (pas nécessairement existante) commençant à offset et s'étendant sur size octets (ou jusqu'à la fin du fichier si size est 0) dans le fichier référencé par fd. L'advice n'est pas contraignant ; il constitue simplement une attente de la part de l'application.

Les valeurs autorisées pour advice incluent:

POSIX_FADV_NORMAL
Indique que l'application n'a pas de conseil à donner concernant son modèle d'accès pour les données spécifiées. Si aucun conseil n'est donné pour un fichier ouvert, c'est l'hypothèse par défaut.
POSIX_FADV_SEQUENTIAL
L'application s'attend à accéder aux données spécifiées séquentiellement (avec des décalages plus bas lus avant ceux plus élevés).
POSIX_FADV_RANDOM
Les données spécifiées seront accédées dans un ordre aléatoire.
POSIX_FADV_NOREUSE
Les données spécifiées ne seront accédées qu'une seule fois.
Avant Linux 2.6.18, POSIX_FADV_NOREUSE avait les mêmes sémantiques que POSIX_FADV_WILLNEED. C'était probablement un bug ; de Linux 2.6.18 jusqu'à Linux 6.2, ce drapeau était un no-op. Depuis Linux 6.3, POSIX_FADV_NOREUSE signale que l'algorithme de remplacement de page du noyau peut ignorer les accès aux pages mises en cache marquées par ce drapeau. Ceci est utile, par exemple, lors du streaming de gros fichiers.
POSIX_FADV_WILLNEED
Les données spécifiées seront accédées dans un futur proche.
POSIX_FADV_WILLNEED initie une lecture non bloquante de la région spécifiée dans le cache de pages. La quantité de données lues peut être réduite par le noyau en fonction de la charge de la mémoire virtuelle. (Quelques mégaoctets seront généralement satisfaits entièrement, et plus est rarement utile.)
POSIX_FADV_DONTNEED
Les données spécifiées ne seront pas accédées dans un futur proche.
POSIX_FADV_DONTNEED tente de libérer les pages mises en cache associées à la région spécifiée. Ceci est utile, par exemple, lors du streaming de gros fichiers. Un programme peut périodiquement demander au noyau de libérer des données mises en cache qui ont déjà été utilisées, afin que des pages mises en cache plus utiles ne soient pas supprimées à la place.
Les requêtes pour supprimer des pages partielles sont ignorées. Il est préférable de conserver les données nécessaires plutôt que de supprimer les données non nécessaires. Si l'application exige que les données soient prises en compte pour la suppression, alors offset et size doivent être alignés sur les pages.
L'implémentation *peut* tenter d'écrire les pages sales dans la région spécifiée, mais ce n'est pas garanti. Aucune page sale non écrite ne sera libérée. Si l'application souhaite s'assurer que les pages sales seront libérées, elle devrait appeler fsync(2) ou fdatasync(2) au préalable.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, un numéro d'erreur est retourné.

ERREURS

EBADF
L'argument fd n'était pas un descripteur de fichier valide.
EINVAL
Une valeur invalide a été spécifiée pour advice.
ESPIPE
Le descripteur de fichier spécifié fait référence à un tube (pipe) ou un FIFO. (ESPIPE est l'erreur spécifiée par POSIX, mais avant Linux 2.6.16, Linux retournait EINVAL dans ce cas.)

VERSIONS

Sous Linux, POSIX_FADV_NORMAL définit la fenêtre de pré-lecture à la taille par défaut pour le périphérique sous-jacent ; POSIX_FADV_SEQUENTIAL double cette taille, et POSIX_FADV_RANDOM désactive complètement la pré-lecture du fichier. POSIX_FADV_NOREUSE ne modifie pas la taille de la fenêtre de pré-lecture. Ces modifications affectent l'ensemble du fichier, pas seulement la région spécifiée (mais les autres descripteurs de fichiers ouverts vers le même fichier ne sont pas affectés).

Différences bibliothèque C/noyau

Le nom de la fonction d'enrobage dans la bibliothèque C est posix_fadvise(). L'appel système sous-jacent s'appelle fadvise64() (ou, sur certaines architectures, fadvise64_64()) ; la différence entre les deux est que le premier appel système suppose que le type de l'argument size est size_t, tandis que le second attend loff_t.

Variantes spécifiques à l'architecture

Certaines architectures nécessitent que les arguments 64 bits soient alignés dans une paire de registres appropriée (voir syscall(2) pour plus de détails). Sur ces architectures, la signature de l'appel de posix_fadvise() indiquée dans la SYNTAXE forcerait un registre à être utilisé comme remplissage entre les arguments fd et offset. Par conséquent, ces architectures définissent une version de l'appel système qui ordonne les arguments de manière appropriée, mais est par ailleurs exactement identique à posix_fadvise().

Par exemple, depuis Linux 2.6.14, ARM dispose de l'appel système suivant :


long arm_fadvise64_64(int fd, int advice,
                      loff_t offset, loff_t size);

Ces détails spécifiques à l'architecture sont généralement cachés aux applications par la fonction d'enrobage posix_fadvise() de glibc, qui invoque l'appel système approprié spécifique à l'architecture.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001.

Le support du noyau est apparu pour la première fois dans Linux 2.5.60 ; l'appel système sous-jacent s'appelle fadvise64(). Le support de la bibliothèque est fourni depuis glibc 2.2, via la fonction d'enrobage posix_fadvise().

Depuis Linux 3.18, le support de l'appel système sous-jacent est optionnel, en fonction du réglage de l'option de configuration CONFIG_ADVISE_SYSCALLS.

Le type de l'argument size a été changé de size_t à off_t dans POSIX.1-2001 TC1.

NOTES

Le contenu du cache de tampons du noyau peut être effacé via l'interface /proc/sys/vm/drop_caches décrite dans proc(5).

On peut obtenir un instantané des pages d'un fichier qui sont résidentes dans le cache de tampons en ouvrant un fichier, en le mappant avec mmap(2), puis en appliquant mincore(2) au mappage.
