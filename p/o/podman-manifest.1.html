NOM

podman-manifest - Créer et manipuler des listes de manifestes et des index d'images

SYNTAXE

podman manifest sous-commande

DESCRIPTION

La commande podman manifest fournit des sous-commandes qui peuvent être utilisées pour :

* Créer une liste de manifestes Docker ou un index d'images OCI en cours de travail.

SOUS-COMMANDES

Commande Page de manuel Description
add podman-manifest-add(1) Ajouter une image ou un artefact à une liste de manifestes ou à un index d'images.
annotate podman-manifest-annotate(1) Ajouter et mettre à jour des informations sur une image ou un artefact dans une liste de manifestes ou un index d'images.
create podman-manifest-create(1) Créer une liste de manifestes ou un index d'images.
exists podman-manifest-exists(1) Vérifier si la liste de manifestes donnée existe dans le stockage local.
inspect podman-manifest-inspect(1) Afficher une liste de manifestes ou un index d'images.
push podman-manifest-push(1) Pousser une liste de manifestes ou un index d'images vers un registre.
remove podman-manifest-remove(1) Supprimer un élément d'une liste de manifestes ou d'un index d'images.
rm podman-manifest-rm(1) Supprimer une liste de manifestes ou un index d'images du stockage local.

EXEMPLES

Construction d'une liste de manifestes multi-architectures depuis un Containerfile

En supposant que le Containerfile utilise des instructions RUN, l'hôte doit disposer d'un moyen d'exécuter des binaires non natifs. La configuration de cela dépasse le cadre de cet exemple. La construction d'une liste de manifestes multi-architectures shazam en parallèle sur 4 threads peut se faire comme suit :

    $ platarch=linux/amd64,linux/ppc64le,linux/arm64,linux/s390x
    $ podman build --jobs=4 --platform=$platarch --manifest shazam .

Note : L'argument --jobs est facultatif. N'utilisez pas l'option --tag (ou -t) de la commande podman build lors de la construction d'une liste de manifestes multi-architectures.

Assemblage d'un manifeste multi-architectures depuis des images construites séparément

En supposant que les images example.com/example/shazam:$arch soient construites séparément sur d'autres hôtes et poussées vers le registre example.com. Elles peuvent être combinées en une liste de manifestes et poussées à l'aide d'une simple boucle :

    $ REPO=example.com/example/shazam
    $ podman manifest create $REPO:latest
    $ for IMGTAG in amd64 s390x ppc64le arm64; do   
              podman manifest add $REPO:latest docker://$REPO:IMGTAG;   
          done
    $ podman manifest push --all $REPO:latest

Note : L'ordre des arguments de l'instruction add est <manifeste> puis <image>. De plus, l'option de poussée --all est requise pour s'assurer que tout le contenu est poussé, pas seulement la plateforme/architecture native.

Suppression et étiquetage d'une liste de manifestes avant la poussée

Une attention particulière est nécessaire lors de la suppression et de la poussée des listes de manifestes, par opposition au contenu. Vous voudrez presque toujours utiliser les sous-commandes manifest rm et manifest push --all. Par exemple, un renommage et une poussée peuvent être effectués comme suit :

    $ podman tag localhost/shazam example.com/example/shazam
    $ podman manifest rm localhost/shazam
    $ podman manifest push --all example.com/example/shazam
