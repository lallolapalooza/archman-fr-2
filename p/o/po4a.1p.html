NOM

po4a - mettre à jour à la fois les fichiers PO et les documents traduits en une seule fois

SYNTAXE

po4a [options] fichier_config

DESCRIPTION

po4a (PO pour tout) facilite la maintenance de la traduction de la documentation en utilisant les outils gettext classiques. La principale caractéristique de po4a est qu'il découple la traduction du contenu de sa structure documentaire. Veuillez vous référer à la page po4a(7) pour une introduction douce à ce projet.

Lors de l'exécution, po4a analyse tous les fichiers de documentation spécifiés dans son fichier de configuration. Il met à jour les fichiers PO (contenant la traduction) pour refléter tout changement apporté à la documentation, et produit une documentation traduite en injectant la traduction du contenu (trouvée dans les fichiers PO) dans la structure du document maître d'origine.

Au début, les fichiers PO ne contiennent que les chaînes à traduire de la documentation originale. Ce format de fichier permet aux traducteurs de fournir manuellement une traduction pour chaque paragraphe extrait par po4a. Si la documentation est modifiée après traduction, po4a marque les traductions correspondantes comme "floues" dans le fichier PO pour demander une révision manuelle par les traducteurs. Les traducteurs peuvent également fournir des "addenda", qui sont du contenu supplémentaire indiquant par exemple qui a effectué la traduction et comment signaler les bogues.

documents maîtres ---+---->-------->---------+
 (rédaction doc)    |                       |
                    V   (exécutions po4a)   >-----+--> documents
                    |                       |     |     traduits
fichiers PO existants -->--> fichiers PO mis à jour >-+     |
     ^                            |               |
     |                            V               |
     +----------<---------<-------+               ^
      (processus de traduction manuelle)          |
                                                  |
addendum -->--------------------------------------+

Le flux de travail de po4a est asynchrone, comme il convient aux projets open-source. Les auteurs de documentation rédigent les documents maîtres à leur propre rythme. Les traducteurs révisent et mettent à jour les traductions dans les fichiers PO. Les mainteneurs réexécutent po4a au besoin, pour refléter tout changement apporté à la documentation originale dans les fichiers PO, et pour produire des traductions de documentation mises à jour, en injectant la dernière traduction dans la dernière structure de document.

Par défaut, un document traduit donné est produit lorsque au moins 80% de son contenu est traduit. Le texte non traduit est conservé dans la langue d'origine. La documentation produite mélange donc les langues si la traduction n'est pas complète. Vous pouvez modifier le seuil de 80% avec l'option --keep décrite ci-dessous. Notez cependant que rejeter les traductions dès qu'elles ne sont pas à 100% peut être décourageant pour les traducteurs dont le travail ne sera presque jamais montré aux utilisateurs, tandis que montrer des "traductions" trop incomplètes peut être troublant pour les utilisateurs finaux.

Stocker les fichiers de documentation traduits dans le système de contrôle de version est probablement une mauvaise idée, car ils sont générés automatiquement. Les fichiers précieux sont les fichiers PO, qui contiennent le travail acharné de vos collègues traducteurs. De plus, certaines personnes trouvent plus facile d'interagir avec les traducteurs via une plateforme en ligne comme weblate, mais c'est naturellement entièrement facultatif.

Tutoriel de démarrage rapide

Supposons que vous mainteniez un programme nommé foo qui a une page de manuel man/foo.1 écrite en anglais (la langue passerelle dans la plupart des projets open-source, mais po4a peut être utilisé depuis ou vers n'importe quelle langue). Il y a quelque temps, quelqu'un a fourni une traduction allemande nommée man/foo.de.1 et a disparu. C'est un problème car vous venez de recevoir un rapport de bogue indiquant que votre documentation contient une information gravement trompeuse qui doit être corrigée dans toutes les langues, mais vous ne parlez pas allemand, vous ne pouvez donc modifier que l'original, pas la traduction. Maintenant, un autre contributeur souhaite contribuer une traduction en japonais, une langue que vous ne maîtrisez pas non plus.

Il est temps de convertir votre documentation à po4a pour résoudre vos cauchemars de maintenance de documentation. Vous voulez mettre à jour la documentation au besoin, vous voulez faciliter le travail de vos collègues traducteurs, et vous voulez vous assurer que vos utilisateurs ne voient jamais de documentation obsolète et donc trompeuse.

La conversion comprend deux étapes : la mise en place de l'infrastructure po4a, et la conversion de la traduction allemande précédente pour récupérer le travail antérieur. Cette dernière partie se fait à l'aide de po4a-gettextize, comme suit. Comme détaillé dans la documentation de po4a-gettextize(1), ce processus est rarement entièrement automatique, mais une fois terminé, le fichier de.po contenant la traduction allemande peut être intégré à votre flux de travail po4a.

po4a-gettextize --format man --master foo.1 --localized foo.de.1 --po de.po

Configurons maintenant po4a. Avec la disposition de fichiers appropriée, votre fichier de configuration pourrait être aussi simple que ceci :

[po_directory] man/po4a/
[type: man] man/foo.1 $lang:man/translated/foo.$lang.1

Il spécifie que tous les fichiers PO (contenant le travail des traducteurs) se trouvent dans le répertoire man/po4a/, et que vous n'avez qu'un seul fichier maître, man/foo.1. Si vous aviez plusieurs fichiers maîtres, vous auriez plusieurs lignes similaires à la seconde. Chaque ligne de ce type spécifie également où écrire les fichiers de traduction correspondants. Ici, la traduction allemande de man/foo.1 se trouve dans man/translated/foo.de.1.

La dernière chose dont nous avons besoin pour compléter la configuration de po4a est un fichier POT contenant le matériel modèle qui devrait être utilisé pour commencer une nouvelle traduction. Créez simplement un fichier vide avec l'extension .pot dans le po_directory spécifié (par exemple, man/po4a/foo.pot), et po4a le remplira avec le contenu attendu.

Voici un récapitulatif des fichiers dans cette configuration :

├── man/
│   ├── foo.1        <- La page de manuel originale, en anglais
│   ├── po4a/
│   │   ├── de.po    <- La traduction PO allemande, issue de la gettextisation
│   │   └── foo.pot  <- Le modèle POT des futures traductions (vide au début)
│   └── translated/  <- Répertoire où les traductions seront créées
└── po4a.cfg         <- Le fichier de configuration

Une fois configuré, l'exécution de po4a analysera votre documentation, mettra à jour le fichier modèle POT, l'utilisera pour mettre à jour les fichiers de traduction PO, et les utilisera pour mettre à jour les fichiers de traduction de la documentation. Le tout en une seule commande :

po4a --verbose po4a.cfg

C'est tout. po4a est maintenant entièrement configuré. Une fois que vous aurez corrigé votre erreur dans man/foo.1, le paragraphe incriminé dans la traduction allemande sera remplacé par le texte corrigé en anglais. Mélanger les langues n'est pas optimal, mais c'est le seul moyen de supprimer les erreurs dans des traductions que vous ne comprenez même pas, et de garantir que le contenu présenté aux utilisateurs n'est jamais trompeur. Mettre à jour la traduction allemande est également beaucoup plus facile dans le fichier PO correspondant, de sorte que le mélange de langues ne durera peut-être pas longtemps. Enfin, lorsqu'un traducteur japonais souhaite contribuer une nouvelle traduction, il devrait renommer foo.pot en ja.po et compléter la traduction. Une fois que vous avez ce fichier, déposez-le simplement dans man/po4a/po/. Une page traduite apparaîtra comme man/translated/foo.ja.1 (à condition qu'une quantité suffisante de contenu soit traduite) lorsque vous exécuterez à nouveau po4a.

OPTIONS

-k, --keep
Seuil minimal du pourcentage de traduction à atteindre pour que le fichier résultant soit écrit (par défaut : 80). Autrement dit, par défaut, les fichiers doivent être traduits à au moins 80 % pour être sauvegardés sur le disque.
-w, --width
Colonne à partir de laquelle le fichier résultant doit être retourné si le format le supporte (par défaut : 76). Si la valeur fournie est 0 ou négative, le fichier résultant ne sera pas retourné du tout. Ceci est utile avec certains formats qui pourraient être endommagés lors d'un retour à la ligne.
-h, --help
Affiche un court message d'aide.
-M, --master-charset
Jeu de caractères des fichiers contenant les documents à traduire. Notez que tous les documents maîtres doivent utiliser le même jeu de caractères.
-L, --localized-charset
Jeu de caractères des fichiers contenant les documents localisés. Notez que tous les documents traduits utiliseront le même jeu de caractères.
-A, --addendum-charset
Jeu de caractères des annexes. Notez que toutes les annexes doivent être dans le même jeu de caractères.
-V, --version
Affiche la version du script et quitte.
-v, --verbose
Augmente la verbosité du programme.
-q, --quiet
Diminue la verbosité du programme.
-d, --debug
Affiche des informations de débogage.
-o, --option
Option(s) supplémentaire(s) à passer au plugin de format. Consultez la documentation de chaque plugin pour plus d'informations sur les options valides et leur signification. Par exemple, vous pourriez passer '-o tablecells' à l'analyseur AsciiDoc, tandis que l'analyseur de texte accepterait '-o tabs=split'.
-f, --force
Génère toujours les fichiers POT et PO, même si po4a estime que ce n'est pas nécessaire.

Le comportement par défaut (lorsque --force n'est pas spécifié) est le suivant :

Si le fichier POT existe déjà, il est régénéré si un document maître ou le fichier de configuration est plus récent (sauf si --no-update est spécifié). Le fichier POT est également écrit dans un document temporaire et po4a vérifie que les modifications sont réellement nécessaires.

De plus, une traduction n'est régénérée que si son document maître, le fichier PO, l'une de ses annexes ou le fichier de configuration est plus récent. Pour éviter d'essayer de régénérer des traductions qui n'atteignent pas le seuil (voir --keep), un fichier avec l'extension .po4a-stamp peut être créé (voir --stamp).

Si un document maître inclut des fichiers, vous devriez utiliser l'option --force car l'heure de modification de ces fichiers inclus n'est pas prise en compte.

Les fichiers PO sont toujours régénérés à partir du POT avec msgmerge -U.

--stamp
Indique à po4a de créer des fichiers de timbre lorsque la traduction n'est pas générée car elle n'atteint pas le seuil. Ces fichiers de timbre sont nommés selon le document traduit attendu, avec l'extension .po4a-stamp.

Note : Ceci active uniquement la création des fichiers .po4a-stamp. Les fichiers de timbre sont toujours utilisés s'ils existent, et ils sont supprimés avec --rm-translations ou lorsque le fichier est finalement traduit.

--no-translations
Ne génère pas les documents traduits, met seulement à jour les fichiers POT et PO.
--no-update
Ne modifie pas les fichiers POT et PO, seule la traduction peut être mise à jour.
--keep-translations
Conserve les fichiers de traduction existants même si la traduction n'atteint pas le seuil spécifié par --keep. Cette option ne crée pas de nouveaux fichiers de traduction avec peu de contenu, mais elle sauvegardera les traductions existantes qui se dégradent en raison des modifications apportées aux fichiers maîtres.

ATTENTION : Ce drapeau modifie le comportement de po4a d'une manière assez drastique : vos fichiers traduits ne seront pas mis à jour du tout tant que la traduction ne s'améliorera pas. N'utilisez ce drapeau que si vous préférez distribuer une documentation traduite obsolète plutôt que de distribuer seulement une documentation non traduite et précise.

--rm-translations
Supprime les fichiers traduits (implique --no-translations).
--no-backups
Ce drapeau ne fait rien depuis la version 0.41, et pourrait être supprimé dans de futures versions.
--rm-backups
Ce drapeau ne fait rien depuis la version 0.41, et pourrait être supprimé dans de futures versions.
--translate-only fichier-traduit
Traduit uniquement le fichier spécifié. Cela peut être utile pour accélérer le traitement si un fichier de configuration contient beaucoup de fichiers. Notez que cette option ne met pas à jour les fichiers PO et POT. Cette option peut être utilisée plusieurs fois.
--variable var=valeur
Définit une variable qui sera développée dans le fichier de configuration po4a. Chaque occurrence de $(var) sera remplacée par valeur. Cette option peut être utilisée plusieurs fois.
--target-lang LANG
Met à jour les fichiers PO et génère les documents traduits uniquement pour la langue spécifiée. Cette option peut être utilisée plusieurs fois.
--srcdir SRCDIR
Définit le répertoire de base pour tous les documents d'entrée spécifiés dans le fichier de configuration po4a.

Si destdir et srcdir sont tous deux spécifiés, les fichiers d'entrée sont recherchés dans les répertoires suivants, dans l'ordre : destdir, le répertoire courant et srcdir. Les fichiers de sortie sont écrits dans destdir s'il est spécifié, ou dans le répertoire courant.

--destdir DESTDIR
Définit le répertoire de base pour tous les documents de sortie spécifiés dans le fichier de configuration po4a (voir --srcdir ci-dessus).

Options modifiant l'en-tête POT

--porefs type
Spécifie le format des références. L'argument type peut être l'une des valeurs suivantes : never pour ne produire aucune référence, file pour spécifier uniquement le fichier sans le numéro de ligne, counter pour remplacer le numéro de ligne par un compteur croissant, et full pour inclure des références complètes (par défaut : full).
--wrap-po no|newlines|nombre (par défaut : 76)
Spécifie comment le fichier po doit être retourné. Ceci donne le choix entre des fichiers joliment retournés mais qui pourraient entraîner des conflits git, ou des fichiers plus faciles à gérer automatiquement mais plus difficiles à lire pour les humains.

Historiquement, la suite gettext reformattait les fichiers po à la 77ème colonne pour des raisons cosmétiques. Cette option spécifie le comportement de po4a. Si définie à une valeur numérique, po4a retournera le fichier po après cette colonne et après les sauts de ligne dans le contenu. Si définie à newlines, po4a ne scindera le msgid et le msgstr qu'après les sauts de ligne dans le contenu. Si définie à no, po4a ne retournera pas du tout le fichier po. Les commentaires de référence sont toujours retournés par les outils gettext que nous utilisons en interne.

Notez que cette option n'a aucun impact sur la manière dont les msgid et msgstr sont retournés, c'est-à-dire sur la façon dont les sauts de ligne sont ajoutés au contenu de ces chaînes.

--master-language
Langue des fichiers sources contenant les documents à traduire. Notez que tous les documents maîtres doivent utiliser la même langue.
--msgid-bugs-address email@adresse
Définit l'adresse de rapport pour les bugs de msgid. Par défaut, les fichiers POT créés n'ont pas de champs Report-Msgid-Bugs-To.
--copyright-holder chaîne
Définit le détenteur des droits d'auteur dans l'en-tête POT. La valeur par défaut est "Free Software Foundation, Inc."
--package-name chaîne
Définit le nom du paquet pour l'en-tête POT. La valeur par défaut est "PACKAGE".
--package-version chaîne
Définit la version du paquet pour l'en-tête POT. La valeur par défaut est "VERSION".

Options pour modifier les fichiers PO

--msgmerge-opt options
Options supplémentaires pour msgmerge(1).

Note : $lang sera développé dans la langue actuelle.

--no-previous
Cette option supprime --previous des options passées à msgmerge. Ceci est nécessaire pour supporter les versions de gettext antérieures à 0.16.
--previous
Cette option ajoute --previous aux options passées à msgmerge. Elle requiert gettext 0.16 ou plus récent, et est activée par défaut.

FICHIER DE CONFIGURATION

po4a attend un fichier de configuration comme argument. Ce fichier doit contenir les éléments suivants :

  • Le chemin vers les fichiers PO et la liste des langues existantes dans le projet ;
  • Optionnellement, des options globales et des alias de configuration qui sont utilisés comme modèles pour configurer les fichiers maîtres individuels ;
  • La liste de chaque fichier maître à traduire, avec des paramètres spécifiques.

Toutes les lignes contiennent

une commande entre crochets, suivie de ses paramètres. Les commentaires commencent par le caractère '#' et se poursuivent jusqu'à la fin de la ligne. Vous pouvez échapper la fin de ligne pour répartir une commande sur plusieurs lignes.

Quelques exemples complets sont présentés sur cette page, tandis que d'autres exemples peuvent être trouvés dans le répertoire "t/cfg" de la distribution source.

Trouver les fichiers PO et POT

La solution la plus simple consiste à spécifier explicitement le chemin vers les fichiers POT et PO, comme suit :

[po4a_paths] man/po/project.pot de:man/po/de.po fr:man/po/fr.po

Ceci spécifie le chemin vers le fichier POT en premier, puis les chemins vers les fichiers PO allemand et français.

Les mêmes informations peuvent être écrites comme suit pour réduire le risque d'erreurs de copier/coller :

[po4a_langs] fr de
[po4a_paths] man/po/project.pot $lang:man/po/$lang.po

Le composant $lang est automatiquement développé en utilisant la liste de langues fournie, ce qui réduit le risque d'erreurs de copier/coller lors de l'ajout d'une nouvelle langue.

Vous pouvez compacter davantage les mêmes informations en ne fournissant que le chemin vers le répertoire contenant votre projet de traduction, comme suit.

[po_directory] man/po/

Le répertoire fourni doit contenir un ensemble de fichiers PO, chacun nommé XX.po où "XX" est l'ISO 639-1 de la langue utilisée dans ce fichier. Le répertoire doit également contenir un seul fichier POT, avec l'extension de fichier ".pot". Pour la première exécution, ce fichier peut être vide mais il doit exister (po4a ne peut pas deviner le nom à utiliser avant l'extension).

Notez que vous devez choisir une seule option entre "po_directory" et "po4a_paths". La première ("po_directory") est plus compacte, réduit davantage le risque d'erreurs de copier/coller, mais vous oblige à utiliser la structure de projet et les noms de fichiers attendus. La seconde ("po4a_paths"), est plus explicite, probablement plus lisible, et conseillée lorsque vous configurez votre premier projet avec po4a.

Fichiers PO centralisés ou fractionnés ?

Par défaut, po4a produit un seul fichier PO par langue cible, contenant l'intégralité de votre projet de traduction. À mesure que votre projet grandit, la taille de ces fichiers peut devenir problématique. Lors de l'utilisation de weblate, il est possible de spécifier des priorités pour chaque segment de traduction (c'est-à-dire msgid) afin que les plus importants soient traduits en premier. Néanmoins, certaines équipes de traduction préfèrent fractionner le contenu en plusieurs fichiers.

Pour avoir un fichier PO par fichier maître, il suffit d'utiliser la chaîne $master dans le nom de vos fichiers PO sur la ligne "[po4a_paths]", comme suit.

[po4a_paths] doc/$master/$master.pot $lang:doc/$master/$lang.po

Avec cette ligne, po4a produira des fichiers POT et PO séparés pour chaque document à traduire. Par exemple, si vous avez 3 documents et 5 langues, cela se traduira par 3 fichiers POT et 15 fichiers PO. Ces fichiers sont nommés comme spécifié dans le modèle "po4a_paths", avec $master substitué au nom de base de chaque document à traduire. En cas de conflit de noms, vous pouvez spécifier le fichier POT à utiliser comme suit, avec le paramètre "pot=".

Cette fonctionnalité peut également être utilisée pour regrouper plusieurs fichiers traduits dans le même fichier POT. L'exemple suivant ne produit que 2 fichiers POT : l10n/po/foo.pot (contenant le matériel de foo/gui.xml) et l10n/po/bar.pot (contenant le matériel de bar/gui.xml et bar/cli.xml).

[po4a_langs] de fr ja
[po4a_paths] l10n/po/$master.pot $lang:l10n/po/$master.$lang.po
[type: xml] foo/gui.xml $lang:foo/gui.$lang.xml pot=foo
[type: xml] bar/gui.xml $lang:bar/gui.$lang.xml pot=bar
[type: xml] bar/cli.xml $lang:bar/cli.$lang.xml pot=bar

En mode fractionné, po4a construit un compendium temporaire lors de la mise à jour du PO, pour partager les traductions entre tous les fichiers PO. Si deux fichiers PO ont des traductions différentes pour la même chaîne, po4a marquera cette chaîne comme floue (fuzzy) et soumettra les deux traductions dans tous les fichiers PO contenant cette chaîne. Lorsqu'elle est dé-floutée par le traducteur, la traduction est automatiquement utilisée dans tous les fichiers PO.

Spécifier les documents à traduire

Vous devez également lister les documents qui doivent être traduits. Pour chaque fichier maître, vous devez spécifier le parseur de format à utiliser, l'emplacement du document traduit à produire, et éventuellement quelques configurations. Les noms de fichiers doivent être mis entre guillemets ou échappés s'ils contiennent des espaces. Voici un exemple :

[type: sgml] "doc/my stuff.sgml"  "fr:doc/fr/mon truc.sgml"  de:doc/de/mein\ kram.sgml
[type: man] script fr:doc/fr/script.1 de:doc/de/script.1
[type: docbook] doc/script.xml fr:doc/fr/script.xml \
            de:doc/de/script.xml

Mais encore une fois, ces lignes complexes sont difficiles à lire et à modifier, par exemple lors de l'ajout d'une nouvelle langue. Il est beaucoup plus simple de réorganiser les choses en utilisant le modèle $lang comme suit :

[type: sgml]    doc/my_stuff.sgml $lang:doc/$lang/my_stuff.sgml
[type: man]     script.1          $lang:po/$lang/script.1
[type: docbook] doc/script.xml    $lang:doc/$lang/script.xml

Spécifier les options

Il existe deux types d'options : les options po4a sont des valeurs par défaut pour les options de ligne de commande de po4a, tandis que les options de format sont utilisées pour modifier le comportement des analyseurs de format. En tant qu'option po4a, vous pourriez par exemple spécifier dans votre fichier de configuration que la valeur par défaut du paramètre de ligne de commande --keep est de 50% au lieu de 80%. Les options de format sont documentées sur la page spécifique de chaque module d'analyse, par exemple Locale::Po4a::Xml(3pm). Vous pourriez par exemple passer nostrip à l'analyseur XML pour ne pas supprimer les espaces autour des chaînes extraites.

Vous pouvez passer ces options pour un fichier maître spécifique, ou même pour une traduction spécifique de ce fichier, en utilisant "opt:" et "opt_XX:" pour la langue "XX". Dans l'exemple suivant, l'option nostrip est passée à l'analyseur XML (pour toutes les langues), tandis que le seuil sera réduit à 0% pour la traduction française (qui est ainsi toujours conservée).

[type:xml] toto.xml $lang:toto.$lang.xml opt:"-o nostrip" opt_fr:"--keep 0"

Dans tous les cas, ces blocs de configuration doivent être situés à la fin de la ligne. La déclaration des fichiers doit venir en premier, puis l'addendum le cas échéant (voir ci-dessous), et seulement ensuite les options. Le regroupement des blocs de configuration n'a pas beaucoup d'importance, car les éléments sont concaténés en interne sous forme de chaînes. Les exemples suivants sont tous équivalents :

[type:xml] toto.xml $lang:toto.$lang.xml opt:"--keep 20" opt:"-o nostrip" opt_fr:"--keep 0"
[type:xml] toto.xml $lang:toto.$lang.xml opt:"--keep 20 -o nostrip" opt_fr:"--keep 0"
[type:xml] toto.xml $lang:toto.$lang.xml opt:--keep opt:20 opt:-o opt:nostrip opt_fr:--keep opt_fr:0

Notez que les options spécifiques à la langue ne sont pas utilisées lors de la construction du fichier POT. Il est par exemple impossible de passer nostrip à l'analyseur uniquement lors de la construction de la traduction française, car le même fichier POT est utilisé pour mettre à jour toutes les langues. Ainsi, les seules options qui peuvent être spécifiques à la langue sont celles qui sont utilisées lors de la production de la traduction, comme l'option "--keep".

Alias de configuration

Pour passer les mêmes options à plusieurs fichiers, le mieux est de définir un alias de type comme suit. Dans l'exemple suivant, "--keep 0" est passé à chaque traduction italienne utilisant ce type "test", qui est une extension du type "man".

[po4a_alias:test] man opt_it:"--keep 0"
[type: test] man/page.1 $lang:man/$lang/page.1

Vous pouvez également étendre un type existant en réutilisant le même nom pour l'alias comme suit. Ceci n'est pas interprété comme une définition récursive erronée.

[po4a_alias:man] man opt_it:"--keep 0"
[type: man] man/page.1 $lang:man/$lang/page.1

Options par défaut globales

Vous pouvez également utiliser des lignes "[options]" pour définir des options qui doivent être utilisées pour tous les fichiers, quel que soit leur type.

[options] --keep 20 --option nostrip

Comme avec les options de ligne de commande, vous pouvez abréger les paramètres passés dans le fichier de configuration :

[options] -k 20 -o nostrip

Priorités des options

Les options de chaque source sont concaténées, garantissant que les valeurs par défaut peuvent être facilement remplacées par des options plus spécifiques. L'ordre est le suivant :

  • Les lignes "[options]" fournissent des valeurs par défaut qui peuvent être remplacées par toute autre source.
  • Les alias de type sont ensuite utilisés. Les paramètres spécifiques à la langue remplacent ceux applicables à toutes les langues.
  • Les paramètres spécifiques à un fichier maître donné remplacent à la fois les paramètres par défaut et ceux provenant de l'alias de type. Dans ce cas également, les paramètres spécifiques à la langue remplacent les paramètres globaux.
  • Enfin, les paramètres fournis sur la ligne de commande po4a remplacent tous les paramètres du fichier de configuration.

Exemple

Voici un exemple montrant comment échapper les espaces et les guillemets :

[po_directory] man/po/

[options] --master-charset UTF-8

[po4a_alias:man] man opt:"-o \"mdoc=NAME,SEE ALSO\""
[type:man] t-05-config/test02_man.1 $lang:tmp/test02_man.$lang.1 \
           opt:"-k 75" opt_it:"-L UTF-8" opt_fr:--verbose

Addendum : Ajouter du contenu supplémentaire dans la traduction

Si vous souhaitez ajouter une section supplémentaire à la traduction, par exemple pour créditer le traducteur, vous devez définir un addendum à la ligne définissant votre fichier maître. Veuillez vous référer à la page po4a(7) pour plus de détails sur la syntaxe des fichiers d'addendum.

[type: pod] script fr:doc/fr/script.1 \
            add_fr:doc/l10n/script.fr.add

Vous pouvez également utiliser des modèles de langue comme suit :

[type: pod] script $lang:doc/$lang/script.1 \
            add_$lang:doc/l10n/script.$lang.add

Si un addendum ne parvient pas à s'appliquer, la traduction est

po4a(1p) — po4a — Outils pour la traduction et l'internationalisation

NOM

po4a - wrapper script pour la traduction des documents

SYNOPSIS

po4a [options] <master_file> [ ... ]

DESCRIPTION

po4a (pronounced p-o-four-a) is a set of scripts that convert the documentation of a project into a format that is easily translatable for translators (gettext PO files), and then convert the translated files back into the original documentation format.

The main advantage is that the translators don't need to know the original documentation format (which could be XML, LaTeX, POD, etc.). They only need to work with PO files, using tools like poedit, gtranslator, emacs, or vim.

po4a uses a configuration file to specify the input file, the output directories, the languages to translate into, and other details.

OPTIONS

The options are passed directly to the underlying po4a::* script.

FICHIER DE CONFIGURATION

A configuration file is needed to describe the translation process. It defines the files to be processed, the languages to translate to, and other parameters.

The configuration file is processed line by line. Lines starting with '#' are comments.

Each line should contain an entry. An entry starts with a type, followed by a list of file names. The file names can be prefixed by modifiers.

[type: type]
This specifies the type of the documentation file. Supported types are docbook, gettext, guide, inline, latex, man, mediawiki, moin, pod, texinfo.

The files mentioned after the type are the files that will be processed. The first file is the master file. Subsequent files are addenda.

The master file can be preceded by an option, for example:

[type: pod] script.pod addendum.pod

In the example above, script.pod is the master file and addendum.pod is an addendum file. The addendum file will be appended to the master file before processing.

If you need to specify different files per language, you can use the variable $lang. For example:

[type: pod] $lang:doc/$lang/script.pod

This will look for doc/en/script.pod for English, doc/fr/script.pod for French, and so on.

The translated files are placed in the directories specified by the language settings.

A translation can be specified using the following syntax:

$lang: [flags] <file_path>

For example:

[type: pod] script.pod www:fr:doc/fr/script.pod

This means that the master file is script.pod, and the French translation is doc/fr/script.pod. The www: prefix is used to indicate a specific output directory (e.g. for web translation). It's optional.

Multiple addenda can be specified:

[type: pod] script.pod addendum1.pod addendum2.pod

Modificateurs d'addendum

Les modificateurs d'addendum peuvent simplifier le fichier de configuration dans le cas où toutes les langues ne fournissent pas d'addendum, ou lorsque la liste des addenda change d'une langue à l'autre. Le modificateur est un seul caractère situé avant le nom du fichier.

?
Inclure addendum_path si ce fichier existe, sinon ne rien faire.
@
addendum_path n'est pas un addendum régulier mais un fichier contenant une liste d'addenda, un par ligne. Chaque addendum peut être précédé de modificateurs.
!
addendum_path est ignoré, il n'est pas chargé et ne sera pas chargé par une spécification d'addendum ultérieure.

L'exemple suivant inclut un addendum dans n'importe quelle langue, mais seulement s'il existe. Aucune erreur n'est signalée si l'addendum n'existe pas.

[type: pod] script $lang:doc/$lang/script.1  add_$lang:?doc/l10n/script.$lang.add

L'exemple suivant inclut une liste d'addenda pour chaque langue :

[type: pod] script $lang:doc/$lang/script.1  add_$lang:@doc/l10n/script.$lang.add

Filtrage des chaînes traduites

Parfois, vous souhaitez masquer certaines chaînes du processus de traduction. Pour ce faire, vous pouvez donner un paramètre pot_in à votre fichier maître pour spécifier le nom du fichier à utiliser à la place du fichier maître réel lors de la création du fichier POT. Voici un exemple :

[type:docbook] book.xml          \
        pot_in:book-filtered.xml \
        $lang:book.$lang.xml

Avec ce réglage, les chaînes à traduire seront extraites de book-filtered.xml (qui doit être produit avant d'appeler po4a) tandis que les fichiers traduits seront construits à partir de book.xml. En conséquence, toute chaîne qui fait partie de book.xml mais pas de book-filtered.xml ne sera pas incluse dans les fichiers PO, empêchant ainsi les traducteurs de fournir une traduction pour celles-ci. Ces chaînes seront donc laissées inchangées lors de la production des documents traduits. Cela diminue naturellement le niveau de traduction, vous pourriez donc avoir besoin de l'option --keep pour vous assurer que le document est quand même produit.
