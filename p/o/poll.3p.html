POLL(3P) Manuel du programmeur POSIX POLL(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

poll — multiplexage d'entrée/sortie

SYNTAXE

#include <poll.h>
int poll(struct pollfd fds[], nfds_t nfds, int timeout);

DESCRIPTION

La fonction poll() fournit aux applications un mécanisme de multiplexage d'entrée/sortie sur un ensemble de descripteurs de fichiers. Pour chaque membre du tableau pointé par fds, poll() examine le descripteur de fichier donné pour les événements spécifiés dans events. Le nombre de structures pollfd dans le tableau fds est spécifié par nfds. La fonction poll() identifie les descripteurs de fichiers sur lesquels une application peut lire ou écrire des données, ou sur lesquels certains événements se sont produits.

L'argument fds spécifie les descripteurs de fichiers à examiner et les événements d'intérêt pour chaque descripteur de fichier. C'est un pointeur vers un tableau avec un membre pour chaque descripteur de fichier ouvert d'intérêt. Les membres du tableau sont des structures pollfd dans lesquelles fd spécifie un descripteur de fichier ouvert et events et revents sont des masques de bits construits en OR-ant une combinaison des indicateurs d'événements suivants :

POLLIN
Des données autres que des données de haute priorité peuvent être lues sans bloquer.

Pour STREAMS, cet indicateur est défini dans revents même si le message est de longueur nulle. Cet indicateur est équivalent à POLLRDNORM | POLLRDBAND.

POLLRDNORM
Des données normales peuvent être lues sans bloquer.

Pour STREAMS, des données de la bande de priorité 0 peuvent être lues sans bloquer. Cet indicateur est défini dans revents même si le message est de longueur nulle.

POLLRDBAND
Des données prioritaires peuvent être lues sans bloquer.

Pour STREAMS, des données des bandes de priorité supérieures à 0 peuvent être lues sans bloquer. Cet indicateur est défini dans revents même si le message est de longueur nulle.

POLLPRI
Des données de haute priorité peuvent être lues sans bloquer.

Pour STREAMS, cet indicateur est défini dans revents même si le message est de longueur nulle.

POLLOUT
Des données normales peuvent être écrites sans bloquer.

Pour STREAMS, des données de la bande de priorité 0 peuvent être écrites sans bloquer.

POLLWRNORM
Équivalent à POLLOUT.
POLLWRBAND
Des données prioritaires peuvent être écrites.

Pour STREAMS, des données des bandes de priorité supérieures à 0 peuvent être écrites sans bloquer. Si une bande de priorité a été écrite au moins une fois sur ce STREAM, cet événement n'examine que les bandes qui ont été écrites au moins une fois.

POLLERR
Une erreur s'est produite sur le périphérique ou le flux. Cet indicateur n'est valide que dans le masque de bits revents ; il sera ignoré dans le membre events.
POLLHUP
Un périphérique a été déconnecté, ou un pipe ou un FIFO a été fermé par le dernier processus qui l'avait ouvert en écriture. Une fois défini, l'état de fermeture d'un FIFO persiste jusqu'à ce qu'un processus ouvre le FIFO en écriture ou jusqu'à ce que tous les descripteurs de fichiers en lecture seule du FIFO soient fermés. Cet événement et POLLOUT sont mutuellement exclusifs ; un flux ne peut jamais être écrivable si une fermeture s'est produite. Cependant, cet événement et POLLIN, POLLRDNORM, POLLRDBAND ou POLLPRI ne sont pas mutuellement exclusifs. Cet indicateur n'est valide que dans le masque de bits revents ; il sera ignoré dans le membre events.
POLLNVAL
La valeur de fd spécifiée est invalide. Cet indicateur n'est valide que dans le membre revents ; il sera ignoré dans le membre events.

La signification et la sémantique des données normales, prioritaires et de haute priorité sont spécifiques au fichier et au périphérique.

Si la valeur de fd est inférieure à 0, events sera ignoré, et revents sera mis à 0 dans cette entrée au retour de poll().

Dans chaque structure pollfd, poll() effacera le membre revents, sauf que lorsque l'application a demandé un rapport sur une condition en définissant l'un des bits de events listés ci-dessus, poll() définira le bit correspondant dans revents si la condition demandée est vraie. De plus, poll() définira les indicateurs POLLHUP, POLLERR et POLLNVAL dans revents si la condition est vraie, même si l'application n'a pas défini le bit correspondant dans events.

Si aucun des événements définis ne s'est produit sur un descripteur de fichier sélectionné, poll() attendra au moins timeout millisecondes qu'un événement se produise sur l'un des descripteurs de fichiers sélectionnés. Si la valeur de timeout est 0, poll() retournera immédiatement. Si la valeur de timeout est -1, poll() bloquera jusqu'à ce qu'un événement demandé se produise ou jusqu'à ce que l'appel soit interrompu.

Les implémentations peuvent imposer des limites à la granularité des intervalles de temps d'attente. Si l'intervalle de temps d'attente demandé nécessite une granularité plus fine que celle prise en charge par l'implémentation, l'intervalle de temps d'attente réel sera arrondi à la valeur prise en charge supérieure.

La fonction poll() ne sera pas affectée par le drapeau O_NONBLOCK.

La fonction poll() prendra en charge les fichiers ordinaires, les périphériques de terminaux et de pseudo-terminaux, les FIFOs, les pipes, les sockets et les fichiers basés sur STREAMS. Le comportement de poll() sur les éléments de fds se référant à d'autres types de fichiers n'est pas spécifié.

Les fichiers ordinaires seront toujours évalués à TRUE pour la lecture et l'écriture.

Un descripteur de fichier pour un socket qui écoute les connexions indiquera qu'il est prêt pour la lecture, une fois que les connexions seront disponibles. Un descripteur de fichier pour un socket qui se connecte de manière asynchrone indiquera qu'il est prêt pour l'écriture, une fois qu'une connexion aura été établie.

À condition que l'application n'effectue aucune action entraînant un comportement non spécifié ou indéfini, la valeur des membres fd et events de chaque élément de fds ne sera pas modifiée par poll().

VALEUR RENVOYÉE

En cas de succès, poll() renverra une valeur non négative. Une valeur positive indique le nombre total de structures pollfd qui ont sélectionné des événements (c'est-à-dire celles pour lesquelles le membre revents est non nul). Une valeur de 0 indique que l'appel a expiré et qu'aucun descripteur de fichier n'a été sélectionné. En cas d'échec, poll() renverra -1 et définira errno pour indiquer l'erreur.

ERREURS

La fonction poll() échouera si :

EAGAIN
L'allocation des structures de données internes a échoué mais une demande ultérieure peut réussir.
EINTR
Un signal a été intercepté pendant poll().
EINVAL
L'argument nfds est supérieur à {OPEN_MAX}, ou l'un des membres fd fait référence à un STREAM ou à un multiplexeur qui est lié (directement ou indirectement) en aval d'un multiplexeur.

b.
Des données peuvent être écrites sur le STREAM ouvert sur la bande prioritaire 0, car l'événement POLLOUT s'est produit sur le STREAM ouvert (fds[0] ou fds[1]).

6.
Si l'événement POLLHUP se produit sur le STREAM ouvert (fds[0] ou fds[1]), le périphérique sur le STREAM ouvert s'est déconnecté.

UTILISATION APPLICATION

Aucune.

RATIONALE

L'événement POLLHUP ne se produit pas pour les FIFOs simplement parce que le FIFO n'est pas ouvert en écriture. Il ne se produit que lorsque le FIFO est fermé par le dernier écrivain et persiste jusqu'à ce qu'un processus ouvre le FIFO en écriture ou que tous les descripteurs de fichiers en lecture seule du FIFO soient fermés.
