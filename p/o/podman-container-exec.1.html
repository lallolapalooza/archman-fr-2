podman-exec(1) Manuel des commandes générales podman-exec(1)

NOM

podman-exec - Exécuter une commande dans un conteneur en cours d'exécution

SYNOPIS

podman exec [options] conteneur commande [arg ...]

podman container exec [options] conteneur commande [arg ...]

DESCRIPTION

podman exec exécute une commande dans un conteneur en cours d'exécution.

OPTIONS

--cidfile=fichier

Lire l'identifiant du conteneur cible depuis le fichier spécifié.

--detach, -d

Démarrer la session d'exécution, mais ne pas s'y attacher. La commande s'exécute en arrière-plan, et la session d'exécution est automatiquement supprimée à son achèvement. La commande podman exec imprime l'identifiant de la session d'exécution et se termine immédiatement après son démarrage.

--detach-keys=séquence

Spécifier la séquence de touches pour détacher un conteneur. Le format est un seul caractère [a-Z] ou un ou plusieurs caractères ctrl-<valeur> où <valeur> est l'un des suivants : a-z, @, ^, [, , ou _. Spécifier "" désactive cette fonctionnalité. La valeur par défaut est ctrl-p,ctrl-q.

Cette option peut également être définie dans le fichier containers.conf(5).

--env, -e=env

Définir des variables d'environnement.

Cette option permet des variables d'environnement arbitraires qui sont disponibles pour le processus à lancer à l'intérieur du conteneur. Si une variable d'environnement est spécifiée sans valeur, Podman vérifie l'environnement de l'hôte pour une valeur et ne définit la variable que si elle est définie sur l'hôte. À titre de cas particulier, si une variable d'environnement se terminant par * est spécifiée sans valeur, Podman recherche dans l'environnement de l'hôte les variables commençant par le préfixe et ajoute ces variables au conteneur.

--env-file=fichier

Lire un fichier délimité par des lignes de variables d'environnement.

--interactive, -i

Lorsque défini sur true, rendre stdin disponible pour le processus contenu. Si false, le stdin du processus contenu est vide et immédiatement fermé.

Si attaché, stdin est redirigé vers le processus contenu. Si détaché, la lecture de stdin sera bloquée jusqu'à une connexion ultérieure.

Attention : Podman consommera l'entrée de stdin dès qu'elle sera disponible, même si le processus contenu ne la demande pas.

--latest, -l

Au lieu de fournir le nom ou l'identifiant du conteneur, utiliser le dernier conteneur créé. Note : le dernier conteneur démarré peut provenir d'autres utilisateurs de Podman sur la machine hôte. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--preserve-fd=FD1[,FD2,...]

Transmettre au processus les descripteurs de fichier additionnels spécifiés dans la liste séparée par des virgules. Il peut être spécifié plusieurs fois. Cette option n'est prise en charge qu'avec le runtime OCI crun. L'utilisation de cette option avec d'autres runtimes OCI peut présenter un risque de sécurité.

(Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--preserve-fds=N

Transmettre au processus N descripteurs de fichier additionnels (en plus de 0, 1, 2). Le total des FD est 3+N. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--privileged

Accorder des privilèges étendus à ce conteneur. La valeur par défaut est false.

Par défaut, les conteneurs Podman sont non privilégiés (=false) et ne peuvent pas, par exemple, modifier des parties du système d'exploitation. Cela est dû au fait qu'un conteneur n'est autorisé que par défaut qu'un accès limité aux périphériques. Un conteneur "privilégié" a le même accès aux périphériques que l'utilisateur qui lance le conteneur, à l'exception des consoles virtuelles (/dev/tty\d+) lors de l'exécution en mode systemd (--systemd=always).

Un conteneur privilégié désactive les fonctionnalités de sécurité qui isolent le conteneur de l'hôte. Les capacités supprimées, les périphériques limités, les points de montage en lecture seule, la séparation Apparmor/SELinux et les filtres Seccomp sont tous désactivés. En raison des fonctionnalités de sécurité désactivées, le champ privilégié ne devrait presque jamais être défini car les conteneurs peuvent facilement s'échapper du confinement.

Les conteneurs s'exécutant dans un espace de noms utilisateur (par exemple, les conteneurs sans privilèges) ne peuvent pas avoir plus de privilèges que l'utilisateur qui les a lancés.

--tty, -t

Allouer un pseudo-TTY. La valeur par défaut est false.

Lorsque défini sur true, Podman alloue un pseudo-TTY et se connecte à l'entrée standard du conteneur. Ceci peut être utilisé, par exemple, pour exécuter un shell interactif temporaire.

NOTE : L'indicateur --tty empêche la redirection de la sortie standard. Il combine STDOUT et STDERR, il peut insérer des caractères de contrôle, et il peut bloquer les pipes. Cette option est uniquement utilisée lorsqu'elle est exécutée interactivement dans un terminal. Lors de l'alimentation en entrée de Podman, utilisez uniquement -i, pas -it.

--user, -u=utilisateur[:groupe]

Définit le nom d'utilisateur ou l'UID utilisé et, éventuellement, le nom de groupe ou le GID pour la commande spécifiée. utilisateur et groupe peuvent être symboliques ou numériques.

Sans cet argument, la commande s'exécute en tant qu'utilisateur spécifié dans l'image du conteneur. Sauf indication contraire par une commande USER dans le Containerfile ou par une valeur passée à cette option, cet utilisateur est généralement root par défaut.

Lorsqu'un espace de noms utilisateur n'est pas utilisé, l'UID et le GID utilisés dans le conteneur et sur l'hôte correspondent. Cependant, lorsque les espaces de noms utilisateur sont utilisés, l'UID et le GID dans le conteneur peuvent correspondre à un autre UID et GID sur l'hôte. Dans les conteneurs sans privilèges, par exemple, un espace de noms utilisateur est toujours utilisé, et root dans le conteneur correspond par défaut à l'UID et au GID de l'utilisateur invoquant Podman.

--workdir, -w=rép

Répertoire de travail à l'intérieur du conteneur.

Le répertoire de travail par défaut pour l'exécution de binaires dans un conteneur est le répertoire racine (/). Le développeur de l'image peut définir une valeur par défaut différente avec l'instruction WORKDIR. L'opérateur peut remplacer le répertoire de travail en utilisant l'option -w.

STATUT DE SORTIE

Le code de sortie de podman exec fournit des informations sur la raison pour laquelle la commande dans le conteneur n'a pas pu être exécutée ou pourquoi elle s'est terminée. Lorsque podman exec se termine avec un code non nul, les codes de sortie suivent le standard chroot, voir ci-dessous :

125 L'erreur concerne Podman lui-même

$ podman exec --foo ctrID /bin/sh; echo $?
Error: unknown flag: --foo
125

126 La commande contenue ne peut pas être invoquée

$ podman exec ctrID /etc; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"/etc\": permission denied": OCI runtime error
126

127 La commande contenue est introuvable

$ podman exec ctrID foo; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"foo\": executable file not found in $PATH": OCI runtime error
127

Code de sortie Le code de sortie de la commande contenue

$ podman exec ctrID /bin/sh -c 'exit 3'; echo $?
3

EXEMPLES

Exécuter une commande dans le conteneur sélectionné avec stdin et un tty alloués :

$ podman exec -it ctrID ls

Exécuter une commande avec le répertoire de travail remplacé dans le conteneur sélectionné avec stdin et un tty alloués :

$ podman exec -it -w /tmp myCtr pwd

Exécuter une commande en tant qu'utilisateur spécifié dans le conteneur sélectionné :

$ podman exec --user root ctrID ls

Exécuter une commande mais ne pas s'attacher à la session d'exécution, laissant la commande s'exécuter en arrière-plan :

$ podman exec -d ctrID find /path/to/search -name yourfile

podman-container-exec 1

NOM

podman-container-exec – Exécuter une commande dans un conteneur en cours d’exécution

SYNOPSIS

podman container exec [OPTIONS] CONTAINER COMMAND [ARG...]

podman container exec [OPTIONS] CONTAINER

DESCRIPTION

La commande podman container exec exécute une commande dans un conteneur en cours d’exécution.

OPTIONS

Toutes les options globales de Podman s’appliquent.

Les options spécifiques à la commande exec sont les suivantes :

-e, --env
Définir des variables d’environnement. Peut être spécifié plusieurs fois pour définir plusieurs variables.
-i, --interactive
Conserver STDIN ouvert même si non attaché.
-t, --tty
Allouer un pseudo-TTY.
-u, --user
Nom d’utilisateur ou UID (et éventuellement un nom de groupe ou GID) à utiliser dans le conteneur.
-w, --workdir
Répertoire de travail dans le conteneur.

STATUT DE SORTIE

Le code de sortie de la commande exec est celui de la commande exécutée dans le conteneur. Si le conteneur n’existe pas ou s’il n’est pas en cours d’exécution, Podman renvoie un code de sortie différent de zéro.

EXEMPLES

Exécuter la commande ls -l dans un conteneur nommé mycontainer :

podman container exec mycontainer ls -l

Exécuter un shell interactif dans un conteneur nommé mycontainer :

podman container exec -it mycontainer /bin/bash

Définir la variable d’environnement MYVAR à la valeur myvalue et exécuter la commande printenv dans le conteneur :

podman container exec -e MYVAR=myvalue mycontainer printenv

podman(1), podman-run(1)
