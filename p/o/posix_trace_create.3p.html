POSIX_TRACE_CREATE(3P) Manuel du programmeur POSIX POSIX_TRACE_CREATE(3P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

posix_trace_create, posix_trace_create_withlog, posix_trace_flush, posix_trace_shutdown — initialisation, vidage et arrêt du flux de trace depuis un processus (TRACING)

SYNOPSIS

#include <sys/types.h>
#include <trace.h>
int posix_trace_create(pid_t pid,
    const trace_attr_t *restrict attr,
    trace_id_t *restrict trid);
int posix_trace_create_withlog(pid_t pid,
    const trace_attr_t *restrict attr, int file_desc,
    trace_id_t *restrict trid);
int posix_trace_flush(trace_id_t trid);
int posix_trace_shutdown(trace_id_t trid);

DESCRIPTION

La fonction posix_trace_create() crée un flux de trace actif. Elle alloue toutes les ressources nécessaires au flux de trace créé pour tracer le processus spécifié par pid conformément à l'argument attr. L'argument attr représente les attributs initiaux du flux de trace et doit avoir été initialisé par la fonction posix_trace_attr_init() avant l'appel à posix_trace_create(). Si l'argument attr est NULL, les attributs par défaut sont utilisés. L'objet d'attributs attr doit être manipulé via un ensemble de fonctions décrites dans la famille de fonctions posix_trace_attr. Si les attributs de l'objet pointé par attr sont modifiés ultérieurement, les attributs du flux de trace ne sont pas affectés. L'attribut creation-time du nouveau flux de trace créé est défini à la valeur de l'horloge système, si l'option Timers n'est pas prise en charge, ou à la valeur de l'horloge CLOCK_REALTIME, si l'option Timers est prise en charge.

L'argument pid représente le processus cible à tracer. Si le processus exécutant cette fonction n'a pas les privilèges appropriés pour tracer le processus identifié par pid, une erreur est renvoyée. Si l'argument pid est zéro, le processus appelant est tracé.

La fonction posix_trace_create() stocke l'identifiant du flux de trace du nouveau flux dans l'objet pointé par l'argument trid. Cet identifiant de flux de trace est utilisé dans les appels subséquents pour contrôler le traçage. L'argument trid ne peut être utilisé que par les fonctions suivantes :

posix_trace_clear() posix_trace_eventid_equal() posix_trace_eventid_get_name() posix_trace_eventtypelist_getnext_id() posix_trace_eventtypelist_rewind() posix_trace_get_attr() posix_trace_get_status() posix_trace_getnext_event() posix_trace_shutdown() posix_trace_start() posix_trace_stop() posix_trace_timedgetnext_event() posix_trace_trid_eventid_open() posix_trace_trygetnext_event()

Si l'option Trace Event Filter est prise en charge, les fonctions supplémentaires suivantes peuvent utiliser l'argument trid :

posix_trace_get_filter() posix_trace_set_filter()

En particulier, notez que les opérations normalement utilisées par un processus d'analyse de trace, telles que posix_trace_rewind() ou posix_trace_close(), ne peuvent pas être invoquées en utilisant l'identifiant du flux de trace retourné par la fonction posix_trace_create().

Un flux de trace est créé dans un état suspendu. Si l'option Trace Event Filter est prise en charge, son filtre de types d'événements de trace est vide.

La fonction posix_trace_create() peut être appelée plusieurs fois à partir du même processus ou de processus différents, avec la limite système indiquée par la valeur invariante d'exécution {TRACE_SYS_MAX}, qui a la valeur minimale {_POSIX_TRACE_SYS_MAX}.

L'identifiant du flux de trace retourné par la fonction posix_trace_create() dans l'argument pointé par trid n'est valide que dans le processus qui a effectué l'appel de fonction. S'il est utilisé depuis un autre processus, qui est un processus enfant, dans les fonctions définies dans POSIX.1‐2008, ces fonctions retourneront avec l'erreur [EINVAL].

La fonction posix_trace_create_withlog() est équivalente à posix_trace_create(), sauf qu'elle associe un journal de trace à ce flux. L'argument file_desc est le descripteur de fichier désignant la destination du journal de trace. La fonction échoue si ce descripteur de fichier fait référence à un fichier dont le type de fichier n'est pas compatible avec la politique de journalisation associée au journal de trace. La liste des types de fichiers appropriés compatibles avec chaque politique de journalisation est définie par l'implémentation.

La fonction posix_trace_create_withlog() retourne dans le paramètre pointé par trid l'identifiant du flux de trace, qui identifie de manière unique le flux de trace nouvellement créé et doit être utilisé dans les appels ultérieurs pour contrôler le traçage. L'argument trid ne peut être utilisé que par les fonctions suivantes :

posix_trace_clear() posix_trace_eventid_equal() posix_trace_eventid_get_name() posix_trace_eventtypelist_getnext_id() posix_trace_eventtypelist_rewind() posix_trace_flush() posix_trace_get_attr() posix_trace_get_status() posix_trace_getnext_event() posix_trace_shutdown() posix_trace_start() posix_trace_stop() posix_trace_timedgetnext_event() posix_trace_trid_eventid_open()

Si l'option Trace Event Filter est prise en charge, les fonctions supplémentaires suivantes peuvent utiliser l'argument trid :

posix_trace_get_filter() posix_trace_set_filter()

En particulier, notez que les opérations normalement utilisées par un processus d'analyse de trace, telles que posix_trace_rewind() ou posix_trace_close(), ne peuvent pas être invoquées en utilisant l'identifiant du flux de trace retourné par la fonction posix_trace_create_withlog().

La fonction posix_trace_flush() initie une opération de vidage qui copie le contenu du flux de trace identifié par l'argument trid dans le journal de trace associé au flux de trace au moment de sa création. Si aucun journal de trace n'a été associé au flux de trace pointé par trid, cette fonction retourne une erreur. La fin de l'opération de vidage peut être vérifiée par la fonction posix_trace_get_status(). Pendant l'opération de vidage, il est possible de tracer de nouveaux événements de trace jusqu'à ce que le flux de trace soit plein. Une fois le vidage terminé, l'espace utilisé par les événements de trace vidés devient disponible pour le traçage de nouveaux événements.

Si le vidage du flux de trace provoque le remplissage du journal de trace résultant, la politique de remplissage du journal de trace est appliquée. Si l'attribut log-full-policy de la trace est défini, ce qui suit se produit :

POSIX_TRACE_UNTIL_FULL

Les événements de trace qui n'ont pas encore été vidés sont ignorés.
POSIX_TRACE_LOOP

Les événements de trace qui n'ont pas encore été vidés sont écrits au début du journal de trace, écrasant les événements de trace précédents qui y étaient stockés.
POSIX_TRACE_APPEND

Les événements de trace qui n'ont pas encore été vidés sont ajoutés au journal de trace.

La fonction posix_trace_shutdown() arrête le traçage des événements de trace dans le flux de trace identifié par trid, comme si posix_trace_stop() avait été appelée. La fonction posix_trace_shutdown() libère toutes les ressources associées au flux de trace.

La fonction posix_trace_shutdown() ne retourne pas tant que toutes les ressources associées au flux de trace n'ont pas été libérées. Lorsque la fonction posix_trace_shutdown() retourne, l'argument trid devient un identifiant de flux de trace invalide. Un appel à cette fonction désalloue inconditionnellement les ressources, que tous les événements de trace aient été récupérés ou non par le processus d'analyse. posix_trace_create - page de manuel POSIX

PROLOG

Ce document décrit les versions de posix_trace_create, posix_trace_create_withlog, posix_trace_flush, et posix_trace_shutdown telles qu'elles apparaissent dans les versions 3, 4 et 5 de la norme IEEE Std 1003.1.

NOM

posix_trace_create, posix_trace_create_withlog, posix_trace_flush, posix_trace_shutdown — créer, vider et fermer des flux de trace POSIX

SYNTAXE

#include <trace.h>

int posix_trace_create(const char *restrict name, const posix_trace_attr_t *restrict attr, posix_trace_id_t *restrict trid);

int posix_trace_create_withlog(const char *restrict name, const posix_trace_attr_t *restrict attr, int file_desc, posix_trace_id_t *restrict trid);

int posix_trace_flush(posix_trace_id_t trid);

int posix_trace_shutdown(posix_trace_id_t trid);

DESCRIPTION

Ces fonctions sont utilisées pour créer, vider et fermer des flux de trace POSIX. Les flux de trace permettent d'enregistrer des événements de trace au fil du temps. L'API de trace POSIX est définie dans le chapitre 17 de la norme IEEE Std 1003.1-2017.

La fonction posix_trace_create crée un flux de trace avec un identificateur unique associé à la valeur de name. Les attributs du flux de trace sont spécifiés par la structure attr. L'identificateur du flux de trace créé est renvoyé via le pointeur trid.

La fonction posix_trace_create_withlog est similaire à posix_trace_create, mais elle associe en outre le flux de trace à un fichier spécifié par le descripteur de fichier file_desc. Ce fichier sert de journal de trace, dans lequel les événements de trace seront enregistrés.

La fonction posix_trace_flush force le vidage de tous les événements de trace qui n'ont pas encore été écrits dans le journal de trace associé au flux identifié par trid. Cette opération est nécessaire pour s'assurer que toutes les données de trace sont enregistrées avant la fermeture du flux.

La fonction posix_trace_shutdown ferme le flux de trace spécifié par trid. Si le flux est associé à un journal de trace, tous les événements de trace restants sont vidés dans le journal avant la fermeture de celui-ci. La fermeture du flux libère les ressources associées.

Si un processus se termine, appelle une fonction de la famille exec, ou est terminé, tous les flux de trace qu'il avait créés et qui n'avaient pas encore été fermés sont automatiquement fermés, comme s'ils avaient fait l'objet d'un appel explicite à la fonction posix_trace_shutdown.

Pour un flux de trace actif avec un journal, lorsque la fonction posix_trace_shutdown est appelée, tous les événements de trace qui n'ont pas encore été vidés dans le journal de trace sont vidés, comme dans la fonction posix_trace_flush, et le journal de trace est fermé.

Lorsqu'un journal de trace est fermé, toutes les informations qui peuvent être récupérées ultérieurement du journal de trace via l'interface de trace doivent avoir été écrites dans le journal de trace. Ces informations incluent les attributs de trace, la liste des types d'événements de trace (avec le mappage entre les noms d'événements de trace et les identificateurs de type d'événement de trace), et l'état de la trace.

De plus, des informations non spécifiées doivent être écrites dans le journal de trace pour permettre la détection d'un journal de trace valide lors de l'opération posix_trace_open.

La fonction posix_trace_shutdown ne renverra pas tant que tous les événements de trace n'auront pas été vidés.

VALEUR RENVOYÉE

En cas de succès, ces fonctions renvoient une valeur de zéro. Sinon, elles renvoient le numéro d'erreur correspondant.

Les fonctions posix_trace_create et posix_trace_create_withlog stockent la valeur de l'identificateur de flux de trace dans l'objet pointé par trid, en cas de succès.

ERREURS

Les fonctions posix_trace_create et posix_trace_create_withlog échoueront si :

EAGAIN
Aucun autre flux de trace ne peut être démarré maintenant. {TRACE_SYS_MAX} a été dépassé.
EINTR
L'opération a été interrompue par un signal. Aucun flux de trace n'a été créé.
EINVAL
Un ou plusieurs des paramètres de trace spécifiés par le paramètre attr sont invalides.
ENOMEM
L'implémentation ne dispose actuellement pas de suffisamment de mémoire pour créer le flux de trace avec les paramètres spécifiés.
EPERM
L'appelant n'a pas les privilèges appropriés pour tracer le processus spécifié par pid.
ESRCH
L'argument pid ne fait pas référence à un processus existant.

La fonction posix_trace_create_withlog échouera si :

EBADF
L'argument file_desc n'est pas un descripteur de fichier valide ouvert en écriture.
EINVAL
L'argument file_desc fait référence à un fichier dont le type de fichier ne prend pas en charge la politique de journalisation associée au journal de trace.
ENOSPC
Plus d'espace disponible sur le périphérique. Le périphérique correspondant à l'argument file_desc ne contient pas l'espace requis pour créer ce journal de trace.

Les fonctions posix_trace_flush et posix_trace_shutdown échoueront si :

EINVAL
La valeur de l'argument trid ne correspond pas à un flux de trace actif avec journal.
EFBIG
Le fichier journal de trace a tenté de dépasser une taille de fichier maximale définie par l'implémentation.
ENOSPC
Plus d'espace disponible sur le périphérique.
