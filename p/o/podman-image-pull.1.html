podman-pull(1) Manuel des commandes générales podman-pull(1)

NOM

podman-pull - Télécharger une image depuis un registre

SYNOPIS

podman pull [options] source [source...]

podman image pull [options] source [source...]

podman pull [options] [transport]nom[:tag|@digest]

podman image pull [options] [transport]nom[:tag|@digest]

DESCRIPTION

podman pull copie une image depuis un registre vers la machine locale. La commande peut télécharger une ou plusieurs images. Si la référence de l'image dans l'argument de ligne de commande ne contient pas de registre, elle est appelée une référence par nom court. Si l'image est une référence par 'nom court', Podman demande à l'utilisateur le registre de conteneur spécifique à partir duquel télécharger l'image, si un alias pour le nom court n'a pas été spécifié dans short-name-aliases.conf. Si une étiquette d'image n'est pas spécifiée, podman pull utilise par défaut l'image avec l'étiquette latest (si elle existe) et la télécharge. Après le téléchargement de l'image, podman affiche l'ID complet de l'image. podman pull peut également télécharger des images en utilisant un digest podman pull image@digest et peut également être utilisé pour télécharger des images à partir d'archives et de stockage local en utilisant différents transports. IMPORTANT : les images sont stockées dans le stockage d'images local.

SOURCE

SOURCE est l'emplacement à partir duquel l'image du conteneur est téléchargée. Il prend en charge tous les transports de containers-transports(5). Si aucun transport n'est spécifié, l'entrée est sujette à la résolution par nom court et le transport docker (c'est-à-dire le registre de conteneurs) est utilisé. Pour les clients distants, y compris les machines Mac et Windows (à l'exclusion de WSL2), docker est le seul transport pris en charge.

# Télécharger depuis un registre de conteneurs
$ podman pull quay.io/username/myimage
# Télécharger depuis un registre de conteneurs avec résolution par nom court
$ podman pull fedora
# Télécharger depuis un registre de conteneurs via le transport docker
$ podman pull docker://quay.io/username/myimage
# Télécharger depuis un répertoire local
$ podman pull dir:/tmp/myimage
# Télécharger depuis une archive au format docker-archive
$ podman pull docker-archive:/tmp/myimage
# Télécharger depuis un démon docker local
$ sudo podman pull docker-daemon:docker.io/library/myimage:33
# Télécharger depuis une archive au format oci-archive
$ podman pull oci-archive:/tmp/myimage

OPTIONS

--all-tags, -a

Toutes les images étiquetées du dépôt sont téléchargées.

*IMPORTANT : Lorsque vous utilisez l'indicateur all-tags, Podman n'itère pas sur les registres de recherche dans containers-registries.conf(5) mais utilise toujours docker.io pour les noms d'image non qualifiés.*

--arch=ARCH

Remplace l'architecture, par défaut celle de l'hôte, de l'image à télécharger. Par exemple, arm. Sauf remplacement, les recherches ultérieures de la même image dans le stockage local correspondent à cette architecture, quel que soit l'hôte.

--authfile=chemin

Chemin du fichier d'authentification. Par défaut : ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'est pas trouvé là, $HOME/.docker/config.json est vérifié, qui est défini en utilisant docker login.

Note : Il existe également une option pour remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utilise les certificats présents dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exclusion de WSL2)).

--creds=[nomutilisateur[:motdepasse]]

Le [nomutilisateur[:motdepasse]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou les deux valeurs ne sont pas fournies, une invite de commande apparaît et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les identifiants spécifiés sont uniquement utilisés pour l'authentification auprès des registres cibles. Ils ne sont pas utilisés pour les miroirs ou lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour vous authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--decryption-key=clé[:phrase-secrète]

La [clé[:phrase-secrète]] à utiliser pour le déchiffrement des images. La clé peut pointer vers des clés et/ou des certificats. Le déchiffrement est tenté avec toutes les clés. Si la clé est protégée par une phrase secrète, celle-ci doit être fournie dans l'argument et omise sinon.

--disable-content-trust

Ceci est une option spécifique à Docker pour désactiver la vérification des images vers un registre de conteneurs et n'est pas prise en charge par Podman. Cette option est une NOOP et fournie uniquement à des fins de compatibilité de script.

--help, -h

Imprime l'énoncé d'utilisation.

--os=OS

Remplace le système d'exploitation, par défaut celui de l'hôte, de l'image à télécharger. Par exemple, windows. Sauf remplacement, les recherches ultérieures de la même image dans le stockage local correspondent à ce système d'exploitation, quel que soit l'hôte.

--platform=OS/ARCH

Spécifie la plateforme pour la sélection de l'image. (Entre en conflit avec --arch et --os) L'option --platform peut être utilisée pour remplacer l'architecture et le système d'exploitation actuels. Sauf remplacement, les recherches ultérieures de la même image dans le stockage local correspondent à cette plateforme, quel que soit l'hôte.

--policy

Politique de téléchargement d'image. La valeur par défaut est always.

  • always : Télécharge toujours l'image et génère une erreur si le téléchargement échoue.
  • missing : Télécharge l'image uniquement si elle n'a pas été trouvée dans le stockage de conteneurs local. Génère une erreur si aucune image n'a été trouvée et que le téléchargement échoue.
  • never : Ne télécharge jamais l'image ; utilise uniquement la version locale. Génère une erreur si l'image n'est pas présente localement.
  • newer : Télécharge si l'image sur le registre est plus récente que celle présente dans le stockage de conteneurs local. Une image est considérée comme plus récente lorsque les digests sont différents. La comparaison des horodatages est sujette à des erreurs. Les erreurs de téléchargement sont supprimées si une image locale a été trouvée.

--quiet, -q

Supprime les informations de sortie lors du téléchargement des images

--retry=tentatives

Nombre de tentatives pour télécharger ou pousser des images entre le registre et le stockage local en cas d'échec. Par défaut : 3.

--retry-delay=durée

Durée du délai entre les tentatives de téléchargement ou de poussée d'images entre le registre et le stockage local en cas d'échec. Par défaut, le délai commence à deux secondes puis augmente exponentiellement. Le délai est utilisé lorsque cette valeur est définie, et aucune augmentation exponentielle ne se produit.

--tls-verify

Exige HTTPS et vérifie les certificats lors du contact avec les registres (par défaut : true). S'il est explicitement défini sur true, la vérification TLS est utilisée. S'il est défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée à moins que le registre cible ne soit répertorié comme registre non sécurisé dans containers-registries.conf(5)

--variant=VARIANT

Utilise VARIANT au lieu de la variante d'architecture par défaut de l'image du conteneur. Certaines images peuvent utiliser plusieurs variantes des architectures arm, telles que arm/v5 et arm/v7.

podman-image-pull.1.en

NAME

podman-image-pull - Pull an image from a registry

SYNOPSIS

podman image pull [options] [name[:tag|@digest]] [...]

podman pull [options] [name[:tag|@digest]] [...]

DESCRIPTION

The podman image pull command downloads one or more container images from a registry. The images can be specified by name and optionally a tag or digest. If no tag is specified, the latest tag is assumed.

If the image name is not qualified with a registry, Podman will use the registry configured in registries.conf. By default, this is docker.io.

Podman supports pulling images using the transports defined in containers-transports(5).

Podman supports the following options.

SOURCE

The source of the image is a registry. Podman consults the registries.conf file to determine which registries to consult when an image name is not fully qualified.

OPTIONS

--all, -a
Download all images that are tagged in the registry.
--arch architecture
Pull an image for a specific architecture.
--authfile path
Path to the authentication file. Default is ${XDG_RUNTIME_DIR}/containers/auth.json. If it does not exist, it is created in JSON format. If authentication is not needed, a file does not have to be created.
--cert-dir path
Use certificates from the specified directory for TLS verification. Default is /etc/containers/certs.d/. This option can be used to override the default directory where container image registries store their TLS certificates.
--creds username:password
Use credentials for a registry. This option can be used to override the default credentials obtained from auth.json.
--daemon-host URI
Connect to a container daemon identified by URI. If not specified, Podman connects to the default Docker host configured in the environment.
--drop-capabilities
Drop privileges not needed to run image. For more information about capabilities, refer to capabilities(7).
--format template
Format output using a Go template.
--get-content
Download image content even if it is already present locally.
--identity identity
Specify identity for image operations, e.g. registry login. This identity is used for registry authentication and image content access.
--internal
Download image content from internal registries. Use this option to enable the download of image content from registries that are not accessible from outside the network. For example, if an image is stored in a private registry that is only accessible from within a corporate network, use this option to download the image. This option is not effective when used with external registries.
--job-name name
Specify a name for the job that will be used for tracking and managing background jobs.
--json
Print the output in JSON format.
--log-level level
Set the logging level for the pull operation. Valid levels are: debug, info, warn, error, fatal, panic, off.
--os OS
Pull an image for a specific OS.
--policy policy
Image pull policy. Can be one of:
missing
Pull image only if not present locally.
never
Never pull image, only use local version.
always
Always pull image even if present locally.
--quiet, -q
Suppress the output. Only the image ID will be printed.
--registry registry
Specify the registry to pull the image from. This option can be used to override the default registry configured in registries.conf.
--remote
Allow podman to run pull commands on a remote host. The remote host is identified by the container daemon URI specified by the daemon-host option.
--retry num
Number of retries to attempt when pulling an image. Default is 5.
--retry-delay time
Delay between retries in seconds. Default is 2 seconds.
--signature-policy path
Path to the signature policy file. Default is /etc/containers/policy.json.
--syslog
Log to syslog instead of stderr. The syslog facility defaults to USER.
--tls-verify
Require TLS verification of the registry. Default is true.

FILES

/var/cache/containers/short-name-aliases.conf, $HOME/.cache/containers/short-name-aliases.conf

When users specify images that do not include the container registry where the image is stored, this is called a short name. The use of unqualified-search registries entails an ambiguity as it is unclear from which registry a given image, referenced by a short name, may be pulled from.

Using short names is subject to the risk of hitting squatted registry namespaces. If the unqualified-search registries are set to ["public-registry.com", "my-private-registry.com"] an attacker may take over a namespace of public-registry.com such that an image may be pulled from public-registry.com instead of the intended source my-private-registry.com.

While it is highly recommended to always use fully-qualified image references, existing deployments using short names may not be easily changed. To circumvent the aforementioned ambiguity, so called short-name aliases can be configured that point to a fully-qualified image reference. Distributions often ship a default shortnames.conf expansion file in /etc/containers/registries.conf.d/ directory. Administrators can use this directory to add their own local short-name expansion files.

When pulling an image, if the user does not specify the complete registry, container engines attempt to expand the short-name into a full name. If the command is executed with a tty, the user is prompted to select a registry from the default list unqualified registries defined in registries.conf. The user's selection is then stored in a cache file to be used in all future short-name expansions. Rootful short-names are stored in /var/cache/containers/short-name-aliases.conf. Rootless short-names are stored in the $HOME/.cache/containers/short-name-aliases.conf file.

For more information on short-names, see containers-registries.conf(5)

registries.conf (/etc/containers/registries.conf)

registries.conf is the configuration file which specifies which container registries is consulted when completing image names which do not include a registry or domain portion.

NOTE: Use the environment variable TMPDIR to change the temporary storage location of downloaded container images. Podman defaults to use /var/tmp.
