NOM

podman-container-restore - Restaure un ou plusieurs conteneurs à partir d'un point de contrôle

SYNOPSIS

podman container restore [options] nom [...]

DESCRIPTION

podman container restore restaure un conteneur à partir d'un point de contrôle de conteneur ou d'une image de point de contrôle. Les ID de conteneur, ID d'image ou noms sont utilisés comme entrée.

OPTIONS

--all, -a

Restaure tous les conteneurs sauvegardés sur un point de contrôle.
La valeur par défaut est false.
IMPORTANT : Cette OPTION ne nécessite pas de nom ou d'ID de conteneur comme argument d'entrée.

--file-locks

Restaure un conteneur avec des verrous de fichiers. Cette option est requise pour restaurer les verrous de fichiers à partir d'une image de point de contrôle. Si l'image de point de contrôle ne contient pas de verrous de fichiers, cette option est ignorée. La valeur par défaut est de ne pas restaurer les verrous de fichiers.
La valeur par défaut est false.

--ignore-rootfs

Si un conteneur est restauré à partir d'un fichier tar.gz de point de contrôle, il est possible qu'il contienne également toutes les modifications du système de fichiers racine. Avec --ignore-rootfs, il est possible de désactiver explicitement l'application de ces modifications du système de fichiers racine au conteneur restauré.
La valeur par défaut est false.
IMPORTANT : Cette OPTION n'est disponible qu'en combinaison avec --import, -i.

--ignore-static-ip

Si le conteneur a été démarré avec --ip, le conteneur restauré essaie également d'utiliser cette adresse IP et la restauration échoue si cette adresse IP est déjà utilisée. Cela peut se produire si un conteneur est restauré plusieurs fois à partir d'un point de contrôle exporté avec --name, -n.

L'utilisation de --ignore-static-ip indique à Podman d'ignorer l'adresse IP si elle a été configurée avec --ip lors de la création du conteneur.

La valeur par défaut est false.

--ignore-static-mac

Si le conteneur a été démarré avec --mac-address, le conteneur restauré essaie également d'utiliser cette adresse MAC et la restauration échoue si cette adresse MAC est déjà utilisée. Cela peut se produire si un conteneur est restauré plusieurs fois à partir d'un point de contrôle exporté avec --name, -n.

L'utilisation de --ignore-static-mac indique à Podman d'ignorer l'adresse MAC si elle a été configurée avec --mac-address lors de la création du conteneur.

La valeur par défaut est false.

--ignore-volumes

Cette option doit être utilisée en combinaison avec l'option --import, -i. Lors de la restauration des conteneurs à partir d'un fichier tar.gz de point de contrôle avec cette option, le contenu des volumes associés n'est pas restauré.
La valeur par défaut est false.

--import, -i=fichier

Importe un fichier tar.gz de point de contrôle, qui a été exporté par Podman. Ceci peut être utilisé pour importer un conteneur sauvegardé sur un point de contrôle depuis un autre hôte.
IMPORTANT : Cette OPTION ne nécessite pas de nom ou d'ID de conteneur comme argument d'entrée.

Lors de l'importation d'un fichier de point de contrôle, Podman sélectionne le même runtime de conteneur qui a été utilisé lors de la création du point de contrôle. Ceci est particulièrement important si un runtime de conteneur spécifique (non par défaut) a été spécifié lors de la création du conteneur. Podman abandonne également la restauration si le runtime de conteneur spécifié lors de la restauration ne correspond pas au runtime de conteneur utilisé pour la création du conteneur.

--import-previous=fichier

Importe un fichier tar.gz pré-point de contrôle qui a été exporté par Podman. Cette option doit être utilisée avec -i ou --import. Elle ne fonctionne qu'avec runc 1.0-rc3 ou supérieur. IMPORTANT : Cette OPTION n'est pas prise en charge par le client distant, y compris les machines Mac et Windows (à l'exception de WSL2).

--keep, -k

Conserve tous les fichiers temporaires de logs et de statistiques créés par CRIU pendant la création du point de contrôle ainsi que pendant la restauration. Ces fichiers ne sont pas supprimés si la restauration échoue, afin de permettre un débogage ultérieur. Si la restauration réussit, ces fichiers ne sont théoriquement pas nécessaires, mais si ces fichiers sont nécessaires, Podman peut les conserver pour une analyse plus approfondie. Cela inclut le répertoire du point de contrôle avec tous les fichiers créés lors de la création du point de contrôle. La taille requise par le répertoire du point de contrôle est à peu près égale à la quantité de mémoire requise par les processus du conteneur sauvegardé sur un point de contrôle.
Sans l'option --keep, -k, le point de contrôle est consommé et ne peut pas être réutilisé.
La valeur par défaut est false.

--latest, -l

Au lieu de fournir l'ID du conteneur ou le nom, utilise le dernier conteneur créé. La valeur par défaut est false. IMPORTANT : Cette OPTION n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exception de WSL2). Cette OPTION ne nécessite pas de nom ou d'ID de conteneur comme argument d'entrée.

--name, -n=nom

Si un conteneur est restauré à partir d'un fichier tar.gz de point de contrôle, il est possible de le renommer avec --name, -n. De cette façon, il est possible de restaurer un conteneur à partir d'un point de contrôle plusieurs fois avec des noms différents.

Si l'option --name, -n est utilisée, Podman n'essaie pas d'attribuer la même adresse IP au conteneur qu'il utilisait avant le point de contrôle, car chaque adresse IP ne peut être utilisée qu'une seule fois, et le conteneur restauré aura une adresse IP différente. Cela signifie également que --name, -n ne peut pas être utilisé en combinaison avec --tcp-established.
IMPORTANT : Cette OPTION n'est disponible que pour une image de point de contrôle ou en combinaison avec --import, -i.

--pod=nom

Restaure un conteneur dans le pod nom. Le pod de destination pour cette restauration doit partager les mêmes espaces de noms que le pod à partir duquel ce conteneur a été sauvegardé sur un point de contrôle (voir **podman pod create --share.
IMPORTANT : Cette OPTION n'est disponible que pour une image de point de contrôle ou en combinaison avec --import, -i.

Cette option nécessite au moins CRIU 3.16.

--print-stats

Affiche des statistiques sur la restauration des conteneurs. La sortie est rendue sous forme de tableau JSON et contient des informations sur le temps nécessaire aux différentes opérations de restauration. De nombreuses statistiques de restauration sont créées par CRIU et simplement transmises à Podman. Les informations suivantes sont fournies dans le tableau JSON :

  • podman_restore_duration : Temps total (en microsecondes) nécessaire pour restaurer tous les points de contrôle.
  • runtime_restore_duration : Temps (en microsecondes) nécessaire au runtime du conteneur pour restaurer le point de contrôle.
  • forking_time : Temps (en microsecondes) nécessaire à CRIU pour créer (forker) tous les processus du conteneur restauré (mesuré par CRIU).
  • restore_time : Temps (en microsecondes) nécessaire à CRIU pour restaurer tous les processus du conteneur (mesuré par CRIU).
  • pages_restored : Nombre de pages mémoire restaurées (mesuré par CRIU).

La valeur par défaut est false.

--publish, -p=port

Remplace les ports que le conteneur publie, tels qu'ils ont été configurés lors du démarrage initial du conteneur, par un nouvel ensemble de règles de transfert de ports.

Pour plus de détails, voir podman run --publish.

--tcp-close

Restaure un conteneur et ferme toutes les connexions TCP. Cette option est utile lorsque les connexions TCP ne sont pas nécessaires après la restauration ou lorsque les connexions seront rétablies par l'application. Si l'image du point de contrôle a été créée avec --tcp-close, cette option doit être utilisée lors de la restauration.
La valeur par défaut est false.

--tcp-established

Restaure un conteneur avec des connexions TCP établies. Si l'image du point de contrôle contient des connexions TCP établies, cette option est requise lors de la restauration. Si l'image du point de contrôle ne contient pas de connexions TCP établies, cette option est ignorée. La valeur par défaut est de ne pas restaurer les conteneurs avec des connexions TCP établies.

podman-container-restore(1) — podman

NAME

podman-container-restore - Restore a container from a checkpoint

SYNOPSIS

podman container restore [OPTIONS] CONTAINER
podman container restore [OPTIONS] IMAGE

DESCRIPTION

The podman container restore command restores a container from a checkpoint created with the podman-container-checkpoint(1) command.

Restoring a container requires the container to be created with the same name, or a new name can be specified using the --name option. The container will be restored to the state it was in when it was checkpointed.

Restoring from a checkpoint image is also supported. The checkpoint image is created by podman container checkpoint with the --create-image option.

If a checkpoint file is imported, the container will be restored using the contents of the checkpoint file. The original container will be removed after the restore. If the original container was running, the restored container will also be running.

The checkpoint must have been created by the same version of Podman, or a compatible version.

The --import and --import-previous flags can be used to restore from a checkpoint file. The --import flag imports the checkpoint file, while the --import-previous flag imports the previous checkpoint file. This can be useful for restoring a container to a previous state.

OPTIONS

--all
Restore all containers that were checkpointed.
--import=path
Import the checkpoint from the specified file.
--import-previous=path
Import the previous checkpoint from the specified file.
--keep-running
Do not stop the container after restoring. The default is to stop the container.
--leave-running
Do not stop the container after checkpointing. The default is to stop the container.
--name=name
The name for the restored container. If not specified, the name of the original container will be used.
-p, --publish=[ip:]host:container
Publish a container's network listener to the host. The format of the mapping is a number of comma-separated mappings. The host and container ports must be specified.
--tcp-established
Restores open TCP connections. The default is false.

EXAMPLES

Restore the container "mywebserver".

# podman container restore mywebserver

Import a checkpoint file and a pre-checkpoint file.

# podman container restore --import-previous pre-checkpoint.tar.gz --import checkpoint.tar.gz

Start the container "mywebserver". Make a checkpoint of the container and export it. Restore the container with other port ranges from the exported file.

$ podman run --rm -p 2345:80 -d webserver
# podman container checkpoint -l --export=dump.tar
# podman container restore -p 5432:8080 --import=dump.tar

Start a container with the name "foobar-1". Create a checkpoint image "foobar-checkpoint". Restore the container from the checkpoint image with a different name.

# podman run --name foobar-1 -d webserver
# podman container checkpoint --create-image foobar-checkpoint foobar-1
# podman inspect foobar-checkpoint
# podman container restore --name foobar-2 foobar-checkpoint
# podman container restore --name foobar-3 foobar-checkpoint
