podman-push(1) Manuel des commandes générales podman-push(1)

NOM

podman-push - Pousse une image, une liste de manifestes ou un index d'images depuis le stockage local vers ailleurs

SYNTAXE

podman push [options] image [destination]

podman image push [options] image [destination]

DESCRIPTION

Pousse une image, une liste de manifestes ou un index d'images depuis le stockage local vers une destination spécifiée.

Stockage d'images

Les images sont poussées depuis celles stockées dans le stockage d'images local.

DESTINATION

DESTINATION est l'emplacement vers lequel l'image du conteneur est poussée. Elle supporte tous les transports de containers-transports(5). Si aucun transport n'est spécifié, le transport docker (c'est-à-dire le registre de conteneurs) est utilisé. Pour les clients distants, y compris les machines Mac et Windows (à l'exception de WSL2), docker est le seul transport supporté.

# Pousser vers un registre de conteneurs
$ podman push quay.io/podman/stable
# Pousser vers un registre de conteneurs via le transport docker
$ podman push docker://quay.io/podman/stable
# Pousser vers un registre de conteneurs avec un autre tag
$ podman push myimage quay.io/username/myimage
# Pousser vers un répertoire local
$ podman push myimage dir:/tmp/myimage
# Pousser vers un fichier tar au format docker-archive
$ podman push myimage docker-archive:/tmp/myimage
# Pousser vers un démon docker local
$ sudo podman push myimage docker-daemon:docker.io/library/myimage:33
# Pousser vers un fichier tar au format OCI
$ podman push myimage oci-archive:/tmp/myimage

OPTIONS

--authfile=chemin

Chemin du fichier d'authentification. Par défaut, ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'y est pas trouvé, $HOME/.docker/config.json est vérifié, qui est défini en utilisant docker login.

Note : Il existe également une option pour remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utiliser les certificats présents dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exception de WSL2))

--compress

Compresse les couches de l'image au format tar lors du push vers un répertoire en utilisant le transport 'dir'. (La compression par défaut est le même type de compression, compressé ou non compressé, que la source)

Note : Cet indicateur ne peut être défini que lors de l'utilisation du transport dir

--compression-format=gzip | zstd | zstd:chunked

Spécifie le format de compression à utiliser. Les valeurs supportées sont : gzip, zstd et zstd:chunked. Le défaut est gzip sauf si remplacé dans le fichier containers.conf. zstd:chunked est incompatible avec le chiffrement des images, et sera traité comme zstd avec un avertissement dans ce cas.

--compression-level=niveau

Spécifie le niveau de compression à utiliser. La valeur est spécifique à l'algorithme de compression utilisé, par exemple, pour zstd les valeurs acceptées sont comprises entre 1 et 20 (inclus) avec un défaut de 3, tandis que pour gzip elles sont comprises entre 1 et 9 (inclus) avec un défaut de 5.

--creds=[nomutilisateur[:motdepasse]]

Le [nomutilisateur[:motdepasse]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou deux valeurs ne sont pas fournies, une invite en ligne de commande apparaît et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les identifiants spécifiés sont uniquement utilisés pour l'authentification auprès des registres cibles. Ils ne sont pas utilisés pour les miroirs ou lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour vous authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--digestfile=FichierDigest

Après avoir copié l'image, écrire le digest de l'image résultante dans le fichier.

--disable-content-trust

Il s'agit d'une option spécifique à Docker pour désactiver la vérification des images auprès d'un registre de conteneurs et n'est pas prise en charge par Podman. Cette option est un NOOP (ne fait rien) et est fournie uniquement pour la compatibilité des scripts.

--encrypt-layer=couche(s)

Couche(s) à chiffrer : indices de couches basés sur 0 avec support de l'indexation négative (par exemple, 0 est la première couche, -1 est la dernière couche). Si non défini, chiffre toutes les couches si l'indicateur encryption-key est spécifié.

--encryption-key=clé

Le [protocole:fichierclé] spécifie le protocole de chiffrement, qui peut être JWE (RFC7516), PGP (RFC4880) et PKCS7 (RFC2315) ainsi que le matériel de clé requis pour le chiffrement de l'image. Par exemple, jwe:/chemin/vers/key.pem ou pgp:admin@example.com ou pkcs7:/chemin/vers/fichier-x509.

--force-compression

Si défini, le push utilise l'algorithme de compression spécifié même si la destination contient déjà une variante compressée différemment. Par défaut, il est égal à true si --compression-format est explicitement spécifié sur la ligne de commande, false sinon.

--format, -f=format

Type de manifeste (oci, v2s2, ou v2s1) à utiliser lors du push d'une image.

--quiet, -q

Lors de l'écriture de l'image de sortie, supprimer l'affichage de la progression

--remove-signatures

Supprimer toute signature préexistante dans l'image.

--retry=tentatives

Nombre de fois où tenter de tirer ou de pousser des images entre le registre et le stockage local en cas d'échec. Le défaut est 3.

--retry-delay=durée

Durée du délai entre les tentatives de relance lors du tirage ou du push d'images entre le registre et le stockage local en cas d'échec. Par défaut, le délai commence à deux secondes puis augmente exponentiellement. Le délai est utilisé lorsque cette valeur est définie, et aucune augmentation exponentielle ne se produit.

--sign-by=clé

Ajouter une signature de “ signature simple ” à la destination en utilisant la clé spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exception de WSL2))

--sign-by-sigstore=paramètre-fichier

Ajouter une signature sigstore basée sur d'autres options spécifiées dans un fichier de paramètres de signature sigstore de conteneur paramètre-fichier. Voir containers-sigstore-signing-params.yaml(5) pour les détails sur le format du fichier.

--sign-by-sigstore-private-key=chemin

Ajouter une signature sigstore à la destination en utilisant une clé privée située au chemin spécifié. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exception de WSL2))

--sign-by-sq-fingerprint=empreinte

Ajouter une signature de “ signature simple ” en utilisant une clé Sequoia-PGP avec l'empreinte spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exception de WSL2))

--sign-passphrase-file=chemin

Si l'image est signée (en utilisant --sign-by, sign-by-sq-fingerprint ou --sign-by-sigstore-private-key), lire la phrase secrète à utiliser depuis le chemin spécifié.

--tls-verify

EXEMPLES

Pousser l'image spécifiée vers un répertoire local :

# podman push imageID dir:/path/to/image

Pousser l'image spécifiée vers un répertoire local au format OCI :

# podman push imageID oci-archive:/path/to/layout:image:tag

Pousser l'image spécifiée vers un registre de conteneurs :

# podman push imageID docker://registry.example.com/repository:tag

Pousser l'image spécifiée vers un registre de conteneurs et enregistrer le digest dans le fichier spécifié :

# podman push --digestfile=/tmp/mydigest imageID docker://registry.example.com/repository:tag

Pousser l'image spécifiée dans le store de conteneurs du démon Docker local :

# podman push imageID docker-daemon:image:tag

Pousser l'image spécifiée avec un nom d'image différent en utilisant les identifiants d'un chemin d'authentification alternatif :

# podman push --authfile temp-auths/myauths.json alpine docker://docker.io/umohnani/alpine
