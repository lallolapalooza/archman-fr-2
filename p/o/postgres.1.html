NOM

postgres - serveur de base de données PostgreSQL

SYNTAXE

postgres [option...]

DESCRIPTION

postgres est le serveur de base de données PostgreSQL. Pour qu'une application cliente puisse accéder à une base de données, elle se connecte (via le réseau ou localement) à une instance postgres en cours d'exécution. L'instance postgres démarre alors un processus serveur séparé pour gérer la connexion.

Une instance postgres gère toujours les données d'un cluster de bases de données unique. Un cluster de bases de données est une collection de bases de données stockées dans un emplacement commun du système de fichiers (la « zone de données »). Plus d'une instance postgres peut être exécutée sur un système à la fois, à condition qu'elles utilisent des zones de données et des ports de communication différents (voir ci-dessous). Lorsque postgres démarre, il doit connaître l'emplacement de la zone de données. L'emplacement doit être spécifié par l'option -D ou la variable d'environnement PGDATA ; il n'y a pas de valeur par défaut. Typiquement, -D ou PGDATA pointe directement vers le répertoire de la zone de données créé par initdb(1). D'autres dispositions de fichiers possibles sont discutées dans la Section 19.2.

Par défaut, postgres démarre au premier plan et imprime les messages de journalisation sur le flux d'erreur standard. Dans les applications pratiques, postgres doit être démarré comme un processus d'arrière-plan, peut-être au démarrage du système.

La commande postgres peut également être appelée en mode mono-utilisateur. L'utilisation principale de ce mode est lors de l'amorçage par initdb(1). Parfois, il est utilisé pour le débogage ou la récupération après sinistre ; notez qu'exécuter un serveur mono-utilisateur n'est pas vraiment adapté au débogage du serveur, car aucune communication interprocessus et aucun verrouillage réaliste ne se produiront. Lorsqu'il est invoqué en mode mono-utilisateur depuis le shell, l'utilisateur peut entrer des requêtes et les résultats seront imprimés à l'écran, mais sous une forme plus utile pour les développeurs que pour les utilisateurs finaux. En mode mono-utilisateur, l'utilisateur de la session sera défini sur l'utilisateur avec l'ID 1, et des pouvoirs de superutilisateur implicites sont accordés à cet utilisateur. Cet utilisateur n'a pas besoin d'exister, de sorte que le mode mono-utilisateur peut être utilisé pour récupérer manuellement certains types de dommages accidentels aux catalogues système.

OPTIONS

postgres accepte les arguments de ligne de commande suivants. Pour une discussion détaillée des options, consultez le Chapitre 19. Vous pouvez éviter de taper la plupart de ces options en configurant un fichier de configuration. Certaines options (sûres) peuvent également être définies à partir du client connecté d'une manière dépendant de l'application pour s'appliquer uniquement à cette session. Par exemple, si la variable d'environnement PGOPTIONS est définie, les clients basés sur libpq passeront cette chaîne au serveur, qui l'interprétera comme des options de ligne de commande postgres.

Objectif général

-B nbuffers

Définit le nombre de tampons partagés à utiliser par les processus serveur. La valeur par défaut de ce paramètre est choisie automatiquement par initdb. La spécification de cette option équivaut à définir le paramètre de configuration shared_buffers.

-c nom=valeur

Définit un paramètre d'exécution nommé. Les paramètres de configuration pris en charge par PostgreSQL sont décrits au Chapitre 19. La plupart des autres options de ligne de commande sont en fait des formes courtes d'une telle affectation de paramètre. -c peut apparaître plusieurs fois pour définir plusieurs paramètres.

-C nom

Imprime la valeur du paramètre d'exécution nommé et quitte. (Voir l'option -c ci-dessus pour plus de détails.) Ceci renvoie les valeurs de postgresql.conf, modifiées par tous les paramètres fournis dans cette invocation. Il ne reflète pas les paramètres fournis lors du démarrage du cluster.

Cela peut être utilisé sur un serveur en cours d'exécution pour la plupart des paramètres. Cependant, le serveur doit être arrêté pour certains paramètres calculés à l'exécution (par exemple, shared_memory_size, shared_memory_size_in_huge_pages et wal_segment_size).

Cette option est destinée à d'autres programmes qui interagissent avec une instance de serveur, tels que pg_ctl(1), pour interroger les valeurs des paramètres de configuration. Les applications destinées aux utilisateurs devraient plutôt utiliser SHOW ou la vue pg_settings.

-d niveau-debug

Définit le niveau de débogage. Plus cette valeur est élevée, plus la sortie de débogage est écrite dans le journal du serveur. Les valeurs vont de 1 à 5. Il est également possible de passer -d 0 pour une session spécifique, ce qui empêchera le niveau de journalisation du serveur du processus postgres parent d'être propagé à cette session.

-D datadir

Spécifie l'emplacement du système de fichiers des fichiers de configuration de la base de données. Voir la Section 19.2 pour plus de détails.

-e

Définit le style de date par défaut sur « Européen », c'est-à-dire l'ordre DMJ pour les champs de date en entrée. Cela provoque également l'impression du jour avant le mois dans certains formats de sortie de date. Voir la Section 8.5 pour plus d'informations.

-F

Désactive les appels fsync pour améliorer les performances, au risque de corruption des données en cas de crash du système. La spécification de cette option équivaut à désactiver le paramètre de configuration fsync. Lisez la documentation détaillée avant d'utiliser ceci !

-h nomhote

Spécifie le nom d'hôte IP ou l'adresse sur laquelle postgres doit écouter les connexions TCP/IP des applications clientes. La valeur peut également être une liste d'adresses séparées par des virgules, ou * pour spécifier l'écoute sur toutes les interfaces disponibles. Une valeur vide spécifie de ne pas écouter sur aucune adresse IP, auquel cas seuls les sockets de domaine Unix peuvent être utilisés pour se connecter au serveur. Par défaut, l'écoute se fait uniquement sur localhost. La spécification de cette option équivaut à définir le paramètre de configuration listen_addresses.

-i

Permet aux clients distants de se connecter via des connexions TCP/IP (domaine Internet). Sans cette option, seules les connexions locales sont acceptées. Cette option équivaut à définir listen_addresses sur * dans postgresql.conf ou via -h.

Cette option est obsolète car elle ne permet pas d'accéder à toutes les fonctionnalités de listen_addresses. Il est généralement préférable de définir listen_addresses directement.

-k répertoire

Spécifie le répertoire du socket de domaine Unix sur lequel postgres doit écouter les connexions des applications clientes. La valeur peut également être une liste de répertoires séparés par des virgules. Une valeur vide spécifie de ne pas écouter sur aucun socket de domaine Unix, auquel cas seuls les sockets TCP/IP peuvent être utilisés pour se connecter au serveur. La valeur par défaut est normalement /tmp, mais cela peut être modifié au moment de la compilation. La spécification de cette option équivaut à définir le paramètre de configuration unix_socket_directories.

-l

Active les connexions sécurisées à l'aide de SSL. PostgreSQL doit avoir été compilé avec la prise en charge de SSL pour que cette option soit disponible. Pour plus d'informations sur l'utilisation de SSL, référez-vous à la Section 18.9.

-N max-connexions

Définit le nombre maximum de connexions clientes que ce serveur acceptera. La valeur par défaut de ce paramètre est choisie automatiquement par initdb. La spécification de cette option équivaut à définir le paramètre de configuration max_connections.

-p port

Spécifie le port TCP/IP ou l'extension de fichier de socket de domaine Unix local sur lequel postgres doit écouter les connexions des applications clientes. Par défaut, utilise la valeur de la variable d'environnement PGPORT, ou si PGPORT n'est pas définie, utilise la valeur établie lors de la compilation (normalement 5432). Si vous spécifiez un port autre que le port par défaut, toutes les applications clientes devront spécifier le même port en utilisant soit des options de ligne de commande, soit PGPORT.

-s

Imprime des informations temporelles et d'autres statistiques à la fin de chaque commande. Ceci est utile pour les benchmarks ou pour l'ajustement du nombre de tampons.

-S memoire-travail

Spécifie la quantité de mémoire de base à utiliser par les tris et les tables de hachage avant de recourir à des fichiers disque temporaires. Voir la description du paramètre de configuration work_mem dans la Section 19.4.1.

-V

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

--version

Affiche la version de postgres et quitte.

--name=value

Définit un paramètre d'exécution nommé ; une forme abrégée de -c.

--describe-config

Cette option affiche les variables de configuration internes du serveur, leurs descriptions et leurs valeurs par défaut au format COPY délimité par des tabulations. Elle est principalement destinée à être utilisée par les outils d'administration.

-?
--help

Affiche l'aide sur les arguments de ligne de commande de postgres et quitte.

Options semi-internes

Les options décrites ici sont principalement utilisées à des fins de débogage, et dans certains cas pour aider à la récupération de bases de données gravement endommagées. Il ne devrait y avoir aucune raison de les utiliser dans une configuration de base de données en production. Elles sont listées ici uniquement pour être utilisées par les développeurs du système PostgreSQL. De plus, ces options pourraient changer ou être supprimées dans une future version sans préavis.

-f { s | i | o | b | t | n | m | h }

Interdit l'utilisation de méthodes d'analyse et de jointure particulières : s et i désactivent respectivement les analyses séquentielles et par index, o, b et t désactivent respectivement les analyses index uniquement, les analyses d'index bitmap et les analyses TID, tandis que n, m et h désactivent respectivement les jointures imbriquées, les jointures par fusion et les jointures par hachage.

Ni les analyses séquentielles ni les jointures imbriquées ne peuvent être complètement désactivées ; les options -fs et -fn découragent simplement l'optimiseur d'utiliser ces types de plans s'il a une autre alternative.

-O

Permet de modifier la structure des tables système. Ceci est utilisé par initdb.

-P

Ignore les index système lors de la lecture des tables système, mais met toujours à jour les index lors de la modification des tables. Ceci est utile lors de la récupération d'index système endommagés.

-t pa[rser] | pl[anner] | e[xecutor]

Affiche des statistiques de temps pour chaque requête relatives à chacun des principaux modules système. Cette option ne peut pas être utilisée conjointement avec l'option -s.

-T

Cette option est destinée au débogage des problèmes qui entraînent la mort anormale d'un processus serveur. La stratégie habituelle dans cette situation est de notifier tous les autres processus serveur qu'ils doivent se terminer, en leur envoyant des signaux SIGQUIT. Avec cette option, SIGABRT sera envoyé à la place, ce qui entraînera la production de fichiers core dump.

-v protocole

Spécifie le numéro de version du protocole frontend/backend à utiliser pour une session particulière. Cette option est réservée à un usage interne.

-W secondes

Un délai de ce nombre de secondes se produit lorsqu'un nouveau processus serveur est démarré, après qu'il ait effectué la procédure d'authentification. Ceci est destiné à donner une opportunité de se connecter au processus serveur avec un débogueur.

Options pour le mode monosuppeur

Les options suivantes ne s'appliquent qu'au mode monosuppeur (voir Mode monosuppeur ci-dessous).

--single

Sélectionne le mode monosuppeur. Ce doit être le premier argument sur la ligne de commande.

database

Spécifie le nom de la base de données à laquelle accéder. Ce doit être le dernier argument sur la ligne de commande. S'il est omis, il prend par défaut le nom de l'utilisateur.

-E

Écho de toutes les commandes sur la sortie standard avant de les exécuter.

-j

Utilise le point-virgule suivi de deux sauts de ligne, plutôt qu'un simple saut de ligne, comme terminateur d'entrée de commande.

-r filename

Envoie toutes les sorties de journal du serveur vers filename. Cette option n'est honorée que lorsqu'elle est fournie en tant qu'argument de ligne de commande.

ENVIRONNEMENT

PGCLIENTENCODING

Encodage de caractères par défaut utilisé par les clients. (Les clients peuvent le remplacer individuellement.) Cette valeur peut également être définie dans le fichier de configuration.

PGDATA

Emplacement par défaut du répertoire de données

PGDATESTYLE

Valeur par défaut du paramètre d'exécution DateStyle. (L'utilisation de cette variable d'environnement est déconseillée.)

PGPORT

Numéro de port par défaut (de préférence défini dans le fichier de configuration)

DIAGNOSTICS

Un message d'échec mentionnant semget ou shmget indique probablement que vous devez configurer votre noyau pour fournir suffisamment de mémoire partagée et de sémaphores. Pour plus de détails, voir la Section 18.4. Vous pourriez être en mesure de reporter la reconfiguration de votre noyau en diminuant shared_buffers pour réduire la consommation de mémoire partagée de PostgreSQL, et/ou en réduisant max_connections pour réduire la consommation de sémaphores.

Un message d'échec suggérant qu'un autre serveur est déjà en cours d'exécution doit être vérifié attentivement, par exemple en utilisant la commande

$ ps ax | grep postgres

ou

$ ps -ef | grep postgres

selon votre système. Si vous êtes certain qu'aucun serveur conflictuel n'est en cours d'exécution, vous pouvez supprimer le fichier de verrouillage mentionné dans le message et réessayer.

Un message d'échec indiquant l'impossibilité de se lier à un port peut indiquer que ce port est déjà utilisé par un processus autre que PostgreSQL. Vous pourriez également obtenir cette erreur si vous terminez postgres et le redémarrez immédiatement en utilisant le même port ; dans ce cas, vous devez simplement attendre quelques secondes jusqu'à ce que le système d'exploitation ferme le port avant de réessayer. Enfin, vous pourriez obtenir cette erreur si vous spécifiez un numéro de port que votre système d'exploitation considère comme réservé. Par exemple, de nombreuses versions d'Unix considèrent les numéros de port inférieurs à 1024 comme « fiables » et ne permettent qu'au superutilisateur Unix d'y accéder.

NOTES

L'utilitaire pg_ctl(1) peut être utilisé pour démarrer et arrêter le serveur postgres de manière sûre et confortable.

Si possible, n'utilisez pas SIGKILL pour tuer le serveur principal postgres. Le faire empêchera postgres de libérer les ressources système (par exemple, la mémoire partagée et les sémaphores) qu'il détient avant de se terminer. Cela pourrait causer des problèmes lors du démarrage d'une nouvelle instance de postgres.

Pour terminer le serveur postgres normalement, les signaux SIGTERM, SIGINT ou SIGQUIT peuvent être utilisés. Le premier attendra que tous les clients se terminent avant de quitter, le second déconnectera de force tous les clients, et le troisième quittera immédiatement sans nettoyage normal, ce qui entraînera une exécution de récupération lors du redémarrage.

Le signal SIGHUP rechargera les fichiers de configuration du serveur. Il est également possible d'envoyer SIGHUP à un processus serveur individuel, mais ce n'est généralement pas judicieux.

Pour annuler une requête en cours, envoyez le signal SIGINT au processus exécutant cette commande. Pour terminer un processus backend proprement, envoyez SIGTERM à ce processus. Voir également pg_cancel_backend et pg_terminate_backend dans la Section 9.28.2 pour les équivalents appelables en SQL de ces deux actions.

Le serveur postgres utilise SIGQUIT pour indiquer aux processus serveurs subordonnés de se terminer sans nettoyage normal. Ce signal ne doit pas être utilisé par les utilisateurs. Il est également déconseillé d'envoyer SIGKILL à un processus serveur — le processus principal postgres interprétera cela comme un crash et forcera tous les processus frères à quitter dans le cadre de sa procédure standard de récupération de crash.

BOGUES

Les options -- ne fonctionneront pas sur FreeBSD ou OpenBSD. Utilisez -c à la place. C'est un bug dans les systèmes d'exploitation concernés ; une future version de PostgreSQL fournira une solution de contournement si cela n'est pas corrigé.

MODE MONOSUPPEUR

Pour démarrer un serveur en mode monosuppeur, utilisez une commande telle que

postgres --single -D /usr/local/pgsql/data autres-options ma_base

Fournissez le chemin correct vers le répertoire de la base de données avec -D, ou assurez-vous que la variable d'environnement PGDATA est définie. Spécifiez également le nom de la base de données particulière dans laquelle vous souhaitez travailler.

Normalement, le serveur en mode monosuppeur traite le saut de ligne comme le terminateur d'entrée de commande ; il n'y a pas d'intelligence concernant les points-virgules, comme c'est le cas dans psql. Pour continuer une commande sur plusieurs lignes, vous devez taper une barre oblique inverse juste avant chaque saut de ligne sauf le dernier. La barre oblique inverse et le saut de ligne adjacent sont tous deux supprimés de la commande d'entrée. Notez que cela se produira même à l'intérieur d'une chaîne de caractères littérale ou d'un commentaire.

Mais si vous utilisez le commutateur de ligne de commande -j, un seul saut de ligne ne termine pas l'entrée de commande ; au lieu de cela, la séquence point-virgule-saut de ligne-saut de ligne le fait. C'est-à-dire, tapez un point-virgule suivi immédiatement d'une ligne complètement vide. La barre oblique inverse-saut de ligne n'est pas traitée spécialement dans ce mode. Encore une fois, il n'y a pas d'intelligence concernant une telle séquence apparaissant dans une chaîne littérale ou un commentaire.

Dans les deux modes d'entrée, si vous tapez un point-virgule qui n'est pas juste avant ou dans le cadre d'un terminateur d'entrée de commande, il est considéré comme un séparateur de commande. Lorsque vous tapez un terminateur d'entrée de commande, les commandes multiples que vous avez entrées seront exécutées comme une seule transaction.

Pour quitter la session, tapez EOF (Control+D, généralement). Si vous avez entré du texte depuis le dernier terminateur d'entrée de commande, alors EOF sera pris comme un terminateur d'entrée de commande, et un autre EOF sera nécessaire pour quitter.

Notez que le serveur en mode monosuppeur ne fournit pas de fonctionnalités d'édition de ligne sophistiquées (pas d'historique de commandes, par exemple). Le mode monosuppeur ne fait pas non plus de traitement en arrière-plan, comme des points de contrôle automatiques ou de la réplication.

EXEMPLES

Pour démarrer postgres en arrière-plan en utilisant les valeurs par défaut, tapez :

$ nohup postgres >logfile 2>&1 </dev/null &

Pour démarrer postgres avec un port spécifique, par exemple 1234 :

$ postgres -p 1234

Pour se connecter à ce serveur en utilisant psql, spécifiez ce port avec l'option -p :

$ psql -p 1234

ou définissez la variable d'environnement PGPORT :

$ export PGPORT=1234
$ psql

Les paramètres nommés d'exécution peuvent être définis dans l'un ou l'autre de ces styles :

$ postgres -c work_mem=1234
$ postgres --work-mem=1234

L'une ou l'autre forme remplace tout réglage qui pourrait exister pour work_mem dans postgresql.conf. Notez que les traits de soulignement dans les noms de paramètres peuvent être écrits comme des traits de soulignement ou des tirets sur la ligne de commande. Sauf pour les expériences à court terme, il est probablement préférable de modifier le réglage dans postgresql.conf plutôt que de s'appuyer sur un commutateur de ligne de commande pour définir un paramètre.
