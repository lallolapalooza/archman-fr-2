NOM

podman-network-create - Crée un réseau Podman

SYNTAXE

podman network create [options] [nom]

DESCRIPTION

Crée une configuration réseau à utiliser avec Podman. Par défaut, Podman crée une connexion de type bridge. Une connexion Macvlan peut être créée avec l'option -d macvlan. Un périphérique parent pour macvlan ou ipvlan peut être désigné avec l'option -o parent=<périphérique> ou --network-interface=<périphérique>.

Si aucune option n'est fournie, Podman attribue un sous-réseau et un nom libres pour le réseau.

Une fois la création du réseau terminée, Podman affiche le nom du réseau nouvellement ajouté.

OPTIONS

--disable-dns

Désactive le plugin DNS pour ce réseau, qui s'il est activé, peut résoudre les noms de conteneur à conteneur. Il n'est pris en charge qu'avec le pilote bridge, pour les autres pilotes il est toujours désactivé.

--dns=ip

Définit le résolveur DNS / serveur de noms à l'échelle du réseau pour les conteneurs de ce réseau. S'il n'est pas défini, les serveurs de l'hôte provenant de /etc/resolv.conf sont utilisés. Il peut être remplacé au niveau du conteneur avec l'option podman run/create --dns. Cette option peut être spécifiée plusieurs fois pour définir plus d'une adresse IP.

--driver, -d=pilote

Pilote pour gérer le réseau. Actuellement, bridge, macvlan et ipvlan sont pris en charge. Par défaut, bridge. En mode sans privilèges (rootless), les pilotes macvlan et ipvlan n'ont pas accès aux interfaces réseau de l'hôte car le réseau sans privilèges nécessite un espace de noms réseau séparé.

Le backend netavark permet l'utilisation de ce que l'on appelle des plugins netavark, voir la documentation plugin-API.md dans netavark. Le binaire doit être placé dans un répertoire spécifié afin que podman puisse le découvrir. Cette liste est définie dans netavark_plugin_dirs dans containers.conf(5) sous la section [network].

Le nom du plugin peut alors être utilisé comme pilote pour créer un réseau pour votre plugin. La liste de tous les pilotes et plugins pris en charge peut être consultée avec podman info --format {{.Plugins.Network}}.

Notez que les pilotes macvlan et ipvlan ne prennent pas en charge la redirection de ports. La prise en charge de la redirection de ports avec un plugin dépend de l'implémentation du plugin.

--gateway=ip

Définit une passerelle pour le sous-réseau. Pour fournir une adresse de passerelle, une option subnet est requise. Peut être spécifié plusieurs fois. L'ordre des arguments des options --subnet, --gateway et --ip-range doit correspondre.

--ignore

Ignore la demande de création si un réseau portant le même nom existe déjà, au lieu d'échouer. Notez que tenter de créer un réseau avec un nom existant et des paramètres différents ne modifie pas la configuration de celui existant.

--interface-name=nom

Cette option mappe l'option network_interface dans la configuration réseau, voir podman network inspect. Selon le pilote, cela peut avoir des effets différents ; pour bridge, elle utilise le nom de l'interface bridge. Pour macvlan et ipvlan, il s'agit du périphérique parent sur l'hôte. C'est la même chose que --opt parent=....

--internal

Restreint l'accès externe de ce réseau lors de l'utilisation d'un réseau bridge. Notez que lors de l'utilisation du backend CNI, DNS sera automatiquement désactivé, voir --disable-dns.

Lors de l'utilisation des pilotes macvlan ou ipvlan avec cette option, aucune route par défaut ne sera ajoutée au conteneur. Comme cela contourne la pile réseau de l'hôte, aucune restriction supplémentaire ne peut être définie par Podman et si un conteneur privilégié est lancé, il peut définir lui-même une route par défaut. Si cela pose problème, les connexions des conteneurs doivent être bloquées sur votre passerelle réseau réelle.

L'utilisation du pilote bridge avec cette option a les effets suivants :
- Les sysctls de transfert IP globaux ne seront pas modifiés dans l'espace de noms réseau de l'hôte.
- Le transfert IP est désactivé sur l'interface bridge au lieu de configurer un pare-feu.
- Aucune route par défaut ne sera ajoutée au conteneur.

Dans tous les cas, aardvark-dns ne résoudra que les noms de conteneurs avec cette option activée. Les autres requêtes répondront par NXDOMAIN.

--ip-range=plage

Alloue une adresse IP de conteneur à partir d'une plage. La plage doit être soit un sous-réseau complet en notation CIDR, soit dans la syntaxe <IPdébut>-<IPfin>, ce qui permet une plage plus flexible que le sous-réseau CIDR. L'option ip-range doit être utilisée avec une option subnet. Peut être spécifiée plusieurs fois. L'ordre des arguments des options --subnet, --gateway et --ip-range doit correspondre.

--ipam-driver=pilote

Définit le pilote IPAM (IP Address Management Driver) pour le réseau. Lorsqu'il n'est pas défini, podman choisit automatiquement un pilote IPAM en fonction du pilote réseau.

Les valeurs valides sont :

  • dhcp : Les adresses IP sont attribuées par un serveur DHCP sur le réseau. Lors de l'utilisation du backend netavark, le netavark-dhcp-proxy.socket doit être activé afin de démarrer le proxy DHCP lors du démarrage d'un conteneur. Pour CNI, utilisez l'unité cni-dhcp.socket à la place.
  • host-local : Les adresses IP sont attribuées localement.
  • none : Aucune adresse IP n'est attribuée aux interfaces.

Affichez le pilote dans la sortie de podman network inspect sous le champ ipam_options.

--ipv6

Active le réseau IPv6 (Double Pile). Si aucun sous-réseau n'est donné, il alloue un sous-réseau IPv4 et un sous-réseau IPv6.

--label=etiquette

Définit les métadonnées d'un réseau (par exemple, --label maccle=valeur).

--opt, -o=option

Définit les options spécifiques au pilote.

Tous les pilotes acceptent les options mtu, metric, no_default_route et d'autres.

  • mtu : Définit l'unité de transmission maximale (MTU) et prend une valeur entière.
  • metric : Définit la métrique de routage pour la route par défaut créée dans chaque conteneur rejoignant ce réseau. Accepte une valeur entière positive. Ne peut être utilisé qu'avec le backend réseau Netavark.
  • no_default_route : Si défini sur 1, Podman n'ajoutera pas automatiquement de route par défaut aux sous-réseaux. Des routes peuvent toujours être ajoutées manuellement en créant une route personnalisée à l'aide de --route.

De plus, le pilote bridge prend en charge les options suivantes :

  • vlan : Cette option attribue une balise VLAN et active le filtrage VLAN. Valeur par défaut : aucune.
  • isolate : Cette option isole les réseaux en bloquant le trafic entre ceux qui ont cette option activée.
  • com.docker.network.bridge.name : Cette option attribue le nom donné au pont Linux créé.
  • com.docker.network.driver.mtu : Définit l'unité de transmission maximale (MTU) et prend une valeur entière.
  • vrf : Cette option attribue une VRF à l'interface bridge. Elle accepte le nom de la VRF et est définie par défaut sur aucune. Ne peut être utilisé qu'avec le backend réseau Netavark.
  • mode : Cette option définit le mode bridge spécifié sur l'interface. Par défaut : managed. Valeurs prises en charge :
  • managed : Podman crée et supprime le pont et modifie ses sysctls. Il ajoute des règles de pare-feu pour masquer le trafic sortant, ainsi que la mise en place de la redirection de ports pour le trafic entrant à l'aide de DNAT.
  • unmanaged : Podman utilise un pont existant. Il doit exister au moment où vous souhaitez démarrer un conteneur qui utilise le réseau. Il n'y aura pas de NAT ni de redirection de ports, même si de telles options ont été passées lors de la création du conteneur.

Les pilotes macvlan et ipvlan prennent en charge les options suivantes :

  • parent : Le périphérique hôte utilisé pour l'interface macvlan. Par défaut, il s'agit de l'interface de routage par défaut.
  • mode : Cette option

NAME

podman-network-create — Create a new network

SYNOPSIS

podman network create [options] [network]

DESCRIPTION

Creates a new Podman network. If no network name is provided, Podman will generate a name for the network.

The network can be configured with the following options.

OPTIONS

--attach-socket=socket

Attach to a network namespace specified by a unix domain socket. This option can be specified multiple times to attach to multiple network namespaces.

--bgp-support

Enable BGP support for the network. Only available with the netavark backend.

--cni-plugin-dir=path

Set the directory that contains the CNI plugin binary files. Defaults to "/usr/lib/cni".

--dns=dns

Set the DNS server to use in the created network.

--dns-opt=dns-opt

Set the DNS option to use in the created network.

--dns-search=dns-search

Set the DNS search domain to use in the created network.

--driver=driver

Set the network driver. Supported drivers: `bridge`, `ipvlan`, `macvlan`, `none`, `rm`.

--domain=domain

Set the DNS domain for the created network.

--gateway=gateway

Set the network gateway address. Can be specified multiple times to set static IPv4 and IPv6 gateways.

--ip-range=ip-range

Set the IP address range for the network in CIDR notation. Can be specified multiple times to set static IPv4 and IPv6 IP ranges.

--ipv6

Enable IPv6 for the network.

--label, -l=label

Add labels to the network.

--macvlan-mode=mode

Set the macvlan mode. Supported modes are: `bridge`, `host-passthrough`, `passthrough`, `private`, `vepa`. Defaults to `bridge`.

--mtu=mtu

Set the MTU for the network. Defaults to the system default MTU.

--name=name

Assign a name to the network. If not provided, a name is generated for the network. This option is deprecated and the network name should be provided as the last argument.

--opt=option

Set network options. This is a list of key-value pairs. Supported options:

  • parent: Set the parent network interface for macvlan and ipvlan. The interface must exist.
  • host: Set the host interface for macvlan. The interface must exist.
  • internal: Create an internal network. Containers connected to an internal network are not reachable from outside the host.
  • ip_range: Set the IP address range for the network in CIDR notation. This option is deprecated, use --ip-range.
  • subnet: Set the subnet for the network in CIDR notation. This option is deprecated, use --subnet.
  • gateway: Set the network gateway. This option is deprecated, use --gateway.
  • aux-addresses: Set additional IP addresses for hosts. The value is a comma-separated list of key=value pairs.
  • ipvlan_mode: Set the ipvlan mode. Supported values for ipvlan are l2, l3, l3s. Defaults to l2.
  • macvlan: Set the specified ip/macvlan mode on the interface.
  • Supported values for macvlan are bridge, private, vepa, passthru. Defaults to bridge.
  • Supported values for ipvlan are l2, l3, l3s. Defaults to l2.

Additionally the macvlan driver supports the bclim option:

•
bclim: Set the threshold for broadcast queueing. Must be a 32 bit integer. Setting this value to -1 disables broadcast queueing altogether.

--route=route

A static route in the format <destination in CIDR notation>,<gateway>,<route metric (optional)>. This route will be added to every container in this network. Only available with the netavark backend. It can be specified multiple times if more than one static route is desired.

--subnet=subnet

The subnet in CIDR notation. Can be specified multiple times to allocate more than one subnet for this network. The argument order of the --subnet, --gateway and --ip-range options must match. This is useful to set a static ipv4 and ipv6 subnet.

EXAMPLES

Create a network with no options.

$ podman network create
podman2

Create a network named newnet that uses 192.5.0.0/16 for its subnet.

$ podman network create --subnet 192.5.0.0/16 newnet
newnet

Create an IPv6 network named newnetv6 with a subnet of 2001:db8::/64.

$ podman network create --subnet 2001:db8::/64 --ipv6 newnetv6
newnetv6

Create a network named newnet that uses 192.168.33.0/24 and defines a gateway as 192.168.33.3.

$ podman network create --subnet 192.168.33.0/24 --gateway 192.168.33.3 newnet
newnet

Create a network that uses a 192.168.55.0/24 subnet and has an IP address range of 192.168.55.129 - 192.168.55.254.

$ podman network create --subnet 192.168.55.0/24 --ip-range 192.168.55.128/25
podman5

Create a network with a static ipv4 and ipv6 subnet and set a gateway.

$ podman network create --subnet 192.168.55.0/24 --gateway 192.168.55.3 --subnet fd52:2a5a:747e:3acd::/64 --gateway fd52:2a5a:747e:3acd::10
podman4

Create a network with a static subnet and a static route.

$ podman network create --subnet 192.168.33.0/24 --route 10.1.0.0/24,192.168.33.10 newnet

Create a network with a static subnet and a static route without a default route.

$ podman network create --subnet 192.168.33.0/24 --route 10.1.0.0/24,192.168.33.10 --opt no_default_route=1 newnet

Create a Macvlan based network using the host interface eth0. Macvlan networks can only be used as root.

$ sudo podman network create -d macvlan -o parent=eth0 --subnet 192.5.0.0/16 newnet
newnet
