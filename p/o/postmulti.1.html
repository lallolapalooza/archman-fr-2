POSTMULTI(1) Manuel des commandes générales POSTMULTI(1)

NOM

postmulti - Gestionnaire d'instances multiples Postfix

SYNOP

Activation de la gestion multi-instances :

postmulti -e init [-v]

Mode itérateur :

postmulti -l [-aRv] [-g groupe] [-i nom]

postmulti -p [-av] [-g groupe] [-i nom] commande-postfix...

postmulti -x [-aRv] [-g groupe] [-i nom] commande-unix...

Gestion du cycle de vie :

postmulti -e create [-av] [-g groupe] [-i nom] [-G groupe] [-I nom] [param=valeur ...]

postmulti -e import [-av] [-g groupe] [-i nom] [-G groupe] [-I nom] [repertoire-config=/chemin]

postmulti -e destroy [-v] -i nom

postmulti -e deport [-v] -i nom

postmulti -e enable [-v] -i nom

postmulti -e disable [-v] -i nom

postmulti -e assign [-v] -i nom [-I nom] [-G groupe]

DESCRIPTION


postmulti(1) permet à un administrateur Postfix de gérer plusieurs instances Postfix sur un même hôte.

postmulti(1) implémente deux modes de fonctionnement fondamentaux. En mode itérateur, il exécute la même commande pour plusieurs instances Postfix. En mode gestion du cycle de vie, il ajoute ou supprime une instance, ou modifie le statut multi-instance d'une instance.

Chaque mode de fonctionnement a sa propre syntaxe de commande. Pour cette raison, chaque mode est documenté dans des sections séparées ci-dessous.

CONTEXTE

Une configuration multi-instances se compose d'une instance Postfix principale et d'une ou plusieurs instances secondaires dont les noms de chemin des répertoires de configuration sont enregistrés dans le fichier main.cf de l'instance principale. Les instances Postfix partagent les fichiers de programmes et la documentation, mais ont leurs propres répertoires de configuration, de file d'attente et de données.

Actuellement, seule l'instance Postfix par défaut peut être utilisée comme instance principale dans une configuration multi-instances. La commande postmulti(1) ne prend pas en charge l'option -c pour sélectionner une instance principale alternative et se termine avec une erreur fatale si la variable d'environnement MAIL_CONFIG est définie sur un répertoire de configuration non-défaut.

Consultez le tutoriel MULTI_INSTANCE_README pour une discussion plus détaillée de la gestion multi-instances avec postmulti(1).

MODE ITérateur

En mode itérateur, postmulti effectue la même opération sur toutes les instances Postfix l'une après l'autre.

Si le support multi-instances n'est pas activé, la commande demandée n'est effectuée que pour l'instance principale.

Le mode itérateur implémente les options de commande suivantes :

Sélection d'une instance

-a
Effectuer l'opération sur toutes les instances. C'est le comportement par défaut.
-g groupe
Effectuer l'opération uniquement pour les membres du groupe nommé.
-i nom
Effectuer l'opération uniquement pour l'instance portant le nom spécifié. Vous pouvez spécifier soit le nom de l'instance, soit le chemin absolu du répertoire de configuration de l'instance. Spécifiez "-" pour sélectionner l'instance Postfix principale.
-R
Inverser l'ordre d'itération. Ceci peut être approprié lors de la mise à jour d'un système multi-instances, où les instances "sinks" sont démarrées avant les instances "sources".

Cette option ne peut pas être utilisée avec -p.

Mode liste

-l
Lister les instances Postfix avec leur nom d'instance, leur nom de groupe d'instance, leur statut activé/désactivé et leur répertoire de configuration.

Mode enveloppe-postfix

-p commande-postfix
Invoquer postfix(1) pour exécuter commande-postfix. Cette option implémente l'interface de postfix-wrapper(5).
  • Avec les commandes de type "start", "postfix check" est exécuté pour les instances qui ne sont pas activées. La liste complète des commandes est spécifiée avec le paramètre postmulti_start_commands.
  • Avec les commandes de type "stop", l'ordre d'itération est inversé et les instances désactivées sont ignorées. La liste complète des commandes est spécifiée avec le paramètre postmulti_stop_commands.
  • Avec "reload" et d'autres commandes qui nécessitent une instance démarrée, les instances désactivées sont ignorées. La liste complète des commandes est spécifiée avec le paramètre postmulti_control_commands.
  • Avec "status" et d'autres commandes qui ne nécessitent pas une instance démarrée, la commande est exécutée pour toutes les instances.
L'option -p peut également être utilisée interactivement pour démarrer/arrêter/etc. une instance nommée ou un groupe d'instances. Par exemple, pour démarrer uniquement les instances du groupe "msa", invoquez postmulti(1) comme suit :
# postmulti -g msa -p start

Mode commande

-x commande-unix
Exécute la commande-unix spécifiée pour toutes les instances Postfix. La commande s'exécute avec les paramètres d'environnement appropriés pour MAIL_CONFIG, command_directory, daemon_directory, config_directory, queue_directory, data_directory, multi_instance_name, multi_instance_group et multi_instance_enable.

Autres options

-v
Active la journalisation détaillée à des fins de débogage. Plusieurs options -v rendent le logiciel de plus en plus verbeux.

MODE GESTION DU CYCLE DE VIE

Avec l'option -e, postmulti(1) peut être utilisé pour ajouter ou supprimer une instance Postfix, et pour gérer le statut multi-instance d'une instance existante.

Les options suivantes sont implémentées :

Sélection d'une instance existante

-a
Lors de la création ou de l'importation d'une instance, placez la nouvelle instance au début de la liste des instances secondaires.
-g groupe
Lors de la création ou de l'importation d'une instance, placez la nouvelle instance avant la première instance secondaire qui est membre du groupe spécifié.
-i nom
Lors de la création ou de l'importation d'une instance, placez la nouvelle instance avant l'instance secondaire correspondante.

Avec d'autres opérations de cycle de vie, appliquez l'opération à l'instance existante nommée. Spécifiez "-" pour sélectionner l'instance Postfix principale.

Nom et assignation d'une instance nouvelle ou existante

-I nom
Assigner un nouveau nom d'instance à l'instance en cours de création ou d'importation. Si vous ne spécifiez pas ce paramètre, le nom d'instance par défaut est "instance". Pour les opérations d'assignation, c'est le nom d'instance existant à modifier.
-G groupe
Assigner un nom de groupe d'instance à l'instance en cours de création ou d'importation. Si vous ne spécifiez pas ce paramètre, le nom de groupe par défaut est "default". Pour les opérations d'assignation, c'est le nom de groupe existant à modifier.

Opérations sur le cycle de vie

create
Crée une nouvelle instance Postfix avec le nom d'instance et le nom de groupe d'instance spécifiés. S'ils ne sont pas spécifiés, les valeurs par défaut "instance" et "default" sont utilisées. Le chemin du répertoire de configuration est dérivé du nom d'instance.
L'option -a place la nouvelle instance au début de la liste des instances secondaires. L'option -g place la nouvelle instance avant la première instance du groupe spécifié. L'option -i place la nouvelle instance avant l'instance spécifiée.
Les paramètres param=valeur peuvent être utilisés pour spécifier des valeurs initiales pour les paramètres de configuration Postfix.
Exemple :
# postmulti -i myinstance -G mygroup -e create
import
Importe une instance Postfix existante dans la gestion multi-instances. Le répertoire de configuration de l'instance à importer doit être spécifié avec le paramètre config_directory. L'instance est ajoutée à la fin de la liste des instances secondaires, sauf si les options -a, -g ou -i sont utilisées pour spécifier son emplacement.
Exemple :
# postmulti -i altinstance -e import config_directory=/etc/postfix-alt
destroy
Supprime une instance Postfix existante de la gestion multi-instances. L'instance est retirée de la liste des instances secondaires.
Exemple :
# postmulti -i myinstance -e destroy
deport
Retire une instance Postfix existante de la gestion multi-instances sans la supprimer. L'instance est retirée de la liste des instances secondaires.
Exemple :
# postmulti -i myinstance -e deport
enable
Active une instance Postfix existante pour qu'elle participe aux opérations multi-instances.
Exemple :
# postmulti -i myinstance -e enable
disable
Désactive une instance Postfix existante afin qu'elle n'ait pas à participer aux opérations multi-instances.
Exemple :
# postmulti -i myinstance -e disable
assign
Modifie le nom d'instance ou le nom de groupe d'une instance existante.
Exemple pour changer le nom d'instance :
# postmulti -i oldname -e assign -I newname
Exemple pour changer le nom de groupe :
# postmulti -i myinstance -e assign -G mygroup

ÉTAT DE SORTIE

Renvoie 0 en cas de succès. Une valeur différente de zéro indique une erreur.


CONFIGURATION

Les informations sur les instances multiples sont stockées dans le fichier main.cf de l'instance Postfix principale (par défaut "/etc/postfix/main.cf"). La directive postfix_instance_directories définit les répertoires de configuration des instances secondaires.

Le fichier main.cf peut également contenir la directive postfix_instance_groups pour attribuer des instances à des groupes.

DIAGNOSTICS

Les messages de journalisation sont envoyés à syslogd et/ou à la sortie d'erreur standard. Les erreurs sont signalées sous forme de messages de statut non nul.

"I">-I nom
Attribue le nom d'instance spécifié nom à une instance existante, nouvellement créée ou importée. Les noms d'instance autres que "-" (qui rend l'instance "sans nom") doivent commencer par "postfix-". Cette restriction réduit la probabilité de conflits de noms avec les fichiers système.
-G groupe
Attribue le nom de groupe spécifié groupe à une instance existante ou à une instance nouvellement créée ou importée.

Création/suppression/changement d'état d'instance

-e action
"Éditer" les instances gérées. Les actions suivantes sont prises en charge :
init
Cette commande est requise avant que postmulti(1) puisse être utilisé pour gérer les instances Postfix. La commande "postmulti -e init" met à jour le fichier main.cf de l'instance principale en définissant :
multi_instance_wrapper =
        ${command_directory}/postmulti -p --
multi_instance_enable = yes
Vous pouvez définir ces paramètres par d'autres moyens si vous préférez.
create
Crée une nouvelle instance Postfix et l'ajoute au paramètre multi_instance_directories de l'instance principale. L'option "-Inom" est recommandée pour donner à l'instance un nom court qui est utilisé pour construire des valeurs par défaut pour les répertoires privés de la nouvelle instance. L'option "-Ggroupe" peut être spécifiée pour attribuer l'instance à un groupe, sinon la nouvelle instance n'appartient à aucun groupe.

Le fichier main.cf de la nouvelle instance est le fichier main.cf standard avec les paramètres qui spécifient les emplacements des fichiers partagés clonés à partir de l'instance principale. Pour les instances "sans nom", vous devez ajuster manuellement "syslog_name" pour obtenir un "logtag" unique commençant par "postfix-" qui identifiera de manière unique l'instance dans les journaux de courrier. Il est plus simple d'attribuer un nom court à l'instance avec l'option "-Inom".

Les arguments optionnels "nom=valeur" spécifient le répertoire de configuration, le répertoire de file d'attente et le répertoire de données de l'instance. Par exemple :

# postmulti -I postfix-mumble \
        -G mygroup -e create \
        config_directory=/my/config/dir \
        queue_directory=/my/queue/dir \
        data_directory=/my/data/dir
Si l'un de ces noms de chemin n'est pas fourni, le programme tente de générer les noms de chemin manquants en prenant le chemin de l'instance principale correspondant, et en remplaçant le dernier composant du chemin par la valeur de l'option -I.

Si le répertoire de configuration de l'instance existe déjà et contient un fichier main.cf et un fichier master.cf, create "importera" l'instance telle quelle. Pour les instances existantes, create et import sont identiques.

import
Importe une instance existante dans la liste des instances gérées par le gestionnaire multi-instance postmulti(1). Cela ajoute l'instance à la liste multi_instance_directories de l'instance principale. Si l'option "-Inom" est fournie, elle spécifie le nouveau nom de l'instance et est utilisée pour définir un emplacement par défaut pour le répertoire de configuration de l'instance (comme avec create ci-dessus). L'option "-Ggroupe" peut être utilisée pour attribuer l'instance à un groupe. Ajoutez un argument "config_directory=/chemin" pour remplacer un nom de chemin par défaut basé sur "-Inom".
destroy
Supprime une instance Postfix secondaire. Pour être candidate à la suppression, une instance doit être désactivée, arrêtée et sa file d'attente ne doit contenir aucun message. Les tentatives de suppression de l'instance Postfix principale déclenchent une erreur fatale, sans détruire l'instance.

L'instance est retirée du paramètre alternate_config_directories du fichier main.cf de l'instance principale et ses répertoires de données, de file d'attente et de configuration sont nettoyés des fichiers et répertoires créés par le système Postfix. Les fichiers main.cf et master.cf sont retirés du répertoire de configuration même s'ils ont été modifiés depuis leur création initiale. Enfin, l'instance est "déportée" de la liste des instances gérées.

Si d'autres fichiers sont présents dans les répertoires privés de l'instance, les répertoires peuvent ne pas être entièrement supprimés, un avertissement est enregistré pour alerter l'administrateur. Il est attendu qu'une instance créée à l'aide de répertoires "frais" via l'action create sera entièrement supprimée par l'action destroy (si d'abord désactivée). Si les répertoires de configuration et de file d'attente de l'instance sont remplis de fichiers supplémentaires (tables d'accès et de réécriture, contenu de jail chroot, etc.), les répertoires de l'instance ne seront pas entièrement supprimés.

L'action destroy déclenche des opérations de suppression de fichiers potentiellement dangereuses. Assurez-vous que les répertoires de données, de file d'attente et de configuration de l'instance sont correctement définis et ne contiennent aucun fichier précieux.

deport
Déporte une instance secondaire de la liste des instances gérées. Cela supprime le répertoire de configuration de l'instance de la liste multi_instance_directories de l'instance principale, mais ne supprime aucun fichier ou répertoire.
assign
Attribue un nouveau nom d'instance ou un nouveau nom de groupe à l'instance sélectionnée. Utilisez "-G -" pour spécifier "aucun groupe" et "-I -" pour spécifier "aucun nom". Si vous choisissez de rendre une instance "sans nom", définissez un syslog_name approprié dans le fichier main.cf correspondant.
enable
Marque l'instance sélectionnée comme activée. Cela définit simplement le paramètre multi_instance_enable sur "yes" dans le fichier main.cf de l'instance.
disable
Marque l'instance sélectionnée comme désactivée. Cela signifie que l'instance ne sera pas démarrée, etc., avec "postfix start", "postmulti -p start" et ainsi de suite. L'instance peut toujours être démarrée, etc., avec "postfix -c config-directory start".

Autres options

-v
Active la journalisation détaillée à des fins de débogage. Plusieurs options -v rendent le logiciel de plus en plus verbeux.

ENVIRONNEMENT

La commande postmulti(1) exporte les variables d'environnement suivantes avant d'exécuter la commande demandée pour une instance donnée :

MAIL_VERBOSE
Ceci est défini lorsque l'option de ligne de commande -v est présente.
MAIL_CONFIG
L'emplacement du répertoire de configuration de l'instance.

PARAMÈTRES DE CONFIGURATION

config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
daemon_directory (voir la sortie de 'postconf -d')
Le répertoire contenant les programmes de support et les programmes démons de Postfix.
import_environment (voir la sortie de 'postconf -d')
La liste des variables d'environnement qu'un processus Postfix privilégié importera d'un processus parent non-Postfix, ou des remplacements d'environnement nom=valeur.
multi_instance_directories (vide)
Une liste optionnelle de répertoires de configuration Postfix non par défaut ; ces répertoires appartiennent à des instances Postfix supplémentaires qui partagent les fichiers exécutables et la documentation de Postfix avec l'instance Postfix par défaut, et qui sont démarrées, arrêtées, etc., avec l'instance Postfix par défaut.
multi_instance_group (vide)
Le nom de groupe d'instance optionnel de cette instance Postfix.
multi_instance_name (vide)
Le nom d'instance optionnel de cette instance Postfix.
multi_instance_enable (non)
Permet à cette instance Postfix d'être démarrée, arrêtée, etc., par un gestionnaire multi-instance.
postmulti_start_commands (start)
Les commandes postfix(1) que le gestionnaire d'instances postmulti(1) traite comme des commandes "start".
postmulti_stop_commands (voir la sortie de 'postconf -d')
Les commandes postfix(1) que le gestionnaire d'instances postmulti(1) traite comme des commandes "stop".
postmulti_control_commands (reload flush)
Les commandes postfix(1) que le gestionnaire d'instances postmulti(1) traite comme des commandes "control", qui opèrent sur les instances en cours d'exécution.
syslog_facility (mail)
La facilité syslog de la journalisation Postfix.
syslog_name (voir 'pos
tconf -d' output)
Un préfixe qui est ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, "smtpd" devient "prefix/smtpd".

Disponible dans Postfix 3.0 et versions ultérieures :

meta_directory (voir la sortie de 'postconf -d')
L'emplacement des fichiers non exécutables qui sont partagés entre plusieurs instances Postfix, tels que postfix-files, dynamicmaps.cf, et les fichiers de modèle multi-instances main.cf.proto et master.cf.proto.
shlib_directory (voir la sortie de 'postconf -d')
L'emplacement des bibliothèques Postfix liées dynamiquement (libpostfix-*.so), et l'emplacement par défaut des plugins de base de données Postfix (postfix-*.so) qui ont un chemin relatif dans le fichier dynamicmaps.cf.

FICHIERS

$meta_directory/main.cf.proto, fichier de configuration par défaut
$meta_directory/master.cf.proto, fichier de configuration par défaut
$daemon_directory/postmulti-script, programme d'assistance au cycle de vie
