POSTALIAS(1) Manuel des commandes générales POSTALIAS(1)

NOM

postalias - Maintenance de la base de données des alias Postfix

SYNTAXE

postalias [-Nfinoprsuvw] [-c config_dir] [-d clé] [-q clé]
[type_fichier:]nom_fichier ...

DESCRIPTION


La commande postalias(1) crée ou interroge une ou plusieurs bases de données d'alias Postfix, ou met à jour une base existante. Les formats de fichiers d'entrée et de sortie sont censés être compatibles avec Sendmail version 8, et être adaptés pour être utilisés comme des cartes d'alias NIS.

Si les fichiers résultants n'existent pas, ils seront créés avec les mêmes permissions de lecture pour le groupe et pour les autres que leur fichier source.

Pendant qu'une mise à jour de base de données est en cours, la livraison des signaux est reportée, et un verrou exclusif et consultatif est placé sur l'ensemble de la base de données, afin d'éviter les surprises dans les processus spectateurs.

Le format des fichiers d'entrée d'alias Postfix est décrit dans aliases(5).

Par défaut, la clé de recherche est mise en minuscules pour rendre les recherches insensibles à la casse ; depuis Postfix 2.3, cette conversion en minuscules n'est effectuée qu'avec les tables dont les clés de recherche sont des chaînes de caractères à casse fixe telles que btree:, dbm: ou hash:. Avec les versions antérieures, la clé de recherche était convertie même avec des tables où un champ de recherche pouvait correspondre à du texte en majuscules et minuscules, comme regexp: et pcre:. Cela entraînait une perte d'informations avec les substitutions de type $nombre.

Options :

-c config_dir
Lire le fichier de configuration main.cf dans le répertoire nommé au lieu du répertoire de configuration par défaut.
-d clé
Rechercher dans les cartes spécifiées la clé et supprimer une entrée par carte. Le code de sortie est zéro si les informations demandées ont été trouvées.

Si une valeur de clé de - est spécifiée, le programme lit les valeurs de clé depuis le flux d'entrée standard. Le code de sortie est zéro si au moins une des clés demandées a été trouvée.

-f
Ne pas convertir la clé de recherche en minuscules lors de la création ou de l'interrogation d'une table.

Avec Postfix version 2.3 et ultérieures, cette option n'a aucun effet pour les tables d'expressions régulières. Là, la conversion en minuscules est contrôlée en ajoutant un drapeau à un motif.

-i
Mode incrémental. Lire les entrées depuis l'entrée standard et ne pas tronquer une base de données existante. Par défaut, postalias(1) crée une nouvelle base de données à partir des entrées dans nom_fichier.
-N
Inclure le caractère nul de terminaison qui termine les clés et les valeurs de recherche. Par défaut, postalias(1) fait ce qui est par défaut pour le système d'exploitation hôte.
-n
Ne pas inclure le caractère nul de terminaison qui termine les clés et les valeurs de recherche. Par défaut, postalias(1) fait ce qui est par défaut pour le système d'exploitation hôte.
-o
Ne pas libérer les privilèges root lors du traitement d'un fichier d'entrée non root. Par défaut, postalias(1) abandonne les privilèges root et s'exécute en tant que propriétaire du fichier source.
-p
Ne pas hériter des permissions d'accès au fichier du fichier d'entrée lors de la création d'un nouveau fichier. Au lieu de cela, créer un nouveau fichier avec des permissions d'accès par défaut (mode 0644).
-q clé
Rechercher dans les cartes spécifiées la clé et écrire la première valeur trouvée dans le flux de sortie standard. Le code de sortie est zéro si les informations demandées ont été trouvées.

Note : cela effectue une seule requête avec la clé telle que spécifiée, et ne fait pas de requêtes itératives avec des sous-chaînes de la clé comme décrit dans la page de manuel aliases(5).

Si une valeur de clé de - est spécifiée, le programme lit les valeurs de clé depuis le flux d'entrée standard et écrit une ligne de sortie au format clé: valeur pour chaque clé trouvée. Le code de sortie est zéro si au moins une des clés demandées a été trouvée.

-r
Lors de la mise à jour d'une table, ne pas se plaindre des tentatives de mise à jour d'entrées existantes, et effectuer ces mises à jour de toute façon.
-s
Récupérer tous les éléments de la base de données et écrire une ligne de sortie au format clé: valeur pour chaque élément. Les éléments sont imprimés dans l'ordre de la base de données, ce qui n'est pas nécessairement le même que l'ordre d'entrée original. Cette fonctionnalité est disponible dans Postfix version 2.2 et ultérieures, et n'est pas disponible pour tous les types de bases de données.
-u
Désactiver la prise en charge de l'UTF-8. La prise en charge de l'UTF-8 est activée par défaut lorsque "smtputf8_enable = yes". Elle exige que les clés et les valeurs soient des chaînes de caractères UTF-8 valides.
-v
Activer la journalisation verbeuse à des fins de débogage. Plusieurs options -v rendent le logiciel de plus en plus verbeux.
-w
Lors de la mise à jour d'une table, ne pas se plaindre des tentatives de mise à jour d'entrées existantes, et ignorer ces tentatives.

Arguments :

type_fichier
Le type de base de données. Pour savoir quels types sont supportés, utilisez la commande "postconf -m".

La commande postalias(1) peut interroger n'importe quel type de fichier supporté, mais elle ne peut créer que les types de fichiers suivants :

btree
La sortie est un fichier btree, nommé nom_fichier.db. Ceci est disponible sur les systèmes prenant en charge les bases de données db.
cdb
La sortie est un fichier nommé nom_fichier.cdb. Ceci est disponible sur les systèmes prenant en charge les bases de données cdb.
dbm
La sortie se compose de deux fichiers, nommés nom_fichier.pag et nom_fichier.dir. Ceci est disponible sur les systèmes prenant en charge les bases de données dbm.
fail
Une table qui échoue de manière fiable à toutes les requêtes. Le nom de la table de recherche est utilisé uniquement pour la journalisation. Cette table existe pour simplifier les tests d'erreurs Postfix.
hash
La sortie est un fichier haché, nommé nom_fichier.db. Ceci est disponible sur les systèmes prenant en charge les bases de données db.
lmdb
La sortie est un fichier basé sur une structure arborescente (btree), nommé nom_fichier.lmdb. lmdb prend en charge les écritures et lectures simultanées par différents processus, contrairement aux autres tables basées sur des fichiers supportées. Ceci est disponible sur les systèmes prenant en charge les bases de données lmdb.
sdbm
La sortie se compose de deux fichiers, nommés nom_fichier.pag et nom_fichier.dir. Ceci est disponible sur les systèmes prenant en charge les bases de données sdbm.

Lorsqu'aucun type_fichier n'est spécifié, le logiciel utilise le type de base de données spécifié via le paramètre de configuration default_database_type. La valeur par défaut de ce paramètre dépend de l'environnement hôte.

nom_fichier
Le nom du fichier source de la base de données d'alias lors de la création d'une base de données.

DIAGNOSTICS


Les problèmes sont enregistrés dans le flux d'erreur standard et dans syslogd(8) ou postlogd(8). Aucune sortie signifie qu'aucun problème n'a été détecté. Les entrées dupliquées sont ignorées et signalées par un avertissement.

postalias(1) se termine avec un code de sortie zéro en cas de succès (y compris la recherche réussie "postalias -q") et se termine avec un code de sortie non nul en cas d'échec.

PARAMETRES DE CONFIGURATION

Les paramètres main.cf suivants sont particulièrement pertinents pour ce programme.

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

alias_database (voir la sortie de 'postconf -d')
Les bases de données d'alias pour la livraison local(8) qui sont mises à jour avec "newaliases" ou avec "sendmail -bi".
config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
berkeley_db_create_buffer_size (16777216)
La taille du tampon d'E/S par table pour les programmes qui créent des tables de hachage ou d'arbre B de Berkeley DB.
berkeley_db_read_buffer_size (131072)
La taille du tampon d'E/S par table pour les programmes qui lisent des tables de hachage ou d'arbre B de Berkeley DB.
default_database_type (voir la sortie de 'postconf -d')
Le type de base de données par défaut à utiliser dans les commandes newaliases(1), postalias(1) et postmap(1).
import_environment (voir la sortie de 'postconf -d')
La liste des variables d'environnement qu'un processus Postfix privilégié importera d'un processus parent non-Postfix, ou des substitutions d'environnement nom=valeur.
smtputf8_enable (yes)
Active le support préliminaire SMTPUTF8 pour les protocoles décrits dans les RFC 6531, RFC 6532 et RFC 6533.
syslog_facility (mail)
La facilité syslog de la journalisation Postfix.
syslog_name (voir la sortie de 'postconf -d')
Un préfixe qui est ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, "smtpd" devienne "prefix/smtpd".

Disponible dans Postfix 2.11 et versions ultérieures :

lmdb_map_size (16777216)
La limite initiale de taille de la base de données LMDB OpenLDAP en octets.
