NOM

podman-login - Se connecter à un registre de conteneurs

SYNTAXE

podman login [options] [registry]

DESCRIPTION

podman login se connecte à un serveur de registre spécifié avec le nom d'utilisateur et le mot de passe corrects. Si le registre n'est pas spécifié, le premier registre sous [registries.search] de registries.conf est utilisé. podman login lit le nom d'utilisateur et le mot de passe depuis STDOUT. Le nom d'utilisateur et le mot de passe peuvent également être définis en utilisant les options username et password. Le chemin du fichier d'authentification peut être spécifié par l'utilisateur en définissant l'option authfile. Le chemin par défaut pour lire et écrire les identifiants est ${XDG_RUNTIME_DIR}/containers/auth.json. Podman utilise les identifiants existants si l'utilisateur ne fournit pas de nom d'utilisateur. Podman recherche d'abord le nom d'utilisateur et le mot de passe dans ${XDG_RUNTIME_DIR}/containers/auth.json, s'ils ne sont pas valides, Podman utilise ensuite les identifiants existants trouvés dans $HOME/.docker/config.json. Si ces identifiants ne sont pas présents, Podman crée ${XDG_RUNTIME_DIR}/containers/auth.json (si le fichier n'existe pas) puis y stocke le nom d'utilisateur et le mot de passe depuis STDOUT sous forme de chaîne encodée en base64. Pour plus de détails sur le format et la configuration du fichier auth.json, voir containers-auth.json(5)

podman [OPTIONS GLOBAL]

podman login [OPTIONS GLOBAL]

podman login [OPTIONS] [REGISTRY] [OPTIONS GLOBAL]

OPTIONS

--authfile=chemin

Chemin du fichier d'authentification. Par défaut, ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'y est pas trouvé, $HOME/.docker/config.json est vérifié, qui est défini à l'aide de docker login.

Remarque : Il existe également la possibilité de remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utiliser les certificats à chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Par défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (sauf WSL2))

--compat-auth-file=chemin

Au lieu de mettre à jour le fichier d'identifiants par défaut, mettez à jour celui situé à chemin et utilisez un format compatible Docker.

--get-login

Retourner l'utilisateur connecté pour le registre. Retourner une erreur si aucune connexion n'est trouvée.

--help, -h

Afficher le message d'utilisation

--password, -p=motdepasse

Mot de passe pour le registre

--password-stdin

Prendre le mot de passe depuis stdin

--secret=nom

Lire le mot de passe pour le registre à partir du secret Podman nom. Si --username n'est pas spécifié, --username=nom est utilisé.

--tls-verify

Exiger HTTPS et vérifier les certificats lors du contact avec les registres (par défaut : true). S'il est explicitement défini sur true, la vérification TLS est utilisée. S'il est défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée sauf si le registre cible est listé comme un registre non sécurisé dans containers-registries.conf(5)

--username, -u=nomutilisateur

Nom d'utilisateur pour le registre

--verbose, -v

afficher des informations détaillées sur le magasin d'identifiants

EXEMPLES

Ajouter des identifiants de connexion pour le registre spécifié au fichier d'authentification par défaut ; notez que contrairement au défaut de docker, les identifiants par défaut se trouvent sous $XDG_RUNTIME_DIR qui est un sous-répertoire de /run (un répertoire éphémère) et ne persistent donc pas après le redémarrage.

$ podman login quay.io
Nom d'utilisateur : umohnani
Mot de passe :
Connexion réussie !

Pour préserver explicitement les identifiants après un redémarrage, vous devrez spécifier le chemin persistant par défaut :

$ podman login --authfile ~/.config/containers/auth.json quay.io
Nom d'utilisateur : umohnani
Mot de passe :
Connexion réussie !

Ajouter des identifiants de connexion en utilisant le nom d'utilisateur et le mot de passe spécifiés pour le registre local au fichier d'authentification par défaut.

$ podman login -u testuser -p testpassword localhost:5000
Connexion réussie !

Ajouter des identifiants de connexion pour un chemin d'authentification alternatif pour le registre spécifié.

$ podman login --authfile authdir/myauths.json quay.io
Nom d'utilisateur : umohnani
Mot de passe :
Connexion réussie !

Ajouter des identifiants de connexion à l'aide d'un secret Podman pour le mot de passe.

$ echo -n MonSecret! | podman secret create nomsecret -
a0ad54df3c97cf89d5ca6193c
$ podman login --secret nomsecret -u testuser quay.io
Connexion réussie !

Ajouter des identifiants de connexion pour l'utilisateur test avec le mot de passe test au registre localhost:5000 en désactivant l'exigence de vérification tls.

$ podman login --tls-verify=false -u test -p test localhost:5000
Connexion réussie !

Ajouter des identifiants de connexion pour l'utilisateur foo avec le mot de passe bar au registre localhost:5000 en utilisant le répertoire de certificats /etc/containers/certs.d.

$ podman login --cert-dir /etc/containers/certs.d/ -u foo -p bar localhost:5000
Connexion réussie !

Ajouter des identifiants de connexion pour les registres spécifiés au fichier d'authentification par défaut pour l'utilisateur donné avec les informations de mot de passe fournies via stdin à partir d'un fichier sur disque.

$ podman login -u testuser --password-stdin < testpassword.txt docker.io
Connexion réussie !

Ajouter des identifiants de connexion pour le registre spécifié au fichier d'authentification par défaut pour l'utilisateur donné avec les informations de mot de passe fournies via stdin à partir d'un pipe.

$ echo $testpassword | podman login -u testuser --password-stdin quay.io
Connexion réussie !

Ajouter des identifiants de connexion pour le registre spécifié au fichier d'authentification par défaut en mode verbeux.

$ podman login quay.io --verbose
Nom d'utilisateur : myusername
Mot de passe :
Utilisé : /run/user/1000/containers/auth.json
Connexion réussie !

VOIR AUSSI

podman(1), podman-logout(1), containers-auth.json(5), containers-certs.d(5), containers-registries.conf(5), podman-secret(1), podman-secret-create(1)

    DESCRIPTION

    Log in to a container registry.

    The podman login command logs you into a container registry. If you do not specify a registry, podman will log you into the default registry, which is defined in the containers-registries.d(5) configuration file.

    To log out, use the podman logout command.

    OPTIONS

    • --cert-dir=<path>

    Path to directory containing TLS certificates for the registry. The default is /etc/containers/certs.d/.

    • -p, --password=<password>

    Password for the registry. If this is not specified, podman will prompt you for a password.

    • --username=<username>

    Username for the registry. If this is not specified, podman will prompt you for a username.

    • --tls-verify=

    Whether to verify the TLS certificate chain for the registry. Defaults to true.

    EXAMPLES

    Log in to the default registry:

    $ podman login
Username:
Password:
Login Succeeded

    Log in to a specific registry:

    $ podman login my.registry.com
Username:
Password:
Login Succeeded

    Log in with username and password:

    $ podman login --username myuser --password mypassword my.registry.com
Login Succeeded

    Log in without verifying TLS certificates:

    $ podman login --tls-verify=false my.registry.com
Username:
Password:
Login Succeeded

    SEE ALSO

    podman-logout(1), containers-registries.d(5)

    DESCRIPTION

    Connecte à un registre de conteneurs.

    La commande podman login vous connecte à un registre de conteneurs. Si vous ne spécifiez pas de registre, podman se connectera au registre par défaut, tel que défini dans le fichier de configuration containers-registries.d(5).

    Pour vous déconnecter, utilisez la commande podman logout.

    OPTIONS

    • --cert-dir=<chemin>

    Chemin vers le répertoire contenant les certificats TLS pour le registre. Le chemin par défaut est /etc/containers/certs.d/.

    • -p, --password=<mot de passe>

    Mot de passe pour le registre. Si ceci n'est pas spécifié, podman vous demandera un mot de passe.

    • --username=<nom d'utilisateur>

    Nom d'utilisateur pour le registre. Si ceci n'est pas spécifié, podman vous demandera un nom d'utilisateur.

    • --tls-verify=<bool>

    Indique s'il faut vérifier la chaîne de certificats TLS pour le registre. Par défaut à true.

    EXAMPLES

    Se connecter au registre par défaut :

    $ podman login
Nom d'utilisateur :
Mot de passe :
Connexion réussie

    Se connecter à un registre spécifique :

    $ podman login my.registry.com
Nom d'utilisateur :
Mot de passe :
Connexion réussie

    Se connecter avec nom d'utilisateur et mot de passe :

    $ podman login --username myuser --password mypassword my.registry.com
Connexion réussie

    Se connecter sans vérifier les certificats TLS :

    $ podman login --tls-verify=false my.registry.com
Nom d'utilisateur :
Mot de passe :
Connexion réussie
