podman-cp(1) Manuel des commandes générales podman-cp(1)

NOM

podman-cp - Copier des fichiers/dossiers entre un conteneur et le système de fichiers local

SYNTAXE

podman cp [options] [conteneur:]chemin_source [conteneur:]chemin_destination

podman container cp [options] [conteneur:]chemin_source [conteneur:]chemin_destination

DESCRIPTION

podman cp permet de copier le contenu de chemin_source vers chemin_destination. Les fichiers peuvent être copiés d'un conteneur vers la machine locale et vice versa, ou entre deux conteneurs. Si - est spécifié pour CHEMIN_SOURCE ou CHEMIN_DESTINATION, il est également possible de streamer une archive tar depuis STDIN ou vers STDOUT.

Les conteneurs peuvent être en cours d'exécution ou arrêtés, et chemin_source ou chemin_destination peuvent être un fichier ou un répertoire.

*IMPORTANT : La commande podman cp suppose que les chemins des conteneurs sont relatifs au répertoire racine du conteneur (/), ce qui signifie que la spécification de la barre oblique initiale est facultative et donc que compassionate_darwin:/tmp/foo/myfile.txt et compassionate_darwin:tmp/foo/myfile.txt sont considérés comme identiques.*

Les chemins de la machine locale peuvent être des valeurs absolues ou relatives. La commande interprète les chemins relatifs d'une machine locale comme étant relatifs au répertoire de travail actuel où podman cp est exécuté.

En supposant un séparateur de chemin de /, un premier argument de chemin_source et un second argument de chemin_destination, le comportement est le suivant :

chemin_source spécifie un fichier :
- chemin_destination n'existe pas
- le fichier est sauvegardé dans un fichier créé à chemin_destination (notez que le répertoire parent doit exister).
- chemin_destination existe et est un fichier
- la destination est écrasée avec le contenu du fichier source.
- chemin_destination existe et est un répertoire
- le fichier est copié dans ce répertoire en utilisant le nom de base de chemin_source.

chemin_source spécifie un répertoire :
- chemin_destination n'existe pas
- chemin_destination est créé comme répertoire et le contenu du répertoire source est copié dans ce répertoire.
- chemin_destination existe et est un fichier
- Condition d'erreur : impossible de copier un répertoire vers un fichier.
- chemin_destination existe et est un répertoire
- chemin_source se termine par /
- le répertoire source est copié dans ce répertoire.
- chemin_source se termine par /. (c'est-à-dire slash suivi d'un point)
- le contenu du répertoire source est copié dans ce répertoire.

La commande nécessite que chemin_source et chemin_destination existent conformément aux règles ci-dessus.

Si chemin_source est local et est un lien symbolique, la cible du lien symbolique est copiée par défaut.

Un deux-points ( : ) est utilisé comme délimiteur entre un conteneur et son chemin ; il peut également être utilisé lors de la spécification de chemins vers un chemin_source ou un chemin_destination sur une machine locale, par exemple, fichier:nom.txt.

*IMPORTANT : lors de l'utilisation d'un deux-points ( : ) dans un chemin de machine locale, vous devez être explicite avec un chemin relatif ou absolu, par exemple : /chemin/vers/fichier:nom.txt ou ./fichier:nom.txt*

L'utilisation de - comme chemin_source streamer le contenu de STDIN sous forme d'archive tar. La commande extrait le contenu du tar vers le CHEMIN_DESTINATION dans le conteneur. Dans ce cas, chemin_destination doit spécifier un répertoire. L'utilisation de - comme chemin_destination streamer le contenu de la ressource (peut être un répertoire) sous forme d'archive tar vers STDOUT.

Notez que podman cp ignore les erreurs de permission lors de la copie depuis un conteneur rootless en cours d'exécution. Les périphériques TTY à l'intérieur d'un conteneur rootless appartiennent à l'utilisateur root de l'hôte et ne peuvent donc pas être lus à l'intérieur de l'espace de noms d'utilisateur du conteneur.

Notez également que podman cp ne prend pas en charge les glob (par exemple, cp dir/*.txt). Pour copier plusieurs fichiers de l'hôte vers le conteneur, utilisez xargs(1) ou find(1) (ou des outils similaires pour enchaîner les commandes) conjointement avec podman cp. Pour copier plusieurs fichiers du conteneur vers l'hôte, utilisez podman mount CONTENEUR et opérez sur le point de montage retourné à la place (voir ALTERNATIVES ci-dessous).

OPTIONS

--archive, -a

Mode archive (copie toutes les informations UID/GID). Lorsqu'il est défini sur true, les fichiers copiés vers un conteneur voient leur propriété modifiée pour devenir l'UID/GID primaire du conteneur. Lorsqu'il est défini sur false, conserve l'UID/GID des sources d'archive au lieu de les modifier pour l'UID/GID primaire du conteneur de destination. La valeur par défaut est true.

--overwrite

Autorise l'écrasement de répertoires par des non-répertoires et vice versa. Par défaut, podman cp génère une erreur lorsqu'il tente d'écraser, par exemple, un fichier régulier par un répertoire.

ALTERNATIVES

Podman offre des capacités bien plus puissantes que la simple commande podman cp pour copier des fichiers entre l'hôte et les conteneurs.

L'utilisation des commandes standard podman-mount(1) et podman-unmount(1) tire parti de toute la chaîne d'outils Linux, plutôt que de simplement cp.

La copie de contenu hors d'un conteneur ou dans un conteneur peut être réalisée avec quelques commandes simples. Par exemple :

Pour copier le répertoire /etc/foobar hors d'un conteneur et le placer dans /tmp sur l'hôte, les commandes suivantes peuvent être exécutées :

mnt=$(podman mount CONTENEURID)
cp -R ${mnt}/etc/foobar /tmp
podman umount CONTENEURID

Pour extraire une archive tar dans un conteneur, les commandes suivantes peuvent être exécutées :

mnt=$(podman mount CONTENEURID)
tar xf content.tgz -C ${mnt}
podman umount CONTENEURID

Pour installer un paquet dans un conteneur qui n'a pas dnf installé, les commandes suivantes peuvent être exécutées :

mnt=$(podman mount CONTENEURID)
dnf install --installroot=${mnt} httpd
chroot ${mnt} rm -rf /var/log/dnf /var/cache/dnf
podman umount CONTENEURID

En utilisant podman mount et podman unmount, vous pouvez utiliser tous les outils Linux standards pour déplacer des fichiers vers et depuis les conteneurs, pas seulement la commande cp.

EXEMPLES

Copier un fichier de l'hôte vers un conteneur :

podman cp /myapp/app.conf containerID:/myapp/app.conf

Copier un fichier d'un conteneur vers un répertoire d'un autre conteneur :

podman cp containerID1:/myfile.txt containerID2:/tmp

Copier un répertoire d'un conteneur vers un répertoire sur l'hôte :

podman cp containerID:/myapp/ /myapp/

Copier le contenu d'un répertoire d'un conteneur vers un répertoire sur l'hôte :

podman cp containerID:/home/myuser/. /home/myuser/

Copier un répertoire d'un conteneur dans un répertoire d'un autre :

podman cp containerA:/myapp containerB:/newapp

Streamer une archive tar depuis STDIN vers un conteneur :

podman cp - containerID:/myfiles.tar.gz < myfiles.tar.gz

VOIR AUSSI

podman(1), podman-mount(1), podman-unmount(1)
