NOM

podman-search - Rechercher une image dans un registre

SYNTAXE

podman search [options] terme

DESCRIPTION

podman search recherche une image correspondante dans un ou plusieurs registres. L'utilisateur peut spécifier quel registre rechercher en précédant le terme de recherche par le nom du registre (par exemple, registry.fedoraproject.org/fedora). Par défaut, tous les registres sans qualification de recherche dans containers-registries.conf(5) sont utilisés.

Le nombre de résultats par défaut est de 25. Le nombre de résultats peut être limité à l'aide de l'option --limit. Si plusieurs registres sont interrogés, la limite s'applique à chaque registre. La sortie peut être filtrée à l'aide de l'option --filter. Pour obtenir toutes les images disponibles dans un registre sans terme de recherche spécifique, l'utilisateur peut simplement entrer le nom du registre suivi d'un "/" (exemple : registry.fedoraproject.org/).

Notez que podman search n'est pas un moyen fiable de déterminer la présence ou l'existence d'une image. Le comportement de recherche des API Docker distribution v1 et v2 est spécifique à l'implémentation de chaque registre. Certains registres peuvent ne pas prendre en charge la recherche du tout. Notez également que la recherche sans terme de recherche ne fonctionne que pour les registres qui implémentent l'API v2.

podman [OPTIONS GLOBALES]

podman search [OPTIONS GLOBALES]

podman search [OPTIONS] TERME

OPTIONS

--authfile=chemin

Chemin du fichier d'authentification. Par défaut : ${XDG_RUNTIME_DIR}/containers/auth.json sur Linux, et $HOME/.config/containers/auth.json sur Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation ne s'y trouve pas, $HOME/.docker/config.json est vérifié, qui est défini à l'aide de docker login.

Note : Il existe également une option pour remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utiliser les certificats situés dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--compatible

Après le nom et la description, afficher également les descripteurs d'étoiles, officiels et automatisés comme le fait Docker. Podman n'affiche pas ces descripteurs par défaut car ils ne sont pas pris en charge par la plupart des registres d'images conteneurs publics.

--creds=[nom_utilisateur[:mot_de_passe]]

Le [nom_utilisateur[:mot_de_passe]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou deux valeurs ne sont pas fournies, une invite de commande apparaît et la valeur peut être entrée. Le mot de passe est saisi sans écho.

Notez que les identifiants spécifiés sont uniquement utilisés pour s'authentifier auprès des registres cibles. Ils ne sont pas utilisés pour les miroirs ou lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour vous authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--filter, -f=filtre

Filtrer la sortie en fonction des conditions fournies (par défaut [])

Filtres pris en charge :

  • stars (int) - nombre minimum d'étoiles requis pour afficher les images
  • is-automated (booléen - true | false) - l'image est-elle automatisée ou non
  • is-official (booléen - true | false) - l'image est-elle officielle ou non

--format=format

Changer le format de sortie en un template Go

Les espaces réservés valides pour le template Go sont listés ci-dessous :

Espace réservé Description
.Automated "[OK]" si l'image est automatisée
.Description Description de l'image
.Index Registre
.Name Nom de l'image
.Official "[OK]" si l'image est officielle
.Stars Nombre d'étoiles de l'image
.Tag Tag du dépôt

Note : utilisez .Tag uniquement si --list-tags est défini.

--help, -h

Afficher l'énoncé d'utilisation

--limit=limite

Limiter le nombre de résultats (par défaut 25). Note : les résultats de chaque registre sont limités à cette valeur. Exemple : si la limite est 10 et que deux registres sont interrogés, le nombre total de résultats est 20, 10 de chaque (s'il y a au moins 10 correspondances dans chaque). L'ordre des résultats de la recherche est l'ordre dans lequel l'API renvoie les résultats.

--list-tags

Lister les tags disponibles dans le dépôt pour l'image spécifiée. Note : --list-tags nécessite que le terme de recherche soit un nom d'image entièrement spécifié. Le résultat contient le nom de l'image et son tag, une ligne pour chaque tag associé à l'image.

--no-trunc

Ne pas tronquer la sortie (défaut false).

--tls-verify

Exiger HTTPS et vérifier les certificats lors du contact avec les registres (défaut : true). Si explicitement défini sur true, la vérification TLS est utilisée. Si défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée à moins que le registre cible ne soit listé comme registre non sécurisé dans containers-registries.conf(5)

EXEMPLES

Rechercher des images contenant le nom spécifié, renvoyant les trois premières images de chaque registre défini.

$ podman search --limit 3 fedora
NOM                                           DESCRIPTION
registry.fedoraproject.org/f29/fedora-toolbox
registry.fedoraproject.org/f30/fedora-toolbox
registry.fedoraproject.org/f31/fedora-toolbox
docker.io/library/fedora                      Constructions Docker officielles de Fedora
docker.io/kasmweb/fedora-37-desktop           Fedora 37 desktop pour Kasm Workspaces
docker.io/kasmweb/fedora-38-desktop           Fedora 38 desktop pour Kasm Workspaces
quay.io/fedora/fedora
quay.io/containerdisks/fedora                 # Images de disque conteneur Fedora <img src="htt...
quay.io/fedora/fedora-minimal

Notez que les descripteurs Étoiles, Officiel et Automatisé ne sont disponibles que sur Docker Hub et ne sont donc pas affichés par défaut.

$ podman search --format "{{.Name}}\t{{.Stars}}\t{{.Official}}" alpine --limit 3
docker.io/library/alpine       7956        [OK]
docker.io/alpine/git           192
docker.io/anapsix/alpine-java  474
quay.io/libpod/alpine          0
quay.io/vqcomms/alpine-tools   0
quay.io/wire/alpine-deps       0

Rechercher et lister les tags de l'image spécifiée en renvoyant les quatre premières images de chaque registre défini.

$ podman search --list-tags registry.access.redhat.com/ubi8 --limit 4
NOM                             TAG
registry.access.redhat.com/ubi8  8.4-211
registry.access.redhat.com/ubi8  8.4-206.1626828523-source
registry.access.redhat.com/ubi8  8.4-199
registry.access.redhat.com/ubi8  8.4-211-source

Note : Ceci ne fonctionne qu'avec les registres qui implémentent l'API v2. Si vous essayez avec un registre v1, une erreur est renvoyée.

FICHIERS

registries.conf (/etc/containers/registries.conf)

registries.conf est le fichier de configuration qui spécifie quels registres de conteneurs sont consultés lors de la complétion des noms d'image qui n'incluent pas de partie registre ou domaine.
