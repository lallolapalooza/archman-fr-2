POSTMAP(1) Manuel des commandes générales POSTMAP(1)

NOM

postmap - gestion des tables de correspondance Postfix

SYNTAXE

postmap [-bfFhimnNoprsuUvw] [-c config_dir] [-d clé] [-q clé]
[type_fichier:]nom_fichier ...

DESCRIPTION


La commande postmap(1) crée ou interroge une ou plusieurs tables de correspondance Postfix, ou met à jour une table existante.

Si les fichiers résultants n'existent pas, ils seront créés avec les mêmes permissions de lecture pour le groupe et les autres que leur fichier source.

Pendant la mise à jour de la table, la livraison des signaux est reportée, et un verrou exclusif et consultatif est placé sur la table entière, afin d'éviter les surprises dans les processus spectateurs.

FORMAT DU FICHIER D'ENTRÉE

Le format d'un fichier de table de correspondance est le suivant :

  • Une entrée de table a la forme 
         clé espace(s) valeur
  • Les lignes vides et les lignes contenant uniquement des espaces sont ignorées, tout comme les lignes dont le premier caractère non-espace est un `#'.
  • Une ligne logique commence par du texte non-espace. Une ligne commençant par un espace continue une ligne logique.

La clé et la valeur sont traitées telles quelles, sauf que les espaces entourant sont supprimés. Les espaces dans les clés de table de correspondance sont pris en charge à partir de Postfix 3.2, en entourant la clé de guillemets doubles `"'. À l'intérieur des guillemets doubles, les caractères guillemets doubles `"' et antislash `\' peuvent être inclus en les échappant avec un antislash précédent.

Lorsque l'option -F est donnée, la valeur doit spécifier un ou plusieurs noms de fichiers séparés par des virgules et/ou des espaces ; postmap(1) concaténera le contenu des fichiers (avec un caractère de nouvelle ligne inséré entre les fichiers) et stockera le résultat encodé en base64 au lieu de la valeur.

Lorsque la clé spécifie des informations d'adresse e-mail, la partie locale doit être entourée de guillemets doubles si requis par la RFC 5322. Par exemple, une partie locale d'adresse contenant un ";", ou une partie locale commençant ou se terminant par un ".".

Par défaut, la clé de recherche est mise en minuscules pour rendre les recherches insensibles à la casse ; à partir de Postfix 2.3, cette mise en minuscules n'est effectuée qu'avec les tables dont les clés de recherche sont des chaînes de caractères à casse fixe comme btree:, dbm: ou hash:. Avec les versions antérieures, la clé de recherche était mise en minuscules même avec des tables où un champ de recherche pouvait correspondre à du texte en majuscules et minuscules, comme regexp: et pcre:. Cela entraînait une perte d'informations avec les substitutions $nombre.

ARGUMENTS DE LA LIGNE DE COMMANDE

-b
Active le mode de requête du corps du message. Lors de la lecture des clés de table de correspondance depuis l'entrée standard avec "-q -", traite l'entrée comme s'il s'agissait d'un message e-mail au format RFC 5322. Chaque ligne du contenu du corps devient une clé de table de correspondance.

Par défaut, l'option -b commence à générer des clés de table de correspondance à la première ligne qui n'est pas un en-tête, et s'arrête à la fin du message. Pour simuler le traitement de body_checks(5), activez l'analyse MIME avec -m. Avec cela, l'option -b ne génère pas de clés de table de correspondance de type corps pour les en-têtes MIME de pièces jointes et pour les en-têtes message/* joints.

NOTE : avec "smtputf8_enable = yes", l'option -b désactive les vérifications de syntaxe UTF-8 sur les clés de requête et les résultats de table de correspondance. Spécifiez l'option -U pour forcer les vérifications de syntaxe UTF-8 de toute façon.

Cette fonctionnalité est disponible dans Postfix version 2.6 et ultérieures.

-c config_dir
Lit le fichier de configuration main.cf dans le répertoire nommé au lieu du répertoire de configuration par défaut.
-d clé
Recherche dans les cartes spécifiées la clé et supprime une entrée par carte. Le statut de sortie est zéro lorsque les informations demandées ont été trouvées.

Si une valeur de clé de - est spécifiée, le programme lit les valeurs de clé depuis le flux d'entrée standard. Le statut de sortie est zéro lorsque au moins une des clés demandées a été trouvée.

-f
Ne pas mettre la clé de table de correspondance en minuscules lors de la création ou de l'interrogation d'une table.

Avec Postfix version 2.3 et ultérieures, cette option n'a aucun effet pour les tables d'expressions régulières. Là, la mise en minuscules est contrôlée en ajoutant un drapeau à un modèle.

-F
Lors de l'interrogation d'une carte, ou de l'énumération d'une carte, décode chaque valeur en base64. Lors de la création d'une carte à partir d'un fichier source, traite chaque valeur comme une liste de noms de fichiers, concatène le contenu de ces fichiers, et stocke le résultat encodé en base64 au lieu de la valeur (voir FORMAT DU FICHIER D'ENTRÉE pour les détails).

Cette fonctionnalité est disponible dans Postfix version 3.4 et ultérieures.

-h
Active le mode de requête des en-têtes de message. Lors de la lecture des clés de table de correspondance depuis l'entrée standard avec "-q -", traite l'entrée comme s'il s'agissait d'un message e-mail au format RFC 5322. Chaque ligne d'en-tête logique devient une clé de table de correspondance. Un en-tête multi-lignes devient une clé de table de correspondance avec un ou plusieurs caractères de nouvelle ligne incorporés.

Par défaut, l'option -h génère des clés de table de correspondance jusqu'à la première ligne qui n'est pas un en-tête. Pour simuler le traitement de header_checks(5), activez l'analyse MIME avec -m. Avec cela, l'option -h génère également des clés de table de correspondance de type en-tête pour les en-têtes MIME de pièces jointes et pour les en-têtes message/* joints.

NOTE : avec "smtputf8_enable = yes", l'option -b désactive les vérifications de syntaxe UTF-8 sur les clés de requête et les résultats de table de correspondance. Spécifiez l'option -U pour forcer les vérifications de syntaxe UTF-8 de toute façon.

Cette fonctionnalité est disponible dans Postfix version 2.6 et ultérieures.

-i
Mode incrémental. Lit les entrées depuis l'entrée standard et ne tronque pas une base de données existante. Par défaut, postmap(1) crée une nouvelle base de données à partir des entrées dans nom_fichier.
-m
Active l'analyse MIME avec "-b" et "-h".

Cette fonctionnalité est disponible dans Postfix version 2.6 et ultérieures.

-N
Inclut le caractère nul de terminaison qui termine les clés et les valeurs de table de correspondance. Par défaut, postmap(1) fait ce qui est par défaut pour le système d'exploitation hôte.
-n
N'inclut pas le caractère nul de terminaison qui termine les clés et les valeurs de table de correspondance. Par défaut, postmap(1) fait ce qui est par défaut pour le système d'exploitation hôte.
-o
Ne pas libérer les privilèges root lors du traitement d'un fichier d'entrée non-root. Par défaut, postmap(1) abandonne les privilèges root et s'exécute comme le propriétaire du fichier source à la place.
-p
Ne pas hériter des permissions d'accès aux fichiers du fichier d'entrée lors de la création d'un nouveau fichier. Au lieu de cela, crée un nouveau fichier avec les permissions d'accès par défaut (mode 0644).
-q clé
Recherche dans les cartes spécifiées la clé et écrit la première valeur trouvée sur le flux de sortie standard. Le statut de sortie est zéro lorsque les informations demandées ont été trouvées.

Note : cela effectue une seule requête avec la clé telle que spécifiée, et ne fait pas de requêtes itératives avec des sous-chaînes de la clé comme décrit pour access(5), canonical(5), transport(5), virtual(5) et d'autres fonctionnalités pilotées par table Postfix.

Si une valeur de clé de - est spécifiée, le programme lit les valeurs de clé depuis le flux d'entrée standard et écrit une ligne de sortie clé valeur pour chaque clé trouvée. Le statut de sortie est zéro lorsque au moins une des clés demandées a été trouvée.

-r
Lors de la mise à jour d'une table, ne pas se plaindre des tentatives de mise à jour d'entrées existantes, et effectuer ces mises à jour de toute façon.
-s
Récupère
postmap(1) — Postfix lookup table utility

NOM

postmap — utilitaire de table de correspondance Postfix

SYNTAXE

postmap [paramètres] [-q cle] [-r cle] [type:]fichier
postmap [paramètres] -i fichier
postmap [paramètres] -m

DESCRIPTION

Le programme postmap (8) crée des tables de correspondance pour Postfix à partir de fichiers texte. Il lit les tables de correspondance à partir des fichiers texte spécifiés, et écrit la sortie dans un format de table de base de données compilé.

Les options -q et -r permettent de tester l'accès aux tables de correspondance. Elles sont utiles pour vérifier la syntaxe des clés et la structure des tables de base de données, mais pas pour l'accès aux données réelles.

L'option -i permet de mettre à jour une table de base de données existante à partir d'un fichier texte. Elle est utilisée pour le traitement des commandes de mise à jour des tables.

L'option -m permet d'afficher tous les éléments de base de données, et d'écrire une ligne de clé valeur pour chaque élément. Les éléments sont imprimés dans l'ordre de la base de données, ce qui n'est pas nécessairement le même que l'ordre d'entrée d'origine.

Cette fonctionnalité est disponible dans Postfix version 2.2 et ultérieures, et n'est pas disponible pour tous les types de bases de données.

ARGUMENTS EN LIGNE DE COMMANDE

type_fichier
Le type de base de données. Pour savoir quels types sont pris en charge, utilisez la commande "postconf -m".

La commande postmap (1) peut interroger tout type de fichier pris en charge, mais elle ne peut créer que les types de fichiers suivants :

btree
Le fichier de sortie est un fichier btree, nommé nom_fichier.db. Ceci est disponible sur les systèmes prenant en charge les bases de données db.
cdb
La sortie consiste en un seul fichier, nommé nom_fichier.cdb. Ceci est disponible sur les systèmes prenant en charge les bases de données cdb.
dbm
La sortie consiste en deux fichiers, nommés nom_fichier.pag et nom_fichier.dir. Ceci est disponible sur les systèmes prenant en charge les bases de données dbm.
fail
Une table qui échoue de manière fiable à toutes les requêtes. Le nom de la table de correspondance est utilisé uniquement pour la journalisation. Cette table existe pour simplifier les tests d'erreurs Postfix.
hash
Le fichier de sortie est un fichier haché, nommé nom_fichier.db. Ceci est disponible sur les systèmes prenant en charge les bases de données db.
lmdb
La sortie est un fichier basé sur btree, nommé nom_fichier.lmdb. lmdb prend en charge les écritures et lectures simultanées à partir de différents processus, contrairement aux autres tables basées sur des fichiers prises en charge. Ceci est disponible sur les systèmes prenant en charge les bases de données lmdb.
sdbm
La sortie consiste en deux fichiers, nommés nom_fichier.pag et nom_fichier.dir. Ceci est disponible sur les systèmes prenant en charge les bases de données sdbm.

Lorsque aucun type_fichier n'est spécifié, le logiciel utilise le type de base de données spécifié via le paramètre de configuration default_database_type.

nom_fichier
Le nom du fichier source de la table de correspondance lors de la reconstruction d'une base de données.

DIAGNOSTICS


Les problèmes sont enregistrés dans le flux d'erreurs standard et dans syslogd(8) ou postlogd(8). Aucune sortie signifie qu'aucun problème n'a été détecté. Les entrées dupliquées sont ignorées et signalées par un avertissement.

postmap(1) se termine avec un code de sortie zéro en cas de succès (y compris la recherche réussie "postmap -q") et se termine avec un code de sortie non nul en cas d'échec.

ENVIRONNEMENT

MAIL_CONFIG
Répertoire contenant les fichiers de configuration Postfix.
MAIL_VERBOSE
Active la journalisation détaillée à des fins de débogage.

PARAMETRES DE CONFIGURATION

Les paramètres main.cf suivants sont particulièrement pertinents pour ce programme. Le texte ci-dessous ne fournit qu'un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

berkeley_db_create_buffer_size (16777216)
La taille du tampon d'E/S par table pour les programmes qui créent des tables hash ou btree Berkeley DB.
berkeley_db_read_buffer_size (131072)
La taille du tampon d'E/S par table pour les programmes qui lisent des tables hash ou btree Berkeley DB.
config_directory (voir la sortie de 'postconf -d')
L'emplacement par défaut des fichiers de configuration main.cf et master.cf de Postfix.
default_database_type (voir la sortie de 'postconf -d')
Le type de base de données par défaut à utiliser dans les commandes newaliases(1), postalias(1) et postmap(1).
import_environment (voir la sortie de 'postconf -d')
La liste des variables d'environnement qu'un processus Postfix privilégié importera d'un processus parent non-Postfix, ou des substitutions d'environnement nom=valeur.
smtputf8_enable (yes)
Active la prise en charge préliminaire de SMTPUTF8 pour les protocoles décrits dans les RFC 6531, 6532 et 6533.
syslog_facility (mail)
La facilité syslog de la journalisation Postfix.
syslog_name (voir la sortie de 'postconf -d')
Un préfixe qui est ajouté au nom du processus dans les enregistrements syslog, de sorte que, par exemple, "smtpd" devienne "prefix/smtpd".

Disponible dans Postfix 2.11 et ultérieures :

lmdb_map_size (16777216)
La limite de taille initiale de la base de données LMDB OpenLDAP en octets.
