NOM

podman-volume-create - Crée un nouveau volume

SYNOPSIS

podman volume create [options] [nom]

DESCRIPTION

Crée un volume vide et le prépare pour être utilisé par les conteneurs. Le volume peut être créé avec un nom spécifique ; si aucun nom n'est donné, un nom aléatoire est généré. Vous pouvez ajouter des métadonnées au volume en utilisant l'indicateur --label et des options de pilote peuvent être définies en utilisant l'indicateur --opt.

OPTIONS

--driver, -d=pilote

Spécifie le nom du pilote de volume (par défaut local). Il existe deux pilotes supportés par Podman lui-même : local et image.

Le pilote local utilise un répertoire sur le disque comme backend par défaut, mais peut également utiliser la commande mount(8) pour monter un système de fichiers en tant que volume si --opt est spécifié.

Le pilote image utilise une image comme source de sauvegarde pour le volume. Un système de fichiers en superposition (overlay) est créé, ce qui permet aux modifications du volume d'être validées en tant que nouvelle couche au-dessus de l'image.

En utilisant une valeur autre que local ou image, Podman tente de créer le volume en utilisant un plugin de volume portant le nom donné. Ces plugins doivent être définis dans la section volume_plugins du fichier de configuration containers.conf(5).

--gid=gid

Définit le GID sous lequel le volume sera créé. Différemment de --opt o=gid=*gid*, la valeur spécifiée n'est pas transmise à l'opération de montage. Le GID spécifié possédera le répertoire du point de montage du volume et affectera l'opération de changement de propriétaire du volume.

--help

Affiche l'énoncé d'utilisation

--ignore

Ne pas échouer si le volume nommé existe déjà, au lieu de cela, afficher simplement le nom. Notez que les nouvelles options ne sont pas appliquées au volume existant.

--label, -l=étiquette

Définit des métadonnées pour un volume (par exemple, --label mykey=value).

--opt, -o=option

Définit des options spécifiques au pilote. Pour le pilote par défaut, local, cela permet à un volume d'être configuré pour monter un système de fichiers sur l'hôte.

Pour le pilote local, les options suivantes sont supportées : type, device, o, et [no]copy.

  • L'option type définit le type du système de fichiers à monter, et est équivalente à l'indicateur -t de mount(8).
  • L'option device définit le périphérique à monter, et est équivalente à l'argument device de mount(8).
  • L'option copy active la copie des fichiers de l'image de conteneur vers le nouveau volume lors de la première exécution. copy est l'option par défaut.

L'option o définit les options pour le montage, et est équivalente aux options du système de fichiers (également -o) passées à mount(8), à l'exception des points suivants :

  • L'option o supporte les options uid et gid pour définir l'UID et le GID du volume créé, qui ne sont normalement pas supportées par mount(8).
  • L'option o supporte l'option size pour définir la taille maximale du volume créé, l'option inodes pour définir le nombre maximum d'inodes pour le volume, et noquota pour désactiver complètement le support des quotas même pour le suivi de l'utilisation du disque. L'option size est supportée sur les systèmes de fichiers "tmpfs" et "xfs[note]". L'option inodes est supportée sur les systèmes de fichiers "xfs[note]". Note : les systèmes de fichiers xfs doivent être montés avec l'indicateur prjquota décrit dans la page de manuel xfs_quota(8). Podman générera une erreur s'ils ne le sont pas.
  • L'option o supporte l'utilisation d'options de volume autres que les options UID/GID avec le pilote local et nécessite des privilèges root.
  • L'option o supporte l'option timeout qui permet aux utilisateurs de définir un délai spécifique au pilote en secondes avant que la création du volume ne échoue. Par exemple, --opt=o=timeout=10 définit un délai pilote de 10 secondes.

Note Ne confondez pas l'option de création --opt,-o avec l'option de montage -o. Par exemple, avec podman volume create, utilisez -o=o=uid=1000 *pas* -o=uid=1000.

Pour le pilote image, la seule option supportée est image, qui spécifie l'image sur laquelle le volume est basé. Cette option est obligatoire lors de l'utilisation du pilote image.

Lorsque vous n'utilisez pas les pilotes local et image, les options données sont transmises directement au plugin de volume. Dans ce cas, les options supportées sont dictées par le plugin en question, et non par Podman.

--uid=uid

Définit l'UID sous lequel le volume sera créé. Différemment de --opt o=uid=*uid*, la valeur spécifiée n'est pas transmise à l'opération de montage. L'UID spécifié possédera le répertoire du point de montage du volume et affectera l'opération de changement de propriétaire du volume.

QUOTAS

podman volume create utilise les contrôles de quota de projet XFS pour gérer la taille et le nombre d'inodes des volumes intégrés. Le répertoire utilisé pour stocker les volumes doit être un système de fichiers XFS et être monté avec l'option pquota.

Exemple d'entrée /etc/fstab :

/dev/podman/podman-var /var xfs defaults,x-systemd.device-timeout=0,pquota 1 2

Podman génère des identifiants de projet pour chaque volume intégré, mais ces identifiants de projet doivent être uniques pour le système de fichiers XFS. Ces identifiants de projet sont générés aléatoirement par défaut, avec une possibilité de chevauchement avec d'autres quotas sur le même système de fichiers.

L'outil xfs_quota peut être utilisé pour attribuer un identifiant de projet au répertoire du pilote de stockage, par exemple :

echo 100000:/var/lib/containers/storage/overlay >> /etc/projects
echo 200000:/var/lib/containers/storage/volumes >> /etc/projects
echo storage:100000 >> /etc/projid
echo volumes:200000 >> /etc/projid
xfs_quota -x -c 'project -s storage volumes' /<point de montage xfs>

Dans l'exemple ci-dessus, nous configurons le pilote de stockage overlay pour les conteneurs nouvellement créés ainsi que les volumes pour utiliser des identifiants de projet avec un décalage de démarrage. Tous les conteneurs se voient attribuer des identifiants de projet plus grands (par exemple, >= 100000). Tous les volumes se voient attribuer des identifiants de projet plus grands commençant par 200000. Cela évite les conflits de gestion xfs_quota avec containers/storage.

EXEMPLES

Crée un volume vide.

$ podman volume create

Crée un volume nommé vide.

$ podman volume create myvol

Crée un volume nommé vide avec une étiquette spécifiée.

$ podman volume create --label foo=bar myvol

Crée un volume nommé tmpfs avec une taille et des options de montage spécifiées.

# podman volume create --opt device=tmpfs --opt type=tmpfs --opt o=size=2M,nodev,noexec myvol

Crée un volume nommé tmpfs testvol avec les options spécifiées.

# podman volume create --opt device=tmpfs --opt type=tmpfs --opt o=uid=1000,gid=1000 testvol

Crée un volume en remplaçant l'UID et le GID du propriétaire.

# podman volume create --uid 1000 --gid 1000 myvol

Crée un volume nommé basé sur une image locale spécifiée dans containers/storage.

# podman volume create --driver image --opt image=fedora:latest fedoraVol

EXEMPLES DE MONTAGE

podman volume create permet de passer les options type, device et o à mount(8) lors de l'utilisation du pilote local.

s3fs-fuse

s3fs-fuse, ou simplement s3fs, est un système de fichiers fuse qui permet de monter des préfixes s3 en tant que montages de système de fichiers.

Installation :

$ doas dnf install s3fs-fuse

Utilisation simple :

$ s3fs --help
$ s3fs -o use_xattr,endpoint=aq-cen
tral-1 bucket:/prefix /mnt

Équivalent avec mount(8)

$ mount -t fuse.s3fs -o use_xattr,endpoint=aq-central-1 bucket:/prefix /mnt

Équivalent avec podman volume create

$ podman volume create s3fs-fuse-volume -o type=fuse.s3fs -o device=bucket:/prefix -o o=use_xattr,endpoint=aq-central-1

Le volume peut ensuite être monté dans un conteneur avec

$ podman run -v s3fs-fuse-volume:/s3:z --rm -it fedora:latest

Veuillez consulter les options disponibles sur leur wiki.

Utilisation avec d'autres utilisateurs de conteneur

L'exemple ci-dessus fonctionne car le volume est monté en tant qu'utilisateur hôte et à l'intérieur du conteneur, root est mappé à l'utilisateur de l'hôte.

Si le montage est accédé par un autre utilisateur à l'intérieur du conteneur, une erreur "Permission denied" sera générée.

$ podman run --user bin:bin -v s3fs-fuse-volume:/s3:z,U --rm -it fedora:latest
$ ls /s3
# ls: /s3: Permission denied

Dans le monde FUSE, les montages sont protégés pour l'utilisateur qui les a montés ; spécifiez l'option de montage allow_other si d'autres utilisateurs ont besoin d'y accéder. > Note : Cela supprimera les mesures de sécurité normales de fuse sur le point de montage, après quoi les permissions normales du système de fichiers devront le protéger.

$ podman volume create s3fs-fuse-other-volume -o type=fuse.s3fs -o device=bucket:/prefix -o o=allow_other,use_xattr,endpoint=aq-central-1
$ podman run --user bin:bin -v s3fs-fuse-volume:/s3:z,U --rm -it fedora:latest
$ ls /s3

Le préfixe doit exister

s3fs échouera au montage si le préfixe n'existe pas dans le bucket.

Créez un répertoire s3 en plaçant un objet vide à la clé prefix/ souhaitée.

$ aws s3api put-object --bucket bucket --key prefix/

Si la performance est votre priorité, consultez goofys, plus performant.

Des systèmes de fichiers FUSE existent pour Google Cloud Storage et Azure Blob Storage.
