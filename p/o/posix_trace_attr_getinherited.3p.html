POSIX_TRACE_ATTR_GETINHERITED(3P) Manuel du programmeur POSIX POSIX_TRACE_ATTR_GETINHERITED(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

posix_trace_attr_getinherited, posix_trace_attr_getlogfullpolicy, posix_trace_attr_getstreamfullpolicy, posix_trace_attr_setinherited, posix_trace_attr_setlogfullpolicy, posix_trace_attr_setstreamfullpolicy — récupérer et définir le comportement d'un flux de trace (TRACAGE)

SYNTAXE

#include <trace.h>
int posix_trace_attr_getinherited(const trace_attr_t *restrict attr,
    int *restrict inheritancepolicy);
int posix_trace_attr_getlogfullpolicy(const trace_attr_t *restrict attr,
    int *restrict logpolicy);
int posix_trace_attr_getstreamfullpolicy(const trace_attr_t *restrict
    attr, int *restrict streampolicy);
int posix_trace_attr_setinherited(trace_attr_t *attr,
    int inheritancepolicy);
int posix_trace_attr_setlogfullpolicy(trace_attr_t *attr,
    int logpolicy);
int posix_trace_attr_setstreamfullpolicy(trace_attr_t *attr,
    int streampolicy);

DESCRIPTION

Les fonctions posix_trace_attr_getinherited() et posix_trace_attr_setinherited() récupèrent et définissent respectivement la politique d'héritage stockée dans l'attribut héritage pour les processus tracés lors des opérations fork() et spawn(). L'attribut héritage de l'objet d'attributs pointé par l'argument attr sera défini à l'une des valeurs suivantes définies par des constantes manuelles dans l'en-tête <trace.h> :

POSIX_TRACE_CLOSE_FOR_CHILD

Après une opération fork() ou spawn(), l'enfant ne sera pas tracé, et le traçage du parent continuera.
POSIX_TRACE_INHERITED

Après une opération fork() ou spawn(), si le parent est tracé, son enfant sera tracé simultanément en utilisant le même flux de trace.

La valeur par défaut pour l'attribut héritage est POSIX_TRACE_CLOSE_FOR_CHILD.

Les fonctions posix_trace_attr_getlogfullpolicy() et posix_trace_attr_setlogfullpolicy() récupèrent et définissent respectivement la politique de remplissage du journal de trace stockée dans l'attribut log-full-policy de l'objet d'attributs pointé par l'argument attr.

L'attribut log-full-policy sera défini à l'une des valeurs suivantes définies par des constantes manuelles dans l'en-tête <trace.h> :

POSIX_TRACE_LOOP

Le journal de trace bouclera jusqu'à ce que le flux de trace associé soit arrêté. Cette politique signifie que lorsque le journal de trace est plein, le système de fichiers réutilisera les ressources allouées aux événements de trace les plus anciens qui ont été enregistrés. De cette manière, le journal de trace contiendra toujours les événements de trace les plus récents vidés.
POSIX_TRACE_UNTIL_FULL

Le flux de trace sera vidé dans le journal de trace jusqu'à ce que le journal de trace soit plein. Cette condition peut être déduite du statut du membre posix_log_full_status (voir la structure **posix_trace_status_info** définie dans <trace.h>). Le dernier événement de trace enregistré sera l'événement de trace POSIX_TRACE_STOP.
POSIX_TRACE_APPEND

Le flux de trace associé sera vidé dans le journal de trace sans limitation de taille du journal. Si l'application spécifie POSIX_TRACE_APPEND, l'implémentation ignorera l'attribut log-max-size.

La valeur par défaut pour l'attribut log-full-policy est POSIX_TRACE_LOOP.

Les fonctions posix_trace_attr_getstreamfullpolicy() et posix_trace_attr_setstreamfullpolicy() récupèrent et définissent respectivement la politique de remplissage du flux de trace stockée dans l'attribut stream-full-policy de l'objet d'attributs pointé par l'argument attr.

L'attribut stream-full-policy sera défini à l'une des valeurs suivantes définies par des constantes manuelles dans l'en-tête <trace.h> :

POSIX_TRACE_LOOP

Le flux de trace bouclera jusqu'à ce qu'il soit explicitement arrêté par la fonction posix_trace_stop(). Cette politique signifie que lorsque le flux de trace est plein, le système de trace réutilisera les ressources allouées aux événements de trace les plus anciens enregistrés. De cette manière, le flux de trace contiendra toujours les événements de trace les plus récents enregistrés.
POSIX_TRACE_UNTIL_FULL

Le flux de trace s'exécutera jusqu'à ce que les ressources du flux de trace soient épuisées. Ensuite, le flux de trace s'arrêtera. Cette condition peut être déduite de posix_stream_status et posix_stream_full_status (voir la structure **posix_trace_status_info** définie dans <trace.h>). Lors de la lecture de ce flux de trace, un événement de trace POSIX_TRACE_STOP sera rapporté après avoir rapporté le dernier événement de trace enregistré. Le système de trace réutilisera les ressources allouées à tous les événements de trace déjà rapportés — voir les fonctions posix_trace_getnext_event(), posix_trace_trygetnext_event(), et posix_trace_timedgetnext_event() — ou déjà vidés pour un flux de trace actif avec journal si l'option Journal de Trace est prise en charge ; voir la fonction posix_trace_flush(). Le système de trace redémarrera le flux de trace lorsqu'il sera vide et pourra le redémarrer plus tôt. Un événement de trace POSIX_TRACE_START sera rapporté avant le prochain événement de trace enregistré.
POSIX_TRACE_FLUSH

Si l'option Journal de Trace est prise en charge, cette politique est identique à la politique de remplissage du flux de trace POSIX_TRACE_UNTIL_FULL, sauf que le flux de trace sera vidé régulièrement comme si posix_trace_flush() avait été explicitement appelée. Définir cette politique pour un flux de trace actif sans journal sera invalide.

La valeur par défaut pour l'attribut stream-full-policy sera POSIX_TRACE_LOOP pour un flux de trace actif sans journal.

Si l'option Journal de Trace est prise en charge, la valeur par défaut pour l'attribut stream-full-policy sera POSIX_TRACE_FLUSH pour un flux de trace actif avec journal.

VALEUR RENVOYÉE

En cas de succès, ces fonctions retourneront une valeur de zéro. Sinon, elles retourneront le numéro d'erreur correspondant.

En cas de succès, la fonction posix_trace_attr_getinherited() stockera la valeur de l'attribut héritage dans l'objet pointé par inheritancepolicy. Sinon, le contenu de cet objet est indéfini.

En cas de succès, la fonction posix_trace_attr_getlogfullpolicy() stockera la valeur de l'attribut log-full-policy dans l'objet pointé par logpolicy. Sinon, le contenu de cet objet est indéfini.

En cas de succès, la fonction posix_trace_attr_getstreamfullpolicy() stockera la valeur de l'attribut stream-full-policy dans l'objet pointé par streampolicy. Sinon, le contenu de cet objet est indéfini.

ERREURS

Ces fonctions peuvent échouer si :

EINVAL
La valeur spécifiée par au moins un des arguments est invalide.
