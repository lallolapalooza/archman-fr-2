POW(3P) Manuel du programmeur POSIX POW(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consulter la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

pow, powf, powl — fonction puissance

SYNTAXE

#include <math.h>
double pow(double x, double y);
float powf(float x, float y);
long double powl(long double x, long double y);

DESCRIPTION

La fonctionnalité décrite sur cette page de référence est alignée sur la norme ISO C. Tout conflit entre les exigences décrites ici et la norme ISO C est involontaire. Ce volume de POSIX.1‐2017 s'en remet à la norme ISO C.

Ces fonctions calculent la valeur de x élevé à la puissance y, xy. Si x est négatif, l'application doit s'assurer que y est un entier.

Une application souhaitant vérifier les situations d'erreur doit initialiser errno à zéro et appeler feclearexcept(FE_ALL_EXCEPT) avant d'appeler ces fonctions. Au retour, si errno est différent de zéro ou si fetestexcept(FE_INVALID | FE_DIVBYZERO | FE_OVERFLOW | FE_UNDERFLOW) est différent de zéro, une erreur s'est produite.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent la valeur de x élevé à la puissance y.

Pour les valeurs finies de x < 0, et les valeurs finies non entières de y, une erreur de domaine se produit et un NaN (s'il est représentable) ou une valeur dépendant de l'implémentation est retourné.

Si la valeur correcte provoquerait un dépassement (overflow), une erreur de plage se produit et pow(), powf(), et powl() retournent ±HUGE_VAL, ±HUGE_VALF, et ±HUGE_VALL, respectivement, avec le même signe que la valeur correcte de la fonction.

Si la valeur correcte provoquerait un sous-dépassement (underflow), et n'est pas représentable, une erreur de plage peut se produire, et pow(), powf(), et powl() retournent 0.0, ou (si l'option flottante IEC 60559 n'est pas supportée) une valeur dépendant de l'implémentation ne dépassant pas en magnitude DBL_MIN, FLT_MIN, et LDBL_MIN, respectivement.

Pour y < 0, si x est zéro, une erreur de pôle peut se produire et pow(), powf(), et powl() retournent ±HUGE_VAL, ±HUGE_VALF, et ±HUGE_VALL, respectivement. Sur les systèmes qui supportent l'option flottante IEC 60559, si x est ±0, une erreur de pôle se produit et pow(), powf(), et powl() retournent ±HUGE_VAL, ±HUGE_VALF, et ±HUGE_VALL, respectivement si y est un entier impair, ou HUGE_VAL, HUGE_VALF, et HUGE_VALL, respectivement si y n'est pas un entier impair.

Si x ou y est un NaN, un NaN est retourné (sauf indication contraire dans cette description).

Pour toute valeur de y (y compris NaN), si x vaut +1, 1.0 est retourné.

Pour toute valeur de x (y compris NaN), si y vaut ±0, 1.0 est retourné.

Pour toute valeur entière impaire de y > 0, si x vaut ±0, ±0 est retourné.

Pour y > 0 et non entier impair, si x vaut ±0, +0 est retourné.

Si x vaut -1, et y vaut ±Inf, 1.0 est retourné.

Pour |x| < 1, si y vaut -Inf, +Inf est retourné.

Pour |x| > 1, si y vaut -Inf, +0 est retourné.

Pour |x| < 1, si y vaut +Inf, +0 est retourné.

Pour |x| > 1, si y vaut +Inf, +Inf est retourné.

Pour y entier impair < 0, si x vaut -Inf, -0 est retourné.

Pour y < 0 et non entier impair, si x vaut -Inf, +0 est retourné.

Pour y entier impair > 0, si x vaut -Inf, -Inf est retourné.

Pour y > 0 et non entier impair, si x vaut -Inf, +Inf est retourné.

Pour y < 0, si x vaut +Inf, +0 est retourné.

Pour y > 0, si x vaut +Inf, +Inf est retourné.

Si la valeur correcte provoquait un sous-dépassement, et est représentable, une erreur de plage peut se produire et la valeur correcte sera retournée.

ERREURS

Ces fonctions échouent si :

Erreur de domaine
La valeur de x est négative et y est un nombre non entier fini.

Si l'expression entière (math_errhandling & MATH_ERRNO) est non nulle, alors errno est défini sur [EDOM]. Si l'expression entière (math_errhandling & MATH_ERREXCEPT) est non nulle, alors l'exception flottante invalide est déclenchée.

Erreur de pôle
La valeur de x est zéro et y est négatif.

Si l'expression entière (math_errhandling & MATH_ERRNO) est non nulle, alors errno est défini sur [ERANGE]. Si l'expression entière (math_errhandling & MATH_ERREXCEPT) est non nulle, alors l'exception flottante de division par zéro est déclenchée.

Erreur de plage
Le résultat provoque un dépassement (overflow).

Si l'expression entière (math_errhandling & MATH_ERRNO) est non nulle, alors errno est défini sur [ERANGE]. Si l'expression entière (math_errhandling & MATH_ERREXCEPT) est non nulle, alors l'exception flottante de dépassement est déclenchée.

Ces fonctions peuvent échouer si :

Erreur de pôle
La valeur de x est zéro et y est négatif.

Si l'expression entière (math_errhandling & MATH_ERRNO) est non nulle, alors errno est défini sur [ERANGE]. Si l'expression entière (math_errhandling & MATH_ERREXCEPT) est non nulle, alors l'exception flottante de division par zéro est déclenchée.

Erreur de plage
Le résultat provoque un sous-dépassement (underflow).

Si l'expression entière (math_errhandling & MATH_ERRNO) est non nulle, alors errno est défini sur [ERANGE]. Si l'expression entière (math_errhandling & MATH_ERREXCEPT) est non nulle, alors l'exception flottante de sous-dépassement est déclenchée.

UTILISATION PAR L'APPLICATION

En cas d'erreur, les expressions (math_errhandling & MATH_ERRNO) et (math_errhandling & MATH_ERREXCEPT) sont indépendantes l'une de l'autre, mais au moins l'une d'elles doit être non nulle.
