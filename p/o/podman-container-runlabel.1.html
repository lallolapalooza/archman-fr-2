NOM

podman-container-runlabel - Exécute une commande telle que décrite par un label d'image de conteneur

SYNTAXE

podman container runlabel [options] label image [arg...]

DESCRIPTION

podman container runlabel lit le label spécifié de l'image et l'exécute comme commande sur l'hôte. Si le label n'existe pas, Podman se termine avec une erreur. Des arguments supplémentaires sont ajoutés à la commande.

Historiquement, les images de conteneurs décrivent leur contenu (par exemple, les couches) et comment un runtime de conteneur (par exemple, crun(1) ou runc(1)) exécute le conteneur. Par exemple, une image peut définir l'environnement et la commande dans sa configuration. Cependant, une image de conteneur ne peut pas spécifier directement comment un moteur de conteneur tel que Podman l'exécute. Par exemple, une configuration d'image n'inclut pas d'informations sur les pilotes de journalisation, les espaces de noms ou les capacités dont elle a besoin pour fonctionner correctement.

podman container runlabel répond à la limitation des images de conteneurs d'une manière simple mais efficace. Podman lit le contenu du label et l'interprète comme une commande exécutée sur l'hôte. Ainsi, une image peut décrire exactement comment elle est exécutée par Podman. Par exemple, un label avec le contenu /usr/bin/podman run -d --pid=host --privileged \${IMAGE} instruit l'image à être exécutée dans un conteneur détaché et privilégié qui utilise l'espace de noms PID de l'hôte. Cela élève l'auto-description d'une image de conteneur de « quoi » à « comment ».

Notez que la commande runlabel est destinée à être exécutée exclusivement dans des environnements de confiance. L'utilisation de la commande sur des images non fiables n'est pas recommandée.

VARIABLES

Le contenu d'un label peut faire référence aux variables suivantes qui sont substituées lors du traitement du label.

IMAGE Le nom de l'image. Lors de l'exécution de podman container runlabel label fedora la variable IMAGE est remplacée par fedora. Les formats valides sont IMAGE, $IMAGE, ${IMAGE} et =IMAGE.

NAME Tel que spécifié par l'option --name. Le format est identique à celui de l'attribut IMAGE.

PWD Sera remplacé par le répertoire de travail courant.

OPTIONS

--authfile=chemin

Chemin du fichier d'authentification. Par défaut : ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'est pas trouvé là, $HOME/.docker/config.json est vérifié, qui est défini à l'aide de docker login.

Note : Il existe également une option pour remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utiliser les certificats dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2)).

--creds=[nomdutilisateur[:motdepasse]]

Le [nomdutilisateur[:motdepasse]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou les deux valeurs ne sont pas fournies, une invite de commande apparaît et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les informations d'identification spécifiées sont uniquement utilisées pour s'authentifier auprès des registres cibles. Elles ne sont pas utilisées pour les miroirs ou lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour s'authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--display

Affiche la valeur du label de l'image après avoir rempli ses variables d'environnement. La commande runlabel n'est pas exécutée si --display est spécifié.

--help, -h

Affiche le message d'utilisation

--name, -n=nom

Utiliser ce nom pour créer du contenu pour le conteneur. Si non spécifié, le nom est par défaut le nom de l'image.

--quiet, -q

Supprimer les informations de sortie lors du téléchargement des images

--replace

Si un conteneur existe avec le nom actuel, il est arrêté, supprimé et un nouveau conteneur est créé à partir de cette image.

--tls-verify

Exiger HTTPS et vérifier les certificats lors du contact avec les registres (par défaut : true). S'il est explicitement défini sur true, la vérification TLS est utilisée. S'il est défini sur false, la vérification TLS n'est pas utilisée. S'il n'est pas spécifié, la vérification TLS est utilisée, sauf si le registre cible est répertorié comme un registre non sécurisé dans containers-registries.conf(5).

EXEMPLES

Exécute le label run d'une image nommée foobar.

$ podman container runlabel run foobar

Exécute le label install d'une image nommée foobar avec des arguments supplémentaires.

$ podman container runlabel install foobar pommes oranges

Affiche le contenu du label run de l'image foobar.

$ podman container runlabel --display run foobar

Ré-exécute un conteneur en utilisant un label qui définit un nom de conteneur fixe. L'indicateur --replace garantit que tout conteneur existant est supprimé au préalable.

$ podman ps -a
CONTAINER ID  IMAGE                             COMMAND               CREATED         STATUS                     PORTS       NAMES
1254c038d892  docker.io/library/busybox:latest  echo Hello from r...  26 seconds ago  Exited (0) 26 seconds ago              test-runlabel
$ podman container runlabel --replace RUN runlabel-test
Hello from runlabel
$ podman ps -a
CONTAINER ID  IMAGE                             COMMAND               CREATED        STATUS                    PORTS       NAMES
28efd9600d0c  docker.io/library/busybox:latest  echo Hello from r...  4 seconds ago  Exited (0) 4 seconds ago              test-runlabel

Cette commande est utile lorsque le label utilise un nom fixe (par exemple, --name monconteneur) et que vous souhaitez l'exécuter répétitivement sans supprimer manuellement le conteneur précédent.

    NOM

    podman-container-runlabel — Exécute une commande dans un conteneur basé sur un label

    SYNTAXE

    podman container runlabel [OPTIONS] label [command] [arg...]

    DESCRIPTION

    La commande podman container runlabel exécute une commande dans un nouveau conteneur basé sur un conteneur dont le label spécifié correspond au label donné. La commande est exécutée dans le nouveau conteneur et le conteneur est supprimé une fois la commande terminée.

    La commande runlabel ne crée pas un nouveau conteneur. Elle recherche des conteneurs existants qui correspondent au label spécifié. Si plusieurs conteneurs correspondent au label, la commande runlabel échouera.

    La commande runlabel est utile pour exécuter des tâches répétitives dans un environnement cohérent. Par exemple, vous pourriez utiliser runlabel pour exécuter des tests de compilation sur une image de conteneur.

    VARIABLES

    Aucune variable d'environnement spécifique n'est requise pour cette commande.

    OPTIONS

    Cette commande n'a pas d'options spécifiques.

    EXEMPLES

    Exécuter la commande echo hello dans un conteneur basé sur un conteneur avec le label my-app :

    $ podman container runlabel my-app echo hello
hello

    VOIR AUSSI

    podman(1), podman-container(1)
