podman-push(1) Manuel des commandes générales podman-push(1)

NOM

podman-push - Pousse une image, une liste de manifestes ou un index d'images du stockage local vers ailleurs

SYNTAXE

podman push [options] image [destination]

podman image push [options] image [destination]

DESCRIPTION

Pousse une image, une liste de manifestes ou un index d'images depuis le stockage local vers une destination spécifiée.

Stockage des images

Les images sont poussées depuis celles stockées dans le stockage d'images local.

DESTINATION

DESTINATION est l'emplacement vers lequel l'image de conteneur est poussée. Elle prend en charge tous les transports de containers-transports(5). Si aucun transport n'est spécifié, le transport docker (c'est-à-dire le registre de conteneurs) est utilisé. Pour les clients distants, y compris les machines Mac et Windows (hors WSL2), docker est le seul transport pris en charge.

# Pousser vers un registre de conteneurs
$ podman push quay.io/podman/stable
# Pousser vers un registre de conteneurs via le transport docker
$ podman push docker://quay.io/podman/stable
# Pousser vers un registre de conteneurs avec un autre tag
$ podman push myimage quay.io/username/myimage
# Pousser vers un répertoire local
$ podman push myimage dir:/tmp/myimage
# Pousser vers une archive tar au format docker-archive
$ podman push myimage docker-archive:/tmp/myimage
# Pousser vers un démon docker local
$ sudo podman push myimage docker-daemon:docker.io/library/myimage:33
# Pousser vers une archive tar au format OCI
$ podman push myimage oci-archive:/tmp/myimage

OPTIONS

--authfile=chemin

Chemin du fichier d'authentification. Par défaut : ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation ne s'y trouve pas, $HOME/.docker/config.json est vérifié, qui est défini à l'aide de docker login.

Note : Il existe également une option pour remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utilise les certificats situés dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--compress

Compresse les couches d'images au format tar lors du transfert vers un répertoire en utilisant le transport 'dir'. (Par défaut : même type de compression, compressé ou non compressé, que la source)

Note : Ce drapeau ne peut être défini qu'avec le transport dir

--compression-format=gzip | zstd | zstd:chunked

Spécifie le format de compression à utiliser. Les valeurs prises en charge sont : gzip, zstd et zstd:chunked. Le défaut est gzip sauf s'il est remplacé dans le fichier containers.conf. zstd:chunked est incompatible avec le chiffrement des images, et sera traité comme zstd avec un avertissement dans ce cas.

--compression-level=niveau

Spécifie le niveau de compression à utiliser. La valeur est spécifique à l'algorithme de compression utilisé, par exemple pour zstd les valeurs acceptées sont dans la plage 1-20 (inclus) avec un défaut de 3, tandis que pour gzip c'est 1-9 (inclus) et a un défaut de 5.

--creds=[nom_utilisateur[:mot_de_passe]]

Le [nom_utilisateur[:mot_de_passe]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou deux valeurs ne sont pas fournies, une invite de commande apparaît et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les identifiants spécifiés ne sont utilisés que pour l'authentification auprès des registres cibles. Ils ne sont pas utilisés pour les miroirs ou lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour s'authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--digestfile=FichierDigest

Après avoir copié l'image, écrivez le digest de l'image résultante dans le fichier.

--disable-content-trust

Ceci est une option spécifique à Docker pour désactiver la vérification des images vers un registre de conteneurs et n'est pas prise en charge par Podman. Cette option est une NOOP et est fournie uniquement à des fins de compatibilité de script.

--encrypt-layer=couche(s)

Couche(s) à chiffrer : indices de couche 0-indexés avec prise en charge de l'indexation négative (par exemple, 0 est la première couche, -1 est la dernière couche). Si non défini, chiffre toutes les couches si l'option encryption-key est spécifiée.

--encryption-key=clé

Le [protocole:fichier_clé] spécifie le protocole de chiffrement, qui peut être JWE (RFC7516), PGP (RFC4880) et PKCS7 (RFC2315) et le matériel de clé requis pour le chiffrement de l'image. Par exemple, jwe:/chemin/vers/clé.pem ou pgp:admin@example.com ou pkcs7:/chemin/vers/fichier/x509.

--force-compression

Si défini, le transfert utilise l'algorithme de compression spécifié même si la destination contient déjà une variante compressée différemment. Par défaut true si --compression-format est explicitement spécifié sur la ligne de commande, false sinon.

--format, -f=format

Type de manifeste (oci, v2s2, ou v2s1) à utiliser lors du transfert d'une image.

--quiet, -q

Lors de l'écriture de l'image de sortie, supprimez la progression.

--remove-signatures

Supprime toutes les signatures préexistantes dans l'image.

--retry=tentatives

Nombre de tentatives de téléchargement ou de transfert d'images entre le registre et le stockage local en cas d'échec. Par défaut : 3.

--retry-delay=durée

Durée du délai entre les tentatives de téléchargement ou de transfert d'images entre le registre et le stockage local en cas d'échec. Par défaut, le délai commence à deux secondes puis augmente exponentiellement. Le délai est utilisé lorsque cette valeur est définie, et aucune augmentation exponentielle ne se produit.

--sign-by=clé

Ajoute une signature de "signature simple" à la destination en utilisant la clé spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--sign-by-sigstore=fichier_param

Ajoute une signature sigstore basée sur des options supplémentaires spécifiées dans un fichier de paramètres de signature sigstore de conteneur, fichier_param. Voir containers-sigstore-signing-params.yaml(5) pour les détails sur le format du fichier.

--sign-by-sigstore-private-key=chemin

Ajoute une signature sigstore à la destination en utilisant une clé privée située au chemin spécifié. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--sign-by-sq-fingerprint=empreinte

Ajoute une signature de "signature simple" en utilisant une clé Sequoia-PGP avec l'empreinte spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--sign-passphrase-file=chemin

Si l'image est signée (en utilisant --sign-by, sign-by-sq-fingerprint ou --sign-by-sigstore-private-key), lit la phrase secrète à utiliser à partir du chemin spécifié.

podman-push(1) — podman — Arch Linux

NOM

podman-push — Pousse une image vers une destination distante

SYNOPSIS

podman push [options] source [destination]

podman push [options] source[:tag] [registry/repository[:tag]]

DESCRIPTION

Pousse une image vers une destination distante. La destination peut être un nom d'image dans un registre de conteneurs, un chemin de répertoire local, ou une archive OCI.

Stockage d'images

Podman ne stocke pas les images dans un registre central. Au lieu de cela, il les stocke en local. Vous pouvez les pousser vers un registre distant en utilisant la commande push.

DESTINATION

La destination peut prendre les formes suivantes :

dir:chemin

Archive l'image dans le répertoire spécifié au format OCI.

oci-archive:chemin:image[:tag]

Archive l'image dans le fichier spécifié au format OCI. Si le chemin est un répertoire, il sera traité comme un répertoire de layout OCI.

docker://registre/repertoire[:tag]

Pousse l'image vers le registre spécifié.

docker-daemon:image[:tag]

Pousse l'image vers le démon Docker local.

[registre/repertoire[:tag]]

Si la destination n'est pas préfixée par un transport, elle est interprétée comme un nom d'image Docker par défaut.

OPTIONS

--all, -a
Pousse toutes les images qui sont liées à la source.
--authfile chemin
Chemin vers le fichier d'authentification.
--cert-dir chemin
Utilise des certificats TLS dans le répertoire spécifié pour se connecter au registre.
--creds identifiants
Identifiants à utiliser pour l'authentification au registre.
--digestfile chemin
Sauvegarde le digest de l'image poussée dans le fichier spécifié.
--format format
Spécifie le format de l'image à pousser. Les formats disponibles sont oci et v2-compatibility.
--help, -h
Affiche l'aide.
--image-history
Conserve l'historique de l'image lors de la poussée.
--no-content
Ne pousse pas le contenu de l'image, seulement la définition et les métadonnées.
--quiet, -q
Ne pas afficher de sortie.
--remove-tags, -r
Supprime les tags spécifiés de l'image après la poussée.
--tls-verify
Vérifie le certificat TLS du registre. Si le registre est listé comme registre non sécurisé dans containers-registries.conf(5), la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée sauf si le registre cible est listé comme registre non sécurisé dans containers-registries.conf(5).

EXEMPLES

Pousse l'image spécifiée vers un répertoire local :

# podman push imageID dir:/path/to/image

Pousse l'image spécifiée vers un répertoire local au format OCI :

# podman push imageID oci-archive:/path/to/layout:image:tag

Pousse l'image spécifiée vers un registre de conteneurs :

# podman push imageID docker://registry.example.com/repository:tag

Pousse l'image spécifiée vers un registre de conteneurs et enregistre le digest dans le fichier spécifié :

# podman push --digestfile=/tmp/mydigest imageID docker://registry.example.com/repository:tag

Pousse l'image spécifiée dans le magasin de conteneurs du démon Docker local :

# podman push imageID docker-daemon:image:tag

Pousse l'image spécifiée avec un nom d'image différent en utilisant les identifiants d'un chemin d'authentification alternatif :

# podman push --authfile temp-auths/myauths.json alpine docker://docker.io/umohnani/alpine
