NOM

podmansh - Exécute un shell de connexion dans le conteneur podmansh de Podman

SYNTAXE

podmansh

DESCRIPTION

Exécute un shell utilisateur dans un conteneur lorsque l'utilisateur se connecte au système. Le conteneur auquel les utilisateurs sont ajoutés peut être défini via un fichier Quadlet de Podman. Cet utilisateur n'a accès qu'aux volumes et aux capacités configurés dans le fichier Quadlet.

Les administrateurs peuvent créer un Quadlet dans /etc/containers/systemd/users, que systemd démarrera pour tous les utilisateurs lors de leur connexion. L'administrateur peut créer un Quadlet spécifique avec le nom de conteneur podmansh, puis permettre aux utilisateurs d'utiliser le shell de connexion /usr/bin/podmansh. Ces shells de connexion utilisateur sont automatiquement exécutés dans le conteneur podmansh via Podman.

Facultativement, l'administrateur peut placer des fichiers Quadlet dans le répertoire /etc/containers/systemd/users/${UID} pour un utilisateur. Seul cet UID exécutera ces services Quadlet lorsque cet utilisateur se connectera.

L'utilisateur est confiné dans l'environnement du conteneur via tous les mécanismes de sécurité, y compris SELinux. Les seules informations disponibles sur le système proviennent des volumes qui fuient dans le conteneur.

Systemd créera automatiquement le conteneur lorsque la session utilisateur sera démarrée. Systemd arrêtera le conteneur lorsque toutes les connexions à la session utilisateur seront supprimées. Cela signifie que les utilisateurs peuvent se connecter au système plusieurs fois, chaque session étant connectée au même conteneur.

Les administrateurs peuvent utiliser des volumes pour exposer des données spécifiques de l'hôte au système hôte à l'utilisateur, sans que l'utilisateur ne soit exposé à d'autres parties du système.

Le délai d'attente pour podmansh peut être défini à l'aide de l'option podmansh_timeout dans containers.conf.

Configuration

Créez une session de connexion utilisateur à l'aide de useradd tout en étant root.

# useradd -s /usr/bin/podmansh lockedu
# grep lockedu /etc/passwd
lockedu:x:4008:4008::/home/lockedu:/usr/bin/podmansh

Créez un fichier Podman Quadlet qui ressemble à l'un des exemples suivants.

Conteneur entièrement verrouillé, aucun accès au système d'exploitation hôte.

# USERID=$(id -u lockedu)
# mkdir -p /etc/containers/systemd/users/${USERID}
# cat > /etc/containers/systemd/users/${USERID}/podmansh.container << _EOF
[Unit]
Description=Le conteneur podmansh
After=local-fs.target
[Container]
Image=registry.fedoraproject.org/fedora
ContainerName=podmansh
UserNS=keep-id
RunInit=yes
DropCapability=all
NoNewPrivileges=true
Exec=sleep infinity
[Install]
RequiredBy=default.target
_EOF

Alternativement, tout en étant root, créez un Quadlet où l'utilisateur est autorisé à devenir root dans l'espace de noms utilisateur. Il peut également lire/écrire de manière permanente du contenu de son répertoire personnel, qui est monté en volume depuis le compte utilisateur réel de l'hôte, plutôt que d'être à l'intérieur du conteneur.

# useradd -s /usr/bin/podmansh confinedu
# grep confinedu /etc/passwd
confinedu:x:4009:4009::/home/confinedu:/usr/bin/podmansh
# USERID=$(id -u confinedu)
# mkdir -p /etc/containers/systemd/users/${USERID}
# cat > /etc/containers/systemd/users/${USERID}/podmansh.container << _EOF
[Unit]
Description=Le conteneur podmansh
After=local-fs.target
[Container]
Image=registry.fedoraproject.org/fedora
ContainerName=podmansh
UserNS=keep-id
RunInit=yes
Volume=%h/data:%h:Z
Exec=sleep infinity
[Service]
ExecStartPre=/usr/bin/mkdir -p %h/data
[Install]
RequiredBy=default.target
_EOF

Un autre exemple, tout en étant root, créez un Quadlet où les utilisateurs de ce conteneur sont autorisés à exécuter des conteneurs avec séparation SELinux et peuvent lire et écrire du contenu dans le répertoire $HOME/data.

# useradd -s /usr/bin/podmansh fullu
# grep fullu /etc/passwd
fullu:x:4010:4010::/home/fullu:/usr/bin/podmansh
# USERID=$(id -u fullu)
# mkdir -p /etc/containers/systemd/users/${USERID}
# cat > /etc/containers/systemd/users/${USERID}/podmansh.container << _EOF
[Unit]
Description=Le conteneur podmansh
After=local-fs.target
[Container]
Image=registry.fedoraproject.org/fedora
ContainerName=podmansh
UserNS=keep-id
RunInit=yes
PodmanArgs=--security-opt=unmask=/sys/fs/selinux   
	--security-opt=label=nested   
	--security-opt=label=user:container_user_u   
	--security-opt=label=type:container_user_t   
	--security-opt=label=role:container_user_r   
	--security-opt=label=level:s0-s0:c0.c1023
Volume=%h/data:%h:Z
WorkingDir=%h
Volume=/sys/fs/selinux:/sys/fs/selinux
Exec=sleep infinity
[Service]
ExecStartPre=/usr/bin/mkdir -p %h/data
[Install]
RequiredBy=default.target
_EOF
