NOM

podman-artifact-push - Pousse un artefact OCI depuis le stockage local vers un registre d'images

SYNOPSIS

podman artifact push [options] image

DESCRIPTION

Pousse un artefact depuis le magasin d'artefacts local vers un registre d'images.

# Pousse un artefact vers un registre de conteneurs
$ podman artifact push quay.io/artifact/foobar1:latest

OPTIONS

--authfile=chemin

Chemin du fichier d'authentification. Par défaut, il s'agit de ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation ne s'y trouve pas, $HOME/.docker/config.json est vérifié, qui est défini à l'aide de docker login.

Note : Il existe également une option pour remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Ceci peut être fait en exécutant export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utilise les certificats situés dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exclusion de WSL2))

--creds=[nom d'utilisateur[:mot de passe]]

Le [nom d'utilisateur[:mot de passe]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou deux valeurs ne sont pas fournies, une invite de commande apparaît et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les informations d'identification spécifiées sont uniquement utilisées pour authentifier les registres cibles. Elles ne sont pas utilisées pour les miroirs ou lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour vous authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--digestfile=FichierDigeste

Après avoir copié l'image, écrit le digeste de l'image résultante dans le fichier.

--quiet, -q

Lors de l'écriture de l'image de sortie, supprime les indications de progression

--retry=tentatives

Nombre de tentatives pour tirer ou pousser des images entre le registre et le stockage local en cas d'échec. La valeur par défaut est 3.

--retry-delay=durée

Durée du délai entre les tentatives de téléchargement ou de poussée d'images entre le registre et le stockage local en cas d'échec. Par défaut, le délai commence à deux secondes puis augmente exponentiellement. Le délai est utilisé lorsque cette valeur est définie et qu'aucun délai exponentiel ne se produit.

--sign-by=clé

Ajoute une signature « simple signature » à la destination en utilisant la clé spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exclusion de WSL2))

--sign-by-sigstore=fichier-param

Ajoute une signature sigstore basée sur des options supplémentaires spécifiées dans un fichier de paramètres de signature sigstore du conteneur fichier-param. Voir containers-sigstore-signing-params.yaml(5) pour plus de détails sur le format du fichier.

--sign-by-sigstore-private-key=chemin

Ajoute une signature sigstore à la destination en utilisant une clé privée située au chemin spécifié. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exclusion de WSL2))

--sign-by-sq-fingerprint=empreinte

Ajoute une signature « simple signature » en utilisant une clé Sequoia-PGP avec l'empreinte spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exclusion de WSL2))

--sign-passphrase-file=chemin

Si l'image est signée (en utilisant --sign-by, sign-by-sq-fingerprint ou --sign-by-sigstore-private-key), lit le mot de passe à utiliser à partir du chemin spécifié.

--tls-verify

Exige HTTPS et vérifie les certificats lors du contact avec les registres (défaut : true). S'il est explicitement défini sur true, la vérification TLS est utilisée. S'il est défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée à moins que le registre cible ne soit listé comme registre non sécurisé dans containers-registries.conf(5)

EXEMPLE

Pousse l'image spécifiée vers un registre de conteneurs :

$ podman artifact push quay.io/baude/artifact:single
Getting image source signatures
Copying blob 3ddc0a3cdb61 done   |
Copying config 44136fa355 done   |
Writing manifest to image destination
