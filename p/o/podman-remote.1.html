podman-remote(1) Manuel des commandes générales podman-remote(1)

NOM

podman-remote - Une CLI distante pour Podman : un outil de gestion simple pour les pods, les conteneurs et les images.

SYNTAXE

podman-remote [options] commande

DESCRIPTION

Podman (Pod Manager) est un moteur de conteneurisation complet, un outil simple et sans démon. Podman fournit une ligne de commande comparable à Docker-CLI, ce qui facilite la transition depuis d'autres moteurs de conteneurisation et permet la gestion des pods, des conteneurs et des images. En bref : alias docker=podman. La plupart des commandes Podman peuvent être exécutées en tant qu'utilisateur ordinaire, sans nécessiter de privilèges supplémentaires.

Podman utilise Buildah(1) en interne pour créer des images de conteneur. Les deux outils partagent le stockage des images (pas des conteneurs), donc chacun peut utiliser ou manipuler les images (mais pas les conteneurs) créées par l'autre.

Podman-remote fournit un client local interagissant avec un nœud backend Podman via une API RESTful tunnellisée par une connexion SSH. Dans ce contexte, un nœud Podman est un système Linux avec Podman installé et le service API activé. Les informations d'identification pour cette session peuvent être passées via des indicateurs, des variables d'environnement ou dans containers.conf.

Le fichier containers.conf est situé sous $HOME/.config/containers/containers.conf sous Linux et Mac, et %APPDATA%\containers\containers.conf sous Windows.

podman [OPTIONS GLOBALES]

OPTIONS GLOBALES

--connection=nom, -c

Nom de la connexion distante

Remplace la variable d'environnement CONTAINER_CONNECTION si elle est définie.

--help, -h

Afficher le message d'utilisation

--identity=chemin

Chemin vers le fichier d'identité SSH. Si le fichier d'identité est chiffré, Podman invite l'utilisateur à saisir la phrase secrète. Si aucun fichier d'identité n'est fourni et qu'aucun utilisateur n'est spécifié, Podman utilise par défaut l'utilisateur exécutant la commande podman. Podman demande le mot de passe de connexion sur le serveur distant.

Priorité de résolution de la valeur d'identité :
- valeur de la ligne de commande
- variable d'environnement CONTAINER_SSHKEY, si CONTAINER_HOST est trouvée
- containers.conf

--log-level=niveau

Niveau des messages de journalisation : debug, info, warn, error (par défaut), fatal ou panic

--url=valeur

URL pour accéder au service Podman (par défaut à partir de containers.conf, pour l'utilisateur sans privilèges "unix:///run/user/$UID/podman/podman.sock" ou en tant que root "unix:///run/podman/podman.sock").

  • CONTAINER_HOST est du format <schéma>://[<utilisateur[:<mot de passe>]@]<hôte>[:<port>][<chemin>]
  • CONTAINER_PROXY est du format <socks5|socks5h>://[<utilisateur[:<mot de passe>]@]<hôte>[:<port>]

Détails :
- schéma est l'un des suivants :
* ssh (par défaut) : un socket Unix local (7) sur l'hôte et le port nommés, accessible via SSH
* tcp : une connexion TCP non chiffrée et non authentifiée vers l'hôte et le port nommés, peut fonctionner avec un proxy si CONTAINER_PROXY est défini
* unix : un socket Unix local (7) à l'chemin spécifié, ou le défaut pour l'utilisateur
- utilisateur correspond par défaut à root ou à l'utilisateur en cours d'exécution (uniquement ssh)
- mot de passe n'a pas de valeur par défaut (uniquement ssh)
- hôte doit être fourni et est soit l'IP soit le nom de la machine hébergeant le service Podman (ssh et tcp)
- port correspond par défaut à 22 (ssh et tcp)
- chemin correspond par défaut à /run/podman/podman.sock, ou /run/user/$UID/podman/podman.sock si exécuté sans privilèges (unix), ou doit être explicitement spécifié (ssh)
- CONTAINER_PROXY : utiliser un proxy (socks5 ou socks5h) pour accéder au service Podman (uniquement tcp)

Priorité de résolution de la valeur URL :
- valeur de la ligne de commande
- variable d'environnement CONTAINER_HOST
- table engine.service_destinations dans containers.conf, à l'exclusion du répertoire /usr/share/containers
- unix:///run/podman/podman.sock

Les connexions distantes utilisent le containers.conf local pour les valeurs par défaut.

Quelques exemples de valeurs d'URL dans des formats valides :
- unix:///run/podman/podman.sock
- unix:///run/user/$UID/podman/podman.sock
- ssh://notroot@localhost:22/run/user/$UID/podman/podman.sock
- ssh://root@localhost:22/run/podman/podman.sock
- tcp://localhost:34451
- tcp://127.0.0.1:34451

--version

Afficher la version

Variables d'environnement

Podman peut définir des variables d'environnement à partir de la table env de [engine] dans containers.conf. Ces variables peuvent être remplacées en passant des variables d'environnement avant les commandes podman.

CONTAINERS_CONF

Définir les emplacements par défaut du fichier containers.conf

CONTAINER_CONNECTION

Définir la valeur par défaut de --connection pour accéder au service Podman.

CONTAINER_HOST

Définir la valeur par défaut de --url pour accéder au service Podman.

CONTAINER_SSHKEY

Définir le chemin par défaut de --identity vers le fichier de clé SSH utilisé pour accéder au service Podman.

Codes de sortie

Le code de sortie de podman donne des informations sur la raison pour laquelle le conteneur n'a pas pu s'exécuter ou pourquoi il s'est arrêté. Lorsque les commandes podman se terminent avec un code non nul, les codes de sortie suivent le standard chroot, voir ci-dessous :

125 L'erreur concerne podman lui-même

$ podman run --foo busybox; echo $?
Error: unknown flag: --foo
125

126 Exécution d'une commande contenue et la commande ne peut pas être invoquée

$ podman run busybox /etc; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"/etc\": permission denied": OCI runtime error
126

127 Exécution d'une commande contenue et la commande ne peut pas être trouvée
$ podman run busybox foo; echo $?
Error: container_linux.go:346: starting container process caused "exec: \"foo\": executable file not found in $PATH": OCI runtime error
127

Code de sortie code de sortie de la commande contenue

$ podman run busybox /bin/sh -c 'exit 3'; echo $?
3

NAME

podman-info — Display Podman related system information.

SYNOPSIS

podman info [ -a | --all ] [ -e | --debug ] [ -f | --format FORMAT ] [ -p | --containers ] [ -q | --quiet ] [ -s | --storage ] [ -v | --version ] [ -x | --sysinfo ] [ -h | --help ]

DESCRIPTION

The podman info command displays system-wide information about Podman, including information about the Podman server, storage driver, storage, etc. The output is typically in JSON format.

GLOBAL OPTIONS

These options are available on most Podman commands.

-a, --all
Print all information.
-e, --debug
Print debug information.
-f, --format FORMAT
Format the output using the given Go template, e.g. 'table {{.ID}} {{.Image}}'. The default is 'table {{.ID}} {{.Image}} {{.Command}} {{.Status}} {{.Ports}}'.
-p, --containers
Print information about containers.
-q, --quiet
Quiet mode - suppress informational messages and only print error messages.
-s, --storage
Print information about storage.
-v, --version
Print version information.
-x, --sysinfo
Print system information.

Environment Variables

See podman(1) for environment variables that are supported by Podman.

Exit Status

Exit status is 0 on success, non-zero on failure.

FILES

containers.conf ($HOME/.config/containers/containers.conf)

Podman has builtin defaults for command line options. These defaults can be overridden using the containers.conf configuration files.

Users can modify defaults by creating the $HOME/.config/containers/containers.conf file. Podman merges its builtin defaults with the specified fields from this file, if it exists. Fields specified in the users file override the built-in defaults.

Podman uses builtin defaults if no containers.conf file is found.
