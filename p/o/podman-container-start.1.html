podman-start(1) Manuel des commandes générales podman-start(1)

NOM

podman-start - Démarrer un ou plusieurs conteneurs

SYNTAXE

podman start [options] conteneur ...

podman container start [options] conteneur ...

DESCRIPTION

Démarre un ou plusieurs conteneurs en utilisant les identifiants de conteneur ou les noms comme entrée. Les options attach et interactive ne peuvent pas être utilisées pour remplacer les options --tty et --interactive définies lors de la création du conteneur. Si un conteneur déjà en cours d'exécution est démarré avec l'option --attach, Podman s'y attache simplement.

OPTIONS

--all

Démarre tous les conteneurs, par défaut seuls les conteneurs en cours d'exécution.

--attach, -a

Attache la sortie standard (STDOUT) et la sortie d'erreur standard (STDERR) du conteneur. La valeur par défaut est false. Cette option ne peut pas être utilisée lors du démarrage de plusieurs conteneurs.

--detach-keys=séquence

Spécifie la séquence de touches pour détacher un conteneur. Le format est un seul caractère [a-Z] ou un ou plusieurs caractères ctrl-<valeur> où <valeur> est l'un des caractères suivants : a-z, @, ^, [, , ou _. Spécifier "" désactive cette fonctionnalité. La valeur par défaut est ctrl-p,ctrl-q.

Cette option peut également être configurée dans le fichier containers.conf(5).

--filter, -f

Filtre les conteneurs qui vont être démarrés à partir des arguments fournis. Plusieurs filtres peuvent être donnés en utilisant l'indicateur --filter plusieurs fois. Les filtres ayant la même clé fonctionnent de manière inclusive, à l'exception de label qui est exclusif. Les filtres ayant des clés différentes fonctionnent toujours de manière exclusive.

Les filtres valides sont listés ci-dessous :

Filtre Description
id [ID] Identifiant du conteneur (correspondance partielle par défaut du préfixe CID ; accepte les expressions régulières)
name [Nom] Nom du conteneur (accepte les expressions régulières)
label [Clé] ou [Clé=Valeur] Étiquette attribuée à un conteneur
exited [Entier] Code de sortie du conteneur
status [Statut] Statut du conteneur : 'created', 'initialized', 'exited', 'paused', 'running', 'unknown'
ancestor [NomImage] Image ou descendant utilisé pour créer le conteneur
before [ID] ou [Nom] Conteneurs créés avant ce conteneur
since [ID] ou [Nom] Conteneurs créés depuis ce conteneur
volume [NomVolume] ou [PointMontageDestination] Volume monté dans le conteneur
health [Statut] healthy ou unhealthy
pod [Pod] nom ou identifiant complet ou partiel du pod
network [Réseau] nom ou identifiant complet du réseau
until [DateTime] Conteneurs créés avant la durée ou l'heure donnée.
command [Commande] La commande exécutée par le conteneur, seul argv[0] est pris en compte

--interactive, -i

Lorsqu'elle est définie sur true, rend la connexion standard d'entrée (stdin) disponible pour le processus contenu. Si false, la connexion standard d'entrée du processus contenu est vide et fermée immédiatement.

Si attaché, stdin est redirigé vers le processus contenu. Si détaché, la lecture de stdin sera bloquée jusqu'à une attache ultérieure.

Attention : Podman consommera les entrées de stdin dès qu'elles seront disponibles, même si le processus contenu ne les demande pas.

--latest, -l

Au lieu de fournir le nom ou l'identifiant du conteneur, utilisez le dernier conteneur créé. Note : le dernier conteneur démarré peut provenir d'autres utilisateurs de Podman sur la machine hôte. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exclusion de WSL2))

--sig-proxy

Redirige les signaux reçus vers le processus du conteneur. SIGCHLD, SIGURG, SIGSTOP et SIGKILL ne sont pas redirigés.

La valeur par défaut est true lors de l'attachement, false sinon.

EXEMPLE

Démarrer un conteneur spécifié :

podman start monserveurweb

Démarrer plusieurs conteneurs :

podman start 860a4b231279 5421ab43b45

Démarrer le conteneur spécifié en mode interactif avec le terminal attaché :

podman start --interactive --attach 860a4b231279

Démarrer le dernier conteneur créé en mode interactif (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (à l'exclusion de WSL2)) :

podman start -i -l

Démarrer des conteneurs par étiquette :

$ podman start --filter label=app=frontend
9351ccb3ef4272532bc0c188bd4f0ddfc2b0de217732cd108259ea126b014647

Démarrer un conteneur par nom :

$ podman start --filter name=backend-app1

Démarrer des conteneurs par statut :

$ podman start --filter status=exited
