posix_memalign(3) Manuel des fonctions de bibliothèque posix_memalign(3)

NOM

posix_memalign, aligned_alloc, memalign, valloc, pvalloc - allouer de la mémoire alignée

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS

#include <stdlib.h>
int posix_memalign(void **memptr, size_t alignment, size_t size);
void *aligned_alloc(size_t alignment, size_t size);
[[deprecated]] void *valloc(size_t size);
#include <malloc.h>
[[deprecated]] void *memalign(size_t alignment, size_t size);
[[deprecated]] void *pvalloc(size_t size);
Exigences pour les macros de test de fonctionnalités dans glibc (voir feature_test_macros(7)):

posix_memalign():

    _POSIX_C_SOURCE >= 200112L

aligned_alloc():

    _ISOC11_SOURCE

valloc():

    Depuis glibc 2.12:
        (_XOPEN_SOURCE >= 500) && !(_POSIX_C_SOURCE >= 200112L)
            || /* glibc >= 2.19: */ _DEFAULT_SOURCE
            || /* glibc <= 2.19: */ _SVID_SOURCE || _BSD_SOURCE
    Avant glibc 2.12:
        _BSD_SOURCE || _XOPEN_SOURCE >= 500

DESCRIPTION

posix_memalign() alloue size octets et place l'adresse de la mémoire allouée dans *memptr. L'adresse de la mémoire allouée sera un multiple de alignment, qui doit être une puissance de deux et un multiple de sizeof(void *). Cette adresse peut plus tard être passée avec succès à free(3). Si size est 0, alors la valeur placée dans *memptr est soit NULL, soit une valeur de pointeur unique.

La fonction obsolète memalign() alloue size octets et retourne un pointeur vers la mémoire allouée. L'adresse mémoire sera un multiple de alignment, qui doit être une puissance de deux.

aligned_alloc() est identique à memalign(), à l'exception de la restriction supplémentaire selon laquelle alignment doit être une puissance de deux.

La fonction obsolète valloc() alloue size octets et retourne un pointeur vers la mémoire allouée. L'adresse mémoire sera un multiple de la taille de page. Elle est équivalente à memalign(sysconf(_SC_PAGESIZE),size).

La fonction obsolète pvalloc() est similaire à valloc(), mais arrondit la taille de l'allocation au multiple suivant de la taille de page système.

Pour toutes ces fonctions, la mémoire n'est pas initialisée à zéro.

VALEUR DE RETOUR

aligned_alloc(), memalign(), valloc() et pvalloc() retournent un pointeur vers la mémoire allouée en cas de succès. En cas d'erreur, NULL est retourné et errno est défini pour indiquer l'erreur.

posix_memalign() retourne zéro en cas de succès, ou l'une des valeurs d'erreur listées dans la section suivante en cas d'échec. La valeur de errno n'est pas définie. Sous Linux (et d'autres systèmes), posix_memalign() ne modifie pas memptr en cas d'échec. Une exigence standardisant ce comportement a été ajoutée dans POSIX.1-2008 TC2.

ERREURS

EINVAL
L'argument alignment n'était pas une puissance de deux, ou n'était pas un multiple de sizeof(void *).
ENOMEM
Pas assez de mémoire.

En-têtes

Tout le monde s'accorde à dire que posix_memalign() est déclarée dans <stdlib.h>.

Sur certains systèmes, memalign() est déclarée dans <stdlib.h> au lieu de <malloc.h>.

Selon SUSv2, valloc() est déclarée dans <stdlib.h>. glibc la déclare dans <malloc.h>, et également dans <stdlib.h> si des macros de test de fonctionnalités appropriées sont définies (voir ci-dessus).

NOTES

Sur de nombreux systèmes, il existe des restrictions d'alignement, par exemple, sur les tampons utilisés pour les E/S directes de blocs. POSIX spécifie l'appel pathconf(path,_PC_REC_XFER_ALIGN) qui indique l'alignement requis. Désormais, on peut utiliser posix_memalign() pour satisfaire cette exigence.

posix_memalign() vérifie que alignment correspond aux exigences détaillées ci-dessus. memalign() peut ne pas vérifier que l'argument alignment est correct.

POSIX exige que la mémoire obtenue à partir de posix_memalign() puisse être libérée en utilisant free(3). Certains systèmes ne fournissent aucun moyen de récupérer la mémoire allouée avec memalign() ou valloc() (car on ne peut passer à free(3) qu'un pointeur obtenu de malloc(3), tandis que, par exemple, memalign() appellerait malloc(3) puis alignerait la valeur obtenue). L'implémentation glibc permet de récupérer la mémoire obtenue à partir de l'une de ces fonctions avec free(3).

Le malloc(3) de glibc retourne toujours des adresses de mémoire alignées sur 8 octets, donc ces fonctions ne sont nécessaires que si vous avez besoin de valeurs d'alignement plus grandes.
