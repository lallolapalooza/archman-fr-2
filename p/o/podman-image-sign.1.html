podman-image-sign(1) Manuel des commandes générales podman-image-sign(1)

NOM

podman-image-sign - Créer une signature pour une image

SYNTAXE

podman image sign [options] image [image ...]

DESCRIPTION

podman image sign crée une signature locale pour une ou plusieurs images locales qui ont été tirées d'un registre. La signature est écrite dans un répertoire dérivé des fichiers de configuration du registre dans $HOME/.config/containers/registries.d s'il existe, sinon /etc/containers/registries.d (sauf indication contraire à la compilation), voir containers-registries.d(5) pour plus d'informations. Par défaut, la signature est écrite dans /var/lib/containers/sigstore pour l'utilisateur root et dans $HOME/.local/share/containers/sigstore pour les utilisateurs non root.

OPTIONS

--all, -a

Signer tous les manifestes de l'image multi-architecture (par défaut : faux).

--authfile=chemin

Chemin du fichier d'authentification. Par défaut : ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'y est pas trouvé, $HOME/.docker/config.json est vérifié, ce qui est défini à l'aide de docker login.

Note : Il existe également une option pour remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Cela peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utiliser les certificats dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2)).

--directory, -d=répertoire

Stocker les signatures dans le répertoire spécifié. Défaut : /var/lib/containers/sigstore

--help, -h

Afficher le message d'utilisation.

--sign-by=identité

Remplacer l'identité par défaut de la signature.

EXEMPLES

Signer l'image busybox avec l'identité foo@bar.com en utilisant le trousseau de clés d'un utilisateur et enregistrer la signature dans /tmp/signatures/.

   $ sudo podman image sign --sign-by foo@bar.com --directory /tmp/signatures docker://privateregistry.example.com/foobar
   $ sudo podman image sign --authfile=/tmp/foobar.json --sign-by foo@bar.com --directory /tmp/signatures docker://privateregistry.example.com/foobar

CONFIGURATION LIÉE

L'emplacement d'écriture (et de lecture) des signatures est défini dans des fichiers de configuration basés sur YAML dans /etc/containers/registries.d/ pour l'utilisateur root, ou $HOME/.config/containers/registries.d pour les utilisateurs non root. Lors de la signature d'une image, Podman utilise ces fichiers de configuration pour déterminer où écrire la signature en fonction du nom du registre d'origine ou d'une valeur de stockage par défaut, sauf indication contraire avec l'option --directory. Par exemple, considérez le fichier de configuration suivant.

docker:
  privateregistry.example.com:
    sigstore: file:///var/lib/containers/sigstore

Lors de la signature d'une image précédée du nom du registre 'privateregistry.example.com', la signature est écrite dans des sous-répertoires de /var/lib/containers/sigstore/privateregistry.example.com. L'utilisation de 'sigstore' signifie également que la signature est 'lue' depuis ce même emplacement lors d'une fonction liée au tirage.

VOIR AUSSI
