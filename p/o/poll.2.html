poll(2) Manuel des appels système poll(2)

NOM

poll, ppoll — attendre qu'un événement se produise sur un descripteur de fichier

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <poll.h>
int poll(struct pollfd *fds, nfds_t nfds, int timeout);
#define _GNU_SOURCE         /* Voir feature_test_macros(7) */
#include <poll.h>
int ppoll(struct pollfd *fds, nfds_t nfds,
          const struct timespec *_Nullable tmo_p,
          const sigset_t *_Nullable sigmask);

DESCRIPTION

poll() effectue une tâche similaire à select(2) : il attend qu'un des descripteurs de fichiers d'un ensemble devienne prêt pour effectuer des opérations d'E/S. L'API spécifique à Linux epoll(7) effectue une tâche similaire, mais offre des fonctionnalités au-delà de celles trouvées dans poll().

L'ensemble des descripteurs de fichiers à surveiller est spécifié dans l'argument fds, qui est un tableau de structures de la forme suivante :


struct pollfd {
    int   fd;         /* descripteur de fichier */
    short events;     /* événements demandés */
    short revents;    /* événements retournés */
};

L'appelant doit spécifier le nombre d'éléments dans le tableau fds dans nfds.

Le champ fd contient un descripteur de fichier pour un fichier ouvert. Si ce champ est négatif, alors le champ events correspondant est ignoré et le champ revents retourne zéro. (Cela fournit un moyen simple d'ignorer un descripteur de fichier pour un seul appel poll() : il suffit de définir le champ fd à son complément bit à bit.)

Le champ events est un paramètre d'entrée, un masque de bits spécifiant les événements qui intéressent l'application pour le descripteur de fichier fd. Ce champ peut être spécifié comme zéro, auquel cas les seuls événements qui peuvent être retournés dans revents sont POLLHUP, POLLERR et POLLNVAL (voir ci-dessous).

Le champ revents est un paramètre de sortie, rempli par le noyau avec les événements qui se sont réellement produits. Les bits retournés dans revents peuvent inclure n'importe lequel de ceux spécifiés dans events, ou l'une des valeurs POLLERR, POLLHUP, ou POLLNVAL. (Ces trois bits n'ont aucune signification dans le champ events, et seront définis dans le champ revents chaque fois que la condition correspondante est vraie.)

Si aucun des événements demandés (et aucune erreur) ne s'est produit pour l'un des descripteurs de fichiers, alors poll() se bloque jusqu'à ce que l'un des événements se produise.

Être "prêt" signifie que l'opération demandée ne bloquera pas ; ainsi, faire un poll() sur des fichiers réguliers, des périphériques blocs et d'autres fichiers sans sémantique de polling raisonnable renvoie toujours instantanément comme étant prêt à lire et écrire.

Notez que l'intervalle timeout sera arrondi à la granularité de l'horloge système, et les délais de planification du noyau signifient que l'intervalle de blocage peut dépasser légèrement. Spécifier une valeur négative dans timeout signifie un timeout infini. Spécifier un timeout de zéro fait que poll() retourne immédiatement, même si aucun descripteur de fichier n'est prêt.

Les bits qui peuvent être définis/retournés dans events et revents sont définis dans <poll.h> :

POLLIN
Il y a des données à lire.
POLLPRI
Il y a une condition exceptionnelle sur le descripteur de fichier. Les possibilités incluent :
•
Il y a des données hors bande sur une socket TCP (voir tcp(7)).
•
Un maître de pseudo-terminal en mode paquet a détecté un changement d'état sur le pseudo-terminal esclave (voir ioctl_tty(2)).
•
Un fichier cgroup.events a été modifié (voir cgroups(7)).
POLLOUT
L'écriture est maintenant possible, bien qu'une écriture plus importante que l'espace disponible dans une socket ou un tube bloquera toujours (sauf si O_NONBLOCK est défini).
POLLRDHUP (depuis Linux 2.6.17)
La connexion de l'homologue de la socket de flux est fermée, ou la moitié d'écriture de la connexion est fermée. Le macro de test de fonctionnalité _GNU_SOURCE doit être défini (avant d'inclure tous les fichiers d'en-tête) pour obtenir cette définition.
POLLERR
Condition d'erreur (seulement retourné dans revents ; ignoré dans events). Ce bit est aussi défini pour un descripteur de fichier faisant référence à l'extrémité d'écriture d'un tube lorsque l'extrémité de lecture a été fermée.
POLLHUP
Raccrochage (seulement retourné dans revents ; ignoré dans events). Notez que lors de la lecture d'un canal tel qu'un tube ou une socket de flux, cet événement indique simplement que l'homologue a fermé son extrémité du canal. Les lectures ultérieures du canal retourneront 0 (fin de fichier) seulement après que toutes les données en attente dans le canal aient été consommées.
POLLNVAL
Requête invalide : fd non ouvert (seulement retourné dans revents ; ignoré dans events).

Lors de la compilation avec _XOPEN_SOURCE défini, on a également les éléments suivants, qui ne fournissent aucune information supplémentaire au-delà des bits listés ci-dessus :

POLLRDNORM
Équivalent à POLLIN.
POLLRDBAND
Des données de bande prioritaire peuvent être lues (généralement non utilisées sous Linux).
POLLWRNORM
Équivalent à POLLOUT.
POLLWRBAND
Des données prioritaires peuvent être écrites.

Linux connaît également, mais n'utilise pas, POLLMSG.

ppoll()

La relation entre poll() et ppoll() est analogue à la relation entre select(2) et pselect(2) : comme pselect(2), ppoll() permet à une application d'attendre de manière sûre jusqu'à ce qu'un descripteur de fichier devienne prêt ou jusqu'à ce qu'un signal soit capturé.

Outre la différence de précision de l'argument timeout, l'appel ppoll() suivant :


ready = ppoll(&fds, nfds, tmo_p, &sigmask);

est presque équivalent à l'exécution atomique des appels suivants :


sigset_t origmask;
int timeout;
timeout = (tmo_p == NULL) ? -1 :
          (tmo_p->tv_sec * 1000 + tmo_p->tv_nsec / 1000000);
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = poll(&fds, nfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

Le segment de code ci-dessus est décrit comme presque équivalent car, alors qu'une valeur de timeout négative pour poll() est interprétée comme un timeout infini, une valeur négative exprimée dans *tmo_p résulte en une erreur de ppoll().

Voir la description de pselect(2) pour une explication de la nécessité de ppoll().

Si l'argument sigmask est spécifié comme NULL, alors aucune manipulation de masque de signal n'est effectuée (et donc ppoll() diffère de poll() uniquement par la précision de l'argument timeout).

L'argument tmo_p spécifie une limite supérieure sur la durée pendant laquelle ppoll() se bloquera. Cet argument est un pointeur vers une structure timespec(3).

Si tmo_p est spécifié comme NULL, alors ppoll() peut se bloquer indéfiniment.

VALEUR DE RETOUR

En cas de succès, poll() renvoie le nombre d'événements prêts qui se sont produits (ce nombre peut être supérieur au nombre de structures pollfd qui ont été modifiées si le descripteur de fichier spécifié dans fds était négatif). Si un délai d'attente expire avant que tout événement ne devienne prêt, poll() renvoie 0.

En cas d'erreur, poll() renvoie -1 et errno est définie pour indiquer l'erreur.

Les erreurs suivantes peuvent être définies dans errno :

EAGAIN
Aucun descripteur de fichier n'est prêt et le délai d'attente était nul.
EBADF
Un des descripteurs de fichiers dans fds n'est pas valide.
EINTR
Un signal a interrompu le retour de l'appel. Le tableau fds n'est pas mis à jour.
EINVAL
L'argument nfds est supérieur au nombre maximal de descripteurs de fichiers autorisés, ou l'argument timeout est invalide (par exemple, il spécifie une durée négative en millisecondes, sauf si c'est interprété comme infini).
ENOMEM
Mémoire insuffisante disponible pour allouer des structures internes.
POLL_ERROR
Une erreur s'est produite.

ERREURS

Voir poll(3) pour la liste des erreurs.

CONFORMITÉ

Les spécifications POSIX.1-2001 et POSIX.1-2008 définissent la fonctionnalité de poll(). Les définitions supplémentaires POLLRDHUP, POLLWRNORM, POLLWRBAND, POLLRDBAND, POLLRDNORM sont considérées comme des extensions.

La fonction ppoll() est spécifique à Linux.

NOTES

La valeur de retour de poll() est le nombre total d'événements prêts, pas le nombre d'appels réussis.

L'utilisation de fd=−1 dans une structure pollfd est une manière portable de désactiver temporairement une entrée : l'appelant peut définir fd à sa complémentation bit à bit (par exemple, `~0`) dans un argument events, et poll() ignorera cette entrée. Le champ revents sera mis à zéro pour cette entrée.

Si le timeout est 0, poll() ne bloque pas. Si le timeout est -1, poll() attend indéfiniment.

Pour les fichiers réguliers, les périphériques blocs et la plupart des autres types de fichiers, les opérations de lecture et d'écriture ne bloquent jamais. Ainsi, les événements POLLIN et POLLOUT seront toujours signalés pour ces types de fichiers.

Il est possible de recevoir des événements autres que ceux demandés dans le champ events. En particulier, les bits POLLERR et POLLHUP peuvent être définis dans revents même s'ils n'ont pas été demandés dans events. Il est donc important de tester le champ revents pour chacun des descripteurs de fichiers.

Si poll() retourne un nombre d'événements non nul, mais que les champs revents de toutes les structures pollfd sont nuls, cela signifie que certains descripteurs de fichiers sont invalides.

L'argument nfds spécifie la taille du tableau fds. Le noyau itère sur les nfds premiers éléments du tableau fds. Si l'un des fd vaut -1, alors events et revents pour cette entrée sont ignorés.

Les différents bits de masque d'événements (par exemple, POLLIN, POLLOUT) sont des constantes définies dans <poll.h>.

Si la valeur de retour de poll() est positive et que certains événements se sont produits, le noyau peut réinitialiser les champs revents pour les descripteurs de fichiers où des événements se sont produits. L'application peut vérifier si tous les événements demandés ont été traités en comparant le nombre d'événements retournés avec le nombre d'événements effectivement traités.

ppoll() notes

L'argument tmo_p pour ppoll() est un pointeur vers une structure timespec. La précision de ppoll() est nettement meilleure que celle de poll().

Voir aussi select(2), epoll(7), poll.h(3).

VALEUR DE RETOUR

En cas de succès, poll() renvoie une valeur non négative qui est le nombre d'éléments dans pollfds dont les champs revents ont été définis à une valeur non nulle (indiquant un événement ou une erreur). Une valeur de retour de zéro indique que l'appel système a expiré avant que des descripteurs de fichiers ne soient prêts.

En cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
fds pointe en dehors de l'espace d'adressage accessible du processus. Le tableau donné en argument n'était pas contenu dans l'espace d'adressage du programme appelant.
EINTR
Un signal est survenu avant tout événement demandé ; voir signal(7).
EINVAL
La valeur nfds dépasse la valeur RLIMIT_NOFILE.
EINVAL
(ppoll()) La valeur de temporisation exprimée dans *tmo_p est invalide (négative).
ENOMEM
Impossible d'allouer de la mémoire pour les structures de données du noyau.

VERSIONS

Sur certains autres systèmes UNIX, poll() peut échouer avec l'erreur EAGAIN si le système ne parvient pas à allouer des ressources internes au noyau, au lieu de ENOMEM comme Linux. POSIX permet ce comportement. Les programmes portables peuvent vouloir vérifier EAGAIN et boucler, tout comme avec EINTR.

Certaines implémentations définissent la constante non standard INFTIM avec la valeur -1 pour être utilisée comme timeout pour poll(). Cette constante n'est pas fournie dans glibc.

Différences bibliothèque C/noyau

L'appel système Linux ppoll() modifie son argument tmo_p. Cependant, la fonction d'enrobage glibc masque ce comportement en utilisant une variable locale pour l'argument de temporisation qui est passé à l'appel système. Ainsi, la fonction glibc ppoll() ne modifie pas son argument tmo_p.

L'appel système brut ppoll() a un cinquième argument, size_t sigsetsize, qui spécifie la taille en octets de l'argument sigmask. La fonction d'enrobage glibc ppoll() spécifie cet argument comme une valeur fixe (égale à sizeof(kernel_sigset_t)). Voir sigprocmask(2) pour une discussion sur les différences entre la notion de sigset du noyau et celle de libc.

HISTORIQUE

POSIX.1-2001. Linux 2.1.23.
Sur les anciens noyaux qui n'ont pas cet appel système, la fonction d'enrobage glibc poll() fournit une émulation utilisant select(2).

NOTES

L'opération de poll() et ppoll() n'est pas affectée par le drapeau O_NONBLOCK.

Pour une discussion sur ce qui peut arriver si un descripteur de fichier surveillé par poll() est fermé dans un autre thread, voir select(2).

BOGUES

Voir la discussion sur les notifications de disponibilité fallacieuses sous la section BUGS de select(2).

EXEMPLES

Le programme ci-dessous ouvre chacun des fichiers nommés dans ses arguments de ligne de commande et surveille les descripteurs de fichiers résultants pour la disponibilité en lecture (POLLIN). Le programme boucle, utilisant répétitivement poll() pour surveiller les descripteurs de fichiers, affichant le nombre de descripteurs de fichiers prêts au retour. Pour chaque descripteur de fichier prêt, le programme :

•
affiche le champ revents renvoyé sous une forme lisible ;
•
si le descripteur de fichier est lisible, lit des données à partir de celui-ci et affiche ces données sur la sortie standard ;
•
si le descripteur de fichier n'était pas lisible, mais qu'un autre événement s'est produit (probablement POLLHUP), ferme le descripteur de fichier.

Supposons que nous exécutons le programme dans un terminal, lui demandant d'ouvrir un FIFO :


$ mkfifo myfifo;
$ ./poll_input myfifo;

Dans une deuxième fenêtre de terminal, nous ouvrons alors le FIFO en écriture, écrivons des données dedans, et fermons le FIFO :


$ echo aaaaabbbbbccccc > myfifo;

Dans le terminal où nous exécutons le programme, nous verrions alors :


Opened "myfifo" on fd 3
About to poll()
Ready: 1
  fd=3; events: POLLIN POLLHUP
    read 10 bytes: aaaaabbbbb
About to poll()
Ready: 1
  fd=3; events: POLLIN POLLHUP
    read 6 bytes: ccccc
About to poll()
Ready: 1
  fd=3; events: POLLHUP
    closing fd 3
All file descriptors closed.  Bye.

Dans la sortie ci-dessus, nous voyons que poll() est retourné trois fois :

•
Lors du premier retour, les bits renvoyés dans le champ revents étaient POLLIN, indiquant que le descripteur de fichier est lisible, et POLLHUP, indiquant que l'autre extrémité du FIFO a été fermée. Le programme a alors consommé une partie de l'entrée disponible.
•
Le deuxième retour de poll() a également indiqué POLLIN et POLLHUP ; le programme a alors consommé le reste de l'entrée disponible.
•
Lors du dernier retour, poll() n'a indiqué que POLLHUP sur le FIFO, moment auquel le descripteur de fichier a été fermé et le programme terminé.

Source du programme

/* poll_input.c
   Licensed under GNU General Public License v2 or later.
*/
#include <err.h>
#include <fcntl.h>
#include <poll.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    int            ready;
    char           buf[10];
    nfds_t         num_open_fds, nfds;
    ssize_t        s;
    struct pollfd  *pfds;
    if (argc < 2) {
       fprintf(stderr, "Usage: %s file...\n", argv[0]);
       exit(EXIT_FAILURE);
    }
    num_open_fds = nfds = argc - 1;
    pfds = calloc(nfds, sizeof(struct pollfd));
    if (pfds == NULL)
        err(EXIT_FAILURE, "malloc");
    /* Open each file on command line, and add it to 'pfds' array.  */
    for (nfds_t j = 0; j < nfds; j++) {
        pfds[j].fd = open(argv[j + 1], O_RDONLY);
        if (pfds[j].fd == -1)
            err(EXIT_FAILURE, "open");
        printf("Opened \"%s\" on fd %d\n", argv[j + 1], pfds[j].fd);
        pfds[j].events = POLLIN;
    }
    /* Keep calling poll() as long as at least one file descriptor is
       open.  */
    while (num_open_fds > 0) {
        printf("About to poll()\n");
        ready = poll(pfds, nfds, -1);
        if (ready == -1)
            err(EXIT_FAILURE, "poll");
        printf("Ready: %d\n", ready);
        /* Deal with array returned by poll().  */
        for (nfds_t j = 0; j < nfds; j++) {
            if (pfds[j].revents != 0) {
                printf("  fd=%d; events: %s%s%s\n", pfds[j].fd,
                       (pfds[j].revents & POLLIN)  ? "POLLIN "  : "",
                       (pfds[j].revents & POLLHUP) ? "POLLHUP " : "",
                       (pfds[j].revents & POLLERR) ? "POLLERR " : "");
                if (pfds[j].revents & POLLIN) {
                    s = read(pfds[j].fd, buf, sizeof(buf));
                    if (s == -1)
                        err(EXIT_FAILURE, "read");
                    printf("    read %zd bytes: %.*s\n",
                           s, (int) s, buf);
                } else {                /* POLLERR | POLLHUP */
                    printf("    closing fd %d\n", pfds[j].fd);
                    if (close(pfds[j].fd) == -1)
                        err(EXIT_FAILURE, "close");
                    num_open_fds--;
                }
            }
        }
    }
    printf("All file descriptors closed.  Bye.\n");
    exit(EXIT_SUCCESS);
}
