podman-start(1) Manuel des commandes générales podman-start(1)

NOM

podman-start - Démarre un ou plusieurs conteneurs

SYNTAXE

podman start [options] conteneur ...

podman container start [options] conteneur ...

DESCRIPTION

Démarre un ou plusieurs conteneurs en utilisant les identifiants de conteneur ou leurs noms comme entrée. Les options attach et interactive ne peuvent pas être utilisées pour remplacer les options --tty et --interactive définies lors de la création du conteneur. En démarrant un conteneur déjà en cours d'exécution avec l'option --attach, Podman s'attache simplement au conteneur.

OPTIONS

--all

Démarre tous les conteneurs. Par défaut, seuls les conteneurs en cours d'exécution sont démarrés.

--attach, -a

Attache la sortie standard (STDOUT) et la sortie d'erreur standard (STDERR) du conteneur. La valeur par défaut est false. Cette option ne peut pas être utilisée lors du démarrage de plusieurs conteneurs.

--detach-keys=séquence

Spécifie la séquence de touches pour détacher un conteneur. Le format est un seul caractère [a-Z] ou un ou plusieurs caractères ctrl-<valeur> où <valeur> est l'un des caractères suivants : a-z, @, ^, [, , ou _. Spécifier "" désactive cette fonctionnalité. La valeur par défaut est ctrl-p,ctrl-q.

Cette option peut également être configurée dans le fichier containers.conf(5).

--filter, -f

Filtre les conteneurs qui seront démarrés à partir des arguments donnés. Plusieurs filtres peuvent être spécifiés en utilisant plusieurs fois l'option --filter. Les filtres ayant la même clé fonctionnent de manière inclusive, à l'exception de label qui est exclusif. Les filtres avec des clés différentes fonctionnent toujours de manière exclusive.

Les filtres valides sont listés ci-dessous :

Filtre Description
id [ID] Identifiant du conteneur (correspondance partielle du préfixe CID par défaut ; accepte les expressions régulières)
name [Nom] Nom du conteneur (accepte les expressions régulières)
label [Clé] ou [Clé=Valeur] Étiquette attribuée à un conteneur
exited [Int] Code de sortie du conteneur
status [Statut] Statut du conteneur : 'created', 'initialized', 'exited', 'paused', 'running', 'unknown'
ancestor [NomImage] Image ou descendant utilisé pour créer le conteneur
before [ID] ou [Nom] Conteneurs créés avant ce conteneur
since [ID] ou [Nom] Conteneurs créés depuis ce conteneur
volume [NomVolume] ou [PointMontageDestination] Volume monté dans le conteneur
health [Statut] healthy ou unhealthy
pod [Pod] nom ou identifiant complet ou partiel du pod
network [Réseau] nom ou identifiant complet du réseau
until [DateTime] Conteneurs créés avant la durée ou l'heure spécifiée.
command [Commande] la commande exécutée par le conteneur, seul argv[0] est pris en compte

--interactive, -i

Lorsque définie sur true, rend l'entrée standard (stdin) disponible pour le processus contenu. Si définie sur false, l'entrée standard du processus contenu est vide et immédiatement fermée.

Si attaché, l'entrée standard est transmise au processus contenu. Si détaché, la lecture de l'entrée standard sera bloquée jusqu'à ce qu'elle soit attachée ultérieurement.

Attention : Podman consommera les entrées depuis l'entrée standard dès qu'elles seront disponibles, même si le processus contenu ne les demande pas.

--latest, -l

Au lieu de fournir le nom ou l'identifiant du conteneur, utilise le dernier conteneur créé. Note : le dernier conteneur démarré peut appartenir à d'autres utilisateurs de Podman sur la machine hôte. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2)).

--sig-proxy

Transmet les signaux reçus au processus du conteneur. SIGCHLD, SIGURG, SIGSTOP et SIGKILL ne sont pas transmis.

La valeur par défaut est true lorsqu'on est attaché, false sinon.

EXEMPLE

Démarrer un conteneur spécifié :

podman start monwebserver

Démarrer plusieurs conteneurs :

podman start 860a4b231279 5421ab43b45

Démarrer un conteneur spécifié en mode interactif avec le terminal attaché :

podman start --interactive --attach 860a4b231279

Démarrer le dernier conteneur créé en mode interactif (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2)) :

podman start -i -l

Démarrer des conteneurs par étiquette :

$ podman start --filter label=app=frontend
9351ccb3ef4272532bc0c188bd4f0ddfc2b0de217732cd108259ea126b014647

Démarrer un conteneur par nom :

$ podman start --filter name=backend-app1
93308911bd4769cda03b75eb7f56588e862e0ea3568f25e1e3defa4138b9b973

Démarrer des conteneurs par statut :

$ podman start --filter status=exited
f8e85f84a749b205fb602895afa6ec8a866045ff27b82f843033712c8b93a2c9
34f997d354017a0076402c3a79245a5b8bd11b597c84385bec25ae8941fd5238
47972eb04aa7c77705b597a929957d1e8a392e00b44c0a2a7f88a01f9f860d11

Démarrer un conteneur par nom :

$ podman start --filter name=backend-app1
93308911bd4769cda03b75eb7f56588e862e0ea3568f25e1e3defa4138b9b973

Démarrer des conteneurs par volume :

$ podman start --filter volume=web-vol
4a3332649ed8bec1e0d82e113074b9a13d45582007aeac969c005992cc480a73

Démarrer un conteneur par réseau :

$ podman start --filter network=web-net
4a3332649ed8bec1e0d82e113074b9a13d45582007aeac969c005992cc480a73
f8e85f84a749b205fb602895afa6ec8a866045ff27b82f843033712c8b93a2c9

Démarrer un conteneur par ancêtre :

$ podman start --filter ancestor=nginx
4a3332649ed8bec1e0d82e113074b9a13d45582007aeac969c005992cc480a73
