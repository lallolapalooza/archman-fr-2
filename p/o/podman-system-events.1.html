NOM

podman-events - Surveiller les événements Podman

SYNTAXE

podman events [options]

podman system events [options]

DESCRIPTION

Surveille et affiche les événements qui se produisent dans Podman. Chaque événement comprend un horodatage, un type, un statut, un nom (le cas échéant) et une image (le cas échéant). Le mécanisme de journalisation par défaut est journald. Cela peut être modifié dans containers.conf en changeant la valeur de events_logger en file. Seuls file et journald sont acceptés. Un logger none est également disponible, mais ce mécanisme de journalisation désactive complètement les événements ; rien n'est rapporté par podman events.

Par défaut, le mode de diffusion est utilisé, affichant les nouveaux événements au fur et à mesure de leur apparition. Les événements précédents peuvent être répertoriés via --since et --until.

Le type d'événement container signale les statuts suivants :
* attach
* checkpoint
* cleanup
* commit
* connect
* create
* died
* disconnect
* exec
* exec_died
* exited
* export
* import
* init
* kill
* mount
* pause
* prune
* remove
* rename
* restart
* restore
* start
* stop
* sync
* unmount
* unpause
* update

Le type d'événement pod signale les statuts suivants :
* create
* kill
* pause
* remove
* start
* stop
* unpause

Le type d'événement image signale les statuts suivants :
* loadFromArchive,
* mount
* pull
* pull-error
* push
* remove
* save
* tag
* unmount
* untag

Le type system signale les statuts suivants :
* refresh
* renumber

Le type volume signale les statuts suivants :
* create
* prune
* remove

Le type secret signale les statuts suivants :
* create
* remove

Événements Create Détaillés

Définir events_container_create_inspect_data=true dans containers.conf(5) demande à Podman de créer des événements container-create plus détaillés qui incluent une charge utile JSON avec des informations détaillées sur le conteneur. La charge utile JSON est identique à celle de podman-container-inspect(1). Le champ associé dans journald est nommé PODMAN_CONTAINER_INSPECT_DATA.

OPTIONS

--filter, -f=filtre

Filtre les événements affichés. Ils doivent être au format "filtre=valeur". Les filtres suivants sont pris en charge :

Filtre Description
container [Nom ou ID] Nom ou ID du conteneur
event event_status (décrit ci-dessus)
image [Nom ou ID] Nom ou ID de l'image
label [clé] ou [clé=valeur] label
pod [Nom ou ID] Nom ou ID du pod
volume [Nom ou ID] Nom ou ID du volume
type Event_type (décrit ci-dessus)

Dans le cas où un ID est utilisé, l'ID peut être sous sa forme complète ou abrégée. L'événement "die" est mappé à "died" pour la compatibilité avec Docker.

--format

Formate la sortie en lignes JSON ou en utilisant le modèle Go donné.

Placeholder Description
.Attributes ... created_at, _by, labels, et plus (map[])
.ContainerExitCode Code de sortie (int)
.ContainerInspectData Charge utile de l'inspection du conteneur
.Error Message d'erreur en cas de statut d'événement d'erreur (par ex. pull-error)
.HealthStatus Statut de santé (chaîne)
.ID ID du conteneur (SHA complet 64 bits)
.Image Nom de l'image en cours d'exécution (chaîne)
.Name Nom du conteneur (chaîne)
.Network Nom du réseau utilisé (chaîne)
.PodID ID du pod associé au conteneur, le cas échéant
.Status Statut de l'événement (par ex., create, start, died, ...)
.Time Horodatage de l'événement (chaîne)
.TimeNano Horodatage de l'événement avec précision nanoseconde (int64)
.Type Type d'événement (par ex., image, conteneur, pod, ...)

--help

Affiche le message d'utilisation.

--no-trunc

Ne pas tronquer la sortie (par défaut true).

--since=horodatage

Afficher tous les événements créés depuis l'horodatage donné

--stream

Diffuser les événements et ne pas quitter après avoir lu le dernier événement connu (par défaut true).

--until=horodatage

Afficher tous les événements créés jusqu'à l'horodatage donné

Les valeurs since et until peuvent être des horodatages au format RFC3339Nano ou une chaîne de durée Go telle que 10m, 5h. Si aucune valeur since ou until n'est fournie, seuls les nouveaux événements sont affichés.

IDENTIFIANTS JOURNALD

Le backend d'événements journald de Podman utilise les identifiants journald suivants. Vous pouvez utiliser ces identifiants pour filtrer directement les événements Podman avec journalctl.

Identifiant Description
SYSLOG_IDENTIFIER Toujours défini sur "podman"
PODMAN_EVENT Le statut de l'événement tel que décrit ci-dessus
PODMAN_TYPE Le type d'événement tel que décrit ci-dessus
PODMAN_TIME L'horodatage de l'écriture de l'événement
PODMAN_NAME Nom de l'objet de l'événement (par ex., conteneur, image)
PODMAN_ID ID de l'objet de l'événement (par ex., conteneur, image)
PODMAN_EXIT_CODE Code de sortie du conteneur
PODMAN_POD_ID ID du pod du conteneur
PODMAN_LABELS Labels du conteneur
PODMAN_HEALTH_STATUS Statut de santé du conteneur
PODMAN_CONTAINER_INSPECT_DATA La charge utile JSON de podman-inspect telle que décrite ci-dessus
PODMAN_NETWORK_NAME Nom du réseau

Nom

podman-system-events - Afficher des événements du système Podman

Synopsis

podman system events [options]

Description

La commande podman system events diffuse en continu des événements du système Podman en temps réel.

Les événements sont décrits par leur ID, leur nom, le type d'objet (conteneur, pod, volume, etc.), le nom de l'image associée et le statut de l'événement.

Options

--all, -a
Ne pas filtrer les événements par type. Tous les événements sont affichés.
--cert-dir <chemin>
Chemin vers les certificats de connexion TLS.
--cont-cri-path <chemin>
Chemin vers le socket CRI pour les conteneurs.
--filter, -f <filtre>

Filtrer les événements par un attribut spécifié.

Les filtres disponibles sont :

event
L'événement qui s'est produit. Valeurs possibles : create, destroy, die, kill, mount, oom, prune, restart, start, stop, unmount, update.
id
L'ID du conteneur ou du pod.
image
Le nom de l'image.
label
Label appliqué à un objet.
name
Le nom du conteneur ou du pod.
type
Le type de l'objet. Valeurs possibles : container, image, pod, volume.
--format <format>

Formater la sortie. Les valeurs possibles sont :

json
Sortie au format JSON Lines.
--help, -h
Imprimer un message d'aide.
--latest, -l
Afficher l'événement du dernier objet créé.
--since <timestamp>
Afficher les événements survenus après un timestamp donné. Le timestamp peut être un nom de temps relatif (par exemple, 5m, 1h) ou un timestamp absolu (par exemple, 2019-04-27T22:47:00Z).
--until <timestamp>
Afficher les événements survenus avant un timestamp donné. Le timestamp peut être un nom de temps relatif (par exemple, 5m, 1h) ou un timestamp absolu (par exemple, 2019-04-27T22:47:00Z).

IDENTIFIANTS JOURNALD

Les événements Podman sont écrits dans le journal systemd. Les valeurs _SYSTEMD_UNIT et CONTAINER_NAME sont définies pour les événements de conteneurs.

Vous pouvez utiliser journalctl pour afficher les événements Podman.

$ sudo journalctl -f -o cat -n 0 _SYSTEMD_UNIT=podman.service
