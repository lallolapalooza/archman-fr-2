podman-manifest-push(1) Manuel des commandes générales podman-manifest-push(1)

NOM

podman-manifest-push - Pousse une liste de manifestes ou un index d'images vers un registre

SYNTAXE

podman manifest push [options] nomdelalisteouindex [destination]

DESCRIPTION

Pousse une liste de manifestes ou un index d'images vers un registre.

VALEUR DE RETOUR

L'ID de l'image de la liste et le digest du manifeste de l'image.

OPTIONS

--add-compression=compression

S'assure que la variante de compression demandée pour chaque plateforme est ajoutée à la liste des manifestes, en conservant l'instance originale intacte dans la même liste de manifestes. Les valeurs prises en charge sont (gzip, zstd et zstd:chunked). L'indicateur suivant peut être utilisé plusieurs fois.

Notez que --compression-format contrôle le format de compression de chaque instance dans la liste des manifestes. --add-compression ajoutera une autre variante pour chaque instance de la liste avec les compressions spécifiées. Utiliser --compression-format gzip --add-compression zstd poussera une liste de manifestes où chaque instance est compressée avec gzip, plus une variante supplémentaire de chaque instance compressée avec zstd.

--all

Pousse les images mentionnées dans la liste des manifestes ou l'index d'images, en plus de la liste ou de l'index lui-même. (Par défaut vrai)

--authfile=chemin

Chemin du fichier d'authentification. Par défaut, ${XDG_RUNTIME_DIR}/containers/auth.json sous Linux, et $HOME/.config/containers/auth.json sous Windows/macOS. Le fichier est créé par podman login. Si l'état d'autorisation n'y est pas trouvé, $HOME/.docker/config.json est vérifié, qui est défini à l'aide de docker login.

Note : Il existe également la possibilité de remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. Ceci peut être fait avec export REGISTRY_AUTH_FILE=chemin.

--cert-dir=chemin

Utilise les certificats dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. (Par défaut : /etc/containers/certs.d) Pour plus de détails, voir containers-certs.d(5). (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--compression-format=gzip | zstd | zstd:chunked

Spécifie le format de compression à utiliser. Les valeurs prises en charge sont : gzip, zstd et zstd:chunked. La valeur par défaut est gzip sauf si elle est remplacée dans le fichier containers.conf. zstd:chunked est incompatible avec le chiffrement des images et sera traité comme zstd avec un avertissement dans ce cas.

--compression-level=niveau

Spécifie le niveau de compression à utiliser. La valeur est spécifique à l'algorithme de compression utilisé, par exemple, pour zstd les valeurs acceptées sont dans la plage 1-20 (inclusive) avec une valeur par défaut de 3, tandis que pour gzip, c'est 1-9 (inclusif) avec une valeur par défaut de 5.

--creds=[nomutilisateur[:motdepasse]]

Le [nomutilisateur[:motdepasse]] à utiliser pour s'authentifier auprès du registre, si nécessaire. Si une ou deux valeurs ne sont pas fournies, une invite de commande s'affiche et la valeur peut être saisie. Le mot de passe est saisi sans écho.

Notez que les identifiants spécifiés sont uniquement utilisés pour l'authentification auprès des registres cibles. Ils ne sont pas utilisés pour les miroirs ou lorsque le registre est réécrit (voir containers-registries.conf(5)) ; pour s'authentifier auprès de ceux-ci, envisagez d'utiliser un fichier containers-auth.json(5).

--digestfile=FichierDigest

Après avoir copié l'image, écrit le digest de l'image résultante dans le fichier.

--force-compression

Si défini, la poussée utilise l'algorithme de compression spécifié même si la destination contient déjà une variante compressée différemment. Par défaut, il vaut true si --compression-format est explicitement spécifié sur la ligne de commande, sinon false.

--format, -f=format

Type de liste de manifestes (oci ou v2s2) à utiliser lors de la poussée de la liste (par défaut oci).

--quiet, -q

Lors de l'écriture du manifeste, supprime la sortie de progression

--remove-signatures

Ne copie pas les signatures lors de la poussée des images.

--rm

Supprime la liste des manifestes ou l'index d'images du stockage local si la poussée réussit.

--sign-by=empreinte

Signe les images poussées avec une signature « simple signature » à l'aide de la clé spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--sign-by-sigstore=param-file

Ajoute une signature sigstore basée sur des options supplémentaires spécifiées dans un fichier de paramètres de signature sigstore du conteneur param-file. Voir containers-sigstore-signing-params.yaml(5) pour plus de détails sur le format du fichier.

--sign-by-sigstore-private-key=chemin

Signe les images poussées avec une signature sigstore à l'aide d'une clé privée située au chemin spécifié. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--sign-by-sq-fingerprint=empreinte

Ajoute une signature « simple signature » à l'aide d'une clé Sequoia-PGP avec l'empreinte spécifiée. (Cette option n'est pas disponible avec le client Podman distant, y compris les machines Mac et Windows (hors WSL2))

--sign-passphrase-file=chemin

Si l'image est signée (en utilisant --sign-by, sign-by-sq-fingerprint ou --sign-by-sigstore-private-key), lit la phrase de passe à utiliser à partir du chemin spécifié.

--tls-verify

Exige HTTPS et vérifie les certificats lors du contact avec les registres (par défaut : true). S'il est explicitement défini sur true, la vérification TLS est utilisée. S'il est défini sur false, la vérification TLS n'est pas utilisée. Si non spécifié, la vérification TLS est utilisée, sauf si le registre cible est répertorié comme un registre non sécurisé dans containers-registries.conf(5)

DESTINATION

DESTINATION est l'emplacement vers lequel l'image de conteneur est poussée. Elle prend en charge tous les transports de containers-transports(5). Si aucun transport n'est spécifié, le transport docker (c'est-à-dire le registre de conteneurs) est utilisé. Pour les clients distants, y compris les machines Mac et Windows (hors WSL2), docker est le seul transport pris en charge.

EXEMPLES

Pousse une liste de manifestes vers un registre de conteneurs :

podman manifest push mylist:v1.11 docker://registry.example.org/mylist:v1.11
