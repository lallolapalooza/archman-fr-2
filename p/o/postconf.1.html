POSTCONF(1) Manuel des commandes générales POSTCONF(1)

NOM

postconf - Utilitaire de configuration Postfix

SYNTAXE

Gestion de main.cf :

postconf [-dfhHnopqvx] [-c répertoire_config] [-C classe,...] [paramètre ...]

postconf [-epv] [-c répertoire_config] paramètre=valeur ...

postconf -# [-pv] [-c répertoire_config] paramètre ...

postconf -X [-pv] [-c répertoire_config] paramètre ...

Gestion des entrées de service master.cf :

postconf -M [-foqvx] [-c répertoire_config] [service[/type] ...]

postconf -M [-ev] [-c répertoire_config] service/type=valeur ...

postconf -M# [-v] [-c répertoire_config] service/type ...

postconf -MX [-v] [-c répertoire_config] service/type ...

Gestion des champs de service master.cf :

postconf -F [-fhHoqvx] [-c répertoire_config] [service[/type[/champ]] ...]

postconf -F [-ev] [-c répertoire_config] service/type/champ=valeur ...

Gestion des paramètres de service master.cf :

postconf -P [-fhHoqvx] [-c répertoire_config] [service[/type[/paramètre]] ...]

postconf -P [-ev] [-c répertoire_config] service/type/paramètre=valeur ...

postconf -PX [-v] [-c répertoire_config] service/type/paramètre ...

Gestion des modèles de messages de rebond :

postconf -b [-v] [-c répertoire_config] [fichier_modèle]

postconf -t [-v] [-c répertoire_config] [fichier_modèle]

Gestion des fonctionnalités TLS :

postconf -T mode [-v] [-c répertoire_config]

Gestion d'autres configurations :

postconf -a|-A|-l|-m [-v] [-c répertoire_config]

DESCRIPTION


Par défaut, la commande postconf(1) affiche les valeurs des paramètres de configuration de main.cf, et émet un avertissement concernant les noms de paramètres potentiellement mal orthographiés (Postfix 2.9 et versions ultérieures). La commande peut également modifier les valeurs des paramètres de configuration de main.cf, ou afficher d'autres informations de configuration du système de messagerie Postfix.

Options :

-a
Lister les types de plug-in SASL disponibles pour le serveur SMTP Postfix. Le type de plug-in est sélectionné avec le paramètre de configuration smtpd_sasl_type en spécifiant l'un des noms listés ci-dessous.
cyrus
Ce plug-in serveur est disponible lorsque Postfix est compilé avec le support de Cyrus SASL.
dovecot
Ce plug-in serveur utilise le serveur d'authentification Dovecot, et est disponible lorsque Postfix est compilé avec une forme quelconque de support SASL.
Cette fonctionnalité est disponible avec Postfix 2.3 et versions ultérieures.
-A
Lister les types de plug-in SASL disponibles pour le client SMTP Postfix. Le type de plug-in est sélectionné avec les paramètres de configuration smtp_sasl_type ou lmtp_sasl_type en spécifiant l'un des noms listés ci-dessous.
cyrus
Ce plug-in client est disponible lorsque Postfix est compilé avec le support de Cyrus SASL.
Cette fonctionnalité est disponible avec Postfix 2.3 et versions ultérieures.
-b [fichier_modèle]
Afficher le texte du message qui apparaît au début des messages de notification d'état de livraison (DSN), en développant les expressions $nom avec les valeurs réelles comme décrit dans bounce(5).

Pour remplacer le paramètre bounce_template_file, spécifiez un nom de fichier modèle à la fin de la commande "postconf -b". Spécifiez un nom de fichier vide pour afficher les modèles intégrés (en langage shell : "").

Cette fonctionnalité est disponible avec Postfix 2.3 et versions ultérieures.

-c répertoire_config
Le fichier de configuration main.cf se trouve dans le répertoire nommé au lieu du répertoire de configuration par défaut.
-C classe,...
Lors de l'affichage des paramètres de main.cf, ne sélectionnez que les paramètres des classes spécifiées :
builtin
Paramètres avec des noms intégrés.
service
Paramètres avec des noms définis par le service (le premier champ d'une entrée master.cf plus un suffixe défini par Postfix).
user
Paramètres avec des noms définis par l'utilisateur.
all
Toutes les classes ci-dessus.
La valeur par défaut est comme si "-C all" était spécifié.

Cette fonctionnalité est disponible avec Postfix 2.9 et versions ultérieures.

-d
Afficher les paramètres par défaut de main.cf au lieu des paramètres réels. Spécifiez -df pour plier les lignes longues pour une lisibilité humaine (Postfix 2.9 et versions ultérieures).
-e
Modifier le fichier de configuration main.cf, et mettre à jour les paramètres avec les paires "nom=valeur" sur la ligne de commande de postconf(1).

Avec -M, modifier le fichier de configuration master.cf, et remplacer une ou plusieurs entrées de service par de nouvelles valeurs comme spécifié avec "service/type=valeur" sur la ligne de commande de postconf(1).

Avec -F, modifier le fichier de configuration master.cf, et remplacer un ou plusieurs champs de service par de nouvelles valeurs comme spécifié avec "service/type/champ=valeur" sur la ligne de commande de postconf(1). Actuellement, le champ "commande" contient le nom de la commande et ses arguments. Ceci peut changer dans un avenir proche, afin que le champ "commande" ne contienne que le nom de la commande, et un nouveau pseudo-champ "arguments" contienne les arguments de la commande.

Avec -P, modifier le fichier de configuration master.cf, et ajouter ou mettre à jour un ou plusieurs paramètres de service (-o paramètre=valeur) avec de nouvelles valeurs comme spécifié avec "service/type/paramètre=valeur" sur la ligne de commande de postconf(1).

Dans tous les cas, le fichier est copié dans un fichier temporaire puis renommé en place. Spécifiez des guillemets pour protéger les caractères spéciaux et les espaces sur la ligne de commande de postconf(1).

L'option -e n'est plus nécessaire avec Postfix version 2.8 et ultérieures, car elle est supposée chaque fois qu'une valeur est spécifiée (vide ou non vide).

-f
Plier les lignes longues lors de l'affichage des entrées du fichier de configuration main.cf ou master.cf, pour une lisibilité humaine.

Cette fonctionnalité est disponible avec Postfix 2.9 et versions ultérieures.

-F
Afficher les paramètres de champ par entrée de master.cf (par défaut tous les services et tous les champs), formatés comme "service/type/champ=valeur", un par ligne. Spécifiez -Ff pour plier les lignes longues.

Spécifiez une ou plusieurs instances "service/type/champ" sur la ligne de commande de postconf(1) p o limite la sortie aux champs d'intérêt. Les champs de nom de paramètre ou de type de service suivants qui sont omis seront traités comme des champs jokers « * ».

Cette fonctionnalité est disponible à partir de Postfix 2.11.

-h
Affiche les valeurs des paramètres ou attributs sans l'étiquette « nom = » qui précède normalement la valeur.
-H
Affiche les noms des paramètres ou attributs sans le « = valeur » qui suit normalement le nom.

Cette fonctionnalité est disponible à partir de Postfix 3.1.

-l
Liste les noms de toutes les méthodes de verrouillage de boîte aux lettres supportées. Postfix supporte les méthodes suivantes :
flock
Une méthode de verrouillage consultatif basée sur le noyau pour les fichiers locaux uniquement. Cette méthode de verrouillage est disponible sur les systèmes dotés d'une bibliothèque compatible BSD.
fcntl
Une méthode de verrouillage consultatif basée sur le noyau pour les fichiers locaux et distants.
dotlock
Une méthode de verrouillage au niveau de l'application. Une application verrouille un fichier nommé nom_fichier en créant un fichier nommé nom_fichier.lock. L'application est censée supprimer son propre fichier de verrouillage, ainsi que les fichiers de verrouillage obsolètes qui ont été laissés après une terminaison anormale du programme.
-m
Liste les noms de tous les types de tables de recherche supportés. Dans les fichiers de configuration Postfix, les tables de recherche sont spécifiées sous la forme type:nom, où type est l'un des types listés ci-dessous. La syntaxe du nom de la table dépend du type de table de recherche, comme décrit dans le document DATABASE_README.
btree
Une structure d'arbre trié et équilibré. Disponible sur les systèmes qui supportent les bases de données Berkeley DB.
cdb
Une structure optimisée en lecture sans support des mises à jour incrémentielles. Disponible sur les systèmes qui supportent les bases de données CDB.

Cette fonctionnalité est disponible à partir de Postfix 2.2.

cidr
Une table qui associe des valeurs à des modèles CIDR (Classless Inter-Domain Routing). Ceci est décrit dans cidr_table(5).

Cette fonctionnalité est disponible à partir de Postfix 2.2.

dbm
Un type de fichier indexé basé sur le hachage. Disponible sur les systèmes qui supportent les bases de données DBM.
environ
Le tableau d'environnement du processus UNIX. La clé de recherche est le nom de la variable d'environnement ; le nom de la table est ignoré. Initialement implémenté pour les tests, quelqu'un pourrait trouver cela utile un jour.
fail
Une table qui échoue de manière fiable à toutes les requêtes. Le nom de la table de recherche est utilisé pour la journalisation. Cette table existe pour simplifier les tests d'erreurs Postfix.

Cette fonctionnalité est disponible à partir de Postfix 2.9.

hash
Un type de fichier indexé basé sur le hachage. Disponible sur les systèmes qui supportent les bases de données Berkeley DB.
inline (en lecture seule)
Une table de recherche en mémoire non partagée. Exemple : « inline:{ clé=valeur, { clé = texte avec espaces blancs ou virgule }} ». Les paires clé-valeur sont séparées par des espaces blancs ou une virgule ; avec une paire clé-valeur à l'intérieur de « {} », les espaces blancs sont ignorés après le « { » d'ouverture, autour du « = » entre la clé et la valeur, et avant le « } » de fermeture. Les tables inline éliminent le besoin de créer un fichier de base de données pour seulement quelques éléments fixes. Voir aussi le type de table static:.

Cette fonctionnalité est disponible à partir de Postfix 3.0.

internal
Une table de hachage en mémoire non partagée. Son contenu est perdu lorsqu'un processus se termine.
lmdb
Client de base de données LMDB d'OpenLDAP (un fichier persistant mappé en mémoire). Disponible sur les systèmes qui supportent les bases de données LMDB. Ceci est décrit dans lmdb_table(5).

Cette fonctionnalité est disponible à partir de Postfix 2.11.

ldap (en lecture seule)
Client de base de données LDAP. Ceci est décrit dans ldap_table(5).
memcache
Client de base de données Memcache. Ceci est décrit dans memcache_table(5).

Cette fonctionnalité est disponible à partir de Postfix 2.9.

mongodb
Client de base de données MongoDB. Ceci est décrit dans mongodb_table(5).

Cette fonctionnalité est disponible à partir de Postfix 3.9.

mysql (en lecture seule)
Client de base de données MySQL. Disponible sur les systèmes qui supportent les bases de données MySQL. Ceci est décrit dans mysql_table(5).
pcre (en lecture seule)
Une table de recherche basée sur des expressions régulières compatibles Perl. Le format du fichier est décrit dans pcre_table(5).
pgsql (en lecture seule)
Client de base de données PostgreSQL. Ceci est décrit dans pgsql_table(5).

Cette fonctionnalité est disponible à partir de Postfix 2.1.

pipemap (en lecture seule)
Une table de recherche qui construit un pipeline de tables. Exemple : « pipemap:{type_1:nom_1, ..., type_n:nom_n} ». Chaque requête « pipemap: » est transmise à la première table. Chaque résultat de recherche devient la requête pour la table suivante dans le pipeline, et la dernière table produit le résultat final. Lorsqu'une recherche dans une table ne produit aucun résultat, le pipeline ne produit aucun résultat. Le premier et le dernier caractère du nom de la table « pipemap: » doivent être « { » et « } ». À l'intérieur, les cartes individuelles sont séparées par une virgule ou un espace blanc.

Cette fonctionnalité est disponible à partir de Postfix 3.0.

proxy
Client Postfix proxymap(8) pour un accès partagé aux bases de données Postfix. La syntaxe du nom de la table est type:nom.

Cette fonctionnalité est disponible à partir de Postfix 2.0.

randmap (en lecture seule)
Une table en mémoire qui effectue une sélection aléatoire. Exemple : « randmap:{résultat_1, ..., résultat_n} ». Chaque requête de table retourne un choix aléatoire parmi les résultats spécifiés. Le premier et le dernier caractère du nom de la table « randmap: » doivent être « { » et « } ». À l'intérieur, les résultats individuels sont séparés par une virgule ou un espace blanc. Pour donner plus de poids à un résultat spécifique, spécifiez-le plusieurs fois.

Cette fonctionnalité est disponible à partir de Postfix 3.0.

regexp (en lecture seule)
Une table de recherche basée sur des expressions régulières. Le format du fichier est décrit dans regexp_table(5).
sdbm
Un type de fichier indexé basé sur le hachage. Disponible sur les systèmes qui supportent les bases de données SDBM.

Cette fonctionnalité est disponible à partir de Postfix 2.2.

socketmap (en lecture seule)
Client socketmap de style Sendmail. Le nom de la table est inet:hôte:port:nom pour un serveur TCP/IP, ou unix:chemin_accesseur:nom pour un serveur de domaine UNIX. Ceci est décrit dans socketmap_table(5).

Cette fonctionnalité est disponible à partir de Postfix 2.10.

sqlite (en lecture seule)
Base de données SQLite. Ceci est décrit dans sqlite_table(5).

Cette fonctionnalité est disponible à partir de Postfix 2.8.

static (en lecture seule)
Une table qui retourne toujours son nom comme résultat de recherche. Par exemple, static:foobar retourne toujours la chaîne foobar comme résultat de recherche. Spécifiez « static:{ texte avec espaces blancs } » lorsque le résultat contient des espaces blancs ; cette forme ignore les espaces blancs après le « { » d'ouverture et avant le « } » de fermeture. Voir aussi la table inline:.

La forme « static:{texte} est disponible à partir de Postfix 3.0.

tcp (en lecture seule)
Client TCP/IP. Le protocole est décrit dans tcp_table(5).
texthash (en lecture seule)
Produit des résultats similaires aux fichiers hash:, sauf qu'il n'est pas nécessaire d'exécuter la commande postmap(1) avant de pouvoir utiliser le fichier, et qu'il ne détecte pas les changements après la lecture du fichier.

Cette fonctionnalité est disponible à partir de Postfix 2.8.

unionmap (en lecture seule)
Une table qui envoie chaque requête à plusieurs tables de recherche et qui concatène tous les résultats trouvés, séparés par une virgule. La syntaxe du nom de la table est la même que pour pipemap.

Cette fonctionnalité est disponible à partir de Postfix 3.0.

unix (en lecture seule)
Une vue limitée de la base de données d'authentification UNIX. Les tables suivantes sont implémentées :
unix:passwd.byname
La table est la base de données des mots de passe UNIX. La clé est un nom de connexion. Le résultat est une entrée du fichier de mots de passe dans passwd(5).
>passwd(5).
unix:group.byname
La table est la base de données de groupe UNIX. La clé est un nom de groupe. Le résultat est une entrée de fichier de groupe au format group(5).
D'autres types de tables peuvent exister en fonction de la façon dont Postfix a été compilé.
-M
Affiche le contenu du fichier master.cf au lieu du contenu du fichier main.cf. Spécifiez -Mf pour plier les lignes longues pour une meilleure lisibilité humaine.

Spécifiez zéro ou plusieurs arguments, chacun avec une paire nom-service ou nom-service/type-service, où nom-service est le premier champ d'une entrée master.cf et type-service est l'un des (inet, unix, fifo, ou pass).

Si nom-service ou nom-service/type-service est spécifié, seules les entrées master.cf correspondantes seront affichées. Par exemple, "postconf -Mf smtp" affichera tous les services nommés "smtp", et "postconf -Mf smtp/inet" n'affichera que le service smtp qui écoute sur le réseau. Les champs de type de service finaux qui sont omis seront traités comme des champs génériques "*".

Cette fonctionnalité est disponible avec Postfix 2.9 et versions ultérieures. La syntaxe a été modifiée de "name.type" à "name/type", et le support des jokers "*" a été ajouté avec Postfix 2.11.

-n
Affiche uniquement les paramètres de configuration qui ont des réglages explicites name=value dans main.cf. Spécifiez -nf pour plier les lignes longues pour une meilleure lisibilité humaine (Postfix 2.9 et versions ultérieures). Pour afficher uniquement les paramètres qui diffèrent des valeurs par défaut intégrées, utilisez la syntaxe bash suivante : 
    LANG=C comm -23 <(postconf -n) <(postconf -d)
Remplacez "-23" par "-12" pour afficher les paramètres qui dupliquent les valeurs par défaut intégrées.
-o name=value
Remplace les réglages des paramètres de main.cf. Cela vous permet de voir l'effet que aurait le changement d'un paramètre lorsqu'il est utilisé dans d'autres paramètres de configuration, par exemple : 
    postconf -x -o stress=yes

Cette fonctionnalité est disponible avec Postfix 2.10 et versions ultérieures.

-p
Affiche les réglages des paramètres de main.cf. C'est le comportement par défaut.

Cette fonctionnalité est disponible avec Postfix 2.11 et versions ultérieures.

-P
Affiche les réglages des paramètres de service de master.cf (par défaut tous les services et tous les paramètres), formatés comme "service/type/paramètre=valeur", un par ligne. Spécifiez -Pf pour plier les lignes longues.

Spécifiez une ou plusieurs instances "service/type/paramètre" sur la ligne de commande postconf(1) pour limiter la sortie aux paramètres d'intérêt. Les champs finaux de nom de paramètre ou de type de service qui sont omis seront traités comme des champs génériques "*".

Cette fonctionnalité est disponible avec Postfix 2.11 et versions ultérieures.

-q
Ne pas enregistrer les avertissements pour les paramètres obsolètes ou inutilisés.

Cette fonctionnalité est disponible avec Postfix 3.9 et versions ultérieures.

-t [fichier_modèle]
Affiche les modèles pour le texte qui apparaît au début des messages de notification de statut de livraison (DSN), sans développer les expressions $nom.

Pour remplacer le réglage du paramètre bounce_template_file, spécifiez un nom de fichier modèle à la fin de la ligne de commande "postconf -t". Spécifiez un nom de fichier vide pour afficher les modèles intégrés (en langage shell : "").

Cette fonctionnalité est disponible avec Postfix 2.3 et versions ultérieures.

-T mode
Si Postfix est compilé sans support TLS, l'option -T ne produit aucune sortie. Sinon, si un mode invalide est spécifié, l'option -T signale une erreur et se termine avec un code d'état non nul. Les modes valides sont :
compile-version
Affiche la version OpenSSL avec laquelle Postfix a été compilé (c'est-à-dire la version OpenSSL dans un fichier d'en-tête). Le format de sortie est le même qu'avec la commande "openssl version".
run-version
Affiche la version OpenSSL avec laquelle Postfix est lié à l'exécution (c'est-à-dire la version OpenSSL dans une bibliothèque partagée).
public-key-algorithms
Affiche les noms en minuscules des algorithmes de clés publiques pris en charge, un par ligne.
Cette fonctionnalité est disponible avec Postfix 3.1 et versions ultérieures.
-v
Active la journalisation détaillée à des fins de débogage. Plusieurs options -v rendent le logiciel de plus en plus verbeux.
-x
Développe $nom dans les valeurs de paramètres de main.cf ou master.cf. Le développement est récursif.

Cette fonctionnalité est disponible avec Postfix 2.10 et versions ultérieures.

-X
Modifie le fichier de configuration main.cf et supprime les paramètres nommés sur la ligne de commande postconf(1). Spécifiez une liste de noms de paramètres, pas des paires "nom=valeur".

Avec -M, modifie le fichier de configuration master.cf et supprime une ou plusieurs entrées de service comme spécifié avec "service/type" sur la ligne de commande postconf(1).

Avec -P, modifie le fichier de configuration master.cf et supprime un ou plusieurs réglages de paramètres de service (-o parameter=value) comme spécifié avec "service/type/paramètre" sur la ligne de commande postconf(1).

Dans tous les cas, le fichier est copié dans un fichier temporaire puis renommé. Spécifiez des guillemets pour protéger les caractères spéciaux sur la ligne de commande postconf(1).

Il n'existe pas de commande postconf(1) pour effectuer l'opération inverse.

Cette fonctionnalité est disponible avec Postfix 2.10 et versions ultérieures. La prise en charge de -M et -P a été ajoutée avec Postfix 2.11.

-#
Modifie le fichier de configuration main.cf et commente les paramètres nommés sur la ligne de commande postconf(1), de sorte que ces paramètres reviennent à leurs valeurs par défaut. Spécifiez une liste de noms de paramètres, pas des paires "nom=valeur".

Avec -M, modifie le fichier de configuration master.cf et commente une ou plusieurs entrées de service comme spécifié avec "service/type" sur la ligne de commande postconf(1).

Dans tous les cas, le fichier est copié dans un fichier temporaire puis renommé. Spécifiez des guillemets pour protéger les caractères spéciaux sur la ligne de commande postconf(1).

Il n'existe pas de commande postconf(1) pour effectuer l'opération inverse.

Cette fonctionnalité est disponible avec Postfix 2.6 et versions ultérieures. La prise en charge de -M a été ajoutée avec Postfix 2.11.
