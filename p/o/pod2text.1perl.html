NOM

pod2text - Convertit des données POD en texte ASCII formaté

SYNTAXE

pod2text [-aclostu] [--code] [-e encodage]
[--errors=style] [--guesswork=règle[,règle...]]
[-i indentation] [-q guillemets]
[--nourls] [--stderr] [-w largeur] [fichier_entrée [fichier_sortie ...]]

pod2text -h

DESCRIPTION

pod2text est un script d'encapsulation autour de Pod::Text et de ses sous-classes. Il les utilise pour générer du texte formaté à partir de sources POD. Il peut optionnellement utiliser des séquences termcap ou des séquences d'échappement de couleur ANSI pour formater le texte.

fichier_entrée est le fichier à lire pour la source POD (le POD peut être intégré dans le code). Si fichier_entrée n'est pas donné, il utilise par défaut "STDIN". fichier_sortie, s'il est donné, est le fichier auquel écrire la sortie formatée. Si fichier_sortie n'est pas donné, la sortie formatée est écrite dans "STDOUT". Plusieurs fichiers POD peuvent être traités lors de la même invocation de pod2text (en économisant les temps de chargement et de compilation des modules) en fournissant plusieurs paires de fichier_entrée et fichier_sortie sur la ligne de commande.

Par défaut, l'encodage de sortie est le même que l'encodage du fichier d'entrée, ou UTF-8 si cet encodage n'est pas défini (sauf sur les systèmes EBCDIC). Voir l'option -e pour définir explicitement l'encodage de sortie et la section "Encoding" dans Pod::Text pour plus de discussion.

OPTIONS

Chaque option est annotée avec la version de podlators dans laquelle cette option a été ajoutée avec sa signification actuelle.

-a, --alt
[1.00] Utilise un format de sortie alternatif qui, entre autres choses, utilise un style de titre différent et marque les entrées "=item" avec un deux-points dans la marge gauche.
--code
[1.11] Inclut également tout texte non-POD du fichier d'entrée dans la sortie. Utile pour visualiser du code documenté avec des blocs POD, avec le POD rendu et le code intact.
-c, --color
[1.00] Formate la sortie avec des séquences d'échappement de couleur ANSI. L'utilisation de cette option nécessite que Term::ANSIColor soit installé sur votre système.
-e encodage, --encoding=encodage
[5.00] Spécifie l'encodage de la sortie. encodage doit être un encodage reconnu par le module Encode (voir Encode::Supported). Si la sortie contient des caractères qui ne peuvent pas être représentés dans cet encodage, c'est une erreur qui sera signalée conformément à la configuration de l'option "errors". Si la gestion des erreurs est autre que "die", le caractère non représentable sera remplacé par le caractère de substitution d'Encode (normalement "?").

AVERTISSEMENT : L'encodage d'entrée de la source POD est indépendant de l'encodage de sortie, et la définition de cette option n'affecte pas l'interprétation de l'entrée POD. À moins que votre source POD ne soit en US-ASCII, son encodage doit être déclaré avec la commande "=encoding" dans la source, aussi près que possible du haut du fichier. Si cela n'est pas fait, Pod::Simple tentera de deviner l'encodage et pourra réussir s'il s'agit de Latin-1 ou de UTF-8, mais il produira des avertissements. Voir perlpod(1) pour plus d'informations.

--errors=style
[2.5.0] Définit le style de gestion des erreurs. "die" indique de lancer une exception en cas d'erreur de formatage POD. "stderr" indique de signaler les erreurs sur la sortie standard, mais de ne pas lancer d'exception. "pod" indique d'inclure une section POD ERRORS dans la documentation résultante résumant les erreurs. "none" ignore complètement les erreurs POD, autant que possible.

La valeur par défaut est "die".

--guesswork=règle[,règle...]
[5.01] Par défaut, pod2text applique certaines règles de formatage par défaut basées sur des suppositions et des expressions régulières qui visent à faciliter l'écriture de la documentation Perl et à nécessiter moins de balisage explicite. Ces règles peuvent ne pas toujours être appropriées, en particulier pour la documentation qui ne concerne pas Perl. Cette option permet de désactiver tout ou partie de celles-ci.

La règle spéciale "all" active toutes les suppositions. C'est aussi la valeur par défaut pour des raisons de compatibilité ascendante. La règle spéciale "none" désactive toutes les suppositions. Sinon, la valeur de cette option doit être une liste séparée par des virgules d'un ou plusieurs des mots-clés suivants :

quoting
Si aucune supposition n'est activée, tout texte entouré de C<> est entouré de guillemets doubles en sortie nroff (terminal) à moins que le contenu ne soit déjà cité. Lorsque ces suppositions sont activées, les guillemets seront également supprimés pour les variables Perl, les noms de fonctions, les appels de fonctions, les nombres et les constantes hexadécimales.

Tout nom de supposition inconnu est silencieusement ignoré (pour une compatibilité future potentielle), alors faites attention à l'orthographe.

-i indentation, --indent=indentation
[1.00] Définit le nombre d'espaces pour indenter le texte normal, et l'indentation par défaut pour les blocs "=over". Par défaut, 4 espaces si cette option n'est pas donnée.
-h, --help
[1.00] Affiche les informations d'utilisation et quitte.
-l, --loose
[1.00] Imprime une ligne vide après un titre "=head1". Normalement, aucune ligne vide n'est imprimée après "=head1", bien qu'une soit toujours imprimée après "=head2", car c'est le formatage attendu pour les pages de manuel ; si vous formatez des documents texte arbitraires, l'utilisation de cette option est recommandée.
-m largeur, --left-margin=largeur, --margin=largeur
[1.24] La largeur de la marge gauche en espaces. Par défaut à 0. C'est la marge pour tout le texte, y compris les titres, pas l'indentation du texte normal ; pour cette dernière, voir l'option -i.
--nourls
[2.5.0] Normalement, les codes de formatage L<> avec une URL mais un texte d'ancrage sont formatés pour montrer à la fois le texte d'ancrage et l'URL. En d'autres termes : 
L<foo|http://example.com/>

est formaté comme :

foo <http://example.com/>

Ce drapeau, s'il est donné, supprime l'URL lorsque du texte d'ancrage est donné, donc cet exemple serait formaté comme juste "foo". Cela peut produire une sortie moins encombrée dans les cas où les URL ne sont pas particulièrement importantes.

-o, --overstrike
[1.06] Formate la sortie avec impression par écrasement. Le texte en gras est rendu comme caractère, retour arrière, caractère. Les italiques et les noms de fichiers sont rendus comme underscore, retour arrière, caractère. De nombreux visualiseurs, tels que less, savent comment convertir cela en texte gras ou souligné.
-q guillemets, --quotes=guillemets
[4.00] Définit les marques de guillemets utilisées pour entourer le texte C<> à guillemets. Si guillemets est un seul caractère, il est utilisé comme guillemet gauche et droit. Sinon, il est divisé en deux, et la première moitié de la chaîne est utilisée comme guillemet gauche et la seconde comme guillemet droit.

guillemets peut également être défini sur la valeur spéciale "none", auquel cas aucun guillemet n'est ajouté autour du texte C<>.

-s, --sentence
[1.00] Suppose que chaque phrase
ends with two spaces and try to preserve that espacement. Sans cette option, tous les espaces blancs consécutifs dans les paragraphes non littéraux sont compressés en un seul espace.
--stderr
[2.1.3] Par défaut, pod2text s'arrête si des erreurs sont détectées dans l'entrée POD. Si --stderr est spécifié et qu'aucun drapeau --errors n'est présent, les erreurs sont envoyées à la sortie standard, mais pod2text ne s'arrête pas. Ceci est équivalent à "--errors=stderr" et est pris en charge pour la compatibilité ascendante.
-t, --termcap
[1.00] Essayer de déterminer la largeur de l'écran et les séquences de gras et de soulignement pour le terminal à partir de termcap, et utiliser ces informations pour formater la sortie. La sortie sera enveloppée à deux colonnes de moins que la largeur de votre terminal. L'utilisation de cette option nécessite que votre système dispose d'un fichier termcap quelque part où Term::Cap peut le trouver et nécessite que votre système prenne en charge termios. Avec cette option, la sortie de pod2text contiendra des séquences de contrôle de terminal pour votre type de terminal actuel.
-u, --utf8
[2.2.0] Définit le codage de sortie sur UTF-8. Ceci est équivalent à "--encoding=UTF-8" et est pris en charge pour la compatibilité ascendante.
-w, --width=largeur, -largeur
[1.00] La colonne à laquelle le texte sera coupé sur le côté droit. La valeur par défaut est 76, sauf si -t est spécifié, auquel cas elle est deux colonnes de moins que la largeur de votre terminal.

ÉTAT DE SORTIE

Tant que tous les documents traités produisent une sortie, même si cette sortie inclut des errata (une section "ERREURS POD" générée avec "--errors=pod"), pod2text se terminera avec le statut 0. Si l'un des documents traités ne produit pas de document de sortie, pod2text se terminera avec le statut 1. S'il y a des erreurs de syntaxe dans un document POD en cours de traitement et que le style de gestion des erreurs est défini sur la valeur par défaut "die", pod2text s'arrêtera immédiatement avec le statut de sortie 255.

DIAGNOSTICS

Si pod2text échoue avec des erreurs, consultez Pod::Text et Pod::Simple pour savoir ce que ces erreurs pourraient signifier. En interne, il peut également produire les diagnostics suivants:

-c (--color) nécessite l'installation de Term::ANSIColor
(F) -c ou --color ont été spécifiés, mais Term::ANSIColor n'a pas pu être chargé.
Option inconnue : %s
(F) Une option de ligne de commande inconnue a été fournie.

En outre, d'autres messages d'erreur de Getopt::Long peuvent résulter d'options de ligne de commande invalides.

ENVIRONNEMENT

COLUMNS
Si -t est spécifié, pod2text prendra la largeur actuelle de votre écran à partir de cette variable d'environnement, si elle est disponible. Elle remplace les informations de largeur du terminal dans TERMCAP.
TERMCAP
Si -t est spécifié, pod2text utilisera le contenu de cette variable d'environnement, si disponible, pour déterminer les séquences de formatage correctes pour votre terminal actuel.
