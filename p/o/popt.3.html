DESCRIPTION

La bibliothèque popt existe essentiellement pour analyser les options de la ligne de commande. Elle est jugée supérieure à bien des égards par rapport à l'analyse manuelle du tableau argv ou à l'utilisation des fonctions getopt() et getopt_long() [voir getopt(3)]. Certains avantages spécifiques de popt sont : elle n'utilise pas de variables globales, permettant ainsi plusieurs passes dans l'analyse de argv ; elle peut analyser un tableau arbitraire d'éléments de style argv, permettant l'analyse de chaînes de ligne de commande provenant de n'importe quelle source ; elle fournit une méthode standard d'alias d'options (qui sera discutée en détail ci-dessous) ; elle peut exécuter des filtres d'options externes ; et, enfin, elle peut générer automatiquement des messages d'aide et d'utilisation pour l'application.

Comme getopt_long(), la bibliothèque popt prend en charge les options de style court et long. Rappelez-vous qu'une option courte consiste en un caractère - suivi d'un seul caractère alphanumérique. Une option longue, courante dans les utilitaires GNU, consiste en deux caractères - suivis d'une chaîne composée de lettres, de chiffres et de tirets. Les options longues sont éventuellement autorisées à commencer par un seul -, principalement pour permettre la compatibilité de la ligne de commande entre les applications popt et les applications X toolkit. L'un ou l'autre type d'option peut être suivi d'un argument. Un espace sépare une option courte de ses arguments ; un espace ou un = sépare une option longue de son argument.

La bibliothèque popt est hautement portable et devrait fonctionner sur n'importe quelle plateforme POSIX. La dernière version est distribuée avec rpm et est toujours disponible sur : ftp://ftp.rpm.org/pub/rpm/dist.

Elle peut être redistribuée sous la licence de la consortium X, voir le fichier COPYING dans la distribution source de popt pour plus de détails.

UTILISATION DE BASE DE POPT

1. LE TABLEAU DES OPTIONS

Les applications fournissent à popt des informations sur leurs options de ligne de commande au moyen d'un « tableau d'options », c'est-à-dire un tableau de structures struct poptOption :

#include <popt.h>

struct poptOption {
    const char * longName;   /* peut être NULL */
    char shortName;          /* peut être '\0' */
    unsigned int argInfo;    /* type d'argument attendu après l'option */
    void * arg;              /* dépend de argInfo */
    int val;                 /* 0 signifie ne pas retourner, juste mettre à jour arg */
    const char * descrip;    /* description pour l'aide automatique -- peut être NULL */
    const char * argDescrip; /* description de l'argument pour l'aide automatique -- peut être NULL*/
};

Chaque membre du tableau définit une seule option qui peut être passée au programme. Les options longues et courtes sont considérées comme une seule option qui peut apparaître sous deux formes différentes. Les deux premiers membres, longName et shortName, définissent les noms de l'option ; le premier est un nom long, tandis que le second est un seul caractère.

Le membre argInfo indique à popt quel type d'argument est attendu après l'option. Si aucun argument n'est attendu, POPT_ARG_NONE doit être utilisé. Les valeurs valides de argInfo sont indiquées dans le tableau suivant :

Valeur Description Type d'arg
POPT_ARG_NONE Aucun argument attendu int
POPT_ARG_STRING Aucune vérification de type à effectuer char *
POPT_ARG_ARGV Aucune vérification de type à effectuer char **
POPT_ARG_SHORT Un argument court est attendu short
POPT_ARG_INT Un argument entier est attendu int
POPT_ARG_LONG Un entier long est attendu long
POPT_ARG_LONGLONG Un très long entier est attendu long long
POPT_ARG_VAL Valeur entière prise de val int
POPT_ARG_FLOAT Un argument flottant est attendu float
POPT_ARG_DOUBLE Un argument double est attendu double

Pour les valeurs numériques, si la valeur argInfo est combinée par bit avec l'une des valeurs POPT_ARGFLAG_OR, POPT_ARGFLAG_AND, ou POPT_ARGFLAG_XOR, la valeur est enregistrée en effectuant un OU, un ET, ou un OU exclusif. Si la valeur argInfo est combinée par bit avec POPT_ARGFLAG_NOT, la valeur sera niée avant d'être enregistrée. Pour les opérations courantes de définition et/ou d'effacement de bits, POPT_BIT_SET et POPT_BIT_CLR ont les drapeaux appropriés définis pour effectuer des opérations sur les bits.

Si la valeur argInfo est combinée par bit avec POPT_ARGFLAG_ONEDASH, l'argument long peut être donné avec un seul - au lieu de deux. Par exemple, si --longopt est une option avec POPT_ARGFLAG_ONEDASH, il est spécifié, -longopt est également accepté.

L'élément suivant, arg, permet à popt de mettre automatiquement à jour les variables du programme lorsque l'option est utilisée. Si arg est NULL, il est ignoré et popt ne prend aucune action spéciale. Sinon, il devrait pointer vers une variable du type indiqué dans la colonne la plus à droite du tableau ci-dessus. Un arg POPT_ARG_ARGV (ré)allouera un tableau de pointeurs de chaînes char *, ajoutera l'argument chaîne, et ajoutera un sentinelle NULL à la fin du tableau si nécessaire. L'adresse cible char ** d'un arg POPT_ARG_ARGV doit être initialisée à NULL.

Si l'option ne prend pas d'argument (argInfo est POPT_ARG_NONE), la variable pointée par arg est mise à 1 lorsque l'option est utilisée. (Incidemment, il n'échappera peut-être pas à l'attention des dactylographes minutieux que la valeur de POPT_ARG_NONE est 0.) Si l'option prend un argument, la variable vers laquelle arg pointe est mise à jour pour refléter la valeur de l'argument. Toute chaîne est acceptable pour les arguments POPT_ARG_STRING et POPT_ARG_ARGV, mais POPT_ARG_INT, POPT_ARG_SHORT, POPT_ARG_LONG, POPT_ARG_LONGLONG, POPT_ARG_FLOAT, et POPT_ARG_DOUBLE sont convertis au type approprié, et une erreur est retournée si la conversion échoue.

POPT_ARG_VAL fait que arg soit mis à la valeur (entière) de val lorsque l'argument est trouvé. Ceci est le plus souvent utile pour les arguments mutuellement exclusifs dans les cas où ce n'est pas une erreur si plusieurs arguments se produisent et où vous voulez que le dernier argument spécifié gagne ; par exemple, "rm -i -f". POPT_ARG_VAL fait que la fonction d'analyse ne retourne pas de valeur, car la valeur de val a déjà été utilisée.

Si la valeur argInfo est combinée par bit avec POPT_ARGFLAG_OPTIONAL, l'argument de l'option longue peut être omis. Si l'option longue est utilisée sans argument, une valeur par défaut de zéro ou NULL sera enregistrée (si le pointeur d'argument est présent), sinon, elle se comporte

1. TABLEAUX D'OPTIONS

Les options de la ligne de commande sont définies à l'aide d'un tableau de structures struct poptOption. Chaque entrée dans le tableau décrit une option de ligne de commande particulière, ou une action spéciale que popt doit effectuer. Voici une description des membres de la structure struct poptOption :

const char * shortName
Le nom court de l'option, ou '\0' si elle n'en a pas.
const char * longName
Le nom long de l'option, ou NULL si elle n'en a pas. Si longName est défini, alors shortName doit également être défini.
int val
La valeur que poptGetNextOpt renverra lorsqu'une option correspondante est trouvée. Si val est 0, alors l'option prend un argument qui doit être lu par poptGetNextOpt. Les options qui prennent un argument et qui devraient être traduites en une valeur booléenne lorsque l'option est rencontrée ont généralement une valeur val de 1.
const char * arg
Ce membre est utilisé de deux manières différentes. Si l'option prend un argument, alors arg pointe vers un pointeur vers une chaîne qui sera remplie avec l'argument de l'option. Si l'option est une option sans argument avec une valeur val de 0, alors arg pointe vers un pointeur qui sera rempli avec la chaîne NULL. Si l'option est une option sans argument avec une valeur val non nulle, alors arg est ignoré. Si l'option est une option avec un argument, mais que l'application ne souhaite pas que l'argument soit stocké dans une variable, alors arg doit être NULL.
const char * descrip
La description de l'option utilisée lors de la génération de messages d'aide automatiques.
const char * argDescrip
Une courte description du type d'arguments que l'option attend, ou NULL si l'option n'attend pas d'arguments.

La structure poptOption peut également avoir des valeurs spéciales pour le membre val :

POPT_ARG_NONE
Indique que l'option ne prend pas d'argument.
POPT_ARG_REQ
Indique que l'option requiert un argument. Si aucun argument n'est fourni, une erreur sera générée.
POPT_ARG_OPT
Indique que l'option prend un argument facultatif.
POPT_ARG_FILENAME
Indique que l'option prend un nom de fichier comme argument. Le nom de fichier est automatiquement traité par popt pour gérer les noms de fichiers qui commencent par un tiret.
POPT_ARG_INCLUDE_TABLE
Indique que cette entrée inclut un autre tableau d'options. Le membre arg pointe vers le tableau à inclure. Le membre descrip doit contenir une description du tableau inclus.
POPT_ARG_CALLBACK
Indique que cette entrée déclenche une fonction de rappel. Le membre arg pointe vers la fonction de rappel, et le membre descrip contient des données arbitraires à passer à la fonction de rappel.
POPT_ARG_POLL
Cette option est utilisée par popt pour la gestion des alias. Elle ne doit pas être utilisée directement par les applications.
POPT_ARGFLAG_DOC_HIDDEN
Si ce drapeau est combiné avec un autre drapeau via un OU bit à bit, l'option ne sera pas affichée dans les messages d'aide automatiques.
POPT_ARGFLAG_SHOW_DEFAULT
Si ce drapeau est combiné avec un autre drapeau via un OU bit à bit, la valeur par défaut de l'argument sera affichée dans les messages d'aide automatiques.

Les options de la ligne de commande peuvent avoir des noms courts (par exemple, -h) et des noms longs (par exemple, --help). L'option val est la valeur que la fonction d'analyse de popt devrait retourner lorsque l'option est rencontrée. Si val est 0, la fonction d'analyse ne retourne pas de valeur, mais analyse l'argument de ligne de commande suivant.

Les deux dernières options, descrip et argDescrip sont uniquement requises si des messages d'aide automatiques sont souhaités (des messages d'utilisation automatiques peuvent être générés sans eux). descrip est une description textuelle de l'argument et argDescrip est un bref résumé du type d'arguments que l'option attend, ou NULL si l'option ne nécessite aucun argument.

Si popt doit fournir automatiquement les options --usage et --help (-?), une ligne dans le tableau doit être la macro POPT_AUTOHELP. Cette macro inclut un autre tableau d'options (via POPT_ARG_INCLUDE_TABLE ; voir ci-dessous) dans le tableau principal, qui fournit les entrées de tableau pour ces arguments. Lorsque --usage ou --help sont passés aux programmes qui utilisent l'aide automatique de popt, popt affiche le message approprié sur stderr dès qu'il trouve l'option et quitte le programme avec un code de retour de 0. Si vous souhaitez utiliser la génération d'aide automatique de popt d'une manière différente, vous devez explicitement ajouter les entrées d'option à votre tableau d'options de programme au lieu d'utiliser POPT_AUTOHELP.

Si la valeur argInfo est combinée bit à bit avec POPT_ARGFLAG_DOC_HIDDEN, l'argument ne sera pas affiché dans la sortie d'aide.

Si la valeur argInfo est combinée bit à bit avec POPT_ARGFLAG_SHOW_DEFAULT, la valeur initiale de l'argument sera affichée dans la sortie d'aide.

La dernière structure du tableau doit avoir toutes les valeurs de pointeur définies sur NULL et toutes les valeurs arithmétiques définies sur 0, marquant la fin du tableau. La macro POPT_TABLEEND est fournie pour cela.

Il existe deux types d'entrées de tableau d'options qui ne spécifient pas d'options de ligne de commande. Lorsque l'un de ces types d'entrées est utilisé, l'élément longName doit être NULL et l'élément shortName doit être '\0'.

Le premier de ces types d'entrées spéciales permet à l'application d'imbriquer un autre tableau d'options dans celui en cours ; un tel imbrication peut s'étendre assez profondément (la profondeur réelle est limitée par la pile du programme). L'inclusion d'autres tableaux d'options permet à une bibliothèque de fournir un ensemble standard d'options de ligne de commande à chaque programme qui l'utilise (ce qui est souvent fait dans les kits d'outils de programmation graphique, par exemple). Pour ce faire, définissez le champ argInfo sur POPT_ARG_INCLUDE_TABLE et le champ arg pour pointer vers le tableau qui est inclus. Si la génération d'aide automatique est utilisée, le champ descrip doit contenir une description globale du tableau d'options inclus.

L'autre type d'entrée de tableau d'options spécial indique à popt d'appeler une fonction (un rappel) lorsqu'une option de ce tableau est trouvée. Ceci est particulièrement utile lorsque des tableaux d'options inclus sont utilisés, car le programme qui fournit le tableau d'options de niveau supérieur n'a pas besoin d'être au courant des autres options fournies par le tableau inclus. Lorsqu'un rappel est défini pour un tableau, la fonction d'analyse ne renvoie jamais d'informations sur une option du tableau. Au lieu de cela, les informations sur les options doivent être conservées via le rappel ou en faisant en sorte que popt définisse une variable via le champ arg de l'option. Les rappels d'options doivent correspondre au prototype suivant :

void poptCallbackType(poptContext con, 
                      const struct poptOption * opt, 
                      const char * arg, void * data);

Le premier paramètre est le contexte qui est en cours d'analyse (voir la section suivante pour des informations sur les contextes), opt pointe vers l'option qui a déclenché ce rappel, et arg est l'argument de l'option. Si l'option ne prend pas d'argument, arg est NULL. Le dernier paramètre, data, est tiré du champ descrip de l'entrée du tableau d'options qui a défini le rappel. Comme descrip est un pointeur, cela permet aux fonctions de rappel de passer un ensemble arbitraire de données (bien qu'un cast de type doive être utilisé).

L'entrée du tableau d'options qui définit un rappel a un argInfo de POPT_ARG_CALLBACK, un arg qui pointe vers la fonction de rappel, et un champ descrip qui spécifie un pointeur arbitraire à passer au rappel.

2. CRÉATION D'UN CONTEXTE

popt peut entrelacer l'analyse de plusieurs ensembles de lignes de commande. Il permet cela en conservant toutes les informations d'état pour un ensemble particulier d'arguments de ligne de commande dans une structure de données poptContext, un type opaque qui ne doit pas être modifié en dehors de la bibliothèque popt.

De nouveaux contextes popt sont créés par poptGetContext() :

poptContext poptGetContext(const char * name, int argc,
                           const char ** argv,
                           const struct poptOption * options,
                           unsigned int flags);

Le premier paramètre, name, est utilisé uniquement pour la gestion des alias (discutée plus loin). Il doit être le nom de l'application dont les options sont analysées, ou doit être NULL si aucun alias d'option n'est souhaité. Les deux arguments suivants spécifient les arguments de ligne de commande à analyser. Ils sont généralement passés à poptGetContext() exactement comme ils ont été passés à la fonction main() du programme. Le paramètre options pointe vers le tableau des options de ligne de commande, décrit dans la section précédente. Le dernier paramètre, flags, peut être n'importe quelle combinaison bit à bit des quatre valeurs suivantes :

Valeur Description
POPT_CONTEXT_NO_EXEC Ignorer les expansions exec
POPT_CONTEXT_KEEP_FIRST Ne pas ignorer argv[0]
POPT_CONTEXT_POSIXMEHARDER Les options ne peuvent pas suivre les arguments
POPT_CONTEXT_ARG_OPTS Retourner les arguments comme options de valeur 0

Un poptContext conserve une trace des options qui ont déjà été analysées et de celles qui restent, entre autres choses. Si un programme souhaite redémarrer le traitement des options d'un ensemble d'arguments, il peut réinitialiser le poptContext en passant le contexte comme seul argument à poptResetContext().

Lorsque le traitement des arguments est terminé, le processus doit libérer le poptContext car il contient des composants alloués dynamiquement. La fonction poptFreeContext() prend un poptContext comme seul argument et libère les ressources utilisées par le contexte.

Voici les prototypes de poptResetContext() et poptFreeContext() :

#include <popt.h>
void poptFreeContext(poptContext con);
void poptResetContext(poptContext con);

3. ANALYSE DE LA LIGNE DE COMMANDE

Après qu'une application a créé un poptContext, elle peut commencer à analyser les arguments. poptGetNextOpt() effectue l'analyse réelle des arguments.

#include <popt.h>
int poptGetNextOpt(poptContext con);

Prenant le contexte comme seul argument, cette fonction analyse l'argument de ligne de commande suivant trouvé. Après avoir trouvé le prochain argument dans le tableau d'options, la fonction remplit l'objet pointé par le pointeur arg de l'entrée du tableau d'options s'il n'est pas NULL. Si la valeur val pour l'option est non nulle, la fonction retourne alors cette valeur. Sinon, poptGetNextOpt() continue sur l'argument suivant.

poptGetNextOpt() retourne -1 lorsque le dernier argument a été analysé, et d'autres valeurs négatives en cas d'erreurs. Il est donc conseillé de maintenir les éléments val dans le tableau d'options supérieurs à 0.

Si toutes les options de ligne de commande sont gérées via les pointeurs arg, l'analyse de la ligne de commande se réduit à la ligne de code suivante :

rc = poptGetNextOpt(poptcon);

Cependant, de nombreuses applications nécessitent une analyse de ligne de commande plus complexe, et utilisent la structure suivante :

while ((rc = poptGetNextOpt(poptcon)) > 0) {
     switch (rc) {
          /* les arguments spécifiques sont gérés ici */
     }
}

Lorsque les options retournées sont traitées, l'application doit connaître la valeur de tous les arguments qui ont été spécifiés après l'option. Il existe deux façons de les découvrir. L'une consiste à demander à popt de remplir une variable avec la valeur de l'option via les éléments arg du tableau d'options. L'autre consiste à utiliser poptGetOptArg() :

#include <popt.h>
char * poptGetOptArg(poptContext con);

Cette fonction retourne l'argument donné pour la dernière option retournée par poptGetNextOpt(), ou elle retourne NULL si aucun argument n'a été spécifié. La fonction appelante est responsable de la désallocation de cette chaîne.

4. ARGUMENTS RESTANTS

De nombreuses applications prennent un nombre arbitraire d'arguments de ligne de commande, tels qu'une liste de noms de fichiers. Lorsque popt rencontre un argument qui ne commence pas par un tiret, il le suppose comme tel et l'ajoute à une liste d'arguments restants. Trois fonctions permettent aux applications d'accéder à de tels arguments :

const char * poptGetArg(poptContext con);
Cette fonction retourne le prochain argument restant et le marque comme traité. 
const char * poptPeekArg(poptContext con);
Le prochain argument restant est retourné mais non marqué comme traité. Cela permet à une application de regarder en avant dans la liste des arguments, sans modifier la liste. 
const char ** poptGetArgs(poptContext con);
Tous les arguments restants sont retournés d'une manière identique à argv. Le dernier élément du tableau retourné pointe vers NULL, indiquant la fin des arguments.

5. MESSAGES D'AIDE AUTOMATIQUES

La bibliothèque popt peut générer automatiquement des messages d'aide décrivant les options qu'un programme accepte. Il existe deux types de messages d'aide qui peuvent être générés. Les messages d'utilisation sont des messages courts qui listent les options valides, mais ne les décrivent pas. Les messages d'aide décrivent chaque option sur une (ou plusieurs) ligne(s), résultant en un message plus long, mais plus utile. Chaque fois que des messages d'aide automatiques sont utilisés, les champs descrip et argDescrip des membres de la structure poptOption doivent être remplis pour chaque option.

La macro POPT_AUTOHELP facilite l'ajout des messages --usage et --help.

es à votre programme, et est décrit dans la partie 1 de cette page de manuel. Si plus de contrôle est nécessaire sur vos messages d'aide, les deux fonctions suivantes sont disponibles :

#include <popt.h>
void poptPrintHelp(poptContext con, FILE * f, int flags);
void poptPrintUsage(poptContext con, FILE * f, int flags);

poptPrintHelp() affiche le message d'aide standard sur le descripteur de fichier standard f, tandis que poptPrintUsage() affiche le message d'utilisation plus court. Les deux fonctions ignorent actuellement l'argument flags ; il est là pour permettre des changements futurs.

GESTION DES ERREURS

Toutes les fonctions popt qui peuvent retourner des erreurs retournent des entiers. Lorsqu'une erreur se produit, un code d'erreur négatif est retourné. Le tableau suivant résume les codes d'erreur qui surviennent :

Erreur Description
POPT_ERROR_NOARG Argument manquant pour une option.
POPT_ERROR_BADOPT L'argument de l'option n'a pas pu être analysé.
POPT_ERROR_UNWANTEDARG L'option ne prend pas d'argument.
POPT_ERROR_OPTSTOODEEP Alias d'option imbriqué trop profondément.
POPT_ERROR_BADQUOTE Les guillemets ne correspondent pas.
POPT_ERROR_ERRNO errno défini, utilisez strerror(errno).
POPT_ERROR_BADNUMBER L'option n'a pas pu être convertie en nombre.
POPT_ERROR_OVERFLOW Un nombre donné était trop grand ou trop petit.
POPT_ERROR_BADOPERATION Opérations logiques mutuellement exclusives demandées.
POPT_ERROR_NULLARG opt->arg ne devrait pas être NULL.
POPT_ERROR_MALLOC Échec de l'allocation mémoire.
POPT_ERROR_BADCONFIG Fichier de configuration échoue au test de cohérence.

Voici une discussion plus détaillée de chaque erreur :

POPT_ERROR_NOARG
Une option qui nécessite un argument a été spécifiée sur la ligne de commande, mais aucun argument n'a été donné. Ceci ne peut être retourné que par poptGetNextOpt().
POPT_ERROR_BADOPT
Une option a été spécifiée dans argv mais n'est pas dans la table d'options. Cette erreur ne peut être retournée que par poptGetNextOpt().
POPT_ERROR_OPTSTOODEEP
Un ensemble d'alias d'options est imbriqué trop profondément. Actuellement, popt ne suit les options que de 10 niveaux (POPT_OPTION_DEPTH) pour empêcher la récursion infinie. Seule poptGetNextOpt() peut retourner cette erreur.
POPT_ERROR_BADQUOTE
Une chaîne analysée a une incohérence de guillemets (comme une apostrophe). poptParseArgvString(), poptReadConfigFile() ou poptReadDefaultConfig() peuvent retourner cette erreur.
POPT_ERROR_ERRNO
Un appel système est retourné avec une erreur, et errno contient toujours l'erreur de l'appel système. poptReadConfigFile() et poptReadDefaultConfig() peuvent retourner cette erreur.
POPT_ERROR_BADNUMBER
Une conversion d'une chaîne en nombre (int ou long) a échoué car la chaîne contenait des caractères non numériques. Cela se produit lorsque poptGetNextOpt() traite un argument de type POPT_ARG_INT, POPT_ARG_SHORT, POPT_ARG_LONG, POPT_ARG_LONGLONG, POPT_ARG_FLOAT ou POPT_ARG_DOUBLE.
POPT_ERROR_OVERFLOW
Une conversion chaîne-vers-nombre a échoué car le nombre était trop grand ou trop petit. Comme POPT_ERROR_BADNUMBER, cette erreur ne peut survenir que lorsque poptGetNextOpt() traite un argument de type POPT_ARG_INT, POPT_ARG_SHORT, POPT_ARG_LONG, POPT_ARG_LONGLONG, POPT_ARG_FLOAT ou POPT_ARG_DOUBLE.
POPT_ERROR_BADOPERATION
Plus d'une opération logique (AND, OR, XOR) a été spécifiée pour une option, ou POPT_ARGFLAG_RANDOM a été spécifié mais la plateforme ne prend pas en charge la fonction random(). Ceci ne peut être retourné que par poptSaveLongLong(), poptSaveLong(), poptSaveInt(), poptSaveShort() et poptGetNextOpt().
POPT_ERROR_NULLARG
Une opération a été invoquée sur un arg cible nul (y compris les arguments de chaîne de longueur nulle). Dans le cas de poptBitsArgs(), cela inclut un tableau argv restant vide. Ceci ne peut être retourné que par les fonctions poptBits*() et poptSave*(), poptConfigFileToString() et poptGetNextOpt().
POPT_ERROR_MALLOC
Échec de l'allocation mémoire. Ceci ne peut être retourné que par poptReadFile(), poptDupArgv(), poptParseArgvString(), poptConfigFileToString() et poptGetNextOpt().
POPT_ERROR_BADCONFIG
Les fichiers de configuration popt sont corrompus. Ceci ne peut être retourné que par poptReadConfigFile() et poptReadConfigFiles().

Deux fonctions sont disponibles pour faciliter aux applications la fourniture de bons messages d'erreur.

const char *const poptStrerror(const int error);
Cette fonction prend un code d'erreur popt et retourne une chaîne décrivant l'erreur, tout comme la fonction standard strerror(). 
const char * poptBadOption(poptContext con, int flags);
Si une erreur s'est produite pendant poptGetNextOpt(), cette fonction retourne l'option qui a causé l'erreur. Si l'argument flags est défini sur POPT_BADOPTION_NOALIAS, l'option la plus externe est retournée. Sinon, flags devrait être 0, et l'option retournée peut avoir été spécifiée via un alias.

Ces deux fonctions rendent la gestion des erreurs popt triviale pour la plupart des applications. Lorsqu'une erreur est détectée par la plupart des fonctions, un message d'erreur est imprimé avec la chaîne d'erreur de poptStrerror(). Lorsqu'une erreur se produit pendant l'analyse des arguments, un code similaire à celui qui suit affiche un message d'erreur utile :

fprintf(stderr, "%s: %s\n",
        poptBadOption(optCon, POPT_BADOPTION_NOALIAS),
        poptStrerror(rc));

ALIASAGE DES OPTIONS

L'un des principaux avantages d'utiliser popt par rapport à getopt() est la possibilité d'utiliser des alias d'options. Cela permet à l'utilisateur de spécifier des options que popt développe en d'autres options lorsqu'elles sont spécifiées. Si le programme grep standard utilisait popt, les utilisateurs pourraient ajouter une option --text qui se développerait en -i -n -E -2 pour leur permettre de trouver plus facilement des informations dans des fichiers texte.

1. SPÉCIFICATION DES ALIAS

Les alias sont normalement spécifiés à deux endroits : /etc/popt et le fichier .popt dans le répertoire personnel de l'utilisateur (trouvé via la variable d'environnement HOME). Les deux fichiers ont le même format, un nombre arbitraire de lignes formatées comme suit :

nom_appli alias nouvelle_option expansion

Le nom_appli est le nom de l'application, qui doit être le même que le paramètre name passé à poptGetContext(). Cela permet à chaque fichier de spécifier des alias pour plusieurs programmes. Le mot-clé alias spécifie qu'un alias est en cours de définition ; actuellement, les fichiers de configuration popt ne prennent en charge que les alias, mais d'autres capacités pourraient être ajoutées à l'avenir. L'option suivante est l'option qui doit être aliasée, et elle peut être une option courte ou longue. Le reste de la ligne spécifie l'expansion de l'alias. Elle est analysée de manière similaire à une commande shell, ce qui permet d'utiliser \, " et ' pour la mise entre guillemets. Si un antislash est le dernier caractère de la ligne, la ligne suivante dans le fichier est supposée être une continuation logique de la ligne contenant l'antislash, tout comme dans le shell.

L'entrée suivante ajouterait une option --text à la commande grep, comme suggéré au début de cette section.

grep alias --text -i -n -E -2

2. ACTIVATION DES ALIAS

Une application doit activer l'expansion des alias pour un poptContext avant d'appeler poptGetNextArg() pour la première fois. Il existe trois fonctions qui définissent des alias pour un contexte :

int poptReadDefaultConfig(poptContext con, int flags);
Cette fonction lit les alias de /etc/popt et du fichier .popt dans le répertoire personnel de l'utilisateur. Actuellement, flags doit être NULL, car il n'est fourni que pour une expansion future. 
int poptReadConfigFile(poptContext con, char * fn);
Le fichier spécifié par fn est ouvert et analysé comme un fichier de configuration popt. Cela permet aux programmes d'utiliser des fichiers de configuration spécifiques au programme. 
int poptAddAlias(poptContext con, struct poptAlias alias,
                 int flags);
Parfois, les processus veulent spécifier des alias sans avoir à les lire à partir d'un fichier de configuration. Cette fonction ajoute un nouvel alias à un contexte. L'argument flags doit être 0, car il est actuellement réservé pour une expansion future. Le nouvel alias est spécifié comme une struct poptAlias, qui est définie comme suit : 
struct poptAlias {
     const char * longName; /* peut être NULL */
     char shortName; /* peut être '\0' */
     int argc;
     const char ** argv; /* doit être libérable avec free() */
};

Les deux premiers éléments, longName et shortName, spécifient l'option qui est aliasée. Les deux derniers, argc et argv, définissent l'expansion à utiliser lorsque l'option aliasée est rencontrée.

ANALYSE DES CHAÎNES D'ARGUMENTS popt - Manuel d'une page

NOM

popt - bibliothèque pour l'analyse des options de ligne de commande

SYNOPSIS

#include <popt.h>

DESCRIPTION

La bibliothèque popt est une bibliothèque pour l'analyse des options de ligne de commande. Elle est conçue pour être flexible et pour gérer un grand nombre de caractéristiques complexes, notamment l'alias d'options, le traitement des options de type booléen, la gestion des arguments requis et facultatifs, et la combinaison d'options.

UTILISATION DE BASE DE POPT

L'utilisation de base de popt implique la création d'un contexte popt, l'itération sur les options et la récupération des arguments non optionnels.

poptContext poptGetContext(const char * login, int argc, const char ** argv,
                        const struct poptOption * options, int flags);
int poptGetNextOpt(poptContext con);
const char *poptGetArg(poptContext con);
void poptFreeContext(poptContext con);

La fonction poptGetContext() initialise une structure de contexte pour l'analyse des options. L'argument login est utilisé pour des chaînes de ressources spécifiques à l'utilisateur, et options est un tableau de structures poptOption qui décrit les options que le programme comprend.

La boucle principale utilise poptGetNextOpt() pour obtenir l'option suivante. Si poptGetNextOpt() renvoie une valeur positive, c'est le code caractère de l'option. Si elle renvoie 0, c'est un argument non optionnel qui a été trouvé. Si elle renvoie -1, il n'y a plus d'options à analyser. Si elle renvoie une valeur négative autre que -1, une erreur s'est produite.

Après l'analyse des options, poptGetArg() peut être utilisée pour récupérer les arguments qui ne sont pas des options.

Enfin, poptFreeContext() doit être appelée pour libérer la mémoire allouée par popt.

GESTION DES ERREURS

popt fournit des fonctions pour obtenir des informations détaillées sur les erreurs d'analyse.

const char *poptBadOption(poptContext con, int flags);
int poptStrerror(int errorcode);

poptBadOption() renvoie une chaîne décrivant la dernière mauvaise option rencontrée. poptStrerror() renvoie une chaîne décrivant un code d'erreur popt spécifique.

ALIAS D'OPTIONS

popt permet de définir des alias pour les options, permettant ainsi à plusieurs chaînes d'options de correspondre à une seule option.

int poptAddAlias(poptContext con, unsigned int flags, const char *name,
                const char **argv);

poptAddAlias() permet d'ajouter des alias au contexte popt. L'argument argv doit se terminer par un pointeur NULL.

ANALYSE DES CHAINES D'ARGUMENTS

Bien que popt soit généralement utilisé pour analyser des arguments déjà divisés en un tableau de style argv, certains programmes doivent analyser des chaînes formatées de manière identique aux lignes de commande. Pour faciliter cela, popt fournit une fonction qui analyse une chaîne en un tableau de chaînes, en utilisant des règles similaires à l'analyse normale du shell.

#include <popt.h>
int poptParseArgvString(char * s, int * argcPtr,
                        char *** argvPtr);
int poptDupArgv(int argc, const char ** argv, int * argcPtr,
                        const char *** argvPtr);

La chaîne s est analysée en un tableau de style argv. L'entier pointé par le paramètre argcPtr contient le nombre d'éléments analysés, et le paramètre final argvPtr contient l'adresse du tableau nouvellement créé. La routine poptDupArgv() peut être utilisée pour créer une copie d'un tableau d'arguments existant.

Le argvPtr créé par poptParseArgvString() ou poptDupArgv() est adapté pour être passé directement à poptGetContext(). Les deux routines renvoient un seul bloc de stockage alloué dynamiquement et contigu qui doit être libéré par free() lorsque l'application a fini d'utiliser le stockage.

GESTION DES ARGUMENTS SUPPLÉMENTAIRES

Certaines applications implémentent l'équivalent d'alias d'options mais doivent le faire par le biais d'une logique spéciale. La fonction poptStuffArgs() permet à une application d'insérer de nouveaux arguments dans le poptContext actuel.

#include <popt.h>
int poptStuffArgs(poptContext con, const char ** argv);

Le argv passé doit avoir un pointeur NULL comme dernier élément. Lorsque poptGetNextOpt() sera appelée ensuite, les arguments "empilés" seront les premiers à être analysés. popt reviendra aux arguments normaux une fois que tous les arguments empilés auront été épuisés.

EXEMPLE

L'exemple suivant est une version simplifiée du programme "robin" qui apparaît dans le chapitre 15 du texte cité ci-dessous. Robin a été dépouillé de tout sauf de sa logique d'analyse d'arguments, légèrement retravaillé et renommé "parse". Il peut s'avérer utile pour illustrer au moins certaines des fonctionnalités de la bibliothèque popt extrêmement riche.

#include <popt.h>
#include <stdio.h>
#include <stdlib.h>
void usage(poptContext optCon, int exitcode, char *error, char *addl) {
    poptPrintUsage(optCon, stderr, 0);
    if (error) fprintf(stderr, "%s: %s\n", error, addl);
    exit(exitcode);
}
int main(int argc, char *argv[]) {
   int     c;            /* utilisé pour l'analyse des arguments */
   int     i = 0;        /* utilisé pour le suivi des options */
   int     speed = 0;    /* utilisé dans l'analyse des arguments pour régler la vitesse */
   int     raw = 0;      /* mode brut ? */
   int     j;
   char    buf[BUFSIZ+1];
   const char *portname;
   poptContext optCon;   /* contexte pour l'analyse des options de ligne de commande */
   struct poptOption optionsTable[] = {
      { "bps", 'b', POPT_ARG_INT, &speed, 0,
	"débit en bits par seconde", "BPS" },
      { "crnl", 'c', 0, 0, 'c',
	"développer les caractères cr en séquences cr/lf", NULL },
      { "hwflow", 'h', 0, 0, 'h',
	"utiliser le contrôle de flux matériel (RTS/CTS)", NULL },
      { "noflow", 'n', 0, 0, 'n',
	"ne pas utiliser de contrôle de flux", NULL },
      { "raw", 'r', 0, &raw, 0,
	"ne pas effectuer de conversions de caractères", NULL },
      { "swflow", 's', 0, 0, 's',
	"utiliser le contrôle de flux logiciel (XON/XOF)", NULL } ,
      POPT_AUTOHELP
      { NULL, 0, 0, NULL, 0 }
    };
   optCon = poptGetContext(NULL, argc, argv, optionsTable, 0);
   poptSetOtherOptionHelp(optCon, "[OPTIONS]* <port>");
   if (argc < 2) {
	poptPrintUsage(optCon, stderr, 0);
	exit(1);
   }
   /* Maintenant, traiter les options, obtenir le nom du port */
   while ((c = poptGetNextOpt(optCon)) >= 0) {
      switch (c) {
       case 'c':
          buf[i++] = 'c';
          break;
       case 'h':
          buf[i++] = 'h';
          break;
       case 's':
          buf[i++] = 's';
          break;
       case 'n':
          buf[i++] = 'n';
          break;
      }
   }
   portname = poptGetArg(optCon);
   if((portname == NULL) || !(poptPeekArg(optCon) == NULL))
      usage(optCon, 1, "Spécifier un seul port", ".ex., /dev/cua0");
   if (c < -1) {
      /* une erreur s'est produite lors du traitement des options */
      fprintf(stderr, "%s: %s\n",
              poptBadOption(optCon, POPT_BADOPTION_NOALIAS),
              poptStrerror(c));
      return 1;
   }
   /* Afficher les options, le nom du port choisi */
   printf("Options choisies : ");
   for(j = 0; j < i ; j++)
      printf("-%c ", buf[j]);
   if(raw) printf("-r ");
   if(speed) printf("-b %d ", speed);
   printf("\nNom du port choisi : %s\n", portname);
   poptFreeContext(optCon);
   exit(0);
}

RPM, un programme populaire de gestion de paquets sous Linux, utilise intensivement les fonctionnalités de popt. Bon nombre de ses arguments de ligne de commande sont implémentés par le biais d'alias popt, ce qui fait de RPM un excellent exemple de la manière de tirer parti de la bibliothèque popt. Pour plus d'informations sur RPM, voir http://www.rpm.org. La distribution source de popt comprend des programmes de test qui utilisent toutes les fonctionnalités des bibliothèques popt de diverses manières. Si une fonctionnalité ne fonctionne pas pour vous, le code de test de popt est le premier endroit où chercher.
