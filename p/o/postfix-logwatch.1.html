POSTFIX-LOGWATCH(1) Manuel des commandes générales POSTFIX-LOGWATCH(1)

NOM

postfix-logwatch - Utilité d'analyse et de traitement des logs Postfix

SYNOPIS

postfix-logwatch [options] [fichier_log ...]

DESCRIPTION


L'utilitaire postfix-logwatch(1) est un analyseur de logs du MTA Postfix qui produit des résumés, des détails et des statistiques concernant le fonctionnement de Postfix.

Cette utilitaire peut être utilisé comme un programme autonome, ou comme un module de filtrage de Logwatch pour produire des rapports de résumé et détaillés de Postfix au sein de Logwatch.

Postfix-logwatch est capable de produire une large gamme de rapports avec des données regroupées et triées autant que possible pour réduire le bruit et mettre en évidence les motifs. Les rapports de résumé bref fournissent un aperçu rapide des opérations générales de Postfix et de la livraison des messages, en signalant les avertissements qui peuvent nécessiter une attention. Les rapports détaillés fournissent des informations faciles à scanner, arrangées hiérarchiquement et organisées, avec autant ou moins de détails que désiré.

Postfix-logwatch produit deux sections principales : une section Résumé et une section Détaillé. Pour la lisibilité et le scan rapide, tous les comptes d'événements ou de succès apparaissent dans la colonne de gauche, suivis d'une brève description du type d'événement, et enfin des statistiques supplémentaires ou des représentations de compte peuvent apparaître dans la colonne la plus à droite.

Le segment suivant d'un rapport de résumé d'exemple illustre ceci :

****** Résumé ********************************************
      81   *Avertissement : taux limite de connexion atteint (anvil)
     146   Averti
  68.310M  Octets acceptés                        71 628 177
  97.645M  Octets livrés                         102 388 245
========   ================================================
    3464   Accepté                                   41.44%
    4895   Rejeté                                    58.56%
--------   ------------------------------------------------
    8359   Total                                    100.00%
========   ================================================
Le rapport avertit que le taux limite de connexion d'anvil a été atteint 81 fois, qu'une action WARN de vérification d'accès Postfix a été enregistrée 146 fois, et un total de 68.310 mégaoctets (71 628 177 octets) ont été acceptés dans le système Postfix, livrant 97.645 mégaoctets de données (en raison de multiples destinataires). Les lignes Accepté et Rejeté montrent que Postfix a accepté 3464 (41.44% du total des messages) et rejeté 4895 (les 58.56% restants) des 8359 messages totaux (les rejets temporaires apparaissent ailleurs).

Il existe des dizaines de sous-sections disponibles dans le rapport Détaillé, dont chacune peut être contrôlée de diverses manières. Chaque sous-section tente de regrouper et de présenter les données les plus significatives aux niveaux supérieurs, tout en poussant les données moins utiles ou bruyantes vers les niveaux inférieurs. L'objectif est de fournir autant de bénéfices que possible grâce au regroupement intelligent des données, afin de permettre un scan de rapport plus rapide, l'identification de motifs et la résolution de problèmes. Les données sont toujours triées par ordre décroissant de compte, puis numériquement par adresse IP ou alphabétiquement selon le cas.

Le segment suivant d'erreurs MX d'un rapport Détaillé d'exemple illustre la structure de base des niveaux hiérarchiques de postfix-logwatch :

****** Détaillé *******************************************
     261   Erreurs MX --------------------------------------
     261      Impossible de rechercher l'hôte MX
     222         Hôte introuvable
      73            foolishspammer.local
      60            completely.bogus.domain.example
      11            friend.example.com
      39         Aucune adresse associée à l'hôte
      23            dummymx.sample.net
      16            pushn.spam.sample.com

L'utilitaire postfix-logwatch lit depuis STDIN ou depuis le fichier_log Postfix nommé. Plusieurs arguments fichier_log peuvent être spécifiés, chacun traité dans l'ordre. L'utilisateur exécutant postfix-logwatch doit avoir la permission de lecture sur chaque fichier journal nommé.

Options

Les options listées ci-dessous affectent le fonctionnement de postfix-logwatch. Les options spécifiées plus tard dans la ligne de commande remplacent les précédentes. Toute option peut être abrégée à une longueur non ambiguë.

-f fichier_config
--fichier_config fichier_config
Utiliser un fichier de configuration alternatif fichier_config au lieu du fichier par défaut. Cette option peut être utilisée plus d'une fois. Plusieurs fichiers de configuration seront traités dans l'ordre présenté sur la ligne de commande. Voir FICHIER DE CONFIGURATION ci-dessous.
--debug mots_clés
Afficher les informations de débogage pendant le fonctionnement de postfix-logwatch. Le paramètre mots_clés est un ou plusieurs mots-clés séparés par des virgules ou des espaces. Pour obtenir la liste des mots-clés valides, utiliser --debug xxx où xxx est un mot-clé invalide.
--[no]delays
Active (désactive) l'affichage du rapport de centiles des retards de messages. Le rapport de centiles des retards affiche les centiles pour chacun des 4 temps de latence de livraison signalés par Postfix (disponible à partir de la version 2.3) sous la forme delays=a/b/c/d, où a est le temps avant la file d'attente active (inclut le temps pour les tentatives de livraison précédentes et le temps dans la file d'attente différée), b est le temps dans la file d'attente active jusqu'à la remise à l'agent de livraison, c est le temps passé à établir les connexions (y compris DNS, HELO et TLS) et d est le temps passé à livrer le message. Le retard total affiché provient du champ delay= dans une ligne de log de livraison de message.

Note : Ce rapport peut consommer une grande quantité de mémoire ; si vous n'en avez pas l'utilité, désactivez le rapport des retards.

--delays_percentiles p1 [p2 ...]
Spécifie les centiles à utiliser dans le rapport des centiles des retards de messages. Les centiles p1, p2, ... vont de 0 à 100 inclus. L'ordre de la liste n'est pas trié - le rapport affichera les colonnes de centiles dans l'ordre que vous spécifiez.
--detail niveau
Définit le niveau de détail maximum pour postfix-logwatch à niveau. Cette option est globale et remplace toutes les autres limiteurs de sortie décrits ci-dessous.

L'utilitaire postfix-logwatch produit une section Résumé, une section Détaillé, et des sections de rapport supplémentaires. Avec un niveau inférieur à 5, postfix-logwatch ne produira que la section Résumé. À partir du niveau 5 et plus, la section Détaillé, et toute section de rapport supplémentaire sont candidates à la sortie. Chaque augmentation incrémentale du niveau génère un sous-niveau de sortie hiérarchique supplémentaire dans la section Détaillé du rapport. Au niveau 10, tous les niveaux sont affichés. Les lignes qui dépassent la largeur maximale du rapport (spécifiée avec max_report_width) seront coupées. Définir niveau à 11 empêchera les lignes du rapport d'être coupées (voir aussi --line_style).

--help
Affiche les informations d'utilisation et une brève description des options de la ligne de commande.
--ignore_service motif
Ignore les lignes de log qui contiennent le nom du service postfix postfix/service. Le paramètre service est une expression régulière.

Note : si vous utilisez des parenthèses dans votre expression régulière, assurez-vous qu'elles sont de groupement et non de capture : utilisez (?:motif) au lieu de (motif).

--ipaddr_width largeur
Spécifie que les adresses IP dans les paires adresse/nom d'hôte doivent être imprimées avec une largeur de champ de largeur caractères. Augmenter la valeur par défaut peut être utile pour les systèmes utilisant de longues adresses IPv6.
-l limiter=levelspec
--limit limiteur=levelspec
Définit le limiteur de niveau limiteur avec la spécification levelspec.
--line_style style
Spécifie comment gérer les longues lignes de rapport. Trois styles sont disponibles : full, truncate, et
b>wrap. Définir style sur full empêchera la coupure des lignes selon max_report_width ; c'est ce qui se passe lorsque detail est égal ou supérieur à 11. Lorsque style est truncate (par défaut), les lignes longues seront tronquées conformément à max_report_width. Définir style sur wrap permettra de renvoyer à la ligne les lignes plus longues que max_report_width de manière à ce que les comptes de frappes de la colonne de gauche ne soient pas obscurcis. Cette option prévaut sur le style de ligne implicite du niveau detail. Les options --full, --truncate et --wrap sont des synonymes.
--[no]long_queue_ids
Active (désactive) l'interprétation des longs identifiants de file d'attente dans les journaux Postfix (>= 2.9).
--nodetail
Désactive la section Detailed du rapport, ainsi que tous les rapports supplémentaires. Cette option fournit un mécanisme pratique pour désactiver rapidement toutes les sections sous le rapport Detailed, où les options de ligne de commande ultérieures peuvent réactiver une ou plusieurs sections pour créer des rapports spécifiques.
--[no]summary
--show_summary
Active (désactive) l'affichage de la section Summary du rapport. La variable postfix_Show_Summary est utilisée dans un fichier de configuration.
--recipient_delimiter delimiter
Sépare les adresses de livraison d'e-mails en utilisant le caractère délimiteur de destinataire delimiter. Cela devrait généralement correspondre au recipient_delimiter spécifié dans le fichier paramètre Postfix main.cf, ou à la valeur par défaut indiquée dans postconf -d recipient_delimiter. Ceci est très utile pour obtenir des statistiques par alias lorsqu'un délimiteur de destinataire est utilisé pour la livraison de courrier.
--reject_reply_patterns r1 [r2 ...]
Spécifie la liste des motifs de rejet utilisés pour créer les groupes de rejet. Chaque entrée de la liste r1 [r2 ...] doit être soit un code de réponse d'expression régulière de trois caractères de la forme [45][0-9.][0-9.], soit le mot "Warn". Le "." dans l'expression régulière est un point littéral qui correspond à n'importe quel sous-code de réponse de rejet ; cette wildcard permet la création de groupes de rejet larges. L'ordre de la liste est préservé, en ce sens que les rapports de rejet seront générés dans le même ordre que les entrées de la liste. Les codes de réponse de rejet spécifiques auront la priorité sur les motifs wildcard, quel que soit l'ordre de la liste.

La liste par défaut est "5.. 4.. Warn", ce qui crée trois groupes de rejets : rejets permanents, échecs de rejet temporaires et avertissements de rejet (comme dans warn_if_reject).

Cette fonctionnalité permet, par exemple, de distinguer les fermetures de canaux de transmission 421 des erreurs 45x (par ex. 450 boîte aux lettres indisponible, 451 erreurs de traitement local, 452 stockage insuffisant). Un tel regroupement serait configuré avec la liste : "421 4.. 5.. Warn". Voir RFC 2821 pour plus d'informations sur les codes de réponse.

Voir également CONFIGURATION FILE concernant l'utilisation de reject_reply_patterns dans un fichier de configuration.

--[no]sect_vars
--show_sect_vars boolean
Active (désactive) l'ajout du nom du limiteur de niveau de chaque section Detailed au titre de cette section. Le nom affiché est l'option de ligne de commande (ou la variable de fichier de configuration) utilisée pour limiter la sortie de cette section. Avec le grand nombre de limiteurs de niveau disponibles dans postfix-logwatch, c'est un mécanisme pratique pour déterminer exactement quel limiteur de niveau affecte une section.
--syslog_name namepat
Spécifie le nom du service syslog que postfix-logwatch utilise pour faire correspondre les lignes syslog. Seules les lignes de journal dont le nom de service correspond à l'expression régulière perl namepat seront utilisées par postfix-logwatch ; toutes les lignes non correspondantes sont ignorées silencieusement. Ceci est utile lorsqu'un paquet Postfix pré-installé utilise un nom autre que celui par défaut (postfix), ou lorsque plusieurs instances Postfix sont utilisées et qu'un rapport par instance est souhaité.

Le motif namepat doit correspondre au paramètre de configuration syslog_name spécifié dans le fichier paramètre Postfix main.cf, le fichier de contrôle maître master.cf, ou la valeur par défaut telle qu'indiquée par la sortie de postconf -d syslog_name.

Note : si vous utilisez des parenthèses dans votre expression régulière, assurez-vous qu'elles sont des conteneurs et non des groupes de capture : utilisez (?:pattern) au lieu de (pattern).

--[no]unknown
--show_unknown boolean
Active (désactive) l'affichage du nom généré par postfix 'unknown' dans les paires IP/hôte formatées dans les rapports Detailed. Par défaut : activé.
--version
Affiche les informations de version de postfix-logwatch.

Limiteurs de Niveau

La sortie de chaque section du rapport Detailed est contrôlée par un limiteur de niveau. Le nom de la variable du limiteur de niveau sera affiché lorsque l'option sect_vars est définie. Les limiteurs de niveau sont définis soit via la ligne de commande en mode autonome avec l'option --limit limiter=levelspec, soit via la variable de fichier de configuration $postfix_limiter=levelspec. Chaque limiteur nécessite un argument levelspec, qui est décrit ci-dessous dans LEVEL CONTROL.

La liste des limiteurs de niveau est présentée ci-dessous.

Plusieurs limiteurs de niveau contrôlent les sous-sections de rejet (par ex. rejectbody, rejectsender, etc.). Comme la liste des variantes de rejet n'est pas connue avant l'exécution après avoir vu reject_reply_patterns, ces limiteurs de rejet sont présentés ci-dessous de manière générique, avec le préfixe ###. Pour utiliser l'un de ces limiteurs de rejet, substituez ### par l'un des codes de réponse de rejet en vigueur, en remplaçant chaque point par un caractère x. Par exemple, en utilisant la liste par défaut reject_reply_patterns de "5.. 4.. Warn", trois variantes de rejectbody sont valides : --limit 5xxrejectbody, --limit 4xxrejectbody et --limit warnrejectbody. Par commodité, vous pouvez éliminer entièrement le préfixe ###, et utiliser à la place l'option nue rejectXXX, et toutes les variations de limiteur de niveau de rejet seront auto-générées en fonction de la liste reject_reply_patterns. Par exemple, le segment de ligne de commande : 

    ... --reject_reply_patterns "421 5.." \
            --limit rejectrbl="1:10:"
deviendra automatiquement : 
    ... --reject_reply_patterns "421 5.." \
            --limit 421rejectrbl="1:10:" --limit 5xxrejectrbl="1:10:"
Voir reject_reply_patterns ci-dessus, et les commentaires dans le fichier de configuration postfix-logwatch.conf.

CONTRÔLE DE NIVEAU


La section Detailed du rapport se compose d'un certain nombre de sous-sections, chacune étant contrôlée à la fois globalement et indépendamment. Deux paramètres influencent la sortie fournie dans le rapport Detailed : un niveau de détail global (spécifié avec --detail) qui a un contrôle final (marteau puissant) limitant la sortie de la section Detailed, et des paramètres de détail spécifiques à la sous-section (petit marteau), qui permettent une limitation supplémentaire de la sortie pour une sous-section. Chaque sous-section peut être limitée à un niveau de profondeur spécifique, et chaque sous-niveau peut être limité par des limites N supérieures ou des seuils. L'argument levelspec pour chacun des limiteurs de niveau énumérés ci-dessus est utilisé à cette fin.

Il est probablement préférable de poursuivre l'explication de la limitation des sous-niveaux avec la hiérarchie bien connue de style plan ci-dessous, et quelques exemples de base :

    niveau 0
       niveau 1
          niveau 2
             niveau 3
                niveau 4
                niveau 4
          niveau 2
             niveau 3
                niveau 4
                niveau 4
                niveau 4
             niveau 3
                niveau 4
             niveau 3
       niveau 1
          niveau 2
             niveau 3
                niveau 4

La forme la plus simple de limitation de la sortie supprime toute sortie en dessous d'un niveau spécifié. Par exemple, un levelspec défini sur "2" affiche uniquement les données des niveaux 0 à 2. Considérez cela comme l'effondrement de chaque élément du sous-niveau 2, cachant ainsi tous les niveaux inférieurs (3, 4, ...), pour donner :

    niveau 0
       niveau 1
          niveau 2
          niveau 2
       niveau 1
          niveau 2

Parfois, le volume de sortie dans une section est trop important, et il est utile de supprimer toutes les données qui ne dépassent pas une certaine valeur seuil. Considérons une attaque par dictionnaire de spam, qui produit des listes très longues d'adresses e-mail ou IP de destinataires ayant frappé une seule fois. Chaque sous-niveau de la hiérarchie peut être limité par seuil en définissant appropriément le levelspec. Définir levels

LIMIT SPECIFICATION

The postfix-logwatch utility may be configured to limit the data output in the Detailed section. Limiters are of three types: Level, Top N, and Minimum Threshold. Limits are specified using the --limit option on the command line, or within a configuration file (see CONFIGURATION FILE).

When --limit is used, a levelspec is expected. This is a levelspec of "2::5" will suppress any data at level 2 that does not exceed a hit count of 5.

Perhaps producing a top N list, such as top 10 senders, is desired. A levelspec of "3:10:" limits level 3 data to only the top 10 hits.

With those simple examples out of the way, a levelspec is defined as a whitespace- or comma-separated list of one or more of the following:

l
Specifies the maximum level to be output for this sub-section, with a range from 0 to 10. if l is 0, no levels will be output, effectively disabling the sub-section (level 0 data is already provided in the Summary report, so level 1 is considered the first useful level in the Detailed report). Higher values will produce output up to and including the specified level.
l.n
Same as above, with the addition that n limits this section's level 1 output to the top n items. The value for n can be any integer greater than 1. (This form of limiting has less utility than the syntax shown below. It is provided for backwards compatibility; users are encouraged to use the syntax below).
l:n:t
This triplet specifies level l, top n, and minimum threshold t. Each of the values are integers, with l being the level limiter as described above, n being a top n limiter for the level l, and t being the threshold limiter for level l. When both n and t are specified, n has priority, allowing top n lists (regardless of threshold value). If the value of l is omitted, the specified values for n and/or t are used for all levels available in the sub-section. This permits a simple form of wildcarding (eg. place minimum threshold limits on all levels). However, specific limiters always override wildcard limiters. The first form of level limiter may be included in levelspec to restrict output, regardless of how many triplets are present.

All three forms of limiters are effective only when postfix-logwatch's detail level is 5 or greater (the Detailed section is not activated until detail is at least 5).

See the EXAMPLES section for usage scenarios.

CONFIGURATION FILE

postfix-logwatch can read configuration settings from a configuration file. Essentially, any command line option can be placed into a configuration file, and these settings are read upon startup.

Because postfix-logwatch can run either standalone or within Logwatch, to minimize confusion, postfix-logwatch inherits Logwatch's configuration file syntax requirements and conventions. These are:

  • White space lines are ignored.
  • Lines beginning with # are ignored
  • Settings are of the form: 
            option = value
  • Spaces or tabs on either side of the = character are ignored.
  • Any value protected in double quotes will be case-preserved.
  • All other content is reduced to lowercase (non-preserving, case insensitive).
  • All postfix-logwatch configuration settings must be prefixed with "$postfix_" or postfix-logwatch will ignore them.
  • When running under Logwatch, any values not prefixed with "$postfix_" are consumed by Logwatch; it only passes to postfix-logwatch (via environment variable) settings it considers valid.
  • The values True and Yes are converted to 1, and False and No are converted to 0.
  • Order of settings is not preserved within a configuration file (since settings are passed by Logwatch via environment variables, which have no defined order).

To include a command line option in a configuration file, prefix the command line option name with the word "$postfix_". The following configuration file setting and command line option are equivalent:

        $postfix_Line_Style = Truncate
        --line_style Truncate
Level limiters are also prefixed with $postfix_, but on the command line are specified with the --limit option: 
        $postfix_Sent = 2
        --limit Sent=2

The order of command line options and configuration file processing occurs as follows: 1) The default configuration file is read if it exists and no --config_file was specified on a command line. 2) Configuration files are read and processed in the order found on the command line. 3) Command line options override any options already set either via command line or from any configuration file.

Command line options are interpreted when they are seen on the command line, and later options will override previously set options. The notable exception is with limiter variables, which are interpreted in the order found, but only after all other options have been processed. This allows --reject_reply_patterns to determine the dynamic list of the various reject limiters.

See also --reject_reply_patterns.

EXIT STATUS

The postfix-logwatch utility exits with a status code of 0, unless an error occurred, in which case a non-zero exit status is returned.

NAME

postfix-logwatch - Logwatch filter for Postfix mail server

SYNOPSIS

logwatch [--detail level] [--range time] [--logfile log]
...
postfix-logwatch [--detail level] [--range time]
...

DESCRIPTION

postfix-logwatch is a Logwatch filter script that processes the Postfix mail server logs. It is intended to be run under the Logwatch framework, but it can also be run as a standalone script.

When run under Logwatch, it parses the Postfix log files and produces a summary report based on the requested detail level.

When run as a standalone script, it processes logs specified on the command line, or the default Postfix log file (/var/log/maillog or /var/log/mail.log), and prints the report to standard output.

LEVEL CONTROL

The level of detail in the report is controlled by the --detail command line argument. The levels are interpreted as follows:

0
Only errors are reported.
1
Errors and warnings are reported.
2
Errors, warnings, and informational messages are reported.
3
All messages are reported.
10
Similar to level 3, but does not truncate long lines.
11
Similar to level 10, but does not truncate long lines and also shows information about mail queue activity.

Note that the exact interpretation of detail levels may vary depending on the Logwatch version and configuration.

CONFIGURATION FILE

The behavior of postfix-logwatch can be customized using a configuration file. When run under Logwatch, the configuration file is typically located at /etc/logwatch/conf/services/postfix.conf.

When run in standalone mode, the configuration file is typically located at /usr/local/etc/postfix-logwatch.conf.

The configuration file uses a simple key-value format. Some common options include:

Maildir
Specifies the directory where mail is stored.
Mailfrom
Specifies the mail address from which messages are sent.
Sender
Specifies the sender of the report.
Debug
Sets the debug level.

EXIT STATUS

The exit status is 0 if the script ran successfully, and non-zero otherwise.

EXAMPLES

Report for today, with all levels of detail:


logwatch --service postfix --range today --detail 10
Same as above, but leaves long lines uncut:





logwatch --service postfix --range today --detail 11

ENVIRONMENT

The postfix-logwatch program uses the following (automatically set) environment variables when running under Logwatch:

LOGWATCH_DETAIL_LEVEL
This is the detail level specified with the Logwatch command line argument --detail or the Detail setting in the ...conf/services/postfix.conf configuration file.
LOGWATCH_DEBUG
This is the debug level specified with the Logwatch command line argument --debug.
postfix_xxx
The Logwatch program passes all settings postfix_xxx in the configuration file ...conf/services/postfix.conf to the postfix filter (which is actually named .../scripts/services/postfix) via environment variable.
