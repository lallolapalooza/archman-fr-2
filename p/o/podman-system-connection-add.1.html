NOM

podman-system-connection-add - Enregistrer la destination pour le service Podman

SYNTAXE

podman system connection add [options] nom destination

DESCRIPTION

Enregistre la destination ssh pour le(s) service(s) Podman distant(s). La destination ssh est donnée comme l'un des éléments suivants :
- [utilisateur@]hôte[:port]
- ssh://[utilisateur@]hôte[:port]
- unix://chemin
- tcp://hôte:port

L'utilisateur est invité à saisir le mot de passe de connexion ssh à distance ou la phrase secrète du fichier de clé, selon les besoins. L'agent ssh-agent est pris en charge s'il est en cours d'exécution.

OPTIONS

--default, -d

Fait de la nouvelle destination la destination par défaut pour cet utilisateur. La valeur par défaut est false.

--identity=chemin

Chemin vers le fichier d'identité ssh. Si le fichier d'identité a été chiffré, Podman demande à l'utilisateur la phrase secrète. Si aucun fichier d'identité n'est fourni et aucun utilisateur n'est spécifié, Podman utilise par défaut l'utilisateur exécutant la commande podman. Podman demande le mot de passe de connexion sur le serveur distant.

--port, -p=port

Port pour la destination ssh. La valeur par défaut est 22.

--socket-path=chemin

Chemin vers le socket de domaine unix du service Podman sur l'hôte de destination ssh.

--tls-ca=chemin

Chemin vers un fichier PEM contenant le bundle d'autorité de certification pour vérifier le certificat du serveur.

--tls-cert=chemin

Chemin vers un fichier PEM contenant le certificat client TLS à présenter au serveur. --tls-key doit également être fourni.

--tls-key=chemin

Chemin vers un fichier PEM contenant la clé privée correspondant à --tls-cert. --tls-cert doit également être fourni.

EXEMPLE

Ajouter une connexion système nommée :

$ podman system connection add QA podman.example.com

Ajouter une connexion système en utilisant les données SSH :

$ podman system connection add --identity ~/.ssh/dev_rsa production ssh://root@server.example.com:2222

Ajouter une connexion système nommée à un socket de domaine Unix local :

$ podman system connection add testing unix:///run/podman/podman.sock

Ajouter une connexion système nommée à un socket TCP local :

$ podman system connection add debug tcp://localhost:8080

Ajouter une connexion avec un port personnalisé :

$ podman system connection add --port 2222 staging user@staging.example.com

Ajouter une connexion avec un chemin de socket personnalisé :

$ podman system connection add --socket-path /run/user/1000/podman/podman.sock remote-user user@remote.example.com

Ajouter une connexion et en faire la destination par défaut :

$ podman system connection add --default production root@prod.example.com

Ajouter une connexion système nommée à un socket TCP distant sécurisé via TLS :

$ podman system connection add secure-debug --tls-cert=tls.crt --tls-key=tls.key --tls-ca=ca.crt tcp://podman.example.com:8443
