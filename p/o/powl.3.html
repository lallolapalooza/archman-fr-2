pow(3) Manuel des fonctions de bibliothèque pow(3)

NOM

pow, powf, powl - fonctions de puissance

BIBLIOTHÈQUE

Bibliothèque mathématique (libm, -lm)

SYNTAXE

#include <math.h>
double pow(double x, double y);
float powf(float x, float y);
long double powl(long double x, long double y);
Exigences relatives aux macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)):

powf(), powl():

    _ISOC99_SOURCE || _POSIX_C_SOURCE >= 200112L
        || /* Depuis glibc 2.19 : */ _DEFAULT_SOURCE
        || /* glibc <= 2.19 : */ _BSD_SOURCE || _SVID_SOURCE

DESCRIPTION

Ces fonctions retournent la valeur de x élevée à la puissance y.

VALEUR DE RETOUR

En cas de succès, ces fonctions retournent la valeur de x élevée à la puissance y.

Si le résultat dépasse la capacité, une erreur de plage se produit et les fonctions retournent HUGE_VAL, HUGE_VALF ou HUGE_VALL, respectivement, avec le signe mathématiquement correct.

Si le résultat est sous-dimensionné et non représentable, une erreur de plage se produit et 0.0 avec le signe approprié est retourné.

Si x est +0 ou -0, et y est un entier impair inférieur à 0, une erreur de pôle se produit et HUGE_VAL, HUGE_VALF ou HUGE_VALL est retourné, avec le même signe que x.

Si x est +0 ou -0, et y est inférieur à 0 et n'est pas un entier impair, une erreur de pôle se produit et +HUGE_VAL, +HUGE_VALF ou +HUGE_VALL est retourné.

Si x est +0 (-0), et y est un entier impair supérieur à 0, le résultat est +0 (-0).

Si x est 0, et y supérieur à 0 et non un entier impair, le résultat est +0.

Si x est -1, et y est l'infini positif ou l'infini négatif, le résultat est 1.0.

Si x est 1, le résultat est 1.0 (même si y est un NaN).

Si y est 0, le résultat est 1.0 (même si x est un NaN).

Si x est une valeur finie inférieure à 0, et y est un nombre non entier fini, une erreur de domaine se produit et un NaN est retourné.

Si la valeur absolue de x est inférieure à 1, et y est l'infini négatif, le résultat est l'infini positif.

Si la valeur absolue de x est supérieure à 1, et y est l'infini négatif, le résultat est +0.

Si la valeur absolue de x est inférieure à 1, et y est l'infini positif, le résultat est +0.

Si la valeur absolue de x est supérieure à 1, et y est l'infini positif, le résultat est l'infini positif.

Si x est l'infini négatif, et y est un entier impair inférieur à 0, le résultat est -0.

Si x est l'infini négatif, et y est inférieur à 0 et n'est pas un entier impair, le résultat est +0.

Si x est l'infini négatif, et y est un entier impair supérieur à 0, le résultat est l'infini négatif.

Si x est l'infini négatif, et y est supérieur à 0 et n'est pas un entier impair, le résultat est l'infini positif.

Si x est l'infini positif, et y est inférieur à 0, le résultat est +0.

Si x est l'infini positif, et y est supérieur à 0, le résultat est l'infini positif.

Sauf indication contraire, si x ou y est un NaN, le résultat est un NaN.

ERREURS

Voir math_error(7) pour plus d'informations sur la manière de déterminer si une erreur s'est produite lors de l'appel de ces fonctions.

Les erreurs suivantes peuvent se produire :

Erreur de domaine : x est négatif, et y est un nombre non entier fini
errno est défini à EDOM. Une exception de nombre à virgule flottante invalide (FE_INVALID) est levée.
Erreur de pôle : x est zéro, et y est négatif
errno est défini à ERANGE (mais voir BUGS). Une exception de division par zéro en virgule flottante (FE_DIVBYZERO) est levée.
Erreur de plage : le résultat dépasse la capacité
errno est défini à ERANGE. Une exception de dépassement de capacité en virgule flottante (FE_OVERFLOW) est levée.
Erreur de plage : le résultat est sous-dimensionné
errno est défini à ERANGE. Une exception de sous-dimensionnement en virgule flottante (FE_UNDERFLOW) est levée.

ATTRIBUTS

Interface Attribut Valeur

NORMES

C11, POSIX.1-2008.

HISTORIQUE

C99, POSIX.1-2001.

La variante retournant double est également conforme à SVr4, 4.3BSD, C89.

BOGUES

Bogues historiques (maintenant corrigés)

Avant glibc 2.28, sur certaines architectures (par exemple, x86-64), pow() pouvait être plus de 10 000 fois plus lent pour certaines entrées que pour d'autres entrées proches. Cela affectait uniquement pow() et non powf() ni powl(). Ce problème a été corrigé dans glibc 2.28.

Un certain nombre de bogues dans l'implémentation glibc de pow() ont été corrigés dans glibc 2.16.

Dans glibc 2.9 et versions antérieures, lorsqu'une erreur de pôle se produit, errno est défini à EDOM au lieu de ERANGE, qui est prescrit par POSIX. Depuis glibc 2.10, glibc fait la bonne chose.

Dans glibc 2.3.2 et versions antérieures, lorsqu'une erreur de dépassement de capacité ou de sous-dimensionnement se produit, pow() de glibc génère une fausse exception de nombre à virgule flottante invalide (FE_INVALID) en plus de l'exception de dépassement de capacité ou de sous-dimensionnement.
