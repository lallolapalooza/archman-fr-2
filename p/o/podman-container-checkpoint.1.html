NOM

podman-container-checkpoint - Sauvegarde un ou plusieurs conteneurs en cours d'exécution

SYNTAXE

podman container checkpoint [options] conteneur [conteneur ...]

DESCRIPTION

podman container checkpoint sauvegarde tous les processus d'un ou plusieurs conteneurs. Un conteneur peut être restauré à partir d'une sauvegarde avec podman-container-restore. Les ID ou noms de conteneurs sont utilisés comme entrée.

IMPORTANT : Si le conteneur utilise systemd comme point d'entrée, la sauvegarde du conteneur pourrait ne pas être possible.

OPTIONS

--all, -a

Sauvegarde tous les conteneurs en cours d'exécution.
Par défaut, c'est false.
IMPORTANT : Cette OPTION ne nécessite pas de nom ou d'ID de conteneur comme argument d'entrée.

--compress, -c=zstd | none | gzip

Spécifie l'algorithme de compression utilisé pour l'archive de sauvegarde créée avec l'OPTION --export, -e. Les algorithmes possibles sont zstd, none et gzip.
Une raison possible d'utiliser none est de permettre une création plus rapide des archives de sauvegarde. Ne pas compresser l'archive de sauvegarde peut entraîner une création plus rapide de celle-ci.
Par défaut, c'est zstd.

--create-image=image

Crée une image de sauvegarde à partir d'un conteneur en cours d'exécution. Il s'agit d'une image OCI standard créée dans le magasin d'images local. Elle se compose d'une seule couche contenant tous les fichiers de sauvegarde. Le contenu de cette couche d'image est dans le même format qu'une sauvegarde créée avec --export. Une image de sauvegarde peut être poussée vers un registre de conteneurs standard et récupérée sur un système différent pour permettre la migration de conteneurs. De plus, l'image peut être exportée avec podman image save et inspectée avec podman inspect. L'inspection d'une image de sauvegarde affiche des informations supplémentaires, stockées sous forme d'annotations, sur l'environnement hôte utilisé pour effectuer la sauvegarde :

  • io.podman.annotations.checkpoint.name : Nom lisible par l'homme du conteneur d'origine.
  • io.podman.annotations.checkpoint.rawImageName : Nom brut de l'image utilisée pour créer le conteneur d'origine (tel que spécifié par l'utilisateur).
  • io.podman.annotations.checkpoint.rootfsImageID : ID de l'image utilisée pour créer le conteneur d'origine.
  • io.podman.annotations.checkpoint.rootfsImageName : Nom de l'image utilisée pour créer le conteneur d'origine.
  • io.podman.annotations.checkpoint.podman.version : Version de Podman utilisée pour créer la sauvegarde.
  • io.podman.annotations.checkpoint.criu.version : Version de CRIU utilisée pour créer la sauvegarde.
  • io.podman.annotations.checkpoint.runtime.name : Runtime du conteneur (par exemple, runc, crun) utilisé pour créer la sauvegarde.
  • io.podman.annotations.checkpoint.runtime.version : Version du runtime du conteneur utilisée pour créer la sauvegarde.
  • io.podman.annotations.checkpoint.conmon.version : Version de conmon utilisée avec le conteneur d'origine.
  • io.podman.annotations.checkpoint.host.arch : Architecture CPU de l'hôte sur lequel la sauvegarde a été créée.
  • io.podman.annotations.checkpoint.host.kernel : Version du noyau Linux de l'hôte où la sauvegarde a été créée.
  • io.podman.annotations.checkpoint.cgroups.version : Version cgroup utilisée par l'hôte où la sauvegarde a été créée.
  • io.podman.annotations.checkpoint.distribution.version : Version de la distribution hôte sur laquelle la sauvegarde a été créée.
  • io.podman.annotations.checkpoint.distribution.name : Nom de la distribution hôte sur laquelle la sauvegarde a été créée.

--export, -e=archive

Exportez la sauvegarde dans une archive. Le type d'archive est spécifié avec --compress. La sauvegarde exportée peut être utilisée pour importer le conteneur sur un autre système et ainsi permettre la migration à chaud des conteneurs. Cette archive de sauvegarde inclut également toutes les modifications apportées au système de fichiers racine du conteneur, sauf si explicitement désactivé avec --ignore-rootfs.

--file-locks

Sauvegarde un conteneur avec des verrous de fichiers. Si une application s'exécutant dans le conteneur utilise des verrous de fichiers, cette OPTION est requise lors de la sauvegarde et de la restauration. Sinon, la sauvegarde des conteneurs avec des verrous de fichiers devrait échouer. Si les verrous de fichiers ne sont pas utilisés, cette option est ignorée.
Par défaut, c'est false.

--ignore-rootfs

Si une sauvegarde est exportée dans une archive, il est possible avec l'aide de --ignore-rootfs de désactiver explicitement l'inclusion des modifications du système de fichiers racine dans le fichier d'archive de sauvegarde.
Par défaut, c'est false.
IMPORTANT : Cette OPTION ne fonctionne qu'en combinaison avec --export, -e.

--ignore-volumes

Cette OPTION doit être utilisée en combinaison avec l'OPTION --export, -e. Lorsque cette OPTION est spécifiée, le contenu des volumes associés au conteneur n'est pas inclus dans l'archive de sauvegarde.
Par défaut, c'est false.

--keep, -k

Conserve tous les fichiers temporaires de journal et de statistiques créés par CRIU pendant la sauvegarde. Ces fichiers ne sont pas supprimés si la sauvegarde échoue, pour faciliter le débogage. Si la sauvegarde réussit, ces fichiers ne sont théoriquement pas nécessaires, mais si ces fichiers sont nécessaires, Podman peut les conserver pour une analyse plus approfondie.
Par défaut, c'est false.

--latest, -l

Au lieu de fournir l'ID ou le nom du conteneur, utilisez le dernier conteneur créé. Par défaut, c'est false. IMPORTANT : Cette OPTION n'est pas disponible avec le client Podman distant, y compris sur les machines Mac et Windows (hors WSL2). Cette OPTION ne nécessite pas de nom ou d'ID de conteneur comme argument d'entrée.

--leave-running, -R

Laisse le conteneur en cours d'exécution après la sauvegarde au lieu de l'arrêter.
Par défaut, c'est false.

--pre-checkpoint, -P

Ne sauvegarde que les informations de mémoire du conteneur, en laissant le conteneur en cours d'exécution. Les opérations ultérieures remplacent les sauvegardes précédentes.
Par défaut, c'est false.

La fonctionnalité qui consiste à ne sauvegarder que la mémoire du conteneur et, lors d'une seconde sauvegarde, à n'écrire que les pages mémoire qui ont changé depuis la première sauvegarde repose sur le bit soft-dirty du noyau Linux, qui n'est pas disponible sur tous les systèmes car il dépend de l'architecture du système et de la configuration du noyau Linux. Podman vérifie si le système actuel prend en charge cette fonctionnalité et renvoie une erreur si ce n'est pas le cas.

--print-stats

Affiche les statistiques sur la sauvegarde des conteneurs. La sortie est rendue dans un tableau JSON et contient des informations sur le temps nécessaire aux différentes opérations de sauvegarde. La plupart des statistiques de sauvegarde sont créées par CRIU et simplement transmises à Podman. Les informations suivantes sont fournies dans le tableau JSON :

  • podman_checkpoint_duration : Temps total (en microsecondes) nécessaire pour créer toutes les sauvegardes.
  • runtime_checkpoint_duration : Temps (en microsecondes) nécessaire au runtime du conteneur pour créer la sauvegarde.
  • freezing_time : Temps (en microsecondes) nécessaire à CRIU pour mettre en pause (geler) tous les processus du conteneur (mesuré par CRIU).
  • frozen_time : Temps (en microsecondes) pendant lequel tous les processus du conteneur ont été mis en pause (mesuré par CRIU).
  • memdump_time : Temps (en microsecondes) nécessaire pour extraire toutes les pages mémoire requises de tous les processus du conteneur (mesuré par CRIU).
  • memwrite_time : Temps (en microsecondes) nécessaire pour écrire toutes les pages mémoire requises dans les fichiers d'image de sauvegarde correspondants (mesuré par CRIU).
  • pages_scanned : Nombre de pages mémoire analysées pour déterminer si elles doivent être sauvegardées (mesuré par CRIU).
  • pages_written : Nombre de pages mémoire effectivement écrite ten to the image fichier de point de contrôle (mesuré par CRIU).

La valeur par défaut est false.

--tcp-established

Sauvegarder un conteneur avec des connexions TCP établies. Si l'image de sauvegarde contient des connexions TCP établies, cette OPTION est requise lors de la restauration. Par défaut, les conteneurs avec des connexions TCP établies ne sont pas sauvegardés.
La valeur par défaut est false.

--with-previous

Extraire le conteneur avec les fichiers image criu précédents dans le pré-point de contrôle. Ne fonctionne qu'avec runc 1.0-rc3 ou une version supérieure.
La valeur par défaut est false.
IMPORTANT : Cette OPTION n'est pas disponible avec --pre-checkpoint.

Cette option nécessite que l'option --pre-checkpoint ait été utilisée précédemment sur le même conteneur. Sans un pré-point de contrôle existant, cette option échoue.

Voir également --pre-checkpoint pour des informations supplémentaires sur la disponibilité de --pre-checkpoint sur différents systèmes.

EXEMPLES

Créer un point de contrôle pour le conteneur « mywebserver ».

# podman container checkpoint mywebserver

Créer une image de point de contrôle pour le conteneur « mywebserver ».

# podman container checkpoint --create-image mywebserver-checkpoint-1 mywebserver

Sauvegarder les informations mémoire du conteneur le plus récent dans une archive.

# podman container checkpoint -P -e pre-checkpoint.tar.zst -l

Conserver les informations mémoire d'une ancienne sauvegarde et ajouter les informations mémoire du nouveau conteneur.

# podman container checkpoint --with-previous -e checkpoint.tar.zst -l

Sauvegarder les informations mémoire du conteneur le plus récent dans une archive avec la méthode de compression spécifiée.

# podman container checkpoint -l --compress=none --export=dump.tar
# podman container checkpoint -l --compress=gzip --export=dump.tar.gz
