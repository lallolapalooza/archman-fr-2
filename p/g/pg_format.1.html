NOM

pg_format - Formatage de la syntaxe SQL PostgreSQL

DESCRIPTION

Ce formateur/nettoyeur SQL supporte les mots-clés de SQL-92, SQL-99, SQL-2003, SQL-2008, SQL-2011 et les mots-clés spécifiques à PostgreSQL. Fonctionne également avec toutes les autres bases de données.

pgFormatter peut fonctionner comme un programme en ligne de commande ou comme un CGI. Il détectera automatiquement son environnement et formatera la sortie en texte ou en HTML en fonction du contexte. Il peut également retourner une réponse formatée en JSON s'il est utilisé comme CGI avec 'Accept: application/json'.

La mise en surbrillance des mots-clés ne sera disponible que dans le contexte CGI.

Exécution en terminal/console

Utilisation : pg_format [options] fichier.sql

Nettoyeur de requêtes SQL PostgreSQL et de code PL/PGSQL.

Arguments :

fichier.sql peut être un fichier, plusieurs fichiers ou utiliser - pour lire la requête depuis stdin.
Retourne le SQL formaté vers stdout ou dans un fichier spécifié avec
l'option -o | --output.

Options :

-a | --anonymize      : obfusque toutes les littérales dans les requêtes, utile pour masquer
                        les données confidentielles avant le formatage.
-b | --comma-start    : dans une liste de paramètres, commence par la virgule (voir -e)
-B | --comma-break    : dans une instruction d'insertion, ajoute un saut de ligne après chaque virgule.
-c | --config FICHIER    : utilise un fichier de configuration. Par défaut, aucun fichier de
                        configuration n'est utilisé, à moins que les fichiers ./.pg_format ou
                        $HOME/.pg_format ou le fichier $XDG_CONFIG_HOME/pg_format/pg_format.conf n'existent.
-C | --wrap-comment   : avec --wrap-limit, applique le reformatage aux commentaires.
-d | --debug          : active le mode débogage. Désactivé par défaut.
-e | --comma-end      : dans une liste de paramètres, termine par la virgule (par défaut)
-f | --function-case N: Change la casse des fonctions PostgreSQL. Par défaut,
                        inchangée : 0. Valeurs : 0=>inchangée, 1=>minuscule,
                        2=>majuscule, 3=>capitalisée.
-F | --format STR     : format de sortie : text ou html. Par défaut : text.
-g | --nogrouping     : ajoute un saut de ligne entre les instructions dans le regroupement de transactions.
                        Par défaut, les instructions sont regroupées.
-h | --help           : affiche ce message et quitte.
-i | --inplace        : écrase les fichiers d'entrée avec le contenu formaté.
-k | --keep-newline   : conserve les lignes vides dans le code plpgsql.
-L | --no-extra-line  : n'ajoute pas de saut de ligne supplémentaire à la fin de la sortie.
-m | --maxlength SIZE : longueur maximale d'une requête, elle sera tronquée au-delà
                        de la taille donnée. Par défaut : pas de troncature.
-M | --multiline      : active la recherche multiligne pour -p ou --placeholder.
-n | --nocomment      : supprime tous les commentaires du code SQL.
-N | --numbering      : numérotation des instructions sous forme de commentaire avant chaque requête.
-o | --output fichier    : définit le nom du fichier pour la sortie. Par défaut : stdout.
-p | --placeholder RE : définit une expression régulière pour trouver le code qui ne doit pas être modifié.
-r | --redshift       : ajoute les mots-clés RedShift à la liste des mots-clés SQL.
                        Obsolète maintenant, utilisez --extra-keyword 'redshift' à la place.
-s | --spaces size    : change l'indentation des espaces, par défaut 4 espaces.
-S | --separator STR  : séparateur de code dynamique, par défaut une seule apostrophe.
-t | --format-type    : essaie un autre type de formatage pour certaines instructions.
-T | --tabs           : utilise des tabulations au lieu d'espaces, lorsque les
                        espaces sont utilisés, la valeur est mise à 1 quelle que soit la valeur définie pour -s.
-u | --keyword-case N : Change la casse du mot-clé réservé. Par défaut,
                        majuscules : 2. Valeurs : 0=>inchangée, 1=>minuscule,
                        2=>majuscule, 3=>capitalisée.
-U | --type-case N    : Change la casse du nom du type de données. Par défaut,
                        minuscules : 1. Valeurs : 0=>inchangée, 1=>minuscule,
                        2=>majuscule, 3=>capitalisée.
-v | --version        : affiche la version de pg_format et quitte.
-w | --wrap-limit N   : limite la longueur des requêtes.
-W | --wrap-after N   : nombre de colonnes après lequel les listes doivent être coupées.
                        Par défaut : met chaque élément sur sa propre ligne.
-X | --no-rcfile      : ne lit pas les fichiers rc automatiquement (./.pg_format ou
                        $HOME/.pg_format ou $XDG_CONFIG_HOME/pg_format).
                        L'option --config / -c le remplace.
--extra-function FICHIER : fichier contenant une liste de fonctions à formater comme les fonctions internes de PostgreSQL.
--extra-keyword FICHIER  : fichier contenant une liste de mots-clés à formater comme les mots-clés internes de PostgreSQL. Utilisez
                        la valeur spéciale 'redshift' pour le support des mots-clés Redshift
                        définis en interne dans pgFormatter.
--no-space-function : supprime l'espace entre l'appel de fonction et la parenthèse ouvrante.
--redundant-parenthesis: ne supprime pas les parenthèses redondantes dans DML.

Exemples :

cat samples/ex1.sql | pg_format -
pg_format -n samples/ex1.sql
pg_format -f 2 -n -o result.sql samples/ex1.sql

Contexte CGI

Installez pg_format dans votre dossier cgi-bin, accordez-lui les autorisations d'exécution en tant que script CGI (peut-être devriez-vous ajouter l'extension .cgi) et accédez-y depuis votre navigateur préféré. Copiez les fichiers logo_pgformatter.png et icon_pgformatter.ico dans le répertoire CGI, pg_format.cgi les recherche dans le même répertoire.

Vous avez un exemple en direct sans autre limitation que dix mille caractères dans votre requête SQL ici :

http://sqlformat.darold.net/

pg_format détectera automatiquement qu'il s'exécute dans un environnement CGI et produira tout le code HTML nécessaire pour faire fonctionner un site de formatage de code en ligne. Il n'y a rien d'autre à faire.

Vous devez d'abord installer les modules Perl CGI et JSON. Si ce n'est pas déjà fait, faites :

        yum install perl-cgi
        yum install perl-json
ou
        apt install libcgi-pm-perl
        apt install libjson-perl

en fonction de votre distribution.

INSTALLATION

Selon votre distribution Linux, vous pourriez avoir besoin d'installer le module Perl autodie :

sudo yum -y install perl-autodie

Téléchargez l'archive depuis github et décompressez l'archive comme suit :

version=5.3 #veuillez utiliser la dernière version publiée depuis github
wget https://github.com/darold/pgFormatter/archive/refs/tags/v${version}.tar.gz
tar xzf v${version}.tar.gz
cd pgFormatter-${version}/
perl Makefile.PL
make && sudo make install
cd ../ && rm -rf v${version}.tar.gz && rm -rf pgFormatter-${version} #nettoyage

Cela copiera le script Perl pg_format dans le répertoire /usr/local/bin/pg_format par défaut et la page de manuel dans /usr/local/share/man/man1/pg_format.1. Ce sont les répertoires d'installation par défaut pour l'installation 'site'.

Si vous souhaitez installer tout sous le répertoire /usr/, utilisez INSTALLDIRS='perl' comme argument de Makefile.PL. Le script sera installé dans /usr/bin/pg_format et la page de manuel dans /usr/share/man/man1/pg_format.1.

Par exemple, pour tout installer comme le fait Debian, procédez comme suit :

perl Makefile.PL INSTALLDIRS=vendor

Par défaut, INSTALLDIRS est défini sur site.

Les tests de régression peuvent être exécutés avec la commande suivante :

make test

Si vous avez docker installé, vous pouvez créer une image pgFormatter en utilisant :

docker build -t darold.net/pgformatter .

puis utilisez-la simplement comme ceci :

cat file.sql | docker run --rm -a stdin -a stdout -i darold.net/pgformatter -

FORMATAGE SPÉCIAL

Option -W, --wrap-after

Cette option peut être utilisée pour définir le nombre de colonnes après lequel les listes doivent être coupées. Par défaut, pgFormatter met chaque élément sur sa propre ligne. Ce format s'applique aux listes SELECT et FROM. Par exemple, la requête suivante :

SELECT a, b, c, d FROM t_1, t_2, t3 WHERE a = 10 AND b = 10;

sera formatée avec -W 4 comme suit :

SELECT a, b, c, d
FROM t_1, t_2, t3
WHERE a = 10
    AND b = 10;

Notez que ce formatage ne convient pas bien aux sous-requêtes dans les listes.

Option -w, --wrap-limit

Cette option limite la longueur des requêtes quel que soit la partie de la requête à la limite, sauf s'il s'agit d'un commentaire. Par exemple, si la limite est atteinte dans une constante de texte, le texte sera coupé. L'indentation n'est pas incluse dans le comptage des caractères. Cette option est appliquée dans tous les cas, même si d'autres options sont utilisées.

Option -C, --wrap-comment

Cette option coupe les commentaires à la longueur définie par -w, --wrap-limit, quelle que soit la partie du commentaire. L'indentation n'est pas incluse dans le comptage des caractères.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

/p>

Option -t, --format-type

Cette option active un formatage alternatif qui ajoute :

* une nouvelle ligne dans la liste des paramètres de procédure/fonction
* une nouvelle ligne dans le DDL de PUBLICATION et POLICY
* conserve l'énumération dans la clause GROUP BY sur une seule ligne

Il faut s'attendre à ce que cette liste s'allonge en fonction des pensées alternatives.

Option -g, --nogrouping

Par défaut, pgFormatter regroupe toutes les instructions lorsqu'elles sont dans une transaction :

BEGIN;
INSERT INTO foo VALUES (1, 'texte 1');
INSERT INTO foo VALUES (2, 'texte 2');
...
COMMIT;

En désactivant le regroupement des instructions, pgFormatter ajoutera toujours des caractères de nouvelle ligne supplémentaires entre les instructions, comme en dehors d'une transaction :

BEGIN;
INSERT INTO foo VALUES (1, 'texte 1');
INSERT INTO foo VALUES (2, 'texte 2');
...
COMMIT;

Cela peut améliorer la lisibilité des transactions non DML.

Option -L, --no-extra-line

Par défaut, pgFormatter ajoute toujours une ligne vide après la fin d'une instruction lorsqu'elle est terminée par un point-virgule, sauf dans un bloc de code plpgsql. Si la ligne vide supplémentaire à la fin de la sortie est inutile, vous pouvez la supprimer en ajoutant cette option à la ligne de commande.

Option --extra-function

pgFormatter applique un certain formatage aux appels de fonctions internes de PostgreSQL, mais il ne peut pas détecter les fonctions définies par l'utilisateur. Il est possible de définir une liste de fonctions dans un fichier (un nom de fonction par ligne) et de la donner à pgFormatter via l'option --extra-function, qui sera formatée comme les fonctions internes de PostgreSQL.

Option --extra-keyword

pgFormatter applique un certain formatage aux mots-clés internes de PostgreSQL, mais il ne peut pas détecter les mots-clés d'autres bases de données. Il est possible de définir une liste de mots-clés dans un fichier (un mot-clé par ligne) et de la donner à pgFormatter via l'option --extra-keyword, qui sera formatée comme les fonctions internes de PostgreSQL.

Vous pouvez également passer une valeur spéciale 'redshift' qui chargera les mots-clés définis en interne dans pgFormatter pour cette base de données. Cela était historiquement possible via l'option -r | --redshift, qui est maintenant obsolète et sera supprimée à l'avenir.

Option --no-space-function

Utilisez cette option pour supprimer l'espace caractère entre un appel de fonction et la parenthèse ouvrante qui suit. Par défaut, pgFormatter ajoute un espace caractère, par exemple :

DROP FUNCTION IF EXISTS app_public.hello (a text);

Lorsque cette option est utilisée, la requête résultante est formatée comme suit :

DROP FUNCTION IF EXISTS app_public.hello(a text);

Option --redundant-parenthesis

Par défaut, pgFormatter essaie de supprimer les parenthèses redondantes dans les DML, mais dans certains cas, elles doivent être préservées. L'utilisation de cette option laissera les parenthèses redondantes inchangées.

CONSEILS

Configuration

Si les paramètres par défaut de pg_format ne correspondent pas entièrement à vos besoins, vous pouvez personnaliser le comportement de pg_format en utilisant un fichier de configuration au lieu de répéter les options de la ligne de commande. Par défaut, pgFormatter recherche les fichiers ./.pg_format ou $HOME/.pg_format ou $XDG_CONFIG_HOME/pg_format/pg_format.conf s'ils existent, mais vous pouvez choisir un fichier de configuration alternatif en utilisant l'option de ligne de commande -c | --config.

Pour personnaliser pg_format.cgi, recherchez un fichier de configuration nommé pg_format.conf dans le même répertoire que le script CGI.

Pour un exemple de fichier de configuration, voir doc/pg_format.conf.sample.

Pour empêcher pg_format de rechercher dans les fichiers $XDG_CONFIG_HOME/pg_format ou $HOME/.pg_format, vous pouvez utiliser l'option de ligne de commande -X | --no-rcfile.

Formatage depuis stdin

Vous pouvez exécuter pg_format sans aucun argument ou avec '-' pour fournir le code SQL à formater via stdin.

Si vous utilisez le mode interactif, vous devez taper `ctrl+d` après avoir tapé votre instruction SQL à formater pour terminer la saisie.

$ pg_format
select * from customers;
< ctrl+d >

Vous pouvez utiliser stdin dans une seule ligne comme suit :

echo "select * from customers;" | pg_format

Formatage depuis VI

Avec pgFormatter, vous pouvez simplement ajouter la ligne suivante à votre fichier ~/.vimrc :

au FileType sql setl formatprg=/usr/local/bin/pg_format\ -

Cela permet à vos commandes gq d'utiliser pgFormatter automatiquement. Par exemple, si vous êtes sur la première ligne, taper :

ESC+gq+G

formatera l'intégralité du fichier.

ESC+gq+2j

formatera les deux lignes suivantes.

Merci à David Fetter pour ce conseil.

Il existe également le plugin (Neo)vim pour le formatage de code pour de nombreux types de fichiers qui prend en charge pg_format pour formater le type de fichier SQL. Merci à Anders Riutta pour le patch pour (Neo)vim.

Formatage depuis Atom

Si vous utilisez Atom comme éditeur favori, vous pouvez installer le package pg-formatter, qui est un wrapper Node.js de pgFormatter.

Fonctionnalités :

* Formater le texte sélectionné ou un fichier entier via un raccourci clavier ou une commande.
* Formater les fichiers SQL à la sauvegarde.

Installation :

Recherchez pg-formatter dans l'interface utilisateur d'Atom ou obtenez-le via la ligne de commande :

apm install pg-formatter

Utilisation :

Appuyez sur Ctrl-Alt-F pour formater le texte sélectionné (ou un fichier entier) ou définissez votre propre raccourci :

'ctrl-alt-p': 'pg-formatter:format'

De plus, vous pouvez formater automatiquement les fichiers SQL à la sauvegarde (désactivé par défaut).

Vous pouvez télécharger le package depuis l'URL :

https://atom.io/packages/pg-formatter

les sources sont disponibles sur https://github.com/gajus/pg-formatter

Merci à Alex Fedoseev pour le package Atom.

Empêcher le remplacement des extraits de code

En utilisant l'option de ligne de commande -p ou --placeholder, il est possible de laisser des parties de code intactes par pgFormatter dans vos requêtes SQL. Par exemple, dans une requête comme :

SELECT * FROM projects WHERE projectnumber
        IN <<internalprojects>> AND username = <<loginname>>;

vous voudrez peut-être que pgFormatter n'interprète pas << et >> comme des opérateurs de décalage de bits et modifie vos extraits de code. Vous pouvez utiliser une expression régulière Perl pour indiquer à pgFormatter de laisser certaines parties de la requête inchangées. Par exemple :

pg_format samples/ex9.sql -p '<<(?:.*)?>>'

ne formatera pas les opérateurs de type décalage de bits.

Si vous souhaitez renvoyer à la ligne les requêtes après 60 caractères (-w 60) et appliquer cette limite également aux commentaires (-C), les URL dans les commentaires pourraient être renvoyées à la ligne. Si vous préférez ne pas renvoyer à la ligne les URL, vous pouvez utiliser une expression régulière pour éviter cela. Par exemple :

pg_format samples/ex62.sql -C -w 60 -p 'https?:\/\/(www\.)?[-a-zA-Z0-9@:%._\+~#=]{1,256}\.[a-zA-Z0-9()]{1,6}\b([-a-zA-Z0-9()@:%_\+.~#?&//=]*)'

renverra à la ligne les requêtes et les commentaires, mais pas les URL.

Empêcher le formatage de code dynamique

Par défaut, pgFormatter prend tout le code entre apostrophes comme une chaîne de caractères constante et n'effectue aucun formatage sur ce code. Il est courant d'utiliser une chaîne comme séparateur de code pour éviter de doubler les apostrophes dans la génération de code dynamique. Dans ce cas, pgFormatter peut échouer à détecter automatiquement le séparateur de code. Par défaut, il recherchera toute chaîne après le mot-clé EXECUTE commençant par un signe dollar. S'il ne peut pas détecter automatiquement votre séparateur de code, vous pouvez utiliser l'option de ligne de commande -S ou --separator pour définir le séparateur de code à utiliser.

Wrapper léger Node.js

Gajus Kuizinas a créé un wrapper Node.js pour exécuter pgFormatter. Vous pouvez le trouver sur https://github.com/gajus/pg-formatter.

Personnaliser le CSS pour la sortie CGI

Vous pouvez modifier le style HTML rendu par le style CSS par défaut en créant un fichier nommé custom_css_file.css dans le répertoire du script CGI pgFormatter. Le CSS par défaut sera entièrement remplacé par le contenu de ce fichier personnalisé. Vous devez examiner la sortie HTML générée pour obtenir le code CSS par défaut utilisé.

Utiliser pgFormatter comme une API

Vous pouvez utiliser pgFormatter comme une API en définissant l'en-tête HTTP 'Accept' avec la valeur 'application/json' lors de son appel en tant qu'application CGI. Si vous ne souhaitez pas activer cette fonctionnalité, définissez "$self->{ 'enable_api' } = 0" dans la sous-routine "set_config" de lib/pgFormatter/CGI.pm.
