PGBOUNCER(1) Bases de données PGBOUNCER(1)

NOM

pgbouncer - multiplexeur de connexions léger pour PostgreSQL

SYNTAXE

pgbouncer [-d][-R][-v][-u utilisateur] <pgbouncer.ini>
pgbouncer -V|-h

Sur Windows, les options sont :

pgbouncer.exe [-v][-u utilisateur] <pgbouncer.ini>
pgbouncer.exe -V|-h

Options supplémentaires pour la configuration d'un service Windows :

pgbouncer.exe --regservice   <pgbouncer.ini>
pgbouncer.exe --unregservice <pgbouncer.ini>

DESCRIPTION

pgbouncer est un multiplexeur de connexions PostgreSQL. Toute application cible peut se connecter à pgbouncer comme s'il s'agissait d'un serveur PostgreSQL, et pgbouncer établira une connexion au serveur réel, ou réutilisera l'une de ses connexions existantes.

L'objectif de pgbouncer est de réduire l'impact sur les performances de l'ouverture de nouvelles connexions à PostgreSQL.

Afin de ne pas compromettre la sémantique des transactions pour le multiplexage des connexions, pgbouncer prend en charge plusieurs types de multiplexage lors de la rotation des connexions :

Multiplexage de session
Méthode la plus respectueuse. Lorsqu'un client se connecte, une connexion serveur lui est attribuée pendant toute la durée de sa connexion. Lorsque le client se déconnecte, la connexion serveur est remise dans le pool. C'est la méthode par défaut.
Multiplexage de transaction
Une connexion serveur est attribuée à un client uniquement pendant une transaction. Lorsque PgBouncer constate que la transaction est terminée, la connexion serveur est remise dans le pool.
Multiplexage d'instruction
Méthode la plus agressive. La connexion serveur est remise dans le pool immédiatement après la fin d'une requête. Les transactions de plusieurs instructions sont interdites dans ce mode car elles seraient rompues.

L'interface d'administration de pgbouncer consiste en de nouvelles commandes SHOW disponibles lors de la connexion à une base de données spéciale "virtuelle" pgbouncer.

DÉMARRAGE RAPIDE

Configuration et utilisation de base comme suit.

1.
Créez un fichier pgbouncer.ini. Détails dans pgbouncer(5). Exemple simple :
 [databases]
 template1 = host=localhost port=5432 dbname=template1
 [pgbouncer]
 listen_port = 6432
 listen_addr = localhost
 auth_type = md5
 auth_file = userlist.txt
 logfile = pgbouncer.log
 pidfile = pgbouncer.pid
 admin_users = utilisateur
2.
Créez un fichier userlist.txt qui contient les utilisateurs autorisés :
 "utilisateur" "même_mot_de_passe_que_sur_le_serveur"
3.
Lancez pgbouncer :
 $ pgbouncer -d pgbouncer.ini
4.
Faites connecter votre application (ou le client psql) à pgbouncer au lieu de directement au serveur PostgreSQL :
 $ psql -p 6432 -U utilisateur template1
5.
Gérez pgbouncer en vous connectant à la base de données spéciale d'administration pgbouncer et en émettant SHOW HELP; pour commencer :
 $ psql -p 6432 -U utilisateur pgbouncer
 pgbouncer=# SHOW HELP;
 NOTICE:  Console usage
 DETAIL:
   SHOW [HELP|CONFIG|DATABASES|FDS|POOLS|CLIENTS|SERVERS|SOCKETS|LISTS|VERSION|...]
   SET key = arg
   RELOAD
   PAUSE
   SUSPEND
   RESUME
   SHUTDOWN
   [...]
6.
Si vous avez apporté des modifications au fichier pgbouncer.ini, vous pouvez le recharger avec :
 pgbouncer=# RELOAD;

COMMUTATEURS DE LIGNE DE COMMANDE

-d, --daemon
Exécuter en arrière-plan. Sans cette option, le processus s'exécute au premier plan.

En mode démon, la spécification de pidfile ainsi que de logfile ou syslog est requise. Aucun message de journal ne sera écrit dans stderr après être passé en arrière-plan.

Note : Ne fonctionne pas sous Windows ; pgbouncer doit y être exécuté en tant que service.

-R, --reboot
OBSOLÈTE : Au lieu de cette option, utilisez un redémarrage progressif avec plusieurs processus pgbouncer écoutant sur le même port en utilisant so_reuseport à la place Redémarrage en ligne. Cela signifie se connecter au processus en cours d'exécution, en charger les sockets ouverts, puis les utiliser. S'il n'y a pas de processus actif, démarrez normalement. Note : Ne fonctionne que si le système d'exploitation prend en charge les sockets Unix et que unix_socket_dir n'est pas désactivé dans la configuration. Ne fonctionne pas sous Windows. Ne fonctionne pas avec les connexions TLS, elles sont abandonnées.
-u NOMUTILISATEUR, --user=NOMUTILISATEUR
Basculer sur l'utilisateur donné au démarrage.
-v, --verbose
Augmenter la verbosité. Peut être utilisé plusieurs fois.
-q, --quiet
Soyez silencieux : ne pas journaliser dans stderr. Cela n'affecte pas la verbosité de la journalisation, seulement que stderr ne doit pas être utilisé. Pour une utilisation dans les scripts init.d.
-V, --version
Afficher la version.
-h, --help
Afficher une aide courte.
--regservice
Win32 : Enregistrer pgbouncer pour qu'il s'exécute en tant que service Windows. La valeur du paramètre de configuration service_name est utilisée comme nom sous lequel s'enregistrer.
--unregservice
Win32 : Désenregistrer un service Windows.

CONSOLE ADMINISTRATEUR

La console est accessible en se connectant normalement à la base de données pgbouncer :

$ psql -p 6432 pgbouncer

Seuls les utilisateurs listés dans les paramètres de configuration admin_users ou stats_users sont autorisés à se connecter à la console. (Sauf si auth_type=any, alors tout utilisateur est autorisé en tant que stats_user.)

De plus, le nom d'utilisateur pgbouncer est autorisé à se connecter sans mot de passe, si la connexion provient du socket Unix et que l'utilisateur client a le même UID que le processus en cours d'exécution.

La console d'administration ne prend actuellement en charge que le protocole de requête simple. Certains pilotes utilisent le protocole de requête étendu pour toutes les commandes ; ces pilotes ne fonctionneront pas pour cela.

Commandes SHOW

Les commandes SHOW affichent des informations. Chaque commande est décrite ci-dessous.

SHOW STATS

Affiche les statistiques. Dans cette commande et les commandes associées, les chiffres totaux sont depuis le démarrage du processus, les moyennes sont mises à jour toutes les stats_period.

database
Les statistiques sont présentées par base de données.

SHOW

Display status information about the server.

The following formats are available:

  • SHOW STATS
  • SHOW STATS_TOTALS
  • SHOW STATS_AVERAGES
  • SHOW TOTALS
  • SHOW SERVERS
  • SHOW CLIENTS
  • SHOW POOLS

There is also a new option to display values for a specific pool.

  • SHOW POOL poolname

SHOW STATS

Display performance statistics.

total_xact_count
Nombre total de transactions SQL mises en pool par pgbouncer.
total_query_count
Nombre total de commandes SQL mises en pool par pgbouncer.
total_received
Volume total en octets du trafic réseau reçu par pgbouncer.
total_sent
Volume total en octets du trafic réseau envoyé par pgbouncer.
total_xact_time
Nombre total de microsecondes passées par pgbouncer lorsqu'il était connecté à PostgreSQL dans une transaction, soit inactif en transaction, soit en cours d'exécution de requêtes.
total_query_time
Nombre total de microsecondes passées par pgbouncer lorsqu'il était activement connecté à PostgreSQL, en cours d'exécution de requêtes.
total_wait_time
Temps passé par les clients à attendre un serveur, en microsecondes. Mis à jour lorsqu'une connexion client se voit attribuer une connexion backend.
avg_xact_count
Transactions moyennes par seconde sur la dernière période de statistiques.
avg_query_count
Requêtes moyennes par seconde sur la dernière période de statistiques.

Octets moyens reçus (depuis les clients) par seconde.
avg_sent
Octets moyens envoyés (vers les clients) par seconde.
avg_xact_time
Durée moyenne d'une transaction, en microsecondes.
avg_query_time
Durée moyenne d'une requête, en microsecondes.
avg_wait_time
Temps moyen passé par les clients à attendre un serveur qui s'est vu attribuer une connexion backend pendant la période de statistiques actuelle, en microsecondes (moyenné par seconde pendant cette période).

Similaire à SHOW STATS mais agrégé sur toutes les bases de données.

Si un nom de base de données est donné, seule cette base de données sera mise en pause.

Les nouvelles connexions client à une base de données mise en pause attendront que RESUME soit appelé.

DISABLE db

Rejeter toutes les nouvelles connexions client sur la base de données donnée.

ENABLE db

Autoriser les nouvelles connexions client après une commande DISABLE précédente.

RECONNECT [db]

Ferme chaque connexion serveur ouverte pour la base de données donnée, ou toutes les bases de données, après sa libération (selon le mode de pooling), même si sa durée de vie n'est pas encore terminée. Les nouvelles connexions serveur peuvent être établies immédiatement et se connecteront selon les besoins, conformément aux paramètres de taille du pool.

Cette commande est utile lorsque la configuration de la connexion serveur a changé, par exemple pour effectuer un basculement progressif vers un nouveau serveur. Il n'est *pas* nécessaire d'exécuter cette commande lorsque la chaîne de connexion dans pgbouncer.ini a été modifiée et rechargée (voir RELOAD) ou lorsque la résolution DNS a changé, car alors l'équivalent de cette commande sera exécuté automatiquement. Cette commande n'est nécessaire que si quelque chose en aval de PgBouncer redirige les connexions.

Après l'exécution de cette commande, il pourrait y avoir une période prolongée pendant laquelle certaines connexions serveur iront vers une ancienne destination et certaines connexions serveur iront vers une nouvelle destination. Ceci est probablement judicieux uniquement lors du basculement du trafic en lecture seule entre répliques en lecture seule, ou lors du basculement entre nœuds d'une configuration de réplication multi-maître. Si toutes les connexions doivent être basculées en même temps, PAUSE est recommandé à la place. Pour fermer les connexions serveur sans attendre (par exemple, dans des scénarios de basculement d'urgence plutôt que de basculement progressif), envisagez également KILL.

KILL db

Supprime immédiatement toutes les connexions client et serveur sur la base de données donnée.

Les nouvelles connexions client à une base de données tuée attendront que RESUME soit appelé.

SUSPEND

Tous les tampons de socket sont vidés et PgBouncer cesse d'écouter les données sur eux. La commande ne reviendra pas avant que tous les tampons ne soient vides. À utiliser lors du redémarrage en ligne de PgBouncer.

Les nouvelles connexions client à une base de données suspendue attendront que RESUME soit appelé.

RESUME [db]

Reprend le travail suite à une commande KILL, PAUSE ou SUSPEND précédente.

SHUTDOWN

Le processus PgBouncer se terminera.

RELOAD

Le processus PgBouncer rechargera ses fichiers de configuration et mettra à jour les paramètres modifiables. Cela inclut le fichier de configuration principal ainsi que les fichiers spécifiés par les paramètres auth_file et auth_hba_file.

PgBouncer remarque lorsqu'un rechargement de fichier de configuration modifie les paramètres de connexion d'une définition de base de données. Une connexion serveur existante vers l'ancienne destination sera fermée lorsque la connexion serveur sera libérée la prochaine fois (selon le mode de pooling), et les nouvelles connexions serveur utiliseront immédiatement les paramètres de connexion mis à jour.

WAIT_CLOSE [db]

Attend que toutes les connexions serveur, soit de la base de données spécifiée, soit de toutes les bases de données, aient quitté l'état « close_needed » (voir SHOW SERVERS). Ceci peut être appelé après un RECONNECT ou un RELOAD pour attendre que le changement de configuration respectif soit entièrement activé, par exemple dans les scripts de basculement.

Autres commandes

SET key = arg

Modifie un paramètre de configuration (voir aussi SHOW CONFIG). Par exemple :

SET log_connections = 1;
SET server_check_query = 'select 2';

(Notez que cette commande est exécutée sur la console d'administration de PgBouncer et définit les paramètres de PgBouncer. Une commande SET exécutée sur une autre base de données sera transmise au backend PostgreSQL comme toute autre commande SQL.)

Signaux

SIGHUP
Recharge la configuration. Identique à l'émission de la commande RELOAD sur la console.
SIGINT
Arrêt sûr. Identique à l'émission de PAUSE et SHUTDOWN sur la console.
SIGTERM
Arrêt immédiat. Identique à l'émission de SHUTDOWN sur la console.
SIGUSR1
Identique à l'émission de PAUSE sur la console.
SIGUSR2
Identique à l'émission de RESUME sur la console.

Paramètres Libevent

D'après la documentation de Libevent :

Il est possible de désactiver la prise en charge d'epoll, kqueue, devpoll, poll ou select en définissant respectivement les variables d'environnement EVENT_NOEPOLL, EVENT_NOKQUEUE, EVENT_NODEVPOLL, EVENT_NOPOLL ou EVENT_NOSELECT.

En définissant la variable d'environnement EVENT_SHOW_METHOD, libevent affiche la méthode de notification du noyau qu'il utilise.
