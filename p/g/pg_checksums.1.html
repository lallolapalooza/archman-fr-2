PG_CHECKSUMS(1) Documentation PostgreSQL 18.1 PG_CHECKSUMS(1)

NOM

pg_checksums - activer, désactiver ou vérifier les sommes de contrôle des données dans un cluster de bases de données PostgreSQL

SYNTAXE

pg_checksums [option...] [[-D | --pgdata]datadir]

DESCRIPTION

pg_checksums vérifie, active ou désactive les sommes de contrôle des données dans un cluster PostgreSQL. Le serveur doit être arrêté proprement avant d'exécuter pg_checksums. Lors de la vérification des sommes de contrôle, le code de sortie est zéro s'il n'y a pas d'erreurs de sommes de contrôle, et non zéro si au moins une erreur de somme de contrôle est détectée. Lors de l'activation ou de la désactivation des sommes de contrôle, le code de sortie est non zéro si l'opération a échoué.

Lors de la vérification des sommes de contrôle, chaque fichier du cluster est parcouru. Lors de l'activation des sommes de contrôle, chaque bloc de fichier de relation dont la somme de contrôle a changé est réécrit sur place. La désactivation des sommes de contrôle met uniquement à jour le fichier pg_control.

OPTIONS

Les options de ligne de commande suivantes sont disponibles :

-D répertoire
--pgdata=répertoire

Spécifie le répertoire où le cluster de bases de données est stocké.

-c
--check

Vérifie les sommes de contrôle. C'est le mode par défaut si rien d'autre n'est spécifié.

-d
--disable

Désactive les sommes de contrôle.

-e
--enable

Active les sommes de contrôle.

-f filenode
--filenode=filenode

Valide uniquement les sommes de contrôle dans la relation avec le filenode filenode.

-N
--no-sync

Par défaut, pg_checksums attend que tous les fichiers soient écrits en toute sécurité sur disque. Cette option fait que pg_checksums retourne sans attendre, ce qui est plus rapide, mais signifie qu'un crash ultérieur du système d'exploitation peut laisser le répertoire de données mis à jour corrompu. Généralement, cette option est utile pour les tests mais ne doit pas être utilisée sur une installation de production. Cette option n'a aucun effet lors de l'utilisation de --check.

-P
--progress

Active le rapport d'avancement. L'activer fournira un rapport d'avancement lors de la vérification ou de l'activation des sommes de contrôle.

--sync-method=méthode

Lorsqu'il est défini sur fsync, ce qui est le défaut, pg_checksums ouvrira et synchronisera récursivement tous les fichiers du répertoire de données. La recherche de fichiers suivra les liens symboliques pour le répertoire WAL et chaque tablespace configuré.

Sous Linux, syncfs peut être utilisé à la place pour demander au système d'exploitation de synchroniser l'ensemble des systèmes de fichiers qui contiennent le répertoire de données, les fichiers WAL et chaque tablespace. Voir recovery_init_sync_method pour des informations sur les mises en garde à prendre en compte lors de l'utilisation de syncfs.

Cette option n'a aucun effet lorsque --no-sync est utilisé.

-v
--verbose

Active la sortie verbeuse. Liste tous les fichiers vérifiés.

-V
--version

Affiche la version de pg_checksums et quitte.

-?
--help

Affiche l'aide sur les arguments de la ligne de commande de pg_checksums et quitte.

ENVIRONNEMENT

PGDATA

Spécifie le répertoire où le cluster de bases de données est stocké ; peut être remplacé en utilisant l'option -D.

PG_COLOR

Spécifie si l'utilisation de la couleur doit être utilisée dans les messages de diagnostic. Les valeurs possibles sont always, auto et never.

NOTES

L'activation des sommes de contrôle dans un grand cluster peut potentiellement prendre beaucoup de temps. Pendant cette opération, le cluster ou d'autres programmes qui écrivent dans le répertoire de données ne doivent pas être démarrés, sinon une perte de données pourrait survenir.

Lors de l'utilisation d'une configuration de réplication avec des outils qui effectuent des copies directes de blocs de fichiers de relation (par exemple pg_rewind(1)), l'activation ou la désactivation des sommes de contrôle peut entraîner des corruptions de page sous la forme de sommes de contrôle incorrectes si l'opération n'est pas effectuée de manière cohérente sur tous les nœuds. Lors de l'activation ou de la désactivation des sommes de contrôle dans une configuration de réplication, il est donc recommandé d'arrêter tous les clusters avant de les basculer tous de manière cohérente. Détruire toutes les répliques, effectuer l'opération sur le maître, puis recréer les répliques à partir de zéro est également sûr.

Si pg_checksums est interrompu ou tué pendant l'activation ou la désactivation des sommes de contrôle, la configuration des sommes de contrôle des données du cluster reste inchangée, et pg_checksums peut être relancé pour effectuer la même opération.
