NOM

pg_amcheck - vérifie la corruption d'une ou plusieurs bases de données PostgreSQL

SYNOPSIS

pg_amcheck [option...] [dbname]

DESCRIPTION

pg_amcheck permet d'exécuter les fonctions de vérification de corruption d'amcheck sur une ou plusieurs bases de données, avec des options pour sélectionner les schémas, tables et index à vérifier, les types de vérifications à effectuer, et si les vérifications doivent être effectuées en parallèle, et si oui, le nombre de connexions parallèles à établir et à utiliser.

Seules les relations de tables ordinaires et toast, les vues matérialisées, les séquences et les index btree sont actuellement prises en charge. Les autres types de relations sont ignorés silencieusement.

Si dbname est spécifié, il doit s'agir du nom d'une seule base de données à vérifier, et aucune autre option de sélection de base de données ne doit être présente. Sinon, si des options de sélection de base de données sont présentes, toutes les bases de données correspondantes seront vérifiées. Si aucune de ces options n'est présente, la base de données par défaut sera vérifiée. Les options de sélection de base de données incluent --all, --database et --exclude-database. Elles incluent également --relation, --exclude-relation, --table, --exclude-table, --index, et --exclude-index, mais uniquement lorsque ces options sont utilisées avec un motif en trois parties (par exemple, mydb*.myschema*.myrel*). Enfin, elles incluent --schema et --exclude-schema lorsque ces options sont utilisées avec un motif en deux parties (par exemple, mydb*.myschema*).

dbname peut également être une chaîne de connexion.

OPTIONS

Les options de ligne de commande suivantes contrôlent ce qui est vérifié :

-a
--all

Vérifie toutes les bases de données, à l'exception de celles exclues par --exclude-database.

-d motif
--database=motif

Vérifie les bases de données correspondant au motif spécifié, à l'exception de celles exclues par --exclude-database. Cette option peut être spécifiée plus d'une fois.

-D motif
--exclude-database=motif

Exclut les bases de données correspondant au motif donné. Cette option peut être spécifiée plus d'une fois.

-i motif
--index=motif

Vérifie les index correspondant au motif spécifié, à moins qu'ils ne soient autrement exclus. Cette option peut être spécifiée plus d'une fois.

Ceci est similaire à l'option --relation, sauf que cela s'applique uniquement aux index, pas aux autres types de relations.

-I motif
--exclude-index=motif

Exclut les index correspondant au motif spécifié. Cette option peut être spécifiée plus d'une fois.

Ceci est similaire à l'option --exclude-relation, sauf que cela s'applique uniquement aux index, pas aux autres types de relations.

-r motif
--relation=motif

Vérifie les relations correspondant au motif spécifié, à moins qu'elles ne soient autrement exclues. Cette option peut être spécifiée plus d'une fois.

Les motifs peuvent être non qualifiés, par exemple myrel*, ou qualifiés par un schéma, par exemple myschema*.myrel* ou qualifiés par une base de données et un schéma, par exemple mydb*.myschema*.myrel*. Un motif qualifié par une base de données ajoutera les bases de données correspondantes à la liste des bases de données à vérifier.

-R motif
--exclude-relation=motif

Exclut les relations correspondant au motif spécifié. Cette option peut être spécifiée plus d'une fois.

Comme pour --relation, le motif peut être non qualifié, qualifié par un schéma, ou qualifié par une base de données et un schéma.

-s motif
--schema=motif

Vérifie les tables et index dans les schémas correspondant au motif spécifié, à moins qu'ils ne soient autrement exclus. Cette option peut être spécifiée plus d'une fois.

Pour sélectionner uniquement les tables dans les schémas correspondant à un motif particulier, envisagez d'utiliser quelque chose comme --table=SCHEMAPAT.* --no-dependent-indexes. Pour sélectionner uniquement les index, envisagez d'utiliser quelque chose comme --index=SCHEMAPAT.*.

Un motif de schéma peut être qualifié par une base de données. Par exemple, vous pouvez écrire --schema=mydb*.myschema* pour sélectionner les schémas correspondant à myschema* dans les bases de données correspondant à mydb*.

-S motif
--exclude-schema=motif

Exclut les tables et index dans les schémas correspondant au motif spécifié. Cette option peut être spécifiée plus d'une fois.

Comme pour --schema, le motif peut être qualifié par une base de données.

-t motif
--table=motif

Vérifie les tables correspondant au motif spécifié, à moins qu'elles ne soient autrement exclues. Cette option peut être spécifiée plus d'une fois.

Ceci est similaire à l'option --relation, sauf que cela s'applique uniquement aux tables, vues matérialisées et séquences, pas aux index.

-T motif
--exclude-table=motif

Exclut les tables correspondant au motif spécifié. Cette option peut être spécifiée plus d'une fois.

Ceci est similaire à l'option --exclude-relation, sauf que cela s'applique uniquement aux tables, vues matérialisées et séquences, pas aux index.

--no-dependent-indexes

Par défaut, si une table est vérifiée, tous les index btree de cette table seront également vérifiés, même s'ils ne sont pas explicitement sélectionnés par une option telle que --index ou --relation. Cette option supprime ce comportement.

--no-dependent-toast

Par défaut, si une table est vérifiée, sa table toast, le cas échéant, sera également vérifiée, même si elle n'est pas explicitement sélectionnée par une option telle que --table ou --relation. Cette option supprime ce comportement.

--no-strict-names

Par défaut, si un argument à --database, --table, --index, ou --relation ne correspond à aucun objet, il s'agit d'une erreur fatale. Cette option transforme cette erreur en avertissement.

Les options de ligne de commande suivantes contrôlent la vérification des tables :

--exclude-toast-pointers

Par défaut, chaque fois qu'un pointeur toast est rencontré dans une table, une recherche est effectuée pour s'assurer qu'il référence des entrées apparemment valides dans la table toast. Ces vérifications peuvent être assez lentes, et cette option peut être utilisée pour les ignorer.

--on-error-stop

Après avoir signalé toutes les corruptions sur la première page d'une table où une corruption est trouvée, arrêtez le traitement de cette relation de table et passez à la table ou à l'index suivant.

Notez que la vérification des index s'arrête toujours après la première page corrompue. Cette option n'a de sens que par rapport aux relations de table.

--skip=option

Si all-frozen est donné, les vérifications de corruption de table ignoreront les pages dans toutes les tables marquées comme toutes gelées (all frozen).

Si all-visible est donné, les vérifications de corruption de table ignoreront les pages dans toutes les tables marquées comme toutes visibles (all visible).

Par défaut, aucune page n'est ignorée. Ceci peut être spécifié comme none, mais comme c'est le comportement par défaut, il n'est pas nécessaire de le mentionner.

--startblock=bloc

Commence la vérification au numéro de bloc spécifié. Une erreur se produira si la relation de table vérifiée a moins de ce nombre de blocs. Cette option ne s'applique pas aux index, et est probablement utile uniquement lors de la vérification d'une seule relation de table. Voir --endblock pour d'autres mises en garde.

--endblock=bloc

Termine la vérification au numéro de bloc spécifié. Une erreur se produira si la relation de table vérifiée a moins de ce nombre de blocs. Cette option ne s'applique pas aux index, et est probablement utile uniquement lors de la vérification d'une seule relation de table. Si une table régulière et une table toast sont vérifiées, cette option s'appliquera aux deux, mais des blocs de toast avec des numéros plus élevés peuvent encore être accédés lors de la validation des pointeurs toast, sauf si cela est supprimé à l'aide de --exclude-toast-pointers.

Les options de ligne de commande suivantes contrôlent la vérification des index B-tree :

--checkunique

Pour chaque index avec une contrainte unique vérifié, vérifiez qu'aucun des doublons n'est visible dans l'index en utilisant l'option checkunique d'amcheck.

--heapallind

exed

Pour chaque index vérifié, vérifiez la présence de toutes les tuples de tas comme tuples d'index dans l'index en utilisant l'option heapallindexed d'amcheck.

--parent-check

Pour chaque index btree vérifié, utilisez la fonction bt_index_parent_check d'amcheck, qui effectue des vérifications supplémentaires des relations parent/enfant pendant la vérification de l'index.

Par défaut, la fonction bt_index_check d'amcheck est utilisée, mais notez que l'utilisation de l'option --rootdescend sélectionne implicitement bt_index_parent_check.

--rootdescend

Pour chaque index vérifié, retrouvez les tuples au niveau feuille en effectuant une nouvelle recherche à partir de la page racine pour chaque tuple en utilisant l'option rootdescend d'amcheck.

L'utilisation de cette option sélectionne également implicitement l'option --parent-check.

Cette forme de vérification a été initialement écrite pour aider au développement des fonctionnalités d'index btree. Elle peut avoir une utilité limitée, voire nulle, pour détecter les types de corruption qui se produisent en pratique. Elle peut également considérablement augmenter le temps et les ressources nécessaires au serveur pour la vérification de la corruption.


Attention

Les vérifications supplémentaires effectuées sur les index B-tree lorsque l'option --parent-check ou l'option --rootdescend est spécifiée nécessitent des verrous de relation relativement forts. Ces vérifications sont les seules qui bloqueront les modifications de données concurrentes des commandes INSERT, UPDATE et DELETE.

Les options de ligne de commande suivantes contrôlent la connexion au serveur :

-h nom_hôte
--host=nom_hôte

Spécifie le nom d'hôte de la machine sur laquelle le serveur est en cours d'exécution. Si la valeur commence par une barre oblique, elle est utilisée comme répertoire pour le socket de domaine Unix.

-p port
--port=port

Spécifie le port TCP ou l'extension de fichier de socket de domaine Unix sur lequel le serveur écoute les connexions.

-U
--username=nom_utilisateur

Nom d'utilisateur pour se connecter.

-w
--no-password

Ne jamais demander de mot de passe. Si le serveur requiert une authentification par mot de passe et qu'un mot de passe n'est pas disponible par d'autres moyens tels qu'un fichier .pgpass, la tentative de connexion échouera. Cette option peut être utile dans les travaux par lots et les scripts où aucun utilisateur n'est présent pour saisir un mot de passe.

-W
--password

Force pg_amcheck à demander un mot de passe avant de se connecter à une base de données.

Cette option n'est jamais essentielle, car pg_amcheck demandera automatiquement un mot de passe si le serveur exige une authentification par mot de passe. Cependant, pg_amcheck perdra une tentative de connexion pour découvrir que le serveur veut un mot de passe. Dans certains cas, il vaut la peine de taper -W pour éviter la tentative de connexion supplémentaire.

--maintenance-db=nom_base

Spécifie une base de données ou une chaîne de connexion à utiliser pour découvrir la liste des bases de données à vérifier. Si ni --all ni aucune option incluant un modèle de base de données n'est utilisée, aucune connexion de ce type n'est requise et cette option ne fait rien. Sinon, tous les paramètres de chaîne de connexion autres que le nom de la base de données inclus dans la valeur de cette option seront également utilisés lors de la connexion aux bases de données vérifiées. Si cette option est omise, la valeur par défaut est postgres ou, si cela échoue, template1.

D'autres options sont également disponibles :

-e
--echo

Affiche sur stdout toutes les requêtes SQL envoyées au serveur.

-j num
--jobs=num

Utilise num connexions simultanées au serveur, ou une par objet à vérifier, selon le moindre.

Par défaut, une seule connexion est utilisée.

-P
--progress

Affiche les informations de progression. Les informations de progression incluent le nombre de relations pour lesquelles la vérification est terminée, et la taille totale de ces relations. Elles incluent également le nombre total de relations qui seront éventuellement vérifiées, et la taille estimée de ces relations.

-v
--verbose

Affiche plus de messages. En particulier, cela affichera un message pour chaque relation en cours de vérification, et augmentera le niveau de détail affiché pour les erreurs du serveur.

-V
--version

Affiche la version de pg_amcheck et quitte.

--install-missing
--install-missing=schéma

Installe toutes les extensions manquantes requises pour vérifier la ou les bases de données. Si elles ne sont pas encore installées, les objets de chaque extension seront installés dans le schéma donné, ou si non spécifié, dans le schéma pg_catalog.

Actuellement, la seule extension requise est amcheck.

-?
--help

Affiche l'aide sur les arguments de la ligne de commande de pg_amcheck et quitte.

ENVIRONNEMENT

pg_amcheck, comme la plupart des autres utilitaires PostgreSQL, utilise également les variables d'environnement prises en charge par libpq (voir la section 32.15).

La variable d'environnement PG_COLOR spécifie s'il faut utiliser la couleur dans les messages de diagnostic. Les valeurs possibles sont always, auto et never.

NOTES

pg_amcheck est conçu pour fonctionner avec PostgreSQL 14.0 et versions ultérieures.

VOIR AUSSI
