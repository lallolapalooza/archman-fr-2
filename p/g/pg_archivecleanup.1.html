NOM

pg_archivecleanup - nettoyer les fichiers d'archive WAL de PostgreSQL

SYNOPSIS

pg_archivecleanup [option...] emplacement_archive dernier_fichier_wal_conservé

DESCRIPTION

pg_archivecleanup est conçu pour être utilisé comme une archive_cleanup_command afin de nettoyer les archives de fichiers WAL lors de l'exécution en tant que serveur de secours (voir Section 26.2). pg_archivecleanup peut également être utilisé comme un programme autonome pour nettoyer les archives de fichiers WAL.

Pour configurer un serveur de secours afin qu'il utilise pg_archivecleanup, ajoutez ceci dans son fichier de configuration postgresql.conf :

archive_cleanup_command = 'pg_archivecleanup emplacement_archive %r'

où emplacement_archive est le répertoire à partir duquel les fichiers de segments WAL doivent être supprimés.

Lorsqu'il est utilisé dans archive_cleanup_command, tous les fichiers WAL logiquement précédents l'argument %r seront supprimés de emplacement_archive. Cela minimise le nombre de fichiers qui doivent être conservés, tout en préservant la capacité de redémarrage en cas de plantage. L'utilisation de ce paramètre est appropriée si emplacement_archive est une zone de transit transitoire pour ce serveur de secours particulier, mais *pas* lorsque emplacement_archive est destiné à être une zone d'archive WAL à long terme, ou lorsque plusieurs serveurs de secours récupèrent à partir du même emplacement d'archive.

Lorsqu'il est utilisé comme programme autonome, tous les fichiers WAL logiquement précédents le dernier_fichier_wal_conservé seront supprimés de emplacement_archive. Dans ce mode, si vous spécifiez un nom de fichier .partial ou .backup, seul le préfixe du fichier sera utilisé comme dernier_fichier_wal_conservé. Ce traitement du nom de fichier .backup vous permet de supprimer sans erreur tous les fichiers WAL archivés avant une sauvegarde de base spécifique. Par exemple, l'exemple suivant supprimera tous les fichiers plus anciens que le nom de fichier WAL 000000010000003700000010 :

pg_archivecleanup -d archive 000000010000003700000010.00000020.backup
pg_archivecleanup:  conserve le fichier WAL « archive/000000010000003700000010 » et les suivants
pg_archivecleanup:  suppression du fichier « archive/00000001000000370000000F »
pg_archivecleanup:  suppression du fichier « archive/00000001000000370000000E »

pg_archivecleanup suppose que emplacement_archive est un répertoire lisible et accessible en écriture par l'utilisateur propriétaire du serveur.

OPTIONS

pg_archivecleanup accepte les arguments de ligne de commande suivants :

-b
--clean-backup-history

Supprime également les fichiers d'historique de sauvegarde. Voir Section 25.3.2 pour plus de détails sur les fichiers d'historique de sauvegarde.

-d
--debug

Affiche de nombreuses informations de journalisation de débogage sur stderr.

-n
--dry-run

Affiche les noms des fichiers qui auraient été supprimés sur stdout (effectue une simulation).

-V
--version

Affiche la version de pg_archivecleanup et quitte.

-x extension
--strip-extension=extension

Fournit une extension qui sera supprimée de tous les noms de fichiers avant de décider s'ils doivent être supprimés. Ceci est généralement utile pour nettoyer les archives qui ont été compressées pendant le stockage, et ont donc eu une extension ajoutée par le programme de compression. Par exemple : -x .gz.

-?
--help

Affiche l'aide sur les arguments de ligne de commande de pg_archivecleanup et quitte.

ENVIRONNEMENT

La variable d'environnement PG_COLOR spécifie si les messages diagnostiques doivent être colorisés. Les valeurs possibles sont always, auto et never.

NOTES

pg_archivecleanup est conçu pour fonctionner avec PostgreSQL 8.0 et versions ultérieures lorsqu'il est utilisé comme utilitaire autonome, ou avec PostgreSQL 9.0 et versions ultérieures lorsqu'il est utilisé comme commande de nettoyage d'archive.

pg_archivecleanup est écrit en C et dispose d'un code source facile à modifier, avec des sections spécifiquement désignées à modifier selon vos besoins.

EXEMPLES

Sur les systèmes Linux ou Unix, vous pourriez utiliser :

archive_cleanup_command = 'pg_archivecleanup -d /mnt/standby/archive %r 2>>cleanup.log'

où le répertoire d'archive est physiquement situé sur le serveur de secours, de sorte que la archive_command y accède via NFS, mais les fichiers sont locaux au serveur de secours. Cela :

•produira une sortie de débogage dans cleanup.log
•supprimera les fichiers qui ne sont plus nécessaires du répertoire d'archive
