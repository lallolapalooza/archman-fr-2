NOM

pg_dumpall - extraire un cluster de bases de données PostgreSQL dans un fichier de script

SYNTAXE

pg_dumpall [option-connexion...] [option...]

DESCRIPTION

pg_dumpall est un utilitaire permettant d'écrire (d'extraire) toutes les bases de données PostgreSQL d'un cluster dans un fichier de script unique. Le fichier de script contient des commandes SQL qui peuvent être utilisées comme entrée pour psql(1) afin de restaurer les bases de données. Il y parvient en appelant pg_dump(1) pour chaque base de données du cluster. pg_dumpall extrait également les objets globaux communs à toutes les bases de données, à savoir les rôles de base de données, les tablespaces et les concessions de privilèges pour les paramètres de configuration. (pg_dump ne sauvegarde pas ces objets.)

Étant donné que pg_dumpall lit les tables de toutes les bases de données, vous devrez très probablement vous connecter en tant que superutilisateur de base de données afin de produire une extraction complète. De plus, vous aurez besoin des privilèges de superutilisateur pour exécuter le script sauvegardé afin d'être autorisé à ajouter des rôles et à créer des bases de données.

Le script SQL sera écrit sur la sortie standard. Utilisez l'option -f/--file ou les opérateurs shell pour le rediriger vers un fichier.

pg_dumpall doit se connecter plusieurs fois au serveur PostgreSQL (une fois par base de données). Si vous utilisez l'authentification par mot de passe, il demandera un mot de passe à chaque fois. Il est pratique d'avoir un fichier ~/.pgpass dans de tels cas. Voir la Section 32.16 pour plus d'informations.


Attention

La restauration d'une extraction entraîne l'exécution de code arbitraire choisi par les superutilisateurs sources sur la destination. Les extractions partielles et les restaurations partielles ne limitent pas cela. Si les superutilisateurs sources ne sont pas fiables, les instructions SQL extraites doivent être inspectées avant la restauration. Notez que le client exécutant l'extraction et la restauration n'a pas besoin de faire confiance aux superutilisateurs sources ou de destination.

OPTIONS

Les options de ligne de commande suivantes contrôlent le contenu et le format de la sortie.

-a
--data-only

Extrait uniquement les données, pas le schéma (définitions de données) ni les statistiques.

-c
--clean

Émet des commandes SQL pour DROP toutes les bases de données, rôles et tablespaces extraits avant de les recréer. Cette option est utile lorsque la restauration doit écraser un cluster existant. Si certains objets n'existent pas dans le cluster de destination, des messages d'erreur ignorables seront signalés pendant la restauration, sauf si --if-exists est également spécifié.

-E encodage
--encoding=encodage

Crée l'extraction dans le jeu de caractères d'encodage spécifié. Par défaut, l'extraction est créée dans l'encodage de la base de données. (Une autre façon d'obtenir le même résultat est de définir la variable d'environnement PGCLIENTENCODING sur l'encodage d'extraction souhaité.)

-f nomfichier
--file=nomfichier

Envoie la sortie vers le fichier spécifié. Si cette option est omise, la sortie standard est utilisée.

-g
--globals-only

Extrait uniquement les objets globaux (rôles et tablespaces), aucune base de données.

-O
--no-owner

Ne pas émettre de commandes pour définir la propriété des objets afin qu'elle corresponde à la base de données d'origine. Par défaut, pg_dumpall émet des instructions ALTER OWNER ou SET SESSION AUTHORIZATION pour définir la propriété des éléments de schéma créés. Ces instructions échoueront lors de l'exécution du script, sauf s'il est démarré par un superutilisateur (ou le même utilisateur qui possède tous les objets du script). Pour créer un script qui peut être restauré par n'importe quel utilisateur, mais qui lui donnera la propriété de tous les objets, spécifiez -O.

-r
--roles-only

Extrait uniquement les rôles, aucune base de données ou tablespace.

-s
--schema-only

Extrait uniquement les définitions d'objets (schéma), pas les données.

-S nomutilisateur
--superuser=nomutilisateur

Spécifie le nom d'utilisateur superutilisateur à utiliser lors de la désactivation des déclencheurs. Ceci n'est pertinent que si --disable-triggers est utilisé. (Généralement, il est préférable de laisser cela de côté et de démarrer plutôt le script résultant en tant que superutilisateur.)

-t
--tablespaces-only

Extrait uniquement les tablespaces, aucune base de données ou rôle.

-v
--verbose

Spécifie le mode verbeux. Cela amènera pg_dumpall à afficher les heures de début/fin dans le fichier d'extraction et les messages de progression sur l'erreur standard. Répéter l'option entraîne l'apparition de messages supplémentaires de niveau débogage sur l'erreur standard. L'option est également transmise à pg_dump.

-V
--version

Affiche la version de pg_dumpall et quitte.

-x
--no-privileges
--no-acl

Empêche l'extraction des privilèges d'accès (commandes grant/revoke).

--binary-upgrade

Cette option est destinée à être utilisée par les utilitaires de mise à niveau sur place. Son utilisation à d'autres fins n'est pas recommandée ni prise en charge. Le comportement de l'option peut changer dans les futures versions sans préavis.

--column-inserts
--attribute-inserts

Extrait les données sous forme de commandes INSERT avec des noms de colonnes explicites (INSERT INTO table (colonne, ...) VALUES ...). Cela rendra la restauration très lente ; elle est principalement utile pour créer des extractions qui peuvent être chargées dans des bases de données non-PostgreSQL.

--disable-dollar-quoting

Cette option désactive l'utilisation de l'imbrication de dollars pour les corps de fonction et force leur citation à l'aide de la syntaxe de chaîne standard SQL.

--disable-triggers

Cette option n'est pertinente que lors de la création d'une extraction avec des données et sans schéma. Elle demande à pg_dumpall d'inclure des commandes pour désactiver temporairement les déclencheurs sur les tables cibles pendant la restauration des données. Utilisez-la si vous avez des vérifications d'intégrité référentielle ou d'autres déclencheurs sur les tables que vous ne souhaitez pas activer pendant la restauration des données.

Actuellement, les commandes émises pour --disable-triggers doivent être exécutées en tant que superutilisateur. Par conséquent, vous devriez également spécifier un nom d'utilisateur superutilisateur avec -S, ou de préférence faire attention à démarrer le script résultant en tant que superutilisateur.

--exclude-database=modèle

N'extrait pas les bases de données dont le nom correspond au modèle. Plusieurs modèles peuvent être exclus en écrivant plusieurs commutateurs --exclude-database. Le paramètre modèle est interprété comme un modèle selon les mêmes règles utilisées par les commandes \d de psql (voir Modèles), donc plusieurs bases de données peuvent également être exclues en écrivant des caractères génériques dans le modèle. Lors de l'utilisation de caractères génériques, faites attention à citer le modèle si nécessaire pour empêcher l'expansion des caractères génériques du shell.

--extra-float-digits=ndigits

Utilise la valeur spécifiée de extra_float_digits lors de l'extraction des données à virgule flottante, au lieu de la précision maximale disponible. Les extractions de routine effectuées à des fins de sauvegarde ne doivent pas utiliser cette option.

--filter=nomfichier

Spécifie un nom de fichier à partir duquel lire les modèles pour les bases de données exclues de l'extraction. Les modèles sont interprétés selon les mêmes règles que --exclude-database. Pour lire depuis STDIN, utilisez - comme nom de fichier. L'option --filter peut être spécifiée conjointement avec --exclude-database pour exclure des bases de données, et peut également être spécifiée plus d'une fois pour plusieurs fichiers de filtre.

Le fichier liste un modèle de base de données par ligne, avec le format suivant :

exclude database MODÈLE

Les lignes commençant par # sont considérées comme des commentaires et ignorées. Les commentaires peuvent également être placés après une ligne de modèle d'objet. Les lignes vides sont également ignorées. Voir Modèles pour savoir comment effectuer l'imbrication dans les modèles.

--if-exists

Utilise des commandes DROP ... IF EXISTS pour supprimer les objets en mode --clean. Cela supprime les erreurs « n'existe pas » qui pourraient autrement être signalées. Cette option n'est pas valide si --clean n'est pas également spécifié.

--inserts

Extrait les données sous forme de commandes INSERT (plutôt que COPY). Cela rendra la restauration très lente ; elle est principalement utile pour créer des extractions qui peuvent be loaded into non-PostgreSQL databases. Note that the restore might fail altogether if you have rearranged column order. The --column-inserts option is safer, though even slower.

--load-via-partition-root

When dumping data for a table partition, make the COPY or INSERT statements target the root of the partitioning hierarchy that contains it, rather than the partition itself. This causes the appropriate partition to be re-determined for each row when the data is loaded. This may be useful when restoring data on a server where rows do not always fall into the same partitions as they did on the original server. That could happen, for example, if the partitioning column is of type text and the two systems have different definitions of the collation used to sort the partitioning column.

--lock-wait-timeout=timeout

Do not wait forever to acquire shared table locks at the beginning of the dump. Instead, fail if unable to lock a table within the specified timeout. The timeout may be specified in any of the formats accepted by SET statement_timeout.

--no-comments

Do not dump COMMENT commands.

--no-data

Do not dump data.

--no-policies

Do not dump row security policies.

--no-publications

Do not dump publications.

--no-role-passwords

Do not dump passwords for roles. When restored, roles will have a null password, and password authentication will always fail until the password is set. Since password values aren't needed when this option is specified, the role information is read from the catalog view pg_roles instead of pg_authid. Therefore, this option also helps if access to pg_authid is restricted by some security policy.

--no-schema

Do not dump schema (data definitions).

--no-security-labels

Do not dump security labels.

--no-statistics

Do not dump statistics. This is the default.

--no-subscriptions

Do not dump subscriptions.

--no-sync

By default, pg_dumpall will wait for all files to be written safely to disk. This option causes pg_dumpall to return without waiting, which is faster, but means that a subsequent operating system crash can leave the dump corrupt. Generally, this option is useful for testing but should not be used when dumping data from production installation.

--no-table-access-method

Do not output commands to select table access methods. With this option, all objects will be created with whichever table access method is the default during restore.

--no-tablespaces

Do not output commands to create tablespaces nor select tablespaces for objects. With this option, all objects will be created in whichever tablespace is the default during restore.

--no-toast-compression

Do not output commands to set TOAST compression methods. With this option, all columns will be restored with the default compression setting.

--no-unlogged-table-data

Do not dump the contents of unlogged tables. This option has no effect on whether or not the table definitions (schema) are dumped; it only suppresses dumping the table data.

--on-conflict-do-nothing

Add ON CONFLICT DO NOTHING to INSERT commands. This option is not valid unless --inserts or --column-inserts is also specified.

--quote-all-identifiers

Force quoting of all identifiers. This option is recommended when dumping a database from a server whose PostgreSQL major version is different from pg_dumpall's, or when the output is intended to be loaded into a server of a different major version. By default, pg_dumpall quotes only identifiers that are reserved words in its own major version. This sometimes results in compatibility issues when dealing with servers of other versions that may have slightly different sets of reserved words. Using --quote-all-identifiers prevents such issues, at the price of a harder-to-read dump script.

--restrict-key=restrict_key

Use the provided string as the psql \restrict key in the dump output. If no restrict key is specified, pg_dumpall will generate a random one as needed. Keys may contain only alphanumeric characters.

This option is primarily intended for testing purposes and other scenarios that require repeatable output (e.g., comparing dump files). It is not recommended for general use, as a malicious server with advance knowledge of the key may be able to inject arbitrary code that will be executed on the machine that runs psql with the dump output.

--rows-per-insert=nrows

Dump data as INSERT commands (rather than COPY). Controls the maximum number of rows per INSERT command. The value specified must be a number greater than zero. Any error during restoring will cause only rows that are part of the problematic INSERT to be lost, rather than the entire table contents.

--statistics

Dump statistics.

--statistics-only

Dump only the statistics, not the schema (data definitions) or data. Statistics for tables, materialized views, foreign tables, and indexes are dumped.

--sequence-data

Include sequence data in the dump. This is the default behavior except when --no-data, --schema-only, or --statistics-only is specified.

--use-set-session-authorization

Output SQL-standard SET SESSION AUTHORIZATION commands instead of ALTER OWNER commands to determine object ownership. This makes the dump more standards compatible, but depending on the history of the objects in the dump, might not restore properly.

-?
--help

Show help about pg_dumpall command line arguments, and exit.

The following command-line options control the database connection parameters.

-d connstr
--dbname=connstr

Specifies parameters used to connect to the server, as a connection string; these will override any conflicting command line options.

The option is called --dbname for consistency with other client applications, but because pg_dumpall needs to connect to many databases, the database name in the connection string will be ignored. Use the -l option to specify the name of the database used for the initial connection, which will dump global objects and discover what other databases should be dumped.

-h host
--host=host

Specifies the host name of the machine on which the database server is running. If the value begins with a slash, it is used as the directory for the Unix domain socket. The default is taken from the PGHOST environment variable, if set, else a Unix domain socket connection is attempted.

-l dbname
--database=dbname

Specifies the name of the database to connect to for dumping global objects and discovering what other databases should be dumped. If not specified, the postgres database will be used, and if that does not exist, template1 will be used.

-p port
--port=port

Specifies the TCP port or local Unix domain socket file extension on which the server is listening for connections. Defaults to the PGPORT environment variable, if set, or a compiled-in default.

-U username
--username=username

User name to connect as.

-w
--no-password

Never issue a password prompt. If the server requires password authentication and a password is not available by other means such as a .pgpass file, the connection attempt will fail. This option can be useful in batch jobs and scripts where no user is present to enter a password.

-W
--password

Force pg_dumpall to prompt for a password before connecting to a database.

This option is never essential, since pg_dumpall will automatically prompt for a password if the server demands password authentication. However, pg_dumpall will waste a connection attempt finding out that the server wants a password. In some cases it is worth typing -W to avoid the extra connection attempt.

Note that the password prompt will occur again for each database to be dumped. Usually, it's better to set up a ~/.pgpass file than to rely on manual password entry.

--role=rolename

Specifies a role name to be used to create the dump. This option causes pg_dumpall to issue a SET ROLE rolename command after connecting to the database. It is useful when the authenticated user (specified by -U) lacks privileges needed by pg_dumpall, but can switch to a role with the required rights. Some installations have a policy against logging in directly as a superuser, and use of this option allows dumps to be made without violating the policy.

PG_COLOR

NAME

pg_dumpall

dump all PostgreSQL databases and maintenance routines

SYNOPSIS

pg_dumpall

[OPTION...]

DESCRIPTION

pg_dumpall est un utilitaire pour dump toutes les bases de données d'un cluster PostgreSQL, ainsi que les informations sur les rôles et les tablespaces. Il génère un fichier script qui peut être réutilisé pour recréer les bases de données dans un autre cluster PostgreSQL.

Le script généré par pg_dumpall contient les commandes nécessaires pour recréer tous les rôles et tablespaces existants dans le cluster source, puis pour dump chaque base de données individuellement. Ensuite, il restaure les données et les objets dans ces bases de données. Le script créé peut être exécuté en utilisant psql.

Comme pg_dumpall exécute pg_dump pour chaque base de données, il hérite de la plupart des options de pg_dump. Pour plus de détails sur les options spécifiques au dump d'une base de données, consultez la page de manuel de pg_dump.

OPTIONS

Pour une liste complète des options, consultez la documentation de pg_dumpall.

Les options principales incluent :

--clean
Inclut des commandes SQL pour supprimer les bases de données et autres objets avant de tenter de les recréer. Utile pour s'assurer que le script peut être réexécuté sans erreur sur un système où certains objets pourraient déjà exister.
--if-exists
Lors de l'utilisation de --clean, ajoutez une vérification pour s'assurer qu'un objet existe avant de tenter de le supprimer. Cela évite les messages d'erreur lorsque l'objet n'est pas trouvé.
--globals-only
Ne dump que les objets globaux (rôles et tablespaces), pas les bases de données elles-mêmes.
--tablespaces-only
Ne dump que la définition des tablespaces.
--roles-only
Ne dump que les rôles.
--schema-only
Ne dump que la structure des objets (schémas), pas les données.
--data-only
Ne dump que les données, pas la structure des objets.
--exclude-database=dbname
Exclut la base de données spécifiée du dump. Peut être spécifié plusieurs fois.
--database=dbname
Ne dump que la base de données spécifiée. Par défaut, toutes les bases de données sont incluses.
--output=filename
Spécifie le fichier de sortie où écrire le script SQL. Si non spécifié, la sortie standard est utilisée.
-f filename
--file=filename
Identique à --output.
-v
--verbose
Active le mode verbeux. pg_dumpall affichera des messages détaillés sur les opérations en cours.
-V
--version
Affiche la version de pg_dumpall et quitte.
-?
--help
Affiche l'aide sur les arguments de la ligne de commande et quitte.

Options de connexion :

-d dbname
--dbname=dbname
Spécifie la base de données à laquelle se connecter pour le dump. La valeur par défaut est souvent `postgres`. Cette option est moins importante pour pg_dumpall que pour pg_dump car il se connecte à plusieurs bases de données.
-h host
--host=host
Spécifie le nom d'hôte du serveur sur lequel le cluster PostgreSQL est en cours d'exécution.
-p port
--port=port
Spécifie le port TCP ou le fichier de socket de domaine Unix sur lequel le serveur est en écoute.
-U username
--username=username
Spécifie le nom d'utilisateur pour se connecter.
-w
--no-password
Ne demande jamais un mot de passe.
-W
--password
Force pg_dumpall à demander un mot de passe avant de se connecter.
--role=rolename
Spécifie un rôle à utiliser pour exécuter la commande. Cela peut être utile pour exécuter le dump avec des privilèges différents de ceux de l'utilisateur connecté.

Options de sortie :

-X
--no-psqlrc
N'exécute pas le fichier de configuration personnel de psql (~/.psqlrc) lors de l'exécution du script de restauration. Ceci est recommandé pour éviter des comportements imprévus.
--no-comments
Ne pas inclure les commentaires dans le script de dump.
--no-publications
Ne pas inclure les publications dans le script de dump.
--no-subscriptions
Ne pas inclure les abonnements dans le script de dump.
--no-security-labels
Ne pas inclure les étiquettes de sécurité dans le script de dump.
--no-tablespaces
Ne pas inclure les tablespaces dans le script de dump.
--no-unlogged-table-data
Ne pas inclure les données des tables non enregistrées (unlogged tables).

Options pour les statistiques :

--statistics
Inclut la plupart des statistiques de l'optimiseur dans le fichier de dump résultant.

ENVIRONMENT

pg_dumpall utilise les variables d'environnement standard pour la connexion et le comportement, telles que PGHOST, PGPORT, PGUSER, PGDATABASE, et PGPASSWORD.

NOTES

Si l'option --statistics est spécifiée, pg_dumpall inclura la plupart des statistiques de l'optimiseur dans le fichier de dump résultant. Cependant, certaines statistiques peuvent ne pas être incluses, comme celles créées explicitement avec CREATE STATISTICS (voir CREATE_STATISTICS(7)) ou les statistiques personnalisées ajoutées par une extension. Par conséquent, il peut être utile d'exécuter ANALYZE sur chaque base de données après la restauration à partir d'un fichier de dump afin d'assurer des performances optimales. Vous pouvez également exécuter vacuumdb -a -z pour analyser toutes les bases de données.

Le script de dump ne doit pas nécessairement s'exécuter entièrement sans erreurs. En particulier, parce que le script émettra CREATE ROLE pour chaque rôle existant dans le cluster source, il est certain qu'il y aura une erreur “role already exists” pour le superutilisateur d'amorçage, à moins que le cluster de destination n'ait été initialisé avec un nom de superutilisateur différent. Cette erreur est inoffensive et doit être ignorée. L'utilisation de l'option --clean est susceptible de produire des messages d'erreur supplémentaires inoffensifs concernant des objets inexistants, bien que vous puissiez les minimiser en ajoutant --if-exists.

pg_dumpall nécessite que tous les répertoires de tablespaces nécessaires existent avant la restauration ; sinon, la création de bases de données échouera pour les bases de données situées dans des emplacements non par défaut.

Il est généralement recommandé d'utiliser l'option -X (--no-psqlrc) lors de la restauration d'une base de données à partir d'un script pg_dumpall pour assurer un processus de restauration propre et éviter les conflits potentiels avec des configurations psql non par défaut. De plus, comme le script pg_dumpall peut inclure des méta-commandes psql, il peut être incompatible avec des clients autres que psql.

EXAMPLES

Pour dump toutes les bases de données :

$ pg_dumpall > db.out

Pour restaurer la ou les bases de données à partir de ce fichier, vous pouvez utiliser :

$ psql -X -f db.out -d postgres

Il n'est pas important de savoir à quelle base de données vous vous connectez ici, car le fichier script créé par pg_dumpall contiendra les commandes appropriées pour créer et se connecter aux bases de données sauvegardées. Une exception est que si vous avez spécifié --clean, vous devez vous connecter initialement à la base de données postgres ; le script tentera de supprimer immédiatement les autres bases de données, ce qui échouera pour la base de données à laquelle vous êtes connecté.

Consultez pg_dump(1) pour plus de détails sur les conditions d'erreur possibles.
