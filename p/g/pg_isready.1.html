NOM

pg_isready - vérifier l'état de connexion d'un serveur PostgreSQL

SYNTAXE

pg_isready [option-connexion...] [option...]

DESCRIPTION

pg_isready est un utilitaire pour vérifier l'état de connexion d'un serveur de base de données PostgreSQL. Le code de sortie spécifie le résultat de la vérification de la connexion.

OPTIONS

-d dbname
--dbname=dbname

Spécifie le nom de la base de données à laquelle se connecter. Le dbname peut être une chaîne de connexion. Si c'est le cas, les paramètres de la chaîne de connexion remplaceront toute option de ligne de commande conflictuelle.

-h hostname
--host=hostname

Spécifie le nom d'hôte de la machine sur laquelle le serveur s'exécute. Si la valeur commence par un slash, elle est utilisée comme répertoire pour le socket Unix.

-p port
--port=port

Spécifie le port TCP ou l'extension de fichier de socket Unix local sur lequel le serveur écoute les connexions. Par défaut, utilise la valeur de la variable d'environnement PGPORT ou, si elle n'est pas définie, le port spécifié lors de la compilation, généralement 5432.

-q
--quiet

Ne pas afficher de message d'état. Ceci est utile lors de l'écriture de scripts.

-t secondes
--timeout=secondes

Le nombre maximum de secondes à attendre lors de la tentative de connexion avant de signaler que le serveur ne répond pas. Définir à 0 désactive. Par défaut, c'est 3 secondes.

-U username
--username=username

Se connecter à la base de données en tant qu'utilisateur username au lieu de l'utilisateur par défaut.

-V
--version

Afficher la version de pg_isready et quitter.

-?
--help

Afficher l'aide sur les arguments de la ligne de commande de pg_isready et quitter.

CODE DE SORTIE

pg_isready retourne 0 au shell si le serveur accepte les connexions normalement, 1 si le serveur rejette les connexions (par exemple, pendant le démarrage), 2 s'il n'y a eu aucune réponse à la tentative de connexion, et 3 si aucune tentative n'a été faite (par exemple, en raison de paramètres invalides).

ENVIRONNEMENT

pg_isready, comme la plupart des autres utilitaires PostgreSQL, utilise également les variables d'environnement prises en charge par libpq (voir la Section 32.15).

La variable d'environnement PG_COLOR spécifie si la couleur doit être utilisée dans les messages de diagnostic. Les valeurs possibles sont always, auto et never.

NOTES

Il n'est pas nécessaire de fournir des valeurs correctes pour le nom d'utilisateur, le mot de passe ou le nom de la base de données pour obtenir l'état du serveur ; cependant, si des valeurs incorrectes sont fournies, le serveur enregistrera une tentative de connexion échouée.

EXEMPLES

Utilisation standard :

$ pg_isready
/tmp:5432 - accepting connections
$ echo $?
0

Exécution avec des paramètres de connexion à un cluster PostgreSQL en cours de démarrage :

$ pg_isready -h localhost -p 5433
localhost:5433 - rejecting connections
$ echo $?
1

Exécution avec des paramètres de connexion à un cluster PostgreSQL qui ne répond pas :

$ pg_isready -h someremotehost
someremotehost:5432 - no response
$ echo $?
2
