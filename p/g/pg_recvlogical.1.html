NOM

pg_recvlogical - contrôle les flux de décodage logique PostgreSQL

SYNOPIS

pg_recvlogical [option...]

DESCRIPTION

pg_recvlogical contrôle les slots de réplication de décodage logique et diffuse les données à partir de tels slots de réplication.

Il crée une connexion en mode réplication, il est donc soumis aux mêmes contraintes que pg_receivewal(1), ainsi qu'à celles de la réplication logique (voir Chapitre 47).

pg_recvlogical n'a pas d'équivalent aux modes 'peek' et 'get' de l'interface SQL de décodage logique. Il envoie des confirmations de rejeu des données de manière différée au fur et à mesure qu'il les reçoit et lors d'une sortie propre. Pour examiner les données en attente sur un slot sans les consommer, utilisez pg_logical_slot_peek_changes.

En l'absence d'erreurs fatales, pg_recvlogical s'exécutera jusqu'à ce qu'il soit terminé par le signal SIGINT (Contrôle+C) ou SIGTERM.

Lorsque pg_recvlogical reçoit un signal SIGHUP, il ferme le fichier de sortie actuel et en ouvre un nouveau en utilisant le nom de fichier spécifié par l'option --file. Cela nous permet de faire pivoter le fichier de sortie en renommant d'abord le fichier actuel, puis en envoyant un signal SIGHUP à pg_recvlogical.

OPTIONS

Au moins une des options suivantes doit être spécifiée pour sélectionner une action :

--create-slot

Crée un nouveau slot de réplication logique avec le nom spécifié par --slot, en utilisant le plugin de sortie spécifié par --plugin, pour la base de données spécifiée par --dbname.

Les options --slot et --dbname sont requises pour cette action.

Les options --enable-two-phase et --enable-failover peuvent être spécifiées avec --create-slot.

--drop-slot

Supprime le slot de réplication avec le nom spécifié par --slot, puis quitte.

L'option --slot est requise pour cette action.

--start

Commence à diffuser les changements du slot de réplication logique spécifié par --slot, en continuant jusqu'à ce qu'il soit terminé par un signal. Si le flux de changements côté serveur se termine par un arrêt ou une déconnexion du serveur, retente en boucle à moins que --no-loop ne soit spécifié.

Les options --slot, --dbname et --file sont requises pour cette action.

Le format du flux est déterminé par le plugin de sortie spécifié lors de la création du slot.

La connexion doit être établie à la même base de données qui a été utilisée pour créer le slot.

--create-slot et --start peuvent être spécifiés ensemble. --drop-slot ne peut pas être combiné avec une autre action.

Les options de ligne de commande suivantes contrôlent l'emplacement et le format de la sortie ainsi que d'autres comportements de réplication :

-E lsn
--endpos=lsn

En mode --start, arrête automatiquement la réplication et quitte avec un code de sortie normal 0 lorsque la réception atteint le LSN spécifié. Si spécifié en dehors du mode --start, une erreur est générée.

S'il existe un enregistrement avec un LSN exactement égal à lsn, l'enregistrement sera sorti.

L'option --endpos n'est pas consciente des limites de transaction et peut tronquer la sortie au milieu d'une transaction. Toute transaction partiellement sortie ne sera pas consommée et sera rejouée lors de la prochaine lecture du slot. Les messages individuels ne sont jamais tronqués.

--enable-failover

Permet de synchroniser le slot avec les serveurs standby. Cette option ne peut être spécifiée qu'avec --create-slot.

-f nom_fichier
--file=nom_fichier

Écrit les données de transaction reçues et décodées dans ce fichier. Utilisez - pour stdout.

Ce paramètre est requis pour --start.

-F intervalle_secondes
--fsync-interval=intervalle_secondes

Spécifie à quelle fréquence pg_recvlogical doit émettre des appels fsync() pour s'assurer que le fichier de sortie est correctement vidé sur disque.

Le serveur demandera occasionnellement au client d'effectuer un vidage et de signaler la position du vidage au serveur. Ce réglage s'ajoute à cela, pour effectuer des vidages plus fréquemment.

Spécifier un intervalle de 0 désactive complètement l'émission d'appels fsync(), tout en signalant la progression au serveur. Dans ce cas, des données pourraient être perdues en cas de crash.

-I lsn
--startpos=lsn

En mode --start, commence la réplication à partir du LSN donné. Pour plus de détails sur l'effet de ceci, voir la documentation au Chapitre 47 et la Section 54.4. Ignoré dans les autres modes.

--if-not-exists

Ne génère pas d'erreur lorsque --create-slot est spécifié et qu'un slot avec le nom spécifié existe déjà.

-n
--no-loop

Lorsque la connexion au serveur est perdue, ne retente pas en boucle, quitte simplement.

-o nom[=valeur]
--option=nom[=valeur]

Passe l'option nom au plugin de sortie avec, si elle est spécifiée, la valeur d'option valeur. Les options existantes et leurs effets dépendent du plugin de sortie utilisé.

-P plugin
--plugin=plugin

Lors de la création d'un slot, utilise le plugin de sortie de décodage logique spécifié. Voir Chapitre 47. Cette option n'a aucun effet si le slot existe déjà.

-s intervalle_secondes
--status-interval=intervalle_secondes

Cette option a le même effet que l'option du même nom dans pg_receivewal(1). Voir la description là-bas.

-S nom_slot
--slot=nom_slot

En mode --start, utilise le slot de réplication logique existant nommé nom_slot. En mode --create-slot, crée le slot avec ce nom. En mode --drop-slot, supprime le slot avec ce nom.

Ce paramètre est requis pour toutes les actions.

-t
--enable-two-phase
--two-phase (obsolète)

Active le décodage des transactions préparées. Cette option ne peut être spécifiée qu'avec --create-slot.

-v
--verbose

Active le mode verbeux.

Les options de ligne de commande suivantes contrôlent les paramètres de connexion à la base de données.

-d nom_base
--dbname=nom_base

La base de données à laquelle se connecter. Voir la description des actions pour ce que cela signifie en détail. Le nom_base peut être une chaîne de connexion. Si c'est le cas, les paramètres de la chaîne de connexion remplaceront toute option de ligne de commande conflictuelle.

Ce paramètre est requis pour --create-slot et --start.

-h nom_hôte_ou_ip
--host=nom_hôte_ou_ip

Spécifie le nom d'hôte de la machine sur laquelle le serveur s'exécute. Si la valeur commence par une barre oblique, elle est utilisée comme répertoire pour le socket Unix. La valeur par défaut est prise de la variable d'environnement PGHOST, si elle est définie, sinon une connexion par socket Unix est tentée.

-p port
--port=port

Spécifie le port TCP ou l'extension de fichier de socket Unix local sur lequel le serveur écoute les connexions. Par défaut, utilise la variable d'environnement PGPORT, si elle est définie, ou une valeur par défaut intégrée.

-U utilisateur
--username=utilisateur

Nom d'utilisateur pour se connecter. Par défaut, l'utilisateur du système d'exploitation actuel.

-w
--no-password

Ne jamais demander de mot de passe. Si le serveur requiert une authentification par mot de passe et qu'un mot de passe n'est pas disponible par d'autres moyens, comme un fichier .pgpass, la tentative de connexion échouera. Cette option peut être utile dans les tâches batch et les scripts où aucun utilisateur n'est présent pour entrer un mot de passe.

-W
--password

Force pg_recvlogical à demander un mot de passe avant de se connecter à une base de données.

Cette option n'est jamais essentielle, car pg_recvlogical demandera automatiquement un mot de passe

NAME

pg_recvlogical

receive PostgreSQL Write-Ahead Log stream

SYNOPSIS

pg_recvlogical [option...]

DESCRIPTION

pg_recvlogical is a utility to stream the PostgreSQL Write-Ahead Log (WAL) using the streaming replication protocol. It allows to receive WAL records from a primary server and store them locally, typically to be used by logical decoding or for point-in-time recovery (PITR).

This utility is primarily intended to be used by applications that require access to the WAL stream for logical decoding, such as logical replication clients or change data capture (CDC) tools.

pg_recvlogical connects to a PostgreSQL server using the streaming replication protocol. It requires the server to be configured to accept replication connections and to have logical decoding enabled. The server must also have at least one logical replication slot created.

The received WAL data is written to files in the directory specified by the --directory option. The files are named according to the WAL segment naming convention.

pg_recvlogical supports the following connection parameters:

  • --host=hostname
  • --port=port
  • --username=username
  • --no-password
  • --password
  • --passfile=filename
  • --channel-interval=seconds
  • --channel-name=name
  • --connection-timeout=seconds
  • --replication=user
  • --synchronous-commit=on | remote_apply | remote_write | local | off
  • --synchronous-name=name

The utility also accepts the following command-line options:

-D directory
--directory=directory
Specifies the directory where the received WAL files will be stored. This directory must exist and be writable by the user running pg_recvlogical. This option is mandatory.
-p filename
--path=filename
Specifies the path to the WAL receiver process output file. This file contains information about the received WAL data, such as the current WAL location. If this option is not specified, the output will be written to stdout. This option is useful for debugging and monitoring purposes.
-S slotname
--slot=slotname
Specifies the name of the logical replication slot to use on the server. This slot must exist on the server and be configured for logical decoding. This option is mandatory.
-w
--no-password
Never prompt for a password. If the server requires password authentication, the command fails. This may be useful in scripts and batch jobs where the password is not available.
-W
--password
Force pg_recvlogical to prompt for a password before connecting to a database. This can be useful when the server has password authentication enabled but the connection string in the environment does not contain a password. If the server demands password authentication, pg_recvlogical will waste a connection attempt finding out that the server wants a password. In some cases it is worth typing -W to avoid the extra connection attempt.

The following additional options are available:

-V
--version

Print the pg_recvlogical version and exit.

-?
--help

Show help about pg_recvlogical command line arguments, and exit.

EXIT STATUS

pg_recvlogical will exit with status 0 when terminated by the SIGINT or SIGTERM signal. (That is the normal way to end it. Hence it is not an error.) For fatal errors or other signals, the exit status will be nonzero.

ENVIRONMENT

This utility, like most other PostgreSQL utilities, uses the environment variables supported by libpq (see Section 32.15).

The environment variable PG_COLOR specifies whether to use color in diagnostic messages. Possible values are always, auto and never.

NOTES

pg_recvlogical will preserve group permissions on the received WAL files if group permissions are enabled on the source cluster.

EXAMPLES

See Section 47.1 for an example.

Cet utilitaire est principalement destiné à être utilisé par des applications qui nécessitent un accès au flux WAL pour le décodage logique, telles que les clients de réplication logique ou les outils de capture de données modifiées (CDC).

Il nécessite que le serveur soit configuré pour accepter les connexions de réplication et que le décodage logique soit activé. Les données WAL reçues sont écrites dans des fichiers dans le répertoire spécifié par l'option --directory. Les fichiers sont nommés conformément à la convention de nommage des segments WAL.
