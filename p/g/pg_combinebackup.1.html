PG_COMBINEBACKUP(1) Documentation PostgreSQL 18.1 PG_COMBINEBACKUP(1)

NOM

pg_combinebackup - reconstruire une sauvegarde complète à partir d'une sauvegarde incrémentielle et des sauvegardes dépendantes

SYNTAXE

pg_combinebackup [option...] [répertoire_sauvegarde...]

DESCRIPTION

pg_combinebackup est utilisé pour reconstruire une sauvegarde complète synthétique à partir d'une sauvegarde incrémentielle et des sauvegardes antérieures dont elle dépend.

Spécifiez toutes les sauvegardes requises sur la ligne de commande, de la plus ancienne à la plus récente. Autrement dit, le premier répertoire de sauvegarde doit être le chemin d'accès à la sauvegarde complète, et le dernier doit être le chemin d'accès à la sauvegarde incrémentielle finale que vous souhaitez restaurer. La sauvegarde reconstruite sera écrite dans le répertoire de sortie spécifié par l'option -o.

pg_combinebackup tentera de vérifier que les sauvegardes que vous spécifiez forment une chaîne de sauvegarde légale à partir de laquelle une sauvegarde complète correcte peut être reconstruite. Cependant, il n'est pas conçu pour vous aider à garder une trace des sauvegardes qui dépendent d'autres sauvegardes. Si vous supprimez une ou plusieurs des sauvegardes précédentes dont dépend votre sauvegarde incrémentielle, vous ne pourrez pas la restaurer. De plus, pg_combinebackup tente seulement de vérifier que les sauvegardes ont la relation correcte les unes avec les autres, pas que chaque sauvegarde individuelle est intacte ; pour cela, utilisez pg_verifybackup(1).

Comme la sortie de pg_combinebackup est une sauvegarde complète synthétique, elle peut être utilisée comme entrée pour une invocation future de pg_combinebackup. La sauvegarde complète synthétique serait spécifiée sur la ligne de commande au lieu de la chaîne de sauvegardes à partir desquelles elle a été reconstruite.

OPTIONS

-d
--debug

Affiche beaucoup de logs de débogage sur stderr.

-k
--link

Utilise des liens physiques au lieu de copier des fichiers vers la sauvegarde synthétique. La reconstruction de la sauvegarde synthétique pourrait être plus rapide (pas de copie de fichiers) et utiliser moins d'espace disque, mais il faut faire attention lors de l'utilisation du répertoire de sortie, car toute modification de ce répertoire (par exemple, le démarrage du serveur) peut également affecter les répertoires d'entrée. De même, les modifications apportées aux répertoires d'entrée (par exemple, le démarrage du serveur sur la sauvegarde complète) pourraient affecter le répertoire de sortie. Ainsi, cette option est mieux utilisée lorsque les répertoires d'entrée ne sont que des copies qui seront supprimées une fois que pg_combinebackup aura terminé.

Nécessite que les sauvegardes d'entrée et le répertoire de sortie se trouvent sur le même système de fichiers.

Si un manifeste de sauvegarde n'est pas disponible ou ne contient pas de somme de contrôle du bon type, des liens physiques seront quand même créés, mais le fichier sera également lu bloc par bloc pour le calcul de la somme de contrôle.

-n
--dry-run

L'option -n/--dry-run demande à pg_combinebackup de déterminer ce qui serait fait sans réellement créer le répertoire cible ni aucun fichier de sortie. Elle est particulièrement utile en combinaison avec --debug.

-N
--no-sync

Par défaut, pg_combinebackup attend que tous les fichiers soient écrits en toute sécurité sur le disque. Cette option fait que pg_combinebackup retourne sans attendre, ce qui est plus rapide, mais signifie qu'un crash ultérieur du système d'exploitation peut laisser la sauvegarde de sortie corrompue. Généralement, cette option est utile pour les tests mais ne doit pas être utilisée lors de la création d'une installation de production.

-o rep_sortie
--output=rep_sortie

Spécifie le répertoire de sortie dans lequel la sauvegarde complète synthétique doit être écrite. Actuellement, cet argument est requis.

-T rep_ancien=rep_nouveau
--tablespace-mapping=rep_ancien=rep_nouveau

Relocalise l'espace de tables dans le répertoire rep_ancien vers rep_nouveau pendant la sauvegarde. rep_ancien est le chemin absolu de l'espace de tables tel qu'il existe dans la dernière sauvegarde spécifiée sur la ligne de commande, et rep_nouveau est le chemin absolu à utiliser pour l'espace de tables dans la sauvegarde reconstruite. Si l'un des chemins doit contenir un signe égal (=), précédez-le d'une barre oblique inverse. Cette option peut être spécifiée plusieurs fois pour plusieurs espaces de tables.

--clone

Utilise le clonage de fichiers efficace (également connu sous le nom de « reflinks » sur certains systèmes) au lieu de copier les fichiers dans le nouveau répertoire de données, ce qui peut entraîner une copie quasi instantanée des fichiers de données.

Si un manifeste de sauvegarde n'est pas disponible ou ne contient pas de somme de contrôle du bon type, le clonage de fichiers sera utilisé pour copier le fichier, mais le fichier sera également lu bloc par bloc pour le calcul de la somme de contrôle.

Le clonage de fichiers n'est pris en charge que sur certains systèmes d'exploitation et systèmes de fichiers. S'il est sélectionné mais non pris en charge, l'exécution de pg_combinebackup échouera. Actuellement, il est pris en charge sous Linux (noyau 4.5 ou ultérieur) avec Btrfs et XFS (sur les systèmes de fichiers créés avec prise en charge de reflink), et sous macOS avec APFS.

--copy

Effectue une copie de fichier régulière. C'est le comportement par défaut. (Voir aussi --copy-file-range, --clone, et -k/--link.)

--copy-file-range

Utilise l'appel système copy_file_range pour une copie efficace. Sur certains systèmes de fichiers, cela donne des résultats similaires à --clone, partageant des blocs de disque physiques, tandis que sur d'autres, cela peut toujours copier des blocs, mais le fait via un chemin optimisé. Actuellement, il est pris en charge sous Linux et FreeBSD.

Si un manifeste de sauvegarde n'est pas disponible ou ne contient pas de somme de contrôle du bon type, copy_file_range sera utilisé pour copier le fichier, mais le fichier sera également lu bloc par bloc pour le calcul de la somme de contrôle.

--manifest-checksums=algorithme

Comme pg_basebackup(1), pg_combinebackup écrit un manifeste de sauvegarde dans le répertoire de sortie. Cette option spécifie l'algorithme de somme de contrôle qui doit être appliqué à chaque fichier inclus dans le manifeste de sauvegarde. Actuellement, les algorithmes disponibles sont NONE, CRC32C, SHA224, SHA256, SHA384 et SHA512. Le défaut est CRC32C.

--no-manifest

Désactive la génération d'un manifeste de sauvegarde. Si cette option n'est pas spécifiée, un manifeste de sauvegarde pour la sauvegarde reconstruite sera écrit dans le répertoire de sortie.

--sync-method=méthode

Lorsqu'il est défini sur fsync, ce qui est le défaut, pg_combinebackup ouvrira et synchronisera récursivement tous les fichiers du répertoire de sauvegarde. Lorsque le format simple est utilisé, la recherche de fichiers suivra les liens symboliques pour le répertoire WAL et chaque espace de tables configuré.

Sous Linux, syncfs peut être utilisé à la place pour demander au système d'exploitation de synchroniser l'ensemble du système de fichiers qui contient le répertoire de sauvegarde. Lorsque le format simple est utilisé, pg_combinebackup synchronisera également les systèmes de fichiers qui contiennent les fichiers WAL et chaque espace de tables. Voir recovery_init_sync_method pour des informations sur les mises en garde à prendre en compte lors de l'utilisation de syncfs.

Cette option n'a aucun effet lorsque --no-sync est utilisé.

-V
--version

Affiche la version de pg_combinebackup et quitte.

-?
--help

Affiche l'aide sur les arguments de la ligne de commande de pg_combinebackup et quitte.

LIMITATIONS

pg_combinebackup ne recalcule pas les sommes de contrôle des pages lors de l'écriture du répertoire de sortie. Par conséquent, si l'une des sauvegardes utilisées pour la reconstruction a été effectuée avec les sommes de contrôle désactivées, mais que la sauvegarde finale a été effectuée avec les sommes de contrôle activées, le répertoire résultant peut contenir des pages avec des sommes de contrôle invalides.

Pour éviter ce problème, il est recommandé d'effectuer une nouvelle sauvegarde complète après avoir modifié l'état de somme de contrôle du cluster à l'aide de pg_checksums(1). Sinon, vous pouvez désactiver, puis éventuellement réactiver les sommes de contrôle sur le répertoire produit par pg_combinebackup afin de corriger le problème.

ENVIRONNEMENT

Cet utilitaire, comme la plupart des autres utilitaires PostgreSQL, utilise les variables d'environnement prises en charge par libpq (voir la Section 32.15).

La variable d'environnement PG_COLOR spécifie si les messages de diagnostic doivent utiliser la couleur. Les valeurs possibles sont always, auto et never.

VOIR AUSSI

pg_basebackup(1) — Documentation PostgreSQL

Nom

pg_basebackup — prend une sauvegarde de base d'un cluster de base de données PostgreSQL

Synopsis

pg_basebackup [option]...

Description

pg_basebackup est un utilitaire qui permet de prendre une sauvegarde de base d'un cluster de bases de données PostgreSQL. Une sauvegarde de base est une copie des fichiers de données du cluster, plus les enregistrements WAL nécessaires pour rendre la sauvegarde cohérente. Elle peut être utilisée pour démarrer une nouvelle réplication ou pour des archives WAL.

Options

-D directory
Répertoire où sera stockée la sauvegarde de base. La valeur par défaut est `.` (le répertoire courant).
-F format
Format de la sauvegarde. Les valeurs possibles sont `p` (plain, le format par défaut) pour une copie des fichiers de données tels quels, ou `t` (tar) pour un fichier tar. Si le format est `t`, le répertoire de destination doit être un seul fichier (par exemple, `backup.tar`).
-Xs[stream]
Inclure les enregistrements WAL dans la sauvegarde. Les valeurs possibles sont `stream` pour le streaming des WAL en continu pendant la sauvegarde, ou `fetch` pour récupérer les WAL après la fin de la sauvegarde. Le streaming est généralement préférable pour les sauvegardes de longue durée.
-R
Crée un fichier `recovery.conf` dans le répertoire de sauvegarde pour permettre la récupération de la sauvegarde sur un nouveau serveur. Ce fichier sera écrit dans le sous-répertoire `pg_wal_archive` ou `pg_stream` du répertoire de sauvegarde, selon l'option `-Xs` utilisée.
-P
Affiche la progression de la sauvegarde sous forme de pourcentage.
-v
Mode verbeux.
-c {fast|immediate}
Comment fermer le serveur après la sauvegarde. `fast` (par défaut) ferme le serveur rapidement, tandis que `immediate` arrête le serveur immédiatement.
-j num_jobs
Nombre de connexions parallèles à utiliser pour la copie des tablespaces. Utile pour accélérer la sauvegarde de clusters contenant de nombreux tablespaces.
-S label
Étiquette à utiliser pour le point de sauvegarde.
-U username
Nom d'utilisateur PostgreSQL à utiliser pour se connecter.
-w
Ne jamais demander de mot de passe.
-W
Toujours demander un mot de passe.
-h host
Spécifie le nom d'hôte du serveur sur lequel se connecter.
-p port
Spécifie le port TCP ou le socket de domaine Unix local sur lequel le serveur écoute.
-d conninfo
Chaîne de connexion complète au serveur PostgreSQL.
-V
Affiche la version de pg_basebackup et quitte.
-?
Affiche l'aide sur les arguments de ligne de commande et quitte.

Limitations

pg_basebackup ne peut pas être utilisé pour sauvegarder un cluster qui n'est pas en cours d'exécution. Pour des sauvegardes de base de données plus complexes ou pour des fonctionnalités avancées telles que les sauvegardes incrémentielles, envisagez d'autres outils comme pg_dump ou pg_rman.

Environnement

Le paramètre d'environnement `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE`, `PGPASSWORD` et `PGCONNECT_TIMEOUT` peut être utilisé pour spécifier les informations de connexion.

Voir aussi

pg_dump(1), pg_restore(1), postgresql.conf(5).
