pg_restore(1)

Paquet: postgresql-libs

Licences: PostgreSQL

PG_RESTORE(1) Documentation PostgreSQL 18.1 PG_RESTORE(1)

NOM

pg_restore - restaure une base de données PostgreSQL à partir d'un fichier d'archive créé par pg_dump

SYNTAXE

pg_restore [option-connexion...] [option...] [nom-fichier]

DESCRIPTION

pg_restore est un utilitaire pour restaurer une base de données PostgreSQL à partir d'une archive créée par pg_dump(1) dans l'un des formats non texte brut. Il émettra les commandes nécessaires pour reconstruire la base de données à l'état où elle se trouvait au moment où elle a été sauvegardée. Les fichiers d'archive permettent également à pg_restore d'être sélectif quant à ce qui est restauré, ou même de réordonner les éléments avant leur restauration. Les fichiers d'archive sont conçus pour être portables entre architectures.

pg_restore peut fonctionner dans deux modes. Si un nom de base de données est spécifié, pg_restore se connecte à cette base de données et restaure le contenu de l'archive directement dans la base de données. Sinon, un script contenant les commandes SQL nécessaires pour reconstruire la base de données est créé et écrit dans un fichier ou sur la sortie standard. Cette sortie scriptée est équivalente au format de sortie texte brut de pg_dump. Certaines options contrôlant la sortie sont donc analogues aux options de pg_dump.

Évidemment, pg_restore ne peut pas restaurer les informations qui ne sont pas présentes dans le fichier d'archive. Par exemple, si l'archive a été créée avec l'option « sauvegarder les données en tant que commandes INSERT », pg_restore ne pourra pas charger les données en utilisant des instructions COPY.


Attention

La restauration d'une sauvegarde entraîne l'exécution de code arbitraire choisi par les superutilisateurs de la source. Les sauvegardes partielles et les restaurations partielles ne limitent pas cela. Si les superutilisateurs de la source ne sont pas fiables, les instructions SQL sauvegardées doivent être inspectées avant la restauration. Les sauvegardes non texte brut peuvent être inspectées en utilisant l'option --file de pg_restore. Notez que le client exécutant la sauvegarde et la restauration n'a pas besoin de faire confiance aux superutilisateurs de la source ou de la destination.

OPTIONS

pg_restore accepte les arguments de ligne de commande suivants.

nom-fichier

Spécifie l'emplacement du fichier d'archive (ou du répertoire, pour une archive au format répertoire) à restaurer. S'il n'est pas spécifié, l'entrée standard est utilisée.

-a
--data-only

Ne restaure que les données, pas le schéma (définitions de données) ni les statistiques. Les données des tables, les gros objets et les valeurs de séquences sont restaurés, s'ils sont présents dans l'archive.

Cette option est similaire, mais pour des raisons historiques pas identique à, la spécification de --section=data.

-c
--clean

Avant de restaurer des objets de base de données, émet des commandes pour DROP tous les objets qui seront restaurés. Cette option est utile pour écraser une base de données existante. Si l'un des objets n'existe pas dans la base de données de destination, des messages d'erreur ignorables seront rapportés, sauf si --if-exists est également spécifié.

-C
--create

Crée la base de données avant de restaurer dedans. Si --clean est également spécifié, supprime et recrée la base de données cible avant de s'y connecter.

Avec --create, pg_restore restaure également le commentaire de la base de données le cas échéant, et tous les paramètres de configuration qui sont spécifiques à cette base de données, c'est-à-dire toutes les commandes ALTER DATABASE ... SET ... et ALTER ROLE ... IN DATABASE ... SET ... qui mentionnent cette base de données. Les privilèges d'accès pour la base de données elle-même sont également restaurés, sauf si --no-acl est spécifié.

Lorsque cette option est utilisée, la base de données nommée avec -d est utilisée uniquement pour émettre les commandes initiales DROP DATABASE et CREATE DATABASE. Toutes les données sont restaurées dans le nom de base de données qui apparaît dans l'archive.

-d dbname
--dbname=dbname

Se connecte à la base de données dbname et restaure directement dans la base de données. Le dbname peut être une chaîne de connexion. Si c'est le cas, les paramètres de la chaîne de connexion outrepasseront toute option de ligne de commande conflictuelle.

-e
--exit-on-error

Sort si une erreur est rencontrée lors de l'envoi de commandes SQL à la base de données. La valeur par défaut est de continuer et d'afficher un décompte des erreurs à la fin de la restauration.

-f nom-fichier
--file=nom-fichier

Spécifie le fichier de sortie pour le script généré, ou pour la liste lorsqu'il est utilisé avec -l. Utilisez - pour stdout.

-F format
--format=format

Spécifie le format de l'archive. Il n'est pas nécessaire de spécifier le format, car pg_restore déterminera automatiquement le format. S'il est spécifié, il peut être l'un des suivants :

c
custom

L'archive est au format personnalisé de pg_dump.

d
directory

L'archive est une archive répertoire.

t
tar

L'archive est une archive tar.

-I index
--index=index

Restaure uniquement la définition de l'index nommé. Plusieurs index peuvent être spécifiés avec plusieurs commutateurs -I.

-j nombre-de-tâches
--jobs=nombre-de-tâches

Exécute les étapes les plus longues de pg_restore — celles qui chargent les données, créent les index ou créent les contraintes — de manière concurrente, en utilisant jusqu'à nombre-de-tâches sessions concurrentes. Cette option peut réduire considérablement le temps de restauration d'une grande base de données sur un serveur fonctionnant sur une machine multiprocesseur. Cette option est ignorée lorsqu'on génère un script plutôt que de se connecter directement à un serveur de base de données.

Chaque tâche est un processus ou un thread, selon le système d'exploitation, et utilise une connexion distincte au serveur.

La valeur optimale pour cette option dépend de la configuration matérielle du serveur, du client et du réseau. Les facteurs incluent le nombre de cœurs de processeur et la configuration du disque. Un bon point de départ est le nombre de cœurs de processeur sur le serveur, mais des valeurs plus élevées peuvent également entraîner des temps de restauration plus rapides dans de nombreux cas. Bien sûr, des valeurs trop élevées entraîneront une diminution des performances en raison du thrashing.

Seuls les formats d'archive personnalisés et répertoire sont pris en charge avec cette option. L'entrée doit être un fichier régulier ou un répertoire (pas, par exemple, un tube ou une entrée standard). De plus, plusieurs tâches ne peuvent pas être utilisées conjointement avec l'option --single-transaction.

-l
--list

Liste la table des matières de l'archive. La sortie de cette opération peut être utilisée comme entrée pour l'option -L. Notez que si des commutateurs de filtrage tels que -n ou -t sont utilisés avec -l, ils restreindront les éléments listés.

-L fichier-liste
--use-list=fichier-liste

Restaure uniquement les éléments d'archive qui sont listés dans fichier-liste, et les restaure dans l'ordre où ils apparaissent dans le fichier. Notez que si des commutateurs de filtrage tels que -n ou -t sont utilisés avec -L, ils restreindront davantage les éléments restaurés.

fichier-liste est normalement créé en modifiant la sortie d'une opération -l précédente. Les lignes peuvent être déplacées ou supprimées, et peuvent également être commentées en plaçant un point-virgule (;) au début de la ligne. Voir ci-dessous pour des exemples.

-n schema
--schema=schema

Restaure uniquement les objets qui se trouvent dans le schéma nommé. Plusieurs schémas peuvent être spécifiés avec plusieurs commutateurs -n. Ceci peut être combiné avec l'option -t pour restaurer juste une table spécifique.

-N schema
--exclude-schema=schema

Ne restaure pas les objets qui se trouvent dans le schéma nommé. Plusieurs schémas à exclure peuvent être spécifiés avec plusieurs commutateurs -N.

Lorsque -n et -N sont tous deux donnés pour le même nom de schéma, le commutateur -N l'emporte et le schéma est exclu.

-O
--no-owner

N'émet pas de commandes pour définir la propriété des objets afin qu'elle corresponde à la base de données d'origine. Par défaut, pg_restore émet des instructions ALTER OWNER ou SET SESSION AUTHORIZATION pour définir le propriétaire

--statistics

Produit des commandes pour restaurer les statistiques, si l'archive en contient. C'est le comportement par défaut.

--statistics-only

Restaure uniquement les statistiques, pas le schéma (définitions de données) ni les données.

--strict-names

Exige que chaque qualificateur de schéma (-n/--schema) et de table (-t/--table) corresponde à au moins un schéma/une table dans le fichier à restaurer.

--transaction-size=N

Exécute la restauration sous forme d'une série de transactions, chacune traitant jusqu'à N objets de base de données. Cette option implique --exit-on-error.

--transaction-size offre un choix intermédiaire entre le comportement par défaut (une transaction par commande SQL) et -1/--single-transaction (une seule transaction pour tous les objets restaurés). Alors que --single-transaction a le moins de surcharge, il peut être peu pratique pour de grandes bases de données car la transaction verrouillera chaque objet restauré, épuisant potentiellement la table de verrous du serveur. Utiliser --transaction-size avec une taille de quelques milliers d'objets offre presque les mêmes avantages de performance tout en limitant l'espace de table de verrous nécessaire.

--use-set-session-authorization

Produit des commandes SQL standard SET SESSION AUTHORIZATION au lieu de commandes ALTER OWNER pour déterminer la propriété des objets. Cela rend la sauvegarde plus compatible avec les normes, mais selon l'historique des objets dans la sauvegarde, elle pourrait ne pas être restaurée correctement.

-?
--help

Affiche l'aide sur les arguments de la ligne de commande de pg_restore, puis quitte.

pg_restore accepte également les arguments de ligne de commande suivants pour les paramètres de connexion :

-h hôte
--host=hôte

Spécifie le nom de l'hôte sur lequel le serveur est en cours d'exécution. Si la valeur commence par une barre oblique, elle est utilisée comme répertoire pour le socket de domaine Unix. La valeur par défaut est prise à partir de la variable d'environnement PGHOST, si elle est définie, sinon une connexion par socket de domaine Unix est tentée.

-p port
--port=port

Spécifie le port TCP ou l'extension du fichier de socket de domaine Unix sur lequel le serveur écoute les connexions. La valeur par défaut est la variable d'environnement PGPORT, si elle est définie, ou une valeur par défaut intégrée.

-U nomd'utilisateur
--username=nomd'utilisateur

Nom d'utilisateur pour se connecter.

-w
--no-password

Ne jamais demander de mot de passe. Si le serveur nécessite une authentification par mot de passe et qu'un mot de passe n'est pas disponible par d'autres moyens, comme un fichier .pgpass, la tentative de connexion échouera. Cette option peut être utile dans les travaux par lots et les scripts où aucun utilisateur n'est présent pour saisir un mot de passe.

-W
--password

Force pg_restore à demander un mot de passe avant de se connecter à une base de données.

Cette option n'est jamais essentielle, car pg_restore demandera automatiquement un mot de passe si le serveur exige une authentification par mot de passe. Cependant, pg_restore gaspillera une tentative de connexion pour découvrir que le serveur veut un mot de passe. Dans certains cas, il vaut la peine de taper -W pour éviter la tentative de connexion supplémentaire.

--role=nomderole

Spécifie un nom de rôle à utiliser pour effectuer la restauration. Cette option amène pg_restore à émettre une commande SET ROLE nomderole après s'être connecté à la base de données. Elle est utile lorsque l'utilisateur authentifié (spécifié par -U) manque des privilèges requis par pg_restore, mais peut basculer vers un rôle disposant des droits nécessaires. Certaines installations ont une politique contre la connexion directe en tant que superutilisateur, et l'utilisation de cette option permet d'effectuer des restaurations sans enfreindre la politique.

PGHOST
PGOPTIONS
PGPORT
PGUSER

Paramètres de connexion par défaut

PG_COLOR

Spécifie si la couleur doit être utilisée dans les messages de diagnostic. Les valeurs possibles sont always, auto et never.

Cet utilitaire, comme la plupart des autres utilitaires PostgreSQL, utilise également les variables d'environnement prises en charge par libpq (voir la section 32.15). Cependant, il ne lit pas PGDATABASE lorsqu'un nom de base de données n'est pas fourni.

DIAGNOSTICS

Lorsqu'une connexion directe à la base de données est spécifiée à l'aide de l'option -d, pg_restore exécute des instructions SQL en interne. Si vous rencontrez des problèmes lors de l'exécution de pg_restore, assurez-vous de pouvoir sélectionner des informations de la base de données en utilisant, par exemple, psql(1). De plus, tous les paramètres de connexion par défaut et les variables d'environnement utilisés par la bibliothèque front-end libpq s'appliqueront.

NOTES

Si votre installation contient des ajouts locaux à la base de données template1, veillez à charger la sortie de pg_restore dans une base de données véritablement vide ; sinon, vous risquez d'obtenir des erreurs en raison de définitions dupliquées des objets ajoutés. Pour créer une base de données vide sans aucune addition locale, copiez à partir de template0 et non de template1, par exemple :

CREATE DATABASE foo WITH TEMPLATE template0;

Les limitations de pg_restore sont détaillées ci-dessous.

•Lors de la restauration de données dans une table préexistante et que l'option --disable-triggers est utilisée, pg_restore émet des commandes pour désactiver les déclencheurs sur les tables utilisateur avant d'insérer les données, puis émet des commandes pour les réactiver après l'insertion des données. Si la restauration est arrêtée au milieu, les catalogues système peuvent se retrouver dans un état incorrect.
•pg_restore ne peut pas restaurer sélectivement les gros objets ; par exemple, seulement ceux d'une table spécifique. Si une archive contient des gros objets, alors tous les gros objets seront restaurés, ou aucun d'entre eux s'ils sont exclus via -L, -t, ou d'autres options.

Voir également la documentation de pg_dump(1) pour les détails sur les limitations de pg_dump.

Par défaut, pg_restore restaurera les statistiques de l'optimiseur si elles sont incluses dans le fichier de sauvegarde. Si toutes les statistiques ne sont pas restaurées, il peut être utile d'exécuter ANALYZE sur chaque table restaurée afin que l'optimiseur dispose de statistiques utiles ; voir les sections 24.1.3 et 24.1.6 pour plus d'informations.

EXEMPLES

Supposons que nous ayons sauvegardé une base de données appelée mydb dans un fichier de sauvegarde au format personnalisé :

$ pg_dump -Fc mydb > db.dump

Pour supprimer la base de données et la recréer à partir de la sauvegarde :

$ dropdb mydb
$ pg_restore -C -d postgres db.dump

La base de données nommée dans le commutateur -d peut être n'importe quelle base de données existant dans le cluster ; pg_restore l'utilise uniquement pour émettre la commande CREATE DATABASE pour mydb. Avec -C, les données sont toujours restaurées dans la base de données nommée qui apparaît dans le fichier de sauvegarde.

Pour restaurer la sauvegarde dans une nouvelle base de données appelée newdb :

$ createdb -T template0 newdb
$ pg_restore -d newdb db.dump

Notez que nous n'utilisons pas -C, et nous nous connectons directement à la base de données à restaurer. Notez également que nous clonons la nouvelle base de données à partir de template0 et non de template1, pour garantir qu'elle soit initialement vide.

Pour réordonner les éléments de la base de données, il faut d'abord extraire la table des matières de l'archive :

$ pg_restore -l db.dump > db.list

Le fichier de liste se compose d'un en-tête et d'une ligne pour chaque élément, par exemple :

;
; Archive créée le Lun 14 Sep 13:55:39 2009
;     dbname: DBDEMOS
;     TOC Entries: 81
;     Compression: 9
;     Dump Version: 1.10-0
;     Format: CUSTOM
;     Integer: 4 bytes
;     Offset: 8 bytes
;     Dumped from database version: 8.3.5
;     Dumped by pg_dump version: 8.3.8
;
;
; Selected TOC Entries:
;
3; 2615 2200 SCHEMA - public pasha
1861; 0 0 COMMENT - SCHEMA public pasha
1862; 0 0 ACL - public pasha
317; 1247 17715 TYPE public composite pasha
319; 1247 25899 DOMAIN public domain0 pasha

Les points-virgules commencent un commentaire, et les nombres au début des lignes font référence à l'ID interne de l'archive attribué à chaque élément.

Les lignes du fichier peuvent être commentées, supprimées et réordonnées. Par exemple :

10; 145433 TABLE map_resolutions postgres
;2; 145344 TABLE species postgres
;4; 145359 TABLE nt_header postgres
6; 145402 TABLE species_records postgres
;8; 145416 TABLE ss_old postgres

pourrait être utilisé comme entrée pour pg_restore et ne restaurerait que les éléments 10 et 6, dans cet ordre :

$ pg_restore -L db.list db.dump

pg_restore(1) — Manuel Arch Linux

NOM

pg_restore — une utilitaire de restauration sélective pour les sauvegardes PostgreSQL au format d'archive

SYNTAXE

pg_restore [options] [nom_fichier]

DESCRIPTION

pg_restore est un utilitaire qui permet de restaurer une base de données PostgreSQL à partir d'une sauvegarde créée par pg_dump dans l'un des formats d'archive (personnalisé, personnalisé-compressé, tar, ou tar-compressé).

La restauration peut être effectuée de manière sélective, c'est-à-dire que certains objets de la base de données peuvent être exclus ou inclus lors de la restauration.

La sauvegarde doit avoir été créée en utilisant pg_dump avec l'une des options de format d'archive.

OPTIONS

pg_restore accepte les options suivantes en ligne de commande :

-c, --clean
Demande à pg_restore d'émettre des commandes de suppression (DROP) pour les tables, vues, fonctions, etc. avant de recréer les objets. Si cette option est spécifiée, les objets seront supprimés avant d'être recréés.
-C, --create
Demande à pg_restore de créer la base de données avant d'y restaurer les données. L'option -d sera ignorée ; la connexion se fera à la base de données par défaut postgres et la base de données spécifiée dans la sauvegarde sera créée.
-d, --dbname=nom_db
Spécifie le nom de la base de données à laquelle se connecter. Si cette option n'est pas spécifiée et que l'option -C n'est pas utilisée, la base de données par défaut est celle dont le nom est spécifié dans la variable d'environnement PGDATABASE, ou celle du nom d'utilisateur courant.
-e, --exit-on-error
Quitte pg_restore dès qu'une erreur se produit. Par défaut, pg_restore essaie de continuer, même après des erreurs.
-F, --format=format
Spécifie le format de la sauvegarde. Les formats possibles sont c (personnalisé), d (personnalisé-compressé), t (tar), et p (plain text, mais cette option est déconseillée et pg_dump devrait être utilisé à la place).
-f, --file=nom_fichier
Spécifie le nom du fichier de sauvegarde à utiliser. Si cette option n'est pas spécifiée, pg_restore lit depuis l'entrée standard.
-j, --jobs=nombre
Exécute les opérations de restauration en parallèle à l'aide de nombre connexions simultanées. Ceci peut accélérer considérablement la restauration des bases de données volumineuses. Les objets sont restaurés dans l'ordre, mais les données sont chargées en parallèle. pg_restore attendra la fin de toutes les opérations parallèles avant de se terminer.
-l, --list
Liste le contenu de la sauvegarde, puis quitte. Cette option permet de voir quels objets sont inclus dans la sauvegarde.
-n, --schema=schéma
Restaure uniquement les objets appartenant au schéma spécifié. Cette option peut être utilisée plusieurs fois pour restaurer des objets de plusieurs schémas. Elle ne s'applique qu'aux objets qui sont dans des schémas (comme les tables, vues, séquences, etc.).
-O, --no-owner
Ne pas spécifier les propriétaires d'objets lors de la création des objets. Par défaut, pg_restore essaie de faire correspondre les propriétaires des objets tels qu'ils sont dans la sauvegarde. Avec cette option, tous les objets seront créés avec les droits de l'utilisateur qui exécute pg_restore.
-P, --create-function=fonction
Restaure uniquement la fonction spécifiée. Cette option peut être utilisée plusieurs fois pour restaurer plusieurs fonctions.
-R, --section=section
Restaure uniquement la section spécifiée. Les sections possibles sont : pre-data, data, et post-data. Le format plain ne supporte pas les sections.
-s, --schema-only
Restaure uniquement les définitions des objets (schéma), sans les données. Si cette option est utilisée, les données ne seront pas restaurées.
-S, --superuser=nom_utilisateur
Spécifie le nom de l'utilisateur superutilisateur pour la connexion. Cet utilisateur sera utilisé pour exécuter les commandes de suppression (DROP) si l'option -c est utilisée.
-t, --table=table
Restaure uniquement la table spécifiée. Cette option peut être utilisée plusieurs fois pour restaurer plusieurs tables. Les dépendances de la table spécifiée seront également restaurées.
-T, --no-tablespaces
Ne pas spécifier les tablespaces lors de la création des objets. Par défaut, pg_restore essaie de faire correspondre les tablespaces tels qu'ils sont dans la sauvegarde. Avec cette option, les objets seront créés dans le tablespace par défaut de la base de données.
-U, --username=nom_utilisateur
Spécifie le nom d'utilisateur à utiliser pour la connexion. Si cette option n'est pas spécifiée, le nom d'utilisateur par défaut est celui du système d'exploitation courant ou PGUSER.
-v, --verbose
Active le mode détaillé, qui affiche des informations sur le processus de restauration.
-V, --version
Affiche la version de pg_restore et quitte.
-x, --no-privileges, --no-acl
Ne pas restaurer les privilèges d'accès (GRANT / REVOKE). Par défaut, les privilèges d'accès sont restaurés.
-1, --single-transaction
Exécute la restauration entière dans une seule transaction. Si une erreur se produit, tout ce qui a été fait sera annulé. Cette option est utile pour garantir l'intégrité des données lors de la restauration.
-h, --host=hôte
Spécifie le nom d'hôte ou l'adresse IP du serveur sur lequel la base de données est en cours d'exécution. Si cette option n'est pas spécifiée, une connexion locale sera tentée ou la variable d'environnement PGHOST sera utilisée.
-p, --port=port
Spécifie le port TCP ou le fichier de socket de domaine Unix sur lequel le serveur est en cours d'exécution. La valeur par défaut est celle spécifiée par la variable d'environnement PGPORT ou la valeur par défaut du système (généralement 5432).

EXEMPLES

Pour restaurer une base de données à partir d'un fichier nommé ma_sauvegarde.tar dans une base de données nommée ma_db :

pg_restore -d ma_db ma_sauvegarde.tar

Pour restaurer uniquement les tables clients et commandes à partir d'une sauvegarde compressée :

pg_restore -d ma_db -t clients -t commandes ma_sauvegarde.dump

Pour lister le contenu d'une sauvegarde :

pg_restore -l ma_sauvegarde.tar

Pour restaurer une base de données en créant la base de données elle-même, puis en restaurant uniquement le schéma :

pg_restore -C -s ma_sauvegarde.tar

DIAGNOSTICS

pg_restore renvoie 0 si tout s'est bien passé, 1 si des erreurs se sont produites, et 2 si des avertissements se sont produits mais que la restauration s'est terminée correctement.

Les erreurs rencontrées pendant la restauration sont affichées sur la sortie d'erreur standard.

NOTES

La restauration peut nécessiter des privilèges d'administrateur si vous créez la base de données ou restaurez des objets nécessitant des privilèges élevés.

Il est recommandé d'utiliser l'option -1 (--single-transaction) pour garantir l'intégrité des données, surtout lors de la restauration de bases de données volumineuses ou complexes.
