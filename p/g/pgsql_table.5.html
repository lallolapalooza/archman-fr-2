PGSQL_TABLE(5) Manuel des formats de fichier PGSQL_TABLE(5)

NOM

pgsql_table - Configuration client PostgreSQL de Postfix

SYNTAXE

postmap -q "chaîne" pgsql:/etc/postfix/nom_fichier
postmap -q - pgsql:/etc/postfix/nom_fichier <fichier_entrée

DESCRIPTION


Le système de messagerie Postfix utilise des tables optionnelles pour la réécriture d'adresses ou le routage des e-mails. Ces tables sont généralement au format dbm ou db.

Alternativement, les tables de recherche peuvent être spécifiées comme des bases de données PostgreSQL. Pour utiliser les recherches PostgreSQL, définissez une source PostgreSQL comme table de recherche dans main.cf, par exemple :

    alias_maps = pgsql:/etc/postfix/pgsql-aliases.cf

Le fichier /etc/postfix/pgsql-aliases.cf a le même format que le fichier main.cf de Postfix, et peut spécifier les paramètres décrits ci-dessous.

MEMBRES DE LISTE

Lors de l'utilisation de SQL pour stocker des listes telles que $mynetworks, $mydestination, $relay_domains, $local_recipient_maps, etc., il est important de comprendre que la table doit stocker chaque membre de la liste comme une clé distincte. La recherche dans la table vérifie l'*existence* de la clé. Voir « Postfix lists versus tables » dans le document DATABASE_README pour une discussion.

NE PAS créer de tables qui retournent la liste complète des domaines dans $mydestination ou $relay_domains, etc., ou des adresses IP dans $mynetworks.

CRÉER des tables avec chaque élément correspondant comme clé et avec une valeur arbitraire. Avec les bases de données SQL, il n'est pas rare de retourner la clé elle-même ou une valeur constante.

PARAMÈTRES PGSQL

hosts
Les hôtes que Postfix essaiera de connecter et d'interroger. En plus d'une URI de connexion PostgreSQL, ce réglage prend en charge les formes historiques unix:/chemin pour les sockets de domaine UNIX et inet:hôte:port pour les connexions TCP, où les préfixes unix: et inet: sont acceptés et ignorés pour la compatibilité descendante. Exemples : 
    hosts = postgresql://username@example.com/nom_base?sslmode=require
    hosts = postgres://user:secret@localhost
    hosts = inet:host1.some.domain inet:host2.some.domain:port
    hosts = host1.some.domain host2.some.domain:port
    hosts = unix:/chemin/vers/fichier

Voir https://www.postgresql.org/docs/current/libpq-connect.html pour la syntaxe des URI de connexion prises en charge.

Les hôtes sont essayés dans un ordre aléatoire. Les connexions sont automatiquement fermées après environ 1 minute d'inactivité et sont rouvertes si nécessaire. Voir idle_interval pour plus de détails.

NOTE : si le réglage hosts spécifie une URI de connexion PostgreSQL, le client PostgreSQL de Postfix ignorera les réglages dbname, user et password pour cette connexion.

NOTE : si le réglage hosts spécifie un seul serveur, ce client suppose que la cible est un équilibreur de charge et se reconnectera immédiatement après un seul échec, au lieu d'échouer temporairement toutes les requêtes. Avec les anciennes versions de ce client, spécifiez le même serveur deux fois.

user
password
Le nom d'utilisateur et le mot de passe pour se connecter au serveur pgsql. Exemple : 
    user = quelqu'un
    password = mot_de_passe

Les réglages user et password sont ignorés pour les connexions hosts spécifiées sous forme d'URI.

dbname
Le nom de la base de données sur les serveurs. Exemple : 
    dbname = base_clients

Le réglage dbname est ignoré pour les connexions hosts spécifiées sous forme d'URI.

Le réglage dbname est requis avec Postfix 3.10 et ultérieur, lorsque hosts spécifie une connexion non-URI ; il est toujours requis avec les versions antérieures de Postfix.

encoding
L'encodage utilisé par le client de base de données. Le réglage par défaut est : 
    encoding = UTF8

Historiquement, le client de base de données était codé en dur pour utiliser LATIN1 dans une tentative de désactiver la prise en charge des caractères multibytes.

Cette fonctionnalité est disponible à partir de Postfix 3.8.

idle_interval (défaut : 60)
Le nombre de secondes après lesquelles une connexion de base de données inactive sera fermée.

Cette fonctionnalité est disponible à partir de Postfix 3.9.

retry_interval (défaut : 60)
Le nombre de secondes pendant lesquelles une connexion de base de données sera ignorée après une erreur.

NOTE : si le réglage hosts spécifie un seul serveur, ce client suppose que la cible est un équilibreur de charge et se reconnectera immédiatement après un seul échec, au lieu d'échouer temporairement toutes les requêtes. Avec les anciennes versions de ce client, spécifiez le même serveur deux fois.

Cette fonctionnalité est disponible à partir de Postfix 3.9.

query
Le modèle de requête SQL utilisé pour rechercher dans la base de données, où %s est un substitut pour l'adresse que Postfix essaie de résoudre, par exemple : 
    query = SELECT replacement FROM aliases WHERE mailbox = '%s'

Ce paramètre prend en charge les expansions '%' suivantes :

%%
Ceci est remplacé par un caractère '%' littéral. (Postfix 2.2 et ultérieur)
%s
Ceci est remplacé par la clé d'entrée. Le quoting SQL est utilisé pour s'assurer que la clé d'entrée n'ajoute pas de métacaractères inattendus.
%u
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %u est remplacé par la partie locale de l'adresse, mise en quote SQL. Sinon, %u est remplacé par la chaîne de recherche entière. Si la partie locale est vide, la requête est supprimée et ne retourne aucun résultat.
%d
Lorsque la clé d'entrée est une adresse de la forme utilisateur@domaine, %d est remplacé par la partie domaine de l'adresse, mise en quote SQL. Sinon, la requête est supprimée et ne retourne aucun résultat.
%[SUD]
Les équivalents en majuscules des expansions ci-dessus se comportent dans le paramètre query identiquement à leurs homologues en minuscules. Avec le paramètre result_format (voir ci-dessous), ils développent la clé d'entrée plutôt que la valeur du résultat.
Les expansions %S, %U et %D ci-dessus sont disponibles à partir de Postfix 2.2.
%[1-9]
Les motifs %1, %2, ... %9 sont remplacés par le composant le plus significatif correspondant du domaine de la clé d'entrée. Si la clé d'entrée est utilisateur@mail.example.com, alors %1 est com, %2 est example et %3 est mail. Si la clé d'entrée n'est pas qualifiée ou n'a pas suffisamment de composants de domaine pour satisfaire tous les motifs spécifiés, la requête est supprimée et ne retourne aucun résultat.
Les expansions %1, ... %9 ci-dessus sont disponibles à partir de Postfix 2.2.
Le paramètre domain décrit ci-dessous limite les clés d'entrée aux adresses dans les domaines correspondants. Lorsque le paramètre domain n'est pas vide, les requêtes SQL pour les adresses non qualifiées ou les adresses dans les domaines non correspondants sont supprimées et ne retournent aucun résultat.

La priorité de ce paramètre a changé avec Postfix 2.2, dans les versions antérieures la priorité était, de la plus haute à la plus basse, select_function, query, select_field, ...

Avec Postfix 2.2, le paramètre query a la priorité la plus élevée, voir INTERFACES DE REQUÊTE OBSOLÈTES ci-dessous.

NOTE : NE mettez PAS de guillemets autour du paramètre query.

result_format (défaut : %s)
Modèle de format appliqué aux attributs de résultat. Le plus souvent utilisé pour ajouter (ou préfixer) du texte au résultat. Ce paramètre prend en charge les expansions '%' suivantes :
%%
Ceci est remplacé par un caractère '%' littéral.
%s
Ceci est remplacé par la valeur de l'attribut de résultat. Lorsque le résultat est vide, il est ignoré.
%u
Lorsque le résultat est une adresse de la forme utilisateur@domaine, %u est remplacé par la partie locale de l'adresse, mise en quote SQL. Sinon, %u est remplacé par la chaîne de résultat entière.
%d
Lorsque le résultat est une adresse de la forme utilisateur@domaine, %d est remplacé par la partie domaine de l'adresse, mise en quote SQL. Sinon, la chaîne de résultat est supprimée et ne retourne aucun résultat.
%[SUD]
Les équivalents en majuscules des expansions ci-dessus se comportent dans le paramètre result_format identiquement à leurs homologues en minuscules. Avec le paramètre query (voir ci-dessus), ils développent la clé d'entrée plutôt que la valeur du résultat.
Les expansions %S, %U et %D ci-dessus sont disponibles à partir de Postfix 2.2.
%[1-9]
Les motifs %1, %2, ... %9 sont remplacés par le composant le plus significatif correspondant du domaine de la clé d'entrée. Si la clé d'entrée est utilisateur@mail.example.com, alors %1 est com, %2 est example et %3 est mail. Si la clé d'entrée n'est pas qualifiée ou n'a pas suffisamment de composants de domaine pour satisfaire tous les motifs spécifiés, la requête est supprimée et ne retourne aucun résultat.
Les expansions %1, ... %9 ci-dessus sont disponibles à partir de Postfix 2.2.

Le paramètre domain décrit ci-dessous limite les clés d'entrée aux adresses dans les domaines correspondants. Lorsque le paramètre domain n'est pas vide, les requêtes SQL pour les adresses non qualifiées ou les adresses dans les domaines non correspondants sont supprimées et ne retournent aucun résultat.

La priorité de ce paramètre a changé avec Postfix 2.2, dans les versions antérieures la priorité était, de la plus haute à la plus basse, select_function, query, select_field, ...

Avec Postfix 2.2, le paramètre query a la priorité la plus élevée, voir INTERFACES DE REQUÊTE OBSOLÈTES ci-dessous.

NOTE : NE mettez PAS de guillemets autour du paramètre result_format.

Si le résultat de la requête contient plusieurs lignes, toutes les lignes sont traitées et leurs valeurs de résultat sont concaténées. Les espaces blancs sont ajoutés comme séparateurs, et ces espaces blancs sont supprimés à la fin de la chaîne résultante.

select_function

Fonction à utiliser pour sélectionner le résultat. Les fonctions disponibles sont any, all, map, first et one.

La valeur par défaut est map.

any
Cette fonction renvoie la première colonne de toutes les lignes retournées. La chaîne de résultat est construite en concaténant toutes les valeurs de colonne avec un espace comme séparateur.
all
Identique à any.
map
Cette fonction renvoie la première colonne de toutes les lignes retournées. La chaîne de résultat est construite en concaténant toutes les valeurs de colonne avec un seul espace comme séparateur.
first
Cette fonction renvoie la première colonne de la première ligne retournée. Si plusieurs lignes sont retournées, les lignes suivantes sont ignorées.
one
Identique à first.

Pour des raisons de compatibilité ascendante, les anciennes fonctions getvalue* sont toujours prises en charge. Elles sont mapeées aux fonctions de sélection comme suit :

getvalue
mappé à map
getfirst
mappé à first
domain

Limite le traitement aux adresses dans le domaine spécifié. Si le paramètre est vide, les adresses non qualifiées sont traitées. Si une adresse est qualifiée et ne correspond pas au domaine spécifié, la recherche est ignorée et aucun résultat n'est retourné.

Ce paramètre est disponible dans Postfix 2.0 et ultérieur.

Par exemple, pour n'accepter que les adresses du domaine example.com : 

    domain = example.com

optional

Ce paramètre indique si la table est facultative. Si elle est définie sur « yes », Postfix continuera même si la table n'existe pas ou ne peut pas être lue. La valeur par défaut est « no ».

Ce paramètre est disponible dans Postfix 2.2 et ultérieur.

cache_policy

Spécifie la politique de mise en cache des résultats des recherches. Les valeurs possibles sont none, all et expired.

none : Aucune mise en cache n'est effectuée.

all : Tous les résultats de recherche sont mis en cache.

expired : La mise en cache est effectuée pendant la durée spécifiée par le paramètre cache_ttl.

La valeur par défaut est all.

Ce paramètre est disponible dans Postfix 3.0 et ultérieur.

cache_ttl

Durée de vie en secondes pour les résultats mis en cache lorsque cache_policy est défini sur expired. La valeur par défaut est 600 secondes (10 minutes).

Ce paramètre est disponible dans Postfix 3.0 et ultérieur.

INTERFACES DE REQUÊTE OBSOLÈTES

Les interfaces de requête suivantes sont obsolètes et devraient être remplacées par le paramètre query :

select_field
Le nom du champ à sélectionner dans la table de base de données.
where_field
Le nom du champ où effectuer la recherche.
table
Le nom de la table de base de données à interroger.

Ces paramètres sont disponibles pour la compatibilité ascendante, mais il est fortement recommandé d'utiliser le paramètre query pour des raisons de flexibilité et de clarté.

DOSAGE

Le fichier de configuration de la table Postfix (par exemple, /etc/postfix/pgsql-aliases.cf) est lu par le programme postmap lors de la création de la table de recherche.

Le résultat de la recherche est utilisé par les services Postfix lorsqu'ils consultent la table.

EXEMPLES

Exemple de fichier de configuration

Pour utiliser une base de données PostgreSQL nommée virtual_mail sur un serveur local comme table d'alias :

    # /etc/postfix/pgsql-aliases.cf
    user = vmail_user
    password = vmail_password
    dbname = virtual_mail
    hosts = localhost
    query = SELECT goto FROM aliases WHERE mailbox = "%s"

Pour créer la table de recherche Postfix :

    postmap /etc/postfix/pgsql-aliases.cf

Pour configurer Postfix pour utiliser cette table :

    # /etc/postfix/main.cf
    alias_maps = pgsql:/etc/postfix/pgsql-aliases.cf

Exemple avec URI de connexion

Utilisation d'une URI de connexion PostgreSQL pour spécifier les détails de connexion :

    # /etc/postfix/pgsql-redirect.cf
    hosts = postgresql://redirect_user@db.example.com/mail_redirect?sslmode=require
    query = SELECT target FROM redirect WHERE source = "%s"

Création de la table :

    postmap /etc/postfix/pgsql-redirect.cf

Configuration dans main.cf :

    # /etc/postfix/main.cf
    sender_dependent_relayhost_maps = pgsql:/etc/postfix/pgsql-redirect.cf

NAME

pgsql_table - Postfix PostgreSQL lookup tables

SYNOPSIS

    /etc/postfix/main.cf, master.cf:

    hash_map_type = pgsql
    pgsql_table_name = table
    pgsql_port_id = port
    pgsql_username = user
    pgsql_password = password
    pgsql_database = database
    pgsql_hostnames = host1[, host2] ...
    pgsql_query_filter = filter
    pgsql_select_field = field
    pgsql_table = table
    pgsql_where_field = field
    pgsql_additional_conditions = conditions
    pgsql_result_format = format
    pgsql_domain = domain
    pgsql_expansion_limit = limit

    or in Postfix 2.2 and later:

    maptype = pgsql:pgsqlname
    where pgsqlname is the name of a PostgreSQL source defined
    in main.cf.

DESCRIPTION

The PostgreSQL lookup table type supports lookup tables that are stored in a PostgreSQL database. The table name, database, username, password, hostname, and port are specified in Postfix configuration parameters.

Starting with Postfix 2.2, lookup tables can be specified as type:mapname. When mapname does not start with a slash or a dot, Postfix treats it as the name of a PostgreSQL source, defined elsewhere in main.cf.

This allows PostgreSQL parameters to be defined once, and reused by multiple lookup tables. For example:

    # main.cf
    # PostgreSQL source definition
    pgsql_source_default:
        pgsql_hostnames = db.example.com
        pgsql_database = mail
        pgsql_user = mailuser
        pgsql_password = secret
        pgsql_port = 5432

    # Lookup tables
    virtual_mailbox_maps = pgsql:pgsql_source_default,
                           pgsql:pgsql_source_mailalias
    alias_maps = pgsql:pgsql_source_default

    # Another source definition
    pgsql_source_mailalias:
        pgsql_hostnames = db2.example.com
        pgsql_database = mail_aliases
        pgsql_user = aliasuser
        pgsql_password = topsecret

LIST MEMBERSHIP

The PostgreSQL lookup table type supports lookup tables that are stored in a PostgreSQL database. The table name, database, username, password, hostname, and port are specified in Postfix configuration parameters.

PGSQL PARAMETERS

The following parameters are available for PostgreSQL lookup tables:

pgsql_hostnames
A list of one or more host names or IP addresses of the PostgreSQL server(s). When multiple hosts are specified, they are tried in order until a connection is established. The default is "localhost".
pgsql_port
The TCP port number on which the PostgreSQL server listens. The default is "5432".
pgsql_database
The name of the PostgreSQL database to connect to. The default is "postgres".
pgsql_user
The PostgreSQL username to connect with. If this is empty, the user name is taken from the operating system environment (e.g. the name of the user running the Postfix process).
pgsql_password
The password for the PostgreSQL user. If this is empty, no password is used.
pgsql_query_filter
A string that defines the SQL query to execute. The format specifier %s is replaced by the lookup key. The default is "SELECT.", which is invalid and needs to be overridden.
pgsql_result_format
A string that defines how to format the result of the SQL query. The default is "%s", which means to use the result value as is.
%s
The result attribute value is used as is.
%u
The result attribute value is an address of the form user@domain, %u is replaced by the local part of the address. When the result has an empty localpart it is skipped.
%d
The result attribute value is an address of the form user@domain, %d is replaced by the domain part of the attribute value. When the result is unqualified it is skipped.
%[SUD1-9]
The upper-case and decimal digit expansions interpolate the parts of the input key rather than the result. Their behavior is identical to that described with query, and in fact because the input key is known in advance, queries whose key does not contain all the information specified in the result template are suppressed and return no results.
For example, using "result_format = smtp:[%s]" allows one to use a mailHost attribute as the basis of a transport(5) table. After applying the result format, multiple values are concatenated as comma separated strings. The expansion_limit and parameter explained below allows one to restrict the number of values in the result, which is especially useful for maps that must return at most one value.

The default value %s specifies that each result value should be used as is.

This parameter is available with Postfix 2.2 and later.

NOTE: DO NOT put quotes around the result format!

domain (default: no domain list)
This is a list of domain names, paths to files, or "type:table" databases. When specified, only fully qualified search keys with a *non-empty* localpart and a matching domain are eligible for lookup: 'user' lookups, bare domain lookups and "@domain" lookups are not performed. This can significantly reduce the query load on the PostgreSQL server. 
    domain = postfix.org, hash:/etc/postfix/searchdomains

It is best not to use SQL to store the domains eligible for SQL lookups.

This parameter is available with Postfix 2.2 and later.

NOTE: DO NOT define this parameter for local(8) aliases, because the input keys are always unqualified.

expansion_limit (default: 0)
A limit on the total number of result elements returned (as a comma separated list) by a lookup against the map. A setting of zero disables the limit. Lookups fail with a temporary error if the limit is exceeded. Setting the limit to 1 ensures that lookups do not return multiple values.

OBSOLETE MAIN.CF PARAMETERS

For compatibility with other Postfix lookup tables, PostgreSQL parameters can also be defined in main.cf. In order to do that, specify as PostgreSQL source a name that doesn't begin with a slash or a dot. The PostgreSQL parameters will then be accessible as the name you've given the source in its definition, an underscore, and the name of the parameter. For example, if the map is specified as "pgsql:pgsqlname", the parameter "hosts" would be defined in main.cf as "pgsqlname_hosts".

Note: with this form, the passwords for the PostgreSQL sources are written in main.cf, which is normally world-readable. Support for this form will be removed in a future Postfix version.

OBSOLETE QUERY INTERFACES

This section describes query interfaces that are deprecated as of Postfix 2.2. Please migrate to the new query interface as the old interfaces are slated to be phased out.

select_function
This parameter specifies a database function name. Example: 
    select_function = my_lookup_user_alias

This is equivalent to:

    query = SELECT my_lookup_user_alias('%s')

This parameter overrides the legacy table-related fields (described below). With Postfix versions prior to 2.2, it also overrides the query parameter. Starting with Postfix 2.2, the query parameter has highest precedence, and the select_function parameter is deprecated.

The following parameters (with lower precedence than the select_function interface described above) can be used to build the SQL select statement as follows:

    SELECT [select_field]
    FROM [table]
    WHERE [where_field] = '%s'
          [additional_conditions]

The specifier %s is replaced with each lookup by the lookup key and is escaped so if it contains single quotes or other odd characters, it will not cause a parse error, or worse, a security problem.

Starting with Postfix 2.2, this interface is obsoleted by the more general query interface described above. If higher precedence the query or select_function parameters described above are defined, the parameters described here are ignored.

select_field
The SQL "select" parameter. Example: 
    select_field = forw_addr
table
The SQL "select .. from" table name. Example: 
    table = mxaliases
where_field
The SQL "select .. where" parameter. Example: 
    where_field = alias
additional_conditions
Additional conditions to the SQL query. Example: 
    additional_conditions = AND status = 'paid'
