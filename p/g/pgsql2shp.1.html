NOM

pgsql2shp - extracteur de tables postgis vers shapefile

SYNTAXE

pgsql2shp [options] base_de_donnees [schema.]table
pgsql2shp [options] base_de_donnees requête

DESCRIPTION

L'extracteur de tables pgsql2shp se connecte directement à la base de données et convertit une table (éventuellement créée par une requête utilisateur) en un fichier shape. Il est compatible avec toutes les versions de PostGIS.

Version : 1.1.5 (2006/10/06)

UTILISATION

La <base_de_donnees> est le nom de la base de données à laquelle se connecter.

La <table> est la table (éventuellement qualifiée par son schéma) à partir de laquelle lire les données spatiales. Alternativement, vous pouvez spécifier une REQUÊTE dont le résultat sera écrit dans le shapefile.

OPTIONS

Les options en ligne de commande sont :

-f <nom_fichier>
Écrire la sortie dans un fichier particulier.
-h <hote>
L'hôte de la base de données auquel se connecter.
-p <port>
Le port auquel se connecter sur l'hôte de la base de données.
-P <mot_de_passe>
Le mot de passe à utiliser lors de la connexion à la base de données.
-u <utilisateur>
Le nom d'utilisateur à utiliser lors de la connexion à la base de données.
-g <colonne_geometrie>
Dans le cas de tables avec plusieurs colonnes de géométrie, la colonne de géométrie à utiliser lors de l'écriture du shapefile.
-b
Utiliser un curseur binaire. Lorsqu'il est utilisé sur des versions de PostGIS antérieures à 1.0.0, cela réduit la probabilité de dérive des coordonnées due à la conversion au format WKT et depuis. Les dérives de coordonnées ne se produiront pas avec les versions 1.0.0 et ultérieures de PostGIS. Ce sera légèrement plus rapide, mais peut échouer si une colonne NON géométrique n'a pas de transtypage vers texte.
-r
Mode brut. Ne pas supprimer le champ gid, ni échapper les noms de colonnes.
-d
Pour la compatibilité descendante : écrire un shapefile tridimensionnel lors de l'extraction d'anciennes bases de données postgis (antérieures à 1.0.0) (la valeur par défaut est d'écrire un shapefile bidimensionnel dans ce cas). À partir de postgis-1.0.0+, les dimensions sont entièrement encodées.
-k
Conserver la casse des identifiants (ne pas mettre les noms de champs en majuscules).
-m <nom_fichier>
Spécifier un fichier contenant un ensemble de correspondances de noms de colonnes (longues) à des noms de colonnes DBF de 10 caractères. Le contenu du fichier est une ou plusieurs lignes de deux noms séparés par des espaces blancs et sans espace final ou initial :

NOMCOLONNE CHAMPDBF1

UNNOMDECOLONNETRESgetLong CHAMPDBF2

etc.

-?
Afficher la version et les informations d'utilisation.

INSTALLATION

Pour compiler le programme à partir des sources, exécutez simplement « make » dans le répertoire source. Ensuite, copiez le binaire dans votre chemin de recherche shell (ou où vous le souhaitez). Ce texte est également disponible sous forme de page de manuel dans le répertoire ../doc/man/, prêt à être copié dans le chemin de recherche des manuels sur les systèmes de type Unix.

EXEMPLES

Une session exemple utilisant l'extracteur pour créer un shapefile à partir d'une base de données pourrait ressembler à ceci :

# pgsql2shp -f mon_fichier -p 5555 ma_bd table_routes
