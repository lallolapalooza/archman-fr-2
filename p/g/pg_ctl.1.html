NOM

pg_ctl - initialiser, démarrer, arrêter ou contrôler un serveur PostgreSQL

SYNTAXE

pg_ctl init[db] [-D datadir] [-s] [-o options-initdb]

pg_ctl start [-D datadir] [-l nomfichier] [-W] [-t secondes] [-s] [-o options] [-p chemin] [-c]

pg_ctl stop [-D datadir] [-m s[mart] | f[ast] | i[mmediate]] [-W] [-t secondes] [-s]

pg_ctl restart [-D datadir] [-m s[mart] | f[ast] | i[mmediate]] [-W] [-t secondes] [-s] [-o options] [-c]

pg_ctl reload [-D datadir] [-s]

pg_ctl status [-D datadir]

pg_ctl promote [-D datadir] [-W] [-t secondes] [-s]

pg_ctl logrotate [-D datadir] [-s]

pg_ctl kill nom_signal id_processus

Sur Microsoft Windows, également :

pg_ctl register [-D datadir] [-N noms-service] [-U nom-utilisateur] [-P motdepasse] [-S a[uto] | d[emand]] [-e source] [-W] [-t secondes] [-s] [-o options]

pg_ctl unregister [-N noms-service]

DESCRIPTION

pg_ctl est un utilitaire pour initialiser un cluster de bases de données PostgreSQL, démarrer, arrêter ou redémarrer le serveur de bases de données PostgreSQL (postgres(1)), ou afficher l'état d'un serveur en cours d'exécution. Bien que le serveur puisse être démarré manuellement, pg_ctl encapsule des tâches telles que la redirection de la sortie des journaux et le détachement correct du terminal et du groupe de processus. Il fournit également des options pratiques pour un arrêt contrôlé.

Le mode init ou initdb crée un nouveau cluster de bases de données PostgreSQL, c'est-à-dire une collection de bases de données qui seront gérées par une seule instance de serveur. Ce mode appelle la commande initdb. Voir initdb(1) pour plus de détails.

Le mode start lance un nouveau serveur. Le serveur est démarré en arrière-plan, et son entrée standard est attachée à /dev/null (ou nul sur Windows). Sur les systèmes de type Unix, par défaut, la sortie standard et l'erreur standard du serveur sont envoyées à la sortie standard de pg_ctl (pas à l'erreur standard). La sortie standard de pg_ctl doit alors être redirigée vers un fichier ou dirigée vers un autre processus tel qu'un programme de rotation des journaux comme rotatelogs ; sinon postgres écrira sa sortie sur le terminal de contrôle (depuis l'arrière-plan) et ne quittera pas le groupe de processus du shell. Sur Windows, par défaut, la sortie standard et l'erreur standard du serveur sont envoyées au terminal. Ces comportements par défaut peuvent être modifiés en utilisant -l pour ajouter la sortie du serveur à un fichier journal. L'utilisation de -l ou de la redirection de sortie est recommandée.

Le mode stop arrête le serveur qui s'exécute dans le répertoire de données spécifié. Trois méthodes d'arrêt différentes peuvent être sélectionnées avec l'option -m. Le mode « Smart » interdit les nouvelles connexions, puis attend que tous les clients existants se déconnectent. Si le serveur est en mode hot standby, la récupération et la réplication en continu seront terminées une fois que tous les clients se seront déconnectés. Le mode « Fast » (par défaut) n'attend pas que les clients se déconnectent. Toutes les transactions actives sont annulées et les clients sont déconnectés de force, puis le serveur est arrêté. Le mode « Immediate » interrompra immédiatement tous les processus du serveur, sans arrêt propre. Ce choix entraînera un cycle de récupération après incident lors du prochain démarrage du serveur.

Le mode restart exécute effectivement un arrêt suivi d'un démarrage. Cela permet de modifier les options de ligne de commande de postgres, ou de modifier les options de fichiers de configuration qui ne peuvent pas être modifiées sans redémarrer le serveur. Si des chemins relatifs ont été utilisés sur la ligne de commande lors du démarrage du serveur, restart pourrait échouer si pg_ctl n'est pas exécuté dans le même répertoire courant qu'il a été utilisé lors du démarrage du serveur.

Le mode reload envoie simplement un signal SIGHUP au processus serveur postgres, lui faisant relire ses fichiers de configuration (postgresql.conf, pg_hba.conf, etc.). Cela permet de modifier les options des fichiers de configuration qui ne nécessitent pas un redémarrage complet du serveur pour prendre effet.

Le mode status vérifie si un serveur est en cours d'exécution dans le répertoire de données spécifié. Si c'est le cas, le PID du serveur et les options de ligne de commande utilisées pour l'invoquer sont affichés. Si le serveur ne fonctionne pas, pg_ctl retourne un code de sortie de 3. Si un répertoire de données accessible n'est pas spécifié, pg_ctl retourne un code de sortie de 4.

Le mode promote commande au serveur standby en cours d'exécution dans le répertoire de données spécifié de terminer le mode standby et de commencer les opérations en lecture/écriture.

Le mode logrotate fait tourner le fichier journal du serveur. Pour plus de détails sur la façon d'utiliser ce mode avec des outils externes de rotation de journaux, voir la section 24.3.

Le mode kill envoie un signal à un processus spécifié. Ceci est principalement utile sur Microsoft Windows qui n'a pas de commande kill intégrée. Utilisez --help pour voir la liste des noms de signaux pris en charge.

Le mode register enregistre le serveur PostgreSQL en tant que service système sur Microsoft Windows. L'option -S permet de sélectionner le type de démarrage du service, soit « auto » (démarre le service automatiquement au démarrage du système) soit « demand » (démarre le service à la demande).

Le mode unregister désenregistre un service système sur Microsoft Windows. Cela annule les effets de la commande register.

OPTIONS

-c
--core-files

Tente de permettre aux plantages du serveur de produire des fichiers core, sur les plates-formes où cela est possible, en levant toute limite de ressource souple imposée aux fichiers core. Ceci est utile pour déboguer ou diagnostiquer des problèmes en permettant d'obtenir une trace de pile d'un processus serveur défaillant.

-D datadir
--pgdata=datadir

Spécifie l'emplacement dans le système de fichiers des fichiers de configuration de la base de données. Si cette option est omise, la variable d'environnement PGDATA est utilisée.

-l nomfichier
--log=nomfichier

Ajoute la sortie du journal du serveur à nomfichier. Si le fichier n'existe pas, il est créé. L'utilisateur umask est défini sur 077, donc l'accès au fichier journal est interdit aux autres utilisateurs par défaut.

-m mode
--mode=mode

Spécifie le mode d'arrêt. mode peut être smart, fast, ou immediate, ou la première lettre de l'un de ces trois. Si cette option est omise, fast est la valeur par défaut.

-o options
--options=options

Spécifie les options à passer directement à la commande postgres. -o peut être spécifié plusieurs fois, toutes les options données étant transmises.

Les options doivent généralement être entourées de guillemets simples ou doubles pour s'assurer qu'elles sont transmises en groupe.

-o options-initdb
--options=options-initdb

Spécifie les options à passer directement à la commande initdb. -o peut être spécifié plusieurs fois, toutes les options données étant transmises.

Les options-initdb doivent généralement être entourées de guillemets simples ou doubles pour s'assurer qu'elles sont transmises en groupe.

-p chemin

Spécifie l'emplacement de l'exécutable postgres. Par défaut, l'exécutable postgres est pris du même répertoire que pg_ctl, ou à défaut, du répertoire d'installation codé en dur. Il n'est pas nécessaire d'utiliser cette option sauf si vous faites quelque chose d'inhabituel et que vous obtenez des err
ors que l'exécutable postgres n'a pas été trouvé.

En mode init, cette option spécifie de manière analogue l'emplacement de l'exécutable initdb.

-s
--silent

N'imprime que les erreurs, aucun message informatif.

-t secondes
--timeout=secondes

Spécifie le nombre maximum de secondes à attendre lors de l'attente de la complétion d'une opération (voir l'option -w). Par défaut, la valeur de la variable d'environnement PGCTLTIMEOUT ou, si elle n'est pas définie, 60 secondes.

-V
--version

Imprime la version de pg_ctl et quitte.

-w
--wait

Attend que l'opération soit terminée. Ceci est pris en charge pour les modes start, stop, restart, promote et register, et c'est le comportement par défaut pour ces modes.

En attendant, pg_ctl vérifie de manière répétée le fichier PID du serveur, en dormant pendant une courte période entre les vérifications. Le démarrage est considéré comme terminé lorsque le fichier PID indique que le serveur est prêt à accepter des connexions. L'arrêt est considéré comme terminé lorsque le serveur supprime le fichier PID. pg_ctl renvoie un code de sortie basé sur le succès du démarrage ou de l'arrêt.

Si l'opération ne se termine pas dans le délai imparti (voir l'option -t), pg_ctl se termine avec un statut de sortie non nul. Mais notez que l'opération peut continuer en arrière-plan et éventuellement réussir.

-W
--no-wait

N'attend pas que l'opération soit terminée. C'est le contraire de l'option -w.

Si l'attente est désactivée, l'action demandée est déclenchée, mais il n'y a aucun retour d'information sur son succès. Dans ce cas, le fichier journal du serveur ou un système de surveillance externe devrait être utilisé pour vérifier la progression et le succès de l'opération.

Dans les versions antérieures de PostgreSQL, c'était le comportement par défaut, sauf pour le mode stop.

-?
--help

Affiche l'aide sur les arguments de la ligne de commande de pg_ctl et quitte.

Si une option est spécifiée qui est valide, mais non pertinente pour le mode de fonctionnement sélectionné, pg_ctl l'ignore.

Options pour Windows

-e source

Nom de la source d'événements que pg_ctl doit utiliser pour enregistrer dans le journal des événements lorsqu'il s'exécute en tant que service Windows. Par défaut, c'est PostgreSQL. Notez que cela ne contrôle que les messages envoyés par pg_ctl lui-même ; une fois démarré, le serveur utilisera la source d'événements spécifiée par son paramètre event_source. Si le serveur échoue très tôt au démarrage, avant que ce paramètre n'ait été défini, il peut également enregistrer en utilisant le nom de source d'événements par défaut, PostgreSQL.

-N nom_service

Nom du service système à enregistrer. Ce nom sera utilisé comme nom de service et comme nom d'affichage. Par défaut, c'est PostgreSQL.

-P mot_de_passe

Mot de passe de l'utilisateur sous lequel exécuter le service.

-S type_demarrage

Type de démarrage du service système. type_demarrage peut être auto, ou demand, ou la première lettre de l'un de ces deux. Si cette option est omise, auto est la valeur par défaut.

-U nom_utilisateur

Nom d'utilisateur sous lequel exécuter le service. Pour les utilisateurs de domaine, utilisez le format DOMAINE\nom_utilisateur.

ENVIRONNEMENT

PGCTLTIMEOUT

Limite par défaut du nombre de secondes à attendre lors de l'attente de la complétion du démarrage ou de l'arrêt. Si elle n'est pas définie, la valeur par défaut est de 60 secondes.

PGDATA

Emplacement par défaut du répertoire de données.

La plupart des modes de pg_ctl nécessitent de connaître l'emplacement du répertoire de données ; par conséquent, l'option -D est requise à moins que PGDATA ne soit défini.

Pour des variables supplémentaires qui affectent le serveur, voir postgres(1).

FICHIERS

postmaster.pid

pg_ctl examine ce fichier dans le répertoire de données pour déterminer si le serveur est actuellement en cours d'exécution.

postmaster.opts

Si ce fichier existe dans le répertoire de données, pg_ctl (en mode restart) transmettra le contenu du fichier comme options à postgres, sauf si elles sont remplacées par l'option -o. Le contenu de ce fichier est également affiché en mode status.

EXEMPLES

Démarrage du Serveur

Pour démarrer le serveur, en attendant qu'il accepte les connexions :

$ pg_ctl start

Pour démarrer le serveur en utilisant le port 5433, et en l'exécutant sans fsync, utilisez :

$ pg_ctl -o "-F -p 5433" start

Arrêt du Serveur

Pour arrêter le serveur, utilisez :

$ pg_ctl stop

L'option -m permet de contrôler *comment* le serveur s'arrête :

$ pg_ctl stop -m smart

Redémarrage du Serveur

Redémarrer le serveur est presque équivalent à arrêter le serveur et à le redémarrer, sauf que par défaut, pg_ctl enregistre et réutilise les options de ligne de commande qui ont été passées à l'instance précédente en cours d'exécution. Pour redémarrer le serveur en utilisant les mêmes options qu'auparavant, utilisez :

$ pg_ctl restart

Mais si -o est spécifié, cela remplace toutes les options précédentes. Pour redémarrer en utilisant le port 5433, en désactivant fsync lors du redémarrage :

$ pg_ctl -o "-F -p 5433" restart

Affichage du Statut du Serveur

Voici un exemple de sortie de statut de pg_ctl :

$ pg_ctl status
pg_ctl: server is running (PID: 13718)
/usr/local/pgsql/bin/postgres "-D" "/usr/local/pgsql/data" "-p" "5433" "-B" "128"

La deuxième ligne est la commande qui serait appelée en mode redémarrage.
