PGREP(1) Manuel des commandes générales PGREP(1)

NOM

pgrep, pkill, pidwait — rechercher, signaler ou attendre des processus en fonction du nom et d'autres attributs

SYNTAXE

pgrep [option ...] motif

pkill [option ...] motif

pidwait [option ...] motif

DESCRIPTION

pgrep parcourt les processus en cours d'exécution et liste les identifiants de processus qui correspondent aux critères de sélection sur la sortie standard. Tous les critères doivent correspondre. Par exemple,

$ pgrep -u root sshd

ne listera que les processus dont le nom inclut sshd ET qui sont détenus par root. D'autre part,

$ pgrep -u root,daemon

listera les processus détenus par root OU daemon.

pkill enverra le signal spécifié (par défaut SIGTERM) à chaque processus au lieu de les lister sur la sortie standard.

pidwait attendra chaque processus au lieu de les lister sur la sortie standard.

OPTIONS

-signal
--signal signal
Définit le signal à envoyer à chaque processus correspondant. Le nom numérique ou symbolique du signal peut être utilisé. En mode pgrep ou pidwait, seule l'option longue peut être utilisée et elle n'a aucun effet sauf si elle est utilisée conjointement avec --require-handler pour filtrer les processus ayant un gestionnaire de signal dans l'espace utilisateur pour un signal particulier.
-c, --count
Supprime la sortie normale ; à la place, affiche un décompte des processus correspondants. Lorsque le compte ne correspond à rien, par exemple renvoie zéro, la commande renverra une valeur non nulle. Notez que pour pkill et pidwait, le compte est le nombre de processus correspondants, et non les processus qui ont été signalés ou attendus avec succès.
-d, --delimiter délimiteur
Définit la chaîne utilisée pour délimiter chaque identifiant de processus dans la sortie (par défaut, un saut de ligne). (pgrep uniquement.)
-e, --echo
Affiche le nom et le PID du processus en cours de suppression. (pkill uniquement.)
-f, --full
Le motif est normalement comparé uniquement au nom du processus. Lorsque -f est défini, la ligne de commande complète est utilisée.
-g, --pgroup pgrp,...
Ne faire correspondre que les processus des groupes de processus spécifiés. Le groupe de processus 0 est traduit en son propre groupe de processus pour pgrep, pkill ou pidwait.
-G, --group gid,...
Ne faire correspondre que les processus dont l'identifiant de groupe réel est spécifié. La valeur numérique ou symbolique peut être utilisée.
-i, --ignore-case
Faire correspondre les processus sans tenir compte de la casse.
-l, --list-name
Lister le nom du processus ainsi que l'identifiant du processus. (pgrep uniquement.)
-a, --list-full
Lister la ligne de commande complète ainsi que l'identifiant du processus. (pgrep uniquement.)
-n, --newest
Sélectionner uniquement le plus récent (démarré le plus récemment) des processus correspondants.
-o, --oldest
Sélectionner uniquement le plus ancien (démarré le moins récemment) des processus correspondants.
-O, --older secs
Sélectionner les processus plus anciens que secs.
-P, --parent ppid,...
Ne faire correspondre que les processus dont l'identifiant de processus parent est spécifié.
-s, --session sid,...
Ne faire correspondre que les processus dont l'identifiant de session de processus est spécifié. L'identifiant de session 0 est traduit en son propre identifiant de session pour pgrep, pkill ou pidwait.
-t, --terminal term,...
Ne faire correspondre que les processus dont le terminal de contrôle est spécifié. Le nom du terminal doit être spécifié sans le préfixe "/dev/".
-u, --euid euid,...
Ne faire correspondre que les processus dont l'identifiant d'utilisateur effectif est spécifié. La valeur numérique ou symbolique peut être utilisée.
-U, --uid uid,...
Ne faire correspondre que les processus dont l'identifiant d'utilisateur réel est spécifié. La valeur numérique ou symbolique peut être utilisée.
-v, --inverse
Inverse la correspondance. Cette option est généralement utilisée dans le contexte de pgrep ou pidwait. Dans le contexte de pkill, l'option courte est désactivée pour éviter une utilisation accidentelle.
-w, --lightweight
Affiche tous les identifiants de thread au lieu des identifiants de processus dans le contexte de pgrep ou pidwait. Dans le contexte de pkill, cette option est désactivée.
-x, --exact
Ne faire correspondre que les processus dont les noms (ou les lignes de commande si -f est spécifié) correspondent exactement au motif.
-F, --pidfile fichier
Lit les PID depuis le fichier. Cette option est plus utile pour pkill ou pidwait que pour pgrep. Le nom de fichier "-" peut être utilisé pour lire depuis STDIN.
-L, --logpidfile
Échoue si le fichier PID (voir -F) n'est pas verrouillé.
-r, --runstates D,R,S,Z,...
Ne faire correspondre que les processus dont l'état correspond.
-A, --ignore-ancestors
Ignore tous les ancêtres de pgrep, pkill ou pidwait. Par exemple, cela peut être utile lors de l'élévation avec sudo ou des outils similaires.
-H, --require-handler
Ne faire correspondre que les processus ayant un gestionnaire de signal dans l'espace utilisateur pour le signal à envoyer.
--cgroup nom,...
Correspondance sur le nom du groupe de contrôle (cgroup) v2 fourni. Voir cgroups(8)
--env nom[=valeur],...
Correspondance avec les processus qui ont ces variables d'environnement. Si le paramètre =valeur n'est pas défini, seul le nom de la variable est mis en correspondance.
--ns pid
Fait correspondre les processus qui appartiennent aux mêmes espaces de noms. Requis pour s'exécuter en tant que root pour faire correspondre les processus d'autres utilisateurs. Voir --nslist pour savoir comment limiter les espaces de noms à comparer.
--nslist nom,...
Ne faire correspondre que les espaces de noms fournis. Espaces de noms disponibles : ipc, mnt, net, pid, user, uts.
-q, --queue valeur
Utilise sigqueue(3) plutôt que kill(2) et l'argument valeur est utilisé pour spécifier un entier à envoyer avec le signal. Si le processus récepteur a installé un gestionnaire pour ce signal en utilisant le drapeau SA_SIGINFO pour sigaction(2), il peut obtenir ces données via le champ si_value de la structure siginfo_t.
-V, --version
Affiche les informations de version et quitte.
-h, --help
Affiche l'aide et quitte.

MOTIF

Le motif est une expression régulière étendue, par défaut, utilisée pour correspondre aux processus.

EXEMPLES

Rechercher les PIDs de tous les processus nommés "kswapd":
$ pgrep kswapd
Envoyer le signal SIGKILL à tous les processus nommés "badapp":
$ pkill badapp
Envoyer le signal SIGHUP à tous les processus qui ont "sshd" dans leur ligne de commande complète:
$ pkill -HUP -f "sshd"
Lister les PIDs et les noms des processus appartenant à l'utilisateur "apache" qui sont associés au terminal "pts/0":
$ pgrep -l -u apache -t pts/0
Envoyer SIGTERM aux processus les plus anciens des groupes 123 et 456:
$ pkill -o -g 123,456

DIAGNOSTICS

Les codes de retour sont 0 si au moins un processus correspondant a été trouvé, 1 s'il n'y a pas eu de correspondance, et supérieur à 1 en cas d'erreur. Si pkill ou pidwait échouent à envoyer un signal ou à attendre un processus, ils renverront un code de sortie supérieur à 1.

OPÉRANDES

motif
Spécifie une expression régulière étendue pour faire correspondre les noms de processus ou les lignes de commande.

EXEMPLES

Exemple 1 : Trouver l'ID de processus du démon named :

$ pgrep -u root named

Exemple 2 : Faire relire son fichier de configuration à syslog :

$ pkill -HUP syslogd

Exemple 3 : Donner des informations détaillées sur tous les processus xterm :

$ ps -fp $(pgrep -d, -x xterm)

Exemple 4 : Faire exécuter les processus chrome avec une priorité plus faible :

$ renice +4 $(pgrep chrome)

Exemple 5 : Attendre la fin d'un processus avec un PID connu :

$ echo ${PID} | pidwait -F -

STATUT DE SORTIE

0
Un ou plusieurs processus correspondent aux critères. Pour pkill et pidwait, un ou plusieurs processus doivent également avoir été signalés ou attendus avec succès.
1
Aucun processus ne correspond ou aucun d'entre eux n'a pu être signalé.
2
Erreur de syntaxe dans la ligne de commande.
3
Erreur fatale : manque de mémoire, etc.

NOTES

Le nom de processus utilisé pour la correspondance est limité aux 15 caractères présents dans la sortie de /proc/pid/stat. Utilisez l'option -f pour faire correspondre la ligne de commande complète, /proc/pid/cmdline. Les threads peuvent ne pas avoir le même nom de processus que le processus parent, mais ils auront la même ligne de commande.

Le processus pgrep, pkill ou pidwait en cours d'exécution ne se signalera jamais lui-même comme une correspondance.

L'option -O --older échouera silencieusement si /proc est monté avec l'option subset=pid.

BOGUES

Les options -n, -o et -v ne peuvent pas être combinées. Faites-moi savoir si vous avez besoin de le faire.

Les processus "zombies" (defunct) sont signalés.

pidwait nécessite l'appel système pidfd_open(2) qui est apparu pour la première fois sous Linux 5.3.
