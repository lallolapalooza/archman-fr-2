PYTHON(1) Manuel des commandes générales PYTHON(1)

NOM

python - langage de programmation interprété, interactif et orienté objet

SYNTAXE

python [ -B ] [ -b ] [ -d ] [ -E ] [ -h ] [ -i ] [ -I ]
[ -m nom-module ] [ -q ] [ -R ] [ -O ] [ -OO ] [ -P ] [ -s ] [ -S ] [ -u ]
[ -v ] [ -V ] [ -W argument ] [ -x ] [ -X option ] [ -? ]
[ --check-hash-based-pycs défaut | toujours | jamais ]
[ --help ] [ --help-env ] [ --help-xoptions ] [ --help-all ]
[ -c commande | script | - ] [ arguments ]

DESCRIPTION

Python est un langage de programmation interprété, interactif et orienté objet qui combine une puissance remarquable avec une syntaxe très claire. Pour une introduction à la programmation en Python, consultez le Tutoriel Python. La Référence de la Bibliothèque Python documente les types, constantes, fonctions et modules intégrés et standards. Enfin, le Manuel de Référence Python décrit la syntaxe et la sémantique du langage de base avec (peut-être trop de) détails. (Ces documents peuvent être trouvés via les RESSOURCES INTERNET ci-dessous ; ils peuvent également être installés sur votre système.)

La puissance de base de Python peut être étendue avec vos propres modules écrits en C ou C++. Sur la plupart des systèmes, de tels modules peuvent être chargés dynamiquement. Python est également adaptable en tant que langage d'extension pour des applications existantes. Consultez la documentation interne pour des indices.

La documentation des modules et paquets Python installés peut être affichée en exécutant le programme pydoc.

OPTIONS DE LIGNE DE COMMANDE

-B
Ne pas écrire de fichiers .pyc lors de l'importation. Voir aussi PYTHONDONTWRITEBYTECODE.
-b
Émettre des avertissements lors de la conversion de chaînes de bytes (bytes ou bytearray) en chaînes de caractères (str). (-bb : émettre des erreurs)
-c commande
Spécifie la commande à exécuter (voir la section suivante). Ceci termine la liste des options (les options suivantes sont passées en arguments à la commande).
--check-hash-based-pycs mode
Configure comment Python évalue la validité des fichiers .pyc basés sur le hash.
-d
Activer les informations de débogage de l'analyseur syntaxique (pour experts uniquement, dépend des options de compilation).
-E
Ignorer les variables d'environnement telles que PYTHONPATH et PYTHONHOME qui modifient le comportement de l'interpréteur.
-h , -? , --help
Affiche l'aide pour l'exécutable de l'interpréteur et quitte.
--help-env
Affiche l'aide sur les variables d'environnement spécifiques à Python et quitte.
--help-xoptions
Affiche l'aide sur les options -X spécifiques à l'implémentation et quitte.
--help-all
Affiche toutes les informations d'utilisation et quitte.
-i
Lorsqu'un script est passé comme premier argument ou que l'option -c est utilisée, passer en mode interactif après l'exécution du script ou de la commande. Ne lit pas le fichier $PYTHONSTARTUP. Ceci peut être utile pour inspecter les variables globales ou une trace de pile lorsqu'un script lève une exception.
-I
Exécute Python en mode isolé. Ceci implique également -E, -P et -s. En mode isolé, sys.path ne contient ni le répertoire du script ni le répertoire site-packages de l'utilisateur. Toutes les variables d'environnement PYTHON\* sont également ignorées. D'autres restrictions peuvent être imposées pour empêcher l'utilisateur d'injecter du code malveillant.
-m nom-module
Recherche dans sys.path le module nommé et exécute le fichier .py correspondant comme un script. Ceci termine la liste des options (les options suivantes sont passées en arguments au module).
-O
Supprime les instructions assert et tout code conditionnel à la valeur de __debug__ ; augmente le nom de fichier pour les fichiers compilés (bytecode) en ajoutant .opt-1 avant l'extension .pyc.
-OO
Fait ce que fait -O et supprime également les docstrings ; modifie le nom de fichier pour les fichiers compilés (bytecode) en ajoutant .opt-2 avant l'extension .pyc.
-P
Ne pas préfixer automatiquement un chemin potentiellement non sécurisé à sys.path tel que le répertoire courant, le répertoire du script ou une chaîne vide. Voir aussi la variable d'environnement PYTHONSAFEPATH.
-q
Ne pas afficher les messages de version et de copyright. Ces messages sont également supprimés en mode non interactif.
-R
Activer la randomisation des hashs. Cette option n'a d'effet que si la variable d'environnement PYTHONHASHSEED est définie à 0, car la randomisation des hashs est activée par défaut.
-s
Ne pas ajouter le répertoire du site utilisateur à sys.path.
-S
Désactiver l'importation du module site et les manipulations dépendantes du site de sys.path qui en découlent. Désactive également ces manipulations si site est explicitement importé plus tard.
-u
Forcer les flux stdout et stderr à être non mis en mémoire tampon. Cette option n'a aucun effet sur le flux stdin.
-v
Afficher un message chaque fois qu'un module est initialisé, montrant l'endroit (nom de fichier ou module intégré) d'où il est chargé. Lorsqu'elle est utilisée deux fois, affiche un message pour chaque fichier vérifié lors de la recherche d'un module. Fournit également des informations sur le nettoyage des modules à la sortie.
-V , --version
Affiche le numéro de version de Python de l'exécutable et quitte. Lorsqu'elle est utilisée deux fois, affiche plus d'informations sur la compilation.
-W argument
Contrôle des avertissements. Le système d'avertissement de Python, par défaut, imprime les messages d'avertissement sur sys.stderr.

Les paramètres les plus simples appliquent une action particulière sans condition à tous les avertissements émis par un processus (même ceux qui sont autrement ignorés par défaut) :


-Wdefault # Avertir une fois par emplacement d'appel
-Werror # Convertir en exceptions
-Walways # Avertir à chaque fois
-Wall # Identique à -Walways
-Wmodule # Avertir une fois par module appelant
-Wonce # Avertir une fois par processus Python
-Wignore # Ne jamais avertir

Les noms d'action peuvent être abrégés au besoin et l'interpréteur les résoudra en nom d'action approprié. Par exemple, -Wi est identique à -Wignore.

La forme complète de l'argument est : action:message:catégorie:module:numéro_ligne

Les champs vides correspondent à toutes les valeurs ; les champs vides finaux peuvent être omis. Par exemple, -W ignore::DeprecationWarning ignore tous les avertissements DeprecationWarning.

Le champ action est tel qu'expliqué ci-dessus mais ne s'applique qu'aux avertissements qui correspondent aux champs restants.

Le champ message doit correspondre à l'ensemble du message d'avertissement imprimé ; cette correspondance n'est pas sensible à la casse.

Le champ catégorie correspond à la catégorie d'avertissement (par exemple, "DeprecationWarning"). Il doit s'agir d'un nom de classe ; la correspondance teste si la catégorie d'avertissement réelle du message est une sous-classe de la catégorie d'avertissement spécifiée.

Le champ module correspond au nom du module (entièrement qualifié) ; cette correspondance n'est pas sensible à la casse.

Le champ numéro_ligne correspond au numéro de ligne, où zéro correspond à tous les numéros de ligne et est donc équivalent à un numéro de ligne omis.

Lorsque plusieurs options correspondent à un avertissement, l'action de la dernière option correspondante est effectuée. Les options -W invalides sont ignorées (bien qu'un message d'avertissement soit imprimé concernant les options invalides lorsque le premier avertissement est émis).

Les avertissements peuvent également être contrôlés à l'aide de la variable d'environnement PYTHONWARNINGS et depuis un programme Python à l'aide du module warnings. Par exemple, la fonction warnings.filterwarnings() peut être utilisée pour utiliser une expression régulière sur le message d'avertissement.

-X option
Définit une option spécifique à l'implémentation. Les options suivantes sont disponibles :


-X cpu_count=N : remplace la valeur de retour de os.cpu_count() ;
-X cpu_count=default annule le remplacement ; également PYTHON_CPU_COUNT


-X dev : active le « mode développement » de CPython, introduisant des
vérifications d'exécution supplémentaires qui sont trop coûteuses pour être activées par défaut. Il
ne sera pas plus verbeux que le défaut si le code est correct : de nouveaux
avertissements ne sont émis que lorsqu'un problème est détecté. Effet du
mode développeur :
* Ajoute un filtre d'avertissement par défaut, comme -W default
* Installe des hooks de débogage sur les allocateurs de mémoire : voir la
fonction C PyMem_SetupDebugHooks()
* Active le module faulthandler pour afficher la trace Python en cas de
plantage
* Active le mode de débogage asyncio
* Définit l'attribut dev_mode de sys.flags sur True
* Le destructeur io.IOBase enregistre les exceptions close()


-X importtime : affiche le temps pris par chaque import. Il affiche le nom du module,
le temps cumulé (y compris les imports imbriqués) et le temps propre (hors imports
imbriqués). Notez que sa sortie peut être défectueuse dans les applications
multithreadées. L'utilisation typique est
python3 -X importtime -c 'import asyncio'


-X faulthandler : active faulthandler


-X frozen_modules=[on|off] : indique si les modules gelés
doivent être utilisés ou non.
La valeur par défaut est « on » (ou « off » si vous exécutez une compilation locale).


-X gil=[0|1] : active (1) ou désactive (0) le GIL ; également
PYTHON_GIL
Disponible uniquement dans les compilations configurées avec --disable-gil.


-X int_max_str_digits=nombre : limite la taille des conversions int<->str.
Cela permet d'éviter les attaques par déni de service lors de l'analyse de données non fiables.
La valeur par défaut est sys.int_info.default_max_str_digits. 0 désactive.


-X no_debug_ranges : désactive l'inclusion des tables mappant les informations de
localisation supplémentaires (ligne de fin, décalage de colonne de début et décalage de colonne
de fin) à chaque instruction dans les objets code. Ceci est utile lorsque
des objets code et des fichiers pyc plus petits sont souhaités, ainsi que pour supprimer
les indicateurs de localisation visuels supplémentaires lorsque l'interpréteur affiche
les traces d'erreurs.


-X perf : prend en charge le profileur « perf » de Linux ; également PYTHONPERFSUPPORT=1


-X perf_jit : prend en charge le profileur « perf » de Linux avec prise en charge DWARF ;
également PYTHON_PERF_JIT_SUPPORT=1


-X presite=MOD : importe ce module avant site ; également PYTHON_PRESITE
Cela ne fonctionne que sur les builds de débogage.


-X pycache_prefix=CHEMIN : active l'écriture de fichiers .pyc dans un arbre parallèle
raciné dans le répertoire donné au lieu de l'arbre de code.


-X showrefcount : affiche le compte de références total et le nombre de blocs de mémoire utilisés
lorsque le programme se termine ou après chaque instruction dans l'interpréteur interactif. Cela ne fonctionne que sur les builds de débogage


-X tracemalloc : commence le traçage des allocations mémoire Python à l'aide du
module tracemalloc. Par défaut, seule la trame la plus récente est stockée dans une trace. Utilisez -X tracemalloc=NFRAME pour commencer le traçage avec une limite de NFRAME trames.


-X utf8 : active le mode UTF-8 pour les interfaces du système d'exploitation,
remplaçant le mode par défaut sensible à la locale. -X utf8=0 désactive explicitement
le mode UTF-8 (même lorsqu'il s'activerait automatiquement). Voir PYTHONUTF8 pour plus de détails.


-X warn_default_encoding : active EncodingWarning opt-in pour 'encoding=None'

-x
Ignore la première ligne de la source. Ceci est destiné uniquement à un hack spécifique à DOS. Attention : les numéros de ligne dans les messages d'erreur seront incorrects d'une unité !

INTERFACE DE L'INTERPRÉTEUR

L'interface de l'interpréteur ressemble à celle du shell UNIX : lorsqu'il est appelé avec l'entrée standard connectée à un périphérique tty, il invite l'utilisateur à entrer des commandes et les exécute jusqu'à ce qu'un EOF soit lu ; lorsqu'il est appelé avec un nom de fichier comme argument ou avec un fichier comme entrée standard, il lit et exécute un script à partir de ce fichier ; lorsqu'il est appelé avec -c commande, il exécute les instructions Python données comme commande. Ici, commande peut contenir plusieurs instructions séparées par des sauts de ligne. L'espacement initial est significatif en Python ! En mode non interactif, toute l'entrée est analysée avant d'être exécutée.

Si disponible, le nom du script et les arguments supplémentaires qui suivent sont passés au script dans la variable Python sys.argv, qui est une liste de chaînes de caractères (vous devez d'abord importer sys pour y accéder). Si aucun nom de script n'est donné, sys.argv[0] est une chaîne vide ; si -c est utilisé, sys.argv[0] contient la chaîne '-c'. Notez que les options interprétées par l'interpréteur Python lui-même ne sont pas placées dans sys.argv.

En mode interactif, l'invite principale est `>>>'; l'invite secondaire (qui apparaît lorsqu'une commande n'est pas complète) est `...'. Les invites peuvent être modifiées par affectation à sys.ps1 ou sys.ps2. L'interpréteur se quitte lorsqu'il lit un EOF à une invite. Lorsqu'une exception non gérée se produit, une trace de la pile est affichée et le contrôle retourne à l'invite principale ; en mode non interactif, l'interpréteur se termine après l'affichage de la trace de la pile. Le signal d'interruption lève l'exception KeyboardInterrupt ; les autres signaux UNIX ne sont pas interceptés (sauf que SIGPIPE est parfois ignoré, au profit de l'exception IOError). Les messages d'erreur sont écrits sur stderr.

FICHIERS ET RÉPERTOIRES

Ceux-ci sont sujets à des différences selon les conventions d'installation locales ; ${prefix} et ${exec_prefix} dépendent de l'installation et doivent être interprétés comme pour les logiciels GNU ; ils peuvent être identiques. La valeur par défaut pour les deux est /usr/local.

${exec_prefix}/bin/python
Emplacement recommandé de l'interpréteur.

${prefix}/lib/python<version>
${exec_prefix}/lib/python<version>

Emplacements recommandés des répertoires contenant les modules standard.

${prefix}/include/python<version>
${exec_prefix}/include/python<version>

Emplacements recommandés des répertoires contenant les fichiers d'en-tête nécessaires au développement d'extensions Python et à l'intégration de l'interpréteur.

VARIABLES D'ENVIRONNEMENT

PYTHONASYNCIODEBUG
Si cette variable d'environnement est définie sur une chaîne non vide, active le mode de débogage du module asyncio.
PYTHON_BASIC_REPL
Si cette variable est définie sur n'importe quelle valeur, l'interpréteur ne tentera pas de charger le REPL basé sur Python qui nécessite curses et readline, et utilisera à la place le REPL traditionnel basé sur l'analyseur.
PYTHONBREAKPOINT
Si cette variable d'environnement est définie sur 0, elle désactive le débogueur par défaut. Elle peut être définie sur l'appelable de votre débogueur de choix.
PYTHONCOERCECLOCALE
Si défini sur la valeur 0, oblige l'application en ligne de commande principale de Python à ignorer la conversion des locales C et POSIX héritées basées sur ASCII en une alternative plus capable basée sur UTF-8.
PYTHON_COLORS
Si cette variable est définie sur 1, l'interpréteur colorisera divers types de sorties. La définir sur 0 désactive ce comportement.
PYTHON_CPU_COUNT
Si cette variable est définie sur un entier positif, elle remplace les valeurs de retour de os.cpu_count et os.process_cpu_count.
Voir aussi l'option -X cpu_count.
PYTHONDEBUG
Si elle est définie sur une chaîne non vide, elle est équivalente à spécifier l'option -d. Si elle est définie sur un entier, elle est équivalente à spécifier -d plusieurs fois.
PYTHONEXECUTABLE
Si cette variable d'environnement est définie, sys.argv[0] sera défini sur sa valeur au lieu de la valeur obtenue via l'exécution C. Ne fonctionne que sur Mac OS X.
PYTHONFAULTHANDLER
Si cette variable d'environnement est définie sur une chaîne non vide, faulthandler.enable() est appelée au démarrage : installe un gestionnaire pour les signaux SIGSEGV, SIGFPE, SIGABRT, SIGBUS et SIGILL pour afficher la trace Python.
Ceci est équivalent à l'option -X faulthandler.
PYTHON_FROZEN_MODULES
Si cette variable est définie sur on ou off, elle détermine si or not frozen modules are ignored by the import machinery. A value of on means they get imported and off means they are ignored. The default is on for non-debug builds (the normal case) and off for debug builds.
See also the -X frozen_modules option.
PYTHON_GIL
If this variable is set to 1, the global interpreter lock (GIL) will be forced on. Setting it to 0 forces the GIL off. Only available in builds configured with --disable-gil.
This is equivalent to the -X gil option.
PYTHON_HISTORY
This environment variable can be used to set the location of a history file (on Unix, it is ~/.python_history by default).
PYTHONNODEBUGRANGES
If this variable is set, it disables the inclusion of the tables mapping extra location information (end line, start column offset and end column offset) to every instruction in code objects. This is useful when smaller code objects and pyc files are desired as well as suppressing the extra visual location indicators when the interpreter displays tracebacks.
PYTHONDONTWRITEBYTECODE
If this is set to a non-empty string it is equivalent to specifying the -B option (don't try to write .pyc files).
PYTHONDEVMODE
If this environment variable is set to a non-empty string, enable Python's "development mode", introducing additional runtime checks that are too expensive to be enabled by default.
This is equivalent to the -X dev option.
PYTHONHASHSEED
If this variable is set to "random", a random value is used to seed the hashes of str and bytes objects.

If PYTHONHASHSEED is set to an integer value, it is used as a fixed seed for generating the hash() of the types covered by the hash randomization. Its purpose is to allow repeatable hashing, such as for selftests for the interpreter itself, or to allow a cluster of python processes to share hash values.

The integer must be a decimal number in the range [0,4294967295]. Specifying the value 0 will disable hash randomization.

PYTHONHOME
Change the location of the standard Python libraries. By default, the libraries are searched in ${prefix}/lib/python<version> and ${exec_prefix}/lib/python<version>, where ${prefix} and ${exec_prefix} are installation-dependent directories, both defaulting to /usr/local. When $PYTHONHOME is set to a single directory, its value replaces both ${prefix} and ${exec_prefix}. To specify different values for these, set $PYTHONHOME to ${prefix}:${exec_prefix}.
PYTHONINSPECT
If this is set to a non-empty string it is equivalent to specifying the -i option.
PYTHONINTMAXSTRDIGITS
Limit the maximum digit characters in an int value when converting from a string and when converting an int back to a str. A value of 0 disables the limit. Conversions to or from bases 2, 4, 8, 16, and 32 are never limited.
This is equivalent to the -X int_max_str_digits=NUMBER option.
PYTHONIOENCODING
If this is set before running the interpreter, it overrides the encoding used for stdin/stdout/stderr, in the syntax encodingname:errorhandler The errorhandler part is optional and has the same meaning as in str.encode. For stderr, the errorhandler part is ignored; the handler will always be ´backslashreplace´.
PYTHONMALLOC
Set the Python memory allocators and/or install debug hooks. The available memory allocators are malloc and pymalloc. The available debug hooks are debug, malloc_debug, and pymalloc_debug.
When Python is compiled in debug mode, the default is pymalloc_debug and the debug hooks are automatically used. Otherwise, the default is pymalloc.
PYTHONMALLOCSTATS
If set to a non-empty string, Python will print statistics of the pymalloc memory allocator every time a new pymalloc object arena is created, and on shutdown.
This variable is ignored if the $PYTHONMALLOC environment variable is used to force the malloc(3) allocator of the C library, or if Python is configured without pymalloc support.
PYTHONNOUSERSITE
If this is set to a non-empty string it is equivalent to specifying the -s option (Don't add the user site directory to sys.path).
PYTHONOPTIMIZE
If this is set to a non-empty string it is equivalent to specifying the -O option. If set to an integer, it is equivalent to specifying -O multiple times.
PYTHONPATH
Augments the default search path for module files. The format is the same as the shell's $PATH: one or more directory pathnames separated by colons. Non-existent directories are silently ignored. The default search path is installation dependent, but generally begins with ${prefix}/lib/python<version> (see PYTHONHOME above). The default search path is always appended to $PYTHONPATH. If a script argument is given, the directory containing the script is inserted in the path in front of $PYTHONPATH. The search path can be manipulated from within a Python program as the variable sys.path.
PYTHON_PERF_JIT_SUPPORT
If this variable is set to a nonzero value, it enables support for the Linux perf profiler so Python calls can be detected by it using DWARF information. Setting to 0 disables.
See also the -X perf_jit option.
PYTHONPERFSUPPORT
If this variable is set to a nonzero value, it enables support for the Linux perf profiler so Python calls can be detected by it. Setting to 0 disables.
See also the -X perf option.
PYTHONPLATLIBDIR
Override sys.platlibdir.
PYTHONPROFILEIMPORTTIME
If this environment variable is set to a non-empty string, Python will show how long each import takes. This is exactly equivalent to setting -X importtime on the command line.
PYTHONPYCACHEPREFIX
If this is set, Python will write .pyc files in a mirror directory tree at this path, instead of in __pycache__ directories within the source tree.
This is equivalent to specifying the -X pycache_prefix=PATH option.
PYTHONSAFEPATH
If this is set to a non-empty string, don't automatically prepend a potentially unsafe path to sys.path such as the current directory, the script's directory or an empty string. See also the -P option.
PYTHONSTARTUP
If this is the name of a readable file, the Python commands in that file are executed before the first prompt is displayed in interactive mode. The file is executed in the same name space where interactive commands are executed so that objects defined or imported in it can be used without qualification in the interactive session. You can also change the prompts sys.ps1 and sys.ps2 in this file.
PYTHONTRACEMALLOC
If this environment variable is set to a non-empty string, start tracing Python memory allocations using the tracemalloc module.
The value of the variable is the maximum number of frames stored in a traceback of a trace. For example, PYTHONTRACEMALLOC=1 stores only the most recent frame.
PYTHONUNBUFFERED
If this is set to a non-empty string it is equivalent to specifying the -u option.
PYTHONUSERBASE
Defines the user base directory, which is used to compute the path of the user site-packages directory and installation paths for python -m pip install --user.
PYTHONUTF8
If set to 1, enable the Python "UTF-8 Mode". Setting to 0 disables.
PYTHONVERBOSE
If this is set to a non-empty string it is equivalent to specifying the -v option. If set to an integer, it is equivalent to specifying -v multiple times.
PYTHONWARNDEFAULTENCODING
If this environment variable is set to a non-empty string, issue a EncodingWarning when the locale-specific default encoding is used.
PYTHONWARNINGS
If this is set to a comma-separated string it is equivalent to specifying the -W option for each separate value.

Variables en mode débogage

La définition de ces variables n'a d'effet que dans une version de débogage de Python, c'est-à-dire si Python a été configuré avec l'option de build --with-pydebug.

PYTHONDUMPREFS
Si cette variable d'environnement est définie, Python déversera les objets et les comptes de références toujours actifs après l'arrêt de l'interpréteur.
PYTHONDUMPREFSFILE
Si définie, Python déversera les objets et

COMPTEURS_DE_REFERENCES_TOUJOURS_ACTIFS_APRÈS

l'arrêt de l'interpréteur dans un fichier sous le chemin donné comme valeur à cette variable d'environnement.

PYTHON_PRESITE
Si cette variable est définie sur un module, ce module sera importé tôt dans le cycle de vie de l'interpréteur, avant que le module site ne soit exécuté, et avant que le module __main__ ne soit créé. Ceci ne fonctionne que sur les builds de débogage.
Ceci est équivalent à l'option -X presite=module.
