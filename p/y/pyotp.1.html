NOM

pyotp - PyOTP

PyOTP est une bibliothèque Python pour générer et vérifier des mots de passe à usage unique. Elle peut être utilisée pour implémenter des méthodes d'authentification à deux facteurs (2FA) ou à facteurs multiples (MFA) dans des applications web et d'autres systèmes qui nécessitent une connexion utilisateur.

  • Assurer la confidentialité du transport en utilisant HTTPS
  • Assurer la confidentialité des secrets HOTP/TOTP en stockant les secrets dans une base de données à accès contrôlé
  • Refuser les attaques par rejeu en rejetant les mots de passe à usage unique qui ont déjà été utilisés par le client (cela nécessite de stocker l'horodatage, l'OTP ou le hachage de l'OTP le plus récemment authentifié dans votre base de données, et de rejeter l'OTP lorsqu'une correspondance est vue)
  • Limiter (limiter le débit) les attaques par force brute contre la fonctionnalité de connexion de votre application (voir RFC 4226, section 7.3)
  • Lors de l'implémentation d'une nouvelle application, envisagez de prendre en charge FIDO U2F/WebAuthn en plus de HOTP/TOTP. U2F utilise la cryptographie asymétrique pour éviter d'utiliser une conception de secret partagé, ce qui renforce votre solution MFA contre les attaques côté serveur. U2F matériel séquestre également le secret client dans un appareil dédié à usage unique, ce qui renforce vos clients contre les attaques côté client. Et en automatisant la portée des identifiants aux identifiants de partie fiable (origines d'application/noms de domaine), U2F ajoute une protection contre les attaques de phishing. Une implémentation de FIDO U2F/WebAuthn est le projet frère de PyOTP, PyWARP.

APERÇU RAPIDE DE L'UTILISATION DES MOTS DE PASSE À USAGE UNIQUE SUR VOTRE TÉLÉPHONE

  • Les OTP impliquent un secret partagé, stocké à la fois sur le téléphone et sur le serveur
  • Les OTP peuvent être générés sur un téléphone sans connexion Internet
  • Les OTP doivent toujours être utilisés comme second facteur d'authentification (si votre téléphone est perdu, votre compte est toujours sécurisé par un mot de passe)
  • Google Authenticator et d'autres applications OTP client vous permettent de stocker plusieurs secrets OTP et de les provisionner à l'aide d'un code QR

INSTALLATION

pip install pyotp

UTILISATION

OTP basés sur le temps

import pyotp
import time
totp = pyotp.TOTP('base32secret3232')
totp.now() # => '492039'
# OTP vérifié pour l'heure actuelle
totp.verify('492039') # => True
time.sleep(30)
totp.verify('492039') # => False

OTP basés sur un compteur

import pyotp
hotp = pyotp.HOTP('base32secret3232')
hotp.at(0) # => '260182'
hotp.at(1) # => '055283'
hotp.at(1401) # => '316439'
# OTP vérifié avec un compteur
hotp.verify('316439', 1401) # => True
hotp.verify('316439', 1402) # => False

Génération d'une clé secrète

Une fonction d'aide est fournie pour générer un secret base32 de 32 caractères, compatible avec Google Authenticator et d'autres applications OTP :

pyotp.random_base32()

Certaines applications souhaitent que la clé secrète soit formatée sous forme de chaîne encodée en hexadécimal :

pyotp.random_hex()  # renvoie un secret de 40 caractères encodé en hexadécimal

Compatible avec Google Authenticator

PyOTP fonctionne avec l'application Google Authenticator pour iPhone et Android, ainsi qu'avec d'autres applications OTP comme Authy. PyOTP inclut la capacité de générer des URI de provisionnement à utiliser avec le scanner de code QR intégré dans ces applications clientes MFA :

L'analyse de ces URL est également prise en charge :

pyotp.parse_uri('otpauth://totp/Secure%20App:alice%40google.com?secret=JBSWY3DPEHPK3PXP&issuer=Secure%20App')
>>> <pyotp.totp.TOTP object at 0xFFFFFFFF>
pyotp.parse_uri('otpauth://hotp/Secure%20App:alice%40google.com?secret=JBSWY3DPEHPK3PXP&issuer=Secure%20App&counter=0'
>>> <pyotp.totp.HOTP object at 0xFFFFFFFF>

DESCRIPTION

These are used to generate one-time passwords.

These algorithms are typically used in multi-factor authentication systems. They require a shared secret between the server and the client, and some form of counter or time-based value.

This library is built to be used with Google Authenticator, but can be used with any other compatible OTP client.

HOTP

Generate and verify HOTP codes. HOTP is an event-based algorithm. The OTP is based on a counter value. This library supports reading and writing the counter value to a file.

TOTP

Generate and verify TOTP codes. TOTP is a time-based algorithm. The OTP is based on the current Unix time, divided by a specified interval. This is the most common algorithm used by authenticator apps like Google Authenticator.

Steam TOTP

The Steam client uses a custom implementation of TOTP which is compatible with RFC6238, but with a few modifications:

  • It uses a 5-digit code instead of 6 digits.
  • The time interval is 30 seconds (same as standard TOTP), but the time is offset by 10 seconds.

Provisioning URI

This library supports generating provisioning URIs, which can be used to provision OTP clients like Google Authenticator. These URIs can be encoded into QR codes for easy setup.

Utils

Utility functions for building provisioning URIs and performing constant-time string comparisons.
