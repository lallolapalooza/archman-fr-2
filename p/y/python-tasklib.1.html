TASKLIB(1) tasklib TASKLIB(1)

NOM

tasklib - Documentation de tasklib

Prend en charge Python 3.5 et supérieur, avec taskwarrior 2.4.x et supérieur. Les versions plus anciennes de taskwarrior n'ont pas été testées et peuvent ne pas fonctionner.

PRÉREQUIS

•
taskwarrior v2.4.x ou supérieur, bien que la dernière version mineure soit recommandée.

INSTALLATION

Installer via pip (recommandé) :

pip install tasklib

Ou cloner depuis github :

git clone https://github.com/robgolding/tasklib.git
cd tasklib
python setup.py install

INITIALISATION

Initialiser optionnellement l'instance TaskWarrior avec data_location (le répertoire de la base de données). Si elle n'existe pas encore, elle sera créée automatiquement sauf si create=False.

L'emplacement par défaut est le même que celui de taskwarrior :

>>> tw = TaskWarrior(data_location='~/.task', create=True)

L'instance TaskWarrior utilisera également votre configuration .taskrc (de sorte qu'elle reconnaisse les mêmes UDAs que votre binaire task, utilise la même configuration, etc.). Pour remplacer l'emplacement de .taskrc, utilisez taskrc_location=~/quelque/chemin/different.

CRÉATION DE TÂCHES

Pour créer une tâche, il suffit de créer un nouvel objet Task :

>>> nouvelle_tache = Task(tw, description="jeter les ordures")

Cette tâche n'est pas encore enregistrée dans TaskWarrior (comme dans Django), jusqu'à ce que vous appeliez la méthode .save() :

>>> nouvelle_tache.save()

Vous pouvez définir n'importe quel attribut comme argument mot-clé pour l'objet Task :

>>> tache_complexe = Task(tw, description="réparer enfin la douche", due=datetime(2015,2,14,8,0,0), priority='H')

ou en définissant les attributs un par un :

>>> tache_complexe = Task(tw)
>>> tache_complexe['description'] = "réparer enfin la douche"
>>> tache_complexe['due'] = datetime(2015,2,14,8,0,0)
>>> tache_complexe['priority'] = 'H'

MODIFICATION DE TACHE

Pour modifier un objet Task créé ou récupéré, utilisez l'accès similaire à un dictionnaire :

>>> devoirs = tw.tasks.get(tags=['ménage'])
>>> devoirs['projet'] = 'Maison'

La modification n'est pas propagée à TaskWarrior tant que vous n'exécutez pas la méthode save() :

>>> devoirs.save()

Les attributs qui correspondent à des objets Python natifs sont convertis. Voir la section Attributs de Tâche.

ATTRIBUTS DE TACHE

Les attributs des objets tâche sont accessibles par leurs indices, comme ceci :

>>> tache = tw.tasks.en_attente().get(tags__contient='travail')  # Il n'y a qu'une tâche en attente avec le tag 'travail'
>>> tache['description']
'Mettre à niveau le serveur Ubuntu'
>>> tache['id']
15
>>> tache['due']
datetime.datetime(2015, 2, 5, 0, 0, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> tache['tags']
['travail', 'serveurs']

Les champs suivants sont désérialisés en objets Python :

  • due, wait, scheduled, until, entry : désérialisés en objet datetime
  • annotations : désérialisées en liste d'objets TaskAnnotation
  • tags : désérialisés en liste de chaînes
  • depends : désérialisés en ensemble d'objets Task

Les attributs doivent être définis en utilisant la représentation Python correcte, qui sera sérialisée dans le format approprié lors de la sauvegarde de la tâche.

PROPRIÉTÉS DE TACHE

Tasklib définit plusieurs propriétés sur l'objet Task, pour plus de commodité :

>>> t.save()
>>> t.enregistre
True
>>> t.en_attente
True
>>> t.actif
False
>>> t.demarrer()
>>> t.actif
True
>>> t.terminer()
>>> t.complete
True
>>> t.en_attente
False
>>> t.supprimer()
>>> t.supprime
True

OPÉRATIONS SUR LES TÂCHES

Après avoir modifié un ou plusieurs attributs, appelez simplement save() pour écrire ces modifications dans la base de données :

>>> tache = tw.tasks.en_attente().get(tags__contient='travail')
>>> tache['due'] = datetime(year=2014, month=1, day=5)
>>> tache.save()

Pour marquer une tâche comme terminée, utilisez done() :

>>> tache = tw.tasks.en_attente().get(tags__contient='travail')
>>> tache.done()
>>> len(tw.tasks.en_attente().filter(tags__contient='travail'))
0

Pour supprimer une tâche, utilisez delete() :

>>> tache = tw.tasks.get(description="tâche ajoutée par erreur")
>>> tache.delete()

Pour mettre à jour un objet tâche avec les valeurs de la base de données TaskWarrior, utilisez refresh(). Exemple :

>>> tache = Task(tw, description="apprendre à cuisiner")
>>> tache.save()
>>> tache['id']
5
>>> tache['tags']
[]

Maintenant, supposons que nous modifions la tâche en utilisant l'interface TaskWarrior dans un autre terminal :

$ task 5 modify +unjour
Tâche 5 modifiée.

Retour dans le processus python ouvert :

>>> tache['tags']
[]
>>> tache.refresh()
>>> tache['tags']
['unjour']

Les tâches peuvent également être démarrées et arrêtées. Utilisez start() et stop() respectivement :

>>> tache.start()
>>> tache['start']
datetime.datetime(2015, 7, 16, 18, 48, 28, tzinfo=<DstTzInfo 'Europe/Prague' CEST+2:00:00 DST>)
>>> tache.stop()
>>> tache['start']
>>> tache.done()
>>> tache['end']
datetime.datetime(2015, 7, 16, 18, 49, 2, tzinfo=<DstTzInfo 'Europe/Prague' CEST+2:00:00 DST>)

RÉCUPÉRATION DES TÂCHES

tw.tasks est un objet TaskQuerySet qui émule l'API QuerySet de Django. Pour obtenir toutes les tâches (y compris celles terminées) :

>>> tw.tasks.all()
['Première tâche', 'Tâche terminée', 'Tâche supprimée', ...]

FILTRAGE

Filtrez les tâches en utilisant la syntaxe familière :

>>> tw.tasks.filter(status='en attente', tags__contient=['travail'])
["Mettre à niveau le serveur Ubuntu"]

Les arguments de filtre sont passés à la commande task (__ est remplacé par un point), donc l'exemple ci-dessus est équivalent à la commande suivante :

$ task status:en attente tags.contient=travail

Les tâches peuvent également être filtrées en utilisant des commandes brutes, comme ceci :

>>> tw.tasks.filter('status:en attente +travail')
["Mettre à niveau le serveur Ubuntu"]

Alt

Bien que cette pratique soit déconseillée, car en utilisant des commandes brutes, vous risquez de perdre une partie de la portabilité de vos commandes entre les différentes versions de TaskWarrior.

Cependant, vous pouvez mélanger des commandes brutes avec des filtres par mot-clé, comme dans l'exemple donné :

>>> tw.tasks.filter('+BLOCKING', project='Home')  # Obtient toutes les tâches bloquantes dans le projet Home
['Fix the toilette']

Cela peut être un moyen astucieux d'utiliser une syntaxe non encore prise en charge par tasklib. Ce qui précède est un excellent exemple, car les balises virtuelles ne fonctionnent pas de la même manière que les balises ordinaires, c'est-à-dire :

>>> tw.tasks.filter(tags=['BLOCKING'])
>>> []

ne fonctionnera pas.

Il existe des fonctions intégrées pour récupérer les tâches en attente et terminées :

>>> tw.tasks.pending().filter(tags__contain='work')
['Upgrade Ubuntu Server']
>>> len(tw.tasks.completed())
227

Utilisez get() pour renvoyer la seule tâche d'un TaskQuerySet, ou lever une exception :

>>> tw.tasks.get(tags__contain='work')['status']
'pending'
>>> tw.tasks.get(status='completed', tags__contains='work')  # Le statut de la seule tâche avec la balise work est pending, donc cela devrait échouer
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "tasklib/task.py", line 224, in get
    'Lookup parameters were {0}'.format(kwargs))
tasklib.task.DoesNotExist: Task matching query does not exist. Lookup parameters were {'status': 'completed', 'tags__contains': ['work']}
>>> tw.tasks.get(status='pending')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "tasklib/task.py", line 227, in get
    'Lookup parameters were {1}'.format(num, kwargs))
ValueError: get() returned more than one Task -- it returned 23! Lookup parameters were {'status': 'pending'}

De plus, comme les filtres renvoient des TaskQuerySets, vous pouvez empiler des filtres les uns sur les autres :

>>> home_tasks = tw.tasks.filter(project='Wife')
>>> home_tasks.filter(due__before=datetime(2015,2,14,14,14,14))  # Ce que je dois faire avant la Saint-Valentin
['Prepare surprise birthday party']

ÉGALITÉ DES OBJETS TASK

Deux tâches sont considérées comme égales si elles ont les mêmes UUID :

>>> task1 = Task(tw, description="Pet the dog")
>>> task1.save()
>>> task2 = tw.tasks.get(description="Pet the dog")
>>> task1 == task2
True

Si vous comparez deux tâches non enregistrées, elles ne sont considérées comme égales que si c'est le même objet Python :

>>> task1 = Task(tw, description="Pet the cat")
>>> task2 = Task(tw, description="Pet the cat")
>>> task1 == task2
False
>>> task3 = task1
>>> task3 == task1
True

ACCÈS AUX VALEURS ORIGINALES

Pour accéder à l'état enregistré de la tâche, utilisez un accès de type dictionnaire en utilisant l'attribut original :

>>> t = Task(tw, description="tidy up")
>>> t.save()
>>> t['description'] = "tidy up the kitchen and bathroom"
>>> t['description']
"tidy up the kitchen and bathroom"
>>> t.original['description']
"tidy up"

Lorsque vous enregistrez la tâche, les valeurs originales sont actualisées pour refléter l'état enregistré de la tâche :

>>> t.save()
>>> t.original['description']
"tidy up the kitchen and bathroom"

TRAITEMENT DES DATES ET HEURES

Tous les attributs de type timestamp des tâches sont convertis en objets datetime conscients du fuseau horaire. Pour ce faire, Tasklib s'appuie sur le module Python zoneinfo, qui apporte la base de données des fuseaux horaires d'Olsen à Python.

Cela vous évite les détails ennuyeux des changements d'heure d'été ou des conversions entre différents fuseaux horaires. Par exemple, pour lister toutes les tâches qui sont dues à minuit si vous êtes actuellement à Berlin :

>>> myzone = zoneinfo.ZoneInfo('Europe/Berlin')
>>> midnight = datetime(2015,2,2,0,0,0,tzinfo=myzone)
>>> tw.tasks.filter(due__before=midnight)

Cependant, c'est encore un peu fastidieux. C'est pourquoi l'objet TaskWarrior est capable de détection automatique du fuseau horaire, en utilisant le module Python tzlocal. Si votre fuseau horaire système est réglé sur 'Europe/Berlin', l'exemple suivant fonctionnera de la même manière que le précédent :

>>> tw.tasks.filter(due__before=datetime(2015,2,2,0,0,0))

Vous pouvez également utiliser des dates simples lors du filtrage :

>>> tw.tasks.filter(due__before=date(2015,2,2))

Dans ce cas, une composante de temps de 00:00:00 est utilisée.

Bien sûr, vous pouvez utiliser des objets datetime naïfs lors de l'initialisation d'un objet Task ou de l'attribution de valeurs à des attributs datetime :

>>> t = Task(tw, description="Buy new shoes", due=date(2015,2,5))
>>> t['due']
datetime.datetime(2015, 2, 5, 0, 0, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> t['due'] = date(2015,2,6,15,15,15)
>>> t['due']
datetime.datetime(2015, 2, 6, 15, 15, 15, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)

Cependant, comme les datetimes conscients et naïfs du fuseau horaire ne sont pas comparables en Python, cela peut entraîner des comportements inattendus :

>>> from datetime import datetime
>>> now = datetime.now()
>>> t = Task(tw, description="take out the trash now")
>>> t['due'] = now
>>> now
datetime.datetime(2015, 2, 1, 19, 44, 4, 770001)
>>> t['due']
datetime.datetime(2015, 2, 1, 19, 44, 4, 770001, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> t['due'] == now
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  TypeError: can't compare offset-naive and offset-aware datetimes

Si vous voulez comparer une valeur datetime consciente avec une valeur datetime naïve, vous devez d'abord localiser la valeur naïve :

>>> from datetime import datetime
>>> now = datetime.now().astimezone()
>>> t['due'] = now
>>> now
datetime.datetime(2015, 2, 1, 19, 44, 4, 770001, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> t['due'] == now
True

De plus, notez qu'il n'a pas d'importance si les objets datetime conscients du fuseau horaire sont définis dans le même fuseau horaire :

>>> import zoneinfo
>>> t['due']
datetime.datetime(2015, 2, 1, 19, 44, 4, 770001, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> now.astimezone(zoneinfo.ZoneInfo('UTC'))
datetime.datetime(2015, 2, 1, 18, 44, 4, 770001, tzinfo=<UTC>)
>>> t['due'] == now.astimezone(zoneinfo.ZoneInfo('UTC'))
True

Note : Le comportement suivant n'est disponible que pour TaskWarrior >= 2.4.0.

Il existe une troisième approche pour configurer les valeurs d'horodatage, qui exploite la commande 'task calc'. Vous pouvez simplement définir n'importe quel attribut datetime sur n'importe quelle chaîne contenant une expression de temps formatée acceptable par TaskWarrior :

$ task calc now + 1d
2015-07-17T21:17:54

Cette syntaxe peut être utilisée dans l'interpréteur Python comme suit :

>>> t['due'] = "now + 1d"
>>> t['due']
datetime.datetime(2015, 7, 17, 21, 19, 31, tzinfo=<DstTzInfo 'Europe/Berlin' CEST+2:00:00 DST>)

On peut facilement constater que la chaîne avec l'expression de temps formatée TaskWarrior est automatiquement convertie en datetime natif dans le fuseau horaire local.

Pour la liste des formats et mots-clés acceptables, veuillez consulter :

  • http://taskwarrior.org/docs/dates.html
  • http://taskwarrior.org/docs/named_dates.html

Cependant, comme chaque assignation de ce type implique un appel à 'task calc' pour la conversion, cela peut causer des problèmes de performance lors de l'assignation répétée de chaînes à des attributs datetime, de manière automatisée.

TRAVAIL AVEC LES ANNOTATIONS

Les annotations des tâches sont représentées dans tasklib par des objets TaskAnnotation. Ceux-ci ressemblent beaucoup à des objets Task, bien que très simplifiés.

>>> annotated_task = tw.tasks.get(description='Annotated task')
>>> annotated_task['annotations']
[Yeah, I am annotated!]

Les annotations n'ont que des valeurs définies pour entry et description :

>>> annotation = annotated_task['annotations'][0]
>>> annotation['entry']
datetime.datetime(2015, 1, 3, 21, 13, 55, tzinfo=<DstTzInfo 'Europe/Berlin' CET+1:00:00 STD>)
>>> annotation['description']
u'Yeah, I am annotated!'

Pour ajouter une annotation à une tâche, utilisez add_annotation() :

>>> task = Task(tw, description="new task")
>>> task.add_annotation("we can annotate any task")
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    File "build/bdist.linux-x86_64/egg/tasklib/task.py", line 355, in add_annotation
tasklib.task.NotSaved: Task needs to be saved to add annotation

Cependant, la tâche doit être enregistrée avant que vous ne puissiez y ajouter une annotation :

>>> task.save()
>>> task.add_annotation("we can annotate saved tasks")
>>> task['annotations']
[we can annotate saved tasks]

Pour supprimer l'annotation, passez sa description à la méthode remove_annotation() :

>>> task.remove_annotation("we can annotate saved tasks")

Alternativement, vous pouvez passer l'objet TaskAnnotation lui-même :

>>> task.remove_annotation(task['annotations'][0])

EXÉCUTION DE COMMANDES PERSONNALISÉES

Pour exécuter des commandes personnalisées, utilisez la méthode execute_command() de l'objet TaskWarrior:

>>> tw = TaskWarrior()
>>> tw.execute_command(['log', 'Finish high school.'])
[u'Logged task.']

Vous pouvez utiliser l'argument de mot-clé config_override pour spécifier un dictionnaire de remplacements de configuration:

>>> tw.execute_command(['3', 'done'], config_override={'gc': 'off'}) # Mark 3 as completed and it will retain its ID

De plus, vous pouvez utiliser l'indicateur return_all=True, qui renvoie le triplet (stdout, sterr, return_code), et allow_failure=False, qui empêchera tasklib de lever une exception si le binaire de tâche a renvoyé un code de retour non nul:

>>> tw.execute_command(['invalidcommand'], allow_failure=False, return_all=True)
([u''],
 [u'Using alternate .taskrc file /home/tbabej/.taskrc',
  u"[task next rc:/home/tbabej/.taskrc rc.recurrence.confirmation=no rc.json.array=off rc.confirmation=no rc.bulk=0 rc.dependency.confirmation=no description ~ 'invalidcommand']",
  u'Configuration override rc.recurrence.confirmation:no',
  u'Configuration override rc.json.array:off',
  u'Configuration override rc.confirmation:no',
  u'Configuration override rc.bulk:0',
  u'Configuration override rc.dependency.confirmation:no',
  u'No matches.',
  u'There are local changes.  Sync required.'],
 1)

PARAMÈTRES DES VALEURS DE CONFIGURATION PERSONNALISÉES

Par défaut, TaskWarrior utilise les valeurs de configuration stockées dans votre .taskrc. Pour voir quels remplacements de valeurs de configuration sont transmis à chaque commande de tâche exécutée, jetez un œil à l'attribut overrides de l'objet TaskWarrior:

>>> tw.overrides
{'confirmation': 'no', 'data.location': '/home/tbabej/.task'}

Pour transmettre vos propres remplacements de configuration, vous devez simplement mettre à jour ce dictionnaire:

>>> tw.overrides.update({'hooks': 'off'})  # tasklib will not trigger hooks

CRÉATION DE SCRIPTS DE HOOK

À partir de la version 2.4.0, TaskWarrior prend en charge les scripts de hook. Tasklib fournit des utilitaires très utiles pour les écrire. Avec tasklib, l'écriture de ces derniers devient un jeu d'enfant:

#!/usr/bin/python
from tasklib.task import Task
task = Task.from_input()
# ... <custom logic>
print task.export_data()

Par exemple, un plugin qui attribuerait la priorité "H" à toute tâche contenant trois points d'exclamation dans la description serait le suivant:

#!/usr/bin/python
from tasklib.task import Task
task = Task.from_input()
if "!!!" in task['description']:
    task['priority'] = "H"
print task.export_data()

Tasklib peut détecter automatiquement s'il s'exécute dans l'événement on-modify, qui fournit plus d'entrées que l'événement on-add et lit les données en conséquence.

Cela signifie que l'exemple ci-dessus fonctionne à la fois pour les événements on-add et on-modify!

Par conséquent, vous pouvez créer un seul fichier de hook pour les événements on-add et on-modify, et il vous suffit de créer un lien symbolique pour l'autre. Cela élimine le besoin de maintenir deux copies du même code et/ou du code boilerplate.

Dans les événements on-modify, tasklib charge à la fois la version originale et la version modifiée de la tâche dans l'objet Task renvoyé. Pour accéder aux données originales (en lecture seule), utilisez l'attribut de type dictionnaire original:

>>> t = Task.from_input()
>>> t['description']
"Modified description"
>>> t.original['description']
"Original description"

TRAVAIL AVEC LES UDA

Comme TaskWarrior lit votre .taskrc, vous n'avez pas besoin de définir d'UDA dans le dictionnaire de configuration de TaskWarrior, comme décrit ci-dessus. Supposons que nous ayons un UDA estimate dans le .taskrc:

uda.estimate.type = numeric

Nous pouvons simplement filtrer et créer des tâches en utilisant l'UDA estimate directement:

>>> tw = TaskWarrior()
>>> task = Task(tw, description="Long task", estimate=1000)
>>> task.save()
>>> task['id']
1

Ceci est enregistré comme un UDA dans TaskWarrior:

$ task 1 export
{"id":1,"description":"Long task","estimate":1000, ...}

Nous pouvons également spécifier des UDA comme arguments dans TaskFilter:

>>> tw.tasks.filter(estimate=1000)
Long task

SYNCHRONISATION

Si vous avez configuré les variables de configuration requises dans votre .taskrc, la synchronisation est aussi simple que:

>>> tw = TaskWarrior()
>>> tw.execute_command(['sync'])

Si vous souhaitez utiliser un serveur/des identifiants non standard, vous devrez fournir des remplacements de configuration à l'instance TaskWarrior. Mettez à jour le dictionnaire config avec les valeurs que vous souhaitez remplacer, puis nous pouvons exécuter la commande de synchronisation à l'aide de la méthode execute_command():

>>> tw = TaskWarrior()
>>> sync_config = {
...     'taskd.certificate': '/home/tbabej/.task/tbabej.cert.pem',
...     'taskd.credentials': 'Public/tbabej/34af54de-3cb2-4d3d-82be-33ddb8fd3e66',
...     'taskd.server': 'task.server.com:53589',
...     'taskd.ca': '/home/tbabej/.task/ca.cert.pem',
...     'taskd.trust': 'ignore hostname'}
>>> tw.config.update(sync_config)
>>> tw.execute_command(['sync'])
