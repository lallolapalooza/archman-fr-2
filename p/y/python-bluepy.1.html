LA CLASSE PERIPHERAL

La classe Peripheral de Bluepy encapsule une connexion à un périphérique Bluetooth LE. Vous créez un objet Peripheral directement en spécifiant son adresse MAC ; lorsque la connexion est établie, les services et caractéristiques proposés par ce périphérique peuvent être découverts et lus ou écrits.

Constructeur

Peripheral([deviceAddr=None[, addrType=ADDR_TYPE_PUBLIC[, iface=None]]])
Si deviceAddr n'est pas None, crée un objet Peripheral et établit une connexion avec le périphérique indiqué par deviceAddr. deviceAddr doit être une chaîne composée de six octets hexadécimaux séparés par des deux-points, par exemple "11:22:33:ab:cd:ed".

Si deviceAddr est None, crée un objet Peripheral non connecté. Vous devez appeler la méthode connect() sur cet objet (en lui passant une adresse de périphérique) avant qu'il ne soit utilisable.

Le paramètre addrType peut être utilisé pour choisir entre les types d'adresse fixe (btle.ADDR_TYPE_PUBLIC) et aléatoire (btle.ADDR_TYPE_RANDOM), en fonction de ce que nécessite le périphérique cible. Voir la section 10.8 de la spécification Bluetooth 4.0 pour plus de détails.

Le paramètre iface permet de définir l'interface Bluetooth sur laquelle établir la connexion. Sous Linux, 0 signifie /dev/hci0, 1 signifie /dev/hci1, etc.

deviceAddr peut également être un objet ScanEntry. Dans ce cas, l'adresse du périphérique, le type d'adresse et le numéro d'interface sont tous pris à partir des valeurs de ScanEntry, et les paramètres addrType et iface sont ignorés.

Le constructeur lèvera une BTLEException si la connexion au périphérique échoue.

Méthodes d'instance

connect(addr[, addrType=ADDR_TYPE_PUBLIC[, iface=None]])
Établit une connexion avec le périphérique indiqué par addr, avec le type d'adresse addrType et le numéro d'interface iface (voir le constructeur Peripheral pour les détails). Vous ne devriez appeler cette méthode que si le Peripheral est non connecté (c'est-à-dire si vous n'avez pas passé d'addr au constructeur) ; un objet périphérique donné ne peut pas être reconnecté une fois connecté.
disconnect()
Interrompt la connexion avec le périphérique et nettoie les ressources système associées. Bien que le destructeur Python d'un Peripheral tente d'appeler cette méthode, vous ne devez pas compter sur le fait qu'elle se produise à un moment précis. Par conséquent, appelez toujours explicitement disconnect() si vous avez terminé la communication avec un périphérique.
getState()
Retourne une chaîne indiquant l'état du périphérique. Les états possibles sont : "conn" - connecté, "disc" - déconnecté, "scan" en cours de scan et "tryconn" - en cours de connexion.
getServices()
Retourne une liste d'objets Service représentant les services proposés par le périphérique. Cela effectuera une découverte de services Bluetooth si cela n'a pas déjà été fait ; sinon, elle retournera immédiatement une liste mise en cache des services.

Sous Python 3.x, cela retourne un objet de type *vue de dictionnaire*, pas une liste.

getServiceByUUID(uuidVal)
Retourne une instance d'un objet Service qui a l'UUID indiqué. uuidVal peut être un objet UUID, ou toute chaîne ou entier qui peut être utilisé pour construire un objet UUID. La méthode retournera immédiatement si le service a été découvert précédemment (par exemple par getServices()), et interrogera le périphérique sinon. Elle lèvera une BTLEEException si le service n'est pas trouvé.
getCharacteristics(startHnd=1, endHnd=0xFFFF, uuid=None)
Retourne une liste contenant des objets Characteristic pour le périphérique. Si aucun argument n'est donné, retournera toutes les caractéristiques. Si startHnd et/ou endHnd sont donnés, la liste est limitée aux caractéristiques dont les handles sont dans la plage donnée - notez qu'il est généralement plus pratique d'utiliser Service.getCharacteristics() pour obtenir les caractéristiques associées à un service particulier. Alternativement, uuid peut être spécifié pour localiser une caractéristique avec une valeur UUID particulière. uuid peut être une chaîne de caractères, un entier ou un type UUID qui peut être utilisé pour construire un objet UUID.

Si aucune caractéristique correspondante n'est trouvée, retourne une liste vide.

getDescriptors(startHnd=1, endHnd=0xFFFF)
Retourne une liste contenant des objets Descriptor pour le périphérique. Si aucun argument n'est donné, retournera tous les descripteurs. Si startHnd et/ou endHnd sont donnés, la liste est limitée aux descripteurs dont les handles sont dans la plage donnée. Encore une fois, il est généralement plus pratique d'utiliser Service.getDescriptors() pour obtenir les descripteurs associés à un service particulier.

Si aucun descripteur correspondant n'est trouvé, retourne une liste vide.

withDelegate(delegate)
Cela stocke une référence à un objet "délégué", qui est appelé lorsque des événements asynchrones tels que les notifications Bluetooth se produisent. Cela devrait être une sous-classe de la classe DefaultDelegate. Voir Utilisation des notifications pour plus d'informations. Cette méthode retourne l'objet Peripheral.
setDelegate(delegate)
(déprécié depuis 0.9.10) Identique à withDelegate().
waitForNotifications(timeout)
Bloque jusqu'à ce qu'une notification soit reçue du périphérique, ou jusqu'à ce que le timeout donné (en secondes) soit écoulé. Si une notification est reçue, la méthode handleNotification() de l'objet délégué sera appelée, et waitForNotifications() retournera alors True.

Si rien n'est reçu avant l'expiration du délai, cette méthode retournera False.

writeCharacteristic(handle, val, withResponse=False)
Écrit les données val (de type str sous Python 2.x, byte sous 3.x) dans la caractéristique identifiée par le handle handle, qui devrait être un entier dans la plage de 1 à 65535. Ceci est utile si vous connaissez le handle d'une caractéristique, mais que vous ne possédez pas d'objet Characteristic.

Si withResponse est vrai, attendra la confirmation que l'écriture a réussi de la part du périphérique.

readCharacteristic(handle)
Lit la valeur actuelle de la caractéristique identifiée par handle. Ceci est utile si vous connaissez le handle de la caractéristique

LA CLASSE SCANNER

Un objet Scanner est utilisé pour rechercher des périphériques LE qui diffusent des données publicitaires. Dans la plupart des situations, cela donnera un ensemble de périphériques disponibles pour la connexion. (Notez, cependant, que les périphériques Bluetooth LE peuvent accepter des connexions sans diffuser de données publicitaires, ou peuvent diffuser des données publicitaires mais peuvent ne pas accepter de connexions).

Constructeur

Scanner([index=0])
Crée et initialise un nouvel objet scanner. index identifie l'interface Bluetooth à utiliser (où 0 est /dev/hci0 etc.). Le scan ne commence que lorsque les méthodes start() ou scan() sont appelées - voir ci-dessous pour plus de détails.

Méthodes d'instance

withDelegate(delegate)
Stocke une référence à un objet délégué, qui reçoit des rappels lorsque des diffusions de périphériques sont reçues. Voir la documentation de DefaultDelegate pour les détails.
scan([timeout = 10])
Scanne les périphériques pendant la durée spécifiée timeout en secondes. Pendant cette période, les rappels à l'objet délégué seront appelés. Lorsque le délai expire, le scan s'arrêtera et la méthode retournera une liste (ou une vue en Python 3.x) d'objets ScanEntry pour tous les périphériques découverts pendant ce temps.

scan() est équivalent à l'appel des méthodes clear(), start(), process() et stop() dans l'ordre.

clear()
Efface l'ensemble actuel des périphériques découverts.
start()
Active la réception des diffusions publicitaires des périphériques. Doit être appelé avant d'appeler process().
process([timeout = 10])
Attend les diffusions publicitaires et appelle l'objet délégué lorsqu'elles sont reçues. Retourne après la période de timeout donnée en secondes. Ceci peut être appelé plusieurs fois (entre les appels à start() et stop()).
stop()
Désactive la réception des diffusions publicitaires. Doit être appelé après le retour de process().
getDevices()
Retourne une liste (une vue en Python 3.x) d'objets ScanEntry pour tous les périphériques qui ont été découverts (depuis le dernier appel à clear()).

Code exemple

Un code de base pour effectuer un scan de périphérique LE pendant 10 secondes suit cet exemple :

# importer les parties nécessaires de la bibliothèque bluepy
from bluepy.btle import Scanner, DefaultDelegate
# créer une classe déléguée pour recevoir les paquets de diffusion BLE
class ScanDelegate(DefaultDelegate):
    def __init__(self):
        DefaultDelegate.__init__(self)
    # lorsque ce script python découvre un paquet de diffusion BLE, imprimer un message avec l'adresse MAC du périphérique
    def handleDiscovery(self, dev, isNewDev, isNewData):
        if isNewDev:
            print "Découverte du périphérique", dev.addr
        elif isNewData:
            print "Données nouvelles reçues de", dev.addr
# créer un objet scanner qui envoie des paquets de diffusion BLE au ScanDelegate
scanner = Scanner().withDelegate(ScanDelegate())
# créer une liste de périphériques uniques que le scanner a découverts lors d'un scan de 10 secondes
devices = scanner.scan(10.0)
# pour chaque périphérique dans la liste des périphériques
for dev in devices:
    # imprimer l'adresse MAC du périphérique, son type d'adresse,
    # et l'Indication de Force du Signal Reçu qui montre à quel point le signal était fort lorsque le script a reçu la diffusion.
    print "Périphérique %s (%s), RSSI=%d dB" % (dev.addr, dev.addrType, dev.rssi)
    # Pour chaque élément de données publicitaires du périphérique, imprimer une description du type de données et la valeur des données elles-mêmes
    # getScanData renvoie une liste de tuples : adtype, desc, value
    # où AD Type signifie « type de données publicitaires », tel que défini par la convention Bluetooth :
    # https://www.bluetooth.com/specifications/assigned-numbers/generic-access-profile
    # desc est une description lisible par l'homme du type de données et value est les données elles-mêmes
    for (adtype, desc, value) in dev.getScanData():
        print "  %s = %s" % (desc, value)

Pour un scan continu, suivez cet exemple :

# importer les parties nécessaires de la bibliothèque bluepy
from bluepy.btle import Scanner, DefaultDelegate
# créer une classe déléguée pour recevoir les paquets de diffusion BLE
class ScanDelegate(DefaultDelegate):
    def __init__(self):
        DefaultDelegate.__init__(self)
    # lorsque ce script python découvre un paquet de diffusion BLE, imprimer un message avec l'adresse MAC du périphérique
    def handleDiscovery(self, dev, isNewDev, isNewData):
        if isNewDev:
            print "Découverte du périphérique", dev.addr
        elif isNewData:
            print "Données nouvelles reçues de", dev.addr
# créer un objet scanner qui envoie des paquets de diffusion BLE au ScanDelegate
scanner = Scanner().withDelegate(ScanDelegate())
# démarrer le scanner et maintenir le processus en cours d'exécution
scanner.start()
while True:
    print "En cours d'exécution..."
    scanner.process()

NOTEZ que (1) le scan LE doit être exécuté en tant que root et (2) le code de scan continu ne se termine jamais, vous devrez donc effectuer des tâches utiles dans la méthode handleDiscovery() de votre délégué.

Voir la documentation de ScanEntry pour les informations disponibles via le paramètre dev passé au délégué.

LA CLASSE SCANENTRY

Un objet ScanEntry contient des informations reçues d'un périphérique Bluetooth LE lors de l'opération Scanner. Cela inclut les paramètres nécessaires pour se connecter au périphérique (adresse MAC, type d'adresse), et les données publicitaires (telles que son nom ou les services disponibles) fournies dans les diffusions du périphérique.

Constructeur

Les objets ScanEntry sont créés par la classe Scanner et ne doivent pas être créés par l'utilisateur.

Méthodes d'instance

getDescription(adtype)
Retourne une description lisible par l'homme du code de 'type' de données publicitaires adtype. Par exemple, une valeur adtype de 9 retournerait la chaîne "Nom local complet". Voir les numéros assignés du Profil d'Accès Générique à https://www.bluetooth.org/en-us/specification/assigned-numbers/generic-access-profile pour une liste complète.
getValueText(adtype)
Retourne une représentation sous forme de chaîne lisible par l'homme des données publicitaires pour le code adtype. Les valeurs telles que le 'nom local' sont renvoyées directement sous forme de chaînes ; d'autres valeurs sont converties en chaînes hexadécimales. Si les données demandées ne sont pas disponibles, None est retourné.
getScanData()
Retourne une liste de tuples (adtype, description, value) contenant le code du type AD, la description lisible par l'homme et la valeur (telles que rapportées par getDescription() et getValueText()) pour tous les éléments de données publicitaires disponibles.

Propriétés

Toutes les propriétés listées ci-dessous sont en lecture seule.

addr
Adresse MAC du périphérique (sous forme de chaîne hexadécimale séparée par des deux-points).
addrType
Type d'adresse du périphérique - l'un des ADDR_TYPE_PUBLIC ou ADDR_TYPE_RANDOM.
iface
Numéro de l'interface Bluetooth (0 = /dev/hci0) sur laquelle les informations publicitaires ont été vues.
rssi
Indication de Force du Signal Reçu pour la dernière diffusion reçue du périphérique. Il s'agit d'une valeur entière mesurée en dB, où 0 dB est la force du signal maximale (théorique), et des nombres plus négatifs indiquent un signal plus faible.
connectable
Valeur booléenne - True si le périphérique supporte les connexions, et False sinon (généralement utilisé pour la pub
vertising 'beacons').
updateCount
Nombre entier d'acquittements publicitaires reçus de l'appareil jusqu'à présent (depuis que clear() a été appelé sur l'objet Scanner qui l'a trouvé).

LA CLASSE DEFAULTDELEGATE

Les fonctions bluepy qui reçoivent des messages Bluetooth de manière asynchrone - telles que les notifications, les indications et les données publicitaires - transmettent ces informations à l'utilisateur en appelant des méthodes sur un objet 'délégué'.

Pour être utile, l'objet délégué sera d'une classe créée par l'utilisateur. Le DefaultDelegate de Bluepy est une classe de base pour cela - vous devriez remplacer certaines ou toutes les méthodes ici par votre propre code spécifique à l'application.

Constructeur

DefaultDelegate()
Initialise l'instance de l'objet.

Méthodes d'instance

handleNotification(cHandle, data)
Appelée lorsqu'une notification ou une indication est reçue d'un objet Peripheral connecté. cHandle est le handle (entier) pour la caractéristique - cela peut être utilisé pour distinguer les notifications de plusieurs sources sur le même périphérique. data sont les données de la caractéristique (un type str sur Python 2.x, et bytes sur 3.x).
handleDiscovery(scanEntry, isNewDev, isNewData)
Appelée lorsqu'une donnée publicitaire est reçue d'un appareil LE pendant qu'un objet Scanner est actif. scanEntry contient les informations de l'appareil et les données publicitaires - voir la classe ScanEntry pour les détails. isNewDev est True si l'appareil (tel qu'identifié par son adresse MAC) n'a pas été vu auparavant par le scanner, et False sinon. isNewData est True si de nouvelles données publicitaires ou mises à jour sont disponibles.

LA CLASSE UUID

Constructeur

UUID(value)
Construit un objet UUID avec la valeur value donnée. Celle-ci peut être :
  • une valeur int dans la plage 0 à 0xFFFFFFFF
  • une valeur str
  • un autre objet UUID
  • toute autre valeur qui peut être convertie en chiffres hexadécimaux à l'aide de str()

Méthodes d'instance

getCommonName()
Retourne une chaîne décrivant cet UUID. Si l'UUID est l'un de ceux répertoriés dans Assigned Numbers, il s'agira d'un nom lisible par l'homme, par exemple "Cycling Speed and Cadence". Sinon, ce sera une chaîne hexadécimale.

Propriétés

Toutes les propriétés listées ci-dessous sont en lecture seule.

binVal
L'UUID exprimé en binaire (un objet str sur Python 2.x, bytes sur 3.x).

LA CLASSE SERVICE

Un objet Service Bluetooth LE représente une collection de caractéristiques et de descripteurs qui sont tous liés à une fonction particulière du périphérique. Cela permet de découvrir des caractéristiques particulières sans avoir à énumérer tout ce qu'offre ce périphérique.

Constructeur

Vous ne devriez pas construire d'objets Service directement. Utilisez plutôt les méthodes getServices() ou getServiceByUUID() d'un objet Peripheral connecté.

Méthodes d'instance

getCharacteristics([forUUID=None])
Retourne une liste d'objets Characteristic associés au service. Si cela n'a pas été fait auparavant, le périphérique est interrogé. Sinon, une liste mise en cache est retournée. Si forUUID est fourni, il peut s'agir d'un objet UUID ou d'une valeur utilisée pour en construire un. Dans ce cas, la liste retournée, qui peut être vide, contient toutes les caractéristiques associées au service qui correspondent à cet UUID.

Propriétés

Toutes les propriétés listées ci-dessous sont en lecture seule.

uuid
L'UUID Bluetooth pour ce service.
peripheral
L'objet Peripheral de l'appareil auquel le service appartient.

LA CLASSE CHARACTERISTIC

Une "caractéristique" Bluetooth LE représente un court élément de données qui peut être lu ou écrit. Celles-ci peuvent être fixes (par exemple, une chaîne représentant le nom du fabricant) ou changer dynamiquement (comme la température actuelle ou l'état d'un bouton). La plupart des interactions avec les périphériques Bluetooth LE se font en lisant ou en écrivant des caractéristiques.

Constructeur

Vous ne devriez pas construire d'objets Characteristic directement. Utilisez plutôt la méthode getCharacteristics() d'un objet Peripheral connecté.

Méthodes d'instance

read()
Lit la valeur actuelle d'une caractéristique sous forme de chaîne d'octets. Pour Python 2.x, il s'agit d'une valeur de type str, et sur Python 3.x, c'est de type bytes. Cela peut être utilisé avec le module struct pour extraire des valeurs entières des données.
write(data[, withResponse=False])
Écrit les données data fournies à la caractéristique. data doit être de type str pour Python 2.x, et de type bytes pour Python 3.x. Bluetooth LE permet à l'expéditeur de demander au périphérique d'envoyer une réponse pour confirmer que les données ont été reçues. Définir le paramètre withResponse sur True effectuera cette demande. Une BTLEException sera levée si le processus de confirmation échoue.
supportsRead()
Retourne True si la caractéristique peut être lue (tel qu'indiqué par ses propriétés) et False sinon.
propertiesToString()
Retourne une chaîne décrivant les propriétés de la caractéristique ('READ', 'WRITE', etc.).
getHandle()
Retourne la valeur entière de 16 bits utilisée pour identifier la caractéristique dans le protocole GATT sous-jacent. Cela peut être utile pour distinguer les notifications de différentes caractéristiques (voir Utilisation des notifications pour plus d'informations).

Propriétés

Toutes les propriétés listées ci-dessous sont en lecture seule.

uuid
L'UUID Bluetooth pour cette caractéristique.
peripheral
L'objet Peripheral de l'appareil auquel la caractéristique appartient.
properties
Un masque de bits des propriétés de la caractéristique.

LA CLASSE DESCRIPTOR

La classe Descriptor est un espace réservé. bluepy ne prend actuellement en charge aucune opération utile avec les descripteurs.

UTILISATION DES NOTIFICATIONS

Dans bluepy, les notifications sont traitées en créant un objet "délégué" et en l'enregistrant auprès du Peripheral. Une méthode du délégué est appelée chaque fois qu'une notification est reçue du périphérique, comme indiqué ci-dessous :

handleNotification(cHandle, data)
Appelée lorsqu'une notification a été reçue d'un Peripheral. Normalement, vous appellerez la méthode waitForNotifications() du périphérique pour permettre cela, mais notez qu'un appareil Bluetooth LE peut transmettre des notifications à tout moment. Cela signifie que handleNotification() peut potentiellement être appelée lorsqu'un appel BluePy est en cours.

Le

cHandle est le 'handle' GATT pour la caractéristique qui envoie la notification. Si un périphérique envoie des notifications pour plus d'une caractéristique, cela peut être utilisé pour les distinguer. La valeur du 'handle' peut être trouvée en appelant la méthode getHandle() d'un objet Characteristic.

Le paramètre data est une valeur de type str (Python 2.x) ou bytes (Python 3.x) contenant les données de notification. Il est recommandé d'utiliser le module struct de Python pour le décompresser, afin de permettre la portabilité entre les versions du langage.

Il est recommandé que la classe utilisée pour l'objet délégué soit dérivée de btle.DefaultDelegate. Cela garantira qu'une méthode par défaut appropriée existe pour toute future requête qui pourrait être ajoutée à l'interface du délégué.

Exemple de code

Le code pour recevoir des notifications d'un périphérique peut suivre l'esquisse ci-dessous :

import btle
class MyDelegate(btle.DefaultDelegate):
    def __init__(self, params):
        btle.DefaultDelegate.__init__(self)
        # ... initialisation ici
    def handleNotification(self, cHandle, data):
        # ... peut-être vérifier cHandle
        # ... traiter 'data'
# Initialisation  -------
p = btle.Peripheral( address )
p.setDelegate( MyDelegate(params) )
# Configuration pour activer les notifications, par exemple :
#   svc = p.getServiceByUUID( service_uuid )
#   ch = svc.getCharacteristics( char_uuid )[0]
#   ch.write( setup_data )
# Boucle principale --------
while True:
    if p.waitForNotifications(1.0):
        # handleNotification() a été appelé
        continue
    print "En attente..."
    # Peut-être faire autre chose ici
