NOM

flask-migrate - Documentation de Flask-Migrate

Flask-Migrate est une extension qui gère les migrations de base de données SQLAlchemy pour les applications Flask en utilisant Alembic. Les opérations de base de données sont rendues disponibles via l'interface en ligne de commande de Flask.

POURQUOI UTILISER FLASK-MIGRATE PLUTÔT QU'ALEMBIC DIRECTEMENT ?

Flask-Migrate est une extension qui configure Alembic de la manière appropriée pour fonctionner avec votre application Flask et Flask-SQLAlchemy. En ce qui concerne les migrations de base de données elles-mêmes, tout est géré par Alembic, vous bénéficiez donc exactement des mêmes fonctionnalités.

INSTALLATION

Installez Flask-Migrate avec pip :

pip install Flask-Migrate

EXEMPLE

Voici un exemple d'application qui gère les migrations de base de données via Flask-Migrate :

from flask import Flask
from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate
app = Flask(__name__)
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///app.db'
db = SQLAlchemy(app)
migrate = Migrate(app, db)
class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(128))

Avec l'application ci-dessus, vous pouvez créer un dépôt de migrations avec la commande suivante :

$ flask db init

Cela ajoutera un dossier migrations à votre application. Le contenu de ce dossier doit être ajouté au contrôle de version avec vos autres fichiers source.

Vous pouvez ensuite générer une migration initiale :

Ensuite, vous pouvez appliquer les modifications décrites par le script de migration à votre base de données :

$ flask db upgrade

Chaque fois que les modèles de base de données changent, répétez les commandes migrate et upgrade.

Pour synchroniser la base de données sur un autre système, il suffit de rafraîchir le dossier migrations depuis le contrôle de version et d'exécuter la commande upgrade.

Pour voir toutes les commandes disponibles, exécutez cette commande :

$ flask db --help

Notez que le script de l'application doit être défini dans la variable d'environnement FLASK_APP pour que toutes les commandes ci-dessus fonctionnent, comme requis par la commande flask.

Si le nom du groupe de commandes db est gênant, il peut être modifié avec l'argument command passé à la classe Migrate :

migrate = Migrate(app, db, command='migrate')

OPTIONS DE CONFIGURATION ALEMBIC

À partir de la version 4.0, Flask-Migrate active automatiquement les options suivantes qui sont désactivées par défaut dans Alembic :

  • compare_type=True : Cette option configure le sous-système de génération de migration automatique pour détecter les changements de type de colonne.
  • render_as_batch=True : Cette option génère des scripts de migration en utilisant le mode batch, un mode opérationnel qui contourne les limitations de nombreuses commandes ALTER dans la base de données SQLite en implémentant un flux de travail de "déplacement et copie". L'activation de ce mode ne devrait faire aucune différence lors du travail avec d'autres bases de données.
migrate = Migrate(app, db, render_as_batch=False)

CALLBACKS DE CONFIGURATION

Parfois, les applications doivent insérer dynamiquement leurs propres paramètres dans la configuration d'Alembic. Une fonction décorée par le callback configure sera appelée après la lecture de la configuration et avant son application. La fonction peut modifier l'objet de configuration ou le remplacer par un autre.

@migrate.configure
def configure_alembic(config):
    # modifier l'objet config
    return config

Plusieurs callbacks de configuration peuvent être définis simplement en décorant plusieurs fonctions. L'ordre dans lequel plusieurs callbacks sont invoqués n'est pas déterminé.

SUPPORT DE BASES DE DONNÉES MULTIPLES

Pour créer un dépôt de migrations multi-bases de données, ajoutez l'argument --multidb à la commande init :

$ flask db init --multidb

Avec cette commande, le dépôt de migrations sera configuré pour suivre les migrations sur votre base de données principale et sur toutes les bases de données supplémentaires définies dans l'option de configuration SQLALCHEMY_BINDS.

RÉFÉRENCE DES COMMANDES

Flask-Migrate expose une classe appelée Migrate. Cette classe contient toute la fonctionnalité de l'extension.

L'exemple suivant initialise l'extension avec l'interface de ligne de commande Flask standard :

from flask_migrate import Migrate
migrate = Migrate(app, db)

Les deux arguments de Migrate sont l'instance de l'application et l'instance de base de données Flask-SQLAlchemy. Le constructeur Migrate accepte également des arguments mots-clés supplémentaires, qui sont passés à la méthode EnvironmentContext.configure() d'Alembic. Comme il est standard pour toutes les extensions Flask, Flask-Migrate peut être initialisé en utilisant également la méthode init_app :

from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate
db = SQLAlchemy()
migrate = Migrate()
def create_app():
     """Modèle usine d'application"""
     ...
     ...
     db.init_app(app)
     migrate.init_app(app, db)
     ...
     ...
     return app

Une fois l'extension initialisée, un groupe db sera ajouté aux options de ligne de commande avec plusieurs sous-commandes. Vous trouverez ci-dessous une liste des sous-commandes disponibles :

•
flask db --help
Affiche la liste des commandes disponibles.
•
flask db list-templates
Affiche la liste des modèles de dépôts de base de données disponibles.
•
flask db init [--multidb] [--template TEMPLATE] [--package]
Initialise la prise en charge des migrations pour l'application. L'option facultative --multidb active les migrations pour plusieurs bases de données.

Crée un script de révision vide. Le script doit être édité manuellement avec les modifications de mise à niveau et de rétrogradation. Voir la documentation d'Alembic pour des instructions sur la façon d'écrire des scripts de migration. Un message de migration optionnel peut être inclus.

Équivalent à revision --autogenerate. Le script de migration est rempli avec les changements détectés automatiquement. Le script généré doit être revu et édité car tous les types de changements ne peuvent pas être détectés automatiquement. Cette commande n'apporte aucune modification à la base de données, elle crée seulement le script de migration.

Édite un script de révision en utilisant $EDITOR.

Rétrograde la base de données. Si revision n'est pas fournie, -1 est supposé.

Définit la révision dans la base de données à celle fournie en argument, sans effectuer de migrations.

Affiche la révision actuelle de la base de données.

Fusionne deux révisions. Crée un nouveau fichier de migration.

Affiche les têtes disponibles dans le répertoire des scripts de révision.
•

Affiche les points de branchement actuels.

Notes :

  • Toutes les commandes acceptent une ou plusieurs options --x-arg ARG=VALUE ou -x ARG=VALUE avec des arguments personnalisés qui peuvent être utilisés dans env.py.
  • Toutes les commandes acceptent une option --directory DIRECTORY qui pointe vers le répertoire contenant les scripts de migration. Si cet argument est omis, le répertoire utilisé est migrations.
  • Un répertoire peut également être spécifié comme argument directory au constructeur Migrate, ou dans la variable d'environnement FLASK_DB_DIRECTORY.
  • L'option --sql présente dans plusieurs commandes effectue une migration en mode 'hors ligne'. Au lieu d'exécuter les commandes de base de données, les instructions SQL qui doivent être exécutées sont imprimées sur la console.
  • Une documentation détaillée sur ces commandes se trouve sur la page de référence des commandes d'Alembic.

RÉFÉRENCE API

Les commandes exposées par l'interface en ligne de commande de Flask-Migrate peuvent également être accessibles par programme en important les fonctions du module flask_migrate. Les fonctions disponibles sont :

•
init(directory='migrations', multidb=False)
Initialise le support de migration pour l'application.
•
revision(directory='migrations', message=None, autogenerate=False, sql=False, head='head', splice=False, branch_label=None, version_path=None, rev_id=None)
Crée un script de révision vide.
•
migrate(directory='migrations', message=None, sql=False, head='head', splice=False, branch_label=None, version_path=None, rev_id=None)
Crée un script de révision automatique.
•
edit(directory='migrations', revision='head')
Édite un ou plusieurs scripts de révision en utilisant $EDITOR.
•
merge(directory='migrations', revisions='', message=None, branch_label=None, rev_id=None)
Fusionne deux révisions. Crée un nouveau fichier de migration.
•
upgrade(directory='migrations', revision='head', sql=False, tag=None)
Met à niveau la base de données.
•
downgrade(directory='migrations', revision='-1', sql=False, tag=None)
Rétrograde la base de données.
•
show(directory='migrations', revision='head')
Affiche la révision désignée par le symbole donné.
•
history(directory='migrations', rev_range=None, verbose=False)
Affiche la liste des migrations. Si une plage n'est pas fournie, tout l'historique est affiché.

heads(directory='migrations', verbose=False, resolve_dependencies=False)
Affiche les têtes disponibles dans le répertoire des scripts.
•
branches(directory='migrations', verbose=False)
Affiche les points de branchement actuels.

Définit la révision dans la base de données à celle fournie en argument, sans effectuer de migrations.

    ALEMBIC CONFIGURATION OPTIONS

    When Flask-Migrate uses Alembic, it relies on the configuration options provided in the alembic.ini file. Some of these options will be overridden by Flask-Migrate to ensure proper integration with your Flask application. The following options are managed by Flask-Migrate:

    script_location
    This option tells Alembic where to find the migration scripts. Flask-Migrate automatically sets this to the migrations directory within your Flask application's root folder.
    sqlalchemy.url
    This option specifies the database connection URL. Flask-Migrate will automatically set this to the database URL configured in your Flask application (e.g., via Flask-SQLAlchemy). If you are using multiple databases, you might need to configure this manually or use a custom callback.

    All other Alembic configuration options (e.g., version_locations, file_template, etc.) will be used as provided in your alembic.ini file. You can customize these to tailor Alembic's behavior to your specific needs.

    CONFIGURATION CALLBACKS

    Flask-Migrate provides hooks that allow you to customize Alembic's configuration and behavior. These hooks are defined in your Flask application's main module (or wherever you initialize your Flask-Migrate instance).

    • env.py: This file is part of Alembic's standard setup. Flask-Migrate automatically generates a basic env.py file for you. You can modify this file to add custom configuration logic, such as setting up database connections for multiple databases or loading custom configurations.

    Within the env.py file, you can access the current Flask application context and the database object. This allows you to perform actions like:

    • Loading your Flask application configuration.
    • Initializing your SQLAlchemy models so Alembic can detect them.
    • Setting up the database connection URL for Alembic.

    For example, you might have code in env.py like this:

    from alembic import context
from your_app import create_app, db # Assuming you have create_app and db

config = context.config

# Interpret the config file for Python logging.
# This line sets up loggers basically.
#
# if config.config_file_name is not None:
#     fileConfig(config.config_file_name)

# add your model's MetaData object here
# for 'autogenerate' support
# from myapp.models import Base
# target_metadata = Base.metadata
target_metadata = None # Flask-Migrate will handle this

# get the Flask app instance
app = create_app()
with app.app_context():
    # Access the SQLAlchemy instance and metadata
    target_metadata = db.metadata
    context.configure(
        connection=db.engine.connect(),
        target_metadata=target_metadata
        # Add other Alembic configuration options here if needed
    )

    with context.begin_transaction():
        context.run_migrations()

    The script_location option in alembic.ini will be overridden by Alembic according to the contents of the alembic.ini file.

    For greater scripting flexibility you can also use the API exposed by Alembic directly.
