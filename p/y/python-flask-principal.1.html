INTRODUCTION

Flask-Principal fournit un cadre très souple pour connecter des fournisseurs de deux types de services, souvent situés dans différentes parties d'une application web :

1.
Fournisseurs d'authentification
2.
Fournisseurs d'informations utilisateur

Par exemple, un fournisseur d'authentification peut être oauth, utilisant Flask-OAuth et les informations utilisateur peuvent être stockées dans une base de données relationnelle. La souplesse du cadre est assurée par l'utilisation de signaux comme interface.

Les principaux composants sont l'Identité, les Besoins (Needs), la Permission, et le Contexte d'Identité (IdentityContext).

1.
L'Identité représente l'utilisateur et est stockée/chargée depuis divers emplacements (par ex. session) pour chaque requête. L'Identité est l'avatar de l'utilisateur pour le système. Elle contient les droits d'accès dont dispose l'utilisateur.
2.
Un Besoin est le plus petit grain de contrôle d'accès et représente un paramètre spécifique pour la situation. Par exemple, "a le rôle d'administrateur", "peut modifier les articles de blog".

Les Besoins sont n'importe quel tuple, ou probablement des objets de votre choix, mais un tuple convient parfaitement. Les types de Besoins prédéfinis (pour économiser votre temps de frappe) sont soit des paires (méthode, valeur) où la méthode est utilisée pour spécifier des choses courantes telles que "role", "user", etc. Et la valeur est la valeur. Un exemple de tel est ('role', 'admin'). Ce qui serait un Besoin pour un rôle d'administrateur. Ou des triplets pour des cas d'utilisation tels que "La permission de modifier une instance particulière d'un objet ou d'une ligne", qui pourrait être représentée par le triplet ('article', 'edit', 46), où 46 est la clé/ID pour cette ligne/objet.

Essentiellement, comment et quels sont les Besoins dépendent largement de l'utilisateur, et est conçu de manière souple afin que tout effet puisse être atteint en utilisant des instances personnalisées comme Besoins.

Alors qu'un Besoin est une permission d'accéder à une ressource, une Identité devrait fournir un ensemble de Besoins auxquels elle a accès.

3.
Une Permission est un ensemble de conditions requises, dont l'une doit être présente pour accéder à une ressource.
4.
Un Contexte d'Identité (IdentityContext) est le contexte d'une certaine identité par rapport à une certaine Permission. Il peut être utilisé comme gestionnaire de contexte ou comme décorateur.

PROTÉGER L'ACCÈS AUX RESSOURCES

Pour les utilisateurs de Flask-Principal (pas les fournisseurs d'authentification), la restriction d'accès est facile à définir à la fois comme décorateur et comme gestionnaire de contexte. Un exemple simple de démarrage rapide est présenté avec des commentaires :

from flask import Flask, Response
from flask.ext.principal import Principal, Permission, RoleNeed
app = Flask(__name__)
# charger l'extension
principals = Principal(app)
# Créer une permission avec un seul Besoin, dans ce cas un RoleNeed.
admin_permission = Permission(RoleNeed('admin'))
# protéger une vue avec un principal pour ce besoin
@app.route('/admin')
@admin_permission.require()
def do_admin_index():
    return Response('Seulement si vous êtes un administrateur')
# cette fois, protéger avec un gestionnaire de contexte
@app.route('/articles')
def do_articles():
    with admin_permission.require():
        return Response('Seulement si vous êtes admin')

FOURNISSEURS D'AUTHENTIFICATION

Les fournisseurs d'authentification doivent utiliser le signal identity-changed pour indiquer qu'une requête a été authentifiée. Par exemple, le code suivant est un exemple hypothétique de la façon dont on pourrait combiner l'extension populaire Flask-Login http://packages.python.org/Flask-Login/ avec Flask-Principal :

from flask import Flask, current_app, request, session
from flask.ext.login import LoginManager, login_user, logout_user, \
     login_required, current_user
from flask.ext.wtf import Form, TextField, PasswordField, Required, Email
from flask.ext.principal import Principal, Identity, AnonymousIdentity, \
     identity_changed
app = Flask(__name__)
Principal(app)
login_manager = LoginManager(app)
@login_manager.user_loader
def load_user(userid):
    # Retourner une instance du modèle User
    return datastore.find_user(id=userid)
class LoginForm(Form):
    email = TextField()
    password = PasswordField()
@app.route('/login', methods=['GET', 'POST'])
def login():
    # Un formulaire de connexion hypothétique qui utilise Flask-WTF
    form = LoginForm()
    # Valider les entrées du formulaire
    if form.validate_on_submit():
        # Récupérer l'utilisateur de la datastore hypothétique
        user = datastore.find_user(email=form.email.data)
        # Comparer les mots de passe (utiliser le hachage de mot de passe en production)
        if form.password.data == user.password:
            # Conserver les informations de l'utilisateur dans la session à l'aide de Flask-Login
            login_user(user)
            # Informer Flask-Principal que l'identité a changé
            identity_changed.send(current_app._get_current_object(),
                                  identity=Identity(user.id))
            return redirect(request.args.get('next') or '/')
    return render_template('login.html', form=form)
@app.route('/logout')
@login_required
def logout():
    # Supprimer les informations de l'utilisateur de la session
    logout_user()
    # Supprimer les clés de session définies par Flask-Principal
    for key in ('identity.name', 'identity.auth_type'):
        session.pop(key, None)
    # Informer Flask-Principal que l'utilisateur est anonyme
    identity_changed.send(current_app._get_current_object(),
                          identity=AnonymousIdentity())
    return redirect(request.args.get('next') or '/')

FOURNISSEURS D'INFORMATIONS UTILISATEUR

Les fournisseurs d'informations utilisateur doivent se connecter au signal identity-loaded pour ajouter toute information supplémentaire à l'instance d'Identité, telle que les rôles. L'exemple suivant est un autre exemple hypothétique utilisant Flask-Login et pourrait être combiné avec l'exemple précédent. Il montre comment utiliser un schéma de permission basé sur les rôles :

from flask.ext.login import current_user
from flask.ext.principal import identity_loaded, RoleNeed, UserNeed
@identity_loaded.connect_via(app)
def on_identity_loaded(sender, identity):
    # Définir l'objet utilisateur de l'identité
    identity.user = current_user
    # Ajouter le UserNeed à l'identité
    if hasattr(current_user, 'id'):
        identity.provides.add(UserNeed(current_user.id))
    # En supposant que le modèle User a une liste de rôles, mettre à jour l'
    # identité avec les rôles que l'utilisateur fournit
    if hasattr(current_user, 'roles'):
        for role in current_user.roles:
            identity.provides.add(RoleNeed(role.name))

La prochaine étape consistera à protéger le point de terminaison qui permet à un utilisateur de modifier un article. Ceci est fait en créant un objet de permission à la volée à l'aide de l'ID de la ressource, dans ce cas le billet de blog :

@app.route('/posts/<post_id>', methods=['PUT', 'PATCH'])
def edit_post(post_id):
    permission = EditBlogPostPermission(post_id)
    if permission.can():
        # Enregistrer les modifications ...
        return render_template('edit_post.html')
    abort(403)  # HTTP Interdit

DÉMARRAGE DE L'EXTENSION

class flask_principal.Principal(app=None, use_sessions=True, skip_static=False)
Extension principale
Paramètres
  • app -- L'application Flask à étendre
  • use_sessions -- Faut-il utiliser les sessions pour extraire et stocker l'identification.
  • skip_static -- Faut-il ignorer les points de terminaison statiques.
identity_loader(f)
Décorateur pour définir une fonction comme chargeur d'identité.

Une fonction de chargeur d'identité est appelée avant la requête pour trouver les identités fournies. La première identité trouvée est utilisée pour charger à partir de.

Par exemple :

app = Flask(__name__)
principals = Principal(app)
@principals.identity_loader
def load_identity_from_weird_usecase():
    return Identity('ali')
identity_saver(f)
Décorateur pour définir une fonction comme enregistreur d'identité.

Un enregistreur de chargeur d'identité est appelé lorsque l'identité est définie pour la persister pour la prochaine requête.

Par exemple :

app = Flask(__name__)
principals = Principal(app)
@principals.identity_saver
def save_identity_to_weird_usecase(identity):
    my_special_cookie['identity'] = identity
set_identity(identity)
Définit l'identité actuelle.
Paramètres
identity -- L'identité à définir

TYPES PRINCIPAUX

class flask_principal.Permission(*needs)
Représente les besoins, dont l'un ou l'autre doit être présent pour accéder à une ressource
Paramètres
needs -- Les besoins pour cette permission
allows(identity)
L'identité peut-elle accéder à cette permission.
Paramètres
identity -- L'identité
can()
Le contexte requis pour cette permission a-t-il accès

Ceci crée un contexte d'identité et teste s'il peut accéder à cette permission

difference(other)
Crée une nouvelle permission composée des exigences de cette permission et non de l'autre.
issubset(other)
Les besoins de cette permission sont-ils un sous-ensemble d'un autre
Paramètres
other -- L'autre permission
require(http_exception=None)
Crée un principal pour cette permission.

Le principal peut être utilisé comme gestionnaire de contexte ou comme décorateur.

Si http_exception est passé, abort() sera appelé avec le code d'exception HTTP. Sinon, une exception PermissionDenied sera levée si l'identité ne répond pas aux exigences.

Paramètres
http_exception -- le code d'exception HTTP (403, 401 etc)
reverse()
Retourne l'inverse de l'état actuel (besoins->exclusions, exclusions->besoins)
test(http_exception=None)
Vérifie si la permission est disponible et lève l'exception pertinente si ce n'est pas le cas. Ceci est utile si vous souhaitez simplement vérifier la permission sans envelopper tout dans un bloc require().

Ceci est équivalent à :

with permission.require():
    pass
union(other)
Crée une nouvelle permission avec les exigences de l'union de celle-ci et de l'autre.
Paramètres
other -- L'autre permission
class flask_principal.Identity(id, auth_type=None)
Représente l'identité de l'utilisateur.
Paramètres
  • id -- L'ID de l'utilisateur
  • auth_type -- Le type d'authentification utilisé pour confirmer l'identité de l'utilisateur.

L'identité est utilisée pour représenter l'identité de l'utilisateur dans le système. Cet objet est créé lors de la connexion, ou au début de la requête tel que chargé à partir de la session de l'utilisateur.

Une fois chargé, il est envoyé via le signal identity-loaded et doit être rempli avec des informations supplémentaires requises.

Les besoins fournis par cette identité doivent être ajoutés à l'ensemble provides après le chargement.

can(permission)
L'identité a-t-elle accès à la permission.
Paramètres
permission -- La permission à tester.
class flask_principal.AnonymousIdentity
Une identité anonyme
class flask_principal.IdentityContext(permission, http_exception=None)
Le contexte d'une identité pour une permission.

Note :

Le principal est généralement créé par l'appel de la méthode flaskext.Permission.require pour les cas d'utilisation normaux.

Le principal se comporte soit comme un gestionnaire de contexte, soit comme un décorateur. La permission est vérifiée pour la fourniture dans l'identité, et si elle est disponible, le flux continue (gestionnaire de contexte) ou la fonction est exécutée (décorateur).

can()
L'identité a-t-elle accès à la permission
http_exception
La permission de ce principal
property identity
L'identité de ce principal

TYPES DE BESOINS PRÉDÉFINIS

class flask_principal.Need(method, value)
Un besoin requis

Ceci est juste un tuple nommé, et pratiquement n'importe quel tuple fera l'affaire.

L'attribut method peut être utilisé pour rechercher l'élément 0, et l'attribut value peut être utilisé pour rechercher l'élément 1.

flask_principal.RoleNeed
alias de functools.partial(<class 'flask_principal.Need'>, 'role')
flask_principal.UserNeed
alias de functools.partial(<class 'flask_principal.Need'>, 'id')
class flask_principal.ItemNeed(method, value, type)
Un besoin d'article requis

Un besoin d'article est juste un tuple nommé, et pratiquement n'importe quel tuple fera l'affaire. En plus des autres besoins, il y a un type

SIGNALS

identity_changed
Signal envoyé lorsque l'identité d'une requête a été modifiée.
identity_loaded
Signal envoyé lorsque l'identité a été initialisée pour une requête.
