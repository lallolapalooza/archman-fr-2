Installation

Installez ou mettez à jour avec pip.

pip install -U https://github.com/wtforms/flask-wtf/archive/main.tar.gz

Démarrage rapide

Hâte de commencer ? Cette page donne une bonne introduction à Flask-WTF. Elle suppose que vous avez déjà Flask-WTF installé. Si ce n'est pas le cas, dirigez-vous vers la section Installation.

Création de formulaires

Flask-WTF fournit l'intégration de votre application Flask avec WTForms. Par exemple :

from flask_wtf import FlaskForm
from wtforms import StringField
from wtforms.validators import DataRequired
class MyForm(FlaskForm):
    name = StringField('name', validators=[DataRequired()])

NOTE :

À partir de la version 0.9.0, Flask-WTF n'importera rien de wtforms, vous devez importer les champs depuis wtforms.

En outre, un champ caché de jeton CSRF est créé automatiquement. Vous pouvez le rendre dans votre modèle :

<form method="POST" action="/">
    {{ form.csrf_token }}
    {{ form.name.label }} {{ form.name(size=20) }}
    <input type="submit" value="Go">
</form>

Si votre formulaire contient plusieurs champs cachés, vous pouvez les rendre en un bloc en utilisant hidden_tag().

<form method="POST" action="/">
    {{ form.hidden_tag() }}
    {{ form.name.label }} {{ form.name(size=20) }}
    <input type="submit" value="Go">
</form>

Validation des formulaires

Validation de la requête dans vos gestionnaires de vues :

@app.route('/submit', methods=['GET', 'POST'])
def submit():
    form = MyForm()
    if form.validate_on_submit():
        return redirect('/success')
    return render_template('submit.html', form=form)

Notez que vous n'avez pas besoin de passer request.form à Flask-WTF ; il le chargera automatiquement. Et la pratique validate_on_submit vérifiera s'il s'agit d'une requête POST et si elle est valide.

Si vos formulaires incluent une validation, vous devrez ajouter à votre modèle pour afficher les messages d'erreur. En utilisant le champ form.name de l'exemple ci-dessus, cela ressemblerait à ceci :

{% if form.name.errors %}
    <ul class="errors">
    {% for error in form.name.errors %}
        <li>{{ error }}</li>
    {% endfor %}
    </ul>
{% endif %}

Dirigez-vous vers Création de formulaires pour en apprendre davantage.

Création de formulaires

Formulaire sécurisé

Sans aucune configuration, FlaskForm sera un formulaire sécurisé par session avec protection csrf. Nous vous encourageons à ne pas changer cela.

Mais si vous souhaitez désactiver la protection csrf, vous pouvez passer :

form = FlaskForm(meta={'csrf': False})

Vous pouvez la désactiver globalement — bien que vous ne devriez vraiment pas — avec la configuration :

WTF_CSRF_ENABLED = False

Pour générer le jeton csrf, vous devez avoir une clé secrète, c'est généralement la même que la clé secrète de votre application Flask. Si vous souhaitez utiliser une autre clé secrète, configurez-la :

WTF_CSRF_SECRET_KEY = 'a random string'

Téléversements de fichiers

Le FileField fourni par Flask-WTF diffère du champ fourni par WTForms. Il vérifiera que le fichier est une instance non vide de FileStorage, sinon data sera None.

from flask_wtf import FlaskForm
from flask_wtf.file import FileField, FileRequired
from werkzeug.utils import secure_filename
class PhotoForm(FlaskForm):
    photo = FileField(validators=[FileRequired()])
@app.route('/upload', methods=['GET', 'POST'])
def upload():
    form = PhotoForm()
    if form.validate_on_submit():
        f = form.photo.data
        filename = secure_filename(f.filename)
        f.save(os.path.join(
            app.instance_path, 'photos', filename
        ))
        return redirect(url_for('index'))
    return render_template('upload.html', form=form)

De même, vous pouvez utiliser le MultipleFileField fourni par Flask-WTF pour gérer plusieurs fichiers. Il vérifiera que les fichiers sont une liste d'instances non vides de FileStorage, sinon data sera None.

from flask_wtf import FlaskForm
from flask_wtf.file import MultipleFileField, FileRequired
from werkzeug.utils import secure_filename
class PhotoForm(FlaskForm):
    photos = MultipleFileField(validators=[FileRequired()])
@app.route('/upload', methods=['GET', 'POST'])
def upload():
    form = PhotoForm()
    if form.validate_on_submit():
        for f in form.photo.data:  # form.photo.data retourne une liste d'objets FileStorage
            filename = secure_filename(f.filename)
            f.save(os.path.join(
                app.instance_path, 'photos', filename
            ))
        return redirect(url_for('index'))
    return render_template('upload.html', form=form)

N'oubliez pas de définir l'attribut enctype du formulaire HTML sur multipart/form-data, sinon request.files sera vide.

<form method="POST" enctype="multipart/form-data">
    ...
</form>

Flask-WTF gère le passage des données du formulaire au formulaire pour vous. Si vous passez explicitement les données, n'oubliez pas que request.form doit être combiné avec request.files pour que le formulaire voie les données du fichier.

form = PhotoForm()
# est équivalent à :
from flask import request
from werkzeug.datastructures import CombinedMultiDict
form = PhotoForm(CombinedMultiDict((request.files, request.form)))

Validation

Flask-WTF prend en charge la validation des téléversements de fichiers avec FileRequired, FileAllowed et FileSize. Ils

peut être utilisé avec les classes FileField et MultipleFileField de Flask-WTF et de WTForms.

FileAllowed fonctionne bien avec Flask-Uploads.

from flask_uploads import UploadSet, IMAGES
from flask_wtf import FlaskForm
from flask_wtf.file import FileField, FileAllowed, FileRequired
images = UploadSet('images', IMAGES)
class UploadForm(FlaskForm):
    upload = FileField('image', validators=[
        FileRequired(),
        FileAllowed(images, 'Images only!')
    ])

Il peut être utilisé sans Flask-Uploads en passant directement les extensions.

class UploadForm(FlaskForm):
    upload = FileField('image', validators=[
        FileRequired(),
        FileAllowed(['jpg', 'png'], 'Images only!')
    ])

Recaptcha

Flask-WTF fournit également un support Recaptcha via un RecaptchaField :

from flask_wtf import FlaskForm, RecaptchaField
from wtforms import TextField
class SignupForm(FlaskForm):
    username = TextField('Username')
    recaptcha = RecaptchaField()

Ceci est accompagné d'un certain nombre de variables de configuration, dont certaines doivent être configurées.

RECAPTCHA_PUBLIC_KEY requis Une clé publique.
RECAPTCHA_PRIVATE_KEY requis Une clé privée.
RECAPTCHA_API_SERVER optionnel Spécifiez votre serveur d'API Recaptcha.
RECAPTCHA_PARAMETERS optionnel Un dictionnaire de paramètres JavaScript (api.js).
RECAPTCHA_DATA_ATTRS optionnel Un dictionnaire d'options d'attributs data. https://developers.google.com/recaptcha/docs/display#javascript_resource_apijs_parameters

Exemple de RECAPTCHA_PARAMETERS et RECAPTCHA_DATA_ATTRS :

RECAPTCHA_PARAMETERS = {'hl': 'zh', 'render': 'explicit'}
RECAPTCHA_DATA_ATTRS = {'theme': 'dark'}

Pour votre commodité, lors des tests de votre application, si app.testing est True, le champ recaptcha sera toujours valide.

Protection CSRF

Toute vue utilisant FlaskForm pour traiter la requête bénéficie déjà de la protection CSRF. Si vous avez des vues qui n'utilisent pas FlaskForm ou qui font des requêtes AJAX, utilisez l'extension CSRF fournie pour protéger également ces requêtes.

Configuration

Pour activer la protection CSRF globalement pour une application Flask, enregistrez l'extension CSRFProtect.

from flask_wtf.csrf import CSRFProtect
csrf = CSRFProtect(app)

Comme les autres extensions Flask, vous pouvez l'appliquer de manière différée :

csrf = CSRFProtect()
def create_app():
    app = Flask(__name__)
    csrf.init_app(app)

NOTE :

La protection CSRF nécessite une clé secrète pour signer sécuritairement le jeton. Par défaut, elle utilisera la SECRET_KEY de l'application Flask. Si vous souhaitez utiliser un jeton séparé, vous pouvez définir WTF_CSRF_SECRET_KEY.

Formulaires HTML

Lors de l'utilisation d'un FlaskForm, affichez le champ CSRF du formulaire comme d'habitude.

<form method="post">
    {{ form.csrf_token }}
</form>

Si le template n'utilise pas de FlaskForm, affichez une entrée cachée avec le jeton dans le formulaire.

<form method="post">
    <input type="hidden" name="csrf_token" value="{{ csrf_token() }}"/>
</form>

Requêtes JavaScript

Lors de l'envoi d'une requête AJAX, ajoutez l'en-tête X-CSRFToken à celle-ci. Par exemple, en jQuery, vous pouvez configurer toutes les requêtes pour envoyer le jeton.

<script type="text/javascript">
    var csrf_token = "{{ csrf_token() }}";
    $.ajaxSetup({
        beforeSend: function(xhr, settings) {
            if (!/^(GET|HEAD|OPTIONS|TRACE)$/i.test(settings.type) && !this.crossDomain) {
                xhr.setRequestHeader("X-CSRFToken", csrf_token);
            }
        }
    });
</script>

Dans Axios, vous pouvez définir l'en-tête pour toutes les requêtes avec axios.defaults.headers.common.

from flask_wtf.csrf import CSRFError
@app.errorhandler(CSRFError)
def handle_csrf_error(e):
    return render_template('csrf_error.html', reason=e.description), 400

Exclure des vues de la protection

Nous vous suggérons fortement de protéger toutes vos vues avec CSRF. Mais si nécessaire, vous pouvez exclure certaines vues à l'aide d'un décorateur.

@app.route('/foo', methods=('GET', 'POST'))
@csrf.exempt
def my_handler():
    # ...
    return 'ok'

Vous pouvez exclure toutes les vues d'un blueprint.

csrf.exempt(account_blueprint)

Vous pouvez désactiver la protection CSRF dans toutes les vues par défaut, en définissant WTF_CSRF_CHECK_DEFAULT sur False, et appeler sélectivement protect() uniquement lorsque vous en avez besoin. Cela vous permet également de faire un prétraitement sur les requêtes avant de vérifier le jeton CSRF.

Comment contribuer à Flask-WTF

Merci de considérer contribuer à Flask-WTF !

Questions de support

Veuillez ne pas utiliser le tracker de problèmes pour cela. Le tracker de problèmes est un outil pour résoudre les bugs et les demandes de fonctionnalités dans Flask-WTF lui-même. Utilisez l'une des ressources suivantes pour les questions sur l'utilisation de Flask-WTF ou les problèmes avec votre propre code :

  • Le canal #get-help sur notre chat Discord : https://discord.gg/pallets
  • La liste de diffusion flask@python.org pour les discussions à long terme ou les problèmes plus importants.
  • Posez des questions sur Stack Overflow. Recherchez d'abord sur Google en utilisant : site:stackoverflow.com flask-wtf {terme de recherche, message d'exception, etc.}

Signaler des problèmes

Incluez les informations suivantes dans votre publication :

  • Décrivez ce que vous attendiez qu'il se passe.
  • Si possible, incluez un exemple minimal reproductible pour nous aider à identifier le problème. Cela permet également de vérifier que le problème ne vient pas de votre propre code.
  • Décrivez ce qui s'est réellement passé. Incluez la trace complète s'il y a eu une exception.
  • Listez vos versions de Python, Flask-WTF et WTForms. Si possible, vérifiez si ce problème est déjà résolu dans les dernières versions ou dans le dernier code du dépôt.

Soumettre des corrections

S'il n'y a pas de problème ouvert pour ce que vous souhaitez soumettre, préférez en ouvrir un pour discussion avant de travailler sur une PR. Vous pouvez travailler sur n'importe quel problème qui n'a pas de PR ouverte qui y est liée ou un mainteneur qui lui est assigné. Ceux-ci apparaissent dans la barre latérale. Pas besoin de demander si vous pouvez travailler sur un problème qui vous intéresse.

Incluez ce qui suit dans votre correctif :

  • Utilisez Black pour formater votre code. Cela et d'autres outils s'exécuteront automatiquement si vous installez pre-commit en suivant les instructions ci-dessous.
  • Incluez des tests si votre correctif ajoute ou modifie du code. Assurez-vous que le test échoue sans votre correctif.
  • Mettez à jour toutes les pages de documentation et les docstrings pertinentes. Les pages de documentation et les docstrings doivent être limitées à 72 caractères.
  • Ajoutez une entrée dans CHANGES.rst. Utilisez le même style que les autres entrées. Incluez également des changements .. versionchanged:: dans les docstrings pertinentes.

Configuration initiale

  • Téléchargez et installez la dernière version de git.
  • Configurez git avec votre nom d'utilisateur et votre adresse e-mail.

Flask integration for WTForms

FEATURES

Here are some of the features:

  • A Flask-WTF form factory for easy creation of forms.
  • CSRF protection for forms.
  • File uploads with secure handling.
  • Integration with Flask's request/response cycle.

USER'S GUIDE

This section provides instructions for setting up and using Flask-WTF.

Installation

Install the package using pip:

$ pip install Flask-WTF

Basic Usage

Here's a simple example of how to use Flask-WTF in a Flask application:

from flask import Flask, render_template, request
from flask_wtf import FlaskForm
from wtforms import StringField, SubmitField
from wtforms.validators import DataRequired

app = Flask(__name__)
# Replace with your own secret key
app.config['SECRET_KEY'] = 'your_secret_key_here'

class MyForm(FlaskForm):
    name = StringField('Name', validators=[DataRequired()])
    submit = SubmitField('Submit')

@app.route('/', methods=['GET', 'POST'])
def index():
    form = MyForm()
    if form.validate_on_submit():
        name = form.name.data
        return f'Hello, {name}!'
    return render_template('index.html', form=form)

if __name__ == '__main__':
    app.run(debug=True)

And in your HTML template (e.g., templates/index.html):

<!DOCTYPE html>
<html>
<head>
    <title>My Form</title>
</head>
<body>
    <form method="POST">
        {{ form.csrf_token }}
        {{ form.name.label }} {{ form.name() }}
        {{ form.submit() }}
    </form>
</body>
</html>

CSRF Protection

Flask-WTF provides CSRF (Cross-Site Request Forgery) protection out of the box. Ensure you have set a SECRET_KEY in your Flask application configuration.

app.config['SECRET_KEY'] = 'a_very_secret_key'

The form factory automatically includes a CSRF token field in your forms. You just need to render it in your template using {{ form.csrf_token }}.

File Uploads

Flask-WTF supports file uploads through the FileField type from WTForms.

from wtforms import FileField, SubmitField
from wtforms.validators import DataRequired

class UploadForm(FlaskForm):
    upload = FileField('File', validators=[DataRequired()])
    submit = SubmitField('Upload')

In your template, ensure the form has enctype="multipart/form-data":

<form method="POST" enctype="multipart/form-data">
    {{ form.csrf_token }}
    {{ form.upload() }}
    {{ form.submit() }}
</form>

In your Flask route, access the uploaded file via request.files:

@app.route('/upload', methods=['GET', 'POST'])
def upload_file():
    form = UploadForm()
    if form.validate_on_submit():
        f = form.upload.data
        # Process the file, e.g., save it
        f.save('uploads/' + f.filename)
        return 'File uploaded successfully'
    return render_template('upload.html', form=form)

ADDITIONAL NOTES

Contributing

Contributions are welcome! If you find a bug or have a feature request, please open an issue on the GitHub repository. If you plan to submit a pull request, please follow these steps:

  • Fork the repository.
  • Create a new branch for your feature or fix.
  • Make your changes and add tests.
  • Run the tests to ensure everything works.
  • Commit your changes.
  • Push your branch to your fork.
  • Open a pull request.

Please reference any relevant issues, for example, fixes #123, in your pull request description.

$ git push --set-upstream fork your-branch-name

Running the tests

Run the basic test suite with pytest.

$ pytest

This runs the tests for the current environment, which is usually sufficient. CI will run the full suite when you submit your pull request. You can run the full test suite with tox if you don't want to wait.

$ tox

Running test coverage

Generating a report of lines that do not have test coverage can indicate where to start contributing. Run pytest using coverage and generate a report.

$ pip install coverage
$ coverage run -m pytest
$ coverage html

Open htmlcov/index.html in your browser to explore the report.

Building the docs

Build the docs in the docs directory using Sphinx.

$ cd docs
$ make html

Open _build/html/index.html in your browser to view the docs.
