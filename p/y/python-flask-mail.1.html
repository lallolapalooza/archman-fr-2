INSTALLATION DE FLASK-MAIL

Installez avec pip et easy_install:

pip install Flask-Mail

ou téléchargez la dernière version depuis le contrôle de version:

git clone https://github.com/mattupstate/flask-mail.git
cd flask-mail
python setup.py install

Si vous utilisez virtualenv, il est supposé que vous installez flask-mail dans le même virtualenv que votre/vos application(s) Flask.

CONFIGURATION DE FLASK-MAIL

Flask-Mail est configuré via l'API de configuration standard de Flask. Ce sont les options disponibles (chacune est expliquée plus loin dans la documentation):

  • MAIL_SERVER : par défaut 'localhost'
  • MAIL_PORT : par défaut 25
  • MAIL_USE_TLS : par défaut False
  • MAIL_USE_SSL : par défaut False
  • MAIL_DEBUG : par défaut app.debug
  • MAIL_USERNAME : par défaut None
  • MAIL_PASSWORD : par défaut None
  • MAIL_DEFAULT_SENDER : par défaut None
  • MAIL_MAX_EMAILS : par défaut None
  • MAIL_SUPPRESS_SEND : par défaut app.testing
  • MAIL_ASCII_ATTACHMENTS : par défaut False

En outre, l'option de configuration standard de Flask TESTING est utilisée par Flask-Mail dans les tests unitaires (voir ci-dessous).

Les e-mails sont gérés via une instance Mail:

from flask import Flask
from flask_mail import Mail
app = Flask(__name__)
mail = Mail(app)

Dans ce cas, tous les e-mails sont envoyés en utilisant les valeurs de configuration de l'application qui a été passée au constructeur de la classe Mail.

Alternativement, vous pouvez configurer votre instance Mail plus tard, au moment de la configuration, en utilisant la méthode init_app:

mail = Mail()
app = Flask(__name__)
mail.init_app(app)

Dans ce cas, les e-mails seront envoyés en utilisant les valeurs de configuration du contexte global current_app de Flask. Ceci est utile si vous avez plusieurs applications fonctionnant dans le même processus mais avec des options de configuration différentes.

ENVOI DE MESSAGES

Pour envoyer un message, créez d'abord une instance Message:

from flask_mail import Message
@app.route("/")
def index():
    msg = Message("Bonjour",
                  sender="from@example.com",
                  recipients=["to@example.com"])

Vous pouvez définir les adresses e-mail des destinataires immédiatement, ou individuellement:

msg.recipients = ["you@example.com"]
msg.add_recipient("somebodyelse@example.com")

Si MAIL_DEFAULT_SENDER est défini, vous n'avez pas besoin de spécifier l'expéditeur du message explicitement, car il utilisera cette valeur de configuration par défaut:

msg = Message("Bonjour",
              recipients=["to@example.com"])

Si l'expéditeur est un tuple à deux éléments, il sera divisé en nom et adresse:

msg = Message("Bonjour",
              sender=("Moi", "me@example.com"))
assert msg.sender == "Moi <me@example.com>"

Le message peut contenir un corps et/ou du HTML:

msg.body = "test"
msg.html = "<b>test</b>"

Enfin, pour envoyer le message, vous utilisez l'instance Mail configurée avec votre application Flask:

mail.send(msg)

EMAILS EN MASSE

Habituellement, dans une application web, vous enverrez un ou deux e-mails par requête. Dans certaines situations, vous pourriez vouloir envoyer des dizaines ou des centaines d'e-mails en un seul lot - probablement dans un processus externe comme un script en ligne de commande ou une tâche cron.

Dans ce cas, vous faites les choses légèrement différemment:

with mail.connect() as conn:
    for user in users:
        message = '...'
        subject = "bonjour, %s" % user.name
        msg = Message(recipients=[user.email],
                      body=message,
                      subject=subject)
        conn.send(msg)

La connexion à votre serveur de messagerie est maintenue et fermée automatiquement une fois que tous les messages ont été envoyés.

Certains serveurs de messagerie limitent le nombre d'e-mails envoyés lors d'une seule connexion. Vous pouvez définir le nombre maximum d'e-mails à envoyer avant de se reconnecter en spécifiant le paramètre MAIL_MAX_EMAILS.

PIÈCES JOINTES

L'ajout de pièces jointes est simple:

with app.open_resource("image.png") as fp:
    msg.attach("image.png", "image/png", fp.read())

Voir l'API pour les détails.

Si MAIL_ASCII_ATTACHMENTS est défini sur True, les noms de fichiers seront convertis en un équivalent ASCII. Cela peut être utile lors de l'utilisation d'un relais de messagerie qui modifie le contenu des e-mails et perturbe la spécification Content-Disposition lorsque les noms de fichiers sont encodés en UTF-8. La conversion en ASCII est une suppression basique des caractères non-ASCII. Cela devrait fonctionner pour tout caractère unicode qui peut être décomposé par NFKD en un ou plusieurs caractères ASCII. Si vous avez besoin de romanisation/translitération (par exemple ß → ss), votre application doit s'en charger et passer une chaîne ASCII appropriée.

TESTS UNITAIRES ET SUPPRESSION DES EMAILS

Lorsque vous envoyez des messages dans des tests unitaires, ou dans un environnement de développement, il est utile de pouvoir supprimer l'envoi d'e-mails.

Si le paramètre TESTING est défini sur True, les e-mails seront supprimés. L'appel de send() sur vos messages n'entraînera pas l'envoi réel de messages.

Alternativement, en dehors d'un environnement de test, vous pouvez définir MAIL_SUPPRESS_SEND sur False. Cela aura le même effet.

Cependant, il est toujours utile de suivre les e-mails qui auraient été envoyés lorsque vous écrivez des tests unitaires.

Afin de suivre les e-mails envoyés, utilisez la méthode record_messages:

with mail.record_messages() as outbox:
    mail.send_message(subject='test',
                      body='test',
                      recipients=emails)
    assert len(outbox) == 1
    assert outbox[0].subject == "test"

L'outbox est une liste d'instances Message envoyées.

Le paquet blinker doit être installé pour que cette méthode fonctionne.

Notez que l'ancienne façon de faire, ajouter l'outbox à l'objet g, est maintenant dépréciée.

SUPPORT DE SIGNALISATION

Ajouté dans la version 0.4.

Flask-Mail fournit désormais un support de signalisation via un signal email_dispatched. Celui-ci est envoyé chaque fois qu'un email est dépêché (même si l'email n'est pas réellement envoyé, par exemple dans un environnement de test).

Une fonction se connectant au signal email_dispatched prend un instance de Message comme premier argument, et une instance de l'application Flask comme argument optionnel :

def log_message(message, app):
    app.logger.debug(message.subject)
email_dispatched.connect(log_message)
