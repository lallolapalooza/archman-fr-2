Flask-Paranoid est une extension simple pour le microframework Flask qui protège l'application contre certaines attaques dans lesquelles le cookie de session de l'utilisateur est volé puis utilisé par l'attaquant.

Lorsqu'un client se connecte à l'application pour la première fois, un jeton représentant certaines caractéristiques de ce client est généré et stocké. Lors des requêtes successives envoyées par ce client, ce jeton est régénéré et comparé au jeton stocké. Si les jetons sont différents, on suppose que le client envoie des requêtes depuis un environnement différent de celui dans lequel la session a été initialement créée. Dans ce cas, la session est détruite et la requête est rejetée à titre préventif.

Par défaut, le jeton est généré à partir de l'adresse IP et de l'agent utilisateur du client. Cela signifie que si un cookie de session d'utilisateur est volé puis utilisé depuis un emplacement différent ou un navigateur différent, le jeton généré changera, et cela bloquera cette requête "différente".

L'idée est basée sur la fonctionnalité de protection de session forte de Flask-Login, mais généralisée pour pouvoir être utilisée en dehors du contexte de Flask-Login. La génération et le stockage des jetons peuvent être personnalisés pour s'adapter à différents types d'applications.

Voici une application simple qui utilise Flask-Paranoid pour protéger la session utilisateur :

from flask import Flask
from flask_paranoid import Paranoid
app = Flask(__name__)
app.config['SECRET_KEY'] = 'top-secret!'
paranoid = Paranoid(app)
paranoid.redirect_view = '/'
@app.route('/')
def index():
    return render_template('index.html')

Dans cet exemple, le jeton paranoid calculé lors de la requête initiale d'un client sera stocké dans la session utilisateur. Si une requête ultérieure génère un jeton différent, la session sera effacée puis une redirection vers l'URL racine sera effectuée, forçant l'attaquant potentiel à se reconnecter.

La seule configuration détermine l'action effectuée lorsqu'une session invalide est détectée, après que la session ait été effacée. Par défaut, il s'agit de renvoyer une erreur 401 au client.

Pour rediriger vers une URL donnée, définissez paranoid.redirect_view sur l'emplacement souhaité :

paranoid.redirect_view = '/login'

Les URL absolues sont également prises en charge :

paranoid.redirect_view = 'https://www.google.com'

Pour rediriger vers une route Flask enregistrée, définissez paranoid.redirect_view sur le nom du point d'entrée souhaité :

paranoid.redirect_view = 'index'

Pour rediriger vers une route à l'intérieur d'un blueprint, utilisez la même syntaxe que celle utilisée par la fonction url_for() :

paranoid.redirect_view = 'auth.login'

Pour que l'extension appelle une fonction de rappel qui génère la réponse, utilisez le décorateur paranoid.on_invalid_session. La fonction doit renvoyer une réponse Flask valide :

@paranoid.on_invalid_session
def invalid_session():
    return 'please login', 401

Comme cette extension remplace la fonctionnalité similaire de Flask-Login, il est recommandé, lors de l'utilisation des deux extensions dans une application, de désactiver la protection de session dans Flask-Login :

login_manager.session_protection = None

Flask-Paranoid détecte si Flask-Login est utilisé et, dans ce cas, efface le cookie "se souvenir de moi" en plus de la session utilisateur lors d'une détection de session invalide.

Flask-Paranoid permet aux applications de personnaliser son fonctionnement interne grâce à l'utilisation de sous-classes.

MODIFICATION DE L'ALGORITHME DE GÉNÉRATION DE JETON

L'implémentation par défaut crée un hachage SHA256 de l'adresse IP du client et de l'agent utilisateur.

Pour utiliser un algorithme de génération de jeton différent, remplacez la méthode create_token :

class MyParanoid(Paranoid):
    def create_token(self):
        pass

Cette méthode est appelée dans le contexte d'une requête, elle peut donc accéder à l'objet request pour obtenir des informations sur le client.

MODIFICATION DE L'ENDROIT DE STOCKAGE DU JETON

L'implémentation par défaut écrit le jeton paranoid dans session['_paranoid_token'].

Si un mécanisme de stockage différent est souhaité, remplacez les méthodes write_token_to_session() et get_token_from_session() :

class MyParanoid(Paranoid):
    def write_token_to_session(self, token):
        pass
    def get_token_from_session(self):
        pass

Un cas d'utilisation délicat est lorsque cette extension est utilisée avec un projet API qui n'utilise pas la session utilisateur et fournit au contraire des jetons d'authentification aux clients. Dans un tel cas, la fonction de génération de jeton de l'application peut être améliorée pour inclure le jeton paranoid. Par exemple :

def get_token(username, password):
    if validate_user(username, password):
        return encode_jwt(claims={'username': username,
                                  'paranoid_token': paranoid.create_token()})

Et ensuite, les méthodes de stockage de jeton peuvent être remplacées comme suit :

class MyParanoid(Paranoid):
    def write_token_to_session(self, token):
        # rien à faire ici, le jeton paranoid est inséré dans le JWT
        # par l'application
        pass
    def get_token_from_session(self):
        claims = decode_jwt(request.headers['X-API-TOKEN'])
        if 'paranoid_token' not in claims:
            abort(401)
        return claims['paranoid_token']

Dans cet exemple, encode_jwt et decode_jwt sont des fonctions d'application qui fonctionnent avec des jetons JWT. Le client s'authentifie en passant le jeton JWT dans l'en-tête X-API-TOKEN.

UTILISATION D'UN MÉCANISME DE NETTOYAGE DE SESSION DIFFÉRENT

Par défaut, cette extension vide le contenu de la session utilisateur, et si Flask-Login est utilisé, supprime également son cookie "se souvenir de moi".

Pour modifier ou remplacer l'algorithme de nettoyage de session, remplacez la méthode clear_session() :

class MyParanoid(Paranoid):
    def clear_session(self, response):
        pass

L'argument response passé à cette méthode est l'objet réponse qui sera renvoyé au client après le nettoyage de la session. Tous les cookies qui doivent être supprimés ou modifiés doivent être inclus dans cet objet réponse.

python-flask-paranoid(1) - Flask extension to secure your session cookies

SYNOSPIS

python-flask-paranoid

DESCRIPTION

This Flask extension helps to secure your session cookies from being easily stolen and used by attackers.

OPTIONS

This command does not take any options.

CONFIGURATION

The following configuration options can be set in your Flask application:

PARANOID_SESSION_TIMEOUT
The session timeout in seconds. Defaults to 300 (5 minutes).
PARANOID_SESSION_COOKIE_SECURE
Whether to use the secure flag on the session cookie. Defaults to True if SECRET_KEY is set.
PARANOID_SESSION_COOKIE_HTTPONLY
Whether to use the HttpOnly flag on the session cookie. Defaults to True.
PARANOID_SESSION_COOKIE_SAMESITE
The SameSite attribute for the session cookie. Defaults to Lax.
PARANOID_SESSION_COOKIE_DOMAIN
The domain for the session cookie.
PARANOID_SESSION_COOKIE_PATH
The path for the session cookie.
PARANOID_SESSION_DATA_KEY
The key used to store session data. Defaults to session.
PARANOID_SESSION_SIGNATURE_KEY
The key used to sign the session data. Defaults to the Flask application's SECRET_KEY.
PARANOID_SESSION_ENCRYPTION_KEY
The key used to encrypt the session data. Defaults to the Flask application's SECRET_KEY.
PARANOID_SESSION_ENCRYPTION_METHOD
The encryption method to use. Defaults to AES-GCM.
PARANOID_SESSION_COOKIE_NAME
The name of the session cookie. Defaults to session.
PARANOID_SESSION_COOKIE_EXPIRES
The expiration time for the session cookie in minutes. Defaults to None (session cookie).

USAGE

To use flask-paranoid, simply import and initialize the extension in your Flask application:


from flask import Flask
from flask_paranoid import Paranoid

app = Flask(__name__)
Paranoid(app)

# ... your Flask application code ...

ADVANCED CONFIGURATION

CHANGING THE ENCRYPTION ALGORITHM

You can change the encryption algorithm by setting the PARANOID_SESSION_ENCRYPTION_METHOD configuration option. Available methods include:

  • AES-GCM (default)
  • AES-CBC

app.config['PARANOID_SESSION_ENCRYPTION_METHOD'] = 'AES-CBC'

CHANGING WHERE THE TOKEN IS STORED

By default, flask-paranoid stores the session token in a cookie. You can change this by providing a custom storage backend.

For example, to store the token in the server-side cache (e.g., using Flask-Caching):


from flask import Flask
from flask_paranoid import Paranoid
from flask_caching import Cache

app = Flask(__name__)
cache = Cache(app, config={'CACHE_TYPE': 'simple'})

class CacheSessionStorage:
    def __init__(self, cache):
        self.cache = cache

    def get(self, key):
        return self.cache.get(key)

    def set(self, key, value):
        self.cache.set(key, value)

    def delete(self, key):
        self.cache.delete(key)

app.config['PARANOID_SESSION_STORAGE'] = CacheSessionStorage(cache)
Paranoid(app)

USING A DIFFERENT SESSION CLEANUP MECHANISM

By default, sessions are cleaned up when the browser is closed or when the session times out. You can implement a custom cleanup mechanism by providing a callback function.


def custom_cleanup_callback():
    # Your custom cleanup logic here
    print("Custom session cleanup!")

app.config['PARANOID_SESSION_CLEANUP_CALLBACK'] = custom_cleanup_callback
