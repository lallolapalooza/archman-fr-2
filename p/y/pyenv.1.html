NOM

pyenv - Gestion simple des versions de Python

SYNOPIS

pyenv <commande> [<arguments>]

DESCRIPTION

pyenv vous permet de passer facilement d'une version de Python à une autre. Il est simple, discret et suit la tradition UNIX des outils à usage unique qui font une chose bien.


Pour commencer à utiliser pyenv

1.
Ajoutez les lignes suivantes à $HOME/.bashrc
if command -v pyenv 1>/dev/null 2>&1; then
   eval "$(pyenv init - bash)"
fi

Ajouter cette ligne active les shims. Veuillez vous assurer que cette ligne est placée vers la fin du fichier de configuration du shell car elle manipule PATH pendant l'initialisation.

Note Debian :
Modifiez seulement votre fichier ~/.bashrc au lieu de créer
~/.bash_profile
Note Zsh : Modifiez votre fichier ~/.zshrc au lieu de ~/.bashrc

Attention : Si vous avez configuré votre système de sorte que la variable BASH_ENV pointe vers .bashrc. Vous devriez presque certainement mettre la ligne mentionnée ci-dessus dans .bash_profile, et pas dans .bashrc. Sinon, vous pourriez observer un comportement étrange, tel que pyenv entrant dans une boucle infinie. Voir #264 https://github.com/pyenv/pyenv/issues/264 pour plus de détails.

2.
Redémarrez votre shell pour que les changements de chemin prennent effet. Vous pouvez maintenant commencer à utiliser pyenv.
exec "$SHELL"
3.
Installez les versions de Python dans $(pyenv root)/versions. Par exemple, pour télécharger et installer Python 3.6.12, exécutez :
pyenv install 3.6.12

NOTE : Si vous avez besoin de passer des options de configuration pour la compilation, veuillez utiliser la variable d'environnement CONFIGURE_OPTS. Si vous rencontrez des problèmes pour installer une version de Python, veuillez consulter la page wiki sur les problèmes de compilation courants https://github.com/pyenv/pyenv/wiki/Common-build-problems

Note Proxy : Si vous utilisez un proxy, exportez les variables d'environnement HTTP_PROXY et HTTPS_PROXY.

Arrêter d'utiliser pyenv

La simplicité de pyenv le rend facile à désactiver temporairement, ou à désinstaller du système. Pour désactiver la gestion de vos versions de Python par pyenv, supprimez simplement la ligne pyenv init de la configuration de démarrage de votre shell. Cela supprimera le répertoire des shims de pyenv du PATH, et les invocations futures comme python exécuteront la version système de Python, comme avant pyenv.

pyenv sera toujours accessible en ligne de commande, mais vos applications Python ne seront pas affectées par le changement de version.

COMPARAISON

pyenv fait...

  • Vous permet de changer la version globale de Python par utilisateur.
  • Offre un support pour les versions de Python par projet.
  • Vous permet de remplacer la version de Python avec une variable d'environnement.
  • Recherche les commandes à partir de plusieurs versions de Python à la fois. Cela peut être utile pour tester différentes versions de Python avec tox

Contrairement à pythonbrew et pythonz, pyenv ne...

  • Dépend pas de Python lui-même. pyenv est construit à partir de scripts shell purs. Il n'y a pas de problème d'amorçage de Python.
  • N'a pas besoin d'être chargé dans votre shell. Au lieu de cela, l'approche de pyenv utilise des shims qui fonctionnent en ajoutant un répertoire à votre $PATH.
  • Ne gère pas virtualenv. Bien sûr, vous pouvez créer virtualenv vous-même, ou utiliser pyenv-virtualenv pour automatiser le processus.

Comment ça marche

À un niveau élevé, pyenv intercepte les commandes Python à l'aide d'exécutables shim injectés dans votre PATH, détermine quelle version de Python a été spécifiée par votre application, et transmet vos commandes à l'installation Python correcte.

Comprendre PATH

Lorsque vous exécutez une commande comme python ou pip, votre système d'exploitation recherche dans une liste de répertoires un fichier exécutable portant ce nom. Cette liste de répertoires se trouve dans une variable d'environnement appelée PATH, chaque répertoire de la liste étant séparé par un deux-points :

/usr/local/bin:/usr/bin:/bin

Les répertoires dans PATH sont recherchés de gauche à droite, donc un exécutable correspondant dans un répertoire au début de la liste a la préséance sur un autre à la fin. Dans cet exemple, le répertoire /usr/local/bin sera recherché en premier, puis /usr/bin

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

, puis /bin.

Comprendre les shims

pyenv fonctionne en insérant un répertoire de shims au début de votre PATH :

$(pyenv root)/shims:/usr/local/bin:/usr/bin:/bin

Grâce à un processus appelé rehashing, pyenv maintient des shims dans ce répertoire pour correspondre à chaque commande Python (python,pip,etc...) parmi toutes les versions installées de Python.

Les shims sont des exécutables légers qui transmettent simplement votre commande à pyenv. Ainsi, avec pyenv installé, lorsque vous exécutez, par exemple, pip, votre système d'exploitation fera ce qui suit :

  • Recherchez dans votre PATH un fichier exécutable nommé pip
  • Trouvez le shim pyenv nommé pip au début de votre PATH
  • Exécutez le shim nommé pip, qui à son tour transmet la commande à pyenv

Choisir la version de Python

Lorsque vous exécutez un shim, pyenv détermine quelle version de Python utiliser en la lisant à partir des sources suivantes, dans cet ordre :

1.
La variable d'environnement PYENV_VERSION (si spécifiée). Vous pouvez utiliser la commande pyenv shell pour définir cette variable d'environnement dans votre session shell actuelle.
2.
Le fichier .python-version spécifique à l'application dans le répertoire actuel (s'il est présent). Vous pouvez modifier le fichier .python-version du répertoire actuel avec la commande pyenv local.
3.
Le premier fichier .python-version trouvé (le cas échéant) en parcourant chaque répertoire parent, jusqu'à atteindre la racine de votre système de fichiers.
4.
Le fichier global $(pyenv root)/version. Vous pouvez modifier ce fichier en utilisant la commande pyenv global. Si le fichier de version globale n'est pas présent, pyenv suppose que vous souhaitez utiliser le Python « système ». (En d'autres termes, quelle que soit la version qui s'exécuterait si pyenv n'était pas dans votre PATH.)

NOTE : Vous pouvez activer plusieurs versions en même temps, y compris plusieurs versions de Python2 ou Python3 simultanément. Cela permet une utilisation parallèle de Python2 et Python3, et est requis avec des outils comme tox. Par exemple, pour définir votre PATH de manière à utiliser d'abord votre Python système et Python3 (définis sur 2.7.9 et 3.4.2 dans cet exemple), mais avoir également Python 3.3.6, 3.2 et 2.5 disponibles sur votre PATH, il faudrait d'abord pyenv install les versions manquantes, puis définir pyenv global system 3.3.6 3.2 2.5. À ce stade, vous devriez pouvoir trouver le chemin exécutable complet de chacun d'eux en utilisant pyenv which, par exemple pyenv which python2.5 (devrait afficher $(pyenv root)/versions/2.5/bin/python2.5), ou pyenv which python3.4 (devrait afficher le chemin vers le Python3 système). Vous pouvez également spécifier plusieurs versions dans un fichier .python-version, séparées par des sauts de ligne ou n'importe quel espace blanc. hy

Localiser l'installation de Python

Une fois que pyenv a déterminé la version de Python spécifiée par votre application, il transmet la commande à l'installation Python correspondante.

Chaque version de Python est installée dans son propre répertoire sous

$(pyenv root)/versions.

Par exemple, vous pourriez avoir ces versions installées :

  • $(pyenv root)/versions/2.7.8/
  • $(pyenv root)/versions/3.4.2/
  • $(pyenv root)/versions/pypy-2.4.0/

Pour pyenv, les noms de version sont simplement les répertoires dans $(pyenv root)/versions.

Gérer les environnements virtuels

Il existe un plugin pyenv nommé pyenv-virtualenv qui offre diverses fonctionnalités pour aider les utilisateurs de pyenv à gérer les environnements virtuels créés par virtualenv ou Anaconda. Comme le script activate de ces environnements virtuels repose sur la modification de la variable $PATH du shell interactif de l'utilisateur, il interceptera les hooks d'exécution de commandes de style shim de pyenv. Nous recommandons d'installer également pyenv-virtualenv si vous avez l'intention d'utiliser ces environnements virtuels.

Configuration avancée

Sautez cette section sauf si vous devez savoir ce que fait chaque ligne de votre profil shell.

pyenv init est la seule commande qui franchit la limite du chargement de commandes supplémentaires dans votre shell. Venant de rvm, certains d'entre vous pourraient être opposés à cette idée. Voici ce que fait réellement pyenv init :

1.
Configure votre chemin de shims. C'est la seule exigence pour que pyenv fonctionne correctement. Vous pouvez le faire manuellement en ajoutant $(pyenv root)/shims au début de votre $PATH.
2.
Réinitialise les shims. De temps en temps, vous devrez reconstruire vos fichiers de shims. Le faire lors de l'initialisation garantit que tout est à jour. Vous pouvez toujours exécuter pyenv rehash manuellement. Vous pouvez désactiver cette fonctionnalité en ajoutant --no-rehash à la fin de votre ligne de commande pyenv init.
3.
Installe le répartiteur sh. Cette partie est également facultative, mais permet à pyenv et à ses plugins de modifier des variables dans votre shell actuel, rendant possibles des commandes comme pyenv shell. Le répartiteur sh ne fait rien de spécial comme remplacer cd ou pirater votre invite de commande, mais si pour une raison quelconque vous avez besoin que pyenv soit un vrai script plutôt qu'une fonction shell, vous pouvez l'ignorer en toute sécurité.

Pour voir exactement ce qui se passe en coulisses, exécutez "pyenv init -".

Désinstaller les versions de Python

Avec le temps, vous accumulerez des versions de Python dans votre répertoire $(pyenv root)/versions.

Pour supprimer les anciennes versions de Python, utilisez la commande pyenv uninstall pour automatiser le processus de suppression.

Alternativement, vous pouvez simplement faire un rm -rf du répertoire de la version que vous souhaitez supprimer. Vous pouvez trouver le répertoire d'une version Python particulière avec la commande pyenv prefix,

par exemple pyenv prefix 2.6.8.

pyenv local

Définit une version locale de Python spécifique à une application en écrivant le nom de la version dans un fichier .python-version dans le répertoire actuel. Cette version remplace la version globale et peut être remplacée à son tour en définissant la variable d'environnement PYENV_VERSION ou avec la commande pyenv shell.

$ pyenv local 2.7.6

Lorsqu'elle est exécutée sans numéro de version, pyenv local affiche la version locale configurée actuellement. Vous pouvez également annuler la version locale :

$ pyenv local --unset

Les versions précédentes de pyenv stockaient les spécifications de version locale dans un fichier nommé .pyenv-version. NAME

pyenv - gérer plusieurs versions d'installation de Python

SYNOPSIS

pyenv [ options ] <command> [ args ]

DESCRIPTION

pyenv permet de basculer facilement entre plusieurs versions d'installation de Python. Il utilise des shims pour intercepter les appels de commandes Python et s'assurer que la version correcte est exécutée. pyenv n'installe pas les versions de Python ; il s'appuie sur python-build (qui est installé comme sous-commande de pyenv) pour cela.

Pour installer une nouvelle version de Python, par exemple :

    $ pyenv install 2.7.6
    $ pyenv versions
      system
    * 2.7.6 (set by /home/yyuu/.pyenv/version)

Une fois installée, vous pouvez définir la version de Python à utiliser :

  • Global : la version de Python à utiliser par défaut. Ceci est enregistré dans le fichier ~/.pyenv/version.

    $ pyenv global 2.7.6

  • Local : la version de Python à utiliser dans un projet spécifique. Ceci est enregistré dans le fichier .python-version dans le répertoire courant.

    $ pyenv local 2.7.6

  • Shell : la version de Python à utiliser pour la session shell actuelle. Ceci est enregistré dans la variable d'environnement PYENV_VERSION.

    $ pyenv shell 2.7.6

COMMAND LINE OPTIONS

-d, --debug
Activer le mode débogage.
-q, --quiet
Supprimer la plupart des messages de sortie.
-v, --version
Afficher le numéro de version de pyenv.
-h, --help
Afficher le message d'aide.

OPTIONS

-l, --list
Lister toutes les versions disponibles.
-f, --force
Installer même si la version semble déjà être installée.
-k, --keep
Garder l'arborescence source dans $PYENV_BUILD_ROOT après l'installation (par défaut : $PYENV_ROOT/sources).
-p, --patch
Appliquer un patch depuis stdin avant la compilation.
-g, --debug
Compiler une version de débogage.

COMPARISON

pyenv set

$ pyenv versions
  system
* 2.7.6 (set by /home/yyuu/.pyenv/version)

pyenv local

$ pyenv local 3.3.3
$ pyenv versions
  system
  2.7.6 (set by /home/yyuu/.pyenv/version)
* 3.3.3 (set by .python-version)

pyenv shell

$ pyenv shell 2.6.8
$ pyenv versions
  system
  2.7.6 (set by /home/yyuu/.pyenv/version)
* 2.6.8 (set by PYENV_VERSION environment variable)
  3.3.3 (set by .python-version)

How It Works

pyenv exécute une commande en utilisant le chemin d'accès complet aux fichiers binaires de la version spécifiée par l'une des méthodes suivantes, dans l'ordre de priorité :

  1. La variable d'environnement PYENV_VERSION.

  2. Le fichier .python-version dans le répertoire courant ou l'un de ses répertoires parents.

  3. Le fichier de configuration global ~/.pyenv/version.

Advanced Configuration

pyenv vous permet de définir les versions de Python globales, locales et shell. Les versions locales remplacent les versions globales, et les versions shell remplacent tout le reste.

Il est également possible de spécifier plusieurs versions à la fois pour la configuration globale et locale. Les versions sont recherchées dans l'ordre dans lequel elles sont spécifiées.

Par exemple, si vous avez installé les versions 2.7.6 et 3.3.3, et que vous préférez 2.7.6 à 3.3.3 :

$ pyenv global 2.7.6 3.3.3
$ python --version
Python 2.7.6

Ou si vous préférez 3.3.3 à 2.7.6 :

$ pyenv global 3.3.3 2.7.6
$ python --version
Python 3.3.3

Uninstalling Python Versions

Pour désinstaller une version de Python, utilisez la commande pyenv uninstall suivie de la version que vous souhaitez supprimer.

$ pyenv uninstall 2.7.6

pyenv shell

Définit une version Python spécifique au shell en définissant la variable d'environnement PYENV_VERSION dans votre shell. Cette version remplace les versions spécifiques à l'application et la version globale.

$ pyenv shell pypy-2.2.1

Lorsque exécuté sans numéro de version, pyenv shell signale la valeur actuelle de PYENV_VERSION. Vous pouvez également annuler la définition de la version du shell :

$ pyenv shell --unset

$ export PYENV_VERSION=pypy-2.2.1
