NOM

Ce projet n'est plus maintenu et recherche un nouveau mainteneur.

python-ptrace est un débogueur utilisant ptrace (appel système Linux, BSD et Darwin pour tracer des processus) écrit en Python.

  • Documentation python-ptrace
  • python-ptrace sur GitHub
  • python-ptrace sur le Cheeseshop Python (PyPI)

python-ptrace est un projet open source écrit en Python sous licence GNU GPLv2. Il prend en charge Python 3.6 et versions ultérieures.

FONCTIONNALITÉS

  • API Python de haut niveau : PtraceDebugger et PtraceProcess
  • Capable de contrôler plusieurs processus : capture des événements fork sur Linux
  • Lecture/écriture d'octets à des adresses arbitraires : attention à l'alignement de la mémoire et division des octets par mot CPU
  • Exécution pas à pas à l'aide de ptrace_singlestep() ou de l'interruption matérielle 3
  • Peut utiliser le désassembleur distorm
  • Dump des registres, des mappings mémoire, de la pile, etc.
  • Traceur et analyseur d'appels système (commande strace.py)

État :

  • Systèmes d'exploitation pris en charge : Linux, FreeBSD, OpenBSD
  • Architectures prises en charge : x86, x86_64 (Linux), PPC (Linux), ARM (Linux EAPI)

Fonctionnalités manquantes :

  • Symboles : il n'est pas possible de s'arrêter sur une fonction ou de lire la valeur d'une variable
  • Pas de prise en charge du langage C : le débogueur affiche le code assembleur, pas votre code C (C++ ou autre langage) !
  • Pas de prise en charge des threads

Utilisation de python-ptrace

Bonjour le monde

Court exemple d'attachement à un processus en cours d'exécution. Il obtient le pointeur d'instruction, exécute une seule étape, et obtient le nouveau pointeur d'instruction :

import ptrace.debugger
import signal
import subprocess
import sys
def debugger_example(pid):
    debugger = ptrace.debugger.PtraceDebugger()
    print("Attachement au processus en cours %s" % pid)
    process = debugger.addProcess(pid, False)
    # process est une instance de PtraceProcess
    print("IP avant : %#x" % process.getInstrPointer())
    print("Exécution d'une seule étape")
    process.singleStep()
    # singleStep() redonne le contrôle au processus. Nous devons attendre
    # que le processus soit à nouveau piégé pour retrouver le contrôle sur
    # le processus.
    process.waitSignals(signal.SIGTRAP)
    print("IP après : %#x" % process.getInstrPointer())
    process.detach()
    debugger.quit()
def main():
    args = [sys.executable, '-c', 'import time; time.sleep(60)']
    child_popen = subprocess.Popen(args)
    debugger_example(child_popen.pid)
    child_popen.kill()
    child_popen.wait()
if __name__ == "__main__":
    main()

API

PtraceProcess

La classe PtraceProcess est une aide pour manipuler un processus tracé.

Exemple :

tracer = PtraceProcess(pid)              # attache le processus
tracer.singleStep()                      # exécute une instruction
tracer.cont()                            # continue l'exécution
tracer.syscall()                         # s'arrête au prochain appel système
tracer.detach()                          # détache le processus
# Obtenir l'état
tracer.getreg('al')                      # obtient la valeur du registre AL
regs = tracer.getregs()                  # lit tous les registres
bytes = tracer.readBytes(regs.ax, 10)    # lit 10 octets
tracer.dumpCode()                        # dump le code (en assembleur ou hexa si le désassembleur est manquant)
tracer.dumpStack()                       # dump la pile (mots mémoire autour de ESP)
# Modifier le processus
shellcode = '...'
ip = tracer.getInstrPointer()            # obtient le registre EIP/RIP
bytes = tracer.writeBytes(ip, shellcode) # écrit quelques octets
tracer.setreg('ebx', 0)                  # met la valeur du registre EBX à zéro

Syscall tracer

Le module ptrace.syscall permet de tracer et d'analyser les appels système.

Exemple :

from ptrace.syscall import SyscallTracer
import ptrace.binding as ptraceb
def syscall_tracer_example(pid):
    tracer = SyscallTracer(pid)
    # tracer.run() exécutera le programme jusqu'à ce qu'il se termine
    # ou jusqu'à ce qu'un signal soit reçu.
    # On peut aussi spécifier un nombre maximum d'appels système à tracer.
    tracer.run(max_syscall=10)
    for syscall_num, syscall_name, args, ret in tracer.get_calls():
        print("%s(%s) = %s" % (syscall_name, ", ".join(args), ret))
    tracer.quit()
# ... appel à syscall_tracer_example(pid)

Syscall.SyscallTracer

La classe SyscallTracer permet de tracer les appels système.

Syscall.SyscallTracer.run()

Exécute le processus et trace les appels système.

Syscall.SyscallTracer.get_calls()

Retourne la liste des appels système tracés.

Syscall.SyscallTracer.quit()

Arrête le processus tracé et détache le traceur.

Événements de processus python-ptrace

Événements de processus

Tous les événements de processus sont basés sur la classe ProcessEvent.

  • ProcessExit : le processus s'est terminé avec un code de sortie, a été tué par un signal ou s'est terminé anormalement
  • ProcessSignal : le processus a reçu un signal
  • NewProcessEvent : un nouveau processus a été créé, par exemple après un appel système fork()

Attributs :

  • Tous les événements ont un attribut "process"
  • ProcessExit a les attributs "exitcode" et "signum" (les deux peuvent être None)
  • ProcessSignal a les attributs "signum" et "name"

Pour NewProcessEvent, utilisez l'attribut process.parent pour obtenir le processus parent.

Note : ProcessSignal a une méthode display() pour afficher son contenu. Utilisez-la juste après avoir reçu le message car elle lit la mémoire du processus pour analyser les raisons pour lesquelles le signal a été envoyé.

Attendre tout événement de processus

La fonction la plus générique est waitProcessEvent() : elle attend tout événement de processus (fin, signal ou nouveau processus) :

event = debugger.waitProcessEvent()

Pour attendre un ou plusieurs signaux, utilisez les méthodes waitSignals(). Sans argument, elle attend tout signal. Les événements autres que les signaux sont levés comme des exceptions Python. Exemples :

signal = debugger.waitSignals()
signal = debugger.waitSignals(SIGTRAP)
signal = debugger.waitSignals(SIGINT, SIGTERM)

Note : signal est un objet ProcessSignal, utilisez signal.signum pour obtenir le numéro du signal.

Attendre les événements d'un processus spécifique

Pour attendre tout événement d'un processus, utilisez la méthode waitEvent() :

event = process.waitEvent()

Pour attendre un ou plusieurs signaux, utilisez la méthode waitSignals(). Sans argument, elle attend tout signal. Les autres événements de processus sont levés comme des exceptions Python. Exemples :

signal = process.waitSignals()
signal = process.waitSignals(SIGTRAP)
signal = process.waitSignals(SIGINT, SIGTERM)

Note : Comme debugger.waitSignals(), signal est un objet ProcessSignal.

Gestion des signaux python-ptrace

Introduction

PtraceSignal essaie d'afficher des informations utiles lorsqu'un signal est reçu. Selon le numéro du signal, il affiche des informations différentes.

Il utilise l'instruction actuelle décodée sous forme de code assembleur pour comprendre pourquoi le signal est émis.

Seul Intel x86 (i386, peut-être x86_64) est actuellement pris en charge.

Lorsqu'un processus reçoit un signal, python-ptrace essaie d'expliquer pourquoi le signal a été émis.

    python-ptrace 0.4.0 (2008-08-19)

    Changements visibles :

    • Renommage du projet en "python-ptrace" (ancien nom était "Ptrace)
    • strace.py : création de l'option --ignore-regex
    • PtraceSignal : support de SIGBUS, affiche les registres associés et l'instruction
    • Support du traçage de l'appel système execve()

    Changements pour les développeurs :

    • La nouvelle API est incompatible avec 0.3.2
    • PtraceProcess.waitProcessEvent() accepte l'argument optionnel blocking=False
    • PtraceProcess.getreg()/setreg() sont capables de lire/écrire les "sous-registres" i386 et x86-64 comme al ou bx
    • Suppression de la fonction iterProc(), remplacée par openProc() avec appel explicite à .close() pour s'assurer que les fichiers sont fermés
    • Création de searchProcessesByName()
    • Remplacement de la constante CPU_PPC par CPU_POWERPC et création de CPU_PPC32 et CPU_PPC64
    • Création de l'objet MemoryMapping, utilisé par les méthodes readMappings() et findStack() de PtraceProcess
    • Définition toujours de toutes les méthodes PtraceProcess mais levée d'une erreur si la fonction n'est pas implémentée

    FEATURES

    • Support for Linux, FreeBSD, OpenBSD, NetBSD, Solaris, Darwin
    • Access to all ptrace requests
    • Process control (attach, detach, kill, continue, single-step)
    • Process memory access (read, write)
    • Process register access (read, write)
    • Process signal handling (wait, send)
    • Process event notification (e.g., exit, exec, signal)
    • Process communication (e.g., PTRACE_PEEKUSR, PTRACE_POKEUSR)
    • Support for multi-threaded processes
    • Integration with existing Python modules (e.g., ctypes, struct)
    • Extensible API for adding new features
