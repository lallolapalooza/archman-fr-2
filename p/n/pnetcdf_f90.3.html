PnetCDF(3f) FONCTIONS DE BIBLIOTHÈQUE PnetCDF(3f)

NOM

PnetCDF - Bibliothèque parallèle pour l'accès aux fichiers au format Network Common Data Form (CDF, CDF-2 et CDF-5)

SYNTAXE

use pnetcdf

La plupart des systèmes :

mpif90 ... -lpnetcdf

Systèmes CRAY PVP :

f90 -dp -i64 ... -lpnetcdf

VERSION DE LA BIBLIOTHÈQUE

Ce document décrit les API PnetCDF pour le langage de programmation Fortran-90.

character*80 nf90mpi_inq_libvers()

character(len=80) :: nf90mpi_inq_libvers

Retourne une chaîne identifiant la version de la bibliothèque PnetCDF, et sa date de compilation, comme : « 1.14.1 du 2025-07-31 ».

La commande RCS ident(1) trouvera une chaîne comme « $Id: @(#) PnetCDF library version 1.14.1 of 2025-07-31 $ » dans la bibliothèque. La commande SCCS what(1) trouvera une chaîne comme « PnetCDF library version 1.14.1 of 2025-07-31 ».

DESCRIPTIONS DES ROUTINES

Toutes les fonctions PnetCDF (sauf nf90mpi_inq_libvers() et nf90mpi_strerror()) retournent un statut entier. Ce comportement remplace l'argument rcode utilisé dans les versions précédentes de la bibliothèque. Si cette valeur de statut retournée n'est pas égale à nf90_noerr (zéro), cela indique qu'une erreur s'est produite. Les statuts possibles sont définis dans le module pnetcdf.

function nf90mpi_strerror(ncerr)

Retourne une traduction textuelle de la valeur ncerr, comme « Nom d'attribut ou de variable contenant des caractères illégaux » ou « Pas un tel fichier ou répertoire ».

function nf90mpi_create(comm, path, cmode, info, ncid)

integer, intent(in) :: comm
character(len=*), intent(in) :: path
integer, intent(in) :: cmode
integer, intent(in) :: info
integer, intent(out) :: ncid
integer :: nf90mpi_create

Crée un nouveau jeu de données netCDF à l'emplacement path collectivement par un groupe de processus MPI spécifiés par comm, renvoyant un identifiant netCDF dans ncid. L'argument cmode peut inclure l'opération OU bit à bit des drapeaux suivants : nf90_noclobber pour protéger les jeux de données existants (par défaut, nf90_clobber, qui les écrase silencieusement), nf90_64bit_offset pour créer un fichier au format décalage 64 bits (CDF-2), par opposition au format classique, par défaut, ou nf90_64bit_data pour créer un fichier au format données 64 bits (CDF-5). Utilisez soit nf90_64bit_offset soit nf90_64bit_data. Le format décalage 64 bits permet la création de fichiers très volumineux avec beaucoup moins de restrictions que le format netCDF classique, mais ne peut être lu que par la bibliothèque netCDF version 3.6 ou supérieure. Les utilisateurs sont avertis que les fichiers utilisant le format décalage 64 bits ne seront pas reconnus par les applications netCDF liées à une version antérieure à la 3.6 de la bibliothèque netCDF. Les applications liées à la version 3.6 ou ultérieure pourront accéder de manière transparente au format classique ou au format décalage 64 bits. Le format données 64 bits permet la création de variables tableaux très volumineuses. Les fichiers CDF-5 ne seront pas reconnus par les bibliothèques netCDF 3 ou 4.

L'argument cmode doit être cohérent entre tous les processus MPI qui créent collectivement le fichier. L'argument info est un objet MPI info. Les utilisateurs peuvent l'utiliser pour fournir des indications d'accès aux fichiers pour une amélioration supplémentaire des performances. Ces indications incluent les indications MPI-IO existantes ainsi que les indications définies et utilisées dans PnetCDF.

Lorsqu'un jeu de données netCDF est créé, il est ouvert en mode nf90_write. Lorsque cette fonction retourne, le nouveau jeu de données netCDF est en mode définir.

Ouvre un jeu de données netCDF existant à l'emplacement path collectivement par un groupe de processus MPI spécifiés par comm, renvoyant un identifiant netCDF dans ncid. Les utilisateurs peuvent l'utiliser pour fournir des indications d'accès aux fichiers pour une amélioration supplémentaire des performances. Ces indications incluent les indications MPI-IO existantes ainsi que les indications définies et utilisées dans PnetCDF.

function nf90mpi_abort(ncid)

integer, intent(in) :: ncid
integer :: nf90mpi_abort

Vous n'avez pas besoin d'appeler cette fonction. Elle est appelée automatiquement par nf90mpi_close() si le jeu de données netCDF était en mode définir et que quelque chose s'est mal passé lors de la validation. Si le jeu de données netCDF n'est pas en mode définir, alors cette fonction est équivalente à nf90mpi_close(). Si elle est appelée après nf90mpi_redef(), mais avant nf90mpi_enddef(), les nouvelles définitions ne sont pas validées et le jeu de données est fermé. Si elle est appelée après nf90mpi_create() mais avant nf90mpi_enddef(), le jeu de données disparaît.

function nf90mpi_close(ncid)

integer, intent(in) :: ncid
integer :: nf90mpi_close

Ferme un jeu de données netCDF ouvert. Si le jeu de données est en mode définir, nf90mpi_enddef() sera appelé avant la fermeture. Après la fermeture d'un jeu de données, son identifiant peut être réattribué à un autre jeu de données.

Ajoute une nouvelle variable à un jeu de données netCDF. Le netCDF doit être en mode définition. name sera le nom de la variable netCDF. xtype est le type externe netCDF de la variable et doit être l'un des suivants : nf90_byte, nf90_char, nf90_short, nf90_int, nf90_float, ou nf90_double pour les formats de fichiers CDF-1 et CDF-2. DESCRIPTIONS DES ARGUMENTS COMMUNS

Dans cette section, nous définissons certains arguments communs utilisés dans la section "DESCRIPTIONS DES FONCTIONS".

integer ncid
est l'ID netCDF retourné par un appel réussi précédent à nf90mpi_open() ou nf90mpi_create()
character(len=*) name
est le nom d'une dimension, d'une variable ou d'un attribut. Il doit commencer par un caractère alphabétique, suivi de zéro ou plusieurs caractères alphanumériques, y compris le trait de soulignement (_) ou le tiret (-). La casse est significative. Le nombre maximum de caractères autorisé est nf90_max_name. Les noms commençant par un trait de soulignement (_) sont réservés à l'usage des interfaces netCDF et PnetCDF.
integer xtype
spécifie le type de données externe d'une variable ou d'un attribut netCDF et est l'un des suivants : nf90_byte, nf90_char, nf90_short, nf90_int, nf90_float, ou nf90_double. Ceux-ci sont utilisés pour spécifier respectivement des entiers de 8 bits, des caractères, des entiers de 16 bits, des entiers de 32 bits, des nombres flottants IEEE de 32 bits et des nombres flottants IEEE de 64 bits.
integer dimids
est un vecteur d'ID de dimensions et définit la forme d'une variable netCDF. La taille du vecteur doit être supérieure ou égale au rang (c'est-à-dire le nombre de dimensions) de la variable (ndims). Le vecteur doit être ordonné par la vitesse à laquelle une dimension varie : dimids(1) doit être l'ID de la dimension la plus rapidement variable et dimids(ndims) doit être l'ID de la dimension la plus lentement variable. Le nombre maximum possible de dimensions pour une variable est donné par la constante symbolique nf90_max_var_dims.
integer dimid
est l'ID d'une dimension netCDF. Les ID de dimensions netCDF sont alloués séquentiellement à partir des entiers positifs commençant par 1.
integer ndims
est soit le nombre total de dimensions dans un jeu de données netCDF, soit le rang (c'est-à-dire le nombre de dimensions) d'une variable netCDF. La valeur ne doit pas être négative ou supérieure à la constante symbolique nf90_max_var_dims.
integer varid
est l'ID d'une variable netCDF ou (pour les fonctions d'accès aux attributs) la constante symbolique nf90_global, qui est utilisée pour référencer les attributs globaux. Les ID de variables netCDF sont alloués séquentiellement à partir des entiers positifs commençant par 1.
integer natts
est le nombre d'attributs globaux dans un jeu de données netCDF pour la fonction nf90mpi_inquire() ou le nombre d'attributs associés à une variable netCDF pour la fonction nf90mpi_varinq().
integer(kind=MPI_OFFSET) start
spécifie le point de départ pour accéder aux valeurs de données d'une variable netCDF en termes de coordonnées indicées du coin de la section de tableau. Les indices commencent à 1 ; ainsi, la première valeur de donnée d'une variable est (1, 1, ..., 1). La taille du vecteur doit être au moins égale au rang de la variable associée et ses éléments doivent correspondre, dans l'ordre, aux dimensions de la variable.
integer(kind=MPI_OFFSET) stride
spécifie l'intervalle d'échantillonnage le long de chaque dimension de la variable netCDF. Les éléments du vecteur d'intervalle correspondent, dans l'ordre, aux dimensions de la variable netCDF (stride(1) donne l'intervalle d'échantillonnage le long de la dimension la plus rapidement variable de la variable netCDF). Les intervalles d'échantillonnage sont spécifiés en unités d'éléments indépendantes du type (une valeur de 1 sélectionne des éléments consécutifs de la variable netCDF le long de la dimension correspondante, une valeur de 2 sélectionne un élément sur deux, etc.).
integer(kind=MPI_OFFSET) imap
spécifie le mappage entre les dimensions d'une variable netCDF et la structure en mémoire du tableau de données interne. Les éléments du vecteur de mappage d'index correspondent, dans l'ordre, aux dimensions de la variable netCDF (imap donne la distance entre les éléments du tableau interne correspondant à la dimension la plus rapidement variable de la variable netCDF). Les distances entre les éléments sont spécifiées en unités d'éléments indépendantes du type (la distance entre les éléments internes qui occupent des emplacements mémoire adjacents est de 1 et non la longueur en octets de l'élément comme dans netCDF 2).

PRE-REMPLISSAGE DE VARIABLE

Avant la version 1.6.1, PnetCDF ne prend pas en charge le remplissage des données. Le mode de remplissage par défaut dans PnetCDF est NF90_NOFILL. Ceci est contraire à la bibliothèque netCDF dont la valeur par défaut est NF90_FILL. Lorsque le mode de remplissage est activé, PnetCDF définit les valeurs de toutes les variables nouvellement définies de longueur finie (c'est-à-dire celles qui n'ont pas de dimension illimitée) à la valeur de remplissage dépendante du type associée à chaque variable. Ceci est fait lorsque nf90mpi_enddef() est appelé. La valeur de remplissage d'une variable peut être modifiée par rapport à la valeur par défaut en définissant l'attribut _FillValue pour la variable. Cet attribut doit avoir le même type que la variable et être de longueur un.

Les variables ayant une dimension illimitée ne sont pas pré-remplies dans PnetCDF. Ceci est également contraire à netCDF, qui pré-remplit les variables d'enregistrement. Dans PnetCDF, le remplissage d'une variable d'enregistrement doit être effectué en appelant nf90mpi_fill_var_rec(). Notez que cela ne remplit qu'un seul enregistrement d'une variable.

Le mode de remplissage pour l'ensemble du fichier peut être défini par nf90mpi_set_fill(). Le réglage du mode de remplissage par variable est également disponible via nf90mpi_def_var_fill(). Dans PnetCDF, la modification du mode de remplissage doit être effectuée en mode de définition. Dans netCDF, ce n'est vrai que pour les variables de taille fixe. Pour les variables d'enregistrement, la modification du mode de remplissage peut être effectuée à tout moment dans netCDF.

PnetCDF-Fortran API

NAME

pnetcdf_f90 - Parallel NetCDF Fortran API

SYNOPSIS

The Parallel NetCDF Fortran API provides routines that are similar to the C API. It allows Fortran programmers to access NetCDF files in parallel using the MPI (Message Passing Interface) standard.

    USE, INTRINSIC :: nf90_constants, ONLY : nf90_...
    INCLUDE 'pnetcdf.inc'

    INTEGER :: ncid, varid, dimid, grpid
    INTEGER :: retval

    ! Example: Creating a NetCDF file
    retval = nf90_create("parallel_file.nc", nf90_clobber + nf90_parallel, ncid)
    IF (retval /= nf90_noerr) THEN
        ! Handle error
    END IF

    ! Example: Defining dimensions
    retval = nf90_def_dim(ncid, "x", 10, dimid)
    IF (retval /= nf90_noerr) THEN
        ! Handle error
    END IF

    ! Example: Defining variables
    retval = nf90_def_var(ncid, "data", nf90_int, (/dimid/), varid)
    IF (retval /= nf90_noerr) THEN
        ! Handle error
    END IF

    ! Example: Writing data
    INTEGER, DIMENSION(10) :: buffer
    ! ... fill buffer with data ...
    retval = nf90_put_var(ncid, varid, buffer)
    IF (retval /= nf90_noerr) THEN
        ! Handle error
    END IF

    ! Example: Closing the file
    retval = nf90_close(ncid)
    IF (retval /= nf90_noerr) THEN
        ! Handle error
    END IF

LIBRARY VERSION

The library version can be obtained using the nf90_inq_libvers routine.

    CHARACTER(LEN=32) :: version_string
    retval = nf90_inq_libvers(version_string)

ROUTINE DESCRIPTIONS

The PnetCDF Fortran API includes routines for file creation, definition, data access, and inquiry. Key routines include:

  • nf90_create: Create a new NetCDF file.
  • nf90_open: Open an existing NetCDF file.
  • nf90_close: Close a NetCDF file.
  • nf90_def_dim: Define a dimension.
  • nf90_def_var: Define a variable.
  • nf90_put_var: Write a variable's data.
  • nf90_get_var: Read a variable's data.
  • nf90_inq_varid: Inquire variable ID.
  • nf90_inq_dimid: Inquire dimension ID.
  • nf90_inq: Inquire NetCDF file information.
  • nf90_enddef: End define mode.
  • nf90_redef: Re-enter define mode.

For a complete list and detailed descriptions, please refer to the PnetCDF documentation.

COMMON ARGUMENT DESCRIPTIONS

The Fortran routines often take arguments like:

  • ncid: NetCDF file ID.
  • varid: Variable ID.
  • dimid: Dimension ID.
  • name: Name of dimension or variable.
  • dtype: Data type (e.g., nf90_int, nf90_float).
  • dims: Array of dimension IDs for a variable.
  • values: Array or scalar containing the data to write or read.
  • start: Starting indices for data access.
  • count: Number of elements to access along each dimension.
  • stride: Stride for data access.

VARIABLE PREFILLING

The Fortran API supports variable prefilling to optimize write operations. When enabled, NetCDF variables are allocated space on disk when they are created, rather than when data is written to them.

ENVIRONMENT VARIABLES

PnetCDF uses environment variables to control its behavior, such as error handling and performance tuning.

  • PNETCDF_DEBUG: Enable debug output.
  • PNETCDF_HINT: Control performance hints.
