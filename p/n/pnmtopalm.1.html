NOM

pnmtopalm - convertir une image PNM en Bitmap Palm

SYNTAXE

pnmtopalm

[-verbose]

[-depth=N]

[-maxdepth=N]

[-colormap]

[-transparent=couleur]

[-density=N]

[-offset]

[-withdummy] [-scanline-compression | -rle-compression | -packbits-compression]

[fichier.pnm]

L'abréviation unique minimale de l'option est acceptable. Vous pouvez utiliser des doubles tirets au lieu de simples tirets pour désigner les options. Vous pouvez utiliser des espaces à la place du signe égal pour séparer le nom d'une option de sa valeur.

DESCRIPTION

Ce programme fait partie de Netpbm(1)

pnmtopalm lit une image PNM en entrée, depuis l'entrée standard ou fichier.pnm et produit un Bitmap Palm en sortie.

Les fichiers Bitmap Palm sont soit des fichiers en niveaux de gris de 1, 2 ou 4 bits de largeur, soit des fichiers couleur de 8 bits de largeur. Par conséquent, pnmtopalm adapte automatiquement les couleurs pour avoir un `maxval` approprié, sauf si vous spécifiez une profondeur ou une profondeur maximale. Les fichiers d'entrée doivent avoir un nombre et un ensemble de couleurs appropriés pour les contraintes de sortie sélectionnées.

Cela signifie souvent que vous devriez passer l'image PNM par pnmquant ou pnmremap avant de la transmettre à pnmtopalm. Netpbm est livré avec plusieurs fichiers de carte de couleurs que vous pouvez utiliser avec pnmremap à cette fin. Ce sont palmgray2.map (4 nuances de gris pour une profondeur de 2), palmgray4.map (16 nuances de gris pour une profondeur de 4) et palmcolor8.map (232 couleurs dans la carte de couleurs Palm par défaut). Dans une installation Netpbm standard, ceux-ci se trouvent dans le répertoire de données Netpbm, et vous pouvez trouver ce répertoire avec une commande shell netpbm-config --datadir.

Exemple :

  pnmremap monimage.ppm \
           -mapfile=$(netpbm-config --datadir)/palmgray2.map \
  | pnmtopalm -depth=2 >monimage.palm

Version Bitmap Palm

pnmtopalm génère un Bitmap Palm de version 0, 1, 2 ou 3. Il génère la version la plus ancienne (la plus basse) qu'il peut pour l'image donnée et les options que vous spécifiez.

  • Si vous spécifiez une densité (option -density) supérieure à 'basse', la version est au moins 3.
  • Si vous spécifiez la transparence (option -transparent) ou une compression, la version est au moins 2.
  • Si vous spécifiez une carte de couleurs personnalisée (option -colormap), la version est au moins 1.
  • Si l'image a plus d'un bit par pixel, la version est au moins 1. L'image a plus d'un bit par pixel si vous la spécifiez avec -depth ou si vous la laissez par défaut et que l'image a plus de deux couleurs (ou nuances de gris).

Toutes les versions de Palm OS peuvent lire un bitmap de version 0. Palm OS 3.0 et versions ultérieures peuvent lire un bitmap de version 1. Palm OS 3.5 et versions ultérieures peuvent lire un bitmap de version 2. Pour lire un bitmap de version 3, vous avez besoin de Palm OS Garnet ou d'un appareil portable exécutant le jeu de fonctionnalités d'affichage haute densité.

OPTIONS

-verbose
Affiche le format du fichier de sortie.
-depth=N
Produit un fichier de profondeur N, où N doit être 1, 2, 4, 8 ou 16. Comme la carte de couleurs Palm par défaut de 8 bits n'est pas en niveaux de gris, si l'image d'entrée est en niveaux de gris ou monochrome, la sortie ne dépassera jamais 4 bits de profondeur, quelle que soit la profondeur spécifiée. Notez que la couleur 8 bits ne fonctionne qu'à partir de PalmOS 3.5 (et supérieur), et la couleur directe 16 bits ne fonctionne qu'à partir de PalmOS 4.0 (et supérieur). Cependant, le format couleur directe 16 bits est également compatible avec les différentes versions de PalmOS 3.x utilisées dans le Handspring Visor, de sorte que ces images peuvent également fonctionner sur cet appareil.
-maxdepth=N
Produit un fichier de profondeur minimale, mais dans tous les cas inférieur à N bits de largeur. Si vous spécifiez 16 bits, la sortie sera toujours une couleur directe 16 bits.
-offset
Définit le champ nextDepthOffset dans l'en-tête du fichier palm pour indiquer la fin du fichier (et remplit la fin du fichier sur 4 octets, car nextDepthOffset ne peut pointer que vers des limites de 4 octets).

Un fichier image palm peut contenir plusieurs rendus de la même image, avec différentes profondeurs de couleur, afin qu'un visualiseur puisse en choisir un approprié pour l'affichage. Le champ nextDepthOffset indique où dans le flux commence le rendu suivant.

pnmtopalm crée un fichier qui ne contient qu'une seule image, mais vous pouvez concaténer séparément plusieurs fichiers à image unique pour créer un fichier multi-images. Si vous le faites, vous devrez utiliser -offset afin que la concaténation résultante soit un flux correct.

Par défaut (si vous ne spécifiez pas -offset), pnmtopalm génère un champ nextDepthOffset indiquant qu'il n'y a pas d'image suivante (et n'ajoute aucun remplissage après l'image).

Les fichiers Bitmap Palm de version 3 ont en fait un champ nextBitmapOffset au lieu de nextDepthOffset. Ce qui précède s'applique quel que soit celui qui est pertinent.

L'option -offset est nouvelle dans Netpbm 10.26 (janvier 2005). Avant cela, pnmtopalm définissait toujours le champ nextDepthOffset sur 'aucun'.

Avant Netpbm 10.27 (mars 2005), vous ne pouvez pas utiliser -offset si vous créez un raster compressé (car pnmtopalm n'est pas assez intelligent pour connaître la taille de l'image au moment où il écrit l'en-tête). Vous ne pouvez pas non plus l'utiliser avec une profondeur de couleur de 16 bits ou avec l'option -colormap, pour à peu près la même raison.

-withdummy
Cette option indique à pnmtopalm d'insérer dans le flux, après l'image, un en-tête d'image factice pour introduire des images haute densité ultérieures.

Cet en-tête d'image factice est une séquence spéciale spécifiée dans les spécifications du Bitmap Palm. Il ressemble à un interpréteur de Bitmap Palm plus ancien à un en-tête d'image invalide, donc un tel interpréteur arrêtera de lire le flux là. Mais un nouvel interpréteur de Bitmap Palm le reconnaît pour ce qu'il est (juste quelque chose pour embêter un ancien interpréteur) et le saute. On suppose que vous ajouterez des images haute densité au flux après cela, ce qui confondrait un ancien interpréteur.

Si vous spécifiez -withdummy, vous devez également spécifier -offset, car cela n'a aucun sens autrement.

-withdummy est nouveau dans Netpbm 10.27 (mars 2005).

-colormap
Construit une carte de couleurs personnalisée et l'inclut dans le fichier de sortie. Ceci n'est pas recommandé par Palm, pour des raisons d'efficacité. Sinon, pnmtopalm utilise la carte de couleurs Palm par défaut pour la sortie couleur.
-transparent=couleur
Marque une couleur particulière comme entièrement transparente. Le format pour spécifier la couleur est soit (lorsqu'il s'agit par exemple d'orange) '1.0,0.5,0.0', où les valeurs sont des flottants entre zéro et un, soit avec la syntaxe '#RGB', '#RRGGBB' ou '#RRRRGGGGBBBB' où R, G et B sont des nombres hexadécimaux. La transparence ne fonctionne qu'à partir de Palm OS 3.5 et supérieur.
-scanline-compression
Spécifie que le bitmap Palm de sortie utilisera le schéma de compression de ligne de balayage Palm. La compression de ligne de balayage ne fonctionne qu'à partir de Palm OS 2.0 et supérieur.
-rle-compression
Spécifie que le bitmap Palm de sortie utilisera le schéma de compression RLE Palm. La compression RLE ne fonctionne qu'à partir de Palm OS 3.5 et supérieur.
-packbits-compression
Spécifie que le bitmap Palm de sortie utilisera le schéma de compression packbits Palm. La compression Packbits ne fonctionne qu'à partir de Palm OS 4.0 et supérieur.

Cette option est nouvelle dans Netpbm 10.27 (mars 2005).

NOTES

Les bitmaps Palm peuvent contenir plusieurs rendus de la même image bitmap, avec différentes profondeurs de couleurs. Pour construire un bitmap Palm à N rendus avec pnmtopalm, construisez d'abord les rendus 1 à N-1 en utilisant l'option -offset, puis construisez le Nème rendu sans l'option -offset. Ensuite, concaténez les rendus individuels dans un seul fichier en utilisant cat.

Si vous incluez des rendus en haute et basse densité, placez les images en haute densité en dernier et lorsque vous créez la dernière des images en basse densité, utilisez l'option -withdummy.

Si vous spécifiez le schéma de compression Palm packbits pour un bitmap couleur directe 16 bits, ce programme génère un bitmap invalide.
