NOM

pnmtojpeg - convertir une image PNM en une image JFIF ('JPEG')

SYNTAXE

pnmtojpeg [-exif=spécificateur-fichier] [-qualité=n] [{-niveauxdegris|-niveau-de-gris}] [-densité=nxn[dpi,dpcm]] [-optimiser|-optimise] [-rgb] [-progressif] [-commentaire=texte] [-dct={int|fast|float}] [-arithmétique] [-redémarrage=n] [-lisser=n] [-mémoiremax=n] [-verbeux] [-ligne-de-base] [-tablesq=spécificateur-fichier] [-slotsq=n[,...]] [-échantillon=HxV[,...]] [-balayages=spécificateur-fichier] [-niveau-trace=N]

nomfichier

L'abréviation unique minimale de l'option est acceptable. Vous pouvez utiliser des doubles tirets au lieu de tirets simples pour indiquer les options. Vous pouvez utiliser des espaces blancs à la place du signe égal pour séparer un nom d'option de sa valeur.

DESCRIPTION

Ce programme fait partie de Netpbm(1)

pnmtojpeg convertit le fichier image PBM, PGM ou PPM nommé, ou l'entrée standard si aucun fichier n'est nommé, en un fichier JFIF sur la sortie standard.

pnmtojpeg utilise la bibliothèque JPEG du groupe Independent JPEG pour créer le fichier de sortie. Voir http://www.ijg.org pour des informations sur la bibliothèque.

« JFIF » est le nom correct du format d'image communément appelé « JPEG ». Strictement parlant, JPEG est une méthode de compression. Le format d'image utilisant la compression JPEG qui est de loin le plus courant est JFIF. Il existe également un sous-format de TIFF qui utilise la compression JPEG.

EXIF est un format d'image qui est un sous-format de JFIF (à savoir, un fichier JFIF qui contient un en-tête EXIF comme marqueur APP1). pnmtojpeg crée une image EXIF lorsque vous spécifiez l'option -exif.

OPTIONS

Les options de base sont :

-exif=spécificateur-fichier
Cette option spécifie que l'image de sortie doit être EXIF (un sous-format de JFIF), c'est-à-dire qu'elle aura un en-tête EXIF en tant que marqueur APP1 JFIF. Le contenu de ce marqueur est le contenu du fichier spécifié. La valeur spéciale - signifie que l'en-tête EXIF doit être lu depuis l'entrée standard. Il est invalide de spécifier l'entrée standard à la fois pour l'en-tête EXIF et l'image d'entrée.

Le fichier EXIF commence par un champ de deux octets qui est la longueur du fichier, y compris le champ de longueur, en binaire pur, octet de poids fort en premier. La valeur spéciale zéro pour le champ de longueur signifie qu'il n'y aura pas d'en-tête EXIF, c'est-à-dire la même chose que pas d'option -exif. Ceci est utile lorsque vous convertissez un fichier de JFIF en PNM à l'aide de jpegtopnm, puis le transformez, puis le reconvertissez en JFIF avec pnmtojpeg, et que vous ne savez pas s'il inclut ou non un en-tête EXIF. jpegtopnm crée un fichier EXIF ne contenant que deux octets de zéro lorsque le fichier JFIF d'entrée n'a pas d'en-tête EXIF. Ainsi, vous pouvez transférer n'importe quel en-tête EXIF du JFIF d'entrée vers le JFIF de sortie sans vous soucier de l'existence réelle d'un en-tête EXIF.

Le contenu du fichier EXIF après le champ de longueur est le contenu exact, octet par octet, du marqueur APP1, sans compter le champ de longueur, qui constitue l'en-tête EXIF.

-qualité=n
Met à l'échelle les tables de quantification pour ajuster la qualité de l'image. n est de 0 (pire) à 100 (meilleur) ; la valeur par défaut est 75. En dessous d'environ 25, cela peut produire des images que certains interprètes ne pourront pas interpréter. Voir ci-dessous pour plus d'informations.
-niveauxdegris
-niveau-de-gris
-rgb
Ces options déterminent l'espace colorimétrique utilisé dans la sortie JFIF. -niveauxdegris (ou -niveau-de-gris) signifie créer un JFIF en niveaux de gris, en convertissant à partir d'une entrée PPM couleur si nécessaire. -rgb signifie créer un JFIF RGB, et le programme échoue si l'entrée n'est pas PPM.

Si vous ne spécifiez ni l'un ni l'autre, le fichier de sortie est au format YCbCr si l'entrée est PPM, et au format niveaux de gris si l'entrée est PBM ou PGM.

Le format YCbCr (une couleur est représentée par une valeur d'intensité et deux valeurs de chrominance) se compresse généralement beaucoup mieux que le format RGB (une couleur est représentée par un rouge, un vert et un bleu). Le format RGB est rare. Mais vous pourrez peut-être convertir plus rapidement entre JFIF et PPM avec RGB, car c'est le même espace colorimétrique que celui utilisé par PPM.

Le fichier testimg.ppm fourni avec Netpbm est 2,3 fois plus grand avec l'option -rgb qu'avec la valeur par défaut YCbCr, et dans une expérience, pnmtojpeg a pris 16 % de temps CPU en plus pour le convertir. Le temps CPU supplémentaire indique probablement que le traitement de toutes les données compressées supplémentaires a consommé tout le temps CPU économisé en n'ayant pas à convertir les entrées RGB en YCbCr.

Le format niveaux de gris prend beaucoup moins de place et prend moins de temps à créer et à traiter que les formats couleur, même si l'image ne contient que du noir, du blanc et du gris.

L'option -rgb a été ajoutée dans Netpbm 10.11 en octobre 2002.

-densité=densité
Cette option détermine les informations de densité (alias résolution) enregistrées dans l'image de sortie JFIF. Elle n'affecte en rien le tramage ; elle indique simplement à celui qui lit le JFIF comment interpréter le tramage.

La valeur de densité prend la forme xxy suivie d'un spécificateur d'unité facultatif dpi ou dpcm. Exemples : 1x1, 3x2, 300x300dpi, 100x200dpcm. Le premier nombre est la densité horizontale ; le 2ème nombre est la densité verticale. Chacun peut être n'importe quel entier de 1 à 65535. Le spécificateur d'unité est dpi pour dots par pouce ou dpcm pour dots par centimètre. Si vous ne spécifiez pas les unités, les informations de densité vont dans le JFIF en indiquant explicitement « densité non spécifiée » (également interprétée comme « inconnue »). Cela peut sembler inutile, mais notez que même sans spécifier les unités, les nombres de densité indiquent le rapport d'aspect des pixels. Par exemple, 1x1 indique que les pixels sont carrés. 3x2 indique que les pixels sont des rectangles verticaux.

Notez que si vous spécifiez des densités horizontales et verticales différentes, l'image JFIF résultante n'est pas une représentation fidèle de l'image PNM d'entrée, car pnmtojpeg convertit le tramage pixel par pixel et les pixels d'une image PNM sont définis comme carrés. Ainsi, si vous commencez avec une image PNM carrée et spécifiez -densité=3x2, l'image JFIF résultante est une version aplatie horizontalement de l'original. Cependant, il est courant d'utiliser une image d'entrée qui est une légère variation du PNM plutôt qu'un vrai PNM, de telle sorte que les pixels ne soient pas carrés. Dans ce cas, l'option -densité appropriée produit une reproduction fidèle de l'image pseudo-PNM d'entrée.

La valeur par défaut est 1x1 en unités non spécifiées.

Avant Netpbm 10.15 (avril 2003), cette option n'existait pas et pnmtojpeg créait toujours un JFIF avec une densité de 1x1 en unités non spécifiées.

-optimiser

Effectue une optimisation des paramètres de codage d'entropie. Sans cela, pnmtojpeg utilise les paramètres de codage par défaut. -optimiser rend généralement le fichier JFIF un peu plus petit, mais pnmtojpeg s'exécute un peu plus lentement et nécessite beaucoup plus de mémoire. La qualité de l'image et la vitesse de décompression ne sont pas affectées par -optimiser.
-progressif
Crée un fichier JPEG progressif (voir ci-dessous).
-commentaire=texte
Inclut un marqueur de commentaire dans la sortie JFIF, avec le texte du commentaire texte.

Sans cette option, il n'y a pas de marqueurs de commentaire dans la sortie.

L'option -qualité vous permet d'échanger la taille du fichier compressé avec la qualité de l'image reconstruite : plus le réglage de qualité est élevé, plus le fichier JFIF est grand, et plus l'image de sortie sera proche de l'originale. Normalement, vous voulez utiliser le réglage de qualité le plus bas (fichier le plus petit) qui décompres

ses en quelque chose visuellement indiscernable de l'image d'origine. À cette fin, le réglage de qualité devrait être compris entre 50 et 95 pour des résultats raisonnables ; la valeur par défaut de 75 est souvent appropriée. Si vous constatez des défauts avec -quality=75, augmentez de 5 ou 10 points à la fois jusqu'à ce que vous soyez satisfait de l'image de sortie. (Le réglage optimal variera d'une image à l'autre.)

-quality=100 génère une table de quantification de tous les 1, minimisant la perte dans l'étape de quantification (mais il y a toujours une perte d'information dans le sous-échantillonnage, ainsi qu'une erreur d'arrondi). Ce réglage est principalement d'intérêt expérimental. Les valeurs de qualité supérieures à environ 95 ne sont pas recommandées pour une utilisation normale ; la taille du fichier compressé augmente considérablement pour un gain minime en qualité d'image de sortie.

Dans l'autre sens, les valeurs de qualité inférieures à 50 produiront des fichiers très petits de faible qualité d'image. Des réglages autour de 5 à 10 pourraient être utiles pour préparer un index d'une grande bibliothèque d'images, par exemple. Essayez -quality=2 (environ) pour des effets cubistes amusants. (Remarque : les valeurs de qualité inférieures à environ 25 génèrent des tables de quantification de 2 octets, qui sont considérées comme optionnelles dans la norme JFIF. pnmtojpeg émet un message d'avertissement lorsque vous donnez une telle valeur de qualité, car certains autres programmes JFIF pourraient ne pas être en mesure de décoder le fichier résultant. Utilisez -baseline si vous avez besoin d'assurer la compatibilité avec des valeurs de qualité faibles.)

L'option -progressive crée un fichier JPEG 'progressif'. Dans ce type de fichier JFIF, les données sont stockées en plusieurs scans de qualité croissante. Si le fichier est transmis sur une liaison de communication lente, le décodeur peut utiliser le premier scan pour afficher rapidement une image de faible qualité, puis améliorer l'affichage avec chaque scan subséquent. L'image finale est exactement équivalente à un fichier JFIF standard du même réglage de qualité, et la taille totale du fichier est à peu près la même – souvent un peu plus petite.

Attention : le JPEG progressif n'est pas encore largement implémenté, donc de nombreux décodeurs seront incapables d'afficher un fichier JPEG progressif.

Si vous essayez de contrôler le compromis qualité/taille de fichier, vous pourriez plutôt envisager le format JPEG2000. Voir pamtojpeg2k(1)

Options pour les utilisateurs avancés :

-dct=int
Utiliser la méthode DCT entière (par défaut).
-dct=fast
Utiliser la DCT entière rapide (moins précise).
-dct=float
Utiliser la méthode DCT à virgule flottante. La méthode flottante est très légèrement plus précise que la méthode entière, mais beaucoup plus lente, sauf si votre machine dispose d'un matériel à virgule flottante très rapide. Notez également que les résultats de la méthode à virgule flottante peuvent varier légèrement d'une machine à l'autre, tandis que les méthodes entières devraient donner les mêmes résultats partout. La méthode entière rapide est beaucoup moins précise que les deux autres.
-arithmetic
Utiliser le codage arithmétique. Par défaut, c'est le codage Huffman. Le codage arithmétique a tendance à donner un résultat plus petit.

Vous pourriez avoir besoin de licences de brevet pour utiliser cette option. Selon le JPEG FAQ, cette méthode est couverte par des brevets appartenant à IBM, AT&T et Mitsubishi.

L'auteur de la FAQ déconseille l'utilisation du codage arithmétique (et donc de cette option) car les économies d'espace ne sont pas suffisantes pour justifier les tracas juridiques.

La plupart des bibliothèques JPEG, y compris celles distribuées par l'Independent JPEG Group depuis environ 1998, ne sont pas capables d'encodage arithmétique. pnmtojpeg utilise une bibliothèque JPEG (soit liée lors de la compilation de l'exécutable pnmtojpeg, soit accédée sur votre système au moment de l'exécution) pour effectuer l'encodage JPEG. Si pnmtojpeg se termine avec le message 'Sorry, there are legal restrictions on arithmetic coding' ou 'Sorry, arithmetic coding not supported', c'est le problème.

-restart=n
Émettre un marqueur de redémarrage JPEG toutes les n lignes MCU, ou tous les n blocs MCU si vous ajoutez B au nombre. -restart 0 (la valeur par défaut) signifie pas de marqueurs de redémarrage.
-smooth=n
Lisser l'image d'entrée pour éliminer le bruit de tramage. n, compris entre 1 et 100, indique la force du lissage. 0 (la valeur par défaut) signifie pas de lissage.
-maxmemory=n
Définir une limite pour la quantité de mémoire à utiliser pour le traitement des grandes images. La valeur est en milliers d'octets, ou en millions d'octets si vous ajoutez M au nombre. Par exemple, -max=4m sélectionne 4 000 000 d'octets. Si pnmtojpeg a besoin de plus d'espace, il utilisera des fichiers temporaires.
-verbose
Afficher sur le flux d'erreur standard des messages concernant le processus de conversion. Cela peut être utile pour déboguer des problèmes.

L'option -restart indique à pnmtojpeg d'insérer des marqueurs supplémentaires qui permettent à un décodeur JPEG de se resynchroniser après une erreur de transmission. Sans marqueurs de redémarrage, tout dommage à un fichier compressé ruinera généralement l'image à partir du point de l'erreur jusqu'à la fin de l'image ; avec des marqueurs de redémarrage, le dommage est généralement limité à la portion de l'image jusqu'au prochain marqueur de redémarrage. Bien sûr, les marqueurs de redémarrage occupent de l'espace supplémentaire. Nous recommandons -restart=1 pour les images qui seront transmises sur des réseaux peu fiables comme Usenet.

L'option -smooth filtre l'entrée pour éliminer le bruit à petite échelle. Ceci est souvent utile lors de la conversion d'images tramées en JFIF : un facteur de lissage modéré de 10 à 50 élimine les motifs de tramage dans le fichier d'entrée, résultant en un fichier JFIF plus petit et une image de meilleure apparence. Cependant, un facteur de lissage trop élevé brouillera visiblement l'image.

Options pour les sorciers :

-baseline
Forcer la génération de tables de quantification compatibles avec la ligne de base. Cela limite les valeurs de quantification à 8 bits même avec des paramètres de qualité bas. (Ce commutateur est mal nommé, car il ne garantit pas que la sortie soit réellement du JPEG de ligne de base. Par exemple, vous pouvez utiliser -baseline et -progressive ensemble.)
-qtables=spécification_fichier
Utiliser les tables de quantification fournies dans le fichier texte spécifié.
-qslots=n[,...]
Sélectionner la table de quantification à utiliser pour chaque composante de couleur.
-sample=HxV[,...]
Définir les facteurs d'échantillonnage JPEG pour chaque composante de couleur.
-scans=spécification_fichier
Utiliser le script de scan spécifié dans le fichier texte. Voir ci-dessous pour plus d'informations sur les scripts de scan.
-tracelevel=N
Définit le niveau de trace de débogage que le programme affiche pendant son exécution. 0 signifie aucun, et c'est la valeur par défaut. Ce niveau contrôle principalement le traçage de la bibliothèque JPEG, et vous pouvez obtenir des informations assez intéressantes sur le processus de compression.

Les options 'sorcier' sont destinées à l'expérimentation avec JPEG. Si vous ne savez pas ce que vous faites, ne les utilisez pas. Ces commutateurs sont documentés plus en détail dans le fichier wizard.doc qui accompagne la bibliothèque JPEG de l'Independent JPEG Group.

EXEMPLES

Cet exemple compresse le fichier PPM foo.ppm avec un facteur de qualité de 60 et enregistre la sortie sous le nom foo.jpg :

    pnmtojpeg -quality=60 foo.ppm > foo.jpg

Voici un exemple plus typique. Il convertit du BMP vers JFIF :

    cat foo.bmp | bmptoppm | pnmtojpeg > foo.jpg

Perte JPEG

Lorsque vous compressez avec JPEG, vous perdez des informations – c'est-à-dire que l'image résultante a une qualité légèrement inférieure à l'originale. C'est une caractéristique de JPEG lui-même, pas d'un programme particulier. Ainsi, si vous faites la chose habituelle avec Netpbm et que vous convertissez de JFIF en PNM, manipulez, puis reconvertissez en JFIF, vous perdrez de la qualité. Plus vous le faites, plus vous perdez. Les dessins (graphiques, dessins animés, dessins au trait, etc. avec peu de couleurs et des bords nets) en souffrent le plus.

Pour éviter cela, vous pouvez utiliser un format d'image compressé autre que JPEG. PNG et JPEG2000 sont de bons choix, et Netpbm contient des convertisseurs pour ceux-ci.

Si vous avez besoin d'utiliser JFIF sur un dessin, vous devriez expérimenter avec les options -quality et -smooth de pnmtojpeg pour obtenir une conversion satisfaisante. -smooth 10 environ est souvent utile.

En raison de la perte, vous devriez faire toutes les manipulations nécessaires sur l'image dans un autre format et convertir en JFIF comme dernière étape. Et si vous pouvez conserver une copie dans le format d'origine, c'est encore mieux.

L'option -optimize de pnmtojpeg vaut la peine d'être utilisée lorsque vous créez une version 'finale' pour publication ou archivage. C'est également un avantage lorsque vous utilisez des réglages de qualité bas pour créer des fichiers JFIF très petits ; l'amélioration en pourcentage est souvent bien plus importante que pour les fichiers plus volumineux. (Actuellement, le mode -optimize est automatiquement activé lorsque vous générez un fichier JPEG progressif).

Vous pouvez effectuer des transformations de retournement et de rotation sans perte avec le programme jpegtran, qui est empaqueté avec la bibliothèque JPEG de l'Independent Jpeg Group. jpegtran utilise sa connaissance intime du fonctionnement de JPEG pour effectuer la transformation sans jamais décompresser réellement l'image.

Un autre programme, cjpeg, est similaire. cjpeg est maintenu par l'Independent JPEG Group et empaqueté avec la bibliothèque JPEG que pnmtojpeg utilise pour tout son travail JPEG. De ce fait, vous pouvez vous attendre à ce qu'il exploite les fonctionnalités JPEG les plus récentes. De plus, étant donné que vous devez avoir la bibliothèque pour exécuter pnmtojpeg, mais pas l'inverse, cjpeg peut être plus couramment disponible.

En revanche, cjpeg ne traite pas ses entrées avec les bibliothèques NetPBM, comme le font tous les outils NetPBM tels que pnmtojpeg. Cela signifie qu'il est moins susceptible d'être cohérent avec tous les autres programmes qui traitent les formats NetPBM. De plus, la syntaxe de commande de pnmtojpeg est cohérente avec celle des autres outils Netpbm, contrairement à cjpeg.

SCRIPTS DE BALAYAGE

Utilisez l'option -scan pour spécifier un script de balayage. Ou utilisez l'option -progressive pour spécifier un script de balayage intégré particulier.

Ce qu'est un script de balayage, et le format de base du fichier de script de balayage, est couvert dans le fichier wizard.doc qui accompagne la bibliothèque JPEG de l'Independent JPEG Group. Les scripts de balayage sont les mêmes pour pnmtojpeg que pour cjpeg.

Cette section contient des informations supplémentaires qui ne sont pas, mais devraient probablement l'être, dans ce document.

Tout d'abord, il existe de nombreuses restrictions sur ce qui constitue un script de balayage valide. La bibliothèque JPEG, et donc pnmtojpeg, vérifie minutieusement tout manque de conformité avec ces restrictions, mais fait peu pour vous dire comment le script ne se conforme pas. Les messages sont très généraux et parfois faux.

Pour commencer, les entrées pour le coefficient DC doivent précéder toute entrée pour les coefficients AC. Le coefficient DC est le Coefficient 0 ; tous les autres coefficients sont des coefficients AC. Donc, dans une entrée pour le coefficient DC, les deux nombres après les deux points doivent être 0 et 0. Dans une entrée pour les coefficients AC, le premier nombre après les deux points ne doit pas être 0.

Dans une entrée DC, les composantes de couleur doivent être dans un ordre croissant. Par exemple, '0,2,1' avant les deux points est faux. Il en va de même pour '0,0,0'.

Dans une entrée pour un coefficient AC, vous devez spécifier une seule composante de couleur. C'est-à-dire, il ne peut y avoir qu'un seul nombre avant les deux points.

Dans la première entrée pour un coefficient particulier pour une composante de couleur particulière, la valeur 'Ah' doit être zéro, mais la valeur Al peut être n'importe quel nombre de bits valide. Dans les entrées ultérieures, Ah doit être la valeur Al de l'entrée précédente (pour ce coefficient pour cette composante de couleur), et la valeur Al doit être un de moins que la valeur Ah.

Le script doit finalement spécifier au moins une partie du coefficient DC pour chaque composante de couleur. Sinon, vous obtenez le message d'erreur 'Le script ne transmet pas toutes les données.' Vous n'avez pas besoin de spécifier tous les bits du coefficient DC, ni aucun des coefficients AC.

Il existe une option standard dans la construction de la bibliothèque JPEG pour omettre la capacité de script de balayage. Si pour une raison quelconque votre bibliothèque a été construite avec cette option, vous obtenez le message 'Fonctionnalité demandée omise lors de la compilation.'

ENVIRONNEMENT

JPEGMEM
Si cette variable d'environnement est définie, sa valeur est la limite de mémoire par défaut. La valeur est spécifiée comme décrit pour l'option -maxmemory. Une option explicite -maxmemory remplace toute valeur de JPEGMEM.
