NOM

pnmremap - remplace les couleurs d'une image PNM par des couleurs d'un autre ensemble

SYNTAXE

pnmremap

-mapfile=fichierpalette

[-floyd|-fs|-nfloyd|-nofs]

[-norandom]

[-firstisdefault]

[-verbose]

[-missingcolor=couleur]

[fichierpnm]

Toutes les options peuvent être abrégées à leur plus courte préfixe unique. Vous pouvez utiliser deux tirets au lieu d'un pour désigner une option. Vous pouvez utiliser soit un espace blanc soit un signe égal entre un nom d'option et sa valeur.

DESCRIPTION

Ce programme fait partie de Netpbm(1)

pnmremap remplace les couleurs d'une image d'entrée par celles d'une palette que vous spécifiez. Lorsque les couleurs de l'entrée sont présentes dans la palette, elles restent identiques dans la sortie. Mais là où l'entrée contient une couleur qui n'est pas dans la palette, pnmremap vous offre ces choix :

  • Choisir la couleur la plus proche de la palette.
  • Choisir la première couleur de la palette.
  • Utiliser une couleur spécifiée par une option de commande (-missing).
  • Serrage (dithering). Cela signifie qu'au lieu de mapper pixel par pixel, pnmremap utilise des couleurs de la palette pour essayer de faire en sorte que des régions multi-pixels de la sortie aient la même couleur moyenne que l'entrée (pour un autre type de serrage, voir ppmdither).

Deux raisons d'utiliser ce programme sont : 1) vous voulez réduire le nombre de couleurs dans l'image d'entrée ; et 2) vous devez alimenter l'image avec quelque chose qui ne peut gérer que certaines couleurs.

Pour réduire les couleurs, vous pouvez générer la palette avec pnmcolormap.

Par défaut, pnmremap mappe une couleur d'entrée qui n'est pas dans la palette à la couleur la plus proche qui est dans la palette. Le plus proche signifie la plus petite distance cartésienne dans l'espace de luminosité rouge, vert, bleu (la plus petite somme des carrés des différences dans les intensités gamma ajustées ITU-R Recommendation BT.709 pour le rouge, le vert et le bleu).

Vous pouvez spécifier à la place une seule couleur par défaut que pnmremap utilisera pour toute couleur de l'image d'entrée qui n'est pas dans la palette. Utilisez l'option -missing pour cela.

Vous pouvez aussi spécifier que la première couleur de l'image palette est la couleur par défaut. Utilisez l'option -firstisdefault pour cela.

La palette est simplement une image PNM. Les couleurs des pixels de l'image sont les couleurs de la palette. L'endroit où apparaissent les pixels dans l'image, et les dimensions de l'image, sont sans importance. Des pixels multiples de la même couleur sont acceptables. Cependant, une image palette est typiquement une seule ligne avec un pixel par couleur.

Si vous spécifiez -missing, la couleur que vous spécifiez ainsi est dans la palette en plus de tout ce qui est dans l'image palette.

Pour des raisons historiques, Netpbm appelle parfois la palette une 'colormap'. Mais elle ne mappe rien réellement. pnmremap crée sa propre carte, basée sur la palette, pour mapper les couleurs de l'image d'entrée aux couleurs de sortie.

Incompatibilité Palette/Type d'image

Dans le cas simple, l'image palette a la même profondeur (nombre de plans, c'est-à-dire le nombre de composantes dans chaque tuple (pixel)) que l'image d'entrée et pnmremap effectue simplement une recherche directe dans la palette pour chaque tuple (pixel) d'entrée. En fait, pnmremap ne se soucie même pas si l'image est une image visuelle.

Mais qu'en est-il lorsque les profondeurs diffèrent ? Dans ce cas, pnmremap convertit l'image d'entrée (dans sa propre mémoire) pour correspondre à la palette et procède ensuite comme ci-dessus.

Il n'y a que deux de ces cas dans lesquels pnmremap sait comment faire la conversion : lorsque l'un d'eux est de type tuple RVB, profondeur 3, et l'autre est de type NIVEAU DE GRIS ou NOIR ET BLANC, profondeur 1 ; et vice versa.

Dans tout autre cas, pnmremap affiche un message d'erreur et échoue.

Notez que tant que vos images d'entrée et de palette sont des PNM, elles tomberont toujours dans l'un des cas que pnmremap peut gérer. Il y a un problème seulement si vous utilisez une image PAM exotique.

Avant Netpbm 10.27 (mars 2005), pnmremap ne pouvait pas gérer le cas d'une palette de profondeur supérieure à l'image d'entrée. (Il affichait un message d'erreur et échouait dans ce cas). Vous pouvez utiliser ppmtoppm pour augmenter la profondeur de l'image d'entrée afin de contourner cette limitation.

Dans tous les cas, l'image de sortie a le même type de tuple et la même profondeur que l'image palette.

Flux d'images multiples

pnmremap gère un flux d'images multiples en entrée, produisant un flux d'images multiples en sortie. Les images d'entrée n'ont pas besoin d'être similaires d'une quelconque manière.

Avant Netpbm 10.30 (octobre 2005), pnmremap ignorait toute image après la première.

Exemples

pnmcolormap testimg.ppm 256 >palette.ppm
pnmremap -map=palette.ppm testimg.ppm >reduced_testimg.ppm

Pour limiter les couleurs à un certain ensemble, un exemple typique est de créer une image pour la publication sur le World Wide Web, où différents navigateurs connaissent différentes couleurs. Mais tous les navigateurs sont censés connaître les 216 couleurs 'web safe' qui sont essentiellement toutes les couleurs que vous pouvez représenter dans une image PPM avec un maxval de 5. Vous pouvez donc faire ceci :

pamseq 3 5 >websafe.pam
pnmremap -map=websafe.pam testimg.ppm >websafe_testimg.ppm

Une autre palette utile est celle de l'ensemble de couleurs TTL IBM à 8 couleurs, que vous pouvez créer avec

pamseq 3 1 >ibmttl.pam

Si vous voulez quantifier une image pour utiliser les couleurs d'une autre, utilisez simplement la seconde comme palette. Vous n'avez pas besoin de la réduire à un seul pixel de chaque couleur, utilisez-la telle quelle.

L'image de sortie a le même type et le même maxval que l'image palette.

PARAMETRES

Il y a un paramètre, qui est obligatoire : La spécification du fichier de l'image PNM d'entrée.

OPTIONS

-mapfile=nomfichierpalette
Ceci nomme le fichier qui contient l'image palette.

Cette option est obligatoire.

-floyd
-fs
-nofloyd
-nofs
Ces options déterminent si pnmremap effectue le serrage de Floyd-Steinberg. Sans Floyd-Steinberg, pnmremap sélectionne la couleur de sortie d'un pixel en se basant uniquement sur la couleur du pixel d'entrée correspondant. Avec Floyd-Steinberg, pnmremap considère des régions de pixels de telle sorte que la couleur moyenne d'une région soit la même en sortie qu'en entrée. L'effet de serrage apparaît comme un motif de points de près, mais de loin, les points se mélangent de sorte que vous voyez plus de couleurs qu'il n'y en a dans la palette de couleurs.

Par exemple, si votre palette de couleurs ne contient que du noir et blanc, et que l'image d'entrée a 4 pixels adjacents de gris, pnmremap avec Floyd-Steinberg générerait les pixels de sortie noir, blanc, noir, blanc, ce qui, de loin, ressemble à du gris. Mais sans Floyd-Steinberg, pnmremap générerait 4 pixels blancs, le blanc étant l'approximation d'un seul pixel pour le gris.

Floyd-Steinberg donne des résultats nettement meilleurs sur les images où la quantification non modifiée présente des artefacts de banding ou autres, surtout lors du passage à un petit nombre de couleurs comme l'ensemble IBM ci-dessus. Cependant, cela prend considérablement plus de temps CPU.

-fs est un synonyme de -floyd. -nofs est un synonyme de -nofloyd.

Par défaut, c'est -nofloyd.

Avant Netpbm 10.46 (mars 2009), le serrage ne fonctionne pas tout à fait comme prévu si la palette a un maxval inférieur à celui de l'entrée. pnmremap réduit la résolution des couleurs au maxval de la palette avant d'effectuer tout serrage, de sorte que le serrage n'a pas pour effet de faire apparaître l'image, de loin, avec le maxval d'origine. Dans les Netpbm actuels, il le fait.

-norandom
Cette option affecte un détail du processus de tramage de Floyd-Steinberg. Elle n'a aucun effet si vous n'utilisez pas le tramage de Floyd-Steinberg.

Par défaut, pnmremap initialise l'accumulateur de propagation d'erreur avec des valeurs aléatoires pour éviter l'apparition de motifs indésirables. Ceci est une extension de l'algorithme original de Floyd-Steinberg.

L'inconvénient est que la même exécution de pnmremap sur la même entrée produit un résultat légèrement différent à chaque fois, ce qui rend la comparaison difficile.

Avec -norandom, pnmremap initialise les accumulateurs d'erreur à zéro et la sortie est complètement prévisible.

-norandom est nouveau dans Netpbm 10.39 (juin 2007).

-firstisdefault
Indique à pnmremap de mapper toute couleur d'entrée qui ne se trouve pas dans la palette à la première couleur de la palette (la couleur du pixel dans le coin supérieur gauche de l'image de palette).

Voir DESCRIPTION.

Si vous spécifiez -firstisdefault, le maxval de votre entrée doit correspondre au maxval de votre image de palette.

-missingcolor=couleur
Spécifie la couleur par défaut vers laquelle pnmremap doit mapper une couleur de l'image d'entrée qui ne se trouve pas dans la palette. couleur peut ou non être dans l'image de palette ; elle fait partie de la palette quoi qu'il en soit.

Si vous spécifiez -missingcolor, le maxval de votre entrée doit correspondre au maxval de votre image de palette.

-verbose
Affiche des messages utiles sur le processus de mappage.

VOIR AUSSI

pnmcolormap(1), pamseq(1), pnmquant(1), ppmquantall(1), pamdepth(1), ppmdither(1), ppmquant(1), ppm(5)

HISTORIQUE

pnmremap est apparu pour la première fois dans Netpbm 9.23 (janvier 2002). Avant cela, sa fonction n'était disponible que dans le cadre de la fonction de pnmquant (qui était dérivé du beaucoup plus ancien ppmquant). La quantification des couleurs a en réalité deux sous-fonctions principales, Netpbm 9.23 les a donc séparées en deux programmes distincts : pnmcolormap et pnmremap, puis Netpbm 9.24 a remplacé pnmquant par un programme qui appelle simplement pnmcolormap et pnmremap.
