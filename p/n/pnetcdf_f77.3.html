PnetCDF(3f) FONCTIONS DE BIBLIOTHÈQUE PnetCDF(3f)

NOM

PnetCDF - Bibliothèque parallèle pour accéder aux fichiers aux formats Network Common Data Form (CDF, CDF-2 et CDF-5)

SYNTAXE

include "pnetcdf.inc"

La plupart des systèmes :

mpif77 ... -lpnetcdf

Systèmes CRAY PVP :

f90 -dp -i64 ... -lnetcdf

La documentation complète pour les bibliothèques PnetCDF se trouve sur le site web de PnetCDF : http://cucis.ece.northwestern.edu/projects/PnetCDF/.

VERSION DE LA BIBLIOTHÈQUE

Ce document décrit les API PnetCDF pour le langage de programmation FORTRAN.

character*80 nfmpi_inq_libvers(void)

(Correspond à nf_inq_libvers() dans netCDF)

Retourne une chaîne identifiant la version de la bibliothèque PnetCDF et sa date de compilation, par exemple : "1.14.1 du 2025-07-31".

La commande RCS ident(1) trouvera une chaîne comme "$Id: @(#) PnetCDF library version 1.14.1 of 2025-07-31 $" dans la bibliothèque. La commande SCCS what(1) trouvera une chaîne comme "PnetCDF library version 1.14.1 of 2025-07-31".

VALEURS DE RETOUR

Toutes les fonctions PnetCDF (sauf nfmpi_inq_libvers() et nfmpi_strerror()) retournent un statut entier.

Si cette valeur de statut retournée n'est pas égale à NF_NOERR (zéro), cela indique qu'une erreur s'est produite. Les valeurs de statut possibles sont définies dans pnetcdf.inc.

character*80 nfmpi_strerror(integer status)

(Correspond à nf_strerror() dans netCDF)

Retourne une traduction textuelle de la valeur de status, par exemple "Le nom d'attribut ou de variable contient des caractères illégaux" ou "Aucun fichier ou répertoire de ce type".

OPÉRATIONS SUR FICHIER

integer function nfmpi_create(integer comm, character*(*) path, integer cmode, integer info, integer ncid)

(Correspond à nf_create() dans netCDF)

Crée un nouveau jeu de données netCDF à l'emplacement path collectivement par un groupe de processus MPI spécifié par comm, retournant un identifiant netCDF dans ncid. L'argument cmode peut inclure l'opérateur OU bit à bit des drapeaux suivants : NF_NOCLOBBER pour protéger les jeux de données existants (par défaut NF_CLOBBER, qui les efface silencieusement), NF_64BIT_OFFSET pour créer un fichier au format décalage 64 bits (CDF-2), par opposition au format classique, par défaut, ou NF_64BIT_DATA pour créer un fichier au format données 64 bits (CDF-5). Utilisez soit NF_64BIT_OFFSET, soit NF_64BIT_DATA. Le format décalage 64 bits permet la création de fichiers très volumineux avec beaucoup moins de restrictions que le format netCDF classique, mais ne peut être lu qu'avec la version 3.6 ou supérieure de la bibliothèque netCDF. Les utilisateurs sont avertis que les fichiers utilisant le format décalage 64 bits ne seront pas reconnus par les applications netCDF liées à une version antérieure à la 3.6 de la bibliothèque netCDF. Les applications liées à la version 3.6 ou supérieure pourront accéder de manière transparente soit au format classique, soit au format décalage 64 bits. Le format données 64 bits permet la création de variables tableaux très volumineux. Les fichiers CDF-5 ne seront actuellement pas reconnus par les bibliothèques netCDF 3 ou 4.

L'argument cmode doit être cohérent entre tous les processus MPI qui créent collectivement le fichier. L'argument info est un objet d'informations MPI. Les utilisateurs peuvent l'utiliser pour fournir des indications d'accès au fichier pour améliorer davantage les performances. Ces indications incluent les indications MPI-IO existantes ainsi que les indications définies et utilisées dans PnetCDF.

Lorsqu'un jeu de données netCDF est créé, il est ouvert en mode NF_WRITE. Lorsque cette fonction retourne, le nouveau jeu de données netCDF est en mode définition.

integer function nfmpi_open(integer comm, character*(*) path, integer mode, integer info, integer ncid)

(Correspond à nf_open() dans netCDF)

Ouvre un jeu de données netCDF existant à l'emplacement path collectivement par un groupe de processus MPI spécifié par comm, retournant un identifiant netCDF dans ncid. Le type d'accès est décrit par le paramètre mode, qui peut inclure l'opérateur OU bit à bit des drapeaux suivants : NF_WRITE pour un accès en lecture-écriture (lecture seule par défaut).

L'argument mode doit être cohérent entre tous les processus MPI qui ouvrent collectivement le fichier. L'argument info est un objet d'informations MPI. Les utilisateurs peuvent l'utiliser pour fournir des indications d'accès au fichier pour améliorer davantage les performances. Ces indications incluent les indications MPI-IO existantes ainsi que les indications définies et utilisées dans PnetCDF.

integer function nfmpi_redef(integer ncid)

(Correspond à nf_redef() dans netCDF)

Met un jeu de données netCDF ouvert en mode définition, de sorte que les dimensions, variables et attributs puissent être ajoutés ou renommés, et que les attributs puissent être supprimés.

integer function nfmpi_enddef(integer ncid)

(Correspond à nf_enddef() dans netCDF)

Sort un jeu de données netCDF ouvert du mode définition. Les modifications apportées au jeu de données netCDF pendant qu'il était en mode définition sont vérifiées et validées sur disque si aucun problème n'est survenu. Après un appel réussi, les données des variables peuvent être lues ou écrites dans le jeu de données.

integer function nfmpi_sync(integer ncid)

(Correspond à nf_sync() dans netCDF)

Les données écrites par les API PnetCDF peuvent être mises en cache par le système de fichiers local sur chaque nœud de calcul. Cette API vide les données mises en cache en appelant MPI_File_sync.

integer function nfmpi_abort(integer ncid)

(Correspond à nf_abort() dans netCDF)

Vous n'avez pas besoin d'appeler cette fonction. Elle est appelée automatiquement par nfmpi_close() si le netCDF était en mode définition et que quelque chose s'est mal passé avec la validation. Si le jeu de données netCDF n'est pas en mode définition, alors cette fonction est équivalente à nfmpi_close(). Si elle est appelée après nfmpi_redef(), mais avant nfmpi_enddef(), les nouvelles définitions ne sont pas validées et le jeu de données est fermé. Si elle est appelée après nfmpi_create() mais avant nfmpi_enddef(), le jeu de données disparaît.

integer function nfmpi_close(integer ncid)

(Correspond à nf_close() dans netCDF)

Ferme un jeu de données netCDF ouvert. Si le jeu de données est en mode définition, nfmpi_enddef() sera appelé avant la fermeture. Après la fermeture d'un jeu de données, son identifiant peut être réaffecté à un autre jeu de données.

VARIABLES

integer function nfmpi_def_var(integer ncid, character*(*) name, integer xtype, integer ndims, integer dimids(1), integer varid)

(Correspond à nf_def_var() dans netCDF)

Ajoute une nouvelle variable à un jeu de données netCDF. Le jeu de données netCDF doit être en mode définition. varid sera défini sur l'identifiant de la variable netCDF. ndims sera le nombre de dimensions pour la variable. name sera le nom de la variable netCDF. xtype est le type externe netCDF de la variable et doit être l'un des types suivants : NF_BYTE, NF_CHAR, NF_SHORT, NF_INT, NF_FLOAT, ou NF_DOUBLE, pour les formats de fichiers CDF-1 et CDF-2. CDF-5 définit des types externes supplémentaires : NF_UBYTE, NF_USHORT, NF_UINT, NF_INT64 et NF_UINT64. L'argument dimids est un vecteur de ndims identifiants de dimension correspondant aux dimensions de la variable.

DESCRIPTIONS DES ARGUMENTS COMMUNES

Dans cette section, nous définissons certains arguments courants utilisés dans la section "DESCRIPTIONS DES FONCTIONS".

entier ncid
est l'ID netCDF renvoyé par un appel réussi précédent à nfmpi_open() ou nfmpi_create()
caractère*(*) nom
est le nom d'une dimension, d'une variable ou d'un attribut. Les noms des dimensions, variables et attributs consistent en des séquences arbitraires de caractères alphanumériques (ainsi que le tiret bas '_', le point '.' et le tiret '-') , commençant par une lettre ou un tiret bas. (Cependant, les noms commençant par un tiret bas sont réservés à un usage système.) La casse est significative dans les noms netCDF. Un nom de longueur zéro n'est pas autorisé.

Le nombre maximum de caractères autorisés
est NF_MAX_NAME.

entier xtype
spécifie le type de données externe d'une variable ou d'un attribut netCDF et est l'un des suivants : NF_BYTE, NF_CHAR, NF_SHORT, NF_INT, NF_FLOAT, ou NF_DOUBLE pour les formats de fichiers CDF-1 et CDF-2. Ceux-ci sont utilisés pour spécifier des entiers de 8 bits, des caractères, des entiers de 16 bits, des entiers de 32 bits, des nombres flottants IEEE de 32 bits, et des nombres flottants IEEE de 64 bits, respectivement.

CDF-5 définit des types externes supplémentaires : NF_UBYTE, NF_USHORT, NF_UINT, NF_INT64, et NF_UINT64.

entier dimids(1)
est un vecteur d'ID de dimensions et définit la forme d'une variable netCDF. La taille du vecteur doit être supérieure ou égale au rang (c'est-à-dire le nombre de dimensions) de la variable (ndims). Le vecteur doit être ordonné par la vitesse à laquelle une dimension varie : dimids(1) doit être l'ID de la dimension la plus rapidement variable et dimids(ndims) doit être l'ID de la dimension la plus lentement variable. Le nombre maximum possible de dimensions pour une variable est donné par la constante symbolique NF_MAX_VAR_DIMS.
entier dimid
est l'ID d'une dimension netCDF. Les ID de dimensions netCDF sont alloués séquentiellement à partir des entiers positifs commençant par 1.
entier ndims
est soit le nombre total de dimensions dans un jeu de données netCDF, soit le rang (c'est-à-dire le nombre de dimensions) d'une variable netCDF. La valeur ne doit pas être négative ou supérieure à la constante symbolique NF_MAX_VAR_DIMS.
entier varid
est l'ID d'une variable netCDF ou (pour les fonctions d'accès aux attributs) la constante symbolique NF_GLOBAL, qui est utilisée pour référencer les attributs globaux. Les ID de variables netCDF sont alloués séquentiellement à partir des entiers positifs commençant par 1.
entier natts
est le nombre d'attributs globaux dans un jeu de données netCDF pour la fonction nfmpi_inquire() ou le nombre d'attributs associés à une variable netCDF pour la fonction nfmpi_varinq().
entier(genre=MPI_OFFSET) index(1)
spécifie les coordonnées de la valeur de données netCDF à accéder. Les indices commencent à 1 ; ainsi, par exemple, la première valeur de données d'une variable bidimensionnelle est (1,1). La taille du vecteur doit être au moins égale au rang de la variable netCDF associée et ses éléments doivent correspondre, dans l'ordre, aux dimensions de la variable.
entier(genre=MPI_OFFSET) start(1)
spécifie le point de départ pour accéder aux valeurs de données d'une variable netCDF en termes de coordonnées indicées du coin de la section du tableau. Les indices commencent à 1 ; ainsi, la première valeur de données d'une variable est (1, 1, ..., 1). La taille du vecteur doit être au moins égale au rang de la variable netCDF associée et ses éléments doivent correspondre, dans l'ordre, aux dimensions de la variable.
entier(genre=MPI_OFFSET) count(1)
spécifie le nombre d'indices sélectionnés le long de chaque dimension de la section du tableau. Ainsi, pour accéder à une seule valeur, par exemple, spécifiez count comme (1, 1, ..., 1). Notez que, pour les E/S avec pas, cet argument doit être ajusté pour être compatible avec les arguments stride et start afin que l'interaction des trois n'essaie pas d'accéder à une coordonnée de données invalide. Les éléments du vecteur count correspondent, dans l'ordre, aux dimensions de la variable.
entier(genre=MPI_OFFSET) stride(1)
spécifie l'intervalle d'échantillonnage le long de chaque dimension de la variable netCDF. Les éléments du vecteur de pas correspondent, dans l'ordre, aux dimensions de la variable netCDF (stride(1)) donne l'intervalle d'échantillonnage le long de la dimension la plus rapidement variable de la variable netCDF). Les intervalles d'échantillonnage sont spécifiés en unités d'éléments indépendants du type (une valeur de 1 sélectionne des éléments consécutifs de la variable netCDF le long de la dimension correspondante, une valeur de 2 sélectionne un élément sur deux, etc.).
entier(genre=MPI_OFFSET) imap(1)
spécifie le mappage entre les dimensions d'une variable netCDF et la structure en mémoire du tableau de données interne. Les éléments du vecteur de mappage d'index correspondent, dans l'ordre, aux dimensions de la variable netCDF (imap(1) donne la distance entre les éléments du tableau interne correspondant à la dimension la plus rapidement variable de la variable netCDF). Les distances entre les éléments sont spécifiées en unités indépendantes du type, en nombre d'éléments (la distance entre les éléments internes qui occupent des emplacements mémoire adjacents est de 1 et non la longueur en octets de l'élément comme dans netCDF 2).

PREMPISSAGE DES VARIABLES

Avant la version 1.6.1, PnetCDF ne prend pas en charge le remplissage des données. Le mode de remplissage par défaut dans PnetCDF est NF_NOFILL. Ceci est contraire à la bibliothèque netCDF dont le défaut est NF_FILL. Lorsque le mode de remplissage est activé, PnetCDF définit les valeurs de toutes les nouvelles variables définies de longueur finie (c'est-à-dire celles qui n'ont pas de dimension illimitée) à la valeur de remplissage dépendante du type associée à chaque variable. Ceci est fait lorsque nfmpi_enddef() est appelé. La valeur de remplissage d'une variable peut être modifiée par rapport à la valeur par défaut en définissant l'attribut `_FillValue' pour la variable. Cet attribut doit avoir le même type que la variable et être de longueur un.

Les variables avec une dimension illimitée ne sont pas préremplies dans PnetCDF. Ceci est également contraire à netCDF, qui préremplit les variables d'enregistrement. Dans PnetCDF, le remplissage d'une variable d'enregistrement doit être effectué en appelant nfmpi_fill_var_rec(). Notez que ceci ne remplit qu'un seul enregistrement d'une variable.

Le mode de remplissage pour l'ensemble du fichier peut être défini par nfmpi_set_fill(). La définition du mode de remplissage par variable est également disponible via nfmpi_def_var_fill(). Dans PnetCDF, la modification du mode de remplissage doit être effectuée en mode définition. Dans netCDF, cela est vrai uniquement pour les variables de taille fixe. Pour les variables d'enregistrement, la modification du mode de remplissage peut être effectuée à tout moment dans NetCDF.
