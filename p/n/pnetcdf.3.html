PnetCDF(3) FONCTIONS DE BIBLIOTHÈQUE PnetCDF(3)

NOM

PnetCDF - Bibliothèque parallèle pour accéder aux fichiers au format Network Common Data Form (CDF, CDF-2 et CDF-5)

SYNTAXE

#include <pnetcdf.h>

mpicc ... -lpnetcdf

La documentation complète des bibliothèques PnetCDF est disponible sur le site web de PnetCDF : http://cucis.ece.northwestern.edu/projects/PnetCDF/.

VERSION DE BIBLIOTHÈQUE

Ce document décrit les API PnetCDF pour le langage de programmation C.

const char* ncmpi_inq_libvers()

(Correspond à nc_inq_libvers() dans netCDF)

Retourne une chaîne identifiant la version de la bibliothèque PnetCDF, et sa date de compilation, par exemple : « 1.14.1 du 2025-07-31 ».

La commande RCS ident(1) trouvera une chaîne comme « $Id: @(#) PnetCDF library version 1.14.1 of 2025-07-31 $ » dans la bibliothèque. La commande SCCS what(1) trouvera une chaîne comme « PnetCDF library version 1.14.1 of 2025-07-31 ».

VALEURS DE RETOUR

Toutes les fonctions PnetCDF (sauf ncmpi_inq_libvers() et ncmpi_strerror()) retournent un statut entier.

Si cette valeur de statut retournée n'est pas égale à NC_NOERR (zéro), cela indique qu'une erreur s'est produite. Les valeurs de statut possibles sont définies dans le fichier d'inclusion système <errno.h> et dans « pnetcdf.h ».

const char* ncmpi_strerror(int status)

(Correspond à nc_strerror() dans netCDF)

Retourne une traduction textuelle sous forme de chaîne de la valeur de status, comme « Nom d'attribut ou de variable contenant des caractères illégaux » ou « Aucun fichier ou répertoire de ce type ».

OPÉRATIONS DE FICHIER

int ncmpi_create(MPI_Comm comm, const char path[], int cmode, MPI_Info info, int* ncid)

(Correspond à nc_create() dans netCDF)

Crée un nouvel ensemble de données netCDF à path collectivement par un groupe de processus MPI spécifié par comm, retournant un ID netCDF dans ncid. L'argument cmode peut inclure l'opération OU binaire des indicateurs suivants : NC_NOCLOBBER pour protéger les ensembles de données existants (par défaut c'est NC_CLOBBER, qui écrase silencieusement les existants), NC_64BIT_OFFSET pour créer un fichier au format offset 64 bits (CDF-2), par opposition au format classique, par défaut, ou NC_64BIT_DATA pour créer un fichier au format données 64 bits (CDF-5). Utilisez soit NC_64BIT_OFFSET, soit NC_64BIT_DATA. Le format offset 64 bits permet la création de très grands fichiers avec beaucoup moins de restrictions que le format netCDF classique, mais peut seulement être lu par la bibliothèque netCDF version 3.6 ou supérieure. Les utilisateurs sont avertis que les fichiers utilisant le format offset 64 bits ne seront pas reconnus par les applications netCDF liées à une version antérieure à la 3.6 de la bibliothèque netCDF. Les applications liées à la version 3.6 ou supérieure pourront accéder de manière transparente soit au format classique, soit au format offset 64 bits. Le format données 64 bits permet la création de très grandes variables tableaux. Les fichiers CDF-5 ne seront actuellement pas reconnus par les bibliothèques netCDF 3 ou 4.

L'argument cmode doit être cohérent entre tous les processus MPI qui créent collectivement le fichier. L'argument info est un objet d'information MPI. Les utilisateurs peuvent l'utiliser pour fournir des indications d'accès aux fichiers pour une amélioration supplémentaire des performances. Les indications incluent les indications MPI-IO existantes ainsi que celles définies et utilisées dans PnetCDF.

Lorsqu'un ensemble de données netCDF est créé, il est ouvert en mode NC_WRITE. Lorsque cette fonction retourne, le nouvel ensemble de données netCDF est en mode de définition.

int ncmpi_open(MPI_Comm comm, const char path[], int mode, MPI_Info info, int* ncid)

(Correspond à nc_open() dans netCDF)

Ouvre un ensemble de données netCDF existant à path collectivement par un groupe de processus MPI spécifié par comm, retournant un ID netCDF dans ncid. Le type d'accès est décrit par le paramètre mode, qui peut inclure l'opération OU binaire des indicateurs suivants : NC_WRITE pour un accès en lecture-écriture (lecture seule par défaut).

L'argument mode doit être cohérent entre tous les processus MPI qui ouvrent collectivement le fichier. L'argument info est un objet d'information MPI. Les utilisateurs peuvent l'utiliser pour fournir des indications d'accès aux fichiers pour une amélioration supplémentaire des performances. Les indications incluent les indications MPI-IO existantes ainsi que celles définies et utilisées dans PnetCDF.

int ncmpi_redef(int ncid)

(Correspond à nc_redef() dans netCDF)

Met un ensemble de données netCDF ouvert en mode de définition, afin que les dimensions, les variables et les attributs puissent être ajoutés ou renommés et les attributs puissent être supprimés.

int ncmpi_enddef(int ncid)

(Correspond à nc_enddef() dans netCDF)

Sort un ensemble de données netCDF ouvert du mode de définition. Les modifications apportées à l'ensemble de données netCDF pendant qu'il était en mode de définition sont vérifiées et validées sur le disque si aucun problème n'est survenu. Après un appel réussi, les données des variables peuvent être lues ou écrites dans l'ensemble de données.

int ncmpi_sync(int ncid)

(Correspond à nc_sync() dans netCDF)

Les données écrites par les API PnetCDF peuvent être mises en cache par le système de fichiers local sur chaque nœud de calcul. Cette API vide les données mises en cache en appelant MPI_File_sync.

int ncmpi_abort(int ncid)

(Correspond à nc_abort() dans netCDF)

Vous n'avez pas besoin d'appeler cette fonction. Cette fonction est appelée automatiquement par ncmpi_close() si le netCDF était en mode de définition et que quelque chose s'est mal passé lors de la validation. Si l'ensemble de données netCDF n'est pas en mode de définition, alors cette fonction est équivalente à ncmpi_close(). Si elle est appelée après ncmpi_redef(), mais avant ncmpi_enddef(), les nouvelles définitions ne sont pas validées et l'ensemble de données est fermé. Si elle est appelée après ncmpi_create() mais avant ncmpi_enddef(), l'ensemble de données disparaît.

int ncmpi_close(int ncid)

(Correspond à nc_close() dans netCDF)

Ferme un ensemble de données netCDF ouvert. Si l'ensemble de données est en mode de définition, ncmpi_enddef() sera appelé avant la fermeture. Après la fermeture d'un ensemble de données, son ID peut être réaffecté à un autre ensemble de données.

(Correspond à nc_inq_format() dans netCDF)

Utilisez ces fonctions pour savoir ce qu'il y a dans un ensemble de données netCDF. En cas de succès, ndims contiendra le nombre de dimensions définies pour cet ensemble de données netCDF, nvars contiendra le nombre de variables, natts contiendra le nombre d'attributs, et unlimdimid contiendra l'ID de la dimension illimitée s'il en existe une, ou -1 sinon. formatn contiendra le numéro de version de l'ensemble de données <format>, l'un de NC_FORMAT_CLASSIC, NC_FORMAT_64BIT, ou NC_FORMAT_64BIT_DATA. Si l'un des paramètres de retour est un pointeur NULL, alors les informations correspondantes ne seront pas retournées ; par conséquent, aucun espace ne doit y être alloué.

DIMENSIONS

int ncmpi_def_dim(int ncid, const char name[], MPI_Offset len, int* dimid)

(Corresponds to nc_def_dim() in netCDF)

Creates a new dimension in a netCDF dataset. The netCDF must be in define mode. The dimension is identified by name and has length len. If the length is zero, the dimension is created as an unlimited dimension. If not NULL, then dimid will contain the dimension ID of the newly created dimension.

DIMENSIONS

int ncmpi_inq_dimid(int ncid, const char name[], int* dimid)

(Corresponds to nc_inq_dimid() in netCDF)

Given a dimension name, returns the ID of a netCDF dimension in dimid.

int ncmpi_inq_dim(int ncid, int dimid, char name[], MPI_Offset* len)

(Corresponds to nc_inq_dim() in netCDF)

(Corresponds to nc_inq_dimname() in netCDF)

int ncmpi_inq_dimlen(int ncid, int dimid, MPI_Offset* len)

(Corresponds to nc_inq_dimlen() in netCDF)

Use these functions to find out about a dimension. If either the name argument or len argument is a NULL pointer, then the associated information will not be returned. Otherwise, name should be big enough (NC_MAX_NAME) to hold the dimension name as the name will be copied into your storage. The length return parameter, len will contain the size of the dimension. For the unlimited dimension, the returned length is the current maximum value used for writing into any of the variables which use the dimension.

int ncmpi_rename_dim(int ncid, int dimid, const char name[])

(Corresponds to nc_rename_dim() in netCDF)

Renames an existing dimension in an open netCDF dataset. If the new name is longer than the old name, the netCDF dataset must be in define mode. You cannot rename a dimension to have the same name as another dimension.

VARIABLES

int ncmpi_def_var(int ncid, const char name[], nc_type xtype, int ndims, const int dimids[], int* varid)

(Corresponds to nc_def_var() in netCDF)

Adds a new variable to a netCDF dataset. The netCDF must be in define mode. If not NULL, then varid will be set to the netCDF variable ID. ndims will be the number of dimensions for the variable. name will be the name of the netCDF variable. xtype is the external, netCDF type of the variable and should be one of NC_BYTE NC_CHAR, NC_SHORT, NC_INT, NC_FLOAT, or NC_DOUBLE, for CDF-1 and CDF-2 file formats. CDF-5 defines additional external types: NC_UBYTE, NC_USHORT, NC_UINT, NC_INT64, and NC_UINT64. dimids argument is a vector of ndims dimension IDs corresponding to the variable dimensions.

Contrairement aux variables, les attributs n'ont pas de fonctions distinctes pour la définition et l'écriture des valeurs. Cette famille de fonctions définit un nouvel attribut avec une valeur ou modifie la valeur d'un attribut existant. Si l'attribut est nouveau, ou si l'espace requis pour stocker la valeur de l'attribut est supérieur à ce qu'il était auparavant, le jeu de données netCDF doit être en mode de définition. Le paramètre len est le nombre de valeurs de out à transférer. Il est souvent égal à un, sauf que pour ncmpi_put_att_text(), il sera généralement égal à strlen(out).

Pour ces fonctions, le composant de type du nom de la fonction fait référence au type en mémoire de la valeur, tandis que l'argument xtype fait référence au type externe pour le stockage de la valeur. Une erreur NC_ERANGE résulte si une conversion entre ces types n'est pas possible. Dans ce cas, la valeur est représentée avec la valeur de remplissage appropriée pour le type externe associé.

int ncmpi_inq_attname(int ncid, int varid, int attnum, char name[])

(Correspond à nc_inq_attname() dans netCDF)

Obtient le nom d'un attribut, étant donné son identifiant de variable et son numéro d'attribut. Cette fonction est utile dans les applications génériques qui doivent obtenir les noms de tous les attributs associés à une variable, car les attributs sont accédés par leur nom plutôt que par leur numéro dans toutes les autres fonctions d'attributs. Le numéro d'un attribut est plus volatile que son nom, car il peut changer lorsque d'autres attributs de la même variable sont supprimés. Les attributs de chaque variable sont numérotés de 0 (le premier attribut) à nvatts-1, où nvatts est le nombre d'attributs pour la variable, tel que retourné par un appel à ncmpi_inq_varnatts(). Si le paramètre name est un pointeur NULL, aucun nom ne sera retourné et aucun espace ne devra être alloué.

Descriptions des arguments courants

Dans cette section, nous définissons certains arguments courants utilisés dans la section "DESCRIPTIONS DES FONCTIONS".

int ncid
est l'identifiant netCDF retourné par un appel réussi précédent à ncmpi_open() ou ncmpi_create()
char name[]
est le nom d'une dimension, d'une variable ou d'un attribut. Les noms des dimensions, des variables et des attributs consistent en des séquences arbitraires de caractères alphanumériques (ainsi que le trait de soulignement '_', le point '.' et le trait d'union '-') , commençant par une lettre ou un trait de soulignement. (Cependant, les noms commençant par un trait de soulignement sont réservés à l'usage système.) La casse est significative dans les noms netCDF. Un nom de longueur nulle n'est pas autorisé. En tant qu'argument d'entrée, il doit s'agir d'un pointeur vers une chaîne terminée par 0 ; en tant qu'argument de sortie, il doit s'agir de l'adresse d'un tampon dans lequel stocker une telle chaîne. Le nombre maximum de caractères autorisés (hors le 0 de terminaison) est NC_MAX_NAME.
nc_type xtype
spécifie le type de données externe d'une variable ou d'un attribut netCDF et est l'un des suivants : NC_BYTE, NC_CHAR, NC_SHORT, NC_INT, NC_FLOAT, ou NC_DOUBLE pour les formats de fichiers CDF-1 et CDF-2. Ceux-ci sont utilisés pour spécifier des entiers de 8 bits, des caractères, des entiers de 16 bits, des entiers de 32 bits, des nombres flottants IEEE de 32 bits et des nombres flottants IEEE de 64 bits, respectivement. (NC_LONG dans la version 2 de netCDF est maintenant obsolète et défini à NC_INT). CDF-5 définit des types externes supplémentaires : NC_UBYTE, NC_USHORT, NC_UINT, NC_INT64 et NC_UINT64.
int dimids[]
est un vecteur d'identifiants de dimensions et définit la forme d'une variable netCDF. La taille du vecteur doit être supérieure ou égale au rang (c'est-à-dire le nombre de dimensions) de la variable (ndims). Le vecteur doit être ordonné selon la vitesse à laquelle une dimension varie : dimids[ndims-1] doit être l'identifiant de la dimension qui varie le plus rapidement et dimids[0] doit être l'identifiant de la dimension qui varie le plus lentement. Le nombre maximum possible de dimensions pour une variable est donné par la constante symbolique NC_MAX_VAR_DIMS.
int dimid
est l'identifiant d'une dimension netCDF. Les identifiants de dimensions netCDF sont alloués séquentiellement à partir des entiers non négatifs en commençant par 0.
int ndims
est soit le nombre total de dimensions dans un jeu de données netCDF, soit le rang (c'est-à-dire le nombre de dimensions) d'une variable netCDF. La valeur ne doit pas être
e négative ou supérieure à la constante symbolique NC_MAX_VAR_DIMS.
entier varid
est l'ID d'une variable netCDF ou (pour les fonctions d'accès aux attributs) la constante symbolique NC_GLOBAL, utilisée pour référencer les attributs globaux. Les ID de variables netCDF sont alloués séquentiellement à partir des entiers non négatifs commençant par 0.
entier* natts
est le nombre d'attributs globaux dans un jeu de données netCDF pour la fonction ncmpi_inquire() ou le nombre d'attributs associés à une variable netCDF pour la fonction ncmpi_varinq().
const MPI_Offset index[]
spécifie les coordonnées de la valeur de donnée netCDF à accéder. Les indices commencent à 0 ; ainsi, par exemple, la première valeur de donnée d'une variable bidimensionnelle est (0,0). La taille du vecteur doit être au moins égale au rang de la variable netCDF associée et ses éléments doivent correspondre, dans l'ordre, aux dimensions de la variable.
const MPI_Offset start[]
spécifie le point de départ pour accéder aux valeurs de données d'une variable netCDF en termes de coordonnées indicées du coin de la section du tableau. Les indices commencent à 0 ; ainsi, la première valeur de donnée d'une variable est (0, 0, ..., 0). La taille du vecteur doit être au moins égale au rang de la variable associée et ses éléments doivent correspondre, dans l'ordre, aux dimensions de la variable.
const MPI_Offset count[]
spécifie le nombre d'indices sélectionnés le long de chaque dimension de la section du tableau. Ainsi, pour accéder à une seule valeur, par exemple, spécifiez count comme (1, 1, ..., 1). Notez que, pour les I/O avec pas, cet argument doit être ajusté pour être compatible avec les arguments stride et start afin que l'interaction des trois n'essaie pas d'accéder à une coordonnée de donnée invalide. Les éléments du vecteur count correspondent, dans l'ordre, aux dimensions de la variable.
const MPI_Offset stride[]
spécifie l'intervalle d'échantillonnage le long de chaque dimension de la variable netCDF. Les éléments du vecteur de pas correspondent, dans l'ordre, aux dimensions de la variable netCDF (stride[0]) donne l'intervalle d'échantillonnage le long de la dimension la moins variant rapidement de la variable netCDF). Les intervalles d'échantillonnage sont spécifiés en unités indépendantes du type d'éléments (une valeur de 1 sélectionne des éléments consécutifs de la variable netCDF le long de la dimension correspondante, une valeur de 2 sélectionne un élément sur deux, etc.). Un argument de pas NULL est traité comme (1, 1, ... , 1).
const MPI_Offset imap[]
spécifie le mappage entre les dimensions d'une variable netCDF et la structure en mémoire du tableau de données interne. Les éléments du vecteur de mappage d'index correspondent, dans l'ordre, aux dimensions de la variable netCDF (imap[0] donne la distance entre les éléments du tableau interne correspondant à la dimension la moins variant rapidement de la variable netCDF). Les distances entre les éléments sont spécifiées en unités indépendantes du type d'éléments (la distance entre les éléments internes qui occupent des emplacements mémoire adjacents est de 1 et non la longueur en octets de l'élément comme dans netCDF 2). Un pointeur NULL signifie que les valeurs résidentes en mémoire ont la même structure que la variable netCDF associée.

PRÉEMPLISAGE DES VARIABLES

Avant la version 1.6.1, PnetCDF ne prend pas en charge le remplissage des données. Le mode de remplissage par défaut dans PnetCDF est NC_NOFILL, contrairement à la bibliothèque netCDF dont le défaut est NC_FILL. Lorsque le mode de remplissage est activé, PnetCDF affecte aux valeurs de toutes les variables nouvellement définies de longueur finie (c'est-à-dire celles qui n'ont pas de dimension illimitée) la valeur de remplissage dépendante du type associée à chaque variable. Ceci est fait lorsque ncmpi_enddef() est appelé. La valeur de remplissage d'une variable peut être modifiée par rapport à la valeur par défaut en définissant l'attribut `_FillValue' pour la variable. Cet attribut doit avoir le même type que la variable et être de longueur un.

Les variables avec une dimension illimitée ne sont pas préremplies dans PnetCDF. Ceci est également contraire à netCDF, qui préremplit les variables d'enregistrement. Dans PnetCDF, le remplissage d'une variable d'enregistrement doit être effectué en appelant ncmpi_fill_var_rec(). Notez que cela ne remplit qu'un seul enregistrement d'une variable.

Le mode de remplissage pour l'ensemble du fichier peut être défini par ncmpi_set_fill(). La définition du mode de remplissage par variable est également disponible via ncmpi_def_var_fill(). Dans PnetCDF, le changement du mode de remplissage doit être effectué en mode de définition. En netCDF, ce n'est vrai que pour les variables de taille fixe. Pour les variables d'enregistrement, le changement du mode de remplissage peut être effectué à tout moment dans NetCDF.
