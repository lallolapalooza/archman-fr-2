NOM

pnmcolormap - créer une palette de couleurs de quantification pour une image Netpbm

SYNTAXE

pnmcolormap

[-centre|-couleur_moyenne|-pixel_moyen]

[-luminosite_etalee|-luminosite_etalee]

[-trier]

[-carre]

ncouleurs|tout

[fichier_pnm]

DESCRIPTION

Ce programme fait partie de Netpbm(1)

pnmcolormap lit une image PNM ou PAM en entrée, choisit ncouleurs couleurs pour représenter au mieux l'image et écrit une palette de couleurs PNM la définissant en sortie. Une image PAM peut en fait contenir des tuples de n'importe quel type, mais le concept de pnmcolormap des valeurs de tuples qui représentent au mieux ceux présents dans l'image peut ne pas avoir de sens si le type de tuple n'est pas RGB ou GRISSCALE. La conception du programme, et le reste de ce manuel, suppose que les tuples représentent des couleurs.

Vous pouvez utiliser cette palette comme entrée pour pnmremap sur la même image d'entrée pour quantifier les couleurs de cette image, c'est-à-dire produire une image similaire avec moins de couleurs. pnmquant fait les étapes pnmcolormap et pnmremap pour vous.

Une palette PNM est une image PNM de toutes dimensions qui contient au moins un pixel de chaque couleur de l'ensemble des couleurs qu'elle représente. Celles que pnmcolormap génère ont exactement un pixel de chaque couleur, sauf lorsque le remplissage est nécessaire avec l'option -carre.

La méthode de quantification est la 'median cut' de Heckbert. Voir MÉTHODE DE QUANTIFICATION.

L'image de sortie est du même format (PBM, PGM, PPM, PAM) que l'image d'entrée. Notez qu'une palette d'une image PBM n'est pas très intéressante.

La palette a généralement le même maxval que l'image d'entrée, mais pnmcolormap peut le réduire s'il y a trop de couleurs dans l'entrée, dans le cadre de son algorithme de quantification.

pnmcolormap fonctionne sur un flux d'entrée multi-images. Dans ce cas, il produit une seule palette qui s'applique à toutes les couleurs de toutes les images d'entrée. Toutes les images doivent avoir le même format, la même profondeur et le même maxval (mais peuvent avoir des hauteurs et largeurs différentes). Ceci est utile si vous devez quantifier un tas d'images qui formeront un film ou seront autrement utilisées ensemble -- vous voudrez généralement qu'elles proviennent toutes de la même palette, alors que calculer une palette séparément pour chaque image ferait que la même couleur dans deux images serait mappée à des couleurs différentes. Avant Netpbm 10.31 (décembre 2005), pnmcolormap ignorait toute image après la première.

Si vous souhaitez créer une palette sans la baser sur les couleurs d'une image d'entrée, pamseq, ppmmake et pnmcat peuvent être utiles.

PARAMÈTRES

Le seul paramètre, qui est obligatoire, est le nombre de couleurs que vous souhaitez dans la palette de sortie. pnmcolormap peut produire une palette avec un nombre légèrement inférieur de couleurs. Vous pouvez spécifier tout pour obtenir une palette de toutes les couleurs de l'image d'entrée (pas de quantification).

OPTIONS

Toutes les options peuvent être abrégées à leur préfixe unique le plus court. Vous pouvez utiliser deux tirets au lieu d'un pour désigner une option. Vous pouvez utiliser soit un espace blanc, soit un signe égal entre un nom d'option et sa valeur.

-trier
Cette option fait que la palette de sortie soit triée par l'intensité du composant rouge, puis le vert, puis le bleu dans l'ordre croissant. Il s'agit d'un tri par insertion, il n'est donc pas très rapide sur les grandes palettes. Le tri est utile car il vous permet de comparer deux ensembles de couleurs.
-carre
Par défaut, pnmcolormap produit en sortie une image PPM avec une ligne et une colonne pour chaque couleur de la palette. Cette option fait que pnmcolormap produit plutôt une image PPM qui est à moins d'une ligne ou d'une colonne d'être carrée, avec le dernier pixel dupliqué si nécessaire pour créer un nombre de pixels qui est un carré presque parfait.
-verbose
Cette option fait que pnmcolormap affiche des messages sur la sortie d'erreur standard concernant la quantification..TP -centre
-couleur_moyenne
-pixel_moyen
-luminosite_etalee
-luminosite_etalee
Ces options contrôlent l'algorithme de quantification. Voir MÉTHODE DE QUANTIFICATION.

MÉTHODE DE QUANTIFICATION

Une méthode de quantification est une façon de choisir quelles couleurs, en nombre inférieur à celles de l'entrée, vous souhaitez dans la sortie. pnmcolormap utilise la méthode de quantification 'median cut' de Heckbert.

Cette méthode consiste à séparer toutes les couleurs en 'boîtes', chacune contenant des couleurs qui représentent à peu près le même nombre de pixels. Vous commencez avec une boîte et divisez les boîtes en deux jusqu'à ce que le nombre de boîtes soit égal au nombre de couleurs que vous souhaitez dans la sortie, et vous choisissez une couleur pour représenter chaque boîte.

Lorsque vous divisez une boîte, vous le faites de sorte que toutes les couleurs d'une sous-boîte soient 'supérieures' à toutes les couleurs de l'autre. 'Supérieur', pour une boîte particulière, signifie qu'elle est plus lumineuse dans le composant de couleur (rouge, vert, bleu) qui a la plus grande étendue dans cette boîte. pnmcolormap vous donne deux façons de définir la 'plus grande étendue' : 1) la plus grande étendue de luminosité ; 2) la plus grande étendue de contribution à la luminosité de la couleur. Par exemple, le rouge est pondéré beaucoup plus que le bleu. Sélectionnez parmi celles-ci avec les options -luminosite_etalee et -luminosite_etalee. Par défaut, c'est -luminosite_etalee.

pnmcolormap offre trois façons de choisir une couleur pour représenter une boîte : 1) la couleur centrale - la couleur à mi-chemin entre les couleurs la plus grande et la moins grande dans la boîte, en utilisant la définition ci-dessus de 'supérieur' ; 2) la moyenne des couleurs (chaque composant moyenné séparément par luminosité) dans la boîte ; 3) la moyenne pondérée par le nombre de pixels d'une couleur dans l'image.

Notez que dans les trois méthodes, il peut y avoir des couleurs dans la sortie qui n'apparaissent pas du tout dans l'entrée.

Sélectionnez parmi celles-ci avec les options -centre, -couleur_moyenne et -pixel_moyen. Par défaut, c'est -centre.

HISTORIQUE

Avant Netpbm 10.15 (avril 2003), pnmcolormap utilisait beaucoup plus de mémoire pour les grandes images car il gardait toute l'image d'entrée en mémoire. Désormais, il la traite ligne par ligne, mais comme il doit parfois effectuer plusieurs passes sur l'image, il copie d'abord l'entrée dans un fichier temporaire consultable si elle n'est pas déjà dans un fichier consultable.

pnmcolormap est apparu pour la première fois dans Netpbm 9.23 (janvier 2002). Avant cela, sa fonction n'était disponible que dans le cadre de la fonction de pnmquant (qui dérivait du ppmquant beaucoup plus ancien). La quantification des couleurs a vraiment deux sous-fonctions principales, donc Netpbm 9.23 les a séparées en deux programmes distincts : pnmcolormap et pnmremap, puis Netpbm 9.24 a remplacé pnmquant par un programme qui appelle simplement pnmcolormap et pnmremap.
