Iptables

et

ip6tables sont utilisés pour configurer, maintenir et inspecter les tables de règles de filtrage de paquets IPv4 et IPv6 dans le noyau Linux. Plusieurs tables différentes peuvent être définies. Chaque table contient un certain nombre de chaînes intégrées et peut également contenir des chaînes

définies

par l'utilisateur. Chaque chaîne est une liste de règles qui peuvent correspondre

à un ensemble de paquets. Chaque règle spécifie quoi faire d'un paquet qui
correspond. C'est ce qu'on appelle une « cible », qui peut être un saut vers

une

Si le paquet ne correspond pas, la règle suivante de la chaîne est examinée ; s'il correspond, alors la règle suivante est spécifiée par la valeur de la cible, qui peut être le nom d'une chaîne définie par l'utilisateur, l'une des cibles décrites dans iptables-extensions(8) , ou l'u

RETURN signifie arrêter de parcourir cette chaîne et reprendre à la règle suivante de la chaîne précédente (appelante). Le protocole de la règle ou du paquet à vérifier. Le protocole spécifié peut être l'un des suivants tcp, udp, udplite, icmp, icmpv6, esp, ah, sctp, mh ou le mot-clé spécial "all", ou il peut s'agir d'une valeur numérique, représentant l'un de ces protocoles ou un autre. FICHIER DE VERROUILLAGE

iptables utilise le fichier /run/xtables.lock pour obtenir un verrou exclusif au lancement.

La variable d'environnement XTABLES_LOCKFILE peut être utilisée pour remplacer le réglage par défaut.

EXTENSIONS DE CORRESPONDANCE ET DE CIBLE

iptables peut utiliser des modules d'extension pour la correspondance de paquets et les cibles. Une liste de ceux-ci est disponible dans la page de manuel iptables-extensions(8).

DIAGNOSTICS

Divers messages d'erreur sont affichés sur la sortie d'erreur standard. Le code de sortie est 0 pour un fonctionnement correct. Les erreurs qui semblent être causées par des paramètres de ligne de commande invalides ou mal utilisés entraînent un code de sortie de 2. Les erreurs qui indiquent une incompatibilité entre le noyau et l'espace utilisateur entraînent un code de sortie de 3. Les erreurs qui indiquent un problème de ressources, tel qu'un verrou occupé, une allocation de mémoire échouée ou des messages d'erreur du noyau, entraînent un code de sortie de 4. Enfin, les autres erreurs entraînent un code de sortie de 1.

COMPATIBILITÉ AVEC IPCHAINS

Cet iptables est très similaire à ipchains de Rusty Russell. La principale différence est que les chaînes INPUT et OUTPUT ne sont traversées que pour les paquets arrivant sur l'hôte local et provenant de l'hôte local respectivement. Par conséquent, chaque paquet ne traverse qu'une seule des trois chaînes (sauf le trafic de bouclage, qui implique les chaînes INPUT et OUTPUT) ; auparavant, un paquet transféré traversait les trois.

L'autre différence principale est que -i fait référence à l'interface d'entrée ; -o fait référence à l'interface de sortie, et les deux sont disponibles pour les paquets entrant dans la chaîne FORWARD.

Les différentes formes de NAT ont été séparées ; iptables est un filtre de paquets pur lors de l'utilisation de la table `filter' par défaut, avec des modules d'extension optionnels. Cela devrait éviter une grande partie de la confusion concernant la combinaison du masquage IP et du filtrage de paquets observée précédemment. Les options suivantes sont donc traitées différemment :

 -j MASQ
 -M -S
 -M -L
Il y a plusieurs autres changements dans iptables.
