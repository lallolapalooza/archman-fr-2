DESCRIPTIO

N

ipmi-config est utilisé pour obtenir et définir des paramètres de configuration dans IPMI. Il peut être utilisé pour configurer les noms d'utilisateur, les mots de passe, les informations de réseau, la sécurité, Serial-over-LAN (SOL), le filtrage des événements de plateforme (PEF), les périphériques de démarrage, la politique de restauration de l'alimentation, les seuils des capteurs, les événements des capteurs et de nombreuses autres options de configuration. Une certaine configuration est généralement requise avant que la plupart des outils IPMI puissent être utilisés pour accéder à une machine à distance. Par défaut, ipmi-config vous permettra de --checkout ou --commit uniquement les valeurs IPMI de base nécessaires à la configuration IPMI. Pour des champs de configuration avancés supplémentaires liés à la configuration du châssis (y compris les options de démarrage), au filtrage des événements de plateforme (PEF) ou aux capteurs, voir l'option --category ci-dessous. Pour plus de détails sur la configuration IPMI de base, voir ipmi-config.conf(5). La majorité des opérations de configuration nécessitent le privilège ADMIN lors de l'utilisation de ipmi-config hors bande. Bien que la connexion via un utilisateur disposant des privilèges ADMIN ne soit pas requise pour une utilisation hors bande, la grande majorité des options de configuration ne seront ni récupérées ni

définies.

Ci-dessous sont listées les options IPMI générales, les options propres à l'outil, les informations de dépannage, les informations de contournement, des exemples et des problèmes connus. Pour une introduction générale à FreeIPMI, veuillez consulter freeipmi(7). Voir UTILISATION GÉNÉRALE ci-dessous pour une description de l'utilisation de base de ipmi-confi

g

UTILISATION

GÉNÉRALE

La plupart des utilisateurs voudront

:

A) Exécuter avec --checkout pour obtenir une copie de la configuration actuelle et la stocker dans un fichier. La sortie standard peut être redirigée vers un fichier ou un fichier peut être spécifié avec l'option --fi

lename.

B) Éditer le fichier de configuration avec un

éditeur.

C) Remettre la configuration en utilisant l'option --commit et en spécifiant le fichier de configuration avec l'option --filename. La configuration peut être remise à plusieurs hôtes en parallèle via la prise en charge des plages

d'hôtes.

Bien que ce ne soit généralement pas nécessaire, certaines cartes mères ne stockent pas les valeurs de configuration en mémoire non volatile. Par conséquent, après un redémarrage du système, certaines valeurs de configuration peuvent avoir changé. L'utilisateur peut souhaiter exécuter les outils de configuration à chaque démarrage pour s'assurer que les valeurs de configuration

persistent.

Des commentaires seront listés occasionnellement dans les fichiers extraits avec des informations sur la façon de configurer les champs. La page de manuel ipmi-config.conf(5) fournit également des informations supplémentaires sur la signification des différents

champs.

Pour les utilisateurs ayant de grands clusters ou des ensembles de nœuds, vous pouvez souhaiter utiliser le même fichier de configuration pour tous les nœuds. Le seul problème est que l'adresse IP et l'adresse MAC seront différentes sur chaque nœud de votre cluster et ne peuvent donc pas être configurées via le même fichier de configuration. L'adresse IP et l'adresse MAC dans votre fichier de configuration peuvent être écrasées en ligne de commande avec l'option --key-pair. L'exemple suivant pourrait être utilisé dans un script pour configurer chaque nœud d'un cluster avec le même fichier de configuration BMC. Le script doit seulement déterminer l'adresse IP et l'adresse MAC correctes à

utiliser.

# ipmi-config --commit -k Lan_Conf:Ip

_Address=$MY_IP -k Lan_Conf:Mac_A
ddress=$MY_MAC --filename=my_bmc.conf

INFORMATIONS DE CONFIGURATION DES CAS PARTICULIERS DU NOYAU

Les champs UserN:Password (où N est un nombre) ne peuvent pas être extraits sur certains systèmes, par conséquent la valeur extraite sera toujours vide.

Le champ UserN:Enable_User (où N est un nombre) ne peut pas être extrait sur les anciens systèmes IPMI, par conséquent la valeur extraite sera parfois vide.

Les champs UserN:Lan_Session_Limit et UserN:Serial_Session_Limit (où N est un nombre) ne peuvent pas être extraits sur certains systèmes, par conséquent la valeur extraite sera toujours vide. S'ils ne sont pas spécifiés dans les commits ultérieurs des configurations, les champs peuvent être réinitialisés à 0 en raison d'une exigence que d'autres champs (configurés avec la limite de session) nécessitent une valeur d'entrée pour la limite de session. Dans la plupart des cas, il n'est pas nécessaire de définir ce champ et la plupart des utilisateurs peuvent choisir de l'ignorer. Ce champ est considéré comme facultatif par les normes IPMI et peut entraîner des erreurs lors de la tentative de le configurer à une valeur non nulle. Si des erreurs surviennent, la réinitialisation de la valeur à 0 devrait résoudre les problèmes.

Les champs Lan_Conf:IP_Address et Lan_Conf:MAC_Address ne peuvent pas être validés en parallèle via la prise en charge des plages d'hôtes. Chaque machine doit être configurée avec un tuple unique d'adresse IP et d'adresse MAC, c'est pourquoi nous interdisons cette configuration dans ipmi-config.

Sur certaines cartes mères, Lan_Conf:MAC_Address peut être en lecture seule et l'adresse MAC est configurée automatiquement.

Sur certaines cartes mères, Lan_Conf:MAC_Address peut être en lecture seule et l'adresse MAC est configurée via une commande OEM. Voir ipmi-oem(8) pour savoir si la configuration OEM pour votre carte mère est prise en charge.

Sur certaines cartes mères, plusieurs champs de configuration d'utilisateur ne peuvent pas être lus ou configurés avant qu'un nom d'utilisateur non nul ou un mot de passe non nul ne soit configuré. Dans certains de ces cas, une sortie appropriée dans le fichier de configuration indiquera cette situation. Cependant, tous les cas particuliers des cartes mères ne peuvent pas être détectés. Les utilisateurs peuvent souhaiter jouer avec l'ordre des champs pour contourner ces problèmes.

Sur certaines cartes mères, l'authentification OEM dans Lan_Conf_Auth ne peut pas être activée. Cependant, les paramètres par défaut de la carte mère ont ces champs activés. Il est conseillé aux utilisateurs de désactiver toute authentification OEM dans cette section.

Sur certaines cartes mères, plusieurs canaux peuvent exister pour la communication IPMI LAN ou série. Si plusieurs canaux existent, la configuration des deux canaux peut être visualisée et finalement configurée en exécutant --checkout en mode verbeux. Chaque section ou nom de clé sera suffixé de manière appropriée avec le mot Channel et le numéro de canal. Par exemple, vous pourriez voir un Lan_Conf_Channel_1 et un Lan_Conf_Channel_3, où vous pouvez configurer la configuration LAN sur les canaux 1 et 3 respectivement.

Sur certaines cartes mères, les modifications de configuration ne seront pas "absorbées" par le système avant que la carte mère ne soit réinitialisée (hard-reset). Cela peut être accompli en éteignant et en rallumant physiquement le système (par exemple, en appuyant sur un bouton), ou cela peut être accompli par une réinitialisation à froid (cold-reset). Une réinitialisation à froid peut être exécutée via bmc-device.

INFORMATIONS DE CONFIGURATION DES CAS PARTICULIERS DU CHÂSSIS

Les champs Chassis_Front_Panel_Buttons:Enable_Standby_Button_For_Entering_Standby, Chassis_Front_Panel_Buttons:Enable_Diagnostic_Interrupt_Button Chassis_Front_Panel_Buttons:Enable_Reset_Button, et Chassis_Front_Panel_Buttons:Enable_Power_Off_Button_For_Power_Off_Only peuvent ne pas pouvoir être extraits sur certains systèmes IPMI, par conséquent la valeur extraite peut être vide. Certains de ces champs peuvent être désactivables, tandis que d'autres ne le sont pas. Le champ Chassis_Power_Conf:Power_Control_Interval ne peut pas être extrait. Par conséquent, la valeur extraite sera toujours vide.

INFORMATIONS DE CONFIGURATION DES CAS PARTICULIERS DES CAPTEURS

Étant donné que de nombreux champs configurables impliquent des nombres décimaux, des imprécisions de précision/virgule flottante peuvent survenir lors de la configuration de nouveaux seuils. Les imprécisions peuvent ne pas être apparentes immédiatement. Il est recommandé aux utilisateurs de vérifier leurs modifications après avoir configuré de nouveaux seuils.

PRISE EN CHARGE DE HOSTRANGED

Plusieurs hôtes peuvent être saisis sous forme de listes d'hôtes explicites séparées par des virgules ou une plage de noms d'hôtes sous la forme générale : préfixe[n-m,l-k,...], où n < m et l < k, etc. Cette dernière forme ne doit pas être confondue avec les classes de caractères d'expressions régulières (également désignées par []). Par exemple, foo[19] ne représente pas foo1 ou foo9, mais plutôt une plage dégénérée : foo19.

Cette syntaxe de plage est destinée uniquement à des fins de commodité sur les clusters avec une convention de nommage préfixeNN et la spécification de plages ne doit pas être considérée comme nécessaire -- la liste foo1,foo9 peut être spécifiée comme telle, ou par la plage foo[1,9].

Voici quelques exemples d'utilisation de plages :

    foo[01-05] au lieu de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] au lieu de foo7,foo9,foo10
    foo[0-3] au lieu de foo0,foo1,foo2,foo3

Pour rappel au lecteur, certains shells interpréteront les crochets ([ et ]) pour la correspondance de modèles. Selon votre shell, il peut être nécessaire d'encadrer les listes de plages entre guillemets.

Lorsque plusieurs hôtes sont spécifiés par l'utilisateur, un thread sera exécuté pour chaque hôte en parallèle jusqu'à la limite de diffusion configurée (qui peut être ajustée via l'option -F). Cela permettra de communiquer avec un grand nombre de nœuds beaucoup plus rapidement que s'ils étaient traités séquentiellement.

Par défaut, la sortie standard de chaque nœud spécifié sera affichée avec le nom d'hôte préfixé à chaque ligne. Bien que cette sortie soit lisible dans de nombreuses situations, elle peut être difficile à lire dans d'autres situations. Par exemple, la sortie de plusieurs nœuds peut être mélangée. Les options -B et -C peuvent être utilisées pour modifier ce comportement par défaut.

La communication IPMI en bande (In-band IPMI) sera utilisée lorsque l'hôte "localhost" est spécifié. Cela permet à l'utilisateur d'ajouter localhost à la sortie hostranged.

DÉPANNAGE GÉNÉRAL

Le plus souvent, les problèmes IPMI sont dus à des problèmes de configuration.

Les problèmes IPMI sur LAN impliquent une mauvaise configuration du BMC de la machine distante. Vérifiez attentivement que les éléments suivants sont correctement configurés dans le BMC de la machine distante : adresse IP, adresse MAC, masque de sous-réseau, nom d'utilisateur, activation de l'utilisateur, privilège utilisateur, mot de passe, privilège LAN, activation LAN et type(s) d'authentification autorisé(s). Pour les connexions IPMI 2.0, vérifiez attentivement que le privilège de la suite de chiffrement et la clé K_g sont correctement configurés. L'outil ipmi-config(8) peut être utilisé pour vérifier et/ou modifier ces paramètres de configuration.

Les problèmes IPMI en bande (Inband IPMI) sont généralement causés par des pilotes mal configurés ou des BMC non standard.

En plus des conseils de dépannages ci-dessous, veuillez également consulter les solutions de contournement ci-dessous si des bogues spécifiques au fournisseur ont été découverts et contournés.

Voici une liste de nombreux problèmes courants pour les messages d'erreur. Pour une assistance supplémentaire, veuillez envoyer un e-mail à la liste de diffusion <freeipmi-users@gnu.org>.

"username invalid" - Le nom d'utilisateur saisi (ou un nom d'utilisateur NUL si aucun n'a été saisi) n'est pas disponible sur la machine distante. Il est également possible que la configuration du nom d'utilisateur du BMC distant soit incorrecte.

"password invalid" - Le mot de passe saisi (ou un mot de passe NUL si aucun n'a été saisi) n'est pas correct. Il est également possible que le mot de passe de l'utilisateur ne soit pas correctement configuré sur le BMC distant.

"password verification timeout" - La vérification du mot de passe a expiré. Une erreur "password invalid" (décrite ci-dessus) ou une erreur générique "session timeout" (décrite ci-dessous) s'est produite. À ce stade du protocole, il ne peut pas être différencié quelle erreur s'est produite.

"k_g invalid" - La clé K_g saisie (ou une clé K_g NUL si aucune n'a été saisie) n'est pas correcte. Il est également possible que la clé K_g ne soit pas correctement configurée sur le BMC distant.

"privilege level insufficient" - Une commande IPMI nécessite un niveau de privilège utilisateur supérieur à celui avec lequel vous êtes authentifié. Veuillez essayer de vous authentifier avec un privilège plus élevé. Cela peut nécessiter de s'authentifier auprès d'un utilisateur différent qui a un privilège maximum plus élevé.

"privilege level cannot be obtained for this user" - Le niveau de privilège avec lequel vous tentez de vous authentifier est supérieur au maximum autorisé pour cet utilisateur. Veuillez réessayer avec un privilège inférieur. Il est également possible que le niveau de privilège maximum autorisé pour un utilisateur ne soit pas correctement configuré sur le BMC distant.

"authentication type unavailable for attempted privilege level" - Le type d'authentification avec lequel vous souhaitez vous authentifier n'est pas disponible

ailable for this privilege level. Please try again with an alternate authentication type or alternate privilege level. It may also be possible the available authentication types you can authenticate with are not correctly configured on the remote

BMC.

"cipher suite id unavailable" - The cipher suite id you wish to authenticate with is not available on the remote BMC. Please try again with an alternate cipher suite id. It may also be possible the available cipher suite ids are not correctly configured on the remote

BMC.

"ipmi 2.0 unavailable" - IPMI 2.0 was not discovered on the remote machine. Please try to use IPMI 1.5

instead.

"connection timeout" - Initial IPMI communication failed. A number of potential errors are possible, including an invalid hostname specified, an IPMI IP address cannot be resolved, IPMI is not enabled on the remote server, the network connection is bad, etc. Please verify configuration and

connectivity.

"session timeout" - The IPMI session has timed out. Please reconnect. If this error occurs often, you may wish to increase the retransmission timeout. Some remote BMCs are considerably slower than

others.

"device not found" - The specified device could not be found. Please check configuration or inputs and try

again.

"driver timeout" - Communication with the driver or device has timed out. Please try

again.

"message timeout" - Communication with the driver or device has timed out. Please try

again.

"BMC busy" - The BMC is currently busy. It may be processing information or have too many simultaneous sessions to manage. Please wait and try

again.

"could not find inband device" - An inband device could not be found. Please check configuration or specify specific device or driver on the command

line.

"driver timeout" - The inband driver has timed out communicating to the local BMC or service processor. The BMC or service processor may be busy or (worst case) possibly

non-functioning
.

SOLUTIONS DE

CONTORNEMENT

Avec autant de fournisseurs implémentant leurs propres solutions IPMI, différents fournisseurs peuvent implémenter incorrectement leurs protocoles IPMI. Ce qui suit décrit un certain nombre de solutions de contournement actuellement disponibles pour gérer les problèmes de conformité découverts. Lorsque c'est possible, des solutions de contournement ont été implémentées pour qu'elles soient transparentes pour l'utilisateur. Cependant, certaines nécessiteront que l'utilisateur spécifie une solution de contournement via l'option

-W.

Le matériel listé ci-dessous peut seulement indiquer le matériel sur lequel un problème a été découvert. Des versions plus récentes du matériel peuvent corriger les problèmes indiqués ci-dessous. Des machines similaires de différents fournisseurs peuvent ou non présenter les mêmes problèmes. Différents fournisseurs peuvent obtenir leur firmware du même développeur de firmware IPMI, il peut donc être utile d'essayer les solutions de contournement listées ci-dessous même si votre carte mère n'est pas

listée.

Si vous pensez que votre matériel a un problème de conformité supplémentaire nécessitant une solution de contournement, veuillez contacter les mainteneurs de FreeIPMI sur <freeipmi-users@gnu.org> ou <freeipmi-devel@gnu.org>

.

assumeio - Cet indicateur de contournement supposera que les interfaces inband communiquent avec les E/S du système plutôt que d'être mappées en mémoire. Cela contournera les systèmes qui rapportent des adresses de base invalides. Ceux qui rencontrent ce problème peuvent voir les erreurs "device not supported" ou "could not find inband device". Problème observé sur HP ProLiant DL145

G1.

spinpoll - Cet indicateur de contournement informera certains pilotes inband (notamment le pilote KCS) de tourner en boucle pendant l'interrogation plutôt que de mettre le processus en veille. Cela peut améliorer significativement le temps d'exécution réel des outils car la granularité d'un ordonnanceur de système d'exploitation peut être bien plus grande que le temps nécessaire pour effectuer une seule transaction de message IPMI. Cependant, en tournant en boucle, votre système peut effectuer moins de travail utile en ne basculant pas le contexte de l'outil pour une tâche plus

utile.

authcap - Cet indicateur de contournement sautera les vérifications précoces des capacités de nom d'utilisateur, des capacités d'authentification et du support K_g et permettra à l'authentification IPMI de réussir. Cela contourne plusieurs problèmes où le système distant ne rapporte pas correctement les capacités de nom d'utilisateur, les capacités d'authentification ou le statut K_g. Ceux qui rencontrent ce problème peuvent voir les erreurs "username invalid", "authentication type unavailable for attempted privilege level" ou "k_g invalid". Problème observé sur Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML, et Sun Fire 2200/4150/4450 avec

ELOM.

nochecksumcheck - Cet indicateur de contournement indiquera à FreeIPMI de ne pas vérifier les sommes de contrôle retournées par les réponses aux commandes IPMI. Cela contourne les systèmes qui retournent des sommes de contrôle invalides en raison d'erreurs d'implémentation, mais le paquet est autrement valide. Les utilisateurs sont avertis quant à l'utilisation de cette option, car elle supprime la validation de l'intégrité du paquet dans un certain nombre de circonstances. Cependant, il est peu probable que ce soit un problème dans la plupart des situations. Ceux qui rencontrent ce problème peuvent voir les erreurs "connection timeout", "session timeout" ou "password verification timeout". Sur les connexions IPMI 1.5, la solution de contournement "noauthcodecheck" peut aussi être nécessaire. Problème observé sur Supermicro X9SCM-iiF, Supermicro X9DRi-F, et Supermicro

X9DRFR.

idzero - Cet indicateur de contournement permettra aux identifiants de session vides d'être acceptés par le client. Cela contourne les sessions IPMI qui rapportent des identifiants de session vides au client. Ceux qui rencontrent ce problème peuvent voir les erreurs "session timeout". Problème observé sur Tyan S2882 avec BMC

M3289.

unexpectedauth - Cet indicateur de contournement permettra aux codes d'authentification non nuls inattendus d'être vérifiés comme s'ils étaient attendus. Cela contourne un problème lorsque les paquets contiennent des données d'authentification non nules alors qu'elles devraient être nulles en raison de l'authentification par message désactivée. Ceux qui rencontrent ce problème peuvent voir les erreurs "session timeout". Problème observé sur Dell PowerEdge 2850, SC1425. Confirmé corrigé sur un firmware plus

récent.

forcepermsg - Cet indicateur de contournement forcera l'authentification par message à être utilisée peu importe ce qui est annoncé par le système distant. Cela contourne un problème lorsque l'authentification par message est annoncée comme désactivée sur le système distant, mais qu'elle est en réalité requise pour le protocole. Ceux qui rencontrent ce problème peuvent voir les erreurs "session timeout". Problème observé sur IBM eServer

325.

endianseq - Cet indicateur de contournement inversera l'endianness des numéros de séquence de session pour permettre à la session de continuer correctement. Cela contourne les numéros de séquence de session IPMI 1.5 qui ont la mauvaise endianness. Ceux qui rencontrent ce problème peuvent voir les erreurs "session timeout". Problème observé sur certains Sun ILOM 1.0/2.0 (dépend de l'endianness du processeur de service)

.

noauthcodecheck - Cet indicateur de contournement indiquera à FreeIPMI de ne pas vérifier les codes d'authentification retournés par les réponses aux commandes IPMI 1.5. Cela contourne les systèmes qui retournent des codes d'authentification invalides en raison d'erreurs de hachage ou d'implémentation. Les utilisateurs sont avertis quant à l'utilisation de cette option, car elle supprime une vérification d'authentification qui valide l'intégrité d'un paquet. Cependant, dans la plupart des organisations, il est peu probable que ce soit un problème de sécurité. Ceux qui rencontrent ce problème peuvent voir les erreurs "connection timeout", "session timeout" ou "password verification timeout". Problème observé sur Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell, et Wiwynn

Windmill.

intel20 - Cet indicateur de contournement contournera plusieurs problèmes d'authentification IPMI 2.0 d'Intel. Les problèmes couverts incluent le remplissage des noms d'utilisateur et la troncature du mot de passe si l'algorithme d'authentification est HMAC-MD5-128. Ceux qui rencontrent ce problème peuvent voir les erreurs "username invalid", "password invalid" ou "k_g invalid". Problème observé sur Intel SE7520AF2 avec Intel Server Management Module (Professional Edition)

.

supermicro20 - Cet indicateur de contournement contournera plusieurs problèmes d'authentification IPMI 2.0 de Supermicro sur les cartes mères avec firmware IPMI Peppercon. Les problèmes couverts incluent la gestion des codes d'authentification de longueur invalide. Ceux qui rencontrent ce problème peuvent voir les erreurs "password invalid". Problème observé sur Supermicro H8QME avec carte fille SIMSO. Confirmé corrigé sur un firmware plus

récent.

sun20 - Cet indicateur de contournement contournera plusieurs problèmes d'authentification IPMI 2.0 de Sun. Les problèmes couverts incluent les clés de hachage de longueur invalide, les clés mal hachées et les enregistrements de suite de chiffrement invalides. Ceux qui rencontrent ce problème peuvent voir les erreurs "password invalid" ou "bmc error". Problème observé sur Sun Fire 4100/4200/4500 avec ILOM. Cette solution de contournement inclut automatiquement la solution de contournement

"opensesspriv".

opensesspriv - Cet indicateur de contournement modifiera légèrement le protocole de connexion IPMI 2.0 de FreeIPMI pour contourner un algorithme de hachage invalide utilisé par le système distant. Le niveau de privilège envoyé pendant l'étape Open Session d'une connexion IPMI 2.0 est utilisé pour hacher les clés au lieu du niveau de privilège envoyé pendant l'étape de connexion RAKP1. Ceux qui rencontrent ce problème peuvent voir les erreurs "password invalid", "k_g invalid", "bad rmcpplus status code" ou "privilege level cannot be obtained for this user". Problème observé sur Sun Fire 4100/4200/4500 avec ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220, et le logiciel BMC OpenIPMI. Cette solution de contournement est automatiquement déclenchée avec la solution de contournement

"sun20".

integritycheckvalue - Cet indicateur de contournement contournera une valeur de vérification d'intégrité invalide lors de l'établissement d'une session IPMI 2.0 lors de l'utilisation de Cipher Suite ID 0. La valeur de vérification d'intégrité devrait être de longueur 0, cependant la carte mère distant répond avec un champ non vide. Ceux qui rencontrent ce problème peuvent voir les erreurs "k_g invalid". Problème observé sur Supermicro X8DTG, Supermicro X8DTU, et Intel S5500WBV/Penguin Relion 700, et Intel S2600JF/Appro

512X.

Pas de support IPMI 1.5 - Certaines cartes mères qui supportent IPMI 2.0 ont été trouvées ne pas supporter IPMI 1.5. Ceux qui rencontrent ce problème peuvent voir les erreurs "ipmi 2.0 unavailable" ou "connection timeout". Ce problème peut être contourné en utilisant IPMI 2.0 au lieu d'IPMI 1.5 en spécifiant --driver-type=LAN_2_0. Problème observé sur un certain nombre de cartes mères HP et

Supermicro.

slowcommit - Cette solution de contournement ralentira les commits vers le BMC en dormant une seconde entre le commit des sections. Cela contourne les cartes mères dont les BMC peuvent être submergés par les commits. Ceux qui rencontrent ce problème peuvent voir des erreurs de commit ou des commits qui ne sont pas écrits dans le BMC. Problème observé sur Supermicro

H8QME.

NOM

ipmi-config - lire, diff et écrire les données de configuration IPMI

SYNTAXIS

ipmi-config [ OPTIONS ]

DESCRIPTION

ipmi-config est un outil de ligne de commande pour interroger et configurer l'interface de gestion de la carte mère (BMC) des systèmes informatiques. Il peut lire, comparer et écrire des données de configuration depuis et vers le BMC.

OPTIONS GÉNÉRALES

-h, --help
Afficher un message d'aide.
-V, --version
Afficher les informations de version.
-c, --comma-separated
Utiliser des virgules comme séparateurs pour les sorties.
-H HOST, --host=HOST
Spécifier le nom d'hôte ou l'adresse IP du BMC.
-U USER, --username=USER
Spécifier le nom d'utilisateur pour l'authentification IPMI.
-P PASSWORD, --password=PASSWORD
Spécifier le mot de passe pour l'authentification IPMI.
-K SECRET, --privilege-key=SECRET
Spécifier la clé de privilège pour l'authentification IPMI.
-p PORT, --port=PORT
Spécifier le port IPMI. La valeur par défaut est 623.
-L SESSION, --session=SESSION
Spécifier le type de session IPMI. Les valeurs possibles sont "ipmi", "ssh" et "redfish".
-v, --verbose
Activer la sortie détaillée.

IPMI-CONFIG OPTIONS

--checkout
Récupérer la configuration du BMC.
--commit
Écrire la configuration dans le BMC.
--diff
Comparer la configuration actuelle avec celle d'un fichier.
--filename=FILENAME
Spécifier le nom du fichier de configuration.
--category=CATEGORY
Spécifier la catégorie de configuration à lire ou écrire. Les catégories possibles sont : core, chassis, pef, sensors, fru, oem.
--key-pair=KEY:VALUE
Spécifier une paire clé-valeur pour la configuration.

SDR CACHE OPTIONS

--sdr-cache-load
Charger le cache SDR depuis un fichier.
--sdr-cache-save
Sauvegarder le cache SDR dans un fichier.
--sdr-cache-file=FILENAME
Spécifier le nom du fichier de cache SDR.

HOSTRANGED OPTIONS

--hostranged-start=HOST
Spécifier le premier hôte dans une plage.
--hostranged-end=HOST
Spécifier le dernier hôte dans une plage.

EXEMPLES

# ipmi-config --checkout

Sort toutes les informations de configuration de base sur la console. # ipmi-config --checkout --category=pef

Sort toutes les informations de configuration pef sur la console. # ipmi-config --checkout --category=pef,chassis

Sort toutes les informations de configuration pef et chassis sur la console.

# ipmi-config --checkout --filename=bmc-data1.conf

Stocke toutes les informations de configuration de base dans bmc-data1.conf.

# ipmi-config --diff --filename=bmc-data2.conf

Affiche toutes les différences entre la configuration actuelle et le fichier bmc-data2.conf.

# ipmi-config --diff --key-pair="lan_conf_misc:gratuitous_arp_interval=8"

Affiche la différence entre la configuration actuelle et 'lan_conf_misc:gratuitous_arp_interval' de valeur '8'.

# ipmi-config --commit --filename=bmc-data1.conf

Valide toutes les valeurs de configuration du fichier bmc-data1.conf.

# ipmi-config --commit --key-pair="lan_conf_misc:gratuitous_arp_interval=4"

Valide la clé 'lan_conf_misc:gratuitous_arp_interval' de valeur '4'.

# ipmi-config --commit --filename=bmc-data-updt.conf --key-pair="lan_conf_misc:gratuitous_arp_interval=4"

Valide toutes les valeurs de configuration de bmc-data-updt.conf et la clé 'lan_conf_misc:gratuitous_arp_interval' de valeur '4'.

DIAGNOSTICS

En cas de succès, le code de sortie est 0. En cas d'erreur non fatale, le code de sortie est 1. En cas d'erreur fatale, le code de sortie est 2.

Si plusieurs hôtes sont spécifiés pour la communication, le code de sortie est 0 si et seulement si toutes les cibles s'exécutent avec succès. Si une erreur non fatale se produit, le code de sortie est 1. Si une erreur fatale se produit, le code de sortie est 2.

PROBLÈMES CONNUS

Sur les systèmes d'exploitation plus anciens, si vous saisissez votre nom d'utilisateur, votre mot de passe et d'autres informations potentiellement liées à la sécurité sur la ligne de commande, ces informations peuvent être découvertes par d'autres utilisateurs lors de l'utilisation d'outils tels que la commande ps(1) ou en consultant le système de fichiers /proc. Il est généralement plus sûr de saisir les informations de mot de passe avec des options telles que les options -P ou -K. La configuration d'informations relatives à la sécurité dans le fichier de configuration FreeIPMI serait également un moyen approprié de masquer ces informations.

Afin d'empêcher les attaques par force brute, certains BMC se "verrouillent" temporairement après un certain nombre d'erreurs d'authentification à distance. Vous devrez peut-être attendre un peu pour que ce "verrouillage" temporaire passe avant de pouvoir vous authentifier à nouveau.
