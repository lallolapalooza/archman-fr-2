NOM

ip-vrf - exécuter une commande contre une vrf

SYNTAXE


ip vrf { COMMANDE | help }

ip vrf show [ NOM ]

ip vrf identify [ PID ]

ip vrf pids NOM

ip vrf exec [ NOM ] commande...

DESCRIPTION

Une VRF fournit une isolation du trafic au niveau de la couche 3 pour le routage, similaire à la façon dont une VLAN est utilisée pour isoler le trafic au niveau de la couche 2. Fondamentalement, une VRF est une table de routage distincte. Les périphériques réseau sont associés à une VRF en asservissant le périphérique à la VRF. À ce stade, les adresses réseau attribuées au périphérique sont locales à la VRF, avec les routes d'hôte et connectées déplacées vers la table associée à la VRF.

Un processus peut spécifier une VRF en utilisant plusieurs API — en liant le socket au périphérique VRF à l'aide de SO_BINDTODEVICE, en définissant l'association VRF à l'aide de IP_UNICAST_IF ou IPV6_UNICAST_IF, ou en spécifiant la VRF pour un message spécifique à l'aide de IP_PKTINFO ou IPV6_PKTINFO.

Par défaut, un processus n'est lié à aucune VRF. Une association peut être définie explicitement en faisant utiliser un programme l'une des API mentionnées ci-dessus ou implicitement en utilisant une aide pour définir SO_BINDTODEVICE pour tous les sockets IPv4 et IPv6 (AF_INET et AF_INET6) lors de la création du socket. Cette commande ip-vrf est une aide pour exécuter une commande contre une VRF spécifique avec l'association VRF héritée du parent à l'enfant.

ip vrf show [ NOM ] - Afficher toutes les VRF configurées

Cette commande liste toutes les VRF et leurs identifiants de table correspondants. Si NOM est donné, alors seule cette VRF et son identifiant de table sont affichés. Cette dernière commande est utile pour les scripts où l'identifiant de table pour une VRF est nécessaire.

ip vrf exec [ NOM ] cmd ... - Exécuter cmd contre la VRF nommée

Cette commande permet aux applications non VRF-conscientes d'être exécutées contre une VRF autre que la VRF par défaut (table principale). Une commande peut être exécutée contre la VRF par défaut en passant "default" comme nom de VRF. Ceci est utile si le shell actuel est associé à une autre VRF (par exemple, VRF de gestion).

Cette commande nécessite que le système soit démarré avec cgroup v2 (par exemple, avec systemd, ajoutez systemd.unified_cgroup_hierarchy=1 à la ligne de commande du noyau).

Cette commande nécessite également d'être exécutée en tant que root. Alternativement, elle peut être exécutée par un utilisateur non privilégié si les capabilities(7) suivantes sont données :

CAP_BPF
Pour charger le programme BPF.
CAP_NET_ADMIN
Pour définir le socket dans le cgroup.
CAP_DAC_OVERRIDE
Pour créer le sous-répertoire cgroup dans /sys.
Si ces capabilities sont ajoutées et si ip(8) est compilé avec libcap(3) alors ces capabilities seront supprimées avant que cmd ne soit exécuté par ip vrf exec. Pour toute autre invocation non privilégiée de ip(8) toutes les capabilities seront supprimées.

NOTE : les capabilities ne seront PAS supprimées si CAP_NET_ADMIN est défini sur INHERITABLE afin d'éviter de casser les programmes avec des capacités ambiantes qui appellent ip.

ip vrf identify [PID] - Rapporter l'association VRF pour un processus

Cette commande affiche l'association VRF du processus spécifié. Si PID n'est pas spécifié, alors l'identifiant du processus actuel est utilisé.

ip vrf pids NOM - Rapporter les processus associés à la VRF nommée

Cette commande affiche tous les identifiants de processus associés à la VRF donnée.

CAVEATS

Cette commande nécessite un noyau compilé avec CGROUPS et CGROUP_BPF activés.

L'aide VRF n'affecte *que* les sockets de couche réseau.

EXEMPLES

ip vrf exec red ssh 10.100.1.254

Exécute ssh vers 10.100.1.254 contre la table VRF red.
