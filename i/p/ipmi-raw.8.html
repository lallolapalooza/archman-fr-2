DESCRIPTIO

N

Ipmi-raw est utilisé pour exécuter des commandes IPMI par valeurs hexadécimales. Les valeurs hexadécimales peuvent être saisies sur la ligne de commande, dans un fichier via l'option --file , ou via stdin si aucune des deux méthodes précédentes n'est

spécifiée.

Ci-dessous sont listées les options IPMI générales, les options spécifiques à l'outil, les informations de dépannage, les informations de contournement, des exemples et des problèmes connus. Pour une introduction générale à FreeIPMI, veuillez consulter free

ipmi
(7).

SUPPORT

HOSTRANGED

Plusieurs hôtes peuvent être saisis soit sous forme de listes explicites d'hôtes séparés par des virgules, soit sous forme d'une plage de noms d'hôtes de la forme générale : préfixe[n-m,l-k,...], où n < m et l < k, etc. La dernière forme ne doit pas être confondue avec les classes de caractères des expressions régulières (aussi notées []). Par exemple, foo[19] ne représente pas foo1 ou foo9, mais représente plutôt une plage dégénérée :

foo19.

Cette syntaxe de plage n'est destinée qu'à la commodité sur les clusters avec une convention de nommage préfixeNN et la spécification de plages ne doit pas être considérée comme nécessaire -- la liste foo1,foo9 pourrait être spécifiée ainsi, ou par la plage foo[1,9]

.

Quelques exemples d'utilisation des plages suivent

: 
    foo[01-05] au lieu de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] au lieu de foo7,foo9,foo10
    foo[0-3] au lieu de foo0,foo1,foo2,
foo3

Pour rappel au lecteur, certains interpréteurs de commandes interpréteront les crochets ([ et ]) pour la correspondance de motifs. Selon votre interpréteur de commandes, il peut être nécessaire d'encadrer les listes de plages entre

guillemets.

Lorsque plusieurs hôtes sont spécifiés par l'utilisateur, un thread sera exécuté pour chaque hôte en parallèle jusqu'au fanout configuré (qui peut être ajusté via l' option -F). Cela permettra la communication avec un grand nombre de nœuds bien plus rapidement que si elle était effectuée en

série.

Par défaut, la sortie standard de chaque nœud spécifié sera affichée avec le nom d'hôte préfixé à chaque ligne. Bien que cette sortie soit lisible dans de nombreuses situations, elle peut être difficile à lire dans d'autres situations. Par exemple, la sortie de plusieurs nœuds peut être mélangée. La option -B et l'option -C peuvent être utilisées pour changer ce comportement par

défaut.

La communication IPMI en bande sera utilisée lorsque l'hô

te « localhost » est spécifié. Cela permet à l'utili
sateur d'ajouter le localhost à la sortie hostranged.

DÉPANNAGE

GÉNÉRAL

Le plus souvent, les problèmes IPMI sont dus à des problèmes de

configuration.

Les problèmes IPMI sur LAN impliquent une mauvaise configuration du BMC de la machine distante. Vérifiez à nouveau pour vous assurer que les éléments suivants sont configurés correctement dans le BMC de la machine distante : adresse IP, adresse MAC, masque de sous-réseau, nom d'utilisateur, activation de l'utilisateur, privilège de l'utilisateur, mot de passe, privilège LAN, activation LAN et type(s) d'authentification autorisé(s). Pour les connexions IPMI 2.0, vérifiez à nouveau pour vous assurer que le(s) privilège(s) de la suite de chiffrement et la clé K_g sont configurés correctement. L' outil ipmi-config(8) peut être utilisé pour vérifier et/ou modifier ces paramètres de

configuration.

Les problèmes IPMI en bande sont généralement causés par des pilotes mal configurés ou des BMC non

standard.

En plus des conseils de dépannage ci-dessous, veuillez voir la section SOLUTIONS DE CONTORNEMENT ci-dessous pour voir également s'il y a des bogues spécifiques à un fabricant qui ont été découverts et

contournés.

Ci-dessous sont listés nombreux problèmes courants pour les messages d'erreur. Pour un support supplémentaire, veuillez envoyer un courriel à la liste de diffusion <freeipmi-users@gnu.org>

.

« username invalid » - Le nom d'utilisateur saisi (ou un nom d'utilisateur NULL si aucun n'a été saisi) n'est pas disponible sur la machine distante. Il est également possible que la configuration du nom d'utilisateur du BMC distant soit

incorrecte.

« password invalid » - Le mot de passe saisi (ou un mot de passe NULL si aucun n'a été saisi) n'est pas correct. Il est également possible que le mot de passe de l'utilisateur ne soit pas correctement configuré sur le BMC

distant.

« password verification timeout » - La vérification du mot de passe a expiré. Une erreur « password invalid » (décrite ci-dessus) ou un « session timeout » générique (décrit ci-dessous) s'est produit. À ce point du protocole, il ne peut pas être différencié lequel s'est

produit.

« k_g invalid » - La clé K_g saisie (ou une clé K_g NULL si aucune n'a été saisie) n'est pas correcte. Il est également possible que la clé K_g ne soit pas correctement configurée sur le BMC

distant.

« privilege level insufficient » - Une commande IPMI nécessite un privilège utilisateur plus élevé que celui avec lequel l'authentification a été effectuée. Veuillez essayer de vous authentifier avec un privilège plus élevé. Cela peut nécessiter de s'authentifier à un utilisateur différent qui a un privilège maximum plus

élevé.

« privilege level cannot be obtained for this user » - Le niveau de privilège avec lequel vous essayez de vous authentifier est plus élevé que le maximum autorisé pour cet utilisateur. Veuillez réessayer avec un privilège plus bas. Il est également possible que le niveau de privilège maximum autorisé pour un utilisateur ne soit pas correctement configuré sur le BMC

distant.

« authentication type unavailable for attempted privilege level » - Le type d'authentification avec lequel vous souhaitez vous authentifier n'est pas disponible pour ce niveau de privilège. Veuillez réessayer avec un type d'authentification alternatif ou un niveau de privilège alternatif. Il est également possible que les types d'authentification disponibles avec lesquels vous pouvez vous authentifier ne soient pas correctement configurés sur le BMC

distant.

« cipher suite id unavailable » - L'identifiant de suite de chiffrement avec le quel vous souhaitez vous authentifier n'est pas disponible sur le BMC distant. Veuillez essayer avec un identifiant de suite de chiffrement alternatif. Il est également possible que les identifiants de suite de chiffrement disponibles ne soient pas correctement configurés sur le BMC

distant.

« ipmi 2.0 unavailable » - IPMI 2.0 n'a pas été découvert sur la machine distante. Veuillez essayer d'utiliser IPMI 1.5 à la

place.

« connection timeout » - La communication IPMI initiale a échoué. Un certain nombre d'erreurs potentielles sont possibles, y compris un nom d'hôte invalide spécifié, une adresse IP IPMI ne peut pas être résolue, IPMI n'est pas activé sur le serveur distant, la connexion réseau est mauvaise, etc. Veuillez vérifier la configuration et la

connectivité.

« session timeout » - La session IPMI a expiré. Veuillez vous reconnecter. Si cette erreur se produit souvent, vous pourriez souhaiter augmenter le délai d'attente de retransmission. Certains BMC distants sont considérablement plus lents que

d'autres.

« device not found » - Le périphérique spécifié n'a pas pu être trouvé. Veuillez vérifier la configuration ou les entrées et

réessayer.

« driver timeout » - La communication avec le pilote ou le périphérique a expiré. Veuillez

réessayer.

« message timeout » - La communication avec le pilote ou le périphérique a expiré. Veuillez

réessayer.

« BMC busy » - Le BMC est actuellement occupé. Il peut traiter des informations ou avoir trop de sessions simultanées à gérer. Veuillez patienter et

réessayer.

« could not find inband device » - Un périphérique en bande n'a pas pu être trouvé. Veuillez vérifier la configuration ou spécifier un périphérique ou pilote spécifique sur la ligne de

commande.

« driver timeout » - Le pilote en bande a expiré en communiquant avec le BMC local ou le processeur de service. Le BMC ou le processeur de service peut être occupé ou (pire) possiblement non

fonctionnel.

« internal IPMI error » - Une erreur IPMI s'est produite que

FreeIPMI ne sait pas comment gérer. Veuillez envoyer un cour
riel à <freeipmi-users@gnu.org> pour signaler le problème.

SOLUTIONS DE

CONTORNEMENT

Avec autant de fabricants différents implémentant leurs propres solutions IPMI, différents fabricants peuvent implémenter incorrectement leurs protocoles IPMI. Ce qui suit décrit un certain nombre de solutions de contournement actuellement disponibles pour gérer les problèmes de conformité découverts. Lorsque c'est possible, des solutions de contournement ont été mises en œuvre pour qu'elles soient transparentes pour l'utilisateur. Cependant, certaines nécessiteront à l'utilisateur de spécifier qu'une solution de contournement soit utilisée via l'option

-W.

Le matériel listé ci-dessous peut seulement indiquer le matériel sur lequel un problème a été découvert. Des versions plus récentes du matériel peuvent corriger les problèmes indiqués ci-dessous. Des machines similaires de fabricants peuvent ou non présenter les mêmes problèmes. Différents fabricants peuvent obtenir une licence de leur firmware auprès du même développeur de firmware IPMI, il peut donc être utile d'essayer les solutions de contournement listées ci-dessous même si votre carte mère n'est pas

listée.

Si vous pensez que votre matériel a un problème de conformité supplémentairee qui nécessite une solution de contournement, veuillez contacter les mainteneurs de FreeIPMI sur <freeipmi-users@gnu.org> ou <freeipmi-devel@gnu.org>

.

assumeio - Ce drapeau de contournement supposera que les interfaces inband communiquent avec l'E/S du système plutôt que d'être mappées en mémoire. Cela contournera les systèmes qui rapportent des adresses de base invalides. Ceux qui rencontrent ce problème peuvent voir les erreurs « device not supported » ou « could not find inband device ». Problème observé sur HP ProLiant DL145

G1.

spinpoll - Ce drapeau de contournement informera certains pilotes inband (notamment le pilote KCS) de tourner en boucle pendant l'interrogation plutôt que de mettre le processus en veille. Cela peut améliorer considérablement le temps d'exécution réel des outils car la granularité d'un ordonnanceur d'un système d'exploitation peut être bien plus grande que le temps nécessaire pour effectuer une seule transaction de message IPMI. Cependant, en tournant en boucle, votre système peut effectuer moins d'utilisations utiles en ne cédant pas la main de l'outil pour une tâche plus

utile.

authcap - Ce drapeau de contournement sautera les vérifications précoces des capacités de nom d'utilisateur, des capacités d'authentification et de la prise en charge de K_g et permettra à l'authentification IPMI de réussir. Cela contourne plusieurs problèmes où le système distant ne rapporte pas correctement les capacités de nom d'utilisateur, les capacités d'authentification ou le statut de K_g. Ceux qui rencontrent ce problème peuvent voir les erreurs « username invalid », « authentication type unavailable for attempted privilege level » ou « k_g invalid ». Problème observé sur Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML, et Sun Fire 2200/4150/4450 avec

ELOM.

nochecksumcheck - Ce drapeau de contournement indiquera à FreeIPMI de ne pas vérifier les sommes de contrôle renvoyées par les réponses aux commandes IPMI. Cela contourne les systèmes qui renvoient des sommes de contrôle invalides en raison d'erreurs d'implémentation, mais le paquet est par ailleurs valide. Les utilisateurs sont avertis quant à l'utilisation de cette option, car elle supprime la validation de l'intégrité des paquets dans un certain nombre de circonstances. Cependant, il est peu probable que cela pose problème dans la plupart des situations. Ceux qui rencontrent ce problème peuvent voir les erreurs « connection timeout », « session timeout » ou « password verification timeout ». Sur les connexions IPMI 1.5, le contournement « noauthcodecheck » peut également être nécessaire. Problème observé sur Supermicro X9SCM-iiF, Supermicro X9DRi-F, et Supermicro

X9DRFR.

idzero - Ce drapeau de contournement permettra aux identifiants de session vides d'être acceptés par le client. Cela contourne les sessions IPMI qui rapportent des identifiants de session vides au client. Ceux qui rencontrent ce problème peuvent voir les erreurs « session timeout ». Problème observé sur Tyan S2882 avec BMC

M3289.

unexpectedauth - Ce drapeau de contournement permettra aux codes d'authentification non nuls inattendus d'être vérifiés comme s'ils étaient attendus. Cela contourne un problème lorsque les paquets contiennent des données d'authentification non nules alors qu'elles devraient être nules en raison de l'authentification par message désactivée. Ceux qui rencontrent ce problème peuvent voir les erreurs « session timeout ». Problème observé sur Dell PowerEdge 2850, SC1425. Corrigé dans les firmwares plus

récents.

forcepermsg - Ce drapeau de contournement forcera l'utilisation de l'authentification par message, peu importe ce qui est annoncé par le système distant. Cela contourne un problème lorsque l'authentification par message est annoncée comme désactivée sur le système distant, mais qu'elle est en réalité requise pour le protocole. Ceux qui rencontrent ce problème peuvent voir les erreurs « session timeout ». Problème observé sur IBM eServer

325.

endianseq - Ce drapeau de contournement inversera l'endianness des numéros de séquence de session pour permettre à la session de continuer correctement. Cela contourne les numéros de séquence de session IPMI 1.5 dont l'endianness est incorrecte. Ceux qui rencontrent ce problème peuvent voir les erreurs « session timeout ». Problème observé sur certains Sun ILOM 1.0/2.0 (dépend de l'endianness du processeur de service)

.

noauthcodecheck - Ce drapeau de contournement indiquera à FreeIPMI de ne pas vérifier les codes d'authentification renvoyés par les réponses aux commandes IPMI 1.5. Cela contourne les systèmes qui renvoient des codes d'authentification invalides en raison d'erreurs de hachage ou d'implémentation. Les utilisateurs sont avertis quant à l'utilisation de cette option, car elle supprime une vérification d'authentification qui valide l'intégrité d'un paquet. Cependant, dans la plupart des organisations, il est peu probable que cela pose un problème de sécurité. Ceux qui rencontrent ce problème peuvent voir les erreurs « connection timeout », « session timeout » ou « password verification timeout ». Problème observé sur Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell, et Wiwynn

Windmill.

intel20 - Ce drapeau de contournement contournera plusieurs problèmes d'authentification IPMI 2.0 d'Intel. Les problèmes couverts incluent le remplissage des noms d'utilisateur et la troncature du mot de passe si l'algorithme d'authentification est HMAC-MD5-128. Ceux qui rencontrent ce problème peuvent voir les erreurs « username invalid », « password invalid » ou « k_g invalid ». Problème observé sur Intel SE7520AF2 avec Intel Server Management Module (Professional Edition)

supermicro20 - Ce drapeau de contournement contournera plusieurs problèmes d'authentification IPMI 2.0 de Supermicro sur les cartes mères avec firmware IPMI Peppercon. Les problèmes couverts incluent la gestion des codes d'authentification de longueur invalide. Ceux qui rencontrent ce problème peuvent voir les erreurs « password invalid ». Problème observé sur Supermicro H8QME avec carte fille SIMSO. Corrigé dans les firmwares plus

récents.

sun20 - Ce drapeau de contournement contournera plusieurs problèmes d'authentification IPMI 2.0 de Sun. Les problèmes couverts incluent les clés de hachage de longueur invalide, les clés mal hachées et les enregistrements de suite de chiffrement invalides. Ceux qui rencontrent ce problème peuvent voir les erreurs « password invalid » ou « bmc error ». Problème observé sur Sun Fire 4100/4200/4500 avec ILOM. Ce contournement inclut automatiquement le contournement « opensesspriv »

.

opensesspriv - Ce drapeau de contournement modifiera légèrement le protocole de connexion IPMI 2.0 de FreeIPMI pour contourner un algorithme de hachage invalide utilisé par le système distant. Le niveau de privilège envoyé lors de l'étape Open Session d'une connexion IPMI 2.0 est utilisé pour hacher les clés au lieu du niveau de privilège envoyé lors de l'étape de connexion RAKP1. Ceux qui rencontrent ce problème peuvent voir les erreurs « password invalid », « k_g invalid », « bad rmcpplus status code » ou « privilege level cannot be obtained for this user ». Problème observé sur Sun Fire 4100/4200/4500 avec ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220, et le BMC logiciel OpenIPMI. Ce contournement est automatiquement déclenché avec le contournement « sun20 »

.

integritycheckvalue - Ce drapeau de contournement contournera une valeur de vérification d'intégrité invalide lors de l'établissement d'une session IPMI 2.0 lors de l'utilisation de la Suite de chiffrement ID 0. La valeur de vérification d'intégrité devrait avoir une longueur de 0, cependant la carte mère distant répond avec un champ non vide. Ceux qui rencontrent ce problème peuvent voir les erreurs « k_g invalid ». Problème observé sur Supermicro X8DTG, Supermicro X8DTU, et Intel S5500WBV/Penguin Relion 700, et Intel S2600JF/Appro

512X.

Ceux qui rencontrent ce problème peuvent voir les erreurs « ipmi 2.0 unavailable » ou « connection timeout ». Ce problème peut être contourné en utilisant IPMI 2.0 au lieu de IPMI 1.5 en spécifiant --driver-type=LAN_2.0. Problème observé sur un certain n

PROBLÈMES

CONNUS

Sur les systèmes d'exploitation plus anciens, si vous saisissez votre nom d'utilisateur, votre mot de passe et d'autres informations potentiellement pertinentes pour la sécurité sur la ligne de commande, ces informations peuvent être découvertes par d'autres utilisateurs lors de l'utilisation d'outils comme la commande ps(1) ou en regardant dans le système de fichiers /proc. Il est généralement plus sûr de saisir les informations de mot de passe avec des options comme les options -P ou -K. Configurer les informations pertinentes pour la sécurité dans le fichier de configuration de FreeIPMI serait également un moyen approprié de masquer ces

informations.

Afin de prévenir les attaques par force brute, certains BMC se « verrouilleront » temporairement a

près un certain nombre d'erreurs d'authentification distantes. Vous devrez peut-être attendre un
moment pour que ce verrouillage temporaire passe avant de pouvoir vous authentifier à nouveau.
