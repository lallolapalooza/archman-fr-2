ipmi_sim_cmd(5) Commandes du simulateur IPMI LAN ipmi_sim_cmd(5)

DESCRIPTION

L'émulation ipmi_sim est configurée à l'aide de ces commandes. Elles peuvent être lues à partir d'un fichier de commandes, exécutées depuis la ligne de commande ou exécutées à l'intérieur du simulateur après son démarrage.

Cela peut être un peu déroutant, mais les interfaces réseau sont configurées par le fichier de configuration ipmi_lan, et les différents contrôleurs de gestion, capteurs, etc. sont spécifiés à l'aide de ce fichier. De plus, cela peut être utilisé pour configurer le simulateur une fois qu'il est lancé, définir des valeurs de capteurs, injecter des événements, et des choses de ce genre.

COMMANDES GÉNÉRALES

Les lignes vides et les lignes commençant par '#' sont ignorées. Les lignes longues peuvent être divisées en plaçant un apostrophe (') à la fin de la ligne à continuer.

quit
Quitter le simulateur.
include "fichier"
Inclure le fichier donné.
define nom "valeur"

Définir le nom donné comme une variable avec la valeur donnée. Cette variable peut être utilisée plus tard en faisant $nom. Ceci ne peut pas être utilisé entre guillemets, mais les guillemets peuvent être divisés et la variable placée entre eux. Par exemple, si vous dites :

define MCNUM "40"

vous pouvez l'utiliser plus tard comme ceci :

mc_add $MCNUM 1 no-device-sdrs 00 00 00 0xc9 0x009000 0x0002

ou

sensor_add $MCNUM 0 21 12 0x6f poll 1000 file "/sys/dev/sens1-"$MCNUM"-1"

sleep temps
Pause de l'interface de commande pendant le nombre de secondes donné. Cela n'affecte pas l'exécution du simulateur.
debug options
Définir la sortie de débogage. Les options valides sont :

msg Afficher les messages.

raw Afficher l'E/S brute.

Entrer rien désactive le débogage.

read_cmds nom_de_fichier
Exécuter les commandes dans le fichier donné.

COMMANDES MC

mc_add AdresseIPMB IDAppareil PossedeSDRsAppareil RevisionAppareil VersionFirmwareMajeure VersionFirmwareMineure SupportAppareil IDFabricant IDProduit
Ajouter un MC au simulateur. Toutes les valeurs sont en hexadécimal. Ce sont principalement des valeurs pour la commande "Get Device ID", voir la spécification pour les détails. Notez que le MC n'est pas activé après avoir été ajouté, vous devez l'ajouter.

Notez que certaines de ces valeurs contrôlent les capacités du MC. Par exemple, HasDeviceSDRs détermine si les commandes du dépôt SDR de l'appareil fonctionneront.

Vous pouvez utiliser has-device-sdrs ou no-device-sdrs dans le champ HasDeviceSDRs.

mc_add_fru_data addr_mc IDAppareil TailleFRU (données [octet1 [octet2 [...]]] | fichier décalage nom_de_fichier)
Définir les données FRU pour un MC et un ID d'appareil donnés. Les données peuvent être fournies directement ici, ou elles peuvent provenir d'un fichier. Le décalage est le point de départ dans le fichier où les données sont stockées.
mc_dump_fru_data addr_mc IDAppareil
Afficher les données FRU pour un MC et un ID d'appareil donnés.
mc_delete addr_mc
Supprimer le MC du système.
mc_disable addr_mc
Désactiver le MC, mais ne pas le supprimer.
mc_enable addr_mc
Activer le MC donné.
mc_setbmc addr_mc
Définir l'adresse du BMC.
mc_set_guid addr_mc guid
Définir la valeur GUID. Le GUID peut être une chaîne (entre guillemets) ou une chaîne hexadécimale.
sel_enable addr_mc max-entrées indicateurs
Activer le journal des événements système (SEL) sur le MC donné. Les indicateurs sont un octet retourné par la commande "Get SEL Info" ; ils contrôlent divers aspects du SEL. Voir la spécification pour les détails.
sel_add addr_mc TypeEnregistrement octet1 octet2 ... octet13
Ajouter une entrée au SEL du MC.
main_sdr_add addr_mc octet1 [octet2 [...]]
Ajouter une entrée au SDR principal du MC.
device_sdr_add addr_mc LUN octet1 [octet2 [...]]
Ajouter une entrée au SDR de l'appareil du MC.

COMMANDES CAPTEUR

sensor_add addr_mc LUN num_capteur type_capteur code_lecture_evenement [poll taux_poll type_poll options_type_poll] [event-only]

Ajouter un capteur au MC et LUN donnés. Le type de capteur est défini par le code de lecture de l'événement.

Si poll est spécifié, le capteur sera interrogé pour obtenir des données. Seul le type de poll file est actuellement supporté. La valeur est un nombre lu dans un fichier. Il a les options suivantes, toutes optionnelles :

div=val divisera la valeur lue par le nombre donné. Ceci est fait après l'opération de multiplication.

mult=val multipliera la valeur lue par le nombre donné. Ceci est fait après la soustraction.

sub=val soustraira la valeur par le nombre donné. Ceci est fait après le masque.

mask=val masquera (ET bit à bit) la valeur par le nombre donné.

base=valeur Spécifie la base de la valeur lue dans le fichier. Par défaut, c'est zéro, ce qui signifie que les conventions "C" sont utilisées.

initstate=valeur définit l'état de l'événement initialement. Ceci est utile pour les capteurs discrets avec des bits qui devraient normalement être définis à "1", comme un bit de présence, pour éviter que le programme ne génère un événement à chaque démarrage.

raw spécifie que les données du fichier sont une valeur brute. Seuls longueur octets sont lus depuis décalage.

ascii spécifie que les données du fichier sont en ASCII. C'est la valeur par défaut. La valeur décalage est utilisée, mais pas la longueur.

longueur=val spécifie la longueur des données à lire dans le fichier. La valeur maximale est 4, et ceci est uniquement utilisé pour les données brutes.

depends=<addr_mc>,<lun>,<num_capteur>,<bit> spécifie un bit de capteur discret qui doit être défini à 1 pour que le capteur soit actif. Généralement, vous utilisez le bit de présence d'un capteur pour indiquer si d'autres capteurs sur l'appareil sont réellement présents. Chacun des autres capteurs aurait une de ces dépendances pointant vers le bit de présence.

event-only spécifie que le capteur ne sera pas lisible, il générera uniquement des événements (spécifié avec un SDR de type 3).

sensor_set_bit addr_mc LUN num_capteur bit_à_définir valeur_bit générer_événement
Définit le bit donné à valeur_bit (0 ou 1) pour le capteur par numéro de bit, soit le seuil pour l'analogique, soit le bit du capteur discret. Si générer_événement est non nul et que le capteur a des événements activés pour ce bit, alors générer un événement.
sensor_set_bit_clr_rest addr_mc LUN num_capteur bit_à_définir valeur_bit générer_événement
Similaire à sensor_set_bit, mais efface automatiquement tous les autres bits.

COMMANDES GÉNÉRALES

version
Renvoie la version du programme.
help [command]
Affiche de l'aide. Si une commande est spécifiée, affiche l'aide pour cette commande spécifique.
show [mc-addr]
Affiche les informations sur tous les MC ou sur un MC spécifique.
load filename
Charge les données du MC depuis un fichier.
save filename [mc-addr]
Sauvegarde les données du MC dans un fichier. Si mc-addr n'est pas spécifié, tous les MC sont sauvegardés.
clear [mc-addr]
Efface les données du MC. Si mc-addr n'est pas spécifié, tous les MC sont effacés.
quit
Quitte le programme.

COMMANDES MC

mc_create mc-addr
Crée un nouveau MC avec l'adresse spécifiée.
mc_delete mc-addr
Supprime le MC spécifié.
mc_get_num_leds mc-addr
Obtient le nombre de LEDs du MC.
mc_get_power mc-addr
Obtient le réglage de puissance ATCA du MC.
mc_reset mc-addr
Réinitialise le MC spécifié.
mc_set_led_state mc-addr led-num state
Définit l'état de la LED spécifiée du MC. L'état peut être 'on', 'off', 'blink'.
mc_set_led_color mc-addr led-num color
Définit la couleur de la LED spécifiée du MC. La couleur peut être 'red', 'green', 'blue', 'amber', 'off'.
mc_set_num_leds mc-addr count
Définit le nombre de LEDs ATCA du MC.
mc_set_power mc-addr power gen-event
Définit le réglage de puissance ATCA du MC à sa valeur numérique. Si gen-event est non nul, génère un événement pour le changement.

COMMANDES DE CAPTEUR

sensor_set_value mc-addr LUN sensor-num value generate-event
Définit la valeur d'octet pour un capteur analogique. Si le capteur dépasse un seuil, que les événements sont activés pour le capteur et que generate-event est non nul, alors un événement est généré pour la condition.
sensor_set_hysteresis mc-addr LUN sensor-num support positive negative
Définit les capacités d'hystérésis du capteur. Il doit s'agir d'un capteur analogique. La valeur de support est la capacité d'hystérésis, identique à la valeur de support d'hystérésis dans le SDR du capteur. Les valeurs d'hystérésis positive et négative sont également définies par cette commande.

La valeur de support peut également être none, readable, settable ou fixed au lieu des nombres.

sensor_set_threshold mc-addr LUN sensor-num threshold-support threshold-enabled [value5 [value4 [... [value0]]]]

Définit le support de seuil pour un capteur. Il doit s'agir d'un capteur analogique. La valeur de threshold-support est identique à la valeur de support d'accès aux seuils dans le SDR du capteur. Les valeurs de threshold-enabled sont une chaîne de caractères '0' et '1' qui activent les 6 seuils correspondants ; la valeur la plus à droite est la valeur 0, la plus à gauche est la valeur 5. Optionnellement, les valeurs de seuil peuvent être spécifiées comme leurs valeurs d'octet.

La valeur de threshold-support peut également être none, readable, settable ou fixed pour la rendre plus lisible. Les seuils sont :

0 - inférieur non critique

1 - inférieur critique

2 - inférieur non récupérable

3 - supérieur non critique

4 - supérieur critique

5 - supérieur non récupérable

sensor_set_event_support mc-addr LUN sensor-num events-enable scanning event-support assert-support deassert-support assert-enabled deassert-enabled

Définit le support d'événements d'un capteur. events-enable activera les événements globaux sur le capteur si non nul, sinon ils seront désactivés. Les valeurs de scanning définissent la valeur de scanning pour le capteur. La valeur event-support définit les capacités d'événement dans le capteur, c'est identique à la valeur "sensor event message control support" dans le SDR du capteur. assert-support, deassert-support, assert-enabled et deassert-enabled sont tous des masques de bits (une chaîne de caractères '0' et '1') qui définissent la capacité de leurs bits de capteur correspondants à générer des événements (support) et s'ils généreront des événements maintenant (activé).

Notez que tous les masques de bits ont le chiffre le plus à droite comme bit zéro, et le chiffre le plus à gauche comme bit d'ordre le plus élevé. Notez que vous devez spécifier 15 bits ici, même si vous ne les utilisez pas tous.

Notez que vous pouvez utiliser enable ou disable dans le champ events-enable, et vous pouvez utiliser scanning ou no-scanning dans le champ scanning.

Pour event-support, vous pouvez utiliser per-state, entire-sensor, global ou none au lieu d'un nombre.

Pour un capteur de seuil, les valeurs sont :

0
- inférieur non critique allant vers le bas

1
- inférieur non critique allant vers le haut

2
- inférieur critique allant vers le bas

3
- inférieur critique allant vers le haut

4
- inférieur non récupérable allant vers le bas

5
- inférieur non récupérable allant vers le haut

6
- supérieur non critique allant vers le bas

7
- supérieur non critique allant vers le haut

8
- supérieur critique allant vers le bas

9
- supérieur critique allant vers le haut

1
- supérieur non récupérable allant vers le bas

1
- supérieur non récupérable allant vers le haut

Notez que les valeurs "inférieur allant vers le haut" et "supérieur allant vers le bas" ne sont pas supportées, car elles sont tout simplement stupides.

COMMANDES OEM ATCA

Celles-ci servent à émuler des capacités ATCA spéciales.

atca_enable
Le système est un système ATCA, active les autres capacités ATCA.

Notez que vous devez faire cela *avant* de créer des MC (cela devrait vraiment être la première chose) car les MC sont configurés un peu différemment pour le mode ATCA. Cela permet aux MC de gérer correctement les commandes PICMG, configure 2 LEDs par défaut et active une gestion appropriée du hot-swap, y compris la LED bleue. Par défaut, la LED bleue supporte le contrôle local et les autres LEDs ne le font pas et sont rouges.

En mode ATCA, pour piloter la machine d'état du hot-swap, vous devez utiliser sensor_set_bit_clr_rest pour définir l'état du hot-swap.

atca_set_site hardware-address site-type site-number
Définit les valeurs données pour un système ATCA, les valeurs renvoyées par les commandes get address.
mc_set_num_leds mc-addr count
Définit le nombre de LEDs ATCA du MC.
mc_set_power mc-addr power gen-event
Définit le réglage de puissance ATCA du MC à sa valeur numérique. Si gen-event est non nul, génère un événement pour le changement.
