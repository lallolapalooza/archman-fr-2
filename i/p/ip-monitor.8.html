IP-MONITOR(8) Linux IP-MONITOR(8)

NOM

ip monitor, rtmon - surveillance d'état

SYNTAXE


ip monitor [ all | LISTE-OBJETS ] [ file NOM FICHIER ] [ label ] [ all-nsid ] [ dev APPAREIL ]

OPTIONS

-t, -timestamp
Affiche un horodatage avant le message d'événement sur une ligne séparée au format :
Timestamp: <Jour> <Mois> <JJ> <hh:mm:ss> <AAAA> <usec> usec
<ÉVÉNEMENT>
-ts, -tshort
Affiche un horodatage court avant le message d'événement sur la même ligne au format :
[<AAAA>-<MM>-<JJ>T<hh:mm:ss>.<ms>] <ÉVÉNEMENT>

DESCRIPTION

L'utilitaire ip peut surveiller en continu l'état des périphériques, des adresses et des routes. Cette option a un format légèrement différent. Nommément, la commande monitor est la première dans la ligne de commande, suivie de la liste des objets :

ip monitor [ all | LISTE-OBJETS ] [ file NOMFICHIER ] [ label ] [ all-nsid ] [ dev APPAREIL ]

LISTE-OBJETS est la liste des types d'objets que nous voulons surveiller. Elle peut contenir link, address, route, mroute, maddress, acaddress, prefix, neigh, netconf, rule, stats, nsid et nexthop. Si aucun argument file n'est donné, ip ouvre RTNETLINK, écoute dessus et affiche les changements d'état dans le format décrit dans les sections précédentes.

Si l'option label est définie, un préfixe est affiché avant chaque message pour indiquer la famille du message. Par exemple :


[NEIGH]10.16.0.112 dev eth0 lladdr 00:04:23:df:2f:d0 REACHABLE [LINK]3: eth1: <BROADCAST,MULTICAST> mtu 1500 qdisc pfifo_fast state DOWN group default
link/ether 52:54:00:12:34:57 brd ff:ff:ff:ff:ff:ff

Si l'option all-nsid est définie, le programme écoute tous les espaces réseau qui ont un nsid assigné dans l'espace réseau où le programme s'exécute. Un préfixe est affiché pour indiquer l'espace réseau d'où provient le message. Exemple :


[nsid 0]10.16.0.112 dev eth0 lladdr 00:04:23:df:2f:d0 REACHABLE

Si l'option file est donnée, le programme n'écoute pas sur RTNETLINK, mais ouvre le fichier donné et en affiche le contenu. Le fichier doit contenir des messages RTNETLINK enregistrés au format binaire. Un tel fichier peut être généré avec l'utilitaire rtmon. Cet utilitaire a une syntaxe de ligne de commande similaire à ip monitor. Idéalement, rtmon devrait être démarré avant que la première commande de configuration réseau ne soit exécutée. Par exemple, si vous insérez :


rtmon file /var/log/rtmon.log

dans un script de démarrage, vous pourrez visualiser l'historique complet plus tard.

Néanmoins, il est possible de démarrer rtmon à tout moment. Il préfixe l'historique avec un instantané de l'état affiché au moment du démarrage.

Si l'option dev est donnée, le programme affiche uniquement les événements liés à cet appareil.
