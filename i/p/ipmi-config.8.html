DESCRIPTIO

N

ipmi-config est utilisé pour obtenir et définir des paramètres de configuration dans IPMI. Il peut être utilisé pour configurer les noms d'utilisateur, les mots de passe, les informations de réseau, la sécurité, le Serial-over-LAN (SOL), le filtrage des événements de plateforme (PEF), les périphériques de démarrage, la politique de restauration de l'alimentation, les seuils des capteurs, les événements des capteurs, et de nombreuses autres options de configuration. Une configuration est généralement requise avant que la plupart des outils IPMI puissent être utilisés pour accéder à une machine à distance. Par défaut, ipmi-config vous permettra de --checkout ou --commit uniquement les valeurs IPMI de base nécessaires à la configuration IPMI. Pour des champs de configuration avancés supplémentaires liés à la configuration du châssis (y compris les options de démarrage), au filtrage des événements de plateforme (PEF) ou aux capteurs, voir l'option --category ci-dessous. Pour plus de détails sur la configuration IPMI de base, voir ipmi-config.conf(5). La majorité des opérations de configuration nécessitent le privilège ADMIN lors de l'utilisation de ipmi-config hors bande. Bien que la connexion via un utilisateur disposant des privilèges ADMIN ne soit pas requise pour une utilisation hors bande, l'immense majorité des options de configuration ne seront pas récupérées ni

définies.

Ci-dessous sont listées les options IPMI générales, les options propres à l'outil, les informations de dépannage, les informations de contournement, des exemples et des problèmes connus. Pour une introduction générale à FreeIPMI, voir freeipmi(7). Voir UTILISATION GÉNÉRALE ci-dessous pour une description de l'utilisation de base de ipmi-confi

g
.

UTILISATION

GÉNÉRALE

La plupart des utilisateurs de voudront

:

A) Exécuter avec --checkout pour obtenir une copie de la configuration actuelle et la stocker dans un fichier. La sortie standard peut être redirigée vers un fichier ou un fichier peut être spécifié avec l'option --filename

.

B) Modifier le fichier de configuration avec un

éditeur.

C) Remettre la configuration en utilisant l'option --commit et en spécifiant le fichier de configuration avec l'option --filename. La configuration peut être remise à plusieurs hôtes en parallèle via le support

hostrange.

Bien que généralement non nécessaire, certaines cartes mères ne stockent pas les valeurs de configuration en mémoire non volatile. Par conséquent, après un redémarrage du système, certaines valeurs de configuration peuvent avoir changé. L'utilisateur peut souhaiter exécuter les outils de configuration à chaque démarrage pour s'assurer que les valeurs de configuration

persistent.

Des commentaires seront listés occasionnellement dans les fichiers extraits avec des informations sur la façon de configurer les champs. Le manpage ipmi-config.conf(5) fournit également des informations supplémentaires sur la signification des différents

champs.

Pour les utilisateurs ayant de grands clusters ou des ensembles de nœuds, vous pouvez souhaiter utiliser le même fichier de configuration pour tous les nœuds. Le seul problème est que l'adresse IP et l'adresse MAC seront différentes sur chaque nœud de votre cluster et ne peuvent donc pas être configurées via le même fichier de configuration. L'adresse IP et l'adresse MAC dans votre fichier de configuration peuvent être écrasées en ligne de commande à l'aide de l'option --key-pair. L'exemple suivant pourrait être utilisé dans un script pour configurer chaque nœud d'un cluster avec le même fichier de configuration BMC. Le script doit seulement déterminer l'adresse IP et l'adresse MAC correctes à

utiliser.

# ipmi-config --commit -k Lan_Conf:Ip

_Address=$MY_IP -k Lan_Conf:Mac_A
ddress=$MY_MAC --filename=my_bmc.conf on class="Sh">

INFORMATIONS DE CONFIGURATION DES CAS PARTICULIERS DE

CORE

Les champs UserN:Password (où N est un nombre) ne peuvent pas être extraits sur certains systèmes, par conséquent la valeur extraite sera toujours

vide.

Les champs UserN:Enable_User (où N est un nombre) ne peuvent pas être extraits sur les systèmes IPMI plus anciens, par conséquent la valeur extraite sera parfois

vide.

Les champs UserN:Lan_Session_Limit et UserN:Serial_Session_Limit (où N est un nombre) ne peuvent pas être extraits sur certains systèmes, par conséquent la valeur extraite sera toujours vide. S'ils ne sont pas spécifiés dans les versions ultérieures des configurations, le champ peut être réinitialisé à 0 en raison d'une exigence selon laquelle d'autres champs (configurés avec la limite de session) nécessiteront une valeur d'entrée pour la limite de session. Dans la plupart des conditions, il n'est pas nécessaire de définir ce champ et la plupart des utilisateurs peuvent choisir de l'ignorer. Ce champ est considéré comme facultatif selon les normes IPMI et peut entraîner des erreurs lors de la tentative de le configurer à une valeur non nulle. Si des erreurs surviennent, le fait de remettre la valeur à 0 devrait résoudre les

problèmes.

Les champs Lan_Conf:IP_Address et Lan_Conf:MAC_Address ne peuvent pas être validés en parallèle via la prise en charge de la plage d'hôtes. Chaque machine doit être configurée avec une paire d'adresse IP et d'adresse MAC unique, par conséquent nous interdisons cette configuration dans ipmi-config

.

Sur certaines cartes mères, Lan_Conf:MAC_Address peut être en lecture seule et l'adresse MAC est configurée automatiquement

.

Sur certaines cartes mères, Lan_Conf:MAC_Address peut être en lecture seule et l'adresse MAC est configurée via une commande OEM. Voir ipmi-oem(8) pour voir si la configuration OEM pour votre carte mère est prise en

charge.

Sur certaines cartes mères, un certain nombre de champs de configuration utilisateur ne peuvent pas être lus ou configurés tant qu'un nom d'utilisateur non nul ou un mot de passe non nul n'a pas été configuré. Dans certains de ces cas, une sortie appropriée dans le fichier de configuration indiquera cette situation. Cependant, tous les cas particuliers de cartes mères peuvent ne pas être détectés. Les utilisateurs peuvent souhaiter jouer avec l'ordre des champs pour contourner ces

problèmes.

Sur certaines cartes mères, l'authentification OEM dans Lan_Conf_Auth ne peut pas être activée. Cependant, les paramètres par défaut de la carte mère ont ces champs activés. Il est conseillé aux utilisateurs de désactiver toute authentification OEM dans cette

section.

Sur certaines cartes mères, plusieurs canaux peuvent exister pour la communication IPMI LAN ou série. Si plusieurs canaux existent, la configuration des deux canaux peut être visualisée et finalement configurée en exécutant --checkout en mode verbeux. Chaque section ou nom de clé sera suffixé de manière appropriée avec le mot Channel et le numéro de canal. Par exemple, vous pourriez voir un Lan_Conf_Channel_1 et Lan_Conf_Channel_3, où vous pouvez configurer la configuration LAN sur les canaux 1 et 3

respectivement.

Sur certaines cartes mères, les changements de configuration ne seront pas « absorbés » par le système tant que la carte mère n'aura pas été réinitialisée à froid. Cela peut être accompli en éteignant et rallumant physiquement le système (par ex. en appuyant sur le bouton), ou cela peut être accompli par une réinitialisation à froid. Une réinitialisation à froid peut être exécutée via bmc-devic

e
.

PRISE EN CHARGE DE LA PLAGE

D'HÔTES

Plusieurs hôtes peuvent être saisis soit sous forme de listes explicites d'hôtes séparés par des virgules, soit sous forme d'une plage de noms d'hôtes sous la forme générale : préfixe[n-m,l-k,...], où n < m et l < k, etc. La dernière forme ne doit pas être confondue avec les classes de caractères d'expressions régulières (aussi notées []). Par exemple, foo[19] ne représente pas foo1 ou foo9, mais représente plutôt une plage dégénérée :

foo19.

Cette syntaxe de plage n'est destinée qu'à la commodité sur les grilles avec une convention de nommage préfixeNN et la spécification des plages ne doit pas être considérée comme nécessaire -- la liste foo1,foo9 pourrait être spécifiée comme telle, ou par la plage foo[1,9]

.

Quelques exemples d'utilisation des plages suivent

: 
    foo[01-05] au lieu de foo01,foo02,foo03,foo04,foo05
    foo[7,9-10] au lieu de foo7,foo9,foo10
    foo[0-3] au lieu de foo0,foo1,foo2,
foo3

Pour rappel au lecteur, certains interpréteurs de commandes interpréteront les crochets ([ et ]) pour la correspondance de motifs. Selon votre interpréteur de commandes, il peut être nécessaire d'encadrer les listes de plages entre

guillemets.

Lorsque plusieurs hôtes sont spécifiés par l'utilisateur, un thread sera exécuté pour chaque hôte en parallèle jusqu'à la diffusion configurée (qui peut être ajustée via l'option -F). Cela permettra la communication avec un grand nombre de nœuds bien plus rapidement que si cela était fait en

série.

Par défaut, la sortie standard de chaque nœud spécifié sera affichée avec le nom d'hôte préfixé à chaque ligne. Bien que cette sortie soit lisible dans de nombreuses situations, elle peut être difficile à lire dans d'autres situations. Par exemple, la sortie de plusieurs nœuds peut être mélangée. Les options -B et -C peuvent être utilisées pour changer ce comportement par

défaut.

La communication IPMI en bande sera utilisée lorsque l'hôte

« localhost » est spécifié. Cela permet à l'utilisateur d
'ajouter le localhost dans la sortie de la plage d'hôtes.

DÉPANNAGE

GÉNÉRAL

Le plus souvent, les problèmes IPMI sont dus à des problèmes de

configuration.

Les problèmes IPMI sur LAN impliquent une mauvaise configuration du BMC de la machine distante. Vérifiez à nouveau pour vous assurer que les éléments suivants sont configurés correctement dans le BMC de la machine distante : adresse IP, adresse MAC, masque de sous-réseau, nom d'utilisateur, activation de l'utilisateur, privilège de l'utilisateur, mot de passe, privilège LAN, activation LAN et type(s) d'authentification autorisé(s). Pour les connexions IPMI 2.0, vérifiez à nouveau pour vous assurer que le(s) privilège(s) de la suite de chiffrement et la clé K_g sont configurés correctement. L'outil ipmi-config(8) peut être utilisé pour vérifier et/ou modifier ces paramètres de

configuration.

Les problèmes IPMI en bande sont généralement causés par des pilotes mal configurés ou des BMC non

standard.

En plus des conseils de dépannage ci-dessous, veuillez voir CONTORNEMENTS ci-dessous pour voir également s'il y a des bogues spécifiques au fournisseur qui ont été découverts et

contournés.

Voici la plupart des problèmes courants pour les messages d'erreur. Pour une assistance supplémentaire, veuillez envoyer un courriel à la liste de diffusion <freeipmi-users@gnu.org>

.

« username invalid » - Le nom d'utilisateur saisi (ou un nom d'utilisateur NULL si aucun n'a été saisi) n'est pas disponible sur la machine distante. Il est également possible que la configuration du nom d'utilisateur du BMC distant soit

incorrecte.

« password invalid » - Le mot de passe saisi (ou un mot de passe NULL si aucun n'a été saisi) n'est pas correct. Il est également possible que le mot de passe de l'utilisateur ne soit pas correctement configuré sur le BMC

distant.

« password verification timeout » - La vérification du mot de passe a expiré. Une erreur « password invalid » (décrite ci-dessus) ou un « session timeout » générique (décrit ci-dessous) s'est produit. À ce point du protocole, il ne peut pas être différencié lequel s'est

produit.

« k_g invalid » - La clé K_g saisie (ou une clé K_g NULL si aucune n'a été saisie) n'est pas correcte. Il est également possible que la clé K_g ne soit pas correctement configurée sur le BMC

distant.

« privilege level insufficient » - Une commande IPMI nécessite un privilège utilisateur supérieur à celui avec lequel l'authentification a été effectuée. Veuillez essayer de vous authentifier avec un privilège supérieur. Cela peut nécessiter de s'authentifier à un utilisateur différent qui a un privilège maximum plus

élevé.

« privilege level cannot be obtained for this user » - Le niveau de privilège avec lequel vous essayez de vous authentifier est supérieur au maximum autorisé pour cet utilisateur. Veuillez réessayer avec un privilège inférieur. Il est également possible que le niveau de privilège maximum autorisé pour un utilisateur ne soit pas correctement configuré sur le BMC

distant.

« authentication type unavailable for attempted privilege level » - Le type d'authentification avec lequel vous souhaitez vous authentifier n'est pasble pour ce niveau de privilège. Veuillez réessayer avec un type d'authentification alternatif ou un niveau de privilège alternatif. Il est également possible que les types d'authentification disponibles avec lesquels vous pouvez vous authentifier ne soient pas correctement configurés sur le BMC

distant.

"cipher suite id unavailable" - L'identifiant de suite de chiffrement avec lequel vous souhaitez vous authentifier n'est pas disponible sur le BMC distant. Veuillez réessayer avec un identifiant de suite de chiffrement alternatif. Il est également possible que les identifiants de suites de chiffrement disponibles ne soient pas correctement configurés sur le BMC

distant.

"ipmi 2.0 unavailable" - IPMI 2.0 n'a pas été découvert sur la machine distante. Veuillez essayer d'utiliser IPMI 1.5 à la

place.

"connection timeout" - La communication IPMI initiale a échoué. Plusieurs erreurs potentielles sont possibles, y compris un nom d'hôte invalide spécifié, une adresse IP IPMI qui ne peut pas être résolue, IPMI n'est pas activé sur le serveur distant, la connexion réseau est mauvaise, etc. Veuillez vérifier la configuration et la

connectivité.

"session timeout" - La session IPMI a expiré. Veuillez vous reconnecter. Si cette erreur se produit souvent, vous pourriez souhaiter augmenter le délai d'attente de retransmission. Certains BMC distants sont considérablement plus lents que

d'autres.

"device not found" - Le périphérique spécifié n'a pas pu être trouvé. Veuillez vérifier la configuration ou les entrées et

réessayer.

"driver timeout" - La communication avec le pilote ou le périphérique a expiré. Veuillez

réessayer.

"message timeout" - La communication avec le pilote ou le périphérique a expiré. Veuillez

réessayer.

"BMC busy" - Le BMC est actuellement occupé. Il peut être en train de traiter des informations ou avoir trop de sessions simultanées à gérer. Veuillez patienter et

réessayer.

"could not find inband device" - Un périphérique interne (inband) n'a pas pu être trouvé. Veuillez vérifier la configuration ou spécifier un périphérique ou pilote spécifique sur la ligne de

commande.

"driver timeout" - Le pilote interne (inband) a expiré lors de la communicatio

n avec le BMC ou le processeur de service local. Le BMC ou le processeur de se
rvice peut être occupé ou (dans le pire des cas) possiblement non fonctionnel.

SOLUTIONS DE

CONTORNEMENT

Avec autant de fournisseurs différents implémentant leurs propres solutions IPMI, différents fournisseurs peuvent implémenter incorrectement leurs protocoles IPMI. Ce qui suit décrit un certain nombre de solutions de contournement actuellement disponibles pour gérer les problèmes de conformité découverts. Lorsque c'est possible, des solutions de contournement ont été implémentées afin qu'elles soient transparentes pour l'utilisateur. Cependant, certaines nécessiteront que l'utilisateur spécifie l'utilisation d'une solution de contournement via l'option

-W.

Le matériel listé ci-dessous peut simplement indiquer le matériel sur lequel un problème a été découvert. Des versions plus récentes du matériel peuvent corriger les problèmes indiqués ci-dessous. Des machines similaires de la part de fournisseurs peuvent ou non présenter les mêmes problèmes. Différents fournisseurs peuvent licencier leur firmware auprès du même développeur de firmware IPMI, il peut donc être utile d'essayer les solutions de contournement listées ci-dessous même si votre carte mère n'est pas

listée.

Si vous pensez que votre matériel a un problème de conformité supplémentaire nécessitant l'implémentation d'une solution de contournement, veuillez contacter les mainteneurs de FreeIPMI sur <freeipmi-users@gnu.org> ou <freeipmi-devel@gnu.org>

.

assumeio - Ce drapeau de solution de contournement supposera que les interfaces interne (inband) communiquent avec les E/S du système plutôt que d'être mappées en mémoire. Cela contournera les systèmes qui rapportent des adresses de base invalides. Ceux qui rencontrent ce problème peuvent voir des erreurs "device not supported" ou "could not find inband device". Problème observé sur HP ProLiant DL145

G1.

spinpoll - Ce drapeau de solution de contournement informera certains pilotes interne (inband), notamment le pilote KCS, de tourner en boucle (spin) lors de l'interrogation plutôt que de mettre le processus en veille. Cela peut améliorer considérablement le temps d'exécution réel des outils car la granularité du planificateur d'un système d'exploitation peut être beaucoup plus grande que le temps nécessaire pour effectuer une seule transaction de message IPMI. Cependant, en tournant en boucle, votre système peut effectuer moins de travail utile en ne basculant pas l'outil pour une tâche plus

utile.

authcap - Ce drapeau de solution de contournement sautera les vérifications précoces des capacités de nom d'utilisateur, des capacités d'authentification et de la prise en charge de K_g et permettra à l'authentification IPMI de réussir. Cela contourne plusieurs problèmes dans lesquels le système distant ne rapporte pas correctement les capacités de nom d'utilisateur, les capacités d'authentification ou le statut de K_g. Ceux qui rencontrent ce problème peuvent voir des erreurs "username invalid", "authentication type unavailable for attempted privilege level" ou "k_g invalid". Problème observé sur Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML, et Sun Fire 2200/4150/4450 avec

ELOM.

nochecksumcheck - Ce drapeau de solution de contournement indiquera à FreeIPMI de ne pas vérifier les sommes de contrôle retournées par les réponses aux commandes IPMI. Cela contourne les systèmes qui retournent des sommes de contrôle invalides en raison d'erreurs d'implémentation, mais le paquet est autrement valide. Les utilisateurs sont avertis quant à l'utilisation de cette option, car elle supprime la validation de l'intégrité du paquet dans un certain nombre de circonstances. Cependant, il est peu probable que ce soit un problème dans la plupart des situations. Ceux qui rencontrent ce problème peuvent voir des erreurs "connection timeout", "session timeout" ou "password verification timeout". Sur les connexions IPMI 1.5, la solution de contournement "noauthcodecheck" peut également être nécessaire. Problème observé sur Supermicro X9SCM-iiF, Supermicro X9DRi-F, et Supermicro

X9DRFR.

idzero - Ce drapeau de solution de contournement permettra aux identifiants de session vides d'être acceptés par le client. Cela contourne les sessions IPMI qui rapportent des identifiants de session vides au client. Ceux qui rencontrent ce problème peuvent voir des erreurs "session timeout". Problème observé sur Tyan S2882 avec BMC

M3289.

unexpectedauth - Ce drapeau de solution de contournement permettra aux codes d'authentification non nuls inattendus d'être vérifiés comme s'ils étaient attendus. Cela contourne un problème lorsque les paquets contiennent des données d'authentification non nules alors qu'elles devraient être nulles en raison de l'authentification par message désactivée. Ceux qui rencontrent ce problème peuvent voir des erreurs "session timeout". Problème observé sur Dell PowerEdge 2850, SC1425. Confirmé corrigé sur un firmware plus

récent.

forcepermsg - Ce drapeau de solution de contournement forcera l'utilisation de l'authentification par message (per-message) quel que soit ce qui est annoncé par le système distant. Cela contourne un problème lorsque l'authentification par message est annoncée comme désactivée sur le système distant, mais qu'elle est en fait requise pour le protocole. Ceux qui rencontrent ce problème peuvent voir des erreurs "session timeout". Problème observé sur IBM eServer

325.

endianseq - Ce drapeau de solution de contournement inversera l'endianness des numéros de séquence de session pour permettre à la session de continuer correctement. Cela contourne les numéros de séquence de session IPMI 1.5 qui ont la mauvaise endianness. Ceux qui rencontrent ce problème peuvent voir des erreurs "session timeout". Problème observé sur certains Sun ILOM 1.0/2.0 (dépend de l'endianness du processeur de service)

.

noauthcodecheck - Ce drapeau de solution de contournement indiquera à FreeIPMI de ne pas vérifier les codes d'authentification retournés par les réponses aux commandes IPMI 1.5. Cela contourne les systèmes qui retournent des codes d'authentification invalides en raison d'erreurs de hachage ou d'implémentation. Les utilisateurs sont avertis quant à l'utilisation de cette option, car elle supprime une vérification d'authentification validant l'intégrité d'un paquet. Cependant, dans la plupart des organisations, il est peu probable que ce soit un problème de sécurité. Ceux qui rencontrent ce problème peuvent voir des erreurs "connection timeout", "session timeout" ou "password verification timeout". Problème observé sur Xyratex FB-H8-SRAY, Intel Windmill, Quanta Winterfell, et Wiwynn

Windmill.

intel20 - Ce drapeau de solution de contournement contournera plusieurs problèmes d'authentification IPMI 2.0 d'Intel. Les problèmes couverts incluent le remplissage (padding) des noms d'utilisateur et la troncature du mot de passe si l'algorithme d'authentification est HMAC-MD5-128. Ceux qui rencontrent ce problème peuvent voir des erreurs "username invalid", "password invalid" ou "k_g invalid". Problème observé sur Intel SE7520AF2 avec Intel Server Management Module (Professional Edition)

.

supermicro20 - Ce drapeau de solution de contournement contournera plusieurs problèmes d'authentification IPMI 2.0 de Supermicro sur les cartes mères avec firmware IPMI Peppercon. Les problèmes couverts incluent la gestion des codes d'authentification de longueur invalide. Ceux qui rencontrent ce problème peuvent voir des erreurs "password invalid". Problème observé sur Supermicro H8QME avec carte fille SIMSO. Confirmé corrigé sur un firmware plus

récent.

sun20 - Ce drapeau de solution de contournement contournera plusieurs problèmes d'authentification IPMI 2.0 de Sun. Les problèmes couverts incluent les clés de hachage de longueur invalide, les clés mal hachées et les enregistrements de suite de chiffrement invalides. Ceux qui rencontrent ce problème peuvent voir des erreurs "password invalid" ou "bmc error". Problème observé sur Sun Fire 4100/4200/4500 avec ILOM. Cette solution de contournement inclut automatiquement la solution de contournement

"opensesspriv".

opensesspriv - Ce drapeau de solution de contournement modifiera légèrement le protocole de connexion IPMI 2.0 de FreeIPMI pour contourner un algorithme de hachage invalide utilisé par le système distant. Le niveau de privilège envoyé pendant l'étape Open Session d'une connexion IPMI 2.0 est utilisé pour hacher les clés au lieu du niveau de privilège envoyé pendant l'étape de connexion RAKP1. Ceux qui rencontrent ce problème peuvent voir des erreurs "password invalid", "k_g invalid", "bad rmcpplus status code" ou "privilege level cannot be obtained for this user". Problème observé sur Sun Fire 4100/4200/4500 avec ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220, et le BMC logiciel OpenIPMI. Cette solution de contournement est automatiquement déclenchée avec la solution de contournement

"sun20".

integritycheckvalue - Ce drapeau de solution de contournement contournera une valeur de vérification d'intégrité invalide lors de l'établissement d'une session IPMI 2.0 lors de l'utilisation du Cipher Suite ID 0. La valeur de vérification d'intégrité devrait être de longueur 0, cependant la carte mère distant répond avec un champ non vide. Ceux qui rencontrent ce problème peuvent voir des erreurs "k_g invalid". Problème observé sur Supermicro X8DTG, Supermicro X8DTU, et Intel S5500WBV/Penguin Relion 700, et Intel S2600JF/Appro

512X.

Pas de support IPMI 1.5 - Certaines cartes mères qui supportent IPMI 2.0 ont été trouvées ne pas supporter IPMI 1.5. Ceux qui rencontrent ce problème peuvent voir des erreurs "ipmi 2.0 unavailable" ou "connection timeout". Ce problème peut être contourné en utilisant IPMI 2.0 au lieu d'IPMI 1.5 en spécifiant --driver-type=LAN_2_0. Problème observé sur un certain nombre de cartes mères HP et

Supermicro.

slowcommit - Cette solution de contournement ralentira les commits vers le BMC en dormant une seconde entre le commit des sections. Cela contourne les cartes mères qui ont des BMC qui peuvent être submergés par les commits. Ceux qui rencontrent ce problème peuvent voir des erreurs de commit ou des commits qui ne sont pas écrits dans le BMC. Problème observé sur Supermicro

H8QME.

veryslowcommit - Cette solution de contournement ralentira les commits vers le BMC en dormant une seconde entre ipmi-config(8) — ipmi-config 1.6.16

WORKAROUNDS

On some motherboards, the BMC is unable to write new commits to the key. This workaround will slow down the commit to every key.

This workaround will force ipmi-config to assume that the channel used SOL is identical to the channel used for LAN. On some motherboards, the SOL channel is reported incorrectly, leading to incorrect configuration. Most notably, this problem has come up when attempting to configure multiple channels.

This workaround is only recommended if you are experiencing problems with the FreeIPMI core utilities and their interaction with your BMC.

commitcharslowly - This workaround will slow down the commit to every key. It works around motherboards that have BMCs that can be overwhelmed by commits. Those hitting this issue may see commit errors or commits not being written to the BMC. Issue observed on Quanta S99Q/Dell FS12-TY and Dell PowerEdge T320.

solchannelassumelanchannel - This workaround will force ipmi-config to assume that the channel used SOL is identical to the channel used for LAN. On some motherboards, the SOL channel is reported incorrectly, leading to incorrect configuration. Most notably, this problem has come up when attempting to configure multiple channels. Issue observed on Intel S5500WBV/Penguin Relion 700.

EXAMPLES

# ipmi-config --checkout

Affiche toutes les informations de configuration de base sur la console. Pour afficher toutes les informations de configuration pef sur la console, utilisez # ipmi-config --checkout --category=pef.

Pour afficher toutes les informations de configuration pef et chassis sur la console, utilisez # ipmi-config --checkout --category=pef,chassis.

# ipmi-config --checkout --filename=bmc-data1.conf

Stocke toutes les informations de configuration de base dans bmc-data1.conf.

# ipmi-config --diff --filename=bmc-data2.conf

Affiche toutes les différences entre la configuration actuelle et le fichier bmc-data2.conf.

# ipmi-config --diff --key-pair="lan_conf_misc:gratuitous_arp_interval=8"

Affiche la différence entre la configuration actuelle et 'lan_conf_misc:gratuitous_arp_interval' d'une valeur de '8'.

# ipmi-config --commit --filename=bmc-data1.conf

Valide toutes les valeurs de configuration du fichier bmc-data1.conf.

# ipmi-config --commit --key-pair="lan_conf_misc:gratuitous_arp_interval=4"

Valide la clé 'lan_conf_misc:gratuitous_arp_interval' d'une valeur de '4'.

# ipmi-config --commit --filename=bmc-data-updt.conf --key-pair="lan_conf_misc:gratuitous_arp_interval=4"

Valide toutes les valeurs de configuration du fichier bmc-data-updt.conf et la clé 'lan_conf_misc:gratuitous_arp_interval' d'une valeur de '4'.

DIAGNOSTICS

En cas d'exécution réussie, le code de sortie est 0. En cas d'erreur non fatale, le code de sortie est 1. En cas d'erreur fatale, le code de sortie est 2.

Si plusieurs hôtes sont spécifiés pour la communication, le code de sortie est 0 si et seulement si toutes les cibles s'exécutent correctement. Si une erreur non fatale se produit, le code de sortie est 1. Si une erreur fatale se produit, le code de sortie est 2.

KNOWN ISSUES

Sur les anciens systèmes d'exploitation, si vous saisissez votre nom d'utilisateur, votre mot de passe et d'autres informations potentiellement sensibles en matière de sécurité sur la ligne de commande, ces informations peuvent être découvertes par d'autres utilisateurs lors de l'utilisation d'outils tels que la commande ps(1) ou en examinant le système de fichiers /proc. Il est généralement plus sûr de saisir les informations de mot de passe avec des options telles que les options -P ou -K. La configuration d'informations sensibles en matière de sécurité dans le fichier de configuration FreeIPMI serait également un moyen approprié de masquer ces informations.

Afin d'empêcher les attaques par force brute, certains BMC se bloquent temporairement après un certain nombre d'erreurs d'authentification à distance. Vous devrez peut-être attendre un certain temps pour que ce blocage temporaire disparaisse avant de pouvoir vous authentifier à nouveau.
