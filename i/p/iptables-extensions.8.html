hashlimit

hashlimit utilise des buckets de hachage pour exprimer une correspondance de limitation de débit (comme la correspondance limit) pour un groupe de connexions utilisant une seule règle iptables. Le regroupement peut être effectué par groupe d'hôtes (adresse source et/ou destination) et/ou par port. Il vous donne la possibilité d'exprimer "N paquets par quantum de temps par groupe" ou "N octets par seconde" (voir ci-dessous pour quelques exemples).

Une option hash limit (--hashlimit-upto, --hashlimit-above) et --hashlimit-name sont requises.

--hashlimit-upto quantité[/seconde|/minute|/heure|/jour]
Correspond si le débit est inférieur ou égal à quantité/quantum. Il est spécifié soit comme un nombre, avec un suffixe de quantum de temps optionnel (la valeur par défaut est 3/heure), soit comme quantitéb/seconde (nombre d'octets par seconde).
--hashlimit-above quantité[/seconde|/minute|/heure|/jour]
Correspond si le débit est supérieur à quantité/quantum.
--hashlimit-burst quantité
Nombre initial maximal de paquets à faire correspondre : ce nombre est rechargé à un toutes les fois où la limite spécifiée ci-dessus n'est pas atteinte, jusqu'à ce nombre ; la valeur par défaut est 5. Lorsque la correspondance de débit par octet est demandée, cette option spécifie la quantité d'octets pouvant dépasser le débit donné. Cette option doit être utilisée avec prudence - si l'entrée expire, la valeur de burst est également réinitialisée.
--hashlimit-mode {srcip|srcport|dstip|dstport},...

--hashlimit-dstmask masque
Comme --hashlimit-srcmask, mais pour les adresses de destination.
--hashlimit-name nom
Le nom de l'entrée /proc/net/ipt_hashlimit/nom.
--hashlimit-htable-size buckets
Le nombre de buckets de la table de hachage
--hashlimit-htable-max entrées
Nombre maximal d'entrées dans le hachage.
--hashlimit-htable-expire msec
Après combien de millisecondes les entrées de hachage expirent.
--hashlimit-htable-gcinterval msec
Combien de millisecondes entre les intervalles de nettoyage.
--hashlimit-rate-match
Classifier le flux au lieu de limiter son débit. Cela agit comme une correspondance vrai/faux sur la question de savoir si le débit est supérieur/inférieur à un certain nombre.

Peut être utilisé avec --hashlimit-rate-match pour spécifier l'intervalle auquel le débit doit être échantillonné.

--label chaîne

Cette cible n'est valide que dans la table nat, dans la chaîne POSTROUTING. Cette cible transmet le paquet à l'espace utilisateur en utilisant le gestionnaire nfnetlink_queue. Le paquet est placé dans la file d'attente identifiée par son numéro de file d'attente de 16 bits. Ceci spécifie le numéro de QUEUE à utiliser. Les numéros de file d'attente valides sont de 0 à 65535. La valeur par défaut est 0.

Ceci spécifie une plage de files d'attente à utiliser. Les paquets sont ensuite équilibrés entre les files d'attente données. REJECT (Spécifique à IPv6)

Ceci est utilisé pour renvoyer un paquet d'erreur en réponse au paquet correspondant : sinon, il est équivalent à DROP, donc c'est une cible terminante, mettant fin au parcours des règles. Cette cible n'est valide que dans les chaînes INPUT, FORWARD et OUTPUT, et les chaînes définies par l'utilisateur qui ne sont appelées que depuis ces chaînes. --reject-with type
Le type donné peut être icmp6-no-route, no-route, icmp6-adm-prohibited, adm-prohibited, icmp6-addr-unreachable, addr-unreach, ou icmp6-port-unreachable, qui renvoient le message d'erreur ICMPv6 approprié (icmp6-port-unreachable est par défaut). Enfin, l'option tcp-reset peut être utilisée sur les règles qui correspondent uniquement au protocole TCP : cela provoque l'envoi d'un paquet TCP RST en retour. Ceci est principalement utile pour bloquer les sondes ident (113/tcp) qui se produisent fréquemment lors de l'envoi de courrier à des serveurs de messagerie défectueux (qui n'accepteront pas votre courrier sinon). tcp-reset ne peut être utilisé qu'avec les versions du noyau 2.6.14 ou ultérieures.

Attention : Vous ne devriez pas appliquer la cible REJECT indiscriminément aux paquets dont l'état de connexion est classé comme INVALID ; au lieu de cela, vous ne devriez que DROP ceux-ci.

Considérez un hôte source transmettant un paquet P, P subissant tellement de délai le long de son chemin que l'hôte source émet une retransmission, P_2, P_2 réussissant à atteindre sa destination et à faire progresser l'état de connexion normalement. Il est concevable que le P arrivant en retard puisse être considéré comme n'étant associé à aucune entrée de suivi de connexion. Générer une réponse de rejet pour un paquet ainsi classé terminerait alors la connexion saine.

Donc, au lieu de :

-A INPUT ... -j REJECT

considérez d'utiliser :

-A INPUT ... -m conntrack --ctstate INVALID -j DROP
-A INPUT ... -j REJECT

SNAT

Cette cible n'est valide que dans la table nat, dans les chaînes POSTROUTING et INPUT, et dans les chaînes définies par l'utilisateur qui ne sont appelées que depuis ces chaînes. Elle spécifie que l'adresse source du paquet doit être modifiée (et tous les paquets futurs de cette connexion seront également modifiés), et que les règles doivent cesser d'être examinées. Elle prend les options suivantes :

C'est le prédécesseur déprécié, IPv4 uniquement, de la cible NFLOG. Il fournit une journalisation dans l'espace utilisateur des paquets correspondants.
