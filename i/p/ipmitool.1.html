NOM

ipmitool - utilitaire pour le contrôle des appareils compatibles IPMI

SYNOPSIS

ipmitool [ <options> ] <commande> [ <sous-commandes et sous-options> ]

<options> := [ <options-générales> | <options-conditionnelles> ]

Toute option reconnue est acceptée. Les options conditionnelles peuvent être ignorées ou leur utilisation reportée jusqu'à ce que le shell ou exec traite la commande concernée.

<options-générales> := [ -h | -V | -v | -I <interface> | -H <adresse> |
-d <N> | -p <port> | -c | -U <nom_utilisateur> |
-L <niveau_privilège> | -l <lun> | -m <adresse_locale> |
-N <sec> | -R <nombre> | <option_mot_de_passe> |
<option_oem> | <options_pontage> ]

<options-conditionnelles> := [ <options_lan> | <options_lanplus> |
<options_commande> ]
Pontage :
<options_pontage> := -t <adresse_cible> [ -b <canal> |
[ -T <adresse> | -B <canal> ] ]

Options utilisées avec -I lan :
<options_lan> := [ -A <type_authentification> ]

Options utilisées avec -I lanplus :
<options_lanplus> := [ -C <suite_chiffrement> | <option_clé> ]

Groupes d'options définissant la même valeur :
<option_clé> := [ -k <clé> | -K | -y <clé_hex> | -Y ]
<option_mot_de_passe> := [ -f <fichier_mot_de_passe> | -a | -P <mot_de_passe> | -E ]
<option_oem> := [ -o <type_oem> | -g | -s ]

Options utilisées avec une commande spécifique <options_commande> :
<options-sdr> := [ -S <fichier_cache_sdr> ]
<options-sel> := [ -O <sel_oem> ]
<options-sol> := [ -e <caractère_escape_sol> ]

DESCRIPTION

Ce programme vous permet de gérer les fonctions de l'Intelligent Platform Management Interface (IPMI) soit du système local, via un pilote de périphérique du noyau, soit d'un système distant, en utilisant IPMI v1.5 et IPMI v2.0. Ces fonctions incluent l'affichage des informations FRU, la configuration LAN, les relevés de capteurs et le contrôle d'alimentation à distance du châssis.

La gestion IPMI d'une interface de système local nécessite qu'un pilote IPMI compatible soit installé et configuré dans le noyau. Sur Linux, ce pilote est appelé OpenIPMI et il est inclus dans les distributions standard. Sur Solaris, ce pilote est appelé BMC et est inclus dans Solaris 10. La gestion d'une station distante nécessite que l'interface IPMI-over-LAN soit activée et configurée. Selon les exigences particulières de chaque système, il peut être possible d'activer l'interface LAN en utilisant ipmitool via l'interface système.

SECURITY

There are several security issues be be considered before enabling the IPMI LAN interface. A remote station has the ability to control a system's power state as well as being able to gather certain platform information. To reduce vulnerability it is strongly advised that the IPMI LAN interface only be enabled in 'trusted' environments where system security is not an issue or where there is a dedicated secure 'management network'.

Further it is strongly advised that you should not enable IPMI for remote access without setting a password, and that that password should not be the same as any other password on that system.

When an IPMI password is changed on a remote machine with the IPMIv1.5 lan interface the new password is sent across the network as clear text. This could be observed and then used to attack the remote system. It is thus recommended that IPMI password management only be done over IPMIv2.0 lanplus interface or the system interface on the local station.

For IPMI v1.5, the maximum password length is 16 characters; longer passwords might be truncated or rejected by the server, or rejected by ipmitool.

For IPMI v2.0, the maximum password length is 20 characters; longer passwords will be rejected by ipmitool.

INTERFACE LAN

La commande ipmitool lan interface communique avec le BMC via une connexion Ethernet LAN en utilisant UDP sous IPv4. Les datagrammes UDP sont formatés pour contenir des messages de requête/réponse IPMI avec des en-têtes de session IPMI et des en-têtes RMCP.

IPMI-over-LAN utilise la version 1 du Remote Management Control Protocol (RMCP) pour prendre en charge la gestion pré-OS et sans OS. RMCP est un protocole requête-réponse livré à l'aide de datagrammes UDP sur le port 623.

L'interface LAN est une connexion multi-session authentifiée ; les messages livrés au BMC peuvent (et doivent) être authentifiés avec un protocole challenge/response utilisant soit un mot de passe/clé en clair, soit l'algorithme de digest de message MD5. ipmitool tentera de se connecter avec le niveau de privilège administrateur car cela est requis pour effectuer les fonctions d'alimentation du châssis.

Vous pouvez indiquer à ipmitool d'utiliser l'interface lan avec l'option -I lan :

> ipmitool -I lan -H <hostname> [-U <username>] [-P <password>] <command>

Un nom d'hôte doit être donné sur la ligne de commande afin d'utiliser l'interface lan avec ipmitool. Le champ du mot de passe est facultatif ; si vous ne fournissez pas de mot de passe sur la ligne de commande, ipmitool tentera de se connecter sans authentification. Si vous spécifiez un mot de passe, il utilisera l'authentification MD5 si elle est prise en charge par le BMC, et un mot de passe/clé en clair sinon, sauf indication contraire par une option de ligne de commande.

INTERFACE LANPLUS

Comme l'interface lan , l'interface lanplus communique avec le BMC via une connexion Ethernet LAN en utilisant UDP sous IPv4. La différence est que l'interface lanplus utilise le protocole RMCP+ tel que décrit dans la spécification IPMI v2.0. RMCP+ permet une authentification et des vérifications d'intégrité des données améliorées, ainsi que le chiffrement et la capacité de transporter plusieurs types de charges utiles. La prise en charge générique de Serial Over LAN nécessite RMCP+, donc la commande ipmitool sol activate nécessite l'utilisation de l'interface lanplus .

L'établissement de session RMCP+ utilise un protocole challenge-response symétrique appelé RAKP (Remote Authenticated Key-Exchange Protocol) qui permet la négociation de nombreuses options. ipmitool ne permet pas encore à l'utilisateur de spécifier la valeur de chaque option, utilisant par défaut les paramètres les plus évidents marqués comme requis dans la spécification v2.0. Les HMACS d'authentification et d'intégrité sont produits avec SHA1, et le chiffrement est effectué avec AES-CBC-128. Les connexions par niveau de rôle ne sont pas encore prises en charge.

ipmitool doit être lié avec la bibliothèque OpenSSL afin d'effectuer les fonctions de chiffrement et de prendre en charge l'interface lanplus . Si les paquets requis ne sont pas trouvés, elle ne sera pas compilée et ne sera pas prise en charge.

Vous pouvez indiquer à ipmitool d'utiliser l'interface lanplus avec l'option -I lanplus :

> ipmitool -I lanplus -H <hostname> [-U <username>] [-P <password>] <command>

Un nom d'hôte doit être donné sur la ligne de commande afin d'utiliser l'interface lan avec ipmitool. À l'exception des options -A et -C , le reste des options de la ligne de commande est identique à celles disponibles pour l'interface lan .

L'option -C vous permet de spécifier les algorithmes d'authentification, d'intégrité et de chiffrement à utiliser pour la session lanplus basée sur l'ID de suite de chiffrement trouvé dans la spécification IPMIv2.0 dans le tableau 22-20. La suite de chiffrement par défaut est 17 qui spécifie les algorithmes d'authentification RAKP-HMAC-SHA256, d'intégrité HMAC-SHA256-128 et de chiffrement AES-CBC-128.

INTERFACE FREE

L'interface ipmitool free utilise les pilotes libfreeipmi de FreeIPMI.

Vous pouvez indiquer à ipmitool d'utiliser l'interface FreeIPMI avec l'option -I :

> ipmitool -I free <command>

INTERFACE IMB

L'interface ipmitool imb prend en charge l'interface Intel IMB (Intel Inter-module Bus) via le périphérique /dev/imb.

Vous pouvez indiquer à ipmitool d'utiliser l'interface IMB avec l'option -I :

> ipmitool -I imb <command>
