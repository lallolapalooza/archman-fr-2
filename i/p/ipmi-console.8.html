DESCRIPTIO

N

ipmiconsole est un utilitaire de console Serial-over-LAN (SOL). Il peut être utilisé pour établir des sessions de console vers des machines distantes à l'aide du protocole IPMI 2.0 SOL. Ipmiconsole communique avec le Baseboard Management Controller (BMC) d'une machine distante pour établir une session de console. Avant que toute communication SOL puisse avoir lieu, le BMC de la machine distante doit être correctement configuré. L'outil FreeIPMI ipmi-config(8) peut être utilisé pour effectuer cette

configuration.

Souvent (bien que pas toujours), la redirection de console doit également être correctement configurée dans le BIOS et/ou le système d'exploitation. Les deux doivent être configurés pour rediriger le trafic de console vers le port COM approprié. Veuillez consulter la documentation de votre carte mère et de votre système d'exploitation pour obtenir des instructions sur la configuration

correcte.

Ci-dessous sont listées les options IPMI générales, les options spécifiques à l'outil, les informations de dépannage, les informations de contournement, des exemples et des problèmes connus. Pour une introduction générale à FreeIPMI, veuillez consulter free

ipmi
(7).

OPTIONS

IPMICONSOLE

Les options suivantes sont spécifiques à ipmiconsole

.
-e CHAR, --escape-char=CH
AR
Spécifie un caractère d'échappement alternatif (caractère par défaut
'&').
--dont-ste
al
Ne pas dérober une session SOL si une session est déjà détectée comme étant en cours d'utilisation. Dans la plupart des circonstances, si SOL est détecté comme étant en cours d'utilisation, ipmiconsole tentera de dérober la session SOL à la session précédente. Ce comportement par défaut existe pour plusieurs raisons, notamment le fait que les sessions SOL antérieures n'ont peut-être pas pu être correctement
désactivées.
--deactiva
te
Désactive la session SOL si une session est détectée comme étant en cours d'utilisation et
quitte.
--serial-keepal
ive
Envoie occasionnellement des caractères NUL pour détecter les connexions série inactives. Cette option est particulièrement utile pour ceux qui prévoient d'exécuter ipmiconsole sans beaucoup d'interaction, par exemple à des fins de journalisation. Bien que les connexions IPMI puissent encore être actives, certaines cartes mères ont présenté des bugs dans lesquels les données série sous-jacentes ne peuvent plus être envoyées/reçues. Du point de vue de ipmiconsole, les données ne sont tout simplement pas envoyées hors du système distant et ce problème n'est détecté qu'une fois qu'il y a une interaction de l'utilisateur. En envoyant occasionnellementsional NUL character, la perte de données de transfert série peut être détectée beaucoup plus rapidement. Il existe un certain risque avec cette option, car l'octet du caractère NUL peut affecter le système distant selon les données qu'il attend ou non. Par exemple, un caractère NUL reçu par getty(8) et ses descendants (tels que agetty(8)) provoquera un changement de débit en bauds, ce qui peut bloquer le
terminal.
--serial-keepalive-em
pty
Cette option est identique à --serial-keepalive sauf que les paquets SOL ne contiendront aucune donnée de caractère NUL. Sur certaines cartes mères, cela peut suffire à gérer une session IPMI bloquée sans le risque qu'envoyer régulièrement un octet de caractère NUL pourrait avoir. Cependant, certains systèmes peuvent ne pas acquitter un paquet SOL sans données de caractère, ce qui signifie que ces paquets de maintien de session ne servent à
rien.
--sol-payload-instance=NU
M
Spécifie le numéro d'instance de la charge utile SOL. La valeur par défaut est 1, les valeurs valides vont de 1 à 15. La plupart des systèmes ne prennent en charge qu'une seule instance, cependant quelques-uns permettent aux utilisateurs d'en accéder
plusieurs.
--deactivate-all-instan
ces

configurée.

DÉPANNAGE

GÉNÉRAL

Le plus souvent, les problèmes IPMI sont dus à des problèmes de

configuration.

Les problèmes IPMI sur LAN impliquent une mauvaise configuration du BMC de la machine distante. Vérifiez à deux reprises que les éléments suivants sont correctement configurés dans le BMC de la machine distante : adresse IP, adresse MAC, masque de sous-réseau, nom d'utilisateur, activation de l'utilisateur, privilège de l'utilisateur, mot de passe, privilège LAN, activation LAN et type(s) d'authentification autorisé(s). Pour les connexions IPMI 2.0, vérifiez à deux reprises que le(s) privilège(s) de la suite de chiffrement et la clé K_g sont correctement configurés. L'outil ipmi-config(8) peut être utilisé pour vérifier et/ou modifier ces paramètres de

configuration.

En plus des conseils de dépannage ci-dessous, veuillez consulter la section CORRECTIFS ci-dessous pour voir s'il existe des bogues spécifiques au fournisseur qui ont été découverts et

contournés.

Ci-dessous sont listés nombreux problèmes courants pour les messages d'erreur. Pour un support supplémentaire, veuillez envoyer un courriel à la liste de diffusion <freeipmi-users@gnu.org>

.

« username invalid » - Le nom d'utilisateur saisi (ou un nom d'utilisateur NULL si aucun n'a été saisi) n'est pas disponible sur la machine distante. Il est également possible que la configuration du nom d'utilisateur du BMC distant soit

incorrecte.

« password invalid » - Le mot de passe saisi (ou un mot de passe NULL si aucun n'a été saisi) n'est pas correct. Il est également possible que le mot de passe de l'utilisateur ne soit pas correctement configuré sur le BMC

distant.

« password verification timeout » - La vérification du mot de passe a expiré. Une erreur « password invalid » (décrite ci-dessus) ou un « session timeout » générique (décrit ci-dessous) s'est produit. À ce point du protocole, il est impossible de différencier lequel s'est

produit.

« k_g invalid » - La clé K_g saisie (ou une clé K_g NULL si aucune n'a été saisie) n'est pas correcte. Il est également possible que la clé K_g ne soit pas correctement configurée sur le BMC

distant.

« privilege level insufficient » - Une commande IPMI nécessite un privilège utilisateur plus élevé que celui avec lequel l'authentification a été effectuée. Veuillez essayer de vous authentifier avec un privilège plus élevé. Cela peut nécessiter de s'authentifier à un utilisateur différent qui a un privilège maximum plus

élevé.

« privilege level cannot be obtained for this user » - Le niveau de privilège avec lequel vous essayez de vous authentifier est supérieur au maximum autorisé pour cet utilisateur. Veuillez réessayer avec un privilège inférieur. Il est également possible que le niveau de privilège maximum autorisé pour un utilisateur ne soit pas correctement configuré sur le BMC

distant.

« authentication type unavailable for attempted privilege level » - Le type d'authentification avec lequel vous souhaitez vous authentifier n'est pas disponible pour ce niveau de privilège. Veuillez réessayer avec un type d'authentification alternatif ou un niveau de privilège alternatif. Il est également possible que les types d'authentification disponibles avec lesquels vous pouvez vous authentifier ne soient pas correctement configurés sur le BMC

distant.

« cipher suite id unavailable » - L'identifiant de suite de chiffrement avec lequel vous souhaitez vous authentifier n'est pas disponible sur le BMC distant. Veuillez réessayer avec un identifiant de suite de chiffrement alternatif. Il est également possible que les identifiants de suite de chiffrement disponibles ne soient pas correctement configurés sur le BMC

distant.

« ipmi 2.0 unavailable » - IPMI 2.0 n'a pas été découvert sur la machine distante. Veuillez essayer d'utiliser IPMI 1.5 à la

place.

« connection timeout » - La communication IPMI initiale a échoué. Un certain nombre d'erreurs potentielles sont possibles, y compris un nom d'hôte invalide spécifié, une adresse IP IPMI qui ne peut pas être résolue, IPMI qui n'est pas activé sur le serveur distant, une mauvaise connexion réseau, etc. Veuillez vérifier la configuration et la

connectivité.

« session timeout » - La session IPMI a expiré. Veuillez vous reconnecter. Si cette erreur se produit souvent, vous souhaiterez peut-être augmenter le délai d'attente de retransmission. Certains BMC distants sont considérablement plus lents que

d'autres.

« internal IPMI error » - Une erreur IPMI s'est produite que

FreeIPMI ne sait pas comment gérer. Veuillez envoyer un cour
riel à <freeipmi-users@gnu.org> pour signaler le problème.

DÉPANNAGE

IPMICONSOLE

Voici les problèmes courants pour les messages d'erreur dans ipmiconsole

.

« SOL unavailable » - SOL n'est pas configuré pour une utilisation sur le BMC distant. Il peut ne pas être configuré en général ou pour l'utilisateur spécifique spécifié. S'authentifier avec un autre utilisateur peut suffire, cependant le protocole IPMI ne révèle pas les détails sur ce qui n'est pas configuré sur le BMC

distant.

« SOL in use » - SOL est déjà en cours d'utilisation sur le BMC distant. Si vous ne spécifiez pas l'option --dont-steal, ipmiconsole essaiera de voler la session SOL à l'autre session. Tous les BMC ne prennent pas en charge la capacité de voler une session

SOL.

« SOL session stolen » - Votre session SOL a été volée par une autre session. Vous souhaiterez peut-être essayer de voler la session en revenant en vous

reconnectant.

« SOL requires encryption » - SOL nécessite un identifiant de suite de chiffrement qui inclut le chiffrement. Veuillez essayer d'utiliser l'identifiant de suite de chiffrement 3, 8 ou 12. Il est également possible que les exigences de chiffrement ne soient pas correctement configurées sur le BMC

distant.

« SOL requires no encryption » - SOL nécessite un identifiant de suite de chiffrement qui n'utilise pas de chiffrement. Veuillez essayer d'utiliser l'identifiant de suite de chiffrement 0, 1, 2, 6, 7 ou 11. Il est également possible que les exigences de chiffrement ne soient pas correctement configurées sur le BMC

distant.

« BMC Implementation » - Le BMC sur la machine distante a un problème grave dans son implémentation. Veuillez consulter la section CORRECTIFS ci-dessous pour des correctifs possibles. Si des correctifs supplémentaires du fournisseur sont nécessaires, veuillez contacter les

auteurs.

« excess retransmissions sent » - Un nombre excessif de retransmissions de paquets SOL s'est produit et ipmiconsole a abandonné. Cela peut être dû à des problèmes réseau ou des problèmes SOL. Certains des mêmes problèmes impliqués avec les erreurs « connection timeout » ou « session timeout » peuvent être en jeu. Veuillez essayer de vous

reconnecter.

« excess errors received » - Un nombre excessif d'erreurs de paquets SOL s'est produit et ipmiconsole a abandonné. Cela peut être dû à des problèmes réseau ou des problèmes SOL. Veuillez essayer de vous

reconnecter.

« BMC Error » - Cette erreur signifie généralement qu'une implémentation SOL du fournisseur nécessite une combinaison d'authentification, de chiffre

ment, de privilège, etc. qui n'ont pas été satisfaits par les choix de l'utilisateur. Veuillez essayer une combinaison de suites de chiffrement, de
privilèges, etc. différents pour résoudre le problème. Veuillez également consulter la section CORRECTIFS ci-dessous pour des correctifs possibles.

CORRECTIF

S

Avec autant de fournisseurs différents implémentant leurs propres solutions IPMI, différents fournisseurs peuvent implémenter leurs protocoles IPMI de manière incorrecte. Ce qui suit décrit un certain nombre de correctifs actuellement disponibles pour gérer les problèmes de conformité découverts. Lorsque c'est possible, des correctifs ont été implémentés afin qu'ils soient transparents pour l'utilisateur. Cependant, certains nécessiteront que l'utilisateur spécifie qu'un correctif doit être utilisé via l'option

-W.

Le matériel listé ci-dessous peut seulement indiquer le matériel sur lequel un problème a été découvert. Des versions plus récentes du matériel peuvent corriger les problèmes indiqués ci-dessous. Des machines similaires de fournisseurs peuvent ou non présenter les mêmes problèmes. Différents fournisseurs peuvent licencier leur firmware auprès du même développeur de firmware IPMI, il peut donc être utile d'essayer les correctifs listés ci-dessous même si votre carte mère n'est pas

listée.

Si vous pensez que votre matériel a un problème de conformité supplémentaire nécessitant qu'un correctif soit implémenté, veuillez contacter les mainteneurs de FreeIPMI sur <freeipmi-users@gnu.org> ou <freeipmi-devel@gnu.org>

.

authcap - Cet indicateur de correctif sautera les vérifications précoces des capacités de nom d'utilisateur, des capacités d'authentification et de la prise en charge de K_g et permettra à l'authentification IPMI de réussir. Il contourne plusieurs problèmes dans lesquels le système distant ne signale pas correctement les capacités de nom d'utilisateur, les capacités d'authentification ou l'état de K_g. Ceux qui rencontrent ce problème peuvent voir les erreurs « username invalid », « authentication type unavailable for attempted privilege level » ou « k_g invalid ». Problème observé sur Asus P5M2/P5MT-R/RS162-E4/RX4, Intel SR1520ML/X38ML et Sun Fire 2200/4150/4450 avec

ELOM.

nochecksumcheck - Cet indicateur de correctif indiquera à FreeIPMI de ne pas vérifier les sommes de contrôle renvoyées par les réponses aux commandes IPMI. Il contourne les systèmes quieturn des sommes de contrôle invalides en raison d'erreurs d'implémentation, mais le paquet est autrement valide. Les utilisateurs sont avertis quant à l'utilisation de cette option, car elle supprime la validation de l'intégrité des paquets dans un certain nombre de circonstances. Cependant, il est peu probable que cela pose problème dans la plupart des situations. Ceux qui rencontrent ce problème peuvent voir des erreurs « connection timeout », « session timeout » ou « password verification timeout ». Sur les connexions IPMI 1.5, le contournement « noauthcodecheck » peut également être nécessaire. Problème observé sur Supermicro X9SCM-iiF, Supermicro X9DRi-F et Supermicro

X9DRFR.

intel20 - Ce drapeau de contournement permet de résoudre plusieurs problèmes d'authentification IPMI 2.0 d'Intel. Les problèmes couverts incluent le remplissage des noms d'utilisateur et la troncature du mot de passe si l'algorithme d'authentification est HMAC-MD5-128. Ceux qui rencontrent ce problème peuvent voir des erreurs « username invalid », « password invalid » ou « k_g invalid ». Problème observé sur Intel SE7520AF2 avec Intel Server Management Module (Professional Edition)

.

supermicro20 - Ce drapeau de contournement permet de résoudre plusieurs problèmes d'authentification IPMI 2.0 de Supermicro sur les cartes mères avec firmware IPMI Peppercon. Les problèmes couverts incluent le traitement des codes d'authentification de longueur invalide. Ceux qui rencontrent ce problème peuvent voir des erreurs « password invalid ». Problème observé sur Supermicro H8QME avec carte fille SIMSO. Corrigé dans les firmwares plus

récents.

sun20 - Ce drapeau de contournement permet de résoudre plusieurs problèmes d'authentification IPMI 2.0 de Sun. Les problèmes couverts incluent les clés de hachage de longueur invalide, les clés mal hachées et les enregistrements de suite de chiffrement invalides. Ceux qui rencontrent ce problème peuvent voir des erreurs « password invalid » ou « bmc error ». Problème observé sur Sun Fire 4100/4200/4500 avec ILOM. Ce contournement inclut automatiquement le contournement « opensesspriv »

.

opensesspriv - Ce drapeau de contournement modifiera légèrement le protocole de connexion IPMI 2.0 de FreeIPMI pour contourner un algorithme de hachage invalide utilisé par le système distant. Le niveau de privilège envoyé lors de l'étape Open Session d'une connexion IPMI 2.0 est utilisé pour hacher les clés au lieu du niveau de privilège envoyé lors de l'étape de connexion RAKP1. Ceux qui rencontrent ce problème peuvent voir des erreurs « password invalid », « k_g invalid », « bad rmcpplus status code » ou « privilege level cannot be obtained for this user ». Problème observé sur Sun Fire 4100/4200/4500 avec ILOM, Inventec 5441/Dell Xanadu II, Supermicro X8DTH, Supermicro X8DTG, Intel S5500WBV/Penguin Relion 700, Intel S2600JF/Appro 512X, Quanta QSSC-S4R/Appro GB812X-CN, Dell C5220 et le BMC logiciel OpenIPMI. Ce contournement est automatiquement déclenché avec le contournement « sun20 »

.

integritycheckvalue - Ce drapeau de contournement permet de résoudre une valeur de vérification d'intégrité invalide lors de l'établissement d'une session IPMI 2.0 avec la suite de chiffrement ID 0. La valeur de vérification d'intégrité devrait être de longueur 0, mais la carte mère distante répond avec un champ non vide. Ceux qui rencontrent ce problème peuvent voir des erreurs « k_g invalid ». Problème observé sur Supermicro X8DTG, Supermicro X8DTU, Intel S5500WBV/Penguin Relion 700 et Intel S2600JF/Appro

512X.

solpayloadsize - Ce drapeau de contournement ne vérifiera pas la validité des tailles de charge utile SOL et supposera un ensemble approprié. Il permet de contourner les systèmes distants qui signalent des tailles de charge utile SOL IPMI 2.0 invalides. Ceux qui rencontrent ce problème peuvent voir des erreurs « BMC Implementation ». Problème observé sur Asus P5M2/RS162-E4/RX4, Intel SR1520ML/X38ML, Inventec 5441/Dell Xanadu II, Sun x4100, Supermicro X8DTH, Supermicro X8DTG, Supermicro X8DTU et Quanta QSSC-S4R/Appro

GB812X-CN.

solport - Ce drapeau de contournement ignorera les ports SOL alternatifs spécifiés pendant le protocole. Il permet de contourner les systèmes distants qui signalent des ports SOL alternatifs invalides. Ceux qui rencontrent ce problème peuvent voir des erreurs « connection timeout ». Problème observé sur Asus P5MT-R et Supermicro

X8DTH-iF.

solstatus - Ce drapeau de contournement ne vérifiera pas le statut d'activation actuel de SOL pendant la configuration du protocole. Il permet de contourner les systèmes distants qui ne prennent pas correctement en charge cette commande. Ceux qui rencontrent ce problème peuvent voir des erreurs « BMC Error ». Problème observé sur Supermicro

X8SIL-F.

solchannelsupport - Ce drapeau de contournement ne vérifiera pas si SOL est pris en charge sur le canal actuel. Il permet de contourner les systèmes distants qui ne prennent pas correctement en charge cette commande. Ceux qui rencontrent ce problème peuvent voir des erreurs « BMC Error ». Problème observé sur Intel Windmill, Quanta Winterfell et Wiwynn

Windmill.

serialalertsdeferred - Cette option de contournement définira les alertes série comme différées plutôt que comme des échecs. Cela permet de contourner les cartes mères qui effectuent IPMI via série ainsi qu'IPMI série sur LAN. Ceux qui rencontrent ce problème peuvent voir « excess retransmissions sent » lorsqu'ils tentent de saisir des données via SOL. Problème observé sur Intel Windmill, Quanta Winterfell et Wiwynn

Windmill.

solpacketseq - Cette option de contournement incrémentera le numéro de séquence du paquet de charge utile SOL dans des circonstances désespérées. Normalement, SOL ne devrait jamais faire cela, mais certaines cartes mères se sont avérées « bloquer » en raison d'un bug inte

rne sur la carte mère. Ce contournement peut aider à débloquer le BMC. Ceux qui rencontrent ce problème peuvent voir « excess retransmiss
ions sent » lorsqu'ils tentent de saisir des données via SOL. Problème observé sur Intel Windmill, Quanta Winterfell et Wiwynn Windmill.

PROBLÈMES

CONNUS

Sur les systèmes d'exploitation plus anciens, si vous saisissez votre nom d'utilisateur, votre mot de passe et d'autres informations potentiellement pertinentes pour la sécurité sur la ligne de commande, ces informations peuvent être découvertes par d'autres utilisateurs lors de l'utilisation d'outils comme la commande ps(1) ou en consultant le système de fichiers /proc. Il est généralement plus sûr de saisir les informations de mot de passe avec des options comme les options -P ou -K. Configurer les informations pertinentes pour la sécurité dans le fichier de configuration de FreeIPMI serait également un moyen approprié de masquer ces

informations.

Afin de prévenir les attaques par force brute, certains BMC se « verrouillent » temporairement après un certain nombre d'erreurs d'authentification à distance. Vous devrez peut-être attendre un moment pour que ce verrouillage temporaire passe avant de pouvoir vous authentifier à

nouveau.

Certaines cartes mères définissent un délai d'inactivité SOL OEM pour les sessions SOL. Si les sessions SOL restent inactives pendant de longues périodes, les sessions ipmiconsole peuvent être fermées brutalement, entraînant très probablement des erreurs de délai d'attente de session. Veuil

lez consulter les notes OEM pour savoir comment modifier ce paramètr
e si vous souhaitez que les sessions restent actives plus longtemps.

NOTES MATÉRIEL

SPÉCIFIQUES

Intel SR1520ML/X38ML : Après un redémarrage, la session SOL semble se « déconnecter » de la carte mère mais rester active. Les données de caractère saisies depuis le client ipmiconsole sont acceptées par la machine distante, mais aucune donnée de caractère ou de console n'est jamais renvoyée par la machine distante.

La session SOL est par conséquent inutile. Il n'y a actuellement aucun contou
rnement en place pour gérer cela. La session doit être fermée et redémarrée.
