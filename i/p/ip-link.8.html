Support du type VLAN
Pour une liaison de type VLAN, les arguments supplémentaires suivants sont pris en charge :

ip link add link DEVICE name NAME type vlan [ protocol VLAN_PROTO ] id VLANID [ reorder_hdr { on | off } ] [ gvrp { on | off } ] [ mvrp { on | off } ] [ loose_binding { on | off } ] [ bridge_binding { on | off } ] [ ingress-qos-map QOS-MAP ] [ egress-qos-map QOS-MAP ]


protocol VLAN_PROTO - soit 802.1Q, soit 802.1ad.

id VLANID - spécifie l'identifiant VLAN à utiliser. Notez que les nombres commençant par " 0 " ou " 0x " sont interprétés comme octaux ou hexadécimaux, respectivement.

reorder_hdr { on | off } - spécifie si les en-têtes Ethernet sont réorganisés ou non (par défaut : on).


Si reorder_hdr est on, l'en-tête VLAN ne sera pas inséré immédiatement mais seulement avant de passer au périphérique physique (si ce périphérique ne prend pas en charge le déchargement VLAN), de manière similaire en réception - par défaut, le paquet sera dés-étiqueté avant d'être reçu par le périphérique VLAN. La réorganisation permet d'accélérer l'étiquetage en sortie et de masquer l'en-tête VLAN en entrée, de sorte que le paquet ressemble à un paquet Ethernet ordinaire, tout en pouvant être source de confusion pour la capture de paquets car l'en-tête VLAN n'existe pas dans le paquet.

Le déchargement VLAN peut être vérifié avec ethtool(8) :

ethtool -k <phy_dev> | grep tx-vlan-offload


où <phy_dev> est le périphérique physique auquel le périphérique VLAN est lié.

gvrp { on | off } - spécifie si ce VLAN doit être enregistré en utilisant le protocole GARP VLAN Registration Protocol.

mvrp { on | off } - spécifie si ce VLAN doit être enregistré en utilisant le protocole Multiple VLAN Registration Protocol.

loose_binding { on | off } - spécifie si l'état du périphérique VLAN est lié à l'état du périphérique physique.

bridge_binding { on | off } - spécifie si l'état de liaison du périphérique VLAN suit l'état des ports de pont qui sont membres du VLAN.

ingress-qos-map QOS-MAP - définit un mappage du champ prio de l'en-tête VLAN à la priorité interne du paquet Linux pour les trames entrantes. Le format est FROM:TO avec plusieurs mappages séparés par des espaces.

egress-qos-map QOS-MAP - définit un mappage de la priorité interne du paquet Linux au champ prio de l'en-tête VLAN, mais pour les trames sortantes. Le format est le même que pour ingress-qos-map.

La priorité du paquet Linux peut être définie avec iptables(8) :

iptables -t mangle -A POSTROUTING [...] -j CLASSIFY --set-class 0:4


et cette priorité "4" peut être utilisée dans le mappage qos de sortie pour définir la priorité VLAN "5" :


ip link set veth0.10 type vlan egress 4:5


Support du type VXLAN
Pour une liaison de type VXLAN, les arguments supplémentaires suivants sont pris en charge :

ip link add DEVICE type vxlan id VNI [ dev PHYS_DEV ] [ { group | remote } IPADDR ] [ local { IPADDR | any } ] [ ttl TTL ] [ tos TOS ] [ df DF ] [ flowlabel FLOWLABEL ] [ dstport PORT ] [ srcport MIN MAX ] [ reserved_bits VALUE ] [ [no]learning ] [ [no]proxy ] [ [no]rsc ] [ [no]l2miss ] [ [no]l3miss ] [ [no]udpcsum ] [ [no]udp6zerocsumtx ] [ [no]udp6zerocsumrx ] [ [no]localbypass ] [ ageing SECONDS ] [ maxaddress NUMBER ] [ [no]external ] [ gbp ] [ gpe ] [ [no]vnifilter ] [ [no]mcroute ]


id VNI - spécifie l'identifiant de réseau VXLAN (ou identifiant de segment VXLAN) à utiliser.

dev PHYS_DEV - spécifie le périphérique physique à utiliser pour la communication de l'extrémité du tunnel.

group IPADDR - spécifie l'adresse IP multicast à rejoindre. Ce paramètre ne peut pas être spécifié avec le paramètre remote.

remote IPADDR - spécifie l'adresse IP de destination unicast à utiliser dans les paquets sortants lorsque l'adresse de la couche de liaison de destination n'est pas connue dans la base de données de transfert du périphérique VXLAN. Ce paramètre ne peut pas être spécifié avec le paramètre group.

local IPADDR - spécifie l'adresse IP source à utiliser dans les paquets sortants.

ttl TTL - spécifie la valeur TTL à utiliser dans les paquets sortants.

tos TOS - spécifie la valeur TOS à utiliser dans les paquets sortants.

df DF - spécifie l'utilisation du bit Don't Fragment (DF) dans les paquets sortants avec des en-têtes IPv4. La valeur inherit fait que le bit est copié de l'en-tête IP d'origine. Les valeurs unset et set font que le bit est toujours désactivé ou toujours activé, respectivement. Par défaut, le bit n'est pas défini.

flowlabel FLOWLABEL - spécifie le label de flux à utiliser dans les paquets sortants.

dstport PORT - spécifie le port de destination UDP à utiliser pour communiquer avec l'extrémité du tunnel
VXLAN distante.

srcport MIN MAX - spécifie la plage de numéros de port à utiliser comme ports source UDP pour communiquer avec l'extrémité du tunnel VXLAN distante.

reserved_bits VALUE - par défaut, le noyau rejette les paquets qui ont des bits définis en dehors des champs requis par les fonctionnalités activées sur le netdevice VXLAN. reserved_bits est une quantité de 64 bits spécifiant quels bits peuvent être définis dans un en-tête VXLAN. Chaque bit défini dans la valeur est un bit toléré défini dans un paquet.

[no]learning - spécifie si les adresses inconnues de la couche de liaison source et les adresses IP sont entrées dans la base de données de transfert du périphérique VXLAN.

[no]rsc - spécifie si le raccourci de routage est activé.

[no]proxy - spécifie si le proxy ARP est activé.

[no]l2miss - spécifie si des notifications de non-correspondance LLADDR netlink sont générées.

[no]l3miss - spécifie si des notifications de non-correspondance d'adresse IP netlink sont générées.

[no]udpcsum - spécifie si la somme de contrôle UDP est calculée pour les paquets transmis sur IPv4.

[no]udp6zerocsumtx - ignore le calcul de la somme de contrôle UDP pour les paquets transmis sur IPv6.

[no]udp6zerocsumrx - autorise les paquets UDP entrants sur IPv6 avec un champ de somme de contrôle zéro.

[no]localbypass - si la destination FDB est locale, avec nolocalbypass activé, les paquets encapsulés sont transmis à la pile réseau de l'espace utilisateur. S'il existe un processus en espace utilisateur écoutant ces paquets, il aura la possibilité de les traiter. Si localbypass est actif (par défaut), la pile réseau du noyau est contournée et les paquets sont injectés dans le périphérique VXLAN cible, en supposant qu'il en existe un.

ageing SECONDS - spécifie la durée de vie en secondes des entrées FDB apprises par le noyau.

maxaddress NUMBER - spécifie le nombre maximal d'entrées FDB.

[no]external - spécifie si un plan de contrôle externe (par exemple, ip route encap) ou la FDB interne doit être utilisé.

[no]vnifilter - spécifie si le périphérique vxlan est capable de filtrer par VNI. Ne fonctionne qu'avec un périphérique vxlan ayant le drapeau external activé. une fois activé, la commande bridge vni est utilisée pour gérer la table de filtrage VNI sur le périphérique. Le périphérique ne peut recevoir que des paquets dont les VNI sont configurés dans la table de filtrage VNI.

[no]mcroute - lorsque le tunnel VXLAN a une destination multicast, si les paquets sous-jacents doivent

uld be sent directly to the physical device (the default), or whether they should be multicast-routed. In the latter case, for purposes of matching a multicast route, (S,G) are, respectively, local and remote address of the tunnel, and iif is the tunnel physical

device.

gbp - enables the Group Policy extension (VXLAN-GBP)

.


Allows one to transport group policy context across VXLAN network peers. If enabled, includes the mark of a packet in the VXLAN header for outgoing packets and fills the packet mark based on the information found in the VXLAN header for incoming

packets.

Format of upper 16 bits of packet mark

(flags);


+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|-|-|-|-|-|-|-|-|-|D|-|-|A|-|-|-|
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

-+-+

D := Don't Learn bit. When set, this bit indicates that the egress VTEP MUST NOT learn the source address of the encapsulated

frame.

A := Indicates that the group policy has already been applied to this packet. Policies MUST NOT be applied by devices when the A bit is set.

Format of lower 16 bits of packet mark (policy

ID):


+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
| Group Policy ID |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

Example:
iptables -A OUTPUT [...] -j MARK --set-mark

0x800FF


gpe - enables the Generic Protocol extension (VXLAN-GPE). Currently, this is only supported together with the external ke

yword.

netkit Type
Support
For a link of type netkit the following additional arguments are supported:

ip link add DEVICE type netkit [ mode MODE ] [ scrub SCRUB ] [ POLICY ] [ peer [ scrub SCRUB ] [ POLICY ] [ NAME

] ]


mode MODE - specifies the operation mode of the netkit device with "l3" and "l2" as possible values. Default option

is "l3".

scrub SCRUB - specifies the scrub behavior of the netkit device with "default" and "none" as possible values. With "default" the device zeroes the skb->{mark,priority} fields before invoking the attached BPF program when its peer device resides in a different network namespace. With "none" the device leaves clearing skb->{mark,priority} up to the BPF program. Default option is "default". Specifying scrub before the peer option refers to the primary device, after the peer option refers to the peer

device.

POLICY - specifies the default device policy when no BPF programs are attached with "forward" and "blackhole" as possible values. Default option is "forward". Specifying policy before the peer option refers to the primary device, after the peer option refers to the peer

device.

NAME - specifies the device name of the peer

device.

Support des types MACVLAN et MACVTAP
Pour une liaison de type MACVLAN ou MACVTAP, les arguments supplémentaires suivants sont pris en charge :

ip link add link DEVICE name NAME type { macvlan | macvtap } mode { private | vepa | bridge | passthru [ nopromisc ] | source [ nodst ] } [ bcqueuelen { LENGTH } ] [ bclim LIMIT ]


type { macvlan | macvtap } - spécifie le type de liaison à utiliser. macvlan crée uniquement une interface virtuelle, tandis que macvtap crée en plus un périphérique caractère /dev/tapX à utiliser comme un périphérique tuntap.

mode private - N'autorise pas la communication entre les instances macvlan sur la même interface physique, même si le commutateur externe prend en charge le mode hairpin.

mode vepa - Mode Virtual Ethernet Port Aggregator. Les données d'une instance macvlan à une autre sur la même interface physique sont transmises sur l'interface physique. Soit le commutateur connecté doit prendre en charge le mode hairpin, soit il doit y avoir un routeur TCP/IP qui achemine les paquets pour permettre la communication. C'est le mode par défaut.

mode bridge - En mode pont, tous les points de terminaison sont directement connectés les uns aux autres, la communication n'est pas redirigée via le pair de l'interface physique.

mode passthru [ nopromisc ] - Ce mode donne plus de puissance à un seul point de terminaison, généralement en mode macvtap. Il n'est pas autorisé pour plus d'un point de terminaison sur la même interface physique. Tout le trafic sera transmis à ce point de terminaison, permettant aux invités virtio de changer d'adresse MAC ou de définir le mode promiscuous afin de pontifier l'interface ou de créer des interfaces vlan par-dessus. Par défaut, ce mode force l'interface sous-jacente en mode promiscuous. La transmission du drapeau nopromisc empêche cela, de sorte que le drapeau promisc peut être contrôlé à l'aide des outils standard.

mode source [ nodst ] - permet de définir une liste d'adresses MAC autorisées, qui est utilisée pour correspondre à l'adresse MAC source des trames reçues sur l'interface sous-jacente. Cela permet de créer des associations VLAN basées sur MAC, au lieu de celles basées sur les ports ou les balises standard. Cette fonctionnalité est utile pour déployer un comportement basé sur MAC 802.1x, où les pilotes des interfaces sous-jacentes ne le permettent pas. Par défaut, les paquets sont également pris en compte (dupliqués) pour le MACVLAN basé sur la destination. La transmission du drapeau nodst empêche les paquets correspondants de passer également par le flux basé sur la destination.

bcqueuelen { LENGTH } - Définit la longueur de la file d'attente RX utilisée pour traiter les paquets broadcast et multicast. LENGTH doit être un entier positif dans la plage [0-4294967295]. Définir une longueur de 0 supprime effectivement tout trafic broadcast/multicast. Si non spécifié, la valeur par défaut du pilote macvlan (1000) est utilisée. Notez que tous les macvlans partageant le même périphérique sous-jacent utilisent la même file d'attente. Le paramètre ici est une requête, la longueur réelle de la file d'attente utilisée sera la longueur maximale demandée par chaque interface macvlan. Lors de la liste des paramètres du périphérique, le paramètre bcqueuelen ainsi que le bcqueuelen réellement utilisé sont listés pour aider l'utilisateur à mieux comprendre le réglage.

bclim LIMIT - Définit le seuil pour la mise en file d'attente des broadcasts. LIMIT doit être un entier de 32 bits. Le régler à -1 désactive complètement la mise en file d'attente des broadcasts. Sinon, une adresse multicast sera mise en file d'attente comme broadcast si le nombre d'appareils l'utilisant est supérieur à la valeur donnée.

Par conséquent, toute chaîne est acceptée, mais peut entraîner une sortie vide.

ip link show

Affiche les appareils asservis par br0

ip link set dev ppp0 mtu 1400

Change le MTU de l'appareil ppp0.

ip link add link eth0 name eth0.10 type vlan id 10

Crée un nouvel appareil VLAN eth0.10 sur l'appareil eth0.

ip link delete dev eth0.10

Supprime l'appareil VLAN.

ip link help gre

Affiche l'aide pour le type de lien gre.

ip link add name tun1 type ipip remote 192.168.1.1 local 192.168.1.2 ttl 225 encap gue encap-sport auto encap-dport 5555 encap-csum encap-remcsum

Crée un IPIP encapsulé avec Generic UDP Encapsulation, et la somme de contrôle UDP externe et la décharge de somme de contrôle distante sont activées.

ip link set dev eth0 xdp obj prog.o

Attache un programme XDP/BPF à l'appareil eth0, où le programme est situé dans prog.o, section "prog" (section par défaut). Dans le cas où un programme XDP/BPF est déjà attaché, une erreur sera générée.

ip -force link set dev eth0 xdp obj prog.o sec foo

Attache un programme XDP/BPF à l'appareil eth0, où le programme est situé dans prog.o, section "foo". Dans le cas où un programme XDP/BPF est déjà attaché, il sera remplacé par le nouveau.

ip -force link set dev eth0 xdp pinned /sys/fs/bpf/foo

Attache un programme XDP/BPF à l'appareil eth0, où le programme a été précédemment épinglé en tant que nœud objet dans le système de fichiers BPF sous le nom foo.

ip link set dev eth0 xdp off

Si un programme XDP/BPF est attaché à l'appareil eth0, le détacher et désactiver efficacement XDP pour l'appareil eth0.

ip link add link wpan0 lowpan0 type lowpan

Crée une interface 6LoWPAN nommée lowpan0 sur l'appareil IEEE 802.15.4 sous-jacent wpan0.

ip link add dev ip6erspan11 type ip6erspan seq key 102 local fc00:100::2 remote fc00:100::1 erspan_ver 2 erspan_dir ingress erspan_hwid 17

Crée une interface IP6ERSPAN version 2 nommée ip6erspan00.
