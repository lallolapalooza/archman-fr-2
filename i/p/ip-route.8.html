DESCRIPTIO

N

ip route est utilisé pour manipuler les entrées des tables de routage du

noyau.

Types de routes

:


unicast - l'entrée de route décrit les chemins réels vers les destinations couvertes par le préfixe de

route.

unreachable - ces destinations sont inaccessibles. Les paquets sont rejetés et le message ICMP host unreachable est généré. Les émetteurs locaux reçoivent une erreur EHOSTUNREACH

.

blackhole - ces destinations sont inaccessibles. Les paquets sont rejetés silencieusement. Les émetteurs locaux reçoivent une erreur EINVAL

.

prohibit - ces destinations sont inaccessibles. Les paquets sont rejetés et le message ICMP communication administratively prohibited est généré. Les émetteurs locaux reçoivent une erreur EACCES

.

local - les destinations sont assignées à cet hôte. Les paquets sont bouclés en arrière et livrés

localement.

broadcast - les destinations sont des adresses de diffusion. Les paquets sont envoyés en diffusion sur le

lien.

throw - une route de contrôle spéciale utilisée avec les règles de politique. Si une telle route est sélectionnée, la recherche dans cette table est terminée en faisant semblant qu'aucune route n'a été trouvée. Sans routage par politique, cela équivaut à l'absence de route dans la table de routage. Les paquets sont rejetés et le message ICMP net unreachable est généré. Les émetteurs locaux reçoivent une erreur ENETUNREACH

.

nat - une route NAT spéciale. Les destinations couvertes par le préfixe sont considérées comme des adresses factices (ou externes) qui nécessitent une traduction vers des adresses réelles (ou internes) avant le transfert. Les adresses vers lesquelles traduire sont sélectionnées avec l'attribut via. Avertissement : Le routage NAT n'est plus pris en charge dans Linux 2.

6.

anycast - non implémenté les destinations sont des adresses anycast assignées à cet hôte. Elles sont principalement équivalentes à local avec une différence : de telles adresses sont invalides lorsqu'elles sont utilisées comme adresse source de n'importe quel

paquet.

multicast - un type spécial utilisé pour le routage multicast. Il n'est pas présent dans les tables de routage normales.

Tables de routes : Linux-2.x peut regrouper les routes dans plusieurs tables de routage identifiées par un nombre dans la plage de 1 à 2^32-1 ou par un nom dans /usr/share/iproute2/rt_tables ou /etc/iproute2/rt_tables (a priorité s'il existe). Par défaut, toutes les routes normales sont insérées dans la table principale (ID 254) et le noyau n'utilise que cette table lors du calcul des routes. Les valeurs (0, 253, 254 et 255) sont réservées à un usage

intégré.

En fait, une autre table existe toujours, qui est invisible mais encore plus importante. C'est la table locale (ID 255). Cette table se compose des routes pour les adresses locales et de diffusion. Le noyau maintient cette table automatiquement et l'administrateur n'a généralement pas besoin de la modifier ou même de la

regarder.

Les tables de routage multiples entrent en jeu lorsque le routage par politique est

utilisé.

Flavors

parameters

Les flavors représentent des opérations supplémentaires qui peuvent modifier ou étendre un sous-ensemble des comportements existants.

psp - Le Penultimate Segment Pop (PSP) copie le dernier SID de la liste SID (portée par le SRH le plus externe) dans l'adresse de destination IPv6 (DA) et supprime (c'est-à-dire retire) le SRH de l'en-tête IPv6. Le flavor NEXT-C-SID peut être configuré pour supporter les longueurs Locator-Block et Locator-Node Function fournies par l'utilisateur.
