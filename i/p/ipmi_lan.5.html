ipmi_lan(5) Fichier de configuration de l'interface IPMI LAN ipmi_lan(5)

NOM

ipmi/lan.conf - Fichier de configuration de l'interface IPMI LAN

SYNTAXE

/etc/ipmi/lan.conf

DESCRIPTION

Les commandes ipmi_sim et ipmilan sont configurées à l'aide de ce fichier de configuration.

ÉLÉMENTS DE CONFIGURATION

Les champs suivants sont utilisés dans de nombreuses commandes :

booléen Peut être "vrai", "faux", "on" ou "off".

priv Un niveau de privilège IPMI. Peut être "callback", "user", "operator", ou "admin".

auth Un type d'autorisation IPMI. Peut être "none" pour aucune authentification, "straight" pour une authentification par mot de passe en clair, "md2" pour utiliser l'authentification par hachage de message MD2, ou "md5" pour utiliser l'authentification par hachage de message MD5.

STRUCTURE DU FICHIER

Les lignes vides et les lignes commençant par '#' sont ignorées.

Les commandes suivantes sont autorisées dans le fichier de configuration :

nom "nom"
Définit un nom pour le BMC. Cela contrôlera d'autres éléments, tels que la valeur par défaut du fichier de commandes de démarrage de ipmi_sim et l'emplacement de stockage des données persistantes.
utilisateur numéro_utilisateur activé nom_utilisateur mot_de_passe priv_max sessions_max
numéro_utilisateur spécifie le numéro d'utilisateur pour l'utilisateur. Notez que le numéro d'utilisateur 0 est invalide, et le numéro d'utilisateur 1 est l'utilisateur spécial "anonyme", dont le nom d'utilisateur est ignoré. Cette valeur peut aller jusqu'à 63, le maximum d'utilisateurs IPMI possible. Si vous souhaitez un accès anonyme, vous devez avoir un numéro d'utilisateur 1.

activé est un booléen qui spécifie si l'utilisateur est activé ou non.

nom_utilisateur spécifie le nom de l'utilisateur, sous forme de nom.

mot_de_passe spécifie le mot de passe de l'utilisateur, sous forme de nom.

priv_max spécifie le niveau de privilège maximum autorisé pour l'utilisateur.

sessions_max spécifie le nombre maximum de sessions que l'utilisateur peut ouvrir.

startcmd "cmd"
spécifie une commande à exécuter lorsqu'une demande de mise sous tension est reçue. Cela permet de démarrer une machine virtuelle qui peut ensuite se connecter au simulateur. Le simulateur gère le processus ici, et l'état de mise sous tension du processus dépend de son existence ou non. Si une demande d'extinction est reçue, si le processus est connecté à une interface série virtuelle, un arrêt contrôlé est d'abord demandé. Si le processus ne se termine pas dans un délai spécifié, un signal SIGTERM est envoyé au processus. SIGTERM est envoyé immédiatement s'il n'y a pas de connexion. Si le processus ne disparaît pas dans un autre délai spécifié, un signal SIGKILL est envoyé.
startnowvrai|faux
Si vrai, démarre la commande startcmd au démarrage du simulateur. Sinon, attend qu'une demande de mise sous tension soit émise.
poweroff_wait secondes
spécifie le temps d'attente pour que la commande startcmd effectue un arrêt contrôlé lors d'une demande d'extinction. Le simulateur envoie une requête à la cible, attend ce délai, puis envoie un signal SIGTERM au processus. Si ce délai est de zéro, aucun SIGTERM ne sera envoyé (ni SIGKILL). Notez que si le simulateur n'a pas de connexion à la VM, l'arrêt contrôlé est ignoré et un SIGTERM est envoyé immédiatement. Le délai par défaut est de 60 secondes.
kill_wait secondes
spécifie le temps d'attente pour que SIGTERM termine le processus. Si le processus ne se termine pas dans ce délai, un signal SIGKILL est envoyé. Si ce délai est de zéro, aucun SIGKILL n'est envoyé. Le délai par défaut est de 20 secondes.
console adresse port
spécifie qu'un port de console doit être ouvert à l'adresse et au port donnés. Vous pouvez vous connecter en telnet à la console et exécuter des commandes d'émulation. Notez qu'il s'agit d'une faille de sécurité assez importante, elle ne devrait être utilisée que pour le débogage dans un environnement contrôlé.
serial canal addr port [option [option [...]]]
canal spécifie le numéro ou le type de canal. Peut être kcs, smic, ou bt ou il peut s'agir de 15. Actuellement, seul le canal d'interface système (canal 15) est pris en charge pour les interfaces série. Si les autres sont spécifiés, il s'agit du canal 15 et l'interface donnée est rapportée dans les commandes de configuration de canal.

addr spécifie l'adresse IP sur laquelle écouter pour les connexions.

port spécifie le port sur lequel écouter pour les connexions.

Les options valides sont :

nom_codec spécifie quel codec utiliser sur le port série. Les options valides sont : TerminalMode, Direct, RadisysAscii et VM. Les trois premières sont des implémentations d'interfaces série IPMI sur certains systèmes et pourraient être utilisées pour simuler ces systèmes. Le mode VM est probablement le plus intéressant ; il est conçu pour être utilisé avec une machine virtuelle comme qemu.

nom_oem spécifie l'implémentation de certaines commandes et options personnalisées OEM sur l'interface. Les options valides sont PigeonPoint et Radisys.

attn c1[,c2[...]] spécifie une liste de caractères, séparés par des virgules, à utiliser comme caractère d'attention sur l'interface. Généralement, la valeur par défaut est correcte. Les caractères sont spécifiés sous forme de chiffres décimaux, octaux ou hexadécimaux de style C.

ipmb addr spécifie l'adresse IPMI de l'interface. La valeur par défaut, 0x20, est généralement correcte, mais lors de l'émulation de systèmes ATCA, cela peut être nécessaire.

sol périphérique baud_par_défaut [history=taille[,backupfile=nom_fichier]] [historyfru=numéro_fru]

Permet une connexion Serial Over LAN (SOL) au périphérique donné. Cela se fera via l'interface 1 pour le MC.

périphérique est le chemin complet vers le nom du périphérique. Il peut également être sous la forme "tcp:adresse:port" ou "telnet:adresse:port" pour établir des connexions via TCP (sans ou avec traitement telnet). Ceci est utile pour fournir un accès SOL aux ports qemu.

baud_par_défaut définit le débit en bauds par défaut initial à utiliser. Ceci est remplacé par les paramètres SOL persistants.

history crée un périphérique d'historique sur l'interface SOL 2. La taille est la taille du tampon. Les données du périphérique sont stockées en permanence dans le tampon d'historique. Se connecter à l'interface SOL 2 provoquera le vidage complet du tampon d'historique. Si backupfile est spécifié, l'historique est rendu persistant. Cependant, il n'est stocké que lors d'un signal capturable ou d'un arrêt normal, un arrêt brutal ou un signal fatal entraînera la perte des données.

historyfru rend l'historique disponible via le numéro de FRU donné sur le MC.

Notez que si la connexion ne parvient pas à s'établir, le simulateur continuera d'essayer de se connecter. De cette façon, vous pouvez corriger les ports série UDP ou les sessions qemu et la reconnexion sera automatique.

loadlib "module" ["options"]

Charge le shared object donné dans le programme.

module est le chemin complet vers le module. Il doit être entre guillemets.

options est une chaîne optionnelle entre guillemets qui transmet des options au module. Le contenu de la chaîne n'est pas spécifié, le module le définit.

NOM

ipmi_lan.conf - Configuration du réseau IPMI

SYNOPSIS

Fichier de configuration

DESCRIPTION

Ce fichier est utilisé pour configurer l'interface réseau IPMI. Il est lu par le démon IPMI.

Le fichier est composé d'une série de commandes. Les commandes suivantes sont des éléments de configuration qui peuvent être utilisés pour configurer le comportement du démon IPMI.

CALLBACKS DU MODULE

Les modules peuvent être enregistrés auprès du système IPMI. Le module doit imprimer sa version. Vous devez fournir cette fonction.

ipmi_sim_module_init(sys_data_t *sys, char *options) est appelé après la lecture du fichier de configuration et avant toute autre initialisation. Le module doit effectuer la majeure partie de son initialisation ici. Vous devez fournir cette fonction.

ipmi_sim_module_post_init(sys_data_t *sys) est appelé après que ipmi_sim ait terminé son initialisation. Cette fonction est facultative.

Le paramètre sys est utilisé pour la plupart des fonctions d'interface avec le code principal d'ipmi_sim, comme la journalisation, les temporisateurs et quelques appels MC. Le contenu est opaque pour le module.

startlan canal
Démarre une zone de configuration LAN. Cela spécifie les paramètres d'une connexion LAN utilisant le canal donné. Ceci peut être spécifié plus d'une fois dans un fichier pour prendre en charge plusieurs connexions LAN. Les commandes suivantes, jusqu'à endlan, sont des commandes spécifiques au LAN listées ci-dessous. canal spécifie le canal pour lequel la configuration LAN sera définie.

COMMANDES DE CONFIGURATION LAN

Les commandes suivantes ne sont valides qu'à l'intérieur d'une zone startlen.

addr adresse-IP [port-UDP]
adresse-IP spécifie l'adresse IP à utiliser pour un port IP. Jusqu'à 4 adresses peuvent être spécifiées. Si aucune adresse n'est spécifiée, elle utilise par défaut un port à 0.0.0.0 (pour toutes les adresses de la machine) sur le port 623.

port-UDP spécifie un port optionnel sur lequel écouter. Il utilise par défaut 623 (le port standard).

PEF_alerting booléen
Active ou désactive les alertes PEF (non pris en charge actuellement).
per_msg_auth booléen
Active ou désactive l'authentification par message.
priv_limit priv
Le privilège maximum autorisé sur cette interface.
allowed_auths_callback [auth [auth [...]]]
auth spécifie les niveaux d'autorisation autorisés pour le niveau de privilège de rappel. Seuls les niveaux spécifiés sur cette ligne sont autorisés pour le niveau d'autorisation. Si cette ligne n'est pas présente, l'autorisation de rappel ne peut pas être utilisée.
allowed_auths_user [auth [auth [...]]]
auth spécifie les niveaux d'autorisation autorisés pour le niveau de privilège utilisateur. Seuls les niveaux spécifiés sur cette ligne sont autorisés pour le niveau d'autorisation. Si cette ligne n'est pas présente, l'autorisation utilisateur ne peut pas être utilisée.
allowed_auths_operator [auth [auth [...]]]
auth spécifie les niveaux d'autorisation autorisés pour le niveau de privilège opérateur. Seuls les niveaux spécifiés sur cette ligne sont autorisés pour le niveau d'autorisation. Si cette ligne n'est pas présente, l'autorisation opérateur ne peut pas être utilisée.
allowed_auths_admin [auth [auth [...]]]
auth spécifie les niveaux d'autorisation autorisés pour le niveau de privilège administrateur. Seuls les niveaux spécifiés sur cette ligne sont autorisés pour le niveau d'autorisation. Si cette ligne n'est pas présente, l'autorisation utilisateur ne peut pas être utilisée.
guid nom
Permet de spécifier le GUID de 16 octets pour la connexion LAN IPMI. Si ce n'est pas spécifié, alors la commande GUID n'est pas prise en charge.
