VERSION

S

Linux 2.4 cassera la compatibilité binaire pour la structure sockaddr_in6 sur les hôtes 64 bits en modifiant l'alignement de in6_addr et en ajoutant un champ sin6_scope_id supplémentaire. Les interfaces du noyau restent compatibles, mais un programme incluant sockaddr_in6 ou in6_addr dans d'autres structures pourrait ne pas l'être. Ce n'est pas un problème pour les hôtes 32 bits comme

i386.

Le champ sin6_flowinfo est nouveau dans Linux 2.4. Il est transmis/lu de manière transparente par le noyau lorsque la longueur d'adresse fournie le contient

. Certains programmes qui fournissent un tampon d'adresse plus long puis
vérifient la longueur de l'adresse sortante peuvent cesser de fonctionner.

NOTE

S

La structure sockaddr_in6 est plus grande que la structure générique sockaddr. Les programmes qui supposent que tous les types d'adresses peuvent être stockés en toute sécurité dans une struct sockaddr doivent être modifiés pour utiliser struct sockaddr_storage à la

SOL_IP, SOL_IPV6, SOL_ICMPV6 et d'autres options de socket SOL_* sont des variantes non portables de IPPROTO_*. Voir aussi ip(
