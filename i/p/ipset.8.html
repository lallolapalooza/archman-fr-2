DESCRIPTIO

N

ipset est utilisé pour configurer, maintenir et inspecter les ensembles IP dans le noyau Linux. Selon le type de l'ensemble, un ensemble IP peut stocker des adresses IP(v4/v6), des numéros de port (TCP/UDP), des paires d'adresses IP et MAC, des paires d'adresse IP et de numéro de port, etc. Voir les définitions des types d'ensembles

ci-dessous.

Les correspondances et cibles iptables faisant référence à des ensembles créent des références, qui protègent les

ensembles donnés dans le noyau. Un ensemble ne peut pas êt
re détruit tant qu'une seule référence pointe vers lui.

S

Les options reconnues par ipset peuvent être divisées en plusieurs groupes

différents.

INTRODUCTIO

N

Un type de set comprend la méthode de stockage par laquelle les données sont stockées et le ou les types de données qui sont stockés dans le set. Par conséquent, le paramètre TYPENAME de la commande create suit la

syntaxe

TYPENAME := méthode:typededonnée[,typededonnée[,typededon

née]]

où la liste actuelle des méthodes est bitmap, hash et list, et les types de données possibles sont ip, net, mac, port et iface. La dimension d'un set est égale au nombre de types de données dans son nom de

type.

Lors de l'ajout, de la suppression ou du test d'entrées dans un set, la même syntaxe de données séparées par des virgules doit être utilisée pour le paramètre d'entrée des commandes,

c'est-à-dire
ipset add fo
o ipaddr,po
rtnum,ipaddr

Si des noms d'hôte ou de services contenant un tiret dans le nom sont utilisés à la place d'adresses IP ou de numéros de service, alors le nom d'hôte ou de service doit être entouré de crochets. Exemple

:
ipset add foo
[test-hostnam
e],[ftp-data]

Dans le cas des noms d'hôte, le résolveur DNS est appelé en interne par ipset, mais s'il retourne plusieurs adresses IP, seule la première est

utilisée.

Les types bitmap et list utilisent un stockage de taille fixe. Les types hash utilisent un hachage pour stocker les éléments. Afin d'éviter des collisions dans le hachage, un nombre limité de chaînages est utilisé et, si celui-ci est épuisé, le doublement de la taille du hachage est effectué lors de l'ajout d'entrées par la commande ipset. Lorsque des entrées sont ajoutées par la cible SET de iptables/ip6tables, la taille du hachage est fixe et le set ne sera pas

dupliqué, même si la nouvelle ent
rée ne peut pas être ajoutée au set.

Tous les types de set prennent en charge le paramètre optionnel timeout lors de la création d'un set et de l'ajout d'entrées. La valeur du paramètre timeout pour la commande create signifie la valeur de délai d'expiration par défaut (en secondes) pour les nouvelles entrées. Si un set est créé avec la prise en charge du délai d'expiration, alors la même option timeout peut être utilisée pour spécifier des valeurs de délai d'expiration non par défaut lors de l'ajout d'entrées. Une valeur de délai d'expiration de zéro signifie que l'entrée est ajoutée de manière permanente au set. La valeur de délai d'expiration des éléments déjà ajoutés peut être modifiée en réajoutant l'élément en utilisant l' option -exist. La plus grande valeur de délai d'expiration possible est 2147483 (en secondes). Exemple

:
ipset create test hash:ip timeout
300
ipset add test 192.168.0.1 timeout
60

Tous les types de set prennent en charge l'extension optionnelle comment. L'activation de cette extension sur un ipset vous permet d'annoter une entrée ipset avec une chaîne de caractères arbitraire. Cette chaîne est complètement ignorée à la fois par le noyau et par ipset lui-même et sert uniquement à fournir un moyen pratique de documenter la raison de l'existence d'une entrée. Les commentaires ne doivent contenir aucun guillemet et le caractère d'échappement habituel (\) n'a aucun sens. Par exemple, la commande shell suivante est illégale

:
ipset add foo 1.1.1.
1 comment "this comme
nt is \"bad\""

Dans l'exemple ci-dessus, votre shell échappera bien sûr les guillemets et ipset verra les guillemets dans l'argument pour le commentaire, ce qui entraînera une erreur d'analyse. Si vous écrivez votre propre système, vous devriez éviter de créer des commentaires contenant un guillemet si vous ne voulez pas casser "ipset save" et "ipset restore", néanmoins, le noyau ne vous empêchera pas de le faire. Ce qui suit est parfaitement acceptable

comment

list:set

Le type list:set utilise une simple liste dans laquelle vous pouvez stocker des noms d'ensembles.

CREATE-OPTIONS := [ size valeur ] [ timeout valeur ] [ counters ] [ comment ] [ skbinfo ]

ADD-ENTRY := nomset [ { before | after } nomset ]

ADD-OPTIONS := [ timeout valeur ] [ packets valeur ] [ bytes valeur ] [ comment chaîne ] [ skbmark valeur ] [ skbprio valeur ] [ skbqueue valeur ]

DEL-ENTRY := nomset [ { before | after } nomset ]

TEST-ENTRY := nomset [ { before | after } nomset ]

Options de création optionnelles :

size valeur
La taille de la liste, la valeur par défaut est 8. Le paramètre est ignoré depuis la version 6.24 d'ipset.

Avec la commande ipset, vous pouvez ajouter, supprimer et tester des noms d'ensembles dans un ensemble de type list:set.

Avec la correspondance set ou la cible SET de netfilter, vous pouvez tester, ajouter ou supprimer des entrées dans les ensembles ajoutés à un ensemble de type list:set. La correspondance essaiera de trouver une entrée correspondante dans les ensembles et la cible essaiera d'ajouter une entrée au premier ensemble où elle peut être ajoutée. Le nombre d'options de direction de la correspondance et de la cible est important : les ensembles qui nécessitent plus de paramètres que ceux spécifiés sont ignorés, tandis que les ensembles avec un nombre égal ou inférieur de paramètres sont vérifiés, les éléments sont ajoutés/supprimés. Par exemple, si a et b sont des ensembles de type list:set, alors dans la commande

iptables -m set --match-set a src,dst -j SET --add-set b src,dst

la correspondance et la cible ignoreront tout ensemble dans a et b qui stocke des triplets de données, mais correspondront à tous les ensembles avec un stockage de données simple ou double dans l'ensemble a et s'arrêteront de correspondre au premier ensemble réussi, et ajouteront src au premier ensemble de données simples ou src,dst au premier ensemble de données doubles dans b auquel l'entrée peut être ajoutée. Vous pouvez imaginer un ensemble de type list:set comme une union ordonnée des éléments de l'ensemble.

Veuillez noter : avec la commande ipset, vous pouvez ajouter, supprimer et **tester** les noms d'ensembles dans un ensemble de type list:set, et **non** la présence d'un membre d'un ensemble (comme une adresse IP).

RESTRICTIONS GÉNÉRALES

Les entrées d'ensemble avec une valeur zéro ne peuvent pas être utilisées avec les méthodes de hachage. La valeur de protocole zéro avec des ports ne peut pas être utilisée.

COMMENTAIRES

Si vous souhaitez stocker des sous-réseaux de même taille à partir d'un réseau donné (par exemple, des blocs /24 à partir d'un réseau /8), utilisez le type d'ensemble bitmap:ip. Si vous souhaitez stocker des réseaux aléatoires de même taille (par exemple, des blocs /24 aléatoires), utilisez le type hash:ip. Si vous avez des blocs réseau de tailles aléatoires, utilisez hash:net.

La correspondance sur les adresses MAC de destination en utilisant le paramètre dst des modules du noyau de correspondance set ne fonctionnera que si l'adresse MAC de destination est disponible dans le paquet à l'étape de traitement donnée, c'est-à-dire qu'elle ne s'applique qu'aux paquets entrants dans les chaînes PREROUTING, INPUT et FORWARD, par rapport à l'adresse MAC telle qu'elle était initialement présente dans le paquet reçu (typiquement, l'une des adresses MAC de l'hôte local). Ce n'est **pas** l'adresse MAC de destination vers laquelle une adresse IP de destination se résout, après routage. Si l'adresse MAC n'est pas disponible (par exemple, dans la chaîne OUTPUT), le paquet ne correspondra tout simplement pas.

La compatibilité descendante est maintenue et l'ancienne syntaxe ipset est toujours prise en charge.

Les types d'ensembles iptree et iptreemap sont supprimés : si vous y faites référence, ils sont automatiquement remplacés par des ensembles de type hash:ip.
