N

Avant que de nombreux outils IPMI puissent être utilisés sur un réseau, le contrôleur de gestion de carte mère (BMC) d'une machine doit être configuré. La configuration peut être assez intimidante pour ceux qui ne connaissent pas grand-chose à l'IPMI. Cette page manuel espère fournir suffisamment d'informations sur la configuration du BMC afin que vous puissiez configurer le BMC de votre système. Lorsque c'est approprié, des configurations BMC typiques seront

suggérées.

Voici un exemple de fichier de configuration partiellement généré en exécutant l'option --checkout avec la commande ipmi-config(8). Cette configuration provient de la catégorie core des valeurs de configuration (par défaut). Cet exemple de configuration devrait être suffisant pour la plupart des utilisateurs après avoir saisi les adresses IP et MAC locales appropriées. À la suite de cet exemple, des sections séparées de cette page manuel discuteront plus en détail des différentes sections du fichier de configuration avec des explications sur la manière de configurer le BMC pour différents

environnements.

Notez que de nombreuses options peuvent ou non être disponibles sur votre machine particulière. Par exemple, Serial-Over-Lan (SOL) n'est disponible que sur les machines IPMI 2.0. Par conséquent, si vous cherchez à configurer une machine IPMI 1.5, de nombreuses options liées à SOL ou à IPMI 2.0 ne vous seront pas disponibles. Le nombre d'utilisateurs configurables peut également varier pour votre machine

particulière.

Le fichier de configuration ci-dessous et la plupart de cette page manuel supposent que l'utilisateur s'intéresse à la configuration d'un BMC pour une utilisation avec IPMI sur LAN. Diverses options de configuration de ipmi-config(8) ont été laissées de côté ou ignorées car elles sont considérées comme inutiles. Les futures versions de cette page manuel essayeront d'inclure plus

d'informations.

Section User1, User2, ..

.

Les sections User du fichier de configuration du BMC servent à configurer les noms d'utilisateur pour la communication IPMI sur LAN. Le nombre d'utilisateurs disponibles pour la configuration sur votre système varie selon le fabricant. À l'exception du nom d'utilisateur pour User1, toutes les sections sont

identiques.

Le ou les noms d'utilisateur avec lesquels vous souhaitez configurer le BMC sont définis avec Username. Le premier nom d'utilisateur sous la section User1 est généralement le nom d'utilisateur NULL et ne peut pas être modifié. Le mot de passe du nom d'utilisateur peut être spécifié avec Password. Il peut être laissé vide pour définir un mot de passe NULL. Chaque utilisateur que vous souhaitez activer doit être activé via l'option de configuration Enable_User. Il est recommandé que tous les noms d'utilisateur aient des mots de passe non NULL ou soient désactivés pour des raisons de

sécurité.

Lan_Enable_Ipmi_Msgs est utilisé pour activer ou désactiver l'accès IPMI sur LAN pour l'utilisateur. Cela doit être défini sur "Yes" pour permettre aux outils IPMI sur LAN de

fonctionner.

Lan_Privilege_Limit spécifie la limite de niveau de privilège maximum autorisée pour l'utilisateur. Différentes commandes IPMI ont différentes restrictions de privilège. Par exemple, déterminer l'état d'alimentation d'une machine ne nécessite que le niveau de privilège "User". Cependant, le cycle d'alimentation nécessite le privilège "Operator". Généralement, vous voudrez attribuer à au moins un utilisateur une limite de privilège de "Administrator" afin que toutes les fonctions du système soient disponibles pour au moins un utilisateur via IPMI sur

LAN.

Lan_Session_Limit spécifie le nombre de sessions IPMI simultanées autorisées pour l'utilisateur. La plupart des utilisateurs voudront définir cela sur "0" pour autoriser un nombre illimité de sessions IPMI simultanées. Ce champ est considéré comme facultatif par les normes IPMI et peut entraîner des erreurs lors de sa configuration sur une valeur non nulle. Si des erreurs surviennent, la remise de la valeur à 0 devrait résoudre les

problèmes.

SOL_Payload_Access spécifie si un utilisateur particulier est autorisé à se connecter avec Serial-Over-LAN (SOL). Cela doit être défini sur "Yes" pour autoriser ce nom d'utilisateur à utiliser

SOL.

La configuration d'exemple ci-dessus désactive "User2" mais active l'utilisateur par défaut "NULL" (c'est-à-dire anonyme). De nombreux outils IPMI (open source et fournisseurs) ne permettent pas à l'utilisateur de saisir un nom d'utilisateur et supposent le nom d'utilisateur NULL par défaut. Si les outils que vous souhaitez utiliser permettent la saisie de noms d'utilisateur, il est recommandé d'activer l'un des noms d'utilisateur non NULL et de désactiver le nom d'utilisateur NULL pour des raisons de sécurité. Il est recommandé de désactiver le nom d'utilisateur NULL dans la section User1, afin que les utilisateurs soient tenus de spécifier un nom d'utilisateur pour la communication IPMI sur

LAN.

Certaines cartes mères peuvent nécessiter qu'un Username soit configuré avant la lecture/l'écriture des autres champs. Si c'est le cas, ces champs seront définis sur <username-no

t-set
-yet>.

Section

Lan_Channel

La section Lan_Channel configure divers paramètres de configuration IPMI sur LAN. À la fois les configurations Volatile et Non_Volatile peuvent être définies. Les configurations Volatile sont configurées immédiatement sur le BMC et auront un effet immédiat sur le système. Les configurations Non_Volatile ne sont disponibles qu'après la prochaine réinitialisation du système. Généralement, à la fois Volatile et Non_Volatile devraient être configurés de manière

identique.

Le paramètre Access_Mode configure la disponibilité d'IPMI sur LAN sur le système. Généralement, cela devrait être défini sur "Always_Available" pour activer IPMI sur

LAN.

Le paramètre Privilege_Limit définit le privilège maximum que tout utilisateur du système peut avoir lors de l'exécution d'IPMI sur LAN. Cela devrait être défini sur le niveau de privilège maximum configuré pour un nom d'utilisateur. Généralement, cela devrait être défini sur "Administrator"

.

Généralement, User_Level_Auth et Per_Message_Auth devraient être définis sur "Yes" pour une sécurité supplémentaire. Désactiver User_Level_Auth permet l'exécution des commandes IPMI de privilège "User" sans authentification. Désactiver Per_Message_Auth permet à moins de messages IPMI individuels de nécessiter une authentificatio

n
.

Lan_Conf

Ceux qui sont familiers avec la mise en place de réseaux trouveront la plupart des champs de cette section auto-explicatifs. L'exemple de configuration BMC ci-dessus illustre la mise en place d'une adresse IP statique. Le champ IP_Address_Source est configuré avec "Static". L'adresse IP, le masque de sous-réseau et les adresses IP de passerelle de la machine sont respectivement configurés avec les champs IP_Address, Subnet_Mask, Default_Gateway_Ip_Address et Backup_Gateway_Ip_Address. Les adresses MAC respectives pour les adresses IP sont configurées sous Mac_Address, Default_Gateway_Mac_Address et Backup_Gateway_Mac_Address

Il n'est pas requis de configurer le IP_Address du BMC pour qu'il soit le même que le P_Address utilisé par votre système d'exploitation pour cette interface réseau. Cependant, si vous choisissez d'utiliser une adresse différente, une configuration ARP alternative devra peut-être être mise en

place.

Pour configurer à la place les informations réseau de votre BMC via DHCP, le champ IP_Address_Source devrait être configuré avec

"Use_DHCP".

Il est recommandé de configurer des adresses IP statiques pour des raisons de résolution d'adresses. Voir Lan_Conf_Misc ci-dessous pour

plus détaillée.

Section

Lan_Conf_Auth

Cette section détermine quels types de mécanismes d'authentification par mot de passe sont autorisés pour les utilisateurs à différents niveaux de privilège sous le protocole IPMI 1.5. Les méthodes d'authentification actuellement prises en charge pour IPMI 1.5 sont None (aucun nom d'utilisateur/mot de passe requis), Straight_Password (les mots de passe sont envoyés en clair), MD2 (les mots de passe sont hachés avec MD2) et MD5 (les mots de passe sont hachés avec MD5). Différents noms d'utilisateur à différents niveaux de privilège peuvent être autorisés à s'authentifier différemment via cette configuration. Par exemple, un nom d'utilisateur avec les privilèges "User" peut être autorisé à s'authentifier avec un mot de passe en clair, mais un nom d'utilisateur avec les privilèges "Administrator" peut être autorisé à s'authentifier uniquement avec

MD5.

La configuration d'exemple ci-dessus prend en charge MD2 et MD5 l'authentification pour tous les utilisateurs aux niveaux de privilège "User", "Operator" et "Administrator". Tous les mécanismes d'authentification ont été désactivés pour le niveau de privilège

"Callback".

En général, vous ne voulez pas autoriser un utilisateur à s'authentifier avec None ou Straight_Password pour des raisons de sécurité. MD2 et MD5 sont des algorithmes de signature numérique qui peuvent chiffrer les mots de passe de manière minimale. Si vous avez choisi de prendre en charge le nom d'utilisateur NULL (User1 activé) et les mots de passe NULL (mot de passe NULL pour User1), vous devrez activer les champs d'authentification None ci-dessus pour permettre aux utilisateurs de se connecter via No

ne
.

Section

Lan_Conf_Misc

Cette section liste les options de configuration IPMI sur LAN diverses. Ce sont des options de configuration IPMI facultatives qui ne sont pas implémentées sur tous les

BMC.

Normalement, un client ne peut pas résoudre l'adresse MAC Ethernet sans que le système d'exploitation distant soit en cours d'exécution. Cependant, IPMI sur LAN ne fonctionnerait pas lorsque la machine est éteinte ou si l'adresse IP utilisée par le système d'exploitation pour cette interface réseau diffère de l'adresse IP du BMC. Une façon de contourner cela est via les ARPs gratuits. Les ARPs gratuits sont des paquets ARP générés par le BMC et envoyés pour annoncer l'adresse IP et MAC du BMC. Les autres machines du réseau peuvent stocker ces informations dans leur cache ARP local pour une résolution ultérieure IP/nom d'hôte. Cela permettrait à IPMI sur LAN de fonctionner lorsque la machine distante est éteinte. L'option Enable_Gratuitous_Arps vous permet d'activer ou de désactiver cette fonctionnalité. L'option Gratuitous_Arp_Interval vous permet de configurer la fréquence à laquelle les ARPs gratuits sont envoyés sur le

réseau.

Au lieu des ARPs gratuits, certains BMC sont capables de répondre aux requêtes ARP, même lorsqu'ils sont éteints. Si cette fonctionnalité est offerte, elle peut être activée via l'option Enable_Arp_Response

.

En général, l'activation des ARPs gratuits est acceptable. Cependant, cela augmentera le trafic sur votre réseau. Si vous utilisez IPMI sur un grand cluster, les ARPs gratuits peuvent facilement submerger votre réseau. Ils devraient être réglés pour se produire moins fréquemment ou être désactivés. S'ils sont désactivés, l'adresse MAC de la machine distante devrait être stockée de manière permanente dans le cache ARP local via arp(8)

.

Voir bmc-watchdog(8) pour une méthode qui permet de désactiver les ARPs gratuits lorsque le système

d'exploitation est en cours d'exécution, mais de
les activer lorsque le système est à l'arrêt.

Section Rmcpplus_Conf_Privileg

e

Cette section prend en charge la configuration des identifiants de suite de chiffrement IPMI 2.0 (y compris Serial-over-LAN). Si votre machine ne prend pas en charge IPMI 2.0, les champs ne seront pas

configurables.

Chaque identifiant de suite de chiffrement décrit une combinaison d'un algorithme d'authentification, d'un algorithme d'intégrité et d'un algorithme de chiffrement pour IPMI 2.0. L'algorithme d'authentification est utilisé pour l'authentification de l'utilisateur avec le BMC. L'algorithme d'intégrité est utilisé pour générer des signatures sur les paquets IPMI. L'algorithme de confidentialité est utilisé pour chiffrer les données. La configuration dans cette section permet d'activer ou de désactiver certains identifiants de suite de chiffrement, et le niveau de privilège maximum qu'unername peut

s'authentifier.

chiffrement.

En général, le niveau de privilège maximal configuré pour un nom d'utilisateur doit être défini pour au moins un identifiant de suite de chiffrement. En général, il s'agit du privilège "Administrator"

Section

SOL_Conf

Cette section sert à configurer Serial-Over-Lan (SOL) et ne sera disponible pour la configuration que sur ces machines. SOL peut être activé avec le champ Enable_SOL. Le niveau de privilège minimum requis pour se connecter avec SOL est spécifié par SOL_Privilege_Level. Il doit être défini au niveau de privilège maximal configuré pour un nom d'utilisateur ayant SOL activé. En général, il s'agit du privilège "Administrator". L'authentification et le chiffrement peuvent être forcés ou non à l'aide des champs Force_SOL_Payload_Authentication et Force_SOL_Payload_Encryption respectivement. Il est recommandé de les activer. Cependant, la prise en charge de l'authentification et/ou du chiffrement forcés dépend des identifiants de suite de chiffrement pris en

charge.

Les options Character_Accumulate_Interval, Character_Send_Threshold , SOL_Retry_Count et , SOL_Retry_Interval sont utilisées pour régler les vitesses de sortie des caractères SOL. Character_Accumulate_Interval détermine la fréquence à laquelle les données série doivent être envoyées régulièrement et Character_Send_Threshold indique le nombre de caractères qui, une fois dépassé, forcera l'envoi des données série. SOL_Retry_Count indique le nombre de fois que les paquets doivent être retransmis si les accusés de réception ne sont pas reçus. SOL_Retry_Interval indique l'intervalle d'expiration. En général, les valeurs recommandées par le fabricant seront suffisantes. Cependant, vous pouvez souhaiter expérimenter avec ces valeurs pour un débit SOL plus

rapide.

Les options Non_Volatile_Bit_Rate et Volatile_Bit_Rate déterminent le débit en bauds que le BMC doit utiliser. Il doit correspondre au débit en bauds défini dans le BIOS et le système d'exploitation, tel que agetty(8). En général, les options Volatile et Non_Volatile doivent être définies de manière

identique.

En plus d'activer SOL dans cette section, les utilisateurs individuels doivent également être capables de se connecter avec SOL. Voir la section Section User1, User2, ...

ci-dessus pour p
lus de détails.
