DESCRIPTIO

N

L'utilitaire ipcs doit écrire des informations sur les mécanismes de communication inter-processus

actifs.

Sans options, les informations doivent être écrites au format abrégé pour les files de messa

ges, les segments de mémoire partagée et les ensembles de sémaphores actuellement actifs da
ns le système. Sinon, les informations affichées sont contrôlées par les options spécifiées.

OPTION

S

L'utilitaire ipcs doit se conformer au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe des

utilitaires.

L'utilitaire ipcs accepte les options suivantes

:
-
q
Écrire des informations sur les files de messages
actives.
-
m
Écrire des informations sur les segments de mémoire partagée
actifs.
-
s
Écrire des informatio
ns sur les ensembles
de sémaphores actifs.

Si -q, -m, ou -s sont spécifiées, seules les informations sur ces mécanismes doivent être écrites. Si aucune de ces trois options n'est spécifiée, les informations sur les trois doivent être écrites, sous réserve des options suivantes

:
-
a
Utiliser toutes les options d'affichage. (Ceci est une notation abrégée pour -b, -c, -o, -p, et -t.
)
-
b
Écrire des informations sur la taille maximale autorisée. (Nombre maximal d'octets dans les messages sur la file pour les files de messages, taille des segments pour la mémoire partagée, et nombre de sémaphores dans chaque ensemble pour les sémaphores.
)
-
c
Écrire le nom d'utilisateur et le nom de groupe du créateur ; voir
ci-dessous.
-
o
Écrire des informations sur l'utilisation en cours. (Nombre de messages sur la file et nombre total d'octets dans les messages sur la file pour les files de messages, et nombre de processus attachés aux segments de mémoire partagée.
)
-
p
Écrire des informations sur les numéros de processus. (ID du dernier processus à avoir envoyé un message et ID du dernier processus à avoir reçu un message sur les files de messages, ID du processus créateur, et ID du dernier processus à s'être attaché ou détaché des segments de mémoire partagée.
)
-
t
Écrire des informations sur les heures. (Heure de la dernière opération de contrôle ayant modifié les permissions d'accès pour tous les mécanismes, heure de la dernière msgsnd() et msgrcv() opérations sur les files de messages, heure de la dernière shmat() et shmdt() opérations sur la mémoire partagée, et heure de la dernière o
pération sem
op() sur les
sémaphores.)

T

Une ligne d'introduction doit être écrite avec le format

: 
"IPC status from %s as of %s\n", <source>, <da
te
>

où <source> indique la source utilisée pour recueillir les statistiques et <date> est l'information qui serait produite par la commande date lorsqu'elle est invoquée dans la locale

POSIX.

L'utilitaire ipcs doit ensuite créer jusqu'à trois rapports en fonction des options -q, -m, et -s. Le premier rapport doit indiquer l'état des files de messages, le deuxième rapport doit indiquer l'état des segments de mémoire partagée, et le troisième rapport doit indiquer l'état des ensembles de

sémaphores.

Si le mécanisme correspondant n'est pas installé ou n'a pas été utilisé depuis le dernier redémarrage, alors le rapport doit être écrit au format

: 
"%s facility not in system.\n", <faci
lit
y>

où <facility> est Message Queue, Shared Memory, ou Semaphore, selon le cas. Si le mécanisme a été installé et a été utilisé depuis le dernier redémarrage, les en-têtes de colonnes séparés par un ou plusieurs caractères <space> et suivis d'un <newline> doivent être écrits comme indiqué ci-dessous, suivis du nom du mécanisme écrit au format

: 
"%s:\n", <faci
lit
y>

où <facility> est Message Queues, Shared Memory, ou Semaphores, selon le cas. Sur les deuxième et troisième rapports, les en-têtes de colonnes n'ont pas besoin d'être écrits si les derniers en-têtes de colonnes écrits fournissent déjà les en-têtes de colonnes pour toutes les informations de ce

rapport.

Les en-têtes de colonnes fournis dans la première colonne ci-dessous et la signification des informations dans ces colonnes doivent être données dans l'ordre ci-dessous ; les lettres entre parenthèses indiquent les options qui doivent faire apparaître la colonne correspondante ; « all » signifie que la colonne doit toujours apparaître. Chaque colonne est séparée par un ou plusieurs caractères <space>. Notez que ces options déterminent uniquement quelles informations sont fournies pour chaque rapport ; elles ne déterminent pas quels rapports sont

écrits.

KEY
(all)
La clé utilisée comme argument pour msgget(), semget(), ou shmget() pour créer l'entrée de la ressource.
Note :
La clé d'un segment de mémoire partagée est remplacée par IPC_PRIVATE lorsque le segment a été supprimé jusqu'à ce que tous les processus attachés au segment le désattachent.

Ce champ doit être écrit en utilisant le format 0x%x.

MODE (tous)
Les modes d'accès et les indicateurs de la ressource. Le mode doit être composé de 11 caractères qui sont interprétés comme suit.

Le premier caractère doit être :

S
Si un processus attend sur une opération msgsnd().
-
Si ce qui précède n'est pas vrai.

Le second caractère doit être :

R
Si un processus attend sur une opération msgrcv().
C ou -
Si le segment de mémoire partagée associé doit être effacé lors de la première opération d'attachement.
-
Si rien de ce qui précède n'est vrai.

Les neuf caractères suivants doivent être interprétés comme trois ensembles de trois bits chacun. Le premier ensemble fait référence aux permissions du propriétaire ; le suivant aux permissions des autres dans le groupe utilisateur de l'entrée de la ressource ; et le dernier à tous les autres. Au sein de chaque ensemble, le premier caractère indique la permission de lire, le second caractère indique la permission d'écrire ou de modifier l'entrée de la ressource, et le dernier caractère est un trait d'union ('-').

Les permissions doivent être indiquées comme suit :

r
Si la permission de lecture est accordée.
w
Si la permission d'écriture est accordée.
a
Si la permission de modification est accordée.
-
Si la permission indiquée n'est pas accordée.

Le premier caractère suivant les permissions spécifie s'il existe une méthode d'accès alternative ou supplémentaire associée à la ressource. S'il n'y a pas de méthode d'accès alternative ou supplémentaire associée à la ressource, un seul espace doit être écrit ; sinon, un autre caractère imprimable est écrit.

PROPRIÉTAIRE (tous)
Le nom d'utilisateur du propriétaire de l'entrée de la ressource. Si le nom d'utilisateur du propriétaire est trouvé dans la base de données des utilisateurs, au moins les huit premières colonnes du nom doivent être écrites en utilisant le format %s. Sinon, l'ID utilisateur du propriétaire doit être écrit en utilisant le format %d.
GROUPE (tous)
Le nom du groupe du propriétaire de l'entrée de la ressource. Si le nom du groupe du propriétaire est trouvé dans la base de données des groupes, au moins les huit premières colonnes du nom doivent être écrites en utilisant le format %s. Sinon, l'ID du groupe du propriétaire doit être écrit en utilisant le format %d.

Les neuf colonnes suivantes doivent être uniquement écrites pour les files de messages :

CRÉATEUR (a,c)
Le nom d'utilisateur du créateur de l'entrée de la ressource. Si le nom d'utilisateur du créateur est trouvé dans la base de données des utilisateurs, au moins les huit premières colonnes du nom doivent être écrites en utilisant le format %s. Sinon, l'ID utilisateur du créateur doit être écrit en utilisant le format %d.
CGROUPE (a,c)
Le nom du groupe du créateur de l'entrée de la ressource. Si le nom du groupe du créateur est trouvé dans la base de données des groupes, au moins les huit premières colonnes du nom doivent être écrites en utilisant le format %s. Sinon, l'ID du groupe du créateur doit être écrit en utilisant le format %d.
CBYTES (a,o)
Le nombre d'octets dans les messages actuellement en attente sur la file de messages associée. Ce champ doit être écrit en utilisant le format %d.
QNUM (a,o)
Le nombre de messages actuellement en attente sur la file de messages associée. Ce champ doit être écrit en utilisant le format %d.
QBYTES (a,b)
Le nombre maximum d'octets autorisés dans les messages en attente sur la file de messages associée. Ce champ doit être écrit en utilisant le format %d.
LSPID (a,p)
L'identifiant du processus du dernier processus ayant envoyé un message à la file associée. Ce champ doit être écrit en utilisant le format :
"%d", <pid>

où <pid> est 0 si aucun message n'a été envoyé à la file de messages correspondante ; sinon, <pid> est l'identifiant du processus du dernier processus ayant envoyé un message à la file.

LRPID (a,p)
L'identifiant du processus du dernier processus ayant reçu un message de la file associée. Ce champ doit être écrit en utilisant le format :
"%d", <pid>

où <pid> est 0 si aucun message n'a été reçu de la file de messages correspondante ; sinon, <pid> est l'identifiant du processus du dernier processus ayant reçu un message de la file.

STIME (a,t)
L'heure d'envoi du dernier message à la file associée. Si un message a été envoyé à la file de messages correspondante, l'heure, la minute et la seconde de la dernière fois qu'un message a été envoyé à la file doivent être écrites en utilisant le format %d:%2.2d:%2.2d. Sinon, le format " no-entry" doit être écrit.
RTIME (a,t)
L'heure de réception du dernier message de la file associée. Si un message a été reçu de la file de messages correspondante, l'heure, la minute et la seconde de la dernière fois qu'un message a été reçu de la file doivent être écrites en utilisant le format %d:%2.2d:%2.2d. Sinon, le format " no-entry" doit être écrit.

Les huit colonnes suivantes doivent être uniquement écrites pour les segments de mémoire partagée.

CRÉATEUR (a,c)
L'utilisateur du créateur de l'entrée de la ressource. Si le nom d'utilisateur du créateur est trouvé dans la base de données des utilisateurs, au moins les huit premières colonnes du nom doivent être écrites en utilisant le format %s. Sinon, l'ID utilisateur du créateur doit être écrit en utilisant le format %d.
CGROUPE (a,c)
Le nom du groupe du créateur de l'entrée de la ressource. Si le nom du groupe du créateur est trouvé dans la base de données des groupes, au moins les huit premières colonnes du nom doivent être écrites en utilisant le format %s. Sinon, l'ID du groupe du créateur doit être écrit en utilisant le format %d.
NATTCH (a,o)
Le nombre de processus attachés au segment de mémoire partagée associé. Ce champ doit être écrit en utilisant le format %d.
SEGSZ (a,b)
La taille du segment de mémoire partagée associé. Ce champ doit être écrit en utilisant le format %d.
CPID (a,p)
L'identifiant du processus du créateur de l'entrée de mémoire partagée. Ce champ doit être écrit en utilisant le format %d.
LPID (a,p)
L'identifiant du processus du dernier processus ayant attaché ou détaché le segment de mémoire partagée. Ce champ doit être écrit en utilisant le format :
"%d", <pid>

où <pid> est 0 si aucun processus n'a attaché le segment de mémoire partagée correspondant ; sinon, <pid> est l'identifiant du processus du dernier processus ayant attaché ou détaché le segment.

ATIME (a,t)
L'heure de fin du dernier attachement au segment de mémoire partagée associé. Si le segment de mémoire partagée correspondant a déjà été attaché, l'heure, la minute et la seconde de la dernière fois que le segment a été attaché doivent être écrites en utilisant le format %d:%2.2d:%2.2d. Sinon, le format " no-entry" doit être écrit.
DTIME (a,t)
L'heure de fin du dernier détachement du segment de mémoire partagée associé. Si le segment de mémoire partagée correspondant a déjà été détaché, l'heure, la minute et la seconde de la dernière fois que le segment a été détaché doivent être écrites en utilisant le format %d:%2.2d:%2.2d. Sinon, le format " no-entry" doit être écrit.

Les quatre colonnes suivantes doivent être uniquement écrites pour les ensembles de sémaphores :

CRÉATEUR (a,c)
L'utilisateur du créateur de l'entrée de la ressource. Si le nom d'utilisateur du créateur est trouvé dans la base de données des utilisateurs, au moins les huit premières colonnes du nom doivent être écrites en utilisant le format %s. Sinon, l'ID utilisateur du créateur doit être écrit en utilisant le format %d.
CGROUPE (a,c)
Le nom du groupe du créateur de l'entrée de la ressource. Si le nom du groupe du créateur est trouvé dans la base de données des groupes, au moins les huit premières colonnes du nom doivent être écrites en utilisant le format %s. Sinon, l'ID du groupe du créateur doit être écrit en utilisant le format %d.
